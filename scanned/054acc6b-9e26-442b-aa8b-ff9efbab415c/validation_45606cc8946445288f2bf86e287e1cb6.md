## Analog Found

### Title
Overly-Wide, Fixed Replay-Tolerance Window Lets Anyone Publicly Re-Play Stale `set_alias_account`/`set_personal_id_account` Transactions to Flip Account Bindings - (File: `substrate/frame/people/src/extension.rs`)

### Summary
The external report's core broken invariant is: a configurable acceptance *bound* (±5% price deviation) is set far wider than operationally justified, letting state (minting) be accepted while the underlying reference value is meaningfully "off," creating a public window for manipulation. The local analog is the `pallet-people` extrinsic-validity *tolerance bound*, `account_setup_time_tolerance()`, hardcoded to `600` blocks in [1](#0-0) . This bound governs how long a `set_alias_account`/`set_personal_id_account` call (bound to a `call_valid_at` block) remains acceptable, and the pallet's own documentation admits that within this window the account↔alias/identity binding can be flipped by *replaying* an old, publicly-visible transaction — not merely by the original signer, but by **any unprivileged submitter**, since the dispatch origin is `None` and the proof/signature is public chain data.

### Finding Description
`AsPersonInfo::AsPersonalAliasWithProof` and `AsPersonalIdentityWithProof` are documented as only "protected against resetting the *same* account" within the tolerance period; if two different accounts are set with overlapping `call_valid_at` validity windows, "those 2 transactions can be replayed indefinitely for the duration of the overlapping period": [2](#0-1) 

The `SignedExtension::validate` implementation enforces only a time-window and a "same value" replay check — not an origin/submitter check, so any third party who observes a previously broadcast transaction can resubmit it verbatim as long as `now <= call_valid_at + account_setup_time_tolerance`: [3](#0-2) 

The dispatchables themselves reconfirm only the time window and "already set" check, not submitter identity, before mutating `AccountToAlias`/`AliasToAccount` (or `AccountToPersonalId`/`People`): [4](#0-3) 

The tolerance constant is a single hardcoded value applied uniformly, with no justification narrower than "whatever is convenient for setup," analogous to `MAX_PRICE_DEVIATION_UPPER_BOUND` being uniformly wide for all assets: [5](#0-4) 

The pallet's own test suite confirms the flip-flop is real and repeatable — two competing bindings (account 10 vs account 11) can be toggled back and forth purely via replay, entirely within the tolerance window, by resubmitting old signed/proved transactions: [6](#0-5) 

### Impact Explanation
`pallet-people` binds an on-chain `AccountId` to a personal identity/alias so that account can subsequently dispatch calls "as" that identity via `under_alias`/`AsPersonalAliasWithAccount` extensions [7](#0-6) . The account bound to an alias/identity is therefore a security-critical piece of state: it determines which signing key can act as the personhood-derived origin. Because the 600-block tolerance window (~1 hour at 6s blocks) permits *anyone* to replay an old, publicly observed `set_alias_account`/`set_personal_id_account` transaction, an attacker can force the binding to revert to a stale account (e.g. one whose key the legitimate person is in the process of rotating away from, perhaps due to compromise) for as long as the overlapping validity windows persist. This is an unauthorized-state-mutation / origin-integrity issue: the account-to-identity binding — which downstream determines dispatch authorization — can be toggled by a party who is not the identity owner and holds no privilege, simply by rebroadcasting old call data.

### Likelihood Explanation
High under normal operation: no privileged actor, validator collusion, or leaked key is required — only public chain data (a previously included transaction) and resubmission before the fixed 600-block window closes. Any person who is mid-way through rotating their bound account (e.g., legitimate key rotation) is exposed for the entire overlap window, and the flip-flop is exactly reproduced by the existing test `replay_protection_for_alias`/`replay_protection_for_identity` in the repo, demonstrating the bound is not merely theoretical but exercised in-tree.

### Recommendation
- Narrow `account_setup_time_tolerance` to the minimum value operationally required for clock/block-time skew, not a broad convenience window.
- Bind replay protection to more than "does the (alias, account) pair match the stored value" — e.g., require a strictly monotonic `call_valid_at`/nonce commitment per alias/identity so an older call can never be re-accepted once a newer one for the same alias has been seen, closing the "indefinitely replayable within overlap" gap described in the pallet's own doc comments.
- Consider making resubmission of a `set_alias_account`/`set_personal_id_account` call attributable/restricted (e.g., require the caller to also prove control of the *new* value each time, rather than allowing bare replay of old signed payloads).

### Proof of Concept
The repository's own test demonstrates the exploitable flip-flop end-to-end:
1. Alice (owning alias) submits `call1` setting her bound account to `10` at block `N`; it succeeds.
2. Immediate replay of `call1` fails (`Stale`), but this only blocks *identical* replays.
3. Alice submits `call2` (valid at `N+1`) to move the binding to `11`.
4. Once block time reaches `N + account_setup_time_tolerance` (600), `call2` succeeds, binding flips to `11`.
5. Any observer — not necessarily Alice — can now resubmit the original `call1` (still within its own tolerance window) and it succeeds again, reverting the binding to `10`.
6. `call2` can likewise be replayed again to flip back to `11`, and so on, for the entire overlap duration.
See [8](#0-7)  for the exact sequence, which is asserted to succeed (`assert_ok!`) at every replay step within the window.

		pub fn set_alias_account(
			origin: OriginFor<T>,
			account: T::AccountId,
			call_valid_at: BlockNumberFor<T>,
		) -> DispatchResultWithPostInfo {
			let rev_ca = Self::ensure_revised_personal_alias(origin)?;
			let now = frame_system::Pallet::<T>::block_number();
			let time_tolerance = Self::account_setup_time_tolerance();
			ensure!(
				call_valid_at <= now && now <= call_valid_at.saturating_add(time_tolerance),
				Error::<T>::TimeOutOfRange
			);
			ensure!(T::AccountContexts::contains(&rev_ca.ca.context), Error::<T>::InvalidContext);
			ensure!(!AccountToPersonalId::<T>::contains_key(&account), Error::<T>::AccountInUse);

			let old_account = AliasToAccount::<T>::get(&rev_ca.ca);
			let old_rev_ca = old_account.as_ref().and_then(AccountToAlias::<T>::get);

			let needs_revision = old_rev_ca.is_some_and(|old_rev_ca| {
				old_rev_ca.revision != rev_ca.revision || old_rev_ca.ring != rev_ca.ring
			});

			// Ensure it changes the account associated, or it needs revision.
			ensure!(
				old_account.as_ref() != Some(&account) || needs_revision,
				Error::<T>::AliasAccountAlreadySet
			);

#[test]
fn replay_protection_for_alias() {
	new_test_ext().execute_with(|| {
		const EXTENSION_VERSION: u8 = 0;
		// Setup Alice as a member.
		PeoplePallet::set_onboarding_size(RuntimeOrigin::root(), 1).unwrap();
		let alice_sec = Simple::new_secret([1u8; 32]);
		let alice_pub = Simple::member_from_secret(&alice_sec);
		let alice_index = PeoplePallet::reserve_new_id();
		PeoplePallet::recognize_personhood(alice_index, Some(alice_pub)).unwrap();
		assert_ok!(PeoplePallet::onboard_people());
		assert_ok!(build_ring(RI_ZERO, None));
		let generate_alias_tx_ext_for_call = |call: RuntimeCall| {
			let other_tx_ext = (frame_system::CheckNonce::<Test>::from(0),);
			// The message is the hash over the extension version, call, and other extensions.
			let msg = (&EXTENSION_VERSION, &call, &other_tx_ext)
				.using_encoded(sp_io::hashing::blake2_256);
			// Open a commitment (using Alice’s public key and public data)
			let commitment = Simple::open(&alice_pub, Some(alice_pub).into_iter()).unwrap();
			// Create a VRF proof and compute the alias output from the call message.
			let (proof, alias_value) =
				Simple::create(commitment, &alice_sec, &MOCK_CONTEXT, &msg).unwrap();
			let alias = ContextualAlias { context: MOCK_CONTEXT, alias: alias_value };
			let tx_ext = (
				AsPerson::<Test>::new(Some(AsPersonInfo::AsPersonalAliasWithProof(
					proof,
					0,
					MOCK_CONTEXT,
				))),
				other_tx_ext.0,
			);
			(tx_ext, alias)
		};
		// --- Transaction 1: set alias account to 10 ---
		// Use the current block number as the valid time.
		let call1 = RuntimeCall::PeoplePallet(crate::Call::set_alias_account {
			account: 10,
			call_valid_at: System::block_number(),
		});
		let (tx_ext1, alias) = generate_alias_tx_ext_for_call(call1.clone());
		let rev_alias = RevisedContextualAlias { revision: 0, ring: 0, ca: alias.clone() };
		// Execute transaction 1. It should succeed.
		assert_ok!(exec_tx(None, tx_ext1.clone(), call1.clone()));
		assert_eq!(crate::AliasToAccount::<Test>::get(&alias), Some(10));
		assert_eq!(crate::AccountToAlias::<Test>::get(10), Some(rev_alias.clone()));
		// Replay transaction 1 immediately: it must fail (replay protected).
		assert_noop!(exec_tx(None, tx_ext1.clone(), call1.clone()), InvalidTransaction::Stale);
		// --- Transaction 2: set alias account to 11 ---
		// Set its valid time to the future: current block number plus the allowed tolerance + 1.
		let call2 = RuntimeCall::PeoplePallet(crate::Call::set_alias_account {
			account: 11,
			call_valid_at: System::block_number() + 1,
		});
		let (tx_ext2, _) = generate_alias_tx_ext_for_call(call2.clone());
		// Transaction 2 is too early: it should be rejected as "Future".
		assert_noop!(exec_tx(None, tx_ext2.clone(), call2.clone()), InvalidTransaction::Future);
		// The mapping still reflects transaction 1.
		assert_eq!(crate::AliasToAccount::<Test>::get(&alias), Some(10));
		assert_eq!(crate::AccountToAlias::<Test>::get(10), Some(rev_alias.clone()));
		assert_eq!(crate::AccountToAlias::<Test>::get(11), None);
		// Advance time by the allowed tolerance. Now transaction 2 becomes valid.
		mock::advance_to(System::block_number() + PeoplePallet::account_setup_time_tolerance());
		// Execute transaction 2. It now succeeds.
		assert_ok!(exec_tx(None, tx_ext2.clone(), call2.clone()));
		assert_eq!(crate::AliasToAccount::<Test>::get(&alias), Some(11));
		assert_eq!(crate::AccountToAlias::<Test>::get(11), Some(rev_alias.clone()));
		assert_eq!(crate::AccountToAlias::<Test>::get(10), None);
		// --- Replaying old transactions within tolerance ---
		// Replay transaction 1. Within the tolerance window its replay is allowed.
		assert_ok!(exec_tx(None, tx_ext1.clone(), call1.clone()));
		assert_eq!(crate::AliasToAccount::<Test>::get(&alias), Some(10));
		assert_eq!(crate::AccountToAlias::<Test>::get(10), Some(rev_alias.clone()));
		assert_eq!(crate::AccountToAlias::<Test>::get(11), None);
		// Replay transaction 2 to set it back to 11.
		assert_ok!(exec_tx(None, tx_ext2.clone(), call2.clone()));
		assert_eq!(crate::AliasToAccount::<Test>::get(&alias), Some(11));
		assert_eq!(crate::AccountToAlias::<Test>::get(11), Some(rev_alias.clone()));
		assert_eq!(crate::AccountToAlias::<Test>::get(10), None);
		// --- Advance time beyond tolerance ---
		// After advancing time a bit more, the time tolerance for transaction 1 is exceeded.
		mock::advance_to(System::block_number() + 1);
		// Now replaying transaction 1 must be rejected as stale.
		assert_noop!(exec_tx(None, tx_ext1, call1), InvalidTransaction::Stale);
		assert_eq!(crate::AliasToAccount::<Test>::get(&alias), Some(11));
		assert_eq!(crate::AccountToAlias::<Test>::get(11), Some(rev_alias));
