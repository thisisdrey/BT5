In `contracts/defuse/core/src/engine/mod.rs::execute_signed_intent`, an attacker submits an `execute_intents` call containing a `MultiPayload` whose `DefusePayload::signer_id` differs from the account actually implied by `signed.verify()`'s returned public key, expecting the engine to trust `signer_id` from the JSON body rather than `has_public_key(&signer_id, &public_key)`. Preconditions: attacker owns key pair `(pk_attacker, sk_attacker)`, victim's account has `pk_victim` registered. Call sequence: attacker signs the payload with `sk_attacker` but sets `signer_id: victim` in the message body; `signed.verify()` returns `pk_attacker`; the engine checks `self.state.has_public_key(&victim, &pk_attacker)` which is false unless attacker's key happens to be registered on victim's account. Binding: `(signer_id, public_key)` authorized == `(account whose funds move, key that signed)`, i.e., `has_public_key(signer_id, verify()) == true` is REQUIRED before `commit_nonce`/`execute_intent`. Impact: Critical - if this check were bypassable, attacker could move victim's `token_balances` with only their own signature. Proof idea: cargo test with mismatched `signer_id`/signing key pair, assert `execute_signed_intents` returns `Err(DefuseError::PublicKeyNotExist(..))` and no `token_balances` change for `victim`.
