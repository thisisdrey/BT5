`Contract::is_nonce_cleanable` (contracts/defuse/src/contract/garbage_collector.rs) returns `deadline < Timestamp::now() || !self.is_valid_salt(salt)`. If a `SaltManager`-role rotates the current salt (making an OLD salt invalid via `SaltManager` role action — out of scope to trigger directly as attacker, but attacker can craft nonces using a salt they predict will be rotated), an unprivileged attacker signs a `DefuseIntents` using the CURRENTLY valid salt, it executes and settles (moves funds). Later the salt is rotated by the DAO (a routine, expected operational event, not attacker-controlled). `is_nonce_cleanable` now returns true for this ALREADY-SETTLED nonce purely due to salt invalidation, and a `GarbageCollector` cleans it, sharing a word with another nonce (see prefix-collision questions above). Binding: settlement count for the original signed payload must remain == 1 even after routine salt rotation + cleanup. Impact: Critical, same double-settlement class triggered by ordinary salt lifecycle rather than expiry. Proof: cargo test rotating salt via test harness, invoking cleanup on the invalidated nonce, and confirming no OTHER live nonce sharing its prefix gets its used-bit cleared.
