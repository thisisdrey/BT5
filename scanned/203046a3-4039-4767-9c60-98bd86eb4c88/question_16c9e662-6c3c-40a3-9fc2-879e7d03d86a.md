`Contract::commit_nonce` (contracts/defuse/src/contract/intents/state.rs) calls `self.accounts.get_or_create(account_id.clone()).get_mut().ok_or(AccountLocked)?.commit_nonce(nonce)` — `get_or_create` creates a fresh account entry if none exists. Binding: on panic, NEAR receipt state changes are entirely reverted, so `commit_nonce`'s in-cache Ok() must NOT persist; the same nonce must remain unused (`is_nonce_used == false`) after the panic. Impact: Critical if the nonce is falsely marked used after a reverted batch, permanently blocking the legitimate first execution (denial of a valid one-time signature) or, conversely, if it silently persists letting the intent be considered 'spent' without ever moving funds — either breaks AUTHORISATION/REPLAY binding.
