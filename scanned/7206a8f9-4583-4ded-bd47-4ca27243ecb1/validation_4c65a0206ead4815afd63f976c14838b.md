### Title
`PSM::redeem()` Skips the Live-Decimals Guard That `mint()` Enforces, Allowing Stale Snapshot Scaling to Misprice Settlements - (File: `substrate/frame/psm/src/lib.rs`)

### Summary
`pallet-psm` snapshots each asset's decimal precision at registration time (`PsmInfo::internal_decimals`, `ExternalAssetInfo::decimals`) and uses that snapshot to scale amounts between internal and external units. The `mint()` dispatchable defends against the snapshot going stale by calling `Self::ensure_decimals_match(...)` before converting [1](#0-0) , which (per its doc comment) errors with `DecimalsMismatch` "If live decimals diverged from the snapshot taken at registration" [2](#0-1) . `redeem()`, however, reads the snapshot fields directly and performs the conversion without ever calling `ensure_decimals_match()`: `let ext_decimals = external.decimals; let internal_decimals = info.internal_decimals;` [3](#0-2) , followed immediately by `Self::internal_to_external(internal_net, ext_decimals, internal_decimals)` [4](#0-3) . This is structurally identical to the RToken bug: a cached scaling factor (there, `_liquidityIndex`; here, the decimals snapshot) is trusted for conversion in one code path while the guard that would catch its staleness is present elsewhere but omitted on this path.

### Finding Description
The pallet documents this exact risk class itself in the related `prdoc` entry: "Runtime drift guard: `mint`/`redeem` return `DecimalsMismatch` if live metadata diverges from the registration snapshot; that asset halts until governance intervenes" [5](#0-4) . That statement asserts both entry points are protected, but the code only implements the check in `mint()`:

- `mint()`: `let (ext_decimals, internal_decimals) = Self::ensure_decimals_match(&info, &internal_asset, &external_asset, &external)?;` [1](#0-0) 
- `redeem()`: no call to `ensure_decimals_match` anywhere in the function; `ext_decimals`/`internal_decimals` are taken straight from the potentially stale snapshot values `external.decimals` and `info.internal_decimals` [6](#0-5) .

The scaling helpers `external_to_internal` / `internal_to_external` unconditionally trust whatever decimals they're given and apply `10^diff` scaling with no independent sanity check against live metadata [7](#0-6) . So if an external asset's live decimals metadata diverges from the value snapshotted in `ExternalAssetInfo::decimals` at registration time (e.g., an asset owner or governance action changes metadata on the underlying `Fungibles` asset after the PSM approved it — a state transition the pallet explicitly anticipates and guards against on the mint side), `redeem()` will silently apply the wrong scaling factor. This produces an internal↔external conversion that does not correspond to the real 1:1 peg the PSM is supposed to enforce, i.e., the exact "amounts not correctly scaled/settled" failure mode the RToken report describes, just triggered from the opposite (withdrawal) direction where mint has a check but redeem does not.

### Impact Explanation
An incorrect scaling factor on `redeem()` directly breaks the PSM's core invariant — "burn N internal 1:1 for N external" — allowing either:
- Users to redeem more external-asset value than their burned internal amount is worth (drains the PSM reserve / theft of backing collateral for other internal holders), or
- Users to receive far less than entitled (fund loss for the redeemer),
depending on which direction decimals drifted. Because `PsmDebt` accounting and reserve transfers derive from these mis-scaled amounts (`effective_internal_net`, `external_out`), this also corrupts the pallet's debt-ceiling and reserve-solvency invariants (`PsmDebt::<T>::mutate` at line 889 [8](#0-7) ), potentially leaving the PSM permanently under- or over-collateralized — a chain-level accounting/fund-loss impact in scope for the program (theft/unbacked mint-or-unlock class, duplicate/incorrect settlement).

### Likelihood Explanation
This requires no privileged actor: any unprivileged, signed account holding the internal or external asset can call the public `redeem` extrinsic [9](#0-8) . The only precondition is that live decimals for the internal or an approved external asset diverge from what was snapshotted — a state the pallet's own design and prdoc acknowledge as an expected, guarded-against scenario on the mint path, confirming it is a reachable, non-adversarial-infrastructure condition rather than a theoretical one.

### Recommendation
Add the same `Self::ensure_decimals_match(&info, &internal_asset, &external_asset, &external)?` call in `redeem()` before computing `ext_decimals`/`internal_decimals`, mirroring `mint()`, so that any live/snapshot divergence halts redemption with `DecimalsMismatch` exactly as documented, instead of silently mis-scaling the settlement.

### Proof of Concept
1. `create_psm` for `internal_asset` with live decimals `D_i`; pallet snapshots `PsmInfo.internal_decimals = D_i`.
2. `add_external_asset` for `external_asset` with live decimals `D_e`; pallet snapshots `ExternalAssetInfo.decimals = D_e`.
3. Live metadata for `external_asset` (or `internal_asset`) is later changed on the underlying `Fungibles` backend so its true decimals become `D_e'` ≠ `D_e` (a state the pallet's `mint` path explicitly detects via `ensure_decimals_match` and halts on with `DecimalsMismatch`).
4. Call `mint(...)` — reverts with `DecimalsMismatch` as designed [1](#0-0) .
5. Call `redeem(internal_asset, external_asset, internal_amount, max_fee)` instead — no equivalent check exists; `ext_decimals = external.decimals` (stale `D_e`) is used directly in `internal_to_external`/`external_to_internal` conversions [10](#0-9) , succeeding with a scaling factor `10^(D_e - D_i)` computed against the stale decimals instead of the true live ones — yielding an `external_out` that misrepresents the actual value being withdrawn from the reserve relative to the internal amount burned.

		///
		/// Scales by `10^(ext_decimals - internal_decimals)` — multiplies up when internal has more
		/// decimals, floor-divides when it has fewer. Returns [`Error::ConversionOverflow`] if
		/// the scaling factor or the product does not fit in the balance type.
		pub(crate) fn external_to_internal(
			amount: BalanceOf<T>,
			ext_decimals: u8,
			internal_decimals: u8,
		) -> Result<BalanceOf<T>, Error<T>> {
			use core::cmp::Ordering::*;
			match ext_decimals.cmp(&internal_decimals) {
				Equal => Ok(amount),
				Less => {
					let diff = (internal_decimals - ext_decimals) as u32;
					let factor = Self::pow10(diff)?;
					amount.checked_mul(&factor).ok_or(Error::<T>::ConversionOverflow)
				},
				Greater => {
					let diff = (ext_decimals - internal_decimals) as u32;
					let factor = Self::pow10(diff)?;
					Ok(amount.checked_div(&factor).unwrap_or_else(BalanceOf::<T>::zero))
				},
			}
		}
