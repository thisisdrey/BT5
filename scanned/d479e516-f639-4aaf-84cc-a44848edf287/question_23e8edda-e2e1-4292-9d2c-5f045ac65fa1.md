Target: `BlockProposalData::consensus_deserialize` in libsigner/src/events.rs and constant `BLOCK_RESPONSE_DATA_MAX_SIZE: u32 = 2 * 1024 * 1024`. Attacker action: send/relay a `BlockProposal` whose inner `BlockProposalData` bytes claim (via the outer length prefix consumed by `read_next_at_most(fd, BLOCK_RESPONSE_DATA_MAX_SIZE)`) a length up to 2MB but the reader is only backed by a shorter buffer (e.g., a truncated StackerDB chunk). Preconditions: attacker is a miner-role or relays a `.miners` StackerDB chunk (the `MinerMessages` lane in `TryFrom<StackerDBChunksEvent>`), which does not require signature-lane checking the way `signers-X-Y` does. Call sequence: `T::consensus_deserialize` (`BlockProposal::consensus_deserialize`) -> `BlockProposalData::consensus_deserialize` -> `read_next_at_most(fd, BLOCK_RESPONSE_DATA_MAX_SIZE)` -> `inner_bytes.as_slice()` reader for `server_version`/`miner_diagnostic_data`/`unknown_bytes`. Equality/fault: bytes actually available in `fd` for the inner blob must be >= the length `read_next_at_most` claims to have read; if `read_next_at_most` can return a shorter-than-declared `Vec<u8>` (rather than erroring), the subsequent `inner_reader.to_vec()` for `unknown_bytes` silently truncates rather than failing, letting a malformed miner message be accepted as version-3 data it never fully contained. Impact: Critical if this can be forced to under-read and still `Ok(..)` (state/version mismatch accepted as authentic) rather than reject a truncated message. Proof idea: Rust test crafting a `BlockProposalData` byte stream with `version = 3` but a truncated inner buffer missing the required `MinerDiagnosticData` fields, and asserting `consensus_deserialize` returns `Err(CodecError::DeserializeError(...))` rather than `Ok` with a partially-populated `miner_diagnostic_data`.
