### Title
`SELFDESTRUCT` executed inside a `delegatecall`d target drains the calling (proxy) contract's entire native balance to an attacker-chosen beneficiary - (`File: substrate/frame/revive/src/exec.rs`, `substrate/frame/revive/src/vm/evm/instructions/host.rs`)

### Summary
`pallet-revive`'s EVM interpreter implements the `SELFDESTRUCT` opcode so that it always operates on the account of the *current top frame*. When a proxy-style contract issues a `delegatecall` into an untrusted target/plugin contract, the pushed frame's `account_id` is set to the **caller's own account**, not the callee's [1](#0-0) . If the delegate-called code then executes `SELFDESTRUCT`, the immediate balance transfer inside `terminate_if_same_tx` moves the *entire* native balance of the proxy to a beneficiary address chosen entirely by the delegate-called (attacker-authored) code [2](#0-1) . This is the exact primitive described in the external report (delegatecall into a target/plugin that self-destructs, draining the proxy), and it is already reproduced by the repository's own test suite.

### Finding Description
`selfdestruct` in the EVM interpreter directly calls `Ext::terminate_if_same_tx`, which reads `frame.account_id` for the balance transfer target and for scheduling deletion [3](#0-2) . For a `delegate_call` frame, `dest` (and hence `account_id`) is deliberately set to the *calling* contract's account so that storage/context is correctly preserved, matching Solidity `delegatecall` semantics [4](#0-3) . Consequently, when the delegate-called code runs `SELFDESTRUCT`, `terminate_if_same_tx` unconditionally transfers `evm_balance(contract_address)` of the *caller* to the beneficiary supplied by the delegate-called code [5](#0-4) .

Crucially, unlike the sibling precompile path `terminate_caller` (invoked through `ISystem.terminate`), which explicitly guards against being reached via delegatecall with `ensure!(self.top_frame().delegate.is_none(), Error::<T>::PrecompileDelegateDenied)` [6](#0-5) , the raw opcode path (`terminate_if_same_tx`) has **no such delegate-context check**. There is no allow-list, permission gate, or plugin-vetting mechanism in `pallet-revive` that prevents an arbitrary `delegatecall` target from invoking `SELFDESTRUCT` and choosing its own beneficiary.

The repository's own test `syscall_passes_for_direct_delegate` confirms this behavior end-to-end: `TerminateDelegator` (the "proxy") `delegatecall`s into `Terminate` (the "plugin"), the plugin executes `selfdestruct(beneficiary)`, and the proxy's full balance is transferred to the plugin-chosen beneficiary while the proxy itself survives [7](#0-6) .

### Impact Explanation
Any contract that performs a `delegatecall` into external/untrusted code (a proxy pattern, plugin system, or any composable contract accepting a target address as input) can have its entire native balance swept to an attacker-controlled address the moment the delegate-called code executes `SELFDESTRUCT`, with zero interaction from the proxy's own logic or owner intent. This is a direct fund-theft/loss vector for any `pallet-revive`-based chain exposing delegatecall-capable contracts, matching the "theft or unbacked mint or unlock" / "contract-held value must conserve value and settle exactly once to the rightful beneficiary" impact classes.

### Likelihood Explanation
This requires no privileged actor, validator, collator, or governance action — only an ordinary user or contract owner performing a `delegatecall` to a contract whose code (or a nested nested call within it) contains `SELFDESTRUCT`. Given `pallet-revive`'s explicit goal of EVM/Solidity compatibility (proxies, diamond patterns, plugin architectures all rely on `delegatecall`), and that the behavior is already deliberately implemented and tested rather than accidental, this is readily triggerable in practice whenever a proxy owner is tricked into pointing delegatecall at a malicious or compromised target.

### Recommendation
Since this mirrors intended EVM/Solidity `SELFDESTRUCT`+`delegatecall` semantics (and Cancun's EIP-6780 restricts actual account deletion to same-tx-created contracts, which `only_if_same_tx` already encodes), a full "fix" would break EVM equivalence. Mitigations should focus on making the risk explicit and containable at the runtime/tooling layer: consider exposing a per-contract or per-runtime opt-out/allow-list for `delegatecall` targets (as the external report itself suggests), and clearly document in `pallet-revive` that any `delegatecall` grants the callee full custody over the caller's native balance via `SELFDESTRUCT`, consistent with how the external report was ultimately "Acknowledged" rather than patched for the analogous EVM behavior.

### Proof of Concept
The existing test `syscall_passes_for_direct_delegate` in `substrate/frame/revive/src/tests/sol/terminate.rs` is a working PoC: `TerminateDelegator` (proxy, funded with 123 + min_balance) delegatecalls `Terminate::terminate(METHOD_SYSCALL, DJANGO)`; the assembly `selfdestruct(beneficiary)` inside `Terminate.sol` executes in the context of `TerminateDelegator`'s account, and after the call `DJANGO` (chosen entirely by the delegate-called plugin) receives the proxy's 123 balance while the proxy contract remains alive but drained to `min_balance` [8](#0-7) .

	fn delegate_call(
		&mut self,
		call_resources: &CallResources<T>,
		address: H160,
		input_data: Vec<u8>,
	) -> Result<(), ExecError> {
		// We reset the return data now, so it is cleared out even if no new frame was executed.
		// This is for example the case for unknown code hashes or creating the frame fails.
		*self.last_frame_output_mut() = Default::default();

		let top_frame = self.top_frame_mut();
		// Clone the contract info and apply pending storage changes so that
		// the child frame can correctly calculate storage deposit refunds.
		// See: <https://github.com/paritytech/contract-issues/issues/213>
		let mut contract_info = top_frame.contract_info().clone();
		top_frame.frame_meter.apply_pending_storage_changes(&mut contract_info);
		let account_id = top_frame.account_id.clone();
		let value = top_frame.value_transferred;
		if let Some(executable) = self.push_frame(
			FrameArgs::Call {
				dest: account_id,
				cached_info: Some(contract_info),
				delegated_call: Some(DelegateInfo {
					caller: self.caller().clone(),
					callee: address,
				}),
			},
			value,
			call_resources,
			self.is_read_only(),
			&input_data,
		)? {
			self.run(executable, input_data)
		} else {
			// Delegate-calls to non-contract accounts are considered success.
			Ok(())
		}
	}

pub fn selfdestruct<'ext, E: Ext>(interpreter: &mut Interpreter<'ext, E>) -> ControlFlow<Halt> {
	if interpreter.ext.is_read_only() {
		return ControlFlow::Break(Error::<E::T>::StateChangeDenied.into());
	}
	let [beneficiary] = interpreter.stack.popn()?;
	let charged = interpreter.ext.charge_or_halt(RuntimeCosts::Terminate { code_removed: true })?;
	let dispatch_result = interpreter.ext.terminate_if_same_tx(&beneficiary.into_address());

		Ok(code_removed) => {
			// halt execution on successful selfdestruct

/// In this test TerminateDelegator terminates itself by making a delegatecall to Terminate.
/// The SYSCALL shall send funds from TerminateDelegator to the beneficiary but TerminateDelegator
/// shall not be truly terminated.
#[test_case(FixtureType::Solc)]
#[test_case(FixtureType::Resolc)]
fn syscall_passes_for_direct_delegate(fixture_type: FixtureType) {
	let (code, _) = compile_module_with_type("Terminate", fixture_type).unwrap();
	let (delegator_code, _) = compile_module_with_type("TerminateDelegator", fixture_type).unwrap();
	ExtBuilder::default().build().execute_with(|| {
		let min_balance = Contracts::min_balance();
		let _ = <Test as Config>::Currency::set_balance(&ALICE, 100_000_000_000);

		let Contract { addr, .. } = builder::bare_instantiate(Code::Upload(code.clone()))
			.constructor_data(
				Terminate::constructorCall {
					skip: true,
					method: METHOD_SYSCALL,
					beneficiary: DJANGO_ADDR.0.into(),
				}
				.abi_encode(),
			)
			.build_and_unwrap_contract();
		let Contract { addr: delegator_addr, .. } =
			builder::bare_instantiate(Code::Upload(delegator_code.clone()))
				.native_value(123)
				.build_and_unwrap_contract();
		let account_delegator = <Test as Config>::AddressMapper::to_account_id(&delegator_addr);

		let result = builder::bare_call(delegator_addr)
			.data(
				TerminateDelegator::delegateCallTerminateCall {
					terminate_addr: addr.0.into(),
					method: METHOD_SYSCALL,
					beneficiary: DJANGO_ADDR.0.into(),
				}
				.abi_encode(),
			)
			.build_and_unwrap_result();
		assert!(!result.did_revert());

		assert_eq!(
			get_balance(&DJANGO),
			123 + min_balance,
			"unexpected django balance after terminate"
		);
		assert_eq!(
			get_balance(&account_delegator),
			min_balance,
			"unexpected delegator balance after terminate"
		);
		assert!(
			get_contract_checked(&addr).is_some(),
			"Terminate contract should still exist after terminate"
		);
		assert!(
			get_contract_checked(&delegator_addr).is_some(),
			"TerminateDelegator contract should still exist after terminate"
		);
	});
