Target: `Nonces::cleanup_by_prefix` / `GarbageCollector::cleanup_nonces` / `Contract::is_nonce_cleanable`. Attacker action: signs a `DefuseIntents` with `VersionedNonce::V1(SaltedNonce{salt, nonce: ExpirableNonce{deadline, nonce: bytes}})` where `deadline` is far in the future (not expired) and `salt` is currently valid, then colludes with (or waits for) `GarbageCollector` role to call `cleanup_nonces` — is_nonce_cleanable only returns true if `deadline < Timestamp::now() || !is_valid_salt(salt)`. Attacker's real attack surface: after `salt` is later rotated/invalidated by `SaltManager` (a normal DAO operation, not attacker-controlled) while the signed payload with that salt is still live, `is_valid_salt(salt)` becomes false, then GarbageCollector cleans the whole 256-bit word at that nonce's prefix via `cleanup_by_prefix`, clearing all 256 bits including nonces from OTHER unrelated signed payloads that happen to share the same top-248-bit prefix. Preconditions: attacker crafts a nonce whose top-248-bit prefix collides with an already-committed, still-valid nonce from a different signature (attacker can brute-force nonce bytes since only 8 bits — the last byte — differ within a prefix group, and the attacker fully controls the 27 `NONCE_BYTES`). Call sequence: attacker submits intent A with nonce `N_A` (prefix `P`, last byte `x1`), which commits and sets bit at `(P, x1)`. Attacker separately submits a still-valid signed intent B (could be attacker's own or a signature they hold, e.g. their own duplicate-looking payload) with nonce `N_B` sharing prefix `P`, last byte `x2` — after cleanup of the whole word for prefix `P` (triggered by any single expired/invalid-salt nonce in that word), `N_B`'s bit is cleared too even though `N_B`'s own deadline/salt were still valid. Binding: `Nonces::cleanup_by_prefix` clears a whole 256-bit word == invalidates only the intended expired nonce; if it clears bits belonging to still-valid, unexpired nonces, `is_nonce_used(N_B)` becomes `false` again while `N_B`'s original signature is still live, allowing intent B's signed payload to be replayed a second time (settlement count == 2, not 1). Scoped impact: Critical — REPLAY; the attacker's own valid signed intent (or a victim's, if attacker can predict/collide prefixes) can be re-executed once cleanup clears a shared word. Proof idea: `cargo test` in sandbox: commit two nonces sharing the same top-248-bit prefix but differing last byte, where one is expired/invalid-salt and the other still valid+unexpired; call `cleanup_nonces` role action; assert `is_nonce_used` on the still-valid nonce flips to `false`, then resubmit its original signed `MultiPayload` and assert it succeeds a second time — violating REPLAY == 1.
