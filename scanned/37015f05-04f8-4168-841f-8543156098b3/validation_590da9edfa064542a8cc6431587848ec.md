### Title
Externally-decaying Coretime sale price keeps ticking during a `SafeMode`/`TxPause` filter window, letting `Broker::purchase` be settled at an unintended below-market price - (File: `substrate/frame/broker/src/utility_impls.rs`)

### Summary
The Reserve report's core broken invariant is: a settlement function whose payout price is a pure function of *elapsed wall-clock time* can be gated by an orthogonal pause/unpause mechanism whose toggling does not stop that clock, so a caller who is allowed to act only after the pause is lifted receives a price that has silently decayed far below what was intended, at the protocol's expense. The Polkadot SDK analog is `pallet-broker`'s Bulk Coretime sale: `Pallet::sale_price` computes the current core price purely from the **relay-chain block number** (`RCBlockNumberProviderOf::<T::Coretime>::current_block_number()`), independent of whether the local chain is currently allowed to process the `purchase` extrinsic. `pallet-safe-mode`/`pallet-tx-pause` (both shipped in this repo and wired into `frame_system::Config::BaseCallFilter`) can filter out `Broker::purchase` for a window of time without affecting relay-chain block production, so the sale's leadin-period price decay continues uninterrupted while purchases are blocked.

### Finding Description
`sale_price` in [1](#0-0)  computes:
```
let num = now.saturating_sub(sale.sale_start).min(sale.leadin_length);
let through = FixedU64::from_rational(num, sale.leadin_length);
T::PriceAdapter::leadin_factor_at(through).saturating_mul_int(sale.end_price)
```
`now` is `RCBlockNumberProviderOf::<T::Coretime>::current_block_number()` — the **relay chain's** block height, not the local chain's ability to include extrinsics. `do_purchase` in [2](#0-1)  only checks `now > sale.sale_start` and `price_limit >= price`; it has no mechanism to detect or compensate for a period during which purchases were externally blocked while relay time (and thus price decay) kept advancing.

Both `pallet-tx-pause` and `pallet-safe-mode` are generic call filters wired into `frame_system::Config::BaseCallFilter` (`InsideBoth<SafeMode, TxPause>` in [3](#0-2) ). Crucially, `SafeMode::enter` is **fully permissionless** — any signed account can invoke it by placing a deposit, with no privileged origin required: [4](#0-3) 
```
pub fn enter(origin: OriginFor<T>) -> DispatchResult {
    let who = ensure_signed(origin)?;
    Self::do_enter(Some(who), T::EnterDuration::get())
}
```
Once entered, all calls not in `WhitelistedCalls` are rejected via `is_allowed`/`Contains`: [5](#0-4) 

Unless `Broker::purchase` (and related sale calls) is explicitly whitelisted, entering safe mode (or `TxPause::pause` targeting `Broker`/`purchase`, gated by `PauseOrigin` in the tx-pause case) blocks `purchase` for `EnterDuration` blocks while relay-chain blocks continue to be produced and `sale_price` continues to decay through the leadin period exactly as designed — the pause mechanism has no coupling to the sale's price clock. When the filter lifts (automatically, after `EnterDuration`, per `remaining()`/auto-exit in `substrate/frame/safe-mode/src/lib.rs`), whoever submits `purchase` first captures cores at the now-decayed price, exactly mirroring the Reserve bug's Bob obtaining the sell token "for a price much lower than he would initially expect before the trading pause."

### Impact Explanation
This directly maps to the required impact class "public underpriced work that degrades block production or stalls bridge processing" analog for chain revenue: Coretime sale proceeds (which fund the relay chain treasury / collator/validator rewards via `T::OnRevenue`) are settled at an unintended, artificially depressed price because the price-decay clock (tied to relay-chain time) is decoupled from the local chain's ability to accept the purchase extrinsic (tied to the call-filter state). This is value loss to the chain's treasury/revenue funnel, not merely front-running — the underlying protocol invariant "the sale price should reflect *organic* demand pressure over the leadin window, gated only by real purchasing activity" is broken because an unprivileged actor can suppress purchasing activity for a bounded, self-triggerable window while the clock still runs.

### Likelihood Explanation
`SafeMode::enter` requires no privileged origin — only a deposit (`EnterDepositAmount`) and a signed account — making the triggering action itself an ordinary, permissionless public entrypoint, not "malicious governance/admin abuse" as root cause. The `EnterDuration` is a fixed, known runtime constant, so an attacker can time entry to align with a moment in the sale's leadin period where the resulting decay after `EnterDuration` blocks yields a materially cheaper price, then race to submit `purchase` in the block where the filter lifts. The main uncertainty is that the specific coretime-westend/coretime-rococo runtimes in this repository do not currently include `pallet-safe-mode`/`pallet-tx-pause` in their pallet list (verified no `SafeMode`/`TxPause` references under `cumulus/parachains/runtimes/coretime*`), so the exact combination is not proven to be live in the shipped Coretime chains today; however, `pallet-broker`'s `sale_price` logic itself contains no defense against this class of clock/filter decoupling, so any runtime (including the reference `substrate/bin/node/runtime`, which does combine `SafeMode`+`TxPause`+time-based sale-style pallets) that adds `pallet-broker` alongside either pause pallet without whitelisting `Broker` calls would be exposed.

### Recommendation
- In `pallet-broker`, make `sale_price`/`do_purchase` resilient to externally-imposed pause windows: either (a) track cumulative "purchase-blocked" relay-chain blocks and exclude them from the leadin-period elapsed-time calculation, or (b) extend `sale.sale_start`/`leadin_length` by the duration purchases were filtered, so the price clock pauses in lockstep with dispatch availability.
- At the runtime-composition level, any runtime that includes `pallet-broker` together with `pallet-safe-mode` and/or `pallet-tx-pause` must add `Broker::purchase`, `Broker::renew`, and related sale-critical calls to `WhitelistedCalls`, or document/enforce that a chain-wide pause automatically extends any in-progress sale's `leadin_length`/`sale_start` by the paused duration.
- Alternatively, drive `sale_price`'s "now" from a monotonic counter of *processed relay blocks during which purchase was actually permitted*, rather than raw relay-chain block height.

### Proof of Concept
1. Runtime `R` includes `pallet_broker` and `pallet_safe_mode` with `SafeMode::WhitelistedCalls` not covering `Broker::purchase`, matching the pattern in `substrate/bin/node/runtime/src/lib.rs` (`SafeModeWhitelistedCalls` only allows `System`, `SafeMode`, `TxPause`) — [6](#0-5) .
2. `Broker::start_sales` begins a sale with a multi-block `leadin_length` (`substrate/frame/broker/src/lib.rs` `start_sales`) — [7](#0-6) .
3. Early in the leadin period, attacker Alice (any signed account, no privilege) calls `SafeMode::enter()`, reserving `EnterDepositAmount` and entering safe mode for `EnterDuration` blocks — [8](#0-7) .
4. During the `EnterDuration` window, `Broker::purchase` calls from any account (including honest bidders willing to pay near `start_price`) are rejected with `CallFiltered` because `Broker` is not in `SafeModeWhitelistedCalls` — filter logic in [9](#0-8) . Relay-chain blocks continue to advance normally.
5. `sale_price` is recomputed using `now = RCBlockNumberProviderOf::<T::Coretime>::current_block_number()`, which has advanced by the full `EnterDuration` in relay-chain blocks, driving `through` closer to (or past) 1 and the price down toward `sale.end_price` — [1](#0-0) .
6. When safe mode auto-exits, Alice immediately submits `Broker::purchase(who, price_limit)` with `price_limit` set to the now-decayed price and succeeds via `do_purchase`'s `price_limit >= price` check — [2](#0-1) , obtaining Coretime for a price far below what would have prevailed had normal purchase activity been allowed to compete throughout the leadin period — the exact structural analog of Bob "getting the sell token for a price much lower than he would initially expect before the trading pause" in the Reserve report.

	pub(crate) fn do_purchase(
		who: T::AccountId,
		price_limit: BalanceOf<T>,
	) -> Result<RegionId, DispatchError> {
		let status = Status::<T>::get().ok_or(Error::<T>::Uninitialized)?;
		let mut sale = SaleInfo::<T>::get().ok_or(Error::<T>::NoSales)?;
		Self::ensure_cores_for_sale(&status, &sale)?;

		let now = RCBlockNumberProviderOf::<T::Coretime>::current_block_number();
		ensure!(now > sale.sale_start, Error::<T>::TooEarly);
		let price = Self::sale_price(&sale, now);
		ensure!(price_limit >= price, Error::<T>::Overpriced);

		let core = Self::purchase_core(&who, price, &mut sale)?;

	/// Return whether the given call is allowed to be dispatched.
	pub fn is_allowed(call: &T::RuntimeCall) -> bool
	where
		T::RuntimeCall: GetCallMetadata,
	{
		let CallMetadata { pallet_name, .. } = call.get_call_metadata();
		// SAFETY: The `SafeMode` pallet is always allowed.
		if pallet_name == <Pallet<T> as PalletInfoAccess>::name() {
			return true;
		}

		if Self::is_entered() {
			T::WhitelistedCalls::contains(call)
		} else {
			true
		}
	}
