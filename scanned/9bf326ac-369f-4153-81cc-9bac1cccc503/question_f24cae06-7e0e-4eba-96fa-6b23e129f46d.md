`TokenDiff::token_fee()` (`contracts/defuse/core/src/intents/token_diff.rs`) returns `Pips::ZERO` for `TokenIdType::Nep171` unconditionally, and for `TokenIdType::Nep245 | TokenIdType::Imt` whenever `amount <= 1`. An attacker signs N `TokenDiff` intents in one batch, each swapping exactly 1 unit of a NEP-245 `TokenId` for a large amount of a NEP-141 `TokenId` (fee-bearing), structuring the value transfer as many `amount == 1` NEP-245 legs instead of one large NEP-141 leg. Does `fees_collected` summed across the batch equal `protocol_fee * total_value_moved`, or can the attacker route arbitrary value through zero-fee `amount<=1` NEP-245/IMT legs while the actual value transferred (via the matched `TokenDiff` counterparty) is unbounded? Impact: Critical — FEES bypass, `fee_collector` balance underpaid vs. deltas actually executed. Proof: `cargo test` executing a `TokenDiff` swap chain of `amount=1` MT legs worth more (in paired counter-value) than an equivalent single NEP-141 diff, and assert `fees_collected` for the batch is 0 despite `protocol_fee > 0`.
