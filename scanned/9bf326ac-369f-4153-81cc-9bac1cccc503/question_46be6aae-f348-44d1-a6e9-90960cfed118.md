`Engine::verify_intent_nonce()` (`contracts/defuse/core/src/engine/mod.rs`) only checks `self.state.is_valid_salt(salt)` when `VersionedNonce::maybe_from(nonce)` returns `Some`; for a legacy (32 random byte) nonce it returns `Ok(())` unconditionally, skipping salt validation entirely. If the DAO rotates/invalidates the current salt via `invalidate_salts()` intending to void all outstanding signed-but-unexecuted intents, does a leaked legacy-nonce-format `MultiPayload` still satisfy `commit_nonce() == the nonce used by this exact payload for the first and only time`, i.e. can it still settle after the salt that was supposed to invalidate it is rotated? Impact: Critical — a signed payload settles despite its authorizing context (current salt) being revoked, i.e. `nonce validity == f(salt)` fails to hold for legacy nonces. Proof: sign a `Transfer` intent with a raw (non-versioned) 32-byte nonce, call `invalidate_salts`, then execute the payload via `execute_intents` and assert it still succeeds and moves funds.
