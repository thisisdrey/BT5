### Title
`pallet-lottery` winner selection is grindable/predictable via `pallet-insecure-randomness-collective-flip` freshness gap — unprivileged ticket buyers can bias the payout - ([File: substrate/frame/lottery/src/lib.rs])

### Summary
The external report's core broken invariant is: a permissionless actor can grind an outcome-determining value because it is derived from data that is either attacker-supplied or fully predictable/public in advance, letting the actor accept or reject the resulting state only when it favors them. The local analog is `pallet-lottery`'s winner selection, which draws its "randomness" from `pallet-insecure-randomness-collective-flip` (`RandomnessCollectiveFlip`), a source that is explicitly documented as public and predictable well before it is consumed.

### Finding Description
`pallet-lottery::choose_ticket` picks the winning ticket index by calling `generate_random_number`, which in turn calls `T::Randomness::random(...)`: [1](#0-0) 

In the shipped reference runtime, `Config::Randomness` is wired to `RandomnessCollectiveFlip`: [2](#0-1) 

`pallet-insecure-randomness-collective-flip::random()` returns a seed together with a `known_since` block number equal to `current_block - 81`. Its own documentation states the value is "known far in advance by anyone observing the chain," and hashing it does **not** remove that predictability: [3](#0-2) [4](#0-3) 

Because the payout block for a lottery (`start + length + delay`) is chosen by the manager and is public, and because the `RandomMaterial` ring buffer entries that will be consumed at that payout block are fixed 81 blocks earlier, any unprivileged participant can observe the relevant parent-hash chain once it lands on-chain and precompute what `choose_ticket`/`generate_random_number` will output — before the ticket-purchase window (`config.start + config.length`) closes, whenever `length + delay < 81` (a value the lottery manager is free to configure, and which the pallet code itself flags as unresolved: `// TODO: deal with randomness freshness`): [5](#0-4) 

`do_buy_ticket` lets any signed account purchase a ticket at any point before `config.start + config.length`, and the ticket index assigned is simply the current `TicketsCount`: [6](#0-5) 

This is the direct structural analog of the external report's `proposeBlock()` bug: there, the proposer XORs a self-chosen `blobHash` with predictable, publicly-known values (`block.prevrandao`, block number) and grinds until the derived "difficulty" is favorable. Here, an unprivileged ticket buyer combines knowledge of a fully-predictable "random" seed (public 81 blocks in advance) with control over *when* and *whether* to submit `buy_ticket`, letting them decide to participate only in lotteries/tickets they can already predict will win, or skip participation in unfavorable draws — no validator, collator, or admin collusion is required, and no existing guard checks freshness of the seed relative to the ticket-purchase deadline.

### Impact Explanation
`on_initialize` unconditionally transfers the entire lottery pot to `Self::choose_account()`'s result: [7](#0-6) 

If the winner can be predicted before the ticket window closes, the "random" selection collapses into attacker-chosen selection: an unprivileged user can guarantee they are the payout beneficiary (theft of pooled funds from other honest ticket buyers) or otherwise manipulate who wins, breaking the "settle exactly once to the rightful beneficiary" invariant for pallet-held value.

### Likelihood Explanation
Likelihood depends entirely on the `delay`/`length` configuration relative to the 81-block freshness window of `RandomnessCollectiveFlip`, which is set by `ManagerOrigin` via `start_lottery`, not by the attacker. No malicious validator, governance abuse, or leaked key is needed on the attacker's side — only observation of public chain state and a well-known, extensively-documented weakness of the randomness source that the pallet is wired to in the reference runtime. The pallet's own code comments (`TODO: deal with randomness freshness`) and the collective-flip pallet's README (`DO NOT USE IN PRODUCTION`) confirm this is a real, unaddressed exposure rather than a theoretical concern.

### Recommendation
- Do not use `pallet-insecure-randomness-collective-flip` as the `Randomness` implementation for `pallet-lottery` (or any value-bearing pallet) in production runtimes; require a VRF-based source (e.g., BABE `RandomnessFromTwoEpochsAgo`) with delay guarantees exceeding the ticket-purchase window.
- Add an explicit runtime-level or pallet-level invariant that `config.delay` (and the freshness of the chosen `Randomness` source) must exceed the source's `known_since` staleness bound, rejecting `start_lottery` configurations that violate it.
- Consider committing to ticket purchases with a hash-then-reveal scheme so the seed cannot be pre-computed relative to entry decisions.

### Proof of Concept
1. Manager calls `start_lottery(price, length, delay, repeat)` with `length + delay < 81` (permitted by the pallet, no explicit lower bound check on freshness).
2. An unprivileged user monitors block headers; once the chain progresses past `payout_block - 81`, the `RandomMaterial` ring buffer entries `RandomnessCollectiveFlip` will use for the payout block are fully known (all needed parent hashes are already finalized/public), see `random()`'s use of `RandomMaterial::<T>::get()`: [8](#0-7) .
3. The user computes `generate_random_number` offline for candidate `TicketsCount` values (the ticket index space) and determines the exact `TicketsCount` value (or range, given modulo-bias retries bounded by `MaxGenerateRandom`) that would make them (or an account they control) the winning ticket index.
4. The user calls `buy_ticket` at the precise moment `TicketsCount` equals the predicted winning index (possible since `TicketsCount` is public state readable before submitting the extrinsic), guaranteeing their ticket wins the full pot at `on_initialize`.

	/// Logic for buying a ticket.
	fn do_buy_ticket(caller: &T::AccountId, call: &<T as Config>::RuntimeCall) -> DispatchResult {
		// Check the call is valid lottery
		let config = Lottery::<T>::get().ok_or(Error::<T>::NotConfigured)?;
		let block_number = frame_system::Pallet::<T>::block_number();
		ensure!(
			block_number < config.start.saturating_add(config.length),
			Error::<T>::AlreadyEnded
		);
		ensure!(T::ValidateCall::validate_call(call), Error::<T>::InvalidCall);
		let call_index = Self::call_to_index(call)?;
		let ticket_count = TicketsCount::<T>::get();
		let new_ticket_count = ticket_count.checked_add(1).ok_or(ArithmeticError::Overflow)?;
		// Try to update the participant status
		Participants::<T>::try_mutate(
			&caller,
			|(lottery_index, participating_calls)| -> DispatchResult {
				let index = LotteryIndex::<T>::get();
				// If lottery index doesn't match, then reset participating calls and index.
				if *lottery_index != index {
					*participating_calls = Default::default();
					*lottery_index = index;
				} else {
					// Check that user is not already participating under this call.
					ensure!(
						!participating_calls.iter().any(|c| call_index == *c),
						Error::<T>::AlreadyParticipating
					);
				}
				participating_calls.try_push(call_index).map_err(|_| Error::<T>::TooManyCalls)?;
				// Check user has enough funds and send it to the Lottery account.
				T::Currency::transfer(caller, &Self::account_id(), config.price, KeepAlive)?;
				// Create a new ticket.
				TicketsCount::<T>::put(new_ticket_count);
				Tickets::<T>::insert(ticket_count, caller.clone());
				Ok(())
			},
		)?;

		Self::deposit_event(Event::<T>::TicketBought { who: caller.clone(), call_index });

		Ok(())
	}

	/// Randomly choose a winning ticket from among the total number of tickets.
	/// Returns `None` if there are no tickets.
	fn choose_ticket(total: u32) -> Option<u32> {
		if total == 0 {
			return None;
		}
		let mut random_number = Self::generate_random_number(0);

		// Best effort attempt to remove bias from modulus operator.
		for i in 1..T::MaxGenerateRandom::get() {
			if random_number < u32::MAX - u32::MAX % total {
				break;
			}

			random_number = Self::generate_random_number(i);
		}

		Some(random_number % total)
	}

	/// Generate a random number from a given seed.
	/// Note that there is potential bias introduced by using modulus operator.
	/// You should call this function with different seed values until the random
	/// number lies within `u32::MAX - u32::MAX % n`.
	/// TODO: deal with randomness freshness
	/// https://github.com/paritytech/substrate/issues/8311
	fn generate_random_number(seed: u32) -> u32 {
		let (random_seed, _) = T::Randomness::random(&(T::PalletId::get(), seed).encode());
		let random_number = <u32>::decode(&mut random_seed.as_ref())
			.expect("secure hashes should always be bigger than u32; qed");
		random_number
	}

impl<T: Config> Randomness<T::Hash, BlockNumberFor<T>> for Pallet<T> {
	/// This randomness uses a low-influence function, drawing upon the block hashes from the
	/// previous 81 blocks. Its result for any given subject will be known far in advance by anyone
	/// observing the chain. Any block producer has significant influence over their block hashes
	/// bounded only by their computational resources. Our low-influence function reduces the actual
	/// block producer's influence over the randomness, but increases the influence of small
	/// colluding groups of recent block producers.
	///
	/// WARNING: Hashing the result of this function will remove any low-influence properties it has
	/// and mean that all bits of the resulting value are entirely manipulatable by the author of
	/// the parent block, who can determine the value of `parent_hash`.
	fn random(subject: &[u8]) -> (T::Hash, BlockNumberFor<T>) {
		let block_number = frame_system::Pallet::<T>::block_number();
		let index = block_number_to_index::<T>(block_number);

		let hash_series = RandomMaterial::<T>::get();
		let seed = if !hash_series.is_empty() {
			// Always the case after block 1 is initialized.
			hash_series
				.iter()
				.cycle()
				.skip(index)
				.take(RANDOM_MATERIAL_LEN as usize)
				.enumerate()
				.map(|(i, h)| (i as i8, subject, h).using_encoded(T::Hashing::hash))
				.triplet_mix()
		} else {
			T::Hash::default()
		};

		(seed, block_number.saturating_sub(RANDOM_MATERIAL_LEN.into()))
	}
