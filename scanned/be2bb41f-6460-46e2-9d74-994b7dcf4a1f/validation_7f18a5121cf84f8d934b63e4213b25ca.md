This is the same address-derivation scheme that made the `pallet-revive` reentrant-instantiate collision possible.

`pallet-contracts`'s `push_frame` (`substrate/frame/contracts/src/exec.rs:909-948`) only writes the cached `ContractInfo` into `ContractInfoOf` when the *parent* frame's `entry_point` is `Call` (line 927-931: `if let (CachedContract::Cached(contract), ExportedFunction::Call) = ...`). When the parent frame is itself a `Constructor` (i.e., we are still inside a contract's own constructor), nothing is flushed to storage, and `push_frame` contains **no check** equivalent to the one added to `pallet-revive` in `substrate/frame/revive/src/exec.rs:1238-1246` (`self.frames().any(|f| f.entry_point == ExportedFunction::Constructor && f.account_id == frame.account_id)`), which returns `DuplicateContract` for a colliding re-entrant `Constructor` frame. `ContractInfo::new` (`substrate/frame/contracts/src/storage.rs:81-110`) only guards via `<ContractInfoOf<T>>::contains_key(account)`, which is blind to an address whose `ContractInfo` is still sitting uncommitted inside an ancestor `Constructor` frame — the on-chain analog of `isContract()`/`extcodesize` returning `0` for an account that is mid-construction.

### Title
Reentrant CREATE2-style instantiate collision in `pallet-contracts` bypasses the `DuplicateContract` guard during constructor execution - (File: `substrate/frame/contracts/src/exec.rs`)

### Summary
`pallet-contracts` derives salted contract addresses independently of the deployer's nonce (`substrate/frame/contracts/src/address.rs:57-67`), and its `push_frame`/`ContractInfo::new` collision guard only detects an existing contract by checking on-chain storage (`ContractInfoOf`), which is not updated for an address whose constructor is still executing on the call stack. This lets a contract's constructor re-enter and instantiate a second contract at the same address (same code hash + salt) while the first constructor is unfinished, exactly mirroring the reported bug class: a status check (`isContract`/`extcodesize`, here `ContractInfoOf::contains_key`) that returns "not a contract yet" while the account is mid-construction, letting privileged logic run twice for what should be a single, exclusively-owned address.

### Finding Description
- `DefaultAddressGenerator::contract_address` (`substrate/frame/contracts/src/address.rs:57-67`) computes `hash("contract_addr_v1" ++ deployer ++ code_hash ++ input_data ++ salt)`. This is deliberately nonce-independent so a given `(deployer, code_hash, input_data, salt)` tuple always maps to the same address — a direct analog of `CREATE2`.
- `ContractInfo::new` (`substrate/frame/contracts/src/storage.rs:81-110`) is the sole duplicate guard, and it only checks `<ContractInfoOf<T>>::contains_key(account)` — i.e., whether the contract's info has already been committed to storage.
- `push_frame` (`substrate/frame/contracts/src/exec.rs:909-948`) commits the *cached* `ContractInfo` to `ContractInfoOf` only when the top frame being nested-from is a `Call` frame (`ExportedFunction::Call`, line 927-931). For a nested instantiate whose *caller* frame is itself a `Constructor` (i.e. contract A's constructor calling out to instantiate contract B, or — critically — a factory contract's `Call` frame instantiating the *same* address twice within one transaction where the first instantiate's `Constructor` frame is still on the stack) the address's `ContractInfo` is never flushed to `ContractInfoOf` before the second `push_frame` call runs `ContractInfo::new` again.
- `pallet-revive` had exactly this bug (see `prdoc/pr_12645.prdoc` and `substrate/frame/revive/src/exec.rs:1238-1246`, test `reentrant_instantiate_at_same_address_is_rejected` in `substrate/frame/revive/src/exec/tests.rs:1270-1350`): a `Constructor` frame re-enters the deployer, which instantiates the same `(code, salt)` pair again, resolving to the identical address and running a second constructor for one account, leaking a consumer reference/code refcount and orphaning a second child-trie storage deposit. The fix added an explicit stack scan for a colliding in-flight `Constructor` frame in `push_frame`.
- The `prdoc/pr_12645.prdoc` fix's `crates:` section lists only `pallet-revive` bumped — `pallet-contracts` was not touched. Reviewing `substrate/frame/contracts/src/exec.rs::push_frame` shows it has no equivalent stack-scan guard for colliding `Constructor` frames; its only collision check is the storage-backed `ContractInfoOf::contains_key`, which is exactly the check proven insufficient in `pallet-revive`.

### Impact Explanation
A second constructor frame executing for the address that a first (still in-flight) constructor already claims duplicates side effects that are meant to happen exactly once per address: consumer-reference accounting, code refcount increments, and storage-deposit/child-trie allocation. This can permanently leak consumer references (preventing account reaping / causing accounting drift) and orphan a storage deposit in a second child trie that is never correctly reconciled, i.e., fund/storage-deposit lock and duplicate "settlement" of contract-instantiation side effects for what should be one exclusively-owned account — matching the required impact class of "duplicate settlement" / "permanent user-fund or bridge-state lock" via a public, unprivileged entry point (any account can deploy a factory contract and trigger this from an ordinary `instantiate` extrinsic, no validator/relayer/admin needed).

### Likelihood Explanation
Reachable by any unprivileged account deploying an ordinary Solidity/ink!-style factory contract that re-enters itself (or another contract in the call graph) to instantiate the identical `(code_hash, salt)` pair before the first constructor frame completes — no special permissions, and it mirrors a pattern parity's own engineers found practical enough to patch in the sibling `pallet-revive` pallet in `pr_12645`. The exact mechanics (nonce-independent salted address, storage-only duplicate check, guard only in `pallet-revive`) are confirmed directly in the code; I was not able to fully trace whether a downstream caller of `Stack::run_instantiate`/`bare_instantiate` in `pallet-contracts` imposes an additional re-entrancy restriction that would block this specific call graph (e.g., whether instantiate-into-instantiate-with-same-address is exercised by any existing test) since I could not locate a `pallet-contracts` equivalent of `reentrant_instantiate_at_same_address_is_rejected` in the index — this should be verified with a live reproduction.

### Recommendation
Port the `pallet-revive` fix to `pallet-contracts`: in `substrate/frame/contracts/src/exec.rs::push_frame`, after constructing the new frame, scan `self.frames()` for an existing `Constructor` frame with the same `account_id` and reject with `Error::<T>::DuplicateContract` before pushing, matching the guard already implemented at `substrate/frame/revive/src/exec.rs:1238-1246`.

### Proof of Concept
1. Deploy a factory contract `F` whose `Call` entry point, on first invocation, calls `seal_instantiate`/`ext.instantiate` with a fixed `(code_hash = C, salt = S)` to instantiate contract `B` at address `X = contract_address(F, C, [], S)`.
2. `B`'s constructor (`Constructor` entry point) re-enters `F`'s `Call` export (analogous to `reentrant_instantiate_at_same_address_is_rejected` in `substrate/frame/revive/src/exec/tests.rs:1270-1350`), which invokes `ext.instantiate` again with the same `(C, S)` — this resolves to the identical address `X` because `DefaultAddressGenerator::contract_address` is nonce-independent (`substrate/frame/contracts/src/address.rs:57-67`).
3. `push_frame` (`substrate/frame/contracts/src/exec.rs:909-948`) calls `ContractInfo::new(&X, ...)` a second time; since `ContractInfoOf::contains_key(X)` is still `false` (the first `Constructor` frame for `X` has not popped and committed to storage), the guard at `substrate/frame/contracts/src/storage.rs:86-88` passes and a second `Constructor` frame for account `X` is pushed and executed, in place of the `DuplicateContract` rejection that `pallet-revive` now enforces.

```rust
impl<T: Config> ContractInfo<T> {
	/// Constructs a new contract info **without** writing it to storage.
	///
	/// This returns an `Err` if an contract with the supplied `account` already exists
	/// in storage.
	pub fn new(
		account: &AccountIdOf<T>,
		nonce: u64,
		code_hash: CodeHash<T>,
	) -> Result<Self, DispatchError> {
		if <ContractInfoOf<T>>::contains_key(account) {
			return Err(Error::<T>::DuplicateContract.into());
		}

		let trie_id = {
			let buf = (account, nonce).using_encoded(T::Hashing::hash);
			buf.as_ref()
				.to_vec()
				.try_into()
				.expect("Runtime uses a reasonable hash size. Hence sizeof(T::Hash) <= 128; qed")
		};

		let contract = Self {
			trie_id,
			code_hash,
			storage_bytes: 0,
			storage_items: 0,
			storage_byte_deposit: Zero::zero(),
			storage_item_deposit: Zero::zero(),
			storage_base_deposit: Zero::zero(),
			delegate_dependencies: Default::default(),
		};

		Ok(contract)
	}
```

```rust
	/// Create a subsequent nested frame.
	fn push_frame(
		&mut self,
		frame_args: FrameArgs<T, E>,
		value_transferred: BalanceOf<T>,
		gas_limit: Weight,
		deposit_limit: BalanceOf<T>,
		read_only: bool,
	) -> Result<E, ExecError> {
		if self.frames.len() == T::CallStack::size() {
			return Err(Error::<T>::MaxCallDepthReached.into());
		}

		// We need to make sure that changes made to the contract info are not discarded.
		// See the `in_memory_changes_not_discarded` test for more information.
		// We do not store on instantiate because we do not allow to call into a contract
		// from its own constructor.
		let frame = self.top_frame();
		if let (CachedContract::Cached(contract), ExportedFunction::Call) =
			(&frame.contract_info, frame.entry_point)
		{
			<ContractInfoOf<T>>::insert(frame.account_id.clone(), contract.clone());
		}

		let frame = top_frame_mut!(self);
		let nested_gas = &mut frame.nested_gas;
		let nested_storage = &mut frame.nested_storage;
		let (frame, executable, _) = Self::new_frame(
			frame_args,
			value_transferred,
			nested_gas,
			gas_limit,
			nested_storage,
			deposit_limit,
			self.determinism,
			read_only,
		)?;
		self.frames.push(frame);
		Ok(executable)
	}
```

```rust
#[test]
fn reentrant_instantiate_at_same_address_is_rejected() {
	// EIP-684: while `B1` constructs at address `X`, its constructor re-enters the deployer to
	// instantiate the same code+salt. That resolves to `X` again and must be rejected rather
	// than run a second constructor for one account.
	let salt = [42u8; 32];

	let constructor_ch = MockLoader::insert(Constructor, |ctx, _| {
		// Re-enter the deployer (BOB) while we are still being constructed.
		ctx.ext
			.call(
				&CallResources::NoLimits,
				&BOB_ADDR,
				U256::zero(),
				vec![],
				ReentrancyProtection::AllowReentry,
				false,
			)
			.unwrap();
		exec_success()
	});

	let invocations = Rc::new(RefCell::new(0u32));
	let second_instantiate_error = Rc::new(RefCell::new(None::<DispatchError>));
	let factory_ch = MockLoader::insert(Call, {
		let invocations = Rc::clone(&invocations);
		let second_instantiate_error = Rc::clone(&second_instantiate_error);
		move |ctx, _| {
			*invocations.borrow_mut() += 1;
			let n = *invocations.borrow();
			// Bound the recursion in case the guard fails to reject the collision.
			if n <= 2 {
				let min_balance = <Test as Config>::Currency::minimum_balance();
				let value = Pallet::<Test>::convert_native_to_evm(min_balance);
				let result = ctx.ext.instantiate(
					&CallResources::NoLimits,
					Code::Existing(constructor_ch),
					value,
					vec![],
					Some(&salt),
				);
				if n == 2 {
					if let Err(err) = &result {
						*second_instantiate_error.borrow_mut() = Some(err.error);
					}
				}
			}
			exec_success()
		}
	});

	ExtBuilder::default()
		.with_code_hashes(MockLoader::code_hashes())
		.existential_deposit(15)
		.build()
		.execute_with(|| {
			let min_balance = <Test as Config>::Currency::minimum_balance();
			set_balance(&ALICE, min_balance * 1000);
			place_contract(&BOB, factory_ch);
			let origin = Origin::from_account_id(ALICE);
			let mut meter =
				TransactionMeter::<Test>::new_from_limits(WEIGHT_LIMIT, min_balance * 100).unwrap();

			// `B1` still constructs; only the colliding re-entrant instantiate fails.
			assert_ok!(MockStack::run_call(
				origin,
				BOB_ADDR,
				&mut meter,
				Pallet::<Test>::convert_native_to_evm(min_balance * 100),
				vec![],
				&ExecConfig::new_substrate_tx(),
			));

			// Initial call plus one re-entry; without the guard it would recurse further.
			assert_eq!(*invocations.borrow(), 2);
			assert_eq!(
				*second_instantiate_error.borrow(),
				Some(<Error<Test>>::DuplicateContract.into())
			);
		});
}
```
