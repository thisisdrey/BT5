## Analog Found: Vacuous 100% "support" when zero eligible voters exist in `pallet-ranked-collective`

### Title
Division-by-zero in `Perbill::from_rational` causes `ranked-collective::Tally::support()` to vacuously return 100% support with zero voters, letting a referendum pass on an empty voter class - (File: `substrate/frame/ranked-collective/src/lib.rs`)

### Summary
The audited Solidity bug is a classic "zero-denominator, vacuous-truth" quorum bypass: `0 >= 0` evaluates `true`, letting an empty-membership DAO proposal pass with no votes cast. The exact same class of bug exists in `pallet-ranked-collective`'s `Tally::support()` implementation, which relies on `Perbill::from_rational(0, 0)`. Substrate's `PerThing::from_rational` default implementation silently converts a `0/0` division error into `Self::one()` (100%) rather than `0%`, so a poll/track whose minimum-rank voter pool is currently empty is treated as having **full support** even though nobody voted.

### Finding Description
`pallet-ranked-collective`'s `VoteTally` implementation computes support as: [1](#0-0) 

```rust
fn support(&self, class: ClassOf<T, I>) -> Perbill {
    Perbill::from_rational(self.bare_ayes, M::get_max_voters(class))
}
```

`get_max_voters` is implemented as the count of members at the class's minimum rank: [2](#0-1) 

```rust
impl<T: Config<I>, I: 'static> GetMaxVoters for Pallet<T, I> {
    type Class = ClassOf<T, I>;
    fn get_max_voters(c: Self::Class) -> MemberIndex {
        MemberCount::<T, I>::get(T::MinRankOfClass::convert(c))
    }
}
```

If no member currently holds the minimum rank required by a given poll class (e.g. a newly-configured high-rank track, or a track whose rank tier has been fully vacated through demotions/removals), `MemberCount` for that rank is `0`. With zero ayes cast, `Tally::support()` then evaluates `Perbill::from_rational(0, 0)`.

`Perbill::from_rational` (the default trait method, not `_with_rounding`) is defined as: [3](#0-2) 

```rust
fn from_rational<N>(p: N, q: N) -> Self
where ... {
    Self::from_rational_with_rounding(p, q, Rounding::Down).unwrap_or_else(|_| Self::one())
}
```

`from_rational_with_rounding` returns `Err(())` when `q.is_zero()`: [4](#0-3) 

```rust
fn from_rational_with_rounding<N>(p: N, q: N, r: Rounding) -> Result<Self, ()>
where ... {
    // q cannot be zero.
    if q.is_zero() { return Err(()) }
    ...
}
```

but the caller (`from_rational`) swallows that `Err` and substitutes `Self::one()` — i.e. **100%** — instead of `0%`. This "0/0 → 1" fallback is confirmed by the project's own fuzz test comment: "the perfect_ratio is `1` when `a == 0 && b == 0`" [5](#0-4) .

Unlike `pallet-conviction-voting`'s `Tally::approval()`, which was explicitly patched to special-case a zero-vote total and return `Perbill::zero()` (see `pr_11567.prdoc` [6](#0-5) , and the guarded code at [7](#0-6) ), `ranked-collective`'s `support()` has **no such guard**. Its `approval()` was hardened against zero-division with `1.max(self.ayes + self.nays)` [8](#0-7) , but `support()` was left unprotected, still calling `Perbill::from_rational` directly on a denominator that can legitimately be zero.

`pallet-referenda`'s `is_passing` gates approval purely on this `support()`/`approval()` output against the track's curves: [9](#0-8) 

```rust
fn is_passing(...) -> bool {
    let x = Perbill::from_rational(elapsed.min(period), period);
    support_needed.passing(x, tally.support(id)) &&
        approval_needed.passing(x, tally.approval(id))
}
```

Since `support()` reports 100% instead of 0%, `support_needed.passing(...)` is satisfied for essentially any curve/track configuration immediately, regardless of the actual (zero) voter turnout.

### Impact Explanation
This breaks the fundamental "referendum must have genuine turnout among eligible rank-holders" invariant, corrupting the `support` component of the tally used by `pallet-referenda` to decide `Confirmed`/`Approved`. On a rank-gated track (e.g. Fellowship or Ambassador tracks seen in `collectives-westend` runtimes) where the required rank tier is momentarily or permanently empty of members, a referendum can reach and stay in the `Confirming` state, and ultimately get `Approved` and dispatched with **zero votes cast**, because `min_support` curves — even ones with a non-trivial floor — are satisfied by the fabricated 100% value. This is unauthorized/forged proof-of-consensus acceptance leading to arbitrary privileged dispatch (fellowship-controlled origins, treasury spends, etc.), matching the "runtime bugs that compromise intended behavior" / "unauthorized execution or origin escalation" impact classes.

### Likelihood Explanation
No malicious peer, validator, collator, or governance actor is required. Any track configuration where the minimum-rank tier can be (even transiently) empty — during collective bootstrapping, after demotions/removals of the last member at a rank, or simply a rank tier that was never populated — creates the zero-denominator condition automatically. An unprivileged account able to submit or advance referenda on such a track can trigger and exploit this; no votes need to be cast at all, only track/timing conditions must line up (submission + waiting out prepare/decision/confirm periods), all of which are normal public interactions with `pallet-referenda`.

### Recommendation
Guard `ranked-collective::Tally::support()` exactly as `conviction-voting::Tally::approval()` was fixed: explicitly check for a zero `get_max_voters(class)` denominator and return `Perbill::zero()` rather than delegating to `Perbill::from_rational`, e.g.:
```rust
fn support(&self, class: ClassOf<T, I>) -> Perbill {
    let max_voters = M::get_max_voters(class);
    if max_voters.is_zero() {
        Perbill::zero()
    } else {
        Perbill::from_rational(self.bare_ayes, max_voters)
    }
}
```
More broadly, audit every other caller of `PerThing::from_rational` (as opposed to `from_rational_with_rounding`) in governance/tally-sensitive code paths, since the "0/0 → 100%" fallback is a general footgun that silently converts a division error into a maximal, not minimal, value.

### Proof of Concept
1. Configure (or naturally reach a state in) a `pallet-referenda` track whose `T::MinRankOfClass` maps to a rank tier that currently has zero members (e.g., all rank-N members demoted/removed, or a newly added high tier never yet populated).
2. Submit a referendum on that track and pay the decision deposit; let it enter the deciding phase without anyone casting a vote (`bare_ayes = 0`, `ayes = 0`, `nays = 0`).
3. On each scheduler-driven service call, `is_passing` computes `tally.support(id)` via `Tally::support`, which evaluates `Perbill::from_rational(0, 0)`.
4. `from_rational_with_rounding` returns `Err(())` because `q.is_zero()`, and `from_rational`'s `unwrap_or_else(|_| Self::one())` converts this into `Perbill::one()` (100%) — see [3](#0-2) .
5. `support_needed.passing(x, Perbill::one())` is true for any curve, so the referendum begins/continues Confirming and is ultimately `Approved`/dispatched with the associated privileged origin — despite zero real votes and zero eligible voters, mirroring the reported Solidity DAO's vacuous quorum/vote-pass bug.
