### Title
Dust `total_tokens_staked` in `pallet-asset-rewards` can blow up `reward_per_token` and permanently brick `stake`/`unstake`/`harvest_rewards` - (File: `substrate/frame/asset-rewards/src/lib.rs`)

### Summary
`pallet-asset-rewards` computes a monotonically-increasing `reward_per_token_stored` accumulator that is scaled by `PRECISION_SCALING_FACTOR` and divided by `pool_info.total_tokens_staked`, exactly the same "reward index / total supply" pattern flagged in the external report (`index = emissionPerSecond * timeDelta * 10**decimals / totalBalance + currentIndex`). Because `total_tokens_staked` can be driven to a dust value (or is attacker-influenced across the pool's lifetime), the per-block increment to `reward_per_token` can become arbitrarily large. Every state-mutating entrypoint (`stake`, `unstake`, `harvest_rewards`, `set_pool_reward_rate_per_block`) unconditionally calls `update_pool_and_staker_rewards` → `reward_per_token`, which uses checked (`ensure_mul`/`ensure_div`/`ensure_add`) arithmetic. Once the accumulator would overflow `T::Balance`, this call returns `Err`, which propagates out of the extrinsic — causing a permanent, unconditional revert on all future calls to `stake`, `unstake`, and `harvest_rewards` for that pool.

### Finding Description
The reward accrual logic lives in `Pallet::<T>::reward_per_token`: [1](#0-0) 

```rust
pub(super) fn reward_per_token(
    pool_info: &PoolInfoFor<T>,
) -> Result<T::Balance, DispatchError> {
    if pool_info.total_tokens_staked.is_zero() {
        return Ok(pool_info.reward_per_token_stored);
    }
    ...
    Ok(pool_info.reward_per_token_stored.ensure_add(
        pool_info
            .reward_rate_per_block
            .ensure_mul(rewardable_blocks_elapsed.into())?
            .ensure_mul(PRECISION_SCALING_FACTOR.into())?
            .ensure_div(pool_info.total_tokens_staked)?,
    )?)
}
```

This mirrors the reported formula `emissionPerSecond * timeDelta * 10**decimals / totalBalance + currentIndex` almost exactly, substituting per-block reward rate for per-second emission and a fixed `PRECISION_SCALING_FACTOR` for `10**decimals`. The only guard against a dust `total_tokens_staked` is the `is_zero()` check — there is no minimum-threshold check as recommended in the external report's remediation. If `total_tokens_staked` is small (e.g. because almost all stakers unstaked, leaving a residual staker with a tiny amount, or because a large `reward_rate_per_block` was set by the admin relative to a small stake), the quotient `reward_rate_per_block * blocks * PRECISION_SCALING_FACTOR / total_tokens_staked` grows very fast per block that passes without anyone calling into the pool.

Unlike the Solidity report where the index has a fixed `uint104` width, here `T::Balance` (a runtime-configurable, typically `u128`) is wider, but the same overflow mechanism exists via the checked-arithmetic helpers (`EnsureMul`/`EnsureDiv`/`EnsureAdd`), which return `Err(ArithmeticError)` instead of saturating/wrapping. This propagates through `update_pool_and_staker_rewards`: [2](#0-1) 

Every mutating call is guarded by "always start by updating the pool and staker rewards", meaning `reward_per_token`'s success is a hard precondition for `stake`, `unstake`, and `harvest_rewards`: [3](#0-2) [4](#0-3) [5](#0-4) 

If the checked arithmetic in `reward_per_token` ever returns `Err`, `unstake` fails deterministically for every account in the pool, including the residual dust staker who is the direct cause and any other staker who joins later, because `update_pool_and_staker_rewards` is invoked unconditionally before the freeze can be released. There is no code path that lets a staker withdraw their frozen `staked_asset_id` tokens without first passing through this failing accrual step, so the freeze (`T::AssetsFreezer::decrease_frozen`) can never be reached once overflow occurs — a permanent fund lock, analogous to the report's "DoS aToken transfers" impact, except here it is a genuine unrecoverable lock rather than merely stalled reward accrual (there is no "just stop accruing rewards" fallback — the whole extrinsic reverts).

### Impact Explanation
This breaks the "Balances/assets/staking must conserve value and settle exactly once" and "message/queue/payout state advances only after execution succeeds atomically" invariants: once the accumulator computation overflows, `unstake` and `harvest_rewards` become permanently unusable for the pool, and any staked/frozen tokens for every staker in that pool become permanently locked (freeze can never be lifted), and unclaimed rewards can never be harvested. This is a public, unprivileged-reachable state (any staker can drive `total_tokens_staked` toward dust by unstaking down to a residual amount, or simply by waiting long enough with a small enough remaining stake and non-trivial reward rate), causing a permanent user-fund lock — matching the "permanent user-fund lock" impact category explicitly listed as in-scope.

### Likelihood Explanation
The pool admin sets `reward_rate_per_block` and can only increase it (`set_pool_reward_rate_per_block` enforces `new_reward_rate_per_block > pool_info.reward_rate_per_block`), so any reasonably active pool with several stakers unstaking over time can end with a small `total_tokens_staked`. No unprivileged action is required beyond ordinary `unstake` calls draining the pool, and no explicit dust threshold check exists to stop the accrual once the pool's staked amount becomes tiny relative to `reward_rate_per_block * PRECISION_SCALING_FACTOR`, so the precondition (dust total supply co-existing with nonzero reward rate over enough elapsed blocks) is realistically reachable without needing a malicious admin, validator, or off-chain actor.

### Recommendation
Adopt the same remediation pattern verified for the referenced report: either (a) increase headroom / use saturating arithmetic that cannot revert while still preserving reward-difference semantics (only deltas of the accumulator matter, so wraparound / saturation is safe), or (b) skip reward accrual entirely (return `Ok(pool_info.reward_per_token_stored)`) when `total_tokens_staked` is below a sane minimum threshold, exactly like the "Do Not Accrue Index When Normalized Total Supply is Below a Threshold" recommendation in the source report. Critically, avoid letting `reward_per_token`'s checked arithmetic ever return `Err` from within `stake`/`unstake`/`harvest_rewards`, since a hard failure there blocks fund withdrawal, not just reward accrual.

### Proof of Concept
1. Admin creates a pool with `reward_rate_per_block = R` (a large value) via `create_pool`.
2. Staker A stakes a large amount; staker B stakes `1` unit (dust).
3. Staker A calls `unstake` for their full amount, leaving `pool_info.total_tokens_staked == 1`.
4. No one interacts with the pool for `N` blocks (trivially achievable — no permissioned actor required, just elapsed time).
5. On the next call to `stake`/`unstake`/`harvest_rewards` (by B or anyone), `reward_per_token` computes `reward_rate_per_block.ensure_mul(N)?.ensure_mul(PRECISION_SCALING_FACTOR)?.ensure_div(1)?` which, for sufficiently large `R * N * PRECISION_SCALING_FACTOR`, exceeds `T::Balance::MAX` and returns `Err(ArithmeticError::Overflow)`.
6. From this point on, `unstake` for staker B (or anyone else in the pool) always fails at `update_pool_and_staker_rewards`, permanently freezing B's staked tokens (and any unharvested rewards) with no available extrinsic to recover them. [2](#0-1)

		pub fn stake(origin: OriginFor<T>, pool_id: PoolId, amount: T::Balance) -> DispatchResult {
			let staker = ensure_signed(origin)?;

			// Always start by updating staker and pool rewards.
			let pool_info = Pools::<T>::get(pool_id).ok_or(Error::<T>::NonExistentPool)?;
			let staker_info = PoolStakers::<T>::get(pool_id, &staker).unwrap_or_default();

				Self::update_pool_and_staker_rewards(&pool_info, &staker_info)?;

			T::AssetsFreezer::increase_frozen(
				pool_info.staked_asset_id.clone(),
				&FreezeReason::Staked.into(),
				&staker,
				amount,
			)?;

			// Update Pools.
			pool_info.total_tokens_staked.ensure_add_assign(amount)?;

			Pools::<T>::insert(pool_id, pool_info);

			// Update PoolStakers.
			staker_info.amount.ensure_add_assign(amount)?;
			PoolStakers::<T>::insert(pool_id, &staker, staker_info);

			// Emit event.
			Self::deposit_event(Event::Staked { staker, pool_id, amount });

			Ok(())
		}

		pub fn unstake(
			origin: OriginFor<T>,
			pool_id: PoolId,
			amount: T::Balance,
			staker: Option<T::AccountId>,
		) -> DispatchResult {
			let caller = ensure_signed(origin)?;
			let staker = staker.unwrap_or(caller.clone());

			// Always start by updating the pool rewards.
			let pool_info = Pools::<T>::get(pool_id).ok_or(Error::<T>::NonExistentPool)?;
			let now = T::BlockNumberProvider::current_block_number();
			ensure!(now > pool_info.expiry_block || caller == staker, BadOrigin);

			let staker_info = PoolStakers::<T>::get(pool_id, &staker).unwrap_or_default();
			let (mut pool_info, mut staker_info) =
				Self::update_pool_and_staker_rewards(&pool_info, &staker_info)?;

			// Check the staker has enough staked tokens.
			ensure!(staker_info.amount >= amount, Error::<T>::NotEnoughTokens);

			// Unfreeze staker assets.
			T::AssetsFreezer::decrease_frozen(
				pool_info.staked_asset_id.clone(),
				&FreezeReason::Staked.into(),
				&staker,
				amount,
			)?;

			// Update Pools.
			pool_info.total_tokens_staked.ensure_sub_assign(amount)?;
			Pools::<T>::insert(pool_id, pool_info);

			// Update PoolStakers.
			staker_info.amount.ensure_sub_assign(amount)?;

			if staker_info.amount.is_zero() && staker_info.rewards.is_zero() {
				PoolStakers::<T>::remove(&pool_id, &staker);
			} else {
				PoolStakers::<T>::insert(&pool_id, &staker, staker_info);
			}

			// Emit event.
			Self::deposit_event(Event::Unstaked { caller, staker, pool_id, amount });

			Ok(())
		}

			let staker_info =
				PoolStakers::<T>::get(pool_id, &staker).ok_or(Error::<T>::NonExistentStaker)?;
			let (pool_info, mut staker_info) =

			// Transfer unclaimed rewards from the pool to the staker.
			T::Assets::transfer(
				pool_info.reward_asset_id,
				&pool_info.account,
				&staker,

				// Could kill the account, but only if the pool was already almost empty.
				Preservation::Expendable,
			)?;

			// Emit event.
			Self::deposit_event(Event::RewardsHarvested {
				caller,
				staker: staker.clone(),
				pool_id,
				amount: staker_info.rewards,
			});

			// Reset staker rewards.
			staker_info.rewards = 0u32.into();

			if staker_info.amount.is_zero() {
				PoolStakers::<T>::remove(&pool_id, &staker);
			} else {
				PoolStakers::<T>::insert(&pool_id, &staker, staker_info);
			}

			Ok(())
		}

		/// Derives the current reward per token for this pool.
		pub(super) fn reward_per_token(
			pool_info: &PoolInfoFor<T>,
		) -> Result<T::Balance, DispatchError> {
			if pool_info.total_tokens_staked.is_zero() {
				return Ok(pool_info.reward_per_token_stored);
			}

			let rewardable_blocks_elapsed: u32 =
				match Self::last_block_reward_applicable(pool_info.expiry_block)
					.ensure_sub(pool_info.last_update_block)?
					.try_into()
				{
					Ok(b) => b,
					Err(_) => return Err(Error::<T>::BlockNumberConversionError.into()),
				};

			Ok(pool_info.reward_per_token_stored.ensure_add(
				pool_info
					.reward_rate_per_block
					.ensure_mul(rewardable_blocks_elapsed.into())?
					.ensure_mul(PRECISION_SCALING_FACTOR.into())?
					.ensure_div(pool_info.total_tokens_staked)?,
			)?)
		}
