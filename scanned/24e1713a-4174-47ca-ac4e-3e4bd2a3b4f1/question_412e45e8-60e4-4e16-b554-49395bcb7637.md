Target: `Contract::ft_resolve_deposit` / `NonFungibleTokenReceiver::nft_on_transfer`'s `notify_on_transfer` + `nft_resolve_deposit` re-entrant path (contracts/defuse/src/contract/tokens/nep171/deposit.rs). Attacker action: deposit an NFT via `nft_transfer_call` with `msg = DepositMessage{receiver_id: attacker, action: Notify(NotifyOnTransfer{contract_id: ATTACKER, msg})}`. `ATTACKER`'s notify handler reenters `execute_intents` with a signed `NftWithdraw` for the same `nep171` token_id (just deposited) to move it to a third account before `nft_resolve_deposit` computes its refund via `promise_result_checked_json`. Preconditions: attacker deposits token_id T on nep171 contract C; `total_supplies` tracks NFT uniqueness (`if total_supply > 1 return Err(NftAlreadyDeposited)`). Call sequence: `nft_on_transfer` -> `self.deposit()` credits attacker with 1 unit of `Nep171TokenId(C, T)`, incrementing `total_supplies` to 1 -> `notify_on_transfer` -> attacker's contract reenters `execute_intents` with `NftWithdraw` for the same token, calling `internal_sub_balance` then `total_supplies.sub` (via withdraw path) -> `.then(nft_resolve_deposit)` reads promise result and, since balance is now 0 (already withdrawn), any 'requested refund' from the notify handler gets capped by the now-zero `balance_left`, resulting in `refund_amount = 0`. Binding: for the unique NFT `Nep171TokenId(C,T)`, exactly one entity holds it in `token_balances` at any settlement point (`total_supply <= 1`, enforced at deposit time) and the depositing NFT contract C's ledger (sender loses ownership) must match exactly one Verifier account gaining it — verify the reentrant withdraw-then-notify-refund sequence can't result in C believing the NFT is still with C (full refund granted) while it's simultaneously credited on Verifier to a second address via the reentrant withdraw's receiver. Impact: Critical, a NEP-171 TokenId collision/duplication where the same physical NFT is claimed by two Verifier balances or the ledger asserts ownership inconsistent with the actual NFT custody. Proof idea: sandbox test with an nft receiver stub that reenters to withdraw the freshly-deposited NFT to a third account inside its notify handler, then assert `total_supplies` for that Nep171TokenId never exceeds 1 and no double-refund is issued to the original NFT contract.
