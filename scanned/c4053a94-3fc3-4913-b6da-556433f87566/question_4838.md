# Q4838: refresh via borrow: satisfy a bound with a value the bound was never designed 

## Question
Entering through `borrow` (mainnet/contracts/market/v0-4-market.clar:1238) while controlling the order of accrual versus price resolution inside the let, can an unprivileged attacker make `refresh` (mainnet/contracts/market/v0-market-vault.clar:171) satisfy a bound with a value the bound was never designed to admit? `refresh` rewrites `mask` and stamps `last-update` to `stacks-block-time` on every write, so the invariant that a resolved price reflects a gated feed whose inputs the caller cannot move in the same transaction would fail, yielding protocol insolvency through uncollateralised debt.
