Target: `decode_http_request` in `libsigner/src/http.rs`, which parses raw bytes off the signer's HTTP listener socket into a `SignerHttpRequest{verb, path, headers, body_offset}` before any StackerDB chunk-event body is examined. Attacker action: an unprivileged remote party opens a TCP connection to the signer's event-observer HTTP port and sends a request whose Content-Length header value is a large or malformed integer (e.g. a value far exceeding the actual body bytes sent, or non-numeric). Preconditions: the signer's HTTP event endpoint is reachable at its configured bind address; no auth is required. Call sequence: the endpoint's handler calls `decode_http_request`, then hands `body_offset` and the raw byte buffer downstream (e.g. to `decode_http_body`/JSON parsing) without re-validating that Content-Length equals actual bytes read. Equality/fault: bytes-read for the body must equal the declared Content-Length; if the handler blocks or over-reads waiting for bytes that never arrive, or under-reads and hands a truncated slice to `serde_json::from_slice`, the equality fails. Impact: Critical — a single crafted request can wedge the connection handler indefinitely (bounded per-connection DoS) or cause the parsed event to silently diverge from what was actually sent. Proof idea: a `libsigner` test opens a `TcpStream` to a local `SignerEventReceiver`, sends a header claiming `Content-Length: 999999` followed by a short body, and asserts the handler returns an `EventError` rather than blocking forever or parsing an incomplete `StackerDBChunksEvent`.
