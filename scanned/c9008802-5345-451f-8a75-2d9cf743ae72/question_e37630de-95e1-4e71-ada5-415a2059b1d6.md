Target: `TokenDiff` intent (contracts/defuse/core/src/intents/token_diff.rs) whose `TokenDeltas` map is keyed by `TokenId` produced via `to_string()`/`DisplayFromStr` in serialized form. Attacker action: sign a `MultiPayload` with a `TokenDiff` intent listing two entries whose `TokenId` keys are constructed from raw JSON strings that differ in whitespace/case but which the borsh-serialized/on-chain `TokenId` enum treats as identical after some normalization elsewhere in the engine. Preconditions: attacker has balances in both a real token and a lookalike token id. Call sequence: engine deserializes `DefusePayload` -> `TokenDiff::deltas: BTreeMap<TokenId, i128>` -> applies to `token_balances`, requiring the sum of deltas across the diff-matched intents to net to zero. Binding: `sum(deltas for TokenId t across a matched TokenDiff group) == 0` for the exact same `TokenId` bytes on both sides of the trade. Impact: Critical - if the two `TokenId` instances used by counterparties in a matched diff are not byte-identical for the same intended asset, the conservation invariant (`CONSERVATION: sum of token_balances changes == 0`) is violated, letting one side under-deliver a lookalike asset while draining the other side's real balance. Proof idea: near-workspaces test executing a two-party `TokenDiff` match with a maliciously near-identical `TokenId` string on one leg, asserting the intent either fails atomically or nets exactly to zero per real `TokenId`.
