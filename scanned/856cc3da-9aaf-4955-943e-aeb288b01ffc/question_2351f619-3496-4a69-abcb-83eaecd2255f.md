Attacker action: submit a `StackerDBChunkData` over the wire with `data` field containing byte length claiming to be within `chunk_size` in the header but with the actual serialized `Vec<u8>` length field (as read by `stackerdb_chunk_hex_deserialize`) inconsistent with bytes available. Preconditions: raw bytes fed to the `libsigner`/`libstackerdb` deserializer, no valid signature required to trigger the parse bug itself (parsing precedes signature check). Equality/fault: bytes allocated for `data` must equal bytes actually present in the input buffer; a length-prefixed allocation with no ceiling check before reading is a memory over-read/DoS site. Impact: Critical, remote crash/DoS from a single malformed chunk before any signature check occurs. Proof idea: a libstackerdb/libsigner test feeding a truncated hex-encoded chunk buffer (declared length > available bytes) into the deserializer, asserting `Err(..)` rather than panic or out-of-bounds read.
