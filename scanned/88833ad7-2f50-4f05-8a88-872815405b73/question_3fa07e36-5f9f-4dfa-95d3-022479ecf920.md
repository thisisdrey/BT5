Target: nonce::salted::SaltedNonce and salts registry `is_valid_salt`. Attacker who knows a salt that was PREVIOUSLY valid (rotated out by SaltManager, an action attacker does not control but can observe on-chain) tries to reuse an OLD signed payload whose nonce embeds that now-invalid salt, expecting `is_valid_salt(salt)` to return false and correctly reject it via `Err(DefuseError::InvalidSalt)`. Preconditions: attacker holds a payload signed against an old salt that has since been rotated out (salts registry retains history per README: 'Admins can disable or rotate salts... there will always be at least one valid salt'). Call sequence: verify_intent_nonce -> `self.state.is_valid_salt(salt)` returns false for the rotated-out salt -> Err(InvalidSalt), payload rejected, no commit_nonce, no execute_intent. Binding: REPLAY/AUTHORISATION — confirm a payload signed under an old salt can NEVER settle after rotation, i.e., value delivered == 0 for that payload, and that rotation cannot be exploited to instead ACCEPT an old-salt payload by any fallback logic. Scoped impact: Critical if rotated-out salts are still accepted (would allow settlement of intents the signer/system considered invalidated by rotation, e.g. after an incident response salt rotation intended to invalidate outstanding intents). Proof idea: near-workspaces test: sign a payload with current salt, rotate salt (via a test-only privileged call, purely to establish the precondition state, not as the attacker action), then have the UNPRIVILEGED attacker submit the old-salted payload and assert execute_intents returns DefuseError::InvalidSalt with zero balance change.
