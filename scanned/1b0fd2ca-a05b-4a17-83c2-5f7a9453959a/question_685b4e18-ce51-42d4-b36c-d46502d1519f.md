Target: `Pips::invert` (crates/primitives/fees/src/lib.rs) as used inside `TokenDiff::supply_delta` and `TokenDiff::closure_supply_delta`. Attacker signs a `TokenDiff` naming a `Nep245TokenId` with `amount == 2` (just above the `amount > 1` fee-applicability threshold) versus a colluding-but-unprivileged counterparty naming the same underlying MT contract but splitting their matching leg into two separate `TokenDiff` intents of amount 1 each within the same `MultiPayload`. Preconditions: both accounts hold balances of the same `Nep245TokenId`. Call sequence: engine executes each `TokenDiff::execute_intent` independently per intent, so `Self::token_fee` is evaluated per-intent on the amount within that single intent, not on the aggregate cross-batch amount for that account/token. Binding: fees credited to `fee_collector` for token T == `Pips::fee_ceil` over every negative delta of T *in the batch* (aggregated) — but actual code sums fee per individual `TokenDiff` intent's own `delta`, so an attacker splitting one logical 2-unit trade into two 1-unit `TokenDiff` intents changes the total fee from `fee_ceil(2)` to `0+0`. Scoped impact: Critical, protocol fee under-collected relative to the batch-level negative delta. Proof idea: cargo test comparing `fee_collector` balance after one `TokenDiff{diff:{T:-2}}` vs after two `TokenDiff{diff:{T:-1}}` intents in one `MultiPayload`, same signer, same batch.
