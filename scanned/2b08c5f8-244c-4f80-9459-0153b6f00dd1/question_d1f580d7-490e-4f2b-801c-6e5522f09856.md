[Target: `resolve_deposit_internal` in contract/tokens/mod.rs, specifically the refund clamping logic `refund_amount = requested_refund.min(*deposited).min(balance_left)` when `balance_left` is computed from `receiver.token_balances.amount_for(&token_id)` AFTER the receiver's account has been reentrantly modified by a concurrent deposit or transfer.] Attacker deposits via `mt_transfer_call` with `msg` = `DepositMessage{receiver_id: attacker_contract, action: Some(DepositAction::Notify(NotifyOnTransfer{msg: <attacker_contract's mt_on_transfer will call a SECOND mt_transfer_call to deposit additional tokens of the SAME TokenId into the Verifier for the SAME receiver_id before returning the refund array>}))}`. Preconditions: attacker controls attacker_contract's wasm and can trigger a second deposit. Call sequence: `deposit()` credits amount A of token X to attacker_contract; `notify_on_transfer` calls `mt_on_transfer`, which (before returning) calls `mt_transfer_call` to deposit amount B of the SAME token X into the Verifier for the same attacker_contract, crediting B synchronously; then `mt_on_transfer` returns a refund array requesting full refund of A; `mt_resolve_deposit` computes `balance_left = A + B` (the updated balance after the reentrant deposit), so `refund_amount = A.min(A).min(A+B) = A`, which is correct — but if the reentrant deposit is of a DIFFERENT token Y, and the refund array requests refund of Y (not X), then `balance_left` for Y is now B (from the reentrant deposit), and `refund_amount = requested_refund_Y.min(deposited_Y=0).min(B) = 0` (since Y was never originally deposited, only reentrantly added), so no refund happens for Y, and the external sender of Y is told 'zero refund needed' despite Y being reentrantly deposited into attacker's account without the sender's authorization. Binding: value debited from the external sender of Y (0, since no refund) == value delivered to attacker's ledger (B of Y, from the reentrant deposit) — the external sender loses B of Y with no compensating refund. Impact: Critical, external sender's tokens are stolen via a reentrant deposit to an unrelated receiver_id. Proof idea: sandbox test where attacker's mt-receiver stub deposits a DIFFERENT token Y into the Verifier for itself before returning a refund array, assert the external sender of Y is not refunded and attacker's ledger shows +B of Y.
