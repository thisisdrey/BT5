Preconditions: some account `victim.near` has previously minted `ImtTokenId{minter_id: victim.near, token_id: 'a'}` giving it a `total_supplies` entry. Call sequence: attacker signs a `DefusePayload` containing `ImtMint{tokens: {'victim.near:a': amount}}` where the IMT token key itself is treated as raw sub-token string containing the full 'minter:sub' text of the target. Binding: `ImtTokenId::from_str(&t.to_string()) == t` for every constructible `t`, i.e. no two `(minter_id, token_id)` pairs produce the same Display string. Scoped impact: Critical, one signer's IMT mint inflates or credits another signer's `total_supplies`/`token_balances` entry for a token they do not control. Proof idea: cargo test asserting `ImtTokenId::new(m1,t1).to_string() != ImtTokenId::new(m2,t2).to_string()` whenever `(m1,t1) != (m2,t2)`, fuzzing `t1`/`t2` with colon-laden strings up to `MAX_TOKEN_ID_LEN`.
