Attacker submits the SAME signed `MultiPayload` (identical nonce, identical `TokenDiff`) twice within one `execute_intents` call's `signed` list. Preconditions: signer has balance sufficient for one execution of the diff, nonce unused. Call sequence: `execute_signed_intents` iterates `signed` -> first call commits nonce via `commit_nonce` then executes `TokenDiff`; second iteration calls `commit_nonce` again for the same nonce. Binding: the number of times this signed payload settles == 1; if `commit_nonce` doesn't reject a nonce already committed within the SAME transaction's not-yet-persisted state (only checked via `is_nonce_used` against already-persisted storage, not against deltas accumulated so far in the same call), replay within one call could double-apply the `TokenDiff`, producing a net non-zero settlement (2x debit, 2x credit, but if paired against only 1x counter-leg by others it breaks conservation). Impact: Critical, replay within one `execute_intents` call. Proof: cargo test submitting `signed: [payload.clone(), payload.clone()]` to `execute_intents` and asserting the second application errors (`NonceAlreadyUsed`) rather than applying the diff twice; also assert final balance reflects only 1x delta.
