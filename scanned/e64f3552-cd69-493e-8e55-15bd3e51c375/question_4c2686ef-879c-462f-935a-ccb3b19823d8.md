Target: Nonces::commit (contracts/wallet/src/nonces.rs). Attacker action: call w_execute_signed with msg.nonce = N and a garbage/invalid proof string, where N is a nonce value the legitimate signer plans to use later (predictable/sequential nonce scheme recommended by docs). Preconditions: wallet with signature_enabled=true, attacker knows or guesses the signer's next sequential nonce N. Call sequence: execute_signed calls self.0.nonces.commit(msg.nonce, msg.created_at, msg.timeout) BEFORE S::verify_request_msg is invoked; commit sets the bit for N in `current` bitmap unconditionally on success, then signature check fails and returns Err, but the nonce bit remains set. Binding: the number of times nonce N settles into `current`/`old` BitMap == number of times a VALID signature for N was verified, but commit occurs prior to verification so 1 != 1 (nonce is consumed by an unverified request). Impact: Critical/High - user funds/actions can become permanently unusable because the legitimate signed request with nonce N will now always fail NonceError::AlreadyUsed, deadlocking that intended action. Proof idea: cargo test calling execute_signed with valid chain_id/signer_id/timestamp but invalid proof; assert Err(InvalidSignature) but then attempt the legitimately signed request with same nonce and assert Err(NonceError::AlreadyUsed).
