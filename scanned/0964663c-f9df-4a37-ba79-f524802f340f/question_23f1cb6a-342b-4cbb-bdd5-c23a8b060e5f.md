Target: `SignerMessage::consensus_deserialize` in `libsigner/src/v0/messages.rs`, which reads `type_prefix_byte` then dispatches via `SignerMessageTypePrefix::try_from` before any signature or slot-owner check occurs (that happens later at `TryFrom<StackerDBChunksEvent>` in `events.rs`). Attacker action: post a StackerDB chunk to a `.signers-X-Y` slot the attacker legitimately owns, whose data's first byte is a valid `SignerMessageTypePrefix` (e.g. `BlockPreCommit = 7`) but whose lane `message_id` (from `get_signers_db_signer_set_message_id`) does not correspond to that type. Preconditions: attacker holds a legitimate signer slot on `.signers-X-Y` for some Y, but writes a payload type meant for a different Y. Call sequence: `TryFrom<StackerDBChunksEvent>::try_from` -> `signer_message_payload_matches_lane(payload_kind, message_id)` -> if mismatched, filtered out via `filter_map` returning `None`. Impact: Critical if this check can be bypassed for a message that reaches the runloop as if from the correct lane, since it would let an attacker on one lane inject payloads for another (an unauthenticated write to the effective event stream).
