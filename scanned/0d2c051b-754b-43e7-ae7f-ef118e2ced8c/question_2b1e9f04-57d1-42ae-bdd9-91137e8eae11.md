Target: Nonces::commit created_at/timeout bound check `now - self.timeout.min(timeout) <= created_at && created_at <= now`. Attacker (a permissionless relayer) holds a validly-signed RequestMessage with msg.timeout set to a very LARGE Duration (e.g. u32::MAX seconds) while msg.created_at is old, exploiting self.timeout.min(timeout) using the WALLET's configured timeout instead of the message's, to keep replay window open far beyond what the signer intended. Precondition: wallet.timeout=1h (state.rs DEFAULT_TIMEOUT), signer signed msg.timeout=100000h thinking it bounds validity to their own preference. Call sequence: execute_signed -> nonces.commit(msg.nonce, msg.created_at, msg.timeout) uses min(self.timeout, timeout) so wallet.timeout still caps it; verify this can't be bypassed to accept an expired created_at. Binding: created_at must satisfy now - min(wallet.timeout, msg.timeout) <= created_at <= now, i.e. the effective validity window used at verification == min of both, never larger than wallet.timeout alone. Impact: High - if this composition is wrong an attacker replayer could hold a stale signed request valid indefinitely and execute it long after the signer intended it revoked. Proof: cargo test with wallet.timeout=1h and msg.timeout=1000h, created_at=2h ago, assert commit() returns Err(NonceError::ExpiredOrFuture).
