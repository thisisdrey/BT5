### Title
Bounty and child-bounty payout functions permanently delete the bounty record even when the beneficiary/curator `Currency::transfer` fails, silently burying funds - ([File: substrate/frame/bounties/src/lib.rs])

### Summary
The external report's core broken invariant is: a value-moving external call is made through a mechanism that can fail for reasons outside the caller's control (a fixed/limited gas stipend that a complex receiver may not satisfy), and the code does not verify the call actually succeeded before treating the payout as final. In `VaultImplementation._issuePayout`, `payable(borrower).transfer(...)` can revert, but the surrounding logic proceeds as if payment happened.

The same "fire funds-moving call, ignore its result, then irrevocably close out the accounting" pattern exists in `pallet-bounties::claim_bounty` and `pallet-child-bounties::claim_child_bounty`. Both call `T::Currency::transfer(..., AllowDeath)` to pay the curator fee and the beneficiary, check the result only via `debug_assert!(res.is_ok())` (a no-op in release/production builds), and then unconditionally delete the bounty storage entry (`*maybe_bounty = None`) and emit a `Claimed`/`BountyClaimed` event, regardless of whether the transfer actually moved funds.

### Finding Description
In `claim_bounty`:
```rust
let res = T::Currency::transfer(&bounty_account, &curator, final_fee, AllowDeath);
debug_assert!(res.is_ok());
let res = T::Currency::transfer(&bounty_account, &beneficiary, payout, AllowDeath);
debug_assert!(res.is_ok());

*maybe_bounty = None;
BountyDescriptions::<T, I>::remove(bounty_id);
T::ChildBountyManager::bounty_removed(bounty_id);

Self::deposit_event(Event::<T, I>::BountyClaimed { index: bounty_id, payout, beneficiary });
Ok(())
``` [1](#0-0) 

The identical pattern exists in `claim_child_bounty`:
```rust
let fee_transfer_result = T::Currency::transfer(&child_bounty_account, curator, curator_fee, AllowDeath);
debug_assert!(fee_transfer_result.is_ok());

let payout_transfer_result = T::Currency::transfer(&child_bounty_account, beneficiary, payout, AllowDeath);
debug_assert!(payout_transfer_result.is_ok());
...
*maybe_child_bounty = None;
``` [2](#0-1) 

`Currency::transfer` with `AllowDeath` still enforces the Existential Deposit (ED) on the **destination** account: if the destination account does not currently exist and the transferred amount is below ED, the transfer returns an `Err` (e.g. `ExistentialDeposit`) instead of moving funds. `payout` and `final_fee`/`curator_fee` are computed purely from `balance.saturating_sub(fee)` and `bounty.fee`, with no floor guaranteeing they exceed ED — nothing in `claim_bounty`/`claim_child_bounty` verifies the curator or beneficiary account already exists or that the transferred amount clears ED. `debug_assert!` is stripped in `--release` builds (the build used for production runtimes), so a failed transfer produces **no panic and no error propagation** — execution simply falls through to deleting the bounty and emitting a "success" event.

Once `*maybe_bounty = None` executes, the storage entry that gates any future claim/retry is gone: `claim_bounty`/`claim_child_bounty` require `BountyStatus::PendingPayout` to exist to operate at all, so there is no way to re-trigger the transfer afterward. Any balance left in `bounty_account`/`child_bounty_account` after a failed transfer is now unreachable by ordinary users — the bounty sub-account is a keyless `PalletId`-derived account with no owning extrinsic path back to the beneficiary or curator (funds could later be swept by a privileged `TransferAllAssets`/treasury path such as `reclaim_bounty_funds`, but only after the bounty has been closed by governance, not by the disadvantaged beneficiary/curator).

### Impact Explanation
This breaks the "settle exactly once to the rightful beneficiary and amount" invariant: the pallet emits `BountyClaimed`/`Claimed` events and permanently removes the payable record even though the beneficiary or curator may have received zero funds. This is a permanent user-fund lock reachable from an unprivileged, permissionless call (`claim_bounty`/`claim_child_bounty` are callable by "anyone" / "any signed origin"), without needing a malicious validator, governance actor, or leaked key — it only requires the beneficiary/curator account to not yet exist on-chain (a very ordinary occurrence, e.g. a freshly generated payout address) and a payout amount that lands below the runtime's ED.

### Likelihood Explanation
The condition is easy to hit accidentally (any curator/beneficiary account that has never received funds and whose fee/payout share happens to fall under ED, which can be arbitrarily small depending on how the treasury council structures the bounty amount and curator fee split). It requires no adversarial coordination — an ordinary bounty payout to a fresh account with a small final split is enough. The `debug_assert!` gives a false sense of safety in tests/debug builds while providing none in production.

### Recommendation
Propagate the `Result` of both `Currency::transfer` calls with `?` (or explicit `ensure!`) instead of `debug_assert!`, so a failing transfer aborts the whole extrinsic and leaves `BountyStatus::PendingPayout` (and the bounty storage entry) intact for retry, or explicitly handle the ED-shortfall case (e.g., top up from the pallet account or require `keep_alive`/pre-existing-account checks) before finalizing and removing bounty state.

### Proof of Concept
1. Governance proposes and funds a bounty with `value` set such that after subtracting the curator `fee`, the resulting `payout` is smaller than the chain's `ExistentialDeposit`.
2. Assign as beneficiary a freshly-generated `AccountId` that has never existed on-chain (0 balance, no storage entry).
3. Curator calls `award_bounty`; after `BountyDepositPayoutDelay`, anyone calls `claim_bounty`.
4. Inside `claim_bounty`, `T::Currency::transfer(&bounty_account, &beneficiary, payout, AllowDeath)` returns `Err(DispatchError::Token(BelowMinimum))` (or similar ED error) because `payout` is below ED and the destination account doesn't exist.
5. In a release build, `debug_assert!(res.is_ok())` is a no-op, so execution proceeds: `*maybe_bounty = None`, `BountyDescriptions::remove`, and `Event::BountyClaimed { payout, beneficiary, .. }` is emitted despite the beneficiary receiving nothing.
6. The bounty sub-account still holds `payout` worth of tokens, but there is no longer any `Bounties` storage entry or extrinsic path for the beneficiary to claim it — funds are stuck absent a privileged sweep (e.g. governance-triggered `reclaim_bounty_funds`, which returns funds to the treasury, not the beneficiary). 		#[pallet::call_index(6)]
		#[pallet::weight(<T as Config<I>>::WeightInfo::claim_bounty())]
		pub fn claim_bounty(
			origin: OriginFor<T>,
			#[pallet::compact] bounty_id: BountyIndex,
		) -> DispatchResult {
			ensure_signed(origin)?; // anyone can trigger claim

			Bounties::<T, I>::try_mutate_exists(bounty_id, |maybe_bounty| -> DispatchResult {
				let bounty = maybe_bounty.take().ok_or(Error::<T, I>::InvalidIndex)?;
				if let BountyStatus::PendingPayout { curator, beneficiary, unlock_at } =
					bounty.status
				{
					ensure!(Self::treasury_block_number() >= unlock_at, Error::<T, I>::Premature);
					let bounty_account = Self::bounty_account_id(bounty_id);
					let balance = T::Currency::free_balance(&bounty_account);
					let fee = bounty.fee.min(balance); // just to be safe
					let payout = balance.saturating_sub(fee);
					let err_amount = T::Currency::unreserve(&curator, bounty.curator_deposit);
					debug_assert!(err_amount.is_zero());

					// Get total child bounties curator fees, and subtract it from the parent
					// curator fee (the fee in present referenced bounty, `self`).
					let children_fee = T::ChildBountyManager::children_curator_fees(bounty_id);
					debug_assert!(children_fee <= fee);

					let final_fee = fee.saturating_sub(children_fee);
					let res =
						T::Currency::transfer(&bounty_account, &curator, final_fee, AllowDeath); // should not fail
					debug_assert!(res.is_ok());
					let res =
						T::Currency::transfer(&bounty_account, &beneficiary, payout, AllowDeath); // should not fail
					debug_assert!(res.is_ok());

					*maybe_bounty = None;

					BountyDescriptions::<T, I>::remove(bounty_id);
					T::ChildBountyManager::bounty_removed(bounty_id);

					Self::deposit_event(Event::<T, I>::BountyClaimed {
						index: bounty_id,
						payout,
						beneficiary,
					});
					Ok(())
				} else {
					Err(Error::<T, I>::UnexpectedStatus.into())
				}
			})?;
			Ok(())
		}

		#[pallet::call_index(5)]
		#[pallet::weight(<T as Config>::WeightInfo::claim_child_bounty())]
		pub fn claim_child_bounty(
			origin: OriginFor<T>,
			#[pallet::compact] parent_bounty_id: BountyIndex,
			#[pallet::compact] child_bounty_id: BountyIndex,
		) -> DispatchResult {
			ensure_signed(origin)?;

			// Ensure child-bounty is in expected state.
			ChildBounties::<T>::try_mutate_exists(
				parent_bounty_id,
				child_bounty_id,
				|maybe_child_bounty| -> DispatchResult {
					let child_bounty =
						maybe_child_bounty.as_mut().ok_or(BountiesError::<T>::InvalidIndex)?;

					if let ChildBountyStatus::PendingPayout {
						ref curator,
						ref beneficiary,
						ref unlock_at,
					} = child_bounty.status
					{
						// Ensure block number is elapsed for processing the
						// claim.
						ensure!(
							Self::treasury_block_number() >= *unlock_at,
							BountiesError::<T>::Premature,
						);

						// Make curator fee payment.
						let child_bounty_account =
							Self::child_bounty_account_id(parent_bounty_id, child_bounty_id);
						let balance = T::Currency::free_balance(&child_bounty_account);
						let curator_fee = child_bounty.fee.min(balance);
						let payout = balance.saturating_sub(curator_fee);

						// Unreserve the curator deposit. Should not fail
						// because the deposit is always reserved when curator is
						// assigned.
						let _ = T::Currency::unreserve(curator, child_bounty.curator_deposit);

						// Make payout to child-bounty curator.
						// Should not fail because curator fee is always less than bounty value.
						let fee_transfer_result = T::Currency::transfer(
							&child_bounty_account,
							curator,
							curator_fee,
							AllowDeath,
						);
						debug_assert!(fee_transfer_result.is_ok());

						// Make payout to beneficiary.
						// Should not fail.
						let payout_transfer_result = T::Currency::transfer(
							&child_bounty_account,
							beneficiary,
							payout,
							AllowDeath,
						);
						debug_assert!(payout_transfer_result.is_ok());

						// Trigger the Claimed event.
						Self::deposit_event(Event::<T>::Claimed {
							index: parent_bounty_id,
							child_index: child_bounty_id,
							payout,
							beneficiary: beneficiary.clone(),
						});

						// Update the active child-bounty tracking count.
						ParentChildBounties::<T>::mutate(parent_bounty_id, |count| {
							count.saturating_dec()
						});

						// Remove the child-bounty description.
						ChildBountyDescriptionsV1::<T>::remove(parent_bounty_id, child_bounty_id);

						// Remove the child-bounty instance from the state.
						*maybe_child_bounty = None;

						Ok(())
					} else {
						Err(BountiesError::<T>::UnexpectedStatus.into())
					}
				},
			)
		}
