Target `RPCPostBlockRequestHandler::try_parse_request` (postblock_v3.rs, in-scope via `broadcast` flag parsing referenced by the audit scope though file target is fastcallreadonly.rs's `auth`/`broadcast` sibling pattern): attacker sends `POST /v3/blocks/upload/?broadcast=1&broadcast=0` (duplicate query keys) with no `authorization` header. Preconditions: `self.auth = Some(password)`. Call sequence: `for (key, value) in form_urlencoded::parse(...) { if key == "broadcast" { broadcast = broadcast || value == "1" } }` — the `||` means ANY occurrence of `broadcast=1` sets `broadcast = true` even if a later `broadcast=0` appears, and `authenticated` stays `false` if no header is present, so `if broadcast && !authenticated { return Err(...) }` should still catch this. Equality: `broadcast == true` implies the request must also satisfy `authenticated == true`; verify no ordering of duplicate params or missing-header case defeats this check for the block-relay path (`Relayer::process_new_nakamoto_block_ext(..., self.broadcast.unwrap_or(false))`). Impact: Critical (unauthenticated forced broadcast of an uploaded Nakamoto block into `set_relay_message`, propagating attacker-supplied blocks network-wide). Proof idea: test posting a raw `NakamotoBlock` body with query string `broadcast=1` and no `authorization` header, assert `try_parse_request` returns `Err(Error::Http(401,_))` and `self.broadcast` is never set to `Some(true)` reaching `try_handle_request`.
