## Title
`reap_stash` permissionlessly kills a staking ledger without notifying `OnStakingUpdate::on_withdraw`, permanently desyncing nomination-pool `TotalValueLocked` accounting - (File: `substrate/frame/staking/src/pallet/impls.rs`, `substrate/frame/staking-async/src/pallet/impls.rs`)

### Summary
The external report's core invariant break is: an emergency/forced withdrawal path removes funds from a strategy's ledger but skips the accounting-update step that normal withdrawals perform, leaving a tracked "amount deployed" variable stale and blocking correct accounting until it drifts back into sync. The same pattern exists in `pallet-staking` / `pallet-staking-async`: the normal `do_withdraw_unbonded` path notifies `T::EventListeners::on_withdraw(controller, value)` so that `pallet-nomination-pools::TotalValueLocked` stays in sync [1](#0-0) , but the permissionless `reap_stash` extrinsic reaches the exact same `kill_stash` removal of ledger state without ever emitting that notification [2](#0-1) .

### Finding Description
`pallet-nomination-pools` keeps a global `TotalValueLocked` storage value that is supposed to always reflect the sum of pools' staked balances, and it is deliberately kept in sync with the staking pallet through the `OnStakingUpdate::on_withdraw` hook — this was fixed historically precisely because "the nomination pools pallet's `TotalValueLocked` may get out of sync if the staking pallet does implicit withdrawal of unlocking chunks" [3](#0-2) . The pool's `on_withdraw` implementation reduces `TotalValueLocked` by the exact amount reported by the staking pallet [4](#0-3) .

The staking pallet's *normal* withdrawal path (`do_withdraw_unbonded`) correctly fires this notification for the delta between old and new ledger totals, even when it internally calls `kill_stash`: [5](#0-4) 

However, `reap_stash` is a **permissionless, unprivileged extrinsic** ("It can be called by anyone, as long as `stash` meets the above requirements") that reaches `kill_stash` through a completely different call path that has no equivalent notification of the ledger's remaining `total` balance being destroyed: [6](#0-5) 

`kill_stash` itself only clears staking metadata (ledger, bonded map, payee, validator/nominator prefs); it never calls `T::EventListeners::on_withdraw` or any equivalent "on_unstake" cleanup for the residual `ledger.total`: [7](#0-6) 

The async version of the pallet exhibits the identical structure — `do_withdraw_unbonded` calls the listener, `kill_stash` does not [8](#0-7) [9](#0-8) , and `reap_stash`/`force_unstake` both call `kill_stash` directly without ever invoking the listener path [10](#0-9) .

Since `TotalValueLocked` is only decremented via the `on_withdraw`/`on_slash` hooks and is never re-derived from the staking ledger during ordinary operation (only during an explicit `TotalValueLockedSync` runtime-upgrade migration [11](#0-10) ), any residual `ledger.total` wiped out by `reap_stash` is permanently "lost" from the reconciliation process: the on-chain `TotalValueLocked` value stays higher than the sum of what is actually staked in the corresponding bonded pool account.

This mirrors the Stargate bug exactly: `emergencyWithdrawToVault()` removed funds from the aggregator without subtracting from `allocatedAmt`, so the tracked value stayed inflated relative to real funds, blocking correct accounting until real balances caught up. Here, `reap_stash` removes ledger balance without subtracting from `TotalValueLocked`, permanently inflating the tracked value versus real bonded/staked balance.

### Impact Explanation
This corrupts the pool-wide `TotalValueLocked` accounting value, which per the storage docs is used to bound pool exit/PPS calculations and is asserted to "never be higher than the sum of `total_balance` of all `PoolMembers`" — an invariant that is directly violated [12](#0-11) . A permanently inflated `TotalValueLocked` misrepresents pool-wide solvency/accounting used by chain observers, governance decisions gated on TVL, and any logic relying on this invariant, matching the "runtime bugs that compromise intended behavior" and "duplicate settlement or payout state must only advance after ... settlement succeed atomically" impact classes. It is a state-accounting integrity bug reachable without any privileged, governance, or malicious-peer assumption.

### Likelihood Explanation
`reap_stash` is explicitly permissionless — "It can be called by anyone" — and only requires that a stash's `ledger.total` (or free balance) falls under the existential deposit, a state reachable naturally via partial slashing or unbonding of a pool's bonded account. Any accountholder can trigger this condition and then call `reap_stash(origin, stash, num_slashing_spans)` on a nomination-pool's bonded account to strip the ledger without the pools pallet ever being told, making the desync trivially triggerable by an ordinary user with no elevated permissions.

### Recommendation
Route `kill_stash`'s removal of a non-zero residual `ledger.total` through the same `T::EventListeners::on_withdraw` (or an explicit `on_unstake`) notification used in `do_withdraw_unbonded`, so any listener (e.g., `pallet-nomination-pools`) can decrement `TotalValueLocked` by the exact amount being wiped, regardless of whether the removal happens via `withdraw_unbonded`, `reap_stash`, or `force_unstake`.

### Proof of Concept
1. Create a nomination pool; its bonded account accumulates stake tracked in `pallet_nomination_pools::TotalValueLocked`.
2. Cause the pool's bonded stash `ledger.total` to fall below the existential deposit through partial unbonding/slashing (a reachable, permissionless sequence), while some small residual balance/ledger total remains.
3. Call `Staking::reap_stash(RuntimeOrigin::signed(anyone), pool_bonded_account, num_slashing_spans)` — this succeeds because the reapable conditions are met.
4. `kill_stash` removes the ledger and bonded map entries; no call to `T::EventListeners::on_withdraw` is made, so `pallet_nomination_pools::TotalValueLocked` is not decremented by the residual amount.
5. Observe `TotalValueLocked::<Runtime>::get()` still includes the destroyed residual stake, permanently exceeding the real total staked balance of remaining pools, in violation of the pallet's documented invariant.

Note: I was unable to fully trace whether `reap_stash`/`kill_stash` interacts with `delegated_staking`'s hold-based accounting the same way in every runtime configuration (Transfer vs Delegate stake strategies) before running out of investigation budget; a Devin session with full repository access should confirm whether the `DelegateStake` adapter path independently guards against this specific desync.

	pub(super) fn do_withdraw_unbonded(
		controller: &T::AccountId,
		num_slashing_spans: u32,
	) -> Result<Weight, DispatchError> {
		let mut ledger = Self::ledger(Controller(controller.clone()))?;
		let (stash, old_total) = (ledger.stash.clone(), ledger.total);
		if let Some(current_era) = CurrentEra::<T>::get() {
			ledger = ledger.consolidate_unlocked(current_era)
		}
		let new_total = ledger.total;

		let ed = asset::existential_deposit::<T>();
		let used_weight =
			if ledger.unlocking.is_empty() && (ledger.active < ed || ledger.active.is_zero()) {
				// This account must have called `unbond()` with some value that caused the active
				// portion to fall below existential deposit + will have no more unlocking chunks
				// left. We can now safely remove all staking-related information.
				Self::kill_stash(&ledger.stash, num_slashing_spans)?;

				T::WeightInfo::withdraw_unbonded_kill(num_slashing_spans)
			} else {
				// This was the consequence of a partial unbond. just update the ledger and move on.
				ledger.update()?;

				// This is only an update, so we use less overall weight.
				T::WeightInfo::withdraw_unbonded_update(num_slashing_spans)
			};

		// `old_total` should never be less than the new total because
		// `consolidate_unlocked` strictly subtracts balance.
		if new_total < old_total {
			// Already checked that this won't overflow by entry condition.
			let value = old_total.defensive_saturating_sub(new_total);
			Self::deposit_event(Event::<T>::Withdrawn { stash, amount: value });

			// notify listeners.
			T::EventListeners::on_withdraw(controller, value);
		}

		Ok(used_weight)
	}

		/// Remove all data structures concerning a staker/stash once it is at a state where it can
		/// be considered `dust` in the staking system. The requirements are:
		///
		/// 1. the `total_balance` of the stash is below existential deposit.
		/// 2. or, the `ledger.total` of the stash is below existential deposit.
		/// 3. or, existential deposit is zero and either `total_balance` or `ledger.total` is zero.
		///
		/// The former can happen in cases like a slash; the latter when a fully unbonded account
		/// is still receiving staking rewards in `RewardDestination::Staked`.
		///
		/// It can be called by anyone, as long as `stash` meets the above requirements.
		///
		/// Refunds the transaction fees upon successful execution.
		///
		/// ## Parameters
		///
		/// - `num_slashing_spans`: Refer to comments on [`Call::withdraw_unbonded`] for more
		/// details.
		#[pallet::call_index(20)]
		#[pallet::weight(T::WeightInfo::reap_stash(*num_slashing_spans))]
		pub fn reap_stash(
			origin: OriginFor<T>,
			stash: T::AccountId,
			num_slashing_spans: u32,
		) -> DispatchResultWithPostInfo {
			ensure_signed(origin)?;

			// virtual stakers should not be allowed to be reaped.
			ensure!(!Self::is_virtual_staker(&stash), Error::<T>::VirtualStakerNotAllowed);

			let ed = asset::existential_deposit::<T>();
			let origin_balance = asset::total_balance::<T>(&stash);
			let ledger_total =
				Self::ledger(Stash(stash.clone())).map(|l| l.total).unwrap_or_default();
			let reapable = origin_balance < ed ||
				origin_balance.is_zero() ||
				ledger_total < ed ||
				ledger_total.is_zero();
			ensure!(reapable, Error::<T>::FundedTarget);

			// Remove all staking-related information and lock.
			Self::kill_stash(&stash, num_slashing_spans)?;

			Ok(Pays::No.into())
		}

pub mod unversioned {
	use super::*;

	/// Checks and updates `TotalValueLocked` if out of sync.
	pub struct TotalValueLockedSync<T>(core::marker::PhantomData<T>);
	impl<T: Config> OnRuntimeUpgrade for TotalValueLockedSync<T> {
		#[cfg(feature = "try-runtime")]
		fn pre_upgrade() -> Result<Vec<u8>, TryRuntimeError> {
			Ok(Vec::new())
		}

		fn on_runtime_upgrade() -> Weight {
			let migrated = BondedPools::<T>::count();

			// recalculate the `TotalValueLocked` to compare with the current on-chain TVL which may
			// be out of sync.
			let tvl: BalanceOf<T> = helpers::calculate_tvl_by_total_stake::<T>();
			let onchain_tvl = TotalValueLocked::<T>::get();

			let writes = if tvl != onchain_tvl {
				TotalValueLocked::<T>::set(tvl);

				log!(
					info,
					"on-chain TVL was out of sync, update. Old: {:?}, new: {:?}",
					onchain_tvl,
					tvl
				);

				// writes: onchain version + set total value locked.
				2
			} else {
				log!(info, "on-chain TVL was OK: {:?}", tvl);

				// writes: onchain version write.
				1
			};

			// reads: migrated * (BondedPools +  Staking::total_stake) + count + onchain
			// version
			//
			// writes: current version + (maybe) TVL
			T::DbWeight::get()
				.reads_writes(migrated.saturating_mul(2).saturating_add(2).into(), writes)
		}
