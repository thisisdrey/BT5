In `contracts/defuse/core/src/engine/mod.rs::Engine::execute_signed_intents`, multiple `MultiPayload`s in the input vector are each fully applied via `execute_signed_intent` (nonce commit + intent execution) before a single `finalize()` call runs `Deltas::finalize` at the very end covering the whole batch. Can an attacker submit a batch `[payload_A (AuthCall to attacker contract), payload_B (Transfer from a third victim account whose nonce the attacker cannot forge)]` in one `execute_intents` call, relying on `payload_A`'s `AuthCall::execute_intent` synchronous effect (only the wNEAR sub-balance, since `do_auth_call`'s actual promise runs after this transaction) to pass, while the *promise-triggered* re-entrant call from `on_auth` executes an *additional* `execute_intents` transaction before this original batch's `finalize()` (which only runs at the end of the original synchronous execution, i.e. before any promise fires) has emitted its `MtEvent`s, so that `Engine::finalize`'s invariant check for the outer batch never actually observes the inner reentrant batch's effect, letting the inner batch double-count a balance the outer batch's `Transfer` was relying on still being present? Precondition: victim signed only `payload_B`. Call sequence: `execute_intents([payload_A, payload_B]) -> execute_signed_intent(A) [sub-balance, schedule do_auth_call promise, detached] -> execute_signed_intent(B) [Transfer using balance not yet affected by A's promise] -> finalize() [emits event synchronously]`, then later, in a separate receipt, `do_auth_call -> on_auth(attacker) -> execute_intents([payload_C spending the same balance B_intent used])`. Binding: the set of balance changes `finalize()` commits for the outer batch == exactly what `payload_A` and `payload_B` authorised, unaffected by any later promise-triggered receipt, and no promise-triggered receipt should be able to spend a balance that the just-finalized batch already committed as spent. Scoped impact: Critical, cross-batch double-spend enabled by the promise/receipt boundary being invisible to `Engine::finalize`'s synchronous invariant. Proof idea: sandbox test batching an `AuthCall` with a normal `Transfer` in one `execute_intents`, having `on_auth` immediately submit a follow-up `execute_intents` spending the same token, and asserting CONSERVATION across the full multi-receipt sequence.
