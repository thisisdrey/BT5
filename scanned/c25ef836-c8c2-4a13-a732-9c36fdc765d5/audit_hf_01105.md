# [M] Missing _baseURI() override causes empty NFT metadata

## Summary
Severity: Medium
Contest weight: 0.0578
Dataset id: 4239
Source: https://huggingface.co/datasets/Zaevlad/audit-findings-dataset
Type: audit-finding

## Details
The vulnerability is a missing override of the internal _baseURI() function in the NFT contract that represents Alchemist positions. Because the contract does not provide its own implementation of _baseURI(), the default implementation from the ERC721 base returns an empty string. TokenURI builds the full metadata URL by concatenating the base URI with the token identifier, so when the base URI is empty the resulting URI is either empty or points to a non‑existent location. This causes wallets, explorers and portfolio dashboards to fetch no metadata, resulting in blank images, missing attribute tables and an overall empty representation of the NFT. The root cause is a logical omission during development: the contract author assumed that the inherited default would be sufficient, but the ERC721 specification requires the developer to supply a concrete base URI when metadata is stored off‑chain. Exploitation is straightforward – any user or third‑party service that queries tokenURI receives an empty string, which they interpret as “no metadata”. The impact is purely user‑experience‑oriented: holders see a zero‑information NFT, which may lead them to believe the token is broken, untrustworthy or even valueless, despite the underlying position still holding its economic value. The condition occurs for every token minted by the contract because the missing override is static and applies globally; there is no conditional path that would sometimes return a valid URI. All participants who interact with the NFT – token owners, traders, portfolio aggregators and any UI that displays the token – are affected. The issue was discovered during a manual code review by an external audit team that inspected the inheritance hierarchy and noticed that _baseURI() was not overridden despite the presence of a tokenURI implementation. It can be hard to notice because the contract compiles and functions correctly from a blockchain perspective; only visual inspection of the UI reveals the problem, and automated tests that do not check metadata may pass. The appropriate remediation is to implement an override of _baseURI() that returns a valid HTTP or IPFS prefix, such as "https://nftmetadata.alchemix.fi/", optionally serving a placeholder image and basic attribute data. For a more robust solution, the contract could adopt an on‑chain metadata scheme similar to UniswapV3 or SablierV2, embedding the JSON directly or using a deterministic hash. This class of bug belongs to the broader category of missing or incorrect metadata URI configuration in ERC721 contracts, where the contract fails to supply a resolvable base URI, leading to empty or broken token metadata. From the user’s perspective the symptom is a blank NFT thumbnail, an empty description field, and a token that appears to have no associated data, contrary to the expectation that each NFT should display an image and attribute set. The failure violates the business logic that each position token should be identifiable and informative, breaking the accounting assumption that token metadata reliably reflects the underlying asset.

## Recommendation
Override _baseURI() and provide at least a placeholder URI like nftmetadata.alchemix.fi/ that returns a logo. Additionally, consider including useful metadata such as the NFT’s value in underlying terms. For a fully on-chain solution, you can take inspiration from UniswapV3 and SablierV2.
