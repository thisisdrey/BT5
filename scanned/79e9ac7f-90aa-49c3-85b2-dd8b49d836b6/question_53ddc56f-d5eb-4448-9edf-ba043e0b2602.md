Target: `TokenDiff` intent (contracts/defuse/core/src/intents/token_diff.rs) keyed by `token_id.to_string()` for netting deltas to zero. Attacker signs a `MultiPayload` containing a `TokenDiff` intent whose `diff` map has two entries that are DISTINCT `TokenId` values (one `Nep245` with colon-bearing `mt_token_id`, one `Imt`) but which stringify identically due to a Display collision. Preconditions: attacker controls the MT/IMT sub-token strings used to build both `TokenId`s. Call sequence: `execute_intents` -> `TokenDiff` handler nets deltas per distinct map key -> if the two colliding `TokenId`s hash/stringify the same, their deltas are summed together instead of tracked separately. Binding: sum of `token_balances` changes for each REAL distinct token across the call == 0 individually; a collision breaks this into `sum(delta_A + delta_B) == 0` while `sum(delta_A) != 0`. Impact: Critical, the batch can leave the Verifier owing more of one real asset than it custodies. Proof idea: cargo test building a `TokenDiff` with two constructed `TokenId`s that collide on `.to_string()`, executing it, and asserting each real underlying asset nets to zero independently.
