For `PingData`/`PongData` (stackslib/src/net/codec.rs), note both types round-trip only a `nonce: u32` with zero binding to the connection's `Preamble.seq` or any per-peer session state at the codec layer. Attacker action: on a connection where the victim node sent a `Ping{nonce: N}` to a *different* peer, the attacker (a separate, unauthenticated connection) sends a `Pong{nonce: N}` guessed/observed from network traffic. Preconditions: attacker can observe or brute-force the 32-bit `nonce` space (no encryption keeps it secret) and has any open connection to the victim, not necessarily the one that received the `Ping`. Call sequence: `PongData::consensus_deserialize` reads only `nonce`, and matching logic outside codec.rs presumably compares it against an outstanding ping nonce per-connection; show whether that per-connection binding exists or whether a `Pong` on connection B can satisfy a `Ping` issued on connection A due to global (not per-neighbor) nonce tracking. Equality: the `nonce` in an accepted `Pong` must equal one issued on that *same authenticated connection/peer identity*, not merely any recently-issued nonce node-wide. Impact: High, liveness/health-check state confusion allowing an unauthenticated peer to falsely assert another peer's connection is alive (steering peer-health bookkeeping). Proof idea: `stackslib::net` test issuing a `PingData` on one simulated peer connection and delivering the matching `PongData::consensus_deserialize` result on a distinct connection object, asserting whether liveness-tracking code distinguishes them.
