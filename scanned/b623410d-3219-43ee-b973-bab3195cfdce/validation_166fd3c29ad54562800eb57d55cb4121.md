### Title
Snowbridge outbound-queue `calculate_fee` truncates the ETH-denominated remote fee to zero via chained division, letting messages be charged and queued for Ethereum delivery with an unbacked (zero) relayer/execution fee - ([File: bridges/snowbridge/pallets/outbound-queue/src/lib.rs])

### Summary
`Pallet::<T>::calculate_fee` (`bridges/snowbridge/pallets/outbound-queue/src/lib.rs:368-393`) computes the ETH-denominated `remote` fee by chaining a `saturating_mul` with a `checked_div`, then feeding the *already-divided* `u128` result into `convert_from_ether_decimals`, which performs one more integer division (`value.checked_div(denom)`, line 417). With realistic `PricingParameters` (small `fee_per_gas`/`reward` relative to the `10^(ETHER_DECIMALS - T::Decimals)` scaling divisor), the final division floors a non-zero, validated fee down to `0`. This is demonstrated directly in the pallet's own test suite: `test_calculate_fees_with_valid_exchange_rate_but_remote_fee_calculated_as_zero` (`bridges/snowbridge/pallets/outbound-queue/src/test.rs:303-319`), whose own comment states "the remote fee calculated here is invalid which should be avoided."

### Finding Description
`calculate_fee` is called from `SendMessage::validate` (`bridges/snowbridge/pallets/outbound-queue/src/send_message_impl.rs:41-74`), which is the function XCM exporters/routers use to determine how much a user must pay before a message is queued to Ethereum. The returned `Fee { local, remote }` is what upstream callers (e.g. `pallet_xcm_bridge_hub_router`/asset-hub exporters) charge the user; `remote` specifically is meant to cover `fee_per_gas * gas_used + reward` on Ethereum, i.e. the real cost incurred by relayers/the bridge to execute the command there.

The computation is:
```
fee (U256, wei) = fee_per_gas * gas_used_at_most + reward       // calculate_remote_fee
fee (u128)       = fee.try_into().defensive_unwrap_or(u128::MAX)
fee = FixedU128::from_inner(fee) * multiplier / exchange_rate    // fine (mul-before-div)
fee = convert_from_ether_decimals(fee)                            // fee / 10^(18-Decimals)
```
`convert_from_ether_decimals` performs a further plain integer division with no rounding-up/ceiling and no minimum-fee floor:
```rust
pub(crate) fn convert_from_ether_decimals(value: u128) -> T::Balance {
    let decimals = ETHER_DECIMALS.saturating_sub(T::Decimals::get()) as u32;
    let denom = 10u128.saturating_pow(decimals);
    value.checked_div(denom).expect("divisor is non-zero; qed").into()
}
```
Because `ETHER_DECIMALS = 18` and most Polkadot/Kusama-based chains use `T::Decimals` in the 10-12 range, `denom` is `10^6`–`10^8`. Any wei-scale intermediate `value` smaller than `denom` truncates to `0`. `PricingParameters::validate()` (`bridges/snowbridge/primitives/core/src/pricing.rs:39-56`) only checks that the individual inputs (`fee_per_gas`, `rewards.local`, `rewards.remote`, `exchange_rate`, `multiplier`) are each non-zero — it never asserts that the final composed `remote` fee (after both divisions) is non-zero. So governance-set (or even legitimately small) pricing parameters can pass validation yet still produce `Fee.remote == 0` for some/all `Command` variants, as directly reproduced by the pallet's own unit test.

Existing guards do not stop this path:
- `PricingParameters::validate` only bounds inputs individually, not the composed output.
- `calculate_fee`/`convert_from_ether_decimals` use `checked_div`/`saturating_*` only to avoid panics/overflow — they do not guard against the output being a truncated-to-zero deliverable fee.
- There is no floor/minimum enforced on the returned `Fee.remote`.

### Impact Explanation
`Fee.remote` is supposed to fully back the cost of executing the command on Ethereum (gas cost + relayer reward). If it truncates to zero while the message is nonetheless accepted, charged, and queued via `do_process_message` (which unconditionally sets `reward: pricing_params.rewards.remote` and `max_fee_per_gas` into the committed message regardless of whether the earlier user-facing `Fee` calculation zeroed out), then messages get delivered/executed on Ethereum with insufficient economic backing on the Polkadot side relative to what users were actually charged via `validate`. This is "public underpriced work that degrades... stalls bridge processing" — relayers are not adequately compensated (or the bridge under-collects from users) for real Ethereum execution costs, which can starve relayer incentives and stall message delivery, a live-scope Snowbridge impact.

### Likelihood Explanation
This requires no privileged actor, malicious relayer, or governance abuse — it is a pure arithmetic property of currently-valid, non-zero `PricingParameters` combined with common decimal configurations (DOT: 10 decimals, KSM: 12 decimals vs. ETHER_DECIMALS: 18). The bug is already exercised and acknowledged in the codebase's own test (`test_calculate_fees_with_valid_exchange_rate_but_remote_fee_calculated_as_zero`), confirming it is reachable with parameters that pass `PricingParameters::validate()`.

### Recommendation
- In `convert_from_ether_decimals`, round up (ceiling division) instead of flooring, or
- Add an explicit floor/minimum-fee check on the final composed `Fee.remote` (and `Fee.local`) after all divisions, rejecting/erroring when a computed fee is zero despite non-zero pricing inputs, and
- Extend `PricingParameters::validate` to simulate/verify that `calculate_fee` produces a non-zero `remote` fee for the cheapest supported `Command`, preventing governance from (even accidentally) setting parameters that under-price bridge execution.

		/// Calculate total fee in native currency to cover all costs of delivering a message to the
		/// remote destination. See module-level documentation for more details.
		pub(crate) fn calculate_fee(
			gas_used_at_most: u64,
			params: PricingParameters<T::Balance>,
		) -> Fee<T::Balance> {
			// Remote fee in ether
			let fee = Self::calculate_remote_fee(
				gas_used_at_most,
				params.fee_per_gas,
				params.rewards.remote,
			);

			// downcast to u128
			let fee: u128 = fee.try_into().defensive_unwrap_or(u128::MAX);

			// multiply by multiplier and convert to local currency
			let fee = FixedU128::from_inner(fee)
				.saturating_mul(params.multiplier)
				.checked_div(&params.exchange_rate)
				.expect("exchange rate is not zero; qed")
				.into_inner();

			// adjust fixed point to match local currency
			let fee = Self::convert_from_ether_decimals(fee);

			Fee::from((Self::calculate_local_fee(), fee))
		}

		/// Calculate fee in remote currency for dispatching a message on Ethereum
		pub(crate) fn calculate_remote_fee(
			gas_used_at_most: u64,
			fee_per_gas: U256,
			reward: U256,
		) -> U256 {
			fee_per_gas.saturating_mul(gas_used_at_most.into()).saturating_add(reward)
		}

		/// The local component of the message processing fees in native currency
		pub(crate) fn calculate_local_fee() -> T::Balance {
			T::WeightToFee::weight_to_fee(
				&T::WeightInfo::do_process_message().saturating_add(T::WeightInfo::commit_single()),
			)
		}

		// 1 DOT has 10 digits of precision
		// 1 KSM has 12 digits of precision
		// 1 ETH has 18 digits of precision
		pub(crate) fn convert_from_ether_decimals(value: u128) -> T::Balance {
			let decimals = ETHER_DECIMALS.saturating_sub(T::Decimals::get()) as u32;
			let denom = 10u128.saturating_pow(decimals);
			value.checked_div(denom).expect("divisor is non-zero; qed").into()
		}

	fn validate(
		message: &Message,
	) -> Result<(Self::Ticket, Fee<<Self as SendMessageFeeProvider>::Balance>), SendError> {
		// The inner payload should not be too large
		let payload = message.command.abi_encode();
		ensure!(
			payload.len() < T::MaxMessagePayloadSize::get() as usize,
			SendError::MessageTooLarge
		);

		// Ensure there is a registered channel we can transmit this message on
		ensure!(T::Channels::contains(&message.channel_id), SendError::InvalidChannel);

		// Generate a unique message id unless one is provided
		let message_id: H256 = message
			.id
			.unwrap_or_else(|| unique((message.channel_id, &message.command)).into());

		let gas_used_at_most = T::GasMeter::maximum_gas_used_at_most(&message.command);
		let fee = Self::calculate_fee(gas_used_at_most, T::PricingParameters::get());

		let queued_message: VersionedQueuedMessage = QueuedMessage {
			id: message_id,
			channel_id: message.channel_id,
			command: message.command.clone(),
		}
		.into();
		// The whole message should not be too large
		let encoded = queued_message.encode().try_into().map_err(|_| SendError::MessageTooLarge)?;

		let ticket = Ticket { message_id, channel_id: message.channel_id, message: encoded };

		Ok((ticket, fee))
	}

	pub fn validate(&self) -> Result<(), InvalidPricingParameters> {
		if self.exchange_rate == FixedU128::zero() {
			return Err(InvalidPricingParameters);
		}
		if self.fee_per_gas == U256::zero() {
			return Err(InvalidPricingParameters);
		}
		if self.rewards.local.is_zero() {
			return Err(InvalidPricingParameters);
		}
		if self.rewards.remote.is_zero() {
			return Err(InvalidPricingParameters);
		}
		if self.multiplier == FixedU128::zero() {
			return Err(InvalidPricingParameters);
		}
		Ok(())
	}
