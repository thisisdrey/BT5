Target: `TokenDiff::token_fee` (token_diff.rs:206-217). Attacker signs a `TokenDiff` on an NEP-245 (`TokenIdType::Nep245`) token with `amount == 1` exactly (the boundary of `if amount > 1`), so `token_fee` returns `Pips::ZERO` for a single-unit multi-token transfer that is economically equivalent to a fungible transfer of significant value (e.g. a semi-fungible token representing 1 unit == 1000 USDC of value). Preconditions: attacker deploys their own NEP-245 contract and deposits it, then repeatedly executes `TokenDiff{diff:{mt_token: -1, other: +X}}` intents, each exempt from fees because `amount<=1`. Call sequence: `execute_intent` -> `Self::token_fee(token_id, 1, protocol_fee)` -> `Pips::ZERO` -> no fee collected. Binding: fees credited to `fee_collector` == fees the executed deltas owed under the DAO's configured `protocol_fee`, for every settled token movement regardless of `amount==1` special-casing intent. Impact: Critical (fees bypassed) if `amount==1` transfers carry disproportionate real value; but scoped strictly to intended fee-exempt NFTs this is by design — attacker abuses semi-fungible MT with amount=1 representing high value. Proof idea: cargo test creating an MT with high per-unit value, executing repeated 1-unit TokenDiff swaps, and asserting fee_collector balance stays 0 while real value transferred is large.
