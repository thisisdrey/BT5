In `Engine::execute_signed_intent` (contracts/defuse/core/src/engine/mod.rs), the account's committed balance change is authorised only if `self.state.has_public_key(&signer_id, &public_key)` holds for the `public_key` returned by `signed.verify()`. Can an attacker submit a `MultiPayload` whose NEP-413 envelope is signed by a key NOT registered to `signer_id` but where `DefusePayload::signer_id` names a victim account with an existing balance, such that `PublicKeyNotExist` is bypassed and `internal_sub_balance(signer_id, ...)` executes? Precondition: victim account exists with token_balances > 0 and has never added attacker's key. Binding: `(signer_id, public_key)` authorised == `(signer_id, public_key)` that actually signed. Scoped impact: Critical, victim's tokens moved without their signature. Proof: cargo test asserting `execute_intents` fails/succeeds appropriately when public_key set differs from signer.
