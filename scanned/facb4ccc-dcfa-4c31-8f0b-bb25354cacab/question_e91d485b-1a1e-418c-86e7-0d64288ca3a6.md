Target: `Ed25519 for RawEd25519` (`SignedRawEd25519Payload::verify`, contracts/defuse/core/src/payload/raw.rs) - Ed25519 signatures are not malleable under strict verification but the underlying `ed25519-dalek`/`defuse_crypto::ed25519::Ed25519::verify` may or may not enforce strict (non-batch) canonical-S verification. Attacker takes their own valid `(payload, public_key, signature)` and attempts bit-flips in the low-order bits of `signature.s` component (adding the curve order) to produce an alternate signature encoding accepted by lenient verifiers as valid for the SAME public_key. Preconditions: attacker holds valid ed25519 keypair, has one valid signed payload already executed (nonce committed). Call sequence: resubmit with the malleable-variant signature bytes but IDENTICAL `payload` (hence identical `hash()` and identical `signer_id`/`nonce`) -> `commit_nonce` keyed by `(signer_id, nonce)` should reject regardless of signature bytes since nonce already committed. Binding: number of times `(signer_id, nonce)` settles == 1 forever regardless of how many byte-distinct signatures verify for it. Impact: Critical only if nonce commitment is somehow keyed by signature/hash bytes rather than `(signer_id, nonce)` - verify it is NOT. Proof: cargo test submitting original signature then a bit-flipped malleable variant of the same payload/nonce, asserting second call errors with nonce-already-committed.
