### Title
`pallet-psm::mint`/`redeem` treat external stablecoins as permanently pegged 1:1 with no price validation, enabling unbacked minting during a de-peg — ([File: substrate/frame/psm/src/lib.rs])

### Summary
The `SmartVaultV4` report's core broken invariant is: code assumes two distinct stablecoins are always worth exactly $1 relative to each other and converts between them using only decimal scaling, with no live price check. `pallet-psm` in this repository reproduces the exact same invariant. `Pallet::mint` and `Pallet::redeem` convert between an "internal" stablecoin and an approved "external" asset (e.g. USDC/USDT) purely via `external_to_internal`/`internal_to_external`, which only rescale by `10^|decimals diff|` — there is no oracle, price feed, or peg-deviation check anywhere in the swap path. [1](#0-0) [2](#0-1) 

### Finding Description
`mint()` takes `external_amount` of an approved `external_asset`, converts it to the internal-asset-denominated amount via pure decimal rescaling (`external_to_internal`), applies a fee, and mints that internal amount to the caller — always treating 1 unit of external as worth 1 unit of internal, decimals aside: [3](#0-2) 

`redeem()` does the mirror operation, burning internal and paying out external from the reserve at the same fixed 1:1 (decimal-adjusted) rate: [4](#0-3) 

The only guards present are decimals-snapshot consistency (`ensure_decimals_match`), fee caps, minimum swap size, and a per-instance/per-asset debt ceiling — none of which detect or react to an external asset trading below (or the internal asset trading above) its intended $1 value: [5](#0-4) 

This is structurally identical to the `SmartVaultV4::yieldVaultCollateral` bug: both hard-code a $1:$1 relationship between two nominally-pegged stablecoins instead of consulting a manipulation-resistant price source, and both allow a user to extract more value than they deposited whenever the peg assumption breaks. The PSM's own documentation acknowledges the assumption ("both USDs and its vault pair are € stablecoins, but can be equivalent to €1 in collateral" is the direct analog of the README's arbitrage note) but only offers a manually-triggered circuit breaker (`set_asset_status`) as mitigation — the same class of after-the-fact governance response Cyfrin's report criticized as insufficient prior to switching to Chainlink pricing. [6](#0-5) 

The `Emergency`/`Full` admin circuit breaker only helps if a privileged operator notices the de-peg and acts before it is exploited; it does not stop the unprivileged, single-block attack path described below, and per the "no admin/governance-as-root-cause" scoping rule the vulnerability is the missing on-chain price check itself, not the delayed admin response.

### Impact Explanation
If any approved external asset (e.g. USDC) trades below $1 on the open market — a routine, historically-observed event — an unprivileged user can:
1. Buy the de-pegged external asset cheaply on the open market.
2. Call `mint()` to swap it 1:1 (minus ~0.5% fee) for the internal stablecoin, which the protocol always treats as worth $1.
3. Sell/redeem the internal stablecoin at its intended peg value elsewhere (DEX, other PSM instance, or via `redeem()` against a different, still-pegged external asset in the same instance).

This is an unbacked-mint / theft-of-reserve primitive: the PSM's reserve of good collateral is drained in exchange for internal-asset liabilities backed by devalued collateral, i.e. the reserve becomes undercollateralized relative to outstanding `PsmDebt`, exactly mirroring the Smart Vault's "borrow more than true collateral value" impact. This falls squarely in the "theft or unbacked mint" and "runtime bugs that compromise intended behavior" impact categories.

### Likelihood Explanation
The attack requires only a signed extrinsic call to `mint`/`redeem` — no admin, governance, validator, relayer, or leaked-key access is needed. It is triggered purely by external market conditions (a stablecoin de-peg), which the report's own precedent (USDC's historical de-peg events) shows is not a hypothetical. The debt ceiling (`max_debt`, `AssetCeilingWeight`) limits the blast radius per instance but does not prevent the exploit — it only caps how much can be drained before the ceiling or a governance intervention halts minting, mirroring exactly the "hypothetical but real, plus directly a manipulation-amplifiable" characterization in the original report.

### Recommendation
Do not treat `external_to_internal`/`internal_to_external` decimal-rescaling as a price oracle. Before allowing `mint`/`redeem` at the assumed 1:1 rate, integrate a manipulation-resistant price feed (e.g. the repository's own `pallet-oracle`, or Chainlink-style external feeds bridged in) to bound the acceptable peg deviation, and automatically restrict/throttle minting (not just via manual `set_asset_status`) when a registered external asset's observed price deviates materially from $1. At minimum, expose the current market price check as a precondition in `mint`, analogous to how `SmartVaultV4` was fixed by sourcing `USDC` price from Chainlink instead of assuming parity.

### Proof of Concept
1. Runtime instantiates `pallet-psm` with `internal_asset = pUSD` and an approved `external_asset = USDC` at `AssetCeilingWeight` > 0 and non-zero `max_debt`.
2. Externally (off-chain, on a DEX), USDC de-pegs to $0.90 due to normal market conditions (as has historically happened).
3. Attacker buys `X` USDC at the discounted market price.
4. Attacker calls `Psm::mint(origin, pUSD, USDC, X, max_fee)`:
   - `external_to_internal(X, ext_decimals, internal_decimals)` returns `X` (decimal-adjusted) regardless of USDC's real market value.
   - Attacker receives `~0.995 * X` pUSD (after minting fee), which the protocol treats as fully $1-backed. [7](#0-6) 
5. Attacker sells the received pUSD on the open market (or redeems it via `Psm::redeem` against a different, still-pegged external asset in the same or another PSM instance) at close to $1, realizing `~0.995 * X * $1 − X * $0.90` profit, funded entirely by the PSM reserve — an unbacked mint extracted from protocol collateral.
6. Repeat until `max_debt`/`AssetCeilingWeight` throttles further minting or an admin manually intervenes via `set_asset_status`, by which point the reserve is already undercollateralized relative to `PsmDebt`.

			ensure!(!internal_equivalent.is_zero(), Error::<T>::AmountTooSmallAfterConversion);
			ensure!(internal_equivalent >= info.min_swap_amount, Error::<T>::BelowMinimumSwap);

			let effective_external =
				Self::internal_to_external(internal_equivalent, ext_decimals, internal_decimals)?;

			ensure!(fee_rate <= max_fee, Error::<T>::FeeTooHigh);

			let internal_to_user = internal_equivalent.saturating_sub(fee);

			let current_total_psm_debt = Self::total_psm_debt(&internal_asset);

		pub(crate) fn external_to_internal(
			amount: BalanceOf<T>,
			ext_decimals: u8,
			internal_decimals: u8,
		) -> Result<BalanceOf<T>, Error<T>> {
			use core::cmp::Ordering::*;
			match ext_decimals.cmp(&internal_decimals) {
				Equal => Ok(amount),
				Less => {
					let diff = (internal_decimals - ext_decimals) as u32;
					let factor = Self::pow10(diff)?;
					amount.checked_mul(&factor).ok_or(Error::<T>::ConversionOverflow)
				},
				Greater => {
					let diff = (ext_decimals - internal_decimals) as u32;
					let factor = Self::pow10(diff)?;
					Ok(amount.checked_div(&factor).unwrap_or_else(BalanceOf::<T>::zero))
