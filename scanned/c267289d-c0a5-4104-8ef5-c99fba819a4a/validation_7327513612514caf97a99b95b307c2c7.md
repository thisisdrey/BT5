### Title
`claim_child_bounty` ignores transfer failure via `debug_assert!`, permanently trapping bounty funds - (File: `substrate/frame/child-bounties/src/lib.rs`)

### Summary

### Finding Description
`claim_child_bounty` computes a `curator_fee` and a `payout` from the child-bounty sub-account's balance, then executes two `Currency::transfer` calls whose results are only checked with `debug_assert!`, not propagated as errors: [1](#0-0) 

Concretely:
```
let fee_transfer_result = T::Currency::transfer(&child_bounty_account, curator, curator_fee, AllowDeath);
debug_assert!(fee_transfer_result.is_ok());
let payout_transfer_result = T::Currency::transfer(&child_bounty_account, beneficiary, payout, AllowDeath);
debug_assert!(payout_transfer_result.is_ok());
Self::deposit_event(Event::<T>::Claimed { .. });
...
*maybe_child_bounty = None;
```
`debug_assert!` is compiled out entirely in release builds (`cfg(debug_assertions)` gated), which is how production Substrate runtimes are built. This is the direct structural analog of the reported LooksRare `LowLevelETH._returnETHIfAny` bug: an external value-moving call (`call(...)` in Solidity / `Currency::transfer` here) whose failure is never checked, so execution proceeds as if the transfer succeeded.

The comments justify this as "should not fail because curator fee is always less than bounty value," but `Currency::transfer` with `ExistenceRequirement::AllowDeath` can still fail even when the source has sufficient balance: if the destination account (`curator` or `beneficiary`) does not yet exist and the transferred amount is below the chain's Existential Deposit, `pallet_balances` refuses to create the account and returns an error rather than silently succeeding. Since curator accounts and bounty beneficiaries are arbitrary, attacker-influenceable addresses (curator fee amount is set by the bounty proposer/curator during `propose_curator`/`accept_curator`, with no enforced minimum ensuring it clears the ED), this failure condition is reachable by an ordinary, unprivileged extrinsic caller without needing a malicious validator, relayer, or governance action.

### Impact Explanation
When the transfer silently fails:
- `child_bounty_account`'s balance is not actually moved to `curator`/`beneficiary`.
- The pallet nevertheless emits `Event::Claimed` (falsely reporting a successful payout), decrements `ParentChildBounties`, removes the child-bounty description, and sets `*maybe_child_bounty = None`, deleting all on-chain bookkeeping that referenced these funds.
- Because the child-bounty record is gone, there is no remaining code path to retry the payout or recover the leftover balance sitting in `child_bounty_account` — funds are permanently locked/orphaned in the sub-account, exactly mirroring the LooksRare "trapped ETH" scenario, except here there's no subsequent user call that can recover it since the settlement bookkeeping has already been wiped.
- This matches the "permanent user-fund lock" and "settle exactly once to the rightful beneficiary and amount" impact categories in the required-impacts list.

### Likelihood Explanation
Triggering requires only: (1) a child-bounty with a small `fee` (curator fee) below ED, and (2) a `curator` (or `beneficiary`) account that has never held a balance. Both are fully controllable by the bounty's curator/proposer flow (`propose_curator`, `accept_curator`) and the claimer, all unprivileged, non-admin actions. No malicious validator/relayer/collator/governance actor is needed — this is a standard extrinsic-call sequence any user with bounty-curator permissions can construct.

### Recommendation
Propagate transfer results as real `DispatchResult` errors instead of `debug_assert!`, e.g.:
```rust
T::Currency::transfer(&child_bounty_account, curator, curator_fee, AllowDeath)?;
T::Currency::transfer(&child_bounty_account, beneficiary, payout, AllowDeath)?;
```
If it is desired to keep claim atomic/best-effort, at minimum do not remove/None-out the child-bounty state or emit `Claimed` unless both transfers actually succeeded, and ensure destination accounts are pre-verified to meet ED (or route dust to a common sink) before wiping the bounty record.

### Proof of Concept
1. Governance/curator flow creates a parent bounty and a child bounty with `fee` set to an amount below `ExistentialDeposit` (e.g., `fee = 1`, with `ED = 1_000_000_000_000`).
2. A brand-new `curator` account (never funded, zero balance, doesn't exist in `System::Account`) is proposed and accepts the curator role via `accept_curator` (reserving its curator deposit from its own signed extrinsic funds obtained elsewhere, e.g., minimal top-up just for deposit but not for receiving the fee).
3. Anyone calls `claim_child_bounty(parent_bounty_id, child_bounty_id)` after `unlock_at`.
4. Inside the call, `T::Currency::transfer(&child_bounty_account, curator, curator_fee=1, AllowDeath)` fails because `curator` doesn't exist and `1 < ED`; in a release build the `debug_assert!` is a no-op, so this failure is silently ignored.
5. Execution continues: `Event::Claimed` is emitted, `ParentChildBounties` decremented, `ChildBountyDescriptionsV1` removed, and `*maybe_child_bounty = None` — deleting the only state that referenced the still-full `child_bounty_account` balance.
6. The balance in `child_bounty_account` (curator_fee + payout) is now permanently unreachable through any extrinsic, since the corresponding child-bounty record no longer exists to support a retried claim. [2](#0-1)

```rust
		#[pallet::call_index(5)]
		#[pallet::weight(<T as Config>::WeightInfo::claim_child_bounty())]
		pub fn claim_child_bounty(
			origin: OriginFor<T>,
			#[pallet::compact] parent_bounty_id: BountyIndex,
			#[pallet::compact] child_bounty_id: BountyIndex,
		) -> DispatchResult {
			ensure_signed(origin)?;

			// Ensure child-bounty is in expected state.
			ChildBounties::<T>::try_mutate_exists(
				parent_bounty_id,
				child_bounty_id,
				|maybe_child_bounty| -> DispatchResult {
					let child_bounty =
						maybe_child_bounty.as_mut().ok_or(BountiesError::<T>::InvalidIndex)?;

					if let ChildBountyStatus::PendingPayout {
						ref curator,
						ref beneficiary,
						ref unlock_at,
					} = child_bounty.status
					{
						// Ensure block number is elapsed for processing the
						// claim.
						ensure!(
							Self::treasury_block_number() >= *unlock_at,
							BountiesError::<T>::Premature,
						);

						// Make curator fee payment.
						let child_bounty_account =
							Self::child_bounty_account_id(parent_bounty_id, child_bounty_id);
						let balance = T::Currency::free_balance(&child_bounty_account);
						let curator_fee = child_bounty.fee.min(balance);
						let payout = balance.saturating_sub(curator_fee);

						// Unreserve the curator deposit. Should not fail
						// because the deposit is always reserved when curator is
						// assigned.
						let _ = T::Currency::unreserve(curator, child_bounty.curator_deposit);

						// Make payout to child-bounty curator.
						// Should not fail because curator fee is always less than bounty value.
						let fee_transfer_result = T::Currency::transfer(
							&child_bounty_account,
							curator,
							curator_fee,
							AllowDeath,
						);
						debug_assert!(fee_transfer_result.is_ok());

						// Make payout to beneficiary.
						// Should not fail.
						let payout_transfer_result = T::Currency::transfer(
							&child_bounty_account,
							beneficiary,
							payout,
							AllowDeath,
						);
						debug_assert!(payout_transfer_result.is_ok());

						// Trigger the Claimed event.
						Self::deposit_event(Event::<T>::Claimed {
							index: parent_bounty_id,
							child_index: child_bounty_id,
							payout,
							beneficiary: beneficiary.clone(),
						});

						// Update the active child-bounty tracking count.
						ParentChildBounties::<T>::mutate(parent_bounty_id, |count| {
							count.saturating_dec()
						});

						// Remove the child-bounty description.
						ChildBountyDescriptionsV1::<T>::remove(parent_bounty_id, child_bounty_id);

						// Remove the child-bounty instance from the state.
						*maybe_child_bounty = None;

						Ok(())
					} else {
						Err(BountiesError::<T>::UnexpectedStatus.into())
					}
				},
			)
		}
```
