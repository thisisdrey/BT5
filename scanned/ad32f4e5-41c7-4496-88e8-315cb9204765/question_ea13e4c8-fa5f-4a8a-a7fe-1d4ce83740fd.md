`NeighborRPC::get_peer_host` and `send_request` (stackslib/src/net/neighbors/rpc.rs) both trust `convo.data_url` populated from a remote peer's self-reported `HandshakeData.data_url` field during the P2P handshake, with no verification that the peer actually controls the host named in that URL — can a remote peer during handshake advertise a `data_url` pointing at a third-party victim service, and does `NeighborRPC::send_request`'s call to `http.connect_http(network_state, network, data_url, data_addr, None)` then cause the node to originate an HTTP RPC request toward that third-party address on the node's behalf (SSRF-style request via `PeerHost::try_from_url`), i.e., is claimed-data_url == attacker-controlled-destination the actual invariant here rather than a validated binding? Impact: node used as an unauthenticated relay/amplifier to send crafted HTTP requests to arbitrary hosts. Proof idea: Rust test handshaking with a data_url pointing to a non-peer address and asserting `send_request` refuses to connect or restricts destinations to the handshake-authenticated peer's own IP.
