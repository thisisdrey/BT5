### Title
Precompile framework has no built-in delegatecall guard — any new precompile that forgets the opt-in `PrecompileDelegateDenied` check lets a malicious intermediary contract act as the caller ([File: substrate/frame/revive/src/precompiles.rs])

### Summary
`pallet-revive`'s precompile framework mirrors the MetaSwap bug class exactly: it is a generic "aggregator" that lets external code (`Config::Precompiles`, e.g. `pallet-assets`, `pallet-asset-conversion`, `pallet-xcm`, `pallet-vesting` precompiles) plug in and act on behalf of whichever address the EVM environment reports as `caller()`. During a `DELEGATECALL`, `env.caller()` returns the *original* caller, not the intermediary contract that issued the delegatecall [1](#0-0) . The framework itself (`Precompile`/`BuiltinPrecompile` traits in `precompiles.rs`) provides no centralized enforcement preventing delegatecall into a precompile — each precompile author must remember to manually add a `PrecompileDelegateDenied` guard [2](#0-1) . This is proven by the fact that this exact bug class was found and had to be patched piecemeal, precompile by precompile, in PR #11715 ("Reject delegatecall into precompiles via `PrecompileDelegateDenied`") after asset-conversion and vesting precompiles already had it but the ERC20 assets precompile and XCM precompile did not [3](#0-2) .

### Finding Description
The `Precompile` trait lets any pallet register itself at a fixed/prefix address and receive calls, including `DELEGATECALL`s, through `call`/`call_with_info` [4](#0-3) . Nothing in `Instance::call`, `Precompiles::get`, or the tuple-composition machinery rejects delegatecalls by default [5](#0-4) [6](#0-5) .

Concretely, the ERC-20 assets precompile derives the "owner" for `approve`/`permit`-style state changes from `Self::caller(env)`, which under `DELEGATECALL` semantics resolves to the *original* caller rather than the delegate-calling contract: [7](#0-6) . This is precisely the MetaSwap confused-deputy primitive: a contract the user trusted enough to `approve()` (or otherwise interact with) can silently delegate into a precompile and cause it to spend/transfer/approve assets under the original caller's identity, because the precompile framework does not enforce a delegatecall guard — it only offers `CrateError::<T>::PrecompileDelegateDenied` as an opt-in error a precompile author can choose to return [8](#0-7) .

The remediation PR itself documents the exact mechanism and confirms it must be applied per-precompile, not centrally: "Delegatecall to precompiles allows a malicious contract to execute precompile logic in a misleading caller context... There is no legitimate use case for delegatecalling into these precompiles" [1](#0-0) , and it required editing four separate files (`assets/precompiles/src/lib.rs`, `asset-conversion/precompiles/src/lib.rs`, `pallet-xcm/precompiles/src/lib.rs`) to converge on consistent behavior [9](#0-8) . Any future or third-party precompile registered via `Config::Precompiles` (custom runtime chains can add arbitrary precompiles per the framework docs) that omits this manual guard reintroduces the exact same vulnerability, since the framework provides no structural protection — only a convention.

### Impact Explanation
A precompile lacking the delegatecall guard allows an unprivileged attacker to deploy a malicious contract that a victim interacts with normally (e.g., believing it's a simple utility/router contract). That contract then issues a `DELEGATECALL` into a sensitive precompile (asset transfer/approval, vesting claim, XCM dispatch). Because `env.caller()` resolves to the victim during delegatecall, the precompile executes privileged logic (asset approval, transfer, XCM send) as if the victim directly authorized it — enabling theft of approved/held tokens, unauthorized XCM dispatch, or unauthorized vesting claims, without any admin/governance/relayer/validator involvement. This is a direct "theft or unbacked mint/unlock" / "unauthorized execution or origin escalation" class impact against real user funds.

### Likelihood Explanation
Likelihood is contained to the framework's structural weakness rather than the four precompiles already patched in this repo (assets, asset-conversion, xcm, vesting all currently carry the guard per the search results). However, the framework provides no compile-time or run-time enforcement that any `Precompile` implementer must check for delegatecall, so likelihood is high for any new precompile (custom chain-specific precompile, or a not-yet-covered builtin) added without following the convention. The historical pattern in this repo (patch needed for 2+ precompiles that initially lacked it, added after the fact via PR #11715) demonstrates this is an easy omission that has already recurred multiple times.

### Recommendation
Move the delegatecall rejection into the shared framework rather than leaving it opt-in per precompile: add a `DENY_DELEGATE_CALL: bool` (or similar) associated constant/default on the `Precompile`/`BuiltinPrecompile` trait, checked centrally in `Instance::call` / the dispatch path in `exec.rs` before invoking `call`/`call_with_info`, defaulting to deny delegatecall unless a precompile explicitly opts in with justification. This removes the possibility that a new or third-party precompile silently reintroduces the confused-deputy vulnerability.

### Proof of Concept
1. Runtime integrates a new custom precompile (via `Config::Precompiles`) exposing a sensitive action (e.g., asset transfer, approval, or XCM send) that derives the acting account from `env.caller()`/`Self::caller(env)`, following the same pattern as `substrate/frame/assets/precompiles/src/lib.rs::approve` [7](#0-6) , but the author forgets to add the `PrecompileDelegateDenied` check (as had to be manually retrofitted for the assets and XCM precompiles in PR #11715).
2. Attacker deploys a "Caller" contract (structurally identical to the one used in the existing delegatecall tests, e.g. `substrate/frame/assets/precompiles/src/tests.rs::delegatecall_is_rejected`) with a function that issues `address(precompile).delegatecall(encodedApproveOrTransferCall)`.
3. Victim is convinced to call this "Caller" contract (e.g., believing it performs some benign multi-step operation).
4. Inside the delegatecall, `env.caller()` resolves to the victim's address, so the precompile executes `approve`/`transfer`/`send-XCM` as the victim, without the victim ever directly invoking the precompile — reproducing the exact MetaSwap "malicious adapter accesses user's approved tokens" primitive, but through a precompile rather than a Solidity aggregator contract.

	pub fn try_to_revert<T: Config>(e: DispatchError) -> Self {

		let construct = CrateError::<T>::TerminatedInConstructor.into();

	/// Your runtime.
	type T: Config;
	/// The Solidity ABI definition of this pre-compile.
	///
	/// Use the [`self::alloy::sol`] macro to define your interface using Solidity syntax.
	/// The input the caller passes to the pre-compile will be validated and parsed
	/// according to this interface.
	///
	/// Please note that the return value is not validated and it is the pre-compiles
	/// duty to return the abi encoded bytes conformant with the interface here.
	type Interface: SolInterface;
	/// Defines at which addresses this pre-compile exists.
	const MATCHER: AddressMatcher;
	/// Defines whether this pre-compile needs a contract info data structure in storage.
	///
	/// Enabling it unlocks more APIs for the pre-compile to use. Only pre-compiles with a
	/// fixed matcher can set this to true. This is enforced at compile time. Reason is that
	/// contract info is per address and not per pre-compile. Too many contract info structures
	/// and accounts would be created otherwise.
	///
	/// # When set to **true**
	///
	/// - An account will be created at the pre-compiles address when it is called for the first
	///   time. The ed is minted.
	/// - Contract info data structure will be created in storage on first call.
	/// - Only `call_with_info` should be implemented. `call` is never called.
	///
	/// # When set to **false**
	///
	/// - No account or any other state will be created for the address.
	/// - Only `call` should be implemented. `call_with_info` is never called.
	///
	/// # What to use
	///
	/// Should be set to false if the additional functionality is not needed. A pre-compile with
	/// contract info will incur both a storage read and write to its contract metadata when called.
	///
	/// The contract info enables additional functionality:
	/// - Storage deposits: Collect deposits from the origin rather than the caller. This makes it
	///   easier for contracts to interact with the pre-compile as deposits
	/// 	are paid by the transaction signer (just like gas). It also makes refunding easier.
	/// - Contract storage: You can use the contracts key value child trie storage instead of
	///   providing your own state.
	/// 	The contract storage automatically takes care of deposits.
	/// 	Providing your own storage and using pallet_revive to collect deposits is also possible,
	/// though.
	/// - Instantitation: Contract instantiation requires the instantiator to have an account. This

/// A pre-compile ready to be called.
pub(crate) struct Instance<E> {
	has_contract_info: bool,
	address: [u8; 20],
	/// This is the function inside `PrimitivePrecompile` at `address`.
	function: fn(&[u8; 20], Vec<u8>, &mut E) -> Result<Vec<u8>, Error>,
}

impl<E> Instance<E> {
	pub fn has_contract_info(&self) -> bool {
		self.has_contract_info
	}

	pub fn call(&self, input: Vec<u8>, env: &mut E) -> ExecResult {
		let result = (self.function)(&self.address, input, env);
		match result {
			Ok(data) => Ok(ExecReturnValue { flags: ReturnFlags::empty(), data }),
			Err(Error::Revert(msg)) => {
				Ok(ExecReturnValue { flags: ReturnFlags::REVERT, data: msg.abi_encode() })
			},
			Err(Error::Panic(kind)) => Ok(ExecReturnValue {
				flags: ReturnFlags::REVERT,
				data: Panic::from(kind).abi_encode(),
			}),
			Err(Error::Error(err)) => Err(err.into()),
		}
	}

	fn get<E: ExtWithInfo<T = T>>(address: &[u8; 20]) -> Option<Instance<E>> {
		let _ = <Self as Precompiles<T>>::CHECK_COLLISION;
		let mut instance: Option<Instance<E>> = None;
		for_tuples!(
			#(
				if Tuple::MATCHER.matches(address) {
					if Tuple::HAS_CONTRACT_INFO {
						instance = Some(Instance {
							address: *address,
							has_contract_info: true,
							function: Tuple::call_with_info,
						})
					} else {
						instance = Some(Instance {
							address: *address,
							has_contract_info: false,
							function: Tuple::call,
						})
					}
				}
			)*
		);
		instance
	}
