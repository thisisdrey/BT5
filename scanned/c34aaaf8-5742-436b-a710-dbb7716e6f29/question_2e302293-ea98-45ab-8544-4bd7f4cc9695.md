Target: `HttpRequestPreamble::consensus_deserialize` header loop (stackslib/src/net/http/request.rs:355-422), the `value.len() > HTTP_PREAMBLE_MAX_ENCODED_SIZE as usize` check applied per-header-value but not to the aggregate of all headers combined with `HTTP_PREAMBLE_MAX_NUM_HEADERS`. Attacker action: send an RPC request with exactly `HTTP_PREAMBLE_MAX_NUM_HEADERS` headers, each valued at just under `HTTP_PREAMBLE_MAX_ENCODED_SIZE`, all distinct non-recognized header names so each is inserted into the `BTreeMap<String,String>` rather than deduplicated. Preconditions: unauthenticated RPC connection. Call sequence: `req.parse(&buf_read)` via `httparse` (bounded by the fixed `headers` array size) -> per-header value-length check -> `headers.insert`. Equality: total memory committed to the `headers` map (`HTTP_PREAMBLE_MAX_NUM_HEADERS * HTTP_PREAMBLE_MAX_ENCODED_SIZE`) must be a value the node is willing to allocate per unauthenticated connection attempt, and `read_to_crlf2(fd)` reading the raw preamble bytes before `httparse::Request::parse` runs must itself be bounded — if `read_to_crlf2` has no independent byte cap, a request with an enormous number of headers/oversized total header block could be buffered in full before `httparse` even runs. Impact: Critical if `read_to_crlf2` is unbounded (bytes read for the raw preamble buffer are not equal to any enforced maximum before parsing begins), enabling a single-connection memory-pressure DoS. Proof idea: Rust test sending a preamble with a header block larger than any documented cap directly to `HttpRequestPreamble::consensus_deserialize`/`read_to_crlf2` and measuring the buffer size read before an error is returned.
