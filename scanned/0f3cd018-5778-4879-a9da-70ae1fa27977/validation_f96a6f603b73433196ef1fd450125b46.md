### Title
`remove_external_asset` deletes an external asset from a PSM using only internal debt accounting, not the actual reserve balance, permanently stranding external tokens — ([File: substrate/frame/psm/src/lib.rs])

### Summary
The reported bug pattern in `MarinateV2.sol` is: a token is de-listed from an approved-tokens registry by checking only an internal bookkeeping flag/amount, not the actual on-chain balance the contract still holds of that token, so real value becomes permanently stranded and unreachable once the registry entry is gone. The `pallet-psm` `remove_external_asset` extrinsic reproduces exactly this pattern: it gates removal on `PsmDebt` (an internal debt counter) being zero, while the actual external-asset balance is held in a reserve account that is shared across *all* external assets registered under the same internal asset and is never checked before the external asset's metadata (fees, ceiling weight, status) is wiped. [1](#0-0) 

### Finding Description
Each PSM instance has a single reserve account derived only from `internal_asset` (`blake2_256((PalletId::TYPE_ID, PalletId, internal_asset).encode())`), which is shared by every approved external asset on that instance; the reserve balance for any given external is "derived, not stored." [2](#0-1) 

`remove_external_asset` only checks the per-`(internal_asset, external_asset)` `PsmDebt` counter, then wipes `ExternalAssets`, `MintingFee`, `RedemptionFee`, `AssetCeilingWeight`, and `PsmDebt` for that pair: [3](#0-2) 

`PsmDebt` is a logical accounting value (internal asset minted, backed 1:1 by external in the reserve), not the actual `T::Fungibles` balance of that specific external asset held by the shared reserve account. Because the reserve account is shared across all externals of the instance, and nothing in `add_external_asset`/`mint`/`redeem` enforces that the reserve's real balance of a given external asset can never diverge from `PsmDebt` for that pair (e.g. dust/rounding from decimals conversion between internal/external assets during mint/redeem, or an unsolicited direct transfer to the reserve account, or accumulated redemption-fee residue that is not routed anywhere for that pair), `PsmDebt == 0` does not guarantee the reserve's actual balance of `external_asset` is zero.

Once `remove_external_asset` succeeds, `ExternalAssets::<T>::contains_key` becomes false, so `set_minting_fee`, `set_redemption_fee`, `set_asset_ceiling_weight`, and `add_external_asset` for that pair, plus `mint`/`redeem` (which are gated by `AssetNotApproved`/status checks tied to `ExternalAssets`), can no longer reference this external asset on this instance. Any residual balance of that external asset sitting in the shared reserve account becomes economically orphaned: there is no dispatchable that lets an admin or user withdraw a de-listed external asset from the PSM reserve.

This exactly parallels the `MarinateV2.sol` root cause: removal from an approved-list is guarded by an internal debt/accounting check instead of a check on the actual asset balance held by the contract/pallet, so funds transferred in (via rounding, fee dust, or unsolicited transfer) outlive the registry entry and become unrecoverable through normal contract/pallet paths.

### Impact Explanation
This falls under "permanent user-fund ... lock" in the impact gate: value legitimately held by the pallet's reserve account (backing a specific external asset) becomes permanently stuck with no dispatchable path to move it once the corresponding `ExternalAssets` entry is removed. Any decimals-conversion rounding, fee-dust, or unsolicited-transfer residue for a de-listed external asset is lost for as long as the pallet exists in this form, which is a fund-loss/lock condition on a live Substrate-based chain's asset-accounting pallet.

### Likelihood Explanation
The `full_admin` origin can legitimately call `remove_external_asset` as soon as `PsmDebt` reaches zero via normal `redeem` activity, without any additional privilege escalation, and `PsmDebt` reaching zero does not require the reserve's true external-asset balance to be zero — any accumulated rounding remainder from repeated mint/redeem cycles across differing decimals, or a stray transfer to the shared reserve account, is enough to produce a stranded, non-zero balance at removal time. This does not require a malicious admin, validator, relayer, or governance actor — the admin can perform routine, intended maintenance (removing an external once its tracked debt is drained) and still strand funds due to the accounting/balance mismatch.

### Recommendation
Before removing `external_asset` from `ExternalAssets`, additionally require that the reserve account's actual `T::Fungibles::balance(external_asset, &Self::psm_account(&internal_asset))` attributable to that external is zero (or, since the reserve account is shared, track and check a per-external balance/residual explicitly rather than relying solely on `PsmDebt`). At minimum, mirror the `MarinateV2` fix: add an explicit `ensure!(actual_balance_of(external_asset) == 0, Error::<T>::ResidualBalance)` check, or add a dispatchable to sweep any de-listed external's residual balance to the `fee_destination`/admin before or as part of removal.

### Proof of Concept
1. Admin creates a PSM for `internal_asset` and calls `add_external_asset` to approve `USDC` (18 decimals) and `USDX` (a different decimals asset) on the same instance — both share the single reserve account derived from `internal_asset` alone. [4](#0-3) 
2. A user calls `mint`/`redeem` repeatedly for `USDX` where `internal_decimals` and `USDX`'s decimals differ; integer-division rounding in the decimals conversion leaves a small residual `USDX` balance in the shared reserve account that is never reflected as outstanding `PsmDebt` for the `(internal_asset, USDX)` pair (debt is fully drained to zero by the final `redeem`, matching the pattern shown in `remove_external_asset_succeeds_after_debt_drained_with_external_decimal_drift`). [5](#0-4) 
3. Admin calls `remove_external_asset(internal_asset, USDX)`. Since `PsmDebt::<T>::get(&internal_asset, &USDX).is_zero()` passes, the call succeeds and wipes the `ExternalAssets`, fee, and ceiling entries for `USDX`. [6](#0-5) 
4. The residual `USDX` balance remains in the shared reserve account, but `mint`/`redeem`/`set_*` calls for `(internal_asset, USDX)` now fail with `AssetNotApproved`, and no dispatchable exists to withdraw the stranded balance — it is permanently locked in the pallet's reserve account.

		pub fn add_external_asset(
			origin: OriginFor<T>,
			internal_asset: T::AssetId,
			external_asset: T::AssetId,
		) -> DispatchResult {
			Self::ensure_psm_admin(origin, &internal_asset, |l| l.can_manage_assets())?;
			let mut info = Psm::<T>::get(&internal_asset).ok_or(Error::<T>::PsmNotFound)?;
			ensure!(
				!ExternalAssets::<T>::contains_key(&internal_asset, &external_asset),
				Error::<T>::AssetAlreadyApproved
			);
			ensure!(info.external_count < T::MaxExternals::get(), Error::<T>::TooManyAssets);
			ensure!(
				T::Fungibles::asset_exists(external_asset.clone()),
				Error::<T>::AssetDoesNotExist
			);

			let asset_decimals = T::Fungibles::decimals(external_asset.clone());
			ensure!(
				T::Fungibles::decimals(internal_asset.clone()) == info.internal_decimals,
				Error::<T>::DecimalsMismatch
			);
			ensure!(
				(asset_decimals.abs_diff(info.internal_decimals) as u32) <= MAX_DECIMALS_DIFF,
				Error::<T>::DecimalsRangeExceeded
			);

			ExternalAssets::<T>::insert(
				&internal_asset,
				&external_asset,
				ExternalAssetInfo {
					status: CircuitBreakerLevel::AllEnabled,
					decimals: asset_decimals,
				},
			);
			info.external_count = info.external_count.saturating_add(1);
			Psm::<T>::insert(&internal_asset, info);

			Self::deposit_event(Event::ExternalAssetAdded { internal_asset, external_asset });
			Ok(())
		}

		#[pallet::call_index(10)]
		#[pallet::weight(T::WeightInfo::remove_external_asset())]
		pub fn remove_external_asset(
			origin: OriginFor<T>,
			internal_asset: T::AssetId,
			external_asset: T::AssetId,
		) -> DispatchResult {
			Self::ensure_psm_admin(origin, &internal_asset, |l| l.can_manage_assets())?;
			let mut info = Psm::<T>::get(&internal_asset).ok_or(Error::<T>::PsmNotFound)?;
			ensure!(
				ExternalAssets::<T>::contains_key(&internal_asset, &external_asset),
				Error::<T>::AssetNotApproved
			);
			ensure!(
				PsmDebt::<T>::get(&internal_asset, &external_asset).is_zero(),
				Error::<T>::AssetHasDebt
			);
			ExternalAssets::<T>::remove(&internal_asset, &external_asset);
			MintingFee::<T>::remove(&internal_asset, &external_asset);
			RedemptionFee::<T>::remove(&internal_asset, &external_asset);
			AssetCeilingWeight::<T>::remove(&internal_asset, &external_asset);
			PsmDebt::<T>::remove(&internal_asset, &external_asset);
			info.external_count = info.external_count.saturating_sub(1);
			Psm::<T>::insert(&internal_asset, info);

			Self::deposit_event(Event::ExternalAssetRemoved { internal_asset, external_asset });
			Ok(())
		}
