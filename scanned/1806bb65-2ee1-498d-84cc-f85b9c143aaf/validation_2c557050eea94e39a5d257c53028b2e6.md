## Analysis

The Ajna report's core broken invariant is: **a public, unprivileged, cheaply-repeatable action drives a self-referential utilization-based multiplier upward with no maximum cap and only slow multiplicative decay, letting an attacker push the value to economically-prohibitive extremes and deny service to everyone else who depends on that market.**

The local analog is the on-demand coretime "spot traffic" mechanism in `polkadot/runtime/parachains/src/on_demand/mod.rs`, which computes a `FixedU128` traffic multiplier from queue utilization vs. a target, using the exact same quadratic feedback formula as `pallet_transaction_payment::TargetedFeeAdjustment`, but — critically — **without an upper bound**.

### Title
Unbounded on-demand coretime spot-traffic multiplier allows unprivileged griefer to price out all on-demand parachains - (File: `polkadot/runtime/parachains/src/on_demand/mod.rs`)

### Summary
`calculate_spot_traffic` in `on_demand/mod.rs` adjusts a global `traffic` multiplier toward a `target_queue_utilisation` using a quadratic feedback term, exactly mirroring the interest-rate/fee-multiplier pattern flagged in the Ajna report. Unlike `TargetedFeeAdjustment`, which clamps to `MinimumMultiplier`/`MaximumMultiplier`, this multiplier has only a floor (`TrafficDefaultValue`) and no ceiling.

### Finding Description
`do_place_order` [1](#0-0)  lets any signed account push an order into a single, shared `OrderStatus::queue` for a `para_id` of the caller's choosing, with no check that the `para_id` is a valid, onboarded on-demand parachain. Each call also invokes `update_spot_traffic`, which recomputes `traffic` via `calculate_spot_traffic` [2](#0-1) :

```
new_traffic = traffic * (1 + diff + diff^2/2)   // when queue over target
```

This is the same feedback structure as `TargetedFeeAdjustment::convert` [3](#0-2) , but that function clamps every result with `.clamp(min_multiplier, max_multiplier)` using a configured `MaximumMultiplier` [4](#0-3) . `calculate_spot_traffic`, by contrast, only enforces a floor via `.max(TrafficDefaultValue)` on both branches [5](#0-4)  — there is no corresponding maximum cap in `Config` (only `TrafficDefaultValue`, `MaxHistoricalRevenue`, `PalletId` are configured) [6](#0-5) .

Because the queue is shared across all on-demand parachains and orders can target arbitrary `ParaId` values, an attacker can cheaply keep `queue_size` at or near `on_demand_queue_max_size` every block, forcing `queue_util_ratio` far above `target_queue_utilisation` continuously. The quadratic term compounds multiplicatively each block (`on_initialize` calls `update_spot_traffic` unconditionally [7](#0-6) ), so `traffic`, and hence `spot_price = traffic * on_demand_base_fee`, can grow without any ceiling toward `FixedU128::MAX`.

### Impact Explanation
Once `spot_price` is inflated, `do_place_order`'s check `ensure!(spot_price.le(&max_amount), Error::<T>::SpotPriceHigherThanMaxAmount)` [8](#0-7)  makes it economically infeasible for any legitimate parachain to buy on-demand blockspace. This is the same class of impact as the Ajna scenario: a public, unprivileged, market-manipulation-driven state variable becomes extreme and self-sustaining, degrading (stalling) block production/assignment for every on-demand parachain sharing the queue — without needing a malicious validator, collator, or governance actor, satisfying the "public underpriced work that degrades block production" impact category.

### Likelihood Explanation
The attack only requires an unprivileged signed account with modest funds to repeatedly call `place_order_with_credits`/`place_order_allow_death` targeting the shared queue up to its configured capacity; no privileged role, validator collusion, or leaked keys are required. Recovery is slow because decay is multiplicative (`traffic * fraction<1`) and only occurs when queue utilization drops below target, which the attacker can prevent by continuing to enqueue cheap orders (including for arbitrary/unused `ParaId`s, since no validity check exists).

### Recommendation
Add a configurable maximum bound (`MaxTraffic`/`MaximumMultiplier`-style `Get<FixedU128>`) and `.clamp(min, max)` the result in `calculate_spot_traffic`, mirroring `TargetedFeeAdjustment`. Additionally, validate that `para_id` passed to `do_place_order` corresponds to an existing on-demand-eligible parachain before allowing it to consume queue capacity and influence the shared traffic multiplier.

### Proof of Concept
1. Attacker repeatedly calls `place_order_with_credits`/`place_order_allow_death` (using either credits or a topped-up account) targeting an arbitrary or attacker-owned `para_id`, keeping `OrderStatus::queue.len()` at `on_demand_queue_max_size` every block.
2. Each block's `on_initialize` → `update_spot_traffic` → `calculate_spot_traffic` sees `queue_util_ratio` (near 100%) far above `on_demand_target_queue_utilization` (e.g. 25%), compounding `traffic` upward with no ceiling, unlike the analogous `TargetedFeeAdjustment` used for transaction fees.
3. After sustained execution (analogous to the report's two-month interest-rate climb), `spot_price = traffic * on_demand_base_fee` becomes prohibitively high, causing legitimate on-demand parachains' `place_order_*` calls to fail with `SpotPriceHigherThanMaxAmount`, denying them blockspace acquisition indefinitely, since recovery requires many low-utilization blocks that the attacker can keep from occurring.

	fn calculate_spot_traffic(
		traffic: FixedU128,
		queue_capacity: u32,
		queue_size: u32,
		target_queue_utilisation: Perbill,
		variability: Perbill,
	) -> Result<FixedU128, SpotTrafficCalculationErr> {
		// Return early if queue has no capacity.
		if queue_capacity == 0 {
			return Err(SpotTrafficCalculationErr::QueueCapacityIsZero);
		}

		// Return early if queue size is greater than capacity.
		if queue_size > queue_capacity {
			return Err(SpotTrafficCalculationErr::QueueSizeLargerThanCapacity);
		}

		// (queue_size / queue_capacity) - target_queue_utilisation
		let queue_util_ratio = FixedU128::from_rational(queue_size.into(), queue_capacity.into());
		let positive = queue_util_ratio >= target_queue_utilisation.into();
		let queue_util_diff = queue_util_ratio.max(target_queue_utilisation.into()) -
			queue_util_ratio.min(target_queue_utilisation.into());

		// variability * queue_util_diff
		let var_times_qud = queue_util_diff.saturating_mul(variability.into());

		// variability^2 * queue_util_diff^2
		let var_times_qud_pow = var_times_qud.saturating_mul(var_times_qud);

		// (variability^2 * queue_util_diff^2)/2
		let div_by_two: FixedU128;
		match var_times_qud_pow.const_checked_div(2.into()) {
			Some(dbt) => div_by_two = dbt,
			None => return Err(SpotTrafficCalculationErr::Division),
		}

		// traffic * (1 + queue_util_diff) + div_by_two
		if positive {
			let new_traffic = queue_util_diff
				.saturating_add(div_by_two)
				.saturating_add(One::one())
				.saturating_mul(traffic);
			Ok(new_traffic.max(<T as Config>::TrafficDefaultValue::get()))
		} else {
			let new_traffic = queue_util_diff.saturating_sub(div_by_two).saturating_mul(traffic);
			Ok(new_traffic.max(<T as Config>::TrafficDefaultValue::get()))
		}
	}
