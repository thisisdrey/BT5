Based on my investigation, I found a strong local analog to the "unupdated global accounting variable" bug class in `pallet-delegated-staking`'s slash-realization path.

### Title
`AgentLedger::total_delegated` is never decremented when a slash is actually realized via `do_slash`, causing permanent overstatement of an agent's effective/stakeable balance - (File: `substrate/frame/delegated-staking/src/lib.rs`)

### Summary
`pallet-delegated-staking` tracks two counters per agent: `total_delegated` (sum of all live delegations) and `pending_slash` (unrealized slash reported by `on_slash`). `effective_balance()` is computed as `total_delegated.saturating_sub(pending_slash)`. When a pending slash is actually realized against a specific delegator via `Pallet::do_slash`, the code reduces the delegator's `Delegation.amount` and the agent's `pending_slash` counter, but never reduces `total_delegated` to match the permanent reduction in the delegator's balance. This mirrors the Tapioca bug where a per-user debt field (`userBorrowPart[user]`) was updated but the corresponding global aggregate (`totalBorrow`) was left stale, corrupting all subsequent computations that depend on the aggregate.

### Finding Description
In `Pallet::do_slash` [1](#0-0) , the flow is:
1. `agent_ledger.ledger.pending_slash > 0` is checked.
2. The delegator's held funds are slashed via `T::Currency::slash(...)`, yielding `actual_slash`.
3. `agent_ledger.remove_slash(actual_slash).save()` — this reduces `pending_slash` by `actual_slash`.
4. `delegation.amount -= actual_slash` — the delegator's per-account delegation is permanently reduced and saved.

Nowhere in this function (nor in `AgentLedger::remove_slash`, which only touches `pending_slash`) is `AgentLedger::total_delegated` decremented.

`effective_balance()` is defined as: [2](#0-1) 
```
pub(crate) fn effective_balance(&self) -> BalanceOf<T> {
    ...
    self.total_delegated.saturating_sub(self.pending_slash)
}
```

Before realization: `total_delegated = D`, `pending_slash = S` (added by `on_slash`), so `effective_balance = D - S` — correctly reflecting the unrealized slash.

After `do_slash` realizes the slash against one or more delegators for amount `S` (summed `actual_slash`): `pending_slash` drops to `0` (assuming the full pending amount is realized), but `total_delegated` remains `D` (unchanged). `effective_balance` becomes `D - 0 = D`, i.e., it snaps back to the pre-slash value even though the delegator's real, held balance has permanently dropped by `S`. The agent's `total_delegated` never again reflects the true sum of live `Delegation.amount` values across all its delegators — it is now permanently inflated by the realized-slash amount, exactly analogous to `totalBorrow` staying stale after `userBorrowPart[user]` was reduced in the Tapioca report.

This corrupted `total_delegated` feeds `stakeable_balance()` (`effective_balance() - unclaimed_withdrawals`), which governs `available_to_bond()` and thus how much the agent is allowed to (re)bond into `T::CoreStaking` via `do_bond`. It also is asserted for consistency by the pallet's own `try_state` check `check_delegators`, which expects `ledger.total_delegated == total_delegated` (the actual sum over all `Delegators` entries) — confirming this invariant is expected to hold and that failing to update it is a genuine storage-consistency corruption, not an intentional design choice.

### Impact Explanation
The corrupted `total_delegated` overstates the agent's effective and stakeable balance permanently after any realized slash. This lets an agent bond/rebond more into core staking than its delegators' real held balances support, and lets downstream consumers (e.g., `pallet-nomination-pools`, which relies on `DelegationInterface`/`StakeAdapter` built on this pallet when using the `DelegateStake` strategy) compute inflated pool balances relative to actual backing funds. Because agents can be pool bonded accounts, this can propagate into TVL-style accounting mismatches for nomination pools using the delegate-stake strategy, and ultimately risks under-collateralized delegation vs. real balances — a fund-accounting integrity break rather than an outright fund theft, but one that degrades intended slashing economics and can allow the agent to over-bond relative to genuinely available (unslashed) funds.

### Likelihood Explanation
The path is reachable through the normal, permissionless flow: `on_slash` (triggered by ordinary core-staking slashing) sets `pending_slash`, and `do_slash` is the standard mechanism (invoked e.g. by `pallet-nomination-pools::apply_slash`, callable by any account) used to realize it against a delegator. No privileged actor, governance, or malicious peer is required — any slash event followed by the standard permissionless slash-application call triggers the divergence. It is deterministic and occurs on every slash realization, not an edge case.

### Recommendation
In `Pallet::do_slash` (`substrate/frame/delegated-staking/src/lib.rs`), after computing `actual_slash`, also decrement `agent_ledger`'s `total_delegated` by `actual_slash` (in addition to `pending_slash`), so that `total_delegated` continues to equal the true sum of live `Delegation.amount` entries. This mirrors the Tapioca fix of updating the global `totalBorrow` alongside the per-user `userBorrowPart[user]` decrement, and would keep `effective_balance()`/`stakeable_balance()` consistent with real backing funds.

### Proof of Concept
1. Agent `A` registers with `total_delegated = 0`.
2. Delegator `D` delegates `100` to `A` → `total_delegated = 100`, `pending_slash = 0`, `effective_balance() = 100`.
3. `A`'s stash is slashed in core staking for `30`; `on_slash` runs → `pending_slash = 30`. `effective_balance() = 100 - 30 = 70` (correct, reflects pending loss).
4. Permissionless caller invokes `do_slash(agent=A, delegator=D, amount=30, reporter=None)`:
   - `T::Currency::slash` removes `30` from `D`'s held balance → `actual_slash = 30`.
   - `agent_ledger.remove_slash(30)` → `pending_slash = 0`.
   - `delegation.amount = 100 - 30 = 70` (correctly reduced).
   - `total_delegated` is **not** touched — remains `100`.
5. Now `effective_balance() = 100 - 0 = 100`, even though the real, live sum of delegations to `A` is `70` (matching `D`'s actual held balance). `stakeable_balance()` and `available_to_bond()` are inflated by exactly `30`, and the pallet's own `check_delegators` try-state invariant (`ledger.total_delegated == sum of Delegation.amount`) would now fail, confirming the corruption.

```rust
	/// Take slash `amount` from agent's `pending_slash`counter and apply it to `delegator` account.
	pub fn do_slash(
		agent: Agent<T::AccountId>,
		delegator: Delegator<T::AccountId>,
		amount: BalanceOf<T>,
		maybe_reporter: Option<T::AccountId>,
	) -> DispatchResult {
		// get inner type
		let agent = agent.get();
		let delegator = delegator.get();

		let agent_ledger = AgentLedgerOuter::<T>::get(&agent)?;
		// ensure there is something to slash
		ensure!(agent_ledger.ledger.pending_slash > Zero::zero(), Error::<T>::NothingToSlash);

		let mut delegation = <Delegators<T>>::get(&delegator).ok_or(Error::<T>::NotDelegator)?;
		ensure!(delegation.agent == agent.clone(), Error::<T>::NotAgent);
		ensure!(delegation.amount >= amount, Error::<T>::NotEnoughFunds);

		// slash delegator
		let (mut credit, missing) =
			T::Currency::slash(&HoldReason::StakingDelegation.into(), &delegator, amount);

		defensive_assert!(missing.is_zero(), "slash should have been fully applied");

		let actual_slash = credit.peek();

		// remove the applied slashed amount from agent.
		agent_ledger.remove_slash(actual_slash).save();
		delegation.amount =
			delegation.amount.checked_sub(&actual_slash).ok_or(ArithmeticError::Overflow)?;
		delegation.update(&delegator);

		if let Some(reporter) = maybe_reporter {
			let reward_payout: BalanceOf<T> = T::SlashRewardFraction::get() * actual_slash;
			let (reporter_reward, rest) = credit.split(reward_payout);

			// credit is the amount that we provide to `T::OnSlash`.
			credit = rest;

			// reward reporter or drop it.
			let _ = T::Currency::resolve(&reporter, reporter_reward);
		}

		T::OnSlash::on_unbalanced(credit);

		Self::deposit_event(Event::<T>::Slashed { agent, delegator, amount });

		Ok(())
	}
```

	/// Effective total balance of the `Agent`.
	///
	/// This takes into account any slashes reported to `Agent` but unapplied.
	pub(crate) fn effective_balance(&self) -> BalanceOf<T> {
		defensive_assert!(
			self.total_delegated >= self.pending_slash,
			"slash cannot be higher than actual balance of delegator"
		);

		// pending slash needs to be burned and cannot be used for stake.
		self.total_delegated.saturating_sub(self.pending_slash)
	}
