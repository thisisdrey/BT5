## Analysis

The Y2K bug's core broken invariant: a price value is consumed without verifying `updatedAt` freshness, so a stale price can silently be treated as current. The closest local analog in this repository is the generic **Oracle pallet** at `substrate/frame/honzon/oracle/src/lib.rs`, which is a reusable primitive intended to feed price/data into downstream consumer pallets (collateral valuation, depeg/liquidation logic, etc.) via the `DataProvider` trait.

### Title
Oracle pallet `DataProvider::get()` discards the timestamp, allowing consumers to act on unboundedly stale data with no freshness check - (File: `substrate/frame/honzon/oracle/src/lib.rs`)

### Summary
`Pallet::get()` and the `DataProvider` implementation return only the aggregated `OracleValue`, dropping the `timestamp` field entirely, so any downstream pallet built on this primitive has no way to detect that the value it receives is stale.

### Finding Description
Oracle data is stored with a timestamp in `Values<T, I>` as `TimestampedValue { value, timestamp }`: [1](#0-0) 

The standard consumer-facing interface, `DataProvider`, strips that timestamp before returning the value: [2](#0-1) 

The `Values` map is only updated when `do_feed_values` is called by an operator and `combined()` successfully produces a new aggregate: [3](#0-2) 

The aggregation logic, `DefaultCombineData::combine_data`, filters *raw per-operator submissions* by `ExpiresIn` before aggregating, but if too few fresh raw submissions remain (e.g. operators stop feeding, go offline, or are slow), it falls back to returning the **previous** aggregated value unchanged: [4](#0-3) 

Because `Values<T, I>` is never itself expired or cleared, and `DataProvider::get()` returns only the bare `OracleValue` with no timestamp, a runtime built with this pallet (e.g. for collateral pricing, liquidation triggers, or depeg detection akin to the Y2K `ControllerPeggedAssetV2`) cannot distinguish a live price from a price that has been frozen in storage indefinitely because operators stopped submitting. This exactly mirrors the reported bug: the `updatedAt`/staleness check is missing at the point where the price is consumed for a critical decision (e.g. depeg/liquidation), even though the raw timestamp data technically exists in the pallet (just as `updatedAt` existed in the Chainlink response but was discarded/unchecked by the caller).

`DataProviderExtended::get_all_values()` does expose the timestamp, but it is not the interface documented/used for simple price consumption (`DataProvider`), and nothing in the pallet enforces that consumers must use the extended API or perform any freshness check.

### Impact Explanation
Any consumer pallet in a runtime built on `polkadot-sdk` that relies on `pallet-oracle`'s `DataProvider::get()` for collateral valuation, liquidation, or peg-stability checks would act on an unboundedly stale price whenever oracle operators stop submitting (network partition, operator downtime, censorship, or intentional operator inaction). This can lead to wrong liquidation/depeg decisions, incorrect collateral accounting, or failure to halt operations that should be halted on a real price move — a direct analog of the "outdated price causing wrong depeg events" impact from the source report, satisfying the "runtime bugs that compromise intended behavior" and "theft or unbacked mint/unlock" impact classes when instantiated in a lending/collateral-style consumer.

### Likelihood Explanation
No malicious actor, governance action, or privileged role is required — the flaw manifests under entirely benign conditions (operators simply not submitting fresh data for any reason, including outages). Any runtime that adopts this shared pallet and wires `DataProvider::get()` into financial logic inherits the defect automatically, since the API contract gives no way to check freshness.

### Recommendation
Change `DataProvider::get()` (or add a required alternative) to return the `TimestampedValue` (or at least fail/return `None`) when `now.saturating_sub(timestamp) > MaxStaleness`, and document/enforce that consumers must check freshness before using the value, similar to introducing a staleness limit and reverting/rejecting on stale Chainlink data in the referenced fix.

### Proof of Concept
1. Configure a runtime with `pallet-oracle` and a consumer pallet that calls `<Oracle as DataProvider<Key, Value>>::get(&key)` for a critical decision (e.g., collateral price check).
2. Have the minimum required oracle operators feed a value once, so `Values<T,I>` is populated with `TimestampedValue { value: PRICE, timestamp: T0 }`.
3. Stop all further `feed_values` submissions (operators offline / censored) for an arbitrarily long time — no re-aggregation occurs, so `Values<T,I>` remains `{ value: PRICE, timestamp: T0 }` forever.
4. At time `T0 + N` (arbitrarily large), the consumer pallet calls `DataProvider::get(&key)` and receives `PRICE` with no indication it is stale, exactly as in `substrate/frame/honzon/oracle/src/tests.rs` `should_combined_data`, where `Timestamp::set_timestamp(23456)` is advanced far past the original feed timestamp `12345` and `ModuleOracle::get(&key)` still returns the old `expected` value unchanged: [5](#0-4) 

This demonstrates that the pallet's primary consumer API provides no mechanism to detect or reject stale data.

	fn do_feed_values(who: T::AccountId, values: Vec<(T::OracleKey, T::OracleValue)>) {
		let now = T::Time::now();
		for (key, value) in &values {
			let timestamped = TimestampedValue { value: value.clone(), timestamp: now };

		}

	}

```rust
	fn combine_data(
		_key: &<T as Config<I>>::OracleKey,
		mut values: Vec<TimestampedValueOf<T, I>>,
		prev_value: Option<TimestampedValueOf<T, I>>,
	) -> Option<TimestampedValueOf<T, I>> {
		let expires_in = ExpiresIn::get();
		let now = T::Time::now();

		values.retain(|x| x.timestamp.saturating_add(expires_in) > now);

		let count = values.len() as u32;
		let minimum_count = MinimumCount::get();
		if count < minimum_count || count == 0 {
			return prev_value;
		}

		let mid_index = count / 2;
		// Won't panic as `values` ensured not empty.
		let (_, value, _) =
			values.select_nth_unstable_by(mid_index as usize, |a, b| a.value.cmp(&b.value));
		Some(value.clone())
	}
```
