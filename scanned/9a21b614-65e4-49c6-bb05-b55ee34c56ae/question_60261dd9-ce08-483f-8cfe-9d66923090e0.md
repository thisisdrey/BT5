Target: `WalletImpl::resolve_auth` timestamp check in contracts/wallet/src/contract.rs. Attacker action: craft `WalletAuthorization::Signature{msg: OffchainMessage{timestamp: far_future, ...}, proof}` signed once by the legitimate owner for a narrow intended validity, then repeatedly call `w_resolve_auth` (a view method, hence free and infinitely repeatable) against every future block indefinitely, since the only check is `if Timestamp::now() < msg.timestamp { return Err(FromTheFuture) }` with no upper-bound expiry check at all. Preconditions: attacker holds a previously-signed offchain authorization (e.g. leaked via a legitimate but since-revoked integration) whose `msg.timestamp` has passed. Call sequence: `resolve_auth` -> `Signature` branch -> timestamp lower-bound check passes forever once `now >= msg.timestamp` -> `S::verify_offchain_msg` passes (signature itself never expires) -> `AuthorizationResolution::new(msg.payload)` returned unconditionally, indefinitely. Binding: the number of times a given signed offchain authorization is honored under a `payload` a downstream consumer settles on should be bounded/expected == what the signer intended, not unbounded reuse of a single signature with no expiry. Scoped impact (High): an authorization the owner intended as a one-time or time-boxed approval remains resolvable to the same `payload` forever, letting an unprivileged holder of the old blob replay it against any downstream integrator that trusts a fresh `w_resolve_auth` call as proof of current intent.
