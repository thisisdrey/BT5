## Analysis

The Unitas report's core broken invariant is: **an oracle price is treated as "current" indefinitely, with no on-chain check that it hasn't gone stale relative to real-world conditions**, because updates are throttled by an out-of-protocol incentive (gas cost) rather than a protocol-enforced freshness bound.

The closest local analog in `paritytech/polkadot-sdk` is the Snowbridge outbound-queue fee pricing mechanism, which uses a governance-set `PricingParameters.exchange_rate` (ETH/DOT) that is consumed directly, with no freshness bound, staleness threshold, or automatic decay/expiry check — exactly the "no clear threshold on when to refresh" pattern from the report.

### Title
Snowbridge outbound-queue fee calculation uses unbounded, non-expiring `PricingParameters.exchange_rate` with no staleness enforcement, permitting public underpriced message delivery - (File: `bridges/snowbridge/pallets/outbound-queue/src/lib.rs`)

### Summary
`snowbridge_pallet_outbound_queue::Pallet::calculate_fee` and `do_process_message` consume `T::PricingParameters::get()` — including the ETH/DOT `exchange_rate` — as if it were always current, with no on-chain timestamp, expiry, or staleness threshold attached to the parameter. The module doc itself acknowledges the value is only refreshed "manually... every few weeks," mirroring the Unitas report's admitted "oracle updated depending on gas fees" behavior with no enforced freshness bound.

`params.exchange_rate` is pulled straight from storage via `T::PricingParameters::get()` inside `do_process_message`: [2](#0-1) 

There is no timestamp field on `PricingParameters`, and no check anywhere that the stored `exchange_rate`/`fee_per_gas` is "recent enough" before being used to price a message: [3](#0-2) 

The module documentation explicitly states this is a manual, non-protocol-enforced update cadence, exactly analogous to the Unitas oracle's gas-fee-gated update pattern: [4](#0-3) 

Because `validate()` only checks values are non-zero (not that they are recent), and no code path re-derives or bounds `exchange_rate` against elapsed time or block number, any user submitting an XCM message through the exporter pays a fee computed from parameters that can be arbitrarily stale relative to the real ETH/DOT market rate and Ethereum gas price. [5](#0-4) 

### Impact Explanation
If the real ETH/DOT rate or Ethereum gas price moves significantly faster than the (documented, manual, "every few weeks") update cadence, the `RemoteFeeAdjusted` computed on-chain will underprice the actual cost of relayer gas reimbursement and relayer reward. Since `do_process_message` is invoked for every ordinary, permissionless XCM message routed to the outbound queue (no privileged origin required to trigger a send), any user can continue sending messages priced against the stale rate. This causes systematically underpriced work: relayers are not adequately compensated to submit messages to Ethereum, discouraging relaying and stalling bridge message processing — squarely matching the allowed impact category "public underpriced work that degrades block production or stalls bridge processing."

### Likelihood Explanation
No malicious relayer, validator, collator, or leaked key is required — the vulnerability is triggered by ordinary users interacting with the bridge (any `pallet_xcm`/exporter usage that lands a message in `MessageQueue` for the outbound queue) during a period where governance has not (or could not, e.g. due to a volatile market) refreshed `PricingParameters` in time. The bug is a missing structural safeguard (no staleness/expiry gate on the pricing data), not governance misbehavior — governance still sets correct values, it's the protocol's failure to bound acceptance of those values over time that is the flaw.

### Recommendation
Attach a `last_updated` block number (or timestamp) to `PricingParameters`, and enforce a maximum allowed age (a `MaxPricingParametersAge` config constant, analogous to the Unitas fix's default 1-day threshold) inside `calculate_fee`/`do_process_message`. If the parameters exceed the threshold, either reject/queue the message for later processing, fall back to a conservative (safe-maximum) fee, or halt outbound processing until governance refreshes the parameters — never silently price using arbitrarily old data.

### Proof of Concept
1. Runtime is deployed with `PricingParameters { exchange_rate: FixedU128::from_rational(1, 400), fee_per_gas: gwei(20), ... }` as configured at genesis/last governance update: [6](#0-5) 
2. Time passes (weeks), and the real ETH/DOT market rate moves substantially (e.g., ETH price rises), while governance has not yet called `set_pricing_parameters` to refresh `exchange_rate`.
3. Any unprivileged user sends an XCM message that is routed through `SnowbridgeExporter`/inbound to the outbound queue's `do_process_message`.
4. `Self::calculate_fee(max_dispatch_gas, pricing_params)` computes `RemoteFeeAdjusted` using the stale `exchange_rate`, producing a DOT fee that under-compensates the real ETH-denominated relayer cost.
5. The message is accepted and committed with this underpriced `max_fee_per_gas`/`reward` baked into `CommittedMessage`, with no on-chain check ever comparing the parameter's age against a threshold before use.

		/// Calculate total fee in native currency to cover all costs of delivering a message to the
		/// remote destination. See module-level documentation for more details.
		pub(crate) fn calculate_fee(
			gas_used_at_most: u64,
			params: PricingParameters<T::Balance>,
		) -> Fee<T::Balance> {
			// Remote fee in ether
			let fee = Self::calculate_remote_fee(
				gas_used_at_most,
				params.fee_per_gas,
				params.rewards.remote,
			);

			// downcast to u128
			let fee: u128 = fee.try_into().defensive_unwrap_or(u128::MAX);

			// multiply by multiplier and convert to local currency
			let fee = FixedU128::from_inner(fee)
				.saturating_mul(params.multiplier)
				.checked_div(&params.exchange_rate)
				.expect("exchange rate is not zero; qed")
				.into_inner();

			// adjust fixed point to match local currency
			let fee = Self::convert_from_ether_decimals(fee);

			Fee::from((Self::calculate_local_fee(), fee))
		}

impl<Balance> PricingParameters<Balance>
where
	Balance: BaseArithmetic + Unsigned + Copy,
{
	pub fn validate(&self) -> Result<(), InvalidPricingParameters> {
		if self.exchange_rate == FixedU128::zero() {
			return Err(InvalidPricingParameters);
		}
		if self.fee_per_gas == U256::zero() {
			return Err(InvalidPricingParameters);
		}
		if self.rewards.local.is_zero() {
			return Err(InvalidPricingParameters);
		}
		if self.rewards.remote.is_zero() {
			return Err(InvalidPricingParameters);
		}
		if self.multiplier == FixedU128::zero() {
			return Err(InvalidPricingParameters);
		}
		Ok(())
	}
}
