## Analysis

The Solidity bug's core invariant is: *an unbounded input to a fixed-point reward-per-token calculation, combined with unbounded elapsed time, can push an intermediate product past the precision multiplier's safe range, corrupting the accounting for all participants.* The local analog is in `pallet-asset-rewards`, which implements the exact same "Synthetix-style" JIT (just-in-time) reward-per-token algorithm cited in its own doc comments. [1](#0-0) 

## Finding

The pool's `reward_rate_per_block` and `expiry_block` are unbounded, and `reward_per_token()` multiplies `reward_rate_per_block * rewardable_blocks_elapsed * PRECISION_SCALING_FACTOR` before dividing by `total_tokens_staked`: [2](#0-1) 

`create_pool` places no upper bound on `reward_rate_per_block`: [3](#0-2) 

`set_pool_reward_rate_per_block` only enforces the rate strictly increases, never checks against a safe maximum, and `set_pool_expiry_block` only enforces the expiry strictly extends, with no upper bound either: [4](#0-3) [5](#0-4) 

Crucially, `update_pool_and_staker_rewards` (which calls `reward_per_token`) is invoked unconditionally at the top of `stake`, `unstake`, and `harvest_rewards`, before any staker-controlled action is checked: [6](#0-5) [7](#0-6) [8](#0-7) 

Because `ensure_mul`/`ensure_div` are checked operations that return `DispatchError` on overflow (rather than the Solidity contract's silent truncation), once `reward_rate_per_block.ensure_mul(rewardable_blocks_elapsed).ensure_mul(PRECISION_SCALING_FACTOR)` exceeds `T::Balance::MAX`, **every future call to `stake`, `unstake`, and `harvest_rewards` on that pool fails permanently**. Since `unstake` itself fails, already-staked tokens become permanently frozen (the `AssetsFreezer` freeze is never lifted), and `cleanup_pool` requires an empty staker set (`ensure!(stakers.is_none(), ...)`) which can never be satisfied.

### Title
Unbounded `reward_rate_per_block` × elapsed-blocks × `PRECISION_SCALING_FACTOR` multiplication in `reward_per_token()` can permanently overflow and freeze staked funds - (`substrate/frame/asset-rewards/src/lib.rs`)

### Summary
`pallet-asset-rewards` computes `reward_per_token` using checked (`ensure_*`) arithmetic on `reward_rate_per_block * rewardable_blocks_elapsed * PRECISION_SCALING_FACTOR` with no upper bound placed on `reward_rate_per_block` or `expiry_block`. Once this product exceeds `T::Balance::MAX`, the checked multiplication returns an error, which propagates out of every extrinsic that calls `update_pool_and_staker_rewards` first — `stake`, `unstake`, and `harvest_rewards`. This permanently traps staked tokens in the pool with no recovery path, mirroring the FarmAccounting bug class where insufficiently bounded reward/time inputs to a fixed-point calculation break accounting for all participants — except here the failure mode is a hard revert/DoS rather than silent truncation.

### Finding Description
`reward_per_token()` at [9](#0-8)  computes `reward_rate_per_block.ensure_mul(rewardable_blocks_elapsed).ensure_mul(PRECISION_SCALING_FACTOR).ensure_div(total_tokens_staked)`. The multiplication happens fully before the division, so a large `reward_rate_per_block` combined with a large number of elapsed blocks since `last_update_block` overflows `T::Balance` regardless of how large `total_tokens_staked` is.

Neither `create_pool` nor `set_pool_reward_rate_per_block` bound `reward_rate_per_block` to a value safe relative to `PRECISION_SCALING_FACTOR` (4096) and the pool's expected lifetime. `set_pool_expiry_block` similarly allows extending the expiry arbitrarily far into the future with no upper bound, which increases the ceiling for `rewardable_blocks_elapsed`. Any legitimate but poorly-bounded parameter choice — or simply a long-lived, low-activity pool that goes uninteracted-with for a long stretch of blocks — pushes the intermediate product past `T::Balance::MAX`.

Once this threshold is crossed, `reward_per_token()` returns `Err`, and this error is unconditionally propagated by `stake`, `unstake`, and `harvest_rewards`, all of which call `Self::update_pool_and_staker_rewards(...)?` before doing anything else. `unstake` failing means the `AssetsFreezer` freeze set up in `stake` is never released, permanently locking the staker's tokens. `cleanup_pool` cannot recover the pool either, since it requires `PoolStakers::iter_key_prefix` to be empty — which can't happen if `unstake` can no longer succeed.

### Impact Explanation
This results in a permanent user-fund lock: staked assets become irrecoverable once the reward accounting overflows, with no governance or admin escape hatch in the pallet itself (no force-unstake, no reward-rate cap enforcement, no way to reset `last_update_block`/`reward_per_token_stored` without going through the same overflowing calculation). This matches the "permanent user-fund... lock" impact category.

### Likelihood Explanation
This does not require a malicious peer, validator, or admin abusing privilege as the root cause — a normal, non-malicious pool configuration (a plausible `reward_rate_per_block` for a low-decimal reward asset, or simply time passing on a long-lived pool with an admin-extended expiry) combined with ordinary elapsed block time is sufficient. Any unprivileged staker's routine `stake`/`unstake`/`harvest_rewards` call is what triggers the permanent failure once the threshold is crossed; the staker did nothing wrong and cannot avoid it.

### Recommendation
Bound `reward_rate_per_block` at `create_pool`/`set_pool_reward_rate_per_block` (and/or bound `expiry_block` extension) to a maximum value such that `reward_rate_per_block * max_possible_blocks_elapsed * PRECISION_SCALING_FACTOR` cannot exceed `T::Balance::MAX`, analogous to the `_MAX_REWARD_AMOUNT` bound added to `FarmAccounting.startFarming()`. Alternatively, restructure `reward_per_token()` to divide by `total_tokens_staked` before applying the full multiplier chain, and/or require frequent mandatory checkpointing (e.g., via a `on_initialize` hook) so `rewardable_blocks_elapsed` can never grow unboundedly large between updates. Provide an emergency admin path to force-reset a pool's reward accounting state if overflow is ever hit, so staked funds are never unrecoverable.

### Proof of Concept
1. Permissioned origin calls `create_pool` with a `reward_rate_per_block` close to a large fraction of `T::Balance::MAX / PRECISION_SCALING_FACTOR` (e.g. `u128::MAX / 4096 / 2`) and a distant `expiry_block`.
2. A staker calls `stake` once early on — this succeeds and sets `last_update_block`.
3. Many blocks pass with no further pool interaction (no malicious actor needed — ordinary chain operation).
4. The admin (acting in good faith, not abusively) later calls `set_pool_expiry_block` to extend the pool, which internally calls `reward_per_token()` — still succeeds if elapsed blocks are below the overflow point, but establishes the pool can keep drifting.
5. Once `reward_rate_per_block * (current_block - last_update_block) * 4096` exceeds `T::Balance::MAX`, calling `unstake` from the original staker fails with an arithmetic overflow `DispatchError` inside `reward_per_token()` → `update_pool_and_staker_rewards()` → `unstake`.
6. The staker's tokens remain frozen via `AssetsFreezer` indefinitely; no extrinsic in the pallet provides a path to unfreeze them once this state is reached.

		pub fn stake(origin: OriginFor<T>, pool_id: PoolId, amount: T::Balance) -> DispatchResult {
			let staker = ensure_signed(origin)?;

			// Always start by updating staker and pool rewards.
			let pool_info = Pools::<T>::get(pool_id).ok_or(Error::<T>::NonExistentPool)?;
			let staker_info = PoolStakers::<T>::get(pool_id, &staker).unwrap_or_default();
			let (mut pool_info, mut staker_info) =
				Self::update_pool_and_staker_rewards(&pool_info, &staker_info)?;

			T::AssetsFreezer::increase_frozen(
				pool_info.staked_asset_id.clone(),
				&FreezeReason::Staked.into(),
				&staker,
				amount,
			)?;

			// Update Pools.
			pool_info.total_tokens_staked.ensure_add_assign(amount)?;

			Pools::<T>::insert(pool_id, pool_info);

			// Update PoolStakers.
			staker_info.amount.ensure_add_assign(amount)?;
			PoolStakers::<T>::insert(pool_id, &staker, staker_info);

			// Emit event.
			Self::deposit_event(Event::Staked { staker, pool_id, amount });

			Ok(())
		}

		#[pallet::call_index(2)]
		pub fn unstake(
			origin: OriginFor<T>,
			pool_id: PoolId,
			amount: T::Balance,
			staker: Option<T::AccountId>,
		) -> DispatchResult {
			let caller = ensure_signed(origin)?;
			let staker = staker.unwrap_or(caller.clone());

			// Always start by updating the pool rewards.
			let pool_info = Pools::<T>::get(pool_id).ok_or(Error::<T>::NonExistentPool)?;
			let now = T::BlockNumberProvider::current_block_number();
			ensure!(now > pool_info.expiry_block || caller == staker, BadOrigin);

			let staker_info = PoolStakers::<T>::get(pool_id, &staker).unwrap_or_default();
			let (mut pool_info, mut staker_info) =
				Self::update_pool_and_staker_rewards(&pool_info, &staker_info)?;

			// Check the staker has enough staked tokens.
			ensure!(staker_info.amount >= amount, Error::<T>::NotEnoughTokens);

			// Unfreeze staker assets.
			T::AssetsFreezer::decrease_frozen(
				pool_info.staked_asset_id.clone(),
				&FreezeReason::Staked.into(),
				&staker,
				amount,
			)?;

			// Update Pools.
			pool_info.total_tokens_staked.ensure_sub_assign(amount)?;
			Pools::<T>::insert(pool_id, pool_info);

			// Update PoolStakers.
			staker_info.amount.ensure_sub_assign(amount)?;

			if staker_info.amount.is_zero() && staker_info.rewards.is_zero() {
				PoolStakers::<T>::remove(&pool_id, &staker);
			} else {
				PoolStakers::<T>::insert(&pool_id, &staker, staker_info);
			}

			// Emit event.
			Self::deposit_event(Event::Unstaked { caller, staker, pool_id, amount });

			Ok(())
		}

		pub fn harvest_rewards(
			origin: OriginFor<T>,
			pool_id: PoolId,
			staker: Option<T::AccountId>,
		) -> DispatchResult {
			let caller = ensure_signed(origin)?;
			let staker = staker.unwrap_or(caller.clone());

			// Always start by updating the pool and staker rewards.
			let pool_info = Pools::<T>::get(pool_id).ok_or(Error::<T>::NonExistentPool)?;
			let now = T::BlockNumberProvider::current_block_number();
			ensure!(now > pool_info.expiry_block || caller == staker, BadOrigin);

			let staker_info =
				PoolStakers::<T>::get(pool_id, &staker).ok_or(Error::<T>::NonExistentStaker)?;
			let (pool_info, mut staker_info) =
				Self::update_pool_and_staker_rewards(&pool_info, &staker_info)?;

			// Transfer unclaimed rewards from the pool to the staker.
			T::Assets::transfer(
				pool_info.reward_asset_id,
				&pool_info.account,
				&staker,
				staker_info.rewards,
				// Could kill the account, but only if the pool was already almost empty.
				Preservation::Expendable,
			)?;

			// Emit event.
			Self::deposit_event(Event::RewardsHarvested {
				caller,
				staker: staker.clone(),
				pool_id,
				amount: staker_info.rewards,
			});

			// Reset staker rewards.
			staker_info.rewards = 0u32.into();

			if staker_info.amount.is_zero() {
				PoolStakers::<T>::remove(&pool_id, &staker);
			} else {
				PoolStakers::<T>::insert(&pool_id, &staker, staker_info);
			}

			Ok(())
		}

		/// Derives the current reward per token for this pool.
		pub(super) fn reward_per_token(
			pool_info: &PoolInfoFor<T>,
		) -> Result<T::Balance, DispatchError> {
			if pool_info.total_tokens_staked.is_zero() {
				return Ok(pool_info.reward_per_token_stored);
			}

			let rewardable_blocks_elapsed: u32 =
				match Self::last_block_reward_applicable(pool_info.expiry_block)
					.ensure_sub(pool_info.last_update_block)?
					.try_into()
				{
					Ok(b) => b,
					Err(_) => return Err(Error::<T>::BlockNumberConversionError.into()),
				};

			Ok(pool_info.reward_per_token_stored.ensure_add(
				pool_info
					.reward_rate_per_block
					.ensure_mul(rewardable_blocks_elapsed.into())?
					.ensure_mul(PRECISION_SCALING_FACTOR.into())?
					.ensure_div(pool_info.total_tokens_staked)?,
			)?)
		}

	fn create_pool(
		creator: &T::AccountId,
		staked_asset_id: T::AssetId,
		reward_asset_id: T::AssetId,
		reward_rate_per_block: T::Balance,
		expiry: DispatchTime<BlockNumberFor<T>>,
		admin: &T::AccountId,
	) -> Result<PoolId, DispatchError> {
		// Ensure the assets exist.
		ensure!(T::Assets::asset_exists(staked_asset_id.clone()), Error::<T>::NonExistentAsset);
		ensure!(T::Assets::asset_exists(reward_asset_id.clone()), Error::<T>::NonExistentAsset);

		// Check the expiry block.
		let now = T::BlockNumberProvider::current_block_number();
		let expiry_block = expiry.evaluate(now);
		ensure!(expiry_block > now, Error::<T>::ExpiryBlockMustBeInTheFuture);

		let pool_id = NextPoolId::<T>::try_mutate(|id| -> Result<PoolId, DispatchError> {
			let current_id = *id;
			*id = id.ensure_add(1)?;
			Ok(current_id)
		})?;

		let footprint = Self::pool_creation_footprint();
		let cost = T::Consideration::new(creator, footprint)?;
		PoolCost::<T>::insert(pool_id, (creator.clone(), cost));

		// Create the pool.
		let pool = PoolInfoFor::<T> {
			staked_asset_id: staked_asset_id.clone(),
			reward_asset_id: reward_asset_id.clone(),
			reward_rate_per_block,
			total_tokens_staked: 0u32.into(),
			reward_per_token_stored: 0u32.into(),
			last_update_block: 0u32.into(),
			expiry_block,
			admin: admin.clone(),
			account: Self::pool_account_id(&pool_id),
		};

		// Insert it into storage.
		Pools::<T>::insert(pool_id, pool);

		// Emit created event.
		Self::deposit_event(Event::PoolCreated {
			creator: creator.clone(),
			pool_id,
			staked_asset_id,
			reward_asset_id,
			reward_rate_per_block,
			expiry_block,
			admin: admin.clone(),
		});

		Ok(pool_id)
	}

	fn set_pool_reward_rate_per_block(
		admin: &T::AccountId,
		pool_id: PoolId,
		new_reward_rate_per_block: T::Balance,
	) -> DispatchResult {
		let pool_info = Pools::<T>::get(pool_id).ok_or(Error::<T>::NonExistentPool)?;
		ensure!(pool_info.admin == *admin, BadOrigin);
		ensure!(
			new_reward_rate_per_block > pool_info.reward_rate_per_block,
			Error::<T>::RewardRateCut
		);

		// Always start by updating the pool rewards.
		let rewards_per_token = Self::reward_per_token(&pool_info)?;
		let mut pool_info = Self::update_pool_rewards(&pool_info, rewards_per_token)?;

		pool_info.reward_rate_per_block = new_reward_rate_per_block;
		Pools::<T>::insert(pool_id, pool_info);

		Self::deposit_event(Event::PoolRewardRateModified { pool_id, new_reward_rate_per_block });

		Ok(())
	}
