[blockreplay.rs::(replay handler)::try_parse_request] Attacker requests `/v3/blocks/replay/{block_id}` for a `block_id` belonging to a **non-canonical** (orphaned) Nakamoto block while omitting the `authorization` header, on a node where `self.auth=Some(secret)` for the replay endpoint. Preconditions: node chainstate contains at least one orphaned/non-canonical block with a known `StacksBlockId`. Call sequence: confirm the auth gate (mirroring `fastcallreadonly`'s `let Some(password) = &self.auth else {...}` pattern) executes in `try_parse_request` prior to any `remine_nakamoto_block`/chainstate lookup keyed by `block_id` captured via the path regex; if the block-id capture and DB lookup happen before the secret check, an attacker without the secret can distinguish 404 (block truly absent) vs 400/500 (block exists but fails replay) vs the eventual 401, leaking canonical-chain membership of arbitrary block IDs without authentication. Equality: the *first* branch taken for any request must be the auth check (`auth_header==secret`) — no chainstate read may occur for an unauthenticated caller. Impact: Critical if compute/relay executes without secret; High (canonicity/membership oracle) if only informational leakage occurs. Proof idea: Rust test sending a `GET /v3/blocks/replay/{id}` for a real then a fake `block_id`, no auth header, asserting identical 401 responses regardless of block existence (no timing/branch difference reaching the DB).
