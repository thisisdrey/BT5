[blocksimulate.rs::RPCNakamotoBlockSimulateRequestHandler] Attacker POSTs to the block-simulate endpoint with a JSON body containing `transactions_hex` entries that are NOT the mempool's actual pending transactions, while the `authorization` header is entirely absent and the node is configured with `self.auth=None`. Preconditions: node run without a block-simulate secret. Call sequence: verify the analogous `let Some(password) = &self.auth else { return Err(...) }` early-out pattern (mirrored from `fastcallreadonly.rs`) exists in `try_parse_request` before `Self::parse_json(body)` decodes attacker-chosen `StacksTransaction`s and mints via `RPCNakamotoBlockSimulateMint{ principal, amount }` are fed into `block_simulate` -> `remine_nakamoto_block`. Equality: requests that reach `remine_nakamoto_block` (which executes attacker-chosen transactions and mints against a real chain tip's Clarity state) == requests carrying the exact configured secret; none execute when `self.auth==None`. Impact: Critical — an unauthenticated caller could otherwise force arbitrary-cost contract execution and forged STX minting simulation against live chainstate, a bounded compute DoS at minimum. Proof idea: Rust test constructing the handler with `auth=None`, sending a `new_block_simulate_with_profiler` request with no header, asserting `try_parse_request` fails closed with 400/401 before `parse_json` ever decodes `transactions_hex`.
