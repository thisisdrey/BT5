Preconditions: DeleteKey followed by AddKey with the same public_key at some later block. Sequence: delete key, re-add SAME public key, attempt replay of a transaction signed under the old nonce epoch. Invariant: nonce monotonicity prevents replay — reused public keys must get nonce >= old nonce per the AccessKey doc comment (docs/DataStructures/AccessKey.md:9-11: 'if new access key reuses same public key, nonce should be equal to old nonce'). Impact: replay of an old pre-deletion transaction if `initial_nonce_value` at re-creation block_height is LOWER than the old key's nonce (e.g. old key had inflated nonce from many fast transactions exceeding one block's ACCESS_KEY_NONCE_RANGE_MULTIPLIER budget). Proof idea: integration test that advances a key's nonce far via `NonceMode::Strict`/rapid tx, deletes it, re-adds the SAME public key at the next block, and asserts `initial_nonce_value(block_height)` is never less than the just-deleted key's last nonce (or if it is, that an old signed-but-unbroadcast tx cannot replay).
