### Title
HOP data-pool `claim`/`ack` signatures are not bound to a submission instance, allowing cross-submission replay of recipient authorization - (File: `substrate/client/hop/src/pool.rs`)

### Summary
The HOP off-chain data pool lets a sender deposit a blob for one or more recipients, who authorize retrieval (`claim`) and receipt (`ack`) by signing `blake2_256(context || hash)` with their ephemeral key. Because the signed payload is only `(context, content-hash)`, and never includes anything that ties it to *this particular submission* (no per-entry nonce, no `sender_id`, no `submit_timestamp`), a signature a recipient produces for one HOP entry is valid forever for **any** future HOP entry that happens to carry the same content hash and lists that recipient's key again — this is structurally identical to the reported `RestoreData` flaw: a signed authorization message that is not rooted to a single, one-time use of the resource it authorizes.

### Finding Description
`find_recipient_idx` verifies a submitted signature against `signing_payload(context, hash)` for every recipient key stored in `HopEntryMeta::recipients`, and `claim`/`ack` accept it as proof of authorization from that recipient: [2](#0-1) 

`claim` and `ack` both call this same verification and, on success, treat the signature as sufficient consent to release data or mark the recipient as acknowledged: [3](#0-2) [4](#0-3) 

Once every recipient acks, the entry is fully removed from the index and from disk, freeing the content hash for reuse: [5](#0-4) 

`insert` only rejects a submission if the exact same content hash is *currently* present in the index; it does nothing to prevent a hash from being reused after its prior entry has been fully acked and purged: [6](#0-5) 

The signed payload construction confirms there is no submission-instance binding at all — only a static context string and the content hash: [1](#0-0) 

Because `HopHash` is `blake2_256(data)` (content-addressed) and any sender can submit arbitrary bytes, an attacker can reconstruct a byte-identical blob to a prior, already-fully-acked entry, resubmit it via `insert` naming a previous recipient again, and that recipient's *old* `claim`/`ack` signature (which they produced for a completely different, prior submission/context) will still verify and immediately authorize release/ack of the new entry — without the recipient ever intending to authorize this new submission. This is exactly the "RestoreData has no nonce and is not rooted to a single RestorationTX" pattern: the authorizing signature is decoupled from the specific instance of the protected resource it was meant to gate.

### Impact Explanation
This breaks the intended one-shot handoff guarantee of the HOP pool: a recipient's authorization for one data delivery can be silently replayed against a different, attacker-controlled submission carrying the same bytes, letting an unrelated party auto-satisfy `claim`/`ack` state (and thus the "recipient consented" invariant) on a submission the recipient never reviewed. Combined with `ack`'s side effect of deleting pool entries once all recipients ack, an attacker can trigger premature purge/consumption of pool capacity/state tied to a victim recipient's stale signature, undermining the delivery-receipt protocol's replay-domain guarantee that HOP is supposed to provide for the off-chain-to-on-chain "promotion" pipeline. This does not directly move on-chain funds, but it corrupts the state a downstream promotion/verification flow (`get_with_auth`, promotion attempts) relies on as ground truth for "recipient acknowledged".

### Likelihood Explanation
Exploitation requires no privileged role: any user of the HOP JSON-RPC submit API can craft a blob matching a previously-seen (and now-expired/fully-acked) content hash and list a known recipient key, and can passively/actively harvest a previously-observed `claim`/`ack` signature and replay it against the new entry — no relayer, validator, or node compromise is needed, only knowledge of a public signature and reproducible content bytes.

### Recommendation
Bind the `claim`/`ack` signing payload to something that uniquely identifies the specific submission instance, not just the content hash — e.g. include a per-entry monotonic nonce/sequence number, the `sender_id`, and/or the `submit_timestamp` in `signing_payload`, mirroring what `submit_signing_payload` already does for the submit-time signature. Alternatively, ensure that a freed content hash can never be reused by a future, independent submission without generating a fresh recipient signature scoped to the new entry's unique identifier.

### Proof of Concept
1. Sender A submits blob `D` with recipient `R`; HOP computes `hash = blake2_256(D)` and stores `HopEntryMeta` in `insert`.
2. `R` calls `ack(hash, sig)` where `sig = sign(blake2_256(HOP_ACK_CONTEXT || hash))`; since `R` is the only recipient, the entry is fully acked and removed from the pool (`pool.rs:636-649`).
3. Attacker later reconstructs byte-identical `D` (public/known content) and calls `insert(D, recipients=[R, attacker_key], ...)` — accepted because the hash is no longer in the index (`pool.rs:389-399`).
4. Attacker replays `R`'s previously observed `sig` against `ack(hash, sig)` (or `claim`) on the new entry; `find_recipient_idx` recomputes the identical `signing_payload(HOP_ACK_CONTEXT, hash)` and the old signature verifies, marking `R` as acked/claimed on a submission `R` never authorized. /// Compute the 32-byte payload that HOP recipients / submitters sign for a given
/// operation. This is `blake2_256(context || hash)` and ensures signatures from
/// one operation cannot be replayed in another.
pub fn signing_payload(context: &[u8], hash: &HopHash) -> [u8; 32] {
	let mut buf = Vec::with_capacity(context.len() + 32);
	buf.extend_from_slice(context);
	buf.extend_from_slice(hash.as_bytes());
	blake2_256(&buf)
}

	fn find_recipient_idx(
		meta: &HopEntryMeta,
		hash: &HopHash,
		signature: &[u8],
		context: &[u8],
	) -> Result<usize, HopError> {
		let multi_sig =
			MultiSignature::decode(&mut &signature[..]).map_err(|_| HopError::InvalidSignature)?;
		let payload = signing_payload(context, hash);

		meta.recipients
			.iter()
			.position(|r| multi_sig.verify(&payload[..], &r.signer.clone().into_account()))
			.ok_or(HopError::NotRecipient)
	}

	/// Claim data from the pool (read-only). Verifies the signature against recipient
	/// public keys. Returns the data if the signature matches a recipient.
	///
	/// This does NOT mark the recipient as claimed — call `ack` after receiving the data
	/// to confirm receipt.
	///
	/// Returns `AlreadyClaimed` if the recipient has already acked (data may be deleted).
	pub fn claim(&self, hash: &HopHash, signature: &[u8]) -> Result<Vec<u8>, HopError> {
		{
			let index = self.index.lock();
			let meta = index.get(hash).ok_or(HopError::NotFound)?;
			// Map NotRecipient → NotFound so callers cannot probe whether a hash
			// exists by observing different error codes.
			let idx = Self::find_recipient_idx(meta, hash, signature, HOP_CLAIM_CONTEXT)
				.map_err(|_| HopError::NotFound)?;

			// If this recipient already acked, the data may be gone.
			if meta.recipients[idx].claimed {
				return Err(HopError::AlreadyClaimed);
			}
		}
		// Read blob from disk and verify its content hash. May be gone if
		// concurrently acked and deleted, in which case we surface NotFound.
		self.read_and_verify_blob(hash)
	}

	pub fn ack(&self, hash: &HopHash, signature: &[u8]) -> Result<(), HopError> {
		// Phase 1: idempotent fast path under read lock.
		{
			let index = self.index.lock();
			let meta = index.get(hash).ok_or(HopError::NotFound)?;
			let idx = Self::find_recipient_idx(meta, hash, signature, HOP_ACK_CONTEXT)
				.map_err(|_| HopError::NotFound)?;
			if meta.recipients[idx].claimed {
				return Ok(());
			}
		}

		// Phase 2: re-run the lookup against the current meta — the entry could
		// have been removed and re-submitted with a different recipient list since Phase 1.
		let mut index = self.index.lock();
		let meta = index.get_mut(hash).ok_or(HopError::NotFound)?;
		let idx = Self::find_recipient_idx(meta, hash, signature, HOP_ACK_CONTEXT)
			.map_err(|_| HopError::NotFound)?;

		if meta.recipients[idx].claimed {
			return Ok(());
		}

		meta.recipients[idx].claimed = true;
