## Finding: DAP issuance drip misattributes pre-change elapsed time to the new `BudgetAllocation` [1](#0-0) 

### Title
Emission/budget schedule not applied atomically across `set_budget_allocation` changes, causing wrong-beneficiary payout of pending issuance — (File: `substrate/frame/dap/src/lib.rs`)

### Summary
`pallet_dap`'s issuance drip mints tokens for the entire elapsed time since `LastIssuanceTimestamp` and splits the resulting mint across recipients using **whatever `BudgetAllocation` is in storage at the moment `drip_issuance` executes** [2](#0-1) . Because `set_budget_allocation` only writes the new percentages and never triggers a settlement of pending, not-yet-dripped issuance under the *old* allocation, any elapsed window that straddles an allocation change is paid out entirely under the new schedule. This is the exact bug class from the report: a schedule update is applied to a time-window that should have been (partly) governed by the prior schedule.

### Finding Description
`drip_issuance` (called every block from `on_initialize`) computes `elapsed = now - LastIssuanceTimestamp`, and only proceeds once `elapsed >= IssuanceCadence` [3](#0-2) . Until that threshold is hit, `LastIssuanceTimestamp` is **not** advanced, so `elapsed` keeps accumulating across multiple blocks.

`set_budget_allocation` is a standalone extrinsic that only validates and overwrites `BudgetAllocation` in storage — it does not call `mint_and_distribute` or otherwise checkpoint/settle the issuance accrued so far under the old allocation: [4](#0-3) 

When `drip_issuance` eventually fires (in a later block, once `elapsed >= IssuanceCadence`), it calls `mint_and_distribute(elapsed)`, which reads `BudgetAllocation::<T>::get()` a single time and applies it to the *entire* accumulated `elapsed` window: [2](#0-1) 

This mirrors exactly the reported flaw: `oldRate * (scheduleChangeTime - lastUpdate) + newRate * (now - scheduleChangeTime)` is required, but the code instead applies `newRate * (now - lastUpdate)` uniformly. Here it is budget *shares* (`Perbill` per `BudgetKey`) rather than a rewards-per-second rate, but the broken invariant is identical: a schedule/rate change is not split at the point it took effect, so state prior to the change is retroactively re-priced under the new parameters.

### Impact Explanation
Every recipient in `T::BudgetRecipients` (e.g., staker-reward pot, validator-incentive pot, treasury/buffer pot) is a `sp_staking::budget::BudgetRecipient`. A `set_budget_allocation` change (a normal, expected governance operation — not "abuse") that lands inside an accumulation window (any time `IssuanceCadence > 0`, which the pallet doc explicitly recommends, e.g. "drip every minute") causes the *entire* pending drip to be paid according to the new split instead of the previously governing one. This silently transfers minted-issuance value between the pallet's own trusted pots (e.g., understating `StakerRewards` and overstating `ValidatorIncentive`/`buffer`, or vice versa) for the pre-change interval — a wrong-beneficiary/wrong-amount payout of protocol-conserved value, matching the "duplicate settlement or payout" / "wrong beneficiary or amount" impact class in scope.

### Likelihood Explanation
This triggers on the ordinary, expected use of `set_budget_allocation` whenever it executes in a block that falls inside an in-progress accumulation window (`elapsed < IssuanceCadence` boundary crossing), which is a routine occurrence for any chain that sets `IssuanceCadence > 0` as the pallet doc recommends. No malicious actor, validator, relayer, or key compromise is required — it is a deterministic consequence of the call ordering relative to `on_initialize`'s drip cadence, so it will occur on essentially every governance-driven reallocation unless the caller is careful to time it to coincide exactly with a drip boundary (which the pallet gives them no way to detect or force).

### Recommendation
Before writing the new `BudgetAllocation`, `set_budget_allocation` should force-settle any pending issuance under the current allocation, e.g. by invoking the same accounting path as `drip_issuance`/`mint_and_distribute` for `elapsed = now - LastIssuanceTimestamp` and resetting `LastIssuanceTimestamp = now`, so the new allocation only ever governs time strictly after the change — analogous to how `pallet_asset_rewards::set_pool_reward_rate_per_block` checkpoints via `update_pool_rewards` before applying the new rate [5](#0-4) .

### Proof of Concept
1. Configure `IssuanceCadence = 60_000` (1 minute) and `BudgetAllocation = {StakerRewards: 85%, Buffer: 15%}`; let block time be 12s.
2. At `t=0`, `LastIssuanceTimestamp = 0`. Blocks tick at `t=12,24,36,...`; since `elapsed < 60_000` each time, `drip_issuance` returns early each block without updating `LastIssuanceTimestamp` (per lines 372-374 of `lib.rs`).
3. At `t=30_000`, governance (or any account passing `BudgetOrigin`) calls `set_budget_allocation({ValidatorIncentive: 85%, Buffer: 15%})`, intending this split to apply going forward only. `BudgetAllocation` storage is overwritten immediately; no mint occurs.
4. At `t=60_000+`, `elapsed = 60_000 >= IssuanceCadence`, so `drip_issuance` calls `mint_and_distribute(60_000)`. The full 60 seconds of issuance — including the 0–30s window where `StakerRewards` should have received 85% — is instead paid 85% to `ValidatorIncentive` and 15% to `Buffer`.
5. Result: `StakerRewards` receives 0 tokens for the first half of the window it was entitled to under the old schedule; `ValidatorIncentive` receives tokens it was not entitled to for that period — a wrong-beneficiary misallocation of newly minted, protocol-conserved issuance, with no need for any malicious actor beyond routine use of `set_budget_allocation`.

				return T::DbWeight::get().reads_writes(2, 2);
			}

			// Apply safety ceiling on elapsed time.
			let max_elapsed = T::MaxElapsedPerDrip::get();
			if elapsed > max_elapsed {
				Self::deposit_event(Event::Unexpected(UnexpectedKind::ElapsedClamped {
					actual_elapsed: elapsed,
					ceiling: max_elapsed,
				}));
				elapsed = max_elapsed;
			}

			// Always advance the clock so elapsed time doesn't accumulate across skipped drips.
			LastIssuanceTimestamp::<T>::put(now);

			let _ = Self::mint_and_distribute(elapsed);
			T::WeightInfo::drip_issuance()
