Target: Contract::resolve_deposit_internal (contracts/defuse/src/contract/tokens/mod.rs) invoked by mt_resolve_deposit/nft_resolve_deposit. Preconditions: attacker's own account as receiver_id, attacker deploys the notified contract. Call sequence: mt_on_transfer -> deposit() credits receiver -> notify_on_transfer promise -> mt_resolve_deposit -> resolve_deposit_internal reads receiver.token_balances.amount_for(token_id) *after* the nested spend, refunding up to balance_left. Binding broken: refund credited by the resolver == value that failed to settle at the original deposit, not value currently sitting in the balance which has since been spent and re-derived by an unrelated intent. Impact: Critical, refund/resolver credit mismatched with what failed to settle can double count value already spent elsewhere. Proof: cargo test with a receiver stub that spends the deposited balance via execute_intents inside the notify hook before the deposit resolver runs, asserting resolve_deposit_internal's computed refund_amount does not exceed the amount still uncommitted to another intent.
