Binding: value debited from `sender_id` == value delivered to `receiver_id` plus value re-credited via `ft_resolve_withdraw`'s refund. Impact: Critical, double-value for the withdrawing attacker's own account, but since `token` is attacker-deployed the movement is self-contained UNLESS `sender_id` differs from the withdraw caller via `msg`-forwarded defuse-to-defuse withdrawals (see `ft_withdraw_intent_msg` test) where a third `defuse2` Verifier's `ft_on_transfer` credits `other_user_id` there while the origin Verifier also refunds `sender_id` on a lied `used` value.
