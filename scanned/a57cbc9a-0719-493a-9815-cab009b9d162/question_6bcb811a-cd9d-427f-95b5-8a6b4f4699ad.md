In RPCPostBlockRequestHandler::try_parse_request, `broadcast` is computed via `for (key, value) in form_urlencoded::parse(...) { if key == "broadcast" { broadcast = broadcast || value == "1"; } }` -- this OR-accumulates across ALL occurrences of the `broadcast` key rather than taking the last one. Can a remote attacker send `?broadcast=0&broadcast=1` while unauthenticated, and does the accumulation logic still set `broadcast=true` requiring authentication (safe), or can an attacker send `?broadcast=1&broadcast=x` such that parsing ambiguity lets `authenticated` check be bypassed by a mismatched interpretation of which broadcast value the handler versus a downstream consumer uses? Equality: the `broadcast` flag value the auth-gate branch reads == the `broadcast` value that governs whether the block is actually relayed downstream. Impact: Critical auth bypass via parameter smuggling on a gated endpoint. Proof idea: net test feeding duplicate `broadcast` query keys with conflicting values and asserting `self.broadcast` matches only the intended semantic, not an attacker-chosen one.
