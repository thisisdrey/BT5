### Title
Oracle `DataProvider` discards freshness data and silently reuses stale aggregated prices after operators stop feeding - ([File: substrate/frame/honzon/oracle/src/lib.rs])

### Summary
`pallet-oracle`'s `DataProvider::get()` strips the timestamp from the aggregated `Values` entry and returns only the raw value to consumers, with no mechanism for a consumer to detect that the underlying price is stale. This mirrors the Chainlink report's core broken invariant: a price consumer trusts an oracle-fed value without validating that the data is still fresh/live, so if reporting stalls (analogous to Chainlink "unable to submit and start a new round"), stale data continues to be treated as current.

### Finding Description
`Pallet::get(key)` returns `Self::values(key)`, the last successfully aggregated `TimestampedValue`, and `DataProvider::get` maps this down to just `.value`, discarding the `timestamp` field entirely: [1](#0-0) [2](#0-1) 

The aggregation logic (`DefaultCombineData::combine_data`) only filters for freshness among the values submitted in the *current* call — it discards individual operator submissions older than `ExpiresIn`, but if the number of still-fresh submissions falls below `MinimumCount`, it falls back to returning `prev_value` unchanged: [3](#0-2) 

Because `combine_data` is only invoked from inside `do_feed_values` (i.e., only when at least one operator submits new data), the `Values` storage entry is never re-evaluated or expired on its own. If oracle operators stop submitting entirely — due to chain congestion, coordinated operator downtime, membership churn, or the same "unable to reach consensus on a new round" conditions cited in the external report — the last aggregated value remains permanently readable via `DataProvider::get()` with no on-chain expiry check: [4](#0-3) 

Unlike the Chainlink `latestRoundData()` interface, which at least *exposes* `updatedAt`/`answeredInRound` so a diligent consumer (per the reporter's own recommended fix) can validate staleness, this pallet's `DataProvider` trait interface gives consumers no access to the timestamp at all — the staleness-check responsibility is architecturally impossible to fulfil downstream. Any pallet (e.g. a CDP/liquidation module, a DEX price oracle consumer, or a lending module) that is later wired to `T::PriceSource = pallet-oracle` via `DataProvider::get` has no way to protect itself, regardless of how carefully that downstream pallet is written.

### Impact Explanation
If a downstream pallet uses this oracle (e.g. for CDP collateral valuation, liquidation triggers, or DEX/lending price checks), and the oracle silently keeps serving a frozen price because operators went silent, price-dependent operations (liquidations, minting, redemptions) execute against out-of-date values. This can allow under-collateralized positions to avoid liquidation, or conversely trigger unjust liquidations, causing fund loss or unbacked value extraction — directly matching the "theft or unbacked mint/unlock" and "runtime bugs that compromise intended behavior" impact classes. No malicious peer, validator, or admin action is required; a benign operator outage is sufficient to trigger the unsafe state.

### Likelihood Explanation
Likelihood is moderate: it requires the honest-majority set of oracle feeders to go quiet (network issues, incentive misalignment, membership set shrinking below `MinimumCount`) rather than any attacker action. This is exactly the same trigger class the external Chainlink report calls out — no compromise needed, just oracle-side unavailability — which the report itself rates as MEDIUM severity for the same reason.

### Recommendation
- Extend the `DataProvider`/`DataProviderExtended` interfaces (or add a new trait) so consumers can retrieve the `timestamp` alongside the value, not just the raw value.
- Add an explicit `ExpiresIn`/staleness check at read time (`Pallet::get`) so that once `now - value.timestamp > ExpiresIn`, `get` returns `None` instead of the stale value, forcing downstream consumers to treat expired data as unavailable rather than trusting it indefinitely.
- Document and enforce that any downstream consumer relying on `DataProvider::get` must reject `None`/stale responses rather than assume liveness.

### Proof of Concept
1. Configure a runtime with `pallet-oracle` and `DefaultCombineData<T, MinimumCount, ExpiresIn>` with `MinimumCount = 3`.
2. Three operators feed a price for key `K` at block 1, producing an aggregated `Values[K] = TimestampedValue { value: P, timestamp: T0 }`.
3. All three feeders stop submitting (simulating an outage/oracle "stuck round").
4. Time advances far beyond `ExpiresIn`. No new `feed_values` call occurs, so `combine_data` is never re-invoked and `Values[K]` is never cleared or marked stale.
5. Any downstream pallet calls `<OracleInstance as DataProvider<Key, Value>>::get(&K)` and receives `Some(P)` — the same price from `T0` — with no indication it is stale, exactly reproducing the "Chainlink price used without checking validity" condition inside this repository's oracle primitive. 	fn do_feed_values(who: T::AccountId, values: Vec<(T::OracleKey, T::OracleValue)>) {
```rust
		let now = T::Time::now();
		for (key, value) in &values {
			let timestamped = TimestampedValue { value: value.clone(), timestamp: now };
			RawValues::<T, I>::insert(&who, key, timestamped);

			// Update `Values` storage if `combined` yielded result.
			if let Some(combined) = Self::combined(key) {
				<Values<T, I>>::insert(key, combined);
			}

			T::OnNewData::on_new_data(&who, key, value);
		}
		Self::deposit_event(Event::NewFeedData { sender: who, values });
	}
```

```rust
	fn combine_data(
		_key: &<T as Config<I>>::OracleKey,
		mut values: Vec<TimestampedValueOf<T, I>>,
		prev_value: Option<TimestampedValueOf<T, I>>,
	) -> Option<TimestampedValueOf<T, I>> {
		let expires_in = ExpiresIn::get();
		let now = T::Time::now();

		values.retain(|x| x.timestamp.saturating_add(expires_in) > now);

		let count = values.len() as u32;
		let minimum_count = MinimumCount::get();
		if count < minimum_count || count == 0 {
			return prev_value;
		}

		let mid_index = count / 2;
		// Won't panic as `values` ensured not empty.
		let (_, value, _) =
			values.select_nth_unstable_by(mid_index as usize, |a, b| a.value.cmp(&b.value));
		Some(value.clone())
	}
```
