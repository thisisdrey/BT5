Target: OffchainMessage::hash() and OffchainMessage::DOMAIN_SEPARATOR consumed by into_nep413_payload's nonce field. Attacker action: attacker submits two OffchainMessage values that differ only in a field NOT covered by hash() (none currently, but path re-ordering could canonicalize identically for a Vec<AccountId> with duplicate/rearranged elements if AccountId Borsh serialization is length-prefixed ambiguously). Preconditions: attacker deploys a wallet contract and constructs path=[A,B] vs path=[A,B] with an extra empty-string account inserted that borsh-serializes to overlapping bytes. Call sequence: hash() = SHA3_256(DOMAIN_SEPARATOR || borsh(msg)); two logically-different OffchainMessage values collide to identical hash() output; the resulting nep413 nonce collides, letting a signature over one message be replayed via into_nep413_payload as authorization for the other. Binding: hash(msg_A) == hash(msg_B) implies msg_A == msg_B (field-wise), for all path/timestamp/payload combinations. Scoped impact: Critical - a signature intended for a narrow payload authorizes a different broader payload sharing the same nonce, letting the attacker settle an intent the signer never approved. Proof idea: cargo test asserting for a set of crafted OffchainMessage values with adversarial path vectors that hash() collisions never occur when msg_A != msg_B (PartialEq).
