Target: JsonPayload { domain, action, msg } round-tripped through String via `impl From<&JsonPayload> for String` (serde_json::to_string_pretty) and consumed as OffchainMessage.payload. Attacker action: attacker crafts a payload string that is valid JSON for JsonPayload with domain/action chosen to impersonate a well-known dApp, then gets it signed by a victim wallet who trusts the pretty-printed rendering shown by their wallet UI as the 'authorized payload'. Preconditions: victim wallet resolves w_resolve_auth successfully returning AuthorizationResolution{payload}. Call sequence: resolve_auth returns AuthorizationResolution::new(msg.payload) with payload equal to the raw signed string; the offchain resolver crate treats this string as the trusted output with no independent binding back to which domain/action the executing contract expected. Binding: the payload string returned by w_resolve_auth == the exact DefusePayload/JsonPayload string the executing contract (e.g. intents.near execute_intents) subsequently parses as its authorized intents. Scoped impact: Critical - a signed OffchainMessage.payload authorized for domain X can be submitted by the resolver/relayer as authorization payload for a completely different contract action, since nothing in message.rs ties payload semantics to the resolving contract identity beyond signer_id/chain_id. Proof idea: cargo test signing OffchainMessage with a JsonPayload for domain='Near MPC', feed the resulting AuthorizationResolution.payload into a different consuming contract expecting DefusePayload<DefuseIntents>, assert it parses and executes despite domain mismatch.
