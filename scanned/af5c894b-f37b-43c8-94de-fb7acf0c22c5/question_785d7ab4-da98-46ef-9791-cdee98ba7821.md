Target: DefusePayload<T> { signer_id, verifying_contract, deadline, nonce, message } in contracts/defuse/core/src/payload/mod.rs, extracted via ExtractDefusePayload from OffchainMessage.payload string carried by NEP-641 authorization when a wallet is used as the front door before intents.near consumes it. Attacker action: attacker crafts a JsonPayload/OffchainMessage.payload whose embedded DefusePayload.signer_id differs from the OffchainMessage.signer_id that WalletImpl::resolve_auth actually checked against env::current_account_id(). Preconditions: a wallet contract W is also the `signer_id` inside a DefusePayload used to call execute_intents on intents.near, and nothing in message.rs or engine::mod.rs cross-checks OffchainMessage.signer_id against the embedded DefusePayload.signer_id since they are parsed by two independent layers. Call sequence: resolve_auth verifies msg.signer_id == W (correct), returns AuthorizationResolution{payload: raw_string}; raw_string is then submitted as MultiPayload to execute_intents, where extract_defuse_payload() parses signer_id = attacker-chosen account V != W. Binding: DefusePayload.signer_id used by Engine::execute_signed_intent to debit/credit balances == the signer_id that was actually authenticated (OffchainMessage.signer_id == W) by any prior authorization layer. Scoped impact: Critical - a wallet-authorized payload can be redirected to debit or move balances of an unrelated account V that never participated in either signature layer, since execute_intents' own signature check (signed.verify()) is independent of the NEP-641 layer's signer_id binding. Proof idea: cargo test crafting a DefusePayload with signer_id=V embedded in an OffchainMessage.payload signed and resolved for signer_id=W, submit resulting MultiPayload to execute_intents, assert Engine::has_public_key(V, pubkey) is the only real check and V's balance moves though V's wallet-layer authorization was never checked.
