# Q2340: get_blockhash amplifies a cheap input into expensive work (blockhash_query.rs)

## Question
Can an unprivileged attacker entering through one JSON-RPC call or websocket subscription from a single client, at most once per CLUSTER_SLOT_TIME_TARGET/2 reach `get_blockhash` in `rpc-client-nonce-utils/src/nonblocking/blockhash_query.rs` with a key that exists on an ancestor fork but not the current one, and make a minimal accepted input to `get_blockhash` fan out into disproportionate downstream work, so that the invariant "Work performed is proportional to the size and fee of the input that triggered it." breaks and the result is DoS?

## Target
- File/function: `rpc-client-nonce-utils/src/nonblocking/blockhash_query.rs` -> `get_blockhash()` (around line 22)
- Entrypoint: one JSON-RPC call or websocket subscription from a single client, at most once per CLUSTER_SLOT_TIME_TARGET/2
- Attacker controls: a key that exists on an ancestor fork but not the current one
- Exploit idea: Send the smallest accepted input that makes `get_blockhash` fan out into large downstream work, so a cheap transaction/packet costs the node orders more.
- Invariant to test: Work performed is proportional to the size and fee of the input that triggered it.
- Expected Immunefi impact: DoS - remote resource exhaustion via non-RPC protocols (315-1,250 SOL)
- Fast validation: Plot input bytes versus work done in `get_blockhash`; assert the ratio is bounded by a constant.
