## Analog Found: PSM Pallet Assumes Permanent 1:1 Peg With No Price/Depeg Check [1](#0-0) 

### Title
Peg Stability Module (PSM) mints/redeems at a hard-coded 1:1 rate with no on-chain depeg detection, allowing bad debt if an approved external asset loses its peg - (File: `substrate/frame/psm/src/lib.rs`)

### Summary
The `pallet-psm` (Peg Stability Module) lets users mint an "internal" asset by depositing an "approved" **external** asset (e.g. a bridged/third-party stablecoin such as USDC/USDT), and redeem internal asset for external asset back out of the reserve. All conversion is a pure decimal-scaling operation — there is **no price oracle, no liquidity check, and no automated peg-verification** anywhere in the mint/redeem path. This is architecturally identical to the reported issue: an oracle/peg-stability mechanism trusts that asset A (WBTC / external stablecoin) is always worth 1:1 the reference asset (BTC / internal stablecoin), with no mechanism to detect or react to a depeg on-chain.

### Finding Description
The pallet's own documentation states the design assumption plainly: *"Instantiable Peg Stability Modules (PSMs). Each PSM enables 1:1 swaps between an internal stablecoin and one or more approved external stablecoins"* [2](#0-1) .

The only unit conversion performed between external and internal asset amounts is `external_to_internal`, which purely scales by the difference in decimals — it contains no reference to market price, exchange rate, or oracle input at all: [3](#0-2) 

The only protective mechanism against a misbehaving/depegged external asset is the `CircuitBreakerLevel` (`AllEnabled` / `MintingDisabled` / `AllDisabled`), which is **manually** toggled by the `full_admin` or `emergency_admin` of a given PSM instance: [4](#0-3) [5](#0-4) 

There is no automatic, price-derived halt condition analogous to the report's recommendation ("if the on-chain liquidity oracle drops below a threshold, halt borrowing/minting"). The system relies entirely on an external asset remaining pegged forever once approved via `add_external_asset`, exactly mirroring the ChainlinkAdapterOracle flaw where WBTC is assumed permanently equivalent to BTC.

### Impact Explanation
If any approved external asset depegs (e.g., a bridged stablecoin loses its 1:1 backing due to a bridge exploit, issuer freeze, or de-peg event), the PSM will continue to:
- Mint the internal asset 1:1 against a devalued external deposit, diluting/undercollateralizing the internal stablecoin and creating protocol-wide bad debt, and
- Allow attackers to redeem the (still fully-valued) internal asset for other, healthy external reserve assets held by the same PSM instance, effectively draining the good collateral using the depegged asset as payment.

This directly matches the report's core impact: "the protocol will not only be stuck with the bad debt caused by the currently outstanding [swaps] but will also continue to [mint against] a now effectively worthless asset."

### Likelihood Explanation
Any unprivileged, signed account can call the public `mint`/`redeem` extrinsics against any PSM instance with an approved external asset — no special permissions are required to trigger the flawed accounting once depeg occurs; the flaw is triggered purely by external market conditions (bridge failure, stablecoin depeg) rather than by a malicious peer, admin, or governance actor, satisfying the impact-gate criteria (implementation bug that lets an unprivileged actor cause wrong-amount settlement / theft of protocol reserves). The only existing mitigation (manual circuit breaker) requires human/admin reaction time and is not triggered automatically by price data, so it does not prevent the initial window of bad debt accrual.

### Recommendation
Introduce an on-chain price/peg check for each `(internal_asset, external_asset)` pair before allowing 1:1 conversion — e.g., integrate with an oracle pallet or on-chain liquidity reference (comparable to the report's suggested dual-oracle approach), and automatically flip the `CircuitBreakerLevel` to `MintingDisabled`/`AllDisabled` when the external asset's observed price deviates from peg by more than a configured tolerance, rather than relying solely on manual admin intervention.

### Proof of Concept
1. `create_psm` is invoked for `internal_asset = STABLE`, and `add_external_asset` approves `external_asset = USDX` (a bridged stablecoin) [6](#0-5) .
2. USDX's bridge is compromised and USDX trades at $0.10 on the open market — no on-chain signal reflects this in the PSM.
3. An attacker calls `mint(origin, STABLE, USDX, large_amount, max_fee)`; `external_to_internal` performs only decimal scaling [7](#0-6) , crediting the attacker with `large_amount` of `STABLE` at full 1:1 value despite depositing near-worthless USDX.
4. The attacker then calls `redeem` against the same PSM instance (or a different PSM instance sharing the internal asset) to withdraw *other, healthy* external reserve assets, extracting real value while the PSM is left holding worthless USDX — producing unbacked internal-asset supply / bad debt, exactly analogous to the WBTC/BTC depeg scenario in the source report.

//!
//! * **Internal** — the stablecoin a PSM issues and burns (e.g. a runtime's own USD-pegged

//!   coexist, each with its own reserve, debt ceiling, fee destination and approved externals. Mint
//!   operations credit the user with the internal asset; redeem operations burn it. Fees are
//!   collected in the internal asset and forwarded to that instance's [`PsmInfo::fee_destination`].
//! * **External** — third-party assets (e.g. USDC, USDT) approved on a specific PSM via
//!   [`Pallet::add_external_asset`] and held in that PSM's reserve. Users deposit external to mint
//!   internal, and burn internal to redeem external. A PSM may approve multiple externals, each
//!   identified by `external_asset`.
//!
//! ## Overview
//!
//! A PSM strengthens its internal asset's peg by providing arbitrage opportunities:
//! - When the internal asset trades **above** $1: Users swap external assets for the internal asset
//!   and sell for profit.
//! - When the internal asset trades **below** $1: Users buy cheap internal asset and swap for
//!   external assets.
//!
//! This creates a price corridor bounded by the minting and redemption fees.
//!
//! ### Key Concepts
//!
//! * **PSM instance**: A configured Peg Stability Module, keyed by its internal asset id and

//! * **Minting**: Deposit external asset → receive internal asset (minus fee).
//! * **Redemption**: Burn internal asset → receive external asset (minus fee).
//! * **Reserve**: External asset balance held by a PSM's reserve account (derived, not stored).

		#[default]

		/// Minting disabled, redemptions still allowed.
		MintingDisabled,
		/// All swaps disabled.
		AllDisabled,
	}

	impl CircuitBreakerLevel {
		/// Whether this level allows minting (external → internal).
		pub const fn allows_minting(&self) -> bool {
			matches!(self, CircuitBreakerLevel::AllEnabled)
		}

		/// Whether this level allows redemption (internal → external).
		pub const fn allows_redemption(&self) -> bool {
			!matches!(self, CircuitBreakerLevel::AllDisabled)
		}
	}

		/// Convert an amount denominated in external-asset units into internal units.
		///
		/// Scales by `10^(ext_decimals - internal_decimals)` — multiplies up when internal has more
		/// decimals, floor-divides when it has fewer. Returns [`Error::ConversionOverflow`] if
		/// the scaling factor or the product does not fit in the balance type.
		pub(crate) fn external_to_internal(
			amount: BalanceOf<T>,
			ext_decimals: u8,
			internal_decimals: u8,
		) -> Result<BalanceOf<T>, Error<T>> {
			use core::cmp::Ordering::*;
			match ext_decimals.cmp(&internal_decimals) {
				Equal => Ok(amount),
				Less => {
					let diff = (internal_decimals - ext_decimals) as u32;
					let factor = Self::pow10(diff)?;
					amount.checked_mul(&factor).ok_or(Error::<T>::ConversionOverflow)
				},
				Greater => {
					let diff = (ext_decimals - internal_decimals) as u32;
					let factor = Self::pow10(diff)?;
					Ok(amount.checked_div(&factor).unwrap_or_else(BalanceOf::<T>::zero))
				},
			}
