# [M] NFT withdrawal grief

## Summary
Severity: Medium
Contest weight: 0.2689
Dataset id: 18662
Source: https://huggingface.co/datasets/Zaevlad/audit-findings-dataset
Type: audit-finding

## Details
The vulnerability is a denial‑of‑service condition that allows a malicious participant to block a legitimate NFT owner (the lienee) from withdrawing their token even when the token is not currently on loan. The contract’s withdrawNftWithInterest() function assumes the NFT is still held by the contract and directly calls IERC721.safeTransferFrom() to move the token to the caller. Because the function does not verify that the NFT remains in the contract at the moment of execution, an attacker can intervene by first calling swapWithEth(), which removes the NFT from the contract, and then immediately invoking withdrawNftWithInterest(). When the transfer is attempted, the safeTransferFrom call reverts because the NFT is no longer owned by the contract, causing the withdrawal to fail. The attacker then calls repayWithNft(), which returns the full amount they paid (lien.credit + lien.price) minus any payableInterest – which is zero when the loan duration is zero – effectively refunding the attacker’s expense. As a result, the legitimate owner sees no NFT returned, receives no error indicating a loan is active, and is left unable to retrieve their asset, creating a grief attack. This issue occurs only when the contract permits new loans to be taken on an NFT that the owner might want to withdraw later; there is no mechanism for the lienee to lock the NFT against new loans. The problem was discovered during a manual audit that examined the interaction between swapWithEth(), withdrawNftWithInterest() and repayWithNft() and identified a sandwich‑style exploit. It can be hard to notice because the revert only happens under a specific ordering of calls and the attacker’s net cost is zero, so the contract appears to function correctly in normal use. The impact is a breach of the protocol’s business logic: users expect to be able to withdraw their NFT when it is not on loan, but the contract can silently prevent this, effectively making the NFT disappear from the user’s perspective. To remediate, the protocol should allow a lien to be marked as “non‑loanable” so that no new swapWithEth() calls can extract the NFT while a withdrawal is pending, and/or add an explicit ownership check right before the safeTransferFrom call and protect the function with a re‑entrancy guard. Conceptually, the fix restores the invariant that an NFT can only be transferred out if the contract still holds it, and gives the owner a way to opt‑out of future loans, thereby eliminating the grief vector.

## Proof of Concept
A lienee who wishes to withdraw his NFT calls `withdrawNftWithInterest()` which tries to [`IERC721.safeTransferFrom()` the NFT](https://github.com/code-423n4/2023-05-particle/blob/1caf678bc20c24c96fc8f6b0046383ff0e9d2a6f/contracts/protocol/ParticleExchange.sol#L183), which reverts if the NFT is not in the contract (being on loan). A griefer might therefore sandwich his call to `withdrawNftWithInterest()` with a `swapWithEth()` and a `repayWithNft()`. [`swapWithEth()` removes the NFT from the contract](https://github.com/code-423n4/2023-05-particle/blob/1caf678bc20c24c96fc8f6b0046383ff0e9d2a6f/contracts/protocol/ParticleExchange.sol#L460), which causes the following `withdrawNftWithInterest()` to revert. For this, the griefer has to [pay `lien.credit + lien.price`](https://github.com/code-423n4/2023-05-particle/blob/1caf678bc20c24c96fc8f6b0046383ff0e9d2a6f/contracts/protocol/ParticleExchange.sol#L440). But this is [returned in full in `repayWithNft()`](https://github.com/code-423n4/2023-05-particle/blob/1caf678bc20c24c96fc8f6b0046383ff0e9d2a6f/contracts/protocol/ParticleExchange.sol#L509-L512), [minus `payableInterest`](https://github.com/code-423n4/2023-05-particle/blob/1caf678bc20c24c96fc8f6b0046383ff0e9d2a6f/contracts/protocol/ParticleExchange.sol#L502) which is [nothing, since the loan time is zero](https://github.com/code-423n4/2023-05-particle/blob/1caf678bc20c24c96fc8f6b0046383ff0e9d2a6f/contracts/libraries/math/MathUtils.sol#L24-L25).

## Recommendation
Allow the option to, at any time, set a lien to not accept a new loan.
