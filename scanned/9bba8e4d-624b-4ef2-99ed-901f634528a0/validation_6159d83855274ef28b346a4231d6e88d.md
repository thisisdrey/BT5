## Finding [1](#0-0) 

### Title
Snowbridge Relayer Reward Is Irrevocably Registered on XCM Send-Success, Not on Destination Execution Success - (File: `bridges/snowbridge/pallets/inbound-queue-v2/src/lib.rs`)

### Summary
`Pallet::process_message` in the Snowbridge v2 inbound queue registers the full relayer reward (`relayer_fee` + any tip) as soon as `T::MessageProcessor::process_message` returns `Ok`. That "success" only means the inbound message was converted to XCM and successfully *handed off to the XCMP sender* for delivery to AssetHub — it says nothing about whether the XCM instructions (asset conversion, `DepositAsset`, etc.) actually execute successfully once they reach AssetHub. This mirrors the Pear Protocol bug: a fee/reward payable to a third party (referrer / relayer) is finalized based on an early, non-final step, while the "real" outcome of the underlying operation (the GMX position / the AssetHub-side XCM execution) is determined later and can fail, leaving the user's fee already spent on a reward they got nothing for.

### Finding Description
`process_message` at [2](#0-1)  does the following:
1. Marks the nonce as consumed.
2. Calls `T::MessageProcessor::process_message`, which is implemented by `XcmMessageProcessor` at [3](#0-2) . That function only converts the message to XCM and calls `Sender::deliver(ticket)` — i.e. it succeeds once the message is queued for delivery to the target parachain (AssetHub), not once it has executed there.
3. Immediately upon that `Ok`, the pallet unconditionally registers `total_tip = relayer_fee + tip` as a reward for the relayer via `T::RewardPayment::register_reward`, with no linkage to whether the forwarded XCM later executes successfully on AssetHub.

The XCM forwarded to AssetHub can fail for reasons entirely disconnected from delivery (e.g., asset conversion/pool issues, insufficient liquidity for fee payment, `DepositAsset` filter mismatch, or an invalid/absent claimer as seen in the `invalid_claimer_does_not_fail_the_message` test at [4](#0-3) ). In such failure paths, assets can end up trapped (`AssetsTrapped`) rather than delivered to the intended beneficiary, requiring the user to separately reclaim them via `ClaimAsset` with the correct claimer/origin — something not guaranteed to succeed (as the invalid-claimer test itself demonstrates by exercising a broken claimer path).

Despite this, the relayer's reward — funded from the user's own locked Ether/tip on Ethereum — has already been made final and claimable at the point the message was merely handed to the XCM sender, exactly as in the reported bug where the referrer fee was registered as soon as the (discounted) fee amount was set, before the GMX position outcome was known.

### Impact Explanation
Users whose forwarded XCM fails or has its funds trapped on AssetHub still pay the full relayer reward out of their bridged value, since `register_reward` is not reversible and is not conditioned on the destination-side execution outcome. This is a value-conservation break: the relayer is paid for "processing" a message whose economic effect for the user did not materialize, and there is no compensating credit-back mechanism analogous to `handleTokenAmountWhenPositionHasFailed` for the referee in the original report. Users can lose part or all of their bridged value while an unrelated party (the relayer) is unconditionally compensated.

### Likelihood Explanation
This triggers under normal Snowbridge V2 operation whenever a message is validly proven, delivered to the sender and dispatched, but the resulting XCM fails or partially fails once executed on AssetHub (e.g. swap/fee-conversion failure, filter rejection, or claimer misconfiguration) — no malicious relayer, governance action, or privileged actor is required. The existing test suite (`invalid_claimer_does_not_fail_the_message`) already demonstrates that the reward-registration path is decoupled from correct downstream settlement, confirming the condition is reachable through normal message content.

### Recommendation
Defer or make the relayer reward registration contingent on confirmed successful execution of the forwarded XCM on the destination chain (e.g., via a delivery/execution confirmation report-back from AssetHub), or hold the reward in a reclaimable/pending state until such confirmation, mirroring the recommended fix in the referenced report: update third-party payouts on confirmed success rather than at the point of best-effort dispatch.

### Proof of Concept
1. Submit a valid Ethereum event to `inbound-queue-v2::submit` whose payload converts to an XCM that will fail or trap assets on AssetHub (e.g., a claimer that does not resolve to a valid deposit target, or an asset conversion that exceeds pool slippage/liquidity), following the same pattern as `invalid_claimer_does_not_fail_the_message` at [5](#0-4) .
2. Observe `RewardRegistered` emitted at BridgeHub immediately, crediting the relayer with `relayer_fee` — this happens purely because `Sender::deliver` succeeded.
3. On AssetHub, observe the forwarded XCM failing (or trapping assets rather than depositing to the intended beneficiary).
4. Confirm the relayer's registered reward remains claimable via `pallet_bridge_relayers::claim_rewards` regardless of the AssetHub-side outcome, while the user's expected asset delivery did not occur as intended.

	impl<T: Config> Pallet<T> {
		pub fn process_message(relayer: T::AccountId, message: Message) -> DispatchResult {
			// Verify that the message was submitted from the known Gateway contract
			ensure!(T::GatewayAddress::get() == message.gateway, Error::<T>::InvalidGateway);

			let (nonce, relayer_fee) = (message.nonce, message.relayer_fee);

			// Verify the message has not been processed
			ensure!(!Nonce::<T>::get(nonce), Error::<T>::InvalidNonce);

			// Mark message as received
			Nonce::<T>::set(nonce);

			let message_id = T::MessageProcessor::process_message(relayer.clone(), message)
				.map_err(|e| match e {
					MessageProcessorError::ProcessMessage(e) => e,
					MessageProcessorError::ConvertMessage(e) => Error::<T>::from(e).into(),
					MessageProcessorError::SendMessage(e) => Error::<T>::from(e).into(),
				})?;

			// Pay relayer reward
			let tip = Tips::<T>::take(nonce).unwrap_or_default();
			let total_tip = relayer_fee.saturating_add(tip);
			if total_tip > 0 {
				T::RewardPayment::register_reward(&relayer, T::DefaultRewardKind::get(), total_tip);
			}

			// Emit event with the message_id
			Self::deposit_event(Event::MessageReceived { nonce, message_id });

			Ok(())
		}

	pub fn process_xcm(
		who: T::AccountId,
		message: Message,
	) -> Result<XcmHash, MessageProcessorError> {
		// Convert the message to XCM
		let xcm = Converter::convert(message).map_err(|error| {
			tracing::error!(target: LOG_TARGET, ?error, "XCM conversion failed with error");
			MessageProcessorError::ConvertMessage(error)
		})?;

		// Forward XCM to a target location
		let dest = TargetLocation::get();
		let message_id = Self::send_xcm(dest.clone(), &who, xcm.clone()).map_err(|error| {
			tracing::error!(target: LOG_TARGET, ?error, ?dest, ?xcm, "XCM send failed with error");
			MessageProcessorError::SendMessage(error)
		})?;

		// Return the message_id
		Ok(message_id)
	}

#[test]
fn invalid_claimer_does_not_fail_the_message() {
	let relayer_account = BridgeHubWestendSender::get();
	let relayer_reward = 1_500_000_000_000u128;

	let beneficiary_acc: [u8; 32] = H256::random().into();
	let beneficiary = Location::new(0, AccountId32 { network: None, id: beneficiary_acc.into() });

	let token_transfer_value = 2_000_000_000_000u128;

	let assets = vec![
		// the token being transferred
		NativeTokenERC20 { token_id: WETH.into(), value: token_transfer_value },
	];

	let origin = H160::random();

	set_up_eth_and_dot_pool();
	BridgeHubWestend::execute_with(|| {
		type RuntimeEvent = <BridgeHubWestend as Chain>::RuntimeEvent;
		let instructions = vec![
			RefundSurplus,
			// Deposit weth and leftover ether fees to beneficiary.
			DepositAsset { assets: Wild(AllCounted(2)), beneficiary: beneficiary.clone() },
		];
		let xcm: Xcm<()> = instructions.into();
		let versioned_message_xcm = VersionedXcm::V5(xcm);

		let message = Message {
			gateway: EthereumGatewayAddress::get(),
			nonce: 1,
			origin,
			assets,
			payload: Payload::Raw(versioned_message_xcm.encode()),
			// Set an invalid claimer
			claimer: Some(hex!("2b7ce7bc7e87e4d6619da21487c7a53f").to_vec()),
			value: 1_500_000_000_000u128,
			execution_fee: 1_500_000_000_000u128,
			relayer_fee: relayer_reward,
		};

		EthereumInboundQueueV2::process_message(relayer_account.clone(), message).unwrap();

		assert_expected_events!(
			BridgeHubWestend,
			vec![
				RuntimeEvent::XcmpQueue(cumulus_pallet_xcmp_queue::Event::XcmpMessageSent { .. }) => {},
				// Check that the relayer reward was registered.
				RuntimeEvent::BridgeRelayers(pallet_bridge_relayers::Event::RewardRegistered { relayer, reward_kind, reward_balance }) => {
					relayer: *relayer == relayer_account,
					reward_kind: *reward_kind == BridgeReward::Snowbridge,
					reward_balance: *reward_balance == relayer_reward,
				},
			]
		);
	});
