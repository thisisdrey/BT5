Attacker action: attacker (permissionless relayer) submits a validly-signed `msg` requesting a `Request{external:[Transfer(owner_designated_recipient, X)]}` where the promise itself (`Self::build_promise(promise)?.detach()`) can independently FAIL asynchronously (e.g. insufficient balance/gas at promise-execution time) AFTER the nonce was already committed and the `SignedRequest` event emitted, permanently burning the owner's nonce for a `Request` that never actually delivered value. Preconditions: wallet's NEAR balance insufficient to cover the `Transfer` action's attached deposit at promise-execution time, or target contract of a `FunctionCall` panics downstream. Call sequence: `execute_signed`(nonce committed, event emitted, returns `Ok`)-> promise detached and executes ASYNCHRONOUSLY -> promise fails on its own receipt, but the RECEIPT that called `execute_signed` still shows success since promise creation succeeded, only the downstream promise fails independently. Binding: value the owner authorised the nonce for == value actually delivered; if the promise fails, the nonce should not be considered irrevocably 'spent' for the same intended effect, or the owner is left having burned a one-time nonce for zero effect (griefing but self-inflicted since owner signed it; only a Critical impact if attacker can force this against the owner's will by manipulating gas/balance at exactly promise time as an unprivileged third party). Impact: High - a signed but non-delivering `Request` permanently consumes the nonce, and if an unprivileged attacker can force wallet's NEAR balance to be insufficient right before relaying (e.g. by front-running a `Transfer` that drains just enough NEAR they're also authorised to move via another path), the owner's legitimate pending request is griefed/frozen.
