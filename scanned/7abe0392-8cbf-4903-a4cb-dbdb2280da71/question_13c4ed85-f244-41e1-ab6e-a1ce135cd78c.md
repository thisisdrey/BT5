Target: `AuthCall` (contracts/defuse/core/src/intents/auth.rs) executed via `ExecutableIntent::execute_intent` -> `Engine::state.auth_call` -> `Contract::auth_call` (contracts/defuse/src/contract/intents/state.rs) -> `Contract::do_auth_call`. Attacker action: signs a `MultiPayload` containing an `AuthCall{ contract_id: <attacker_contract>, state_init: None, msg: <crafted>, attached_deposit: NearToken::ZERO, min_gas: None }` as one intent in a `DefuseIntents` batch that also contains a `Transfer` or `FtWithdraw` debiting the same signer. Preconditions: attacker has a funded Verifier balance and a deployed contract implementing `AuthCallee::on_auth` that calls back into `execute_intents` on the same Verifier with a second self-signed `MultiPayload` reusing the still-uncommitted wNEAR/token balance. Call sequence: `execute_signed_intents` -> `Engine::finalize` commits deltas -> receipt fires `do_auth_call` -> attacker's `on_auth` re-enters `execute_intents` before the outer receipt's remaining Promises (e.g. `ft_withdraw`) settle. Binding: the set of balance changes committed by the receipt == the set the signed intents authorised; broken if the re-entrant call lets the same wNEAR balance be spent by both the outer and re-entrant execution. Impact: Critical, double-spend of the signer's own balance credited into a receiver the attacker controls, at the signer's or a counterparty's expense. Proof: near-workspaces sandbox test deploying an `on_auth` callee that issues a second `execute_intents` call, asserting `sum(token_balances deltas across both executions) != authorised_delta`.
