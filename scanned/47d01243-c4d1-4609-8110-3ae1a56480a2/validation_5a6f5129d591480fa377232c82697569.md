## Title
Restricted (blacklisted) staking accounts can still receive staking rewards via `set_payee`/`RewardDestination::Account` bypassing the `T::Filter` whitelist check enforced on `bond` - (File: `substrate/frame/staking/src/pallet/mod.rs`)

### Summary
`pallet-staking` gates the ability to *become* a staker with a `T::Filter` restriction: `bond` explicitly rejects any stash that is on the restricted list with `Error::<T>::Restricted` [1](#0-0) . The same restriction is enforced on `bond_extra`/`rebond` for restricted accounts, as shown by the `restricted_accounts_can_only_withdraw` test in the async staking pallet [2](#0-1) . However, `set_payee` — which lets *any* unrestricted, bonded stash redirect its reward destination to an arbitrary `RewardDestination::Account(payee)` — performs no equivalent `T::Filter::contains(&payee)` check [3](#0-2) . This exactly mirrors the Ion Protocol M-05 bug class: a whitelist/permission gate exists on the "join"/entry function (there: `supply`, here: `bond`), but not on the mechanism that redirects future accrued value (there: ERC20 transfer, here: `RewardDestination::Account`), letting a non-whitelisted/restricted address receive protocol rewards.

### Finding Description
The `bond` extrinsic enforces the restriction filter on the stash before allowing it to enter the staking system: [4](#0-3) 

`set_payee`, by contrast, only checks that the deprecated `RewardDestination::Controller` variant is not used — it does not validate that the `payee` account (when `RewardDestination::Account(x)`) is unrestricted: [3](#0-2) 

Because `payee` accepts an arbitrary `AccountId` (this is the same pattern used internally for virtual bonding, e.g. `ledger.bond(RewardDestination::Account(payee.clone()))` in `virtual_bond`) [5](#0-4) , any already-bonded, unrestricted stash can call `set_payee` to point rewards at a restricted address. When era rewards are paid out, funds flow to that `payee` account with no re-check of the restriction filter at payout time — the filter is only consulted at the `bond`/`bond_extra`/`rebond` entry points, never at reward-distribution time. This is functionally identical to the Ion Protocol issue: the whitelist gate is bound to the "become a lender" action, but the value-accruing destination (interest-bearing token transfer there; reward payee here) is a separate, unchecked code path.

### Impact Explanation
This lets an account that the runtime has deliberately restricted from staking (via `T::Filter`, e.g. sanctioned or blacklisted addresses in a permissioned deployment) nonetheless accumulate staking rewards indefinitely, defeating the intended protective purpose of the restriction. This is a runtime bug that compromises intended behavior (unauthorized receipt of protocol payouts to accounts explicitly meant to be excluded), which is in-scope per the "runtime bugs that compromise intended behavior" and "theft or unbacked mint... to the wrong beneficiary" impact classes.

### Likelihood Explanation
High likelihood: no privileged access, malicious peer, or governance action is required. Any two ordinary, unprivileged signed accounts — one unrestricted stash and any restricted address as the target — can trigger this by simply calling the public `set_payee` extrinsic. It is directly analogous to the "will not fix" externally-reported behavior, confirming this class of gap is a real, reachable design gap rather than a theoretical one.

### Recommendation
Either (a) add a `T::Filter::contains(payee)` check inside `set_payee` (and inside `bond`'s payee argument, and `virtual_bond`) whenever `RewardDestination::Account(x)` is used, rejecting restricted destinations, or (b) explicitly document and accept that `T::Filter` only restricts becoming a staker and not receipt of rewards, matching the Ion team's "will not fix" stance — but this decision should be made deliberately by chain operators who rely on `T::Filter` for compliance/sanctions purposes, since the current code silently permits the bypass.

### Proof of Concept
1. Runtime configures `T::Filter` to restrict account `B` (e.g., via a sanctions/blacklist implementation of `Contains`).
2. Account `A` (unrestricted) calls `Staking::bond(origin=A, value=100, payee=RewardDestination::Account(A))` — succeeds since `A` passes the `Filter` check [1](#0-0) .
3. Account `A` calls `Staking::set_payee(origin=A, payee=RewardDestination::Account(B))` — succeeds because `set_payee` never checks `T::Filter::contains(&B)` [6](#0-5) .
4. At era payout, `B` (a restricted account that could never itself call `bond`) receives the staking reward transfer, exactly as the whitelisted-lender bypass in the external report allowed a non-whitelisted address to receive interest-bearing tokens via transfer instead of via the gated `supply` entrypoint.

```rust
		pub fn bond(
			origin: OriginFor<T>,
			#[pallet::compact] value: BalanceOf<T>,
			payee: RewardDestination<T::AccountId>,
		) -> DispatchResult {
			let stash = ensure_signed(origin)?;

			ensure!(!T::Filter::contains(&stash), Error::<T>::Restricted);

			if StakingLedger::<T>::is_bonded(StakingAccount::Stash(stash.clone())) {
				return Err(Error::<T>::AlreadyBonded.into());
			}

			// An existing controller cannot become a stash.
			if StakingLedger::<T>::is_bonded(StakingAccount::Controller(stash.clone())) {
				return Err(Error::<T>::AlreadyPaired.into());
			}

			// Reject a bond which is considered to be _dust_.
			if value < asset::existential_deposit::<T>() {
				return Err(Error::<T>::InsufficientBond.into());
			}

			let stash_balance = asset::free_to_stake::<T>(&stash);
			let value = value.min(stash_balance);
			Self::deposit_event(Event::<T>::Bonded { stash: stash.clone(), amount: value });
			let ledger = StakingLedger::<T>::new(stash.clone(), value);

			// You're auto-bonded forever, here. We might improve this by only bonding when
			// you actually validate/nominate and remove once you unbond __everything__.
			ledger.bond(payee)?;
```

```rust
#[test]
fn restricted_accounts_can_only_withdraw() {
	ExtBuilder::default().build_and_execute(|| {
		// alice is a non blacklisted account.
		let alice = 301;
		let _ = Balances::make_free_balance_be(&alice, 500);
		// alice can bond
		assert_ok!(Staking::bond(RuntimeOrigin::signed(alice), 100, RewardDestination::Staked));

		// and bob is a blacklisted account
		let bob = 302;
		let _ = Balances::make_free_balance_be(&bob, 500);
		restrict(&bob);

		// Bob cannot bond
		assert_noop!(
			Staking::bond(RuntimeOrigin::signed(bob), 100, RewardDestination::Staked,),
			Error::<Test>::Restricted
		);

		// alice is blacklisted now and cannot bond anymore
		restrict(&alice);

		assert_noop!(
			Staking::bond_extra(RuntimeOrigin::signed(alice), 100),
			Error::<Test>::Restricted
		);

		// but she can unbond her existing bond
		assert_ok!(Staking::unbond(RuntimeOrigin::signed(alice), 100));

		// she cannot rebond the unbonded amount
		Session::roll_until_active_era(2);
		assert_noop!(Staking::rebond(RuntimeOrigin::signed(alice), 50), Error::<Test>::Restricted);

		// move to era when alice fund can be withdrawn
		Session::roll_until_active_era(5);

		// alice can withdraw now
		assert_ok!(Staking::withdraw_unbonded(RuntimeOrigin::signed(alice), 0));

		// she still cannot bond
		assert_noop!(
			Staking::bond(RuntimeOrigin::signed(alice), 100, RewardDestination::Staked,),
			Error::<Test>::Restricted
		);

		// bob is removed from restrict list
		remove_from_restrict_list(&bob);

		// bob can bond now
		assert_ok!(Staking::bond(RuntimeOrigin::signed(bob), 100, RewardDestination::Staked));
```

```rust
	/// Virtually bonds `keyless_who` to `payee` with `value`.
	///
	/// The payee must not be the same as the `keyless_who`.
	fn virtual_bond(
		keyless_who: &Self::AccountId,
		value: Self::Balance,
		payee: &Self::AccountId,
	) -> DispatchResult {
		if StakingLedger::<T>::is_bonded(StakingAccount::Stash(keyless_who.clone())) {
			return Err(Error::<T>::AlreadyBonded.into());
		}

		// check if payee not same as who.
		ensure!(keyless_who != payee, Error::<T>::RewardDestinationRestricted);

		// mark who as a virtual staker.
		VirtualStakers::<T>::insert(keyless_who, ());

		Self::deposit_event(Event::<T>::Bonded { stash: keyless_who.clone(), amount: value });
		let ledger = StakingLedger::<T>::new(keyless_who.clone(), value);

		ledger.bond(RewardDestination::Account(payee.clone()))?;

		Ok(())
	}
```
