### Title
Unauthenticated, unbounded `Tips` storage growth via `add_tip` for arbitrary/non-existent nonces - ([File: bridges/snowbridge/pallets/inbound-queue-v2/src/lib.rs])

### Summary
The report's core broken invariant is: a state-mutating entry point writes into a mapping meant to gate/track a specific, verifiable object (an order), but the write path never checks that the referenced object actually exists or is otherwise validated, and the mapping is never bounded or reconciled. The Snowbridge inbound-queue-v2 pallet has the same shape: any signed account can permanently write an entry into the `Tips` storage map for **any** `u64` nonce — including nonces that will never correspond to a real inbound message — because the only check performed is that the nonce hasn't already been marked processed, not that a message with that nonce exists or will ever arrive.

### Finding Description
`Tips` is a plain `StorageMap<_, Blake2_128Concat, u64, u128, OptionQuery>` keyed purely by an externally supplied `u64` nonce: [1](#0-0) 

The only public entry point that reaches this map is `AddTip::add_tip`, whose validation is limited to checking the nonce has not yet been processed: [2](#0-1) 

It does not verify:
- that a message with that nonce was ever emitted by the Ethereum Gateway,
- that the nonce is within any plausible/near-future range of the current nonce counter (there is no upper bound check against the last consumed nonce or any watermark),
- that the caller has any relationship to the message being tipped.

This function is reachable by any signed account on the sending chain (Asset Hub) through `snowbridge-pallet-system-frontend::add_tip`, which is a fully public, signed extrinsic that swaps a caller-supplied fee asset for Ether, burns it, and forwards an `EthereumSystemCall::AddTip { sender, message_id, amount }` XCM `Transact` to Bridge Hub, which ultimately calls into the inbound-queue-v2 `AddTip` implementation: [3](#0-2) 

The only place `Tips` entries are ever removed is in `process_message`, when a message with that exact nonce is actually submitted and successfully processed: [4](#0-3) 

Because nonces for messages that never existed (e.g., far-future or otherwise unused nonce values) will never be submitted via `submit`, any `Tips` entry created for such a nonce can never be cleaned up by `process_message`. There is no admin/root call to purge stale `Tips` entries and no bound on the map's cardinality (keyspace is the full `u64` range), so this is a permanent, unauthenticated storage-growth vector — directly analogous to the report's `cancelled` mapping being written without ever validating the referenced object, with no subsequent invariant enforcing correctness or cleanup.

### Impact Explanation
This is public, underpriced work against chain state: an attacker with a signed account and minimal fee-asset balance can repeatedly call `add_tip` with fabricated/never-to-be-used nonces, permanently inflating on-chain storage on Bridge Hub with entries that will never be reconciled. Because storage growth is not bounded by the actual bridge message throughput, this degrades state size and can be used to bloat chain state cheaply and indefinitely, which the acceptance criteria classify as "public underpriced work that degrades block production or stalls bridge processing." It does not require a malicious relayer, validator, or governance actor — only a signed, unprivileged account with a small swappable balance.

### Likelihood Explanation
High likelihood: the entry point is fully public (`ensure_signed` only), requires only ability to pay/swap a nonzero fee asset (arbitrarily small), and needs no coordination with real bridge activity. The attack is a single-transaction, repeatable action bounded only by transaction fees, not by any pallet-level nonce-range or existence check.

### Recommendation
- In `AddTip::add_tip` (and/or `process_message`), reject tips for nonces that are implausible relative to the last known/consumed nonce (e.g., enforce an upper bound close to the current nonce watermark, or require the nonce to correspond to a message that has already been observed/committed on the outbound side).
- Add a mechanism (permissioned or time-bounded) to reap stale, never-claimed `Tips` entries, or require a bounded/rent-charged storage item so unclaimed tips cannot accumulate indefinitely for free.
- Mirror the mai-protocol fix's spirit: validate the "order" (here, the nonce/message reference) actually exists and is within a legitimate window before accepting state that purports to reference it.

### Proof of Concept
1. Attacker holds a small amount of any asset that can be swapped to Ether via `T::Swap` on Asset Hub.
2. Attacker calls `snowbridge_pallet_system_frontend::add_tip(message_id = <arbitrary future/never-used nonce>, asset = <minimal amount>)`.
3. This burns the minimal fee/tip and forwards an XCM `Transact` with `EthereumSystemCall::AddTip` to Bridge Hub.
4. On Bridge Hub, `inbound-queue-v2::AddTip::add_tip` only checks `!Nonce::<T>::get(nonce)` (true, since that nonce was never used) and inserts into `Tips::<T>`.
5. Because no message with that nonce is ever submitted via `submit`, this `Tips` entry is never read/removed by `process_message`, permanently occupying storage.
6. Repeating this with new arbitrary nonces lets the attacker grow `Tips` storage without bound, at minimal per-call cost.

		pub fn process_message(relayer: T::AccountId, message: Message) -> DispatchResult {
			// Verify that the message was submitted from the known Gateway contract
			ensure!(T::GatewayAddress::get() == message.gateway, Error::<T>::InvalidGateway);

			let (nonce, relayer_fee) = (message.nonce, message.relayer_fee);

			// Verify the message has not been processed
			ensure!(!Nonce::<T>::get(nonce), Error::<T>::InvalidNonce);

			// Mark message as received
			Nonce::<T>::set(nonce);

			let message_id = T::MessageProcessor::process_message(relayer.clone(), message)
				.map_err(|e| match e {
					MessageProcessorError::ProcessMessage(e) => e,
					MessageProcessorError::ConvertMessage(e) => Error::<T>::from(e).into(),
					MessageProcessorError::SendMessage(e) => Error::<T>::from(e).into(),
				})?;

			// Pay relayer reward
			let tip = Tips::<T>::take(nonce).unwrap_or_default();
			let total_tip = relayer_fee.saturating_add(tip);
			if total_tip > 0 {
				T::RewardPayment::register_reward(&relayer, T::DefaultRewardKind::get(), total_tip);
			}

			// Emit event with the message_id
			Self::deposit_event(Event::MessageReceived { nonce, message_id });

			Ok(())
		}

	impl<T: Config> AddTip for Pallet<T> {
		fn add_tip(nonce: u64, amount: u128) -> Result<(), AddTipError> {
			ensure!(amount > 0, AddTipError::AmountZero);
			// If the nonce is already processed, return an error
			ensure!(!Nonce::<T>::get(nonce.into()), AddTipError::NonceConsumed);
			// Otherwise add the tip.
			Tips::<T>::mutate(nonce, |tip| {
				*tip = Some(tip.unwrap_or_default().saturating_add(amount));
			});
			return Ok(());
		}
	}
