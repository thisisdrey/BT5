Target: `ImtTokenId::new`/`into_generic_tokens` (crates/primitives/token-id/src/imt.rs, contracts/defuse/core/src/tokens.rs::imt::ImtTokens::into_generic_tokens). Attacker signs an `ImtMint` intent with `tokens` map containing a sub-token id string `"othermint.near:X"` where `minter_id` is resolved from the signer's own account. Preconditions: signer is an ordinary account, not `othermint.near`. Call sequence: `into_generic_tokens` builds `ImtTokenId::new(minter_id=attacker.near, "othermint.near:X")`, checks only `token_id.len() > MAX_TOKEN_ID_LEN`, then converts `.into()` to `TokenId::Imt`. Binding: `TokenId::from_str(&t.to_string()) == t` and the resulting `(minter_id, token_id)` pair must not equal any `(othermint.near, X)` pair mintable only by `othermint.near`. Impact: Critical - if the round trip is broken, an attacker could mint value under an identity string that a resolver or downstream check treats as belonging to `othermint.near`. Proof idea: cargo test signing `ImtMint{tokens: {"othermint.near:X": amount}}` from `attacker.near` and asserting the resulting balance key's `minter_id` field equals `attacker.near`, not `othermint.near`.
