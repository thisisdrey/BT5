Target: EventReceiver::main_loop (libsigner/src/events.rs) error-handling match arm `Err(e) => { warn!(...); continue; }` for any EventError not explicitly UnrecognizedEvent or Terminated. Attacker action: repeatedly send single malformed POST bodies to distinct recognized URLs (/stackerdb_chunks, /proposal_response, /new_burn_block, /new_block) that each individually fail JSON deserialization inside process_event. Preconditions: attacker can reach the event port; no rate limiting or backoff exists in this loop. Call sequence: next_event() -> process_event -> serde_json::from_slice fails -> Err(EventError::Deserialize) is returned up through next_event() -> main_loop's `Err(e)` arm logs and continues immediately, re-entering http_server.recv() for the next request. Equality/fault: none of the malformed inputs are ever validated against origin, so 'every message reaching the warn! path == an unauthenticated remote input the runloop never sees' holds by design, but the accept-loop itself never distinguishes a repeated single attacker connection from the legitimate node, meaning any reachable third party can drive this loop indefinitely with zero authentication cost per message. Scoped impact: Critical - a bounded-compute DoS is achievable because each malformed single message forces a full parse attempt (JSON deserialization of an attacker-sized body up to the node's content-length) with no per-message authentication gate before that work is done. Proof idea: benchmark test sending N malformed /new_block POSTs with large bodies to a bound SignerEventReceiver and measuring CPU/time spent in process_event's read_to_string + serde_json::from_slice per message with no source authentication.
