### Title
Validator self-stake incentive budget is permanently drained (not recovered) when an era has zero weighted era-points, mirroring the "first-period gauge" undistributed-rewards bug - ([File: substrate/frame/staking-async/src/pallet/impls.rs])

### Summary
The gauge report's core defect is: a reward budget is snapshotted for a period whose distribution denominator (`totalVotesPerPeriod`) can legitimately be zero, causing per-share payout math to skip everyone, and the "stuck emissions" recovery path never accounts for a zero-denominator period, so the budget is neither paid out nor recoverable. The same broken invariant exists in `pallet-staking-async`'s validator self-stake incentive: `ErasValidatorIncentiveBudget` is snapshotted into a per-era pot every era regardless of whether any validator earns era-points, but `calculate_validator_incentive_for_page` requires a non-zero `ErasSumWeightedPoints[era]` (or, pre-cutoff, non-zero `ErasSumValidatorIncentiveWeight[era]`) to pay anyone. If that denominator is zero for a live era, the function returns `None` for every validator, and `EraRewardManager::drain` unconditionally sweeps the era pot's remaining balance to `T::UnclaimedRewardHandler` at era-history-window expiry — i.e., the funds are moved out of the reward-payout path entirely rather than being recovered as "stuck emissions" through any validator-facing or governance-facing accounting path tied to the original incentive allocation.

### Finding Description
`ErasValidatorIncentiveBudget<T>` and its era pot are unconditionally created and funded every era in `EraRewardManager::snapshot_era_rewards` [1](#0-0) 
independent of whether any validator will actually earn era-points that era. Payout math in `calculate_validator_incentive_for_page` divides the budget by `ErasSumWeightedPoints::<T>::get(era)` (post-cutoff) or `ErasSumValidatorIncentiveWeight::<T>::get(era)` (pre-cutoff); if that sum is zero, the function short-circuits to `None`, which the test suite confirms is treated as an "inconsistency" rather than a legitimately-empty-period case (the code even emits `UnexpectedKind::ValidatorIncentiveWeightMismatch`): [2](#0-1) 
Tests explicitly construct this exact "denominator zero, budget non-zero" branch and confirm no incentive is paid to any validator that era: [3](#0-2) 
`ErasSumWeightedPoints` starts at zero by `ValueQuery` default and is only incremented when a validator is credited nonzero era-points via `reward_active_era` [4](#0-3) 
so an era in which the whole validator set earns zero points (e.g., because of a chain outage, mass offline/slash event, or a short "genesis-like" period) makes the denominator zero for every validator by construction, not just as an injected fault.

Once such an era's history window expires, `EraRewardManager::cleanup_era` calls `drain`, which unconditionally withdraws whatever balance remains in the incentive pot and forwards it to `T::UnclaimedRewardHandler` via `on_unbalanced` [5](#0-4) 
There is no branch anywhere in `calculate_validator_incentive_for_page`, `snapshot_era_rewards`, or `drain` that detects "budget was snapshotted but the era legitimately had zero rewardable weighted points" and redirects/reallocates that specific budget back to validators or to a recoverable accounting bucket tied to that era — it is simply swept with the generic "unclaimed reward" handling, exactly like the gauge case where `stuckEmissionsRecovery` never special-cases a zero-vote period.

### Impact Explanation
This is a runtime-behavior-compromising accounting bug: validator self-stake incentive funds that were budgeted (minted/allocated) for an era are silently forfeited to the generic unclaimed-reward sink instead of reaching the intended validator beneficiaries, whenever an entire era produces zero weighted era-points. Because `ErasSumWeightedPoints`/`ErasSumValidatorIncentiveWeight` can genuinely be zero (not just via storage corruption) for an era where no validator is credited points, this is a real, non-privileged-actor-dependent path to loss of intended rewards — the funds don't go to an attacker, but the payout invariant "budget allocated for validators must be paid to validators" is broken, which is directly analogous to the acknowledged low-risk finding in the external report.

### Likelihood Explanation
Low-to-moderate likelihood in practice: it requires an era where the entire elected validator set earns zero `RewardPoint`s (session-report-driven), which is an edge case but can arise from validator-set/session-report anomalies, migrations, or an era immediately following incentive activation before any session report lands. The code's own test suite (`new_formula_zero_denominator_emits_unexpected_and_skips_payout`) demonstrates the maintainers are aware the zero-denominator state is reachable and currently treat it purely as a "log + skip" event rather than a recoverable-funds event, matching the "acknowledged, low risk" disposition of the original report.

### Recommendation
Detect the case where `ErasValidatorIncentiveBudget[era] > 0` but the relevant denominator (`ErasSumWeightedPoints[era]` or `ErasSumValidatorIncentiveWeight[era]`) is zero at the time the era's incentive pot would otherwise be drained, and route that specific era's remaining incentive-pot balance back through a dedicated, auditable recovery path (e.g., a governance-callable "recover era incentive budget" call, or automatic redistribution into the next era's incentive budget) instead of the generic `UnclaimedRewardHandler` sweep in `EraRewardManager::drain`/`cleanup_era`, mirroring the report's recommendation to make `stuckEmissionsRecovery` handle the zero-votes-in-period case explicitly.

### Proof of Concept
1. Enable the validator incentive feature and advance to an active era `E` (as in `setup_incentive_with_budget`), so `ErasValidatorIncentiveBudget::<T>::get(E)` and the incentive era pot are funded via `EraRewardManager::snapshot_era_rewards`.
2. Ensure no validator is credited era-points for era `E` (i.e., `Eras::<T>::reward_active_era` is never called with any non-zero point tuple for era `E`), so `ErasSumWeightedPoints::<T>::get(E) == 0` by default (`sum_weighted_points_initial_value_is_zero`, confirmed at [4](#0-3) ).
3. Advance past era `E`'s payout window and call `make_all_reward_payment(E)`: every validator's `calculate_validator_incentive_for_page` call returns `None` due to the zero-denominator branch (see the closely analogous forced-fault test at [3](#0-2) ), so no incentive is paid to anyone despite a positive budget.
4. Advance until era `E` falls outside `HistoryDepth` and `EraRewardManager::cleanup_era(E)` runs; `drain` withdraws the still-full incentive pot balance and forwards it to `T::UnclaimedRewardHandler`, permanently removing it from the validator-incentive accounting path with no era-specific recovery mechanism.

	pub(crate) fn snapshot_era_rewards(era: EraIndex) -> EraRewardAllocation<BalanceOf<T>> {
		let staker_era_pot = Self::create(era, RewardKind::StakerRewards);
		let incentive_era_pot = Self::create(era, RewardKind::ValidatorSelfStake);

		let general_staker_pot =
			T::RewardPots::pot_account(RewardPot::General(RewardKind::StakerRewards));
		let general_incentive_pot =
			T::RewardPots::pot_account(RewardPot::General(RewardKind::ValidatorSelfStake));

		// Leave ED in the general pots to keep them alive.
		let staker_balance = T::Currency::reducible_balance(
			&general_staker_pot,
			Preservation::Preserve,
			Fortitude::Polite,
		);
		let incentive_balance = T::Currency::reducible_balance(
			&general_incentive_pot,
			Preservation::Preserve,
			Fortitude::Polite,
		);

		let actual_staker = if !staker_balance.is_zero() {
			match T::Currency::transfer(
				&general_staker_pot,
				&staker_era_pot,
				staker_balance,
				Preservation::Preserve,
			) {
				Ok(_) => staker_balance,
				Err(e) => {
					log!(error, "Era {:?}: staker reward transfer failed: {:?}", era, e);
					defensive!("Failed to transfer staker rewards to era pot");
					Zero::zero()
				},
			}
		} else {
			Zero::zero()
		};

		let actual_incentive = if !incentive_balance.is_zero() {
			match T::Currency::transfer(
				&general_incentive_pot,
				&incentive_era_pot,
				incentive_balance,
				Preservation::Preserve,

				Err(e) => {

					Zero::zero()
				},
			}
		} else {
			Zero::zero()
		};

		log!(
			info,
			"Era {:?}: snapshotted staker_rewards={:?}, validator_incentive={:?}",
			era,
			actual_staker,
			actual_incentive
		);

		EraRewardAllocation { staker_rewards: actual_staker, validator_incentive: actual_incentive }

	/// Drains an era pot's remaining balance to the unclaimed reward handler.
	///
	/// The pot account itself is kept alive (provider retained) so the same slot
	/// can be reused by a future era. No-op if the pot was never created (e.g.
	/// the era ran in legacy minting mode).
	pub(crate) fn drain(era: EraIndex, kind: RewardKind) {
		let pot_account = T::RewardPots::pot_account(RewardPot::Era(era, kind));

		// Skip if pot was never created (legacy mode doesn't create pots).
		if frame_system::Pallet::<T>::providers(&pot_account) == 0 {
			return;
		}

		let remaining = T::Currency::balance(&pot_account);

		if remaining.is_zero() {
			return;
		}

		match T::Currency::withdraw(
			&pot_account,
			remaining,
			Precision::BestEffort,
			Preservation::Expendable,
			Fortitude::Force,
		) {
			Ok(credit) => {
				T::UnclaimedRewardHandler::on_unbalanced(credit);
				log!(
					debug,
					"Drained {:?} unclaimed rewards from era {:?} {:?} pot",
					remaining,
					era,
					kind
				);
			},
			Err(e) => {
				defensive!("Failed to withdraw unclaimed rewards from era pot");
				log!(
					error,
					"Era {:?} {:?}: unclaimed reward withdrawal failed: {:?}",
					era,
					kind,
					e
				);
			},
		}
	}

	/// Whether the slot backing this era's staker reward pot exists.
	///
	/// Because slots are reused across eras (rotating pool), this returns
	/// `true` for an era as long as *some* era mapping to the same slot
	/// has created the account.
	#[cfg(any(test, feature = "try-runtime"))]
	pub(crate) fn has_staker_rewards_pot(era: EraIndex) -> bool {
		let pot = T::RewardPots::pot_account(RewardPot::Era(era, RewardKind::StakerRewards));
		frame_system::Pallet::<T>::providers(&pot) > 0
	}

	///
	/// Pot accounts are kept alive for reuse by a future era at the same slot.
	pub(crate) fn cleanup_era(era: EraIndex) {
		Self::drain(era, RewardKind::StakerRewards);

fn new_formula_zero_denominator_emits_unexpected_and_skips_payout() {
	// A post-cutoff era whose `ErasSumWeightedPoints` is zero despite a live budget and a
	// validator with points/weight is a storage inconsistency: the payout must skip the
	// incentive and surface an `Unexpected` event rather than silently pay nothing.
	ExtBuilder::default().build_and_execute(|| {
		let alice = 11; // validator

		setup_incentive_with_budget(45, 5);
		Session::roll_until_active_era(2);
		Eras::<Test>::reward_active_era(vec![(alice, 1)]);
		Session::roll_until_active_era(3);

		// WHEN: corrupt the denominator to zero on a weighted-points era.
		let valid_sum = ErasSumWeightedPoints::<Test>::get(2);
		ErasSumWeightedPoints::<Test>::remove(2);
		let _ = staking_events_since_last_call();

		make_all_reward_payment(2);
		let events = staking_events_since_last_call();

		// THEN: no incentive paid, and the inconsistency is reported.

		)));

		// Restore valid state so the post-test try-state hook still runs and passes.
		ErasSumWeightedPoints::<Test>::insert(2, valid_sum);
	});
