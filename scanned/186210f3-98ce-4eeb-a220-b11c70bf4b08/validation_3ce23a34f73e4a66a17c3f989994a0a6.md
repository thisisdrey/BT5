### Title
Stale `ChildrenCuratorFees` accumulation via curator reassignment causes parent bounty curator fee under-payment / fund lock - ([File: substrate/frame/child-bounties/src/lib.rs])

### Summary
`pallet-child-bounties` accumulates curator fees for all child bounties of a parent bounty in the single storage item `ChildrenCuratorFees<T>`, which is later subtracted from the parent bounty curator's fee in `pallet-bounties::claim_bounty`. The accumulator is only ever incremented (in `propose_curator`) and is never decremented when a child-bounty curator is unassigned via `unassign_curator`. Because `propose_curator` can be called again on the same child bounty after it returns to the `Added` state, the same child-bounty "slot" can add its fee to the parent-level accumulator multiple times, while only the final fee is ever actually paid out. This mirrors the reported bug class: an accounting value is appended to at multiple lifecycle points/layers without any reconciliation step to remove stale contributions, causing over-counting that a downstream consumer (`endProposal` in the report, `claim_bounty` here) never audits.

### Finding Description
`propose_curator` in `substrate/frame/child-bounties/src/lib.rs` sets the child bounty's fee and unconditionally adds it to the shared `ChildrenCuratorFees` map: [1](#0-0) 

`unassign_curator`, which any signed account can invoke (directly if they are the curator, or on an `Active` child bounty once `update_due` has passed, i.e. the curator became "inactive" — a condition reachable without any privileged role), transitions the child bounty back to `ChildBountyStatus::Added` and slashes/returns the curator deposit, but never touches `ChildrenCuratorFees`: [2](#0-1) 

Because the child bounty is now `Added` again, the parent curator can legitimately call `propose_curator` a second time with a new fee for the *same* child bounty. That call again does `ChildrenCuratorFees::<T>::mutate(parent_bounty_id, |value| *value = value.saturating_add(fee))`, so the stale first fee is never subtracted — the accumulator now double-counts a single child-bounty's curator fee. `claim_child_bounty` (the only place a child bounty's fee is actually paid) never adjusts `ChildrenCuratorFees` either: [3](#0-2) 

Finally, when the parent bounty is claimed, `pallet-bounties::claim_bounty` reads this inflated cumulative value and subtracts it from the parent curator's fee: [4](#0-3) 

`final_fee = fee.saturating_sub(children_fee)` will be under-computed (potentially to zero) relative to the fees actually paid to child curators, because `children_fee` includes stale, already-abandoned fee commitments from unassigned/reassigned curators that were never paid out.

### Impact Explanation
This breaks the "conserve value and settle exactly once" invariant for treasury-derived funds: the parent bounty curator's rightful fee is silently reduced or fully consumed by phantom fee amounts that were never disbursed to anyone. The excess balance remains stuck in the bounty sub-account with no code path to reclaim it for the correct beneficiary (the parent curator), constituting a permanent partial fund lock/misallocation of treasury-approved bounty value. This does not require a malicious peer, validator, governance actor, or leaked key — only routine bounty curator turnover (which is an expected, documented governance workflow) combined with the public, unprivileged `unassign_curator` call available once a curator becomes inactive.

### Likelihood Explanation
Curator reassignment (`unassign_curator` → re-`propose_curator`) is a normal, expected part of the bounty lifecycle explicitly documented in the pallet (curator inactivity, curator resignation, or curator slashing by `RejectOrigin`). Any bounty with more than one curator assignment cycle on the same child bounty index will trigger this double-accumulation. No exotic preconditions, races, or privileged actions are required beyond the standard bounty workflow, making this a straightforward and repeatable accounting error in a live treasury pallet.

### Recommendation
Track curator fee commitments per child-bounty rather than as a single monotonic per-parent accumulator, or explicitly decrement `ChildrenCuratorFees` by the previous fee whenever `unassign_curator` or `close_child_bounty` removes/resets a curator assignment, before any new fee is added. Alternatively, compute `children_fee` at claim time by summing the `fee` field of all currently-live child bounties for the parent, rather than relying on an accumulator that is never fully reconciled on removal.

### Proof of Concept
1. Council creates and funds parent bounty `B` with total value `V`, curator fee `F_parent`; curator accepted, `Active`.
2. Parent curator calls `add_child_bounty` creating child bounty `C0`, then `propose_curator(C0, curator_A, fee=100)`. `curator_A` accepts → `ChildrenCuratorFees[B] = 100`.
3. Time passes `BountyUpdatePeriod` blocks without an update from `curator_A` (child bounty `Active`, `update_due` in the past).
4. Any unprivileged signed account calls `unassign_curator(B, C0)`. Because `update_due < now`, the unassign succeeds via the public, non-curator branch; `curator_A` is slashed, child bounty `C0` returns to `Added`. `ChildrenCuratorFees[B]` remains `100`.
5. Parent curator, following normal process, re-proposes a new curator: `propose_curator(C0, curator_B, fee=100)`. `curator_B` accepts, later awards and `claim_child_bounty` pays `curator_B` fee `100` from `C0`'s sub-account. `ChildrenCuratorFees[B]` is now `200` (never decremented for the abandoned `curator_A` fee, and never decremented at claim time either).
6. Only `100` was ever actually paid to any child curator, but `ChildrenCuratorFees[B] = 200`.
7. Parent curator calls `claim_bounty(B)`. `final_fee = fee.saturating_sub(200)`, e.g. if `F_parent = 150`, `final_fee = 0` (saturates), permanently under-paying the parent curator by `150` and leaving that value stranded in the bounty sub-account with no beneficiary path to reclaim it.

		pub fn unassign_curator(
			origin: OriginFor<T>,
			#[pallet::compact] parent_bounty_id: BountyIndex,
			#[pallet::compact] child_bounty_id: BountyIndex,
		) -> DispatchResult {
			let maybe_sender = ensure_signed(origin.clone())
				.map(Some)
				.or_else(|_| T::RejectOrigin::ensure_origin(origin).map(|_| None))?;

			ChildBounties::<T>::try_mutate_exists(
				parent_bounty_id,
				child_bounty_id,
				|maybe_child_bounty| -> DispatchResult {
					let child_bounty =
						maybe_child_bounty.as_mut().ok_or(BountiesError::<T>::InvalidIndex)?;

					let slash_curator =
						|curator: &T::AccountId, curator_deposit: &mut BalanceOf<T>| {
							let imbalance =
								T::Currency::slash_reserved(curator, *curator_deposit).0;
							T::OnSlash::on_unbalanced(imbalance);
							*curator_deposit = Zero::zero();
						};

					match child_bounty.status {
						ChildBountyStatus::Added => {
							// No curator to unassign at this point.
							return Err(BountiesError::<T>::UnexpectedStatus.into());
						},
						ChildBountyStatus::CuratorProposed { ref curator } => {
							// A child-bounty curator has been proposed, but not accepted yet.
							// Either `RejectOrigin`, parent bounty curator or the proposed
							// child-bounty curator can unassign the child-bounty curator.
							ensure!(
								maybe_sender.map_or(true, |sender| {
									sender == *curator ||
										Self::ensure_bounty_active(parent_bounty_id)
											.map_or(false, |(parent_curator, _)| {
												sender == parent_curator
											})
								}),
								BadOrigin
							);
							// Continue to change bounty status below.
						},
						ChildBountyStatus::Active { ref curator } => {
							// The child-bounty is active.
							match maybe_sender {
								// If the `RejectOrigin` is calling this function, slash the curator
								// deposit.
								None => {
									slash_curator(curator, &mut child_bounty.curator_deposit);
									// Continue to change child-bounty status below.
								},
								Some(sender) if sender == *curator => {
									// This is the child-bounty curator, willingly giving up their
									// role. Give back their deposit.
									T::Currency::unreserve(curator, child_bounty.curator_deposit);
									// Reset curator deposit.
									child_bounty.curator_deposit = Zero::zero();
									// Continue to change bounty status below.
								},
								Some(sender) => {
									let (parent_curator, update_due) =
										Self::ensure_bounty_active(parent_bounty_id)?;
									if sender == parent_curator ||
										update_due < Self::treasury_block_number()
									{
										// Slash the child-bounty curator if
										// + the call is made by the parent bounty curator.
										// + or the curator is inactive.
										slash_curator(curator, &mut child_bounty.curator_deposit);
									// Continue to change bounty status below.
									} else {
										// Curator has more time to give an update.
										return Err(BountiesError::<T>::Premature.into());
									}
								},
							}
						},
						ChildBountyStatus::PendingPayout { ref curator, .. } => {
							let (parent_curator, _) = Self::ensure_bounty_active(parent_bounty_id)?;
							ensure!(
								maybe_sender.map_or(true, |sender| parent_curator == sender),
								BadOrigin,
							);
							slash_curator(curator, &mut child_bounty.curator_deposit);
							// Continue to change child-bounty status below.
						},
					};
					// Move the child-bounty state to Added.
					child_bounty.status = ChildBountyStatus::Added;
					Ok(())
				},
			)
		}

		#[pallet::call_index(5)]
		#[pallet::weight(<T as Config>::WeightInfo::claim_child_bounty())]
		pub fn claim_child_bounty(
			origin: OriginFor<T>,
			#[pallet::compact] parent_bounty_id: BountyIndex,
			#[pallet::compact] child_bounty_id: BountyIndex,
		) -> DispatchResult {
			ensure_signed(origin)?;

			// Ensure child-bounty is in expected state.
			ChildBounties::<T>::try_mutate_exists(
				parent_bounty_id,
				child_bounty_id,
				|maybe_child_bounty| -> DispatchResult {
					let child_bounty =
						maybe_child_bounty.as_mut().ok_or(BountiesError::<T>::InvalidIndex)?;

					if let ChildBountyStatus::PendingPayout {
						ref curator,
						ref beneficiary,
						ref unlock_at,
					} = child_bounty.status
					{
						// Ensure block number is elapsed for processing the
						// claim.
						ensure!(
							Self::treasury_block_number() >= *unlock_at,
							BountiesError::<T>::Premature,
						);

						// Make curator fee payment.
						let child_bounty_account =
							Self::child_bounty_account_id(parent_bounty_id, child_bounty_id);
						let balance = T::Currency::free_balance(&child_bounty_account);
						let curator_fee = child_bounty.fee.min(balance);
						let payout = balance.saturating_sub(curator_fee);

						// Unreserve the curator deposit. Should not fail
						// because the deposit is always reserved when curator is
						// assigned.
						let _ = T::Currency::unreserve(curator, child_bounty.curator_deposit);

						// Make payout to child-bounty curator.
						// Should not fail because curator fee is always less than bounty value.
						let fee_transfer_result = T::Currency::transfer(
							&child_bounty_account,
							curator,
							curator_fee,
							AllowDeath,
						);
						debug_assert!(fee_transfer_result.is_ok());

						// Make payout to beneficiary.
						// Should not fail.
						let payout_transfer_result = T::Currency::transfer(
							&child_bounty_account,
							beneficiary,
							payout,
							AllowDeath,
						);
						debug_assert!(payout_transfer_result.is_ok());

						// Trigger the Claimed event.
						Self::deposit_event(Event::<T>::Claimed {
							index: parent_bounty_id,
							child_index: child_bounty_id,
							payout,
							beneficiary: beneficiary.clone(),
						});

						// Update the active child-bounty tracking count.
						ParentChildBounties::<T>::mutate(parent_bounty_id, |count| {
							count.saturating_dec()
						});

						// Remove the child-bounty description.
						ChildBountyDescriptionsV1::<T>::remove(parent_bounty_id, child_bounty_id);

						// Remove the child-bounty instance from the state.
						*maybe_child_bounty = None;

						Ok(())
					} else {
						Err(BountiesError::<T>::UnexpectedStatus.into())
					}
				},
			)
		}
