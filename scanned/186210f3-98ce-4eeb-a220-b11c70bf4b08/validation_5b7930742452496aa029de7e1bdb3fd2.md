### Title
`pallet-psm` mints internal stablecoin 1:1 against external stablecoins with no price check, allowing unbacked-mint drain during a depeg — (File: `substrate/frame/psm/src/lib.rs`)

### Summary
`pallet-psm::mint()` converts a deposited "external" stablecoin (e.g. USDC/USDT) into the PSM's internal stablecoin purely via decimal scaling (`external_to_internal`), with no reference to any price feed. It assumes the external asset is always worth exactly 1 unit of the internal stablecoin, mirroring the exact broken invariant in the external report: "assumes all stablecoins are priced at 1 USD." [1](#0-0) [2](#0-1) 

### Finding Description
`mint()` computes `internal_equivalent = external_to_internal(external_amount, ext_decimals, internal_decimals)` — a pure decimal-rescaling operation, not a price-fetching one — then mints that amount of internal asset (minus fee) to the caller while transferring the external asset into the PSM reserve at face value: [3](#0-2) 

There is no oracle, no Chainlink/DIA-style price feed, and no check that the deposited external stablecoin is actually trading near $1. The only backstop is the `CircuitBreakerLevel` (`AllEnabled` / `MintingDisabled` / `AllDisabled`), which must be *manually* flipped by an admin via `set_asset_status` — this is a reactive, privileged, out-of-band mitigation, not a protocol-level invariant: [4](#0-3) 

The debt accounting (`PsmDebt`, `max_debt`, per-asset ceiling weights) only tracks *nominal* internal-asset amounts minted against each external asset — it has no concept of the external asset's real market value, so it cannot detect or bound the amount of value that leaves the reserve mispriced: [5](#0-4) 

This is the direct structural analog of the M-24 report: DIA's `getPriceUSD18` blindly assumes every quote token trading against USD is worth exactly $1 (`_basePrice18 = 10**18` default, or the DIA "/USD" feed value), just as `pallet-psm` blindly assumes every approved external asset is worth exactly 1 unit of the internal stablecoin. In both cases, the code path never independently verifies the peg before treating the asset as fully backed/priced value.

### Impact Explanation
If any approved external asset depegs downward (e.g. USDC dropping to $0.87, as cited in the original report), any unprivileged account can:
1. Acquire the depegged asset cheaply on the open market.
2. Call `mint()` to deposit it into the PSM reserve at full nominal (1:1 decimal) value and receive internal stablecoin (pUSD-equivalent) minus a small fixed fee (default 0.5%).
3. Immediately sell or redeem the minted internal stablecoin elsewhere (DEX, or redeem against a *different, still-healthy* external asset in the same PSM instance, since redemption debt tracking is per-external but the internal asset itself is fungible once minted and can be redeemed via any approved external with sufficient debt/reserve).

This mints internal stablecoin that is not actually fully backed (the reserve now holds a devalued asset while the user extracted full nominal value), draining real economic backing from the PSM and from later, honest redeemers. This is an unbacked-mint / value-theft primitive requiring no privileged actor — only an external market depeg event, exactly matching the accepted "external pre-condition" in the source report. It falls squarely under the required impact "theft or unbacked mint" for balances/asset accounting.

### Likelihood Explanation
Likelihood is contingent on an external stablecoin depeg event (same precondition as the source report), which is a realistic and recurring occurrence for USD-pegged stablecoins (USDC's March 2023 depeg cited in the original report). Once it occurs, exploitation requires only a signed, unprivileged `mint` extrinsic — no governance, validator, relayer, or node compromise. The only defense is a human admin noticing and calling `set_asset_status` before/during the depeg window, which is inherently reactive and can lag real-time price movements (there is no automatic pause tied to any price signal because none is read).

### Recommendation
Introduce a price-verification step in `mint()` (and ideally `redeem()`) before treating `external_amount` as 1:1 backing:
- Integrate an oracle (e.g. the newly introduced `pallet-oracle`) to fetch the external asset's live USD price.
- Reject or haircut mints when the external asset's price deviates from $1 beyond a configurable tolerance band, or scale `internal_equivalent` by the observed price rather than pure decimal conversion.
- Alternatively/additionally, add an automatic, price-triggered circuit breaker so depegs are caught without requiring a human admin to react in real time.

### Proof of Concept
1. PSM instance configured with internal asset `pUSD` and external assets `USDC` (weight 60%) and `USDT` (weight 40%), `AllEnabled`, no depeg-time governance intervention yet.
2. USDC depegs to $0.87 on external markets (per historical precedent cited in the source report).
3. Attacker buys 1,000,000 depegged USDC on the open market for ~$870,000.
4. Attacker calls `Psm::mint(origin, pUSD, USDC, 1_000_000 * unit, max_fee)`:
   - `external_to_internal` computes `internal_equivalent ≈ 1,000,000` (pure decimal scaling, ignoring the $0.87 real price) — see `substrate/frame/psm/src/lib.rs` lines 716-725.
   - Ceiling and debt checks pass (lines 732-741) since they only track nominal debt.
   - Attacker receives ~995,000 pUSD (after 0.5% fee) that is fully fungible/tradeable at $1 elsewhere.
5. Attacker has converted ~$870,000 of real value into ~$995,000 of nominal internal-stablecoin claims, a ~$125,000 unbacked mint extracted from the PSM's reserve, to be realized later by honest holders attempting to redeem against the now-underbacked reserve.

Note: I could not fully inspect the bodies of `external_to_internal`/`internal_to_external` (only their signatures/usage were located within tool-call limits), so the exact rounding/decimal-scaling arithmetic is inferred from call sites and the README rather than directly read line-by-line; this does not affect the core finding that no price oracle is consulted anywhere in the mint/redeem path.

		pub fn mint(
			origin: OriginFor<T>,
			internal_asset: T::AssetId,
			external_asset: T::AssetId,
			external_amount: BalanceOf<T>,
			max_fee: Permill,
		) -> DispatchResult {
			let who = ensure_signed(origin)?;
			let info = Psm::<T>::get(&internal_asset).ok_or(Error::<T>::PsmNotFound)?;

			let external = ExternalAssets::<T>::get(&internal_asset, &external_asset)
				.ok_or(Error::<T>::UnsupportedAsset)?;
			ensure!(external.status.allows_minting(), Error::<T>::MintingStopped);

			let (ext_decimals, internal_decimals) =
				Self::ensure_decimals_match(&info, &internal_asset, &external_asset, &external)?;

			let internal_equivalent =
				Self::external_to_internal(external_amount, ext_decimals, internal_decimals)?;
			ensure!(!internal_equivalent.is_zero(), Error::<T>::AmountTooSmallAfterConversion);
			ensure!(internal_equivalent >= info.min_swap_amount, Error::<T>::BelowMinimumSwap);

			let effective_external =
				Self::internal_to_external(internal_equivalent, ext_decimals, internal_decimals)?;

			let fee_rate = MintingFee::<T>::get(&internal_asset, &external_asset);
			ensure!(fee_rate <= max_fee, Error::<T>::FeeTooHigh);
			let fee = fee_rate.mul_ceil(internal_equivalent);
			let internal_to_user = internal_equivalent.saturating_sub(fee);

			let current_total_psm_debt = Self::total_psm_debt(&internal_asset);
			ensure!(
				current_total_psm_debt.saturating_add(internal_equivalent) <= info.max_debt,
				Error::<T>::ExceedsMaxPsmDebt
			);

			let current_debt = PsmDebt::<T>::get(&internal_asset, &external_asset);
			let max_debt = Self::max_asset_debt(&internal_asset, &external_asset, &info);
			let new_debt = current_debt.saturating_add(internal_equivalent);
			ensure!(new_debt <= max_debt, Error::<T>::ExceedsMaxPsmDebt);

			let psm_account = Self::psm_account(&internal_asset);
			T::Fungibles::transfer(
				external_asset.clone(),
				&who,
				&psm_account,
				effective_external,
				Preservation::Expendable,
			)?;
			T::Fungibles::mint_into(internal_asset.clone(), &who, internal_to_user)?;
			if !fee.is_zero() {
				T::Fungibles::mint_into(internal_asset.clone(), &info.fee_destination, fee)?;
			}

			PsmDebt::<T>::insert(&internal_asset, &external_asset, new_debt);

## Circuit Breaker

Each approved external on each instance has an independent circuit breaker
with three levels:

| Level             | Minting | Redemption | Use Case                          |
| ----------------- | ------- | ---------- | --------------------------------- |
| `AllEnabled`      | Allowed | Allowed    | Normal operation                  |
| `MintingDisabled` | Blocked | Allowed    | Drain debt from a problematic external |

`set_asset_status` is callable at both the `Full` (`full_admin`) and
