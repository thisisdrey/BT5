Target: WalletImpl::execute_signed no-sign path via SignatureSchema for a schema variant which implements verify_request_msg to always return true ('no-sign' mode referenced in scope). Attacker discovers/deploys against a wallet-contract variant instantiated with a no-sign SignatureSchema (e.g. used for testing/bootstrapping per WALLET_NO_SIGN_CODE_HASH seen in sdk tests) that is mistakenly left reachable on a production global-contract deployment, and submits w_execute_signed(msg, proof) with an EMPTY or arbitrary proof string, since verify_request_msg trivially returns true regardless of proof content. Precondition: a wallet AccountId has state_init pointing to the no-sign global contract code hash (as used in crates/wallet/sdk/tests/test.rs w_init test) yet holds real Verifier balances. Call sequence: execute_signed still enforces chain_id, signer_id, nonce commit, but S::verify_request_msg(&pk, &msg, proof) is a no-op returning true, so ANY attacker-constructed Request executes as long as chain_id/signer_id/nonce are set correctly (all of which the attacker fully controls when constructing msg themselves, since msg is just data - the ONLY real gate is the signature, and here it's absent). Binding: for a wallet holding fund-bearing balances, execute_signed must only proceed when proof cryptographically proves possession of the wallet owner's private key, i.e. S::verify_request_msg must be a real cryptographic check, never a constant-true no-sign schema, for any wallet address reachable while holding Verifier token_balances. Impact: Critical - any unprivileged party can construct msg{signer_id: no-sign-wallet, nonce: fresh, chain_id: correct} and drain all of its Verifier-custodied balances with zero signature. Proof: cargo test/near-workspaces deploying the no-sign wallet variant, depositing Verifier tokens to its account, then calling w_execute_signed with proof='' and an external Transfer promise to attacker's own account, asserting the transfer succeeds and the wallet's Verifier balance is now 0, proving no signature was required to move funds.
