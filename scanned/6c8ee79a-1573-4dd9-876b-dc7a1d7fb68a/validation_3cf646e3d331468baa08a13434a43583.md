Based on my investigation, the strongest local analog to the Witch.sol "second grab overwrites original owner" bug class is in `pallet-staking-async`'s offence queue, where a `reporter` field is silently and irrecoverably overwritten when a second, higher-severity offence report supersedes an already-queued record — exactly mirroring the pattern where a second privileged-but-permissionless action destroys the record needed to make the rightful party whole, while the codebase demonstrably *does* know how to preserve such "prior" state for other fields (`prior_slash_fraction`) but omits it for `reporter`.

### Title
Offence-queue update in `on_new_offences` overwrites the original reporter, permanently losing their earned slash-reward eligibility - ([File: substrate/frame/staking-async/src/pallet/impls.rs])

### Summary
`pallet-staking-async`'s `OffenceQueue<T>` stores, per `(era, validator)`, a single `OffenceRecord` that includes a `reporter: Option<AccountId>` field used later to pay out the slashing reward. When a second offence report for the same `(era, validator)` arrives with a strictly higher `slash_fraction` before the first record is processed, the queue entry is replaced and the `reporter` is unconditionally set to the new report's `o.reporters.first()`, discarding the previous reporter with no fallback storage. This is structurally identical to the Witch.sol bug: a second "grab" (higher-severity report) overwrites the record that identifies the rightful beneficiary (the original owner / first reporter), and there is no secondary mapping to recover it, even though the pallet explicitly preserves the analogous `prior_slash_fraction` for exactly this reason.

### Finding Description
In `on_new_offences` [1](#0-0) , when an `existing` `OffenceQueue` entry is found and the incoming `slash_fraction` is higher, the record is replaced:

```rust
if let Some(existing) = OffenceQueue::<T>::get(offence_era, &validator) {
    if slash_fraction.deconstruct() > existing.slash_fraction.deconstruct() {
        OffenceQueue::<T>::insert(
            offence_era,
            &validator,
            OffenceRecord {
                reporter: o.reporters.first().cloned(),
                reported_era: active_era.index,
                slash_fraction,
                ..existing
            },
        );
```

`..existing` preserves `exposure_page` and `prior_slash_fraction`, but `reporter` is unconditionally replaced by the new call's reporter (or `None` if the new report carries no reporters). The `OffenceRecord` struct comment for `prior_slash_fraction` explicitly documents the intended design pattern of *preserving the overwritten value* [2](#0-1) , yet no equivalent field/preservation exists for the previous reporter.

Later, when the offence is finally processed, only the single surviving `reporter` is credited: [3](#0-2)  sets `unapplied.reporter = offence_record.reporter;`, and `apply_slash`/`pay_reporters` pays out to that lone account only [4](#0-3) . Whoever originally and correctly reported the offence first is paid nothing if a second, independently-submitted report (from a different account, or an unsigned/anonymous equivocation report with an empty `reporters` vector) happens to carry a higher `slash_fraction` before the queue entry is processed — this can occur naturally, e.g., a second GRANDPA/BABE equivocation for the same validator in the same era with different severity, or a differently-computed `slash_fraction` at a later point.

### Impact Explanation
This breaks the intended incentive/reward-settlement invariant for offence reporting: the party who did the correct, first, legitimate work of detecting and reporting misbehaviour permanently loses their earned reward with no recovery path, while the runtime silently reassigns/burns that credit. This falls under "duplicate settlement or payout / permanent loss of rightful beneficiary's entitlement" for staking reward accounting, matching the required-impacts category of settlement state only advancing correctly to the rightful beneficiary.

### Likelihood Explanation
The reporting path (`report_equivocation` / `report_equivocation_unsigned` on the relay chain, forwarded into `on_new_offences` via `rc-client`) is reachable by any unprivileged account submitting valid equivocation proofs — no validator, node, or governance privilege is required to *submit* a report; only detecting/possessing the second piece of evidence is needed. Because slash fractions for different concurrent offences (e.g., multiple equivocations, or `im-online` fraction growing with more discovered offenders) are not identical across reports for the same validator/era, a legitimately higher-severity report from a second, unrelated party will routinely and non-maliciously trigger the overwrite — this is not merely a contrived attacker path but an ordinary occurrence of the existing test suite's own scenarios (e.g. `offence_discarded_correctly`) demonstrating record overwrites for the same `(era, validator)` key.

### Recommendation
Preserve the original reporter analogous to how `prior_slash_fraction` is preserved: either (a) accumulate reporters into a bounded list on the `OffenceRecord` so all legitimate reporters across superseding reports are paid their share at processing time, or (b) only allow the `reporter` field to be overwritten if the previous one is `None`, keeping the first reporter recorded (`reporter: existing.reporter.or_else(|| o.reporters.first().cloned())`), mirroring the Yield team's recommended fix pattern of never losing the earliest legitimate claimant.

### Proof of Concept
1. Validator `V` commits equivocation offence A at era `E`. Reporter Alice submits `report_equivocation` first; via `rc-client` this reaches `on_new_offences`, and since no existing queue entry exists, `OffenceQueue::<T>::insert(E, V, OffenceRecord { reporter: Some(Alice), slash_fraction: F1, .. })` is stored (line 1577-1589).
2. Before this entry is processed (`ProcessingOffence` hasn't reached it yet — queue processing is one offence per block, see `substrate/frame/staking-async/src/tests/slashing.rs:1928-1969`), a second, independent equivocation offence B for the *same validator and era* is reported (e.g., via an unsigned equivocation report carrying no reporters, or by Bob), with `slash_fraction = F2 > F1`.
3. `on_new_offences` finds `existing` with `slash_fraction = F1 < F2`, and executes the overwrite branch (lines 1534-1545), storing `reporter: None` (or `Some(Bob)`), discarding `Some(Alice)` permanently.
4. When the offence is processed in `process_offence` / `apply_slash`, only the new `reporter` value is paid via `pay_reporters` (`substrate/frame/staking-async/src/slashing.rs:651-655`); Alice, despite being the first and legitimate reporter of the underlying misbehaviour, receives nothing, and there is no stored trace of her prior report to reconcile or reclaim from — the same unrecoverable-loss pattern documented in the Witch.sol `vaultOwners` overwrite bug.
