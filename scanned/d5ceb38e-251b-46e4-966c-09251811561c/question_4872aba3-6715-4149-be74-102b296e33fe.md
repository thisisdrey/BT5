In `Transfer::execute_intent` (contracts/defuse/core/src/intents/tokens.rs) the debit `internal_sub_balance(sender_id, tokens)` and credit `internal_add_balance(receiver_id, tokens)` happen synchronously before `engine.state.notify_on_transfer` detaches a `Promise`. An attacker signs `Transfer{receiver_id: attacker_contract, tokens: {ft:1000}, notification: Some(NotifyOnTransfer{state_init: Some(malicious_state_init), msg, min_gas: None})}` where `attacker_contract` is a NEP-616 deterministic account not yet deployed; the `mt_on_transfer()` callee re-enters `execute_intents` with a second payload from the same signer performing an `FtWithdraw` of the same `ft` balance before the outer engine's `Engine::finalize` invariant check completes. Preconditions: signer has 1000 `ft`, `mt_on_transfer` re-entrant call succeeds because state was already committed by `Deltas`. Call sequence: `Transfer::execute_intent` -> `notify_on_transfer` -> `Contract::notify_on_transfer` (Promise, detached) -> attacker `mt_on_transfer` -> re-entrant `execute_intents` -> `FtWithdraw::execute_intent` -> `ft_withdraw`. Binding: value credited to `receiver_id` by `Transfer` plus value withdrawn by `FtWithdraw` == value originally held by `sender_id`, i.e. sum of all balance deltas for `ft` across the whole receipt tree == 0. Impact: Critical, signer's `ft` balance both transferred and independently withdrawn, net negative to the Verifier's custodied `ft`. Proof idea: sandbox test with deployed `mt_receiver` stub whose `mt_on_transfer` calls `execute_intents` with a second signed FtWithdraw payload; assert final on-chain `ft.balance_of(defuse)` < sum of all `mt_balance_of` claims.
