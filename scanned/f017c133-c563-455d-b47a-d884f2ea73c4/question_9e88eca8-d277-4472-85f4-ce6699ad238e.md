Precondition: the same `RPCPostBlockRequestHandler` instance is reused across pipelined/keep-alive requests on one connection without an intervening `restart()` call due to an error path skipping cleanup. Impact: Critical — a second, unauthenticated `POST /v3/blocks/upload/` (no `broadcast` query, no header) on the same connection could inherit a stale `broadcast=true` from a prior authenticated request if `restart()` is skipped, forcing relay of an unauthenticated block. Proof: Rust test issuing two sequential requests on one `TestRPC`/`StacksHttp` session — first authenticated+broadcast=1, second unauthenticated with no broadcast — asserting the handler's internal state is reset (`handler.broadcast == Some(false)` or `None`) before the second `try_handle_request` runs.
