## Analysis

The Plaza Finance bug pattern is: a checkpoint timestamp (`lastDistribution`) that gates a periodic, elapsed-time-based payout is reset to `block.timestamp` (the *actual* call time) rather than the *scheduled* time, so any delay in triggering the action causes a permanent loss of the reward that should have accrued for the delayed interval.

The `pallet-dap` (Dynamic Allocation Pool) issuance-drip logic contains the same class of bug. [1](#0-0) 

### Title
Permanent, irreversible loss of issuance/inflation in `pallet-dap::drip_issuance` when elapsed time exceeds `MaxElapsedPerDrip` - (`substrate/frame/dap/src/lib.rs`)

### Summary
`Pallet::<T>::drip_issuance()` computes `elapsed = now - LastIssuanceTimestamp`, clamps `elapsed` to the configured safety ceiling `T::MaxElapsedPerDrip` when it is exceeded, mints/distributes issuance only for the clamped `elapsed`, but then unconditionally sets `LastIssuanceTimestamp` to `now` (the actual, unclamped wall-clock time) instead of `last + elapsed` (the clamped, credited time). This is structurally identical to the Plaza Finance `Pool.sol` bug: the checkpoint used to gate a time-based payout is advanced to "now" instead of to the point actually credited, silently and permanently discarding the uncredited interval.

### Finding Description
In `drip_issuance` (`substrate/frame/dap/src/lib.rs:365-399`):

```rust
let mut elapsed = now.saturating_sub(last);
...
let max_elapsed = T::MaxElapsedPerDrip::get();
if elapsed > max_elapsed {
    Self::deposit_event(Event::Unexpected(UnexpectedKind::ElapsedClamped { ... }));
    elapsed = max_elapsed;          // only `max_elapsed` worth is minted
}

// Always advance the clock so elapsed time doesn't accumulate across skipped drips.
LastIssuanceTimestamp::<T>::put(now);   // <-- checkpoint jumps to `now`, not `last + max_elapsed`

let _ = Self::mint_and_distribute(elapsed);
```

If `now - last` exceeds `MaxElapsedPerDrip` (e.g. because block production stalled, `on_initialize` was skipped for an extended window, or the runtime was paused/upgraded for longer than the configured ceiling), only `max_elapsed` worth of inflation is minted and distributed. The remaining time (`now - last - max_elapsed`) is not deferred to the next drip — it is discarded forever because the checkpoint is set to `now` rather than `last + max_elapsed`. This is the exact same root cause pattern flagged in the Plaza Finance report (`lastDistribution = block.timestamp` instead of `lastDistribution + distributionPeriod`).

The project's own prdoc for the `MigrateV1ToV2` migration (`prdoc/stable2606/pr_11809.prdoc`) explicitly documents this exact failure mode for the *migration* path: "elapsed is then clamped by `MaxElapsedPerDrip`, so only up to one cap's worth of inflation is actually credited on the first drip, and the rest is silently dropped." That fix only addressed the one-shot migration seeding case via a dedicated catch-up drip; it did not change the regular `drip_issuance` hook, which retains the identical drop-on-clamp behavior for every subsequent occurrence of a stall exceeding `MaxElapsedPerDrip`. [2](#0-1) 

### Impact Explanation
Every time chain block production/`on_initialize` execution is delayed by more than `T::MaxElapsedPerDrip` (a configurable but finite ceiling, integrity-checked only to be `> IssuanceCadence`, not tied to any hard chain-halt guarantee), the excess elapsed time is permanently and irreversibly lost — no future drip recovers it. Since `mint_and_distribute` feeds staker/validator/incentive/treasury reward pots via `BudgetAllocation`, this directly reduces intended issuance/rewards to stakers and other budget recipients, matching the "runtime bugs that compromise intended behavior" and "loss of yield" impact classes. Unlike an attacker-triggered exploit, this requires no privileged actor — any sufficiently long stall (network partition, congestion, extended runtime-upgrade window, `on_initialize` weight exhaustion, etc.) triggers the loss automatically.

### Likelihood Explanation
`drip_issuance` runs on every block via `on_initialize` (`substrate/frame/dap/src/lib.rs:210-212`), so under normal operation `elapsed` rarely nears `MaxElapsedPerDrip`. However, any real-world stall longer than the configured ceiling (which must be small enough to bound "accidental over-minting," per the doc comment, hence necessarily a finite, not-astronomically-large value) will silently trigger the loss. Given production chains can and do experience multi-block stalls (spam, congestion, migrations, temporary halts), this is a realistic and reachable condition, not a purely theoretical one.

### Recommendation
On clamping, advance `LastIssuanceTimestamp` by the credited amount (`last.saturating_add(max_elapsed)`) instead of jumping to `now`. This preserves the uncredited remainder so it is picked up on the next drip (subject to the same ceiling, spread across multiple drips if necessary), mirroring the correct fix recommended for Plaza Finance (`lastDistribution + distributionPeriod` instead of `block.timestamp`).

### Proof of Concept
1. Configure `IssuanceCadence = 60_000` (1 min) and `MaxElapsedPerDrip = 6 * 12_000` (6 blocks worth, as used in the test at `substrate/frame/staking-async/integration-tests/src/ah/test.rs:2234`).
2. Let `LastIssuanceTimestamp = T0`.
3. Simulate a stall where no blocks execute for a period longer than `MaxElapsedPerDrip` (e.g. `T1 = T0 + 10 * 12_000`).
4. Call/observe `drip_issuance` at `T1`: `elapsed = T1 - T0 = 120_000` > `max_elapsed = 72_000`, so `elapsed` is clamped to `72_000`, `mint_and_distribute(72_000)` runs, and `LastIssuanceTimestamp` is set to `T1` (not `T0 + 72_000`).
5. The `48_000`ms (`T1 - T0 - 72_000`) of elapsed time — and its corresponding issuance — is never minted in this or any future drip, confirmed by `Event::Unexpected(UnexpectedKind::ElapsedClamped { actual_elapsed: 120_000, ceiling: 72_000 })` being the only signal, with no compensating future credit. 			}

			// First block after genesis: initialize timestamp, don't drip.
			// For existing chains, use `migrations::MigrateV1ToV2` to seed this
			// value from ActiveEra.start so this branch is never hit post-upgrade.
			if last == 0 {
				LastIssuanceTimestamp::<T>::put(now);
				return T::DbWeight::get().reads_writes(2, 2);
			}

			// Apply safety ceiling on elapsed time.
			let max_elapsed = T::MaxElapsedPerDrip::get();
			if elapsed > max_elapsed {
				Self::deposit_event(Event::Unexpected(UnexpectedKind::ElapsedClamped {
					actual_elapsed: elapsed,
					ceiling: max_elapsed,
