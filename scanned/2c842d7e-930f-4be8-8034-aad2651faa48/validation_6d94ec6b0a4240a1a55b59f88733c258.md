## Title
`pallet-psm` mints/settles on requested amount instead of the actual amount reported by `Fungibles::transfer`, breaking the fee-on-transfer/rebasing invariant - (File: `substrate/frame/psm/src/lib.rs`)

### Summary
`pallet_psm::mint` and `pallet_psm::redeem` transfer external assets via `T::Fungibles::transfer`, whose documented and implemented contract is to **return the actual amount that moved** (not necessarily the requested `amount`), exactly analogous to a `safeTransferFrom` call on a fee-on-transfer/rebasing ERC20. The pallet discards this return value with `?` and instead credits/debits users and the debt ledger using amounts computed purely from the *pre-transfer* request (`internal_to_user`, `effective_internal_net`), never the value actually confirmed to have moved.

### Finding Description
In `mint` (`substrate/frame/psm/src/lib.rs:702-767`):

```rust
T::Fungibles::transfer(
    external_asset.clone(),
    &who,
    &psm_account,
    effective_external,
    Preservation::Expendable,
)?;
T::Fungibles::mint_into(internal_asset.clone(), &who, internal_to_user)?;
``` [1](#0-0) 

`internal_to_user` was derived earlier purely from `internal_equivalent`/`effective_external`, i.e. from what the caller *requested* to deposit — not from what `psm_account` actually received.

In `redeem` (`substrate/frame/psm/src/lib.rs:809-902`), the same pattern appears on the outgoing leg:
```rust
if !external_out.is_zero() {
    T::Fungibles::transfer(
        external_asset.clone(),
        &psm_account,
        &who,
        external_out,
        Preservation::Expendable,
    )?;
}
``` [2](#0-1) 
while `PsmDebt` is decremented by `effective_internal_net`, a value computed from the *requested* `external_out`, not the amount actually delivered.

The `fungibles::Mutate::transfer` trait explicitly documents and returns the *actual amount transferred* as its `Ok` value:
```rust
fn transfer(...) -> Result<Self::Balance, DispatchError> {
    ...
    Self::decrease_balance(asset.clone(), source, amount, BestEffort, preservation, Polite)?;
    let _ = Self::increase_balance(asset.clone(), dest, amount, BestEffort);
    ...
    Ok(amount)
}
``` [3](#0-2) 
and concrete backends like `pallet-assets::do_transfer` state this directly: "Returns the actual amount placed into `dest`... Will fail if the amount transferred is so small that it cannot create the destination due to minimum balance requirements." [4](#0-3) 
The internals (`decrease_balance`/`prep_debit`) can legitimately return an `actual` amount that differs from the requested `amount` under `BestEffort` decrement semantics and minimum-balance/dust handling. [5](#0-4) 

This is the same broken invariant as the reported Solidity bug: the code assumes the transfer moves exactly the requested amount and mints/settles based on that assumption rather than the confirmed, actual amount moved. Any `T::Fungibles` backend registered for an external asset (per the pallet's own README, meant to host third-party assets like USDC/USDT, potentially bridged/foreign representations with fee-like or dust-losing transfer semantics) that can produce `actual < requested` on transfer will cause the PSM to over-mint internal stablecoin relative to what it actually received into its reserve, or under-decrement debt relative to what actually left the reserve.

### Impact Explanation
This directly threatens asset-accounting soundness of the PSM: over-minting the internal (pUSD-like) stablecoin without matching backing in the reserve is unbacked mint / value non-conservation — a core "Balances… must conserve value and settle exactly once to the rightful beneficiary and amount" violation. Under sustained use, the internal asset would become under-collateralized against its `PsmDebt`/reserve, and the debt/redeem side becoming decoupled from real reserve balance can eventually create insolvency (some redeemers unable to redeem, or reserve overdrawn relative to what governance believes is backed).

### Likelihood Explanation
This is reachable by any unprivileged signed account through the public `mint`/`redeem` extrinsics — no privileged, admin, relayer, or validator involvement is required. The precondition is that the runtime configures `T::Fungibles` with an asset backend whose `transfer` can legitimately return `actual < requested` (e.g. `pallet-assets` under `BestEffort`/dust-related paths, or any foreign/bridged asset representation with transfer-fee-like semantics), which the PSM's own documentation anticipates by design (it is explicitly built to host arbitrary "third-party assets" such as USDC/USDT). No governance misconfiguration is needed to trigger the mismatch — it is a structural flaw in how `mint`/`redeem` ignore the trait's actual-amount return value.

### Recommendation
Use the `Result<Balance, DispatchError>` actually returned by `T::Fungibles::transfer` (and by `burn_from`/`mint_into`) as the source of truth for `internal_to_user` (mint side) and for the `PsmDebt` decrement / burned amount (redeem side), rather than pre-transfer computed values. Bind the returned actual amount, e.g.:
```rust
let actual_external = T::Fungibles::transfer(
    external_asset.clone(), &who, &psm_account, effective_external, Preservation::Expendable,
)?;
ensure!(actual_external == effective_external, Error::<T>::Unexpected);
```
or, if partial transfers must be tolerated, recompute `internal_to_user`/fee from `actual_external` instead of `effective_external`. Apply the same correction symmetrically in `redeem` for the external payout and reserve/debt accounting.

### Proof of Concept
Conceptual PoC (backend-dependent, cannot be fully driven purely from `pallet-psm`'s own default mock which uses a non-fee-bearing test asset):
1. Configure a runtime where `T::Fungibles` for an approved external asset is a foreign/bridged asset representation whose transfer implementation can return `actual < amount` (e.g. an asset registered with a nonzero `min_balance`/dust-losing path in `pallet-assets`, or any custom `fungibles::Mutate` impl modeling a fee-on-transfer token).
2. Call `Psm::mint(origin, internal_asset, external_asset, external_amount, max_fee)`.
3. Observe: `psm_account`'s external asset balance increases by `actual_external < effective_external`, but `internal_to_user` minted to the caller is still computed from `effective_external`/`internal_equivalent` (the requested amount), and `PsmDebt` is incremented by the full `internal_equivalent` — over-crediting the user relative to the reserve's actual backing.
4. Repeat `redeem` calls will similarly show `PsmDebt` decremented by more than what actually leaves the reserve if the outgoing transfer under-delivers, since the code never inspects the value returned by `T::Fungibles::transfer` on line `substrate/frame/psm/src/lib.rs:880-886`. 			external_asset: T::AssetId,
			internal_amount: BalanceOf<T>,
			max_fee: Permill,
		) -> DispatchResult {
			let who = ensure_signed(origin)?;

			let external = ExternalAssets::<T>::get(&internal_asset, &external_asset)
				.ok_or(Error::<T>::UnsupportedAsset)?;
			ensure!(external.status.allows_redemption(), Error::<T>::AllSwapsStopped);

			let ext_decimals = external.decimals;
			let internal_decimals = info.internal_decimals;

			ensure!(internal_amount >= info.min_swap_amount, Error::<T>::BelowMinimumSwap);

			let fee_rate = RedemptionFee::<T>::get(&internal_asset, &external_asset);
			ensure!(fee_rate <= max_fee, Error::<T>::FeeTooHigh);
			let fee = fee_rate.mul_ceil(internal_amount);
			let internal_net = internal_amount.saturating_sub(fee);

			let external_out =
				Self::internal_to_external(internal_net, ext_decimals, internal_decimals)?;
			ensure!(
				internal_net.is_zero() || !external_out.is_zero(),
				Error::<T>::AmountTooSmallAfterConversion
			);
			// `effective_internal_net` is the internal value that round-trips to `external_out`;
			// it is what we actually burn and what the tracked debt decreases by. Any truncation
			// dust stays in the caller's internal balance, symmetric with `mint`, which takes
			// only the round-tripped share of the external amount.
			let effective_internal_net =
				Self::external_to_internal(external_out, ext_decimals, internal_decimals)?;

			let current_debt = PsmDebt::<T>::get(&internal_asset, &external_asset);
			ensure!(current_debt >= effective_internal_net, Error::<T>::InsufficientReserve);

			let reserve = Self::get_reserve(&internal_asset, &external_asset);
			if reserve < external_out {
				defensive!("PSM reserve is less than expected output amount");
				return Err(Error::<T>::Unexpected.into());
			}

			if !fee.is_zero() {
				T::Fungibles::transfer(
					internal_asset.clone(),
					&who,
					&info.fee_destination,
					fee,
					Preservation::Expendable,
				)?;
			}

			if !effective_internal_net.is_zero() {
				T::Fungibles::burn_from(
					internal_asset.clone(),
					&who,
					effective_internal_net,
					Preservation::Expendable,
					Precision::Exact,
					Fortitude::Polite,
				)?;
			}

			let psm_account = Self::psm_account(&internal_asset);
			if !external_out.is_zero() {
				T::Fungibles::transfer(
					external_asset.clone(),
					&psm_account,
					&who,
					external_out,
					Preservation::Expendable,
				)?;
			}

			PsmDebt::<T>::mutate(&internal_asset, &external_asset, |debt| {
				*debt = debt.saturating_sub(effective_internal_net);
			});

			Self::deposit_event(Event::Redeemed {
				who,
				internal_asset,
				external_asset,
				internal_consumed: effective_internal_net.saturating_add(fee),
				external_received: external_out,
				internal_fee: fee,
			});
			Ok(())
		}

	/// Transfer funds from one account into another.
	///
	/// A transfer where the source and destination account are identical is treated as No-OP after
	/// checking the preconditions.
	fn transfer(
		asset: Self::AssetId,
		source: &AccountId,
		dest: &AccountId,
		amount: Self::Balance,
		preservation: Preservation,
	) -> Result<Self::Balance, DispatchError> {
		let _extra = Self::can_withdraw(asset.clone(), source, amount)
			.into_result(preservation != Expendable)?;
		Self::can_deposit(asset.clone(), dest, amount, Extant).into_result()?;
		if source == dest {
			return Ok(amount);
		}

		Self::decrease_balance(asset.clone(), source, amount, BestEffort, preservation, Polite)?;
		// This should never fail as we checked `can_deposit` earlier. But we do a best-effort
		// anyway.
		let _ = Self::increase_balance(asset.clone(), dest, amount, BestEffort);
		Self::done_transfer(asset, source, dest, amount);
		Ok(amount)
	}
