Target: `Nonces::commit` ordering bug in contracts/wallet/src/nonces.rs, invoked from `WalletImpl::execute_signed`. Attacker action: submit `w_execute_signed(msg, invalid_proof)` with a `nonce` value matching one the legitimate signer intends to use later, where `proof` is garbage (fails verification). Preconditions: attacker knows/guesses the next `nonce` the legitimate relayer will submit for the victim wallet. Call sequence: `execute_signed` calls `self.0.nonces.commit(...)` BEFORE `S::verify_request_msg(...)`, so the nonce bit is set even though the call later returns `Error::InvalidSignature`. Binding: a nonce is committed (`Nonces::commit` returns Ok) == a validly signed message consumed it; here the nonce is consumed by an unsigned/invalid request. Impact: Critical, this blocks the real signer's legitimately signed request using that nonce from ever being able to execute (frozen wallet action / permanently unrecoverable specific-nonce action), since `old.get_bit || current.set_bit` will reject the legitimate later commit as `AlreadyUsed`. Proof idea: cargo test calling `w_execute_signed` with bad proof and nonce N, then replaying the legitimately signed msg with nonce N, assert it now fails with `AlreadyUsed` despite never having succeeded.
