# [M] M-05 | Enforced Options Not Applied On releaseOnEid

## Summary
Severity: Medium
Contest weight: 0.0426
Dataset id: 1989
Source: https://huggingface.co/datasets/Zaevlad/audit-findings-dataset
Type: audit-finding

## Details
The vulnerability resides in the releaseOnEid function of the contract that forwards cross‑chain messages via the internal _lzSend call. The function accepts a set of user‑provided messaging options, but it fails to merge those options with the protocol‑enforced options by calling the combineOptions helper. As a result, the mandatory options that the LayerZero endpoint requires for a send‑type message – such as gas limits, payment enforcement, or reliability flags – are never attached to the outbound packet. The root cause is a missing combineOptions invocation, which means the caller’s raw options are passed directly to _lzSend, effectively overriding any safety defaults that the contract intended to enforce. An attacker who can influence the options argument (for example by calling releaseOnEid through a malicious contract) can supply a crafted option set that disables gas budgeting or removes verification flags, allowing the message to be sent with insufficient resources or without required security checks. This can be exploited to cause the cross‑chain transfer to fail silently, to trigger a denial‑of‑service on the destination chain, or in worst cases to manipulate the message payload because the enforced integrity checks are bypassed. From a user’s perspective the symptom is that a transaction appears to succeed on the source chain but the expected asset (NFT, token, or state update) never appears on the destination chain, or the user receives an empty or zero‑value response. The issue occurs every time releaseOnEid is invoked, i.e., whenever a user attempts to release a token on a remote chain, and only when the caller can control the options parameter. All participants that rely on the contract’s cross‑chain functionality – token holders, marketplace operators, and the broader protocol – are affected because the reliability and accounting guarantees of the messaging layer are compromised. The flaw was discovered during a manual security audit that inspected the flow of options through the LayerZero integration and noticed that the combineOptions step was omitted. It is hard to notice because the function still compiles and the transaction does not revert; the missing options are invisible in the transaction receipt, and the failure only manifests as missing assets on the remote chain. To remediate the issue the releaseOnEid implementation should invoke combineOptions with the contract’s enforced options and the caller‑provided options before passing the result to _lzSend, thereby guaranteeing that all mandatory messaging parameters are present regardless of user input. This class of bug is a typical “option enforcement bypass” where user‑controlled configuration overrides required security settings, leading to accounting inconsistencies and potential loss of funds.

## Recommendation
Apply combineOptions to the user provided options in the releaseOnEid function.
