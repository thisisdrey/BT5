### Title
Oracle price staleness is undetectable by downstream consumers because `DataProvider::get` discards the timestamp and `DefaultCombineData` falls back to an unbounded-age `prev_value` when fresh submissions are unavailable - ([File: substrate/frame/honzon/oracle/src/lib.rs])

### Summary
`pallet-oracle`'s `DefaultCombineData::combine_data` filters out raw operator submissions older than `ExpiresIn`, but when too few fresh submissions remain it silently falls back to returning the *previous* aggregated value with no age check at all, and that stale value is written back into `Values` storage. Any consumer using the standard `DataProvider::get(key)` interface receives only the bare `OracleValue` — the timestamp is stripped — so it has no way to detect or reject staleness on its own. This is the direct on-chain analog of the reported `getOraclePrice`/`getCollateralExchangeInfo` issue: price data is consumed without verifying freshness against any threshold.

### Finding Description
`pallet-oracle` stores aggregated data in `Values<T, I>` as `TimestampedValue { value, timestamp }` [1](#0-0)  and computes it via `combined()` → `T::CombineData::combine_data(key, values, Self::values(key))` [2](#0-1) .

The default aggregation strategy, `DefaultCombineData`, retains only raw values whose `timestamp + ExpiresIn > now`, but if fewer than `MinimumCount` values survive (including the `count == 0` case, i.e. *no* operator has submitted fresh data at all), it returns `prev_value` unconditionally, with no check on how old `prev_value.timestamp` actually is: [3](#0-2) 

This means `Values<T,I>[key]` can persist at an arbitrarily stale timestamp indefinitely — if oracle operators stop feeding for any reason (network outage, all operators removed via governance timing, deliberate withholding, chain congestion, etc.), the last known value keeps being echoed back forever with no decay or invalidation.

Critically, the primary integration point exposed to other pallets — `DataProvider::get` — throws away the timestamp entirely: [4](#0-3) 

Any consuming pallet that uses `<Oracle as DataProvider<Key, Value>>::get(key)` (the idiomatic, documented integration pattern per the pallet's own README: "The pallet implements the `DataProvider` and `DataProviderExtended` traits, allowing other pallets to easily consume the oracle data") gets a bare value with zero freshness information and therefore cannot implement a staleness check itself, even if it wanted to. The only APIs that retain the timestamp are `get_value`/`all_values` view functions and `DataProviderExtended::get_all_values`, but consuming pallets are not required to use these, and the pallet provides no built-in enforcement (no error, no `None`, no event) when the aggregated value has silently gone stale.

Existing guards do not stop this path:
- `ExpiresIn` only filters *raw per-operator* submissions before aggregation; it never bounds the age of the *aggregated* `Values` entry that downstream code actually reads.
- `MinimumCount` only guards how many fresh submissions are needed to produce a *new* aggregate; it does not prevent an old aggregate from continuing to be served.
- There is no on-chain expiry/eviction of `Values<T,I>` entries themselves.

### Impact Explanation
Any runtime pallet wired to consume `pallet-oracle` price/rate data via the standard `DataProvider` trait (e.g. collateral valuation, liquidation triggers, swap pricing, risk calculations) can be driven off arbitrarily stale prices without any means to detect it, because the interface it is designed to consume strips exactly the information needed to make that determination. This can lead to financial decisions (mint/redeem/liquidation/valuation) executing against out-of-date market data — the same class of impact identified in the external report (Medium impact/likelihood: reliance on outdated price data in financial calculations).

### Likelihood Explanation
Likelihood is Medium: it requires no malicious actor, admin abuse, or governance action — it only requires oracle operators to stop submitting fresh data (an operational/liveness condition, e.g. off-chain feeder downtime, network partition, or an operator set that temporarily drops below `MinimumCount`), which is a realistic and unprivileged condition to occur naturally on a live chain.

### Recommendation
- Bound the age of `prev_value` in `DefaultCombineData::combine_data`: if `prev_value.timestamp + ExpiresIn <= now`, return `None` instead of echoing back a stale aggregate.
- Extend `DataProvider::get` (or add a freshness-aware variant) so consumers can access or enforce a timestamp check, rather than only exposing the raw value with no age information.
- Consider exposing a pallet-level `Error`/event when an aggregate exists but has exceeded `ExpiresIn`, so integrators are not silently served indefinitely-stale data.

### Proof of Concept
1. Configure `Oracle` with `DefaultCombineData<T, MinimumCount=3, ExpiresIn=3600>` as in the reference runtime wiring: [5](#0-4) .
2. Three operators feed a price at t=0 via `feed_values`, producing an aggregated `Values[key] = TimestampedValue { value: P, timestamp: 0 }` [6](#0-5) .
3. All operators go offline (or are removed) and never feed again.
4. At any later time `t >> 3600` (well past `ExpiresIn`), a consumer pallet calls `<Oracle as DataProvider<u32,u128>>::get(&key)`. Internally `combined()` retrieves `read_raw_values` (now empty/expired), calls `combine_data` with `values=[]`, `prev_value=Some(TimestampedValue{P,0})`; since `count == 0`, `combine_data` returns `prev_value` unchanged [7](#0-6) , which gets written back into `Values` via `<Values<T,I>>::insert(key, combined)` whenever `feed_values`/`feed_value` is invoked by anyone (or simply remains in storage untouched since last write).
5. The consumer receives `Some(P)` via `DataProvider::get` with no indication that this price is arbitrarily stale, and proceeds to use it in a financial calculation.

	fn combine_data(
		_key: &<T as Config<I>>::OracleKey,
		mut values: Vec<TimestampedValueOf<T, I>>,
		prev_value: Option<TimestampedValueOf<T, I>>,
	) -> Option<TimestampedValueOf<T, I>> {
		let expires_in = ExpiresIn::get();
		let now = T::Time::now();

		values.retain(|x| x.timestamp.saturating_add(expires_in) > now);

		let count = values.len() as u32;
		let minimum_count = MinimumCount::get();
		if count < minimum_count || count == 0 {
			return prev_value;
		}
