## Analysis

The `GlmRouter.requestDeposit` bug is fundamentally: **treating a raw amount of a nominally-pegged asset as if it always equals its face USD value**, without an oracle/price check, when computing thresholds/percentages that gate protocol behavior.

The direct local analog is `pallet-psm` (Peg Stability Module), which performs 1:1 swaps between an internal stablecoin and external assets (USDC, USDT, DAI, etc.) using only **decimal scaling**, with no price oracle at all.

### Title
Peg Stability Module (`pallet-psm`) mints internal stablecoin 1:1 against external assets using only decimal conversion, with no real-value/price check - (File: `substrate/frame/psm/src/lib.rs`)

### Summary
`Pallet::mint` and `Pallet::redeem` in `pallet-psm` convert between an "internal" stablecoin and approved "external" assets (e.g. USDC, USDT, DAI) purely via `external_to_internal`/`internal_to_external`, which only rescale for decimal differences [1](#0-0) . There is no conversion-rate or oracle input analogous to the report's recommended "calculate the USDC value before calculating the deposit percentage" — the pallet assumes 1 unit of external asset is always worth exactly 1 unit of internal asset (adjusted only for decimals), the same raw-amount-as-value assumption flagged in the external report.

### Finding Description
`mint()` computes `internal_equivalent` from the raw `external_amount` using only `Self::external_to_internal`, which scales by `10^(ext_decimals - internal_decimals)` and nothing else [2](#0-1) . This `internal_equivalent` is then used directly to:
- Check the aggregate `max_debt` ceiling: `current_total_psm_debt.saturating_add(internal_equivalent) <= info.max_debt` [3](#0-2) 
- Check the per-external normalized ceiling derived from `AssetCeilingWeight` [4](#0-3) [5](#0-4) 
- Mint the internal asset 1:1 (minus fee) to the user [6](#0-5) 

At no point is any current market price of the external asset consulted — exactly the pattern in the report, where `_amount` is used to gate percentage-based logic without checking whether the token is actually worth $1. The pallet's own README acknowledges the consequence: *"With 0.5% fees on both sides, arbitrage opportunities exist when the internal asset trades outside $0.995-$1.005."* — but this framing only covers the **internal** asset's price; it does not address the case where an **external** asset itself depegs below $1 (as USDC did to $0.8774 in March 2023, the exact scenario cited in the report). If an external asset depegs downward, users can deposit devalued tokens and mint full 1:1 internal stablecoin, directly monetizing the discrepancy and reducing the effective backing ratio of the PSM's reserve.

Existing guards do not stop this path:
- `ensure_decimals_match` only checks decimal metadata consistency, not price [7](#0-6) .
- Debt ceilings (`max_debt`, `AssetCeilingWeight`) are governance-configured caps on volume, not price-sensitive circuit breakers; they permit minting up to the ceiling regardless of the external asset's real market value.
- The circuit breaker (`AllEnabled`/`MintingDisabled`/`AllDisabled`) only helps if an admin manually reacts to a depeg event before it happens or during the window before detection — an unprivileged caller can act as soon as the price departs from $1 and before any admin intervention.

### Impact Explanation
If an approved external asset depegs below $1, unprivileged users can mint internal stablecoin backed at less than 1:1, extracting value from the PSM reserve at the expense of the internal-stablecoin's global backing/peg — a genuine unbacked-mint condition matching the "theft or unbacked mint" impact category. Because internal-asset holders redeem 1:1 against the (now under-collateralized) reserve, later redeemers bear the shortfall, i.e., value is not conserved across the PSM's mint/redeem cycle.

### Likelihood Explanation
Likelihood is Medium, mirroring the original report's rating: it requires a real-world price deviation of an approved external stablecoin (a market event, not an on-chain compromise of any actor), after which any unprivileged signed account can immediately exploit the mispricing via the public `mint` extrinsic before governance intervenes with the circuit breaker.

### Recommendation
Introduce a price/value check (e.g., integrate with `pallet-asset-rate`'s `ConversionFromAssetBalance`/`ConversionToAssetBalance` traits [8](#0-7) , or an oracle) before computing `internal_equivalent` in `mint`, so that debt-ceiling checks and minted amounts reflect the external asset's real value rather than assuming a hardcoded 1:1 peg adjusted only for decimals.

### Proof of Concept
1. PSM instance configured with `internal_asset` and external `USDC_ASSET_ID` approved at some `AssetCeilingWeight` and `max_debt`.
2. External market price of USDC drops to $0.8774 (as happened in March 2023).
3. Attacker calls `Psm::mint(origin, internal_asset, USDC_ASSET_ID, 1_000_000 * USDC_UNIT, max_fee)`.
4. `external_to_internal` converts the raw `1_000_000` units 1:1 (decimals-adjusted only) to `internal_equivalent = 1_000_000` internal units, ignoring that the real USD value deposited is only ~$877,400 [9](#0-8) .
5. `mint` proceeds, crediting the attacker with internal stablecoin minus the small fixed fee, fully backed on paper but under-collateralized in real value [6](#0-5) .
6. Attacker immediately redeems or sells the internal stablecoin at its full peg value elsewhere, realizing the ~12% arbitrage extracted from the PSM reserve/other holders.

		/// Convert an amount denominated in external-asset units into internal units.
		///
		/// Scales by `10^(ext_decimals - internal_decimals)` — multiplies up when internal has more
		/// decimals, floor-divides when it has fewer. Returns [`Error::ConversionOverflow`] if
		/// the scaling factor or the product does not fit in the balance type.
		pub(crate) fn external_to_internal(
			amount: BalanceOf<T>,
			ext_decimals: u8,
			internal_decimals: u8,
		) -> Result<BalanceOf<T>, Error<T>> {
			use core::cmp::Ordering::*;
			match ext_decimals.cmp(&internal_decimals) {
				Equal => Ok(amount),
				Less => {
					let diff = (internal_decimals - ext_decimals) as u32;
					let factor = Self::pow10(diff)?;
					amount.checked_mul(&factor).ok_or(Error::<T>::ConversionOverflow)
				},
				Greater => {
					let diff = (ext_decimals - internal_decimals) as u32;
					let factor = Self::pow10(diff)?;
					Ok(amount.checked_div(&factor).unwrap_or_else(BalanceOf::<T>::zero))
				},
			}
		}

/// Exposes conversion of an arbitrary balance of an asset to native balance.
impl<T> ConversionFromAssetBalance<BalanceOf<T>, AssetKindOf<T>, BalanceOf<T>> for Pallet<T>
where
	T: Config,
{
	type Error = pallet::Error<T>;

	fn from_asset_balance(
		balance: BalanceOf<T>,
		asset_kind: AssetKindOf<T>,
	) -> Result<BalanceOf<T>, pallet::Error<T>> {
		let rate = pallet::ConversionRateToNative::<T>::get(asset_kind)
			.ok_or(pallet::Error::<T>::UnknownAssetKind.into())?;
		Ok(rate.saturating_mul_int(balance))
	}
	/// Set a conversion rate to `1` for the `asset_id`.
	#[cfg(feature = "runtime-benchmarks")]
	fn ensure_successful(asset_id: AssetKindOf<T>) {
		pallet::ConversionRateToNative::<T>::set(asset_id.clone(), Some(1.into()));
	}
}
