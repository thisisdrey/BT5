## Analysis

The Sherlock report's core broken invariant is: **a protocol treats multiple stable assets as interchangeable at a fixed 1:1 value, with no oracle checking real market price, allowing a user to deposit a de-pegged (cheap) collateral and withdraw value denominated in a non-de-pegged asset, at the expense of other depositors.**

The closest verifiable local analog is the new **`pallet-psm`** (Peg Stability Module) at `substrate/frame/psm/src/lib.rs`. This pallet is architecturally identical to the reported flaw: it lets users `mint` internal stablecoin by depositing any approved *external* asset (e.g. USDC or USDT) and `redeem` that internal stablecoin for **any other approved external asset in the same PSM instance**, always at a fixed 1:1 rate adjusted only for decimals — never for actual market price.

### Title
Peg Stability Module treats all approved external assets as interchangeable 1:1 collateral, enabling value extraction across a de-peg - (File: substrate/frame/psm/src/lib.rs)

### Summary
`pallet_psm::mint` and `pallet_psm::redeem` convert between the internal stablecoin and any approved external asset using only a decimals-scaling conversion (`external_to_internal` / `internal_to_external`), with no price oracle or per-asset valuation check. [1](#0-0)  Debt is tracked per `(internal_asset, external_asset)` pair but redemption is not restricted to the same external asset that was used to mint, and no mechanism verifies that different externals in the same PSM instance retain equal real-world value. This mirrors exactly the reported issue's broken invariant: value is priced as if a stablecoin is permanently worth exactly 1 unit of the reference asset, ignoring de-pegs.

### Finding Description
`mint()` deposits `external_amount` of an approved external asset and mints `internal_equivalent` (converted purely by decimal-place scaling, not price) of the internal asset to the caller, minus a fee. [2](#0-1)  `redeem()` burns internal asset and pays out **any other approved external asset** on the same PSM instance, again using pure decimal conversion with no valuation check, drawing from the shared reserve/debt accounting of that instance. [3](#0-2) 

Both externals share the same instance-level `max_debt` ceiling and independent per-`(internal, external)` `PsmDebt`/reserve accounting, but nothing prevents a user from minting with a depegged asset and redeeming a fully-pegged one:

- A user deposits `external_amount` of external asset **A** (currently trading at, say, $0.90 on the open market due to a de-peg) and mints `internal_equivalent` of internal asset at the protocol's assumed 1:1 rate. [4](#0-3) 
- The same user (or any user holding that internal asset) then calls `redeem()` targeting external asset **B** (still at $1.00), which pays out from **B**'s own reserve/debt bucket at the same fixed 1:1 rate. [5](#0-4) 
- The attacker effectively converted $0.90 of real value (asset A) into $1.00 of real value (asset B, or the internal asset itself), extracting the difference from asset B's depositors/redeemers, who now find B's reserve depleted relative to the internal-asset debt it's supposed to back.

This is the same corrupted value as in the Sherlock report — the "vault value" (here, the fungible internal-asset debt across externals) is computed using a fixed peg assumption instead of the true relative value of the underlying collateral. Existing guards (`max_debt`, `AssetCeilingWeight`, per-external `PsmDebt`, circuit breaker) only bound *volume*, not *price*; none of them detect or block a price divergence between two approved externals of the same PSM instance. The README itself acknowledges the underlying assumption is only safe within a narrow band ("$0.995–$1.005") but does not enforce it on-chain. [6](#0-5) 

### Impact Explanation
Any user can call the fully public, unprivileged `mint`/`redeem` extrinsics to systematically drain the reserve of a still-pegged external asset by first minting internal stablecoin against a de-pegged external asset at fictitious par. This directly causes **fund loss for the fee_destination/other holders backed by the non-depegged asset**, and can make the internal stablecoin under-collateralized as a whole, since `PsmDebt` no longer reflects the true value of assets actually held in the corresponding reserve. This falls under the accepted impact categories of "theft or unbacked mint" and "runtime bugs that compromise intended behavior."

### Likelihood Explanation
No privileged actor, oracle manipulation, or governance action is required — an ordinary de-peg event on any widely used stablecoin (USDT/USDC-style) combined with two calls to already-public extrinsics (`mint`, `redeem`) is sufficient. This requires only that a PSM instance has two or more approved external assets (a normal, documented configuration per the README's "50%/50% (USDC/USDT)" example). [7](#0-6) 

### Recommendation
Do not treat externals in the same PSM instance as fungible for redemption purposes based purely on decimals. Either:
1. Restrict `redeem()` to only pay out the same external asset that backs the caller's specific debt (tag debt/claims by originating external asset), or
2. Integrate a live price oracle per external asset and require its price to be within a governance-configured band of the peg before allowing cross-asset mint/redeem, halting via the circuit breaker automatically if the band is breached, similar to `pallet-oracle`'s `DataProvider` already present in the codebase. [8](#0-7) 

### Proof of Concept
1. Governance creates a PSM instance for internal asset `I` and approves externals `A` (e.g. USDC) and `B` (e.g. USDT), each with non-zero `AssetCeilingWeight` and default 0.5% fees, per `create_psm`/`add_external_asset`/`set_asset_ceiling_weight`. [9](#0-8) 
2. Asset `A` de-pegs to $0.90 on secondary markets (e.g. Uniswap/CEX), while `B` remains at $1.00 (this is off-chain market data — the PSM has no way to know or react to it).
3. Attacker acquires a large quantity of de-pegged `A` cheaply on the open market, then calls `Psm::mint(origin, I, A, external_amount, max_fee)`, receiving `internal_equivalent` of internal asset `I` at the protocol's fixed 1:1 (decimals-only) rate. [2](#0-1) 
4. Attacker calls `Psm::redeem(origin, I, B, internal_amount, max_fee)`, burning `I` and receiving external asset `B` from `B`'s reserve, again at the fixed 1:1 rate. [3](#0-2) 
5. The attacker now holds `B` (real value ~$1.00 per unit) obtained in exchange for `A` (real value ~$0.90 per unit) minus ~1% total fees, netting real profit extracted from `B`'s reserve — at the expense of other holders/redeemers of `B`-backed debt.

**Uncertainty note:** I was not able to fully read the remainder of `substrate/frame/psm/src/lib.rs` (file was truncated at 1000 of 1745 lines) or the governance/removal paths (`remove_external_asset`, `set_asset_ceiling_weight`, etc.), so I cannot rule out an unread mitigating check further down in the file (e.g. a possible price-band enforcement I have not seen). I recommend that whoever picks this up read the full file, including `benchmarking.rs` and `tests.rs`, to confirm no oracle/price check exists elsewhere in the pallet before treating this as fully confirmed.

		pub fn redeem(
			origin: OriginFor<T>,
			internal_asset: T::AssetId,
			external_asset: T::AssetId,
			internal_amount: BalanceOf<T>,
			max_fee: Permill,
		) -> DispatchResult {
			let who = ensure_signed(origin)?;
			let info = Psm::<T>::get(&internal_asset).ok_or(Error::<T>::PsmNotFound)?;

			let external = ExternalAssets::<T>::get(&internal_asset, &external_asset)
				.ok_or(Error::<T>::UnsupportedAsset)?;
			ensure!(external.status.allows_redemption(), Error::<T>::AllSwapsStopped);

			let ext_decimals = external.decimals;
			let internal_decimals = info.internal_decimals;

			ensure!(internal_amount >= info.min_swap_amount, Error::<T>::BelowMinimumSwap);

			let fee_rate = RedemptionFee::<T>::get(&internal_asset, &external_asset);
			ensure!(fee_rate <= max_fee, Error::<T>::FeeTooHigh);
			let fee = fee_rate.mul_ceil(internal_amount);
			let internal_net = internal_amount.saturating_sub(fee);

			let external_out =
				Self::internal_to_external(internal_net, ext_decimals, internal_decimals)?;
			ensure!(
				internal_net.is_zero() || !external_out.is_zero(),
				Error::<T>::AmountTooSmallAfterConversion
			);
			// `effective_internal_net` is the internal value that round-trips to `external_out`;
			// it is what we actually burn and what the tracked debt decreases by. Any truncation
			// dust stays in the caller's internal balance, symmetric with `mint`, which takes
			// only the round-tripped share of the external amount.
			let effective_internal_net =
				Self::external_to_internal(external_out, ext_decimals, internal_decimals)?;

			let current_debt = PsmDebt::<T>::get(&internal_asset, &external_asset);
			ensure!(current_debt >= effective_internal_net, Error::<T>::InsufficientReserve);

			let reserve = Self::get_reserve(&internal_asset, &external_asset);
			if reserve < external_out {
				defensive!("PSM reserve is less than expected output amount");
				return Err(Error::<T>::Unexpected.into());
			}

			if !fee.is_zero() {
				T::Fungibles::transfer(
					internal_asset.clone(),
					&who,
					&info.fee_destination,
					fee,
					Preservation::Expendable,
				)?;
			}

			if !effective_internal_net.is_zero() {
				T::Fungibles::burn_from(
					internal_asset.clone(),
					&who,
					effective_internal_net,
					Preservation::Expendable,
					Precision::Exact,
					Fortitude::Polite,
				)?;
			}

			let psm_account = Self::psm_account(&internal_asset);
			if !external_out.is_zero() {
				T::Fungibles::transfer(
					external_asset.clone(),
					&psm_account,
					&who,
					external_out,
					Preservation::Expendable,
				)?;
			}

			PsmDebt::<T>::mutate(&internal_asset, &external_asset, |debt| {
				*debt = debt.saturating_sub(effective_internal_net);
			});

			Self::deposit_event(Event::Redeemed {
				who,
				internal_asset,
				external_asset,
				internal_consumed: effective_internal_net.saturating_add(fee),
				external_received: external_out,
				internal_fee: fee,
			});
			Ok(())
		}
