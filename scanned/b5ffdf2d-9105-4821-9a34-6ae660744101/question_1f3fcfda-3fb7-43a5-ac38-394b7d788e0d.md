Across postblock_v3.rs, blocksimulate.rs, blockreplay.rs, txsimulate.rs, and postblock_proposal.rs, the auth-header lookup is always `preamble.headers.get("authorization")` against a `BTreeMap<String, String>` populated during HTTP preamble parsing (stackslib/src/net/http/request.rs). If an attacker sends TWO `Authorization:` header lines with different values (header injection/duplication), does the preamble parser's insertion into the BTreeMap silently overwrite the first with the second (last-wins), or does it error/concatenate -- and if last-wins, can an attacker send `Authorization: <wrong>` followed by `Authorization: <correct password>` (or vice versa) to control which value the auth-gated handler sees versus what a downstream logging/audit consumer of the same preamble might see if it iterates headers differently? Equality: the `authorization` value the auth-gate branch compares == the value any other consumer of `preamble.headers` observes; must be identical, not order-dependent. Impact: Critical auth bypass / request smuggling via duplicate header injection. Proof idea: net test crafting a raw HTTP request with two `Authorization` header lines, parsing via `http.read_preamble`, and asserting `preamble.headers.get("authorization")` returns a single deterministic value, then asserting handler auth-gate uses the same value.
