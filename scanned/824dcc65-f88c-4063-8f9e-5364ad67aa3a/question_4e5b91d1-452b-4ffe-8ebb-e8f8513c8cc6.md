Target: Deltas::notify_on_transfer passthrough (contracts/defuse/core/src/engine/state/deltas.rs) tied to intents::tokens::NotifyOnTransfer, reachable from a signed intent inside a MultiPayload. Attacker action: attacker signs an intent that both debits their own balance and issues NotifyOnTransfer to a contract they deploy, where that contract's ft_on_transfer-style callback returns a used/unused amount value chosen adversarially, then observes whether the *_resolve_* callback re-credits based on the attacker-controlled return value without cross-checking it against the amount actually deducted from token_balances at debit time. Preconditions: attacker deploys a receiver implementing the notify interface. Call sequence: signed intent -> internal_sub_balance debits attacker (recorded in TransferMatcher) -> notify_on_transfer fires a promise to attacker's contract -> resolver credits back 'unused' amount reported by the attacker's contract's return value. Binding: value debited from attacker's token_balances at intent-execution time == value delivered to the notified receiver's accounting + value re-credited by the resolver based on the receiver's returned unused amount, with the returned unused amount itself bounded by <= value debited. Impact: Critical, if the resolver trusts an attacker-returned 'unused' figure exceeding the original debit, the resolver mints unbacked balance (SETTLEMENT violation, ledger owes more than custodied). Proof: near-workspaces sandbox test where the attacker's receiver contract returns an 'unused' amount larger than what was transferred to it, asserting the resolver clamps the re-credit to <= amount debited and never exceeds it.
