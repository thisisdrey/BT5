### Title
`pallet-psm` treats all approved external stablecoins as permanently worth exactly 1:1 with the internal stablecoin, with no price oracle validation, allowing minting against a depegged asset - ([File: substrate/frame/psm/src/lib.rs])

### Summary
`pallet-psm` implements Peg Stability Module swaps that convert between an "internal" stablecoin and approved "external" stablecoins using only a **decimal-precision** conversion (`external_to_internal` / `internal_to_external`), never a market price. The pallet hard-codes the assumption that 1 unit of any approved external asset is worth exactly 1 unit of the internal asset, adjusted only for decimals — the same class of flaw as the reported RAACNFT bug, which assumed `crvUSD == 1 USD` with no oracle to catch a depeg.

### Finding Description
In `mint`, the external amount deposited by the caller is converted to an "internal equivalent" purely via decimal rescaling: [1](#0-0) 

No component of `mint` or `redeem` queries a price feed or oracle for the real market value of `external_asset` relative to `internal_asset`; the whole pricing model is `1 external unit == 1 internal unit`, decimals aside, as documented in the pallet's own overview: [2](#0-1) 

The only "market" mechanism in the pallet is the mint/redemption fee spread, which is meant to defend the **internal** asset's own peg to $1, not to protect the reserve against a depeg of an **external** asset: [3](#0-2) 

If any approved external asset (e.g. a USDC/USDT-style token) trades below $1 on the open market — which the linked report shows is a realistic, historically observed event for pegged assets like crvUSD — any unprivileged, signed user can:
1. Buy the depegged external asset cheaply on the open market.
2. Call `mint` to deposit it into the PSM at the pallet's fixed 1:1 (decimal-only) rate and receive full-value internal asset (minus the fixed governance-set fee, unrelated to the depeg size).
3. Immediately `redeem` that internal asset against a *different*, still fully-pegged external asset in the same PSM instance (or sell the internal asset on the open market), extracting the price difference from the PSM's reserve/other external-asset holders.

The pallet's `PsmDebt` and `max_debt` accounting track nominal units of internal asset minted against each external, not real dollar value, so this drains real backing from the reserve while the on-chain debt/ceiling bookkeeping stays "balanced" — mirroring exactly how RAACNFT's `tokenToHousePrice` bookkeeping stays "correct" in USD terms while the actual crvUSD paid diverges from real value.

### Impact Explanation
This directly threatens the accounting invariant "Balances, assets... must conserve value and settle exactly once to the rightful beneficiary and amount." A depeg event in any approved external asset lets an ordinary user mint internal stablecoin backed by devalued collateral and redeem it 1:1 against fully-valued collateral of another external asset (or against the internal asset's own market price), silently under-collateralizing the PSM reserve. Because `add_external_asset` approval is a one-time governance action and depegs are market events that happen *after* approval (not an admin/governance decision at exploit time), the loss path is triggered purely by an unprivileged, signed extrinsic call during a normal market event — not by a malicious admin, governance actor, or privileged party.

### Likelihood Explanation
Likelihood is comparable to the original report: any stablecoin pegged asset can and historically does trade away from exactly $1 (the linked report cites crvUSD's price history as evidence this is common, not rare). Any PSM instance holding more than one external asset, or whose internal asset itself is liquid on secondary markets, is exposed the moment one of its approved externals deviates from peg beyond the fixed fee spread — no special conditions, front-running, or privileged access are required, only monitoring an external stablecoin's price and calling the public `mint`/`redeem` extrinsics.

### Recommendation
Do not treat 1:1 nominal parity between internal and external assets as a hard-coded invariant. Either:
- Bound `mint`/`redeem` conversions by a price oracle for each approved external asset and reject/adjust swaps when the observed price deviates from $1 beyond a safety margin, or
- Track per-external debt against a live valuation rather than nominal units, so a depeg on one external cannot be laundered into full-value internal asset or into another, fully-pegged external asset.

### Proof of Concept
1. Governance creates PSM instance for `internal_asset` with two approved externals, `USDX` and `USDY`, both minting-enabled with 0% weight cap headroom.
2. `USDY` depegs to $0.90 on the open market (a real, observed stablecoin event, as the linked report documents for crvUSD).
3. Attacker buys `100_000` `USDY` for `90_000` USD-equivalent on the open market.
4. Attacker calls:
```rust
Psm::mint(origin, internal_asset, USDY, 100_000, max_fee)
```
using the flow in `mint`: [4](#0-3) 
and receives ~`100_000` (minus 0.5% fee) of `internal_asset`, which is worth `$100_000` in the market's eyes (assuming internal is well-pegged), for an outlay worth only `$90_000`.
5. Attacker calls `Psm::redeem(origin, internal_asset, USDX, internal_amount, max_fee)` to withdraw fully-pegged `USDX` from the same reserve, realizing the ~$10,000 profit extracted directly from the PSM's `USDX` reserve/backing.
6. `PsmDebt` and `max_debt` for both externals remain internally "consistent" (nominal units conserved), masking that the reserve is now under-collateralized relative to real dollar value — the same disconnect between nominal accounting and real value described in the RAACNFT report.

		pub fn mint(
			origin: OriginFor<T>,
			internal_asset: T::AssetId,
			external_asset: T::AssetId,
			external_amount: BalanceOf<T>,
			max_fee: Permill,
		) -> DispatchResult {
			let who = ensure_signed(origin)?;
			let info = Psm::<T>::get(&internal_asset).ok_or(Error::<T>::PsmNotFound)?;

			let external = ExternalAssets::<T>::get(&internal_asset, &external_asset)
				.ok_or(Error::<T>::UnsupportedAsset)?;
			ensure!(external.status.allows_minting(), Error::<T>::MintingStopped);

			let (ext_decimals, internal_decimals) =
				Self::ensure_decimals_match(&info, &internal_asset, &external_asset, &external)?;

			let internal_equivalent =
				Self::external_to_internal(external_amount, ext_decimals, internal_decimals)?;
			ensure!(!internal_equivalent.is_zero(), Error::<T>::AmountTooSmallAfterConversion);
			ensure!(internal_equivalent >= info.min_swap_amount, Error::<T>::BelowMinimumSwap);

			let effective_external =
				Self::internal_to_external(internal_equivalent, ext_decimals, internal_decimals)?;

			let fee_rate = MintingFee::<T>::get(&internal_asset, &external_asset);
			ensure!(fee_rate <= max_fee, Error::<T>::FeeTooHigh);
			let fee = fee_rate.mul_ceil(internal_equivalent);
			let internal_to_user = internal_equivalent.saturating_sub(fee);

			let current_total_psm_debt = Self::total_psm_debt(&internal_asset);
			ensure!(
				current_total_psm_debt.saturating_add(internal_equivalent) <= info.max_debt,
				Error::<T>::ExceedsMaxPsmDebt
			);

			let current_debt = PsmDebt::<T>::get(&internal_asset, &external_asset);
			let max_debt = Self::max_asset_debt(&internal_asset, &external_asset, &info);
			let new_debt = current_debt.saturating_add(internal_equivalent);
			ensure!(new_debt <= max_debt, Error::<T>::ExceedsMaxPsmDebt);

			let psm_account = Self::psm_account(&internal_asset);
			T::Fungibles::transfer(
				external_asset.clone(),
				&who,
				&psm_account,
				effective_external,
				Preservation::Expendable,
			)?;
			T::Fungibles::mint_into(internal_asset.clone(), &who, internal_to_user)?;
			if !fee.is_zero() {
				T::Fungibles::mint_into(internal_asset.clone(), &info.fee_destination, fee)?;
			}
