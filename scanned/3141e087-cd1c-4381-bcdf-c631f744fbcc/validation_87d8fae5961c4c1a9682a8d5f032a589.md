Based on my investigation, I found a genuine local analog to the "hardcoded example constant" bug class, in `pallet_dap`'s issuance curve used by the Asset Hub Westend staking payout pipeline.

### Title
Hardcoded, undocumented `fixed_total_issuance` baseline in `IssuanceCurve::issue` permanently decouples DAP token emission from actual on-chain issuance - (File: cumulus/parachains/runtimes/assets/asset-hub-westend/src/staking.rs)

### Summary
`pallet_dap` mints new tokens every era/drip and distributes them to staker/validator-incentive/treasury pots based on `IssuanceCurve::issue`. In the production Asset Hub Westend wiring, this curve ignores the `_total_issuance` argument entirely and instead multiplies the inflation rate against a hardcoded snapshot constant `fixed_total_issuance: i128 = 5_216_342_402_773_185_773`, exactly mirroring the reported bug class: a constant meant to track a live, changing quantity (total issuance / epoch duration) is instead frozen from a one-time value with no on-chain guarantee it stays valid.

### Finding Description
`IssuanceCurve::issue` at [1](#0-0)  computes:
```
fn issue(_total_issuance: Balance, elapsed_millis: u64) -> Balance {
    const MILLISECONDS_PER_YEAR: u64 = ...;
    let fixed_total_issuance: i128 = 5_216_342_402_773_185_773;
    let fixed_inflation_rate = FixedU128::from_rational(8, 100);
    let yearly_emission = fixed_inflation_rate.saturating_mul_int(fixed_total_issuance);
    let emission = relative_period.saturating_mul_int(yearly_emission);
    emission.saturated_into()
}
```
The function signature takes `_total_issuance: Balance` (the live `T::Currency::total_issuance()` value passed by `pallet_dap::mint_and_distribute` at [2](#0-1)  ) but the parameter is discarded (`_total_issuance`), and a hardcoded snapshot integer is substituted instead. This constant is only valid at the moment it was captured; every subsequent mint/burn/slash on Asset Hub Westend (transfers are irrelevant, but minting via DAP itself, slashing burns via `Dap` as `Slash`/`OnSlash`, treasury burns, etc.) changes `total_issuance` while the 8% inflation baseline used for emission stays pinned to the stale snapshot forever. There is no on-chain doc, migration, or governance-bound source of truth for `fixed_total_issuance`; it is a literal comment-level assumption ("Fixed total TI that we use as baseline") exactly analogous to the reported `EPOCH_SECONDS` constant that is "based on an example and not the official documentation" with "no guarantee it will remain the same."

Compounding this: `pallet_staking_async::Config::EraPayout = ()` for this runtime (line 294 in staking.rs) — inflation logic has been fully migrated to DAP, so this stale constant is the *sole* source of protocol issuance, not a secondary fallback.

### Impact Explanation
Because token issuance/emission for staking rewards, validator incentives, and the treasury pot permanently derives from a stale, hardcoded issuance snapshot rather than the real, evolving `total_issuance`, the effective inflation rate silently diverges from the intended "8% of total issuance per year" economic policy as issuance grows or shrinks. Over time this either under-mints (starving staker/validator rewards, which can affect security-budget economics and validator incentive alignment) or over-mints relative to intended tokenomics documented as "8% of current supply." This is a runtime bug that compromises intended behavior (mis-priced/mis-scaled reward emission), falling within the "Polkadot SDK Pivots" category of balances/staking/treasury payout state that must reflect the documented invariant, though it does not by itself allow theft, forged proofs, or origin escalation — its severity is bounded to economic/inflation drift rather than a directly exploitable fund-theft primitive.

### Likelihood Explanation
This triggers automatically and continuously — no attacker action is required. Every DAP drip (`on_initialize` → `drip_issuance` → `mint_and_distribute`, gated only by `IssuanceCadence`/`MaxElapsedPerDrip` at [3](#0-2) ) uses this frozen constant. The divergence from the real supply is guaranteed to grow monotonically as issuance changes, making this a certainty rather than a conditional risk, purely from normal chain operation.

### Recommendation
Remove the hardcoded `fixed_total_issuance` literal and use the `_total_issuance` parameter that `mint_and_distribute` already supplies (i.e., rename it back to `total_issuance` and multiply the 8% rate against the live value). If a fixed baseline is genuinely intended by design (e.g., to decouple emission from supply), that decision and its exact value must be documented as a governance-set, versioned, upgradable parameter (e.g., via `pallet_dap::migrations` or a dedicated storage item) rather than a compile-time literal comment, and covered by an integrity/try-state check similar to `check_budget_allocation`.

### Proof of Concept
1. Deploy/observe Asset Hub Westend runtime as configured in [4](#0-3)  where `pallet_dap::Config::IssuanceCurve = IssuanceCurve`.
2. Let normal chain operation proceed: DAP mints tokens each drip (`mint_and_distribute`), staking slashes route through `Dap` as `OnUnbalanced`/`Slash`, and normal burns (fees, dust, EVM gas rounding per the pallet's own doc comment) occur.
3. Query real `Balances::total_issuance()` at any later block versus the hardcoded `fixed_total_issuance = 5_216_342_402_773_185_773` used inside `IssuanceCurve::issue`.
4. Observe that `IssuanceCurve::issue` computes yearly emission as `8% * 5_216_342_402_773_185_773`, regardless of how far actual total issuance has diverged from that number — confirming the intended "8% of current total issuance" inflation policy is not actually implemented, and instead a permanently stale constant governs reward/treasury minting for the life of the runtime (until code is redeployed).

pub struct IssuanceCurve;
impl sp_staking::budget::IssuanceCurve<Balance> for IssuanceCurve {
	fn issue(_total_issuance: Balance, elapsed_millis: u64) -> Balance {
		const MILLISECONDS_PER_YEAR: u64 = (1000 * 3600 * 24 * 36525) / 100;
		let relative_period =
			FixedU128::from_rational(elapsed_millis.into(), MILLISECONDS_PER_YEAR.into());

		// Fixed total TI that we use as baseline for the issuance.
		let fixed_total_issuance: i128 = 5_216_342_402_773_185_773;
		let fixed_inflation_rate = FixedU128::from_rational(8, 100);
		let yearly_emission = fixed_inflation_rate.saturating_mul_int(fixed_total_issuance);

		let emission = relative_period.saturating_mul_int(yearly_emission);
		emission.saturated_into()
	}
}

		pub(crate) fn drip_issuance() -> Weight {
			let now_moment = T::Time::now();
			let now: u64 = now_moment.saturated_into();
			let last = LastIssuanceTimestamp::<T>::get();
			let mut elapsed = now.saturating_sub(last);

			let cadence = T::IssuanceCadence::get();
			if cadence > 0 && elapsed < cadence {
				return T::DbWeight::get().reads(2);
			}

			// First block after genesis: initialize timestamp, don't drip.
			// For existing chains, use `migrations::MigrateV1ToV2` to seed this
			// value from ActiveEra.start so this branch is never hit post-upgrade.
			if last == 0 {
				LastIssuanceTimestamp::<T>::put(now);
				return T::DbWeight::get().reads_writes(2, 2);
			}

			// Apply safety ceiling on elapsed time.
			let max_elapsed = T::MaxElapsedPerDrip::get();
			if elapsed > max_elapsed {
				Self::deposit_event(Event::Unexpected(UnexpectedKind::ElapsedClamped {
					actual_elapsed: elapsed,
					ceiling: max_elapsed,
				}));
				elapsed = max_elapsed;
			}

			// Always advance the clock so elapsed time doesn't accumulate across skipped drips.
			LastIssuanceTimestamp::<T>::put(now);

			let _ = Self::mint_and_distribute(elapsed);
			T::WeightInfo::drip_issuance()
		}
