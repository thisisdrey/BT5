Target: `Engine::execute_signed_intent` `has_public_key` check timing relative to nonce commit for a RACE where the SAME public key is removed between signing and submission by the account owner itself (not attacker-controlled, but relevant to whether a STALE signature can double-authorize). Attacker (as account owner) signs `MultiPayload` p1 with key K and nonce N, then removes K via `remove_public_key` (their own legitimate action) and adds a NEW key K2, then submits the OLD p1 anyway hoping stale validation lets it through. Precondition: K removed before p1 submitted. Call sequence: `execute_signed_intent` -> `signed.verify()` recovers K from p1's signature -> `has_public_key(signer_id, K)` now `false` -> `Err(PublicKeyNotExist)` before nonce commit. Binding: an intent signed by a key no longer authorized for that `signer_id` settles == 0 times; the `(signer_id, public_key)` pair the engine uses for authorization must equal a pair CURRENTLY registered, not merely one that WAS valid at signing time. Impact: Critical if `has_public_key` check is ever skipped or cached stale, allowing an old signature to move funds after key rotation/removal (would be authorization bypass on a REVOKED key).
