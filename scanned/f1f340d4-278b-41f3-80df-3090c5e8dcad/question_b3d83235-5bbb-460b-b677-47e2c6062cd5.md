`SignerEventReceiver::next_event`'s `/shutdown` handler (libsigner/src/events.rs) sets `stop_signal` to true and returns `Err(EventError::Terminated)` on ANY POST to `/shutdown`, with no body or origin verification (compare to `SignerStopSignaler::send` which POSTs a hardcoded body but the receiver never checks it). Can a remote attacker who can open a TCP connection to the signer's event-receiver port send `POST /shutdown HTTP/1.1` with an empty or arbitrary body to permanently terminate the signer's `main_loop`? Equality broken: origin of the `/shutdown` POST == the signer's own `SignerStopSignaler` instance (no shared token is checked). Impact: Critical - single-message unauthenticated denial-of-service that permanently halts the signer's event processing loop. Proof: Rust test binding `SignerEventReceiver`, sending a raw `POST /shutdown HTTP/1.1\r\nContent-Length: 0\r\n\r\n` from a fresh `TcpStream`, then asserting `next_event` subsequently returns `Err(EventError::Terminated)` and `is_stopped()` is true.
