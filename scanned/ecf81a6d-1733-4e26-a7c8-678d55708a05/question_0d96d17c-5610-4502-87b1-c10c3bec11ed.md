Preconditions: signer's account has a valid public key registered; no salt or deadline is attached to this nonce because it's legacy. Call sequence: `execute_signed_intent` -> `verify_intent_nonce` returns `Ok(())` immediately for legacy nonces (`let Some(nonce) = VersionedNonce::maybe_from(nonce) else { return Ok(()); }`) -> `commit_nonce`. Binding: `the number of times this exact signed payload can ever be replayed == 1, forever`, independent of nonce format — the legacy path enforces this ONLY via `is_used` bitmap, never via salt/expiry. Scoped impact: Critical — because legacy nonces never expire and are per README 'still supported', if the underlying `token_balances` and account are ever cleaned/migrated/re-created (e.g. account entry legacy->versioned upgrade in `MaybeLegacyNonces`), a stale but still-valid signature with a far-future deadline remains replayable exactly once but indefinitely, and cannot be invalidated by the DAO/SaltManager (per `GarbageCollector` cleanup: 'Legacy nonces can't be cleared').
