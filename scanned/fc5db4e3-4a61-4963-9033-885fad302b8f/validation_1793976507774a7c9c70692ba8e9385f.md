### Title
Snowbridge V2 outbound `AliasOrigin` spoofing guard is configured only on bridge-hub-westend, not bridge-hub-rococo - ([File: cumulus/parachains/runtimes/bridge-hubs/bridge-hub-rococo/src/bridge_to_ethereum_config.rs])

### Summary
`snowbridge_outbound_queue_primitives::v2::EthereumBlobExporter` takes a generic `AllowedAliasOrigin: Contains<Location>` parameter that is required to reject `AliasOrigin` XCM instructions that try to spoof the Asset Hub's own sovereign/agent location, per [1](#0-0) . Bridge-hub-westend wires this correctly with `EverythingBut<Equals<AssetHubLocation>>` [2](#0-1) , but bridge-hub-rococo's `bridge_to_ethereum_config.rs` only defines the V1 `EthereumBlobExporter` and has no V2 exporter, no `AllowedAliasOrigin`, and no equivalent filter at all [3](#0-2) .

### Finding Description
The security fix that binds the V2 outbound XCM converter's accepted `AliasOrigin` to "everything except the Asset Hub location" is a config-level, per-runtime parameter, not something enforced centrally in `snowbridge-outbound-queue-primitives`. The library-level `EthereumBlobExporter` in `bridges/snowbridge/primitives/outbound-queue/src/v2/converter/mod.rs` takes `AllowedAliasOrigin` as a generic and defers entirely to whatever the runtime supplies [4](#0-3) . Nothing in the trait bound forces a runtime integrator to exclude the Asset Hub's own location — the type is fully runtime-supplied, exactly analogous to the vault report's complaint that a security-critical byte sequence is hardcoded per deployment and can silently diverge from the reviewed/patched version. Bridge-hub-westend received the patch (`EverythingBut<Equals<AssetHubLocation>>`), while bridge-hub-rococo in this snapshot has no V2 outbound queue pallet, exporter, or filter configured whatsoever, meaning the fix from pr_12159 was never propagated/ported to it.

### Impact Explanation
If/when a V2 outbound queue and `EthereumBlobExporter` are wired for bridge-hub-rococo (or any other bridge-hub runtime) without also supplying the `EverythingBut<Equals<AssetHubLocation>>` (or equivalent) filter, a signed Asset Hub user could submit an `AliasOrigin(AssetHubLocation)` instruction inside their outbound XCM, exactly as demonstrated by the existing regression test `signed_assethub_user_cannot_bypass_origin_alteration_when_routing_to_ethereum` [5](#0-4) . This would let an unprivileged user spoof the bridge's primary Asset-Hub-derived agent account — the account that holds bridged ERC-20/ETH reserves on the Ethereum side — allowing unauthorized `Transact`/`DepositAsset` execution under that agent's identity and theft of bridge-held funds, matching the "unbacked mint/unlock" and "origin escalation" impact categories.

### Likelihood Explanation
The likelihood depends entirely on whether/when bridge-hub-rococo (or a new/cloned bridge-hub runtime) enables the V2 outbound pipeline; in the current snapshot there is no V2 outbound queue wired for rococo at all, so it's not yet directly exploitable there. However, this is precisely the failure mode the external report warns about: a security-critical parameter that must be kept in lock-step with the audited/patched source is configured ad hoc per file/runtime instead of being enforced by the shared library, so any future integration (new testnet, new bridge-hub instance, a revert/rebase that drops the `AllowedAliasOrigin` argument) can silently reintroduce the exact spoofing bug that pr_12159 fixed, with no compiler or runtime-level guard preventing it.

### Recommendation
- Short term: audit every runtime that instantiates `snowbridge_outbound_queue_primitives::v2::EthereumBlobExporter` (currently only bridge-hub-westend) and ensure `AllowedAliasOrigin` always excludes the local Asset Hub location before enabling the V2 pipeline anywhere else, including bridge-hub-rococo.
- Long term: move the Asset-Hub-exclusion check out of the generic runtime-supplied `AllowedAliasOrigin` parameter and into the shared `snowbridge-outbound-queue-primitives` crate as a mandatory, non-overridable check (or require the `AssetHubParaId`/`AssetHubLocation` type itself to always be excluded internally), so the protection cannot be omitted by a runtime configuration mistake, and add a compile-time or `#[cfg(test)]` assertion across all bridge-hub runtimes that verifies this invariant automatically.

### Proof of Concept
The existing test already proves the vulnerability class when the filter is absent/misconfigured — it constructs a forged XCM with `ClearOrigin` + `InitiateTransfer{ preserve_origin: true }` + `AliasOrigin(AssetHubLocation)` and shows that without the `EverythingBut<Equals<AssetHubLocation>>` guard the message would have been queued and exported to Ethereum under the spoofed Asset Hub agent origin [6](#0-5) . Reproducing this on any bridge-hub runtime that wires `EthereumBlobExporter` (v2) with `AllowedAliasOrigin = Everything` (or omits it, as bridge-hub-rococo currently does by not having V2 outbound at all) reproduces the spoofed-origin bridge fund theft.

pub fn signed_assethub_user_cannot_bypass_origin_alteration_when_routing_to_ethereum() {
	fund_on_bh();
	fund_on_ah();

	let forged_assethub_origin = Location::new(1, [Parachain(AssetHubWestend::para_id().into())]);
	let expected_assethub_agent = AgentIdOf::convert_location(&forged_assethub_origin).unwrap();
	assert_eq!(
		expected_assethub_agent,
		hex!("81c5ab2571199e3188135178f3c2c8e2d268be1313d029b30f534fa579b69b79").into()
	);

	AssetHubWestend::execute_with(|| {
		type RuntimeOrigin = <AssetHubWestend as Chain>::RuntimeOrigin;

		let local_fee_asset =
			Asset { id: AssetId(Location::parent()), fun: Fungible(LOCAL_FEE_AMOUNT_IN_DOT) };

		let remote_fee_asset =
			Asset { id: AssetId(ethereum()), fun: Fungible(REMOTE_FEE_AMOUNT_IN_ETHER) };

		let arbitrary_agent_call = ContractCall::V1 {
			target: ETHEREUM_DESTINATION_ADDRESS,
			calldata: vec![0xde, 0xad, 0xbe, 0xef],
			value: 0,
			gas: 100_000,
		};

		let assets = vec![local_fee_asset.clone(), remote_fee_asset.clone()];
		let forged_xcm = Xcm(vec![
			WithdrawAsset(assets.into()),
			PayFees { asset: local_fee_asset },
			// Clear the origin register to None. Under the logic flaw in the XCM executor's
			// InitiateTransfer implementation (with preserve_origin: true), this causes the
			// executor to export the message without prepending any origin-altering instructions.
			// Details: https://forum.polkadot.network/t/postmortem-xcm-initiatetransfer-origin-leak/17357
			ClearOrigin,
			InitiateTransfer {
				destination: ethereum(),
				remote_fees: Some(AssetTransferFilter::ReserveWithdraw(Definite(
					remote_fee_asset.into(),
				))),
				preserve_origin: true,
				assets: BoundedVec::truncate_from(vec![]),
				remote_xcm: Xcm(vec![
					AliasOrigin(forged_assethub_origin),
					DepositAsset { assets: Wild(AllCounted(0)), beneficiary: beneficiary() },
					Transact {
						origin_kind: OriginKind::Xcm,
						call: arbitrary_agent_call.encode().into(),
						fallback_max_weight: None,
					},
					SetTopic([9u8; 32]),
				]),
			},
		]);

		assert_ok!(<AssetHubWestend as AssetHubWestendPallet>::PolkadotXcm::execute(
			RuntimeOrigin::signed(AssetHubWestendSender::get()),
			bx!(VersionedXcm::from(forged_xcm)),
			Weight::from(EXECUTION_WEIGHT),
		));
	});
