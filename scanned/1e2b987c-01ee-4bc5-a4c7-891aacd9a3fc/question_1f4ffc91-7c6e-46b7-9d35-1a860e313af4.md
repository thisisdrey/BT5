`Engine::execute_signed_intent` in `contracts/defuse/core/src/engine/mod.rs` commits the nonce via `self.state.commit_nonce(signer_id.clone(), nonce)?` BEFORE calling `intents.execute_intent(&signer_id, self, hash)?`. If `TokenDiff::execute_intent` later fails (e.g. `DefuseError::BalanceOverflow` from `fees_collected.add`), does the nonce commit get rolled back together with the balance state inside the same `execute_intents` call, or can an attacker exploit ordering so the nonce is consumed while `Deltas::internal_apply_deltas` partial mutations for OTHER intents earlier in the same batch persist because only the failing `TokenDiff`'s own delta is reverted, not the whole transaction? Binding: nonce commit for `(signer_id, nonce)` count of successful settlements == 1, and it equals 0 if `execute_intents` as a whole returns `Err`. Impact: Critical if a nonce is burned without producing a fully-conserved settlement (locks the signer out of ever reusing what should still be an unspent nonce) or conversely if partial deltas persist despite an overall error. Proof: near-workspaces test causing a downstream `TokenDiff` overflow error, then reusing the same nonce in a fresh `MultiPayload` and asserting it is accepted (proving full rollback) or that all balances are unchanged from before the failed call.
