Preconditions: signer transfers N of token T to receiver via Transfer+NotifyOnTransfer; receiver has valid public key registered for signing. Call sequence: `internal_mt_batch_transfer` credits receiver -> `mt_on_transfer` promise -> receiver contract calls `execute_intents([signed_withdraw_of_T])` before returning its refund value -> `mt_resolve_transfer` then reads promise_result and, seeing 'full refund' claimed, subtracts from receiver's (now-drained) `token_balances` via `.sub(token_id, refund.0).unwrap()`. Scoped impact: Critical, double-credit across sender refund and receiver's already-spent balance.
