### Title
Windows WFP bypass filter unconditionally permits any remote UDP traffic to the Nebula listener port, defeating Windows Defender Firewall enforcement - (File: wfp/wfp_windows.go, udp/udp_bypass_windows.go)

### Summary
On Windows builds, `wrapWithWDFBypass` installs a high-priority WFP PERMIT filter (`PermitUDPPort`) for the Nebula UDP listener port whenever `listen.windows_bypass_wdf` is true, which is the default. [1](#0-0)  This filter is registered in a dynamic sublayer weighted `0xFFFF` with `FWPM_FILTER_FLAG_CLEAR_ACTION_RIGHT`, explicitly designed to outrank and override Windows Defender Firewall's block rules for that port. [2](#0-1) [3](#0-2)  This is architecturally the same class of issue as the reported EasyTrack/Voting duplicate-permission bug: one enforcement path (WDF, the operator's intended perimeter control) is meant to gate inbound access, but a second, functionally equivalent path (the WFP session filter) unconditionally grants the access that WDF was supposed to restrict, and any host on the network reachable to that UDP port — including one with no valid Nebula certificate at all — benefits from the bypass.

### Finding Description
`PermitUDPPort` builds two filters — one at `FWPM_LAYER_ALE_AUTH_RECV_ACCEPT_V4` and one at `_V6` — matching only `IP_PROTOCOL == UDP` and `IP_LOCAL_PORT == <listener port>`, with no condition on source address, no certificate check, and no relationship to Nebula's own authentication/authorization state. [4](#0-3)  Because the filter sits in a sublayer weighted `0xFFFF` with `fwpmFilterFlagClearActionRight` set, it wins WFP arbitration over Windows Defender Firewall's `MPSSVC_WF` sublayer even when WDF has a rule blocking inbound UDP to that port. [5](#0-4)  The bypass is installed automatically on first `ReloadConfig` and defaults to enabled (`c.GetBool("listen.windows_bypass_wdf", true)`), so an operator who relies on WDF as a perimeter control (e.g., to restrict which network segments can even reach the Nebula UDP port) gets that restriction silently overridden by Nebula itself. [1](#0-0) 

This duplicates functionality that should be gated by a single, consistently-enforced control: WDF is the administrator-configured restriction, while the Nebula-installed WFP permit is a second, broader-reaching path that grants the same "may send packets to this port" capability to any remote source, unconditionally.

### Impact Explanation
Any remote host — including one holding no Nebula CA-issued certificate — that can route a UDP packet to the Nebula listener port on a Windows peer will have that packet delivered past Windows Defender Firewall, regardless of any WDF block rules the operator configured for that port/profile. This removes an independent, defense-in-depth network control the operator explicitly set up, exposing the handshake-processing path (`handshake_manager.go`'s `HandleIncoming`/`beginHandshake`) directly to unauthenticated packets from any network the host is attached to (e.g., a supposedly-blocked public/untrusted profile), which is exactly the kind of surface WDF profile rules are meant to shut off before Nebula's own cert/PKI verification (`certVerifier`) ever runs. [6](#0-5) 

### Likelihood Explanation
High. The bypass is on by default (`true`), requires no special attacker capability beyond network reachability to the UDP port, and is installed automatically the first time the listener reloads its config. [7](#0-6) 

### Recommendation
Do not default `listen.windows_bypass_wdf` to enabled; require explicit administrator opt-in, and document clearly that enabling it removes WDF as an independent perimeter control for the Nebula port. Scope the WFP permit filter as narrowly as possible (e.g., only to the specific interface/LUID the tunnel is bound to, not to "any interface" for all UDP traffic on that port) and avoid `FWPM_FILTER_FLAG_CLEAR_ACTION_RIGHT` so an administrator's explicit WDF block can still take precedence over Nebula's own convenience bypass.

### Proof of Concept
1. Deploy a Nebula Windows node with default config (`listen.windows_bypass_wdf` unset, defaults to `true`).
2. On that node, configure Windows Defender Firewall with an explicit inbound block rule for the Nebula UDP listener port (simulating an operator-enforced network segmentation policy).
3. Observe that `wrapWithWDFBypass.ReloadConfig` installs the WFP PERMIT filter for that port on first reload. [1](#0-0) 
4. From an attacker-controlled host with no Nebula CA cert, on a network segment WDF was configured to block, send a UDP packet to the listener port.
5. Confirm the packet reaches `HandleIncoming`/`beginHandshake` despite the WDF block rule, because the WFP sublayer (weight `0xFFFF`, `ClearActionRight`) outranks WDF's `MPSSVC_WF` sublayer. [3](#0-2)
