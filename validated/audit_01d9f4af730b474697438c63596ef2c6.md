## Finding

Gitaly relies entirely on an **opt-in, per-RPC concurrency limiter** for backpressure and never bounds the raw number of concurrent gRPC streams a single connection/client can open at the transport layer. This is a structural analog of the Teku mplex issue (CL-2021-04): an attacker can open unbounded streams whose per-stream resource cost is paid before the application-level limiter (or even the payload) is ever inspected.

### Root cause

`GitalyServerFactory.New` builds the gRPC server's `ServerOption` list without ever calling `grpc.MaxConcurrentStreams(...)`. Only keepalive enforcement and interceptors are configured: [1](#0-0) 

Since `grpc.MaxConcurrentStreams` is left unset, the underlying `golang.org/x/net/http2`-based gRPC transport falls back to its default of effectively unlimited concurrent streams per connection (grpc-go uses `math.MaxUint32` when `MaxStreams` is zero). A stream, once opened at the HTTP/2 level, already causes gRPC to allocate a `ServerStream`, spin up interceptor chains, and (per `requestinfohandler`) allocate a `RequestInfo` struct and Prometheus label state — all *before* any application-level rate limiting is applied.

Gitaly's only defense is the config-driven `limithandler` middleware, which is:
1. **Opt-in per RPC** — it only limits methods explicitly listed under `[[concurrency]]` in the config file: [2](#0-1) 
Any RPC not listed (which, per `doc/backpressure.md`, is expected to be most RPCs unless operators add entries) has `limiter == nil` and bypasses limiting entirely: [3](#0-2) 

2. **Keyed by repository, extracted only after the first message is received.** The `StreamInterceptor`'s `wrappedStream.RecvMsg` only computes `lockKey` (via `LimitConcurrencyByRepo`, which reads `requestinfohandler.Extract(ctx).Repository.GetRelativePath()`) on the *first* received message, and if that key is empty (no repository field, storage/partition-scoped RPC, or the request simply hasn't been fully read), no limiting is applied at all: [4](#0-3) [5](#0-4) 

So a client can open a very large number of concurrent streams to any Gitaly-exposed RPC — especially storage/partition-scoped RPCs or any method with no `[[concurrency]]` entry — and each stream's transport/interceptor bookkeeping (goroutines, `RequestInfo`, Prometheus vectors, buffers) is created unconditionally, independent of whether a concurrency limiter ultimately would have rejected it. This mirrors the Teku bug class: cheap-to-open streams whose per-stream allocation cost is paid up front, with the mitigating limiter only engaging conditionally/late (in Teku's case, after protocol negotiation; in Gitaly's case, after the first message is parsed and only for configured, repo-scoped RPCs).

### Impact

An authenticated (or, for RPCs with no auth enforcement gaps aside, any client able to reach the gRPC/HTTP2 listener) peer can flood a Gitaly node with a very large number of concurrently open streams targeting unconfigured or non-repository-scoped RPCs, exhausting goroutines/memory and degrading the node for legitimate repository operations — a resource-exhaustion DoS at the RPC-handler layer, not mitigated by the existing per-repo `[[concurrency]]` queueing, which is scoped narrowly and activates only after message parsing.

### Recommendation
- Set an explicit `grpc.MaxConcurrentStreams` server option in `internal/gitaly/server/server.go` to bound streams per connection.
- Consider limiting streams before the first message is parsed (e.g., a connection/stream-count admission check ahead of `requestinfohandler`), rather than relying solely on the keyed, repo-scoped limiter that activates late.
- Extend `[[concurrency]]`-style limiting (or a global default limit) to storage/partition-scoped and otherwise-unconfigured RPCs so that "no config entry" doesn't mean "no limit." [6](#0-5) 

---

Note: this is an analog derived from static code review of the concurrency-limiting and gRPC server setup, not a proven exploit — I did not find a way to empirically test the actual grpc-go transport default in this environment, and confirming true unbounded-ness would require checking the pinned `google.golang.org/grpc` version's transport defaults in `go.mod`/vendor, which I did not verify.

	if info := requestinfohandler.Extract(ctx); info != nil {
		return info.Repository.GetRelativePath()

func (w *wrappedStream) RecvMsg(m interface{}) error {
	if err := w.ServerStream.RecvMsg(m); err != nil {
		return err
	}

	// Only perform limiting on the first request of a stream
	if !w.initial {
		return nil
	}

	w.initial = false

	ctx := w.Context()

	lockKey := w.limiterMiddleware.getLockKey(ctx)
	if lockKey == "" {
		return nil
	}

	// Check if request is authenticated
	limiter := w.limiterMiddleware.methodLimiters[w.info.FullMethod]
	unauthLimiter, ok := w.limiterMiddleware.methodLimitersUnauthenticated[w.info.FullMethod]
	if !auth.IsAuthenticated(ctx) && ok {
		limiter = unauthLimiter
	}

	if limiter == nil {
		// No concurrency limiting
		return nil

// WithConcurrencyLimiters sets up middleware to limit the concurrency of
// requests based on RPC and repository
func WithConcurrencyLimiters(cfg config.Cfg) (map[string]*limiter.AdaptiveLimit, map[string]*limiter.AdaptiveLimit, SetupFunc) {
	perRPCLimits := map[string]*limiter.AdaptiveLimit{}
	perRPCLimitsUnauthenticated := map[string]*limiter.AdaptiveLimit{}

	for _, concurrency := range cfg.Concurrency {
		// Create authenticated limiter
		limitName := fmt.Sprintf("perRPC%s", concurrency.RPC)
		if concurrency.Adaptive {
			perRPCLimits[concurrency.RPC] = limiter.NewAdaptiveLimit(limitName, limiter.AdaptiveSetting{
				Initial:       concurrency.InitialLimit,
				Max:           concurrency.MaxLimit,
				Min:           concurrency.MinLimit,
				BackoffFactor: limiter.DefaultBackoffFactor,
			})
		} else {
			perRPCLimits[concurrency.RPC] = limiter.NewAdaptiveLimit(limitName, limiter.AdaptiveSetting{
				Initial: concurrency.Concurrency(),
			})
		}

		// Create unauthenticated limiter if configured
		unauthLimits := concurrency.Unauthenticated
		if unauthLimits.IsSet() {
			limitNameUnauth := fmt.Sprintf("perRPC%s-unauthenticated", concurrency.RPC)
			if unauthLimits.Adaptive {
				perRPCLimitsUnauthenticated[concurrency.RPC] = limiter.NewAdaptiveLimit(limitNameUnauth, limiter.AdaptiveSetting{
					Initial:       unauthLimits.InitialLimit,
					Max:           unauthLimits.MaxLimit,
					Min:           unauthLimits.MinLimit,
					BackoffFactor: limiter.DefaultBackoffFactor,
				})
			} else if unauthLimits.Concurrency() > 0 {
				perRPCLimitsUnauthenticated[concurrency.RPC] = limiter.NewAdaptiveLimit(limitNameUnauth, limiter.AdaptiveSetting{
					Initial: unauthLimits.Concurrency(),
				})
			}
		}
	}
