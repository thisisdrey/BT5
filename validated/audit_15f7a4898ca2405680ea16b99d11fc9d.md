Audit Report

## Title
Constant per-command gas estimate for `RegisterForeignToken` ignores variable-length name/symbol payload, causing under-gassed Ethereum execution - (File: `bridges/snowbridge/primitives/outbound-queue/src/v2/message.rs`)

## Summary
`ConstantGasMeter::maximum_dispatch_gas_used_at_most` assigns a fixed gas budget (`1_200_000`) to `Command::RegisterForeignToken` regardless of the actual size of the `name`/`symbol` fields that get ABI-encoded into the command payload delivered to Ethereum [1](#0-0) . Because these fields are variable-length `Vec<u8>` derived from token metadata [2](#0-1) , the actual EVM gas needed to ABI-decode and store `name`/`symbol` on the Ethereum Gateway can exceed the flat estimate as their length grows, while only an aggregate message-size cap is enforced.

## Finding Description
The `abi_encode` implementation for `Command::RegisterForeignToken` embeds the full `name` and `symbol` byte vectors into the ABI payload [3](#0-2) , so the size of the delivered payload — and correspondingly the EVM gas cost to decode/copy/store it — scales with these field lengths. However, `ConstantGasMeter::maximum_dispatch_gas_used_at_most` returns the same `1_200_000` figure for `Command::RegisterForeignToken` irrespective of payload size [4](#0-3) .

This computed gas value is embedded directly in the `OutboundCommandWrapper.gas` field committed to the outbound queue for delivery to Ethereum [5](#0-4) . The only size guard applied before this is the aggregate `MaxMessagePayloadSize` check on the whole encoded message in `send_message_impl.rs`, which bounds total message size but does not scale the gas estimate with the specific `name`/`symbol` field lengths that drive the constant-vs-actual gas mismatch [6](#0-5) .

## Impact Explanation
If the actual Ethereum-side gas required to execute `registerForeignToken` (proportional to `name`/`symbol` length) exceeds the constant `1_200_000` estimate, the Gateway call will run out of gas and revert. Because the message/nonce state on the Substrate side is already committed once accepted into the outbound queue, this results in wasted relayer gas and a stalled/unprocessable registration message — matching the "public underpriced work that degrades block production or stalls bridge processing" impact category permitted by the gate.

## Likelihood Explanation
I was unable to fully verify, within the available search, whether the extrinsic path that constructs `Command::RegisterForeignToken` (referenced in `bridges/snowbridge/pallets/system-v2/src/lib.rs` and `bridges/snowbridge/pallets/system/src/lib.rs`) restricts `name`/`symbol` length via a bounded type before forwarding to the outbound queue. This bound (if it exists and is small) would directly affect how large the underestimation gap can practically grow, and is material to establishing real-world exploitability. The vulnerable estimator code itself is confirmed and unconditional on any such upstream bound, but without confirming the practical bound on `name`/`symbol` length, the severity and reachability of an actual gas-exhaustion scenario cannot be fully established from the code reviewed.

## Recommendation
Make `ConstantGasMeter::maximum_dispatch_gas_used_at_most` scale with the actual ABI-encoded payload size for variable-length commands (in particular `RegisterForeignToken`), e.g., `base_gas + per_byte_gas * payload.len()`. Add a test asserting the estimated gas is monotonic and sufficient with respect to `name.len() + symbol.len()`, and confirm/enforce a tight upstream bound on `name`/`symbol` length in the registration extrinsic.

## Proof of Concept
1. Construct `Command::RegisterForeignToken { token_id, name: <near-MaxMessagePayloadSize-sized bytes>, symbol: <near-MaxMessagePayloadSize-sized bytes>, decimals }`.
2. Observe `ConstantGasMeter::maximum_dispatch_gas_used_at_most` still returns `1_200_000`, identical to the empty `name`/`symbol` case (`bridges/snowbridge/primitives/outbound-queue/src/v2/message.rs:291-306`).
3. This command passes `SendMessage::validate`'s aggregate size check as long as total message size stays under `MaxMessagePayloadSize` (`bridges/snowbridge/pallets/outbound-queue-v2/src/send_message_impl.rs:23-32`).
4. The committed `gas` field for this larger payload is identical to the small-payload case, demonstrating the estimate does not scale with actual payload/execution cost.

```rust
impl GasMeter for ConstantGasMeter {
	fn maximum_dispatch_gas_used_at_most(command: &Command) -> u64 {
		match command {
			Command::SetOperatingMode { .. } => 40_000,
			Command::Upgrade { initializer, .. } => {
				// total maximum gas must also include the gas used for updating the proxy before
				// the the initializer is called.
				50_000 + initializer.maximum_required_gas
			},
			Command::UnlockNativeToken { .. } => 200_000,
			Command::RegisterForeignToken { .. } => 1_200_000,
			Command::MintForeignToken { .. } => 100_000,
			Command::CallContract { gas: gas_limit, .. } => *gas_limit,
		}
	}
}
```
