### Title
Active-Permission Key Can Overwrite Owner/Witness Permission via AccountPermissionUpdateContract - (File: `actuator/src/main/java/org/tron/core/actuator/AccountPermissionUpdateActuator.java`)

### Summary
`AccountPermissionUpdateActuator.validate()` fully replaces an account's `Owner`, `Witness`, and `Active` permission set based solely on the contents of the incoming `AccountPermissionUpdateContract`, without ever checking which permission (`permissionId`) was used to authorize/sign the transaction, nor comparing the weight/scope of the signer's authorizing permission to the new permission structure being installed [1](#0-0) .

### Finding Description
Transaction-level signature verification for any contract, including `AccountPermissionUpdateContract`, is performed generically in `TransactionCapsule.validateSignature()`, which resolves the signer's `Permission` from `contract.getPermissionId()` and checks the aggregated signature weight against that permission's threshold via `checkWeight` [2](#0-1) . There is a separate `checkPermission(permissionId, permission, contract)` call (line 490) intended to restrict which contract types a non-owner (`permissionId != 0`) `Active` permission may execute, based on that permission's `operations` bitmap.

The problem is in `AccountPermissionUpdateActuator` itself: once an `Active` permission has `AccountPermissionUpdateContract` enabled in its `operations` bitmap (a bit an account owner may set to let a delegated/low-value Active key perform routine permission maintenance), `checkPermission()` in `TransactionCapsule` only validates that the *bit* is set — it does not restrict what the resulting `Owner`/`Witness`/`Active` permissions in the contract payload may contain. `AccountPermissionUpdateActuator.validate()` (lines 148-229) only performs structural sanity checks on the new permissions (key count, threshold, distinct addresses, valid operations bitmap) via `checkPermission(Permission)` (lines 71-146); it never verifies that the signer's *own* permission weight/threshold is greater than or equal to the new permissions being installed, nor that the signer holds the `Owner` permission before being allowed to redefine the `Owner` permission [3](#0-2) .

As a result, any Active permission key that was ever granted the `AccountPermissionUpdateContract` capability bit (e.g., a low-weight operational key meant only for that one contract type) can submit a transaction that completely rewrites the account's `Owner` permission — inserting its own address with full weight/threshold — thereby granting itself full owner-level authority over the account, and can simultaneously strip out the legitimate owner's keys from every permission slot. This mirrors the Keycloak analog: a narrowly-scoped privilege (`manage-users`/limited Active permission) is used to self-assign a higher, unbounded privilege (`realm-admin`/`Owner` permission) because the permission-boundary check only validates "is this operation type allowed," not "does the requester have authority commensurate with the change being made."

### Impact Explanation
An attacker who compromises or is legitimately delegated a narrowly-scoped Active key (with `AccountPermissionUpdateContract` enabled) can escalate to full `Owner` control of the account, remove all other authorized keys, and permanently lock the legitimate owner and all other active keys out of the account — a concrete unauthorized-account-takeover / permanent-loss-of-control impact.

### Likelihood Explanation
Requires only a single signed `AccountPermissionUpdateContract` transaction from an address holding any `Active` permission slot that includes `AccountPermissionUpdateContract` in its `operations` bitmap — a configuration accounts commonly use to delegate routine key-rotation duties to lower-trust operational keys. No witness/committee/SR privileges or off-chain access are required.

### Recommendation
In `AccountPermissionUpdateActuator.validate()`, when the authorizing `permissionId` is not the `Owner` permission (`id != 0`), restrict the scope of changes the transaction is allowed to make — e.g., disallow modification of the `Owner` permission, and/or require that the new permission's total weight/threshold not exceed the authorizing permission's own weight, closing the gap between "may invoke this contract type" and "may grant arbitrary new authority."

### Proof of Concept
1. Owner account sets an `Active` permission (id=2, low key weight) with the `operations` bitmap bit for `AccountPermissionUpdateContract` enabled — a common configuration for delegated permission-maintenance keys, exercised in `AccountPermissionUpdateActuatorTest.successUpdatePermissionKey` [4](#0-3) .
2. The holder of that Active key crafts a new `AccountPermissionUpdateContract` where the `owner` field's `Permission` contains only the attacker's own key with full weight/threshold, sets `permissionId=2` on the transaction, and signs with the Active key.
3. `validateSignature` resolves permission id 2 and confirms the signature weight meets that Active permission's (low) threshold; `checkPermission` confirms `AccountPermissionUpdateContract` is an allowed operation for that permission.
4. `AccountPermissionUpdateActuator.execute()` installs the attacker-controlled `Owner` permission unconditionally, since `validate()` never compares the new `Owner` permission against the authority of permission id 2.

  @Override
  public boolean validate() throws ContractValidateException {

    if (chainBaseManager == null) {
      throw new ContractValidateException(ActuatorConstant.STORE_NOT_EXIST);
    }

    if (this.any == null) {
      throw new ContractValidateException(ActuatorConstant.CONTRACT_NOT_EXIST);
    }

    AccountStore accountStore = chainBaseManager.getAccountStore();
    DynamicPropertiesStore dynamicStore = chainBaseManager.getDynamicPropertiesStore();

    if (dynamicStore.getAllowMultiSign() != 1) {
      throw new ContractValidateException("multi sign is not allowed, "
          + "need to be opened by the committee");
    }
    if (!this.any.is(AccountPermissionUpdateContract.class)) {
      throw new ContractValidateException(
          "contract type error,expected type [AccountPermissionUpdateContract],real type["
              + any.getClass() + "]");
    }
    final AccountPermissionUpdateContract accountPermissionUpdateContract;
    try {
      accountPermissionUpdateContract = any.unpack(AccountPermissionUpdateContract.class);
    } catch (InvalidProtocolBufferException e) {
      logger.debug(e.getMessage(), e);
      throw new ContractValidateException(e.getMessage());
    }
    byte[] ownerAddress = accountPermissionUpdateContract.getOwnerAddress().toByteArray();
    if (!DecodeUtil.addressValid(ownerAddress)) {
      throw new ContractValidateException("invalidate ownerAddress");
    }
    AccountCapsule accountCapsule = accountStore.get(ownerAddress);
    if (accountCapsule == null) {
      throw new ContractValidateException("ownerAddress account does not exist");
    }

    if (!accountPermissionUpdateContract.hasOwner()) {
      throw new ContractValidateException("owner permission is missed");
    }

    if (accountCapsule.getIsWitness()) {
      if (!accountPermissionUpdateContract.hasWitness()) {
        throw new ContractValidateException("witness permission is missed");
      }
    } else {
      if (accountPermissionUpdateContract.hasWitness()) {
        throw new ContractValidateException("account isn't witness can't set witness permission");
      }
    }

    if (accountPermissionUpdateContract.getActivesCount() == 0) {
      throw new ContractValidateException("active permission is missed");
    }
    if (accountPermissionUpdateContract.getActivesCount() > 8) {
      throw new ContractValidateException("active permission is too many");
    }

    Permission owner = accountPermissionUpdateContract.getOwner();
    Permission witness = accountPermissionUpdateContract.getWitness();
    List<Permission> actives = accountPermissionUpdateContract.getActivesList();

    if (owner.getType() != PermissionType.Owner) {
      throw new ContractValidateException("owner permission type is error");
    }
    checkPermission(owner);
    if (accountCapsule.getIsWitness()) {
      if (witness.getType() != PermissionType.Witness) {
        throw new ContractValidateException("witness permission type is error");
      }
      checkPermission(witness);
    }
    for (Permission permission : actives) {
      if (permission.getType() != PermissionType.Active) {
        throw new ContractValidateException("active permission type is error");
      }
      checkPermission(permission);
    }
    return true;
  }

  public static boolean validateSignature(Transaction transaction,
      byte[] hash, AccountStore accountStore, DynamicPropertiesStore dynamicPropertiesStore)
      throws PermissionException, SignatureException, SignatureFormatException {
    Transaction.Contract contract = transaction.getRawData().getContractList().get(0);
    int permissionId = contract.getPermissionId();
    byte[] owner = getOwner(contract);
    AccountCapsule account = accountStore.get(owner);
    Permission permission = null;
    if (account == null) {
      if (permissionId == 0) {
        permission = AccountCapsule.getDefaultPermission(ByteString.copyFrom(owner));
      }
      if (permissionId == 2) {
        permission = AccountCapsule
            .createDefaultActivePermission(ByteString.copyFrom(owner), dynamicPropertiesStore);
      }
    } else {
      permission = account.getPermissionById(permissionId);
    }
    if (permission == null) {
      throw new PermissionException("permission isn't exit");
    }
    checkPermission(permissionId, permission, contract);
    long weight = checkWeight(permission, transaction.getSignatureList(), hash, null);
    if (weight >= permission.getThreshold()) {
      return true;
    }
    return false;
  }
