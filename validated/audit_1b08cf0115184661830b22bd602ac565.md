### Title
Fee bypass on divisible NEP-245/IMT token swaps via unit-sized `TokenDiff` splitting - (File: contracts/defuse/core/src/intents/token_diff.rs)

### Summary
`TokenDiff::execute_intent` computes and collects the protocol fee independently for each `TokenDiff` intent, based on that single intent's own delta amount. `TokenDiff::token_fee` explicitly waives the fee for `Nep245` (multi-token) and `Imt` token types whenever the per-intent amount is `<= 1`. Because a signer can bundle an arbitrary number of `TokenDiff` intents into one `DefuseIntents` execution, a large economic swap of a divisible NEP-245/IMT asset can be decomposed into many unit-sized (`amount == 1`) legs, each individually exempt from fees, while the aggregate value moved is identical to what would have triggered `protocol_fee` if submitted as one intent.

### Finding Description
`fees owed` should equal `fees collected` for every unit of value exchanged through `TokenDiff`. The engine breaks this binding at the per-intent granularity check in `token_fee`: [1](#0-0) 

```
pub fn token_fee(token_id: impl Into<TokenIdType>, amount: u128, fee: Pips) -> Pips {
    let token_id = token_id.into();
    match token_id {
        TokenIdType::Nep141 => {}
        TokenIdType::Nep245 | TokenIdType::Imt if amount > 1 => {}
        // do not take fees on NFTs and MTs with |delta| <= 1
        TokenIdType::Nep171 | TokenIdType::Nep245 | TokenIdType::Imt => return Pips::ZERO,
    }
    fee
}
```

This is invoked from `TokenDiff::execute_intent`, which loops over the deltas contained in a *single* `TokenDiff` intent and computes `fee` from that intent's own `amount`: [2](#0-1) 

`DefuseIntents::execute_intent` (and `Intent::execute_intent`) simply iterate over an arbitrary-length `Vec<Intent>` supplied in one signed `MultiPayload`, executing each `TokenDiff` intent (and its fee computation) independently: [3](#0-2) 

Because the exemption threshold (`amount <= 1`) is checked per-intent rather than on the aggregate delta a signer is transacting in the whole execution, a solver/user pair can replace a single `TokenDiff` swap of `N` units of an NEP-245 (`Nep245TokenId`) or IMT (`ImtTokenId`) asset — which would incur `fee.fee_ceil(N)` — with `N` separate `TokenDiff` intents each moving exactly `1` unit, each of which computes `token_fee(..., 1, fee) == Pips::ZERO`. The counter-party side supplies the offsetting deltas (matched via the `Deltas`/`TokenTransferMatcher` invariant in `contracts/defuse/core/src/engine/state/deltas.rs`), so the batch still nets to zero and settles normally — only the fee-collector side is shorted.

Equality broken: `sum(fee_ceil(delta_i))` over `i` unit-sized intents (`== 0`) versus `fee_ceil(sum(delta_i))` for the equivalent single intent (`> 0` for any `fee > 0` and `N` large enough).

### Impact Explanation
This falls under "fees bypassed or over-collected" (Critical), since the fee-collector account (`engine.state.fee_collector()`) receives strictly less than what the protocol fee schedule (`Pips`) dictates for the actual value exchanged, while the swapping parties settle the full intended amounts. Any divisible NEP-245 or IMT asset traded through `TokenDiff` (which is the primary intent-matching mechanism between users/solvers in this protocol) is affected — not just true NFTs with `amount == 1` by nature.

### Likelihood Explanation
Exploitation only requires an unprivileged signer (or a colluding solver/user pair) to construct multiple `TokenDiff` intents instead of one within a `MultiPayload`/`execute_intents` call — no special role, key, or deployment misconfiguration is needed, and the split can be automated. The only cost to the attacker is proportionally more intents (and therefore more gas) for larger amounts, but this is an economic trade-off, not a blocker, and is fully within the attacker's control.

### Recommendation
Compute and enforce the NEP-245/IMT fee-exemption threshold against the cumulative amount a signer moves for a given token within the whole execution (or across the whole batch of `TokenDiff` intents in one `execute_signed_intents` call), not per individual intent's delta. Alternatively, remove the `amount <= 1` exemption for `Nep245`/`Imt` token types and only special-case genuinely non-fungible `Nep171` token ids, since NEP-245/IMT tokens can represent arbitrarily valuable divisible assets.

### Proof of Concept
1. Protocol fee `fee = Pips::ONE_PERCENT` (1%), fee collector `C`.
2. User `A` wants to swap `1000` units of an NEP-245 token `T` (`Nep245TokenId`) for token `U` with counter-party `B`.
   - **Single intent (expected)**: `A` signs one `TokenDiff{ diff: {T: -1000, U: +X} }`. `token_fee(T, 1000, 1%) = 1%`, so `fees_collected[T] = fee_ceil(1000) = 10`, credited to `C`.
   - **Split intents (bypass)**: `A` instead signs 1000 `TokenDiff` intents in the same `MultiPayload`, each `{T: -1, U: +x}` with `sum(x) == X`. For every intent, `token_fee(T, 1, 1%) == Pips::ZERO` per `contracts/defuse/core/src/intents/token_diff.rs:211`, so `fees_collected` is `0` for all 1000 intents.
3. `B`'s corresponding `TokenDiff` intents supply the matching opposite deltas (either as one intent or similarly split), so `Deltas::finalize` in `contracts/defuse/core/src/engine/state/deltas.rs` sees a balanced batch and the execution succeeds via `Engine::execute_signed_intents`.
4. Result: `A` and `B` fully exchange `1000` units of `T` for `U` exactly as in the single-intent case, but `C` (fee collector) receives `0` instead of `10` units of `T` — the "fees owed vs. fees collected" invariant is broken with concrete value loss to the protocol's fee revenue.
