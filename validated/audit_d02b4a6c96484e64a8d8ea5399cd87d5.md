### Title
Unbounded JSON-RPC log/block filter result accumulation until client polls or filter expires enables memory-exhaustion DoS - (File: `framework/src/main/java/org/tron/core/services/jsonrpc/TronJsonRpcImpl.java`)

### Summary
The `CVE-2022-42319` bug class is: a server allocates memory to buffer a response for a client request, but that memory is only freed once the client actually reads the response — an unresponsive/malicious client can force unbounded buffering. java-tron's Ethereum-compatible JSON-RPC filter subsystem (`eth_newFilter` / `eth_newBlockFilter` + `eth_getFilterChanges`) has the same pattern: any anonymous JSON-RPC client can create a log filter whose matched results are buffered server-side in an unbounded queue, and that queue is only drained (and the client's held memory freed) when the client calls `eth_getFilterChanges`. If the client never polls, the buffered results accumulate for the full lifetime of the filter.

### Finding Description
When a log filter is created, its state is tracked in a `LogFilterAndResult`, whose backing store is an **unbounded** `LinkedBlockingQueue<LogFilterElement>`: [1](#0-0) 

Every time a block is processed, `Manager.postLogsFilter` publishes a `LogsFilterCapsule` for the block's transaction logs: [2](#0-1) 

`TronJsonRpcImpl.handleLogsFilter` then dispatches this to every registered filter and appends all matching `LogFilterElement`s to the filter's result queue with `logFilterAndResult.getResult().addAll(localResults)`, with no cap on the number of elements accumulated: [3](#0-2) 

The queue is only drained via `popAll()`, which is invoked exclusively from `eth_getFilterChanges` (`getFilterResult`): [4](#0-3) 

Critically, the filter's expiration timer (`expireTimeStamp`) is only refreshed when the client actually polls (`updateExpireTime()` is called in the constructor and again inside `getFilterResult` after a successful poll), not on every event added to the queue: [5](#0-4) 

This means an attacker can call `eth_newFilter` with a broad match (e.g., no address restriction, `fromBlock=0`/`toBlock=latest`) and simply never call `eth_getFilterChanges`. For the entire un-extended expiration window, every subsequent block's matching logs are appended to the filter's in-memory queue with no size bound, exactly mirroring the Xenstore pattern of "temporary memory not freed until the client reads the response."

### Impact Explanation
An unauthenticated/anonymous JSON-RPC client can repeatedly create broad-matching filters (subject only to whatever filter-count limit exists via `JsonRpcExceedLimitException` on `eth_newFilter`/`eth_newBlockFilter`) and never poll them. Each filter accumulates an unbounded amount of `LogFilterElement` data as new blocks are produced, multiplying memory pressure on the full node/JSON-RPC service process. Sustained abuse can exhaust heap memory, causing the node process to slow down, throw `OutOfMemoryError`, or crash — a Denial of Service against the JSON-RPC-serving node, consistent with the "node crash or halt" / "API the node can no longer serve" impact criteria.

### Likelihood Explanation
Reachable by any anonymous JSON-RPC client with no special privileges — `eth_newFilter`/`eth_newBlockFilter` and `eth_getFilterChanges` are standard, unauthenticated public JSON-RPC methods exposed by `TronJsonRpcImpl`. No signed transaction or on-chain privilege is required; the attacker only needs network access to the JSON-RPC endpoint and can open many such filters and simply not poll them while the chain continues producing blocks with matching logs.

### Recommendation
- Bound the per-filter result queue size (e.g., cap `LogFilterAndResult`/`BlockFilterAndResult` result size) and drop/replace oldest entries or mark the filter as overflowed/expired when the cap is exceeded, similar to how `filterCapsuleQueue.offer(...)` failures are already logged in `Manager`.
- Decouple filter expiration from client polling: expire filters based on absolute creation-time TTL (or accumulated unread size) rather than only extending the timer on `eth_getFilterChanges` calls, so an unpolled filter cannot accumulate indefinitely.
- Enforce/verify a strict global cap on total filters and on aggregate buffered elements across all filters per client/connection.

### Proof of Concept
1. Connect to the node's JSON-RPC endpoint anonymously.
2. Call `eth_newFilter` with an empty/broad filter (no `address`, `fromBlock: "0x0"`, `toBlock: "latest"`) to match essentially all contract logs.
3. Repeat step 2 up to the configured filter limit, without ever calling `eth_getFilterChanges` for any of the created filter IDs.
4. Let the chain continue producing blocks with contract activity; observe `TronJsonRpcImpl.handleLogsFilter` → `processLogFilterEntry` continually appending matched `LogFilterElement`s into each filter's unbounded `LinkedBlockingQueue`, growing heap usage until the filters' un-extended expiry window elapses, at which point memory is finally reclaimed — reproducing the "response not read → memory not freed" pattern from CVE-2022-42319.

      Map<String, LogFilterAndResult> eventFilterMap,
      LogsFilterCapsule logsFilterCapsule) {
    LogFilterAndResult logFilterAndResult = entry.getValue();
    if (logFilterAndResult.isExpire()) {
      eventFilterMap.remove(entry.getKey());
      return;
    }

    long blockNumber = logsFilterCapsule.getBlockNumber();
    long fromBlock = logFilterAndResult.getLogFilterWrapper().getFromBlock();
    long toBlock = logFilterAndResult.getLogFilterWrapper().getToBlock();
    if (!(fromBlock <= blockNumber && blockNumber <= toBlock)) {
      return;
    }

    if (logsFilterCapsule.getBloom() != null && !logFilterAndResult.getLogFilterWrapper()
        .getLogFilter().matchBloom(logsFilterCapsule.getBloom())) {
      return;
    }

    LogFilter logFilter = logFilterAndResult.getLogFilterWrapper().getLogFilter();
    List<LogFilterElement> elements =
        LogMatch.matchBlock(logFilter, blockNumber, logsFilterCapsule.getBlockHash(),
            logsFilterCapsule.getTxInfoList(), logsFilterCapsule.isRemoved());

    for (LogFilterElement element : elements) {

      try {
        // compare with hashcode() first, then with equals(). If not exist, put it.
        cachedElement = logElementCache.get(element, () -> element);
      } catch (ExecutionException e) {
        logger.error("Getting/loading LogFilterElement from cache fails", e); // never happen
        cachedElement = element;
      }
      localResults.add(cachedElement);
    }
    logFilterAndResult.getResult().addAll(localResults);

  public Object[] getFilterResult(String filterId, Map<String, BlockFilterAndResult>
      blockFilter2Result, Map<String, LogFilterAndResult> eventFilter2Result)
      throws ItemNotFoundException {
    Object[] result;

    if (blockFilter2Result.containsKey(filterId)) {
      List<String> blockHashList = blockFilter2Result.get(filterId).popAll();
      result = blockHashList.toArray(new String[blockHashList.size()]);
      blockFilter2Result.get(filterId).updateExpireTime();

    } else if (eventFilter2Result.containsKey(filterId)) {
      List<LogFilterElement> logElementList = eventFilter2Result.get(filterId).popAll();
      result = logElementList.toArray(new LogFilterElement[0]);
      eventFilter2Result.get(filterId).updateExpireTime();

    } else {
      throw new ItemNotFoundException(FILTER_NOT_FOUND);
    }

    return result;
  }
