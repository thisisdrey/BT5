Audit Report

## Title
`renew()` in `pallet-broker` charges the caller with no user-supplied price ceiling, unlike `purchase()` - (File: `substrate/frame/broker/src/dispatchable_impls.rs`)

## Summary
`do_purchase` requires callers to supply `price_limit` and enforces `ensure!(price_limit >= price, Error::<T>::Overpriced)` before charging [1](#0-0) . `do_renew` takes only a `core` index and unconditionally charges `record.price` via `purchase_core` with no caller-supplied bound whatsoever [2](#0-1) , and the public `renew` extrinsic exposes no price parameter at all [3](#0-2) .

## Finding Description
`do_renew` reads `record.price` from `PotentialRenewals` and immediately charges it through `Self::purchase_core(&who, record.price, &mut sale)`, which calls `Self::charge` unconditionally [4](#0-3) . Unlike `do_purchase`, there is no `price_limit` parameter and no `ensure!` guard comparing the charge against any caller-expressed maximum. The `record.price` used for the charge is itself a value that was computed and stored at the end of the *prior* call to `do_renew` (or set during initial region assignment), using `price = Self::sale_price(&sale, now).min(price_cap)` where `price_cap = max(record.price + renewal_bump * record.price, end_price)` [5](#0-4) , both of which are influenced by other market participants' purchases and by `rotate_sale`'s price-adaptation logic run at each sale boundary. Because `renew` provides no way for the caller to bound the charge, and because the value that ends up in `record.price` for a future renewal is not fixed by the caller but by aggregate market/timing conditions since the last write, this mirrors the `purchase`/`price_limit` inconsistency described in the claim: `renew` shares the same charging code path (`purchase_core` → `charge`) but omits the slippage-style protection that `purchase` has.

## Impact Explanation
A normal, unprivileged user calling the public `renew` extrinsic can be charged `record.price`, an amount derived from state (`sale_price`, `end_price`, `renewal_bump`) that can move between the time the user observes it off-chain and the time the renewal transaction executes, with no in-extrinsic mechanism to cap or reject an unexpectedly higher charge. This is a cost-correctness / underpriced-or-overpriced-work class defect: the caller has no guarantee that what they pay matches what they agreed to pay, directly analogous to the acknowledged gap in `purchase()`.

## Likelihood Explanation
This occurs under ordinary, non-adversarial chain conditions: transaction inclusion delay, other market participants purchasing/renewing cores between blocks, or sale rotation changing `end_price` via the price-adaptation mechanism. No malicious actor, governance action, or privileged capability is required — any user submitting `renew(core)` is exposed whenever these ordinary conditions shift `record.price` between calls.

## Recommendation
Add a `price_limit: BalanceOf<T>` parameter to the `renew` extrinsic, mirroring `purchase`, and enforce `ensure!(price_limit >= record.price, Error::<T>::Overpriced)` in `do_renew` before calling `purchase_core`, giving the caller the same slippage protection available for `purchase`.

## Proof of Concept
1. A core's renewal price is recorded in `PotentialRenewals` after a prior `do_renew`/initial assignment, computed from `sale_price(&sale, now).min(price_cap)` at that time [5](#0-4) .
2. Before the user's `renew(core)` transaction is included, other market activity or a sale rotation changes `end_price`/`sale_price` inputs feeding the next stored `record.price`.
3. The user calls `renew(core)`; `do_renew` charges the stored `record.price` via `purchase_core` with no `ensure!` check against any caller-supplied maximum, unlike `do_purchase`'s `Overpriced` guard [4](#0-3) .
4. The caller is charged an amount they had no opportunity to bound or reject within the extrinsic itself, reproducing the missing-slippage-protection defect present in `renew` but absent from `purchase`.

	pub(crate) fn do_purchase(
		who: T::AccountId,
		price_limit: BalanceOf<T>,
	) -> Result<RegionId, DispatchError> {
		let status = Status::<T>::get().ok_or(Error::<T>::Uninitialized)?;
		let mut sale = SaleInfo::<T>::get().ok_or(Error::<T>::NoSales)?;
		Self::ensure_cores_for_sale(&status, &sale)?;

		let now = RCBlockNumberProviderOf::<T::Coretime>::current_block_number();
		ensure!(now > sale.sale_start, Error::<T>::TooEarly);
		let price = Self::sale_price(&sale, now);
		ensure!(price_limit >= price, Error::<T>::Overpriced);

		let core = Self::purchase_core(&who, price, &mut sale)?;

	pub(crate) fn do_renew(who: T::AccountId, core: CoreIndex) -> Result<CoreIndex, DispatchError> {
		let config = Configuration::<T>::get().ok_or(Error::<T>::Uninitialized)?;
		let status = Status::<T>::get().ok_or(Error::<T>::Uninitialized)?;
		let mut sale = SaleInfo::<T>::get().ok_or(Error::<T>::NoSales)?;
		Self::ensure_cores_for_sale(&status, &sale)?;

		let renewal_id = PotentialRenewalId { core, when: sale.region_begin };
		let record = PotentialRenewals::<T>::get(renewal_id).ok_or(Error::<T>::NotAllowed)?;
		let workload =
			record.completion.drain_complete().ok_or(Error::<T>::IncompleteAssignment)?;

		let old_core = core;

		let core = Self::purchase_core(&who, record.price, &mut sale)?;
