### Title
Missing Domain Separation in `ValidateMultiSign` Precompile Enables Cross-Application Signature Replay - ([File: actuator/src/main/java/org/tron/core/vm/PrecompiledContracts.java])

### Summary
The `ValidateMultiSign` TVM precompile (address `0x...0a`) lets any smart contract verify that a set of signatures satisfies an account's permission threshold over a hash computed as `sha256(address || permissionId || data)`. Just like the Muon `LibMuon` bug — where different `verify*` functions hashed structurally similar payloads without including a method/type discriminator — this hash construction has no binding to *which contract or application* requested the signature, so a signature produced for one dApp's authorization flow can be replayed verbatim against a completely different contract that also calls this precompile with the same `(address, permissionId, data)` tuple.

### Finding Description
`ValidateMultiSign.execute` builds the message to verify purely from attacker/caller-supplied `address`, `permissionId`, and an arbitrary `data` (bytes32) parameter: [1](#0-0) 

It then recovers signer addresses from this hash and checks their combined weight against the account's on-chain `Permission`: [2](#0-1) 

Nothing in the hashed payload identifies the calling contract, the specific action being authorized, or any application-level "method name"/purpose tag — exactly the class of omission flagged in the Muon report ("If the app has different methods, the method name should be included as well"). Any contract on TVM can invoke this same precompile address with an identical `(address, permissionId, data)` triple and obtain the same hash, so a signature a user produced to authorize a specific action for one dApp (e.g., signing `data = keccak256("withdraw 100 USDT to X")` for dApp A) is equally valid input to any other dApp B's call into `ValidateMultiSign` that happens to construct/receive the same `(address, permissionId, data)` combination — because the precompile has no way to bind the signature to the caller/contract or the intended semantic action.

### Impact Explanation
Because `ValidateMultiSign` is the on-chain trust primitive TRC-20/DeFi contracts use to implement custom multisig-gated authorization (e.g., meta-transactions, permit-style approvals) on top of TRON account permissions, a missing domain separator allows an attacker who observes a valid `(data, signature[])` pair intended for one contract to replay it into a different, unrelated contract sharing the same account/permission context, causing that second contract to treat the account as having "authorized" an action it never approved. This is a concrete unauthorized-account-operation / fund-theft vector for any contract that relies on this precompile without independently adding its own domain separation (e.g., embedding its own contract address or a method selector into `data`), and the assumption that ValidateMultiSign is itself function-scoped is a reasonable and common developer mistake given the precompile's simplistic contract.

### Likelihood Explanation
Exploitation only requires deploying an ordinary smart contract that calls the `ValidateMultiSign` precompile (address `0x...0a`) — reachable by any unprivileged contract deployer — and obtaining a legitimately-signed `(data, signature[])` tuple from any dApp built on this primitive (these are often published on-chain or exposed via UI flows for gasless approvals). No privileged keys or consensus roles are required.

### Recommendation
Require callers of `ValidateMultiSign` to include a domain/method-specific tag in the hashed payload — e.g., mix in the calling contract's address (`msg.sender`/`caller` from the VM context) and/or a fixed method identifier — so a signature computed for one contract/action cannot be replayed against a different contract or action. At minimum, document prominently that `data` must itself already be domain-separated (bound to the calling contract address, chain id, and action) by every consumer of this precompile, and consider enforcing it at the precompile level by folding in the calling contract address automatically, similar to how `LibMuon.verifyLiquidationSig` was fixed to include a method-specific discriminator.

### Proof of Concept
1. dApp A asks user U (who holds a weighted key in account `ACC`'s permission `P`) to sign `hash = sha256(ACC || P || data)` where `data` is a 32-byte value dApp A derives from an action description (e.g., `data = sha256("withdraw:100USDT:toA")`), and submits `(ACC, P, data, sig)` to `ValidateMultiSign` inside its own contract logic to authorize the withdrawal.
2. Attacker observes this `(data, sig)` pair (e.g., from a public transaction, or a phished/collected signature intended for dApp A).
3. Attacker deploys/uses contract B, which independently calls `ValidateMultiSign(ACC, P, data, sig)` for its own unrelated privileged action (e.g., "approve transfer to attacker") whenever it happens to construct the same `data` value (attacker can influence what value contract B hashes, e.g., by choosing input parameters to B that make its derived `data` collide with the one already signed for dApp A).
4. Because the precompile hash has no contract/method-specific domain separator, `ValidateMultiSign` returns `true` for contract B as well, letting the attacker execute B's privileged action as if U had authorized it, using a signature U never intended for B. [3](#0-2)

  public static class ValidateMultiSign extends PrecompiledContract {

    private static final int ENGERYPERSIGN = 1500;
    private static final int MAX_SIZE = 5;
    private static final int ABI_HEADER_WORDS = 5;
    private static final int ABI_ITEM_WORDS = 5;


    @Override
    public long getEnergyForData(byte[] data) {
      long cnt = (data.length / WORD_SIZE - 5) / 5;
      // one sign 1500, half of ecrecover
      return cnt * ENGERYPERSIGN;
    }

    @Override
    public Pair<Boolean, byte[]> execute(byte[] rawData) {
      if (VMConfig.allowTvmOsaka()
          && !isValidAbiEncoding(rawData, ABI_HEADER_WORDS, ABI_ITEM_WORDS)) {
        return Pair.of(false, EMPTY_BYTE_ARRAY);
      }
      DataWord[] words = DataWord.parseArray(rawData);
      byte[] address = words[0].toTronAddress();
      int permissionId = words[1].intValueSafe();
      byte[] data = words[2].getData();

      byte[] combine = ByteUtil.merge(address, ByteArray.fromInt(permissionId), data);
      byte[] hash = Sha256Hash.hash(CommonParameter
          .getInstance().isECKeyCryptoEngine(), combine);

      if (VMConfig.allowTvmSelfdestructRestriction()) {
        int sigArraySize = words[words[3].intValueSafe() / WORD_SIZE].intValueSafe();
        if (sigArraySize > MAX_SIZE) {
          return Pair.of(true, DATA_FALSE);
        }
      }
      byte[][] signatures = VMConfig.allowTvmSelfdestructRestriction() ?
          extractSigArray(words, words[3].intValueSafe() / WORD_SIZE, rawData) :
          extractBytesArray(words, words[3].intValueSafe() / WORD_SIZE, rawData);

      if (signatures.length == 0 || signatures.length > MAX_SIZE) {
        return Pair.of(true, DATA_FALSE);
      }

      AccountCapsule account = this.getDeposit().getAccount(address);
      if (account != null) {
        try {
          Permission permission = account.getPermissionById(permissionId);
          if (permission != null) {
            //calculate weight
            long totalWeight = 0L;
            List<byte[]> executedSignList = new ArrayList<>();
            for (byte[] sign : signatures) {
              byte[] recoveredAddr = recoverAddrBySign(sign, hash);

              sign = merge(recoveredAddr, sign);
              if (ByteArray.matrixContains(executedSignList, recoveredAddr)) {
                if (ByteArray.matrixContains(executedSignList, sign)) {
                  continue;
                }
                MUtil.checkCPUTime();
              }
              long weight = TransactionCapsule.getWeight(permission, recoveredAddr);
              if (weight == 0) {
                //incorrect sign
                return Pair.of(true, DATA_FALSE);
              }
              totalWeight += weight;
              executedSignList.add(sign);
              executedSignList.add(recoveredAddr);
            }

            if (totalWeight >= permission.getThreshold()) {
              return Pair.of(true, dataOne());
            }
          }
        } catch (Throwable t) {
          if (t instanceof OutOfTimeException) {
            throw t;
          }
          logger.info("ValidateMultiSign error:{}", t.getMessage());
        }
      }
      return Pair.of(true, DATA_FALSE);
    }
  }
