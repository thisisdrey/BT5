Audit Report

## Title
Snowbridge outbound-queue-v2 `AliasOrigin` filter only blacklists AssetHub, letting an unprivileged caller forge any other chain's Ethereum agent identity - (File: `bridges/snowbridge/primitives/outbound-queue/src/v2/converter/convert.rs`)

## Summary
The production `SnowbridgeExporterV2` on Bridge Hub Westend is configured with `EverythingBut<Equals<AssetHubLocation>>` as its `AllowedAliasOrigin` filter, which rejects only the exact AssetHub location and accepts any other `AliasOrigin` value embedded in a routed XCM. [1](#0-0)  Because the underlying `InitiateTransfer{preserve_origin:true}` executor path only appends an `AliasOrigin` automatically when the current origin register is `Some`, an attacker who first clears the origin via `ClearOrigin` and then embeds a hand-crafted `AliasOrigin(victim_location)` instruction directly inside `remote_xcm` causes that attacker-controlled instruction to be forwarded verbatim (since the `_` branch of the match falls back to pushing `ClearOrigin` only for the executor-generated instruction, while the attacker's own `remote_xcm` content, including the forged `AliasOrigin`, is appended unconditionally afterward). [2](#0-1)  The `XcmConverter::convert()` only validates this forged `AliasOrigin` against `AllowedAliasOrigin::contains()`, hashes it into a real `AgentId` via `AgentIdOf::convert_location`, and uses it as the authorizing identity for `Transact`/`CallContract` execution on Ethereum. [3](#0-2) 

## Finding Description
`pr_12159` added `AllowedAliasOrigin: Contains<Location>` specifically to close a documented forgery vector (`ClearOrigin` + `InitiateTransfer{preserve_origin:true}` origin leak, referenced at `https://forum.polkadot.network/t/postmortem-xcm-initiatetransfer-origin-leak/17357`), but the mitigation applied in the production runtime is `EverythingBut<Equals<AssetHubLocation>>` — an exclusion of exactly one location rather than an inclusion-based check tied to the genuine sending origin. [4](#0-3) [1](#0-0) 

The regression test that validates the fix, `signed_assethub_user_cannot_bypass_origin_alteration_when_routing_to_ethereum`, only exercises `forged_assethub_origin` and confirms it is now rejected. [5](#0-4)  The unit-test suite for the converter separately and explicitly proves that an `AliasOrigin(Location::new(1,[GlobalConsensus(Polkadot), Parachain(1000)]))` — i.e., any location other than AssetHub — passes `convert()` successfully under the exact same `EverythingBut<Equals<AssetHubLocation>>` filter used in production. [6](#0-5) 

The root executor behavior that makes the attacker-embedded `AliasOrigin` reach the converter unfiltered is confirmed in `xcm-executor`: when `ClearOrigin` precedes `InitiateTransfer`, `self_ref.origin_ref()` is `None`, so the `Some(origin) if preserve_origin` branch is skipped and the fallback pushes only `ClearOrigin`, after which the attacker's own `remote_xcm` (containing the forged `AliasOrigin`) is appended without any additional origin verification by the executor. [2](#0-1)  This message is exported to Ethereum through `SnowbridgeExporterV2`, whose `validate()` uses the presence of `AliasOrigin` to identify V2 messages and constructs `XcmConverter::<..., EverythingBut<Equals<AssetHubLocation>>>`, which only rejects the single blacklisted location. [7](#0-6) 

The `AliasOrigin` value is hashed to derive the `AgentId` — a unique mapping to a real Agent contract on Ethereum that authorizes `Transact` execution — via `HashedDescription`-based `AgentIdOf::convert_location`. [8](#0-7)  No check exists anywhere in this path (the exporter's `validate()`, the `XcmConverter::convert()`, or the executor's `InitiateTransfer` handling) that confirms the forged `AliasOrigin` matches the extrinsic's genuine signed origin, so any sibling parachain's or system chain's location — anything other than the literal `AssetHubLocation` constant — is accepted.

## Impact Explanation
This constitutes unauthorized execution/origin escalation: an unprivileged, signed AssetHub account can impersonate the Ethereum-side Agent contract of any other bridged parachain or consensus system (any location != `AssetHubLocation`) and cause the Gateway to execute an attacker-chosen `Transact`/`ContractCall` under that agent's authority. This can misuse or drain funds/permissions held by the impersonated agent's contract and mis-attribute settlement to the wrong sender, aligning with "unauthorized execution or origin escalation" and "theft or unbacked mint or unlock" in the impact gate.

## Likelihood Explanation
The precondition — bypassing origin alteration via `ClearOrigin` + `InitiateTransfer{preserve_origin:true}` with a user-embedded `AliasOrigin` in `remote_xcm` — is already demonstrated as reachable from a plain signed extrinsic in the repository's own emulated test for the AssetHub case. [9](#0-8)  Swapping the `forged_assethub_origin` constant for any other `Location` (e.g., a sibling parachain) requires no additional privilege, timing assumption, or trust — it is a mechanical substitution of the exact same attack already proven exploitable, and the converter unit test independently confirms such a substituted location passes `convert()`. [6](#0-5) 

## Recommendation
Replace the exclusion-based `AllowedAliasOrigin = EverythingBut<Equals<AssetHubLocation>>` with an inclusion-based check that validates the `AliasOrigin` against the actual verified sending origin (derived from `universal_source`/the executor's origin register) rather than trusting a user-suppliable instruction embedded in `remote_xcm`. Alternatively/additionally, fix the underlying `InitiateTransfer` executor logic so that when the origin register is cleared before the instruction runs, `preserve_origin: true` cannot cause an attacker-supplied `AliasOrigin` inside `remote_xcm` to be treated as legitimate. Add regression tests forging `AliasOrigin` for sibling parachains, other system chains, and arbitrary consensus locations, not just `AssetHubLocation`.

## Proof of Concept
1. On AssetHub Westend, as any signed account, call `pallet_xcm::execute` with an XCM: `WithdrawAsset` (local + remote fee assets), `PayFees`, `ClearOrigin`, then `InitiateTransfer{ destination: ethereum(), preserve_origin: true, remote_xcm: [AliasOrigin(Location::new(1,[Parachain(VICTIM_PARA_ID)])), DepositAsset{..}, Transact{ origin_kind: Xcm, call: <attacker ContractCall> }, SetTopic(..)] }`, mirroring `signed_assethub_user_cannot_bypass_origin_alteration_when_routing_to_ethereum` but replacing `forged_assethub_origin` with any location other than `AssetHubLocation`. [9](#0-8) 
2. Because `SnowbridgeExporterV2` is configured with `EverythingBut<Equals<AssetHubLocation>>` in production, `XcmConverter::convert()` accepts the forged `AliasOrigin` for `VICTIM_PARA_ID` (as generically proven by `xcm_converter_convert_success`). [6](#0-5) [1](#0-0) 
3. The message is committed to `snowbridge_pallet_outbound_queue_v2::Messages` and delivered to Ethereum, where the Gateway derives `AgentId` from the victim parachain's location via `AgentIdOf::convert_location` and executes the attacker's `Transact` under that agent's authority. [8](#0-7) [3](#0-2)

/// Creates an AgentId from a Location. An AgentId is a unique mapping to an Agent contract on
