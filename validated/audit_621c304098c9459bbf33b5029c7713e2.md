Based on my investigation, I found a genuine analog in `handshake/machine.go`'s `validateCert`, which is the pre-authentication path an attacker with no CA-signed certificate can reach (a raw handshake message).

### Title
Peer-declared certificate version/key bound only after `Recombine`, but version negotiation happens before verifier gate is fully binding - ([File: handshake/machine.go])

### Summary
The external report's bug class is: a critical field supplied by the untrusted party (`bridgeAmount`/`tokenAmount`) is not cross-checked against the authoritative value before being used to move value/state, allowing an attacker to induce inconsistent behavior. In `handshake/machine.go`, `validateCert` reconstructs the peer certificate from attacker-supplied fields (`payload.CertVersion`, `payload.Cert`) via `cert.Recombine`, and only *after* recombination does it check the public key equality and hand off to `m.verifier`. Version negotiation (`rc.Version() != m.myVersion`) mutates `m.myVersion` based on attacker-declared cert version before the final trust decision is fully re-anchored to the currently negotiated version for subsequent messages.

### Finding Description
`validateCert` in [1](#0-0)  takes `payload.CertVersion` and `payload.Cert` — both attacker-controlled fields carried in an unauthenticated handshake payload — and passes them to `cert.Recombine` together with `m.hs.PeerStatic()` (the noise static key learned from the handshake) and `cred.Cert.Curve()`. Only after recombination does the code assert `rc.PublicKey() == m.hs.PeerStatic()`, and only then is `m.verifier(rc)` invoked to perform CA-pool trust verification via [2](#0-1)  which calls `CAPool.VerifyCertificate`. Crucially, the "which version are we, going forward" state (`m.myVersion`) is updated based on the peer's self-declared `rc.Version()` before that verification's outcome is durably bound to the rest of the session (line 365-369), mirroring the source bug's pattern of trusting an attacker-supplied auxiliary value (`bridgeAmount`) ahead of validating it against the authoritative source (`tokenAmount`/actual balance).

### Impact Explanation
If the two related values (the version/format used to interpret `payload.Cert` and the version ultimately verified against the CA pool via `CAPool.verify`, which enforces `signer.Certificate.Curve() != c.Curve()` in [3](#0-2) ) diverge, an attacker with no CA-signed certificate could attempt to smuggle a differently-typed/parsed certificate blob through `Recombine` while the Machine's negotiated version state is adjusted mid-flight, potentially causing certificate/curve confusion during verification (remote state poisoning of the handshake machine's trusted version) or a crash/panic in downstream ASN.1 (`cert/cert_v2.go`) or protobuf (`cert/cert_v1.go`) unmarshalers if `Recombine`'s length/version checks are insufficiently strict for a given curve/version combination.

### Likelihood Explanation
Medium: this code path is reached by any unauthenticated party who initiates or responds to a handshake message (`ProcessPacket` → `processPayload` → `validateCert`), i.e., exactly the "no CA-signed certificate" attacker class permitted by the rules. No existing tunnel, valid cert, or lighthouse trust relationship is required — only the ability to send an arbitrary first/second handshake-stage UDP packet, as demonstrated by the e2e tests in [4](#0-3)  that already probe malformed/unexpected handshake fields.

### Recommendation
1. Re-verify or re-derive `m.myVersion` strictly from the value returned and fully authenticated by `m.verifier` (i.e., `verified.Certificate.Version()`), not from the pre-verification `rc.Version()`, before it is allowed to influence any subsequent message construction or parsing.
2. Add an explicit invariant check that the version/curve pair used to call `cert.Recombine` matches the version/curve pair that is subsequently accepted by `CAPool.VerifyCertificate`, failing closed (`m.failed = true`) on any mismatch, analogous to enforcing `tokenAmount == bridgeAmount` in the original report.
3. Add fuzz/unit tests that send mismatched `CertVersion` vs. actual `Cert` bytes/curve to `validateCert` to confirm it fails safely rather than partially updating `m.myVersion` before the verifier rejects the certificate.

### Proof of Concept
Not able to fully construct a concrete PoC within the current investigation — reproducing this would require: (1) crafting a handshake payload where `payload.CertVersion` declares one cert version while `payload.Cert` is encoded for a different version/curve than `cred.Cert.Curve()`, (2) sending it via `Machine.ProcessPacket` before any CA trust is established, and (3) observing whether `m.myVersion` is mutated or a crash occurs in `cert.Recombine`/downstream unmarshalers prior to `m.verifier` rejecting the certificate. I could not verify the internals of `cert.Recombine` (not located in the indexed snippets) to confirm whether it already fully guards against version/curve mismatches — this should be checked directly in a full Devin session with file-system access, since the index may not contain the complete `cert.Recombine` implementation.

```go
func (m *Machine) validateCert(payload Payload) error {
	cred := m.getCred(m.myVersion)
	if cred == nil {
		m.failed = true
		return fmt.Errorf("%w: %v", ErrNoCredential, m.myVersion)
	}
	rc, err := cert.Recombine(
		cert.Version(payload.CertVersion),
		payload.Cert,
		m.hs.PeerStatic(),
		cred.Cert.Curve(),
	)
	if err != nil {
		m.failed = true
		return fmt.Errorf("recombine cert: %w", err)
	}

	if !bytes.Equal(rc.PublicKey(), m.hs.PeerStatic()) {
		m.failed = true
		return ErrPublicKeyMismatch
	}

	// Version negotiation, if the peer sent a different version and we have it, switch
	if rc.Version() != m.myVersion {
		if m.getCred(rc.Version()) != nil {
			m.myVersion = rc.Version()
		}
	}

	verified, err := m.verifier(rc)
	if err != nil {
		m.failed = true
		return fmt.Errorf("verify cert: %w", err)
	}

	m.result.RemoteCert = verified
	m.remoteCertSet = true
	return nil
}
```

```go
func (ncp *CAPool) verify(c Certificate, now time.Time, certFp string, signerFp string) (*CachedCertificate, error) {
	if ncp.IsBlocklisted(certFp) {
		return nil, ErrBlockListed
	}

	signer, err := ncp.GetCAForCert(c)
	if err != nil {
		return nil, err
	}

	if signer.Certificate.Curve() != c.Curve() {
		return nil, ErrCurveMismatch
	}
```
