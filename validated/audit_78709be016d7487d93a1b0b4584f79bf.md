This CVE describes a Redis-specific issue: an unprivileged/authenticated Redis client abusing `CONFIG SET proto-max-bulk-len` on 32-bit Redis to overflow an integer during bulk-length parsing in `redis-server` (a C codebase), leading to heap corruption. This repository is the Go language distribution itself [1](#0-0) , containing the compiler, runtime, and standard library — there is no Redis server code, no `proto-max-bulk-len`-style configurable protocol limit, and no analogous 32-bit bulk-length integer-overflow parser in production Go paths.

The closest thematically related constructs I found are all defensively guarded against overflow rather than vulnerable to it:

- `bytes.Repeat` and `strings.Repeat` explicitly check `bits.Mul` overflow before allocating and panic safely rather than corrupting memory: [2](#0-1) [3](#0-2) 
- `runtime.growslice` explicitly checks for the exact class of 32-bit overflow-then-segfault bug called out in its comment, and panics instead of proceeding: [4](#0-3) 
- `net/http`'s `MaxBytesReader`/`maxBytesReader.Read` enforces a size limit on request bodies using `int64` arithmetic with explicit negative-limit handling, and is used as the mitigation pattern for large-body attacks in `net/http/server.go`'s `globalOptionsHandler`: [5](#0-4) [6](#0-5) 
- `encoding/gob`'s `decoderState.getLength` bounds decoded lengths against both the buffer size and a `tooBig` sanity constant before use, explicitly warning that gob's limits are not configurable and callers must be cautious with untrusted input — this is the opposite of Redis's configurable `proto-max-bulk-len`, since Go's gob limits are fixed and non-adjustable by an attacker: [7](#0-6) [8](#0-7) 

None of these represent an unpatched, reachable integer-overflow-to-memory-corruption primitive analogous to CVE-2021-21309; stretching any of them into an "analog" would not be a genuine, reproducible finding.

func (l *maxBytesReader) Read(p []byte) (n int, err error) {
	if l.err != nil {
		return 0, l.err
	}
	if len(p) == 0 {
		return 0, nil
	}
	// If they asked for a 32KB byte read but only 5 bytes are
	// remaining, no need to read 32KB. 6 bytes will answer the
	// question of the whether we hit the limit or go past it.
	// 0 < len(p) < 2^63
	if int64(len(p))-1 > l.n {
		p = p[:l.n+1]
	}
	n, err = l.r.Read(p)

	if int64(n) <= l.n {
		l.n -= int64(n)
		l.err = err
		return n, err
	}

// getLength decodes the next uint and makes sure it is a possible
// size for a data item that follows, which means it must fit in a

func (state *decoderState) getLength() (int, bool) {
	n := int(state.decodeUint())
	if n < 0 || state.b.Len() < n || tooBig <= n {
		return 0, false
	}
	return n, true
}
