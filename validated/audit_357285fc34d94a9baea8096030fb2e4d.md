### Title
Native stake/vote precompiles omit the self-destruct guard added to `FreezeBalanceV2Processor`, allowing state to be written against a self-destructed account address - (File: `actuator/src/main/java/org/tron/core/vm/nativecontract/`)

### Summary
The Envoy CVE involves an object (the `origin` header) being removed mid-flight while a later processing phase (`encodeHeaders`) still dereferences a stale reference to it, producing a crash. The java-tron analog is `SELFDESTRUCT`/`suicide2` marking an account as self-destructed in the `Repository` cache (`selfDestructCache`) while the underlying `AccountCapsule` row is not actually removed from `AccountStore` until `commit()` at the top of the call stack [1](#0-0) . Between the `markSelfDestruct` call and the final commit, the same contract address can still be the target of native TVM staking/voting precompiles that are dispatched through `Actuator2`-style processors in `org.tron.core.vm.nativecontract`.

### Finding Description
`FreezeBalanceV2Processor` was hardened with a fork-gated check that throws `OutOfTimeException` when `repository.isSelfDestructed(ownerAddress)` is true, as shown by the dedicated regression test `StakeV2AfterSelfDestructTest.freezeAfterSelfDestructIsForkGated` [2](#0-1) . This proves the java-tron team recognized that a contract can call `SELFDESTRUCT` and then, via a reentrant internal call in the same transaction context (before `Repository.commit()` finalizes the deletion), invoke a native staking precompile on the same, now-"destructed" address, producing state that is logically inconsistent with the address's imminent deletion from `AccountStore`.

A grep across the codebase shows the `isSelfDestructed(...)` guard only appears in `FreezeBalanceV2Processor.java` and nowhere else among the sibling native processors: `CancelAllUnfreezeV2Processor.java`, `UnfreezeBalanceV2Processor.java`, `WithdrawExpireUnfreezeProcessor.java`, `VoteWitnessProcessor.java`, `DelegateResourceProcessor.java`, and `UnDelegateResourceProcessor.java` . These processors are reachable the same way `FreezeBalanceV2Processor` is: through a TVM contract call/precompile that any unprivileged transaction sender can trigger via `TriggerSmartContract`.

The root cause parallels the Envoy bug: `RepositoryImpl.markSelfDestruct` only records intent in an in-memory `selfDestructCache`; the actual account row remains readable/writable via `getAccount`/`updateAccount` until commit [3](#0-2) . Any code path that fails to consult `isSelfDestructed` before mutating stake/vote/delegation state operates on a "removed" object exactly like Envoy's CORS filter dereferencing a removed `origin` header — the difference being the consequence here is corrupted ledger state (frozen balances, votes, or delegated resources anchored to an address whose `AccountCapsule` disappears) rather than a segfault.

### Impact Explanation
If any of the un-guarded processors (`UnfreezeBalanceV2Processor`, `CancelAllUnfreezeV2Processor`, `WithdrawExpireUnfreezeProcessor`, `VoteWitnessProcessor`, `DelegateResourceProcessor`, `UnDelegateResourceProcessor`) can, in fact, be invoked on a self-destructed contract address within the same transaction before commit (mirroring the exact call pattern `StakeV2AfterSelfDestructTest` exercises for freeze), the result would be stake/vote/delegated-resource capsules keyed to an address that is deleted from `AccountStore` at commit time. This can manifest as:
- Permanently frozen/unbacked balances (funds recorded as frozen or delegated to/from an address that no longer exists in `AccountStore`), and
- Orphaned vote or delegation records that can no longer be reconciled by legitimate account operations, since the account row backing them is gone.

This satisfies the "permanent freezing of funds / unbacked balance" impact bar.

### Likelihood Explanation
Reachability requires only a contract deployer to write a contract that calls `SELFDESTRUCT`/`suicide2` and then, in the same call frame or via a subsequent internal call before the outer transaction commits, invokes one of the un-guarded native precompiles on `getContextAddress()`/`self`. This is a single-transaction, unprivileged attack surface (any TVM contract call), consistent with the existing test harness `StakeV2AfterSelfDestructTest`, which was clearly created because this exact scenario was found problematic for `FreezeBalanceV2Processor`. Whether the other six processors are actually exploitable this way could not be fully confirmed from the index (their full source was not retrieved in this session), so this should be verified by reading each processor's `validate`/`execute` implementation directly.

### Recommendation
Audit `CancelAllUnfreezeV2Processor`, `UnfreezeBalanceV2Processor`, `WithdrawExpireUnfreezeProcessor`, `VoteWitnessProcessor`, `DelegateResourceProcessor`, and `UnDelegateResourceProcessor` for the same `repository.isSelfDestructed(ownerAddress)` fork-gated guard that `FreezeBalanceV2Processor` has, and add equivalent regression tests analogous to `StakeV2AfterSelfDestructTest` for each.

### Proof of Concept
Not fully constructible from the indexed code alone — the concrete PoC would require confirming that `CALL`/`DELEGATECALL` reentrancy back into the self-destructed contract's context, occurring after `suicide2()`/`markSelfDestruct()` but before the top-level `Repository.commit()`, actually reaches `UnfreezeBalanceV2Processor.execute()` (or one of the other listed processors) with the destructed address as owner. The existing test `StakeV2AfterSelfDestructTest.freezeAfterSelfDestructIsForkGated` [4](#0-3)  demonstrates the pattern for `FreezeBalanceV2Processor` and should be replicated against the un-guarded processors to confirm exploitability; this requires reading their full `validate()`/`execute()` bodies, which were not available in the index during this investigation.

  @Override
  public boolean isSelfDestructed(byte[] address) {
    Key key = Key.create(address);
    if (selfDestructCache.contains(key)) {
      return true;
    }

    if (parent != null) {
      boolean isSelfDestructed = parent.isSelfDestructed(address);
      if (isSelfDestructed) {
        selfDestructCache.add(key);
      }
      return isSelfDestructed;
    } else {
      return false;
    }
  }
