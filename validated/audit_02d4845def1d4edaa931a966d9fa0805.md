### Title
Unstaked attacker can churn aborted QUIC handshakes to bypass `ConnectionRateLimiter` and `overall_connection_rate_limiter` accounting, forcing unbounded-rate asymmetric TLS handshake work - ([File: streamer/src/nonblocking/quic.rs])

### Summary
`ConnectionRateLimiter::register_connection` and `overall_connection_rate_limiter.consume_tokens` are only invoked inside `setup_connection` after a QUIC handshake *succeeds* (the `Ok(new_connection)` branch), not when it times out or is aborted by the peer. An unstaked attacker who opens a connection and aborts it before the handshake completes never consumes a rate-limiter token, so the per-IP and global connection-attempt limiters never engage against repeated abusive attempts, even though each attempt still forces the server to perform expensive asymmetric TLS handshake crypto.

### Finding Description
In `run_server` (`streamer/src/nonblocking/quic.rs`), incoming connections pass two *peek-only* checks before a handshake is even attempted: [1](#0-0) 
Neither `overall_connection_rate_limiter.current_tokens() == 0` nor `rate_limiter.is_allowed(...)` consumes a token — they only test whether existing balances are exhausted. Actual token consumption happens later, in `setup_connection`, but only inside the successful-handshake branch: [2](#0-1) 
If the handshake times out or fails/gets aborted, execution instead goes to `handle_connection_error`, which only increments error stats and never touches `rate_limiter` or `overall_connection_rate_limiter`: [3](#0-2) 

Because of this, an attacker that repeatedly opens a QUIC connection and aborts it before `connecting` resolves `Ok` never causes either limiter's token bucket to be decremented. The only resource guard active during the un-completed handshake window is `ClientConnectionTracker`, which caps the number of *concurrently* in-flight connection attempts to `qos.max_concurrent_connections()`: [4](#0-3) 
`ClientConnectionTracker` is dropped (freeing a slot) as soon as `setup_connection` returns, including on the abort/error path, so an attacker that deliberately resets the connection as soon as it's initiated frees the slot almost immediately (bounded only by RTT), letting it re-open a new connection and repeat. This defeats the code's own stated design goal in the comment directly above the checks — "protect against connection attempt bursts with a global rate-limiter" and "rate-limit abusive peers by (control-asserted) ip" — because both of those limiters are gated on handshake *success*, not on the attempt itself, and thus never fire for a churn attacker who intentionally never completes the handshake.

`configure_server` in `streamer/src/quic.rs` shows no stateless-retry/address-validation cookie step is configured before the full crypto handshake begins, so the server performs the expensive TLS 1.3 handshake (including client-certificate signature verification via `get_remote_pubkey`) for every attempted connection, regardless of whether it will be aborted.

### Impact Explanation
This falls into the "attacker cheaply forces work that vastly exceeds fees ever collected" category: an unstaked, fee-paying-nothing remote peer can force the leader's QUIC endpoint to repeatedly perform asymmetric TLS handshake cryptography (ECDHE + certificate signature verification) at a rate limited only by `max_concurrent_connections` and attacker RTT/bandwidth, rather than by `max_connections_per_ipaddr_per_min` or the global `TOTAL_CONNECTIONS_PER_SECOND` bucket that are supposed to bound exactly this kind of load. This degrades leader CPU availability for legitimate sigverify/scheduling/buffering work with zero cost to the attacker.

### Likelihood Explanation
Fully reachable by an unprivileged, unstaked remote attacker with only network reachability to the public TPU QUIC port — no stake, keys, or special config needed. The attack is simple to script (open connection, abort before `Connecting` resolves, repeat) and is directly reproducible against the existing test harness (`setup_quic_server`/`make_client_endpoint` in the `streamer/src/nonblocking/quic.rs` test module).

### Recommendation
Consume (or at least provisionally reserve) rate-limiter tokens at connection-*attempt* time (i.e., when `incoming.accept()` is called, before the handshake completes), not only on successful completion. If an attempt subsequently fails/aborts/times out, the token can either remain consumed (charging the cost of the attempt) or be refunded on success — but the token bucket should never be entirely blind to aborted attempts, since those are exactly the requests that cost CPU without producing a legitimate accepted connection.

### Proof of Concept
Integration test plan (extends existing `setup_quic_server`/`make_client_endpoint` test scaffolding in `streamer/src/nonblocking/quic.rs`):
```rust
#[tokio::test(flavor = "multi_thread")]
async fn test_handshake_churn_bypasses_rate_limiters() {
    let SpawnTestServerResult { stats, server_address, cancel, join_handle, .. } =
        setup_quic_server(
            None,
            QuicStreamerConfig { max_connections_per_ipaddr_per_min: 2, ..QuicStreamerConfig::default_for_tests() },
            SwQosConfig::default(),
        );

    // Repeatedly connect and abort *before* the handshake future resolves,
    // simulating churn that never triggers `register_connection`.
    for _ in 0..500 {
        let endpoint_fut = make_client_endpoint(&server_address, None);
        // Race a very short timeout against the connect future so we abort
        // before the server-side `connecting` resolves Ok.
        let _ = tokio::time::timeout(Duration::from_micros(1), endpoint_fut).await;
    }
    tokio::time::sleep(Duration::from_millis(500)).await;

    // Expect: total_incoming_connection_attempts is large (churn succeeded),
    // but neither per-IP nor global limiter counters grew proportionally,
    // proving the abusive attempts were never accounted against the limiters
    // meant to bound them.
    assert!(stats.total_incoming_connection_attempts.load(Ordering::Relaxed) > 100);
    assert_eq!(stats.connection_rate_limited_per_ipaddr.load(Ordering::Relaxed), 0);
    assert_eq!(stats.connection_rate_limited_across_all.load(Ordering::Relaxed), 0);

    cancel.cancel();
    join_handle.await.unwrap();
}
```
Expected result: the assertions pass on current code, demonstrating that hundreds of aborted handshake attempts from a single IP incur zero rate-limiting even though `max_connections_per_ipaddr_per_min` was set to 2, confirming the bypass.
