## #Vulnerability found for this question

### Title
Stale trust in already-established tunnels after CA removal enables continued CA-scoped firewall bypass and traffic flow with a revoked CA - (File: `firewall.go`, `connection_manager.go`, `cert/ca_pool.go`)

### Summary
The reported bug class is: an "accepted" trust list (`TokenManager.acceptedTokens`) can have an entry removed, but dependent security logic (`liquidate`, `claimRewards`) keeps operating on stale per-entity state (`minted`, `rewards`) that was never invalidated for the removed entry, letting the attacker keep both sides of the trust relationship. The same class of bug is reachable in nebula's certificate-authority trust model: `CAPool` is the "accepted CA list," and when a CA is removed from that list on reload, already-established tunnels signed by the removed CA are not immediately severed. Instead, invalidation is deferred to a periodic background check that is itself gated by a config flag, and the firewall's CA-based rule matching does not re-validate current CA trust for one of its two lookup paths.

### Finding Description
`CAPool.AddCA`/pool construction builds the "accepted CAs" map keyed by fingerprint, and `GetCAForCert` performs a pure map lookup with **no signature validation performed** (per its own doc comment): [1](#0-0) 

When the CA pool is reloaded (e.g. an admin edits `pki.ca` to drop a compromised/rotated CA), an entirely new `CAPool` is built and swapped in atomically: [2](#0-1) 

However, this swap by itself does **not** tear down tunnels that were already established with certificates signed by the now-removed CA. Invalidation of existing sessions is deferred to the connection manager's periodic traffic check, `isInvalidCertificate`, which re-verifies the peer's cached certificate against the *current* `CAPool`: [3](#0-2) 

Critically, whether an invalid/no-longer-trusted certificate actually causes teardown is gated by the `pki.disconnect_invalid` setting, which is only consulted for non-blocklisted invalidation (a removed CA is not the same as a blocklisted fingerprint): [4](#0-3) 

If `pki.disconnect_invalid` is set to `false` (or during the window before the next periodic check runs), the tunnel remains fully live: the Noise session was already established at handshake time and per-packet forwarding does not re-verify CA trust at all. The firewall's per-packet `Drop` path only uses the peer's cached certificate object and the CA pool for **rule matching**, not for trust re-validation: [5](#0-4) 

Within that rule matching, `FirewallCA.match` has two lookup paths — one keyed by CA name (which does cross-check the live `caPool` via `GetCAForCert`), and one keyed by `ca_sha`, which matches directly against the peer certificate's stored `Issuer()` fingerprint **without any cross-check against the current CAPool at all**: [6](#0-5) 

This mirrors the reported bug's core defect precisely: an item removed from an "accepted" list (`acceptedTokens` / CA pool) does not propagate synchronously into the dependent enforcement logic (`liquidate`/`claimRewards` loops / firewall CA-sha matching and live traffic forwarding), leaving stale privileged state (`minted=0` with collateral untouched / an established encrypted tunnel and matching `ca_sha` firewall rule) that a peer can continue to exploit after the removal.

### Impact Explanation
An operator who revokes trust in a CA by removing it from `pki.ca` cannot rely on that action alone to cut off already-connected peers signed by that CA:
- With `pki.disconnect_invalid: false` (a supported, documented configuration), sessions with revoked-CA peers persist indefinitely, allowing continued decrypted traffic flow and continued matching of `ca_sha`-scoped firewall allow rules, since `FirewallCA.match`'s `ca_sha` branch never reconsults the live `CAPool`.
- Even with the default `true`, there is a window (bounded by the connection manager's traffic-check interval) during which a peer whose CA was just revoked keeps full data-plane access, because the firewall's per-packet path performs no CA-trust re-check — only rule matching.

This is a remote state-poisoning / stale-authorization issue: the enforcement point (firewall, per-packet forwarding) trusts state (the established `ConnectionState`/cached cert) that a security-relevant control-plane action (CA removal) was supposed to invalidate but did not immediately propagate.

### Likelihood Explanation
This requires an administrator action (CA removal via config reload) combined with either the `pki.disconnect_invalid: false` setting or simply timing relative to the periodic connection-manager check — both are realistic, reachable, attacker-independent operational conditions rather than a malicious-peer-only scenario, since the "attacker" here is simply any peer who legitimately held a certificate from the now-untrusted CA and continues using their already-established tunnel.

### Recommendation
- Have CA-pool reload actively walk the hostmap and immediately tear down (or re-verify) any hostinfo whose peer certificate's issuer is no longer present in the new `CAPool`, rather than relying solely on the next periodic `isInvalidCertificate` traffic check.
- Make CA revocation via pool removal behave like blocklisting (i.e., always disconnect), independent of `pki.disconnect_invalid`, since removal is an explicit trust decision, not a passive expiry.
- In `FirewallCA.match`, cross-check the `ca_sha` lookup against `caPool.GetCAForCert`/`CAs` map membership (like the `CANames` path already does) so a `ca_sha` rule cannot continue to match traffic from a certificate whose issuing CA has been removed from the live pool.

### Proof of Concept
1. Start a nebula node with `pki.disconnect_invalid: false` and a firewall rule using `ca_sha: <fingerprint-of-CA-A>`.
2. Establish a tunnel with a peer whose certificate is signed by CA-A.
3. Reload the node's config with `pki.ca` no longer containing CA-A (revoking it) — `PKI.reload` swaps in a new `CAPool` via [7](#0-6)  without tearing down the existing tunnel.
4. Continue sending traffic through the existing tunnel: `Firewall.Drop` still permits it via `inConns`/`table.match`, and any `ca_sha`-scoped rule still matches per `FirewallCA.match`'s `CAShas` branch at [8](#0-7) , since that branch never re-checks `caPool` for current trust — traffic keeps flowing from a peer whose CA was explicitly revoked.

// GetCAForCert attempts to return the signing certificate for the provided certificate.
// No signature validation is performed
func (ncp *CAPool) GetCAForCert(c Certificate) (*CachedCertificate, error) {
	issuer := c.Issuer()
	if issuer == "" {
		return nil, fmt.Errorf("no issuer in certificate")
	}

	signer, ok := ncp.CAs[issuer]
	if ok {
		return signer, nil
	}

	return nil, ErrCaNotFound
}

// isInvalidCertificate decides if we should destroy a tunnel.
// returns true if pki.disconnect_invalid is true and the certificate is no longer valid.
// Blocklisted certificates will skip the pki.disconnect_invalid check and return true.
func (cm *connectionManager) isInvalidCertificate(now time.Time, hostinfo *HostInfo) bool {
	remoteCert := hostinfo.GetCert()
	if remoteCert == nil {
		return false //don't tear down tunnels for handshakes in progress
	}

	caPool := cm.intf.pki.GetCAPool()
	err := caPool.VerifyCachedCertificate(now, remoteCert)
	if err == nil {
		return false //cert is still valid! yay!
	} else if err == cert.ErrBlockListed { //avoiding errors.Is for speed
		// Block listed certificates should always be disconnected
		hostinfo.logger(cm.l).Info("Remote certificate is blocked, tearing down the tunnel",
			"error", err,
			"fingerprint", remoteCert.Fingerprint,
		)
		return true
	} else if cm.intf.disconnectInvalid.Load() {
		hostinfo.logger(cm.l).Info("Remote certificate is no longer valid, tearing down the tunnel",
			"error", err,
			"fingerprint", remoteCert.Fingerprint,
		)
		return true
	} else {
		//if we reach here, the cert is no longer valid, but we're configured to keep tunnels from now-invalid certs open
		return false
	}
}

// Drop returns an error if the packet should be dropped, explaining why. It
// returns nil if the packet should not be dropped.
func (f *Firewall) Drop(fp firewall.Packet, incoming bool, h *HostInfo, caPool *cert.CAPool, localCache firewall.ConntrackCache) error {
	// Make sure remote address matches nebula certificate, and determine how to treat it
	if h.networks == nil {
		// Simple case: Certificate has one address and no unsafe networks
		if h.vpnAddrs[0] != fp.RemoteAddr {
			f.metrics(incoming).droppedRemoteAddr.Inc(1)
			return ErrInvalidRemoteIP
		}
	} else {
		nwType, ok := h.networks.Lookup(fp.RemoteAddr)
		if !ok {
			f.metrics(incoming).droppedRemoteAddr.Inc(1)
			return ErrInvalidRemoteIP
		}
		switch nwType {
		case NetworkTypeVPN:
			break // nothing special
		case NetworkTypeVPNPeer:
			f.metrics(incoming).droppedRemoteAddr.Inc(1)
			return ErrPeerRejected // reject for now, one day this may have different FW rules
		case NetworkTypeUnsafe:
			break // nothing special, one day this may have different FW rules
		default:
			f.metrics(incoming).droppedRemoteAddr.Inc(1)
			return ErrUnknownNetworkType //should never happen
		}
	}

	// Make sure we are supposed to be handling this local ip address
	if !f.routableNetworks.Contains(fp.LocalAddr) {
		f.metrics(incoming).droppedLocalAddr.Inc(1)
		return ErrInvalidLocalIP
	}

	// Check if we spoke to this tuple, if we did then allow this packet
	if f.inConns(fp, h, caPool, localCache) {
		return nil
	}

	table := f.OutRules
	if incoming {
		table = f.InRules
	}

	// We now know which firewall table to check against
	if !table.match(fp, incoming, h.ConnectionState.peerCert, caPool) {
		f.metrics(incoming).droppedNoRule.Inc(1)
		return ErrNoMatchingRule
	}

	// We always want to conntrack since it is a faster operation
	f.addConn(fp, incoming)

	return nil
}

func (fc *FirewallCA) match(p firewall.Packet, c *cert.CachedCertificate, caPool *cert.CAPool) bool {
	if fc == nil {
		return false
	}

	if fc.Any.match(p, c) {
		return true
	}

	if t, ok := fc.CAShas[c.Certificate.Issuer()]; ok {
		if t.match(p, c) {
			return true
		}
	}

	s, err := caPool.GetCAForCert(c.Certificate)
	if err != nil {
		return false
	}

	return fc.CANames[s.Certificate.Name()].match(p, c)
}
