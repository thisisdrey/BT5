### Title
Unhealthy positions become permanently unliquidatable when `debtFloorInUsd` and `maxLiquidable` interact — (`contracts/Pool.sol`)

### Summary
`Pool.liquidate` enforces two constraints on `amountToRepay_`: it cannot exceed `maxLiquidable` of the account's debt, and the remaining debt after repayment must be either zero or above `debtFloorInUsd`. When a position's debt is such that repaying the maximum allowed fraction leaves a nonzero remainder below `debtFloorInUsd`, every possible `amountToRepay_` reverts, making the unhealthy position impossible to liquidate — a liveness break structurally identical to the M-9 bug (a size check re-applied at fill time blocks an operation that was valid at creation time).

### Finding Description
In `Pool.liquidate`:

- `amountToRepay_.wadDiv(_debtTokenBalance) > maxLiquidable` reverts with `AmountGreaterThanMaxLiquidable` — so the liquidator cannot repay the full debt when `maxLiquidable < 1e18`.
- The remaining debt `_debtTokenBalance - amountToRepay_` is quoted to USD and reverts with `RemainingDebtIsLowerThanTheFloor` if it lands in `(0, debtFloorInUsd)`. [1](#0-0) 

These two checks create a forbidden band. If `debtInUsd` is in the range `(debtFloorInUsd, debtFloorInUsd / (1 - maxLiquidable))`, then:

- Repaying the full debt is required to reach remaining debt `== 0` (the only non-reverting outcome), but full repay exceeds `maxLiquidable` when `maxLiquidable < 1e18`.
- Any repay at or below `maxLiquidable` leaves remaining debt in `(0, debtFloorInUsd)`, reverting.

The position enters this band through ordinary market movement: a user mints debt well above the floor (valid at creation, like the StopLimit order in M-9), then the collateral price drops or the synth price moves so the debt value slides into the forbidden band — exactly as the USDC price drop pushed the Bracket order under `minOrderSize`. The same `debtFloorInUsd` check exists in `DebtToken.repay`, so the borrower also cannot partially repay to escape the band — only `repayAll` works for them, and third-party liquidators have no such escape. [2](#0-1) 

The test suite confirms both reverts but never tests their combination (each "debt floor" test uses `maxLiquidable = 100%`). [3](#0-2) 

### Impact Explanation
Direct loss of core protocol functionality: while the position sits in the forbidden band no liquidator can touch it, so if collateral continues to fall the position accrues bad debt that cannot be cleared — protocol insolvency risk. The borrower is also trapped: they cannot reduce leverage via `repay` (any partial repay leaving sub-floor dust reverts) and SmartFarmingManager unwind paths that repay partially would revert; their funds are effectively frozen until they can source enough synth to `repayAll` or exit entirely.

### Likelihood Explanation
Requires `debtFloorInUsd > 0` and `maxLiquidable < 1e18` to be configured together — a plausible deployed configuration since both are independently useful governor controls and their interplay is undocumented. Once set, no attacker action or privileged role is needed; ordinary oracle price movement pushes positions into the band, and any unprivileged liquidator calling the public `liquidate` observes the revert.

### Recommendation
Skip or relax the floor check inside `liquidate` when the post-repay remainder would fall below `debtFloorInUsd` — e.g., clamp `amountToRepay_` up to the full balance when `remaining < debtFloorInUsd`, so the liquidation closes the position entirely (mirroring M-9's fix of bypassing `checkMinOrderSize` for internal order creation). Alternatively, allow `repay`-path callers to clear sub-floor remainders.

### Proof of Concept
Hardhat, extending `test/Pool.test.ts`:

```ts
it('position is unliquidatable when max repay leaves dust below floor', async function () {
  // debt = 1 msETH ($4,000); collateral price dropped so position is unhealthy
  await pool.updateDebtFloor(parseEther('3000'))          // floor = $3,000
  await pool.updateMaxLiquidable(parseEther('0.5'))       // max 50% repayable
  const debt = await msEthDebtToken.balanceOf(alice.address) // 1 msETH

  // full repay → exceeds maxLiquidable
  await expect(
    pool.connect(liquidator).liquidate(msEth.address, alice.address, debt, msdMET.address)
  ).revertedWithCustomError(pool, 'AmountGreaterThanMaxLiquidable')

  // 50% repay → remaining $2,000 < $3,000 floor
  await expect(
    pool.connect(liquidator).liquidate(msEth.address, alice.address, debt.div(2), msdMET.address)
  ).revertedWithCustomError(pool, 'RemainingDebtIsLowerThanTheFloor')

  // alice herself cannot partially repay out of the band
  await expect(
    msEthDebtToken.connect(alice).repay(alice.address, debt.div(4))
  ).revertedWithCustomError(msEthDebtToken, 'RemainingDebtIsLowerThanTheFloor')
})
```

Any `amountToRepay_` in `(0, debt]` either exceeds `maxLiquidable` (when `> debt/2`) or leaves remainder `< floor` (when `≤ debt/2` only escapes if `debt - x ≥ floor`, i.e. `x ≤ debt - floor`; for debt in the band `debt - floor < maxLiquidable·debt`... concretely with debt=$4,000, floor=$3,000, max=50%: allowed repay ≤ $2,000 leaves ≥ $2,000 < $3,000 — always reverts). Position is permanently stuck until prices move it out of the band.
