### Title
Griefing attack: dust `repay` front-running reverts victim's full/partial debt repayment - (File: contracts/DebtToken.sol)

### Summary
`DebtToken.repay(onBehalfOf_, amount_)` lets anyone repay debt on behalf of any account. Because the repaid amount is a caller-supplied absolute value rather than "repay up to the current balance," an attacker can front-run a victim's `repay` transaction with a dust repayment of their own synthetic tokens. The victim's transaction then reverts — either via arithmetic underflow at `balanceOf(onBehalfOf_) - _repaid` (line 446) or via `BurnAmountExceedsBalance` in `_burn` (line 529) — at a cost to the attacker of a few wei of synthetic token. This is the same bug class as the papr `_reduceDebt` underflow griefing.

### Finding Description
`repay` is permissionless with respect to `onBehalfOf_`: [1](#0-0) 

The flow:
1. `(_repaid, _fee) = quoteRepayOut(amount_)` — `_repaid` is derived from the caller's `amount_`, not clamped to the target's debt.
2. If `debtFloorInUsd > 0`, `balanceOf(onBehalfOf_) - _repaid` is computed at line 446 and underflows when `_repaid > balanceOf`.
3. Even when `debtFloorInUsd == 0`, `_burn` reverts with `BurnAmountExceedsBalance` if `_accountBalance < amount_` (line 529).

Attack scenario:
- Alice has `D` debt and submits `repay(alice, D_gross)` (gross amount covering `D` plus repay fee) to fully close her position — e.g., to unlock/withdraw collateral in a follow-up or same-tx bundle via `Operator.execute`/`SmartFarmingManager`.
- Bob front-runs with `repay(alice, dustAmount)`, where `dustAmount` is chosen so `quoteRepayOut` yields `_repaid = 1` (or any small amount). Bob burns ~1 wei of his own `msSynthetic`.
- Alice's debt is now `D - 1`. Her transaction tries to repay `D`, computes `balanceOf(alice) - _repaid = (D-1) - D` → underflow (or `BurnAmountExceedsBalance`), and reverts.
- Bob can repeat this every time Alice resubmits, paying ~1 wei of synth each time. Because debt grows with interest, Alice cannot simply retry the same calldata; she must recompute and hope Bob doesn't front-run again.

The same griefing applies to any integrated flow that computes a fixed repay amount off-chain or on-chain before calling `repay` — e.g. `SmartFarmingManager.flashRepay`/`leverage` unwind paths that burn a precomputed amount — making the whole multi-step zap revert.

Note `repayAll` is immune (it reads `balanceOf` fresh at line 478), but `repay` is not, and callers needing to pay an exact amount (e.g. limiting how much synth is burned, or zaps precomputing amounts) must use `repay`.

### Impact Explanation
Temporary denial of service / griefing: an unprivileged attacker can repeatedly revert any user's attempt to repay debt via `repay` — including full repayment needed to close a position and withdraw collateral — at near-zero cost (dust amounts of synthetic token). Funds are not stolen, but the victim's repayment path is blocked as long as the attacker keeps front-running, matching the accepted severity of the reference finding.

### Likelihood Explanation
- Requires only a mempool front-run (or back-run ordering on L2s with public sequencing) and a dust amount of the synthetic token, which the attacker can buy or issue cheaply.
- No privileged role, no oracle manipulation, no flash loan needed.
- Natural interest accrual already makes exact-amount `repay` calls fragile, so users are pushed toward precomputed amounts — precisely the case the attacker exploits.
- Constraints: if `repayFee > 0`, `quoteRepayOut` rounds down, so the attacker must pick `amount_` that yields `_repaid >= 1`; if `debtFloorInUsd > 0`, the attacker's dust repay must leave the victim's remaining debt ≥ floor (easily satisfied — it only reduces debt by dust) or repay it fully (which the attacker won't do since that pays the victim's whole debt). Neither check blocks the attack.

### Recommendation
Clamp the repaid amount to the beneficiary's actual debt inside `repay`, e.g.:

```solidity
uint256 _debt = balanceOf(onBehalfOf_);
if (_repaid > _debt) {
    _repaid = _debt;
    // recompute/burn only the corresponding gross amount or refund the excess
}
```

Alternatively, change the semantics so `amount_` is treated as a maximum and only `min(_repaid, debt)` is burned. This mirrors the upstream fix of clamping `amount` to the stored debt in `_reduceDebtWithoutBurn`.

### Proof of Concept
Foundry fork sketch against a deployed `DebtToken` (e.g. `MsUSDDebt` on Base):

```solidity
// SPDX-License-Identifier: MIT
pragma solidity 0.8.24;

import "forge-std/Test.sol";
import {DebtToken} from "../contracts/DebtToken.sol";
import {ISyntheticToken} from "../contracts/interfaces/ISyntheticToken.sol";

contract RepayGriefingTest is Test {
    DebtToken debtToken;      // deployed DebtToken on fork
    ISyntheticToken synth;    // its syntheticToken()
    address alice = makeAddr("alice"); // pre-existing debtor
    address bob = makeAddr("bob");

    function test_dustRepayGriefsFullRepay() public {
        uint256 aliceDebt = debtToken.balanceOf(alice);
        assertGt(aliceDebt, 0);

        // Bob obtains a small amount of synth (issue or buy), then:
        vm.startPrank(bob);
        // choose dust so quoteRepayOut(dust) >= 1 but << aliceDebt
        (uint256 repaidDust,) = debtToken.quoteRepayOut(1e10);
        debtToken.repay(alice, 1e10); // front-run: burns Bob's synth, Alice debt -= repaidDust
        vm.stopPrank();

        // Alice's precomputed full repayment now reverts
        uint256 gross;
        // gross was computed off-chain before Bob's tx to cover old aliceDebt + fee
        (gross,) = debtToken.quoteRepayIn(aliceDebt);
        deal(address(synth), alice, gross);
        vm.prank(alice);
        vm.expectRevert(); // underflow at line 446 or BurnAmountExceedsBalance at line 529
        debtToken.repay(alice, gross);
    }
}
```

Steps: fork a chain where a debtor exists, have Bob front-run with a dust `repay(alice, dust)`, then Alice's fixed-amount `repay` reverts deterministically. Repeatability: Bob can repeat for every resubmission at ~1 wei of synth per attempt.

    function repay(
        address onBehalfOf_,
        uint256 amount_
    )
        external
        override
        whenNotShutdown
        nonReentrant
        onlyIfSyntheticTokenExists
        returns (uint256 _repaid, uint256 _fee)
    {
        if (amount_ == 0) revert AmountIsZero();

        accrueInterest();

        address _msgSender = _msgSender();
        IPool _pool = pool;
        ISyntheticToken _syntheticToken = syntheticToken;

        (_repaid, _fee) = quoteRepayOut(amount_);
        if (_fee > 0) {
            _syntheticToken.seize(_msgSender, _pool.feeCollector(), _fee);
        }

        uint256 _debtFloorInUsd = _pool.debtFloorInUsd();
        if (_debtFloorInUsd > 0) {
            uint256 _newDebtInUsd = _pool.masterOracle().quoteTokenToUsd(
                address(_syntheticToken),
                balanceOf(onBehalfOf_) - _repaid
            );
            if (_newDebtInUsd > 0 && _newDebtInUsd < _debtFloorInUsd) {
                revert RemainingDebtIsLowerThanTheFloor();
            }
        }

        _syntheticToken.burn(_msgSender, _repaid);
        _burn(onBehalfOf_, _repaid);

        emit DebtRepaid(_msgSender, onBehalfOf_, amount_, _repaid, _fee);
    }
