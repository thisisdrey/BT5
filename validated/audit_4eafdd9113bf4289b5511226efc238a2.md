### Title
Unauthenticated `/stackerdb_chunks` POST endpoint allows forged `SignerEvent::SignerMessages` with attacker-controlled pubkey/slot pairing - (File: `libsigner/src/events.rs`)

### Summary
`SignerEventReceiver::next_event` accepts any HTTP POST to `/stackerdb_chunks` on its bound socket with no shared secret, TLS, or IP allow-list, and the `TryFrom<StackerDBChunksEvent> for SignerEvent<T>` conversion only calls `chunk.recover_pk()` to obtain a public key from the attacker-supplied signature — it never checks that key against the actual slot owner recorded for that `slot_id` in the node's StackerDB configuration. Any remote party that can reach the bound port can self-sign a chunk with a throwaway key and have it delivered downstream as an authentic `SignerMessages` entry.

### Finding Description
The intended invariant is: "every message the signer library surfaces == a message an authorized StackerDB slot owner signed." In `libsigner/src/events.rs`, `SignerEventReceiver::bind` opens a plain `tiny_http` server with no authentication layer [1](#0-0) , and `next_event` dispatches any POST to `/stackerdb_chunks` straight into `process_event::<T, StackerDBChunksEvent>` [2](#0-1) , which JSON-deserializes the body and calls `TryInto<SignerEvent<T>>` with no source verification [3](#0-2) .

Inside `TryFrom<StackerDBChunksEvent> for SignerEvent<T>`, for a `signers-N-M` contract chunk, the code does:
```
let Ok(pk) = chunk.recover_pk() else { ... return None; };
...
Some((chunk.slot_id, pk, message))
``` [4](#0-3) 

`recover_pk()` only recovers *some* public key from the `sig` field over the chunk data — it does not consult any expected-owner mapping for `slot_id` (that mapping lives in the node's StackerDB config/DB, e.g. `stackslib/src/net/stackerdb/db.rs` and `config.rs`, which is never referenced from this conversion path). The recovered key is placed directly into `SignerEvent::SignerMessages { messages: Vec<(u32, StacksPublicKey, T)>, .. }` [5](#0-4)  and forwarded to consumers via `forward_event` without further checks [6](#0-5) .

Thus the equality "recovered-pubkey == expected-slot-owner-for-slot_id" is never evaluated anywhere in this path. Any party who can open a TCP connection to the bound address can POST a self-constructed `StackerDBChunksEvent` JSON body with a `slot_id` chosen arbitrarily and a chunk signed by a throwaway keypair; the library will accept it as `SignerEvent::SignerMessages` carrying that throwaway key as if it were the legitimate slot owner. This is corroborated by the actual code comment/warning in `stacks-signer/src/lib.rs` explicitly cautioning that exposing this endpoint beyond a local/trusted network "could potentially expose sensitive data or functionalities to security risks if additional proper security checks are not integrated" [7](#0-6) , confirming there is no such check present in code.

### Impact Explanation
An attacker reaching the signer's event-listener port can inject arbitrary, self-signed "signer messages" that bypass the node's genuine StackerDB chunk-ingestion signature verification entirely (that verification, done in `stackslib/src/net/stackerdb/db.rs`/`sync.rs`, is never exercised on this path since the attacker talks directly to the signer's HTTP listener, not through the node's StackerDB replication). The downstream signer runloop consumes `SignerEvent::SignerMessages` under the assumption the `(slot_id, pubkey)` pairing reflects a legitimate, on-chain-registered slot owner, which can lead to processing of forged signer protocol messages (e.g., spoofed nonce/vote/rejection messages attributed to an arbitrary key) — an unauthenticated write of forged data into signer runtime state. This matches "unauthenticated/unauthorized write to state" / "network-wide propagation of forged data" at Critical severity, repeatable per POST request.

### Likelihood Explanation
Preconditions: the attacker must be able to reach the TCP port the `SignerEventReceiver` is bound to. No secret, prior key, or privileged role is required — this is a bare HTTP POST with a JSON body. If the signer endpoint is reachable beyond `localhost` (a configuration the codebase itself warns against but does not prevent programmatically), exploitation cost is a single crafted HTTP request repeatable indefinitely.

### Recommendation
Add per-message authentication independent of the network transport: require the received `StackerDBChunkData`'s `slot_id`/contract pairing to be cross-checked against the signer's own record of the expected/authorized owner public key for that slot (obtained via the node's chainstate, not trusted blindly from the POST body), reject chunks whose `recover_pk()` result does not match that expected owner, and/or restrict the listener to loopback/mTLS/shared-secret-authenticated connections by default.

### Proof of Concept
1. Start a `SignerEventReceiver`/`Signer` bound to `127.0.0.1:<port>` as in `libsigner/src/tests/mod.rs`'s `test_status_endpoint` pattern.
2. From a separate "attacker" thread, construct a `StackerDBChunkData` with `slot_id` set to a real signer slot, sign it with a throwaway `Secp256k1PrivateKey` (not the configured slot owner), wrap it in a `StackerDBChunksEvent` for `signers-0-<id>.<contract>`, serialize to JSON, and POST it to `http://127.0.0.1:<port>/stackerdb_chunks`.
3. Assert that `running_signer.stop()` / the consumer channel yields `SignerEvent::SignerMessages { messages, .. }` containing a tuple whose `StacksPublicKey` equals the attacker's throwaway key's public key, at the target `slot_id` — with no rejection — confirming the missing equality check at `libsigner/src/events.rs:596-613`.

    fn forward_event(&mut self, ev: SignerEvent<T>) -> bool {
        if self.out_channels.is_empty() {
            // nothing to do
            error!("No channels connected to event receiver");
            false
        } else if self.out_channels.len() == 1 {
            // avoid a clone
            if let Err(e) = self.out_channels[0].send(ev) {
                error!("Failed to send to signer runloop: {:?}", &e);
                return false;
            }
            true
        } else {
            for (i, out_channel) in self.out_channels.iter().enumerate() {
                if let Err(e) = out_channel.send(ev.clone()) {
                    error!("Failed to send to signer runloop #{}: {:?}", i, &e);
                    return false;
                }
            }
            true
        }
    }
```

fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
