### Title
`HttpApiAccessFilter` disabled-API restriction can be bypassed via a crafted URL with canceling path segments - (File: `framework/src/main/java/org/tron/core/services/filter/HttpApiAccessFilter.java`)

### Summary
`HttpApiAccessFilter` is the single access-control gate that enforces the operator-configured `node.disabledApi` blocklist across the FullNode, SolidityNode and PBFT HTTP APIs. [1](#0-0) [2](#0-1)  Its `isDisabled` check derives the endpoint name from an incompletely-normalized URI path, and a crafted request path containing an extra directory segment followed by `..` causes the check to compute the wrong path element, letting the request slip past the block and reach an endpoint the node operator explicitly disabled. [3](#0-2) 

### Finding Description
`HttpApiAccessFilter.doFilter` builds `endpoint` from `contextPath + servletPath`, then calls `isDisabled(endpoint)`, which normalizes the URI and checks whether `endpoint.split("/")[2]` (the second path segment) is in the operator's `disabledApiList`: [4](#0-3) [3](#0-2) 

The bug is that `URI.create(endpoint).normalize()` only collapses `..` against the segment immediately preceding it. For a URL like `/wallet/a/b/../getnowblock`, normalization removes `b/..`, producing `/wallet/a/getnowblock`. The filter then reads `split("/")[2]`, which is `"a"` — not `"getnowblock"` — so `disabledApiList.contains("a")` is false and the request is treated as *not disabled*, even though the disabled endpoint name is present in the URL. This is confirmed directly by the project's own unit test, which asserts the bypass: [5](#0-4) 

The same faulty `isDisabled` logic (and equivalent normalization gap) protects all `/wallet/*`, `/walletsolidity/*`, monitoring and node-info endpoints across `FullNodeHttpApiService`, `SolidityNodeHttpApiService` and `HttpApiOnPBFTService`, including sensitive read paths such as `/wallet/listnodes`, `/monitor/getstatsinfo`, and `/monitor/getnodeinfo` that operators may deliberately disable to reduce information exposure. [6](#0-5)  This mirrors the Liferay advisory's bug class: a security-relevant access restriction is bypassed by a specially crafted URL that the restriction-check logic fails to canonicalize/interpret consistently with how the underlying request is actually routed and served.

### Impact Explanation
Any unauthenticated remote client can craft an HTTP GET/POST request path containing a benign extra segment plus a `..` component to reach an HTTP API endpoint the node operator explicitly placed in `node.disabledApi` to restrict exposure (e.g., node topology/peer info via `listnodes`, `getnodeinfo`, or account/blockchain query endpoints an operator wanted hidden for security or resource reasons). This is a confidentiality/access-control violation matching CWE-862 (Missing Authorization) — the node continues to expose an API surface its configuration says it should not serve, directly analogous to the Liferay CVE's unauthorized access to a restricted resource via a crafted URL.

### Likelihood Explanation
The bypass requires only a single unauthenticated HTTP request with a specific URL pattern (`/wallet/<segment>/<segment>/../<disabled-endpoint>`), reachable by any anonymous API client with no special conditions, and is deterministically reproduced by the codebase's own test. [7](#0-6) 

### Recommendation
Fix `isDisabled` in `HttpApiAccessFilter` (and the analogous `RpcApiAccessInterceptor.isDisabled` if it has similar assumptions) to derive the endpoint name from the fully resolved/canonical servlet path as actually dispatched by the container, rather than re-deriving it from a partially normalized raw string split by index. Prefer using the container-resolved `HttpServletRequest.getServletPath()`/`getPathInfo()` post-dispatch, or perform full canonicalization (repeated normalization until stable, and reject paths still containing `..` after canonicalization) before extracting the endpoint segment used for the blocklist comparison. [3](#0-2) 

### Proof of Concept
1. Configure `node.disabledApi = ["getnowblock"]` on a running FullNode.
2. Send `GET /wallet/getnowblock` — the node correctly returns `{"Error":"this API is unavailable due to config"}` per `HttpApiAccessFilter`. [8](#0-7) 
3. Send `GET /wallet/a/b/../getnowblock` — reproduced by the existing test `testIsDisabled`, `isDisabled` returns `false` for this path, so the filter's blocking branch is skipped and the request is forwarded to the `getnowblock` servlet, defeating the operator's restriction. [9](#0-8)

  public void doFilter(ServletRequest request, ServletResponse response, FilterChain chain) {
    try {
      if (request instanceof HttpServletRequest) {
        String contextPath = ((HttpServletRequest) request).getContextPath();
        String endpoint = contextPath + ((HttpServletRequest) request).getServletPath();
        HttpServletResponse resp = (HttpServletResponse) response;

        if (isDisabled(endpoint)) {
          resp.setStatus(HttpServletResponse.SC_NOT_FOUND);
          resp.setContentType("application/json; charset=utf-8");
          JSONObject jsonObject = new JSONObject();
          jsonObject.put("Error", "this API is unavailable due to config");
          resp.getWriter().println(jsonObject.toJSONString());
          return;
        }

        CharResponseWrapper responseWrapper = new CharResponseWrapper(resp);
        chain.doFilter(request, responseWrapper);

      } else {
        chain.doFilter(request, response);
      }

    } catch (Exception e) {
      logger.error("http api access filter exception: {}", e.getMessage());
    }
  }

  private boolean isDisabled(String endpoint) {
    boolean disabled = false;

    try {
      endpoint = URI.create(endpoint).normalize().toString();
      List<String> disabledApiList = CommonParameter.getInstance().getDisabledApiList();
      if (!disabledApiList.isEmpty()) {
        disabled = disabledApiList.contains(endpoint.split("/")[2].toLowerCase(Locale.ROOT));
      }
    } catch (Exception e) {
      logger.warn("check isDisabled except, endpoint={}, {}", endpoint, e.getMessage());
    }

    return disabled;
  }
