### Title
Oversized receipt bypasses bandwidth grant due to clamped size accounting in `try_forward` - ([File: runtime/runtime/src/congestion_control.rs])

### Summary
`ReceiptSinkV2::try_forward` clamps any receipt's counted size to `max_receipt_size` before checking/deducting it against the receiving shard's bandwidth `forward_limit.size`, even though a receipt can legitimately exceed `max_receipt_size` after `output_data_receivers` are appended post-validation (as in nested `promise_and`/`promise_return` DAGs). This lets an oversized receipt consume less bandwidth budget than its real size, forwarding it to a shard whose grant did not account for the extra bytes.

### Finding Description
In `try_forward`, the size used for the bandwidth-limit check and deduction is clamped: [1](#0-0)  The comment explicitly acknowledges "There is a bug which allows to create receipts that are above the size limit" and references https://github.com/near/nearcore/issues/12606, and the workaround pretends the receipt is `max_receipt_size` "to avoid receipts getting stuck." The clamped `size` (not the real serialized size) is what gets checked against `forward_limit.size` and subtracted from it: [2](#0-1) 

An unprivileged attacker can trigger the root cause of the oversized receipt via a contract-controlled promise DAG: a promise `A` executes, creates promise `C` sized at exactly `max_receipt_size`, and calls `promise_return`, which rewires the DAG so `C -then-> B`; this attaches `output_data_receivers` to `C`'s already-validated receipt after the size check, pushing its real serialized size above `max_receipt_size`. This exact scenario is codified in the existing regression test `test_max_receipt_size_promise_return`: [3](#0-2) , and the test explicitly asserts (via `assert_oversized_receipt_occurred`) that an oversized receipt does appear as an incoming receipt on-chain, confirming the size-limit check is bypassed. [4](#0-3) 

Because `try_forward` is called both from the immediate-forward path [5](#0-4)  and from the buffered-forward path [6](#0-5) , every oversized receipt that passes through the sink will have its true size under-counted against the receiver's `OutgoingLimit`, meaning the bandwidth scheduler's per-shard grant computed for the receiving shard does not reserve enough bandwidth for the real payload.

### Impact Explanation
This falls under a shard-halting/witness-blowup risk category: the receiving shard accepts a receipt whose actual bytes exceed what its bandwidth grant assumed, inflating the chunk's incoming-receipts data and witness size beyond the value the scheduler accounted for. The existing test comments explicitly state the receipt "should be rejected, but currently isn't" and separately note "The runtime shouldn't die when it encounters a large receipt" — indicating this was already identified internally as a liveness/availability concern rather than a fund-theft or consensus-divergence bug. No unit or integration evidence in this repo shows this clamp workaround causes chunk application failure, witness rejection, or state-root divergence; it is a known, tracked, and mitigated-by-clamp workaround (the receiving side still processes it without crashing per the test's assertion "runtime shouldn't die").

### Likelihood Explanation
Fully reachable by an unprivileged account: deploy a wasm contract with promise-chaining methods (`max_receipt_size_promise_return_method1`), fund an account, and submit ordinary function-call transactions — no validator/node privileges required. The `test_max_receipt_size_promise_return` test proves the construction is reliable and repeatable using only the existing `near_test_contracts::rs_contract()` test contract's promise APIs.

### Recommendation
This is a pre-existing, explicitly tracked bug (nearcore issue #12606) with a documented workaround already in place at `runtime/runtime/src/congestion_control.rs:413-427`; the workaround exists specifically to prevent receipts from getting permanently stuck (a liveness fix), not to conceal an exploitable fund-theft/consensus vector. The actual root cause is that receipt size validation happens before `output_data_receivers` are appended via `promise_return`; the fix should re-validate serialized receipt size after all post-processing (including `output_data_receivers` attachment) completes, rejecting the action if it exceeds `max_receipt_size`, rather than clamping the size used for bandwidth accounting downstream.

### Proof of Concept
The existing test `test_max_receipt_size_promise_return` in `test-loop-tests/src/tests/max_receipt_size.rs` already reproduces the construction and asserts (via `assert_oversized_receipt_occurred`) that an incoming receipt with size above `max_receipt_size` appears on-chain, confirming the bypass.     fn forward_from_buffer_to_shard(
        &mut self,
        buffer_shard_id: ShardId,
        state_update: &mut TrieUpdate,
        apply_state: &ApplyState,
        shard_layout: &ShardLayout,
    ) -> Result<(), RuntimeError> {
        let mut num_forwarded = 0;
        let mut outgoing_metadatas_updates: Vec<(ByteSize, Gas)> = Vec::new();
        for receipt_result in
            self.outgoing_buffers.to_shard(buffer_shard_id).iter(&state_update.trie, true)
        {
            let receipt = receipt_result?;
            let gas = receipt_congestion_gas(&receipt, &apply_state.config)?;
            let size = receipt_size(&receipt)?;
            let should_update_outgoing_metadatas = receipt.should_update_outgoing_metadatas();
            let receipt = receipt.into_receipt();
            let target_shard_id = receipt.receiver_shard_id(&shard_layout)?;

            match Self::try_forward(
                receipt,
                gas,
                size,
                target_shard_id,
                &mut self.outgoing_limit,
                &mut self.outgoing_receipts,
                apply_state,
                &mut self.stats,
            )? {
                ReceiptForwarding::Forwarded => {
                    self.own_congestion_info.remove_receipt_bytes(size)?;
                    self.own_congestion_info.remove_buffered_receipt_gas(gas.as_gas().into())?;
                    if should_update_outgoing_metadatas {
                        // Can't update metadatas immediately because state_update is borrowed by iterator.
                        outgoing_metadatas_updates.push((ByteSize::b(size), gas));
                    }
                    // count how many to release later to avoid modifying
                    // `state_update` while iterating based on
                    // `state_update.trie`.
                    num_forwarded += 1;
                }
                ReceiptForwarding::NotForwarded(_) => {
                    break;
                }
            }
        }

        self.outgoing_buffers.to_shard(buffer_shard_id).pop_n(state_update, num_forwarded)?;
        for (size, gas) in outgoing_metadatas_updates {
            self.outgoing_metadatas.update_on_receipt_popped(
                buffer_shard_id,
                size,
                gas,
                state_update,
            )?;
        }
        Ok(())
    }

/// Assert that there was an incoming receipt with size above max_receipt_size
fn assert_oversized_receipt_occurred(node: &TestLoopNode<'_>) {
    let client = node.client();
    let chain = &client.chain;
    let epoch_manager = &*client.epoch_manager;

    let tip = chain.head().unwrap();
    let epoch_id = epoch_manager.get_epoch_id(&tip.last_block_hash).unwrap();
    let protocol_version = epoch_manager.get_epoch_protocol_version(&epoch_id).unwrap();
    let runtime_config = client.runtime_adapter.get_runtime_config(protocol_version);
    let max_receipt_size = runtime_config.wasm_config.limit_config.max_receipt_size;

    let mut block = chain.get_block(&tip.last_block_hash).unwrap();

    // Go over all blocks down to genesis looking for a receipt above max_receipt_size.
    loop {
        if block.header().is_genesis() {
            panic!("Didn't find receipt with size above max_receipt_size!");
        }
        let prev_block = chain.get_block(block.header().prev_hash()).unwrap();

        let shard_layout = epoch_manager
            .get_shard_layout(&epoch_manager.get_epoch_id(block.hash()).unwrap())
            .unwrap();

        let oversized = if ProtocolFeature::Spice.enabled(protocol_version) {
            // With spice chunks are executed asynchronously and their produced receipts are
            // persisted as receipt proofs keyed by the block in which the chunk was applied,
            // rather than as incoming receipts on the following block.
            shard_layout.shard_ids().any(|shard_id| {
                chain
                    .chain_store()
                    .iter_receipt_proofs_for_shard(block.hash(), shard_id)
                    .iter()
                    .flat_map(|proof| proof.0.iter())
                    .any(|receipt| receipt_is_oversized(receipt, max_receipt_size))
            })
        } else {
            block.chunks().iter_new().any(|new_chunk| {
                let shard_id = new_chunk.shard_id();
                let prev_shard_index = epoch_manager
                    .get_prev_shard_id_from_prev_hash(block.header().prev_hash(), shard_id)
                    .unwrap()
                    .2;
                let prev_height_included =
                    prev_block.chunks().get(prev_shard_index).unwrap().height_included();
                let incoming_receipts_proofs = get_incoming_receipts_for_shard(
                    &chain.chain_store,
                    epoch_manager,
                    shard_id,
                    &shard_layout,
                    *block.hash(),
                    prev_height_included,
                    ReceiptFilter::TargetShard,
                )
                .unwrap();
                incoming_receipts_proofs
                    .iter()
                    .flat_map(|response| response.1.iter())
                    .flat_map(|proof| proof.0.iter())
                    .any(|receipt| receipt_is_oversized(receipt, max_receipt_size))
            })
        };

        if oversized {
            return;
        }

        block = prev_block;
    }
}

fn receipt_is_oversized(receipt: &Receipt, max_receipt_size: u64) -> bool {
    let receipt_size: u64 = borsh::object_length(receipt).unwrap().try_into().unwrap();
    if receipt_size > max_receipt_size {
        tracing::info!(%receipt_size, %max_receipt_size, "found receipt above max size");
        return true;
    }
    false
}
