### Title
Unauthenticated `RecvError` packet allows any off-path spoofer to force tunnel teardown (remote state poisoning / DoS) - (File: outside.go)

### Summary
`header.RecvError` packets are handled in the "Unencrypted packets" branch of `readOutsidePackets`, before any handshake/certificate authentication or AEAD verification is performed. The only "authentication" applied is a check that the spoofable UDP source `netip.AddrPort` matches the hostinfo's currently known remote address. Because UDP source addresses are trivially forgeable and the comparison is the sole gate before a state-mutating, tunnel-destroying action (`f.closeTunnel`), this mirrors the reported bug class: a critical function (here, tunnel teardown / hostmap state mutation) that lacks real cryptographic access control and can be invoked by an attacker holding no valid Nebula certificate at all.

### Finding Description
In `outside.go`, `readOutsidePackets` dispatches on header type immediately after parsing (no decrypt, no cert check): [1](#0-0) 

`header.RecvError` is handled by `f.handleRecvError(via.UdpAddr, h)`. That function's only defense is comparing the packet's claimed source address to the hostinfo's last known remote: [2](#0-1) 

If `hr.IsValid() && hr != addr` fails to hold (i.e., the spoofed source matches the victim's actual current remote `AddrPort`), the code proceeds to `f.closeTunnel(hostinfo)` and `f.handshakeManager.DeleteHostInfo(hostinfo)` — fully authenticated-tunnel-destroying operations — with zero cryptographic proof that the sender possesses any valid Nebula certificate, session key, or even network on-path position. The only unforgeable input required is `h.RemoteIndex`, a 32-bit value used purely for lookup via `QueryReverseIndex`, and the source `AddrPort`, which is not bound to any secret (UDP has no built-in source authentication).

This is analogous to the reported smart-contract bug class: `rescue`/`blacklist` were public functions that mutated critical state without verifying the caller's authority. Here, `handleRecvError` mutates critical VPN session state (tears down an active, authenticated tunnel) while gating only on a spoofable, non-cryptographic value (UDP source address + a 32-bit index), rather than on certificate/handshake authentication as every other state-mutating remote packet path in Nebula requires (e.g., `Message`, `LightHouse`, `Test`, `CloseTunnel`, and `Control` are all processed only after `hostinfo.ConnectionState.Decrypt`/`VerifyRelay` succeeds).

### Impact Explanation
An attacker who can spoof UDP packets with a source address matching a victim node's peer (a classic UDP source-spoofing primitive, feasible on many networks/paths that do not enforce BCP38/anti-spoofing, or from an on-path/adjacent-network position) can force the victim to tear down a live, authenticated tunnel to a specific peer without ever presenting a valid certificate or completing a handshake. Repeated or scripted spoofed `RecvError` packets amount to a remote, unauthenticated denial-of-service against any specific Nebula peer relationship, and also feed into the handshake manager's pending-hostmap deletion path, disrupting reconnection state. This is a "remote state poisoning" / DoS impact reachable with no certificate.

### Likelihood Explanation
Likelihood depends on the attacker's ability to spoof the exact source `AddrPort` of a legitimate peer, which requires either (a) network-level IP spoofing capability (not universally blocked), or (b) an on-path/adjacent attacker. `h.RemoteIndex` is a 32-bit handshake-generated index, not secret but also not trivially guessable at scale; however it is exposed in cleartext in the handshake and message headers already sent over the wire, so any attacker able to observe traffic (or who is on-path) knows both the required index and address pair. The `listen.send_recv_error` / `listen.accept_recv_error` config knobs (`recvErrorAlways`/`recvErrorPrivate`/`recvErrorNever`) can reduce exposure but do not eliminate it in default/permissive configurations.

### Recommendation
Treat `RecvError` as untrusted control input to the same standard as other unauthenticated pre-handshake packets: do not allow it to directly trigger `closeTunnel`/`DeleteHostInfo` based solely on a source-address match. Instead, require some proof tied to the session (e.g., only honor `RecvError` if it correlates with independent transport-level evidence such as repeated send failures observed locally, or require the `RemoteIndex` to also be accompanied by a validated, low-cost cryptographic tag), or simply demote `RecvError`'s effect to a soft signal (e.g., trigger a re-handshake attempt/keepalive probe) rather than an unconditional teardown, mirroring how `CloseTunnel` is only trusted once it arrives inside the AEAD-authenticated channel.

### Proof of Concept
1. Establish two legitimate Nebula peers `A` and `B` with a live tunnel; note `B`'s current UDP `AddrPort` as seen by `A`, and `A`'s local index for that hostinfo (visible in prior unencrypted handshake headers exchanged in cleartext).
2. From an attacker-controlled host capable of spoofing UDP source addresses as `B`'s `AddrPort` (or from an on-path position), craft a raw UDP packet with `header.H{Type: header.RecvError, RemoteIndex: <A's local index for the B hostinfo>}` and send it to `A`'s listening port, with spoofed source = `B`'s `AddrPort`.
3. `A` receives the packet in `readOutsidePackets`, dispatches to `handleRecvError` before any decryption; `QueryReverseIndex` finds the real hostinfo; the address check `hr != addr` passes since the source is spoofed to match; `A` calls `f.closeTunnel(hostinfo)`, destroying the live tunnel to `B` despite the attacker never having a valid certificate or completing a handshake.

(Note: exploitation requires the ability to spoof the victim's UDP source address; this was not independently verified in a live network test due to tool constraints — the code path itself confirms the logic gap.)

func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
