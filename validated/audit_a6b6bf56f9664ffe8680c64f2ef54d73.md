### Title
Unauthenticated `RecvError` packet allows any attacker to force-close arbitrary Nebula tunnels without holding a CA-signed certificate - (File: outside.go)

### Summary
`readOutsidePackets` dispatches `header.RecvError` packets to `handleRecvError` **before** any Noise/AEAD authentication step is performed on the packet — `RecvError` is handled in the same early switch that also routes unauthenticated `Handshake` packets, prior to `hostinfo.ConnectionState.Decrypt`. Inside `handleRecvError`, the spoofing check is conditioned on the target hostinfo already having a *valid* learned remote address, so an attacker who has not completed any handshake (and holds no CA-signed certificate at all) can spoof a UDP source and a guessed/observed 32-bit `RemoteIndex` to tear down another party's tunnel and mutate hostmap state.

### Finding Description
This is the same bug class as the external report: a state-changing entry point trusts data on the wire without verifying that the sender is the authenticated party that "owns" the session/state being mutated.

In `outside.go`, the dispatch happens before decryption: [1](#0-0) 

`handleRecvError` then does: [2](#0-1) 

The critical logic is:
```go
hr := hostinfo.GetRemote()
if hr.IsValid() && hr != addr {
    f.l.Info("Someone spoofing recv_errors?", ...)
    return
}
f.closeTunnel(hostinfo)
f.handshakeManager.DeleteHostInfo(hostinfo)
```
- The only "authentication" is a comparison against `hostinfo.GetRemote()`, which is just a previously-learned UDP address, not a cryptographic proof. UDP source addresses are trivially spoofable in a reflection/off-path sense for this kind of "fire and forget" DoS packet, since no reply needs to be routed back to the attacker for the packet to have its effect (it isn't a request/response, it's an instruction to close and delete).
- If `hr.IsValid()` is `false` — which happens whenever the tunnel hasn't yet learned/roamed to a live remote (e.g., freshly established via relay, or transiently unset) — the entire spoofing check is skipped (`hr.IsValid() && hr != addr` evaluates false), and the tunnel is torn down and deleted unconditionally for anyone who can produce a `RemoteIndex` that resolves via `QueryReverseIndex`.
- `QueryReverseIndex`/`h.RemoteIndex` values are visible on the wire in every packet a peer exchanges (they are not secrets, and the header is unauthenticated at this point), so an on-path or off-path attacker who has observed even one packet for a target tunnel obtains everything needed to forge this attack — no CA-signed certificate, no completed handshake, and no cryptographic material of any kind is required.
- The action taken, `f.closeTunnel(hostinfo)` + `f.handshakeManager.DeleteHostInfo(hostinfo)`, mutates protocol state for the two legitimate peers of that tunnel, exactly analogous to `CredibleAccountModule::validateUserOp` mutating `SessionData` state for a wallet it wasn't authorized to touch — in both cases the root cause is a state-changing function reachable by an unauthenticated caller because the code never verifies the caller is the entity legitimately associated with the session/module instance being modified.

### Impact Explanation
An attacker with no certificate, no handshake, and no cryptographic secret can force termination of active or pending Nebula tunnels between two legitimate, honest peers, causing denial of service and forcing expensive rehandshakes. Because the check that exists is bypassable both by (a) UDP source spoofing when `hr.IsValid()` and (b) complete absence of a check when `hr` isn't yet valid, this is a practical availability/integrity issue on the mesh, not merely a theoretical one. This matches "remote state poisoning" / DoS impact categories called out in the validation criteria.

### Likelihood Explanation
Likelihood is high: `RemoteIndex` values are sent in cleartext in every packet header (see `header.Encode`), so any passive observer on the network path (or a peer that has exchanged even one packet) can harvest valid indexes; UDP is connectionless so source-address spoofing for one-shot disruptive packets is straightforward on many networks; and no rate limiting/authentication gates this specific message type prior to dispatch besides the coarse `sendRecvErrorConfig`/`acceptRecvErrorConfig` policy toggles, which govern whether recv-errors are honored at all, not who is allowed to send them.

### Recommendation
Do not act on `RecvError` packets against a hostinfo that has no cryptographically-authenticated binding to the sender. Concretely:
- Require `hr.IsValid()` before honoring a `RecvError` at all (treat an unset/invalid remote as "cannot verify sender, drop"), rather than skipping the check.
- Prefer authenticating `RecvError` (e.g., via a short authenticated tag bound to the tunnel's established keys, similar to how relay packets are AEAD-verified) instead of relying on UDP source-address equality, since source addresses are not a security boundary.
- Rate-limit/backoff `RecvError`-triggered teardown per remote index to reduce the blast radius of any residual spoofing window.

### Proof of Concept
1. Observe (or otherwise learn) the `RemoteIndex` used by two legitimate Nebula peers `A` and `B` for their tunnel — this value is visible in the cleartext header of any packet either peer transmits.
2. Craft a bare `header.RecvError` packet (`header.Encode(..., header.RecvError, 0, remoteIndex, 0)`), matching the format produced in `sendRecvError`: [3](#0-2) 
3. Send it to `A`'s UDP listen port. Two exploitable conditions:
   - If `A`'s hostinfo for `B` has not yet learned/roamed to a valid remote (`hr.IsValid() == false`, e.g. right after a relay-established or pending handshake), the packet is accepted unconditionally.
   - Otherwise, spoof the UDP source address to match `A`'s currently-known remote for `B` (`hr`), which is not a secret.
4. `A` calls `f.closeTunnel(hostinfo)` and `f.handshakeManager.DeleteHostInfo(hostinfo)`, tearing down the tunnel — all without the attacker ever presenting a certificate or completing a handshake.

func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
