### Title
Unauthenticated `RecvError` control packets allow a certificate-less network attacker to force tunnel teardown (state poisoning analog to unprotected cancel) - ([File: outside.go])

### Summary
The GMX report describes a bug class where a state-transition operation (order cancellation) is triggered by an untrusted/unverified external condition and executes without adequate protection, letting an attacker force or block a state change to their advantage. In Nebula, the `RecvError` message type is processed **before any decryption or certificate/peer authentication** and is accepted purely based on a UDP source-address match, letting an attacker who holds no CA-signed certificate at all forge this control packet and force an authenticated tunnel to tear down.

### Finding Description
`readOutsidePackets` dispatches `header.RecvError` packets straight to `handleRecvError` in the "Unencrypted packets" branch, prior to any `ConnectionState.Decrypt` or certificate check: [1](#0-0) 

`handleRecvError` looks up the hostinfo purely by `h.RemoteIndex` (an attacker-guessable/observable 32-bit value carried in cleartext on every packet) and validates the sender only by comparing the packet's source `netip.AddrPort` against the hostinfo's currently known remote address: [2](#0-1) 

If that comparison succeeds — which is trivial for an off-path attacker able to spoof a UDP source address/port, or simply true when the hostinfo has no remote set yet (e.g., mid-roam, mid-relay-transition) — the tunnel is torn down (`f.closeTunnel(hostinfo)`) and the pending handshake state is deleted (`f.handshakeManager.DeleteHostInfo(hostinfo)`), with **zero cryptographic authentication of the sender**. No certificate, no Noise handshake, no decryption is required to reach this state-mutating code path — it is reachable by literally anyone who can send a 12-byte UDP datagram to the target's listen port with a guessed/observed `RemoteIndex`, i.e., exactly the class of attacker who holds no CA-signed certificate.

This mirrors the GMX bug class: a state-transition path ("cancel"/teardown) is reachable and effective without the caller having satisfied the protocol's core authorization gate (there: token transfer success; here: certificate-authenticated Noise handshake), letting an attacker unilaterally force the target into a chosen state (torn-down tunnel) at will, at the expense of the legitimate peer.

### Impact Explanation
An attacker with no valid certificate can force disestablishment of any established Nebula tunnel merely by spoofing (or, if on-path, recording and forging) the peer's source `ip:port` and guessing/observing the `RemoteIndex`. This is a remote state-poisoning primitive: it can be used to repeatedly disrupt tunnels, force churn/rehandshakes at will, or precisely time teardown to interfere with an in-progress roam, relay migration, or rehandshake window — the same kind of "force a state transition at a chosen moment to gain advantage" dynamic that made the GMX cancel-path bug harmful.

### Likelihood Explanation
Reachable pre-authentication, with no certificate, no successful handshake, and no decryption required. The only obstacles are learning/guessing a valid `RemoteIndex` (transmitted in cleartext on every data/handshake packet an attacker can observe on-path, or via traffic analysis) and being able to place a matching source `ip:port` on the wire (trivial on-path, and off-path spoofing is often possible for UDP unless egress/ingress filtering is enforced by the network). The code comment `"Someone spoofing recv_errors?"` at [3](#0-2)  shows the maintainers are aware address-based validation is spoofable but only log, not reject.

### Recommendation
Do not let an unauthenticated control message single-handedly tear down an authenticated tunnel. Require `RecvError` to be authenticated (e.g., MAC'd/encrypted with the tunnel's established keys, or gated behind a matching, recently-sent packet index/nonce) before acting on it, or at minimum require corroborating signals (e.g., only honor it after failing X consecutive keepalives) rather than acting on a single unauthenticated cleartext packet.

### Proof of Concept
1. Observe (or record from a punch/holepunch/relay exchange) a victim's `RemoteIndex` value from any packet on the wire between two Nebula peers.
2. Craft a 12-byte header with `Type = header.RecvError`, `RemoteIndex = <observed index>`, matching the header encoding in [4](#0-3) .
3. Send this UDP datagram to the victim's listen port, spoofing (or, if on-path, simply reusing) the current peer's `ip:port` so it matches `hostinfo.GetRemote()`.
4. Observe `handleRecvError` tear down the tunnel and delete pending handshake state with no certificate or handshake ever having been presented by the attacker: [2](#0-1) .

```go
func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
```
