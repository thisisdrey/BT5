### Title
Unstaked/staked QUIC connection eviction can be indefinitely deferred via periodic stream activity, enabling connection-slot griefing - (File: streamer/src/nonblocking/quic.rs)

### Summary
The Mochi `MochiVault` bug lets an attacker perform a cheap, unprivileged, repeatable action (`deposit()`) that resets a timestamp (`lastDeposit[_id]`) gating a delay check (`wait()`), permanently blocking a victim's legitimate action (`withdraw()`). The reachable analog in agave's QUIC/streamer path is the `last_update` timestamp on each `ConnectionEntry`, which any connected peer can refresh at will simply by finishing a stream, and which is the sole criterion used by `ConnectionTable::prune_oldest` to decide which connection(s) get evicted when connection capacity is exceeded.

### Finding Description
Each accepted QUIC connection is tracked in a `ConnectionTable` as a `ConnectionEntry` carrying a `last_update: Arc<AtomicU64>` [1](#0-0) . This value is refreshed every time a stream on that connection finishes — an action fully controlled by the remote peer, requiring no stake and negligible cost — via `on_stream_finished`, e.g. in `SwQos`: [2](#0-1) 
and identically in `SimpleQos`: [3](#0-2) 

When the connection table becomes full, the only eviction path (`prune_oldest`) selects the connection group whose `last_update` is the minimum across the table and evicts it: [4](#0-3) 

Because `last_update` is refreshed purely by the attacker opening/finishing trivial (even empty/near-empty) streams — the same "cheap periodic action" pattern as the Mochi `deposit()` griefing — an attacker who holds one or more connection slots can keep resetting their own `last_update` value just often enough to never be the minimum, thereby avoiding eviction indefinitely and denying slot availability to competing (possibly higher-value/legitimate) unstaked or staked peers trying to establish new connections in `try_add_connection`, which returns `None`/closes the incoming connection with `CONNECTION_CLOSE_CODE_TOO_MANY` once capacity limits are hit: [5](#0-4) 

This mirrors the report's root cause precisely: a permissionless, cheap, repeatable action resets a timestamp used as the sole basis for a scarce-resource decision (deposit timestamp -> withdrawal delay gate; here, `last_update` timestamp -> LRU eviction gate), letting an attacker perpetually defer a resource reclamation/allocation decision to the detriment of other (legitimate) users.

Note: `ConnectionTable` also exposes `prune_random`, which evicts based on lowest **stake** rather than recency [6](#0-5) ; it is unclear from the code reviewed whether `prune_random` or `prune_oldest` is the path actually invoked for the unstaked connection table versus the staked table in the current connection-acceptance flow, since the exact call site tying `prune_oldest`/`prune_random` into `SwQos`'s accept logic was not fully traced before this session ended (only 1 call site of `prune_oldest` was located in `swqos.rs`, and 4 in `quic.rs`, but the surrounding conditional logic determining which table/threshold triggers which prune function was not read).

### Impact Explanation
If `prune_oldest` (LRU-based) is indeed the active eviction strategy for the (unstaked) connection table under load, an unstaked attacker occupying one or more of the `DEFAULT_MAX_UNSTAKED_CONNECTIONS` slots can keep refreshing `last_update` with trivial, near-zero-cost stream completions and thereby never be the "oldest" entry. This denies new unstaked connections from legitimate clients once the table is saturated by attacker-controlled connections, constituting a low-cost QoS/DoS evasion against a resource management mechanism explicitly meant to bound QUIC connections (in-scope per the prompt's allowed categories: "QUIC/UDP streamer ... account locks"). This does not, by itself, cause a node panic, deadlock, or invalid recorded block, so the severity is bounded to a griefing/QoS-evasion class similar in spirit (not identical impact) to the original finding.

### Likelihood Explanation
Likelihood is high in principle since refreshing `last_update` requires no stake and is a normal, allowed client action (finishing any stream) — no protocol violation is needed. However, actual exploitability depends on unverified details: (1) which prune function is actually wired into the accept path for unstaked vs. staked tables, (2) whether `DEFAULT_MAX_UNSTAKED_CONNECTIONS` (2000) and `DEFAULT_MAX_QUIC_CONNECTIONS_PER_UNSTAKED_PEER` (8) make it economically practical for a single attacker (needing multiple source IPs/ports) to occupy enough slots to matter, and (3) whether other independent mitigations (e.g., per-IP connection-per-minute rate limiting `DEFAULT_MAX_CONNECTIONS_PER_IPADDR_PER_MINUTE`, stream throttling via SWQoS stake-weighted EMA) already blunt this in practice. These were not fully confirmed.

### Recommendation
- Confirm which eviction function (`prune_oldest` vs `prune_random`) governs the unstaked connection table in the live accept path, and if it is purely LRU-based, incorporate a component resistant to griefing — e.g., weight eviction by connection *age since creation* (not last activity) combined with per-connection total useful throughput/behavior, similar to how `prune_random` already factors in stake.
- Consider capping how much a single connection's `last_update` can be "refreshed" per unit time, or basing eviction preference on a combination of low stake AND staleness rather than staleness alone, so cheap keep-alive traffic cannot indefinitely preserve a slot.

### Proof of Concept
Conceptual (not executed): an attacker opens the maximum permitted unstaked connections per peer/IP up to the unstaked connection table's global capacity, and on each connection periodically opens and finishes a minimal-size unidirectional stream just before its entry would become the oldest (lowest `last_update`) in the table. Because `on_stream_finished` unconditionally bumps `last_update` to `timing::timestamp()` [2](#0-1) , and `prune_oldest` only evicts the minimum-`last_update` entries [7](#0-6) , the attacker's connections are never selected for eviction, while genuine new unstaked connection attempts are rejected via the capacity check in `try_add_connection` [8](#0-7) .

/// Prune the connection which has the oldest update
///
/// Return number pruned
impl<S: OpaqueStreamerCounter> ConnectionTable<S> {
    pub(crate) fn new(table_type: ConnectionTableType, cancel: CancellationToken) -> Self {
        Self {
            table: IndexMap::default(),
            total_size: 0,
            table_type,
            cancel,
        }
    }

    fn table_size(&self) -> usize {
        self.total_size
    }

    fn is_staked(&self) -> bool {
        matches!(self.table_type, ConnectionTableType::Staked)
    }

    pub(crate) fn prune_oldest(&mut self, max_size: usize) -> usize {
        let mut num_pruned = 0;
        let key = |(_, connections): &(_, &Vec<_>)| {
            connections.iter().map(ConnectionEntry::last_update).min()
        };
        while self.total_size.saturating_sub(num_pruned) > max_size {
            match self.table.values().enumerate().min_by_key(key) {
                None => break,
                Some((index, connections)) => {
                    num_pruned += connections.len();
                    self.table.swap_remove_index(index);
                }
            }
        }
        self.total_size = self.total_size.saturating_sub(num_pruned);
        num_pruned
    }

    // Randomly selects sample_size many connections, evicts the one with the
    // lowest stake, and returns the number of pruned connections.
    // If the stakes of all the sampled connections are higher than the
    // threshold_stake, rejects the pruning attempt, and returns 0.
    pub(crate) fn prune_random(&mut self, sample_size: usize, threshold_stake: u64) -> usize {
        let num_pruned = std::iter::once(self.table.len())
            .filter(|&size| size > 0)
            .flat_map(|size| {
                let mut rng = rng();
                repeat_with(move || rng.random_range(0..size))
            })
            .map(|index| {
                let connection = self.table[index].first();
                let stake = connection.map(|connection: &ConnectionEntry<S>| connection.stake());
                (index, stake)
            })
            .take(sample_size)
            .min_by_key(|&(_, stake)| stake)
            .filter(|&(_, stake)| stake < Some(threshold_stake))
            .and_then(|(index, _)| self.table.swap_remove_index(index))
            .map(|(_, connections)| connections.len())
            .unwrap_or_default();
        self.total_size = self.total_size.saturating_sub(num_pruned);
        num_pruned
    }

    pub(crate) fn try_add_connection<F: FnOnce() -> Arc<S>>(
        &mut self,
        key: ConnectionTableKey,
        port: u16,
        client_connection_tracker: ClientConnectionTracker,
        connection: Option<Connection>,
        peer_type: ConnectionPeerType,
        last_update: Arc<AtomicU64>,
        max_connections_per_peer: usize,
        stream_counter_factory: F,
    ) -> Option<(Arc<AtomicU64>, CancellationToken, Arc<S>)> {
        let connection_entry = self.table.entry(key).or_default();
        let has_connection_capacity = connection_entry
            .len()
            .checked_add(1)
            .map(|c| c <= max_connections_per_peer)
            .unwrap_or(false);
        if has_connection_capacity {
            let cancel = self.cancel.child_token();
            let stream_counter = connection_entry
                .first()
                .map(|entry| entry.stream_counter.clone())
                .unwrap_or_else(stream_counter_factory);
            connection_entry.push(ConnectionEntry::new(
                cancel.clone(),
                peer_type,
                last_update.clone(),
                port,
                client_connection_tracker,
                connection,
                stream_counter.clone(),
            ));
            self.total_size += 1;
            Some((last_update, cancel, stream_counter))
        } else {
            if let Some(connection) = connection {
                connection.close(
                    CONNECTION_CLOSE_CODE_TOO_MANY.into(),
                    CONNECTION_CLOSE_REASON_TOO_MANY,
                );
            }
            None
        }
    }
