## Analog Found

### Title
Permissionless `keeper_close_order` lets a zero-stake caller redirect rent to an attacker-controlled `fee_recipient` - (File: `programs/marginfi/src/instructions/marginfi_account/order.rs`)

### Summary
The reported bug class is: an unprivileged/zero-weight actor calls a permissionless function and, despite having no legitimate stake in the outcome, extracts a payout that should not accrue to them (in the original report, gas refunds paid per address regardless of actual voting power). The marginfi analog is `keeper_close_order`, which is permissionless (callable by any signer, no ownership/authority check on the caller) and closes an `Order` PDA while sending its rent lamports to a `fee_recipient` account that the caller fully controls, with "no checks whatsoever."

### Finding Description
`keeper_close_order` is invoked through the `KeeperCloseOrder` accounts struct, which requires no signer at all tied to the `marginfi_account` or the `order` — only that the `order` account `has_one = marginfi_account`, and `close = fee_recipient` sends the order's rent to whatever `fee_recipient` UncheckedAccount is passed in: [1](#0-0) 

The doc comment on `fee_recipient` explicitly states there are no restrictions: "CHECK: no checks whatsoever, keeper decides this without restriction." Compare this with `PlaceOrder`, where the fee is paid to a hard-coded, validated `global_fee_wallet`: [2](#0-1) 

The `keeper_close_order` handler itself performs a permissionless close check (`can_close`) based purely on whether the order's tagged balances still exist on the account — it never checks who is calling, whether they hold any position, or whether they have any relationship to the order or its `fee_payer`: [3](#0-2) 

This is functionally analogous to the FrankenDAO `_castVote` bug: a caller with zero legitimate claim (no votes / no stake in the order) can trigger a state-mutating, value-transferring action and direct the payout (rent, akin to the vote-refund) to themselves, simply by satisfying a condition (`can_close`) that has nothing to do with caller identity or entitlement. `close_liquidation_record`, by contrast, was explicitly designed to prevent this exact issue: its rent always returns to the original `record_payer` regardless of which third party calls close: [4](#0-3) 

`keeper_close_order` has no equivalent protection — the caller nominates the recipient of the rent themselves.

### Impact Explanation
Any order the caller can trigger `can_close` for (e.g. because one of its tagged balances has since been fully withdrawn/repaid and closed) can be closed by an unrelated third party who diverts the PDA's rent lamports to their own wallet instead of the account that actually paid for the order's creation (the order's `fee_payer`). This is an unauthorized transfer of funds (rent) away from the rightful payer to an unprivileged actor with no stake in the order, account, or protocol — the same "value extraction by a party with zero legitimate claim" pattern as the referenced report, just applied to order rent instead of a governance refund vault.

### Likelihood Explanation
Order accounts are small (rent is modest, on the order of Order PDA rent-exemption lamports), but the attack requires zero cost beyond monitoring for closable orders (orders whose tagged balance has naturally closed) and is fully permissionless — `KeeperCloseOrder` has no signer/authority constraint tying the caller to the order, the account, or its `fee_payer`. Any bot scanning on-chain state for orders in this state can systematically claim the rent from every closable order across the protocol.

### Recommendation
Restrict `fee_recipient` in `KeeperCloseOrder` similarly to how `close_liquidation_record` handles it: route the rent back to the order's original `fee_payer` (which would need to be stored on the `Order` account, analogous to `record_payer`) rather than allowing an arbitrary, caller-supplied `fee_recipient`. If a keeper incentive is desired, it should be a small, protocol-configured, capped bounty rather than the entire rent balance directed to an unchecked account.

### Proof of Concept
1. Attacker monitors for any `Order` PDA where one of its two tagged balances has been closed (e.g., normal user activity closes a balance via `withdraw_all`/`repay_all`), satisfying the `can_close` condition in `keeper_close_order`. [5](#0-4) 
2. Attacker (who has no relation to the `marginfi_account`, the order, or its original `fee_payer`) submits `keeper_close_order`, supplying their own wallet as `fee_recipient`.
3. Anchor's `close = fee_recipient` constraint on the `order` account transfers the order's full rent balance to the attacker's wallet, and no on-chain check rejects this because `fee_recipient` is explicitly documented and implemented as unchecked. [6](#0-5) 
4. Repeat across all closable orders protocol-wide to systematically harvest rent that should have returned to each order's original `fee_payer`.

pub fn keeper_close_order(ctx: Context<KeeperCloseOrder>) -> MarginfiResult {
    let KeeperCloseOrder {
        order: order_loader,
        marginfi_account,
        ..
    } = &ctx.accounts;

    let order = order_loader.load()?;
    let marginfi_account_info = marginfi_account.to_account_info();

    // Manual owner check: Only attempt to deserialize when the account is not closed
    let (authority_pk, group_pk, can_close) = if marginfi_account_info.owner.eq(&system_program::ID)
        && marginfi_account_info.data_is_empty()
    {
        (Pubkey::default(), Pubkey::default(), true)
    } else {
        // Deserialize manually using bytemuck to avoid lifetime issues
        let mut data = marginfi_account_info.try_borrow_mut_data()?;

        // Check discriminator
        require!(
            data.len() >= 8 + std::mem::size_of::<MarginfiAccount>(),
            MarginfiError::InternalLogicError
        );

        let disc = &data[..8];
        check_eq!(
            disc,
            MarginfiAccount::DISCRIMINATOR,
            MarginfiError::InternalLogicError
        );

        let marginfi_account: &mut MarginfiAccount =
            bytemuck::from_bytes_mut(&mut data[8..8 + std::mem::size_of::<MarginfiAccount>()]);

        let balances = &marginfi_account.lending_account.balances;
        // Can close if any of the balances used in the order no longer exists (or if its tag was cleared)
        let can_close = order.tags.iter().any(|tag| {
            !balances
                .iter()
                .any(|balance| balance.is_active() && balance.tag == *tag)
        });
        if can_close {
            marginfi_account.decrement_active_orders()?;
        }
        (
            marginfi_account.authority,
            marginfi_account.group,
            can_close,
        )
    };

    check!(can_close, MarginfiError::LiquidatorOrderCloseNotAllowed);

    emit!(KeeperCloseOrderEvent {
        header: AccountEventHeader {
            signer: None,
            marginfi_account: marginfi_account_info.key(),
            marginfi_account_authority: authority_pk,
            marginfi_group: group_pk,
        },
        order: order_loader.key(),
    });

    Ok(())
}

/// Anyone can call close, but rent always goes to the original record_payer.
#[tokio::test]
async fn close_liquidation_record_permissionless_caller() -> anyhow::Result<()> {
    let test_f = TestFixture::new(Some(TestSettings::all_banks_payer_not_admin())).await;
    let (liquidatee, record_pk, payer) = setup_with_liquidation_record(&test_f).await?;

    // Create a third-party signer (not the record_payer)
    let third_party = Keypair::new();
    {
        let ctx = test_f.context.borrow_mut();
        let blockhash = ctx.banks_client.get_latest_blockhash().await.unwrap();
        let tx = system_transaction::transfer(
            &ctx.payer,
            &third_party.pubkey(),
            1_000_000_000,
            blockhash,
        );
        ctx.banks_client.process_transaction(tx).await?;
    }

    // Record the record_payer's balance before close
    let payer_balance_before = {
        let ctx = test_f.context.borrow_mut();
        ctx.banks_client.get_balance(payer).await?
    };

    // Third party calls close — should succeed
    let close_ix = liquidatee
        .make_close_liquidation_record_ix(record_pk, payer)
        .await;
    {
        let ctx = test_f.context.borrow_mut();
        let tx = Transaction::new_signed_with_payer(
            &[close_ix],
            Some(&third_party.pubkey()),
            &[&third_party],
            ctx.banks_client.get_latest_blockhash().await.unwrap(),
        );
        ctx.banks_client
            .process_transaction_with_preflight(tx)
            .await?;
    }

    // Verify record is closed
    {
        let ctx = test_f.context.borrow_mut();
        let account = ctx.banks_client.get_account(record_pk).await?;
        assert!(account.is_none(), "record account should be closed");
    }

    // Verify rent went to record_payer (not the third-party caller)
    let payer_balance_after = {
        let ctx = test_f.context.borrow_mut();
        ctx.banks_client.get_balance(payer).await?
    };
    assert!(
        payer_balance_after > payer_balance_before,
        "record_payer should have received rent back"
    );
