### Title
Unauthenticated forged peer identity written to PeerDB via self-reported HandshakeData address - (File: stackslib/src/net/chat.rs)

### Summary
When a node makes an outbound connection and receives a `Handshake`/`HandshakeAccept` in return, `handle_handshake` re-keys and persists the remote peer's PeerDB entry using the `addrbytes`/`port` fields taken from the peer-supplied `HandshakeData`, not the actual TCP peer address that was dialed. A malicious responder can therefore claim an arbitrary third-party `(network_id, addrbytes, port)` identity that gets written into the node's `PeerDB` frontier table.

### Finding Description
`NeighborKey::from_handshake` builds the neighbor's on-disk identity directly from the wire-controlled `HandshakeData` fields, with no cross-check against the actual socket address of the connection: [1](#0-0) 

In `handle_handshake`, when `self.stats.outbound` is true (i.e., this node initiated the connection), the code calls `Neighbor::load_and_update` with the raw `handshake_data`, then persists it via `neighbor.save_update`, all inside a fresh DB transaction that is committed unconditionally: [2](#0-1) 

`Neighbor::load_and_update` computes the address key purely from `NeighborKey::from_handshake(peer_version, network_id, handshake_data)`, looks up/creates the `PeerDB` row keyed on that address, and updates it via `handshake_update`, which itself only touches `public_key`, `expire_block`, `asn`/`org`, and `last_contact_time` — it never validates `addrbytes`/`port` against the actual connection: [3](#0-2) [4](#0-3) 

Finally `try_insert_peer` performs the actual write to the `PeerDB` frontier table using `neighbor.addr.addrbytes`/`neighbor.addr.port` as the identity key, with no comparison to the socket the connection came from: [5](#0-4) 

Root cause: the code conflates "the address a peer claims to have" (self-reported, attacker-controlled `HandshakeData.addrbytes`/`port`) with "the address a peer actually connects from," and persists the former into a table used to steer future connection attempts (`PeerDB` frontier). No signature, secret, or independent verification ties the claimed address to the TCP source. This matches the general pattern of accepting self-reported NAT/relay addresses in P2P handshakes, but here it is written to durable state and used for the network's peer-discovery frontier.

### Impact Explanation
An attacker who accepts a single outbound connection from a victim node (e.g., by getting the victim to dial them via gossip, bootstrap config, or simply running a reachable peer that the victim discovers) can, upon completing the handshake, cause the victim to write/update a `PeerDB` row for an arbitrary, attacker-chosen `(network_id, addrbytes, port)` that the attacker does not own. This is an unauthenticated write into the frontier table that other subsystems consult to select future connection targets. Effects include: DB pollution of the peer frontier, poisoning peer discovery/gossip (`nat_frontier`/`get_fresh_random_neighbors`-style consumers), and potential reflection — causing the victim (and any node it later relays the forged neighbor record to) to attempt connections toward a third party's IP:port repeatedly. Because this happens on every outbound handshake completion, it is trivially repeatable across churn/reconnects and across every peer the attacker convinces the victim to dial.

### Likelihood Explanation
Preconditions are modest and match the unprivileged-attacker model: the attacker just needs to be dialed as an outbound peer by the target node (a very common occurrence for any publicly-reachable node acting as a bootstrap peer, being gossiped, or being scanned/found), respond to the handshake with a valid signature over `HandshakeData`, and set `expire_block_height` in the future so the re-key path is taken. No RPC secret, no other peer's key, and no privileged role is required — only running a normal P2P responder. This is remotely reachable via the standard P2P port and repeatable on every reconnect.

### Recommendation
When processing a handshake on an outbound connection, validate the `HandshakeData.addrbytes`/`port` against the actual socket address used to establish the connection (`self.to_neighbor_key()` / the dialed address) before calling `Neighbor::load_and_update`/`save_update`. If the peer reports a different address (e.g., due to legitimate NAT/proxy), either reject the update, or store it as advisory-only metadata separate from the primary frontier key, rather than allowing it to override the `PeerDB` identity that peer-discovery and connection-scheduling logic rely on.

### Proof of Concept
Rust test plan in `stackslib/src/net/chat.rs` / `stackslib/src/net/db.rs` test modules:
1. Construct a `ConversationP2P` with `self.stats.outbound = true` for a connection actually established to socket address `A` (e.g., `1.2.3.4:20444`).
2. Craft a valid, signed `StacksMessage` containing `StacksMessageType::Handshake(HandshakeData)` where `HandshakeData.addrbytes`/`port` is set to an unrelated address `B` (e.g., `9.9.9.9:20444`) not associated with the test connection, with `expire_block_height` far in the future.
3. Call `convo.handle_handshake(&mut local_peer, &mut network, &mut message, false)`.
4. After the call, invoke `PeerDB::get_peer(conn, network_id, &addrbytes_B, port_B)` and assert it returns `Some(neighbor)` — a frontier row keyed on `B`, an address the test harness never actually connected to/from — demonstrating the forged write.

impl Neighbor {
    /// Update fields in this neighbor from a given handshake.
    /// Also, re-calculate the peer's ASN and organization ID
    pub fn handshake_update(
        &mut self,
        conn: &DBConn,
        handshake_data: &HandshakeData,
    ) -> Result<(), net_error> {
        let pubk = handshake_data
            .node_public_key
            .to_public_key()
            .map_err(|e| net_error::DeserializeError(e.into()))?;
        let asn_opt =
            PeerDB::asn_lookup(conn, &handshake_data.addrbytes).map_err(net_error::DBError)?;

        let asn = match asn_opt {
            Some(a) => a,
            None => 0,
        };

        self.public_key = pubk;
        self.expire_block = handshake_data.expire_block_height;
        self.last_contact_time = get_epoch_time_secs();

        if asn != 0 {
            self.asn = asn;
            self.org = asn; // TODO; AS number is a place-holder for an organization ID (an organization can own multiple ASs)
        }

        Ok(())
    }

                let mut ret = neighbor;
                ret.addr = addr.clone();

                (ret, false)
            }

    pub fn try_insert_peer(
        tx: &Transaction,
        neighbor: &Neighbor,
        stacker_dbs: &[QualifiedContractIdentifier],
    ) -> Result<bool, db_error> {
        let present = PeerDB::has_peer(
            tx,
            neighbor.addr.network_id,
            &neighbor.addr.addrbytes,
            neighbor.addr.port,
        )?;
        if present {
            // already here
            PeerDB::update_peer(tx, neighbor)?;
            PeerDB::update_peer_stacker_dbs(tx, neighbor, stacker_dbs)?;
            return Ok(true);
        }

        let slots = PeerDB::peer_slots(
            tx,
            neighbor.addr.network_id,
            &neighbor.addr.addrbytes,
            neighbor.addr.port,
        )?;
        for slot in slots.iter() {
            let used_slot = PeerDB::has_peer_at(tx, neighbor.addr.network_id, *slot)?;
            if !used_slot {
                // have a spare slot!
                PeerDB::insert_or_replace_peer(tx, neighbor, *slot)?;
                PeerDB::insert_or_replace_stacker_dbs(tx, *slot, stacker_dbs)?;
                return Ok(true);
            }
        }

        // no slots free
        return Ok(false);
    }
