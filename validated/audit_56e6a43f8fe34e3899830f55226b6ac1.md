Unauthenticated remote `/shutdown` request terminates signer's event receiver main loop - ([File: libsigner/src/events.rs])

### Summary
The `SignerEventReceiver::next_event` handler treats any HTTP `POST /shutdown` request as a valid termination signal without checking the request's origin, an authentication token, or any shared secret. Since the event-receiver's TCP port is bound to accept connections from the configured stacks-node (not restricted to loopback in this code), any remote party capable of reaching that port can send a single crafted HTTP request to permanently stop the signer's event processing loop.

### Finding Description
The equality the code should enforce — "sender authorized to issue `/shutdown` == the local stacks-node event-dispatcher" — is never checked. In `next_event` (events.rs lines 443-445):
```
} else if request.url() == "/shutdown" {
    event_receiver.stop_signal.store(true, Ordering::SeqCst);
    Err(EventError::Terminated)
```
The dispatch logic only inspects `request.url()`; it does not validate any secret, header, or the peer's source address against the expected local node. `SignerStopSignaler::send` (the legitimate internal caller, lines 376-395) itself just opens a plain `TcpStream::connect` to the receiver's bound address and sends a raw `POST /shutdown` request with an arbitrary body — demonstrating that the endpoint is designed to be triggered by nothing more than a correctly-formed HTTP request over the socket, with no cryptographic or token-based proof of origin.

Once `stop_signal` is set, `is_stopped()` (line 462-464) returns `true`, and `main_loop` (lines 284-312) breaks out on the next iteration after receiving `EventError::Terminated`, permanently halting the signer's event-processing thread. There is no restart logic visible in this file; an operator must manually restart the signer process.

### Impact Explanation
Any remote party that can open a TCP connection to the signer's event-receiver port can send one `POST /shutdown` request and permanently disable that signer's event loop — it will no longer receive `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, or `/new_block` events from the node. This is a single-message, unauthenticated, repeatable remote DoS against the signer's event pipeline, matching the "Critical - remote crash/unauthenticated DoS from few messages" category.

### Likelihood Explanation
No preconditions beyond network reachability to the bound event-receiver port are required — no secret, no peer key, no StackerDB slot ownership, no privileged role. The attacker's cost is a single crafted HTTP POST request. This is trivially repeatable against every signer whose event-receiver port is reachable.

### Recommendation
Require the event-receiver to verify the request originates from the local trusted stacks-node before honoring `/shutdown` (and ideally all endpoints) — e.g., bind the HTTP server to loopback only, and/or require a shared secret/bearer token configured between the node and the signer, checked before processing `/shutdown` (and other write-triggering endpoints).

    fn main_loop(&mut self) {
        loop {
            if self.is_stopped() {

                }

                    info!("Caught termination signal");
                    break;

                }
            };
