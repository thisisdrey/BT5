### Title
Unauthenticated remote DoS via `/shutdown` HTTP request permanently kills the signer's event receiver - ([File: libsigner/src/events.rs])

### Summary
`SignerEventReceiver::next_event` matches on `request.url() == "/shutdown"` and unconditionally sets `event_receiver.stop_signal.store(true, Ordering::SeqCst)` with no check of caller identity, secret, or source. Any remote party who can open a TCP connection to the signer's event-receiver port (which the shipped sample config binds to `0.0.0.0:30000`) can send a single crafted `POST /shutdown` and permanently halt the signer's `main_loop`.

### Finding Description
The intended equality is: the party allowed to stop the event receiver == the local signer process that owns the `SignerStopSignaler` returned by `get_stop_signaler()`. In practice, `SignerStopSignaler::send()` is just a convenience wrapper that connects to `self.local_addr` and POSTs `/shutdown` [1](#0-0) ; nothing distinguishes this internally-generated request from one sent by an arbitrary remote peer. The actual authorization decision lives in `next_event()`, which handles `/shutdown` by directly flipping the shared `AtomicBool` and returning `Err(EventError::Terminated)`, without checking any header, token, or source address: [2](#0-1) . `main_loop()` treats `EventError::Terminated` as a clean exit signal and `break`s out permanently [3](#0-2) . There is no `auth_token`/`Authorization` verification anywhere in `libsigner`, and the `auth_password`/`auth_token` config pair documented in `docs/signing.md` only guards the node's block-proposal RPC endpoint, not the signer's inbound event HTTP server. The sample signer config explicitly binds this listener to all interfaces (`endpoint = "0.0.0.0:30000"`), so the port is remotely reachable, not merely loopback-bound.

### Impact Explanation
A single unauthenticated `POST /shutdown` from any remote attacker who can reach the signer's event port sets `stop_signal` to `true`; the very next call to `next_event()` (whether from that same connection or a subsequent request) returns `Err(EventError::Terminated)`, causing `main_loop()` to `break` and exit permanently [4](#0-3) . This stops the signer from ever again receiving `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, or `/new_block` events pushed by the node, silencing the signer for the remainder of its process lifetime (until manually restarted). This is a Critical unauthenticated remote DoS achievable with a single crafted message.

### Likelihood Explanation
The attacker needs only network reachability to the configured signer `endpoint` port (0.0.0.0-bound per the sample/documented config), no credentials, no StackerDB slot, and no P2P handshake — a raw `TcpStream` connection with a hand-written HTTP request suffices, exactly mirroring `SignerStopSignaler::send()`'s own request format [5](#0-4) . The attack is trivially repeatable and costs a single TCP round trip.

### Recommendation
Require proof of local/authorized origin before honoring `/shutdown` — e.g., bind the event-receiver's control channel to loopback only, or require a shared secret/token (checked against the node's `auth_token`) or a local Unix-domain socket / in-process channel for the stop signal instead of an unauthenticated HTTP route reachable from the network.

### Proof of Concept
Rust test in `libsigner/src/tests/mod.rs` style: spawn `SignerEventReceiver` via `Signer::spawn` bound to `127.0.0.1:PORT` (or `0.0.0.0:PORT` to mirror the documented config), then from an independent `TcpStream::connect` (not via `SignerStopSignaler`) send `POST /shutdown HTTP/1.1\r\nHost: ...\r\nConnection: close\r\nContent-Length: 0\r\n\r\n`; assert that a subsequent probe (e.g., `GET /status`) hangs/fails and that `event_receiver.is_stopped()` is `true`, and that `next_event()` returns `Err(EventError::Terminated)`, matching the behavior at [2](#0-1)  — with no signer key or auth header ever presented.
