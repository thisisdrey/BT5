### Title
Unvalidated `git_object_directory`/`git_alternate_object_directories` RPC fields allow storage escape via crafted `Repository` calldata - (File: internal/git/gitcmd/command_factory.go)

### Summary
Every Gitaly RPC accepts a public `Repository` protobuf message whose `git_object_directory` and `git_alternate_object_directories` fields are meant only for Gitaly's internal object-quarantine flow, but nothing prevents an ordinary RPC caller from setting these fields directly. The core git-command builder consumes them unvalidated, joining them onto the repository path to build `GIT_OBJECT_DIRECTORY`/`GIT_ALTERNATE_OBJECT_DIRECTORIES` for every spawned git process, independent of the path-traversal checks that exist elsewhere in the codebase for the same fields.

### Finding Description
The `Repository` proto explicitly documents these fields as controlling `GIT_OBJECT_DIRECTORY`/`GIT_ALTERNATE_OBJECT_DIRECTORIES`: [1](#0-0) 

`ExecCommandFactory.newCommand`, which is the central path used to construct essentially every git subprocess invocation in Gitaly, resolves the repository path via `GetRepoPath` (which validates `relative_path`/`storage_name`) and then separately, without any additional validation, feeds the caller-supplied object-directory fields straight into `alternates.Env`: [2](#0-1) 

`alternates.Env` simply does `filepath.Join(repoPath, dir)` for each directory and joins them with `:` into the environment variable — it performs no containment check: [3](#0-2) 

By contrast, the codebase does have a validating accessor for the same fields — `(*Repo).ObjectDirectoryPath` in `internal/git/localrepo/paths.go` — which calls `storage.ValidateRelativePath` and rejects traversal sequences or quarantine-prefix mismatches: [4](#0-3) 

However, `ObjectDirectoryPath` is only used by a handful of specific service RPCs; it is **not** invoked by `newCommand`/`alternates.Env`, the code path that actually sets the environment variables for git subprocess execution. This is exactly the "arbitrary call data" pattern from the report: an internal-use field (analogous to the `taker` field meant to always equal the trusted contract) is exposed as ordinary, unauthenticated user input on the outward-facing interface (the `Repository` message on every RPC, analogous to arbitrary calldata passed to the exchange), and only some code paths validate it while the most consequential one (actual git process execution) does not.

### Impact Explanation
An RPC caller who controls the `Repository` message of a request (which is normal, expected input for virtually all Gitaly RPCs) can set `git_alternate_object_directories` to a path containing traversal sequences (e.g. `../../other-storage/other-repo/objects`) or an absolute path elsewhere on the filesystem. Because `filepath.Join` does not sandbox `..` components, the resulting `GIT_ALTERNATE_OBJECT_DIRECTORIES` value can point outside of the intended repository's object store. Any git command that then searches for objects (e.g. `cat-file`, `log`, `pack-objects`) will search the attacker-chosen directory as well as the legitimate object directory, enabling cross-repository/cross-tenant object disclosure — an attacker with knowledge (or brute-forceable knowledge, since content-addressed) of an object ID in a repository they don't have access to could retrieve its contents through a repository they do control, bypassing storage isolation between repositories/tenants.

### Likelihood Explanation
The `Repository` message and its `git_object_directory`/`git_alternate_object_directories` fields are ordinary top-level RPC input, not an internal-only channel — any authenticated Gitaly client (which in GitLab's architecture, per-project, is not necessarily trusted with cross-repository access) can populate them on nearly any RPC that forwards the repository to `newCommand`. No malicious peer, leaked token, or privileged actor is required beyond normal RPC access to a repository whose commands go through this shared code path, satisfying the "ordinary user's...crafted RPC field" requirement.

### Recommendation
1. Validate `git_object_directory`/`git_alternate_object_directories` at the single choke point where git subprocess environment variables are constructed (`ExecCommandFactory.newCommand`/`alternates.Env`), using the same containment logic as `storage.ValidateRelativePath` / `(*Repo).ObjectDirectoryPath`, rather than relying on validation that only some call sites perform.
2. Alternatively, do not accept these fields as free-form client input at all outside of the internal quarantine flow: derive them exclusively from Gitaly-generated quarantine directories (as done in `quarantine.Apply`) and reject/ignore externally supplied values on RPCs that are not part of the quarantine machinery.
3. Add regression tests asserting that a `Repository` message with a traversal or absolute path in these fields is rejected before any git subprocess is spawned.

### Proof of Concept
1. Attacker has access to Repository A (their own) and knows/guesses an object ID `X` that exists only in Repository B (belongs to another user/project) on the same Gitaly storage.
2. Attacker issues any RPC that resolves a git command through `ExecCommandFactory.newCommand` against Repository A, but sets `Repository.git_alternate_object_directories = ["../../<storage-relative-path-to-B>/objects"]` (or an absolute path to B's object directory) in the request.
3. `newCommand` computes `repoPath` for Repository A via `GetRepoPath` (validated), but then calls `alternates.Env(repoPath, "", ["../../.../B/objects"])`, producing `GIT_ALTERNATE_OBJECT_DIRECTORIES=<A's path>/../../.../B/objects`, which resolves outside of Repository A.
4. The git subprocess (e.g. `git cat-file -p X`) run against Repository A now also searches Repository B's object directory and returns object `X`'s content to the attacker, even though the attacker has no access rights to Repository B.

Note: I was unable to directly view the concrete implementation of `Locator.GetRepoPath`/`ValidateRepository` in this session (only its interface in `internal/gitaly/storage/locator.go`) to conclusively confirm it performs no additional check on `git_object_directory`/`git_alternate_object_directories`; this assessment is based on the interface contract, the dedicated (separately invoked) validation in `paths.go`, and the unguarded usage in `command_factory.go`/`alternates.go`. Confirming the exact runtime behavior of `GetRepoPath` would require further code review.

```go
// Env returns the alternate object directory environment variables.
func Env(repoPath, objectDirectory string, alternateObjectDirectories []string) []string {
	var env []string
	if objectDirectory != "" {
		env = append(env, fmt.Sprintf("GIT_OBJECT_DIRECTORY=%s", filepath.Join(repoPath, objectDirectory)))
	}

	if len(alternateObjectDirectories) > 0 {
		var dirsList []string

		for _, dir := range alternateObjectDirectories {
			dirsList = append(dirsList, filepath.Join(repoPath, dir))
		}

		env = append(env, fmt.Sprintf("GIT_ALTERNATE_OBJECT_DIRECTORIES=%s", strings.Join(dirsList, ":")))
	}

	return env
}
```

```go
// ObjectDirectoryPath returns the full path of the object directory. The errors returned are gRPC
// errors with relevant error codes and should be passed back to gRPC without further decoration.
func (repo *Repo) ObjectDirectoryPath(ctx context.Context) (string, error) {
	repoPath, err := repo.Path(ctx)
	if err != nil {
		return "", err
	}

	objectDirectoryPath := repo.GetGitObjectDirectory()
	if objectDirectoryPath == "" {
		return "", structerr.NewInvalidArgument("object directory path is not set")
	}

	storagePath, err := repo.locator.GetStorageByName(ctx, repo.GetStorageName())
	if err != nil {
		return "", fmt.Errorf("get storage by name: %w", err)
	}

	// Ensure the path points somewhere in the storage.
	relativeObjectDirectoryPath, err := storage.ValidateRelativePath(storagePath, filepath.Join(repoPath, objectDirectoryPath))
	if err != nil {
		return "", structerr.NewInvalidArgument("validate relative path: %w", err)
	}

	parentDir := filepath.Base(filepath.Dir(relativeObjectDirectoryPath))
	baseDir := filepath.Base(relativeObjectDirectoryPath)
	isTransactionQuarantineDir := (baseDir == "quarantine") || ((parentDir == "quarantine") && strings.HasPrefix(baseDir, "tmp_objdir"))
```
