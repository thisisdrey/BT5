### Title
StackerDB slot-signature replay across different StackerDB contracts due to missing domain separation - (File: `libstackerdb/src/libstackerdb.rs`)

### Summary
`SlotMetadata::auth_digest()` computes the digest that is signed/verified for every StackerDB chunk write from only `(slot_id, slot_version, data_hash)`. It does not bind the signature to the specific StackerDB smart contract (`QualifiedContractIdentifier`) or to any chain/network identifier. Because the same signer key/address frequently occupies the same numeric `slot_id` across multiple independent StackerDB instances (e.g. the alternating `.signers-0-xxx` / `.signers-1-xxx` contracts that are reused across many reward cycles, or the miners contract), a signature that was validly produced for one contract's slot can be replayed by any network observer to a *different* StackerDB contract, resulting in an unauthorized write that is accepted as if it were authored for that other contract.

### Finding Description
The chunk-authenticating digest is: [1](#0-0) 

It hashes only `slot_id`, `slot_version`, and `data_hash`. Verification mirrors this: [2](#0-1) 

Neither the smart-contract identifier nor a chain/network id is part of the signed material. The write path that actually persists a chunk only checks the per-slot signer and the per-slot lamport version — it never checks that the signature was produced *for this contract*: [3](#0-2) 

The same gap exists on the gossip/validation path used both for `PUT /v2/stackerdb/.../chunks` and for unsolicited `StackerDBPushChunk` gossip messages: [4](#0-3) 

Slot ownership (which address owns which `slot_id`) is contract-specific and is reused across many logically distinct StackerDB instances. In particular, the signer-messages system persists slot assignments in two long-lived contracts keyed only by `reward_cycle % 2`: [5](#0-4) [6](#0-5) 

`.signers-0-xxx` is the *same physical StackerDB contract* for every even reward cycle, and `.signers-1-xxx` for every odd one; slot IDs are simply positional indices into the current signer set (`get_parsed_signer_slots`): [7](#0-6) 

`reconfigure_stackerdb` only resets a slot's version when the *signer for that slot changes*; if the same signer keeps the same `slot_id` across a config refresh (e.g. across different reward cycles, or coincidentally between the `-0-` and `-1-` contracts, or on the miners contract), the version counter is untouched and old, previously-broadcast signatures for that (slot_id, slot_version, data_hash) tuple remain fully valid on any other contract that assigns the same address to that slot at a version still below the captured one: [8](#0-7) 

Because `StackerDBChunkData`/`SlotMetadata` signatures observed on the wire (StackerDB chunks are pushed/replicated in the clear over p2p gossip and are also readable via the public `GET /v2/stackerdb/.../chunks` endpoint) carry no contract or chain binding, an unprivileged attacker who merely observes one valid signed chunk can resubmit it verbatim to a *different* StackerDB replica (different contract, potentially different node) whose current slot version for the same signer address/slot_id is lower than the captured value. `try_replace_chunk`/`validate_received_chunk` will accept it as an authentic, in-order write, because the signature check has no way to distinguish "signed for contract A" from "signed for contract B."

This is the direct analog of the reported PPS-oracle issue: the signed payload lacks a domain separator (no `contract_id`/`address(this)` equivalent, no `chain_id`), so a signature that is valid in one context is fully valid and replayable in another context that shares the same underlying key/slot assignment.

### Impact Explanation
This breaks the equality "chunk authenticated for StackerDB X" vs. "chunk stored into StackerDB Y" — non-canonical (wrong-context) data is accepted as canonical for the target contract. The practical result is an unauthorized write into a StackerDB replica the attacker does not control and for which the attacker does not hold any private key — they only need to have observed one legitimately signed, in-flight chunk. This can be used to inject stale/attacker-chosen (but validly-signed-elsewhere) signer or miner protocol messages into a StackerDB instance where they were never intended, corrupting the eventually-consistent replicated state used by Nakamoto miners/signers coordination. This matches the "Critical: unauthenticated/unauthorized write to state or StackerDB" impact bucket.

### Likelihood Explanation
The precondition — the same signer/miner address occupying the same `slot_id` in more than one StackerDB contract instance at a moment where the target's slot version is still below the captured value — is not guaranteed on every attempt, but is structurally likely: the `.signers-0-xxx`/`.signers-1-xxx` contracts are long-lived and reused every other reward cycle with largely-overlapping signer sets/orderings, and slot versions are per-slot lamport clocks that reset only when the assigned signer address changes. An attacker only needs to passively capture one broadcast/gossip chunk (no server-side auth is required to observe StackerDB gossip or query `GET /v2/stackerdb/.../chunks`) and replay it to another contract's `PUT` endpoint or via push-gossip.

### Recommendation
Bind the signed digest to the specific StackerDB instance and network, e.g.:
```rust
fn auth_digest(&self, contract_id: &QualifiedContractIdentifier, chain_id: u32) -> Sha512Trunc256Sum {
    let mut hasher = Sha512_256::new();
    hasher.update(chain_id.to_be_bytes());
    hasher.update(contract_id.serialize_to_vec()); // or its hash
    hasher.update(self.slot_id.to_be_bytes());
    hasher.update(self.slot_version.to_be_bytes());
    hasher.update(self.data_hash.0);
    Sha512Trunc256Sum::from_hasher(hasher)
}
```
Thread the contract id (and chain id) through `sign`/`verify` in `libstackerdb/src/libstackerdb.rs`, and update every call site (`try_replace_chunk` in `stackslib/src/net/stackerdb/db.rs`, `validate_received_chunk` in `stackslib/src/net/stackerdb/mod.rs`, the miner/signer chunk-signing helpers) to pass the correct contract identifier so a chunk signed for one StackerDB can never validate against another.

### Proof of Concept
1. Configure/observe two StackerDB contracts (e.g. `.signers-0-xxx` used in reward cycle N, and `.signers-1-xxx` used in reward cycle N+1) where the operator running signer key `K` is assigned `slot_id = i` in both (common, since slot assignment is purely positional over the reward-cycle's signer ordering, which frequently repeats for stable stake distributions).
2. Passively capture a legitimately signed `StackerDBChunkData { slot_id: i, slot_version: v, sig, data }` broadcast by `K` on `.signers-0-xxx` (via p2p `StackerDBPushChunk` gossip, or via `GET /v2/stackerdb/<addr>/signers-0-xxx/chunks/i`).
3. Ensure `.signers-1-xxx`'s current stored version for slot `i` is `< v` (true immediately after a reconfiguration reset, or simply if that contract has seen fewer writes).
4. POST the captured chunk unmodified to `.signers-1-xxx`'s `/v2/stackerdb/<addr>/signers-1-xxx/chunks` endpoint (or replay it as `StackerDBPushChunk` gossip naming `.signers-1-xxx`).
5. `try_replace_chunk`/`validate_received_chunk` verify only `(slot_id, slot_version, data_hash)` against the slot's known signer address — with no contract binding, the wrong-context signature verifies successfully and the write is accepted into `.signers-1-xxx`, even though the attacker never had `K`'s private key and the message was never intended for that contract.

    /// Get the digest to sign that authenticates this chunk data and metadata
    fn auth_digest(&self) -> Sha512Trunc256Sum {
        let mut hasher = Sha512_256::new();
        hasher.update(self.slot_id.to_be_bytes());
        hasher.update(self.slot_version.to_be_bytes());
        hasher.update(self.data_hash.0);
        Sha512Trunc256Sum::from_hasher(hasher)
    }

    /// Sign this slot metadata, committing to slot_id, slot_version, and
    /// data_hash.  Sets self.signature to the signature.
    /// Fails if the underlying crypto library fails
    pub fn sign(&mut self, privkey: &StacksPrivateKey) -> Result<(), Error> {
        let auth_digest = self.auth_digest();
        let sig = privkey
            .sign(&auth_digest.0)
            .map_err(|se| Error::SigningError(se.to_string()))?;

        self.signature = sig;
        Ok(())
    }

    /// Verify that a given principal signed this chunk metadata.
    /// Note that the address version is ignored.
    pub fn verify(&self, principal: &StacksAddress) -> Result<bool, Error> {
        let sigh = self.auth_digest();
        let pubk = StacksPublicKey::recover_to_pubkey_without_validating_low_s(
            sigh.as_bytes(),
            &self.signature,
        )
        .map_err(|ve| Error::VerifyingError(ve.to_string()))?;

        let pubkh = Hash160::from_node_public_key(&pubk);
        Ok(pubkh == *principal.bytes())
    }
}

        &self,
        smart_contract: &QualifiedContractIdentifier,
        slots: &[(StacksAddress, u32)],
    ) -> Result<(), net_error> {
        let stackerdb_id = self.get_stackerdb_id(smart_contract)?;
        let mut total_slots_read = 0u32;

            total_slots_read =

                    .checked_add(*slot_count)
                    .ok_or(net_error::OverflowError(

                    self.get_slot_validation(smart_contract, slot_id)?

    pub fn try_replace_chunk(
        &self,
        smart_contract: &QualifiedContractIdentifier,
        slot_desc: &SlotMetadata,
        chunk: &[u8],
    ) -> Result<(), net_error> {
        // Check per-replica chunk-size cap.
        if (chunk.len() as u64) > self.config.chunk_size {
            return Err(net_error::StackerDBChunkTooBig(chunk.len()));
        }

        let slot_validation = self
            .get_slot_validation(smart_contract, slot_desc.slot_id)?
            .ok_or(net_error::NoSuchSlot(
                smart_contract.clone(),
                slot_desc.slot_id,
            ))?;

        if !slot_desc.verify(&slot_validation.signer)? {
            return Err(net_error::BadSlotSigner(
                slot_validation.signer,
                slot_desc.slot_id,
            ));
        }
        if slot_desc.slot_version <= slot_validation.version {
            return Err(net_error::StaleChunk {
                supplied_version: slot_desc.slot_version,
                latest_version: slot_validation.version,
            });
        }
