### Title
Nep245/Imt `TokenDiff` fee bypass via delta chunking into multiple `amount ≤ 1` intents - (File: contracts/defuse/core/src/intents/token_diff.rs)

### Summary
`TokenDiff::execute_intent` computes and collects the protocol fee independently for each signed `TokenDiff` intent, using that intent's own per-token delta magnitude as the `amount` passed to `TokenDiff::token_fee`. Because `token_fee` exempts `Nep245`/`Imt` tokens whenever `amount <= 1`, a signer can split one large negative delta (e.g. `-1000`) on a `Nep245` `TokenId` into many separately signed `TokenDiff` intents each with `delta = -1`, included in the same `MultiPayload` batch, so every individual `token_fee` call sees `amount = 1` and returns `Pips::ZERO`, whereas a single `delta = -1000` intent would have been charged `fee.fee_ceil(1000)`.

### Finding Description
The broken binding: total fee credited to `fee_collector` for a `Nep245`/`Imt` token `T` after a batch that nets `-1000` of `T` out of the signer's balance should equal `Pips::fee_ceil(1000)` regardless of how the `-1000` delta is partitioned across signed intents, but it does not.

Code path: `TokenDiff::execute_intent` iterates `self.diff` (a single intent's `BTreeMap<TokenId, i128>`), and for each negative delta computes `Self::token_fee(token_id, amount, protocol_fee).fee_ceil(amount)` using only that intent's local `amount` [1](#0-0) . `token_fee` explicitly waives the fee for `Nep245`/`Imt` when `amount <= 1`: `TokenIdType::Nep245 | TokenIdType::Imt if amount > 1 => {}` / `TokenIdType::Nep171 | TokenIdType::Nep245 | TokenIdType::Imt => return Pips::ZERO` [2](#0-1) .

There is no batch-wide aggregation of deltas per token before fee calculation; `Engine::execute_signed_intent` dispatches each signed payload's intents independently to `execute_intent`, and only the net-zero balance invariant is checked globally via `TransferMatcher`/`finalize`, not the fee [3](#0-2) . Consequently, an attacker who signs 1000 separate `TokenDiff` intents each with `{T: -1}` (matched against a counterparty's offsetting positive deltas so the batch nets to zero as required by `TransferMatcher::finalize` [4](#0-3) ) causes 1000 independent `token_fee` calls each seeing `amount = 1`, all returning `Pips::ZERO`, instead of one call with `amount = 1000` that would return the configured `Pips` fee.

Existing guards (`MultiPayload::verify`, nonce/salt checks, `TransferMatcher::finalize`) only validate signatures, nonces, and that the sum of all deltas nets to zero across the batch; none of them re-aggregate per-token negative deltas across multiple intents/signers for fee purposes, so they do not prevent this divergence.

### Impact Explanation
The `fee_collector` under-collects the protocol fee on the `Nep245`/`Imt` leg of a trade: for a genuine `-1000` transfer that should pay `fee.fee_ceil(1000)`, the attacker pays `0`. This is repeatable per token, per batch, and across any account, as long as a counterparty (which may be the attacker's own second account, or a cooperating/naive solver) supplies the matching positive-side deltas required by the invariant check. This matches the explicitly listed Critical category "protocol fees bypassed or over-collected."

### Likelihood Explanation
Preconditions are attacker-controlled and cheap: the attacker needs to hold the `Nep245`/`Imt` balance being moved, and needs a counterparty side (which can be their own second controlled account) whose deltas net the batch to zero on all tokens involved. Splitting one intent into N unit intents costs extra signatures/payload size but no extra tokens or privileges, and NEAR gas/size limits are explicitly out of scope for this audit as a mitigating factor. The exploit is fully repeatable across tokens and batches.

### Recommendation
Aggregate the total negative delta for each `TokenId` across all intents within the batch (or at least require `token_fee`'s `amount` parameter to reflect the account's net negative flow of that token across the whole `MultiPayload`, not the per-intent delta) before applying the `Nep245`/`Imt` `amount <= 1` fee exemption, or remove/restrict the exemption to a single `TokenDiff` intent that is guaranteed to be the only one touching that `TokenId` per signer per batch.

    fn execute_signed_intent(&mut self, signed: MultiPayload) -> Result<()> {
        // verify signed payload and get public key
        let public_key = signed.verify().ok_or(DefuseError::InvalidSignature)?;

        // calculate intent hash
        let hash = signed.hash();

        // extract NEP-413 payload
        let DefusePayload::<DefuseIntents> {
            signer_id,
            verifying_contract,
            deadline,
            nonce,
            message: intents,
        } = signed.extract_defuse_payload()?;

        // check recipient
        if verifying_contract != *self.state.verifying_contract() {
            return Err(DefuseError::WrongVerifyingContract);
        }

        self.inspector.on_deadline(deadline);

        // make sure message is still valid
        if deadline < Timestamp::now() {
            return Err(DefuseError::DeadlineExpired);
        }

        // make sure the account has this public key
        if !self.state.has_public_key(&signer_id, &public_key) {
            return Err(DefuseError::PublicKeyNotExist(signer_id, public_key));
        }

        // commit nonce
        self.verify_intent_nonce(nonce, deadline)?;
        self.state.commit_nonce(signer_id.clone(), nonce)?;

        intents.execute_intent(&signer_id, self, hash)?;
        self.inspector.on_intent_executed(&signer_id, hash, nonce);

        Ok(())
    }

    // Finalizes all transfers, or returns unmatched deltas.
    // If unmatched deltas overflow, then Err(None) is returned.
    pub fn finalize(self) -> Result<Transfers, InvariantViolated> {
        let mut transfers = Transfers::default();
        let mut deltas = TokenDeltas::default();
        for (token_id, transfer_matcher) in self.0 {
            if let Err(unmatched) = transfer_matcher.finalize_into(&token_id, &mut transfers)
                && (unmatched == 0 || deltas.apply_delta(token_id, unmatched).is_none())
            {
                return Err(InvariantViolated::Overflow);
            }
        }
        if !deltas.is_empty() {
            return Err(InvariantViolated::UnmatchedDeltas {
                unmatched_deltas: deltas,
            });
        }
        Ok(transfers)
    }
