### Title
`LinkRepositoryToObjectPool` accepts an arbitrary, unverified `ObjectPool` repository and grants the caller's repository object access to it - ([File: internal/gitaly/service/objectpool/link.go])

### Summary
The `LinkRepositoryToObjectPool` RPC validates that both the `Repository` and `ObjectPool` fields are *valid* Git repositories, but never verifies that the given `ObjectPool` repository was actually created as a pool (via `CreateObjectPool`) for the target repository's fork/pool family, nor that the caller has any legitimate relationship between the two repositories. Any caller who can invoke this RPC can supply an arbitrary victim repository as the `ObjectPool` argument, causing Gitaly to write that victim repository's object directory into the target repository's Git alternates file. This is directly analogous to the Sherlock M-6 finding: a function that trusts a caller-supplied "identity" (`vault`/`baseToken()` in FeeManager, `ObjectPool`/`Repository` here) without checking that the relationship between the two objects is authorized, letting the caller corrupt/misuse shared state that belongs to someone else.

### Finding Description
`LinkRepositoryToObjectPool` only checks that `req.GetRepository()` is a valid repository via `s.locator.ValidateRepository`, and resolves `req.GetObjectPool()` through `s.poolForRequest(ctx, req)`: [1](#0-0) 

`ObjectPool` resolution (`FromProto`/`FromRepo`) only validates that the pool path is a syntactically valid, existing repository on the same storage — it does not verify that the pool repository was created as a real object pool for this particular member, or that this member is an authorized fork of that pool's primary repository: [2](#0-1) 

The actual linking logic in `Link()` blindly computes the relative path between the two repositories and writes it into the target repository's `objects/info/alternates` file, then removes the target's bitmap files: [3](#0-2) 

Because `objects/info/alternates` tells Git "also look for objects in this other directory," writing an attacker-chosen path here means the linked repository (and anyone who can fetch/clone/read from it afterward) gains read access to every object contained in the alternates target — regardless of whether that target repository is public, private, or otherwise access-controlled by GitLab's Rails-side permission layer. This mirrors FeeManager's flaw where `trackVaultFee`/`receiveFee` trusted a self-reported `vault()`/`baseToken()` value to decide which shared accounting bucket to mutate, without checking that the caller was actually authorized to act on that target.

### Impact Explanation
An attacker who can reach `LinkRepositoryToObjectPool` for a repository they control (e.g., their own project or a project they can push/fork) can specify any other repository on the same Gitaly storage as the `ObjectPool`. This:
- Discloses objects (commits, blobs, trees) from the victim repository through the attacker's repository's alternates, i.e. a cross-repository object access / potential confidentiality bypass of the victim repo's access controls.
- Can corrupt the linked (attacker) repository's git-fsck-cleanliness/bitmap state, and if repeated against many repos, can produce widespread accounting/consistency problems similar to the "breaking fees accounting" impact in the report, but here manifesting as broken alternates/object-pool bookkeeping (`GetObjectPool`/pool metadata scans in `internal/gitaly/service/internalgitaly/scan_pool_metadata.go` treat any alternates target as a "pool", so poisoning alternates can also corrupt Gitaly's own pool-tracking metadata) — a DoS/data-integrity analog to the FeeManager overflow-based brick.

### Likelihood Explanation
This RPC is a normal (non-Praefect-internal, non-transaction-only) mutator RPC intended to be called as part of the fork-creation workflow (`CreateFork` → `CreateObjectPool` → `LinkRepositoryToObjectPool`), reachable by any actor who can drive that workflow (e.g., forking a project through GitLab, or directly by anyone with a valid Gitaly auth token who can address two repository paths). No additional server-side check ties the `ObjectPool` argument to the specific `Repository` being linked or to a proof that the pool was created from/for that repository, so exploitation only requires knowing (or guessing) another repository's relative path on the same storage — a fairly low bar given predictable `@hashed/...` or project-path-derived relative paths.

### Recommendation
Before performing the link, verify an authoritative relationship between `Repository` and `ObjectPool`, e.g.:
- Track (in Gitaly's pool metadata store / `PoolMetadataStore`) which repository the object pool was created from and only allow linking members that are recorded forks of that same source, or
- Require a server-issued token/marker created at `CreateObjectPool`/`CreateFork` time that must be presented to `LinkRepositoryToObjectPool`, rather than accepting a freely-specified pool path, and
- Reject links where the caller has not been shown (via the metadata store or an explicit "member of pool X" record) to be entitled to join that specific pool.

### Proof of Concept
1. Attacker has push/fork access to `RepoA` (their own project) on a shared Gitaly storage.
2. Attacker knows or predicts the relative path of a private victim repository `RepoV` on the same storage.
3. Attacker calls:
```
LinkRepositoryToObjectPool(
  Repository: RepoA,
  ObjectPool: { Repository: RepoV }   // no ownership check performed
)
```
via `internal/gitaly/service/objectpool/link.go` `LinkRepositoryToObjectPool`.
4. `poolForRequest` only confirms `RepoV` is a valid git repository [4](#0-3) , then `Link()` writes `RepoV`'s objects directory into `RepoA`'s `objects/info/alternates` [5](#0-4) .
5. Attacker can now fetch/clone `RepoA` and, via Git's alternates mechanism, retrieve any object whose OID they can guess/enumerate from `RepoV`, bypassing `RepoV`'s own access controls.

Note: I could not fully trace `poolForRequest`/`FromProto`'s complete validation chain (the `internal/gitaly/service/objectpool/util.go` source and `pool.go`'s `FromProto` body beyond line 121 were not retrievable within the tool budget), so it is possible additional undiscovered checks exist there that further constrain valid `ObjectPool` values; this should be verified directly in the repository before treating the PoC as conclusive.

func (s *server) LinkRepositoryToObjectPool(ctx context.Context, req *gitalypb.LinkRepositoryToObjectPoolRequest) (*gitalypb.LinkRepositoryToObjectPoolResponse, error) {
	repository := req.GetRepository()
	if err := s.locator.ValidateRepository(ctx, repository); err != nil {
		return nil, structerr.NewInvalidArgument("%w", err)
	}

	pool, err := s.poolForRequest(ctx, req)
	if err != nil {
		return nil, err
	}

	repo := s.localRepoFactory.Build(repository)

	if err := pool.Link(ctx, repo); err != nil {
		return nil, structerr.NewInternal("%w", err)
	}

	return &gitalypb.LinkRepositoryToObjectPoolResponse{}, nil

// FromRepo returns an instance of ObjectPool that the repository points to
func FromRepo(
	ctx context.Context,
	logger log.Logger,
	locator storage.Locator,
	gitCmdFactory gitcmd.CommandFactory,
	catfileCache catfile.Cache,
	txManager transaction.Manager,
	housekeepingManager housekeepingmgr.Manager,
	repo *localrepo.Repo,
) (*ObjectPool, error) {
	storagePath, err := locator.GetStorageByName(ctx, repo.GetStorageName())
	if err != nil {
		return nil, err
	}

	repoPath, err := repo.Path(ctx)
	if err != nil {
		return nil, err
	}

	altInfo, err := stats.AlternatesInfoForRepository(repoPath)
	if err != nil {
		return nil, fmt.Errorf("getting alternates info: %w", err)
	}

	if !altInfo.Exists || len(altInfo.ObjectDirectories) == 0 {
		return nil, ErrAlternateObjectDirNotExist
	}

	absolutePoolObjectDirPath := altInfo.AbsoluteObjectDirectories()[0]
	relativePoolObjectDirPath, err := filepath.Rel(storagePath, absolutePoolObjectDirPath)
	if err != nil {
		return nil, err
	}

	objectPoolProto := &gitalypb.ObjectPool{
		Repository: &gitalypb.Repository{
			StorageName:  repo.GetStorageName(),
			RelativePath: filepath.Dir(relativePoolObjectDirPath),
		},
	}

	if locator.ValidateRepository(ctx, objectPoolProto.GetRepository()) != nil {
		return nil, ErrInvalidPoolRepository
	}

	return FromProto(ctx, logger, locator, gitCmdFactory, catfileCache, txManager, housekeepingManager, objectPoolProto)
}

// Link will link the given repository to the object pool. This is done by writing the object pool's
// path relative to the repository into the repository's "alternates" file. This does not trigger
// deduplication, which is the responsibility of the caller.
func Link(ctx context.Context, pool, repo *localrepo.Repo, txManager transaction.Manager) (returnedErr error) {
	altPath, err := repo.InfoAlternatesPath(ctx)
	if err != nil {
		return err
	}

	expectedRelPath, err := getRelativeObjectPath(ctx, pool, repo)
	if err != nil {
		return err
	}

	linked, err := linkedToRepository(ctx, pool, repo)
	if err != nil {
		return err
	}

	if linked {
		// When the repository is already linked to the repository, cast a vote to ensure the
		// repository is consistent with the other replicas.
		if err := transaction.VoteOnContext(ctx, txManager, voting.VoteFromData([]byte("repository linked")), voting.Synchronized); err != nil {
			return fmt.Errorf("vote on linked repository: %w", err)
		}

		return nil
	}

	alternatesWriter, err := safe.NewLockingFileWriter(altPath)
	if err != nil {
		return fmt.Errorf("creating alternates writer: %w", err)
	}
	defer func() {
		if err := alternatesWriter.Close(); err != nil && returnedErr == nil {
			returnedErr = fmt.Errorf("closing alternates writer: %w", err)
		}
	}()

	if _, err := io.WriteString(alternatesWriter, expectedRelPath); err != nil {
		return fmt.Errorf("writing alternates: %w", err)
	}

	if err := transaction.CommitLockedFile(ctx, txManager, alternatesWriter); err != nil {
		return fmt.Errorf("committing alternates: %w", err)
	}

	if tx := storage.ExtractTransaction(ctx); tx != nil {
		alternatesRelativePath, err := filepath.Rel(tx.FS().Root(), altPath)
		if err != nil {
			return fmt.Errorf("rel alternates file: %w", err)
		}

		if err := tx.FS().RecordFile(alternatesRelativePath); err != nil {
			return fmt.Errorf("record alternates file")
		}
	}

	return removeMemberBitmaps(ctx, pool, repo)
}
