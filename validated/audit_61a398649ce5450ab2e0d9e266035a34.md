This confirms the analog. In `Firewall.inConns`, the routine-local `ConntrackCache` is checked first and, on a hit, immediately returns `true` (allow) without re-validating against the current `f.rulesVersion` or the authoritative `conntrack.Conns` state [1](#0-0) . The cache is only reset when `ConntrackCacheTicker.Get()` observes that its ticker generation has advanced, which happens on a fixed interval (`firewall.conntrack.routine_cache_timeout`, defaulting to 1s when running multiple routines) [2](#0-1) [3](#0-2) . Meanwhile the authoritative path in the same function re-validates a stale `conntrack.Conns` entry against `f.rulesVersion` on every lookup and deletes it if it no longer matches [4](#0-3) , and `evict` removes truly expired entries from `conntrack.Conns` via the timer wheel [5](#0-4)  — but none of that authoritative re-validation/eviction logic is consulted once a flow is already sitting in the local cache.

### Title
Stale routine-local conntrack cache allows firewall bypass after rule reload or entry expiry - (File: firewall.go)

### Summary
`Firewall.Drop` accepts an optional per-goroutine `ConntrackCache` (`localCache`) that is consulted before the authoritative `Conntrack.Conns` table. Once a flow's `firewall.Packet` tuple is inserted into this local cache, every subsequent lookup for that tuple is allowed unconditionally until the cache is reset by `ConntrackCacheTicker`, regardless of whether the underlying conntrack entry has since expired or the firewall ruleset has been reloaded to a version that would reject the flow.

### Finding Description
`Firewall.inConns` is structured as two paths: a fast local-cache path and an authoritative path against `f.Conntrack`. The fast path returns `true` on any hit without checking `rulesVersion` or entry `Expires`:
```go
if localCache != nil {
    if _, ok := localCache[fp]; ok {
        return true
    }
}
``` [1](#0-0) 

The authoritative path, reached only on a local-cache miss, purges expired entries via the timer wheel and re-validates any entry whose `rulesVersion` is stale against the *current* firewall table, dropping it if it no longer matches:
```go
if c.rulesVersion != f.rulesVersion {
    ...
    if !table.match(fp, c.incoming, h.ConnectionState.peerCert, caPool) {
        ...
        delete(conntrack.Conns, fp)
        conntrack.Unlock()
        return false
    }
    ...
    c.rulesVersion = f.rulesVersion
}
``` [6](#0-5) 

This re-validation and the timer-wheel-driven eviction exist specifically to handle `firewall.reload` correctness (see `TestFirewall_DropConntrackReload`) [7](#0-6) , but they are entirely bypassed once a tuple is present in `localCache`. The local cache is only invalidated when `ConntrackCacheTicker.Get()` detects the ticker has advanced a generation:
```go
if tick := c.cacheTick.Load(); tick != c.cacheV {
    c.cacheV = tick
    ...
    c.cache = make(ConntrackCache, ll)
}
``` [8](#0-7) 

That ticker fires on a fixed interval controlled by `firewall.conntrack.routine_cache_timeout`, which defaults to `1 * time.Second` whenever more than one reader routine is configured:
```go
conntrackCacheTimeout := c.GetDuration("firewall.conntrack.routine_cache_timeout", 0)
if routines > 1 && !c.IsSet("firewall.conntrack.routine_cache_timeout") {
    conntrackCacheTimeout = 1 * time.Second
}
``` [9](#0-8) 

This is the same bug class as the referenced report: a security decision is made from a cached snapshot (`localCache` / cached tvl) instead of consulting the authoritative, up-to-date state (`conntrack.Conns` re-validated against `rulesVersion` / on-chain tvl), producing incorrect results for the lifetime of the cache.

### Impact Explanation
During the window between an operator's firewall-rule reload and the next local-cache reset tick (up to the configured `routine_cache_timeout`, default 1s under multi-routine mode), packets belonging to previously-allowed flows continue to be admitted by `Drop` even though the new ruleset would reject them via `table.match` and even though the underlying conntrack entry would otherwise have expired. This is a firewall enforcement bypass: traffic that an operator just intended to block (e.g., after tightening rules or revoking a peer's access via cert/rule changes) can still traverse the tunnel for a short but attacker-exploitable window, and an attacker who can keep the flow's exact 4-tuple alive (or replay it) can extend the effective bypass window across successive packets as long as they keep landing on a routine whose local cache still has a stale hit.

### Likelihood Explanation
This requires only normal traffic capability plus the operator performing a firewall reload while `routines > 1` (the shipped default trigger for enabling this cache) or an explicitly configured `routine_cache_timeout > 0`. No malicious peer/lighthouse assumption is required; the flaw is in reconciling the per-routine fast-path cache with the authoritative ruleset/expiry state.

### Recommendation
Do not let a `localCache` hit short-circuit the authoritative `rulesVersion` and expiry checks. Either (a) store the `rulesVersion` alongside the cached tuple and re-validate/discard local-cache entries stamped with an older version the same way `conntrack.Conns` entries are handled, or (b) invalidate the entire local cache synchronously whenever `f.rulesVersion` changes (e.g., by comparing a captured `rulesVersion` on `Get()` in addition to the ticker generation), rather than relying solely on a fixed-interval ticker.

### Proof of Concept
1. Configure nebula with `routines > 1` (enabling the default 1s `firewall.conntrack.routine_cache_timeout`) and a permissive inbound rule.
2. Send a UDP flow matching the rule; `Firewall.Drop` calls `addConn` and the flow's tuple is inserted into `localCache` on the next `inConns` hit [10](#0-9) .
3. Reload the firewall config to a stricter ruleset that would reject this tuple (bumping `f.rulesVersion`, as exercised in `TestFirewall_DropConntrackReload`) [11](#0-10) .
4. Immediately resend a packet matching the same tuple on the same reader routine before the `ConntrackCacheTicker` fires again; `inConns` hits the `localCache` and returns `true`, admitting the packet even though `table.match` against the new rules (and a cache-miss path) would have returned `ErrNoMatchingRule` [1](#0-0) .

// Evict checks if a conntrack entry has expired, if so it is removed, if not it is re-added to the wheel
// Caller must own the connMutex lock!
func (f *Firewall) evict(p firewall.Packet) {
	// Are we still tracking this conn?
	conntrack := f.Conntrack
	t, ok := conntrack.Conns[p]
	if !ok {
		return
	}

	newT := t.Expires.Sub(time.Now())

	// Timeout is in the future, re-add the timer
	if newT > 0 {
		conntrack.TimerWheel.Advance(time.Now())
		conntrack.TimerWheel.Add(p, newT)
		return
	}

	// This conn is done
	delete(conntrack.Conns, p)
}

// Get checks if the cache ticker has moved to the next version before returning
// the map. If it has moved, we reset the map.
func (c *ConntrackCacheTicker) Get() ConntrackCache {
	if c == nil {
		return nil
	}
	if tick := c.cacheTick.Load(); tick != c.cacheV {
		c.cacheV = tick
		if ll := len(c.cache); ll > 0 {
			if c.l.Enabled(context.Background(), slog.LevelDebug) {
				c.l.Debug("resetting conntrack cache", "len", ll)
			}
			c.cache = make(ConntrackCache, ll)
		}
	}

	return c.cache
}
