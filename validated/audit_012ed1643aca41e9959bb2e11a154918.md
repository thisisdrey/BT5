### No vulnerability found for this question.

**Analysis:**

The claimed double-spend does not occur. `Contract::execute_intents` wraps the real `Contract` state in `Deltas` via `Engine::new(self, ...)` [1](#0-0) [2](#0-1) , and both `AuthCall`s in a batch are processed sequentially, synchronously, within the *same* `execute_intents` function-call execution via `DefuseIntents::execute_intent` iterating intents [3](#0-2) .

Each `auth_call` invokes `Contract::withdraw` → `internal_sub_balance`, which mutates `owner.token_balances` directly and returns `Err(DefuseError::BalanceOverflow)` if the subtraction underflows — this check and mutation happen strictly *before* the `near_withdraw(...).then(...).detach()` promise is scheduled [4](#0-3) [5](#0-4) . So for the second `AuthCall` in the batch, the balance is already fully debited by the first, and the second `sub()` fails immediately, before its own promise is ever created.

Because this `Err` propagates up through `execute_signed_intent` and `execute_signed_intents` unhandled [6](#0-5) , the top-level `execute_intents` handler panics via `.unwrap_or_else(|e| e.panic())` [1](#0-0) . Under NEAR protocol semantics, when a function call panics, the entire action receipt fails atomically: all state writes made during that call are rolled back, and any promises "created" via host calls during that same execution (including the first `AuthCall`'s `.detach()`-ed `near_withdraw().then(...)`) are never actually dispatched as outgoing receipts, since receipt creation is only finalized on successful completion of the calling function.

Thus the binding — total wNEAR debited across all `AuthCall`/`NativeWithdraw`/`StorageDeposit` intents for one signer in one `execute_intents` call never exceeds the signer's starting balance — holds: the second intent's `internal_sub_balance` check fails synchronously before any promise for it is scheduled, and the panic caused by that failure also prevents the first intent's already-scheduled promise from ever being dispatched, since the whole receipt reverts. There is no double-spend and no divergence between `Deltas`'s in-memory ledger and the real `Contract::token_balances`, since they are updated together in lock-step through the same `Deltas<&mut Contract>` wrapper, not out-of-band.

    fn execute_signed_intent(&mut self, signed: MultiPayload) -> Result<()> {
        // verify signed payload and get public key
        let public_key = signed.verify().ok_or(DefuseError::InvalidSignature)?;

        // calculate intent hash
        let hash = signed.hash();

        // extract NEP-413 payload
        let DefusePayload::<DefuseIntents> {
            signer_id,
            verifying_contract,
            deadline,
            nonce,
            message: intents,
        } = signed.extract_defuse_payload()?;

        // check recipient
        if verifying_contract != *self.state.verifying_contract() {
            return Err(DefuseError::WrongVerifyingContract);
        }

        self.inspector.on_deadline(deadline);

        // make sure message is still valid
        if deadline < Timestamp::now() {
            return Err(DefuseError::DeadlineExpired);
        }

        // make sure the account has this public key
        if !self.state.has_public_key(&signer_id, &public_key) {
            return Err(DefuseError::PublicKeyNotExist(signer_id, public_key));
        }

        // commit nonce
        self.verify_intent_nonce(nonce, deadline)?;
        self.state.commit_nonce(signer_id.clone(), nonce)?;

        intents.execute_intent(&signer_id, self, hash)?;
        self.inspector.on_intent_executed(&signer_id, hash, nonce);

        Ok(())
    }

    fn internal_sub_balance(
        &mut self,
        owner_id: &AccountIdRef,
        tokens: impl IntoIterator<Item = (TokenId, u128)>,
    ) -> Result<()> {
        let owner = self
            .accounts
            .get_mut(owner_id)
            .ok_or_else(|| DefuseError::AccountNotFound(owner_id.to_owned()))?
            .get_mut()
            .ok_or_else(|| DefuseError::AccountLocked(owner_id.to_owned()))?;

        for (token_id, amount) in tokens {
            if amount == 0 {
                return Err(DefuseError::InvalidIntent);
            }

            owner
                .token_balances
                .sub(token_id.clone(), amount)
                .ok_or(DefuseError::BalanceOverflow)?;
        }

        Ok(())
    }
