Based on my analysis of `substrate/frame/broker/src/dispatchable_impls.rs` and `substrate/frame/broker/src/tick_impls.rs`, the claim is confirmed to describe a real gap, though the actual exploit mechanism differs from the report's framing (which incorrectly claims `AutoRenewals` alone drives the stale renewal).

Audit Report

## Title
`pallet-broker::do_remove_lease` fails to purge the corresponding `PotentialRenewals` and `AutoRenewals` entries, allowing a revoked lease's core to be renewed and re-occupied after removal - ([File: substrate/frame/broker/src/dispatchable_impls.rs])

## Summary
`do_remove_lease` only removes the matching entry from `Leases`, leaving any previously-created `PotentialRenewalRecord` for that lease's core (created by an earlier `rotate_sale` call) and any matching `AutoRenewalRecord` in `AutoRenewals` untouched. [1](#0-0)  Because `renew_cores`/`do_renew` key off `PotentialRenewals` and `AutoRenewals` rather than cross-checking `Leases`, the next sale rotation will successfully renew and re-assign the core to the already-removed task.

## Finding Description
When a lease is enrolled for auto-renewal via `do_enable_auto_renew`, an `AutoRenewalRecord{core, task, next_renewal}` is inserted into `AutoRenewals`. [2](#0-1)  Separately, each `rotate_sale` call processes `Leases` and, for leases expiring within the upcoming region, inserts a `PotentialRenewalRecord` keyed by `PotentialRenewalId{core, when: region_end}` so the lease can be renewed at the next rotation. [3](#0-2) 

If governance calls `remove_lease` (→ `do_remove_lease`) *after* this `PotentialRenewalRecord` has already been created for the current region but *before* the next `rotate_sale`, the removal only strips the task from `Leases`; the `PotentialRenewalRecord` and any `AutoRenewalRecord` referencing that core/task remain in storage. [1](#0-0)  At the next `rotate_sale`, `renew_cores` iterates `AutoRenewals` and calls `do_renew(payer, record.core)` for each entry whose `next_renewal` has arrived. [4](#0-3)  `do_renew` looks up `PotentialRenewals` purely by `(core, sale.region_begin)` — it never checks whether `task` is still present in `Leases` — so it finds the stale record, succeeds, purchases/renews the core, and re-inserts a fresh `Workplan` entry for the removed task. [5](#0-4) 

This differs from the report's specific claim that `AutoRenewals` "on its own" keeps the lease active indefinitely: in practice `renew_cores` self-heals stale `AutoRenewalRecord`s in most cases because `do_renew` fails (`Error::NotAllowed`) once the corresponding `PotentialRenewals` entry is absent, dropping the record from the returned list. [6](#0-5)  However, the exploit window identified above — where a `PotentialRenewalRecord` was already created for the current region *before* the lease was removed — is real: `do_remove_lease` never clears it, so one additional un-entitled renewal cycle (and continued core occupation) is possible for a task whose lease governance explicitly revoked. `do_swap_leases`, `do_disable_auto_renew`, and `do_enable_auto_renew` also never cross-validate against `Leases`, confirming no other guard closes this gap. [7](#0-6) 

## Impact Explanation
This is a state-consistency/runtime-behavior bug: `remove_lease` is a privileged administrative action whose intended effect (immediately revoking the task's entitlement to its core) is not fully realized, allowing a bulk-coretime core that should have been returned to the sale/reservation pool to remain allocated to a revoked task for at least one further renewal cycle, and to consume the sovereign account's funds for that renewal. This matches "runtime bugs that compromise intended behavior" in the impact gate, since coretime core allocation is a scarce resource and the bug causes incorrect allocation independent of any single malicious actor's direct action at the trigger point.

## Likelihood Explanation
Likelihood is limited to a narrow timing window: the stale `PotentialRenewalRecord` must already exist for the specific core (created by a prior `rotate_sale` for a lease scheduled to expire in the current region) at the moment `remove_lease` is called, and one further renewal cycle must elapse before the inconsistency is exposed. Enrollment in auto-renewal (`enable_auto_renew`) is permissionless-callable by the sovereign account of the task, so no elevated privilege beyond that is needed to set up the precondition, but the actual removal trigger (`remove_lease`) is a privileged governance/root action, and the bug's persistence is bounded to one rotation because `renew_cores` otherwise self-purges stale `AutoRenewalRecord`s that fail `do_renew`.

## Recommendation
`do_remove_lease` should also purge any `PotentialRenewalRecord` and `AutoRenewalRecord` referencing the removed task's core so that no further renewal can occur after the lease is revoked, e.g., by retaining only non-matching entries in `AutoRenewals` and removing the corresponding `PotentialRenewals` entry for that core/region before returning `Ok(())`.

## Proof of Concept
1. Root calls the lease-setup flow so `task T1` holds `core C1` via `Leases`, with `until` set so the lease expires within the current sale region.
2. `enable_auto_renew` is called for `T1`/`C1` by its sovereign account, inserting an `AutoRenewalRecord{core: C1, task: T1, ...}` into `AutoRenewals`.
3. `rotate_sale` runs (via `do_tick`) and, because the lease is expiring this region, inserts `PotentialRenewalRecord` at `PotentialRenewalId{core: C1, when: region_end}`.
4. Root calls `remove_lease(T1)` before the next rotation — `Leases` no longer contains `T1`, but the `PotentialRenewalRecord` for `C1` and the `AutoRenewalRecord` for `T1`/`C1` remain untouched.
5. Advance to the next sale rotation (`rotate_sale` → `renew_cores` → `do_renew`); assert that `do_renew` succeeds and a new `Workplan`/`Region` entry is created for `C1` still assigned to `T1`, confirming the revoked lease's task continues to occupy and be renewed on the core after removal.

	pub(crate) fn do_renew(who: T::AccountId, core: CoreIndex) -> Result<CoreIndex, DispatchError> {
		let config = Configuration::<T>::get().ok_or(Error::<T>::Uninitialized)?;
		let status = Status::<T>::get().ok_or(Error::<T>::Uninitialized)?;
		let mut sale = SaleInfo::<T>::get().ok_or(Error::<T>::NoSales)?;
		Self::ensure_cores_for_sale(&status, &sale)?;

		let renewal_id = PotentialRenewalId { core, when: sale.region_begin };
		let record = PotentialRenewals::<T>::get(renewal_id).ok_or(Error::<T>::NotAllowed)?;
		let workload =
			record.completion.drain_complete().ok_or(Error::<T>::IncompleteAssignment)?;

		let old_core = core;

		let core = Self::purchase_core(&who, record.price, &mut sale)?;

		Self::deposit_event(Event::Renewed {
			who,
			old_core,
			core,
			price: record.price,
			begin: sale.region_begin,
			duration: sale.region_end.saturating_sub(sale.region_begin),
			workload: workload.clone(),
		});

		Workplan::<T>::insert((sale.region_begin, core), &workload);

		let begin = sale.region_end;
		let end_price = sale.end_price;
		// Renewals should never be priced lower than the current `end_price`:
		let price_cap = cmp::max(record.price + config.renewal_bump * record.price, end_price);
		let now = RCBlockNumberProviderOf::<T::Coretime>::current_block_number();
		let price = Self::sale_price(&sale, now).min(price_cap);
		log::debug!(
			"Renew with: sale price: {:?}, price cap: {:?}, old price: {:?}",
			price,
			price_cap,
			record.price
		);
		let new_record = PotentialRenewalRecord { price, completion: Complete(workload) };
		PotentialRenewals::<T>::remove(renewal_id);
		PotentialRenewals::<T>::insert(PotentialRenewalId { core, when: begin }, &new_record);
		SaleInfo::<T>::put(&sale);
		if let Some(workload) = new_record.completion.drain_complete() {
			log::debug!("Recording renewable price for next run: {:?}", price);
			Self::deposit_event(Event::Renewable { core, price, begin, workload });
		}
		Ok(core)
	}

	pub(crate) fn do_swap_leases(id: TaskId, other: TaskId) -> DispatchResult {
		let mut id_leases_count = 0;
		let mut other_leases_count = 0;
		Leases::<T>::mutate(|leases| {
			leases.iter_mut().for_each(|lease| {
				if lease.task == id {
					lease.task = other;
					id_leases_count += 1;
				} else if lease.task == other {
					lease.task = id;
					other_leases_count += 1;
				}
			})
		});
		Ok(())
	}

	pub(crate) fn do_enable_auto_renew(
		sovereign_account: T::AccountId,
		core: CoreIndex,
		task: TaskId,
		workload_end_hint: Option<Timeslice>,
	) -> DispatchResult {
		let sale = SaleInfo::<T>::get().ok_or(Error::<T>::NoSales)?;
		let mut core = core;

		// Check if the core is expiring in the next bulk period; if so, we will renew it now.
		//
		// In case we renew it now, we don't need to check the workload end since we know it is
		// eligible for renewal.
		if PotentialRenewals::<T>::get(PotentialRenewalId { core, when: sale.region_begin })
			.is_some()
		{
			core = Self::do_renew(sovereign_account.clone(), core)?;
		} else if let Some(workload_end) = workload_end_hint {
			ensure!(
				PotentialRenewals::<T>::get(PotentialRenewalId { core, when: workload_end })
					.is_some(),
				Error::<T>::NotAllowed
			);
		} else {
			return Err(Error::<T>::NotAllowed.into());
		}

		// We are sorting auto renewals by `CoreIndex`.
		AutoRenewals::<T>::try_mutate(|renewals| {
			let pos = renewals
				.binary_search_by(|r: &AutoRenewalRecord| r.core.cmp(&core))
				.unwrap_or_else(|e| e);
			renewals.try_insert(
				pos,
				AutoRenewalRecord {
					core,
					task,
					next_renewal: workload_end_hint.unwrap_or(sale.region_end),
				},
			)
		})
		.map_err(|_| Error::<T>::TooManyAutoRenewals)?;

		Self::deposit_event(Event::AutoRenewalEnabled { core, task });
		Ok(())
	}

	pub(crate) fn do_disable_auto_renew(core: CoreIndex, task: TaskId) -> DispatchResult {
		AutoRenewals::<T>::try_mutate(|renewals| -> DispatchResult {
			let pos = renewals
				.binary_search_by(|r: &AutoRenewalRecord| r.core.cmp(&core))
				.map_err(|_| Error::<T>::AutoRenewalNotEnabled)?;

			let renewal_record = renewals.get(pos).ok_or(Error::<T>::AutoRenewalNotEnabled)?;

			ensure!(
				renewal_record.core == core && renewal_record.task == task,
				Error::<T>::NoPermission
			);
			renewals.remove(pos);
			Ok(())
		})?;

		Self::deposit_event(Event::AutoRenewalDisabled { core, task });
		Ok(())
	}

	pub(crate) fn renew_cores(sale: &SaleInfoRecordOf<T>) {
		let renewals = AutoRenewals::<T>::get();

		let Ok(auto_renewals) = renewals
			.into_iter()
			.flat_map(|record| {
				// Check if the next renewal is scheduled further in the future than the start of
				// the next region beginning. If so, we skip the renewal for this core.
				if sale.region_begin < record.next_renewal {
					return Some(record);
				}

				let Some(payer) = T::SovereignAccountOf::maybe_convert(record.task) else {
					Self::deposit_event(Event::<T>::AutoRenewalFailed {
						core: record.core,
						payer: None,
					});
					return None;
				};

				if let Ok(new_core_index) = Self::do_renew(payer.clone(), record.core) {
					Some(AutoRenewalRecord {
						core: new_core_index,
						task: record.task,
						next_renewal: sale.region_end,
					})
				} else {
					Self::deposit_event(Event::<T>::AutoRenewalFailed {
						core: record.core,
						payer: Some(payer),
					});

					None
				}
			})
			.collect::<Vec<AutoRenewalRecord>>()
			.try_into()
		else {
			Self::deposit_event(Event::<T>::AutoRenewalLimitReached);
			return;
		};

		AutoRenewals::<T>::set(auto_renewals);
	}
