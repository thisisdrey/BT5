### Title
Replay-window TOCTOU in `ConnectionState.Decrypt` allows a duplicated packet to bypass the anti-replay window - ([File: connection_state.go])

### Finding Description
`ConnectionState.Decrypt` splits the replay-window check into two separately-locked critical sections with the actual AEAD decryption happening *outside* the lock: [1](#0-0) 

`cs.window.Check` is called and released under `decryptLock`, then `cs.dKey.DecryptDanger` runs unlocked, and only afterward is `cs.decryptLock` re-acquired to call `cs.window.Update`. `Bits.Check` only inspects state (it does not mark the counter as seen) [2](#0-1) , and the actual "mark as seen"/anti-replay bookkeeping happens only in `Bits.Update` [3](#0-2) . Because no state is mutated between `Check` and `Update`, if two copies of a packet carrying the *same* `messageCounter` are processed concurrently (e.g. by two different UDP reader goroutines/queues for the same tunnel — `readOutsidePackets` takes a `q int` queue index, implying multi-queue concurrent dispatch) [4](#0-3) , both goroutines can pass `Check` (window not yet updated by the other), both will successfully run `DecryptDanger` on the identical ciphertext/nonce, and only the second call to `Update` will be rejected as a duplicate — but only *after* the ciphertext has already been decrypted and (in the winning goroutine) delivered up the stack. This lets a captured/replayed UDP packet be decrypted and forwarded to the tun device twice instead of being dropped as a replay, violating the intended "replayed packets are always dropped before use" invariant, even though the window state itself is not corrupted or rewound afterward.

This does not constitute AEAD key/nonce reuse for encryption purposes (the operation is a deterministic *decryption* of already-transmitted ciphertext with a nonce/counter the sender legitimately used once), and the window itself self-heals since one of the two racing calls to `Update` will always correctly return `false`/`ErrAlreadySeen`. The impact is bounded to a duplicate delivery of a single previously-seen packet, contingent on true concurrent dispatch of the same 4-tuple flow to multiple goroutines, which in most real network stacks with flow-hashed RSS/SO_REUSEPORT queueing is unlikely for genuinely duplicated packets (same 4-tuple typically lands on the same queue), making practical exploitability of the race uncertain without further verification of nebula's UDP dispatch architecture (multi-queue goroutine assignment could not be fully confirmed in `udp/conn.go`/`interface.go` within the available investigation).

### Impact Explanation
At most this allows a single previously-observed encrypted packet to be decrypted and delivered to the tun device twice under a narrow race window, rather than being uniformly dropped as a replay. It does not enable arbitrary replay acceptance, does not rewind or corrupt the `Bits` window state (subsequent `Update` calls still correctly return `false`), and does not cause key/nonce reuse in `DecryptDanger` in the sense of a confidentiality break. This is a narrow, self-correcting TOCTOU race, not a full replay-window bypass or decrypt-path wedge.

### Likelihood Explanation
Exploitation requires the attacker to get two copies of the exact same ciphertext+counter delivered to two different reader goroutines processing the same `ConnectionState` at effectively the same instant. This depends on nebula's UDP read dispatch actually being able to route identical 4-tuple traffic to different concurrent goroutines (unconfirmed from available code), and winning a tight timing race between `Check` and the second `Update`. This makes the finding low-likelihood and environment-dependent rather than a reliably reproducible remote replay bypass.

### Recommendation
Hold `decryptLock` for the entire `Check → Decrypt → Update` sequence in `ConnectionState.Decrypt` (and `VerifyRelay`), or merge `Check`+`Update` into a single atomic "reserve-then-decrypt-then-confirm" operation on `Bits` so no other goroutine can observe the same un-marked counter between the check and the mark, closing the TOCTOU window entirely.

### Proof of Concept
Add a concurrency test in `connection_state_test.go`:
1. Build a `ConnectionState` with a real `dKey`/`eKey` pair and pre-encrypt one packet with a fixed `messageCounter`.
2. Spawn N goroutines that all call `cs.Decrypt(l, counter, ...)` simultaneously with the identical ciphertext.
3. Assert that only exactly one goroutine returns a nil error (successful decrypt+accept), and all others return `ErrAlreadySeen`.
4. Assert `cs.window.Check(l, counter)` returns `false` after the race resolves (window state is consistent).
5. If more than one goroutine returns nil error, that demonstrates the duplicate-delivery race described above.

		return nil, ErrAlreadySeen

// Check returns true if i is within (or way out in front of) the window, and not a replay
func (b *Bits) Check(l *slog.Logger, i uint64) bool {
	// If i is the next number, return true.
	if i > b.current {
		return true
	}

	if b.strictlyWithinWindow(i) {
		return !b.get(i)
	}

	// Not within the window
	if l.Enabled(context.Background(), slog.LevelDebug) {
		l.Debug("rejected a packet (top)", "current", b.current, "incoming", i)
	}
	return false
}

func (b *Bits) Update(l *slog.Logger, i uint64) bool {
	// Fast path: i is the next expected counter. Split out so the function
	// stays small and avoids paying for the slow paths' slog argument-build
	// stack frame on every call. The bit read/test/write is inlined to
	// touch the backing word once.
	if i == b.current+1 {
		pos := i & b.lengthMask
		word := pos >> 6
		mask := uint64(1) << (pos & 63)
		w := b.bits[word]
		if i > b.length && w&mask == 0 {
			b.lostCounter.Inc(1)
		}
		b.bits[word] = w | mask
		b.current = i
		return true
	}
	return b.updateSlow(l, i)
}

// updateSlow handles jumps, in-window backfill, dupes, and out-of-window.
func (b *Bits) updateSlow(l *slog.Logger, i uint64) bool {
	// If i is a jump, adjust the window, record lost, update current, and return true
	if i > b.current {
		end := i
		if end > b.current+b.length {
			end = b.current + b.length
		}
		count := end - b.current
		startPos := (b.current + 1) & b.lengthMask

		var lost int64
		if b.current >= b.length {
			// Steady state: every cleared slot is past warmup, so any unset
			// bit we evict is a lost packet from the previous cycle.
			wasSet := b.clearRange(startPos, count)
			lost = int64(count) - int64(wasSet)
		} else {
			// Warmup (the very first window). Some cleared slots represent
			// packets <= length where eviction is not "lost" in the usual
			// sense. This branch is taken at most once per connection so we
			// don't bother optimizing it.
			for n := b.current + 1; n <= end; n++ {
				if !b.get(n) && n > b.length {
					lost++
				}
			}
			b.clearRange(startPos, count)
		}

		// Anything past the new window can never be backfilled, so it's lost.
		if i > b.current+b.length {
			lost += int64(i - b.current - b.length)
		}
		b.lostCounter.Inc(lost)

		b.set(i)
		b.current = i
		return true
	}

	// If i is within the current window but below the current counter, check to see if it's a duplicate
	if b.strictlyWithinWindow(i) {
		pos := i & b.lengthMask
		word := pos >> 6
		mask := uint64(1) << (pos & 63)
		w := b.bits[word]
		if b.current == i || w&mask != 0 {
			if l.Enabled(context.Background(), slog.LevelDebug) {
				l.Debug("Receive window",
					"accepted", false,
					"currentCounter", b.current,
					"incomingCounter", i,
					"reason", "duplicate",
				)
			}
			b.dupeCounter.Inc(1)
			return false
		}

		b.bits[word] = w | mask
		return true
	}

	// In all other cases, fail and don't change current.
	b.outOfWindowCounter.Inc(1)
	if l.Enabled(context.Background(), slog.LevelDebug) {
		l.Debug("Receive window",
			"accepted", false,
			"currentCounter", b.current,
			"incomingCounter", i,
			"reason", "nonsense",
		)
	}
	return false
}
