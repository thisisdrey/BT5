### Title
Unvalidated `new_authority` in `TransferToNewAccount`/`TransferToNewAccountPda` Permits Permanent Fund Lockout - (File: `programs/marginfi/src/instructions/marginfi_account/transfer_account.rs`)

### Summary
`transfer_to_new_account` and `transfer_to_new_account_pda` move all of a `MarginfiAccount`'s balances into a newly created account whose `authority` is set to the caller-supplied `new_authority` account, which is explicitly annotated `/// CHECK: WARN: New authority is completely unchecked`. Neither instruction validates that `new_authority` is a non-default, controllable key before the migration is finalized on-chain, mirroring the reported ft4 class of bug where a new most-privileged descriptor is installed without validating it retains the necessary capability flags/keys.

### Finding Description
`TransferToNewAccount`/`TransferToNewAccountPda` accept `new_authority` as an `UncheckedAccount<'info>` [1](#0-0) . Inside `transfer_to_new_account`, `initialize_migrated_account` sets the new account's `authority` field directly to `ctx.accounts.new_authority.key()` and copies over all of `old_account.lending_account` (deposits/borrows), while `finalize_migrated_old_account` zeroes the old account's `lending_account` and permanently sets `ACCOUNT_DISABLED` on it [2](#0-1) . There is no on-chain check that `new_authority != Pubkey::default()` or that it is otherwise a key capable of producing a valid signature. All subsequent authorization for the account is gated purely on `marginfi_account.authority == signer` (or, if frozen, the group admin) via `is_signer_authorized` [3](#0-2) .

The `Pubkey::default()` bail-out that exists is only enforced client-side in the CLI helper `marginfi_account_transfer`, not in the on-chain program [4](#0-3) . Any direct caller of the on-chain instruction (bypassing the CLI) can supply `new_authority = Pubkey::default()` (or any other unrecoverable key with no known private key) as the `new_authority` account, since it is a plain `UncheckedAccount` with no signer or ownership constraint. The team's own test suite explicitly documents this design gap: `// WARN: User picks the new authority with no restrictions!` [5](#0-4) .

### Impact Explanation
If `new_authority` is set to `Pubkey::default()` (or any key nobody controls), the resulting new `MarginfiAccount` holds all of the migrated deposits/borrows, but its `authority` field can never be a valid transaction signer — the zero pubkey has no corresponding private key. Because `is_signer_authorized` only ever authorizes the exact `authority` field (or the group admin only while `ACCOUNT_FROZEN`, which is not automatically set here), no one — not the original user, not any admin role — can withdraw, repay, or otherwise operate the new account. The old account is simultaneously wiped of balances and marked `ACCOUNT_DISABLED`, so the funds are unrecoverable through the normal transfer path. This is a permanent lock/freeze of user funds, matching the impact class described in the report (locked funds due to an unvalidated new most-privileged owner).

### Likelihood Explanation
This requires the account's current authority to sign a `transfer_to_new_account`/`transfer_to_new_account_pda` transaction while supplying a bad `new_authority` — either through user/tooling error (e.g. a UI bug, malformed integration, or third-party CPI caller building the transaction incorrectly) or if a malicious front-end/integrator crafts the transaction to strand user funds. Since the check that prevents this exists only in the CLI (not on-chain), any other client, SDK, or CPI caller lacks the safety net entirely, making this reachable outside of the officially blessed CLI path.

### Recommendation
Add an on-chain constraint in `TransferToNewAccount`/`TransferToNewAccountPda` requiring `new_authority.key() != Pubkey::default()`, consistent with the check already present in `p0-cli/src/processor/account.rs`. Consider also requiring `new_authority` to be a `Signer` or otherwise proving key control (e.g., requiring a companion signature/attestation) before finalizing an irreversible balance migration, so that the strongest owner of the new account is guaranteed operable, analogous to validating required flags on a new privileged descriptor.

### Proof of Concept
1. User A creates a `MarginfiAccount` and deposits funds via `MarginfiAccountInitialize` + deposit.
2. User A (or any transaction builder with knowledge of the account/authority) submits `transfer_to_new_account` (or `_pda`) directly to the program, setting `new_authority = Pubkey::default()` and a fresh `new_marginfi_account` keypair/PDA.
3. The instruction succeeds: `initialize_migrated_account` sets `new_account.authority = Pubkey::default()` and copies all balances from the old account [6](#0-5) ; `finalize_migrated_old_account` zeroes the old account's `lending_account` and sets `ACCOUNT_DISABLED` [7](#0-6) .
4. Any later attempt to withdraw/repay/borrow/close on the new account fails `is_signer_authorized`/`account_not_frozen_for_authority` checks because no signer can ever match `Pubkey::default()`, and the account is not `ACCOUNT_FROZEN` so the group admin also cannot intervene through the standard freeze-remediation path.
5. Funds in the new account are permanently locked; the old account is already disabled and empty.

fn initialize_migrated_account(
    new_account: &mut MarginfiAccount,
    old_account: &MarginfiAccount,
    new_authority: Pubkey,
    current_timestamp: u64,
    old_account_key: Pubkey,
) {
    new_account.initialize(old_account.group, new_authority, current_timestamp);
    new_account.lending_account = old_account.lending_account;
    new_account.emissions_destination_account = old_account.emissions_destination_account;
    new_account.account_flags = old_account.account_flags;
    new_account.migrated_from = old_account_key;
    new_account.indexer_flags = old_account.indexer_flags;
    new_account.sync_indexer_flags();
}

fn finalize_migrated_old_account(
    old_account: &mut MarginfiAccount,
    new_account_key: Pubkey,
    current_timestamp: u64,
) {
    old_account.migrated_to = new_account_key;
    old_account.last_update = current_timestamp;
    old_account.lending_account = LendingAccount::zeroed();
    old_account.set_flag(ACCOUNT_DISABLED, true);
    old_account.sync_indexer_flags();
}

pub fn is_signer_authorized(
    marginfi_account: &MarginfiAccount,
    group_admin: Pubkey,
    signer: Pubkey,
    allow_receivership: bool,
    allow_order_execution: bool,
) -> bool {
    if allow_receivership && marginfi_account.get_flag(ACCOUNT_IN_RECEIVERSHIP) {
        return marginfi_account.authority != signer; // forbidden to take receivership of your own account
    }

    if allow_order_execution && marginfi_account.get_flag(ACCOUNT_IN_ORDER_EXECUTION) {
        return true;
    }

    if marginfi_account.get_flag(ACCOUNT_FROZEN) {
        return group_admin == signer;
    }

    marginfi_account.authority == signer
}
