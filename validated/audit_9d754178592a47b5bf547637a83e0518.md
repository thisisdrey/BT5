### Title
Unstaked global stream-load budget is enforced per source-IP connection group, not aggregated across all unstaked senders, allowing Sybil-IP throughput multiplication - ([File: streamer/src/nonblocking/stream_throttle.rs])

### Summary
`StakedStreamLoadEMA::available_load_capacity_in_throttling_duration` returns a fixed constant (`max_unstaked_load_in_throttling_window`, derived from `MAX_UNSTAKED_TPS`/`EXPECTED_UNSTAKED_STREAMS_RATIO`) that is intended to represent the *total* stream budget shared by all unstaked senders. In practice this value is only checked against a per-`ConnectionTableKey` `ConnectionStreamCounter` in `throttle_stream`, and for unstaked peers the key is `ConnectionTableKey::IP(ip)` since `remote_pubkey` is always `None`. Connections sharing the same source IP correctly share one `stream_counter`, but the aggregate cap is never tracked or enforced globally across distinct IPs.

### Finding Description
`SwQos::on_new_stream` (streamer/src/nonblocking/swqos.rs:497-516) calls `max_streams_per_throttling_interval`, which forwards to `StakedStreamLoadEMA::available_load_capacity_in_throttling_duration(ConnectionPeerType::Unstaked, _)` [1](#0-0) . For `Unstaked` this simply returns the constant `max_unstaked_load_in_throttling_window` [2](#0-1) , computed once at construction from `MAX_UNSTAKED_TPS` (200) and `STREAM_THROTTLING_INTERVAL_MS` (100 ms) [3](#0-2) [4](#0-3) . This value never depends on how many unstaked connections/IPs currently exist, and `increment_load` only accumulates load for staked peers into the shared EMA (`if peer_type.is_staked() { ... }`), so unstaked traffic is never fed back into any global counter at all [5](#0-4) .

The actual enforcement happens in `throttle_stream`, which compares this constant against a per-connection-group `ConnectionStreamCounter.stream_count` [6](#0-5) . `ConnectionTable::try_add_connection` keys connections by `ConnectionTableKey::new(ip, remote_pubkey)` [7](#0-6) , and `ConnectionTableKey::new` maps to `ConnectionTableKey::IP(ip)` whenever `remote_pubkey` is `None` [8](#0-7) . Since `SwQos::build_connection_context` sets `remote_pubkey: None` for any connection that fails `get_connection_stake` (i.e., every unstaked connection) [9](#0-8) , all unstaked connections from the same IP land in one `ConnectionEntry` group and correctly share a single `ConnectionStreamCounter` via `connection_entry.first().map(|entry| entry.stream_counter.clone())` [10](#0-9) . But two different source IPs produce two different `ConnectionTableKey::IP` entries, each getting an independent `ConnectionStreamCounter`, and each independently allowed up to the *entire* `max_unstaked_load_in_throttling_window` per `STREAM_THROTTLING_INTERVAL` — because that constant was never designed as a per-key limit, but as the aggregate unstaked share of `max_streams_per_ms`.

Consequently an attacker who opens unstaked QUIC connections from N distinct source IP addresses (trivial for an unprivileged remote client — no stake, gossip, or peer control required) obtains N independent throttling budgets, each equal to the full intended aggregate unstaked budget, instead of splitting a single shared budget. This directly evades the "unstaked/staked stream limits enforced per source, not evadable by connection multiplication" invariant for the IP-diversity dimension (as opposed to same-IP connection multiplication, which is already correctly capped by the shared counter and `max_connections_per_unstaked_peer`).

### Impact Explanation
Legitimate unstaked senders sharing the intended ~20%-of-`max_streams_per_ms` aggregate budget are throttled via `throttled_unstaked_streams` while an attacker using multiple source IPs consumes a multiple of that budget on the ingress QUIC streamer, starving other unstaked clients and consuming disproportionate CPU/thread time in `handle_connection`'s stream-accept loop [11](#0-10) . This is a TPU QoS-bypass/starvation issue: fairness among unstaked senders is not actually enforced globally, only per source-IP connection group.

### Likelihood Explanation
Feasible and repeatable: an unprivileged client needs only multiple source IP addresses (common with cloud/VPS/NAT diversity) to open separate unstaked QUIC connections; no stake, keys, or validator control are needed. Each new IP is a fresh `ConnectionTableKey::IP`, immediately getting a fresh, full-sized throttling budget with no cross-IP coordination or aggregate accounting.

### Recommendation
Track unstaked load in a shared, global counter (analogous to `load_in_recent_interval`/EMA used for staked throttling) and divide/gate `max_unstaked_load_in_throttling_window` by real-time observed aggregate unstaked consumption, or maintain a single shared `ConnectionStreamCounter`-like structure across all unstaked `ConnectionTableKey`s so the constant budget is actually enforced in aggregate rather than being handed out per-IP independently.

### Proof of Concept
Integration test extending the pattern in `test_max_streams_for_unstaked_connection` (streamer/src/nonblocking/stream_throttle.rs:283-297) and `swqos.rs`'s connection tests:
1. Spin up the QUIC streamer with `SwQosConfig::default_for_tests()` (unstaked only) as used in `tpu-client-next/tests/connection_workers_scheduler_test.rs`.
2. From N different simulated client source IPs (e.g., bind N distinct loopback aliases or mock `remote_address` values fed into `build_connection_context`), open one unstaked QUIC connection each, and drive streams via `on_new_stream`/`throttle_stream` concurrently for one `STREAM_THROTTLING_INTERVAL`.
3. Assert that the sum of streams accepted across all N connections during the interval exceeds `max_unstaked_load_in_throttling_window` (the intended aggregate cap), demonstrating that per-IP independent budgets multiply the effective unstaked throughput by N instead of enforcing a single shared cap.
4. Contrast with same-IP multi-connection case (reusing `test_connection_denied_until_allowed`-style setup) which correctly caps at one shared `ConnectionStreamCounter`, to show the discrepancy is specific to IP diversity.

pub(crate) async fn throttle_stream(
    stats: &StreamerStats,
    peer_type: ConnectionPeerType,
    remote_addr: std::net::SocketAddr,
    stream_counter: &Arc<ConnectionStreamCounter>,
    max_streams_per_throttling_interval: u64,
) {
    let throttle_interval_start = stream_counter.reset_throttling_params_if_needed();
    let streams_read_in_throttle_interval = stream_counter.stream_count.load(Ordering::Relaxed);
    if streams_read_in_throttle_interval >= max_streams_per_throttling_interval {
        // The peer is sending faster than we're willing to read. Sleep for what's
        // left of this read interval so the peer backs off.
        let throttle_duration =
            STREAM_THROTTLING_INTERVAL.saturating_sub(throttle_interval_start.elapsed());

        if !throttle_duration.is_zero() {
            debug!(
                "Throttling stream from {remote_addr:?}, peer type: {peer_type:?}, \
                 max_streams_per_interval: {max_streams_per_throttling_interval}, \
                 read_interval_streams: {streams_read_in_throttle_interval} throttle_duration: \
                 {throttle_duration:?}"
            );
            stats.throttled_streams.fetch_add(1, Ordering::Relaxed);
            match peer_type {
                ConnectionPeerType::Unstaked => {
                    stats
                        .throttled_unstaked_streams
                        .fetch_add(1, Ordering::Relaxed);
                }
                ConnectionPeerType::Staked(_) => {
                    stats
                        .throttled_staked_streams
                        .fetch_add(1, Ordering::Relaxed);
                }
            }
            sleep(throttle_duration).await;
        }
    }
}
