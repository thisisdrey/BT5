### Title
Fee-payer buffer-eviction via un-debited balance checks in `check_fee_payer_unlocked` - ([File: core/src/banking_stage/transaction_scheduler/receive_and_buffer.rs])

### Summary
`handle_packet_batch_message` validates each incoming transaction's fee payer independently against the live `working_bank` state via `Consumer::check_fee_payer_unlocked`, without accounting for lamports that would be consumed by other not-yet-executed transactions from the same fee payer received in the same batch/pass. [1](#0-0)  Because `push_ids_into_queue` evicts the globally lowest-priority queued transaction whenever the buffer's `id_to_transaction_state` map exceeds capacity, an attacker who can make their doomed transactions carry a competitive priority can use this to displace unrelated, legitimately-payable transactions from other users. [2](#0-1) 

### Finding Description
`check_fee_payer_unlocked` loads the fee payer account directly from `bank.rc.accounts` and calls `validate_fee_payer`, checking only that the *current, undebited* balance covers the fee for *this one* transaction: [3](#0-2) 
This check is invoked per-packet inside `handle_packet_batch_message`, in a loop over all packets in the received `packet_batch_message`, with no tracking of lamports "reserved" for earlier transactions from the same fee payer seen earlier in the same loop: [4](#0-3) 

Because the bank is not actually debited until a transaction is executed (which happens much later, after scheduling), an attacker can craft N independent transactions (different blockhashes/nonces, so they pass the age/dedup checks) from a single fee payer that only has enough balance for one of them. Each transaction is checked against the same unspent balance and each individually passes `check_fee_payer_unlocked`. Every accepted transaction is inserted via `container.insert_map_only` and pushed into the priority queue via `container.push_ids_into_queue`: [5](#0-4) 

`push_ids_into_queue` enforces capacity by inserting the new id(s) first and then popping the *lowest-priority* entries from the `BTreeSet`-backed `priority_queue` until the map size is back at capacity: [2](#0-1) 

Eviction is priority-based, not source-based or FIFO, so if the attacker's transactions carry a priority (compute-unit price) at or above that of legitimate lower/queued transactions, the attacker's transactions win the eviction contest even though N-1 of them are mathematically guaranteed to fail with `InsufficientFundsForFee`/`InsufficientFundsForRent` once the first one from that payer actually executes and debits the account. This lets a single funded-for-one-tx attacker occupy disproportionate buffer capacity and evict other users' legitimately payable, fee-paying transactions, i.e., pre-fee work (parsing, sanitization, ALT resolution, age/lock checks, the `check_fee_payer_unlocked` account load) is spent on transactions from a party who cannot ultimately pay for more than one of them, and that spent capacity directly displaces other paying users.

The upstream `SaturationState`/priority-floor mechanism in `scheduler_controller.rs` only throttles *future* incoming low-priority packets once the buffer is nearly saturated; it does not protect transactions already resident in the buffer from being evicted, and it does not detect or bound per-fee-payer buffer share. [6](#0-5) [7](#0-6) 

### Impact Explanation
A single unstaked, unprivileged attacker with one funded fee-payer account can generate an unbounded number of independent, distinctly-hashed transactions cheaply (locally signed, no bank interaction required beforehand) and burst them at the leader's TPU. Since each is checked against the same, not-yet-debited balance, all N pass `check_fee_payer_unlocked` in a single receive pass and are pushed into the priority queue, evicting other users' legitimate, ultimately-executable transactions purely based on priority ordering. This matches the "grossly underpriced pre-fee work" / QoS-evasion / buffer-fairness bounty category: work (packet parsing, sanitization, account load, insertion) is spent on transactions that the fee payer cannot possibly cover beyond the first one, at the direct expense of other fee-paying users' transactions being dropped from the buffer.

### Likelihood Explanation
- Preconditions are minimal: attacker needs one funded account (funded with just enough for a single transaction's fee) and the ability to sign and send many distinct transactions (varying blockhash/nonce) in one packet burst — fully within the "unstaked remote client sending packets to TPU" threat model.
- No dedup or per-fee-payer rate limiting exists in the receive path to catch same-payer overspend before it is buffered; nonce dedup logic only protects against *identical* nonce-address collisions, not distinct-nonce/blockhash transactions from the same payer. [8](#0-7) 
- The attack is trivially repeatable per burst and scales with the container capacity margin (`TOTAL_BUFFERED_PACKETS`), making it easy to reproduce deterministically in a unit/integration test.

### Recommendation
Track a running "reserved lamports" ledger per fee payer within a single `handle_packet_batch_message` pass (and ideally across the whole buffered window until execution), subtracting already-accepted-but-unexecuted fees/rent from the fee payer's loaded balance before validating subsequent transactions from the same payer. Alternatively/complementarily, enforce a per-fee-payer cap on the number of concurrently buffered (unexecuted) transactions, and prefer evicting excess transactions from the same offending fee payer over evicting distinct payers' transactions when capacity is exceeded.

fn test_fee_payer_burst_evicts_victim_transaction() {
    let (sender, receiver) = bounded(1024);
    let (bank_forks, mint_keypair) = test_bank_forks_with_fee();
    let (mut receive_and_buffer, mut container) =
        setup_transaction_view_receive_and_buffer(receiver, bank_forks.clone());

    // Attacker funded for exactly ONE tx worth of fee.
    let attacker = Keypair::new();
    let bank = bank_forks.read().unwrap().root_bank();
    let single_tx_fee = LOW_FEE; // low compute-unit-price fee amount
    bank.process_transaction(&transfer_lamports(&mint_keypair, &attacker.pubkey(), single_tx_fee))
        .unwrap();
    drop(bank);

    // Legitimate victim, funded and fee-paying, sent alongside.
    let victim = Keypair::new();
    bank_forks.read().unwrap().root_bank();
    // fund victim similarly...

    let container_capacity = TOTAL_BUFFERED_PACKETS; // container's capacity

    // Craft N = capacity attacker transactions from the same fee payer,
    // each with distinct recent blockhash/nonce so they don't dedup,
    // all with priority >= victim's priority.
    let mut txs: Vec<VersionedTransaction> = (0..container_capacity)
        .map(|_| transfer_with_priority(&attacker, &Pubkey::new_unique(), 1, HIGH_FEE, Hash::new_unique()))
        .collect();
    txs.push(transfer_with_priority(&victim, &Pubkey::new_unique(), 1, LOW_FEE_PLUS, victim_blockhash));

    let packet_batch = to_banking_packet_batch(&txs);
    sender.send(packet_batch).unwrap();

    let stats = receive_and_buffer
        .receive_and_buffer_packets(&mut container, &BufferedPacketsDecision::Hold)
        .unwrap();

    // All attacker transactions pass check_fee_payer_unlocked (undebited balance)
    assert_eq!(stats.num_dropped_on_fee_payer, 0);
    // Buffer is at capacity, so victim's legitimate transaction is evicted
    // via priority-based capacity drop despite it being fully payable.
    assert!(stats.num_dropped_on_capacity > 0);
    // Expected (desired) fix behavior: victim's transaction should remain queued,
    // or the attacker's transactions beyond the first should be rejected/limited.
    assert!(container_contains_fee_payer(&container, &victim.pubkey()));
}

impl TransactionViewReceiveAndBuffer {
    /// Return number of received packets.
    fn handle_packet_batch_message(
        &mut self,
        container: &mut TransactionViewStateContainer,
        decision: &BufferedPacketsDecision,
        root_bank: &Bank,
        working_bank: &Bank,
        packet_batch_message: BankingPacketBatch,
    ) -> ReceivingStats {
        let start = Instant::now();
        // If outside holding window, do not parse.
        let should_parse = !matches!(decision, BufferedPacketsDecision::Forward);

        let sanitize_config = sanitize_config();
        let transaction_account_lock_limit = working_bank.get_transaction_account_lock_limit();

        let mut error_counters = TransactionErrorMetrics::default();
        let mut receiving_stats = ReceivingStats::default();

        for packet in packet_batch_message.iter() {
            let Some(packet_data) = packet.data(..) else {
                continue;
            };

            receiving_stats.num_received += 1;
            if !should_parse {
                receiving_stats.num_dropped_without_parsing += 1;
                continue;
            }

            let bytes = packet_bytes(packet, packet_data);
            let state = match Self::try_handle_packet(
                bytes,
                root_bank,
                working_bank,
                transaction_account_lock_limit,
                &sanitize_config,
                &self.filter_keys,
            ) {
                // Successful parse, ALTs resolved, and no obvious static issues.
                Ok(state) => state,

                // Parsing or some other static checks failed.
                Err(ref err) => {
                    receiving_stats.add_packet_handling_error(err);
                    continue;
                }
            };

            let priority = state.priority();
            let raw_nonce_address = state.transaction().get_durable_nonce().cloned();

            // When we first receive a transaction, we drop it if a) it looks nonce-like, AND
            // b) there is a higher-priority nonce transaction using the same nonce in the queue
            // or any in-flight nonce transaction using the same nonce. This means we discard
            // blockhash transactions structured like nonce transactions; this is acceptable because
            // they would fail after the earlier nonce transaction is processed, and it allows us to
            // prefilter without loading from accounts-db.
            let drop_incoming_nonce_tx = raw_nonce_address
                .and_then(|address| container.get_nonce_transaction_priority_id(&address))
                .is_some_and(|existing| {
                    existing.priority >= priority || !container.is_queued(existing)
                });

            if drop_incoming_nonce_tx {
                receiving_stats.num_dropped_on_nonce_dedup += 1;
                continue;
            }

            // Check blockhash transaction age is ok, or nonce transaction has a valid nonce.
            // Only a fully validated nonce address can be used for priority queue eviction.
            let validated_nonce_address = match working_bank.check_transaction_without_status_cache(
                state.transaction(),
                working_bank.max_processing_age(),
                &mut error_counters,
            ) {
                // Valid nonce transaction
                Ok(Some(nonce_address)) => Some(nonce_address),

                // Valid blockhash transaction
                Ok(None) => None,

                // Invalid
                Err(ref err) => {
                    receiving_stats.add_transaction_error(err);
                    continue;
                }
            };

            // Check the transaction's fee-payer validates.
            if let Err(_err) = Consumer::check_fee_payer_unlocked(
                working_bank,
                state.transaction(),
                &mut error_counters,
            ) {
                receiving_stats.num_dropped_on_fee_payer += 1;
                continue;
            };

            let transaction_id = container.insert_map_only(state);
            let priority_id = TransactionPriorityId::new(priority, transaction_id);

            // Now, if this is a nonce transaction, we know it is validated and higher-priority than any
            // which may exist in the priority queue. If one is queued, evict it. Regardless, record the
            // incoming nonce transaction's nonce as in-use.
            if let Some(nonce_address) = validated_nonce_address {
                if let Some(existing_nonce_priority_id) =
                    container.get_nonce_transaction_priority_id(&nonce_address)
                {
                    receiving_stats.num_evicted_on_nonce_dedup += 1;
                    container.remove_by_id(existing_nonce_priority_id.id);
                }
                container.set_nonce_transaction_priority_id(&nonce_address, priority_id);
            }

            // Transaction is already fully validated and can be inserted into priority queue.
            receiving_stats.num_dropped_on_capacity +=
                container.push_ids_into_queue(std::iter::once(priority_id));

    fn push_ids_into_queue(
        &mut self,
        priority_ids: impl Iterator<Item = TransactionPriorityId>,
    ) -> usize {
        for id in priority_ids {
            self.priority_queue.insert(id);
        }

        // The number of items in the `id_to_transaction_state` map is
        // greater than or equal to the number of elements in the queue.
        // To avoid the map going over capacity, we use the length of the
        // map here instead of the queue.
        let num_dropped = self
            .id_to_transaction_state
            .len()
            .saturating_sub(self.capacity);

        for _ in 0..num_dropped {
            let priority_id = self.priority_queue.pop_first().expect("queue is not empty");
            self.remove_state(priority_id.id);
        }

        num_dropped
    }

    /// Update the scheduler priority floor.
    ///
    /// Semantics: when the retained scheduler buffer is nearly full, drop
    /// arrivals that are at-or-below the current queue-min priority, i.e. no
    /// better than what the bounded scheduler candidate set would evict.
    fn update_scheduler_priority_floor(&mut self, num_dropped_on_capacity: usize) {
        let buffer_size = self.container.buffer_size();
        let saturated = self
            .saturation_state
            .update(buffer_size, num_dropped_on_capacity);
        let priority_floor = if saturated {
            self.container
                .get_min_max_priority()
                .map_or(0, |(min, _)| min)
        } else {
            0
        };

        self.saturation_state.publish_floor(priority_floor);
    }
