### Title
Precompiled contract sig/array extraction trusts unvalidated length and offset words before copying — analogous unvalidated-length buffer copy pattern to CVE-2026-9265 - (File: actuator/src/main/java/org/tron/core/vm/PrecompiledContracts.java)

### Summary
CVE-2026-9265 stems from a fundamental pattern: an attacker-controlled *declared length* field is trusted to size and copy a buffer without validating it against the actual bounds of the source buffer, producing a read past the intended data. The same root-cause pattern — trusting attacker-supplied offset/length words taken from calldata to slice another attacker-supplied buffer, with no bounds check performed before the copy — exists in java-tron's `ValidateMultiSign` and `BatchValidateSign` TVM precompiled-contract implementations via `extractBytesArray` / `extractSigArray` / `extractBytes`.

### Finding Description
`extractBytesArray` and `extractSigArray` read a length word and per-item offset words directly from `DataWord[] words` (parsed from raw contract-call `data`), and pass an attacker-influenced `offset`/`len` straight into `Arrays.copyOfRange(data, offset, offset + len)` with no check that `offset`/`offset+len` are within `data.length`: [1](#0-0) 

`ValidateMultiSign.execute` calls this extraction **outside** of the method's inner `try { ... } catch (Throwable t)` block that only wraps the later permission/signature-verification logic: [2](#0-1) 

The only guard against malformed shapes is `isValidAbiEncoding`, and it is applied conditionally — only `if (VMConfig.allowTvmOsaka())`: [3](#0-2) 

Even when that ABI-shape guard passes (correct total length/word alignment), it does not validate that the internal offset/length *values* embedded in the words are within range of `rawData` — `extractBytesArray`/`extractSigArray` still compute `(bytesOffset + offset + 2) * WORD_SIZE` and pass it to `Arrays.copyOfRange` unchecked. A crafted `bytesOffset` or nested length word can therefore produce a negative or out-of-range slice request.

The existing regression tests (`BatchValidateSignContractTest`, `ValidateMultiSignContractTest`, `OperationsTest#testTip854OuterFrameContainment`) demonstrate the project's own awareness of this exact bug class ("TIP-854" comments describe rejecting malformed calldata shapes so the precompile doesn't propagate an exception into the outer VM frame), but the mitigation added (`isValidAbiEncoding`) is feature-gated behind `allowTvmOsaka` and only checks the *overall* calldata shape, not the *individual* offset/length words consumed inside `extractBytesArray`/`extractSigArray`/`extractBytes`.

### Impact Explanation
Unlike the C/Perl case, the JVM enforces array bounds checks, so this cannot leak adjacent heap memory into a return value the way the PKCS12 `strncpy`/`strlen` bug does. Instead, an out-of-range `Arrays.copyOfRange` call throws `ArrayIndexOutOfBoundsException`/`NegativeArraySizeException`. Because the extraction call sits outside `ValidateMultiSign`'s try/catch, this exception is not gracefully converted into `Pair.of(true, DATA_FALSE)`; it can propagate up through the TVM call path from a `CALL` to the precompile address. Depending on whether the VM/Program call-frame dispatcher uniformly catches `Throwable` for precompile invocations in all TVM code paths, this can manifest as an unhandled runtime exception during transaction execution — a reachable, attacker-controlled denial-of-service/crash vector for contract execution rather than a confidentiality leak.

### Likelihood Explanation
Reachable by any account issuing a smart-contract call whose bytecode invokes the `validatemultisign`/`batchvalidatesign` precompiles (address-routed precompiled contracts), i.e., a single signed transaction from an unprivileged deployer/caller. The `allowTvmOsaka`-gated ABI-shape guard reduces but does not eliminate exposure, since it only validates the outer word-count shape, not the inner offset/length values consumed by `extractBytesArray`/`extractSigArray`.

### Recommendation
Add explicit bounds validation for every attacker-derived offset and length before it is used in `Arrays.copyOfRange`/`extractBytes` inside `extractBytesArray`, `extractSigArray`, and `extractBytes` (verify `offset >= 0`, `len >= 0`, and `offset + len <= data.length`), and wrap the entire `ValidateMultiSign`/`BatchValidateSign` extraction-and-verification flow (not just the inner permission-check block) in a `try/catch(Throwable)` that returns `Pair.of(true, DATA_FALSE)` on any malformed input, independent of the `allowTvmOsaka` feature flag.

### Proof of Concept
Construct calldata for `validatemultisign(address,uint256,bytes32,bytes[])` (or the raw ABI-encoded words consumed by `ValidateMultiSign.execute`) where the dynamic-array offset word (`words[3]`) points to a length word whose value, combined with a per-item offset word, makes `(bytesOffset + offset + 2) * WORD_SIZE` (in `extractBytesArray`, `PrecompiledContracts.java:406-409`) or the analogous computation in `extractSigArray` (`PrecompiledContracts.java:414-425`) resolve to a negative or beyond-array-bounds index into `rawData`. Deploy a minimal contract that performs a `STATICCALL`/`CALL` to the `ValidateMultiSign` precompile address with this crafted payload and observe whether the resulting `ArrayIndexOutOfBoundsException`/`NegativeArraySizeException` propagates uncaught out of `ValidateMultiSign.execute` (since the extraction call at `PrecompiledContracts.java:1072-1074` is outside the method's `try/catch`), verifying whether it is absorbed cleanly by the outer VM dispatcher or surfaces as an unhandled exception during transaction processing.

  private static byte[][] extractBytesArray(DataWord[] words, int offset, byte[] data) {
    if (offset > words.length - 1) {
      return new byte[0][];
    }
    int len = words[offset].intValueSafe();
    byte[][] bytesArray = new byte[len][];
    for (int i = 0; i < len; i++) {
      int bytesOffset = words[offset + i + 1].intValueSafe() / WORD_SIZE;
      int bytesLen = words[offset + bytesOffset + 1].intValueSafe();
      bytesArray[i] = extractBytes(data, (bytesOffset + offset + 2) * WORD_SIZE,
          bytesLen);
    }
    return bytesArray;
  }

  private static byte[][] extractSigArray(DataWord[] words, int offset, byte[] data) {
    if (offset > words.length - 1) {
      return new byte[0][];
    }
    int len = words[offset].intValueSafe();
    byte[][] bytesArray = new byte[len][];
    for (int i = 0; i < len; i++) {
      int bytesOffset = words[offset + i + 1].intValueSafe() / WORD_SIZE;
      bytesArray[i] = extractBytes(data, (bytesOffset + offset + 2) * WORD_SIZE,
          SIG_LENGTH);
    }
    return bytesArray;
  }

  private static byte[] extractBytes(byte[] data, int offset, int len) {
    return Arrays.copyOfRange(data, offset, offset + len);
  }
