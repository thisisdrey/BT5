**Reasoning:** The scenario describes exactly the intended, safe behavior rather than a bug. `wasm_bytes` is deterministic across cache hit/miss and across nodes because it is always derived from the actual contract bytecode length at write time (on a cache miss: `let wasm_bytes = code.code().len() as u64;` before `compile_and_cache`, and the same expression inside `compile_and_persist` when the `CompiledContractInfo` record is built), and the on-disk/in-memory cache entry is addressed by a key that embeds `code_hash` (a cryptographic hash of the exact bytecode) together with the config/VM hash. [1](#0-0) [2](#0-1) [3](#0-2) 

Because the cache key is content-addressed by `code_hash`, any node that hits the cache (in-memory `AnyCache` or on-disk `CompiledContractInfo`) for a given key is, by construction, retrieving metadata that was computed from bit-identical bytecode to what the original compiling node saw — a hash collision would be required for divergence, which is outside the threat model. `before_loading_executable`/`after_loading_executable` then charge `add_contract_loading_fee(wasm_code_bytes)` identically regardless of whether the value came from a fresh compile or a cache read. [4](#0-3) 

This is explicitly the invariant the codebase's own spec calls out under "Determinism": gas values and outcomes must be identical across validators regardless of cache state, and the design achieves this precisely via the content-addressed cache key plus deriving `wasm_bytes` from the real code length rather than any attacker- or node-controlled field. [5](#0-4) 

There is no reachable attacker-controlled path to make `wasm_bytes` diverge between a compiling node and a cache-hitting node for the same `code_hash`; the restart/eviction scenario described does not introduce any inconsistency, since the on-disk cache entry's `wasm_bytes` field was written from the same code at compile time and is keyed by `code_hash`. This does not meet the bar for a concrete loss/freezing of funds, consensus divergence, or shard halt — it is normal, correct caching behavior.

        if config.fix_contract_loading_cost {

                let error =

                return Err(error);
            }
        }
        Ok(())
    }
