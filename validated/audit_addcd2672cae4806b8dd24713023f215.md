### Title
Unauthenticated remote crash of the entire nebula listener via any `recvmmsg`/`recvmsg` errno propagating through `ListenOut` to `onFatal` - ([File: interface.go])

### Summary
This is the closest reachable analog to the Canto finding. In Canto, a benign/expected condition in an unrelated code path (`distributeFees` returning an error for zero fees) is escalated to a hard failure that reverts an entire unrelated user transaction. In nebula, the analogous escalation is at the transport layer: `StdConn.recvmmsg`/`recvmsg` in `udp/udp_linux.go` turns *any* non-zero `errno` from the `recvmmsg`/`recvmsg` syscall into a hard `error` return, and `StdConn.ListenOut` simply returns that error up the stack instead of treating it as a per-packet condition and continuing to read.

### Finding Description
`listenOut` in `interface.go` runs `li.ListenOut(...)` in a loop-owning goroutine: [1](#0-0) 

`ListenOut` on Linux (`udp/udp_linux.go`) loops calling `recvmmsg`/`recvmsg`, and any error returned by that call causes `ListenOut` itself to `return err`, ending the read loop entirely: [2](#0-1) 

`recvmmsg`/`recvmsg` convert *any* nonzero `errno` from the syscall (other than `EINTR`, which is retried by the caller) into a returned Go `error`: [3](#0-2) 

Back in `listenOut`, once `ListenOut` returns a non-nil error while the interface isn't already shutting down, it is logged and passed to `onFatal`, which triggers a one-time process-wide shutdown trigger: [4](#0-3) 

The failure mode this mirrors from the Canto bug: a condition that is a routine, expected occurrence on a UDP socket (not an attack, not corruption) is treated by the code as an unrecoverable fatal error, and that decision is made in a totally generic, non-targeted code path that affects every peer's traffic, not just a single problematic packet/connection. On Linux, unconnected UDP sockets can surface asynchronous ICMP "port unreachable"/"host unreachable" errors from *any* remote address as an `ECONNREFUSED`/`ECONNRESET`/`EHOSTUNREACH` errno on a subsequent `recvmsg`/`recvmmsg` call, completely independent of which peer's datagram is actually being read. Such ICMP messages are trivially forgeable by any off-path or on-path attacker without holding a nebula certificate, since they merely need to be routed to the host (source IP is not authenticated at the network layer). Because `recvmmsg`/`recvmsg`'s error handling in `udp_linux.go` has no allowance for this class of "soft" socket error, that errno is converted into a fatal error that tears down the read loop and, via `onFatal`, brings down the whole nebula listener/tunnel service, exactly as the Canto hook's unconditional propagation of an incidental error reverted otherwise-unrelated user transactions.

### Impact Explanation
If reachable, this results in a remote, unauthenticated denial-of-service against the entire nebula node: all currently-established tunnels for all peers are terminated when the listener goroutine exits and `onFatal`/`triggerShutdown` fire, not merely the packet or connection associated with the triggering condition. This matches the "remote crash impact" / "remote state poisoning" bar for a valid analog, since a single unauthenticated network event unrelated to the recipient of any specific packet can take down service for every legitimate, cert-holding peer.

### Likelihood Explanation
Likelihood depends on whether the specific socket options used by nebula (`SO_REUSEPORT`, no explicit `IP_RECVERR`/`SO_BSDCOMPAT` disabling of ICMP-derived socket errors) actually let ICMP-triggered errno values surface through `recvmmsg`/`recvmsg` in this configuration; I was not able to fully verify this from the available code (whether nebula disables `ICMP` error delivery to the UDP socket via a sockopt, or whether the kernel version/behavior in the deployed environment suppresses it for connectionless sockets). This is a real, well-known Linux networking behavior class (`recvmmsg`/`recvmsg` returning `ECONNREFUSED` on unconnected UDP sockets due to unrelated ICMP), but confirming exploitability requires runtime/kernel verification that a background agent with an actual environment could perform; treat the likelihood as plausible but not proven from static analysis alone.

### Recommendation
In `udp/udp_linux.go`'s `recvmmsg`/`recvmsg`, do not propagate every non-`EINTR` errno as a fatal `ListenOut`-ending error. Specifically:
- Distinguish genuinely fatal socket conditions (e.g., the fd was closed, `EBADF`) from transient/soft errors (e.g., `ECONNREFUSED`, `EHOSTUNREACH`, `ENETUNREACH`) that can arise from unrelated, unauthenticated ICMP traffic on unconnected UDP sockets.
- For soft errors, log and `continue` the read loop (similar to how `EINTR` is already retried) rather than returning the error to `listenOut`.
- Only call `f.onFatal` for conditions that truly indicate the socket can no longer service any traffic.

### Proof of Concept
Not independently verified in an environment (no filesystem/terminal access here). The path to demonstrate this, for a background agent with a running nebula node:
1. Start a nebula node with an established tunnel to at least one peer.
2. From an unauthenticated attacker-controlled path with the ability to reach the node's UDP listening port/IP, send a forged ICMP Port/Host Unreachable message referencing the nebula UDP socket's local port (or otherwise induce a kernel-delivered async error on the listening `SOCK_DGRAM` socket, e.g., by having a previously-contacted address respond with ICMP unreachable while the socket has pending errors enabled).
3. Observe whether `recvmmsg`/`recvmsg` returns a non-zero errno, causing `ListenOut` to return an error, `listenOut` to call `f.onFatal`, and all tunnels to be torn down — confirming or refuting the DoS.

// onFatal stores the first fatal reader error, and calls triggerShutdown if it was the first one
func (f *Interface) onFatal(err error) {
	swapped := f.fatalErr.CompareAndSwap(nil, &err)
	if !swapped {
		return
	}
	if f.triggerShutdown != nil {
		f.triggerShutdown()
	}
}

func (f *Interface) listenOut(i int) {
	var li udp.Conn
	if i > 0 {
		li = f.writers[i]
	} else {
		li = f.outside
	}

	ctCache := firewall.NewConntrackCacheTicker(f.ctx, f.l, f.conntrackCacheTimeout)
	lhh := f.lightHouse.NewRequestHandler()
	plaintext := make([]byte, udp.MTU)
	h := &header.H{}
	fwPacket := &firewall.Packet{}
	nb := make([]byte, 12, 12)

	err := li.ListenOut(func(fromUdpAddr netip.AddrPort, payload []byte) {
		f.readOutsidePackets(ViaSender{UdpAddr: fromUdpAddr}, plaintext[:0], payload, h, fwPacket, lhh, nb, i, ctCache.Get())
	})

	// An error after teardown began is shutdown noise, the closed flag covers resources
	// Close releases itself and the cancelled ctx covers ones torn down by their owners
	// reacting to it, like the user device pipes
	if err != nil && !f.closed.Load() && f.ctx.Err() == nil {
		f.l.Error("Error while reading inbound packet, closing", "error", err)
		f.onFatal(err)
	}

	f.l.Debug("underlay reader is done", "reader", i)
}

// recvmmsg does one blocking recvmmsg (MSG_WAITFORONE), reading up to len(msgs) datagrams
func (u *StdConn) recvmmsg(msgs []rawMessage) (int, error) {
	r, _, errno := unix.Syscall6(
		unix.SYS_RECVMMSG,
		uintptr(u.sysFd),
		uintptr(unsafe.Pointer(&msgs[0])),
		uintptr(len(msgs)),
		unix.MSG_WAITFORONE,
		0,
		0,
	)
	if errno != 0 {
		if u.closed.Load() {
			return 0, net.ErrClosed
		}
		return 0, &net.OpError{Op: "recvmmsg", Err: errno}
	}
	n := int(r)
	if (n == 0 || msgs[0].Len == 0) && u.closed.Load() {
		return 0, net.ErrClosed
	}
	return n, nil
}

// recvmsg does one blocking recvmsg into msgs[0]
func (u *StdConn) recvmsg(msgs []rawMessage) (int, error) {
	r, _, errno := unix.Syscall6(
		unix.SYS_RECVMSG,
		uintptr(u.sysFd),
		uintptr(unsafe.Pointer(&msgs[0].Hdr)),
		0,
		0,
		0,
		0,
	)
	if errno != 0 {
		if u.closed.Load() {
			return 0, net.ErrClosed
		}
		return 0, &net.OpError{Op: "recvmsg", Err: errno}
	}
	if r == 0 && u.closed.Load() {
		return 0, net.ErrClosed
	}
	msgs[0].Len = uint32(r)
	return 1, nil
}
