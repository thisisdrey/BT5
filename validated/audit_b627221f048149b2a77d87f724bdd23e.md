### Title
Unauthenticated `RecvError` packet lets an attacker with no CA-signed certificate tear down an arbitrary victim tunnel by guessing/observing a remote index - ([File: outside.go])

### Summary
`header.RecvError` packets are processed *before* any decryption or certificate/handshake authentication, exactly like `header.Handshake` packets. `handleRecvError` uses the attacker-supplied `h.RemoteIndex` field straight off the wire to look up a live `HostInfo` and, if the packet's source UDP address happens to equal (or the hostinfo has no recorded remote yet) the tunnel's remote endpoint, it unconditionally tears the tunnel down. No cryptographic proof of identity is required to send this packet type.

### Finding Description
`readOutsidePackets` branches on the packet header type before any authentication occurs: [1](#0-0) 

`header.RecvError` is dispatched straight to `f.handleRecvError(via.UdpAddr, h)`, which is called with only the raw header and the sender's UDP address — no cert, no cryptographic verification of the sender's identity: [2](#0-1) 

The vulnerable trust decision is the address comparison:
```go
hr := hostinfo.GetRemote()
if hr.IsValid() && hr != addr {
    ...
    return
}
f.closeTunnel(hostinfo)
f.handshakeManager.DeleteHostInfo(hostinfo)
```
This mirrors the `Vault.mintYieldFee` bug class: the function should only accept a "state change" request (closing/tearing down state) from the party it was actually cryptographically bound to (the CA-authenticated peer holding the tunnel keys), but instead it trusts a caller-controlled value taken directly off an unauthenticated packet — the UDP source address `addr`, which is a plain, spoofable IP header field (UDP source addresses are trivially forgeable, and even without spoofing, an on-path/off-path attacker who can observe or guess the target's UDP 4-tuple and `RemoteIndex` needs no certificate at all to reach this code path). If `hr` is not yet valid (e.g., before the first roam/learn), the check is skipped entirely and any attacker can immediately close the tunnel with just a guessable `RemoteIndex`.

The `RemoteIndex` itself is a 32-bit value generated by `generateIndex` and exchanged in cleartext handshake headers, so it is observable to any on-path attacker and is not secret; unlike the encrypted counters used for message decryption, it is not covered by AEAD authentication for this control packet type.

### Impact Explanation
An attacker who has never obtained a CA-signed certificate — and who can either spoof UDP packets to the target or observe traffic between two Nebula nodes to learn a live `RemoteIndex`/UDP endpoint pair — can send a single unauthenticated `RecvError` packet to force `closeTunnel` and `DeleteHostInfo` on the victim's established tunnel. This is a remote denial-of-service / forced-teardown of the encrypted mesh tunnel between two authenticated peers, achievable without ever presenting a certificate to the CA pool or completing a handshake, matching the "remote crash/state poisoning" and "firewall/handshake bypass" impact classes called out in the validation criteria.

### Likelihood Explanation
Reaching this code requires only sending a 12-byte cleartext UDP packet with `Type = RecvError` and a `RemoteIndex` value; `ShouldRecvError` rate/allow-list gating exists but is a mitigation, not an authentication mechanism (per the CHANGELOG entry noting `recv_error` handling was already flagged for review: "Disable sending recv_error messages when a packet is received outside the allowable counter window" (#1459)). The `RemoteIndex` is not secret (it travels in cleartext in every packet header), so an attacker positioned to sniff or spoof traffic between two peers can trivially construct a valid teardown packet.

### Recommendation
Do not allow an unauthenticated packet type to mutate hostmap/tunnel state based solely on a UDP-header-derived source address matching a previously learned (and possibly still-unset) remote address. At minimum:
- Require `hr.IsValid()` before ever honoring a `RecvError` (never skip the check when `hr` is invalid).
- Bind `RecvError` handling to an authenticated channel (e.g., require it be sent inside an encrypted `Message`/control packet like `NebulaControl`, verified by the session's AEAD keys) instead of accepting it in cleartext prior to any decryption.
- Treat the UDP source-address match as, at best, a weak heuristic, not a security boundary, since UDP source addresses are attacker-controlled.

### Proof of Concept
1. Node A and Node B complete a legitimate Nebula handshake and establish a tunnel; Node A's `RemoteIndex` for B (and vice versa) is exchanged in cleartext handshake headers observable on the wire.
2. Attacker M (holding no CA-issued certificate) observes the handshake or otherwise learns B's `RemoteIndex` value and A's UDP `AddrPort`.
3. M crafts a raw UDP packet: `header.Encode(buf, header.Version, header.RecvError, 0, <B's RemoteIndex>, 0)` and sends it to A's UDP endpoint, spoofing the source address to match B's (`hr`) if a stricter check is in place, or simply sending it before A has learned/roamed `hr` (so the `hr.IsValid()` check is bypassed).
4. `handleRecvError` on A finds the hostinfo via `QueryReverseIndex`, the address check passes (or is skipped), and A calls `f.closeTunnel(hostinfo)` plus `DeleteHostInfo`, forcibly terminating the encrypted tunnel — despite M never having presented any certificate to A's `cert.CAPool`. func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
