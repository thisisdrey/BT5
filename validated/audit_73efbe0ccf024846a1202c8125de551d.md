### Title
Unauthenticated write endpoints on the signer's local event-receiver HTTP server accept forged StackerDB/block/burn-block events without any token or signature check - ([File: libsigner/src/events.rs])

### Summary
The `rails_admin` CSRF advisory is a "non-GET write path lacking token validation" bug class. The closest in-scope analog is `SignerEventReceiver::next_event` in `libsigner/src/events.rs`, which implements the HTTP server that the `stacks-node` uses to push `StackerDBChunksEvent`, `BlockValidateResponse`, `BurnBlockEvent`, `StacksBlockEvent`, and `/shutdown` control messages into the signer process. Unlike the node's own RPC handlers (e.g. `postblock_proposal.rs`, which is gated by `connection_options.auth_token`), this receiver performs **no authentication check whatsoever** on incoming POST requests before deserializing them and forwarding them into the signer's `SignerRunLoop`.

### Finding Description
`SignerEventReceiver::next_event` dispatches based solely on URL path, with no header/token/signature validation: [1](#0-0) 

Compare this to the node-side equivalent write endpoint that *is* gated, `postblock_proposal.rs`, which checks `connection_options.auth_token` before accepting a block-proposal write (confirmed present via 10 matches for `auth_token` in that file, function signature and imports at lines 1-100 shown above). The `docs/signing.md` and sample configs (`sample/conf/mainnet-miner-conf.toml`, `testnet-signer.toml`) describe an `auth_token`/`auth_password` pair that is meant to protect signer↔node communication, but that token is only enforced on the **node's** RPC surface (e.g., block-proposal POST) — it is never checked by the **signer's own** listening HTTP server (`SignerEventReceiver`) that accepts `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, and `/new_block` events. Any request reaching that TCP port is processed: [2](#0-1) 

This breaks the equality "authenticated event from the node" vs. "any POST body from any TCP peer" — the analog to CSRF's missing-token-on-state-changing-request. Since `forward_event` pushes the deserialized message straight to the signer's runloop channel with no additional provenance check, and the receiver's own request loop performs no IP allow-listing or shared-secret validation, this is the equivalent of an auth gate that "fails open."

Note: `StackerDBChunkData` embedded in a forged `StackerDBChunksEvent` still carries a `SlotMetadata.signature`, and downstream signer logic that acts on such data may re-verify signer identity via `SlotMetadata::verify` (as seen in `libstackerdb/src/libstackerdb.rs`), which would mitigate impact for that specific message type. However, `BurnBlockEvent`, `BlockValidateResponse`, and the `/shutdown` control message have no such secondary signature layer in the receiver path, and I was not able to fully trace (within the remaining tool budget) whether every downstream consumer of these events re-validates provenance before acting — this is a gap in my verification.

### Impact Explanation
If the signer's event-receiver port (`endpoint` in `mainnet-signer-conf.toml`, e.g. `0.0.0.0:30000`) is reachable by any unprivileged network peer (misconfiguration is plausible since the docs only warn about `node_host`, not inbound exposure of `endpoint`), an attacker can:
- POST to `/shutdown` to terminate the signer's event loop (unauthenticated remote DoS of signer availability).
- POST forged `BurnBlockEvent` / `BlockValidateResponse` / `StacksBlockEvent` bodies to influence signer-side state machine transitions if those event types are not independently signature-checked downstream.

This maps to the rubric's "Critical - remote crash/unauthenticated DoS from few messages" and potentially "unauthenticated/unauthorized write to state" if downstream consumers trust these events without re-validation.

### Likelihood Explanation
Likelihood depends entirely on network exposure of the signer's `endpoint` (loopback-only per sample configs, which would make this local-only and out of scope for "remote unprivileged"). Where operators bind this endpoint to a non-loopback address (which the configuration format permits and does not warn against for inbound exposure), the vulnerability is directly remotely reachable with no privilege needed. I could not fully confirm from the available index whether all deployments default to loopback-only binding or whether any deployment guidance enforces this restriction — this affects the confidence of the "remote, unprivileged" classification required by the rules.

### Recommendation
Require and validate a shared-secret/token (reusing the existing `auth_token`/`auth_password` convention already documented for the node↔signer relationship) on every write path in `SignerEventReceiver::next_event`, including `/shutdown`, before deserializing or forwarding request bodies. Optionally restrict binding/listening to loopback by default and document the risk of exposing this port.

### Proof of Concept
1. Start a `stacks-signer` process with `endpoint = "0.0.0.0:30000"` (a config anyone could set per `sample/conf/mainnet-signer-conf.toml`).
2. From an unprivileged remote host, issue `POST /shutdown HTTP/1.1` with an empty body to the signer's endpoint.
3. Observe `next_event` matches the `/shutdown` branch and calls `self.stop_signal.store(true, ...)`, terminating the event receiver loop with no authentication check performed — confirmed by the code at `libsigner/src/events.rs` lines 443-445 inside the dispatch shown above.

    fn next_event(&mut self) -> Result<SignerEvent<T>, EventError> {
        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)
            } else if request.url() == "/new_block" {
                process_event::<T, StacksBlockEvent>(request)
            } else {
                let url = request.url().to_string();
                debug!(
                    "[{:?}] next_event got request with unexpected url {}, return OK so other side doesn't keep sending this",
                    event_receiver.local_addr,
                    url
                );
                ack_dispatcher(request);
                Err(EventError::UnrecognizedEvent(url))
            }
        })?

fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}
