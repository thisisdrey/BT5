## Finding

### Title
Bankrupted marginfi accounts are permanently disabled and can never be closed, locking rent-exempt SOL forever - (File: `programs/marginfi/src/state/marginfi_account.rs`, `programs/marginfi/src/instructions/marginfi_group/handle_bankruptcy.rs`)

### Summary
Once `lending_pool_handle_bankruptcy` sets the `ACCOUNT_DISABLED` flag on a `MarginfiAccount`, that flag is never cleared anywhere in the program. Both the user-initiated close path (`marginfi_account_close`) and the permissionless cleanup path (`admin_close_account`) explicitly require the account to not be disabled via `can_be_closed()`, so a bankrupted account is permanently unclosable — exactly analogous to the reported "rejected auction always in default state" bug, where a terminal state has no exit transition back to a closeable state.

### Finding Description
`handle_bankruptcy` zeroes out the account's bad debt and then sets the disabled flag unconditionally: [1](#0-0) 

`can_be_closed()` — used by both close paths — returns `false` whenever `ACCOUNT_DISABLED` is set, with no other logic in the codebase to unset this flag: [2](#0-1) 

The authority-initiated close instruction enforces `can_be_closed()`: [3](#0-2) 

The permissionless 60-day-inactivity cleanup instruction (`admin_close_account`) enforces the same check: [4](#0-3) 

A repo-wide search confirms no instruction anywhere unsets `ACCOUNT_DISABLED` (`unset_flag(ACCOUNT_DISABLED...)` does not exist in the codebase), and the only other place that sets it is `transfer_to_new_account`/`transfer_to_new_account_pda`, which sets it on the *old* account being migrated away — it never clears it back: [5](#0-4) 

The account lifecycle documentation itself confirms bankruptcy is a terminal, effectively irreversible state ("The account is effectively zeroed out and disabled") but the "Closed" stage description (stage 5) assumes only "no remaining balances," omitting that a disabled account can never reach the closed state regardless of balances: [6](#0-5) 

The `ACCOUNT_DISABLED` bit is also excluded from the fuzz-harness's "stuck transient flag" check because it is treated as an intentional terminal state rather than a transient one that must clear, which is consistent with this being unaddressed by design rather than a temporary glitch: [7](#0-6) 

### Impact Explanation
Once any account is bankrupted (which the `BANKRUPTCY.md` guide states is rare but does happen — "liquidators haven't been running properly... an asset is too illiquid... an asset's price changes drastically"), the rent-exempt SOL backing that account's PDA is permanently locked — no authority, admin, or permissionless instruction can ever reclaim it. This is an unauthorized/unrecoverable permanent lock of user funds (the account's rent), and it also leaves stale/dead accounts (`PoolFactory`-style listing analog: `PoolFactory.marketPools`/`pools`) accumulating indefinitely in on-chain state, which the `admin_close_account` permissionless-cleanup mechanism was specifically designed to prevent for the general "empty and inactive" case but fails to cover once bankruptcy has occurred.

### Likelihood Explanation
Bankruptcy itself requires unusual market conditions (illiquid asset, drastic price move, liquidator downtime) and is explicitly documented as rare ("As of November 2025, bankruptcy has never been executed in the main pool"). However, once it does occur — through the normal, unprivileged `handle_bankruptcy` flow (permissionless when `PERMISSIONLESS_BAD_DEBT_SETTLEMENT_FLAG` is set) — the resulting lock is deterministic and unconditional; there is no code path, privileged or not, that reverses it.

### Recommendation
Add either: (1) a dedicated permissionless/admin instruction that allows closing an `ACCOUNT_DISABLED` account once its balances are confirmed empty (bankruptcy already zeroes all balances), returning rent to the fee wallet the same way `admin_close_account` does; or (2) relax `can_be_closed()`/`admin_close_account`'s check so that `ACCOUNT_DISABLED` accounts with fully empty balances and no pending liquidation/order state are eligible for closure.

### Proof of Concept
1. Set up a lender and a borrower bank as in `programs/marginfi/tests/admin_actions/bankruptcy_auth.rs`.
2. Drive the borrower account into bankruptcy (zero collateral asset while liability remains), then call `lending_pool_handle_bankruptcy` — this succeeds and sets `ACCOUNT_DISABLED`, as verified in existing tests (`assert!(borrower_marginfi_account.get_flag(ACCOUNT_DISABLED));` in `programs/marginfi/tests/admin_actions/bankruptcy_auth.rs:214-228`).
3. Attempt `marginfi_account_close` as the account authority — fails with `MarginfiError::IllegalAction` because `can_be_closed()` returns `false` (`programs/marginfi/src/state/marginfi_account.rs:181-196`).
4. Wait >60 days and attempt the permissionless `admin_close_account` — also fails for the same reason (`programs/marginfi/src/instructions/marginfi_account/admin_close.rs:26-30`).
5. No instruction exists to unset `ACCOUNT_DISABLED`, so the account (and its rent) remains permanently unclosable.

```rust
    fn can_be_closed(&self) -> bool {
        let is_disabled = self.get_flag(ACCOUNT_DISABLED);
        let is_in_flashloan = self.get_flag(ACCOUNT_IN_FLASHLOAN);
        let is_in_receivership = self.get_flag(ACCOUNT_IN_RECEIVERSHIP);
        let is_frozen = self.get_flag(ACCOUNT_FROZEN);
        let only_has_empty_balances = self.lending_account.balances.iter().all(|balance| {
            let liability_shares: I80F48 = balance.liability_shares.into();
            balance.get_side().is_none() && liability_shares <= I80F48::ZERO
        });

        !is_disabled
            && only_has_empty_balances
            && !is_in_flashloan
            && !is_in_receivership
            && !is_frozen
    }
```

```rust
/// Assert no marginfi account ended the sequence with a transient flag
/// stuck. Any `1` bit at the masked positions means a `*End*` ix
/// failed to clear its corresponding flag — a real bug, since the
/// harness's `#[end]` runs after every flow completes.
pub fn assert_marginfi_accounts_have_no_transient_flags(
    trident: &mut Trident,
    marginfi_accounts: &[Pubkey],
) {
    for &pk in marginfi_accounts {
        let Some(acc) = trident.get_account_with_type::<MarginfiAccount>(&pk, None) else {
            continue;
        };
        let stuck = acc.account_flags & TRANSIENT_FLAGS_MASK;
        invariant!(
            stuck == 0,
            "marginfi account {pk} has stuck transient flags 0x{stuck:x} (full account_flags 0x{:x})",
            acc.account_flags
        );
    }
```
