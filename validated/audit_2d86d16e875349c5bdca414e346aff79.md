### Title
Regex-based `objectformat`/`refstorage` config probing lets a crafted repository config spoof Gitaly's hash/reference-backend classification - ([File: internal/git/gitcmd/object_id.go])

### Summary
Gitaly determines two security-relevant repository properties — the object-hash algorithm (SHA1/SHA256) and the reference-storage backend (files/reftable/MVCC) — not by asking Git itself, but by manually scanning the repository's raw `config` file with a hand-written regex "probe" and defaulting to a fixed value whenever the probe doesn't match. This is the same anti-pattern as the reported `StashFactory` version check: a heuristic classifier applied to attacker-influenceable input, whose output silently drives downstream trust decisions (which Git binary to use, how to validate/parse object IDs) rather than erroring safely on ambiguity.

### Finding Description
`DetectObjectHash` opens the repository's `config` file and matches lines against `regexpObjectFormat`, defaulting to `sha1` if no match is found, then maps the captured string to `ObjectHashSHA1`/`ObjectHashSHA256` via `ObjectHashByFormat`: [1](#0-0) 

Likewise, `DetectReferenceBackend` scans for a `refstorage` key inside an `[extensions]` section using its own regex parser (`sectionRegex`/`refstorageRegex`), defaulting to `files`: [2](#0-1) 

Both functions are explicitly documented as not validating the configuration and are used to select the Git binary (e.g. the MVCC-specific binary) and to build the hash function used for OID validation elsewhere in the codebase: [3](#0-2) 

The `config` file that these probes read is not always something Gitaly itself generated under controlled conditions. In `CreateRepositoryFromSnapshot`, a bare repository is initialized and then an externally supplied TAR archive — fetched over HTTP from an address the request controls — is extracted directly on top of it via the system `tar` binary, with the code's own comment acknowledging the archive is "trusted *a lot*": [4](#0-3) 

If that archive contains a `config` file (or one is later synced from a replication source, as in `createFromSnapshot`'s `syncGitconfig` step), its `[extensions] objectformat`/`refstorage` values are exactly the "probe surface" `DetectObjectHash`/`DetectReferenceBackend` trust: [5](#0-4) 

Because the parsers are simple regex scans rather than authoritative validation (e.g. they don't cross-check `core.repositoryformatversion`, don't verify the value against the actual on-disk object/reftable layout, and silently fall back to a default on any parse ambiguity), a crafted config can cause Gitaly to compute an object hash function or select a reference backend/Git binary that does not match the repository's real on-disk format — mirroring the `StashFactory` flaw where a "probe" incorrectly classifies an unexpected input and the system proceeds with the wrong classification instead of rejecting it.

### Impact Explanation
Misclassification of the object hash affects OID length/format validation (`ObjectHash.ValidateHex`), `EmptyTreeOID`/`ZeroOID` comparisons, and hashing used throughout ref-update and object-lookup code paths. Misclassification of the reference backend selects the wrong bundled Git binary/behavior (including the experimental MVCC binary) for a repository whose on-disk layout doesn't match, which can produce broken/undefined repository state, inconsistent ref-transaction handling, or crashes — a correctness and availability impact consistent with "broken logic" called out in the report, reachable without any privileged actor since the snapshot/replication config sync path is described by its own maintainers as insufficiently hardened.

### Likelihood Explanation
Reaching this requires control over the `CreateRepositoryFromSnapshot` HTTP source (or being a Gitaly replication peer feeding `createFromSnapshot`), both of which are explicitly flagged in the code as untrusted/needing hardening rather than being fully privileged operator paths. The detection functions themselves are always invoked afterward via `localrepo.Repo.ObjectHash`/`ReferenceBackend`, so any repository whose `config` was populated from such a source is silently exposed to misclassification.

### Recommendation
Do not infer object-hash/reference-backend by best-effort regex parsing of an attacker-reachable config file. Instead, derive these properties authoritatively (e.g. via `git rev-parse --show-object-format`/`--show-ref-format` executed against the repository, or from state recorded by Gitaly itself at creation time) and fail closed with an error instead of defaulting to `sha1`/`files` when detection is ambiguous or the value is unexpected, so a crafted config cannot silently steer Gitaly into treating a repository as a format it isn't.

### Proof of Concept
1. Serve a TAR archive from an HTTP endpoint (used as `http_url` in `CreateRepositoryFromSnapshotRequest`) whose `config` entry contains `[extensions]\nrefstorage = mvcc` (or an `objectformat`/`refstorage` value inconsistent with the actual object/ref layout also included in the archive).
2. Call `CreateRepositoryFromSnapshot`; the archive is extracted on top of the freshly `git init`'d repository as shown in `create_repository_from_snapshot.go`.
3. Subsequent calls that invoke `repo.ObjectHash(ctx)` / `repo.ReferenceBackend(ctx)` (e.g. via `ObjectFormat` RPC or internal housekeeping such as `preparePackRefs`) will classify the repository based on the regex match in `object_id.go`/`reference_backend.go`, potentially selecting a hash function or Git binary/reference backend mismatched with the repository's true on-disk contents.

var regexpObjectFormat = regexp.MustCompile(`^[ \t]*(?i:objectformat)[ \t]*=[ \t]*(.*)[ \t;#]?`)

// DetectObjectHash detects the object-hash used by the given repository. It plucks out the first
// objectformat configuration value from the repository's configuration file and doesn't validate
// the configuration.
//
// Note: It is recommended to use localrepo.ObjectHash since that value is
// cached for a given repository.
func DetectObjectHash(ctx context.Context, repoPath string) (_ git.ObjectHash, returnedErr error) {
	configFile, err := os.Open(filepath.Join(repoPath, "config"))
	if err != nil {
		return git.ObjectHash{}, fmt.Errorf("open: %w", err)
	}
	defer func() {
		if err := configFile.Close(); err != nil {
			returnedErr = errors.Join(returnedErr, fmt.Errorf("close: %w", err))
		}
	}()

	objectFormat := git.ObjectHashSHA1.Format
	scanner := bufio.NewScanner(configFile)
	for scanner.Scan() {
		if matches := regexpObjectFormat.FindSubmatch(scanner.Bytes()); len(matches) > 0 {
			objectFormat = string(matches[1])
			break
		}
	}

	if err := scanner.Err(); err != nil {
		return git.ObjectHash{}, fmt.Errorf("scan: %w", err)
	}

	return git.ObjectHashByFormat(objectFormat)

// DetectReferenceBackend detects the reference backend used by the repository.
// It plucks out the first refstorage configuration value from the repository's configuration
// file and doesn't validate the configuration.
//
// Note: It is recommended to use localrepo.ReferenceBackend since that value is
// cached for a given repository.
func DetectReferenceBackend(ctx context.Context, repoPath string) (_ git.ReferenceBackend, returnedErr error) {
	configFile, err := os.Open(filepath.Join(repoPath, "config"))
	if err != nil {
		return git.ReferenceBackend{}, fmt.Errorf("open: %w", err)
	}
	defer func() {
		if err := configFile.Close(); err != nil {
			returnedErr = errors.Join(returnedErr, fmt.Errorf("close: %w", err))
		}
	}()

	// We default to the files backend and override it with the first refstorage value found in
	// the configuration. Only the reference backend is relevant here, as it alone determines
	// which bundled Git binary is able to read the repository. We deliberately do not inspect the
	// object storage extension: a repository using the MVCC reference backend must be served by
	// the MVCC binary regardless of how its objects are stored.
	refStorage := git.ReferenceBackendFiles.Name

	scanner := bufio.NewScanner(configFile)

	inExtensions := false
	for scanner.Scan() {
		line := scanner.Text()
		if m := sectionRegex.FindStringSubmatch(line); m != nil {
			inExtensions = strings.EqualFold(m[1], "extensions")
			continue
		}
		if !inExtensions {
			continue
		}
		if m := refstorageRegex.FindStringSubmatch(line); m != nil {
			refStorage = strings.TrimSpace(m[1])
		}
	}

	return git.ReferenceBackendByName(refStorage)
}

func (s *server) untar(ctx context.Context, path string, in *gitalypb.CreateRepositoryFromSnapshotRequest) error {
	req, err := http.NewRequestWithContext(ctx, "GET", in.GetHttpUrl(), nil)
	if err != nil {
		return structerr.NewInvalidArgument("Bad HTTP URL: %w", err)
	}

	client := httpClient
	if resolvedAddress := in.GetResolvedAddress(); resolvedAddress != "" {
		client, err = newResolvedHTTPClient(in.GetHttpUrl(), resolvedAddress)
		if err != nil {
			return structerr.NewInvalidArgument("creating resolved HTTP client: %w", err)
		}
	}

	if in.GetHttpAuth() != "" {
		req.Header.Set("Authorization", in.GetHttpAuth())
	}

	rsp, err := client.Do(req)
	if err != nil {
		return structerr.NewInternal("HTTP request failed: %w", err)
	}
	defer rsp.Body.Close()

	if rsp.StatusCode < http.StatusOK || rsp.StatusCode >= http.StatusMultipleChoices {
		return structerr.NewInternal("HTTP server: %s", rsp.Status)
	}

	cmd, err := command.New(ctx, s.logger, []string{"tar", "-C", path, "-xvf", "-"}, command.WithStdin(rsp.Body))
	if err != nil {
		return err
	}

	return cmd.Wait()
}

func (s *server) CreateRepositoryFromSnapshot(ctx context.Context, in *gitalypb.CreateRepositoryFromSnapshotRequest) (*gitalypb.CreateRepositoryFromSnapshotResponse, error) {
	repository := in.GetRepository()
	if err := s.locator.ValidateRepository(ctx, repository, storage.WithSkipRepositoryExistenceCheck()); err != nil {
		return nil, structerr.NewInvalidArgument("%w", err)
	}

	if err := repoutil.Create(ctx, s.logger, s.locator, s.gitCmdFactory, s.catfileCache, s.txManager, s.repositoryCounter, repository, func(repo *gitalypb.Repository) error {
		path, err := s.locator.GetRepoPath(ctx, repo, storage.WithRepositoryVerificationSkipped())
		if err != nil {
			return structerr.NewInternal("getting repo path: %w", err)
		}

		// The archive contains a partial git repository, missing a config file and
		// other important items. Initializing a new bare one and extracting the
		// archive on top of it ensures the created git repository has everything
		// it needs (especially, the config file and hooks directory).
		//
		// NOTE: The received archive is trusted *a lot*. Before pointing this RPC
		// at endpoints not under our control, it should undergo a lot of hardening.
		if err := s.untar(ctx, path, in); err != nil {
			return structerr.NewInternal("extracting snapshot: %w", err)
		}

		return nil
	}); err != nil {
		return nil, structerr.NewInternal("creating repository: %w", err)
	}
