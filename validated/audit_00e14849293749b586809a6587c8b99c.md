### Title
Bridge burn succeeds on source chain while destination mint can fail, stranding funds in `failedMessages` and forfeiting the LayerZero fee - ([File: contracts/ProxyOFT.sol](metronome-synth-public--025/contracts/ProxyOFT.sol))

### Summary
`ProxyOFT._debitFrom` burns the user's synthetic tokens on the source chain after only checking source-side conditions (`isBridgingActive`, `isDestinationChainSupported`). It performs no check that the destination-side mint will succeed. On the destination, `_creditTo` calls `SyntheticToken.mint`, which reverts if the token is deactivated (`onlyIfSyntheticTokenIsActive`) or if `bridgedInSupply() > maxBridgedInSupply` (`SurpassMaxBridgingSupply`). The result mirrors the reported bug class: the source-side debit is irreversible while the destination-side credit can fail due to a governor-controlled flag/cap that changed after the user committed, costing the user the cross-chain fee and leaving the funds dependent on a manual `retryMessage`.

### Finding Description
`_debitFrom` validates only local state and then calls `syntheticToken.burn(from_, amount_)`, permanently removing supply on the source chain. [1](#0-0) 

On the destination, `_creditTo` unconditionally calls `syntheticToken.mint`. [2](#0-1) 

`SyntheticToken._mint` is gated by `onlyIfSyntheticTokenIsActive` and enforces `maxBridgedInSupply`/`maxTotalSupply` caps, both governor-tunable parameters that can change between the user's send and the message delivery. [3](#0-2) 

`NonblockingLzAppUpgradeable._blockingLzReceive` catches the revert and stores the payload hash in `failedMessages`, so the tokens are not re-minted and the message just sits there. [4](#0-3) 

There is a `retryMessage` recovery path, but it only succeeds once the governor restores the active flag or raises the cap — exactly like the original report where funds are stuck until the owner re-whitelists the token.

### Impact Explanation
A user who calls `sendFrom` pays the LayerZero native fee and has their synth tokens burned on the source chain. If the destination mint reverts (token deactivated or bridged-in cap reached — both settable by governance at any time), the user receives nothing on the destination and the burned supply is not restored. Funds are frozen in the `failedMessages` queue until a privileged state change plus a successful `retryMessage`. This is temporary freezing of user funds plus guaranteed loss of the bridging fee.

### Likelihood Explanation
Likelihood is moderate-to-low because triggering conditions require a governor action (deactivating the synthetic token or the cap being reached organically). However, no unprivileged action or malicious endpoint is needed to be harmed — any ordinary user's in-flight or newly-initiated bridge during such a configuration window is affected, and `sendFrom` gives no warning that the destination will reject the mint since the checks are asymmetric.

### Recommendation
Mirror the destination-side preconditions on the source chain where feasible: `_debitFrom` should revert early if `syntheticToken` is inactive, since `isSyntheticTokenActive` is a per-token flag the local `SyntheticToken` contract already exposes. Additionally, expose a view/quote that simulates the destination mint conditions so front-ends can warn users, and document that `retryMessage` must be called after the destination condition is fixed. A longer-term fix is a credit-back/recovery path (e.g., a failed-message handler that re-mints on the source chain) so users are not dependent on governance restoring the flag.

### Proof of Concept
Hardhat fork sketch:

```solidity
// chain A (source): user holds synth tokens from issueSynth
uint256 fee = oft.estimateSendFee(dstChainId, alice, amount);
oft.sendFrom{value: fee}(alice, dstChainId, alice, amount);
// -> SyntheticToken.burn succeeds on A; totalSupply decreases

// governor on chain B (destination) deactivates the token
syntheticTokenB.connect(governor).toggleSyntheticTokenIsActive(); // or maxBridgedInSupply set to 0

// LayerZero delivers message on B: lzReceive -> _blockingLzReceive
// -> nonblockingLzReceive -> _creditTo -> syntheticToken.mint
// -> reverts (SyntheticTokenIsNotActive / SurpassMaxBridgingSupply)
// -> payload hash stored in failedMessages; alice has no tokens on B
//    and tokens were burned on A; the LZ fee is lost

// alice must wait for governance to re-enable, then:
oftB.retryMessage(srcChainId, srcAddress, nonce, payload); // succeeds only then

    function retryMessage(uint16 _srcChainId, bytes calldata _srcAddress, uint64 _nonce, bytes calldata _payload) public payable virtual {
        // assert there is message to retry
        bytes32 payloadHash = failedMessages[_srcChainId][_srcAddress][_nonce];
        require(payloadHash != bytes32(0), "NonblockingLzApp: no stored message");
        require(keccak256(_payload) == payloadHash, "NonblockingLzApp: invalid payload");
        // clear the stored message
        failedMessages[_srcChainId][_srcAddress][_nonce] = bytes32(0);
        // execute the message. revert if it fails again
        _nonblockingLzReceive(_srcChainId, _srcAddress, _nonce, _payload);
        emit RetryMessageSuccess(_srcChainId, _srcAddress, _nonce, payloadHash);
    }
