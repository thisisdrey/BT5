### Title
Truncated 64-bit SHA-1 quarantine-prefix check allows cross-repository object-directory access via brute-forced collision - (File: internal/gitaly/storage/locator.go)

### Summary
`QuarantineDirectoryPrefix` truncates a SHA-1 digest of a repository's relative path down to 8 bytes (64 bits) and uses that truncated value as the sole cryptographic-style check that a client-supplied `GitObjectDirectory` really belongs to the requesting repository. [1](#0-0)  This mirrors the reported bug class: shortening a hash used as a "proof of ownership" check makes brute-force collisions computationally reachable, defeating the intended security guarantee.

### Finding Description
`ObjectDirectoryPath` is called whenever an RPC's `Repository` message carries a `GitObjectDirectory` field that doesn't resolve to a path inside the repository itself (i.e., a quarantine directory living in the storage's shared temp dir). [2](#0-1)  In that case, the only check that the supplied path actually belongs to the caller's own repository is a `strings.HasPrefix` match against `expectedQuarantinePrefix := filepath.Join(tempDir, storage.QuarantineDirectoryPrefix(repo))`. [3](#0-2) 

`QuarantineDirectoryPrefix` computes this "proof" as:
```go
func QuarantineDirectoryPrefix(repo Repository) string {
	hash := [20]byte{}
	if repo != nil {
		hash = sha1.Sum([]byte(repo.GetRelativePath()))
	}
	return fmt.Sprintf("quarantine-%x-", hash[:8])
}
``` [4](#0-3) 

Only the first 8 bytes (64 bits) of the 160-bit SHA-1 digest are kept. This is exactly the flaw pattern described in the external report: shortening a cryptographic digest that is used as an access-control token turns an otherwise-infeasible full-hash collision search into a bounded brute-force problem. Every RPC that accepts a `Repository` message with an attacker-controlled `RelativePath` (e.g., repository creation, import, or any RPC where the caller chooses the relative path of their own project) lets an attacker precompute `sha1(relativePath)[:8]` for arbitrary candidate relative-path strings offline, with no interaction with the server required, until a candidate collides with the truncated prefix of a *different*, real repository whose quarantine directory currently exists on disk under the shared per-storage temp directory (`TempDir`, computed from `<storage>/+gitaly/tmp`). [5](#0-4) 

Because the temp directory is shared across all repositories in a storage, and the prefix comparison is the *only* gate distinguishing "this quarantine directory belongs to repo A" from "it belongs to repo B," an attacker who creates (or already owns) a repository whose relative path hashes (truncated) to the same 8-byte prefix as a victim repository's in-flight quarantine directory can point their own `GitObjectDirectory` field at the victim's quarantine directory. The `HasPrefix` check will pass because it only inspects those 8 bytes, allowing the request to resolve into a directory that was never allocated for the attacker's repository.

### Impact Explanation
Successful exploitation lets an attacker's RPC resolve `ObjectDirectoryPath` (and consequently any Git command run with `GIT_OBJECT_DIRECTORY`/`GIT_ALTERNATE_OBJECT_DIRECTORIES` pointing at it) into another repository's quarantine directory. This can expose objects a victim pushed but that have not yet been merged into the victim's main object store (quarantined pending pre-receive hook approval), i.e., cross-repository object disclosure, and depending on the RPC, could let the attacker cause writes to intersect the wrong repository's quarantine, undermining the isolation the quarantine mechanism is designed to guarantee (see `doc/object_quarantine.md`). [6](#0-5)  This falls squarely in the "quarantine gating" bypass category.

### Likelihood Explanation
64 bits of collision space is significantly weaker than the full 160-bit SHA-1 output, but is still a large offline search space; the attacker also needs a target repository whose quarantine directory is live on disk at the time of the attack (i.e., a push actively awaiting pre-receive/hook processing), and needs to control or predict the naming/creation of their own repository's relative path (which is often at least partially attacker-influenced, e.g., project path/import path). This raises the bar compared to the original 128/160-bit Merkle proof report, but the truncation to 64 bits is an unambiguous, unnecessary weakening of an otherwise-available 160-bit SHA-1 digest, and the existing test suite documents the exact 16-hex-character truncated values, confirming the design as intentional but insufficiently reviewed for its collision-resistance requirements. [7](#0-6) 

### Recommendation
Use the full untruncated hash (or a hash with sufficient bit length, e.g. at least 128 bits, ideally the full SHA-1/SHA-256 digest) in `QuarantineDirectoryPrefix`, and additionally bind the check to a value that is not solely a function of attacker-controlled input (e.g., include a per-transaction random nonce or the storage-generated quarantine directory's own randomly-generated suffix) instead of relying purely on `strings.HasPrefix` matching against a hash of client-suppliable data.

### Proof of Concept
1. Attacker computes `sha1(candidateRelativePath)[:8]` for many candidate relative paths offline until one collides with the known/observed truncated prefix `quarantine-XXXXXXXXXXXXXXXX-` of a victim repository currently mid-push (quarantine directories are discoverable by filename pattern under the shared storage temp dir).
2. Attacker creates/imports a repository using `candidateRelativePath` as its `RelativePath`.
3. Attacker issues an RPC (e.g., any RPC accepting a `Repository` with `GitObjectDirectory` set) with `GitObjectDirectory` set to the victim's quarantine directory path (relative to attacker's own repo root, following the same `objects/../..` traversal patterns already tested in `paths_test.go`). [8](#0-7) 
4. `ObjectDirectoryPath` computes `expectedQuarantinePrefix` from the attacker's own relative path and finds it matches (via the 64-bit collision) the victim's actual quarantine directory path, so the `strings.HasPrefix` check at `internal/git/localrepo/paths.go:71` succeeds and the RPC operates against the victim's quarantined objects. [9](#0-8)

1. `git receive-pack` receives a push

1. `git receive-pack` [configures the unpack process](https://gitlab.com/gitlab-org/git/-/blob/v2.24.0/builtin/receive-pack.c#L1721) to write objects into the quarantine directory
1. `git receive-pack` unpacks the objects into the quarantine directory
1. `git receive-pack` [runs the `pre-receive` hook](https://gitlab.com/gitlab-org/git/-/blob/v2.24.0/builtin/receive-pack.c#L1498) with special `GIT_OBJECT_DIRECTORY` and `GIT_ALTERNATE_OBJECT_DIRECTORIES` environment variables that add the quarantine directory to the search path
1. If the `pre-receive` hook rejects the push, `git receive-pack` removes the quarantine directory and its contents. The push is aborted.
1. If the `pre-receive` hook passes, `git receive-pack` [merges the quarantine directory into the main object directory](https://gitlab.com/gitlab-org/git/-/blob/v2.24.0/builtin/receive-pack.c#L1510).
1. `git receive-pack` enters the ref update transaction

Note that by the time the `update` hook runs, the quarantine directory
has already been merged into the main object directory so it no longer
matters. The same goes for the `post-receive` hook which runs even
later.

Because `pre-receive` has the special quarantine configuration data in
environment variables, any `git` process spawned by `pre-receive` will
inherit the quarantine config and will be able to see the objects that
are being pushed.

func TestQuarantineDirectoryPrefix(t *testing.T) {
	// An nil repository works alright, even if nonsensical.
	require.Equal(t, "quarantine-0000000000000000-", QuarantineDirectoryPrefix(nil))

	// A repository with only a relative path.
	require.Equal(t, "quarantine-8843d7f92416211d-", QuarantineDirectoryPrefix(&gitalypb.Repository{
		RelativePath: "foobar",
	}))

	// A different relative path has a different hash.
	require.Equal(t, "quarantine-60518c1c11dc0452-", QuarantineDirectoryPrefix(&gitalypb.Repository{
		RelativePath: "barfoo",
	}))

	// Only the relative path matters. The storage name doesn't matter either given that the
	// temporary directory is per storage.
	require.Equal(t, "quarantine-60518c1c11dc0452-", QuarantineDirectoryPrefix(&gitalypb.Repository{
		StorageName:        "storage-name",
		RelativePath:       "barfoo",
		GitObjectDirectory: "object-directory",
		GitAlternateObjectDirectories: []string{
			"alternate",
		},
		GlRepository:  "gl-repo",
		GlProjectPath: "gl/repo",
	}))
}
