### Title
`simulate_intents` reports success/`invariant_violated: None` for `AuthCall`/`NotifyOnTransfer` batches that `execute_intents` executes with real cross-contract calls, causing divergent outcomes when a callee branches on real receipt data - (File: `contracts/defuse/core/src/engine/state/cached.rs`)

### Summary
`simulate_intents` runs the `Engine` over `CachedState<Contract>` (a view-only state), whose `auth_call` and `notify_on_transfer` implementations are hard no-ops per the code comment "Simulation that uses a cached state cannot create promises, as it is a view call". `execute_intents` runs over the real `Contract` state, whose `auth_call`/`notify_on_transfer` dispatch real `Promise`s to the target contract via `do_auth_call`/`notify_and_resolve_transfer`. Because the callee code is entirely attacker-controlled, an attacker can construct a receiver that behaves differently when it observes real NEAR runtime execution context, causing the simulated report and the real execution to diverge for the exact same signed batch and state.

### Finding Description
The claimed binding is: `simulate_intents(batch).invariant_violated == None` (and `simulate_intents(batch).report` reflecting a benign outcome) implies `execute_intents(batch)` on the same state produces the corresponding benign, matching real outcome.

Tracing the code:
- `simulate_intents` builds `Engine::new(self.cached(), &mut inspector)` [1](#0-0) , where `self.cached()` wraps `Contract` in `CachedState<W>` [2](#0-1) .
- For `CachedState`, the `notify_on_transfer` implementation is an explicit no-op with the comment "Simulation that uses a cached state cannot create promises, as it is a view call" [3](#0-2) . The `auth_call` implementation for `CachedState` is likewise a no-op (not dispatching any promise), consistent with the same constraint noted at the top of that impl block.
- In contrast, the real `Contract::auth_call` dispatches `Self::do_auth_call(...)` or, if a deposit is attached, chains a `near_withdraw` promise followed by `do_auth_call`, all `.detach()`ed as real cross-contract promises [4](#0-3) . `do_auth_call` schedules `ext_auth_callee::ext_on(p).on_auth(signer_id, auth_call.msg)` against the attacker-chosen `auth_call.contract_id` [5](#0-4) . Similarly, real `Contract::notify_on_transfer` dispatches `Self::notify_and_resolve_transfer(...).detach()` [6](#0-5) .
- The engine itself and its balance/nonce/signature checks (`execute_signed_intent`, `verify_intent_nonce`, `commit_nonce`, `finalize`) are identical between both paths [7](#0-6) , so the divergence is isolated entirely to the promise-dispatching side effects of `AuthCall`/`NotifyOnTransfer`.

Because the target `contract_id` in `AuthCall` (or the FT/NFT/MT receiver in `NotifyOnTransfer`) is attacker-deployed and attacker-controlled, the attacker can write `on_auth`/`mt_on_transfer`-style receiver logic that:
- During `simulate_intents`: is never invoked at all (no promise scheduled) — the simulated report simply shows the `AuthCall` event as if it "succeeded" (there is no callee-side failure path since nothing runs).
- During `execute_intents`: is actually invoked on-chain as a real receipt, where the attacker's callee can check `env::promise_results_count()`, `env::used_gas()`, `env::block_height()`, or any other real-runtime-only value, and branch to revert, panic, or perform different logic (e.g., refuse the callback, cause `do_auth_call`'s promise-result check to fail, or otherwise change downstream refund/`resolve` behavior) — behavior the simulation could never reproduce because no promise/receipt is ever generated in the cached path.

No existing guard closes this gap: `simulate_intents` explicitly documents (via code comment) that it is view-only and cannot create promises, and there is no cross-check, warning, or invariant that forces callers to treat `AuthCall`/`NotifyOnTransfer` results as unverified/unsimulated. `MultiPayload::verify`, nonce/salt checks, and `Deltas::finalize` all operate purely on balance deltas and do not model receipt-level callee behavior at all.

### Impact Explanation
This does not move, credit, or freeze Verifier-custodied token balances in a way that violates internal accounting invariants — `Deltas::finalize` still enforces net-zero balance changes for tokens tracked by the engine, and the `AuthCall`/`NotifyOnTransfer` side effects are external cross-contract calls whose "failure" or "different behavior" does not by itself cause the Verifier to lose custody of funds beyond what the signer authorized. The impact is specifically the one named in the rules' High-severity bucket: "`simulate_intents` reporting an outcome `execute_intents` does not produce when a party settles on that report." A relayer or counterparty who trusts the `SimulationOutput.invariant_violated: None` / benign report and broadcasts the batch based on that report can be misled about what actually happens on-chain, e.g. an `AuthCall` to an attacker's contract that appears harmless in simulation but reverts, drains gas, or executes adversarial logic for real when actually run. This is repeatable across any batch containing `AuthCall` or `NotifyOnTransfer` intents to any attacker-controlled contract, and the blast radius is any relayer/counterparty workflow that uses `simulate_intents` as a pre-flight check before submitting `execute_intents`.

### Likelihood Explanation
The attacker only needs to: (1) deploy their own receiver/callee contract implementing `on_auth` (for `AuthCall`) or the transfer-notification receiver logic, with a branch on `env::promise_results_count()` or other real-runtime-only signals; (2) sign a `MultiPayload` batch that includes an `AuthCall` (or `NotifyOnTransfer`) targeting that contract, using only their own Verifier balance/keys; (3) have the batch's `simulate_intents` output evaluated and trusted by any counterparty (e.g., a solver/relayer that intends to broadcast on the strength of the simulation report). All of this is achievable by an unprivileged actor with no special role, no victim key, and no DAO/relayer-key access — deploying a contract and signing one's own intents are permitted actions. The exploit is fully deterministic and reproducible on every attempt since `CachedState`'s no-op behavior for `auth_call`/`notify_on_transfer` is unconditional.

### Recommendation
Either (a) have `simulate_intents` explicitly flag/report that `AuthCall` and `NotifyOnTransfer` intents were not actually executed (e.g., include a distinct field/marker in `SimulationReport` listing "unsimulated cross-contract calls" rather than presenting a report visually equivalent to one where they succeeded), so consumers cannot mistake the absence of a promise for a successful promise; or (b) document/enforce at the API and client-SDK level that `simulate_intents` results must never be treated as authoritative for batches containing `AuthCall`/`NotifyOnTransfer` intents, and require callers to only rely on the balance-invariant and nonce/signature checks portion of the report for such batches.

    fn simulate_intents(&self, signed: Vec<MultiPayload>) -> SimulationOutput {
        let mut inspector = SimulateInspector::default();
        let engine = Engine::new(self.cached(), &mut inspector);

        let invariant_violated = match engine.execute_signed_intents(signed) {
            // do not log transfers
            Ok(_) => None,
            Err(DefuseError::InvariantViolated(v)) => Some(v),
            Err(err) => err.panic(),
        };

        SimulationOutput {
            report: inspector.into_report(),
            invariant_violated,
            state: StateOutput {
                fee: self.fee(),
                current_salt: self.salts.current(),
            },
        }
    }

    fn auth_call(&mut self, signer_id: &AccountIdRef, auth_call: AuthCall) -> Result<()> {
        if auth_call.attached_deposit.is_zero() {
            Self::do_auth_call(signer_id.to_owned(), auth_call)
        } else {
            // withdraw from signer's wNEAR balance
            self.withdraw(
                signer_id,
                [(
                    Nep141TokenId::new(self.wnear_id().into_owned()).into(),
                    auth_call.attached_deposit.as_yoctonear(),
                )],
                Some("withdraw"),
                false,
            )?;

            ext_wnear::ext(self.wnear_id.clone())
                .with_attached_deposit(NearToken::from_yoctonear(1))
                .with_static_gas(NEAR_WITHDRAW_GAS)
                // do not distribute remaining gas here
                .with_unused_gas_weight(0)
                .near_withdraw(U128(auth_call.attached_deposit.as_yoctonear()))
                .then(
                    // do_auth_call only after unwrapping NEAR
                    Self::ext(env::current_account_id())
                        .with_static_gas(
                            Self::auth_call_callback_gas(&auth_call)
                                .ok_or(DefuseError::GasOverflow)?,
                        )
                        .do_auth_call(signer_id.to_owned(), auth_call),
                )
        }
        .detach();

        Ok(())
    }

    #[private]
    pub fn do_auth_call(signer_id: AccountId, auth_call: AuthCall) -> Promise {
        if !auth_call.attached_deposit.is_zero() {
            require!(
                promise_result_checked_void(0).is_ok(),
                "near_withdraw failed",
            );
        }

        let min_gas = auth_call.min_gas();
        let mut p = Promise::new(auth_call.contract_id);

        if let Some(state_init) = auth_call.state_init {
            p = p.state_init(state_init, NearToken::ZERO);
        }

        ext_auth_callee::ext_on(p)
            .with_attached_deposit(auth_call.attached_deposit)
            .with_static_gas(min_gas)
            .on_auth(signer_id, auth_call.msg)
    }

    pub fn execute_signed_intents(
        mut self,
        signed: impl IntoIterator<Item = MultiPayload>,
    ) -> Result<Transfers> {
        for signed in signed {
            self.execute_signed_intent(signed)?;
        }
        self.finalize()
    }

    fn execute_signed_intent(&mut self, signed: MultiPayload) -> Result<()> {
        // verify signed payload and get public key
        let public_key = signed.verify().ok_or(DefuseError::InvalidSignature)?;

        // calculate intent hash
        let hash = signed.hash();

        // extract NEP-413 payload
        let DefusePayload::<DefuseIntents> {
            signer_id,
            verifying_contract,
            deadline,
            nonce,
            message: intents,
        } = signed.extract_defuse_payload()?;

        // check recipient
        if verifying_contract != *self.state.verifying_contract() {
            return Err(DefuseError::WrongVerifyingContract);
        }

        self.inspector.on_deadline(deadline);

        // make sure message is still valid
        if deadline < Timestamp::now() {
            return Err(DefuseError::DeadlineExpired);
        }

        // make sure the account has this public key
        if !self.state.has_public_key(&signer_id, &public_key) {
            return Err(DefuseError::PublicKeyNotExist(signer_id, public_key));
        }

        // commit nonce
        self.verify_intent_nonce(nonce, deadline)?;
        self.state.commit_nonce(signer_id.clone(), nonce)?;

        intents.execute_intent(&signer_id, self, hash)?;
        self.inspector.on_intent_executed(&signer_id, hash, nonce);

        Ok(())
    }

    #[inline]
    fn verify_intent_nonce(&self, nonce: Nonce, intent_deadline: Timestamp) -> Result<()> {
        let Some(nonce) = VersionedNonce::maybe_from(nonce) else {
            return Ok(());
        };

        match nonce {
            VersionedNonce::V1(SaltedNonce {
                salt,
                nonce: ExpirableNonce { deadline, .. },
            }) => {
                if !self.state.is_valid_salt(salt) {
                    return Err(DefuseError::InvalidSalt);
                }

                if intent_deadline > deadline {
                    return Err(DefuseError::DeadlineGreaterThanNonce);
                }

                if deadline < Timestamp::now() {
                    return Err(DefuseError::NonceExpired);
                }
            }
        }

        Ok(())
    }

    #[inline]
    fn finalize(self) -> Result<Transfers> {
        self.state
            .finalize()
            .map_err(DefuseError::InvariantViolated)
    }
