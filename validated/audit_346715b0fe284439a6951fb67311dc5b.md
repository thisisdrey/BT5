### Title
Cross-Origin WebSocket Handshake Bypasses `http.CrossOriginProtection` Because GET Is Unconditionally Treated as a "Safe Method" - ([File: src/net/http/csrf.go])

### Summary
`http.CrossOriginProtection.Check` in `src/net/http/csrf.go` immediately allows any request whose method is `GET`, `HEAD`, or `OPTIONS`, before ever inspecting `Sec-Fetch-Site` or `Origin`. A WebSocket handshake is initiated by the browser as an ordinary cross-origin `GET` request with an `Upgrade: websocket` header, so it is classified as "safe" and passes through unconditionally, even though establishing a WebSocket connection is a stateful, side-effect-bearing action equivalent to what the CSRF protection is meant to stop. This mirrors the primitive in CVE-2019-13727: a browser-navigable, crafted HTML page can drive a WebSocket connection that evades the server's same-origin enforcement.

### Finding Description
Attacker input: a victim visits an attacker-controlled HTML page that opens `new WebSocket("wss://victim.example/ws")`. The browser sends a cross-origin `GET` handshake request carrying `Origin: https://attacker.example` and (on modern browsers) `Sec-Fetch-Site: cross-site`.

Go entry point: `CrossOriginProtection.Handler` (`src/net/http/csrf.go:206-218`) wraps the application's WebSocket-upgrade handler and calls `Check`.

Failed check: in `Check` (`src/net/http/csrf.go:134-175`), the very first branch is:
```go
switch req.Method {
case "GET", "HEAD", "OPTIONS":
    return nil // Safe methods are always allowed.
}
```
Because the handshake method is `GET`, execution returns `nil` immediately — the subsequent `Sec-Fetch-Site` switch and the `Origin`/`Host` comparison (lines 141-174) are never reached, regardless of how obviously cross-site the request is.

Sink: the wrapped handler proceeds to complete the WebSocket upgrade (`w.ServeHTTP`/`Hijack`) for the cross-origin caller, establishing a persistent, bidirectional, cookie-authenticated channel to the origin server exactly as the classic WebSocket same-origin-bypass class describes.

### Impact Explanation
Any Go server that relies on `http.CrossOriginProtection` to gate a WebSocket endpoint (a natural use, since the package's doc explicitly targets "non-safe cross-origin browser requests") gets no protection at all for that endpoint, because WebSocket upgrades are always sent as `GET`. An attacker page can open an authenticated (cookie-carrying) WebSocket session to the victim's origin, then send/receive data over it — a session-riding/CSRF-equivalent bypass with confidentiality and integrity impact once the underlying protocol carries sensitive per-user data. This is a PUBLIC-track class of report (well-known, standard-library documented mitigation, not exploit code) but represents a genuine same-origin/CSRF-protection gap in `net/http`, directly analogous to the WebSocket same-origin bypass in CVE-2019-13727.

### Likelihood Explanation
Victim workflow: normal browsing to an attacker page while authenticated to the target site — no privileges beyond an ordinary victim clicking a link. Attacker capability: only needs to serve HTML/JS; no control of the target server or network path is required. `Sec-Fetch-Site`/`Origin` are attacker-controlled/browser-set but the method-based short-circuit makes them irrelevant for WebSocket handshakes.

### Recommendation
In `CrossOriginProtection.Check`, do not treat `GET` (and ideally `HEAD`/`OPTIONS` combined with an `Upgrade` header) as unconditionally safe when the request is a protocol-upgrade request (i.e., `Connection: Upgrade` / `Upgrade: websocket` present). Route such requests through the same `Sec-Fetch-Site`/`Origin` validation applied to non-safe methods, or document explicitly that `CrossOriginProtection` does not protect WebSocket/upgrade endpoints and that callers must implement their own `Origin` check (as `Upgrader.CheckOrigin` does in third-party libraries).

### Proof of Concept
```go
package http_test

import (
	"net/http"
	"net/http/httptest"
	"testing"
)

// TestCrossOriginProtectionWebSocketBypass demonstrates that a cross-origin
// WebSocket handshake (a GET request) is never checked against Origin /
// Sec-Fetch-Site by http.CrossOriginProtection, unlike a POST request.
func TestCrossOriginProtectionWebSocketBypass(t *testing.T) {
	protection := http.NewCrossOriginProtection()
	handler := protection.Handler(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		// Stand-in for a WebSocket upgrade handler.
		w.WriteHeader(http.StatusSwitchingProtocols)
	}))

	req := httptest.NewRequest("GET", "https://victim.example/ws", nil)
	req.Header.Set("Connection", "Upgrade")
	req.Header.Set("Upgrade", "websocket")
	req.Header.Set("Origin", "https://attacker.example")
	req.Header.Set("Sec-Fetch-Site", "cross-site")

	w := httptest.NewRecorder()
	handler.ServeHTTP(w, req)

	// Expected (secure) behavior: 403 Forbidden, same as a cross-site POST
	// would receive. Actual behavior: 101, because GET is always allowed.
	if w.Code != http.StatusForbidden {
		t.Errorf("cross-origin WebSocket handshake was not blocked: got status %d, want %d", w.Code, http.StatusForbidden)
	}
}

// Check applies cross-origin checks to a request.
// It returns an error if the request should be rejected.
func (c *CrossOriginProtection) Check(req *Request) error {
	switch req.Method {
	case "GET", "HEAD", "OPTIONS":
		// Safe methods are always allowed.
		return nil
	}

	switch req.Header.Get("Sec-Fetch-Site") {
	case "":
		// No Sec-Fetch-Site header is present.
		// Fallthrough to check the Origin header.
	case "same-origin", "none":
		return nil
	default:
		if c.isRequestExempt(req) {
			return nil
		}
		return errCrossOriginRequest
	}

	origin := req.Header.Get("Origin")
	if origin == "" {
		// Neither Sec-Fetch-Site nor Origin headers are present.
		// Either the request is same-origin or not a browser request.
		return nil
	}

func (c *CrossOriginProtection) Handler(h Handler) Handler {
	return HandlerFunc(func(w ResponseWriter, r *Request) {
		if err := c.Check(r); err != nil {
			if deny := c.deny.Load(); deny != nil {
				(*deny).ServeHTTP(w, r)
				return
			}
			Error(w, err.Error(), StatusForbidden)
			return
		}
		h.ServeHTTP(w, r)
	})
}
