### Title
Any user can disable cross-chain synthetic-token transfers by reducing the ProxyOFT payload limit - ([File: contracts/dependencies/@layerzerolabs/solidity-examples/contracts-upgradeable/lzApp/LzAppUpgradeable.sol](contracts/dependencies/@layerzerolabs/solidity-examples/contracts-upgradeable/lzApp/LzAppUpgradeable.sol))

### Summary

`ProxyOFT` inherits LayerZero’s `LzAppUpgradeable` through `ComposableOFTCoreUpgradeable`, exposing `setPayloadSizeLimit(uint16,uint256)` as a public function. The function writes the destination-specific `payloadSizeLimitLookup` but lacks the `onlyOwner` restriction applied to the adjacent LayerZero configuration functions. Because `ProxyOFT.owner()` resolves to the `PoolRegistry` governor, the missing modifier creates a direct authorization bypass.

### Finding Description

`ProxyOFT` is deployed as the cross-chain adapter for `SyntheticToken` and exposes outbound transfers through `sendFrom`. [1](#0-0) [2](#0-1) 

Within the inherited LayerZero implementation, all neighboring administrative messaging configuration functions require `onlyOwner`, including `setTrustedRemote`, `setTrustedRemoteAddress`, `setPrecrime`, and `setMinDstGas`. `setPayloadSizeLimit`, however, performs the storage write without an authorization check. [3](#0-2) 

An attacker can call the function through the deployed `ProxyOFT` contract and set a supported destination chain’s payload limit below the encoded OFT transfer payload size. Subsequent calls to `sendFrom` construct a standard OFT payload and enter the inherited LayerZero send path, where the configured payload-size check rejects the transfer. The destination-chain and bridging checks in `_debitFrom` do not compensate for the missing owner check. [4](#0-3) 

### Impact Explanation

This breaks the bridge’s liveness invariant for a supported destination chain. One unprivileged transaction can prevent every user from sending that synthetic asset to the selected chain. Governance can restore the limit, but the attacker can repeatedly lower it again, maintaining a temporary freeze of the affected users’ ability to bridge their synthetic-token balances.

The issue is analogous to a missing privileged check on a globally shared configuration value: one unauthenticated write changes the protocol state consumed by every subsequent user of the same cross-chain route.

### Likelihood Explanation

The attack requires only an EOA and one external call; no governor, keeper, malicious LayerZero endpoint, forged remote peer, oracle manipulation, or prior token balance is required. `ProxyOFT` deliberately defines `owner()` as the registry governor, demonstrating that the inherited configuration surface is intended to be privileged. [5](#0-4) 

The vulnerability is reachable on every `ProxyOFT` instance inheriting this implementation. Limiting the payload to `1` byte is sufficient because a normal OFT packet necessarily exceeds that size.

### Recommendation

Add `onlyOwner` to `setPayloadSizeLimit` in `LzAppUpgradeable`, or explicitly override it in `ProxyOFT` with an equivalent governor-only check:

```solidity
function setPayloadSizeLimit(uint16 _dstChainId, uint256 _size) external onlyOwner {
    payloadSizeLimitLookup[_dstChainId] = _size;
}
```

The production deployment should also be reviewed for other externally inherited configuration functions that rely on `onlyOwner` but may have had the modifier removed.

### Proof of Concept

The following Foundry-style test demonstrates the authorization bypass against a configured `ProxyOFT` instance:

```solidity
function test_anyoneCanDisableOftRoute() public {
    address attacker = makeAddr("attacker");
    address victim = makeAddr("victim");
    uint16 dstChainId = configuredDstChainId;
    uint256 amount = 1 ether;

    deal(address(syntheticToken), victim, amount);

    // Unprivileged caller changes the global route configuration.
    vm.prank(attacker);
    proxyOFT.setPayloadSizeLimit(dstChainId, 1);

    uint256 fee = proxyOFT.estimateSendFee(dstChainId, victim, amount);
    vm.deal(victim, fee);

    // Every normal transfer packet is now larger than the attacker-set limit.
    vm.prank(victim);
    vm.expectRevert("LzApp: payload size is too large");
    proxyOFT.sendFrom{value: fee}(victim, dstChainId, victim, amount);

    // The attempted send fully reverts and the victim retains the tokens.
    assertEq(syntheticToken.balanceOf(victim), amount);
}
```
