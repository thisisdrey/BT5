This confirms the vulnerability: the `endpoint` config for the signer's event receiver defaults to `0.0.0.0:30000` in the sample configs [1](#0-0) , meaning the socket is not restricted to localhost and is remotely reachable. The `/shutdown` branch in `next_event` performs no signature, auth-token, or IP check whatsoever before setting `stop_signal` and returning `Err(EventError::Terminated)` [2](#0-1) , which then causes `main_loop` to break out of its loop on the very next check [3](#0-2) . The `auth_token`/`auth_password` mechanism referenced in configs is used only for the node's block-proposal RPC endpoint (validated in `stackslib`), not for this event-receiver HTTP server; `next_event`'s dispatch only checks `request.url()` and `request.method()`, with no header/token check at all [4](#0-3) . The existing `SignerStopSignaler::send` is just a normal unauthenticated client that connects and sends this exact request [5](#0-4) , and there is nothing distinguishing it from a request forged by anyone with network access to the port — the test `test_status_endpoint` demonstrates that arbitrary raw HTTP requests are accepted by any `TcpStream` connecting to the bound port [6](#0-5) .

### Title
Unauthenticated remote DoS via `/shutdown` endpoint in `SignerEventReceiver::next_event` - (File: libsigner/src/events.rs)

### Summary
The signer's event-receiver HTTP server exposes a `/shutdown` endpoint that terminates the receiver's `main_loop` with zero authentication, IP restriction, or secret check. Any TCP client that can reach the bound port (which is commonly configured as `0.0.0.0:30000`, i.e., all interfaces) can send a single crafted `POST /shutdown` request and permanently kill the signer's event ingestion path.

### Finding Description
The claimed equality — "party allowed to stop the event receiver == party who holds the node's dispatch trust" — is broken. `next_event` dispatches purely on `request.url()` and `request.method()` with no verification of sender identity, no comparison against a shared secret/auth token, and no check that the request originated from the node's loopback/trusted address [4](#0-3) . When `request.url() == "/shutdown"`, the code unconditionally sets `stop_signal` to `true` and returns `EventError::Terminated` [2](#0-1) . `main_loop` treats `EventError::Terminated` as a clean exit signal and breaks immediately [3](#0-2) , after which `is_stopped()` returns `true` permanently since `stop_signal` is never reset. The legitimate caller, `SignerStopSignaler::send`, constructs exactly `POST /shutdown HTTP/1.1\r\nHost: {addr}\r\nConnection: close\r\nContent-Length: {len}\r\nContent-Type: text/plain\r\n\r\n{body}` and sends it over a plain `TcpStream::connect` [7](#0-6)  — there is no cryptographic binding (signature, HMAC, token) between this data and the caller's identity, so any third party can replay the identical bytes. The `auth_token`/`auth_password` pair configured in signer/node configs governs the *node's block-proposal RPC*, not the *signer's event-receiver server that binds `endpoint`* [1](#0-0) ; this port carries no such gate.

### Impact Explanation
Any attacker with network reachability to the signer's `endpoint` bind address (commonly `0.0.0.0:<port>` per shipped sample configs) can send a single unauthenticated HTTP request to permanently stop the signer's event ingestion thread, causing it to stop receiving `stackerdb_chunks`, `proposal_response`, `new_burn_block`, and `new_block` events from the node. This is a remote, unauthenticated, single-message DoS against a component central to Nakamoto consensus signing (the signer will effectively go dark for block validation/signing purposes), matching the Critical "remote crash/unauthenticated DoS from few messages" category. It is trivially repeatable against every signer whose port is reachable.

### Likelihood Explanation
No preconditions beyond TCP reachability to the bound signer event port are required — no key, no StackerDB slot, no node RPC secret. The attack is a single crafted TCP write of a well-known, fixed byte sequence, achievable from any unprivileged remote host if the port is exposed (which is the documented/sample default binding of `0.0.0.0`).

### Recommendation
Restrict the `/shutdown` (and ideally the whole event-receiver server) to only accept connections from a trusted source: bind to `127.0.0.1`/loopback by default and document that non-loopback binding requires a reverse proxy with authentication, and/or require the stop-signal request to include a locally-generated secret/token (e.g., generated at `bind()` time and known only to the in-process `SignerStopSignaler`) that is checked in `next_event` before honoring `/shutdown`.

                    request.method(),
                )));

                process_event::<T, StackerDBChunksEvent>(request)
