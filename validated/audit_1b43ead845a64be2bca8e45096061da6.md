Based on my research, I found a strong analog in Bazel's own ZIP/JAR parsing code that mirrors the exact bug class of the ESP-IDF AVRCP OOB read: a vendor/attacker-controlled length field is trusted and used to advance a read pointer and dereference multi-byte fields without validating that the declared length stays inside the actual buffer.

### Title
Heap Out-of-Bounds Read in ijar's Central Directory Extra-Field Parser - (File: `third_party/ijar/zip.cc`)

### Summary
`InputZipFile::ProcessCentralDirEntry()` in [1](#0-0)  parses each Central Directory Header (CDH) of a ZIP/JAR file supplied to Bazel's `ijar` tool (used to build interface jars from any `.jar` input, including jars fetched from external Maven repositories/mirrors or checked into an untrusted branch). Unlike `ProcessLocalFileEntry()` in the very same file, which explicitly guards every field read with `EnsureRemaining()` before touching memory ( [2](#0-1) ), `ProcessCentralDirEntry()` performs no such check at all.

### Finding Description
After reading `file_name_length`, `extra_field_length`, and `file_comment_length` directly from the (attacker-controlled) CDH bytes, the function walks the "extra fields" region with:
```
const u1 *extra_p = p;
p += extra_field_length;
while (extra_p != p) {
  const u2 header_id = get_u2le(extra_p);
  const u2 data_size = get_u2le(extra_p);
  const u1 *extra = extra_p;
  extra_p += data_size;
  if (header_id == ZIP64_EXTRA_FIELD_TAG) {
    ...
    *uncompressed_size = get_u8le(extra);
    ...
``` [3](#0-2) 

None of `get_u4le`, `get_u2le(extra_p)` x2, or `get_u8le(extra)` are preceded by any check that `extra_p`/`extra` plus the number of bytes about to be read stays within the mapped input buffer, nor is `extra_field_length` itself checked against the number of bytes actually remaining in the central directory (there is no analogous `EnsureRemaining()` call anywhere in `ProcessCentralDirEntry`, contrasted with its sibling function). A crafted CDH with a `data_size`/`extra_field_length` value that is inconsistent with the true remaining buffer size causes `extra_p` to walk past the end of the mapped ZIP data, and the subsequent `get_u2le`/`get_u8le` calls dereference memory beyond the input buffer — a heap out-of-bounds read, structurally identical to the AVRCP vendor-command parser's failure to validate an attacker-supplied length field against the actual payload before reading.

Bazel's own `singlejar` tool (a separate, hardened C++ zip implementation used for producing deploy jars) demonstrates the correct pattern that `ijar` is missing: `ExtraField::find()` in [4](#0-3)  explicitly checks `byte_ptr(start) + sizeof(ExtraField) > byte_ptr(end)` and `byte_ptr(start) + extra_field->size() > byte_ptr(end)` before ever dereferencing the extra-field header — a check entirely absent from `ijar/zip.cc`'s central-directory extra-field loop.

### Impact Explanation
`ijar` runs as part of normal Bazel Java build actions to generate ABI/interface jars from arbitrary `.jar` inputs, including third-party jars resolved from Maven repositories, `http_jar`/`http_archive` downloads, or jars committed on an untrusted CI branch. A hostile origin server or a malicious contributor supplying a crafted jar can trigger heap OOB reads in the `ijar` process during a routine build, potentially crashing the build worker or leaking adjacent heap memory content into build outputs/parsed fields (e.g., corrupted size/offset values propagated from `get_u8le`).

### Likelihood Explanation
The attacker only needs to control the bytes of a `.jar`/`.zip` file that Bazel processes with `ijar` — no local machine access, credentials, or MITM capability is required. `ijar` performs no checksum verification of its own before parsing (it isn't part of the fetch/integrity-checked path — verification, if any, happens earlier on the raw archive bytes, not on the internal consistency of the ZIP structure itself), so a file that passes a `sha256` check on its outer bytes can still contain an internally malformed Central Directory that triggers this bug.

### Recommendation
Add the same remaining-bytes bounds validation used in `ProcessLocalFileEntry`/`EnsureRemaining()` (and mirrored correctly in `singlejar`'s `ExtraField::find()`) to `ProcessCentralDirEntry`'s extra-field walking loop: validate `extra_field_length` against the actual remaining central-directory bytes before entering the loop, and validate each `data_size` against the remaining extra-field bytes before advancing `extra_p` or calling `get_u2le`/`get_u8le`.

### Proof of Concept
Construct a minimal ZIP/JAR whose single Central Directory Header declares `extra_field_length` larger than the number of bytes actually present before the End Of Central Directory record (or whose embedded extra-field `data_size` is set to an oversized value, e.g. `0xFFFF`, similar to the existing `CreateZipWithMalformedExtraField()` test helper pattern already used for `singlejar` in [5](#0-4) , but fed to `ijar`'s `zip.cc` reader instead). Feed this file to the `ijar` binary; under ASan, `get_u2le`/`get_u8le` inside `ProcessCentralDirEntry` will read past the mapped input buffer, demonstrating the heap-buffer-overflow (read).

bool InputZipFile::ProcessCentralDirEntry(const u1 *&p, u8 *compressed_size,
                                          u8 *uncompressed_size, char *filename,
                                          size_t filename_size, u4 *attr,
                                          u8 *offset) {
  u4 signature = get_u4le(p);

  if (signature != CENTRAL_FILE_HEADER_SIGNATURE) {
    if (signature != DIGITAL_SIGNATURE && signature != EOCD_SIGNATURE &&
        signature != ZIP64_EOCD_SIGNATURE) {
      error("invalid central file header signature: 0x%x\n", signature);
    }
    return false;
  }

  p += 16;  // skip to 'compressed size' field
  *compressed_size = get_u4le(p);
  *uncompressed_size = get_u4le(p);
  u2 file_name_length = get_u2le(p);
  u2 extra_field_length = get_u2le(p);
  u2 file_comment_length = get_u2le(p);
  p += 4;  // skip to external file attributes field
  *attr = get_u4le(p);
  *offset = get_u4le(p);
  {
    size_t len = (file_name_length < filename_size)
      ? file_name_length
      : (filename_size - 1);
    memcpy(reinterpret_cast<void*>(filename), p, len);
    filename[len] = 0;
  }
  p += file_name_length;
  const u1 *extra_p = p;
  p += extra_field_length;
  while (extra_p != p) {
    const u2 header_id = get_u2le(extra_p);
    const u2 data_size = get_u2le(extra_p);
    const u1 *extra = extra_p;
    extra_p += data_size;
    if (header_id == ZIP64_EXTRA_FIELD_TAG) {
      if (*uncompressed_size == U4_MAX) {
        *uncompressed_size = get_u8le(extra);
      }
      if (*compressed_size == U4_MAX) {
        *compressed_size = get_u8le(extra);
      }
      if (*offset == U4_MAX) {
        *offset = get_u8le(extra);
      }
    }
  }
  p += file_comment_length;
  return true;
}

std::string CreateZipWithMalformedExtraField() {
  std::string zip_data;
  const std::string filename = "evil.bin";

  // 1. Local File Header (LFH)
  size_t lh_offset = zip_data.size();
  size_t lh_size = sizeof(LH) + filename.size();
  zip_data.resize(lh_offset + lh_size, 0);
  auto* lh = reinterpret_cast<LH*>(&zip_data[lh_offset]);
  lh->signature();
  lh->version(10);
  lh->file_name(filename.data(), filename.size());

  // 2. Extra field payload containing an oversized payload_size
  uint8_t ef_buffer[8] = {0};
  auto* ef1 = reinterpret_cast<ExtraField*>(ef_buffer);
  ef1->signature(0x000d);
  ef1->payload_size(0);

  auto* ef2 = reinterpret_cast<ExtraField*>(ef_buffer + ef1->size());
  ef2->signature(0xdead);
  ef2->payload_size(0xf000);  // Malformed size exceeding extra field buffer

  // 3. Central Directory Header (CDH)
  size_t cdh_offset = zip_data.size();
  size_t cdh_size = sizeof(CDH) + filename.size() + sizeof(ef_buffer);
  zip_data.resize(cdh_offset + cdh_size, 0);
  auto* cdh = reinterpret_cast<CDH*>(&zip_data[cdh_offset]);
  cdh->signature();
  cdh->version(20);
  cdh->version_to_extract(10);
  cdh->local_header_offset32(lh_offset);
  cdh->file_name(filename.data(), filename.size());
  cdh->extra_fields(ef_buffer, sizeof(ef_buffer));

  // 4. End of Central Directory (EOCD)
  size_t ecd_offset = zip_data.size();
  zip_data.resize(ecd_offset + sizeof(ECD), 0);
  auto* ecd = reinterpret_cast<ECD*>(&zip_data[ecd_offset]);
  ecd->signature();
  ecd->this_disk_entries16(1);
  ecd->total_entries16(1);
  ecd->cen_size32(cdh_size);
  ecd->cen_offset32(cdh_offset);

  return zip_data;
