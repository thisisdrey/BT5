#No Vulnerability found for this question.

**Analysis supporting this conclusion:**

The claimed binding `TokenId::Nep245(Nep245TokenId::new(X,"nep141:victim-ft.near")) == TokenId::Nep141(Nep141TokenId::new("victim-ft.near"))` is false and demonstrably never holds.

`Nep245TokenId`'s `Display`/`Debug` impl formats as `"{contract_id}:{mt_token_id}"` [1](#0-0)  , and the outer `TokenId` enum prefixes this with the variant discriminant (`"nep141:"`, `"nep245:"`, etc.) via `write!(f, "{}:{}", TokenIdType::Nep245, token_id)` [2](#0-1) . So the attacker's crafted deposit produces the string `"nep245:X:nep141:victim-ft.near"`, while the real victim balance is keyed as `"nep141:victim-ft.near"` — these are different strings with different prefixes, not a collision.

`TokenId::from_str` splits only on the *first* `:` to determine the type discriminant (`Nep141`, `Nep171`, `Nep245`, `Imt`) [3](#0-2) , so `"nep245:X:nep141:victim-ft.near"` always parses back into `TokenId::Nep245(Nep245TokenId { contract_id: X, mt_token_id: "nep141:victim-ft.near" })`, never into `TokenId::Nep141(...)`. The two `TokenId` enum variants are distinct discriminants (`Nep141 = 0`, `Nep245 = 2`) [4](#0-3) , so they hash/compare unequal and are stored under entirely separate balance-map keys.

Tracing `mt_on_transfer`, the attacker-controlled predecessor `token` (=X) is embedded as `contract_id` in `Nep245TokenId::new(token.clone(), token_id)` [5](#0-4) , and this is a known, intentionally-tested behavior — the test suite explicitly notes "Deposit a fictitious token, nep245:user.test.near:<token-id>, into defuse. This is possible because `mt_on_transfer` creates a token from any contract" [6](#0-5) , and confirms the fictitious balance stays isolated under its own `Nep245` key, never merging with the real `Nep141` ledger entry [7](#0-6) .

Since the two `TokenId` values are provably distinct both as strings and as parsed enum values, the worthless self-minted "wrapped" balance can never masquerade as or merge into the real `victim-ft.near` NEP-141 balance. No collision, no unauthorized credit to the real asset's ledger entry.

impl FromStr for TokenId {
    type Err = TokenIdError;

    #[inline]
    fn from_str(s: &str) -> Result<Self, Self::Err> {
        let (typ, data) = s
            .split_once(':')
            .ok_or(strum::ParseError::VariantNotFound)?;
        match typ.parse()? {
            TokenIdType::Nep141 => data.parse().map(Self::Nep141),
            TokenIdType::Nep171 => data.parse().map(Self::Nep171),
            TokenIdType::Nep245 => data.parse().map(Self::Nep245),
            TokenIdType::Imt => data.parse().map(Self::Imt),
        }
    }
}
