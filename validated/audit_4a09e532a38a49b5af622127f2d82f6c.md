### Title
Zero-gas contract-loading DoS via `MethodNotFound`/empty-method `FunctionCall` on stable protocol (pre-`FixContractLoadingCost`) - ([File: runtime/near-vm-runner/src/wasmtime_runner/mod.rs])

### Summary
On the current stable protocol (`fix_contract_loading_cost = false`, activation deferred to nightly-only PV 129), a `FunctionCall` receipt whose method name is empty or does not resolve on the deployed contract charges **zero gas** for the contract-loading step (deserialize + link + `instantiate_pre` of the compiled wasmtime module), even though that CPU work was fully performed. This lets an unprivileged attacker deploy large (up to `max_contract_size` = 4 MiB) wasm contracts and trigger real, non-trivial module-loading work for near-zero gas, repeatable across many receipts/accounts.

### Finding Description
`WasmtimeVM::with_compiled_and_loaded` (`runtime/near-vm-runner/src/wasmtime_runner/mod.rs:686-834`) performs cache lookup, `Module::deserialize`, `link`, and `instantiate_pre` (lines 704-810) *before* any loading-fee accounting happens. Only afterward does it call:
- `gas_counter.before_loading_executable` (`gas_counter.rs:235-255`) — rejects an empty method name immediately, *without* charging any fee.
- `gas_counter.after_loading_executable` (`gas_counter.rs:258-272`) — charges `add_contract_loading_fee` (`contract_loading_base` + `contract_loading_bytes * len`) only when `fix_contract_loading_cost` is **false** (the legacy/stable path).

The `closure` passed into `with_compiled_and_loaded` (defined in `WasmtimeVM::prepare`, `mod.rs:891-939`) then resolves the requested export; if it is missing, it returns `PreparationResult::OutcomeAbortButNopInOldProtocol(MethodResolveError::MethodNotFound)` — carrying the `gas_counter` that *already has* the loading fee accumulated in it (line 821 fee charge happens before line 826 closure call).

`PreparedContract::run` maps that variant to `VMOutcome::abort_but_nop_outcome_in_old_protocol` (`runtime/near-vm-runner/src/logic/logic.rs:4743-4752`), which — because `config.fix_contract_loading_cost` is `false` on stable — calls `Self::nop_outcome(error)` instead of `Self::abort`. `nop_outcome` (`logic.rs:4723-4739`) discards the entire `ExecutionResultState`/`GasCounter` and hard-codes `burnt_gas: Gas::ZERO, used_gas: Gas::ZERO`. The empty-method-name path is even worse: `before_loading_executable` returns the resolve error *before* the fee is ever added to the counter, so the same zero-gas outcome results from an `OutcomeAbort` (via the ordinary `abort()` path, which just has nothing to sum).

This exact behavior is pinned by the repo's own test suite pre/post the (nightly-only) fix:
- `runtime/near-vm-runner/src/tests/runtime_errors.rs:114-131` (`test_infinite_initializer_export_not_found`) shows `burnt gas 0` for the pre-fix protocol version vs. `burnt gas 104071548` post-fix, for the identical `MethodNotFound` scenario.
- `runtime/near-vm-runner/src/tests/runtime_errors.rs:188-204` (`test_export_not_found`) shows the same `burnt gas 0` vs. non-zero split.
- `protocol-model/spec/contract-vm.md:92,106` documents this exact pre/post-fix ordering and explicitly calls out `FixContractLoadingCost` as nightly-only (PV 129), not active at stable `PROTOCOL_VERSION` 86.

Attacker path: an ordinary funded account submits `DeployContract(bytecode)` where `bytecode` is a valid, near-max-size (`max_contract_size` = 4 MiB per config) wasm module that compiles successfully but exports no method matching the attacker's chosen `method_name` (or a `FunctionCall` with `method_name = ""`). It then submits `FunctionCall(method_name=<nonexistent or empty>)`. Existing checks (signature, nonce, access key, `max_contract_size`, `DeployContract`/`FunctionCall` action fees) all pass normally — none of them account for the VM-side module-loading cost, which is a separate, purpose-built fee (`contract_loading_base`/`contract_loading_bytes`) that exists precisely to cover this cost (see `gas_counter.rs:216-227` comment) and is nulled out by the legacy nop-outcome path.

Note: contract *compilation* itself is charged (approximately) via `deploy_contract_base`/`deploy_contract_byte` at deploy time (`runtime/runtime/src/actions.rs:301-306` comment), and the compiled artifact is cached both on-disk and, after first load, in the in-memory `AnyCache`. So the "free" work per exploited receipt is specifically the *loading* step (deserialize of the cached compiled module + link + `instantiate_pre`) for that contract's first (and only, if the attacker never calls it again) invocation — not repeated re-compilation of the same contract. To scale the attack, the attacker must deploy N distinct max-size contracts (each its own `DeployContract` receipt, its own account/cache key) and issue one `FunctionCall` with a bad method name against each, so each incurs an uncharged full loading step exactly once.

### Impact Explanation
This is a gas-metering totality break: real CPU work (wasmtime module deserialize/link/instantiate for near-max-size modules) is performed by every validator/stateless-validation chunk-producer applying the receipt, while the sender pays (and the network measures) zero gas for it. Repeated at scale (many distinct max-size contracts × bad-method `FunctionCall`s packed into receipts) this inflates real per-chunk wall-clock compute cost without a matching gas/compute charge, degrading block-application throughput — a resource-exhaustion vector against chunk producers/validators, the closest matching category being availability/DoS (contributing toward shard-application slowdown) rather than direct fund theft.

### Likelihood Explanation
Fully reachable by an unprivileged funded account using only standard `DeployContract`+`FunctionCall` actions; no special permissions, validator access, or leaked keys required. It is deterministic and repeatable — confirmed as the actual pre-fix behavior by the codebase's own regression tests, and the fix (`FixContractLoadingCost`, `core/primitives-core/src/version.rs:607`) is gated behind nightly-only PV 129, meaning it is **not active** on stable `PROTOCOL_VERSION` 86 in this tree. Cost to the attacker is only the `DeployContract`/`FunctionCall` base+per-byte fees (a fraction of the true loading cost), making the attack economically favorable at scale.

### Recommendation
Backport/stabilize `FixContractLoadingCost` (or an equivalent fix) to the active mainnet protocol version so that: (1) the contract-loading fee is pre-charged in `before_loading_executable` before any deserialize/link/instantiate work happens (as already implemented for the nightly path), and (2) loading-phase resolution failures (`MethodNotFound`, `MethodEmptyName`) finalize via `VMOutcome::abort` (a real, gas-bearing outcome) rather than `nop_outcome`, so the already-accumulated loading fee is retained in `burnt_gas`/`used_gas` instead of being discarded by `abort_but_nop_outcome_in_old_protocol`.

    /// VM independent setup before loading the executable.
    ///
    /// Does VM independent checks that happen after the instantiation of
    /// VMLogic but before loading the executable. This includes pre-charging gas
    /// costs for loading the executable, which depends on the size of the WASM code.
    #[cfg(feature = "wasmtime_vm")]
    pub(crate) fn before_loading_executable(
        &mut self,
        config: &near_parameters::vm::Config,
        method_name: &str,
        wasm_code_bytes: u64,
    ) -> std::result::Result<(), super::errors::FunctionCallError> {
        if method_name.is_empty() {
            let error = super::errors::FunctionCallError::MethodResolveError(
                super::errors::MethodResolveError::MethodEmptyName,
            );
            return Err(error);
        }
        if config.fix_contract_loading_cost {
            if self.add_contract_loading_fee(wasm_code_bytes).is_err() {
                let error =
                    super::errors::FunctionCallError::HostError(super::HostError::GasExceeded);
                return Err(error);
            }
        }
        Ok(())
    }

    /// Legacy code to preserve old gas charging behaviour in old protocol versions.
    #[cfg(feature = "wasmtime_vm")]
    pub(crate) fn after_loading_executable(
        &mut self,
        config: &near_parameters::vm::Config,
        wasm_code_bytes: u64,
    ) -> std::result::Result<(), super::errors::FunctionCallError> {
        if !config.fix_contract_loading_cost {
            if self.add_contract_loading_fee(wasm_code_bytes).is_err() {
                return Err(super::errors::FunctionCallError::HostError(
                    super::HostError::GasExceeded,
                ));
            }
        }
        Ok(())
    }
