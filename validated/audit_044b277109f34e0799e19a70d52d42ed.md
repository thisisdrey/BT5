Confirmed: `GetNodeInfoServlet` is registered as an unauthenticated public HTTP endpoint (only rate-limited via `RateLimiterServlet`, no auth/session check), and it is mounted at `/wallet/getnodeinfo` (plus Solidity/PBFT variants) in `FullNodeHttpApiService.java`.### Title
Unauthenticated Node Version and Internal Topology Disclosure via `GetNodeInfoServlet` (`getnodeinfo` API) - (File: framework/src/main/java/org/tron/core/services/http/GetNodeInfoServlet.java)

### Summary
The HTTP endpoint served by `GetNodeInfoServlet` returns a full `NodeInfo` JSON object — including the exact running code version, DB schema version, JVM/OS build details, and the IP/port/node-ID of every connected peer — to any unauthenticated caller, with no access control beyond a generic QPS rate limiter.

### Finding Description
`GetNodeInfoServlet.doGet` calls `NodeInfoService.getNodeInfo()` and serializes the result directly to the response with no authentication or authorization check: [1](#0-0) 

`NodeInfoService.getNodeInfo()` populates the response with `Version.getVersion()` (exact deployed code version) and `Version.VERSION_CODE`, plus internal deployment details such as `dbVersion`, listen ports, discovery configuration, and — for every peer — its host/IP, port, hex-encoded `nodeId`, latency, sync state and disconnect reasons: [2](#0-1) 

It also exposes machine-level fingerprinting data (Java version, OS name/version, CPU/memory stats) via `setMachineInfo`: [3](#0-2) 

The servlet only extends `RateLimiterServlet`, which enforces QPS/global rate limiting but performs no authentication, session validation, or IP allow-listing — any request that passes the rate limiter is dispatched straight to `doGet`: [4](#0-3) 

The exact deployed version string (`Version.getVersion()` = `"4.8.2.2"`, `VERSION_NAME` = `"GreatVoyage-v4.8.2.1-1-gbd2450fe06"`) is hard-coded in `Version.java` and echoed verbatim by the endpoint: [5](#0-4) 

Additionally, `GetNodeInfoOnSolidityServlet` and the PBFT equivalent expose the identical data set on the Solidity/PBFT query-only nodes: [6](#0-5) 

This is directly analogous to the `git.json.php` bug class: an unauthenticated endpoint that discloses the exact deployed software version (enabling attackers to cross-reference java-tron's public GHSA history to pick unpatched CVEs against the specific node) plus internal network/infrastructure details (peer IPs/ports/node IDs) that go beyond what a git-log leak would even reveal.

### Impact Explanation
Any anonymous network client can fingerprint the exact java-tron build running on a node and cross-reference it against public CVEs/GHSAs to select working exploits, and can enumerate the node's active/passive peer list (IP, port, cryptographic node ID) to map network topology for follow-on targeted attacks (e.g., eclipse attacks, targeted DoS against specific peers, or reconnaissance for known peer-level vulnerabilities). This is an information-disclosure issue (CWE-200) reachable by any unprivileged HTTP client with zero authentication.

### Likelihood Explanation
Trivial and always reachable: `getnodeinfo` is a standard, documented public HTTP API endpoint on both FullNode and Solidity/PBFT nodes, requires no credentials, and only competes with an IP/QPS rate limiter, not an authorization gate. A single unauthenticated `GET` request suffices.

### Recommendation
Gate `GetNodeInfoServlet` (and its Solidity/PBFT variants) behind the same access controls already used for other sensitive endpoints (e.g., require it to be explicitly allow-listed via `HttpApiAccessFilter`/`node.http.disabledApi`, restrict it to loopback/admin networks by default, or strip sensitive fields — exact version string, `dbVersion`, and peer `nodeId`/host/port — from the response for unauthenticated callers).

### Proof of Concept
```bash
# Single unauthenticated request against a FullNode HTTP API
curl -s http://target-node:8090/wallet/getnodeinfo | python3 -m json.tool
```
Expected response includes fields populated by `setConfigNodeInfo`/`setConnectInfo` such as `configNodeInfo.codeVersion`, `configNodeInfo.versionNum`, `configNodeInfo.dbVersion`, and `peerList[].host`, `peerList[].port`, `peerList[].nodeId` — all served without any authentication token or session.
