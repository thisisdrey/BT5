Audit Report

## Title
Regulatory/compliance staking restriction (`Filter`/`Restricted`) is not enforced on the `pallet-delegated-staking::delegate_to_agent` path, allowing a restricted account to stake indirectly - (File: `substrate/frame/delegated-staking/src/lib.rs`)

## Summary
`pallet-staking-async::bond`/`bond_extra` and `pallet-nomination-pools::join` both explicitly check `T::Filter::contains(&who)` and reject with `Error::Restricted` before allowing a stash/member to bond funds. `pallet-delegated-staking::delegate_to_agent` performs no equivalent check on the `delegator` before calling `do_delegate`/`do_bond`, which ultimately invokes `T::CoreStaking::bond_extra`/`virtual_bond` — the internal `StakingInterface` methods that bypass the extrinsic-level `Filter` guard entirely.

## Finding Description
`pallet-staking-async::Pallet::bond`/`bond_extra` enforce `ensure!(!T::Filter::contains(&stash), Error::<T>::Restricted)` directly in the dispatchable body [1](#0-0) . `pallet-nomination-pools::join` re-implements the identical filter check before allowing a member to bond into a pool [2](#0-1) .

`pallet-delegated-staking::delegate_to_agent`, by contrast, only validates `Delegation::can_delegate` (checks the delegator isn't already delegating elsewhere or itself an agent) and that the target is a registered agent — it never references `T::Filter` or `Error::Restricted` in any form [3](#0-2) . It proceeds to `do_delegate` (holds funds, updates `AgentLedger`/`Delegation`) and `do_bond`, which calls `T::CoreStaking::bond_extra`/`T::CoreStaking::virtual_bond` directly on the `StakingInterface` trait — bypassing the `Call::bond`/`Call::bond_extra` extrinsic-level guard [4](#0-3) . A search of the pallet source confirms no `Filter` type or `Restricted` error is defined or referenced anywhere in `pallet-delegated-staking`'s non-test code, meaning there is structurally no enforcement point for this control inside this pallet.

The delegated-staking pallet's own doc comments confirm its design intent: it is meant to be usable by "external account, off-chain entity or xcm MultiLocation" as an alternate, composable staking primitive, explicitly separate from and complementary to `pallet-staking`/`pallet-nomination-pools` [5](#0-4) . The existing tests only validate that Filter/Restricted interactions are enforced between `pallet-staking` and `pallet-nomination-pools::join` (`existing_pool_member_cannot_stake`, `stakers_cannot_join_pool`), and do not cover `delegate_to_agent` at all, confirming the gap is untested and unenforced [6](#0-5) .

The `prdoc` for the feature (`pr_7685.prdoc`) explicitly lists `pallet-delegated-staking` as a crate bumped by the "Introduce filters to restrict accounts from staking" change, indicating awareness that this pallet is in scope for the restriction feature, yet no corresponding `Filter` check was actually added to its dispatchables.

## Impact Explanation
This is a runtime bug that compromises the intended behavior of a governance-configured compliance control (`T::Filter`). A runtime operator relying on `Filter` to block specific accounts (e.g., sanctioned addresses) from staking would have a false sense of security: a restricted account can still economically stake — earning rewards and contributing to an agent's total delegated/bonded stake in `CoreStaking` — merely by calling the public, unprivileged `delegate_to_agent` extrinsic instead of `Staking::bond`. This matches the "runtime bugs that compromise intended behavior" impact category in the gate.

## Likelihood Explanation
The exploit is fully reachable by an unprivileged external attacker: any restricted account can call the public `register_agent` (or use an existing agent) and then call the public `delegate_to_agent` extrinsic directly — no validator, governance, or off-chain privilege is required, and no existing guard blocks it. This is deterministic and repeatable on any runtime that both configures a non-trivial `T::Filter` on `pallet-staking-async`/`pallet-staking` and includes `pallet-delegated-staking` in the runtime (standalone or as the pools `DelegateStake` backend).

## Recommendation
Add a `Filter` associated type to `pallet-delegated-staking::Config` and enforce `ensure!(!T::Filter::contains(&delegator), Error::<T>::Restricted)` in `delegate_to_agent` (and any other delegator-funds-increasing entrypoint, e.g. `delegate_extra`/`do_bond_extra` paths) before `do_delegate`/`do_bond` execute. Alternatively, have `CoreStaking::virtual_bond`/`bond_extra` consult the filter against the ultimate economic staker (the delegator) rather than only the stash/agent key used for on-chain bonding.

## Proof of Concept
1. Governance adds `alice` to the compliance restriction list backing `T::Filter`.
2. `alice` calls `Staking::bond(signed(alice), 100, RewardDestination::Staked)` → fails with `Error::<T>::Restricted` (per `substrate/frame/staking-async/src/pallet/mod.rs` line 1859-equivalent check).
3. `bob` calls `DelegatedStaking::register_agent(signed(bob), bob_reward_account)` (unprivileged, permissionless).
4. `alice` calls `DelegatedStaking::delegate_to_agent(signed(alice), bob, 100)`.
5. Call succeeds: `Delegation::can_delegate` only checks non-agent/non-existing-delegator status; `do_delegate` holds `alice`'s funds; `do_bond` calls `T::CoreStaking::virtual_bond(&bob, 100, ...)`, bonding the funds under `bob`'s agent ledger — with no `Restricted` check anywhere in the path.
6. `alice`, despite being restricted, now holds an economically staked position via `bob`'s agent, demonstrating the bypass.

//!
//! This pallet implements [`sp_staking::DelegationInterface`] that provides delegation
//! functionality to `delegators` and `agents`. It is designed to be used in conjunction with
//! [`StakingInterface`] and relies on [`Config::CoreStaking`] to provide primitive staking
//! functions.
//!
//! Currently, it does not expose any dispatchable calls but is written with a vision to expose them
//! in the future such that it can be utilised by any external account, off-chain entity or xcm

//!
//! ## Key Terminologies
//! - **Agent**: An account who accepts delegations from other accounts and act as an agent on their
//!   behalf for staking these delegated funds. Also, sometimes referred as `Delegatee`.
//! - **Delegator**: An account who delegates their funds to an `agent` and authorises them to use
//!   it for staking.
//! - **AgentLedger**: A data structure that holds important information about the `agent` such as

//! primitive function: delegation of funds to an `agent` with the intent of staking. The agent can

		pub fn delegate_to_agent(
			origin: OriginFor<T>,
			agent: T::AccountId,
			amount: BalanceOf<T>,
		) -> DispatchResult {
			let delegator = ensure_signed(origin)?;

			// ensure delegator is sane.
			ensure!(
				Delegation::<T>::can_delegate(&delegator, &agent),
				Error::<T>::InvalidDelegation
			);

			// ensure agent is sane.
			ensure!(Self::is_agent(&agent), Error::<T>::NotAgent);

			// add to delegation.
			Self::do_delegate(Delegator::from(delegator), Agent::from(agent.clone()), amount)?;

			// bond the newly delegated amount to `CoreStaking`.
			Self::do_bond(Agent::from(agent), amount)
		}

	/// Bond `amount` to `agent_acc` in [`Config::CoreStaking`].
	fn do_bond(agent_acc: Agent<T::AccountId>, amount: BalanceOf<T>) -> DispatchResult {
		let agent_ledger = AgentLedgerOuter::<T>::get(&agent_acc.get())?;

		let available_to_bond = agent_ledger.available_to_bond();
		defensive_assert!(amount == available_to_bond, "not expected value to bond");

		if agent_ledger.is_bonded() {
			T::CoreStaking::bond_extra(&agent_ledger.key, amount)
		} else {
			T::CoreStaking::virtual_bond(&agent_ledger.key, amount, agent_ledger.reward_account())
		}
	}

	/// Delegate `amount` from `delegator` to `agent`.
	fn do_delegate(
		delegator: Delegator<T::AccountId>,
		agent: Agent<T::AccountId>,
		amount: BalanceOf<T>,
	) -> DispatchResult {
		// get inner type
		let agent = agent.get();
		let delegator = delegator.get();

		let mut ledger = AgentLedger::<T>::get(&agent).ok_or(Error::<T>::NotAgent)?;

		if let Some(mut existing_delegation) = Delegation::<T>::get(&delegator) {
			ensure!(existing_delegation.agent == agent, Error::<T>::InvalidDelegation);
			// update amount and return the updated delegation.
			existing_delegation.amount = existing_delegation
				.amount
				.checked_add(&amount)
				.ok_or(ArithmeticError::Overflow)?;
			existing_delegation
		} else {
			Delegation::<T>::new(&agent, amount)
		}
		.update(&delegator);

		// try to hold the funds.
		T::Currency::hold(&HoldReason::StakingDelegation.into(), &delegator, amount)?;

		ledger.total_delegated =
			ledger.total_delegated.checked_add(&amount).ok_or(ArithmeticError::Overflow)?;
		ledger.update(&agent);

		Self::deposit_event(Event::<T>::Delegated { agent, delegator, amount });

		Ok(())
	}

	#[test]
	fn existing_pool_member_cannot_stake() {
		// A pool member is able to stake directly since staking only uses free funds but once a
		// staker, they cannot join/add extra bond to the pool. They can still withdraw funds.
		ExtBuilder::default().build_and_execute(|| {
			start_era(1);
			// GIVEN: a pool.
			fund(&200, 1000);
			let pool_id = create_pool(200, 800);

			// WHEN: delegator joins a pool
			let delegator = 100;
			fund(&delegator, 1000);
			assert_ok!(Pools::join(RawOrigin::Signed(delegator).into(), 200, pool_id));

			// THEN: they cannot stake anymore
			assert_noop!(
				Staking::bond(
					RuntimeOrigin::signed(delegator),
					500,
					RewardDestination::Account(101)
				),
				StakingError::<T>::Restricted
			);
		});
	}
