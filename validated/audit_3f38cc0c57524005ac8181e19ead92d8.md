### Title
AddressRegistrar.register() permanently locks any deposit overpayment above the storage cost with no withdrawal path - (File: `runtime/near-wallet-contract/implementation/address-registrar/src/lib.rs`)

### Summary
The `AddressRegistrar` contract, part of the eth-implicit wallet contract tooling, exposes a `#[payable]` `register()` method that requires callers to attach a deposit covering the storage cost of a new `address -> account_id` mapping. When the mapping is created successfully, any deposit amount in excess of the computed `required_deposit` is silently retained by the contract, and the contract exposes no function to reclaim, withdraw, or rescue those excess (or any) tokens.

### Finding Description
`register()` computes `required_deposit` from the byte cost of storing the address/account_id entry and compares it against `given_deposit = env::attached_deposit()`: [1](#0-0) 

If `given_deposit < required_deposit` the call panics, but there is no corresponding upper-bound check. On the success path (`Entry::Vacant`), the entry is inserted and the function returns without transferring back any of the excess deposit: [2](#0-1) 

The only place the contract ever issues a refund is the collision branch (`Entry::Occupied`), where the *entire* deposit is returned because no storage was written: [3](#0-2) 

The full contract surface is `new`, `register`, `lookup`, and `get_address`; there is no owner, no admin/rescue method, and no other action path that can move NEAR out of the contract's balance: [4](#0-3) 

This is a direct structural analog of the reported bug class: a contract designed to accept token deposits from ordinary callers on the success path has no corresponding function to withdraw funds that are not otherwise accounted for by its own bookkeeping (here, any amount above the exact storage-byte cost).

### Impact Explanation
Any unprivileged caller who overestimates the required deposit (e.g., due to client-side estimation drift, a flat/rounded deposit convention, or simply attaching more NEAR than strictly necessary "to be safe") on a successful `register()` call has the excess permanently locked in the contract's balance. There is no method, owner-gated or otherwise, to move that balance back out. This is a permanent freezing of user funds, matching the required impact bar (funds become unrecoverable through any contract-level mechanism).

### Likelihood Explanation
The `register()` deposit check only enforces a lower bound (`given_deposit < required_deposit → panic`), so it is trivial and unprivileged for any caller (including normal wallet UIs that round up deposits) to overpay and trigger the freeze on every successful registration. No special permissions or preconditions are needed beyond calling a public, payable method with more NEAR attached than the exact computed storage cost.

### Recommendation
Add a check that refunds the difference (`given_deposit - required_deposit`) back to `env::predecessor_account_id()` on the successful (`Entry::Vacant`) path, mirroring the refund already performed on the collision path. Alternatively, require callers to attach exactly `required_deposit` and reject any excess, or add an explicit rescue/withdraw method restricted to a designated owner account for any accumulated balance not backed by storage accounting.

### Proof of Concept
1. Deploy `AddressRegistrar` and call `new()`.
2. Compute `required_deposit` for a given `account_id` (bytes_to_store = 20 + account_id length, multiplied by `storage_byte_cost`).
3. Call `register(account_id)` attaching a deposit strictly greater than `required_deposit` (e.g., `required_deposit + 1 NEAR`), where `account_id` has not been registered before (goes down the `Entry::Vacant` branch).
4. Observe: the call succeeds, the mapping is stored, and `Some(address)` is returned, but the contract's account balance increases by the *full* attached deposit rather than just `required_deposit` — the excess (`1 NEAR` in this example) is never transferred back.
5. There is no subsequent call (by the caller or any other account) that can retrieve this excess balance from the contract, since `register`, `lookup`, and `get_address` are the only methods and none move funds out except the collision-refund path in step-73-85, which does not apply here.

#[near_bindgen]
#[derive(PanicOnDefault, BorshDeserialize, BorshSerialize)]
#[borsh(crate = "near_sdk::borsh")]
pub struct AddressRegistrar {
    pub addresses: LookupMap<Address, AccountId>,
}

#[near_bindgen]
impl AddressRegistrar {
    #[init]
    pub fn new() -> Self {
        Self { addresses: LookupMap::new(StorageKey::Addresses) }
    }

    /// Computes the address associated with the given `account_id` and
    /// attempts to store the mapping `address -> account_id`. If there is
    /// a collision where the given `account_id` has the same address as a
    /// previously registered one then the mapping is NOT updated and `None`
    /// is returned. Otherwise, the mapping is stored and the address is
    /// returned as a hex-encoded string with `0x` prefix.
    #[payable]
    pub fn register(&mut self, account_id: AccountId) -> Option<String> {
        // It is not allowed to register eth-implicit accounts because the purpose
        // of the registry is to allow looking up the named account associated with
        // an address obtained via hashing, but eth-implicit accounts are already
        // parsable as addresses.
        if is_eth_implicit(&account_id) {
            let log_message = format!("Refuse to register eth-implicit account {account_id}");
            env::log_str(&log_message);
            return None;
        }

        // Must store the address and the account id
        let bytes_to_store = 20 + (account_id.len() as u128);
        let required_deposit =
            NearToken::from_yoctonear(env::storage_byte_cost().as_yoctonear() * bytes_to_store);
        let given_deposit = env::attached_deposit();
        // The caller must pay for the storage cost of registering.
        if given_deposit < required_deposit {
            let message = format!(
                "Insufficient deposit to cover storage cost. Given={} Expected={}",
                given_deposit.as_yoctonear(),
                required_deposit.as_yoctonear(),
            );
            env::panic_str(&message);
        }

        let address = account_id_to_address(&account_id);

        match self.addresses.entry(address) {
            Entry::Vacant(entry) => {
                let address = format!("0x{}", hex::encode(address));
                let log_message = format!("Added entry {} -> {}", address, account_id);
                entry.insert(account_id);
                env::log_str(&log_message);
                Some(address)
            }
            Entry::Occupied(entry) => {
                let log_message = format!(
                    "Address collision between {} and {}. Keeping the former.",
                    entry.get(),
                    account_id
                );
                env::log_str(&log_message);
                // Transfer the deposit back to the caller since no storage was updated.
                let refund_promise = env::promise_batch_create(&env::predecessor_account_id());
                env::promise_batch_action_transfer(refund_promise, given_deposit);
                None
            }
        }
    }

    /// Attempt to look up the account ID associated with the given address.
    /// If an entry for that address is found then the associated account id
    /// is returned, otherwise `None` is returned. Use the `register` method
    /// to add entries to the map.
    /// This function will panic if the given address is not the hex-encoding
    /// of a 20-byte array. The `0x` prefix is optional.
    pub fn lookup(&self, address: String) -> Option<AccountId> {
        let address = {
            let mut buf = [0u8; 20];
            hex::decode_to_slice(address.strip_prefix("0x").unwrap_or(&address), &mut buf)
                .unwrap_or_else(|_| env::panic_str("Invalid hex encoding"));
            buf
        };
        self.addresses.get(&address).cloned()
    }

    /// Computes the address associated with the given `account_id` and
    /// returns it as a hex-encoded string with `0x` prefix. This function
    /// does not update the mapping stored in this contract. If you want
    /// to register an account ID use the `register` method.
    pub fn get_address(&self, account_id: AccountId) -> String {
        let address = account_id_to_address(&account_id);
        format!("0x{}", hex::encode(address))
    }
}
