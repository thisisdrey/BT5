### Title
Unauthenticated remote write and remote shutdown of the signer's event-receiver HTTP endpoint - (File: libsigner/src/events.rs)

### Summary
The `stacks-signer` process runs its own inbound HTTP server (`SignerEventReceiver`) which the `stacks-node` is expected to POST events to (StackerDB chunks, block proposals, burn blocks, shutdown). Unlike every RPC endpoint in `stackslib/src/net/api/*` (`postblock_v3.rs`, `blockreplay.rs`, `blocksimulate.rs`, `fastcallreadonly.rs`, `txsimulate.rs`), which gate sensitive operations behind an `authorization` header compared against a configured password, this signer-side listener performs **no authentication check whatsoever** on any of its routes.

### Finding Description
`SignerEventReceiver::next_event` in `libsigner/src/events.rs` dispatches incoming HTTP POST requests purely by URL path, with no credential check anywhere in the dispatch logic: [1](#0-0) 

Compare this to the equivalent node-side RPC handlers, which all require a matching `authorization` header before accepting a privileged POST body, e.g.: [2](#0-1) [3](#0-2) 

The signer binds its listener socket directly with no ACL/auth wrapper: [4](#0-3) 

Sample deployment configuration documents this endpoint as bound on all interfaces (`0.0.0.0:30000`), meaning it is reachable from the network if not firewalled: [5](#0-4) [6](#0-5) 

This breaks the intended equality "only the paired `stacks-node` may deliver events to this signer" vs. the actual behavior "any network-reachable client may deliver events to this signer." Concretely:
- `POST /stackerdb_chunks` is deserialized as a `StackerDBChunksEvent` and forwarded into the signer's processing pipeline with no verification that the request actually came from the configured node.
- `POST /shutdown` immediately sets the stop flag and terminates the signer's event loop / main loop, exactly matching the internal mechanism `SignerStopSignaler::send` uses to shut itself down: [7](#0-6) 
Any remote, unauthenticated party can trivially replicate this same HTTP request to kill the signer's event listener.
- `POST /proposal_response`, `POST /new_burn_block`, `POST /new_block` are likewise accepted from anyone.

While `StackerDBChunkData` chunk payloads themselves carry a `sig` field that is checked for validity against expected signer addresses when written into StackerDB or gossiped over the P2P network (see `stackslib/src/net/stackerdb/mod.rs::validate_received_chunk` and `stackslib/src/net/stackerdb/db.rs::try_replace_chunk`), the event-receiver ingestion path in `libsigner` does not perform this authentication before forwarding events to the runloop, and independent of that, the `/shutdown` route has no data-integrity check to bypass at all — it is a pure unauthenticated DoS primitive.

### Impact Explanation
This matches the report's Critical bucket: "remote crash/unauthenticated DoS from few messages" (the `/shutdown` route) and potentially "unauthenticated/unauthorized write to state" (forged/duplicate events fed into the signer runloop via `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block`). A signer that stops responding to block proposals/signing duties directly affects Nakamoto consensus liveness for that signer's stake weight, and can be triggered by a single unauthenticated POST if the signer's `endpoint` (per sample configs, `0.0.0.0:port`) is reachable from the network.

### Likelihood Explanation
The likelihood depends entirely on network exposure of the signer's `endpoint` bind address. The shipped sample configs (`sample/conf/mainnet-signer.toml`, `sample/conf/testnet-signer.toml`, `docs/signing.md`) show the endpoint bound to `0.0.0.0`, and nothing in `libsigner` enforces a loopback-only bind or any authentication, so any operator who follows the documented deployment pattern without an external firewall is exposed. This is a configuration-dependent finding: I could not verify from the index whether there is a mandatory firewall/deployment guideline elsewhere that mitigates this, or a lower-level constraint restricting the bind address — this should be verified by a Devin session with full repo access before treating this as unconditionally exploitable in default deployments.

### Recommendation
Add an authentication mechanism (matching the `auth_token`/`auth_password` scheme already used between the `stacks-node` and its RPC endpoints) to the signer's event-receiver HTTP server, checked before any request dispatch in `SignerEventReceiver::next_event`, and reject unauthenticated requests to all routes including `/shutdown`. At minimum, restrict `bind()` to loopback by default and document/require operators to keep this port private via network policy if binding to a non-loopback address.

### Proof of Concept
```
# Given a running stacks-signer with endpoint = "0.0.0.0:30000" (per sample config)
curl -X POST http://<signer-ip>:30000/shutdown \
     -H "Content-Type: text/plain" \
     --data "any bytes"
# -> signer's SignerEventReceiver sets stop_signal = true and the event loop
#    (and therefore the signer runloop) terminates, with no credentials supplied.
``` [8](#0-7)

    fn next_event(&mut self) -> Result<SignerEvent<T>, EventError> {
        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)
            } else if request.url() == "/new_block" {
                process_event::<T, StacksBlockEvent>(request)
            } else {
                let url = request.url().to_string();
                debug!(
                    "[{:?}] next_event got request with unexpected url {}, return OK so other side doesn't keep sending this",
                    event_receiver.local_addr,
                    url
                );
                ack_dispatcher(request);
                Err(EventError::UnrecognizedEvent(url))
            }
        })?
