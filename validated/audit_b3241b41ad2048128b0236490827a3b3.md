### Title
Global (non-per-IP) `max_concurrent_connections` slot exhaustion via half-open QUIC handshakes bypasses per-IP `ConnectionRateLimiter` - ([File: streamer/src/nonblocking/quic.rs])

### Summary
`ConnectionRateLimiter::is_allowed` intentionally treats any never-before-seen source IP as unthrottled (`None => true`), and `register_connection` is only invoked in `setup_connection` after a QUIC handshake successfully completes. An attacker who continuously opens QUIC connections from one real (non-spoofed) IP but never completes the TLS handshake never gets an entry in the per-IP token bucket, yet each attempt still reserves a slot in the single, globally-shared `open_connections` counter guarded by `ClientConnectionTracker::new`.

### Finding Description
In `run_server` [1](#0-0)  the mitigation order is: (1) check `overall_connection_rate_limiter.current_tokens() == 0`, (2) check `rate_limiter.is_allowed(ip)`, (3) reserve a slot via `ClientConnectionTracker::new(stats, qos.max_concurrent_connections())`. Per-IP throttling in `ConnectionRateLimiter::is_allowed` returns `true` unconditionally for any IP with no prior record [2](#0-1) , and the record is only created by `register_connection`, which is only called from `setup_connection` after the handshake future resolves `Ok` [3](#0-2) . If the attacker lets the handshake time out (or repeatedly aborts before completion), `register_connection` is never called, so the attacking IP is never inserted into the per-IP bucket and can retry indefinitely without being throttled by IP.

Similarly, `overall_connection_rate_limiter.consume_tokens(1)` is only invoked post-handshake in `setup_connection` [4](#0-3) ; the pre-accept check only reads `current_tokens()` without decrementing [5](#0-4) , so concurrent unfinished handshakes never actually deplete this bucket either.

The only resource that is actually consumed at accept time regardless of handshake outcome is the single global (not per-IP) `stats.open_connections` counter enforced by `ClientConnectionTracker::new`, bounded by `qos.max_concurrent_connections()` [6](#0-5) . This limit is computed globally as `(max_staked_connections + max_unstaked_connections) * 5 / 4` with no per-IP dimension [7](#0-6) . A slot is held from `ClientConnectionTracker::new` until the `ClientConnectionTracker` is dropped, which happens only when `setup_connection`'s handshake `timeout(QUIC_CONNECTION_HANDSHAKE_TIMEOUT, connecting)` resolves (success, error, or timeout) [8](#0-7) .

Consequently, a single attacking IP that keeps a sufficient number of concurrent half-open QUIC Initial handshakes in flight (more than `max_concurrent_connections`) can exhaust the entire global connection-slot budget for the duration of the handshake timeout, causing subsequent legitimate connection attempts from any IP (staked or unstaked) to be rejected via `refused_connections_too_many_open_connections` / `incoming.refuse()`, while the attacker itself is never charged against `ConnectionRateLimiter`.

The code comments in `run_server` show this tradeoff is a known design choice (deferring per-IP throttling until "a peer has asserted control over their ip address," to avoid IP-spoofing amplification attacks) [9](#0-8) , but the stated mitigations ("protect against connection attempt bursts with a global rate-limiter") do not actually bound concurrent unfinished handshakes, since that bucket is decremented only on successful completion, not at accept time.

### Impact Explanation
This is a liveness/availability (DoS) issue: an unstaked, unprivileged attacker directly hitting the public TPU QUIC port can starve the shared connection-acceptance capacity (`open_connections` / `max_concurrent_connections`) for the whole node, preventing legitimate staked and unstaked peers from establishing new QUIC connections and submitting transactions for the duration of the attack. It does not cause unbounded memory (the counter is bounded), a panic, or a consensus/verification bypass — it is a targeted availability degradation of the ingress path.

### Likelihood Explanation
Preconditions are minimal: the attacker needs only network reachability to the leader's TPU QUIC port and the ability to open many concurrent QUIC connections from one real IP without completing the handshake (e.g., by never responding to the server's handshake flight, or deliberately delaying/aborting after the Initial packet). No stake, keys, or special privileges are required. The attack is repeatable indefinitely as long as the attacker maintains more than `max_concurrent_connections` outstanding half-open attempts, cycling as each hits `QUIC_CONNECTION_HANDSHAKE_TIMEOUT`.

### Recommendation
Bind pre-handshake resource reservation (`ClientConnectionTracker`) with a per-IP cap in addition to the global cap, so a single source cannot consume the entire shared pending-connection budget; alternatively, deduct from `overall_connection_rate_limiter` at accept time (before handshake) rather than only on successful completion, and/or track outstanding half-open attempts per IP (independent from the confirmed-IP `ConnectionRateLimiter`) to bound per-source pending handshake concurrency.

### Proof of Concept
Integration test plan (extends existing `run_server`/`setup_connection` test harness in `streamer/src/nonblocking/quic.rs`):
1. Configure `qos.max_concurrent_connections()` to a small test value (e.g., 10) via `SwQosConfig::default_for_tests()`.
2. From a single client IP, open `> max_concurrent_connections` QUIC `Connecting` handles concurrently but never drive them to completion (do not perform the TLS handshake, or hold at Initial stage) until `QUIC_CONNECTION_HANDSHAKE_TIMEOUT` elapses.
3. Assert via `stats.refused_connections_too_many_open_connections` that a second, independent client IP attempting a normal (fully-handshaking) connection during this window is refused (`incoming.refuse()` path), even though the second IP has never previously connected.
4. Assert via `ConnectionRateLimiter` internals (or `stats.connection_rate_limited_per_ipaddr`) that the attacking IP is never recorded/throttled by `is_allowed`/`register_connection`, confirming the per-IP limiter is bypassed while the global slot budget is exhausted.

impl ClientConnectionTracker {
    /// Check the max_concurrent_connections limit and if it is within the limit
    /// create ClientConnectionTracker and increment open connection count. Otherwise returns Err
    fn new(stats: Arc<StreamerStats>, max_concurrent_connections: usize) -> Result<Self, ()> {
        let open_connections = stats.open_connections.fetch_add(1, Ordering::Relaxed);
        if open_connections >= max_concurrent_connections {
            stats.open_connections.fetch_sub(1, Ordering::Relaxed);
            debug!(
                "There are too many concurrent connections opened already: open: \
                 {open_connections}, max: {max_concurrent_connections}"
            );
            return Err(());
        }

        Ok(Self { stats })
    }
}

        // Check if we have records in the rate limiter for the given IP address
        match self.limiter.current_tokens(ip) {
            Some(r) => r > 0, // we have a record, and rate is not exceeded
            None => true,     // if we have not seen IP, allow connection request
