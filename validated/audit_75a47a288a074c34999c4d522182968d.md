This is an important finding. `CreateRepositoryFromSnapshot` fetches an arbitrary HTTP URL controlled by the RPC request and extracts it directly onto the newly-created repository's disk path via `extractTarToDirectory` [1](#0-0)  before any partition assignment or git-fsck-like validation of file contents occurs, and the code comment explicitly warns "the received archive is trusted a lot" [2](#0-1) . An attacker fully controls `HttpUrl`/`HttpAuth` and thus the tar contents, meaning they can include a crafted `objects/info/alternates` file. `CreateRepositoryFromBundle`, in contrast, only invokes `git clone --mirror` on a bundle, which cannot write an `objects/info/alternates` file [3](#0-2) , so that vector is not exploitable — but the snapshot-based path is.

Once such a repository is created with an attacker-controlled `objects/info/alternates` file pointing (via a relative path escaping the repo but staying inside the storage root) at `<victim>/objects`, the very next transactional access to the attacker's own repository triggers `partitionAssigner.getPartitionIDRecursive` → `assignPartitionID` → `getAlternatePartitionID`, which reads that file via `gitstorage.ReadAlternatesFile` [4](#0-3) , validates only that the resolved path stays inside the storage root and isn't self-referential [5](#0-4) , and then recursively assigns/joins the victim repository's partition [6](#0-5) . There is no check anywhere in this code path that the alternate target is a pool the caller is authorized to join, or that a legitimate `LinkRepositoryToObjectPool` call ever occurred for this specific attacker repository — `getAlternatePartitionID` only rejects self-reference, chained alternates, and out-of-storage escapes.

### Title
Attacker-controlled snapshot TAR can inject a forged `objects/info/alternates` file to co-locate an unauthorized repository into a victim repository's WAL/transaction partition - (File: internal/gitaly/service/repository/create_repository_from_snapshot.go, internal/gitaly/storage/storagemgr/partition_assigner.go)

### Summary
`CreateRepositoryFromSnapshot` extracts an attacker-supplied TAR (fetched from an attacker-controlled `HttpUrl`) directly into a newly created repository's disk path without validating repository metadata files such as `objects/info/alternates`. Because `partition_assigner.go`'s `getAlternatePartitionID` only validates that an alternates path stays within the storage root, is not self-referential, and is not chained, an attacker can plant an alternates file pointing at any other repository's object directory in the same storage, causing their own repository to be placed into that victim repository's storage partition — without ever going through the authorized `LinkRepositoryToObjectPool`/`Link` flow.

### Finding Description
`CreateRepositoryFromSnapshot` builds the new repository by calling `s.extractSnapshot` → `s.extractTarToDirectory`, which extracts arbitrary regular files (including `objects/info/alternates`) from the tar stream onto the freshly created repository directory [7](#0-6) . The tar content originates from an HTTP response fetched from `in.GetHttpUrl()`, a field fully controlled by the calling RPC client [8](#0-7) . The extraction path-traversal protections (`strings.HasPrefix(targetPath, targetDir+...)`) only stop the tar from writing outside the target repository directory [9](#0-8) ; they do not restrict which relative-path *content* may be written inside legitimate repository metadata files such as `objects/info/alternates`.

Later, when any transactional RPC (mutator or accessor) accesses this newly created repository, `beginTransactionForRepository`/`storageHandle.Begin` invokes the `partitionAssigner`, which for repositories without a partition assignment calls `assignPartitionID` → `getAlternatePartitionID` [10](#0-9) . This function reads the alternates file with `gitstorage.ReadAlternatesFile` [11](#0-10) , resolves it relative to the attacker's own repository, and validates only that it is inside the storage root, not chained, and not self-referential [5](#0-4) . If the resolved path names an existing repository directory anywhere in the same storage (e.g. the victim's relative path), `getPartitionIDRecursive` is called recursively on it and its partition ID is adopted as the attacker repository's own partition ID [6](#0-5) . No authorization check verifies that the "alternate" target was ever legitimately linked to the attacker's repository via the trusted `objectpool.Link` code path (which normally computes and writes the alternates content itself, from a `pool` object resolved server-side) [12](#0-11) .

This bypasses the intended trust model where alternates files are only ever written by Gitaly's own `Link` logic in response to an authorized `LinkRepositoryToObjectPool`/`CreateFork`/`CreateObjectPool` RPC that resolves the pool through `poolForRequest`, not through arbitrary caller-supplied file content.

### Impact Explanation
Once co-located in the victim's partition, the attacker's transactions on their own (attacker-owned) repository share the same WAL/badger keyspace and snapshot machinery as the victim repository. Depending on how snapshot isolation and cross-repository visibility are implemented for partitioned repositories, this could allow the attacker to observe or interfere with the victim repository's transactional state (e.g. concurrent transaction serialization, potential visibility of the victim's object data via git alternate object lookup once the alternates file is honored by git tooling, since alternates directly grant git object read access to the target directory). This matches the "cross-repository objects or metadata disclosed" impact class.

### Likelihood Explanation
Requires only an unprivileged user capable of calling `CreateRepositoryFromSnapshot` with an `HttpUrl` they control (e.g. hosting a crafted tar on infrastructure they own) and knowledge of the victim's relative storage path (which, depending on deployment, may be predictable/derived, e.g. `@hashed/...` scheme, or leaked via other APIs). No race condition or special timing is needed beyond triggering the RPC before any legitimate partition assignment for the newly created repository. This is fully within the "no admin/operator role" unprivileged threat model described.

### Recommendation
- Reject or strip `objects/info/alternates` (and any other Git metadata files that reference paths outside the extracted tar's own tree) during `CreateRepositoryFromSnapshot`/`ReplicateRepository` tar extraction.
- In `getAlternatePartitionID`, require that the alternate target repository is validated to be an actual object pool the caller/repository has been authorized to join (e.g., by checking that the alternates content was set only by Gitaly's own `Link` logic, or by re-verifying via a pool membership record), not merely a syntactically valid same-storage path.
- Consider validating alternates file contents at repository creation time (`repoutil.Create`) for all repository-creating RPCs that accept raw file trees.

func (s *server) extractSnapshot(ctx context.Context, source, target *gitalypb.Repository) error {
	repoClient, err := s.newRepoClient(ctx, source.GetStorageName())
	if err != nil {
		return fmt.Errorf("new client: %w", err)
	}

	stream, err := repoClient.GetSnapshot(ctx, &gitalypb.GetSnapshotRequest{Repository: source})
	if err != nil {
		return fmt.Errorf("get snapshot: %w", err)
	}

	// We need to catch a possible 'invalid repository' error from GetSnapshot. On an empty read,
	// we read the first message from the stream here to get access to the possible 'invalid repository' error.
	firstBytes, err := stream.Recv()
	if err != nil {
		switch {
		case structerr.GRPCCode(err) == codes.NotFound && strings.Contains(err.Error(), "GetRepoPath: not a git repository:"):
			// The error condition exists for backwards compatibility purposes, only,
			// and can be removed in the next release.
			return ErrInvalidSourceRepository
		case structerr.GRPCCode(err) == codes.NotFound && strings.Contains(err.Error(), storage.ErrRepositoryNotFound.Error()):
			return ErrInvalidSourceRepository
		case structerr.GRPCCode(err) == codes.FailedPrecondition && strings.Contains(err.Error(), storage.ErrRepositoryNotValid.Error()):
			return ErrInvalidSourceRepository
		default:
			return fmt.Errorf("first snapshot read: %w", err)
		}
	}

	snapshotReader := io.MultiReader(
		bytes.NewReader(firstBytes.GetData()),
		streamio.NewReader(func() ([]byte, error) {
			resp, err := stream.Recv()
			return resp.GetData(), err
		}),
	)

	targetPath, err := s.locator.GetRepoPath(ctx, target, storage.WithRepositoryVerificationSkipped())
	if err != nil {
		return fmt.Errorf("target path: %w", err)
	}

	// Extract tar using Go's tar package
	if err := s.extractTarToDirectory(ctx, snapshotReader, targetPath); err != nil {
		return fmt.Errorf("extract tar: %w", err)
	}

	return nil
}

func (s *server) untar(ctx context.Context, path string, in *gitalypb.CreateRepositoryFromSnapshotRequest) error {
	req, err := http.NewRequestWithContext(ctx, "GET", in.GetHttpUrl(), nil)
	if err != nil {
		return structerr.NewInvalidArgument("Bad HTTP URL: %w", err)
	}

	client := httpClient
	if resolvedAddress := in.GetResolvedAddress(); resolvedAddress != "" {
		client, err = newResolvedHTTPClient(in.GetHttpUrl(), resolvedAddress)
		if err != nil {
			return structerr.NewInvalidArgument("creating resolved HTTP client: %w", err)
		}
	}

	if in.GetHttpAuth() != "" {
		req.Header.Set("Authorization", in.GetHttpAuth())
	}

	rsp, err := client.Do(req)
	if err != nil {
		return structerr.NewInternal("HTTP request failed: %w", err)
	}
	defer rsp.Body.Close()

	if rsp.StatusCode < http.StatusOK || rsp.StatusCode >= http.StatusMultipleChoices {
		return structerr.NewInternal("HTTP server: %s", rsp.Status)
	}

	cmd, err := command.New(ctx, s.logger, []string{"tar", "-C", path, "-xvf", "-"}, command.WithStdin(rsp.Body))
	if err != nil {
		return err
	}

	return cmd.Wait()
}

func (pa *partitionAssigner) assignPartitionID(ctx context.Context, relativePath string, recursiveCall bool, partitionHint storage.PartitionID) (storage.PartitionID, error) {
	// Check if the repository has an alternate. If so, it needs to go into the same
	// partition with it.
	ptnID, err := pa.getAlternatePartitionID(ctx, relativePath, recursiveCall, partitionHint)
	if err != nil {
		if !errors.Is(err, gitstorage.ErrNoAlternate) {
			return 0, fmt.Errorf("get alternate partition ID: %w", err)
		}

		ptnID = partitionHint
		if ptnID == invalidPartitionID {
			// The repository has no alternate. Unpooled repositories go into their own partitions.
			// Allocate a new partition ID for this repository.
			ptnID, err = pa.allocatePartitionID()
			if err != nil {
				return 0, fmt.Errorf("acquire partition id: %w", err)
			}
		}
	}

	if err := pa.partitionAssignmentTable.setPartitionID(relativePath, ptnID); err != nil {
		return 0, fmt.Errorf("set partition: %w", err)
	}

	return ptnID, nil
}

func ReadAlternatesFile(repositoryPath string) (string, error) {
	alternates, err := stats.ReadAlternatesFile(repositoryPath)
	if err != nil {
		if errors.Is(err, fs.ErrNotExist) {
			return "", ErrNoAlternate
		}

		return "", fmt.Errorf("read alternates file: %w", err)
	}

	if len(alternates) == 0 {
		return "", ErrNoAlternate
	} else if len(alternates) > 1 {
		// Repositories shouldn't have more than one alternate given they should only be
		// linked to a single pool at most.
		return "", ErrMultipleAlternates
	}
