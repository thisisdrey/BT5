### Title
Unauthenticated `RecvError` packets allow spoofed remote-index/IP DOS of legitimate tunnels - (File: `outside.go`, `interface.go`)

### Summary
`handleRecvError` in `outside.go` tears down a live tunnel based on an unauthenticated, unencrypted `header.RecvError` control packet whose only "replay/identity" checks are (1) an attacker-suppliable 32-bit `RemoteIndex` used to look up the hostinfo via `QueryReverseIndex`, and (2) a comparison of the UDP source address against the hostinfo's last-known remote — a value that is not cryptographically bound to the packet and is trivially spoofable on UDP. [1](#0-0)  This is analogous to the reported `_deduplicateOrder` bug class: a state-mutating, "already-processed" style check keyed on attacker-controllable values (index + claimed source) that a third party can forge to disrupt a legitimate party's session, causing a denial of service.

### Finding Description
`RecvError` packets are processed before any encryption/authentication check, directly off the wire type/subtype dispatch: [2](#0-1) 

`handleRecvError` then:
1. Optionally rate-gates via `acceptRecvErrorConfig.ShouldRecvError(addr)` (a sampling/config gate, not a cryptographic check).
2. Looks up `hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)` using the attacker-supplied 32-bit index from the packet header.
3. Compares the *claimed* UDP source address (`addr`, taken from the packet's IP/UDP header, i.e. trivially spoofable) against `hostinfo.GetRemote()`.
4. If they match (or if the hostinfo's remote hasn't been set yet), it calls `f.closeTunnel(hostinfo)` and `f.handshakeManager.DeleteHostInfo(hostinfo)` — tearing down the tunnel and forcing a fresh handshake. [1](#0-0) 

Nothing in this path verifies a MAC, signature, or any value derived from the session keys; the "was this message caused by an errant packet from this remote" decision rests entirely on (a) guessing/observing a 32-bit index and (b) an IP-address match that requires no possession of key material — exactly the same class of weakness as the report's `_deduplicateOrder`, where an attacker-controlled value (`order.nonce`/`order.benefactor`) let a third party manipulate state that should only be affected by the legitimate counterparty. Here, an attacker who can spoof UDP packets (or, on some networks, observe/guess the remote index, which appears on the wire in cleartext handshake/message headers) can force disconnection and re-handshake of a legitimate tunnel repeatedly, denying service.

### Impact Explanation
Repeated forged `RecvError` packets let a network-adjacent or spoofing-capable attacker continuously tear down established tunnels between two legitimate Nebula peers, forcing constant re-handshakes (a network-level DOS on tunnel availability), without needing a valid CA-issued certificate or session key. The remote index is visible in cleartext in normal traffic headers, so an attacker who can observe or intercept any packet between two peers (or who successfully spoofs the source UDP address) obtains everything needed to mount the attack.

### Likelihood Explanation
Moderate. The attack requires (1) knowledge of a live `RemoteIndex` value, obtainable by observing any packet exchanged between the victim peers (indexes are sent in cleartext headers), and (2) either genuine on-path position or the ability to spoof the victim peer's UDP source address, which is possible in many network environments (no BCP38 filtering, certain L2/adjacent-network positions, or reflection). No cryptographic secret is required, unlike normal data-plane or handshake packets.

### Recommendation
Do not tear down a tunnel purely on an unauthenticated `RecvError` packet plus an IP-address match. Options:
- Require some proof of possession, e.g. only accept `RecvError` when carrying a value that could only be produced by someone holding the session key (a small MAC over the index using the current session key), rather than relying solely on the RemoteIndex lookup and spoofable source IP.
- Rate-limit/backoff more aggressively per (remote-index, claimed source) pair, and require multiple consistent errors from the same authenticated flow before tearing down.
- At minimum, tighten `ShouldRecvError`/`acceptRecvErrorConfig` defaults so an attacker cannot cheaply trigger repeated teardown, and log/alert when the "someone spoofing recv_errors?" branch is hit instead of silently ignoring only the mismatched case (the matched/valid case is the actual risk).

### Proof of Concept
1. Attacker observes (or is on-path for) traffic between Alice and Bob, learning Bob's `RemoteIndex` (visible in cleartext in the wire header of any message Bob sends/receives, e.g. via `header.H.RemoteIndex`).
2. Attacker crafts a `header.RecvError` packet: `header.Encode(buf, header.Version, header.RecvError, 0, aliceObservedIndex, 0)` and sends it to Alice, spoofing the UDP source address to match Bob's known address (or simply sending from any address if `hostinfo.GetRemote()` is not yet set, e.g. right after roaming).
3. Alice's `readOutsidePackets` dispatches directly to `f.handleRecvError(via.UdpAddr, h)` without any decryption/authentication. [3](#0-2) 
4. `handleRecvError` finds the hostinfo via `QueryReverseIndex(h.RemoteIndex)`, the spoofed `addr` matches `hostinfo.GetRemote()`, and Alice's tunnel to Bob is torn down (`closeTunnel` + `DeleteHostInfo`). [4](#0-3) 
5. Repeating this at will denies Alice and Bob a stable tunnel, forcing continuous re-handshakes — a DOS analogous to the reported nonce-collision DOS on `mint()`/`completeRedeem()`.

func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
