## Analog Found: Unauthenticated `getnodeinfo` API Discloses Internal Node Topology & Configuration

### Title
Unauthenticated `/wallet/getnodeinfo` (and gRPC `GetNodeInfo`) API discloses internal peer IPs, ports and node configuration to any client - (File: framework/src/main/java/org/tron/core/services/http/GetNodeInfoServlet.java)

### Summary
The eZ Platform advisory concerns a REST endpoint that discloses internal configuration data (site access names) to any unauthenticated caller. The direct analog in java-tron is the `getnodeinfo` HTTP endpoint and its gRPC counterpart, which return detailed internal node/network configuration — including connected peers' IP addresses and ports, node listen/backup ports, discovery settings, and node counts — to any anonymous API client, with no authentication or authorization check by default.

### Finding Description
`GetNodeInfoServlet.doGet`/`doPost` calls `NodeInfoService.getNodeInfo()` and serializes the full result directly to the HTTP response with no access control: [1](#0-0) 

The same unauthenticated exposure exists via gRPC in `RpcApiService`: [2](#0-1) 

`NodeInfoService.setConnectInfo` populates each `PeerInfo` entry with the remote peer's real `host` (IP address) and `port`, and `setConfigNodeInfo` fills in the node's own listen port, backup port/priority, discovery-enable flag, and active/passive/seed node counts: [3](#0-2) [4](#0-3) 

The only gate on any HTTP API path is `HttpApiAccessFilter`, which only blocks an endpoint if it is explicitly listed in the operator-configured `disabledApiList` — which is empty by default, so `getnodeinfo` is reachable by any anonymous caller out of the box: [5](#0-4) 

This mirrors the eZ Platform bug class (CWE-200, information exposure through an API meant for authenticated/administrative use but reachable by anyone) — instead of leaking site-access names, java-tron leaks the network topology of the node's peers and its own service configuration.

### Impact Explanation
Disclosure of peer IP addresses/ports, discovery configuration, and backup member/priority settings gives an unauthenticated remote attacker a detailed network map of a full/solidity/PBFT node's peer-to-peer connections and internal service configuration. This facilitates targeted network-level attacks (e.g., DoS against specific peers, eclipse/Sybil setup, or targeting backup/witness infrastructure) against nodes and their peers, which is a legitimate confidentiality impact for a publicly reachable node information API. It does not by itself allow theft of funds or unauthorized transactions, so its severity is bounded to information disclosure impacting node/network security posture.

### Likelihood Explanation
The endpoint is registered without authentication on the default full node, solidity node, and PBFT HTTP API surfaces:

Any anonymous HTTP client can call `GET /wallet/getnodeinfo` (or the equivalent `walletsolidity`/PBFT paths, and the gRPC `GetNodeInfo` RPC) with zero preconditions, making exploitation trivial and remotely reachable by design.

### Recommendation
Restrict `getnodeinfo` (HTTP and gRPC) to trusted/internal callers by default — e.g., require it to be explicitly enabled via configuration (opt-in) rather than opt-out via `disabledApiList`, or strip peer IP/port and sensitive `ConfigNodeInfo` fields (listen ports, backup priority/ports, discovery flag) from the response returned to non-authenticated/non-local callers, similar to how eZ Platform restricted the site-access listing to authorized requests only.

### Proof of Concept
Against a node running the default HTTP API service (no `disabledApiList` entry for `getnodeinfo`), an anonymous client can run:
```
curl http://<node-host>:8090/wallet/getnodeinfo
```
The JSON response includes `peerInfoList[].host`/`port` for every connected peer and `configNodeInfo` fields (`listenPort`, `backupListenPort`, `backupPriority`, `discoverEnable`, `activeNodeSize`, `passiveNodeSize`, `sendNodeSize`), all sourced from `NodeInfoService.setConnectInfo`/`setConfigNodeInfo` with no authentication check applied by `GetNodeInfoServlet` or `HttpApiAccessFilter`.

  private boolean isDisabled(String endpoint) {
    boolean disabled = false;

    try {
      endpoint = URI.create(endpoint).normalize().toString();
      List<String> disabledApiList = CommonParameter.getInstance().getDisabledApiList();
      if (!disabledApiList.isEmpty()) {
        disabled = disabledApiList.contains(endpoint.split("/")[2].toLowerCase(Locale.ROOT));
      }
    } catch (Exception e) {
      logger.warn("check isDisabled except, endpoint={}, {}", endpoint, e.getMessage());
    }

    return disabled;
  }
