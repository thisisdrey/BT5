Based on my investigation, the strongest candidate is in `extractSigArray`/`extractBytes32Array`/`extractBytesArray` helper methods in `PrecompiledContracts.java`, which parse attacker-controlled TVM call data using length fields taken directly from the input without validating that the derived offsets stay within the `words`/`data` array bounds.

### Title
Out-of-bounds read in precompiled contract batch-signature/array parsing via attacker-controlled length/offset fields - (File: actuator/src/main/java/org/tron/core/vm/PrecompiledContracts.java)

### Summary
`extractSigArray`, `extractBytes32Array`, and `extractBytesArray` in `PrecompiledContracts.java` parse ABI-encoded arrays from smart-contract call data by reading a length word and then indexing into the `words` array and the raw `data` byte array using offsets derived from attacker-supplied `DataWord` values, without bounds-checking the derived indices against the actual array size.

### Finding Description
`extractBytes32Array` computes `len = words[offset].intValueSafe()` and then loops `bytesArray[i] = words[offset + i + 1].getData()` for `i` in `[0, len)` with no check that `offset + i + 1 < words.length` [1](#0-0) . Similarly, `extractSigArray` only checks `offset > words.length - 1` for the initial offset, but then iterates `len` times computing `words[offset + i + 1]` and calling `extractBytes(data, (bytesOffset + offset + 2) * WORD_SIZE, SIG_LENGTH)`, where `bytesOffset` is itself derived from attacker data divided by `WORD_SIZE` [2](#0-1) . `extractBytes` performs a raw `Arrays.copyOfRange(data, offset, offset + len)` with no bounds validation at all [3](#0-2) . Because `len` and `bytesOffset` are attacker-controlled 32-byte words converted via `intValueSafe()`, a crafted precompile call can make `offset + i + 1` exceed `words.length` (causing `ArrayIndexOutOfBoundsException`) or make `(bytesOffset + offset + 2) * WORD_SIZE` and `offset+len` in `Arrays.copyOfRange` exceed `data.length`, which throws `ArrayIndexOutOfBoundsException` for negative/overflowed start or silently zero-pads for out-of-range end (Java's `copyOfRange` pads with zero bytes rather than reading OOB memory, but the array-index style overrun on `words[]` is a direct unchecked read past array bounds). This directly mirrors the CVE-2018-8105 bug class: a length/offset field taken from untrusted input drives a buffer read without validating it stays inside the allocated buffer.

### Impact Explanation
An `ArrayIndexOutOfBoundsException` thrown mid-execution inside a precompiled contract invoked from the TVM interpreter loop is an uncaught runtime exception in a code path that is supposed to return `Pair.of(false, ...)` on malformed input rather than throw. Depending on where this exception propagates in the VM/transaction execution pipeline, this can crash the node's transaction processing thread or cause inconsistent handling between full nodes that catch generic `Throwable` versus places that don't, risking a node crash or a consensus-relevant execution divergence if some nodes handle the exception differently than others.

### Likelihood Explanation
Reachability requires only a deployed contract that calls the relevant precompiled contract address with crafted call data — this is achievable by any unprivileged contract deployer/caller since precompiled contracts are invoked via normal TVM `CALL` opcodes with arbitrary attacker-supplied byte data, and no permission checks gate the parsing of `len`/`offset` fields before the array indexing occurs.

### Recommendation
Add explicit bounds checks in `extractBytes32Array` and `extractSigArray` before indexing `words[offset + i + 1]` (verify `offset + i + 1 < words.length` for every iteration, not just the initial `offset`), and add bounds validation in `extractBytes` to verify `offset >= 0 && offset + len <= data.length` before calling `Arrays.copyOfRange`, returning a failure `Pair.of(false, EMPTY_BYTE_ARRAY)` instead of throwing when the encoded length/offset is inconsistent with the actual call data size.

### Proof of Concept
Craft a transaction that calls the precompiled contract using `extractSigArray`/`extractBytes32Array` (e.g., the batch-validate-sign precompile) with a `data` payload whose length-prefix word (`words[offset]`) is set to a large value (e.g., `0xFFFFFFFF` truncated via `intValueSafe()`), while the actual `data`/`words` array supplied is short. This causes the loop to index `words[offset + i + 1]` past the end of the actual populated `words` array, throwing `ArrayIndexOutOfBoundsException` during precompile execution.

    int len = words[offset].intValueSafe();
    byte[][] bytes32Array = new byte[len][];

  private static byte[][] extractBytesArray(DataWord[] words, int offset, byte[] data) {
    if (offset > words.length - 1) {
      return new byte[0][];
    }
    int len = words[offset].intValueSafe();
    byte[][] bytesArray = new byte[len][];
    for (int i = 0; i < len; i++) {
      int bytesOffset = words[offset + i + 1].intValueSafe() / WORD_SIZE;
      int bytesLen = words[offset + bytesOffset + 1].intValueSafe();
      bytesArray[i] = extractBytes(data, (bytesOffset + offset + 2) * WORD_SIZE,
          bytesLen);
    }
    return bytesArray;
  }

  private static byte[][] extractSigArray(DataWord[] words, int offset, byte[] data) {
    if (offset > words.length - 1) {
      return new byte[0][];
    }
    int len = words[offset].intValueSafe();
    byte[][] bytesArray = new byte[len][];
    for (int i = 0; i < len; i++) {
      int bytesOffset = words[offset + i + 1].intValueSafe() / WORD_SIZE;
      bytesArray[i] = extractBytes(data, (bytesOffset + offset + 2) * WORD_SIZE,
          SIG_LENGTH);
    }
    return bytesArray;
  }

  private static byte[] extractBytes(byte[] data, int offset, int len) {
    return Arrays.copyOfRange(data, offset, offset + len);
  }
