This confirms the mechanism: `internal_add_balance` and `internal_sub_balance` on `Deltas<S>` both feed the raw amount into `self.deltas.deposit`/`self.deltas.withdraw` (the `TransferMatcher`), which is the same ledger the fee-collector credit is deposited into via `internal_add_balance(fee_collector, fees_collected)` at [1](#0-0) . This means the fee amount is a real, load-bearing component of the batch's zero-sum invariant checked by `TransferMatcher::finalize` [2](#0-1) , exactly as demonstrated by the `solver_user_closure` test where the counterparty's contribution is fee-adjusted via `TokenDiff::closure_delta` [3](#0-2) .

### Title
Splitting a NEP-245/IMT negative `TokenDiff` delta into unit-size (`|delta|<=1`) legs bypasses `Pips::fee_ceil` entirely - (File: contracts/defuse/core/src/intents/token_diff.rs)

### Summary
`TokenDiff::token_fee` waives fees whenever `TokenIdType::Nep245`/`Imt` has `amount <= 1`, intended for NFT-like sub-tokens inside multi-token contracts [4](#0-3) . Because `DefuseIntents` allows an arbitrary `Vec<Intent>` under one signature [5](#0-4) , a signer can replace one `TokenDiff{diff:{token_id: -1_000_000}}` leg with 1,000,000 separate `TokenDiff{diff:{token_id: -1}}` legs in the same `MultiPayload`, making `Self::token_fee(token_id, 1, protocol_fee).fee_ceil(1)` evaluate to `Pips::ZERO` 1,000,000 times instead of `Pips::fee_ceil(1_000_000)` once.

### Finding Description
The broken binding: `fees_collected(token_id) == Pips::fee_ceil(total_negative_delta(token_id))` for the batch. As written, the loop in `TokenDiff::execute_intent` computes the fee per-leg on the *magnitude of that single leg* rather than on the aggregate negative delta contributed by the signer for `token_id` across the whole `DefuseIntents`/batch [6](#0-5) . Since `token_fee` treats any NEP-245/IMT delta of magnitude `<=1` as fee-exempt (a heuristic meant to avoid taxing genuinely non-fungible 1-of-1 sub-tokens), an attacker who owns/controls a fungible NEP-245 balance can partition any negative delta into `N` legs of `-1` each, still producing the *same total raw debit* fed into `TransferMatcher` (via `internal_sub_balance`/`internal_apply_deltas`) [7](#0-6) , but with `fees_collected` summing to `0` instead of `Pips::fee_ceil(N)`. Because `internal_add_balance(fee_collector, fees_collected)` deposits the fee into the same `TransferMatcher` ledger that enforces the batch's zero-sum invariant [8](#0-7) , the counterparty side of the trade (which normally supplies less than the nominal amount because a portion is diverted to `fee_collector`, as shown by `closure_delta`) instead needs to supply the *full, non-fee-adjusted* amount for the ledger to balance — the value that would have gone to `fee_collector` instead flows entirely to the attacker/counterparty. No existing guard (`MultiPayload::verify`, `verify_intent_nonce`, `TransferMatcher::finalize`, `checked_*` arithmetic) checks or aggregates the negative delta per `(signer, token_id)` across the intents in the batch before computing the fee.

### Impact Explanation
`fee_collector` under-collects protocol fees on NEP-245 (multi-token) and IMT assets by exactly `Pips::fee_ceil(|total_delta|)` per exploited batch, with the diverted value credited to whichever party is receiving the matched credit in the batch (the attacker's own second account, or their trade counterparty in a self-arranged closure). This is repeatable per batch/token/account with no bound on `N` other than transaction size/gas, matching the "protocol fees bypassed" Critical impact category, since real value that should be credited to `fee_collector` never leaves the trading parties.

### Likelihood Explanation
The attacker needs only their own signing key(s) and control of any NEP-245 (or IMT) balance/counterparty (which they can arrange entirely with two self-controlled Defuse accounts inside one `execute_intents` call, no privileged role required). Constructing `N` `TokenDiff` intents inside a single signed `DefuseIntents` payload is a pure client-side JSON-construction task; no additional signatures, deposits, or special permissions are needed beyond what any user already has. The only friction is transaction size/gas for large `N`, which is explicitly out of scope but does not block smaller-`N` exploitation, and it is fully reproducible in `near-workspaces`/unit tests by comparing `fees_collected` for a single `-1_000_000` leg vs. many `-1` legs.

### Recommendation
Aggregate negative deltas per `(signer, token_id)` across all `TokenDiff`/`Intent` entries in the whole `DefuseIntents`/batch before applying `token_fee`'s amount-based NFT exemption (i.e., base the `amount <= 1` fee-exemption check on the true total magnitude of same-token debits by the signer in the transaction, not on each individual leg in isolation), or forbid multiple `TokenDiff` legs referencing the same `(signer, token_id)` pair within a single execution context.

### Proof of Concept
`cargo test` in `contracts/defuse/core` (or `tests/src/tests/defuse/intents/token_diff.rs` using the sandbox harness):
1. Set up two Defuse accounts (attacker A and attacker-controlled B, or A and a normal counterparty), fund A with `1_000_000` units of a NEP-245 token, set `protocol_fee = Pips::ONE_PERCENT`.
2. Case 1: sign `DefuseIntents{intents: [TokenDiff{diff:{token_id: -1_000_000}}]}` for A plus a matching counterparty `TokenDiff` (using `TokenDiff::closure_delta`) and execute; assert `fee_collector`'s balance increases by `Pips::ONE_PERCENT.fee_ceil(1_000_000)`.
3. Case 2: sign `DefuseIntents{intents: (0..1_000_000).map(|_| TokenDiff{diff:{token_id: -1}}).collect()}` for A plus the same aggregate counterparty credit, execute; assert `fee_collector`'s balance increases by `0`.
4. Assert the two `fee_collector` balance deltas differ (`Pips::ONE_PERCENT.fee_ceil(1_000_000) != 0`), proving fee bypass for equivalent net transfers.

    // Finalizes all transfers, or returns unmatched deltas.
    // If unmatched deltas overflow, then Err(None) is returned.
    pub fn finalize(self) -> Result<Transfers, InvariantViolated> {
        let mut transfers = Transfers::default();
        let mut deltas = TokenDeltas::default();
        for (token_id, transfer_matcher) in self.0 {
            if let Err(unmatched) = transfer_matcher.finalize_into(&token_id, &mut transfers)
                && (unmatched == 0 || deltas.apply_delta(token_id, unmatched).is_none())
            {
                return Err(InvariantViolated::Overflow);
            }
        }
        if !deltas.is_empty() {
            return Err(InvariantViolated::UnmatchedDeltas {
                unmatched_deltas: deltas,
            });
        }
        Ok(transfers)
    }
