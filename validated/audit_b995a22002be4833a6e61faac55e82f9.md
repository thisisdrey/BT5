### Title
StackerDB sync accepts a valid chunk of any sufficient version as satisfying a specific-version fetch request, letting a malicious replica stall propagation of the true latest chunk - ([File: stackslib/src/net/stackerdb/sync.rs])

### Summary
`StackerDBSync::getchunks_try_finish` treats any `StackerDBChunk` reply from a neighbor as satisfying whichever chunk request is outstanding for that `slot_id`, without ever checking that the returned `slot_version` matches the version that was actually requested (`chunk_request.slot_version`, taken from the neighbor's own advertised inventory). `validate_downloaded_chunk`/`validate_received_chunk` only enforce a floor (`data.slot_version >= expected_version`, the pre-sync baseline) and a ceiling (`max_writes`), never equality with the requested version. This mirrors the CometBFT class of bug: an index/commitment binding that the network trusts implicitly (here, "the version I asked for" vs "the version I got back") is never checked for equality, so a peer can substitute a different, still-validly-signed, payload and have it accepted as if it fulfilled the specific request.

### Finding Description
The sync flow is:
1. `make_chunk_request_schedule` builds a `StackerDBGetChunkData{slot_id, slot_version: remote_version}` for a specific slot, targeting the newest version a neighbor advertised in its `StackerDBChunkInv` [1](#0-0) .
2. `getchunks_begin` sends this exact `StackerDBGetChunkData` (with `slot_id` and `slot_version`) to the selected neighbor [2](#0-1) .
3. `getchunks_try_finish` receives a `StackerDBChunk` reply and calls `validate_downloaded_chunk`, then unconditionally calls `add_downloaded_chunk(naddr, data)` if it validates [3](#0-2) .
4. `validate_downloaded_chunk` just forwards to `PeerNetwork::validate_received_chunk`, which checks size, `expected_versions[slot_id]` as a floor, signer identity, and `max_writes` — but never compares `data.slot_version` to the version that was actually requested from that neighbor [4](#0-3) .
5. `add_downloaded_chunk` then removes the `slot_id` from `chunk_fetch_priorities` regardless of which version was actually delivered, so the sync round considers this slot "handled" for the remainder of the round [5](#0-4) .

Because the requesting node's own `expected_versions` reflect the *pre-sync* local baseline (set once in `getchunksinv_try_finish`, not updated per request) [6](#0-5) , a malicious replica that legitimately owns the requested `slot_id` (i.e., holds the real signer key for that slot) can respond to a request for the latest version `V_new` with an older-but-still-signed-and-still->=baseline chunk `V_old`. The reply passes every check in `validate_received_chunk` (correct signer, size in bounds, version within `[expected_version, max_writes]`) yet is not the version that was actually requested. `add_downloaded_chunk` still consumes the fetch priority for that slot, so the requester stops asking other, honest neighbors for the true latest chunk during that round.

### Impact Explanation
This lets an unprivileged remote peer that is a legitimate signer for one or more StackerDB slots (e.g., a signer node participating in the signer StackerDB used for block-signing coordination) selectively re-serve stale-but-authentic versions of its own slot(s) in place of the newest version, causing honest peers to falsely conclude they've completed the fetch for that slot in the current sync round. This is a version-downgrade / stale-data-served-as-satisfying-request condition analogous to "serving non-canonical state as canonical" and "steering a node off the tip," since it lets an attacker suppress propagation of freshly-signed data (e.g., updated signer messages, block responses) it doesn't want disseminated, without needing any secret beyond its own valid slot key. It does not corrupt other slots' data or forge signatures, but it degrades data freshness/dissemination guarantees that the P2P StackerDB sync protocol is supposed to provide.

### Likelihood Explanation
Likelihood is moderate-to-high in adversarial settings: any registered slot owner (a common role — e.g., an existing signer set member) can exploit this from their own node with no special access, simply by replying to `StackerDBGetChunk` requests for their slot with an older, valid signature instead of their newest data. If they are the only (or preferred) source of a given slot's newest version in a peer's inventory view, they can repeatedly nullify that peer's fetch attempts for that slot across sync rounds.

### Recommendation
In `validate_received_chunk` (or in `getchunks_try_finish`/`validate_downloaded_chunk`), track and check that the returned `data.slot_id` and `data.slot_version` match the specific `StackerDBGetChunkData{slot_id, slot_version}` that was sent to that neighbor for that in-flight request, rejecting (and unpinning) replies that don't match exactly, rather than only enforcing a coarse `>= expected_version` floor.

### Proof of Concept
1. Attacker node registers/owns `slot_id = 5` in a StackerDB instance and has previously written version `10`.
2. It publishes a `StackerDBChunkInv` claiming version `12` for slot 5 (a version it does possess and can sign).
3. An honest peer's `make_chunk_request_schedule` builds `StackerDBGetChunkData{slot_id: 5, slot_version: 12}` targeting the attacker, per `stackslib/src/net/stackerdb/sync.rs:376-400`.
4. On receiving the `StackerDBGetChunk`, the attacker returns a `StackerDBChunk` for slot 5 at version `11` (validly signed, still `>= expected_version` baseline of `10`).
5. `validate_received_chunk` accepts it (size ok, signer ok, `11 >= 10`, `11 <= max_writes`) per `stackslib/src/net/stackerdb/mod.rs:649-717`; `add_downloaded_chunk` removes slot 5 from `chunk_fetch_priorities` per `stackslib/src/net/stackerdb/sync.rs:561-581`.
6. The honest peer never fetches version 12 in this round even though it explicitly requested it and the attacker advertised it, despite no other validation failure being reported.

    pub fn add_downloaded_chunk(&mut self, naddr: NeighborAddress, data: StackerDBChunkData) {
        let slot_id = data.slot_id;
        let _slot_version = data.slot_version;

        if let Some(data_list) = self.downloaded_chunks.get_mut(&naddr) {
            data_list.push(data);
        } else {
            self.downloaded_chunks.insert(naddr.clone(), vec![data]);
        }

        self.chunk_fetch_priorities
            .retain(|(chunk, ..)| chunk.slot_id != slot_id);

        if !self.chunk_fetch_priorities.is_empty() {
            let next_chunk_fetch_priority =
                self.next_chunk_fetch_priority % self.chunk_fetch_priorities.len();
            self.next_chunk_fetch_priority = next_chunk_fetch_priority;
        }

        self.total_stored += 1;
    }

    pub fn validate_received_chunk(
        &self,
        smart_contract_id: &QualifiedContractIdentifier,
        config: &StackerDBConfig,
        data: &StackerDBChunkData,
        expected_versions: &[u32],
    ) -> Result<bool, net_error> {
        // validate -- must not exceed this replica's configured chunk size.
        if (data.data.len() as u64) > config.chunk_size {
            info!(
                "Received StackerDBChunk for {} ID {}, which is oversized: {} bytes (max {} bytes)",
                smart_contract_id,
                data.slot_id,
                data.data.len(),
                config.chunk_size
            );
            return Ok(false);
        }

        // validate -- must be a valid chunk
        let Some(expected_version) = expected_versions.get(data.slot_id as usize) else {
            info!(
                "Received StackerDBChunk for {} ID {}, which is too big ({})",
                smart_contract_id,
                data.slot_id,
                expected_versions.len()
            );
            return Ok(false);
        };

        // validate -- must be signed by the expected author
        let addr = match self
            .stackerdbs
            .get_slot_signer(smart_contract_id, data.slot_id)?
        {
            Some(addr) => addr,
            None => {
                return Ok(false);
            }
        };

        let slot_metadata = data.get_slot_metadata();
        if !slot_metadata.verify(&addr)? {
            info!(
                "StackerDBChunk for {} ID {} is not signed by {}",
                smart_contract_id, data.slot_id, &addr
            );
            return Ok(false);
        }

        // validate -- must be the current or newer version
        if data.slot_version < *expected_version {
            info!(
                "Received StackerDBChunk for {} ID {} version {}, which is stale (expected {})",
                smart_contract_id, data.slot_id, data.slot_version, *expected_version
            );
            return Ok(false);
        }

        // validate -- must not exceed max writes
        if data.slot_version > config.max_writes {
            info!(
                "Write count exceeded for StackerDBChunk for {} ID {} version {} (max is {})",
                smart_contract_id, data.slot_id, data.slot_version, config.max_writes
            );
            return Ok(false);
        }

        Ok(true)
