### Title
Unauthenticated remote shutdown of signer event receiver via bare `/shutdown` POST - (File: libsigner/src/events.rs)

### Summary
`SignerEventReceiver::next_event` treats any HTTP POST to `/shutdown` as authoritative and permanently halts the receiver's `main_loop`, with no verification that the sender is the locally-configured trusted node. Any TCP-reachable attacker can send one unauthenticated request to permanently stop all future signer event delivery (StackerDB chunks, burn blocks, proposal responses).

### Finding Description
In `libsigner/src/events.rs:443-445`, the `/shutdown` branch of `next_event` executes `event_receiver.stop_signal.store(true, Ordering::SeqCst); Err(EventError::Terminated)` purely based on URL match — there is no header, token, or peer-identity check anywhere in the `with_server` closure (`libsigner/src/events.rs:414-458`) before this branch is reached. This is the same code path the legitimate `SignerStopSignaler::send` uses to shut the receiver down (`libsigner/src/events.rs:376-396`), and it works precisely because the wire protocol has no distinguishing secret: any TCP client that can complete an HTTP/1.1 request to the bound socket is functionally indistinguishable from the trusted node. Once `Err(EventError::Terminated)` propagates, `EventReceiver::main_loop` (`libsigner/src/events.rs:284-312`) matches it and unconditionally `break`s out of the loop, printing "Caught termination signal" and returning from `main_loop` — with no code elsewhere respawning or restarting this loop, so the signer's event-intake thread ends permanently until the signer process itself is restarted.

### Impact Explanation
A single unauthenticated request permanently disables the signer's HTTP event intake, meaning the signer will no longer receive `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, or `/new_block` events from its associated Stacks node. This is a remote, unauthenticated, single-message denial of service against the signer's runloop — matching the "Critical: remote crash/unauthenticated DoS from few messages" category, since it silently and durably removes the signer from block-signing operation without any crash or log alarm distinguishable from a normal shutdown.

### Likelihood Explanation
The only precondition is TCP reachability to the signer's event-receiver bind address/port, which the node itself connects to over plain HTTP with no authentication scheme in this protocol. The attack requires a single crafted HTTP POST with no body and no special headers, is trivially repeatable, and requires no privileged role, secret, or prior state.

### Recommendation
Add an authentication mechanism to the event-receiver HTTP endpoint (e.g., a shared secret/token configured between the node and signer, checked before acting on `/shutdown` and other control/data endpoints) or bind the receiver to a loopback-only address and have the stop signal be triggered via an in-process/local-only mechanism rather than a plaintext, unauthenticated `/shutdown` POST reachable from the network.

### Proof of Concept
1. In a test module for `libsigner/src/events.rs`, create a `SignerEventReceiver::<SomeT>::new(false)`, call `bind` on `127.0.0.1:0` to get a free port, and spawn `main_loop` (or repeatedly call `next_event`) in a thread, with a consumer channel registered via `add_consumer`.
2. From the test's main thread, open a raw `TcpStream::connect` to the bound address and write the literal bytes `"POST /shutdown HTTP/1.1\r\nHost: 127.0.0.1\r\nConnection: close\r\nContent-Length: 0\r\n\r\n"` — no auth header.
3. Assert `receiver.is_stopped()` becomes `true` shortly after.
4. Send a subsequent legitimate `/stackerdb_chunks` POST with a valid JSON `StackerDBChunksEvent` body to the same address, and assert the consumer channel's `recv_timeout` never receives it, proving the receiver is permanently down. [1](#0-0) [2](#0-1) [3](#0-2)

                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);

                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));

                process_event::<T, StackerDBChunksEvent>(request)
