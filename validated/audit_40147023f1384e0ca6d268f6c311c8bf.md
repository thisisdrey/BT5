### Title
`MetAirdrop` recipients can front-run reward revocation or fund recovery to claim unclaimed MET - (File: `contracts/utils/RecurringAirdrop.sol`)

### Summary
`RecurringAirdrop.claim()` permits any eligible recipient to claim their cumulative allocation while the current `merkleRoot` remains active, while the governor can subsequently invalidate outstanding proofs through `updateMerkleRoot()` or remove the backing tokens through `TokenHolder.sweep()`. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
A recipient observing a pending governor transaction that changes `merkleRoot`, disables future claims, or sweeps the contract's `MET` balance can submit `claim(amount_, proof_)` first. [4](#0-3)   
The claim verifies against the still-active root, increments `claimed[msg.sender]`, and transfers the reward before the privileged transaction executes. [5](#0-4)   
For `MetAirdrop`, `_transferReward()` either sends `MET` directly after the lock period or locks it into `esMET` for the recipient; in both cases the claimed allocation is no longer recoverable by the airdrop contract. [6](#0-5)   
The governor-only checks do not prevent this because the attacker only calls the public `claim()` function before the privileged state transition. [7](#0-6) 

### Impact Explanation
A recipient can preserve an allocation that governance intends to revoke and receive unclaimed `MET` or locked `esMET` before the revocation or sweep transaction lands. [8](#0-7) [9](#0-8)   
If a sweep executes first, the same recipient's claim can fail because the backing `MET` has already been transferred to the governor-selected recipient. [3](#0-2) 

### Likelihood Explanation
The attack requires a funded airdrop contract, a valid unused Merkle proof, and a publicly visible governor transaction. [10](#0-9)   
`nonReentrant` does not prevent the race because the claim and privileged revocation are separate transactions. [1](#0-0) 

### Recommendation
There is no fully trustless way to prevent an eligible recipient from claiming before a later revocation transaction. If retroactive revocation is required, claims should become effective only after governance finalizes the allocation, or the claim transaction should require a current distribution authorization that cannot be exercised while a revocation is pending. Operationally, privileged root updates and sweeps can be submitted through private transaction channels, but this only reduces mempool visibility rather than eliminating the underlying race.

```ts
// test/MetAirdrop.frontrun.test.ts
import {expect} from 'chai'
import {ethers} from 'hardhat'
import MerkleTree from 'merkletreejs'
import {randomBytes} from 'crypto'
import {loadFixture, time} from '@nomicfoundation/hardhat-network-helpers'
import {parseEther} from 'ethers/lib/utils'
import {setTokenBalance} from './helpers'

const leaf = (account: string, amount: string) =>
  Buffer.from(
    ethers.utils
      .solidityKeccak256(['address', 'uint256'], [account, amount])
      .slice(2),
    'hex'
  )

const treeFor = (rewards: Record<string, string>) =>
  new MerkleTree(
    Object.entries(rewards).map(([account, amount]) =>
      leaf(ethers.utils.getAddress(account), amount)
    ),
    ethers.utils.keccak256,
    {sortPairs: true}
  )

describe('MetAirdrop claim frontrun', function () {
  async function fixture() {
    const [governor, alice, bob] = await ethers.getSigners()

    const MetAirdrop = await ethers.getContractFactory('MetAirdrop', governor)
    const airdrop = await MetAirdrop.deploy()
    await airdrop.deployed()

    const met = await ethers.getContractAt('IERC20', await airdrop.MET(), governor)

    const amount = parseEther('1').toString()
    const initialTree = treeFor({
      [alice.address]: amount,
      [bob.address]: parseEther('2').toString(),
    })

    await airdrop.updateMerkleRoot(
      initialTree.getHexRoot(),
      `0x${randomBytes(32).toString('hex')}`
    )

    await setTokenBalance(met.address, airdrop.address, parseEther('1000'))

    return {governor, alice, bob, airdrop, met, amount, initialTree}
  }

  it('lets a recipient claim before revocation or sweeping', async function () {
    const {governor, alice, bob, airdrop, met, amount, initialTree} =
      await loadFixture(fixture)

    // Wait until MetAirdrop pays MET directly instead of locking into esMET.
    await time.increase(8 * 24 * 60 * 60)

    // Alice sees a pending revocation and submits claim first.
    const proof = initialTree.getHexProof(leaf(alice.address, amount))
    await expect(airdrop.connect(alice).claim(amount, proof))
      .to.changeTokenBalance(met, alice, amount)

    // The governor transaction then replaces the distribution with a Bob-only tree.
    const bobOnlyTree = treeFor({[bob.address]: parseEther('2').toString()})
    await airdrop
      .connect(governor)
      .updateMerkleRoot(
        bobOnlyTree.getHexRoot(),
        `0x${randomBytes(32).toString('hex')}`
      )

    // The old allocation is no longer claimable, but Alice already received it.
    await expect(
      airdrop.connect(alice).claim(amount, proof)
    ).to.be.revertedWithCustomError(airdrop, 'InvalidProof')
  })
})
```

```text
    function claim(uint256 amount_, bytes32[] calldata proof_) external nonReentrant {
        if (merkleRoot == bytes32(0)) revert NothingToClaim();

        uint256 _claimable = amount_ - claimed[msg.sender];
        if (_claimable == 0) revert NothingToClaim();

        claimed[msg.sender] += _claimable;
```
