### Title
Expired CA certificates are added to the trust pool before expiry validation completes, allowing an expired CA to remain trusted for signature verification - (File: cert/ca_pool.go)

### Summary
`CAPool.AddCA` mutates the trust store (`ncp.CAs[sum] = cc`) before it checks whether the CA certificate is expired. The `ErrExpired` error is only returned *after* the certificate has already been inserted into the map that `verify()`/`GetCAForCert()` consult for all subsequent certificate validation. This mirrors the reported bug class: a state mutation is performed before the validation math/check that is supposed to gate it, so the "invalid" result still poisons state that downstream logic trusts.

### Finding Description
`AddCA` computes the fingerprint, builds a `CachedCertificate`, and unconditionally stores it in `ncp.CAs[sum]` before ever checking `c.Expired(time.Now())`: [1](#0-0) 

```
func (ncp *CAPool) AddCA(c Certificate) error {
	...
	ncp.CAs[sum] = cc          // <-- mutation happens first

	if c.Expired(time.Now()) {
		return fmt.Errorf("%s: %w", c.Name(), ErrExpired)   // <-- check happens after
	}
	return nil
}
```

`NewCAPoolFromPEMReader` calls `AddCA` for every CA in the bundle, and when it sees `ErrExpired` it deliberately `continue`s the loop rather than aborting, ultimately returning the built pool together with `ErrExpired`: [2](#0-1) 

The doc comment even states: *"If the pool contains any expired certificates, an ErrExpired will be returned along with the pool. The caller must handle any such errors."* This puts the entire correctness burden on callers to discard the returned pool on any non-nil error — but the pool already contains the expired CA in `CAs` regardless of what the caller does with the error, because the map write happened unconditionally in `AddCA` before the expiry check.

Every subsequent trust decision (`verify`, `GetCAForCert`, `VerifyCertificate`, `VerifyCachedCertificate`) looks the CA up directly from `ncp.CAs[issuer]` with no additional gate on the CA's own validity independent of what `AddCA` decided to store: [3](#0-2) [4](#0-3) 

`verify()` does check `signer.Certificate.Expired(now)` at validation time (line ~224), which is the correct defensive re-check and is the main mitigating factor here — so an already-expired CA is still rejected at verification time via that separate check. However, this is a redundant safety net, not a structural fix: the pool state itself is inconsistent with the error contract, and any code path that adds a CA and doesn't immediately abort/discard the pool on error (matching the documented but easily-missed contract) leaves an untrusted/expired root wired into `ncp.CAs` for the lifetime of the pool object, exactly the order-of-operations flaw described in the report (mutate state, then compute/report the validity result).

### Impact Explanation
If a caller of `AddCA`/`AddCAFromPEM`/`NewCAPoolFromPEMReader` treats a non-fatal-looking `ErrExpired` return loosely (e.g. logs a warning and continues using the returned pool, which is exactly what the API's own doc comment invites: "the caller must handle any such errors" implies the pool is still usable), the expired CA is fully installed in `ncp.CAs` and will be returned by `GetCAForCert` for any certificate it issued. The only remaining barrier against accepting certificates chained to that expired root is the `signer.Certificate.Expired(now)` check inside `verify()`. Any refactor, alternate call path, or future change that reads `ncp.CAs` directly (rather than going through `verify()`) would silently trust an expired CA, since the mutation already happened unconditionally. This is a certificate/CA-pool trust-boundary defect reachable by any attacker holding a certificate signed by a CA that has since expired but was reloaded/re-added to a running pool (e.g. via SIGHUP config reload flows that call these constructors).

### Likelihood Explanation
Moderate-to-low on its own because the redundant expiry check in `verify()` currently blocks the most direct exploitation path (an expired signer is still rejected there). The likelihood is elevated by the fact that the public API contract ("returned along with the pool... caller must handle") actively encourages callers to keep using the returned, already-polluted pool after seeing an error, and by the fact that nothing in `AddCA` prevents the entry from being written before the check — a single removal or bypass of the secondary check in `verify()` (or any new code path that queries `ncp.CAs` directly for trust decisions) would immediately become an authentication bypass with no further changes required.

### Recommendation
Perform the `c.Expired(time.Now())` check before writing to `ncp.CAs[sum]`, so that an expired CA is never inserted into the trust map in the first place:
```go
func (ncp *CAPool) AddCA(c Certificate) error {
	if !c.IsCA() { ... }
	if !c.CheckSignature(c.PublicKey()) { ... }

	sum, err := c.Fingerprint()
	if err != nil { ... }

	if c.Expired(time.Now()) {
		return fmt.Errorf("%s: %w", c.Name(), ErrExpired)
	}

	cc := &CachedCertificate{...}
	ncp.CAs[sum] = cc
	return nil
}
```
If callers rely on expired CAs still being enumerable (e.g. for diagnostics), track them in a separate, clearly-untrusted structure rather than the live `CAs` trust map, and make `verify()`'s in-band expiry re-check a defense-in-depth measure rather than the sole safeguard.

### Proof of Concept
1. Construct a CA certificate `ca` that is already expired (`NotAfter` in the past).
2. Call `pool.AddCA(ca)` (or `NewCAPoolFromPEMReader` with a bundle containing it).
3. Observe that `pool.CAs[fingerprint(ca)]` is populated with the expired CA even though `AddCA`/`NewCAPoolFromPEMReader` returned `ErrExpired`.
4. Any code path that inspects `pool.CAs` directly (bypassing `verify()`'s redundant `signer.Certificate.Expired(now)` check) — such as tooling, future refactors, or `GetCAForCert` consumers that skip full `verify()` — would treat certificates signed by this expired CA as trusted. // If the pool contains any expired certificates, an ErrExpired will be

	return NewCAPoolFromPEMReader(bytes.NewReader(caPEMs))
}

// NewCAPoolFromPEMReader will create a new CA pool from the provided reader.
// The reader must contain a PEM-encoded set of nebula certificates.
func NewCAPoolFromPEMReader(r io.Reader) (*CAPool, error) {
	pool := NewCAPool()

	var expired bool

	scanner := bufio.NewScanner(r)
	scanner.Split(SplitPEM)

	for scanner.Scan() {
		pemBytes := scanner.Bytes()

		block, rest := pem.Decode(pemBytes)
		if len(bytes.TrimSpace(rest)) > 0 {
			return nil, ErrInvalidPEMBlock
		}
		if block == nil {
			return nil, ErrInvalidPEMBlock
		}

		c, err := unmarshalCertificateBlock(block)
		if err != nil {
			return nil, err
		}

		err = pool.AddCA(c)
		if errors.Is(err, ErrExpired) {
			expired = true
			continue
		} else if err != nil {
			return nil, err
		}
	}
	if err := scanner.Err(); err != nil {
		return nil, ErrInvalidPEMBlock
	}

	if expired {
		return pool, ErrExpired
	}

// AddCA verifies a Nebula CA certificate and adds it to the pool.
func (ncp *CAPool) AddCA(c Certificate) error {
	if !c.IsCA() {
		return fmt.Errorf("%s: %w", c.Name(), ErrNotCA)
	}

	if !c.CheckSignature(c.PublicKey()) {
		return fmt.Errorf("%s: %w", c.Name(), ErrNotSelfSigned)
	}

	sum, err := c.Fingerprint()
	if err != nil {
		return fmt.Errorf("could not calculate fingerprint for provided CA; error: %w; %s", err, c.Name())
	}

	cc := &CachedCertificate{
		Certificate:    c,
		Fingerprint:    sum,
		InvertedGroups: make(map[string]struct{}),
	}

	for _, g := range c.Groups() {
		cc.InvertedGroups[g] = struct{}{}
	}

	ncp.CAs[sum] = cc

	if c.Expired(time.Now()) {
		return fmt.Errorf("%s: %w", c.Name(), ErrExpired)
	}

	return nil
}

func (ncp *CAPool) verify(c Certificate, now time.Time, certFp string, signerFp string) (*CachedCertificate, error) {
	if ncp.IsBlocklisted(certFp) {
		return nil, ErrBlockListed
	}

	signer, err := ncp.GetCAForCert(c)
	if err != nil {
		return nil, err
	}

	if signer.Certificate.Curve() != c.Curve() {
		return nil, ErrCurveMismatch
	}

	if signer.Certificate.Expired(now) {
		return nil, ErrRootExpired
	}

	if c.Expired(now) {
		return nil, ErrExpired
	}

	// If we are checking a cached certificate then we can bail early here
	// Either the root is no longer trusted or everything is fine
	if len(signerFp) > 0 {
		if signerFp != signer.Fingerprint {
			return nil, ErrFingerprintMismatch
		}
		return signer, nil
	}
	if !c.CheckSignature(signer.Certificate.PublicKey()) {
		return nil, ErrSignatureMismatch
	}

	err = CheckCAConstraints(signer.Certificate, c)
	if err != nil {
		return nil, err
	}

	return signer, nil

// GetCAForCert attempts to return the signing certificate for the provided certificate.
// No signature validation is performed
func (ncp *CAPool) GetCAForCert(c Certificate) (*CachedCertificate, error) {
	issuer := c.Issuer()
	if issuer == "" {
		return nil, fmt.Errorf("no issuer in certificate")
	}

	signer, ok := ncp.CAs[issuer]
	if ok {
		return signer, nil
	}

	return nil, ErrCaNotFound
}
