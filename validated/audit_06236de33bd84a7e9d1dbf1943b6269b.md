Audit Report

## Title
Value sent to stateless built-in precompiles (ECRecover, Sha256, Identity, Modexp, Bn128*, Blake2F) is permanently locked - (File: `substrate/frame/revive/src/exec.rs`)

## Summary
`Stack::run`/`new_frame` in `substrate/frame/revive/src/exec.rs` unconditionally transfers `frame.value_transferred` to the destination account for every non-delegate call before dispatching to the precompile logic. Built-in precompiles declared with `HAS_CONTRACT_INFO = false` (e.g. `Identity`, `ECRecover`, `Sha256`, `Ripemd160`, `Modexp`, `Bn128Add/Mul/Pairing`, `Blake2F`) only implement pure computational `call` entrypoints that never read, forward, or refund the transferred value, so any native balance routed to these fixed addresses becomes permanently unspendable.

## Finding Description
The transfer happens regardless of destination type: [1](#0-0) 

The pallet's own documentation for `HAS_CONTRACT_INFO = false` confirms that no account or state is created to represent the precompile, meaning the balance transfer still lands on the underlying `AccountId` derived from the fixed address, with nothing to act on it: [2](#0-1) 

Only precompiles with `HAS_CONTRACT_INFO = true` receive special account bookkeeping (minted ED, consumer reference) to represent "real" state — this is not applied to stateless precompiles: [3](#0-2) 

Concretely, the `Identity` precompile (fixed address `0x4`, `HAS_CONTRACT_INFO = false`) only echoes its input bytes back and never touches the transferred value: [4](#0-3) 

The `Precompile::call` default entrypoint (used for `HAS_CONTRACT_INFO = false` precompiles) has no value-handling logic whatsoever: [5](#0-4) 

There is no guard anywhere in the transfer/dispatch path in `exec.rs` that checks whether the destination precompile is stateless and rejects non-zero value before the unconditional `transfer_from_origin` call. This confirms the claim's described root cause and code path accurately.

## Impact Explanation
Since these precompile addresses (`0x1`–`0x9`) are fixed, code-less, and have no controlling private key, any value transferred to them via `call{value}` or an equivalent EVM `CALL` has no path to be moved back out — no extrinsic, precompile logic, or governance sweep exists in this codebase to reclaim it. This is a legitimate instance of "permanent user-fund lock," which is an explicitly recognized impact category in the Polkadot SDK impact gate.

## Likelihood Explanation
These are the same well-known low addresses used across all EVM-compatible chains (matching Ethereum precompile conventions), making them a realistic target for accidental sends: copy-pasted contract logic, computed/derived address collisions, or simple user/tooling mistakes. No privileged actor, governance action, or malicious peer is required — the loss occurs through ordinary use of a public entrypoint (`call`/EVM `CALL`) by any unprivileged account, and is deterministically repeatable.

## Recommendation
Apply the same guard already used for `PointEval` (which rejects the call outright: `Err(<CrateError<T>>::UnsupportedPrecompileAddress.into())`) uniformly to all stateless built-in precompiles (`HAS_CONTRACT_INFO = false`) when `value_transferred` is non-zero, rejecting the call instead of performing a silent, unrecoverable balance transfer. Alternatively, restructure `Stack::run`/`new_frame` so the value transfer occurs only after confirming the destination is capable of holding or using it.

## Proof of Concept
1. Fund an account/contract with native balance.
2. Issue an EVM `CALL` (or `pallet-revive`'s `call` extrinsic) to address `0x0000...0004` (`Identity` precompile) with non-zero `value` and arbitrary input data.
3. As shown by the pallet's existing test pattern asserting `Pallet::<Test>::evm_balance(&precompile_addr)` reflects the transferred amount post-call, the value is retained at the precompile's address.
4. No subsequent call, extrinsic, or governance action exists in the codebase to move that balance out — the funds are permanently locked.

pub struct Identity<T>(PhantomData<T>);

impl<T: Config> PrimitivePrecompile for Identity<T> {
	type T = T;
	const MATCHER: BuiltinAddressMatcher = BuiltinAddressMatcher::Fixed(NonZero::new(0x4).unwrap());
	const HAS_CONTRACT_INFO: bool = false;

	fn call(
		_address: &[u8; 20],
		input: Vec<u8>,
		env: &mut impl Ext<T = Self::T>,
	) -> Result<Vec<u8>, Error> {
		env.frame_meter_mut()
			.charge_weight_token(RuntimeCosts::Identity(input.len() as _))?;
		Ok(input)
	}
