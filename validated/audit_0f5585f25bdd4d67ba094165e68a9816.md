### Title
Unauthenticated remote `/shutdown` request permanently terminates the signer's event-receiver main loop - (File: libsigner/src/events.rs)

### Finding Description
`next_event`'s dispatch logic treats any POST to `/shutdown` as authoritative: `event_receiver.stop_signal.store(true, Ordering::SeqCst); Err(EventError::Terminated)` [1](#0-0) , with no check that the request originated from the legitimate in-process `SignerStopSignaler` rather than an arbitrary TCP client. `SignerStopSignaler::send` itself is just a plain `TcpStream::connect` followed by a raw HTTP POST with a fixed body and no credential, secret, or signature of any kind [2](#0-1) . `EventReceiver::main_loop` treats `EventError::Terminated` as an unconditional break condition, ending event ingestion permanently [3](#0-2) . The `HttpServer` is bound via `HttpServer::http(listener)` at whatever socket address the operator configures as `endpoint` in the signer's TOML config (e.g. `endpoint = "[::1]:30000"` in the test config, but this is admin-controlled and could be `0.0.0.0`) [4](#0-3) [5](#0-4) . No authentication mechanism (no shared secret, no source-IP allowlist, no token) gates the `/shutdown` route or any other route on this listener before triggering termination.

### Impact Explanation
Any party capable of opening a TCP connection to the signer's bound event-listener address can send a single crafted `POST /shutdown` and cause the signer's `main_loop` to observe `EventError::Terminated` and break, permanently halting event ingestion (block proposals, StackerDB chunk events, burn-block/new-block events) until the process is restarted. This matches the Critical "remote crash/unauthenticated DoS from few messages" category, since it is a single HTTP request causing permanent denial of the signer's core function.

### Likelihood Explanation
This endpoint is architecturally intended for loopback/internal use — the `SignerStopSignaler` connects to `self.local_addr` from within the same process to wake up its own blocking thread — but nothing in the code enforces that the connection is local or that the caller is trusted. The exposure to a genuinely remote unprivileged attacker depends entirely on the operator's `endpoint` binding configuration. In the shipped test configs it's bound to `[::1]` (loopback), which would not be remotely reachable by an external attacker; however, the code contains no defense-in-depth check, so if an operator binds to a non-loopback interface (as the `metrics_endpoint = "0.0.0.0:9090"` example in the same config shows is a real-world pattern for this project), the DoS becomes trivially remotely exploitable with zero cost and full repeatability. I was not able to fully confirm from the available index whether stock/documented deployment guidance forces loopback-only binding for `endpoint` (as opposed to `metrics_endpoint`), so the exact remote-reachability precondition in default/production deployments remains partially unverified.

### Recommendation
Require some form of caller authentication or provenance verification on the `/shutdown` route (and ideally on all POST routes) — e.g., a shared secret/token known only to the in-process stop signaler, verifying the request originates from `127.0.0.1`/`::1`, or replacing the raw-HTTP self-wakeup with an in-process channel/condvar so no network path to `/shutdown` needs to exist at all.

### Proof of Concept
```rust
// libsigner/src/events.rs (test) — attacker without any credential shuts down the receiver
#[test]
fn attacker_can_shutdown_event_receiver() {
    let mut receiver: SignerEventReceiver<StacksBlockEvent> = SignerEventReceiver::new(false);
    let addr = receiver.bind("127.0.0.1:0".parse().unwrap()).unwrap();

    let handle = std::thread::spawn(move || {
        let mut stream = std::net::TcpStream::connect(addr).unwrap(); // "attacker" client
        let body = "attacker-controlled";
        let req = format!(
            "POST /shutdown HTTP/1.1\r\nHost: {addr}\r\nConnection: close\r\nContent-Length: {}\r\n\r\n{}",
            body.len(), body
        );
        use std::io::Write;
        stream.write_all(req.as_bytes()).unwrap();
    });
    handle.join().unwrap();

    let result = receiver.next_event();
    assert!(matches!(result, Err(EventError::Terminated)));
    assert!(receiver.is_stopped());
}
```
This demonstrates that no credential is presented, yet `next_event` reaches `Err(EventError::Terminated)` at [1](#0-0) , which in `main_loop` causes an unconditional `break` at [6](#0-5) .

    fn main_loop(&mut self) {
        loop {
            if self.is_stopped() {
                info!("Event receiver stopped");
                break;
            }
            let next_event = match self.next_event() {
                Ok(event) => event,
                Err(EventError::UnrecognizedEvent(..)) => {
                    // got an event that we don't care about (not a problem)
                    continue;
                }
                Err(EventError::Terminated) => {
                    // we're done
                    info!("Caught termination signal");
                    break;
                }
                Err(e) => {
                    warn!("Failed to receive next event: {:?}", &e);
                    continue;
                }
            };
            if !self.forward_event(next_event) {
                info!("Failed to forward event");
                break;
            }
        }
        info!("Event receiver main loop exit");
    }
