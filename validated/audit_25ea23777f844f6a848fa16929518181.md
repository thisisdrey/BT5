### Title
Unbounded array allocation from unchecked, user-controlled length field in TVM precompiled-contract helpers - (File: actuator/src/main/java/org/tron/core/vm/PrecompiledContracts.java)

### Summary
`PrecompiledContracts.extractBytes32Array` and `extractBytesArray` read a length value directly out of attacker-supplied call data and immediately allocate a Java array of that size, with no upper bound check against the actual size of the call data or any energy-metered limit. This mirrors the weixin4j CWE-1325 "Improperly Controlled Sequential Memory Allocation" pattern (allocating memory proportional to an untrusted length field before validating it against real bounds).

### Finding Description
`extractBytes32Array` and `extractBytesArray` compute `len` from a `DataWord` taken from the ABI-encoded call data via `intValueSafe()`, and then allocate `new byte[len][]` before any bound is enforced: [1](#0-0) 

`intValueSafe()` returns any value up to `Integer.MAX_VALUE` for a 4-byte-or-fewer word — it only clamps to `Integer.MAX_VALUE` on true overflow, it does not clamp to any sane bound related to the actual `data.length`: [2](#0-1) 

Because the "count" word is fully attacker-controlled and independent from the real length of `data` (an attacker can put an arbitrary 32-byte integer such as `0x7fffffff` in that word slot while sending a much shorter payload), `new byte[len][]` can attempt to allocate an array of ~2^31 object references (many gigabytes) before the subsequent loop even touches `data`, which would otherwise fail with an `ArrayIndexOutOfBoundsException`. The allocation happens unconditionally, ahead of any content/length cross-check, exactly the "sequential/unchecked allocation before validation" root cause described in the advisory.

### Impact Explanation
Any account that can submit a transaction invoking the TVM `CALL` opcode into the precompiled-contract address that uses these helpers (multi-signature validation precompiles) can trigger a multi-gigabyte array allocation attempt in a single call. This can throw `OutOfMemoryError` inside the node's JVM, which is not narrowly scoped exception handling for allocation failures — this can crash or destabilize the full node process handling the transaction, i.e., a node crash/halt caused by a single unprivileged transaction, which is explicitly an accepted impact class.

### Likelihood Explanation
The precompiled contracts in `PrecompiledContracts.java` are reachable from any TVM contract execution via `CALL`/`STATICCALL` to a fixed precompile address — this is available to any unprivileged contract deployer or caller who can construct calldata with a forged length word, requiring no special permission, and is directly reachable from a single broadcast transaction.

### Recommendation
Bound `len` extracted in `extractBytes32Array`/`extractBytesArray`/`extractSigArray` against a sane maximum (e.g., derived from the real remaining `data.length` or a fixed protocol maximum like `MAX_SIZE`) before allocating the array, and reject the call (return `Pair.of(false, ...)`) if the declared count is inconsistent with the actual calldata size, mirroring the bound checks already present elsewhere (e.g., `MAX_SIZE`/`isValidAbiEncoding`).

### Proof of Concept
Construct calldata for a precompiled contract that calls `extractBytesArray`/`extractBytes32Array` with:
- A valid ABI header so `isValidAbiEncoding` (if enforced) passes structurally.
- The length word at the expected `offset` set to a large value (e.g. `0x7fffffff`), while the actual remaining `data` array is short.

Invoking this precompile once from a contract call causes `new byte[0x7fffffff][]` to execute, attempting to allocate roughly 8–16 GB (4 or 8 bytes per reference depending on JVM pointer compression) in a single step, before any per-element bounds check runs against the true payload size.   private static byte[][] extractBytes32Array(DataWord[] words, int offset) {
    int len = words[offset].intValueSafe();
    byte[][] bytes32Array = new byte[len][];
    for (int i = 0; i < len; i++) {
      bytes32Array[i] = words[offset + i + 1].getData();
    }
    return bytes32Array;
  }

  private static byte[][] extractBytesArray(DataWord[] words, int offset, byte[] data) {
    if (offset > words.length - 1) {
      return new byte[0][];
    }
    int len = words[offset].intValueSafe();
    byte[][] bytesArray = new byte[len][];
    for (int i = 0; i < len; i++) {
      int bytesOffset = words[offset + i + 1].intValueSafe() / WORD_SIZE;
      int bytesLen = words[offset + bytesOffset + 1].intValueSafe();
      bytesArray[i] = extractBytes(data, (bytesOffset + offset + 2) * WORD_SIZE,
          bytesLen);
    }
    return bytesArray;
  }
