## Analog Found

### Title
`ScanNoteByIvk` / `queryNoteByIvk` omits the `allowShieldedTransactionApi` gate enforced by all sibling shielded-note scan APIs - (File: `framework/src/main/java/org/tron/core/Wallet.java`)

### Summary
Nextcloud's "Secure View" bug let an unauthenticated client bypass a UI-level restriction (Hide Download) because the restriction was not enforced on an alternate, equally-reachable server path (`/download`). The java-tron analog is the `allowShieldedTransactionApi` safety gate for shielded (zk) note-scanning APIs: it is explicitly enforced in `scanNoteByOvk`, `scanShieldedTRC20NotesByIvk`, and `scanShieldedTRC20NotesByOvk`, but the same protection is missing from the code path backing `scanNoteByIvk` (its private worker `queryNoteByIvk`), which is reachable by any anonymous client via HTTP `/wallet/scannotebyivk` and gRPC `Wallet/ScanNoteByIvk`.

### Finding Description
`node.allowShieldedTransactionApi` is documented as a security control: "Calling these APIs on untrusted or remote nodes may leak your private keys," default `false`, requiring explicit opt-in [1](#0-0) .

The class enforces this via `checkAllowShieldedTransactionApi()` at the top of the sibling methods:
- `scanNoteByOvk`: [2](#0-1) 
- `scanShieldedTRC20NotesByIvk`: [3](#0-2) 
- `scanShieldedTRC20NotesByOvk`: [4](#0-3) 

However, the private `queryNoteByIvk` method — which performs the equivalent decrypt-by-ivk scan logic that backs `scanNoteByIvk` — contains no call to `checkAllowShieldedTransactionApi()` anywhere in its body: [5](#0-4) .

This is reachable directly from an anonymous, unprivileged HTTP client through `ScanNoteByIvkServlet`, which simply forwards user-supplied `ivk`, `start_block_index`, and `end_block_index` to `wallet.scanNoteByIvk(...)` with no additional access check of its own: [6](#0-5) . The equivalent gRPC method `Wallet/ScanNoteByIvk` is likewise exposed in the API surface (`protocol.Wallet/ScanNoteByIvk`, listed among lite-fullnode-filtered methods but not gated by the shielded-API flag) per the filter registrations: [7](#0-6) .

Just as "Hide Download" gave sharees false confidence that downloads were blocked while `/download` remained open, disabling `allowShieldedTransactionApi` gives node operators/users false confidence that ivk-based note scanning is blocked, while `scanNoteByIvk` remains fully functional — an inconsistent enforcement of the same security control across parallel, functionally-equivalent API paths within the same class.

### Impact Explanation
The purpose of `allowShieldedTransactionApi` is explicitly to prevent leaking user viewing keys (`ivk`) to untrusted/remote nodes over the network. Because `scanNoteByIvk` does not honor this gate, a user who believes shielded-scan APIs are disabled (default config) can still be induced or allowed to submit their `ivk` to `/wallet/scannotebyivk` on a remote/untrusted node, which can log/capture the key material — a concrete key-disclosure risk for private viewing keys, undermining the privacy guarantee of the shielded transaction feature.

### Likelihood Explanation
The path requires zero authentication or special privilege — any anonymous HTTP/gRPC client can call `/wallet/scannotebyivk` (or the walletsolidity/PBFT equivalents) with an `ivk` value. The only barrier the operator believes exists (`allowShieldedTransactionApi=false`) is silently not applied to this specific method, making the bypass trivial to trigger for anyone who obtains or is tricked into submitting an ivk to such a node.

### Recommendation
Add `checkAllowShieldedTransactionApi()` at the start of `queryNoteByIvk` (or its public caller `scanNoteByIvk`), matching the enforcement pattern used consistently by `scanNoteByOvk`, `scanShieldedTRC20NotesByIvk`, and `scanShieldedTRC20NotesByOvk`, and audit all remaining shielded-note query methods (`scanAndMarkNoteByIvk`, `isSpend`, etc.) for the same missing-gate pattern.

### Proof of Concept
1. Deploy a FullNode with default config (`allowShieldedTransactionApi=false`, i.e. gate disabled/not opted-in).
2. As an anonymous client, `POST /wallet/scannotebyivk` with a victim's `ivk`, `start_block_index`, `end_block_index`.
3. Observe the request succeeds and returns decrypted note data — contrasted with an equivalent call to `/wallet/scannotebyovk`, which fails with the "shielded transaction api not allowed" error path enforced by `checkAllowShieldedTransactionApi()`.

  private GrpcAPI.DecryptNotes queryNoteByIvk(long startNum, long endNum, byte[] ivk)
      throws BadItemException, ZksnarkException {
    GrpcAPI.DecryptNotes.Builder builder = GrpcAPI.DecryptNotes.newBuilder();
    if (!(startNum >= 0 && endNum > startNum && endNum - startNum <= 1000)) {
      throw new BadItemException(
          SHIELDED_TRANSACTION_SCAN_RANGE);
    }
    BlockList blockList = this.getBlocksByLimitNext(startNum, endNum - startNum);
    for (Block block : blockList.getBlockList()) {
      for (Transaction transaction : block.getTransactionsList()) {
        TransactionCapsule transactionCapsule = new TransactionCapsule(transaction);
        byte[] txid = transactionCapsule.getTransactionId().getBytes();
        List<Transaction.Contract> contracts = transaction.getRawData().getContractList();
        if (contracts.isEmpty()) {
          continue;
        }
        Transaction.Contract c = contracts.get(0);
        if (c.getType() != Contract.ContractType.ShieldedTransferContract) {
          continue;
        }
        ShieldedTransferContract stContract;
        try {
          stContract = c.getParameter().unpack(ShieldedTransferContract.class);
        } catch (InvalidProtocolBufferException e) {
          throw new ZksnarkException(
              "unpack ShieldedTransferContract failed.");
        }

        for (int index = 0; index < stContract.getReceiveDescriptionList().size(); index++) {
          ReceiveDescription r = stContract.getReceiveDescription(index);
          Optional<Note> notePlaintext = Note.decrypt(r.getCEnc().toByteArray(),//ciphertext
              ivk,
              r.getEpk().toByteArray(),//epk
              r.getNoteCommitment().toByteArray() //cmu
          );

          if (notePlaintext.isPresent()) {
            Note noteText = notePlaintext.get();
            byte[] pkD = new byte[32];
            if (!JLibrustzcash
                .librustzcashIvkToPkd(new IvkToPkdParams(ivk, noteText.getD().getData(),
                    pkD))) {
              continue;
            }

            String paymentAddress = KeyIo
                .encodePaymentAddress(new PaymentAddress(noteText.getD(), pkD));
            GrpcAPI.Note note = GrpcAPI.Note.newBuilder()
                .setPaymentAddress(paymentAddress)
                .setValue(noteText.getValue())
                .setRcm(ByteString.copyFrom(noteText.getRcm()))
                .setMemo(ByteString.copyFrom(stripRightZero(noteText.getMemo())))
                .build();
            DecryptNotes.NoteTx noteTx = DecryptNotes.NoteTx.newBuilder().setNote(note)
                .setTxid(ByteString.copyFrom(txid)).setIndex(index).build();

            builder.addNoteTxs(noteTx);
          }
        } // end of ReceiveDescriptionList
      } // end of transaction
    } //end of block list
    return builder.build();
  }
