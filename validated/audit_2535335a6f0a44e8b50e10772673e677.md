# No vulnerability found for this question.

The behavior described is the intended design, not a bug. In `action_stake` (`runtime/runtime/src/actions.rs:59-110`), when `stake.stake` is between 0 and `account.locked()`, `increment` is 0 via `saturating_sub`, so `account.amount()`/`account.locked()` are left untouched and only `result.validator_proposals` gets the lower `stake.stake` value [1](#0-0) . This is exactly how NEAR's staking model works: "the locked balance can only increase" on a `Stake` action, and actual unstaking/decreasing is deferred to the epoch boundary [2](#0-1) .

The reconciliation happens in `update_validator_accounts` (`runtime/runtime/src/lib.rs:1663-1759`), which explicitly enforces the invariant `account.locked() >= max_of_stakes` (fatal error otherwise) and computes `return_stake` as `account.locked() - max(max_of_stakes, last_proposal)`, correctly using `max_of_stakes` from `EpochManager`'s `stake_info` (derived from `EpochInfo::stake_change` over the past three epochs, via `compute_stake_return_info` in `chain/epoch-manager/src/lib.rs:1648-1688`) and `last_proposals` — not the stale in-account `locked` value [3](#0-2) . This mirrors the exact "Proof idea" in the question and confirms the reconciliation is correct: the temporary mismatch between the submitted proposal and the account's `locked` field is by design and is safely resolved at the next epoch boundary, with `amount + locked` conserved throughout (no funds created, no state-root divergence).

**File:** docs/ChainSpec/EpochAndStaking/Staking.md (L9-14)
```markdown
On a stake action the balance gets locked immediately (but the locked balance can only increase), and the stake proposal is 
passed to the epoch manager. Proposals get accumulated during an epoch and get processed all at once when an epoch is finalized.
Unlocking only happens at the start of an epoch.

Account's stake is defined per epoch and is stored in `EpochInfo`'s `validators` and `fishermen` sets. `locked` is always
equal to the maximum of the last three stakes and the highest proposal in the current epoch.
```
