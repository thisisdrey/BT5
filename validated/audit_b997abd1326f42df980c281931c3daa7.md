### Title
Unauthenticated `/shutdown` HTTP endpoint allows any TCP peer to terminate the signer's event-receiver thread - (File: libsigner/src/events.rs)

### Summary
`SignerEventReceiver::next_event` dispatches purely on `request.url()` with no secret, token, or origin check, so any TCP client that can reach the bound event-receiver socket can POST `/shutdown` and force `stop_signal.store(true, ...)` plus an `Err(EventError::Terminated)` that unwinds through `main_loop` and permanently exits the receiver thread. This "shutdown" path is meant to be reachable only by the process's own `SignerStopSignaler::send`, but nothing enforces that restriction on the wire.

### Finding Description
The claimed equality — "only `SignerStopSignaler` can invoke `/shutdown`" — is false. `next_event` routes solely on URL string equality: [1](#0-0) 
There is no shared-secret, bearer-token, loopback-only check, or any other capability check before this branch executes; any HTTP client that opens a TCP connection to the bound `HttpServer` and issues `POST /shutdown` reaches the exact same code that `SignerStopSignaler::send` uses internally to wake the thread: [2](#0-1) 
Once `stop_signal` is set and `Err(EventError::Terminated)` propagates out of `with_server(...)?` in `next_event`, `main_loop`'s match arm treats it as a terminal (non-recoverable) condition and `break`s out of the loop entirely, ending the whole event-receiver thread for the process: [3](#0-2) 
Contrast this with the legitimate control paths (`/status`, `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block`) which at least require `POST` and expect a JSON/consensus-encoded body parsed via `process_event`, but still apply no authentication either — `/shutdown` is simply the most damaging of these because it kills the entire pipeline with a single request rather than one bad/rejected event.

### Impact Explanation
Any remote party able to open a TCP connection to the signer's event-receiver bound address can send a single crafted `POST /shutdown HTTP/1.1` and permanently stop that signer's event-receiver thread (no `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, or `/new_block` events will be processed afterward until the signer process is restarted). This is a single-message, unauthenticated, remote DoS against a component of consensus infrastructure (the signer), matching the "Critical - remote crash/unauthenticated DoS from few messages" category. It is fully repeatable (attacker can just resend it if the signer restarts and rebinds before it comes back online).

### Likelihood Explanation
The only precondition is TCP reachability to the signer's bound event-receiver socket address, which is exactly the precondition granted by this question ("attacker can open a TCP connection to the signer event-receiver's bound socket address"). No secret, key, peer role, or other privilege is needed — the attacker just needs to know/guess the host:port and issue one HTTP POST. Attacker cost is a single crafted packet/request.

### Recommendation
Require the internal stop-signaler to authenticate its shutdown request (e.g., a per-process random secret token generated at `bind()` time and included in the `SignerStopSignaler`'s request, checked in `next_event` before honoring `/shutdown`), or replace the HTTP-based stop mechanism with an in-process signaling primitive (e.g., a self-pipe/condvar/local Unix socket) that cannot be reached over the network at all, so `/shutdown` is not exposed as a routable HTTP endpoint.

### Proof of Concept
1. Start a `SignerEventReceiver` via `bind()` on `127.0.0.1:<port>` and spawn `main_loop()` in a thread, as done in existing tests under `stacks-node/src/tests/signer/`.
2. From a separate, unrelated `TcpStream::connect` (not via `SignerStopSignaler`), send raw bytes: `POST /shutdown HTTP/1.1\r\nHost: 127.0.0.1:<port>\r\nConnection: close\r\nContent-Length: 0\r\n\r\n`.
3. Assert that the spawned `main_loop` thread joins/exits shortly after (i.e., logs `"Caught termination signal"` per `libsigner/src/events.rs:296-300`), proving termination was achievable without ever calling `SignerStopSignaler::send`.
