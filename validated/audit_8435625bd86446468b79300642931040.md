Based on the investigation, here is the analog vulnerability found in the Nebula codebase.

### Title
Unauthenticated Handshake Flood Enables CPU-Exhaustion DoS on `HandshakeManager.HandleIncoming` - (File: handshake_manager.go)

### Summary
The external HAL-23 report flags the SSP Relay server for exposing endpoints reachable by unauthenticated clients with no rate limiting, creating a DoS/brute-force exposure. Nebula's UDP-facing handshake path has the same bug class: `Interface.readOutsidePackets` dispatches any well-formed `header.Handshake` packet straight into `HandshakeManager.HandleIncoming` before any certificate or peer-authentication check occurs, and the entire code path has no per-source-IP or global request-rate throttling.

### Finding Description
`readOutsidePackets` routes packets of `h.Type == header.Handshake` unconditionally to `f.handshakeManager.HandleIncoming(via, packet, h)` right after basic header parsing/version checks — no CA-signed-certificate check has occurred yet at this point. [1](#0-0) 

`HandleIncoming` only filters on subtype and, for stage-1 packets (`MessageCounter == 1`), performs an optional `remote_allow_list` IP-based gate (not a rate limit — a static allow/deny list) before calling `beginHandshake`, which is reachable by anyone able to send a stage-1 handshake UDP packet from a source IP not explicitly denied. [2](#0-1) 

`beginHandshake` then builds a fresh Noise `Machine` and immediately calls `machine.ProcessPacket(nil, packet)`, which performs an expensive Noise `ReadMessage` (asymmetric/ECDH crypto) — all of this executes *before* `validatePeerCert` is reached, i.e. before the sender's certificate is verified against any CA. [3](#0-2) 

There is no rate limiter, token bucket, or per-IP throttle anywhere in the codebase (confirmed via repo-wide search); the only related mechanism is the static `remote_allow_list`, which is an allow/deny IP filter, not a request-rate control. [4](#0-3) 

Because a stage-1 packet requires no valid certificate or prior authentication to reach the expensive crypto step, an attacker with no CA-signed certificate can repeatedly send spoofed/garbage stage-1 handshake packets (varying source port/IP or hitting an allowed source range) to force the responder to perform unbounded Noise handshake computations, with no cost-based or rate-based defense.

### Impact Explanation
An attacker can flood a Nebula node with forged stage-1 handshake packets to consume CPU cycles on asymmetric cryptographic operations for every packet received, degrading or denying service to legitimate peers trying to establish tunnels. This matches the HAL-23 impact class (denial-of-service due to lack of rate limiting on a critical, unauthenticated-reachable endpoint), scoring similarly moderate: exploitable without any credential, but requiring sustained volume to materially impact availability.

### Likelihood Explanation
Likelihood is moderate: no special network position or valid certificate is required, the handshake port is by design open to arbitrary internet hosts (this is how Nebula establishes new tunnels), and the `remote_allow_list` default configuration is open (`0.0.0.0/0` allowed) unless explicitly restricted by the operator. The attack requires only crafting a valid-looking handshake header and body.

### Recommendation
Introduce request-rate limiting (e.g., a token-bucket per source IP, and/or a global cap on concurrent pending Noise handshakes in `HandshakeManager`) that is checked in `HandleIncoming` prior to invoking `beginHandshake`, so that per-source stage-1 handshake attempts are throttled before the costly Noise `ProcessPacket`/`ReadMessage` operation runs.

### Proof of Concept
1. From an attacker-controlled host with no CA-issued certificate, craft a UDP packet with `header.Handshake` type, `HandshakeIXPSK0` subtype, `RemoteIndex = 0`, `MessageCounter = 1`, and a plausible Noise payload length.
2. Send this packet repeatedly at high rate to the victim's listening UDP port, optionally spoofing/rotating the source address to avoid any address-based tracking.
3. Each packet reaches `beginHandshake` → `machine.ProcessPacket` and performs a full Noise `ReadMessage` (ECDH) before any certificate is verified, with no rate limiter rejecting excess requests. [2](#0-1) [5](#0-4)

func (hm *HandshakeManager) HandleIncoming(via ViaSender, packet []byte, h *header.H) {
	// Gate on known handshake subtypes. Unknown subtypes (or future ones we
	// don't yet support) are dropped here rather than silently routed through
	// the IX path. Add a case when introducing a new pattern.
	switch h.Subtype {
	case header.HandshakeIXPSK0:
		// supported
	default:
		hm.l.Debug("dropping handshake with unsupported subtype",
			"from", via, "subtype", h.Subtype)
		return
	}

	// First remote allow list check before we know the vpnIp
	if !via.IsRelayed {
		if !hm.lightHouse.GetRemoteAllowList().AllowUnknownVpnAddr(via.UdpAddr.Addr()) {
			hm.l.Debug("lighthouse.remote_allow_list denied incoming handshake", "from", via)
			return
		}
	}

	// First message of a new handshake. The wire format requires RemoteIndex
	// to be zero here (the initiator has no responder index to fill in yet),
	// and generateIndex never allocates 0, so any non-zero RemoteIndex on a
	// stage-1 packet is malformed or someone probing for an index collision.
	// Drop without paying the cost of running noise on a pending Machine.
	if h.MessageCounter == 1 {
		if h.RemoteIndex != 0 {
			hm.l.Debug("dropping stage-1 handshake with non-zero RemoteIndex",
				"from", via, "remoteIndex", h.RemoteIndex)
			return
		}
		hm.beginHandshake(via, packet, h)
		return
	}

func (hm *HandshakeManager) beginHandshake(via ViaSender, packet []byte, h *header.H) {
	f := hm.f
	cs := f.pki.getCertState()

	v := cs.DefaultVersion()
	if cs.GetCredential(v) == nil {
		f.l.Error("Unable to handshake with host because no certificate is available",
			"from", via, "certVersion", v)
		return
	}

	machine, err := handshake.NewMachine(
		v, cs.GetCredential,
		hm.certVerifier(), func() (uint32, error) { return generateIndex(f.l) },
		false, header.HandshakeIXPSK0,
	)
	if err != nil {
		f.l.Error("Failed to create handshake machine", "from", via, "error", err)
		return
	}

	response, result, err := machine.ProcessPacket(nil, packet)
	if err != nil {
		f.l.Error("Failed to process handshake packet", "from", via, "error", err)
		return
	}

	if result == nil {
		// Multi-message pattern: the responder Machine would need to be
		// registered in hm.indexes so a future inbound packet finds it via
		// continueHandshake. The current manager doesn't do that yet, so
		// fail loudly rather than silently dropping the in-flight handshake.
		// TODO: support multi-message responder flows (XX, pqIX, etc.).
		// See also the IX-shaped cipher key assignment in handshake.Machine.
		f.l.Error("multi-message handshake responder is not supported",
			"from", via, "error", handshake.ErrMultiMessageUnsupported)
		return
	}

	remoteCert := result.RemoteCert
	if remoteCert == nil {
		f.l.Error("Handshake did not produce a peer certificate", "from", via)
		return
	}

	// Validate peer identity
	vpnAddrs, anyVpnAddrsInCommon, ok := hm.validatePeerCert(via, remoteCert)
	if !ok {
		return
	}
