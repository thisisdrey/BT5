### Title
V2 certificate parser silently accepts trailing/excess bytes after the signature field instead of rejecting them - (File: cert/cert_v2.go)

### Summary
The external report's bug class is "excess input is silently accepted/ignored instead of being rejected/returned," which in the Rubicon case meant unused ether was kept rather than refunded. In Nebula's certificate parsing path, `unmarshalCertificateV2` reads a strict ASN.1 SEQUENCE envelope but never verifies that all of the bytes inside that envelope were consumed once the signature field is read, so extraneous/unaccounted-for bytes appended after the signature (but still inside the outer SEQUENCE) are simply dropped without causing a parse error.

### Finding Description
`unmarshalCertificateV2` opens the outer SEQUENCE and correctly checks `input.Empty()` immediately after doing so at the top level [1](#0-0) . It then sequentially reads `rawDetails`, an optional curve byte, an optional/required public key, and finally the signature via `input.ReadASN1(&rawSignature, TagCertSignature)` [2](#0-1) . After this final read, the function proceeds directly to `unmarshalDetails`, builds the `certificateV2`, calls `c.validate()`, and returns — there is no subsequent check that `input.Empty()` is true [3](#0-2) . Because `cryptobyte.String.ReadASN1` only consumes the bytes belonging to the tag it is asked to read, any additional TLV elements or raw bytes appended after the signature field — but still nested inside the outer SEQUENCE that was opened at line 578 — are left unread and never trigger `ErrBadFormat`. This mirrors the reported bug class: bytes/value the caller supplied beyond what the parser strictly needed are neither validated nor rejected, they are just silently discarded.

### Impact Explanation
This is a certificate/handshake parsing defect reachable by any unauthenticated peer sending a handshake message, since `Recombine`/`unmarshalCertificateV2` is invoked on attacker-controlled certificate bytes during the Noise handshake before any CA trust decision is made [4](#0-3) . An attacker can craft two byte-distinct certificate blobs that parse to the *same* logical `certificateV2` (identical details/curve/publicKey/signature) by appending arbitrary junk bytes inside the outer SEQUENCE after the signature TLV. Because certificate fingerprinting and comparison in this codebase are based on the parsed/marshaled representation rather than on rejecting non-canonical encodings, this weakens the guarantee that a certificate has exactly one canonical wire encoding, which is a foundational property ASN.1 DER-style validators must enforce to prevent certificate/hash malleability and to keep blocklist/pinning logic (e.g. `BlocklistFingerprint`) trustworthy against variant encodings of the "same" cert.

### Likelihood Explanation
High likelihood of exploitability from a parsing perspective: it requires no valid CA-signed certificate, no privileged position, and no cryptographic break — only sending a syntactically-non-canonical but tag-valid ASN.1 blob during a handshake. It is reachable purely through the certificate-recombination path used before certificate/CA trust is established. However, translating the "extra bytes ignored" defect into a concrete authentication-bypass or filtering-bypass primitive would additionally depend on how `Fingerprint()`/equality checks over `certificateV2` are computed elsewhere (not fully confirmed in this review — see caveat below).

### Recommendation
After successfully reading the signature (`cert/cert_v2.go` line 615), add an explicit check that the outer `input` buffer is empty, e.g. `if !input.Empty() { return nil, ErrBadFormat }`, so that any unconsumed trailing bytes inside the outer SEQUENCE cause the certificate to be rejected outright rather than silently ignored — analogous to the recommended fix of requiring `msg.value == max_fill_withFee` (exact-match / no-excess) in the original report.

### Proof of Concept
1. Construct a valid V2 certificate byte sequence `b` that parses successfully via `unmarshalCertificateV2`.
2. Because the outer envelope is a DER/BER-style SEQUENCE with variable length encoding, append extra bytes/TLV elements after the encoded signature field but still within the length declared by the outer SEQUENCE tag (i.e., increase the outer SEQUENCE's declared length to cover the appended bytes).
3. Call `unmarshalCertificateV2(bModified, publicKey, curve)` (reachable via `cert.Recombine` during handshake processing, see `cert/cert.go:128-159`) and observe that it returns success with no error, identical to parsing the unmodified `b`, because the function never checks `input.Empty()` after line 617.

Caveat: I could not fully verify within the available index whether `certificateV2.Fingerprint()`/signature verification operate over the original raw bytes `b` or over a re-marshaled canonical form, which would determine whether this non-canonical-encoding acceptance also produces two different fingerprints for what should be "the same" certificate. Confirming this would require inspecting `cert/cert_v2.go`'s `Fingerprint()`, `Marshal()`, and `marshalForSigning()` implementations in full, which were only partially returned by the search tool. func unmarshalCertificateV2(b []byte, publicKey []byte, curve Curve) (*certificateV2, error) {
	l := len(b)
	if l == 0 || l > MaxCertificateSize {
		return nil, ErrBadFormat
	}

	input := cryptobyte.String(b)
	// Open the envelope
	if !input.ReadASN1(&input, asn1.SEQUENCE) || input.Empty() {
		return nil, ErrBadFormat
	}

	// Grab the cert details, we need to preserve the tag and length
	var rawDetails cryptobyte.String
	if !input.ReadASN1Element(&rawDetails, TagCertDetails) || rawDetails.Empty() {
		return nil, ErrBadFormat
	}

	//Maybe grab the curve
	var rawCurve byte
	if !readOptionalASN1Byte(&input, &rawCurve, TagCertCurve, byte(curve)) {
		return nil, ErrBadFormat
	}
	curve = Curve(rawCurve)

	// Maybe grab the public key
	var rawPublicKey cryptobyte.String
	if len(publicKey) > 0 {
		// If a public key is passed in, then the handshake certificate must
		// not have a public key present
		if input.PeekASN1Tag(TagCertPublicKey) {
			return nil, ErrCertPubkeyPresent
		}
		rawPublicKey = make(cryptobyte.String, len(publicKey))
		copy(rawPublicKey, publicKey)
	} else if !input.ReadOptionalASN1(&rawPublicKey, nil, TagCertPublicKey) {
		return nil, ErrBadFormat
	}

	if len(rawPublicKey) == 0 {
		return nil, ErrBadFormat
	}

	// Grab the signature
	var rawSignature cryptobyte.String
	if !input.ReadASN1(&rawSignature, TagCertSignature) || rawSignature.Empty() {
		return nil, ErrBadFormat
	}

	// Finally unmarshal the details
	details, err := unmarshalDetails(rawDetails)
	if err != nil {
		return nil, err
	}

	c := &certificateV2{
		details:    details,
		rawDetails: rawDetails,
		curve:      curve,
		publicKey:  rawPublicKey,
		signature:  rawSignature,
	}

	err = c.validate()
	if err != nil {
		return nil, err
	}

	return c, nil
}

// Recombine will attempt to unmarshal a certificate received in a handshake.
// Handshakes save space by placing the peers public key in a different part of the packet, we have to
// reassemble the actual certificate structure with that in mind.
// Implementations MUST assert the public key is not in the raw certificate bytes if the passed in public key is not empty.
func Recombine(v Version, rawCertBytes, publicKey []byte, curve Curve) (Certificate, error) {
	if publicKey == nil {
		return nil, ErrNoPeerStaticKey
	}

	if rawCertBytes == nil {
		return nil, ErrNoPayload
	}

	var c Certificate
	var err error

	switch v {
	// Implementations must ensure the result is a valid cert!
	case VersionPre1, Version1:
		c, err = unmarshalCertificateV1(rawCertBytes, publicKey)
	case Version2:
		c, err = unmarshalCertificateV2(rawCertBytes, publicKey, curve)
	default:
		return nil, ErrUnknownVersion
	}
