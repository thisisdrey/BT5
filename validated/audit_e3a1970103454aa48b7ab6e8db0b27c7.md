### Title
Malicious Shareholder Can Permanently Block `vesting::distribute()` via `set_allow_direct_coin_transfers` — (`aptos-move/framework/aptos-framework/sources/vesting.move`)

---

### Summary

`vesting::distribute()` iterates over all shareholders and calls `aptos_account::deposit_coins()` for each. If any single shareholder has opted out of direct coin transfers (`allow_arbitrary_coin_transfers = false`) and does not have a `CoinStore<AptosCoin>` registered, the inner `deposit_coins` call aborts. Because Move transactions are all-or-nothing, this abort rolls back the entire `distribute()` call, permanently blocking every other shareholder from receiving their vested APT. `terminate_vesting_contract()` is also blocked because it calls `distribute()` internally.

---

### Finding Description

In `vesting::distribute()`, after withdrawing stake, the function loops over every shareholder and deposits their share:

```move
shareholders.for_each_ref(|shareholder| {
    let shareholder = *shareholder;
    let shares = pool_u64::shares(grant_pool, shareholder);
    let amount = pool_u64::shares_to_amount_with_total_coins(grant_pool, shares, total_distribution_amount);
    let share_of_coins = coin::extract(&mut coins, amount);
    let recipient_address = get_beneficiary(vesting_contract, shareholder);
    aptos_account::deposit_coins(recipient_address, share_of_coins);  // <-- can abort
});
``` [1](#0-0) 

`aptos_account::deposit_coins<AptosCoin>` contains the following abort path:

```move
if (!coin::is_account_registered<CoinType>(to)) {
    assert!(
        can_receive_direct_coin_transfers(to),
        error::permission_denied(EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS)
    );
    coin::register<CoinType>(&create_signer(to));
};
``` [2](#0-1) 

`can_receive_direct_coin_transfers` returns `false` when the account has explicitly called `set_allow_direct_coin_transfers(self, false)`:

```move
public fun can_receive_direct_coin_transfers(account: address): bool acquires DirectTransferConfig {
    !exists<DirectTransferConfig>(account)
        || borrow_global<DirectTransferConfig>(account).allow_arbitrary_coin_transfers
}
``` [3](#0-2) 

`set_allow_direct_coin_transfers` is a public entry function callable by any account: [4](#0-3) 

With the ongoing APT → FungibleAsset migration, an account can hold APT exclusively in a primary fungible store without ever having a `CoinStore<AptosCoin>`. In that state, `coin::is_account_registered<AptosCoin>(to)` returns `false`, the `can_receive_direct_coin_transfers` guard is reached, and if the account has opted out, the entire `distribute()` transaction aborts.

The Aptos formal-verification spec explicitly acknowledges this unresolved abort path:

```
spec distribute(contract_address: address) {
    // TODO: Can't handle abort in loop.
    pragma verify = false;
``` [5](#0-4) 

`terminate_vesting_contract()` calls `distribute()` unconditionally before changing state, so it is equally blocked: [6](#0-5) 

---

### Impact Explanation

A single malicious (or misconfigured) shareholder can permanently prevent every other shareholder in the same vesting contract from receiving their vested APT. Because `terminate_vesting_contract()` also calls `distribute()`, the admin cannot terminate the contract and recover funds either. All APT locked in the vesting contract's stake pool becomes permanently inaccessible to the other shareholders — a direct, permanent freeze of user-controlled on-chain assets.

---

### Likelihood Explanation

The attack is cheap and requires no privileged access:

1. The attacker is a shareholder (or becomes one; the admin controls who is added, but the attacker only needs to be included once).
2. The attacker calls `set_allow_direct_coin_transfers(self, false)` — a public entry function.
3. The attacker ensures their account has no `CoinStore<AptosCoin>` (natural for FA-only accounts on mainnet post-migration).
4. Every subsequent call to `distribute()` or `terminate_vesting_contract()` aborts.

The admin can work around the attack by calling `set_beneficiary` to redirect the malicious shareholder's distribution to a different address, but this requires the admin to detect the attack and act. Until then, all other shareholders are frozen out.

---

### Recommendation

Replace the unconditional `aptos_account::deposit_coins` call inside the loop with a conditional check, or adopt a pull-payment (claim) model so that a single recipient's inability to receive coins does not block the entire distribution. For example, accumulate failed distributions into a separate claimable balance per shareholder rather than aborting the whole transaction.

---

### Proof of Concept

1. Admin creates a vesting contract with shareholders `A` (malicious) and `B` (innocent).
2. Shareholder `A` calls `aptos_account::set_allow_direct_coin_transfers(A, false)`.
3. Shareholder `A` holds APT only via primary fungible store (no `CoinStore<AptosCoin>`), so `coin::is_account_registered<AptosCoin>(A)` returns `false`.
4. After the lockup expires, anyone calls `vesting::distribute(contract_address)`.
5. The loop reaches shareholder `A`; `deposit_coins<AptosCoin>(A, ...)` hits the `assert!(can_receive_direct_coin_transfers(A), ...)` guard → aborts.
6. The entire transaction is rolled back; shareholder `B` receives nothing.
7. `terminate_vesting_contract(admin, contract_address)` also aborts (it calls `distribute()` first).
8. All vested APT remains locked in the stake pool indefinitely.

        assert_active_vesting_contract(contract_address);

        // Distribute all withdrawable coins, which should have been from previous rewards withdrawal or vest.
        distribute(contract_address);

        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        verify_admin(admin, vesting_contract);
        let (active_stake, _, pending_active_stake, _) = stake::get_stake(vesting_contract.staking.pool_address);

        emit(

                admin: vesting_contract.admin,
                vesting_contract_address: contract_address,
            },
        );

    /// Set whether `account` can receive direct transfers of coins that they have not explicitly registered to receive.
    public entry fun set_allow_direct_coin_transfers(
        account: &signer, allow: bool
    ) acquires DirectTransferConfig {
        let addr = signer::address_of(account);
        if (exists<DirectTransferConfig>(addr)) {
            let direct_transfer_config = borrow_global_mut<DirectTransferConfig>(addr);
            // Short-circuit to avoid emitting an event if direct transfer config is not changing.
            if (direct_transfer_config.allow_arbitrary_coin_transfers == allow) { return };

            direct_transfer_config.allow_arbitrary_coin_transfers = allow;

            emit(
                DirectCoinTransferConfigUpdated {
                    account: addr,
                    new_allow_direct_transfers: allow
                }
            );
        } else {
            let direct_transfer_config = DirectTransferConfig {
                allow_arbitrary_coin_transfers: allow,
                update_coin_transfer_events: new_event_handle<
                    DirectCoinTransferConfigUpdatedEvent>(account)
            };
            emit(
                DirectCoinTransferConfigUpdated {
                    account: addr,
                    new_allow_direct_transfers: allow
                }
            );
            move_to(account, direct_transfer_config);
        };
    }
