### Title
Unstaked connection table saturation via IP rotation (per-IP limits do not bound aggregate table occupancy) - (streamer/src/nonblocking/swqos.rs, streamer/src/nonblocking/quic.rs)

### Summary
The unstaked path enforces per-IP connection rate (`ConnectionRateLimiter`) and per-IP concurrent connection caps (`max_connections_per_unstaked_peer` in `ConnectionTable::try_add_connection`), but neither limit is scoped globally per attacker — both are keyed purely by source `IpAddr`. An attacker controlling many distinct IPv6 addresses (e.g., a /64 allocation) can open connections from a new IP for each batch, each staying under the per-IP thresholds, and cumulatively occupy slots up to `max_unstaked_connections` in the shared `unstaked_connection_table`.

### Finding Description
`ConnectionRateLimiter` and `ConnectionTable` both key state by `ConnectionTableKey::IP(ip)` / raw `IpAddr` [1](#0-0) , [2](#0-1) . In `run_server`, incoming connections are checked against a global burst limiter and then a per-IP `ConnectionRateLimiter::is_allowed` before `ClientConnectionTracker`/`setup_connection` proceed [3](#0-2) . There is no per-subnet (e.g., /64 or /56) aggregation or identity binding beyond the literal source IP — an attacker who owns many distinct addresses gets a fresh `TokenBucket` and a fresh `ConnectionTable` entry per new IP, since `KeyedRateLimiter`/`ConnectionTable` have no concept of "these IPs are the same actor."

Once past per-IP admission, `SwQos::try_add_connection` for `ConnectionPeerType::Unstaked` calls `prune_unstaked_connections_and_add_new_connection`, which only prunes the *shared* `unstaked_connection_table` down to 90% of `max_unstaked_connections` when the table is already at/above the cap, and otherwise just inserts the new connection [4](#0-3) . `prune_oldest`/`prune_random` evict entries irrespective of whether they belong to the attacker or a legitimate unstaked sender, so once the table fills up, an attacker distributing connections across many IPs contributes proportionally more entries than any single legitimate sender restricted to one or a few IPs, and continual reconnection from new IPs keeps re-filling slots that get vacated by pruning legitimate single-IP senders' older connections (per `prune_oldest`, which evicts based on `last_update`, oldest first, with no per-source fairness) [5](#0-4) .

The per-IP mitigations (`max_connections_per_ipaddr_per_min`, `max_connections_per_unstaked_peer`) are real and do throttle a *single* IP [6](#0-5) , [7](#0-6) , but they provide no bound on the number of distinct IPs one network-layer entity (e.g., one /64) can present, so `max_unstaked_connections` is the only real ceiling, and it is shared by all unstaked senders combined — an attacker with N addresses can claim up to `max_connections_per_unstaked_peer * N` slots (bounded above by `max_unstaked_connections`), crowding out other unstaked clients.

### Impact Explanation
This matches the stated scope: unstaked `ConnectionTable` saturation denying legitimate unstaked senders TPU capacity/QoS. The impact is capacity-based DoS against unstaked traffic (fairness violation among untrusted/unprivileged senders), not a memory-safety, consensus, or verification bypass — bounded by `DEFAULT_MAX_UNSTAKED_CONNECTIONS = 2000` [8](#0-7) , so memory stays bounded, but service fairness/availability for legitimate unstaked clients is degraded.

### Likelihood Explanation
Feasibility depends entirely on the attacker's ability to source many distinct IPv6 addresses cheaply from a single allocation (e.g., a /64 gives 2^64 addresses) and rotate through them faster than the per-IP token bucket accumulates cost — this is an infrastructure precondition external to the code, not a code defect that can be fixed by tightening a single per-IP knob. Given the stated preconditions ("attacker has access to many IPv6 addresses in one prefix, unstaked"), the exploit is straightforward to reproduce: it requires no exploit of a bug per se, but exploits an inherent design gap — IP-based rate limiting alone cannot bound a Sybil-style multi-address adversary. The unstaked table's saturation only denies *other unstaked* senders; staked senders are unaffected since staked/unstaked tables and pruning are separate [9](#0-8) .

### Recommendation
Add subnet-level aggregation for IPv6 (e.g., rate-limit and cap connections keyed by /64 or /56 prefix in addition to per-IP) in `ConnectionRateLimiter` and `ConnectionTable`/`ConnectionTableKey`, so a single allocation cannot present unlimited "distinct" identities. Additionally, consider making unstaked-table eviction fairness-aware (e.g., per-subnet round robin or per-subnet share caps) rather than purely age-based (`prune_oldest`), so no single subnet can occupy a disproportionate fraction of `max_unstaked_connections`.

### Proof of Concept
Integration test plan (extends existing `streamer/src/nonblocking/quic.rs` / `swqos.rs` test infra):
```rust
#[tokio::test]
async fn test_unstaked_table_saturation_via_ip_rotation() {
    // Configure a small max_unstaked_connections (e.g. 50) and
    // max_connections_per_unstaked_peer that allows a handful of
    // connections per IP (e.g. 4), with default per-IP rate limiter.
    let qos_config = SwQosConfig {
        max_unstaked_connections: 50,
        max_connections_per_unstaked_peer: 4,
        ..Default::default()
    };
    // Spin up N=20 distinct IPv6 client sockets from the same /64
    // (e.g. loopback-mapped test harness supporting distinct SocketAddr
    // per simulated client), each opening up to
    // max_connections_per_unstaked_peer connections (below per-IP cap).
    // Total connections attempted: 20 * 4 = 80 > max_unstaked_connections (50).
    //
    // Assert:
    // 1. Each individual IP's connections all succeed under per-IP caps
    //    (i.e., is_allowed()/try_add_connection() never rejects due to
    //    per-IP limiter for any single IP).
    // 2. unstaked_connection_table.total_size converges to
    //    max_unstaked_connections (50), i.e. cumulative occupancy is
    //    bounded only by the shared unstaked cap, not by attacker identity.
    // 3. A legitimate single-IP sender's connection attempted after the
    //    table is saturated is either rejected or requires pruning an
    //    attacker-owned (as opposed to fairly-selected) entry -- i.e.
    //    prune_oldest has no notion of "attacker subnet" and evicts
    //    purely by age, demonstrating no fairness-across-source guarantee.
}
```
This test would demonstrate that `ConnectionTable::try_add_connection`/`ConnectionTableKey::new`/`ConnectionRateLimiter` place no aggregate bound on distinct-IP occupancy of `unstaked_connection_table`, only on connections-per-single-IP, confirming the described QoS-evasion path.

    fn prune_unstaked_connection_table(
        &self,
        unstaked_connection_table: &mut ConnectionTable<ConnectionStreamCounter>,
        max_unstaked_connections: usize,
        stats: Arc<StreamerStats>,
    ) {
        if unstaked_connection_table.total_size >= max_unstaked_connections {
            // Prune the connection table down to 90% capacity
            const PRUNE_TABLE_RATIO: f64 = 0.90;
            let max_connections = (PRUNE_TABLE_RATIO * (max_unstaked_connections as f64)) as usize;
            let num_pruned = unstaked_connection_table.prune_oldest(max_connections);
            stats
                .num_evictions_unstaked
                .fetch_add(num_pruned, Ordering::Relaxed);
        }
    }

    async fn prune_unstaked_connections_and_add_new_connection(
        &self,
        client_connection_tracker: ClientConnectionTracker,
        connection: &Connection,
        connection_table: Arc<Mutex<ConnectionTable<ConnectionStreamCounter>>>,
        max_connections: usize,
        conn_context: &SwQosConnectionContext,
    ) -> Result<
        (
            Arc<AtomicU64>,
            CancellationToken,
            Arc<ConnectionStreamCounter>,
        ),
        ConnectionHandlerError,
    > {
        let stats = self.stats.clone();
        if max_connections > 0 {
            let mut connection_table = connection_table.lock().await;
            self.prune_unstaked_connection_table(&mut connection_table, max_connections, stats);
            self.cache_new_connection(
                client_connection_tracker,
                connection,
                connection_table,
                conn_context,
            )
        } else {
            connection.close(
                CONNECTION_CLOSE_CODE_DISALLOWED.into(),
                CONNECTION_CLOSE_REASON_DISALLOWED,
            );
            Err(ConnectionHandlerError::ConnectionAddError)
        }
    }
