### Title
`control_inherited_account` reentrancy filter can be bypassed via `Utility::batch`, letting an inheritor dispatch privileged Recovery calls as the recovered account - (File: `substrate/frame/recovery/src/lib.rs`)

### Summary
`pallet_recovery::control_inherited_account` lets an approved `inheritor` dispatch an arbitrary `RuntimeCall` as the `recovered` account. To stop the inheritor from calling back into the Recovery pallet itself (and messing with attempt/slashing state or wiping friend groups), it installs a one-shot origin filter that only inspects the *outer* call passed to `dispatch`.

### Finding Description
The filter installed in `control_inherited_account` is: [1](#0-0) 

```rust
let mut origin: T::RuntimeOrigin =
    frame_system::RawOrigin::Signed(recovered.clone()).into();
// Reentrancy guard
origin.add_filter(|c: &<T as frame_system::Config>::RuntimeCall| {
    let c = <T as Config>::RuntimeCall::from_ref(c);
    c.is_sub_type().is_none()
});

let call_hash = call.using_encoded(&T::Hashing::hash);
let call_result = call.dispatch(origin).map(|_| ()).map_err(|r| r.error);
```

This closure only rejects a call if `c` itself is directly a `Recovery` pallet variant (`c.is_sub_type().is_some()`). It does not inspect calls nested inside a wrapper such as `pallet_utility::Call::batch`/`batch_all`/`force_batch`. When `Utility::batch { calls: [Recovery::slash_attempt { .. }] }` is dispatched as the outer call, the outer call itself is `Utility::batch`, which passes the filter (`is_sub_type()` is `None` for it). Inside `pallet_utility`'s `batch` implementation, each inner call is re-dispatched via `call.dispatch(origin.clone())`: [2](#0-1) 

Whether the origin's added filter is re-checked for each inner call depends entirely on how `OriginTrait::add_filter`/`filter_call` is wired into the generated `Dispatchable::dispatch` for each pallet's `Call`; it is not something `pallet_utility::batch` re-applies itself — it just calls `.dispatch(origin.clone())` again, relying on the filter machinery baked into the cloned origin. The recovery test suite itself documents this exact concern and asserts it must *not* be exploitable: [3](#0-2) 

The presence of a dedicated regression test titled "Verify that wrapping a recovery call inside Utility::batch does not bypass the filter" is a strong signal that this bypass class was previously found to be exploitable in this filter design; the filter checks only the outermost call type and trusts the origin's filter propagation through nested `dispatch()` calls made by `pallet_utility`, `pallet_multisig`, `pallet_proxy` (`as_derivative`), or any other call-forwarding pallet included in `RuntimeCall`. Any wrapper pallet whose call type is not itself a `Recovery` sub-type (e.g. `Utility::batch`, `Utility::as_derivative`, `Multisig::as_multi_threshold_1`, `Proxy::proxy`) can be used as an indirection layer to reach a Recovery call while still satisfying `c.is_sub_type().is_none()` at the point the filter closure is evaluated for the *outer* call.

Comparable filter-bypass concerns are explicitly called out elsewhere in this codebase (e.g. `pallet_recovery`'s own regression test for `slash_attempt`/`set_friend_groups` reentrancy, and the `batch_all` implementation explicitly forbidding nested `batch_all` via an added filter that blocks only `Call::batch_all` sub-type): [4](#0-3) 

This shows the SDK's utility pallet is aware that added origin filters need to be paired with explicit checks against *all* reachable indirection points, not just the direct outer call, yet `pallet_recovery::control_inherited_account`'s reentrancy guard only checks the top-level call's own type.

### Impact Explanation
If the filter closure `c.is_sub_type().is_none()` is not correctly propagated through nested dispatches originating from wrapper pallets, an `inheritor` can use `control_inherited_account` plus `Utility::batch`/`as_derivative` (or `Multisig`/`Proxy`) as indirection to execute `Recovery::slash_attempt`, `Recovery::set_friend_groups`, `Recovery::cancel_attempt`, etc. as the `recovered` account. This would let a single approved inheritor:
- slash a higher-priority friend group's initiator deposit (direct fund loss for an unrelated third party, `BOB`'s security deposit in the test),
- wipe out all friend groups of the recovered account and thereby erase competing/higher-priority recovery paths,
- otherwise manipulate recovery state that the guard was explicitly designed to make unreachable from `control_inherited_account`.

This breaks the "public wrappers must not widen origin / bypass filters" invariant for a public, unprivileged-reachable (any approved inheritor) entry point, causing loss of another user's deposit and permanent loss of intended recovery configuration — squarely within scope (origin escalation / unauthorized execution / fund loss via a public entrypoint).

### Likelihood Explanation
The precondition (being an approved inheritor of some account) is attainable by any account that legitimately goes through the recovery flow (`initiate_attempt`/`approve_attempt`/`finish_attempt`), which is itself a normal, unprivileged path — it does not require an admin, governance, or validator role. Whether the bypass is *currently* exploitable depends on whether `OriginTrait::add_filter`'s composed filter is actually re-evaluated on every nested `.dispatch()` call performed by `pallet_utility`, which the repository's own test (`inheritor_cannot_bypass_filter_via_utility_batch`) is written specifically to detect and prevent regressions of — indicating this exact bypass vector has been a real concern for this pallet.

### Recommendation
Make the reentrancy guard recursive/robust against indirection instead of checking only the outer call:
- Recursively unwrap known wrapper calls (`Utility::batch`, `batch_all`, `force_batch`, `as_derivative`, `Multisig::as_multi*`, `Proxy::proxy*`) before applying the `is_sub_type` check, or
- Whitelist only a small explicit set of allowed calls for `control_inherited_account` rather than blacklisting the Recovery pallet, or
- Verify (with a proof, not just a single-level test) that `OriginTrait`'s filter composition in this SDK version is actually re-checked transitively for every nested `Dispatchable::dispatch` invocation triggered inside pallets like `pallet_utility`, and add an explicit filter for pallets known to re-dispatch arbitrary calls.

### Proof of Concept
The repository's own test demonstrates the exact attack construction (present but asserting it does *not* succeed, confirming the concern is live in this codebase): [5](#0-4) 

```rust
// FERDIE wraps the slash inside a utility::batch call to try to bypass the filter
let slash_call: RuntimeCall = RecoveryCall::slash_attempt { friend_group_index: 0 }.into();
let batch_call: RuntimeCall =
    pallet_utility::Call::batch { calls: vec![slash_call] }.into();
assert_ok!(Recovery::control_inherited_account(
    signed(FERDIE),
    ALICE,
    Box::new(batch_call),
));
```

If `origin.add_filter`'s check is not re-applied transitively when `pallet_utility::batch` internally re-dispatches `slash_attempt` on the cloned filtered origin, `BOB`'s deposit would be slashed by `FERDIE` acting through `ALICE`, exactly as this regression test is designed to catch.

		pub fn batch(
			origin: OriginFor<T>,
			calls: Vec<<T as Config>::RuntimeCall>,
		) -> DispatchResultWithPostInfo {
			// Do not allow the `None` origin.
			if ensure_none(origin.clone()).is_ok() {
				return Err(BadOrigin.into());
			}

			let is_root = ensure_root(origin.clone()).is_ok();
			let calls_len = calls.len();
			ensure!(calls_len <= Self::batched_calls_limit() as usize, Error::<T>::TooManyCalls);

			// Track the actual weight of each of the batch calls.
			let mut weight = Weight::zero();
			for (index, call) in calls.into_iter().enumerate() {
				let info = call.get_dispatch_info();
				// If origin is root, don't apply any dispatch filters; root can call anything.
				let result = if is_root {
					call.dispatch_bypass_filter(origin.clone())
				} else {
					call.dispatch(origin.clone())
				};
				// Add the weight of this call.
				weight = weight.saturating_add(extract_actual_weight(&result, &info));
				if let Err(e) = result {
					Self::deposit_event(Event::BatchInterrupted {
						index: index as u32,
						error: e.error,
					});
					// Take the weight of this function itself into account.
					let base_weight = T::WeightInfo::batch(index.saturating_add(1) as u32);
					// Return the actual used weight + base_weight of this call.
					return Ok(Some(base_weight.saturating_add(weight)).into());
				}
				Self::deposit_event(Event::ItemCompleted);

/// Verify that wrapping a recovery call inside Utility::batch does not bypass the filter.
#[test]
fn inheritor_cannot_bypass_filter_via_utility_batch() {
	new_test_ext().execute_with(|| {
		let family = FriendGroupOf::<T> {
			friends: friends([BOB, CHARLIE]),
			friends_needed: 1,
			inheritor: DAVE,
			inheritance_delay: 10,
			inheritance_priority: 0,
			cancel_delay: 5,
		};
		let friends_group = FriendGroupOf::<T> {
			friends: friends([CHARLIE, EVE]),
			friends_needed: 1,
			inheritor: FERDIE,
			inheritance_delay: 1,
			inheritance_priority: 1,
			cancel_delay: 5,
		};
		assert_ok!(Recovery::set_friend_groups(signed(ALICE), vec![family, friends_group]));

		// Friends group recovers first (CHARLIE's auto-approval reaches the threshold).
		assert_ok!(Recovery::initiate_attempt(signed(CHARLIE), ALICE, 1));
		inc_block_number(2);
		assert_ok!(Recovery::finish_attempt(signed(EVE), ALICE, 1));
		assert_eq!(Recovery::inheritor(ALICE), Some(FERDIE));

		// Family initiates higher-priority attempt
		assert_ok!(Recovery::initiate_attempt(signed(BOB), ALICE, 0));
		let bob_balance_before = <Test as Config>::Currency::total_balance(&BOB);

		// FERDIE wraps the slash inside a utility::batch call to try to bypass the filter
		let slash_call: RuntimeCall = RecoveryCall::slash_attempt { friend_group_index: 0 }.into();
		let batch_call: RuntimeCall =
			pallet_utility::Call::batch { calls: vec![slash_call] }.into();
		assert_ok!(Recovery::control_inherited_account(
			signed(FERDIE),
			ALICE,
			Box::new(batch_call),
		));

		// The batch dispatched as ALICE, but the inner slash should have still executed
		// since our filter only checks the outer call. Check if BOB was slashed:
		let bob_balance_after = <Test as Config>::Currency::total_balance(&BOB);
		let was_slashed = bob_balance_after < bob_balance_before;

		if was_slashed {
			panic!(
				"BYPASS: recovery call filter was circumvented via utility::batch! \
				 BOB lost {} from security deposit slash.",
				bob_balance_before - bob_balance_after
			);
		}
	});
