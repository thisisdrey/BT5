### Title
StackerDB Chunk Signature Omits Contract/Domain Binding, Enabling Cross-StackerDB Chunk Replay - (File: `libstackerdb/src/libstackerdb.rs`)

### Summary
`SlotMetadata::auth_digest()` computes the digest that authenticates a StackerDB chunk write over only `slot_id`, `slot_version`, and `data_hash` — it never binds the signature to the specific StackerDB (smart-contract) instance the chunk belongs to. Any properly-signed chunk observed on the network can therefore be replayed, unmodified, into a *different* StackerDB contract that an attacker controls, as long as the attacker configures that contract to list the original signer's address as the owner of a matching slot ID. This is the same missing-domain-separator class of bug as the reported "withdraw message replayable on a different chain" issue, except the missing domain component here is the controlling contract identity (StackerDB "chain") rather than an EVM `chainId`.

### Finding Description
The signing/verification digest for a chunk's metadata is: [1](#0-0) 

and it is used both to sign and to verify: [2](#0-1) 

Note that neither the `QualifiedContractIdentifier` of the StackerDB contract, nor any network/chain identifier, is mixed into this digest. The consumers of `verify()` also do not separately bind the check to the contract: `StackerDBTx::try_replace_chunk` only checks the recovered signer against the local per-contract signer table, not against the digest itself: [3](#0-2) 

and `PeerNetwork::validate_received_chunk` does the same for chunks received over the wire (downloaded or pushed): [4](#0-3) 

The StackerDB "signer" for a slot is whatever `StacksAddress` the *smart contract* returns from `stackerdb-get-signer-slots`, and this is entirely attacker-controllable when the attacker deploys their own controlling contract: [5](#0-4) 

Because chunk data (and thus signed chunks) are relayed and stored network-wide, and StackerDB contracts are permissionless (any contract satisfying the `stackerdb-trait` can become a replicated StackerDB, per the doc comment "a node can begin replicating a StackerDB whenever its operator wants"): [6](#0-5) 

an attacker can: (1) observe any signed `(slot_id, slot_version, data, sig)` chunk that some victim signer `V` legitimately wrote to StackerDB contract `A` (chunk contents and signatures are broadcast/public), (2) deploy a new contract `B` whose `stackerdb-get-signer-slots` assigns `V`'s address to the same `slot_id`, and (3) submit/relay the exact same `(slot_id, slot_version, sig)` plus the original `data` to `B`. Since `auth_digest()` never encodes which contract (`A` or `B`) the signature was meant for, `SlotMetadata::verify()` succeeds for `B` too, and `try_replace_chunk` / `validate_received_chunk` accept and store/propagate it as an authentic write by `V` into `B` — a StackerDB `V` never intended to write to and has no relationship with.

### Impact Explanation
This lets an unprivileged remote attacker forge a legitimate signer's authorization for an unrelated StackerDB instance, causing the network to store and propagate data as though it were authored/authorized there by that signer. This matches the "Critical: network-wide propagation of forged data" category — the attacker doesn't need the victim's private key, only a previously-observed valid signature/chunk pair and the ability to deploy/control a target contract that maps the victim's address onto a matching slot.

### Likelihood Explanation
Likelihood is high given the preconditions are all attacker-controllable and require no special privilege: StackerDB contracts are deployable by anyone and are evaluated purely from on-chain data (`StackerDBConfig::from_smart_contract`), signer addresses are public, and chunk contents/signatures are broadcast in the clear over the p2p StackerDB replication protocol, making the "previously observed chunk" precondition trivially satisfiable for any actively-used StackerDB (e.g. signer coordination DBs).

### Recommendation
Include the `QualifiedContractIdentifier` (and ideally a chain/network identifier) as part of the `auth_digest()` preimage in `SlotMetadata`, e.g. hash in the contract's serialized identifier alongside `slot_id`, `slot_version`, and `data_hash`. This requires plumbing the contract ID into `SlotMetadata::sign`/`verify`/`auth_digest`, and updating all call sites (`StackerDBChunkData::sign/verify`, `try_replace_chunk`, `validate_received_chunk`) to pass the relevant `smart_contract` identifier so a chunk signed for one StackerDB can never verify against another.

### Proof of Concept
1. Victim `V` (holding private key `pk_V`) legitimately signs and pushes chunk `(slot_id=0, slot_version=1, data=D)` to StackerDB contract `A`, producing signature `S` via `SlotMetadata::sign` (`libstackerdb/src/libstackerdb.rs:171-179`). This chunk is relayed network-wide (visible to any peer, e.g. via `StackerDBChunk`/`StackerDBPushChunk`).
2. Attacker deploys contract `B` implementing the `stackerdb-trait`, whose `stackerdb-get-signer-slots` returns `{ signer: V, num-slots: 1 }` for slot 0 (`config.rs::parse_slot_entry`), causing nodes that load `B`'s config to treat `V` as slot 0's owner for `B` as well.
3. Attacker crafts `StackerDBChunkData { slot_id: 0, slot_version: 1, sig: S, data: D }` for contract `B` and either submits it via the `postblock`/StackerDB HTTP POST chunk endpoint or pushes it via `StackerDBPushChunk` p2p message.
4. `PeerNetwork::validate_received_chunk` (`stackslib/src/net/stackerdb/mod.rs:649-717`) / `StackerDBTx::try_replace_chunk` (`stackslib/src/net/stackerdb/db.rs:400-437`) look up `B`'s configured signer for slot 0 (`V`), call `slot_metadata.verify(&V)`, which succeeds because `auth_digest()` never referenced contract `A` vs `B`. The forged-context chunk is accepted and stored/propagated as an authentic write to `B` by `V`.

    /// Get the digest to sign that authenticates this chunk data and metadata
    fn auth_digest(&self) -> Sha512Trunc256Sum {
        let mut hasher = Sha512_256::new();
        hasher.update(self.slot_id.to_be_bytes());
        hasher.update(self.slot_version.to_be_bytes());
        hasher.update(self.data_hash.0);
        Sha512Trunc256Sum::from_hasher(hasher)
    }

    /// Verify that a given principal signed this chunk metadata.
    /// Note that the address version is ignored.
    pub fn verify(&self, principal: &StacksAddress) -> Result<bool, Error> {
        let sigh = self.auth_digest();
        let pubk = StacksPublicKey::recover_to_pubkey_without_validating_low_s(
            sigh.as_bytes(),
            &self.signature,
        )
        .map_err(|ve| Error::VerifyingError(ve.to_string()))?;

        let pubkh = Hash160::from_node_public_key(&pubk);
        Ok(pubkh == *principal.bytes())
    }

        &self,
        smart_contract: &QualifiedContractIdentifier,
        slot_desc: &SlotMetadata,
        chunk: &[u8],

        // Check per-replica chunk-size cap.
        if (chunk.len() as u64) > self.config.chunk_size {
            return Err(net_error::StackerDBChunkTooBig(chunk.len()));
        }

        let slot_validation = self
            .get_slot_validation(smart_contract, slot_desc.slot_id)?
            .ok_or(net_error::NoSuchSlot(
                smart_contract.clone(),
                slot_desc.slot_id,
            ))?;

        if !slot_desc.verify(&slot_validation.signer)? {
            return Err(net_error::BadSlotSigner(
                slot_validation.signer,
                slot_desc.slot_id,
            ));
        }

    fn parse_slot_entry(
        entry: ClarityValue,
        contract_id: &QualifiedContractIdentifier,
    ) -> Result<(StacksAddress, u32), String> {
        let ClarityValue::Tuple(slot_data) = entry else {
            let reason = format!(
                "StackerDB fn `{contract_id}.{STACKERDB_SLOTS_FUNCTION}` returned non-tuple slot entry",
            );
            return Err(reason);
        };

        let Ok(ClarityValue::Principal(signer_principal)) = slot_data.get("signer") else {
            let reason = format!(
                "StackerDB fn `{contract_id}.{STACKERDB_SLOTS_FUNCTION}` returned tuple without `signer` entry of type `principal`",
            );
            return Err(reason);
        };

        let Ok(ClarityValue::UInt(num_slots)) = slot_data.get("num-slots") else {
            let reason = format!(
                "StackerDB fn `{contract_id}.{STACKERDB_SLOTS_FUNCTION}` returned tuple without `num-slots` entry of type `uint`",
            );
            return Err(reason);
        };

        let num_slots = u32::try_from(*num_slots)
            .map_err(|_| format!("Contract `{contract_id}` set too many slots for one signer (max = {STACKERDB_INV_MAX})"))?;
        if num_slots > STACKERDB_INV_MAX {
            return Err(format!("Contract `{contract_id}` set too many slots for one signer (max = {STACKERDB_INV_MAX})"));
        }

        let PrincipalData::Standard(standard_principal) = signer_principal else {
            return Err(format!(
                "StackerDB contract `{contract_id}` set a contract principal as a writer, which is not supported"
            ));
        };
        let addr = StacksAddress::from(standard_principal.clone());
        Ok((addr, num_slots))
    }
