### Title
Reward funds recorded for a delegation cycle with zero total votes are permanently unclaimable (null-vote-cycle fund freeze) - ([File: chainbase/src/main/java/org/tron/core/service/MortgageService.java])

### Summary
`MortgageService.payReward()` unconditionally records block/transaction-fee rewards for the current cycle into `DelegationStore`, but the voter-facing `computeReward()` path silently discards (via `continue`) any reward whose corresponding `totalVote` for that cycle/witness is `0` or unset (`REMARK`). Because `MaintenanceManager.doMaintenance()` snapshots `witness.getVoteCount()` into `DelegationStore.setWitnessVote()` for every witness regardless of whether that count is `0`, a witness/cycle combination with zero recorded votes causes any reward paid into that cycle to become permanently stranded — no voter can ever claim it and there is no reclaim/rollover mechanism. This is the same "null epoch" class of bug as the reported Y2K Carousel issue: value is deposited into an accounting bucket that structurally has no eligible claimants.

### Finding Description
- Every block, `Manager.payReward()` calls `mortgageService.payBlockReward()` (and conditionally `payTransactionFeeReward()`) for the block-producing witness: [1](#0-0) 

- `MortgageService.payReward()` stores the residual (post-brokerage) value into the delegation store keyed by the *current cycle* and witness address, with no check on whether that cycle/witness pair has any voters: [2](#0-1) 

- `DelegationStore.addReward()` simply accumulates this value under `(cycle, address)`: [3](#0-2) 

- At every maintenance cycle transition, `MaintenanceManager.doMaintenance()` snapshots the vote count for the *next* cycle for **all** witnesses (`consensusDelegate.getAllWitnesses()`), including those with `voteCount == 0` (e.g., newly registered SRs, genesis witnesses before any vote, or witnesses that lost all votes): [4](#0-3) 

- When a voter later calls `withdrawReward`/`queryReward`, `computeReward()` looks up `totalVote = delegationStore.getWitnessVote(cycle, srAddress)` and explicitly skips distributing the reward if `totalVote == REMARK || totalVote == 0`: [5](#0-4) 

Because the reward is written into the store unconditionally in `payReward()`, but only ever consumed proportionally to `totalVote` in `computeReward()`, any cycle where a witness earned block/fee rewards while its recorded vote count for that cycle is `0` results in that reward amount being written to a DB slot that can never be read out by any account. There is no treasury sweep, no rollover to the next cycle, and no alternate distribution path for these funds — mirroring exactly the "null epoch" emissions-loss pattern from the reported issue, except here it is real TRX (block reward / transaction fee pool funds) rather than emission tokens.

### Impact Explanation
This results in a concrete permanent loss/freezing of protocol funds: TRX drawn from the fixed block-reward emission and the transaction fee pool (`chainBaseManager.getDynamicPropertiesStore().getTransactionFeePool()`, which is decremented regardless of whether the reward is later claimable) is locked forever in an inaccessible accounting bucket whenever a witness produces blocks/collects fees during a cycle in which its total vote count is `0`. This satisfies the "permanent freezing of funds" impact category, since the funds are debited from the live fee pool / minted as reward but end up unbacked by any claimable balance.

### Likelihood Explanation
This is reachable through completely ordinary, permissionless chain operation — no privileged or malicious actor is required. It naturally occurs whenever a currently-active or standby witness has zero recorded votes for a cycle (common right after genesis, right after a witness is newly registered/elected, or after all voters withdraw votes from a witness that remains scheduled for the cycle due to the one-cycle-delayed snapshot in `doMaintenance()`), and that witness still produces blocks or is otherwise paid within that cycle window. Given `setWitnessVote` runs for the full witness set (`getAllWitnesses()`), not just witnesses with confirmed non-zero votes, this condition is not an exotic edge case.

### Recommendation
- In `MortgageService.payReward()` (or `Manager.payReward()`), check whether the witness has any recorded/expected votes for the current cycle before crediting the DelegationStore reward slot; if not, credit the witness's own allowance directly (as is already done for `brokerageAmount`) or route the amount to a treasury/foundation account instead of the unclaimable pool.
- Alternatively, in `computeReward()`/`accumulateWitnessVi()`, when `totalVote == 0` for a cycle, roll the stored reward forward to the next cycle for the same witness rather than silently discarding it, ensuring it eventually becomes claimable when votes exist.

### Proof of Concept
1. At genesis/cycle transition, a witness has `voteCount == 0` (e.g., new SR registered with no votes yet), and `MaintenanceManager.doMaintenance()` runs `delegationStore.setWitnessVote(nextCycle, witnessKey, 0)`.
2. During that cycle, the witness is scheduled and produces a block; `Manager.payReward()` → `mortgageService.payBlockReward()` → `payReward()` stores `delegationStore.addReward(cycle, witnessAddress, value)` with `value > 0`.
3. Any account that later votes for this witness and calls `withdrawReward`/`queryReward` for a range spanning this cycle will have `computeReward()` compute `totalVote = getWitnessVote(cycle, witnessAddress) == 0`, hit the `continue` branch, and receive `0` for that cycle.
4. No code path ever re-reads or redistributes `delegationStore.getReward(cycle, witnessAddress)` for this cycle again — the value is permanently stranded in the DB.

```java
  private long computeReward(long cycle, List<Pair<byte[], Long>> votes) {
    long reward = 0;
    for (Pair<byte[], Long> vote : votes) {
      byte[] srAddress = vote.getKey();
      long totalReward = delegationStore.getReward(cycle, srAddress);
      if (totalReward <= 0) {
        continue;
      }
      long totalVote = delegationStore.getWitnessVote(cycle, srAddress);
      if (totalVote == DelegationStore.REMARK || totalVote == 0) {
        continue;
      }
      long userVote = vote.getValue();
      double voteRate = (double) userVote / totalVote;
      reward += voteRate * totalReward;
    }
    return reward;
  }
```
