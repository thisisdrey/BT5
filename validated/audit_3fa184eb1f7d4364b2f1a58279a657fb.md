### Title
Unauthenticated repair-response nonce matching allows any network host to hijack/DoS pending shred-repair requests - ([File: core/src/repair/outstanding_requests.rs])

### Summary
Agave's shred-repair protocol matches repair *responses* to previously-sent repair *requests* solely by a 32-bit random `nonce`, with no binding to the peer the request was actually sent to. Any host that can reach a validator's public repair UDP port can send a spoofed repair-response packet carrying a guessed nonce and garbage/mismatched shred payload. When it fails validation, the code deletes the pending request entry anyway, causing the eventual legitimate response to be dropped as "unknown nonce." This is the direct on-chain-validator analog of the Chainlink report: response/fulfillment matching by a bare ID with no requester/peer binding lets an attacker's spoofed "fulfillment" consume and invalidate a legitimate pending request.

### Finding Description
Repair requests are registered with `OutstandingRequests::add_request_with_metadata`, which allocates a nonce with `rng().random_range(0..Nonce::MAX)` (32-bit space) and stores the pending request in an LRU keyed only by that nonce: [1](#0-0) 

When any packet flagged `REPAIR` arrives, `verify_repair_nonce` extracts the nonce/shred and calls `register_response` — with no check that the packet's source address/identity corresponds to the peer the original request was sent to: [2](#0-1) 

`register_response` matches purely on nonce and, critically, if the response fails `verify_response` (or is late), it deletes the outstanding entry regardless: [3](#0-2) 

`ShredRepairType::verify_response` only checks fields *derived from the attacker-controlled shred payload itself* (slot, index, merkle root) — it does not verify a signature or sender identity at this stage: [4](#0-3) 

Because the nonce space (2^32) is matched against a small outstanding-request LRU (capacity `16*1024`), and no address/identity binding exists, an unprivileged remote host can flood the target's repair socket (whose address is publicly advertised in gossip `ContactInfo`) with packets carrying random nonces and arbitrary shred bytes. Statistically, roughly 1 in every ~262,144 (2^32 / 16384) guesses will collide with a currently outstanding nonce. Because `verify_response` will almost always fail for attacker-controlled shred bytes (wrong slot/index/merkle root), the matched entry is deleted via `should_delete = true`, silently discarding the real pending repair request before the legitimate peer's response arrives. The later legitimate response then finds no matching nonce and is dropped as invalid, exactly the "hijack a request slot so the legitimate response fails" pattern from the report. The `BlockIdRepairService` path shares the identical nonce-only matching and delete-on-failure logic: [5](#0-4) 

### Impact Explanation
This is a low-cost, unprivileged, remotely triggerable denial-of-service against a validator's ledger/shred repair pipeline. By spraying random-nonce garbage packets at a node's repair UDP port, an attacker (no stake, no gossip membership requirement, not a chosen repair peer) can repeatedly invalidate in-flight repair requests, causing shred/block repair to stall or be significantly delayed. Since repair is the mechanism validators use to catch up on missed shreds/blocks, sustained disruption can keep a targeted node behind and unable to make progress, which is a legitimate node-level availability impact.

### Likelihood Explanation
Likelihood is moderate-to-high: it requires no special privileges, no valid keypair/stake, and no participation in consensus or gossip beyond knowing the target's repair socket address (which is broadcast in `ContactInfo`). The attack only needs raw UDP send capability and a modest packet rate (a few hundred thousand packets to reliably collide with any of up to 16K outstanding nonces); no IP spoofing is required since the matching logic never checks the sender's address.

### Recommendation
Bind the outstanding repair request to a canonical identifier that includes the peer's identity or the socket the request was addressed to (e.g., verify that the response's source pubkey/signature matches `RepairRequestHeader.recipient`/the queried repair peer before matching by nonce), so that off-path/uninvolved senders cannot inject or invalidate outstanding requests. Additionally, consider not deleting the outstanding-request entry purely because a single response fails `verify_response` — only delete on expiration or after exhausting `num_expected_responses` with valid responses — so a spoofed/garbage packet cannot pre-emptively evict a still-pending legitimate request.

### Proof of Concept
1. Observe (via gossip `ContactInfo`) the repair UDP socket address of a target validator.
2. From an unprivileged external host, repeatedly send UDP packets shaped like `RepairProtocol` responses (`repair_response_packet_from_bytes` format: arbitrary payload bytes + trailing serialized `Nonce`) to the target's repair socket, with random `nonce` values and non-matching/garbage shred payloads (see wire format in `core/src/repair/repair_response.rs`).
3. Whenever a guessed nonce collides with a currently outstanding request (statistically ~1 per 2^32/16384 attempts), `verify_repair_nonce` → `OutstandingRequests::register_response` fails `ShredRepairType::verify_response` and deletes the entry (`core/src/repair/outstanding_requests.rs:74-92`).
4. The legitimate repair peer's real response for that request later arrives but finds no matching nonce and is discarded — the original repair request is effectively lost/DoS'd, requiring the client to time out and re-issue it, delaying block/shred catch-up.

    pub fn register_response<R>(
        &mut self,
        nonce: u32,
        response: &S,
        now: u64,
        success_fn: impl Fn(&T) -> R,
    ) -> Option<R> {
        let mut should_delete = false;
        let response = self.requests.get_mut(&nonce).and_then(|status| {
            if status.num_expected_responses == 0 {
                // No more expected responses
                return None;
            }

            if now >= status.expire_timestamp || !status.request.verify_response(response) {
                // Invalid/expired response should invalidate this nonce.
                should_delete = true;
                return None;
            }

            status.num_expected_responses -= 1;
            if status.num_expected_responses == 0 && status.metadata.is_none() {
                // No metadata, and no more expected responses safe to delete eagerly.
                should_delete = true;
            }
            Some(success_fn(&status.request))
        });

        if should_delete {
            self.requests
                .pop(&nonce)
                .expect("request must exist when marked for deletion");
        }
        response
    }

impl RequestResponse for ShredRepairType {
    type Response = [u8]; // shred's payload
    fn num_expected_responses(&self) -> u32 {
        match self {
            ShredRepairType::Orphan(_) => MAX_ORPHAN_REPAIR_RESPONSES as u32,
            ShredRepairType::Shred(_, _)
            | ShredRepairType::HighestShred(_, _)
            | ShredRepairType::ShredForBlockId { .. } => 1,
        }
    }
    fn verify_response(&self, shred: &Self::Response) -> bool {
        #[inline]
        fn get_shred_index(shred: &[u8]) -> Option<u64> {
            shred::layout::get_index(shred).map(u64::from)
        }
        let Some(shred_slot) = shred::layout::get_slot(shred) else {
            return false;
        };
        match self {
            ShredRepairType::Orphan(slot) => shred_slot <= *slot,
            ShredRepairType::HighestShred(slot, index) => {
                shred_slot == *slot && get_shred_index(shred) >= Some(*index)
            }
            ShredRepairType::Shred(slot, index) => {
                shred_slot == *slot && get_shred_index(shred) == Some(*index)
            }
            ShredRepairType::ShredForBlockId {
                slot,
                index,
                fec_set_merkle_root,
                ..
            } => {
                shred_slot == *slot
                    && matches!(shred::layout::get_shred_type(shred), Ok(ShredType::Data))
                    && shred::layout::get_index(shred) == Some(*index)
                    && get_merkle_root(shred) == Some(*fec_set_merkle_root)
            }
        }
    }
}
