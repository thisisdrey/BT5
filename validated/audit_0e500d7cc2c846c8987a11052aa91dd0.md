## Analog Identified: Snowbridge outbound-queue fee pricing has no staleness/freshness enforcement

### Title
Snowbridge outbound message fee calculation trusts unbounded-age `PricingParameters` with no staleness check, enabling public underpriced relayer work that can stall Ethereum-bound message delivery - (File: `bridges/snowbridge/pallets/outbound-queue/src/lib.rs`)

### Summary
The Snowbridge outbound-queue pallet computes the fee charged to users sending messages to Ethereum using an ETH/DOT `exchange_rate`, `fee_per_gas`, and `rewards` values stored in `PricingParameters`. These parameters carry no timestamp and no freshness check — exactly the missing invariant described in the external PushOracle report. The pallet doc itself concedes governance is expected to "manually update these parameters every few weeks," but nothing on-chain enforces that update cadence or rejects fee computation once the parameters are stale relative to real-world ETH/DOT and gas-price movement.

### Finding Description
`PricingParameters` is a plain struct with `exchange_rate`, `fee_per_gas`, `rewards`, and `multiplier` — no `updated_at` / expiry field: [1](#0-0) 

Its only validation is non-zero-ness, not freshness: [2](#0-1) 

The pallet's own module documentation explicitly acknowledges the reliance on manual, infrequent governance updates and treats this as an "interim measure" pending an on-chain price source: [3](#0-2) 

Every public message submission that goes through the outbound queue computes its fee purely from whatever `PricingParameters` happens to be in storage at that moment, with no check on how long ago it was set: [4](#0-3) 

The `reward` and `max_fee_per_gas` baked into the committed message (which determines what the Ethereum-side relayer is refunded/paid) are taken directly from the same stale `pricing_params`: [5](#0-4) 

`set_pricing_parameters` only guards against zero values, not staleness, and there is no automated re-check before it is consumed by `calculate_fee`/`do_process_message`: [6](#0-5) 

Because any signed account can submit XCM/commands that route through `do_process_message` and `calculate_fee` at any time, an unprivileged actor can exploit a window where real-world ETH gas price or ETH/DOT rate has moved but on-chain `PricingParameters` have not been refreshed — this requires no admin/governance action by the attacker, only observing that the existing guard (`validate()`) never checks for staleness.

### Impact Explanation
If Ethereum gas price rises meaningfully after `PricingParameters.fee_per_gas`/`exchange_rate` were last set (which, per the module docs, may be "every few weeks"), the on-chain-computed `RemoteFeeAdjusted` and the `max_fee_per_gas`/`reward` embedded in `CommittedMessage` will undercharge relative to actual Ethereum-side delivery cost. Relayers relaying these messages are refunded `Min(GasPrice, Message.MaxFeePerGas) * GasUsed + Message.Reward` on the Ethereum gateway contract — if the stale `MaxFeePerGas`/`Reward` fall below real gas costs, relaying becomes unprofitable and relayers stop servicing the channel. Since outbound messages must be processed and committed within `MaxMessagesPerBlock` before yielding, an unrelayed backlog causes the outbound queue to stall, matching the gate's "public underpriced work that degrades block production or stalls bridge processing" impact category. Conversely, a stale rate moving the other direction causes systematic overcharging of ordinary users. Either direction is directly caused by the missing staleness invariant, mirroring the original PushOracle finding.

### Likelihood Explanation
Likelihood is driven purely by normal crypto market volatility over the multi-week intervals the pallet's own documentation admits between governance updates — no privileged or malicious actor is required to trigger the condition, and any signed account's ordinary `submit`/XCM-triggered message send is enough to consume the stale rate via `calculate_fee`/`do_process_message`.

### Recommendation
Add a last-updated block number/timestamp to `PricingParameters`, and enforce a maximum staleness window in `calculate_fee`/`do_process_message` (e.g., reject or pause message intake if `PricingParameters` have not been refreshed within `N` blocks), rather than relying solely on manual governance cadence with only a non-zero sanity check.

### Proof of Concept
1. Governance sets `PricingParameters { exchange_rate, fee_per_gas, rewards, multiplier }` via `set_pricing_parameters` (as in the existing test at `bridges/snowbridge/pallets/system/src/tests.rs:86-97`).
2. Real-world ETH gas price/ETH-DOT rate drifts materially over the following weeks (no code change required, no admin action needed).
3. Any signed account continues to call the public message-sending path (e.g. XCM export through `EthereumBlobExporter`/`snowbridge_pallet_system::send`), which triggers `Pallet::do_process_message` → `Self::calculate_fee`, using the now-stale `PricingParameters` unconditionally: [7](#0-6) 
4. Because `calculate_fee`/`validate()` never checks age, every message committed during this window bakes in an outdated `max_fee_per_gas`/`reward`, underpaying (or overpaying) relative to real delivery cost, with no on-chain signal to halt intake until governance manually notices and updates the parameters.

<br>

Note: candidates involving `pallet_asset_rate`/Treasury `BalanceConverter` and Snowbridge's `set_pricing_parameters` governance call itself were also considered, but those require an admin/governance actor as the direct trigger (excluded by the gate). The path above only requires ordinary public message submission to exploit the missing staleness guard, so it was kept as the strongest analog.

	pub fn validate(&self) -> Result<(), InvalidPricingParameters> {
		if self.exchange_rate == FixedU128::zero() {
			return Err(InvalidPricingParameters);
		}
		if self.fee_per_gas == U256::zero() {
			return Err(InvalidPricingParameters);
		}
		if self.rewards.local.is_zero() {
			return Err(InvalidPricingParameters);
		}
		if self.rewards.remote.is_zero() {
			return Err(InvalidPricingParameters);
		}
		if self.multiplier == FixedU128::zero() {
			return Err(InvalidPricingParameters);
		}
		Ok(())
	}

		/// Process a message delivered by the MessageQueue pallet
		pub(crate) fn do_process_message(
			_: ProcessMessageOriginOf<T>,
			mut message: &[u8],
		) -> Result<bool, ProcessMessageError> {
			use ProcessMessageError::*;

			// Yield if the maximum number of messages has been processed this block.
			// This ensures that the weight of `on_finalize` has a known maximum bound.
			ensure!(
				MessageLeaves::<T>::decode_len().unwrap_or(0) <
					T::MaxMessagesPerBlock::get() as usize,
				Yield
			);

			// Decode bytes into versioned message
			let versioned_queued_message: VersionedQueuedMessage =
				VersionedQueuedMessage::decode(&mut message).map_err(|_| Corrupt)?;

			// Convert versioned message into latest supported message version
			let queued_message: QueuedMessage =
				versioned_queued_message.try_into().map_err(|_| Unsupported)?;

			// Obtain next nonce
			let nonce = <Nonce<T>>::try_mutate(
				queued_message.channel_id,
				|nonce| -> Result<u64, ProcessMessageError> {
					*nonce = nonce.checked_add(1).ok_or(Unsupported)?;
					Ok(*nonce)
				},
			)?;

			let pricing_params = T::PricingParameters::get();
			let command = queued_message.command.index();
			let params = queued_message.command.abi_encode();
			let max_dispatch_gas =
				T::GasMeter::maximum_dispatch_gas_used_at_most(&queued_message.command);
			let reward = pricing_params.rewards.remote;

			// Construct the final committed message
			let message = CommittedMessage {
				channel_id: queued_message.channel_id,
				nonce,
				command,
				params,
				max_dispatch_gas,
				max_fee_per_gas: pricing_params
					.fee_per_gas
					.try_into()
					.defensive_unwrap_or(u128::MAX),
				reward: reward.try_into().defensive_unwrap_or(u128::MAX),
				id: queued_message.id,
			};

		/// Calculate total fee in native currency to cover all costs of delivering a message to the
		/// remote destination. See module-level documentation for more details.
		pub(crate) fn calculate_fee(
			gas_used_at_most: u64,
			params: PricingParameters<T::Balance>,
		) -> Fee<T::Balance> {
			// Remote fee in ether
			let fee = Self::calculate_remote_fee(
				gas_used_at_most,
				params.fee_per_gas,
				params.rewards.remote,
			);

			// downcast to u128
			let fee: u128 = fee.try_into().defensive_unwrap_or(u128::MAX);

			// multiply by multiplier and convert to local currency
			let fee = FixedU128::from_inner(fee)
				.saturating_mul(params.multiplier)
				.checked_div(&params.exchange_rate)
				.expect("exchange rate is not zero; qed")
				.into_inner();

			// adjust fixed point to match local currency
			let fee = Self::convert_from_ether_decimals(fee);

			Fee::from((Self::calculate_local_fee(), fee))
		}

		/// Set pricing parameters on both sides of the bridge
		///
		/// Fee required: No
		///
		/// - `origin`: Must be root
		#[pallet::call_index(2)]
		#[pallet::weight((T::WeightInfo::set_pricing_parameters(), DispatchClass::Operational))]
		pub fn set_pricing_parameters(
			origin: OriginFor<T>,
			params: PricingParametersOf<T>,
		) -> DispatchResult {
			ensure_root(origin)?;
			params.validate().map_err(|_| Error::<T>::InvalidPricingParameters)?;
			PricingParameters::<T>::put(params.clone());

			let command = Command::SetPricingParameters {
				exchange_rate: params.exchange_rate.into(),
				delivery_cost: T::InboundDeliveryCost::get().saturated_into::<u128>(),
				multiplier: params.multiplier.into(),
			};
			Self::send(PRIMARY_GOVERNANCE_CHANNEL, command, PaysFee::<T>::No)?;

			Self::deposit_event(Event::PricingParametersChanged { params });
			Ok(())
		}
