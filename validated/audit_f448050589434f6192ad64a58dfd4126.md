### Title
Unauthenticated `/wallet/getnodeinfo` (and `/monitor/getnodeinfo`) HTTP/gRPC endpoint discloses internal node topology, peer IPs, and JVM/OS internals - (File: framework/src/main/java/org/tron/core/services/NodeInfoService.java)

### Summary
The external advisory concerns an OPC UA server leaking sensitive internal information to any remote, unauthenticated client. The analogous condition in java-tron is `GetNodeInfoServlet` (`/wallet/getnodeinfo`, aliased at `/monitor/getnodeinfo` and on the Solidity/PBFT nodes), which by default is reachable by anyone who can send a plain HTTP request to the node's HTTP API port, with no signature, permission, or API-key check other than the generic `disabledApiList` opt-out.

### Finding Description
`GetNodeInfoServlet.doGet` simply calls `nodeInfoService.getNodeInfo()` and serializes the entire result to JSON with no filtering or redaction: [1](#0-0) 

`NodeInfoService.getNodeInfo()` aggregates and returns, for every peer connection: the remote peer's `host` (IP), `nodeId`, sync/latency/flow statistics, and local/remote disconnect reasons, plus full JVM/OS machine data (thread counts, CPU/memory stats, Java version, OS name) and, when a deadlock is detected, complete thread stack traces: [2](#0-1) [3](#0-2) 

It also reports internal `configNodeInfo`, including listen port, backup port, backup member count, discovery settings, and consensus-relevant limits: [4](#0-3) 

Access control for this path is only the generic `HttpApiAccessFilter`, which merely checks whether the endpoint appears in an admin-configured `disabledApiList` (opt-out, not opt-in, and empty by default) — it performs no authentication, signature, or origin check: [5](#0-4) 

The servlet is wired into the default full-node HTTP servlet mappings without any additional guard, and is also exposed on the Solidity node and on the `/monitor/getnodeinfo` alias: [6](#0-5) [7](#0-6) 

Additionally, when an exception occurs, the servlet logs the full stack trace and returns the raw exception message to the caller via `Util.printErrorMsg(e)`, further increasing information exposure on error paths: [8](#0-7) 

### Impact Explanation
An anonymous remote caller can enumerate a node's peer list (IP addresses, node IDs, connection/backup state), determine sync lag, disconnect reasons, backup member counts/ports, and JVM/OS fingerprint, all of which materially aid network reconnaissance for follow-on targeted attacks (e.g., identifying and targeting specific SR/witness or backup nodes, planning eclipse/DoS attacks, or exploiting known JVM/OS versions). This matches CWE-200 (exposure of sensitive information to unauthorized actor) and is reachable by any anonymous API client, consistent with the scope restrictions of this analysis (HTTP/gRPC/JSON-RPC query paths into Wallet). It does not by itself cause fund theft or consensus compromise, keeping severity at Medium, matching the CVSS of the referenced advisory (network, no privileges, no user interaction, confidentiality-only impact).

### Likelihood Explanation
Likelihood is high: the endpoint requires no authentication, no transaction signing, and no special permissions — a single unauthenticated HTTP GET/POST to `/wallet/getnodeinfo` (or `/monitor/getnodeinfo`) on any full node, Solidity node, or PBFT node with the HTTP API enabled (the default `FullNodeHttpApiService`/`SolidityNodeHttpApiService` configuration) returns the full payload.

### Recommendation
- Restrict `/wallet/getnodeinfo` and `/monitor/getnodeinfo` behind authenticated/administrative access (e.g., require it to be in an allow-list of trusted callers, an admin token, or bind it only to a loopback/internal-management HTTP listener) rather than relying solely on the opt-out `disabledApiList`.
- Strip or redact peer IP addresses/node IDs, backup topology details, and JVM/OS fingerprint data from the response returned to public callers; expose only what is strictly necessary for public health checks (e.g., block height, sync status).
- Avoid returning raw exception messages/stack traces to HTTP clients in `GetNodeInfoServlet`; log server-side only and return a generic error to the caller.

### Proof of Concept
1. Start a java-tron full node with the default HTTP API enabled (`fullNodeHttpEnable = true`), no entry for `getnodeinfo` in `disabledApiList`.
2. From any unauthenticated remote host, issue: `curl http://<node-ip>:<http-port>/wallet/getnodeinfo`.
3. Observe the JSON response containing `peerList[].host` (peer IP addresses), `peerList[].nodeId`, `configNodeInfo` (listen port, backup port/priority/member size, discovery flags), and `machineInfo` (CPU/memory, Java version, OS name, and, if a deadlock exists, full thread stack traces) — all disclosed to a caller with no credentials or transaction signature, confirming [1](#0-0)  as the unauthenticated disclosure sink.

  private boolean isDisabled(String endpoint) {
    boolean disabled = false;

    try {
      endpoint = URI.create(endpoint).normalize().toString();
      List<String> disabledApiList = CommonParameter.getInstance().getDisabledApiList();
      if (!disabledApiList.isEmpty()) {
        disabled = disabledApiList.contains(endpoint.split("/")[2].toLowerCase(Locale.ROOT));
      }
    } catch (Exception e) {
      logger.warn("check isDisabled except, endpoint={}, {}", endpoint, e.getMessage());
    }

    return disabled;
