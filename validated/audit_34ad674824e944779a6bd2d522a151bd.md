### Title
Attacker-controlled `HandshakeData.addrbytes/port` lets a remote peer hijack an existing PeerDB frontier row's trust state via `Neighbor::load_and_update` - (File: `stackslib/src/net/chat.rs`)

### Summary
`NeighborKey::from_handshake` (chat.rs:412-423) builds the PeerDB lookup key purely from the self-reported `handshake_data.addrbytes`/`port` fields, not from the actual TCP peer address. `Neighbor::load_and_update` (chat.rs:475-516) uses this attacker-chosen key to fetch an existing `Neighbor` row via `PeerDB::get_peer` (chat.rs:487), and if a row exists it preserves all of that row's state (including `allowed`/`denied`/`in_degree`/`out_degree`) while only `handshake_update` (chat.rs:438-465) overwrites `public_key`, `expire_block`, and `last_contact_time`. This lets a handshake claiming a victim's address inherit the victim's `allowed` trust flag while substituting the attacker's own public key.

### Finding Description
The broken equality: the frontier row keyed by `NeighborKey{addrbytes, port}` should only ever be updated by a peer that actually owns `addrbytes:port`, but the code path never verifies this — it merges on the claimed address alone.

- `NeighborKey::from_handshake` derives the DB key strictly from `handshake_data.addrbytes`/`handshake_data.port` [1](#0-0) .
- `Neighbor::load_and_update` looks up `PeerDB::get_peer(conn, network_id, &addr.addrbytes, addr.port)` using that self-reported key, and if a row is found, it retains the on-disk `Neighbor` (including `allowed`/`denied`/`in_degree`/`out_degree`, per the function's own doc comment: "all previously-calculated state and local configuration state will be loaded as well. This includes ... the allow/deny time limits") and only patches `addr` [2](#0-1) .
- `Neighbor::handshake_update` then overwrites `public_key`, `expire_block`, and `last_contact_time` from the handshake's claimed key/expire fields, without touching `allowed`/`denied`/`in_degree`/`out_degree` [3](#0-2) .

The result is that any handshake asserting `addrbytes`/`port` equal to a previously-trusted peer's address will be merged into that peer's existing frontier row, substituting the public key while carrying forward the `allowed` grant and degree counters — with no proof-of-address-ownership check anywhere in this call chain.

### Impact Explanation
An attacker who sends a single crafted `Handshake` claiming an already-`allowed` victim's `addrbytes`/`port` can overwrite that frontier row's `public_key` in `PeerDB`, effectively assuming the identity and trust grant of the victim for any code that keys off `NeighborKey{addr}` (e.g., always-allow logic, walk selection, whitelisting). This is an unauthenticated write to trusted P2P state, matching the Critical category ("unauthenticated/unauthorized write to state"). The attack is repeatable against any peer with an existing frontier entry.

### Likelihood Explanation
Preconditions are modest: the victim's address must already have a PeerDB row with `allowed != 0` (a common condition for bootstrap/allowed peers), and the attacker only needs to know that address (which is often public, e.g., in bootstrap node lists) and be able to open a P2P connection and send a `Handshake` — no secret, prior key, or privileged role required. This is a low-cost, remotely-reachable, unauthenticated attack.

### Recommendation
Bind the PeerDB lookup/merge key to the transport-verified peer address (the actual TCP socket address of the connection) rather than the self-reported `handshake_data.addrbytes/port`, or require that self-reported address information only be trusted for outbound connections (where the node dialed that address itself) and never applied to update-in-place merges for inbound handshakes without corroborating out-of-band proof of address ownership (e.g., requiring a matching NAT-punch/handshake completion from that source, or refusing to update `allowed` peers' public keys unless the previous key's signature is also presented).

### Proof of Concept
Rust test plan for `stackslib/src/net/chat.rs` (or `net/neighbors` test module):
1. Instantiate a test `PeerDB`, insert a victim `Neighbor` at address `X` with `public_key = victim_pk`, `allowed = -1` (always-allow).
2. Construct a `HandshakeData` with `addrbytes = X.addrbytes`, `port = X.port`, and `node_public_key = attacker_pk` (different from `victim_pk`).
3. Call `Neighbor::load_and_update(conn, peer_version, network_id, &handshake_data)`.
4. Persist via `neighbor.save_update(conn)` / `PeerDB::update_peer`.
5. Assert: `PeerDB::get_peer(conn, network_id, &X.addrbytes, X.port)` returns a `Neighbor` with `public_key == attacker_pk` and `allowed == -1`, proving the attacker's key inherited the victim's always-allow trust flag.

    pub fn handshake_update(
        &mut self,
        conn: &DBConn,
        handshake_data: &HandshakeData,
    ) -> Result<(), net_error> {
        let pubk = handshake_data
            .node_public_key
            .to_public_key()
            .map_err(|e| net_error::DeserializeError(e.into()))?;
        let asn_opt =
            PeerDB::asn_lookup(conn, &handshake_data.addrbytes).map_err(net_error::DBError)?;

        let asn = match asn_opt {
            Some(a) => a,
            None => 0,
        };

        self.public_key = pubk;
        self.expire_block = handshake_data.expire_block_height;
        self.last_contact_time = get_epoch_time_secs();

        if asn != 0 {
            self.asn = asn;
            self.org = asn; // TODO; AS number is a place-holder for an organization ID (an organization can own multiple ASs)
        }

        Ok(())
    }

    /// PeerDB with information in the handshake.
    /// * If we already know about this neighbor, then all previously-calculated state and local
    ///   configuration state will be loaded as well.  This includes things like the calculated
    ///   in/out-degree and last-contact time, as well as the allow/deny time limits.
    /// * If we do not know about this neighbor, then the above state will not be loaded.
    ///
    /// Returns (the neighbor, whether or not the neighbor was known)
    pub fn load_and_update(
        conn: &DBConn,
        peer_version: u32,
        network_id: u32,
        handshake_data: &HandshakeData,
    ) -> Result<(Neighbor, bool), net_error> {
        let addr = NeighborKey::from_handshake(peer_version, network_id, handshake_data);
        let pubk = handshake_data
            .node_public_key
            .to_public_key()
            .map_err(|e| net_error::DeserializeError(e.into()))?;

        let peer_opt = PeerDB::get_peer(conn, network_id, &addr.addrbytes, addr.port)
            .map_err(net_error::DBError)?;

        let (mut neighbor, present) = match peer_opt {
            Some(neighbor) => {
                let mut ret = neighbor;
                ret.addr = addr.clone();
                (ret, true)
            }
            None => {
                let ret = Neighbor::empty(&addr, &pubk, handshake_data.expire_block_height);
                (ret, false)
            }
        };
