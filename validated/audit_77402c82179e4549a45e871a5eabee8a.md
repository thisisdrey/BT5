### Title
`liquidate()` does not check the `pause-liquidation` / grace-period flags, allowing liquidations while liquidations are supposed to be paused - (File: `mainnet/contracts/market/v0-4-market.clar`)

### Summary
The market contract defines a private pause check `is-liquidation-paused` and public DAO-only setters `set-pause-liquidation` / `set-liquidation-grace-period` to allow the DAO to halt liquidations (e.g. during oracle incidents or emergency response) and to enforce a grace period after unpausing. [1](#0-0) [2](#0-1)  However, the actual `liquidate` public function never calls `is-liquidation-paused`, so the pause flag has no effect on the liquidation flow itself, mirroring the reported bug class of state-mutating flows that bypass the pause mechanism.

### Finding Description
`is-liquidation-paused` combines a manual DAO pause flag with global/per-asset liquidation grace periods to determine if liquidations should be blocked. [1](#0-0)  The DAO can toggle this via `set-pause-liquidation`, which also sets a grace period on unpause to prevent immediately liquidating positions affected by stale prices/oracle issues right after resuming. [3](#0-2) 

The `liquidate` public function, however, only performs health/LTV checks (`ERR-HEALTHY`), same-block borrow protection, oracle price resolution, and debt/collateral processing - it never asserts against `is-liquidation-paused` before executing collateral seizure and debt socialization. [4](#0-3)  The downstream state mutations (`collateral-remove`, `debt-remove-scaled` in `v0-market-vault.clar`) are only gated by that contract's own independent `collateral-remove`/`debt-remove` pause flags, set separately via `market-vault`'s `set-pause-states`, not by `pause-liquidation`. [5](#0-4) [6](#0-5) 

This means the DAO can call `set-pause-liquidation(true, ...)` expecting all liquidations to stop, but any ordinary liquidator can still call `liquidate()`/`liquidate-many()` and successfully seize collateral and socialize bad debt, since the code path never consults `pause-liquidation` or the grace-period maps. This is the same bug class as the referenced report: a dedicated pause flag exists, but a security-critical state-mutating flow ("liquidate," analogous to `topupMarketBalance`/`refundUser`) is unguarded by it.

### Impact Explanation
Liquidation is a fund-moving, state-changing operation that seizes user collateral and can socialize bad debt into vault-wide loss (writing down `lindex`/`total-assets`) affecting all depositors. [7](#0-6)  If the DAO pauses liquidations specifically to protect users during an oracle incident, price manipulation window, or emergency response, an attacker/liquidator can still trigger liquidations using manipulated or stale prices during the "paused" window, resulting in theft of a borrower's collateral (direct theft of user funds) and/or unintended bad-debt socialization onto other depositors (protocol insolvency risk). This lands in the Critical impact category (direct theft of user funds at rest, or protocol insolvency via forced bad-debt socialization).

### Likelihood Explanation
Likelihood is high once the DAO pauses liquidation for a legitimate emergency reason (e.g., oracle malfunction) - this is exactly the scenario the pause exists to prevent, so an attacker/liquidator monitoring for such pause events and combining it with any oracle deviation (in-scope: oracle manipulation caused by a bug in this code, or exploiting stale-price windows) can immediately profit by liquidating positions that should have been protected.

### Recommendation
Add an explicit assertion at the start of `liquidate` (and `liquidate-many`) that checks `(is-liquidation-paused debt-aid)` (or the relevant asset id) and aborts with an appropriate error (e.g. `ERR-LIQUIDATION-PAUSED`) before any state-mutating calls, mirroring how `pause-liquidation`/grace-period were clearly intended to gate this flow.

### Proof of Concept
1. DAO calls `set-pause-liquidation(true, grace-period)` on `v0-4-market.clar` expecting all liquidations to halt. [3](#0-2) 
2. An attacker (or ordinary liquidator) still calls `liquidate(borrower, collateral-ft, debt-ft, debt-amount, min-collateral-expected, collateral-receiver, price-feeds)` directly. [8](#0-7) 
3. Since `liquidate` never calls `is-liquidation-paused`, execution proceeds through health checks, liquidation-parameter calculation, and finally calls `.v0-market-vault collateral-remove` / `debt-remove-scaled`, which succeed as long as `market-vault`'s own (separately-controlled) `collateral-remove`/`debt-remove` pause flags are false. [5](#0-4) 
4. The borrower's collateral is seized and, if fully liquidated, bad debt may be socialized across the vault - despite the DAO having explicitly paused liquidations. [9](#0-8)
