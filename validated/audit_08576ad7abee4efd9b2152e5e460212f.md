### Title
Unauthenticated forged block-validation-response injection via `/proposal_response` - ([File: libsigner/src/events.rs])

### Summary
The signer's event-receiver HTTP server exposes `/proposal_response`, which deserializes any POSTed JSON directly into a `BlockValidateResponse` and forwards it to the runloop as `SignerEvent::BlockValidationResponse`, with no signature, secret, or session/request-id check tying the reply to a validation request this signer node actually submitted to its own stacks-node. Because the sample/documented configuration binds this listener to `0.0.0.0`, and the signer_signature_hash of a pending proposal is public gossip information, any unprivileged remote attacker who can reach this port and has observed a pending block's signature hash can forge the node's verdict and cause the signer to broadcast a false pre-commit or rejection to the rest of the network.

### Finding Description
`next_event` in `libsigner/src/events.rs` routes any POST to `/proposal_response` straight into `process_event::<T, BlockValidateResponse>(request)`: [1](#0-0) 

`process_event` reads the raw HTTP body, deserializes it with `serde_json::from_slice` into `E = BlockValidateResponse`, and calls `.try_into()` with no further validation — no auth header check, no HMAC/signature check, no correlation with an outstanding request id: [2](#0-1) 

`TryFrom<BlockValidateResponse> for SignerEvent<T>` performs a pure 1:1 mapping with no additional checks: [3](#0-2) 

This event is forwarded unmodified to the signer runloop (`forward_event`) and dispatched to `handle_event_match` → `handle_block_validate_response`: [4](#0-3) [5](#0-4) 

The only gate before the forged verdict is acted upon is `block_lookup_by_reward_cycle(signer_signature_hash)` — it must match a block the signer is already tracking as pending: [6](#0-5) 

This is not a secret: `signer_signature_hash` is derived from a `NakamotoBlock` header that is broadcast publicly by the miner (over StackerDB/`MinerMessages`), so any attacker observing the network can obtain it. There is no check anywhere in this path that the `BlockValidateResponse` actually originated from this signer's own `node_host` RPC call to `/v3/block_proposal` — the code trusts whatever arrives on `/proposal_response`.

The `auth_password`/`auth_token` mechanism documented in the sample configs only protects the signer's outbound calls to the node's block-proposal RPC endpoint; it is never checked by the event-receiver HTTP server in `libsigner/src/events.rs`: [7](#0-6) 

And the documented/sample signer `endpoint` binds to all interfaces, making the listener remotely reachable in a real deployment following this repo's own guidance: [8](#0-7) [9](#0-8) 

Attacker's exact message: a crafted JSON body shaped as `BlockValidateResponse::Ok(BlockValidateOk{ signer_signature_hash: <observed hash>, cost: ..., validation_time_ms: ..., ... })` (or `::Reject`), POSTed to `http://<signer-ip>:30000/proposal_response`.

Exploit flow:
1. Attacker observes a pending block proposal's `signer_signature_hash` from public StackerDB/gossip traffic.
2. Attacker POSTs a forged `BlockValidateResponse::Ok` (or `Reject`) for that hash to the signer's `/proposal_response` port.
3. `process_event` accepts it unconditionally and emits `SignerEvent::BlockValidationResponse`.
4. `handle_block_validate_response` → `handle_block_validate_ok`/`handle_block_validate_reject` finds the matching pending `block_info` and treats the forged verdict as if the node had actually validated the block, marking it `PreCommitted` (or `LocallyRejected`) and broadcasting a `BlockPreCommit`/rejection message over StackerDB to the rest of the signer set.

Existing guards fail because: (a) there is no cryptographic or secret-based authentication on the event HTTP server itself, (b) the only "check" is that the hash corresponds to a block the signer is tracking, which is public information, not a secret nonce tied to the specific outbound RPC call.

### Impact Explanation
A successful forged POST causes the targeted signer to broadcast a false `BlockPreCommit` or rejection to all other signers over StackerDB — this is unauthenticated writing of forged data into the signer's local state and its network-wide propagation via StackerDB gossip, matching the Critical category ("unauthenticated/unauthorized write to state or StackerDB, network-wide propagation of forged data"). This can desynchronize the signer's actual validation state from the node's real verdict (e.g., pre-committing to sign a block the node never actually approved, or rejecting one it did approve), undermining the "the node reports having processed/validated it" ground truth the signer protocol depends on. It is repeatable against every pending proposal as long as the attacker can observe its hash and reach the port.

### Likelihood Explanation
Preconditions: the signer's event-receiver port must be reachable by the attacker (satisfied by the repo's own documented/sample configuration binding to `0.0.0.0`), and the attacker must know a pending block's `signer_signature_hash`, which is publicly gossiped/observable and requires no privileged role, secret, or key. Attacker cost is a single crafted HTTP POST; no signature or computational effort is required. This is fully remote, unauthenticated, and repeatable for every future pending proposal.

### Recommendation
Authenticate the event-receiver HTTP server: require a shared secret/HMAC or the `auth_password` on inbound requests to `/proposal_response` (and the other POST endpoints), and/or bind the listener to loopback only by default with an explicit opt-in warning for non-loopback binds. Additionally, correlate incoming `BlockValidateResponse` events with the specific outstanding request the signer itself issued to the node (e.g., a per-request nonce/token generated when calling `/v3/block_proposal`), rejecting responses that don't match, instead of only checking that the hash exists among tracked blocks.

fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}

    /// Handle the block validate response returned from our prior calls to submit a block for validation
    fn handle_block_validate_response(
        &mut self,
        stacks_client: &StacksClient,
        block_validate_response: &BlockValidateResponse,
        sortition_state: &mut Option<SortitionsView>,
    ) {
        info!("{self}: Received a block validate response: {block_validate_response:?}");
        match block_validate_response {
            BlockValidateResponse::Ok(block_validate_ok) => {
                crate::monitoring::actions::record_block_validation_latency(
                    block_validate_ok.validation_time_ms,
                );
                self.handle_block_validate_ok(stacks_client, block_validate_ok, sortition_state);
            }
            BlockValidateResponse::Reject(block_validate_reject) => {
                self.handle_block_validate_reject(block_validate_reject, sortition_state);
            }
        };
        // Remove this block validation from the pending table
        let signer_sig_hash = block_validate_response.signer_signature_hash();
        self.signer_db
            .remove_pending_block_validation(signer_sig_hash)
            .unwrap_or_else(|e| warn!("{self}: Failed to remove pending block validation: {e:?}"));

        // Check if there is a pending block validation that we need to submit to the node
        self.check_pending_block_validations(stacks_client);
    }
