### Title
Fee bypass on NEP-245/IMT `TokenDiff` transfers via 1-unit leg splitting - ([File: contracts/defuse/core/src/intents/token_diff.rs])

### Summary
`TokenDiff::execute_intent` computes the protocol fee for a negative delta independently per `TokenDiff` intent, using only that single intent's own `delta`. For NEP-245/IMT token ids, `TokenDiff::token_fee` waives the fee entirely whenever the per-intent `amount <= 1`. An unprivileged signer can therefore split a single logical exposure such as `delta = -2` into two separate `TokenDiff` intents in the same `MultiPayload` (or same signed `DefuseIntents.intents` list), each with `delta = -1`, and pay zero fee instead of `Pips::fee_ceil(2)`.

### Finding Description
The binding claimed to hold is:
`sum over intents in batch of fee_collected(T) == Pips::fee_ceil(aggregate_negative_delta(T))`

This does not hold. `DefuseIntents::execute_intent` iterates intents and executes each independently: [1](#0-0) 

Each `TokenDiff::execute_intent` call computes fees purely from its own `self.diff` map, with no visibility into other intents in the same or other payloads: [2](#0-1) 

The fee eligibility check `TokenDiff::token_fee` waives fees for NEP-245/IMT (and NEP-171) whenever the per-intent `amount <= 1`: [3](#0-2) 

The only later invariant check, `TransferMatcher::finalize` in `Deltas`, only verifies that the *net token balance movements* (after fees already applied per-intent) sum to zero across the batch (via deposits/withdrawals matching) — it does not re-derive or verify fee amounts against an aggregated delta per token: [4](#0-3) [5](#0-4) 

**Attacker's exact payload**: sign one `DefusePayload` (single nonce, single signature) whose `DefuseIntents.intents` contains two `TokenDiff` intents on the same NEP-245/IMT `token_id`, each with `diff = { token_id: -1 }` (paired with an appropriate counter-leg to balance the batch, e.g. from a counterparty or a second token). Because each `TokenDiff::execute_intent` call sees `amount = 1` (not `> 1`), `token_fee` returns `Pips::ZERO` both times, so `fees_collected` is `0` for that token across the whole batch. If the same signer instead submitted one `TokenDiff` with `delta = -2` on that token, `amount = 2 > 1` triggers the non-zero branch and `fee_ceil(2)` fee is charged and credited to `fee_collector`.

No existing guard (`MultiPayload::verify`, nonce checks, `TransferMatcher::finalize`) inspects or aggregates the per-token delta across multiple intents/payloads before computing fees — the fee logic is strictly local to a single `TokenDiff::diff` entry.

### Impact Explanation
The protocol fee (credited to `fee_collector`) is under-collected for any signer who splits NEP-245/IMT negative exposures into ≤1-unit legs, at no cost or risk to the attacker. This directly matches the "protocol fees bypassed or over-collected" Critical category. The blast radius is scoped to NEP-245/IMT token diffs (NEP-141 is unaffected since its fee always applies regardless of amount), but it is repeatable indefinitely — any signer can split arbitrarily large aggregate deltas into many 1-unit legs (e.g., delta = -1000 split into 1000 intents each with delta = -1) to fully avoid fees on that token, at the cost of extra intents/gas only.

### Likelihood Explanation
No special privileges or roles are required — any signer able to construct and sign a `MultiPayload`/`DefuseIntents` with multiple `TokenDiff` intents can do this. It requires a NEP-245 or IMT token with quantities greater than 1 in play (common for semi-fungible/multi-token assets) and a counterparty (or another leg) to balance the batch per `TransferMatcher::finalize`, which is the same requirement as any normal swap. The only "cost" is additional intents (more entries in the payload / gas), which is trivial relative to the fee saved on larger amounts.

### Recommendation
Aggregate negative deltas per `TokenId` across all `TokenDiff` intents processed within the same execution context (batch) before evaluating the NEP-245/IMT `amount > 1` fee-waiver threshold, rather than evaluating it per individual intent's own delta. Alternatively, compute and reserve the fee based on the `TransferMatcher`'s finalized net withdrawal amount per token per account rather than at intent-execution time.

### Proof of Concept
Add a `cargo test` under `contracts/defuse/core/src/intents/token_diff.rs` (or `tests/src/tests/defuse/intents/token_diff.rs` using the sandbox harness pattern already present, e.g. `swap_p2p`/`swap_many`):
1. Create a NEP-245/IMT token id `mt_token` and a signer with balance `>= 2` of `mt_token`, plus a counterparty who supplies the matching `+2` (or `+1`/`+1`) counter-leg to keep the batch net-zero, using `Pips::ONE_PERCENT` (or any non-zero) fee.
2. Test A: sign one `TokenDiff` intent with `diff = { mt_token: -2, other_token: +X }` from the signer, paired with a counterparty `TokenDiff`. Execute via `execute_intents`/`simulate_intents`. Assert `fees_collected` for `mt_token` credited to `fee_collector` equals `Pips::fee_ceil(2)` via `TokenDiff::token_fee(mt_token, 2, fee).fee_ceil(2)`.
3. Test B: sign two separate `TokenDiff` intents from the same signer (same `DefuseIntents.intents` list/nonce), each `diff = { mt_token: -1, other_token: +X/2 }`, paired with matching counterparty legs. Execute the batch. Assert `fee_collector`'s balance of `mt_token` increases by `0` (bug) instead of `Pips::fee_ceil(2)` (expected/fixed).
4. Assert Test A's fee != Test B's fee for identical aggregate `mt_token` exposure of `-2`, demonstrating the bypass.

    pub fn finalize(self) -> Result<Transfers, InvariantViolated> {
        let mut transfers = Transfers::default();
        let mut deltas = TokenDeltas::default();
        for (token_id, transfer_matcher) in self.0 {
            if let Err(unmatched) = transfer_matcher.finalize_into(&token_id, &mut transfers)
                && (unmatched == 0 || deltas.apply_delta(token_id, unmatched).is_none())
            {
                return Err(InvariantViolated::Overflow);
            }
        }
        if !deltas.is_empty() {
            return Err(InvariantViolated::UnmatchedDeltas {
                unmatched_deltas: deltas,
            });
        }
        Ok(transfers)
    }
