Audit Report

## Title
Missing `is_delegate_call` guard on `System` builtin precompile allows state-changing `terminate()` to execute in the caller's storage/value context via `DELEGATECALL` - (File: `substrate/frame/revive/src/precompiles/builtin/system.rs`)

## Summary
The `System` precompile's `call()` dispatcher only guards the state-changing `terminate` selector against `is_read_only()` (static-call) contexts, but never checks `env.is_delegate_call()`, unlike every other stateful precompile in the codebase. Because `pallet-revive`'s `delegate_call` implementation pushes a new frame that reuses the calling contract's `account_id` and `value_transferred`, a contract that `DELEGATECALL`s into address `0x900` with the `terminate` selector will have `env.terminate_caller` operate on its own account rather than being blocked, letting an attacker-influenced code path drain the delegating contract's full native balance to an attacker-chosen beneficiary and destroy the account.

## Finding Description
`System::call()` in `substrate/frame/revive/src/precompiles/builtin/system.rs` matches on `ISystemCalls::terminate` and rejects it only `if env.is_read_only()`: [1](#0-0) 
The actual state-changing branch calls `env.terminate_caller(&h160)` unconditionally otherwise: [2](#0-1) 

No call to `env.is_delegate_call()` exists anywhere in this file. By contrast, sibling precompiles explicitly reject delegate calls before dispatching any state-changing logic, e.g. `AssetConversion`: [3](#0-2) 
and equivalent guards exist in `substrate/frame/assets/precompiles/src/lib.rs`, `substrate/frame/vesting/precompiles/src/lib.rs`, and `polkadot/xcm/pallet-xcm/precompiles/src/lib.rs`, all referencing `pallet_revive::Error::<T>::PrecompileDelegateDenied`.

Critically, `Stack::delegate_call` in `substrate/frame/revive/src/exec.rs` pushes the new frame with `dest: account_id` where `account_id` is cloned from the *current* top frame (i.e., the delegating/calling contract), and reuses `value = top_frame.value_transferred`: [4](#0-3) 
Only the executed code/caller identity is swapped via `DelegateInfo`, while the frame's `account_id` (storage/balance context) remains that of the delegating contract. This is the standard EVM `DELEGATECALL` semantic and is exactly what makes an unguarded state-changing precompile dangerous: any contract that delegate-calls into code reaching the `System` precompile's `terminate` selector will have `terminate_caller` executed against its own account, since the precompile provides no rejection for this call type.

## Impact Explanation
`terminate` schedules destruction of the calling frame's account and transfers its native balance to an attacker-supplied `beneficiary`. If reachable via `DELEGATECALL` from a victim contract (e.g., through a proxy/library pattern, a common and expected composability primitive in EVM-compatible chains), an unprivileged attacker can drain the victim contract's entire native balance and destroy it — this matches the "theft or unbacked mint or unlock" / "permanent user-fund lock" impact class for `pallet-revive`'s EVM compatibility layer, requiring no privileged actor.

## Likelihood Explanation
`DELEGATECALL` is a standard, freely available EVM opcode/Solidity primitive, and the `System` precompile sits at the fixed, well-known, and intentionally-reachable address `0x900`. Any contract that performs a delegate-call into attacker-influenced or attacker-authored code (e.g., a proxy delegating to a library) can trigger this without any race condition, front-running, or privileged capability, making this highly reachable and repeatable.

## Recommendation
Add the same `!env.is_delegate_call()` guard used in `asset-conversion`, `assets`, `vesting`, and `pallet-xcm` precompiles to `System::call()`, returning `pallet_revive::Error::<T>::PrecompileDelegateDenied` before dispatching `terminate` (or unconditionally at the top of `call()`, mirroring the sibling precompiles' pattern).

## Proof of Concept
1. Deploy `VictimContract` holding native balance.
2. Deploy `MaliciousLib` whose code calls `ISystem(0x900).terminate(attackerAddress)`.
3. `VictimContract` performs `address(MaliciousLib).delegatecall(abi.encodeCall(ISystem.terminate, (attacker)))`.
4. `Stack::delegate_call` pushes a frame with `dest: VictimContract.account_id`, executing the `System` precompile without an `is_delegate_call` check.
5. The `terminate` branch is reached (not `is_read_only`), and `env.terminate_caller(&attackerAddress)` executes against `VictimContract`'s own account, transferring its full balance to `attacker` and scheduling deletion of `VictimContract`.
