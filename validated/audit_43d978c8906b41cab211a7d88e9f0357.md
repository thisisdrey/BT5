Audit Report

## Title
Permanent Fund Lock in `pallet-asset-rewards` from Uncapped `last_update_block` After Pool Expiry - (File: `substrate/frame/asset-rewards/src/lib.rs`)

## Summary
`update_pool_rewards()` unconditionally sets `last_update_block` to the current block number rather than capping it at `expiry_block`, unlike the capping logic used in `reward_per_token()` via `last_block_reward_applicable()`. Once any state-mutating call occurs after a pool's expiry (which an ordinary staker can trigger on their own stake regardless of expiry), `last_update_block` exceeds `expiry_block`, and every subsequent call to `reward_per_token()` underflows in `last_block_reward_applicable(expiry_block).ensure_sub(last_update_block)`, permanently reverting all future calls that touch the pool, including the admin's own repair path.

## Finding Description
`update_pool_rewards()` persists `last_update_block = T::BlockNumberProvider::current_block_number()` unconditionally: [1](#0-0) , while `reward_per_token()` caps the elapsed-block computation using `last_block_reward_applicable(pool_info.expiry_block)` which returns `min(now, expiry_block)`: [2](#0-1) [3](#0-2) .

`update_pool_and_staker_rewards()` calls `reward_per_token()` first (using the pool's pre-update state) and then calls `update_pool_rewards()`, which stamps the *actual* current block into `last_update_block` regardless of `expiry_block`: [4](#0-3) .

`unstake` allows the staker to act on their own stake at any time, independent of expiry (`caller == staker` bypasses the expiry gate), and persists the corrupted pool state: [5](#0-4) . `stake` similarly persists pool state unconditionally: [6](#0-5) .

Once `now > expiry_block` and any such call executes, `last_update_block` becomes `> expiry_block` in storage. On the next call to `reward_per_token()`, `last_block_reward_applicable(expiry_block)` returns `expiry_block` (since `now >= expiry_block`), and `expiry_block.ensure_sub(last_update_block)` underflows because `last_update_block > expiry_block`, returning `Err` and reverting the whole extrinsic. This affects `stake`, `unstake`, `harvest_rewards` (via `update_pool_and_staker_rewards`), and `set_pool_reward_rate_per_block` / `set_pool_expiry_block` (via direct calls to `reward_per_token`): [7](#0-6) [8](#0-7) .

Critically, the admin's `set_pool_expiry_block` remediation also calls `reward_per_token(&pool_info)` on the already-corrupted pool state before applying the new expiry, so it also fails with the same underflow: [9](#0-8) . There is no code path that resets or caps `last_update_block` once it has exceeded `expiry_block`.

## Impact Explanation
This is a permanent user-fund lock. Once the underflow condition is triggered, every extrinsic that touches the pool via `reward_per_token()` (`stake`, `unstake`, `harvest_rewards`, `set_pool_reward_rate_per_block`, `set_pool_expiry_block`) fails deterministically for that pool. Remaining stakers can never `unstake` their frozen staked-asset balance, nor `harvest_rewards` for accrued but unclaimed reward-asset balance. `cleanup_pool` requires `stakers.is_none()`, so the admin cannot force-close the pool while stakers remain, leaving staked and reward assets held in the pool's sub-account permanently unreachable — satisfying the "permanent user-fund lock" impact category named in the gate.

## Likelihood Explanation
This requires no privileged actor or malicious behavior — the bypass condition `caller == staker` in `unstake` is explicitly designed to let any ordinary staker act on their own position at any time, including after expiry. Any pool with `expiry_block` reached while multiple stakers remain is exposed the moment any one staker calls `stake` or `unstake` (or the admin calls `set_pool_reward_rate_per_block`) even once after expiry — an entirely ordinary, expected interaction pattern for a farm that outlives its configured lifetime without immediate admin cleanup.

## Recommendation
In `update_pool_rewards()`, set `new_pool_info.last_update_block = Self::last_block_reward_applicable(pool_info.expiry_block)` instead of the raw current block number, mirroring the capping already performed in `reward_per_token()`. This guarantees `last_update_block` never exceeds `expiry_block`, eliminating the underflow in `ensure_sub` for all downstream callers, including the admin's `set_pool_expiry_block` remediation path.

## Proof of Concept
1. Create a pool with a short lifetime (e.g. `expiry_block = 25`) and two stakers, `staker1` and `staker2`, each with a non-zero stake before expiry, as shown in the pre-existing `integration` test setup pattern: [10](#0-9) .
2. Advance the mock chain's block number past `expiry_block` (e.g. to block 30) without calling `set_pool_expiry_block`.
3. Call `unstake(origin=staker1, pool_id, amount, staker=None)` — `caller == staker` bypasses the expiry gate at [11](#0-10) , and the resulting `Pools::<T>::insert` persists `last_update_block = 30` while `expiry_block` remains `25`.
4. Call `unstake` or `harvest_rewards` for `staker2` (who still has staked tokens): `reward_per_token()` computes `last_block_reward_applicable(25).ensure_sub(30)` = `25 - 30`, which underflows and returns `Err`, aborting the extrinsic.
5. Attempt `set_pool_expiry_block` as the admin to repair the pool: it calls `reward_per_token(&pool_info)` on the same corrupted state first and fails identically.
6. Assert that `staker2`'s stake and any unclaimed rewards remain permanently locked, with no available extrinsic path to recover them, confirming the permanent lock.

		/// Derives the current reward per token for this pool.
		pub(super) fn reward_per_token(
			pool_info: &PoolInfoFor<T>,
		) -> Result<T::Balance, DispatchError> {
			if pool_info.total_tokens_staked.is_zero() {
				return Ok(pool_info.reward_per_token_stored);
			}

			let rewardable_blocks_elapsed: u32 =
				match Self::last_block_reward_applicable(pool_info.expiry_block)
					.ensure_sub(pool_info.last_update_block)?
					.try_into()
				{
					Ok(b) => b,
					Err(_) => return Err(Error::<T>::BlockNumberConversionError.into()),
				};

			Ok(pool_info.reward_per_token_stored.ensure_add(
				pool_info
					.reward_rate_per_block
					.ensure_mul(rewardable_blocks_elapsed.into())?
					.ensure_mul(PRECISION_SCALING_FACTOR.into())?
					.ensure_div(pool_info.total_tokens_staked)?,
			)?)
		}

	fn set_pool_expiry_block(
		admin: &T::AccountId,
		pool_id: PoolId,
		new_expiry: DispatchTime<BlockNumberFor<T>>,
	) -> DispatchResult {
		let now = T::BlockNumberProvider::current_block_number();
		let new_expiry_block = new_expiry.evaluate(now);
		ensure!(new_expiry_block > now, Error::<T>::ExpiryBlockMustBeInTheFuture);

		let pool_info = Pools::<T>::get(pool_id).ok_or(Error::<T>::NonExistentPool)?;
		ensure!(pool_info.admin == *admin, BadOrigin);
		ensure!(new_expiry_block > pool_info.expiry_block, Error::<T>::ExpiryCut);

		// Always start by updating the pool rewards.
		let reward_per_token = Self::reward_per_token(&pool_info)?;
		let mut pool_info = Self::update_pool_rewards(&pool_info, reward_per_token)?;

		pool_info.expiry_block = new_expiry_block;
