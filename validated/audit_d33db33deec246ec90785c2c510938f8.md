### Title
Stale conntrack cache lets firewall-revoked flows keep passing after a rule reload - (File: `firewall.go`, `firewall/cache.go`)

### Summary
The report describes ERC20 allowance double-spending: a previously-granted permission (an approval) is still honored by the spender even after the owner tries to change/revoke it, because the check for "is this still allowed" is stale. The closest reachable analog in this codebase is Nebula's firewall conntrack fast-path cache: once a flow is marked "allowed" in the per-routine `ConntrackCache`, that cached "yes" is returned unconditionally for a whole cache epoch, even if the firewall rule that originally allowed the flow has since been reloaded/tightened to deny it.

### Finding Description
`Firewall.inConns` is the function that decides whether an already-tracked flow may continue without re-evaluating firewall rules. It first checks a per-goroutine `localCache` and, if present, short-circuits and returns `true` with no further validation: [1](#0-0) 

Only when the flow is *not* in `localCache` does it fall through to the "did the ruleset change since this conn was tracked" check, which re-validates the packet against the current `InRules`/`OutRules` table when `c.rulesVersion != f.rulesVersion`: [2](#0-1) 

That revalidation logic is correct and is exactly what protects normal (non-cached) `inConns` calls after a `reloadFirewall` bumps `rulesVersion`, as shown by `TestFirewall_DropConntrackReload`: [3](#0-2) 

However, `localCache` is populated from `ConntrackCacheTicker`, whose reset cadence is governed purely by a wall-clock ticker (`conntrackCacheTimeout`) and is completely independent of firewall rule/version changes: [4](#0-3) 

`reloadFirewall` bumps `f.rulesVersion` on every reload so future rule lookups are revalidated, but it does nothing to reset or invalidate the `ConntrackCacheTicker` held by `Interface`: [5](#0-4) 

Consequently, if an operator (or automated policy engine) tightens/removes a firewall rule for a flow that is already established and whose `Packet` key is currently sitting in `localCache`, that flow keeps being unconditionally allowed — bypassing the `rulesVersion` revalidation entirely — until the next tick of the cache ticker clears the map. This is the structural analog of the ERC20 issue: a permission that the "owner" (admin) tried to change is still honored by the "spender" (the reader goroutine) because the enforcement point consulted a stale, unauthenticated cache instead of re-checking the authoritative state.

### Impact Explanation
This is a firewall-bypass class issue: traffic that should be immediately dropped after a firewall policy reload can continue to be forwarded for the remainder of the current conntrack-cache tick interval. In a mesh where firewall policy is used to segment/isolate hosts (the entire purpose of Nebula's firewall), a host whose access is revoked via a rule change can continue sending/receiving packets on already-open flows past the intended revocation point, i.e. a concrete "firewall bypass" impact as defined in this scan's acceptance criteria.

### Likelihood Explanation
Likelihood depends on operational conditions: it requires (a) `conntrack_cache_timeout` to be non-zero (the fast path is skipped entirely when it is 0, per `NewConntrackCacheTicker`'s `d == 0` early return) and (b) a firewall reload happening while a flow relying on the revoked rule is already conntracked and cached. Given that reloads are a normal operational action (SIGHUP / config reload, or automatic reload on certificate `UnsafeNetworks` change per `reloadFirewall`), and the cache is on by default in most deployments for performance, the window is real but bounded to the configured cache timeout, making this a moderate-likelihood, time-bounded issue rather than a permanent bypass.

### Recommendation
Tie the conntrack local-cache validity to the firewall's `rulesVersion` instead of (or in addition to) a fixed wall-clock ticker: either invalidate/reset the `ConntrackCacheTicker` whenever `reloadFirewall` installs a new firewall (bump `cacheTick` from `reloadFirewall`), or store the `rulesVersion` alongside each `localCache` entry and re-validate it the same way `inConns` already does for the non-cached path, so that a stale cache entry can never mask a policy change.

### Proof of Concept
Conceptual reproduction (mirrors `TestFirewall_DropConntrackReload` but exercising the cached path):
1. Start Nebula with `firewall.conntrack_cache_timeout` set to a non-trivial value (e.g. default) and an inbound rule that allows a given flow.
2. Send a packet matching that flow so it becomes conntracked and, due to concurrent/subsequent packets on the same reader routine, gets inserted into that routine's `localCache` via `inConns`'s `localCache[fp] = struct{}{}` line: [6](#0-5) 
3. Reload the firewall config to remove/deny that rule; `reloadFirewall` bumps `f.rulesVersion` as shown above.
4. Within the current cache tick window, resend a packet matching the same flow key on the same reader routine — `inConns` returns `true` immediately from the `localCache` hit before ever consulting `rulesVersion`, so the packet is forwarded despite the rule having been revoked, until the next `ConntrackCacheTicker` tick resets the map.

Note: I was unable to fully trace the exact default value of `conntrack_cache_timeout` and its precise wiring order relative to `reloadFirewall` due to running out of tool iterations before reading `main.go`/`interface.go` in full; this should be verified by a follow-up session before treating the bound on exploitation window as authoritative.

// ConntrackCache is used as a local routine cache to know if a given flow
// has been seen in the conntrack table.
type ConntrackCache map[Packet]struct{}

type ConntrackCacheTicker struct {
	cacheV    uint64
	cacheTick atomic.Uint64

	l     *slog.Logger
	cache ConntrackCache
}

func NewConntrackCacheTicker(ctx context.Context, l *slog.Logger, d time.Duration) *ConntrackCacheTicker {
	if d == 0 {
		return nil
	}

	c := &ConntrackCacheTicker{
		l:     l,
		cache: ConntrackCache{},
	}

	go c.tick(ctx, d)

	return c
}

func (c *ConntrackCacheTicker) tick(ctx context.Context, d time.Duration) {
	t := time.NewTicker(d)
	defer t.Stop()
	for {
		select {
		case <-ctx.Done():
			return
		case <-t.C:
			c.cacheTick.Add(1)
		}
	}
}

// Get checks if the cache ticker has moved to the next version before returning
// the map. If it has moved, we reset the map.
func (c *ConntrackCacheTicker) Get() ConntrackCache {
	if c == nil {
		return nil
	}
	if tick := c.cacheTick.Load(); tick != c.cacheV {
		c.cacheV = tick
		if ll := len(c.cache); ll > 0 {
			if c.l.Enabled(context.Background(), slog.LevelDebug) {
				c.l.Debug("resetting conntrack cache", "len", ll)
			}
			c.cache = make(ConntrackCache, ll)
		}
	}

	return c.cache
}

func (f *Interface) reloadFirewall(c *config.C) {
	cs := f.pki.getCertState()
	curCert := cs.getCertificate(cert.Version2)
	if curCert == nil {
		curCert = cs.getCertificate(cert.Version1)
	}

	// The firewall builds its routableNetworks set from the certificate's UnsafeNetworks at construction.
	// Check to see if that set has changed, and if so, rebuild the firewall.
	certUnsafeChanged := curCert != nil && !slices.Equal(curCert.UnsafeNetworks(), f.firewall.unsafeNetworks)

	if !c.HasChanged("firewall") && !certUnsafeChanged {
		f.l.Debug("No firewall config change detected")
		return
	}

	fw, err := NewFirewallFromConfig(f.l, cs, c)
	if err != nil {
		f.l.Error("Error while creating firewall during reload", "error", err)
		return
	}

	oldFw := f.firewall
	conntrack := oldFw.Conntrack
	conntrack.Lock()
	defer conntrack.Unlock()

	fw.rulesVersion = oldFw.rulesVersion + 1
	// If rulesVersion is back to zero, we have wrapped all the way around. Be
	// safe and just reset conntrack in this case.
	if fw.rulesVersion == 0 {
		f.l.Warn("firewall rulesVersion has overflowed, resetting conntrack",
			"firewallHashes", fw.GetRuleHashes(),
			"oldFirewallHashes", oldFw.GetRuleHashes(),
			"rulesVersion", fw.rulesVersion,
		)
	} else {
		fw.Conntrack = conntrack
	}

	f.firewall = fw

	oldFw.Destroy()
	f.l.Info("New firewall has been installed",
		"firewallHashes", fw.GetRuleHashes(),
		"oldFirewallHashes", oldFw.GetRuleHashes(),
		"rulesVersion", fw.rulesVersion,
	)
}
