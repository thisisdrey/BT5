### Title
Path traversal via unvalidated `git_object_directory`/`git_alternate_object_directories` fields lets a crafted RPC set arbitrary `GIT_OBJECT_DIRECTORY`/`GIT_ALTERNATE_OBJECT_DIRECTORIES` for spawned git processes - ([File: internal/git/alternates/alternates.go])

### Summary
The `Repository` protobuf message that accompanies virtually every Gitaly RPC carries client-settable `git_object_directory` and `git_alternate_object_directories` fields [1](#0-0) . These are intended only to be looped back from GitLab Rails during `pre-receive` quarantine access checks [2](#0-1) , but the low-level code that actually turns them into `GIT_OBJECT_DIRECTORY`/`GIT_ALTERNATE_OBJECT_DIRECTORIES` environment variables for every spawned git subprocess does no bounds checking at all.

### Finding Description
`ExecCommandFactory.newCommand` resolves the repository path and then unconditionally calls `alternates.Env(repoPath, repo.GetGitObjectDirectory(), repo.GetGitAlternateObjectDirectories())` to build the environment for the git process it is about to exec: [3](#0-2) 

`alternates.Env` simply does `filepath.Join(repoPath, dir)` for the object directory and each alternate directory, with no check that the joined path stays inside the repository or the storage root: [4](#0-3) 

This is materially different from the two other places in the codebase that resolve the same kind of value and do bound the result to the storage root — `Repo.ObjectDirectoryPath` explicitly calls `storage.ValidateRelativePath` and further restricts non-quarantine paths to a repo-specific quarantine-prefix in the storage temp dir [5](#0-4) , and `altObjectDirs` explicitly rejects any alternate that escapes the storage root [6](#0-5) . `alternates.Env`, which is the function actually used to build the environment for every git subprocess Gitaly executes, has no equivalent guard.

The only gate that exists is at the gRPC-transaction middleware layer, and it is explicitly acknowledged as incomplete. `beginTransactionForRepository` only rejects requests with these fields set when the RPC is a `Mutator` *and* the WAL/partition transaction machinery is active; for `Accessor` RPCs it simply requires an internal `MetadataKeySnapshotRelativePath` header and otherwise passes the repository (and therefore its attacker-controlled object-directory fields) straight through to the handler without validating the directory values themselves: [7](#0-6) [8](#0-7) . The code comment itself states this is a known, deliberately unaddressed gap: "This allows for circumventing the transaction management by configuring the either of the object directories. We'll leave this unaddressed for now..." [9](#0-8) . Additionally, this middleware check is only invoked for repositories going through the WAL/partition transaction path at all — outside that flow (or for RPCs/paths that don't run through `beginTransactionForRepository`), `repo.GetGitObjectDirectory()`/`repo.GetGitAlternateObjectDirectories()` reach `alternates.Env` with no validation whatsoever.

This is analogous to the reported PSwapLib bug class: a field that is meant to be constrained to a narrow, trusted flow (the "hanging approval"/quarantine directory) is instead accepted and acted upon directly from caller-supplied input without re-validating it at the point where it actually takes effect, letting the caller redirect a security-relevant resource path (object directory / approval amount) outside its intended scope.

### Impact Explanation
If an attacker can invoke a Gitaly RPC that carries a `Repository` message under their control (e.g., a caller with only unprivileged internal-API access, a compromised/impersonated Rails-side caller, or any RPC path where `git_object_directory`/`git_alternate_object_directories` aren't stripped/rewritten before reaching the handler), they can set these fields to `../`-style relative or absolute paths. Because `alternates.Env` performs a raw `filepath.Join` with no root check, Git will be launched with `GIT_OBJECT_DIRECTORY`/`GIT_ALTERNATE_OBJECT_DIRECTORIES` pointing outside the intended repository — potentially into another repository's object store or elsewhere in the storage filesystem. Depending on which RPC is invoked, this could allow: cross-repository object disclosure (reading blobs/commits/trees that belong to a repository the caller has no access to), or corruption/writes into another repository's object directory for mutating commands, since Git will write new loose objects into `GIT_OBJECT_DIRECTORY` if it is settable and writable.

### Likelihood Explanation
Exploitability depends heavily on whether an actual attacker-reachable RPC path exposes these fields unfiltered to end users versus only being set internally by Rails/Praefect on already-authenticated internal loops. The codebase's own middleware comment confirms the underlying design gap is real and currently un-mitigated at the point where paths are actually consumed (`alternates.Env`), and confirms it is reachable at minimum by any RPC that is not routed through the WAL/partition manager, or by any Accessor RPC once the (weak) snapshot-relative-path metadata precondition is satisfied. I was not able to fully verify, within the remaining investigation budget, whether every externally reachable Gitaly gRPC entrypoint strips/overwrites these fields before they reach `newCommand`, so likelihood is assessed as medium/uncertain pending confirmation of the exact set of reachable RPCs and their auth-token scoping.

### Recommendation
Enforce the same bounds validation used in `localrepo.ObjectDirectoryPath`/`git.altObjectDirs` inside `alternates.Env` (or at the single call site in `command_factory.go`) before using `GetGitObjectDirectory()`/`GetGitAlternateObjectDirectories()` to build subprocess environment variables — reject or clamp any resolved path that is not contained within the repository's storage root, and reject absolute paths and `..` traversal outright. Do not rely solely on the transaction middleware, since it does not cover all code paths and by its own admission is intentionally incomplete for object-directory fields today.

### Proof of Concept
Not independently reproduced with live tooling in this session; concept is:
1. Craft or intercept a Gitaly RPC request whose `Repository` field sets `git_alternate_object_directories: ["../../other-repo/objects"]` (or an absolute path) against a repository the caller does have some level of access to.
2. Send the RPC to Gitaly through whatever entrypoint accepts attacker-influenced `Repository` messages without stripping these fields (e.g., an Accessor RPC satisfying the `MetadataKeySnapshotRelativePath` precondition, per `restoreSnapshotRelativePath` [8](#0-7) ).
3. Observe that `ExecCommandFactory.newCommand` sets `GIT_ALTERNATE_OBJECT_DIRECTORIES=<repoPath>/../../other-repo/objects` via `alternates.Env` [10](#0-9) [11](#0-10) , causing the spawned git process (e.g. `git cat-file`, `git log`) to resolve objects from the unrelated repository's object store.

// Env returns the alternate object directory environment variables.
func Env(repoPath, objectDirectory string, alternateObjectDirectories []string) []string {
	var env []string
	if objectDirectory != "" {
		env = append(env, fmt.Sprintf("GIT_OBJECT_DIRECTORY=%s", filepath.Join(repoPath, objectDirectory)))
	}

	if len(alternateObjectDirectories) > 0 {
		var dirsList []string

		for _, dir := range alternateObjectDirectories {
			dirsList = append(dirsList, filepath.Join(repoPath, dir))
		}

		env = append(env, fmt.Sprintf("GIT_ALTERNATE_OBJECT_DIRECTORIES=%s", strings.Join(dirsList, ":")))
	}

	return env
}

func restoreSnapshotRelativePath(ctx context.Context, methodInfo protoregistry.MethodInfo, req proto.Message) (proto.Message, error) {
	// Rails sends RPCs from its access checks with quarantine applied. The quarantine paths are relative to the
	// snapshot repository of the original transaction. While the relative path of the request is the original relative
	// path of the repository before snapshotting, Rails sends the snapshot repository's path in a header. For the
	// quarantine paths to apply correctly, we must thus rewrite the request to point to the snapshot repository here.
	snapshotRelativePath := metadata.GetValue(ctx, MetadataKeySnapshotRelativePath)
	if snapshotRelativePath == "" {
		return nil, ErrQuarantineWithoutSnapshotRelativePath
	}

	rewrittenReq, targetRepo, err := rewritableRequest(methodInfo, req)
	if err != nil {
		return nil, fmt.Errorf("rewritable request: %w", err)
	}

	targetRepo.RelativePath = snapshotRelativePath

	return rewrittenReq, nil
}
