### Title
Unbounded header count in `net/mail.ReadMessage` allows memory-exhaustion via unlimited MIME-style headers - ([File: src/net/mail/message.go])

### Summary
The Apache CXF advisory describes an unbounded number of attachment headers being deserialized per message, with no cap on header entries, leading to resource exhaustion. The Go standard library's own MIME-header parser in `net/textproto` was hardened against exactly this class of issue by adding `maxHeaders`/`maxMemory` limits (see `readMIMEHeader`, used by `mime/multipart` and `net/http`), but `net/mail`'s own header reader, `readHeader`, deliberately reimplements a simplified, unbounded version of the same logic and never received the same caps.

### Finding Description
An unauthenticated attacker who can get a victim application to parse an email/message body (e.g. an SMTP/IMAP proxy, a webhook receiver, or any service calling `net/mail.ReadMessage`) controls the raw header block. `ReadMessage` (`src/net/mail/message.go:54-66`) calls `readHeader(tp)` (`src/net/mail/message.go:75-114`), which loops with `r.ReadContinuedLine()` and unconditionally appends every parsed key/value into map `m` — there is no counter analogous to `maxHeaders`, and no memory-accounting check analogous to `maxMemory` that exist in the hardened sibling function `net/textproto.readMIMEHeader` (`src/net/textproto/reader.go:523-608`, note the `maxHeaders--`/`errMessageTooLarge` and `maxMemory -=`/`errMessageTooLarge` checks at lines 575-578 and 585-591). The comment in `readHeader` explicitly states it "copies the relevant code from net/textproto, simplified for RFC 5322," but the simplification dropped the resource-limiting checks, not just the RFC 7230 validation. This mirrors the CXF bug: a MIME-style header parser without a maximum-headers-per-message restriction, sitting directly beside a sibling parser (`mime/multipart`/`net/http`) that already enforces such a limit (`multipartmaxheaders`/`maxMIMEHeaders()` defaulting to 10000, `src/mime/multipart/multipart.go:346-363`).

### Impact Explanation
An attacker-supplied message with an arbitrarily large number of distinct header lines (or repeated keys) forces `readHeader` to grow the `map[string][]string` without bound, consuming memory and CPU proportional to attacker input size with no server-side cap — the same "uncontrolled resource consumption" (CWE-400) class as the CXF advisory. This is a real availability risk for any Go service that calls `mail.ReadMessage` on untrusted input (mail-processing services, ticketing webhooks, gateways). Under Go's vulnerability triage this is a plausible PUBLIC-track resource-exhaustion issue, analogous to the `net/textproto`/`mime/multipart` header-count hardening that was already applied elsewhere in this same codebase but omitted from `net/mail`.

### Likelihood Explanation
Victim workflow: any Go service that accepts raw email/RFC-5322-formatted messages from untrusted senders and parses them with `net/mail.ReadMessage` (a common, documented use case — see `mime/multipart.ExampleNewReader`, which builds a `mail.Message` from untrusted body and passes it into `multipart.NewReader`). The attacker needs no privileges beyond being able to submit a message/email — no authentication, no TLS trust, no malicious peer control assumed.

### Recommendation
Add the same header-count and memory-accounting bounds used in `net/textproto.readMIMEHeader` to `net/mail.readHeader` (e.g. a `maxHeaders` decrement with an error return once exceeded, and a memory budget analogous to `maxMemory`), defaulting to a reasonable cap (e.g. matching or configurable similarly to `multipartmaxheaders`).

func TestReadMessage_UnboundedHeaderCount(t *testing.T) {
	var b strings.Builder
	// Craft a huge number of distinct header lines; no limit exists to reject this.
	const n = 2_000_000
	for i := 0; i < n; i++ {
		b.WriteString("X-Header-")
		b.WriteString(strings.Repeat("a", 1)) // keep keys small but numerous
		b.WriteString(": v\r\n")
	}
	b.WriteString("\r\nbody")

	msg, err := ReadMessage(strings.NewReader(b.String()))
	if err != nil {
		t.Fatalf("unexpected error: %v", err)
	}
	// No cap was enforced: the header map grew to size n, unlike
	// net/textproto.readMIMEHeader, which would return errMessageTooLarge
	// once maxHeaders (or maxMemory) is exceeded.
	if len(msg.Header) < n/2 {
		t.Fatalf("expected large unbounded header map, got %d entries", len(msg.Header))
	}
}

func ReadMessage(r io.Reader) (msg *Message, err error) {
	tp := textproto.NewReader(bufio.NewReader(r))

	hdr, err := readHeader(tp)
	if err != nil && (err != io.EOF || len(hdr) == 0) {
		return nil, err
	}

	return &Message{
		Header: Header(hdr),
		Body:   tp.R,
	}, nil
}

// readHeader reads the message headers from r.
// This is like textproto.ReadMIMEHeader, but doesn't validate.
// The fix for issue #53188 tightened up net/textproto to enforce
// restrictions of RFC 7230.
// This package implements RFC 5322, which does not have those restrictions.
// This function copies the relevant code from net/textproto,
// simplified for RFC 5322.
func readHeader(r *textproto.Reader) (map[string][]string, error) {
	m := make(map[string][]string)

	// The first line cannot start with a leading space.
	if buf, err := r.R.Peek(1); err == nil && (buf[0] == ' ' || buf[0] == '\t') {
		line, err := r.ReadLine()
		if err != nil {
			return m, err
		}
		return m, fmt.Errorf("malformed initial line: %q", line)
	}

	for {
		kv, err := r.ReadContinuedLine()
		if kv == "" {
			return m, err
		}

		// Key ends at first colon.
		k, v, ok := strings.Cut(kv, ":")
		if !ok {
			return m, fmt.Errorf("malformed header line: %q", kv)
		}
		key := textproto.CanonicalMIMEHeaderKey(k)

		// Permit empty key, because that is what we did in the past.
		if key == "" {
			continue
		}

		// Skip initial spaces in value.
		value := strings.TrimLeft(v, " \t")

		m[key] = append(m[key], value)

		if err != nil {
			return m, err
		}
	}
}

// readMIMEHeader is a version of ReadMIMEHeader which takes a limit on the header size.
// It is called by the mime/multipart and net/http package.
func readMIMEHeader(r *Reader, maxMemory, maxHeaders int64) (MIMEHeader, error) {
	// Avoid lots of small slice allocations later by allocating one
	// large one ahead of time which we'll cut up into smaller
	// slices. If this isn't big enough later, we allocate small ones.
	var strs []string
	hint := r.upcomingHeaderKeys()
	if hint > 0 {
		if hint > 1000 {
			hint = 1000 // set a cap to avoid overallocation
		}
		strs = make([]string, hint)
	}

	m := make(MIMEHeader, hint)

	// Account for 400 bytes of overhead for the MIMEHeader, plus 200 bytes per entry.
	// Benchmarking map creation as of go1.20, a one-entry MIMEHeader is 416 bytes and large
	// MIMEHeaders average about 200 bytes per entry.
	maxMemory -= 400
	const mapEntryOverhead = 200

	// The first line cannot start with a leading space.
	if buf, err := r.R.Peek(1); err == nil && (buf[0] == ' ' || buf[0] == '\t') {
		const errorLimit = 80 // arbitrary limit on how much of the line we'll quote
		line, err := r.readLineSlice(errorLimit)
		if err != nil {
			return m, err
		}
		return m, ProtocolError(fmt.Sprintf("malformed MIME header initial line: %q", line))
	}

	for {
		kv, err := r.readContinuedLineSlice(maxMemory, mustHaveFieldNameColon)
		if len(kv) == 0 {
			return m, err
		}

		// Key ends at first colon.
		k, v, ok := bytes.Cut(kv, colon)
		if !ok {
			return m, ProtocolError(fmt.Sprintf("malformed MIME header line: %q", kv))
		}
		key, ok := canonicalMIMEHeaderKey(k)
		if !ok {
			return m, ProtocolError(fmt.Sprintf("malformed MIME header line: %q", kv))
		}
		for _, c := range v {
			if !validHeaderValueByte(c) {
				return m, ProtocolError(fmt.Sprintf("malformed MIME header line: %q", kv))
			}
		}

		maxHeaders--
		if maxHeaders < 0 {
			return nil, errMessageTooLarge
		}

		// Skip initial spaces in value.
		value := string(bytes.TrimLeft(v, " \t"))

		vv := m[key]
		if vv == nil {
			maxMemory -= int64(len(key))
			maxMemory -= mapEntryOverhead
		}
		maxMemory -= int64(len(value))
		if maxMemory < 0 {
			return m, errMessageTooLarge
		}
		if vv == nil && len(strs) > 0 {
			// More than likely this will be a single-element key.
			// Most headers aren't multi-valued.
			// Set the capacity on strs[0] to 1, so any future append
			// won't extend the slice into the other strings.
			vv, strs = strs[:1:1], strs[1:]
			vv[0] = value
			m[key] = vv
		} else {
			m[key] = append(vv, value)
		}

		if err != nil {
			return m, err
		}
	}
}

const maxMIMEHeaderSize = 10 << 20

// as well as the maximum combined total of header entries Reader.ReadForm will return
// in FileHeaders.
var multipartmaxheaders = godebug.New("multipartmaxheaders")

func maxMIMEHeaders() int64 {
	if s := multipartmaxheaders.Value(); s != "" {
		if v, err := strconv.ParseInt(s, 10, 64); err == nil && v >= 0 {
			multipartmaxheaders.IncNonDefault()
			return v
		}
	}
	return 10000
}
