### Title
`Pool.swap` prices synthetic token swaps purely at oracle rate with a fixed fee and no size-dependent slippage, enabling sandwiching of oracle updates - (File: contracts/Pool.sol)

### Summary
`Pool.swap` burns `syntheticTokenIn_` and mints `syntheticTokenOut_` at the exact price quoted by `masterOracle()`, minus only a fixed per-pair percentage fee from `FeeProvider.swapFees` (`contracts/Pool.sol:642-671`, `contracts/Pool.sol:508-525`). There is no trade-size-dependent slippage and no `minAmountOut` parameter. This is the same bug class as the reference report: any oracle price update that moves a synth pair by more than ~2× the swap fee can be sandwiched by an unprivileged attacker, who extracts the price delta by minting/burning synthetic supply at stale-then-updated oracle prices.

### Finding Description
- `swap` is callable by any EOA holding the input synth; its only guards are `whenNotShutdown`, `nonReentrant`, existence modifiers, `isSwapActive`, and a balance check (`contracts/Pool.sol:649-658`).
- The output amount is computed entirely from `masterOracle().quote(tokenIn, tokenOut, amountIn)` and a flat `wadMul` fee — no dependence on reserves, pool depth, or trade size (`contracts/Pool.sol:508-525`).
- The swap mints `syntheticTokenOut_` out of thin air (`syntheticTokenOut_.mint`) and burns the input, so mispricing directly dilutes/extracts value from the synthetic asset supply rather than from a counterparty AMM pool (`contracts/Pool.sol:660-668`).
- `quoteSwapIn`/`quoteSwapOut` are symmetric pure-oracle quotes, so the round trip is deterministic and atomically exploitable in a bundle.

Attack trace (unprivileged):
1. Attacker acquires `msAssetIn` (e.g. by minting against collateral or buying on a DEX).
2. An oracle update is pending in the mempool that will move the `msAssetIn/msAssetOut` price by `Δ > 2·swapFee`.
3. Front-run: `pool.swap(msAssetIn, msAssetOut, amountIn)` buys `msAssetOut` at the stale (better) price.
4. Oracle update executes.
5. Back-run: `pool.swap(msAssetOut, msAssetIn, amountOut)` sells at the updated price; profit = `Δ − 2·fee` on the full swappable size, since there is no slippage curve limiting size.

### Impact Explanation
Each exploited update mints unbacked synthetic supply to the attacker (or equivalently lets the attacker capture the price delta at the protocol's expense). Because synths minted via `swap` carry no debt position, the value extracted dilutes all holders/borrowers of the synthetic assets and can render synthetic supply under-collateralized — protocol insolvency / direct value extraction, proportional to swappable size rather than any pool depth.

### Likelihood Explanation
Requires `isSwapActive`, a listed synth pair, and a price move exceeding `2·swapFee`. EM-currency-like or volatile synths (e.g. msDOGE-style exotic synths as exercised in `test/Pool.test.ts`) routinely move more than the fee in a single update, and oracle updates on-chain are observable and front-runnable. No privileged role is needed; the attacker only needs the input synth, which is itself permissionlessly obtainable. Medium likelihood, gated mainly on the configured `swapFee` magnitude per pair.

### Recommendation
- Add a `minAmountOut_` parameter to `swap` so callers bound execution price.
- Preferably, add size-aware slippage or a per-tx/per-block swap cap so large swaps cannot harvest the full price delta.
- Alternatively price swaps off a TWAP/manipulation-resistant source rather than the spot `masterOracle().quote`.

### Proof of Concept
Reproducible on a Hardhat fork using the existing test harness pattern (`test/Pool.test.ts:1067-1124`):

```ts
// fork test sketch
// setup: pool with msEth, msDoge listed; swapFee = 0.1% on both directions
const { pool, masterOracleMock, msEth, msDoge, alice } = await loadFixture(fixture)

// attacker (alice) holds msEth
const amountIn = await msEth.balanceOf(alice.address)

// FRONT-RUN: buy msDoge at old price
await pool.connect(alice).swap(msEth.address, msDoge.address, amountIn)
const dogeBal = await msDoge.balanceOf(alice.address)

// ORACLE UPDATE: DOGE price doubles (>= 2*fee move)
await tokenOracleMock.updatePrice(msDoge.address, dogePrice.mul(2))

// BACK-RUN: sell msDoge back to msEth
await pool.connect(alice).swap(msDoge.address, msEth.address, dogeBal)

// assert: attacker ends with ~2x msEth (minus fees) — pure extraction
expect(ethAfter).to.be.gt(amountIn.mul(19).div(10))
```

Caveat: the test suite uses `MasterOracleMock`/`TokenOracleMock` for prices; on a real fork the price update step corresponds to a genuine oracle push (Chainlink relay etc.), which is the mempool event being sandwiched — consistent with the reference finding's assumptions.
