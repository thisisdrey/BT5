### Title
Unbounded full-store scan in the public `getPaginatedNowWitnessList` API allows CPU-exhaustion DoS via cheap vote spam - (File: `framework/src/main/java/org/tron/core/Wallet.java`)

### Summary
`Wallet.getPaginatedNowWitnessList` is exposed via the unauthenticated HTTP endpoint `/wallet/getpaginatedwitnesslist` (`GetPaginatedNowWitnessListServlet`), its Solidity-node counterpart, and the corresponding gRPC API. [1](#0-0)  Despite being called "paginated", before applying `offset`/`limit` it internally calls `countVote(votesStore)`, which unconditionally iterates **every entry** in `VotesStore` regardless of the requested page size. [2](#0-1)  `countVote` walks the full `VotesStore` DB iterator and, for each entry, iterates that voter's `oldVotes`/`newVotes` lists. [3](#0-2) 

### Finding Description
`VotesStore` holds one entry per account that casts a `VoteWitnessContract` transaction during the current voting cycle, and it is only cleared once per maintenance period. [4](#0-3)  Any unprivileged account can grow this store cheaply and unboundedly during an epoch: `VoteWitnessActuator` only requires the caller to own tron power and vote for existing witnesses, with no cap on the number of *distinct voting accounts*. [5](#0-4)  By creating many accounts (e.g., funded with a small amount of frozen TRX each) and having each cast one `VoteWitnessContract`, an attacker can drive `VotesStore` to a very large number of keys.

Because `getPaginatedNowWitnessList` calls `countVote(votesStore)` on *every* request — even when the client only asks for `limit=1` — each such request forces a full linear scan of the entire `VotesStore`, independent of the requested page size. [6](#0-5)  This is unlike a normal actuator loop that is bounded by TVM energy metering; this code path runs entirely in the HTTP/gRPC query-serving thread with no energy or CPU-time accounting, so the cost is fully attacker-controllable and repeatable at will (the endpoint is public and rate-limited only generically via `RateLimiterServlet`, not by request cost).

### Impact Explanation
Once `VotesStore` is inflated, every call to `getpaginatedwitnesslist` (HTTP), the Solidity-node/gRPC equivalents, forces a full-store scan and per-vote iteration, consuming CPU and disk I/O proportional to attacker-controlled store size rather than to the requested page. Repeated concurrent requests from an anonymous API client can starve node query-serving threads, degrading or denying the witness-list query API for legitimate users/wallets/exchanges relying on it, and can add sustained CPU pressure to the node process. This matches the reported bug class (unbounded loop reachable by an unprivileged actor, causing resource exhaustion of a live service) applied to a genuinely reachable java-tron API rather than a TVM-metered contract loop.

### Likelihood Explanation
Medium-High. No special privilege is needed: any account can submit `VoteWitnessContract` transactions, and creating many distinct voting accounts (each just needs enough frozen balance for 1 tron-power vote) is inexpensive relative to the linear cost imposed on every subsequent read of the endpoint. The endpoint itself requires no authentication and is commonly used by wallets/explorers, so it is realistically reachable and would be called at volume in production.

### Recommendation
- Change `getPaginatedNowWitnessList` so the vote-count aggregation work scales with the requested `limit`/`offset` rather than the entire `VotesStore` size (e.g., precompute/cache aggregated vote deltas once per block/maintenance cycle instead of recomputing on every request), or
- Cap/limit how much of `VotesStore` is scanned per call and require pagination cursors into the underlying store itself, and
- Consider bounding `VotesStore` growth per cycle (e.g., limiting distinct new-voter entries per block/account) or charging bandwidth/energy proportional to store growth to make the underlying vote-spam more costly.

### Proof of Concept
1. From many funded accounts, each freeze a minimal amount of TRX for tron power and broadcast one `VoteWitnessContract` transaction voting for an existing witness — this is standard, unprivileged, single-signed-transaction behavior and creates one `VotesStore` entry per account. [5](#0-4) 
2. Repeat with a large number of distinct accounts to grow `VotesStore` to a large key count within one voting cycle (the store is not pruned until the next maintenance cycle). [4](#0-3) 
3. Issue repeated `GET/POST /wallet/getpaginatedwitnesslist` (or the gRPC/Solidity-node equivalents) with `limit=1` — each call still triggers `countVote(votesStore)`, fully scanning the inflated store. [2](#0-1) [1](#0-0) 
4. Send this request concurrently from multiple clients to consume node CPU/I/O disproportionate to the trivial requested page size, degrading the API's availability for other callers.

  private Map<ByteString, Long> countVote(VotesStore votesStore) {
    // Initialize a result map to store vote changes for each witness
    Map<ByteString, Long> countWitness = Maps.newHashMap();

    // VotesStore is a key-value store, where the key is the address of the voter
    Iterator<Entry<byte[], VotesCapsule>> dbIterator = votesStore.iterator();

    while (dbIterator.hasNext()) {
      Entry<byte[], VotesCapsule> next = dbIterator.next();
      VotesCapsule votes = next.getValue();

      /**
       * VotesCapsule contains two lists:
       * - Old votes: Last votes from the previous epoch, updated in maintenance period
       * - New votes: Latest votes in current epoch, updated after each vote transaction
       */
      votes.getOldVotes().forEach(vote -> {
        ByteString voteAddress = vote.getVoteAddress();
        long voteCount = vote.getVoteCount();
        countWitness.put(voteAddress,
            countWitness.getOrDefault(voteAddress, 0L) - voteCount);
      });
      votes.getNewVotes().forEach(vote -> {
        ByteString voteAddress = vote.getVoteAddress();
        long voteCount = vote.getVoteCount();
        countWitness.put(voteAddress,
            countWitness.getOrDefault(voteAddress, 0L) + voteCount);
      });
    }
    return countWitness;
