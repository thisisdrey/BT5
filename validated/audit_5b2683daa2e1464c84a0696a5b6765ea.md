### Title
Replay-window check/update race allows duplicate decryption of a captured packet - ([File: connection_state.go])

### Summary
`ConnectionState.Decrypt` and `ConnectionState.VerifyRelay` in [1](#0-0)  split the anti-replay check into two separately-locked operations with the actual AEAD decryption performed *outside* the lock, in between. This mirrors the Ondo `completeRedemptions` bug class: a value is read, used to gate an action, and the corresponding "commit" of that read (marking the counter as consumed) happens only after the action, so a second caller can observe the stale, not-yet-updated state and be allowed to perform the same action again.

### Finding Description
`Decrypt` performs:
1. `cs.decryptLock.Lock(); result := cs.window.Check(l, messageCounter); cs.decryptLock.Unlock()` — [2](#0-1) 
2. `cs.dKey.DecryptDanger(...)` performed **without holding decryptLock** — [3](#0-2) 
3. `cs.decryptLock.Lock(); result = cs.window.Update(l, messageCounter); cs.decryptLock.Unlock()` — [4](#0-3) 

`VerifyRelay` has the identical structure for relay frames: `Check` → unlocked `DecryptDanger` → `Update` — [5](#0-4) 

`Bits.Check` only inspects the bitmap without mutating it, and `Bits.Update` is what actually marks the counter consumed (`b.bits[word] = w | mask`) and rejects duplicates — [6](#0-5) [7](#0-6) 

Because `Check` and `Update` for the *same* `messageCounter` are two independent, non-atomic critical sections with the expensive decrypt operation sandwiched between them, two goroutines processing the same captured/replayed ciphertext concurrently can both pass `Check` (since neither has yet called `Update`), both successfully run `DecryptDanger` (the AEAD nonce/counter is attacker-controlled data replayed verbatim, so decryption succeeds identically for both), and only the second `Update` call detects the duplicate — after the plaintext has already been produced and handed to the caller for the first (and, transiently, the second) invocation.

Nebula runs multiple concurrent UDP-reading routines that feed decryption per interface queue (confirmed via `interface.go` reader routine setup and `outside.go`'s `readOutsidePackets`), so it is plausible for the same physical UDP packet or a rapid, deliberately duplicated replay to be dispatched to the decrypt path on two different worker goroutines before the first one finishes its `Update` call.

This is directly analogous to the Ondo `completeRedemptions` bug: `totalBurned` (the "already spent" state) is computed/read before being durably updated, so a second call operating on the stale value gets an outcome it should not be entitled to. Here, the "already spent" state is the replay-window bit for a message counter, and the second call gets a full decrypt of a duplicate/replayed frame it should have been rejected for.

### Impact Explanation
An attacker who can capture ciphertext traversing the wire (no CA-signed certificate or key material required — the attacker never needs to decrypt or forge, only to duplicate bytes already on the wire) can attempt to have the same encrypted frame processed twice by racing two copies of it into Nebula's UDP listeners. If the race window is hit, the anti-replay protection is bypassed for that packet: the frame is decrypted and delivered to the tun device (or, for `VerifyRelay`, forwarded through a relay) more than once, defeating the very guarantee `ReplayWindow`/`Bits` exists to provide. This is a traffic-replay bypass of the intended security control, which the changelog itself treats as security-relevant (`Advance the replay window on relayed packets so a relay drops replayed frames instead of re-forwarding them` and `Lock replay window updates so concurrent readers can't corrupt it` — [8](#0-7) ), but those historical fixes addressed bitmap corruption and relay-forwarding advancement, not this specific Check/decrypt/Update TOCTOU gap.

### Likelihood Explanation
Exploitation requires winning a narrow timing race across independent lock acquisitions to line up two decrypt attempts for the same counter before the first `Update` commits. This is inherently probabilistic and depends on scheduler timing, packet dispatch across worker goroutines, and network conditions for delivering duplicate UDP datagrams close together — it is not a deterministic, single-shot bypass. I could not fully confirm from static reading how many concurrent goroutines actually invoke `Decrypt`/`VerifyRelay` for the *same* `ConnectionState` in practice (i.e., whether routing guarantees typically serialize per-hostinfo delivery), which materially affects real-world likelihood; this would need runtime/dynamic verification (e.g., a stress test racing duplicate UDP injections against a live tunnel) that is outside static analysis.

### Recommendation
Hold `decryptLock` across the entire check-decrypt-update sequence (or otherwise reserve the counter atomically before decrypting, e.g. by having `Check`+"reserve" be a single atomic operation and rolling back to `Update`only on decrypt failure), so no other goroutine can observe the same counter as "not yet consumed" while a decrypt for it is in flight.

### Proof of Concept
Conceptual/logical PoC (not independently executed in this session — flagged as unverified dynamic behavior):
1. Establish a tunnel between two Nebula nodes.
2. Capture one legitimate data-plane UDP packet (header + ciphertext) sent from A to B.
3. From an unauthenticated vantage point on the path, inject two copies of the exact same captured UDP packet to B nearly simultaneously (e.g., via two sockets or a burst send) so they are picked up by two different reader goroutines.
4. If both goroutines' `Check` calls execute before either's `Update` call, both will call `DecryptDanger` successfully and deliver the decrypted payload to the tun device twice, despite the anti-replay window being length-1024 and designed to reject the duplicate.

This mirrors the `TestRelayReplayProtection` test's setup for capturing and replaying a relay frame — [9](#0-8)  — but targets the race window rather than a sequential replay, which that existing test does not exercise.

func (cs *ConnectionState) Decrypt(l *slog.Logger, messageCounter uint64, out []byte, packet []byte, nb []byte) ([]byte, error) {
	var err error
	cs.decryptLock.Lock()
	result := cs.window.Check(l, messageCounter)
	cs.decryptLock.Unlock()
	if !result {
		return nil, ErrAlreadySeen
	}

	out, err = cs.dKey.DecryptDanger(out, packet[:header.Len], packet[header.Len:], messageCounter, nb)
	if err != nil {
		return nil, err
	}

	cs.decryptLock.Lock()
	result = cs.window.Update(l, messageCounter)
	cs.decryptLock.Unlock()
	if !result {
		return nil, ErrAlreadySeen
	}
	return out, nil
}

// VerifyRelay verifies AEAD protected (but not encrypted) relay frames. packet must be length-checked by the caller.
func (cs *ConnectionState) VerifyRelay(l *slog.Logger, messageCounter uint64, packet []byte, nb []byte) error {
	cs.decryptLock.Lock()
	result := cs.window.Check(l, messageCounter)
	cs.decryptLock.Unlock()
	if !result {
		return ErrAlreadySeen
	}

	signedPayload := packet[:len(packet)-cs.dKey.Overhead()]
	signatureValue := packet[len(packet)-cs.dKey.Overhead():]
	_, err := cs.dKey.DecryptDanger(nil, signedPayload, signatureValue, messageCounter, nb)
	if err != nil {
		return err
	}

	cs.decryptLock.Lock()
	result = cs.window.Update(l, messageCounter)
	cs.decryptLock.Unlock()
	if !result {
		return ErrAlreadySeen
	}

	return nil
}

func (b *Bits) Update(l *slog.Logger, i uint64) bool {
	// Fast path: i is the next expected counter. Split out so the function
	// stays small and avoids paying for the slow paths' slog argument-build
	// stack frame on every call. The bit read/test/write is inlined to
	// touch the backing word once.
	if i == b.current+1 {
		pos := i & b.lengthMask
		word := pos >> 6
		mask := uint64(1) << (pos & 63)
		w := b.bits[word]
		if i > b.length && w&mask == 0 {
			b.lostCounter.Inc(1)
		}
		b.bits[word] = w | mask
		b.current = i
		return true
	}
	return b.updateSlow(l, i)
}

// TestRelayReplayProtection asserts that a relay (forwarding-type) node rejects
// replayed relay frames. A captured relay frame, re-injected with the same
// message counter, must be dropped by the replay window rather than re-forwarded
// to the relay target. Before the fix, handleOutsideRelayPacket authenticated the
// frame but never advanced the replay window, so every replay was re-forwarded.
func TestRelayReplayProtection(t *testing.T) {
	t.Parallel()
	ca, _, caKey, _ := cert_test.NewTestCaCert(cert.Version2, cert.Curve_CURVE25519, time.Now(), time.Now().Add(10*time.Minute), nil, nil, []string{})
	myControl, myVpnIpNet, _, _ := newSimpleServer(cert.Version2, ca, caKey, "me     ", "10.128.0.1/24,fc00::1/64", m{"relay": m{"use_relays": true}})
	relayControl, relayVpnIpNet, relayUdpAddr, _ := newSimpleServer(cert.Version2, ca, caKey, "relay  ", "10.128.0.128/24,fc00::128/64", m{"relay": m{"am_relay": true}})
	theirUdp := netip.MustParseAddrPort("10.0.0.2:4242")
	theirControl, theirVpnIpNet, theirUdpAddr, _ := newSimpleServerWithUdp(cert.Version2, ca, caKey, "them   ", "fc00::2/64", theirUdp, m{"relay": m{"use_relays": true}})

	myVpnV6 := myVpnIpNet[1]
	relayVpnV4 := relayVpnIpNet[0]
	relayVpnV6 := relayVpnIpNet[1]
	theirVpnV6 := theirVpnIpNet[0]

	// Teach me how to reach the relay and that them is reachable via the relay
	myControl.InjectLightHouseAddr(relayVpnV4.Addr(), relayUdpAddr)
	myControl.InjectLightHouseAddr(relayVpnV6.Addr(), relayUdpAddr)
	myControl.InjectRelays(theirVpnV6.Addr(), []netip.Addr{relayVpnV6.Addr()})
	relayControl.InjectLightHouseAddr(theirVpnV6.Addr(), theirUdpAddr)

	r := router.NewR(t, myControl, relayControl, theirControl)
	defer r.RenderFlow()

	myControl.Start()
	relayControl.Start()
	theirControl.Start()

	// Establish the relayed tunnel in both directions so all handshakes complete.
	t.Log("Establish the relayed tunnel")
	myControl.InjectTunPacket(BuildTunUDPPacket(theirVpnV6.Addr(), 80, myVpnV6.Addr(), 80, []byte("Hi from me")))
	p := r.RouteForAllUntilTxTun(theirControl)
	assertUdpPacket(t, []byte("Hi from me"), p, myVpnV6.Addr(), theirVpnV6.Addr(), 80, 80)
	theirControl.InjectTunPacket(BuildTunUDPPacket(myVpnV6.Addr(), 80, theirVpnV6.Addr(), 80, []byte("Hi from them")))
	p = r.RouteForAllUntilTxTun(myControl)
	assertUdpPacket(t, []byte("Hi from them"), p, theirVpnV6.Addr(), myVpnV6.Addr(), 80, 80)

	// Drain anything still queued on me's UDP tx so the next packet we pull is the
	// relay frame we are about to generate.
	for myControl.GetFromUDP(false) != nil {
	}

	// Capture a single legitimate relay frame that me transmits toward the relay.
	t.Log("Capture a relay frame from me -> relay")
	myControl.InjectTunPacket(BuildTunUDPPacket(theirVpnV6.Addr(), 80, myVpnV6.Addr(), 80, []byte("replay me")))
	relayFrame := myControl.GetFromUDP(true)
	require.Equal(t, relayUdpAddr, relayFrame.To, "captured frame should be addressed to the relay")
	var fh header.H
	require.NoError(t, fh.Parse(relayFrame.Data))
	require.Equal(t, header.Message, fh.Type)
	require.Equal(t, header.MessageRelay, fh.Subtype)

	// drainForwards counts relay frames the relay forwards toward them within the
	// settle window. We match on destination + (Message, MessageRelay) so the
	// relay's own direct traffic to them can't be miscounted.
	drainForwards := func(settle time.Duration) int {
		ch := relayControl.GetUDPTxChan()
		count := 0
		for {
			select {
			case pkt := <-ch:
				var ph header.H
				if pkt.To == theirUdpAddr && ph.Parse(pkt.Data) == nil &&
					ph.Type == header.Message && ph.Subtype == header.MessageRelay {
					count++
				}
				pkt.Release()
			case <-time.After(settle):
				return count
			}
		}
	}

	// First delivery of the captured frame: the relay should forward it once.
	t.Log("Deliver the captured frame once; relay forwards it to them")
	relayControl.InjectUDPPacket(relayFrame)
	require.Equal(t, 1, drainForwards(200*time.Millisecond), "relay should forward the first, legitimate copy")

	// Replay the exact same frame several times. A correct replay window rejects
	// these duplicates so the relay forwards none of them.
	t.Log("Replay the captured frame; relay must drop the duplicates")
	const replays = 3
	for i := 0; i < replays; i++ {
		relayControl.InjectUDPPacket(relayFrame)
	}
	forwarded := drainForwards(200 * time.Millisecond)
	assert.Equal(t, 0, forwarded, "relay re-forwarded %d/%d replayed relay frames; replay protection is ineffective on relay tunnels", forwarded, replays)
