### Title
Inbound-walk `HandshakeAccept` allows a peer to bind an arbitrary claimed identity to `cur_neighbor`'s PeerDB record - (File: stackslib/src/net/neighbors/walk.rs)

### Summary
`NeighborWalk::handle_handshake_accept` only rejects an address mismatch between the reported `HandshakeData` and `self.cur_neighbor` when `self.walk_outbound` is true. For inbound walks, no such check exists at all, so `update_neighbor` unconditionally applies the reported `handshake.node_public_key`/`expire_block_height` to `self.cur_neighbor` and persists it via `PeerDB`, even though nothing ties that reported public key to the peer actually holding the connection.

### Finding Description
The claimed equality — "identity recorded in `cur_neighbor` == identity of the peer physically answering on this connection" — is only enforced conditionally:

```rust
if self.walk_outbound && neighbor_from_handshake.addr != self.cur_neighbor.addr {
    ...
    return Err(net_error::PeerNotConnected(...));
};
...
if self.walk_outbound || self.first_neighbor.addr != self.cur_neighbor.addr {
    let new_cur_neighbor = self.neighbor_db.update_neighbor(network, cur_neighbor, Some(data), db_data)?;
    self.cur_neighbor = new_cur_neighbor;
}
``` [1](#0-0) 

For an inbound walk (`walk_outbound == false`) that has stepped past the first neighbor (`self.first_neighbor.addr != self.cur_neighbor.addr`, which happens on any subsequent walk step in the MHRWDA frontier walk driven by `step()`), the address-match guard is entirely skipped, and `update_neighbor` is still invoked with the attacker-supplied `HandshakeAcceptData`.

`update_neighbor` calls `cur_neighbor.handshake_update(&tx, &data.handshake)`, which unconditionally overwrites the neighbor's `public_key` and `expire_block` fields from the wire-controlled `HandshakeData`, then persists (`save_update`) to `PeerDB`: [2](#0-1) [3](#0-2) 

The comment in the code explicitly rationalizes skipping the check for inbound walks ("this does not matter for inbound walks, because we don't always know the real address anyway"), but this reasoning only justifies skipping the *address* comparison for NAT reasons — it does not justify skipping validation of the *public key* being written into the DB record keyed by `cur_neighbor.addr`. The result is that `cur_neighbor.public_key` (and `expire_block`) is set from data supplied by whatever peer is answering on the wire, without any check that this claimed public key actually corresponds to that peer's already-known identity, or matches `neighbor_from_handshake`'s address/pubkey pairing.

### Impact Explanation
An attacker who is walked as an inbound neighbor (i.e., who previously connected inbound and was added to the local node's pingback/frontier state, and is later re-contacted as `cur_neighbor` during a subsequent walk step) can supply a forged `node_public_key` (and `expire_block_height`) in its `HandshakeAccept`/`StackerDBHandshakeAccept` reply. This value is written directly into the local `PeerDB` row keyed by that peer's real address via `update_neighbor`/`handshake_update`, and is added to `self.new_frontier`/`self.frontier`, which is later persisted/gossiped to other peers via `replace_neighbors` and further crawl responses. This is an unauthenticated write of attacker-influenced data (the public key field) into the PeerDB, and can propagate a forged public-key/expire-height association for that peer's IP/port across the network's peer walks — matching the "unauthenticated/unauthorized write to state" and "network-wide propagation of forged data" Critical categories.

### Likelihood Explanation
Preconditions: the attacker only needs to be reachable as an inbound peer that the local node's walk state machine treats as `cur_neighbor` in an inbound walk, and the walk must have progressed past the very first neighbor (`self.first_neighbor.addr != self.cur_neighbor.addr`), which is a normal, easily reached state in the random walk (MHRWDA) as `step()` runs repeatedly. No secret, admin role, or victim cooperation is required — a bare TCP connection and a crafted `HandshakeAccept` reply suffice. It is fully repeatable per walk cycle.

### Recommendation
Remove the `self.walk_outbound &&` short-circuit so the address/public-key consistency check between `neighbor_from_handshake` and `cur_neighbor` (or at minimum the public key) is enforced for inbound walks too, or otherwise refuse to call `update_neighbor`/`handshake_update` with attacker-supplied `HandshakeData` unless the reported identity is verified against the already-known `cur_neighbor` record (e.g., only allow first-time key learning, not overwriting an established key without proof of ownership).

### Proof of Concept
Add a test in `stackslib/src/net/neighbors/mod.rs` (or a dedicated `walk` test module) that:
1. Instantiates a `NeighborWalk` with `walk_outbound = false` and a `cur_neighbor` whose `addr` differs from `self.first_neighbor.addr` (simulate having already stepped once).
2. Constructs a `HandshakeAcceptData` whose embedded `HandshakeData.node_public_key` is a freshly generated keypair unrelated to the real peer, with `addrbytes`/`port` matching `cur_neighbor.addr` (or differing, since the address check is skipped anyway).
3. Calls `handle_handshake_accept` with this crafted data.
4. Asserts `self.cur_neighbor.public_key` now equals the attacker's forged key (demonstrating the bug) — the fix should instead cause an `Err` or leave `public_key` unchanged, asserted via `assert_ne!(self.cur_neighbor.public_key, forged_pubkey)`.

    fn update_neighbor(
        &self,
        network: &mut PeerNetwork,
        mut cur_neighbor: Neighbor,
        new_data: Option<&HandshakeAcceptData>,
        new_db_data: Option<&StackerDBHandshakeData>,
    ) -> Result<Neighbor, net_error> {
        let tx = network.peerdb_tx_begin()?;

        if let Some(data) = new_data {
            cur_neighbor.handshake_update(&tx, &data.handshake)?;
        }

        if let Some(db_data) = new_db_data {
            cur_neighbor.save_update(&tx, Some(db_data.smart_contracts.as_slice()))?;
        } else {
            cur_neighbor.save_update(&tx, None)?;
        }

        tx.commit()?;
        Ok(cur_neighbor)
    }

    pub fn handshake_update(
        &mut self,
        conn: &DBConn,
        handshake_data: &HandshakeData,
    ) -> Result<(), net_error> {
        let pubk = handshake_data
            .node_public_key
            .to_public_key()
            .map_err(|e| net_error::DeserializeError(e.into()))?;
        let asn_opt =
            PeerDB::asn_lookup(conn, &handshake_data.addrbytes).map_err(net_error::DBError)?;

        let asn = match asn_opt {
            Some(a) => a,
            None => 0,
        };

        self.public_key = pubk;
        self.expire_block = handshake_data.expire_block_height;
        self.last_contact_time = get_epoch_time_secs();

        if asn != 0 {
            self.asn = asn;
            self.org = asn; // TODO; AS number is a place-holder for an organization ID (an organization can own multiple ASs)
        }

        Ok(())
    }
