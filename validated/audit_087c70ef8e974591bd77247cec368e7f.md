### Title
Client-Supplied `GitObjectDirectory`/`GitAlternateObjectDirectories` Fields Bypass Storage/Repository Containment Checks When Building Git Subprocess Environment - (File: internal/git/alternates/alternates.go, internal/git/gitcmd/command_factory.go)

### Summary
Gitaly builds `GIT_OBJECT_DIRECTORY`/`GIT_ALTERNATE_OBJECT_DIRECTORIES` environment variables for every spawned git subprocess directly from the client-supplied `Repository.GitObjectDirectory` and `Repository.GitAlternateObjectDirectories` proto fields, without applying the same path-containment validation that other code paths in the same codebase enforce for the identical data. This mirrors the WETH `approve(address owner, address spender)` bug class: a function trusts an externally supplied "identity"/location parameter (here, an object-directory path) instead of relying on the validated, derived value the rest of the system expects (a quarantine directory generated internally by Gitaly).

### Finding Description
`alternates.Env` unconditionally joins the caller-supplied directories with the repository path and emits them as environment variables: [1](#0-0) 

This is invoked from `ExecCommandFactory.newCommand` for essentially every git subprocess Gitaly spawns, using the `Repository` proto message from the incoming RPC request: [2](#0-1) 

Elsewhere in the codebase, the exact same fields (`GetGitObjectDirectory()`) are validated with `storage.ValidateRelativePath` and an explicit quarantine-prefix check before being trusted as a filesystem path: [3](#0-2) 

Likewise, the file-based alternates resolution mechanism (`objects/info/alternates`) explicitly rejects any alternate directory that escapes the storage root: [4](#0-3) 

No equivalent check exists in `alternates.Env`/`newCommand`. The storagemgr transaction middleware even documents this as a known, unaddressed gap: it explicitly notes that manually configuring `GitObjectDirectory`/`GitAlternateObjectDirectories` on a request "allows for circumventing the transaction management," and defers fixing it: [5](#0-4) 

Because `filepath.Join` cleans `..` segments, a client that sets `GitAlternateObjectDirectories` to a relative path such as `"../../other-storage/other-repo.git/objects"` on any accessor RPC will cause Gitaly to spawn git with `GIT_ALTERNATE_OBJECT_DIRECTORIES` pointing outside the target repository — and outside the storage root entirely — with no containment check comparable to `alternateOutsideStorageError` or `ObjectDirectoryPath`'s validation.

### Impact Explanation
Any RPC that runs through `ExecCommandFactory.newCommand` with a `Repository` message whose `GitObjectDirectory`/`GitAlternateObjectDirectories` are attacker-controlled can direct the spawned git process to read objects from an arbitrary directory that the caller specifies, rather than the object pool/quarantine directory Gitaly itself would have derived. This breaks repository/tenant isolation for object visibility: objects from another repository (or any readable directory on the host matching a Git object layout) can be exposed through RPCs like `FindCommits`, `GetObjectDirectorySize`, or other accessor calls that echo back quarantine-style directories, effectively defeating the purpose of the quarantine/alternates isolation model documented in `doc/object_quarantine.md`.

### Likelihood Explanation
The `GitObjectDirectory`/`GitAlternateObjectDirectories` fields are normal, client-settable fields on the `Repository` proto message accepted by many RPCs (this is exactly the mechanism Rails uses during pre-receive access checks, so the code path is definitely reachable by "ordinary" callers with gRPC access, e.g., via a crafted RPC field). The middleware's own comments confirm this is a real, currently-unmitigated behavior rather than a hypothetical one.

### Recommendation
Route `GitObjectDirectory`/`GitAlternateObjectDirectories` through the same validation used in `localrepo.Repo.ObjectDirectoryPath` (or an equivalent `storage.ValidateRelativePath` + quarantine-prefix check) before they are used to build the `GIT_OBJECT_DIRECTORY`/`GIT_ALTERNATE_OBJECT_DIRECTORIES` environment variables in `alternates.Env`/`newCommand`. Reject any resulting path that escapes the storage root or does not match the internally generated quarantine directory prefix, consistent with the containment logic already implemented in `internal/git/dirs.go` and `internal/git/localrepo/paths.go`.

### Proof of Concept
1. Obtain gRPC access to Gitaly sufficient to call any accessor RPC accepting a `Repository` message (e.g., `FindCommits`).
2. Craft the request with `Repository.RelativePath` set to a legitimate repository, but `GitAlternateObjectDirectories` set to `["../../other-storage-sibling/target-repo.git/objects"]`.
3. Observe that `command_factory.go`'s `newCommand` builds `GIT_ALTERNATE_OBJECT_DIRECTORIES` via `alternates.Env` with no containment check (contrast with the `alternateOutsideStorageError` check present in `internal/git/dirs.go` for the file-based mechanism), and the git subprocess is spawned with that environment.
4. The RPC response can then reveal object data (e.g., commit metadata) sourced from `target-repo.git/objects`, which the caller was never authorized to access directly.

// Env returns the alternate object directory environment variables.
func Env(repoPath, objectDirectory string, alternateObjectDirectories []string) []string {
	var env []string
	if objectDirectory != "" {
		env = append(env, fmt.Sprintf("GIT_OBJECT_DIRECTORY=%s", filepath.Join(repoPath, objectDirectory)))
	}

	if len(alternateObjectDirectories) > 0 {
		var dirsList []string

		for _, dir := range alternateObjectDirectories {
			dirsList = append(dirsList, filepath.Join(repoPath, dir))
		}

		env = append(env, fmt.Sprintf("GIT_ALTERNATE_OBJECT_DIRECTORIES=%s", strings.Join(dirsList, ":")))
	}

	return env
}

	if err != nil {
		return "", fmt.Errorf("get storage by name: %w", err)

	// Ensure the path points somewhere in the storage.
	relativeObjectDirectoryPath, err := storage.ValidateRelativePath(storagePath, filepath.Join(repoPath, objectDirectoryPath))
	if err != nil {
		return "", structerr.NewInvalidArgument("validate relative path: %w", err)
	}

	parentDir := filepath.Base(filepath.Dir(relativeObjectDirectoryPath))
	baseDir := filepath.Base(relativeObjectDirectoryPath)
	isTransactionQuarantineDir := (baseDir == "quarantine") || ((parentDir == "quarantine") && strings.HasPrefix(baseDir, "tmp_objdir"))

	// Transactions quarantine a repository by pointing the object directory to a 'quarantine' named
	// directory in the transaction's temporary directory. If the base directory is `quarantine`,
	// Git push may apply an additional layer of quarantine such as `/quarantine/tmp_objdir-incoming-Gbc29N`
	// so we don't assert the `/quarantine` being the last element of the path. We thus also check for
	// whether the parent directory is in `quarantine` and whether the base directory has the expected
	// `tmp_objdir` suffix.
	if !isTransactionQuarantineDir {
		// We need to check whether the relative object directory as given by the repository is
		// a valid path. This may either be a path in the Git repository itself, where it may either
		// point to the main object directory storage or to an object quarantine directory as
		// created by git-receive-pack(1). Alternatively, if that is not the case, then it may be a
		// manual object quarantine directory located in the storage's temporary directory. These
		// have a repository-specific prefix which we must check in order to determine whether the
		// quarantine directory does in fact belong to the repo at hand.
		if _, origError := storage.ValidateRelativePath(repoPath, objectDirectoryPath); origError != nil {
			tempDir, err := repo.locator.TempDir(repo.GetStorageName())
			if err != nil {
				return "", structerr.NewInvalidArgument("getting storage's temporary directory: %w", err)
			}

			expectedQuarantinePrefix := filepath.Join(tempDir, storage.QuarantineDirectoryPrefix(repo))
			absoluteObjectDirectoryPath := filepath.Join(repoPath, objectDirectoryPath)

			// The relative path is outside of the repository
			if !strings.HasPrefix(absoluteObjectDirectoryPath, expectedQuarantinePrefix) {
				return "", structerr.NewInvalidArgument("not a valid relative path: %w", origError)
			}
		}
	}
