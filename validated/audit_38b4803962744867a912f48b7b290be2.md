### Title
Unauthenticated injection of forged `NewBlock`/`NewBurnBlock` signer events via `/new_block` and `/new_burn_block` - (File: libsigner/src/events.rs)

### Summary
`SignerEventReceiver::next_event` dispatches any HTTP POST to `/new_block` or `/new_burn_block` straight into `process_event::<T, StacksBlockEvent>` / `process_event::<T, BurnBlockEvent>` with no signature, secret, or origin check, then converts the parsed JSON directly into `SignerEvent::NewBlock`/`SignerEvent::NewBurnBlock` and forwards it to the signer runloop. Any remote party who can reach the bound event-receiver TCP port can craft an arbitrary JSON body and have it accepted as an indistinguishable, genuine node-originated event.

### Finding Description
The routing in `next_event` matches on `request.url()` alone and performs `process_event::<T, StacksBlockEvent>(request)`/`process_event::<T, BurnBlockEvent>(request)` for these two routes with no prior authentication step: [1](#0-0) 

`process_event` simply reads the HTTP body, parses it as JSON into the target struct, and converts it via `TryInto<SignerEvent<T>>` — there is no header check, no shared-secret comparison, no peer-address allow-listing anywhere in this function or in `SignerEventReceiver::bind`/`next_event`: [2](#0-1) 

The `StacksBlockEvent` and `BurnBlockEvent` payload fields (`index_block_hash`, `consensus_hash`, `block_hash`, `block_height`, `transactions`, `burn_block_height`, `burn_block_hash`, etc.) are fully attacker-controlled via JSON and are copied verbatim into `SignerEvent::NewBlock`/`SignerEvent::NewBurnBlock`: [3](#0-2) [4](#0-3) 

The resulting event is forwarded verbatim to the signer runloop via `forward_event`: [5](#0-4) 

Checking for any authentication mechanism that could apply here: the only `auth_token`/`auth_password` mechanism in the codebase protects the *node's* `postblock_proposal` RPC endpoint (i.e., authenticates the signer/miner calling into the node), not the signer's own event-receiver HTTP server that the node POSTs events into. There is no equivalent secret check on the `libsigner` side for `/new_block` or `/new_burn_block`. The bind address itself (`0.0.0.0:30000` in sample configs) is often not restricted to loopback, meaning this port can be remotely reachable if the operator does not separately firewall it. The equality the code implicitly assumes — "every `NewBlock`/`NewBurnBlock` event equals one produced by the trusted local node" — is broken: any TCP-reachable client can produce that same event.

### Impact Explanation
An attacker with TCP reachability to the signer's event-receiver port can inject arbitrary, forged `SignerEvent::NewBlock`/`SignerEvent::NewBurnBlock` notifications (fake `block_id`, `consensus_hash`, `transactions`, `burn_height`, `burn_header_hash`) into the signer's internal transport/runloop channel, indistinguishable from genuine node-sourced events. This is unauthenticated write into the signer's internal state/transport layer and is fully repeatable per message (no rate limiting or nonce). This matches the "unauthenticated/unauthorized write to state" Critical category, scoped strictly to the transport surfacing of forged chain-state notifications (downstream signer-decision consequences are explicitly out of scope for this finding).

### Likelihood Explanation
Preconditions are minimal: only network reachability to the bound event-receiver address (e.g., `0.0.0.0:30000` per sample configs) and no privileged role, secret, or key are required. The attacker cost is a single crafted HTTP POST with valid JSON; the attack is fully repeatable and requires no target state beyond the receiver being bound and listening.

### Recommendation
Add authentication to the signer's event-receiver HTTP server (e.g., require and verify a shared-secret header matching the node's configured value, mirroring the `auth_token`/`auth_password` pattern already used for the node's RPC-side block-proposal endpoint) before calling `process_event` for `/new_block`, `/new_burn_block`, `/stackerdb_chunks`, and `/proposal_response`. Additionally/alternatively, document and enforce binding this listener to loopback-only or an authenticated reverse proxy by default.

### Proof of Concept
Rust test plan (to add under `libsigner/src/events.rs` `tests` module or a new integration test):
1. Instantiate `SignerEventReceiver::<StacksMessage>::new(false)`, `bind` to `127.0.0.1:0` (ephemeral port), call `add_consumer` with a channel, spawn `main_loop` in a thread.
2. From a separate "attacker" thread/`TcpStream` (no relation to any node), POST a hand-crafted JSON body to `http://<bound_addr>/new_block`:
```json
{
  "index_block_hash": "0x00..00",
  "consensus_hash": "0x00..00",
  "block_hash": "0x00..00",
  "block_height": 999999,
  "transactions": []
}
```
3. Assert the consumer channel receives `SignerEvent::NewBlock { block_id, consensus_hash, block_height: 999999, .. }` matching the forged values, with no error or rejection — demonstrating `process_event::<T, StacksBlockEvent>` in `libsigner/src/events.rs` accepted and forwarded the attacker's payload as a legitimate event.
4. Repeat for `/new_burn_block` with a forged `BurnBlockEvent` JSON body and assert `SignerEvent::NewBurnBlock{ burn_height, .. }` is received unchanged.

    /// Forward an event
    /// Return true on success; false on error.
    /// Returning false terminates the event receiver.
    fn forward_event(&mut self, ev: SignerEvent<T>) -> bool {
        if self.out_channels.is_empty() {
            // nothing to do
            error!("No channels connected to event receiver");
            false
        } else if self.out_channels.len() == 1 {
            // avoid a clone
            if let Err(e) = self.out_channels[0].send(ev) {
                error!("Failed to send to signer runloop: {:?}", &e);
                return false;
            }
            true
        } else {
            for (i, out_channel) in self.out_channels.iter().enumerate() {
                if let Err(e) = out_channel.send(ev.clone()) {
                    error!("Failed to send to signer runloop #{}: {:?}", i, &e);
                    return false;
                }
            }
            true
        }
    }

fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}
