The chain_id and signer_id checks are enforced in `contracts/wallet/src/contract.rs::execute_signed`, not in `schema.rs`. Before the nonce is committed or `S::verify_request_msg` is even called, the code explicitly checks `msg.chain_id != env::chain_id()` and `msg.signer_id != env::current_account_id()`, returning (and ultimately panicking on) `Error::InvalidChainId` / `Error::InvalidSignerId` respectively. [1](#0-0) 

`schema.rs`'s `verify_request_msg` is solely responsible for cryptographic proof verification and is documented as such — it is not the enforcement point for chain/signer binding, and the actual entrypoint `execute_signed` never reaches nonce-commit or signature verification unless both checks pass first, so no request for a foreign chain or a sibling wallet's `signer_id` can be executed against this wallet. [2](#0-1) [3](#0-2)
