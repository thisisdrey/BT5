## Analysis

The binding claimed to be broken: **fee_collected(token T, batch) == Pips::fee_ceil(fee, Σ|negative deltas of T|)** — i.e. the total fee credited to `fee_collector` for token `T` across a batch should depend only on the aggregate amount of `T` sold, not on how that sale is split across intents.

Tracing `TokenDiff::execute_intent`, the fee is computed **per intent, per token**, strictly from that single intent's own `delta`: [1](#0-0) 

and the fee-exemption rule in `TokenDiff::token_fee` is: [2](#0-1) 

`token_fee` returns `Pips::ZERO` for `Nep245`/`Imt` whenever `amount <= 1`, regardless of how many separate intents move that token within the same batch. There is no batch-level aggregation of deltas per token before the fee is applied — `Engine::execute_signed_intents` simply loops over each signed payload's intents and calls `TokenDiff::execute_intent` independently: [3](#0-2) 

`TransferMatcher`/`finalize()` only enforces that the whole batch's balance changes net to zero (conservation of value) — it does not participate in fee calculation and does not re-aggregate per-token deltas for fee purposes: [4](#0-3) 

So an unprivileged signer holding 1000 units of a `Nep245` token can sign 1000 separate `TokenDiff` intents (each with a unique nonce), each with `diff = { T: -1, Y: +k }`, submitted together in one `MultiPayload` batch (paired against a counterparty's matching legs, or their own matched legs, so the batch still nets to zero). For every leg, `token_fee(Nep245, 1, fee)` returns `Pips::ZERO`, so `fee_ceil(1) == 0`. The cumulative fee collected is `0`, versus `fee.fee_ceil(1000)` if the same net trade had been expressed as one `TokenDiff` with `delta = -1000`. No guard (`verify`, nonce checks, `TransferMatcher::finalize`, `assert_one_yocto`) inspects cross-intent aggregate amounts per token, so nothing prevents this split.

This is a genuine, reproducible fee-bypass on `Nep245`/`Imt` token types, matching the Critical category "protocol fees bypassed."

### Title
TokenDiff fee bypass via unit-splitting on Nep245/Imt tokens - (File: `contracts/defuse/core/src/intents/token_diff.rs`)

### Summary
`TokenDiff::token_fee` waives fees on `Nep245`/`Imt` tokens whenever the per-intent `|delta| <= 1`, but this exemption is evaluated purely per-intent with no aggregation across a batch. An attacker can split a large `Nep245` sale into many unit-sized (`delta == -1`) `TokenDiff` intents signed in a single `MultiPayload`, causing the total fee credited to `fee_collector` to be zero instead of `fee.fee_ceil(total_amount)`.

### Finding Description
The broken binding: total fee credited for token `T` in a batch should equal `Pips::fee_ceil(fee, Σ|negative deltas of T|)`, but the code computes it as `Σ fee_ceil_per_intent(delta_i)`, and `fee_ceil_per_intent` is `0` whenever `|delta_i| <= 1` for `Nep245`/`Imt`: [5](#0-4) [2](#0-1) 

Root cause: the fee-exemption threshold (`amount <= 1` for NFT-like semantics) is checked against the delta of a single `TokenDiff` intent, not against the aggregate flow of that token across the whole signed batch. Since `Engine::execute_signed_intents` and `TransferMatcher::finalize` only enforce overall balance conservation (not fee correctness), a signer can decompose one economically large trade into many `delta == ±1` legs, each independently qualifying for the zero-fee exemption.

Attacker payload: 1000 signed `TokenDiff` intents (unique nonces, same signer or matched counterparties), each `diff = {T: -1, Y: +k}`, batched into one `execute_intents(signed: Vec<MultiPayload>)` call, versus the honest equivalent of one `TokenDiff` with `diff = {T: -1000, Y: +1000k}`.

### Impact Explanation
The protocol fee normally credited to `fee_collector` via `internal_add_balance` for a `Nep245`/`Imt` trade is entirely bypassed — for a 1000-unit trade, the collector receives `0` instead of `fee.fee_ceil(1000)`. This is repeatable indefinitely by any signer, for any `Nep245`/`Imt` token, in every batch, with no cap on transaction size beyond gas/tx-size limits. This matches the Critical category "protocol fees bypassed."

### Likelihood Explanation
Preconditions are minimal and fully within an unprivileged signer's control: hold any amount of a `Nep245`/`Imt` token, a nonzero protocol fee, and the ability to sign and submit N intents in one `MultiPayload` batch (each just needs a distinct nonce, which any signer can generate freely). No special role or relayer key is required. The only cost is proportionally larger transaction/gas size for more legs, which does not block feasibility for economically significant trades.

### Recommendation
Compute `token_fee`'s exemption threshold against the aggregate absolute delta of the same token across the whole batch (or across all `TokenDiff` intents by the same signer within one `execute_signed_intents` call), not per individual intent's delta. Alternatively, remove the `amount <= 1` exemption for `Nep245`/`Imt` transfers unless the token is provably non-fungible (e.g., verified `Nep171`-style single-supply asset), since NEP245 fungible sub-tokens can represent arbitrarily large per-unit value.

### Proof of Concept
`cargo test` (near-workspaces sandbox) plan:
1. Deploy a `Nep245` (MT) contract; deposit `1000` units of token `T` to attacker's Verifier balance; set nonzero `fee` (e.g. `Pips::ONE_PERCENT`) and a `fee_collector`.
2. Batch A ("honest"): sign one `TokenDiff{ diff: {T: -1000, Y: +closure} }`, submit via `execute_intents`; assert `fee_collector` balance of `T`-fee token equals `fee.fee_ceil(1000)` (nonzero).
3. Batch B ("split"): sign 1000 separate `TokenDiff{ diff: {T: -1, Y: +closure_i} }` intents (unique nonces), submit all in one `MultiPayload` vector via `execute_intents`; assert `fee_collector`'s resulting fee balance is `0`.
4. Assert `fee_collected(Batch B) < fee_collected(Batch A)`, specifically `fee_collected(Batch B) == 0` while `fee_collected(Batch A) == fee.fee_ceil(1000) > 0`, proving the FEES binding is violated.

    fn execute_signed_intent(&mut self, signed: MultiPayload) -> Result<()> {
        // verify signed payload and get public key
        let public_key = signed.verify().ok_or(DefuseError::InvalidSignature)?;

        // calculate intent hash
        let hash = signed.hash();

        // extract NEP-413 payload
        let DefusePayload::<DefuseIntents> {
            signer_id,
            verifying_contract,
            deadline,
            nonce,
            message: intents,
        } = signed.extract_defuse_payload()?;

        // check recipient
        if verifying_contract != *self.state.verifying_contract() {
            return Err(DefuseError::WrongVerifyingContract);
        }

        self.inspector.on_deadline(deadline);

        // make sure message is still valid
        if deadline < Timestamp::now() {
            return Err(DefuseError::DeadlineExpired);
        }

        // make sure the account has this public key
        if !self.state.has_public_key(&signer_id, &public_key) {
            return Err(DefuseError::PublicKeyNotExist(signer_id, public_key));
        }

        // commit nonce
        self.verify_intent_nonce(nonce, deadline)?;
        self.state.commit_nonce(signer_id.clone(), nonce)?;

        intents.execute_intent(&signer_id, self, hash)?;
        self.inspector.on_intent_executed(&signer_id, hash, nonce);

        Ok(())
    }

/// Accumulates internal deposits and withdrawals on different tokens
/// to match transfers using `.finalize()`
///
/// Transfers in `TokenDiff` intents are represented as deltas without receivers.
/// This struct accumulates tokens all transfers, and converts them from deltas, to
/// a set of transfers from one account to another.
/// Note that this doesn't touch account balances. The balances were already changed
/// in an earlier stage while executing the intent.
#[derive(Debug, Default)]
pub struct TransferMatcher(HashMap<TokenId, TokenTransferMatcher>);

impl TransferMatcher {
    #[inline]
    pub fn new() -> Self {
        Self(HashMap::new())
    }

    #[inline]
    pub fn deposit(&mut self, owner_id: AccountId, token_id: TokenId, amount: u128) -> bool {
        self.0.entry_or_default(token_id).deposit(owner_id, amount)
    }

    #[inline]
    pub fn withdraw(&mut self, owner_id: AccountId, token_id: TokenId, amount: u128) -> bool {
        self.0.entry_or_default(token_id).withdraw(owner_id, amount)
    }

    #[inline]
    pub fn add_delta(&mut self, owner_id: AccountId, token_id: TokenId, delta: i128) -> bool {
        self.0.entry_or_default(token_id).add_delta(owner_id, delta)
    }

    // Finalizes all transfers, or returns unmatched deltas.
    // If unmatched deltas overflow, then Err(None) is returned.
    pub fn finalize(self) -> Result<Transfers, InvariantViolated> {
        let mut transfers = Transfers::default();
        let mut deltas = TokenDeltas::default();
        for (token_id, transfer_matcher) in self.0 {
            if let Err(unmatched) = transfer_matcher.finalize_into(&token_id, &mut transfers)
                && (unmatched == 0 || deltas.apply_delta(token_id, unmatched).is_none())
            {
                return Err(InvariantViolated::Overflow);
            }
        }
        if !deltas.is_empty() {
            return Err(InvariantViolated::UnmatchedDeltas {
                unmatched_deltas: deltas,
            });
        }
        Ok(transfers)
    }
}
