### Title
Global `overall_connection_rate_limiter` admission gate has no per-source-IP contribution cap or stake reservation, allowing IP-distributed unstaked flood to starve TPU connection admission for all peers - ([File: streamer/src/nonblocking/quic.rs])

### Summary
`run_server` gates every incoming QUIC connection with a single shared `TokenBucket` (`overall_connection_rate_limiter`, capacity `MAX_CONNECTION_BURST=1000`, refill `TOTAL_CONNECTIONS_PER_SECOND=2500`) that is checked and consumed before any stake information is known. Because this bucket is keyed globally (not per-IP and not per-stake), an attacker who owns many distinct source IPs (e.g. rotating through an IPv6 prefix) can keep each IP's contribution below the much more generous per-IP `ConnectionRateLimiter` threshold while collectively draining the shared global budget, denying admission to legitimate staked and unstaked peers alike.

### Finding Description
In `run_server` (`streamer/src/nonblocking/quic.rs:270-281`), two independent limiters are constructed:
- `rate_limiter`: a per-IP `ConnectionRateLimiter` seeded with `max_connections_per_ipaddr_per_min` (default 8/min) and `10x` burst (80).
- `overall_connection_rate_limiter`: a single global `TokenBucket` shared by every connection regardless of source IP or stake, refilling at only `2500`/s with `1000` burst.

Admission order in the accept loop (`streamer/src/nonblocking/quic.rs:346-369`) checks the global bucket first (`overall_connection_rate_limiter.current_tokens() == 0`) and only then the per-IP bucket. After the QUIC handshake completes, `setup_connection` (`streamer/src/nonblocking/quic.rs:483-508`) registers the per-IP token and then consumes one token from the *same shared global bucket* (`overall_connection_rate_limiter.consume_tokens(1)`), still before stake is resolved via `get_connection_stake`/`qos.build_connection_context`.

Because the global bucket has no per-key partitioning, any peer's successful connection consumes from the same finite pool available to everyone else on that TPU endpoint. The per-IP limiter (`ConnectionRateLimiter`, `streamer/src/nonblocking/connection_rate_limiter.rs:16-29`) only bounds requests *from a single IP*; it does nothing to prevent many distinct IPs from each staying under their individual quota while summing well past `TOTAL_CONNECTIONS_PER_SECOND`. Stake-aware admission logic (`SwQos::try_add_connection`, `streamer/src/nonblocking/swqos.rs:344-414`) only runs *after* both rate limiters have already passed, so it cannot rescue a legitimate staked peer whose connection was already rejected/ignored by the shared global gate.

### Impact Explanation
This is a TPU-wide connection admission Denial of Service: while the attacker sustains real completed QUIC handshakes from enough distinct source IPs to exceed `2500`/s aggregate (each individual IP staying below its `~0.13`/s sustained / 80 burst allowance), every other incoming connection — including from staked validators/forwarders — hits `overall_connection_rate_limiter.current_tokens() == 0` at `streamer/src/nonblocking/quic.rs:347` and is dropped via `incoming.ignore()`, or fails the post-handshake `consume_tokens` check at line 495 and is closed with `CONNECTION_CLOSE_CODE_DISALLOWED`. No reservation exists for staked peers in this global gate, so legitimate transaction ingress to the leader's TPU can be starved cluster-wide for the duration of the attack.

### Likelihood Explanation
The attacker needs no stake, no validator/gossip control, and no packet spoofing — only the ability to bind and complete real QUIC handshakes from many distinct, real source IP addresses (readily available via IPv6 prefix allocation on commodity cloud/VPS providers, or many IPv4 addresses). Sustaining slightly above 2500 completed handshakes/sec split across enough IPs (e.g., a few hundred IPs each opening a handful of connections per second, well under the per-IP `80` burst / `8`-per-minute steady rate) is operationally feasible and requires no coordination with any staked/leader/gossip entity.

### Recommendation
Partition or weight the global admission budget by stake (e.g., reserve a fraction of `overall_connection_rate_limiter` tokens exclusively for staked peers, or move the global check to run after stake resolution with separate staked/unstaked buckets), and/or bound the maximum contribution any single unstaked IP/subnet can make toward the shared token pool so that distributing load across many IPs cannot bypass the intended fairness guarantee.

    // and default per-IP limits (8/min, 80 burst).
    let SpawnTestServerResult { stats, server_address, cancel, .. } =
        setup_quic_server(/* staked_nodes with one staked peer for control */ ..);

    // Spawn N (>1000) distinct synthetic source IPs (e.g. loopback-bound IPv6 addresses
    // ::1..::N on a test namespace, or mocked SocketAddr in a unit-level TokenBucket test),
    // each opening 1-2 connections concurrently -- individually under the per-IP burst (80)
    // but summing above MAX_CONNECTION_BURST + TOTAL_CONNECTIONS_PER_SECOND.
    let handles: Vec<_> = (0..2000)
        .map(|i| tokio::spawn(make_client_endpoint_from_ip(synthetic_ip(i), &server_address)))

    // demonstrating starvation of legitimate/staked admission by IP-distributed unstaked load.
    assert!(staked_conn.is_err() /* or closed with CONNECTION_CLOSE_REASON_DISALLOWED */);
