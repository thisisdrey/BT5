### Title
Per-connection stream throttling in `SwQos` allows unstaked connection-churn to bypass the aggregate `MAX_UNSTAKED_TPS` cap - ([File: streamer/src/nonblocking/stream_throttle.rs])

### Summary
`StakedStreamLoadEMA::available_load_capacity_in_throttling_duration` returns a fixed constant, `max_unstaked_load_in_throttling_window`, for every unstaked connection regardless of how many unstaked connections currently exist. Since `throttle_stream` is applied independently per `ConnectionStreamCounter` (one per connection), an attacker who opens multiple unstaked connections from a single IP can multiply the aggregate accepted stream rate by the number of connections instead of being bounded by the intended global `MAX_UNSTAKED_TPS`.

### Finding Description
`StakedStreamLoadEMA::new` computes `max_unstaked_load_in_throttling_window = MAX_UNSTAKED_TPS * STREAM_THROTTLING_INTERVAL_MS / 1000` once, as a flat constant derived from the global `MAX_UNSTAKED_TPS = 200` design target [1](#0-0) . This same value is handed back for *every* unstaked connection via `available_load_capacity_in_throttling_duration` with no division by the number of active unstaked connections [2](#0-1) .

In `SwQos::on_new_stream`, each connection carries its own `SwQosConnectionContext::stream_counter: Arc<ConnectionStreamCounter>`, created fresh in `cache_new_connection` via `Arc::new(ConnectionStreamCounter::new())` when the connection is admitted into the connection table [3](#0-2) . `throttle_stream` only checks and increments this per-connection counter against `max_streams_per_throttling_interval` (the same fixed constant for every unstaked connection) [4](#0-3) , and `max_streams_per_throttling_interval` is computed per-call from `SwQos::max_streams_per_throttling_interval` [5](#0-4) .

Because there is no shared, cross-connection accounting for unstaked stream throughput — only a per-IP connection-count cap (`max_connections_per_unstaked_peer`, from `SwQosConfig`) — an attacker who opens `N` unstaked connections from one IP (up to `max_connections_per_unstaked_peer`, default value not fully confirmed from index but present in `DEFAULT_MAX_QUIC_CONNECTIONS_PER_UNSTAKED_PEER`) can drive each connection at the per-connection cap of `max_unstaked_load_in_throttling_window` streams per `STREAM_THROTTLING_INTERVAL` (100 ms). The aggregate accepted-stream rate then scales as `N * max_unstaked_load_in_throttling_window`, exceeding the intended global `MAX_UNSTAKED_TPS` design budget by a factor of `N`. Global unstaked connection admission is bounded only by `SwQosConfig::max_unstaked_connections` (with LRU pruning in `prune_unstaked_connection_table`) [6](#0-5) , not by aggregate stream rate, so the amplification factor can reach the full `max_unstaked_connections` (or `max_concurrent_connections`, which is 1.25× staked+unstaked totals) [7](#0-6) .

The staked path (`StakedStreamLoadEMA::increment_load` / `staked_throttling_enabled`) has a shared EMA that reacts to aggregate staked load, but this shared feedback mechanism only applies to staked traffic (`increment_load` only updates `load_in_recent_interval` for staked peers) [8](#0-7) ; the unstaked cap remains a static per-connection constant with no cross-connection aggregation or feedback.

### Impact Explanation
This is a remote, unprivileged DoS/QoS-evasion vector on the leader's TPU ingress path: an attacker can amplify unstaked stream ingress by opening additional short-lived/parallel connections, defeating the intended `MAX_UNSTAKED_TPS` budget that exists specifically to bound unstaked load's impact on downstream `sigverify`/banking-stage capacity relative to staked traffic. This matches the "QoS evasion" / "banking-stage ingress DoS" bounty category rather than a consensus-safety bug — no invalid block or fund-loss is produced, but validator ingress resources (stream acceptance, sigverify queue) can be consumed disproportionately by unstaked, unprivileged clients.

### Likelihood Explanation
Preconditions are entirely within reach of an unprivileged remote client: it only needs to open multiple concurrent QUIC connections to the public TPU port, each of which is naturally unstaked and independently gets a fresh `ConnectionStreamCounter`. The connection admission path (`prune_unstaked_connections_and_add_new_connection`) does not require any special stake or configuration and is reachable simply by connecting quickly enough to stay under `max_unstaked_connections`/`max_concurrent_connections` before pruning triggers. The exploit is a straightforward connection-churn strategy with no timing subtleties beyond opening connections in parallel, making it highly feasible and repeatable.

### Recommendation
Track aggregate unstaked stream load with a shared counter (analogous to the staked `StakedStreamLoadEMA.load_in_recent_interval`), and make `available_load_capacity_in_throttling_duration(Unstaked, ...)` divide the fixed unstaked budget by the current count of active unstaked connections (or enforce a single shared token-bucket across all unstaked connections) so that the effective per-connection allowance shrinks as more unstaked connections are opened, keeping the aggregate bounded by `MAX_UNSTAKED_TPS` regardless of `N`.

### Proof of Concept
Integration test plan (in `streamer/src/nonblocking/swqos.rs` or a new integration test under `streamer/tests`):
1. Construct a `SwQos` with `SwQosConfig { max_unstaked_connections: K, max_connections_per_unstaked_peer: K, .. }` for some `K > 1`.
2. Spawn `K` concurrent tasks, each simulating a distinct unstaked connection from the same source IP: call `build_connection_context` → `try_add_connection` → repeatedly call `on_new_stream`/`throttle_stream` as fast as possible for a duration of `STREAM_THROTTLING_INTERVAL` (100 ms).
3. Sum the total number of streams accepted (not throttled) across all `K` connections within that 100 ms window.
4. Assert failure of the invariant: total accepted streams ≈ `K * max_unstaked_load_in_throttling_window` (e.g., `K * 20` with defaults), which is `K` times larger than the intended aggregate budget `MAX_UNSTAKED_TPS * STREAM_THROTTLING_INTERVAL_MS / 1000 == 20`. Expected (buggy) result: total scales linearly with `K` instead of being capped at a single connection's worth of throughput, demonstrating the per-IP aggregate limit is not enforced.

    pub(crate) fn available_load_capacity_in_throttling_duration(
        &self,
        peer_type: ConnectionPeerType,
        total_stake: u64,
    ) -> u64 {
        match peer_type {
            ConnectionPeerType::Unstaked => self.max_unstaked_load_in_throttling_window,
            ConnectionPeerType::Staked(stake) => {
                if self.staked_throttling_enabled.load(Ordering::Relaxed) {
                    // 1 is added to `max_unstaked_load_in_throttling_window` to guarantee that staked
                    // clients get at least 1 more number of streams than unstaked connections.
                    self.max_staked_load_in_throttling_window
                        .saturating_mul(stake)
                        .checked_div(total_stake)
                        .unwrap_or(self.max_unstaked_load_in_throttling_window + 1)
                        .max(self.max_unstaked_load_in_throttling_window + 1)
                } else {
                    self.max_staked_load_in_throttling_window
                }
            }
        }
    }

pub(crate) async fn throttle_stream(
    stats: &StreamerStats,
    peer_type: ConnectionPeerType,
    remote_addr: std::net::SocketAddr,
    stream_counter: &Arc<ConnectionStreamCounter>,
    max_streams_per_throttling_interval: u64,
) {
    let throttle_interval_start = stream_counter.reset_throttling_params_if_needed();
    let streams_read_in_throttle_interval = stream_counter.stream_count.load(Ordering::Relaxed);
    if streams_read_in_throttle_interval >= max_streams_per_throttling_interval {
        // The peer is sending faster than we're willing to read. Sleep for what's
        // left of this read interval so the peer backs off.
        let throttle_duration =
            STREAM_THROTTLING_INTERVAL.saturating_sub(throttle_interval_start.elapsed());

        if !throttle_duration.is_zero() {
            debug!(
                "Throttling stream from {remote_addr:?}, peer type: {peer_type:?}, \
                 max_streams_per_interval: {max_streams_per_throttling_interval}, \
                 read_interval_streams: {streams_read_in_throttle_interval} throttle_duration: \
                 {throttle_duration:?}"
            );
            stats.throttled_streams.fetch_add(1, Ordering::Relaxed);
            match peer_type {
                ConnectionPeerType::Unstaked => {
                    stats
                        .throttled_unstaked_streams
                        .fetch_add(1, Ordering::Relaxed);
                }
                ConnectionPeerType::Staked(_) => {
                    stats
                        .throttled_staked_streams
                        .fetch_add(1, Ordering::Relaxed);
                }
            }
            sleep(throttle_duration).await;
        }
    }

    fn prune_unstaked_connection_table(
        &self,
        unstaked_connection_table: &mut ConnectionTable<ConnectionStreamCounter>,
        max_unstaked_connections: usize,
        stats: Arc<StreamerStats>,
    ) {
        if unstaked_connection_table.total_size >= max_unstaked_connections {
            // Prune the connection table down to 90% capacity
            const PRUNE_TABLE_RATIO: f64 = 0.90;
            let max_connections = (PRUNE_TABLE_RATIO * (max_unstaked_connections as f64)) as usize;
            let num_pruned = unstaked_connection_table.prune_oldest(max_connections);
            stats
                .num_evictions_unstaked
                .fetch_add(num_pruned, Ordering::Relaxed);
        }
    }
