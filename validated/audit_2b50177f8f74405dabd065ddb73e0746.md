### Title
HTTP TRACE method on all java-tron REST endpoints echoes request headers via unoverridden `HttpServlet.doTrace()` - (File: framework/src/main/java/org/tron/core/services/http/RateLimiterServlet.java)

### Summary
Every public HTTP API servlet in java-tron (`GetAccountServlet`, `GetNowBlockServlet`, `BroadcastServlet`, etc.) extends `RateLimiterServlet`, which itself extends `javax.servlet.http.HttpServlet` and only overrides `service()` and the `doGet`/`doPost` handlers. [1](#0-0)  None of these classes, nor `HttpService`/`FullNodeHttpApiService`, override or block `doTrace()`, and no registered filter (`HttpApiAccessFilter`, `HttpInterceptor`, `LiteFnQueryHttpFilter`) restricts the allowed HTTP methods. [2](#0-1) [3](#0-2) 

### Finding Description
`RateLimiterServlet.service()` forwards every request (after rate-limit bookkeeping) to `super.service(req, resp)`, which is the standard `javax.servlet.http.HttpServlet` dispatcher. [4](#0-3)  That default dispatcher routes an HTTP `TRACE` request to the base class's `doTrace()` implementation, which is not overridden anywhere in the codebase (confirmed by the absence of any `doTrace`/`TRACE` references in the HTTP services package). The stock javax.servlet `doTrace()` implementation echoes the full incoming request line and **all request headers** back to the client in the response body (`message/http` content type). This is functionally analogous to the Apache Traffic Server TRACE issue (CVE-2022-47184): an unauthenticated client can use the TRACE verb to have the server reflect header data it would not otherwise expose, including any `X-Forwarded-For`/`Via`/proxy-injected headers, cookies, or other client/infrastructure metadata attached to the request en route to the node.

This is reachable on every servlet registered in `FullNodeHttpApiService.addServlet()`, i.e. the entire `/wallet/*`, `/net/listnodes`, and `/monitor/*` surface (`GetNowBlockServlet`, `GetAccountServlet`, `BroadcastServlet`, `TriggerSmartContractServlet`, etc.), as well as the Solidity/PBFT equivalents that subclass the same servlets. [5](#0-4)  None of the filters wired via `addFilter()` inspect or reject the HTTP method before dispatch — `HttpApiAccessFilter` only checks whether the endpoint is administratively disabled, and `HttpInterceptor` only records metrics. [6](#0-5) 

### Impact Explanation
An anonymous network client can send a TRACE request to any exposed java-tron HTTP endpoint and receive back a verbatim echo of the request headers it sent (and any headers appended by intermediate proxies/load balancers, such as internal `X-Forwarded-For`, `Via`, or authentication-adjacent headers if any reverse proxy in front of the node adds them). This is an information-disclosure primitive rather than a fund-theft or consensus-halting bug: it can leak internal network topology, proxy chains, or session-adjacent header values to any party able to reach the node's HTTP port, which downstream can facilitate further reconnaissance/attacks against node operators. It does not directly enable unauthorized account operations, so its severity should be scoped as informational/reconnaissance rather than critical impact on funds or consensus.

### Likelihood Explanation
High reachability: TRACE requires no authentication, no signed transaction, and no special client — any HTTP client capable of issuing a custom-verb request against the node's HTTP API port can trigger it on any of the dozens of registered servlets. The only mitigating factor is that many reverse proxies/load balancers or WAFs deployed in front of production nodes strip or block TRACE by default, and Jetty itself may already restrict TRACE at the connector level depending on version/configuration — this repo does not show any such Jetty-level restriction, and it could not be fully confirmed without runtime testing.

### Recommendation
Explicitly disable TRACE (and other unused verbs like OPTIONS/PUT/DELETE where not needed) at the servlet layer, e.g. by overriding `doTrace()` in `RateLimiterServlet` to return `405 Method Not Allowed` for all subclasses, or by adding a `Filter`/Jetty `HttpConfiguration` restriction that rejects any request whose method is not in an explicit allow-list (`GET`, `POST`). This closes the disclosure surface uniformly for every current and future HTTP servlet without requiring per-servlet changes.

### Proof of Concept
```
curl -X TRACE http://<node-ip>:<full-node-http-port>/wallet/getnowblock -H "X-Forwarded-For: 10.0.0.5" -v
```
Expected (vulnerable) behavior: node responds with `Content-Type: message/http` and a body echoing `TRACE /wallet/getnowblock HTTP/1.1` followed by all submitted headers including `X-Forwarded-For: 10.0.0.5`, confirming the default `HttpServlet.doTrace()` reflection path is reachable through `RateLimiterServlet`.     // Check per-endpoint first to avoid consuming global IP/QPS quota for requests
    // that would be rejected by the per-endpoint limiter anyway. acquirePermit()
    // chooses blocking or non-blocking semantics based on rate.limiter.apiNonBlocking.
    boolean perEndpointAcquired = rateLimiter == null || rateLimiter.acquirePermit(runtimeData);
    boolean acquireResource = perEndpointAcquired && GlobalRateLimiter.acquirePermit(runtimeData);

    String contextPath = req.getContextPath();
    String url = Strings.isNullOrEmpty(req.getServletPath())
        ? MetricLabels.UNDEFINED : contextPath + req.getServletPath();
    // int64_as_string is honored only on GET requests (URL query). POST is intentionally
    // unsupported because reading the body here would consume request.getReader() and
    // break downstream servlets that read it themselves.
    if ("GET".equalsIgnoreCase(req.getMethod())) {
      JsonFormat.setInt64AsString(Util.getInt64AsString(req));
    }
    try {
      resp.setContentType("application/json; charset=utf-8");

      if (acquireResource) {
        Histogram.Timer requestTimer = Metrics.histogramStartTimer(
            MetricKeys.Histogram.HTTP_SERVICE_LATENCY, url);
        super.service(req, resp);
        Metrics.histogramObserve(requestTimer);
      } else {
        resp.getWriter()
            .println(Util.printErrorMsg(new IllegalAccessException("lack of computing resources")));
      }

      } else {

  @Override
  protected void addFilter(ServletContextHandler context) {
    // filters the specified APIs
    // when node is lite fullnode and openHistoryQueryWhenLiteFN is false
    context.addFilter(new FilterHolder(liteFnQueryHttpFilter), "/*",
        EnumSet.allOf(DispatcherType.class));

    // http access filter, it should have higher priority than HttpInterceptor
    context.addFilter(new FilterHolder(httpApiAccessFilter), "/*",
        EnumSet.allOf(DispatcherType.class));
    // note: if the pathSpec of servlet is not started with wallet, it should be included here
    context.getServletHandler().getFilterMappings()[1]
        .setPathSpecs(new String[] {"/wallet/*",
            "/net/listnodes",
            "/monitor/getstatsinfo",
            "/monitor/getnodeinfo"});

    // metrics filter
    ServletHandler handler = new ServletHandler();
    FilterHolder fh = handler
        .addFilterWithMapping((Class<? extends Filter>) HttpInterceptor.class, "/*",
            EnumSet.of(DispatcherType.REQUEST));
    context.addFilter(fh, "/*", EnumSet.of(DispatcherType.REQUEST));
  }
