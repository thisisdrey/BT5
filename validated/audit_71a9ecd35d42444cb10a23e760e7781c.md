### Title
Extraction escape via unsandboxed `tar` in `CreateRepositoryFromSnapshot` - ([File: internal/gitaly/service/repository/create_repository_from_snapshot.go])

### Summary
The `CreateRepositoryFromSnapshot` RPC extracts an attacker-supplied tar archive by shelling out directly to the system `tar` binary with no symlink/hardlink/path validation, unlike the equivalent manual tar-extraction code path Gitaly maintains elsewhere in the same package.

### Finding Description
`CreateRepositoryFromSnapshot` fetches an archive from a client-supplied `HttpUrl` and streams the HTTP response body straight into `tar -C path -xvf -`: [1](#0-0) 

The comment on the RPC itself and inline in the code both acknowledge the archive is "trusted *a lot*" and that the content is not hardened: [2](#0-1) 

Contrast this with `extractTarToDirectory`, used for repository replication, which manually parses the tar stream with Go's `archive/tar` and explicitly rejects absolute symlinks and validates that both symlink and hardlink targets stay within the destination directory before creating them: [3](#0-2) 

`CreateRepositoryFromSnapshot`'s `untar` has none of these protections — it relies entirely on the behavior of the external `tar` binary, whose handling of symlinks pointing outside the extraction root, hardlinks, device files, or other special entries is not validated by Gitaly at all. A malicious/compromised HTTP source (which the client fully controls via `HttpUrl`/`ResolvedAddress`/`HttpAuth`) can serve a tar stream containing a symlink entry (e.g., `objects/malicious -> ../../../etc`) followed by a regular file entry through that symlink, or a hardlink to an arbitrary file, causing writes outside of the intended repository directory on the Gitaly storage.

### Impact Explanation
Because there is no validation of tar entry types or link targets, a caller of this RPC that controls (or can redirect/proxy) the snapshot HTTP endpoint can write files outside the newly-created repository's directory, anywhere the Gitaly process's file permissions allow. This can lead to storage escape (writing into other repositories on the same storage, or into Gitaly's config/hooks directories), and depending on what gets overwritten, could enable further compromise (e.g., overwriting custom hooks executed on subsequent Git operations, which chains into arbitrary code execution).

### Likelihood Explanation
Reachable directly from an unprivileged/ordinary caller of the `CreateRepositoryFromSnapshot` RPC — the request fully controls the source URL of the tar stream. The main constraint is that the caller must control or be able to influence the HTTP response served from that URL (i.e., serve their own malicious tar archive), which is inherent to the RPC's design (it is meant to fetch snapshots from an arbitrary/attacker-influenced source, as the code comment itself warns). No additional privilege beyond calling this RPC is required.

### Recommendation
Replace the raw `tar` binary invocation in `untar()` with the same hardened, Go-native tar extraction logic already implemented in `extractTarToDirectory` (in `internal/gitaly/service/repository/replicate.go`), which rejects absolute symlinks and validates that symlink/hardlink targets do not escape the destination directory. Alternatively, invoke `tar` with restrictive flags (e.g., refusing symlinks, `--no-same-owner`, and post-extraction path validation) and reject archives containing any entry types other than regular files and directories.

### Proof of Concept
1. Stand up an HTTP server that returns a tar stream containing:
   - A directory entry for the target repo.
   - A symlink entry `evil -> ../../../../../tmp` (relative target escaping repo directory).
   - A regular file entry `evil/pwned` whose content will be written through the symlink outside the repo directory.
2. Call `CreateRepositoryFromSnapshot` with `HttpUrl` pointing at that server (and optionally `ResolvedAddress` to bypass DNS-based restrictions).
3. Observe that `/tmp/pwned` (or another out-of-repo path) is created on the Gitaly host, demonstrating the extraction escape, since `untar()` performs no symlink/hardlink target validation before invoking the system `tar` binary.

func (s *server) untar(ctx context.Context, path string, in *gitalypb.CreateRepositoryFromSnapshotRequest) error {
	req, err := http.NewRequestWithContext(ctx, "GET", in.GetHttpUrl(), nil)
	if err != nil {
		return structerr.NewInvalidArgument("Bad HTTP URL: %w", err)
	}

	client := httpClient
	if resolvedAddress := in.GetResolvedAddress(); resolvedAddress != "" {
		client, err = newResolvedHTTPClient(in.GetHttpUrl(), resolvedAddress)
		if err != nil {
			return structerr.NewInvalidArgument("creating resolved HTTP client: %w", err)
		}
	}

	if in.GetHttpAuth() != "" {
		req.Header.Set("Authorization", in.GetHttpAuth())
	}

	rsp, err := client.Do(req)
	if err != nil {
		return structerr.NewInternal("HTTP request failed: %w", err)
	}
	defer rsp.Body.Close()

	if rsp.StatusCode < http.StatusOK || rsp.StatusCode >= http.StatusMultipleChoices {
		return structerr.NewInternal("HTTP server: %s", rsp.Status)
	}

	cmd, err := command.New(ctx, s.logger, []string{"tar", "-C", path, "-xvf", "-"}, command.WithStdin(rsp.Body))
	if err != nil {
		return err
	}

	return cmd.Wait()
}

// extractTarToDirectory extracts a tar archive to the specified directory using Go's tar package
func (s *server) extractTarToDirectory(ctx context.Context, reader io.Reader, targetDir string) error {
	targetDir = filepath.Clean(targetDir)
	tarReader := tar.NewReader(reader)

	for {
		select {
		case <-ctx.Done():
			return ctx.Err()
		default:
		}

		header, err := tarReader.Next()
		if err == io.EOF {
			break // End of archive
		}
		if err != nil {
			return fmt.Errorf("reading tar header: %w", err)
		}

		targetPath := filepath.Join(targetDir, header.Name)

		if !strings.HasPrefix(targetPath, targetDir+string(os.PathSeparator)) &&
			targetPath != targetDir {
			return fmt.Errorf("invalid file path in tar: %s", header.Name)
		}

		switch header.Typeflag {
		case tar.TypeDir:
			if err := os.MkdirAll(targetPath, os.FileMode(header.Mode)); err != nil {
				return fmt.Errorf("creating directory %s: %w", targetPath, err)
			}

		case tar.TypeReg:
			if err := s.extractFile(ctx, tarReader, targetPath, header); err != nil {
				return fmt.Errorf("extracting file %s: %w", targetPath, err)
			}

		case tar.TypeSymlink:
			if filepath.IsAbs(header.Linkname) {
				return fmt.Errorf("absolute symlink not allowed: %s -> %s", header.Name, header.Linkname)
			}

			// Resolve the relative symlink target from the symlink's parent directory
			// and verify it stays within the extraction boundary, consistent with the
			// hard link validation below.
			resolvedTarget := filepath.Join(filepath.Dir(targetPath), header.Linkname)
			if !strings.HasPrefix(resolvedTarget, targetDir+string(os.PathSeparator)) &&
				resolvedTarget != targetDir {
				return fmt.Errorf("symlink target escapes extraction directory: %s -> %s", header.Name, header.Linkname)
			}

			// Remove existing file/symlink if it exists
			if err := os.Remove(targetPath); err != nil && !os.IsNotExist(err) {
				return fmt.Errorf("removing existing file for symlink %s: %w", targetPath, err)
			}

			if err := os.Symlink(header.Linkname, targetPath); err != nil {
				return fmt.Errorf("creating symlink %s -> %s: %w", targetPath, header.Linkname, err)
			}

		case tar.TypeLink:
			linkTarget := filepath.Join(targetDir, header.Linkname)

			if !strings.HasPrefix(linkTarget, targetDir+string(os.PathSeparator)) &&
				linkTarget != targetDir {
				return fmt.Errorf("invalid hard link target: %s", header.Linkname)
			}

			// Remove existing file if it exists
			if err := os.Remove(targetPath); err != nil && !os.IsNotExist(err) {
				return fmt.Errorf("removing existing file for hard link %s: %w", targetPath, err)
			}

			if err := os.Link(linkTarget, targetPath); err != nil {
				return fmt.Errorf("creating hard link %s -> %s: %w", targetPath, linkTarget, err)
			}
