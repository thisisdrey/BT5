### Title
PermitUDPPort's lack of remote-address/CIDR scoping unconditionally defeats host-level WDF subnet restrictions on the nebula UDP port - (File: wfp/wfp_windows.go)

### Summary
`PermitUDPPort` installs a WFP PERMIT filter that matches only on `IP_PROTOCOL == UDP` and `IP_LOCAL_PORT == <port>`, with no `FWPM_CONDITION_IP_REMOTE_ADDRESS` or any local/remote CIDR condition. Because this filter is installed at `FWPM_LAYER_ALE_AUTH_RECV_ACCEPT_V4/V6` in a sublayer with weight `0xFFFF` and `fwpmFilterFlagClearActionRight` set, it arbitrates above and overrides any Windows Defender Firewall (WDF) rule an administrator configured to restrict the nebula port to a specific source subnet, allowing UDP from any address to reach the listener.

### Finding Description
`addUDPPortFilter` builds exactly two conditions - protocol and local port - and nothing address-related: [1](#0-0) 
This filter is placed in a dynamic sublayer registered with `weight: 0xFFFF` (the maximum) via `registerSublayer`: [2](#0-1) 
and the filter itself carries `fwpmFilterFlagClearActionRight`, whose purpose is explicitly documented as preventing lower-priority WDF sublayer filters (which share the same layer) from overriding this PERMIT: [3](#0-2) 
The call path is triggered automatically on Windows listener startup, gated by the config key `listen.windows_bypass_wdf`, which **defaults to true**: [4](#0-3) 
Because the PERMIT filter carries no remote-address condition, any UDP packet with a matching destination port is accepted at the ALE layer regardless of its source IP - meaning any WDF rule an admin created to restrict the nebula port to, e.g., a management subnet, is arbitrated away entirely by this higher-weight, clear-action-right filter. This is separate from and prior to nebula's own application-layer `firewall.go` CIDR enforcement (`AddRule`'s `localCidr`/`cidr` matching in `firewallPort.match`), so nebula's internal handshake/cert/firewall checks are unaffected, but the host-level WDF defense-in-depth is bypassed for all source addresses, not just legitimate nebula peers.

### Impact Explanation
This defeats an administrator's host-firewall-based subnet restriction ("defense in depth") for the nebula UDP listener port host-wide: any attacker capable of sending UDP packets to the host's bound port - regardless of source subnet - reaches the socket and is handed to nebula's handshake processing, even though the admin explicitly configured WDF to block all sources outside a management subnet. This matches the "firewall bypass" impact category: an OS-level access control the operator relied on is silently and unconditionally rendered ineffective for the scope of the nebula port.

### Likelihood Explanation
This is fully deterministic and default-on: `listen.windows_bypass_wdf` defaults to `true`, so on any Windows nebula node the bypass filter installs automatically at startup with no address restriction. Any external attacker who can route UDP packets to the host's nebula port satisfies the precondition; no privileges, certificates, or configuration control are needed by the attacker - only an admin-configured WDF rule that is silently overridden.

### Recommendation
Add remote-address/CIDR conditions (`FWPM_CONDITION_IP_REMOTE_ADDRESS`) to `addUDPPortFilter`, or otherwise let the bypass filter honor the same `local_cidr`/`unsafe_routes` scoping nebula's own firewall config exposes, so the WFP PERMIT only bypasses WDF for expected/allowed source ranges rather than unconditionally for all sources. At minimum, document clearly (and default the config flag to `false`) that enabling `listen.windows_bypass_wdf` removes all WDF-based source restrictions for the nebula port.

### Proof of Concept
Integration test plan (Windows only):
1. Configure a WDF inbound rule blocking UDP on nebula's configured port except from `10.0.0.0/24` (simulating an admin-restricted management subnet).
2. Start nebula with `listen.windows_bypass_wdf` at its default (`true`), triggering `wrapWithWDFBypass` -> `wfp.PermitUDPPort(port)` -> `addUDPPortFilter`.
3. From a host outside `10.0.0.0/24`, send a UDP packet to the nebula port.
4. Assert that the packet is received by the nebula listener socket (e.g., observed via packet capture or nebula debug logging showing a received handshake attempt), despite the WDF rule that should have blocked it.
5. Compare against the case where `listen.windows_bypass_wdf` is set to `false`: the same out-of-subnet packet should be dropped by WDF and never reach nebula's socket.

// above WDF's default sublayer. The sublayer is dynamic (no PERSISTENT flag) and goes away when the engine handle closes.
func registerSublayer(engine uintptr) (windows.GUID, error) {
	key, err := windows.GenerateGUID()
	if err != nil {
		return windows.GUID{}, fmt.Errorf("GenerateGUID for sublayer: %w", err)
	}

	name, _ := windows.UTF16PtrFromString("Nebula WDF bypass sublayer")
	desc, _ := windows.UTF16PtrFromString("Permit filters bypassing Windows Defender Firewall")
	sl := fwpmSublayer0{
		subLayerKey: key,
		displayData: fwpmDisplayData0{name: name, description: desc},
		weight:      0xFFFF,
	}
	r1, _, _ := procFwpmSubLayerAdd0.Call(
		engine,
		uintptr(unsafe.Pointer(&sl)),
		0, // sd == NULL
	)
	if r1 != 0 {
		return windows.GUID{}, fmt.Errorf("FwpmSubLayerAdd0: 0x%x", r1)
	}
	return key, nil
}
