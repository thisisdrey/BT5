### Title
Unauthenticated `/shutdown` HTTP request permanently terminates `SignerEventReceiver::main_loop` - (File: libsigner/src/events.rs)

### Summary
`SignerEventReceiver::next_event` treats any POST to `/shutdown` as a legitimate stop command, setting `stop_signal` and returning `EventError::Terminated`, without checking the caller's identity, a secret, or even the source address. Any remote TCP client that can reach the signer's configured event-receiver listen address can send this single HTTP request and permanently stop the signer's event-processing loop.

### Finding Description
The event receiver's request dispatcher matches on `request.url()` alone: [1](#0-0) 

There is no authentication check (no shared secret, no header check, no peer/address allow-list) distinguishing the legitimate internal shutdown call made by `SignerStopSignaler::send` from an externally originating request. `SignerStopSignaler::send` itself just opens a plain `TcpStream` to the bound `local_addr` and writes a raw HTTP POST to `/shutdown`: [2](#0-1) 

Any TCP peer able to reach the bound address can construct the identical bytes (`POST /shutdown HTTP/1.1 ... Content-Length: N ... <body>`) and trigger the same code path. When `next_event` returns `Err(EventError::Terminated)`, `main_loop` breaks out and logs "Caught termination signal", exiting the loop entirely: [3](#0-2) 

Because `stop_signal` is a shared `AtomicBool` with no reset path, this is a one-shot, irreversible action — the receiver thread does not restart, and no further node-pushed events (`/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block`) will ever be processed again for the life of the process.

### Impact Explanation
A single unauthenticated HTTP POST permanently disables the signer's ingestion of node-pushed events (StackerDB chunks, block proposals, burn blocks, new blocks), effectively blinding the signer to consensus-relevant data it needs to participate correctly, until the operator manually restarts the process. This is a remote, unauthenticated, single-message DoS against a control-plane action, matching the "Critical - remote crash/unauthenticated DoS from few messages" category.

### Likelihood Explanation
The only precondition is TCP reachability to the signer's configured event-receiver bind address/port — no secret, no peer registration, no StackerDB slot ownership, and no privileged role is required. The attack is a single crafted HTTP request, trivially repeatable against any signer whose event endpoint is reachable from the attacker's network position (e.g., bound to a non-loopback address per operator configuration).

### Recommendation
Require authentication for the `/shutdown` endpoint (e.g., a local-only Unix socket, a shared secret/token compared in constant time, or restrict handling to loopback-originated connections), or remove the HTTP-triggered shutdown mechanism entirely in favor of an in-process channel/signal that cannot be reached over the network.

                Ok(event) => event,
                Err(EventError::UnrecognizedEvent(..)) => {
                    // got an event that we don't care about (not a problem)
                    continue;
                }
                Err(EventError::Terminated) => {
                    // we're done
                    info!("Caught termination signal");
                    break;
                }
                Err(e) => {
                    warn!("Failed to receive next event: {:?}", &e);
                    continue;
                }
            };

                info!("Failed to forward event");
                break;
            }
        }
