Audit Report

## Title
Integer-division truncation in `convert_from_ether_decimals` lets the Snowbridge outbound-queue fee collapse to zero, allowing unpriced message spam - (File: `bridges/snowbridge/pallets/outbound-queue/src/lib.rs`)

## Summary
`Pallet::calculate_fee` converts the wei-denominated remote fee to local `Balance` precision via `convert_from_ether_decimals`, which performs plain integer division with no rounding-up, minimum-fee floor, or post-conversion non-zero check. For DOT (10 decimals), any wei fee under `10^8` truncates to `0`, and this value is accepted as-is by `SendMessage::validate`/`deliver` without any re-validation, letting an unprivileged user submit and enqueue bridge messages to Ethereum with a zero remote fee.

## Finding Description
`Pallet::calculate_fee` computes the remote fee and calls `convert_from_ether_decimals`, which does `value.checked_div(denom)` where `denom = 10^(18 - T::Decimals)` [1](#0-0) . This is a floor division with no lower-bound enforcement, so a computed wei fee smaller than `denom` truncates to zero. `calculate_fee` performs the multiplier/exchange-rate arithmetic and then calls this conversion without any subsequent check that the result is non-zero [2](#0-1) .

`PricingParameters::validate()` only rejects zero-valued fields (`exchange_rate`, `fee_per_gas`, `rewards.local`, `rewards.remote`, `multiplier`); it never checks whether the resulting *converted* fee for a realistic `gas_used_at_most` stays above the truncation threshold [3](#0-2) .

The pallet's own test reproduces this exact scenario with fully valid (non-zero) `PricingParameters` — `exchange_rate = 1/1`, `fee_per_gas = 1`, `rewards.remote = 1`, `multiplier = 1/1` — yielding `fee.remote == 0` while `fee.local` remains non-zero [4](#0-3) .

`SendMessage::validate` computes this fee from attacker-controllable inputs (the command determines `gas_used_at_most` via `T::GasMeter::maximum_gas_used_at_most`) and returns it as the price to charge, with no floor check [5](#0-4) . `SendMessage::deliver` then unconditionally enqueues the message (only checking the halted operating mode), never re-validating that the fee computed in `validate` was non-zero [6](#0-5) .

## Impact Explanation
This matches the "public underpriced work that degrades block production or stalls bridge processing" impact category. An unprivileged user can pick a command whose gas cost, combined with the currently configured `PricingParameters`, produces a wei-denominated remote fee under the `10^8` (DOT, 10 decimals) or `10^6` (KSM, 12 decimals) truncation threshold, causing `Fee.remote` to be silently zeroed while the message is still fully accepted, queued, committed to the Merkle root, and forwarded for relaying/execution on Ethereum — enabling free, repeatable spam of outbound bridge capacity.

## Likelihood Explanation
Reachability depends entirely on the live `PricingParameters` configuration and requires no privileged access — any ordinary user choosing message parameters can trigger it once parameters land in the truncation-prone regime. The pallet's own unit test demonstrates the defect occurs under valid, non-zero, `validate()`-passing parameters, showing the vulnerable condition is realistically reachable rather than purely theoretical.

## Recommendation
Add an explicit non-zero/minimum-fee check after `convert_from_ether_decimals` in `calculate_fee` (e.g., `ensure!(fee > T::Balance::zero(), Error::<T>::FeeTooLow)` or saturate to a configured minimum), or switch the division to round up (`ceil` instead of `floor`), and extend `PricingParameters::validate()` to reject parameter combinations that would produce a zero converted fee for the pallet's minimum supported `gas_used_at_most`.

## Proof of Concept
1. Configure `PricingParameters` as in `test_calculate_fees_with_valid_exchange_rate_but_remote_fee_calculated_as_zero` (`bridges/snowbridge/pallets/outbound-queue/src/test.rs`, lines 303-319): `exchange_rate = 1/1`, `fee_per_gas = 1`, `rewards = {local: 1, remote: 1}`, `multiplier = 1/1`.
2. Call `OutboundQueue::calculate_fee(250_000, price_params)` — observe `fee.remote == 0` while `fee.local == 698000000`.
3. In a live deployment with such parameters, submit an XCM message via `SnowbridgeExporter`/`EthereumBlobExporter` using a `Command` whose gas usage falls in this zero-truncation range; `Pallet::validate` returns `Fee.remote == 0`.
4. `Pallet::deliver` enqueues the message unconditionally, and it proceeds to commitment and relay to Ethereum with zero remote fee charged.

			gas_used_at_most: u64,
			params: PricingParameters<T::Balance>,
		) -> Fee<T::Balance> {
			// Remote fee in ether
			let fee = Self::calculate_remote_fee(
				gas_used_at_most,
				params.fee_per_gas,
				params.rewards.remote,
			);

			// downcast to u128
			let fee: u128 = fee.try_into().defensive_unwrap_or(u128::MAX);

			// multiply by multiplier and convert to local currency
			let fee = FixedU128::from_inner(fee)
				.saturating_mul(params.multiplier)
				.checked_div(&params.exchange_rate)
				.expect("exchange rate is not zero; qed")
				.into_inner();

			// adjust fixed point to match local currency
			let fee = Self::convert_from_ether_decimals(fee);

			Fee::from((Self::calculate_local_fee(), fee))
		}

fn test_calculate_fees_with_valid_exchange_rate_but_remote_fee_calculated_as_zero() {

		let price_params: PricingParameters<<Test as Config>::Balance> = PricingParameters {

			multiplier: FixedU128::from_rational(1, 1),
		};

		assert_eq!(fee.local, 698000000);
		// Though none zero pricing params the remote fee calculated here is invalid
		// which should be avoided
		assert_eq!(fee.remote, 0);
	});
}

	fn validate(
		message: &Message,
	) -> Result<(Self::Ticket, Fee<<Self as SendMessageFeeProvider>::Balance>), SendError> {
		// The inner payload should not be too large
		let payload = message.command.abi_encode();
		ensure!(
			payload.len() < T::MaxMessagePayloadSize::get() as usize,
			SendError::MessageTooLarge
		);

		// Ensure there is a registered channel we can transmit this message on
		ensure!(T::Channels::contains(&message.channel_id), SendError::InvalidChannel);

		// Generate a unique message id unless one is provided
		let message_id: H256 = message
			.id
			.unwrap_or_else(|| unique((message.channel_id, &message.command)).into());

		let gas_used_at_most = T::GasMeter::maximum_gas_used_at_most(&message.command);
		let fee = Self::calculate_fee(gas_used_at_most, T::PricingParameters::get());

		let queued_message: VersionedQueuedMessage = QueuedMessage {
			id: message_id,
			channel_id: message.channel_id,
			command: message.command.clone(),
		}
		.into();
		// The whole message should not be too large
		let encoded = queued_message.encode().try_into().map_err(|_| SendError::MessageTooLarge)?;

		let ticket = Ticket { message_id, channel_id: message.channel_id, message: encoded };

		Ok((ticket, fee))
	}

	fn deliver(ticket: Self::Ticket) -> Result<H256, SendError> {
		let origin = AggregateMessageOrigin::Snowbridge(ticket.channel_id);
