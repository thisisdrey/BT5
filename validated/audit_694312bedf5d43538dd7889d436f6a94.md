### Title
Unbounded blocking read in `process_event` on `Content-Length`-declared-but-unsent body stalls the signer's single-threaded event `main_loop` - ([File: libsigner/src/events.rs])

### Summary
`SignerEventReceiver::next_event` calls `http_server.recv()` and then `process_event`, which does `request.as_reader().read_to_string(&mut body)` at events.rs:526 with no read timeout configured anywhere on the accepted `TcpStream`. Because `main_loop` (events.rs:284-312) processes events strictly serially through `next_event`, a single connection that sends a `Content-Length` header far larger than the bytes actually delivered (and then stalls) blocks the read indefinitely, freezing the entire signer event-processing loop for as long as the attacker holds the connection open.

### Finding Description
The claimed equality "time-spent-per-event == bounded by a read timeout" does not hold: no code in `libsigner/src/events.rs`, `SignerEventReceiver::bind` (events.rs:404-408), or `next_event` (events.rs:413-459) sets `TcpStream::set_read_timeout` on the incoming connection's socket, and `tiny_http::HttpServer::http()` as used here is not configured with any request/read timeout. `process_event` (events.rs:519-542) reads the body via `request.as_reader().read_to_string(&mut body)` (line 526), which for `tiny_http` follows the declared `Content-Length` and blocks on the underlying socket read until that many bytes arrive or the connection errors/closes. An attacker who can open a TCP connection to the signer's bound event port can send a valid HTTP request line/headers with `Content-Length: <large>`, send only a small prefix of the body, and then simply stop sending data (without closing the connection). The `read_to_string` call blocks on that single connection's socket read. Since `main_loop` calls `next_event` → `with_server` → `http_server.recv()` → `process_event` synchronously and only proceeds to accept/process the next request after the current one resolves, this single stalled connection starves the entire loop, delaying processing of stackerdb chunks, block proposals, burn blocks, and all other signer events.

### Impact Explanation
This is a remote, unauthenticated, single-connection Denial of Service against the signer's event-processing pipeline: while the connection is stalled, the signer does not observe new miner block proposals, StackerDB chunks, burn blocks, or node blocks, which can delay or prevent the signer from participating in block signing during the stall. It is repeatable by simply reconnecting after any timeout/reset, and requires no secret, key, or privileged role — only network reachability to the bound event-observer port and the ability to hold open a TCP connection. This matches the Critical category ("remote crash/unauthenticated DoS from few messages").

### Likelihood Explanation
Preconditions: the attacker needs network reachability to the signer's event-observer HTTP endpoint (the address/port the stacks-node's event dispatcher POSTs to, as configured for the signer). No node RPC secret, peer key, or StackerDB slot ownership is required — only the ability to open a raw TCP connection and send a crafted HTTP request. Attacker cost is a single TCP connection and a handful of bytes with a stall; it is trivially repeatable and requires no volumetric traffic (a single stalled connection suffices because of the serial `main_loop`), which distinguishes it from the excluded "volumetric DDoS/connection-slot exhaustion needing only traffic volume" category.

### Recommendation
Set an explicit read/deadline timeout on each accepted connection's underlying socket before reading the body (e.g., obtain the peer's `TcpStream`/use `tiny_http`'s configuration options for read timeouts, or wrap `as_reader()` reads in a bounded loop with `set_read_timeout`), and/or process each accepted request's body read in a worker thread/pool so a single slow-loris-style connection cannot block `main_loop`'s serial event dispatch. Additionally, cap max read time and enforce a maximum body size irrespective of the declared `Content-Length` before beginning the read.

// libsigner/src/events.rs (test module) — conceptual Rust net test
#[test]
fn slow_body_stalls_next_event() {
    let mut receiver: SignerEventReceiver<v0::messages::SignerMessage> =
        SignerEventReceiver::new(false);
    let addr = receiver.bind("127.0.0.1:0".parse().unwrap()).unwrap();

    // Attacker connection: send headers with big Content-Length, send 1 byte, then stall.
    let attacker = std::thread::spawn(move || {
        let mut stream = TcpStream::connect(addr).unwrap();
        let req = format!(
            "POST /stackerdb_chunks HTTP/1.1\r\nHost: {addr}\r\nContent-Length: 10000\r\n\r\nX"
        );
        stream.write_all(req.as_bytes()).unwrap();
        // do not send remaining 9999 bytes; keep connection open
        std::thread::sleep(std::time::Duration::from_secs(60));
    });

    let start = std::time::Instant::now();
    // next_event should return (error or event) within a short bounded time if a
    // read timeout is enforced. Absent a timeout, this call blocks far past
    // any reasonable bound (e.g., > 5s), demonstrating the DoS.
    let _ = receiver.next_event();
    assert!(start.elapsed() < std::time::Duration::from_secs(5),
        "next_event blocked without a read timeout, confirming single-connection DoS");
}

    fn main_loop(&mut self) {
        loop {
            if self.is_stopped() {
                info!("Event receiver stopped");
                break;
            }
            let next_event = match self.next_event() {
                Ok(event) => event,
                Err(EventError::UnrecognizedEvent(..)) => {
                    // got an event that we don't care about (not a problem)
                    continue;
                }
                Err(EventError::Terminated) => {
                    // we're done
                    info!("Caught termination signal");
                    break;
                }
                Err(e) => {
                    warn!("Failed to receive next event: {:?}", &e);
                    continue;
                }
            };
            if !self.forward_event(next_event) {
                info!("Failed to forward event");
                break;
            }
        }
        info!("Event receiver main loop exit");
    }

    /// Errors are recoverable -- the caller should call this method again even if it returns an
    /// error.
    fn next_event(&mut self) -> Result<SignerEvent<T>, EventError> {
        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)
            } else if request.url() == "/new_block" {
                process_event::<T, StacksBlockEvent>(request)
            } else {
                let url = request.url().to_string();
                debug!(
                    "[{:?}] next_event got request with unexpected url {}, return OK so other side doesn't keep sending this",
                    event_receiver.local_addr,
                    url
                );
                ack_dispatcher(request);
                Err(EventError::UnrecognizedEvent(url))
            }
        })?
    }
