### Title
Operator Beneficiary With Opted-Out Direct Coin Transfers Permanently Freezes Staker APT in `staking_contract::distribute_internal` — (`aptos-move/framework/aptos-framework/sources/staking_contract.move`)

---

### Summary

`staking_contract::set_beneficiary_for_operator` accepts any arbitrary address as the operator's commission beneficiary with no validation. `distribute_internal` then pushes APT to that beneficiary via `aptos_account::deposit_coins`, which aborts if the beneficiary has opted out of direct coin transfers and is not registered for `AptosCoin`. Because `distribute_internal` is called atomically for all recipients, a single aborting beneficiary permanently freezes the staker's APT — there is no alternative withdrawal path.

---

### Finding Description

`staking_contract::set_beneficiary_for_operator` sets an arbitrary address as the operator's commission recipient with no checks: [1](#0-0) 

`distribute_internal` then iterates over all distribution recipients and calls `aptos_account::deposit_coins` for each one, including the operator's beneficiary: [2](#0-1) 

`aptos_account::deposit_coins` aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` when the recipient account exists, is **not** registered for `AptosCoin`, and has explicitly set `allow_arbitrary_coin_transfers = false`: [3](#0-2) 

Because the entire `distribute_internal` call is atomic, one aborting `deposit_coins` reverts the whole transaction. The staker's share is never paid out.

`distribute_internal` is also called as a prerequisite inside `unlock_stake` and `switch_operator`: [4](#0-3) 

So the staker cannot unlock their stake, switch operators, or receive any distribution — every path that could recover funds calls `distribute_internal` first.

Contrast this with `vesting::set_beneficiary`, which **does** guard against this by requiring the new beneficiary to be registered for APT before accepting it: [5](#0-4) 

`staking_contract::set_beneficiary_for_operator` has no equivalent guard.

---

### Impact Explanation

A staker's entire APT principal and accumulated rewards held in the staking contract become permanently unwithdrawable. The staker cannot call `unlock_stake`, `switch_operator`, or `distribute` — all three paths invoke `distribute_internal`, which aborts. The funds are correctly attributed to the staker on-chain but are inaccessible without a contract upgrade. This matches the "permanent freezing of user-controlled staking balances" impact class in the Aptos bounty scope.

---

### Likelihood Explanation

The trigger requires two unprivileged transactions:
1. A beneficiary address calls `aptos_account::set_allow_direct_coin_transfers(false)` and never registers a `CoinStore<AptosCoin>`.
2. The operator calls `staking_contract::set_beneficiary_for_operator(<that address>)`.

Both are standard, permissionless entry functions. A malicious operator can execute this deliberately, or an operator could accidentally set a beneficiary that later opts out. The `operator_beneficiary_change_enabled` feature flag must be on, but it is a mainnet-enabled feature.

---

### Recommendation

Mirror the guard already present in `vesting::set_beneficiary`: validate that the new beneficiary is registered for `AptosCoin` (or can receive direct coin transfers) before accepting it in `set_beneficiary_for_operator`:

```move
public entry fun set_beneficiary_for_operator(
    operator: &signer, new_beneficiary: address
) acquires BeneficiaryForOperator {
    assert!(features::operator_beneficiary_change_enabled(), ...);
    // Add this guard, matching vesting::set_beneficiary:
    aptos_account::assert_account_is_registered_for_apt(new_beneficiary);
    ...
}
```

Alternatively, refactor `distribute_internal` to use a pull-payment pattern (record amounts owed per recipient and let each recipient claim independently), so one recipient's inability to receive funds does not block others.

---

### Proof of Concept

1. Operator creates a staking contract with a staker.
2. Attacker-controlled address `B` calls `aptos_account::set_allow_direct_coin_transfers(false)` and never registers `CoinStore<AptosCoin>`.
3. Operator calls `staking_contract::set_beneficiary_for_operator(B)` — succeeds with no validation.
4. Staking rewards accumulate; lockup expires.
5. Staker calls `staking_contract::distribute(staker_addr, operator_addr)`.
   - `distribute_internal` is entered.
   - Commission share is computed for the operator; `recipient` is resolved to `B`.
   - `aptos_account::deposit_coins(B, commission_coins)` is called.
   - `coin::is_account_registered<AptosCoin>(B)` → `false`.
   - `can_receive_direct_coin_transfers(B)` → `false` (opted out).
   - **Aborts** with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS`.
6. Staker calls `unlock_stake` → same abort (calls `distribute_internal` first).
7. Staker calls `switch_operator` → same abort.
8. Staker's APT is permanently frozen in the staking pool. [6](#0-5) [7](#0-6)

```text
    fun distribute_internal(
        staker: address,
        operator: address,
        staking_contract: &mut StakingContract,
    ) acquires BeneficiaryForOperator {
        let pool_address = staking_contract.pool_address;
        // Create the Staker resource if it doesn't exist to backfill the Staker resource for each pool.
        if (!exists<Staker>(pool_address)) {
            let pool_signer =
                &account::create_signer_with_capability(&staking_contract.signer_cap);
            move_to(pool_signer, Staker { staker });
        };
        let (_, inactive, _, pending_inactive) = stake::get_stake(pool_address);
        let total_potential_withdrawable = inactive + pending_inactive;
        let coins =
            stake::withdraw_with_cap(
                &staking_contract.owner_cap, total_potential_withdrawable
            );
        let distribution_amount = coin::value(&coins);
        if (distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };

        let distribution_pool = &mut staking_contract.distribution_pool;
        update_distribution_pool(
            distribution_pool,
            distribution_amount,
            operator,
            staking_contract.commission_percentage
        );

        // Buy all recipients out of the distribution pool.
        while (distribution_pool.shareholders_count() > 0) {
            let recipients = distribution_pool.shareholders();
            let recipient = recipients[0];
            let current_shares = distribution_pool.shares(recipient);
            let amount_to_distribute =
                distribution_pool.redeem_shares(recipient, current_shares);
            // If the recipient is the operator, send the commission to the beneficiary instead.
            if (recipient == operator) {
                recipient = beneficiary_for_operator(operator);
            };
            aptos_account::deposit_coins(
                recipient, coin::extract(&mut coins, amount_to_distribute)
            );

            emit(
                Distribute {
                    operator,
                    pool_address,
                    recipient,
                    amount: amount_to_distribute
                }
            );
        };

        // In case there's any dust left, send them all to the staker.
        if (coin::value(&coins) > 0) {
            aptos_account::deposit_coins(staker, coins);
            distribution_pool.update_total_coins(0);
        } else {
            coin::destroy_zero(coins);
        }
    }
```
