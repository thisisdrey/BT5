### Title
Unauthenticated event-listener HTTP endpoint allows remote forgery of `SignerEvent`s — ([File: libsigner/src/events.rs])

### Summary
`SignerEventReceiver::next_event` dispatches based solely on the HTTP request path (`/stackerdb_chunks`, `/new_block`, `/proposal_response`, `/new_burn_block`) with no verification that the request originated from the configured Stacks node. Any TCP peer that can reach the bound listener socket can POST a crafted JSON body and have it deserialized into a `SignerEvent` that is forwarded straight to the signer runloop.

### Finding Description
`SignerEventReceiver::bind` merely opens a plain `tiny_http::HttpServer` on the configured socket with no TLS and no credential check: [1](#0-0) 

`next_event` then reads a request, checks only the HTTP method and URL string, and routes straight into `process_event`: [2](#0-1) 

`process_event` reads the raw body, deserializes it as JSON into the target type (`StackerDBChunksEvent`, `StacksBlockEvent`, `BlockValidateResponse`, `BurnBlockEvent`), and converts it into a `SignerEvent<T>` via `TryFrom`/`TryInto` — with no signature, secret, or source check anywhere in this path: [3](#0-2) 

For the `/stackerdb_chunks` → `MINERS_NAME` contract branch specifically, `TryFrom<StackerDBChunksEvent> for SignerEvent<T>` deserializes each `chunk.data` directly into `T` (miner message) with **no `recover_pk()`/signature check at all** (unlike the sibling `SIGNERS_NAME` branch which does call `chunk.recover_pk()`): [4](#0-3) 

Once `next_event()` returns `Ok(SignerEvent::MinerMessages(..))`, `EventReceiver::main_loop` unconditionally calls `forward_event`, which sends the event on the internal channel to the signer runloop with no additional gate: [5](#0-4) [6](#0-5) 

The only "authentication" concept present in the surrounding system (`auth_token` / `auth_password`) protects the opposite direction — the signer's outbound calls into the node's RPC endpoints (e.g., block-proposal validation) — not inbound POSTs arriving at the signer's event-listener socket, as documented in the node/signer config samples: [7](#0-6) [8](#0-7) 

Notably, the reference signer config even binds this listener to `0.0.0.0:30000` (all interfaces) rather than loopback: [9](#0-8) 

So the equality "message delivered to signer runloop == message the configured node's dispatcher sent" is broken: any TCP client that can reach the listening port can substitute an arbitrary message with no proof of origin.

### Impact Explanation
An attacker who can reach the signer's event-listener socket can inject fabricated `SignerEvent::MinerMessages`, `SignerEvent::SignerMessages` (partially, gated by lane/signature checks for that specific branch only), `SignerEvent::BlockValidationResponse`, `SignerEvent::NewBurnBlock`, or `SignerEvent::NewBlock` values directly into the signer's decision pipeline, independent of what the real node observed. This is repeatable per HTTP POST and requires no cryptographic material. Given the signer runloop's decisions can influence block signing/voting, this qualifies as unauthenticated injection of forged data into a node-adjacent trust boundary — matching the "unauthenticated/unauthorized write to state" Critical category as scoped to the transport layer in this question (independent of downstream runloop handling, which is explicitly out of scope for this question).

### Likelihood Explanation
Preconditions: the attacker must be able to open a TCP connection to the signer's bound listener address/port. If the operator binds the listener to `0.0.0.0` (as the reference `mainnet-signer-conf.toml` sample does) and it is reachable through NAT/firewall, this is directly exploitable by any unprivileged remote party with no secret and no peer/slot ownership. If the operator binds strictly to `127.0.0.1`, this is not remotely reachable and the finding is moot for that deployment — but the code itself provides no enforcement of this; it is purely operator-configuration-dependent, and the sample config shipped in-repo does not default to loopback-only binding.

### Recommendation
Add authentication to the event-listener HTTP endpoint: require a shared secret/HMAC or bearer token (mirroring `auth_token`) on inbound event POSTs, verify it in `next_event`/`process_event` before dispatch, and/or bind the listener to loopback by default with an explicit opt-in for exposing it more broadly. Additionally, apply the same `recover_pk()`-based signer/miner signature verification used in the `SIGNERS_NAME` branch to the `MINERS_NAME` (`/stackerdb_chunks` miner) branch before trusting chunk contents.

use std::net::{TcpStream, SocketAddr};
use std::io::Write;
use std::thread;

#[test]
fn attacker_can_inject_miner_messages_without_node() {
    let mut receiver: SignerEventReceiver<SomeSignerMessageType> = SignerEventReceiver::new(false);
    let addr: SocketAddr = "127.0.0.1:0".parse().unwrap();
    let bound = receiver.bind(addr).unwrap();

    // "Attacker" thread: no relation to the configured node, no secret used.
    let attacker_addr = bound;
    thread::spawn(move || {
        let mut stream = TcpStream::connect(attacker_addr).unwrap();
        let body = r#"{"contract_id":"...miners...","modified_slots":[ ... crafted chunk with valid consensus-encoded T bytes ... ]}"#;
        let req = format!(
            "POST /stackerdb_chunks HTTP/1.1\r\nHost: {}\r\nContent-Length: {}\r\nContent-Type: application/json\r\nConnection: close\r\n\r\n{}",
            attacker_addr, body.len(), body
        );
        stream.write_all(req.as_bytes()).unwrap();
    });

    // Assert the receiver accepts and returns a forged event with no origin check.
    let event = receiver.next_event().unwrap();
    assert!(matches!(event, SignerEvent::MinerMessages(_)));
}

    fn forward_event(&mut self, ev: SignerEvent<T>) -> bool {
        if self.out_channels.is_empty() {
            // nothing to do
            error!("No channels connected to event receiver");
            false
        } else if self.out_channels.len() == 1 {
            // avoid a clone
            if let Err(e) = self.out_channels[0].send(ev) {
                error!("Failed to send to signer runloop: {:?}", &e);
                return false;
            }

                    error!("Failed to send to signer runloop #{}: {:?}", i, &e);
                    return false;
                }

        }

fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}
