### Title
Unbounded attacker-controlled array length in precompiled contract ABI-decoding helpers causes OutOfMemoryError / ArrayIndexOutOfBoundsException - (File: actuator/src/main/java/org/tron/core/vm/PrecompiledContracts.java)

### Summary
The CVE describes a heap-based buffer over-read in `elf32_xlatetom` because `ebl_core_note` trusts an attacker-supplied length field from a crafted note header without validating it against the actual buffer size. The analogous root cause exists in java-tron's precompiled-contract calldata decoders `extractBytes32Array` and `extractBytesArray`, which read an unvalidated, attacker-controlled length word directly from TVM calldata and use it to allocate arrays and index into the decoded `DataWord[]` without bounds checking against the actual input size.

### Finding Description
`extractBytes32Array` and `extractBytesArray` decode dynamic ABI arrays from precompiled-contract input by reading a length word directly from caller-supplied calldata and then looping that many times over the `words` array with no check that `offset + i + 1` stays within `words.length`: [1](#0-0) 

`len` comes from `words[offset].intValueSafe()`, which is fully attacker-controlled via the calldata of a call to the precompile (this pattern backs the `ValidateMultiSign`-style precompile exercised by `ValidateMultiSignContractTest`, which builds `words` arrays and signature arrays from raw call data): [2](#0-1) 

Unlike other precompiles in the same file (e.g. `ModExp`), which explicitly clamp inputs with `UPPER_BOUND` checks before use, or `isValidAbiEncoding`, which validates the header/tail relationship against `data.length` before use: [3](#0-2) 
`extractBytes32Array`/`extractBytesArray` perform no such validation of `len` against `words.length` or `data.length` before allocating `new byte[len][]` or indexing `words[offset + i + 1]`.

### Impact Explanation
A single crafted transaction calling the affected precompile with a manipulated length word can:
- Trigger `ArrayIndexOutOfBoundsException` by supplying a `len` larger than the actual number of remaining `DataWord`s, reading past the intended input bounds (direct analog of the CVE's out-of-bounds read).
- Trigger `NegativeArraySizeException` with a negative-looking length.
- Trigger `OutOfMemoryError` by supplying a very large `len` (e.g., near `Integer.MAX_VALUE`) to `new byte[len][]`, an `Error` (not `Exception`) that is not reliably caught by ordinary transaction-execution exception handling, risking node instability/crash rather than a clean revert.

### Likelihood Explanation
The precompile is reachable by any unprivileged account through a normal signed transaction invoking the contract address that maps to this precompile (no special privilege required), making the likelihood high once the precise precompile address/selector is confirmed.

### Recommendation
Add explicit bounds validation in `extractBytes32Array` and `extractBytesArray` before allocating or indexing: verify `len >= 0`, cap `len` to a sane maximum, and verify `offset + len + 1 <= words.length` (and that `bytesOffset`/`bytesLen` stay within `data.length`) before use, mirroring the existing `isValidAbiEncoding`/`UPPER_BOUND` patterns already used elsewhere in this file.

### Proof of Concept
Craft calldata to the affected precompile such that the word at `words[offset]` (the declared array length) is a large value (e.g., `0x7fffffff`) while the actual calldata is short. Calling this from a contract invocation causes `extractBytes32Array`/`extractBytesArray` to attempt `new byte[0x7fffffff][]` (OutOfMemoryError) or to index beyond `words.length` (ArrayIndexOutOfBoundsException) during precompile execution triggered by an ordinary transaction.

  private static byte[][] extractBytes32Array(DataWord[] words, int offset) {
    int len = words[offset].intValueSafe();
    byte[][] bytes32Array = new byte[len][];
    for (int i = 0; i < len; i++) {
      bytes32Array[i] = words[offset + i + 1].getData();
    }
    return bytes32Array;
  }

  private static byte[][] extractBytesArray(DataWord[] words, int offset, byte[] data) {
    if (offset > words.length - 1) {
      return new byte[0][];
    }
    int len = words[offset].intValueSafe();
    byte[][] bytesArray = new byte[len][];
    for (int i = 0; i < len; i++) {
      int bytesOffset = words[offset + i + 1].intValueSafe() / WORD_SIZE;
      int bytesLen = words[offset + bytesOffset + 1].intValueSafe();
      bytesArray[i] = extractBytes(data, (bytesOffset + offset + 2) * WORD_SIZE,
          bytesLen);
    }
    return bytesArray;
  }
