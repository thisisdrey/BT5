I found a genuine equality break in `handle_unsolicited_StackerDBPushChunk`: the local inventory (`StackerDBChunkInv.slot_versions`) is patched to reflect a pushed chunk's version *before* the chunk is actually written to the local StackerDB replica.

### Title
Unsolicited StackerDB push advertises inventory version for a chunk that was never stored - (File: stackslib/src/net/stackerdb/mod.rs)

### Summary
`PeerNetwork::handle_unsolicited_StackerDBPushChunk` validates a pushed `StackerDBChunkData` with `validate_received_chunk` (size, signer, version, max-writes) and then unconditionally patches the in-memory `slot_versions` inventory to the pushed version, before the chunk is ever persisted via `try_replace_chunk`/`insert_chunk`.

### Finding Description
`validate_received_chunk` at [1](#0-0)  only checks signature/version/size bounds; it never writes the chunk to `self.stackerdbs`. Immediately after this check succeeds, `handle_unsolicited_StackerDBPushChunk` mutates the reply `StackerDBChunkInv` in place: [2](#0-1) 

The doc comment for this function explicitly states the caller must be careful because "the only modification possible here is to wake up the state machine," implying the actual storage happens elsewhere (in `Relayer::process_stacker_db_chunks`, via `try_replace_chunk` inside a DB transaction) [3](#0-2) . That downstream storage path can independently fail (`StaleChunk`, DB error, or simply never being invoked if the caller drops the returned `(bool,bool)` tuple without following through) and is logged only as a `debug!`/`warn!`, not propagated back to undo the inventory patch made here.

This breaks the equality "advertised inventory version == actually stored version." A remote, unauthenticated peer that opens a p2p connection and sends a validly-signed `StackerDBPushChunk` (which only requires knowledge of the chunk owner's signature — an ordinary StackerDB writer, not an admin) can cause the node to believe (and subsequently advertise to third parties via `StackerDBChunkInv`) that it has version N of a slot when the underlying replica may still hold an older version, if the write path afterward is skipped or fails for reasons unrelated to validity (DB error, or `send_reply=true` short-circuiting before the caller actually stores the chunk).

### Impact Explanation
This matches the "served vs committed" equality-break category. Peers computing sync backlogs from this node's advertised `StackerDBChunkInv` will conclude the slot is up to date and skip requesting it, causing the actual (stale) chunk to never propagate — a form of steering peers off the real replicated state (analogous to serving non-canonical state as canonical for the StackerDB subsystem). It does not directly cause fund loss (no financial resource analogous to the auction bug exists here), so the impact is best characterized as High per the read-endpoint/canonical-state-serving criteria, not Critical.

### Likelihood Explanation
Reaching this requires only an authenticated P2P handshake (any peer, no special privilege) and a validly-signed chunk for a slot whose owner key is already public (since slot signers/owners are recorded in `SlotValidation`, an attacker only needs their own slot's private key, which is the normal case for a StackerDB writer advertising their own data). The gap between "inventory patched" and "chunk actually persisted" is a structural, not merely theoretical, TOCTOU: the function's own doc/comments acknowledge storage happens elsewhere. However, exploiting it deterministically (forcing the downstream write to fail while still reaching this code path) requires timing/DB-transaction conditions I could not fully confirm are attacker-controllable from a remote position — this is the main uncertainty in this finding.

### Recommendation
Only patch `slot_versions` inventory after `try_replace_chunk`/`insert_chunk` has actually succeeded (i.e., move the inventory patch to occur post-storage in `Relayer::process_stacker_db_chunks`, or make `handle_unsolicited_StackerDBPushChunk` perform the store itself and patch on success only).

### Proof of Concept
1. Attacker connects as an ordinary peer and completes a handshake, becoming "authenticated" per `authenticate_unsolicited_messages` [4](#0-3) .
2. Attacker signs a `StackerDBChunkData` for a slot it legitimately owns with `slot_version = N`, and sends it as `StackerDBPushChunk`.
3. `handle_unsolicited_StackerDBPushChunk` validates it via `validate_received_chunk` (passes) and immediately sets `data.slot_versions[slot_id] = N` in the reply inventory [2](#0-1) , then replies with this `StackerDBChunkInv` if `send_reply` is set.
4. If the actual persistence step (elsewhere, via `try_replace_chunk`) does not happen or fails silently for that chunk, any peer querying this node's inventory afterward is told version N is present, while the local replica still serves an older/absent chunk on `StackerDBGetChunk`, creating a served-vs-committed mismatch that can stall replication of the true latest chunk across the network.

Note: I was not able to fully trace every code path that determines whether/when the actual `try_replace_chunk` write executes relative to this inventory patch (e.g., whether `send_reply=false` callers always subsequently persist the chunk before any inventory could be queried), so confidence in a fully deterministic exploit chain is moderate; a Devin session with full-repo access could confirm the exact caller sequencing in `relay.rs`/`p2p.rs` to nail down the precise race window.

    pub fn validate_received_chunk(
        &self,
        smart_contract_id: &QualifiedContractIdentifier,
        config: &StackerDBConfig,
        data: &StackerDBChunkData,
        expected_versions: &[u32],
    ) -> Result<bool, net_error> {
        // validate -- must not exceed this replica's configured chunk size.
        if (data.data.len() as u64) > config.chunk_size {
            info!(
                "Received StackerDBChunk for {} ID {}, which is oversized: {} bytes (max {} bytes)",
                smart_contract_id,
                data.slot_id,
                data.data.len(),
                config.chunk_size
            );
            return Ok(false);
        }

        // validate -- must be a valid chunk
        let Some(expected_version) = expected_versions.get(data.slot_id as usize) else {
            info!(
                "Received StackerDBChunk for {} ID {}, which is too big ({})",
                smart_contract_id,
                data.slot_id,
                expected_versions.len()
            );
            return Ok(false);
        };

        // validate -- must be signed by the expected author
        let addr = match self
            .stackerdbs
            .get_slot_signer(smart_contract_id, data.slot_id)?
        {
            Some(addr) => addr,
            None => {
                return Ok(false);
            }
        };

        let slot_metadata = data.get_slot_metadata();
        if !slot_metadata.verify(&addr)? {
            info!(
                "StackerDBChunk for {} ID {} is not signed by {}",
                smart_contract_id, data.slot_id, &addr
            );
            return Ok(false);
        }

        // validate -- must be the current or newer version
        if data.slot_version < *expected_version {
            info!(
                "Received StackerDBChunk for {} ID {} version {}, which is stale (expected {})",
                smart_contract_id, data.slot_id, data.slot_version, *expected_version
            );
            return Ok(false);
        }

        // validate -- must not exceed max writes
        if data.slot_version > config.max_writes {
            info!(
                "Write count exceeded for StackerDBChunk for {} ID {} version {} (max is {})",
                smart_contract_id, data.slot_id, data.slot_version, config.max_writes
            );
            return Ok(false);
        }

        Ok(true)

    /// Process newly-arrived chunks obtained from a peer stackerdb replica.
    /// Chunks that we store will be broadcast, since successful storage implies that they were new
    /// to us (and thus might be new to our neighbors)
    pub fn process_stacker_db_chunks(
        &mut self,
        rc_consensus_hash: &ConsensusHash,
        stackerdb_configs: &HashMap<QualifiedContractIdentifier, StackerDBConfig>,
        sync_results: Vec<StackerDBSyncResult>,
        event_observer: Option<&dyn StackerDBEventDispatcher>,
    ) -> Result<(), Error> {
        // sort stacker results by contract, so as to minimize the number of transactions.
        let mut sync_results_map: HashMap<QualifiedContractIdentifier, Vec<StackerDBSyncResult>> =
            HashMap::new();
        for sync_result in sync_results.into_iter() {
            if let Some(result_list) = sync_results_map.get_mut(&sync_result.contract_id) {
                result_list.push(sync_result);
            } else {
                sync_results_map.insert(sync_result.contract_id.clone(), vec![sync_result]);
            }
        }

        let mut all_events: HashMap<QualifiedContractIdentifier, Vec<StackerDBChunkData>> =
            HashMap::new();

        for (sc, sync_results) in sync_results_map.into_iter() {
            if let Some(config) = stackerdb_configs.get(&sc) {
                let tx = self.stacker_dbs.tx_begin(config.clone())?;
                for sync_result in sync_results.into_iter() {
                    for (origin, chunk) in sync_result.chunks_to_store.into_iter() {
                        let md = chunk.get_slot_metadata();
                        if let Err(e) = tx.try_replace_chunk(&sc, &md, &chunk.data) {
                            if matches!(e, Error::StaleChunk { .. }) {
                                // This is a common and expected message, so log it as a debug and with a sep message
                                // to distinguish it from other message types.
                                debug!(
                                    "Dropping stale StackerDB chunk";
                                    "stackerdb_contract_id" => %sync_result.contract_id,
                                    "slot_id" => md.slot_id,
                                    "slot_version" => md.slot_version,
                                    "num_bytes" => chunk.data.len(),
                                    "error" => %e
                                );
                            } else {
                                warn!(
                                    "Failed to store chunk for StackerDB";
                                    "stackerdb_contract_id" => %sync_result.contract_id,
                                    "slot_id" => md.slot_id,
                                    "slot_version" => md.slot_version,
                                    "num_bytes" => chunk.data.len(),
                                    "error" => %e
                                );
                            }
                            continue;
                        } else {
                            log_stored_stackerdb_chunk(&sync_result.contract_id, &chunk, &origin);
                        }

                        if let Some(event_list) = all_events.get_mut(&sync_result.contract_id) {
                            event_list.push(chunk.clone());
                        } else {
                            all_events.insert(sync_result.contract_id.clone(), vec![chunk.clone()]);
                        }

                        let msg = StacksMessageType::StackerDBPushChunk(StackerDBPushChunkData {
                            contract_id: sc.clone(),
                            rc_consensus_hash: rc_consensus_hash.clone(),
                            chunk_data: chunk,
                        });
                        if let Err(e) = self.p2p.broadcast_message(vec![], msg) {
                            warn!("Failed to broadcast StackerDB chunk: {e:?}");
                        }
                    }
                }
                tx.commit()?;
