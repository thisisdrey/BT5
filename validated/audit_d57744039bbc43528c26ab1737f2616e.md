Audit Report

## Title
Outbound-queue-v2 `process_delivery_receipt` ignores the `success` flag of the delivery receipt, paying relayer rewards and irreversibly clearing `PendingOrders` for failed deliveries - (File: `bridges/snowbridge/pallets/outbound-queue-v2/src/lib.rs`)

## Summary
`DeliveryReceipt` decodes the Ethereum `InboundMessageDispatched(nonce, topic, success, reward_address)` event and carries a `success: bool` field indicating whether the message dispatch on Ethereum actually succeeded. [1](#0-0)  `Pallet::process_delivery_receipt` never reads or checks `receipt.success` before paying the relayer reward and permanently removing the corresponding `PendingOrders` entry. [2](#0-1) 

## Finding Description
`submit_delivery_receipt` verifies the proof via `T::Verifier::verify`, decodes the log into a `DeliveryReceipt` (which includes `success`), and unconditionally forwards it to `process_delivery_receipt`: [3](#0-2) 

Inside `process_delivery_receipt`, only two checks gate the payout and removal: that `receipt.gateway` matches `T::GatewayAddress`, and that a `PendingOrder` exists for `receipt.nonce`. `receipt.success` is never referenced: [4](#0-3) 

A search of the entire pallet confirms `success` is never used anywhere in the pallet's logic beyond being decoded and dropped inside `DeliveryReceipt::try_from`. The module doc explicitly documents the intended (bug-consistent) flow: "Fetch the pending order by nonce of the message, pay reward with fee attached in the order" / "Remove the order from `PendingOrders`," with no success gating mentioned: [5](#0-4) 

Because `<PendingOrders<T>>::remove(nonce)` runs unconditionally once the order is found, this is irreversible — any subsequent receipt for the same `nonce` fails with `InvalidPendingNonce` since the entry no longer exists, so a failed delivery can never be corrected or reconciled through this pallet.

## Impact Explanation
This is a duplicate/incorrect settlement of bridge payout state: a genuine, correctly-proven `InboundMessageDispatched` event with `success = false` (a real Ethereum-side execution failure) still results in `T::RewardPayment::register_reward` paying the full relayer fee `order.fee`, exactly as if delivery had succeeded, and the `PendingOrder` is deleted, permanently marking a failed message as "delivered" with no path to retry or reconcile. This falls squarely under the pivot requiring "message queues, bridge markers, receipts, and payout state must only advance after decode, dispatch, execution, and settlement succeed atomically" — the exact wrong values are the relayer reward amount (`order.fee`, paid despite `success=false`) and the `PendingOrders[nonce]` queue marker (cleared despite failed execution).

## Likelihood Explanation
High. This requires only an unprivileged, honest relayer submitting a genuine, unmodified failed-delivery receipt via the public `submit_delivery_receipt` extrinsic — no malicious relayer, forged proof, or privileged access is needed. `T::Verifier::verify` legitimately accepts the proof since the underlying event genuinely occurred; the bug is purely that the pallet fails to branch on the semantic outcome the proof itself carries.

## Recommendation
In `process_delivery_receipt`, branch on `receipt.success`: if `true`, keep current behavior (pay reward, remove `PendingOrder`); if `false`, withhold or reduce the relayer reward for the failed dispatch and either retain the `PendingOrder` for retry/resolution or transition it to an explicit "failed" state instead of unconditionally deleting it via `<PendingOrders<T>>::remove(nonce)`.

## Proof of Concept
1. `do_process_message` queues a message, creating `PendingOrders[nonce] = { nonce, fee, block_number }`. [6](#0-5) 
2. On Ethereum, dispatch of the inbound message fails and the Gateway emits `InboundMessageDispatched(nonce, topic, success=false, reward_address)`.
3. Any relayer submits this genuine event/receipt via `submit_delivery_receipt(origin, event)`.
4. `T::Verifier::verify` succeeds; `DeliveryReceipt::try_from` decodes `success = false` correctly.
5. `process_delivery_receipt` checks only `gateway` and `PendingOrders[nonce]` existence; both pass, so `T::RewardPayment::register_reward(&reward_account, ..., order.fee)` executes and `<PendingOrders<T>>::remove(nonce)` runs unconditionally.
6. The relayer is paid despite the failed delivery, and the failed message is permanently marked resolved in `PendingOrders`, matching the code path exercised (minus the success check) in the existing `submit_delivery_receipt_succeeds_after_unhalt` test. [7](#0-6)

		/// Process a delivery receipt from a relayer, to allocate the relayer reward.
		pub fn process_delivery_receipt(
			relayer: <T as frame_system::Config>::AccountId,
			receipt: DeliveryReceipt,
		) -> DispatchResult
		where
			<T as frame_system::Config>::AccountId: From<[u8; 32]>,
		{
			// Verify that the message was submitted from the known Gateway contract
			ensure!(T::GatewayAddress::get() == receipt.gateway, Error::<T>::InvalidGateway);

			let reward_account = if receipt.reward_address == [0u8; 32] {
				relayer
			} else {
				receipt.reward_address.into()
			};

			let nonce = receipt.nonce;

			let order = <PendingOrders<T>>::get(nonce).ok_or(Error::<T>::InvalidPendingNonce)?;

			if order.fee > 0 {
				// Pay relayer reward
				T::RewardPayment::register_reward(
					&reward_account,
					T::DefaultRewardKind::get(),
					order.fee,
				);
			}

			<PendingOrders<T>>::remove(nonce);

			Self::deposit_event(Event::MessageDelivered { nonce });

			Ok(())
		}

fn submit_delivery_receipt_succeeds_after_unhalt() {
	new_tester().execute_with(|| {
		let nonce = 0;
		let fee: u128 = 1_000_000;
		let order = PendingOrder { nonce, fee, block_number: System::block_number() };
		PendingOrders::<Test>::insert(nonce, order);

		let relayer: AccountId32 = [7u8; 32].into();
		let origin = RuntimeOrigin::signed(relayer);
		let event = Box::new(mock_valid_event_proof());

		// Bridge halted — receipt rejected, order untouched.
		set_verifier_halted(true);
		assert_noop!(
			OutboundQueue::submit_delivery_receipt(origin.clone(), event.clone()),
			Error::<Test>::Verification(VerificationError::Halted)
		);
		assert!(PendingOrders::<Test>::get(nonce).is_some());

		// Bridge resumed — same receipt succeeds and the order is settled.
		set_verifier_halted(false);
		assert_ok!(OutboundQueue::submit_delivery_receipt(origin, event));
		assert!(PendingOrders::<Test>::get(nonce).is_none());

		System::assert_has_event(mock::RuntimeEvent::OutboundQueue(Event::MessageDelivered {
			nonce,
		}));
	});
