### Title
Unauthenticated single-request abort permanently kills the signer's monitoring server thread, freezing all Prometheus gauges - (File: stacks-signer/src/monitoring/server.rs)

### Summary
`MonitoringServer::main_loop` (server.rs:116-171) calls `refresh_metrics` once per loop iteration before blocking on `self.http_server.recv()`, and every response path in the loop uses `.expect(...)` on `request.respond(...)` (lines 134, 141, 149, 162, 168-169). If a client disconnects before the response write completes, `respond()` returns an `Err`, `.expect()` panics, and the panic unwinds the entire `main_loop` call, not just the current iteration.

### Finding Description
The invariant the question is testing — "signer metrics gauges continue to refresh after any single crafted disconnect" — is broken. `main_loop` has no per-request panic isolation: `request.respond(response).expect("Failed to send response")` and the three similar sites for `/info`, `/`, `/heartbeat`, and the 404 fallback (server.rs:134, 141, 149, 161-162, 167-169) will panic if the underlying `tiny_http` write fails (e.g., broken pipe/connection reset because the peer closed the socket after sending the request but before reading the response). Because `refresh_metrics`/`update_metrics` (server.rs:174-210) and the request-serving logic live in the same function-level loop with no `catch_unwind`, a panic anywhere in that loop unwinds out of `main_loop` entirely, terminating the whole function — including the `loop {}` that would otherwise call `refresh_metrics` and `self.http_server.recv()` again.

Reachability: `MonitoringServer::start` is invoked from `start_serving_monitoring_metrics` (mod.rs:172-186), which spawns it on a dedicated OS thread named `signer_metrics` via `std::thread::Builder::new().spawn(...)`. There is no retry/respawn logic wrapping this thread. A default (non-abort) panic strategy is used (no `panic = "abort"` in the workspace), so the panic is confined to the `signer_metrics` thread — but that thread is never restarted. Once it panics, the closure passed to `spawn` simply returns, the thread exits, and `main_loop` (and therefore `refresh_metrics`/`update_metrics`) never executes again for the remaining lifetime of the process.

Attacker exact action: open a TCP connection to the configured `metrics_endpoint`, send a valid minimal HTTP request line (e.g., `GET /metrics HTTP/1.1\r\n\r\n`), then immediately close the socket before the server can write the response back. `tiny_http`'s `respond()` will surface the write failure as an `Err`, triggering `.expect("Failed to send response")` to panic.

### Impact Explanation
A single unauthenticated TCP connection that aborts before reading the HTTP response permanently kills the `signer_metrics` thread. After that point:
- The `/metrics`, `/info`, `/`, and `/heartbeat` endpoints stop responding at all (the whole `HttpServer::recv()` loop is dead), not just gauge refresh.
- `stacks_tip_height`, `reward_cycle_id`, nonce, and balance gauges freeze at their last-known values forever, appearing to external monitoring/alerting (e.g., Prometheus/Grafana) as if the signer is healthy and unchanged, silently defeating operational monitoring for the signer.
- No automatic recovery exists; the process must be restarted to restore monitoring.

This matches the "Critical - remote crash/unauthenticated DoS from few messages" category, scoped specifically to the signer's monitoring subsystem: one crafted disconnect permanently disables the entire monitoring HTTP server (not merely metric refresh) for the life of the process.

### Likelihood Explanation
- Precondition: operator must configure `metrics_endpoint` (config.rs) and build with the `monitoring_prom` feature — this is a common/default deployment pattern for signer operators who want Prometheus scraping.
- No authentication or secret is required to hit this endpoint; it is a plain HTTP listener.
- Attack cost is a single TCP connection and one HTTP request line, then close-before-read — trivially reproducible, not volumetric.
- Fully repeatable: as soon as the operator restarts the process, the same one-shot attack works again.

### Recommendation
Wrap each request-handling branch (and the `refresh_metrics`/`update_metrics` calls) in `std::panic::catch_unwind`, or replace `.expect(...)` on `request.respond(...)` with a `match`/`if let Err(e) = ... { warn!(...); continue; }` pattern so that a failed write to a disconnected client only skips that one request instead of unwinding the whole `main_loop`. Additionally, consider wrapping the thread spawned in `start_serving_monitoring_metrics` with a supervising restart loop so a panic (from any other unexpected source) does not permanently disable monitoring.

    pub fn main_loop(&mut self) -> Result<(), MonitoringError> {
        info!("{}: Starting Prometheus metrics server", self);
        loop {
            if let Err(err) = self.refresh_metrics() {
                error!("Monitoring: Error refreshing metrics: {:?}", err);
            }
            let request = match self.http_server.recv() {
                Ok(request) => request,
                Err(err) => {
                    error!("Monitoring: Error receiving request: {:?}", err);
                    return Err(MonitoringError::Terminated);
                }
            };

            debug!("{}: received request {}", self, request.url());

            if request.url() == "/metrics" {
                let response = HttpResponse::from_string(gather_metrics_string());
                request.respond(response).expect("Failed to send response");
                continue;
            }

            if request.url() == "/info" {
                request
                    .respond(HttpResponse::from_string(self.get_info_response()))
                    .expect("Failed to respond to request");
                continue;
            }

            // return 200 OK for "/"
            if request.url() == "/" {
                request
                    .respond(HttpResponse::from_string("OK"))
                    .expect("Failed to respond to request");
                continue;
            }

            // Run heartbeat check to test connection to the node
            if request.url() == "/heartbeat" {
                let (msg, status) = if self.heartbeat() {
                    ("OK", 200)
                } else {
                    ("Failed", 500)
                };
                request
                    .respond(HttpResponse::from_string(msg).with_status_code(status))
                    .expect("Failed to respond to request");
                continue;
            }

            // unknown request, return 404
            request
                .respond(HttpResponse::from_string("Not Found").with_status_code(404))
                .expect("Failed to respond to request");
        }
    }

    fn refresh_metrics(&mut self) -> Result<(), MonitoringError> {
        let now = Instant::now();
        if now.duration_since(self.last_metrics_poll).as_secs() > 60 {
            self.last_metrics_poll = now;
            self.update_metrics()?;
        }
        Ok(())
    }

    /// Update metrics by making RPC calls to the Stacks node
    fn update_metrics(&self) -> Result<(), MonitoringError> {
        debug!("{}: Updating metrics", self);
        let peer_info = self.stacks_client.get_peer_info()?;
        if let Ok(height) = i64::try_from(peer_info.stacks_tip_height) {
            update_stacks_tip_height(height);
        } else {
            warn!(
                "Failed to parse stacks tip height: {}",
                peer_info.stacks_tip_height
            );
        }
        let pox_info = self.stacks_client.get_pox_data()?;
        if let Ok(reward_cycle) = i64::try_from(pox_info.reward_cycle_id) {
            update_reward_cycle(reward_cycle);
        }
        let signer_stx_addr = self.stacks_client.get_signer_address();
        let account_entry = self.stacks_client.get_account_entry(signer_stx_addr)?;
        let balance = i64::from_str_radix(&account_entry.balance[2..], 16).map_err(|e| {
            MonitoringError::FetchError(ClientError::MalformedClarityValue(format!(
                "Failed to parse balance: {} with err: {}",
                account_entry.balance, e,
            )))
        })?;
        update_signer_nonce(account_entry.nonce);
        update_signer_stx_balance(balance);
        Ok(())
    }

    /// Start serving monitoring metrics.
    /// This will only serve the metrics if the `monitoring_prom` feature is enabled.
    pub fn start_serving_monitoring_metrics(config: GlobalConfig) -> Result<(), String> {
        if config.metrics_endpoint.is_none() {
            return Ok(());
        }
        let _ = std::thread::Builder::new()
            .name("signer_metrics".to_string())
            .spawn(move || {
                if let Err(monitoring_err) = super::server::MonitoringServer::start(&config) {
                    error!("Monitoring: Error in metrics server: {:?}", monitoring_err);
                }
            });
        Ok(())
    }
