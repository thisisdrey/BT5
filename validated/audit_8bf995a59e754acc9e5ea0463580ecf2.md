### Title
Same-transaction pull-oracle repricing enables risk-free cross-synth swap arbitrage - ([File: contracts/Pool.sol](contracts/Pool.sol))

### Summary
Metronome prices all synth-to-synth swaps through `masterOracle().quote()` at the moment of each `Pool.swap` call, and `Operator.execute` lets any EOA batch arbitrary calls — including `updatePriceFeeds`/`updatePrice` on the pull provider — into one atomic transaction. As in the FlatMoney/Pyth issue, two distinct valid prices can therefore be observed inside one transaction: the attacker swaps USD-synth → ETH-synth at price P1, pushes a newer Pyth/RedStone update with P2 > P1, and swaps back ETH-synth → USD-synth at P2, extracting `(P2/P1 - 1) - 2*swapFee` per unit with no inventory risk.

### Finding Description
`Pool.swap` burns `syntheticTokenIn_`, prices the trade via `quoteSwapOut` → `masterOracle().quote(...)`, and mints `syntheticTokenOut_` to the caller (`contracts/Pool.sol:642-671`). There is no per-block price pinning, no same-transaction update guard, and no check that the oracle price was the same across the transaction. `Operator.execute` executes an arbitrary array of calls with `msg.value` forwarding (`contracts/Operator.sol:34-55`), and the deployed configuration routes pricing through a pull oracle (Pyth on mainnet, RedStone on Hemi) that anyone can permissionlessly update — the repo's own E2E tests batch `pyth.updatePriceFeeds` + `deposit` and `updatePrice` + `debtPositionOf` in a single `operator.execute` (`test/E2E.mainnet.test.ts:944-1077`, `test/E2E.hemi.pullOracle.test.ts:129-175`). Pyth accepts any signed update whose `publishTime <= block.timestamp`, and publishes multiple updates per block window, so two different valid prices can be made current in the same transaction. The attacker only needs to pre-position inventory (hold or mint msUSD/msETH against collateral) and submit `Operator.execute([updateP1, swap(msUSD→msETH), updateP2, swap(msETH→msUSD)])` — or run the whole thing from an attacker contract calling `Pool.swap` directly.

### Impact Explanation
Direct value extraction from the protocol: `Pool.swap` mints synthetic tokens at oracle value, so each profitable round-trip mints more synth value than was burned, paid for by other synth holders/LPs via dilution of the debt pools. Profit per round-trip ≈ `notional * ((P2 - P1)/P1 - 2*swapFee)` and can be repeated every block where a profitable update pair exists, scaling with attacker inventory.

### Likelihood Explanation
Requires (a) the pull oracle to be the active price source (deployed config on Hemi uses RedStone; Pyth wiring exists for mainnet), (b) two valid updates in the block's accepted window with relative move exceeding twice the swap fee — feasible during normal volatility since Pyth updates roughly every 400ms, and (c) attacker wins execution ordering, which is guaranteed since they submit all steps atomically in one transaction. No privileged role is needed; all calls are public.

### Recommendation
Pin oracle consistency per transaction in the protocol layer: e.g., have `MasterOracle`/the pull provider record the last price-update timestamp and reject reads (or reuse the earlier price) when an update landed in the same `block.timestamp`/`block.number` as a previous update in the tx — the FlatMoney fix pattern (`if (lastUpdate >= block.timestamp) return`). Alternatively require `swap` to settle against a price published strictly before the current block.

### Proof of Concept
Fork test sketch (Hardhat, mainnet/Hemi fork), following the existing E2E pattern:

```ts
// prerequisites: alice holds msUSD (issued against collateral or bought)
const p1 = await pythAPI.getPriceFeedsUpdateData([ETH_FEED_ID])          // older update
const p2 = await pythAPI.getPriceFeedsUpdateData([ETH_FEED_ID /* newer ts, price > p1 */])
const fee = await pyth.getUpdateFee(p1) + await pyth.getUpdateFee(p2)

const calls = [
  {target: pyth.address, value: fee1, callData: pyth.interface.encodeFunctionData('updatePriceFeeds', [p1])},
  {target: pool.address, value: 0,    callData: pool.interface.encodeFunctionData('swap', [msUSD.address, msETH.address, amountIn])},
  {target: pyth.address, value: fee2, callData: pyth.interface.encodeFunctionData('updatePriceFeeds', [p2])},
  {target: pool.address, value: 0,    callData: pool.interface.encodeFunctionData('swap', [msETH.address, msUSD.address, receivedETH])},
]
await operator.connect(alice).execute(calls, {value: fee})
// assert: msUSD balance after > before when (P2/P1 - 1) > 2 * defaultSwapFee
```
