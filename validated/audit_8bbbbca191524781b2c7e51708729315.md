### Title
Unbounded per-account asset map growth enables bandwidth-accounting DoS via `TransferAssetActuator` / `BandwidthProcessor` - (File: `chainbase/src/main/java/org/tron/core/db/BandwidthProcessor.java`)

### Summary
Any unprivileged account can accumulate an unbounded number of distinct TRC10 token balances by having anyone send it 1 unit of many different asset IDs via `TransferAssetActuator`. There is no cap on the number of distinct entries in an account's `assetV2` map. Every time that account is later involved in a transaction (as sender), `BandwidthProcessor.updateUsage()` performs an unbounded iteration over the account's entire asset map to recompute free-bandwidth usage for every asset it holds — this is directly analogous to the reported `GetAllBalances`-triggers-unbounded-iteration bug class, except here the unbounded collection is walked on the hot path of ordinary transaction processing/bandwidth accounting rather than at genesis.

### Finding Description
`TransferAssetActuator.execute()` calls `accountCapsule.addAssetAmountV2(...)`, which unconditionally inserts a new entry into the target account's `assetV2` map for any valid, existing TRC10 token ID, with no check on how many distinct assets the target account already holds: [1](#0-0) [2](#0-1) 

Because TRC10 token issuance is permissionless (subject only to a fee) and asset transfers of 1-unit amounts are cheap, an attacker can issue or acquire many distinct token IDs and transfer tiny amounts of each into a victim account, growing that account's `assetV2Map` without bound.

Later, whenever the victim account is the owner of *any* transaction (even an unrelated `TransferContract`), `BandwidthProcessor.updateUsage()` is invoked and iterates over the account's entire asset map to update free-net usage bookkeeping for every asset the account holds: [3](#0-2) 

This method is called from `BandwidthProcessor.consume()`, which is invoked during transaction processing in `Manager.java`, and is also invoked from query-serving code paths in `Wallet.java` (e.g. `getAccountNet`), which itself additionally iterates the same asset map a second time via `setAssetNetLimit`: [4](#0-3) [5](#0-4) 

Thus a single victim account, once "polluted" with an arbitrarily large number of distinct asset entries by an attacker's transactions, becomes expensive to process on every subsequent transaction it makes and every API query about it — an unbounded-iteration-over-attacker-controlled-map pattern, matching the reported bug class where an unbounded, attacker-inflatable balance map is walked on a critical path (there: genesis; here: per-transaction bandwidth accounting and account/net RPC queries).

### Impact Explanation
Each additional distinct asset in an account's map adds one more iteration of `increase()` bandwidth-recovery math per transaction that account submits and per RPC query (`getAccountNet`) issued against it. This is a computational-cost/DoS vector on the transaction execution and gRPC/HTTP query path: an attacker can render a targeted account (or, if they target their own address then trigger many transactions from it, degrade block-processing time broadly) disproportionately expensive to process relative to the resources spent (bandwidth/fee) by the attacker, without any corresponding cap or fee scaling. Since block application must process all transactions from all accounts sequentially, a sufficiently polluted account slows down Manager's transaction consumption and any node serving `getAccountNet`/wallet queries for it.

### Likelihood Explanation
Medium. Exploitation requires the attacker to pay for TRC10 issuance fees and transfer fees repeatedly (issuing/holding many token IDs and sending 1-unit transfers), which is a real but bounded cost; there's no complexity beyond normal transaction issuance, and no special privilege is needed — any transaction broadcaster can do this against any account, including their own or a victim's. This mirrors the original report's assessment that there's "no material incentive... other than slowing down" a target, but the mechanism is concretely reachable from ordinary signed transactions.

### Recommendation
- Cap the number of distinct TRC10 asset entries (`assetV2Map` size) an account may hold, enforced in `AccountCapsule.addAssetAmountV2` / validated in `TransferAssetActuator.validate()` before allowing a transfer that would introduce a new asset entry to the recipient.
- Alternatively/additionally, avoid recomputing bandwidth usage for the full asset map on every transaction in `BandwidthProcessor.updateUsage()` — only touch/recompute the specific asset(s) involved in the current contract, rather than iterating `getAssetMapV2()`/`getAllFreeAssetNetUsageV2()` for all held assets on every unrelated transaction.
- Apply the same denom-by-denom targeted-lookup approach recommended in the original report (avoid `GetAll*`-style full iteration; look up only the balances relevant to the current operation) in both `BandwidthProcessor.updateUsage` and `Wallet.getAccountNet`/`setAssetNetLimit`.

### Proof of Concept
1. Attacker issues (or otherwise controls) N distinct TRC10 tokens (e.g., N = 10,000), paying the standard asset-issue fee each time.
2. Attacker submits N `TransferAssetContract` transactions, each transferring 1 unit of a different token ID to victim address `V`. `TransferAssetActuator.execute()` inserts a new key into `V`'s `assetV2Map` for each transfer (`AccountCapsule.addAssetAmountV2`), with no limit on map size.
3. `V`'s `assetV2Map` now has N entries.
4. Any transaction subsequently submitted with `V` as the owner (or any `getAccountNet` RPC query on `V`) causes `BandwidthProcessor.updateUsage(V)` (and, for RPC, `Wallet.setAssetNetLimit`) to iterate all N map entries, multiplying the per-transaction/per-query processing cost by N relative to a normal account, without a corresponding fee increase.

  public boolean addAssetAmountV2(byte[] key, long amount,
      DynamicPropertiesStore dynamicPropertiesStore, AssetIssueStore assetIssueStore) {
    importAsset(key);
    boolean disableJavaLangMath = dynamicPropertiesStore.disableJavaLangMath();
    //key is token name
    if (dynamicPropertiesStore.getAllowSameTokenName() == 0) {
      Map<String, Long> assetMap = this.account.getAssetMap();
      AssetIssueCapsule assetIssueCapsule = assetIssueStore.get(key);
      String tokenID = assetIssueCapsule.getId();
      String nameKey = ByteArray.toStr(key);
      Long currentAmount = assetMap.get(nameKey);
      if (currentAmount == null) {
        currentAmount = 0L;
      }
      this.account = this.account.toBuilder()
          .putAsset(nameKey, addExact(currentAmount, amount, disableJavaLangMath))
          .putAssetV2(tokenID, addExact(currentAmount, amount, disableJavaLangMath))
          .build();
    }
    //key is token id
    if (dynamicPropertiesStore.getAllowSameTokenName() == 1) {
      String tokenIDStr = ByteArray.toStr(key);
      Map<String, Long> assetMapV2 = this.account.getAssetV2Map();
      Long currentAmount = assetMapV2.get(tokenIDStr);
      if (currentAmount == null) {
        currentAmount = 0L;
      }
      this.account = this.account.toBuilder()
          .putAssetV2(tokenIDStr, addExact(currentAmount, amount, disableJavaLangMath))
          .build();
    }
    return true;
  }

  public void updateUsage(AccountCapsule accountCapsule) {
    long now = chainBaseManager.getHeadSlot();
    long oldNetUsage = accountCapsule.getNetUsage();
    long latestConsumeTime = accountCapsule.getLatestConsumeTime();
    accountCapsule.setNetUsage(increase(accountCapsule, BANDWIDTH,
            oldNetUsage, 0, latestConsumeTime, now));
    long oldFreeNetUsage = accountCapsule.getFreeNetUsage();
    long latestConsumeFreeTime = accountCapsule.getLatestConsumeFreeTime();
    accountCapsule.setFreeNetUsage(increase(oldFreeNetUsage, 0, latestConsumeFreeTime, now));

    if (chainBaseManager.getDynamicPropertiesStore().getAllowSameTokenName() == 0) {
      Map<String, Long> assetMap = accountCapsule.getAssetMap();
      assetMap.forEach((assetName, balance) -> {
        long oldFreeAssetNetUsage = accountCapsule.getFreeAssetNetUsage(assetName);
        long latestAssetOperationTime = accountCapsule.getLatestAssetOperationTime(assetName);
        accountCapsule.putFreeAssetNetUsage(assetName,
            increase(oldFreeAssetNetUsage, 0, latestAssetOperationTime, now));
      });
    }
    Map<String, Long> assetMapV2 = accountCapsule.getAssetMapV2();
    Map<String, Long> map = new HashMap<>(assetMapV2);
    accountCapsule.getAllFreeAssetNetUsageV2().forEach((k, v) -> {
      if (!map.containsKey(k)) {
        map.put(k, 0L);
      }
    });
    map.forEach((assetName, balance) -> {
      long oldFreeAssetNetUsage = accountCapsule.getFreeAssetNetUsageV2(assetName);
      long latestAssetOperationTime = accountCapsule.getLatestAssetOperationTimeV2(assetName);
      accountCapsule.putFreeAssetNetUsageV2(assetName,
          increase(oldFreeAssetNetUsage, 0, latestAssetOperationTime, now));
    });

  private Map<String, Long> setAssetNetLimit(Map<String, Long> assetNetLimitMap,
      AccountCapsule accountCapsule) {
    Map<String, Long> allFreeAssetNetUsage;
    if (chainBaseManager.getDynamicPropertiesStore().getAllowSameTokenName() == 0) {
      allFreeAssetNetUsage = accountCapsule.getAllFreeAssetNetUsage();
      allFreeAssetNetUsage.keySet().forEach(asset -> {
        byte[] key = ByteArray.fromString(asset);
        assetNetLimitMap
            .put(asset, chainBaseManager.getAssetIssueStore().get(key).getFreeAssetNetLimit());
      });
    } else {
      allFreeAssetNetUsage = accountCapsule.getAllFreeAssetNetUsageV2();
      allFreeAssetNetUsage.keySet().forEach(asset -> {
        byte[] key = ByteArray.fromString(asset);
        assetNetLimitMap
            .put(asset, chainBaseManager.getAssetIssueV2Store().get(key).getFreeAssetNetLimit());
      });
    }
    return allFreeAssetNetUsage;
  }

  public AccountNetMessage getAccountNet(ByteString accountAddress) {
    if (accountAddress == null || accountAddress.isEmpty()) {
      return null;
    }
    AccountNetMessage.Builder builder = AccountNetMessage.newBuilder();
    AccountCapsule accountCapsule =
        chainBaseManager.getAccountStore().get(accountAddress.toByteArray());
    if (accountCapsule == null) {
      return null;
    }

    BandwidthProcessor processor = new BandwidthProcessor(chainBaseManager);
    processor.updateUsage(accountCapsule);

    long netLimit = processor
        .calculateGlobalNetLimit(accountCapsule);
    long freeNetLimit = chainBaseManager.getDynamicPropertiesStore().getFreeNetLimit();
    long totalNetLimit = chainBaseManager.getDynamicPropertiesStore().getTotalNetLimit();
    long totalNetWeight = chainBaseManager.getDynamicPropertiesStore().getTotalNetWeight();

    Map<String, Long> assetNetLimitMap = new HashMap<>();
    Map<String, Long> allFreeAssetNetUsage = setAssetNetLimit(assetNetLimitMap, accountCapsule);

    builder.setFreeNetUsed(accountCapsule.getFreeNetUsage())
        .setFreeNetLimit(freeNetLimit)
        .setNetUsed(accountCapsule.getNetUsage())
        .setNetLimit(netLimit)
        .setTotalNetLimit(totalNetLimit)
        .setTotalNetWeight(totalNetWeight)
        .putAllAssetNetUsed(allFreeAssetNetUsage)
        .putAllAssetNetLimit(assetNetLimitMap);
    return builder.build();
  }
