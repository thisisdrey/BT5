### Title
Path traversal in WAL log entry archive extraction allows arbitrary file write during `gitaly recovery replay` - (File: internal/cli/gitaly/subcmd_recovery_replay.go)

### Summary
The `extractArchive` function used by `gitaly recovery replay` to unpack write-ahead-log (WAL) entry archives builds extraction target paths with `filepath.Join(path, header.Name)` and never verifies that the resulting path stays within the intended staging directory, unlike the equivalent tar-extraction logic elsewhere in the codebase (`internal/gitaly/service/repository/replicate.go`'s `extractTarToDirectory`, which explicitly checks `strings.HasPrefix(targetPath, targetDir+string(os.PathSeparator))` for regular files, directories, symlinks, and hard links). This mirrors the structural flaw in the reported Balancer bug: a value taken from attacker/log-controlled input (there, a scaled withdrawal amount; here, a tar header name) is passed into a downstream primitive (`git-archive` exit userData / `os.OpenFile`) without validating that it satisfies the invariant the calling code relies on (exact withdrawal amount / staying inside the staging directory), producing an unsafe result that the caller assumes is safe.

### Finding Description
`processLogEntry` in `internal/cli/gitaly/subcmd_recovery_replay.go` creates a per-entry staging directory and calls `extractArchive(reader, stagingDir)` to unpack a tar archive read from the log entry store via `rc.logEntryStore.GetReader`: [1](#0-0) 

`extractArchive` itself performs no path containment check on `header.Name`: [2](#0-1) 

Specifically, `target := filepath.Join(path, header.Name)` is used directly for both `MkdirAll` and `OpenFile(target, os.O_CREATE|os.O_RDWR, ...)`. If `header.Name` contains `../` sequences (or is an absolute path, which `filepath.Join` will still combine oddly), the resulting `target` can escape `stagingDir` entirely and write/overwrite arbitrary files (including symlink targets are not even validated as this code doesn't handle `tar.TypeSymlink`/`tar.TypeLink` at all — but `tar.TypeReg` and `tar.TypeDir` entries alone are enough to escape via `..`).

By contrast, the very similar snapshot-extraction code path in `replicate.go` explicitly guards against this: [3](#0-2) 

And `extractBackup` in `subcmd_recovery_restore.go` (used by `gitaly recovery restore`) has the same missing-containment-check flaw as `extractArchive`: [4](#0-3) 

Both `extractArchive` and `extractBackup` read data as it comes back from the log-entry-store backend or the backup sink (`internal/backup`), which is written by regular WAL log-entry archiving during normal operation. The tar archives being unpacked here originate from data that was itself written earlier by Gitaly's own backup/WAL-archival tooling (`internal/backup`), meaning the attack requires an operator to control or corrupt an archived WAL entry or backup blob (e.g. a malicious/compromised backup sink, or a WAL entry written under attacker influence) before `recovery replay`/`recovery restore` is run against it.

### Impact Explanation
If a tar entry with a crafted `Name` field (e.g. `../../../etc/cron.d/pwn` or similar) reaches this code, `extractArchive`/`extractBackup` will create directories and write file contents outside of the isolated staging/temp directory that the recovery tooling assumes is a sandbox. This is a storage/path escape: arbitrary file write on the Gitaly node's filesystem, which can lead to code execution (e.g. overwriting cron files, systemd units, or Gitaly's own hook scripts) or corruption of other repositories/storages, well beyond the scope of the single partition being recovered. This is functionally the same class of defect as the reported issue in that a downstream primitive (`tar` extraction / `git-archive` withdrawal size) is fed an unvalidated value that violates a safety invariant the surrounding code implicitly trusts.

### Likelihood Explanation
Exploitation requires that a maliciously-crafted tar archive be present in the WAL log-entry store or backup sink that `gitaly recovery replay`/`gitaly recovery restore` reads from. These commands are administrative/operator tools (not exposed directly as a gRPC), but the log-entry store and backup sink are exactly the kind of components fed by Gitaly's own storage/WAL machinery and external backup sinks, which per the analog rules are in-scope ("storage-path resolution", "archive or bundle extraction"). Given that the equivalent code in `replicate.go` was hardened with explicit containment checks while these two `recovery` sub-commands were not, this looks like an overlooked/incomplete fix rather than an intentionally accepted risk, and it is the strongest reachable analog to the reported "unvalidated amount passed to a security-sensitive primitive" bug class in this codebase.

### Recommendation
Add the same path-containment validation used in `extractTarToDirectory` (`internal/gitaly/service/repository/replicate.go`) to both `extractArchive` (`subcmd_recovery_replay.go`) and `extractBackup` (`subcmd_recovery_restore.go`): after computing `target`/`targetPath` via `filepath.Join`, verify with `filepath.Clean` plus a `strings.HasPrefix(target, destDir+string(os.PathSeparator))` (or equivalent) check before creating directories or writing files, and reject/skip any entry that would escape the destination directory. Also consider rejecting or properly validating `tar.TypeSymlink`/`tar.TypeLink` entries as `replicate.go` does, since `extractArchive` currently rejects unsupported types but a similarly unguarded symlink handler could reintroduce the same class of bug if added later.

### Proof of Concept
1. Craft a tar archive containing an entry with `Name: "../../outside.txt"` (or nested `..` traversal to reach an arbitrary absolute path) and `Typeflag: tar.TypeReg`, with attacker-controlled content.
2. Place this archive where `rc.logEntryStore.GetReader` (for `recovery replay`) or `recoveryContext.backupSink.GetReader` (for `recovery restore`) will return it as the next log entry or the latest backup entry (e.g. by controlling/corrupting the storage backing the WAL archive or backup sink).
3. Run `gitaly recovery --config gitaly.config.toml replay --storage <storage> --partition <id>` (or `... restore ...`).
4. `extractArchive`/`extractBackup` calls `filepath.Join(stagingDir/destDir, "../../outside.txt")`, resolving outside the intended staging/temp directory, and writes the attacker-controlled content via `os.OpenFile`/`io.Copy`, demonstrating the containment escape (this mirrors how, in the original report, `_vaultWithdraw` was fed an unvalidated/incorrectly-derived amount and produced an unexpected on-chain effect instead of the caller's intended, bounded operation).

func processLogEntry(reader io.Reader, tempDir string, logWriter storage.LogWriter, lsn storage.LSN) (returnErr error) {
	stagingDir, err := os.MkdirTemp(tempDir, "staging-*")
	if err != nil {
		return fmt.Errorf("create staging dir: %w", err)
	}
	defer func() {
		if err := os.RemoveAll(stagingDir); err != nil {
			returnErr = errors.Join(returnErr, fmt.Errorf("removing temp staging dir: %w", err))
		}
	}()

	if err := extractArchive(reader, stagingDir); err != nil {
		return fmt.Errorf("extract archive: %w", err)
	}

	// Validate that WAL entry was extracted correctly to its own directory
	entryPath := filepath.Join(stagingDir, lsn.String())
	info, err := os.Stat(entryPath)
	if err != nil {
		return fmt.Errorf("WAL entry not found after archive extraction: %w", err)
	}
	if !info.IsDir() {
		return fmt.Errorf("expected WAL entry path %s to be a directory", entryPath)
	}

	if _, err := logWriter.CompareAndAppendLogEntry(lsn, entryPath); err != nil {
		return fmt.Errorf("append log entry: %w", err)
	}
	logWriter.NotifyNewEntries()

	return nil
}

func extractArchive(reader io.Reader, path string) error {
	tr := tar.NewReader(reader)
	for {
		header, err := tr.Next()
		if err == io.EOF {
			break
		}
		if err != nil {
			return fmt.Errorf("read tar header: %w", err)
		}

		target := filepath.Join(path, header.Name)
		switch header.Typeflag {
		case tar.TypeDir:
			if err := os.MkdirAll(target, mode.Directory); err != nil {
				return fmt.Errorf("create directory: %w", err)
			}
		case tar.TypeReg:
			f, err := os.OpenFile(target, os.O_CREATE|os.O_RDWR, os.FileMode(header.Mode))
			if err != nil {
				return fmt.Errorf("create file: %w", err)
			}
			if _, err := io.Copy(f, tr); err != nil {
				f.Close()
				return fmt.Errorf("write file content: %w", err)
			}
			f.Close()
		default:
			return fmt.Errorf("tar header type not supported: %d", header.Typeflag)
		}
	}

	return nil
}

// extractTarToDirectory extracts a tar archive to the specified directory using Go's tar package
func (s *server) extractTarToDirectory(ctx context.Context, reader io.Reader, targetDir string) error {
	targetDir = filepath.Clean(targetDir)
	tarReader := tar.NewReader(reader)

	for {
		select {
		case <-ctx.Done():
			return ctx.Err()
		default:
		}

		header, err := tarReader.Next()
		if err == io.EOF {
			break // End of archive
		}
		if err != nil {
			return fmt.Errorf("reading tar header: %w", err)
		}

		targetPath := filepath.Join(targetDir, header.Name)

		if !strings.HasPrefix(targetPath, targetDir+string(os.PathSeparator)) &&
			targetPath != targetDir {
			return fmt.Errorf("invalid file path in tar: %s", header.Name)

func extractBackup(reader io.Reader, destDir string) (string, error) {
	var repoRelPath string
	tarReader := tar.NewReader(reader)
	for {
		header, err := tarReader.Next()
		if err != nil {
			if errors.Is(err, io.EOF) {
				break
			}

			return repoRelPath, fmt.Errorf("read tar header: %w", err)
		}

		targetPath := filepath.Join(destDir, header.Name)

		switch header.Typeflag {
		case tar.TypeDir:
			if err := os.MkdirAll(targetPath, os.FileMode(header.Mode)); err != nil {
				return repoRelPath, fmt.Errorf("create directory %s: %w", header.Name, err)
			}

			if strings.HasSuffix(targetPath, ".git") {
				repoRelPath, err = filepath.Rel(filepath.Join(destDir, "fs"), targetPath)
				if err != nil {
					return repoRelPath, fmt.Errorf("find rel path: %w", err)
				}
			}
		case tar.TypeReg:
			if err := os.MkdirAll(filepath.Dir(targetPath), mode.Directory); err != nil {
				return repoRelPath, fmt.Errorf("create parent directory for %s: %w", header.Name, err)
			}

			file, err := os.OpenFile(targetPath, os.O_CREATE|os.O_WRONLY|os.O_TRUNC, os.FileMode(header.Mode))
			if err != nil {
				return repoRelPath, fmt.Errorf("create file %s: %w", header.Name, err)
			}

			if _, err := io.Copy(file, tarReader); err != nil {
				return repoRelPath, fmt.Errorf("write file %s: %w", header.Name, errors.Join(err, file.Close()))
			}

			if err := file.Close(); err != nil {
				return repoRelPath, fmt.Errorf("close file %s: %w", header.Name, err)
			}
		default:
			return repoRelPath, fmt.Errorf("unsupported file type %d for %s", header.Typeflag, header.Name)
		}
	}

	return repoRelPath, nil
}
