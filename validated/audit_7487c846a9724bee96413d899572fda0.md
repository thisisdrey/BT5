## Title
StackerDB chunk signatures don't bind to a specific StackerDB contract, enabling cross-contract chunk replay by any relaying peer - (File: libstackerdb/src/libstackerdb.rs, stackslib/src/net/stackerdb/mod.rs)

### Summary
`SlotMetadata::auth_digest()` computes the signed digest for a StackerDB chunk from only `slot_id`, `slot_version`, and `data_hash` [1](#0-0) . The `QualifiedContractIdentifier` (which StackerDB instance the chunk belongs to) is never part of the signed payload. Authentication of "which contract this chunk is for" is enforced only by the caller supplying the correct `smart_contract_id` when looking up the expected signer address, not by anything inside the signature itself. This is the same defect class as the CryptPad report: the "gate" (signature verification) only covers a subset of the fields that determine authorization scope (here, contract identity is left out), so a value that is authentic in one context can be replayed as authentic in a different context that the signer never approved.

### Finding Description
`PeerNetwork::validate_received_chunk` — used both for downloaded chunks (`StackerDBSync::validate_downloaded_chunk`) and for unsolicited pushes (`PeerNetwork::handle_unsolicited_StackerDBPushChunk`) — validates a chunk as follows [2](#0-1) :
1. Size check against `config.chunk_size`.
2. Look up `expected_version` for `data.slot_id` from the caller-supplied `expected_versions` array (itself derived from the target `smart_contract_id`'s local inventory).
3. Look up the slot's signer address via `self.stackerdbs.get_slot_signer(smart_contract_id, data.slot_id)`.
4. Verify `data.get_slot_metadata().verify(&addr)`.

The `verify()`/`sign()` pair in `SlotMetadata` only ever hash `(slot_id, slot_version, data_hash)` [3](#0-2) . Nothing about the target `smart_contract_id` is part of what the signer actually signed. The contract-scoping only happens through *which lookup* the verifier performs (`get_slot_signer(smart_contract_id, slot_id)`), not through anything cryptographically bound to the message.

Concretely, in `handle_unsolicited_StackerDBPushChunk`, the attacker (any unprivileged relaying peer) fully controls the `contract_id` field of `StackerDBPushChunkData` [4](#0-3) . If a signer address `S` legitimately signed a chunk `(slot_id=X, slot_version=V, data=D)` for StackerDB contract `A` (e.g., one reward cycle's signer-set contract), and that same address `S` also happens to occupy `slot_id=X` in a different, locally-replicated StackerDB contract `B` (e.g., an adjacent reward cycle's signer-set contract, which commonly reuses overlapping signer sets/slot ordering), then:
- The signature `sig` recovers to `S` regardless of which contract is asserted.
- `get_slot_signer(B, X)` also returns `S`.
- `slot_metadata.verify(&S)` succeeds, because the signed digest never mentioned contract `A` or `B`.

The chunk is thus accepted as legitimate data for contract `B`'s slot `X`, even though `S` never signed anything for `B`. This lets an attacker replay stale/foreign-context data as if it were canonical for a different StackerDB instance, propagating forged (mis-attributed) data through the p2p StackerDB gossip path with no privileged access required — only observation of a previously broadcast chunk and knowledge that the signer's slot indices coincide across the two DB instances.

### Impact Explanation
This breaks the intended equality "signed-for-contract-B == stored-for-contract-B": data that was only ever authenticated for one StackerDB context can be stored and re-broadcast (`process_stacker_db_chunks`/`broadcast_message`) as valid current data for a different StackerDB context [5](#0-4) . Given the scan's impact tiers, this maps to network-wide propagation of forged (mis-scoped) data via StackerDB gossip and, in signer-set StackerDB contracts, non-canonical/cross-cycle data being served/replicated as canonical for the wrong reward cycle.

### Likelihood Explanation
No privileged role or secret key is required from the attacker: any peer that can relay `StackerDBPushChunk` messages can attempt this. The only precondition is that the same signer address occupies the same `slot_id` across two StackerDB contracts the victim node replicates — a realistic scenario for reward-cycle based signer-set StackerDBs where signer sets and their slot ordering commonly overlap between adjacent cycles or between distinct signer-set contracts. This is a data-integrity/design gap rather than a probabilistic collision, so likelihood is tied to signer-set overlap, which is common in the Stacks signer-set churn model.

### Recommendation
Include the target `QualifiedContractIdentifier` (or a chain-agnostic identifier bound to it) inside `SlotMetadata::auth_digest()` so that a chunk signature is only valid for the specific StackerDB contract it was created for. This requires a coordinated update to `libstackerdb::SlotMetadata::sign`/`verify` and all call sites that construct/verify `StackerDBChunkData`/`SlotMetadata`, since the wire format signing changes.

### Proof of Concept
1. Register signer address `S` for `slot_id = X` in StackerDB contract `A` (e.g., `signers-0-3`) and also for `slot_id = X` in StackerDB contract `B` (e.g., `signers-1-3`), both replicated by the victim node.
2. Have `S` sign a legitimate chunk for contract `A`: `StackerDBChunkData::new(X, V, D)`, `chunk.sign(&S_privkey)`.
3. As an unprivileged relaying peer, send a `StackerDBPushChunk` p2p message with `contract_id = B` but reusing the exact same `chunk_data` (same `slot_id`, `slot_version`, `sig`, `data`) signed in step 2.
4. Observe that `PeerNetwork::validate_received_chunk` (called from `handle_unsolicited_StackerDBPushChunk`) accepts the chunk for contract `B`, because `get_slot_signer(B, X)` resolves to `S` and `slot_metadata.verify(&S)` succeeds — despite `S` never having signed anything for contract `B` [6](#0-5) .

    /// Get the digest to sign that authenticates this chunk data and metadata
    fn auth_digest(&self) -> Sha512Trunc256Sum {
        let mut hasher = Sha512_256::new();
        hasher.update(self.slot_id.to_be_bytes());
        hasher.update(self.slot_version.to_be_bytes());
        hasher.update(self.data_hash.0);
        Sha512Trunc256Sum::from_hasher(hasher)
    }

    /// Sign this slot metadata, committing to slot_id, slot_version, and
    /// data_hash.  Sets self.signature to the signature.
    /// Fails if the underlying crypto library fails
    pub fn sign(&mut self, privkey: &StacksPrivateKey) -> Result<(), Error> {
        let auth_digest = self.auth_digest();
        let sig = privkey
            .sign(&auth_digest.0)
            .map_err(|se| Error::SigningError(se.to_string()))?;

        self.signature = sig;
        Ok(())
    }

    /// Verify that a given principal signed this chunk metadata.
    /// Note that the address version is ignored.
    pub fn verify(&self, principal: &StacksAddress) -> Result<bool, Error> {
        let sigh = self.auth_digest();
        let pubk = StacksPublicKey::recover_to_pubkey_without_validating_low_s(
            sigh.as_bytes(),
            &self.signature,
        )
        .map_err(|ve| Error::VerifyingError(ve.to_string()))?;

        let pubkh = Hash160::from_node_public_key(&pubk);
        Ok(pubkh == *principal.bytes())
    }

    pub fn validate_received_chunk(
        &self,
        smart_contract_id: &QualifiedContractIdentifier,
        config: &StackerDBConfig,
        data: &StackerDBChunkData,
        expected_versions: &[u32],
    ) -> Result<bool, net_error> {
        // validate -- must not exceed this replica's configured chunk size.
        if (data.data.len() as u64) > config.chunk_size {
            info!(
                "Received StackerDBChunk for {} ID {}, which is oversized: {} bytes (max {} bytes)",
                smart_contract_id,
                data.slot_id,
                data.data.len(),
                config.chunk_size
            );
            return Ok(false);
        }

        // validate -- must be a valid chunk
        let Some(expected_version) = expected_versions.get(data.slot_id as usize) else {
            info!(
                "Received StackerDBChunk for {} ID {}, which is too big ({})",
                smart_contract_id,
                data.slot_id,
                expected_versions.len()
            );
            return Ok(false);
        };

        // validate -- must be signed by the expected author
        let addr = match self
            .stackerdbs
            .get_slot_signer(smart_contract_id, data.slot_id)?
        {
            Some(addr) => addr,
            None => {
                return Ok(false);
            }
        };

        let slot_metadata = data.get_slot_metadata();
        if !slot_metadata.verify(&addr)? {
            info!(
                "StackerDBChunk for {} ID {} is not signed by {}",
                smart_contract_id, data.slot_id, &addr
            );
            return Ok(false);
        }
