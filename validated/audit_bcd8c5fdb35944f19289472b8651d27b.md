### Title
Alternates-file parser ignores Git's C-quoted-string escaping, enabling a storage-boundary bypass on repositories created from snapshots - (File: internal/git/dirs.go)

### Summary
Gitaly's alternates-file readers (`altObjectDirs` in `internal/git/dirs.go` and `ReadAlternatesFile` in `internal/git/stats/repository_info.go`) parse `objects/info/alternates` as plain newline-delimited strings and explicitly do not implement the C-style quoting that real Git supports for this file, exactly mirroring the reported bug class where a relayer assumed one implementation's interface/format applied identically to a different, incompatible one.

### Finding Description
Git's own alternates-file parser (`link_alt_odb_entries()` in Git core) allows an entry to begin with a double quote, in which case the remainder of the line is unquoted using C-style unquoting (interpreting backslash/octal escape sequences) before being used as the actual path. Gitaly's implementation is aware of this divergence and deliberately does not replicate it:

```go
// ObjectDirectories looks for Git object directories, including
// alternates specified in objects/info/alternates.
//
// CAVEAT Git supports quoted strings in here, but we do not. We should
// never need those on a Gitaly server.
``` [3](#0-2) 

The storage-boundary check operates on the raw, un-unquoted string:
```go
if !filepath.IsAbs(newDir) {
    newDir = filepath.Join(objDir, newDir)
}
if !strings.HasPrefix(newDir, storagePrefix) {
    return nil, alternateOutsideStorageError(newDir)
}
``` [4](#0-3) 

The equivalent reader used by `AlternatesInfoForRepository`/object-pool linking logic has the same limitation, only stripping blank lines and `#`-comments, with no unquoting: [5](#0-4) 

Because an attacker who controls `objects/info/alternates` content can supply a line that, when interpreted literally by Gitaly's Go parser, looks like it stays inside the storage root (so `alternateOutsideStorageError` is not raised and `linkedToRepository`/`AlternatesInfoForRepository` treat it as valid), but which Git's own C-quoting-aware reader will decode into an entirely different filesystem path once `git` is later invoked against that repository (e.g. any RPC executing `git cat-file`, `git fsck`, `git repack`, etc. via `internal/git/gitcmd`). This is a semantic gap identical in nature to the CamelotRelayer bug: Gitaly assumes a "compatible enough" parser for a format actually implemented differently by the real backend it wraps (Git), and the validation logic is bypassed because it doesn't operate on the same decoded value the real engine will use.

Reachability: content of `objects/info/alternates` is normally written only by Gitaly itself during `objectpool.Link` [6](#0-5) , but `CreateRepositoryFromSnapshot` extracts an arbitrary, fully client/URL-supplied tar archive on top of a freshly initialized bare repository with the code comment noting "The received archive is trusted *a lot*" [7](#0-6) , and `ReplicateRepository`'s snapshot extraction path writes tar contents from a peer verbatim to disk, only checking for `..`/symlink path traversal, not file content [8](#0-7) . Both are unprivileged/ordinary-operator-reachable code paths (repo creation / replication), letting an attacker place a crafted `objects/info/alternates` entry into a repository that Gitaly will subsequently treat as validated.

### Impact Explanation
If Git's decoded alternates path differs from what Gitaly's naive parser validated, this is a cross-repository/storage escape: a repository could be linked to (or read objects from) an alternate object directory outside the intended storage root or belonging to another tenant's repository, once real `git` commands are executed against it — matching the "concrete storage escape" / "cross-repository object access" criteria. At minimum, it causes silent inconsistency between what Gitaly believes the alternates configuration is and what Git will actually resolve, which can also manifest as unexpected fsck/repack failures (DoS of the handler) when Git parses an entry Gitaly's tooling mis-classified.

### Likelihood Explanation
Requires that (a) Git's alternates format indeed treats a leading `"` specially via C-style unquoting (behavior inherited from upstream Git, not modified by Gitaly), and (b) an attacker can get attacker-controlled bytes into `objects/info/alternates` of a repository Gitaly will operate on. Condition (b) is satisfied by the `CreateRepositoryFromSnapshot` RPC, which the code itself flags as extracting fully untrusted content, making the path realistic for any deployment exposing that RPC (or any import/fork flow built on top of tar-snapshot-based repository creation/replication).

### Recommendation
Do not assume Gitaly's simplified line-based parser is equivalent to Git's own alternates parser. Either:
1. Reject/strip any alternates entry that begins with `"` (a quote character) before validating and recording it, since Gitaly does not support quoting — failing closed rather than silently mis-validating, or
2. Implement the same C-style unquoting Git performs (`unquote_c_style`) before applying the storage-prefix containment check, so that the string being validated is exactly the string Git will actually use.
Additionally, treat repository content extracted via `CreateRepositoryFromSnapshot`/`ReplicateRepository` snapshot extraction as untrusted with respect to `objects/info/alternates`: re-validate (or strip and regenerate) this file server-side after extraction rather than trusting whatever bytes were present in the uploaded archive.

### Proof of Concept
1. An attacker controls (or can redirect, via `CreateRepositoryFromSnapshotRequest.HttpUrl`) a tar archive that Gitaly extracts verbatim into a new bare repository via `s.untar` [9](#0-8) .
2. The archive includes `objects/info/alternates` containing a line beginning with `"` followed by a C-style-escaped sequence that decodes (per Git's parser) to a path such as `../../../other-repo/objects`, while the literal (unescaped) bytes Gitaly parses via `altObjectDirs`/`ReadAlternatesFile` do not contain the literal substring `..` and thus pass the naive `strings.HasPrefix(newDir, storagePrefix)` check [10](#0-9) .
3. Any subsequent Gitaly-invoked `git` command against this repository (via `internal/git/gitcmd`) resolves the alternate using Git's real, quote-aware parser, exposing objects from `other-repo` (or another storage root) to the attacker's repository, while Gitaly's own bookkeeping (`AlternatesInfoForRepository`, `linkedToRepository`) still believes the alternate is a validated, in-bounds path.

*(Note: I was not able to directly execute or byte-for-byte confirm Git's C-quoting parser behavior for `objects/info/alternates` inside this sandbox — this analysis is based on the explicit CAVEAT comment in Gitaly's own source acknowledging the divergence from upstream Git's alternates parsing, plus the confirmed reachability via `CreateRepositoryFromSnapshot`/`ReplicateRepository`. A background agent with git binary access should verify the exact quoting/escape semantics of Git's `link_alt_odb_entries()` against the bundled Git version to fully confirm exploitability before treating this as certain.)*

// extractTarToDirectory extracts a tar archive to the specified directory using Go's tar package
func (s *server) extractTarToDirectory(ctx context.Context, reader io.Reader, targetDir string) error {
	targetDir = filepath.Clean(targetDir)
	tarReader := tar.NewReader(reader)

	for {
		select {
		case <-ctx.Done():
			return ctx.Err()
		default:
		}

		header, err := tarReader.Next()
		if err == io.EOF {
			break // End of archive
		}
		if err != nil {
			return fmt.Errorf("reading tar header: %w", err)
		}

		targetPath := filepath.Join(targetDir, header.Name)

		if !strings.HasPrefix(targetPath, targetDir+string(os.PathSeparator)) &&
			targetPath != targetDir {
			return fmt.Errorf("invalid file path in tar: %s", header.Name)
		}

		switch header.Typeflag {
		case tar.TypeDir:
			if err := os.MkdirAll(targetPath, os.FileMode(header.Mode)); err != nil {
				return fmt.Errorf("creating directory %s: %w", targetPath, err)
			}

		case tar.TypeReg:
			if err := s.extractFile(ctx, tarReader, targetPath, header); err != nil {
				return fmt.Errorf("extracting file %s: %w", targetPath, err)
			}

		case tar.TypeSymlink:
			if filepath.IsAbs(header.Linkname) {
				return fmt.Errorf("absolute symlink not allowed: %s -> %s", header.Name, header.Linkname)
			}

			// Resolve the relative symlink target from the symlink's parent directory
			// and verify it stays within the extraction boundary, consistent with the
			// hard link validation below.
			resolvedTarget := filepath.Join(filepath.Dir(targetPath), header.Linkname)
			if !strings.HasPrefix(resolvedTarget, targetDir+string(os.PathSeparator)) &&
				resolvedTarget != targetDir {
				return fmt.Errorf("symlink target escapes extraction directory: %s -> %s", header.Name, header.Linkname)
			}

			// Remove existing file/symlink if it exists
			if err := os.Remove(targetPath); err != nil && !os.IsNotExist(err) {
				return fmt.Errorf("removing existing file for symlink %s: %w", targetPath, err)
			}

			if err := os.Symlink(header.Linkname, targetPath); err != nil {
				return fmt.Errorf("creating symlink %s -> %s: %w", targetPath, header.Linkname, err)
			}

		case tar.TypeLink:
			linkTarget := filepath.Join(targetDir, header.Linkname)

			if !strings.HasPrefix(linkTarget, targetDir+string(os.PathSeparator)) &&
				linkTarget != targetDir {
				return fmt.Errorf("invalid hard link target: %s", header.Linkname)
			}

			// Remove existing file if it exists
			if err := os.Remove(targetPath); err != nil && !os.IsNotExist(err) {
				return fmt.Errorf("removing existing file for hard link %s: %w", targetPath, err)
			}

			if err := os.Link(linkTarget, targetPath); err != nil {
				return fmt.Errorf("creating hard link %s -> %s: %w", targetPath, linkTarget, err)
			}

		default:
			// Skip unsupported file types (devices, FIFOs, etc.)
			s.logger.WithField("file", header.Name).WithField("type", header.Typeflag).
				WarnContext(ctx, "skipping unsupported file type in tar archive")
		}

		if header.Typeflag == tar.TypeReg || header.Typeflag == tar.TypeDir {
			if err := os.Chmod(targetPath, os.FileMode(header.Mode)); err != nil {
				return fmt.Errorf("setting permissions for %s: %w", targetPath, err)
			}
		}
	}

	return nil
}
