### Title
Password Leak in `securityPreservingHTTPClient` Redirect-Error Message via `%s` on `*url.URL` - ([File: src/cmd/go/internal/web/http.go])

### Summary
`cmd/go`'s module-download HTTP client is careful to redact credentials with `URL.Redacted()` everywhere it logs or reports URLs, but `securityPreservingHTTPClient`'s `CheckRedirect` callback formats `lastHop` and `req.URL` with plain `%s` instead of `.Redacted()`, so any embedded userinfo password in the URL (e.g. `https://user:pass@host/mod`) is emitted verbatim into the returned error string. This mirrors the Glances bug class: a security helper (`Redacted()`/`as_dict_secure()`) exists and is used almost everywhere, but one specific formatting call bypasses it and leaks the credential value.

### Finding Description
`securityPreservingHTTPClient` (`src/cmd/go/internal/web/http.go:52-65`) wraps `http.Client.CheckRedirect` to detect an HTTPS→HTTP downgrade during redirect-following when fetching module/VCS metadata:
```go
c.CheckRedirect = func(req *http.Request, via []*http.Request) error {
    if len(via) > 0 && via[0].URL.Scheme == "https" && req.URL.Scheme != "https" {
        lastHop := via[len(via)-1].URL
        return fmt.Errorf("redirected from secure URL %s to insecure URL %s", lastHop, req.URL)
    }
    return checkRedirect(req, via)
}
```
`lastHop` and `req.URL` are `*url.URL` values. `fmt.Errorf`'s `%s` verb calls `(*url.URL).String()` (`src/net/url/url.go:808`), which writes the full userinfo including the plaintext password, unlike `(*url.URL).Redacted()` (`src/net/url/url.go:886-896`) which explicitly masks the password with `xxxxx`. Every other place in the same file (`get`, `getFile`) consistently calls `url.Redacted()` before formatting a URL into a message (e.g. lines 119, 206, 221, 223, 231, 233, 241, 243, 251, 262, 266, 298, 308, 321). This one call site is the exception, and the resulting error propagates up through `get()`'s error path (`src/cmd/go/internal/web/http.go:173-179, 205-213`), where under `-x`/`GOFLAGS=-x` it is printed with `%v` directly to stderr (`fmt.Fprintf(os.Stderr, "# get %s: %v\n", secure.Redacted(), err)`), i.e. the *outer* URL is redacted but the *embedded, already-rendered* error text is not, so the password still appears in the build log.

This is directly analogous to the Glances finding: a "secure" sanitizer function/pattern is applied broadly, but one specific value (here, the URL rendered inside an `fmt.Errorf` at a different code path) escapes the same defense because the developer used the raw/insecure formatter (`%s`→`String()`) instead of the safe one (`Redacted()`).

### Impact Explanation
Module fetch/proxy URLs and VCS metadata URLs configured via `GOPROXY`, `GONOSUMCHECK`, or direct VCS `go-import` meta tags can legitimately contain embedded basic-auth credentials (`https://user:pass@...`). If such a URL is redirected from HTTPS to plain HTTP, the resulting error string — printed to build logs/stderr under `go get -x`, or potentially captured by CI systems/log aggregators — contains the plaintext password. This is a credential-disclosure issue (CWE-200-class), matching the CVSS profile of the analog report (confidentiality-only, no integrity/availability impact). Given `cmd/go` is part of the Go toolchain itself and the exposure occurs via a normal `go get`/module-download workflow, this would fall under Go's **PUBLIC** track for a low-severity information disclosure if confirmed as unfixed upstream — but I was unable to verify against the current upstream `go/src/cmd/go/internal/web/http.go` whether this exact line has already been patched, since only this repository's snapshot was inspected.

### Likelihood Explanation
Requires: (1) a module/VCS URL with embedded credentials configured by a developer (a supported, documented use case for private module proxies), and (2) that URL's server issuing an HTTPS→HTTP redirect during a `go get`/`go mod download` operation, and (3) the build being run with `-x` (verbose command tracing) or the error being logged/displayed elsewhere. This is a real but narrow victim workflow — not attacker-controlled in the sense of a remote unauthenticated request, but it is an ordinary-user data-handling path (private proxy credentials in a URL) that silently bypasses the tool's own redaction convention.

### Recommendation
Change the `CheckRedirect` closure to use `.Redacted()` for both URLs:
```go
return fmt.Errorf("redirected from secure URL %s to insecure URL %s", lastHop.Redacted(), req.URL.Redacted())
```
consistent with every other formatting call in the file.

	secureURL, _ := url.Parse("https://user:supersecret@example.com/mod")

		t.Fatal("expected redirect-downgrade error")

		t.Fatalf("expected leak reproduced (pre-fix), got: %q", msg)
	}

	// if contains(msg, "supersecret") {
	//     t.Fatalf("password leaked in redirect error: %q", msg)

func contains(s, sub string) bool {
	return len(s) >= len(sub) && (func() bool {
		for i := 0; i+len(sub) <= len(s); i++ {
			if s[i:i+len(sub)] == sub {
				return true
			}
		}
		return false
	})()
}

// securityPreservingHTTPClient returns a client that is like the original
// but rejects redirects to plain-HTTP URLs if the original URL was secure.
func securityPreservingHTTPClient(original *http.Client) *http.Client {
	c := new(http.Client)
	*c = *original
	c.CheckRedirect = func(req *http.Request, via []*http.Request) error {
		if len(via) > 0 && via[0].URL.Scheme == "https" && req.URL.Scheme != "https" {
			lastHop := via[len(via)-1].URL
			return fmt.Errorf("redirected from secure URL %s to insecure URL %s", lastHop, req.URL)
		}
		return checkRedirect(req, via)
	}
	return c
}

// Redacted is like [URL.String] but replaces any password with "xxxxx".
// Only the password in u.User is redacted.
func (u *URL) Redacted() string {
	if u == nil {
		return ""
	}

	ru := *u
	if _, has := ru.User.Password(); has {
		ru.User = UserPassword(ru.User.Username(), "xxxxx")
	}
	return ru.String()
}
