### Title
`FetchIntoObjectPool` performs no verification that `origin` is an actual member of the target object pool, allowing cross-repository object injection - ([File: internal/gitaly/service/objectpool/fetch_into_object_pool.go])

### Summary
`FetchIntoObjectPool` fetches all references/objects from an arbitrary caller-supplied `origin` repository into an arbitrary caller-supplied object pool. The only relationship check performed between `origin` and `object_pool` is that they share the same storage name; there is no check confirming that `origin` is actually linked (an alternates member) to that specific pool before objects are pulled into it.

### Finding Description
The RPC handler validates only structural fields, not the ownership/membership relationship between the two repositories that are about to be merged at the object level: [1](#0-0) 

```
func validateFetchIntoObjectPoolRequest(req *gitalypb.FetchIntoObjectPoolRequest) error {
    ...
    if originRepository.GetStorageName() != poolRepository.GetStorageName() {
        return errors.New("origin has different storage than object pool")
    }
    return nil
}
```

The handler then builds the pool from the target-repository field and unconditionally fetches from the caller-supplied `origin`: [2](#0-1) 

`FetchFromOrigin` itself only checks that the object pool exists (`o.Exists(ctx)`), not that `origin` is a member of, or was ever linked to, this pool: [3](#0-2) 

Compare this with `Link`/`linkedToRepository`, which do enforce an explicit alternates-membership check (`altInfo.ObjectDirectories[0] == expectedRelPath`) before treating a repository as a pool member: [4](#0-3) 

No equivalent membership assertion exists on the `FetchIntoObjectPool` path. This mirrors the report's root cause pattern: an operation ("burn NFT" / "fetch into pool") is executed against a target ("depositer contract" / "object pool") without validating that the referenced resource ("NFT" / "origin repository") actually belongs to that target's trust boundary. The `additional_repository` annotation on `origin` in the proto only enables Praefect's request-routing/rewriting logic; it performs no per-repository authorization or pool-membership assertion: [5](#0-4) 

### Impact Explanation
Because `origin` can be any repository on the same storage/virtual storage, and the RPC unconditionally fetches its objects into the pool, an actor able to invoke this RPC for a pool they administer (e.g., their own fork's pool) can specify an unrelated repository as `origin`. This pulls that repository's objects and refs into the caller's pool. Once ingested, those objects become permanently retained (pools never prune, and dangling objects are rescued via `rescueDanglingObjects`) and become reachable as alternates to every other member of that pool, resulting in cross-repository object disclosure/pollution outside of the intended fork/pool relationship — the same class of "operate on a resource the caller does not actually own" defect flagged in the reference finding.

### Likelihood Explanation
Any client capable of invoking `ObjectPoolService.FetchIntoObjectPool` (or any coordinator layer that forwards this RPC on behalf of a fork/pool owner) can trigger this path simply by crafting the `origin` field to name a repository outside of the pool's actual membership set — no special privilege beyond ordinary access to invoke pool RPCs for one's own object pool is required, and no additional Gitaly-side check blocks it.

### Recommendation
Before performing the fetch in `FetchFromOrigin`/`FetchIntoObjectPool`, verify that `origin` is (or is permitted to become) an actual member of the target object pool — e.g., by checking `origin`'s alternates file resolves to this specific pool (reusing the same `linkedToRepository`-style check used in `Link`), or by requiring that `LinkRepositoryToObjectPool` has already established the relationship prior to allowing a fetch from that origin.

### Proof of Concept
1. Actor A creates object pool `P` from repository `R1` (`CreateObjectPool`) and links `R1` to `P`.
2. Actor A knows (or can enumerate) the relative path of an unrelated repository `R2` on the same storage (not linked to `P`).
3. Actor A calls `FetchIntoObjectPool` with `object_pool = P`, `origin = R2`.
4. `validateFetchIntoObjectPoolRequest` only checks the storage names match, and `FetchFromOrigin` only checks that `P` exists — no check that `R2` is linked to `P`.
5. All refs/objects from `R2` are fetched into `P`'s object database and retained (dangling refs rescued), making `R2`'s objects permanently reachable through `P`'s alternates for every current and future member of `P`.

func validateFetchIntoObjectPoolRequest(req *gitalypb.FetchIntoObjectPoolRequest) error {
	if req.GetOrigin() == nil {
		return errors.New("origin is empty")
	}

	if req.GetObjectPool() == nil {
		return errors.New("object pool is empty")
	}

	originRepository, poolRepository := req.GetOrigin(), req.GetObjectPool().GetRepository()

	if originRepository.GetStorageName() != poolRepository.GetStorageName() {
		return errors.New("origin has different storage than object pool")
	}

	return nil
}

// linkedToRepository tests if a repository is linked to an object pool
func linkedToRepository(ctx context.Context, pool, repo *localrepo.Repo) (bool, error) {
	poolPath, err := pool.Path(ctx)
	if err != nil {
		return false, fmt.Errorf("getting object pool path: %w", err)
	}

	repoPath, err := repo.Path(ctx)
	if err != nil {
		return false, fmt.Errorf("getting repo path: %w", err)
	}

	altInfo, err := stats.AlternatesInfoForRepository(repoPath)
	if err != nil {
		return false, fmt.Errorf("getting alternates info: %w", err)
	}

	if !altInfo.Exists || len(altInfo.ObjectDirectories) == 0 {
		return false, nil
	}

	relPath := altInfo.ObjectDirectories[0]
	expectedRelPath, err := getRelativeObjectPath(ctx, pool, repo)
	if err != nil {
		return false, err
	}

	if relPath == expectedRelPath {
		return true, nil
	}

	if filepath.Clean(relPath) != filepath.Join(poolPath, "objects") {
		return false, fmt.Errorf("unexpected alternates content: %q", relPath)
	}

	return false, nil
}
