### Title
Heap buffer over-read in ZIP central-directory extra-field parsing — ([File: third_party/ijar/zip.cc])

### Summary
`InputZipFile::ProcessCentralDirEntry` in `third_party/ijar/zip.cc` parses a ZIP central-directory header (CDH) taken from an attacker-controlled input JAR/ZIP (ijar processes any input jar, including third-party jars pulled in as build dependencies) without any bounds checking of the declared `file_name_length`, `extra_field_length`, or `file_comment_length` against the actual remaining bytes of the memory-mapped file.

### Finding Description
`ProcessCentralDirEntry` reads the fixed 46-byte CDH fields, then unconditionally advances the cursor `p` by attacker-supplied 16-bit lengths: [1](#0-0) 

Unlike `ProcessLocalFileEntry`, which calls `EnsureRemaining()` before consuming `file_name_length_` and `extra_field_length_`: [2](#0-1) 

`ProcessCentralDirEntry` has **no** `EnsureRemaining` calls at all — it relies solely on the comment's assumption that "the central directory is always followed by another data structure that has a signature," which is not enforced by any code: [3](#0-2) 

Worse, the extra-field parsing loop trusts the attacker-controlled `data_size` sub-field of each extra-field record to advance `extra_p`, comparing it against `p` (which was itself advanced by the untrusted `extra_field_length`) for loop termination: [4](#0-3) 

If `extra_p + data_size` does not land exactly on `p` (e.g., a crafted `data_size` that overshoots), `extra_p != p` remains true and the loop keeps calling `get_u2le(extra_p)`/`get_u8le(extra)` past the end of the declared extra-field region — and, if the CDH sits near the end of the mmap'd file, past the end of the mapped file entirely. Because the file is opened via `mmap` (`MappedInputFile`), reading past the mapping is a heap/mapping buffer over-read that can crash the process (SIGSEGV) or return uninitialized/adjacent memory contents (`*uncompressed_size`, `*compressed_size`, `*offset` are populated from this data and subsequently used to locate/read local file data, potentially disclosing adjacent memory in `filename`/output artifacts).

This is directly analogous to the reported dcraw `parse_tiff_ifd` bug class: parsing attacker-controlled structured metadata (IFD entries / here, ZIP CDH + extra fields) advances a read cursor using untrusted length fields without validating against the actual buffer bounds.

### Impact Explanation
An attacker who can supply a JAR/ZIP dependency that Bazel processes with `ijar` (e.g., via `http_archive`/`http_jar`, `maven_jar`, or any downloaded `.jar` used with `java_library`'s interface-jar generation, which invokes this exact `ijar` C++ code) can craft a CDH whose `extra_field_length`/`file_comment_length` fields cause the parser to read past the memory-mapped file. This can crash the Bazel build (denial of service local to the build) or leak adjacent process memory contents into observable artifacts (the generated interface jar / stderr diagnostics), which is an information-disclosure primitive matching CVE-2018-19566's class (C:H impact via over-read).

### Likelihood Explanation
Likelihood is high for triggering a crash: no checksum/integrity mechanism validates the *internal structure* of a downloaded ZIP/JAR once its overall byte content matches the pinned `sha256`/`integrity` (that only ensures the file bytes match what was recorded, not that the ZIP structure is well-formed) — so a first-time or unpinned dependency, or any jar accepted by `ijar` without a prior integrity pin, is fully attacker-controlled at the byte level. `EnsureRemaining` bounds checks exist elsewhere in this same file (`ProcessLocalFileEntry`), showing the authors were aware of the need for such checks but omitted them in `ProcessCentralDirEntry`.

### Recommendation
Add `EnsureRemaining`-style bounds checks in `ProcessCentralDirEntry` before consuming `file_name_length`, `extra_field_length`, and `file_comment_length`, and validate that each extra-field record's `header_id`/`data_size` pair stays within `[extra_p, p)` before dereferencing, aborting with an error instead of continuing to read past validated bounds.

### Proof of Concept
Not independently executed (no filesystem/terminal access in this session), but a reproducible test can be added following the pattern of `third_party/ijar/test/zip_test.sh` / the existing `ZipHeadersTest`-style unit tests: construct a minimal ZIP whose single CDH declares `extra_field_length = 0xFFFF` while only a few real bytes of file remain after the CDH's fixed fields, then invoke `InputZipFile::ProcessNext()`/`ProcessAll()` on it and observe an out-of-bounds read (ASAN heap-buffer-overflow report) or crash, contrasting with `ProcessLocalFileEntry`, which correctly rejects the analogous case via `EnsureRemaining`.

// Returns true if the central directory contains another file and false if not.
// Of course, in the latter case, the size output variables are not changed.
// Note that the central directory is always followed by another data structure
// that has a signature, so parsing it this way is safe.
bool InputZipFile::ProcessCentralDirEntry(const u1 *&p, u8 *compressed_size,
                                          u8 *uncompressed_size, char *filename,
                                          size_t filename_size, u4 *attr,
                                          u8 *offset) {
  u4 signature = get_u4le(p);

  if (signature != CENTRAL_FILE_HEADER_SIGNATURE) {
    if (signature != DIGITAL_SIGNATURE && signature != EOCD_SIGNATURE &&
        signature != ZIP64_EOCD_SIGNATURE) {
      error("invalid central file header signature: 0x%x\n", signature);
    }
    return false;
  }

  p += 16;  // skip to 'compressed size' field
  *compressed_size = get_u4le(p);
  *uncompressed_size = get_u4le(p);
  u2 file_name_length = get_u2le(p);
  u2 extra_field_length = get_u2le(p);
  u2 file_comment_length = get_u2le(p);
  p += 4;  // skip to external file attributes field
  *attr = get_u4le(p);
  *offset = get_u4le(p);
  {
    size_t len = (file_name_length < filename_size)
      ? file_name_length
      : (filename_size - 1);
    memcpy(reinterpret_cast<void*>(filename), p, len);
    filename[len] = 0;
  }
  p += file_name_length;
  const u1 *extra_p = p;
  p += extra_field_length;
  while (extra_p != p) {
    const u2 header_id = get_u2le(extra_p);
    const u2 data_size = get_u2le(extra_p);
    const u1 *extra = extra_p;
    extra_p += data_size;
    if (header_id == ZIP64_EXTRA_FIELD_TAG) {
      if (*uncompressed_size == U4_MAX) {
        *uncompressed_size = get_u8le(extra);
      }
      if (*compressed_size == U4_MAX) {
        *compressed_size = get_u8le(extra);
      }
      if (*offset == U4_MAX) {
        *offset = get_u8le(extra);
      }
    }
  }
