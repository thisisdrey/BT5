### Title
Committee toggling `ALLOW_MARKET_TRANSACTION` off permanently freezes tokens already locked in resting TRC10 market orders - (File: `actuator/src/main/java/org/tron/core/actuator/MarketCancelOrderActuator.java`)

### Summary
`MarketSellAssetActuator` lets any account escrow TRX/TRC10 tokens into a resting order in the on-chain order book when the order does not fully match immediately [1](#0-0) . The only way for the order owner to reclaim that escrowed balance/token before a match is `MarketCancelOrderActuator`, whose `validate()` requires `dynamicStore.supportAllowMarketTransaction()` to be `true` [2](#0-1) . This is the exact same committee-controlled flag (`ALLOW_MARKET_TRANSACTION`) that gates order creation in `MarketSellAssetActuator.validate()` [3](#0-2) . If the committee (via a normal, non-malicious proposal) disables `ALLOW_MARKET_TRANSACTION` after users have placed resting orders, `MarketCancelOrderActuator.validate()` unconditionally reverts for every order owner, so users with funds already locked in the order book have no path to withdraw them — mirroring the `AutoCompound`/`Automator` bug where disabling the "vault" flag blocks the only withdrawal path (`withdrawLeftoverBalances`) for users who already deposited.

### Finding Description
Both the deposit path (`MarketSellAssetActuator`) and the sole "get my funds back" path (`MarketCancelOrderActuator`) share one guard check, `dynamicStore.supportAllowMarketTransaction()` [4](#0-3) [5](#0-4) . This flag is set via a governance proposal (`ALLOW_MARKET_TRANSACTION`) processed in `ProposalUtil`/`ProposalService`, and read from `DynamicPropertiesStore` [6](#0-5) . Once the flag transitions from enabled to disabled through normal committee operation, any account holding an active, unmatched order (state `NEW`, checked via `orderCapsule.isActive()` in the cancel path [7](#0-6) ) can no longer submit `MarketCancelOrderContract` because `validate()` throws before ever checking order ownership. There is no alternate mechanism in the actuator set to return escrowed balances for a disabled market — `MarketUtils.returnSellTokenRemain` is only invoked from inside `MarketCancelOrderActuator.execute()` and the auto-match logic in `MarketSellAssetActuator`, both of which require the feature flag to be enabled to even reach the escrow-return code.

### Impact Explanation
Any unprivileged account that placed a resting sell order before the flag was disabled has its TRX or TRC10 token balance permanently (until the committee re-enables the feature, if ever) locked with no way to cancel and recover it. This is a freezing-of-funds condition triggered by a normal, expected administrative action (a committee proposal), not by malicious behavior — directly analogous to the `AutoCompound.setVault(false)` scenario in the referenced report, where disabling a switch that both gates new deposits and gates withdrawal traps already-deposited user funds.

### Likelihood Explanation
`ALLOW_MARKET_TRANSACTION` is a normal proposal parameter changeable by the committee through the standard governance process (as documented in `ProposalUtil`), not an attacker-controlled or malicious-actor path. Any time the committee disables the on-chain TRC10 exchange feature (e.g., to deprecate it, pause it during an incident, or migrate to a new mechanism) while resting orders exist, every affected order owner is immediately and unconditionally blocked from cancelling. This matches the C4 judge's classification of the analogous bug as "a temporary, mitigable DoS caused by normal administrative operations" — Medium severity.

### Recommendation
Decouple order cancellation from the market-transaction-enabled flag: `MarketCancelOrderActuator.validate()` should not require `supportAllowMarketTransaction()` to be true, since cancelling an existing order and returning escrowed funds does not create new market exposure. At minimum, allow cancellation regardless of the flag's current state, mirroring the fix direction taken for `AutoCompound` (making the leftover-balance withdrawal path independent of the vault-active flag).

### Proof of Concept
1. Committee proposal sets `ALLOW_MARKET_TRANSACTION = 1` (enabled).
2. User A submits `MarketSellAssetContract` selling TRX for TRC10 token X with a price that does not immediately match; `MarketSellAssetActuator.execute()` deducts A's TRX balance and stores the resting order via `saveRemainOrder` [8](#0-7) .
3. Committee proposal sets `ALLOW_MARKET_TRANSACTION = 0` (disabled) — a routine governance action.
4. User A submits `MarketCancelOrderContract` for their order id. `MarketCancelOrderActuator.validate()` immediately throws `ContractValidateException("Not support Market Transaction, need to be opened by the committee")` at line 168-171, before ever checking order ownership or existence.
5. User A's escrowed TRX remains locked indefinitely in the order book with no actuator available to release it while the flag stays disabled.
