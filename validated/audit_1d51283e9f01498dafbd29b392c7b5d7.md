### Title
Fee bypass by splitting a Nep245/Imt token_in leg into unit-size `TokenDiff` intents within one signed `MultiPayload` - (File: `contracts/defuse/core/src/intents/token_diff.rs`)

### Summary
`TokenDiff::token_fee` waives protocol fee for `Nep245`/`Imt` tokens whenever the *single intent's* `|delta|` is `<=1`. Because `DefuseIntents::execute_intent` executes a `Vec<Intent>` under one signature by iterating and calling each `TokenDiff::execute_intent` independently, without ever aggregating deltas on the same token across intents before computing the fee, a signer can split a large Nep245/Imt token_in amount into many `-1` legs in a single signed payload and pay zero fee in aggregate, instead of `Pips::fee_ceil(protocol_fee, N)` that a single consolidated leg would owe.

### Finding Description
The broken binding: sum over i of `Pips::fee_ceil(protocol_fee, 1)` (which is `Pips::ZERO` for Nep245/Imt per-leg since `amount<=1`) for i in 1..=N legs should equal `Pips::fee_ceil(protocol_fee, N)` for one consolidated leg — but it does not, because the LHS is always `0` while the RHS is `> 0` for any nonzero `protocol_fee`.

Code path: `execute_signed_intent` extracts a `DefusePayload<DefuseIntents>` from one signed `MultiPayload`, verifies signature/nonce once [3](#0-2) , then calls `intents.execute_intent(...)` on the whole `DefuseIntents`, which iterates its `Vec<Intent>` and independently calls `execute_intent` on every entry, including every `TokenDiff` [4](#0-3) . Each `TokenDiff::execute_intent` computes the fee per-intent from that intent's own delta map only [5](#0-4) , and `token_fee` explicitly zeroes the fee for `Nep171`/`Nep245`/`Imt` when `amount <= 1` [2](#0-1) .

Attacker's payload: one signed `MultiPayload` whose `DefuseIntents.intents` contains N `TokenDiff { diff: {token_id: -1}, .. }` entries for the same Nep245 `token_id` (attacker as signer_id), plus a counterparty `TokenDiff` (can be a colluding second account, or a separate signed payload in the same `execute_intents`/`simulate_intents` batch) supplying the offsetting `+N` deposit for that token so the global `TransferMatcher::finalize` invariant nets to zero for that token [6](#0-5) . Since fee is only ever charged on negative deltas (token_in) [7](#0-6) , the counterparty's positive delta is fee-free regardless, and the attacker's N unit legs are each fee-free too, so the aggregate fee collected is `0` instead of `Pips::fee_ceil(protocol_fee, N)`.

Existing guards do not prevent this: `MultiPayload::verify`, nonce/salt checks, and the `TransferMatcher` invariant only ensure balances net to zero across the batch — they do not police how the same aggregate amount is fee-computed, since fee computation happens per-`TokenDiff`-intent, not per-token aggregated over the whole batch/`Transfers` output.

### Impact Explanation
The `fee_collector` under-collects protocol fee on any Nep245 (multi-token) or Imt asset transfer that a user chooses to structure as many unit-amount `TokenDiff` legs instead of one consolidated leg, fully bypassing the protocol fee regardless of the true aggregate amount moved. This is repeatable by any unprivileged signer, for any Nep245/Imt token, in any batch size, and directly matches the listed Critical category "protocol fees bypassed." It does not move funds without authorization or break netting — it only zeroes the fee revenue that would otherwise accrue to `fee_collector`.

### Likelihood Explanation
No special privileges are needed — this only requires an unprivileged signer able to hold a Nep245/Imt balance and sign a `MultiPayload` with multiple `TokenDiff` intents, plus a counterparty (or self-controlled second account) to balance the netting invariant. The only cost is constructing N intents in one payload and the corresponding NEAR gas/tx size for N legs, which scales with the batch size; for modest N this is trivially feasible and fully repeatable across tokens and accounts.

### Recommendation
Compute `token_fee` based on the aggregated absolute delta per `token_id` across the entire `DefuseIntents` batch (or across the whole `MultiPayload`/execution), not per individual `TokenDiff` intent, before applying the `amount <= 1` fee-waiver logic for `Nep245`/`Imt`. Alternatively, remove/restrict the per-leg fee waiver for `Nep245`/`Imt` fungible-style holdings, or track a running total per token_id across all intents processed by `Engine` and apply the waiver threshold to that running total instead of each intent's isolated delta.

### Proof of Concept
`cargo test` (defuse-core or sandbox integration) plan:
1. Set `protocol_fee = Pips::ONE_PERCENT` (or any nonzero fee) via test `Env::builder().fee(fee)`.
2. Create a Nep245 token_id with sufficient balance for attacker (signer) equal to `10_000`.
3. Construct one signed `MultiPayload` from the attacker containing 10_000 `TokenDiff` intents, each `{ diff: {token_id: -1} }`.
4. Construct a second signed `MultiPayload` from a counterparty containing a single `TokenDiff { diff: {token_id: +10_000} }` to satisfy the `TransferMatcher` invariant.
5. Execute both via `execute_intents` (or `simulate_intents().into_result()` to confirm no invariant violation).
6. Assert: `fee_collector` balance for `token_id` after execution equals `0`.
7. Assert (comparison side): a single consolidated `TokenDiff { diff: {token_id: -10_000} }` executed in an equivalent scenario credits `fee_collector` with `Pips::fee_ceil(protocol_fee, 10_000)` (`> 0`).
8. The two assertions together demonstrate `sum(fee_ceil(protocol_fee, 1) for 10_000 legs) == 0 < Pips::fee_ceil(protocol_fee, 10_000)`, proving the binding is broken.

    fn execute_signed_intent(&mut self, signed: MultiPayload) -> Result<()> {
        // verify signed payload and get public key
        let public_key = signed.verify().ok_or(DefuseError::InvalidSignature)?;

        // calculate intent hash
        let hash = signed.hash();

        // extract NEP-413 payload
        let DefusePayload::<DefuseIntents> {
            signer_id,
            verifying_contract,
            deadline,
            nonce,
            message: intents,
        } = signed.extract_defuse_payload()?;

        // check recipient
        if verifying_contract != *self.state.verifying_contract() {
            return Err(DefuseError::WrongVerifyingContract);
        }

        self.inspector.on_deadline(deadline);

        // make sure message is still valid
        if deadline < Timestamp::now() {
            return Err(DefuseError::DeadlineExpired);
        }

        // make sure the account has this public key
        if !self.state.has_public_key(&signer_id, &public_key) {
            return Err(DefuseError::PublicKeyNotExist(signer_id, public_key));
        }

        // commit nonce
        self.verify_intent_nonce(nonce, deadline)?;
        self.state.commit_nonce(signer_id.clone(), nonce)?;

        intents.execute_intent(&signer_id, self, hash)?;
        self.inspector.on_intent_executed(&signer_id, hash, nonce);

        Ok(())
    }

    // Finalizes all transfers, or returns unmatched deltas.
    // If unmatched deltas overflow, then Err(None) is returned.
    pub fn finalize(self) -> Result<Transfers, InvariantViolated> {
        let mut transfers = Transfers::default();
        let mut deltas = TokenDeltas::default();
        for (token_id, transfer_matcher) in self.0 {
            if let Err(unmatched) = transfer_matcher.finalize_into(&token_id, &mut transfers)
                && (unmatched == 0 || deltas.apply_delta(token_id, unmatched).is_none())
            {
                return Err(InvariantViolated::Overflow);
            }
        }
        if !deltas.is_empty() {
            return Err(InvariantViolated::UnmatchedDeltas {
                unmatched_deltas: deltas,
            });
        }
        Ok(transfers)
    }
