### Title
Protocol fee on NEP-245/IMT `TokenDiff` swaps can be fully bypassed by splitting a transfer into unit-amount deltas - (File: contracts/defuse/core/src/intents/token_diff.rs)

### Summary
`TokenDiff::token_fee()` waives the protocol fee entirely whenever the transferred amount of a `Nep245` or `Imt` token is `<= 1`, an exemption meant to avoid a `fee_ceil` rounding artifact that would otherwise consume 100% of a single-unit transfer. Because the exemption is evaluated per `TokenDiff` delta rather than on the economically intended aggregate amount, an attacker can split an arbitrarily large NEP-245/IMT swap into many unit-sized `TokenDiff` intents and pay zero protocol fee on the whole transfer, whereas a single intent moving the same total amount would owe a nonzero fee.

The fee rate itself is determined by `token_fee`: [2](#0-1) 

For `Nep245`/`Imt` token types, if `amount > 1` the normal protocol fee applies; if `amount <= 1` the fee is forced to `Pips::ZERO`. This threshold is evaluated independently for each `TokenDiff` intent's delta on a given token, not on the total amount a signer moves across a batch of intents.

Because a single signer can submit multiple `TokenDiff` intents (in one signed `DefuseIntents` payload, or across several `MultiPayload`s within one `execute_intents` call), the fee-determination logic never sees the aggregate transferred amount — it only ever evaluates deltas of `1` unit. The equality/threshold binding that should guarantee "fees owed" scale with volume is broken: `fees owed(aggregate amount)` != `sum(fees collected per-unit split)`, with the right-hand side always `0` regardless of how large the aggregate transfer is.

This directly mirrors the Kairos `minOfferCost` bypass: a guarantee (there, a minimum interest; here, a fee proportional to volume) holds only up to a boundary condition (there, `interests == minInterestsToRepay`; here, `amount <= 1`), and once the attacker structures their calls to stay exactly at/under that boundary repeatedly, the aggregate outcome violates the intended invariant, even though each individual call is "correct" in isolation.

### Impact Explanation
This falls under the "fees owed versus fees collected" boundary explicitly called out as Critical impact. Any unprivileged user trading NEP-245 (multi-token, e.g. wrapped Defuse-internal tokens) or IMT (intent-mintable) tokens through `TokenDiff` can avoid the protocol fee entirely on transfers of any size by decomposing them into unit deltas, directly reducing protocol fee revenue collected by `fee_collector()` to zero for these token classes, while other users (or NEP-141 traders, who have no such exemption) continue to pay the intended fee. This is a direct, repeatable value transfer from the protocol/fee collector to the attacker (saved fees), requiring no privileged role, no relayer key, and no special configuration deviation — only ordinary `execute_intents` calls.

### Likelihood Explanation
High. No special conditions are required beyond a signer holding NEP-245/IMT balances and wanting to swap/transfer them; splitting a swap into N intents of unit deltas is mechanical and can be automated by any solver/user. Multiple `TokenDiff` intents can be batched in one `execute_intents` call, so this doesn't even require many separate transactions (subject only to gas limits, which are not exclusionary given `execute_intents` allows up to 300 TGas per the sandbox harness).

### Recommendation
Compute the `Nep245`/`Imt` fee-exemption threshold on the aggregated per-token, per-signer amount across the whole set of intents executed within a single `execute_intents`/`Engine` invocation, not on each individual `TokenDiff` delta in isolation. Alternatively, remove the blanket exemption for `amount <= 1` and instead accumulate fractional/rounded fee remainders across the engine's lifetime (similar to how `TransferMatcher` accumulates deltas) so that a fee is guaranteed proportional to the real aggregate volume moved, regardless of how the signer chooses to split it into intents.

### Proof of Concept
1. Signer holds `10_000` units of a `Nep245` token (e.g. a Defuse-internal wrapped token) and wants to swap all of it via `TokenDiff` against another token, with protocol `fee = 100 bips` (1%).
2. **Single intent path (baseline):** signer submits one `TokenDiff` with `diff = {token_in: -10000, token_out: +X}`. `token_fee` returns the nonzero fee (since `amount = 10000 > 1`), so `sendInterests`-equivalent logic in `execute_intent` collects `fee_ceil(10000, 1%) = 100` units of `token_in` to `fee_collector()`, per [1](#0-0) .
3. **Split path (attack):** signer instead submits `10000` separate `TokenDiff` intents (batched into one `execute_intents([...])` call across one or more signed `MultiPayload`s), each with `diff = {token_in: -1, token_out: +x}`. For each, `token_fee` hits the `amount <= 1` branch and returns `Pips::ZERO`, per [3](#0-2) . Total fee collected across all 10000 intents is `0`.
4. Net result: the signer moves the same aggregate `10000` units of `token_in`, receives the same aggregate `token_out` (matched by counter-party `TokenDiff`s in the batch), but pays `0` fee instead of `100` units — a complete bypass of the protocol fee, purely by choosing how to structure otherwise-equivalent signed intents.
