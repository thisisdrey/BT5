### Title
Unauthenticated forged `BlockValidateResponse` injection into signer's `/proposal_response` HTTP listener - (File: libsigner/src/events.rs)

### Summary
The `SignerEventReceiver::next_event` dispatches any POST to `/proposal_response` straight into `process_event::<T, BlockValidateResponse>`, which JSON-deserializes the body and hands it to a `TryFrom` conversion that unconditionally wraps it as `SignerEvent::BlockValidationResponse`. Nowhere along this path is there a signature, origin, or `auth_token`/`auth_password` check on the *incoming* HTTP request to the signer's listener, so any TCP client that can reach the bound `endpoint` can post a forged validation verdict indistinguishable from a real one from the signer runloop's point of view.

### Finding Description
The claimed equality — "a `BlockValidationResponse` delivered to the runloop == a response actually produced by this node's block validator for a block it was asked to validate" — is broken. `SignerEventReceiver::next_event` in `libsigner/src/events.rs` routes any POST to `/proposal_response` to `process_event::<T, BlockValidateResponse>(request)` with no check other than HTTP method [1](#0-0) . `process_event` (and the `TryFrom<BlockValidateResponse> for SignerEvent<T>` it relies on) only deserializes JSON and returns `Ok(SignerEvent::BlockValidationResponse(..))` — there is no verification that the request came from the paired stacks-node's event-dispatcher rather than an arbitrary remote peer.

The `auth_token`/`auth_password` mechanism visible in the sample configs (`sample/conf/mainnet-signer.toml`, `sample/conf/signer/mainnet-signer-conf.toml`) is used for authenticating requests going *into* the stacks-node's RPC (e.g. `/v3/block_proposal` in `stackslib/src/net/api/postblock_proposal.rs`), not for authenticating requests arriving at the signer's own HTTP listener that the node's `ProposalCallbackHandler`/`EventDispatcher` POSTs to [2](#0-1) . Nothing in `SignerEventReceiver::bind`/`next_event` checks that inbound field against any secret [3](#0-2) .

The signer's listener `endpoint` is operator-configurable and the shipped reference config explicitly shows it bound to all interfaces (`endpoint = "0.0.0.0:30000"` in `sample/conf/signer/mainnet-signer-conf.toml`), making the port remotely reachable in that documented deployment mode, while other samples default to `127.0.0.1`. Whether the port is remotely reachable is therefore a deployment/config choice, not something enforced by the code — but the code path itself performs no authentication regardless of bind address.

Once injected, `handle_event_match` in `stacks-signer/src/v0/signer.rs` treats the forged event exactly like a genuine one: `BlockValidationResponse` is dispatched to `handle_block_validate_response` → `handle_block_validate_ok`/`handle_block_validate_reject`, which look up the block by the attacker-supplied `signer_signature_hash` and mutate `signer_db` state (`mark_pre_committed`, `mark_locally_rejected`, sending pre-commits/rejections onto StackerDB) [4](#0-3) [5](#0-4) .

### Impact Explanation
An attacker who can reach the signer's `/proposal_response` listener can forge an `Ok`/`Reject` validation verdict for any block hash the signer is currently tracking (`self.submitted_block_proposal` or any block present via `block_lookup_by_reward_cycle`). This can flip a block's local state (e.g. force `mark_locally_rejected` on a block the node itself validated as OK, or force a bogus `mark_pre_committed`/pre-commit broadcast for a block the node never actually approved), which then propagates over StackerDB as `send_block_pre_commit`/rejection broadcasts to the rest of the signer set. This is a case of unauthenticated write into signer local state plus network-wide propagation of a forged verdict signal — matching the Critical category ("unauthenticated/unauthorized write to state ... network-wide propagation of forged data").

### Likelihood Explanation
Preconditions: the attacker needs TCP reachability to the signer's HTTP listener port and no valid signer proposal validation currently expected to arrive at that hash would prevent processing — `block_lookup_by_reward_cycle` will simply no-op if the block isn't tracked (`debug!("... not tracking. Ignoring...")`), so the attack is only effective while a real block is pending validation with a known/guessable `signer_signature_hash`. Attacker cost is low (single crafted POST, no secret required) if the operator has bound the listener to a non-loopback address, which the project's own reference config (`sample/conf/signer/mainnet-signer-conf.toml`, `endpoint = "0.0.0.0:30000"`) explicitly documents as a supported configuration. Repeatable per message with no rate limiting visible in this path.

### Recommendation
Authenticate requests to the signer's event-receiver endpoints (at minimum `/proposal_response` and `/stackerdb_chunks`) using the same shared secret configured via `auth_token`/`auth_password`, verified inside `SignerEventReceiver::next_event`/`process_event` before dispatching to `TryFrom`. Additionally/alternatively, default and document that the signer's `endpoint` must bind to loopback only, and have the code reject binds to non-loopback addresses unless an explicit auth secret is configured.

    /// Wait for the node to post something, and then return it.
    /// Errors are recoverable -- the caller should call this method again even if it returns an
    /// error.
    fn next_event(&mut self) -> Result<SignerEvent<T>, EventError> {
        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)
            } else if request.url() == "/new_block" {
                process_event::<T, StacksBlockEvent>(request)
            } else {
                let url = request.url().to_string();
                debug!(
                    "[{:?}] next_event got request with unexpected url {}, return OK so other side doesn't keep sending this",
                    event_receiver.local_addr,
                    url
                );
                ack_dispatcher(request);
                Err(EventError::UnrecognizedEvent(url))
            }
        })?
    }

    /// Handle the block validate response returned from our prior calls to submit a block for validation
    fn handle_block_validate_response(
        &mut self,
        stacks_client: &StacksClient,
        block_validate_response: &BlockValidateResponse,
        sortition_state: &mut Option<SortitionsView>,
    ) {
        info!("{self}: Received a block validate response: {block_validate_response:?}");
        match block_validate_response {
            BlockValidateResponse::Ok(block_validate_ok) => {
                crate::monitoring::actions::record_block_validation_latency(
                    block_validate_ok.validation_time_ms,
                );
                self.handle_block_validate_ok(stacks_client, block_validate_ok, sortition_state);
            }
            BlockValidateResponse::Reject(block_validate_reject) => {
                self.handle_block_validate_reject(block_validate_reject, sortition_state);
            }
        };
        // Remove this block validation from the pending table
        let signer_sig_hash = block_validate_response.signer_signature_hash();
        self.signer_db
            .remove_pending_block_validation(signer_sig_hash)
            .unwrap_or_else(|e| warn!("{self}: Failed to remove pending block validation: {e:?}"));

        // Check if there is a pending block validation that we need to submit to the node
        self.check_pending_block_validations(stacks_client);
    }
