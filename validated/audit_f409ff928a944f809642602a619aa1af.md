### Title
Missing signature verification in `validate_handshake`'s `Some(_)` branch allows unauthenticated peer re-keying - (File: stackslib/src/net/chat.rs)

### Summary
`ConversationP2P::validate_handshake` only calls `message.verify_secp256k1(&handshake_data.node_public_key)` in the `None` branch (when the connection has no known public key yet). In the `Some(_)` branch (an already-established connection), the signature is never checked against the claimed `node_public_key` — only outbound address/port consistency is checked. The unconditional self-impersonation check at lines 1114-1124 runs in both branches and does block the exact scenario described in the question (claiming `local_peer`'s own public key), but it does not compensate for the missing signature check for any *other* claimed key.

### Finding Description
`validate_handshake` (stackslib/src/net/chat.rs:1047-1127) branches on `self.connection.get_public_key()`:
- `None` branch (lines 1059-1071): calls `message.verify_secp256k1(&handshake_data.node_public_key)`, tying the claimed key to the actual signer.
- `Some(_)` branch (lines 1072-1091): performs only an outbound address/port sanity check — `message.verify_secp256k1` is **never called**.

After the `match`, the code unconditionally re-checks that `handshake_data.node_public_key` is not equal to `local_peer`'s own key (lines 1114-1124), so the specific self-impersonation case in the question (attacker claims the node's own public key but signs with an unrelated key) is caught in **both** branches — this part of the question's premise is confirmed but does not yield an exploitable equality break.

However, tracing the equality the question asks about ("node_public_key claimed in payload must equal the key that produced the valid signature… verify this holds across both branches") shows it does **not** hold in the `Some(_)` branch: there is no verification tying the claimed `node_public_key` to the signature at all in that path. This means on an existing/already-keyed connection (e.g., after a prior successful handshake), a party controlling that TCP connection can send a second `Handshake` with an arbitrary `node_public_key` (any key other than `local_peer`'s own) and an unrelated/invalid signature, and `validate_handshake` will still return `Ok`. If, as the normal call sequence implies, `update_from_handshake_data` is subsequently invoked, `self.connection.set_public_key(Some(pubk))` (chat.rs:1164) would overwrite the peer's previously-authenticated public key with this unverified, attacker-chosen key.

### Impact Explanation
This breaks the invariant that a peer's public key can only be updated by someone who actually controls the corresponding private key. It would let a party on an established connection assert an arbitrary identity (e.g. impersonate a known, trusted peer's key) without proving key possession, undermining downstream authentication/authorization decisions keyed off the connection's public key (peer identity, allowlisting, StackerDB slot ownership checks, etc.). This matches "unauthenticated/unauthorized write to state."

### Likelihood Explanation
Precondition: the attacker must already have an established `ConversationP2P` with a known public key (i.e., must have completed at least one prior legitimate handshake on that connection) — this is trivially reachable by any unprivileged remote party who can connect to the P2P port and complete an initial handshake, then send a second crafted `Handshake`. No secret or privileged role is required.

### Recommendation
Call `message.verify_secp256k1(&handshake_data.node_public_key)` unconditionally in `validate_handshake`, regardless of whether `self.connection.get_public_key()` is `None` or `Some(_)`, so that any claimed `node_public_key` — including re-key attempts on already-established connections — is always cryptographically tied to the actual signer before being accepted.

    fn validate_handshake(
        &mut self,
        local_peer: &LocalPeer,
        chain_view: &BurnchainView,
        message: &mut StacksMessage,
    ) -> Result<(), net_error> {
        let handshake_data = match message.payload {
            StacksMessageType::Handshake(ref mut data) => data.clone(),
            _ => panic!("Message is not a handshake"),
        };

        match self.connection.get_public_key() {
            None => {
                // if we don't yet have a public key for this node, verify the message.
                // if it's improperly signed, it's probably a poorly-timed re-key request (but either way the message should be rejected)
                message
                    .verify_secp256k1(&handshake_data.node_public_key)
                    .map_err(|_e| {
                        debug!(
                            "{:?}: invalid handshake: not signed with given public key",
                            &self
                        );
                        net_error::InvalidMessage
                    })?;
            }
            Some(_) => {
                // for outbound connections, the self-reported address must match socket address if we already have a public key.
                // (not the case for inbound connections, since the peer socket address we see may
                // not be the same as the address the remote peer thinks it has).
                // The only exception to this is if the remote peer does not yet know its own
                // public IP address, in which case, its handshake addrbytes will be the
                // any-network bind address (0.0.0.0 or ::)
                if self.stats.outbound
                    && (!handshake_data.addrbytes.is_anynet()
                        && (self.peer_addrbytes != handshake_data.addrbytes
                            || self.peer_port != handshake_data.port))
                {
                    // wrong peer address
                    debug!(
                        "{:?}: invalid handshake -- wrong addr/port ({:?}:{:?})",
                        &self, &handshake_data.addrbytes, handshake_data.port
                    );
                    return Err(net_error::InvalidHandshake);
                }
            }
        };

    pub fn update_from_handshake_data(
        &mut self,
        preamble: &Preamble,
        handshake_data: &HandshakeData,
    ) -> Result<bool, net_error> {
        let pubk = handshake_data
            .node_public_key
            .to_public_key()
            .map_err(|e| net_error::DeserializeError(e.into()))?;

        self.peer_version = preamble.peer_version;
        self.peer_network_id = preamble.network_id;
        self.peer_services = handshake_data.services;
        self.peer_expire_block_height = handshake_data.expire_block_height;
        self.handshake_addrbytes = handshake_data.addrbytes.clone();
        self.handshake_port = handshake_data.port;
        self.data_url = handshake_data.data_url.clone();

        let mut updated = false;
        let cur_pubk_opt = self.connection.get_public_key();
        if let Some(cur_pubk) = cur_pubk_opt {
            if pubk != cur_pubk {
                debug!(
                    "{:?}: Upgrade key {:?} to {:?} expires {:?}",
                    &self,
                    &to_hex(&cur_pubk.to_bytes_compressed()),
                    &to_hex(&pubk.to_bytes_compressed()),
                    self.peer_expire_block_height
                );
                updated = true;
            }
        }

        self.connection.set_public_key(Some(pubk.clone()));

        Ok(updated)
    }
