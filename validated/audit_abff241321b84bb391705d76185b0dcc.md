Audit Report

## Title
Donated tokens sent to the DAP general staker/incentive pot are snapshotted into `ErasValidatorReward`/`ErasValidatorIncentiveBudget` as if they were legitimate inflation, silently distorting era reward accounting - (File: `substrate/frame/staking-async/src/reward.rs`)

## Summary
`EraRewardManager::snapshot_era_rewards` computes the amount moved into an era's reward pot by reading the entire `reducible_balance` of `general_staker_pot`/`general_incentive_pot` — plain derived `AccountId`s with no access control on incoming transfers — rather than a value tracked independently of the account's live balance. Any unprivileged account can call `Balances::transfer_keep_alive` (or any transfer) to these deterministically-derived pot addresses before era rotation, and the full donated amount is swept into `ErasValidatorReward`/`ErasValidatorIncentiveBudget` and paid to validators/nominators via `payout_stakers`, without any minting or governance action.

## Finding Description
`EraRewardManager::snapshot_era_rewards` reads `T::Currency::reducible_balance(&general_staker_pot, Preservation::Preserve, Fortitude::Polite)` and `reducible_balance(&general_incentive_pot, ...)`, then unconditionally transfers those exact balances into freshly-created era pots as `actual_staker`/`actual_incentive`, returned as `EraRewardAllocation`. [1](#0-0) 

There is no independent ledger of "how much DAP actually dripped this era" — the code comment itself states "DAP drips inflation continuously into the general pots. At era boundary, this transfers the accumulated balances (minus ED) into era pots," treating whatever balance currently sits in the account as the legitimate drip amount. [2](#0-1)  The transfer logic unconditionally moves the full `staker_balance`/`incentive_balance` read from the account, with no reconciliation against a tracked "expected" drip amount. [3](#0-2) 

Because `general_staker_pot` and `general_incentive_pot` are computed via `T::RewardPots::pot_account(RewardPot::General(...))` — a deterministic derivation, not an access-controlled account — any signed account can transfer arbitrary funds into them, and those funds are indistinguishable from genuine DAP drip by the time `snapshot_era_rewards` runs.

## Impact Explanation
This allows an unprivileged external attacker to inflate `ErasValidatorReward`/`ErasValidatorIncentiveBudget` for an arbitrary era beyond what the DAP-governance-configured `Perbill` split intends, causing validators/nominators to be paid amounts that do not correspond to the intended reward curve. This is a runtime bug that compromises intended behavior of the staking reward distribution: the corrupted value is the era's `staker_rewards`/`validator_incentive` allocation (and downstream `ErasValidatorReward`/`ErasValidatorIncentiveBudget`), which then determines actual payouts via `payout_stakers`.

## Likelihood Explanation
The general pot account IDs are deterministically derived and thus computable by anyone off-chain. No permissioning exists on `Currency::transfer` into an arbitrary `AccountId`, so any funded, unprivileged account can trigger the donation with a single `balances.transfer_keep_alive` call. `snapshot_era_rewards` runs unconditionally every era, so the inflated balance is guaranteed to be swept into the era pot with no additional attacker action required beyond the donation and waiting for era rotation.

## Recommendation
Track the amount actually dripped by `pallet-dap` into each general pot with an explicit accumulator (incremented on drip, decremented on snapshot) rather than relying on `reducible_balance`. `snapshot_era_rewards` should transfer only the tracked delta; any additional balance in the pot beyond that tracked amount should be treated as external donation and excluded from `EraRewardAllocation`, either returned, burned, or diverted to a separate bucket that does not feed `ErasValidatorReward`/`ErasValidatorIncentiveBudget`.

## Proof of Concept
1. Compute the well-known account for `RewardPot::General(RewardKind::StakerRewards)` via `T::RewardPots::pot_account`.
2. From any unprivileged, funded account, call `Balances::transfer_keep_alive(general_staker_pot, X)` before the next era rotation.
3. At era-end, `EraRewardManager::snapshot_era_rewards` reads `reducible_balance(&general_staker_pot, ...)` including the donated `X`, and transfers the full amount into the era pot as `actual_staker`. [4](#0-3) 
4. The era's `staker_rewards` allocation (and subsequent `payout_stakers` distributions) is inflated by `X` above the DAP-intended amount, with no minting or governance action involved.

```rust
	pub(crate) fn snapshot_era_rewards(era: EraIndex) -> EraRewardAllocation<BalanceOf<T>> {
		let staker_era_pot = Self::create(era, RewardKind::StakerRewards);
		let incentive_era_pot = Self::create(era, RewardKind::ValidatorSelfStake);

		let general_staker_pot =
			T::RewardPots::pot_account(RewardPot::General(RewardKind::StakerRewards));
		let general_incentive_pot =
			T::RewardPots::pot_account(RewardPot::General(RewardKind::ValidatorSelfStake));

		// Leave ED in the general pots to keep them alive.
		let staker_balance = T::Currency::reducible_balance(
			&general_staker_pot,
			Preservation::Preserve,
			Fortitude::Polite,
		);
		let incentive_balance = T::Currency::reducible_balance(
			&general_incentive_pot,
			Preservation::Preserve,
			Fortitude::Polite,
		);

		let actual_staker = if !staker_balance.is_zero() {
			match T::Currency::transfer(
				&general_staker_pot,
				&staker_era_pot,
				staker_balance,
				Preservation::Preserve,
			) {
				Ok(_) => staker_balance,
				Err(e) => {
					log!(error, "Era {:?}: staker reward transfer failed: {:?}", era, e);
					defensive!("Failed to transfer staker rewards to era pot");
					Zero::zero()
				},
			}
		} else {
			Zero::zero()
		};

		let actual_incentive = if !incentive_balance.is_zero() {
			match T::Currency::transfer(
				&general_incentive_pot,
				&incentive_era_pot,
				incentive_balance,
				Preservation::Preserve,
			) {
				Ok(_) => incentive_balance,
				Err(e) => {
					log!(error, "Era {:?}: validator incentive transfer failed: {:?}", era, e);
					defensive!("Failed to transfer validator incentive to era pot");
					Zero::zero()
				},
			}
		} else {
			Zero::zero()
		};
```
