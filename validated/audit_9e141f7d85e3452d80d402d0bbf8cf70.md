Based on my investigation, I found a concrete analog to the reported bug class in `libsigner`'s HTTP event-receiver transport, which is explicitly in scope.

### Title
Signer's HTTP event listener accepts unauthenticated `BlockValidateResponse` (`/proposal_response`), letting a network-adjacent attacker forge the node's block-validation verdict - (File: `libsigner/src/events.rs`)

### Summary
`SignerEventReceiver`, the HTTP server every `stacks-signer` process runs to receive events pushed by its paired `stacks-node`, dispatches incoming `POST` requests purely by URL path with no authentication of any kind. Sample configs bind this listener to `0.0.0.0`, so any network-adjacent host can `POST` a forged `BlockValidateResponse` to `/proposal_response` and drive the signer's block-signing state machine as if the node itself had validated (or rejected) a block.

### Finding Description
`SignerEventReceiver::next_event` reads an HTTP request and dispatches solely on `request.url()`, with zero header/credential check anywhere in the function or in `process_event`: [1](#0-0) 

Compare this to the analogous node-side endpoints in `stackslib`, which *do* gate privileged writes behind an `Authorization` header equality check (e.g. `/v3/block_proposal`): [2](#0-1) 

The `auth_token`/`auth_password` pair documented for signer deployments is used only in the *opposite* direction — the signer authenticates itself as a client when calling the node's `/v3/block_proposal` endpoint: [3](#0-2) 

Nothing authenticates the *inbound* direction: the node (or an attacker) pushing events into the signer's own listener at `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block`. Sample configs explicitly recommend binding this listener on the wildcard address: [4](#0-3) 

Downstream, `/stackerdb_chunks` payloads are protected because the signer independently verifies each chunk's ECDSA signature against a known registered signer address before trusting it (`chunk.recover_pk()` + `is_valid_signer`): [5](#0-4) [6](#0-5) 

However, `/proposal_response` (`BlockValidateResponse`, containing `BlockValidateOk`/`BlockValidateReject`) carries **no signature or provenance check whatsoever**. `handle_block_validate_response` only checks that the referenced `signer_signature_hash` matches a block the signer is already tracking in its local DB — it never verifies that the *verdict itself* actually originated from the paired stacks-node: [7](#0-6) [8](#0-7) 

An attacker who can reach the listener therefore only needs the `signer_signature_hash` of a block the signer is already tracking (observable via the miner's `.miners` StackerDB chunk broadcast, which is itself public gossip data) to inject a fabricated `BlockValidateOk`, causing `handle_block_validate_ok` to advance the block straight to `mark_pre_committed` and broadcast a pre-commit — **without the node ever having validated the block**.

### Impact Explanation
This breaks the equality "block validated by the node" vs. "block treated as validated by the signer." Because `handle_block_validate_ok` only re-checks *local DB consistency* (`check_block_against_signer_db_state`), not that a real node validation occurred, a forged `/proposal_response` can push a signer into broadcasting a pre-commit for a block that never passed `/v3/block_proposal` validation — undermining the entire purpose of the two-phase validate-then-sign design and enabling a bounded-set attacker (needs only network reachability to the signer's listen port) to steer signers toward committing to an unvalidated/invalid block. This aligns with the "steering a node off the tip via false [validation] state" / unauthorized write to signer decision state impact class.

### Likelihood Explanation
Requires the attacker to reach the signer's bound TCP port. Given documented/sample configurations bind to `0.0.0.0:30000` and the code performs zero header, source-IP, or token check, this is trivially reachable for any operator who follows the shipped sample config over any but a fully firewalled loopback deployment. No secret key or privileged role is required — only the `signer_signature_hash`, which is derivable from public block-header data broadcast on `.miners`.

### Recommendation
Add authentication to `SignerEventReceiver::next_event` (e.g., require and check the same shared secret configured as `auth_password`/`auth_token` on every `POST` route, not just as a client-side credential toward the node), and/or bind the listener to loopback-only by default, and/or require the node to also sign the outgoing event payload so the signer can verify provenance the same way it already does for StackerDB chunks.

### Proof of Concept
1. Configure a signer with `endpoint = "0.0.0.0:30000"` per the sample config.
2. Observe a live block proposal's `signer_signature_hash` on the `.miners` StackerDB contract (public gossip).
3. From any host that can reach port 30000, send:
```
POST /proposal_response HTTP/1.1
Host: <signer-ip>:30000
Content-Type: application/json
Content-Length: <n>

{"Ok":{"signer_signature_hash":"<observed-hash>","cost":{...},"validation_time_ms":0,"replay_tx_hash":null,"replay_tx_exhausted":false}}
```
4. The signer's event receiver forwards this with no auth check (`libsigner/src/events.rs:413-458`), and `handle_block_validate_ok` (`stacks-signer/src/v0/signer.rs:1882-1919`) treats it as a genuine node verdict, advancing the block to `PreCommitted` and broadcasting a pre-commit signature over StackerDB — despite the real node never having validated it.

    fn next_event(&mut self) -> Result<SignerEvent<T>, EventError> {
        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)
            } else if request.url() == "/new_block" {
                process_event::<T, StacksBlockEvent>(request)
            } else {
                let url = request.url().to_string();
                debug!(
                    "[{:?}] next_event got request with unexpected url {}, return OK so other side doesn't keep sending this",
                    event_receiver.local_addr,
                    url
                );
                ack_dispatcher(request);
                Err(EventError::UnrecognizedEvent(url))
            }
        })?

                    replay_tx_hash,

    /// Handle the block validate response returned from our prior calls to submit a block for validation
    fn handle_block_validate_response(
        &mut self,
        stacks_client: &StacksClient,
        block_validate_response: &BlockValidateResponse,
        sortition_state: &mut Option<SortitionsView>,
    ) {
        info!("{self}: Received a block validate response: {block_validate_response:?}");
        match block_validate_response {
            BlockValidateResponse::Ok(block_validate_ok) => {
                crate::monitoring::actions::record_block_validation_latency(
                    block_validate_ok.validation_time_ms,
                );
                self.handle_block_validate_ok(stacks_client, block_validate_ok, sortition_state);
            }
            BlockValidateResponse::Reject(block_validate_reject) => {
                self.handle_block_validate_reject(block_validate_reject, sortition_state);
            }
        };
        // Remove this block validation from the pending table
        let signer_sig_hash = block_validate_response.signer_signature_hash();
        self.signer_db
            .remove_pending_block_validation(signer_sig_hash)
            .unwrap_or_else(|e| warn!("{self}: Failed to remove pending block validation: {e:?}"));

        // Check if there is a pending block validation that we need to submit to the node
        self.check_pending_block_validations(stacks_client);
    }
