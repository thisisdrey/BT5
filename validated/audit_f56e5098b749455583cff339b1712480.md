### Title
`lending_pool_close_bank` does not verify outstanding fee/insurance buckets are zero before closing the bank, permanently locking those funds - ([File: programs/marginfi/src/instructions/marginfi_group/close_bank.rs])

### Summary
`lending_pool_close_bank` closes a `Bank` account (returns rent to the admin via Anchor's `close = admin`) after checking only that `lending_position_count`, `borrowing_position_count`, `total_asset_shares`, `total_liability_shares`, and `emissions_remaining` are zero. It never checks `bank.collected_insurance_fees_outstanding`, `bank.collected_group_fees_outstanding`, or `bank.collected_program_fees_outstanding`. These are separate accounting counters, decoupled from `total_asset_shares`/`total_liability_shares`, that accrue independently (via interest accrual and via dust routing in `withdraw_all`/`close_balance`). If any of them is non-zero when the bank is closed, the corresponding tokens sitting in the bank's liquidity/insurance/fee vaults become permanently unrecoverable because every instruction that can move them (`lending_pool_collect_bank_fees`, `lending_pool_withdraw_fees`, `lending_pool_withdraw_insurance`, `lending_pool_withdraw_fees_permissionless`) requires loading the now-closed `Bank` account.

### Finding Description
`lending_pool_close_bank` [1](#0-0)  performs these checks before allowing Anchor to close the bank account:
- `CLOSE_ENABLED_FLAG` set
- `lending_position_count == 0 && borrowing_position_count == 0`
- `total_asset_shares` and `total_liability_shares` are zero (with tolerance)
- `emissions_remaining` is zero (with tolerance)

It never checks `collected_insurance_fees_outstanding`, `collected_group_fees_outstanding`, or `collected_program_fees_outstanding`. These fields track fee/insurance amounts that have been carved out of the liquidity vault's interest accrual but not yet swept into the dedicated fee/insurance vaults, and are also incremented by dust routed in `withdraw_all` and `close_balance` (asset-side dust is added to `collected_insurance_fees_outstanding`) [2](#0-1) [3](#0-2) . Because these amounts accrue independently from `total_asset_shares`/`total_liability_shares` (which the close check does examine), it is possible for a bank to reach the state where shares/position counts are zero while these fee buckets are still non-zero (e.g., accrued protocol fees during the bank's life, or trailing dust from the last balance closures).

Once the bank account is closed via Anchor's `close = admin`, the corresponding real SPL tokens (still sitting in the bank's liquidity vault, or awaiting sweep) become unreachable: every instruction capable of moving them —`lending_pool_collect_bank_fees`, `lending_pool_withdraw_fees`, `lending_pool_withdraw_insurance`, `lending_pool_withdraw_fees_permissionless`— requires a live `AccountLoader<'info, Bank>` for that PDA [4](#0-3) [5](#0-4) . With the account closed and its data zeroed/rent reclaimed, these instructions can no longer be constructed against that bank, so the fee/insurance tokens are permanently locked. This is structurally the same bug class as the reported `SpiceAuction::removeAuctionConfig` issue: a state-deletion path fails to reconcile/verify a *separate* accounting bucket that is decoupled from the primary balance-tracking totals, resulting in stranded funds that can no longer be moved by any instruction.

### Impact Explanation
This is a permanent lock of protocol/insurance fee funds (not user deposits) belonging to the group/global-fee-wallet. The impact is a fund-freezing bug reachable purely through normal, privileged (group admin) usage of `lending_pool_close_bank`, without needing any malicious behavior — an admin closing a bank in the ordinary lifecycle (after users have withdrawn) can unknowingly strand accrued fees/insurance dust. This satisfies the "permanent lock/freeze" acceptance criterion, and the affected funds are core protocol accounting values (`collected_*_fees_outstanding` on `Bank`), not admin-privileged mock state.

### Likelihood Explanation
Likelihood is moderate: `total_asset_shares`/`total_liability_shares` reaching zero while `collected_insurance_fees_outstanding` or `collected_group_fees_outstanding` remain non-zero is a realistic end-of-life scenario for any bank that accrued interest/fees and where the last depositors withdrew via `withdraw_all` (which itself can route dust into `collected_insurance_fees_outstanding`), before `lending_pool_collect_bank_fees` was called to sweep those fees to the dedicated vaults. Since bank closure is admin-gated but relies purely on the incomplete check-list above, no attacker action is required — an admin simply following the documented "close a bank with no open positions" flow can trigger the fund lock.

### Recommendation
Add checks in `lending_pool_close_bank` requiring `collected_insurance_fees_outstanding`, `collected_group_fees_outstanding`, and `collected_program_fees_outstanding` to be zero (or below `ZERO_AMOUNT_THRESHOLD`) before allowing the bank to close, mirroring the existing `emissions_remaining` check:
```rust
check!(
    I80F48::from(bank.collected_insurance_fees_outstanding).is_zero_with_tolerance(ZERO_AMOUNT_THRESHOLD)
        && I80F48::from(bank.collected_group_fees_outstanding).is_zero_with_tolerance(ZERO_AMOUNT_THRESHOLD)
        && I80F48::from(bank.collected_program_fees_outstanding).is_zero_with_tolerance(ZERO_AMOUNT_THRESHOLD),
    MarginfiError::BankCannotClose
);
```
This forces admins to call `lending_pool_collect_bank_fees` / `lending_pool_withdraw_fees` / `lending_pool_withdraw_insurance` to fully sweep any outstanding fee/insurance dust before the bank PDA (and the ability to move those funds) is destroyed.

### Proof of Concept
Conceptual sequence (cannot be executed here, but derivable directly from the cited code paths):
1. Users deposit/borrow on a bank; interest accrues, incrementing `bank.collected_insurance_fees_outstanding` / `collected_group_fees_outstanding` via `accrue_interest` fee-split logic in `programs/marginfi/src/state/bank.rs`.
2. Last user calls `lending_account_withdraw` with `withdraw_all = true`; `withdraw_all` closes the balance and any residual fractional token amount is added to `bank.collected_insurance_fees_outstanding` [6](#0-5) . Now `total_asset_shares == 0`, `lending_position_count == 0`, but `collected_insurance_fees_outstanding > 0`.
3. Admin does not call `lending_pool_collect_bank_fees` (nothing forces this), and calls `lending_pool_close_bank`. The existing checks all pass (`CLOSE_ENABLED_FLAG` set, zero positions, zero shares, zero `emissions_remaining`) [7](#0-6) ; the bank account is then closed by Anchor's `close = admin` [8](#0-7) .
4. The tokens tracked by `collected_insurance_fees_outstanding` remain physically in the (now-orphaned) liquidity vault PDA. No instruction (`lending_pool_collect_bank_fees`, `lending_pool_withdraw_fees`, `lending_pool_withdraw_insurance`) can be invoked anymore because they all require an active `AccountLoader<'info, Bank>` for that bank — which no longer exists. The funds are permanently locked.

pub fn lending_pool_close_bank(ctx: Context<LendingPoolCloseBank>) -> MarginfiResult {
    let mut group = ctx.accounts.group.load_mut()?;
    // Note: Groups created prior to 0.1.2 have a non-authoritative count here, so subtraction
    // without saturation could reduce the count below zero.
    group.banks = group.banks.saturating_sub(1);

    let bank = ctx.accounts.bank.load()?;

    // banks created prior to 0.1.4 can never be closed because we cannot guarantee an accurate
    // position count for those banks.
    check!(
        bank.get_flag(CLOSE_ENABLED_FLAG),
        MarginfiError::BankCannotClose,
        "Only banks created in 0.1.4 and later can close"
    );
    check!(
        bank.lending_position_count == 0 && bank.borrowing_position_count == 0,
        MarginfiError::BankCannotClose,
        "Only banks with no open positions can close"
    );
    check!(
        I80F48::from(bank.total_asset_shares).is_zero_with_tolerance(ZERO_AMOUNT_THRESHOLD)
            && I80F48::from(bank.total_liability_shares)
                .is_zero_with_tolerance(ZERO_AMOUNT_THRESHOLD),
        MarginfiError::BankCannotClose
    );
    check!(
        I80F48::from(bank.emissions_remaining).is_zero_with_tolerance(ZERO_AMOUNT_THRESHOLD),
        MarginfiError::BankCannotClose
    );

    drop(bank);

    // Bank will now be closed by anchor

    Ok(())
