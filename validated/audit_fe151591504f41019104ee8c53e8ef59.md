### Title
EIP-7918 reserve-price comparison in `CalcExcessBlobGas` uses a blob-scaled price instead of the per-gas blob base fee, causing wrong `excessBlobGas`/blob base fee after Osaka - (File: consensus/misc/eip4844/eip4844.go)

### Summary
`calcExcessBlobGas` implements the EIP-7918 "reserve price" floor for the blob base fee. Per EIP-7918, the reserve price (`BLOB_BASE_COST * base_fee_per_gas`) must be compared against the *per-unit* blob base fee (`get_base_fee_per_blob_gas`, i.e. the raw `blobBaseFee`). The Go implementation instead compares the reserve price against `bcfg.blobPrice(...)`, which is `blobBaseFee * params.BlobTxBlobGasPerBlob` (131072) — the price of a *whole blob*, not the per-gas price. This introduces exactly the kind of unit/scale mismatch highlighted in the referenced report (comparing/combining values expressed in different, unreconciled scales), and it changes the outcome of the reserve-price branch versus the EIP-7918 spec.

### Finding Description [1](#0-0) 
defines:
```go
func (bc *BlobConfig) blobBaseFee(excessBlobGas uint64) *big.Int {
	return fakeExponential(minBlobGasPrice, new(big.Int).SetUint64(excessBlobGas), new(big.Int).SetUint64(bc.UpdateFraction))
}
func (bc *BlobConfig) blobPrice(excessBlobGas uint64) *big.Int {
	f := bc.blobBaseFee(excessBlobGas)
	return new(big.Int).Mul(f, big.NewInt(params.BlobTxBlobGasPerBlob))
}
```
`blobBaseFee` is the per-unit-of-blob-gas price (this is what `CalcBlobFee`, i.e. `header.excessBlobGas -> base_fee_per_blob_gas`, returns to the rest of the protocol). `blobPrice` multiplies that per-gas price by `BlobTxBlobGasPerBlob` (131072) to get the price of an entire blob.

The EIP-7918 branch is: [2](#0-1) 
```go
if isOsaka {
    var (
        baseCost     = big.NewInt(params.BlobBaseCost)
        reservePrice = baseCost.Mul(baseCost, parent.BaseFee)
        blobPrice    = bcfg.blobPrice(parentExcessBlobGas)
    )
    if reservePrice.Cmp(blobPrice) > 0 {
        scaledExcess := parentBlobGasUsed * uint64(bcfg.Max-bcfg.Target) / uint64(bcfg.Max)
        return parentExcessBlobGas + scaledExcess
    }
}
```
EIP-7918 specifies the comparison as `reserve_price = BLOB_BASE_COST * parent.base_fee_per_gas` versus `base_fee_per_blob_gas = get_base_fee_per_blob_gas(parent)` — i.e. the raw per-gas blob base fee, not the price of a full blob. By using `bcfg.blobPrice(...)` (which is `blobBaseFee * 131072`) instead of the raw `bcfg.blobBaseFee(...)`, the comparator on the right-hand side is inflated by a factor of 131072. This means `reservePrice.Cmp(blobPrice) > 0` will almost never be true when it should be true under the correct spec formula (since `reservePrice` would need to be ~131072x larger than intended to trigger the branch).

As a direct consequence, on network segments/forks where the reserve-price floor should engage (i.e., when the real blob base fee sits below `BLOB_BASE_COST * base_fee_per_gas`), Geth will instead silently fall through to the "Original EIP-4844 formula" path: [3](#0-2) 
```go
// Original EIP-4844 formula.
return excessBlobGas - targetGas
```
producing a different `excessBlobGas` value than an EIP-7918-conformant client would compute for the same parent header.

### Impact Explanation
`excessBlobGas` is a consensus-critical header field: `VerifyEIP4844Header` rejects any block whose `header.ExcessBlobGas` does not exactly match `CalcExcessBlobGas(config, parent, header.Time)` [4](#0-3) , and the resulting value directly determines the blob base fee (`CalcBlobFee`) used for blob-gas fee-market accounting in subsequent blocks. If this Geth build computes a different `excessBlobGas` than a spec-conformant client under the same Osaka-era conditions (reserve price below-vs-above the true per-gas blob base fee, but the comparison miscategorizes it due to the 131072x scale error), the two clients disagree on:
1. What `excessBlobGas` a valid header must contain (Geth would reject a block that a conformant client accepts, or vice versa) — a hard consensus split.
2. The blob base fee charged/verified for blob transactions in the next block, changing fee accounting.

This matches the "Critical - a consensus split where Geth accepts or rejects a mainnet block other clients treat oppositely" category, since it is a deterministic, non-malicious-input divergence in a core header-validation rule reachable on every block once Osaka (and the EIP-7918 reserve-price condition) is active.

### Likelihood Explanation
This code path is exercised on every block once the Osaka fork is active and the chain contains excess blob gas (`excessBlobGas >= targetGas`), which is a routine, non-adversarial condition — it does not require a malicious peer or crafted attack, only ordinary blob-gas market conditions where the effective blob price is low relative to the base fee (a state the reserve-price mechanism is specifically designed to handle). Given that the repo's own tests (`TestCalcExcessBlobGasEIP7918`) exercise this branch and appear tuned to the buggy implementation, this divergence would occur automatically in normal operation and is not merely theoretical.

### Recommendation
Compare `reservePrice` against the raw per-gas blob base fee (`bcfg.blobBaseFee(parentExcessBlobGas)`), not `bcfg.blobPrice(...)`:
```go
reservePrice = new(big.Int).Mul(big.NewInt(params.BlobBaseCost), parent.BaseFee)
baseFeePerBlobGas := bcfg.blobBaseFee(parentExcessBlobGas)
if reservePrice.Cmp(baseFeePerBlobGas) > 0 {
    ...
}
```
Cross-check against the canonical EIP-7918 reference implementation/test vectors to confirm the comparator units, and add explicit unit-labelled tests (`reservePrice` in wei-per-blob-gas units vs `blobPrice` in wei-per-blob units) to prevent regressions of this scale mismatch.

### Proof of Concept
Deterministic path (no attacker input needed, just chain state), using the code at [5](#0-4) :
1. Let Osaka be active, `parent.BaseFee = B`, `parent.ExcessBlobGas = E` such that the true `base_fee_per_blob_gas = fakeExponential(minBlobGasPrice, E, UpdateFraction) = F`.
2. Choose `B` and `E` such that, per the correct EIP-7918 rule, `BLOB_BASE_COST * B > F` (reserve price should dominate, triggering the scaled-excess branch) but `BLOB_BASE_COST * B <= F * BlobTxBlobGasPerBlob` (i.e., `BLOB_BASE_COST * B` is less than 131072 times `F`) — a wide and easily satisfiable numeric window given `BlobTxBlobGasPerBlob = 131072`.
3. Under this configuration, a spec-conformant EIP-7918 client computes `excessBlobGas = E + parentBlobGasUsed*(Max-Target)/Max`, while this Geth build's `calcExcessBlobGas` evaluates `reservePrice.Cmp(blobPrice) > 0` as false (because `blobPrice = F*131072 >> reservePrice`), falls through, and computes `excessBlobGas = E + parentBlobGasUsed - targetGas` instead.
4. The two values differ, so a header with the spec-correct `ExcessBlobGas` is rejected by this Geth node (via `VerifyEIP4844Header`'s equality check [4](#0-3) ) while accepted by a conformant client, and vice versa for a header built using Geth's (wrong) value — a reproducible consensus split, verifiable purely by unit-testing `calcExcessBlobGas` against the EIP-7918 reference formula with the parameters above.

func calcExcessBlobGas(isOsaka bool, bcfg BlobConfig, parent *types.Header) uint64 {
	var parentExcessBlobGas, parentBlobGasUsed uint64
	if parent.ExcessBlobGas != nil {
		parentExcessBlobGas = *parent.ExcessBlobGas
		parentBlobGasUsed = *parent.BlobGasUsed
	}

	var (
		excessBlobGas = parentExcessBlobGas + parentBlobGasUsed
		targetGas     = uint64(bcfg.Target) * params.BlobTxBlobGasPerBlob
	)
	if excessBlobGas < targetGas {
		return 0
	}

	// EIP-7918 (post-Osaka) introduces a different formula for computing excess,
	// in cases where the price is lower than a 'reserve price'.
	if isOsaka {
		var (
			baseCost     = big.NewInt(params.BlobBaseCost)
			reservePrice = baseCost.Mul(baseCost, parent.BaseFee)
			blobPrice    = bcfg.blobPrice(parentExcessBlobGas)
		)
		if reservePrice.Cmp(blobPrice) > 0 {
			scaledExcess := parentBlobGasUsed * uint64(bcfg.Max-bcfg.Target) / uint64(bcfg.Max)
			return parentExcessBlobGas + scaledExcess
		}
	}

	// Original EIP-4844 formula.
	return excessBlobGas - targetGas
}
