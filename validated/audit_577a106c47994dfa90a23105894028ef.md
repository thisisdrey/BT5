### Title
Unauthenticated event listener accepts forged `SignerEvent`s from any TCP peer - (File: libsigner/src/events.rs)

### Summary
`SignerEventReceiver::bind` opens a plain `tiny_http` server via `HttpServer::http(listener)` with no peer-identity check, shared secret, or signature verification anywhere in the accept/dispatch path. `next_event` routes any POST to `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, or `/new_block` straight into `process_event`, which only JSON-deserializes the body and converts it into a `SignerEvent`, so any TCP peer that can reach the bound socket can inject fabricated signer events indistinguishable from ones sent by the trusted local stacks-node event dispatcher.

### Finding Description
The intended invariant is: every `SignerEvent` delivered to the signer runloop should equal an event actually emitted by the locally configured, trusted stacks-node process. This equality is broken because:

- `bind` just does `HttpServer::http(listener)` with no TLS, no auth header, no shared secret check: [1](#0-0) 
- `next_event` accepts any HTTP request from `http_server.recv()` and dispatches purely based on `request.url()`, with no check on the source address or any credential: [2](#0-1) 
- `process_event` reads the raw body and deserializes it directly to the target JSON type, then converts it via `TryInto<SignerEvent<T>>`, with no signature or provenance check at all: [3](#0-2) 
- For `/proposal_response`, the JSON body is converted to `SignerEvent::BlockValidationResponse` with a pure pass-through, no validation of any kind: [4](#0-3) 
- For `/new_burn_block`, the JSON body becomes `SignerEvent::NewBurnBlock` with fields (burn height, hashes, consensus hash) taken verbatim from attacker-controlled JSON: [5](#0-4) 
- For `/stackerdb_chunks`, note that this path does perform a real cryptographic guard for signer-contract chunks — it recovers the pubkey (`chunk.recover_pk()`) from the chunk's own signature before treating it as a signer message: [6](#0-5) . However, for the miner contract lane (`MINERS_NAME`), there is **no signature check at all** — the raw `chunk.data` is deserialized directly into `T` (miner messages) with no signer/proposer verification at this layer: [7](#0-6) .

So `/proposal_response`, `/new_burn_block`, `/new_block`, and the miner-message lane of `/stackerdb_chunks` have zero cryptographic binding to the trusted node at this HTTP-ingestion layer. The only guard that exists (StackerDB chunk signature recovery) is confined to the signer-contract lane and does not protect the other three endpoints or the miner lane.

### Impact Explanation
Any remote peer with network reachability to the bound event-receiver socket can synthesize arbitrary `BlockValidateResponse`, `BurnBlockEvent`, or `StacksBlockEvent` JSON bodies and have them accepted verbatim as if the local stacks-node emitted them, injecting forged data into the signer runloop (unauthenticated write to signer-local state / decision inputs). This matches the "unauthenticated/unauthorized write to state" Critical category for the endpoints lacking any lower-layer signature check. This is repeatable per POST request with no rate limiting visible in this code path.

### Likelihood Explanation
Exploitability is entirely conditioned on whether the event-receiver socket is reachable beyond loopback. The code itself places no restriction on the bind address — `bind` accepts whatever `SocketAddr` is configured — and does not enforce loopback-only binding in `libsigner/src/events.rs`. In a deployment where the operator binds the signer's event-observer endpoint to a non-loopback interface (a configuration decision outside this file), any remote unprivileged TCP client can reach it with no secret, no peer identity, and no StackerDB slot required for the `/proposal_response`, `/new_burn_block`, `/new_block`, and miner-lane `/stackerdb_chunks` paths. Cost to the attacker is a single crafted HTTP POST.

### Recommendation
Add authentication to the event-receiver HTTP endpoint: require a pre-shared secret/bearer token configured to match the node's event-observer config, verify a mutually-known secret or mTLS, and/or bind by default to loopback with an explicit, documented opt-in and warning for non-loopback bind addresses. Additionally, treat the miner-message lane in `TryFrom<StackerDBChunksEvent>` (`libsigner/src/events.rs:549-567`) with the same signature-verification rigor used for the signer-contract lane, rather than deserializing unauthenticated chunk bytes directly.

```rust
// libsigner/src/events.rs (test)
use std::io::Write;
use std::net::{TcpStream, SocketAddr};
use crate::events::{SignerEventReceiver, SignerEvent, EventReceiver};

#[test]
fn unauthenticated_remote_peer_can_inject_proposal_response() {
    let mut receiver: SignerEventReceiver<v0::messages::SignerMessage> =
        SignerEventReceiver::new(false);
    let bound_addr = receiver.bind("127.0.0.1:0".parse().unwrap()).unwrap();

    // Simulate a remote, non-dispatcher peer
    std::thread::spawn(move || {
        let mut stream = TcpStream::connect(bound_addr).unwrap();
        let body = r#"{"result":"Reject", "reason":"forged", ...}"#; // crafted BlockValidateResponse JSON
        let req = format!(
            "POST /proposal_response HTTP/1.1\r\nHost: {}\r\nContent-Length: {}\r\nConnection: close\r\n\r\n{}",
            bound_addr, body.len(), body
        );
        stream.write_all(req.as_bytes()).unwrap();
    });

    let event = receiver.next_event().unwrap();
    assert!(matches!(event, SignerEvent::BlockValidationResponse(_)));
    // event content is populated purely from attacker-supplied bytes,
    // with no check that the peer is the configured stacks-node.
}
```

```rust
fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}
```
