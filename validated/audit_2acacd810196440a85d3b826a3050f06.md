Based on my investigation, I found the strongest analog to CVE-2017-11663 (crafted-input invalid memory read/crash in a media parser) in java-tron's `ValidateMultiSign` precompiled contract, which parses attacker-controlled TVM calldata without bounds checks unless a specific activation flag is set.

### Title
Unguarded ABI-word decoding in `ValidateMultiSign`/`BatchValidateSign` precompiles causes uncaught RuntimeException on crafted calldata pre-TIP-854 activation - (File: `actuator/src/main/java/org/tron/core/vm/PrecompiledContracts.java`)

### Summary
The `ValidateMultiSign.execute()` method decodes calldata into a `DataWord[]` array and indexes into it (`words[0]`, `words[1]`, `words[3]`, and offsets derived from attacker-supplied word values) without validating the calldata shape, unless the `allowTvmOsaka` (TIP-854) config flag is active. [1](#0-0) 

### Finding Description
`ValidateMultiSign.execute(byte[] rawData)` only calls `isValidAbiEncoding()` to reject malformed calldata when `VMConfig.allowTvmOsaka()` is true. When that flag is disabled, `DataWord.parseArray(rawData)` and subsequent indexing (`words[0]`, `words[1]`, `words[2]`, `words[3]`, and `words[words[3].intValueSafe() / WORD_SIZE]`) execute directly against attacker-controlled, arbitrarily short or malformed byte arrays, similar to how WildMIDI's `_WM_SetupMidiEvent` read past buffer bounds when parsing a crafted MIDI file. [2](#0-1)  The project's own regression test explicitly documents this as unguarded legacy behavior: "this precompile has no outer catch, so a too-short input raises inside the decoder." [3](#0-2) 

By contrast, the sibling `BatchValidateSign.execute()` wraps its entire body (`doExecute`) in a `try { } catch (Throwable t)` that unconditionally converts any exception into a benign `(true, zero-bytes)` result, so it does not propagate. [4](#0-3)  `ValidateMultiSign` has no equivalent outer catch around the initial decode section (lines 1057–1074); its only `try/catch` wraps the later permission-checking logic (lines 1082–1117), not the decode. [5](#0-4) 

### Impact Explanation
An exception raised in the decode path is an unchecked `RuntimeException` (e.g. `ArrayIndexOutOfBoundsException`). When the precompile is invoked via a `CALL` opcode from within the normal EVM interpreter loop, `VM.play()`'s outer `try/catch (RuntimeException e)` catches it, marks the program stopped, and spends all energy — this is a contained "revert," not a crash. [6](#0-5)  I was unable to fully verify, due to running out of tool iterations, whether every call path that reaches `ValidateMultiSign.execute()` — including constant/`triggerConstantContract` HTTP/gRPC calls, energy estimation, or any invocation of `Program.callToPrecompiledAddress()` that might occur outside the `VM.play()` loop's catch block — is uniformly wrapped by an equivalent catch. If such a path exists (e.g. an API query invoking the precompile logic without going through `VM.play()`), the uncaught exception could crash the servicing thread for that specific query path rather than the whole node process.

### Likelihood Explanation
Triggering the crafted-calldata condition only requires an unprivileged party to submit a transaction (or constant call) that invokes address `0x...0a` (`validateMultiSign`) with a calldata length shorter than the expected `(5 + n*5) * 32` bytes, e.g. `new byte[(5+1)*32]` as shown in the test. [7](#0-6)  This requires no special privileges and is only exploitable while `allowTvmOsaka` (TIP-854) is not yet activated on the target network; on networks where TIP-854 is already activated, `isValidAbiEncoding()` rejects the malformed input before the unsafe indexing runs. [8](#0-7) 

### Recommendation
Add the same `isValidAbiEncoding` guard (or an unconditional outer `try/catch`, matching `BatchValidateSign`'s pattern) to `ValidateMultiSign.execute()` regardless of the `allowTvmOsaka` flag, so malformed calldata is rejected uniformly instead of relying on activation-gated validation. Also verify all invocation paths of precompiled contracts (constant calls, energy estimation, JSON-RPC/gRPC `triggerConstantContract`) route through a handler that catches `RuntimeException` before it can escape to a server thread.

### Proof of Concept
```java
// actuator/src/main/java/org/tron/core/vm/PrecompiledContracts.java (ValidateMultiSign)
VMConfig.initAllowTvmOsaka(0); // pre-TIP-854 network state
ValidateMultiSign contract = new ValidateMultiSign();
contract.setRepository(RepositoryImpl.createRoot(StoreFactory.getInstance()));
byte[] tooShortCalldata = new byte[(5 + 1) * 32]; // fewer words than the decoder assumes
contract.execute(tooShortCalldata); // raises RuntimeException inside decode (words[3] / indexing)
```
This mirrors the project's own `testTip854PreActivationNoOp` test, which documents that the call "may throw" and treats it as expected legacy behavior. [7](#0-6)

    private static final int ENGERYPERSIGN = 1500;
    private static final int MAX_SIZE = 5;
    private static final int ABI_HEADER_WORDS = 5;
    private static final int ABI_ITEM_WORDS = 5;


    @Override
    public long getEnergyForData(byte[] data) {
      long cnt = (data.length / WORD_SIZE - 5) / 5;
      // one sign 1500, half of ecrecover
      return cnt * ENGERYPERSIGN;
    }

    @Override
    public Pair<Boolean, byte[]> execute(byte[] rawData) {
      if (VMConfig.allowTvmOsaka()
          && !isValidAbiEncoding(rawData, ABI_HEADER_WORDS, ABI_ITEM_WORDS)) {
        return Pair.of(false, EMPTY_BYTE_ARRAY);
      }
      DataWord[] words = DataWord.parseArray(rawData);
      byte[] address = words[0].toTronAddress();
      int permissionId = words[1].intValueSafe();
      byte[] data = words[2].getData();

      byte[] combine = ByteUtil.merge(address, ByteArray.fromInt(permissionId), data);
      byte[] hash = Sha256Hash.hash(CommonParameter
          .getInstance().isECKeyCryptoEngine(), combine);

      if (VMConfig.allowTvmSelfdestructRestriction()) {
        int sigArraySize = words[words[3].intValueSafe() / WORD_SIZE].intValueSafe();
        if (sigArraySize > MAX_SIZE) {
          return Pair.of(true, DATA_FALSE);
        }
      }
      byte[][] signatures = VMConfig.allowTvmSelfdestructRestriction() ?
          extractSigArray(words, words[3].intValueSafe() / WORD_SIZE, rawData) :
          extractBytesArray(words, words[3].intValueSafe() / WORD_SIZE, rawData);
