### Title
Unauthenticated remote `/shutdown` POST permanently kills the signer's event receiver `main_loop` - ([File: libsigner/src/events.rs])

### Summary
`SignerEventReceiver::next_event` matches the request URL `/shutdown` and unconditionally sets `stop_signal` to `true` with no check on the sender's identity, origin, or any secret/auth token, causing `main_loop` to terminate. Any TCP client that can reach the bound event-receiver address (commonly configured as `0.0.0.0:PORT`, e.g. `sample/conf/signer/mainnet-signer-conf.toml` uses `endpoint = "0.0.0.0:30000"`) can send a single unauthenticated `POST /shutdown` HTTP request and disable the signer's event ingestion permanently.

### Finding Description
In `next_event()`, the dispatch logic checks `request.url()` against several known routes and, for `/shutdown`, immediately does: [1](#0-0) 
with no verification of the caller — no shared secret, no comparison against `SignerStopSignaler`'s local address, no auth header check (unlike the node's `auth_token`/`auth_password` gating used for the `events_observer`/block-proposal endpoints, per `docs/signing.md`). `EventError::Terminated` is then returned, which `main_loop` treats as a clean exit condition: [2](#0-1) 
The endpoint is designed only to be used internally by `SignerStopSignaler::send`, which connects to `self.local_addr` and issues the exact same `POST /shutdown` request: [3](#0-2) 
but nothing in `next_event()` restricts acceptance to that internal caller — the HTTP server (`tiny_http`) accepts connections from any peer that can reach the bound socket, and the handler dispatches purely on `request.url()` and `request.method()`.

### Impact Explanation
Once `stop_signal` is set, `is_stopped()` returns `true` on every subsequent `main_loop` iteration of the event-receiver thread, so `main_loop` (both the trait-default in `EventReceiver::main_loop` and the receiver's own check inside `next_event`) breaks out permanently: [4](#0-3) [5](#0-4) 
This severs the event-receiver thread spawned in `Signer::spawn`, so all downstream event consumers (the signer's `signer_runloop` thread, which processes `stackerdb_chunks`, `proposal_response`, `new_burn_block`, and `new_block` events) stop receiving any new events from the node: [6](#0-5) 
A single unauthenticated POST request thus causes an unauthenticated remote denial-of-service against a signer node, halting its participation in block signing until the process is restarted — this matches the Critical "remote crash/unauthenticated DoS from few messages" category.

### Likelihood Explanation
The only precondition is TCP reachability to the configured `endpoint` address/port. Sample and reference configs explicitly bind this to `0.0.0.0`, exposing it beyond localhost: [7](#0-6) 
The codebase itself documents awareness of this exposure risk without providing a code-level mitigation: [8](#0-7) 
Attacker cost is a single crafted HTTP POST with `Content-Length` and a body — no cryptographic material, no valid StackerDB slot, and no signature is required. The attack is trivially repeatable against any operator who follows the documented sample configuration.

### Recommendation
Do not expose an unauthenticated shutdown path over the network socket. Options: (1) require a shared secret/token (already used for node `auth_token`) to be present and validated before honoring `/shutdown`; (2) restrict `/shutdown` acceptance to loopback-originated connections by checking the peer address from the underlying `TcpStream`/`tiny_http` request; or (3) use a separate local-only IPC mechanism (e.g., a unix domain socket or an in-process channel) for `SignerStopSignaler` instead of an HTTP route reachable by any TCP peer.
