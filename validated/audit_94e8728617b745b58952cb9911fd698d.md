Found a valid, reachable analog in Nebula's `RecvError` control-message handling. It shares the report's root cause: a state-changing action is authorized by a check that has no cryptographic binding and no per-use/replay guard, so an attacker with zero legitimate credentials (no CA-signed cert, no session keys) can trigger the privileged action as many times as desired.

### Title
Unauthenticated, spoofable `RecvError` control packets let a certificate-less attacker repeatedly force tunnel teardown (`Interface.handleRecvError`) - (File: outside.go)

### Summary
`RecvError` packets are processed completely outside of the Noise/AEAD authenticated path. Unlike `Message`/`MessageRelay` packets — which require `ConnectionState.Decrypt`/`VerifyRelay` (AEAD verification tied to session keys derived from a CA-signed certificate) — and unlike `CloseTunnel`, which is validated by the AEAD-protected data path (confirmed by `TestCloseTunnelAuthenticated`), a `RecvError` packet is accepted purely because its UDP source `netip.AddrPort` textually matches the value cached in `hostinfo.GetRemote()`.

### Finding Description
In `outside.go`, `readOutsidePackets` routes `header.RecvError` straight to `f.handleRecvError(via.UdpAddr, h)` before any certificate or key material is consulted: [1](#0-0) 

`handleRecvError` then only performs a config gate (`acceptRecvErrorConfig`, which defaults to "accept from private or any address" depending on config) and a plain address-equality check against the hostinfo's currently known remote endpoint — never a cryptographic proof of knowledge of the session keys or the peer certificate: [2](#0-1) 

If the addresses match, it unconditionally calls `f.closeTunnel(hostinfo)` and deletes the pending handshake state, exactly the kind of unauthenticated, repeatable, state-mutating action described in the report (an actor with no legitimate standing can invoke a privileged/state-changing operation without any per-use or possession check). There is no per-packet counter, no AEAD tag, and no anti-replay window applied to `RecvError` (that machinery, `ConnectionState.window`/`Bits`, is only used for the encrypted `Message`/`MessageRelay` path, per `connection_state.go`): [3](#0-2) 

Contrast this with `CloseTunnel`, which the e2e suite explicitly proves cannot be forged without valid session state — a bogus, unauthenticated `CloseTunnel` packet is rejected and the tunnel survives: [4](#0-3) 

No equivalent authenticated-path guarantee exists for `RecvError`.

### Impact Explanation
Any attacker who can put a packet on the wire with a source `UDP AddrPort` equal to the real remote endpoint (on-path attacker, or off-path if the network doesn't enforce anti-spoofing / source validation) can force `closeTunnel` on the victim, with zero certificate, zero handshake, and zero session key material. Because the check is a bare equality test and not a token or counter, it can be sent an unbounded number of times, causing the analogous "repeated unguarded privileged action" impact: continual, remote, unauthenticated tunnel teardown / connectivity denial — a remote DoS / state-poisoning primitive that matches the "remote crash impact"/"remote state poisoning" categories.

### Likelihood Explanation
Reachable by exactly the attacker model in scope: no CA-signed certificate is required at all, since `RecvError` bypasses the Noise handshake and AEAD entirely. The only obstacle is knowing/spoofing the victim's UDP source `AddrPort`, which is often observable (lighthouse-advertised, or visible on-path) making this practically exploitable for on-path or same-NAT attackers, and for off-path attackers wherever egress/ingress filtering (BCP38) is not enforced by the network.

### Recommendation
Bind `RecvError` acceptance to authenticated session state instead of a bare source-address string compare: e.g., require a valid, authenticated indicator tied to the current session (such as verifying the packet under the peer's current AEAD key/counter, or requiring a monotonically increasing, per-tunnel single-use nonce that is checked against `ConnectionState.window` like the data-plane path), so that only a party in possession of the actual session keys can trigger `closeTunnel`. At minimum, rate-limit/deduplicate `RecvError`-triggered teardowns per remote index so a spoofed flood cannot repeatedly force disconnects.

### Proof of Concept
1. Establish a legitimate tunnel between `me` and `them` so `hostinfo.GetRemote()` on `me` equals `them`'s real `UdpAddr`.
2. From any host capable of sending a UDP packet with source `AddrPort` equal to `them`'s address (on-path/MITM, or off-path without egress filtering), craft a minimal packet: `header.Encode(buf, header.Version, header.RecvError, 0, hi.RemoteIndex, 0)` where `hi.RemoteIndex` is `me`'s local index for the tunnel with `them` (obtainable, e.g., from any legitimately captured packet header, or by brute-forcing the 32-bit index space, or exploiting the same on-path position used to spoof the address).
3. Send this packet repeatedly to `me`'s listening UDP port with source address spoofed to `them`'s `UdpAddr`.
4. Observe `handleRecvError` passes the `hr != addr` check every time and calls `f.closeTunnel(hostinfo)` plus `handshakeManager.DeleteHostInfo`, tearing the tunnel down on each send — with no cryptographic material and no per-use restriction, unlike the properly-guarded `CloseTunnel` path exercised in `TestCloseTunnelAuthenticated`. func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)

func (cs *ConnectionState) Decrypt(l *slog.Logger, messageCounter uint64, out []byte, packet []byte, nb []byte) ([]byte, error) {
	var err error
	cs.decryptLock.Lock()
	result := cs.window.Check(l, messageCounter)
	cs.decryptLock.Unlock()
	if !result {
		return nil, ErrAlreadySeen
	}

	out, err = cs.dKey.DecryptDanger(out, packet[:header.Len], packet[header.Len:], messageCounter, nb)
	if err != nil {
		return nil, err
	}

	cs.decryptLock.Lock()
	result = cs.window.Update(l, messageCounter)
	cs.decryptLock.Unlock()
	if !result {
		return nil, ErrAlreadySeen
	}
	return out, nil
}
