### No vulnerability found for this question.

The code exactly implements the documented boundary: `verify_intent_nonce` rejects only when `deadline < Timestamp::now()` [1](#0-0) , meaning `deadline == Timestamp::now()` is accepted by design (inclusive lower bound), matching the README's own definition: "the deadline of the intent does not exceed nonce deadline (which cannot be less than the current time)" [2](#0-1) . The same inclusive semantics are used consistently elsewhere, e.g. `ExpirableNonce::has_expired` also uses `deadline < Timestamp::now()` [3](#0-2)  and `garbage_collector::is_nonce_cleanable` uses the same `deadline < Timestamp::now()` check for cleanup eligibility [4](#0-3) . There is no separate "policy" that requires strict `>` — the binding claimed in the question (`deadline >= now()` should be rejected, only `> now()` accepted) does not exist anywhere in the spec or code; the actual and only documented binding is `deadline >= now()` is valid, which is exactly what's implemented.

Existing tests explicitly validate this boundary set (invalid salt, deadline greater than nonce, nonce expired, nonce can be committed) and none assert that `deadline == now()` must fail [5](#0-4) .

Even granting the premise, allowing execution when `deadline == Timestamp::now()` does not cause any fund-moving discrepancy: it does not move, credit, or withdraw tokens without authorization, does not double-settle a payload, does not break invariant zero-net balancing, and does not bypass a lock or fee. It is, at most, an off-by-one interpretation dispute about an inclusive vs exclusive boundary — explicitly called out in the audit rules as excluded ("boundary condition, not fund-moving by itself"), and it doesn't meet any Critical or High impact category (no locked-account bypass, no wallet request forgery, no `simulate_intents`/`execute_intents` divergence). This is intended, documented behavior, not a bug.

    fn verify_intent_nonce(&self, nonce: Nonce, intent_deadline: Timestamp) -> Result<()> {
        let Some(nonce) = VersionedNonce::maybe_from(nonce) else {
            return Ok(());
        };

        match nonce {
            VersionedNonce::V1(SaltedNonce {
                salt,
                nonce: ExpirableNonce { deadline, .. },
            }) => {
                if !self.state.is_valid_salt(salt) {
                    return Err(DefuseError::InvalidSalt);
                }

                if intent_deadline > deadline {
                    return Err(DefuseError::DeadlineGreaterThanNonce);
                }

                if deadline < Timestamp::now() {
                    return Err(DefuseError::NonceExpired);
                }
            }
