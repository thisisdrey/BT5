### Title
QUIC Staked-Peer QoS Classification Not Re-Evaluated for Lifetime of a Connection - ([File: streamer/src/nonblocking/swqos.rs])

### Summary
The external report describes a bug class where a minimum-eligibility check (`min_delegation_amount`) is enforced only once, at the moment of the privileged action, and never re-validated afterward, letting a user withdraw funds immediately after and keep the benefit gained from the one-time check. In agave's QUIC streamer, `ConnectionPeerType` (staked vs. unstaked) and the associated QoS entitlements (extra concurrent uni-streams, higher per-connection stream throttling allowance) are computed exactly once when a connection is accepted, in `SwQos::build_connection_context` [1](#0-0)  and cached for the entire connection lifetime; there is no mechanism that re-checks or downgrades a connection's stake tier while it stays alive.

### Finding Description
`SwQos::build_connection_context` reads the current stake for the peer from `staked_nodes` and decides `ConnectionPeerType::Staked(stake)` vs `Unstaked` a single time, at connection acceptance [2](#0-1) . This `peer_type` is then baked into `SwQosConnectionContext` and used in `cache_new_connection` to compute `max_concurrent_uni_streams` via `compute_max_allowed_uni_streams_with_rtt`, which is set on the QUIC connection once and never updated afterward [3](#0-2) . The per-connection stream throttling budget (`available_load_capacity_in_throttling_duration`) also keys off the same cached `peer_type`/`total_stake` snapshot for the life of the connection [4](#0-3) [5](#0-4) .

Meanwhile, the underlying stake data (`staked_nodes`) is refreshed independently by `StakedNodesUpdaterService` every 5 seconds from the root bank's `current_epoch_staked_nodes()` [6](#0-5) , but that refresh only affects *new* connections' `build_connection_context` calls — it never walks the `ConnectionTable` to reclassify or evict already-`Staked` connections whose backing stake has since dropped below the threshold, been undelegated, or moved to a different node identity. No `reclassify`/`recheck` logic exists in the codebase for this path (confirmed by search).

Because the QUIC connection idle timeout is 30 seconds (`QUIC_MAX_TIMEOUT`) but is refreshed by keep-alive pings sent every second (`QUIC_KEEP_ALIVE`) [7](#0-6) [8](#0-7) , a connection can be kept open indefinitely by the client simply by sending traffic/keep-alives, long past any subsequent stake reduction.

### Impact Explanation
An attacker (any unprivileged user who can temporarily acquire delegated stake, e.g. via a flash-stake/self-stake maneuver or by briefly delegating to their own identity right before an epoch snapshot) can:
1. Obtain enough stake to be classified `ConnectionPeerType::Staked(stake)` with a favorable `stake_ratio` at `build_connection_context` time.
2. Open QUIC connections to a validator's TPU, locking in an elevated `max_concurrent_uni_streams` allotment and a larger per-interval stream-throttling budget for those connections.
3. Immediately reduce/withdraw/deactivate the stake (the classification check is never repeated for already-open connections).
4. Keep the connections alive via keep-alive pings, retaining staked-tier QoS/priority treatment — evicting legitimately staked peers from limited connection-table slots (`max_staked_connections`, pruned via `prune_random`) and consuming a disproportionate share of the QUIC/stream bandwidth that is supposed to be proportionally rationed by real, current stake.

This is a QoS evasion of the stake-weighted resource allocation that agave's TPU streamer relies on to prioritize genuinely staked validators' transaction traffic over unstaked/adversarial traffic, directly mirroring the reported "maintain minimum only momentarily" bypass.

### Likelihood Explanation
Moderate. It requires an attacker to briefly hold delegated stake sufficient to clear the `min_stake_ratio` threshold in `build_connection_context` (`stake_ratio >= 1 / (max_streams_per_ms * STREAM_THROTTLING_INTERVAL_MS)`), open connections, and then reduce stake while keeping connections alive. No validator/operator privilege is needed — any staked identity (even with a small/temporary stake) reachable over the public TPU QUIC endpoint can attempt this, and the mechanics rely purely on timing between the 5-second stake refresh cycle and indefinitely-renewable QUIC keep-alives.

### Recommendation
Periodically re-evaluate `peer_type`/stake for entries already present in the staked `ConnectionTable` (e.g., during `StakedNodesUpdaterService`'s refresh cycle, or via a background sweep over `SwQos`'s connection tables) and downgrade/close/reclassify connections whose backing stake has fallen below the staking threshold, rather than trusting the one-time classification computed at connection acceptance for the full connection lifetime.

### Proof of Concept
Conceptual reproduction (based on code paths, not executed):
1. Delegate stake to a validator identity such that, at the next `StakedNodesUpdaterService` refresh, `get_connection_stake` returns a `stake_ratio` above `min_stake_ratio` in `SwQos::build_connection_context`.
2. Open a QUIC connection to the target validator's TPU during this window; `cache_new_connection` locks in `ConnectionPeerType::Staked(stake)` and a proportionally large `max_concurrent_uni_streams`/throttling budget.
3. Immediately undelegate/withdraw the stake.
4. Keep the connection alive using QUIC keep-alive frames (1s interval, 30s idle timeout) and continue sending streams — `throttle_stream`/`available_load_capacity_in_throttling_duration` continue to use the stale cached `peer_type`/`total_stake`, since no code path re-derives or re-checks classification for an existing connection.

    fn build_connection_context(&self, connection: &Connection) -> SwQosConnectionContext {
        let remote_address = connection.remote_address();
        get_connection_stake(connection, &self.staked_nodes).map_or(
            SwQosConnectionContext {
                peer_type: ConnectionPeerType::Unstaked,
                total_stake: 0,
                remote_pubkey: None,
                in_staked_table: false,
                remote_address,
                stream_counter: None,
                last_update: Arc::new(AtomicU64::new(timing::timestamp())),
            },
            |(pubkey, stake, total_stake)| {
                // The heuristic is that the stake should be large enough to have 1 stream pass through within one throttle
                // interval during which we allow max (MAX_STREAMS_PER_MS * STREAM_THROTTLING_INTERVAL_MS) streams.

                let peer_type = {
                    let max_streams_per_ms = self.staked_stream_load_ema.max_streams_per_ms();
                    let min_stake_ratio =
                        1_f64 / (max_streams_per_ms * STREAM_THROTTLING_INTERVAL_MS) as f64;
                    let stake_ratio = stake as f64 / total_stake as f64;
                    if stake_ratio < min_stake_ratio {
                        // If it is a staked connection with ultra low stake ratio, treat it as unstaked.
                        ConnectionPeerType::Unstaked
                    } else {
                        ConnectionPeerType::Staked(stake)
                    }
                };

                SwQosConnectionContext {
                    peer_type,
                    total_stake,
                    remote_pubkey: Some(pubkey),
                    in_staked_table: false,
                    remote_address,
                    last_update: Arc::new(AtomicU64::new(timing::timestamp())),
                    stream_counter: None,
                }
            },
        )
    }

    pub(crate) fn available_load_capacity_in_throttling_duration(
        &self,
        peer_type: ConnectionPeerType,
        total_stake: u64,
    ) -> u64 {
        match peer_type {
            ConnectionPeerType::Unstaked => self.max_unstaked_load_in_throttling_window,
            ConnectionPeerType::Staked(stake) => {
                if self.staked_throttling_enabled.load(Ordering::Relaxed) {
                    // 1 is added to `max_unstaked_load_in_throttling_window` to guarantee that staked
                    // clients get at least 1 more number of streams than unstaked connections.
                    self.max_staked_load_in_throttling_window
                        .saturating_mul(stake)
                        .checked_div(total_stake)
                        .unwrap_or(self.max_unstaked_load_in_throttling_window + 1)
                        .max(self.max_unstaked_load_in_throttling_window + 1)
                } else {
                    self.max_staked_load_in_throttling_window
                }
            }
        }
    }

const STAKE_REFRESH_CYCLE: Duration = Duration::from_secs(5);

pub struct StakedNodesUpdaterService {
    thread_hdl: JoinHandle<()>,
}

impl StakedNodesUpdaterService {
    pub fn new(
        exit: Arc<AtomicBool>,
        bank_forks: Arc<RwLock<BankForks>>,
        staked_nodes: Arc<RwLock<StakedNodes>>,
        staked_nodes_overrides: Arc<RwLock<HashMap<Pubkey, u64>>>,
    ) -> Self {
        let thread_hdl = Builder::new()
            .name("solStakedNodeUd".to_string())
            .spawn(move || {
                while !exit.load(Ordering::Relaxed) {
                    let stakes = {
                        let root_bank = bank_forks.read().unwrap().root_bank();
                        root_bank.current_epoch_staked_nodes()
                    };
                    let overrides = staked_nodes_overrides.read().unwrap().clone();
                    *staked_nodes.write().unwrap() = StakedNodes::new(stakes, overrides);
                    std::thread::sleep(STAKE_REFRESH_CYCLE);
                }
            })
            .unwrap();

        Self { thread_hdl }
    }
