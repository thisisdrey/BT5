### Title
Old Operator's Pending Commission Shares Charged Commission by New Operator After `switch_operator` — (`aptos-move/framework/aptos-framework/sources/staking_contract.move`)

---

### Summary

After `switch_operator` records old_operator's earned commission in the `distribution_pool`, the staking contract is re-keyed under `new_operator`. When `distribute` is later called, `distribute_internal` passes `operator = new_operator` to `update_distribution_pool`. Because `update_distribution_pool` exempts only the current `operator` argument from commission charges, old_operator's shares are no longer exempt and a portion is transferred to new_operator as "commission on commission."

---

### Finding Description

**Step 1 — `switch_operator` records old_operator's commission**

`switch_operator` first calls `distribute_internal(staker, old_operator, staking_contract)`, which clears any existing distributions. It then calls `request_commission_internal(old_operator, staking_contract)`: [1](#0-0) 

Inside `request_commission_internal`, `add_distribution(old_operator, staking_contract, old_operator, commission_amount)` is called, which calls `update_distribution_pool` with `operator = old_operator` (no-op since pool is empty after the prior distribute), then `buy_in(old_operator, commission_amount)`. The pool now has:
- `total_coins = commission_amount`
- old_operator holds all shares [2](#0-1) 

Then `stake::unlock_with_cap(commission_amount, ...)` moves the commission to `pending_inactive`. Finally, the contract's `commission_percentage` is updated to `new_commission_percentage` and the contract is stored under `new_operator`: [3](#0-2) 

**Step 2 — `distribute` is called after lockup expires**

`distribute(staker, new_operator)` calls `distribute_internal(staker, operator = new_operator, staking_contract)`. The commission (now `inactive`) has earned rewards during the lockup period, so `distribution_amount > commission_amount`. `update_distribution_pool` is called with `operator = new_operator`: [4](#0-3) 

**Step 3 — `update_distribution_pool` charges old_operator**

The exemption check is `if (shareholder != operator)`. With `operator = new_operator`, old_operator is **not** exempt: [5](#0-4) 

The stolen amount is:

```
unpaid_commission = (distribution_amount - commission_amount)
                    * new_commission_percentage / 100
```

Shares worth `unpaid_commission` are transferred from old_operator to new_operator.

---

### Impact Explanation

Old_operator's fully-earned commission is partially stolen by new_operator. The stolen amount equals the rewards that accrued on the pending commission during the lockup period, multiplied by `new_commission_percentage`. For large staking contracts with long lockup periods and high new commission rates, this is a direct, on-chain theft of staking balance from old_operator.

---

### Likelihood Explanation

The staker controls both the timing of `switch_operator` and the choice of `new_operator`. A staker colluding with new_operator (or a staker who is also the new_operator) can reliably trigger this path. No privileged access is required beyond the staker's own signer. The call to `distribute` is permissionless (anyone can call it), so the theft executes automatically once the lockup expires.

---

### Recommendation

In `distribute_internal`, before calling `update_distribution_pool`, iterate over the distribution pool's shareholders and exempt any shareholder whose address appears as a shareholder (i.e., treat every existing shareholder as an operator-equivalent for the purpose of commission exemption). Alternatively, store the `operator` address that was used when shares were originally added to the pool, and use that stored address — not the current contract operator — as the exemption key in `update_distribution_pool`.

fun test_commission_on_commission_theft(
    aptos_framework: &signer,
    staker: &signer,
    old_op: &signer,
    new_op: &signer,
) acquires Store, BeneficiaryForOperator {
    // 1. Setup: create staking contract with old_op at 10% commission
    setup(aptos_framework, staker, old_op, INITIAL_BALANCE);
    create_staking_contract(staker, @0xA, @0xA, INITIAL_BALANCE / 2, 10, b"");

    // 2. Accumulate rewards (fast-forward epochs)
    stake::end_epoch(); // rewards accrue

    // 3. Switch operator to new_op at 10% commission
    //    This calls request_commission_internal(old_op) internally,
    //    recording old_op's commission in distribution_pool
    switch_operator(staker, @0xA, @0xB, 10);

    // 4. Record old_op's expected payout (all shares in pool)
    let expected = staking_contract::pending_attribution_snapshot(
        signer::address_of(staker), @0xB, @0xA
    );

    // 5. More rewards accrue on the pending_inactive commission
    stake::end_epoch();

    // 6. Distribute — now operator=new_op, so old_op is charged commission
    distribute(signer::address_of(staker), @0xB);

    // 7. Assert old_op received less than expected due to new_op's commission theft
    // (check old_op's coin balance vs expected)
    // actual < expected  =>  vulnerability confirmed
}
