### Title
Unauthenticated POST to `/v3/blocks/upload/` triggers identical network-wide block relay as the authenticated `broadcast=1` path - (File: stackslib/src/net/api/postblock_v3.rs)

### Summary
`RPCPostBlockRequestHandler::try_handle_request` decides whether to call `node.set_relay_message(...)` based solely on `data_resp.accepted`, never consulting `self.broadcast`/authentication status. This means a remote, unauthenticated caller who omits `?broadcast=1` and the `authorization` header can still cause the node to relay the posted Nakamoto block to the entire P2P network, exactly as if the privileged/authenticated `broadcast=1` path had been used.

### Finding Description
`try_parse_request` (lines 99-122) computes `authenticated` and `broadcast` flags and only rejects the request outright if `broadcast && !authenticated` (line 120). If `broadcast` is left `false` (the default, unauthenticated case), the request is accepted and parsed normally, storing `self.broadcast = Some(false)` (line 134).

In `try_handle_request` (lines 147-207), the block is passed to `Relayer::process_new_nakamoto_block_ext` with `self.broadcast.unwrap_or(false)` as an argument (line 172), but the *only* code that gates the network relay is:

```rust
// should set to relay...
if data_resp.accepted {
    node.set_relay_message(StacksMessageType::NakamotoBlocks(NakamotoBlocksData {
        blocks: vec![block],
    }));
}
``` [1](#0-0) 

This check depends exclusively on `data_resp.accepted` (i.e., whether the local chainstate accepted the block), and does not re-check `self.broadcast` or `authenticated`. Consequently, whether the request came from `StacksHttpRequest::new_post_block_v3` (unauthenticated, `broadcast=false`) at line 224 or `new_post_block_v3_broadcast` (authenticated, `broadcast=1`) at line 235, the exact same `set_relay_message` call fires as long as the block is accepted by `process_new_nakamoto_block_ext`. The `broadcast`/`authorization` parameters therefore only gate whether the *request itself* is rejected with 401 when `broadcast=1` is requested without auth - they do not gate the actual network-relay side effect for the default (unauthenticated, `broadcast=false`) path. [2](#0-1) [3](#0-2) 

### Impact Explanation
Any remote party able to reach the node's RPC port can submit a validly-formed Nakamoto block without providing the RPC secret and without requesting `broadcast=1`, and — provided the block is accepted by local validation logic in `process_new_nakamoto_block_ext` — the node will still set it as the outbound relay message, causing it to be gossiped to every connected peer. This defeats the intended purpose of the `broadcast`/`authorization` gate, which is meant to restrict who can compel a node to disseminate a block to the wider network via this RPC endpoint.

### Likelihood Explanation
- The endpoint is reachable by any unprivileged remote peer with network access to the RPC port (no secret, no special role required).
- The only precondition is that the submitted block passes `process_new_nakamoto_block_ext`'s local acceptance logic (this still requires the block to satisfy consensus validation rules such as signer-set signatures, so an attacker cannot inject a wholly fabricated/invalid block, but *can* force relay of any block they already possess that the node has not yet seen via normal p2p).
- Attack cost is a single HTTP POST with a valid Nakamoto block; it is trivially repeatable for every distinct accepted block.

### Recommendation
Gate the `node.set_relay_message(...)` call on `self.broadcast == Some(true)` (and therefore `authenticated`) in addition to `data_resp.accepted`, so unauthenticated/non-broadcast submissions are only locally accepted/staged and never trigger outbound P2P relay:
```rust
if data_resp.accepted && self.broadcast.unwrap_or(false) {
    node.set_relay_message(...);
}
```

impl StacksHttpRequest {
    /// Make a new post-block request
    pub fn new_post_block_v3(host: PeerHost, block: &NakamotoBlock) -> StacksHttpRequest {
        StacksHttpRequest::new_for_peer(
            host,
            "POST".into(),
            PATH.into(),
            HttpRequestContents::new().payload_stacks(block),
        )
        .expect("FATAL: failed to construct request from infallible data")
    }

    /// Make a new post-block request, with intent to broadcast
    pub fn new_post_block_v3_broadcast(
        host: PeerHost,
        block: &NakamotoBlock,
        auth: &str,
    ) -> StacksHttpRequest {
        let mut request = StacksHttpRequest::new_for_peer(
            host,
            "POST".into(),
            PATH.into(),
            HttpRequestContents::new()
                .query_arg("broadcast".into(), "1".into())
                .payload_stacks(block),
        )
        .expect("FATAL: failed to construct request from infallible data");
        request.add_header("authorization".into(), auth.into());
        request
    }
