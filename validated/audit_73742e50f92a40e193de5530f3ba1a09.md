### Title
Insecure default `listen.accept_recv_error = always` permits unauthenticated remote tunnel teardown - ([File: interface.go])

### Summary
Nebula's `RecvError` message type (`header.RecvError`) is processed in plaintext, with no cryptographic authentication, before any handshake/certificate state is consulted. Whether these packets are honored is governed by `listen.accept_recv_error`, which defaults to `"always"` [1](#0-0) . This mirrors the "rollable by default" pattern in the external report: a security-relevant behavior (tearing down an active, authenticated tunnel) is enabled out-of-the-box, and the operator must actively opt out (set it to `never`/`private`) to get the safer behavior, rather than the safer behavior being the default that must be explicitly relaxed.

### Finding Description
`RecvError` packets are dispatched straight out of header parsing, ahead of any tunnel/cert lookup:
```go
case header.RecvError:
    f.handleRecvError(via.UdpAddr, h)
    return
``` [2](#0-1) 

`handleRecvError` gates on `f.acceptRecvErrorConfig.ShouldRecvError(addr)`, and with the default `recvErrorAlways` this check always passes:

	case recvErrorPrivate:
		return endpoint.Addr().IsPrivate()
	case recvErrorAlways:
		return true

Once accepted, the handler looks up the hostinfo purely by the 32-bit `RemoteIndex` carried in the cleartext header and, if the source address happens to match the currently-cached remote for that hostinfo, tears the tunnel down:
```go
hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
...
hr := hostinfo.GetRemote()
if hr.IsValid() && hr != addr {
    f.l.Info("Someone spoofing recv_errors?", ...)
    return
}
f.closeTunnel(hostinfo)
f.handshakeManager.DeleteHostInfo(hostinfo)
``` [4](#0-3) 

The `RemoteIndex` field is transmitted unencrypted in every packet's header (`Version|Type|Subtype|Reserved|RemoteIndex|MessageCounter`), so it is directly observable to anyone who can see traffic on the wire:
```go
type H struct {
	Version        uint8
	Type           MessageType
	Subtype        MessageSubType
	Reserved       uint16
	RemoteIndex    uint32
	MessageCounter uint64
}
``` [5](#0-4) 

The only barrier to a forged `RecvError` succeeding is that the source `netip.AddrPort` of the spoofed UDP packet must match `hostinfo.GetRemote()`. This is a source-address check, not a cryptographic one — it does not require possession of any CA-signed certificate or any handshake material. An attacker anywhere on-path (or capable of UDP source spoofing toward the target, which is common for UDP) who observes a single legitimate packet from a tunnel peer learns both the victim's peer address and the `RemoteIndex`, and can forge a 16-byte `RecvError` packet that satisfies both checks, causing the victim to unilaterally tear down and re-handshake an active, authenticated tunnel.

This is directly analogous to the cited bug class: a security-sensitive default (`rollable = true` for loans; `accept_recv_error = always` here) grants an unauthenticated party (a would-be "roller"/attacker) capability by default, and the safer posture (`rollable = false` / `accept_recv_error = never` or `private`) requires the defender to explicitly opt in.

### Impact Explanation
An unauthenticated, unprivileged network attacker who can observe (or spoof from) a peer's UDP flow can force repeated tunnel teardowns on any Nebula node running with the default configuration, without holding any CA-signed certificate. This is a remote state-poisoning / denial-of-service primitive: it collapses established Noise sessions on demand, forces repeated re-handshakes, and can be used to disrupt availability or as a primitive to influence handshake timing/race conditions elsewhere in the handshake manager. Because the default is "always" rather than "never" or "private", every fresh Nebula deployment is exposed until an operator explicitly hardens this setting.

### Likelihood Explanation
Likelihood is moderate-to-high in adversarial network environments: the `RemoteIndex` is sent in cleartext on every packet, so any passive observer of a single peer packet (e.g., a shared network segment, an ISP-level observer, or another compromised host in the same broadcast domain) obtains everything needed to forge the packet. The remaining requirement — matching source `AddrPort` — is trivially satisfiable via UDP source spoofing in networks that don't enforce BCP38/ingress filtering, or automatically satisfied for any on-path attacker. Since the default value ships as `"always"`, this is exploitable out-of-the-box without any operator misconfiguration.

### Recommendation
Change the default of `listen.accept_recv_error` (and ideally `listen.send_recv_error`, which controls the same class of unauthenticated signal) from `"always"` to a safer default such as `"never"` or `"private"`, requiring operators to explicitly opt in to accepting unauthenticated `RecvError` signals from public endpoints — mirroring the sponsor's fix of defaulting `rollable` to `false` in the referenced report. At minimum, document the security tradeoff clearly and consider adding a lightweight proof-of-knowledge (e.g., tying `RecvError` acceptance to the current message counter window, similar to the existing "disable sending recv_error outside the allowable counter window" mitigation already applied to the send side) before trusting the tear-down action.

### Proof of Concept
1. Node A and Node B complete a Nebula handshake; Node A's tunnel to B is identified locally by `RemoteIndex` = X (visible in the cleartext header of any Message packet A sends to B).
2. An attacker positioned to observe traffic between A and B (or capable of spoofing UDP source `AddrPort` of B) crafts a 16-byte header: `Version=1, Type=RecvError(2), Subtype=0, Reserved=0, RemoteIndex=X, MessageCounter=0`, using `header.Encode(...)`.
3. Attacker sends this packet, spoofing the source address to match B's known address, to A's UDP listener.
4. On A (default config, `listen.accept_recv_error` unset ⇒ `"always"`), `readOutsidePackets` routes it to `handleRecvError`, which passes the `ShouldRecvError` check unconditionally, finds the hostinfo via `QueryReverseIndex(X)`, confirms the (spoofed) source matches `hostinfo.GetRemote()`, and calls `f.closeTunnel(hostinfo)` plus `DeleteHostInfo`, tearing down the legitimate tunnel between A and B without either party's cryptographic material ever being touched.

				f.acceptRecvErrorConfig = recvErrorAlways

			}

func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
```
