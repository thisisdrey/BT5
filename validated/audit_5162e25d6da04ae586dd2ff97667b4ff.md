The `new` function referenced in `libstackerdb/src/libstackerdb.rs` is `StackerDBChunkData::new(slot_id: u32, slot_version: u32, data: Vec<u8>)`, which simply constructs a struct from already-parsed Rust values — it performs no byte-level parsing, no length field reads, and no buffer indexing at all. [1](#0-0) 

The actual wire deserialization path is `StackerDBChunkData::consensus_deserialize`, which reads fixed-size fields (`slot_id: u32`, `slot_version: u32`, `sig: MessageSignature`) via `read_next`, and reads the variable-length `data` via `read_next_at_most(fd, STACKERDB_MAX_CHUNK_SIZE)`, which caps the chunk size at 16 MB and returns a `CodecError` rather than performing any unchecked/out-of-bounds read if the declared length is invalid or exceeds the cap. [2](#0-1) 

There is no code path in this file where an attacker-controlled length field is used to index or slice a buffer without a prior bounds check — the only place data length appears is bounded by `read_next_at_most`'s cap enforcement, and `new` itself never touches raw bytes. [3](#0-2)

        let slot_id: u32 = read_next(fd)?;
        let slot_version: u32 = read_next(fd)?;
