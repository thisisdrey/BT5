### Title
Contract-loading CPU cost (deserialize/link/instantiate_pre) is fully consumed before the loading fee is charged, enabling near-free CPU-cost extraction via undersized `prepaid_gas` - ([File: runtime/near-vm-runner/src/wasmtime_runner/mod.rs])

### Summary
`WasmtimeVM::with_compiled_and_loaded` performs the full module `deserialize`, memory-export resolution, `Linker::link`, and `instantiate_pre` before the contract-loading gas fee is ever charged, because on stable (protocol version 86) `fix_contract_loading_cost` is `false` and the fee is only applied post-load via `after_loading_executable`. An attacker can send a `FunctionCall` with `prepaid_gas` just above the base action-dispatch fees but below `contract_loading_base + contract_loading_bytes * code_len` against an already-cached large contract, forcing the runtime to do the full loading CPU work and then abort on `GasExceeded`, paying only the minimal send/base fee.

### Finding Description
`WasmtimeVM::with_compiled_and_loaded` resolves the cached artifact and unconditionally runs `Module::deserialize`, resolves the `memory` export, builds a `Linker`, calls `link`, and calls `instantiate_pre` [1](#0-0) . Only after all of that work completes does the code call `gas_counter.before_loading_executable` and then, on the success path, `gas_counter.after_loading_executable` [2](#0-1) .

`before_loading_executable` only pre-charges the loading fee if `config.fix_contract_loading_cost` is set; otherwise it is a no-op besides the empty-method-name check. `after_loading_executable` charges the fee only when `fix_contract_loading_cost` is *not* set — i.e., the legacy/stable ordering [3](#0-2) . Per the component spec, on the current stable protocol version, `fix_contract_loading_cost` is `false` (the fix is nightly-only, gated behind protocol version 129), so the loading fee is charged strictly after the deserialize/link/instantiate work has already executed.

An attacker-controlled `FunctionCall.gas` value flows directly into `prepaid_gas` for the receipt with no minimum-gas check tying it to the eventual contract-loading cost: transaction validation only checks `total_prepaid_gas <= max_total_prepaid_gas` [4](#0-3) , and `tx_cost`/`verify_and_charge_tx_ephemeral` only require the account to afford `total_cost` (send/exec fees + the attacker's chosen `prepaid_gas`) [5](#0-4) [6](#0-5) . Nothing requires `prepaid_gas` to be large enough to cover `contract_loading_base + contract_loading_bytes * code_len` for the target contract.

Thus an attacker can: (1) deploy or reuse a large wasm contract so its compiled artifact becomes cached (in-memory `AnyCache` and/or on-disk cache) [7](#0-6) ; (2) submit a `FunctionCall` action against it with `gas` set just above `new_action_receipt` + `function_call_base` send/exec fees but below the loading fee for that contract's size; (3) the runtime executes the receipt, runs the full `with_compiled_and_loaded` path (real deserialize/link/instantiate_pre CPU work on the cached large module), then hits `after_loading_executable`'s `add_contract_loading_fee` call, which fails with `GasExceeded`, producing `PreparationResult::OutcomeAbort` and a committed abort outcome burning only the small amount of gas already spent on action dispatch — not the CPU actually consumed.

### Impact Explanation
This is a METERING_TOTALITY violation: real CPU work (module deserialization, symbol/memory-export resolution, host-function linking, `instantiate_pre`) is performed for cached artifacts before the corresponding gas fee is charged or even reserved. This lets an unprivileged attacker repeatedly extract expensive block-apply CPU time from chunk producers while paying only the minimal base action-dispatch fee, causing a disproportionate CPU-vs-gas-burnt ratio during chunk application. Repeated at scale (many receipts per chunk, each targeting large cached contracts), this is a resource-exhaustion/DoS vector against chunk production, since the gas actually burnt per receipt (and hence the implicit throttling via the chunk gas limit) massively understates the CPU actually consumed.

### Likelihood Explanation
- Preconditions: the target contract's compiled artifact must already be cached (attacker can deploy their own large contract and warm the cache with one prior call), which is trivial and cheap for an ordinary funded account to arrange.
- Cost to attacker: only the small `new_action_receipt` + `function_call_base` send/exec fee per malicious receipt, since the actual heavy fee is never successfully charged (the receipt aborts with `GasExceeded` before or right at the fee-charging point).
- Feasibility/repeatability: fully repeatable — this is a straightforward wasm call with attacker-chosen `gas`, requiring only knowledge of the target contract's size (which is public) and current `wasm_contract_loading_base`/`wasm_contract_loading_bytes` parameters (public config) to pick a `prepaid_gas` value in the exploitable window.

### Recommendation
Charge (or reserve) the contract-loading fee based on the known/cached `wasm_bytes` size *before* performing `Module::deserialize`, `link`, and `instantiate_pre`, rather than after. This is effectively what `fix_contract_loading_cost` already implements in `before_loading_executable`; that behavior should be made unconditional (or activated) on the currently active protocol version rather than gated behind an as-yet-inactive nightly-only protocol feature.

### Proof of Concept
Integration test in `runtime/near-vm-runner/src/tests/` (or `runtime/runtime/tests/`, following the pattern of `test_max_core_instance_size_breached` in `runtime/near-vm-runner/src/tests/runtime_errors.rs:29-93`):
1. Deploy/prepare a large wasm contract (e.g., via `near_test_contracts::contract_with_many_methods`/similar) and ensure it is compiled and cached (call `precompile`/`compile_and_cache` or run once beforehand so the artifact sits in the in-memory/on-disk cache).
2. Compute `loading_fee = contract_loading_base + contract_loading_bytes * code_len` from the active `Config`'s `ExtCostsConfig`.
3. Construct a `VMContext`/`GasCounter` with `prepaid_gas` set to `new_action_receipt_fee + function_call_base_fee + 1` (i.e., just above the minimal dispatch cost, but strictly less than `loading_fee`).
4. Call `WasmtimeVM::prepare(...).run(...)` (with `fix_contract_loading_cost = false`, matching stable config) and assert:
   - `outcome.aborted` is `Some(FunctionCallError::HostError(HostError::GasExceeded))`.
   - `outcome.used_gas` (or `burnt_gas`) is far smaller than `loading_fee`.
   - Instrument/measure (via `tracing`/instant timers around `with_compiled_and_loaded`, or an instruction/wall-clock counter) that `deserialize` + `link` + `instantiate_pre` executed to completion despite the abort, demonstrating disproportionate real CPU work relative to `burnt_gas`.

    /// VM independent setup before loading the executable.
    ///
    /// Does VM independent checks that happen after the instantiation of
    /// VMLogic but before loading the executable. This includes pre-charging gas
    /// costs for loading the executable, which depends on the size of the WASM code.
    #[cfg(feature = "wasmtime_vm")]
    pub(crate) fn before_loading_executable(
        &mut self,
        config: &near_parameters::vm::Config,
        method_name: &str,
        wasm_code_bytes: u64,
    ) -> std::result::Result<(), super::errors::FunctionCallError> {
        if method_name.is_empty() {
            let error = super::errors::FunctionCallError::MethodResolveError(
                super::errors::MethodResolveError::MethodEmptyName,
            );
            return Err(error);
        }
        if config.fix_contract_loading_cost {
            if self.add_contract_loading_fee(wasm_code_bytes).is_err() {
                let error =
                    super::errors::FunctionCallError::HostError(super::HostError::GasExceeded);
                return Err(error);
            }
        }
        Ok(())
    }

    /// Legacy code to preserve old gas charging behaviour in old protocol versions.
    #[cfg(feature = "wasmtime_vm")]
    pub(crate) fn after_loading_executable(
        &mut self,
        config: &near_parameters::vm::Config,
        wasm_code_bytes: u64,
    ) -> std::result::Result<(), super::errors::FunctionCallError> {
        if !config.fix_contract_loading_cost {
            if self.add_contract_loading_fee(wasm_code_bytes).is_err() {
                return Err(super::errors::FunctionCallError::HostError(
                    super::HostError::GasExceeded,
                ));
            }
        }
        Ok(())
    }
