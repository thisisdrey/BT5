### Title
Closing or fully withdrawing a Balance forfeits `emissions_outstanding` without settlement - (File: `programs/marginfi/src/state/marginfi_account.rs`)

### Summary
When a user fully exits a position via `lending_account_withdraw` (with `withdraw_all = true`) or `lending_account_close_balance`, the underlying `BankAccountWrapper::withdraw_all` and `BankAccountWrapper::close_balance` routines close/free the `Balance` slot without settling or paying out the `emissions_outstanding` field tracked on that balance. This mirrors the reported bug class in the Infrared report: an "exit" style instruction that is supposed to fully return a user's holdings but silently leaves reward value stranded/unaccounted for, because the exit path does not treat outstanding rewards as part of what must be resolved before the position is closed.

### Finding Description
Each `Balance` slot tracks unclaimed emissions in a dedicated field: [1](#0-0) 

`withdraw_all`, used by `lending_account_withdraw` when `withdraw_all=true`, only checks/zeroes asset and liability shares before calling `balance.close()` — it never reads or settles `emissions_outstanding`: [2](#0-1) 

Similarly, `close_balance` (invoked by the standalone `lending_account_close_balance` instruction, used to remove dust/zero-share balances so a new position can be opened) only validates that liability and asset amounts are zero-with-tolerance, then calls `balance.close()` — again with no reference to `emissions_outstanding`: [3](#0-2) 

The instruction wrapper for close balance likewise performs no emissions check: [4](#0-3) 

Notably, the program defines a dedicated error specifically intended to guard against this scenario: [5](#0-4) 

However, `CannotCloseOutstandingEmissions` is never referenced by any instruction handler in the current codebase (only its definition and error-code mapping exist) — a `grep_search` across the repo found it solely in `errors.rs` and a generic test-utility error-name table, with no call site in `close_balance.rs`, `withdraw.rs`, or `marginfi_account.rs`. This strongly suggests the check that used to gate closing a balance with outstanding emissions has been dropped or was never wired into the current withdraw-all/close-balance code paths, leaving `emissions_outstanding` unprotected.

Because `withdraw_all` internally calls `balance.close()` and this instruction is the *only* mechanism to remove a Balance slot (per the integrator docs: "Set `withdraw_all` to true to ignore your amount input... This is the only way to close a Balance so it no longer appears on your Account"), a user who withdraws their full principal position also permanently frees the slot, and any `emissions_outstanding` value recorded there is not paid out and is effectively wiped when the slot is reused for a future position (slots are reused/zeroed for new balances, as implied by the `Balance.active` state machine).

### Impact Explanation
Any unclaimed/outstanding emissions reward that has accrued but not yet been airdropped to the user (per the emissions/incentives model described in the docs) is forfeited the moment the user performs the standard, unprivileged "exit" flow (`lending_account_withdraw` with `withdraw_all=true`, or `lending_account_close_balance`). This is a permanent loss of user-owned reward value with no recovery path, analogous to the referenced report where an `exit()` call does not fully account for reward state, though here the effect is worse (loss) rather than an inadvertent re-stake. This qualifies as unauthorized/undesired state change causing token/value loss for an ordinary user acting entirely within intended, unprivileged flows.

### Likelihood Explanation
Likelihood is high in ordinary usage: any depositor in a bank running an emissions/incentive campaign (per `guides/USER/EMISSIONS.md`) who fully withdraws or closes a dust balance before the weekly emissions airdrop is processed will trigger this. No privileged access or unusual conditions are required — a normal user calling the documented "withdraw all" flow suffices.

### Recommendation
Before allowing `balance.close()` inside both `withdraw_all` and `close_balance`, settle any nonzero `emissions_outstanding` (e.g., transfer it to the user or roll it into a "pending emissions" account-level accumulator) or explicitly re-introduce a check equivalent to `CannotCloseOutstandingEmissions` that blocks closing the balance until emissions are zero or have been flushed/paid. Wire this error back into `lending_account_close_balance` and the `withdraw_all` path in `BankAccountWrapper`, and add a regression test asserting that a balance with nonzero `emissions_outstanding` cannot be silently closed.

### Proof of Concept
Conceptual reproduction (cannot execute in ask-only mode, but derivable directly from code paths cited above):
1. Group admin sets up an emissions/incentive campaign on a bank (`lending_pool_configure_bank` w/ emissions params, as described in `guides/USER/EMISSIONS.md`).
2. User deposits into that bank; emissions accrue over time into `Balance.emissions_outstanding` (via `update_emissions`, referenced in `programs/marginfi/src/state/marginfi_account.rs`) but have not yet been airdropped.
3. Before the weekly emissions distribution/airdrop occurs, the user calls `lending_account_withdraw` with `withdraw_all = true` for that bank.
4. `BankAccountWrapper::withdraw_all` (`programs/marginfi/src/state/marginfi_account.rs:1623-1656`) validates only asset/liability shares and calls `balance.close()`; `emissions_outstanding` is never read, paid, or migrated.
5. The Balance slot becomes inactive/reusable; the previously accrued `emissions_outstanding` value is lost with no user-facing balance or event reflecting it, and no error (`CannotCloseOutstandingEmissions`) is raised to prevent the action.

pub fn lending_account_close_balance(ctx: Context<LendingAccountCloseBalance>) -> MarginfiResult {
    let LendingAccountCloseBalance {
        marginfi_account,
        bank: bank_loader,
        group: marginfi_group_loader,
        ..
    } = ctx.accounts;

    let mut marginfi_account = marginfi_account.load_mut()?;
    let mut bank = bank_loader.load_mut()?;

    check!(
        !marginfi_account.get_flag(ACCOUNT_DISABLED),
        MarginfiError::AccountDisabled
    );

    let group = &*marginfi_group_loader.load()?;
    bank.accrue_interest(
        Clock::get()?.unix_timestamp,
        group,
        #[cfg(not(feature = "client"))]
        bank_loader.key(),
    )?;

    bank.update_bank_cache(group)?;

    let in_receivership = marginfi_account.get_flag(ACCOUNT_IN_RECEIVERSHIP);
    let lending_account: &mut marginfi_type_crate::types::LendingAccount =
        &mut marginfi_account.lending_account;
    let mut bank_account =
        BankAccountWrapper::find(&bank_loader.key(), &mut bank, lending_account)?;

    bank_account.close_balance(in_receivership)?;
    lending_account.sort_balances();
    marginfi_account.sync_indexer_flags();
    marginfi_account.last_update = Clock::get()?.unix_timestamp as u64;

    Ok(())
}
