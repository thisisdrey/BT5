### Title
Unstaked attacker can exhaust the global handshake-admission budget via never-completing QUIC connections, starving all staked and unstaked peers - ([File: streamer/src/nonblocking/quic.rs])

### Summary
`ClientConnectionTracker::new` checks a single global atomic counter (`StreamerStats::open_connections`) against `qos.max_concurrent_connections()`, which for `SwQos` is `(max_staked_connections + max_unstaked_connections) * 5 / 4` — a shared headroom budget meant to absorb in-flight handshakes for *both* staked and unstaked peers. Because this counter is incremented the moment a raw incoming connection passes the coarse rate limiters (before TLS handshake / peer-stake verification), a single unstaked attacker who opens many QUIC connections and simply never completes the handshake can hold the tracker slots open and drive `open_connections` up to the limit, after which `incoming.refuse()` fires for every subsequent connection attempt from any peer, staked or not.

### Finding Description
In `run_server` (`streamer/src/nonblocking/quic.rs`), each accepted `incoming` connection goes through two coarse checks — the global `overall_connection_rate_limiter` and the per-IP `rate_limiter.is_allowed()` — and then: [1](#0-0) 
`ClientConnectionTracker::new` is called with `qos.max_concurrent_connections()` as the shared limit, before the connection has completed its TLS handshake or been attributed to a specific pubkey/stake: [2](#0-1) 
The tracker only decrements `open_connections` in its `Drop` impl, i.e. when the connection is later closed/removed — not when the handshake times out on its own, and no code path here enforces a handshake deadline before the tracker is created: [3](#0-2) 

Critically, `qos.max_concurrent_connections()` for the production `SwQos` implementation is defined as a single global number covering both staked and unstaked peers, not scoped per source IP or per peer type: [4](#0-3) 

The per-IP `ConnectionRateLimiter` (`rate_limiter.is_allowed`) checked earlier in the loop does not close this window: it only depletes tokens for an IP once `register_connection` has been invoked, and per its own doc comment that only happens after "source IP is verified" (i.e., after the handshake completes and identity is established): [5](#0-4) 
`is_allowed` returns `true` for any IP with no prior recorded (confirmed) connection, so an attacker who never completes a handshake never triggers per-IP throttling on that basis, leaving only the coarse, rate-based (not concurrency-based) `overall_connection_rate_limiter` as the sole global gate before the shared `open_connections` counter is consumed.

Because `try_add_connection` (per-IP/per-peer connection-table caps and staked/unstaked partitioning in `SwQos::try_add_connection`) only runs *after* the handshake succeeds and `ClientConnectionTracker` already reserved a global slot, none of the per-peer-type caps in `swqos.rs` protect the pre-handshake admission budget: [6](#0-5) 

### Impact Explanation
This is a QoS-bypass / connection-admission DoS: a single unstaked, unprivileged client can consume the entire shared `(max_staked_connections + max_unstaked_connections) * 5/4` in-flight-handshake budget by holding open (or continuously refreshing) enough non-completing QUIC connections, causing `stats.refused_connections_too_many_open_connections` to increment and `incoming.refuse()` to be issued for every subsequent connection attempt — including from legitimate staked validators/leaders trying to submit transactions over TPU/QUIC. This matches the "QoS evasion / total TPU connection admission DoS from a single unstaked attacker" bounty category, since the invariant that per-source accounting should bound one source's consumption of the shared handshake budget does not hold — the budget accounting is fully global, not per-IP.

### Likelihood Explanation
Preconditions are minimal and match the stated attacker model exactly: an unstaked remote client can open raw QUIC connections to the public TPU QUIC port and simply not respond to/complete the TLS handshake before the connection is naturally torn down. No stake, peer identity, or special privileges are required. The attack is repeatable and sustainable as long as the attacker maintains enough concurrently pending (or serially refreshed, subject to the coarse global rate limiter) connections to occupy the shared budget; since per-IP throttling never engages for non-completed handshakes, the attacker is bounded largely by local socket/file-descriptor resources, not by the server-side defenses.

### Recommendation
Scope the pre-handshake admission budget per source IP (or per source-IP hash bucket) in addition to the existing global cap, so a single IP cannot consume more than a small fraction of `max_concurrent_connections()`. Alternatively, apply `rate_limiter`-style accounting (token consumption) at `ClientConnectionTracker::new` time — before handshake completion — rather than only after IP verification, and/or enforce a bounded handshake completion deadline tied to the tracker's lifetime so slots are reclaimed promptly regardless of attacker behavior.

### Proof of Concept
Integration test plan (in `streamer/src/nonblocking/quic.rs` test module, using `setup_quic_server`/`make_client_endpoint` helpers already present in the test suite):
1. Spawn a QUIC server with `SwQosConfig::default()` (or small `max_staked_connections`/`max_unstaked_connections` for a fast test) to compute `budget = (max_staked + max_unstaked) * 5/4`.
2. From a single test-controlled client "attacker" process, open `budget` raw QUIC connections to the server address but abort each `Connecting` future immediately after `client_connection.into()`/before completing the TLS handshake (e.g., drop the socket immediately after sending the initial packet, or use a raw UDP socket sending only an Initial packet and then going silent).
3. Assert `stats.open_connections.load(Ordering::Relaxed) >= budget` and that `stats.refused_connections_too_many_open_connections.load(Ordering::Relaxed) > 0`.
4. Then, using `make_client_endpoint` with a valid staked keypair/context, attempt a normal legitimate connection and assert it is refused (`ConnectionError`/refused, not accepted), demonstrating the shared budget starves legitimate staked traffic.
5. Vary step 2 to originate all "attacker" connections from a single source IP, confirming `ConnectionRateLimiter::is_allowed` does not block them (since `register_connection` is never called for uncompleted handshakes), proving the capacity is global rather than per-IP scoped.

impl ClientConnectionTracker {
    /// Check the max_concurrent_connections limit and if it is within the limit
    /// create ClientConnectionTracker and increment open connection count. Otherwise returns Err
    fn new(stats: Arc<StreamerStats>, max_concurrent_connections: usize) -> Result<Self, ()> {
        let open_connections = stats.open_connections.fetch_add(1, Ordering::Relaxed);
        if open_connections >= max_concurrent_connections {
            stats.open_connections.fetch_sub(1, Ordering::Relaxed);
            debug!(
                "There are too many concurrent connections opened already: open: \
                 {open_connections}, max: {max_concurrent_connections}"
            );
            return Err(());
        }

        Ok(Self { stats })
    }
}

    /// Check if the connection from the said `ip` is allowed.
    /// Here we assume that only IPs with actual confirmed connections are stored in it,
    /// since we should only modify server state once source IP is verified
    pub fn is_allowed(&self, ip: &IpAddr) -> bool {
        // Check if we have records in the rate limiter for the given IP address
        match self.limiter.current_tokens(ip) {
            Some(r) => r > 0, // we have a record, and rate is not exceeded
            None => true,     // if we have not seen IP, allow connection request
        }
    }

    pub fn register_connection(&self, ip: &IpAddr) -> bool {
        if self.limiter.consume_tokens(*ip, 1).is_ok() {
            debug!("Request from IP {ip:?} allowed");
            true // Request allowed
        } else {
            debug!("Request from IP {ip:?} blocked");
            false // Request blocked
        }
    }
