### Title
Unauthenticated RecvError packets allow remote tunnel-state poisoning / forced re-handshake via spoofable source-address check - (File: `outside.go`)

### Summary
`handleRecvError()` is reachable directly from `readOutsidePackets()` for any inbound UDP packet with `header.Type == header.RecvError`, before any certificate, Noise handshake, or AEAD authentication has occurred for that packet. The only gate against a forged sender is comparing the packet's plaintext source `netip.AddrPort` against `hostinfo.GetRemote()`, which is exactly the kind of "check an address, not a proven identity" mistake the external report flags in `onOwnershipTransferred()` (which trusted the caller identity without verifying it was the legitimate owner or that the operation hadn't already been performed by someone else).

### Finding Description
`readOutsidePackets()` dispatches unencrypted `header.RecvError` packets straight to `f.handleRecvError(via.UdpAddr, h)`: [1](#0-0) 

`handleRecvError()` itself: [2](#0-1) 

The function:
1. Looks up an existing, already-authenticated `HostInfo` purely by the attacker-supplied `h.RemoteIndex` (a 32-bit value carried in cleartext) via `QueryReverseIndex`.
2. Its only anti-spoofing check is `hr := hostinfo.GetRemote(); if hr.IsValid() && hr != addr { ... return }` — i.e., it trusts the UDP packet's source address/port to represent the peer, which is exactly the "identity is asserted by the caller, not cryptographically proven" pattern from the report. UDP source addresses are trivially spoofable on many networks, and even without spoofing, on-path or NAT-adjacent attackers can match the 4-tuple.
3. If the (guessable/observable) `RemoteIndex` and source address line up, `f.closeTunnel(hostinfo)` and `f.handshakeManager.DeleteHostInfo(hostinfo)` are called — destroying already-established, authenticated tunnel state belonging to two legitimately-certified peers, triggered by a party that has never presented or had verified any certificate for this exchange.

This is analogous to the report's core flaw: a function meant to be driven only by a trusted, already-verified party (`onOwnershipTransferred` should only be actionable by the actual current pair owner) is instead reachable by anyone who can call it, gated by an insufficient identity check (missing "check `address(this)` is the owner" / missing "already used" check) — here, gated only by matching a spoofable UDP source tuple rather than any cryptographic proof of identity.

### Impact Explanation
An attacker with no valid certificate for the network can force termination of an established, authenticated tunnel between two legitimate peers by sending a single unauthenticated UDP packet (`header.RecvError`) with a guessed/observed `RemoteIndex` and a spoofed source address matching the victim's currently known remote. This is a remote state-poisoning / denial-of-service primitive against the hostmap and forces the two peers to re-handshake, which both disrupts traffic and increases the window during which fresh (potentially foot-in-the-door) handshakes/routing decisions occur. It does not require possession of any CA-signed certificate.

### Likelihood Explanation
`RemoteIndex` values are 32-bit but transmitted in cleartext on every packet for a tunnel, so an on-path or off-path attacker who can observe a small number of packets (or who is co-located on a NAT, or who can brute force / partially observe indices) can learn or guess a valid `RemoteIndex`. Combined with UDP source-address spoofing (feasible on many transport paths since nebula runs over unauthenticated UDP), the attack requires no cryptographic material and only one crafted 16-byte packet, making likelihood non-trivial, though it is bounded by `acceptRecvErrorConfig.ShouldRecvError` rate/CIDR gating and the need for either address spoofing or a matching real UDP tuple.

### Recommendation
1. Do not act on `RecvError` (or any pre-authentication control message) using only a plaintext source-address match; require that recv-error handling be corroborated by something the peer could only produce if it holds the negotiated session keys (e.g., only accept `RecvError`-driven teardown after failing a subsequent liveness/HMAC-authenticated test packet), or authenticate `RecvError` itself.
2. Tighten `handleRecvError` so a mismatch is not silently ignored only for the "spoofing" log — consider requiring multiple corroborating unauthenticated signals before tearing down state, and rate-limit/backoff per source aggressively regardless of `acceptRecvErrorConfig`.
3. Ensure `DeleteHostInfo`/`closeTunnel` triggered from unauthenticated code paths cannot be used to force expensive re-handshakes at attacker-chosen times (rate limit teardown-by-RecvError separately from general RecvError acceptance).

### Proof of Concept
1. Establish a legitimate authenticated tunnel between `me` and `them` (any standard handshake flow, e.g. as in `e2e/handshakes_test.go`).
2. Attacker observes/guesses `them`'s `RemoteIndex` for the tunnel with `me` (visible in cleartext header of any packet on the wire, e.g. via passive on-path capture).
3. Attacker crafts a bare `header.RecvError` packet (`header.Encode(..., header.RecvError, 0, guessedRemoteIndex, 0)`), spoofing the UDP source address/port to match `me`'s currently known `CurrentRemote` for `them` (as recorded in `them`'s `HostInfo.GetRemote()`), and sends it to `them`.
4. `readOutsidePackets` → `handleRecvError` finds the matching `HostInfo` via `QueryReverseIndex`, the spoofed address matches `hr`, and `them` calls `closeTunnel` + `DeleteHostInfo`, destroying the authenticated tunnel state without the attacker ever presenting a valid certificate.

func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
