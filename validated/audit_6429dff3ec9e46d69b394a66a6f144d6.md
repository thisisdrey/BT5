I have enough evidence to finalize the analog now.### Title
`ca_name` firewall rules are keyed by attacker-influenced, non-unique certificate `Name()` string instead of a scoped CA identity — ([File: firewall.go])

### Summary
Nebula firewall rules support restricting traffic by `ca_name`, which is meant to scope a rule to a specific trusted CA. The implementation stores and matches these rules using `Certificate.Name()`, a free-form human-readable string field that is not guaranteed unique across CAs, rather than the CA's cryptographic fingerprint. This is the same bug class as the Spigot "whitelisted functions aren't scoped to revenue contracts" finding: a security-relevant allow-list entry is keyed by an unscoped, collidable identifier instead of a value cryptographically bound to the specific trusted resource, so a differently-rooted CA that happens to share a name can satisfy a rule intended only for another CA.

### Finding Description
`FirewallCA.addRule` stores caName-scoped rules in a map keyed by the raw `caName` string: [1](#0-0) 

At match time, `FirewallCA.match` resolves the packet's signing CA via `caPool.GetCAForCert` (which correctly looks up by cryptographic issuer fingerprint) but then throws away that unique identity and re-indexes the rule table using `s.Certificate.Name()`: [2](#0-1) 

`Name()` is simply an arbitrary string field carried in the certificate details, set at CA-creation time by whoever runs `nebula-cert ca -name ...`, with no requirement of global uniqueness: [3](#0-2) 

Unlike `CAShas`, which is keyed by `c.Certificate.Issuer()` — the SHA-256 fingerprint of the signing CA, a value that is unique and unforgeable — `CANames` is keyed purely by this arbitrary label: [4](#0-3) 

The `CAPool` itself is keyed by fingerprint, not name, confirming that `Fingerprint`/`Issuer()` is the only value the system otherwise treats as a unique CA identity: [5](#0-4) [6](#0-5) 

In a deployment where the local `pki.ca` file/config trusts more than one CA (a supported, documented configuration for federated networks), an operator can write a rule like `ca_name: "trusted-org"` intending to scope access to hosts whose certificate chains back to the CA named "trusted-org". If a second, independently-generated CA in the trust pool is also named "trusted-org" (whether by coincidence, or because an admin/attacker who controls CA provisioning names their CA to match), any host certificate signed by that second CA will satisfy `fc.CANames["trusted-org"].match(...)`, even though it was never intended to be trusted for that rule. This is precisely analogous to the Spigot bug: an allow-list entry (`ca_name`) is not scoped to the specific resource (a single CA fingerprint) it was meant to protect, and a colliding identifier (the `Name()` string, analogous to the 4-byte selector) causes an unrelated, independently-signed certificate to be silently granted the same firewall trust.

### Impact Explanation
A firewall rule intended to restrict traffic (inbound or outbound) to hosts whose certificates are signed by one specific, trusted CA can be unintentionally satisfied by hosts signed by a different CA that merely shares the same `Name()` value. This is a concrete firewall-rule scoping bypass: traffic that should be dropped (no matching rule) is instead allowed, because the CA-name lookup does not validate that the resolved signer's fingerprint is the one the administrator intended. In multi-CA/federated Nebula deployments this can let a host trusted only by a lower-trust or differently-scoped CA pass through firewall rules meant to gate access to a higher-trust CA's members, producing an authentication/authorization bypass at the firewall layer.

### Likelihood Explanation
Likelihood is scoped to environments where the `CAPool` contains more than one CA and at least one `ca_name`-based firewall rule is used to differentiate trust between CAs by name — a configuration explicitly supported by the code (`ca_name`/`ca_sha` are independent, alternative matching keys in `FirewallCA`). Because CA `Name()` values are arbitrary strings chosen at CA-creation time and are not validated for uniqueness anywhere in `cert/ca_pool.go` or `AddCA`, any operator who provisions multiple CAs (or any party able to provision/get their CA added into a trust pool) can trivially create a same-named CA, since there is no cryptographic binding preventing the collision.

### Recommendation
Key `FirewallCA`'s name-based rule table by the CA's certificate fingerprint (as already computed and available via `CachedCertificate.Fingerprint`/`Issuer()`) rather than by `Certificate.Name()`, or require that `ca_name` be resolved to a specific fingerprint at rule-load time (failing config validation if the name is ambiguous across multiple CAs in the pool) and store/match on that fingerprint. At minimum, `AddCA` should reject or warn when a newly added CA's `Name()` collides with an already-trusted CA of a different fingerprint, and `FirewallCA.match` should validate that the resolved signer identity is unambiguous before consulting `CANames`.

```go
func (fc *FirewallCA) match(p firewall.Packet, c *cert.CachedCertificate, caPool *cert.CAPool) bool {
	if fc == nil {
		return false
	}

	if fc.Any.match(p, c) {
		return true
	}

	if t, ok := fc.CAShas[c.Certificate.Issuer()]; ok {
		if t.match(p, c) {
			return true
		}
	}

	s, err := caPool.GetCAForCert(c.Certificate)
	if err != nil {
		return false
	}

	return fc.CANames[s.Certificate.Name()].match(p, c)
}
```

```go
// AddCA verifies a Nebula CA certificate and adds it to the pool.
func (ncp *CAPool) AddCA(c Certificate) error {
	if !c.IsCA() {
		return fmt.Errorf("%s: %w", c.Name(), ErrNotCA)
	}

	if !c.CheckSignature(c.PublicKey()) {
		return fmt.Errorf("%s: %w", c.Name(), ErrNotSelfSigned)
	}

	sum, err := c.Fingerprint()
	if err != nil {
		return fmt.Errorf("could not calculate fingerprint for provided CA; error: %w; %s", err, c.Name())
	}

	cc := &CachedCertificate{
		Certificate:    c,
		Fingerprint:    sum,
		InvertedGroups: make(map[string]struct{}),
	}

	for _, g := range c.Groups() {
		cc.InvertedGroups[g] = struct{}{}
	}

	ncp.CAs[sum] = cc

	if c.Expired(time.Now()) {
		return fmt.Errorf("%s: %w", c.Name(), ErrExpired)
	}

	return nil
}
```

```go
// GetCAForCert attempts to return the signing certificate for the provided certificate.
// No signature validation is performed
func (ncp *CAPool) GetCAForCert(c Certificate) (*CachedCertificate, error) {
	issuer := c.Issuer()
	if issuer == "" {
		return nil, fmt.Errorf("no issuer in certificate")
	}

	signer, ok := ncp.CAs[issuer]
	if ok {
		return signer, nil
	}

	return nil, ErrCaNotFound
}
```
