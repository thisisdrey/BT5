The Go standard library has a direct analog to this Rack vulnerability in `net/http`'s multipart byte-range handling.

### Title
`net/http`'s `parseRange` allows unbounded number of overlapping byte ranges, enabling multipart response amplification DoS - (File: src/net/http/fs.go)

### Summary
`parseRange` in [1](#0-0)  parses a comma-separated `Range` header and only rejects the result if the *total* byte coverage exceeds the file size (the fix for CVE-2024-26141, applied via `sumRangesSize(ranges) > size`). It places no limit on the *number* of ranges in the header. A request like `Range: bytes=0-0,0-0,0-0,...` (repeated thousands of times) has trivial total coverage (1 byte) so it sails through both `parseRange` and the `sumRangesSize` check, exactly mirroring the Rack advisory's bypass of the CVE-2024-26141-style fix.

### Finding Description
Attacker sends an unauthenticated HTTP GET/HEAD request with a crafted `Range` header to any handler that calls `http.ServeFile`/`http.ServeContent`/`http.FileServer`. `serveContent` at [2](#0-1)  calls `parseRange(rangeReq, size)` and then only checks `sumRangesSize(ranges) > size` to discard "wasteful" requests — it never checks `len(ranges)`. `parseRange` itself, at [3](#0-2) , appends one `httpRange` entry per comma-separated segment with no cap on iteration count.

When `len(ranges) > 1`, `serveContent` computes `rangesMIMESize(ranges, ctype, size)` — which iterates every range and calls `mw.CreatePart` per entry [4](#0-3)  — and then spawns a goroutine that, for every range, calls `mw.CreatePart`, `content.Seek`, and `io.CopyN` [5](#0-4) . Each of these per-range operations (MIME header/boundary construction, seek syscall, string formatting for `Content-Range`) is real CPU/IO work, so N ranges in the header directly multiply the server-side work and output size, even though each range covers only 1 byte and the aggregate "size" check passes.

### Impact Explanation
An unauthenticated attacker can send a single small HTTP request with a `Range` header containing many thousands of tiny overlapping ranges (e.g., `bytes=0-0,0-0,0-0,...`) to any `net/http` file-serving handler. This forces the server to perform proportionally many seeks, reads, and multipart part constructions, amplifying a small request into large CPU, I/O, and response-bandwidth cost per request — a resource-exhaustion/DoS effect on the file-serving path, structurally identical to the Rack advisory.

### Likelihood Explanation
Any application using `http.FileServer`, `http.ServeFile`, or `http.ServeContent` (an extremely common pattern for serving static assets) is reachable by any unauthenticated client that can send a normal GET/HEAD request with a `Range` header — no special privileges, TLS tampering, or victim workflow beyond a plain HTTP request are required.

### Recommendation
Add a bound on the number of ranges accepted in `parseRange` (e.g., reject headers with more than some fixed number of comma-separated ranges, similar to Apache's/other servers' limits), independent of the existing total-size (`sumRangesSize`) check, so that pathological range counts are rejected before multipart processing begins.

### Proof of Concept
```go
package http

import (
	"strings"
	"testing"
)

// Demonstrates that many overlapping 1-byte ranges pass parseRange
// and the sumRangesSize check unchanged, despite thousands of ranges.
func TestParseRangeManyOverlappingRanges(t *testing.T) {
	const size = 1000
	n := 50000
	parts := make([]string, n)
	for i := range parts {
		parts[i] = "0-0"
	}
	header := "bytes=" + strings.Join(parts, ",")

	ranges, err := parseRange(header, size)
	if err != nil {
		t.Fatalf("parseRange returned error: %v", err)
	}
	if len(ranges) != n {
		t.Fatalf("got %d ranges, want %d", len(ranges), n)
	}

	// This is the only guard fs.go applies before building a multipart
	// response (see serveContent), and it does NOT reject this case,
	// even though it will trigger n CreatePart/Seek/CopyN operations.
	if sumRangesSize(ranges) > size {
		t.Fatalf("expected sumRangesSize check to NOT reject this pathological request")
	}
}
```
Expected result: the test passes, confirming that 50,000 overlapping ranges are accepted by both `parseRange` and the existing `sumRangesSize` guard, so `serveContent` will proceed to build a 50,000-part multipart response for a request containing only a few hundred bytes of header.

func parseRange(s string, size int64) ([]httpRange, error) {
	if s == "" {
		return nil, nil // header not present
	}
	const b = "bytes="
	if len(s) < len(b) || !ascii.EqualFold(s[:len(b)], b) {
		return nil, errors.New("invalid range")
	}
	var ranges []httpRange
	noOverlap := false
	for ra := range strings.SplitSeq(s[len(b):], ",") {
		ra = textproto.TrimString(ra)
		if ra == "" {
			continue
		}
		start, end, ok := strings.Cut(ra, "-")
		if !ok {
			return nil, errors.New("invalid range")
		}
		start, end = textproto.TrimString(start), textproto.TrimString(end)
		var r httpRange
		if start == "" {
			// If no start is specified, end specifies the
			// range start relative to the end of the file,
			// and we are dealing with <suffix-length>
			// which has to be a non-negative integer as per
			// RFC 7233 Section 2.1 "Byte-Ranges".
			if end == "" || end[0] == '-' {
				return nil, errors.New("invalid range")
			}
			i, err := strconv.ParseInt(end, 10, 64)
			if i < 0 || err != nil {
				return nil, errors.New("invalid range")
			}
			if i > size {
				i = size
			}
			r.start = size - i
			r.length = size - r.start
		} else {
			i, err := strconv.ParseInt(start, 10, 64)
			if err != nil || i < 0 {
				return nil, errors.New("invalid range")
			}
			if i >= size {
				// If the range begins after the size of the content,
				// then it does not overlap.
				noOverlap = true
				continue
			}
			r.start = i
			if end == "" {
				// If no end is specified, range extends to end of the file.
				r.length = size - r.start
			} else {
				i, err := strconv.ParseInt(end, 10, 64)
				if err != nil || r.start > i {
					return nil, errors.New("invalid range")
				}
				if i >= size {
					i = size - 1
				}
				r.length = i - r.start + 1
			}
		}
		ranges = append(ranges, r)
	}
	if noOverlap && len(ranges) == 0 {
		// The specified ranges did not overlap with the content.
		return nil, errNoOverlap
	}
	return ranges, nil
}

func rangesMIMESize(ranges []httpRange, contentType string, contentSize int64) (encSize int64) {
	var w countingWriter
	mw := multipart.NewWriter(&w)
	for _, ra := range ranges {
		mw.CreatePart(ra.mimeHeader(contentType, contentSize))
		encSize += ra.length
	}
	mw.Close()
	encSize += int64(w)
	return
}
