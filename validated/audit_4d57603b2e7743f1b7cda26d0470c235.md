### Title
StackerDB `write-freq` rate limit is never enforced on chunk writes, letting any valid slot signer bypass the smart-contract-mandated write cadence - ([File: stackslib/src/net/stackerdb/db.rs])

### Summary
The StackerDB control-plane contract can specify a `write-freq` (minimum wall-clock interval between writes to a slot) via `stackerdb-get-config` (`stackslib/src/net/stackerdb/config.rs:422-437`), and the wire protocol/error type `net_error::TooFrequentSlotWrites` exists specifically to reject a write that violates this cadence (`stackslib/src/net/mod.rs:244-245`). However, no code path that actually stores a chunk ever checks `config.write_freq` or a slot's `write_time` against it, so the restriction is never enforced.

### Finding Description
`StackerDBTx::try_replace_chunk` (`stackslib/src/net/stackerdb/db.rs:400-438`) checks, in order: chunk-size cap, signer signature validity, version staleness, and `max_writes`. It never reads `slot_validation.write_time` or compares it to `self.config.write_freq`, even though `SlotValidation`/the chunks table tracks `write_time` (`stackslib/src/net/stackerdb/db.rs:52-75`) precisely for this purpose. Likewise, `PeerNetwork::validate_received_chunk` (`stackslib/src/net/stackerdb/mod.rs:649-718`), which gates both downloaded and pushed (`StackerDBPushChunk`) chunks before they are accepted for storage, checks chunk size, expected version, signer, staleness, and `max_writes` — but never `write_freq`. The only consumer of `write_freq` in the whole `net/stackerdb` module is `StackerDBSync::modify_chunk_priorities` (`stackslib/src/net/stackerdb/sync.rs:340`), which uses it purely to decide whether *this node* should bother fetching a chunk from a peer, not whether a write should be accepted.

This breaks the intended equality "chunk accepted for storage ⇔ write satisfies contract's `write-freq`". A legitimately-signed but too-frequent chunk is stored and disseminated as if it were compliant, because storage-side code silently treats `write_freq` as non-existent.

### Impact Explanation
Any principal that legitimately owns a StackerDB slot (e.g. a signer in `.signers-0-xxx`/`.signers-1-xxx` or `.miners`) can write to their slot as fast as `max_writes` and `chunk_size` allow, completely ignoring the contract-specified write cadence. Because accepted chunks are broadcast network-wide via `PeerNetwork::process_stacker_db_chunks` / `StacksMessageType::StackerDBPushChunk` (`stackslib/src/net/relay.rs:2445-2452`), this is not merely a local inconsistency — it propagates network-wide and can be used to flood all StackerDB replicas and downstream consumers (e.g. signer/miner coordination messages) at a rate the protocol design explicitly intended to bound. This falls under "network-wide propagation of forged/uncontrolled data" and bounded-compute/resource DoS on StackerDB replication, which HIGH-tier impact in the rules (steering/uncontrolled write rate feeding into signer decision inputs, though the signer decision logic itself is out of scope — the impact here is on the StackerDB replication/storage layer).

### Likelihood Explanation
High likelihood: this requires no privileged/admin access beyond being a normal, already-authorized StackerDB slot owner (a role explicitly reachable without admin keys, e.g. any registered signer). No race condition or timing trick is needed — the check is simply absent on every call path, so exploitation is deterministic and trivial to reproduce.

### Recommendation
Enforce `write_freq` in the storage path: in `StackerDBTx::try_replace_chunk`, after loading `slot_validation`, reject the write with `net_error::TooFrequentSlotWrites` if `get_epoch_time_secs() < slot_validation.write_time + self.config.write_freq`. Apply the same check in `PeerNetwork::validate_received_chunk` before accepting pushed/downloaded chunks, using the slot's stored `write_time` (via `get_slot_write_timestamps`/`get_slot_validation`) compared against `config.write_freq`.

### Proof of Concept
1. Deploy or use an existing StackerDB contract whose `stackerdb-get-config` returns a nonzero `write-freq` (e.g. `write-freq: u600`), assigning `signer_addr` one slot.
2. As `signer_addr`, sign and `POST` a `StackerDBChunkData` chunk (slot_id=0, slot_version=1) to `/v2/stackerdb/<contract>/chunks` (handled by `RPCPostStackerDBChunkRequestHandler`, `stackslib/src/net/api/poststackerdbchunk.rs:163-306`). It is accepted.
3. Immediately (within the same second, well under the 600s `write_freq`) sign and POST slot_version=2 for the same slot.
4. Observe: the second POST is accepted (`accepted: true`) despite violating the configured `write-freq`, because neither `try_replace_chunk` (`stackslib/src/net/stackerdb/db.rs:400-438`) nor `validate_received_chunk` (`stackslib/src/net/stackerdb/mod.rs:649-718`) checks `write_time`/`write_freq`. Repeating this in a tight loop up to `max_writes` demonstrates unrestricted write-rate flooding that the contract's `write-freq` was meant to prevent.     /// Otherwise, this errors out with Error::StaleChunk
    pub fn try_replace_chunk(
        &self,
        smart_contract: &QualifiedContractIdentifier,
        slot_desc: &SlotMetadata,
        chunk: &[u8],
    ) -> Result<(), net_error> {
        // Check per-replica chunk-size cap.
        if (chunk.len() as u64) > self.config.chunk_size {
            return Err(net_error::StackerDBChunkTooBig(chunk.len()));
        }

        let slot_validation = self
            .get_slot_validation(smart_contract, slot_desc.slot_id)?
            .ok_or(net_error::NoSuchSlot(
                smart_contract.clone(),
                slot_desc.slot_id,
            ))?;

        if !slot_desc.verify(&slot_validation.signer)? {
            return Err(net_error::BadSlotSigner(
                slot_validation.signer,
                slot_desc.slot_id,
            ));
        }
        if slot_desc.slot_version <= slot_validation.version {
            return Err(net_error::StaleChunk {
                supplied_version: slot_desc.slot_version,
                latest_version: slot_validation.version,
            });
        }
        if slot_desc.slot_version > self.config.max_writes {
            return Err(net_error::TooManySlotWrites {
                supplied_version: slot_desc.slot_version,
                latest_version: slot_validation.version,
                max_writes: self.config.max_writes,
            });
        }
        self.insert_chunk(smart_contract, slot_desc, chunk)
    }

    /// pushed to us (with [`PeerNetwork::handle_unsolicited_StackerDBPushChunk`])
    ///
    /// NOTE: does not check write frequency, since the caller has different ways of doing this.
    /// Returns:
    /// - Ok(true) if the chunk is valid
    /// - Ok(false) if the chunk is invalid
    /// - Err(..) on DB error
    pub fn validate_received_chunk(
        &self,
        smart_contract_id: &QualifiedContractIdentifier,
        config: &StackerDBConfig,
        data: &StackerDBChunkData,
        expected_versions: &[u32],
    ) -> Result<bool, net_error> {
        // validate -- must not exceed this replica's configured chunk size.
        if (data.data.len() as u64) > config.chunk_size {
            info!(
                "Received StackerDBChunk for {} ID {}, which is oversized: {} bytes (max {} bytes)",
                smart_contract_id,
                data.slot_id,
                data.data.len(),
                config.chunk_size
            );
            return Ok(false);
        }

        // validate -- must be a valid chunk
        let Some(expected_version) = expected_versions.get(data.slot_id as usize) else {
            info!(
                "Received StackerDBChunk for {} ID {}, which is too big ({})",
                smart_contract_id,
                data.slot_id,
                expected_versions.len()
            );
            return Ok(false);
        };

        // validate -- must be signed by the expected author
        let addr = match self
            .stackerdbs
            .get_slot_signer(smart_contract_id, data.slot_id)?
        {
            Some(addr) => addr,
            None => {
                return Ok(false);
            }
        };

        let slot_metadata = data.get_slot_metadata();
        if !slot_metadata.verify(&addr)? {
            info!(
                "StackerDBChunk for {} ID {} is not signed by {}",
                smart_contract_id, data.slot_id, &addr
            );
            return Ok(false);
        }

        // validate -- must be the current or newer version
        if data.slot_version < *expected_version {
            info!(
                "Received StackerDBChunk for {} ID {} version {}, which is stale (expected {})",
                smart_contract_id, data.slot_id, data.slot_version, *expected_version
            );
            return Ok(false);
        }

        // validate -- must not exceed max writes
        if data.slot_version > config.max_writes {
            info!(
                "Write count exceeded for StackerDBChunk for {} ID {} version {} (max is {})",
                smart_contract_id, data.slot_id, data.slot_version, config.max_writes
            );
            return Ok(false);
        }

        Ok(true)
    }
