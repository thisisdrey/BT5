### Title
Fee bypass on `TokenDiff` intents for NEP-245/IMT tokens by splitting transfers into unit (`|delta|==1`) chunks - (File: contracts/defuse/core/src/intents/token_diff.rs)

### Summary
`TokenDiff::token_fee` deliberately returns `Pips::ZERO` for `Nep245`/`Imt` token deltas whose absolute value is `<= 1`, waiving the protocol fee that would otherwise apply. Because a `DefuseIntents` payload can contain an arbitrary number of `TokenDiff` intents (or a batch of `execute_intents` can contain arbitrarily many signed payloads), a user/solver can move any total amount of a NEP-245 or IMT token through a sequence of unit-sized (`delta = ±1`) diffs, paying zero protocol fee on the entire trade instead of the `fee` configured via `set_fee`.

### Finding Description
In `TokenDiff::execute_intent`, the fee for a negative delta (token_in) is computed as: [1](#0-0) 

`Self::token_fee` explicitly zeroes the fee for MT/IMT tokens with `|delta| <= 1`: [2](#0-1) 

`fee_ceil` itself always rounds up and cannot legitimately yield 0 for `amount >= 1` when `fee > 0`: [3](#0-2) 

so the only avenue to zero fee on a NEP-245/IMT swap is the `|delta| <= 1` carve-out in `token_fee`. A `DefuseIntents` message can carry an arbitrary `Vec<Intent>`, each processed independently in order: [4](#0-3) 

and `execute_signed_intents`/`execute_intents` accept a `Vec<MultiPayload>` executed sequentially into the same `Deltas`/`TransferMatcher` accumulator, which only checks that the *sum* of deltas per token nets to zero across the whole batch: [5](#0-4) [6](#0-5) 

Nothing prevents a signer/solver from splitting a NEP-245/IMT trade of size N into N separate `TokenDiff` intents each with `delta = -1`/`+1` on the token in question (either as N intents inside one `DefuseIntents.intents` vector, or across N signed payloads in the same `execute_intents` call). Each individual diff entry sees `amount == 1`, so `token_fee` returns `Pips::ZERO`, and the whole trade completes with `fees_collected` empty for that token — even though the aggregate transferred amount can be arbitrarily large. This breaks the fees-owed-vs-fees-collected binding: the protocol fee configured by `Role::FeesManager`/`DAO` via `set_fee` is silently bypassed for MT/IMT-denominated swaps whenever a counterparty structures the trade as unit-sized diffs.

### Impact Explanation
This matches the "fees bypassed" Critical impact category: the DAO-configured protocol fee (`fees.fee`) is completely avoidable for any NEP-245 or IMT token swap by chunking the trade into `|delta|==1` `TokenDiff` intents, at the cost of only extra intents in the same execute/simulate call (no extra signature overhead beyond what a solver already controls, since a solver can freely choose how to structure its own signed `TokenDiff` intents). This causes the fee collector to permanently receive 0 fees on such trades, which is a direct, unauthorized diversion of protocol revenue with no requirement for privileged access, upgrade, or victim cooperation.

### Likelihood Explanation
Likelihood is high for any solver/market maker that is fee-sensitive: constructing N unit-delta `TokenDiff` intents (or signing N small payloads) is a purely mechanical, permissionless operation available to any account with a valid public key on Defuse — no special role or contract state is required. The main constraint is the added intent/payload count (and correspondingly larger transaction size/gas), which bounds how large N can practically be per call, but this is not a blocking factor for meaningful fee avoidance on any NEP-245/IMT asset with per-unit value (e.g., a fungible-like multi-token where 1 unit still represents non-trivial value), and could be repeated across multiple `execute_intents` calls to move fee-free volume over time.

### Recommendation
Do not zero the fee based on the size of a single `TokenDiff` delta. Instead, either: (1) remove the `|delta| <= 1` exemption for `Nep245`/`Imt` entirely and apply `fee_ceil` uniformly regardless of amount, or (2) if the exemption exists to avoid fee-related rounding issues on genuinely-NFT-like MT/IMT tokens (`amount` intended to mean "quantity of a unique token", not a fungible unit), disambiguate NFT-like token IDs from fungible-style MT/IMT token IDs at the type level (e.g. via a supply/decimals flag) rather than inferring "NFT-ness" from the transient per-intent `amount` field, since that field is fully attacker-controlled by how a trade is chunked across intents/payloads.

### Proof of Concept
1. DAO sets a non-zero protocol `fee` via `set_fee` for the Defuse contract: [7](#0-6) 
2. A user and solver want to swap N units of an MT/IMT token (`token_id`, `TokenIdType::Nep245`/`Imt`) for some other token.
3. Instead of one `TokenDiff` intent with `delta = -N` on `token_id` (which would incur `fee_ceil(N)` fee via `token_fee` returning the full configured `fee` since `amount > 1`), the solver signs (or the batch contains) N separate `TokenDiff` intents, each with `delta = -1` on `token_id`, matched by N corresponding `delta = +1` entries from the counterparty (or across multiple such intents within `DefuseIntents.intents`).
4. In `TokenDiff::execute_intent`, for each of these unit intents, `amount = 1`, so `Self::token_fee(token_id, 1, protocol_fee)` returns `Pips::ZERO` (per the `Nep171 | Nep245 | Imt` match arm requiring `amount > 1` to charge fee) — see `contracts/defuse/core/src/intents/token_diff.rs:206-217`. `fees_collected` for `token_id` stays empty across all N intents.
5. `Engine::execute_signed_intents` nets the N unit withdrawals/deposits to the same aggregate transfer as a single N-unit swap would have produced (per `TransferMatcher::finalize`), so the trade settles for the full amount, but the fee collector's balance for `token_id` never increases — the trade completes with 0 protocol fee instead of `fee_ceil(N)`.

    // Finalizes all transfers, or returns unmatched deltas.
    // If unmatched deltas overflow, then Err(None) is returned.
    pub fn finalize(self) -> Result<Transfers, InvariantViolated> {
        let mut transfers = Transfers::default();
        let mut deltas = TokenDeltas::default();
        for (token_id, transfer_matcher) in self.0 {
            if let Err(unmatched) = transfer_matcher.finalize_into(&token_id, &mut transfers)
                && (unmatched == 0 || deltas.apply_delta(token_id, unmatched).is_none())
            {
                return Err(InvariantViolated::Overflow);
            }
        }
        if !deltas.is_empty() {
            return Err(InvariantViolated::UnmatchedDeltas {
                unmatched_deltas: deltas,
            });
        }
        Ok(transfers)
    }
