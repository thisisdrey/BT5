### Title
Missing request/response version binding lets a malicious replica serve the oldest-acceptable (not the requested) chunk version, stalling StackerDB convergence - (File: stackslib/src/net/stackerdb/sync.rs)

### Summary
`getchunks_begin` sends a `StackerDBGetChunkData` request for a *specific* `slot_version` computed per-neighbor in `make_chunk_request_schedule` [1](#0-0) , but the response is validated in `getchunks_try_finish` -> `validate_downloaded_chunk` only against `self.expected_versions`, which is the requester's own local slot versions captured once per round in `getchunksinv_try_finish` [2](#0-1) , not against the version that was actually requested for that particular outstanding `StackerDBGetChunkData`. This means the returned chunk's `slot_version` is never checked for equality with the requested `chunk_request.slot_version`.

### Finding Description
The state machine tracks a per-round `expected_versions: Vec<u32>` set from local DB slot versions at the end of `getchunksinv_try_finish` [2](#0-1) . When issuing chunk requests in `getchunks_begin`, each request carries a specific `slot_version` taken from the peer's advertised inventory at schedule-build time [3](#0-2) . However, when the reply comes back in `getchunks_try_finish`, the code only calls `self.validate_downloaded_chunk(network, config, &data)` [4](#0-3) , which in turn calls `network.validate_received_chunk(..., data, &self.expected_versions)` [5](#0-4) . This validation path only has access to the requester's own recorded local version per slot (`expected_versions[slot_id]`), not the specific version number (`chunk_request.slot_version`) that was placed in the outstanding request sent to that neighbor. There is no per-inflight-request bookkeeping (e.g., mapping neighbor+slot_id -> requested version) consulted at response time to enforce `data.slot_version == requested_version`.

A malicious replica that legitimately holds an older, validly-signed chunk (e.g., version 3, still signed by the real slot owner, from before it advanced to version 5) can respond to a request for version 5 with its stale version-3 chunk. As long as version 3 is greater than the requester's stored local version (e.g., 2), the "newer than local" check passes and the chunk is accepted and stored via `add_downloaded_chunk` [6](#0-5) , even though it does not match the version actually requested.

### Impact Explanation
The victim node stores a stale-but-genuinely-signed chunk as its new "current" value for that slot, believing it has made progress toward the tip. Because the DB update is monotonic (each accepted chunk only needs to exceed the prior local version, not equal the specific requested version), a colluding/malicious replica can repeatedly answer with `local_version + 1` on each round instead of the true latest version, slowing (though — given the monotonic +1 floor and the possibility that other honest replicas serve the true latest version in the same or later rounds via the rarest-first scheduling in `make_chunk_request_schedule` [7](#0-6)  — not necessarily permanently blocking) convergence to the actual latest chunk. This is a genuine gap in request/response version binding, but the data itself is not forged (it carries the legitimate slot owner's valid signature over older content), and other honest replicas in the peer set can still supply the true latest version in subsequent rounds since `chunk_invs` and priorities are recomputed every sync round.

### Likelihood Explanation
The attacker only needs to be one of the chosen replicas returned by `find_qualified_replicas`/`chunk_invs`, which any P2P peer that advertises the StackerDB config's contract can become, and must possess (or have possessed) an older valid chunk version for a slot it doesn't even need to own — no privileged key or secret is required to relay data it received from gossip. This is remotely triggerable over the P2P StackerDB protocol on every sync round, is repeatable, and costs the attacker nothing beyond running a normal peer.

### Recommendation
Track the exact requested `(neighbor, slot_id) -> slot_version` at request-issue time (e.g., in a dedicated map populated in `getchunks_begin`), and in `getchunks_try_finish` reject any `StackerDBChunk` response whose `slot_version` does not equal the version that was specifically requested from that neighbor for that slot, in addition to the existing "newer than local" check.

### Proof of Concept
Rust test plan in `stackslib/src/net/stackerdb/tests/sync.rs`:
1. Set up a `StackerDBSync` instance with local slot 0 at version 2.
2. Drive it through `getchunksinv_try_finish` so `expected_versions[0] == 2` and schedule a `StackerDBGetChunkData{slot_id:0, slot_version:5}` request to a mock malicious replica (simulate remote inv advertising version 5).
3. Have the mock replica reply with a `StackerDBChunkData{slot_id:0, slot_version:3}` chunk, validly signed by the actual slot-owner key, instead of version 5.
4. Feed this into `getchunks_try_finish` and assert that `validate_downloaded_chunk` returns `Ok(true)` and the chunk is accepted via `add_downloaded_chunk`, despite `data.slot_version (3) != requested chunk_request.slot_version (5)` — demonstrating the missing request/response version-equality check.

    pub fn make_chunk_request_schedule(
        &self,
        network: &PeerNetwork,
        local_slot_versions_opt: Option<Vec<u32>>,
    ) -> Result<Vec<(StackerDBGetChunkData, Vec<NeighborAddress>)>, net_error> {
        let rc_consensus_hash = network.get_chain_view().rc_consensus_hash.clone();
        let local_slot_versions = if let Some(local_slot_versions) = local_slot_versions_opt {
            local_slot_versions
        } else {
            self.stackerdbs.get_slot_versions(&self.smart_contract_id)?
        };

        let local_write_timestamps = self
            .stackerdbs
            .get_slot_write_timestamps(&self.smart_contract_id)?;

        if local_slot_versions.len() != local_write_timestamps.len() {
            let msg = format!("{}: Local slot versions ({}) out of sync with DB slot versions ({}); abandoning sync and trying again", &self.smart_contract_id, local_slot_versions.len(), local_write_timestamps.len());
            warn!("{}", &msg);
            return Err(net_error::Transient(msg));
        }

        let mut need_chunks: HashMap<usize, (StackerDBGetChunkData, Vec<NeighborAddress>)> =
            HashMap::new();
        let now = get_epoch_time_secs();

        // who has data we need?
        for ((i, local_version), write_ts) in local_slot_versions
            .iter()
            .enumerate()
            .zip(local_write_timestamps.iter())
        {
            if self.write_freq > 0 && write_ts + self.write_freq > now {
                debug!(
                    "{:?}: {}: Chunk {} was written too frequently ({} + {} > {}) in {}, so will not fetch chunk",
                    network.get_local_peer(),
                    &self.smart_contract_id,
                    i,
                    write_ts,
                    self.write_freq,
                    now,
                    &self.smart_contract_id,
                );
                continue;
            }

            for (naddr, chunk_inv) in self.chunk_invs.iter() {
                if chunk_inv.slot_versions.len() != local_slot_versions.len() {
                    // remote peer and our DB are out of sync, so just skip this
                    continue;
                }

                let Some(remote_version) = chunk_inv.slot_versions.get(i) else {
                    // remote peer isn't tracking this chunk
                    continue;
                };

                if local_version >= remote_version {
                    // remote peer has same view as local peer, or stale
                    continue;
                }

                let (request, available) = if let Some(x) = need_chunks.get_mut(&i) {
                    // someone has this chunk already
                    x
                } else {
                    // haven't seen anyone with this data yet.
                    // Add a record for it
                    need_chunks.insert(
                        i,
                        (
                            StackerDBGetChunkData {
                                contract_id: self.smart_contract_id.clone(),
                                rc_consensus_hash: rc_consensus_hash.clone(),
                                slot_id: i as u32,
                                slot_version: *remote_version,
                            },
                            vec![naddr.clone()],
                        ),
                    );
                    continue;
                };

                if request.slot_version < *remote_version {
                    // this peer has a newer view
                    available.clear();
                    available.push(naddr.clone());
                    *request = StackerDBGetChunkData {
                        contract_id: self.smart_contract_id.clone(),
                        rc_consensus_hash: rc_consensus_hash.clone(),
                        slot_id: i as u32,
                        slot_version: *remote_version,
                    };
                } else if request.slot_version == *remote_version {
                    // this peer has the same view as a prior peer.
                    // just track how many times we see this
                    available.push(naddr.clone());
                }
            }
        }

        // prioritize requests by rarest-chunk-first order, but choose neighbors in random order
        let mut schedule: Vec<_> = need_chunks
            .into_iter()
            .map(|(_, (stackerdb_getchunkdata, mut neighbors))| {
                neighbors.shuffle(&mut thread_rng());
                (stackerdb_getchunkdata, neighbors)
            })
            .collect();

        schedule.sort_by(|item_1, item_2| item_1.1.len().cmp(&item_2.1.len()));
        schedule.reverse();

        debug!(
            "{:?}: {}: Will request up to {} chunks. Schedule: {:?}",
            network.get_local_peer(),
            &self.smart_contract_id,
            &schedule.len(),
            &schedule
        );
        Ok(schedule)
    }

    /// Store a downloaded chunk to RAM, and update bookkeeping
    pub fn add_downloaded_chunk(&mut self, naddr: NeighborAddress, data: StackerDBChunkData) {
        let slot_id = data.slot_id;
        let _slot_version = data.slot_version;

        if let Some(data_list) = self.downloaded_chunks.get_mut(&naddr) {
            data_list.push(data);
        } else {
            self.downloaded_chunks.insert(naddr.clone(), vec![data]);
        }

        self.chunk_fetch_priorities
            .retain(|(chunk, ..)| chunk.slot_id != slot_id);

        if !self.chunk_fetch_priorities.is_empty() {
            let next_chunk_fetch_priority =
                self.next_chunk_fetch_priority % self.chunk_fetch_priorities.len();
            self.next_chunk_fetch_priority = next_chunk_fetch_priority;
        }

        self.total_stored += 1;
    }
