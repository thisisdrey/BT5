Audit Report

## Title
Griefing via zero-value `stake`/`unstake` permanently advances `last_update_block`, rounding reward-per-token accrual to zero and losing rewards for the accrual period - (File: `substrate/frame/asset-rewards/src/lib.rs`)

## Summary
`reward_per_token` in `pallet-asset-rewards` computes `reward_rate_per_block * rewardable_blocks_elapsed * PRECISION_SCALING_FACTOR / total_tokens_staked`, and `update_pool_rewards` unconditionally advances `last_update_block` to the current block regardless of whether the resulting increment truncated to zero. Since `stake`/`unstake` are permissionless, callable every block, and impose no `amount > 0` requirement, an attacker can call `stake(pool_id, 0)` every block to force `rewardable_blocks_elapsed = 1` on each update, and whenever `reward_rate_per_block * 4096 < total_tokens_staked`, that block's reward is permanently discarded for every staker in the pool.

## Finding Description
`reward_per_token` at [1](#0-0)  computes the reward increment using integer division scaled only by `PRECISION_SCALING_FACTOR = 4096` [2](#0-1) . `update_pool_rewards` then unconditionally stamps `last_update_block = current_block_number()` regardless of whether the computed `reward_per_token` increment was nonzero: [3](#0-2) .

Both `stake` and `unstake` call `update_pool_and_staker_rewards` (which internally calls `reward_per_token` then `update_pool_rewards`) unconditionally on every invocation, and neither extrinsic validates that `amount` is nonzero: [4](#0-3)  and [5](#0-4) . There is no `ensure!(!amount.is_zero(), ...)` guard, no minimum-stake requirement, and no check that the computed reward increment was nonzero before advancing `last_update_block`. Because `rewardable_blocks_elapsed` is measured relative to `last_update_block`, an attacker calling `stake(pool_id, 0)` every block forces `rewardable_blocks_elapsed = 1` on each call, maximizing the odds that `reward_rate_per_block * 1 * 4096 < total_tokens_staked` truncates to zero while `last_update_block` still advances, permanently erasing that block's accrual for the whole pool.

## Impact Explanation
This degrades reward payouts for a live pallet's public, unprivileged extrinsics — an attacker with no special role or elevated permission can indefinitely suppress reward accrual in any pool where `total_tokens_staked` is large relative to `reward_rate_per_block * 4096`, at the cost of only zero-value transaction fees. This matches the "public underpriced work that degrades ... reward payouts" impact category: legitimate stakers permanently lose reward-asset accrual for griefed blocks, with the corrupted value being `Pools::<T>::get(pool_id).last_update_block` (and consequently `reward_per_token_stored`) advancing without corresponding reward-per-token accumulation.

## Likelihood Explanation
The attack requires only an ordinary signed account calling public extrinsics `stake`/`unstake` with `amount = 0` every block; no governance, validator, collator, or leaked-key access is needed. On any chain with low transaction fees this is trivially repeatable and does not require the attacker to hold or risk any staked funds. The precision constant `PRECISION_SCALING_FACTOR = 4096` is fixed and small, so the rounding-to-zero condition is easily reachable as `total_tokens_staked` grows in higher-TVL pools.

## Recommendation
- Reject zero-amount `stake`/`unstake` calls via `ensure!(!amount.is_zero(), Error::<T>::...)`.
- Do not advance `last_update_block` when the computed reward-per-token increment rounds to zero; instead track a remainder/dust accumulator so unrounded reward-time is not silently discarded, or only advance `last_update_block` up to the last block for which a nonzero increment was actually accounted.
- Increase `PRECISION_SCALING_FACTOR` or switch `reward_per_token_stored` to a higher-precision fixed-point type (e.g., `FixedU128`), analogous to `pallet-nomination-pools`'s `RewardCounter` [6](#0-5) .

## Proof of Concept
1. Admin creates a pool via `create_pool` with `reward_rate_per_block = R` and stakers holding `total_tokens_staked = S` such that `R * 4096 < S`.
2. Attacker calls `stake(pool_id, 0)` every subsequent block.
3. Each call triggers `reward_per_token` at [1](#0-0) , computing `rewardable_blocks_elapsed = 1` and `R * 1 * 4096 / S == 0` due to truncation.
4. `update_pool_rewards` still sets `last_update_block = now` [7](#0-6) , permanently discarding that block's reward; subsequent `harvest_rewards` calls by real stakers never see that block's reward accounted in `reward_per_token_stored`.
5. Repeating step 2 indefinitely suppresses essentially all reward accrual for the pool at the cost of only zero-value transaction fees.

		pub fn unstake(
			origin: OriginFor<T>,
			pool_id: PoolId,
			amount: T::Balance,
			staker: Option<T::AccountId>,
		) -> DispatchResult {
			let caller = ensure_signed(origin)?;
			let staker = staker.unwrap_or(caller.clone());

			// Always start by updating the pool rewards.
			let pool_info = Pools::<T>::get(pool_id).ok_or(Error::<T>::NonExistentPool)?;
			let now = T::BlockNumberProvider::current_block_number();
			ensure!(now > pool_info.expiry_block || caller == staker, BadOrigin);

			let staker_info = PoolStakers::<T>::get(pool_id, &staker).unwrap_or_default();
			let (mut pool_info, mut staker_info) =
				Self::update_pool_and_staker_rewards(&pool_info, &staker_info)?;

			// Check the staker has enough staked tokens.
			ensure!(staker_info.amount >= amount, Error::<T>::NotEnoughTokens);

			// Unfreeze staker assets.
			T::AssetsFreezer::decrease_frozen(
				pool_info.staked_asset_id.clone(),
				&FreezeReason::Staked.into(),
				&staker,
				amount,
			)?;

			// Update Pools.
			pool_info.total_tokens_staked.ensure_sub_assign(amount)?;
			Pools::<T>::insert(pool_id, pool_info);

			// Update PoolStakers.
			staker_info.amount.ensure_sub_assign(amount)?;

			if staker_info.amount.is_zero() && staker_info.rewards.is_zero() {
				PoolStakers::<T>::remove(&pool_id, &staker);
			} else {
				PoolStakers::<T>::insert(&pool_id, &staker, staker_info);
			}

			// Emit event.
			Self::deposit_event(Event::Unstaked { caller, staker, pool_id, amount });

			Ok(())
		}
