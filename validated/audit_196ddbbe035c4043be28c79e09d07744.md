### Title
Fixed-window stream throttling allows ~2x QoS bypass at STREAM_THROTTLING_INTERVAL boundaries - ([File: streamer/src/nonblocking/stream_throttle.rs])

### Finding Description
`ConnectionStreamCounter::reset_throttling_params_if_needed` implements a fixed (non-sliding) window rate limiter: it tracks `stream_count` and `last_throttling_instant`, and resets `stream_count` to 0 only when `now - last_throttling_instant > STREAM_THROTTLING_INTERVAL` (100ms), at which point `last_throttling_instant` is bumped to `now` [1](#0-0) . `throttle_stream` then only sleeps if `stream_count >= max_streams_per_throttling_interval`, i.e. it enforces the cap only within each fixed window independent of the previous window's usage [2](#0-1) . `on_stream_accepted` increments `stream_count` after every stream is opened via `qos.on_new_stream`/`on_stream_accepted` in the connection handling loop [3](#0-2) [4](#0-3) .

Because the window is fixed rather than sliding, an attacker who can time stream creation relative to the 100ms boundary can open `max_streams_per_throttling_interval` streams just before a reset, then open another full budget immediately after the reset fires, effectively sending up to `2 * max_streams_per_throttling_interval` streams within a much shorter real-time span than 100ms, repeatable at every window boundary.

### Impact Explanation
This is a QoS evasion against the per-connection stream ingress limiter used by `SwQos`, allowing an unstaked/unprivileged remote client to sustain close to double the intended stream (transaction) ingestion rate around window boundaries, increasing TPU processing load from that connection beyond the configured budget. This falls under the "QoS evasion" bounty category referenced in the rules.

### Likelihood Explanation
Exploitation requires the attacker to time stream opens relative to the throttling window with reasonably fine granularity (order of a few ms, not strict microsecond precision, since the exploitable margin is proportional to attacker's timing jitter tolerance) and to repeat this at each 100ms boundary. This is a purely client-side timing exercise against a public, unauthenticated QUIC/TPU port with no special privileges needed, making it straightforward for a single attacker to attempt, though network jitter/RTT variance will reduce the achievable multiplier below a clean 2x in practice.

### Recommendation
Replace the fixed-window counter with a sliding-window or token-bucket algorithm that accounts for stream arrival times continuously (similar to `simple_qos.rs`'s token-bucket-based `consume_tokens`/`us_to_have_tokens` approach already used elsewhere) so that the enforced rate bound holds over any rolling `STREAM_THROTTLING_INTERVAL`-length window, not just within calendar-aligned windows.

```rust
// streamer/src/nonblocking/stream_throttle.rs (test module)
#[tokio::test]
async fn test_boundary_straddle_doubles_throughput() {
    let stream_counter = Arc::new(ConnectionStreamCounter::new());
    let stats = StreamerStats::default();
    let max_streams = 100u64;

    // Simulate filling the budget just before the window ends.
    for _ in 0..max_streams {
        stream_counter.stream_count.fetch_add(1, Ordering::Relaxed);
    }
    // Wait until just after STREAM_THROTTLING_INTERVAL elapses so reset triggers.
    tokio::time::sleep(STREAM_THROTTLING_INTERVAL + Duration::from_millis(1)).await;

    let start = std::time::Instant::now();
    // First call resets stream_count to 0 due to elapsed interval.
    throttle_stream(
        &stats,
        ConnectionPeerType::Unstaked,
        "127.0.0.1:0".parse().unwrap(),
        &stream_counter,
        max_streams,
    ).await;

    // Immediately consume another full budget right after reset.
    for _ in 0..max_streams {
        stream_counter.stream_count.fetch_add(1, Ordering::Relaxed);
    }

    // Assert total admitted within a window shorter than STREAM_THROTTLING_INTERVAL
    // exceeds max_streams (demonstrating up to 2x the intended cap).
    assert!(start.elapsed() < STREAM_THROTTLING_INTERVAL);
    assert!(stream_counter.stream_count.load(Ordering::Relaxed) >= max_streams);
    // Total streams admitted across the two adjacent windows = 2 * max_streams,
    // violating "streams bounded to max_streams per any STREAM_THROTTLING_INTERVAL window".
}
```
Expected result: the test demonstrates that up to `2 * max_streams_per_throttling_interval` streams are admitted within a time span close to `STREAM_THROTTLING_INTERVAL`, violating the intended sliding-window rate invariant.

```rust
    pub(crate) fn reset_throttling_params_if_needed(&self) -> tokio::time::Instant {
        let last_throttling_instant = *self.last_throttling_instant.read().unwrap();
        if tokio::time::Instant::now().duration_since(last_throttling_instant)
            > STREAM_THROTTLING_INTERVAL
        {
            let mut last_throttling_instant = self.last_throttling_instant.write().unwrap();
            // Recheck as some other thread might have done throttling since this thread tried to acquire the write lock.
            if tokio::time::Instant::now().duration_since(*last_throttling_instant)
                > STREAM_THROTTLING_INTERVAL
            {
                *last_throttling_instant = tokio::time::Instant::now();
                self.stream_count.store(0, Ordering::Relaxed);
            }
            *last_throttling_instant
        } else {
            last_throttling_instant
        }
```

```rust
pub(crate) async fn throttle_stream(
    stats: &StreamerStats,
    peer_type: ConnectionPeerType,
    remote_addr: std::net::SocketAddr,
    stream_counter: &Arc<ConnectionStreamCounter>,
    max_streams_per_throttling_interval: u64,
) {
    let throttle_interval_start = stream_counter.reset_throttling_params_if_needed();
    let streams_read_in_throttle_interval = stream_counter.stream_count.load(Ordering::Relaxed);
    if streams_read_in_throttle_interval >= max_streams_per_throttling_interval {
        // The peer is sending faster than we're willing to read. Sleep for what's
        // left of this read interval so the peer backs off.
        let throttle_duration =
            STREAM_THROTTLING_INTERVAL.saturating_sub(throttle_interval_start.elapsed());

        if !throttle_duration.is_zero() {
            debug!(
                "Throttling stream from {remote_addr:?}, peer type: {peer_type:?}, \
                 max_streams_per_interval: {max_streams_per_throttling_interval}, \
                 read_interval_streams: {streams_read_in_throttle_interval} throttle_duration: \
                 {throttle_duration:?}"
            );
            stats.throttled_streams.fetch_add(1, Ordering::Relaxed);
            match peer_type {
                ConnectionPeerType::Unstaked => {
                    stats
                        .throttled_unstaked_streams
                        .fetch_add(1, Ordering::Relaxed);
                }
                ConnectionPeerType::Staked(_) => {
                    stats
                        .throttled_staked_streams
                        .fetch_add(1, Ordering::Relaxed);
                }
            }
            sleep(throttle_duration).await;
        }
    }
}
```
