### Title
`AtlasConfig.attachments_max_size` is not enforced on attachment content accepted via the download path or via genesis loading - ([File: stackslib/src/net/atlas/db.rs])

### Summary
`AtlasDB::should_keep_attachment` is the only function that checks `attachment.content.len() <= attachments_max_size`, and it is called only from the RPC `POST /v2/attachments/new` path in `posttransaction.rs`. Neither the batch-resolution/download insertion path (`AtlasDB::insert_instantiated_attachment` / `insert_uninstantiated_attachment`) nor the genesis-attachment loading path (`AtlasDB::instantiate`) invoke this check, so a remote peer serving an oversized attachment body over `/v2/attachments/{hash}` can have it stored without a size bound.

### Finding Description
The equality the code is supposed to maintain is `len(Attachment.content) <= AtlasConfig.attachments_max_size` for every row written to the `attachments` table [1](#0-0)  The only place this equality is checked is `AtlasDB::should_keep_attachment`: [2](#0-1) 

That function is called exclusively by the user-transaction attachment path in `posttransaction.rs` and by test code — never by the downloader's insertion functions. The two insertion functions used when an attachment is fetched from a peer and matched against a queued/checked instance, `insert_uninstantiated_attachment` and `insert_instantiated_attachment`, write `attachment.content` directly into SQLite with no length check at all: [3](#0-2) [4](#0-3) 

Similarly, the genesis/config attachment loading path in `AtlasDB::instantiate` inserts every configured genesis attachment's content with no size check: [5](#0-4) 

Because `attachments_max_size` string only appears in `mod.rs`, `db.rs` (the `should_keep_attachment` definition), `config/mod.rs`, and `tests.rs`, and never in `download.rs`, the AttachmentsDownloader's batch resolution logic that ultimately calls `insert_instantiated_attachment`/`insert_uninstantiated_attachment` on data received from a remote peer's `/v2/attachments/{hash}` GET response has no size gate on the content before it is committed to `AtlasDB`. An attacker-controlled peer can therefore respond to an attachment request with a body far larger than `attachments_max_size` (bounded only by the generic HTTP payload/response size limit, which is much larger and configured independently of `attachments_max_size`), and the downloader will accept and persist it as long as its hash matches the requested `content_hash`.

### Impact Explanation
A malicious peer that legitimately serves attachment content (any remote node can be queried for attachments it claims to have) can force a victim node to store attachment blobs sized up to the HTTP layer's much larger generic body limit instead of the operator-configured `attachments_max_size`, defeating the intended per-attachment storage cap. Since attachment instances are queued from on-chain transaction events and get downloaded from multiple peers in the network, this allows storage-exhaustion amplification across nodes that resolve the same instance from the same or colluding malicious peers — a resource-exhaustion condition tied to a commitment (the `AttachmentInstance`) that nominally corresponds to a small attachment. This is repeatable per queued attachment instance and does not require any privileged role.

### Likelihood Explanation
The attacker only needs to run an ordinary peer that another node queries for a known/queued attachment instance (a normal, expected P2P/RPC interaction — no secret, no StackerDB slot ownership, no admin role required). The attacker crafts the HTTP response body to exceed `attachments_max_size` while still hashing to the expected `content_hash` (the attacker chooses arbitrary content for attachments it originates, or replays a previously-accepted oversized blob for any instance it can serve). This is straightforward and remotely reachable with low cost, and repeatable per instance.

### Recommendation
Enforce `should_keep_attachment` (or equivalently `content.len() <= atlas_config.attachments_max_size`) at every insertion path into the `attachments` table: in the downloader before calling `insert_uninstantiated_attachment`/`insert_instantiated_attachment` (reject/skip oversized responses and mark the instance as unavailable rather than storing), and in `AtlasDB::instantiate` when loading genesis/config attachments (fail fast or skip oversized genesis entries rather than trusting the local config blindly).

### Proof of Concept
1. In a `stackslib::net::atlas` test, construct an `AtlasConfig` with a small `attachments_max_size` (e.g., 10 bytes).
2. Queue an `AttachmentInstance` for a `content_hash` matching a crafted `Attachment { content: vec![0u8; 1000] }` (content larger than `attachments_max_size`, hash computed to match).
3. Drive the downloader's batch-resolution logic (the code path that calls `AtlasDB::insert_instantiated_attachment` on data returned from a simulated `/v2/attachments/{hash}` GET) with this oversized content.
4. Assert on `AtlasDB::find_attachment(&content_hash)`: currently it succeeds and returns the 1000-byte content, proving `insert_instantiated_attachment` at `stackslib/src/net/atlas/db.rs:576-592` stores content without checking `attachments_max_size`, in contrast to `should_keep_attachment` at `stackslib/src/net/atlas/db.rs:249-266` which would have rejected it.
5. Repeat similarly for `AtlasDB::instantiate` (genesis loading, `db.rs:211-247`) with an oversized `genesis_attachments` entry, confirming it is inserted unchecked.

    fn instantiate(&mut self) -> Result<(), db_error> {
        let genesis_attachments = self.atlas_config.genesis_attachments.take();

        let tx = self.tx_begin()?;

        for row_text in ATLASDB_INITIAL_SCHEMA {
            tx.execute_batch(row_text)?;
        }
        for row_text in ATLASDB_SCHEMA_2 {
            tx.execute_batch(row_text)?;
        }

        tx.execute(
            "INSERT INTO db_config (version) VALUES (?1)",
            params![ATLASDB_VERSION],
        )?;

        if let Some(attachments) = genesis_attachments {
            let now = util::get_epoch_time_secs() as i64;
            for attachment in attachments {
                tx.execute(
                    "INSERT INTO attachments (hash, content, was_instantiated, created_at) VALUES (?, ?, 1, ?)",
                    params![
                        attachment.hash(),
                        attachment.content,
                        now,
                    ],
                )
                .map_err(db_error::SqliteError)?;
            }
        }

        tx.commit().map_err(db_error::SqliteError)?;

        self.add_indexes()?;
        Ok(())
    }

    pub fn should_keep_attachment(
        &self,
        contract_id: &QualifiedContractIdentifier,
        attachment: &Attachment,
    ) -> bool {
        if !self.atlas_config.contracts.contains(contract_id) {
            info!(
                "Atlas: will discard posted attachment - {} not in supported contracts",
                contract_id
            );
            return false;
        }
        if attachment.content.len() as u32 > self.atlas_config.attachments_max_size {
            info!("Atlas: will discard posted attachment - attachment too large");
            return false;
        }
        true
    }

    pub fn insert_uninstantiated_attachment(
        &mut self,
        attachment: &Attachment,
    ) -> Result<(), db_error> {
        // Insert the new attachment
        let uninstantiated_attachments = self.count_uninstantiated_attachments()?;
        if uninstantiated_attachments >= self.atlas_config.max_uninstantiated_attachments {
            let to_delete =
                1 + uninstantiated_attachments - self.atlas_config.max_uninstantiated_attachments;
            self.evict_k_oldest_uninstantiated_attachments(to_delete)?;
        }

        let tx = self.tx_begin()?;
        let now = util::get_epoch_time_secs() as i64;
        let res = tx.execute(
            "INSERT OR REPLACE INTO attachments (hash, content, was_instantiated, created_at) VALUES (?, ?, 0, ?)",
            params![
                attachment.hash(),
                attachment.content,
                now,
            ],
        );
        res.map_err(db_error::SqliteError)?;
        tx.commit().map_err(db_error::SqliteError)?;
        Ok(())
    }

        &mut self,

        tx.execute(

        )?;
        tx.execute(
            "UPDATE attachment_instances SET is_available = 1 WHERE content_hash = ?1 AND status = ?2",
            params![attachment.hash(), AttachmentInstanceStatus::Checked],
        )?;
        tx.commit()?;
        Ok(())
    }
