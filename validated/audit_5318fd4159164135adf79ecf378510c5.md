### Title
Divide-before-multiply in `interestRatePerSecond()` truncates accrued interest and protocol fee on every accrual - (File: `contracts/DebtToken.sol`)

### Summary
`DebtToken.interestRatePerSecond()` computes `interestRate / SECONDS_PER_YEAR`, performing an integer division *before* the multiplication by the elapsed time in `_calculateInterestAccrual()`. The truncated remainder (up to `SECONDS_PER_YEAR - 1` wei of the wad-scaled APR) is lost on every accrual, so the `debtIndex` grows slower than the configured APR. Borrowers systematically underpay interest and the `feeCollector` systematically under-collects the synth fee minted in `accrueInterest()`.

### Finding Description
In `contracts/DebtToken.sol`:

- `interestRatePerSecond()` (line ~319) returns `interestRate / SECONDS_PER_YEAR` — division first, discarding the remainder of a wad-scaled value divided by ~31.5M.
- `_calculateInterestAccrual()` (lines ~559-565) then computes `_interestRateToAccrue = interestRatePerSecond() * (block.timestamp - lastTimestampAccrued)` and applies `_interestRateToAccrue.wadMul(totalSupply_)` for the accrued amount and `wadMul(debtIndex)` for the index.

Because the division is applied to the rate before scaling by elapsed time, the per-second rate is floored. The lost remainder is bounded by `SECONDS_PER_YEAR` (~3.15e7 wei), while typical per-second rates are ~3.17e8–3.17e9 (for 1%–10% APR), i.e. a systematic under-accrual of up to ~10% of the intended interest at low APRs and ~1% at 10% APR. The correct ordering is `interestRate * elapsed / SECONDS_PER_YEAR` (multiply first, then divide), which loses only the sub-wei remainder of the final product.

The bug is reachable by any unprivileged user: `DebtToken.issue()`, `DebtToken.repay()`, `DebtToken.mint()`/`flashIssue()` via `SmartFarmingManager`, `Pool.liquidate`, and a bare `accrueInterest()` call all flow through `_calculateInterestAccrual()`, and the floored per-second rate is embedded into `debtIndex`, which scales `balanceOf()` for every debtor and the synth minted to `pool.feeCollector()`.

### Impact Explanation
- Every borrower (including an attacker who opens a large, long-lived debt position via `issue()` or leveraged `SmartFarmingManager.leverage()` → `flashIssue`/`mint`) is charged a strictly lower effective APR than governance configured. The attacker captures the rounding delta as profit against the protocol.
- The feeCollector's interest fee minted in `accrueInterest()` (`syntheticToken.mint(pool.feeCollector(), _interestAmountAccrued + pendingInterestFee)`) is permanently reduced by the same relative amount — theft of protocol yield, continuous and compounding since `debtIndex` compounds the floored rate.
- `balanceOf()` uses `principal * debtIndex / debtIndexOf[account]`, so the understated index flows directly into `Pool.debtPositionOf`/`debtOf`, meaning collateral requirements and liquidation thresholds are evaluated against a smaller-than-intended debt — a marginal but systematic solvency weakening in the borrower's favor.

### Likelihood Explanation
Certain on every deployment where `interestRate` is not an exact multiple of `SECONDS_PER_YEAR` — practically always, since APR is set in wad units (e.g. `0.02e18`) and `31,557,600` does not divide typical wad values. No attacker setup is required beyond holding a debt position; the loss accrues automatically each second and compounds into `debtIndex`. The magnitude is bounded (fraction-of-a-percent to ~10% of interest depending on APR), which caps the severity, matching the Medium classification of the source report.

### Recommendation
Reorder so multiplication precedes division, e.g. in `_calculateInterestAccrual()`:

```solidity
uint256 _interestRateToAccrue = interestRate.wadMul(block.timestamp - _lastTimestampAccrued) / SECONDS_PER_YEAR;
```

or equivalently compute `interestRate * elapsed` first and divide by `SECONDS_PER_YEAR` once, eliminating `interestRatePerSecond()`'s intermediate truncation (keep it for external consumers but document the flooring, or return a higher-precision ray value).

### Proof of Concept
Hardhat-style test (drop into `test/DebtToken.test.ts` accrual suite):

```ts
it('under-accrues interest due to divide-before-multiply in interestRatePerSecond', async function () {
  const {msUSDDebt, msUSD, feeCollector, user1} = await loadFixture(fixture);
  const rate = parseEther('0.02'); // 2% APR
  await msUSDDebt.updateInterestRate(rate);

  const ONE_YEAR = 31557600; // SECONDS_PER_YEAR
  await time.increase(ONE_YEAR);
  await msUSDDebt.accrueInterest();

  // Exact math: interestRate * elapsed / SECONDS_PER_YEAR applied to principal
  const principal = parseEther('100');
  const exactInterest = principal.mul(rate.mul(ONE_YEAR).div(ONE_YEAR)).div(parseEther('1')); // = 2e18
  // Contract math: (rate / SPY) * SPY — remainder lost
  const perSec = await msUSDDebt.interestRatePerSecond(); // floor(2e16 / 31557600)
  const contractRate = perSec.mul(ONE_YEAR);              // < rate*1 (lost remainder)

  expect(contractRate).to.be.lt(rate);
  const loss = rate.sub(contractRate); // > 0: systematic under-accrual

  const debt = await msUSDDebt.balanceOf(user1.address);
  const feeMinted = await msUSD.balanceOf(feeCollector.address);
  // debt and feeMinted are both lower than 100e18 * (1 + 0.02)
  expect(debt).to.be.lt(principal.mul(102).div(100));
});
```

The numerical divergence is small per unit time but deterministic, continuous, benefits every borrower at the protocol's/feeCollector's expense, and compounds through `debtIndex` — reproducing the reported bug class on Metronome's own interest-accrual path.

Note: I verified the divide-before-multiply pattern directly in `DebtToken.sol` (`interestRatePerSecond` line ~319 feeding `_calculateInterestAccrual` lines ~559-565); `grep` hit counts were not itemized per-line so other fee-quote paths in `Pool.sol` were not exhaustively confirmed as free of the same pattern — the DebtToken path is nonetheless the strongest reachable analog.
