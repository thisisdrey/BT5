### Title
Unauthenticated `RecvError` packets allow remote tunnel-state poisoning and forced teardown without certificate verification - (File: outside.go)

### Summary
Nebula's `RecvError` control message is processed as an unencrypted, unauthenticated packet type. `handleRecvError` accepts it based solely on a source-address comparison against the value cached in the hostinfo, with no cryptographic proof that the sender holds the peer's static key or CA-signed certificate. This mirrors the reported Shardus bug class: a message that claims to originate from/relate to a legitimate, already-identified party is trusted and used to mutate protocol state (there: vote slot occupancy; here: tunnel/hostinfo existence) without verifying the authenticity of the claim.

### Finding Description
`readOutsidePackets` explicitly classifies `header.Handshake` and `header.RecvError` as "Unencrypted packets" and dispatches them before the tunnel's AEAD/decrypt step or any certificate check: [1](#0-0) 

`handleRecvError` then looks up the hostinfo by the reverse remote index (`h.RemoteIndex`, an attacker-supplied 32-bit value on an unauthenticated packet) and only guards against spoofing by comparing the packet's UDP source address to the address currently cached as the peer's remote: [2](#0-1) 

```go
func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	...
	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	...
	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?", ...)
		return
	}

	f.closeTunnel(hostinfo)
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
```
The only check preventing an attacker without a valid certificate/private key from forging this claim is matching the UDP source `netip.AddrPort` — a value trivially spoofable on UDP by an on-path or off-path attacker capable of IP spoofing, with no MAC, signature, or nonce tied to the claimed remote index. This is architecturally the same flaw pattern flagged in the report: acceptance of a message purportedly describing a peer's protocol state (there, a vote "from" a peer; here, an error "about" a peer's tunnel) without validating that the actual party authorized it, allowing an outsider with no CA-signed identity to manipulate consensus/tunnel state for a legitimate node.

`ShouldRecvError` defaults to `recvErrorAlways`, so by default every source is eligible: [3](#0-2) 

Note also the CHANGELOG documents this exact category of concern was previously tightened ("Disable sending `recv_error` messages when a packet is received outside the allowable counter window") and closetunnel packets were made to require authentication (`TestCloseTunnelAuthenticated` in `e2e/tunnels_test.go:471-573` shows `CloseTunnel` is now rejected when unauthenticated), but `RecvError` remains an unauthenticated, unencrypted message type that still directly triggers `closeTunnel` + `DeleteHostInfo`: [4](#0-3) [5](#0-4) 

### Impact Explanation
An attacker with no valid Nebula certificate can spoof UDP packets with `Type = header.RecvError` and a guessed/observed `RemoteIndex`, matching the victim's currently-known remote `AddrPort` (observable via traffic analysis on the wire, since Nebula runs over plain UDP), to force `closeTunnel` and `DeleteHostInfo` on the victim's live tunnel to a peer. Repeated forging can prevent stable tunnel establishment between two legitimate, correctly-certified peers, denying overlay connectivity — a remote state-poisoning/DoS impact on the mesh, similar in category (loss of ability for legitimate parties to make progress) to the total-network-shutdown impact in the reference report, though scoped to the affected tunnel(s) rather than a global consensus halt.

### Likelihood Explanation
Exploitability requires: (1) knowledge/observation of a live `RemoteIndex` and the current UDP `AddrPort` the sending side uses for that peer (learnable by observing UDP traffic on the path or by triggering handshakes/roams), and (2) the ability to spoof a UDP source address matching that `AddrPort`, or to be on-path. This is a lower bar than compromising a CA-signed certificate/private key, satisfying "no CA-signed certificate" reachability. It is not as trivially exploitable network-wide as the original report (which required no address spoofing and directly bricked global consensus), so likelihood is moderate rather than high.

### Recommendation
Do not act on `RecvError` (or any control-plane message that mutates tunnel/hostinfo state) unless it is authenticated — e.g., require it to be sent inside the AEAD-protected tunnel (like `CloseTunnel` now is, per `TestCloseTunnelAuthenticated`), or bind it to a value only the legitimate peer could produce (e.g., a MAC over recent counters using the established session key) instead of relying solely on UDP source-address comparison, which is spoofable.

### Proof of Concept
1. Establish two legitimate Nebula nodes A and B with valid CA-signed certs, complete a handshake, and observe/record B's local `remoteIndexId` for A's tunnel and A's currently-known `AddrPort` (learnable via passive network observation or by triggering a roam/probe).
2. From an unauthenticated host, craft a raw UDP packet with `header.H{Type: header.RecvError, RemoteIndex: <observed index>}` and source address spoofed to equal A's `AddrPort` as seen by B, and send it to B's listen port.
3. `readOutsidePackets` on B routes it via the unencrypted-packet switch directly to `handleRecvError` before any decrypt/cert check.
4. Since the spoofed source matches `hostinfo.GetRemote()`, B calls `closeTunnel` and `handshakeManager.DeleteHostInfo`, tearing down the legitimate tunnel without any cryptographic proof from A.
5. Repeating this whenever A and B attempt to re-handshake denies them stable connectivity, demonstrating remote state poisoning/DoS by an attacker holding no valid certificate.

func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
