## Finding

### Title
Cross-StackerDB replay of validly-signed chunks due to missing domain separation in `SlotMetadata::auth_digest` - (File: `libstackerdb/src/libstackerdb.rs`)

### Summary
The digest that a StackerDB writer signs over binds only `(slot_id, slot_version, data_hash)` and never binds the identity of the StackerDB instance (its controlling smart-contract `QualifiedContractIdentifier`) that the chunk is meant for. Because the same signer address can legitimately occupy the same `slot_id` in multiple different StackerDB-controlled contracts, a chunk that was validly signed and broadcast for one StackerDB can be relayed — verbatim, by any unprivileged network peer — into an entirely different StackerDB, where it will pass signature verification and be stored/re-broadcast as if it were freshly authorized for that context.

### Finding Description
`SlotMetadata::auth_digest` computes the signed message as: [1](#0-0) 

```
hash(slot_id.to_be_bytes() || slot_version.to_be_bytes() || data_hash.0)
```

There is no contract identifier, reward-cycle identifier, or any other value that scopes this signature to a *specific* StackerDB replica. `StackerDBChunkData::verify`/`SlotMetadata::verify` only check that this digest recovers to the `signer` address that the *target* contract's configuration says owns that `slot_id`: [2](#0-1) 

That signer-to-slot mapping is derived independently per contract via `eval_signer_slots`, which reads whatever `(signer, num-slots)` list the contract author supplies: [3](#0-2) 

Both the storage path (`try_replace_chunk`) and the network-facing validation path (`validate_received_chunk`, used for both `StackerDBChunkInv`/push-chunk handling and the `FutureView`-buffering path) perform exactly this signer-lookup-then-`verify()` check and nothing more: [4](#0-3) [5](#0-4) 

Since *any* StackerDB smart contract is permitted to declare any known-public `StacksAddress` as the owner of any `slot_id` (StackerDB is explicitly documented as being open to third-party, permissionless deployment — "any reachable Stacks node can fulfill requests… it is up to the StackerDB maintainer to convince node operators to replicate"): [6](#0-5) 

an attacker who controls (or deploys) a StackerDB contract can deliberately assign a well-known signer's address to the same `slot_id` that signer already uses in a legitimate StackerDB (e.g., a real `.signers-N-M` contract). The attacker then simply relays a chunk that the honest signer already broadcast for the real contract — obtained by passively observing gossip, since `StackerDBPushChunkData` is broadcast network-wide by `process_stacker_db_chunks`: [7](#0-6) 

into the attacker's own contract's `contract_id`. Because `auth_digest` never included the original `contract_id`, the identical `(slot_id, slot_version, data_hash)` triple recovers to the same legitimate signer address, and the message is accepted, stored, and further re-broadcast by any node replicating the attacker's contract — all without the real signer's participation or knowledge, and without the attacker needing any private key.

This is the structural analog of the ZetaChain "index too granular / not committing to enough context" bug: there, an under-specified hash allowed the *same* logical event to be replayed as "new" across an unintended future context; here, an under-specified signed digest allows the *same* signed message to be replayed as "authorized" across an unintended StackerDB context.

### Impact Explanation
This lets an unprivileged party propagate forged/attacker-selected historical data under the name and address of a legitimate signer/miner into an arbitrary StackerDB, which passes the node's `verify()` signature check and gets stored (`try_replace_chunk`) and rebroadcast (`process_stacker_db_chunks`). Any application or consumer of that StackerDB (including the node's own signer/miner logic if it happens to also read that DB) would treat this replayed chunk as authentically signed by the victim, since the on-chain "authenticate writes by public key hash" guarantee documented for StackerDB is silently broken across DB instances. This matches the "unauthorized write to state / network-wide propagation of forged data" High/Critical class described by the analog rules.

### Likelihood Explanation
Exploitation requires: (1) a node configured to replicate an attacker-controlled StackerDB contract (which the documentation explicitly allows to be permissionless/arbitrary), (2) the attacker arranging that contract's `stackerdb-get-signer-slots` to place a target victim address at the same `slot_id` used in a real StackerDB, and (3) capturing one legitimately-broadcast chunk from that victim (trivial, since chunks are broadcast network-wide). No secret key, admin role, or novel cryptographic break is required — only passive observation and a contract deployment the attacker fully controls. This is a realistic, low-cost, remote and unprivileged path.

### Recommendation
Include the StackerDB's `QualifiedContractIdentifier` (and ideally a reward-cycle/epoch or other context identifier as needed) in `SlotMetadata::auth_digest`, so that a signature is only valid for the specific StackerDB instance it was created for. This requires updating `SlotMetadata`/`StackerDBChunkData` signing and verification, and the call sites in `stackslib/src/net/stackerdb/db.rs` and `stackslib/src/net/stackerdb/mod.rs` that construct/verify the digest, being mindful of backward-compatibility/versioning for already-deployed contracts.

### Proof of Concept
1. Observe (via normal P2P gossip) a `StackerDBPushChunkData` broadcast for the real `.signers-1-1` contract, signed by victim signer `S` for `slot_id = 3`, `slot_version = 5`, with some `data`.
2. Deploy an attacker-controlled StackerDB contract `evil-db` whose `stackerdb-get-signer-slots` returns `S` as the owner of `slot_id = 3` (and any node with a low enough max-writes/version state), matching `parse_slot_entry`/`eval_signer_slots` requirements (`stackslib/src/net/stackerdb/config.rs`).
3. Get some node to configure/replicate `evil-db` (e.g., convince an operator, or if it's auto-added via a hint/discovery path).
4. Send a `StackerDBChunkData { slot_id: 3, slot_version: 5, sig: <victim's original sig>, data: <same data> }` targeting `evil-db`'s contract_id.
5. `validate_received_chunk`/`try_replace_chunk` recompute the same `auth_digest` (no contract binding), recover pubkey `S`, match the configured `slot_validation.signer`, and accept + store + rebroadcast the chunk as legitimately signed for `evil-db`, even though `S` never signed anything for `evil-db`.

    /// Get the digest to sign that authenticates this chunk data and metadata
    fn auth_digest(&self) -> Sha512Trunc256Sum {
        let mut hasher = Sha512_256::new();
        hasher.update(self.slot_id.to_be_bytes());
        hasher.update(self.slot_version.to_be_bytes());
        hasher.update(self.data_hash.0);
        Sha512Trunc256Sum::from_hasher(hasher)
    }

    /// Note that the address version is ignored.
    pub fn verify(&self, principal: &StacksAddress) -> Result<bool, Error> {
        let sigh = self.auth_digest();
        let pubk = StacksPublicKey::recover_to_pubkey_without_validating_low_s(
            sigh.as_bytes(),
            &self.signature,
        )
        .map_err(|ve| Error::VerifyingError(ve.to_string()))?;

        let pubkh = Hash160::from_node_public_key(&pubk);
        Ok(pubkh == *principal.bytes())
    }

    fn eval_signer_slots(
        chainstate: &mut StacksChainState,
        burn_dbconn: &dyn BurnStateDB,
        contract_id: &QualifiedContractIdentifier,
        tip: &StacksBlockId,
    ) -> Result<Vec<(StacksAddress, u32)>, NetError> {
        let value = chainstate.eval_read_only(
            burn_dbconn,
            tip,
            contract_id,
            &format!("({STACKERDB_SLOTS_FUNCTION})"),
        )?;

        let result = value.expect_result()?;
        let slot_list = match result {
            Err(err_val) => {
                let err_code = err_val.expect_u128()?;
                let reason = format!(
                    "Contract {} failed to run `stackerdb-get-signer-slots`: error u{}",
                    contract_id, &err_code
                );
                warn!("{}", &reason);
                return Err(NetError::InvalidStackerDBContract(
                    contract_id.clone(),
                    reason,
                ));
            }
            Ok(ok_val) => ok_val.expect_list()?,
        };

        let mut total_num_slots = 0u32;
        let mut ret = vec![];
        for slot_value in slot_list.into_iter() {
            let (addr, num_slots) =
                Self::parse_slot_entry(slot_value, contract_id).map_err(|e| {
                    warn!("Failed to parse StackerDB slot entry: {}", &e);
                    NetError::InvalidStackerDBContract(contract_id.clone(), e)
                })?;

            if num_slots > STACKERDB_INV_MAX {
                let reason = format!(
                    "Contract {} stipulated more than maximum number of slots for one signer ({})",
                    contract_id, STACKERDB_INV_MAX
                );
                warn!("{}", &reason);
                return Err(NetError::InvalidStackerDBContract(
                    contract_id.clone(),
                    reason,
                ));
            }

            total_num_slots =
                total_num_slots
                    .checked_add(num_slots)
                    .ok_or(NetError::OverflowError(format!(
                        "Contract {} stipulates more than u32::MAX slots",
                        &contract_id
                    )))?;

            if total_num_slots > STACKERDB_INV_MAX {
                let reason = format!(
                    "Contract {contract_id} stipulated more than the maximum number of slots"
                );
                warn!("{reason}");
                return Err(NetError::InvalidStackerDBContract(
                    contract_id.clone(),
                    reason,
                ));
            }

            ret.push((addr, num_slots));
        }
        Ok(ret)
    }

    /// Add or replace a chunk for a given reward cycle, if it is valid
    /// Otherwise, this errors out with Error::StaleChunk
    pub fn try_replace_chunk(
        &self,
        smart_contract: &QualifiedContractIdentifier,
        slot_desc: &SlotMetadata,
        chunk: &[u8],
    ) -> Result<(), net_error> {
        // Check per-replica chunk-size cap.
        if (chunk.len() as u64) > self.config.chunk_size {
            return Err(net_error::StackerDBChunkTooBig(chunk.len()));
        }

        let slot_validation = self
            .get_slot_validation(smart_contract, slot_desc.slot_id)?
            .ok_or(net_error::NoSuchSlot(
                smart_contract.clone(),
                slot_desc.slot_id,
            ))?;

        if !slot_desc.verify(&slot_validation.signer)? {
            return Err(net_error::BadSlotSigner(
                slot_validation.signer,
                slot_desc.slot_id,
            ));
        }
        if slot_desc.slot_version <= slot_validation.version {
            return Err(net_error::StaleChunk {
                supplied_version: slot_desc.slot_version,
                latest_version: slot_validation.version,
            });
        }
        if slot_desc.slot_version > self.config.max_writes {
            return Err(net_error::TooManySlotWrites {
                supplied_version: slot_desc.slot_version,
                latest_version: slot_validation.version,
                max_writes: self.config.max_writes,
            });
        }
        self.insert_chunk(smart_contract, slot_desc, chunk)
    }

/// StackerDBSet differ from AtlasDBs in that data chunks are not authenticated by the blockchain,
