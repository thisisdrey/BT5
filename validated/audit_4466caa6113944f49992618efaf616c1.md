### Title
Protocol fee bypass on NEP-245 (multi-token) TokenDiff legs via unit-size splitting - (File: `contracts/defuse/core/src/intents/token_diff.rs`)

### Summary
`TokenDiff::token_fee` waives the protocol fee whenever a `TokenIdType::Nep245` (or `Imt`) leg has `amount <= 1`, a rule meant for genuine NFT-like single-unit transfers. Because NEP-245 is the multi-token standard and can represent arbitrary, larger fungible-like balances under one `TokenId`, an attacker can split what would otherwise be one large negative delta (e.g. `-1000`) into many separate `TokenDiff` intents each with `delta == -1` on the same token, causing `Pips::fee_ceil` to be computed as `0` on every leg instead of the fee that would be owed on the aggregate.

### Finding Description
The broken binding is: fee owed on token `T` for a signer's total negative exposure `Σ|delta_T|` across a batch should equal `Pips::fee_ceil(Σ|delta_T|, protocol_fee)`, but the code instead computes fee **per intent, per leg**, using only that intent's own `amount = delta.unsigned_abs()`: [1](#0-0) 

`Self::token_fee` explicitly zeroes the fee for `Nep245`/`Imt` whenever the per-intent `amount <= 1`: [2](#0-1) 

Because `TokenId::Nep245` (the NEP-245 multi-token id) is not restricted to a supply of 1 like `Nep171` (single NFT), a signer can hold and trade arbitrarily large balances under one `Nep245` `TokenId`. An attacker who wants to trade `N` units of such a token (`N` large) with a counterparty can, instead of signing one `TokenDiff{ X: -N, Y: +Z }` (which would incur `fee_ceil(N)` on `X`), sign `N` separate `TokenDiff` payloads each `{ X: -1, Y: +z_i }` with distinct nonces, all included in the same `MultiPayload` batch alongside the counterparty's single aggregate `TokenDiff{ X: +N, Y: -Z }`. Each of these `N` intents independently executes `token_fee(X, amount=1, protocol_fee)`, which returns `Pips::ZERO` per [3](#0-2) , so `fee_ceil(1) == 0` for every leg. `TransferMatcher::finalize` only checks that per-token deltas across the whole batch net to zero [4](#0-3) ; it has no notion of "this signer's total negative exposure on `X` this batch" and therefore does not re-aggregate for fee purposes. No nonce, signature, or lock check inspects fee-relevant amount aggregation across intents, so the split is fully valid and undetected.

### Impact Explanation
The `fee_collector` under-collects protocol fees on the entire NEP-245 leg of the trade — potentially 100% of the fee that would be owed on an equivalent single `-N` delta — while the signer's and counterparty's balances still move the full intended amount. This is repeatable for any account, any NEP-245 `TokenId`, and any trade size, as long as the attacker is willing to sign `N` distinct intents (linear in trade size) instead of one. This matches the "protocol fees bypassed" Critical impact category, since it is systemic value that never reaches the fee_collector despite `protocol_fee > 0` being configured.

### Likelihood Explanation
Preconditions are minimal and fully within an unprivileged attacker's control: the attacker needs a NEP-245 balance inside the Verifier (or simply be one leg of any P2P/solver trade priced in an NEP-245 token) and the ability to sign `N` `TokenDiff` payloads with distinct nonces, which is ordinary wallet functionality, not a privileged operation. The only cost is `N` intents in one `MultiPayload`/transaction (linear signing cost, not gas-bound exploitation), and it works against any counterparty (a solver's single aggregate counter-intent still nets to zero in `TransferMatcher`). This is realistic for any market using NEP-245 as a fungible-like wrapped asset (e.g. multi-token representations of pooled/fractionalized assets).

### Recommendation
Compute the NEP-245/Imt "do not take fees" exemption based on the signer's aggregated negative delta for that token across the whole intent/batch (or simply remove the `amount <= 1` fee exemption for `Nep245`/`Imt`, reserving the zero-fee carve-out strictly for `Nep171` where per-token supply is inherently 1), so that splitting a trade into unit legs cannot reduce total fee owed below `fee_ceil` of the aggregate delta.

### Proof of Concept
`cargo test` plan (extending `contracts/defuse/core/src/intents/token_diff.rs` or `tests/src/tests/defuse/intents/token_diff.rs`):
1. Configure `Env::builder().fee(Pips::ONE_PERCENT)` (or any nonzero fee) with a NEP-245 token `mt.near:tokenA` and two users, `attacker` and `counterparty`.
2. Deposit `attacker` with `1000` units of `mt.near:tokenA` and `counterparty` with sufficient `ft.near` balance.
3. Path A (baseline): `attacker` signs one `TokenDiff{ tokenA: -1000, ft: +closure }`, `counterparty` signs the matching `TokenDiff{ tokenA: +1000, ft: -Z }`; execute via `execute_intents`; assert `fees_collected` on `tokenA` equals `Pips::ONE_PERCENT.fee_ceil(1000)` (nonzero).
4. Path B (exploit): `attacker` signs `1000` separate `TokenDiff{ tokenA: -1, ft: +z_i }` intents (distinct nonces), `counterparty` signs one `TokenDiff{ tokenA: +1000, ft: -Z }`; bundle all `1001` payloads into one `MultiPayload` and call `execute_intents`.
5. Assert: total `fees_collected` on `tokenA` in Path B is `0`, while Path A's is `Pips::ONE_PERCENT.fee_ceil(1000) > 0`, despite both moving identical net `1000` units of `tokenA` — proving fee under-collection strictly from leg-splitting with no other behavioral difference.

    // Finalizes all transfers, or returns unmatched deltas.
    // If unmatched deltas overflow, then Err(None) is returned.
    pub fn finalize(self) -> Result<Transfers, InvariantViolated> {
        let mut transfers = Transfers::default();
        let mut deltas = TokenDeltas::default();
        for (token_id, transfer_matcher) in self.0 {
            if let Err(unmatched) = transfer_matcher.finalize_into(&token_id, &mut transfers)
                && (unmatched == 0 || deltas.apply_delta(token_id, unmatched).is_none())
            {
                return Err(InvariantViolated::Overflow);
            }
        }
        if !deltas.is_empty() {
            return Err(InvariantViolated::UnmatchedDeltas {
                unmatched_deltas: deltas,
            });
        }
        Ok(transfers)
    }
