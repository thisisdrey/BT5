### Title
Duplicate-weight counting for a single key in `ValidateMultiSign` precompile can bypass the permission threshold - (`File: actuator/src/main/java/org/tron/core/vm/PrecompiledContracts.java`)

### Summary
The `ValidateMultiSign` TVM precompile computes the total signing weight for a multi-sig `Permission` by iterating over the supplied signatures and summing the weight of each recovered address. Its de-duplication logic only skips a signature when the *exact byte sequence* of a previous signature for the same recovered address is repeated; it does not prevent counting the weight of the same address twice when two *different* valid signature byte-strings recover to the same address.

### Finding Description
In `PrecompiledContracts.ValidateMultiSign.execute` [1](#0-0) , the dedup check is:
```
if (ByteArray.matrixContains(executedSignList, recoveredAddr)) {
  if (ByteArray.matrixContains(executedSignList, sign)) {
    continue;
  }
  MUtil.checkCPUTime();
}
long weight = TransactionCapsule.getWeight(permission, recoveredAddr);
...
totalWeight += weight;
executedSignList.add(sign);
executedSignList.add(recoveredAddr);
```
When `recoveredAddr` has already appeared but the current `sign` bytes differ from any previously seen signature for that address, the code does **not** `continue`/reject — it merely calls `MUtil.checkCPUTime()` (a CPU-time guard) and then falls through to add the key's weight to `totalWeight` again. This is the exact analog of the Ronin bug class described in the report: the multisig weight accounting can be inflated ("modification of weight to an unexpected value") so that the threshold check `totalWeight >= permission.getThreshold()` at [2](#0-1)  succeeds without genuinely independent authorizations equal to the threshold.

This is only exploitable if a single private key can produce two distinct, valid 65-byte signatures over the same message hash that both recover to the same address (e.g., via ECDSA signature malleability, s vs n−s with adjusted recovery id). I was not able to confirm from the retrieved code whether `ECKey`/`SignUtils` enforce canonical (low-S) signatures on this recovery path (`recoverAddrBySign` in the same file), so this precondition is not fully proven and should be verified against `crypto/src/main/java/org/tron/common/crypto/ECKey.java` and the `recoverAddrBySign` helper in `PrecompiledContracts.java` before treating this as confirmed.

### Impact Explanation
If malleable signatures are accepted by the recovery path, a caller could satisfy `ValidateMultiSign` (and thus any smart contract logic gating fund transfers/approvals on this precompile) with fewer independently-controlled keys than the permission's threshold requires, by supplying two differently-encoded signatures from a single controlled key. Any contract relying on this precompile as an on-chain multi-sig gate for asset movement would be bypassable, directly mirroring the Ronin bridge's threshold-bypass loss of funds.

### Likelihood Explanation
Exploitability hinges entirely on whether the signature recovery path used by this precompile accepts non-canonical/malleable signatures for the same key producing distinct byte encodings. This precondition could not be confirmed with the available evidence, so likelihood is uncertain pending verification of `recoverAddrBySign` and the underlying `ECKey`/`SM2` signature validation/canonicalization rules.

### Recommendation
Change the dedup logic to key strictly on `recoveredAddr` (not on the raw signature bytes): once an address's weight has been counted once, any further signature recovering to the same address must be skipped outright, regardless of its byte encoding. Additionally, confirm/enforce canonical (low-S) signature validation in the recovery path used by this precompile to eliminate the malleability precondition entirely.

### Proof of Concept
Conceptual (not fully verified due to tool-call limits):
1. Create a `Permission` with threshold `T` and multiple keys, where key `K1` alone has weight `< T` but two keys' combined weight `>= T`.
2. Using only `K1`, produce two distinct valid signatures over the same `hash` (e.g., by flipping `s` to `n - s` and adjusting the recovery id, if the recovery path accepts this).
3. Submit both signatures as the `sigs` array to `ValidateMultiSign`.
4. If the recovery path treats both as valid and recovers the same address `K1`, the loop's dedup check (matching on exact `sign` bytes, not address) fails to prevent double counting, and `totalWeight` reaches `T` using only one real key — bypassing the intended multi-signature threshold.   public static class ValidateMultiSign extends PrecompiledContract {

    private static final int ENGERYPERSIGN = 1500;
    private static final int MAX_SIZE = 5;
    private static final int ABI_HEADER_WORDS = 5;
    private static final int ABI_ITEM_WORDS = 5;


    @Override
    public long getEnergyForData(byte[] data) {
      long cnt = (data.length / WORD_SIZE - 5) / 5;
      // one sign 1500, half of ecrecover
      return cnt * ENGERYPERSIGN;
    }

    @Override
    public Pair<Boolean, byte[]> execute(byte[] rawData) {
      if (VMConfig.allowTvmOsaka()
          && !isValidAbiEncoding(rawData, ABI_HEADER_WORDS, ABI_ITEM_WORDS)) {
        return Pair.of(false, EMPTY_BYTE_ARRAY);
      }
      DataWord[] words = DataWord.parseArray(rawData);
      byte[] address = words[0].toTronAddress();
      int permissionId = words[1].intValueSafe();
      byte[] data = words[2].getData();

      byte[] combine = ByteUtil.merge(address, ByteArray.fromInt(permissionId), data);
      byte[] hash = Sha256Hash.hash(CommonParameter
          .getInstance().isECKeyCryptoEngine(), combine);

      if (VMConfig.allowTvmSelfdestructRestriction()) {
        int sigArraySize = words[words[3].intValueSafe() / WORD_SIZE].intValueSafe();
        if (sigArraySize > MAX_SIZE) {
          return Pair.of(true, DATA_FALSE);
        }
      }
      byte[][] signatures = VMConfig.allowTvmSelfdestructRestriction() ?
          extractSigArray(words, words[3].intValueSafe() / WORD_SIZE, rawData) :
          extractBytesArray(words, words[3].intValueSafe() / WORD_SIZE, rawData);

      if (signatures.length == 0 || signatures.length > MAX_SIZE) {
        return Pair.of(true, DATA_FALSE);
      }

      AccountCapsule account = this.getDeposit().getAccount(address);
      if (account != null) {
        try {
          Permission permission = account.getPermissionById(permissionId);
          if (permission != null) {
            //calculate weight
            long totalWeight = 0L;
            List<byte[]> executedSignList = new ArrayList<>();
            for (byte[] sign : signatures) {
              byte[] recoveredAddr = recoverAddrBySign(sign, hash);

              sign = merge(recoveredAddr, sign);
              if (ByteArray.matrixContains(executedSignList, recoveredAddr)) {
                if (ByteArray.matrixContains(executedSignList, sign)) {
                  continue;
                }
                MUtil.checkCPUTime();
              }
              long weight = TransactionCapsule.getWeight(permission, recoveredAddr);
              if (weight == 0) {
                //incorrect sign
                return Pair.of(true, DATA_FALSE);
              }
              totalWeight += weight;
              executedSignList.add(sign);
              executedSignList.add(recoveredAddr);
            }

            if (totalWeight >= permission.getThreshold()) {
              return Pair.of(true, dataOne());
            }
          }
        } catch (Throwable t) {
          if (t instanceof OutOfTimeException) {
            throw t;
          }
          logger.info("ValidateMultiSign error:{}", t.getMessage());
        }
      }
      return Pair.of(true, DATA_FALSE);
    }
  }
