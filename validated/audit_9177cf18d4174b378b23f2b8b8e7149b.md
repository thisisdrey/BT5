### Title
Protocol fees on Nep245/Imt `TokenDiff` trades can be bypassed by splitting a trade into amount=1 legs - (File: `contracts/defuse/core/src/intents/token_diff.rs`)

### Summary
`TokenDiff::token_fee` waives the protocol fee entirely whenever the per-intent `|delta| <= 1` for `Nep245`/`Imt` token types, and `TokenDiff::execute_intent` computes the fee independently for each `TokenDiff` intent using only that intent's own delta, not the aggregate volume traded on that token within the batch. Any unprivileged signer can therefore decompose a Nep245/Imt trade of any size into many amount=1 `TokenDiff` legs (matched against corresponding +1 legs elsewhere in the same `MultiPayload` batch, which the attacker fully controls) to reduce the total collected protocol fee to zero, whereas expressing the same net trade as a single `TokenDiff` would incur a nonzero fee.

### Finding Description
The broken binding: for a fixed net trade of `N` units on a given Nep245/Imt `token_id` inside one settled batch, the total fee collected by the protocol should be invariant to how that trade is split across multiple signed `TokenDiff` intents in that batch:

`Σ fees_collected(token_id) == TokenDiff::token_fee(token_id, N, fee).fee_ceil(N)`

```rust
pub fn token_fee(token_id: impl Into<TokenIdType>, amount: u128, fee: Pips) -> Pips {
    let token_id = token_id.into();
    match token_id {
        TokenIdType::Nep141 => {}
        TokenIdType::Nep245 | TokenIdType::Imt if amount > 1 => {}
        // do not take fees on NFTs and MTs with |delta| <= 1
        TokenIdType::Nep171 | TokenIdType::Nep245 | TokenIdType::Imt => return Pips::ZERO,
    }
    fee
}
``` [2](#0-1) 

fee is derived from `amount = delta.unsigned_abs()` of the *single* `TokenDiff` currently being executed, and added to `fees_collected` for that intent only. Since `execute_signed_intents` iterates over independent `MultiPayload` entries and each `TokenDiff::execute_intent` call is oblivious to how much of the same token other intents in the batch move, the exemption is evaluated per-leg, not per aggregate trade.

Exploit: instead of signing one `TokenDiff` with `diff = {nep245_token: -N}` (which for `N>1` charges `fee.fee_ceil(N) > 0` when `fee>0`), the attacker signs `N` separate `TokenDiff` intents (from one or more accounts they control) each with `diff = {nep245_token: -1}`, matched by corresponding `+1` deposits elsewhere in the same batch (e.g., from the attacker's own second account, or from a cooperating counterparty). Each of these legs hits the `amount <= 1` branch of `token_fee`, returning `Pips::ZERO`, so `fee_ceil(1) == 0` for every leg. The overall batch still satisfies `TransferMatcher::finalize`'s net-zero invariant (`contracts/defuse/core/src/engine/state/deltas.rs:267-283`), because the attacker controls the matching legs, so the batch settles successfully with zero fee collected on that token, versus a nonzero fee if the same net amount had been expressed as one `TokenDiff`.

No existing guard catches this: `MultiPayload::verify`, nonce/salt checks, and the `TransferMatcher` invariant all operate correctly and are unrelated to fee sizing; the fee computation itself is the flawed component, and it is evaluated strictly per-intent-leg rather than per aggregate token volume in the batch.

### Impact Explanation
Protocol fees are under-collected/bypassed for any Nep245 or Imt token trade, which is explicitly listed as a Critical impact ("protocol fees bypassed or over-collected"). The fee_collector account (`engine.state.fee_collector()`, credited via `internal_add_balance` in `execute_intent`) receives less than it is owed for every Nep245/Imt trade that an attacker chooses to split into unit legs. This is fully repeatable: any account, any Nep245/Imt token, any volume — the larger the trade, the more fee is avoided in absolute terms (fee avoided scales with the whole trade size, not just the marginal unit boundary).

### Likelihood Explanation
No privileged role, relayer key, or victim signature is needed. The attacker only needs to: (1) hold or acquire a Nep245/Imt balance in the Verifier (normal deposit flow), (2) sign multiple `TokenDiff` `DefusePayload`s with their own key(s), and (3) submit them together via `execute_intents`/`simulate_intents`. Splitting a trade of size `N` into `N` unit legs costs additional gas/payload size but no extra economic cost, and is fully within the "ordinary signer" capability described in the attacker profile. This is trivially repeatable across any batch, any Nep245/Imt token, and any counterparty (including self-trading across two attacker-controlled accounts).

### Recommendation
Compute the Nep245/Imt fee exemption and fee amount based on the aggregate negative delta accumulated for that `token_id` across the whole settling batch (e.g., inside `TransferMatcher`/`Deltas` after all intents are collected, or by tracking per-token per-batch cumulative `amount` before evaluating the `amount > 1` threshold), rather than per individual `TokenDiff` intent. Alternatively, remove the `amount <= 1` fee exemption for `Nep245`/`Imt` altogether (charge `fee_ceil` unconditionally like `Nep141`), reserving the exemption only for genuinely atomic `Nep171` NFTs.

### Proof of Concept
`cargo test` plan (unit-level, in `contracts/defuse/core/src/intents/token_diff.rs::tests`, extendable to a `near-workspaces`/sandbox batch test):

1. Construct a `Nep245TokenId` (fungible-like sub-token, e.g. `"mt.near:ft1"`) and a nonzero `fee: Pips` (e.g. `Pips::ONE_PERCENT`).
2. Compute `fee_single = TokenDiff::token_fee(&token_id, 2, fee).fee_ceil(2)` — expected `> 0`.
3. Compute `fee_split = TokenDiff::token_fee(&token_id, 1, fee).fee_ceil(1) * 2` — expected `== 0`.
4. `assert_ne!(fee_single, fee_split)` and `assert!(fee_split < fee_single)`, demonstrating collected fee is strictly reduced by splitting.
5. (Sandbox extension) Build two `MultiPayload` batches settling the identical net trade of `-2`/`+2` on the same Nep245 token between two accounts: (a) one batch with a single `TokenDiff{diff: {token: -2}}` vs matching `+2`; (b) one batch with two `TokenDiff{diff: {token: -1}}` intents vs two matching `+1` intents. Call `execute_intents` on each in a fresh sandbox state and assert the fee_collector's post-trade balance for `token_id` is nonzero in case (a) and zero in case (b), proving the fee bypass end-to-end without touching mainnet.
