Confirmed: both `UnfreezeBalanceV2Actuator.execute()` (`actuator/src/main/java/org/tron/core/actuator/UnfreezeBalanceV2Actuator.java`) and `UnfreezeBalanceV2Processor.execute()` (`actuator/src/main/java/org/tron/core/vm/nativecontract/UnfreezeBalanceV2Processor.java`) define a `updateAccountFrozenInfo()`-style decrement method but never call it to actually subtract the unfrozen amount from the account's `frozenV2List` entry.

### Title
Unfreeze (Stake2.0) never decrements FreezeV2.amount, allowing unlimited repeated unfreeze and unbacked balance creation - ([File: actuator/src/main/java/org/tron/core/actuator/UnfreezeBalanceV2Actuator.java])

### Summary
`UnfreezeBalanceV2Actuator` and its TVM-facing twin `UnfreezeBalanceV2Processor` validate an unfreeze request against `AccountCapsule.getFrozenV2List()` (the account's staked/frozen amount per resource type) and then execute the unfreeze by adding an entry to `UnfrozenV2` and reducing global resource weight counters — but the code path that is supposed to subtract the unfrozen amount from the `FreezeV2` entry (`updateAccountFrozenInfo`) is dead code: it is defined in `UnfreezeBalanceV2Actuator` but never invoked from `execute()`, and no equivalent call exists at all in `UnfreezeBalanceV2Processor.execute()`. This mirrors the mirage-xen bug class: a check exists (`checkExistFrozenBalance`/`checkUnfreezeBalance`) that is supposed to gate a state-clearing operation, but the corresponding "commit"/"clear" step that should make the check's precondition become false afterward is never actually applied, so the same underlying resource can be treated as still fully "frozen" and unfrozen again and again.

### Finding Description [1](#0-0) 
`execute()` computes `unfreezeAmount` from expired unfreeze entries, adds the newly requested `unfreezeBalance` to `UnfrozenV2` list, calls `updateTotalResourceWeight` (which only touches the aggregate `FrozenBalanceForBandwidthV2`/`EnergyV2`/`TronPowerV2` counters used for bandwidth/energy weight bookkeeping) and `updateVote`, then persists the account — but it never calls `updateAccountFrozenInfo`, the method defined at: [2](#0-1) 
which is the only code in the class that actually decrements the `FreezeV2.amount` field per resource type in `accountCapsule.getFrozenV2List()`.

`validate()` relies exclusively on that `FreezeV2.amount` field to gate the operation: [3](#0-2) 
`checkExistFrozenBalance` returns true as long as any `FreezeV2` entry for the resource type has `amount > 0`, and `checkUnfreezeBalance` only requires `unfreezeBalance <= frozenAmount`. Since `frozenAmount` is never reduced after a successful unfreeze, both checks keep passing for the original frozen amount indefinitely.

The same missing-decrement pattern exists in the TVM native-contract path used when a smart contract calls the unfreeze precompile: [4](#0-3) 
`execute()` here also omits any call to decrement `FreezeV2.amount`.

### Impact Explanation
An account that froze `X` TRX for BANDWIDTH/ENERGY/TRON_POWER can repeatedly submit `UnfreezeBalanceV2Contract` transactions (or invoke the corresponding TVM native contract from a smart contract) for up to `X` each time, since `FreezeV2.amount` for that resource type is never reduced by the actuator/processor. Each successful call adds `unfreezeBalance` to the account's `UnfrozenV2` list, which after the unfreeze delay period matures into real, spendable TRX balance via `WithdrawExpireUnfreezeActuator`/`CancelAllUnfreezeV2Actuator`. This lets an attacker who froze `X` TRX withdraw `N * X` TRX (bounded only by `UNFREEZE_MAX_TIMES = 32` pending unfreeze slots and the `getUnfreezingV2Count` limit, but each entry can independently mature and be withdrawn, freeing slots for more), creating unbacked TRX balance out of thin air — a direct theft/inflation of funds. It also permanently corrupts total resource weight accounting since `updateTotalResourceWeight` keeps subtracting from the global bandwidth/energy/tron-power weight totals for balances that were never actually reduced on the account's frozen ledger, further destabilizing the network's resource-pricing model.

### Likelihood Explanation
Reachable directly and unprivileged: any account holder who has frozen even a small amount of TRX for bandwidth/energy under Stake 2.0 can trigger `UnfreezeBalanceV2Contract` via a normal signed transaction, or any TVM contract can call the corresponding native contract. No special permissions, witness/SR status, or timing tricks beyond the existing `UNFREEZE_MAX_TIMES` per-account throttle (32 concurrent pending unfreezes) are required, and pending unfreezes can be withdrawn/cleared (via `WithdrawExpireUnfreezeContract` or `CancelAllUnfreezeV2Contract`) to free slots and repeat the cycle indefinitely.

### Recommendation
Call `updateAccountFrozenInfo(freezeType, accountCapsule, unfreezeBalance)` in `UnfreezeBalanceV2Actuator.execute()` immediately after computing `unfreezeBalance`, and add an equivalent decrement of the matching `FreezeV2` entry in `UnfreezeBalanceV2Processor.execute()`, ensuring the account's `FreezeV2.amount` is authoritatively reduced before it is persisted so `checkExistFrozenBalance`/`checkUnfreezeBalance` correctly reflect the remaining frozen balance on subsequent calls.

### Proof of Concept
1. Account `A` freezes `1000 TRX` for BANDWIDTH via `FreezeBalanceV2Contract` → `FreezeV2{type=BANDWIDTH, amount=1000}`.
2. `A` submits `UnfreezeBalanceV2Contract{resource=BANDWIDTH, unfreeze_balance=1000}`. `validate()` passes (`checkExistFrozenBalance` true, `checkUnfreezeBalance` true since `1000 <= 1000`). `execute()` adds `UnFreezeV2{amount=1000}` to the pending list and reduces `FrozenBalanceForBandwidthV2` global weight counter, but leaves `FreezeV2.amount` at `1000`.
3. `A` repeats step 2 up to 32 times (or interleaved with withdrawing matured entries via `WithdrawExpireUnfreezeContract`), each time passing validation because `FreezeV2.amount` is still `1000`.
4. After the unfreeze delay elapses, `A` withdraws each matured `UnFreezeV2` entry via `WithdrawExpireUnfreezeActuator`, receiving `1000 TRX` per entry — far exceeding the `1000 TRX` originally frozen.

  public boolean checkExistFrozenBalance(AccountCapsule accountCapsule, ResourceCode freezeType) {
    List<FreezeV2> frozenV2List = accountCapsule.getFrozenV2List();
    for (FreezeV2 frozenV2 : frozenV2List) {
      if (frozenV2.getType().equals(freezeType) && frozenV2.getAmount() > 0) {
        return true;
      }
    }
    return false;
  }

  public boolean checkUnfreezeBalance(AccountCapsule accountCapsule,
                                      final UnfreezeBalanceV2Contract unfreezeBalanceV2Contract,
                                      ResourceCode freezeType) {
    boolean checkOk = false;

    long frozenAmount = 0L;
    List<FreezeV2> freezeV2List = accountCapsule.getFrozenV2List();
    for (FreezeV2 freezeV2 : freezeV2List) {
      if (freezeV2.getType().equals(freezeType)) {
        frozenAmount = freezeV2.getAmount();
        break;
      }
    }

    if (unfreezeBalanceV2Contract.getUnfreezeBalance() > 0
        && unfreezeBalanceV2Contract.getUnfreezeBalance() <= frozenAmount) {
      checkOk = true;
    }

    return checkOk;
  }

  public void updateAccountFrozenInfo(ResourceCode freezeType, AccountCapsule accountCapsule, long unfreezeBalance) {
    List<FreezeV2> freezeV2List = accountCapsule.getFrozenV2List();
    for (int i = 0; i < freezeV2List.size(); i++) {
      if (freezeV2List.get(i).getType().equals(freezeType)) {
        FreezeV2 freezeV2 = FreezeV2.newBuilder()
            .setAmount(freezeV2List.get(i).getAmount() - unfreezeBalance)
            .setType(freezeV2List.get(i).getType())
            .build();
        accountCapsule.updateFrozenV2List(i, freezeV2);
        break;
      }
    }
  }

  public long execute(UnfreezeBalanceV2Param param, Repository repo) {
    byte[] ownerAddress = param.getOwnerAddress();
    long unfreezeBalance = param.getUnfreezeBalance();
    VoteRewardUtil.withdrawReward(ownerAddress, repo);

    AccountCapsule accountCapsule = repo.getAccount(ownerAddress);
    long now = repo.getDynamicPropertiesStore().getLatestBlockHeaderTimestamp();

    long unfreezeExpireBalance = this.unfreezeExpire(accountCapsule, now);

    if (repo.getDynamicPropertiesStore().supportAllowNewResourceModel()
        && accountCapsule.oldTronPowerIsNotInitialized()) {
      accountCapsule.initializeOldTronPower();
    }

    long expireTime = this.calcUnfreezeExpireTime(now, repo);
    accountCapsule.addUnfrozenV2List(param.getResourceType(), unfreezeBalance, expireTime);

    this.updateTotalResourceWeight(accountCapsule, param.getResourceType(), unfreezeBalance, repo);
    this.updateVote(accountCapsule, param.getResourceType(), ownerAddress, repo);

    if (repo.getDynamicPropertiesStore().supportAllowNewResourceModel()
        && !accountCapsule.oldTronPowerIsInvalid()) {
      accountCapsule.invalidateOldTronPower();
    }

    repo.updateAccount(accountCapsule.createDbKey(), accountCapsule);
    return unfreezeExpireBalance;
  }
