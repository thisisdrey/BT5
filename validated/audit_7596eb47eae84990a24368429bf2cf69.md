### Title
Reward-Siphoning via Last-Block Vote Reallocation Before Maintenance Cycle Boundary - (File: `chainbase/src/main/java/org/tron/core/service/MortgageService.java`, `consensus/src/main/java/org/tron/consensus/dpos/MaintenanceManager.java`)

### Summary
TRON's SR voting-reward algorithm computes each witness's per-cycle reward index (`Vi`) using the witness's *total* vote count observed at the instant `doMaintenance()` runs, not a time-weighted average over the cycle. A voter (`VoteWitnessContract`) can move an existing, already-frozen TRON Power onto a witness in the very last block of a maintenance cycle and reallocate it away in the first block of the next cycle, capturing a full cycle's proportional reward share for a witness despite having voted for that witness for only a fraction of a second of real time. This mirrors the reported `distribute()`/`harvest()` MEV pattern: staking immediately before a reward snapshot and unstaking immediately after to capture rewards not proportionally earned.

### Finding Description
Witness reward accrual works as follows:

1. Per-block/tx-fee rewards accumulate continuously into `delegationStore.addReward(cycle, witness, value)` via `MortgageService.payReward()`. [1](#0-0) 

2. At the maintenance boundary, `MaintenanceManager.doMaintenance()` snapshots the cycle's `Vi` (reward-per-vote index) using the witness's **current** `voteCount`, i.e. whatever votes are present at that exact instant: [2](#0-1) 

3. `DelegationStore.accumulateWitnessVi()` divides the *entire cycle's* accumulated reward by that instantaneous vote count to produce `deltaVi`: [3](#0-2) 

4. A voter's reward for a cycle is `deltaVi * userVoteCount` — the *full* cycle's delta, with no intra-cycle time weighting: [4](#0-3) 

5. Changing votes (`VoteWitnessActuator.countVoteAccount` / `VoteWitnessProcessor.execute`) has no cooldown and immediately calls `withdrawReward()` (settling prior rewards) before recording the new vote allocation for the current cycle: [5](#0-4) [6](#0-5) 

`MortgageService.withdrawReward()` sets `beginCycle = endCycle = currentCycle` when settling, so a vote cast in the current (still open) cycle is tracked from `beginCycle = currentCycle` — meaning the *entire* upcoming `Vi` delta for that cycle (computed at the next maintenance) applies to the new vote allocation, regardless of how briefly it was actually held during that cycle. [6](#0-5) 

There is no minimum holding-period, cooldown, or time-weighting check in `VoteWitnessActuator.validate()` — only a check that the total vote count does not exceed TRON Power: [7](#0-6) 

An account that already holds TRON Power (frozen balance) — no flash loan needed, since voting itself has no lock, only the underlying freeze does — can:
1. Submit a `VoteWitnessContract` in the last block before the cycle boundary, redirecting all votes onto witness `W` (which has accrued a large unclaimed reward pool for the cycle).
2. Let `doMaintenance()` snapshot `Vi` for that cycle using the now-inflated vote total including the attacker's votes.
3. Submit `WithdrawRewardContract`/query reward, then immediately redirect votes elsewhere in the very next block.

This captures a share of the entire cycle's reward for witness `W` proportional to the attacker's vote weight, diluting the legitimate share earned by voters who backed `W` for the whole cycle — effectively siphoning rewards from long-term voters, the same mechanism as flash-staking around a `distribute()` call in the external report.

### Impact Explanation
This allows an account with existing TRON Power to repeatedly extract a disproportionate share of SR/vote rewards every maintenance cycle (~6 hours) at the expense of voters who genuinely held their votes for the full cycle, resulting in ongoing, low-cost theft of reward funds from other stakers. This is a concrete unauthorized transfer-of-value bug class (reward siphoning), matching the report's "theft of part of the reward from actual stakers."

### Likelihood Explanation
Likelihood is Medium: the attacker needs pre-existing frozen TRX (TRON Power) — this is not a flash-loan-in-one-block attack because freezing has an unlock delay — but reallocating already-owned voting power between witnesses is completely unrestricted and free, requiring only correctly-timed transactions around known, public maintenance-cycle boundaries (cycle timing is deterministic/on-chain and can be computed in advance), making the exploit trivially repeatable every cycle by any account holding TRON Power.

### Recommendation
- Time-weight vote rewards within a cycle (e.g., prorate `Vi` contribution by the number of blocks/time a given vote allocation was actually held), rather than using a single end-of-cycle snapshot of `voteCount`.
- Alternatively, freeze the vote allocation used for `Vi` computation at the start of the cycle (before block-reward accrual begins) rather than at the maintenance instant, so late-cycle vote changes cannot retroactively claim a share of already-accrued rewards.
- Consider a minimum holding period for votes before they become reward-eligible for the cycle in which they were cast.

### Proof of Concept
1. Attacker already has frozen TRX and TRON Power `P`, currently voting for witness `A`.
2. Witness `B` has accumulated a large reward pool this cycle via `payBlockReward`/`payTransactionFeeReward` (`MortgageService.payReward`) but has few voters.
3. In the last block before the maintenance boundary, attacker sends `VoteWitnessContract` reallocating all `P` votes from `A` to `B`. `VoteWitnessProcessor.execute`/`VoteWitnessActuator.countVoteAccount` records `B`'s new vote weight with `beginCycle = currentCycle`.
4. Block triggers `MaintenanceManager.doMaintenance()`; `accumulateWitnessVi` computes `deltaVi` for `B` using `witness.getVoteCount()`, now including attacker's `P`.
5. Attacker calls `WithdrawRewardContract`/`queryReward`; `MortgageService.computeReward` grants attacker `deltaVi * P`, the full cycle's proportional share, despite holding the vote for only one block.
6. Attacker immediately reallocates votes back to `A` (or elsewhere), repeating next cycle.

  public void withdrawReward(byte[] address) {
    if (!dynamicPropertiesStore.allowChangeDelegation()) {
      return;
    }
    AccountCapsule accountCapsule = accountStore.get(address);
    long beginCycle = delegationStore.getBeginCycle(address);
    long endCycle = delegationStore.getEndCycle(address);
    long currentCycle = dynamicPropertiesStore.getCurrentCycleNumber();
    long reward = 0;
    if (beginCycle > currentCycle || accountCapsule == null) {
      return;
    }
    if (beginCycle == currentCycle) {
      AccountCapsule account = delegationStore.getAccountVote(beginCycle, address);
      if (account != null) {
        return;
      }
    }
    //withdraw the latest cycle reward
    if (beginCycle + 1 == endCycle && beginCycle < currentCycle) {
      AccountCapsule account = delegationStore.getAccountVote(beginCycle, address);
      if (account != null) {
        reward = computeReward(beginCycle, endCycle, account);
        adjustAllowance(address, reward);
        reward = 0;
        logger.info("Latest cycle reward {}, {}.", beginCycle, account.getVotesList());
      }
      beginCycle += 1;
    }
    //
    endCycle = currentCycle;
    if (CollectionUtils.isEmpty(accountCapsule.getVotesList())) {
      delegationStore.setBeginCycle(address, endCycle + 1);
      return;
    }
    if (beginCycle < endCycle) {
      reward += computeReward(beginCycle, endCycle, accountCapsule);
      adjustAllowance(address, reward);
    }
    delegationStore.setBeginCycle(address, endCycle);
    delegationStore.setEndCycle(address, endCycle + 1);
    delegationStore.setAccountVote(endCycle, address, accountCapsule);
    logger.info("Adjust {} allowance {}, now currentCycle {}, beginCycle {}, endCycle {}, "
            + "account vote {}.", Hex.toHexString(address), reward, currentCycle,
        beginCycle, endCycle, accountCapsule.getVotesList());
  }

  private long computeReward(long beginCycle, long endCycle, AccountCapsule accountCapsule) {
    if (beginCycle >= endCycle) {
      return 0;
    }

    long reward = 0;
    long newAlgorithmCycle = dynamicPropertiesStore.getNewRewardAlgorithmEffectiveCycle();
    List<Pair<byte[], Long>> srAddresses = accountCapsule.getVotesList().stream()
        .map(vote -> new Pair<>(vote.getVoteAddress().toByteArray(), vote.getVoteCount()))
        .collect(Collectors.toList());
    if (beginCycle < newAlgorithmCycle) {
      long oldEndCycle = min(endCycle, newAlgorithmCycle,
          dynamicPropertiesStore.disableJavaLangMath());
      reward = getOldReward(beginCycle, oldEndCycle, srAddresses);
      beginCycle = oldEndCycle;
    }
    if (beginCycle < endCycle) {
      for (Pair<byte[], Long>  vote : srAddresses) {
        byte[] srAddress = vote.getKey();
        BigInteger beginVi = delegationStore.getWitnessVi(beginCycle - 1, srAddress);
        BigInteger endVi = delegationStore.getWitnessVi(endCycle - 1, srAddress);
        BigInteger deltaVi = endVi.subtract(beginVi);
        if (deltaVi.signum() <= 0) {
          continue;
        }
        long userVote = vote.getValue();
        reward += deltaVi.multiply(BigInteger.valueOf(userVote))
            .divide(DelegationStore.DECIMAL_OF_VI_REWARD).longValue();
      }
    }

  public void accumulateWitnessVi(long cycle, byte[] address, long voteCount) {
    BigInteger preVi = getWitnessVi(cycle - 1, address);
    long reward = getReward(cycle, address);
    if (reward == 0 || voteCount == 0) { // Just forward pre vi
      if (!BigInteger.ZERO.equals(preVi)) { // Zero vi will not be record
        setWitnessVi(cycle, address, preVi);
      }
    } else { // Accumulate delta vi
      BigInteger deltaVi = BigInteger.valueOf(reward)
          .multiply(DECIMAL_OF_VI_REWARD)
          .divide(BigInteger.valueOf(voteCount));
      setWitnessVi(cycle, address, preVi.add(deltaVi));
    }

  private void countVoteAccount(VoteWitnessContract voteContract) {
    AccountStore accountStore = chainBaseManager.getAccountStore();
    VotesStore votesStore = chainBaseManager.getVotesStore();
    MortgageService mortgageService = chainBaseManager.getMortgageService();
    byte[] ownerAddress = voteContract.getOwnerAddress().toByteArray();

    VotesCapsule votesCapsule;

    //
    mortgageService.withdrawReward(ownerAddress);

    AccountCapsule accountCapsule = accountStore.get(ownerAddress);

    DynamicPropertiesStore dynamicStore = chainBaseManager.getDynamicPropertiesStore();
    if (dynamicStore.supportAllowNewResourceModel()
        && accountCapsule.oldTronPowerIsNotInitialized()) {
      accountCapsule.initializeOldTronPower();
    }

    if (!votesStore.has(ownerAddress)) {
      votesCapsule = new VotesCapsule(voteContract.getOwnerAddress(),
          accountCapsule.getVotesList());
    } else {
      votesCapsule = votesStore.get(ownerAddress);
    }

    accountCapsule.clearVotes();
    votesCapsule.clearNewVotes();

    voteContract.getVotesList().forEach(vote -> {
      logger.debug("countVoteAccount, address[{}]",
          ByteArray.toHexString(vote.getVoteAddress().toByteArray()));

      votesCapsule.addNewVotes(vote.getVoteAddress(), vote.getVoteCount());
      accountCapsule.addVotes(vote.getVoteAddress(), vote.getVoteCount());
    });

    accountStore.put(accountCapsule.createDbKey(), accountCapsule);
    votesStore.put(ownerAddress, votesCapsule);
  }
