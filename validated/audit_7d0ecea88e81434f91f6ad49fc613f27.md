### Title
DoS via unrecovered panic on unchecked negative chunk offsets in MVCC manifest parser - (File: internal/git/mvcc/manifest.go)

### Summary
Similar to the Firedancer report where an unchecked `parent_off` field in a shred causes an `unwrap()` panic that crashes the validator process, Gitaly's MVCC manifest parser fails to validate that binary offset fields decoded from an on-disk/fetched manifest blob are non-negative before using them to slice a byte buffer. Because manifest parsing happens inside a detached goroutine that is not wrapped by Gitaly's gRPC panic-recovery interceptor, a resulting Go runtime panic is not converted into an `Internal` gRPC error — it crashes the entire `gitaly` process.

### Finding Description
`parseChunks` decodes each TOC entry's file offset directly from an 8-byte big-endian field and casts it to a signed `int`: [1](#0-0) 

```
chunkOffsetInFile := int(binary.BigEndian.Uint64(data[chunkOffset+4 : chunkOffset+tocChunkSize]))
...
nextChunkOffsetInFile := int(binary.BigEndian.Uint64(data[nextChunkStart+4 : nextChunkStart+tocChunkSize]))
if chunkOffsetInFile > dataEnd || nextChunkOffsetInFile > dataEnd || nextChunkOffsetInFile < chunkOffsetInFile {
    return nil, fmt.Errorf("chunk %d has out-of-bounds offsets [%d, %d)", i, chunkOffsetInFile, nextChunkOffsetInFile)
}
``` [2](#0-1) 

A large `uint64` (e.g. `0xFFFFFFFFFFFFFFFF`) converted to Go's 64-bit signed `int` wraps to a negative value. The bounds check only tests `offset > dataEnd` and `next < current`; it never checks `offset >= 0`. Two offsets that are both negative but ordered correctly (e.g. `-200` then `-100`) pass this check untouched, producing a `manifestChunk{offset: -200, size: 100}` that is accepted as valid — exactly analogous to the missing `parent_off` bound check in the Firedancer shred parser that lets `slot.checked_sub(parent_offset)` produce a value later used unchecked.

This poisoned negative offset is then used directly as a slice bound in `ParseManifest`: [3](#0-2) 

```
for i := range numPath {
    start := pathChunk.offset + i*pw
    record := data[start : start+pw]
```

A negative `start` triggers an unrecoverable Go runtime panic: `slice bounds out of range [-200:]`.

Critically, `ParseManifest` is invoked from `LocalCache.prepareManifestFile`, which is called from `LocalCache.prepare`, which itself runs inside a bare goroutine launched by `PrepareWithManifest` with no `recover()`: [4](#0-3) [5](#0-4) 

Gitaly's gRPC servers install `panichandler.UnaryPanicHandler`/`StreamPanicHandler` to convert panics inside the request-handling goroutine into `codes.Internal` errors: [6](#0-5) 

However, that `defer recover()` only guards the goroutine executing the interceptor chain. A panic in the detached goroutine spawned by `PrepareWithManifest` (`go func() { m.prepareErr = m.prepare(ctx, hash) ... }()`) happens on a different goroutine stack and is **not** caught by this interceptor, so Go's runtime terminates the whole process.

The manifest hash driving which manifest blob gets fetched and parsed can come from RPC metadata rather than only from the locally-resolved pointer, per the documented `PrepareWithManifest` contract ("used when the RPC already contains a manifest hash in the metadata. Example: request coming from Gitaly hooks."): [7](#0-6) 

This means the specific manifest object fetched and parsed is influenced by data flowing through the push/hook pipeline, giving an avenue to reach a crafted manifest blob during ordinary repository mutation flows on an MVCC-backed storage.

### Impact Explanation
An unrecovered panic on a background goroutine terminates the entire `gitaly` process, not just the individual RPC. This affects every repository and every in-flight RPC being served by that process, causing a full liveness outage until the process is restarted — directly comparable to the Firedancer validator crash described in the report, which is worse than a normal handled RPC error because Gitaly's panic-safety net (`panichandler`) does not apply outside the interceptor-wrapped goroutine.

### Likelihood Explanation
Exploitation requires the MVCC backend to be in use (it is a newer, still-evolving storage backend per the package documentation) and requires the attacker to influence which manifest hash/blob is resolved and fetched (e.g., via crafted RPC metadata or a manifest blob reachable through the push/commit pipeline). This is a plausible but not fully-confirmed remote trigger path within the scope explored; the exact metadata-to-hash wiring for external RPCs was not fully traced in this pass.

### Recommendation
In `parseChunks` (and `parseManifestHeader`), explicitly reject negative decoded offsets/sizes before using them (`if chunkOffsetInFile < 0 || nextChunkOffsetInFile < 0 { return nil, fmt.Errorf(...) }`), in addition to the existing upper-bound checks. Additionally, wrap `LocalCache.prepare`'s goroutine body in the same panic-recovery pattern used by `panichandler` (log-and-convert-to-error) so that malformed data parsed off the main request goroutine cannot crash the whole Gitaly process.

### Proof of Concept
Construct a manifest binary with a TOC entry whose 8-byte big-endian offset field is set to a value such as `0xFFFFFFFFFFFFFF38` (`int64` value `-200`) and a following terminator/next-chunk offset of `0xFFFFFFFFFFFFFF9C` (`-100`), keeping `nextChunkOffsetInFile >= chunkOffsetInFile` and both `<= dataEnd` numerically as signed ints so the existing check in `parseChunks` (lines 309-311) is bypassed. Place this as the PATH chunk. When `ParseManifest` processes the PATH records (`internal/git/mvcc/manifest.go` lines 182-196), `data[start:start+pw]` with negative `start` triggers `panic: runtime error: slice bounds out of range [-200:]` inside the unrecovered goroutine started in `PrepareWithManifest` (`internal/git/mvcc/cache.go` lines 168-173), crashing the Gitaly process.

func (m *LocalCache) prepareManifestFile(ctx context.Context, hash string) (manifest *Manifest, err error) {
	// Construct the manifest path
	manifestFilePath := filepath.Join(m.storagePath, m.repositoryID, mvccCacheDir, "manifests", hash)

	// Verify if it already exists on the local filesystem or not
	existLocally, err := fileExist(manifestFilePath)
	if err != nil {
		return nil, fmt.Errorf("check if file exists: %w", err)
	}

	if !existLocally {
		// If it does not exist, read content from ObjectStorage
		manifestReader, err := m.rs.ReadManifest(ctx, m.repositoryID, hash)
		if err != nil {
			return nil, fmt.Errorf("read manifest file: %w", err)
		}

		defer func() {
			closeErr := manifestReader.Close()
			err = errors.Join(err, closeErr)
		}()

		// Create the manifest file on the local file system atomically. This is a protection against
		// potential concurrent requests trying to create the same manifest file.
		if err = createFileAtomic(ctx, manifestFilePath, manifestReader); err != nil {
			return nil, fmt.Errorf("write manifest: %w", err)
		}
	}

	// Now that it exist on disk, let's open the file.
	manifestFile, err := os.Open(manifestFilePath)
	if err != nil {
		return nil, fmt.Errorf("opening manifest %s: %w", manifestFilePath, err)
	}

	// Read the content in memory. These files should not be that large.
	// The Manifest parsing logic needs the whole file at once to parse it.
	manifestContent := bytes.Buffer{}
	_, err = manifestContent.ReadFrom(manifestFile)
	if err != nil {
		return nil, fmt.Errorf("reading manifest: %w", err)
	}

	// Return the parsed manifest
	return ParseManifest(manifestContent.Bytes())

// UnaryPanicHandler creates a new unary server interceptor that handles panics.
func UnaryPanicHandler(logger log.Logger) grpc.UnaryServerInterceptor {
	return func(ctx context.Context, req interface{}, info *grpc.UnaryServerInfo, handler grpc.UnaryHandler) (resp interface{}, err error) {
		defer handleCrash(logger, info.FullMethod, func(grpcMethodName string, r interface{}) {
			err = toPanicError(grpcMethodName, r)
		})

		return handler(ctx, req)
	}
}

// StreamPanicHandler creates a new stream server interceptor that handles panics.
func StreamPanicHandler(logger log.Logger) grpc.StreamServerInterceptor {
	return func(srv interface{}, stream grpc.ServerStream, info *grpc.StreamServerInfo, handler grpc.StreamHandler) (err error) {
		defer handleCrash(logger, info.FullMethod, func(grpcMethodName string, r interface{}) {
			err = toPanicError(grpcMethodName, r)
		})

		return handler(srv, stream)
	}
}
