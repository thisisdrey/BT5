## Title
Withdrawal of collateral becomes permanently blocked if the hardcoded oracle infrastructure fails or is censored - ([File: mainnet/contracts/market/v0-4-market.clar])

### Summary
`collateral-remove` in `v0-4-market.clar` unconditionally requires a successful on-chain oracle price resolution whenever the caller has any outstanding debt. Price resolution is routed through a single, hardcoded external dependency — the Pyth infra deployed at `'SP1CGXWEAMG6P6FT04W66NVGJ7PQWMDAC19R7PJ0Y.pyth-storage-v4`/`pyth-oracle-v4`/`wormhole-core-v4` (or the DIA oracle) — and any failure of that dependency (publisher/relayer downtime, censorship of price update transactions, staleness, or the price contract reverting) makes `price-resolve` fail, which reverts the entire withdrawal. This mirrors the reported `TokenBridge` bug class: an unprivileged user's funds become inaccessible purely because a single external service the contract depends on is unavailable, with no fallback or admin escape hatch.

### Finding Description
`collateral-remove` (`mainnet/contracts/market/v0-4-market.clar:1107-1169`) branches on whether the user `has-debt`. When it does, the full path requires `get-notional-evaluation`, which for every relevant asset calls `price-resolve` (`v0-4-market.clar:373-395`) via `get-assets` → `price-multi-resolve` → `resolve-price-feed` (`v0-4-market.clar:332-335`), and even in the "disabled collateral" branch calls `price-resolve` directly (`v0-4-market.clar:1146`, guarded only by `unwrap!` to `ERR-DISABLED-COLLATERAL-PRICE-FAILED`).

`resolve-price-feed` calls `resolve-pyth`, which calls `call-pyth` (`v0-4-market.clar:308-310`):
```
(contract-call? 'SP1CGXWEAMG6P6FT04W66NVGJ7PQWMDAC19R7PJ0Y.pyth-storage-v4 get-price ident)
```
This is a hardcoded call to a single external contract/publisher network. If:
- the Pyth off-chain guardian/relayer network is down or censors updates so prices go stale beyond `max-staleness` (checked in `oracle-timestamp-fresh`, `v0-4-market.clar:365-371`),
- the storage contract reverts (`ERR_PRICE_FEED_NOT_FOUND`/`ERR_STALE_PRICE`, seen in `pyth-storage-v4.clar:44-57`),
- or the wormhole guardian set is unavailable/rotated in a way that blocks `verify-and-update-price-feeds`,

then `call-pyth` returns an error, `resolve-pyth` propagates it, `price-resolve` fails with `ERR-ORACLE-PYTH`/`ERR-ORACLE-INVARIANT`, and the entire `collateral-remove` transaction reverts — for every user who has any debt, regardless of which asset they're trying to withdraw.

There is no fallback price source enforced (DIA exists as an alternate `type`, but each asset is registered with one oracle `type`, chosen at asset registration, not user-selectable), and no admin/emergency withdrawal path that lets a user retrieve collateral without a fresh price when the oracle dependency is broken. The `write-feeds`/`price-feeds` in-band update mechanism (`v0-4-market.clar:129-152`) only helps if the underlying Pyth VAA/guardian infrastructure is actually functioning — it does not help if the coordinator/publisher itself is down or censoring, exactly the failure mode described in the report.

### Impact Explanation
Any user who has borrowed against collateral (i.e., `has-debt` is true) is unable to withdraw any of their collateral for as long as the required price feed for their assets cannot be resolved on-chain. Since liquidation (`liquidate`) also depends on oracle price resolution, the position is similarly not liquidatable, meaning the collateral is frozen in place — not stolen, but inaccessible to its owner. This is a **temporary freezing of funds** (in-scope High impact) for the duration of the oracle outage/censorship, and could become effectively permanent if the single hardcoded oracle contract address is deprecated, migrated, or permanently censored without a corresponding governance upgrade of the market contract.

### Likelihood Explanation
This requires no attacker action against Zest's own contracts — it is triggered purely by an outage or censorship of the single external oracle dependency Zest hardcodes into its price-resolution path. Given that Pyth relies on off-chain guardians/relayers, and this is the same failure class the external report flags (single coordinator down/censoring), this is a realistic operational risk rather than a purely theoretical one. It is bounded to affect only users with debt (skip-price path exists for zero-debt withdrawals), which somewhat limits but does not eliminate exposure.

### Recommendation
Add a fallback/emergency exit mechanism for collateral withdrawal that does not require a live price resolution to succeed under all circumstances — e.g., allow governance-gated pause/override to permit withdrawal using a last-known-good stored price snapshot (with appropriate risk assumptions), or allow full-position closure (repay + withdraw) once debt is independently repaid without requiring price resolution for that specific flow. At minimum, provide a decentralization/redundancy plan for the oracle dependency (multiple independent price sources aggregated, not a single hardcoded contract call) so that a single outage cannot block every indebted user's withdrawal path.

### Proof of Concept
1. User deposits collateral and borrows some debt via `market.clar`/`v0-4-market.clar`, creating a position where `has-debt` is true.
2. The Pyth off-chain guardian network stops publishing updates for the relevant price identifiers (or transactions calling `verify-and-update-price-feeds` are censored/dropped), so the price stored in `pyth-storage-v4` becomes older than `max-staleness` for the asset.
3. User calls `collateral-remove` on `v0-4-market.clar`. Because `has-debt` is true, the contract calls `get-notional-evaluation` → `price-resolve` → `resolve-pyth` → `call-pyth`, which either returns a stale-price error from `pyth-storage-v4:read-price-with-staleness-check` or fails the `oracle-timestamp-fresh` check in `v0-4-market.clar:387-388`, causing the whole `try!` chain to abort with `ERR-ORACLE-INVARIANT`/`ERR-ORACLE-PYTH`.
4. `collateral-remove` reverts. The user cannot withdraw any collateral (nor be liquidated, since `liquidate` follows the same oracle dependency) for as long as the oracle outage/censorship persists, with no alternate path to reclaim funds. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) [5](#0-4)

(define-private (price-resolve
  (data { type: (buff 1), ident: (buff 32), callcode: (optional (buff 1)), max-staleness: uint }))
  (let ((type (get type data))
        (ident (get ident data))
        (key { type: type, ident: ident })
        (resolution (try! (resolve-price-feed type ident)))
        (price (get value resolution))
        (callcode (get callcode data))
        (final-price (try! (resolve-callcode price callcode)))
        (last-update-time (oracle-last-update key))
        (timestamp (get timestamp resolution))
        (max-staleness (get max-staleness data)))

    ;; validate price and timestamp using max-staleness from oracle data
    (asserts! (and (oracle-price-legal final-price) (oracle-timestamp-fresh timestamp last-update-time max-staleness))
              ERR-ORACLE-INVARIANT)

    ;; update timestamp if newer
    (if (> timestamp last-update-time)
        (map-set last-update key timestamp)
        false)

    (ok final-price)))

(define-public (collateral-remove (ft <ft-trait>) (amount uint) (receiver (optional principal)) (price-feeds (optional (list 3 (buff 8192)))))
  (let ((ft-address (contract-of ft))
        (asset (try! (get-asset ft-address)))
        (asset-id (get id asset))
        (account contract-caller)
        (collateral-receiver (match receiver recv recv contract-caller))
        (position (try! (get-position account)))
        (has-debt (> (len (get debt position)) u0)))

    (asserts! (> amount u0) ERR-AMOUNT-ZERO)

    (if has-debt
        ;; HAS DEBT: Full flow with price resolution and health checks
        (let ((is-collateral-enabled (get collateral asset))
              (feeds-check (try! (write-feeds price-feeds)))
              (position-mask (get mask position))
              (pos-full (if is-collateral-enabled position (try! (get-full-position account))))
              (u-debt (accrue-user-debts (get debt pos-full)))
              (u-coll (accrue-user-collateral (get collateral pos-full)))
              (assets (get-assets position-mask))
              (curr-coll-aid (find-collateral-amount (get collateral position) asset-id))
              (removing-all (is-eq amount curr-coll-aid))
              (current-group (try! (get-egroup position-mask)))
              (current-ltvb (buff-to-uint-be (get LTV-BORROW current-group)))
              (notional-valued-assets (get-notional-evaluation { position: position, assets: assets }))
              (collateral-value (get collateral notional-valued-assets))
              (debt-value (get debt notional-valued-assets))
              (removed-asset-value (find-and-resolve-asset-value assets asset-id amount true)))

          (asserts! (is-healthy collateral-value debt-value current-ltvb) ERR-UNHEALTHY)
          (asserts!
            (if is-collateral-enabled
                (let ((t (asserts! (>= collateral-value removed-asset-value) ERR-INSUFFICIENT-COLLATERAL))
                      (post-removal-collateral-value (- collateral-value removed-asset-value)))
                  (if removing-all
                      (let ((future-mask (bit-and position-mask (bit-not (pow u2 asset-id)))))
                        (try! (is-healthy-with-mask post-removal-collateral-value debt-value future-mask)))
                      (is-healthy post-removal-collateral-value debt-value current-ltvb)))
                (let ((oracle-data (get oracle asset))
                      (price (unwrap! (price-resolve oracle-data) ERR-DISABLED-COLLATERAL-PRICE-FAILED))
                      (decimals (get decimals asset))
                      (user-amount (find-collateral-amount (get collateral pos-full) asset-id))
                      (disabled-notional (normalize (* user-amount price) decimals false))
                      (removal-notional (normalize (* amount price) decimals true))
                      (total-collateral-value (+ collateral-value disabled-notional)))
                  (asserts! (>= total-collateral-value removal-notional) ERR-INSUFFICIENT-COLLATERAL)
                  (is-healthy (- total-collateral-value removal-notional) debt-value current-ltvb)))
            ERR-UNHEALTHY)

          (let ((result (try! (contract-call? .v0-market-vault collateral-remove account amount ft asset-id collateral-receiver))))
            (print { action: "collateral-remove", caller: contract-caller,
                     data: { account: account, receiver: collateral-receiver, asset-id: asset-id,
                             asset-addr: ft-address, amount: amount, updated-collateral-amount: result,
                             position-collateral-usd: collateral-value, position-debt-usd: debt-value }})
            (ok result)))

        ;; NO DEBT: Skip price resolution entirely
        (let ((result (try! (contract-call? .v0-market-vault collateral-remove account amount ft asset-id collateral-receiver))))
          (print { action: "collateral-remove", caller: contract-caller,
                   data: { account: account, receiver: collateral-receiver, asset-id: asset-id,
                           asset-addr: ft-address, amount: amount, updated-collateral-amount: result,
                           position-collateral-usd: u0, position-debt-usd: u0 }})
          (ok result)))))
