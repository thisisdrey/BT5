### Title
Gas key nonce floor reset via same-height delete+re-add enables GasKeyNonce transaction replay/double-spend - (File: runtime/runtime/src/access_keys.rs)

### Summary
`add_gas_key` unconditionally reseeds every `NonceIndex` for a re-created gas key to `initial_nonce_value(block_height) = (block_height - 1) * ACCESS_KEY_NONCE_RANGE_MULTIPLIER`, without regard to nonce values already consumed for that `(account_id, public_key, index)` earlier in the very same apply at the same `block_height`. A single receipt that first deletes and then re-adds a gas key with the same public key can push a nonce_index's stored value backward below a nonce that was already used and executed earlier in the same chunk, allowing that earlier transaction to be resubmitted and revalidated as if it were fresh.

### Finding Description
`initial_nonce_value` (runtime/runtime/src/access_keys.rs:46-50) exists to stop replay across access-key re-creation by tying the new nonce floor to `block_height`, relying on the invariant that `block_height` only increases between key-creation events (this is the fix for near/nearcore#3779). That invariant silently assumes the floor is only ever set once per block height for a given key slot.

`add_gas_key` (runtime/runtime/src/access_keys.rs:194-228) breaks this assumption for gas keys because gas keys support `num_nonces` independent `NonceIndex` slots that are consumed incrementally by ordinary `GasKeyNonce` transactions *during* chunk application at the current `block_height`. If, within a single action receipt (e.g., a self-targeted `FunctionCall` promise batch that includes `DeleteKey` then `AddKey` with the same public key), the account:
1. deletes the gas key via `action_delete_key` → `delete_gas_key` (access_keys.rs:93-134), which wipes all nonce rows with `remove_gas_key_nonce`, and
2. immediately re-adds a gas key with the same public key via `action_add_key` → `add_gas_key` (access_keys.rs:194-228),

then `add_gas_key` rewrites every nonce_index back to `(block_height - 1) * 1_000_000` — the same floor used for the *entire* current block height, regardless of any nonce value already recorded above that floor for the same index earlier in the same chunk (from a legitimately-processed `GasKeyNonce` transaction, e.g. a `WithdrawFromGasKeyAction`). Because `block_height` did not advance, the floor does not monotonically increase relative to nonces already consumed this height; it resets downward to the height-level floor. A previously-executed transaction with nonce `n` such that `(H-1)*1_000_000 < n <` the already-consumed stored nonce now again satisfies "`n` > stored nonce", so it can be resubmitted and reprocessed by the standard nonce check, re-triggering its effects (e.g. `action_withdraw_from_gas_key`, access_keys.rs:290-335) a second time.

None of the existing checks catch this: `action_delete_key`/`action_add_key` only check for duplicate keys and burn the gas key's remaining balance at delete time (access_keys.rs:103-113); they do not compare the pre-existing nonce state against the new floor, and `set_gas_key_nonce` (core/store/src/utils/mod.rs:386-410) performs an unconditional overwrite.

### Impact Explanation
This breaks value conservation / replay protection: a `WithdrawFromGasKeyAction`-bearing `GasKeyNonce` transaction that already transferred funds out of a gas key's balance to the owning account can be resubmitted and accepted again against the recreated gas key instance, double-spending the funds that were already withdrawn/burned once. This is a double-spend/replay category impact under value conservation.

### Likelihood Explanation
The attacker only needs an ordinary funded account with:
- a gas key of `GasKeyFullAccess` with a nonzero `GasKeyInfo.balance` and at least one `NonceIndex`,
- a self-targeted contract call (deployed by the attacker) able to batch `DeleteKey` then `AddKey` for the same public key in one action receipt (standard promise-batch host functions),
- a legitimately-submitted `GasKeyNonce` withdrawal transaction executed earlier in the same chunk that advanced the target nonce_index above `(H-1)*1_000_000`.

All of this is achievable by a single unprivileged account without validator/node access, using only self-issued transactions and its own deployed contract, and is repeatable every chunk in which the attacker can arrange the ordering.

### Recommendation
When re-adding a gas key (or any nonce_index) at `add_gas_key`, do not blindly overwrite nonce_index rows to `initial_nonce_value(block_height)`. Instead, seed each nonce_index to `max(initial_nonce_value(block_height), previous_max_nonce_seen_for_that_index)`, or track a monotonic per-account/per-index high-water-mark that persists independent of key deletion, so the floor can never move backward relative to nonces already consumed at the current or any prior height.

pub(crate) fn initial_nonce_value(block_height: BlockHeight) -> Nonce {
    // Set default nonce for newly created access key to avoid transaction hash collision.
    // See <https://github.com/near/nearcore/issues/3779>.
    (block_height - 1) * near_primitives::account::AccessKey::ACCESS_KEY_NONCE_RANGE_MULTIPLIER
}

fn delete_gas_key(
    config: &RuntimeConfig,
    state_update: &mut TrieUpdate,
    account: &mut Account,
    result: &mut ActionResult,
    account_id: &AccountId,
    public_key: &PublicKey,
    access_key: &AccessKey,
    gas_key_info: &GasKeyInfo,
) -> Result<(), RuntimeError> {
    if gas_key_info.balance > GasKeyInfo::MAX_BALANCE_TO_BURN {
        result.result = Err(ActionErrorKind::GasKeyBalanceTooHigh {
            account_id: account_id.clone(),
            public_key: Some(Box::new(public_key.clone())),
            balance: gas_key_info.balance,
        }
        .into());
        return Ok(());
    }
    result.tokens_burnt =
        result.tokens_burnt.checked_add(gas_key_info.balance).ok_or(IntegerOverflowError)?;
    let num_nonces = gas_key_info.num_nonces as usize;
    for i in 0..gas_key_info.num_nonces {
        remove_gas_key_nonce(state_update, account_id.clone(), public_key.clone(), i);
    }
    let nonce_key_len = gas_key_nonce_key_len(account_id, &public_key.into());
    let nonce_remove_compute = storage_removes_compute(
        &config.wasm_config.ext_costs,
        num_nonces,
        nonce_key_len * num_nonces,
        AccessKey::NONCE_VALUE_LEN * num_nonces,
    );
    result.compute_usage = safe_add_compute(result.compute_usage, nonce_remove_compute)?;
    remove_access_key(state_update, account_id.clone(), public_key.clone());
    account.set_storage_usage(account.storage_usage().saturating_sub(gas_key_storage_cost(
        &config.fees,
        public_key,
        access_key,
        gas_key_info.num_nonces,
    )));
    Ok(())
}

fn add_gas_key(
    fee_config: &RuntimeFeesConfig,
    state_update: &mut TrieUpdate,
    account: &mut Account,
    account_id: &AccountId,
    public_key: &PublicKey,
    access_key: &AccessKey,
    gas_key_info: &GasKeyInfo,
    block_height: BlockHeight,
) -> Result<(), StorageError> {
    // For gas keys, nonce stored on access key is not used and should always be zero
    let mut access_key = access_key.clone();
    access_key.nonce = 0;
    set_access_key(state_update, account_id.clone(), public_key.clone(), &access_key);

    // Set up nonces for gas key
    let num_nonces = gas_key_info.num_nonces;
    let nonce = initial_nonce_value(block_height);
    for i in 0..num_nonces {
        set_gas_key_nonce(state_update, account_id.clone(), public_key.clone(), i, nonce);
    }

    account.set_storage_usage(
        account
            .storage_usage()
            .checked_add(gas_key_storage_cost(fee_config, public_key, &access_key, num_nonces))
            .ok_or_else(|| {
                StorageError::StorageInconsistentState(format!(
                    "Storage usage integer overflow for account {}",
                    account_id
                ))
            })?,
    );
    Ok(())
}

pub(crate) fn action_withdraw_from_gas_key(
    state_update: &mut TrieUpdate,
    account: &mut Account,
    result: &mut ActionResult,
    account_id: &AccountId,
    action: &WithdrawFromGasKeyAction,
) -> Result<(), RuntimeError> {
    let Some(mut access_key) = get_access_key(state_update, account_id, &action.public_key)? else {
        result.result = Err(ActionErrorKind::GasKeyDoesNotExist {
            account_id: account_id.clone(),
            public_key: Box::new(action.public_key.clone()),
        }
        .into());
        return Ok(());
    };
    let Some(gas_key_info) = access_key.gas_key_info_mut() else {
        // Key exists but is not a gas key
        result.result = Err(ActionErrorKind::GasKeyDoesNotExist {
            account_id: account_id.clone(),
            public_key: Box::new(action.public_key.clone()),
        }
        .into());
        return Ok(());
    };

    let Some(updated_balance) = gas_key_info.balance.checked_sub(action.amount) else {
        result.result = Err(ActionErrorKind::InsufficientGasKeyBalance {
            account_id: account_id.clone(),
            public_key: Box::new(action.public_key.clone()),
            balance: gas_key_info.balance,
            required: action.amount,
        }
        .into());
        return Ok(());
    };
    gas_key_info.balance = updated_balance;
    set_access_key(state_update, account_id.clone(), action.public_key.clone(), &access_key);

    let new_account_balance = account.amount().checked_add(action.amount).ok_or_else(|| {
        RuntimeError::StorageError(StorageError::StorageInconsistentState(
            "Account balance integer overflow".to_string(),
        ))
    })?;
    account.set_amount(new_account_balance);
    Ok(())
}
