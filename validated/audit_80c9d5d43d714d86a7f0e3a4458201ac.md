### Title
Unbounded tar extraction and directory walk in SetCustomHooks allows resource-exhaustion DoS - ([File: internal/gitaly/repoutil/custom_hooks.go])

### Summary
`SetCustomHooks`/`RestoreCustomHooks` accept a client-streamed tar archive with no limit on total size, entry count, or nesting depth before or during extraction. The tar is piped straight into a spawned `tar -xf` process by `ExtractHooks`, and the resulting `custom_hooks` directory is then fully walked and hashed file-by-file in `newDirectoryVote`, so an attacker-controlled tar-bomb (e.g., millions of zero-byte files) drives both the extraction subprocess and the vote-hashing walk to consume unbounded CPU, inodes, and disk on the shard.

### Finding Description
The gRPC handler `SetCustomHooks` in [1](#0-0)  reads the streamed request data via a `streamio.NewReader` with no cap on total bytes received, and passes it directly to `repoutil.SetCustomHooks`. That function calls `ExtractHooks`, which pipes the reader into a spawned `tar -xf -` subprocess with no `--exclude`, no member-count limit, and no size/quota enforcement: [2](#0-1) . After extraction, `SetCustomHooks` calls `newDirectoryVote`, which performs a `filepath.WalkDir` over every extracted entry, opening and hashing every file's contents synchronously and without any bound on the number of entries visited: [3](#0-2) . There is no check anywhere in this call chain — before spawning `tar`, during the stream read, or before/during the `WalkDir` — that bounds the number of tar entries, nesting depth, or total extracted size. The `hooksLock` held during this operation is repository-specific but the CPU/inode/disk consumed is shared with the storage shard, so a large-enough tar (attacker fully controls its own repo's `SetCustomHooksRequest` content) causes the RPC handler to run for an extended time while consuming shard-wide disk/inode resources, and can be repeated by re-invoking the RPC.

### Impact Explanation
This matches a resource-exhaustion / DoS class impact: the `SetCustomHooks` RPC handler thread is tied up for an extended duration, disk inodes/space on the shared storage volume are consumed, and (depending on Gitaly's concurrency limiter configuration) this can degrade or block other repositories/tenants sharing the same storage shard, since `tar` extraction and the `WalkDir`/hashing pass are unbounded in this code path.

### Likelihood Explanation
The attacker only needs standard push/write access to their own repository and the ability to call `SetCustomHooks` (or `RestoreCustomHooks`, which shares the same underlying implementation) — no special privilege is required. The request is trivial to construct (a tar containing many small/zero-byte files or deeply nested directories) and can be repeated at will, making this a low-effort, repeatable attack. The main mitigating factor is that request-level timeouts, Gitaly's per-request concurrency limiter, or filesystem-level disk quotas (if configured) may bound worst-case impact, but these are not enforced within the code path itself.

### Recommendation
Enforce limits before and during extraction: cap the total bytes read from the client stream (e.g., reject/stream-abort once a maximum tar size is exceeded), pass `tar` a member/size limit or use a Go-native tar reader that can enforce a maximum entry count and cumulative decompressed size as entries are extracted, and apply the same entry-count/size cap while performing the `newDirectoryVote` `WalkDir`. Consider adding a bound on directory nesting depth to avoid excessive path-length or filesystem-metadata overhead.

func ExtractHooks(ctx context.Context, logger log.Logger, reader io.Reader, path string, stripPrefix bool) error {
	// GNU tar does not accept an empty file as a valid tar archive and produces
	// an error. Since an empty hooks tar is symbolic of a repository having no
	// hooks, the reader is peeked to check if there is any data present.
	buf := bufio.NewReader(reader)
	if _, err := buf.Peek(1); errors.Is(err, io.EOF) {
		return nil
	}

	stripComponents := "0"
	if stripPrefix {
		stripComponents = "1"
	}

	cmdArgs := []string{"-xf", "-", "-C", path, "--strip-components", stripComponents, CustomHooksDir}

	var stderrBuilder strings.Builder
	cmd, err := command.New(ctx, logger, append([]string{"tar"}, cmdArgs...),
		command.WithStdin(buf),
		command.WithStderr(&stderrBuilder))
	if err != nil {
		return fmt.Errorf("executing tar command: %w", err)
	}

	if err := cmd.Wait(); err != nil {
		stderr := stderrBuilder.String()

		// GNU and BSD tar versions have differing errors when attempting to
		// extract specified members from a valid tar archive. If the tar
		// archive is valid the errors for GNU and BSD tar should have the
		// same prefix, which can be checked to validate whether the expected
		// content is present in the archive for extraction.
		if strings.HasPrefix(stderr, "tar: custom_hooks: Not found in archive") {
			return nil
		}

		return structerr.New("waiting for tar command completion: %w", err).WithMetadata("stderr", stderr)
	}

	return nil

func newDirectoryVote(basePath string) (*voting.VoteHash, error) {
	voteHash := voting.NewVoteHash()

	if err := filepath.WalkDir(basePath, func(path string, entry fs.DirEntry, err error) error {
		if err != nil {
			return err
		}

		relPath, err := filepath.Rel(basePath, path)
		if err != nil {
			return fmt.Errorf("getting relative path: %w", err)
		}

		// Write file relative path to hash.
		_, _ = voteHash.Write([]byte(relPath))

		info, err := entry.Info()
		if err != nil {
			return fmt.Errorf("getting file info: %w", err)
		}

		// Write file permissions to hash.
		permBytes := make([]byte, 4)
		binary.BigEndian.PutUint32(permBytes, uint32(info.Mode()))
		_, _ = voteHash.Write(permBytes)

		if entry.IsDir() {
			return nil
		}

		file, err := os.Open(path)
		if err != nil {
			return fmt.Errorf("opening file: %w", err)
		}
		defer file.Close()

		// Copy file data to hash.
		if _, err = io.Copy(voteHash, file); err != nil {
			return fmt.Errorf("copying file to hash: %w", err)
		}

		return nil
	}); err != nil {
		return nil, fmt.Errorf("walking directory: %w", err)
	}

	return &voteHash, nil
}
