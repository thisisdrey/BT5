Audit Report

## Title
Dust `total_tokens_staked` in `pallet-asset-rewards` can blow up `reward_per_token` and permanently brick `stake`/`unstake`/`harvest_rewards` - (File: `substrate/frame/asset-rewards/src/lib.rs`)

## Summary
`Pallet::<T>::reward_per_token` [1](#0-0)  computes `reward_rate_per_block * rewardable_blocks_elapsed * PRECISION_SCALING_FACTOR / total_tokens_staked` using checked (`Ensure*`) arithmetic that returns `Err` on overflow, with the only dust guard being an `is_zero()` check on `total_tokens_staked`. Every state-mutating call (`stake`, `unstake`, `harvest_rewards`) unconditionally routes through `update_pool_and_staker_rewards` → `reward_per_token` before any freeze/transfer occurs [2](#0-1) , so if the accumulator computation ever overflows `T::Balance`, all subsequent calls into that pool revert deterministically, permanently locking any staked/frozen tokens and unharvested rewards for every staker in the pool.

## Finding Description
The code exactly matches the reported logic: `reward_per_token` short-circuits only when `total_tokens_staked.is_zero()`, otherwise computes the reward delta by multiplying `reward_rate_per_block` by elapsed rewardable blocks and `PRECISION_SCALING_FACTOR`, then dividing by `total_tokens_staked`, using `ensure_mul`/`ensure_div`/`ensure_add` which propagate `ArithmeticError` on overflow rather than saturating [3](#0-2) .

`stake` [4](#0-3) , `unstake` [5](#0-4) , and `harvest_rewards` [6](#0-5)  all call `update_pool_and_staker_rewards` as their first fallible operation, before any freeze adjustment or asset transfer. If `reward_per_token` returns `Err`, the extrinsic reverts before `T::AssetsFreezer::decrease_frozen` (in `unstake`) or the reward transfer (in `harvest_rewards`) is ever reached, so there is no code path to unfreeze or withdraw once the accumulator computation fails.

However, this is meaningfully bounded by `rewardable_blocks_elapsed`, which is derived from `Self::last_block_reward_applicable(pool_info.expiry_block).ensure_sub(pool_info.last_update_block)` — i.e., capped by the pool's `expiry_block`, not unbounded wall-clock time [7](#0-6) . This caps the reachable magnitude of `reward_rate_per_block * rewardable_blocks_elapsed * PRECISION_SCALING_FACTOR` for any given pool's lifetime, but does not eliminate the overflow risk: since `set_pool_reward_rate_per_block` only permits increasing the rate and the admin/pool creator controls `expiry_block` (which can be extended far into the future), and any staker can freely reduce `total_tokens_staked` to `1` via ordinary `unstake` calls, the preconditions (large `reward_rate_per_block * blocks_until_expiry * PRECISION_SCALING_FACTOR` relative to `T::Balance::MAX`, combined with dust `total_tokens_staked`) remain realistically reachable through unprivileged `unstake` actions alone — no privileged action beyond the pool's own configuration (set once by an admin at pool creation/adjustment) is required to trigger the actual overflow.

## Impact Explanation
This matches the "permanent user-fund lock" impact category: once `reward_per_token` overflows for a pool, `unstake` and `harvest_rewards` become permanently unusable for every staker in that pool, since `T::AssetsFreezer::decrease_frozen` and the reward `T::Assets::transfer` can never be reached — the checked-arithmetic failure occurs unconditionally before those calls. Frozen staked-asset balances and unclaimed reward-asset balances become permanently unrecoverable, breaking the invariant that staking/reward state must settle exactly once and that value must remain conserved and withdrawable.

## Likelihood Explanation
Any staker can unilaterally drive `total_tokens_staked` toward `1` via ordinary, unprivileged `unstake` calls — no admin cooperation is required for that half of the precondition. Whether the overflow is actually reachable in a given pool depends on the admin-configured `reward_rate_per_block` and `expiry_block` (both set by the permissioned pool admin), which bound the maximum accrual over the pool's life. This makes the finding pool-configuration-dependent: pools with sufficiently large `reward_rate_per_block` relative to `T::Balance::MAX` and a sufficiently long remaining `expiry_block` window are vulnerable to unprivileged dust-staking-induced overflow, while pools with conservative rate/expiry settings are not. The vulnerability is real and the guard (`is_zero()`-only check) is insufficient, but exploitability is conditioned on pool parameters rather than being universally and immediately triggerable in every pool.

## Recommendation
Add a minimum-total-staked threshold check in `reward_per_token` (skip/return `reward_per_token_stored` unchanged when `total_tokens_staked` is below a sane floor, analogous to skipping accrual on zero), or replace the checked-arithmetic chain with saturating arithmetic for the accumulator since only deltas matter for reward computation, so that no combination of admin-set `reward_rate_per_block`/`expiry_block` and staker-driven dust `total_tokens_staked` can cause `stake`/`unstake`/`harvest_rewards` to hard-fail on this computation.

## Proof of Concept
1. Pool admin creates a pool with a large `reward_rate_per_block` and a far-future `expiry_block` via `create_pool`.
2. Staker A stakes a large amount; Staker B stakes `1` unit.
3. Staker A calls `unstake` for their full amount, leaving `pool_info.total_tokens_staked == 1`.
4. Time passes (blocks elapse, up to the pool's `expiry_block` bound) without further interaction.
5. The next call to `stake`/`unstake`/`harvest_rewards` triggers `reward_per_token`'s `ensure_mul(...).ensure_mul(PRECISION_SCALING_FACTOR)?.ensure_div(1)?`, which for sufficiently large `reward_rate_per_block * elapsed_blocks * PRECISION_SCALING_FACTOR` (bounded by pool's configured expiry) overflows `T::Balance::MAX`, returning `Err(ArithmeticError::Overflow)`.
6. From this point, `unstake`/`harvest_rewards` permanently fail for Staker B and any other staker in the pool, with no extrinsic available to recover frozen stake or unharvested rewards [1](#0-0) .

		pub fn unstake(
			origin: OriginFor<T>,
			pool_id: PoolId,
			amount: T::Balance,
			staker: Option<T::AccountId>,
		) -> DispatchResult {
			let caller = ensure_signed(origin)?;
			let staker = staker.unwrap_or(caller.clone());

			// Always start by updating the pool rewards.
			let pool_info = Pools::<T>::get(pool_id).ok_or(Error::<T>::NonExistentPool)?;
			let now = T::BlockNumberProvider::current_block_number();
			ensure!(now > pool_info.expiry_block || caller == staker, BadOrigin);

			let staker_info = PoolStakers::<T>::get(pool_id, &staker).unwrap_or_default();
			let (mut pool_info, mut staker_info) =
				Self::update_pool_and_staker_rewards(&pool_info, &staker_info)?;

			// Check the staker has enough staked tokens.
			ensure!(staker_info.amount >= amount, Error::<T>::NotEnoughTokens);

			// Unfreeze staker assets.
			T::AssetsFreezer::decrease_frozen(
				pool_info.staked_asset_id.clone(),
				&FreezeReason::Staked.into(),
				&staker,
				amount,
			)?;

			// Update Pools.
			pool_info.total_tokens_staked.ensure_sub_assign(amount)?;
			Pools::<T>::insert(pool_id, pool_info);

			// Update PoolStakers.
			staker_info.amount.ensure_sub_assign(amount)?;

			if staker_info.amount.is_zero() && staker_info.rewards.is_zero() {
				PoolStakers::<T>::remove(&pool_id, &staker);
			} else {
				PoolStakers::<T>::insert(&pool_id, &staker, staker_info);
			}

			// Emit event.
			Self::deposit_event(Event::Unstaked { caller, staker, pool_id, amount });

			Ok(())
		}

		pub fn harvest_rewards(

			pool_id: PoolId,

		) -> DispatchResult {
			let caller = ensure_signed(origin)?;
			let staker = staker.unwrap_or(caller.clone());

			// Always start by updating the pool and staker rewards.
			let pool_info = Pools::<T>::get(pool_id).ok_or(Error::<T>::NonExistentPool)?;
			let now = T::BlockNumberProvider::current_block_number();
			ensure!(now > pool_info.expiry_block || caller == staker, BadOrigin);

			let staker_info =
				PoolStakers::<T>::get(pool_id, &staker).ok_or(Error::<T>::NonExistentStaker)?;
			let (pool_info, mut staker_info) =
				Self::update_pool_and_staker_rewards(&pool_info, &staker_info)?;

			// Transfer unclaimed rewards from the pool to the staker.
			T::Assets::transfer(
				pool_info.reward_asset_id,
				&pool_info.account,
				&staker,
				staker_info.rewards,
				// Could kill the account, but only if the pool was already almost empty.
				Preservation::Expendable,
			)?;

			// Emit event.
			Self::deposit_event(Event::RewardsHarvested {
				caller,
				staker: staker.clone(),
				pool_id,
				amount: staker_info.rewards,
			});

			// Reset staker rewards.
			staker_info.rewards = 0u32.into();

			if staker_info.amount.is_zero() {
				PoolStakers::<T>::remove(&pool_id, &staker);
			} else {
				PoolStakers::<T>::insert(&pool_id, &staker, staker_info);
			}

			Ok(())
		}

		pub(super) fn reward_per_token(
			pool_info: &PoolInfoFor<T>,
		) -> Result<T::Balance, DispatchError> {
			if pool_info.total_tokens_staked.is_zero() {
				return Ok(pool_info.reward_per_token_stored);
			}

			let rewardable_blocks_elapsed: u32 =
				match Self::last_block_reward_applicable(pool_info.expiry_block)
					.ensure_sub(pool_info.last_update_block)?
					.try_into()
				{
					Ok(b) => b,
					Err(_) => return Err(Error::<T>::BlockNumberConversionError.into()),
				};

			Ok(pool_info.reward_per_token_stored.ensure_add(
				pool_info
					.reward_rate_per_block
					.ensure_mul(rewardable_blocks_elapsed.into())?
					.ensure_mul(PRECISION_SCALING_FACTOR.into())?
					.ensure_div(pool_info.total_tokens_staked)?,
			)?)
		}
