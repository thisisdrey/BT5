This repository (`Loderfordw/intents--019`) implements the NEAR Intents protocol — an intent-settlement engine with token balances, `TokenDiff` swaps, and IMT/NEP-141/171/245 token accounting [1](#0-0)  — not a lending/borrowing protocol with an interest-rate model, usage index, or debt token. The reported bug class requires two derived representations of the same accruing value (a debt token's index-scaled `totalSupply()` vs. a cached `reserve.totalUsage` field) becoming desynchronized between an index update and a rate calculation that consumes the stale field.

I searched for anything structurally analogous — cached/duplicated supply or balance state feeding into a downstream calculation (fee computation, utilization-like ratio, or delta-closure math) computed from a value that could go stale relative to its authoritative source:

- `TokenDiff::execute_intent` computes fees and applies deltas directly from `self.diff` in a single pass with no separate "index update" step that could get out of sync — the fee and the balance delta are computed atomically from the same signed payload data [2](#0-1) .
- `Contract::deposit`/`withdraw` update `total_supplies` and `token_balances` together, atomically, within the same function — there is no intermediate step where one value is refreshed while the other still reflects an older state [3](#0-2) [4](#0-3) .
- `escrow-swap`'s fee/fill logic also computes fees directly from the current fill amounts with no cached/accruing index [5](#0-4) , but `contracts/escrow-swap/**` is explicitly out of scope for this analysis.

There is no interest-accrual/usage-index concept, no debt token, and no two-step "update index, then later use a cached total" pattern anywhere in the in-scope directories (`contracts/defuse/**`, `contracts/wallet/**`, `contracts/poa/**`, `contracts/global-deployer/src/**`, `contracts/outlayer/app/src/**`, `contracts/treasury-logger/src/**`, `crates/**`). Consequently, none of the required custody bindings (signature vs. balance change, `MultiPayload` settlement count, batch delta sum vs. zero, debited vs. delivered+refunded value, `TokenId` vs. asset moved, fees owed vs. collected) can be shown broken by this specific bug class in this codebase.
