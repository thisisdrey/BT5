## Finding: Missing domain separation in StackerDB chunk signatures allows cross-replica signature/chunk replay (CakePHP SecurityComponent analog)

### Summary
`SlotMetadata`'s signed digest binds only `slot_id`, `slot_version`, and `data_hash` — it never binds the StackerDB's smart-contract identifier (or message type). Because Nakamoto signer-message StackerDBs (`.signers-{0|1}-{message_id}`) all derive their `slot_id → signer` assignment from the *same* underlying signer-slot list (`stackerdb-get-signer-slots-page`), the same signer occupies the identical `slot_id` across many distinct StackerDB replicas. A chunk legitimately signed by a signer for one message-type replica therefore verifies as authentic when replayed, unmodified, into a *different* message-type replica that the signer never intended to write to — exactly the "form not bound to the model/action it's submitted against" defect from the CakePHP `SecurityComponent` advisory.

### Finding Description
The signed digest is computed purely from local slot fields: [1](#0-0) 

Note `auth_digest()` hashes only `slot_id`, `slot_version`, `data_hash` — no `smart_contract_id`/message identifier is included.

The signer-to-slot mapping for every signer-message StackerDB of a given reward-cycle/set is derived from the *same* shared list: [2](#0-1) [3](#0-2) 

so `.signers-0-<msgA>` and `.signers-0-<msgB>` assign the exact same `slot_id` to the exact same signer address, confirmed by the test iterating all `message_id` contracts against one shared slot list: [4](#0-3) 

Every validation path that accepts a chunk write only checks "does the signature recover to *the* address configured for this `slot_id` in *this* contract" — it never checks that the signature was produced with *this* contract/message type in mind:

- HTTP POST handler rejects only on `BadSigner` (address mismatch), not on cross-contract mismatch: [5](#0-4) 
- Local DB write path (`try_replace_chunk`) only checks the recovered address against the configured `signer` for that `slot_id`: [6](#0-5) 
- Gossip/push validation (`validate_received_chunk`) looks up the owner *for this specific contract* and calls `slot_metadata.verify(&addr)`, which only checks the recovered pubkey-hash equality, not contract binding: [7](#0-6) 
- Unsolicited push-chunk handling exhibits the identical acceptance logic (rejects only on wrong-signer, not wrong-contract): [8](#0-7) 

Because a signer's chunk pushes are broadcast on the p2p network (no secrecy involved — StackerDB gossip is public), any unprivileged peer can observe a validly signed `StackerDBChunkData`/`StackerDBPushChunkData` for `.signers-<set>-<msgA>`, and re-submit that identical byte sequence (same `slot_id`, `slot_version`, `sig`, `data`) via `POST /v2/stackerdb/.../chunks` or via unsolicited `StackerDBPushChunk` gossip targeting `.signers-<set>-<msgB>` for the same reward-cycle/signer-set. If the target replica's current slot version is still below the replayed `slot_version` (a very likely state, since different message-type DBs advance independently), the write is accepted as if the signer had authorized it for that DB.

### Impact Explanation
This is an unauthenticated/unauthorized write into a StackerDB replica: the signer's authorization was scoped to one message-type DB but the code accepts it for any DB sharing that slot assignment. Concrete consequences:
- **Griefing/DoS on the signer's slot**: the attacker can advance `slot_version` in a DB the signer never intended to write, consuming that replica's monotonic version counter and (where `max_writes` is finite) exhausting the signer's write budget for that message-type DB without the signer's consent.
- **Cross-type data injection**: an attacker can plant one message type's payload into a different message-type StackerDB slot as "signed" data. Downstream consumers that parse chunk content by DB/message type (e.g. the signer state-machine loader) may store or process attacker-replayed bytes believing they are freshly authorized for that specific channel, since deserialization/consumption code for a given `.signers-<set>-<msg>` contract has no way to detect that the signature was scoped to a different contract.
- No secret key, no privileged role, and no local resources are required — only observation of otherwise-public gossip and a single unauthenticated HTTP POST or unsolicited push.

### Likelihood Explanation
High feasibility: all inputs (the legitimate chunk) are obtainable by any network participant via ordinary StackerDB gossip/replication, which is the protocol's normal operation. The only precondition — that the same signer occupies the same `slot_id` in two different `.signers-<set>-*` contracts — is guaranteed by design, since every `.signers-<set>-<message_id>` contract reads the identical slot list from `.signers`. No timing races or privileged access are required; a single well-timed POST/gossip message is sufficient.

### Recommendation
Bind the signed digest to the target StackerDB context so signatures cannot be replayed across replicas: include the `smart_contract_id` (and ideally message/type discriminant) inside `SlotMetadata::auth_digest()` (and consequently in `sign()`/`verify()`), and correspondingly update all producers (`stacks-signer` clients) to sign against the augmented digest. This restores the missing domain separation, analogous to fixing CakePHP's `SecurityComponent` by binding the security token to the specific form/action rather than accepting it for any form submission.

### Proof of Concept
1. Observe (via normal StackerDB chunk-push gossip) a validly signed `StackerDBChunkData { slot_id: i, slot_version: v, sig, data }` broadcast by signer `S` for `.signers-<set>-<msgA>`.
2. Confirm (from public `.signers` contract state) that `S` also owns `slot_id = i` in `.signers-<set>-<msgB>` (guaranteed, since both derive from the same `stackerdb-get-signer-slots-page`).
3. If `.signers-<set>-<msgB>`'s current version for slot `i` is `< v`, submit the identical `(slot_id, slot_version, sig, data)` tuple to `.signers-<set>-<msgB>` via `POST /v2/stackerdb/<msgB-contract>/chunks` (see `poststackerdbchunk.rs`) or via unsolicited `StackerDBPushChunk` gossip.
4. `validate_received_chunk`/`try_replace_chunk` accept the write because `slot_metadata.verify(&addr)` only checks that the recovered pubkey hash equals `S`'s address for `msgB`'s slot `i` — it never checks that `S` signed intending `msgB`.

    /// Get the digest to sign that authenticates this chunk data and metadata
    fn auth_digest(&self) -> Sha512Trunc256Sum {
        let mut hasher = Sha512_256::new();
        hasher.update(self.slot_id.to_be_bytes());
        hasher.update(self.slot_version.to_be_bytes());
        hasher.update(self.data_hash.0);
        Sha512Trunc256Sum::from_hasher(hasher)
    }

    /// Sign this slot metadata, committing to slot_id, slot_version, and
    /// data_hash.  Sets self.signature to the signature.
    /// Fails if the underlying crypto library fails
    pub fn sign(&mut self, privkey: &StacksPrivateKey) -> Result<(), Error> {
        let auth_digest = self.auth_digest();
        let sig = privkey
            .sign(&auth_digest.0)
            .map_err(|se| Error::SigningError(se.to_string()))?;

        self.signature = sig;
        Ok(())
    }

    /// Verify that a given principal signed this chunk metadata.
    /// Note that the address version is ignored.
    pub fn verify(&self, principal: &StacksAddress) -> Result<bool, Error> {
        let sigh = self.auth_digest();
        let pubk = StacksPublicKey::recover_to_pubkey_without_validating_low_s(
            sigh.as_bytes(),
            &self.signature,
        )
        .map_err(|ve| Error::VerifyingError(ve.to_string()))?;

        let pubkh = Hash160::from_node_public_key(&pubk);
        Ok(pubkh == *principal.bytes())
    }

pub enum StackerDBErrorCodes {
    /// The slot already holds a chunk whose version is at least the one submitted.
    DataAlreadyExists,
    /// The chunk's slot ID is out of range for this replica's slot allocation.
    NoSuchSlot,
    /// The chunk's signature does not recover to the address that owns the slot.
    BadSigner,
    /// The chunk exceeds the replica's configured chunk size.
    ChunkTooBig,
    /// The chunk's slot version exceeds the replica's configured maximum writes.

}

impl StackerDBErrorCodes {
    pub fn code(&self) -> u32 {

            Self::DataAlreadyExists => 0,
            Self::NoSuchSlot => 1,

            Self::ChunkTooBig => 3,
