### Title
Cross-StackerDB-instance signature replay due to missing domain separation in `SlotMetadata` signing scheme - (File: `libstackerdb/src/libstackerdb.rs`)

### Summary
`SlotMetadata::auth_digest()` computes the signed digest for a StackerDB chunk from only `slot_id`, `slot_version`, and `data_hash` [1](#0-0) . It does not bind the signature to the smart-contract identifier of the StackerDB instance (or to any reward-cycle/consensus-hash context). The contract identity is only used *after* the fact, to look up which `StacksAddress` is expected to own a given `slot_id` for that particular contract [2](#0-1) . This is the same class of bug as the reported EIP-2612 issue: the signature scheme lacks a "chain ID"-equivalent domain separator, so a signature valid in one context can be replayed in a structurally similar but distinct context.

### Finding Description
A StackerDB chunk is authenticated purely via `SlotMetadata::verify()`, which recovers the public key from the digest `sha512/256(slot_id || slot_version || data_hash)` and compares its hash to the `StacksAddress` on file for `(contract_id, slot_id)` [3](#0-2) . The `contract_id` (and the `rc_consensus_hash` carried in `StackerDBPushChunkData`) never enters the signed bytes — they are look-up keys/wire metadata only, as seen in `StackerDBPushChunkData`'s wire format [4](#0-3)  and its codec [5](#0-4) .

Consequently, `validate_received_chunk()` (used both for sync-downloaded chunks and for unsolicited pushes) will accept a chunk whose signature was produced for a *different* StackerDB smart contract, as long as:
1. The same signer address happens to own the same `slot_id` in the target contract (a common situation, since successive reward-cycle signer-set StackerDB contracts, e.g. `signers-N-*`, frequently re-assign the same relative slot index to the same signer address), and
2. `slot_version`/`max_writes` and the size checks in the target contract's config are satisfied [6](#0-5) .

This is precisely the equality the report's bug class breaks: "signature authenticated for domain A" is treated as "signature authenticated for domain B" because no domain separator (contract_id / reward-cycle identity) is part of the signed payload — the StackerDB analog of a chain-forked EIP-2612 domain separator collision.

### Impact Explanation
An attacker who observes any legitimately signed chunk broadcast for slot `S` in StackerDB contract `A` (chunks are gossiped in plaintext over p2p and are also servable via read endpoints) can replay that exact `StackerDBChunkData` (same `sig`, `slot_id`, `slot_version`, `data`) into a *different* StackerDB contract `B` in which the same address owns slot `S`, via `StackerDBPushChunk` or via the chunk-upload write path, and have the node accept and store it as valid for `B` (`validate_received_chunk` returns `Ok(true)`, and `try_replace_chunk` in `db.rs` performs the write) despite the true slot owner never having signed/authorized any data for `B`. This causes an unauthorized/unintended write of attacker-selected, previously-signed data into a StackerDB instance the signer did not target, and gets propagated to peers as legitimate new chunk data. This matches "unauthenticated/unauthorized write to state or StackerDB" / "network-wide propagation of forged data" in the impact rubric, since the content lands in a context the signer never authorized, potentially confusing signer-set consensus state stored via these StackerDB messages between reward cycles.

### Likelihood Explanation
Exploitation is remote and unprivileged: it requires only observing one broadcast/legitimately-obtained chunk (chunks are not secret; they propagate over the p2p network and can be fetched via `StackerDBGetChunk`) and replaying it toward a different, structurally compatible StackerDB contract. No node secret or admin role is required — only a passively/actively observed valid signature and knowledge that the target contract assigns the same slot index to the same address (which is derivable from the target contract's signer set, itself public smart-contract state).

### Recommendation
- **Short term**: Include a domain separator in `SlotMetadata::auth_digest()` — e.g., the `QualifiedContractIdentifier` (or a hash of it) and/or the network/chain ID — so a signature is only valid for the specific StackerDB instance it was produced for.
- **Long term**: Audit all message-signing schemes in `libstackerdb`/`libsigner` for missing domain separation (contract ID, reward cycle, network ID) to prevent cross-instance or cross-fork signature replay, mirroring the mitigation recommended for `DOMAIN_SEPARATOR` regeneration in EIP-2612 permit contracts.

### Proof of Concept
1. Signer `S` (address `addr`) is assigned `slot_id = 5` in StackerDB contract `A` (e.g., reward-cycle N signer set) and signs a `StackerDBChunkData { slot_id: 5, slot_version: 1, data: D }` via `StackerDBChunkData::sign` [7](#0-6) .
2. This chunk is broadcast normally (e.g. `StackerDBPushChunkData { contract_id: A, ... }`) and observed by an attacker.
3. `addr` is also assigned `slot_id = 5` in contract `B` (e.g., reward-cycle N+1's StackerDB contract, common when relative signer ranking is preserved), currently at version 0.
4. Attacker sends `StackerDBPushChunkData { contract_id: B, rc_consensus_hash: <current for B>, chunk_data: <same chunk from step 1> }` to a node replicating `B`.
5. `handle_unsolicited_StackerDBPushChunk` → `validate_received_chunk(B, config_B, chunk, expected_versions)` looks up `get_slot_signer(B, 5)` → `addr`, verifies via `slot_metadata.verify(&addr)` which succeeds because the digest formula ignores `contract_id` [2](#0-1) ; version check (`1 >= 0`) passes; chunk is accepted and stored/rebroadcast for contract `B`, even though `addr` never authorized data for `B`.

    /// Get the digest to sign that authenticates this chunk data and metadata
    fn auth_digest(&self) -> Sha512Trunc256Sum {
        let mut hasher = Sha512_256::new();
        hasher.update(self.slot_id.to_be_bytes());
        hasher.update(self.slot_version.to_be_bytes());
        hasher.update(self.data_hash.0);
        Sha512Trunc256Sum::from_hasher(hasher)
    }

    /// Note that the address version is ignored.
    pub fn verify(&self, principal: &StacksAddress) -> Result<bool, Error> {
        let sigh = self.auth_digest();
        let pubk = StacksPublicKey::recover_to_pubkey_without_validating_low_s(
            sigh.as_bytes(),
            &self.signature,
        )
        .map_err(|ve| Error::VerifyingError(ve.to_string()))?;

        let pubkh = Hash160::from_node_public_key(&pubk);
        Ok(pubkh == *principal.bytes())
    }

    pub fn validate_received_chunk(
        &self,
        smart_contract_id: &QualifiedContractIdentifier,
        config: &StackerDBConfig,
        data: &StackerDBChunkData,
        expected_versions: &[u32],
    ) -> Result<bool, net_error> {
        // validate -- must not exceed this replica's configured chunk size.
        if (data.data.len() as u64) > config.chunk_size {
            info!(
                "Received StackerDBChunk for {} ID {}, which is oversized: {} bytes (max {} bytes)",
                smart_contract_id,
                data.slot_id,
                data.data.len(),
                config.chunk_size
            );
            return Ok(false);
        }

        // validate -- must be a valid chunk
        let Some(expected_version) = expected_versions.get(data.slot_id as usize) else {
            info!(
                "Received StackerDBChunk for {} ID {}, which is too big ({})",
                smart_contract_id,
                data.slot_id,
                expected_versions.len()
            );
            return Ok(false);
        };

        // validate -- must be signed by the expected author
        let addr = match self
            .stackerdbs
            .get_slot_signer(smart_contract_id, data.slot_id)?
        {
            Some(addr) => addr,
            None => {
                return Ok(false);
            }
        };

        let slot_metadata = data.get_slot_metadata();
        if !slot_metadata.verify(&addr)? {
            info!(
                "StackerDBChunk for {} ID {} is not signed by {}",
                smart_contract_id, data.slot_id, &addr
            );
            return Ok(false);
        }

        // validate -- must be the current or newer version
        if data.slot_version < *expected_version {
            info!(
                "Received StackerDBChunk for {} ID {} version {}, which is stale (expected {})",
                smart_contract_id, data.slot_id, data.slot_version, *expected_version
            );
            return Ok(false);
        }

        // validate -- must not exceed max writes
        if data.slot_version > config.max_writes {
            info!(
                "Write count exceeded for StackerDBChunk for {} ID {} version {} (max is {})",
                smart_contract_id, data.slot_id, data.slot_version, config.max_writes
            );
            return Ok(false);
        }

        Ok(true)
    }
