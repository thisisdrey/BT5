### Title
Unauthenticated cross-repository object disclosure via `LinkRepositoryToObjectPool` linking any repository to an attacker-chosen object pool - ([File: internal/gitaly/service/objectpool/link.go])

### Summary
`LinkRepositoryToObjectPool` accepts a caller-supplied `object_pool` repository from the RPC request and unconditionally calls `pool.Link(ctx, repo)`, which writes that pool's path into the target repository's `objects/info/alternates` file [1](#0-0) . Aside from validating that the pool path is a well-formed pool repository (`storage.IsPoolRepository` / `pool.IsValid`) [2](#0-1) , there is no check that the `object_pool` actually belongs to, was forked from, or is otherwise legitimately associated with the target `repository`. This mirrors the Anyswap bug class: a caller-supplied "target" (`_anyswapData.router` / here, `object_pool`) is trusted to receive/grant broad, persistent privilege (infinite ERC20 approval / here, permanent alternate-object-directory read access) without validating the relationship between caller and target.

### Finding Description
Once linked, Git treats the pool's entire object database as locally readable to the member repository via alternates, permanently and without further authorization checks, as documented in `doc/object_pools.md` [3](#0-2) . The core `Link` function only checks whether the repository is *already* linked to a pool with an unexpected value; it does not verify that the pool is the pool this repository was created for [4](#0-3) . The gRPC handler itself performs no ownership/lineage validation between `req.GetRepository()` and `req.GetObjectPool()` before calling `pool.Link` [1](#0-0) . Any caller with access to invoke this RPC against two repositories (e.g., their own two projects on a shared storage) can link a repository they control to an arbitrary existing pool repository, and thereby gain persistent read access — via `git cat-file`, `git fetch`, or any read RPC — to every object contained in that pool, including objects that belong to unrelated, private forks that also happen to share the same pool.

### Impact Explanation
This is a cross-repository object access vulnerability: linking to an arbitrary pool grants durable, unauthenticated read access to potentially private objects (blobs, commits, trees) belonging to other users'/projects' repositories that share that object pool, since Git alternates expose the entire object store of the alternate, not just objects reachable from specific refs. This can lead to disclosure of private source code, secrets committed to history, or other sensitive repository content across a forking boundary that the caller should not have access to.

### Likelihood Explanation
The `LinkRepositoryToObjectPool` RPC is a MUTATOR-classified RPC reachable by any client (Rails/gitlab-shell or GitLab worker) with the ordinary authorization to invoke Gitaly RPCs against a repository they can write to — it is exercised routinely by GitLab as part of the fork-object-pool lifecycle [5](#0-4) . Exploitation only requires knowing/guessing a pool's `storage_name`/`relative_path` (pool paths use a somewhat predictable `@pools/...` hashed layout) and calling this RPC against a repository the attacker controls, making likelihood moderate to high depending on how strictly the calling layer (e.g., GitLab Rails) restricts which pools a caller may reference.

### Recommendation
Validate that the `object_pool` in `LinkRepositoryToObjectPoolRequest` is actually associated with the `repository` being linked (e.g., verify the pool's known member list, or that the pool was created from/for this repository's fork network) before writing the alternates file, rather than trusting the caller-supplied pool reference outright.

### Proof of Concept
1. Attacker creates/owns Repository A and Repository B on the same Gitaly storage.
2. Attacker discovers or is granted access to invoke Gitaly RPCs, and knows (or brute-forces) the `storage_name`/`relative_path` of an existing object pool `P` belonging to an unrelated private repository (e.g. via GitLab's `@pools/<hash>` naming scheme).
3. Attacker calls `LinkRepositoryToObjectPool(object_pool=P, repository=A)`.
4. `internal/gitaly/service/objectpool/link.go` calls `pool.Link(ctx, repoA)`, which writes `P`'s object directory path into `A/objects/info/alternates` with no ownership check [6](#0-5) .
5. Attacker now reads objects from `P` (including private objects unrelated to `A`) through ordinary read RPCs against `A`, such as `GetBlob`/`TreeEntry`/`CommitService`, since Git resolves any object hash present in the alternate.

func (s *server) LinkRepositoryToObjectPool(ctx context.Context, req *gitalypb.LinkRepositoryToObjectPoolRequest) (*gitalypb.LinkRepositoryToObjectPoolResponse, error) {
	repository := req.GetRepository()
	if err := s.locator.ValidateRepository(ctx, repository); err != nil {
		return nil, structerr.NewInvalidArgument("%w", err)
	}

	pool, err := s.poolForRequest(ctx, req)
	if err != nil {
		return nil, err
	}

	repo := s.localRepoFactory.Build(repository)

	if err := pool.Link(ctx, repo); err != nil {
		return nil, structerr.NewInternal("%w", err)
	}

	return &gitalypb.LinkRepositoryToObjectPoolResponse{}, nil
}

func FromProto(
	ctx context.Context,
	logger log.Logger,
	locator storage.Locator,
	gitCmdFactory gitcmd.CommandFactory,
	catfileCache catfile.Cache,
	txManager transaction.Manager,
	housekeepingManager housekeepingmgr.Manager,
	proto *gitalypb.ObjectPool,
) (*ObjectPool, error) {
	poolPath, err := locator.GetRepoPath(ctx, proto.GetRepository(), storage.WithRepositoryVerificationSkipped())
	if err != nil {
		return nil, err
	}

	if !storage.IsPoolRepository(proto.GetRepository()) {
		// When creating repositories in the ObjectPool service we will first create the
		// repository in a temporary directory. So we need to check whether the path we see
		// here is in such a temporary directory and let it pass.

		if err != nil {
			return nil, fmt.Errorf("getting temporary storage directory: %w", err)

		txManager:           txManager,
		housekeepingManager: housekeepingManager,
	}

	if !pool.IsValid(ctx) {
		return nil, ErrInvalidPoolRepository
	}

# Object Pools

When creating forks of a repository, most of the objects for forked repository
and the repository it forked from are shared. Storing those shared objects
multiple times is a waste of disk space and also of CPU time, given that those
shared objects would have to be repacked for both repositories. To fix this
waste of resources, we use object pools, which are essentially a repository
which holds the shared objects of both repositories.

The sharing of objects for a given repository and its object pool is done via
alternate object directories which Gitaly sets up when linking a repository to
an object pool by writing the `objects/info/alternates` file.

func (o *ObjectPool) Link(ctx context.Context, repo *localrepo.Repo) error {
	return Link(ctx, o.Repo, repo, o.txManager)

// Link will link the given repository to the object pool. This is done by writing the object pool's
// path relative to the repository into the repository's "alternates" file. This does not trigger
// deduplication, which is the responsibility of the caller.
func Link(ctx context.Context, pool, repo *localrepo.Repo, txManager transaction.Manager) (returnedErr error) {
	altPath, err := repo.InfoAlternatesPath(ctx)
	if err != nil {
		return err
	}

	expectedRelPath, err := getRelativeObjectPath(ctx, pool, repo)
	if err != nil {
		return err
	}

	linked, err := linkedToRepository(ctx, pool, repo)
	if err != nil {
		return err
	}

	if linked {
		// When the repository is already linked to the repository, cast a vote to ensure the
		// repository is consistent with the other replicas.
		if err := transaction.VoteOnContext(ctx, txManager, voting.VoteFromData([]byte("repository linked")), voting.Synchronized); err != nil {
			return fmt.Errorf("vote on linked repository: %w", err)
		}

		return nil
	}

	alternatesWriter, err := safe.NewLockingFileWriter(altPath)
	if err != nil {
		return fmt.Errorf("creating alternates writer: %w", err)
	}
	defer func() {
		if err := alternatesWriter.Close(); err != nil && returnedErr == nil {
			returnedErr = fmt.Errorf("closing alternates writer: %w", err)
		}
	}()

	if _, err := io.WriteString(alternatesWriter, expectedRelPath); err != nil {
		return fmt.Errorf("writing alternates: %w", err)
	}
