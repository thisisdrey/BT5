### Title
Protocol fee bypass on Nep245/Imt tokens via splitting a bulk transfer into unit-delta `TokenDiff` legs - (File: contracts/defuse/core/src/intents/token_diff.rs)

### Summary
`TokenDiff::token_fee` exempts Nep245/Imt token legs from fees when the per-intent `|delta| <= 1`, and this exemption is evaluated independently for every `TokenDiff` intent in a batch rather than on the aggregate amount transferred for a given token. An attacker can split a bulk Nep245/Imt transfer of size N into N separate `TokenDiff` intents (packed into one or more `MultiPayload`s) each with `delta = -1`, causing `token_fee` to return `Pips::ZERO` for every leg, so the total fee collected is `0` instead of `Pips::fee_ceil(protocol_fee, N)`.

### Finding Description
The claimed binding: `fees credited to fee_collector for token T across the batch == Pips::fee_ceil(protocol_fee, sum of |negative deltas of T|)`. This is violated whenever the sum of `|negative deltas of T|` is split across multiple `TokenDiff` intents with `|delta| <= 1` each.

Root cause is in `TokenDiff::token_fee`: [2](#0-1) 
For `TokenIdType::Nep245`/`Imt`, if `amount > 1` the normal `fee` is charged, but if `amount <= 1` it returns `Pips::ZERO` ("do not take fees on NFTs and MTs with |delta| <= 1").

`TokenDiff::execute_intent` computes this fee per intent, using only that intent's own `delta` for the token, not any batch-wide total: [3](#0-2) 

`Engine::execute_signed_intents` processes an arbitrary list of `MultiPayload`s sequentially, and each payload's `DefuseIntents` can itself contain an arbitrary `Vec<Intent>`, each `TokenDiff` executed and fee-accounted independently: [4](#0-3) [5](#0-4) 

Exploit flow: signer holding N units of an Nep245/Imt token crafts either one `MultiPayload` containing N `TokenDiff` intents (or N separate signed `MultiPayload`s with distinct nonces) each with `diff = {token_id: -1, other_token_id: +k}`, matched by a counterparty's opposing `TokenDiff` intent(s) so the batch nets to zero per the `TransferMatcher::finalize` invariant (`InvariantViolated::UnmatchedDeltas`) at [6](#0-5) . Each of the N legs independently gets `amount = 1 <= 1`, so `token_fee` returns `Pips::ZERO` for every leg — total fee = 0. Submitting the same net transfer as a single `TokenDiff` with `delta = -N` (`N > 1`) instead charges `fee_ceil(protocol_fee, N)`. None of `MultiPayload::verify`, nonce/salt checks, or the `TransferMatcher` invariant check the aggregate fee-taking amount per token across intents — the invariant only ensures deltas net to zero, not that fees were computed on the combined amount.

### Impact Explanation
The fee_collector (protocol) permanently loses the protocol fee that would otherwise be collected on Nep245/Imt token legs whenever a transfer of size N>1 is restructured as N unit legs. This is repeatable for any account, any Nep245/Imt token, and any batch size, with no cap — the larger N, the more fee is bypassed (potentially the entire fee on a large MT transfer). This matches the explicitly listed Critical category "protocol fees bypassed."

### Likelihood Explanation
Preconditions are minimal and fully within an unprivileged attacker's control: hold ≥1 unit of an Nep245/Imt token, a counterparty (which can be the attacker's own second account) to net the batch to zero, and `protocol_fee > 0`. No special role, relayer key, or DAO/upgrade access is needed — only the ability to sign `MultiPayload`s and call `execute_intents`, which is standard usage. Cost is just constructing N small intents instead of 1; NEAR gas/storage costs are explicitly out of scope for severity but do not meaningfully deter exploitation for realistic N.

### Recommendation
Compute the Nep245/Imt fee exemption on the aggregate negative delta for a given `token_id` across the entire batch (i.e., inside `TransferMatcher`/`Deltas` finalization, or by pre-aggregating all `TokenDiff` intents' deltas per token before applying `token_fee`), rather than per individual `TokenDiff` intent. Alternatively, remove the `amount <= 1` exemption entirely, or bound how many `TokenDiff` intents touching the same token/signer combination can appear before fee is computed on their sum.

### Proof of Concept
`cargo test` in `contracts/defuse/core` (or `tests/src/tests/defuse/intents/token_diff.rs` sandbox test):
1. Configure `Env::builder().fee(Pips::ONE_PERCENT)` (or any nonzero fee) with an Nep245/Imt token `T`.
2. Deposit `N` units (e.g., `N = 10`) of `T` to `user1`, and enough of a paired FT `T2` to `user2` to allow a matching swap.
3. Case A ("combined"): sign one `TokenDiff` from `user1` with `diff = {T: -N, T2: +M}` and a matching `TokenDiff` from `user2` with `diff = {T: +N, T2: -M}` (using `TokenDiff::closure_delta`/`closure_supply_delta` to keep the invariant satisfied with fee). Execute via `execute_intents`; assert `fees_collected.amount_for(&T) == Pips::fee_ceil(fee, N)` (nonzero).
4. Case B ("split"): sign `N` separate `TokenDiff` intents from `user1`, each `diff = {T: -1, T2: +m_i}`, plus matching counter legs from `user2`, so the batch still nets to zero. Execute via `execute_intents`; assert `fees_collected.amount_for(&T) == 0`.
5. Assert `fees_collected_case_A.amount_for(&T) > fees_collected_case_B.amount_for(&T)` even though both move the same total `N` units of `T`, demonstrating the fee bypass and violating the stated binding.

    // Finalizes all transfers, or returns unmatched deltas.
    // If unmatched deltas overflow, then Err(None) is returned.
    pub fn finalize(self) -> Result<Transfers, InvariantViolated> {
        let mut transfers = Transfers::default();
        let mut deltas = TokenDeltas::default();
        for (token_id, transfer_matcher) in self.0 {
            if let Err(unmatched) = transfer_matcher.finalize_into(&token_id, &mut transfers)
                && (unmatched == 0 || deltas.apply_delta(token_id, unmatched).is_none())
            {
                return Err(InvariantViolated::Overflow);
            }
        }
        if !deltas.is_empty() {
            return Err(InvariantViolated::UnmatchedDeltas {
                unmatched_deltas: deltas,
            });
        }
        Ok(transfers)
    }
}
