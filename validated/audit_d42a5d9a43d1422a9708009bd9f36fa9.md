### Title
Malicious peer can indefinitely monopolize a canonical tenure's download slot via timeout-adjacent stalling, blocking failover to honest peers - ([File: stackslib/src/net/download/nakamoto/tenure_downloader_set.rs])

### Summary
`NakamotoTenureDownloaderSet::make_tenure_downloaders` refuses to create a new downloader for a `ConsensusHash` if `has_downloader_for_tenure` finds any existing (even non-idle) downloader entry for that tenure, and only frees the peer/downloader slot when `NeighborRPC::is_dead_or_broken` fires or the download naturally finishes. A malicious peer that always responds just under the dead/broken timeout, and never lets its download reach `is_done()`, keeps its assigned downloader permanently non-idle and non-dead, which blocks the scheduler from ever trying an honest alternate peer for that same tenure.

### Finding Description
`has_downloader_for_tenure` iterates all downloaders and returns `true` if any entry — idle or not, dead or not — matches the target `ConsensusHash`: [1](#0-0) 

In `make_tenure_downloaders`, for each candidate peer popped for a scheduled tenure `ch`, the code first tries `try_resume_peer` (which only reassigns *idle* downloader slots), and if that fails, checks `has_downloader_for_tenure(ch)`; if true, it simply drops the schedule entry (`schedule.pop_front()`) without instantiating a downloader for the new candidate peer, discarding any other honest peers that were queued for that tenure: [2](#0-1) 

The only mechanisms that free up a slot to allow a different peer are:
1. The downloader becoming idle (checked via `clear_available_peers`, which only removes peer bindings for downloaders where `downloader.idle == true`) — allowing `try_resume_peer` to hijack that slot for a different peer: [3](#0-2) 
2. The peer being marked dead/broken by `NeighborRPC::is_dead_or_broken`, checked in `run()`: [4](#0-3) 

If a malicious peer answers each HTTP request just under the dead/broken timeout on every round of `run()`/`download_confirmed_tenures`, its downloader never transitions to `idle=true` at the moment `make_tenure_downloaders` polls state (since a request is effectively always outstanding or immediately re-issued), and `is_dead_or_broken` never trips because the peer is technically responsive within the timeout window. As long as the attacker also avoids ever completing the tenure (e.g., returning data that is accepted without error but does not advance the downloader to `is_done()`), the slot for that `ConsensusHash` remains permanently occupied by the malicious peer, and `has_downloader_for_tenure` will keep discarding every other candidate honest peer offering the same tenure.

Because `NakamotoTenureDownloaderSet::run` documents that "each machine can make progress even if there is only one available peer," the design assumes any stalled machine will eventually go idle or die — but this assumption depends entirely on the wire-level, purely-elapsed-time-based `is_dead_or_broken` check having no complementary "no forward progress" / total-attempt budget at the tenure-scheduling layer. No such complementary check exists in `tenure_downloader_set.rs`.

### Impact Explanation
This lets a single unprivileged, remotely-reachable peer stall a node's confirmed-tenure download pipeline for a specific `ConsensusHash` indefinitely, without needing to be trusted, privileged, or to hold any secret — merely responding to legitimate download requests slowly (just under the timeout) is sufficient. Since `NakamotoTenureDownloader` for tenure N+1 depends on tenure N's blocks being obtained first (as noted in the module's own design comment), stalling a single tenure can cascade to block sync progress for all subsequent tenures, effectively steering/keeping the node off the canonical tip while consuming negligible bandwidth (not a volumetric attack — a single slow connection suffices).

### Likelihood Explanation
The attacker needs only to run an ordinary Stacks p2p peer, advertise (via inventory) that it has the targeted tenure, and answer the corresponding HTTP-over-P2P download request at "timeout minus epsilon" while returning parseable-but-non-completing payloads. This requires no privileged role, no secret, and no volumetric traffic — it is a pure protocol-timing/state-machine gap. Reachability is standard P2P connectivity that any peer already has.

### Recommendation
Add a maximum total-time / maximum-attempts budget per tenure download independent of individual request timeouts (e.g., track `first_assigned` time or an attempt counter in `NakamotoTenureDownloaderSet`), and evict/deprioritize a downloader (freeing the slot for another peer) once that budget is exceeded, even if the peer is not formally "dead or broken." Alternatively, make `has_downloader_for_tenure` allow instantiation of a competing downloader to a different peer for the same tenure when the existing one has been non-idle beyond some staleness threshold.

### Proof of Concept
Add a test in `stackslib/src/net/tests/download/nakamoto.rs` (or a new unit test in `tenure_downloader_set.rs`) that:
1. Constructs a `NakamotoTenureDownloaderSet` with one scheduled `ConsensusHash` and two candidate peers: peer A (malicious) and peer B (honest), both advertising the tenure via `tenure_block_ids`.
2. Calls `make_tenure_downloaders` so peer A is assigned to the downloader for `ch` (verify via `has_downloader_for_tenure(&ch)` and `downloaders[..].naddr == peer_a`).
3. Mocks `NeighborRPC`/network so peer A's responses always arrive at `connection_opts.timeout - 1` and never advance the downloader to `is_done()` (e.g., stub `handle_next_download_response` to return `Ok(Some(vec![]))` repeatedly, or use a controllable mock stream).
4. Loops calling `run()` (or `download_confirmed_tenures`) many times, asserting after each iteration that `neighbor_rpc.is_dead_or_broken(&peer_a)` is `false`, `downloaders[idx].idle` is `false`, and `peers.get(&peer_b)` is never populated / peer B's slot is never created for `ch`.
5. Final assertion: after N iterations (bounded by test-controlled wall clock), `has_downloader_for_tenure(&ch)` is still `true` and bound exclusively to peer A, proving peer B was never tried despite being available and honest.

    /// Does there exist a downloader (possibly unscheduled) for the given tenure?
    pub(crate) fn has_downloader_for_tenure(&self, tenure_id: &ConsensusHash) -> bool {
        for downloader_opt in self.downloaders.iter() {
            let Some(downloader) = downloader_opt else {
                continue;
            };
            if &downloader.tenure_id_consensus_hash == tenure_id {
                debug!(
                    "Have downloader for tenure {tenure_id} already (idle={}, state={}, naddr={})",
                    downloader.idle, &downloader.state, &downloader.naddr
                );
                return true;
            }
        }
        false
    }
