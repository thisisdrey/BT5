## Analysis

The bug class in the Sherlock report is: an exchange-rate/price-ratio division computed with insufficient fixed-point precision that silently rounds down to zero, defeating a downstream minimum-amount safety check and letting an attacker extract value while paying (or fronting) no cost. The closest verified local analog is in Snowbridge's outbound-queue fee pricing.

### Title
Outbound message fee (`remote` component) silently rounds to zero, letting senders under-pay for committed Ethereum-side relayer rewards - (File: `bridges/snowbridge/pallets/outbound-queue/src/lib.rs`)

### Summary
`Pallet::<T>::calculate_fee` converts the ether-denominated remote cost of a message into the parachain's native currency by dividing by `params.exchange_rate` (a `FixedU128`). When `exchange_rate` is large relative to the remote fee (i.e. `fee_in_wei * multiplier < 1/exchange_rate` in fixed-point terms), integer/fixed-point division truncates the `remote` fee component to `0`, exactly like the Sherlock finding's `(priceIn * 1e8) / priceOut == 0` case. [1](#0-0) 

This is not hypothetical: the pallet's own test suite reproduces it directly. [2](#0-1) 

### Finding Description
`calculate_fee` is invoked from `SendMessage::validate`, which is the public entry point used by any pallet/XCM path that sends a message to Ethereum (via `EthereumBlobExporter::deliver` or `snowbridge_pallet_system::Pallet::send`): [3](#0-2) 

The returned `Fee { local, remote }` is what upstream callers charge the sender to cover both local processing weight and the remote Ethereum-side gas/reward. Meanwhile, the *actual* value promised to relayers on Ethereum is taken directly from `pricing_params.rewards.remote` (a raw `U256` wei amount) and embedded, unaffected by the truncation, into the `CommittedMessage` that gets merkelized and later paid out on the Gateway contract: [4](#0-3) 

So the two values are computed independently:
- The fee *charged* to the sender for the remote portion = `FixedU128::from_inner(fee).saturating_mul(multiplier).checked_div(&exchange_rate)` → can truncate to `0`.
- The reward *promised* to relayers and later paid in ETH on Ethereum = `pricing_params.rewards.remote` (U256, unaffected).

There is no `require`/`ensure!(fee.remote > 0, ...)` guard anywhere in `calculate_fee`, `validate`, or `deliver`. The only invariant enforced is that the *parameters themselves* are non-zero (`PricingParameters::validate`), not that the *computed* fee is non-zero: [5](#0-4) 

This mirrors exactly the Sherlock root cause: valid, non-zero individual inputs (`priceIn`, `priceOut` / `exchange_rate`, `fee_per_gas`) but a computed derived quantity (`exchangeRate` / `fee.remote`) that rounds to zero, silently bypassing the mechanism meant to make the requester pay for the value they extract.

### Impact Explanation
Governance sets `exchange_rate`, `fee_per_gas`, and `rewards.remote` periodically via `set_pricing_parameters`. Whenever the real-world ETH/DOT price moves such that `exchange_rate` combined with a message's `gas_used_at_most * fee_per_gas + reward` (in wei) yields a fixed-point quotient below one native-currency unit, any unprivileged user sending a low-gas message (e.g. a governance-agnostic, cheap `Command`) pays `fee.remote == 0` while the committed message still carries the full `reward` in wei that Ethereum-side relayers will be paid out of the bridge's real ETH holdings. Repeated cheaply/costlessly, this degrades the bridge's fee model — public, underpriced use of the outbound queue that drains/misallocates the reward budget backing relayer payouts and stalls the intended economics of bridge processing, matching the "public underpriced work that degrades block production or stalls bridge processing" impact category.

### Likelihood Explanation
No special privilege is required — any account that can call into `SendMessage::validate` (via XCM `ExportMessage`/reserve-transfer-to-Ethereum flows, or `snowbridge_pallet_system::Pallet::send`) can trigger this with ordinary parameter values as prices drift, and the pallet's own test (`test_calculate_fees_with_valid_exchange_rate_but_remote_fee_calculated_as_zero`) shows the condition is reachable with plausible, non-degenerate `PricingParameters`. The precision window is realistic given ETH (18 decimals) vs DOT (10 decimals) and volatile ETH/DOT pricing that governance updates only periodically.

### Recommendation
- In `calculate_fee`, after computing `fee.remote`, reject or clamp: `ensure!(fee.remote > Zero::zero() || gas_used_at_most == 0, Error::<T>::FeeTooLow)` (or round up rather than down, e.g. using `checked_rounding_div` with `SignedRounding::Major` as already used elsewhere in the codebase for similar fee-rounding problems, see `substrate/frame/revive/src/evm/fees.rs`'s `compute_max_integer_quotient`).
- Alternatively, enforce a protocol-level minimum non-zero `fee.remote` in `validate` before a `Ticket` is issued, so no message can be queued whose promised Ethereum-side reward is not backed by a correspondingly non-zero collected fee.

### Proof of Concept
Using the existing pallet test harness values:
```rust
// bridges/snowbridge/pallets/outbound-queue/src/test.rs
let price_params = PricingParameters {
    exchange_rate: FixedU128::from_rational(1, 1),
    fee_per_gas: 1_u32.into(),
    rewards: Rewards { local: 1_u32.into(), remote: 1_u32.into() },
    multiplier: FixedU128::from_rational(1, 1),
};
let fee = OutboundQueue::calculate_fee(250_000, price_params.clone());
assert_eq!(fee.remote, 0); // sender pays 0 for the remote/reward portion
// yet CommittedMessage::reward is populated from price_params.rewards.remote (=1 wei, non-zero)
// via do_process_message, independent of the truncated fee.remote charged upstream.
```
This is already asserted by `test_calculate_fees_with_valid_exchange_rate_but_remote_fee_calculated_as_zero` in the repo, confirming the divergence between charged fee and promised on-chain (Ethereum) reward obligation is reachable with non-degenerate configuration. [2](#0-1)

		pub(crate) fn calculate_fee(
			gas_used_at_most: u64,
			params: PricingParameters<T::Balance>,
		) -> Fee<T::Balance> {
			// Remote fee in ether
			let fee = Self::calculate_remote_fee(
				gas_used_at_most,
				params.fee_per_gas,
				params.rewards.remote,
			);

			// downcast to u128
			let fee: u128 = fee.try_into().defensive_unwrap_or(u128::MAX);

			// multiply by multiplier and convert to local currency
			let fee = FixedU128::from_inner(fee)
				.saturating_mul(params.multiplier)
				.checked_div(&params.exchange_rate)
				.expect("exchange rate is not zero; qed")
				.into_inner();

			// adjust fixed point to match local currency
			let fee = Self::convert_from_ether_decimals(fee);

			Fee::from((Self::calculate_local_fee(), fee))
		}

	});

	fn validate(
		message: &Message,
	) -> Result<(Self::Ticket, Fee<<Self as SendMessageFeeProvider>::Balance>), SendError> {
		// The inner payload should not be too large
		let payload = message.command.abi_encode();
		ensure!(
			payload.len() < T::MaxMessagePayloadSize::get() as usize,
			SendError::MessageTooLarge
		);

		// Ensure there is a registered channel we can transmit this message on
		ensure!(T::Channels::contains(&message.channel_id), SendError::InvalidChannel);

		// Generate a unique message id unless one is provided
		let message_id: H256 = message
			.id
			.unwrap_or_else(|| unique((message.channel_id, &message.command)).into());

		let gas_used_at_most = T::GasMeter::maximum_gas_used_at_most(&message.command);
		let fee = Self::calculate_fee(gas_used_at_most, T::PricingParameters::get());

		let queued_message: VersionedQueuedMessage = QueuedMessage {
			id: message_id,
			channel_id: message.channel_id,
			command: message.command.clone(),
		}
		.into();
		// The whole message should not be too large
		let encoded = queued_message.encode().try_into().map_err(|_| SendError::MessageTooLarge)?;

		let ticket = Ticket { message_id, channel_id: message.channel_id, message: encoded };

		Ok((ticket, fee))
	}

	pub fn validate(&self) -> Result<(), InvalidPricingParameters> {
		if self.exchange_rate == FixedU128::zero() {
			return Err(InvalidPricingParameters);
		}
		if self.fee_per_gas == U256::zero() {
			return Err(InvalidPricingParameters);
		}
		if self.rewards.local.is_zero() {
			return Err(InvalidPricingParameters);
		}
		if self.rewards.remote.is_zero() {
			return Err(InvalidPricingParameters);
		}
		if self.multiplier == FixedU128::zero() {
			return Err(InvalidPricingParameters);
		}
		Ok(())
	}
