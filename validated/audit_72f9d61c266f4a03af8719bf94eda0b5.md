The analog exists and is essentially a direct port of the Footium bug: `RecurringAirdrop.claim` tracks a cumulative `claimed[msg.sender]` that is never reset across `updateMerkleRoot` calls, and computes the payout as `amount_ - claimed[msg.sender]`, which underflows if a new root encodes per-round (non-cumulative) amounts.

### Title
Users cannot claim airdrop rewards, or claim less than intended, when `merkleRoot` is updated with per-round instead of cumulative amounts - ([File: contracts/utils/RecurringAirdrop.sol])

### Summary
`RecurringAirdrop` (and its deployed specialization `MetAirdrop`) pays out `amount_ - claimed[msg.sender]` on each `claim`. The `claimed` mapping persists across `updateMerkleRoot` calls, so the contract implicitly assumes every new merkle tree encodes each account's *all-time cumulative* entitlement. If a new tree encodes only the current round's amount and that amount is less than what the user already claimed, `claim` reverts on arithmetic underflow, permanently locking that user's round-N reward. If it is larger, the user receives less than intended.

### Finding Description
In `claim` (contracts/utils/RecurringAirdrop.sol:52-66):

```solidity
uint256 _claimable = amount_ - claimed[msg.sender];
if (_claimable == 0) revert NothingToClaim();
claimed[msg.sender] += _claimable;
_transferReward(msg.sender, _claimable);
```

`updateMerkleRoot` (lines 81-90) replaces `merkleRoot` but leaves `claimed` untouched. The leaf is just `keccak256(abi.encodePacked(msg.sender, amount_))` — nothing binds the leaf or the claim accounting to a specific root/round. This is identical to `FootiumPrizeDistributor`'s `totalERC20Claimed`/`totalETHClaimed` pattern.

Concrete scenario:
1. Round 1 root grants Alice 100 tokens. Alice calls `claim(100, proof)`; `claimed[alice] = 100`.
2. Governor calls `updateMerkleRoot` with a round-2 tree granting Alice 50 tokens (intended: +50 this round).
3. Alice calls `claim(50, proof2)`; `50 - 100` underflows and the tx reverts. The 50 tokens are stuck forever — no admin function can decrement `claimed`.
4. If round 2 had granted 150 (i.e., cumulative 250 was intended, or Alice claims 150 while only owed 150 total including round 1), Alice receives `150 - 100 = 50` instead of 150 — a 100-token shortfall.

`MetAirdrop` (contracts/MetAirdrop.sol) inherits `claim` unchanged and only overrides `_transferReward` to lock the payout into esMET, so it carries the same defect; it is deployed on mainnet per `deployments/mainnet/MetAirdrop.json`. The test suite itself encodes the cumulative-amount assumption: `test/MetAirdrop.test.ts:159-177` expects `amount1 - amount0` on the second-round claim.

### Impact Explanation
Permanent freezing of unclaimed rewards: any user whose new leaf amount is less than their `claimed` balance can never claim that round's reward (`claim` always reverts). Users with a larger new amount silently receive less than entitled. Funds remain locked in the airdrop contract (recoverable only via governor `sweep` on MetAirdrop, which just reassigns them).

### Likelihood Explanation
Triggering requires a governor root update, so it is not attacker-initiated. However, the contract gives no on-chain enforcement or even documentation that leaf amounts must be cumulative; the natural way to build a "season 2" distribution file is with per-season amounts, which is precisely the misconfiguration that causes the DoS/shortfall. The cumulative convention is only observable from tests, not from the contract.

### Recommendation
Scope claim tracking per merkle root instead of globally, e.g.:

```solidity
mapping(bytes32 => mapping(address => bool)) public hasClaimed;
// in claim:
if (hasClaimed[merkleRoot][msg.sender]) revert NothingToClaim();
hasClaimed[merkleRoot][msg.sender] = true;
_transferReward(msg.sender, amount_);
```

Alternatively, key `claimed` as `claimed[merkleRoot][account]` if partial claims within one root must remain supported.

### Proof of Concept
Hardhat-style test extending the existing `test/MetAirdrop.test.ts` fixture:

```ts
it('reverts when new root encodes per-round amount below claimed', async () => {
  // Round 1: alice gets 100
  const amount0 = rewards0[alice.address] // = 100
  await airdrop.connect(alice).claim(amount0, merkleTree0.getHexProof(generateLeaf(alice.address, amount0)))
  expect(await airdrop.claimed(alice.address)).eq(amount0)

  // Round 2: leaf encodes only the new-round amount (50 < 100)
  const amount1 = BigNumber.from('50')
  const leaf1 = generateLeaf(alice.address, amount1)
  const rootPerRound = merkleTree1PerRound.getHexRoot() // tree with (alice, 50)
  await airdrop.updateMerkleRoot(rootPerRound, `0x${randomBytes(32).toString('hex')}`)

  // Arithmetic underflow: 50 - 100
  await expect(
    airdrop.connect(alice).claim(amount1, merkleTree1PerRound.getHexProof(leaf1))
  ).to.be.reverted // panic 0x11
})
```

    function claim(uint256 amount_, bytes32[] calldata proof_) external nonReentrant {
        if (merkleRoot == bytes32(0)) revert NothingToClaim();

        bytes32 _leaf = keccak256(abi.encodePacked(msg.sender, amount_));
        if (!MerkleProof.verify(proof_, merkleRoot, _leaf)) revert InvalidProof();

        uint256 _claimable = amount_ - claimed[msg.sender];
        if (_claimable == 0) revert NothingToClaim();

        claimed[msg.sender] += _claimable;

        _transferReward(msg.sender, _claimable);

        emit RewardClaimed(msg.sender, _claimable);
    }
