### Title
Non-owner Active permission holders with `AccountPermissionUpdateContract` authorization can overwrite the Owner permission and seize full account control - (File: `actuator/src/main/java/org/tron/core/actuator/AccountPermissionUpdateActuator.java`)

### Summary
`AccountPermissionUpdateActuator` allows any transaction whose signer authenticates via a non-zero `permissionId` (an Active permission) to fully rewrite an account's Owner permission, Witness permission, and all Active permissions, as long as that Active permission's `operations` bitmap contains the `AccountPermissionUpdateContract` bit. The actuator's `execute()`/`validate()` never checks which `permissionId` authorized the transaction, so a narrowly-scoped delegated key — analogous to Opencast's `ROLE_COURSE_ADMIN` — can use its limited authority to grant itself (or any address) the account's top-level Owner permission.

### Finding Description
`TransactionCapsule.checkPermission()` [1](#0-0)  only verifies that when `permissionId != 0`, the permission used to sign is of type `Active` and its `operations` bitmap has the bit set for the contract type being invoked (`AccountPermissionUpdateContract`), via `checkPermissionOperations`/`WalletUtil.checkPermissionOperations` [2](#0-1) . It does not restrict *what* the contract is allowed to modify, only that the contract type is permitted.

`AccountPermissionUpdateActuator.validate()` and `execute()` accept the entire new `owner`, `witness`, and `actives` permission set from the contract payload and apply them unconditionally via `account.updatePermissions(...)`, with no check tying the requested changes back to the specific permission (`permissionId`) that authorized the transaction: [3](#0-2)  and the full `validate()` body [4](#0-3) .

Critically, `getAvailableContractType()` (used in `checkPermission`) includes `AccountPermissionUpdateContract` as an assignable operation bit for Active permissions — confirmed by the test `checkAvailableContractTypeCorrespondingToCode`, whose expected bitmap includes the contract type [5](#0-4) , in contrast with the *default* active-permission bitmap which explicitly excludes it, per `checkActiveDefaultOperationsCorrespondingToCode` [6](#0-5) . This shows the system deliberately allows an account owner to grant a subordinate Active permission the ability to invoke `AccountPermissionUpdateContract`, presumably to let a delegated key manage that Active permission's own keys/threshold — but nothing in the actuator restricts the scope of what such a delegated key can rewrite. Once granted that single bit, the holder of that Active permission can submit an `AccountPermissionUpdateContract` that replaces the account's Owner permission (`PermissionType.Owner`) with a permission set that includes the attacker's own key at sufficient weight to meet the new threshold — thereby escalating from a narrowly-scoped delegated Active role to full Owner control of the account, with no further validation preventing this (`checkPermission()` only validates internal well-formedness of each permission, not the caller's authorization to modify it) [7](#0-6) .

### Impact Explanation
This is a direct analog of GHSA-94qw-r73x-j7hg / CVE-2020-5231 (CWE-285, Improper Authorization): a limited, non-privileged role is granted a narrow capability, but due to missing fine-grained authorization checks, that capability can be used to seize full administrative control. In java-tron's case, the "narrow capability" is a delegated Active permission with only the `AccountPermissionUpdateContract` bit enabled (e.g., intended to let a delegated party update just that one Active permission's keys), and the "administrative control" is the account's Owner permission — the root-of-trust permission for TRX transfers, resource freezing, voting, and every other on-chain action for that account. An attacker who is granted (or otherwise obtains signing rights over) such an Active permission key can permanently take over the target account, resulting in unauthorized account operations and theft of funds.

### Likelihood Explanation
Exploitation requires that an account owner has, at some point, delegated an Active permission with the `AccountPermissionUpdateContract` operation bit enabled — a valid, supported multisig configuration in TRON (since `getAvailableContractType()` permits it) used e.g. for permission-management delegation. Any account that does this, intentionally or via a compromised key with that narrow scope, is fully exposed to takeover by that key holder, with no additional signatures or threshold from the true Owner key required. This is a realistic and reachable configuration for any advanced multisig user of the network, and requires only a single broadcast transaction to exploit.

### Recommendation
In `AccountPermissionUpdateActuator.validate()`/`execute()`, restrict what a transaction signed via a non-owner `permissionId` may modify: a transaction authorized only via an Active permission (i.e. `contract.getPermissionId() != 0`) should not be allowed to alter the Owner permission, the Witness permission, or any Active permission other than the one it was authorized under. Only transactions authorized by the Owner permission (`permissionId == 0`) should be permitted to rewrite the full permission set.

### Proof of Concept
1. Account owner `A` (Owner permission threshold met by `A`'s key) configures an Active permission `P2` with `operations` bit set for `AccountPermissionUpdateContract`, and assigns delegated key `B` to `P2` (e.g., intending `B` to manage some other limited active permission on `A`'s behalf).
2. `B` crafts and signs (using only `P2`, `permissionId = 2`) an `AccountPermissionUpdateContract` transaction whose `owner` field sets a brand-new Owner permission consisting solely of `B`'s key with `threshold = 1`.
3. `TransactionCapsule.checkPermission` passes because `P2` is `Active` type and has the `AccountPermissionUpdateContract` bit set [1](#0-0) .
4. `AccountPermissionUpdateActuator.validate()`/`execute()` accepts and applies the new Owner permission unconditionally [3](#0-2) .
5. `B` now solely controls account `A`'s Owner permission and can transfer all funds, freeze/unfreeze balances, vote, or further modify permissions at will.

  public static boolean checkPermissionOperations(Permission permission, Contract contract)
      throws PermissionException {
    ByteString operations = permission.getOperations();
    if (operations.size() != 32) {
      throw new PermissionException(String.format("operations size must 32, actual: %d",
          operations.size()));
    }
    int contractType = contract.getTypeValue();
    boolean b = (operations.byteAt(contractType / 8) & (1 << (contractType % 8))) != 0;
    return b;
  }

  private boolean checkPermission(Permission permission) throws ContractValidateException {
    DynamicPropertiesStore dynamicStore = chainBaseManager.getDynamicPropertiesStore();
    if (permission.getKeysCount() > dynamicStore.getTotalSignNum()) {
      throw new ContractValidateException("number of keys in permission should not be greater "
          + "than " + dynamicStore.getTotalSignNum());
    }
    if (permission.getKeysCount() == 0) {
      throw new ContractValidateException("key's count should be greater than 0");
    }
    if (permission.getType() == PermissionType.Witness && permission.getKeysCount() != 1) {
      throw new ContractValidateException("Witness permission's key count should be 1");
    }
    if (permission.getThreshold() <= 0) {
      throw new ContractValidateException("permission's threshold should be greater than 0");
    }
    String name = permission.getPermissionName();
    if (!StringUtils.isEmpty(name) && name.length() > 32) {
      throw new ContractValidateException("permission's name is too long");
    }
    //check owner name ?
    if (permission.getParentId() != 0) {
      throw new ContractValidateException("permission's parent should be owner");
    }

    long weightSum = 0;
    List<ByteString> addressList = permission.getKeysList()
        .stream()
        .map(x -> x.getAddress())
        .distinct()
        .collect(toList());
    if (addressList.size() != permission.getKeysList().size()) {
      throw new ContractValidateException(
          "address should be distinct in permission " + permission.getType());
    }
    for (Key key : permission.getKeysList()) {
      if (!DecodeUtil.addressValid(key.getAddress().toByteArray())) {
        throw new ContractValidateException("key is not a validate address");
      }
      if (key.getWeight() <= 0) {
        throw new ContractValidateException("key's weight should be greater than 0");
      }
      try {
        weightSum = addExact(weightSum, key.getWeight());
      } catch (ArithmeticException e) {
        throw new ContractValidateException(e.getMessage());
      }
    }
    if (weightSum < permission.getThreshold()) {
      throw new ContractValidateException(
          "sum of all key's weight should not be less than threshold in permission " + permission
              .getType());
    }

    ByteString operations = permission.getOperations();
    if (permission.getType() != PermissionType.Active) {
      if (!operations.isEmpty()) {
        throw new ContractValidateException(
            permission.getType() + " permission needn't operations");
      }
      return true;
    }
    //check operations
    if (operations.isEmpty() || operations.size() != 32) {
      throw new ContractValidateException("operations size must 32");
    }

    byte[] types1 = dynamicStore.getAvailableContractType();
    for (int i = 0; i < 256; i++) {
      boolean b = (operations.byteAt(i / 8) & (1 << (i % 8))) != 0;
      boolean t = ((types1[(i / 8)] & 0xff) & (1 << (i % 8))) != 0;
      if (b && !t) {
        throw new ContractValidateException(i + " isn't a validate ContractType");
      }
    }
    return true;
  }

  @Override
  public boolean validate() throws ContractValidateException {

    if (chainBaseManager == null) {
      throw new ContractValidateException(ActuatorConstant.STORE_NOT_EXIST);
    }

    if (this.any == null) {
      throw new ContractValidateException(ActuatorConstant.CONTRACT_NOT_EXIST);
    }

    AccountStore accountStore = chainBaseManager.getAccountStore();
    DynamicPropertiesStore dynamicStore = chainBaseManager.getDynamicPropertiesStore();

    if (dynamicStore.getAllowMultiSign() != 1) {
      throw new ContractValidateException("multi sign is not allowed, "
          + "need to be opened by the committee");
    }
    if (!this.any.is(AccountPermissionUpdateContract.class)) {
      throw new ContractValidateException(
          "contract type error,expected type [AccountPermissionUpdateContract],real type["
              + any.getClass() + "]");
    }
    final AccountPermissionUpdateContract accountPermissionUpdateContract;
    try {
      accountPermissionUpdateContract = any.unpack(AccountPermissionUpdateContract.class);
    } catch (InvalidProtocolBufferException e) {
      logger.debug(e.getMessage(), e);
      throw new ContractValidateException(e.getMessage());
    }
    byte[] ownerAddress = accountPermissionUpdateContract.getOwnerAddress().toByteArray();
    if (!DecodeUtil.addressValid(ownerAddress)) {
      throw new ContractValidateException("invalidate ownerAddress");
    }
    AccountCapsule accountCapsule = accountStore.get(ownerAddress);
    if (accountCapsule == null) {
      throw new ContractValidateException("ownerAddress account does not exist");
    }

    if (!accountPermissionUpdateContract.hasOwner()) {
      throw new ContractValidateException("owner permission is missed");
    }

    if (accountCapsule.getIsWitness()) {
      if (!accountPermissionUpdateContract.hasWitness()) {
        throw new ContractValidateException("witness permission is missed");
      }
    } else {
      if (accountPermissionUpdateContract.hasWitness()) {
        throw new ContractValidateException("account isn't witness can't set witness permission");
      }
    }

    if (accountPermissionUpdateContract.getActivesCount() == 0) {
      throw new ContractValidateException("active permission is missed");
    }
    if (accountPermissionUpdateContract.getActivesCount() > 8) {
      throw new ContractValidateException("active permission is too many");
    }

    Permission owner = accountPermissionUpdateContract.getOwner();
    Permission witness = accountPermissionUpdateContract.getWitness();
    List<Permission> actives = accountPermissionUpdateContract.getActivesList();

    if (owner.getType() != PermissionType.Owner) {
      throw new ContractValidateException("owner permission type is error");
    }
    checkPermission(owner);
    if (accountCapsule.getIsWitness()) {
      if (witness.getType() != PermissionType.Witness) {
        throw new ContractValidateException("witness permission type is error");
      }
      checkPermission(witness);
    }
    for (Permission permission : actives) {
      if (permission.getType() != PermissionType.Active) {
        throw new ContractValidateException("active permission type is error");
      }
      checkPermission(permission);
    }
    return true;
