Audit Report

## Title
Silent payout failure in `claim_bounty` allows bounty funds to be diverted from the beneficiary while state falsely reports settlement - (File: `substrate/frame/bounties/src/lib.rs`)

## Summary
`Pallet::claim_bounty` transfers the curator fee and beneficiary payout via `T::Currency::transfer(..., AllowDeath)` and only guards the result with `debug_assert!(res.is_ok())`, which compiles to a no-op in release/production WASM runtimes. If the beneficiary's `payout` is below `ExistentialDeposit` and the account has never held a balance, the transfer to the beneficiary fails silently, yet the extrinsic still deletes the `Bounties` entry and emits `Event::BountyClaimed` as if funds were delivered. The same pattern exists in `claim_child_bounty`.

## Finding Description
In `claim_bounty` [1](#0-0) , the beneficiary payout transfer result is checked only with `debug_assert!(res.is_ok())` [2](#0-1) . `ensure_signed(origin)?` at the top of the function permits any signed account to trigger the claim [3](#0-2) . `AllowDeath` only waives the existential-deposit requirement for the sender (bounty sub-account); it does not exempt the receiver from needing to meet `ExistentialDeposit` to be created. When `payout = balance.saturating_sub(fee)` is below `ExistentialDeposit` and `beneficiary` is a previously unused account, `T::Currency::transfer` returns `Err`, which `debug_assert!` silently discards in release builds. Execution proceeds unconditionally: `*maybe_bounty = None` deletes the bounty record, `BountyDescriptions::remove` is called, and `Event::BountyClaimed { index, payout, beneficiary }` is emitted reporting a successful payout that never occurred.

Because the `Bounties` entry no longer exists, the permissionless `reclaim_bounty_funds` extrinsic [4](#0-3)  can subsequently sweep the undelivered funds remaining in the bounty sub-account to the treasury account instead of the rightful beneficiary, via `T::TransferAllAssets::force_transfer_all_assets`. The identical unguarded pattern (`debug_assert!(fee_transfer_result.is_ok())` / `debug_assert!(payout_transfer_result.is_ok())`) is present in `claim_child_bounty` in `substrate/frame/child-bounties/src/lib.rs`.

## Impact Explanation
This breaks the invariant that payout state must only advance once settlement succeeds, and diverts value away from the rightful beneficiary — either permanently stuck in the bounty sub-account or swept to the treasury by a follow-up `reclaim_bounty_funds` call — while the chain's emitted event and storage state falsely indicate the beneficiary was paid `payout`. This matches the required impact of "theft or unbacked mint or unlock" / failure to "conserve value and settle exactly once to the rightful beneficiary and amount," since the exact corrupted value is the beneficiary's payout balance combined with the falsely-emitted `BountyClaimed` event and prematurely deleted `Bounties` storage entry.

## Likelihood Explanation
The trigger path requires only routine, non-privileged actions: a curator performing the normal `award_bounty` call with a beneficiary that is a fresh/never-used account, and a payout amount (post-fee) below `ExistentialDeposit` — a realistic outcome for small bounties or high relative fees. Any arbitrary signed account can then invoke the permissionless `claim_bounty`. Since production runtimes are compiled with `debug_assertions` disabled, the `debug_assert!` guard is inert on every live chain using this pallet, making the condition deterministically reachable without any admin/governance misbehavior.

## Recommendation
Replace `debug_assert!(res.is_ok())` in `claim_bounty` (and the analogous checks in `claim_child_bounty`) with proper error propagation (e.g. `res?`), so a failed transfer aborts the extrinsic and rolls back the `Bounties`/`ChildBounties` removal, instead of finalizing a claim whose transfer never completed.

## Proof of Concept
1. Fund a bounty with a `value`/`fee` combination such that `payout = balance - fee` is greater than `0` but strictly less than `ExistentialDeposit`.
2. Curator calls `award_bounty` with `beneficiary` set to an account with zero balance that has never existed in `frame_system::Account`.
3. After `unlock_at`, any signed account calls `claim_bounty(origin, bounty_id)`.
4. In a release-mode runtime, `T::Currency::transfer(&bounty_account, &beneficiary, payout, AllowDeath)` returns `Err(TokenError::BelowMinimum)`; `debug_assert!` is compiled out and the error is discarded.
5. `Bounties` entry is deleted and `Event::BountyClaimed` is emitted, but `Balances::free_balance(beneficiary)` remains `0`.
6. Any account calls `reclaim_bounty_funds(bounty_id)`, sweeping the undelivered `payout` from the bounty sub-account to the treasury account instead of the beneficiary.

		pub fn claim_bounty(
			origin: OriginFor<T>,
			#[pallet::compact] bounty_id: BountyIndex,
		) -> DispatchResult {
			ensure_signed(origin)?; // anyone can trigger claim

			Bounties::<T, I>::try_mutate_exists(bounty_id, |maybe_bounty| -> DispatchResult {
				let bounty = maybe_bounty.take().ok_or(Error::<T, I>::InvalidIndex)?;
				if let BountyStatus::PendingPayout { curator, beneficiary, unlock_at } =
					bounty.status
				{
					ensure!(Self::treasury_block_number() >= unlock_at, Error::<T, I>::Premature);
					let bounty_account = Self::bounty_account_id(bounty_id);
					let balance = T::Currency::free_balance(&bounty_account);
					let fee = bounty.fee.min(balance); // just to be safe
					let payout = balance.saturating_sub(fee);
					let err_amount = T::Currency::unreserve(&curator, bounty.curator_deposit);
					debug_assert!(err_amount.is_zero());

					// Get total child bounties curator fees, and subtract it from the parent
					// curator fee (the fee in present referenced bounty, `self`).
					let children_fee = T::ChildBountyManager::children_curator_fees(bounty_id);
					debug_assert!(children_fee <= fee);

					let final_fee = fee.saturating_sub(children_fee);
					let res =
						T::Currency::transfer(&bounty_account, &curator, final_fee, AllowDeath); // should not fail
					debug_assert!(res.is_ok());
					let res =
						T::Currency::transfer(&bounty_account, &beneficiary, payout, AllowDeath); // should not fail
					debug_assert!(res.is_ok());

					*maybe_bounty = None;

					BountyDescriptions::<T, I>::remove(bounty_id);
					T::ChildBountyManager::bounty_removed(bounty_id);

					Self::deposit_event(Event::<T, I>::BountyClaimed {
						index: bounty_id,
						payout,
						beneficiary,
					});
					Ok(())
				} else {
					Err(Error::<T, I>::UnexpectedStatus.into())
				}
			})?;
			Ok(())
		}

		pub fn reclaim_bounty_funds(
			origin: OriginFor<T>,
			#[pallet::compact] bounty_id: BountyIndex,
		) -> DispatchResultWithPostInfo {
			ensure_signed(origin)?;

			// A live bounty still manages its account, so leave it untouched.
			ensure!(!Bounties::<T, I>::contains_key(bounty_id), Error::<T, I>::BountyStillActive);

			debug_assert!(
				T::ChildBountyManager::child_bounties_count(bounty_id) == 0,
				"child bounties should not exist for a closed bounty"
			);

			let bounty_account = Self::bounty_account_id(bounty_id);
			let treasury_account = Self::account_id();

			let transferred = T::TransferAllAssets::force_transfer_all_assets(
				&bounty_account,
				&treasury_account,
			)?;

			// Free only if something moved, otherwise paid to prevent griefing.
			if !transferred {
				return Ok(Pays::Yes.into());
			}

			Self::deposit_event(Event::<T, I>::BountyFundsReclaimed { bounty_id });

			Ok(Pays::No.into())
		}
