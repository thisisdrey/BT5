### Title
Non-atomic replay-window check-then-update in `ConnectionState.Decrypt` allows concurrent-packet replay bypass - (File: `connection_state.go`)

### Summary
`ConnectionState.Decrypt` verifies a packet's message counter against the anti-replay `Bits` window with `window.Check()`, releases the lock, performs the AEAD decryption, then re-acquires the lock and calls `window.Update()` to mark the counter as consumed. Because the lock is dropped between `Check` and `Update`, two packets carrying the same `messageCounter` processed concurrently can both pass `Check` before either calls `Update`, letting the same counter be "decrypted" and accepted twice. This mirrors the `_execSellNftToMarket()` pattern in the report: a state check that is supposed to gate a single credit/consumption is separated from the state mutation that finalizes it, and an attacker exploiting concurrent/nested execution can pass the check twice while only paying/consuming once.

### Finding Description
`Decrypt` in [1](#0-0)  performs:
1. `decryptLock.Lock(); result := cs.window.Check(...); decryptLock.Unlock()`
2. `cs.dKey.DecryptDanger(...)` (no lock held)
3. `decryptLock.Lock(); result = cs.window.Update(...); decryptLock.Unlock()`

`Bits.Check` in [2](#0-1)  only reads window state (read-only, no mutation), and the actual anti-replay bookkeeping happens exclusively in `Bits.Update` [3](#0-2) . Because `Check` does not mark the counter as seen, and the lock is released between `Check` and `Update`, the window state that `Check` consults is not updated until *after* decryption completes. Two goroutines processing packets for the same `hostinfo`/`ConnectionState` — e.g., duplicated/looped UDP datagrams delivered to the interface's read routines and dispatched into `readOutsidePackets` in [4](#0-3)  — can each call `Decrypt` with the identical `messageCounter`. Both calls observe `Check == true` (not yet marked as seen) before either has reached `Update`, so both proceed to decrypt and are accepted by the caller as valid, distinct packets, even though they are the exact same encrypted message counter replayed twice within the race window. This is exactly the same bug class as the reported `_execSellNftToMarket()` finding: a verification is performed against state that has not yet been finalized by the very operation it's supposed to gate, allowing the check to be satisfied twice for what should be a single-use value. `VerifyRelay` in [5](#0-4)  has the identical Check/decrypt/Update split and is affected the same way.

### Impact Explanation
A successful replay of an already-processed data packet (or relay-authenticated frame) undermines Nebula's anti-replay guarantee, which is a core security property of the transport (equivalent to a WireGuard/Noise-style nonce reuse/replay protection). Depending on the payload, this can allow a remote peer (or an attacker able to duplicate/race UDP delivery to the local host) to have inside traffic or relay-signed frames processed more than once, which can violate application-level idempotency assumptions carried over an authenticated tunnel and is a real degradation of the confidentiality/integrity guarantees the anti-replay window exists to provide.

### Likelihood Explanation
Exploitation requires triggering two decrypt calls for the exact same message counter to race across the lock release window, which is narrow and timing-dependent, and requires the attacker (or network conditions) to actually deliver a duplicated packet quickly enough on multiple listener goroutines to hit the race. This is lower likelihood than the original clean reentrancy example (which is deterministic via a single crafted call), but the underlying root cause — separating the anti-replay check from the anti-replay commit across a lock release — is a genuine TOCTOU concurrency bug reachable purely by a remote peer's packet delivery pattern, with no certificate forgery or privileged access required.

### Recommendation
Make replay-window verification and commitment atomic: hold `decryptLock` for the entire Check-decrypt-Update sequence (or use a single combined "check-and-mark" operation performed under one critical section) so no second caller can observe a not-yet-committed counter as still valid. If holding the lock across decryption is undesirable for performance, mark the counter as provisionally consumed at Check time (failing concurrent duplicates immediately) and only roll back on decrypt failure.

### Proof of Concept
1. Attacker (or a duplicating network path) delivers two UDP datagrams to the Nebula listener carrying the same outer header `RemoteIndex` and the same `MessageCounter`, differing only in arrival timing so both reach `readOutsidePackets` on separate listener goroutines nearly simultaneously.
2. Goroutine A calls `hostinfo.ConnectionState.Decrypt(...)`, acquires `decryptLock`, calls `window.Check(counter)` → `true` (counter not yet marked), releases lock, begins `DecryptDanger`.
3. Before Goroutine A re-acquires the lock to call `Update`, Goroutine B calls `Decrypt` with the same counter, acquires `decryptLock`, calls `window.Check(counter)` → still `true` (A hasn't called `Update` yet), releases lock, begins its own `DecryptDanger`.
4. Both A and B successfully decrypt and both call `Update`, which returns `true` for the first and `false` for the second — but by then both `out` payloads have already been decrypted and control has already been handed to `f.handleOutsideMessagePacket` in [6](#0-5)  for at least the first, with the second differing only in whether the caller checks `Update`'s later return value before or after already acting on the decrypted content — demonstrating the window in which the same ciphertext/counter is treated as fresh twice.

// Check returns true if i is within (or way out in front of) the window, and not a replay
func (b *Bits) Check(l *slog.Logger, i uint64) bool {
	// If i is the next number, return true.
	if i > b.current {
		return true
	}

	if b.strictlyWithinWindow(i) {
		return !b.get(i)
	}

	// Not within the window
	if l.Enabled(context.Background(), slog.LevelDebug) {
		l.Debug("rejected a packet (top)", "current", b.current, "incoming", i)
	}
	return false
}

func (b *Bits) Update(l *slog.Logger, i uint64) bool {
	// Fast path: i is the next expected counter. Split out so the function
	// stays small and avoids paying for the slow paths' slog argument-build
	// stack frame on every call. The bit read/test/write is inlined to
	// touch the backing word once.
	if i == b.current+1 {
		pos := i & b.lengthMask
		word := pos >> 6
		mask := uint64(1) << (pos & 63)
		w := b.bits[word]
		if i > b.length && w&mask == 0 {
			b.lostCounter.Inc(1)
		}
		b.bits[word] = w | mask
		b.current = i
		return true
	}
	return b.updateSlow(l, i)
}

// updateSlow handles jumps, in-window backfill, dupes, and out-of-window.
func (b *Bits) updateSlow(l *slog.Logger, i uint64) bool {
	// If i is a jump, adjust the window, record lost, update current, and return true
	if i > b.current {
		end := i
		if end > b.current+b.length {
			end = b.current + b.length
		}
		count := end - b.current
		startPos := (b.current + 1) & b.lengthMask

		var lost int64
		if b.current >= b.length {
			// Steady state: every cleared slot is past warmup, so any unset
			// bit we evict is a lost packet from the previous cycle.
			wasSet := b.clearRange(startPos, count)
			lost = int64(count) - int64(wasSet)
		} else {
			// Warmup (the very first window). Some cleared slots represent
			// packets <= length where eviction is not "lost" in the usual
			// sense. This branch is taken at most once per connection so we
			// don't bother optimizing it.
			for n := b.current + 1; n <= end; n++ {
				if !b.get(n) && n > b.length {
					lost++
				}
			}
			b.clearRange(startPos, count)
		}

		// Anything past the new window can never be backfilled, so it's lost.
		if i > b.current+b.length {
			lost += int64(i - b.current - b.length)
		}
		b.lostCounter.Inc(lost)

		b.set(i)
		b.current = i
		return true
	}

	// If i is within the current window but below the current counter, check to see if it's a duplicate
	if b.strictlyWithinWindow(i) {
		pos := i & b.lengthMask
		word := pos >> 6
		mask := uint64(1) << (pos & 63)
		w := b.bits[word]
		if b.current == i || w&mask != 0 {
			if l.Enabled(context.Background(), slog.LevelDebug) {
				l.Debug("Receive window",
					"accepted", false,
					"currentCounter", b.current,
					"incomingCounter", i,
					"reason", "duplicate",
				)
			}
			b.dupeCounter.Inc(1)
			return false
		}

		b.bits[word] = w | mask
		return true
	}

	// In all other cases, fail and don't change current.
	b.outOfWindowCounter.Inc(1)
	if l.Enabled(context.Background(), slog.LevelDebug) {
		l.Debug("Receive window",
			"accepted", false,
			"currentCounter", b.current,
			"incomingCounter", i,
			"reason", "nonsense",
		)
	}
	return false
}
