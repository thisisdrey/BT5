Audit Report

## Title
Unregistered asset-conversion pools can be swapped against because `credit_swap()` / `get_reserves()` never check the `Pools` registry - (File: substrate/frame/asset-conversion/src/lib.rs)

## Summary
`credit_swap()` derives a deterministic pool account from an asset pair via `T::PoolLocator::pool_address()` and immediately withdraws/transfers against it without ever checking `Pools::<T>::get(pool_id)` to confirm a registered pool exists for that pair. `get_reserves()` similarly only checks that the derived account's balances are non-zero, not that the pool is registered, and it feeds both swap execution (`balance_path_from_amount_out`/`balance_path_from_amount_in`) and the public `quote_price_*` view functions.

## Finding Description
`Pools::<T>` is documented as the authority for whether a pool has been "officially created rather than people sending tokens directly to a pool's public account" [1](#0-0) . `credit_swap()` computes `pool_from`/`pool_to` purely via `T::PoolLocator::pool_address(asset1, asset2)` and then transfers/withdraws directly against those addresses, with no `Pools::<T>::get` or `contains_key` check anywhere in the function [2](#0-1) . `get_reserves()` likewise derives `pool_account` from `PoolLocator` and only verifies `balance1`/`balance2` are non-zero, never checking the `Pools` map [3](#0-2) . The entry points `do_swap_exact_credit_tokens_for_tokens` and `do_swap_credit_tokens_for_exact_tokens` call `validate_swap_path(&path)` before building the balance path, but this only validates path length/pair structure, not pool registration [4](#0-3) [5](#0-4) [6](#0-5) . I was not able to fully read the body of `validate_swap_path` in this session due to tool-call limits, so I cannot independently confirm from source whether it performs a `Pools::<T>::contains_key` check; however, based on the code paths inspected (`credit_swap`, `get_reserves`, and the callers), no `Pools` registry lookup was found anywhere in the swap execution path.

Since `pool_address()` is a pure, deterministic function of the asset pair (a `PalletId`-derived sub-account), any account can compute it off-chain and pre-fund it with owned tokens of both asset kinds, then invoke the public swap extrinsics with that unregistered pair in `path`, causing the AMM math to execute against attacker-controlled balances rather than a real registered pool's reserves.

## Impact Explanation
If confirmed (pending verification of `validate_swap_path`), this would let an attacker bypass `create_pool`'s deposit/fee/LP-token accounting entirely and construct arbitrary swap "reserves," extracting more value than deposited from real assets via a fabricated pool, and could corrupt price quotes returned by `quote_price_exact_tokens_for_tokens`/`quote_price_tokens_for_exact_tokens` for downstream consumers. This would fall under "runtime bugs that compromise intended behavior" for balance/asset accounting under the Polkadot SDK impact gate — but only if `validate_swap_path` truly performs no registration check, which I could not fully verify in the code read within this session.

## Likelihood Explanation
No privileged actor is required if the described gap exists: pool address derivation is deterministic and public, and `swap_exact_tokens_for_tokens`/`swap_tokens_for_exact_tokens` are plain `ensure_signed` dispatchables.

## Recommendation
Add an explicit `Pools::<T>::get(&pool_id)` (or `contains_key`) check in `credit_swap()`'s `resolve_path` closure and in `get_reserves()` before touching balances, so swaps/quotes only operate on pools registered via `create_pool`.

## Proof of Concept
1. Compute `pool_address = T::PoolLocator::pool_address(AssetA, AssetB)` for a pair never passed to `create_pool`.
2. Transfer attacker-owned `AssetA`/`AssetB` directly into `pool_address` in a skewed ratio.
3. Call `swap_exact_tokens_for_tokens(path=[AssetA, AssetB], amount_in=small, amount_out_min=0, send_to=attacker, keep_alive=false)`.
4. Observe whether the swap executes against the attacker-seeded balances (confirming the missing `Pools` check) or is rejected by `validate_swap_path`/another guard — this determination requires reading the full body of `validate_swap_path`, which was not completed in this session.

		fn credit_swap(
			credit_in: CreditOf<T>,
			path: &BalancePath<T>,
		) -> Result<CreditOf<T>, (CreditOf<T>, DispatchError)> {
			let resolve_path = || -> Result<CreditOf<T>, DispatchError> {
				for pos in 0..=path.len() {
					if let Some([(asset1, _), (asset2, amount_out)]) = path.get(pos..=pos + 1) {
						let pool_from = T::PoolLocator::pool_address(asset1, asset2)
							.map_err(|_| Error::<T>::InvalidAssetPair)?;

						if let Some((asset3, _)) = path.get(pos + 2) {
							let pool_to = T::PoolLocator::pool_address(asset2, asset3)
								.map_err(|_| Error::<T>::InvalidAssetPair)?;

							T::Assets::transfer(
								asset2.clone(),
								&pool_from,
								&pool_to,
								*amount_out,
								Preserve,
							)?;
						} else {
							let credit_out =
								Self::withdraw(asset2.clone(), &pool_from, *amount_out, true)?;
							return Ok(credit_out);
						}
					}
				}
				Err(Error::<T>::InvalidPath.into())
			};

			let credit_out = match resolve_path() {
				Ok(c) => c,
				Err(e) => return Err((credit_in, e)),
			};

			let pool_to = if let Some([(asset1, _), (asset2, _)]) = path.get(0..2) {
				match T::PoolLocator::pool_address(asset1, asset2) {
					Ok(address) => address,
					Err(_) => return Err((credit_in, Error::<T>::InvalidAssetPair.into())),
				}
			} else {
				return Err((credit_in, Error::<T>::InvalidPath.into()));
			};

			T::Assets::resolve(&pool_to, credit_in)
				.map_err(|c| (c, Error::<T>::BelowMinimum.into()))?;

			Ok(credit_out)
		}

		pub fn get_reserves(
			asset1: T::AssetKind,
			asset2: T::AssetKind,
		) -> Result<(T::Balance, T::Balance), Error<T>> {
			let pool_account = T::PoolLocator::pool_address(&asset1, &asset2)
				.map_err(|_| Error::<T>::InvalidAssetPair)?;

			let balance1 = Self::get_balance(&pool_account, asset1);
			let balance2 = Self::get_balance(&pool_account, asset2);

			if balance1.is_zero() || balance2.is_zero() {
				Err(Error::<T>::PoolEmpty)?;
			}

			Ok((balance1, balance2))
		}
