Unbounded group-count parsing in unauthenticated handshake certificate enables pre-authentication CPU DoS - (File: cert/cert_v2.go)

### Summary
An attacker with no CA-signed certificate can still trigger full parsing of an arbitrary "certificate" they craft into an initial handshake packet, because ASN.1 parsing of `Details` (name, networks, unsafe networks, and groups) happens in `unmarshalCertificateV2`/`unmarshalDetails` before any signature verification occurs. While individual name and network entries are length-capped (`MaxNameLength`, `MaxNetworkLength`), the *number* of `groups` entries in a certificate is unbounded except by the overall `MaxCertificateSize` (65536 bytes). This mirrors the M-13 pattern of an attacker inflating an unbounded, attacker-controlled list (creators) that is fully iterated before any authorization gate — except here the analogous gate is "CA signature verification," which runs strictly after all list elements have already been parsed and heap-allocated.

### Finding Description
`cert/cert_v2.go`'s `unmarshalDetails` reads the `TagDetailsGroups` ASN.1 sequence and loops: [1](#0-0) 
each iteration allocating a `string` and appending it to `groups`, with no cap on iteration count — only a bound on each individual entry via `val.Empty()` (no upper length check on group name, unlike name/network fields). The overall input is bounded only by `MaxCertificateSize = 65536`: [2](#0-1) [3](#0-2) 

This certificate is embedded in the handshake payload's `Cert` field, itself unmarshaled from an attacker-supplied packet with no size ceiling of its own: [4](#0-3) 

Critically, `handshake.Machine.validateCert` calls `cert.Recombine` (which drives `unmarshalCertificateV2`/`unmarshalDetails`) **before** calling the CA verifier: [5](#0-4) 

This is reached from `beginHandshake`, which is invoked for every unauthenticated, unindexed stage-1 handshake packet arriving from any source IP that passes only the coarse `AllowUnknownVpnAddr` allow-list check (no cryptographic gate yet): [6](#0-5) [7](#0-6) 

So the parsing/allocation cost of an arbitrarily large `groups` list is paid for every forged handshake attempt, entirely independent of whether the certificate's signature will ultimately verify — directly analogous to `_settleAuction` looping over attacker-specified creators before any economic/authorization check limits the loop size.

### Impact Explanation
An attacker with no valid CA-issued certificate (i.e., no trust relationship with the target mesh) can send UDP packets shaped as handshake stage-1 messages containing a crafted (self-signed or garbage-signed) certificate whose `groups` field is packed with the maximum number of minimal-length entries that fit under the 65536-byte certificate ceiling. Each such packet forces the responder to fully parse and heap-allocate the entire groups slice before the signature check (which will fail) is ever performed. Repeated at volume from spoofed or distributed source addresses, this converts a cheap-to-forge packet into asymmetric CPU/allocation cost on the responder, exhausting handshake-processing capacity and denying legitimate peers the ability to establish tunnels — a remote CPU-exhaustion / availability impact reachable without holding any credential.

### Likelihood Explanation
Reaching this code path requires no CA-signed certificate, no established tunnel, and no prior trust — only knowledge of the UDP listener's address and the wire format for a stage-1 `HandshakeIXPSK0` packet (both of which are public/documented). The only gate before this parsing is the coarse `remote_allow_list` IP allow-list, which does not defend against a permitted-but-malicious sender, and the noise `ReadMessage` step, which does not require a valid certificate to decode the outer payload structure that carries the raw cert bytes. This makes the finding straightforwardly reachable by exactly the threat actor the prompt requires: someone lacking a CA-signed certificate.

### Recommendation
Add an explicit upper bound on the number of `groups` (and, defensively, `networks`/`unsafeNetworks`) entries accepted during `unmarshalDetails`, enforced as soon as the count is known (e.g., abort the loop once a `MaxGroups` threshold is exceeded) rather than relying solely on the aggregate `MaxCertificateSize`. Additionally, consider performing a cheap structural/size sanity check on the handshake certificate bytes before allocating per-element Go slices, so that unauthenticated peers cannot force expensive allocation work ahead of signature verification.

### Proof of Concept
1. Construct a `certificateV2` ASN.1 blob whose `TagDetailsGroups` sequence contains as many minimal (e.g., 1-byte) `UTF8String` group entries as fit within `MaxCertificateSize` (65536 bytes total certificate size), using an arbitrary/self-generated key pair (no real CA signature needed since it will ultimately fail verification).
2. Embed this blob as the `Cert` field of a handshake `Payload`, marshal it per `handshake/payload.go`, and wrap it as noise ciphertext for a stage-1 `HandshakeIXPSK0` message with `MessageCounter=1`, `RemoteIndex=0`.
3. Send this UDP packet to a Nebula node's listen port from an address that passes `remote_allow_list.AllowUnknownVpnAddr`.
4. Observe that `beginHandshake` → `machine.ProcessPacket` → `validateCert` → `cert.Recombine` → `unmarshalCertificateV2`/`unmarshalDetails` fully parses and allocates the entire (maximal) groups slice before the subsequent CA verification step rejects the certificate — repeat at high packet rate to measure responder CPU/allocation cost per forged packet versus a minimal-groups baseline.

func (m *Machine) validateCert(payload Payload) error {
	cred := m.getCred(m.myVersion)
	if cred == nil {
		m.failed = true
		return fmt.Errorf("%w: %v", ErrNoCredential, m.myVersion)
	}
	rc, err := cert.Recombine(
		cert.Version(payload.CertVersion),
		payload.Cert,
		m.hs.PeerStatic(),
		cred.Cert.Curve(),
	)
	if err != nil {
		m.failed = true
		return fmt.Errorf("recombine cert: %w", err)
	}

	if !bytes.Equal(rc.PublicKey(), m.hs.PeerStatic()) {
		m.failed = true
		return ErrPublicKeyMismatch
	}

	// Version negotiation, if the peer sent a different version and we have it, switch
	if rc.Version() != m.myVersion {
		if m.getCred(rc.Version()) != nil {
			m.myVersion = rc.Version()
		}
	}

	verified, err := m.verifier(rc)
	if err != nil {
		m.failed = true
		return fmt.Errorf("verify cert: %w", err)
	}

	if !via.IsRelayed {

			return
		}
	}

			return
		}

func (hm *HandshakeManager) beginHandshake(via ViaSender, packet []byte, h *header.H) {
	f := hm.f
	cs := f.pki.getCertState()

	v := cs.DefaultVersion()
	if cs.GetCredential(v) == nil {
		f.l.Error("Unable to handshake with host because no certificate is available",
			"from", via, "certVersion", v)
		return
	}

	machine, err := handshake.NewMachine(
		v, cs.GetCredential,
		hm.certVerifier(), func() (uint32, error) { return generateIndex(f.l) },
		false, header.HandshakeIXPSK0,
	)
	if err != nil {
		f.l.Error("Failed to create handshake machine", "from", via, "error", err)
		return
	}

	response, result, err := machine.ProcessPacket(nil, packet)
	if err != nil {
		f.l.Error("Failed to process handshake packet", "from", via, "error", err)
		return
	}
