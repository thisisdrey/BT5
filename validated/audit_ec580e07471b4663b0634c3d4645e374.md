## Title
Cross-contract StackerDB chunk replay: signed chunk metadata is not bound to the target StackerDB contract - (File: `libstackerdb/src/libstackerdb.rs`, `stackslib/src/net/stackerdb/db.rs`)

### Summary
`SlotMetadata::verify`/`sign` authenticate a chunk over `(slot_id, slot_version, data_hash)` only — the target smart-contract identifier is never part of the signed digest. Because the Nakamoto `.signers-{set}-{msgid}` StackerDB contracts assign the *same* `slot_id` to a given signer address across every message-type contract for a reward cycle, a validly-signed chunk originally authored for one message-type contract can be replayed byte-for-byte into a *different* StackerDB contract that the same signer also owns the same `slot_id` in, and it passes all server-side validation.

### Finding Description
`SlotMetadata::auth_digest` hashes only `slot_id`, `slot_version`, and `data_hash`: [1](#0-0) 

`sign`/`verify` operate purely on this digest, with no contract/context binding: [2](#0-1) 

Server-side acceptance, `StackerDBs::try_replace_chunk`, only checks chunk size, the signer configured **for that slot_id in that contract**, staleness, and write-count — it never checks that the signature was produced *for this contract*: [3](#0-2) 

The HTTP write path (`POST /v2/stackerdb/{principal}/{contract_name}/chunks`) performs no additional context check (e.g. no `rc_consensus_hash` binding) before calling `try_replace_chunk`: [4](#0-3) 

Crucially, the same signer→slot_id assignment is reused across all per-message-type StackerDB contracts for a signer set/reward cycle. The boot contract computes one sorted `signer-slots` list per reward cycle and every `.signers-{set}-{msgid}` contract reads that same page via `stackerdb-get-signer-slots-page`: [5](#0-4) 

This is explicitly exercised/confirmed by the test that asserts the **same** expected slot list holds for every `message_id` under a given `signer_set`: [6](#0-5) 

Because StackerDB reads are unauthenticated/public (any peer can `GET` a chunk, or observe it via unsolicited P2P push), an unprivileged attacker can capture a validly-signed `(slot_id, slot_version, data, sig)` tuple that signer `S` posted to contract `.signers-0-A` for message type A, and then `POST` that exact same tuple to a different contract `.signers-0-B` (message type B) in which `S` also owns the same `slot_id`. `slot_desc.verify(&slot_validation.signer)` succeeds because the digest/signature never encoded which contract it was meant for, and version/size checks are contract-local and easily satisfiable (e.g., replaying into a slot that is fresh or behind).

This breaks the intended equality "chunk data stored under signer S's slot in contract C was authored by S *for contract C*" — the server instead treats "signed by S for *some* slot_id" as sufficient, silently accepting cross-contract replayed data as canonical for a context the signer never intended.

### Impact Explanation
Consumers of a specific StackerDB contract's chunks assume the stored bytes for a slot were authored for that specific message type/contract (e.g. `StackerDBListener::load_chunks` deserializes chunk bytes for the `StateMachineUpdate` contract as `SignerMessageV0::StateMachineUpdate`, and other message-type contracts feed block-signing/vote logic). Injecting a replayed-but-validly-signed payload from a different message-type contract into a slot can:
- Desynchronize a signer's advertised state (stale/foreign data appearing as their current message for an unrelated message type), degrading consensus/coordination logic that trusts per-slot authenticity (`stacks-node/src/nakamoto_node/stackerdb_listener.rs`).
- Force downstream consumers to repeatedly reject/re-parse foreign-shaped bytes, a bounded compute cost on read paths.
This matches the "High: serving non-canonical state as canonical" category — data attributed to a signer in a context they never signed for is served/stored as if legitimate.

### Likelihood Explanation
Exploitation requires only: (1) observing one legitimately-signed chunk for signer `S` (trivial, since StackerDB reads are public/unauthenticated), and (2) knowing that `S` owns the identical `slot_id` in another `.signers-{set}-*` contract for the same reward cycle (guaranteed by the shared, sorted slot-assignment scheme). No private key, no node secret, and no elevated role is needed — purely remote and unprivileged, satisfying the scope's "unauthorized write to state" impact class via a replay rather than a forgery.

### Recommendation
Include the target `smart_contract`/`QualifiedContractIdentifier` (and ideally the reward-cycle/consensus context) inside `SlotMetadata::auth_digest`, so a signature is only valid for the specific StackerDB instance it was produced for. This requires a wire/protocol version bump since it changes what bytes are signed by `SlotMetadata::sign` and verified by `SlotMetadata::verify`.

### Proof of Concept
1. Attacker connects to a public node and fetches the current chunk for slot `k` of `.signers-0-A` owned by signer `S`, i.e. `(slot_id=k, slot_version=v, data=D, sig=SIG)`, via the public StackerDB chunk-read RPC.
2. Attacker determines (via the public `stackerdb-get-signer-slots-page`/`get_stackerdb_signer_slots` client calls) that `S` also owns slot `k` in `.signers-0-B` for the same reward cycle — guaranteed by the shared boot-contract slot-assignment logic.
3. Attacker issues `POST /v2/{signer-principal}/signers-0-B/chunks` with `slot_id=k, slot_version=v' (> current version in B), sig=SIG, data=D`.
4. `RPCPostStackerDBChunkRequestHandler::try_handle_request` → `try_replace_chunk` verifies `SIG` against `S`'s address for slot `k` (succeeds, since the digest is contract-agnostic), passes size/version/write-count checks, and stores `D` into `.signers-0-B`'s slot `k`, marked as accepted: [7](#0-6) 
5. Any consumer of `.signers-0-B` slot `k` now retrieves foreign, replayed data attributed to signer `S`, without `S` ever having authored/signed a chunk for that contract.

    fn auth_digest(&self) -> Sha512Trunc256Sum {
        let mut hasher = Sha512_256::new();
        hasher.update(self.slot_id.to_be_bytes());
        hasher.update(self.slot_version.to_be_bytes());
        hasher.update(self.data_hash.0);
        Sha512Trunc256Sum::from_hasher(hasher)
    }

    pub fn sign(&mut self, privkey: &StacksPrivateKey) -> Result<(), Error> {
        let auth_digest = self.auth_digest();
        let sig = privkey
            .sign(&auth_digest.0)
            .map_err(|se| Error::SigningError(se.to_string()))?;

        self.signature = sig;
        Ok(())
    }

    /// Verify that a given principal signed this chunk metadata.
    /// Note that the address version is ignored.
    pub fn verify(&self, principal: &StacksAddress) -> Result<bool, Error> {
        let sigh = self.auth_digest();
        let pubk = StacksPublicKey::recover_to_pubkey_without_validating_low_s(
            sigh.as_bytes(),
            &self.signature,
        )
        .map_err(|ve| Error::VerifyingError(ve.to_string()))?;

        let pubkh = Hash160::from_node_public_key(&pubk);
        Ok(pubkh == *principal.bytes())
    }

    pub fn try_replace_chunk(
        &self,
        smart_contract: &QualifiedContractIdentifier,
        slot_desc: &SlotMetadata,
        chunk: &[u8],
    ) -> Result<(), net_error> {
        // Check per-replica chunk-size cap.
        if (chunk.len() as u64) > self.config.chunk_size {
            return Err(net_error::StackerDBChunkTooBig(chunk.len()));
        }

        let slot_validation = self
            .get_slot_validation(smart_contract, slot_desc.slot_id)?
            .ok_or(net_error::NoSuchSlot(
                smart_contract.clone(),
                slot_desc.slot_id,
            ))?;

        if !slot_desc.verify(&slot_validation.signer)? {
            return Err(net_error::BadSlotSigner(
                slot_validation.signer,
                slot_desc.slot_id,
            ));
        }
        if slot_desc.slot_version <= slot_validation.version {
            return Err(net_error::StaleChunk {
                supplied_version: slot_desc.slot_version,
                latest_version: slot_validation.version,
            });
        }
        if slot_desc.slot_version > self.config.max_writes {
            return Err(net_error::TooManySlotWrites {
                supplied_version: slot_desc.slot_version,
                latest_version: slot_validation.version,
                max_writes: self.config.max_writes,
            });
        }
        self.insert_chunk(smart_contract, slot_desc, chunk)
    }
