### Title
Premature wipe of the `old` nonce bitmap lets an already-executed signed `Request` be replayed - (File: `contracts/wallet/src/nonces.rs`)

### Summary
`Nonces::check_cleanup` rotates `current` into `old` and, in the *same* invocation, can also wipe `old` entirely when it detects `2*timeout` has elapsed since the last rotation. Because both thresholds are evaluated against the shared `last_cleaned_at` timestamp in one lazy, on-demand call (rather than as two temporally distinct events), a nonce that was committed less than `2*timeout` before the check can be erased in a single step, letting a previously-consumed `Nonce`/signed `RequestMessage` be resubmitted and executed a second time.

### Finding Description
The documented binding (`contracts/wallet/README.md:91-94`) is:
`is_used(nonce) == true` for every `t` with `t - commit_time < 2*timeout`.

`check_cleanup` implements this with a single shared `last_cleaned_at` marker: [1](#0-0) 

```
if self.last_cleaned_at < last_valid_nonce_at {
    self.old = std::mem::take(&mut self.current);      // rotate current -> old
    if self.last_cleaned_at < last_valid_nonce_at - self.timeout {
        self.old = BitMap::new(BTreeMap::new());        // wipe old
    }
    self.last_cleaned_at = now;
}
```

`check_cleanup` is only invoked lazily, from `commit` (during `w_execute_signed`) and from `execute_extension`: [2](#0-1) [3](#0-2) 

If the wallet receives no traffic for longer than `2*timeout` since `last_cleaned_at`, the *next* call that finally triggers `check_cleanup` sees both conditions true simultaneously: `current` is rotated into `old`, and that very same `old` (which now contains the just-rotated `current`, i.e. nonces committed as recently as `now - timeout`) is wiped in the same statement, instead of surviving one more full `timeout` as the two-stage design intends. Concretely, a nonce `X` committed at `T0 = last_cleaned_at + timeout - ε` (just before the natural rotation point) can be erased at `now = last_cleaned_at + 2*timeout + δ` (with tiny `δ`), i.e. only `now - T0 ≈ timeout + ε + δ` after commit — well under the guaranteed `2*timeout` — because the wipe branch does not distinguish "old that already survived one full window" from "old that was rotated in this very call."

Exploit flow: an attacker (any unprivileged relayer/observer) captures a previously broadcast, valid `(RequestMessage, proof)` pair for a victim's wallet (these are plaintext call arguments visible on-chain once submitted). They wait for/observe a period of wallet inactivity spanning the `2*timeout` boundary (or trigger it indirectly if the victim itself makes another unrelated call that lands exactly on this boundary), then resubmit the exact same `msg`/`proof` via `w_execute_signed`. Since `is_used`/`commit` now reports the nonce as free (the bitmap was cleared prematurely), `commit` succeeds, signature verification passes (same valid proof), and `execute_request` runs a second time — e.g. re-triggering `Transfer`/`FunctionCall` promises against the wallet's Verifier balances that were already meant to be single-use.

No existing guard catches this: `commit` only consults `self.old.get_bit(nonce) || self.current.set_bit(nonce)` [4](#0-3) , both of which have already been vacated by the faulty `check_cleanup` call before `commit`'s own bit-check runs.

### Impact Explanation
A wallet contract re-executes a `Request` its owner authorized only once, causing double-spend of the wallet's assets/promises (e.g. duplicate `Transfer`/`FunctionCall` actions, or a duplicate withdrawal-style intent settled against Verifier-held balances) — matching the High-severity category "a wallet contract executing a Request its owner did not authorise for this chain and account" (a second, unintended execution). The blast radius is per-wallet: any individual wallet contract with irregular/low activity around a `2*timeout` gap is susceptible, and any historically observed signed request for that wallet becomes replayable at that moment.

### Likelihood Explanation
This requires: (1) an idle period exceeding `2*timeout` between calls that invoke `check_cleanup` on the target wallet — plausible for low-traffic wallets with the recommended `1 hour` timeout, or engineerable if the attacker itself can cheaply trigger a harmless call to land the rotation boundary; (2) possession of a previously valid, already-broadcast `(msg, proof)` pair, which is public once submitted on-chain. No privileged role, key compromise, or victim cooperation is needed beyond normal public transaction visibility, making this feasible for any unprivileged relayer/observer to attempt opportunistically and repeatable across wallets/timeouts.

### Recommendation
Track two independent timestamps (`current_started_at` and `old_started_at`, or equivalent generation counters) so that a "rotate" event and a "wipe" event are only ever applied to bitmaps that have actually persisted a full `timeout` in that state, never to a bitmap combined/created within the same `check_cleanup` invocation. Alternatively, perform the wipe check using the timestamp of the *previous* rotation (before `self.old` is overwritten this call) rather than reusing `last_cleaned_at`/`last_valid_nonce_at` derived from `now`.

### Proof of Concept
```rust
// contracts/wallet/src/nonces.rs (illustrative; requires exposing/mocking `Timestamp::now()`
// via the crate's existing time-mocking utilities used elsewhere in the workspace)
#[test]
fn premature_wipe_allows_replay() {
    let timeout = Duration::from_secs(3600); // 1 hour
    let mut nonces = Nonces::new(timeout);

    let t0 = Timestamp::now(); // last_cleaned_at == UNIX_EPOCH initially; first commit rotates baseline
    // commit a nonce near the end of a "current" window
    let created_at = t0; // treat as baseline after an implicit first rotation
    nonces.commit(1, created_at, timeout).unwrap();

    // fast-forward just under 2*timeout since last_cleaned_at, with NO intermediate check_cleanup calls
    mock_time::advance(timeout + timeout - Duration::from_secs(1)); // ~ 2*timeout - ε since last rotation baseline

    // single check_cleanup call straddles both thresholds at once
    nonces.check_cleanup();

    // BINDING: is_used(1) must remain true because elapsed-since-commit < 2*timeout
    assert!(nonces.is_used_for_test(1) == true, "nonce wiped before 2*timeout retention guarantee");

    // demonstrate replay: commit should fail (AlreadyUsed) if guarantee holds;
    // bug manifests as commit succeeding here instead
    let result = nonces.commit(1, created_at, timeout);
    assert!(matches!(result, Err(NonceError::AlreadyUsed)));
}
```
Assertions to add on both sides of the equality: before the bug fix, `is_used(nonce)` flips to `false` and a second `commit(nonce, ...)` succeeds at `elapsed ≈ timeout` (< `2*timeout`); after a correct fix, `is_used(nonce)` must stay `true` and `commit` must return `NonceError::AlreadyUsed` until `elapsed >= 2*timeout`.

        }

        if self.old.get_bit(nonce) || self.current.set_bit(nonce) {
            return Err(NonceError::AlreadyUsed);
        }

        Ok(())
    }

    #[cfg(feature = "std")]
    pub fn check_cleanup(&mut self) {
        let now = Timestamp::now();
        let last_valid_nonce_at = now - self.timeout;

        // check if it's time to rotate
        if self.last_cleaned_at < last_valid_nonce_at {
            // rotate current -> old
            self.old = std::mem::take(&mut self.current);
            // check if `2 * timeout` has passed since last rotation
            if self.last_cleaned_at < last_valid_nonce_at - self.timeout {
                // cleanup old nonces
                self.old = BitMap::new(BTreeMap::new());
            }
            // update last rotation time
            self.last_cleaned_at = now;
        }
    }
