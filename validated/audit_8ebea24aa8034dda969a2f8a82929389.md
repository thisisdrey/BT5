### Title
`Pool.swap()` lacks any slippage protection, allowing oracle-price sandwich attacks on swappers - (File: contracts/Pool.sol)

### Summary
`Pool.swap()` burns the caller's `syntheticTokenIn_` and mints `syntheticTokenOut_` at whatever `MasterOracle` reports at execution time. Unlike the buggy `GSPFunding.sellShares()` (where `baseMinAmount`/`quoteMinAmount` exist but can be set to 0), Metronome's swap exposes **no `amountOutMin` / deadline parameter at all** — the function signature is `swap(ISyntheticToken, ISyntheticToken, uint256 amountIn_)`. The user has no on-chain way to bound the executed price, so any adverse oracle price movement between mempool observation and inclusion is silently accepted. [1](#0-0) [2](#0-1) 

### Finding Description
The swap path is:

1. `swap()` burns `amountIn_` of the input synth immediately (line 660).
2. `quoteSwapOut()` then calls `masterOracle().quote(tokenIn, tokenOut, amountIn)` and deducts `feeProvider.swapFees(...)` to compute `_amountOut` (lines 508–525, 662).
3. `_amountOut` of the output synth is minted to the caller (line 668).

The burn happens *before* the quote, so the user is irrevocably committed at the execution-time oracle price with zero recourse. There is no `minAmountOut`, no deadline, and no comparison against a caller-supplied expected rate anywhere in `Pool.sol` (a grep for `amountOutMin|minAmount|slippage|deadline` over production contracts returns hits only in `SmartFarmingManager.sol`, which delegates to an external `ISwapper.swapExactInput(..., amountOutMin_, ...)` — the pool-level oracle swap itself is unprotected).

Attack sketch (unprivileged EOA):
- Victim submits `swap(msUSD, msETH, amountIn)` in the public mempool.
- `MasterOracle.quote` ultimately resolves to an externally sourced price (push oracle update, or a DEX-derived feed). An attacker who can move that quoted price in the same block — either by front-running a pending oracle update transaction, or by manipulating an oracle-readable spot/TWAP source (same-transaction manipulation, which is allowed) — sandwiches the victim: buy `msETH` exposure (or push the msUSD/msETH rate) before the victim's tx, let the victim's swap execute at the degraded rate, then unwind after.
- Because swap is symmetric burn/mint at the oracle rate, the value the victim loses accrues to holders of the output-side exposure — i.e., the attacker who positioned ahead of the price move.

The guards present (`whenNotShutdown`, `nonReentrant`, `onlyIfSyntheticTokenExists`, `isSwapActive`, balance check) do nothing to constrain execution price.

### Impact Explanation
Direct loss of user funds: the victim receives materially less `syntheticTokenOut_` than the fair rate at submission time, with the difference capturable by the sandwiching attacker. Every `swap()` caller on every deployed pool (Base, Hemi, Mainnet, Optimism, Swell, Plasma ABIs all expose the same 3-arg `swap`) is affected whenever the oracle price is adverse at inclusion.

### Likelihood Explanation
High whenever the underlying oracle feed can be moved or front-run within a block by an unprivileged actor (spot-price or thin-liquidity feeds, or mempool-visible oracle updates). Requires no privileged role; the attacker only needs capital to shift the price source and to take the opposite side. Mitigating factor: if `MasterOracle` is backed purely by robust push oracles (e.g., Chainlink), the attack reduces to classic oracle-update front-running, which still applies around volatile updates.

### Recommendation
Add a `minAmountOut_` (and ideally a `deadline_`) parameter to `swap`, revert if `quoteSwapOut` result is below it, and compute the quote before burning so a failed slippage check aborts cleanly:

```solidity
function swap(
    ISyntheticToken syntheticTokenIn_,
    ISyntheticToken syntheticTokenOut_,
    uint256 amountIn_,
    uint256 minAmountOut_
) ... {
    ...
    (_amountOut, _fee) = quoteSwapOut(...);
    if (_amountOut < minAmountOut_) revert SlippageExceeded();
    syntheticTokenIn_.burn(_msgSender, amountIn_);
    ...
}
```

Update `IPool.swap` accordingly. Routers/`Operator.execute` callers should thread the parameter through.

### Proof of Concept
```ts
// Hardhat fork sketch — Pool.sol::swap has no minAmountOut
// Setup: alice holds msUSD; masterOracle initially quotes 1 msUSD : X msETH

const quotedBefore = await pool.quoteSwapOut(msUSD.address, msETH.address, amountIn);

// 1) Attacker observes alice's pending swap in mempool and
//    moves the oracle-readable price (e.g. front-runs a price update
//    or manipulates the DEX feed MasterOracle reads from),
//    pushing msUSD/msETH down 5%.
await attackerManipulateOracle(downBy(parseEther('0.05')));

// 2) Victim tx executes at the degraded rate — no revert possible
const tx = await pool.connect(alice).swap(msUSD.address, msETH.address, amountIn);
const quotedAfter = await pool.quoteSwapOut(msUSD.address, msETH.address, amountIn);
expect(quotedAfter._amountOut).to.be.lt(quotedBefore._amountOut); // alice loses ~5%, no protection

// 3) Attacker unwinds their position for profit; alice's loss is realized.
// With a minAmountOut param, step 2 would have reverted.
```

Contrast with `SmartFarmingManager.sol` flows, which correctly pass `amountOutMin_` into `ISwapper.swapExactInput` — the same protection is simply missing at the pool swap boundary.

    function swap(
        ISyntheticToken syntheticTokenIn_,
        ISyntheticToken syntheticTokenOut_,
        uint256 amountIn_
    )
        external
        override
        whenNotShutdown
        nonReentrant
        onlyIfSyntheticTokenExists(syntheticTokenIn_)
        onlyIfSyntheticTokenExists(syntheticTokenOut_)
        returns (uint256 _amountOut, uint256 _fee)
    {
        address _msgSender = _msgSender();

        if (!isSwapActive) revert SwapFeatureIsInactive();
        if (amountIn_ == 0 || amountIn_ > syntheticTokenIn_.balanceOf(_msgSender)) revert AmountInIsInvalid();

        syntheticTokenIn_.burn(_msgSender, amountIn_);

        (_amountOut, _fee) = quoteSwapOut(syntheticTokenIn_, syntheticTokenOut_, amountIn_);

        if (_fee > 0) {
            syntheticTokenOut_.mint(_poolRegistry.feeCollector(), _fee);
        }

        syntheticTokenOut_.mint(_msgSender, _amountOut);

        emit SyntheticTokenSwapped(_msgSender, syntheticTokenIn_, syntheticTokenOut_, amountIn_, _amountOut, _fee);
    }
