Audit Report

## Title
`ProxyType::NonTransfer` proxy filter omits `pallet_revive::Call::call`, letting a non-transfer delegate move the delegator's native balance - (File: `cumulus/parachains/runtimes/assets/asset-hub-westend/src/lib.rs`)

## Summary
`ProxyType::NonTransfer` is implemented as a denylist of `RuntimeCall` variants (`Balances`, `Assets`, `Nfts`, `Uniques`, `NftFractionalization`, `Scheduler`, `Treasury`, `Vesting::vested_transfer`, `ConvictionVoting`, `Referenda`, `Whitelist`), and `RuntimeCall::Revive` is absent from this list despite `pallet_revive` being included in the asset-hub-westend runtime. `pallet_revive::Pallet::call` explicitly accepts a `value` parameter transferred from `origin` to `dest`, functionally equivalent to a balance transfer, so a delegate holding a `NonTransfer` proxy can move the delegator's native funds through this unlisted path.

## Finding Description
`InstanceFilter::filter` is the sole gate `pallet_proxy::Pallet::proxy` uses to authorize delegate-initiated dispatch under the delegator's origin. For `ProxyType::NonTransfer`, the filter negates a fixed enumeration of variants rather than allowlisting safe calls, so any variant not named — including `RuntimeCall::Revive(pallet_revive::Call::call { dest, value, .. })` — passes the filter and is dispatched with the real account's origin. `pallet_revive::Pallet::call` transfers `value` from `origin` to `dest` regardless of whether `dest` is a contract or plain account, making it a direct value-transfer primitive equivalent in effect to `Balances::transfer`, yet it is not covered by the denylist.

## Impact Explanation
Any account that grants a `NonTransfer` proxy to a delegate under the expectation that funds cannot be moved is exposed to full balance drain via `Revive::call(dest, value, ...)`, satisfying "theft ... of user funds" and "unauthorized execution or origin escalation" under the impact gate, since the proxy origin restriction — an explicit security control — is bypassed.

## Likelihood Explanation
No privileged or governance action is needed; any legitimately delegated `NonTransfer` proxy becomes exploitable the moment the delegate is malicious or compromised — the exact threat scenario `NonTransfer` is designed to prevent. The attack path is a single `pallet_proxy::proxy` extrinsic wrapping `pallet_revive::call`.

## Recommendation
Add `RuntimeCall::Revive(..)` (or specifically `pallet_revive::Call::call`, `instantiate`, and `instantiate_with_code`, which carry a `value`) to the `ProxyType::NonTransfer` denylist match arm in `cumulus/parachains/runtimes/assets/asset-hub-westend/src/lib.rs`, consistent with how `Balances`/`Assets`/etc. are excluded. Longer term, converting `NonTransfer` to an explicit allowlist would prevent future pallets from silently bypassing the restriction.

## Proof of Concept
1. Account `A` executes `Proxy::add_proxy(D, ProxyType::NonTransfer, delay)`.
2. `D` calls `Proxy::proxy(A, Some(ProxyType::NonTransfer), Box::new(RuntimeCall::Revive(pallet_revive::Call::call { dest: attacker_address, value: A_full_balance, weight_limit: Weight::MAX, storage_deposit_limit: 0, data: vec![] })))`.
3. `ProxyType::NonTransfer::filter` returns `true` because `RuntimeCall::Revive` is not matched in the denylist at lines 834-849.
4. `pallet_revive::Pallet::call` executes with `origin = A`, transferring `value` to `attacker_address`.
5. `A`'s transferable balance is drained despite the `NonTransfer` restriction.
