## Analysis

The throttle capacity for unstaked traffic is a **fixed constant applied per‑connection**, not a cluster‑wide budget shared across all unstaked connections. This lets an unstaked attacker scale total ingress work linearly with the number of connections they can open, up to `max_unstaked_connections`.

### Title
Per-connection (not aggregate) unstaked stream throttling quota lets attacker scale pre-fee sigverify CPU cost linearly with unstaked connection count - ([File: streamer/src/nonblocking/stream_throttle.rs])

### Summary
`StakedStreamLoadEMA::available_load_capacity_in_throttling_duration` grants every unstaked QUIC connection an independent, fixed `MAX_UNSTAKED_TPS` (200 streams/sec) budget rather than sharing a single cluster-wide unstaked budget, and unstaked load is never accounted into any shared/global counter (`increment_load` only tracks staked). An unstaked attacker who opens the maximum allowed unstaked connections (`max_unstaked_connections`, default 2000) and streams garbage payloads at just under 200 streams/sec on each connection can push far more work into `fetch_stage`/`sigverify_stage` than the system's own design budget (`EXPECTED_UNSTAKED_STREAMS_RATIO` = 20% of total capacity) intends, without ever producing a valid, fee-paying transaction.

### Finding Description
`SwQos::on_new_stream` (`streamer/src/nonblocking/swqos.rs:497-516`) calls `throttle_stream` using a per-connection `max_streams_per_throttling_interval` obtained from `max_streams_per_throttling_interval` → `StakedStreamLoadEMA::available_load_capacity_in_throttling_duration`. For `ConnectionPeerType::Unstaked` this always returns the same constant `max_unstaked_load_in_throttling_window` (`streamer/src/nonblocking/stream_throttle.rs:167-188`), computed once at startup from `MAX_UNSTAKED_TPS` (200) and independent of the current number of unstaked connections. The counter enforcing this quota, `ConnectionStreamCounter`, is allocated fresh per connection (`swqos.rs:209-219`) and reset per-connection every 100ms (`reset_throttling_params_if_needed`, `stream_throttle.rs:211-230`), so the 200 TPS budget is strictly local to a single connection.

`increment_load` (`stream_throttle.rs:160-165`) only feeds staked load into the shared EMA — unstaked streams never contribute to any aggregate accounting, so there is no mechanism that reduces per-connection unstaked quota as the number of unstaked connections grows. The only aggregate control is the connection-count cap `max_unstaked_connections` (default 2000), enforced in `prune_unstaked_connections_and_add_new_connection`/`prune_unstaked_connection_table` (`swqos.rs:241-290`). Because per-IP limits (`max_connections_per_unstaked_peer`=8) and the per-IP connection-rate limiter only restrict a single source IP, an attacker controlling multiple IPs (NAT/VPS pool) can occupy up to the full 2000-connection unstaked pool.

Result: total sustainable unstaked ingress = `max_unstaked_connections * MAX_UNSTAKED_TPS` = 2000 × 200 = 400,000 streams/sec — 4x the codebase's own stated design target of 20% of `DEFAULT_MAX_STREAMS_PER_MS` (100,000/sec, per the `EXPECTED_UNSTAKED_STREAMS_RATIO` comment). Every stream is forwarded through `fetch_stage` into `sigverify_stage`, where dedup and `ed25519_verify_serial` (`core/src/sigverify.rs:282-344`) spend real CPU before a garbage/invalid packet is discarded — work that is never repaid by a fee since the transaction is never valid.

### Impact Explanation
This is a QoS/pre-fee-work-pricing design gap: work spent per packet before a fee is collected scales with attacker-controlled connection count rather than being bounded to a proportionate share of validator capacity. This falls under "grossly underpriced pre-fee work" / QoS evasion for unstaked ingress, allowing a purely unstaked, unprivileged remote attacker to consume a disproportionate (and configuration-inconsistent) share of sigverify/dedup CPU relative to what the per-flow throttle design intends, degrading available sigverify throughput for legitimate staked traffic during that CPU contention window.

### Likelihood Explanation
Fully achievable by an unstaked remote client with access to multiple source IP addresses (commodity via cloud VPS pool/NAT egress diversity), respecting the RTT-based `max_streams_in_flight`/per-connection throttle math exactly as designed, requiring no stake, no keys, and no cooperation from any validator/peer. The only friction is acquiring ~2000 distinct source IPs (or being bound by the same IP's `max_connections_per_unstaked_peer`=8 and per-minute connection-rate limiter), both trivially available to a moderately resourced attacker.

### Recommendation
Track unstaked load in a shared, connection-count-aware budget (mirroring how staked load already uses a shared EMA), e.g. divide the fixed unstaked window budget by the current unstaked connection-table size, or maintain a global unstaked `StakedStreamLoadEMA`-style counter and enforce `EXPECTED_UNSTAKED_STREAMS_RATIO * max_streams_per_ms` as an aggregate ceiling instead of `MAX_UNSTAKED_TPS` per connection.

    pub(crate) fn available_load_capacity_in_throttling_duration(
        &self,
        peer_type: ConnectionPeerType,
        total_stake: u64,
    ) -> u64 {
        match peer_type {
            ConnectionPeerType::Unstaked => self.max_unstaked_load_in_throttling_window,
            ConnectionPeerType::Staked(stake) => {
                if self.staked_throttling_enabled.load(Ordering::Relaxed) {
                    // 1 is added to `max_unstaked_load_in_throttling_window` to guarantee that staked
                    // clients get at least 1 more number of streams than unstaked connections.
                    self.max_staked_load_in_throttling_window
                        .saturating_mul(stake)
                        .checked_div(total_stake)
                        .unwrap_or(self.max_unstaked_load_in_throttling_window + 1)
                        .max(self.max_unstaked_load_in_throttling_window + 1)
                } else {
                    self.max_staked_load_in_throttling_window
                }
            }
        }
    }

        let last_throttling_instant = *self.last_throttling_instant.read().unwrap();
