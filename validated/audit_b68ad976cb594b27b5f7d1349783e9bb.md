### Title
Unprotected first-writer partition assignment allows relative-path squatting and cross-repository partition collision - (File: internal/gitaly/storage/storagemgr/partition_assigner.go)

### Summary
`partitionAssigner.getPartitionID` / `getPartitionIDRecursive` / `assignPartitionID` permanently record, in the `partitionAssignmentTable` (backed by the storage's Badger KV store), which partition a given repository *relative path* belongs to. When the flag `isRepositoryCreation` is set, this assignment is allowed to happen for a relative path that **does not yet exist on disk** [1](#0-0) . Whichever transaction is first to request a partition for that not-yet-existing path "wins" and writes the binding via `assignPartitionID`/`setPartitionID`, with no check on who is entitled to create a repository at that path [2](#0-1) . This is structurally the same bug class as the `L2EthToken.initialization` issue: a one-time, security-relevant piece of state (here, the partition a repository path is permanently bound to, including which alternate/pool it is co-located with) is set by whichever caller gets there first, rather than being scoped to the legitimate creator.

### Finding Description
`getPartitionID(ctx, relativePath, partitionWithRelativePath, isRepositoryCreation)` is the entry point used when a transaction begins for repository-creating RPCs (e.g. `CreateRepository`, `CreateFork`, `CreateObjectPool`) [3](#0-2) . It supports an optional `partitionWithRelativePath` "hint" — the alternate/origin repository that the new repository should be co-located with in the same partition (used for pool members and forks) [4](#0-3) .

`getPartitionIDRecursive`, when it finds no existing assignment for `relativePath`, acquires a per-path lock and then validates the path is a Git directory — *unless* `isRepositoryCreation` is true, in which case a **non-existing** path is accepted and immediately gets a partition assigned to it [1](#0-0) . The assignment is then written unconditionally to the KV store by `assignPartitionID`/`setPartitionID`, with no verification that the caller who requested the assignment is the same actor who will ultimately create the repository at that relative path [5](#0-4) .

Because the assignment table is keyed purely by relative path and is checked/consulted before validating repo existence again on a subsequent call (`getPartitionID` re-reads `partitionAssignmentTable.getPartitionID` first) [6](#0-5) , the first transaction that begins targeting a given (not-yet-created) relative path — potentially with an attacker-chosen `partitionWithRelativePath` hint pointing at an attacker-controlled pool/alternate repository — permanently fixes that path's partition ID and co-location before the legitimate owner ever creates the repository there. A later, legitimate `CreateRepository`/`CreateFork` RPC for the same relative path will be forced into whatever partition was already claimed, since `getPartitionID` only checks that the hint and the resolved ID *agree*, returning `ErrRepositoriesAreInDifferentPartitions` otherwise, but happily reusing a pre-existing assignment when no hint is given [7](#0-6) .

### Impact Explanation
Repositories that share a partition are grouped together by the storage/transaction manager and can be linked via the alternates mechanism (an object pool and its members share a partition) [2](#0-1) [8](#0-7) . If an unprivileged actor can front-run the partition assignment for a relative path that a victim will later use to create a repository (e.g. a predictable fork/pool path), the attacker can force the not-yet-existing victim repository into the attacker's own partition/pool ahead of time. This is a cross-repository object-access / partition-confusion primitive: once the legitimate repository is created at that path, it is bound to the pre-claimed partition, and code paths that trust the partition assignment to establish alternate/pool relationships (`getAlternatePartitionID`) could give the attacker's repository unwarranted association with the victim's repository's storage domain.

### Likelihood Explanation
Reaching `isRepositoryCreation`-gated assignment requires beginning a transaction for a repository-creation RPC targeting a not-yet-existing relative path, which is something any client permitted to call `CreateRepository`/`CreateFork`/`CreateObjectPool` can trigger without needing to actually complete the repository creation (aborting after the assignment is written is sufficient, since `assignPartitionID` commits immediately and independently of whether the surrounding transaction eventually creates the on-disk repository). No additional privilege beyond ordinary RPC access is required, and the race only requires being first to target a specific, guessable/predictable relative path.

### Recommendation
Do not permanently persist a partition assignment for a relative path purely on the basis of a create-intent request. Defer `setPartitionID` until the repository is actually and successfully created on disk (i.e., make the assignment part of the same atomic commit that creates the repository, and roll it back if the surrounding transaction that created it is aborted), and re-validate that the relative path still doesn't exist and isn't already claimed at commit time, not merely at the time of the initial lock acquisition.

### Proof of Concept
1. Attacker predicts or controls a relative path `P` that will later be used to create a legitimate repository (e.g., a fork of a public project, or a project's future pool path).
2. Attacker sends a repository-creation RPC (or begins a transaction with `isRepositoryCreation=true`) targeting relative path `P`, optionally supplying `partitionWithRelativePath` pointing at an attacker-owned repository, then aborts before the repository is actually created on disk.
3. `getPartitionIDRecursive` accepts the non-existing path (`isRepositoryCreation=true` bypasses the `ValidateGitDirectory` failure) [1](#0-0)  and `assignPartitionID` persists the partition assignment for `P`, tying it to the attacker's chosen partition [2](#0-1) .
4. When the legitimate owner later creates the repository at `P`, `getPartitionID` finds the pre-existing assignment and reuses it, binding the victim's repository into the attacker-influenced partition [6](#0-5) .

Note: I was unable to fully trace, within the available exploration budget, the exact RPC/transaction-begin call site that sets `isRepositoryCreation=true` and whether an additional guard elsewhere (e.g., re-validation on commit) mitigates this before the WAL/transaction manager actually persists the badger write outside of a successful repo creation. This should be verified against `internal/gitaly/storage/storagemgr/partition` transaction-begin code before treating this as fully confirmed.

		return fmt.Errorf("flush: %w", err)

	return nil

func (pa *partitionAssigner) getPartitionID(ctx context.Context, relativePath, partitionWithRelativePath string, isRepositoryCreation bool) (storage.PartitionID, error) {
	var partitionHint storage.PartitionID
	if partitionWithRelativePath != "" {
		var err error
		// See if the target repository itself is already in a partition. If so, we should assign the other repository
		// in the same partition if it is not yet partitioned.
		if partitionHint, err = pa.partitionAssignmentTable.getPartitionID(relativePath); err != nil {
			if !errors.Is(err, storage.ErrPartitionAssignmentNotFound) {
				return 0, fmt.Errorf("get possible partition id: %w", err)
			}

			// There was no assignment.
			partitionHint = 0
		}

		// Get or assign the alternate into a partition. If the target repository was already assigned into a partition,
		// assign the alternate in the same partition. The hinted repository should always exist already as it is an object pool, or
		// the origin repo of a fork.
		if partitionHint, err = pa.getPartitionIDRecursive(ctx, partitionWithRelativePath, false, partitionHint, false); err != nil {
			return 0, fmt.Errorf("get additional relative path's partition ID: %w", err)
		}
	}

	// Get the repository's partition, or assign if it yet wasn't assigned, assign it with the alternate.
	ptnID, err := pa.getPartitionIDRecursive(ctx, relativePath, false, partitionHint, isRepositoryCreation)
	if err != nil {
		return 0, fmt.Errorf("get partition ID: %w", err)
	}

	if partitionHint != 0 && ptnID != partitionHint {
		return 0, ErrRepositoriesAreInDifferentPartitions
	}

	return ptnID, nil
}

func (pa *partitionAssigner) getPartitionIDRecursive(ctx context.Context, relativePath string, recursiveCall bool, partitionHint storage.PartitionID, isRepositoryCreation bool) (storage.PartitionID, error) {
	// Check first whether the repository is already assigned into a partition. If so, just return the assignment.
	ptnID, err := pa.partitionAssignmentTable.getPartitionID(relativePath)
	if err != nil {
		if !errors.Is(err, storage.ErrPartitionAssignmentNotFound) {
			return 0, fmt.Errorf("get partition: %w", err)
		}

		// Repository wasn't yet assigned into a partition. This is the slow path. Requests attempting
		// to get or assign a partition ID concurrently are serialized.

		releaseLock, err := pa.acquireRepositoryLock(ctx, relativePath)
		if err != nil {
			return 0, fmt.Errorf("acquire repository lock: %w", err)
		}

		defer releaseLock()

		// With the repository locked, check first whether someone else assigned it into a partition
		// while we weren't holding the lock between the first failed attempt getting the assignment
		// and locking the repository.
		ptnID, err = pa.partitionAssignmentTable.getPartitionID(relativePath)
		if !errors.Is(err, storage.ErrPartitionAssignmentNotFound) {
			if err != nil {
				return 0, fmt.Errorf("recheck partition: %w", err)
			}

			// Some other goroutine assigned a partition between the failed attempt and locking the
			// repository.
			return ptnID, nil
		}

func (pa *partitionAssigner) assignPartitionID(ctx context.Context, relativePath string, recursiveCall bool, partitionHint storage.PartitionID) (storage.PartitionID, error) {
	// Check if the repository has an alternate. If so, it needs to go into the same
	// partition with it.
	ptnID, err := pa.getAlternatePartitionID(ctx, relativePath, recursiveCall, partitionHint)
	if err != nil {
		if !errors.Is(err, gitstorage.ErrNoAlternate) {
			return 0, fmt.Errorf("get alternate partition ID: %w", err)
		}

		ptnID = partitionHint
		if ptnID == invalidPartitionID {
			// The repository has no alternate. Unpooled repositories go into their own partitions.
			// Allocate a new partition ID for this repository.
			ptnID, err = pa.allocatePartitionID()
			if err != nil {
				return 0, fmt.Errorf("acquire partition id: %w", err)
			}
		}
	}

	if err := pa.partitionAssignmentTable.setPartitionID(relativePath, ptnID); err != nil {
		return 0, fmt.Errorf("set partition: %w", err)
	}

	return ptnID, nil
}

func (pa *partitionAssigner) getAlternatePartitionID(ctx context.Context, relativePath string, recursiveCall bool, partitionHint storage.PartitionID) (storage.PartitionID, error) {
	alternate, err := gitstorage.ReadAlternatesFile(filepath.Join(pa.storagePath, relativePath))
	if err != nil {
		return 0, fmt.Errorf("read alternates file: %w", err)
	}

	if recursiveCall {
		// recursive being true indicates we've arrived here through another repository's alternate.
		// Repositories in Gitaly should only have a single alternate that points to the repository's
		// pool. Chains of alternates are unexpected and could go arbitrarily long, so fail the operation.
		return 0, storage.ErrAlternateHasAlternate
	}

	// The relative path should point somewhere within the same storage.
	alternateRelativePath, err := storage.ValidateRelativePath(
		pa.storagePath,
		// Take the relative path to the repository, not 'repository/objects'.
		filepath.Dir(
			// The path in alternates file points to the object directory of the alternate
			// repository. The path is relative to the repository's own object directory.
			filepath.Join(relativePath, "objects", alternate),
		),
	)
	if err != nil {
		return 0, fmt.Errorf("validate relative path: %w", err)
	}

	if alternateRelativePath == relativePath {
		// The alternate must not point to the repository itself. Not only is it non-sensical
		// but it would also cause a dead lock as the repository is locked during this call
		// already.
		return 0, storage.ErrAlternatePointsToSelf
	}

	// Recursively get the alternate's partition ID or assign it one. This time
	// we set recursive to true to fail the operation if the alternate itself has an
	// alternate configured.
	ptnID, err := pa.getPartitionIDRecursive(ctx, alternateRelativePath, true, partitionHint, false)
	if err != nil {
		return 0, fmt.Errorf("get partition ID: %w", err)
	}

	return ptnID, nil
}
