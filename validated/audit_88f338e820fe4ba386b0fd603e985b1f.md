### Title
Stale `VMConfig.allowTvmVote()` gate leaves `FREEZE`/`UNFREEZE` TVM opcodes able to bypass STATICCALL read-only enforcement - (File: actuator/src/main/java/org/tron/core/vm/OperationActions.java)

### Summary
The TVM enforces that state-mutating opcodes cannot run inside a `STATICCALL` (read-only) context by checking `program.isStaticCall()` and throwing `Program.StaticCallModificationException()`. Nearly every resource-mutating opcode added after the freeze/vote feature (`FREEZEBALANCEV2`, `UNFREEZEBALANCEV2`, `WITHDRAWEXPIREUNFREEZE`, `CANCELALLUNFREEZEV2`, `DELEGATERESOURCE`, `UNDELEGATERESOURCE`, `VOTEWITNESS`, `WITHDRAWREWARD`) unconditionally enforces this check. However, the original `freezeAction`/`unfreezeAction` implementations still gate the static-call check behind the legacy feature flag `VMConfig.allowTvmVote()`, instead of enforcing it unconditionally like the newer opcodes.

`freezeAction`/`unfreezeAction` only reject a static call when `VMConfig.allowTvmVote()` is true. If `allowTvmVote` is not active on a given network/fork state (e.g., during any period where this specific hard fork flag has not been enabled, is disabled for testing, or on chains/genesis configs that never activate it while other TVM upgrades such as `allowTvmFreezeV2` are active), a `STATICCALL` into a contract executing the legacy `FREEZE`/`UNFREEZE` opcodes would not be blocked from attempting resource state changes — defeating the very invariant (`isStaticCall()` must forbid all state mutation) that the rest of the opcode set enforces unconditionally. Since `freezeAction` degrades gracefully into a no-op when `allowTvmFreezeV2()` is true (just pushes zero), the practical mutation path is specifically `unfreezeAction`, which unconditionally calls `program.unfreeze(...)` — a real state-changing operation reclaiming frozen TRX — whenever the `allowTvmVote` gate is false, regardless of static-call context.

This is the closest reachable analog to the reported bug class: a caller restricted to a "read-only"/"view" execution context (STATICCALL, exactly analogous to Piwik's "view permission") can trigger a state-mutating operation because the authorization check (`isStaticCall()`) is conditionally skipped rather than enforced, an instance of CWE-269 (Improper Privilege Management) applied to TVM's read/write privilege boundary.

### Impact Explanation
If exploitable on a live network configuration where `allowTvmVote` is disabled while contracts using the legacy `FREEZE`/`UNFREEZE` opcodes are still callable, an attacker could invoke a victim contract via `STATICCALL` (e.g., from another contract, or via `eth_call`/`triggerconstantcontract` semantics that assume "constant"/no-mutation execution) and have it perform unfreeze operations that were assumed impossible in a read-only context, resulting in unauthorized resource-balance state mutation outside of the code paths the rest of the protocol assumes are safe for constant/view calls.

### Likelihood Explanation
Exploitability is conditional on the specific combination of feature-activation flags (`allowTvmVote` off while `FREEZE`/`UNFREEZE` opcodes remain reachable) — on current mainnet these flags are very likely both permanently activated already, which would make the gap dormant/unreachable in practice. I could not fully verify from the indexed code the exact hard-fork activation status or config defaults for `allowTvmVote` vs. `allowTvmFreezeV2` on the target deployment, so likelihood is assessed as low-to-moderate and contingent on network/fork configuration that could not be conclusively confirmed with available tools.

### Recommendation
Remove the `VMConfig.allowTvmVote()` conditional from `freezeAction` and `unfreezeAction` so that the `isStaticCall()` check is unconditional, consistent with `freezeBalanceV2Action`, `unfreezeBalanceV2Action`, `voteWitnessAction`, `withdrawRewardAction`, and all other resource-mutating opcodes.

### Proof of Concept
1. Deploy a contract `A` whose fallback/function invokes the legacy `UNFREEZE` opcode (bytecode-level, pre-`allowTvmFreezeV2` semantics).
2. Deploy a contract `B` that performs `STATICCALL` into `A`.
3. On a network/test environment where `VMConfig.allowTvmVote()` returns `false` (e.g., unit test harness toggling `VMConfig.initAllowTvmVote(0)` as seen in the codebase's test patterns for other flags), call `B` via `triggerconstantcontract`/`eth_call`.
4. Observe that `unfreezeAction` executes `program.unfreeze(...)` without throwing `StaticCallModificationException`, whereas an equivalent call into `unfreezeBalanceV2Action` under the same static context correctly throws.

  public static void freezeAction(Program program) {
    // after allow vote, check static
    if (VMConfig.allowTvmVote() && program.isStaticCall()) {
      throw new Program.StaticCallModificationException();
    }
    // 0 as bandwidth, 1 as energy
    DataWord resourceType = program.stackPop();
    DataWord frozenBalance = program.stackPop();
    DataWord receiverAddress = program.stackPop();

    if (VMConfig.allowTvmFreezeV2()) {
      // after v2 activated, we just push zero to stack and do nothing
      program.stackPush(DataWord.ZERO());
    } else {
      boolean result = program.freeze(receiverAddress, frozenBalance, resourceType );
      program.stackPush(result ? DataWord.ONE() : DataWord.ZERO());
    }
    program.step();
  }

  public static void unfreezeAction(Program program) {
    if (VMConfig.allowTvmVote() && program.isStaticCall()) {
      throw new Program.StaticCallModificationException();
    }

    DataWord resourceType = program.stackPop();
    DataWord receiverAddress = program.stackPop();

    boolean result = program.unfreeze(receiverAddress, resourceType);
    program.stackPush(result ? DataWord.ONE() : DataWord.ZERO());
    program.step();
  }

  public static void voteWitnessAction(Program program) {
    if (program.isStaticCall()) {
      throw new Program.StaticCallModificationException();
    }

    int amountArrayLength = program.stackPop().intValueSafe();
    int amountArrayOffset = program.stackPop().intValueSafe();
    int witnessArrayLength = program.stackPop().intValueSafe();
    int witnessArrayOffset = program.stackPop().intValueSafe();

    boolean result = program.voteWitness(witnessArrayOffset, witnessArrayLength,
        amountArrayOffset, amountArrayLength);
    program.stackPush(result ? DataWord.ONE() : DataWord.ZERO());
    program.step();
  }
