### Title
StackerDB chunk signatures omit the target contract identifier, enabling cross-DB replay of authenticated chunks - (File: `libstackerdb/src/libstackerdb.rs`)

### Summary
`SlotMetadata::auth_digest()` computes the signed digest for a StackerDB chunk over only `slot_id`, `slot_version`, and `data_hash`, with no binding to the StackerDB contract (`QualifiedContractIdentifier`) the chunk belongs to. [1](#0-0) 
This mirrors the reported bug class: a signature that omits a required domain/context value (there, `chainId`; here, the target StackerDB contract) lets a validly-authenticated message be replayed outside the context it was authorized for.

### Finding Description
`validate_received_chunk` in `stackslib/src/net/stackerdb/mod.rs` looks up the expected signer address via `get_slot_signer(smart_contract_id, data.slot_id)`, then calls `slot_metadata.verify(&addr)`, which recomputes `auth_digest()` and recovers the public key strictly from `(slot_id, slot_version, data_hash)`. [2](#0-1) 
The `smart_contract_id` is used only to select which signer address to check against — it is never part of the bytes that are actually signed. `SlotMetadata::verify` and `StackerDBChunkData::verify`/`recover_pk` confirm the same limited digest. [3](#0-2) 

Because Nakamoto signers reuse the same signing key across multiple, structurally similar StackerDB replicas (e.g. distinct per-reward-cycle signer contracts such as `signers-0-xxx` / `signers-1-xxx`), it is plausible for the same `StacksAddress` to be assigned the same `slot_id` in more than one StackerDB contract instance. In that situation, a chunk that was legitimately signed and stored for contract A's slot `N` carries a signature that is *also* valid for contract B's slot `N`, since the signed digest never encodes which contract it was intended for. An unprivileged relayer can capture such a chunk (chunks are gossiped in cleartext via `StackerDBPushChunk`/`StackerDBGetChunk`) and resubmit it against a different StackerDB contract instance where the same address/slot pairing exists. `validate_received_chunk` will accept it as long as the (unrelated) version/size/max-writes checks pass, because those checks are purely local to the target DB and do not reference the originating contract at all.

This is the direct structural analog of the report: the "chainId" that should scope a signature to its execution context is missing; here the missing scope is the target StackerDB contract identifier.

### Impact Explanation
This breaks the equality "authenticated for DB A" vs. "stored as authenticated in DB B": a message a signer only intended to publish in one StackerDB replica can be planted, by any unprivileged network participant, into a different StackerDB replica as if it were freshly and specifically authorized there. Depending on which StackerDB contracts share slot assignments (signer message stores are the primary candidate, since `MessageSlotID`/slot layout and signer sets recur structurally across reward cycles and split contracts), this allows unauthorized cross-context writes of otherwise-genuine signer data — e.g., resurrecting a stale, no-longer-valid signer message (block approval/rejection, transaction bundle, etc.) as current state in a different contract/cycle without the signer countersigning for that specific context. This matches the "unauthenticated/unauthorized write to state or StackerDB" and "network-wide propagation of forged[-context] data" impact classes.

### Likelihood Explanation
Exploitation requires no privileged access and no cryptographic break — only observing a legitimately gossiped chunk (which is broadcast unencrypted over P2P/StackerDB sync) and resubmitting it to a different, structurally compatible StackerDB contract where the signature happens to validate against the expected slot signer. The likelihood is bounded primarily by how often the same address ends up assigned the same `slot_id` across distinct StackerDB contract instances, which I was not able to fully confirm from the available index (the exact slot-assignment algorithm for `signers-0-xxx`/`signers-1-xxx` contracts and cross-cycle stability was not fully retrievable in this session).

### Recommendation
Include the target `QualifiedContractIdentifier` (and ideally a network/chain identifier) as part of the digest computed in `SlotMetadata::auth_digest()`, so that a chunk signature is cryptographically scoped to the specific StackerDB contract it is meant for:
```rust
fn auth_digest(&self, contract_id: &QualifiedContractIdentifier) -> Sha512Trunc256Sum {
    let mut hasher = Sha512_256::new();
    hasher.update(contract_id.to_string().as_bytes());
    hasher.update(self.slot_id.to_be_bytes());
    hasher.update(self.slot_version.to_be_bytes());
    hasher.update(self.data_hash.0);
    Sha512Trunc256Sum::from_hasher(hasher)
}
```
This requires updating `sign`/`verify` call sites in `libstackerdb/src/libstackerdb.rs` and `stackslib/src/net/stackerdb/mod.rs` to thread the contract ID through, which is a breaking wire-format/protocol change requiring a version gate.

### Proof of Concept
1. Node operator has signing key `K` assigned to `slot_id = 3` in StackerDB contract `A` (e.g., `signers-0-<cycle N>`) and also to `slot_id = 3` in StackerDB contract `B` (e.g., `signers-0-<cycle N+1>`, if the same reward set/slot layout persists).
2. Signer legitimately signs and pushes `StackerDBChunkData { slot_id: 3, slot_version: 5, sig, data }` to contract `A`. This chunk propagates via P2P to any listening peer, per `handle_unsolicited_StackerDBPushChunk`. [4](#0-3) 
3. An unprivileged attacker captures this chunk and resubmits it (same `sig`, same `data`, `slot_id=3`) against contract `B`, where the expected version for slot 3 is `< 5` (e.g. a fresh or lagging replica).
4. `validate_received_chunk` for contract `B` fetches `get_slot_signer(B, 3)` → returns the same address as in contract `A`; `slot_metadata.verify(&addr)` succeeds because the digest never referenced which contract it was for. [2](#0-1) 
5. The chunk is accepted and stored into contract `B`'s slot 3 even though the signer never authorized publishing this data into contract `B`.

    /// Verify that a given principal signed this chunk metadata.
    /// Note that the address version is ignored.
    pub fn verify(&self, principal: &StacksAddress) -> Result<bool, Error> {
        let sigh = self.auth_digest();
        let pubk = StacksPublicKey::recover_to_pubkey_without_validating_low_s(
            sigh.as_bytes(),
            &self.signature,
        )
        .map_err(|ve| Error::VerifyingError(ve.to_string()))?;

        let pubkh = Hash160::from_node_public_key(&pubk);
        Ok(pubkh == *principal.bytes())
    }
}

/// Helper methods for StackerDBChunkData messages
impl StackerDBChunkData {
    /// Create a new StackerDBChunkData instance.
    pub fn new(slot_id: u32, slot_version: u32, data: Vec<u8>) -> StackerDBChunkData {
        StackerDBChunkData {
            slot_id,
            slot_version,
            sig: MessageSignature::empty(),
            data,
        }
    }

    /// Calculate the hash of the chunk bytes.  This is the SHA512/256 hash of the data.
    pub fn data_hash(&self) -> Sha512Trunc256Sum {
        Sha512Trunc256Sum::from_data(&self.data)
    }

    /// Create an owned SlotMetadata describing the metadata of this slot.
    pub fn get_slot_metadata(&self) -> SlotMetadata {
        SlotMetadata {
            slot_id: self.slot_id,
            slot_version: self.slot_version,
            data_hash: self.data_hash(),
            signature: self.sig.clone(),
        }
    }

    /// Sign this given chunk data message with the given private key.
    /// Sets self.signature to the signature.
    /// Fails if the underlying signing library fails.
    pub fn sign(&mut self, privk: &StacksPrivateKey) -> Result<(), Error> {
        let mut md = self.get_slot_metadata();
        md.sign(privk)?;
        self.sig = md.signature;
        Ok(())
    }

    pub fn recover_pk(&self) -> Result<StacksPublicKey, Error> {
        let digest = self.get_slot_metadata().auth_digest();
        StacksPublicKey::recover_to_pubkey_without_validating_low_s(digest.as_bytes(), &self.sig)
            .map_err(|ve| Error::VerifyingError(ve.to_string()))
    }

    /// Verify that this chunk was signed by the given
    /// public key hash (`addr`).  Only fails if the underlying signing library fails.
    pub fn verify(&self, addr: &StacksAddress) -> Result<bool, Error> {
        let md = self.get_slot_metadata();
        md.verify(addr)
    }
}
