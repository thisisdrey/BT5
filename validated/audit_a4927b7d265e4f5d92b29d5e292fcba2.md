### Title
Unauthenticated remote `POST /shutdown` terminates the signer's event receiver - (File: libsigner/src/events.rs)

### Summary
`SignerEventReceiver::next_event` routes any HTTP request whose `url()` equals `/shutdown` into a branch that unconditionally sets `stop_signal` to `true` and returns `EventError::Terminated`, with no check of the request body, source, or any secret/token. `EventStopSignaler::send` (the intended, trusted internal caller) happens to use this same endpoint, but nothing on the wire distinguishes its request from an attacker's request to the same socket.

### Finding Description
The event listener is a `tiny_http::HttpServer` bound by `SignerEventReceiver::bind` [1](#0-0) , and the dispatch logic in `next_event` matches on `request.url()` for `/status`, `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/shutdown`, `/new_block` [2](#0-1) . The `/shutdown` arm does nothing but flip the atomic stop flag and return `Terminated`:
```rust
} else if request.url() == "/shutdown" {
    event_receiver.stop_signal.store(true, Ordering::SeqCst);
    Err(EventError::Terminated)
}
``` [3](#0-2) 

The only intended sender is `SignerStopSignaler::send`, which connects to the receiver's own `local_addr` and issues a raw `POST /shutdown` over a plain `TcpStream` [4](#0-3) . There is no shared secret, token, loopback-only enforcement, or origin check embedded in that request — it is indistinguishable from a request forged by any other TCP client that can reach the same address. `main_loop` treats `Err(EventError::Terminated)` as the exit signal for the whole receiver thread [5](#0-4) , after which the signer stops processing all StackerDB chunks, burn blocks, proposal responses, and new blocks.

The equality the code needs but does not enforce is: *"the sender of `/shutdown` == the process holding this receiver's own stop signal (i.e., the signer's own runloop)."* Instead the code checks only the URL string, which any TCP peer reaching the socket can supply.

### Impact Explanation
A single unauthenticated `POST /shutdown` (or even a raw TCP connection with that request line) permanently halts the signer's event-processing loop until the operator restarts the signer process. Since signer participation is required for block validation/signing responses, this is a Critical unauthenticated DoS against an individual signer, repeatable at will and requiring only one crafted request per kill.

### Likelihood Explanation
The only precondition is network reachability to the bound socket. The question explicitly frames this to be tested "as reachable," and nothing in `bind`/`next_event` restricts the listener to loopback or checks peer identity — `HttpServer::http(listener)` binds exactly to whatever `SocketAddr` is configured [1](#0-0) . If the signer's `endpoint` config is bound to a non-loopback interface (common in containerized/dockerized or multi-host signer deployments), this is exploitable by any remote attacker; even if bound to loopback only, any local process (including a low-privileged one) can trivially exploit it. The attack requires no authentication token, no valid StackerDB slot, and no prior state — just one TCP connection and a fixed HTTP request body.

### Recommendation
Do not expose an unauthenticated shutdown path over the network. Replace the `/shutdown` HTTP request with a genuinely internal signal — e.g., have `SignerStopSignaler` set the `AtomicBool` directly (it already holds an `Arc<AtomicBool>` clone) and use a local-only mechanism (e.g., writing to a `UnixListener`/self-pipe, or simply having `next_event`'s blocking `recv()` interrupted via a short poll/timeout loop that also checks `is_stopped()`) instead of accepting a plaintext HTTP POST that any remote peer can replay. If an HTTP-based signal must be kept for compatibility, require it to arrive on a loopback-only listener/unix socket and additionally verify a per-process random shared secret set at startup.

### Proof of Concept
```rust
// libsigner/src/events.rs (test module) or a standalone integration test
use std::net::{TcpStream, SocketAddr};
use std::io::Write;
use libsigner::{EventReceiver, SignerEventReceiver, SignerEvent};

#[test]
fn unauthenticated_remote_shutdown_dos() {
    let mut receiver: SignerEventReceiver<SomeSignerMessageType> = SignerEventReceiver::new(false);
    let addr: SocketAddr = "127.0.0.1:0".parse().unwrap();
    let bound = receiver.bind(addr).unwrap();

    // Attacker-controlled plain TCP client, NOT using SignerStopSignaler
    let mut stream = TcpStream::connect(bound).unwrap();
    let body = "attacker";
    let req = format!(
        "POST /shutdown HTTP/1.1\r\nHost: {}\r\nConnection: close\r\nContent-Length: {}\r\n\r\n{}",
        bound, body.len(), body
    );
    stream.write_all(req.as_bytes()).unwrap();

    // next_event should return Terminated even though the sender never held
    // a legitimate SignerStopSignaler
    let result = receiver.next_event();
    assert!(matches!(result, Err(libsigner::EventError::Terminated)));
    assert!(receiver.is_stopped());
}
```
This demonstrates that any TCP peer reaching the bound address can force `next_event` to return `Terminated` and `is_stopped()` to become `true`, matching the claim exactly.
