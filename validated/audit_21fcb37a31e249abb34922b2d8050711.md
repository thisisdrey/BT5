### Title
Zero-debt users cannot withdraw collateral when any oracle feed is unavailable, because `debtPositionOf` unnecessarily prices all deposits - ([File: contracts/Pool.sol](contracts/Pool.sol))

### Summary
Analogous to the Y2K `triggerEndEpoch`/`getLatestPrice` finding, Metronome performs oracle price queries that are not strictly required for the functional outcome, and a revert in those queries blocks user withdrawals. `DepositToken.withdraw` → `_revertIfLocked` → `unlockedBalanceOf` calls `Pool.debtPositionOf`, which unconditionally prices **all** of the account's deposit tokens via `depositOf` and all debt tokens via `debtOf` — even when the account has zero debt (where `unlockedBalanceOf` short-circuits to the full balance anyway) and even for tokens whose balance is `0` (where the oracle quote is multiplied by zero). A single stale/down feed therefore freezes withdrawals of unrelated collateral for users with no debt.

### Finding Description
`DepositToken.withdraw` calls `_revertIfLocked`, which calls `unlockedBalanceOf`. [1](#0-0) 

`unlockedBalanceOf` calls `pool.debtPositionOf`, which computes `_debtInUsd = debtOf(account_)` and then `(_depositInUsd, _issuableLimitInUsd) = depositOf(account_)`. [2](#0-1) 

`debtOf` loops over `debtTokensOfAccount` and calls `masterOracle.quoteTokenToUsd(syntheticToken, balanceOf(account_))` — invoking the oracle even when `balanceOf` is `0`. [3](#0-2) 

`depositOf` similarly iterates every deposit token of the account and quotes each underlying's USD price. If the account has no debt, `_debtInUsd == 0` and `unlockedBalanceOf` returns `balanceOf[account_]` — making the entire `depositOf` computation irrelevant to the result — but it executes first and will revert if any feed (e.g., a stale `vaToken` price, a Chainlink stale-round check, or a pull oracle that hasn't been updated) reverts. The price data is effectively "informational" for a zero-debt account, yet it gates the withdrawal path.

The tests confirm the revert propagates into user flows: `msdUSDC.withdraw` reverts with `price-expired` once the oracle is stale. [4](#0-3) 

### Impact Explanation
- Users with zero debt cannot withdraw collateral while any oracle feed used by the pool's tokens is stale/unavailable — a temporary freezing of user funds that is not justified by solvency checks (there is no debt to secure).
- Liquidations and repayments can also be blocked by an unrelated zero-balance token's stale feed in `debtOf`, since `quoteTokenToUsd(x, 0)` still calls the oracle.
- The protocol mitigates this partially via `Operator.execute` (update pull oracle + act in one tx), but this only helps pull-oracle deployments; push/Chainlink feeds or sequencer-downtime scenarios cannot be self-healed by users, and `withdraw`/`transfer`/`transferFrom` remain bricked.

### Likelihood Explanation
Requires an external condition (oracle staleness or feed downtime), which is exactly the same pre-condition as the reference Y2K finding (Arbitrum sequencer grace period). Metronome deploys many collateral `DepositToken`s across chains and uses pull oracles (Pyth/RedStone) on some deployments where prices are *expected* to be stale between updates, making the zero-debt withdrawal revert a routine occurrence rather than an edge case — the E2E tests explicitly demonstrate `debtPositionOf` reverting with `price-too-behind`/`invalid-token-price` when feeds are not updated. [5](#0-4) 

### Recommendation
- In `Pool.debtOf`, skip the oracle quote when `_debtToken.balanceOf(account_) == 0`.
- In `DepositToken.unlockedBalanceOf` (or `debtPositionOf`), avoid pricing deposits when `_debtInUsd == 0` — e.g., compute `debtOf` first and only call `depositOf` when debt is non-zero, or add a `debtOf`-only fast path.
- In `Pool.depositOf`, skip quoting tokens with zero balance.

### Proof of Concept
Hardhat fork test sketch (mirroring `test/Operator.test.ts` fixture):

```ts
// alice deposits USDC only, no debt
await usdc.connect(alice).approve(msdUSDC.address, amount)
await msdUSDC.connect(alice).deposit(amount, alice.address)

// make ONE oracle feed stale (e.g., the USDC feed via MasterOracleMock expiration,
// or on a pull-oracle deployment simply don't push updates)
await pullOracle.setExpirationPeriod(1)
await time.increase(time.duration.hours(2))

// BUG: withdraw reverts even though alice has zero debt and the
// price is irrelevant to the unlock check
await expect(msdUSDC.connect(alice).withdraw(amount, alice.address))
  .revertedWith('price-expired') // already demonstrated in Operator.test.ts L121-128

// Same for transfer of msdUSDC (also gated by _revertIfLocked)
await expect(msdUSDC.connect(alice).transfer(bob.address, amount))
  .revertedWith('price-expired')
```

The existing test at `test/Operator.test.ts:121-128` already demonstrates the core revert: `withdraw` fails with `price-expired` for a user whose only operation requires no price at all once `_debtInUsd == 0`.
