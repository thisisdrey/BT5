### Title
Uninitialized `accountIndexOf` credits `balance × INITIAL_INDEX` rewards when the token index equals `INITIAL_INDEX` — drains entire reward pool - ([File: contracts/RewardsDistributor.sol](contracts/RewardsDistributor.sol))

### Summary
`RewardsDistributor._calculateTokenDelta` only back-fills a missing account index when the token index is *strictly greater* than `INITIAL_INDEX`. When the stored token index still equals `INITIAL_INDEX`, a depositor whose `accountIndexOf` is `0` is treated as if their index were `0`, producing a delta of `INITIAL_INDEX` (1e18) multiplied by their whole token balance — a massive over-accrual that is claimable for real reward tokens.

### Finding Description
Rewards are tracked per `(token, account)` via `accountIndexOf`, initialized lazily in `_updateTokensAccruedOf`/`_calculateTokenDelta`: [1](#0-0) 

The fallback `_accountIndex = INITIAL_INDEX` only fires when `_tokenIndex > INITIAL_INDEX`. When `tokenStates[token_].index == INITIAL_INDEX` exactly, `_deltaIndex = INITIAL_INDEX - 0 = 1e18`, and `_tokensDelta = balance × 1e18`.

This state pair — `accountIndexOf == 0` with `index == INITIAL_INDEX` — is reachable by an unprivileged attacker:

1. Attacker deposits into a `DepositToken` (or mints `DebtToken` debt) *before* any reward speed is configured. `updateBeforeMintOrBurn`/`updateBeforeTransfer` no-op while `tokenStates[token_].index == 0`, so the attacker's `accountIndexOf` stays `0` while holding a positive balance. [2](#0-1) 
2. Governance later calls `updateTokenSpeed`, which sets `tokenStates[token_] = {index: INITIAL_INDEX, timestamp: block.timestamp}`. [3](#0-2) 
3. In the **same block** (same timestamp), the attacker calls the permissionless `updateBeforeMintOrBurn(token, attacker)`. `_calculateTokenIndex` returns zeros because `_deltaTimestamps == 0`, so the index is *not* advanced past `INITIAL_INDEX`. [4](#0-3) 
4. `_updateTokensAccruedOf` then computes `_tokensDelta = attackerBalance.wadMul(1e18)` and adds it to `tokensAccruedOf[attacker]`. [5](#0-4) 
5. `claimRewards(attacker)` pays out `min(accrued, rewardToken.balanceOf(this))`, draining the distributor's entire reward-token balance. [6](#0-5) [7](#0-6) 

### Impact Explanation
Theft of unclaimed yield: the attacker extracts the whole `rewardToken` balance held by `RewardsDistributor` (rewards owed to all users), in a single transaction, with only a deposit of their own funds which remain withdrawable afterward. The required precondition (depositing before reward speed activation, then acting in the same block/timestamp as `updateTokenSpeed`) is achievable by mempool observation on the deployed chains, and `updateBeforeMintOrBurn` is explicitly callable by anyone.

### Likelihood Explanation
Likelihood is gated by timing rather than access: `updateBeforeMintOrBurn` is public, and once the block carrying `updateTokenSpeed` passes and any accrual advances the index past `INITIAL_INDEX`, the fallback path closes. The window is exactly the `updateTokenSpeed` transaction's block (or, more generally, any moment where `index == INITIAL_INDEX` and `timestamp` was just set — i.e., before the next timestamp tick causes an index bump). An attacker who pre-positions a deposit and back-runs the governor's `updateTokenSpeed` tx, or calls within the same timestamp, captures the full pool. No privileged role, oracle manipulation, or malicious infrastructure is required.

### Recommendation
Initialize `_accountIndex` to `INITIAL_INDEX` whenever it is `0`, not only when `_tokenIndex > INITIAL_INDEX`:

```solidity
if (_accountIndex == 0) {
    _accountIndex = _tokenIndex > INITIAL_INDEX ? _tokenIndex : INITIAL_INDEX;
}
```

Equivalently, use `>=` semantics so a stored index equal to `INITIAL_INDEX` produces a zero delta for never-initialized accounts. Alternatively, eagerly write `accountIndexOf[token][account] = INITIAL_INDEX` in `updateBeforeMintOrBurn`/`updateBeforeTransfer` on first touch.

### Proof of Concept
Foundry sketch:

```solidity
function testUninitializedAccountIndexDrainsRewards() public {
    // 1. Attacker deposits while no reward speed configured (tokenStates.index == 0)
    uint256 depositAmount = 100e18;
    underlying.mint(attacker, depositAmount);
    vm.prank(attacker);
    depositToken.deposit(depositAmount, attacker); // hook no-ops; accountIndexOf == 0

    // 2. Governor activates rewards
    vm.prank(governor);
    rewardsDistributor.updateTokenSpeed(IERC20(address(depositToken)), 1e18); // index = INITIAL_INDEX

    // 3. Same block (same timestamp): attacker calls public update fn
    vm.prank(attacker);
    rewardsDistributor.updateBeforeMintOrBurn(IERC20(address(depositToken)), attacker);

    // deltaIndex = INITIAL_INDEX - 0 = 1e18
    uint256 accrued = rewardsDistributor.tokensAccruedOf(attacker);
    assertEq(accrued, depositAmount); // wadMul(balance, 1e18) — astronomical vs real rewards

    // 4. Drain the distributor
    uint256 poolBal = rewardToken.balanceOf(address(rewardsDistributor));
    rewardsDistributor.claimRewards(attacker);
    assertEq(rewardToken.balanceOf(attacker), poolBal);
    assertEq(rewardToken.balanceOf(address(rewardsDistributor)), 0);
}
```
