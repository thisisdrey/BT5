### Title
Unstaked connection eviction is FIFO-by-connect-time, not activity-based, allowing connection churn to starve legitimate long-lived unstaked senders - ([File: streamer/src/nonblocking/quic.rs])

### Summary
`ConnectionTable::prune_oldest` evicts entries by minimum `last_update` timestamp, intending an LRU-style "evict least recently active" policy, but `last_update` is set exactly once — at connection acceptance time — and is never refreshed on subsequent stream/packet activity. As a result, eviction order is effectively FIFO by connection age, letting an unprivileged unstaked attacker continuously churn new connections to always look "newest" and force eviction of older, actively-used legitimate unstaked connections, without ever exceeding `max_connections_per_unstaked_peer`.

### Finding Description
`ConnectionEntry` stores a `last_update: Arc<AtomicU64>` [1](#0-0) , and `ConnectionTable::prune_oldest` selects the table bucket with the smallest `last_update` across its connections and evicts it entirely when `total_size` exceeds `max_size` [2](#0-1) .

This `last_update` value is set once, at connection-context construction time, to `timing::timestamp()` — i.e., wall-clock time the connection was accepted — for both unstaked and staked peers: [3](#0-2) . It is threaded unchanged through `try_add_connection` into the stored `ConnectionEntry` [4](#0-3) , and only cloned/returned, never subsequently updated (`.store()`) anywhere in `quic.rs`, `swqos.rs`, or `simple_qos.rs` in response to stream activity, data reception, or keep-alives.

`prune_unstaked_connection_table` is invoked on every incoming unstaked connection attempt once `total_size >= max_unstaked_connections`, pruning down to 90% capacity via `prune_oldest` [5](#0-4) , and this path is reached from `try_add_connection` for `ConnectionPeerType::Unstaked` unconditionally on every unstaked connection attempt [6](#0-5) .

Because `last_update` never reflects actual activity, `prune_oldest`'s "least recently used" semantics degenerate into "earliest connected." An attacker opening a continuous stream of brand-new unstaked connections (from many distinct source IPs/pubkeys, each individually respecting `max_connections_per_unstaked_peer`) will always populate the table with the freshest timestamps. Once the unstaked table nears `max_unstaked_connections`, every new attacker connection attempt triggers `prune_oldest`, which evicts the bucket with the oldest `last_update` — i.e., whichever legitimate unstaked sender connected earliest, regardless of whether that connection is actively and validly transmitting transactions. This inverts the intended fairness/anti-starvation property of an LRU cap: genuinely active, long-lived legitimate senders are preferentially evicted over newly-opened attacker connections, purely as a function of connection age rather than activity or abuse signal.

No other check (per-IP rate limiter, per-peer connection cap, stream throttling) mitigates this, since the exploit does not require any single peer/IP to exceed its cap — it only requires enough distinct sources (or IP reuse across the rate-limiter's window) to keep injecting new "youngest" entries into the shared unstaked table.

### Impact Explanation
This is a QoS evasion / fairness-guarantee bypass: an unprivileged unstaked attacker can force eviction of other legitimate unstaked senders' active QUIC connections from the leader's TPU port, denying them TPU stream capacity, without exceeding any individual per-peer or per-IP limit. This matches the "unstaked sender starvation" bounty category — cluster-wide degradation of unstaked transaction ingestion fairness caused by a QoS/rate-limit design flaw reachable from any unstaked remote client.

### Likelihood Explanation
The precondition is simply that the unstaked table is near capacity from a mix of legitimate and attacker connections — a routine operating condition given `max_unstaked_connections` is a fixed, moderate value. The attacker needs only the ability to open many QUIC connections from diverse source IPs (or otherwise stay under the per-IP connection rate limiter) faster than legitimate connections are naturally recycled; each attacker connection trivially satisfies `max_connections_per_unstaked_peer` individually. This requires no stake, no keys, and no protocol-level cleverness — just sustained low-cost connection churn, making it highly feasible and repeatable.

### Recommendation
Update `last_update` on actual connection/stream activity (e.g., on `on_stream_accepted`/packet receipt) rather than only at connection creation, so `prune_oldest` evicts genuinely idle connections instead of merely older ones. Alternatively, weight `prune_oldest` eviction by both age and activity, or bound the fraction of unstaked capacity any recently-created cohort of connections can occupy per time window to prevent churn-based takeover.

### Proof of Concept
```rust
// streamer/src/nonblocking/quic.rs (test module)
#[test]
fn test_prune_oldest_favors_connection_age_not_activity() {
    use std::net::Ipv4Addr;
    let cancel = CancellationToken::new();
    let mut table = ConnectionTable::new(ConnectionTableType::Unstaked, cancel);
    let stats = Arc::new(StreamerStats::default());
    let max_connections_per_peer = 1;

    // Legitimate victim connects first (older last_update), stays "active"
    // but its last_update timestamp is never refreshed post-creation.
    let victim_ip = IpAddr::V4(Ipv4Addr::new(1, 0, 0, 0));
    table.try_add_connection(
        ConnectionTableKey::IP(victim_ip), 0,
        ClientConnectionTracker::new(stats.clone(), 1000).unwrap(),
        None, ConnectionPeerType::Unstaked,
        Arc::new(AtomicU64::new(0)), // old timestamp, never updated
        max_connections_per_peer,
        || Arc::new(NullStreamerCounter {}),
    ).unwrap();

    // Attacker churns many new connections with strictly increasing timestamps,
    // each from a distinct IP, each individually within max_connections_per_peer.
    for i in 1..10u32 {
        let attacker_ip = IpAddr::V4(Ipv4Addr::new(100 + i as u8, 0, 0, 0));
        table.try_add_connection(
            ConnectionTableKey::IP(attacker_ip), 0,
            ClientConnectionTracker::new(stats.clone(), 1000).unwrap(),
            None, ConnectionPeerType::Unstaked,
            Arc::new(AtomicU64::new(i as u64)), // always newer than victim
            max_connections_per_peer,
            || Arc::new(NullStreamerCounter {}),
        ).unwrap();
    }

    // Simulate capacity pressure: prune down to 5 entries.
    table.prune_oldest(5);

    // Assert: victim's connection was evicted purely for being oldest,
    // even though "last_update" does not reflect real inactivity —
    // it was never refreshed for anyone, attacker or victim.
    assert!(!table.table.contains_key(&ConnectionTableKey::IP(victim_ip)));
}
```
This demonstrates that `prune_oldest` deterministically evicts the earliest-connected (not least-active) entry, confirming that sustained attacker connection churn can starve a legitimate unstaked sender's connection out of the table while never exceeding `max_connections_per_unstaked_peer`.

    pub(crate) fn prune_oldest(&mut self, max_size: usize) -> usize {
        let mut num_pruned = 0;
        let key = |(_, connections): &(_, &Vec<_>)| {
            connections.iter().map(ConnectionEntry::last_update).min()
        };
        while self.total_size.saturating_sub(num_pruned) > max_size {
            match self.table.values().enumerate().min_by_key(key) {
                None => break,
                Some((index, connections)) => {
                    num_pruned += connections.len();
                    self.table.swap_remove_index(index);
                }
            }
        }
        self.total_size = self.total_size.saturating_sub(num_pruned);
        num_pruned
    }
