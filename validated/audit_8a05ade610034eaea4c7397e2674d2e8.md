### Title
Unauthenticated Signer Event-Receiver Endpoint Accepts Forged Node Events - (File: libsigner/src/events.rs)

### Summary
The `stacks-signer` binds an HTTP listener (`SignerEventReceiver`) that is meant to receive event pushes exclusively from its paired, trusted `stacks-node`. This receiver performs no authentication of the caller and accepts any well-formed POST to its known routes.

### Finding Description
`SignerEventReceiver::next_event` dispatches based solely on URL path, with no credential, token, or peer-identity check anywhere in the handler: [1](#0-0) 

The only gating in `process_event` is that the body must deserialize into the expected event type; there is no check that the request originated from the configured `node_host` or carries any shared secret: [2](#0-1) 

Sample configuration explicitly shows this listener defaulting to `0.0.0.0`, i.e., bound to all interfaces rather than loopback-only: [3](#0-2) 

By contrast, the node's own privileged RPC endpoints (block proposal, tx/block simulate, fast-call-read-only) explicitly gate on a shared `auth_token` header before accepting a request: [4](#0-3) 

This is the same bug class as the mitmweb advisory: an internal-only control-plane API (here, the signer's event ingestion endpoint, analogous to mitmweb's `127.0.0.1:8081` API) is reachable by any unauthenticated party who can route a request to the bound socket — no reverse-proxy trick is even needed since the signer's own default bind address is `0.0.0.0`. The equality being broken is "trusted-node-originated event" vs. "any POST received," which the receiver treats as equivalent.

### Impact Explanation
An attacker on the same network segment (or anyone who can reach the port if not firewalled, e.g. cloud/NAT misconfiguration) can:
- POST to `/shutdown` to immediately terminate the signer's event loop (unauthenticated remote DoS of signer availability), since the handler sets the stop signal on any request to that path with no auth check: [5](#0-4) 
- POST forged `StackerDBChunksEvent`, `BlockValidateResponse`, `BurnBlockEvent`, or `StacksBlockEvent` payloads to `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block`, injecting attacker-controlled data directly into the signer's event channel that feeds its run-loop, spoofing what the trusted node is reporting.

Per the scan rules, evaluating the signer's downstream decision logic is out of scope, but the transport-layer fact that the ingestion boundary performs no authentication of the caller, unlike every other privileged control endpoint in this codebase, is squarely in scope and is a High-severity, unauthenticated-write-to-internal-state / DoS finding.

### Likelihood Explanation
High. No special access or secret is required. The signer explicitly warns in its own startup log that communicating with untrusted networks is risky, indicating the developers are aware the receiver has no built-in authentication and rely entirely on network-level isolation: [6](#0-5) 
That is a documented operational caveat, not a code-level mitigation — the endpoint itself will accept and act on any request that reaches it.

### Recommendation
Add an authentication gate to `SignerEventReceiver` symmetric to the `auth_token`/`auth_password` mechanism already used for the node's block-proposal RPC (e.g., require and verify a shared-secret `Authorization` header on every POST before dispatching to `process_event`, and reject `/shutdown` and event routes without it). At minimum, default-bind to `127.0.0.1` instead of `0.0.0.0` and document that binding to `0.0.0.0` requires an authenticated proxy in front of it.

### Proof of Concept
1. Start a `stacks-signer` with its default sample config (`endpoint = "0.0.0.0:30000"`).
2. From a remote/network-adjacent host, send: `POST /shutdown HTTP/1.1` to `<signer-ip>:30000` — the signer's event receiver terminates its main loop with no credential check, per `libsigner/src/events.rs:443-445`.
3. Alternatively, POST a crafted JSON body to `/proposal_response` or `/stackerdb_chunks` matching the expected `BlockValidateResponse`/`StackerDBChunksEvent` schema — it will be accepted and forwarded into the signer's event channel as if it came from the trusted node, per `libsigner/src/events.rs:519-542`.

    fn next_event(&mut self) -> Result<SignerEvent<T>, EventError> {
        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)
            } else if request.url() == "/new_block" {
                process_event::<T, StacksBlockEvent>(request)
            } else {
                let url = request.url().to_string();
                debug!(

                    event_receiver.local_addr,
                    url
                );
                ack_dispatcher(request);
                Err(EventError::UnrecognizedEvent(url))
            }
        })?

fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}
