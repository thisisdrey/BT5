Audit Report

## Title
Unbounded `UnappliedSlashes` queue causes unmetered, unweighted mass-slash processing that can stall era rotation - ([File: substrate/frame/staking/src/pallet/impls.rs])

## Summary
`pallet-staking`'s `UnappliedSlashes` storage map is declared `#[pallet::unbounded]` with no cap on the number of pending slash entries per era [1](#0-0) . Every deferred slash from `on_offence` is pushed onto this `Vec` with no admission check [2](#0-1) , and `start_era` unconditionally calls `apply_unapplied_slashes`, which `take()`s and iterates the entire `Vec` for the era in a single unweighted loop [3](#0-2) .

## Finding Description
The `on_offence` handler processes each reported offender and, when `SlashDeferDuration > 0`, pushes the computed `unapplied` slash into `UnappliedSlashes` keyed by the deferred era, with no limit check on the resulting `Vec` length [4](#0-3) . This queue can grow proportionally to the number of offenders reported within a slash-defer window.

At the era boundary, `start_era` — part of the mandatory, non-skippable session/era rotation hook — calls `Self::apply_unapplied_slashes(active_era)` unconditionally [5](#0-4) . That function drains the *entire* accumulated `Vec` for the era and applies every slash in one pass via `slashing::apply_slash`, which itself iterates over each slash's nominator exposures, with no `WeightMeter`, no per-call bound, and no ability to bail and resume in a later block [3](#0-2) .

This confirms the structural pattern described in the claim: an unbounded admission path into a queue, and a mandatory consumer that must fully drain it in a single unmetered pass on a path that cannot be skipped. The referenced prdoc for PR #7424 ("Bounded Slashing: Paginated Offence Processing & Slash Application") explicitly notes it was reverted in #7939, confirming the unbounded design remains the live behavior in this codebase.

## Impact Explanation
If a sufficiently large number of offences are reported and deferred within a single `SlashDeferDuration` window, `apply_unapplied_slashes` must synchronously process the entire backlog inside `start_era`, which executes inside the mandatory era-rotation path with no weight metering or bailout mechanism. This can consume disproportionate computation/storage-write volume within what is nominally bounded block execution, risking stalled or degraded block/era progression — a public underpriced/unmetered work condition that degrades block production, matching the allowed "public underpriced work that degrades block production or stalls... processing" impact category.

## Likelihood Explanation
Triggering this requires a large-scale offence-reporting event (e.g., broad equivocation or validity-attack activity across many validators with large nominator sets) accumulating within one deferral window — an externally-arising network condition rather than a single low-cost attacker transaction. This is a plausible, non-privileged-governance-dependent scenario since offence reporting via the session/consensus layer is not gated by staking-pallet-level admission controls, and legacy `pallet-staking` remains live in this repository (unlike `pallet-staking-async`, which has the paginated fix).

## Recommendation
Port the paginated `OffenceQueue`/bounded `apply_unapplied_slashes` design already implemented in `pallet-staking-async` into legacy `pallet-staking`, capping per-era admission of `UnappliedSlashes` entries and bounding per-call slash processing (e.g., via a `WeightMeter`) so that era rotation cannot be blocked by an unbounded backlog.

## Proof of Concept
1. Set `SlashDeferDuration > 0`.
2. Report offences for a large number of active validators within one deferral window, each with near-maximum nominator exposure.
3. Each report pushes an entry into `UnappliedSlashes` via `on_offence` with no limit check [6](#0-5) .
4. When the era advances to the deferred era, `start_era` triggers `apply_unapplied_slashes`, which drains and applies the entire accumulated `Vec` in one unweighted loop [7](#0-6) , performing `O(offenders × nominators_per_offender)` work synchronously with no bailout, risking stalled era progression.

	/// Start a new era. It does:
	/// * Increment `active_era.index`,
	/// * reset `active_era.start`,
	/// * update `BondedEras` and apply slashes.
	fn start_era(start_session: SessionIndex) {
		let active_era = ActiveEra::<T>::mutate(|active_era| {
			let new_index = active_era.as_ref().map(|info| info.index + 1).unwrap_or(0);
			*active_era = Some(ActiveEraInfo {
				index: new_index,
				// Set new active era start in next `on_finalize`. To guarantee usage of `Time`
				start: None,
			});
			new_index
		});

		let bonding_duration = T::BondingDuration::get();

		BondedEras::<T>::mutate(|bonded| {
			bonded.push((active_era, start_session));

			if active_era > bonding_duration {
				let first_kept = active_era.defensive_saturating_sub(bonding_duration);

				// Prune out everything that's from before the first-kept index.
				let n_to_prune =
					bonded.iter().take_while(|&&(era_idx, _)| era_idx < first_kept).count();

				// Kill slashing metadata.
				for (pruned_era, _) in bonded.drain(..n_to_prune) {
					slashing::clear_era_metadata::<T>(pruned_era);
				}

				if let Some(&(_, first_session)) = bonded.first() {
					T::SessionInterface::prune_historical_up_to(first_session);
				}
			}
		});

		Self::apply_unapplied_slashes(active_era);
	}

	/// Apply previously-unapplied slashes on the beginning of a new era, after a delay.
	fn apply_unapplied_slashes(active_era: EraIndex) {
		let era_slashes = UnappliedSlashes::<T>::take(&active_era);
		log!(
			debug,
			"found {} slashes scheduled to be executed in era {:?}",
			era_slashes.len(),
			active_era,
		);
		for slash in era_slashes {
			let slash_era = active_era.saturating_sub(T::SlashDeferDuration::get());
			slashing::apply_slash::<T>(slash, slash_era);
		}
	}
