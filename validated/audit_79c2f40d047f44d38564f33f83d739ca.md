### Title
Unauthenticated `RecvError` packet allows a spoofing attacker to force teardown of an established tunnel without holding a CA-signed certificate - ([File: outside.go])

### Summary
Nebula's `RecvError` control message is processed entirely before any Noise handshake or per-session cryptographic check. `handleRecvError` in `outside.go` trusts the packet's `RemoteIndex` field and the observed UDP source address alone to identify which tunnel to tear down, with no signature, no replay protection, and no requirement that the sender ever completed a handshake or holds a CA-signed certificate.

### Finding Description
`readOutsidePackets` dispatches `header.RecvError` to `f.handleRecvError(via.UdpAddr, h)` immediately after header parsing, before any per-session `ConnectionState` lookup, decryption, or replay-window check is performed: [1](#0-0) 

`handleRecvError` then:
1. Checks only a coarse endpoint-class policy (`always`/`never`/`private`) via `acceptRecvErrorConfig.ShouldRecvError(addr)` — no cryptographic authentication.
2. Looks up the hostinfo purely by the attacker-supplied `RemoteIndex`.
3. Compares the *currently known* remote address (`hr`) to the packet's *observed* source address (`addr`), which for UDP is fully attacker-controllable via source-IP spoofing on many network paths (no port/address binding proof exists for this packet type).
4. If they match, it unconditionally calls `f.closeTunnel(hostinfo)` and `f.handshakeManager.DeleteHostInfo(hostinfo)`. [2](#0-1) 

This mirrors the structural flaw in the H-13 report: a state-changing action (`withdrawCredit`) is permitted using pre-existing, stale trust state (`indicies[index]`) without re-validating the actor's standing against the event that should gate it (the incident/`applyCover`). Here, an entity that never authenticated via the CA-signed certificate/Noise handshake (i.e., holds no valid credential) is nonetheless able to force a state transition — tunnel teardown — on an already-established, mutually-authenticated session, purely by supplying a guessed/observed `RemoteIndex` and a spoofed source address. The check that exists (`hr != addr`) is the only gate, and it is trivially satisfiable by an off-path or on-path attacker who can spoof UDP source addresses, since RecvError is unauthenticated by design (it precedes `ConnectionState.Decrypt` and the replay window in `bits.go`/`connection_state.go`).

### Impact Explanation
An attacker with no CA-signed certificate can:
- Force disconnection of an active, fully-authenticated tunnel between two legitimate peers by sending a single crafted `RecvError` packet with a known/observed `localIndexId` and a spoofed source address matching the victim's current remote endpoint.
- Repeatedly evict/poison hostmap and handshake-manager state (`closeTunnel` + `DeleteHostInfo`), degrading availability and enabling downgrade attacks (forcing repeated re-handshakes that could be raced by an active on-path attacker).

This is a remote state-poisoning / firewall-adjacent authentication bypass reachable without possessing any valid certificate, consistent with the "no CA-signed certificate" attacker model required by the rules.

### Likelihood Explanation
Exploitability depends on the attacker learning or guessing a valid `RemoteIndex` (32-bit, populated via `generateIndex`) for a live tunnel and being able to spoof the peer's UDP source address (feasible on networks without egress/ingress source filtering, or fully on-path). This is a real but non-trivial precondition — it is not a "malicious peer/lighthouse" or "valid-certificate-holder" scenario, since the attacker never needs to complete or hold a handshake credential; it is a purely header/address-driven bypass.

### Recommendation
- Do not act on `RecvError` using only source-address comparison; require it to be cryptographically bound to the session (e.g., authenticate with a MAC keyed off the session's derived key, or require it be piggybacked on an authenticated packet).
- Rate-limit and log-only by default for `RecvError`-triggered teardown paths, or require corroborating evidence (e.g., N consecutive UDP errors within a short window) before tearing down an active `ConnectionState`.
- Consider gating `RecvError` handling behind the connection's established replay window/counter so an attacker must already possess valid traffic-layer keys.

### Proof of Concept
1. Establish `me <-> them` tunnel; observe/learn `them`'s `localIndexId` (the value nebula would place in `RemoteIndex` on packets sent to `me`) — e.g., via traffic analysis or a prior on-path position.
2. From attacker-controlled network access, craft a UDP packet with header `Type=RecvError`, `RemoteIndex=<learned index>`, and source address spoofed to match `them`'s known UDP endpoint, sent to `me`.
3. `me.handleRecvError` finds the hostinfo by index, sees `hr == addr` (spoofed match), and calls `closeTunnel` + `DeleteHostInfo` on the legitimate, fully-authenticated tunnel — despite the attacker never having completed a handshake or presented a CA-signed certificate.

**Uncertainty note:** I was not able to fully verify within the available tool budget whether `RemoteIndex` values are exposed anywhere in cleartext traffic that would make guessing/learning them trivial for a fully off-path attacker (this would raise likelihood further), nor whether any additional rate-limiting/mitigation exists elsewhere in the UDP receive path that I did not locate. This should be confirmed by a maintainer or via a live Devin session before treating this as a confirmed, high-likelihood finding.

func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
