### Title
`go tool objdump -S` discloses arbitrary local `.go` file contents via attacker-controlled `//line` filename with no path/traversal restriction - ([File: src/cmd/internal/disasm/disasm.go])

### Summary
`FileCache.Line` in `cmd/internal/disasm/disasm.go` reads and prints the source line corresponding to each disassembled instruction when `objdump -S` (or `pprof`, which reuses the same package) is used. The filename passed to `Line` comes straight from the binary's embedded pcln/DWARF line-number table, which the compiler populates verbatim from `//line` directives found in the compiled source. Like the PostCSS `loadFile` regression, the only gate applied to this attacker-influenced path is an extension check (`.go` here vs `.map` there); there is no check that the resolved path stays under the expected source tree, so an absolute or `../`-escaping path is read and its content is disclosed into the disassembly output.

### Finding Description
Attacker input: a Go source file distributed to a victim (e.g., via a module or repo) containing a line such as `//line /home/victim/.ssh/some_private.go:1`. When compiled, the compiler's line-directive handling resolves this into the pcln/DWARF line table verbatim for absolute paths [1](#0-0)  (relative paths are anchored to the directive's own directory, but absolute paths pass through unmodified, matching the compiler doc's stated semantics [2](#0-1) ). This filename is embedded into the produced binary's line-number table via `Link.generateDebugLinesSymbol`/`populateDWARF` [3](#0-2) .

When the victim later runs `go tool objdump -S <binary>` to inspect the built binary, `objdump`'s `main` calls `disasm.DisasmForFile` and `Disasm.Print` [4](#0-3) . `Print`, for each instruction, retrieves `file, line` from the pcln table and calls `fc.Line(file, line)` to fetch and print the corresponding source line [5](#0-4) .

`FileCache.Line` only checks that the filename ends in `.go`, then calls `os.ReadFile(filename)` directly with no check for `..` traversal or that the path is anchored under any expected base/module directory: [6](#0-5) . This mirrors the PostCSS bug precisely: an extension allow-list (`.map` there, `.go` here) is the *only* defense, and the "is this path allowed to escape the known base" check (present when `cssFile`/a base is known) is entirely absent for the untrusted, attacker-supplied filename embedded in the artifact.

### Impact Explanation
Running `go tool objdump -S` on a binary built from attacker-supplied source causes the tool to read and print the contents of an arbitrary `.go` file chosen by the attacker (any absolute path ending in `.go`, or a `../`-escaping relative one), disclosing its contents in the disassembly output. This is analogous to the PostCSS cross-project `sourcesContent`/`sources` disclosure: a malicious dependency/source file makes a downstream analysis tool (disassembler in this case, source-map consumer in PostCSS's case) leak unrelated local files. The primitive is bounded to files ending in `.go`, which limits (but does not eliminate) the blast radius compared to PostCSS's unrestricted `.map` read — an attacker can still target other `.go` files on the victim's disk (private/unpublished source trees, vendored code, etc.) for disclosure. This would likely be assessed on Go's PUBLIC track as a low/medium-severity information-disclosure bug in a diagnostic tool, not a build-time or execution-time compromise.

### Likelihood Explanation
The victim workflow is realistic: a developer builds an untrusted or third-party Go program/module (compilation of malicious source, without execution, is explicitly allowed per Go's threat model) and then uses `go tool objdump -S` (or a tool built on `cmd/internal/disasm`, such as `cmd/pprof`) to inspect the generated binary for debugging/performance analysis — a common workflow for analyzing suspicious or unfamiliar binaries. No special privileges are required by the attacker beyond supplying the source file with a crafted `//line` directive.

### Recommendation
In `FileCache.Line` (`src/cmd/internal/disasm/disasm.go`), before calling `os.ReadFile`, validate that the resolved filename does not escape an expected base directory (e.g., reject absolute paths and `..`-escaping relative paths for files not already known-trusted, similar to `net/http.containsDotDot`/`ServeFile`'s explicit `..` rejection [7](#0-6) ), or refuse to load source annotations for files whose recorded path was set via a `//line` directive pointing outside the object's own module/build directory.

### Proof of Concept
```go
package disasm

import (
	"os"
	"path/filepath"
	"testing"
)

// Simulates the sink in FileCache.Line being fed an attacker-controlled
// filename embedded via a //line directive and read into the pcln table.
func TestFileCacheLine_ArbitraryFileRead(t *testing.T) {
	dir := t.TempDir()
	secret := filepath.Join(dir, "secret.go")
	if err := os.WriteFile(secret, []byte("package secret // TOP_SECRET_abcdef\n"), 0o644); err != nil {
		t.Fatal(err)
	}

	fc := NewFileCache(8)
	// "filename" here stands in for the attacker-controlled //line-directive
	// path embedded verbatim into the binary's pcln/DWARF table.
	got, err := fc.Line(secret, 1)
	if err != nil {
		t.Fatalf("unexpected error: %v", err)
	}
	if got == nil {
		t.Fatal("expected content, got nil")
	}
	if string(got) != "package secret // TOP_SECRET_abcdef" {
		t.Fatalf("expected disclosed secret content, got: %q", got)
	}
	// No check ever rejects `secret` for being outside any base directory
	// of the compiled program — only the ".go" extension is enforced.
}
```
Expected assertion: the test passes, demonstrating that any `.go` file on disk reachable by an absolute or traversal path is read and returned verbatim by `FileCache.Line`, with the path originating end-to-end from an attacker-controlled `//line` directive that reaches this sink via `go tool objdump -S`.

func (fc *FileCache) Line(filename string, line int) ([]byte, error) {
	if filepath.Ext(filename) != ".go" {
		return nil, nil
	}

	// Clean filenames returned by src.Pos.SymFilename()
	// or src.PosBase.SymFilename() removing
	// the leading src.FileSymPrefix.
	filename = strings.TrimPrefix(filename, src.FileSymPrefix)

	// Expand literal "$GOROOT" rewritten by obj.AbsFile()
	filename = filepath.Clean(os.ExpandEnv(filename))

	var cf *CachedFile
	var e *list.Element

	for e = fc.files.Front(); e != nil; e = e.Next() {
		cf = e.Value.(*CachedFile)
		if cf.FileName == filename {
			break
		}
	}

	if e == nil {
		content, err := os.ReadFile(filename)
		if err != nil {
			return nil, err
		}
