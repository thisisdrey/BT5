### Title
Shareholder Opting Out of Direct Coin Transfers Permanently Blocks All Vesting Distributions — (`aptos-move/framework/aptos-framework/sources/vesting.move`)

---

### Summary

`vesting::distribute()` uses a push-payment loop that calls `aptos_account::deposit_coins<AptosCoin>()` for every shareholder in sequence. If any single recipient's deposit aborts — which any shareholder can trigger unprivileged by calling `set_allow_direct_coin_transfers(false)` — the entire transaction reverts. All other shareholders are permanently blocked from receiving their vested APT, mirroring the BoxExchange push-payment griefing pattern exactly.

---

### Finding Description

`vesting::distribute()` iterates over every shareholder and pushes coins to each one atomically:

```move
shareholders.for_each_ref(|shareholder| {
    let shareholder = *shareholder;
    let shares = pool_u64::shares(grant_pool, shareholder);
    let amount = pool_u64::shares_to_amount_with_total_coins(...);
    let share_of_coins = coin::extract(&mut coins, amount);
    let recipient_address = get_beneficiary(vesting_contract, shareholder);
    aptos_account::deposit_coins(recipient_address, share_of_coins);  // ← can abort
});
``` [1](#0-0) 

`aptos_account::deposit_coins<CoinType>` aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` when the recipient account exists, has not registered the legacy `CoinStore<AptosCoin>`, and has explicitly set `allow_arbitrary_coin_transfers = false`:

```move
if (!coin::is_account_registered<CoinType>(to)) {
    assert!(
        can_receive_direct_coin_transfers(to),
        error::permission_denied(EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS)
    );
    coin::register<CoinType>(&create_signer(to));
};
coin::deposit<CoinType>(to, coins)
``` [2](#0-1) 

`create_account` only creates the primary fungible store for APT (FA path) via `register_apt`; it does **not** register the legacy `CoinStore<AptosCoin>`. So any shareholder whose account was created this way and who subsequently calls `set_allow_direct_coin_transfers(false)` will have `coin::is_account_registered<AptosCoin>` return `false` and `can_receive_direct_coin_transfers` return `false`, causing `deposit_coins` to abort. [3](#0-2) 

The developers themselves acknowledged this exact risk in the `set_beneficiary` function comment:

```move
// Verify that the beneficiary account is set up to receive APT. This is a requirement so distribute() wouldn't
// fail and block all other accounts from receiving APT if one beneficiary is not registered.
assert_account_is_registered_for_apt(new_beneficiary);
``` [4](#0-3) 

However, this guard only applies when an admin sets a **beneficiary**. There is no equivalent check on the **shareholder's own address** at contract creation time or at distribution time. A shareholder with no beneficiary set is paid directly, and that path is unguarded.

The same push-loop pattern exists in `staking_contract::distribute_internal`, which also calls `aptos_account::deposit_coins` in a `while` loop over all distribution pool recipients: [5](#0-4) 

---

### Impact Explanation

Any shareholder in a vesting contract can permanently freeze the `distribute()` entry point for the entire contract by calling the unprivileged `set_allow_direct_coin_transfers(false)` transaction on their own account (and ensuring they have not registered the legacy `CoinStore<AptosCoin>`). Once triggered:

- Every subsequent call to `vesting::distribute()` or `vesting::distribute_many()` aborts.
- All other shareholders are permanently unable to receive their vested APT rewards or principal.
- `terminate_vesting_contract` also calls `distribute()` internally, so contract termination is also blocked.
- The APT remains locked in the vesting contract's stake pool indefinitely.

This constitutes **permanent freezing of other users' on-chain APT balances** — a direct in-scope impact. [6](#0-5) 

---

### Likelihood Explanation

- The trigger is a single unprivileged transaction (`aptos_account::set_allow_direct_coin_transfers(false)`) callable by any account holder at any time after being added as a shareholder.
- No admin cooperation or special privilege is required.
- The attack is irreversible: once the shareholder opts out, `distribute()` will always abort unless the admin sets a beneficiary for that shareholder — but `set_beneficiary` requires the new beneficiary to be registered for APT, which the attacker controls.
- A malicious shareholder in any multi-party vesting contract can execute this to grief all co-shareholders. [7](#0-6) 

---

### Recommendation

Replace the push-payment loop with a pull pattern:

1. In `distribute()`, instead of pushing coins to each shareholder immediately, record each shareholder's claimable balance in a `Table<address, u64>` or similar mapping stored on the vesting contract.
2. Add a separate `claim(contract_address: address)` entry function that lets each shareholder pull their own balance.
3. Alternatively, wrap each individual `deposit_coins` call in a way that skips failed deposits and accumulates unclaimed balances, similar to the fix described in the original report.

This matches the pattern already acknowledged by the developers in the `set_beneficiary` comment — the invariant "distribute() must not fail due to a single recipient" is known but not enforced on the shareholder-direct path.

---

### Proof of Concept

1. Admin creates a vesting contract with two shareholders: `alice` (honest) and `bob` (attacker), each with 50% shares.
2. `bob` calls `aptos_account::set_allow_direct_coin_transfers(false)` — a standard unprivileged transaction.
3. `bob` ensures he has never called `coin::register<AptosCoin>()` (the legacy store is absent; only the FA primary store exists from account creation).
4. After the staking lockup expires, anyone calls `vesting::distribute(contract_address)`.
5. The loop reaches `bob`'s entry: `coin::is_account_registered<AptosCoin>(bob)` → `false`; `can_receive_direct_coin_transfers(bob)` → `false`; `assert!` fires → transaction aborts.
6. `alice` receives nothing. The entire APT balance remains locked in the stake pool.
7. Every future call to `distribute()` produces the same abort. `terminate_vesting_contract` also aborts (it calls `distribute()` first). `alice`'s funds are permanently frozen. [8](#0-7) [9](#0-8)

    /// Distribute any withdrawable stake from the stake pool.
    public entry fun distribute(contract_address: address) acquires VestingContract {
        assert_active_vesting_contract(contract_address);

        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        let coins = withdraw_stake(vesting_contract, contract_address);
        let total_distribution_amount = coin::value(&coins);
        if (total_distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };

        // Distribute coins to all shareholders in the vesting contract.
        let grant_pool = &vesting_contract.grant_pool;
        let shareholders = &grant_pool.shareholders();
        shareholders.for_each_ref(|shareholder| {
            let shareholder = *shareholder;
            let shares = pool_u64::shares(grant_pool, shareholder);
            let amount = pool_u64::shares_to_amount_with_total_coins(grant_pool, shares, total_distribution_amount);
            let share_of_coins = coin::extract(&mut coins, amount);
            let recipient_address = get_beneficiary(vesting_contract, shareholder);
            aptos_account::deposit_coins(recipient_address, share_of_coins);
        });

        // Send any remaining "dust" (leftover due to rounding error) to the withdrawal address.
        if (coin::value(&coins) > 0) {
            aptos_account::deposit_coins(vesting_contract.withdrawal_address, coins);
        } else {
            coin::destroy_zero(coins);
        };

        emit(
            Distribute {
                admin: vesting_contract.admin,
                vesting_contract_address: contract_address,
                amount: total_distribution_amount,
            },
        );
    }

    public entry fun set_allow_direct_coin_transfers(
        account: &signer, allow: bool
    ) acquires DirectTransferConfig {
        let addr = signer::address_of(account);
        if (exists<DirectTransferConfig>(addr)) {
            let direct_transfer_config = borrow_global_mut<DirectTransferConfig>(addr);
            // Short-circuit to avoid emitting an event if direct transfer config is not changing.
            if (direct_transfer_config.allow_arbitrary_coin_transfers == allow) { return };

            direct_transfer_config.allow_arbitrary_coin_transfers = allow;

            emit(
                DirectCoinTransferConfigUpdated {
                    account: addr,
                    new_allow_direct_transfers: allow
                }
            );
        } else {
            let direct_transfer_config = DirectTransferConfig {
                allow_arbitrary_coin_transfers: allow,
                update_coin_transfer_events: new_event_handle<
                    DirectCoinTransferConfigUpdatedEvent>(account)
            };
            emit(
                DirectCoinTransferConfigUpdated {
                    account: addr,
                    new_allow_direct_transfers: allow
                }
            );
            move_to(account, direct_transfer_config);
        };
    }
