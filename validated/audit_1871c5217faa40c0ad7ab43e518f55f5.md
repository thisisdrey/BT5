### Title
Access-key deletion/recreation resets nonce below previously-consumed values, enabling transaction replay and double-spend - (File: `runtime/runtime/src/access_keys.rs`)

### Summary
`add_regular_key` unconditionally sets a re-created access key's nonce to `initial_nonce_value(block_height) = (block_height - 1) * ACCESS_KEY_NONCE_RANGE_MULTIPLIER`, with no check against the nonce the key had (or any nonce ever consumed under that public key) before being deleted. Because a transaction signed at height `H0` can carry a nonce up to `H0 * M - 1`, deleting and re-adding the same key at the same height resets its stored nonce to `(H0-1) * M`, which is strictly lower than any nonce already spent at `H0`. This lets the account holder replay an already-applied, byte-identical transaction later in the `transaction_validity_period` window, because `verify_nonce`/`verify_and_charge_tx_ephemeral` only compare the tx nonce against the access key's *current* stored nonce, not against transaction execution history.

### Finding Description
`initial_nonce_value` computes the nonce assigned to a (re)created access key purely from the current `block_height`, with the sole documented purpose of avoiding tx-hash collisions (per the referenced issue #3779): [1](#0-0) 

`add_regular_key` applies this value directly to any key added via `AddKeyAction`, including a key that is being re-added under the same public key immediately after a `DeleteKeyAction` in the same or an earlier action within the same receipt/transaction: [2](#0-1) 

Nonce admission is checked only against the height-derived upper bound and the access key's *current* stored nonce (or `pending.max_nonce`), never against a persisted high-water-mark independent of the key's own storage row: [3](#0-2) [4](#0-3) 

On a successful verification, the access key's nonce field is updated to the just-used `tx_nonce`: [5](#0-4) 

Exploit flow:
1. At height `H0`, the attacker (an ordinary account with two access keys `K` full-access and `K2`) submits `tx1 = Transfer(deposit)` signed by `K` with `nonce = N = H0*M - 1` (the maximum admissible nonce at `H0`, since `verify_nonce`'s upper-bound check requires `tx_nonce < H0*M`). This applies successfully and `K`'s stored nonce becomes `N`.
2. In the same chunk at `H0`, the attacker submits `tx2 = [DeleteKey(K), AddKey(K, same permission)]` signed by `K2`. `action_delete_key` removes `K`'s storage row entirely; the subsequent `action_add_key`→`add_regular_key` call recreates `K` with `nonce = initial_nonce_value(H0) = (H0-1)*M`, which is far below `N` (difference of `M`, e.g. ~1,000,000).
3. Later, at height `H1 > H0` (still inside `transaction_validity_period`), the attacker resubmits the byte-identical `tx1` (same nonce `N`, same signature, same `block_hash`). `verify_nonce` checks `N > effective_nonce = (H0-1)*M` — true — and `N < H1*M` — true. Signature verification also succeeds since `K`'s public key is unchanged. The transfer is re-applied, crediting the receiver a second time from a single signed message.

No existing check catches this: signature verification only validates the cryptographic signature/public key match, not "has this exact nonce ever been consumed by this pubkey before deletion"; nonce checking is scoped to the access key's live trie row, which is wiped and reset by ordinary `DeleteKey`/`AddKey` actions available to any unprivileged account.

### Impact Explanation
This breaks the fundamental value-conservation/replay-protection invariant: a single signed transaction executes twice, double-crediting the receiver (and double-debiting the signer, but the signer is the attacker and may have replayed a transfer directed to a controlled receiver or exploited a counterparty relying on execute-once semantics for a specific signed payload/nonce). This matches NEAR's "double-spend/replay" bounty category.

### Likelihood Explanation
Preconditions are trivial and fully within an unprivileged user's control: an account with two access keys, standard `Transfer`, `DeleteKey`, and `AddKey` actions, and knowledge of `ACCESS_KEY_NONCE_RANGE_MULTIPLIER`. No validator, node-operator, or special access is required. The attack is deterministic and repeatable (the recreated key can be deleted/re-added again to open further replay windows), bounded only by `transaction_validity_period` for how late the replay can be submitted, which is generous (on the order of a day of blocks).

### Recommendation
When recreating an access key under a public key that previously existed on the account (or generally on `AddKeyAction`), never allow the new nonce to regress below the highest nonce ever observed for that public key. Options: persist a per-account/per-pubkey high-water-mark nonce that survives `DeleteKey`, and take `max(initial_nonce_value(block_height), last_known_nonce_for_pubkey + 1)` when setting the nonce in `add_regular_key`/`add_gas_key`; alternatively, disallow reusing the exact same public key within `transaction_validity_period` of its own deletion.

### Proof of Concept
Runtime/apply integration test (`runtime/runtime/src/tests/apply.rs` style):
1. Create account `alice` with keys `K` (FullAccess) and `K2` (FullAccess), and `bob` as receiver, at height `H0`.
2. Apply `tx1 = Transfer{deposit}` signed by `K` with `nonce = H0*M - 1`, receiver `bob`. Assert `verify_and_charge_tx_ephemeral` returns `TxVerdict::Success`, apply it, and assert `bob`'s balance increased by exactly `deposit`.
3. In the same chunk/height `H0`, apply `tx2 = [DeleteKey(K), AddKey(K, FullAccess)]` signed by `K2`. Assert success, and read back `K`'s access key via `get_access_key` to confirm its nonce is now `(H0-1)*M`.
4. Advance to height `H1 = H0 + 10` (well within validity period). Re-verify the byte-identical `tx1` (same nonce, same signature bytes) against the current state/access key. Assert `verify_and_charge_tx_ephemeral` again returns `TxVerdict::Success` (not `Failed(InvalidNonce)`), apply it, and assert `bob`'s balance increased by a second `deposit` — proving double execution of a single signed transaction.

pub(crate) fn initial_nonce_value(block_height: BlockHeight) -> Nonce {
    // Set default nonce for newly created access key to avoid transaction hash collision.
    // See <https://github.com/near/nearcore/issues/3779>.
    (block_height - 1) * near_primitives::account::AccessKey::ACCESS_KEY_NONCE_RANGE_MULTIPLIER
}

fn add_regular_key(
    fee_config: &RuntimeFeesConfig,
    state_update: &mut TrieUpdate,
    account: &mut Account,
    account_id: &AccountId,
    public_key: &PublicKey,
    access_key: &AccessKey,
    block_height: BlockHeight,
) -> Result<(), StorageError> {
    let mut access_key = access_key.clone();
    access_key.nonce = initial_nonce_value(block_height);
    set_access_key(state_update, account_id.clone(), public_key.clone(), &access_key);

    account.set_storage_usage(
        account
            .storage_usage()
            .checked_add(access_key_storage_usage(fee_config, public_key, &access_key))
            .ok_or_else(|| {
                StorageError::StorageInconsistentState(format!(
                    "Storage usage integer overflow for account {}",
                    account_id
                ))
            })?,
    );
    Ok(())
}

/// Verify that the transaction nonce is valid.
fn verify_nonce(
    tx_nonce: Nonce,
    current_nonce: Nonce,
    block_height: Option<BlockHeight>,
    nonce_mode: NonceMode,
) -> Result<(), InvalidTxError> {
    match nonce_mode {
        NonceMode::Monotonic => {
            if tx_nonce <= current_nonce {
                return Err(InvalidTxError::InvalidNonce { tx_nonce, ak_nonce: current_nonce });
            }
        }
        NonceMode::Strict => {
            if !current_nonce.checked_add(1).is_some_and(|expected| tx_nonce == expected) {
                return Err(InvalidTxError::InvalidNonce { tx_nonce, ak_nonce: current_nonce });
            }
        }
    }
    if let Some(height) = block_height {
        let upper_bound = height
            .saturating_mul(near_primitives::account::AccessKey::ACCESS_KEY_NONCE_RANGE_MULTIPLIER);
        if tx_nonce >= upper_bound {
            return Err(InvalidTxError::NonceTooLarge { tx_nonce, upper_bound });
        }
    }
    Ok(())
}
