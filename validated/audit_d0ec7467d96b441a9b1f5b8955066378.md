### Title
Unbounded body read in signer event receiver enables single-connection DoS - (File: `libsigner/src/events.rs`)

### Finding Description
`process_event::<T, E>` reads the entire HTTP body of an incoming `/new_block`, `/stackerdb_chunks`, `/proposal_response`, or `/new_burn_block` POST with `request.as_reader().read_to_string(&mut body)` and applies no length cap before or during the read [1](#0-0) . The `MAX_MESSAGE_LEN`/`MAX_HTTP_HEADER_LEN` caps that exist in `libsigner/src/http.rs` are only exercised on the outbound RPC client path (`decode_http_body`, used by `run_http_request`) [2](#0-1) , not on the inbound `tiny_http`-driven event-receiver path in `events.rs`. `next_event` is fully synchronous: it calls `http_server.recv()` and processes exactly one request at a time inside `with_server`, and `main_loop` is a single, non-concurrent loop over `next_event` [3](#0-2) [4](#0-3) . Consequently one connection that sends a huge `Content-Length` header and then trickles bytes (or sends none) will cause `read_to_string` to block/allocate indefinitely on that single thread, starving every other pending event (block-proposal responses, new blocks, burn blocks, StackerDB chunks) since there is only one event-receiver thread per signer (`Signer::spawn` starts exactly one `event_receiver.main_loop()` thread) [5](#0-4) .

The signer's event-receiver `endpoint` is documented and shipped in sample configs as binding to all interfaces (`endpoint = "0.0.0.0:30000"`), and the receiver applies no authentication or source-IP check on incoming POSTs — the `auth_password`/`auth_token` pairing documented in `docs/signing.md` governs the *node's* block-proposal RPC endpoint, not this signer-side event listener [6](#0-5) [7](#0-6) . Nothing in `next_event`/`process_event` checks a shared secret or peer identity before invoking `read_to_string`, so any TCP client that can route to that port can trigger the unbounded read.

### Impact Explanation
An attacker who can reach the signer's bound event port can open a connection, send a POST to any of the recognized routes with an oversized `Content-Length` and a slow/absent body, and block the signer's sole event-receiver thread indefinitely. Because `main_loop` is single-threaded and synchronous, this stalls processing of all subsequent legitimate events (block proposals, validation responses, burn blocks, StackerDB chunks) for that signer, effectively taking the signer offline for signing purposes without sending it a single valid, well-formed message. This is repeatable per new connection and requires no privileged role, matching the Critical "remote crash/unauthenticated DoS from few messages" category (denial of signing service on the affected signer).

### Likelihood Explanation
Preconditions: the signer's event-receiver port must be network-reachable to the attacker, which is exactly how the shipped reference configs (`sample/conf/signer/mainnet-signer-conf.toml`, endpoint `0.0.0.0:30000`) are documented, so operators following the docs verbatim expose this port. Attacker cost is trivial — a single TCP connection with a crafted `Content-Length` header and a trickle of bytes (or none) — no cryptographic material, no valid StackerDB slot, and no node RPC secret are required. It is fully repeatable on demand.

### Recommendation
Impose an explicit byte cap (e.g., `MAX_MESSAGE_LEN` or a dedicated event-body limit) before calling `read_to_string`/`read_to_end`, by wrapping `request.as_reader()` in a `Read::take(cap)` and rejecting bodies whose declared `Content-Length` exceeds the cap up front; also apply a read timeout so a stalled body cannot block the receiver thread indefinitely, and consider handling requests off the single accept-loop thread (e.g., a bounded worker pool) so a slow/oversized request cannot starve unrelated event types.

### Proof of Concept
Rust test plan (net test, mirroring style of `stacks-node/src/event_dispatcher/tests.rs`):
1. Instantiate `SignerEventReceiver::<StacksBlockEvent>::new(false)`, call `bind()` on `127.0.0.1:<port>`, and spawn `main_loop()` in a thread with a consumer channel attached via `add_consumer`.
2. From a separate thread acting as the attacker, open a raw `TcpStream` to the bound port and send:
   `POST /new_block HTTP/1.1\r\nHost: 127.0.0.1:<port>\r\nContent-Length: 4294967295\r\nContent-Type: application/json\r\n\r\n` followed by only a handful of bytes, then sleep/never send the rest.
3. From the main test thread, immediately after, send a second, legitimate, well-formed `/status` request (or a minimal valid event) to the same port on a new connection.
4. Assert that the legitimate request's response/consumer-channel message is not received within a short timeout (e.g., `rx.recv_timeout(Duration::from_secs(2))` returns `Err`), demonstrating that the receiver thread is blocked inside `process_event`'s `read_to_string` call in `libsigner/src/events.rs:526` and cannot service subsequent events — the assertion should fail once a size cap/timeout is added to `process_event`.

    fn next_event(&mut self) -> Result<SignerEvent<T>, EventError> {
        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)
            } else if request.url() == "/new_block" {
                process_event::<T, StacksBlockEvent>(request)
            } else {
                let url = request.url().to_string();
                debug!(
                    "[{:?}] next_event got request with unexpected url {}, return OK so other side doesn't keep sending this",
                    event_receiver.local_addr,
                    url
                );
                ack_dispatcher(request);
                Err(EventError::UnrecognizedEvent(url))
            }
        })?
    }

/// Decode an HTTP body, given the headers.
pub fn decode_http_body(headers: &HashMap<String, String>, mut buf: &[u8]) -> io::Result<Vec<u8>> {
    let chunked = if let Some(val) = headers.get("transfer-encoding") {
        val == "chunked"
    } else {
        false
    };

    let body = if chunked {
        // chunked encoding
        let ptr = &mut buf;
        let mut fd = HttpChunkedTransferReader::from_reader(ptr, MAX_MESSAGE_LEN.into());
        let mut decoded_body = vec![];
        fd.read_to_end(&mut decoded_body)?;
        decoded_body
    } else {
        // body is just as-is
        buf.to_vec()
    };

    Ok(body)
}
