### Title
Unauthenticated `POST /shutdown` permanently kills the signer event-receiver loop - ([File: libsigner/src/events.rs])

### Summary
The signer's HTTP event-receiver dispatches on `request.url()` inside `SignerEventReceiver::next_event` without any authentication check. Any remote party that can reach the bound event-receiver address can send a single unauthenticated `POST /shutdown` request and permanently terminate the receiver's `main_loop`, disabling the signer's ability to receive block proposals, StackerDB chunks, and burn-block events until the process is restarted.

### Finding Description
`next_event` routes based solely on the request path/method, with no secret, token, or peer check: [1](#0-0) 

The `/shutdown` branch unconditionally sets `event_receiver.stop_signal.store(true, Ordering::SeqCst)` and returns `Err(EventError::Terminated)` as soon as it sees `POST /shutdown`, regardless of the request body or sender identity — the same mechanism `SignerStopSignaler::send` itself uses to wake the thread: [2](#0-1) 

`main_loop` treats `EventError::Terminated` as a clean exit and `break`s out of the loop entirely: [3](#0-2) 

There is no comparison against a secret, no source-IP allowlist, and no restart of `main_loop` after this branch — once the loop exits, the event-receiver thread is gone for the lifetime of the process. Any attacker who can open a TCP connection to the bound `local_addr` and send `POST /shutdown HTTP/1.1\r\n...\r\n\r\n<body>` achieves exactly what the legitimate internal stop signal achieves.

### Impact Explanation
A single unauthenticated HTTP request from any reachable remote party stops the signer's event ingestion thread permanently (`main_loop` exits and is never restarted from within this code path). This is a repeatable, one-message denial of service against the signer node: the signer no longer receives `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, or `/new_block` events, silencing it from block-signing duties until an operator manually restarts the signer process. This matches "Critical - remote crash/unauthenticated DoS from few messages."

### Likelihood Explanation
The only precondition is that the attacker can open a TCP connection to the signer's event-receiver bind address and send bytes — no secret, peer identity, or StackerDB slot ownership is required. The attack is a single, trivially crafted HTTP request, fully repeatable against any signer whose event-receiver socket is reachable from the attacker's network position.

### Recommendation
Require an authentication check (e.g., matching the internally-known stop token/secret, or restricting `/shutdown` to loopback-only connections) before honoring the `/shutdown` path in `next_event`, rather than trusting any inbound `POST /shutdown`.

### Proof of Concept
Rust test plan (net test):
1. Instantiate `SignerEventReceiver::<T>::new(false)` and call `bind(addr)` to get `local_addr`.
2. Spawn `main_loop()` in a thread.
3. From a separate `TcpStream`, connect to `local_addr` and send raw bytes: `"POST /shutdown HTTP/1.1\r\nHost: {addr}\r\nConnection: close\r\nContent-Length: 4\r\nContent-Type: text/plain\r\n\r\ntest"`.
4. Assert that the spawned thread exits (`join()` returns) shortly after, and that a subsequent legitimate `POST /stackerdb_chunks` request to the same address is never processed (connection refused/ignored), confirming the receiver is dead — reproducing the exact `Err(EventError::Terminated) => break` path at `libsigner/src/events.rs:296-299` triggered from the `/shutdown` branch at `libsigner/src/events.rs:443-445`.
