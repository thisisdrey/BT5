## Title
Block/transaction-fee rewards paid to a witness with zero votes are permanently lost - (File: `chainbase/src/main/java/org/tron/core/service/MortgageService.java`, `chainbase/src/main/java/org/tron/core/store/DelegationStore.java`)

### Summary
`MortgageService.payReward` credits block-production and transaction-fee rewards to a witness's per-cycle reward bucket in `DelegationStore` unconditionally, without checking whether that witness currently has any voters (analogous to `InfraredVault.notifyRewardAmount` distributing rewards regardless of whether there are stakers). When the maintenance cycle later tries to convert that reward bucket into the "value-per-vote" (`Vi`) index that voters use to claim their share, `DelegationStore.accumulateWitnessVi` silently discards the reward if the witness's vote count for that cycle is zero, with no fallback mechanism to reclaim or redistribute it.

### Finding Description
Every time a witness produces a block or receives a transaction-fee share, `Manager.payReward` invokes `mortgageService.payBlockReward` / `payTransactionFeeReward`, both of which call the private `payReward` helper: [1](#0-0) 

This unconditionally adds `value` (minus brokerage) into `delegationStore.addReward(cycle, witnessAddress, value)` for the *current* cycle, regardless of whether any voter is delegating to this witness in that cycle.

At the next maintenance cycle, `MaintenanceManager.doMaintenance()` converts each witness's accumulated cycle reward into a delta of the "value-per-vote" index (`Vi`), which is the sole mechanism voters use to compute their claimable share: [2](#0-1) 

The conversion logic in `DelegationStore.accumulateWitnessVi` (and its duplicate in `RewardViCalService.accumulateWitnessVi`) explicitly skips the delta calculation whenever `voteCount == 0`, even if a non-zero `reward` was recorded for that cycle: [3](#0-2) 

Because the `Vi` delta is never recorded, no voter can ever redeem that reward: `MortgageService.computeReward`/`getOldReward` derive rewards strictly from `Vi` deltas (new algorithm) or from `totalVote`-weighted shares that are similarly skipped when `totalVote == 0`: [4](#0-3) 

A witness can have zero votes while still being an actively producing SR: any unprivileged account can broadcast `VoteWitnessContract` transactions to withdraw all votes from a witness mid-cycle (the witness remains in the active/standby set until the next election at maintenance, per `MaintenanceManager.updateWitnessValue`/`doMaintenance`). During that window the witness keeps earning `payBlockReward`/`payTransactionFeeReward`/`payStandbyWitness` credits into `DelegationStore`, but because `voteCount` for that cycle is 0 at the time `accumulateWitnessVi` runs, the accrued TRX reward bucket is silently orphaned — it is never converted into a claimable index delta, never refunded to any pool, and remains permanently inaccessible in the `DelegationStore`.

### Impact Explanation
This is a permanent freezing/loss-of-funds bug: TRX rewards that were paid out of the block-reward and transaction-fee pools (real, previously-circulating value) become unclaimable and effectively burned whenever a witness earns rewards in a cycle where it has zero recorded votes. This matches the "High/Medium" impact classification in the referenced report — reward tokens minted/allocated for a period are lost because there is no stakeholder (voter) mechanism reachable to claim them, and no governance/sweep function exists to recover them.

### Likelihood Explanation
Low-to-Medium: it requires that a witness be actively producing blocks (i.e., already elected into the active or standby set) while having zero recorded votes for the reward cycle, which can be triggered by an ordinary account casting/withdrawing votes (`VoteWitnessContract`) around cycle boundaries. This is more likely for newly bootstrapped or edge/standby witnesses whose voters withdraw support during a cycle, and is entirely reachable by a normal, unprivileged transaction broadcaster who can time vote withdrawals — no privileged role is needed to trigger the condition, only to be an SR receiving the rewards.

### Recommendation
When `accumulateWitnessVi` (in both `DelegationStore` and `RewardViCalService`) encounters `voteCount == 0` but `reward > 0`, do not silently drop the reward. Instead, either (a) roll the un-distributable reward forward into the next cycle's reward bucket for the same witness so it can be captured once votes exist again, or (b) return it to a recoverable pool (e.g., the transaction fee pool or a burn-tracked treasury) rather than leaving it stranded in per-cycle storage with no consumer.

### Proof of Concept
1. A witness `W` is elected into the active/standby witness set (has produced blocks, receiving `payBlockReward`/`payTransactionFeeReward`).
2. All accounts holding votes for `W` broadcast `VoteWitnessContract` transactions removing their votes from `W` mid-cycle (via `VoteWitnessActuator.countVoteAccount`), while `W` remains an active SR until the next `doMaintenance()` re-election.
3. `W` continues producing blocks; `Manager.payReward` keeps calling `mortgageService.payBlockReward`/`payTransactionFeeReward`, incrementing `delegationStore.addReward(currentCycle, W, value)`.
4. At the next maintenance cycle, `MaintenanceManager.doMaintenance()` calls `delegationStore.accumulateWitnessVi(curCycle, W, witness.getVoteCount())` with `voteCount == 0` (no voters left for `W` in that cycle snapshot).
5. Because `voteCount == 0`, the `else` branch computing `deltaVi` never executes; the previous `Vi` is simply forwarded, meaning the reward accumulated in step 3 has no corresponding `Vi` delta and can never be claimed by any account via `MortgageService.withdrawReward`/`queryReward`. [5](#0-4)

```java
  private long computeReward(long cycle, List<Pair<byte[], Long>> votes) {
    long reward = 0;
    for (Pair<byte[], Long> vote : votes) {
      byte[] srAddress = vote.getKey();
      long totalReward = delegationStore.getReward(cycle, srAddress);
      if (totalReward <= 0) {
        continue;
      }
      long totalVote = delegationStore.getWitnessVote(cycle, srAddress);
      if (totalVote == DelegationStore.REMARK || totalVote == 0) {
        continue;
      }
      long userVote = vote.getValue();
      double voteRate = (double) userVote / totalVote;
      reward += voteRate * totalReward;
    }
    return reward;
  }
```

```java
  public void accumulateWitnessVi(long cycle, byte[] address, long voteCount) {
    BigInteger preVi = getWitnessVi(cycle - 1, address);
    long reward = getReward(cycle, address);
    if (reward == 0 || voteCount == 0) { // Just forward pre vi
      if (!BigInteger.ZERO.equals(preVi)) { // Zero vi will not be record
        setWitnessVi(cycle, address, preVi);
      }
    } else { // Accumulate delta vi
      BigInteger deltaVi = BigInteger.valueOf(reward)
          .multiply(DECIMAL_OF_VI_REWARD)
          .divide(BigInteger.valueOf(voteCount));
      setWitnessVi(cycle, address, preVi.add(deltaVi));
    }
  }
```
