### Title
Pending `old_operator` commission bypasses beneficiary redirect after `switch_operator` — (`aptos-move/framework/aptos-framework/sources/staking_contract.move`)

---

### Summary

`switch_operator` calls `request_commission_internal(old_operator, ...)` which records `old_operator` as a shareholder in the `distribution_pool` for the pending (still-locked) commission. The staking contract is then re-keyed under `new_operator`. When `distribute(staker, new_operator)` is later called, `distribute_internal` receives `operator = new_operator`. The beneficiary-redirect guard `if (recipient == operator)` compares `old_operator == new_operator`, which is always `false`, so `old_operator` receives the commission directly instead of `beneficiary_for_operator(old_operator)`.

---

### Finding Description

**Step 1 — `switch_operator` seeds the distribution pool with `old_operator`'s address:**

Inside `switch_operator`, after removing the contract from the map, `distribute_internal` is called with `operator = old_operator` to flush any already-inactive funds (beneficiary redirect works correctly here). Then `request_commission_internal(old_operator, ...)` is called: [1](#0-0) 

`request_commission_internal` calls `add_distribution` with `operator = old_operator` and `recipient = old_operator`: [2](#0-1) 

This mints shares for `old_operator` in `staking_contract.distribution_pool`. The commission is in `pending_inactive` state — it cannot be withdrawn yet.

**Step 2 — the contract is re-keyed under `new_operator`:** [3](#0-2) 

The same `StakingContract` struct (with `distribution_pool` still holding `old_operator`'s shares) is now stored under the `new_operator` key.

**Step 3 — `distribute(staker, new_operator)` passes `operator = new_operator` to `distribute_internal`:** [4](#0-3) 

**Step 4 — the beneficiary-redirect guard fails:** [5](#0-4) 

`recipient` is `old_operator`; `operator` is `new_operator`. The condition is `false`. `old_operator` receives the APT commission directly, bypassing `beneficiary_for_operator(old_operator)`.

---

### Impact Explanation

APT commission that `old_operator`'s beneficiary is entitled to is instead deposited to `old_operator`'s account. This is a direct, unauthorized reassignment of APT from a user-designated beneficiary to a different address, satisfying the "direct theft / unauthorized reassignment of APT" impact gate.

---

### Likelihood Explanation

The trigger is a normal, unprivileged staker transaction (`switch_operator`). No privileged keys, governance, or validator control are required. The condition is met whenever:
1. `old_operator` has accrued rewards (common after any epoch),
2. `old_operator` has set a beneficiary via `set_beneficiary_for_operator`, and
3. the staker calls `switch_operator` before the lockup expires and the commission is distributed.

All three conditions are routine in production staking setups.

---

### Recommendation

In `switch_operator`, after calling `request_commission_internal`, iterate the `distribution_pool` shareholders and, for any shareholder equal to `old_operator`, record a mapping (e.g., a field on `StakingContract` or a separate resource) that redirects that address to `beneficiary_for_operator(old_operator)` at distribution time. Alternatively, `distribute_internal` should accept an explicit `commission_recipient_override: Option<address>` so the caller can pass the correct beneficiary when the operator identity has changed.

---

### Proof of Concept

```move
#[test(aptos_framework = @0x1, staker = @0x100, op1 = @0x200, op2 = @0x300, beneficiary = @0x400)]
public entry fun test_switch_operator_bypasses_beneficiary(
    aptos_framework: &signer,
    staker: &signer,
    op1: &signer,
    op2: &signer,
    beneficiary: &signer,
) acquires Store, BeneficiaryForOperator {
    // 1. Setup: create staking contract with op1
    setup_staking_contract(aptos_framework, staker, op1, INITIAL_BALANCE, 10);
    let staker_addr = signer::address_of(staker);
    let op1_addr   = signer::address_of(op1);
    let op2_addr   = signer::address_of(op2);
    let ben_addr   = signer::address_of(beneficiary);

    // 2. op1 sets a beneficiary
    set_beneficiary_for_operator(op1, ben_addr);
    assert!(beneficiary_for_operator(op1_addr) == ben_addr, 0);

    // 3. Advance epoch so rewards accrue, then request commission (pending_inactive)
    stake::end_epoch();
    request_commission(op1, staker_addr, op1_addr);
    // commission is now pending_inactive in distribution_pool keyed to op1_addr

    // 4. Staker switches to op2 — this calls request_commission_internal(op1,...) again
    //    and re-keys the contract under op2
    switch_operator(staker, op1_addr, op2_addr, 10);

    // 5. Wait for lockup to expire so pending_inactive becomes inactive
    let pool_address = stake_pool_address(staker_addr, op2_addr);
    stake::fast_forward_to_unlock(pool_address);

    // 6. Distribute under new_operator key
    distribute(staker_addr, op2_addr);

    // 7. Assert: beneficiary should have received commission, op1 should not
    let ben_balance = coin::balance<AptosCoin>(ben_addr);
    let op1_balance = coin::balance<AptosCoin>(op1_addr);
    // BUG: ben_balance == 0, op1_balance > INITIAL_BALANCE
    assert!(ben_balance > 0, 1);          // FAILS — beneficiary got nothing
    assert!(op1_balance == INITIAL_BALANCE, 2); // FAILS — op1 got the commission
}
```
