### Title
Unauthenticated `header.RecvError` packet allows spoofed teardown of an established tunnel - ([File: outside.go])

### Summary
`Interface.handleRecvError` in `outside.go` processes an entirely unauthenticated, unencrypted `header.RecvError` packet and, if its `RemoteIndex` matches an existing hostinfo's reverse index and the packet's source `addr` matches that hostinfo's currently known remote endpoint, calls `f.closeTunnel(hostinfo)` and `f.handshakeManager.DeleteHostInfo(hostinfo)`. Both the index and the "matching addr" check rely on values that travel in the clear (index) or can be UDP-source-spoofed (addr), so no possession of any session key, certificate, or handshake state is required to destroy an authenticated tunnel.

### Finding Description
`readOutsidePackets` dispatches `header.RecvError` packets directly to `f.handleRecvError(via.UdpAddr, h)` before any AEAD/session validation occurs: [1](#0-0) 

`handleRecvError` performs only two checks before tearing down the tunnel: a config gate (`ShouldRecvError`, default `"always"` which returns `true` for any address) and a comparison of the sender's UDP address to the hostinfo's currently known remote (`GetRemote()`): [2](#0-1) 

Neither check involves any cryptographic authentication of the packet. `h.RemoteIndex` is the plaintext, unencrypted index that appears in the header of every packet exchanged between the two peers (used precisely so receivers can look up `HostInfo` before decryption), so it is trivially learned by anyone who can observe traffic between the peers. The only other check, `hr != addr`, compares the packet's *claimed* source `netip.AddrPort` against the victim's currently known remote endpoint — but UDP has no source-address authentication at the transport layer, so an attacker who can spoof IP/UDP headers (a classic on-path/adjacent-network capability requiring no Nebula credentials at all) can set the spoofed source to exactly match `hr`. Once both values line up, `closeTunnel` (which calls `hostMap.DeleteHostInfo`) and `handshakeManager.DeleteHostInfo` are invoked unconditionally: [3](#0-2) 

This satisfies the question's exact concern: an attacker who can (a) learn/guess the `RemoteIndex` (visible in cleartext on the wire) and (b) spoof a UDP source address equal to the victim's current remote endpoint, can unilaterally force teardown of an authenticated Nebula tunnel and eviction from the handshake manager, without ever possessing a session key or valid certificate.

### Impact Explanation
This is a denial-of-service / forced tunnel-teardown primitive: the victim's active, authenticated tunnel state is destroyed by an unauthenticated packet, forcing a fresh handshake. Because the attack also purges pending handshake state via `f.handshakeManager.DeleteHostInfo`, it can be used repeatedly to prevent reconnection ("fast reconnect" abuse) or to create a window in which an active on-path attacker attempts to interfere with the ensuing re-handshake (downgrade/interception opportunity), matching the "remote state poisoning" / "remote crash-or-wedge (DoS)" bounty impact category.

### Likelihood Explanation
Feasibility depends on two attacker capabilities: observing/guessing the peer's `RemoteIndex` (easy for any passive on-path observer, since it's sent unencrypted in every packet) and spoofing a UDP packet whose source IP:port equals the victim's current remote endpoint (feasible for on-path attackers, attackers sharing a NAT/broadcast segment, or anyone in a position to send spoofed UDP absent egress/ingress filtering — no BCP38 filtering assumption required by the code). This is squarely within the scope of "attacker-sent UDP packets, spoofed source addresses" called out as in-scope in the audit rules; no CA-signed certificate, leaked key, or config control is needed. The default `listen.accept_recv_error = "always"` makes the config gate ineffective for any deployment that has not manually restricted it.

### Recommendation
Do not allow an unauthenticated packet type to destroy authenticated hostmap/handshake state. Options: require `RecvError` to be authenticated (e.g., signed/MAC'd with a value derived from the session, or only accepted before any successful decrypt has occurred on that index), rate-limit/require repetition or corroborating signals (e.g., loss of traffic for a timeout window) before tearing down an established tunnel, or drop the address-based spoof check in favor of validating a small proof tied to the current session (such as accepting `RecvError` only if it was solicited, or requiring it to also carry information only derivable from actual decrypt failures on the receiving side, not from mere observation).

### Proof of Concept
Unit test in `outside_test.go`-style harness:
1. Establish two hostinfos over a mocked `udp.Conn`, completing a handshake so `hostinfo.remote` (via `SetRemote`/`GetRemote`) is set to `victimAddr`, and note the local index used as `ReverseIndex` in the hostmap (`hostMap.QueryReverseIndex`).
2. Without performing any handshake or holding any key, construct a raw `header.RecvError` packet via `header.Encode` with `RemoteIndex` set to the victim's known reverse index.
3. Call `f.readOutsidePackets` (or directly `f.handleRecvError`) with `addr` set equal to `victimAddr` (simulating a spoofed source) but do not supply any valid ciphertext/signature.
4. Assert that `f.hostMap.QueryReverseIndex(index)` returns nil afterward (i.e., `closeTunnel`/`DeleteHostInfo` were invoked), demonstrating that an attacker with no key material destroyed the session purely via index+addr knowledge.
5. Fuzz test: iterate over addr/index combinations against `acceptRecvErrorConfig.ShouldRecvError` and confirm that under the default `recvErrorAlways` config, any correct (index, addr) pair — regardless of provenance — succeeds in tearing down the tunnel, expected assertion: this should fail (i.e., teardown should require authentication), but currently passes.

```go
func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
```
