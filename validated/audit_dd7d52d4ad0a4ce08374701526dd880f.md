Audit Report

## Title
Permissionless `deposit_reward_tokens` funds can be fully swept by the pool admin via `cleanup_pool` before any staker exists - (File: substrate/frame/asset-rewards/src/lib.rs)

## Summary
`deposit_reward_tokens` allows any signed account to push reward-asset tokens into a pool's pot account with no requirement that a staker exists and no bookkeeping of the depositor or contributed amount. When `PoolStakers` is empty for a pool (e.g., before the first stake, or after all stakers exit), the admin-only `cleanup_pool` extrinsic transfers the pool's entire reducible reward-asset balance to `pool_info.admin`, including any funds deposited by unrelated third parties via `deposit_reward_tokens`.

## Finding Description
`deposit_reward_tokens` performs a bare `T::Assets::transfer` from the caller into `pool_info.account` with no check on `pool_info.total_tokens_staked` and no per-depositor accounting: [1](#0-0) 

`reward_per_token` intentionally does not advance the reward accrual counter while `total_tokens_staked` is zero, so tokens deposited during a zero-staker window are never credited to any staker's `PoolStakerInfo`; they remain as a raw balance in `pool_info.account` [2](#0-1) 

`cleanup_pool` only verifies that `PoolStakers::iter_key_prefix(pool_id)` is empty, then sweeps the entire `reducible_balance` of the pool's reward asset to `pool_info.admin`, with no distinction between admin-owned residual funds and third-party deposits made through `deposit_reward_tokens`: [3](#0-2) 

The exploit path is reachable purely through public extrinsics: an unprivileged account calls `deposit_reward_tokens` on a pool with zero stakers (e.g., immediately after `create_pool`, or after all stakers unstake), and the pool admin subsequently calls the standard, documented `cleanup_pool` operation. No existing guard prevents deposits when `total_tokens_staked == 0`, and no guard in `cleanup_pool` restricts the swept amount to admin-contributed funds.

## Impact Explanation
This breaks the value-conservation invariant that pool funds must settle exactly once to the rightful beneficiary: an unprivileged depositor's contribution can be fully captured by the pool admin instead of being credited to any staker or returned to the depositor. The exact corrupted value is the reward-asset balance held at `pool_info.account`, which `cleanup_pool` redirects entirely to `pool_info.admin` via `T::Assets::transfer(pool_info.reward_asset_id, &pool_info.account, &pool_info.admin, pool_balance, ...)` regardless of provenance.

## Likelihood Explanation
The precondition-triggering step (`deposit_reward_tokens` while the pool has zero stakers) requires no privilege beyond `ensure_signed` and can be performed by anyone at any time, including immediately after pool creation. The completing step (`cleanup_pool`) is admin-gated but represents the pallet's normal, documented pool-lifecycle behavior ("return the remaining reward tokens to the admin") rather than malicious abuse of an out-of-scope privilege — it is a foreseeable, non-adversarial admin action that naturally occurs whenever a pool empties of stakers after third-party deposits were made.

## Recommendation
- Reject `deposit_reward_tokens` when `PoolInfo::total_tokens_staked` is zero, or track deposited-but-unaccrued balances separately from admin-owned funds.
- Restrict `cleanup_pool` to reclaim only the admin's own residual balance, excluding externally deposited amounts that were never credited to a staker.

## Proof of Concept
1. Admin calls `create_pool` for `pool_id = 0` with a given `staked_asset_id`/`reward_asset_id` [4](#0-3) .
2. Before any account calls `stake`, an unprivileged account `U` calls `deposit_reward_tokens(pool_id=0, amount=X)`, transferring `X` reward-asset tokens into `pool_info.account` [5](#0-4) .
3. Since `PoolStakers::iter_key_prefix(0)` is empty, the admin calls `cleanup_pool(pool_id=0)`; `pool_balance` (including `U`'s `X`) is computed via `reducible_balance` and transferred entirely to `pool_info.admin` [6](#0-5) .
4. `U`'s deposited `X` tokens are now held by the admin instead of any staker, and `U` has no path to reclaim them.

		pub fn cleanup_pool(origin: OriginFor<T>, pool_id: PoolId) -> DispatchResult {
			let who = ensure_signed(origin)?;

			let pool_info = Pools::<T>::get(pool_id).ok_or(Error::<T>::NonExistentPool)?;
			ensure!(pool_info.admin == who, BadOrigin);

			let stakers = PoolStakers::<T>::iter_key_prefix(pool_id).next();
			ensure!(stakers.is_none(), Error::<T>::NonEmptyPool);

			let pool_balance = T::Assets::reducible_balance(
				pool_info.reward_asset_id.clone(),
				&pool_info.account,
				Preservation::Expendable,
				Fortitude::Polite,
			);
			T::Assets::transfer(
				pool_info.reward_asset_id,
				&pool_info.account,
				&pool_info.admin,
				pool_balance,

			)?;
