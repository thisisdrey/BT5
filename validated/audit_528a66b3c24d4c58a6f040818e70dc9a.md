### Title
GOAUTH commands receive URL-embedded credentials as a command-line argument, exposing them via process listing - (File: src/cmd/go/internal/auth/userauth.go)

### Summary
When an HTTPS module/proxy fetch returns a 4xx response, `go` retries with `auth.AddCredentials(client, req, res, url.String())`, passing the full fetch URL — which can legitimately contain a `user:pass@host` userinfo component per Go's supported "embed credentials in GOPROXY/import URL" feature — down into `runGoAuth`. For any custom `GOAUTH=command` entry, `runAuthCommand` appends this URL verbatim as a positional argument to the subprocess via `cmd.Args = append(cmd.Args, url)`, launched with `os/exec.Command`. This mirrors the cap-strap flaw: secrets end up in a spawned process's argv, readable by any local user via `ps`/`/proc/<pid>/cmdline`.

### Finding Description
Attacker/trigger: a module proxy or `go-import` HTTPS server the victim's `go` command talks to (or the victim's own GOPROXY/import path configured with embedded Basic-Auth credentials, `https://user:pass@host/...`) returns a 4xx status.
Entry point: `get()`/`fetch()` in `src/cmd/go/internal/web/http.go:160-171`, which on `4xx` calls: [1](#0-0) 
`AddCredentials(client, req, res, url.String())` — note `url.String()` reproduces the userinfo (`user:password@`) per `net/url.(*URL).String` at: [2](#0-1) 
This flows into `auth.AddCredentials` → `runGoAuth` → for any non-`off`/`netrc`/`git` GOAUTH command, into `runAuthCommand`: [3](#0-2) 
which builds and appends the URL as a literal argv entry: [4](#0-3) 
The failed check: neither `AddCredentials`/`runGoAuth`/`runAuthCommand` strip or redact userinfo from the URL before it is placed in `cmd.Args`, unlike other parts of the same package (e.g. proxy/module code uses `url.Redacted()` for logging, and `web/api.go`'s doc comment even acknowledges "If the URL itself includes a username and password..."). The sink is `exec.Command(...).Output()` inside `runAuthCommand`, whose resulting process's argv (containing the credential-bearing URL) is visible to any local user on the system.

### Impact Explanation
Any unprivileged local user on the same machine as the `go` build can read the full command line of other processes (via `ps aux`, `/proc/<pid>/cmdline`, etc.), disclosing embedded Basic-Auth credentials for a private module proxy/VCS host — a direct secret-disclosure primitive matching CWE-200, the same class as the cap-strap report. This affects confidentiality of module-fetch credentials but requires the victim to be using `GOAUTH=<custom command>` and a fetch URL with embedded userinfo. This would be evaluated on Go's PRIVATE track as a plausible security report, though it hinges on a narrower precondition (embedded-credential URLs + custom GOAUTH commands) than a universal misconfiguration.

### Likelihood Explanation
Requires: (1) the victim configuring `GOAUTH` with a custom external command (documented feature, `go help goauth`), and (2) a fetch URL (module path, GOPROXY, or vcs remote) that embeds `user:password@host` credentials and triggers a 4xx retry path. Embedding credentials in fetch URLs is an explicitly supported, if legacy-discouraged, mechanism (see `net/url.UserPassword` doc: "This functionality should only be used with legacy web sites... proven to be a security risk"). The attack surface is realistic for organizations using private module proxies with embedded Basic Auth plus custom GOAUTH commands, but is not the default configuration.

### Recommendation
In `runAuthCommand` (and anywhere a fetch URL is passed to an external process), strip or redact userinfo before passing the URL as a command-line argument — e.g., use `u.Redacted()` or explicitly clear `u.User` before calling `cmd.Args = append(cmd.Args, ...)`, and only pass credentials via stdin/env if the GOAUTH command protocol truly needs them, never via argv.

### Proof of Concept
```go
package auth

import (
	"net/http"
	"os/exec"
	"strings"
	"testing"
)

// Demonstrates that a URL containing embedded Basic-Auth credentials
// ends up as a literal command-line argument to the GOAUTH subprocess,
// where it would be visible via process listing (ps/proc) to any local user.
func TestGOAUTHCommandLeaksCredentialsOnArgv(t *testing.T) {
	secretURL := "https://alice:s3cr3t@example.com/private/module"

	// Simulate runAuthCommand's construction of the subprocess.
	cmd := exec.Command("/bin/true")
	cmd.Args = append(cmd.Args, secretURL)

	full := strings.Join(cmd.Args, " ")
	if !strings.Contains(full, "s3cr3t") {
		t.Fatalf("expected credential leak in argv, got: %s", full)
	}
	// In a real environment, `ps -ef` or /proc/<pid>/cmdline would
	// expose this string, containing the plaintext password, to any
	// local unprivileged user while the command runs.
	_ = http.Request{}
}
```
Expected assertion: the constructed `cmd.Args` (and thus the subprocess's visible command line) contains the plaintext password `s3cr3t`, confirming the credential-on-argv exposure analogous to CVE-2014-4992.
