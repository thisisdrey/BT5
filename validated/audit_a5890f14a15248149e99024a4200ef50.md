### Title
FetchIntoObjectPool does not verify the caller is authorized to write into the target object pool, allowing cross-repository object injection - ([File: internal/gitaly/service/objectpool/fetch_into_object_pool.go])

### Summary
The Sherlock finding is that a bridge call accepts a destination `chainId` field supplied via calldata without validating it matches the caller's intended (or only permitted) chain, letting funds be routed to a chain the caller didn't (or shouldn't) reach. The structurally analogous issue in Gitaly is that `FetchIntoObjectPool` accepts two independently caller-supplied repository identifiers — `Origin` and `ObjectPool.Repository` — and only checks that they share the same `StorageName`, never that the caller is actually authorized to write into that specific pool or that the origin/pool pairing is legitimate.

### Finding Description
`FetchIntoObjectPool` is validated by `validateFetchIntoObjectPoolRequest`, which only rejects requests when `Origin` or `ObjectPool` are unset, or when the two repositories live on different storages: [1](#0-0) 

There is no check that the caller has any relationship between `Origin` and the object pool it names — e.g. that the pool is the pool the origin repository is (or should be) linked to. `objectpool.FromProto` only verifies that the target path looks like a pool repository (`storage.IsPoolRepository`) or lives under the storage's temp dir, and that it is a valid git repository: [2](#0-1) 

Once the pool is resolved, `FetchIntoObjectPool` performs `objectPool.FetchFromOrigin(ctx, origin, ...)`, fetching all objects reachable from the caller-chosen `Origin` repository directly into the caller-chosen pool repository — there is no ownership/ACL check binding the origin repository to that particular pool.

### Impact Explanation
Because only the storage name is checked (not repository ownership or project/tenant membership), an authenticated RPC caller who can reach the `ObjectPoolService` can name *any* existing pool repository on the same storage as the `ObjectPool` target and *any* repository they control as `Origin`. This causes objects from the attacker's repository to be fetched into another project's/tenant's object pool. Since a pool's objects become part of the alternate object store shared by every repository linked to that pool (via the `objects/info/alternates` mechanism validated in `internal/git/objectpool/link.go` and `internal/git/dirs.go`), this effectively injects attacker-controlled objects into the object store visible to unrelated repositories/tenants sharing that pool — a cross-repository object access/injection primitive, and a disk-space/DoS vector for the affected pool.

### Likelihood Explanation
`FetchIntoObjectPool` is a standard, reachable gRPC endpoint (`ObjectPoolService`) invoked with an ordinary, crafted RPC request — no special privilege beyond normal Gitaly RPC access is required, and the only constraint enforced is storage-name equality, which is trivially satisfiable in any multi-tenant deployment sharing a storage.

### Recommendation
Require `FetchIntoObjectPool` to verify that `Origin` is actually linked (or eligible to be linked) to the specified `ObjectPool` — e.g. by checking that the origin repository's alternates file already points at the pool, or by deriving the pool from the origin via `objectpool.FromRepo` rather than trusting an independently supplied `ObjectPool` field — instead of only comparing storage names.

### Proof of Concept
1. As a caller with access to Gitaly's `ObjectPoolService`, create/own repository `A` on storage `default`.
2. Identify or know the relative path of an existing pool repository `P` on the same storage that `A` is not linked to (pools typically live under a predictable `@pools/...` layout).
3. Call `FetchIntoObjectPool` with `Origin = A` and `ObjectPool.Repository = P`.
4. `validateFetchIntoObjectPoolRequest` passes because both repositories share `StorageName == "default"`; `objectpool.FromProto` succeeds because `P` is a valid pool repository.
5. `objectPool.FetchFromOrigin` fetches all objects reachable in `A` into pool `P`, making attacker-controlled objects part of the shared alternate object store used by every repository linked to `P`. [3](#0-2)

func (s *server) FetchIntoObjectPool(ctx context.Context, req *gitalypb.FetchIntoObjectPoolRequest) (*gitalypb.FetchIntoObjectPoolResponse, error) {
	if err := validateFetchIntoObjectPoolRequest(req); err != nil {
		return nil, structerr.NewInvalidArgument("%w", err)
	}

	objectPool, err := objectpool.FromProto(ctx, s.logger, s.locator, s.gitCmdFactory, s.catfileCache, s.txManager, s.housekeepingManager, req.GetObjectPool())
	if err != nil {
		return nil, structerr.NewInvalidArgument("object pool invalid: %w", err)
	}

		return s.localRepoFactory.Build(repo)
	}); err != nil {

func validateFetchIntoObjectPoolRequest(req *gitalypb.FetchIntoObjectPoolRequest) error {
	if req.GetOrigin() == nil {
		return errors.New("origin is empty")
	}

	if req.GetObjectPool() == nil {
		return errors.New("object pool is empty")
	}

	originRepository, poolRepository := req.GetOrigin(), req.GetObjectPool().GetRepository()

	if originRepository.GetStorageName() != poolRepository.GetStorageName() {
		return errors.New("origin has different storage than object pool")
	}

	return nil

// FromProto returns an object pool object from its Protobuf representation. This function verifies
// that the object pool exists and is a valid pool repository.
func FromProto(
	ctx context.Context,
	logger log.Logger,
	locator storage.Locator,
	gitCmdFactory gitcmd.CommandFactory,
	catfileCache catfile.Cache,
	txManager transaction.Manager,
	housekeepingManager housekeepingmgr.Manager,
	proto *gitalypb.ObjectPool,
) (*ObjectPool, error) {
	poolPath, err := locator.GetRepoPath(ctx, proto.GetRepository(), storage.WithRepositoryVerificationSkipped())
	if err != nil {
		return nil, err
	}

	if !storage.IsPoolRepository(proto.GetRepository()) {
		// When creating repositories in the ObjectPool service we will first create the
		// repository in a temporary directory. So we need to check whether the path we see
		// here is in such a temporary directory and let it pass.
		tempDir, err := locator.TempDir(proto.GetRepository().GetStorageName())
		if err != nil {
			return nil, fmt.Errorf("getting temporary storage directory: %w", err)
		}

		if !strings.HasPrefix(poolPath, tempDir) {
			return nil, ErrInvalidPoolDir
		}
	}

	pool := &ObjectPool{
		Repo:                localrepo.New(logger, locator, gitCmdFactory, catfileCache, proto.GetRepository()),
		logger:              logger,
		locator:             locator,
		gitCmdFactory:       gitCmdFactory,
		txManager:           txManager,
		housekeepingManager: housekeepingManager,
	}

	if !pool.IsValid(ctx) {
		return nil, ErrInvalidPoolRepository
	}

	return pool, nil
}
