### Title
DoS via unbounded tar extraction in `ExtractHooks` (`SetCustomHooks`/`RestoreCustomHooks`) - ([File: internal/gitaly/repoutil/custom_hooks.go])

### Summary
`ExtractHooks` streams an attacker-supplied tar archive directly into `tar -xf -` with no enforced limit on total stream size, entry count, path-component length, or extraction time. A repository owner invoking `SetCustomHooks`/`RestoreCustomHooks` can submit a tar bomb (huge entry counts or extremely long path names) to consume disk inodes/CPU on the Gitaly node before the atomic swap even completes.

### Finding Description
`ExtractHooks` peeks the stream for emptiness and then pipes the reader straight into a spawned `tar -xf - -C path --strip-components N custom_hooks` subprocess with no byte, entry-count, or wall-clock ceiling: [1](#0-0) . The calling RPC handlers `SetCustomHooks`/`RestoreCustomHooks` read the request stream via `streamio.NewReader` with no size accounting before forwarding to `repoutil.SetCustomHooks` → `ExtractHooks`: [2](#0-1) . `SetCustomHooks` (the repoutil version) extracts into a temp directory (`tempdir.NewWithoutContext`) before the atomic rename swap, so a large/highly-entried tar fully lands on disk in the temp dir first, and `newDirectoryVote` subsequently walks and hashes every extracted file, adding further CPU/I/O cost proportional to entry count: [3](#0-2) [4](#0-3) . No `storage.ValidateRelativePath`-style limit, no gRPC max-message-size enforcement, and no repository quota check intercepts this path — a repository-owning attacker fully controls the tar content and its size/entry count.

### Impact Explanation
An attacker-controlled repository owner can cause the Gitaly node to spend excessive CPU (per-entry tar processing, per-entry hashing in `newDirectoryVote`) and consume disk inodes/space (temp directory holding all extracted entries) via a single RPC call, potentially degrading service for other tenants co-located on the same storage/node. This maps to a resource-exhaustion / DoS impact class.

### Likelihood Explanation
The precondition is trivial: any unprivileged GitLab user who owns/can push to a repository can invoke `SetCustomHooks` (used internally e.g. by GitLab Rails custom hooks feature) or the deprecated `RestoreCustomHooks` with an arbitrarily large or highly-entried tar stream, and no configuration change is needed since there is no default entry/size cap. However, this is not qualitatively different from other unbounded streaming/write paths already present in Gitaly (e.g. ordinary `git push` of many objects, `CreateRepositoryFromBundle`), where storage/disk-quota enforcement is expected to live at the GitLab Rails/Workhorse layer rather than in Gitaly itself, which somewhat reduces the marginal severity of this specific handler versus already-accepted risk in the broader architecture.

### Recommendation
Enforce limits before/while extracting: cap total decompressed size and entry count while streaming into `tar` (e.g., wrap the reader with a byte-counting limiter and/or use `archive/tar` in Go to inspect headers and reject excessive `Typeflag`/`Size`/`Name` length/entry counts before invoking the subprocess), add a context-based timeout around the `tar` extraction, and consider validating path-component length against a sane maximum in the tar header prior to writing to disk.

```go
func TestExtractHooks_TarBomb(t *testing.T) {
    ctx := testhelper.Context(t)
    logger := testhelper.NewLogger(t)
    dir := testhelper.TempDir(t)

    var buf bytes.Buffer
    tw := tar.NewWriter(&buf)
    // Write N tiny entries under custom_hooks/ to simulate an entry-count bomb.
    for i := 0; i < 1_000_000; i++ {
        hdr := &tar.Header{
            Name: fmt.Sprintf("custom_hooks/%040d", i), // long-ish name too
            Mode: 0o644,
            Size: 0,
        }
        require.NoError(t, tw.WriteHeader(hdr))
    }
    require.NoError(t, tw.Close())

    start := time.Now()
    err := repoutil.ExtractHooks(ctx, logger, &buf, dir, false)
    require.NoError(t, err)
    t.Logf("extraction took %s, wrote %d inodes", time.Since(start), 1_000_000)
    // Assert wall-clock/inode usage exceeds an acceptable bound (fails today because no cap exists).
}
```
Expected: no error is returned and Gitaly happily writes 1,000,000 zero-byte files into a temp directory (consuming inodes) and hashes each one in `newDirectoryVote`, demonstrating the absence of any size/entry-count ceiling.

```go
func ExtractHooks(ctx context.Context, logger log.Logger, reader io.Reader, path string, stripPrefix bool) error {
	// GNU tar does not accept an empty file as a valid tar archive and produces
	// an error. Since an empty hooks tar is symbolic of a repository having no
	// hooks, the reader is peeked to check if there is any data present.
	buf := bufio.NewReader(reader)
	if _, err := buf.Peek(1); errors.Is(err, io.EOF) {
		return nil
	}

	stripComponents := "0"
	if stripPrefix {
		stripComponents = "1"
	}

	cmdArgs := []string{"-xf", "-", "-C", path, "--strip-components", stripComponents, CustomHooksDir}

	var stderrBuilder strings.Builder
	cmd, err := command.New(ctx, logger, append([]string{"tar"}, cmdArgs...),
		command.WithStdin(buf),
		command.WithStderr(&stderrBuilder))
	if err != nil {
		return fmt.Errorf("executing tar command: %w", err)
	}
```

```go
func newDirectoryVote(basePath string) (*voting.VoteHash, error) {
	voteHash := voting.NewVoteHash()

	if err := filepath.WalkDir(basePath, func(path string, entry fs.DirEntry, err error) error {
		if err != nil {
			return err
		}

		relPath, err := filepath.Rel(basePath, path)
		if err != nil {
			return fmt.Errorf("getting relative path: %w", err)
		}

		// Write file relative path to hash.
		_, _ = voteHash.Write([]byte(relPath))

		info, err := entry.Info()
		if err != nil {
			return fmt.Errorf("getting file info: %w", err)
		}

		// Write file permissions to hash.
		permBytes := make([]byte, 4)
		binary.BigEndian.PutUint32(permBytes, uint32(info.Mode()))
		_, _ = voteHash.Write(permBytes)

		if entry.IsDir() {
			return nil
		}

		file, err := os.Open(path)
		if err != nil {
			return fmt.Errorf("opening file: %w", err)
		}
		defer file.Close()

		// Copy file data to hash.
		if _, err = io.Copy(voteHash, file); err != nil {
			return fmt.Errorf("copying file to hash: %w", err)
		}

		return nil
	}); err != nil {
		return nil, fmt.Errorf("walking directory: %w", err)
	}
```

```go
func (s *server) SetCustomHooks(stream gitalypb.RepositoryService_SetCustomHooksServer) error {
	ctx := stream.Context()

	firstRequest, err := stream.Recv()
	if err != nil {
		return structerr.NewInternal("getting first request: %w", err)
	}

	repo := firstRequest.GetRepository()
	if err := s.locator.ValidateRepository(ctx, repo); err != nil {
		return structerr.NewInvalidArgument("%w", err)
	}

	reader := streamio.NewReader(func() ([]byte, error) {
		if firstRequest != nil {
			data := firstRequest.GetData()
			firstRequest = nil
			return data, nil
		}

		request, err := stream.Recv()
		return request.GetData(), err
	})

	if err := repoutil.SetCustomHooks(ctx, s.logger, s.locator, s.txManager, reader, repo); err != nil {
		return structerr.NewInternal("setting custom hooks: %w", err)
	}

	return stream.SendAndClose(&gitalypb.SetCustomHooksResponse{})
}
```
