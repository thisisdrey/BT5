### Title
Custom hooks environment trusts client-supplied `GitObjectDirectory`/`GitAlternateObjectDirectories` without storage-root validation - (File: internal/gitaly/hook/custom.go)

### Summary
The external report's bug class is "a security-relevant field (`lp_wallet`) is accepted and trusted without validation, and later used to move value to the wrong destination." The closest reachable analog in Gitaly is `customHooksEnv` in `internal/gitaly/hook/custom.go`, which builds `GIT_OBJECT_DIRECTORY`/`GIT_ALTERNATE_OBJECT_DIRECTORIES` for custom hook execution directly from the `Repository.GitObjectDirectory` / `Repository.GitAlternateObjectDirectories` proto fields via a plain `filepath.Join`, without the same root-escape validation that other consumers of these fields enforce.

### Finding Description
`Repository.GitObjectDirectory` and `Repository.GitAlternateObjectDirectories` are ordinary fields on the `Repository` message that ships with virtually every RPC request [1](#0-0) . They exist to let Gitaly point Git at a quarantine directory during a push, and are normally derived internally from Git's own quarantine mechanism, but nothing in the proto or in `customHooksEnv` prevents a caller from setting these fields to an arbitrary string, including one containing `../` traversal sequences.

When Gitaly resolves the *actual* object directory for git operations (`ObjectDirectoryPath`), it explicitly validates the result against the storage root with `storage.ValidateRelativePath`, rejects anything from `.stat`/`quarantine` mismatch, and returns `InvalidArgument` on traversal [2](#0-1) . This is proven by dedicated tests that assert traversal payloads like `"../bazqux.git"` or `"objects/../.."` are rejected [3](#0-2) .

By contrast, `customHooksEnv`, which sets up the environment used to run project custom hooks (`pre-receive`, `post-receive`, `update`), performs no such validation. It just does:

```go
objectDirectory = filepath.Join(repoPath, payload.Repo.GetGitObjectDirectory())
...
absolutePaths = append(absolutePaths, filepath.Join(repoPath, alternateObjectDirectory))
``` [4](#0-3) 

`filepath.Join` cleans `..` segments syntactically but does not prevent the result from resolving outside `repoPath`/the storage root — exactly the traversal case that `paths_test.go` proves must otherwise be rejected. The resulting `GIT_OBJECT_DIRECTORY`/`GIT_ALTERNATE_OBJECT_DIRECTORIES` environment variables are then handed to every custom hook script (`newCustomHooksExecutor`) [5](#0-4) , and are also propagated into the `Allowed` API call as `GitObjectDirectory`/`GitAlternateObjectDirectories` parameters [6](#0-5) .

Gitaly's own middleware documentation acknowledges that these two fields being independently settable on any mutator/accessor RPC is a known weak point used to "circumvent transaction management," but only mitigates it at the *transaction* layer (rejecting mutators with quarantine fields set outside of a transaction), not at the `customHooksEnv`/hook-execution layer [7](#0-6) .

### Impact Explanation
If a value for `GitObjectDirectory`/`GitAlternateObjectDirectories` that escapes the storage root reaches `customHooksEnv` (e.g. via a crafted accessor RPC field, which the middleware explicitly allows to bypass the transaction path, or via any code path that forwards `payload.Repo` from an externally influenced `Repository` message), custom hook scripts for that repository will be executed with `GIT_OBJECT_DIRECTORY`/`GIT_ALTERNATE_OBJECT_DIRECTORIES` pointing at attacker-chosen locations. This can make Git object lookups performed by the hook itself resolve objects from outside the intended repository/storage root, an object-pool/alternates isolation violation, analogous to the report's root cause of "an address is trusted and used to route value without validating it points to the intended, protocol-controlled destination."

### Likelihood Explanation
Because `GitObjectDirectory`/`GitAlternateObjectDirectories` are plain fields on the widely-reused `Repository` message and are explicitly called out in `middleware.go` as being configurable on requests outside of the legitimate quarantine flow, the precondition (an attacker or a compromised/careless caller setting these fields on an RPC whose `Repository` eventually reaches `customHooksEnv`) is plausible without any privileged access beyond ordinary Gitaly RPC access. However, full confirmation that a specific unprivileged, end-to-end RPC (e.g., an unauthenticated git push over SmartHTTP/SSH) can inject an arbitrary value into `payload.Repo` (as opposed to Gitaly always deriving it from its own quarantine subsystem) could not be fully traced in the available index — this is the main uncertainty in this analog.

### Recommendation
Route `GitObjectDirectory`/`GitAlternateObjectDirectories` handling in `customHooksEnv` through the same validated resolution used by `ObjectDirectoryPath` (`storage.ValidateRelativePath` against the storage root), rejecting any value that escapes `repoPath`/storage root before constructing `GIT_OBJECT_DIRECTORY`/`GIT_ALTERNATE_OBJECT_DIRECTORIES`, instead of relying on an unchecked `filepath.Join`.

### Proof of Concept
Not independently reproduced; confirmed by static code comparison only. `internal/git/localrepo/paths_test.go` demonstrates the traversal payloads (`"../bazqux.git"`, `"objects/../.."`, `"/../bazqux.git"`) that `ObjectDirectoryPath` rejects [3](#0-2) ; the same payloads passed through `payload.Repo.GetGitObjectDirectory()`/`GetGitAlternateObjectDirectories()` into `customHooksEnv` are not checked against `storage.ValidateRelativePath` before being joined and exported as environment variables [4](#0-3) .

// ObjectDirectoryPath returns the full path of the object directory. The errors returned are gRPC
// errors with relevant error codes and should be passed back to gRPC without further decoration.
func (repo *Repo) ObjectDirectoryPath(ctx context.Context) (string, error) {
	repoPath, err := repo.Path(ctx)
	if err != nil {
		return "", err
	}

	objectDirectoryPath := repo.GetGitObjectDirectory()
	if objectDirectoryPath == "" {
		return "", structerr.NewInvalidArgument("object directory path is not set")
	}

	storagePath, err := repo.locator.GetStorageByName(ctx, repo.GetStorageName())
	if err != nil {
		return "", fmt.Errorf("get storage by name: %w", err)
	}

	// Ensure the path points somewhere in the storage.
	relativeObjectDirectoryPath, err := storage.ValidateRelativePath(storagePath, filepath.Join(repoPath, objectDirectoryPath))
	if err != nil {
		return "", structerr.NewInvalidArgument("validate relative path: %w", err)
	}
```
