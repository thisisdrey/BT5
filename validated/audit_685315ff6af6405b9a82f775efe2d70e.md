### Title
TOCTOU race between zip checksum verification and extraction in Go module download (`modfetch.download`) - ([File: src/cmd/go/internal/modfetch/fetch.go])

### Summary
The `go` command verifies a downloaded module zip's checksum and records it, then releases its cache lock, and only afterward re-opens the same on-disk zip file path to extract it — with no re-verification at extraction time. A local user with write access to `GOMODCACHE` can swap the zip's contents in the window between the checksum check and the extraction, exactly mirroring the CVE-2015-8239 pattern of "verify a digest, then act on a mutable path later."

### Finding Description
`Fetcher.download` (`src/cmd/go/internal/modfetch/fetch.go:97-118`) calls `f.DownloadZip(ctx, mod)` to obtain the on-disk zip path, then separately calls `unzip(ctx, mod, zipfile)`. [1](#0-0) 

`DownloadZip` acquires `lockVersion(ctx, mod)`, runs `f.downloadZip` (which hashes the file and checks it via `checkModSum`/`checkSumDB` before an atomic `os.Rename` into the final `zipfile` path), and then releases the lock via `defer unlock()` when the closure returns. [2](#0-1) [3](#0-2) 

`unzip` then independently re-acquires the *same* lock via `lockVersion(ctx, mod)` before extracting the file with `modzip.Unzip(dir, mod, zipfile)`. [4](#0-3) 

Between `DownloadZip`'s `unlock()` and `unzip`'s re-acquisition of the lock, nothing holds the lock, so a concurrent process with write access to the module cache directory can replace the bytes at `zipfile` after the checksum was validated (and recorded into `go.sum`/the `.ziphash` file) but before `modzip.Unzip` reads and extracts it. `unzip` never re-hashes the file it extracts — it trusts the path, not the content, at the moment of use. The only place that re-verifies zip content against the recorded hash is the separate, user-invoked `go mod verify` command (`src/cmd/go/internal/modcmd/verify.go:93-144`), which is not run as part of normal `go build`/`go get` extraction. [5](#0-4) 

This is the same bug class as CVE-2015-8239: a digest is checked against one artifact, but the artifact actually consumed later (extracted, and subsequently compiled/executed as package source) is fetched again from a mutable path with no re-check, leaving a TOCTOU window for anyone with write access to that path.

### Impact Explanation
If exploited, an attacker with concurrent local write access to `GOMODCACHE` (e.g., a shared, multi-tenant, or CI cache directory) could substitute malicious Go source into the extracted module directory that gets built and executed by the victim's `go build`/`go run`, resulting in code execution under the victim's identity — despite `go.sum` verification appearing to have "passed." This would be a PUBLIC-track integrity issue for module authentication, analogous in severity class to the sudo digest bypass, though it depends on a non-default threat model (shared/writable module cache).

### Likelihood Explanation
Requires: (1) a victim running `go build`/`go get`/`go mod download` against a module cache directory that a second, less-trusted local principal can write to, and (2) that second principal winning a narrow race between `DownloadZip`'s lock release and `unzip`'s lock acquisition. This is a real but narrow window (single lock release/reacquire cycle, no I/O in between), so it is a low-probability, timing-dependent race rather than a reliably exploitable primitive.

### Recommendation
Hold the version lock continuously across both the checksum verification and the extraction step (merge `DownloadZip`+`unzip` locking into a single critical section), or have `unzip`/`modzip.Unzip` re-verify the zip's hash against the recorded `.ziphash`/go.sum entry immediately before extracting, rather than trusting the previously-recorded checksum for a file re-opened from a shared path.

### Proof of Concept
A full external race requires two processes; the essential defect can be demonstrated by showing `unzip` performs no hash check on its input:

```go
package modfetch

import (
	"os"
	"path/filepath"
	"testing"

	"golang.org/x/mod/module"
)

// TestUnzipDoesNotReverifyHash demonstrates that unzip() extracts whatever
// bytes currently exist at zipfile's path, without re-checking the hash
// that was verified earlier by DownloadZip/checkMod.
func TestUnzipDoesNotReverifyHash(t *testing.T) {
	dir := t.TempDir()
	zipfile := filepath.Join(dir, "v1.0.0.zip")

	// Simulate: checksum was verified against "good" content earlier,
	// then the file on disk is swapped before unzip() runs (the race window).
	goodZip := buildValidTestZip(t, "example.com/m", "v1.0.0") // helper producing a valid, verified zip
	if err := os.WriteFile(zipfile, goodZip, 0666); err != nil {
		t.Fatal(err)
	}

	// Attacker replaces the file after the hash check but before extraction.
	maliciousZip := buildValidTestZip(t, "example.com/m", "v1.0.0") // different content, same mod/version
	if err := os.WriteFile(zipfile, maliciousZip, 0666); err != nil {
		t.Fatal(err)
	}

	mod := module.Version{Path: "example.com/m", Version: "v1.0.0"}
	if _, err := unzip(t.Context(), mod, zipfile); err != nil {
		t.Fatalf("unzip failed: %v", err)
	}
	// Expected (vulnerable) result: unzip succeeds using the swapped content,
	// with no error about a checksum mismatch, because unzip() never
	// re-hashes zipfile against the previously recorded ziphash.
}
```
Expected assertion: `unzip` extracts the swapped content without any checksum error, confirming there is no re-verification at the point of use.

		return "", err
	}

func (f *Fetcher) DownloadZip(ctx context.Context, mod module.Version) (zipfile string, err error) {
	// The par.Cache here avoids duplicate work.
	return downloadZipCache.Do(mod, func() (string, error) {
		zipfile, err := CachePath(ctx, mod, "zip")
		if err != nil {
			return "", err
		}
		ziphashfile := zipfile + "hash"

		// Return early if the zip and ziphash files exist.
		if _, err := os.Stat(zipfile); err == nil {
			if _, err := os.Stat(ziphashfile); err == nil {
				if !HaveSum(f, mod) {
					f.checkMod(ctx, mod)
				}
				return zipfile, nil
			}
		}

		// The zip or ziphash file does not exist. Acquire the lock and create them.
		if cfg.CmdName != "mod download" {
			vers := mod.Version
			if mod.Path == "golang.org/toolchain" {
				// Shorten v0.0.1-go1.13.1.darwin-amd64 to go1.13.1.darwin-amd64
				_, vers, _ = strings.Cut(vers, "-")
				if i := strings.LastIndex(vers, "."); i >= 0 {
					goos, goarch, _ := strings.Cut(vers[i+1:], "-")
					vers = vers[:i] + " (" + goos + "/" + goarch + ")"
				}
				fmt.Fprintf(os.Stderr, "go: downloading %s\n", vers)
			} else {
				fmt.Fprintf(os.Stderr, "go: downloading %s %s\n", mod.Path, vers)
			}
		}
		unlock, err := lockVersion(ctx, mod)
		if err != nil {
			return "", err
		}
		defer unlock()

		if err := f.downloadZip(ctx, mod, zipfile); err != nil {
			return "", err
		}
		return zipfile, nil
	})
