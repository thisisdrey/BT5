### Title
Unauthenticated `/shutdown` HTTP endpoint on `SignerEventReceiver` allows any remote peer to permanently halt the signer's event loop - (File: libsigner/src/events.rs)

### Summary
`SignerEventReceiver::next_event` treats any HTTP POST to `/shutdown` as authoritative, regardless of its origin, setting `stop_signal` to `true` and returning `Err(EventError::Terminated)`. Since `EventReceiver::main_loop` breaks out of its loop on `EventError::Terminated`, a single unauthenticated POST from an arbitrary TCP client permanently silences the signer's event stream.

### Finding Description
`SignerStopSignaler::send` (the only intended caller of shutdown) works by opening a plain `TcpStream` to the receiver's bound address and sending a raw `POST /shutdown HTTP/1.1` request with no secret, token, or origin check whatsoever: [1](#0-0) 

The server side, in `SignerEventReceiver::next_event`, dispatches purely on `request.url() == "/shutdown"` with no verification of the request's source, no shared secret, and no comparison against any signaler-specific value — it unconditionally stores `true` into `stop_signal` and returns `Terminated`: [2](#0-1) 

The requested equality — "only the node's stop signaler should be able to author a termination" — is not enforced anywhere in the code; the handler only checks the URL path, which is public knowledge and requires no credential to reach, since the HTTP server is bound via `HttpServer::http(listener)` with no auth middleware: [3](#0-2) 

Once `stop_signal` is `true`, `is_stopped()` returns `true` forever (it's a one-way flag, never reset), and `EventReceiver::main_loop` breaks out of its loop on the next `Terminated` or `is_stopped()` check: [4](#0-3) [5](#0-4) 

This permanently halts delivery of `stackerdb_chunks`, `proposal_response`, and `new_burn_block`/`new_block` events to the signer's runloop, with no restart path short of restarting the signer process.

### Impact Explanation
Any remote TCP client that can reach the signer's bound event socket can send one crafted HTTP POST to `/shutdown` and permanently disable that signer's event receiver, cutting it off from block proposals, burn block notifications, and StackerDB chunk events. This is a single-message, unauthenticated, repeatable DoS against a Stacks signer node, which matches the "Critical - remote crash/unauthenticated DoS from few messages" category. The signer configuration explicitly warns that the endpoint is meant to face only the local/trusted node and not be exposed externally, confirming this attack path is only theoretically mitigated by network topology, not by any code-level guard: [6](#0-5) 

### Likelihood Explanation
The only precondition is TCP reachability to the address configured in `config.endpoint`, which the signer binds via `SignerEventReceiver::bind` [3](#0-2) . No secret, key, StackerDB slot ownership, or any privileged role is required — an attacker only needs to know or scan for the bound port. Cost per attack is a single POST request, and the effect is permanent for the life of the process (repeatable trivially against any restart).

### Recommendation
Require the `/shutdown` request to carry a value only the node/stop-signaler can know (e.g., a locally-generated random token embedded at bind time and included by `SignerStopSignaler`, checked in `next_event` before honoring the shutdown), or restrict the shutdown path to loopback-originated connections by checking `request.remote_addr()` against `127.0.0.1`/the configured node IP before acting on `/shutdown`. At minimum, the endpoint should not be reachable from the same network segment as the RPC event dispatcher without additional authentication.

### Proof of Concept
```rust
// libsigner/src/events.rs (test) or a new integration test
use std::io::Write;
use std::net::TcpStream;
use libsigner::{EventReceiver, SignerEventReceiver, EventError};
use crate::v0::messages::SignerMessage; // or any SignerEventTrait impl

#[test]
fn unauthenticated_shutdown_halts_receiver() {
    let mut receiver: SignerEventReceiver<SignerMessage> = SignerEventReceiver::new(false);
    let addr = receiver.bind("127.0.0.1:0".parse().unwrap()).unwrap();

    // Attacker: arbitrary client, no credentials
    let body = "arbitrary";
    let mut stream = TcpStream::connect(addr).unwrap();
    let req = format!(
        "POST /shutdown HTTP/1.1\r\nHost: {}\r\nConnection: close\r\nContent-Length: {}\r\n\r\n{}",
        addr, body.len(), body
    );
    stream.write_all(req.as_bytes()).unwrap();

    // Server side: next_event should now return Terminated permanently
    let result = receiver.next_event();
    assert!(matches!(result, Err(EventError::Terminated)));
    assert!(receiver.is_stopped());

    // Any subsequent call also terminates - the receiver is permanently dead
    let result2 = receiver.next_event();
    assert!(matches!(result2, Err(EventError::Terminated)));
}
```
This reproduces the exact code path at [7](#0-6)  being triggered by an unauthenticated client, without invoking `SignerStopSignaler::send` at all.

                Ok(event) => event,
                Err(EventError::UnrecognizedEvent(..)) => {
                    // got an event that we don't care about (not a problem)
                    continue;
                }

                    // we're done
                    info!("Caught termination signal");
                    break;

                    warn!("Failed to receive next event: {:?}", &e);
                    continue;
                }
            };

                info!("Failed to forward event");
                break;
            }
        }
