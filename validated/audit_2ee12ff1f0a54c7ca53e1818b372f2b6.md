### Title
Protocol fee bypass on `Nep245`/`Imt` `TokenDiff` intents via unit-delta splitting - (File: contracts/defuse/core/src/intents/token_diff.rs)

### Summary
`TokenDiff::execute_intent` computes the protocol fee independently for each `TokenDiff` intent based solely on that intent's own `|delta|`, and `TokenDiff::token_fee` returns `Pips::ZERO` for `Nep245`/`Imt` token types whenever `amount <= 1` [1](#0-0) . An attacker can therefore split a single large fungible withdrawal on a `Nep245`/`Imt` `TokenId` into many `TokenDiff` intents each with `delta = -1`, each evaluated with `amount == 1` and thus fee-exempt, inside one signed `MultiPayload` (a `DefuseIntents` message can carry many intents under a single signature/nonce) [2](#0-1) .

### Finding Description
The binding that should hold is: `fee_collector_credit(batch) == protocol_fee applied to Σ|negative deltas| for a given token across the whole batch`. In practice, `fee_collector_credit(batch) == Σ over each individual TokenDiff intent of token_fee(token_id, |delta_i|, protocol_fee).fee_ceil(|delta_i|)`, evaluated **per intent**, not on the aggregate [3](#0-2) .

For `Nep245`/`Imt` token types, `token_fee` returns `Pips::ZERO` whenever `amount <= 1`:
```
TokenIdType::Nep245 | TokenIdType::Imt if amount > 1 => {}
TokenIdType::Nep171 | TokenIdType::Nep245 | TokenIdType::Imt => return Pips::ZERO,
``` [1](#0-0) 

A single `MultiPayload` is verified once (one signature, one nonce commit via `commit_nonce`), then `intents.execute_intent(...)` is invoked, which dispatches to each contained intent in sequence, including multiple `TokenDiff` intents [4](#0-3) . Because fee computation and `fees_collected` accumulation happen inside each `TokenDiff::execute_intent` call independently (line 56-100), splitting one `delta = -N` movement on a fungible `Nep245`/`Imt` `TokenId` into `N` intents each with `delta = -1` makes every per-intent `amount` equal to `1`, so `token_fee` always returns `Pips::ZERO` and `fee.fee_ceil(1) == 0` for every intent, while the aggregate signer debit and aggregate token movement are identical to a single `delta = -N` intent that would have paid `protocol_fee` on the full `N`.

No existing guard prevents this: nonce/signature verification is at the payload level, not per intent, so a single valid signature covers arbitrarily many split `TokenDiff` intents; `internal_apply_deltas` and `internal_add_balance` correctly track balances but have no knowledge of, or aggregation across, intents for fee purposes.

### Impact Explanation
The signer's aggregate debit on a `Nep245`/`Imt` token (e.g. moving 100 units) is identical whether expressed as one `TokenDiff{delta:-100}` or 100 `TokenDiff{delta:-1}` intents, but the amount credited to `fee_collector` differs: nonzero for the former, zero for the latter. This is a direct protocol-fee bypass — value that should be collected as fee for the protocol/fee_collector never leaves the signer's controlled outflow, an explicitly listed Critical impact category ("protocol fees bypassed or over-collected"). It affects any `Nep245` (multi-token, e.g. wrapped balances routed via other NEP-245 contracts) or `Imt` token type where balances can exceed 1 unit, and is repeatable across accounts, tokens, and batches at no additional cost beyond payload size/gas for extra intents in the same transaction.

### Likelihood Explanation
The attacker needs no special privilege: any signer with a `Nep245`/`Imt` balance representable as `N` unit deltas (e.g., a fungible-style multi-token) can construct one `MultiPayload` containing `N` `TokenDiff` intents, each `{token_id: -1, <opposite counter-token>: +k}` or a pure diff pattern balancing against a matched counterparty in the same or another payload, and submit via `execute_intents`/`simulate_intents`. Cost scales with the number of intents (transaction size/gas), which is bounded by NEAR's per-transaction gas/size limits but still allows meaningful splitting (hundreds of unit-intents per batch) with zero incremental privilege requirement. `protocol_fee > 0` is the only contract-side precondition, which is the normal operating state.

### Recommendation
Compute the fee-exemption threshold on the aggregated `Nep245`/`Imt` delta magnitude across the whole intent batch/message for a given `token_id`, not per individual `TokenDiff` intent — e.g., accumulate all negative deltas per `token_id` at the `DefuseIntents`/engine level before invoking `token_fee`, or drop the `amount <= 1` exemption for `Nep245`/`Imt` tokens whose registered/observed total supply for that `TokenId` exceeds 1 (i.e., only exempt genuinely NFT-like MT ids), and re-evaluate `fee_ceil` against that aggregate.

### Proof of Concept
```
cargo test -p defuse-core token_diff_fee_bypass_via_unit_splitting
```
Test plan:
1. Set `protocol_fee = Pips::ONE_PERCENT` (or any nonzero fee) and a fixed `fee_collector`.
2. Give a signer account a balance of 100 units of a `Nep245`/`Imt` `TokenId` (and enough of a counter-token for a balanced diff, or just test `TokenDiff::execute_intent` directly with only the negative leg, matching how `token_fee`/`fees_collected` are computed independent of balancing).
3. Case A: execute one `TokenDiff::execute_intent` with `diff = {token_id: -100}` and assert `fees_collected`/`fee_collector` balance increases by `Pips::ONE_PERCENT.fee_ceil(100) > 0`.
4. Case B: execute 100 separate `TokenDiff::execute_intent` calls (or 100 `TokenDiff` intents inside one `DefuseIntents` batch under one signature/nonce), each `diff = {token_id: -1}`, and assert cumulative `fee_collector` credit == 0.
5. Assert both cases produce identical signer debit (`-100` total) on `token_id`, but `fee_collector` credit differs (Case A > 0, Case B == 0), proving `fee_collector` credit is not a function of aggregate negative delta alone — confirming the binding violation.

    fn execute_signed_intent(&mut self, signed: MultiPayload) -> Result<()> {
        // verify signed payload and get public key
        let public_key = signed.verify().ok_or(DefuseError::InvalidSignature)?;

        // calculate intent hash
        let hash = signed.hash();

        // extract NEP-413 payload
        let DefusePayload::<DefuseIntents> {
            signer_id,
            verifying_contract,
            deadline,
            nonce,
            message: intents,
        } = signed.extract_defuse_payload()?;

        // check recipient
        if verifying_contract != *self.state.verifying_contract() {
            return Err(DefuseError::WrongVerifyingContract);
        }

        self.inspector.on_deadline(deadline);

        // make sure message is still valid
        if deadline < Timestamp::now() {
            return Err(DefuseError::DeadlineExpired);
        }

        // make sure the account has this public key
        if !self.state.has_public_key(&signer_id, &public_key) {
            return Err(DefuseError::PublicKeyNotExist(signer_id, public_key));
        }

        // commit nonce
        self.verify_intent_nonce(nonce, deadline)?;
        self.state.commit_nonce(signer_id.clone(), nonce)?;

        intents.execute_intent(&signer_id, self, hash)?;
        self.inspector.on_intent_executed(&signer_id, hash, nonce);

        Ok(())
    }
