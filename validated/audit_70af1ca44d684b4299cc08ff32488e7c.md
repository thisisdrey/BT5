### Title
Cross-repository GetArchive cache poisoning via unbound `GlProjectPath` cache key - ([File: internal/gitaly/service/repository/archive.go])

### Summary
`GetArchive` derives its shared, node-wide archive cache key solely from the client-supplied `GlProjectPath` field, `git archive` arguments, and pathspecs, without binding the key to the actual `StorageName`/`RelativePath` of the repository being archived. This is the same root-cause class as the reported `TokenDistributor._hashLeaf` bug: a value used as a unique identity check is built by concatenating attacker-influenced fields that are not properly bound/delimited to the resource they are supposed to represent, enabling one tenant's request to collide with another's cached content.

### Finding Description
`createArchiveCacheKey` hashes only `gitLabProjectPath`, `args`, and `pathspecs`: [1](#0-0) 

This key is used to Fetch/populate a single, shared `s.archiveCache` (a `streamcache.Cache`) for the whole Gitaly node: [2](#0-1) 

`GetArchive` builds `repo := s.localRepoFactory.Build(repository)` from the request's `Repository` message and passes `repo.GetGlProjectPath()` into the cache key. `GetGlProjectPath()` is a plain client-supplied string field on the `Repository` proto (`GlProjectPath`), part of the `storage.Repository` interface: [3](#0-2) 

`ValidateRepository`/`GetRepoPath`, called from `GetArchive`, only validate `StorageName` and `RelativePath` (existence, escaping the storage root, being a valid git directory); nowhere is `GlProjectPath` checked for consistency with the actual storage/relative path being served: [4](#0-3) [5](#0-4) 

Because the cache key omits `StorageName`/`RelativePath` entirely, a client that can reach `GetArchive` for *any* repository it is authorized to access can set the `Repository.GlProjectPath` field to an arbitrary string (e.g., matching another project's path) while pointing `StorageName`/`RelativePath` at its own repository. The resulting cache entry is stored under a key that a legitimate request for the real "victim" project (with the same `GlProjectPath`, commit args and pathspecs) will also compute and hit — causing the victim to be served the attacker's archive content, or vice versa (an attacker crafting a matching key to retrieve a previously cached victim archive from the shared cache). This mirrors the report's core issue: using naive field concatenation/hashing as an implicit authorization/identity check without delimiters or binding to the true resource identity, allowing forged/colliding lookups.

Contrast this with `internal/cache/keyer.go`'s `compositeKeyHashHex`, which explicitly guards against this exact collision class by length-prefixing each component before hashing (`prefixLen`) precisely because naive concatenation of variable-length fields can collide: [6](#0-5) 
The `GetArchive` cache key construction lacks this protection and, more fundamentally, never incorporates the repository's true storage identity at all.

### Impact Explanation
This allows cross-repository/cross-tenant content confusion in the shared archive cache: an authenticated caller for repository A can poison or read cache entries logically associated with repository B by controlling only the untrusted `GlProjectPath` metadata field, without any authorization check binding it to the repository actually being archived. Depending on deployment (multi-tenant Gitaly/GitLab), this is a confidentiality/integrity issue — one project's archived source code could be served to a requester for a different project.

### Likelihood Explanation
Any caller with access to the `GetArchive` RPC (a normal, frequently used ordinary-user RPC for downloading repository archives) can trigger this by simply setting the `GlProjectPath` field of the `Repository` message in the request to an arbitrary value while pointing to a repository they legitimately control. No privileged access, malicious peer, or MITM is required — it is directly reachable from a standard, unprivileged RPC field.

### Recommendation
Include the repository's `StorageName` and `RelativePath` (or another value derived from the verified, canonical repository identity) as required, length-delimited components of `createArchiveCacheKey`, rather than relying on the unverified `GlProjectPath` field. Apply the same length-prefixing/delimiting technique already used in `internal/cache/keyer.go`'s `prefixLen` to all concatenated components (`gitLabProjectPath`, `args`, `pathspecs`, and the added storage identity) to eliminate ambiguous-boundary hash collisions, matching the report's recommendation to avoid unstructured packing of variable-length fields.

### Proof of Concept
1. Attacker has legitimate access to `RepoA` (`StorageName="default"`, `RelativePath="attacker/repoA.git"`).
2. Attacker calls `GetArchive` on `RepoA` but sets `Repository.GlProjectPath = "victim/project"`, with `CommitId`/`Format`/`Path` chosen to match a request the victim is expected to make (or simply guesses/observes common values such as `HEAD`/`tar.gz`).
3. `createArchiveCacheKey("victim/project", args, pathspecs)` is computed and the archive content of `RepoA` is stored into `s.archiveCache` under that key.
4. When the victim's own `GetArchive` call for the real `victim/project` repository executes with the same `args`/`pathspecs`, `createArchiveCacheKey` computes the identical key and `s.archiveCache.Fetch` returns the cached (attacker-controlled) archive instead of generating a fresh one from the victim's actual repository — because the cache key never included `StorageName`/`RelativePath` to disambiguate the two repositories.

// createArchiveCacheKey creates a cache key using the GitLab project's path, the `git archive`
// command arguments and the pathspecs. The goal is to create a key that is unique not only
// across repository, but also across the content of each archive within the same repository.
func createArchiveCacheKey(gitLabProjectPath string, args []string, pathspecs []string) string {
	cacheKeyHash := sha256.New()
	cacheKeyHash.Write([]byte(gitLabProjectPath))
	cacheKeyHash.Write([]byte(strings.Join(args, ",")))
	cacheKeyHash.Write([]byte(strings.Join(pathspecs, ",")))
	return hex.EncodeToString(cacheKeyHash.Sum(nil))
}

// ValidateRelativePath validates a relative path by joining it with rootDir and verifying the result
// is either rootDir or a path within rootDir. Returns clean relative path from rootDir to relativePath
// or an ErrRelativePathEscapesRoot if the resulting path is not contained within rootDir.
func ValidateRelativePath(rootDir, relativePath string) (string, error) {
	absPath := filepath.Join(rootDir, relativePath)
	if rootDir != absPath && !strings.HasPrefix(absPath, rootDir+string(os.PathSeparator)) {
		return "", ErrRelativePathEscapesRoot
	}

	return filepath.Rel(rootDir, absPath)
}

// ValidateGitDirectory validates the directory at the given path looks like a valid
// Git repository. If the path points to a valid directory which doesn't contain the
// expected entries InvalidGitDirectoryError is returned. A directory is considered to
// be valid Git directory if it contains 'objects', 'refs' and 'HEAD'.
func ValidateGitDirectory(path string) error {
	if info, err := os.Stat(path); err != nil {
		return fmt.Errorf("stat: %w", err)
	} else if !info.IsDir() {
		return errors.New("not a directory")
	}

	for _, file := range []string{"objects", "refs", "HEAD"} {
		if _, err := os.Stat(filepath.Join(path, file)); err != nil {
			if !errors.Is(err, fs.ErrNotExist) {
				return fmt.Errorf("stat %q: %w", file, err)
			}

			return InvalidGitDirectoryError{MissingEntry: file}
		}
	}

	return nil
}

// compositeKeyHashHex returns a hex encoded string that is a SHA256 hash sum of
// the composite key made up of the following properties: Gitaly version, gRPC
// method, repo cache current generation ID, protobuf request, and enabled
// feature flags.
func compositeKeyHashHex(ctx context.Context, genID string, req proto.Message) (string, error) {
	method, ok := grpc.Method(ctx)
	if !ok {
		return "", ErrCtxMethodMissing
	}

	reqSum, err := proto.Marshal(req)
	if err != nil {
		return "", err
	}

	h := sha256.New()

	var flagsWithValue []string
	for flag, enabled := range featureflag.FromContext(ctx) {
		flagsWithValue = append(flagsWithValue, flag.FormatWithValue(enabled))
	}
	sort.Strings(flagsWithValue)

	for _, i := range []string{
		version.GetVersion(),
		method,
		genID,
		string(reqSum),
		strings.Join(flagsWithValue, " "),
	} {
		_, err := h.Write(prefixLen(i))
		if err != nil {
			return "", err
		}
	}

	return hex.EncodeToString(h.Sum(nil)), nil
}

// prefixLen reduces the risk of collisions due to different combinations of
// concatenated strings producing the same content.
// e.g. f+oobar and foo+bar concatenate to the same thing: foobar
func prefixLen(s string) []byte {
	return []byte(fmt.Sprintf("%08x%s", len(s), s))
}
