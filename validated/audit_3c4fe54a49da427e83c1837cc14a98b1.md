### Title
Unbounded growth of `DelegatedResourceAccountIndex.toAccounts`/`fromAccounts` list via repeated `FreezeBalanceContract` delegation - ([File: actuator/src/main/java/org/tron/core/actuator/FreezeBalanceActuator.java])

### Summary
`FreezeBalanceActuator.delegateResource()` maintains, for the legacy (non-optimized) delegation index path, a single protobuf-backed list of receiver/owner addresses (`toAccountsList` / `fromAccountsList`) per account, keyed only by the owner/receiver address, with no cap on the number of entries. Any funded account can call `FreezeBalanceContract` repeatedly with distinct `receiverAddress` values (each a freshly created, minimally funded account) and each call permanently appends one more entry to this list, which is loaded fully into memory, deserialized, mutated, and re-serialized on every subsequent operation.

### Finding Description
In `FreezeBalanceActuator.delegateResource` (actuator/src/main/java/org/tron/core/actuator/FreezeBalanceActuator.java), when `dynamicPropertiesStore.supportAllowDelegateOptimization()` is false, the legacy index-maintenance code path executes: [1](#0-0) 
This reads (or creates) a `DelegatedResourceAccountIndexCapsule` for the owner address, and if the `receiverAddress` is not already present in `toAccountsList`, calls `ownerIndexCapsule.addToAccount(receiverAddress)`; symmetrically it updates the receiver's `fromAccountsList`. The capsule implementation places no bound on list size: [2](#0-1) 
Because delegation is only gated by a minimum frozen balance of 1 TRX (`FrozenBalance must be greater than or equal to 1 TRX`, enforced analogously in `FreezeBalanceProcessor.validate`) and `calcFee()` for delegation returns 0 (no extra bandwidth/energy fee beyond the frozen balance itself, which is later unlockable), an attacker can programmatically:
1. Create many new, minimally funded receiver accounts (each just needs to exist as an `AccountCapsule`, which can be auto-created as the receiver during delegation — see `FreezeBalanceActuator.validate` receiver-creation logic).
2. Issue a `FreezeBalanceContract` transaction that delegates a minimal frozen balance (1 TRX) to each new receiver address.
3. Each such transaction appends a new entry to the *same* `DelegatedResourceAccountIndexCapsule` value stored under the owner's key in `DelegatedResourceAccountIndexStore`, growing the value without bound, and forces every future read/deserialize/serialize/write of that key to process an ever-larger protobuf message.

This mirrors the CVE-2016-6580 pattern in the `priority` library: a single logical structure (there, the priority tree keyed by stream ID; here, the delegation index keyed by owner/receiver address) accepts unbounded low-cost entries from a single unprivileged actor, with no maximum enforced, causing unbounded memory allocation and increasing CPU/serialization cost on every subsequent access to that structure.

### Impact Explanation
Because the growing list is stored as a single value under one DB key (`DelegatedResourceAccountIndexStore` keyed by account address), continued abuse inflates that one record's size indefinitely. Every node that processes further delegation transactions from/to the same address must deserialize and re-serialize the entire growing list, causing increasing CPU and memory cost per block that includes such a transaction, and increasing persistent storage (blockchain state) size. In the worst case this could push toward node resource exhaustion/slowdown for nodes replaying or synchronizing the chain, which is a Medium-severity denial-of-service class analogous to the CVE.

### Likelihood Explanation
Likelihood depends on whether `supportAllowDelegateOptimization()` is active on a given network/fork. If the fork enabling `AllowDelegateOptimization` (which replaces the shared-list index with independent per-pair keys, see `DelegateResourceProcessor`/`DelegateResourceActuator`, which do not have this unbounded-list issue) has been activated, this legacy code path is unreachable in practice on that network. I could not fully verify from the indexed code whether this fork is enabled by default or already activated on the reference network configuration, so likelihood is uncertain and conditional on network configuration/fork status.

### Recommendation
- Enforce a maximum size on `toAccountsList`/`fromAccountsList` in `DelegatedResourceAccountIndexCapsule`/`FreezeBalanceActuator`, or require that the optimized (`supportAllowDelegateOptimization`) delegation-index model be mandatory rather than optional, eliminating the legacy shared-list code path entirely.
- If the optimized model is already the default and the legacy path is dead code, remove it to eliminate any risk of it being reachable in alternate configurations.

### Proof of Concept
Conceptual PoC (not executed, based on code reading):
1. Deploy/connect to a java-tron node where `supportAllowDelegateOptimization()` returns false.
2. From attacker-controlled account A with sufficient TRX, repeatedly broadcast `FreezeBalanceContract` transactions with `resource=BANDWIDTH` (or `ENERGY`), `frozenBalance=1_000_000` (1 TRX), and a freshly generated `receiverAddress` for each transaction (receiver accounts are auto-created if absent, per `FreezeBalanceActuator.validate`/execute logic).
3. Each transaction triggers `FreezeBalanceActuator.delegateResource`, which appends the new receiver to A's `DelegatedResourceAccountIndexCapsule.toAccountsList` (and the receiver's `fromAccountsList`), with no upper bound checked.
4. Repeating this thousands of times inflates the single stored index value for account A, increasing serialization/deserialization cost and storage footprint on every node that processes or re-validates transactions referencing account A. [3](#0-2) [4](#0-3)

  private long delegateResource(byte[] ownerAddress, byte[] receiverAddress, boolean isBandwidth,
      long balance, long expireTime) {
    AccountStore accountStore = chainBaseManager.getAccountStore();
    DynamicPropertiesStore dynamicPropertiesStore = chainBaseManager.getDynamicPropertiesStore();
    DelegatedResourceStore delegatedResourceStore = chainBaseManager.getDelegatedResourceStore();
    DelegatedResourceAccountIndexStore delegatedResourceAccountIndexStore = chainBaseManager
        .getDelegatedResourceAccountIndexStore();
    byte[] key = DelegatedResourceCapsule.createDbKey(ownerAddress, receiverAddress);
    //modify DelegatedResourceStore
    DelegatedResourceCapsule delegatedResourceCapsule = delegatedResourceStore
        .get(key);
    if (delegatedResourceCapsule != null) {
      if (isBandwidth) {
        delegatedResourceCapsule.addFrozenBalanceForBandwidth(balance, expireTime);
      } else {
        delegatedResourceCapsule.addFrozenBalanceForEnergy(balance, expireTime);
      }
    } else {
      delegatedResourceCapsule = new DelegatedResourceCapsule(
          ByteString.copyFrom(ownerAddress),
          ByteString.copyFrom(receiverAddress));
      if (isBandwidth) {
        delegatedResourceCapsule.setFrozenBalanceForBandwidth(balance, expireTime);
      } else {
        delegatedResourceCapsule.setFrozenBalanceForEnergy(balance, expireTime);
      }

    }
    delegatedResourceStore.put(key, delegatedResourceCapsule);

    //modify DelegatedResourceAccountIndexStore
    if (!dynamicPropertiesStore.supportAllowDelegateOptimization()) {

      DelegatedResourceAccountIndexCapsule ownerIndexCapsule =
          delegatedResourceAccountIndexStore.get(ownerAddress);
      if (ownerIndexCapsule == null) {
        ownerIndexCapsule = new DelegatedResourceAccountIndexCapsule(
            ByteString.copyFrom(ownerAddress));
      }
      List<ByteString> toAccountsList = ownerIndexCapsule.getToAccountsList();
      if (!toAccountsList.contains(ByteString.copyFrom(receiverAddress))) {
        ownerIndexCapsule.addToAccount(ByteString.copyFrom(receiverAddress));
      }
      delegatedResourceAccountIndexStore.put(ownerAddress, ownerIndexCapsule);

      DelegatedResourceAccountIndexCapsule receiverIndexCapsule
          = delegatedResourceAccountIndexStore.get(receiverAddress);
      if (receiverIndexCapsule == null) {
        receiverIndexCapsule = new DelegatedResourceAccountIndexCapsule(
            ByteString.copyFrom(receiverAddress));
      }
      List<ByteString> fromAccountsList = receiverIndexCapsule
          .getFromAccountsList();
      if (!fromAccountsList.contains(ByteString.copyFrom(ownerAddress))) {
        receiverIndexCapsule.addFromAccount(ByteString.copyFrom(ownerAddress));
      }
      delegatedResourceAccountIndexStore.put(receiverAddress, receiverIndexCapsule);

    } else {
      // modify DelegatedResourceAccountIndexStore new
      delegatedResourceAccountIndexStore.convert(ownerAddress);
      delegatedResourceAccountIndexStore.convert(receiverAddress);
      delegatedResourceAccountIndexStore.delegate(ownerAddress, receiverAddress,
          dynamicPropertiesStore.getLatestBlockHeaderTimestamp());
    }
