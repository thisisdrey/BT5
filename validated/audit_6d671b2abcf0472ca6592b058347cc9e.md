### Title
Missing authorization binding between repository and object pool in `LinkRepositoryToObjectPool` allows cross-repository object pool linking - (File: internal/gitaly/service/objectpool/link.go)

### Summary
`LinkRepositoryToObjectPool` and the underlying `objectpool.Link` function will link *any* repository to *any* existing, valid object pool on the same storage, with no check that the two are actually supposed to be associated (e.g. that the repository is a fork/descendant of one of the pool's legitimate members). This mirrors the Alchemix Bribe bug class: a state-mutating operation that is supposed to be gated by a relationship check (gauge ↔ bribe, analogous to fork-parent ↔ pool) instead only validates generic, unrelated preconditions (token whitelisting ↔ "is this a valid pool repository").

### Finding Description
The RPC handler only validates that the `repository` field is a valid repository and that the `object_pool` field resolves to a valid, existing pool repository: [1](#0-0) 

`poolForRequest` (shared by `Link`, `Delete`, and `FetchIntoObjectPool`) resolves the pool purely from its own on-disk validity — it never checks that the *target* repository is authorized to join that specific pool: [2](#0-1) 

The actual linking logic, `objectpool.Link`, simply writes the pool's path into the repository's `objects/info/alternates` file once it determines the repository is not already linked — again with no ownership/membership check, only a check that an existing alternates entry doesn't already point elsewhere: [3](#0-2) 

The only "access control"-like validation anywhere in this call chain is `ObjectPool.IsValid`, which just confirms the pool path is a legitimate repository — not that it's the *correct* pool for the given member: [4](#0-3) 

This is structurally identical to the reported Bribe flaw: `addRewardToken()` is meant to be the sole, access-controlled entry point deciding *which* whitelisted token may join *this specific* bribe's reward list, but `notifyRewardAmount()` reaches the same state mutation (`_addRewardToken`) while only validating an unrelated, broader precondition (global whitelist status) instead of the specific relationship. Here, `LinkRepositoryToObjectPool` is meant to establish a specific, intentional relationship (repository ↔ its own object pool), but the code only validates broad, unrelated preconditions (repository well-formedness, pool well-formedness) instead of the actual relationship between the two, which is left entirely to the RPC's caller.

### Impact Explanation
Because there's no server-side check binding `repository` to `object_pool`, any caller able to issue the `LinkRepositoryToObjectPool` RPC (or the sibling `FetchIntoObjectPool`, which likewise only checks that `origin` and `object_pool` share a storage name: [5](#0-4) ) can link an arbitrary repository to an arbitrary, unrelated object pool that already exists on the same storage. Since alternates grant the linked repository read access to every object contained in the pool, this allows cross-repository object disclosure — objects that were only ever pushed to an unrelated (potentially private) repository become readable through a repository the attacker controls, purely because they share a pool that the attacker did not create the relationship for. It can also corrupt an unrelated pool's consistency (bitmap removal side effects, `FetchIntoObjectPool` importing refs from an attacker-chosen `origin` into a pool used by other, legitimate members), degrading or denial-of-servicing pool housekeeping for those members.

### Likelihood Explanation
Gitaly's RPC surface here is designed to be driven by a trusted orchestrator (GitLab Rails/Praefect) that is expected to perform the repository↔pool relationship check before calling these RPCs; Gitaly itself performs no such check. Exploitability therefore depends on whether a caller can reach these mutator RPCs directly with a crafted `object_pool`/`origin` field (e.g., through a compromised or insufficiently-validated internal API path, or any component that forwards user-influenced repository identifiers into these fields) rather than via a privileged/leaked-token attacker — the vulnerability is squarely gitaly's failure to enforce a relationship invariant that its own documentation (`doc/object_pools.md`) describes as a security-relevant lifecycle step, without gating it in code.

### Recommendation
`LinkRepositoryToObjectPool` (and `FetchIntoObjectPool`) should not rely solely on validating that each side of the request is independently well-formed. Gitaly should enforce that the `repository` being linked is actually an intended member of the given pool (e.g., by recording/verifying pool membership metadata — such as the ancestry/fork relationship or an explicit pool-ownership record — rather than trusting the caller-supplied pairing of `repository` and `object_pool`/`origin`).

### Proof of Concept
1. Create object pool `A` from repository `R1` via `CreateObjectPool` (origin `R1`).
2. As a caller with access to the `ObjectPoolService`, call `LinkRepositoryToObjectPool` with `repository = R2` (an unrelated repository the attacker controls) and `object_pool = A`.
3. `poolForRequest` succeeds because pool `A` is a valid pool repository; `objectpool.Link` writes `A`'s object directory into `R2/objects/info/alternates` — no check is made that `R2` was ever forked from or otherwise entitled to join `A`.
4. `R2` can now read every object present in pool `A`, including objects that were only ever part of `R1` (or any other member fetched into `A` via `FetchIntoObjectPool`), demonstrating cross-repository object disclosure with no relationship authorization performed by Gitaly itself.

func (s *server) LinkRepositoryToObjectPool(ctx context.Context, req *gitalypb.LinkRepositoryToObjectPoolRequest) (*gitalypb.LinkRepositoryToObjectPoolResponse, error) {
	repository := req.GetRepository()
	if err := s.locator.ValidateRepository(ctx, repository); err != nil {
		return nil, structerr.NewInvalidArgument("%w", err)
	}

	pool, err := s.poolForRequest(ctx, req)
	if err != nil {
		return nil, err
	}

func (s *server) poolForRequest(ctx context.Context, req PoolRequest) (*objectpool.ObjectPool, error) {
	pool, err := objectpool.FromProto(ctx, s.logger, s.locator, s.gitCmdFactory, s.catfileCache, s.txManager, s.housekeepingManager, req.GetObjectPool())
	if err != nil {
		if errors.Is(err, objectpool.ErrInvalidPoolDir) {
			return nil, errInvalidPoolDir
		}

		if errors.Is(err, objectpool.ErrInvalidPoolRepository) {
			return nil, structerr.NewFailedPrecondition("%w", err)
		}

		return nil, structerr.NewInternal("%w", err)
	}

	return pool, nil
```

func Link(ctx context.Context, pool, repo *localrepo.Repo, txManager transaction.Manager) (returnedErr error) {
	altPath, err := repo.InfoAlternatesPath(ctx)
	if err != nil {
		return err
	}

	expectedRelPath, err := getRelativeObjectPath(ctx, pool, repo)
	if err != nil {
		return err
	}

	linked, err := linkedToRepository(ctx, pool, repo)
	if err != nil {
		return err
	}

	if linked {
		// When the repository is already linked to the repository, cast a vote to ensure the
		// repository is consistent with the other replicas.
		if err := transaction.VoteOnContext(ctx, txManager, voting.VoteFromData([]byte("repository linked")), voting.Synchronized); err != nil {
			return fmt.Errorf("vote on linked repository: %w", err)
		}

		return nil
	}

	alternatesWriter, err := safe.NewLockingFileWriter(altPath)
	if err != nil {
		return fmt.Errorf("creating alternates writer: %w", err)
	}
	defer func() {
		if err := alternatesWriter.Close(); err != nil && returnedErr == nil {
			returnedErr = fmt.Errorf("closing alternates writer: %w", err)
		}
	}()

	if _, err := io.WriteString(alternatesWriter, expectedRelPath); err != nil {
		return fmt.Errorf("writing alternates: %w", err)
	}

	if err := transaction.CommitLockedFile(ctx, txManager, alternatesWriter); err != nil {
		return fmt.Errorf("committing alternates: %w", err)
	}
```

func validateFetchIntoObjectPoolRequest(req *gitalypb.FetchIntoObjectPoolRequest) error {
	if req.GetOrigin() == nil {
		return errors.New("origin is empty")
	}

	if req.GetObjectPool() == nil {
		return errors.New("object pool is empty")
	}

	originRepository, poolRepository := req.GetOrigin(), req.GetObjectPool().GetRepository()

	if originRepository.GetStorageName() != poolRepository.GetStorageName() {
		return errors.New("origin has different storage than object pool")
	}

	return nil
}
