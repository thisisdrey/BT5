### Title
Cluster-wide DoS via shared error-tracker cap in Praefect's `HealthClient` circuit breaker - ([File: internal/praefect/nodes/tracker/errors.go])

### Summary
Praefect's `ErrorTracker` accumulates read/write RPC error counts keyed only by physical `nodeStorage`, not by repository, virtual storage tenant, or client. Any client whose requests route through Praefect to a given Gitaly storage node can drive up this shared counter with cheap-to-trigger failing RPCs until the configured `ReadErrorThresholdCount`/`WriteErrorThresholdCount` is reached, tripping the health-check circuit breaker for the entire node and causing failover/unhealthy marking that affects every repository hosted on that node — an analog of the reported flash-loan-driven `cap` exhaustion that blocks unrelated users.

### Finding Description
`errorTracker` stores `readErrors`/`writeErrors` in maps keyed solely by `node` (physical storage name), incrementing on every failed accessor/mutator RPC observed by the `catchErrorStreamer` client interceptor: [1](#0-0) [2](#0-1) 

`HealthClient.Check` short-circuits the actual gRPC health check and reports failure purely based on whether the shared threshold has been reached for that storage: [3](#0-2) 

Because the tracking key is the node's storage name — not repository, virtual storage tenant, or requesting user — any RPC that fails against that physical node (accessor or mutator) contributes to the same rolling-window bucket used by every other repository/tenant sharing that node, exactly like the reported `OrigamiCircuitBreakerAllUsersPerPeriod.preCheck` bucket that is shared across all users regardless of who generates the volume: [4](#0-3) 

An unprivileged tenant with access to any repository routed to that physical node can cheaply generate failing RPCs (e.g., malformed/invalid requests that the backend Gitaly node rejects with errors) to intentionally exhaust the shared error budget within `ErrorThresholdWindow`, without needing elevated privileges or access to other tenants' repositories.

### Impact Explanation
Once the threshold is reached, `HealthClient.Check` reports the node as unhealthy regardless of its real state, which feeds into the election/failover logic (`localElector.checkNodes`, `nodeStatus.updateStatus`/`isHealthy`) that demotes the primary or marks it down cluster-wide: [5](#0-4) [6](#0-5) 

Because the physical storage node typically hosts many repositories/tenants, tripping this breaker causes a denial of service (unwanted failover, or complete unavailability for the shard's virtual storage) for all unrelated repositories on that node — not just the attacker's own repository. This mirrors the reported bug class: an inexpensive, unprivileged action fills a shared cap and blocks legitimate operations for other users.

### Likelihood Explanation
The requirement is only that the attacker can issue RPCs (accessor or mutator) against a repository whose data is served by the targeted physical storage, and that some of those RPCs fail (which can be induced deliberately, e.g., via crafted invalid arguments, or by inducing timeouts/errors reliably). No special privilege beyond ordinary repository access is required, and `WriteErrorThresholdCount`/`ReadErrorThresholdCount` in typical configurations are modest counts within a window (as validated in tests, e.g. thresholds of 5) which are easy to exceed programmatically: [7](#0-6) 

### Recommendation
Scope the error tracker key to something that cannot be cheaply manipulated by a single unprivileged tenant relative to the blast radius of the resulting action — e.g., require a much larger, load-proportional threshold, incorporate rate limiting per-client/per-repository before RPCs reach the shared tracker, or require corroborating failures from multiple distinct repositories/clients before tripping the node-wide circuit breaker. Consider decoupling "individual repository/RPC failure" from "physical node health" so that a burst of failures confined to one repository cannot single-handedly flip the health state of an entire shard.

### Proof of Concept
1. Attacker has ordinary write/read access to a repository `R` whose primary is served by Gitaly storage node `N` behind Praefect with `Failover.Enabled = true` and a configured `ErrorThresholdWindow`/`WriteErrorThresholdCount` (e.g. 5).
2. Attacker repeatedly issues mutator (or accessor) RPCs against `R` crafted to fail on the Gitaly backend (e.g., invalid ref names, malformed pack data, or any deterministic backend error), each failure incrementing `errorTracker.writeErrors[N]` (or `readErrors[N]`) via `catchErrorStreamer.SendMsg`/`RecvMsg`: [1](#0-0) 
3. Once `WriteThresholdReached(N)` (or `ReadThresholdReached(N)`) becomes true within the window, `HealthClient.Check` starts failing health checks for node `N` regardless of its true health: [3](#0-2) 
4. The election strategy observes repeated failed health checks and demotes/marks node `N` unhealthy, disrupting service for all other repositories hosted on `N` — even though only the attacker's own repository `R` generated the failing traffic.

// ErrorTracker allows tracking how many read/write errors have occurred, and whether or not it has

// IncrReadErr increases the read errors for a node by 1
func (e *errorTracker) IncrReadErr(node string) {
	e.incrReadErrTime(node, time.Now())
}

func (e *errorTracker) incrReadErrTime(node string, t time.Time) {
	select {
	case <-e.ctx.Done():
		return
	default:
		e.m.Lock()
		defer e.m.Unlock()

		e.readErrors[node] = append(e.readErrors[node], t)

		if len(e.readErrors[node]) > e.readThreshold {
			e.readErrors[node] = e.readErrors[node][1:]
		}
	}
}

// Check circuit breaks the health check if write or read error thresholds have been reached. If not, it performs
// the health check.
func (hc HealthClient) Check(ctx context.Context, req *grpc_health_v1.HealthCheckRequest, opts ...grpc.CallOption) (*grpc_health_v1.HealthCheckResponse, error) {
	if hc.tracker.ReadThresholdReached(hc.storage) {
		return nil, fmt.Errorf("read error threshold reached for storage %q", hc.storage)
	}

	if hc.tracker.WriteThresholdReached(hc.storage) {
		return nil, fmt.Errorf("write error threshold reached for storage %q", hc.storage)
	}

	return hc.HealthClient.Check(ctx, req, opts...)
}

// checkNodes issues a gRPC health check for each node managed by the
// shard.
func (s *localElector) checkNodes(ctx context.Context) error {
	defer s.updateMetrics()

	var wg sync.WaitGroup
	for _, n := range s.nodes {
		wg.Add(1)
		go func(n Node) {
			defer wg.Done()
			_, _ = n.CheckHealth(ctx)
		}(n)
	}
	wg.Wait()

	s.m.Lock()
	defer s.m.Unlock()

	if s.primaryNode.IsHealthy() {
		return nil
	}

	var newPrimary Node

	for _, node := range s.nodes {
		if node != s.primaryNode && node.IsHealthy() {
			newPrimary = node
			break
		}
	}

	if newPrimary == nil {
		return ErrPrimaryNotHealthy
	}

	s.primaryNode = newPrimary

	return nil
}

func (n *nodeStatus) IsHealthy() bool {

func (n *nodeStatus) isHealthy() bool {
	if len(n.statuses) < healthcheckThreshold {
		return false
	}

	for _, ok := range n.statuses[len(n.statuses)-healthcheckThreshold:] {
		if !ok {
			return false
		}
	}

	return true
}

func (n *nodeStatus) updateStatus(status bool) {
	n.mtx.Lock()
	n.statuses = append(n.statuses, status)
	if len(n.statuses) > healthcheckThreshold {
		n.statuses = n.statuses[1:]
	}
	n.mtx.Unlock()
}
