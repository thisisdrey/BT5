### Title
Legacy (non-hardened) Exchange AMM calculation path lacks invariant/sanity checks, allowing pool balance manipulation - (File: `chainbase/src/main/java/org/tron/core/capsule/ExchangeCapsule.java`)

### Summary
`ExchangeCapsule.transaction()`, invoked from `ExchangeTransactionActuator.execute()`/`doValidate()`, computes new AMM pool balances using either a legacy `ExchangeProcessor` (double-precision Bancor-style math) or a "hardened" `SafeExchangeProcessor` (BigDecimal math with an explicit non-negative balance invariant check), depending on the `allowHardenExchangeCalculation` dynamic property. The invariant check that guards against corrupted/negative pool state is only executed when `hardenedCalc == true`; the default/legacy path performs no equivalent sanity check, analogous to the missing `seemsLegit`/pause checks described in the external report.

### Finding Description
`ExchangeCapsule.transaction()` selects the processor and only validates the resulting balances in the hardened branch: [1](#0-0) 

The negative-balance invariant (`if (hardenedCalc && (newFirstTokenBalance < 0 || newSecondTokenBalance < 0)) throw ...`) is gated by `hardenedCalc`, so when the actuator runs in legacy mode this consistency check for the exchange pool state (the AMM analog of "seemsLegit") is skipped entirely.

`ExchangeTransactionActuator` (reachable from any signed `ExchangeTransactionContract` broadcast by any account) passes `allowHarden()` directly into `transaction()`, and `allowHarden()` simply reflects a chain-wide dynamic property that must be toggled on by a committee proposal: [2](#0-1) [3](#0-2) 

The legacy `ExchangeProcessor` relies on `double` arithmetic for the Bancor-style relay-token math and never checks whether the resulting balances make sense (e.g., could go negative due to precision loss/overflow at extreme inputs), unlike the hardened processor: [4](#0-3) [5](#0-4) 

The only other guard in the actuator is `tokenExpected` in `doValidate()`, which protects the caller from getting less than expected — it does not protect exchange pool integrity: [6](#0-5) 

### Impact Explanation
If a value of `sellTokenQuant`/pool state combination that yields negative or otherwise corrupted balances in the legacy double-precision path is reachable via a normal `ExchangeTransactionContract`, the check that would otherwise reject it (as demonstrated only in `hardenedCalc=true` unit tests, e.g. `testHardenedTransactionNegativeBalanceThrows`) is bypassed in the default/legacy path. This is speculative without a demonstrated concrete input that breaks `double` math to go negative on the legacy path — I could not confirm within available tooling that such an input exists, since the dynamic property gating `hardenedCalc` and the exact numeric conditions for a legacy-path exploit were not fully traced.

### Likelihood Explanation
The `ExchangeTransactionContract` is reachable directly from any signed transaction (unprivileged), so an attacker fully controls `tokenID`/`tokenQuant`/`exchangeId` inputs to `ExchangeCapsule.transaction()`. However, whether the legacy `double`-based Bancor formula can actually be forced into producing negative/inconsistent balances (as opposed to merely producing rounding-error losses) is not verified here.

### Recommendation
Apply the same non-negative/consistency invariant check to the legacy (non-hardened) `ExchangeProcessor` path in `ExchangeCapsule.transaction()`, not just the hardened path, so pool balance sanity is guaranteed regardless of the `allowHardenExchangeCalculation` toggle.

### Proof of Concept
Not concretely demonstrated. Unit tests (`ExchangeCapsuleTest.testHardenedTransactionNegativeBalanceThrows`) confirm the invariant check exists and is exercised only when `hardenedCalc=true`; a PoC for the legacy path would require identifying specific pool-balance/quant inputs where the `double`-based `ExchangeProcessor` computation drives `newFirstTokenBalance` or `newSecondTokenBalance` negative, which was not established with the available tools.

  public long transaction(byte[] sellTokenID, long sellTokenQuant, boolean useStrictMath,
      boolean hardenedCalc) throws ContractValidateException {
    long supply = 1_000_000_000_000_000_000L;
    Processor processor = hardenedCalc
        ? SafeExchangeProcessor.INSTANCE : new ExchangeProcessor(supply, useStrictMath);

    long buyTokenQuant = 0;
    long firstTokenBalance = this.exchange.getFirstTokenBalance();
    long secondTokenBalance = this.exchange.getSecondTokenBalance();
    long newFirstTokenBalance;
    long newSecondTokenBalance;

    if (this.exchange.getFirstTokenId().equals(ByteString.copyFrom(sellTokenID))) {
      buyTokenQuant = processor.exchange(firstTokenBalance,
          secondTokenBalance,
          sellTokenQuant);
      newFirstTokenBalance = hardenedCalc
          ? StrictMathWrapper.addExact(firstTokenBalance, sellTokenQuant)
          : firstTokenBalance + sellTokenQuant;
      newSecondTokenBalance = hardenedCalc
          ? StrictMathWrapper.subtractExact(secondTokenBalance, buyTokenQuant)
          : secondTokenBalance - buyTokenQuant;

    } else {
      buyTokenQuant = processor.exchange(secondTokenBalance,
          firstTokenBalance,
          sellTokenQuant);
      newFirstTokenBalance = hardenedCalc
          ? StrictMathWrapper.subtractExact(firstTokenBalance, buyTokenQuant)
          : firstTokenBalance - buyTokenQuant;
      newSecondTokenBalance = hardenedCalc
          ? StrictMathWrapper.addExact(secondTokenBalance, sellTokenQuant)
          : secondTokenBalance + sellTokenQuant;

    }

    if (hardenedCalc && (newFirstTokenBalance < 0 || newSecondTokenBalance < 0)) {
      throw new ContractValidateException("Exchange balance must be >=0 after transaction");
    }
    this.exchange = this.exchange.toBuilder()
        .setFirstTokenBalance(newFirstTokenBalance)
        .setSecondTokenBalance(newSecondTokenBalance)
        .build();

    return buyTokenQuant;

  private long exchangeToSupply(long balance, long quant) {
    logger.debug("balance: " + balance);
    long newBalance = balance + quant;
    logger.debug("balance + quant: " + newBalance);

    double issuedSupply = -supply * (1.0
        - Maths.pow(1.0 + (double) quant / newBalance, 0.0005, this.useStrictMath));
    logger.debug("issuedSupply: " + issuedSupply);
    long out = (long) issuedSupply;
    supply += out;

    return out;
  }

  private long exchangeFromSupply(long balance, long supplyQuant) {
    supply -= supplyQuant;

    double exchangeBalance = balance
        * (Maths.pow(1.0 + (double) supplyQuant / supply, 2000.0, this.useStrictMath) - 1.0);
    logger.debug("exchangeBalance: " + exchangeBalance);

    return (long) exchangeBalance;
  }

  @Override
  public long exchange(long sellTokenBalance, long buyTokenBalance, long sellTokenQuant) {
    long relay = exchangeToSupply(sellTokenBalance, sellTokenQuant);
    return exchangeFromSupply(buyTokenBalance, relay);
  }

  private BigDecimal exchangeToSupply(long balance, long quant) {
    long newBalance = StrictMathWrapper.addExact(balance, quant);
    BigDecimal bdQuant = BigDecimal.valueOf(quant);
    BigDecimal bdNewBalance = BigDecimal.valueOf(newBalance);
    BigDecimal base = BigDecimal.ONE.add(
        bdQuant.divide(bdNewBalance, 18, RoundingMode.HALF_UP));
    double powResult = StrictMathWrapper.pow(base.doubleValue(), 0.0005);
    return SUPPLY.negate().multiply(
        BigDecimal.ONE.subtract(BigDecimal.valueOf(powResult))).setScale(0, RoundingMode.DOWN);
  }

  private long exchangeFromSupply(long balance, BigDecimal supplyQuant) {
    BigDecimal bdBalance = BigDecimal.valueOf(balance);
    BigDecimal base = BigDecimal.ONE.add(
        supplyQuant.divide(SUPPLY, 18, RoundingMode.HALF_UP));
    double powResult = StrictMathWrapper.pow(base.doubleValue(), 2000.0);
    BigDecimal exchangeBalance = bdBalance.multiply(
        BigDecimal.valueOf(powResult).subtract(BigDecimal.ONE));
    return exchangeBalance.setScale(0, RoundingMode.DOWN).longValueExact();
  }

  @Override
  public long exchange(long sellTokenBalance, long buyTokenBalance, long sellTokenQuant) {
    BigDecimal relay = exchangeToSupply(sellTokenBalance, sellTokenQuant);
