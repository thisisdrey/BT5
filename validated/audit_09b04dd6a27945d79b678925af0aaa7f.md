### Title
Unstaked stream-throttling quota is scoped per-connection, allowing QoS evasion via connection churn - ([File: streamer/src/nonblocking/stream_throttle.rs])

### Finding Description
The unstaked stream rate limit is enforced entirely inside a per-connection `ConnectionStreamCounter`, which is freshly allocated for every new connection by `SwQos::cache_new_connection` via `Arc::new(ConnectionStreamCounter::new())` [1](#0-0) . `throttle_stream` only consults this per-connection counter and `ConnectionStreamCounter::reset_throttling_params_if_needed`, comparing `stream_count` against `max_streams_per_throttling_interval` for the last `STREAM_THROTTLING_INTERVAL_MS` (100ms) window [2](#0-1) .

Critically, the global `StakedStreamLoadEMA` that governs `available_load_capacity_in_throttling_duration` only accumulates load from staked peers — `increment_load` guards the accumulation with `if peer_type.is_staked()` [3](#0-2) . Unstaked traffic is never fed into any cross-connection accounting structure; the only cap applied to an unstaked peer is `max_unstaked_load_in_throttling_window = MAX_UNSTAKED_TPS * STREAM_THROTTLING_INTERVAL_MS / 1000` (20 streams per 100ms, i.e. 200 TPS) applied per `ConnectionStreamCounter` instance [4](#0-3) [5](#0-4) .

Because each new QUIC connection gets a brand-new `ConnectionStreamCounter` with `stream_count = 0`, an attacker who exhausts the 200 TPS budget on connection A can simply open connection B (bounded only by `max_connections_per_unstaked_peer`/`max_unstaked_connections` table capacity and the `ConnectionRateLimiter` token bucket burst) and immediately get a fresh, unthrottled 200 TPS budget, multiplying effective per-IP unstaked throughput by however many concurrent/churned connections are permitted.

### Impact Explanation
This is a QoS-evasion class issue: unstaked senders can exceed the intended `MAX_UNSTAKED_TPS` cap by a factor bounded only by `max_connections_per_unstaked_peer` and connection-table pruning behavior in `SwQos::prune_unstaked_connections_and_add_new_connection` / `prune_unstaked_connection_table` [6](#0-5) , rather than the intended single 200 TPS/connection design limit. Because the leader's overall unstaked stream capacity is a shared, finite resource, this lets one attacker capture disproportionate TPU stream bandwidth, starving other unstaked senders — matching the "QoS evasion" bounty category referenced in the question, scoped to unfair capacity capture rather than any consensus or memory-safety break.

### Likelihood Explanation
The preconditions are all attacker-controlled and require no privilege: an unstaked remote client can open multiple concurrent QUIC connections (up to `max_connections_per_unstaked_peer`) or churn connections (open new after old closes) as long as it has burst tokens left in the `ConnectionRateLimiter`'s `TokenBucket` [7](#0-6) . Since the per-connection throttle window is only 100ms, and connection setup/teardown is cheap for an attacker, sustained multiplication of effective throughput is feasible as long as new-connection admission (rate limiter burst + per-peer connection cap) keeps pace with the churn rate.

### Recommendation
Track unstaked stream load in a per-source (e.g., per-IP or per-connection-table) global accounting structure analogous to `StakedStreamLoadEMA`, rather than solely in a per-connection counter that resets to zero on every new connection. Alternatively, key the throttling counter by the connection's remote IP (as already used in `ConnectionTableKey`) rather than by the ephemeral `ConnectionStreamCounter` instance, so that the quota persists across connection churn until the interval genuinely elapses.

    fn prune_unstaked_connection_table(
        &self,
        unstaked_connection_table: &mut ConnectionTable<ConnectionStreamCounter>,
        max_unstaked_connections: usize,
        stats: Arc<StreamerStats>,
    ) {
        if unstaked_connection_table.total_size >= max_unstaked_connections {
            // Prune the connection table down to 90% capacity
            const PRUNE_TABLE_RATIO: f64 = 0.90;
            let max_connections = (PRUNE_TABLE_RATIO * (max_unstaked_connections as f64)) as usize;

                .num_evictions_unstaked
                .fetch_add(num_pruned, Ordering::Relaxed);
        }
    }

    pub(crate) fn available_load_capacity_in_throttling_duration(
        &self,
        peer_type: ConnectionPeerType,
        total_stake: u64,
    ) -> u64 {
        match peer_type {
            ConnectionPeerType::Unstaked => self.max_unstaked_load_in_throttling_window,
            ConnectionPeerType::Staked(stake) => {
                if self.staked_throttling_enabled.load(Ordering::Relaxed) {
                    // 1 is added to `max_unstaked_load_in_throttling_window` to guarantee that staked
                    // clients get at least 1 more number of streams than unstaked connections.
                    self.max_staked_load_in_throttling_window
                        .saturating_mul(stake)
                        .checked_div(total_stake)
                        .unwrap_or(self.max_unstaked_load_in_throttling_window + 1)
                        .max(self.max_unstaked_load_in_throttling_window + 1)
                } else {
                    self.max_staked_load_in_throttling_window
                }
            }
        }
    }

    /// Reset the counter and last throttling instant and
    /// return last_throttling_instant regardless it is reset or not.
    pub(crate) fn reset_throttling_params_if_needed(&self) -> tokio::time::Instant {
        let last_throttling_instant = *self.last_throttling_instant.read().unwrap();
        if tokio::time::Instant::now().duration_since(last_throttling_instant)
            > STREAM_THROTTLING_INTERVAL
        {
            let mut last_throttling_instant = self.last_throttling_instant.write().unwrap();
            // Recheck as some other thread might have done throttling since this thread tried to acquire the write lock.
            if tokio::time::Instant::now().duration_since(*last_throttling_instant)
                > STREAM_THROTTLING_INTERVAL
            {
                *last_throttling_instant = tokio::time::Instant::now();
                self.stream_count.store(0, Ordering::Relaxed);
            }
            *last_throttling_instant
        } else {
            last_throttling_instant
        }
    }
}

pub(crate) async fn throttle_stream(
    stats: &StreamerStats,
    peer_type: ConnectionPeerType,
    remote_addr: std::net::SocketAddr,
    stream_counter: &Arc<ConnectionStreamCounter>,
    max_streams_per_throttling_interval: u64,
) {
    let throttle_interval_start = stream_counter.reset_throttling_params_if_needed();
    let streams_read_in_throttle_interval = stream_counter.stream_count.load(Ordering::Relaxed);
    if streams_read_in_throttle_interval >= max_streams_per_throttling_interval {
        // The peer is sending faster than we're willing to read. Sleep for what's
        // left of this read interval so the peer backs off.
        let throttle_duration =
            STREAM_THROTTLING_INTERVAL.saturating_sub(throttle_interval_start.elapsed());

        if !throttle_duration.is_zero() {
            debug!(
                "Throttling stream from {remote_addr:?}, peer type: {peer_type:?}, \
                 max_streams_per_interval: {max_streams_per_throttling_interval}, \
                 read_interval_streams: {streams_read_in_throttle_interval} throttle_duration: \
                 {throttle_duration:?}"
            );
            stats.throttled_streams.fetch_add(1, Ordering::Relaxed);
            match peer_type {
                ConnectionPeerType::Unstaked => {
                    stats
                        .throttled_unstaked_streams
                        .fetch_add(1, Ordering::Relaxed);
                }
                ConnectionPeerType::Staked(_) => {
                    stats
                        .throttled_staked_streams
                        .fetch_add(1, Ordering::Relaxed);
                }
            }
            sleep(throttle_duration).await;
        }
    }
