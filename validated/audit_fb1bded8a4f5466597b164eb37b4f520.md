### Title
UDP TPU-vote receiver statically marks all packets `FROM_STAKED_NODE`, letting unstaked attackers pass `ForwardingStage::initial_packet_meta_filter` and consume sanitize/priority/forward resources - ([File: core/src/forwarding_stage.rs])

### Summary
`ForwardingStage`'s `initial_packet_meta_filter` gates per-packet sanitize/priority/forward work solely on `meta.is_from_staked_node()`, but for the TPU-vote UDP socket that flag is not derived from any cryptographic stake check. `streamer::recv_loop` sets it unconditionally from a static, per-socket boolean (`is_staked_service`), and `fetch_stage.rs` hardcodes that boolean to `true` for the whole TPU-vote UDP socket. Any unstaked remote sender who reaches the publicly-advertised TPU-vote UDP port therefore gets `FROM_STAKED_NODE=true` for free, without spoofing anything, and can drive `ForwardingStage::buffer_packet_batches`.

### Finding Description
`initial_packet_meta_filter` is the sole staked/unstaked gate before expensive per-packet work in `ForwardingStage`: [1](#0-0) 

That flag is populated in `streamer/src/streamer.rs::recv_loop`, purely from the socket-level `is_staked_service` argument — there is no per-packet stake-table lookup, no pubkey check, nothing tied to the sender's identity at all: [2](#0-1) 

`FetchStage::new_multi_socket` hardcodes `is_staked_service = true` for every TPU-vote UDP socket, with the comment "only staked connections should be voting" — an assumption, not an enforced invariant: [3](#0-2) 

This UDP TPU-vote port is a public, gossip-advertised address, reachable by any unprivileged remote client: [4](#0-3) 

Contrast this with the QUIC ingress path, where staked/unstaked classification is derived from an authenticated TLS client pubkey looked up against the real stake table (`ConnectionPeerType::Staked(stake)` via `SimpleQos`/stake-weighted QoS): [5](#0-4) [6](#0-5) 

No equivalent authentication exists for the UDP vote path: UDP itself does not authenticate the sender, and the code does not attempt to correlate `packet.meta().addr` with any stake table before setting the flag — it is set unconditionally for every packet received on that socket.

**Exploit flow:** an unstaked attacker crafts a wire-format transaction that (a) has a syntactically valid ed25519 signature (trivial — attacker signs with their own throwaway keypair) and (b) satisfies `is_simple_vote_tx`/`reject_non_vote` shape checks used by `ed25519_verify_serial` for the `tpu_vote` channel (i.e., looks like a vote instruction call) and sends it via UDP to the leader/any validator's public TPU-vote port. `recv_loop` marks it `FROM_STAKED_NODE`. It passes dedup and `ed25519_verify_serial` (signature format check only — no stake/authorization check happens at sigverify time) in `SigVerifyStage::run_transaction_task`: [7](#0-6) 

It is then sent to `forward_stage_sender`, reaching `ForwardingStage::buffer_packet_batches`, where `initial_packet_meta_filter` — believing it "staked" — admits it into `SanitizedTransactionView::try_new_sanitized`, `RuntimeTransaction::try_new`, and `calculate_priority`, then inserts it into the priority container and eventually forwards it out over the (shared, rate-limited) `MAX_BYTES_PER_SECOND` forwarding budget to the next leader: [8](#0-7) [9](#0-8) 

No existing guard rejects this: the vote path's dedup/priority-floor/sigverify checks are format-level, not stake-authentication checks; `initial_packet_meta_filter` is the intended stake gate and it is bypassed by construction because the underlying flag was never trustworthy for UDP ingress.

### Impact Explanation
This is a QoS/pre-fee-work-pricing evasion: packets that never pay any fee and hold no stake are treated identically to legitimate staked-validator vote traffic by the forwarding pipeline's admission filter, causing the validator to perform sanitize, transaction-view construction, and priority/cost calculation, plus consume the shared outbound forwarding data budget (`MAX_BYTES_PER_SECOND` = 12MB/s) and vote-forwarding channel capacity (`TPU_VOTE_CHANNEL_SIZE`), work and bandwidth normally reserved for actually-staked forwarding traffic. Repeated, cheap unstaked submissions can starve legitimate staked vote-forwarding of the shared budget/queue capacity, degrading vote propagation to the leader — a real, unstaked-attacker-triggerable, underpriced-work / QoS-evasion condition scoped to `core/src/forwarding_stage.rs` and its upstream `core/src/fetch_stage.rs` / `streamer/src/streamer.rs` dependency.

### Likelihood Explanation
High feasibility, no privileged preconditions: the TPU-vote UDP port is intentionally public and gossip-advertised; an attacker needs only a throwaway keypair to produce a validly-signed, vote-shaped packet (cheap, offline, repeatable at line rate since UDP has no handshake). No stake, no validator identity, and no IP spoofing are required — the flaw is that the flag is socket-static, not address-derived, so even a completely honest source IP gets mislabeled. This makes the issue trivially and repeatably reproducible by any unprivileged remote client.

### Recommendation
Do not derive `FROM_STAKED_NODE` from a static per-socket boolean for connectionless UDP ingress. Either (a) remove the UDP TPU-vote fast path's assumption entirely and perform a genuine stake-table lookup keyed on transaction content (e.g., the vote account/authorized voter derivable after sanitization) before setting the flag or admitting into `ForwardingStage`, or (b) migrate the TPU-vote path to require the same cryptographically-authenticated (QUIC + stake table via pubkey) verification already used by `SimpleQos`/stake-weighted QoS, and stop trusting `is_staked_service` as a stand-in for "sender is staked" on raw UDP sockets.

### Proof of Concept
Rust unit/integration test plan (in `streamer/src/streamer.rs` and `core/src/forwarding_stage.rs`):
1. Unit test in `streamer.rs`: bind a plain UDP socket, call `streamer::receiver(..., is_staked_service: true)` (mirroring `fetch_stage.rs`'s TPU-vote configuration), send a packet from an unrelated, unstaked local ephemeral socket/keypair with no entry in any stake table, and assert that the received `PacketBatch`'s `meta().is_from_staked_node()` is `true` — demonstrating the flag is set with zero identity verification.
2. Integration test extending `core/src/forwarding_stage.rs`'s existing `test_forwarding`/`test_initial_packet_meta_filter`: construct a `simple_transfer_with_flags(PacketFlags::FROM_STAKED_NODE | PacketFlags::SIMPLE_VOTE_TX)` packet whose signer is a keypair with zero stake in the test `Bank`/`genesis_config`, feed it through `ForwardingStage::buffer_packet_batches`, and assert it is accepted into `packet_container` and counted in `metrics.votes_forwarded` — proving priced forwarding work occurs for a zero-stake sender.
3. Invariant/fuzz target: fuzz `packet::Meta::flags`/`addr` fed into `initial_packet_meta_filter`, cross-checking against a mock stake-table lookup on `meta.addr`/embedded pubkey; assert `FROM_STAKED_NODE` is never `true` unless the lookup independently confirms nonzero stake for the packet's true signer — this differential test would fail against the current `recv_loop` implementation, confirming the bypass.
