### Title
Unstaked/unprivileged QUIC peers can indefinitely evade connection-table pruning by refreshing `last_update` via trivial streams - (File: streamer/src/nonblocking/quic.rs, streamer/src/nonblocking/swqos.rs, streamer/src/nonblocking/simple_qos.rs)

### Summary
The QUIC streamer's connection-table eviction policy (`ConnectionTable::prune_oldest`) selects victims purely by comparing a per-connection `last_update` timestamp, and that timestamp is refreshed on every completed stream — including trivial, near-zero-cost streams — regardless of the peer's stake or legitimacy. This mirrors the Ditto bug class: a cheap, otherwise-legitimate action (finishing a minimal stream) resets the very timestamp that a purely time-based enforcement mechanism (capacity/QoS pruning) relies on, letting a low-value/unprivileged connection perpetually dodge being the pruning target.

### Finding Description
`ConnectionEntry` stores a shared `last_update: Arc<AtomicU64>` used only to rank connections by recency for eviction: [1](#0-0) 

`ConnectionTable::prune_oldest` evicts the table entry (grouped by IP/pubkey) whose *minimum* `last_update` among its connections is the smallest, i.e., the "least recently active": [2](#0-1) 

Both QoS controller implementations update `last_update` to "now" every time a stream is finished, with no throttle, cost-check, or minimum-data requirement: [3](#0-2) [4](#0-3) 

`prune_oldest` is invoked from `SwQos::prune_unstaked_connection_table`, which is the mechanism that reclaims slots in the unstaked connection table whenever it is at/above `max_unstaked_connections`, to make room for new (potentially higher-value) unstaked connections: [5](#0-4) 

Because a connection's eligibility for eviction depends solely on `last_update`, and `last_update` can be refreshed arbitrarily cheaply (opening a unidirectional stream and writing as little as 1 byte, as seen in the streamer's own tests, is enough to trigger `on_stream_finished`): [6](#0-5) 

an unprivileged (unstaked, zero-stake) client can hold a connection slot indefinitely by periodically finishing trivial streams faster than it can ever become the minimum-`last_update` entry, even while every other connection in the table is legitimately busier or newer. This is directly analogous to the Ditto `merge()`/`updatedAt` bug: a cheap action intended for routine use (appending a minimal order / finishing a minimal stream) resets the timestamp that a time-based enforcement policy (liquidation eligibility / connection pruning) depends on, letting the actor dodge the intended consequence (liquidation / eviction) indefinitely.

### Impact Explanation
This is a QoS-evasion condition: it lets a low-value/no-stake peer entrench a QUIC connection slot in the bounded `unstaked_connection_table` (default capacity `DEFAULT_MAX_UNSTAKED_CONNECTIONS`), denying rotation and fair access to that slot for other unstaked peers attempting to connect once the table is saturated, since `prune_unstaked_connection_table` will always prefer to evict genuinely idle connections over the attacker's artificially-refreshed one. It undermines the intent of the LRU-style admission-control policy that is supposed to reclaim capacity from inactive/low-priority connections for new/legitimate traffic.

### Likelihood Explanation
High feasibility for any unprivileged network peer: no stake or special role is required to open unstaked QUIC connections and drive trivial streams; the cost of refreshing `last_update` is a single small stream write, well below the cost of legitimate work, and can be automated to run indefinitely with a simple timer.

### Recommendation
Do not let bare stream completion alone extend eviction eligibility for connections that don't meet a minimum activity/priority bar (e.g., require a minimum number of meaningful/valid packets, weight `last_update` refresh by stake for unstaked/low-value peers, or bound how often a given peer's `last_update` can be refreshed relative to its share of total capacity), analogous to imposing a stricter post-condition check as recommended for the Ditto `combineShorts`-style fix.

### Proof of Concept
1. Configure a streamer with a small `max_unstaked_connections` (e.g., via `SwQosConfig`).
2. Open an unstaked QUIC connection and repeatedly open/finish trivial 1-byte unidirectional streams on a fixed short interval (faster than any table-pruning check), which calls `on_stream_finished` -> updates `last_update` each time (as exercised in `streamer/src/quic.rs` tests around line 978-992 and `swqos.rs` lines 490-494).
3. Have other unstaked peers attempt to connect once the table reaches capacity; observe via `SwQos::prune_unstaked_connection_table` (`swqos.rs:241-256`) and `ConnectionTable::prune_oldest` (`quic.rs:964-980`) that the artificially-refreshed attacker connection is never selected for eviction, while genuinely idle/newer connections are pruned instead, denying capacity to legitimate new peers.

    pub(crate) fn prune_oldest(&mut self, max_size: usize) -> usize {
        let mut num_pruned = 0;
        let key = |(_, connections): &(_, &Vec<_>)| {
            connections.iter().map(ConnectionEntry::last_update).min()
        };
        while self.total_size.saturating_sub(num_pruned) > max_size {
            match self.table.values().enumerate().min_by_key(key) {
                None => break,
                Some((index, connections)) => {
                    num_pruned += connections.len();
                    self.table.swap_remove_index(index);
                }
            }
        }
        self.total_size = self.total_size.saturating_sub(num_pruned);
        num_pruned
    }

    fn prune_unstaked_connection_table(
        &self,
        unstaked_connection_table: &mut ConnectionTable<ConnectionStreamCounter>,
        max_unstaked_connections: usize,
        stats: Arc<StreamerStats>,
    ) {
        if unstaked_connection_table.total_size >= max_unstaked_connections {
            // Prune the connection table down to 90% capacity
            const PRUNE_TABLE_RATIO: f64 = 0.90;
            let max_connections = (PRUNE_TABLE_RATIO * (max_unstaked_connections as f64)) as usize;
            let num_pruned = unstaked_connection_table.prune_oldest(max_connections);
            stats
                .num_evictions_unstaked
                .fetch_add(num_pruned, Ordering::Relaxed);
        }
    }
