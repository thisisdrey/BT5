### Title
Unauthenticated remote shutdown and forged event injection into `SignerEventReceiver` HTTP listener — ([File: libsigner/src/events.rs])

### Summary
`libsigner/src/events.rs`'s `SignerEventReceiver` implements the HTTP listener that the `stacks-signer` binary binds to receive node-pushed events (`/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block`, `/shutdown`, `/status`). The handler dispatches on URL and method only [1](#0-0) ; there is no authentication check anywhere in this file or in `libsigner/src/http.rs` (confirmed no `Authorization`/`auth_token`/`auth_password` handling exists in `libsigner/**`). Any host that can reach this listener can POST to `/shutdown` and immediately halt the signer's event loop, or POST forged `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block` bodies that get parsed and forwarded straight into the signer runloop.

### Finding Description
The documented deployment pattern in `docs/signing.md` explicitly configures this listener with `endpoint = "0.0.0.0:30000"` [2](#0-1) , i.e., bound on all interfaces, alongside an `auth_token`/`auth_password` pair that the docs claim "must match" between node and signer for "signer communication" [3](#0-2) . Sample configs reiterate this expectation as a security control ("Authentication for signer communication") [4](#0-3) .

However, that `auth_token` is consumed only by the *node's* RPC surface (e.g., `postblock_proposal.rs`, `net/httpcore.rs`, `net/api/mod.rs`) to authenticate inbound requests to the node — confirmed by grep showing `auth_token` referenced in `stackslib/src/net/api/postblock_proposal.rs`, `stackslib/src/config/mod.rs`, `stackslib/src/net/api/mod.rs`, and `stackslib/src/net/httpcore.rs`, but zero occurrences anywhere under `libsigner/**`. The signer's own `SignerEventReceiver::next_event()` — the code that actually accepts the node-pushed HTTP POSTs on the documented `0.0.0.0:30000` listener — never inspects any header, token, or credential before acting:

```rust
if request.url() == "/shutdown" {
    event_receiver.stop_signal.store(true, Ordering::SeqCst);
    Err(EventError::Terminated)
} else if request.url() == "/new_block" {
    process_event::<T, StacksBlockEvent>(request)
}
``` [5](#0-4) 

This breaks the intended equality "request authenticated by shared token" ⇔ "request accepted and acted on." Here every request is accepted and acted on regardless of authentication, so the equality fails open. The `/shutdown` path is the most damaging: it stores `true` into the shared `stop_signal`, causing `is_stopped()` to return `true` and the receiver's `main_loop` (and, transitively, the signer's own runloop that depends on this channel) to exit [6](#0-5) . `process_event` for the other routes deserializes attacker-supplied JSON directly into `StackerDBChunksEvent`, `BlockValidateResponse`, `BurnBlockEvent`, or `StacksBlockEvent` and forwards the resulting `SignerEvent` straight to the signer runloop's channel with no origin check [7](#0-6) , [8](#0-7) .

### Impact Explanation
Per the rules, this is a Critical-class finding: "remote crash/unauthenticated DoS from few messages." A single unauthenticated `POST /shutdown` HTTP request to the signer's listener (documented to bind `0.0.0.0`) terminates its event-receiving loop, and by extension the signer stops consuming further block-proposal/StackerDB events from the node — a remote, unauthenticated, one-request denial of service against a signer node. Beyond the DoS, the same missing check lets any network client inject forged `SignerEvent`s (fake `StackerDBChunksEvent`, `BlockValidateResponse`, `BurnBlockEvent`, `StacksBlockEvent`) into the signer's processing pipeline, even though the surrounding documentation and sample configs assert that `auth_token`/`auth_password` gates this "signer communication."

### Likelihood Explanation
Likelihood is high wherever the listener is reachable per the documented configuration pattern (`endpoint = "0.0.0.0:30000"`, as shown in `docs/signing.md`). No credentials, no prior state, and a single HTTP request are required — this mirrors the PraisonAI `AgentTeam.launch()` class of bug: a network-facing service with a documented remote-bind configuration and no enforced authentication in the actual route-registration/handling code, despite hardened-looking auth options existing elsewhere in the same project.

### Recommendation
1. Add a shared-secret check (compare against the configured `auth_password`) to `SignerEventReceiver::next_event()` in `libsigner/src/events.rs` before dispatching to any handler, including `/status` and especially `/shutdown`.
2. Return `401 Unauthorized` for missing/incorrect tokens instead of processing the request.
3. Default the signer's `endpoint` bind to loopback (`127.0.0.1`) unless a token is explicitly configured, and update `docs/signing.md`'s example away from `0.0.0.0` without emphasizing the required auth.
4. Add regression tests mirroring `libsigner/src/tests/mod.rs::test_status_endpoint` / `test_simple_signer` that assert unauthenticated requests to `/shutdown`, `/stackerdb_chunks`, etc. are rejected.

### Proof of Concept
Given a signer configured per `docs/signing.md` (`endpoint = "0.0.0.0:30000"`), any remote host can run:
```
curl -X POST http://<signer-host>:30000/shutdown
```
This reaches `SignerEventReceiver::next_event()` [9](#0-8) , sets `stop_signal` to `true` with no authentication check performed anywhere in the call path, and the signer's event-receiver main loop exits on the next iteration [10](#0-9) , halting event ingestion for that signer instance.

    fn main_loop(&mut self) {
        loop {
            if self.is_stopped() {
                info!("Event receiver stopped");
                break;
            }
            let next_event = match self.next_event() {
                Ok(event) => event,
                Err(EventError::UnrecognizedEvent(..)) => {
                    // got an event that we don't care about (not a problem)
                    continue;
                }
                Err(EventError::Terminated) => {
                    // we're done
                    info!("Caught termination signal");
                    break;
                }
                Err(e) => {
                    warn!("Failed to receive next event: {:?}", &e);
                    continue;
                }
            };
            if !self.forward_event(next_event) {
                info!("Failed to forward event");
                break;
            }
        }
        info!("Event receiver main loop exit");
    }

    /// Forward an event
    /// Return true on success; false on error.
    /// Returning false terminates the event receiver.
    fn forward_event(&mut self, ev: SignerEvent<T>) -> bool {
        if self.out_channels.is_empty() {
            // nothing to do
            error!("No channels connected to event receiver");
            false
        } else if self.out_channels.len() == 1 {
            // avoid a clone
            if let Err(e) = self.out_channels[0].send(ev) {
                error!("Failed to send to signer runloop: {:?}", &e);
                return false;
            }
            true
        } else {
            for (i, out_channel) in self.out_channels.iter().enumerate() {
                if let Err(e) = out_channel.send(ev.clone()) {
                    error!("Failed to send to signer runloop #{}: {:?}", i, &e);
                    return false;
                }
            }
            true
        }
    }

```rust
fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}
