### Title
Unauthenticated `/shutdown` HTTP request permanently halts `SignerEventReceiver` event loop - ([File: libsigner/src/events.rs])

### Summary
The `SignerEventReceiver::next_event` handler treats any `POST /shutdown` request on the bound event-receiver socket as an authoritative termination signal, with no authentication, secret, or origin check. Any remote party that can reach this socket can permanently stop the signer's event ingestion loop with a single crafted HTTP request.

### Finding Description
The intended design has `SignerStopSignaler::send` (the *internal* stop mechanism) connect to its own `local_addr` and issue `POST /shutdown` purely to wake up the blocking `HttpServer::recv()` call so the already-set `AtomicBool` stop flag can be observed: [1](#0-0) 

However, `next_event` does not distinguish between this legitimate loopback wakeup call and an arbitrary external request. It unconditionally honors any `/shutdown` URL: [2](#0-1) 

This sets the *same* shared `stop_signal: Arc<AtomicBool>` that `is_stopped()` checks, and returns `Err(EventError::Terminated)`, which `main_loop` treats as an unconditional exit: [3](#0-2) 

The broken equality is: "authorization to terminate the event receiver" is claimed to require holding the process-internal stop signal, but in the actual code it equals "any request whose URL is `/shutdown`," regardless of sender identity, secret, or origin. There is no header/token check, no loopback-only restriction, and no comparison against the internal `stop_signal` state before honoring the request — unlike `/status`, `/stackerdb_chunks`, etc., which at least require content matching a specific event type, `/shutdown` requires nothing but the literal path string.

### Impact Explanation
Any attacker who can open a TCP connection to the bound `SignerEventReceiver` address (the endpoint the stacks-node posts StackerDB chunks, burn-block, and block-validation events to) can send a single `POST /shutdown` request to permanently terminate that signer's event-processing thread. After this, `main_loop` exits and the signer stops receiving all subsequent `stackerdb_chunks`, `new_burn_block`, `proposal_response`, and `new_block` events until the process is manually restarted — an unauthenticated, single-message, permanent DoS of a core signer subsystem. This matches the "Critical - remote crash/unauthenticated DoS from few messages" impact category.

### Likelihood Explanation
No secret, credential, or privileged role is required — only network reachability to the bound event-receiver socket, which is the exact channel the local stacks-node uses to push events to the signer. The attack requires exactly one crafted HTTP POST and is trivially repeatable/scriptable. The only precondition is network reachability to that port, which is explicitly granted in the question's threat model.

### Recommendation
Remove the unauthenticated `/shutdown` HTTP endpoint entirely, or gate it behind a check that the request originates from the process's own loopback connection to `local_addr` (e.g., verify `request.remote_addr()` matches the receiver's own bind address, or use a local-only IPC/pipe mechanism instead of an HTTP path) combined with a shared-secret/token known only to the internal `SignerStopSignaler`. At minimum, restrict binding of the event receiver to loopback-only interfaces and add per-request origin validation before honoring `/shutdown`.

### Proof of Concept
```rust
// libsigner/src/events.rs (test module)
#[test]
fn unauthenticated_shutdown_terminates_receiver() {
    let mut receiver: SignerEventReceiver<StackerDBChunksEvent> = SignerEventReceiver::new(false);
    let addr = receiver.bind("127.0.0.1:0".parse().unwrap()).unwrap();

    // Attacker: unrelated TcpStream, no stop_signal, no credentials
    let mut attacker_stream = TcpStream::connect(addr).unwrap();
    let body = "attacker payload";
    let req = format!(
        "POST /shutdown HTTP/1.1\r\nHost: {}\r\nConnection: close\r\nContent-Length: {}\r\n\r\n{}",
        addr, body.len(), body
    );
    attacker_stream.write_all(req.as_bytes()).unwrap();

    // Victim signer's own event loop observes forced termination
    let result = receiver.next_event();
    assert!(matches!(result, Err(EventError::Terminated)));
    assert!(receiver.is_stopped());
}
```
This demonstrates that an unrelated, unauthenticated TCP client can force `next_event()` to return `Err(EventError::Terminated)` and set `is_stopped() == true`, exactly as described, with no credential or internal stop-signal access required.
