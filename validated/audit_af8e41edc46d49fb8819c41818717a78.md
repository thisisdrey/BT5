## Title
Unauthenticated `RecvError` packets allow tunnel teardown by spoofing a peer's UDP source address - (File: outside.go)

### Summary
`handleRecvError` in `outside.go` tears down an established, authenticated tunnel based on an entirely unauthenticated, unencrypted `header.RecvError` packet. The only "proof" the code demands from the sender is that the packet's UDP source address matches the tunnel's currently-known remote address — a value that is trivially spoofable over UDP and requires no Nebula certificate, no CA signature, and no completed handshake. This mirrors the MultiSig report's root cause: the code trusts a cheap, unauthenticated signal (a `call` returning `true` / a packet merely "arriving") as if it proved a real, validated relationship, and acts on attacker-controlled state as a result.

### Finding Description
`readOutsidePackets` dispatches `header.RecvError` packets before any decryption or certificate check: [1](#0-0) 

`handleRecvError` then looks up the hostinfo purely by the numeric `RemoteIndex` carried in the plaintext header, and performs only an address-string comparison against the last known remote endpoint: [2](#0-1) 

The only anti-spoofing control is `hr.IsValid() && hr != addr`. This check:
- Requires no cryptographic signature, no certificate, and no CA trust chain — exactly the "no CA-signed certificate" attacker model.
- Is bypassable via plain UDP source-address spoofing (trivial on UDP, and not defended against elsewhere in the send path since `sendRecvError`/`handleRecvError` never touch the AEAD-authenticated channel).
- Is bypassable entirely if the target hostinfo's remote is not yet "valid" (`!hr.IsValid()`), a state that exists during roaming/handshake windows, in which case the check is skipped altogether and the index alone is trusted.

Once the spoofed check passes, the code calls `f.closeTunnel(hostinfo)` and `f.handshakeManager.DeleteHostInfo(hostinfo)`, destroying real cryptographic tunnel state on the strength of an unauthenticated claim — the same class of defect as the MultiSig bug, where a low-level, weakly-verified signal ("the call returned true" / "a RecvError packet arrived with a matching index/addr string") is treated as proof of a valid, authorized condition ("the peer really lost this session") without validating it end-to-end (e.g., under the AEAD session, or bound to `RemoteIndex` plus a MAC).

### Impact Explanation
This is a remote, unauthenticated tunnel-teardown / denial-of-service primitive: any attacker who can send UDP packets to a Nebula node (and can guess or observe a live `RemoteIndex`, which is a 32-bit value transmitted in plaintext on every packet) can repeatedly force-close established tunnels between legitimate, fully-authenticated peers, without ever possessing a CA-signed certificate or completing a handshake. Because `DeleteHostInfo` is also called, this additionally clears pending-handshake state, amplifying disruption during reconnection. This falls under "remote state poisoning" / "remote crash" (of tunnel state) per the validation rules — no valid certificate or existing peer authorization is required to trigger it, only a lucky/observed index and (in the general case) a spoofed source address.

### Likelihood Explanation
High. `RecvError` is unencrypted, requires no session key, and its acceptance is gated by `listen.accept_recv_error` (default `always`) and a plain address-string equality check that UDP source spoofing defeats. The index space is only 32 bits and is broadcast in cleartext on every regular data packet from the target node, making guessing/harvesting practical for any on-path or off-path attacker able to spoof UDP source IP/port. This is materially easier to exploit than most other findings inspected in this codebase because it needs zero interaction with the certificate/handshake machinery at all.

### Recommendation
- Short term: stop trusting `RecvError` unless it can be validated against session state that an attacker cannot forge — e.g. require the packet to be authenticated (a MAC over `RemoteIndex` using the tunnel's cipher state, similar to how relay/message packets are AEAD-protected) rather than a bare unencrypted type byte plus an address-string comparison.
- Long term: treat all unauthenticated pre-handshake/plaintext message types (`RecvError`, and any other type dispatched in `readOutsidePackets` before decryption) as hostile input by default, and require `listen.accept_recv_error` to default to `never`/`private` unless the deployment explicitly opts into the weaker behavior, documenting the spoofing risk.

### Proof of Concept
1. Passively observe (or have previously participated in) traffic to a target Nebula node long enough to learn a live tunnel's `RemoteIndex` (sent in cleartext in the header of every packet the target transmits).
2. Craft a UDP packet with `header.RecvError` type/`RemoteIndex` set to the observed value, sourced from a spoofed UDP address matching the tunnel's current remote endpoint (or targeting a hostinfo whose `GetRemote()` is not yet `IsValid()`, e.g. during roam).
3. Send it to the target's listening UDP port.
4. `handleRecvError` passes the address check (or skips it) and calls `f.closeTunnel(hostinfo)` plus `DeleteHostInfo`, tearing down the legitimate tunnel — repeatable indefinitely for persistent DoS — without the attacker ever holding a valid certificate or completing any handshake.

Note: I could not find any additional cryptographic binding (e.g., a MAC) protecting `RecvError` packets elsewhere in the codebase within the scope of this review; if such a control exists outside the files indexed here, it would mitigate this finding, but nothing in `outside.go`'s dispatch or `handleRecvError`/`sendRecvError` indicates one.

func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
