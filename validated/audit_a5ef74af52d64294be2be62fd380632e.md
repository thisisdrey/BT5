### Title
Unbounded per-file `git check-attr` round trips in `Instance.Stats` allow repository-content-driven CPU/wall-time exhaustion of the `CommitLanguages` RPC handler - ([File: internal/gitaly/linguist/linguist.go])

### Summary
`Instance.Stats` iterates every blob returned by `git-ls-tree`/`git-diff-tree` for a commit and, for each one, calls `newFileInstance` which invokes `checkAttr.Check(path)` — a synchronous, mutex-serialized round trip to a single long-lived `git check-attr --stdin` process. Neither `Stats` nor `CheckAttrCmd` impose any limit on the number of tree entries processed, so a repository with an attacker-chosen number of distinct paths drives a correspondingly large, purely sequential amount of work in the `CommitLanguages` RPC handler.

### Finding Description
`Instance.Stats` (`internal/gitaly/linguist/linguist.go:80-214`) builds a `gitpipe.LsTree`/`gitpipe.DiffTree` iterator over the target commit's full tree, and for every entry calls `newFileInstance(filename, checkAttr)`, which internally calls `checkAttr.Check(path)` (`internal/git/gitattributes/check_attr.go:63-107`). `Check` locks a single mutex (`c.m`), writes the path to the shared `check-attr --stdin` process's stdin, flushes, and blocks reading exactly `c.count` NUL-delimited tokens back from stdout before returning — i.e., one synchronous round trip per file, fully serialized by the mutex across the whole tree walk [1](#0-0) . There is no cap on the number of loop iterations, no sampling, and no early-exit based on tree size anywhere in `Stats` [2](#0-1) . The only bound on the operation's duration is the caller-supplied gRPC context, and Gitaly's per-RPC concurrency/queueing limits are opt-in (`cfg.Concurrency`) rather than defaults tied to repository size [3](#0-2) . The reachable RPC is `CommitLanguages`, which resolves a revision and calls `linguist.New(...).Stats(ctx, commitID)` with no pre-check on tree size [4](#0-3) . Since `CreateRepositoryFromURL`-style imports let an attacker fully control the content of a repository they own (including tree shape and blob count) before any subsequent `CommitLanguages` call is made against it, they can shape the commit tree to maximize serialized `check-attr` round trips.

### Impact Explanation
Each request against a maliciously large tree occupies one goroutine, one `catfile` object-reader process, and one `check-attr --stdin` process for a duration roughly linear in the number of distinct file paths, with no size-based rejection in `Stats`. This matches a DoS-of-RPC-handler impact class: repeated invocation with large-tree commits can degrade the responsible Gitaly node's CPU/goroutine budget, and because `CommitLanguages` is treated as a mutator with its own transaction/vote path, it also consumes replication/voting resources under Praefect. The blast radius is scoped to Gitaly's ability to serve `CommitLanguages` (and similar stats callers) for the affected repository's storage, not full storage-node compromise.

### Likelihood Explanation
An unprivileged user who can import a project from a URL they control (or push/fork one) fully controls the tree shape and blob count of a commit, so crafting a tree with hundreds of thousands or millions of tiny distinct paths is trivial and repeatable without any special role. The only friction is generating and hosting the malicious upstream repository and triggering the stats RPC (which GitLab Rails does e.g. on project pages), both of which are within normal unprivileged capability.

### Recommendation
Impose an explicit cap on the number of tree entries (or cumulative blob count) processed by `Instance.Stats` before falling back to a partial/best-effort result or rejecting with `ResourceExhausted`; alternatively, batch/pipeline `check-attr` requests instead of one synchronous round trip per path, and enforce a hard wall-clock or entry-count budget inside `Stats` independent of the caller's context deadline.

func WithConcurrencyLimiters(cfg config.Cfg) (map[string]*limiter.AdaptiveLimit, map[string]*limiter.AdaptiveLimit, SetupFunc) {
	perRPCLimits := map[string]*limiter.AdaptiveLimit{}
	perRPCLimitsUnauthenticated := map[string]*limiter.AdaptiveLimit{}

	for _, concurrency := range cfg.Concurrency {
		// Create authenticated limiter
		limitName := fmt.Sprintf("perRPC%s", concurrency.RPC)
		if concurrency.Adaptive {
			perRPCLimits[concurrency.RPC] = limiter.NewAdaptiveLimit(limitName, limiter.AdaptiveSetting{
				Initial:       concurrency.InitialLimit,
				Max:           concurrency.MaxLimit,
				Min:           concurrency.MinLimit,
				BackoffFactor: limiter.DefaultBackoffFactor,
			})
		} else {
			perRPCLimits[concurrency.RPC] = limiter.NewAdaptiveLimit(limitName, limiter.AdaptiveSetting{
				Initial: concurrency.Concurrency(),
			})
		}

		// Create unauthenticated limiter if configured
		unauthLimits := concurrency.Unauthenticated
		if unauthLimits.IsSet() {
			limitNameUnauth := fmt.Sprintf("perRPC%s-unauthenticated", concurrency.RPC)
			if unauthLimits.Adaptive {
				perRPCLimitsUnauthenticated[concurrency.RPC] = limiter.NewAdaptiveLimit(limitNameUnauth, limiter.AdaptiveSetting{
					Initial:       unauthLimits.InitialLimit,
					Max:           unauthLimits.MaxLimit,
					Min:           unauthLimits.MinLimit,
					BackoffFactor: limiter.DefaultBackoffFactor,
				})
			} else if unauthLimits.Concurrency() > 0 {
				perRPCLimitsUnauthenticated[concurrency.RPC] = limiter.NewAdaptiveLimit(limitNameUnauth, limiter.AdaptiveSetting{
					Initial: unauthLimits.Concurrency(),
