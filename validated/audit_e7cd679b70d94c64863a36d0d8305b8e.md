### Title
Client-supplied `git_object_directory`/`git_alternate_object_directories` fields bypass path-traversal validation and are injected verbatim into Git subprocess environment - (`internal/git/alternates/alternates.go`)

### Summary
The bug pattern reported externally — a privileged action validates one set of inputs (amounts, tokens, min-outputs) but the actual operation is driven by a disconnected raw payload that receives no equivalent validation — has a concrete analog in Gitaly's Git command construction path. The `Repository` protobuf message carries `git_object_directory` and `git_alternate_object_directories` fields that are used verbatim to build `GIT_OBJECT_DIRECTORY`/`GIT_ALTERNATE_OBJECT_DIRECTORIES` environment variables for every spawned Git process, through `alternates.Env()`, without ever passing through the path-traversal/storage-boundary validation that Gitaly applies elsewhere (`ObjectDirectoryPath`). Meanwhile, the "validated" identity of the request — `storage_name` + `relative_path` — is a completely separate pair of fields that goes through `ValidateRepository`/`ValidateRelativePath`. An attacker only needs to control the `Repository` message of an RPC (an ordinary, non-privileged capability for any RPC accepting a `Repository`) to make the constructed Git process see an arbitrary directory as part of its object search path.

### Finding Description
`Repository.GitObjectDirectory` and `Repository.GitAlternateObjectDirectories` are plain, client-settable proto3 string fields: [1](#0-0) 

They are documented as directly controlling `GIT_OBJECT_DIRECTORY`/`GIT_ALTERNATE_OBJECT_DIRECTORIES` on every Git command run against the repository: [2](#0-1) 

The actual command-construction code path (`ExecCommandFactory.newCommand`) resolves the repository's on-disk path via the locator (which *does* validate `storage_name`/`relative_path`), but then feeds the *separate*, unvalidated `GitObjectDirectory`/`GitAlternateObjectDirectories` fields straight into `alternates.Env`: [3](#0-2) 

`alternates.Env` performs no bounds checking whatsoever — it simply joins the repo path with the attacker-controlled directory string and emits it as an environment variable that Git will use as an object search path: [4](#0-3) 

This is the crux of the "data used for the operation might not match its inputs" bug class: Gitaly *does* have a rigorous validator for object directory paths — `Repo.ObjectDirectoryPath()` — which checks that the resulting path stays within the storage root, and additionally special-cases legitimate quarantine directories by checking a repo-specific temp-dir prefix: [5](#0-4) 

But this validator is only invoked from a couple of call sites (`internal/gitaly/service/repository/size.go`), not from the command-construction path that actually sets up every Git subprocess's environment. The primary command path (`command_factory.go`) never calls it, so the "inputs" (`storage_name`, `relative_path`) that get validated for authorization/partition-routing purposes are disconnected from the "inputs" (`git_object_directory`, `git_alternate_object_directories`) that actually determine what objects a Git process can read.

The codebase itself acknowledges this design gap in the transaction middleware, where the presence of these fields is treated as a special, unauthenticated escape hatch: [6](#0-5) 

The comment explicitly states: *"This allows for circumventing the transaction management by configuring the either of the object directories... We'll leave this unaddressed for now."*

### Impact Explanation
Any RPC that accepts a `Repository` message (essentially every Gitaly RPC) allows the caller to additionally populate `git_object_directory`/`git_alternate_object_directories` with a path such as `../../other-repo-namespace/other-repo.git/objects`. Because `alternates.Env` performs a raw `filepath.Join` with no `ValidateRelativePath`-style containment check, this becomes `GIT_ALTERNATE_OBJECT_DIRECTORIES=<storage>/other-repo-namespace/other-repo.git/objects` for the spawned Git command. Any accessor RPC (e.g. `GetBlob`, `TreeEntry`, `FindCommit`, `CatFile`) run against that request will then be able to resolve and return objects that exist only in the other repository's object store — a cross-repository/cross-tenant object-store isolation break, letting an authenticated-but-unprivileged caller with access to *any* repository on a shared storage read blob/commit/tree contents of a repository they were never granted access to, as long as they can guess or enumerate its relative path.

### Likelihood Explanation
The `Repository` message and its `git_object_directory`/`git_alternate_object_directories` fields are ordinary, unauthenticated proto3 fields — no capability check gates who may set them, unlike the intended flow where only Rails (via the pre-receive hook/access-check loop) is supposed to populate them with quarantine paths. Any client capable of constructing a Gitaly RPC request (e.g., through Workhorse/GitLab-Shell forwarding, or any consumer with gRPC access) can set them directly. The middleware code comment confirms this is a known, currently-unaddressed gap rather than a purely theoretical one. Likelihood is High for a party that already has some level of RPC access to the Gitaly node (e.g., a legitimate user of one repository on a multi-tenant storage).

### Recommendation
Route the client-supplied `git_object_directory` and `git_alternate_object_directories` fields through the same `ValidateRelativePath`/storage-root containment check used by `Repo.ObjectDirectoryPath()` before they are used to build the `alternates.Env()` environment variables in `command_factory.go`. Alternatively, as already suggested in the middleware code comment, remove the ability for external RPC callers to set object-directory fields at all, and instead derive/attach quarantine directories exclusively from Gitaly-internal state (e.g., the `quarantine.Dir` type), never trusting the raw values coming in over the wire.

### Proof of Concept
1. Identify two repositories, `repoA` (attacker-accessible) and `repoB` (target, on the same storage), and the storage-relative path of `repoB`, e.g. `@hashed/aa/bb/aabb....git`.
2. Issue any read RPC (e.g., `GetBlob`, `FindCommit`, `TreeEntry`) targeting `repoA`, but additionally set on the `Repository` message:
   - `git_object_directory = ""` (or `objects`)
   - `git_alternate_object_directories = ["../../@hashed/aa/bb/aabb....git/objects"]`
3. Gitaly resolves `repoA`'s path via the locator (valid, passes `ValidateRepository`), then calls `alternates.Env(repoAPath, "", ["../../@hashed/aa/bb/aabb....git/objects"])`, which joins the traversal string onto `repoAPath` with no containment check, producing `GIT_ALTERNATE_OBJECT_DIRECTORIES=<storage>/@hashed/aa/bb/aabb....git/objects`.
4. The underlying `git` process for the RPC will now be able to resolve/read objects that only exist in `repoB`, letting the attacker fetch blob/commit/tree content belonging to `repoB` by supplying an object ID from that repo (e.g. learned through other side channels) even though they have no access grant to `repoB`.

// Env returns the alternate object directory environment variables.
func Env(repoPath, objectDirectory string, alternateObjectDirectories []string) []string {
	var env []string
	if objectDirectory != "" {
		env = append(env, fmt.Sprintf("GIT_OBJECT_DIRECTORY=%s", filepath.Join(repoPath, objectDirectory)))
	}

	if len(alternateObjectDirectories) > 0 {
		var dirsList []string

		for _, dir := range alternateObjectDirectories {
			dirsList = append(dirsList, filepath.Join(repoPath, dir))
		}

		env = append(env, fmt.Sprintf("GIT_ALTERNATE_OBJECT_DIRECTORIES=%s", strings.Join(dirsList, ":")))
	}

	return env
}

// ObjectDirectoryPath returns the full path of the object directory. The errors returned are gRPC
// errors with relevant error codes and should be passed back to gRPC without further decoration.
func (repo *Repo) ObjectDirectoryPath(ctx context.Context) (string, error) {
	repoPath, err := repo.Path(ctx)
	if err != nil {
		return "", err
	}

	objectDirectoryPath := repo.GetGitObjectDirectory()
	if objectDirectoryPath == "" {
		return "", structerr.NewInvalidArgument("object directory path is not set")
	}

	storagePath, err := repo.locator.GetStorageByName(ctx, repo.GetStorageName())
	if err != nil {
		return "", fmt.Errorf("get storage by name: %w", err)
	}

	// Ensure the path points somewhere in the storage.
	relativeObjectDirectoryPath, err := storage.ValidateRelativePath(storagePath, filepath.Join(repoPath, objectDirectoryPath))
	if err != nil {
		return "", structerr.NewInvalidArgument("validate relative path: %w", err)
	}

	parentDir := filepath.Base(filepath.Dir(relativeObjectDirectoryPath))
	baseDir := filepath.Base(relativeObjectDirectoryPath)
	isTransactionQuarantineDir := (baseDir == "quarantine") || ((parentDir == "quarantine") && strings.HasPrefix(baseDir, "tmp_objdir"))

	// Transactions quarantine a repository by pointing the object directory to a 'quarantine' named
	// directory in the transaction's temporary directory. If the base directory is `quarantine`,
	// Git push may apply an additional layer of quarantine such as `/quarantine/tmp_objdir-incoming-Gbc29N`
	// so we don't assert the `/quarantine` being the last element of the path. We thus also check for
	// whether the parent directory is in `quarantine` and whether the base directory has the expected
	// `tmp_objdir` suffix.
	if !isTransactionQuarantineDir {
		// We need to check whether the relative object directory as given by the repository is
		// a valid path. This may either be a path in the Git repository itself, where it may either
		// point to the main object directory storage or to an object quarantine directory as
		// created by git-receive-pack(1). Alternatively, if that is not the case, then it may be a
		// manual object quarantine directory located in the storage's temporary directory. These
		// have a repository-specific prefix which we must check in order to determine whether the
		// quarantine directory does in fact belong to the repo at hand.
		if _, origError := storage.ValidateRelativePath(repoPath, objectDirectoryPath); origError != nil {
			tempDir, err := repo.locator.TempDir(repo.GetStorageName())
			if err != nil {
				return "", structerr.NewInvalidArgument("getting storage's temporary directory: %w", err)
			}

			expectedQuarantinePrefix := filepath.Join(tempDir, storage.QuarantineDirectoryPrefix(repo))
			absoluteObjectDirectoryPath := filepath.Join(repoPath, objectDirectoryPath)

			// The relative path is outside of the repository
			if !strings.HasPrefix(absoluteObjectDirectoryPath, expectedQuarantinePrefix) {
				return "", structerr.NewInvalidArgument("not a valid relative path: %w", origError)
			}
		}
	}

	fullPath := filepath.Join(repoPath, objectDirectoryPath)
	if _, err := os.Stat(fullPath); os.IsNotExist(err) {
		return "", structerr.NewNotFound("object directory does not exist: %q", fullPath)
	}

	return fullPath, nil
}
