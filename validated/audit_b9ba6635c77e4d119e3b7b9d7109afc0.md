**Binding claimed broken:** `refund_amount debited by resolve_deposit_internal == deposited_amount (pre-reentrancy)`, which the question claims could exceed the receiver's *actual current* balance after a reentrant transfer-out, causing either a panic (frozen funds) or an incorrect debit from unrelated tokens.

The refund amount is explicitly capped by `balance_left`, the receiver's *current* balance for that specific `TokenId`, read fresh at the time `resolve_deposit_internal` executes (after the reentrant `mt_on_transfer`/`Notify` promise has already run and settled). If the attacker's callback transfers the deposited balance out before this resolver runs, `balance_left` for that token will already reflect the reduced/zero balance, so `refund_amount` is capped to what's actually present — it can never subtract more than what exists, cannot panic via underflow, and cannot debit unrelated tokens (the subtraction is scoped per-`TokenId`, not a generic pool). [2](#0-1) 

This same pattern is used consistently for FT, NFT, and MT resolution (`ft_resolve_deposit`, `nft_resolve_deposit`, `mt_resolve_deposit` all funnel into `resolve_deposit_internal`), and is separately exercised by tests such as `mt_transfer_call_calls_mt_on_transfer_multi_token`'s `malicious_refund_multi_token` and `malicious_receiver_multi_token` cases, which assert the receiver ends with `0` balance (fully drained/capped, not frozen or over-debited) even when the receiver's callback attempts a malicious/oversized refund claim. [3](#0-2) [4](#0-3) 

The `sub` call itself is also checked (`Amounts::sub` returns `None`/errors on underflow rather than panicking on integer overflow), but the `.min(balance_left)` capping ensures the underflow path in `sub` is never even reachable via this route. [5](#0-4)

            authorized_id: None,
            token_ids: Vec::with_capacity(tokens_count).into(),
            amounts: Vec::with_capacity(tokens_count).into(),
            memo: Some(REFUND_MEMO.into()),
        };

        let Some(receiver) = self
            .storage
            .accounts
            .get_mut(receiver_id)
            .map(Lock::as_inner_unchecked_mut)

            tokens_iter.for_each(|(_, amount)| *amount = 0);
            return;
