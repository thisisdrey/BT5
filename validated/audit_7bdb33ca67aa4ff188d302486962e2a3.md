### Title
`StackerDBTx::try_replace_chunk` stores chunk bytes without verifying they hash to the signed `data_hash` - ([File: stackslib/src/net/stackerdb/db.rs])

### Summary
`try_replace_chunk` only checks that `slot_desc` (the *metadata* struct containing `slot_id`, `slot_version`, `data_hash`, `signature`) was validly signed by the slot's owner via `slot_desc.verify(&slot_validation.signer)`. It never recomputes `Sha512Trunc256Sum::from_data(chunk)` and compares it against `slot_desc.data_hash` before calling `insert_chunk`, so the binding between "the bytes the signer actually signed for" and "the bytes actually stored/relayed" is not enforced at this layer.

### Finding Description
`SlotMetadata::verify` cryptographically authenticates only the metadata fields (`slot_id`, `slot_version`, `data_hash`, ...) — it recovers/validates a public key against the signature over those fields, it does not touch the `chunk: &[u8]` payload at all. In `try_replace_chunk` (stackslib/src/net/stackerdb/db.rs:400-438) the sequence is:

1. size cap check (`chunk.len() > self.config.chunk_size`)
2. fetch `slot_validation`
3. `slot_desc.verify(&slot_validation.signer)?` — verifies the signature over the **claimed** `data_hash` field of `slot_desc`, not a fresh hash of `chunk`
4. stale/monotonic version checks
5. `self.insert_chunk(smart_contract, slot_desc, chunk)` at line 437

`insert_chunk` (lines 374-396) then writes `Sha512Trunc256Sum::from_data(chunk)` (the *real* hash of the bytes) into the `data_hash` column alongside `slot_desc.signature` (the signature that was produced over the *original, possibly different* `data_hash`). Nowhere in this path is `Sha512Trunc256Sum::from_data(chunk) == slot_desc.data_hash` checked before accepting the write. This breaks the intended invariant that "the signature stored with a chunk actually covers the bytes stored with it."

Concretely, an attacker who has observed any legitimately signed `(slot_id, slot_version=V, data_hash=H1, signature=SIG)` metadata for a slot (this is public gossip/RPC data, not secret) can pair it with arbitrary bytes `B` whose hash `H2 != H1`, and send that `(slot_desc, B)` pair to a victim node before the legitimate `(slot_desc, A)` chunk (where `hash(A)=H1`) arrives/gets processed for that same version. Because the stale-check only compares `slot_version <= slot_validation.version`, and the target node has not yet stored version `V`, the forged pair passes all checks in `try_replace_chunk` and gets persisted with `data = B`, `data_hash = H2`, `signature = SIG` (a signature that was never produced over `B` or `H2`).

### Impact Explanation
A node can be made to store and subsequently gossip/relay attacker-chosen bytes `B` under a slot that is presented (to other peers, via `get_slot_metadata`/chunk sync) as validly signed by the true slot owner, because the stored `signature` field is `SIG`, which superficially "belongs" to that owner/slot. This is unauthenticated write of arbitrary content into StackerDB state and can propagate to peers that sync chunks from the compromised node, i.e., network-wide propagation of forged data — matching the Critical impact category (unauthenticated/unauthorized write to StackerDB state, network-wide propagation of forged data). It is repeatable per slot-version race and does not require any node secret, private key, or admin role — only a public/observed metadata tuple and being first to deliver to a given victim node for that version.

### Likelihood Explanation
Preconditions: the attacker needs one previously-broadcast, validly-signed `SlotMetadata` (public gossip data — trivial to obtain by observing the network) for a slot/version not yet stored by the target node, and network position/timing sufficient to deliver their forged `(metadata, B)` pair to the victim before the legitimate `(metadata, A)` propagates there. This is a race but requires no privileged access, no secrets, and no compute beyond crafting a message — it is remotely reachable via the same P2P/RPC chunk-push paths that call into `try_replace_chunk` (e.g. `stackslib/src/net/api/poststackerdbchunk.rs`, `stackslib/src/net/relay.rs`).

### Recommendation
In `try_replace_chunk`, after the size check and before (or alongside) `slot_desc.verify`, recompute `let real_hash = Sha512Trunc256Sum::from_data(chunk);` and reject with a new error (e.g. `net_error::BadChunkHash`) if `real_hash != slot_desc.data_hash`. Also change `insert_chunk` to write `slot_desc.data_hash` (the value that was actually verified/signed) rather than recomputing and silently overwriting it with `Sha512Trunc256Sum::from_data(chunk)`, so that any future audit of the stored row reflects the value that was cryptographically checked.

    pub fn try_replace_chunk(
        &self,
        smart_contract: &QualifiedContractIdentifier,
        slot_desc: &SlotMetadata,
        chunk: &[u8],
    ) -> Result<(), net_error> {
        // Check per-replica chunk-size cap.
        if (chunk.len() as u64) > self.config.chunk_size {
            return Err(net_error::StackerDBChunkTooBig(chunk.len()));
        }

        let slot_validation = self
            .get_slot_validation(smart_contract, slot_desc.slot_id)?
            .ok_or(net_error::NoSuchSlot(
                smart_contract.clone(),
                slot_desc.slot_id,
            ))?;

        if !slot_desc.verify(&slot_validation.signer)? {
            return Err(net_error::BadSlotSigner(
                slot_validation.signer,
                slot_desc.slot_id,
            ));
        }
        if slot_desc.slot_version <= slot_validation.version {
            return Err(net_error::StaleChunk {
                supplied_version: slot_desc.slot_version,
                latest_version: slot_validation.version,
            });
        }
        if slot_desc.slot_version > self.config.max_writes {
            return Err(net_error::TooManySlotWrites {
                supplied_version: slot_desc.slot_version,
                latest_version: slot_validation.version,
                max_writes: self.config.max_writes,
            });
        }
        self.insert_chunk(smart_contract, slot_desc, chunk)
    }
