### Title
Unbounded array allocation from attacker-controlled length in `ValidateMultiSign` precompile causes node crash - ([File: actuator/src/main/java/org/tron/core/vm/PrecompiledContracts.java])

### Summary
The `ValidateMultiSign` precompiled contract, reachable via a normal `CALL`/`STATICCALL` from any smart contract, decodes an ABI-encoded signature array whose declared length is taken directly from transaction calldata and used to allocate a Java array without an upper bound, before any permission/signature validation occurs.

### Finding Description
`ValidateMultiSign.execute()` reads the signature-array length from calldata and, when `VMConfig.allowTvmSelfdestructRestriction()` is **not** enabled, calls `extractBytesArray()` directly instead of the bounded `extractSigArray()` path: [1](#0-0) 

The size guard (`sigArraySize > MAX_SIZE`) is only applied inside the `if (VMConfig.allowTvmSelfdestructRestriction())` branch; the `extractBytesArray` fallback path performs no such check: [2](#0-1) 

`extractBytesArray` computes `len` from `words[offset].intValueSafe()` — a value fully controlled by the caller's calldata — and immediately allocates `new byte[len][]` before any of the length’s legitimacy is checked against actual available words. Since `intValueSafe()` clamps overflowing `DataWord` values up to `Integer.MAX_VALUE`, an attacker can set this length to `Integer.MAX_VALUE`, forcing an allocation of an object-reference array of that size (multi-gigabyte), which throws `OutOfMemoryError` or otherwise exhausts JVM heap. This is directly analogous to the CVE-2021-30501 bug class: a size value taken from untrusted/crafted input is used to allocate a buffer without a sane upper bound, causing an abort/crash instead of a graceful validation failure.

### Impact Explanation
An `OutOfMemoryError` thrown deep inside precompiled-contract execution during transaction processing can destabilize or crash the executing FullNode/SolidityNode JVM process, or degrade it to the point where it can no longer process further transactions or serve API requests — a node crash/halt condition. Because this occurs inside `Manager`'s block/transaction application path (via TVM execution), a malicious contract call embedded in a transaction can trigger this on any node that executes/re-executes the block, which is broader than a single-node DoS.

### Likelihood Explanation
Exploitability is contingent on `VMConfig.allowTvmSelfdestructRestriction()` being disabled for the target network (pre-hard-fork networks, private/test chains, or any network configuration lagging that feature flag). On networks where it is already active, the bounded `extractSigArray` path is used instead and this specific route is closed. Where reachable, any account can invoke it with a single crafted contract call — no special privileges, keys, or witness/SR role required — so likelihood is high specifically on unpatched/legacy configurations.

### Recommendation
Move the `sigArraySize`/`MAX_SIZE` bound check outside the `allowTvmSelfdestructRestriction()` conditional so it always executes before `extractBytesArray`/`extractSigArray` is invoked, and add a defensive maximum-length check (and bounds check against `words.length`) directly inside `extractBytesArray`/`extractBytes32Array` themselves, rejecting the call gracefully instead of allocating an unbounded array.

### Proof of Concept
1. Deploy a contract that performs a `staticcall`/`call` to the `ValidateMultiSign` precompiled contract address.
2. Craft calldata so that `words[3]` points to an offset whose corresponding "array length" word encodes a very large integer (e.g., `0xffffffff...`, which `intValueSafe()` clamps to `Integer.MAX_VALUE`).
3. On a network/build where `VMConfig.allowTvmSelfdestructRestriction()` is false, `execute()` calls `extractBytesArray(words, offset, rawData)` with `len = Integer.MAX_VALUE`, executing `new byte[Integer.MAX_VALUE][]` at [3](#0-2) , throwing `OutOfMemoryError` and disrupting node operation.

  private static byte[][] extractBytesArray(DataWord[] words, int offset, byte[] data) {
    if (offset > words.length - 1) {
      return new byte[0][];
    }
    int len = words[offset].intValueSafe();
    byte[][] bytesArray = new byte[len][];
    for (int i = 0; i < len; i++) {
      int bytesOffset = words[offset + i + 1].intValueSafe() / WORD_SIZE;
      int bytesLen = words[offset + bytesOffset + 1].intValueSafe();
      bytesArray[i] = extractBytes(data, (bytesOffset + offset + 2) * WORD_SIZE,
          bytesLen);
    }
    return bytesArray;
  }
