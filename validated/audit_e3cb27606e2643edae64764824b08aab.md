### Title
Fee-exempt boundary on NEP-245/IMT lets fungible-value transfers be split into unit legs to bypass all protocol fees - (File: contracts/defuse/core/src/intents/token_diff.rs)

### Summary
`TokenDiff::token_fee` waives fees for `TokenIdType::Nep245`/`TokenIdType::Imt` whenever the per-intent `amount` (the absolute value of a single negative delta) is not strictly greater than 1, i.e. `amount == 1` always falls into the zero-fee arm. Because fee evaluation happens independently per `TokenDiff` intent (each intent's own `self.diff` entry for a token), a signer can split any transfer of NEP-245/IMT-wrapped value of total magnitude N into N separate `delta = -1` `TokenDiff` intents inside one signed `MultiPayload`/`DefuseIntents`, so every per-intent `amount` is 1 and `token_fee` returns `Pips::ZERO` on every leg, yielding `total_fee_collected == 0` for any N.

### Finding Description
The intended binding is: for a NEP-245/IMT token moved with total negative-delta magnitude N under protocol `fee`, `total_fee_collected(N) == fee.fee_ceil(N)` when `fee > 0` and N is fungible-like value (not a genuine singleton NFT unit). The actual code computes fee strictly per `TokenDiff` intent invocation: [1](#0-0) 

and the fee-rate lookup is: [2](#0-1) 

The match arm order is `Nep141 => {}` (always charge), then `Nep245 | Imt if amount > 1 => {}` (charge only if `amount > 1`), then the catch-all `Nep171 | Nep245 | Imt => return Pips::ZERO`. Since the guard is strict `>`, `amount == 1` is the *only* magnitude that always lands in the zero-fee catch-all for NEP-245/IMT — not `<1` (delta=0 is rejected earlier as `InvalidIntent`), only exactly 1.

Each `TokenDiff` intent's `diff` is a `BTreeMap<TokenId, i128>` (`TokenDeltas`), so a single intent can carry only one delta entry per `token_id`. But `DefuseIntents::execute_intent` iterates every intent in the list independently: [3](#0-2) 

and `Engine::execute_signed_intent` executes the whole `intents` vector under one verified signature/nonce: [4](#0-3) 

So the attacker's payload is: one `MultiPayload` signing a `DefuseIntents { intents: [TokenDiff{diff:{token_id: -1}}; N] }` (with matching counterparty legs elsewhere in the batch supplying the offsetting `+1` deposits so the batch's `TransferMatcher`/`finalize` invariant still nets to zero — that invariant only enforces supply conservation, not fee correctness). Each of the N `execute_intent` calls independently computes `amount = 1` and `Self::token_fee(...) == Pips::ZERO`, so `fees_collected` stays empty on every leg, and `internal_add_balance(fee_collector, ...)` is never invoked. NEP-245 tokens are not niche 1-of-1 NFTs in this codebase — they are the standard representation for fungible value bridged from another Defuse/FT contract (see tests moving 500/1000/8000-unit balances as `Nep245TokenId`), so this exemption applies broadly to real fungible value, not just genuine NFTs.

No existing guard (nonce/signature verification, `TransferMatcher::finalize` supply-conservation check, `internal_apply_deltas`) aggregates deltas across intents for the same token/signer before computing the fee rate, so the divergence is real.

### Impact Explanation
The fee_collector never receives protocol fees for any NEP-245/IMT-denominated transfer, regardless of its true economic size, as long as the signer structures it as unit (`|delta|=1`) legs within one signed batch. This is an unconditional, unbounded protocol-fee bypass (Critical: "protocol fees bypassed") applicable to any account, any NEP-245/IMT token, and any volume; it is fully repeatable across accounts/tokens/batches at will.

### Likelihood Explanation
Preconditions are minimal: any unprivileged signer with a positive NEP-245/IMT balance and a counterparty (or self-matching diff) to satisfy `TransferMatcher::finalize`'s conservation check, and any `fee > 0`. The cost is a single signed `MultiPayload` containing N `TokenDiff` intents (all under the attacker's existing nonce/signature machinery) — no special role, no relayer key, no upgrade required. This is straightforward and highly feasible to execute repeatedly.

### Recommendation
Change the fee-exemption boundary in `TokenDiff::token_fee` (contracts/defuse/core/src/intents/token_diff.rs:206-216) to no longer treat "amount == 1" as inherently fee-exempt for NEP-245/IMT, or restrict the exemption to token_ids that are cryptographically/structurally guaranteed to be non-fungible (max supply 1), and/or aggregate `amount` per `(signer, token_id)` across the entire `DefuseIntents`/batch before evaluating `token_fee`, rather than per individual intent.

### Proof of Concept
`cargo test` in `contracts/defuse/core` (or a `near-workspaces` sandbox test alongside `tests/src/tests/defuse/intents/token_diff.rs`), parametrized over `N ∈ {1, 10, 1000}`:
1. Set up two signers with an existing NEP-245-wrapped fungible balance (e.g., via `mt_transfer_call` from a NEP-141 FT into a second Defuse contract, as in `simulate_mt_withdraw_intent`), with `fee = Pips::ONE_PERCENT` (or any nonzero fee).
2. Have signer A sign one `MultiPayload` with `DefuseIntents.intents` containing N `TokenDiff{ diff: {token_id: -1} }` intents, and signer B (or A itself in a closing leg) supply matching `+1` legs to satisfy `TransferMatcher::finalize`.
3. Execute via `execute_signed_intents`/`execute_intents`.
4. Assert `fee_collector`'s MT balance for `token_id` is `0` for every N tested, and contrast with `fee.fee_ceil(N)` — the intended fee for an equivalent single `TokenDiff{token_id: -N}` intent — to show the divergence grows with N while actual collected fee stays `0`.

    fn execute_signed_intent(&mut self, signed: MultiPayload) -> Result<()> {
        // verify signed payload and get public key
        let public_key = signed.verify().ok_or(DefuseError::InvalidSignature)?;

        // calculate intent hash
        let hash = signed.hash();

        // extract NEP-413 payload
        let DefusePayload::<DefuseIntents> {
            signer_id,
            verifying_contract,
            deadline,
            nonce,
            message: intents,
        } = signed.extract_defuse_payload()?;

        // check recipient
        if verifying_contract != *self.state.verifying_contract() {
            return Err(DefuseError::WrongVerifyingContract);
        }

        self.inspector.on_deadline(deadline);

        // make sure message is still valid
        if deadline < Timestamp::now() {
            return Err(DefuseError::DeadlineExpired);
        }

        // make sure the account has this public key
        if !self.state.has_public_key(&signer_id, &public_key) {
            return Err(DefuseError::PublicKeyNotExist(signer_id, public_key));
        }

        // commit nonce
        self.verify_intent_nonce(nonce, deadline)?;
        self.state.commit_nonce(signer_id.clone(), nonce)?;

        intents.execute_intent(&signer_id, self, hash)?;
        self.inspector.on_intent_executed(&signer_id, hash, nonce);

        Ok(())
    }
