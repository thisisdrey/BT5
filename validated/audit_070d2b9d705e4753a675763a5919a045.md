## Valid Analog Found

### Title
Out-of-bounds array read in `extractBytes32Array` when processing `BatchValidateSign` precompile calldata - (File: `actuator/src/main/java/org/tron/core/vm/PrecompiledContracts.java`)

### Summary
The CVE describes an out-of-bounds read in `ansilove_ansi` caused by insufficient bounds validation of length/offset fields parsed from an attacker-supplied file. The same bug class — an attacker-controlled offset/length used to index into an array without a bounds check — exists in java-tron's `BatchValidateSign` precompiled contract, reachable by any account that deploys or calls a smart contract invoking the `batchValidateSign` precompile at address `0x66`.

### Finding Description
In `PrecompiledContracts.java`, the helper `extractBytesArray` and `extractSigArray` both guard against out-of-range offsets: [1](#0-0) [2](#0-1) 

Both begin with `if (offset > words.length - 1) { return new byte[0][]; }` before indexing `words[offset]`. However, `extractBytes32Array`, used to parse the address array in the `BatchValidateSign` precompile, has no equivalent check: [3](#0-2) 

It directly indexes `words[offset]` and then `words[offset + i + 1]` in a loop, where `offset` and the loop bound `len` both derive from attacker-controlled `DataWord`s parsed from the raw calldata via `DataWord.parseArray(data)`.

The call site in `BatchValidateSignContract.doExecute` is: [4](#0-3) 

`words[2].intValueSafe() / WORD_SIZE` is fully attacker-controlled and can be crafted to point past the end of the `words` array, or `words[offset].intValueSafe()` (the `len` field) can be crafted to be very large, causing the loop to read `words[offset + i + 1]` far beyond the array bounds. Since `words` is a Java array (not a byte buffer with implicit zero-padding like `ByteUtil.parseBytes`), this throws an uncaught `ArrayIndexOutOfBoundsException` inside `PrecompiledContract.execute`, rather than returning a safe empty/false result like the sibling methods do.

Note: when `VMConfig.allowTvmSelfdestructRestriction()` is active, `sigArraySize`/`addrArraySize` are bounds-checked against `MAX_SIZE` before this call, which may mitigate the crash on chains where that feature is enabled. On chains/configurations where this flag is not yet active, the check is skipped and the malformed input reaches `extractBytes32Array` unguarded.

### Impact Explanation
An unprivileged caller can invoke the `BatchValidateSign` precompile (address `0x66`) from any deployed contract or via `TriggerConstantContract`/`TriggerSmartContract` with crafted calldata that causes an `ArrayIndexOutOfBoundsException` during TVM execution. Depending on how the exception propagates through the VM execution wrapper, this can result in an unhandled runtime exception during transaction/block processing — a denial-of-service condition consistent with the "out-of-bounds read and application crash" impact of the reference CVE.

### Likelihood Explanation
Reaching this code path only requires broadcasting a transaction that calls a contract invoking the `BatchValidateSign` precompile with a crafted `addresses` offset/length header — no special privileges, keys, or SR/witness status are needed. The precompile is a standard TVM feature reachable from any address.

### Recommendation
Add the same `offset > words.length - 1` bounds guard (and a sane upper bound on `len`) to `extractBytes32Array` that already exists in `extractBytesArray` and `extractSigArray`, and ensure `MAX_SIZE`-style validation of `addrArraySize` is unconditionally applied rather than gated behind `VMConfig.allowTvmSelfdestructRestriction()`.

### Proof of Concept
1. Deploy/call a contract that performs a low-level `call` to precompile address `0x66` (`BatchValidateSign`).
2. Craft calldata where the header word at slot `2` (the "addresses array offset" word) encodes an offset such that `words[2].intValueSafe() / WORD_SIZE` equals or exceeds `words.length`, or where the length word at that offset is a large positive value exceeding the remaining `words` array size.
3. Submit as a normal `TriggerSmartContract`/constant call transaction; `extractBytes32Array` indexes `words[offset]` / `words[offset + i + 1]` out of bounds, throwing an uncaught `ArrayIndexOutOfBoundsException` in `PrecompiledContract.execute`.
