### Title
Bazel's `git_repository` re-enables local-protocol submodule cloning (`protocol.file.allow=always`), allowing an attacker-controlled Git remote to read arbitrary local files via `.gitmodules` - (File: `tools/build_defs/repo/git_worker.bzl`)

### Summary
`tools/build_defs/repo/git_worker.bzl` unconditionally forces `protocol.file.allow=always` before running `git submodule update --init [--recursive]` whenever a `git_repository` rule is configured with `init_submodules` or `recursive_init_submodules`. This deliberately overrides Git's own hardening (CVE-2022-39253) that restricts submodules from being cloned over the local `file://` transport unless the user explicitly opts in.

### Finding Description
`update_submodules` in `git_worker.bzl` always passes `-c protocol.file.allow=always` to the submodule update command: [1](#0-0) 

This flag is applied regardless of where `remote` points, so any repository fetched by `git_repository` — including one at an attacker-influenced `branch`/`tag` (unpinned, no content hash) or a compromised upstream a pinned `commit` was taken from — can ship a `.gitmodules` file declaring a submodule `url = "file:///some/absolute/path"`. Git's default policy since 2.38.1 (`protocol.file.allow=user`) blocks exactly this scenario because submodule URLs are not considered "user provided." Bazel explicitly disables that protection for every git checkout that requests submodules: [2](#0-1) 

Because `add_origin`/`fetch`/`reset` only pin the top-level repository content (and only when `commit` — not `tag`/`branch` — is specified), the submodule graph itself is fully attacker-controlled content that is executed with elevated local-clone privileges: [3](#0-2) 

### Impact Explanation
A `file://` submodule clone lets Git perform a local optimized clone (using hardlinks/`--local` semantics) of an arbitrary path on the machine running the build. This can read files outside the intended repository directory/exec root (e.g., adjacent output-base directories, other checked-out repositories, or other locally accessible paths), corresponding to the "read outside the repository/exec root" impact class.

### Likelihood Explanation
This only fires when a `git_repository` sets `init_submodules = True` or `recursive_init_submodules = True` (common for third-party C/C++ dependencies with vendored submodules) and the fetched Git content is attacker-influenced — e.g., built from an untrusted branch/tag in CI, or a supply-chain-compromised upstream that has not pinned `commit`. Given no attacker interaction with the local machine is required beyond the content being fetched by the build, likelihood is moderate but scoped to a fairly common pattern (`recursive_init_submodules`).

### Recommendation
Do not blanket-force `protocol.file.allow=always`. Only allow local-protocol submodules when the submodule path is verifiably confined under the already-fetched repository (or drop the override entirely, letting users opt in explicitly per submodule via their own git config), and prefer requiring/enforcing a pinned `commit` (content-addressed) before permitting recursive submodule initialization.

### Proof of Concept
1. Create a Git repo `evil.git` with a `.gitmodules` entry: `[submodule "x"] path = x url = file:///etc` (or any sensitive local absolute path reachable by the build machine).
2. Configure: `git_repository(name="dep", remote="https://.../evil.git", branch="main", recursive_init_submodules=True)`.
3. Run `bazel fetch @dep//...`; `git_worker.bzl`'s `update_submodules` executes `git -c protocol.file.allow=always submodule update --init --recursive --checkout --force`, causing Git to clone the local `file:///etc` path into `@dep`'s submodule directory, exposing its contents in the external repository tree — reproducible via a `src/test/shell/bazel` test that stages a malicious `.gitmodules` in a local git server fixture and asserts files outside the intended checkout appear under the fetched repository. def git_repo(ctx, directory):
    """ Fetches data from git repository and checks out file tree.

    Called by git_repository rule.

    Args:
        ctx: Context of the calling rules, for reading the attributes.
        Please refer to the git_repository rule for the description.
        directory: Directory where to check out the file tree.
    Returns:
        The struct with the following fields:
        commit: Actual HEAD commit of the checked out data.
        shallow_since: Actual date and time of the HEAD commit of the checked out data.
    """
    if ctx.attr.shallow_since:
        if ctx.attr.tag:
            fail("shallow_since not allowed if a tag is specified; --depth=1 will be used for tags")
        if ctx.attr.branch:
            fail("shallow_since not allowed if a branch is specified; --depth=1 will be used for branches")

    # Use shallow-since if given
    if ctx.attr.shallow_since:
        shallow = "--shallow-since=%s" % ctx.attr.shallow_since
    else:
        shallow = "--depth=1"

    reset_ref = ""
    fetch_ref = ""
    if ctx.attr.commit:
        reset_ref = ctx.attr.commit
        fetch_ref = ctx.attr.commit
    elif ctx.attr.tag:
        reset_ref = "tags/" + ctx.attr.tag
        fetch_ref = "tags/" + ctx.attr.tag + ":tags/" + ctx.attr.tag
    elif ctx.attr.branch:
        reset_ref = "origin/" + ctx.attr.branch
        fetch_ref = ctx.attr.branch + ":origin/" + ctx.attr.branch
    else:
        reset_ref = "origin/HEAD"
        fetch_ref = "HEAD:refs/remotes/origin/HEAD"

    git_repo = _GitRepoInfo(
        directory = ctx.path(directory),
        shallow = shallow,
        reset_ref = reset_ref,
        fetch_ref = fetch_ref,
        remote = str(ctx.attr.remote),
        init_submodules = ctx.attr.init_submodules,
        recursive_init_submodules = ctx.attr.recursive_init_submodules,
    )

def update_submodules(ctx, git_repo, recursive = False):
    if recursive:
        # "protocol.file.allow=always" allows the submodule command clone from a local directory.
        # It's necessary for Git 2.38.1 and assoicated backport versions.
        # See https://github.com/bazelbuild/bazel/issues/17040
        _git_maybe_shallow(ctx, git_repo, "-c", "protocol.file.allow=always", "submodule", "update", "--init", "--recursive", "--checkout", "--force")
    else:
        _git_maybe_shallow(ctx, git_repo, "-c", "protocol.file.allow=always", "submodule", "update", "--init", "--checkout", "--force")
