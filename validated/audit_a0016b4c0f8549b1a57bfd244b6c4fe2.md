### Title
Unvalidated `GitAlternateObjectDirectories`/`GitObjectDirectory` repository fields allow path traversal and cross-repository object disclosure via `alternates.Env` - ([File: internal/git/alternates/alternates.go])

### Finding Description
`alternates.Env` builds the `GIT_OBJECT_DIRECTORY` and `GIT_ALTERNATE_OBJECT_DIRECTORIES` environment variables by blindly joining attacker-influenced strings to the repository path with `filepath.Join` and `strings.Join(dirsList, ":")`, with no bounds or traversal checking: [1](#0-0) 

This function is invoked unconditionally for every git command run against a repository, in `ExecCommandFactory.newCommand`, using the raw values straight from the incoming gRPC `Repository` message (`repo.GetGitObjectDirectory()`, `repo.GetGitAlternateObjectDirectories()`): [2](#0-1) 

Unlike the dedicated `ObjectDirectoryPath()` helper used only by the `GetObjectDirectorySize` RPC, which calls `storage.ValidateRelativePath` and additionally checks for the transaction/quarantine directory prefix before trusting the value: [3](#0-2) 

`alternates.Env`/`newCommand` perform **no such validation**. The `storagemgr` middleware only checks that a `MetadataKeySnapshotRelativePath` header is present when these fields are set (to support WAL transactions); it does not validate that the paths are safe or scoped to the repository, and non-transactional requests pass the raw value straight through unchanged: [4](#0-3) 

Because Gitaly's repository storage layout uses a deterministic hashed path scheme (`@hashed/xx/yy/<hash>.git`), an attacker who controls a `Repository` message for a repo they own can set `GitAlternateObjectDirectories` to a relative traversal path (e.g. `"../../<other-hash-prefix>/objects"`) reaching another repository's `objects` directory on the same storage. Any subsequent git operation on their own repo (e.g. `ObjectFormat`, `ListAllCommits`, blob/commit reads, etc., which all go through `CommandFactory.New`) will then have that foreign object database available as an alternate, letting the attacker resolve/read objects (blobs, commit contents) that exist in another user's private repository if they can guess or brute-force valid object IDs (OIDs), a well-known "leaky alternates" cross-repository disclosure class.

### Impact Explanation
This is a cross-repository object disclosure / storage-path escape: an attacker can cause Gitaly to read git objects from outside the intended repository's object database, potentially exposing blobs/commits of other users' private repositories that reside on the same storage shard. This matches GitLab bounty's "unauthorized access to another user's private repository data" impact class.

### Likelihood Explanation
The attacker only needs to control the `GitObjectDirectory`/`GitAlternateObjectDirectories` fields of a `Repository` message referencing a repo they own (explicitly in scope per the threat model: "control RPC fields and repository content"), which is trivial for anyone who can send Gitaly a crafted gRPC request. The remaining difficulty is guessing/knowing the target repository's storage-relative path and knowing/guessing valid OIDs to actually retrieve content — this reduces practical severity but the path-escape itself is unauthenticated and repeatable with no privileged access, admin role, or secret required.

### Recommendation
Validate `GitObjectDirectory` and each entry of `GitAlternateObjectDirectories` in `alternates.Env` (or before it is called in `newCommand`) using `storage.ValidateRelativePath` against the repository root (and reuse the quarantine-directory-prefix logic from `localrepo.ObjectDirectoryPath`), rejecting any value that escapes the repository or an authorized quarantine/transaction directory, for every code path that reaches `CommandFactory.New`, not just `GetObjectDirectorySize`.

### Proof of Concept
```go
// internal/git/alternates/alternates_test.go (illustrative)
func TestEnv_TraversalNotValidated(t *testing.T) {
    repoPath := "/data/storage/@hashed/aa/bb/1111.git"
    env := Env(repoPath, "", []string{"../../cc/dd/2222.git/objects"})
    // No error is returned and the resulting GIT_ALTERNATE_OBJECT_DIRECTORIES
    // env var points outside repoPath into a sibling repository's object store.
    require.Contains(t, env[0], "/data/storage/@hashed/cc/dd/2222.git/objects")
}
```
At the RPC level, an attacker owning `repo-a` sends any RPC that carries a `Repository` message through `CommandFactory.New` (e.g. `ObjectFormat`) with:
```
Repository{
  StorageName: "default",
  RelativePath: "@hashed/aa/bb/1111.git",
  GitAlternateObjectDirectories: []string{"../../cc/dd/2222.git/objects"},
}
```
Gitaly executes the git command with `GIT_ALTERNATE_OBJECT_DIRECTORIES` pointing into `2222.git/objects`, without any error, allowing subsequent object lookups (e.g. `cat-file`, `rev-list`) against that repo's data if the attacker supplies known OIDs.

func Env(repoPath, objectDirectory string, alternateObjectDirectories []string) []string {
	var env []string
	if objectDirectory != "" {
		env = append(env, fmt.Sprintf("GIT_OBJECT_DIRECTORY=%s", filepath.Join(repoPath, objectDirectory)))
	}

	if len(alternateObjectDirectories) > 0 {
		var dirsList []string

		for _, dir := range alternateObjectDirectories {
			dirsList = append(dirsList, filepath.Join(repoPath, dir))
		}

		env = append(env, fmt.Sprintf("GIT_ALTERNATE_OBJECT_DIRECTORIES=%s", strings.Join(dirsList, ":")))
	}

```go
func (repo *Repo) ObjectDirectoryPath(ctx context.Context) (string, error) {
	repoPath, err := repo.Path(ctx)
	if err != nil {
		return "", err
	}

	objectDirectoryPath := repo.GetGitObjectDirectory()
	if objectDirectoryPath == "" {
		return "", structerr.NewInvalidArgument("object directory path is not set")
	}

	storagePath, err := repo.locator.GetStorageByName(ctx, repo.GetStorageName())
	if err != nil {
		return "", fmt.Errorf("get storage by name: %w", err)
	}

	// Ensure the path points somewhere in the storage.
	relativeObjectDirectoryPath, err := storage.ValidateRelativePath(storagePath, filepath.Join(repoPath, objectDirectoryPath))
	if err != nil {
		return "", structerr.NewInvalidArgument("validate relative path: %w", err)
	}

	parentDir := filepath.Base(filepath.Dir(relativeObjectDirectoryPath))
	baseDir := filepath.Base(relativeObjectDirectoryPath)
	isTransactionQuarantineDir := (baseDir == "quarantine") || ((parentDir == "quarantine") && strings.HasPrefix(baseDir, "tmp_objdir"))

	// Transactions quarantine a repository by pointing the object directory to a 'quarantine' named
	// directory in the transaction's temporary directory. If the base directory is `quarantine`,
	// Git push may apply an additional layer of quarantine such as `/quarantine/tmp_objdir-incoming-Gbc29N`
	// so we don't assert the `/quarantine` being the last element of the path. We thus also check for
	// whether the parent directory is in `quarantine` and whether the base directory has the expected
	// `tmp_objdir` suffix.
	if !isTransactionQuarantineDir {
		// We need to check whether the relative object directory as given by the repository is
		// a valid path. This may either be a path in the Git repository itself, where it may either
		// point to the main object directory storage or to an object quarantine directory as
		// created by git-receive-pack(1). Alternatively, if that is not the case, then it may be a
		// manual object quarantine directory located in the storage's temporary directory. These
		// have a repository-specific prefix which we must check in order to determine whether the
		// quarantine directory does in fact belong to the repo at hand.
		if _, origError := storage.ValidateRelativePath(repoPath, objectDirectoryPath); origError != nil {
			tempDir, err := repo.locator.TempDir(repo.GetStorageName())
			if err != nil {
				return "", structerr.NewInvalidArgument("getting storage's temporary directory: %w", err)
			}

			expectedQuarantinePrefix := filepath.Join(tempDir, storage.QuarantineDirectoryPrefix(repo))
			absoluteObjectDirectoryPath := filepath.Join(repoPath, objectDirectoryPath)

			// The relative path is outside of the repository
			if !strings.HasPrefix(absoluteObjectDirectoryPath, expectedQuarantinePrefix) {
				return "", structerr.NewInvalidArgument("not a valid relative path: %w", origError)
			}
		}
	}
```
