### Title
StackerDB chunk signature does not bind the target contract, enabling cross-contract slot replay in the `.signers-{set}-{msg_id}` StackerDBs - (File: libstackerdb/src/libstackerdb.rs)

### Summary
The StackerDB chunk-signing scheme signs only `(slot_id, slot_version, data_hash)` and never binds the signature to the specific StackerDB contract (`smart_contract`/`contract_id`) it is intended for. Because the Nakamoto `.signers` boot contract assigns the *same* signer→slot mapping to every sibling message-type contract of a given signer set (`signers-{set}-1` for `BlockResponse`, `signers-{set}-2` for `StateMachineUpdate`, `signers-{set}-3` for `BlockPreCommit`), a validly-signed chunk observed on one of these StackerDBs can be replayed verbatim by anyone into a sibling StackerDB of the same signer set and will pass all storage-layer checks, since none of them verify that the signature was produced for *that* contract.

### Finding Description
`SlotMetadata::auth_digest()` / `verify()` and `StackerDBChunkData::sign()`/`verify()`/`recover_pk()` compute and check a digest over only `slot_id`, `slot_version`, and `data_hash`: [1](#0-0) [2](#0-1) 

The write path that stores a chunk, `StackerDBTx::try_replace_chunk`, only checks chunk size, that `slot_desc.verify(&slot_validation.signer)` succeeds for that contract's *stored* slot owner, freshness of `slot_version`, and `max_writes` — it never checks that the signature was computed for this particular `smart_contract`: [3](#0-2) 

The same holds for the push-gossip path, `PeerNetwork::validate_received_chunk`, which re-derives the expected signer solely from `(smart_contract_id, slot_id)` and verifies the signature against that address, again without checking that the signature was made for that contract: [4](#0-3) 

Crucially, the slot→signer assignment is *identical* across all sibling message-type contracts for a given signer set. Each `signers-{set}-{message_id}.clar` contract simply proxies the same page from the shared `.signers` contract, keyed only by `set` (0 or 1), not by `message_id`: [5](#0-4) [6](#0-5) [7](#0-6) 

This was verified end-to-end in tests: for `signer_set in 0..2` and every `message_id in 0..SIGNER_SLOTS_PER_USER`, the `signers-{signer_set}-{message_id}` contract returns the exact same slot list as the shared page: [8](#0-7) 

The `message_id` (contract instance selection) is purely a routing concept used only by `MessageSlotID::stacker_db_contract` when the *client* decides where to send a message: [9](#0-8) 

Consequently: `verify_signature(chunk) == true` for slot `S` under contract `A` implies it is also `== true` for the same slot `S` under any sibling contract `B` of the same signer set, because the signer-address lookup (`get_slot_signer`/slot ownership) resolves to the *same* address in both, and the signature itself never encodes which contract it authorizes. This is the exact analog of the reported bug class: request-scoped authorization data (`requestId` in the report; here, the target `contract_id`/StackerDB instance) is never checked against the signed payload, so an attacker can present arbitrary "context" (a different destination contract) together with legitimately-signed data and have it accepted.

### Impact Explanation
Any unprivileged network participant who observes a validly-signed chunk broadcast on one signer-message StackerDB (e.g. `signers-1-1`/BlockResponse, which are gossiped over the p2p network and also readable via the public `GET /v2/stackerdb/.../chunks/...` endpoint) can replay that exact `(slot_id, slot_version, sig, data)` tuple to a sibling StackerDB contract of the same signer set (e.g. `signers-1-2`/StateMachineUpdate or `signers-1-3`/BlockPreCommit) via the public `POST /v2/stackerdb/{contract}/chunks` endpoint. `try_replace_chunk` will accept it because the signer lookup for that slot resolves to the same address in the target contract, and only version freshness is otherwise checked (an unused/low-version slot in the sibling contract trivially satisfies this). This is an unauthenticated write into StackerDB replica state that the attacker was never authorized to make on that specific StackerDB instance — matching the Critical-tier "unauthenticated/unauthorized write to state or StackerDB" impact category. It also lets an attacker consume/occupy a signer's slot version counter in a StackerDB the signer never intended to write to at that version, and forge the *stored, served* replica content for that slot/contract with data that was never produced with that contract's authorization in mind.

Downstream, `libsigner/src/events.rs`'s `signer_message_payload_matches_lane` filters based on the payload type-byte prefix before a `SignerEvent` is handed to signer/miner decision logic, which limits — but does not eliminate — the effect for that specific consumer path (that filtering logic is explicitly out of scope here). The storage-layer vulnerability (unauthenticated cross-contract write acceptance) exists independently of that filter and affects every reader of the raw StackerDB replica (RPC `GET`, p2p sync/inventory), which will serve the forged/misplaced chunk as legitimate, authenticated content for that contract/slot.

### Likelihood Explanation
High feasibility for a determined attacker with no privileges: the required "ingredients" — a previously-broadcast signed chunk and the current slot version at the target contract — are both public information (gossiped over p2p and queryable via the RPC/StackerDB metadata endpoints). No cryptographic material or privileged role is needed; only a raw POST/push replay of already-public bytes into a different contract path.

### Recommendation
- **Short term:** Bind the signed digest to the specific StackerDB contract: include the `contract_id` (or a domain-separation tag unique to `(contract_id)`) inside `SlotMetadata::auth_digest()`, and reject any chunk whose signature was not computed for the contract it is being posted/gossiped to. Apply the same binding check in `try_replace_chunk` (`stackslib/src/net/stackerdb/db.rs`) and `validate_received_chunk`/`handle_unsolicited_StackerDBPushChunk` (`stackslib/src/net/stackerdb/mod.rs`).
- **Long term:** Add regression tests that attempt to replay a validly-signed chunk from one `signers-{set}-{msg_id}` contract into a sibling contract of the same signer set and assert rejection; broaden adversarial testing to cover "correct signature, wrong destination/context" scenarios generally.

### Proof of Concept
1. During reward cycle `N`, signer set `S`, observe (via p2p gossip or `GET /v2/stackerdb/<signers-S-1 boot contract>/chunks/<slot_id>/<version>`) a validly-signed `StackerDBChunkData { slot_id, slot_version, sig, data }` that signer address `A` posted to `signers-S-1` (BlockResponse StackerDB).
2. Query `GET /v2/stackerdb/<signers-S-2 boot contract>` metadata to learn the current stored `slot_version` for the same `slot_id` (owned by the same address `A`, per `stackerdb-get-signer-slots-page`).
3. `POST /v2/stackerdb/<signers-S-2 boot contract>/chunks` with the *same* `slot_id`, `sig`, and `data` captured in step 1 (bump `slot_version` if needed to exceed the value observed in step 2).
4. `try_replace_chunk` (`stackslib/src/net/stackerdb/db.rs:398-439`) will succeed: `slot_desc.verify(&slot_validation.signer)` passes because `slot_validation.signer == A` in `signers-S-2` too, and no check ties the signature to `signers-S-1`. The chunk is now stored and served as authentic content under `signers-S-2`, even though `A` never signed anything intended for that contract.

    /// Get the digest to sign that authenticates this chunk data and metadata
    fn auth_digest(&self) -> Sha512Trunc256Sum {
        let mut hasher = Sha512_256::new();
        hasher.update(self.slot_id.to_be_bytes());
        hasher.update(self.slot_version.to_be_bytes());
        hasher.update(self.data_hash.0);
        Sha512Trunc256Sum::from_hasher(hasher)
    }

    /// Sign this slot metadata, committing to slot_id, slot_version, and
    /// data_hash.  Sets self.signature to the signature.
    /// Fails if the underlying crypto library fails
    pub fn sign(&mut self, privkey: &StacksPrivateKey) -> Result<(), Error> {
        let auth_digest = self.auth_digest();
        let sig = privkey
            .sign(&auth_digest.0)
            .map_err(|se| Error::SigningError(se.to_string()))?;

        self.signature = sig;
        Ok(())
    }

    /// Verify that a given principal signed this chunk metadata.
    /// Note that the address version is ignored.
    pub fn verify(&self, principal: &StacksAddress) -> Result<bool, Error> {
        let sigh = self.auth_digest();
        let pubk = StacksPublicKey::recover_to_pubkey_without_validating_low_s(
            sigh.as_bytes(),
            &self.signature,
        )
        .map_err(|ve| Error::VerifyingError(ve.to_string()))?;

        let pubkh = Hash160::from_node_public_key(&pubk);
        Ok(pubkh == *principal.bytes())
    }

    /// Add or replace a chunk for a given reward cycle, if it is valid
    /// Otherwise, this errors out with Error::StaleChunk
    pub fn try_replace_chunk(
        &self,
        smart_contract: &QualifiedContractIdentifier,
        slot_desc: &SlotMetadata,
        chunk: &[u8],
    ) -> Result<(), net_error> {
        // Check per-replica chunk-size cap.
        if (chunk.len() as u64) > self.config.chunk_size {
            return Err(net_error::StackerDBChunkTooBig(chunk.len()));
        }

        let slot_validation = self
            .get_slot_validation(smart_contract, slot_desc.slot_id)?
            .ok_or(net_error::NoSuchSlot(
                smart_contract.clone(),
                slot_desc.slot_id,
            ))?;

        if !slot_desc.verify(&slot_validation.signer)? {
            return Err(net_error::BadSlotSigner(
                slot_validation.signer,
                slot_desc.slot_id,
            ));
        }
        if slot_desc.slot_version <= slot_validation.version {
            return Err(net_error::StaleChunk {
                supplied_version: slot_desc.slot_version,
                latest_version: slot_validation.version,
            });
        }
        if slot_desc.slot_version > self.config.max_writes {
            return Err(net_error::TooManySlotWrites {
                supplied_version: slot_desc.slot_version,
                latest_version: slot_validation.version,
                max_writes: self.config.max_writes,
            });
        }
        self.insert_chunk(smart_contract, slot_desc, chunk)
    }
}

    pub fn validate_received_chunk(
        &self,
        smart_contract_id: &QualifiedContractIdentifier,
        config: &StackerDBConfig,
        data: &StackerDBChunkData,
        expected_versions: &[u32],
    ) -> Result<bool, net_error> {
        // validate -- must not exceed this replica's configured chunk size.
        if (data.data.len() as u64) > config.chunk_size {
            info!(
                "Received StackerDBChunk for {} ID {}, which is oversized: {} bytes (max {} bytes)",
                smart_contract_id,
                data.slot_id,
                data.data.len(),
                config.chunk_size
            );
            return Ok(false);
        }

        // validate -- must be a valid chunk
        let Some(expected_version) = expected_versions.get(data.slot_id as usize) else {
            info!(
                "Received StackerDBChunk for {} ID {}, which is too big ({})",
                smart_contract_id,
                data.slot_id,
                expected_versions.len()
            );
            return Ok(false);
        };

        // validate -- must be signed by the expected author
        let addr = match self
            .stackerdbs
            .get_slot_signer(smart_contract_id, data.slot_id)?
        {
            Some(addr) => addr,
            None => {
                return Ok(false);
            }
        };

        let slot_metadata = data.get_slot_metadata();
        if !slot_metadata.verify(&addr)? {
            info!(
                "StackerDBChunk for {} ID {} is not signed by {}",
                smart_contract_id, data.slot_id, &addr
            );
            return Ok(false);
        }

        // validate -- must be the current or newer version
        if data.slot_version < *expected_version {
            info!(
                "Received StackerDBChunk for {} ID {} version {}, which is stale (expected {})",
                smart_contract_id, data.slot_id, data.slot_version, *expected_version
            );
            return Ok(false);
        }

        // validate -- must not exceed max writes
        if data.slot_version > config.max_writes {
            info!(
                "Write count exceeded for StackerDBChunk for {} ID {} version {} (max is {})",
                smart_contract_id, data.slot_id, data.slot_version, config.max_writes
            );
            return Ok(false);
        }

        Ok(true)
    }

fn signers_db_get_slots() {
    let stacker_1 = TestStacker::from_seed(&[3, 4]);
    let stacker_2 = TestStacker::from_seed(&[5, 6]);

    let (mut peer, test_signers, latest_block_id, _) = prepare_signers_test(
        function_name!(),
        vec![],
        &[stacker_1.clone(), stacker_2.clone()],
        None,

    let private_key = peer.config.private_key.clone();

    let mut expected_signers: Vec<_> =
        [&stacker_1.signer_private_key, &stacker_2.signer_private_key]
            .iter()
            .map(|sk| {
                let pk = Secp256k1PublicKey::from_private(sk);
                let pk_bytes = pk.to_bytes_compressed();
                let signer_addr = StacksAddress::p2pkh(false, &pk);
                let stackerdb_entry = TupleData::from_data(vec![
                    (
                        ClarityName::from_literal("signer"),
                        PrincipalData::from(signer_addr).into(),
                    ),
                    (ClarityName::from_literal("num-slots"), Value::UInt(1)),
                ])
                .unwrap();
                (pk_bytes, stackerdb_entry)
            })
            .collect();

    // should be sorted by the pk bytes
    expected_signers.sort_by_key(|x| x.0.clone());
    let expected_stackerdb_slots = Value::cons_list_unsanitized(
        expected_signers
            .into_iter()
            .map(|(_pk, entry)| Value::from(entry))
            .collect(),
    )
    .unwrap();

    for signer_set in 0..2 {
        for message_id in 0..SIGNER_SLOTS_PER_USER {
            let contract_name =
                ContractName::try_from(format!("signers-{}-{}", &signer_set, &message_id)).unwrap();
            let signers = readonly_call(
                &mut peer,
                &latest_block_id,
                contract_name.clone(),
                ClarityName::from_literal("stackerdb-get-signer-slots"),
                vec![],
            )
            .expect_result_ok()
            .unwrap();

            debug!("Check .{}", contract_name);
            if signer_set == 0 {
                assert_eq!(signers.expect_list().unwrap(), vec![]);
            } else {
                assert_eq!(signers, expected_stackerdb_slots);
            }
        }
    }
