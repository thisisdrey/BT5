### Title
`Pool.swap` lacks deadline and minimum-output protection, exposing users to stale-price execution — ([File: contracts/Pool.sol](contracts/Pool.sol))

### Summary
`Pool.swap` lets a user burn one synthetic token and mint another at a `MasterOracle`-quoted price, but accepts neither a `deadline` nor a `minAmountOut` parameter. A swap transaction that sits in the mempool across an oracle price update executes at whatever price is current at inclusion time, with no way for the user to bound their loss — the same bug class as the reported Unitas `swap` missing-deadline finding, and worse because Metronome also lacks any slippage bound.

### Finding Description
`Pool.swap` is a public entry point guarded only by `whenNotShutdown`, `nonReentrant`, `onlyIfSyntheticTokenExists`, and the `isSwapActive` flag [1](#0-0) . It burns `amountIn_` of the input synth immediately, then prices the output via `quoteSwapOut`, which calls `masterOracle().quote(tokenIn, tokenOut, amountIn_)` at execution time and deducts the `feeProvider` swap fee [2](#0-1) . `quoteSwapOut` itself resolves the price purely from the oracle at call time [3](#0-2) . The interface confirms there is no deadline or minOut parameter [4](#0-3) . A grep for `deadline`, `minAmount`, or `slippage` across `contracts/` returns no protective checks on this path.

### Impact Explanation
A user broadcasts `swap(msETH, msUSD, amountIn)` expecting the price quoted at submission. If the transaction is delayed (mempool congestion, builder/sequencer reordering) and a `MasterOracle` price update lands in between — e.g., ETH/USD drops 5% — the swap executes at the stale-for-the-user new price and mints proportionally less `msUSD`, with no revert path. Because the protocol burns-then-mints at oracle parity rather than settling against an AMM, the user bears the entire price drift with zero recourse. This is a direct, quantifiable loss of user funds on a single public call, matching the medium-severity profile of the reference report. Note that same-transaction oracle manipulation is not required for the loss; ordinary price drift plus inclusion delay suffices, and an unprivileged searcher can additionally time execution to capture favorable drift relative to the victim's intent (the protocol fee/collector side is unaffected, so value is simply destroyed or re-priced against the user).

### Likelihood Explanation
- Reachability: `swap` is permissionless to any holder of a registered synthetic token; `isSwapActive` is a governor flag that is enabled in the deployed configuration.
- Trigger: requires only that an oracle price update be mined between broadcast and inclusion — a routine occurrence on volatile pairs, and systematically exploitable by block builders that can order a pending oracle update before the victim's swap.
- No existing mitigation: `nonReentrant` and `SynthContext._msgSender` do not constrain execution price; there is no `minAmountOut` or `deadline` anywhere on the swap path.

### Recommendation
Add a `minAmountOut_` parameter (and optionally `deadline_`) to `swap` and `IPool.swap`, and revert if the oracle-quoted `_amountOut` is below it:

```solidity
// contracts/Pool.sol
function swap(
    ISyntheticToken syntheticTokenIn_,
    ISyntheticToken syntheticTokenOut_,
    uint256 amountIn_,
    uint256 minAmountOut_,
    uint256 deadline_
) external ... {
    if (block.timestamp > deadline_) revert TransactionExpired();
    ...
    (_amountOut, _fee) = quoteSwapOut(syntheticTokenIn_, syntheticTokenOut_, amountIn_);
    if (_amountOut < minAmountOut_) revert SlippageExceeded();
    ...
}
```

### Proof of Concept
Hardhat-style sketch against the existing test harness (mirroring `test/Pool.test.ts` swap tests):

```ts
// Setup: alice holds msETH; msUSD registered; swap active.
const amountIn = await msEth.balanceOf(alice.address);
const quotedBefore = (await pool.quoteSwapOut(msEth.address, msUsd.address, amountIn))._amountOut;

// 1. Alice broadcasts swap(...) — tx sits in mempool.
const tx = await pool.connect(alice).swap(msEth.address, msUsd.address, amountIn);

// 2. Before inclusion, an oracle update drops ETH price 10%.
await masterOracle.updatePrice(weth.address, ethPrice.mul(90).div(100)); // oracle push tx ordered first

// 3. Alice's swap now executes at the worse price — no revert possible.
const quotedAfter = (await pool.quoteSwapOut(msEth.address, msUsd.address, amountIn))._amountOut;
// quotedAfter ≈ quotedBefore * 0.9 — alice receives ~10% less msUSD,
// and had no way to specify minAmountOut or deadline to prevent it.
```

On a mainnet fork, replace step 2 with advancing blocks past a real Chainlink/`MasterOracle` update; the observable outcome is identical: `swap` mints less output than the price the user saw at broadcast, with no parameter allowing the user to reject the fill.
