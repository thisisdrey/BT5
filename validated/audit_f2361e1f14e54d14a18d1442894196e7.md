### Title
Anti-replay window TOCTOU in `ConnectionState.Decrypt`/`VerifyRelay` permits duplicate-packet race bypass - (File: `connection_state.go`)

### Summary
`ConnectionState.Decrypt` (and its relay counterpart `VerifyRelay`) split the anti-replay check into two separately-locked operations — `window.Check()` and `window.Update()` — with the expensive AEAD decryption performed in between while `decryptLock` is released. This mirrors the report's root cause pattern: a "read the current state, then later commit the state change" sequence with an unguarded window in between where a second, concurrently-arriving action can slip through before the first commit lands, exactly as an lp position could grow past a checked cap between `getMaxCommunityLpPositon()` and `setPerTokenWalletCap()`.

### Finding Description
`Decrypt` does:
```go
cs.decryptLock.Lock()
result := cs.window.Check(l, messageCounter)
cs.decryptLock.Unlock()
...
out, err = cs.dKey.DecryptDanger(...)   // no lock held
...
cs.decryptLock.Lock()
result = cs.window.Update(l, messageCounter)
cs.decryptLock.Unlock()
``` [1](#0-0) 

`Check` only inspects the replay `Bits` window without marking the counter as seen; the counter is only recorded as consumed later, in `Update`, after decryption completes. Between the `Check` and `Update` calls the lock is fully released, so if two packets carrying the same `messageCounter` for the same tunnel are processed concurrently by different reader goroutines (nebula runs `listen.routines`/`tun.routines` > 1 with `SO_REUSEPORT`, each spinning its own `listenOut`/`readOutsidePackets` loop calling into the shared `ConnectionState`), both goroutines can pass `Check` before either calls `Update`. Both then independently perform `DecryptDanger` and proceed to hand the plaintext to the firewall/tun pipeline in `readOutsidePackets`/`handleOutsideMessagePacket`. [2](#0-1) [3](#0-2) 

The same pattern is duplicated in `VerifyRelay`, which additionally gates relay-forwarded traffic. [4](#0-3) 

This is directly analogous to the report's TOCTOU class: a value is validated ("no lp above cap" / "counter not yet seen"), an unguarded window elapses (owner calls two functions manually / decrypt runs unlocked), and a second concurrent event (an lp deposit / a duplicated packet) is admitted before the final state-commit (`setPerTokenWalletCap` / `window.Update`) closes the window — breaking the invariant the check was meant to enforce.

### Impact Explanation
An attacker who can capture a single legitimately-encrypted packet (no CA-signed certificate of their own is required — they only need visibility of on-wire traffic between two existing peers) can duplicate/replay it to the target's UDP listener(s). If the duplicate arrives while the original is still mid-flight through `Decrypt`, both copies can pass the replay `Check`, both get decrypted, and both get delivered into the tun device / firewall / lighthouse processing path — i.e., a successful protocol-level bypass of nebula's anti-replay defense for a race-won duplicate, and duplicate delivery of application traffic to the tunnel owner.

### Likelihood Explanation
Exploitation requires: (1) capturing one ciphertext packet on the wire (passive, no cert needed), (2) sending it twice in quick succession to the target's UDP port(s) so that two independent reader goroutines race through `Decrypt` concurrently. Because nebula's listener architecture uses multiple routines on the same socket for throughput (`routines`/`SO_REUSEPORT`), and the unlocked window between `Check` and `Update` spans a full AEAD decrypt, the race window is real but narrow and timing-dependent, making this a plausible but non-trivial-to-win race rather than a deterministic bypass.

### Recommendation
Collapse the check-and-commit into a single critical section: hold `decryptLock` (or use a compare-and-set primitive on the `Bits` window) across both the "is this counter already seen" check and the "mark seen" update so no other goroutine can observe the pre-update state for the same counter, even though this reduces decrypt parallelism for the same tunnel. Alternatively, reserve the counter (mark-seen) before performing `DecryptDanger` and unmark it only on decryption failure, guaranteeing at most one decrypt attempt per counter is ever admitted.

### Proof of Concept
1. Establish a nebula tunnel between two hosts, both running with `listen.routines` > 1 (SO_REUSEPORT enabled) so `listenOut` spawns multiple concurrent reader goroutines sharing one `ConnectionState`. [5](#0-4) 
2. Passively capture one encrypted `header.Message` UDP packet sent to the target.
3. Immediately re-inject two copies of the identical packet to the target's UDP socket(s) at (near) the same instant, aiming to land on two different reader routines.
4. Observe in `Decrypt` that both invocations can pass `cs.window.Check(l, messageCounter)` before either calls `cs.window.Update(l, messageCounter)`, because the lock is released between the two calls and `DecryptDanger` runs unlocked. [1](#0-0) 
5. Both copies proceed through `handleOutsideMessagePacket` and are written to the tun device, evidencing a successful duplicate/replay past the intended anti-replay window enforcement.

func (cs *ConnectionState) Decrypt(l *slog.Logger, messageCounter uint64, out []byte, packet []byte, nb []byte) ([]byte, error) {
	var err error
	cs.decryptLock.Lock()
	result := cs.window.Check(l, messageCounter)
	cs.decryptLock.Unlock()
	if !result {
		return nil, ErrAlreadySeen
	}

	out, err = cs.dKey.DecryptDanger(out, packet[:header.Len], packet[header.Len:], messageCounter, nb)
	if err != nil {
		return nil, err
	}

	cs.decryptLock.Lock()
	result = cs.window.Update(l, messageCounter)
	cs.decryptLock.Unlock()
	if !result {
		return nil, ErrAlreadySeen
	}
	return out, nil
}

// VerifyRelay verifies AEAD protected (but not encrypted) relay frames. packet must be length-checked by the caller.
func (cs *ConnectionState) VerifyRelay(l *slog.Logger, messageCounter uint64, packet []byte, nb []byte) error {
	cs.decryptLock.Lock()
	result := cs.window.Check(l, messageCounter)
	cs.decryptLock.Unlock()
	if !result {
		return ErrAlreadySeen
	}

	signedPayload := packet[:len(packet)-cs.dKey.Overhead()]
	signatureValue := packet[len(packet)-cs.dKey.Overhead():]
	_, err := cs.dKey.DecryptDanger(nil, signedPayload, signatureValue, messageCounter, nb)
	if err != nil {
		return err
	}

	cs.decryptLock.Lock()
	result = cs.window.Update(l, messageCounter)
	cs.decryptLock.Unlock()
	if !result {
		return ErrAlreadySeen
	}

	return nil
}

func (f *Interface) handleOutsideMessagePacket(hostinfo *HostInfo, out []byte, packet []byte, fwPacket *firewall.Packet, nb []byte, q int, localCache firewall.ConntrackCache) {
	err := newPacket(out, true, fwPacket)
	if err != nil {
		hostinfo.logger(f.l).Warn("Error while validating inbound packet",
			"error", err,
			"packet", out,
		)
		return
	}

	dropReason := f.firewall.Drop(*fwPacket, true, hostinfo, f.pki.GetCAPool(), localCache)
	if dropReason != nil {
		// NOTE: We give `packet` as the `out` here since we already decrypted from it and we don't need it anymore
		// This gives us a buffer to build the reject packet in
		f.rejectOutside(out, hostinfo.ConnectionState, hostinfo, nb, packet, q)
		if f.l.Enabled(context.Background(), slog.LevelDebug) {
			hostinfo.logger(f.l).Debug("dropping inbound packet",
				"fwPacket", fwPacket,
				"reason", dropReason,
			)
		}
		return
	}

	_, err = f.readers[q].Write(out)
	if err != nil {
		f.l.Error("Failed to write to tun", "error", err)
	}
