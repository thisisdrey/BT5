### Title
DNS-rebinding protection (`GetURLAndResolveConfig`) can be bypassed for SCP-style SSH URLs containing an `@` after the host - ([File: internal/git/gitcmd/command_resolve.go])

### Summary
`getURLAndResolveConfigForSCP` is supposed to replace the untrusted hostname of an scp-like SSH URL (`[user@]host:path`) with the DNS-pinned `resolvedAddress` in order to defend against DNS-rebinding when Gitaly later invokes `git fetch`/`git ls-remote` over SSH. When the attacker-controlled `path` portion (the part after the first colon) contains an `@` character while the host portion itself has none, the naive string handling reconstructs a URL that still starts with the original, unresolved hostname before the first colon, so git's own SSH transport re-resolves the attacker's hostname at fetch time instead of using the pinned IP.

### Finding Description
`getURLAndResolveConfigForSCP` at [1](#0-0)  does:

```go
hostAndPath := strings.SplitN(remoteURL, ":", 2)
...
if userAndHost := strings.SplitAfterN(remoteURL, "@", 2); len(userAndHost) > 1 {
    userPrefix = userAndHost[0]
}
return fmt.Sprintf("%s%s:%s", userPrefix, resolvedAddress, hostAndPath[1]), nil, nil
```

The bug is that `userAndHost` is computed by splitting the **entire original `remoteURL`** on `@`, not just the host portion (`hostAndPath[0]`). If the attacker supplies a `remote_url` such as `"attacker.example:x@y/repo.git"` (no `@` before the first `:`, but an `@` in the path after it):

- `hostAndPath = ["attacker.example", "x@y/repo.git"]` — passes the `/`-before-colon check.
- `userAndHost = strings.SplitAfterN(remoteURL, "@", 2) = ["attacker.example:x@", "y/repo.git"]`, so `userPrefix = "attacker.example:x@"`.
- The final string becomes `"attacker.example:x@" + resolvedAddress + ":" + "x@y/repo.git"`, e.g. `attacker.example:x@203.0.113.5:x@y/repo.git`.

When this string is later handed to `git` as an scp-like SSH remote, git parses the host as everything before the **first** unescaped colon that isn't preceded by a `/`. In the crafted output that is still `attacker.example` — the original, untrusted hostname — not the pinned `resolvedAddress`. The resolved IP and the rest of the original path end up embedded inside what git treats as the "path" component, which is functionally inert for connection purposes.

This defeats the entire purpose of the `resolved_address` field, whose doc comment states it is "used to avoid DNS rebinding by mapping the url to the resolved address" (see field docs in [2](#0-1) , and callers such as [3](#0-2) , [4](#0-3) ). The existing test suite only exercises `@` appearing before the colon (`user@host:path`) or not at all, never `@` appearing in the path after the colon, so this case is untested and unguarded. [5](#0-4) 

### Impact Explanation
This is a Server-Side Request Forgery / DNS-rebinding bypass. An unprivileged user who can configure a repository mirror or trigger `CreateRepositoryFromURL`/`FetchRemote`/`FindRemoteRootRef`/`UpdateRemoteMirror` with an attacker-controlled `remote_url` can craft a hostname+path combination containing `@` after the colon. GitLab Rails resolves the hostname to a "safe" public IP at validation time and passes it as `resolved_address`, expecting Gitaly to pin the connection to that IP. Because of this bug, Gitaly's git process instead re-resolves the original attacker-controlled hostname via DNS at fetch time. If the attacker rebinds DNS for that hostname to an internal-only address (e.g., cloud metadata service, internal admin endpoints) between validation and fetch, Gitaly's SSH-based git fetch will connect to the internal target, defeating the SSRF/DNS-rebinding protection this code was built for.

### Likelihood Explanation
The attacker needs only standard, unprivileged capabilities already granted by the threat model: ability to create/configure a repository import or push mirror with a custom URL (a `Remote`/`FetchRemoteRequest`/`UpdateRemoteMirrorRequest` field they control end-to-end). No special role, no credential theft, no non-default configuration is required — only crafting a hostname string containing `@` in the path segment following the colon, and controlling DNS for the attacker-owned domain to rebind after validation. This is entirely reproducible and repeatable.

### Recommendation
Compute the user-prefix split only against the host component (`hostAndPath[0]`), not the whole `remoteURL`, e.g.:

```go
host := hostAndPath[0]
var userPrefix string
if idx := strings.LastIndex(host, "@"); idx != -1 {
    userPrefix = host[:idx+1]
}
return fmt.Sprintf("%s%s:%s", userPrefix, resolvedAddress, hostAndPath[1]), nil, nil
```
This ensures any `@` occurring in the path portion cannot leak the original hostname back into the position git treats as the connection target, and the resolved IP always fully replaces the untrusted host before the first colon.

### Proof of Concept
```go
func TestGetURLAndResolveConfigForSCP_HostNotReplaced(t *testing.T) {
    url, _, err := GetURLAndResolveConfig("attacker.example:x@y/repo.git", "203.0.113.5")
    require.NoError(t, err)
    // BUG: resulting URL still starts with the attacker-controlled hostname
    // before the first colon, instead of the pinned resolved address.
    require.Equal(t, "attacker.example:x@203.0.113.5:x@y/repo.git", url)
    // When git parses this as scp-like syntax, host == "attacker.example",
    // NOT "203.0.113.5" — the DNS-rebinding pin is bypassed.
}
```
Triggerable end-to-end via `FetchRemoteRequest{RemoteParams: &Remote{Url: "attacker.example:x@y/repo.git", ResolvedAddress: "203.0.113.5"}}` sent to `RepositoryService.FetchRemote`, or the analogous fields on `UpdateRemoteMirrorRequest`/`CreateRepositoryFromURLRequest`/`FindRemoteRootRefRequest`.

```go
func getURLAndResolveConfigForSCP(remoteURL, resolvedAddress string) (string, []ConfigPair, error) {
	hostAndPath := strings.SplitN(remoteURL, ":", 2)
	if len(hostAndPath) != 2 {
		return "", nil, fmt.Errorf("invalid protocol/URL encountered: %s", remoteURL)
	}

	if strings.Contains(hostAndPath[0], "/") {
		return "", nil, fmt.Errorf("SSH URLs with '/' before colon are unsupported")
	}

	var userPrefix string

	if userAndHost := strings.SplitAfterN(remoteURL, "@", 2); len(userAndHost) > 1 {
		userPrefix = userAndHost[0]
	}

	return fmt.Sprintf("%s%s:%s", userPrefix, resolvedAddress, hostAndPath[1]), nil, nil
}
```
