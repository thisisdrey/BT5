### Title
`SlotMetadata::auth_digest` omits the StackerDB contract identifier, enabling cross-contract chunk-signature replay - (File: `libstackerdb/src/libstackerdb.rs`)

### Summary
`SlotMetadata::auth_digest()` computes the digest that principals sign to authenticate a StackerDB chunk write as `H(slot_id || slot_version || data_hash)` only [1](#0-0) . It never commits to the StackerDB's `QualifiedContractIdentifier`. The identity of "which StackerDB this signature is for" is supplied out-of-band by the verifier, which looks up the expected signer for `(smart_contract, slot_id)` and checks the signature against that address [2](#0-1) , and similarly in `try_replace_chunk` [3](#0-2) . This mirrors the `OnChainLab` bug class: the raw hash that gets signed/recovered is never bound to the "verifying contract" (there, `address(this)`; here, the StackerDB smart-contract identifier), so a signature valid in one binding context is also valid in another.

### Finding Description
A principal's signing key controls slot `N` across every StackerDB replica in which that same address happens to be assigned slot `N` (e.g., the same signer occupying the same ordinal slot across multiple `signer-<cycle>-<message-id>` contracts, or across different reward cycles/contracts that reuse the same signer-set ordering) [4](#0-3) . Because the signed digest only commits to `(slot_id, slot_version, data_hash)` and never to the `smart_contract` identifier, a signature produced for contract A's slot N with a given `(slot_version, data_hash)` is byte-for-byte valid for contract B's slot N as well, provided the same signer holds slot N in both and an attacker (or the node forwarding stale/replayed traffic) can present the same `(slot_id, slot_version, data)` under contract B's identifier. `validate_received_chunk` and `try_replace_chunk` both resolve "who is allowed to write this slot" purely via a DB lookup keyed on `smart_contract_id` and never re-derive or check that the signature itself commits to that same contract [5](#0-4) [6](#0-5) . This is exactly the missing-domain-binding pattern from the external report (`keccak256(abi.encode(block.chainid, address(this), hash))` was recommended there); here the missing binding is the StackerDB's `QualifiedContractIdentifier`.

### Impact Explanation
Since chunk data itself is attacker/signer-controlled and only the signature is being replayed, this is not an arbitrary cross-account takeover, but it does break the intended per-contract authentication boundary: a validly signed chunk authored for one StackerDB context can be stored/relayed as authentic under a *different* StackerDB contract identifier as long as slot ownership coincides. Consumers such as `TryFrom<StackerDBChunksEvent> for SignerEvent<T>` key their trust purely on which contract the chunk arrived under and the recovered signer [7](#0-6) ; a replayed-but-validly-signed chunk crossing contract boundaries can cause stale or out-of-context signer/miner data to be accepted as canonical for a StackerDB it was never actually authorized against, i.e., non-canonical/mismatched data served as canonical, and forged-looking (validly signed but out-of-context) data being propagated network-wide via the normal chunk-push/relay path [8](#0-7) .

### Likelihood Explanation
Exploitability requires the same signer address to legitimately hold the same `slot_id` in two different StackerDB contracts, which is a realistic and common configuration (signer sets are assigned slots by ordinal position and the same set/order is reused across the multiple `signer-<cycle>-<message-id>` lane contracts each reward cycle, and potentially across adjacent cycles) [9](#0-8) . No node secret or third-party key is needed — only a chunk that was validly signed by its rightful owner for one context and then replayed under a different, slot-colliding contract identifier.

### Recommendation
Bind the signed digest to the StackerDB's identity, analogous to the recommended `keccak256(abi.encode(block.chainid, address(this), hash))` fix: include the `QualifiedContractIdentifier` (and optionally a chain/network identifier) inside `SlotMetadata::auth_digest()` in `libstackerdb/src/libstackerdb.rs`, and update all `sign`/`verify` call sites (`StackerDBChunkData::sign/verify/recover_pk`, and downstream callers in `stackslib/src/net/stackerdb/mod.rs` and `db.rs`) to pass the contract identifier into the digest computation so a signature is only valid for the specific StackerDB it was produced for.

### Proof of Concept
Conceptually (Rust, using existing test helpers):
1. Create two StackerDB contracts A and B, each configuring the same signer address `S` at `slot_id = 5`.
2. `S` signs a `StackerDBChunkData { slot_id: 5, slot_version: 1, data: b"vote-for-block-X" }` intended for contract A via `chunk_data.sign(&S_privkey)` [10](#0-9) .
3. Call `stackerdbs.try_replace_chunk(&contract_A, &chunk_data.get_slot_metadata(), &chunk_data.data)` — succeeds as expected.
4. Replay the exact same `chunk_data` (unmodified signature) against contract B: `stackerdbs.try_replace_chunk(&contract_B, &chunk_data.get_slot_metadata(), &chunk_data.data)`.
5. Because `auth_digest()` never includes the contract identifier, `slot_desc.verify(&slot_validation.signer)` in `try_replace_chunk` succeeds for contract B too [3](#0-2) , storing/propagating the same signed payload as valid, authentic data for a contract it was never signed for.

    /// Get the digest to sign that authenticates this chunk data and metadata
    fn auth_digest(&self) -> Sha512Trunc256Sum {
        let mut hasher = Sha512_256::new();
        hasher.update(self.slot_id.to_be_bytes());
        hasher.update(self.slot_version.to_be_bytes());
        hasher.update(self.data_hash.0);
        Sha512Trunc256Sum::from_hasher(hasher)
    }

    /// pushed to us (with [`PeerNetwork::handle_unsolicited_StackerDBPushChunk`])
    ///
    /// NOTE: does not check write frequency, since the caller has different ways of doing this.
    /// Returns:
    /// - Ok(true) if the chunk is valid
    /// - Ok(false) if the chunk is invalid
    /// - Err(..) on DB error
    pub fn validate_received_chunk(
        &self,
        smart_contract_id: &QualifiedContractIdentifier,
        config: &StackerDBConfig,
        data: &StackerDBChunkData,
        expected_versions: &[u32],
    ) -> Result<bool, net_error> {
        // validate -- must not exceed this replica's configured chunk size.
        if (data.data.len() as u64) > config.chunk_size {
            info!(
                "Received StackerDBChunk for {} ID {}, which is oversized: {} bytes (max {} bytes)",
                smart_contract_id,
                data.slot_id,
                data.data.len(),
                config.chunk_size
            );
            return Ok(false);
        }

        // validate -- must be a valid chunk
        let Some(expected_version) = expected_versions.get(data.slot_id as usize) else {
            info!(
                "Received StackerDBChunk for {} ID {}, which is too big ({})",
                smart_contract_id,
                data.slot_id,
                expected_versions.len()
            );
            return Ok(false);
        };

        // validate -- must be signed by the expected author
        let addr = match self
            .stackerdbs
            .get_slot_signer(smart_contract_id, data.slot_id)?
        {
            Some(addr) => addr,
            None => {
                return Ok(false);
            }
        };

        let slot_metadata = data.get_slot_metadata();
        if !slot_metadata.verify(&addr)? {
            info!(
                "StackerDBChunk for {} ID {} is not signed by {}",
                smart_contract_id, data.slot_id, &addr
            );
            return Ok(false);
        }

    /// Otherwise, this errors out with Error::StaleChunk
    pub fn try_replace_chunk(
        &self,
        smart_contract: &QualifiedContractIdentifier,
        slot_desc: &SlotMetadata,
        chunk: &[u8],
    ) -> Result<(), net_error> {
        // Check per-replica chunk-size cap.
        if (chunk.len() as u64) > self.config.chunk_size {
            return Err(net_error::StackerDBChunkTooBig(chunk.len()));
        }

        let slot_validation = self
            .get_slot_validation(smart_contract, slot_desc.slot_id)?
            .ok_or(net_error::NoSuchSlot(
                smart_contract.clone(),
                slot_desc.slot_id,
            ))?;

        if !slot_desc.verify(&slot_validation.signer)? {
            return Err(net_error::BadSlotSigner(
                slot_validation.signer,
                slot_desc.slot_id,
            ));
