## Title
Guard Representative addresses can accrue witness rewards that become permanently unwithdrawable, freezing funds - (File: chainbase/src/main/java/org/tron/core/service/MortgageService.java)

### Summary
The reported Notional/AuraStash bug is a class-mismatch issue: the reward-accrual path can generate a reward that the reward-redemption path doesn't recognize/allow to be reclaimed, so the value becomes permanently stuck. The same class of bug exists in java-tron's witness reward system: `MortgageService` accrues block/standby/transaction-fee/brokerage rewards for *any* witness address without excluding "Guard Representative" (genesis witness) addresses, but every reward-withdrawal entry point (`WithdrawBalanceActuator`, `WithdrawRewardProcessor`) explicitly and unconditionally rejects withdrawal for those same addresses. Once such an address accrues reward, that value can never be extracted through any available on-chain path.

### Finding Description
Reward accrual for a witness happens unconditionally in `MortgageService.payReward()`, called from `payBlockReward()`, `payTransactionFeeReward()`, and `payStandbyWitness()`: [1](#0-0) 

This method is invoked for the actual block-producing witness and for all standby witnesses every cycle/block via `Manager.payReward()`, with no check for whether the recipient address is a genesis ("Guard Representative", GP) witness: [2](#0-1) 

Meanwhile, the two entry points that let an account actually redeem accrued reward both hard-block GP addresses:

`WithdrawBalanceActuator.validate()`: [3](#0-2) 

`WithdrawRewardProcessor.validate()` (the TVM native-contract path used for `withdrawreward` opcode): [4](#0-3) 

Because `payReward`/`payStandbyWitness`/`VoteWitnessActuator` reward accrual paths (which call `mortgageService.withdrawReward(ownerAddress)` internally to roll cycle reward into `AccountCapsule.allowance`, see `VoteWitnessActuator.countVoteAccount`) never check for GP status: [5](#0-4) 

...an address that is both (a) listed as a genesis witness in the chain's genesis config and (b) elected/active as a standby or active Super Representative will keep having block reward, transaction-fee reward, standby pay, and vote-based brokerage/`allowance` accumulate in `DelegationStore`/`AccountCapsule.getAllowance()`. However, that value can never leave the protocol: both withdrawal actuators unconditionally throw `ContractValidateException` for any address matching a genesis witness, with no alternate redemption mechanism (no admin sweep, no reassignment, no exception).

### Impact Explanation
Any TRX value that accumulates as `allowance`/`DelegationStore` reward for a Guard Representative address is permanently locked and can never be transferred to spendable balance — this constitutes permanent freezing of protocol-legitimate funds, satisfying the "permanent freezing of funds" impact bar. The amount at risk scales with how long/actively such an address remains an elected witness, since rewards (block reward, standby pay, transaction fee reward, and voter brokerage) accrue every cycle with no cap.

### Likelihood Explanation
This requires only that a genesis-witness-listed address becomes (or already is) an actively voted-in Super Representative or standby witness — a normal, permissionless outcome of TRX holders casting votes via `VoteWitnessContract`, which is an unprivileged, broadcastable transaction. No malicious SR/witness collusion or special privilege is needed beyond the address being both a genesis witness and receiving votes, both of which are ordinary chain states. Reward accrual itself is fully automatic per block via `Manager.payReward()`.

### Recommendation
Either (a) exclude GP/genesis-witness addresses from reward accrual entirely (skip `payReward`/`payStandbyWitness`/brokerage credit for such addresses), mirroring the restriction already enforced at withdrawal time, or (b) provide a legitimate redemption path for reward already accrued to GP addresses so value is not stranded. The accrual-side check should be made symmetric with the withdrawal-side check in `WithdrawBalanceActuator.validate()` / `WithdrawRewardProcessor.validate()`.

### Proof of Concept
1. Configure/observe a genesis witness address `G` present in `CommonParameter.getInstance().getGenesisBlock().getWitnesses()`.
2. Have TRX holders vote for `G` via `VoteWitnessContract` until `G` becomes an active or standby witness.
3. Blocks are produced; `Manager.payReward()` calls `mortgageService.payBlockReward()`/`payStandbyWitness()`/`payTransactionFeeReward()` for `G`, incrementing `DelegationStore` reward and `AccountCapsule.allowance` for `G` — see `MortgageService.payReward()`/`payStandbyWitness()`.
4. Submit a `WithdrawBalanceContract` (or `withdrawreward` TVM call) from `G`. Both `WithdrawBalanceActuator.validate()` and `WithdrawRewardProcessor.validate()` throw `ContractValidateException` because `G` matches a genesis witness, permanently blocking redemption of the accrued reward, which remains locked forever in `allowance`/`DelegationStore`.

  public void payStandbyWitness() {
    List<WitnessCapsule> witnessStandbys = witnessStore.getWitnessStandby(
        dynamicPropertiesStore.allowWitnessSortOptimization());
    long voteSum = witnessStandbys.stream().mapToLong(WitnessCapsule::getVoteCount).sum();
    if (voteSum < 1) {
      return;
    }
    long totalPay = dynamicPropertiesStore.getWitness127PayPerBlock();
    double eachVotePay = (double) totalPay / voteSum;
    for (WitnessCapsule w : witnessStandbys) {
      long pay = (long) (w.getVoteCount() * eachVotePay);
      payReward(w.getAddress().toByteArray(), pay);
      logger.debug("Pay {} stand reward {}.", Hex.toHexString(w.getAddress().toByteArray()), pay);
    }
  }

  public void payBlockReward(byte[] witnessAddress, long value) {
    logger.debug("Pay {} block reward {}.", Hex.toHexString(witnessAddress), value);
    payReward(witnessAddress, value);
  }

  public void payTransactionFeeReward(byte[] witnessAddress, long value) {
    logger.debug("Pay {} transaction fee reward {}.", Hex.toHexString(witnessAddress), value);
    payReward(witnessAddress, value);
  }

  private void payReward(byte[] witnessAddress, long value) {
    long cycle = dynamicPropertiesStore.getCurrentCycleNumber();
    int brokerage = delegationStore.getBrokerage(cycle, witnessAddress);
    double brokerageRate = (double) brokerage / 100;
    long brokerageAmount = (long) (brokerageRate * value);
    value -= brokerageAmount;
    delegationStore.addReward(cycle, witnessAddress, value);
    adjustAllowance(witnessAddress, brokerageAmount);
  }

  private void payReward(BlockCapsule block) {
    WitnessCapsule witnessCapsule =
        chainBaseManager.getWitnessStore().getUnchecked(block.getInstance().getBlockHeader()
            .getRawData().getWitnessAddress().toByteArray());
    if (getDynamicPropertiesStore().allowChangeDelegation()) {
      mortgageService.payBlockReward(witnessCapsule.getAddress().toByteArray(),
          getDynamicPropertiesStore().getWitnessPayPerBlock());
      mortgageService.payStandbyWitness();

      if (chainBaseManager.getDynamicPropertiesStore().supportTransactionFeePool()) {
        long transactionFeeReward = floorDiv(
            chainBaseManager.getDynamicPropertiesStore().getTransactionFeePool(),
                Constant.TRANSACTION_FEE_POOL_PERIOD,
            chainBaseManager.getDynamicPropertiesStore().disableJavaLangMath());
        mortgageService.payTransactionFeeReward(witnessCapsule.getAddress().toByteArray(),
            transactionFeeReward);
        chainBaseManager.getDynamicPropertiesStore().saveTransactionFeePool(
            chainBaseManager.getDynamicPropertiesStore().getTransactionFeePool()
                - transactionFeeReward);
      }

  public void validate(WithdrawRewardParam param, Repository repo) throws ContractValidateException {
    if (repo == null) {
      throw new ContractValidateException(STORE_NOT_EXIST);
    }

    byte[] ownerAddress = param.getOwnerAddress();

    boolean isGP = CommonParameter.getInstance()
        .getGenesisBlock().getWitnesses().stream().anyMatch(witness ->
            Arrays.equals(ownerAddress, witness.getAddress()));
    if (isGP) {
      throw new ContractValidateException(
          ACCOUNT_EXCEPTION_STR + StringUtil.encode58Check(ownerAddress)
              + "] is a guard representative and is not allowed to withdraw Balance");
