### Title
Unauthenticated stage-1 handshake floods force full Noise crypto processing before certificate/CA verification, with the documented anti-DoS cookie mechanism never implemented - (File: handshake_manager.go / handshake/handshake.proto)

### Summary
The Perennial report describes an attacker triggering an expensive protocol operation (an oracle price request) at negligible cost, because the fee/cost accounting only happens *after* the action is allowed to proceed, letting an attacker repeatedly force costly work onto the system without paying for it, leading to fund drain/DoS. The structurally equivalent pattern in Nebula is in the handshake responder path: any unauthenticated packet (no CA-signed certificate required) that looks like a stage-1 handshake message causes the responder to run the full expensive Noise cryptographic exchange (X25519 DH, key derivation, payload decryption) *before* any certificate/CA-pool verification takes place, and Nebula has no implemented anti-DoS admission-control mechanism to charge/rate-limit that cost up front.

### Finding Description
`HandshakeManager.HandleIncoming` dispatches any inbound packet with `MessageCounter == 1` and `RemoteIndex == 0` directly to `beginHandshake`, gated only by the remote-allow-list (an IP/CIDR filter, not an identity check): [1](#0-0) 

`beginHandshake` then unconditionally constructs a new `handshake.Machine` and calls `machine.ProcessPacket`, which performs the full Noise `ReadMessage` (elliptic-curve Diffie-Hellman and payload decryption) *before* any peer certificate is validated against the CA pool: [2](#0-1) [3](#0-2) 

Certificate verification is delegated to `CertVerifier`, which is only invoked as part of payload processing after the Noise message has already been read/decrypted — i.e., after the expensive asymmetric crypto work has been paid for by the responder, not the initiator: [4](#0-3) 

Only after `ProcessPacket` returns does `beginHandshake` call `hm.validatePeerCert`, which is where CA-pool/cert validation and allow-list checks actually occur: [5](#0-4) [6](#0-5) 

The protocol wire format itself documents that an anti-DoS admission-control field was designed but never wired up: the `Cookie` field in the handshake payload was "reserved for an anti-DoS mechanism that was never implemented. No released version of nebula has ever populated it; the hand-written parser silently skips it on read": [7](#0-6) 

This mirrors the Perennial finding precisely: in both systems, an attacker can trigger an expensive, resource-consuming operation (oracle version request / Noise handshake computation) cheaply because the mechanism meant to gate or charge for that cost (settlement fee accounting / anti-DoS cookie) either doesn't fire on the cheap path, or was never implemented, while the expensive backend work still executes.

### Impact Explanation
An attacker with no valid, CA-signed certificate can send a flood of malformed-but-well-formed-enough stage-1 packets (`MessageCounter=1`, `RemoteIndex=0`) from spoofable UDP source addresses. Each one forces the responder to:
1. Allocate a new `handshake.Machine` and Noise `HandshakeState`.
2. Run a full X25519 Diffie-Hellman exchange and AEAD payload decryption.
3. Only *after* that CPU cost is paid, reject the packet in certificate/CA-pool verification (`validatePeerCert`) if the embedded certificate is not CA-signed.

Because there is no admission-control/cookie step before the expensive crypto runs, and the wire format's dedicated field for that purpose was explicitly never implemented, this allows a remote, unauthenticated attacker to force asymmetric CPU consumption on any Nebula node reachable over UDP, degrading or denying service to legitimate handshakes (DoS), the same "impact" class the Perennial report categorizes as fund/keeper drain leading to DoS of the Market.

### Likelihood Explanation
Reachability requires only sending crafted UDP packets to a listening Nebula node — no valid CA-issued certificate, no prior authentication, and no access to any peer or lighthouse credential is needed, satisfying the "no CA-signed certificate" constraint. The remote-allow-list check that precedes `beginHandshake` is an IP/CIDR filter, not an authentication control, so any address permitted by that list (in the common configuration, "allow all except explicitly denied") can reach this path. The one open question is exactly how cheap it is for the attacker to construct a stage-1 packet that survives far enough into `ProcessPacket` to force the DH computation (whether Noise's own message parsing rejects malformed messages before doing the DH, versus doing DH unconditionally as part of `ReadMessage`); the code inspected shows the DH/decrypt happens inside `ReadMessage` prior to any cert check, but the precise crypto-cost asymmetry per garbage packet was not fully traced into the underlying `flynn/noise` library, which is out of the indexed repo's scope.

### Recommendation
Implement the previously-reserved anti-DoS admission mechanism (a stateless cookie/proof-of-work challenge, as WireGuard-style protocols use) so that an unauthenticated initiator must demonstrate return-routability or minimal work before the responder commits to running Noise `ReadMessage`/DH on a fresh `Machine`. At minimum, add per-source-address or global rate limiting on `beginHandshake` invocations so that unauthenticated stage-1 floods cannot force unbounded expensive cryptographic work before certificate/CA-pool validation rejects the peer.

### Proof of Concept
Conceptual (not runnable without the full noise/cert stack, based on the traced code path):
1. From an address permitted by the target's `remote_allow_list`, repeatedly send UDP packets shaped as valid Nebula headers with `Type=Handshake`, `Subtype=HandshakeIXPSK0`, `MessageCounter=1`, `RemoteIndex=0`, and a syntactically valid (but not CA-signed) Noise IX message body.
2. Each packet reaches `HandshakeManager.HandleIncoming` → `beginHandshake` (`handshake_manager.go:177-184`, `701-726`), which builds a fresh `handshake.Machine` and calls `ProcessPacket`, performing the Noise `ReadMessage` DH/decrypt (`handshake/machine.go:203-241`) before the embedded certificate is checked against the CA pool in `validatePeerCert` (`handshake_manager.go:992-1038`).
3. Because the `Cookie` anti-DoS field documented in `handshake/handshake.proto:17-28` is never populated or checked, there is no cheap pre-crypto rejection step, so each attacker packet costs the attacker only a UDP send but costs the responder a full asymmetric handshake computation.
4. Repeating step 1 at volume exhausts responder CPU before any certificate is validated, denying legitimate handshakes — the DoS impact analogous to the Perennial oracle-fee-drain DoS. [8](#0-7) [9](#0-8) [10](#0-9) [7](#0-6)

func (hm *HandshakeManager) HandleIncoming(via ViaSender, packet []byte, h *header.H) {
	// Gate on known handshake subtypes. Unknown subtypes (or future ones we
	// don't yet support) are dropped here rather than silently routed through
	// the IX path. Add a case when introducing a new pattern.
	switch h.Subtype {
	case header.HandshakeIXPSK0:
		// supported
	default:
		hm.l.Debug("dropping handshake with unsupported subtype",
			"from", via, "subtype", h.Subtype)
		return
	}

	// First remote allow list check before we know the vpnIp
	if !via.IsRelayed {
		if !hm.lightHouse.GetRemoteAllowList().AllowUnknownVpnAddr(via.UdpAddr.Addr()) {
			hm.l.Debug("lighthouse.remote_allow_list denied incoming handshake", "from", via)
			return
		}
	}

	// First message of a new handshake. The wire format requires RemoteIndex
	// to be zero here (the initiator has no responder index to fill in yet),
	// and generateIndex never allocates 0, so any non-zero RemoteIndex on a
	// stage-1 packet is malformed or someone probing for an index collision.
	// Drop without paying the cost of running noise on a pending Machine.
	if h.MessageCounter == 1 {
		if h.RemoteIndex != 0 {
			hm.l.Debug("dropping stage-1 handshake with non-zero RemoteIndex",
				"from", via, "remoteIndex", h.RemoteIndex)
			return
		}
		hm.beginHandshake(via, packet, h)
		return
	}

	// Continuation message must match a pending handshake by index.
	// Anything else is an orphaned packet (e.g., late retransmit after
	// timeout) and is dropped.
	if hh := hm.queryIndex(h.RemoteIndex); hh != nil {
		hm.continueHandshake(via, hh, packet)
		return
	}
}

// beginHandshake handles an incoming handshake packet that doesn't match any
// existing pending handshake. It creates a new responder Machine and processes
// the first message.
func (hm *HandshakeManager) beginHandshake(via ViaSender, packet []byte, h *header.H) {
	f := hm.f
	cs := f.pki.getCertState()

	v := cs.DefaultVersion()
	if cs.GetCredential(v) == nil {
		f.l.Error("Unable to handshake with host because no certificate is available",
			"from", via, "certVersion", v)
		return
	}

	machine, err := handshake.NewMachine(
		v, cs.GetCredential,
		hm.certVerifier(), func() (uint32, error) { return generateIndex(f.l) },
		false, header.HandshakeIXPSK0,
	)
	if err != nil {
		f.l.Error("Failed to create handshake machine", "from", via, "error", err)
		return
	}

	response, result, err := machine.ProcessPacket(nil, packet)
	if err != nil {
		f.l.Error("Failed to process handshake packet", "from", via, "error", err)
		return
	}

	if result == nil {
		// Multi-message pattern: the responder Machine would need to be
		// registered in hm.indexes so a future inbound packet finds it via
		// continueHandshake. The current manager doesn't do that yet, so
		// fail loudly rather than silently dropping the in-flight handshake.
		// TODO: support multi-message responder flows (XX, pqIX, etc.).
		// See also the IX-shaped cipher key assignment in handshake.Machine.
		f.l.Error("multi-message handshake responder is not supported",
			"from", via, "error", handshake.ErrMultiMessageUnsupported)
		return
	}

	remoteCert := result.RemoteCert
	if remoteCert == nil {
		f.l.Error("Handshake did not produce a peer certificate", "from", via)
		return
	}

	// Validate peer identity
	vpnAddrs, anyVpnAddrsInCommon, ok := hm.validatePeerCert(via, remoteCert)
	if !ok {
		return
	}

// validatePeerCert checks the peer certificate for self-connection and remote allow list.
// Returns the VPN addrs, whether any of them fall within one of our own VPN
// networks, and true if valid; false if rejected.
func (hm *HandshakeManager) validatePeerCert(via ViaSender, remoteCert *cert.CachedCertificate) ([]netip.Addr, bool, bool) {
	f := hm.f
	vpnNetworks := remoteCert.Certificate.Networks()

	// The cert package rejects host certs with no networks at parse time, so
	// reaching this state would mean an invariant was bypassed elsewhere.
	// Refuse explicitly so downstream code (which indexes vpnAddrs[0]) can't
	// panic if that invariant ever changes.
	if len(vpnNetworks) == 0 {
		f.l.Info("No networks in certificate",
			"from", via, "cert", remoteCert)
		return nil, false, false
	}

	vpnAddrs := make([]netip.Addr, len(vpnNetworks))
	anyVpnAddrsInCommon := false

	for i, network := range vpnNetworks {
		if f.myVpnAddrsTable.Contains(network.Addr()) {
			f.l.Error("Refusing to handshake with myself",
				"vpnNetworks", vpnNetworks,
				"from", via,
				"certName", remoteCert.Certificate.Name(),
				"certVersion", remoteCert.Certificate.Version(),
				"fingerprint", remoteCert.Fingerprint,
				"issuer", remoteCert.Certificate.Issuer(),
			)
			return nil, false, false
		}
		vpnAddrs[i] = network.Addr()
		if f.myVpnNetworksTable.Contains(network.Addr()) {
			anyVpnAddrsInCommon = true
		}
	}

	if !via.IsRelayed {
		if !f.lightHouse.GetRemoteAllowList().AllowAll(vpnAddrs, via.UdpAddr.Addr()) {
			f.l.Debug("lighthouse.remote_allow_list denied incoming handshake",
				"vpnAddrs", vpnAddrs, "from", via)
			return nil, false, false
		}
	}

	return vpnAddrs, anyVpnAddrsInCommon, true

// ProcessPacket handles an incoming handshake message. It advances the Noise
// state, validates the peer certificate via the verifier, and optionally
// produces a response.
//
// out is a destination buffer the response is appended to and returned. Pass
// nil to allocate fresh, or pass a re-used buffer sliced to length 0 (e.g.
// buf[:0]) with sufficient capacity to avoid allocation. The returned slice
// is nil when no outgoing message is produced (handshake complete on this
// side, or final message of a multi-message pattern).
//
// Returns a non-nil Result when the handshake is complete.
// An error return may not indicate a fatal condition, check Failed() to
// determine if the Machine can still be used.
func (m *Machine) ProcessPacket(out, packet []byte) ([]byte, *Result, error) {
	if m.failed {
		return nil, nil, ErrMachineFailed
	}
	if len(packet) < header.Len {
		return nil, nil, ErrPacketTooShort
	}
	// Reject packets whose subtype doesn't match the one this Machine was
	// built for. A pending handshake that suddenly receives a different
	// subtype on its index is either a stray packet that matched by chance
	// or a peer protocol violation; drop it without failing the Machine so
	// the legitimate retransmit can still complete.
	if header.MessageSubType(packet[1]) != m.subtype {
		return nil, nil, ErrSubtypeMismatch
	}
	if m.result.Initiator && m.hs.MessageIndex() == 0 {
		m.failed = true
		return nil, nil, ErrInitiateNotCalled
	}

	// The (eKey, dKey) ordering here is correct for IX, where the initiator
	// completes the handshake by reading the responder's stage-2 message.
	// noise returns (cs1, cs2) where cs1 is the initiator->responder cipher.
	// For 3-message patterns where a responder finishes by reading the final
	// message, this ordering would be wrong; revisit when XX/pqIX lands.
	msg, eKey, dKey, err := m.hs.ReadMessage(nil, packet[header.Len:])
	if err != nil {
		// Noise ReadMessage failed. The noise library checkpoints and rolls back
		// on failure, so the Machine is still alive. The caller can retry with
		// a different packet.
		return nil, nil, fmt.Errorf("noise ReadMessage: %w", err)
	}

	// From here on, noise state has advanced. Any error is fatal.
	flags := m.peerMsgFlags()

	if err := m.processPayload(msg, flags); err != nil {
		return nil, nil, err
	}
