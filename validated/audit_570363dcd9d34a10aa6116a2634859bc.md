### Title
`pallet_dap::drip_issuance` permanently forfeits inflation time when clamped by `MaxElapsedPerDrip`, under-issuing budget-recipient rewards - (File: `substrate/frame/dap/src/lib.rs`)

### Summary
`pallet_dap::drip_issuance` computes `elapsed = now - LastIssuanceTimestamp`, clamps it to `T::MaxElapsedPerDrip` for the *minting* calculation, but then unconditionally sets `LastIssuanceTimestamp = now` rather than `LastIssuanceTimestamp = last + elapsed_actually_used`. This is the same broken-invariant pattern as the RocketPool `inflationCalcBlock` bug: the checkpoint is advanced past the point that inflation was actually accounted for, so the un-minted remainder is silently and permanently lost rather than carried forward to the next drip.

### Finding Description [1](#0-0) 

```rust
pub(crate) fn drip_issuance() -> Weight {
    let now_moment = T::Time::now();
    let now: u64 = now_moment.saturated_into();
    let last = LastIssuanceTimestamp::<T>::get();
    let mut elapsed = now.saturating_sub(last);
    ...
    // Apply safety ceiling on elapsed time.
    let max_elapsed = T::MaxElapsedPerDrip::get();
    if elapsed > max_elapsed {
        Self::deposit_event(Event::Unexpected(UnexpectedKind::ElapsedClamped { ... }));
        elapsed = max_elapsed;
    }

    // Always advance the clock so elapsed time doesn't accumulate across skipped drips.
    LastIssuanceTimestamp::<T>::put(now);

    let _ = Self::mint_and_distribute(elapsed);
    ...
}
```

The comment "Always advance the clock so elapsed time doesn't accumulate across skipped drips" is an explicit acknowledgement of the design decision that causes the bug: whenever real elapsed time between two `on_initialize` executions exceeds `MaxElapsedPerDrip` (e.g. a chain stall/halt, a long parachain-block gap, a runtime upgrade freeze, or any period where blocks are not produced for longer than the ceiling), only `max_elapsed` worth of issuance is minted via `mint_and_distribute(elapsed)`, but the checkpoint `LastIssuanceTimestamp` is set to the *full* `now` value. The difference `(now - last) - max_elapsed` — i.e., the time beyond the ceiling — is dropped from all future accounting: the next drip's `elapsed` calculation starts from `now`, not from `last + max_elapsed`, so that gap is never minted for and never revisited.

This mirrors the RocketPool defect exactly: the checkpoint (`inflationCalcBlock` / here `LastIssuanceTimestamp`) is updated to "the block/time the function was invoked" instead of "the point up to which inflation was actually calculated" (`last + actually-processed-interval`). The safety ceiling `IssuanceCadence`/`MaxElapsedPerDrip` guards intend to bound single-drip mint size for defensive reasons, but the current implementation converts that defensive clamp into a permanent, uncorrectable loss of accrued issuance for all `BudgetRecipients` (staker rewards pot, validator incentive pot, DAP buffer), rather than deferring the remainder to be minted on a subsequent drip.

### Impact Explanation
Every registered `BudgetRecipient` (staker reward pot, validator incentive pot, DAP buffer) permanently loses its proportional share of the un-minted remainder whenever a stall exceeding `MaxElapsedPerDrip` occurs, because `IssuanceCurve::issue` is never invoked for that lost time window and `LastIssuanceTimestamp` no longer reflects it. This is a runtime bug that "compromises intended behavior" of the token-economics inflation schedule: recipients (most notably the staker reward pot funding `pallet-staking-async` in non-minting mode) receive strictly less inflation than the configured issuance curve intends, with no path to recover the shortfall. Depending on how long/how often such gaps occur (chain restarts, long finality stalls, XCM/consensus incidents), this compounds into a measurable, permanent under-issuance of the protocol's reward economics — analogous to the "APY silently dropping below configured rate" impact in the original report, but here it is deterministic under any real stall rather than needing external manipulation.

### Likelihood Explanation
The clamp path is not gated behind any privileged or malicious actor — it triggers purely as a function of elapsed wall-clock time between two executions of `on_initialize`, which is entirely a byproduct of normal chain operation (network stalls, long parachain block production gaps, upgrades). No governance, admin, validator misbehavior, or off-chain infrastructure compromise is required; it is a deterministic consequence of the code path itself once `now - last > MaxElapsedPerDrip`, and the migration/tests in `substrate/frame/dap/src/migrations.rs` and `mock.rs` confirm `MaxElapsedPerDrip` is a real, configured runtime parameter (600_000ms in the test mock) that is expected to be hit occasionally by design (hence the explicit event `ElapsedClamped`), not an unreachable edge case.

### Recommendation
On clamp, advance `LastIssuanceTimestamp` only by the amount of elapsed time actually passed to `mint_and_distribute`, i.e. `LastIssuanceTimestamp::<T>::put(last.saturating_add(elapsed))` (using the clamped `elapsed`) instead of `now`. This preserves the un-accounted remainder so it is picked up and minted on the next drip (functionally identical to the RocketPool fix of setting `inflationCalcBlock = lastTimeOfInflationMint + interval * inflationIntervals` instead of `block.number`), while still bounding the size of any single drip's mint via the existing ceiling.

### Proof of Concept
1. Configure a runtime with `IssuanceCadence = 60_000` and `MaxElapsedPerDrip = 600_000` (10 minutes), as in `substrate/frame/dap/src/mock.rs`.
2. Set `LastIssuanceTimestamp = T0`.
3. Advance `T::Time` (e.g. simulate a chain stall / long gap between block executions) to `T0 + 1_200_000` (20 minutes elapsed) before the next call to `on_initialize`/`drip_issuance`.
4. `drip_issuance` computes `elapsed = 1_200_000`, clamps it to `elapsed = 600_000` (`ElapsedClamped` event emitted), calls `mint_and_distribute(600_000)`, then executes `LastIssuanceTimestamp::<T>::put(now)` where `now = T0 + 1_200_000`.
5. Verify: `mint_and_distribute` was only invoked with 600_000ms worth of issuance; the remaining 600_000ms of intended inflation for all `BudgetRecipients` is never minted in this or any subsequent call, because `LastIssuanceTimestamp` now equals `T0 + 1_200_000`, not `T0 + 600_000`. The shortfall is permanent and unrecoverable through any public interface.

			// For existing chains, use `migrations::MigrateV1ToV2` to seed this
			// value from ActiveEra.start so this branch is never hit post-upgrade.
			if last == 0 {
				LastIssuanceTimestamp::<T>::put(now);
				return T::DbWeight::get().reads_writes(2, 2);
			}

			// Apply safety ceiling on elapsed time.
			let max_elapsed = T::MaxElapsedPerDrip::get();
			if elapsed > max_elapsed {
				Self::deposit_event(Event::Unexpected(UnexpectedKind::ElapsedClamped {
					actual_elapsed: elapsed,
					ceiling: max_elapsed,
				}));
				elapsed = max_elapsed;
			}

			// Always advance the clock so elapsed time doesn't accumulate across skipped drips.

		}
