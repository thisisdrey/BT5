### Title
`staking_contract::set_beneficiary_for_operator` Lacks APT Registration Guard, Allowing Operator to Permanently Block Staker Distributions — (`aptos-move/framework/aptos-framework/sources/staking_contract.move`)

---

### Summary

`staking_contract::set_beneficiary_for_operator` allows an operator to set any address as their commission beneficiary without verifying that the address can receive `AptosCoin`. When `distribute_internal` later calls `aptos_account::deposit_coins(beneficiary, ...)`, if the beneficiary is not registered for `AptosCoin` **and** has disabled direct coin transfers, the call aborts. Because `distribute_internal` is called atomically inside `unlock_stake`, `switch_operator`, and `distribute`, the abort propagates and permanently blocks the staker from unlocking or withdrawing their stake.

The `vesting::set_beneficiary` function contains an explicit guard and comment acknowledging exactly this risk, but `staking_contract::set_beneficiary_for_operator` has no equivalent guard.

---

### Finding Description

`aptos_account::deposit_coins<CoinType>` aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` when two conditions hold simultaneously:

1. The recipient has **no** `CoinStore<AptosCoin>` (i.e., `coin::is_account_registered<AptosCoin>(to)` is `false`).
2. The recipient has called `set_allow_direct_coin_transfers(account, false)`, making `can_receive_direct_coin_transfers(to)` return `false`. [1](#0-0) 

An account created via `aptos_account::create_account` receives only a primary fungible store (FA store), **not** a `CoinStore<AptosCoin>`, so condition 1 is satisfied for any freshly created account. [2](#0-1) 

`staking_contract::set_beneficiary_for_operator` sets the operator's commission recipient with no APT-registration check: [3](#0-2) 

`distribute_internal` then routes the operator's commission share to `beneficiary_for_operator(operator)` and calls `deposit_coins` on it: [4](#0-3) 

If that call aborts, the entire transaction reverts. `distribute_internal` is called unconditionally inside `unlock_stake`, `switch_operator`, and `distribute`: [5](#0-4) [6](#0-5) 

By contrast, `vesting::set_beneficiary` explicitly guards against this with `assert_account_is_registered_for_apt` and a comment explaining the exact risk: [7](#0-6) 

`staking_contract::set_beneficiary_for_operator` has no equivalent guard.

---

### Impact Explanation

Once the operator sets a blocking beneficiary and inactive/pending-inactive coins exist in the stake pool, every call to `distribute`, `unlock_stake`, and `switch_operator` by the staker reverts. The staker's APT is locked in the stake pool with no path to withdrawal until the operator voluntarily changes the beneficiary or the beneficiary re-enables direct coin transfers. This constitutes a permanent freeze of staking balances reachable by an unprivileged operator transaction.

---

### Likelihood Explanation

Any operator with an active staking contract can trigger this in one transaction. The attack requires:
1. Creating a fresh account (no `CoinStore<AptosCoin>`).
2. Calling `set_allow_direct_coin_transfers(new_account, false)`.
3. Calling `set_beneficiary_for_operator(operator, new_account)`.

All three steps are unprivileged entry functions available on mainnet. The operator may be motivated to DoS a staker (e.g., to prevent stake withdrawal during a dispute or to extract leverage).

---

### Recommendation

Add the same guard that `vesting::set_beneficiary` uses:

```move
public entry fun set_beneficiary_for_operator(
    operator: &signer, new_beneficiary: address
) acquires BeneficiaryForOperator {
    assert!(
        features::operator_beneficiary_change_enabled(),
        std::error::invalid_state(EOPERATOR_BENEFICIARY_CHANGE_NOT_SUPPORTED)
    );
+   // Verify the beneficiary can receive APT so distribute_internal cannot be blocked.
+   aptos_account::assert_account_is_registered_for_apt(new_beneficiary);
    ...
}
```

`assert_account_is_registered_for_apt` checks both account existence and `coin::is_account_registered<AptosCoin>`, which is sufficient to bypass the `can_receive_direct_coin_transfers` branch in `deposit_coins`. [8](#0-7) 

---

### Proof of Concept

```
// Step 1 – operator creates a fresh account with no CoinStore<AptosCoin>
aptos_account::create_account(@blocker);          // FA store only, no coin store

// Step 2 – blocker disables direct coin transfers
aptos_account::set_allow_direct_coin_transfers(@blocker_signer, false);

// Step 3 – operator sets the blocker as beneficiary (no guard, succeeds)
staking_contract::set_beneficiary_for_operator(@operator_signer, @blocker);

// Step 4 – staker tries to unlock stake after lockup expires
// distribute_internal is called; inactive coins > 0; deposit_coins(@blocker, ...) aborts
// → unlock_stake aborts; staker's APT is frozen
staking_contract::unlock_stake(@staker_signer, @operator, amount);  // ABORTS

// Step 5 – staker tries to switch operators to escape
// switch_operator also calls distribute_internal → also aborts
staking_contract::switch_operator(@staker_signer, @operator, @new_operator, 10); // ABORTS
```

    public entry fun set_beneficiary_for_operator(
        operator: &signer, new_beneficiary: address
    ) acquires BeneficiaryForOperator {
        assert!(
            features::operator_beneficiary_change_enabled(),
            std::error::invalid_state(EOPERATOR_BENEFICIARY_CHANGE_NOT_SUPPORTED)
        );
        // The beneficiay address of an operator is stored under the operator's address.
        // So, the operator does not need to be validated with respect to a staking pool.
        let operator_addr = signer::address_of(operator);
        let old_beneficiary = beneficiary_for_operator(operator_addr);
        if (exists<BeneficiaryForOperator>(operator_addr)) {
            borrow_global_mut<BeneficiaryForOperator>(operator_addr).beneficiary_for_operator =
                new_beneficiary;
        } else {
            move_to(
                operator,
                BeneficiaryForOperator { beneficiary_for_operator: new_beneficiary }
            );
        };

        emit(
            SetBeneficiaryForOperator {
                operator: operator_addr,
                old_beneficiary,
                new_beneficiary
            }
        );
    }
