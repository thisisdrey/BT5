Audit Report

## Title
Unbounded slippage in `SwapFirstAssetTrader::refund_weight` lets an attacker sandwich XCM fee refunds and drain refunded value via the AssetConversion pool - (File: cumulus/primitives/utility/src/lib.rs)

## Summary
`SwapFirstAssetTrader::refund_weight` swaps unused fee credit from the `Target` asset back into the user's original fee asset via `SwapCredit::swap_exact_tokens_for_tokens(vec![Target::get(), refund_swap_asset], refund, None)`, passing `None` as the minimum-output bound [1](#0-0)  This is confirmed in the live source and contrasts with `buy_weight`, which correctly requests an exact output via `swap_tokens_for_exact_tokens` [2](#0-1) , and with the analogous refund logic in the transaction-payment asset-conversion adapter, which always quotes and enforces a minimum via `Some(refund_asset_amount)` before swapping back.

## Finding Description
`pallet_asset_conversion`'s swap dispatchables enforce `ProvidedMinimumNotSufficientForSwap` only when `amount_out_min` is `Some(_)`; when `None` is passed, the check is skipped entirely and any nonzero output is accepted. `refund_weight` extracts the unused portion of `total_fee` (held in `Target` asset) and calls `swap_exact_tokens_for_tokens` with `None`, so the refund swap accepts whatever price the pool currently offers [3](#0-2) . The underlying `AssetConversion` pool is public and permissionlessly tradable via dispatchables like `swap_exact_tokens_for_tokens`, so any account can move reserves immediately before the refund executes and reverse the trade afterward, capturing the spread. This type is wired into the XCM `Trader` configuration in asset-hub-rococo, asset-hub-westend, penpal, and the staking-async parachain runtime (confirmed via `xcm_config.rs` references to `SwapFirstAssetTrader` in each), so `refund_weight` runs on any XCM message overpaying weight fees in a swappable, non-`Target` asset — a routine occurrence given conservative fee estimation.

## Impact Explanation
The corrupted value is the amount of the user's original fee-payment asset credited back on refund. Sandwiching the refund swap allows an attacker to extract value from the refund at the expense of the intended beneficiary (the paying account), which is a form of public underpriced work / value non-conservation during fee settlement on a public AMM pool, reachable by any unprivileged account with no special access.

## Likelihood Explanation
The attack requires only observing/predicting an XCM message that will trigger a nontrivial refund and racing ordinary public swap extrinsics against the same pool before and after the refund executes — no privileged relayer, governance, or validator behavior is needed, matching the required "unprivileged external attacker using public extrinsics" bar.

## Recommendation
Before calling `SwapCredit::swap_exact_tokens_for_tokens` in `refund_weight`, quote the current price via `QuotePrice::quote_price_exact_tokens_for_tokens(Target::get(), refund_swap_asset, refund_amount, true)` and pass `Some(quoted_min)` (with reasonable tolerance) as `amount_out_min`, mirroring the pattern in the asset-conversion transaction-payment adapter's `correct_and_deposit_fee`. On failure/insufficient output, retain the credit in `total_fee` as the existing error branch already does.

## Proof of Concept
1. Configure a runtime using `SwapFirstAssetTrader` as the XCM `Trader` (as in asset-hub-rococo/westend, penpal, or staking-async parachain) with an `AssetConversion` pool between `Target` and a foreign asset.
2. Attacker observes an incoming XCM message paying fees in the foreign asset with overprovisioned `payment`.
3. Immediately before execution, attacker calls the public `swap_tokens_for_exact_tokens`/`swap_exact_tokens_for_tokens` dispatchable to skew the pool reserves so `Target -> foreign` conversion is unfavorable.
4. The XCM message executes; `buy_weight` withdraws the exact `Target` fee; the unused portion triggers `refund_weight`, which swaps `Target -> foreign` with `None` as `amount_out_min`, accepting the skewed rate [1](#0-0) .
5. Attacker reverses the initial swap, pocketing the spread extracted from the undervalued refund.
