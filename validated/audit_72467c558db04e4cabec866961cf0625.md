### Title
Kamino `kamino_harvest_reward` lacks reward-mint/farm identity validation present in the Drift equivalent, allowing the "reward" harvest path to drain the bank's actual staked collateral instead of genuine yield rewards - (File: `programs/marginfi/src/instructions/kamino/harvest_reward.rs`)

### Summary
The Sherlock finding is a bug-class about a "harvest/reinvest"-style operation failing to exclude the protocol's own core asset (the BPT LP token) from the set of tokens that can be moved out to an external destination, letting the vault's actual collateral be siphoned off under the guise of a reward. In marginfi-v2's external-integration harvest instructions, the same bug class recurs: the Drift integration explicitly defends against this (`drift_harvest_reward`), while the Kamino integration (`kamino_harvest_reward`) contains no equivalent defense at all.

### Finding Description
`DriftHarvestReward` explicitly guards against harvesting the bank's own position/mint: [1](#0-0) 

This constraint set ensures the "harvest" market can never be the bank's own spot market or share the bank's own mint — i.e., it prevents the reward-harvest path from being used to move the bank's actual collateral asset.

`KaminoHarvestReward`, however, has no such protection. Its `#[derive(Accounts)]` struct only checks the bank's asset tag; every other account relevant to which farm/reward is being harvested — `user_state`, `farm_state`, `global_config`, `rewards_vault`, `rewards_treasury_vault`, `farm_vaults_authority` — is declared as a bare `UncheckedAccount` with no `has_one`, `seeds`, or `constraint` tying it back to the bank's own Kamino obligation/farm, and `reward_mint` is never compared against `bank.mint`: [2](#0-1) 

The handler itself simply diffs the reward ATA balance before/after the CPI and forwards the full delta to the global fee wallet, with no sanity check on what mint or farm was actually harvested: [3](#0-2) 

Compare this to the Drift design intent, documented directly in the code: [4](#0-3) 

The Kamino instruction is missing this class of check entirely — there is nothing preventing `farm_state`/`reward_mint` from resolving to the bank's own Kamino reserve/collateral mint rather than a genuinely separate reward configuration.

### Impact Explanation
If Kamino's Farms CPI accounting does not itself strictly wall off "unclaimed reward" balances from staked principal for a given `(farm_state, reward_index)` pair, the missing identity checks mean the harvest path could be used to redirect the bank's actual deposited collateral (rather than incidental reward tokens) to the `global_fee_wallet`, which is a form of unauthorized transfer of user funds out of the bank's liquidity vault authority-controlled position, directly analogous to selling the BPT LP token that represents vault principal. This would cause a shortfall between the bank's recorded liabilities/deposits and its actual backing assets (insolvency/bad debt risk for depositors).

### Likelihood Explanation
The instruction's account validation is reachable by whoever is permitted to call `kamino_harvest_reward` (no `Signer`/authority field is present in the accounts struct as inspected, and none of the sensitive Kamino-side accounts are bound to the bank via Anchor constraints), which is a materially weaker access-control/identity-binding posture than the parallel, already-hardened `drift_harvest_reward` instruction in the same codebase — indicating this is a real gap and not an intentional design choice, since the sibling integration explicitly closes this exact class of issue.

### Recommendation
Mirror the Drift integration's protections in `KaminoHarvestReward`:
- Add a constraint that `reward_mint.key() != bank.load()?.mint`.
- Bind `farm_state`/`user_state`/`global_config`/`rewards_vault`/`rewards_treasury_vault`/`farm_vaults_authority` to the bank's actual Kamino obligation/reserve via `has_one`/PDA `seeds` constraints (as is done for the equivalent Kamino deposit/withdraw instructions), so an unrelated or same-collateral farm cannot be substituted.
- Verify (via CPI-return data or explicit farm/reserve metadata) that the harvested reward index corresponds to a reward mint distinct from the reserve's own collateral/liquidity mint before forwarding the harvested amount.

### Proof of Concept
Not independently verified end-to-end because the exact isolation guarantees of the external Kamino Farms program's `HarvestReward` CPI (whether "rewards_issued_unclaimed" can never overlap with staked principal for a same-mint reward configuration) could not be confirmed from the indexed files. What is concretely confirmed is the structural asymmetry: `drift_harvest_reward` enforces `harvest_drift_spot_market.mint != bank.mint` and `harvest_drift_spot_market != bank.integration_acc_1` [5](#0-4) , while `kamino_harvest_reward` has no analogous constraint on `reward_mint`, `farm_state`, or `user_state` [6](#0-5) . A background Devin agent with repo/tool access should confirm exploitability by tracing the Kamino Farms mock/CPI (`kamino_mocks::kamino_farms::cpi::harvest_reward`) to determine whether a `farm_state`/`reward_index` can be crafted so that `reward_mint` equals the bank's own reserve/collateral mint and the harvested amount is sourced from staked principal rather than a separate reward bucket.

pub fn kamino_harvest_reward(
    ctx: Context<KaminoHarvestReward>,
    reward_index: u64,
) -> MarginfiResult {
    let pre_transfer_balance = accessor::amount(&ctx.accounts.user_reward_ata.to_account_info())?;
    ctx.accounts.cpi_harvest_rewards(reward_index)?;
    let post_transfer_balance = accessor::amount(&ctx.accounts.user_reward_ata.to_account_info())?;
    let received = post_transfer_balance - pre_transfer_balance;
    ctx.accounts
        .cpi_transfer_obligation_owner_to_destination(received)?;
    Ok(())
}
