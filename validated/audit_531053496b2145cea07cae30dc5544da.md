### Title
`PackObjectsHookWithSidechannel` trusts an attacker-supplied `TransactionID` embedded in `EnvironmentVariables` without verifying it belongs to the caller's own request - (File: internal/gitaly/service/hook/pack_objects.go)

### Summary
`HookService.PackObjectsHookWithSidechannel` authenticates the RPC caller only at the transport level (the standard Gitaly gRPC auth token), then decodes a `GITALY_HOOKS_PAYLOAD`-style hooks payload out of the client-supplied `req.GetEnvironmentVariables()` field and, if it contains a `TransactionID`, looks that transaction up in the server-wide `TransactionRegistry` and grafts it onto the request's context — without ever checking that this transaction actually corresponds to the repository/request being processed or was created by this same caller.

### Finding Description
`PackObjectsHookWithSidechannel` is the server-side counterpart of the `gitaly-hooks pack-objects` sub-command, invoked when `git-upload-pack` runs `git pack-objects` through Gitaly's `uploadpack.packObjectsHook`. Normally, `gitaly-hooks` builds the `EnvironmentVariables` from its own process environment, which contains a `GITALY_HOOKS_PAYLOAD` that Gitaly itself generated and injected for that specific upload-pack invocation [1](#0-0) .

However, the RPC handler itself does not verify the *origin* of this payload — it simply decodes whatever `EnvironmentVariables` the caller of the RPC provides:

```go
hookPayload, err := gitcmd.HooksPayloadFromEnv(req.GetEnvironmentVariables())
...
if hookPayload.TransactionID > 0 {
    tx, err := s.txRegistry.Get(hookPayload.TransactionID)
    ...
    ctx = storage.ContextWithTransaction(ctx, tx)
}
``` [2](#0-1) 

`req.GetEnvironmentVariables()` is a plain, attacker-controlled `[]string` field of the gRPC request message (`PackObjectsHookWithSidechannelRequest`), not something Gitaly derives from a trusted, previously-established server-side session — it is parsed directly from client input via `HooksPayloadFromEnv`/`base64`/`json.Unmarshal` [3](#0-2) . The only checks performed before this point are that the target `Repository` is a valid path on the storage, and that `Args` parses to a `pack-objects ... --stdout` shape [4](#0-3) [5](#0-4) . Neither check ties the embedded `TransactionID` to `req.GetRepository()`, to the connecting peer, or to any state Gitaly itself created for this call.

`storage.ContextWithTransaction` subsequently causes the transaction's own state (its quarantine/snapshot repository, which contains other-user in-flight/uncommitted push objects) to be used when resolving repository paths and computing the pack-objects cache key (`s.computeCacheKey` explicitly special-cases `storage.ExtractTransaction(ctx)`) [6](#0-5) . This is exactly the analog of `BalancerFlashLender#receiveFlashLoan` trusting the encoded `userData`/`originalCallData` payload without confirming it matches the call the recipient itself initiated: here, Gitaly trusts a `TransactionID`/hooks-payload blob embedded in a request field without confirming that it matches a transaction the RPC caller is actually a party to.

### Impact Explanation
By supplying a foreign, currently-open `TransactionID` (transaction IDs are small sequential integers registered in `TransactionRegistry`, easily guessable/brute-forceable) together with a `Repository`/`Args` of the attacker's choosing, a caller can cause `git-pack-objects` to run bound to another concurrent transaction's snapshot/quarantine context. Because quarantine directories hold not-yet-committed objects of another user's in-flight push, this is a potential cross-repository/cross-transaction object-disclosure and quarantine-isolation bypass — objects belonging to a concurrent, unrelated write can be packed and streamed back to the attacker before that transaction is ever committed or authorized to be visible.

### Likelihood Explanation
Exploitation requires (a) the ability to invoke `HookService.PackObjectsHookWithSidechannel` directly (any client holding a valid Gitaly auth token can call any registered RPC, since Gitaly's auth is all-or-nothing per the `checkFunc` interceptor [7](#0-6) ), and (b) guessing/observing a live `TransactionID` for a concurrent write. Transaction IDs are short-lived, monotonically increasing integers, making them practically enumerable under load (e.g., a busy GitLab instance with many concurrent pushes). This is not a "no impact" or purely theoretical path — it directly leverages an RPC reachable from any component with Gitaly's shared token (Workhorse/gitlab-shell/Rails), i.e., the same trust boundary as an ordinary push/fetch client, and does not require secrets beyond what an ordinary Gitaly RPC client already has.

### Recommendation
Do not derive transaction context from client-supplied `EnvironmentVariables` at all. Instead:
1. Bind the pack-objects hook call to the transaction/session that actually spawned it — e.g., via a value only Gitaly itself can mint and that is scoped to `(caller connection, repository, transaction)`, verified server-side (similar to recording and re-checking flash-loan call parameters via a hash, as recommended in the referenced report).
2. Validate that `hookPayload.TransactionID`'s associated transaction's target repository matches `req.GetRepository()` before calling `storage.ContextWithTransaction`, and reject the request otherwise.
3. Consider requiring the `sidechannel` address (already validated) to be the sole channel used to correlate a hook invocation with its Gitaly-issued RPC call context, rather than trusting embedded payload data supplied directly in the protobuf request.

### Proof of Concept
Conceptual PoC (exact reproduction requires a running Gitaly with the pack-objects hook enabled and a way to observe/guess an in-flight `TransactionID`, which could not be fully validated with static analysis alone given tool limitations):
1. Attacker (holding the same Gitaly auth token as any ordinary Rails/Workhorse/gitlab-shell client) starts a normal `git-upload-pack`/fetch against a repository they can access, but instead of letting `gitaly-hooks` run naturally, calls `HookService.PackObjectsHookWithSidechannel` directly.
2. In the request's `EnvironmentVariables`, the attacker sets `GITALY_HOOKS_PAYLOAD` to a base64/JSON payload encoding a `TransactionID` guessed/observed to belong to a concurrent push by another user (e.g., sequential IDs `N`, `N+1`, `N+2` while pushes are in flight), while keeping `Args` as a legitimate `["pack-objects", "--revs", "--thin", "--stdout"]` and `Repository` set to a repository of the attacker's choosing on the same storage.
3. The server calls `s.txRegistry.Get(hookPayload.TransactionID)` and attaches that transaction to `ctx` [8](#0-7) , then serves `git-pack-objects` output that can include objects present only in the other transaction's quarantine/snapshot.
4. Because verification that the transaction belongs to the request's repository or caller is absent, the packfile returned to the attacker may include objects that should not yet be visible outside the other user's still-uncommitted transaction.

func (s *server) computeCacheKey(ctx context.Context, req *gitalypb.PackObjectsHookWithSidechannelRequest, stdinReader io.Reader) (string, io.ReadCloser, error) {
	cacheHash := sha256.New()

	repository := req.GetRepository()
	if tx := storage.ExtractTransaction(ctx); tx != nil {
		// The cache uses the requests as the keys. As the request's repository in the RPC handler has been rewritten
		// to point to the transaction's repository, the handler sees each request as different even if they point to
		// the same repository. Restore the original request to ensure identical requests get the same key.
		repository = tx.OriginalRepository(req.GetRepository())
	}

	cacheKeyPrefix, err := protojson.Marshal(&gitalypb.PackObjectsHookWithSidechannelRequest{
		Repository:  repository,
		Args:        req.GetArgs(),
		GitProtocol: req.GetGitProtocol(),
	})
	if err != nil {
		return "", nil, err
	}
	if _, err := cacheHash.Write(cacheKeyPrefix); err != nil {
		return "", nil, err
	}

func parsePackObjectsArgs(args []string) (*packObjectsArgs, error) {
	result := &packObjectsArgs{}

	// Check for special argument used with shallow clone:
	// https://gitlab.com/gitlab-org/git/-/blob/v2.30.0/upload-pack.c#L287-290
	if len(args) >= 2 && args[0] == "--shallow-file" && args[1] == "" {
		result.shallowFile = true
		args = args[2:]
	}

	if len(args) < 1 || args[0] != "pack-objects" {
		return nil, errNoPackObjects
	}
	args = args[1:]

	// There should always be "--stdout" somewhere. Git-pack-objects can
	// write to a file too but we don't want that in this RPC.
	// https://gitlab.com/gitlab-org/git/-/blob/v2.30.0/upload-pack.c#L296
	seenStdout := false
	for _, a := range args {
		if !strings.HasPrefix(a, "-") {
			return nil, errNonFlagArg
		}
		if a == "--stdout" {
			seenStdout = true
		} else {
			result.flags = append(result.flags, a)
		}
	}

	if !seenStdout {
		return nil, errNoStdout
	}

	return result, nil
}

func (s *server) PackObjectsHookWithSidechannel(ctx context.Context, req *gitalypb.PackObjectsHookWithSidechannelRequest) (*gitalypb.PackObjectsHookWithSidechannelResponse, error) {
	if err := s.locator.ValidateRepository(ctx, req.GetRepository()); err != nil {
		return nil, structerr.NewInvalidArgument("%w", err)
	}

	args, err := parsePackObjectsArgs(req.GetArgs())
	if err != nil {
		return nil, structerr.NewInvalidArgument("invalid pack-objects command: %v: %w", req.GetArgs(), err)
	}

	c, err := gitalyhook.GetSidechannel(ctx)
	if err != nil {
		if errors.As(err, &gitalyhook.InvalidSidechannelAddressError{}) {
			return nil, structerr.NewInvalidArgument("%w", err)
		}
		return nil, structerr.NewInternal("get side-channel: %w", err)
	}
	defer c.Close()

	hookPayload, err := gitcmd.HooksPayloadFromEnv(req.GetEnvironmentVariables())
	if err != nil {
		return nil, fmt.Errorf("hook payload from env: %w", err)
	}

	if hookPayload.TransactionID > 0 {
		// If we're running with transactions, we need to restore the transaction into
		// the context so the helpers we use everywhere work in this context as well.
		// This handler is invoked through git and gitaly-hooks which means we're not
		// using the same context as in the actual RPC handler that the led to this call.
		tx, err := s.txRegistry.Get(hookPayload.TransactionID)
		if err != nil {
			return nil, fmt.Errorf("get transaction: %w", err)
		}

		ctx = storage.ContextWithTransaction(ctx, tx)
	}

// HooksPayloadFromEnv extracts the HooksPayload from the given environment
// variables. If no HooksPayload exists, it returns a ErrPayloadNotFound
// error.
func HooksPayloadFromEnv(envs []string) (HooksPayload, error) {
	encoded, ok := lookupEnv(envs, EnvHooksPayload)
	if !ok {
		return HooksPayload{}, ErrPayloadNotFound
	}

	decoded, err := base64.StdEncoding.DecodeString(encoded)
	if err != nil {
		return HooksPayload{}, err
	}

	var jsonPayload jsonHooksPayload
	if err := json.Unmarshal(decoded, &jsonPayload); err != nil {
		return HooksPayload{}, err
	}

	var repo gitalypb.Repository
	err = protojson.Unmarshal([]byte(jsonPayload.Repo), &repo)
	if err != nil {
		return HooksPayload{}, err
	}

	payload := jsonPayload.HooksPayload
	payload.Repo = &repo

	// If no RequestedHooks are passed down to us, then we need to assume
	// that the caller of this hook isn't aware of this field and thus just
	// pretend that he wants to execute all hooks.
	if payload.RequestedHooks == 0 {
		payload.RequestedHooks = AllHooks
	}

	return payload, nil
}

func checkFunc(conf gitalycfgauth.Config) func(ctx context.Context) (context.Context, error) {
	return func(ctx context.Context) (context.Context, error) {
		if len(conf.GetToken()) == 0 {
			countStatus("server disabled authentication", conf.Transitioning).Inc()
			return ctx, nil
		}

		err := gitalyauth.CheckToken(ctx, conf.GetToken(), time.Now())
		switch status.Code(err) {
		case codes.OK:
			countStatus(okLabel(conf.Transitioning), conf.Transitioning).Inc()
		case codes.Unauthenticated:
			countStatus("unauthenticated", conf.Transitioning).Inc()
		case codes.PermissionDenied:
			countStatus("denied", conf.Transitioning).Inc()
		default:
			countStatus("invalid", conf.Transitioning).Inc()
		}

		if conf.Transitioning {
			err = nil
		}

		return ctx, err
	}
}
