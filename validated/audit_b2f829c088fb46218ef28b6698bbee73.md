I have enough evidence to make a determination. The `endpoint` config (e.g., `0.0.0.0:30000` in `sample/conf/signer/mainnet-signer-conf.toml` line 39) confirms the signer's event-receiver HTTP server is intentionally bindable on all interfaces, i.e., remotely reachable, and there is no authentication check on the `/shutdown` path.

### Title
Unauthenticated remote `/shutdown` POST permanently kills the signer's event receiver - (File: libsigner/src/events.rs)

### Summary
`SignerEventReceiver::next_event` treats any POST to `/shutdown` as equivalent to the local-only stop signal sent by `SignerStopSignaler::send`, with no source-address check, no auth token, and no shared secret. Since the signer's event endpoint can be configured to listen on `0.0.0.0` (as shown in the sample config), any remote peer that can reach that TCP port can send the same raw HTTP bytes and permanently stop the signer's event-receiver main loop.

### Finding Description
The broken equality: the code treats "a POST to `/shutdown` arrived on the socket" as equivalent to "the local operator/process authorized a shutdown," but nothing in the request path distinguishes the two. `SignerStopSignaler::send` (the legitimate, intra-process caller) simply opens a `TcpStream` to `self.local_addr` and writes a raw `POST /shutdown HTTP/1.1 ...` request [1](#0-0) . On the receiving side, `next_event` dispatches purely on `request.url()`: `else if request.url() == "/shutdown" { event_receiver.stop_signal.store(true, Ordering::SeqCst); Err(EventError::Terminated) }` [2](#0-1) . There is no check of the request's peer address, no comparison against a shared secret/auth token, and no restriction to loopback — any bytes matching that URL/method flip the same `AtomicBool` used by `main_loop`'s `EventReceiver::main_loop` to decide whether to keep running: `if self.is_stopped() { info!("Event receiver stopped"); break; }` [3](#0-2) . Because the bind address for this HTTP server is fully attacker-configurable at deployment (and the sample config explicitly documents binding it to `0.0.0.0:30000`, i.e., all interfaces) [4](#0-3) , this endpoint is reachable by any remote host that can route to that port, not just the local stacks-node process. Once `stop_signal` is set, `main_loop` exits permanently and there is no re-bind/restart logic shown in `SignerEventReceiver`/`Signer::spawn` [5](#0-4) , so the signer stops receiving all subsequent StackerDB chunks, block proposals, and burn-block events until manually restarted.

### Impact Explanation
A single unauthenticated TCP connection with a crafted `POST /shutdown` body permanently disables a signer's event ingestion, functionally taking that signer offline for block validation/signing duties, a repeatable, one-message, unauthenticated remote DoS against a component reachable per the project's own documented deployment configuration (`endpoint = "0.0.0.0:30000"`). This matches "Critical - remote crash/unauthenticated DoS from few messages."

### Likelihood Explanation
Preconditions: the signer's event-listener port must be reachable from the attacker's network position (the shipped sample config binds it to `0.0.0.0`, i.e., all interfaces, not `127.0.0.1`). No secret, key, or StackerDB slot is needed — a bare `TcpStream` with the exact bytes `SignerStopSignaler::send` uses suffices. Attacker cost is a single TCP connection and no retries are needed since the flag is permanent (sticky) until process restart.

### Recommendation
Gate `/shutdown` handling behind an authentication check (e.g., require the same auth token/shared secret used elsewhere, or restrict the check to `request.remote_addr()` being loopback), or replace the raw HTTP-triggered stop mechanism with an in-process-only signal (e.g., a Unix domain socket, a separate loopback-only control port bound explicitly to `127.0.0.1`, or an internal channel) so remote peers cannot reach it regardless of the configured `endpoint`.

fn test_remote_shutdown_dos() {
    let ev = SignerEventReceiver::new(false);
    let (res_send, _res_recv) = channel();
    let mut signer = Signer::new(SimpleRunLoop::new(1), ev, res_send);
    let endpoint: SocketAddr = "0.0.0.0:31500".parse().unwrap();
    let running_signer = signer.spawn(endpoint).unwrap();

    // simulate an unauthenticated remote peer (no shared secret, no auth header)
    let mut sock = TcpStream::connect(("127.0.0.1", 31500)).unwrap();
    let body = "attacker-controlled shutdown";
    let req = format!(
        "POST /shutdown HTTP/1.1\r\nHost: x\r\nConnection: close\r\nContent-Length: {}\r\n\r\n{}",
        body.len(), body
    );
    sock.write_all(req.as_bytes()).unwrap();

    sleep_ms(500);
    // assert the event receiver's stop_signal (via is_stopped()) is now true,
    // and that a legitimate subsequent /stackerdb_chunks POST is never processed
    // because main_loop has already exited.
}
