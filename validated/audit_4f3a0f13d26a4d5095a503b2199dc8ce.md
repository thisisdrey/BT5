### Title
Per-IP and global QUIC connection rate limiters are bypassed by abandoning handshakes before completion, letting an unstaked attacker occupy the entire handshake-concurrency budget for free - (File: streamer/src/nonblocking/quic.rs)

### Summary
`run_server` only *peeks* the per-IP and global connection token buckets (`ConnectionRateLimiter::is_allowed`, `overall_connection_rate_limiter.current_tokens()`) before spawning a handshake, and only *consumes* tokens (`register_connection`, `consume_tokens`) once a connection successfully completes its QUIC handshake in `setup_connection`. If the attacker aborts the connection before the handshake finishes (it hits `QUIC_CONNECTION_HANDSHAKE_TIMEOUT` or errors out), neither rate limiter is ever decremented, so the accounting never reflects the attempt.

### Finding Description
In `run_server`, incoming connections are gated by two cheap, non-mutating checks before a handshake task is spawned: `overall_connection_rate_limiter.current_tokens() == 0` [1](#0-0)  and `rate_limiter.is_allowed(&incoming.remote_address().ip())` [2](#0-1) . `ConnectionRateLimiter::is_allowed` explicitly does not consume tokens, and for an IP with no prior record it always returns `true` [3](#0-2) .

The only actual token consumption for both the per-IP bucket (`register_connection`) and the global bucket (`overall_connection_rate_limiter.consume_tokens(1)`) happens inside `setup_connection`, and only on the `Ok(new_connection)` branch reached after a completed handshake [4](#0-3) . If the handshake times out (`QUIC_CONNECTION_HANDSHAKE_TIMEOUT = 2s`) or errors, execution instead falls into `handle_connection_error`/the timeout branch, which never calls `register_connection` or `consume_tokens` [5](#0-4) .

Consequently, an attacker who opens a QUIC connection and deliberately never completes the handshake (e.g., sends only an Initial packet and stops responding) never registers against either rate limiter. The only real defenses against this pattern are: (1) `ClientConnectionTracker::new`, which enforces a *global* (not per-IP) `max_concurrent_connections` cap on in-flight handshakes [6](#0-5) , and (2) the fixed 2-second handshake timeout that eventually frees the slot. Since the cap is global, a single unstaked attacker (or a small set of IPs) can occupy the entire `max_concurrent_connections` budget by continuously opening and abandoning connections, forcing every incoming connection (including from other IPs and legitimate stakers) to go through `ClientConnectionTracker::new` failing and being refused (`refused_connections_too_many_open_connections`) [7](#0-6) , while the code comment's stated intent — "cap total connections per-peer/ip" and "rate-limit abusive peers by (control-asserted) ip" — is not actually enforced for this attack pattern [8](#0-7) .

### Impact Explanation
This allows an unprivileged, unstaked, non-spoofing attacker to force repeated TLS/QUIC handshake CPU work and `ClientConnectionTracker` allocation/drop cycles at a rate limited only by the global concurrency cap divided by the 2-second timeout, without ever tripping the per-IP `ConnectionRateLimiter` or the global `overall_connection_rate_limiter`. This matches the scoped impact described: CPU/memory spent on handshake setup/teardown that is not gated by any fee and can starve the global handshake-slot pool used by legitimate (including staked) connections, degrading leader ingress capacity.

### Likelihood Explanation
Preconditions are minimal: only UDP reachability to the TPU QUIC port is required, no stake and no valid TLS completion needed. The attacker only needs to initiate QUIC connection attempts and stop responding before the handshake resolves (well within the 2-second `QUIC_CONNECTION_HANDSHAKE_TIMEOUT` window), which is trivially scriptable and repeatable indefinitely.

### Recommendation
Perform the per-IP and global rate-limit token consumption (or at least a provisional/atomic reservation) at connection-accept time (before spawning the handshake task) rather than only after successful handshake completion, or additionally track and cap outstanding (not-yet-verified) handshake attempts per source IP, not just the global `max_concurrent_connections` counter, so abandoned handshakes from a single IP cannot monopolize the shared concurrency budget.

### Proof of Concept
Integration test plan (extending existing `streamer/src/nonblocking/quic.rs` test harness, e.g. near `test_quic_stream_timeout`):
1. Start `setup_quic_server` with a small `max_concurrent_connections` / `max_unstaked_connections` and default `max_connections_per_ipaddr_per_min`.
2. From a single client IP, repeatedly open QUIC connections via `Endpoint::connect` but never complete the handshake (drop the future or stop responding to handshake packets) at a rate faster than one every `QUIC_CONNECTION_HANDSHAKE_TIMEOUT`.
3. Assert that `stats.connection_rate_limited_per_ipaddr` and `stats.connection_rate_limited_across_all` remain at 0 after many such abandoned attempts (proving the limiters were never engaged), while `stats.connection_setup_timeout` grows unbounded.
4. Concurrently, from a second legitimate IP, attempt a normal connection during the attack window and assert it is refused via `stats.refused_connections_too_many_open_connections` incrementing, demonstrating denial of service to legitimate peers despite the attacker never being rate-limited.

    /// Check the max_concurrent_connections limit and if it is within the limit
    /// create ClientConnectionTracker and increment open connection count. Otherwise returns Err
    fn new(stats: Arc<StreamerStats>, max_concurrent_connections: usize) -> Result<Self, ()> {
        let open_connections = stats.open_connections.fetch_add(1, Ordering::Relaxed);
        if open_connections >= max_concurrent_connections {
            stats.open_connections.fetch_sub(1, Ordering::Relaxed);
            debug!(
                "There are too many concurrent connections opened already: open: \
                 {open_connections}, max: {max_concurrent_connections}"
            );
            return Err(());
        }

        Ok(Self { stats })
    }
}
