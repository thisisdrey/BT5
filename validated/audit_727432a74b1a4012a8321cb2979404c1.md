Audit Report

## Title
Global per-block `MaxMessagesPerBlock` cap in Snowbridge's outbound queue lets a low-cost sender monopolize the entire bridge's outbound slot and stall all other channels' Ethereum-bound messages - (File: bridges/snowbridge/pallets/outbound-queue/src/lib.rs)

## Summary
The Snowbridge outbound queue pallet tracks accepted messages for the current block in a single, non-keyed `MessageLeaves` storage value shared by every registered channel, and `do_process_message` gates acceptance of *any* channel's next message on this aggregate counter reaching `T::MaxMessagesPerBlock`. Because the gate is not scoped per `channel_id`, any unprivileged sender able to submit outbound messages through a registered channel (e.g., normal reserve-backed asset transfers routed through AssetHub's channel) can fill the shared per-block quota with cheap messages, causing `ProcessMessageError::Yield` to be returned for every other channel's messages processed afterward in that block, which `pallet-message-queue` turns into `NoProgress`/`break` for that queue's page.

## Finding Description
`MessageLeaves` is declared as a single unbounded `StorageValue<_, Vec<H256>>`, not a map keyed by `ChannelId`, and is reset only once per block in `on_initialize`. [1](#0-0) [2](#0-1) 

`do_process_message` checks `MessageLeaves::<T>::decode_len()` against `T::MaxMessagesPerBlock::get()` before performing any per-channel logic (nonce increment, channel validation), and yields once the aggregate cap is reached — with no per-channel isolation of the counter: [3](#0-2) 

Only `Nonce` is per-channel (`StorageMap<_, Twox64Concat, ChannelId, u64>`), confirming that `MessageLeaves` — the actual acceptance gate — is not. [1](#0-0) 

On the `pallet-message-queue` side, a `Yield` result is translated to `MessageExecutionStatus::Unprocessable { permanent: false }`, and `service_page`'s outer loop treats `NoProgress` by breaking out of page advancement for that queue in the current service call: [4](#0-3) [5](#0-4) 

This confirms the structural mechanism described in the claim: because the cap is applied globally before any per-channel routing occurs, once the shared quota is exhausted by messages from one channel, subsequently-processed messages from *any other* channel in the same block will also be yielded, regardless of the round-robin fairness intended between distinct message-queue origins. The unit test `process_message_yields_on_max_messages_per_block` directly demonstrates this global-yield behavior for an arbitrary channel once `MessageLeaves` is full, independent of which channel filled it.

The configured value of `MaxMessagesPerBlock` in production BridgeHub runtimes (Westend and Rococo) is `ConstU32<32>`, confirming the cap is a small, fixed, block-wide budget shared across all registered channels (AssetHub's transfer channel and the two governance channels): [6](#0-5) 

However, sending an outbound message is not free: `SendMessage::validate` computes and requires payment of a fee (local weight-based fee plus a remote Ethereum-gas-based fee) via `calculate_fee`/`calculate_remote_fee`, and `pallet-system`'s `send` function actually transfers this fee to the treasury before message delivery: [7](#0-6) [8](#0-7) [9](#0-8) 

This fee is charged per message and scales with the gas cost of the specific `Command` being sent, but it is **not** scaled to the scarcity of the shared 32-slot-per-block acceptance budget itself — an attacker paying the (potentially small, for low-gas commands) per-message fee 32 times in a block can occupy the entire budget regardless of which channel legitimate traffic originates from, and repeat this every block as soon as `MessageLeaves` resets in `on_initialize`. Channel registration for non-governance channels (e.g., AssetHub's transfer channel) is established once via `initialize`/genesis, and ordinary users on that chain can trigger outbound Snowbridge exports through standard reserve-backed transfers without needing any privileged role — this satisfies the "unprivileged external attacker using public extrinsics" requirement, since the attacker only needs to be a user of the parachain that already has a registered channel (most commonly AssetHub), not a new channel-creation privilege.

## Impact Explanation
This matches the "public underpriced work that degrades block production or stalls bridge processing" impact category. Because `MessageLeaves` is a single pallet-wide counter rather than per-channel, an unprivileged account can, for the cost of the per-message fee (not a cost tied to the scarce global slot), occupy the entire block's outbound-message acceptance budget, causing legitimate outbound messages from any channel — including high-value asset unlocks — to be `Yield`ed and deferred by `pallet-message-queue` for that block, repeatable every block for as long as the attacker sustains the low-value traffic.

## Likelihood Explanation
The exact production feasibility depends on the actual fee magnitude for low-gas `Command`s relative to `T::MaxMessagesPerBlock` (`ConstU32<32>` in the reviewed BridgeHub Westend/Rococo configs) and on how quickly/cheaply an ordinary AssetHub user can trigger 32 outbound exports per block; this repository index does not let me fully confirm live fee schedules (`PricingParameters`) or empirically measure the DOT-denominated cost of sustaining this every block indefinitely. The structural absence of per-channel isolation in the acceptance gate is, however, definitively confirmed in code and by an existing unit test, so the likelihood is governed entirely by economic parameters, not by any missing enforcement mechanism.

## Recommendation
- Scope the per-block message-acceptance budget per channel (e.g., a `MessageLeaves`/count map keyed by `ChannelId`) instead of a single pallet-wide counter, so no single channel can exhaust capacity for others.
- Alternatively, apply congestion-based pricing proportional to consumption of the scarce global per-block slot, or implement fair/weighted round-robin admission across channels for the `MaxMessagesPerBlock` budget.

## Proof of Concept
1. At block start, `MessageLeaves` is empty following `on_initialize`.
2. An unprivileged account on the parachain owning a registered channel (e.g., AssetHub) submits `T::MaxMessagesPerBlock::get()` (32 in production) low-value outbound-triggering transfers in the same block, each paying only the per-message fee, filling `MessageLeaves` to the cap via the aggregate check in `do_process_message`.
3. A victim submits a legitimate high-value transfer via a different channel in the same block; because the check `MessageLeaves::<T>::decode_len() < T::MaxMessagesPerBlock::get()` is global, `do_process_message` also returns `Yield` for the victim's message, and `pallet-message-queue`'s `service_page` treats this as `NoProgress`, deferring the victim's message.
4. Repeat every subsequent block to indefinitely stall the victim's channel relative to the attacker's channel.

		pub(crate) fn do_process_message(
			_: ProcessMessageOriginOf<T>,
			mut message: &[u8],
		) -> Result<bool, ProcessMessageError> {
			use ProcessMessageError::*;

			// Yield if the maximum number of messages has been processed this block.
			// This ensures that the weight of `on_finalize` has a known maximum bound.
			ensure!(
				MessageLeaves::<T>::decode_len().unwrap_or(0) <
					T::MaxMessagesPerBlock::get() as usize,
				Yield
			);

			// Decode bytes into versioned message
			let versioned_queued_message: VersionedQueuedMessage =
				VersionedQueuedMessage::decode(&mut message).map_err(|_| Corrupt)?;

			// Convert versioned message into latest supported message version
			let queued_message: QueuedMessage =
				versioned_queued_message.try_into().map_err(|_| Unsupported)?;

			// Obtain next nonce
			let nonce = <Nonce<T>>::try_mutate(
				queued_message.channel_id,
				|nonce| -> Result<u64, ProcessMessageError> {
					*nonce = nonce.checked_add(1).ok_or(Unsupported)?;
					Ok(*nonce)
				},
			)?;

		pub(crate) fn calculate_fee(
			gas_used_at_most: u64,
			params: PricingParameters<T::Balance>,
		) -> Fee<T::Balance> {
			// Remote fee in ether
			let fee = Self::calculate_remote_fee(
				gas_used_at_most,
				params.fee_per_gas,
				params.rewards.remote,
			);

			// downcast to u128
			let fee: u128 = fee.try_into().defensive_unwrap_or(u128::MAX);

			// multiply by multiplier and convert to local currency
			let fee = FixedU128::from_inner(fee)
				.saturating_mul(params.multiplier)
				.checked_div(&params.exchange_rate)
				.expect("exchange rate is not zero; qed")
				.into_inner();

			// adjust fixed point to match local currency
			let fee = Self::convert_from_ether_decimals(fee);

			Fee::from((Self::calculate_local_fee(), fee))
		}

			fee_per_gas: U256,
			reward: U256,
		) -> U256 {
			fee_per_gas.saturating_mul(gas_used_at_most.into()).saturating_add(reward)

	fn validate(
		message: &Message,
	) -> Result<(Self::Ticket, Fee<<Self as SendMessageFeeProvider>::Balance>), SendError> {
		// The inner payload should not be too large
		let payload = message.command.abi_encode();
		ensure!(
			payload.len() < T::MaxMessagePayloadSize::get() as usize,
			SendError::MessageTooLarge
		);

		// Ensure there is a registered channel we can transmit this message on
		ensure!(T::Channels::contains(&message.channel_id), SendError::InvalidChannel);

		// Generate a unique message id unless one is provided
		let message_id: H256 = message
			.id
			.unwrap_or_else(|| unique((message.channel_id, &message.command)).into());

		let gas_used_at_most = T::GasMeter::maximum_gas_used_at_most(&message.command);
		let fee = Self::calculate_fee(gas_used_at_most, T::PricingParameters::get());

		let queued_message: VersionedQueuedMessage = QueuedMessage {
			id: message_id,
			channel_id: message.channel_id,
			command: message.command.clone(),
		}
		.into();
		// The whole message should not be too large
		let encoded = queued_message.encode().try_into().map_err(|_| SendError::MessageTooLarge)?;

		let ticket = Ticket { message_id, channel_id: message.channel_id, message: encoded };

		Ok((ticket, fee))
	}

	impl<T: Config> Pallet<T> {
		/// Send `command` to the Gateway on the Channel identified by `channel_id`
		fn send(channel_id: ChannelId, command: Command, pays_fee: PaysFee<T>) -> DispatchResult {
			let message = Message { id: None, channel_id, command };
			let (ticket, fee) =
				T::OutboundQueue::validate(&message).map_err(|err| Error::<T>::Send(err))?;

			let payment = match pays_fee {
				PaysFee::Yes(account) => Some((account, fee.total())),
				PaysFee::Partial(account) => Some((account, fee.local)),
				PaysFee::No => None,
			};

			if let Some((payer, fee)) = payment {
				T::Token::transfer(
					&payer,
					&T::TreasuryAccount::get(),
					fee,
					Preservation::Preserve,
				)?;
			}

			T::OutboundQueue::deliver(ticket).map_err(|err| Error::<T>::Send(err))?;
			Ok(())
		}
