### Title
Atlas attachment downloader stores fetched attachment content without verifying it matches the requested `content_hash` - (File: stackslib/src/net/atlas/download.rs)

### Summary
The Atlas attachment-sync pipeline requests attachment content from peers keyed by a specific `content_hash` (`AttachmentRequest.content_hash`), but when the HTTP response comes back, `AttachmentsBatchStateContext::extend_with_attachments` inserts the decoded `Attachment` into `self.attachments` without ever comparing `response.attachment.hash()` to the `content_hash` that was actually requested. The unverified attachment is later unconditionally persisted into `AtlasDB` via `insert_instantiated_attachment`.

### Finding Description
`AttachmentsBatchStateContext::get_prioritized_attachments_requests` builds an `AttachmentRequest` carrying a specific `content_hash` derived from on-chain attachment instances [1](#0-0) . Requests are dispatched and polled by `BatchedRequestsState::try_proceed`, which simply records any HTTP 200 response as `succeeded` without inspecting its content against the request that produced it [2](#0-1) .

When results are folded back into the context, `extend_with_attachments` decodes the response body and inserts the resulting `Attachment` object straight into a `HashSet<Attachment>` — with no check that `response.attachment.hash() == request.content_hash`: [3](#0-2) 

Once the batch state machine reaches `Done`, every attachment in that set is unconditionally written to disk via `AtlasDB::insert_instantiated_attachment`, regardless of whether any tracked `AttachmentInstance` hash actually matches it: [4](#0-3) 

`insert_instantiated_attachment` performs an unconditional `INSERT OR REPLACE` keyed by the attachment's own recomputed hash, with no cap analogous to `max_uninstantiated_attachments` (that cap only applies to the separate "uninstantiated" pool used by `insert_uninstantiated_attachment`) [5](#0-4) [6](#0-5) .

This breaks the "authenticated vs. stored" equality expected of a content-addressed store: the design intends for a fetched blob to be validated against the `content_hash` that a peer is being asked for before being persisted as `was_instantiated = 1` state. Instead, any node advertising itself as an Atlas peer and responding to a `GetAttachment` request can supply arbitrary bytes (up to `attachments_max_size`) and have the node commit them permanently to its `AtlasDB`, uncapped by any eviction/quota mechanism that governs the "uninstantiated" side of the store.

### Impact Explanation
A remote, unprivileged peer participating in Atlas sync can cause a Stacks node to durably persist attacker-chosen data into its local `AtlasDB` (`attachments` table, `was_instantiated=1` rows) whenever the node requests any legitimate attachment from it. Because the stored hash is self-consistent (recomputed from the attacker's own bytes) it will simply not match the instance the node originally wanted, so the intended attachment resolution silently fails while the garbage data accumulates without any of the cleanup/eviction limits that protect the "uninstantiated" side of the table. This is an unauthenticated write of attacker-controlled data into node state (bounded per-request by `attachments_max_size`, and in aggregate by however many attachment requests the node issues to that peer), which matches the "unauthenticated/unauthorized write to state" impact class.

### Likelihood Explanation
Likelihood is moderate: exploitation requires that the node has selected the attacker as one of its Atlas "outbound sync peers" and issues at least one `AttachmentRequest` to it (which happens routinely during ordinary BNS/attachment sync when following normal blocks with `attachments-count > 0`). No special privileges, keys, or timing precision are needed — the attacker only needs to answer HTTP GET `/v2/attachments/<hash>`-style requests with a 200 and arbitrary octet-stream content that decodes as an `Attachment`.

### Recommendation
In `AttachmentsBatchStateContext::extend_with_attachments`, verify `response.attachment.hash() == request.content_hash` before inserting into `self.attachments`; treat a mismatch the same as a failed request (`report.bump_failed_requests()` and do not store). Additionally, consider applying a quota/eviction policy to `insert_instantiated_attachment` similar to `max_uninstantiated_attachments`, so that even validated-but-unresolved growth of the "attachments" table remains bounded.

### Proof of Concept
1. Stand up a malicious HTTP peer that the target node includes in `get_outbound_sync_peers()` / Atlas hint replicas.
2. Wait for (or trigger) the target node to enqueue an `AttachmentRequest` for some legitimate `content_hash` `H` (e.g. by processing a block containing a BNS/Atlas attachment commitment).
3. When the target's `AttachmentsInventoryRequest`/`AttachmentRequest` for `H` arrives, respond with HTTP 200 and an `application/octet-stream` (or the Atlas response encoding expected by `decode_atlas_get_attachment`) body containing arbitrary bytes `B` (`hash(B) != H`, size ≤ `attachments_max_size`).
4. Observe that `extend_with_attachments` accepts the response and inserts `Attachment{content: B}` into `context.attachments` without any hash check.
5. On the next `Done` transition, `AttachmentsDownloader::run` calls `atlasdb.insert_instantiated_attachment(&Attachment{content: B})`, persisting `B` into the `attachments` SQLite table keyed by `hash(B)`, even though no `AttachmentInstance` ever referenced `hash(B)`.
6. Repeat for each attachment request the target issues to the malicious peer to grow the `attachments` table with attacker-controlled data that is never subject to the uninstantiated-attachment eviction/cap logic.

Note: I was not able to fully inspect `decode_atlas_get_attachment`'s exact wire format (in `stackslib/src/net/api/getattachment.rs`) within the available iterations to confirm whether any additional implicit validation exists at the HTTP-decode layer; based on the code reviewed, no `content_hash` comparison occurs anywhere in the `download.rs` pipeline, which is the authoritative point where trust decisions for Atlas content are made.

    pub fn get_prioritized_attachments_requests(&self) -> BinaryHeap<AttachmentRequest> {
        let mut queue = BinaryHeap::new();
        let mut enqueued = HashSet::new();
        for ((contract_id, pages, _), peers_responses) in self.inventories.iter() {
            let missing_attachments = match self
                .attachments_batch
                .attachments_instances
                .get(contract_id)
            {
                None => continue,
                Some(missing_attachments) => missing_attachments,
            };
            // Note: we're getting missing_attachments (attachment_id: content_hash)
            for (attachment_index, content_hash) in missing_attachments.iter() {
                let page_index = attachment_index / AttachmentInstance::ATTACHMENTS_INV_PAGE_SIZE;
                // Since there's a limit in the number of pages that a node can request,
                // we can potentially have multiple inventory request at once.
                if !pages.contains(&page_index) {
                    continue;
                }

                if enqueued.contains(content_hash) {
                    debug!("Atlas: {} already enqueued", content_hash);
                    continue;
                }

                let mut sources = HashMap::new();
                let position_in_page =
                    attachment_index % AttachmentInstance::ATTACHMENTS_INV_PAGE_SIZE;

                for (peer_url, response) in peers_responses.iter() {
                    // Considering the response, look for the page with the index
                    // we're looking for.
                    let search_page = response.pages.iter().find(|page| page.index == page_index);

                    let has_attachment = search_page
                        .and_then(|search_page| {
                            search_page.inventory.get(position_in_page as usize)
                        })
                        .map(|result| *result == 1)
                        .unwrap_or(false);

                    if !has_attachment {
                        debug!(
                            "Atlas: peer does not have attachment ({}, {}) in its inventory {:?}",
                            page_index, position_in_page, response.pages
                        );
                        continue;
                    }

                    let report = self
                        .peers
                        .get(peer_url)
                        .expect("Atlas: unable to retrieve reliability report for peer");
                    sources.insert(peer_url.clone(), report.clone());
                }

                if sources.is_empty() {
                    warn!("Atlas: could not find a peer including attachment in its inventory");
                    continue;
                }

                // Success, we found at least one inventory including the attachment we're looking for.
                let request = AttachmentRequest {
                    sources,
                    content_hash: content_hash.clone(),
                    stacks_block_height: self.attachments_batch.stacks_block_height,
                    canonical_stacks_tip_height: self.attachments_batch.canonical_stacks_tip_height,
                };
                enqueued.insert(content_hash);
                queue.push(request);
            }
        }
        queue
    }

    pub fn extend_with_attachments(
        mut self,
        results: &mut BatchedRequestsResult<AttachmentRequest>,
    ) -> AttachmentsBatchStateContext {
        for (request, response) in results.succeeded.drain() {
            let report = self
                .peers
                .get_mut(request.get_url())
                .expect("Atlas: unable to retrieve reliability report for peer");

            let response = if let Some(r) = response {
                r
            } else {
                report.bump_failed_requests();
                continue;
            };

            if let Ok(response) = response.decode_atlas_get_attachment() {
                self.attachments.insert(response.attachment);
                report.bump_successful_requests();
            } else {
                report.bump_failed_requests();
            }
        }
        let mut events_ids = results.faulty_peers.keys().copied().collect::<Vec<usize>>();
        self.events_to_deregister.append(&mut events_ids);

        self
    }

    pub fn insert_uninstantiated_attachment(
        &mut self,
        attachment: &Attachment,
    ) -> Result<(), db_error> {
        // Insert the new attachment
        let uninstantiated_attachments = self.count_uninstantiated_attachments()?;
        if uninstantiated_attachments >= self.atlas_config.max_uninstantiated_attachments {
            let to_delete =
                1 + uninstantiated_attachments - self.atlas_config.max_uninstantiated_attachments;
            self.evict_k_oldest_uninstantiated_attachments(to_delete)?;
        }

        let tx = self.tx_begin()?;
        let now = util::get_epoch_time_secs() as i64;
        let res = tx.execute(
            "INSERT OR REPLACE INTO attachments (hash, content, was_instantiated, created_at) VALUES (?, ?, 0, ?)",
            params![
                attachment.hash(),
                attachment.content,
                now,
            ],
        );
        res.map_err(db_error::SqliteError)?;
        tx.commit().map_err(db_error::SqliteError)?;
        Ok(())
    }

    pub fn insert_instantiated_attachment(
        &mut self,
        attachment: &Attachment,
    ) -> Result<(), db_error> {
        let now = util::get_epoch_time_secs() as i64;
        let tx = self.tx_begin()?;
        tx.execute(
            "INSERT OR REPLACE INTO attachments (hash, content, was_instantiated, created_at) VALUES (?, ?, 1, ?)",
            params![attachment.hash(), attachment.content, now],
        )?;
        tx.execute(
            "UPDATE attachment_instances SET is_available = 1 WHERE content_hash = ?1 AND status = ?2",
            params![attachment.hash(), AttachmentInstanceStatus::Checked],
        )?;
        tx.commit()?;
        Ok(())
    }
