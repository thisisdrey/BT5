### Title
`Pool.swap` has no slippage/deadline protection, enabling sandwiching of oracle price updates to mint underpriced synthetic tokens - ([File: contracts/Pool.sol])

### Summary
`Pool.swap` burns one synthetic token and mints another at a price taken entirely from `masterOracle().quote()`, with no user-supplied `amountOutMin` or deadline. An unprivileged attacker who observes a pending oracle price-update transaction can front-run it by swapping into the asset about to appreciate at the stale price and swap back after the update executes, extracting unbacked synthetic supply each round.

### Finding Description
In `Pool.swap` (contracts/Pool.sol:642-671), the exchange rate is computed purely on-chain at execution time:

```solidity
syntheticTokenIn_.burn(_msgSender, amountIn_);
(_amountOut, _fee) = quoteSwapOut(syntheticTokenIn_, syntheticTokenOut_, amountIn_);
if (_fee > 0) { syntheticTokenOut_.mint(_poolRegistry.feeCollector(), _fee); }
syntheticTokenOut_.mint(_msgSender, _amountOut);
```

`quoteSwapOut` (lines 508-525) calls `_poolRegistry.masterOracle().quote(...)` and deducts `feeProvider.swapFees(...)`. There is no `amountOutMin`, no deadline, and no staleness comparison — the swap always executes at whatever price the oracle reports in that exact block.

This mirrors the incident class: the attacker exploits knowledge of a transaction's *future effect* (here, the oracle update) before it lands. Because each swap is an atomic repricing at oracle value with zero market impact, ordering around the update is pure profit:

1. Attacker holds `msUSD` (obtained by depositing collateral and `DebtToken.issue`, or bought on market).
2. Oracle operator submits an update raising `msETH`'s USD price.
3. Front-run: `pool.swap(msUSD, msETH, amountIn)` converts USD→ETH at the old, lower ETH price.
4. Update executes.
5. Back-run: `pool.swap(msETH, msUSD, amountOut)` converts back at the new, higher ETH price, netting `amountIn * (priceNew/priceOld - 1) - fees` of freshly minted `msUSD`.

No modifier blocks this: `swap` is callable by any EOA or via `Operator.execute`, `whenNotShutdown`/`nonReentrant` don't restrict ordering, and `onlyIfSyntheticTokenExists`/`isSwapActive` are satisfied on the deployed mainnet `Pool` (swap is a supported feature, gated only by the `isSwapActive` flag which the deployment uses). Supply caps on `DebtToken`/`SyntheticToken` maxTotalSupply only bound per-token supply, not value extraction, since `msUSD` minted is fully fungible debt-backed claims.

### Impact Explanation
Each round-trip mints synthetic tokens whose oracle value exceeds what was burned, i.e., the protocol emits unbacked supply equal to the price delta. The attacker can then swap the profit into other synths or repay external debt. This dilutes the collateral backing of all synthetic token holders — protocol insolvency / direct extraction of value proportional to the oracle price move and the attacker's capital, repeatable on every price update. Flash-funded capital via `DebtToken.flashIssue` or external flash loans can bootstrap the `msUSD`/`msETH` inventory around the update block.

### Likelihood Explanation
Oracle updates are on-chain transactions visible in the public mempool on every deployment (mainnet, Optimism, Base, etc.), and price moves occur continuously. Execution requires only an EOA calling `Pool.swap` twice around a known pending update — no privileged role, no oracle manipulation (the oracle data itself is correct; only ordering is exploited). Profitability requires the per-update price delta to exceed round-trip `swapFees`; for pairs with zero/low configured `defaultSwapFee` or during volatile repricing, this is routinely satisfied.

### Recommendation
Add a `minAmountOut` (and optionally `deadline`) parameter to `Pool.swap`, revert if `_amountOut < minAmountOut`. Additionally or alternatively, impose a per-block/epoch limit on minted swap volume, or a small mandatory swap fee so that small oracle deltas are unprofitable. Optionally check oracle freshness relative to a user-committed block.

### Proof of Concept
Foundry fork sketch (mainnet), assuming swap active and low/zero fee on the pair:

```solidity
function test_oracleUpdateSandwich() public {
    // attacker holds msUSD from collateralized issue()
    uint256 amountIn = 1_000_000e18;
    deal(address(msUSD), attacker, amountIn);

    uint256 before_ = msUSD.balanceOf(attacker);

    // FRONT-RUN the pending oracle update: buy msETH at stale price
    vm.prank(attacker);
    pool.swap(msETH /*in*/ , msUSD /*out*/, ...); // placeholder ordering
    // concretely:
    vm.prank(attacker);
    pool.swap(msUSD, msETH, amountIn); // priced at old ETH price via masterOracle().quote

    // pending oracle update lands (impersonate oracle feed update tx)
    vm.prank(oracleUpdater);
    chainlinkEthFeed.updateAnswer(newHigherPrice); // or masterOracle push

    // BACK-RUN: sell msETH back at the new price
    uint256 msEthBal = msETH.balanceOf(attacker);
    vm.prank(attacker);
    pool.swap(msETH, msUSD, msEthBal);

    uint256 after_ = msUSD.balanceOf(attacker);
    assertGt(after_, before_); // unbacked msUSD minted, profit > 0 after fees
}
```

Invariant broken: swap conservation — total USD value of minted synths across the pair of swaps exceeds value burned, with the difference created ex nihilo against pool collateral.
