### Title
Unbounded response size/time in ListLFSPointers/ListAllLFSPointers when Limit=0 - ([File: internal/gitaly/service/blob/lfs_pointers.go])

### Summary
`sendLFSPointers` only enforces the client-supplied `limit`, and treats `limit == 0` as "no cap" via `if limit > 0 && i >= limit { break }`. An unprivileged repository owner can push an unbounded number of small (≤200 byte) LFS-pointer-shaped blobs and then call `ListAllLFSPointers`/`ListLFSPointers` with `Limit: 0`, forcing the server to walk the entire object store (`gitpipe.CatfileInfoAllObjects` for the "All" variant, or a full revlist graph walk for `ListLFSPointers`) and stream every matching pointer back with no server-side ceiling.

### Finding Description
In `ListAllLFSPointers` (internal/gitaly/service/blob/lfs_pointers.go:80-123) the handler builds a `gitpipe.CatfileInfoAllObjects` pipeline over the whole repository, filtering only by object type/size (≤`lfsPointerMaxSize`, 200 bytes), and hands the result to `sendLFSPointers(chunker, catfileObjectIter, int(in.GetLimit()))`. Similarly, `ListLFSPointers` (lines 28-76) does a `gitpipe.Revlist` graph walk with the same blob-size filter. Both funnel into the shared `sendLFSPointers` (lines 212-263), whose only stopping condition besides iterator exhaustion is: [1](#0-0) 
Because `limit > 0` is required to trigger the break, a client-supplied `Limit: 0` (the protobuf default, requiring no special field-setting) disables the cutoff entirely. Nothing else in the two RPC handlers imposes an independent server-side cap — `ValidateRepository`/`ValidateRevision` checks only validate repository identity and revision syntax, not response cardinality. Since a valid LFS pointer text blob is tiny (well under 200 bytes) while an LFS object it references can be large, an attacker who owns/forks a repo can cheaply create millions of such blobs (e.g., via commits containing many pointer-shaped file blobs) and then invoke the RPC with the default limit, forcing Gitaly to perform a full `--batch-all-objects`-style walk (or revlist walk) and stream a correspondingly large, effectively unbounded gRPC response.

### Impact Explanation
This causes sustained CPU consumption (object enumeration, `cat-file` info/content reads for every candidate blob) and outbound bandwidth (streamed LFSPointer messages) proportional to attacker-controlled repository content, with no proportional cost or cap imposed by the Gitaly RPC itself. On a shared Gitaly host this can starve other tenants sharing the same storage/process (resource exhaustion / DoS of the RPC handler and, at scale, the host), matching a "Denial of Service" impact class.

### Likelihood Explanation
Preconditions are minimal: the attacker only needs the ability to push arbitrary blob content to a repository they own (a baseline capability for any GitLab user) and to invoke `ListAllLFSPointers`/`ListLFSPointers` with the default `Limit` (0). No admin/operator privileges, no non-default configuration, and no external cooperation are required, making this readily repeatable and cheap to scale (pointer blobs are far smaller than the LFS objects they nominally reference).

### Recommendation
Enforce a server-side maximum bound on the number of pointers (and/or objects scanned) independent of the client-supplied `Limit`, e.g., clamp `limit` to a configured maximum when it is `0` or exceeds that maximum, or make the underlying `CatfileInfoAllObjects`/`Revlist` walk itself abortable once the maximum is reached rather than relying solely on client input. Consider also bounding total scanned-object count/time, not just emitted-pointer count, since the cost driver is the full object-store walk itself.

func TestListAllLFSPointers_UnboundedWithZeroLimit(t *testing.T) {
    cfg, repoProto, repoPath := setupRepositoryService(t)
    repo := localrepo.NewTestRepo(t, cfg, repoProto)

    // Attacker-controlled: push N small valid LFS pointer blobs (each < 200 bytes).
    const n = 1_000_000 // scale up to demonstrate unbounded growth
    for i := 0; i < n; i++ {
        pointerContent := fmt.Sprintf("version https://git-lfs.github.com/spec/v1\noid sha256:%064d\nsize 12345\n", i)
        gittest.WriteBlob(t, cfg, repoPath, []byte(pointerContent))
    }
    // ... commit these blobs so they're reachable/present in the object store ...

    client, ctx := setupBlobServiceClient(t, cfg)
    start := time.Now()
    stream, err := client.ListAllLFSPointers(ctx, &gitalypb.ListAllLFSPointersRequest{
        Repository: repoProto,
        Limit:      0, // default value; no server-side cap applied
    })
    require.NoError(t, err)

    var total int
    for {
        resp, err := stream.Recv()
        if err == io.EOF {
            break
        }
        require.NoError(t, err)
        total += len(resp.GetLfsPointers())
    }
    t.Logf("received %d pointers in %s", total, time.Since(start))
    // Assertion: wall-clock/response size scales linearly with N with no server enforced cap,
    // demonstrating the RPC is unbounded regardless of repository size chosen by the owner.
}

func sendLFSPointers(chunker *chunk.Chunker, iter gitpipe.CatfileObjectIterator, limit int) error {
	buffer := bytes.NewBuffer(make([]byte, 0, lfsPointerMaxSize))

	var i int
	for iter.Next() {
		lfsPointer := iter.Result()

		// Avoid allocating bytes for an LFS pointer until we know the current blob really
		// is an LFS pointer.
		buffer.Reset()

		// Given that we filter pipeline objects by size, the biggest object we may see here
		// is 200 bytes in size. So it's not much of a problem to read this into memory
		// completely.
		if _, err := io.Copy(buffer, lfsPointer); err != nil {
			return structerr.NewInternal("reading LFS pointer data: %w", err)
		}

		pointer, fileOid, fileSize := git.IsLFSPointer(buffer.Bytes())
		if !pointer {
			continue
		}

		objectData := make([]byte, buffer.Len())
		copy(objectData, buffer.Bytes())

		if err := chunker.Send(&gitalypb.LFSPointer{
			Data:     objectData,
			Size:     int64(len(objectData)),
			Oid:      lfsPointer.ObjectID().String(),
			FileOid:  fileOid,
			FileSize: fileSize,
		}); err != nil {
			return structerr.NewInternal("sending LFS pointer chunk: %w", err)
		}

		i++
		if limit > 0 && i >= limit {
			break
		}
	}
