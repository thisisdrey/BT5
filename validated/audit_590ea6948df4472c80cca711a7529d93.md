### Title
`Pool.swap` lacks slippage protection — oracle-priced mint output can shift arbitrarily while the transaction is pending - (File: contracts/Pool.sol)

### Summary
`Pool.swap` burns a user's synthetic token and mints a different synthetic token, where the output amount is determined entirely by `masterOracle().quote()` at execution time. The function accepts no `minAmountOut`/slippage parameter, so a user cannot bound the amount they receive. If the oracle price moves (or is updated via a pull-oracle price update) between transaction submission and execution, the user receives fewer tokens than quoted, with no way to revert.

### Finding Description
`Pool.swap` (contracts/Pool.sol:642-671) takes only `syntheticTokenIn_`, `syntheticTokenOut_`, and `amountIn_`. It burns `amountIn_` of the input synth, then calls `quoteSwapOut` (contracts/Pool.sol:508-525), which computes `_amountOut = masterOracle().quote(syntheticTokenIn_, syntheticTokenOut_, amountIn_)` minus the swap fee, and mints the result to the caller. There is no caller-supplied bound on `_amountOut`, and no comparison against any expected rate.

The `MasterOracle` in production is backed by a pull oracle (Pyth), whose price feeds are permissionlessly updatable on-chain by anyone submitting fresh signed prices (`pyth.updatePriceFeeds`, see test/E2E.mainnet.test.ts:1056-1058). This means the effective swap rate can be changed by any EOA in the same block as the victim's transaction, or between mempool submission and inclusion — exactly the condition the bug class describes.

### Impact Explanation
A victim's swap executes at an oracle rate different from the one quoted at submission time. Because `swap` burns first and mints afterward at whatever the oracle returns, the victim absorbs 100% of adverse price movement. Additionally, the swap mints `syntheticTokenOut_` against the same collateral base as all other synths — when the rate is skewed in an attacker's favor (burn cheap synth, mint over-valued synth), value is extracted from other synth holders, diluting backing. Impact: direct loss of user funds and potential protocol insolvency via unbacked synthetic issuance.

### Likelihood Explanation
Any unprivileged user can trigger it: `swap` is `external`, gated only by `whenNotShutdown`, `nonReentrant`, `onlyIfSyntheticTokenExists`, `isSwapActive`, and a balance check — none of which constrain the output amount. With a pull oracle as `defaultOracle`, an attacker can sandwich a pending victim swap between a price update and a counter-swap of their own, or simply exploit natural feed updates. Even absent malicious intent, users have no recourse when the oracle updates mid-flight.

### Recommendation
Add a `minAmountOut_` (and optionally a `maxAmountIn_`-style overload using `quoteSwapIn`) parameter to `Pool.swap` and `IPool.swap`, reverting if the computed `_amountOut` is below the caller's bound — the same `minShares`/`minOut` pattern commonly implemented in staking/minting contracts, and already used for `leverage`/`flashRepay` slippage checks in `SmartFarmingManager`.

### Proof of Concept
Hardhat/fork sketch (existing `test/E2E.mainnet.test.ts` fixture provides pool, `msUSD`, `msETH`, `masterOracle`, and Pyth update path):

```ts
// victim alice holds msUSD and submits:
const txPromise = pool.connect(alice).swap(msUSD.address, msETH.address, aliceMsUsdBalance)

// before inclusion, attacker updates Pyth feeds so masterOracle.quote(msUSD->msETH)
// returns a worse rate (or in mock terms: masterOracle.updatePrice(msETH, higherPrice))
await pyth.updatePriceFeeds(attackerSubmittedPriceUpdate, {value: fee})

// victim's tx now executes at the new rate: burns identical amountIn,
// mints strictly less msETH than quoteSwapOut showed at signing time
const {_amountOut} = await pool.quoteSwapOut(msUSD.address, msETH.address, aliceMsUsdBalance)
// _amountOut < amountQuotedBeforeUpdate, and swap() cannot revert on the difference
```

Concrete reproduction: in `test/Pool.test.ts` fixture, call `quoteSwapOut`, then `masterOracle.updatePrice(msDoge.address, higherPrice)` (or lower `msEth` price) between quote and `pool.swap(...)` — the swap succeeds and mints less than the pre-submission quote, demonstrating the absent slippage bound.
