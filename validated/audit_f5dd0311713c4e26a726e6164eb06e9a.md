### Title
`do_native_withdraw` has no resolve/refund callback so a failed final `transfer` leaves signer's wNEAR permanently debited with no NEAR delivered - ([File: contracts/defuse/src/contract/tokens/nep141/native.rs])

### Summary
`native_withdraw` debits the signer's internal wNEAR balance synchronously, then chains `near_withdraw().then(do_native_withdraw(withdraw)).detach()`. `do_native_withdraw` only checks that `near_withdraw` (the wNEAR unwrap) succeeded via `promise_result_checked_void(0)`, then issues `Promise::new(receiver_id).transfer(amount)` as a bare, uncallbacked, detached promise. Unlike `ft_withdraw`/`nft_withdraw`/`mt_withdraw`, which all attach a `*_resolve_withdraw` callback that inspects the transfer outcome and refunds the internal ledger on failure, `native_withdraw` has no such resolve step at all.

### Finding Description
Binding claimed: `internal_sub_balance(signer, wNEAR, amount)` (executed synchronously in `native_withdraw`, [1](#0-0) ) `==` `NEAR actually delivered to receiver_id via the final transfer`.

Code path:
- `native_withdraw` calls `self.withdraw(...)` which subtracts the wNEAR balance from the signer's ledger unconditionally and before any promise executes [1](#0-0) .
- It then schedules `near_withdraw(...).then(do_native_withdraw(withdraw)).detach()` — note the `.detach()` at the very end, meaning nothing downstream of `do_native_withdraw` is ever inspected by the contract [2](#0-1) .
- `do_native_withdraw` only validates that `near_withdraw` succeeded (`promise_result_checked_void(0)`), then returns `Promise::new(withdraw.receiver_id).transfer(withdraw.amount)` as the final action — no `.then()` is attached to this promise [3](#0-2) .
- Contrast with `ft_withdraw`, which attaches `ft_resolve_withdraw` after `do_ft_withdraw`, explicitly checking the transfer result and calling `self.deposit(...)` to refund on failure [4](#0-3) [5](#0-4) . `nft_withdraw`/`mt_withdraw` follow the same resolve pattern [6](#0-5) [7](#0-6) . `native_withdraw` has no equivalent.

Root cause: a plain NEAR `transfer` action (as opposed to `ft_transfer`) sent to a `receiver_id` that requires additional balance to be created/maintained (e.g., a named account that does not yet exist and whose required registration/storage cost exceeds the transferred amount) fails at the receipt level; the funds are refunded back to the *sending contract's own account balance*, not to the signer's internal ledger. Because `do_native_withdraw`'s returned promise is never followed by a `.then()` callback, and the whole chain is `.detach()`ed, the Defuse contract has no mechanism to detect this failure or credit the signer back — the signer's internal wNEAR balance remains at zero (already subtracted) while the NEAR is retained by the contract account outside of any accounted-for holder in the internal ledger.

Attacker/user flow: any signer submits a signed `NativeWithdraw { receiver_id, amount }` intent via `execute_intents` where `receiver_id` is a syntactically valid `AccountId` that does not exist and requires more balance for account creation/registration than what a bare `transfer` action provides. The intent executes, `do_native_withdraw` succeeds (the outer promise chain reports success because only the `near_withdraw` step is checked), the signer's wNEAR is burned, but the receiver never gets credited and the signer has no recorded balance to claim a refund from.

Existing guards do not catch this: `promise_result_checked_void(0)` in `do_native_withdraw` only verifies the *first* promise result (`near_withdraw`), not the final `transfer`'s outcome, and there is no index-1 check because there is no follow-up callback at all.

### Impact Explanation
This causes the signer's funds (wNEAR balance, already burned to real NEAR held by the contract) to become permanently unrecoverable from the perspective of the Defuse Verifier's internal accounting: the internal ledger shows the signer's balance debited, no refund path exists, and the NEAR itself sits in the contract's un-tracked native balance rather than being credited back to anyone. This matches the Critical category "user funds permanently frozen" since the signer loses access to funds with no possible recovery through the protocol, and it's repeatable for any signer/attacker for every choice of a failing `receiver_id`.

### Likelihood Explanation
This requires only signing a `NativeWithdraw` intent with a `receiver_id` engineered to make the final `transfer` receipt fail (e.g., a newly-chosen, not-yet-existing named account requiring more than a bare transfer provides for account creation, or one that's since been deleted). No special privileges, roles, or relayer keys are needed — this is fully within the "unprivileged attacker" model (an attacker can target their own or victim's funds if they can get a signature, but more directly, this is a self-harm/footgun for any legitimate signer, and also weaponizable by a malicious relayer/dApp front-end tricking a user into signing a `NativeWithdraw` toward a doomed `receiver_id`). The existing sandbox test `native_withdraw_intent` only exercises the success path with implicit accounts and an already-existing account, and does not test a failing receiver, so this gap in coverage is consistent with the missing refund logic [8](#0-7) .

### Recommendation
Add a `native_resolve_withdraw`-style `#[private]` callback attached via `.then()` after `do_native_withdraw`'s returned promise (mirroring `ft_resolve_withdraw`/`nft_resolve_withdraw`/`mt_resolve_withdraw`), which checks `promise_result_checked_void` (or equivalent) on the final `transfer` outcome and, on failure, re-deposits the equivalent wNEAR amount back to the signer's internal balance (re-wrapping the retained native NEAR back into wNEAR custody, or crediting an internal NEAR-denominated balance) so the debit/delivery equality is restored. Remove the `.detach()` in `native_withdraw` so the resolve callback is actually scheduled and can act as the safety net.

```rust
// tests/src/tests/defuse/intents/native_withdraw_failure.rs (new test)
#[rstest]
#[tokio::test]
async fn native_withdraw_to_failing_receiver_loses_funds(#[future(awt)] env: Env) {
    let user = env.create_user().await;
    env.initial_ft_storage_deposit([user.account_id()], []).await;

    let amount = NearToken::from_near(1);
    // receiver_id chosen to be a syntactically valid, not-yet-existing named account
    // whose implicit creation via bare `transfer` fails post-facto
    // (e.g. a long named subaccount requiring storage registration beyond the transfer amount)
    let receiver_id: AccountId = "this-account-does-not-exist.testnet".parse().unwrap();

    env.near_deposit(env.wnear.contract_id(), amount).await.unwrap();
    env.ft(env.wnear.contract_id())
        .unwrap()
        .transfer_call(
            env.defuse.contract_id(),
            amount.as_yoctonear(),
            DepositMessage::new(user.account_id().clone()).to_string(),
        )
        .wait_until::<Final>()
        .await
        .unwrap();

    let withdraw_payload = user
        .sign_defuse_payload_default(
            &env.defuse,
            [NativeWithdraw { receiver_id: receiver_id.clone(), amount }],
        )
        .await
        .unwrap();

    // LHS of binding: internal wNEAR balance before
    let balance_before = env
        .contract::<Mt>(env.defuse.contract_id())
        .mt_balance_of(MtBalanceOfArgs {
            account_id: user.account_id(),
            token_id: &TokenId::Nep141(Nep141TokenId::new(env.wnear.contract_id().clone())).to_string(),
        })
        .await
        .unwrap()
        .0;
    assert_eq!(balance_before, amount.as_yoctonear());

    // execute_intents "succeeds" (top-level call returns Ok)
    let (res, _) = env
        .defuse_simulate_and_execute_intents(env.defuse.contract_id(), [withdraw_payload])
        .await
        .expect("execute_intents reports success despite downstream transfer failure");

    // RHS of binding: NEAR never delivered to receiver_id (account still doesn't exist / balance unchanged)
    let receiver_balance = env.account(&receiver_id).await;
    assert!(receiver_balance.is_none() || receiver_balance.unwrap().amount == NearToken::ZERO);

    // wNEAR balance was already debited and NEVER refunded -> funds permanently unrecoverable
    let balance_after = env
        .contract::<Mt>(env.defuse.contract_id())
        .mt_balance_of(MtBalanceOfArgs {
            account_id: user.account_id(),
            token_id: &TokenId::Nep141(Nep141TokenId::new(env.wnear.contract_id().clone())).to_string(),
        })
        .await
        .unwrap()
        .0;
    assert_eq!(balance_after, 0, "signer's wNEAR was debited with no refund");
}
```
This demonstrates the broken equality: `internal_sub_balance` (LHS, moved to 0) does not equal `NEAR delivered to receiver_id` (RHS, still 0/nonexistent), with `execute_intents` reporting success and no refund path triggered.

impl FungibleTokenWithdrawResolver for Contract {
    #[private]
    fn ft_resolve_withdraw(
        &mut self,
        token: AccountId,
        sender_id: AccountId,
        amount: U128,
        is_call: bool,
    ) -> U128 {
        let used = if is_call {
            // `ft_transfer_call` returns successfully transferred amount
            match promise_result_checked_json::<U128>(0) {
                Ok(Ok(used)) => used.0.min(amount.0),
                Ok(Err(_deserialize_err)) => 0,
                // do not refund on failed `ft_transfer_call` due to
                // NEP-141 vulnerability: `ft_resolve_transfer` fails to
                // read result of `ft_on_transfer` due to insufficient gas
                Err(_) => amount.0,
            }
        } else {
            // `ft_transfer` returns empty result on success
            if promise_result_checked_void(0).is_ok() {
                amount.0
            } else {
                0
            }
        };

        let refund = amount.0.saturating_sub(used);
        if refund > 0 {
            self.deposit(
                sender_id,
                [(Nep141TokenId::new(token).into(), refund)],
                Some(REFUND_MEMO),
            )
            .unwrap_or_else(|err| err.panic());
        }

        U128(used)
    }

#[rstest]
#[tokio::test]
async fn native_withdraw_intent(
    #[future(awt)] env: Env,
    ed25519_pk: PublicKey,
    secp256k1_pk: PublicKey,
) {
    let (user, other_user) = futures::join!(env.create_user(), env.create_user());

    env.initial_ft_storage_deposit([user.account_id(), other_user.account_id()], [])
        .await;

    let amounts_to_withdraw = [
        // Check for different account_id types
        // See https://github.com/near/nearcore/blob/dcfb6b9fb9f896b839b8728b8033baab963de344/core/parameters/src/cost.rs#L691-L709
        (
            ed25519_pk.to_implicit_account_id(),
            NearToken::from_near(100),
        ),
        (
            secp256k1_pk.to_implicit_account_id(),
            NearToken::from_near(200),
        ),
        (user.account_id().to_owned(), NearToken::from_near(300)),
    ];

    let initial_balances = {
        let mut result = vec![];
        for (account, _) in &amounts_to_withdraw {
            let balance = env
                .account(account)
                .await
                .map_or(NearToken::ZERO, |a| a.amount);

            result.push(balance);
        }
        result
    };

    let total_amount_yocto = amounts_to_withdraw
        .iter()
        .map(|(_, amount)| amount.as_yoctonear())
        .sum();

    env.near_deposit(
        env.wnear.contract_id(),
        NearToken::from_yoctonear(total_amount_yocto),
    )
    .await
    .expect("failed to wrap NEAR");

    env.ft(env.wnear.contract_id())
        .unwrap()
        .transfer_call(
            env.defuse.contract_id(),
            total_amount_yocto,
            DepositMessage::new(other_user.account_id().clone()).to_string(),
        )
        .gas(Gas::from_tgas(300))
        .wait_until::<Final>()
        .await
        .expect("failed to deposit wNEAR to user2");

    // withdraw native NEAR to corresponding receivers
    let withdraw_payload = other_user
        .sign_defuse_payload_default(
            &env.defuse,
            amounts_to_withdraw
                .iter()
                .cloned()
                .map(|(receiver_id, amount)| NativeWithdraw {
                    receiver_id,
                    amount,
                }),
        )
        .await
        .unwrap();

    let (res, _) = env
        .defuse_simulate_and_execute_intents(env.defuse.contract_id(), [withdraw_payload.clone()])
        .await
        .expect("execute_intents: failed to withdraw native NEAR to receivers");

    assert_eq_defuse_event_logs(withdraw_payload.to_event_log(), res.logs());

    assert_eq!(
        env.contract::<Mt>(env.defuse.contract_id())
            .mt_balance_of(MtBalanceOfArgs {
                account_id: other_user.account_id(),
                token_id: &TokenId::Nep141(Nep141TokenId::new(env.wnear.contract_id().clone()))
                    .to_string()
            })
            .await
            .unwrap()
            .0,
        0,
        "there should be nothing left deposited for user1"
    );

    // Check balances of NEAR on the blockchain
    for ((receiver_id, amount), initial_balance) in amounts_to_withdraw.iter().zip(initial_balances)
    {
        let balance = env.account(receiver_id).await.unwrap().amount;

        assert!(
            balance == initial_balance.checked_add(*amount).unwrap(),
            "wrong NEAR balance for {receiver_id}: expected minimum {amount}, got {balance}"
        );
    }
