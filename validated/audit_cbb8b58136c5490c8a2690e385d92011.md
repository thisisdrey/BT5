### Title
Unauthenticated block upload triggers unconditional network-wide relay of accepted Nakamoto blocks - (File: stackslib/src/net/api/postblock_v3.rs)

### Summary
`RPCPostBlockRequestHandler::try_parse_request` only requires authentication when the `broadcast=1` query parameter is present, but `try_handle_request` queues the posted block for relay via `node.set_relay_message(...)` based solely on whether `Relayer::process_new_nakamoto_block_ext` accepted the block, with no check of `self.broadcast` or an "authenticated" flag. This decouples the auth gate from the actual relay side-effect.

### Finding Description
In `try_parse_request` [1](#0-0) , `broadcast` defaults to `false` and is only forced to require authentication when the query string explicitly contains `broadcast=1`. If an attacker omits the `authorization` header and omits `broadcast=1` entirely, the request passes this gate with `authenticated = false` and `broadcast = false`, and `self.broadcast` is set to `Some(false)`.

In `try_handle_request` [2](#0-1) , the block is passed to `Relayer::process_new_nakamoto_block_ext(..., self.broadcast.unwrap_or(false))`, and then — regardless of the `broadcast` flag or whether the request was authenticated — if `data_resp.accepted` is true, the block is unconditionally pushed onto the node's relay queue via `node.set_relay_message(StacksMessageType::NakamotoBlocks(NakamotoBlocksData { blocks: vec![block] }))`.

I was not able to fully trace, within the tool budget available, the exact downstream consumer of `set_relay_message` (in `stackslib/src/net/mod.rs`/`stackslib/src/net/p2p.rs`/`stackslib/src/net/rpc.rs`) to confirm with certainty whether this queued message is subsequently broadcast to all peers unconditionally, or whether some other later gate (e.g. in `p2p.rs`'s message-relay loop) re-checks authentication/broadcast intent before actual network dissemination. The `broadcast` boolean passed into `process_new_nakamoto_block_ext` appears to only affect internal event-coordinator broadcasting (announcing to local subscribers), not the `set_relay_message` call, which structurally is unconditional on it in the code I read.

### Impact Explanation
If confirmed, this would mean any remote unprivileged peer could POST a validly-formed Nakamoto block with no RPC secret and no `broadcast=1`, have it validated and accepted by `Relayer::process_new_nakamoto_block_ext`, and have the node still queue it for network-wide gossip — making the "requires secret to set broadcast=1" gate meaningless with respect to actual peer-to-peer propagation, since propagation depends only on `data_resp.accepted`, not on `self.broadcast`/`authenticated`. This would match the Critical category of "network-wide propagation of forged/attacker-submitted data via an auth-bypassed path," assuming the block still needs to pass full consensus validation inside `process_new_nakamoto_block_ext` (which is out of scope to re-audit, per the rules — block-validation internals are excluded).

### Likelihood Explanation
I could not fully verify within the available budget whether `set_relay_message`'s queued content is unconditionally broadcast without further gating downstream, which is essential to confirming actual exploitability of "network-wide gossip." The `authorization`/`broadcast` gate at the HTTP layer is clearly decoupled from the relay-queuing decision in the code read, but I cannot confirm with full confidence that no other check exists further down the pipeline before the relay message reaches the p2p broadcast logic.

### Recommendation
Gate the `node.set_relay_message(...)` call in `try_handle_request` on the same conditions used for authentication (e.g. `if data_resp.accepted && self.broadcast.unwrap_or(false) { ... }`), so that only authenticated/broadcast-intended block uploads are queued for network relay, consistent with the auth gate already enforced in `try_parse_request`.

### Proof of Concept

impl RPCRequestHandler for RPCPostBlockRequestHandler {
    /// Reset internal state
    fn restart(&mut self) {
        self.block = None;
        self.broadcast = None;
    }

    /// Make the response
    fn try_handle_request(
        &mut self,
        preamble: HttpRequestPreamble,
        _contents: HttpRequestContents,
        node: &mut StacksNodeState,
    ) -> Result<(HttpResponsePreamble, HttpResponseContents), NetError> {
        // get out the request body
        let block = self
            .block
            .take()
            .ok_or(NetError::SendError("`block` not set".into()))?;

        let response = node
            .with_node_state(|network, sortdb, chainstate, _mempool, rpc_args| {
                let mut handle_conn = sortdb.index_handle_at_tip();
                let stacks_tip = network.stacks_tip.block_id();
                Relayer::process_new_nakamoto_block_ext(
                    &network.burnchain,
                    sortdb,
                    &mut handle_conn,
                    chainstate,
                    &stacks_tip,
                    &block,
                    rpc_args.coord_comms,
                    NakamotoBlockObtainMethod::Uploaded,
                    self.broadcast.unwrap_or(false),
                )
            })
            .map_err(|e| {
                StacksHttpResponse::new_error(&preamble, &HttpError::new(400, e.to_string()))
            });

        let data_resp = match response {
            Ok(accepted) => {
                debug!(
                    "Received POSTed Nakamoto block {}/{}: {:?}",
                    &block.header.consensus_hash,
                    &block.header.block_hash(),
                    &accepted
                );
                StacksBlockAcceptedData {
                    accepted: accepted.is_accepted(),
                    stacks_block_id: block.block_id(),
                }
            }
            Err(e) => {
                return e.try_into_contents().map_err(NetError::from);
            }
        };

        // should set to relay...
        if data_resp.accepted {
            node.set_relay_message(StacksMessageType::NakamotoBlocks(NakamotoBlocksData {
                blocks: vec![block],
            }));
        }
