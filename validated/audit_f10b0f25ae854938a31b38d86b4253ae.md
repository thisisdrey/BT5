### Title
Unauthenticated handshake flood forces unbounded Noise/X25519 computation on the responder before certificate verification - ([File: handshake_manager.go])

### Summary
The Brahma report's root issue is that an unauthenticated third party (a bot) controls an unbounded cost variable (`tx.gasprice`) that is applied directly to a victim-borne calculation with no cap, letting the attacker externalize cost onto the victim. The reachable analog in this codebase is `HandshakeManager.beginHandshake`, which runs full Noise IX handshake cryptography (X25519 key agreement + AEAD) for every inbound stage-1 packet before any certificate is verified and with no per-source rate limiting or cost cap, so an attacker who holds no CA-signed certificate can force the responder to spend unbounded CPU on their behalf.

### Finding Description
`HandshakeManager.HandleIncoming` dispatches any packet with `MessageCounter == 1` and `RemoteIndex == 0` straight to `beginHandshake`, gated only by the coarse `remote_allow_list` (an IP allow/deny list, not an authentication check): [1](#0-0) 

`beginHandshake` then unconditionally constructs a new `handshake.Machine` and calls `machine.ProcessPacket`, which invokes `m.hs.ReadMessage`, performing the Noise IX Diffie-Hellman and AEAD operations, before the peer certificate has been verified: [2](#0-1) 

Certificate verification only happens afterward, inside `validateCert`, which is invoked from `processPayload` during `ProcessPacket` — i.e., the expensive asymmetric crypto has already run by the time the certificate is checked: [3](#0-2) 

Unlike the fee-token calculation in the report — where `tx.gasprice` is an attacker-controlled input plugged into a cost formula with no ceiling — here the attacker-controlled input is simply "send another forged stage-1 packet," and the cost formula is "run a full Noise handshake," with no rate limiter, proof-of-work, or per-source throttle anywhere in `HandleIncoming` or `beginHandshake`. `remote_allow_list` (checked in `HandleIncoming`) filters by source IP/network, not by identity or cost, and is trivially satisfied by any allowed subnet or an unconfigured (default-allow) deployment.

### Impact Explanation
Any host that can reach the UDP listener — with no CA-signed certificate, since certificate verification only occurs after the costly crypto operations — can flood stage-1 handshake packets and force the responder to perform unbounded X25519/AEAD computation, exhausting CPU and creating an availability/DoS condition analogous to the "drain a victim's resource with an uncapped attacker-controlled cost" bug class in the report.

### Likelihood Explanation
Likelihood is high: the only precondition is being able to send a UDP packet shaped like a valid stage-1 handshake header (`MessageCounter=1`, `RemoteIndex=0`) to an open listener, which requires no cryptographic material and no prior trust relationship.

### Recommendation
Add a cost cap before performing Noise state advancement on unauthenticated stage-1 packets: apply per-source-IP rate limiting/token-bucket throttling in `HandleIncoming`/`beginHandshake` prior to invoking `machine.ProcessPacket`, and/or defer expensive crypto until a lightweight stateless integrity/cookie check (e.g., a retry cookie) has been satisfied, similar to mitigations used by other handshake protocols (WireGuard-style cookie replies) to bound the work an unauthenticated peer can trigger.

### Proof of Concept
1. From a host with no Nebula certificate, craft repeated UDP packets matching the wire format expected by `HandleIncoming` for a stage-1 handshake (`Type=Handshake`, `Subtype=HandshakeIXPSK0`, `MessageCounter=1`, `RemoteIndex=0`), as done by `makeHandshakePacket` in the existing test suite: [4](#0-3) 
2. Send these at high volume to a Nebula node's listen port.
3. Each packet reaches `beginHandshake` and triggers a full `handshake.Machine.ProcessPacket` (Noise IX DH + AEAD) before any certificate is verified, with no throttling in the dispatch path, allowing sustained CPU exhaustion on the victim from an unauthenticated sender.

func (hm *HandshakeManager) beginHandshake(via ViaSender, packet []byte, h *header.H) {
	f := hm.f
	cs := f.pki.getCertState()

	v := cs.DefaultVersion()
	if cs.GetCredential(v) == nil {
		f.l.Error("Unable to handshake with host because no certificate is available",
			"from", via, "certVersion", v)
		return
	}

	machine, err := handshake.NewMachine(
		v, cs.GetCredential,
		hm.certVerifier(), func() (uint32, error) { return generateIndex(f.l) },
		false, header.HandshakeIXPSK0,
	)
	if err != nil {
		f.l.Error("Failed to create handshake machine", "from", via, "error", err)
		return
	}

	response, result, err := machine.ProcessPacket(nil, packet)
	if err != nil {
		f.l.Error("Failed to process handshake packet", "from", via, "error", err)
		return
	}

func (m *Machine) validateCert(payload Payload) error {
	cred := m.getCred(m.myVersion)
	if cred == nil {
		m.failed = true
		return fmt.Errorf("%w: %v", ErrNoCredential, m.myVersion)
	}
	rc, err := cert.Recombine(
		cert.Version(payload.CertVersion),
		payload.Cert,
		m.hs.PeerStatic(),
		cred.Cert.Curve(),
	)
	if err != nil {
		m.failed = true
		return fmt.Errorf("recombine cert: %w", err)
	}

	if !bytes.Equal(rc.PublicKey(), m.hs.PeerStatic()) {
		m.failed = true
		return ErrPublicKeyMismatch
	}

	// Version negotiation, if the peer sent a different version and we have it, switch
	if rc.Version() != m.myVersion {
		if m.getCred(rc.Version()) != nil {
			m.myVersion = rc.Version()
		}
	}

	verified, err := m.verifier(rc)
	if err != nil {
		m.failed = true
		return fmt.Errorf("verify cert: %w", err)
	}
