### Title
Operator Can Set Beneficiary to `@vm_reserved` (`@0x0`), Permanently Freezing Staker Funds via Aborted `distribute_internal` — (`File: aptos-move/framework/aptos-framework/sources/staking_contract.move`)

---

### Summary

`staking_contract::set_beneficiary_for_operator` accepts any `new_beneficiary` address with no validation. An operator can set their beneficiary to `@0x0` (`@vm_reserved`). Every subsequent call to `distribute_internal` will attempt `aptos_account::deposit_coins(@0x0, commission)`, which calls `account::create_account(@0x0)` — an operation that unconditionally aborts for `@vm_reserved`. This permanently wedges all distributions for the affected staking contract, freezing the staker's APT in the stake pool with no recovery path.

---

### Finding Description

**Root cause — missing zero/reserved-address guard in `set_beneficiary_for_operator`:**

`staking_contract::set_beneficiary_for_operator` writes `new_beneficiary` directly into `BeneficiaryForOperator` with no validation:

```move
public entry fun set_beneficiary_for_operator(
    operator: &signer, new_beneficiary: address
) acquires BeneficiaryForOperator {
    assert!(
        features::operator_beneficiary_change_enabled(),
        std::error::invalid_state(EOPERATOR_BENEFICIARY_CHANGE_NOT_SUPPORTED)
    );
    let operator_addr = signer::address_of(operator);
    ...
    borrow_global_mut<BeneficiaryForOperator>(operator_addr).beneficiary_for_operator =
        new_beneficiary;   // ← no check: new_beneficiary != @0x0
    ...
}
``` [1](#0-0) 

**Propagation — `distribute_internal` redirects commission to the poisoned beneficiary:**

```move
if (recipient == operator) {
    recipient = beneficiary_for_operator(operator);  // returns @0x0
};
aptos_account::deposit_coins(
    recipient, coin::extract(&mut coins, amount_to_distribute)  // deposit to @0x0
);
``` [2](#0-1) 

**Abort path — `deposit_coins` calls `create_account(@0x0)` which aborts:**

```move
public fun deposit_coins<CoinType>(to: address, coins: Coin<CoinType>) ... {
    if (!account::exists_at(to)) {
        create_account(to);   // aborts if to == @vm_reserved
    };
    ...
}
``` [3](#0-2) 

The formal spec confirms `create_account` aborts for `@vm_reserved` (`@0x0`), `@aptos_framework` (`@0x1`), and `@aptos_token` (`@0x3`): [4](#0-3) 

`system_addresses::is_reserved_address` confirms `@vm_reserved = @0x0`: [5](#0-4) 

**`delegation_pool::set_beneficiary_for_operator` has the same missing guard:**

```move
public entry fun set_beneficiary_for_operator(
    operator: &signer,
    new_beneficiary: address   // ← no validation
) acquires BeneficiaryForOperator {
``` [6](#0-5) 

In the delegation pool case, `buy_in_active_shares(pool, @0x0, commission)` succeeds (it is a pool-internal share credit, not a coin transfer), so the commission APT is permanently locked in shares owned by `@0x0` — a permanent loss rather than a freeze.

**Contrast with `vesting::create_vesting_contract`, which correctly guards its `withdrawal_address`:**

```move
assert!(
    !system_addresses::is_reserved_address(withdrawal_address),
    error::invalid_argument(EINVALID_WITHDRAWAL_ADDRESS),
);
``` [7](#0-6) 

`set_beneficiary_for_operator` in both `staking_contract` and `delegation_pool` omits this guard entirely.

---

### Impact Explanation

**`staking_contract` path (permanent freeze of staker APT):**

Once an operator sets `new_beneficiary = @0x0`, every call to `distribute(staker, operator)` aborts inside `distribute_internal`. Because `distribute_internal` is also called inside `switch_operator` (the only way for a staker to change operators), the staker cannot switch operators either. The staker's APT is permanently locked in the stake pool with no recovery path. This is a direct, permanent freeze of user-controlled on-chain assets (APT staking balances) triggered by an unprivileged operator transaction.

**`delegation_pool` path (permanent loss of commission APT):**

`buy_in_active_shares(pool, @0x0, commission_active)` credits shares to `@0x0`. Since `@0x0` is uncontrolled, those shares — and the APT they represent — are permanently inaccessible. Delegators' own shares are unaffected, but the commission APT is burned into the pool. [8](#0-7) 

---

### Likelihood Explanation

- The trigger is a single unprivileged operator transaction: `set_beneficiary_for_operator(@0x0)`.
- No governance approval or admin action is required.
- The feature flag `operator_beneficiary_change_enabled` is already enabled on mainnet (it is a shipped feature with SDK builder support).
- A malicious or compromised operator can execute this against any staking contract they operate, affecting all stakers who delegated to them.
- The `delegation_pool` variant has no feature flag at all.

---

### Recommendation

Add a reserved-address guard in both `set_beneficiary_for_operator` functions, mirroring the existing guard in `vesting::create_vesting_contract`:

```move
// staking_contract.move and delegation_pool.move
public entry fun set_beneficiary_for_operator(
    operator: &signer, new_beneficiary: address
) acquires BeneficiaryForOperator {
    assert!(
        !system_addresses::is_reserved_address(new_beneficiary),
        error::invalid_argument(EINVALID_BENEFICIARY_ADDRESS)
    );
    // ... existing logic
}
```

Additionally, consider requiring that `new_beneficiary` has an existing account registered for APT (analogous to `assert_account_is_registered_for_apt` used in `vesting::set_beneficiary`), to prevent deposits to any address that would cause `deposit_coins` to abort.

---

### Proof of Concept

**`staking_contract` freeze scenario (Move pseudocode):**

```
1. Operator calls:
   staking_contract::set_beneficiary_for_operator(operator_signer, @0x0)
   // BeneficiaryForOperator { beneficiary_for_operator: @0x0 } stored under operator_addr

2. Staker calls unlock_stake(...) → commission enters distribution_pool

3. Anyone calls:
   staking_contract::distribute(staker_addr, operator_addr)
   → distribute_internal(staker_addr, operator_addr, &mut staking_contract)
     → recipient = operator_addr (has commission shares)
     → recipient = beneficiary_for_operator(operator_addr) = @0x0
     → aptos_account::deposit_coins(@0x0, commission_coins)
       → account::exists_at(@0x0) == false  (vm_reserved has no regular account)
       → create_account(@0x0)
         → ABORT: auth_key == @vm_reserved
   // distribute_internal aborts; staker's coins remain locked in stake pool forever

4. Staker tries switch_operator(...) → calls distribute_internal → same abort
   // No recovery path exists
```

The staker's APT staking balance is permanently frozen. The broken invariant is: `distribute_internal` must always be able to deliver commission to the operator's beneficiary, but no guard prevents the beneficiary from being set to an address where `deposit_coins` unconditionally aborts.
