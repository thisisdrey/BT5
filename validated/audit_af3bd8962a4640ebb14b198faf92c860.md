### Title
Certificate-Version Negotiation Lets an Unauthenticated Peer Silently Downgrade the Trust Anchor Mid-Handshake - (File: handshake/machine.go)

### Summary
`Machine.validateCert` treats certificates of different `cert.Version` (V1/VersionPre1 protobuf vs. V2 ASN.1) as fungible, 1:1-interchangeable proofs of identity for the purpose of picking which credential/version this side of the handshake will use, based solely on an unauthenticated peer-supplied `payload.CertVersion` field, before the certificate has been cryptographically verified against a CA.

### Finding Description
In `validateCert`, the certificate is first reconstructed with `cert.Recombine` using the *peer-supplied* `payload.CertVersion` [2](#0-1) , and only afterward is version negotiation performed:

```go
// Version negotiation, if the peer sent a different version and we have it, switch
if rc.Version() != m.myVersion {
    if m.getCred(rc.Version()) != nil {
        m.myVersion = rc.Version()
    }
}
``` [1](#0-0) 

This mirrors the stablecoin bug's root cause: distinct assets (here, certificate *versions*, which use different serialization/validation code paths — protobuf for V1 vs ASN.1 for V2) are treated as one interchangeable "certificate" concept with zero cost to switch between them, and the switch happens on attacker-controlled input (`payload.CertVersion`) *before* the certificate is verified by `m.verifier` (`CheckCAConstraints`/`VerifyCertificate`) at line 371 [3](#0-2) . An attacker with no CA-signed certificate at all can send a handshake message containing an arbitrary `payload.CertVersion` and arbitrary `payload.Cert` bytes; `cert.Recombine` will attempt to unmarshal them under whichever version/curve combination is requested [4](#0-3) . Because `m.myVersion` (which subsequently controls which credential/cert-parsing path is used for the rest of the exchange, including `marshalOutgoing`'s `cred := m.getCred(m.myVersion)` at line 407) is mutated purely from unauthenticated peer input, this creates a pre-authentication code-path confusion: the responder can be steered onto a certificate-parsing implementation (V1 protobuf vs V2 ASN.1) that the local operator did not intend to expose, widening the unauthenticated attack surface reachable during the handshake before any signature or CA-pool check has succeeded.

### Impact Explanation
An unauthenticated network attacker (no valid CA-signed certificate) can force the responder to switch its in-progress handshake state to a certificate version/parser of the attacker's choosing prior to any cryptographic verification, expanding the reachable pre-auth parsing surface (V1 protobuf unmarshal vs V2 ASN.1 unmarshal) and enabling confusion between two code paths with different validation semantics (e.g., V1's "ignore extra networks" behavior noted in `cert_v1.go`'s `validate()` [5](#0-4)  vs V2's stricter multi-network handling). This does not by itself grant a certificate bypass — `m.verifier` will still reject an unsigned/invalid certificate — but it violates the intended invariant that the locally configured/expected certificate version governs which parser and validation rules apply, and it does so using only attacker-supplied handshake bytes from a peer holding no valid credentials.

### Likelihood Explanation
High reachability: any unauthenticated UDP peer can send a crafted stage-1/stage-2 handshake packet; `ProcessPacket` only checks packet length and subtype before invoking `processPayload` → `validateCert` [6](#0-5) . No CA-signed certificate, prior handshake state, or firewall/hostmap trust is required to reach this code path — it fires on the very first handshake message.

### Recommendation
Do not let the peer-declared `payload.CertVersion` mutate `m.myVersion` (and thereby the credential/parser used for the remainder of the handshake) until the certificate has been fully verified by `m.verifier`. Perform negotiation only after `VerifyCertificate`/`CheckCAConstraints` succeed, or restrict negotiation to a fixed allow-list of versions decided independently of untrusted payload content, so that certificate "version" is not treated as a fungible, pre-verification-swappable attribute.

### Proof of Concept
1. Attacker (holding no CA-signed certificate) sends a handshake stage-1 packet to a Nebula node configured to expect `cert.Version2`, with `payload.CertVersion` set to `cert.Version1` and an arbitrary (unsigned) `payload.Cert` blob.
2. `validateCert` calls `cert.Recombine(cert.Version1, ...)`, and even though the subsequent `m.verifier(rc)` call ultimately rejects the bad signature, `m.myVersion` has already been flipped to `Version1` per lines 364-369 for the duration of processing this message, based purely on unauthenticated attacker input [7](#0-6) .

func (m *Machine) ProcessPacket(out, packet []byte) ([]byte, *Result, error) {
	if m.failed {
		return nil, nil, ErrMachineFailed
	}
	if len(packet) < header.Len {
		return nil, nil, ErrPacketTooShort
	}
	// Reject packets whose subtype doesn't match the one this Machine was
	// built for. A pending handshake that suddenly receives a different
	// subtype on its index is either a stray packet that matched by chance
	// or a peer protocol violation; drop it without failing the Machine so
	// the legitimate retransmit can still complete.
	if header.MessageSubType(packet[1]) != m.subtype {
		return nil, nil, ErrSubtypeMismatch
	}
	if m.result.Initiator && m.hs.MessageIndex() == 0 {
		m.failed = true
		return nil, nil, ErrInitiateNotCalled
	}

	// The (eKey, dKey) ordering here is correct for IX, where the initiator
	// completes the handshake by reading the responder's stage-2 message.
	// noise returns (cs1, cs2) where cs1 is the initiator->responder cipher.
	// For 3-message patterns where a responder finishes by reading the final
	// message, this ordering would be wrong; revisit when XX/pqIX lands.
	msg, eKey, dKey, err := m.hs.ReadMessage(nil, packet[header.Len:])
	if err != nil {
		// Noise ReadMessage failed. The noise library checkpoints and rolls back
		// on failure, so the Machine is still alive. The caller can retry with
		// a different packet.
		return nil, nil, fmt.Errorf("noise ReadMessage: %w", err)
	}

	// From here on, noise state has advanced. Any error is fatal.
	flags := m.peerMsgFlags()

	if err := m.processPayload(msg, flags); err != nil {
		return nil, nil, err
	}

func (m *Machine) validateCert(payload Payload) error {
	cred := m.getCred(m.myVersion)
	if cred == nil {
		m.failed = true
		return fmt.Errorf("%w: %v", ErrNoCredential, m.myVersion)
	}
	rc, err := cert.Recombine(
		cert.Version(payload.CertVersion),
		payload.Cert,
		m.hs.PeerStatic(),
		cred.Cert.Curve(),
	)
	if err != nil {
		m.failed = true
		return fmt.Errorf("recombine cert: %w", err)
	}

	if !bytes.Equal(rc.PublicKey(), m.hs.PeerStatic()) {
		m.failed = true
		return ErrPublicKeyMismatch
	}

	// Version negotiation, if the peer sent a different version and we have it, switch
	if rc.Version() != m.myVersion {
		if m.getCred(rc.Version()) != nil {
			m.myVersion = rc.Version()
		}
	}

	verified, err := m.verifier(rc)
	if err != nil {
		m.failed = true
		return fmt.Errorf("verify cert: %w", err)
	}

	m.result.RemoteCert = verified
	m.remoteCertSet = true
	return nil
}

func Recombine(v Version, rawCertBytes, publicKey []byte, curve Curve) (Certificate, error) {
	if publicKey == nil {
		return nil, ErrNoPeerStaticKey
	}

	if rawCertBytes == nil {
		return nil, ErrNoPayload
	}

	var c Certificate
	var err error

	switch v {
	// Implementations must ensure the result is a valid cert!
	case VersionPre1, Version1:
		c, err = unmarshalCertificateV1(rawCertBytes, publicKey)
	case Version2:
		c, err = unmarshalCertificateV2(rawCertBytes, publicKey, curve)
	default:
		return nil, ErrUnknownVersion
	}

	if err != nil {
		return nil, err
	}

	if c.Curve() != curve {
		return nil, fmt.Errorf("certificate curve %s does not match expected %s", c.Curve().String(), curve.String())
	}

	return c, nil
}
