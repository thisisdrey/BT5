### Title
`flashRepay` full-debt repayment reverts due to rounding mismatch between `quoteRepayIn` and `quoteRepayOut` - (File: contracts/SmartFarmingManager.sol)

### Summary
Analogous to the Napier `swapUnderlyingForYt` rounding bug, `SmartFarmingManager.flashRepay` computes the gross synthetic amount needed to fully repay a debt via `DebtToken.quoteRepayIn` (which adds the fee with `wadMul`, rounding half-up), but `DebtToken.repay` then recomputes the net repaid amount via `quoteRepayOut` using `wadDiv` (also rounding half-up). These two roundings are not inverses of each other, so when a user tries to repay their entire debt the resulting `_repaid` can be either 1 wei above `balanceOf` (reverting with `BurnAmountExceedsBalance` in `_burn`) or 1 wei below it, leaving dust debt that reverts with `RemainingDebtIsLowerThanTheFloor`. The user-facing flash-repay flow therefore reverts on full repayments whenever `repayFee > 0` and `debtFloorInUsd > 0`. [1](#0-0) 

### Finding Description
In `flashRepay`, the repay amount is capped at the full debt:

```solidity
(uint256 _maxRepayAmount, ) = _debtToken.quoteRepayIn(_debtToken.balanceOf(_msgSender));
uint256 _amountToRepay = Math.min(_swapAmountOut, _maxRepayAmount);
(_repaid, ) = _debtToken.repay(_msgSender, _amountToRepay);
``` [2](#0-1) 

`quoteRepayIn` returns `amountToRepay_ + amountToRepay_.wadMul(repayFee)`, where `wadMul` rounds half-up — i.e. it can be up to 0.5 wei below the mathematically exact gross amount. `repay` then calls `quoteRepayOut(amount_)`, which computes `_amountToRepay = amount_.wadDiv(HUNDRED_PERCENT + _repayFee)`, again rounding half-up. Because both functions round to nearest (not in opposite, safe directions), `quoteRepayOut(quoteRepayIn(debt))` is not guaranteed to equal `debt`. [3](#0-2) 

Two failure modes in `repay` when the user wants a full repay:

1. `_repaid > balanceOf(onBehalfOf_)` → `_burn` reverts with `BurnAmountExceedsBalance` at line 529.
2. `_repaid < balanceOf(onBehalfOf_)` by a few wei → the remaining debt is `> 0` and below `debtFloorInUsd`, so `repay` reverts with `RemainingDebtIsLowerThanTheFloor` at lines 442-450.

The final health check in `flashRepay` cannot rescue either case since `repay` itself reverts first. Notably, `repayAll` avoids this entirely by computing the gross amount for the fee seizure via `quoteRepayIn` but burning `balanceOf` directly — the same "don't round-trip the quote" pattern that Napier adopted as the fix. [4](#0-3) 

### Impact Explanation
`flashRepay` is the only atomic "unwind a leveraged position" path: a user whose collateral is locked cannot withdraw it without repaying debt, and cannot repay synth debt without either already holding the synth or withdrawing collateral to swap. If a user's only feasible repay amount is their full debt (typical for leveraged positions unwound via `flashRepay`), the rounding mismatch causes a guaranteed revert for specific `debt`/`repayFee` combinations. The user's collateral is temporarily frozen in the protocol — they must either acquire extra synth on the open market to use `repayAll`, or repeatedly guess a `withdrawAmount_`/`swapAmountOutMin_` combination whose swap output avoids both failure modes. This is the same DoS-of-core-function class as the Napier issue.

### Likelihood Explanation
The revert occurs whenever `(debt + wadMul(debt, repayFee)) wadDiv (1e18 + repayFee) != debt`, which happens for a substantial fraction of debt values whenever `repayFee > 0` and the swap returns exactly `_maxRepayAmount` (or slightly more). The second failure mode additionally requires `debtFloorInUsd > 0`, which is configured on deployed pools to prevent dust debt. No privileged action, oracle manipulation, or attacker setup is needed — an ordinary user calling `flashRepay` to close their own position hits it. Likelihood is moderate: whether a given position triggers it depends on the wei-level value of `debt * repayFee mod (1e18 + repayFee)`.

### Recommendation
Do not round-trip the gross→net quote inside `repay` for the max-repay path. Options, mirroring `repayAll`:

- In `flashRepay`, when `_swapAmountOut >= _maxRepayAmount`, call `repayAll(_msgSender)` instead of `repay(_msgSender, _maxRepayAmount)`.
- Alternatively, change `quoteRepayIn` to round the fee up (`mulDivUp`/`wadMulUp`) and `quoteRepayOut` to round the repaid amount down, so `quoteRepayOut(quoteRepayIn(x)) >= x` is guaranteed — analogous to Napier's recommended `divWadUp` fix.

### Proof of Concept
Conceptual Foundry test (fork mainnet where a `repayFee > 0` and `debtFloorInUsd > 0` exist):

```solidity
// Assume alice has an open position: msdVaUSDC deposit + msUSD debt D.
uint256 debt = msUSDDebt.balanceOf(alice);
(uint256 gross, ) = msUSDDebt.quoteRepayIn(debt);
// gross = debt + wadMul(debt, repayFee)

(uint256 net, ) = msUSDDebt.quoteRepayOut(gross);
// For many (debt, repayFee) pairs, net == debt - 1 or debt + 1.

// Case A: net = debt + 1 -> repay reverts BurnAmountExceedsBalance
// Case B: net = debt - 1 -> remaining dust < debtFloorInUsd -> RemainingDebtIsLowerThanTheFloor
// Force _swapAmountOut >= gross via mock swapper rate = 1e18:
vm.prank(alice);
smartFarmingManager.flashRepay(msUSD, msdVaUSDC, withdrawAmount, 0);
// expect revert
```

A concrete triggering example: `repayFee = 1e15` (0.1%), `debt = D` where `wadMul(D, 1e15)` rounds down by ≥1 wei effective in the division, e.g. `D = 1000e18 + 333` — `D * 0.001 = 1000.000333e18`, `wadMul` gives `1000000333000000000000` (exact here), but values where `D * fee mod 1e18 >= 5e17` push `gross` up by a fractional wei that `wadDiv` then rounds up past `D`. Iterating `debt` over a small range in a fork test will surface both revert modes quickly.

    function quoteRepayIn(uint256 amountToRepay_) public view override returns (uint256 _amount, uint256 _fee) {
        uint256 _repayFee = pool.feeProvider().repayFee();
        if (_repayFee == 0) {
            return (amountToRepay_, _fee);
        }

        _fee = amountToRepay_.wadMul(_repayFee);
        _amount = amountToRepay_ + _fee;
    }

    /**
     * @notice Quote debt `_amountToRepay` by burning `_amount` synthetic tokens
     * @param amount_ Gross amount
     * @return _amountToRepay Debt amount to repay
     * @return _fee The fee amount to collect
     */
    function quoteRepayOut(uint256 amount_) public view override returns (uint256 _amountToRepay, uint256 _fee) {
        uint256 _repayFee = pool.feeProvider().repayFee();
        if (_repayFee == 0) {
            return (amount_, _fee);
        }

        _amountToRepay = amount_.wadDiv(HUNDRED_PERCENT + _repayFee);
        _fee = amount_ - _amountToRepay;
    }
