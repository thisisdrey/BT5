### Title
Unprotected slippage in Snowbridge tip/fee swap allows sandwich attack to devalue bridge tips and registration fees - (File: `bridges/snowbridge/pallets/system-frontend/src/lib.rs`)

### Summary
The `swap_and_burn` helper in `pallet-snowbridge-system-frontend` calls `T::Swap::swap_exact_tokens_for_tokens` with `amount_out_min` hardcoded to `None`, meaning the pool-based AMM swap performed by `pallet-asset-conversion` accepts any output amount, however low. This function underlies the public extrinsics `register_token` and `add_tip`, both callable by any signed account, so an attacker can sandwich these swaps in the AssetConversion pool to extract value at the caller's expense.

### Finding Description
`swap_and_burn` is invoked from `swap_fee_asset_and_burn`, which is called from two public, unprivileged dispatchables:
- `register_token` (any origin whose `asset_id` is nested in itself) [1](#0-0) 
- `add_tip` (any signed account) [2](#0-1) 

Both routes call `swap_fee_asset_and_burn`, which swaps the user-supplied fee/tip asset into Ether via `Self::swap_and_burn` whenever the asset isn't already Ether: [3](#0-2) 

`swap_and_burn` itself performs the AMM swap through `pallet_asset_conversion::Swap::swap_exact_tokens_for_tokens` and explicitly passes `None` for the minimum-output parameter, with the in-code comment "No minimum amount required": [4](#0-3) 

`swap_exact_tokens_for_tokens` treats `amount_out_min = None` as "accept whatever the pool returns," since the guard that checks the resulting `amount_out` against a minimum is skipped when `None` is provided: [5](#0-4) 

The `AssetConversion` pool is a plain constant-product AMM whose price at execution time is entirely determined by the reserves in the same block, so it is trivially manipulable by any unprivileged account submitting ordinary extrinsics (front-run swap to skew price, let the victim's swap execute at the skewed price, back-run swap to restore price and capture the difference) — no validator, collator, relayer, or admin role is required.

### Impact Explanation
`ether_gained`, the result of this unprotected swap, is not just a local value — it becomes the `amount` field forwarded via XCM `Transact` to the `EthereumSystem::RegisterToken`/`AddTip` calls on BridgeHub: [6](#0-5) [7](#0-6) 

This means the sandwich attacker can systematically siphon value out of every tip/registration-fee swap, so the amount registered/credited toward the relayer reward (or the Ethereum registration fee) is measurably lower than the user actually paid — a direct value-conservation break in the bridge reward/fee-forwarding path, while the tipper's input tokens are fully consumed regardless of the manipulated output.

### Likelihood Explanation
High. `add_tip` is a plain signed extrinsic with no special origin checks, and the AssetConversion pool reserves are public on-chain state that any account can move within the same block via its own prior/following swap extrinsics. No privileged or off-chain actor is needed — this is standard atomic sandwiching by an ordinary user, exactly the attacker primitive described in the source report.

### Recommendation
Do not pass `None` for `amount_out_min`. Compute a caller-supplied or oracle/quote-derived minimum (e.g., using `QuotePrice::quote_price_exact_tokens_for_tokens` with a bounded tolerance, or exposing an explicit `min_ether_out`/slippage parameter on `register_token`/`add_tip`) and pass `Some(min)` into `swap_exact_tokens_for_tokens`, so the swap reverts rather than settling at an attacker-manipulated price.

### Proof of Concept
1. Attacker observes a pending `add_tip(message_id, tip_asset)` (or `register_token`) extrinsic from victim in the transaction pool/next block.
2. Attacker submits `AssetConversion::swap_exact_tokens_for_tokens` swapping a large amount of `tip_asset` into `ether_location` first in the same block, moving the pool reserve ratio unfavorably against further `tip_asset -> ether` swaps.
3. Victim's `add_tip` executes, internally calling `swap_and_burn` → `Swap::swap_exact_tokens_for_tokens(..., None, ...)`, which accepts the now-degraded exchange rate since no minimum is enforced (`substrate/frame/asset-conversion/src/lib.rs:988-1002` skips the `ProvidedMinimumNotSufficientForSwap` check).
4. Attacker submits a reverse swap `ether -> tip_asset` to restore the pool and realize the arbitrage profit extracted from the victim's swap.
5. The `ether_gained` recorded and forwarded as the `AddTip.amount` to BridgeHub is now lower than fair value, reducing the actual relayer reward credited on Ethereum despite the victim paying the full intended tip amount.

		fn swap_and_burn(
			origin: Location,
			tip_asset_location: Location,
			ether_location: Location,
			tip_amount: u128,
		) -> Result<u128, DispatchError> {
			// Swap tip asset to ether
			let swap_path = vec![tip_asset_location.clone(), ether_location.clone()];
			let who = T::AccountIdConverter::convert_location(&origin)
				.ok_or(Error::<T>::LocationConversionFailed)?;

			let ether_gained = T::Swap::swap_exact_tokens_for_tokens(
				who.clone(),
				swap_path,
				tip_amount,
				None, // No minimum amount required
				who,
				true,
			)?;

			// Burn the ether
			let ether_asset = Asset::from((ether_location.clone(), ether_gained));

			burn_for_teleport::<T::AssetTransactor>(&origin, &ether_asset)
				.map_err(|_| Error::<T>::BurnError)?;

			Ok(ether_gained)
		}

		fn swap_fee_asset_and_burn(
			origin: Location,
			fee_asset: Asset,
		) -> Result<u128, DispatchError> {
			let ether_location = T::EthereumLocation::get();
			let (fee_asset_location, fee_amount) = match fee_asset {
				Asset { id: AssetId(ref loc), fun: Fungible(amount) } => (loc, amount),
				_ => {
					tracing::debug!(target: LOG_TARGET, ?fee_asset, "error matching fee asset");
					return Err(Error::<T>::UnsupportedAsset.into());
				},
			};
			if fee_amount == 0 {
				return Ok(0);
			}

			let ether_gained = if *fee_asset_location != ether_location {
				Self::swap_and_burn(
					origin.clone(),
					fee_asset_location.clone(),
					ether_location,
					fee_amount,
				)
				.inspect_err(|&e| {
					tracing::debug!(target: LOG_TARGET, ?e, "error swapping asset");
				})?
			} else {
				burn_for_teleport::<T::AssetTransactor>(&origin, &fee_asset)
					.map_err(|_| Error::<T>::BurnError)?;
				fee_amount
			};
			Ok(ether_gained)
		}
