### Title
Delegated resource lock can be shortened via repeated TVM-native `freezeBalance` delegation - (File: `actuator/src/main/java/org/tron/core/vm/nativecontract/FreezeBalanceProcessor.java`)

### Summary
The old-style, contract-invoked `FreezeBalanceProcessor.delegateResource` method updates the `DelegatedResourceCapsule` expire time by unconditionally overwriting it with a freshly computed value, without ever checking that the new expire time is not shorter than the currently-stored, still-active one. This is the same root-cause class as the GG-3 "Shorten Lock" report: a party controlling the `_from`/owner side of a lock relationship can push a shorter expiry onto an existing, longer lock held by the counterparty (`_to`/receiver), unlocking previously delegated resource earlier than the receiver was promised.

### Finding Description
`FreezeBalanceProcessor.execute()` computes `expireTime = nowInMs + param.getFrozenDuration() * FROZEN_PERIOD` and, when delegating, calls `delegateResource(...)`, which does: [1](#0-0) 

Inside, the capsule is fetched/created and updated via `addFrozenBalanceForBandwidth`/`addFrozenBalanceForEnergy`, which always sets `ExpireTimeForBandwidth`/`ExpireTimeForEnergy` to whatever `expireTime` was just passed in, regardless of the capsule's previous expire time: [2](#0-1) 

Crucially, `FreezeBalanceProcessor.validate()` contains **no** remaining-time / lock-period check analogous to what exists in the newer `DelegateResourceActuator`. Compare with `DelegateResourceActuator.validate()`, which explicitly loads the existing `DelegatedResourceCapsule` for the owner/receiver pair and calls `validRemainTime()` to reject any new lock whose duration is shorter than the remaining time of the currently active lock: [3](#0-2) [4](#0-3) 

`FreezeBalanceProcessor.validate()` only checks balance/frozen-count/resource-type/receiver-existence, never comparing the requested `frozenDuration` against any pre-existing delegated expire time: [5](#0-4) 

Because `frozenDuration` is a caller-supplied field on `FreezeBalanceParam` (set from opcode arguments in the TVM), an owner who has already delegated frozen balance to a receiver with a long expiry can issue a second `freezeBalance`-and-delegate call to the same receiver with a minimal duration; `addFrozenBalanceForBandwidth`/`addFrozenBalanceForEnergy` will add the new balance to the total but reset `ExpireTimeForBandwidth`/`ExpireTimeForEnergy` for the *entire* delegated balance (old + new) down to the new, shorter value: [6](#0-5) 

This directly mirrors the GG-3 bug class: `_to.stakeUntil` (here, the receiver's delegated-resource expire time) is overwritten by a shorter value supplied by `_from` (the owner), shortening a lock the receiver was relying on.

### Impact Explanation
The receiver of delegated resource (bandwidth/energy) relies on the expire time to know when the delegation can be reclaimed by the owner (`UnfreezeBalanceProcessor`/`UnfreezeBalanceActuator` refuse to release the delegated resource before `expireTimeForBandwidth`/`expireTimeForEnergy`). By shortening the expire time, the owner can unlock and reclaim delegated resource/TRX earlier than the terms under which the receiver accepted or came to depend on that delegation, undermining any off-chain or on-chain assumptions (e.g., collateral, resource guarantees, SR voting weight duration) built on the original lock duration. This can allow unauthorized early reclamation of value that was supposed to remain locked/delegated to the receiver, i.e., a form of unbacked/prematurely-freed balance guarantee — a Medium/High severity issue depending on how downstream systems rely on delegation duration guarantees.

### Likelihood Explanation
This path is reachable by any contract deployer/caller who can trigger the `freezeBalance` native-contract precompile from within a smart contract (an ordinary, permissionless operation once resource-delegation-from-VM is enabled). No special privilege beyond owning TRX to freeze and calling the precompile with a small `frozenDuration` is required, making this trivially and repeatably exploitable by any owner who wants to shorten a lock they previously extended to a receiver.

### Recommendation
In `FreezeBalanceProcessor.validate()` (and correspondingly `execute()`/`delegateResource()`), fetch the existing `DelegatedResourceCapsule` for the `(ownerAddress, receiverAddress)` pair before allowing a new delegate-with-freeze call, and reject (or clamp) any new `expireTime` that is earlier than the currently stored, unexpired `ExpireTimeForBandwidth`/`ExpireTimeForEnergy` — mirroring the `validRemainTime()` check already present in `DelegateResourceActuator`. Alternatively, always take `max(existingExpireTime, newExpireTime)` in `addFrozenBalanceForBandwidth`/`addFrozenBalanceForEnergy` when the existing balance is non-zero and not yet expired.

### Proof of Concept
1. From a smart contract, invoke the `freezeBalance` native opcode/precompile with `ownerAddress = A`, `receiverAddress = B`, `frozenDuration = 30` (days) for BANDWIDTH — this creates/updates the `DelegatedResourceCapsule(A,B)` with `ExpireTimeForBandwidth = now + 30*FROZEN_PERIOD`.
2. Immediately (or shortly after) call `freezeBalance` again from the same contract with `ownerAddress = A`, `receiverAddress = B`, a small `frozenBalance`, and `frozenDuration = 3` (minimum) for BANDWIDTH.
3. `FreezeBalanceProcessor.delegateResource` calls `addFrozenBalanceForBandwidth(frozenBalance, expireTime)` with the new, much shorter `expireTime`, which unconditionally overwrites `ExpireTimeForBandwidth` on the capsule holding the combined (30-day + new) frozen balance.
4. `A` can now call `unfreezeBalance` after only 3 days (instead of 30) and reclaim the entire delegated balance, including the portion originally promised to be locked for 30 days to `B`, verified via `UnfreezeBalanceProcessor.validate()`'s check `delegatedResourceCapsule.getExpireTimeForBandwidth() > now` succeeding earlier than intended: [7](#0-6)

  public void validate(FreezeBalanceParam param, Repository repo) throws ContractValidateException {
    if (repo == null) {
      throw new ContractValidateException(STORE_NOT_EXIST);
    }

    // validate arg @frozenBalance
    byte[] ownerAddress = param.getOwnerAddress();
    AccountCapsule ownerCapsule = repo.getAccount(ownerAddress);
    long frozenBalance = param.getFrozenBalance();
    if (frozenBalance <= 0) {
      throw new ContractValidateException("FrozenBalance must be positive");
    } else if (frozenBalance < TRX_PRECISION) {
      throw new ContractValidateException("FrozenBalance must be greater than or equal to 1 TRX");
    } else if (frozenBalance > ownerCapsule.getBalance()) {
      throw new ContractValidateException("FrozenBalance must be less than or equal to accountBalance");
    }

    // validate frozen count of owner account
    int frozenCount = ownerCapsule.getFrozenCount();
    if (frozenCount != 0 && frozenCount != 1) {
      throw new ContractValidateException("FrozenCount must be 0 or 1");
    }

    // validate arg @resourceType
    switch (param.getResourceType()) {
      case BANDWIDTH:
      case ENERGY:
        break;
      default:
        throw new ContractValidateException(
            "Unknown ResourceCode, valid ResourceCode[BANDWIDTH、ENERGY]");
    }

    // validate for delegating resource
    byte[] receiverAddress = param.getReceiverAddress();
    if (!FastByteComparisons.isEqual(ownerAddress, receiverAddress)) {
      param.setDelegating(true);

      // check if receiver account exists. if not, then create a new account
      AccountCapsule receiverCapsule = repo.getAccount(receiverAddress);
      if (receiverCapsule == null) {
        receiverCapsule = repo.createNormalAccount(receiverAddress);
      }

      // forbid delegating resource to contract account
      if (receiverCapsule.getType() == Protocol.AccountType.Contract) {
        throw new ContractValidateException(
            "Do not allow delegate resources to contract addresses");
      }
    }
  }

  private void delegateResource(
      byte[] ownerAddress,
      byte[] receiverAddress,
      long frozenBalance,
      long expireTime,
      boolean isBandwidth,
      Repository repo) {
    byte[] key = DelegatedResourceCapsule.createDbKey(ownerAddress, receiverAddress);

    // insert or update DelegateResource
    DelegatedResourceCapsule delegatedResourceCapsule = repo.getDelegatedResource(key);
    if (delegatedResourceCapsule == null) {
      delegatedResourceCapsule = new DelegatedResourceCapsule(
          ByteString.copyFrom(ownerAddress),
          ByteString.copyFrom(receiverAddress));
    }
    if (isBandwidth) {
      delegatedResourceCapsule.addFrozenBalanceForBandwidth(frozenBalance, expireTime);
    } else {
      delegatedResourceCapsule.addFrozenBalanceForEnergy(frozenBalance, expireTime);
    }
    repo.updateDelegatedResource(key, delegatedResourceCapsule);

  private void validRemainTime(ResourceCode resourceCode, long lockPeriod, long expireTime,
      long now) throws ContractValidateException {
    long remainTime = expireTime - now;
    if (lockPeriod * BLOCK_PRODUCED_INTERVAL < remainTime) {
      throw new ContractValidateException(
          "The lock period for " + resourceCode.name() + " this time cannot be less than the "
              + "remaining time[" + remainTime + "ms] of the last lock period for "
              + resourceCode.name() + "!");
    }
  }
