Audit Report

## Title
Silent tip loss when BridgeHub `add_tip` fails after asset is already burned on AssetHub - (File: `bridges/snowbridge/pallets/system-v2/src/lib.rs`)

## Summary
`snowbridge-pallet-system-frontend::add_tip` unconditionally withdraws and burns/swaps the user's tip asset on AssetHub via `swap_fee_asset_and_burn` before any confirmation that the tip can actually be applied on BridgeHub, then dispatches a `Transact` to `snowbridge-pallet-system-v2::add_tip`. That extrinsic swallows failures from the underlying queue's `AddTip::add_tip` (e.g. `AddTipError::NonceConsumed` / `AddTipError::UnknownMessage`) and always returns `Ok(())`, merely recording the amount into an unconsumed `LostTips` counter instead of reverting or refunding.

## Finding Description
On AssetHub, `Pallet::add_tip` calls `Self::swap_fee_asset_and_burn(who.clone().into(), asset)?`, which either swaps the tip asset for Ether via `T::Swap::swap_exact_tokens_for_tokens` and burns the resulting Ether, or burns the supplied Ether directly via `burn_for_teleport::<T::AssetTransactor>`, debiting the user's real balance immediately [1](#0-0) [2](#0-1) . The resulting `ether_gained` is packaged into an `EthereumSystemCall::AddTip{...}` and dispatched as an `UnpaidExecution`/`Transact` XCM to BridgeHub [3](#0-2) .

On BridgeHub, `snowbridge_pallet_system_v2::Pallet::add_tip` forwards to `InboundQueue::add_tip` or `OutboundQueue::add_tip` depending on `message_id`, but if that call returns an `Err`, the error is not propagated — it is only recorded into `LostTips::<T>` and the extrinsic still returns `Ok(())` [4](#0-3) . The storage comment itself confirms there is no consumer of `LostTips` today ("Capturing the lost tips here supports implementing a recovery method in the future") [5](#0-4) .

The failure conditions are real and reachable in normal operation, not just adversarially:
- Inbound: `AddTip::add_tip` for the inbound queue returns `Err(AddTipError::NonceConsumed)` once `Nonce::<T>::get(nonce)` is true, i.e., once the message has already been processed by `process_message` [6](#0-5) , and `process_message` itself sets `Nonce::<T>::set(nonce)` as soon as the message arrives [7](#0-6) .
- Outbound: `AddTip::add_tip` for the outbound queue returns `Err(AddTipError::UnknownMessage)` once `PendingOrders::<T>` no longer contains the nonce, which happens as soon as `process_delivery_receipt` removes the order after a relayer submits a delivery receipt [8](#0-7) [9](#0-8) .

Because the burn on AssetHub happens before the BridgeHub call is even attempted, and because the `Transact`'s dispatch success is decoupled from the inner `DispatchResult` (which is forced to `Ok(())` regardless), there is no mechanism anywhere in `system-v2`, `system-frontend`, or the queue pallets that reads `LostTips` and refunds or re-credits the user. Confirmed via repo-wide search: `LostTips` is only referenced in `system-v2/src/lib.rs` and its own test file, with no read/claim/refund logic elsewhere in production code.

This matches the pattern of the referenced Caviar bug: value is unconditionally collected from the payer up front based on an optimistic assumption, while the actual crediting step is gated by a condition (nonce not yet consumed / order still pending) that the collection step does not check, and the mismatch is never reconciled.

## Impact Explanation
This is a permanent user-fund loss: a user's real balance is burned on AssetHub with no way to reclaim it if the corresponding relayer-reward-crediting operation on BridgeHub fails due to an ordinary race with relayer/message processing. This aligns with the "permanent user-fund or bridge-state lock" category in the Polkadot SDK impact gate, since asset custody is not conserved and no rightful beneficiary (user, relayer, or `LostTips` claimant) ever receives the burned value.

## Likelihood Explanation
No privileged actor is required; any signed AssetHub account can call `add_tip`. The failure condition (nonce already consumed / order already removed) is a normal outcome of the bridge's expected operation — relayers routinely submit delivery receipts and inbound messages routinely get processed — so a tip submitted for a message that finalizes concurrently or slightly before the `Transact` executes on BridgeHub is a realistic, repeatable, non-adversarial occurrence, not a contrived edge case.

## Recommendation
Either (1) propagate the queue's `AddTipError` from `system-v2::add_tip` so the `Transact` fails, and restructure the AssetHub side so the burn only occurs after BridgeHub confirms the tip was applied (e.g., a reserve/commit pattern or XCM response before burning), or (2) implement the promised recovery path for `LostTips` — a claim extrinsic letting the recorded sender reclaim the lost amount — rather than leaving it as a dead counter.

## Proof of Concept
1. A relayer submits a delivery receipt for outbound nonce `N`, causing `process_delivery_receipt` to remove `PendingOrders::<T>::get(N)` (`bridges/snowbridge/pallets/outbound-queue-v2/src/lib.rs:475`).
2. Concurrently, a user calls `EthereumSystemFrontend::add_tip(origin, MessageId::Outbound(N), asset)` on AssetHub.
3. `swap_fee_asset_and_burn` burns/swaps the user's asset for Ether immediately (`bridges/snowbridge/pallets/system-frontend/src/lib.rs:372-404`).
4. The `Transact` reaches BridgeHub; `system_v2::add_tip` calls `OutboundQueue::add_tip(N, amount)`, which returns `Err(AddTipError::UnknownMessage)` since the order was already removed.
5. `system_v2::add_tip` swallows the error, adds `amount` to `LostTips::<T>::get(sender)`, emits `TipProcessed{success: false}`, and returns `Ok(())`.
6. The user's burned Ether is unrecoverable: no relayer reward was boosted, and `LostTips` has no consumer in the codebase.

		fn swap_fee_asset_and_burn(
			origin: Location,
			fee_asset: Asset,
		) -> Result<u128, DispatchError> {
			let ether_location = T::EthereumLocation::get();
			let (fee_asset_location, fee_amount) = match fee_asset {
				Asset { id: AssetId(ref loc), fun: Fungible(amount) } => (loc, amount),
				_ => {
					tracing::debug!(target: LOG_TARGET, ?fee_asset, "error matching fee asset");
					return Err(Error::<T>::UnsupportedAsset.into());
				},
			};
			if fee_amount == 0 {
				return Ok(0);
			}

			let ether_gained = if *fee_asset_location != ether_location {
				Self::swap_and_burn(
					origin.clone(),
					fee_asset_location.clone(),
					ether_location,
					fee_amount,
				)
				.inspect_err(|&e| {
					tracing::debug!(target: LOG_TARGET, ?e, "error swapping asset");
				})?
			} else {
				burn_for_teleport::<T::AssetTransactor>(&origin, &fee_asset)
					.map_err(|_| Error::<T>::BurnError)?;
				fee_amount
			};
			Ok(ether_gained)
		}

		pub fn add_tip(
			origin: OriginFor<T>,
			sender: AccountIdOf<T>,
			message_id: MessageId,
			amount: u128,
		) -> DispatchResult {
			T::FrontendOrigin::ensure_origin(origin)?;

			let result = match message_id {
				Inbound(nonce) => <T as pallet::Config>::InboundQueue::add_tip(nonce, amount),
				Outbound(nonce) => <T as pallet::Config>::OutboundQueue::add_tip(nonce, amount),
			};

			if let Err(ref e) = result {
				tracing::debug!(target: LOG_TARGET, ?e, ?message_id, ?amount, "error adding tip");
				LostTips::<T>::mutate(&sender, |lost_tip| {
					*lost_tip = lost_tip.saturating_add(amount);
				});
			}

			Self::deposit_event(Event::<T>::TipProcessed {
				sender,
				message_id,
				amount,
				success: result.is_ok(),
			});

			Ok(())
		}

	impl<T: Config> Pallet<T> {
		pub fn process_message(relayer: T::AccountId, message: Message) -> DispatchResult {
			// Verify that the message was submitted from the known Gateway contract
			ensure!(T::GatewayAddress::get() == message.gateway, Error::<T>::InvalidGateway);

			let (nonce, relayer_fee) = (message.nonce, message.relayer_fee);

			// Verify the message has not been processed
			ensure!(!Nonce::<T>::get(nonce), Error::<T>::InvalidNonce);

			// Mark message as received
			Nonce::<T>::set(nonce);

			let message_id = T::MessageProcessor::process_message(relayer.clone(), message)
				.map_err(|e| match e {
					MessageProcessorError::ProcessMessage(e) => e,
					MessageProcessorError::ConvertMessage(e) => Error::<T>::from(e).into(),
					MessageProcessorError::SendMessage(e) => Error::<T>::from(e).into(),
				})?;

			// Pay relayer reward
			let tip = Tips::<T>::take(nonce).unwrap_or_default();
			let total_tip = relayer_fee.saturating_add(tip);
			if total_tip > 0 {
				T::RewardPayment::register_reward(&relayer, T::DefaultRewardKind::get(), total_tip);
			}

			// Emit event with the message_id
			Self::deposit_event(Event::MessageReceived { nonce, message_id });

			Ok(())
		}
