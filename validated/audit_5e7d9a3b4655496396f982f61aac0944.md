### Title
Reward index divides emissions by `DebtToken.totalSupply()` (principal only) but accrues against `balanceOf()` (principal + accrued interest), inflating borrower rewards and draining the distributor - ([File: contracts/RewardsDistributor.sol](contracts/RewardsDistributor.sol))

### Summary
`RewardsDistributor._calculateTokenIndex` grows the per-token reward index using `token_.totalSupply()` as the denominator, while `_calculateTokenDelta` multiplies the index delta by `token_.balanceOf(account_)`. For `DepositToken` these two measures are consistent. For `DebtToken` they are not: `balanceOf` returns `principalOf(account).rayMul(debtIndex)` — an interest-growing balance — while `totalSupply` tracks issued principal and does not include accrued interest. The same misalignment as the reference bug (index computed on one supply basis, applied to balances on another) causes borrowers to be allocated more reward than `tokenSpeed` emits, letting early claimers drain reward tokens owed to other holders.

### Finding Description
In `contracts/RewardsDistributor.sol:204-207`, the index delta is `_tokensAccrued.wadDiv(_totalSupply)` where `_totalSupply = token_.totalSupply()`. In `contracts/RewardsDistributor.sol:229-230`, each account's delta is `token_.balanceOf(account_).wadMul(_deltaIndex)`.

`RewardsDistributor` registers both `DepositToken` and `DebtToken` as reward-bearing tokens (`onlyIfTokenExists`, lines 91-97). For a `DebtToken` with speed > 0:

- `Σ balanceOf(account)` = `(Σ principalOf) * debtIndex > totalSupply` whenever `debtIndex > 1e27` (interest has accrued, which is the normal state for any active market).
- Therefore `Σ _tokensDelta = Σ balanceOf * deltaIndex > totalSupply * deltaIndex = _tokensAccrued`.

Every account accrues `balanceOf`-weighted rewards while the index only emitted `speed * Δt` total. The overshoot factor grows with `debtIndex` — the longer a debt market lives, the larger the divergence. All accrued amounts flow into the shared `tokensAccruedOf` map (lines 261-265) and are paid from the distributor's single `rewardToken` balance (lines 248-256), which is funded only at the real emission rate.

Attack path (unprivileged, public entry points only):
1. Attacker borrows via `DebtToken.issue`/`Pool` using an attacker-supplied deposit token position — `issue` is callable by anyone through the pool's public mint flow.
2. Time passes; `debtIndex` grows via `accrueInterest`, inflating `balanceOf(attacker)` beyond the principal that `totalSupply` reflects.
3. Attacker calls `claimRewards(attacker)` (public, lines 134-168) and receives `balanceOf * deltaIndex`, i.e., more than the pro-rata share the emission rate intended. Because `claimRewards` iterates all `tokens` and pays out `tokensAccruedOf`, inflated debt-token accrual consumes rewards earmarked for deposit-token holders too.
4. `_transferRewardIfEnoughTokens` pays in full while balance suffices and silently skips when it doesn't, so honest users who claim later get zero — unclaimed yield is stolen.

Invariant broken: reward accrual conservation (`Σ account rewards ≤ emitted rewards`).

### Impact Explanation
Direct theft of unclaimed yield. Borrower accounts are over-credited relative to actual emissions by a factor equal to `debtIndex` (compounding over the market's lifetime). Since all tokens share one reward pool, first-come claimers — anyone can call `claimRewards(account)` for any account — drain the `rewardToken` balance, permanently depriving deposit-token and debt-token holders of accrued rewards. No privileged role, governance action, or oracle manipulation is required: an unprivileged borrower with any collateral position reproduces it.

### Likelihood Explanation
High. The discrepancy requires only an active `DebtToken` reward speed and non-zero accrued interest (`debtIndex > RAY`), the default state of any live debt market. Note this does not affect `DepositToken` indexes, where `balanceOf`/`totalSupply` are consistent. One caveat: the exact divergence magnitude depends on `DebtToken.totalSupply` semantics — the finding holds where `totalSupply` is principal-denominated while `balanceOf` is index-scaled; the RewardsDistributor side of the mismatch is confirmed at lines 204-207 and 229-230.

### Recommendation
Make the index denominator consistent with the accrual basis. Either:
- Use `Σ balanceOf` as denominator — e.g., expose `totalSupply()` on `DebtToken` that includes accrued interest (`principalTotal.rayMul(debtIndex)`), or
- Accrue rewards on `principalOf(account)` to match a principal-only `totalSupply`.

Pick one convention and enforce it in both `_calculateTokenIndex` and `_calculateTokenDelta` for every registered token type.
