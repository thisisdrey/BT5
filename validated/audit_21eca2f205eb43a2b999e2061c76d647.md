### Title
`pallet-scarcity` transfer/burn trust a stale, origin-embedded NFT snapshot instead of re-reading storage, letting one `AsScarcity` authorization mint duplicate feeless settlements via `pallet_utility::batch` - (File: `substrate/frame/scarcity/src/lib.rs`, `substrate/frame/scarcity/src/extension.rs`)

### Summary
The SEDA bug's core broken invariant was: a per-message "is this eligible for free execution" check that inspects only the message's *content*, with no per-transaction/per-block de-duplication, so an attacker can bundle the same free-eligible message many times and get unmetered, repeated state mutation. The local analog is `pallet-scarcity`'s `AsScarcity` transaction extension plus its feeless `transfer`/`burn` calls: the extension authorizes and removes an NFT from storage **once per extrinsic** at `prepare` time, but `transfer`/`burn` dispatch logic reads the authorized NFT out of the *origin value itself* (`Origin::Nft { owner, nft }`) rather than re-checking current chain storage. When this signed, `AsScarcity`-authorized origin is reused for multiple inner calls (e.g. via `pallet_utility::batch`/`batch_all`), each inner `transfer` independently re-inserts the *same* cloned `Nft` record to a different destination, for free (`Pays::No`), duplicating an NFT across multiple owners from a single authorization.

### Finding Description
`AsScarcity::validate` reads the caller's NFT from `NftsByOwner` and swaps the extrinsic origin to `Origin::Nft { owner, nft }` [1](#0-0) . `AsScarcity::prepare` then removes the NFT from `NftsByOwner` exactly once, for the whole extrinsic, and stashes it in `Pre::UsingNft` for potential rollback [2](#0-1) .

Critically, the dispatchables that consume this origin do **not** re-verify current storage state; they trust the `Nft` value carried inside the origin:

```rust
pub fn transfer(origin: OriginFor<T>, to: T::AccountId) -> DispatchResultWithPostInfo {
    let Ok(Origin::Nft { owner, nft }) = origin.into() else { ... };
    ...
    NftsByOwner::<T>::insert(&to, nft.clone());
    Instances::<T>::insert(nft.instance, &to);
    ...
    Ok(Pays::No.into())
}
``` [3](#0-2) 

and `burn` similarly consumes only the `nft` embedded in the origin, marked feeless via `#[pallet::feeless_if(... is_nft_origin(origin) ...)]` [4](#0-3) .

`Origin::Nft` is a plain, `Clone`-able enum value, not a storage handle [5](#0-4) . Any FRAME dispatch wrapper that reuses/clones the already-transformed origin for more than one inner dispatch (the canonical example being `pallet_utility::batch`/`batch_all`/`force_batch`, which iterate a `Vec<RuntimeCall>` and dispatch each with `origin.clone()`) will hand the *same* `Nft{owner, nft}` snapshot to every inner call. Because `transfer`/`burn` never re-read `NftsByOwner`/`Instances` to confirm the NFT is still where the extension left it, each inner call in the batch independently succeeds, each one for free (`Pays::No`), and each one calls `NftsByOwner::<T>::insert(&to, nft.clone())` with a distinct `to`. This corrupts the pallet's core invariant documented in its own module docs — "each purse key can hold at most one NFT" / "one NFT per owner key — the coinage model" [6](#0-5) [7](#0-6)  — by minting the same permanent `InstanceId` into multiple purse keys simultaneously, and doing so completely fee-free since both feeless dispatchables were designed to only require a single upfront `AsScarcity` authorization.

This mirrors the SEDA root cause precisely: a stateless "is this call eligible to run for free" check (`is_nft_origin`) that does not account for the call being executed multiple times off a single authorization/validation pass, combined with a public dispatch wrapper (`batch`) that lets an unprivileged, ordinary signed user replay the authorized action many times in one atomic unit.

### Impact Explanation
An attacker holding a single Scarcity NFT can, in one signed, `AsScarcity`-authorized extrinsic wrapped in `pallet_utility::batch_all`, duplicate that one instance into an arbitrary number of purse keys — each insertion overwrites `Instances::<T>` with a different current owner while leaving stale entries in `NftsByOwner` for previously-targeted destinations, corrupting the "each purse key holds at most one NFT" accounting invariant, and does so entirely fee-free (`Pays::No` on every inner call). This is a duplicate-settlement / unbacked-duplication bug affecting on-chain asset accounting, and because every inner dispatch is marked `Pays::No`, it is also unmetered work that a validator must execute repeatedly for free, directly matching the "public underpriced work that degrades block production" impact class.

### Likelihood Explanation
No privileged actor, governance, relayer, or malicious node/validator is required — only an ordinary account that owns one Scarcity NFT and constructs a normal signed extrinsic using the standard, publicly documented `AsScarcity` + `pallet_utility::batch_all` combination. The vulnerable code path (`transfer`/`burn` trusting the origin-embedded `Nft` rather than storage) is reachable by any account with a live NFT and requires no special preconditions beyond runtime inclusion of both `pallet-scarcity` and `pallet-utility` with the Scarcity call routable through `RuntimeCall` (both are present together in the kitchensink/node runtime referenced by this repo's development runtime wiring).

### Recommendation
Make `transfer` and `burn` re-validate current chain state instead of trusting the value embedded in the origin: re-fetch `NftsByOwner::<T>::get(&owner)` inside the dispatchable and confirm it still matches the `instance`/`state_nonce` that `AsScarcity` authorized, or have `AsScarcity::prepare` mark the purse as "already consumed this block" so a second consumption of the same authorized origin within a batch is rejected. Alternatively, disallow the Scarcity feeless calls from executing under a cloned/replayed origin at all — e.g. reject `transfer`/`burn` when call depth/origin reuse indicates it is being dispatched more than once per extension `prepare` invocation.

### Proof of Concept
1. Attacker owns NFT `nft` (instance `I`, state_nonce `N`) at purse key `A`.
2. Attacker submits one extrinsic: outer call `Utility::batch_all([Scarcity::transfer(to=B), Scarcity::transfer(to=C)])`, signed with the `AsScarcity` extension set to `AsNft { instance: I, state_nonce: N }`.
3. `AsScarcity::validate`/`prepare` runs once for the whole extrinsic: it reads `nft` from `NftsByOwner[A]`, removes it from storage, and sets the origin to `Origin::Nft{owner: A, nft}` [8](#0-7) .
4. `Utility::batch_all` dispatches each inner call with a clone of this same origin.
5. First `transfer(to=B)` executes: inserts `nft` into `NftsByOwner[B]`, `Instances[I] = B`, returns `Pays::No` [9](#0-8) .
6. Second `transfer(to=C)` executes with the *same* cloned origin (still containing the original `nft` value, unaffected by step 5's storage writes): inserts `nft` into `NftsByOwner[C]`, `Instances[I] = C`, again `Pays::No`.
7. Result: `NftsByOwner[B]` and `NftsByOwner[C]` both now hold instance `I` (only `Instances[I]` points to `C`, but `B`'s stale record still exists and passes `is_nft_origin`/subsequent `AsScarcity` checks against `NftsByOwner[B]` until independently cleaned up), all for the price of a single `AsScarcity`-authorized, feeless batch — violating the one-NFT-per-purse invariant without paying any transaction fee for the duplicate operation.

		#[pallet::call_index(3)]
		#[pallet::weight(T::WeightInfo::transfer())]
		#[pallet::feeless_if(|origin: &OriginFor<T>, _to: &T::AccountId| -> bool {
			Pallet::<T>::is_nft_origin(origin)
		})]
		pub fn transfer(origin: OriginFor<T>, to: T::AccountId) -> DispatchResultWithPostInfo {
			let Ok(Origin::Nft { owner, nft }) = origin.into() else {
				return Err(DispatchError::BadOrigin.into());
			};
			ensure!(to != owner, Error::<T>::SelfTransfer);
			ensure!(!NftsByOwner::<T>::contains_key(&to), Error::<T>::AddressOccupied);

			let from = owner;
			let state_nonce =
				nft.state_nonce.checked_add(1).ok_or(Error::<T>::StateNonceOverflow)?;
			let nft = Nft { last_moved: T::UnixTime::now().as_secs(), state_nonce, ..nft };
			NftsByOwner::<T>::insert(&to, nft.clone());
			Instances::<T>::insert(nft.instance, &to);
			Self::deposit_event(Event::Transferred { instance: nft.instance, from, to });
			Ok(Pays::No.into())
		}
