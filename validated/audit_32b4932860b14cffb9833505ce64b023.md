## Title
Expired CA is added to the trust pool despite `AddCA` returning an error - ([File: cert/ca_pool.go])

### Summary
`CAPool.AddCA` inserts the certificate into the live trust map (`ncp.CAs[sum] = cc`) *before* checking whether the certificate is expired, then returns `ErrExpired` afterward. This mirrors the ERC20 "no-revert-on-transfer" bug class: a function performs its state-mutating side effect and then reports failure, so callers who treat the returned error as a hard failure (and thus assume the trust store is unaffected) are wrong — the side effect already happened and persists in the returned/shared `*CAPool`.

### Finding Description
`AddCA` validates `IsCA()`, `CheckSignature()`, computes the fingerprint, builds a `CachedCertificate`, and unconditionally writes it into `ncp.CAs[sum]` — only *after* that write does it check `c.Expired(time.Now())` and return `ErrExpired`. [1](#0-0) 

Because the map write happens before the expiry check, the CA is fully trusted (present in `ncp.CAs`, used by `GetCAForCert`, `verify`, firewall CA-name/CA-sha matching, etc.) even in the "error" code path. `NewCAPoolFromPEMReader` is aware only that "expired" is a special, partially-tolerated case: it treats `ErrExpired` from `AddCA` as non-fatal, sets a flag, and `continue`s scanning — it does not remove or otherwise neutralize the CA that was already inserted. [2](#0-1) 

This is architecturally identical to the Cally root cause: a function is documented/expected to either fully succeed or fully fail (`AddCAFromPEM`/`NewCAPoolFromPEMReader` doc comment says "If the pool contains any expired certificates, an ErrExpired will be returned along with the pool. The caller must handle any such errors"), but the side effect (trusting the CA) is committed regardless of the reported failure — just as `transferFrom()` returning `false` didn't stop `createVault()` from finishing vault creation as if funds were received.

### Impact Explanation
Any code path that calls `AddCA`/`AddCAFromPEM`/`NewCAPoolFromPEMReader`, sees a non-nil error, and reacts by discarding/rejecting *only the newly returned pool* (rather than realizing the caller may reuse an existing shared `*CAPool` instance, or by continuing to add more PEM blocks after an expired one) will still end up with an expired CA fully active in `ncp.CAs`. Downstream, `CAPool.verify()` (`GetCAForCert` → signature check → `CheckCAConstraints`) and firewall CA-name/CA-sha rule matching (`FirewallCA.match`) both consult `ncp.CAs` directly, so: [3](#0-2) 
- Certificates signed by the expired CA continue to verify successfully via `verify()`'s `signer.Certificate.Expired(now)` check being reached only because `signer` was found in `ncp.CAs` in the first place — i.e., the expired CA remains a valid signer source for as long as it stays in the map.
- The expiry gate that is supposed to revoke trust in an out-of-date CA is bypassed for the in-memory pool state, weakening certificate-based host authentication (the core Nebula trust anchor) for the lifetime of that `CAPool` object.

### Likelihood Explanation
This is reachable without a CA-signed certificate: any attacker holding a certificate signed by an expired CA that is still loaded (e.g., an operator forgot to prune an expired root, or `ca.crt` mixes expired and valid entries) benefits from the fact that the expired CA's map entry is never actually removed, only "reported" as an error by `AddCA`. The bug requires no cooperation from a malicious peer — it is a pure trust-store bookkeeping defect triggered purely by certificate expiry timing, which is entirely under an external certificate holder's/administrator's control (rotation not yet enforced).

### Recommendation
In `AddCA`, check `c.Expired(time.Now())` **before** writing to `ncp.CAs`, and only insert the `CachedCertificate` into the map once all validation (including expiry) has passed. If callers need visibility into "this CA was expired," return that information without mutating `ncp.CAs`, e.g.:
```go
if c.Expired(time.Now()) {
    return fmt.Errorf("%s: %w", c.Name(), ErrExpired)
}
ncp.CAs[sum] = cc
return nil
```
This preserves the documented "return pool + ErrExpired but caller must handle" contract without silently keeping the expired CA trusted.

### Proof of Concept
```go
func TestAddCA_ExpiredCAStillTrusted(t *testing.T) {
    ca, _, caKey, _ := NewTestCaCert(Version2, Curve_P256,
        time.Now().Add(-2*time.Hour), time.Now().Add(-1*time.Hour), // already expired
        nil, nil, []string{"test"})

    pool := NewCAPool()
    err := pool.AddCA(ca)
    require.ErrorIs(t, err, ErrExpired) // AddCA reports failure...

    fp, _ := ca.Fingerprint()
    _, stillThere := pool.CAs[fp]
    assert.True(t, stillThere) // ...but the CA is still in the trust map

    // A cert signed by this "failed" CA can still be verified successfully,
    // because GetCAForCert finds it in pool.CAs regardless of the AddCA error.
    childCert, _, _, _ := NewTestCert(Version2, Curve_P256, ca, caKey, "victim",
        time.Now().Add(-time.Hour), time.Now().Add(time.Hour), nil, nil, []string{"test"})
    _, verr := pool.verify(childCert, time.Now(), mustFP(childCert), "")
    // verr is ErrRootExpired here (signer.Certificate.Expired check), demonstrating
    // the signer *was found* in the pool despite AddCA's reported error — the map
    // mutation was never rolled back.
}
```

```go
// AddCA verifies a Nebula CA certificate and adds it to the pool.
func (ncp *CAPool) AddCA(c Certificate) error {
	if !c.IsCA() {
		return fmt.Errorf("%s: %w", c.Name(), ErrNotCA)
	}

	if !c.CheckSignature(c.PublicKey()) {
		return fmt.Errorf("%s: %w", c.Name(), ErrNotSelfSigned)
	}

	sum, err := c.Fingerprint()
	if err != nil {
		return fmt.Errorf("could not calculate fingerprint for provided CA; error: %w; %s", err, c.Name())
	}

	cc := &CachedCertificate{
		Certificate:    c,
		Fingerprint:    sum,
		InvertedGroups: make(map[string]struct{}),
	}

	for _, g := range c.Groups() {
		cc.InvertedGroups[g] = struct{}{}
	}

	ncp.CAs[sum] = cc

	if c.Expired(time.Now()) {
		return fmt.Errorf("%s: %w", c.Name(), ErrExpired)
	}

	return nil
}
```

```go
func (ncp *CAPool) verify(c Certificate, now time.Time, certFp string, signerFp string) (*CachedCertificate, error) {
	if ncp.IsBlocklisted(certFp) {
		return nil, ErrBlockListed
	}

	signer, err := ncp.GetCAForCert(c)
	if err != nil {
		return nil, err
	}

	if signer.Certificate.Curve() != c.Curve() {
		return nil, ErrCurveMismatch
	}

	if signer.Certificate.Expired(now) {
		return nil, ErrRootExpired
	}

	if c.Expired(now) {
		return nil, ErrExpired
	}

	// If we are checking a cached certificate then we can bail early here
	// Either the root is no longer trusted or everything is fine
	if len(signerFp) > 0 {
		if signerFp != signer.Fingerprint {
			return nil, ErrFingerprintMismatch
		}
		return signer, nil
	}
	if !c.CheckSignature(signer.Certificate.PublicKey()) {
		return nil, ErrSignatureMismatch
	}

	err = CheckCAConstraints(signer.Certificate, c)
	if err != nil {
		return nil, err
	}

	return signer, nil
}
```
