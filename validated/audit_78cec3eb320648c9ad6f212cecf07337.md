### Title
RewardsDistributor computes reward deltas on interest-grown `DebtToken.balanceOf`, over-crediting passive debt holders - ([File: contracts/RewardsDistributor.sol])

### Summary
CVE-2017-5462 is a state-carry flaw: the NSS DRBG's internal state `V` fails to carry bits forward on update, so each step's output does not reflect accumulated prior state. The Metronome analog is in `RewardsDistributor._calculateTokenDelta`: reward deltas are computed as `token_.balanceOf(account_) * deltaIndex` using the **current** balance, but for `DebtToken`, `balanceOf` grows passively with accrued interest. The distributor "carries" only the index delta, not the per-interval balance, so interest accrued over the whole window is retroactively rewarded as if the grown balance existed the entire time.

### Finding Description
`claimRewards` / `updateBeforeMintOrBurn` / `updateBeforeTransfer` funnel into `_updateTokensAccruedOf`, which calls `_calculateTokenDelta` (`contracts/RewardsDistributor.sol:217-231`):

```solidity
uint256 _deltaIndex = _tokenIndex - _accountIndex;
_tokensDelta = token_.balanceOf(account_).wadMul(_deltaIndex);
```

For a `DebtToken`, `balanceOf` returns `principalOf[account] * debtIndex / debtIndexOf[account]` (`contracts/DebtToken.sol:196-206`), which increases monotonically as `accrueInterest` grows `debtIndex` (`contracts/DebtToken.sol:551-566`). The distributor's checkpoints (`accountIndexOf`, `tokenStates`) only update when the token contract calls `updateBeforeMintOrBurn`/`updateBeforeTransfer` or when the user claims. A user who performs no mint/burn/repay keeps a stale `accountIndexOf` while their `balanceOf` keeps compounding. When they finally call `claimRewards(account)`, the entire index delta since the last checkpoint is multiplied by the inflated current balance, over-crediting them relative to an identical user whose balance was checkpointed more frequently. The excess is paid from the shared `rewardToken` balance in `_transferRewardIfEnoughTokens` (`contracts/RewardsDistributor.sol:248-256`).

Reachability: an unprivileged EOA deposits collateral via `DepositToken.deposit`, issues debt via `DebtToken.issue`, then simply waits and calls `claimRewards`. No privileged role, oracle manipulation, or malicious contract is required; no modifier (`nonReentrant`, `onlyIfTokenExists`, `onlyIfDistributorExists`) blocks it, and the flaw worsens with higher `interestRate` and longer gaps between checkpoints.

### Impact Explanation
Direct theft of unclaimed yield: the attacker extracts more `rewardToken` than the fair per-interval accrual, draining the distributor at the expense of other depositors/borrowers. The over-credit equals roughly `principal * (debtIndexGrowth - 1) * indexDelta`, scaling with APR and checkpoint staleness.

### Likelihood Explanation
Requires only a debt position on a reward-bearing `DebtToken` and patience; every borrower passively accrues the over-credit, and an attacker maximizes it by avoiding any interaction that triggers `updateBeforeMintOrBurn`. Medium likelihood: reward speed must be nonzero and `rewardToken` must be funded, both deployed-configuration facts.

### Recommendation
In `_calculateTokenDelta`, cap the balance used for `DebtToken` rewards to `principalOf[account]` (interest already accrues to the protocol feeCollector, not the borrower), or force a rewards checkpoint on every `accrueInterest`-driven state change. Alternatively, snapshot balances per epoch like Compound's Comp-style accrual on every index update.

### Proof of Concept
```solidity
// Foundry fork test sketch
function test_rewardOvcreditOnGrownDebt() public {
    // setup: pool, depositToken (WBTC), debtToken (msUSD) with speed > 0 set by governor
    // attacker deposits collateral and issues debt once (seeds accountIndexOf)
    depositToken.deposit(1e8, attacker);
    debtToken.issue(10_000e18, attacker);           // triggers updateBeforeMintOrBurn

    // let reward index AND debt index grow; attacker never touches position again
    vm.warp(block.timestamp + 365 days);

    uint256 balGrown = debtToken.balanceOf(attacker); // principal * debtIndex/debtIndexOf > principal
    uint256 principal = debtToken.principalOf(attacker);
    assertGt(balGrown, principal);

    // claim: deltaIndex multiplied by grown balance
    distributor.claimRewards(attacker);
    uint256 got = rewardToken.balanceOf(attacker);

    // fair value would use time-weighted balance < balGrown for the whole window
    uint256 fair = principal.wadMul(indexNow - indexAtIssue); // lower bound on fair accrual
    assertGt(got, fair); // attacker stole yield proportional to accrued interest
}
```
