### Title
`VotePacketReceiver::buffer_packet_batch` never checks `packet.meta().discard()`, allowing sigverify-rejected/forged vote packets to reach `vote_storage` - (File: core/src/banking_stage/vote_packet_receiver.rs)

### Summary
`SigVerifyWorkerPool::run_transaction_task` only decides whether to forward an *entire batch* based on whether it contains at least one packet that passed `ed25519_verify_serial`/`reject_non_vote`; it does not strip out the individual packets in that batch that were marked `discard=true` by signature/vote-shape verification. `VotePacketReceiver::buffer_packet_batch`, which consumes these forwarded batches on the banking side, iterates every packet in the batch and attempts to sanitize/insert it into `VoteStorage` without ever checking `packet.meta().discard()`. This lets a signature-invalid or non-vote packet slip into `vote_storage` as long as it happens to be batched alongside one legitimately-verified vote packet.

### Finding Description
The TPU-vote QUIC path is exposed to unstaked/unprivileged senders (it uses `spawn_simple_qos_server`/`SimpleQosConfig` rate-limiting rather than the stake-weighted QoS used for the main TPU path) [1](#0-0) . Raw packets go from the streamer into `SigVerifyWorkerPool`'s `tpu_vote_receiver` channel [2](#0-1) .

In `run_transaction_task`, `ed25519_verify_serial` is called with `reject_non_vote=true`; per-packet, `verify_packet` sets `discard=true` on any packet that is either not vote-shaped or whose ed25519 signature fails to verify [3](#0-2) . Crucially, the *forwarding decision* is made at the batch level: the whole `PacketBatch` (including any individually-discarded packets) is sent to `state.banking_stage_sender` as long as `num_valid_packets` for the batch is nonzero [4](#0-3) . Discarded packets are never removed from the batch before it is sent.

On the receiving side, `VotePacketReceiver::buffer_packet_batch` iterates `packet_batch.iter()` and, for every packet, calls `packet.data(..)` and `SanitizedTransactionView::try_new_sanitized(...)`, then (if parsing succeeds and it is not filtered by `filter_keys`) calls `vote_storage.insert_packet(...)`. At no point in this function is `packet.meta().discard()` checked [5](#0-4) . This is inconsistent with the rest of the codebase, where discard is always explicitly checked before further processing (e.g. `verify_packet`, `apply_priority_floor_to_batch`, `dedup_packets_and_count_discards`).

Further compounding this, `LatestValidatorVote::new_from_view` (called from `insert_packet`) does not perform any cryptographic signature check either — it only verifies that the claimed signer occupies a signer-index slot (`signed = index < vote.num_required_signatures()`), a purely structural/positional check [6](#0-5) . Actual ed25519 verification is expected to have already happened upstream in sigverify — but as shown above, that guarantee does not hold for every packet in a forwarded batch.

Exploit flow: an attacker crafts a packet that (a) parses successfully via `SanitizedTransactionView::try_new_sanitized`, (b) structurally looks like a legacy/TowerSync vote instruction naming a real (publicly known) validator's `vote_pubkey`/`authorized_voter_pubkey` in the correct signer-index slots, but (c) carries an invalid/garbage ed25519 signature (attacker does not have the private key). Sent alone, such packets fail `ed25519_verify_serial` and (if the whole batch is 100% attacker garbage) `num_valid_packets == 0`, so the batch is dropped and never reaches banking. However, on a live leader, real vote traffic is continuously arriving on the same TPU-vote port; if the streamer batches multiple senders' packets together within the same receive window, a batch can contain both a legitimate voter's valid packet and the attacker's forged packet. Because forwarding is an all-or-nothing decision per batch based on `num_valid_packets > 0`, the forged (still-discarded) packet rides along into banking, where `buffer_packet_batch` processes it without checking `discard()` and inserts it into `vote_storage`, keyed by the real validator's `vote_pubkey`.

### Impact Explanation
This is a verification-bypass condition: unstaked/unauthenticated attacker input can be inserted into `VoteStorage`'s per-validator latest-vote cache without having passed real ed25519 signature verification, provided it is co-batched with legitimate traffic. Because `insert_vote` overwrites the single cached "latest vote" entry per `vote_pubkey`, a forged entry can clobber/compete with a legitimate validator's genuine latest vote for that slot, potentially causing the leader to record/pack a bogus/stale vote transaction on behalf of a real validator, or to waste banking-stage cycles processing/attempting-to-execute an unauthenticated vote transaction. This falls under the "verification bypass" bounty category referenced in the rules, and secondarily contributes to unnecessary buffering/processing load on the vote path.

### Likelihood Explanation
Exploitability depends on whether the underlying streamer/QUIC packet batches ever contain packets from more than one distinct sender/connection in the same `PacketBatch` — if batches are strictly per-connection, this bug is unreachable by an unstaked attacker acting alone (their own batches would have `num_valid_packets == 0` and be dropped entirely). This detail could not be conclusively confirmed within the available context (the exact batching/receive logic in the low-level streamer/QUIC receiver was not retrievable). If batches are shared across senders (a common pattern for UDP/QUIC packet coalescing), the attack is highly feasible and repeatable: the attacker only needs to spray forged vote-shaped packets continuously at the TPU-vote port (subject to the `SimpleQosConfig` rate limit of `MAX_VOTES_PER_SECOND = 20` per the QoS config) and rely on natural co-batching with genuine validator vote traffic, which is constant on a live leader.

### Recommendation
In `VotePacketReceiver::buffer_packet_batch`, explicitly skip any packet where `packet.meta().discard()` is true before attempting to sanitize/insert it, matching the pattern used elsewhere in the codebase (e.g., `forwarding_stage.rs`'s `initial_packet_meta_filter`). Additionally, consider stripping/filtering discarded packets out of a `PacketBatch` in `SigVerifyWorkerPool::run_transaction_task` before forwarding to banking, rather than relying purely on the batch-level `num_valid_packets > 0` check, so no downstream consumer can accidentally process an unverified packet.

    // If this packet was already marked as discard, drop it
    if packet.meta().discard() {
        return false;
    }

    let Some(data) = packet.data(..) else {
        return false;
    };

    let (is_simple_vote_tx, verified) = {
        let Ok(view) = SanitizedTransactionView::try_new_sanitized(data, &sanitize_config()) else {
            return false;
        };

        if !enable_tx_v1 && matches!(view.version(), TransactionVersion::V1) {
            return false;
        }

        let is_simple_vote_tx = is_simple_vote_transaction_view(&view);
        if reject_non_vote && !is_simple_vote_tx {
            (is_simple_vote_tx, false)
        } else {
            let signatures = view.signatures();
            if signatures.is_empty() {
                (is_simple_vote_tx, false)
            } else {
                let message = view.message_data();
                let static_account_keys = view.static_account_keys();
                let verified = signatures
                    .iter()
                    .zip(static_account_keys.iter())
                    .all(|(signature, pubkey)| signature.verify(pubkey.as_ref(), message));
                (is_simple_vote_tx, verified)
            }
        }
    };

    if is_simple_vote_tx {
        packet.meta_mut().flags |= PacketFlags::SIMPLE_VOTE_TX;
    }

    verified

    fn buffer_packet_batch(
        &self,
        packet_batch: &BankingPacketBatch,
        sanitize_config: &SanitizeConfig,
        vote_storage: &mut VoteStorage,
        vote_source: VoteSource,
        slot_metrics_tracker: &mut LeaderSlotMetricsTracker,
        stats: &mut ReceiveAndBufferStats,
    ) {
        stats.num_packets_received += packet_batch.len();

        for packet in packet_batch.iter() {
            let Some(packet_data) = packet.data(..) else {
                continue;
            };

            match SanitizedTransactionView::try_new_sanitized(
                packet_bytes(packet, packet_data),
                sanitize_config,
            ) {
                Ok(packet) => {
                    if self.should_filter_packet(&packet) {
                        stats.packet_stats.filtered_account_key_count += 1;
                        continue;
                    }

                    stats.num_buffered_packets += 1;
                    let vote_insertion_metrics = vote_storage.insert_packet(vote_source, packet);
                    slot_metrics_tracker.accumulate_vote_insertion_metrics(&vote_insertion_metrics);
                    stats.dropped_packets_count += vote_insertion_metrics.total_dropped_packets();
                }
                Err(err) => {
                    stats.errors += 1;
                    match err {
                        TransactionViewError::AddressLookupMismatch => {}
                        TransactionViewError::ParseError | TransactionViewError::SanitizeError => {
                            stats.packet_stats.failed_sanitization_count += 1
                        }
                    }
                }
            }
        }
    }
