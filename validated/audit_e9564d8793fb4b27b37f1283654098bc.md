### Title
Relay-forwarding replay window was not advanced on relayed frames, allowing indefinite replay/forgery of forwarded traffic - ([File: outside.go], historically in `handleOutsideRelayPacket`, fixed per CHANGELOG.md)

### Summary
The CHANGELOG documents (and the current e2e test `TestRelayReplayProtection` guards against regressing) a bug where a `ForwardingType` relay authenticated the AEAD tag on a relayed `MessageRelay` frame but never called the replay-window `Update()` step, only `Check()`. This is directly analogous to the ERC777 report: a piece of state that is scheduled to be updated (the replay window / "new tokens") was recognized during a "read" path (`Check`, analogous to a balance getter) but the corresponding "commit" step (`Update`, analogous to `consolidateBalanceOf`) was skipped in that specific code path, so the artifact (packet) could be reused indefinitely.

### Finding Description
`ConnectionState.VerifyRelay` in [1](#0-0)  is the AEAD-verification-only path used by forwarding relays to authenticate a relayed frame without decrypting it. It performs `window.Check()` before verifying the AEAD tag and `window.Update()` after — when this is called correctly, the replay window is both checked and advanced. The regression fixed in the changelog was that `handleOutsideRelayPacket` authenticated the frame (verified the tag) but never advanced the replay window, so `Check()` would keep returning true for the same message counter on every replay, and the relay would keep forwarding the same captured frame to the terminal peer indefinitely. This is captured by the regression test: [2](#0-1) 

The test explicitly forwards a frame once, replays it 3 more times, and asserts the relay forwards `0` of the replays: [3](#0-2) 

And the CHANGELOG entry confirming this was a real fix, not merely a test artifact: [4](#0-3) 

The bug is reachable by any peer capable of forwarding traffic through a relay node — no CA-signed certificate forgery is required by the *attacker performing the replay*, since replaying a previously captured, validly-signed relay frame requires only network position/capture capability (classic replay attack surface), matching the "no CA-signed certificate" reachability constraint in the rules (the attacker doesn't need to *possess* a valid cert themselves — they only need to capture and resend traffic that a relay node processes).

### Impact Explanation
If unfixed, an on-path attacker (or a compromised relay peer with just network visibility into UDP traffic destined for the relay) could indefinitely replay a captured relay frame, causing the relay to repeatedly re-forward stale encrypted traffic to the terminal peer. Depending on payload content this enables traffic replay/duplication (e.g., resending old commands/data), a form of forged traffic re-delivery within the overlay, and volumetric abuse of the relay/terminal peer (remote state poisoning / resource exhaustion via unlimited forwarding of a single captured frame).

### Likelihood Explanation
This is high-likelihood in relay-enabled deployments (`relay.am_relay`/`relay.use_relays`) since capturing a UDP frame in transit and re-injecting it is trivial for anyone with visibility into the path to/from the relay (e.g., a NAT hop, a malicious or compromised network intermediary), and the flaw required no cryptographic break — only omission of the anti-replay `Update()` call in one specific relay code path.

### Recommendation
Ensure every code path that authenticates a relayed frame (both `VerifyRelay`/decrypt paths) always advances the replay window via `Update()` immediately after successful AEAD authentication, mirroring what `Decrypt` does at [5](#0-4) . Keep the regression test `TestRelayReplayProtection` in [6](#0-5)  as a permanent guard, and audit all other callers of `Check`/`Update` (e.g., any new relay or fast-path packet handlers) to confirm the check-then-commit pattern is never split across a return boundary that skips `Update`.

### Proof of Concept
1. Stand up `me` → `relay` → `them` with `relay.use_relays`/`relay.am_relay` as in `TestRelayReplayProtection`.
2. Establish the relayed tunnel bidirectionally.
3. Capture one legitimate relay frame (`header.Message`/`header.MessageRelay`) sent from `me` toward `relay`.
4. Re-inject the exact same captured UDP packet into `relay` 3+ times.
5. Pre-fix: `relay` forwards the replayed frame to `them` every time (since `Check` never sees the counter as "already consumed"). Post-fix: `relay` forwards it 0 times, per [7](#0-6) .

**Note:** this vulnerability is already fixed in the current codebase (CHANGELOG.md #1751, and covered by `TestRelayReplayProtection`). I present it as the closest legitimate analog to the ERC777 report because both share the identical root-cause pattern: a "check" of state succeeded while the corresponding "commit/update" step was skipped in one specific code path, allowing the stale/already-scheduled state to be exploited repeatedly until an explicit fix forced the update to happen consistently.

// VerifyRelay verifies AEAD protected (but not encrypted) relay frames. packet must be length-checked by the caller.
func (cs *ConnectionState) VerifyRelay(l *slog.Logger, messageCounter uint64, packet []byte, nb []byte) error {
	cs.decryptLock.Lock()
	result := cs.window.Check(l, messageCounter)
	cs.decryptLock.Unlock()
	if !result {
		return ErrAlreadySeen
	}

	signedPayload := packet[:len(packet)-cs.dKey.Overhead()]
	signatureValue := packet[len(packet)-cs.dKey.Overhead():]
	_, err := cs.dKey.DecryptDanger(nil, signedPayload, signatureValue, messageCounter, nb)
	if err != nil {
		return err
	}

	cs.decryptLock.Lock()
	result = cs.window.Update(l, messageCounter)
	cs.decryptLock.Unlock()
	if !result {
		return ErrAlreadySeen
	}

	return nil
}

// TestRelayReplayProtection asserts that a relay (forwarding-type) node rejects
// replayed relay frames. A captured relay frame, re-injected with the same
// message counter, must be dropped by the replay window rather than re-forwarded
// to the relay target. Before the fix, handleOutsideRelayPacket authenticated the
// frame but never advanced the replay window, so every replay was re-forwarded.
func TestRelayReplayProtection(t *testing.T) {
	t.Parallel()
	ca, _, caKey, _ := cert_test.NewTestCaCert(cert.Version2, cert.Curve_CURVE25519, time.Now(), time.Now().Add(10*time.Minute), nil, nil, []string{})
	myControl, myVpnIpNet, _, _ := newSimpleServer(cert.Version2, ca, caKey, "me     ", "10.128.0.1/24,fc00::1/64", m{"relay": m{"use_relays": true}})
	relayControl, relayVpnIpNet, relayUdpAddr, _ := newSimpleServer(cert.Version2, ca, caKey, "relay  ", "10.128.0.128/24,fc00::128/64", m{"relay": m{"am_relay": true}})
	theirUdp := netip.MustParseAddrPort("10.0.0.2:4242")
	theirControl, theirVpnIpNet, theirUdpAddr, _ := newSimpleServerWithUdp(cert.Version2, ca, caKey, "them   ", "fc00::2/64", theirUdp, m{"relay": m{"use_relays": true}})

	myVpnV6 := myVpnIpNet[1]
	relayVpnV4 := relayVpnIpNet[0]
	relayVpnV6 := relayVpnIpNet[1]
	theirVpnV6 := theirVpnIpNet[0]

	// Teach me how to reach the relay and that them is reachable via the relay
	myControl.InjectLightHouseAddr(relayVpnV4.Addr(), relayUdpAddr)
	myControl.InjectLightHouseAddr(relayVpnV6.Addr(), relayUdpAddr)
	myControl.InjectRelays(theirVpnV6.Addr(), []netip.Addr{relayVpnV6.Addr()})
	relayControl.InjectLightHouseAddr(theirVpnV6.Addr(), theirUdpAddr)

	r := router.NewR(t, myControl, relayControl, theirControl)
	defer r.RenderFlow()

	myControl.Start()
	relayControl.Start()
	theirControl.Start()

	// Establish the relayed tunnel in both directions so all handshakes complete.
	t.Log("Establish the relayed tunnel")
	myControl.InjectTunPacket(BuildTunUDPPacket(theirVpnV6.Addr(), 80, myVpnV6.Addr(), 80, []byte("Hi from me")))
	p := r.RouteForAllUntilTxTun(theirControl)
	assertUdpPacket(t, []byte("Hi from me"), p, myVpnV6.Addr(), theirVpnV6.Addr(), 80, 80)
	theirControl.InjectTunPacket(BuildTunUDPPacket(myVpnV6.Addr(), 80, theirVpnV6.Addr(), 80, []byte("Hi from them")))
	p = r.RouteForAllUntilTxTun(myControl)
	assertUdpPacket(t, []byte("Hi from them"), p, theirVpnV6.Addr(), myVpnV6.Addr(), 80, 80)

	// Drain anything still queued on me's UDP tx so the next packet we pull is the
	// relay frame we are about to generate.
	for myControl.GetFromUDP(false) != nil {
	}

	// Capture a single legitimate relay frame that me transmits toward the relay.
	t.Log("Capture a relay frame from me -> relay")
	myControl.InjectTunPacket(BuildTunUDPPacket(theirVpnV6.Addr(), 80, myVpnV6.Addr(), 80, []byte("replay me")))
	relayFrame := myControl.GetFromUDP(true)
	require.Equal(t, relayUdpAddr, relayFrame.To, "captured frame should be addressed to the relay")
	var fh header.H
	require.NoError(t, fh.Parse(relayFrame.Data))
	require.Equal(t, header.Message, fh.Type)
	require.Equal(t, header.MessageRelay, fh.Subtype)

	// drainForwards counts relay frames the relay forwards toward them within the
	// settle window. We match on destination + (Message, MessageRelay) so the
	// relay's own direct traffic to them can't be miscounted.
	drainForwards := func(settle time.Duration) int {
		ch := relayControl.GetUDPTxChan()
		count := 0
		for {
			select {
			case pkt := <-ch:
				var ph header.H
				if pkt.To == theirUdpAddr && ph.Parse(pkt.Data) == nil &&
					ph.Type == header.Message && ph.Subtype == header.MessageRelay {
					count++
				}
				pkt.Release()
			case <-time.After(settle):
				return count
			}
		}
	}

	// First delivery of the captured frame: the relay should forward it once.
	t.Log("Deliver the captured frame once; relay forwards it to them")
	relayControl.InjectUDPPacket(relayFrame)
	require.Equal(t, 1, drainForwards(200*time.Millisecond), "relay should forward the first, legitimate copy")

	// Replay the exact same frame several times. A correct replay window rejects
	// these duplicates so the relay forwards none of them.
	t.Log("Replay the captured frame; relay must drop the duplicates")
	const replays = 3
	for i := 0; i < replays; i++ {
		relayControl.InjectUDPPacket(relayFrame)
	}
	forwarded := drainForwards(200 * time.Millisecond)
	assert.Equal(t, 0, forwarded, "relay re-forwarded %d/%d replayed relay frames; replay protection is ineffective on relay tunnels", forwarded, replays)

	r.RenderHostmaps("Final hostmaps", myControl, relayControl, theirControl)
}
