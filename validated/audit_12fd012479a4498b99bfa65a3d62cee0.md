### Title
Global `ClientConnectionTracker` capacity can be exhausted by unauthenticated pre-handshake connection floods, causing legitimate leader TPU handshakes to be refused - ([File: streamer/src/nonblocking/quic.rs])

### Summary
The QUIC accept loop admits connections into the single global `ClientConnectionTracker` slot pool (`max_concurrent_connections`) before the handshake completes and before any per-IP or per-peer-type accounting is actually enforced, because both the overall and per-IP rate limiters are only *checked* (not consumed) at accept time and are only truly consumed after a successful handshake. An attacker who opens many parallel, never-completing QUIC handshakes from one or a few IPs can occupy the entire global tracker capacity, causing `incoming.refuse()` to fire for all subsequent connections (staked or not) via `refused_connections_too_many_open_connections`.

### Finding Description
In the accept loop `run_server` in `streamer/src/nonblocking/quic.rs`, for every incoming connection the server:
1. Checks `overall_connection_rate_limiter.current_tokens() == 0` [1](#0-0) . `current_tokens()` is a pure peek (`net-utils/src/token_bucket.rs::current_tokens`) — it does not consume anything [2](#0-1) . The bucket is only actually drained later via `consume_tokens(1)` inside `setup_connection`, i.e. only *after* the handshake succeeds [3](#0-2) .
2. Checks `rate_limiter.is_allowed(&ip)` for per-IP limiting [4](#0-3) . `is_allowed` only inspects the existing bucket for that IP and never mutates state — its own test explicitly asserts "just checking should not mutate state" [5](#0-4) . The IP bucket is only ever debited via `register_connection`, which — like the global limiter — is only called after the handshake completes [6](#0-5) .
3. Only then does it call `ClientConnectionTracker::new(stats, qos.max_concurrent_connections())`, which atomically checks/increments a single global `AtomicUsize` (`stats.open_connections`) against `max_concurrent_connections` [7](#0-6) . This is the only real admission gate before the handshake, and it is IP-agnostic and pubkey-agnostic.
4. If the tracker check fails, the server increments `refused_connections_too_many_open_connections` and calls `incoming.refuse()` [8](#0-7) .

`max_concurrent_connections()` is a fixed, global number computed from configured staked/unstaked capacity, e.g. `(max_staked_connections + max_unstaked_connections) * 5 / 4` in `SwQos` [9](#0-8)  or `max_staked_connections * 5 / 4` in `SimpleQos` [10](#0-9) . With defaults of 2000/2000 this cap is 5000 [11](#0-10) .

Since neither the global nor the per-IP token buckets are consumed until *after* the handshake resolves, an attacker who keeps connections in-flight without completing the handshake (e.g. sending only an Initial packet and stalling, or slow-walking the handshake up to `QUIC_CONNECTION_HANDSHAKE_TIMEOUT` = 2s [12](#0-11) ) can repeatedly pass both rate-limit checks from a single IP (since `is_allowed` returns `true` when no tokens have ever been consumed for that IP) and consume tracker slots up to the global cap. Real per-peer/per-IP QoS enforcement (`ConnectionTable::try_add_connection`, staked/unstaked table limits) only happens later inside `qos.try_add_connection`, which is reached only after the handshake completes [13](#0-12)  — by which point the attacker has already occupied the entire global tracker budget and legitimate peers are refused via `incoming.refuse()`.

### Impact Explanation
This is a Denial-of-Service / QoS-evasion bug on the TPU QUIC ingress: an unstaked, unprivileged attacker can deny all TPU connection admission (staked and unstaked alike) by keeping `max_concurrent_connections` worth of half-open handshakes alive, without ever needing to complete a handshake or be individually rate-limited, since the enforcement mechanisms that are supposed to bound per-source abuse (`overall_connection_rate_limiter`, per-IP `ConnectionRateLimiter`) do not actually take effect until after the attacker's connection succeeds — which never needs to happen. This falls under "global outstanding-handshake capacity exhausted by one attacker before per-peer-type/per-IP QoS is even applied, denying all TPU ingress," i.e., a QoS/rate-limit evasion causing validator TPU DoS.

### Likelihood Explanation
Feasible with unprivileged network access only: no stake, no valid keypair, no gossip participation required. The attacker only needs to open UDP/QUIC connections to the leader's public TPU port and avoid completing the handshake (or intentionally stall it) for up to `QUIC_CONNECTION_HANDSHAKE_TIMEOUT` (2s), repeating indefinitely to sustain saturation. Because per-IP `is_allowed` is a no-op until a completed connection registers tokens, this can be done from very few source IPs, making it cheap and repeatable.

### Recommendation
Enforce actual admission-control consumption (not just a peek) for both the overall and per-IP rate limiters at accept time, before incrementing the global tracker counter, so that half-open/never-completing handshakes are debited against the attacker's own IP quota and the global rate budget immediately rather than only after success. Alternatively, tie `ClientConnectionTracker::new`'s admission decision to per-IP outstanding-handshake counts (not just a single global atomic), so a burst from one or few IPs cannot consume the entire global budget.

### Proof of Concept
```rust
// streamer/src/nonblocking/quic.rs (new test)
#[tokio::test(flavor = "multi_thread")]
async fn test_pre_handshake_tracker_exhaustion_denies_legit_client() {
    // Configure a small max_concurrent_connections for a fast repro
    // (e.g. via SwQosConfig { max_staked_connections: 4, max_unstaked_connections: 4, ..Default::default() })
    let SpawnTestServerResult { server_address, stats, cancel, join_handle, .. } =
        setup_quic_server(None, QuicStreamerConfig::default_for_tests(), SwQosConfig {
            max_staked_connections: 4,
            max_unstaked_connections: 4,
            ..Default::default()
        });

    // Attacker: open (max_concurrent_connections) UDP sockets that send only
    // QUIC Initial packets and never complete the handshake, all from the
    // same loopback IP (different ports simulate different "connections"
    // from one attacker-controlled source).
    let max_concurrent = (4 + 4) * 5 / 4; // matches SwQos::max_concurrent_connections()
    let mut half_open = Vec::new();
    for _ in 0..max_concurrent {
        // send raw Initial packet(s) to server_address without completing handshake,
        // e.g. via a raw UDP socket, or a quinn endpoint whose connect() future is
        // never polled to completion / whose peer never responds.
        half_open.push(spawn_stalled_handshake(server_address));
    }

    // Give the accept loop time to admit all of them into ClientConnectionTracker.
    tokio::time::sleep(Duration::from_millis(200)).await;

    // Legitimate low-volume client attempts to connect concurrently.
    let legit = make_client_endpoint(&server_address, None).await;
    // ... attempt legit.connect(...) and await for a bounded time ...

    // Assertion: refusal counter grew roughly to max_concurrent, and legit
    // connection was refused while attacker's half-open connections still occupy slots.
    assert!(
        stats.refused_connections_too_many_open_connections.load(Ordering::Relaxed) > 0,
        "expected legitimate/other connections to be refused due to tracker exhaustion"
    );

    cancel.cancel();
    join_handle.await.unwrap();
}
```
Expected result on the current code: `refused_connections_too_many_open_connections` increments and the legitimate client's connection is refused, while `stats.connection_rate_limited_across_all` and `stats.connection_rate_limited_per_ipaddr` remain at 0 for the attacker's half-open connections (proving the rate limiters never engaged pre-handshake).

impl ClientConnectionTracker {
    /// Check the max_concurrent_connections limit and if it is within the limit
    /// create ClientConnectionTracker and increment open connection count. Otherwise returns Err
    fn new(stats: Arc<StreamerStats>, max_concurrent_connections: usize) -> Result<Self, ()> {
        let open_connections = stats.open_connections.fetch_add(1, Ordering::Relaxed);
        if open_connections >= max_concurrent_connections {
            stats.open_connections.fetch_sub(1, Ordering::Relaxed);
            debug!(
                "There are too many concurrent connections opened already: open: \
                 {open_connections}, max: {max_concurrent_connections}"
            );
            return Err(());
        }

        Ok(Self { stats })
    }
}

    /// Check if the connection from the said `ip` is allowed.
    /// Here we assume that only IPs with actual confirmed connections are stored in it,
    /// since we should only modify server state once source IP is verified
    pub fn is_allowed(&self, ip: &IpAddr) -> bool {
        // Check if we have records in the rate limiter for the given IP address
        match self.limiter.current_tokens(ip) {
            Some(r) => r > 0, // we have a record, and rate is not exceeded
            None => true,     // if we have not seen IP, allow connection request
        }
    }
