### Title
Unauthenticated remote `POST /shutdown` permanently halts the signer's event-processing loop - ([File: libsigner/src/events.rs])

### Summary
`SignerEventReceiver::next_event()` dispatches any HTTP POST to `/shutdown` by unconditionally setting `stop_signal` to `true` and returning `EventError::Terminated`, with no check on the caller's identity, source address, or any shared secret. Any remote party able to open a TCP connection to the signer's event-receiver port can send one crafted `POST /shutdown` request and permanently stop the signer's event loop.

### Finding Description
The intended invariant is that only the node's coordinated shutdown path (via `SignerStopSignaler::send()`) should be able to set `stop_signal` and terminate `main_loop`. In practice, `next_event()` implements this invariant purely as a URL/method match with no authentication: [1](#0-0) 

```rust
} else if request.url() == "/shutdown" {
    event_receiver.stop_signal.store(true, Ordering::SeqCst);
    Err(EventError::Terminated)
```

There is no verification of a shared secret, source IP allow-list, or any other credential before honoring this request — contrast this with `/status`, `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, and `/new_block`, which are likewise dispatched purely by URL string match without any auth token. `SignerStopSignaler::send()` — the legitimate caller — simply issues a plain HTTP POST to `/shutdown` over a bare TCP connection [2](#0-1) , which is indistinguishable from a request forged by any other TCP client. `main_loop` interprets `EventError::Terminated` as a clean exit signal and breaks its loop: [3](#0-2) 

Once `stop_signal` is `true`, `is_stopped()` returns `true` on every subsequent iteration [4](#0-3) , so `main_loop` exits immediately at the top of the loop and never calls `next_event()` again — the signer's event stream is permanently halted until process restart.

### Impact Explanation
A single unauthenticated HTTP POST to `/shutdown` on the signer's event-receiver port causes the signer's `EventReceiver::main_loop` to exit permanently, halting all downstream signer event processing (StackerDB chunk events, block-validation responses, new-burn-block/new-block events, status checks). This is an unauthenticated, single-message, remote denial of service against a signer node — matching the "Critical - remote crash/unauthenticated DoS from few messages" category. It does not forge or write any chain state, but it does silence a specific signer's event stream, which can affect the signer's participation in block signing.

### Likelihood Explanation
- Preconditions: attacker only needs TCP reachability to the signer's event-receiver bind address/port; no secret, key, or privileged role is required.
- The signer's event-receiver is an HTTP server (`tiny_http`) whose bind address is configured by the operator; if it is bound to a non-loopback interface or reachable via port-forwarding/NAT misconfiguration, it is remotely reachable by any unprivileged network peer.
- The dispatcher does not authenticate the caller as "the node" — it merely trusts the URL path, so any TCP client that speaks HTTP can reproduce the exact bytes `SignerStopSignaler::send()` sends.
- Attack cost is a single crafted HTTP request; it is trivially repeatable each time the signer process is restarted, and the DoS is persistent (no auto-recovery in this file) until process restart.

### Recommendation
Do not use an unauthenticated public URL to convey a local intra-process control signal over the network. Options:
- Enforce that the `/shutdown` endpoint only be honored for requests originating from `127.0.0.1`/the loopback interface (since `SignerStopSignaler` always connects to `self.local_addr`, which is the receiver's own bind address).
- Replace the network-based stop signal with a genuine in-process synchronization primitive (e.g., a channel, condition variable, or self-pipe) instead of sending an HTTP request over the same port that receives node events.
- If a network signal must be kept for compatibility, require a shared secret/token in the shutdown request and validate it before setting `stop_signal`.

### Proof of Concept
Rust test plan (to be run within `libsigner`'s test harness, using `SignerEventReceiver` directly, similar to existing tests in `libsigner/src/tests/mod.rs`):
1. Construct a `SignerEventReceiver<T>` and call `bind()` on `127.0.0.1:0` (or any test port) to obtain the bound `SocketAddr`.
2. Spawn `main_loop()` in a background thread.
3. From the *test* thread (acting as an unprivileged remote attacker, not through `SignerStopSignaler`), open a bare `TcpStream::connect(addr)` and write:
   ```
   POST /shutdown HTTP/1.1\r\nHost: 127.0.0.1\r\nConnection: close\r\nContent-Length: 4\r\n\r\nabcd
   ```
4. Assert that shortly after, `receiver.is_stopped()` (via the `stop_signal` `AtomicBool`, exposed e.g. through `get_stop_signaler()` or a test-only accessor) becomes `true`.
5. Assert that the background thread running `main_loop()` joins/exits (i.e., the loop has broken), confirming permanent termination of event processing triggered by an unauthenticated peer — corresponding to the `Err(EventError::Terminated)` branch at `libsigner/src/events.rs:443-445` and the `break` in `main_loop` at `libsigner/src/events.rs:296-300`.
