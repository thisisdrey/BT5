This confirms the key point: storage staking accounting (`current_storage_usage` / `account.storage_usage()`) is tracked entirely independently from `TrieStorageUpdate::memory_usage`. The gas/byte charging for `storage_write` is done directly in the VM host function based on the actual `key.len()`/`value.len()` byte counts [1](#0-0) , and this is reflected into `Account::storage_usage()` which drives the storage-staking check in `check_storage_stake` [2](#0-1) . The trie's internal `memory_usage` field on `TrieStorageUpdate` (in `core/store/src/trie/trie_storage_update.rs`) is purely an MPT-internal bookkeeping value used to compute node hashes for the Merkle root — it is part of `RawTrieNodeWithSize` and contributes to the node hash [3](#0-2) , but it is never read by any storage-staking or refund logic.
