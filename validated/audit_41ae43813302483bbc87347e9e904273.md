### Title
Unauthenticated remote shutdown of `SignerEventReceiver` via unauthenticated `POST /shutdown` - (File: `libsigner/src/events.rs`)

### Summary
The `SignerEventReceiver::next_event` handler treats any HTTP `POST` to the `/shutdown` URL path as a valid stop command, with no check that the request actually originated from the process's own `SignerStopSignaler`. Any remote party able to open a TCP connection to the bound event-receiver port can send this request and permanently terminate the receiver's event loop.

### Finding Description
The claimed equality — "the shutdown command == one issued by the node operator's local stop signaler" — is broken: `next_event` dispatches purely on the URL string and HTTP method, with no token, secret, source-address check, or session state distinguishing the legitimate signaler from an arbitrary sender.

```rust
// libsigner/src/events.rs
} else if request.url() == "/shutdown" {
    event_receiver.stop_signal.store(true, Ordering::SeqCst);
    Err(EventError::Terminated)
}
``` [1](#0-0) 

The legitimate caller, `SignerStopSignaler::send`, is just a regular `TcpStream` connecting to `self.local_addr` and writing a raw HTTP request string — it carries no secret or credential that authenticates it as privileged:
```rust
if let Ok(mut stream) = TcpStream::connect(self.local_addr) {
    let body = "Yo. Shut this shit down!".to_string();
    let req = format!(
        "POST /shutdown HTTP/1.1\r\nHost: {}\r\nConnection: close\r\nContent-Length: {}\r\nContent-Type: text/plain\r\n\r\n{}",
        self.local_addr, body.len(), body
    );
    ...
}
``` [2](#0-1) 

Any TCP client that reaches the port and sends the same bytes (or any well-formed `POST /shutdown` with any body/no body, since the body is never validated) triggers the identical code path. Once `stop_signal` is set, `is_stopped()` returns `true` on every subsequent call, and `main_loop` breaks permanently on the `Err(EventError::Terminated)` arm:
```rust
Err(EventError::Terminated) => {
    info!("Caught termination signal");
    break;
}
``` [3](#0-2) 

There is no re-arm/reset of `stop_signal` anywhere in this file, so once tripped the receiver thread exits for good and stops relaying `stackerdb_chunks`, `proposal_response`, `new_burn_block`, and `new_block` events to the signer runloop from that point forward. No signature check, secret, or auth-gate exists on this endpoint (unlike, e.g., the JSON-body event types which at least require a `serde_json` deserialize into a known struct via `process_event`, though that too has no auth).

### Impact Explanation
A single unauthenticated `POST /shutdown` permanently stops the `SignerEventReceiver::main_loop`, which stops delivery of `stackerdb_chunks` (mined block proposals/miner messages), `proposal_response`, `new_burn_block`, and `new_block` events into the signer's processing pipeline. This is an unauthenticated, single-message, remote DoS of the signer's node→signer event channel — the signer effectively goes blind to node events until manually restarted. This matches the Critical category "remote crash/unauthenticated DoS from few messages" (here, exactly one message).

### Likelihood Explanation
Preconditions: the attacker must merely be able to open a TCP connection to the port that `EventReceiver::bind` is listening on and send well-formed HTTP bytes — no secret, peer key, or StackerDB slot ownership required. Attacker cost is a single crafted HTTP request. Whether this port is exposed beyond loopback depends on the operator's bind configuration (`stacks-signer` config `endpoint`/event-receiver bind address), which was not fully traced in this session — I was unable to confirm from the indexed files whether the default or common deployments bind this listener to `0.0.0.0` or restrict to `127.0.0.1`. If bound to any interface reachable by a remote attacker, the exploit is trivially repeatable (though only needs to succeed once, since the effect is permanent until restart).

### Recommendation
Add authentication to the `/shutdown` path distinguishing the local `SignerStopSignaler` from arbitrary remote senders — e.g., require the request originate from loopback (check peer address) and/or include a per-process random secret/token known only to the signaler and the receiver, validated before setting `stop_signal`. Alternatively, replace the HTTP-based stop signal with an in-process channel/self-pipe mechanism that does not go over the network at all.

### Proof of Concept
Rust test plan:
1. Instantiate a `SignerEventReceiver<T>`, call `bind(addr)` on `127.0.0.1:0` (or a fixed test port), and spawn `main_loop()` in a thread with a consumer registered via `add_consumer`.
2. From a separate, plain `std::net::TcpStream::connect(addr)` (not via `SignerStopSignaler`), write the raw bytes:
   `"POST /shutdown HTTP/1.1\r\nHost: 127.0.0.1\r\nConnection: close\r\nContent-Length: 4\r\nContent-Type: text/plain\r\n\r\ntest"`.
3. Assert that a subsequent call to `next_event()` (or the spawned `main_loop` thread) observes `Err(EventError::Terminated)` and that the `main_loop` thread joins/exits.
4. Assert that further legitimate `POST /stackerdb_chunks` events sent afterward are no longer forwarded to the consumer channel, confirming permanent loss of event delivery — the crash/DoS site being `libsigner/src/events.rs:443-445` and the loop-exit site being `libsigner/src/events.rs:296-300`.
