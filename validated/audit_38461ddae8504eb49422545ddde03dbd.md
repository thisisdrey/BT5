### Title
Unauthenticated `/new_burn_block` HTTP endpoint lets any TCP peer inject a forged burn-chain tip into the signer's event stream - (File: `libsigner/src/events.rs`)

### Summary
`SignerEventReceiver::next_event` dispatches any POST to `/new_burn_block` straight into `process_event::<T, BurnBlockEvent>` with no authentication, secret, or signature check of any kind. The JSON body is deserialized directly into `BurnBlockEvent` and converted verbatim into `SignerEvent::NewBurnBlock`, so a remote peer with only TCP reachability to the signer's listener can forge the burn-chain tip the signer runloop believes it received from its own node.

### Finding Description
The equality that should hold is: *the burn-chain state forwarded to the signer runloop as `SignerEvent::NewBurnBlock` == the state actually observed by this node's burnchain indexer*. This is broken because the handler performs no authentication.

`SignerEventReceiver::bind` opens a plain `tiny_http::HttpServer` on the configured listen address [1](#0-0) . `next_event` reads a request, and purely based on URL string matching routes `/new_burn_block` to `process_event::<T, BurnBlockEvent>(request)` — there is no header check, no token comparison, no peer/IP allow-list, nothing besides the path/method match [2](#0-1) .

`process_event` simply reads the raw body, acks the dispatcher, and deserializes it as JSON into the target type with `serde_json::from_slice`, then calls `.try_into()` [3](#0-2) .

`TryFrom<BurnBlockEvent> for SignerEvent<T>` copies attacker-controlled fields verbatim into the emitted event with no cross-check against any locally observed chain state: [4](#0-3) .

The `connection_options.auth_token` mechanism documented elsewhere in the repo only protects the **node's** RPC endpoints (e.g. `/v3/block_proposal`, `/v2/blocks?broadcast=1`) that the signer calls into [5](#0-4) ; it does not protect the **signer's own** inbound event listener implemented in `events.rs`, which is what receives `/new_burn_block`. There is no equivalent secret check anywhere in `next_event`/`process_event` for the reverse direction (node → signer, or here, arbitrary attacker → signer).

Sample configs show this listener is meant to bind to loopback (e.g. `endpoint = "127.0.0.1:30000"` in `mainnet-signer.toml`) but the reference signer config explicitly documents binding it to `0.0.0.0:30000` (all interfaces) as a valid/example configuration, and nothing in the code enforces loopback-only binding — `bind()` accepts whatever `SocketAddr` is configured with no restriction.

### Impact Explanation
Any remote party that can open a TCP connection to the signer's event-listener port can send a single crafted HTTP POST to `/new_burn_block` with a fabricated `burn_block_height`, `burn_block_hash`, `consensus_hash`, and `parent_burn_block_hash`, and the signer's runloop will receive `SignerEvent::NewBurnBlock` with those forged values as if they came from its own trusted node. This is a forged burn-chain tip injected directly into the signer's decision-making event stream, with no verification that it matches the burnchain indexer's actual view. The message is fully repeatable and costs the attacker nothing beyond a bare HTTP request per injection.

### Likelihood Explanation
No preconditions beyond TCP reachability to the bound port are required — no secret, no peer registration, no StackerDB slot ownership. The only variable is deployment: if the operator binds the listener to `0.0.0.0` (as the shipped reference config does) or the port is otherwise exposed (e.g., via port-forwarding, cloud security-group misconfiguration, or containers sharing a network namespace), the endpoint is directly reachable by an unprivileged remote attacker. The vulnerability is present unconditionally in the code — the current design relies entirely on network-level isolation instead of any check in `events.rs`.

### Recommendation
Add authentication to the signer's inbound event HTTP server in `libsigner/src/events.rs`: require a shared secret in the request headers (reusing the existing `auth_token`/`auth_password` pairing already used between node and signer) and reject any request that fails to present it, before deserializing the body. Additionally consider binding the listener to loopback by default and requiring explicit opt-in for wider exposure.

```rust
use std::net::TcpStream;
use std::io::Write;

#[test]
fn unauthenticated_forged_burn_block_is_accepted() {
    let mut receiver = SignerEventReceiver::<SomeMessageType>::new(false);
    let addr = receiver.bind("127.0.0.1:0".parse().unwrap()).unwrap();
    let (tx, rx) = std::sync::mpsc::channel();
    receiver.add_consumer(tx);

    // Spawn next_event() in a thread
    std::thread::spawn(move || {
        let ev = receiver.next_event().unwrap();
        // assert forged data flows through unauthenticated
        assert!(matches!(ev, SignerEvent::NewBurnBlock { consensus_hash, .. }
            if consensus_hash == forged_consensus_hash()));
    });

    // Attacker with no credentials, just TCP reachability
    let body = serde_json::json!({
        "burn_block_hash": "0x00...deadbeef",
        "burn_block_height": 999999,
        "consensus_hash": "0x00...c0ffee",
        "parent_burn_block_hash": "0x00...beef",
        "reward_recipients": [],
        "burn_amount": 0,
    }).to_string();

    let req = format!(
        "POST /new_burn_block HTTP/1.1\r\nHost: {}\r\nContent-Length: {}\r\nContent-Type: application/json\r\n\r\n{}",
        addr, body.len(), body
    );
    let mut stream = TcpStream::connect(addr).unwrap();
    stream.write_all(req.as_bytes()).unwrap();
    // no Authorization header sent at all

    // Assertion: rx receives the forged NewBurnBlock event
}
```

```rust
fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}
```
