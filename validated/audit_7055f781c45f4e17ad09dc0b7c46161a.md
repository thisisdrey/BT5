The CVE-2016-0737 describes an OpenStack Swift (Python) proxy-server defect where interrupted client requests to Large Object URLs failed to properly close backend connections, causing resource exhaustion. Searching for the closest analog in this Go repository — the `net/http` server and reverse-proxy code — shows the opposite: Go's HTTP/1.1 server already implements exactly the defensive logic this bug-class requires.

Specifically, `net/http`'s `conn.serve` loop and the `response` type track whether a request body was fully consumed and force the connection closed otherwise via `shouldReuseConnection` and the `closeAfterReply` flag, rather than reusing/leaking it: [1](#0-0) 

When a body read error occurs mid-request (the direct analog of an "interrupted request to a Large Object URL"), the body-closing path in `finishRequest`/discard logic explicitly marks the connection for closing rather than continuing to hold it open: [2](#0-1) 

This exact behavior — closing the connection instead of leaking it when a body read is interrupted or too large — is covered by dedicated regression tests: [3](#0-2) [4](#0-3) 

The `ReverseProxy` (the closest Go analog to Swift's proxy-server) also defers closing of the outbound request body to avoid leaking connections on interrupted/canceled requests: [5](#0-4) 

And known historical proxy-connection-leak issues (e.g., slow/hanging CONNECT responses, persistent-connection leaks on broken connections) already have fixes and regression tests in place: [6](#0-5) [7](#0-6) 

There is no unfixed instance in this codebase where an interrupted request to a large-object-style endpoint leaves a server or proxy connection open/unbounded; the mechanisms (`closeAfterReply`, `shouldReuseConnection`, `requestTooLarge`, background-read/EOF tracking) are specifically designed to prevent this class of resource exhaustion, and are exercised by existing tests. This is a different runtime (Python/Swift) and no matching, currently-exploitable root cause exists in the Go standard library to serve as a valid analog.

```go
// shouldReuseConnection reports whether the underlying TCP connection can be reused.
// It must only be called after the handler is done executing.
func (w *response) shouldReuseConnection() bool {
	if w.closeAfterReply {
		// The request or something set while executing the
		// handler indicated we shouldn't reuse this
		// connection.
		return false
	}

	if w.req.Method != "HEAD" && w.contentLength != -1 && w.bodyAllowed() && w.contentLength != w.written {
		// Did not write enough. Avoid getting out of sync.
		return false
	}

	// There was some error writing to the underlying connection
	// during the request, so don't re-use this conn.
	if w.conn.werr != nil {
		return false
	}

	// We haven't read the entire request body, so we can't reuse the connection.
	if !w.reqBody.consumedEntireBody() {
		return false
	}

	return true
```
