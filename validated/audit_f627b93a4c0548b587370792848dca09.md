### Title
Unauthenticated inflation of `InactiveIssuance` via direct transfers to `pallet-dap`'s public staging account - (File: `substrate/frame/dap/src/lib.rs`)

### Summary
`pallet-dap`'s `on_idle` hook drains the entire balance of its `staging_account()` into the `buffer_account()` and calls `T::Currency::deactivate(available)` on the full drained amount, with no verification that the funds actually originated from a genuine burn/slash event routed through `OnUnbalanced`. Because `staging_account()` is a deterministically-derivable, publicly-exposed `AccountId` (also exposed directly via the `staging()` view function), any unprivileged account can transfer arbitrary funds into it using an ordinary `Balances::transfer_*` call, and those funds will be treated identically to genuine slashed/burned funds on the next `on_idle`.

### Finding Description
`on_unbalanced` deposits credits from the `fungible::Balanced`/legacy `Currency` unbalancing paths (staking slashes, fee burns, dust removal, etc.) into `staging_account()`: [1](#0-0) 

`on_idle` then reads *whatever balance currently sits* in `staging_account()` (`reducible_balance`), transfers all of it to `buffer_account()`, and calls `deactivate_buffer_funds`, which invokes `T::Currency::deactivate(amount)`: [2](#0-1) [3](#0-2) 

There is no accounting that distinguishes "funds that arrived via `on_nonzero_unbalanced` (a genuine burn source)" from "funds that arrived via a plain, unprivileged `Balances::transfer_allow_death`/`transfer_keep_alive` call directly to the same account." The pallet even exposes the exact address through a public view function so any caller can discover it without needing to re-derive the `PalletId` sub-account: [4](#0-3) 

The pallet's own test explicitly demonstrates that whatever balance is in staging gets deactivated on `on_idle`, matching an amount equal to what was deposited, without any origin/role check comparable to a Burner role: [5](#0-4) 

This is the direct structural analog of the reported `CoreRef._burnFeiHeld` issue: a state-mutating "burn/deactivate" primitive is reachable through a public, unguarded entrypoint (an ordinary transfer to a known address) without any check that the caller/funds are entitled to trigger that privileged accounting effect.

### Impact Explanation
`deactivate()` reduces `active_issuance()` (`TotalIssuance - InactiveIssuance`) without reducing `TotalIssuance`. `active_issuance` is a chain-wide economic-accounting primitive read by inflation/reward-curve logic (e.g., `IssuanceCurve::issue(total_issuance, elapsed)` in `mint_and_distribute`) and by other consumers of `fungible::Inspect::active_issuance()` across the runtime: [6](#0-5) 

An unprivileged attacker can arbitrarily and repeatedly deflate perceived active issuance system-wide simply by sending funds they already own to the well-known staging account, at no net cost beyond the transferred amount ending up in the pallet's buffer account (from which it is later redistributed to `BudgetRecipients`, i.e., potentially back to the attacker if they are a registered recipient, or otherwise misdirected). This corrupts an accounting invariant (`InactiveIssuance` should reflect only genuine burns) that downstream reward/inflation computation relies on, without requiring any privileged role, governance action, or malicious relayer/validator — matching the "runtime bugs that compromise intended behavior" and "public underpriced work" impact classes in scope.

### Likelihood Explanation
High: the only requirement is knowledge of `staging_account()`, which is directly exposed via the `staging()` public view function, and a standard signed `Balances::transfer_allow_death`/`transfer_keep_alive` extrinsic that any account can submit. No special timing, front-running, or privileged access is needed; `on_idle` runs automatically once weight/block conditions permit.

### Recommendation
Track the specific amount of genuinely-burned funds deposited via `on_nonzero_unbalanced` in dedicated storage (rather than relying on the live balance of `staging_account()`), and have `on_idle` drain/deactivate only that tracked amount. Alternatively, prevent arbitrary transfers into `staging_account()` from being treated as burns, e.g. by using a non-transferable/no-op-inflow account model or by netting out balance sitting there against a running "expected from burns" counter before deactivating.

### Proof of Concept
1. Runtime `R` configures `pallet_dap::Pallet<R>` as (part of) `OnUnbalanced`/`Slash` for `pallet_balances` or `pallet_staking`, as done in `cumulus/parachains/runtimes/assets/asset-hub-westend/src/staking.rs` and `substrate/bin/node/runtime/src/lib.rs`.
2. Attacker (unprivileged, no roles) queries the `dap` pallet's `staging()` view function to obtain `staging_account()`.
3. Attacker submits `Balances::transfer_keep_alive(staging_account, X)` from their own account.
4. On the next `on_idle` execution, `Pallet::<T>::on_idle` reads `reducible_balance(staging_account)` (now including the attacker's transferred `X`), moves it to `buffer_account()`, and calls `deactivate_buffer_funds(available)`, decreasing `active_issuance()` by `X` even though `TotalIssuance` is unaffected and no actual slash/burn occurred — reproducing the exact `slash_to_dap_accumulates_to_staging_then_deactivates_on_idle` test behavior but with attacker-supplied, non-burn funds as the input. 		fn on_idle(_block: BlockNumberFor<T>, remaining_weight: Weight) -> Weight {
			let mut meter = WeightMeter::with_limit(remaining_weight);

			// Need at least one read (staging account balance).
			if meter.try_consume(T::DbWeight::get().reads(1)).is_err() {
				return meter.consumed();
			}

			let staging_account = Self::staging_account();
			let available = T::Currency::reducible_balance(
				&staging_account,
				Preservation::Preserve,
				Fortitude::Polite,
			);

			if available.is_zero() {
				return meter.consumed();
			}

			// Need 1 read and 2 writes for the transfer, plus 1 read and 1 write for
			// deactivate (InactiveIssuance) and 1 read for TotalIssuance.
			if meter.try_consume(T::DbWeight::get().reads_writes(3, 3)).is_err() {
				return meter.consumed();
			}

			let buffer = Self::buffer_account();
			if T::Currency::transfer(&staging_account, &buffer, available, Preservation::Preserve)
				.is_err()
			{
				defensive!("DAP: staging account transfer to buffer failed");
				return meter.consumed();
			}

			Self::deactivate_buffer_funds(available);
			Self::deposit_event(Event::StagingDrained { amount: available });

	fn on_nonzero_unbalanced(amount: CreditOf<T>) {

fn slash_to_dap_accumulates_to_staging_then_deactivates_on_idle() {
	build_and_execute(true, || {
		set_default_budget_allocation();

		let buffer = DapPallet::buffer_account();
		let staging = DapPallet::staging_account();
		let ed = <Balances as Inspect<_>>::minimum_balance();

		let alice = account_id(1);
		let bob = account_id(2);
		let charlie = account_id(3);

		// Given: buffer and staging each have ED; users have balances.
		assert_eq!(Balances::free_balance(&buffer), ed);
		assert_eq!(Balances::free_balance(&staging), ed);
		let initial_active = <Balances as Inspect<_>>::active_issuance();
		let initial_total = <Balances as Inspect<_>>::total_issuance();

		// When: multiple slashes occur via OnUnbalanced (simulating staking slashes).
		for (who, amount) in [(&alice, 30u64), (&bob, 20), (&charlie, 50)] {
			let credit = <Balances as Balanced<_>>::withdraw(
				who,
				amount,
				Precision::Exact,
				Preservation::Preserve,
				Fortitude::Force,
			)
			.unwrap();
			DapPallet::on_unbalanced(credit);
		}

		// Then: funds land in staging, not buffer.
		assert_eq!(Balances::free_balance(&staging), ed + 100);
		assert_eq!(Balances::free_balance(&buffer), ed);

		// And: users lost their slashed amounts.
		assert_eq!(Balances::free_balance(&alice), 100 - 30);
		assert_eq!(Balances::free_balance(&bob), 200 - 20);
		assert_eq!(Balances::free_balance(&charlie), 300 - 50);

		// And: active issuance is NOT yet decreased (deactivation is deferred to on_idle).
		assert_eq!(<Balances as Inspect<_>>::active_issuance(), initial_active);

		// And: total issuance unchanged (funds moved, not destroyed).
		assert_eq!(<Balances as Inspect<_>>::total_issuance(), initial_total);

		// When: on_idle drains staging into buffer and deactivates.
		DapPallet::on_idle(1, Weight::MAX);

		// Then: staging retains only ED; buffer gained all slashed funds.
		assert_eq!(Balances::free_balance(&staging), ed);
		assert_eq!(Balances::free_balance(&buffer), ed + 100);

		// And: active issuance decreased by 100 (funds deactivated in DAP buffer).
		assert_eq!(<Balances as Inspect<_>>::active_issuance(), initial_active - 100);

		// And: total issuance still unchanged.
		assert_eq!(<Balances as Inspect<_>>::total_issuance(), initial_total);
	});
