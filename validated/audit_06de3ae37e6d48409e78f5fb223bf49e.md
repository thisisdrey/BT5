### Title
Protocol fee bypass via unit-splitting NEP-245/IMT `TokenDiff` intents - (`contracts/defuse/core/src/intents/token_diff.rs`)

### Summary
`TokenDiff::token_fee` waives the protocol fee whenever a `TokenIdType::Nep245` or `TokenIdType::Imt` `token_in` delta has `amount <= 1`, on the assumption that such deltas represent atomic, non-fungible-like MT items. Because NEP-245 balances are ordinary fungible amounts (not restricted to `total_supply <= 1` the way `Nep171` is), an attacker can decompose any arbitrarily large `token_in` amount into many `amount = 1` `TokenDiff` intents settled between two self-controlled accounts, so every fee computation hits the zero-fee branch while the aggregate value moved is unbounded.

### Finding Description
The binding that should hold is:

`fee_owed(token_in, |D|) == Σ fee_ceil(protocol_fee_pips, |δ_i|)` for any decomposition `D = Σ δ_i` of the same economic transfer of token `T`.

In `TokenDiff::execute_intent` [1](#0-0) , the fee is computed independently per `TokenDiff` intent, based only on that intent's own `amount = delta.unsigned_abs()`:

```rust
if *delta < 0 {
    let amount = delta.unsigned_abs();
    let fee = Self::token_fee(token_id, amount, protocol_fee).fee_ceil(amount);
    ...
}
```

And `token_fee` exempts `Nep245`/`Imt` tokens entirely when `amount <= 1`: [2](#0-1) 

This exemption is designed for atomic NFT-like items (`Nep171`, whose `total_supply` is capped at 1 by `Contract::deposit`, see [3](#0-2) ). But `Nep245` (multi-token/NEP-245) balances have no such cap — they are ordinary fungible quantities, as shown by the wrapping tests where NEP-141 balances are represented 1:1 as `Nep245TokenId` amounts across Defuse instances (e.g. `tests/src/tests/defuse/tokens/nep245/mod.rs`).

Exploit flow: an attacker who controls two of their own accounts (self-dealing, fully within "unprivileged" capability — sign with own keys, hold own Verifier balances) can sign `N` separate `TokenDiff` payloads, each moving exactly `1` unit of a `Nep245`-wrapped valuable asset from account A to account B (and the matching `+1` counter-leg), instead of one payload with `delta = -N`. Each of the `N` intents independently hits `amount == 1 <= 1` and returns `Pips::ZERO`, so `fee_ceil` charges nothing on any of them, while the same `N` units moved in a single intent (`amount = N > 1`) would have incurred `protocol_fee.fee_ceil(N) > 0`. All `N` intents can be submitted together in one `execute_signed_intents`/`execute_intents` call [4](#0-3) , since the engine simply loops over the signed payloads and commits a fresh nonce per payload — there is no aggregation of fee-liable amount across the batch, and no guard checks for this splitting pattern (`MultiPayload::verify`, `verify_intent_nonce`, `commit_nonce` etc. only enforce authenticity/replay-protection, not fee aggregation).

### Impact Explanation
The fee owed to `fee_collector` is under-collected: for a decomposed `Nep245` transfer of size `N`, actual fees collected are `0` instead of `protocol_fee.fee_ceil(N)`. This is repeatable indefinitely across tokens, accounts, and batches (any attacker pair with `Nep245`/`Imt` balances), and the value moved has no upper bound beyond gas/batch-size limits. This falls squarely into the Critical category "protocol fees bypassed... at the fee_collector's expense," since no unauthorized signature or invariant violation is needed — only granularity of legitimately signed intents.

### Likelihood Explanation
Preconditions are minimal: the attacker only needs two accounts they control with `Nep245` (or `Imt`) balances in the Verifier (obtainable via ordinary wrapping/`mt_transfer_call` flows shown in the existing test suite) and the ability to sign and submit `N` matched `TokenDiff` payloads. No privileged role, relayer key, or victim key is required. The only cost is transaction/gas overhead for `N` small intents instead of 1 large one, which is linear and bounded by NEAR gas limits per call (splittable across multiple `execute_intents` calls if needed). This is highly feasible and fully reproducible offline.

### Recommendation
Compute/aggregate the fee-liable amount per `(signer, token)` pair across the entire intent batch (or at minimum disallow the `amount <= 1` fee exemption for `Nep245`/`Imt` types, since unlike `Nep171` their `total_supply` is not capped at 1), so that the zero-fee branch only applies to genuinely atomic assets. Alternatively, restrict the exemption using the token's own supply/decimals metadata rather than the per-intent delta amount.

### Proof of Concept
`cargo test` (unit test in `contracts/defuse/core/src/intents/token_diff.rs` or a `near-workspaces`/sandbox test in `tests/src/tests/defuse/intents/token_diff.rs`):
1. Deploy Defuse with `protocol_fee = Pips::ONE_PERCENT` (or any non-zero fee), fee_collector = C.
2. Create a `Nep245TokenId` wrapping a valuable NEP-141 asset (e.g. via `mt_transfer_call` from a NEP-141-backed Defuse instance as in `tests/src/tests/defuse/tokens/nep245/mod.rs`), deposit `N = 1000` units to attacker-controlled account A, and set up matching account B.
3. Case 1 (single intent): sign/execute one `TokenDiff` pair moving `N` units of the `Nep245` token from A to B; assert `fee_collector` balance increases by `protocol_fee.fee_ceil(N)` (non-zero).
4. Case 2 (split intents): sign/execute `N` separate `TokenDiff` pairs each moving `1` unit of the same `Nep245` token from A to B in a single `execute_intents(signed)` call; assert `fee_collector` balance increases by `0`.
5. Assert `Case 1 fee > Case 2 fee` for the same aggregate economic amount `N`, demonstrating the fee-collector-side deficit and confirming the broken binding `fee_owed(N) == Σ fee_ceil(1)`.

    pub fn token_fee(token_id: impl Into<TokenIdType>, amount: u128, fee: Pips) -> Pips {
        let token_id = token_id.into();
        match token_id {
            TokenIdType::Nep141 => {}
            TokenIdType::Nep245 | TokenIdType::Imt if amount > 1 => {}
            // do not take fees on NFTs and MTs with |delta| <= 1
            TokenIdType::Nep171 | TokenIdType::Nep245 | TokenIdType::Imt => return Pips::ZERO,
        }
        fee
