### Title
Relay control-plane trusts an unauthenticated `RelayFromAddr` claim, letting any tunnel-holding peer impersonate another node's VPN address in relay state - (File: relay_manager.go)

### Summary
`relayManager.handleCreateRelayRequest` accepts the `RelayFromAddr` field out of an incoming `NebulaControl_CreateRelayRequest` message and uses it directly as the VPN address to register relay state for, without ever checking that this address matches the VPN address(es) actually bound to the sending peer's authenticated certificate (`h.vpnAddrs`). This mirrors the DYAD `burnDyad` flaw: a caller is authenticated as *some* identity, but the function acts on a caller-supplied identifier for a *different* identity without verifying ownership.

### Finding Description
`AddRelay`/`handleCreateRelayRequest` in `relay_manager.go` process the `RelayFromAddr`/`RelayToAddr` fields taken straight from the wire message `m`: [1](#0-0) [2](#0-1) 

`from` (`RelayFromAddr`) is only checked to ensure it isn't the local node's own address (`f.myVpnAddrsTable.Contains(from)`); it is never checked against `h.vpnAddrs`, i.e. the VPN address(es) that were cryptographically bound to the certificate presented by `h` during the Noise handshake (`handshake.Machine.validateCert` / `HandshakeManager.validatePeerCert`): [3](#0-2) [4](#0-3) 

Because the certificate binds `h.vpnAddrs` to `h`'s Noise static key, `h` cannot forge a *tunnel* for another address — but the relay control message's `RelayFromAddr`/`RelayToAddr` fields are plain protobuf fields inside the `Control` channel payload and are never cross-checked against that bound identity. The legitimate initiator path (`StartRelays`) always sets `RelayFromAddr` to its own `f.myVpnAddrs[0]`: [5](#0-4) 
but the responder path never enforces that this invariant actually holds for an attacker-controlled message.

As a result, any peer `h` that has completed a normal handshake (i.e. holds a valid certificate for its *own* address, but not for the address it names in `RelayFromAddr`) can:
- If `target == me`: cause `AddRelay(rm.l, h, f.hostMap, from, ...)` to register `h` as the `TerminalType`, `Established` relay for the arbitrary `from` address it supplied — i.e., register itself in the local hostmap as an authorized relay endpoint for a victim address it does not own: [6](#0-5) 
- If `target != me`: cause the local node to allocate `ForwardingType` relay state keyed on the attacker-supplied `from` and to send `CreateRelayRequest`s toward `target` on behalf of that spoofed address: [7](#0-6) 

### Impact Explanation
This lets an authenticated-but-unrelated peer inject relay state that associates its own tunnel with an arbitrary victim VPN address, without ever presenting a certificate for that address. Since relay state directly influences how traffic addressed to that VPN address is subsequently forwarded (`RelayState.CopyRelayForIps`, `unlockedGetHostList`, `SendVia`), this is a remote state-poisoning / traffic-redirection primitive against the hostmap/relay trust model — an attacker can insert itself as a "relay" for a peer's address it has no certificate for, potentially diverting or intercepting traffic destined for that peer through itself.

### Likelihood Explanation
Exploitation only requires the attacker to run a normal Nebula node with a valid (self) certificate that is allowed to communicate with the target relay node — no privilege beyond a standard peer role is needed, and the vulnerable code path (`HandleControlMsg` → `handleCreateRelayRequest`) is reached automatically whenever `useRelays` is enabled and a `Control`/`CreateRelayRequest` message is received. The only gating factor is having any established tunnel to the node under attack, which is the normal operating mode of the mesh.

### Recommendation
In `handleCreateRelayRequest` (and `handleCreateRelayResponse`), validate that `from` (`RelayFromAddr`) is contained in `h.vpnAddrs` (the addresses cryptographically bound to the sender's verified certificate) before creating or updating any `Relay`/`RelayState` entries. Reject the message otherwise, analogous to adding an ownership check before performing the privileged action.

### Proof of Concept
1. Stand up three nodes signed by the same CA: `Victim` (address `V`), `Relay` (address `R`, `am_relay`-capable, tunnel established with both `Victim` and `Attacker`), and `Attacker` (address `A`).
2. `Attacker` completes a normal handshake with `Relay` (obtaining a valid `HostInfo h` for `A` on `Relay`).
3. `Attacker` crafts and sends a `Control` message of type `NebulaControl_CreateRelayRequest` to `Relay` with `RelayFromAddr = V` (the victim's address, not `A`'s) and `RelayToAddr = Relay`'s own address.
4. On `Relay`, `relayManager.HandleControlMsg` → `handleCreateRelayRequest` executes; since `f.myVpnAddrsTable.Contains(target)` is true and there is no check that `from == h.vpnAddrs[0]`, `AddRelay(rm.l, h, f.hostMap, V, ...)` runs, registering `h` (bound to `Attacker`'s tunnel) as an `Established` `TerminalType` relay for `V` in `Relay`'s hostmap — despite `Attacker` never having presented a certificate for `V`.
5. Inspect `Relay`'s hostmap/relay state (`h.relayState.QueryRelayForByIp(V)`) to confirm the spoofed relay entry now exists, redirecting `Relay`'s future relay-forwarding decisions for `V` toward `Attacker`'s tunnel.

func (rm *relayManager) handleCreateRelayRequest(v cert.Version, h *HostInfo, f *Interface, m *NebulaControl) {
	//nil-checks for protoAddrToNetAddr handled by caller
	from := protoAddrToNetAddr(m.RelayFromAddr)
	target := protoAddrToNetAddr(m.RelayToAddr)

	logMsg := rm.l.With(
		"relayFrom", from,
		"relayTo", target,
		"initiatorRelayIndex", m.InitiatorRelayIndex,
		"vpnAddrs", h.vpnAddrs,
	)

	logMsg.Info("handleCreateRelayRequest")
	// Is the source of the relay me? This should never happen, but did happen due to
	// an issue migrating relays over to newly re-handshaked host info objects.
	if f.myVpnAddrsTable.Contains(from) {
		logMsg.Error("Discarding relay request from myself", "myIP", from)
		return
	}

	// Is the target of the relay me?
	if f.myVpnAddrsTable.Contains(target) {
		existingRelay, ok := h.relayState.QueryRelayForByIp(from)
		if ok {
			switch existingRelay.State {
			case Requested:
				ok = h.relayState.CompleteRelayByIP(from, m.InitiatorRelayIndex)
				if !ok {
					logMsg.Error("Relay State not found")
					return
				}
			case Established:
				if existingRelay.RemoteIndex != m.InitiatorRelayIndex {
					// We got a brand new Relay request, because its index is different than what we saw before.
					// This should never happen. The peer should never change an index, once created.
					logMsg.Error("Existing relay mismatch with CreateRelayRequest",
						"existingRemoteIndex", existingRelay.RemoteIndex)
					return
				}
			case Disestablished:
				if existingRelay.RemoteIndex != m.InitiatorRelayIndex {
					// We got a brand new Relay request, because its index is different than what we saw before.
					// This should never happen. The peer should never change an index, once created.
					logMsg.Error("Existing relay mismatch with CreateRelayRequest",
						"existingRemoteIndex", existingRelay.RemoteIndex)
					return
				}
				// Mark the relay as 'Established' because it's safe to use again
				h.relayState.UpdateRelayForByIpState(from, Established)
			case PeerRequested:
				// I should never be in this state, because I am terminal, not forwarding.
				logMsg.Error("Unexpected Relay State found",
					"existingRemoteIndex", existingRelay.RemoteIndex,
					"state", existingRelay.State)
			}
		} else {
			_, err := AddRelay(rm.l, h, f.hostMap, from, &m.InitiatorRelayIndex, TerminalType, Established)
			if err != nil {
				logMsg.Error("Failed to add relay", "error", err)
				return
			}
		}

		relay, ok := h.relayState.QueryRelayForByIp(from)
		if !ok {
			logMsg.Error("Relay State not found", "from", from)
			return
		}

func (m *Machine) validateCert(payload Payload) error {
	cred := m.getCred(m.myVersion)
	if cred == nil {
		m.failed = true
		return fmt.Errorf("%w: %v", ErrNoCredential, m.myVersion)
	}
	rc, err := cert.Recombine(
		cert.Version(payload.CertVersion),
		payload.Cert,
		m.hs.PeerStatic(),
		cred.Cert.Curve(),
	)
	if err != nil {
		m.failed = true
		return fmt.Errorf("recombine cert: %w", err)
	}

	if !bytes.Equal(rc.PublicKey(), m.hs.PeerStatic()) {
		m.failed = true
		return ErrPublicKeyMismatch
	}

	// Version negotiation, if the peer sent a different version and we have it, switch
	if rc.Version() != m.myVersion {
		if m.getCred(rc.Version()) != nil {
			m.myVersion = rc.Version()
		}
	}

	verified, err := m.verifier(rc)
	if err != nil {
		m.failed = true
		return fmt.Errorf("verify cert: %w", err)
	}

	m.result.RemoteCert = verified
	m.remoteCertSet = true
	return nil

// validatePeerCert checks the peer certificate for self-connection and remote allow list.
// Returns the VPN addrs, whether any of them fall within one of our own VPN
// networks, and true if valid; false if rejected.
func (hm *HandshakeManager) validatePeerCert(via ViaSender, remoteCert *cert.CachedCertificate) ([]netip.Addr, bool, bool) {
	f := hm.f
	vpnNetworks := remoteCert.Certificate.Networks()

	// The cert package rejects host certs with no networks at parse time, so
	// reaching this state would mean an invariant was bypassed elsewhere.
	// Refuse explicitly so downstream code (which indexes vpnAddrs[0]) can't
	// panic if that invariant ever changes.
	if len(vpnNetworks) == 0 {
		f.l.Info("No networks in certificate",
			"from", via, "cert", remoteCert)
		return nil, false, false
	}

	vpnAddrs := make([]netip.Addr, len(vpnNetworks))
	anyVpnAddrsInCommon := false

	for i, network := range vpnNetworks {
		if f.myVpnAddrsTable.Contains(network.Addr()) {
			f.l.Error("Refusing to handshake with myself",
				"vpnNetworks", vpnNetworks,
				"from", via,
				"certName", remoteCert.Certificate.Name(),
				"certVersion", remoteCert.Certificate.Version(),
				"fingerprint", remoteCert.Fingerprint,
				"issuer", remoteCert.Certificate.Issuer(),
			)
			return nil, false, false
		}
		vpnAddrs[i] = network.Addr()
		if f.myVpnNetworksTable.Contains(network.Addr()) {
			anyVpnAddrsInCommon = true
		}
	}

	if !via.IsRelayed {
		if !f.lightHouse.GetRemoteAllowList().AllowAll(vpnAddrs, via.UdpAddr.Addr()) {
			f.l.Debug("lighthouse.remote_allow_list denied incoming handshake",
				"vpnAddrs", vpnAddrs, "from", via)
			return nil, false, false
		}
	}

	return vpnAddrs, anyVpnAddrsInCommon, true
