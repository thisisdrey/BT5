### Title
`initialize()` functions across upgradeable contracts can be frontrun, allowing attacker-supplied config - (File: `contracts/Pool.sol`, `contracts/PoolRegistry.sol`)

### Summary
All core Metronome Synth contracts are `Initializable` proxies whose `initialize()` functions carry no authorization beyond the `initializer` modifier. Anyone can call them on a freshly deployed proxy before the deployer's initialization transaction lands, permanently taking over the initialization parameters (including `poolRegistry`, `masterOracle`, and `feeCollector`).

### Finding Description
`Pool.initialize(IPoolRegistry poolRegistry_)` is `public initializer` with no deployer/sender check: it stores the caller-supplied `_poolRegistry` and sets `isSwapActive`/`maxLiquidable`. Because every privileged path in `Pool` (`onlyGovernor`, `onlyIfCanMint`, `isGuardian`, `feeCollector()`, `masterOracle()`, `operator()` resolution in `SynthContext._msgSender`) resolves through `_poolRegistry`, an attacker who supplies their own `PoolRegistry` gains effective governance of the pool proxy. [1](#0-0) 

`PoolRegistry.initialize(IMasterOracle masterOracle_, address feeCollector_)` is likewise unprotected; a frontrunner sets the oracle and fee collector of the canonical registry proxy. [2](#0-1) 

The implementations call `_disableInitializers()` in their constructors, so the bug only affects the proxy instances at deployment time — exactly the same shape as the USSD finding. [3](#0-2) 

The same pattern repeats across `DebtToken`, `DepositToken`, `SyntheticToken`, `Treasury`, `FeeProvider`, `RewardsDistributor`, `SmartFarmingManager`, `AMO`, and `ProxyOFT` — all have `initialize` + `initializer` with no authorization.

### Impact Explanation
- Worst case: if the deployer (or the rest of the ecosystem wired to the proxy address) proceeds to use the frontrun proxy, the attacker controls `poolRegistry`/`masterOracle`/`feeCollector`, which cascades to full control of governor-gated setters (`addDepositToken`, `updateTreasury`, `updateFeeProvider`, `updateMasterOracle`), oracle quotes used by `swap`/`liquidate`, and fee flows — direct theft of user funds and protocol insolvency.
- Likely case: the deployer notices their `initialize` tx reverted (`Initializable: contract is already initialized`) and must redeploy the proxy, incurring gas/deployment cost and delaying launch — a liveness/operational cost identical in kind to the referenced USSD medium finding.

### Likelihood Explanation
Requires winning a mempool race on the deployment transaction — trivially achievable on public mempools (Ethereum mainnet, BSC, Optimism, Base — all of which have deployments in this repo) or via a generalized frontrunner bot. No privileged role is needed. However, real impact depends on the deployer continuing to use a poisoned proxy, which is why this is medium rather than high.

### Recommendation
- Initialize in the same transaction as proxy deployment (e.g., `TransparentUpgradeableProxy`/`ERC1967Proxy` constructor `data` argument, or OpenZeppelin `upgrades.deployProxy`), which makes frontrunning impossible.
- Alternatively, record `msg.sender` in the proxy constructor or gate `initialize` with an `onlyDeployer` check.

### Proof of Concept
Foundry fork-style test outline:

```solidity
function testFrontrunInitialize() public {
    // Deployer deploys implementation + proxy, but initialization tx is pending
    Pool impl = new Pool();
    ERC1967Proxy proxy = new ERC1967Proxy(address(impl), "");
    Pool pool = Pool(address(proxy));

    // Attacker frontruns the deployer's initialize() call
    MaliciousRegistry evil = new MaliciousRegistry(); // returns attacker as governor/oracle/feeCollector
    vm.prank(attacker);
    pool.initialize(IPoolRegistry(address(evil))); // succeeds — no auth check

    // Deployer's legitimate initialize now reverts
    vm.prank(deployer);
    vm.expectRevert("Initializable: contract is already initialized");
    pool.initialize(IPoolRegistry(address(realRegistry)));

    // Attacker-controlled registry => attacker controls governor-gated functions
    assertEq(address(pool.poolRegistry()), address(evil));
}
```

The identical flow applies to `PoolRegistry.initialize` (attacker sets `masterOracle` and `feeCollector`), giving control over all pricing and fee collection if the poisoned registry proxy is used downstream.
