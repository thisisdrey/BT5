### Title
Unauthenticated, unbounded HTTP body read in the signer's event receiver causes memory-exhaustion DoS - (File: libsigner/src/events.rs)

### Summary
`SignerEventReceiver::next_event` accepts unauthenticated POST requests on the signer's event-listener socket and dispatches them to `process_event`, which reads the entire request body into memory with `request.as_reader().read_to_string(&mut body)` with no `Content-Length` cap and no maximum-body-size check anywhere in the path.

### Finding Description
The signer runs a plain HTTP server (`tiny_http`, wrapped as `HttpServer` in `libsigner/src/events.rs`) to receive events pushed by a Stacks node (`/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block`). [1](#0-0) 

Once a POST is routed, `process_event` reads the whole body into a `String` without ever consulting `Content-Length`, without any `MAX_MESSAGE_LEN`/`MAX_PAYLOAD_LEN`-style cap, and without any authentication check: [2](#0-1) 

This stands in stark contrast to every comparable HTTP body-consuming path elsewhere in this codebase, all of which explicitly bound the body size against the advertised `Content-Length` before allocating/parsing:
- `postblock.rs` / `postblock_v3.rs` reject bodies whose `Content-Length` exceeds `MAX_PAYLOAD_LEN`. [3](#0-2) 
- `posttransaction.rs` does the same. [4](#0-3) 
- `poststackerdbchunk.rs` rejects bodies over `MAX_MESSAGE_LEN`. [5](#0-4) 
- `fastcallreadonly.rs`/`callreadonly.rs` enforce `maximum_call_argument_size`. [6](#0-5) 
- The node's own P2P/HTTP framing layer (`httpcore.rs`) always derives `payload_len` from `Content-Length` and bounds preamble/message sizes with `MAX_MESSAGE_LEN`/`BoundReader`. [7](#0-6) 
- Even libsigner's own outbound HTTP client path (`run_http_request`/`decode_http_body`) bounds chunked bodies via `HttpChunkedTransferReader::from_reader(ptr, MAX_MESSAGE_LEN.into())`. [8](#0-7) 

The event receiver's inbound path is the one exception: it never checks `Content-Length` against any cap and never bounds the read, breaking the equality that every other body-consuming endpoint in this repo enforces ("advertised/received length ≤ bound before allocating"). Any TCP peer that can reach the signer's bound port can open a connection and POST an arbitrarily large body to any of the routed URLs (or an unrecognized one, which still gets fully read before falling through to `ack_dispatcher`) — no signature, no shared secret, no StackerDB check, and no size ceiling gate this. The `HttpServer::http(listener)` binds directly on the operator-configured address; nothing in `events.rs` restricts inbound peers by IP or requires prior authentication before the body is buffered.

### Impact Explanation
Because the body is buffered fully into a `String` with no bound, a single crafted request with a very large `Content-Length`/body can force the signer process to allocate memory proportional to the attacker's payload, exhausting available memory and crashing or freezing the signer (denial of service against a validator-critical component). This matches CWE-400/CWE-770, the same bug class as the referenced KubeEdge CloudHub `/edge.crt` advisory (unauthenticated read of an oversized HTTP body into memory with no length bound). Given that signer availability is directly tied to block validation/signing liveness in Nakamoto consensus, an availability failure here has outsized operational significance.

### Likelihood Explanation
This is exploitable with a single unauthenticated HTTP request from any network peer that can reach the signer's bound listener address/port; no cryptographic material, session state, or prior interaction with the Stacks node is required. The only mitigating factor is deployment-dependent: if operators bind the listener strictly to `127.0.0.1` or a private/firewalled interface reachable only by their own node, exposure is reduced; if bound more broadly (e.g., to satisfy a remote/containerized node relationship), it is directly internet-reachable. The code itself provides no defense-in-depth (no size cap, no auth), unlike every sibling endpoint in the repository, so likelihood is high whenever the port is reachable by an untrusted party.

### Recommendation
- Before calling `read_to_string`, check the request's `Content-Length` header (as `libsigner/src/http.rs::decode_http_request` already parses headers) against a fixed cap analogous to `MAX_MESSAGE_LEN`/`STACKERDB_MAX_CHUNK_SIZE`, and reject/close the connection if it is missing or exceeds the cap.
- Bound the actual read with a `Read::take(cap)` (or an equivalent bounded reader, mirroring `HttpChunkedTransferReader::from_reader(ptr, MAX_MESSAGE_LEN.into())` already used in `libsigner/src/http.rs`) so that even a spoofed/absent `Content-Length` cannot cause unbounded buffering.
- Consider requiring a shared secret or mTLS between the node and the signer's event endpoint, consistent with the "eventing" channel being a trust boundary that currently has none.

### Proof of Concept
1. Configure/start a `stacks-signer` with its event receiver bound to a reachable address (e.g., `endpoint = "0.0.0.0:<port>"`).
2. From an unauthenticated remote host, open a TCP connection to `<signer-ip>:<port>`.
3. Send:
   ```
   POST /stackerdb_chunks HTTP/1.1\r\n
   Host: <signer-ip>:<port>\r\n
   Content-Type: application/json\r\n
   Content-Length: 4294967295\r\n
   Connection: close\r\n\r\n
   ```
   followed by a very large stream of arbitrary bytes (or repeated chunked payloads) with no client-side cap.
4. `SignerEventReceiver::next_event` → `process_event` (`libsigner/src/events.rs:519-537`) reads the entire body via `read_to_string` with no size check, causing the signer process's memory usage to grow unbounded until the process is OOM-killed or the host becomes unresponsive — reproducing the KubeEdge CloudHub-style DoS in the signer.

    fn next_event(&mut self) -> Result<SignerEvent<T>, EventError> {
        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)
            } else if request.url() == "/new_block" {
                process_event::<T, StacksBlockEvent>(request)
            } else {
                let url = request.url().to_string();
                debug!(
                    "[{:?}] next_event got request with unexpected url {}, return OK so other side doesn't keep sending this",
                    event_receiver.local_addr,
                    url
                );
                ack_dispatcher(request);
                Err(EventError::UnrecognizedEvent(url))
            }
        })?

fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));

    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

/// Decode an HTTP body, given the headers.
pub fn decode_http_body(headers: &HashMap<String, String>, mut buf: &[u8]) -> io::Result<Vec<u8>> {
    let chunked = if let Some(val) = headers.get("transfer-encoding") {
        val == "chunked"
    } else {
        false
    };

    let body = if chunked {
        // chunked encoding
        let ptr = &mut buf;
        let mut fd = HttpChunkedTransferReader::from_reader(ptr, MAX_MESSAGE_LEN.into());
        let mut decoded_body = vec![];
        fd.read_to_end(&mut decoded_body)?;
        decoded_body
    } else {
        // body is just as-is
        buf.to_vec()
    };

    Ok(body)
}
