### Title
Flashloan-manipulable utilization rate lets an attacker bias a bank's interest accrual for its entire pending period - (File: `programs/marginfi/src/state/bank.rs`)

### Summary
Marginfi's permissionless `lending_pool_accrue_bank_interest` instruction computes the interest rate charged for the *entire* elapsed `time_delta` since the last accrual using only the **instantaneous** `total_assets`/`total_liabilities` snapshot taken at call time, rather than a time-weighted average. This mirrors the Aragon `EarlyExecution` bug class: a transient, flashloan-funded balance change is used to force a state transition (here, locking in an interest rate for a whole accrual period) that persists after the temporary capital is withdrawn.

### Finding Description
`accrue_interest` on `Bank` computes `time_delta = current_timestamp - self.last_update`, reads `total_assets`/`total_liabilities` at that instant, derives `utilization_rate = total_liabilities / total_assets`, and then applies the resulting APR to the **entire** `time_delta` (which can be hours, days, or longer if no one has called the permissionless accrual instruction recently): [1](#0-0) [2](#0-1) 

The utilization ratio and resulting APR feed directly into `calc_interest_rate_accrual_state_changes`, which multiplies the rate by the full `time_delta` to update `asset_share_value`/`liability_share_value` and collect protocol/group/insurance fees for that whole period: [3](#0-2) 

`lending_pool_accrue_bank_interest` is a fully permissionless, unprivileged instruction: [4](#0-3) 

Because `total_assets`/`total_liabilities` are read fresh, in-instruction, an attacker can, within a single atomic Solana transaction:
1. Deposit a large flashloaned amount of the bank's asset into the bank (a normal, always-available `lending_account_deposit`, no `ACCOUNT_IN_FLASHLOAN` gating required since no borrow/repay pairing is needed for a pure deposit/withdraw).
2. Call the permissionless `lending_pool_accrue_bank_interest`, which locks in a *lower* utilization ratio (hence lower borrow APR / lower lender APR / lower fee accrual) for the **entire pent-up `time_delta`** since the last accrual.
3. Withdraw the deposit back out, unwinding the position with no lasting exposure and repaying the flashloan.

This is structurally identical to the Aragon report's pattern: temporarily inflating a balance (`lockAndVote` collateral / here, bank deposit) to trigger an action with effects that outlive the position (`_attemptEarlyExecution` / here, `accrue_interest`'s permanent update of `asset_share_value`/`liability_share_value` and fee accrual for the whole elapsed period), then reversing the position before any subsequent check can catch the manipulation. There is no TWAP, no minimum observation window, and no restriction preventing deposit → accrue → withdraw in the same transaction.

### Impact Explanation
Successful exploitation permanently and irreversibly biases the accrued interest state (`asset_share_value`, `liability_share_value`, `collected_group_fees_outstanding`, `collected_insurance_fees_outstanding`) for the entire elapsed accrual period, using capital that was never actually at risk in the pool for that period. This constitutes an unauthorized state change / theft of yield: real depositors receive less interest than they should have, and protocol/insurance/group fees are permanently under-collected for that period, while the same or another account can use the same trick to depress its own effective borrowing cost over an extended backlog. Repeated abuse (e.g., against banks whose permissionless `accrue_interest` is called infrequently) directly reduces protocol/insurance solvency margins over time.

### Likelihood Explanation
Likelihood depends on how long `time_delta` is allowed to accumulate before `lending_pool_accrue_bank_interest` is called (keeper cadence) and on the size of capital an attacker can access via a flashloan relative to the bank's total assets — the bigger `time_delta` and the more the attacker can move the utilization ratio, the larger the bias. Since the instruction is fully permissionless and requires no special account state or privilege, and the deposit/accrue/withdraw sequence can be built entirely from existing, always-available instructions in one atomic transaction, exploitation is straightforward for any bank that goes a non-trivial amount of time between accrual calls.

### Recommendation
- Use a time-weighted / checkpointed utilization measure (e.g., sample utilization at multiple points, or require `accrue_interest` calls at bounded intervals) instead of a single instantaneous read applied to an unbounded `time_delta`.
- Alternatively, cap the `time_delta` used for the utilization snapshot (segment large gaps into smaller windows, resampling utilization at some fixed cadence) so a single-instant deposit cannot bias an arbitrarily long backlog.
- Consider blocking large intra-transaction deposit+withdraw sequences immediately surrounding an `accrue_interest` call, or requiring that `accrue_interest` cannot be combined with deposit/withdraw of the same bank in the same transaction by the same fee payer/authority.

### Proof of Concept
Conceptual PoC (Solana, single atomic transaction, unprivileged actor):
1. Flashloan (from any external protocol, or use idle capital) a large amount of Bank X's asset mint.
2. `lending_account_deposit` into Bank X with the flashloaned amount, drastically lowering `utilization_rate = total_liabilities / total_assets`.
3. Call permissionless `lending_pool_accrue_bank_interest` on Bank X — this locks in the depressed APR for the full backlog `time_delta` via `accrue_interest`/`calc_interest_rate_accrual_state_changes` [2](#0-1) .
4. `lending_account_withdraw` the deposited amount back out in the same transaction.
5. Repay the flashloan.

Result: `asset_share_value`/`liability_share_value` and collected fees for Bank X are permanently updated based on a utilization ratio that existed only for the duration of one transaction, biasing the true accrued interest for the entire elapsed period, at no lasting capital cost to the attacker.

        let total_liabilities = self.get_liability_amount(self.total_liability_shares.into())?;

        self.last_update = current_timestamp;

pub fn calc_interest_rate_accrual_state_changes(
    time_delta: u64,
    total_assets_amount: I80F48,
    total_liabilities_amount: I80F48,
    interest_rate_calc: &InterestRateCalc,
    asset_share_value: I80F48,
    liability_share_value: I80F48,
) -> MarginfiResult<InterestRateStateChanges> {
    // If the cache is empty, we need to calculate the interest rates
    let utilization_rate: I80F48 = total_liabilities_amount
        .checked_div(total_assets_amount)
        .ok_or_else(math_error!())?;
    debug!(
        "Utilization rate: {}, time delta {}s",
        utilization_rate, time_delta
    );
    let interest_rates = interest_rate_calc.calc_interest_rate(utilization_rate)?;

    debug!("{:#?}", interest_rates);

    let ComputedInterestRates {
        lending_rate_apr,
        borrowing_rate_apr,
        group_fee_apr,
        insurance_fee_apr,
        protocol_fee_apr,
        ..
    } = interest_rates;

    Ok(InterestRateStateChanges {
        new_asset_share_value: calc_accrued_interest_payment_per_period(
            lending_rate_apr,
            time_delta,
            asset_share_value,
        )
        .ok_or_else(math_error!())?,
        new_liability_share_value: calc_accrued_interest_payment_per_period(
            borrowing_rate_apr,
            time_delta,
            liability_share_value,
        )
        .ok_or_else(math_error!())?,
        insurance_fees_collected: calc_interest_payment_for_period(
            insurance_fee_apr,
            time_delta,
            total_liabilities_amount,
        )
        .ok_or_else(math_error!())?,
        group_fees_collected: calc_interest_payment_for_period(
            group_fee_apr,
            time_delta,
            total_liabilities_amount,
        )
        .ok_or_else(math_error!())?,
        protocol_fees_collected: calc_interest_payment_for_period(
            protocol_fee_apr,
            time_delta,
            total_liabilities_amount,
        )
        .ok_or_else(math_error!())?,
    })
}
