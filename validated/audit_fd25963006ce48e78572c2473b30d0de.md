### Title
ECDSA legacy signing leaks ephemeral nonce via non-constant-time `big.Int.ModInverse` - ([File: src/crypto/ecdsa/ecdsa_legacy.go])

### Summary
`signLegacy` computes `kInv = new(big.Int).ModInverse(k, N)` where `k` is a fresh, secret per-signature ephemeral nonce, using `math/big`'s Lehmer/Euclidean `GCD`-based `ModInverse`, which Go explicitly documents as not constant-time. This mirrors the Mbed TLS bug class in ALPINE-CVE-2025-54764 (`mbedtls_mpi_mod_inv`/`mbedtls_mpi_gcd` leaking through timing when applied to secret values), except here it is the ECDSA ephemeral scalar rather than an RSA CRT parameter that is exposed.

### Finding Description
`crypto/ecdsa.Sign`/`SignASN1` route to `signLegacy` for any `*PrivateKey` whose `Curve` is a custom (non-fips140/nistec) `elliptic.Curve` implementation [1](#0-0) . Inside the per-signature retry loop, a fresh secret nonce `k` is drawn via `randFieldElement`, and its modular inverse is computed with `kInv = new(big.Int).ModInverse(k, N)` [2](#0-1) . `big.Int.ModInverse` internally calls `GCD`, which for values with more than one word dispatches to `lehmerGCD`, an inherently variable-time Euclidean-style algorithm whose iteration count and operations depend on the bit pattern of the operands [3](#0-2) [4](#0-3) . `Exp`'s doc comment and `ModInverse`'s implementation give no constant-time guarantee [5](#0-4) . Because `k` is secret per-signature material, an attacker able to measure signing latency across many signatures (network or local timing) can obtain partial information about `k`, enabling lattice-based nonce-bias key-recovery attacks against the private key `D`, the same primitive class as the historical "Minerva"/ECDSA-nonce-timing attacks. Go's own codebase acknowledges this general risk elsewhere: `crypto/dsa`'s `fermatInverse` explicitly avoids `math/big.Int.ModInverse` for exactly this reason ("This has better constant-time properties than Euclid's method (implemented in math/big.Int.ModInverse) ... math/big itself isn't strictly constant-time") [6](#0-5) , but no equivalent mitigation exists in `signLegacy`.

### Impact Explanation
Concrete impact: local/observable timing side channel on the ECDSA ephemeral nonce, which can leak enough bits to permit lattice attacks recovering the long-term private key `D` after collecting a number of signatures — a confidentiality/integrity bypass of the signing key, not merely resource exhaustion. This maps to Go's **PUBLIC** track at best: the affected path (`signLegacy`) is explicitly gated to "deprecated custom curves" only [7](#0-6) , i.e. it is not exercised by any standard NIST curve (P-224/256/384/521) which instead use the constant-time `fips140/nistec` implementation. This significantly limits real-world exposure to applications that deliberately register and use a legacy/custom `elliptic.Curve`.

### Likelihood Explanation
The victim workflow requires an application to still be using a **custom, non-standard curve** with `crypto/ecdsa.Sign`/`SignASN1` (e.g., serving repeated signatures such as TLS handshakes or a signing oracle) and an attacker capable of measuring signing time with sufficient precision across many samples. This is a narrow, opt-in configuration (deprecated legacy path), and Go's standard curves are unaffected, which reduces likelihood substantially compared to a default-path RSA/TLS timing bug.

### Recommendation
Replace `ModInverse` in `signLegacy` with a Fermat's-little-theorem-based exponentiation (`kInv = k^(N-2) mod N` via `big.Int.Exp`), matching the mitigation already used in `crypto/dsa.fermatInverse`, or migrate remaining custom-curve consumers to constant-time scalar arithmetic.

		t.Fatal(err)

	rand.Read(hash)

	const n = 2000
	durations := make([]time.Duration, n)
	for i := 0; i < n; i++ {
		start := time.Now()
		if _, _, err := ecdsa.Sign(rand.Reader, priv, hash); err != nil {
			t.Fatal(err)
		}
		durations[i] = time.Since(start)
	}

	// constant-time inversion (e.g., Fermat's method) were used instead.

// GCD sets z to the greatest common divisor of a and b and returns z.
// If x or y are not nil, GCD sets their value such that z = a*x + b*y.
//
// a and b may be positive, zero or negative. (Before Go 1.14 both had
// to be > 0.) Regardless of the signs of a and b, z is always >= 0.
//
// If a == b == 0, GCD sets z = x = y = 0.
//
// If a == 0 and b != 0, GCD sets z = |b|, x = 0, y = sign(b) * 1.
//
// If a != 0 and b == 0, GCD sets z = |a|, x = sign(a) * 1, y = 0.
func (z *Int) GCD(x, y, a, b *Int) *Int {
	if len(a.abs) == 0 || len(b.abs) == 0 {
		lenA, lenB, negA, negB := len(a.abs), len(b.abs), a.neg, b.neg
		if lenA == 0 {
			z.Set(b)
		} else {
			z.Set(a)
		}
		z.neg = false
		if x != nil {
			if lenA == 0 {
				x.SetUint64(0)
			} else {
				x.SetUint64(1)
				x.neg = negA
			}
		}
		if y != nil {
			if lenB == 0 {
				y.SetUint64(0)
			} else {
				y.SetUint64(1)
				y.neg = negB
			}
		}
		return z
	}

	return z.lehmerGCD(x, y, a, b)
}

// fermatInverse calculates the inverse of k in GF(P) using Fermat's method.
// This has better constant-time properties than Euclid's method (implemented
// in math/big.Int.ModInverse) although math/big itself isn't strictly
// constant-time so it's not perfect.
func fermatInverse(k, P *big.Int) *big.Int {
	two := big.NewInt(2)
	pMinus2 := new(big.Int).Sub(P, two)
	return new(big.Int).Exp(k, pMinus2, P)
}
