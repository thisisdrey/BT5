## Analog Found: Unbounded Array-Index Arithmetic in `ValidateMultiSign` Precompile Input Decoder

### Title
Uncaught out-of-bounds array access in `ValidateMultiSign` precompile due to unvalidated offset/length fields - (File: `actuator/src/main/java/org/tron/core/vm/PrecompiledContracts.java`)

### Summary
The FFmpeg bug class is: a size/offset value taken from untrusted input is used to index/copy into a buffer without validating it against the buffer's actual bounds, causing an out-of-bounds memory operation. The closest reachable analog in java-tron is in the `ValidateMultiSign` TVM precompiled contract (address `0x...a`), where attacker-controlled offset/length words from the precompile calldata are used to compute array indices for `Arrays.copyOfRange` without bounds validation, and — unlike its sibling `BatchValidateSign` — this call path is **not** wrapped in an exception guard.

### Finding Description
`ValidateMultiSign.execute()` reads offset fields directly from calldata and uses them, unvalidated, to slice into the raw data array: [1](#0-0) 

The extraction helpers compute `bytesOffset`/`bytesLen` purely from attacker-supplied `DataWord` values and pass them straight into `Arrays.copyOfRange`: [2](#0-1) 

Crucially, this call (`extractSigArray`/`extractBytesArray`) happens **before** the `try { ... } catch (Throwable t)` block that wraps the rest of `ValidateMultiSign.execute()` (the signature-verification logic, lines 1080-1118 in the same file) — it is not covered by that guard.

By contrast, its sibling precompile `BatchValidateSign` wraps its entire `doExecute()` (including the equivalent extraction calls) in a top-level `catch (Throwable t)` that safely returns a default value: [3](#0-2) 

The precompile's `execute()` return value is consumed directly by `Program.callToPrecompiledAddress()` with **no surrounding try/catch**: [4](#0-3) 

This mirrors the FFmpeg root cause structurally: a length/offset value derived from one part of attacker-supplied input (the "second presentation's dimensions") is used to size/index a copy operation into a buffer sized from a different assumption, without a bounds check, and the resulting out-of-bounds access is not caught by any surrounding safety net.

### Impact Explanation
If `extractBytesArray`/`extractSigArray` throws an unchecked exception (e.g. `ArrayIndexOutOfBoundsException` from `Arrays.copyOfRange` in `extractBytes`, or `NegativeArraySizeException` from a crafted negative `len`), the exception propagates out of `ValidateMultiSign.execute()` uncaught, through `callToPrecompiledAddress()` (also unguarded at that call site), and up the TVM execution stack. I was **not able to fully verify** in the time available whether an outer layer (e.g. `TransactionTrace`/`Runtime`) ultimately catches `Throwable` at transaction-application level to merely fail the single transaction, or whether it can propagate further during block application in `Manager` and destabilize node processing. This is the key open question limiting confidence in the "node crash/halt" impact tier; if such an outer catch does not exist for this precompile path, the impact could reach denial-of-service against block application.

### Likelihood Explanation
This precompile is reachable from any contract via a plain `CALL`/`STATICCALL`/`DELEGATECALL` to the fixed address `0x...a`, requiring no special permission — an unprivileged contract deployer or caller can trigger it directly, satisfying the reachability requirement (no malicious-SR/witness/p2p assumptions needed).

### Recommendation
Move the `extractSigArray`/`extractBytesArray` calls (and the `words[...]` index derivations) inside the same `try { } catch (Throwable t)` guard already used to protect the rest of `ValidateMultiSign.execute()`, matching the pattern already used in `BatchValidateSign.execute()`. Additionally, validate `bytesOffset`, `bytesLen`, and `offset + len` against `data.length` before calling `Arrays.copyOfRange`.

  private static byte[][] extractBytesArray(DataWord[] words, int offset, byte[] data) {
    if (offset > words.length - 1) {
      return new byte[0][];
    }
    int len = words[offset].intValueSafe();
    byte[][] bytesArray = new byte[len][];
    for (int i = 0; i < len; i++) {
      int bytesOffset = words[offset + i + 1].intValueSafe() / WORD_SIZE;
      int bytesLen = words[offset + bytesOffset + 1].intValueSafe();
      bytesArray[i] = extractBytes(data, (bytesOffset + offset + 2) * WORD_SIZE,
          bytesLen);
    }
    return bytesArray;
  }

  private static byte[][] extractSigArray(DataWord[] words, int offset, byte[] data) {
    if (offset > words.length - 1) {
      return new byte[0][];
    }
    int len = words[offset].intValueSafe();
    byte[][] bytesArray = new byte[len][];
    for (int i = 0; i < len; i++) {
      int bytesOffset = words[offset + i + 1].intValueSafe() / WORD_SIZE;
      bytesArray[i] = extractBytes(data, (bytesOffset + offset + 2) * WORD_SIZE,
          SIG_LENGTH);
    }
    return bytesArray;
  }

  private static byte[] extractBytes(byte[] data, int offset, int len) {
    return Arrays.copyOfRange(data, offset, offset + len);
  }
