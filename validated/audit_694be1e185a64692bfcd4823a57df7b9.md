### Title
Heap buffer over-read parsing untrusted ZIP/JAR central directory entries in `InputZipFile::ProcessCentralDirEntry` - (File: third_party/ijar/zip.cc)

### Summary
`InputZipFile::ProcessCentralDirEntry` reads a central-directory entry's `file_name_length`, `extra_field_length`, and `file_comment_length` fields and then advances the cursor `p` and the `extra_p` walking pointer by those attacker-controlled 16-bit values with **no bounds check** against the actual size of the mmap'd input file, unlike the sibling function `InputZipFile::ProcessLocalFileEntry`, which explicitly calls `EnsureRemaining()` before consuming `file_name_length_`/`extra_field_length_` bytes. [1](#0-0) [2](#0-1) 

### Finding Description
`ijar`/singlejar-style ZIP parsing in `zip.cc` maps the untrusted archive into memory and walks the central directory starting at `central_dir_` using `ProcessCentralDirEntry`, called both from `InputZipFile::ProcessNext` (used during real extraction/repacking) and from the output-size estimation loop. [3](#0-2) [4](#0-3) 

Inside `ProcessCentralDirEntry`, after validating the 4-byte central-file-header signature, the code unconditionally reads `file_name_length`, `extra_field_length`, `file_comment_length` from the header and then:
- `memcpy`s `file_name_length` bytes from `p` into a fixed `PATH_MAX` buffer (bounded only by the destination buffer size, not by remaining input bytes),
- advances `p` by `file_name_length`, then by `extra_field_length`, walking an inner `extra_p` cursor through the extra-field TLVs reading 2-byte tag/size pairs and advancing by attacker-supplied `data_size`,
- finally advances `p` by `file_comment_length`.
None of these advances are preceded by an `EnsureRemaining()`-style check against `input_file_->Length()`. [5](#0-4) 

The comment above the function claims "the central directory is always followed by another data structure that has a signature, so parsing it this way is safe" — but that only protects the *outer* loop's signature check on the *next* entry; it does not protect the byte-for-byte field reads (`get_u2le`, `memcpy`, extra-field TLV walk) performed *while inside* a single malformed entry whose length fields point past the end of the mapped file. [6](#0-5) 

This is structurally the same bug class as CVE-2017-11734 (Ming's `decompileCALLFUNCTION`): a binary-format parser trusts attacker-supplied length fields taken from a crafted file and reads past the buffer bounds because a bounds check present elsewhere in the same parser (here, `EnsureRemaining()` in `ProcessLocalFileEntry`) is missing in this code path.

### Impact Explanation
A crafted archive (e.g., an `http_archive`/`http_jar` source served by a hostile origin, or an untrusted `.jar`/`.zip` build input processed by ijar/singlejar-style tooling) with a central-directory entry whose `file_name_length`, `extra_field_length`, or extra-field `data_size` values are set larger than the remaining bytes in the mapped file will cause the parser to read heap memory beyond the end of the mmap'd region. This is an out-of-bounds read (information disclosure into `filename`/derived state, or a crash) triggered purely by parsing untrusted file content — no code execution of Starlark or dependency-CVE reasoning is required.

### Likelihood Explanation
Any attacker who can supply a ZIP/JAR file consumed by this ijar code path (a malicious or compromised download source, or an untrusted archive checked out on a CI branch) can trigger this without any special privileges; the only requirement is that the crafted archive's central directory record passes the leading 4-byte signature check, after which none of the length-derived reads are validated against the file's actual size.

### Recommendation
Add the same `EnsureRemaining()` bounds validation used in `ProcessLocalFileEntry` to `ProcessCentralDirEntry` before consuming `file_name_length`, `extra_field_length`, and `file_comment_length` bytes, and before walking the extra-field TLV chain, rejecting the archive with an error rather than reading past `zipdata_in_ + input_file_->Length()`.

### Proof of Concept
Construct a minimal ZIP with a valid End-Of-Central-Directory record and a single central directory header (`CENTRAL_FILE_HEADER_SIGNATURE`) whose `file_name_length` field is set to a value (e.g. 0xFFFF) that extends past the end of the mapped file buffer, with no trailing bytes actually present. Feed it to `ZipExtractor::Create`/`ProcessAll` (as used by `third_party/ijar/zip_main.cc`'s `extract`/`list` path). A JUnit/C++ gtest analogous to the existing `zip_headers_test.cc`/`output_jar_simple_test.cc` malformed-field tests (e.g., extending `CreateZipWithMalformedExtraField`-style helpers) can construct such a truncated central directory entry and assert that `ProcessCentralDirEntry` either returns an error or that an AddressSanitizer build reports a heap-buffer-overflow read rather than silently proceeding.     return false;

bool InputZipFile::ProcessCentralDirEntry(const u1 *&p, u8 *compressed_size,
                                          u8 *uncompressed_size, char *filename,
                                          size_t filename_size, u4 *attr,
                                          u8 *offset) {
  u4 signature = get_u4le(p);

  if (signature != CENTRAL_FILE_HEADER_SIGNATURE) {
    if (signature != DIGITAL_SIGNATURE && signature != EOCD_SIGNATURE &&
        signature != ZIP64_EOCD_SIGNATURE) {
      error("invalid central file header signature: 0x%x\n", signature);
    }
    return false;
  }

  p += 16;  // skip to 'compressed size' field
  *compressed_size = get_u4le(p);
  *uncompressed_size = get_u4le(p);
  u2 file_name_length = get_u2le(p);
  u2 extra_field_length = get_u2le(p);
  u2 file_comment_length = get_u2le(p);
  p += 4;  // skip to external file attributes field
  *attr = get_u4le(p);
  *offset = get_u4le(p);
  {
    size_t len = (file_name_length < filename_size)
      ? file_name_length
      : (filename_size - 1);
    memcpy(reinterpret_cast<void*>(filename), p, len);
    filename[len] = 0;
  }
  p += file_name_length;
  const u1 *extra_p = p;
  p += extra_field_length;
  while (extra_p != p) {
    const u2 header_id = get_u2le(extra_p);
    const u2 data_size = get_u2le(extra_p);
    const u1 *extra = extra_p;
    extra_p += data_size;
    if (header_id == ZIP64_EXTRA_FIELD_TAG) {
      if (*uncompressed_size == U4_MAX) {
        *uncompressed_size = get_u8le(extra);
      }
      if (*compressed_size == U4_MAX) {
        *compressed_size = get_u8le(extra);
      }
      if (*offset == U4_MAX) {
        *offset = get_u8le(extra);
      }
    }
  }
  p += file_comment_length;

std::string CreateZipWithMalformedExtraField() {
  std::string zip_data;
  const std::string filename = "evil.bin";

  // 1. Local File Header (LFH)
  size_t lh_offset = zip_data.size();
  size_t lh_size = sizeof(LH) + filename.size();
  zip_data.resize(lh_offset + lh_size, 0);
  auto* lh = reinterpret_cast<LH*>(&zip_data[lh_offset]);
  lh->signature();
  lh->version(10);
  lh->file_name(filename.data(), filename.size());

  // 2. Extra field payload containing an oversized payload_size
  uint8_t ef_buffer[8] = {0};
  auto* ef1 = reinterpret_cast<ExtraField*>(ef_buffer);
  ef1->signature(0x000d);
  ef1->payload_size(0);

  auto* ef2 = reinterpret_cast<ExtraField*>(ef_buffer + ef1->size());
  ef2->signature(0xdead);
  ef2->payload_size(0xf000);  // Malformed size exceeding extra field buffer

  // 3. Central Directory Header (CDH)
  size_t cdh_offset = zip_data.size();
  size_t cdh_size = sizeof(CDH) + filename.size() + sizeof(ef_buffer);
  zip_data.resize(cdh_offset + cdh_size, 0);
  auto* cdh = reinterpret_cast<CDH*>(&zip_data[cdh_offset]);
  cdh->signature();
  cdh->version(20);
  cdh->version_to_extract(10);
  cdh->local_header_offset32(lh_offset);
  cdh->file_name(filename.data(), filename.size());
  cdh->extra_fields(ef_buffer, sizeof(ef_buffer));

  // 4. End of Central Directory (EOCD)
  size_t ecd_offset = zip_data.size();
  zip_data.resize(ecd_offset + sizeof(ECD), 0);
  auto* ecd = reinterpret_cast<ECD*>(&zip_data[ecd_offset]);
  ecd->signature();
  ecd->this_disk_entries16(1);
  ecd->total_entries16(1);
  ecd->cen_size32(cdh_size);
  ecd->cen_offset32(cdh_offset);

  return zip_data;
}
