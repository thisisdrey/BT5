### Title
Unauthenticated PeerDB forgery via unchecked HandshakeData address in `handle_neighbor_handshake_accept` / `add_or_schedule_replace_neighbor` - (File: stackslib/src/net/neighbors/walk.rs, stackslib/src/net/neighbors/db.rs)

### Summary
When the local node's neighbor-walk state machine dials a neighbor-of-neighbor address (`na`/`naddr`) and receives back a `HandshakeAccept`/`StackerDBHandshakeAccept`, the code stores the neighbor's self-reported `HandshakeData.addrbytes`/`port` into the `PeerDB` without verifying that it matches the actual socket address (`naddr`) that was dialed. This lets a peer the node connects to plant an arbitrary, attacker-chosen (potentially third-party/victim) `NeighborKey` into the local node's `PeerDB`, which subsequently gets served/gossiped to other peers via `Neighbors` messages.

### Finding Description
`Neighbor::load_and_update` (stackslib/src/net/chat.rs:475-516) builds the stored `NeighborKey` purely from attacker-controlled `HandshakeData` fields:
```
let addr = NeighborKey::from_handshake(peer_version, network_id, handshake_data);
```
This key (derived from `handshake_data.addrbytes`/`handshake_data.port`) is used unconditionally to look up/build the `Neighbor` record, and `Neighbor::save`/`save_update` (stackslib/src/net/neighbors/neighbor.rs:50-74) persist it into `PeerDB` with no check that it equals the network-authenticated remote endpoint.

`NeighborWalkDB::add_or_schedule_replace_neighbor` (stackslib/src/net/neighbors/db.rs:368-426) calls `Neighbor::load_and_update` and then `.save()`/`.save_update()` directly — again with no equality check against the actual TCP peer address.

The call site `handle_neighbor_handshake_accept` (stackslib/src/net/neighbors/walk.rs:1092-1124), invoked from `neighbor_handshakes_try_finish` (walk.rs:1133-1231), receives a `HandshakeAccept` on a connection that the local node itself opened to `naddr` (obtained from `cur_neighbor`'s `Neighbors` reply, see `neighbor_handshakes_begin`, walk.rs:979-1089). It passes `&data.handshake` straight into `add_or_schedule_replace_neighbor` with **no check that `data.handshake.addrbytes/port == naddr.addrbytes/port`**, and **no check on the public key hash either**. Contrast this with the sibling function `handle_handshake_accept` (walk.rs:676-737), which *does* enforce `neighbor_from_handshake.addr == self.cur_neighbor.addr` for the outbound walk-to-`cur_neighbor` case, and with `pingback_handshakes_try_finish` (walk.rs:1683-1725), which enforces a public-key-hash check via `check_handshake_pubkey_hash` but *still* never checks that the self-reported address equals the dialed `naddr`.

Exploit flow:
1. Local node performs a normal neighbor walk: gets `cur_neighbor`'s `Neighbors` list, which includes an entry pointing at the attacker's real, reachable P2P address (`na`).
2. Local node dials `na` and sends a `Handshake`.
3. Attacker's node, replying as the real TCP peer at `na`, sends back a `HandshakeAccept`/`StackerDBHandshakeAccept` whose `HandshakeData.addrbytes`/`port` field is set to an arbitrary victim IP:port that the attacker does not own.
4. `neighbor_handshakes_try_finish` → `handle_neighbor_handshake_accept` → `add_or_schedule_replace_neighbor` → `Neighbor::load_and_update` builds a `Neighbor` keyed on the victim's address and `.save()`s it into `PeerDB`.
5. This forged `PeerDB` entry is later included when the local node answers `GetNeighbors` requests from other peers, propagating the forged victim address across the network and potentially causing other nodes to attempt outbound TCP connections to the victim (SSRF-style).

No existing guard in this path (no `MAX_MESSAGE_LEN`/signature/pubkey-hash/socket-address check) prevents this, because the only address-consistency checks in the codebase (`handle_handshake_accept`'s `cur_neighbor.addr` check, `validate_handshake`'s outbound-socket check in chat.rs:1072-1091, and `check_handshake_pubkey_hash` in the pingback path) do not cover the neighbor-of-neighbor handshake-accept path.

### Impact Explanation
This is an unauthenticated write to node state (PeerDB) that plants a forged `NeighborKey` for a third party the attacker doesn't control, matching the "network-wide propagation of forged data" / "unauthenticated write to state" Critical category. Because `PeerDB` entries are later surfaced to other peers via `Neighbors`/`GetNeighbors` responses, this is repeatable and can be propagated network-wide, causing other nodes to attempt connections to the forged (victim) address.

### Likelihood Explanation
- Attacker only needs to run one reachable P2P node and be listed as (or get itself accepted as) a neighbor-of-neighbor during a normal, unauthenticated neighbor walk performed by any node — no allow/deny status, no reward-cycle dependency, no secret/privileged role needed.
- The attacker's own node completes a legitimate low-level handshake framing and simply lies in the `HandshakeData.addrbytes`/`port` field of its `HandshakeAccept` reply.
- Repeatable on every neighbor-walk cycle; cost to attacker is minimal (run a peer, wait to be discovered/dialed).

### Recommendation
In `handle_neighbor_handshake_accept` (and in `pingback_handshakes_try_finish`), verify that `data.handshake.addrbytes == naddr.addrbytes && data.handshake.port == naddr.port` (mirroring the check already present in `handle_handshake_accept` for `cur_neighbor`) before calling `add_or_schedule_replace_neighbor`/persisting to `PeerDB`. Reject or drop the accept (as an unsolicited/invalid handshake) if the self-reported address does not match the actually-dialed socket address, unless it is the documented any-net (`0.0.0.0`/`::`) exception. Also add the pubkey-hash check (`check_handshake_pubkey_hash`) to `handle_neighbor_handshake_accept`, which currently lacks it entirely.

    fn handle_handshake_accept(
        &mut self,
        network: &mut PeerNetwork,
        preamble: &Preamble,
        data: &HandshakeAcceptData,
        db_data: Option<&StackerDBHandshakeData>,
    ) -> Result<Neighbor, net_error> {
        let local_peer_str = format!("{:?}", network.get_local_peer());

        let mut neighbor_from_handshake = self
            .neighbor_db
            .neighbor_from_handshake(network, preamble, data)?;

        // if the neighbor accidentally gave us a private IP address, then
        // just use the one we used to contact it.  This can happen if the
        // node is behind a load-balancer, or is doing port-forwarding,
        // etc. But do nothing if both cur_neighbor and its reported address are private.
        if (neighbor_from_handshake.addr.addrbytes.is_in_private_range()
            || neighbor_from_handshake.addr.addrbytes.is_anynet())
            && !self.cur_neighbor.addr.addrbytes.is_in_private_range()
        {
            debug!(
                "{}: outbound neighbor gave private IP address {:?}; assuming it meant {:?}",
                local_peer_str, &neighbor_from_handshake.addr, &self.cur_neighbor.addr
            );
            neighbor_from_handshake.addr.addrbytes = self.cur_neighbor.addr.addrbytes.clone();
            neighbor_from_handshake.addr.port = self.cur_neighbor.addr.port;
        }

        if self.walk_outbound && neighbor_from_handshake.addr != self.cur_neighbor.addr {
            // somehow, got a handshake from someone that _isn't_ cur_neighbor.
            // Note that this does not matter for inbound walks, because we don't always know the
            // real address anyway (since an inbound neighbor might be NAT'ed from us).
            debug!("{}: got unsolicited (or bootstrapping) HandshakeAccept from outbound {:?} (expected {:?})", 
                       local_peer_str,
                       &neighbor_from_handshake.addr,
                       &self.cur_neighbor.addr);

            return Err(net_error::PeerNotConnected(format!("Got unsolicited (or bootstrapping) HandshakeAccept from outbound {:?} (expected {:?})", &neighbor_from_handshake.addr, &self.cur_neighbor.addr)));
        };

    fn handle_neighbor_handshake_accept(
        &mut self,
        network: &mut PeerNetwork,
        naddr: NeighborAddress,
        preamble: &Preamble,
        data: &HandshakeAcceptData,
        db_data: Option<&StackerDBHandshakeData>,
    ) -> Result<(), net_error> {
        // NOTE: even if cur_neighbor is an inbound neighbor, the neighbors
        // of cur_neighbor that we could handshake with are necessarily
        // outbound connections.  So, save them all.
        // Do we know about this peer already?
        let (new, neighbor) = self.neighbor_db.add_or_schedule_replace_neighbor(
            network,
            preamble,
            &data.handshake,
            db_data,
            &mut self.neighbor_replacements,
        )?;

        if new {
            // neighbor was new
            self.new_frontier
                .insert(neighbor.addr.clone(), neighbor.clone());
        } else {
            // frontier maintenance
            self.frontier
                .insert(neighbor.addr.clone(), neighbor.clone());
        }

        self.resolved_handshake_neighbors.insert(naddr, neighbor);
        Ok(())
    }

    /// Does a given handshakedata represent an expected public key hash?
    fn check_handshake_pubkey_hash(
        nk: &NeighborKey,
        data: &HandshakeAcceptData,
        naddr: &NeighborAddress,
    ) -> bool {
        let neighbor_pubkey_hash =
            Hash160::from_node_public_key_buffer(&data.handshake.node_public_key);
        if neighbor_pubkey_hash != naddr.public_key_hash {
            debug!(
                "Neighbor {:?} had an unexpected pubkey hash: expected {:?} != {:?}",
                nk, &naddr.public_key_hash, &neighbor_pubkey_hash
            );
            return false;
        }

        true
    }

    /// Finish up connecting to newly-discovered inbound peers
    pub fn pingback_handshakes_try_finish(
        &mut self,
        network: &mut PeerNetwork,
    ) -> Result<bool, net_error> {
        assert!(self.state == NeighborWalkState::PingbackHandshakesFinish);

        // see if we got any replies
        for (naddr, message) in self.comms.collect_replies(network).into_iter() {
            // if we got back a HandshakeAccept, and it's on the same chain as us, we're good!
            let (data, db_data) = match message.payload {
                StacksMessageType::HandshakeAccept(ref data) => {
                    debug!("{:?}: received HandshakeAccept from peer {:?}; now known to be routable from us", network.get_local_peer(), &message.to_neighbor_key(&data.handshake.addrbytes, data.handshake.port));
                    (data, None)
                }
                StacksMessageType::StackerDBHandshakeAccept(ref data, ref db_data) => {
                    debug!("{:?}: received StackerDBHandshakeAccept from peer {:?}; now known to be routable from us", network.get_local_peer(), &message.to_neighbor_key(&data.handshake.addrbytes, data.handshake.port));
                    (data, Some(db_data))
                }
                _ => {
                    let nkey = naddr.to_neighbor_key(network);

                        "{:?}: Neighbor {:?} replied {:?} instead of pingback handshake",

                network,
                &message.preamble,
                &data.handshake,
                db_data,
