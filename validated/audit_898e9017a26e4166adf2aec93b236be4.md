### Title
Protocol fee bypass on `Nep245`/`Imt` token trades via unit-sized `TokenDiff` splitting - (File: `contracts/defuse/core/src/intents/token_diff.rs`)

### Summary
`TokenDiff::execute_intent` computes and charges the protocol fee independently for each `TokenDiff` intent, using only that single intent's `delta` magnitude as `amount`. `TokenDiff::token_fee` explicitly returns `Pips::ZERO` whenever the token is `Nep245`/`Imt` and `amount <= 1`. An attacker can place any number of unit-sized (`delta == ±1`) `TokenDiff` intents inside the `intents` vector of a single signed `DefuseIntents` payload (or across a batch), so every fee computation sees `amount == 1` and returns zero, while the net token movement realized in the ledger equals the sum of all the unit deltas.

### Finding Description
Binding claimed broken: `fee_owed(net_delta_on_TokenId) == fee_credited_to(fee_collector)` where `net_delta_on_TokenId` is the true aggregate negative delta a signer incurs on a `Nep245`/`Imt` `TokenId` across a batch/payload.

Root cause: in `TokenDiff::execute_intent` (`contracts/defuse/core/src/intents/token_diff.rs:59-78`), each `(token_id, delta)` pair inside a *single* `TokenDiff.diff` map is fee-evaluated on its own, calling `Self::token_fee(token_id, delta.unsigned_abs(), protocol_fee).fee_ceil(amount)`. `token_fee` (lines 206-216) skips the fee entirely for `TokenIdType::Nep245 | TokenIdType::Imt` whenever `amount <= 1`. Nothing aggregates deltas across multiple `TokenDiff` intents for the same signer/token before this check runs — `DefuseIntents::execute_intent` (`contracts/defuse/core/src/intents/mod.rs:97-113`) simply loops over `self.intents` and calls `execute_intent` on each independently, and `Engine::finalize`/`Deltas::finalize` (`contracts/defuse/core/src/engine/mod.rs:113-118`) only checks that the sum of all deltas across the whole batch nets to zero per token — it does not re-derive or re-check fees against any netted amount.

Exploit: an attacker signs one `DefusePayload<DefuseIntents>` whose `intents` field contains N separate `Intent::TokenDiff` entries, each with `diff = { token_A(Nep245): -1, token_B: +k }` (or any ratio), for a total effective trade of N units of `token_A` for `N*k` of `token_B`. Any counterparty (who need not collude or split anything) can satisfy the net-zero invariant with a single ordinary `TokenDiff` of `{ token_A: +N, token_B: -N*k }`. Each of the attacker's N intents independently calls `token_fee` with `amount == 1`, which returns `Pips::ZERO`, so `fees_collected` is `0` for every one of them, even though the true aggregate negative delta on `token_A` is `N`. A single non-split `TokenDiff` of the same aggregate size would have charged `protocol_fee` on `fee_ceil(N)`.

No existing guard prevents this: `verify`, nonce/salt checks, and the invariant check in `finalize` all validate signature/replay/net-zero-balance properties, not fee correctness, and none of them recompute fees on a netted basis.

### Impact Explanation
Protocol fees are fully bypassed on the negative (`token_in`) side of any `Nep245` or feature-gated `Imt` trade, for arbitrarily large amounts, by paying only extra gas/transaction-size cost to enumerate unit deltas. This matches the "protocol fees bypassed" Critical category: the fee that should have been credited to `fee_collector` is never collected, directly reducing protocol revenue with no compensating loss to the attacker beyond the marginal gas cost of the extra intents. The attack is fully repeatable across any `Nep245`/`Imt` `TokenId`, any account, and any batch, and requires no privileged role — only an ordinary counterparty willing to trade.

### Likelihood Explanation
Feasible for any unprivileged user who holds a `Nep245`/`Imt` balance and wants to trade it away: they only need to construct one signed payload with N `TokenDiff` intents instead of one, which is a normal, permitted use of `DefuseIntents.intents` (documented as an ordered "sequence of intents"). The size of N is bounded only by NEAR's per-transaction gas/size limits, which caps how much can be evaded in a single transaction but does not prevent repeating the pattern across multiple transactions to launder an arbitrarily large aggregate amount over time.

### Recommendation
Compute and charge the fee based on the netted (aggregate) delta per `(signer_id, token_id)` across the whole `DefuseIntents`/batch, not per individual `TokenDiff` intent — e.g., accumulate all deltas into `Deltas` first, then run one `token_fee`/`fee_ceil` pass over the final netted negative deltas per token per signer, before/after intent execution, instead of inside the per-intent loop.
