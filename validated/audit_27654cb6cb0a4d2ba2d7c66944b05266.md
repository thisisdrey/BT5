### Title
Reftable block parsing underflows unsigned arithmetic on unvalidated block-length/restart-count fields, causing an out-of-bounds panic (DoS) - (File: internal/git/reftable/reftable.go)

### Summary
`Table.parseRefBlock` computes `RestartStart` from two values taken directly from the bytes of a `.ref` reftable file — the 3-byte block length (`currentBS`, from `extractBlockLen`) and the 2-byte restart count (`b.RestartCount`) — without validating that `currentBS - 2 - 3*RestartCount` cannot go negative. All of these operands are `uint`, so any table encoding a small block length together with a large restart count causes the subtraction to wrap around to a very large `uint` value instead of erroring out, exactly analogous to the reported curve-points bug where a later point smaller than an earlier one causes an unchecked subtraction to underflow. [1](#0-0) 

### Finding Description
`extractBlockLen` reads the 3-byte block length straight from file bytes with no bound checking against the actual block size, and `RestartCount` is read as a raw `uint16` from the same untrusted buffer. [2](#0-1) [3](#0-2) 
These two attacker-controlled fields are combined via unsigned subtraction (`currentBS - 2 - 3*uint(b.RestartCount)`) with no check that `currentBS >= 2 + 3*RestartCount`. If `RestartCount` is set larger than `(currentBS-2)/3`, the computation wraps to a huge `uint`, producing a bogus `RestartStart` far beyond the buffer. This value is then used as the loop bound in `getRefsFromBlock`: [4](#0-3) 
Because `idx < b.RestartStart` is now (almost) always true, the loop keeps advancing `idx` and indexing into `src[idx:...]` well past the end of the byte slice, causing a Go slice-bounds-out-of-range panic rather than a controlled error return — unlike the well-checked failure paths already present elsewhere in the same file (`parseHeader`, `parseFooter`, `getBlockRange`, `getVarInt`'s own bound check). [5](#0-4) 

This mirrors the reported bug class precisely: a structural invariant (“the next value must not decrease/underflow the previous one”) is enforced in some places (header/footer parsing has magic/version/hash/CRC32 checks) but is missing at the specific arithmetic site that later performs the risky subtraction, just as `setCurve()`/`setCurvePoint()` lacked the monotonicity check that `getMultiplier()` implicitly required.

`.ref` table files are parsed by `reftable.ParseTable`/`GetReferences` in code paths that consume table files without re-deriving them from a live, currently-open Git process guaranteeing well-formedness — e.g. reftable resequencing during ordinary transaction processing (`internal/gitaly/storage/storagemgr/partition/reftable.go`, which calls `reftable.ParseTable` on tables written during a transaction) and reference listing/backup/replication code paths (`internal/gitaly/service/ref`, `internal/backup/repository.go`, `internal/gitaly/service/repository/replicate.go`) that call `GetReferences()` on `.ref` files that may originate from replication, restore, or fork/import operations where the byte layout is not independently re-validated before being handed to this parser. [6](#0-5) 

### Impact Explanation
A crafted or corrupted reftable block (small `block_len` field combined with a large `restart_count`) triggers an unrecovered Go panic (index out of range) inside the RPC-serving process handling the request that reads references from the affected repository/table (list-refs, replication, restore, or transaction resequencing). Because this runs in-process rather than through git's own hardened reftable implementation, a panic here can crash the goroutine/handler and, depending on recovery middleware, potentially destabilize the serving process — a denial of service against the handler processing the crafted repository/table.

### Likelihood Explanation
Reaching this code requires only that a `.ref` reftable file with attacker-influenced/corrupted block-length and restart-count fields be parsed by Gitaly's own reftable reader — e.g. through a replicated, restored (from backup), or otherwise transferred repository using the reftable backend, or a corrupted table encountered during transaction/compaction bookkeeping. No git binary re-validation of these specific byte offsets occurs before `parseRefBlock` runs, and the check that exists elsewhere in the file (`getVarInt`'s `start > blockEnd`) is not applied to the `RestartStart` computation itself, making the missing-invariant bug directly reachable whenever a non-conformant table is processed.

### Recommendation
Add an explicit bounds check before computing `RestartStart` in `parseRefBlock`, rejecting the block if `currentBS < 2` or `uint(b.RestartCount)*3 > currentBS-2` (or equivalently perform the subtraction in a wider/signed type and check for a negative result) similar to the recommended `checkCurve`-style guard in the source report. Additionally, validate `RestartStart <= blockEnd` and `idx` bounds against `len(src)` at each read inside `getRefsFromBlock`/`getVarInt`, returning a parse error instead of allowing an out-of-bounds slice panic.

### Proof of Concept
1. Take a valid reftable ref block. Overwrite the 3-byte `block_len` field read by `extractBlockLen` with a small value (e.g. 8).
2. Overwrite the trailing 2-byte restart count (`b.RestartCount`) with a large value (e.g. `0xFFFF`).
3. Call `Table.GetReferences()` (or trigger any Gitaly code path that parses this table, such as reference listing or reftable resequencing in `internal/gitaly/storage/storagemgr/partition/reftable.go`).
4. `parseRefBlock` computes `RestartStart = blockStart + 8 - 2 - 3*65535`, which underflows to a huge `uint` value; `getRefsFromBlock`'s loop condition `idx < b.RestartStart` never becomes false before `idx` exceeds `len(src)`, causing a slice-bounds-out-of-range panic instead of a graceful parse error. func (t *Table) getVarInt(src []byte, start uint, blockEnd uint) (uint, uint, error) {
```go
	var val uint

	val = uint(src[start]) & 0x7f

	for (uint(src[start]) & 0x80) > 0 {
		start++
		if start > blockEnd {
			return 0, 0, fmt.Errorf("exceeded block length")
		}

		val = ((val + 1) << 7) | (uint(src[start]) & 0x7f)
	}

	return start + 1, val, nil
}
```

```go
func (t *Table) parseRefBlock(src []byte, headerOffset, blockStart, blockEnd uint) ([]git.Reference, error) {
	currentBS := t.extractBlockLen(src, blockStart+headerOffset)

	fullBlockSize := t.blockSize
	if fullBlockSize == 0 {
		fullBlockSize = currentBS
	} else if currentBS < fullBlockSize && currentBS < (blockEnd-blockStart) && src[blockStart+currentBS] != 0 {
		fullBlockSize = currentBS
	}

	b := &block{
		BlockStart:    blockStart + headerOffset,
		FullBlockSize: fullBlockSize,
	}

	if err := binary.Read(bytes.NewBuffer(src[blockStart+currentBS-2:]), binary.BigEndian, &b.RestartCount); err != nil {
		return nil, fmt.Errorf("reading restart count: %w", err)
	}

	b.RestartStart = blockStart + currentBS - 2 - 3*uint(b.RestartCount)

	return t.getRefsFromBlock(src, b)
```
