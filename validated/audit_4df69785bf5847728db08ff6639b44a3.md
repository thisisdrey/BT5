### Title
Signer Event Receiver accepts unauthenticated `BlockValidateResponse`/`StackerDBChunksEvent` HTTP POSTs, allowing forged validation results to be injected into the signer runloop - ([File: libsigner/src/events.rs])

### Summary
The `stacks-signer` process runs an HTTP listener (`SignerEventReceiver`) bound to the address configured in `endpoint` (commonly `0.0.0.0:30000` in the sample configs) that is meant to receive events only from its paired, trusted `stacks-node`. Unlike the node-to-signer `auth_token`/`auth_password` check used for the *signer-to-node* `/v3/block_proposal` path, there is **no authentication whatsoever** on the *node-to-signer* HTTP endpoint. Any remote host that can reach that port can POST directly to `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, or `/new_block` and have the payload parsed and forwarded into the signer's decision-making runloop as if it came from the legitimate node.

### Finding Description
`SignerEventReceiver::next_event` in [1](#0-0)  dispatches incoming HTTP requests purely based on URL path (`/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block`, `/status`, `/shutdown`) with zero credential check. `process_event` in the same file simply reads the body and deserializes it — again with no authentication step: [2](#0-1) .

`libsigner/src/http.rs`'s `decode_http_request`/`decode_http_response` helpers parse headers but never look for or validate an `Authorization` header [3](#0-2) ; a repo-wide search for `authorization`/`auth_token` under `libsigner/**` returned no matches at all, confirming there is no auth mechanism on this channel.

This is the structural analog of the reported soft-serve bug class: the system has one strongly-authenticated channel (signer → node, guarded by the `auth_token`/`auth_password` string compared in `postblock_proposal.rs`/`postblock_v3.rs`, see [4](#0-3) ) and a second, structurally different channel (node → signer events) that an attacker can use instead, which "fails open" because it was never gated by any credential at all — exactly like keyboard-interactive SSH bypassing the intended pubkey check in soft-serve.

Critically, one of the accepted event types is `BlockValidateResponse` (`/proposal_response`), which is consumed by `handle_block_validate_response` in `stacks-signer/src/v0/signer.rs` (confirmed to exist via `fn handle_block_validate_response` match) and directly informs whether the signer proceeds to co-sign a block. Because this message has no origin authentication, and reflects the node's local judgement of block validity (not a cryptographically signed statement from the chain), an attacker with network access to the signer's bound port can inject a forged "block is valid" response.

By contrast, `StackerDBChunksEvent` payloads containing `SignerMessage`s from other signers are separately authenticated at the application layer via `chunk.recover_pk()` / `is_valid_signer()` checks in `stacks-signer/src/v0/signer.rs` (lines ~529–538), so forging *signer-to-signer* gossip through this channel would still fail signature checks. The unauthenticated exposure specifically matters for `/proposal_response` (`BlockValidateResponse`), which carries no independent signature and is trusted as coming from the local node.

### Impact Explanation
If the signer's event-receiver port is reachable by an unauthenticated remote attacker (e.g., misconfigured firewall, container network, or cloud deployment exposing `0.0.0.0:<port>` as shown in the sample configs), the attacker can POST a forged `/proposal_response` claiming a malicious or non-canonical block proposal is valid, steering the signer toward approving/co-signing state that the actual node chainstate never validated. This matches the "High" tier described in the rules (auth bypass / forged-data propagation influencing consensus-adjacent decisions), since it breaks the equality "validated-by-node" vs. "claimed-as-validated."

### Likelihood Explanation
Exploitability is contingent on network reachability of the signer's listener port — this is not exploitable purely over the open P2P network from an arbitrary peer, but requires that the operator's `endpoint` (bound with `HttpServer::http(listener)` — no TLS, no auth) is exposed beyond loopback/trusted LAN, which several sample configs default to `0.0.0.0`. Given many production deployments run node and signer in separate containers/hosts and open the events port for connectivity, this is a realistic operational condition rather than a purely theoretical one.

### Recommendation
Add authentication to the signer's event-receiver HTTP path (`SignerEventReceiver::next_event`/`process_event`), mirroring the existing `auth_token` check used on the node's `/v3/block_proposal` endpoint — e.g., require and validate a shared-secret `Authorization` header before dispatching to `process_event`, and reject unauthenticated requests with 401 rather than parsing and forwarding them.

### Proof of Concept
1. Configure `stacks-signer` per `sample/conf/signer/mainnet-signer-conf.toml`, with `endpoint = "0.0.0.0:30000"`.
2. From a remote unauthenticated host with network access to port 30000, send:
```
POST /proposal_response HTTP/1.1
Host: <signer-host>:30000
Content-Type: application/json
Content-Length: <n>

{ ...forged BlockValidateResponse JSON indicating a chosen block is valid... }
```
3. `SignerEventReceiver::next_event` matches `/proposal_response`, calls `process_event::<T, BlockValidateResponse>`, which deserializes the body with no credential check [5](#0-4)  and forwards it to the signer runloop via `forward_event`, ultimately reaching `handle_block_validate_response` in `stacks-signer/src/v0/signer.rs`.     /// Wait for the node to post something, and then return it.
    /// Errors are recoverable -- the caller should call this method again even if it returns an
    /// error.
    fn next_event(&mut self) -> Result<SignerEvent<T>, EventError> {
        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)
            } else if request.url() == "/new_block" {
                process_event::<T, StacksBlockEvent>(request)
            } else {
                let url = request.url().to_string();
                debug!(
                    "[{:?}] next_event got request with unexpected url {}, return OK so other side doesn't keep sending this",
                    event_receiver.local_addr,
                    url
                );
                ack_dispatcher(request);
                Err(EventError::UnrecognizedEvent(url))
            }
        })?
    }

fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}

/// Decode the HTTP request payload into its headers and body.
/// Returns (verb, path, table of headers, body_offset) on success
pub fn decode_http_request(payload: &[u8]) -> Result<SignerHttpRequest, EventError> {
    // realistically, there won't be more than 32 headers
    let mut headers_buf = [httparse::EMPTY_HEADER; MAX_HTTP_HEADERS];
    let mut req = httparse::Request::new(&mut headers_buf);
    let (verb, path, headers, body_offset) =
        if let Ok(httparse::Status::Complete(body_offset)) = req.parse(payload) {
            // version must be valid
            match req
                .version
                .ok_or(EventError::MalformedRequest("No HTTP version".to_string()))?
            {
                0 => {}
                1 => {}
                _ => {
                    return Err(EventError::MalformedRequest(
                        "Invalid HTTP version".to_string(),
                    ));
                }
            };

            let verb = req
                .method
                .ok_or(EventError::MalformedRequest("No HTTP method".to_string()))?
                .to_string();
            let path = req
                .path
                .ok_or(EventError::MalformedRequest("No HTTP path".to_string()))?
                .to_string();

            let mut headers: HashMap<String, String> = HashMap::new();
            for i in 0..req.headers.len() {
                let value = String::from_utf8(req.headers[i].value.to_vec()).map_err(|_e| {
                    EventError::MalformedRequest("Invalid HTTP header value: not utf-8".to_string())
                })?;
                if !value.is_ascii() {
                    return Err(EventError::MalformedRequest(
                        "Invalid HTTP request: header value is not ASCII-US".to_string(),
                    ));
                }
                if value.len() > MAX_HTTP_HEADER_LEN {
                    return Err(EventError::MalformedRequest(
                        "Invalid HTTP request: header value is too big".to_string(),
                    ));
                }

                let key = req.headers[i].name.to_string().to_lowercase();
                if headers.get(&key).is_some() {
                    return Err(EventError::MalformedRequest(format!(
                        "Invalid HTTP request: duplicate header \"{key}\""
                    )));
                }
                headers.insert(key, value);
            }
            (verb, path, headers, body_offset)
        } else {
            return Err(EventError::Deserialize(
                "Failed to decode HTTP headers".to_string(),
            ));
        };

    Ok(SignerHttpRequest::new(verb, path, headers, body_offset))
}
