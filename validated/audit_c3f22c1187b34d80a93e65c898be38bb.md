### Title
Missing cryptographic access control on unencrypted RecvError packets allows remote tunnel teardown via spoofed UDP source address - (File: outside.go, interface.go)

### Summary
`recv_error` (`header.RecvError`) packets are processed as a plaintext, unauthenticated control message. Unlike every other packet type, they never pass through the AEAD `Decrypt`/`VerifyRelay` step that ties a packet to a completed, certificate-verified handshake. The only "authorization" check is a comparison of the UDP source address against the value nebula already has cached for that hostinfo, which is trivially bypassed by spoofing the source `ip:port` on connectionless UDP. This mirrors the reported `burn()` access-control bug: a state-changing, destructive operation (destroying a live tunnel) can be triggered by anyone able to send a packet, not just the legitimate party the operation is scoped to.

### Finding Description
In `readOutsidePackets`, before any hostinfo lookup, AEAD verification, or certificate check, the type switch dispatches unencrypted `header.RecvError` packets directly to `handleRecvError`: [1](#0-0) 

`handleRecvError` looks up the hostinfo purely from the attacker-controlled 32-bit `h.RemoteIndex` field, and its only sender-legitimacy check is a plain equality comparison between the UDP source address of the received packet and the cached remote address of that hostinfo: [2](#0-1) 

That check (`hr != addr`) is a network-layer address comparison, not a cryptographic proof of possession of the session or a certificate. Because UDP is connectionless and has no built-in source-address authentication, an attacker who is on-path (or otherwise able to spoof UDP source `ip:port`) and who has observed or guessed the target's `RemoteIndex` (visible on the wire in every packet header of that tunnel, since the header itself is never encrypted — see `header.H.Parse`) can forge a bare `RecvError` packet with:
- destination address = the target's real UDP endpoint,
- spoofed source = the address of the target's real peer,
- `RemoteIndex` = the observed index.

This packet requires no certificate, no handshake, and no AEAD key at all, yet it results in `f.closeTunnel(hostinfo)` and `f.handshakeManager.DeleteHostInfo(hostinfo)`, immediately tearing down the tunnel: [3](#0-2) 

By default `listen.accept_recv_error` is `"always"` (`recvErrorAlways`), meaning this path is active on every node unless the operator explicitly restricts it: [4](#0-3) 

This is precisely a "missing access control" pattern analogous to `burn()`: an operation intended to be trusted only when it genuinely originates from a session peer is instead gated by a spoofable, non-cryptographic check.

### Impact Explanation
An attacker with no CA-signed certificate and no valid session key can repeatedly and remotely force teardown of any live nebula tunnel by sending forged, unencrypted `RecvError` packets with a spoofed source address and an observed/guessed remote index. This is a remote denial-of-service against arbitrary tunnels (state poisoning of the hostmap/handshake manager), degrading availability of the mesh without requiring any authentication material, consistent with the "critical" severity classification of unauthenticated state-destroying operations in the reported analog.

### Likelihood Explanation
Exploitation requires: (1) the ability to spoof a UDP source `ip:port` toward the victim (feasible for on-path attackers, and in many network environments even off-path via UDP spoofing since there's no return-routability check), and (2) knowledge of the 32-bit `RemoteIndex`, which is sent in cleartext in the header of every packet of that tunnel and thus observable to any on-path or off-path eavesdropper who can see traffic between the two peers. Given the default config (`accept_recv_error: always`), likelihood is high for on-path adversaries and moderate for pure off-path spoofers depending on network egress filtering (BCP38).

### Recommendation
Do not allow an unauthenticated, unencrypted packet type to trigger destructive state changes (tunnel teardown, hostmap deletion). Either:
- Require `RecvError` handling to additionally validate a value derived from the session (e.g., require the packet to be authenticated/MACed with a key derived from the tunnel's Noise session, similar to how `Test`/`Message` packets are authenticated), or
- Treat `RecvError` purely as a hint that triggers a faster re-handshake probe rather than an immediate `closeTunnel`/`DeleteHostInfo`, and require corroborating evidence (e.g., a subsequent authenticated packet, or timeout-based confirmation) before destroying tunnel state, or
- Tie acceptance more strictly to `listen.accept_recv_error` defaulting to a stricter mode (e.g., `never` or `private`) rather than `always`.

### Proof of Concept
1. Observe (sniff) UDP traffic between victim node A (real endpoint `A_addr`) and its peer B (real endpoint `B_addr`); record the 32-bit index A uses for that tunnel (`h.RemoteIndex`), visible in the cleartext header of any packet A sends/receives.
2. Craft a bare header-only UDP packet: `header.Encode(buf, header.Version, header.RecvError, 0, <observed index>, 0)` per `sendRecvError`: [5](#0-4) 
3. Send this packet to `A_addr`, spoofing the UDP source address as `B_addr`.
4. On A, `readOutsidePackets` routes the unencrypted `RecvError` type straight to `handleRecvError` (no AEAD/cert check): [6](#0-5) 
5. `handleRecvError` finds the hostinfo by index, sees the spoofed source address matches the cached remote for B, and calls `f.closeTunnel(hostinfo)` plus `f.handshakeManager.DeleteHostInfo(hostinfo)`, destroying the tunnel: [7](#0-6) 
6. Repeating this at will prevents A and B from maintaining a stable tunnel — a remote, certificate-less denial of service.

```go
func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
```

```go
func (f *Interface) reloadAcceptRecvError(c *config.C) {
	if c.InitialLoad() || c.HasChanged("listen.accept_recv_error") {
		stringValue := c.GetString("listen.accept_recv_error", "always")

		switch stringValue {
		case "always":
			f.acceptRecvErrorConfig = recvErrorAlways
		case "never":
			f.acceptRecvErrorConfig = recvErrorNever
		case "private":
			f.acceptRecvErrorConfig = recvErrorPrivate
		default:
			if c.GetBool("listen.accept_recv_error", true) {
				f.acceptRecvErrorConfig = recvErrorAlways
			} else {
				f.acceptRecvErrorConfig = recvErrorNever
			}
		}

		f.l.Info("Loaded accept_recv_error config", "acceptRecvError", f.acceptRecvErrorConfig.String())
	}
}
```
