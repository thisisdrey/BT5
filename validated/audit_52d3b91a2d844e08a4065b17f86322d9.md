### Title
Unstaked attacker can exhaust the shared global `open_connections`/`max_concurrent_connections` budget with abandoned QUIC handshakes, evading per-IP rate limiting and starving legitimate TPU senders - (File: streamer/src/nonblocking/quic.rs)

### Summary
In `run_server`, a connection accepted via `Incoming::accept()` is admitted to the global `ClientConnectionTracker`/`open_connections` budget before the QUIC handshake completes, while both the per-IP `ConnectionRateLimiter` and the global `overall_connection_rate_limiter` are only *consumed* (via `register_connection`/`consume_tokens`) in `setup_connection` after a successful handshake. An unstaked attacker can therefore open many connection attempts from a single IP and simply abandon the handshake before it resolves, occupying the shared, unpartitioned `max_concurrent_connections()` slot budget for up to `QUIC_CONNECTION_HANDSHAKE_TIMEOUT` per attempt without ever tripping `connection_rate_limited_per_ipaddr` or `connection_rate_limited_across_all`.

### Finding Description
In `run_server` (streamer/src/nonblocking/quic.rs:331-407), for every accepted `Incoming`:
1. `overall_connection_rate_limiter.current_tokens() == 0` is only *checked*, never decremented at this point [1](#0-0) .
2. `rate_limiter.is_allowed(&ip)` is likewise a non-mutating check; `ConnectionRateLimiter::is_allowed` returns `true` for any IP that has no prior recorded token consumption [2](#0-1) .
3. `ClientConnectionTracker::new` then increments the single, global `stats.open_connections` counter and enforces the only real cap, `qos.max_concurrent_connections()`, which is a flat sum unrelated to source IP (e.g. `(max_staked_connections + max_unstaked_connections) * 5 / 4` for `SwQos`) [3](#0-2) [4](#0-3) .
4. Only after `incoming.accept()` succeeds does `setup_connection` run, awaiting `timeout(QUIC_CONNECTION_HANDSHAKE_TIMEOUT, connecting)`. Only on a *successful* handshake are `rate_limiter.register_connection(&from.ip())` and `overall_connection_rate_limiter.consume_tokens(1)` actually called [5](#0-4) .

Because the per-IP and global token buckets are only decremented post-handshake, an attacker who never completes the cryptographic handshake (e.g. drops/ignores the TLS handshake packets after the initial) never registers against either limiter — `is_allowed`/`current_tokens` remain effectively unaffected — yet each such attempt still consumes a slot in the single shared `open_connections` counter for the full `QUIC_CONNECTION_HANDSHAKE_TIMEOUT` duration (decremented in `setup_connection` only once the `timeout()` future resolves, success or failure) [6](#0-5) . Since `open_connections`/`max_concurrent_connections` is not partitioned per source IP or per stake class, an attacker sending many parallel half-open connection attempts from one IP can occupy the entire budget, causing subsequent `ClientConnectionTracker::new` calls for *any* other peer (including staked, legitimate senders) to fail and be counted as `refused_connections_too_many_open_connections` (`incoming.refuse()`) [7](#0-6) . Because each occupied slot frees itself after `QUIC_CONNECTION_HANDSHAKE_TIMEOUT` but the attacker can immediately re-issue a fresh burst of `Incoming::accept()`s, the exhaustion can be sustained indefinitely through churn, all while `connection_rate_limited_per_ipaddr` stays at zero for the attacker.

The code comment at lines 331-340 explicitly documents that per-IP limiting is deliberately deferred until after handshake completion to avoid enabling IP-spoofing attacks between peers, but this rationale does not address (and the implementation does not mitigate) the case where the attacker uses its own real IP and simply never completes the handshake — the one control meant to bound this ("cap total connections per-peer/ip") is not actually applied pre-handshake, and the only remaining control is the flat, unpartitioned global slot cap.

### Impact Explanation
This falls under QoS evasion / TPU capacity starvation: an unstaked, unprivileged client can fill the shared `open_connections` budget (gating every future accepted QUIC connection, staked or unstaked) using nothing but abandoned handshakes from a single source IP, without ever being penalized by the per-IP `ConnectionRateLimiter`. Because the connection admission gate is global rather than partitioned by IP or stake, this can deny TPU QUIC connection capacity to legitimate (including staked) senders, degrading transaction ingestion for the leader.

### Likelihood Explanation
Preconditions are minimal: the attacker only needs to reach the leader's public TPU QUIC endpoint and be able to send QUIC initial packets while withholding/aborting the TLS handshake completion (e.g., closing the socket or never responding to server handshake flights). No stake, keys, or special access are required. The attack is repeatable indefinitely via churn since each stalled slot self-frees after `QUIC_CONNECTION_HANDSHAKE_TIMEOUT` and can be immediately replaced by a new attempt, and a single IP suffices because the enforcement point (`max_concurrent_connections`) is global, not per-IP.

### Recommendation
Bound in-flight (pre-handshake) connection attempts per source IP independently of the post-handshake `ConnectionRateLimiter`, e.g. by tracking outstanding unverified attempts per IP with a small cap, or by reserving/consuming a per-IP quota at `Incoming::accept()` time (released on handshake failure/timeout) rather than only after successful handshake. Alternatively, partition the `max_concurrent_connections` slot pool so no single IP can consume more than a small fraction of the pending-handshake budget, decoupling the global admission cap from the per-IP behavior.

### Proof of Concept
Integration test plan (extending the existing test harness in `streamer/src/nonblocking/quic.rs`'s `#[cfg(test)]` module and `setup_quic_server`/`make_client_endpoint` helpers used in `tpu-client-next/tests/connection_workers_scheduler_test.rs`):
1. Start a QUIC server via `setup_quic_server` with a small `max_concurrent_connections` (e.g. via `SwQosConfig { max_staked_connections: 1, max_unstaked_connections: 4, .. }`) and default `QUIC_CONNECTION_HANDSHAKE_TIMEOUT`.
2. From a single client IP, open N `quinn::Endpoint::connect(...)` attempts but never let the handshake complete (e.g., use a client TLS config that fails verification post-Initial, or drop the endpoint immediately after `connect()` without awaiting the `Connecting` future) — issue enough attempts to exceed `max_concurrent_connections`.
3. Concurrently, from a second, distinct IP (or loopback alias), attempt a normal `make_client_endpoint` connection and confirm it is refused (`stats.refused_connections_too_many_open_connections` increments, `Connecting` never resolves within the test timeout).
4. Assert `stats.connection_rate_limited_per_ipaddr.load(Ordering::Relaxed) == 0` for the attacker IP throughout, while `stats.refused_connections_too_many_open_connections` or `stats.outstanding_incoming_connection_attempts` rises, demonstrating the second IP's legitimate connection is starved without the attacker ever being penalized by the per-IP limiter.

impl ClientConnectionTracker {
    /// Check the max_concurrent_connections limit and if it is within the limit
    /// create ClientConnectionTracker and increment open connection count. Otherwise returns Err
    fn new(stats: Arc<StreamerStats>, max_concurrent_connections: usize) -> Result<Self, ()> {
        let open_connections = stats.open_connections.fetch_add(1, Ordering::Relaxed);
        if open_connections >= max_concurrent_connections {
            stats.open_connections.fetch_sub(1, Ordering::Relaxed);
            debug!(
                "There are too many concurrent connections opened already: open: \
                 {open_connections}, max: {max_concurrent_connections}"
            );
            return Err(());
        }

        Ok(Self { stats })
    }
}

    /// Here we assume that only IPs with actual confirmed connections are stored in it,

    pub fn is_allowed(&self, ip: &IpAddr) -> bool {
        // Check if we have records in the rate limiter for the given IP address
        match self.limiter.current_tokens(ip) {
            Some(r) => r > 0, // we have a record, and rate is not exceeded
            None => true,     // if we have not seen IP, allow connection request
