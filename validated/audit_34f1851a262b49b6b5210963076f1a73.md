### Title
Global `overall_connection_rate_limiter` token bucket is shared across all source IPs and can be exhausted by rotating unstaked source addresses, starving legitimate staked/unstaked connections - ([File: streamer/src/nonblocking/quic.rs])

### Summary
`streamer/src/nonblocking/quic.rs` maintains a single global `TokenBucket` (`overall_connection_rate_limiter`, bounded by `TOTAL_CONNECTIONS_PER_SECOND = 2500.0` and `MAX_CONNECTION_BURST = 1000`) that gates new QUIC connection acceptance in the `run_server` accept loop, in addition to the per-IP `ConnectionRateLimiter` in `streamer/src/nonblocking/connection_rate_limiter.rs`. Because the global bucket has no notion of source identity, an attacker who spreads a burst of connection attempts across many distinct source addresses (e.g., rotating within an IPv6 /64, which is trivially available to a single unprivileged host) can keep each individual IP under its own per-IP cap while collectively draining the shared global token bucket to zero.

### Finding Description
The per-IP limiter (`ConnectionRateLimiter::is_allowed`/`register_connection` in `streamer/src/nonblocking/connection_rate_limiter.rs`) is explicitly documented as enforcing rate limits keyed by `IpAddr`, meaning any single source address is capped independently. However, `run_server` in `streamer/src/nonblocking/quic.rs` additionally consults a single global `TokenBucket` instance (`overall_connection_rate_limiter`) sized at `TOTAL_CONNECTIONS_PER_SECOND` (2500/sec) with `MAX_CONNECTION_BURST` (1000) burst allowance, and this check applies uniformly to *all* incoming connections before any stake-based classification differentiates staked vs. unstaked traffic.

Because this global bucket's token count is a function of aggregate connection volume from *all* sources combined, and not scoped per-source, an attacker does not need to violate any individual per-IP limit to deplete it. By rotating through K distinct source addresses within a single IPv6 /64 (a single host can trivially generate an enormous number of distinct addresses in a /64), the attacker can sustain an aggregate connection rate approaching `TOTAL_CONNECTIONS_PER_SECOND + MAX_CONNECTION_BURST` indefinitely, with each individual address well under its own per-IP quota. This collapses `current_tokens()` on the shared bucket to 0, and the `run_server` accept path then rejects/drops new connection attempts irrespective of whether they originate from staked validators or legitimate unstaked clients, since the global check gates entry before any staked-node prioritization logic can run.

This violates the stated invariant that unstaked connection limits are enforced per-source and cannot be evaded through identity/address churn — the global bucket effectively reintroduces a shared, unscoped resource that a distributed/rotating unstaked attacker can starve without ever tripping the per-IP guard that is supposed to be the primary defense against exactly this kind of behavior.

### Impact Explanation
This is a coarse-grained, unauthenticated Denial-of-Service against the TPU QUIC ingress path: a single unprivileged remote attacker rotating source addresses within one IPv6 /64 can deny new TPU connections to *all* clients (both staked and unstaked) on a leader/validator node, without needing any elevated privileges, stake, or leaked keys. This matches the Agave bounty category of a rate-limit/QoS bypass leading to availability impact on the TPU ingress.

### Likelihood Explanation
Feasibility is high: acquiring many unique IPv6 addresses within a single /64 requires no special privilege — any host with IPv6 connectivity can bind to or spoof (depending on network egress filtering) many addresses in its own /64 block. No cooperation from staked nodes, gossip, or validator config is required. The attack is fully reproducible by any unprivileged client with modest IPv6 address diversity and a QUIC client capable of opening many short-lived connections.

### Recommendation
Scope the "overall" connection admission control so that it cannot be trivially bypassed by address churn — e.g., weight/throttle contribution to the global bucket by subnet prefix (e.g., /64 or /56) rather than only by exact `IpAddr`, or make the global bucket's replenishment/burst budget reserve a guaranteed minimum share for staked-identified connections so unstaked floods (even distributed across many addresses) cannot fully starve staked traffic. Consider tracking connection admission per subnet aggregate in addition to per-exact-IP in `ConnectionRateLimiter`.

### Proof of Concept
Integration test plan (to be added under `streamer/src/nonblocking/quic.rs` tests or a new integration test):
1. Instantiate a `quic::run_server`-equivalent test harness with the real `overall_connection_rate_limiter` (`TokenBucket::new(TOTAL_CONNECTIONS_PER_SECOND as u64, MAX_CONNECTION_BURST, TOTAL_CONNECTIONS_PER_SECOND/60.0)` or however it is constructed).
2. Spawn K (e.g., 50) unique IPv6 source addresses drawn from a single simulated /64.
3. From each of the K addresses, open connections at a rate below the per-IP `ConnectionRateLimiter` threshold (so each individual address is never blocked by `ConnectionRateLimiter::is_allowed`).
4. Simultaneously, have a "legitimate" staked client attempt connections at a steady low rate.
5. Assert: (a) none of the K attacker addresses are ever blocked by the per-IP limiter, and (b) `overall_connection_rate_limiter.current_tokens()` reaches 0, and (c) the legitimate staked client's connection acceptance rate falls below a defined floor (e.g., <50% of attempted), demonstrating starvation caused purely by aggregate volume from distinct sources.     /// Check if the connection from the said `ip` is allowed.
    /// Here we assume that only IPs with actual confirmed connections are stored in it,
    /// since we should only modify server state once source IP is verified
    pub fn is_allowed(&self, ip: &IpAddr) -> bool {
        // Check if we have records in the rate limiter for the given IP address
        match self.limiter.current_tokens(ip) {
            Some(r) => r > 0, // we have a record, and rate is not exceeded
            None => true,     // if we have not seen IP, allow connection request
        }
    }

    pub fn register_connection(&self, ip: &IpAddr) -> bool {
        if self.limiter.consume_tokens(*ip, 1).is_ok() {
            debug!("Request from IP {ip:?} allowed");
            true // Request allowed
        } else {
            debug!("Request from IP {ip:?} blocked");
            false // Request blocked
        }
    }
