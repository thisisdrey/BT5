## Analysis

The reachable analog in Nebula is the freshness/staleness check in `HandshakeManager.CheckAndComplete`, which — just like the Symmetrical `liquidatePartyA` signature that omits any nonce/state binding — allows a captured, already-authenticated protocol message to be replayed later and accepted as if it reflected current state, overriding a legitimate, more current session. [1](#0-0) 

### Title
Handshake staleness check is bypassed when the existing tunnel was locally initiated, allowing replay of a captured stage-1 handshake to overwrite an established, valid tunnel - (File: handshake_manager.go)

### Summary
`CheckAndComplete` is supposed to protect an already-established tunnel from being torn down by an older/replayed handshake by comparing `lastHandshakeTime` values. That comparison is unconditionally skipped whenever the existing `HostInfo` was created as the initiator side, so a passively captured, previously-valid stage-1 handshake packet can be replayed by a network attacker at any later time to force the responder to discard its current session and rebuild state from stale data — with no nonce, counter, or freshness value that is actually enforced on this path.

### Finding Description
`beginHandshake` processes any inbound stage-1 packet (`MessageCounter == 1`, `RemoteIndex == 0`) by creating a fresh responder `Machine`, validating the peer's certificate, and then calling `CheckAndComplete`: [2](#0-1) 

Certificate validation only checks that the certificate is not expired and correctly signed — it says nothing about whether the specific handshake message is fresh: [3](#0-2) . The only anti-staleness/anti-replay control for *stage-1* messages is the `lastHandshakeTime` comparison inside `CheckAndComplete`:

```go
// Is this a newer handshake?
if existingHostInfo.lastHandshakeTime >= hostinfo.lastHandshakeTime && !existingHostInfo.ConnectionState.initiator {
    return existingHostInfo, ErrExistingHostInfo
}
existingHostInfo.logger(hm.l).Info("Taking new handshake")
``` [4](#0-3) 

`lastHandshakeTime` is populated directly from the attacker-visible `payload.Time` field carried in the (unauthenticated-for-freshness) handshake payload: [5](#0-4) , and the wire format documents this `Time` field as ordinary payload data with no nonce/counter binding to the current session state: [6](#0-5) .

The condition `existingHostInfo.lastHandshakeTime >= hostinfo.lastHandshakeTime && !existingHostInfo.ConnectionState.initiator` only rejects a stale/replayed handshake when the *existing* tunnel was created as a responder. If the existing tunnel was created as the *initiator* (i.e., this node initiated the currently-active session), the staleness comparison is bypassed entirely (`!initiator` is `false`, short-circuiting the `&&`), and any handshake packet — including a passively captured, arbitrarily old stage-1 packet from the same legitimate peer — is accepted as "newer" and replaces the existing `HostInfo`, tearing down the live tunnel and rebuilding session state from stale material. This exactly mirrors the root cause of H-1: a check meant to prevent "old signed state" from being applied after the real state has moved on is not actually bound to any monotonic/session-specific nonce, so an attacker who merely captures and replays a previously valid protocol message on the wire (no CA-signed certificate of their own required) can force acceptance of stale state.

### Impact Explanation
A pure network attacker who can observe/replay UDP traffic between two Nebula peers — without needing a CA-signed certificate — can replay an old, previously captured stage-1 handshake packet from a legitimate peer whenever the target locally initiated the current session. This forces `CheckAndComplete` to discard the live `HostInfo`/`ConnectionState` (including its cipher keys and replay window) and begin building a new one from stale material, causing tunnel disruption/rebuild on demand and creating a remote, repeatable denial-of-service / session-state-poisoning primitive against victims that have no way to detect the replay is stale, since the only guard against staleness is disabled on this path.

### Likelihood Explanation
Likelihood is moderate-to-high in typical deployments: any node that at some point initiates a handshake to a peer (which is common, e.g., both sides can be initiators over the tunnel's lifetime) is vulnerable whenever an attacker who can observe UDP traffic (on-path, or in a position to record packets, e.g. shared network segments, misconfigured relays, or simple traffic capture) replays one previously captured stage-1 packet. No cryptographic break or attacker-owned certificate is required — only replay of a legitimately captured packet.

### Recommendation
Remove the `!existingHostInfo.ConnectionState.initiator` carve-out, or otherwise bind handshake acceptance to a value that cannot be replayed independent of session state (e.g., always require `hostinfo.lastHandshakeTime` to be strictly newer than `existingHostInfo.lastHandshakeTime` regardless of which side initiated, and/or track handshake nonces/message counters per remote index so a previously-seen stage-1 payload cannot be reprocessed as "new" after the tunnel it produced has already been superseded).

### Proof of Concept
1. Node A and Node B complete a handshake where A is the initiator (`ConnectionState.initiator == true` on A's side for the established `HostInfo`).
2. An attacker on-path captures A's original stage-1 UDP packet (`MessageCounter == 1`, `RemoteIndex == 0`) sent to B.
3. Time passes; A and B continue operating on the established tunnel (possibly having roamed, rehandshaked with newer certs, etc., but A's local `HostInfo` for this session is still recorded with `initiator == true`).
4. Attacker replays the captured stage-1 packet to A.
5. In `beginHandshake` -> `CheckAndComplete`, since `existingHostInfo.ConnectionState.initiator == true`, the staleness check `existingHostInfo.lastHandshakeTime >= hostinfo.lastHandshakeTime && !existingHostInfo.ConnectionState.initiator` evaluates to `false` regardless of how old `hostinfo.lastHandshakeTime` is, so A logs "Taking new handshake" and replaces its live session with one derived from the stale replayed packet, per [7](#0-6) .

func (hm *HandshakeManager) beginHandshake(via ViaSender, packet []byte, h *header.H) {
	f := hm.f
	cs := f.pki.getCertState()

	v := cs.DefaultVersion()
	if cs.GetCredential(v) == nil {
		f.l.Error("Unable to handshake with host because no certificate is available",
			"from", via, "certVersion", v)
		return
	}

	machine, err := handshake.NewMachine(
		v, cs.GetCredential,
		hm.certVerifier(), func() (uint32, error) { return generateIndex(f.l) },
		false, header.HandshakeIXPSK0,
	)
	if err != nil {
		f.l.Error("Failed to create handshake machine", "from", via, "error", err)
		return
	}

	response, result, err := machine.ProcessPacket(nil, packet)
	if err != nil {
		f.l.Error("Failed to process handshake packet", "from", via, "error", err)
		return
	}

	if result == nil {
		// Multi-message pattern: the responder Machine would need to be
		// registered in hm.indexes so a future inbound packet finds it via
		// continueHandshake. The current manager doesn't do that yet, so
		// fail loudly rather than silently dropping the in-flight handshake.
		// TODO: support multi-message responder flows (XX, pqIX, etc.).
		// See also the IX-shaped cipher key assignment in handshake.Machine.
		f.l.Error("multi-message handshake responder is not supported",
			"from", via, "error", handshake.ErrMultiMessageUnsupported)
		return
	}

	remoteCert := result.RemoteCert
	if remoteCert == nil {
		f.l.Error("Handshake did not produce a peer certificate", "from", via)
		return
	}

	// Validate peer identity
	vpnAddrs, anyVpnAddrsInCommon, ok := hm.validatePeerCert(via, remoteCert)
	if !ok {
		return
	}

func (m *Machine) validateCert(payload Payload) error {
	cred := m.getCred(m.myVersion)
	if cred == nil {
		m.failed = true
		return fmt.Errorf("%w: %v", ErrNoCredential, m.myVersion)
	}
	rc, err := cert.Recombine(
		cert.Version(payload.CertVersion),
		payload.Cert,
		m.hs.PeerStatic(),
		cred.Cert.Curve(),
	)
	if err != nil {
		m.failed = true
		return fmt.Errorf("recombine cert: %w", err)
	}

	if !bytes.Equal(rc.PublicKey(), m.hs.PeerStatic()) {
		m.failed = true
		return ErrPublicKeyMismatch
	}

	// Version negotiation, if the peer sent a different version and we have it, switch
	if rc.Version() != m.myVersion {
		if m.getCred(rc.Version()) != nil {
			m.myVersion = rc.Version()
		}
	}

	verified, err := m.verifier(rc)
	if err != nil {
		m.failed = true
		return fmt.Errorf("verify cert: %w", err)
	}

	m.result.RemoteCert = verified
	m.remoteCertSet = true
	return nil
