### Title
Pingback handshake finish accepts hash-matching key with forged self-reported address, poisoning peer-DB frontier - (File: stackslib/src/net/neighbors/walk.rs)

### Summary
`check_handshake_pubkey_hash` in `stackslib/src/net/neighbors/walk.rs` only verifies that `Hash160::from_node_public_key_buffer(&data.handshake.node_public_key)` equals `naddr.public_key_hash`; it never asserts that `data.handshake.addrbytes`/`data.handshake.port` match the address the walk actually dialed (`naddr`/`peer_nk`). The self-reported (and unverified) address fields from the `HandshakeAccept` payload are then persisted verbatim into the peer DB by `add_or_schedule_replace_neighbor` → `Neighbor::load_and_update`, so a legitimate key-holder can make the node's frontier record an arbitrary third-party IP:port as "belonging to" their key.

### Finding Description
`pingback_handshakes_try_finish` (`stackslib/src/net/neighbors/walk.rs:1683-1742`) iterates replies keyed by the `naddr` the walk actually connected to, extracts the `HandshakeAcceptData`, computes `peer_nk` from the message's self-reported `data.handshake.addrbytes/port`, and calls `check_handshake_pubkey_hash(&peer_nk, data, &naddr)` (`walk.rs:1663-1680`). That function's entire validation is:
```
let neighbor_pubkey_hash = Hash160::from_node_public_key_buffer(&data.handshake.node_public_key);
if neighbor_pubkey_hash != naddr.public_key_hash { return false; }
true
```
There is no comparison of `data.handshake.addrbytes`/`port` against `naddr.addrbytes`/`port` (the address actually verified reachable via the outbound TCP dial). On success, `self.neighbor_db.add_or_schedule_replace_neighbor(network, &message.preamble, &data.handshake, db_data, ...)` (`walk.rs:1718-1724`) is invoked, which calls `Neighbor::load_and_update(&tx, preamble.peer_version, preamble.network_id, handshake)` in `stackslib/src/net/neighbors/db.rs:378-379`, building/saving the `Neighbor` record from the `HandshakeData` fields — i.e., from the attacker-controlled `addrbytes`/`port`, not from the connection-verified `naddr`.

The one place that cross-checks self-reported address against the actual connection is `ConversationP2P::validate_handshake` (`stackslib/src/net/chat.rs:1072-1091`), but that check only fires in the `Some(_)` branch, i.e. when the local peer *already* has a stored public key for that specific conversation. For a pingback handshake to a newly-discovered address, the conversation has no prior public key, so this branch is skipped entirely and only the signature (`verify_secp256k1`) is checked — the signature proves the sender holds the private key, not that the address field is truthful.

Consequently, an attacker who legitimately owns a keypair that is (or becomes) the pingback target can respond to the pingback `Handshake` with a signed `HandshakeAccept` whose `node_public_key` matches the expected hash but whose `addrbytes`/`port` name an arbitrary victim IP/port. `check_handshake_pubkey_hash` returns `true`, and the forged address is written into the peer DB as the `Neighbor` entry for that public key.

### Impact Explanation
This breaks the invariant that a frontier entry's `addrbytes`/`port` reflects the network address the key's owner actually controls. It results in the node persisting a forged mapping (attacker's real key → victim's IP/port) into its own peer DB, which subsequently drives the walk's future connection attempts and neighbor gossip toward the victim address under a false identity claim. This is a stored/persisted forged record (not just an in-memory guess), reachable purely by responding to an unauthenticated/unprivileged pingback dial — matching the "steering a node off the tip via false inventory" style High-impact category, since it corrupts the node's view of the network topology and can be repeated for any address the attacker chooses, for as long as the attacker's key remains a live pingback target.

### Likelihood Explanation
Preconditions: the attacker must be selected as a pingback target (i.e., have an inbound connection accepted by the victim node, or otherwise be scheduled for `PingbackHandshakesBegin`), and must be able to receive and respond to the outbound handshake the victim node sends when initiating the pingback dial. No RPC secret, no privileged role, and no other peer's key are required — the attacker only needs to run a normal, reachable P2P peer and respond with a specially crafted (but validly self-signed) `HandshakeAccept`. This is a low-cost, remotely reachable, repeatable action for any node capable of getting itself dialed via pingback.

### Recommendation
In `check_handshake_pubkey_hash` (`stackslib/src/net/neighbors/walk.rs`), additionally require `data.handshake.addrbytes == naddr.addrbytes && data.handshake.port == naddr.port` (allowing only the documented any-net exception used elsewhere), rejecting the handshake otherwise. Alternatively/also, when persisting via `add_or_schedule_replace_neighbor`/`Neighbor::load_and_update`, use the verified dialed address (`naddr`/`peer_nk`) rather than the self-reported `handshake.addrbytes/port` fields to build the stored `NeighborKey`.

### Proof of Concept
Add a test in `stackslib/src/net/neighbors/walk.rs` test module:
1. Set up a `NeighborWalk` in `PingbackHandshakesFinish` state with a pending pingback to `naddr` = `{addrbytes: A, port: P, public_key_hash: hash(K)}` (the address actually dialed).
2. Craft a `StacksMessageType::HandshakeAccept` signed with private key `K`, whose `HandshakeData.node_public_key` is the buffer for `K` (hash matches `naddr.public_key_hash`) but whose `HandshakeData.addrbytes/port` are set to an arbitrary victim address `V:Q` (different from `A:P`).
3. Feed this reply through the walk's `comms` mock so `pingback_handshakes_try_finish` processes it.
4. Assert `check_handshake_pubkey_hash` returns `true` for this crafted `data`/`naddr` pair, and assert that after calling `add_or_schedule_replace_neighbor`, the peer DB (via `Neighbor::load_by_address` or `PeerDB::get_peer`) contains a `Neighbor` row keyed on `V:Q` associated with public key `K` — demonstrating the forged victim address was persisted as the frontier entry for the attacker's real key.     /// Does a given handshakedata represent an expected public key hash?
    fn check_handshake_pubkey_hash(
        nk: &NeighborKey,
        data: &HandshakeAcceptData,
        naddr: &NeighborAddress,
    ) -> bool {
        let neighbor_pubkey_hash =
            Hash160::from_node_public_key_buffer(&data.handshake.node_public_key);
        if neighbor_pubkey_hash != naddr.public_key_hash {
            debug!(
                "Neighbor {:?} had an unexpected pubkey hash: expected {:?} != {:?}",
                nk, &naddr.public_key_hash, &neighbor_pubkey_hash
            );
            return false;
        }

        true
    }

    /// Finish up connecting to newly-discovered inbound peers
    pub fn pingback_handshakes_try_finish(
        &mut self,
        network: &mut PeerNetwork,
    ) -> Result<bool, net_error> {
        assert!(self.state == NeighborWalkState::PingbackHandshakesFinish);

        // see if we got any replies
        for (naddr, message) in self.comms.collect_replies(network).into_iter() {
            // if we got back a HandshakeAccept, and it's on the same chain as us, we're good!
            let (data, db_data) = match message.payload {
                StacksMessageType::HandshakeAccept(ref data) => {
                    debug!("{:?}: received HandshakeAccept from peer {:?}; now known to be routable from us", network.get_local_peer(), &message.to_neighbor_key(&data.handshake.addrbytes, data.handshake.port));
                    (data, None)
                }
                StacksMessageType::StackerDBHandshakeAccept(ref data, ref db_data) => {
                    debug!("{:?}: received StackerDBHandshakeAccept from peer {:?}; now known to be routable from us", network.get_local_peer(), &message.to_neighbor_key(&data.handshake.addrbytes, data.handshake.port));
                    (data, Some(db_data))
                }
                _ => {
                    let nkey = naddr.to_neighbor_key(network);
                    debug!(
                        "{:?}: Neighbor {:?} replied {:?} instead of pingback handshake",
                        network.get_local_peer(),
                        &nkey,
                        &message.get_message_name()
                    );
                    continue;
                }
            };

            let peer_nk = message.to_neighbor_key(&data.handshake.addrbytes, data.handshake.port);
            if !Self::check_handshake_pubkey_hash(&peer_nk, data, &naddr) {
                continue;
            }

            self.neighbor_db.add_or_schedule_replace_neighbor(
                network,
                &message.preamble,
                &data.handshake,
                db_data,
                &mut self.neighbor_replacements,
            )?;
        }

                "{}: already know about neighbor {:?}",
