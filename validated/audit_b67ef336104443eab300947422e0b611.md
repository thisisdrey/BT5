### Title
Unauthenticated peer can stall a `NakamotoTenureDownloader` forever by repeatedly returning an empty tenure body in `GetTenureBlocks` state - (File: stackslib/src/net/download/nakamoto/tenure_downloader.rs)

### Summary
When a `NakamotoTenureDownloader` is in `NakamotoTenureDownloadState::GetTenureBlocks`, a peer can respond with an HTTP body that decodes to zero blocks. `try_accept_tenure_blocks` treats this as a no-op (`Ok(None)`) without advancing `self.state` or returning an error, and `handle_next_download_response` unconditionally sets `self.idle = true` afterward. Since `send_next_download_request` only checks `has_inflight`/`is_dead_or_broken` and re-derives the request from `self.state`, it will re-issue the identical `GetTenureBlocks(end_block_id, ..)` request indefinitely, with no per-file attempt counter or backoff.

### Finding Description
In `try_accept_tenure_blocks` [1](#0-0) , an empty `tenure_blocks` vector short-circuits with `Ok(None)` and leaves `self.state` untouched. `handle_next_download_response` calls this path for the `GetTenureBlocks` arm and then unconditionally sets `self.idle = true` regardless of outcome [2](#0-1) . `send_next_download_request` then re-derives the next request purely from `self.state` via `make_next_download_request`, which for `GetTenureBlocks(end_block_id, start_request_time)` always constructs `StacksHttpRequest::new_get_nakamoto_tenure(peerhost, end_block_id.clone(), None)` [3](#0-2) , and there is no attempt counter, error, or backoff check inside this file that would abandon the peer or the slot after repeated empty responses [4](#0-3) . A malicious peer that owns the connection targeted by this downloader (i.e., is the `naddr` this machine is bound to) can therefore respond to every `GetTenureBlocks` request with a zero-block tenure body forever, and this file alone contains no mechanism to detect or terminate that loop.

### Impact Explanation
The attacker achieves an indefinite stall of the specific `NakamotoTenureDownloader` instance assigned to them for one historic tenure: no error is raised, no peer is blocklisted, and `self.state` never advances past `GetTenureBlocks`, so that tenure's blocks are never fetched from this peer via this state machine. This is a low-cost, repeatable, unauthenticated availability degradation reachable by any peer the node is downloading a historic tenure from — it requires no secret, no signature forgery, and no privileged role, matching the "unauthenticated DoS" category, though its blast radius is confined to the single downloader slot/peer pairing rather than a full node crash.

### Likelihood Explanation
Preconditions are minimal: the attacker only needs to be selected as the `naddr` peer for a given tenure's downloader (which happens naturally in normal peer selection/rotation) and to keep the TCP/HTTP connection alive while returning a valid but empty-tenure HTTP body on every `GetTenureBlocks` request. The attack costs the attacker essentially nothing per message and is fully repeatable for as long as the connection stays open. Whether this actually blocks the node's overall sync progress (versus just this one slot) depends on eviction/rotation logic in `tenure_downloader_set.rs` and `download_state_machine.rs`, which were not fully traced in this investigation — it is possible those layers eventually reassign the tenure to another peer or detect a lack of progress via other timeouts, which would bound (but not eliminate) the practical impact.

### Recommendation
Track an attempt/backoff counter (or reuse `start_request_time` to enforce a request-level timeout) in `NakamotoTenureDownloadState::GetTenureBlocks`, and treat repeated empty-tenure responses from the same peer as an error (e.g., return `Err(NetError::InvalidMessage)` or mark the peer dead) instead of silently returning `Ok(None)` with `self.idle = true`.

### Proof of Concept

2. Build a `StacksHttpResponse` whose body decodes via `decode_nakamoto_tenure()` into an empty `Vec<NakamotoBlock>`.

Assert after every call that `downloader.state == NakamotoTenureDownloadState::GetTenureBlocks(end_block_id, t0)` (unchanged) and `downloader.idle == true`, demonstrating the state never advances and the identical request would be re-issued by `make_next_download_request`/`send_next_download_request`.

    pub fn send_next_download_request(
        &mut self,
        network: &mut PeerNetwork,
        neighbor_rpc: &mut NeighborRPC,
    ) -> Result<bool, NetError> {
        if neighbor_rpc.has_inflight(&self.naddr) {
            debug!("Peer {} has an inflight request", &self.naddr);
            return Ok(true);
        }
        if neighbor_rpc.is_dead_or_broken(network, &self.naddr) {
            return Err(NetError::PeerNotConnected(format!(
                "Failed to send next download request to {:?}: connection is dead or broken",
                &self.naddr
            )));
        }

        let Some(peerhost) = NeighborRPC::get_peer_host(network, &self.naddr) else {
            // no conversation open to this neighbor
            neighbor_rpc.add_dead(
                network,
                &self.naddr,
                DropReason::DeadConnection("No authenticated connection open".into()),
                DropSource::NakamotoTenureDownloader,
            );
            return Err(NetError::PeerNotConnected(format!(
                "No authenticated connection open to {:?} for tenure download",
                &self.naddr
            )));
        };

        let request = match self.make_next_download_request(peerhost) {
            Ok(Some(request)) => request,
            Ok(None) => {
                return Ok(true);
            }
            Err(_) => {
                return Ok(false);
            }
        };

        neighbor_rpc.send_request(network, self.naddr.clone(), request)?;
        self.idle = false;
        Ok(true)
    }
