### Title
Missing Authentication on Signer's Event-Receiver HTTP Endpoints Allows Forged StackerDB/Block Data Injection - (File: libsigner/src/events.rs)

### Summary
`auth_token`/`Authorization` header checking exists only on the node side (e.g., `postblock_proposal.rs`, `httpcore.rs`) for inbound requests to the node. The signer's own HTTP listener, `SignerEventReceiver::next_event`, never validates any `Authorization` header on the requests it receives before dispatching them into the signer's processing pipeline.

### Finding Description
The `SignerEventReceiver` implementation binds an HTTP server and dispatches incoming POSTs purely by URL path — `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block`, `/shutdown` — with no check of an `Authorization` header or any shared secret before calling `process_event` and forwarding the resulting `SignerEvent` to the signer run-loop. [1](#0-0) 

By contrast, the node-side `auth_token` is documented specifically as securing "the communication channel between this node and a connected `stacks-signer` instance" via the `Authorization` header, and is enforced on the node's inbound endpoints (e.g. `/v3/block_proposal`). [2](#0-1) 

A `grep` across `libsigner/**` for `Authorization` returns no matches at all, confirming the signer's HTTP receiver code path never reads or validates that header. The equality that should hold — "event originated from the authenticated node with the shared `auth_token`" vs. "event accepted and forwarded to the signer run-loop" — is broken: any request reaching the signer's bound TCP port (which per `docs/signing.md` is often `0.0.0.0:30000`, i.e. bound on all interfaces) is treated as trusted, authenticated node data. [3](#0-2) 

The `/stackerdb_chunks` and `/new_block`/`/proposal_response` handlers deserialize attacker-controlled JSON directly into `SignerEvent<T>` and hand it to `forward_event`, which pushes it straight to the signer's decision-making channel with no origin check. [4](#0-3) 

### Impact Explanation
Because the endpoint is bound to `0.0.0.0` in the reference config and has no authentication, any network-reachable, unprivileged remote party can POST forged `StackerDBChunksEvent`, `BurnBlockEvent`, or `StacksBlockEvent` payloads directly to the signer, bypassing the node entirely. This lets an attacker inject fabricated StackerDB chunk data, burn-block, or block events into the signer's run-loop without needing the node's private key, the `auth_token`, or any signature — a remote unauthenticated write into the signer's internal state/event stream. Depending on how the run-loop interprets these forged events (e.g., stackerdb chunk contents used for signer coordination, or forged burn-block/tenure events), this can steer signer decisions using data that never actually came from the trusted node, which the task's impact bar explicitly calls out ("StackerDB chunk stored without a valid owner signature" / "forged gossip relayed" analog, but for the signer ingestion channel instead of node P2P).

### Likelihood Explanation
High. This requires only network reachability to the signer's configured `endpoint` (default guidance shows `0.0.0.0:30000`) and knowledge of the fixed set of well-known URL paths (`/stackerdb_chunks`, `/new_burn_block`, `/new_block`, `/proposal_response`, `/shutdown`) — all of which are publicly documented in this very repository (`docs/signing.md`, sample configs). No secrets, node keys, or signatures are needed to reach `process_event` and have the payload forwarded. Note: I could not verify from static reading alone whether some deployments place this endpoint behind `127.0.0.1` binding by convention/firewalling in practice; the code itself imposes no such restriction, and the sample signer config binds `0.0.0.0`.

### Recommendation
- Require and validate an `Authorization` header (matching the node's configured `auth_token`/`auth_password`) on every request in `SignerEventReceiver::next_event` before dispatching to `process_event`, rejecting unauthenticated requests with 401.
- Default-bind the event receiver to `127.0.0.1` unless explicitly overridden, and document/warn prominently when binding to `0.0.0.0` without auth configured.
- Consider mutual authentication (e.g., HMAC over the body using the shared secret) rather than a bare bearer token, to also guard against tampering in transit.

### Proof of Concept
1. Configure a `stacks-signer` per `sample/conf/signer/mainnet-signer-conf.toml`, with `endpoint = "0.0.0.0:30000"`.
2. From any host that can reach the signer's port (no credentials, no node key), send:
   `POST /stackerdb_chunks HTTP/1.1` with a crafted JSON body deserializable into `StackerDBChunksEvent`.
3. Observe in `libsigner/src/events.rs::next_event` that the request is accepted (`request.method() == Post` and URL matches), passed to `process_event::<T, StackerDBChunksEvent>(request)` with no `Authorization`/`auth_token` check, and — on successful JSON parsing — forwarded via `forward_event` into the signer run-loop's channel as a legitimate node-originated event.     /// Errors are recoverable -- the caller should call this method again even if it returns an
    /// error.
    fn next_event(&mut self) -> Result<SignerEvent<T>, EventError> {
        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)
            } else if request.url() == "/new_block" {
                process_event::<T, StacksBlockEvent>(request)
            } else {
                let url = request.url().to_string();
                debug!(
                    "[{:?}] next_event got request with unexpected url {}, return OK so other side doesn't keep sending this",
                    event_receiver.local_addr,
                    url
                );
                ack_dispatcher(request);
                Err(EventError::UnrecognizedEvent(url))
            }
        })?

    /// Forward an event
    /// Return true on success; false on error.
    /// Returning false terminates the event receiver.
    fn forward_event(&mut self, ev: SignerEvent<T>) -> bool {
        if self.out_channels.is_empty() {
            // nothing to do
            error!("No channels connected to event receiver");
            false
        } else if self.out_channels.len() == 1 {
            // avoid a clone
            if let Err(e) = self.out_channels[0].send(ev) {
                error!("Failed to send to signer runloop: {:?}", &e);
                return false;
            }
            true
        } else {
            for (i, out_channel) in self.out_channels.iter().enumerate() {
                if let Err(e) = out_channel.send(ev.clone()) {
                    error!("Failed to send to signer runloop #{}: {:?}", i, &e);
                    return false;
                }
            }
            true
        }
    }
