### Title
Out-of-bounds slice panic in `suffixarray.Index.Read` due to unvalidated chunk-size field - (File: src/index/suffixarray/suffixarray.go)

### Summary
`Index.Read` deserializes a suffix-array index from an `io.Reader` and calls the internal helper `readSlice` to decode each index chunk. `readSlice` reads an attacker-controlled `size` field and slices its fixed-size buffer with it (`buf[binary.MaxVarintLen64:size]`) without checking that `size` is at least `binary.MaxVarintLen64` or at most `len(buf)`, so a crafted stream causes an immediate `slice bounds out of range` runtime panic. This mirrors the CVE-2017-14226 pattern of an iterator/size field being trusted from untrusted serialized data and used to index into a buffer without validation, leading to an out-of-bounds access (there a heap over-read, here a Go bounds-check panic/DoS).

### Finding Description
Attacker input is a byte stream fed to `Index.Read(r io.Reader)` [1](#0-0) , which loops calling `readSlice(r, buf, sa, uint64(n))` [2](#0-1) . Inside `readSlice`, the chunk size is read via `readInt` into `size64` and only checked for overflow/negativity:
```go
size64, err = readInt(r, buf)
...
if int64(int(size64)) != size64 || int(size64) < 0 {
    return 0, errCorrupted
}
size := int(size64)
``` [3](#0-2) 
There is no check that `size >= binary.MaxVarintLen64` (10) or `size <= len(buf)` (`bufSize = 16<<10`) before the slice expression:
```go
if _, err = io.ReadFull(r, buf[binary.MaxVarintLen64:size]); err != nil {
``` [4](#0-3) 
If the attacker supplies `size < 10`, this is `buf[10:size]` with low > high, an invalid slice expression that panics with "slice bounds out of range" regardless of capacity. If `size > 16384` (`bufSize`), it panics with "slice bounds out of range ... with capacity 16384". Both are reachable purely by crafting the serialized stream that a caller passes to `Read`; no privileged input is required — this only relies on the previously-fixed protection for index counts (`go.dev/issue/53352`, visible in the comment and check at lines 146-152) which addresses a different part of the same decode loop but leaves the `size` field itself unvalidated.

### Impact Explanation
A crafted/corrupted serialized index (e.g., persisted by one process and loaded by another, or transmitted between systems) causes any consumer of `suffixarray.Index.Read` to panic instead of returning the documented `errCorrupted` error, i.e., a denial of service in the parsing/deserialization path of untrusted "published"/stored data. This is the same bug class as the CVE (iterator/size mishandling on attacker-supplied serialized data leading to out-of-bounds access) with a security-relevant negative outcome: a program that intended to gracefully reject corrupt index data (as `TestIndexCorruption` and `TestIssue53352` demonstrate the package's own intent to return `errCorrupted` rather than crash) instead crashes. This is a plausible malicious-input parser panic on a well-defined public deserialization API, matching Go's policy for accepting panic-only findings in parsers of untrusted data; it would likely be assessed as a PUBLIC-track fix (a `readSlice` size-bounds check), not urgent/security-critical crypto/authn bypass.

### Likelihood Explanation
Any application that calls `Index.Write` to persist an index and later `Index.Read`s it back from a source it does not fully trust (shared cache, uploaded artifact, network peer) is affected. The attacker only needs to supply the size-prefix bytes of the encoding; no authentication or special privileges are needed, matching the "ordinary user data / published data consumed by a normal victim workflow" premise.

### Recommendation
In `readSlice`, validate `size` immediately after decoding it: require `size >= binary.MaxVarintLen64 && size <= len(buf)`, returning `errCorrupted` otherwise, before performing `buf[binary.MaxVarintLen64:size]`.

### Proof of Concept
```go
package suffixarray

import (
	"bytes"
	"encoding/binary"
	"testing"
)

// TestReadCorruptedSizeUnderflowPanics demonstrates that a crafted
// serialized index with a too-small chunk-size field panics instead
// of returning errCorrupted.
func TestReadCorruptedSizeUnderflowPanics(t *testing.T) {
	data := []byte("x")
	index := New(data)
	var buf bytes.Buffer
	if err := index.Write(&buf); err != nil {
		t.Fatal(err)
	}
	encoding := buf.Bytes()

	// Locate the index-chunk size field (immediately after data length
	// varint header + data bytes) and corrupt it to an under-sized value
	// (less than binary.MaxVarintLen64), which readSlice does not reject.
	n := len(data)
	sizeFieldOffset := 10 + n
	// Encode a corrupted size of 2 (as varint*2) -- too small.
	corrupt := make([]byte, binary.MaxVarintLen64)
	binary.PutVarint(corrupt, 2)
	copy(encoding[sizeFieldOffset:sizeFieldOffset+binary.MaxVarintLen64], corrupt)

	defer func() {
		if r := recover(); r == nil {
			t.Fatal("expected panic due to invalid slice bounds, got none")
		} else {
			t.Logf("got panic (bug reproduced): %v", r)
		}
	}()

	var idx Index
	_ = idx.Read(bytes.NewReader(encoding)) // panics instead of returning errCorrupted
}
```
Expected (buggy) behavior: the test panics with `runtime error: slice bounds out of range [10:2]` instead of `Read` returning `errCorrupted`. After applying the recommended bounds check, `Read` should return `errCorrupted` and the test (rewritten to assert on the error) should pass without panicking.

func (x *Index) Read(r io.Reader) error {
	// buffer for all reads
	buf := make([]byte, bufSize)

	// read length
	n64, err := readInt(r, buf)
	if err != nil {
		return err
	}
	if int64(int(n64)) != n64 || int(n64) < 0 {
		return errCorrupted
	}
	n := int(n64)

	// allocate space
	if 2*n < cap(x.data) || cap(x.data) < n || x.sa.int32 != nil && n > maxData32 || x.sa.int64 != nil && n <= maxData32 {
		// new data is significantly smaller or larger than
		// existing buffers - allocate new ones
		x.data = make([]byte, n)
		x.sa.int32 = nil
		x.sa.int64 = nil
		if n <= maxData32 {
			x.sa.int32 = make([]int32, n)
		} else {
			x.sa.int64 = make([]int64, n)
		}
	} else {
		// re-use existing buffers
		x.data = x.data[0:n]
		x.sa = x.sa.slice(0, n)
	}

	// read data
	if _, err := io.ReadFull(r, x.data); err != nil {
		return err
	}

	// read index
	sa := x.sa
	for sa.len() > 0 {
		n, err := readSlice(r, buf, sa, uint64(n))
		if err != nil {
			return err
		}
		sa = sa.slice(n, sa.len())
	}
	return nil
}
