This confirms the key architectural fact: `TokenDiff::execute_intent` applies each signer's delta immediately via `engine.state.internal_apply_deltas(signer_id, [(token_id, delta)])` (which routes to `internal_add_balance`/`internal_sub_balance`), writing the actual account balance for that specific `signer_id` and `token_id` before `TransferMatcher` ever runs its cross-intent matching logic.### Binding
For every account `X` and token `T`: `token_balances[X][T]_after − token_balances[X][T]_before == Σ(deltas X personally signed for T)`. This equality is enforced structurally, independent of `TransferMatcher`.

### Evaluation
The premise of the question — that `TransferMatcher::finalize`'s cross-intent, per-`TokenId` aggregation can let a rounding residual leak into an account's actual balance across unrelated intents — does not hold, because `TransferMatcher` never writes account balances. It is a purely secondary bookkeeping structure.

The actual balance mutation happens at `TokenDiff::execute_intent`, which for each `(token_id, delta)` pair in the *signer's own* diff calls `engine.state.internal_apply_deltas(signer_id, [(token_id.clone(), *delta)])`, which resolves to `internal_add_balance`/`internal_sub_balance` [1](#0-0) . These are dispatched to the actual account-balance store (`CachedState::internal_add_balance`/`internal_sub_balance`) at [2](#0-1) , which mutate `account.token_amounts` keyed strictly by `owner_id` (the intent's `signer_id`) and the exact `amount` from that intent — with no dependency on any other intent in the batch.

`Deltas<S>` wraps this state only to *mirror* every add/sub into `TransferMatcher` (`self.deltas.deposit`/`self.deltas.withdraw`) purely for building `Transfers` (used for the MT transfer event) and for a global sanity check via `finalize()` [3](#0-2) . `TransferMatcher::finalize` never calls `internal_add_balance`/`internal_sub_balance` again — it only classifies already-applied deltas into sender→receiver pairs for the event, and returns `InvariantViolated::UnmatchedDeltas` if the batch-wide sum per token isn't zero [4](#0-3) .

So even in the crafted scenario (three triangular loops whose 1-unit `fee_ceil` residuals happen to cancel across unrelated token IDs), the only effect of `finalize()` succeeding is that the batch is accepted (no `InvariantViolated` error) and an MT transfer event is emitted reflecting matched flows. It does **not** grant any account extra balance beyond what its own signed `TokenDiff.diff` entries specified, because those balance writes already happened deterministically per-intent before `finalize()` runs. The repo's own `invariant_violated` test confirms the reverse direction: when the batch-wide net isn't zero, `execute_intents` fails and reverts, but even before reverting each user's balance change would only ever reflect that user's own diff [5](#0-4) .

Cross-token residual cancellation across unrelated triangular loops (e.g., a `+1` on token A canceling a `-1` on unrelated token C) is structurally impossible to begin with, since `TransferMatcher` keys transfers by `HashMap<TokenId, TokenTransferMatcher>` — deltas for different `TokenId`s are never mixed or netted against each other [6](#0-5) . Only same-`TokenId` deltas across different accounts are ever matched into a `Transfers` entry, and that matching only decides who is credited as "sender"/"receiver" in the emitted event — the actual balance numbers were already fixed per-intent.

    // Finalizes all transfers, or returns unmatched deltas.
    // If unmatched deltas overflow, then Err(None) is returned.
    pub fn finalize(self) -> Result<Transfers, InvariantViolated> {
        let mut transfers = Transfers::default();
        let mut deltas = TokenDeltas::default();
        for (token_id, transfer_matcher) in self.0 {
            if let Err(unmatched) = transfer_matcher.finalize_into(&token_id, &mut transfers)
                && (unmatched == 0 || deltas.apply_delta(token_id, unmatched).is_none())
            {
                return Err(InvariantViolated::Overflow);
            }
        }
        if !deltas.is_empty() {
            return Err(InvariantViolated::UnmatchedDeltas {
                unmatched_deltas: deltas,
            });
        }
        Ok(transfers)
    }
