### Title
Forged `RelayData` entries in the `relayers` field let an attacker suppress broadcast to an arbitrary connected peer - (File: `stackslib/src/net/p2p.rs`, `stackslib/src/net/chat.rs`)

### Summary
`PeerNetwork::broadcast_message` and `PeerNetwork::sample_broadcast_peers` skip forwarding a gossiped message to any currently-connected peer whose authenticated public-key hash appears in the message's `relay_hints`. These hints come directly from the attacker-controlled `relayers: Vec<RelayData>` field of the received `StacksMessage`, and `ConversationP2P::process_relayers` only validates that the list has no cycles and does not name the local node itself — it never verifies that the named peers actually relayed this specific message.

### Finding Description
The intended invariant is: *peers excluded from broadcast == peers who actually already relayed this message*. This is broken because:

- `sample_broadcast_peers` builds `relay_pubkhs` straight from the wire-supplied `relay_hints` and removes any live conversation whose pubkey hash matches, with no cross-check against real relay events: [1](#0-0) 
- `broadcast_message` performs the identical unverified check before forwarding per-recipient: [2](#0-1) 
- The only validation applied to the inbound `relayers` list is `ConversationP2P::process_relayers`, which checks for cycles (`check_relayer_cycles`) and that the local peer isn't listed (`check_relayers_remote`) — it does not confirm that any listed `RelayData.peer.public_key_hash` corresponds to a peer that genuinely handled this message: [3](#0-2) 

An attacker who knows (or guesses) a victim's public-key hash — learnable from any prior handshake, since it's not secret — can craft a `StacksMessage` (e.g. carrying `StacksMessageType::Transaction`) whose `relayers` vector includes a forged `RelayData` entry naming the victim's `public_key_hash`, with no cycle and without naming the receiving node itself. `process_relayers` accepts it. When the receiving node subsequently calls `broadcast_message`/`sample_broadcast_peers` with this `relayers` list, any live conversation to the victim on that node is silently excluded, denying the victim this data via that path.

### Impact Explanation
An unprivileged remote attacker can selectively deny a specific connected peer relay of a transaction (or, via the analogous block-push path validated the same way in `validate_blocks_push`) without corrupting or forging the payload itself, and while all other peers still receive it. This degrades gossip propagation reliability toward a targeted victim and is repeatable per message/per victim pubkey-hash. It does not crash the node, corrupt state, or forge data — the effect is confined to selective, silent non-delivery from the specific relaying node(s) that were fed the forged hint.

### Likelihood Explanation
Low cost: attacker only needs to know the victim's public-key hash (obtainable via a normal handshake) and be able to send a `StacksMessageType::Transaction`/blocks-push style message with a custom `relayers` field to any node that is also connected to the victim. No secret, signature forgery, or privileged role is required. Effectiveness depends on the victim also having redundant propagation paths through other peers, which in a well-connected gossip network partially mitigates full denial but does not eliminate the per-path suppression.

### Recommendation
Do not trust self-declared `RelayData` for broadcast-exclusion decisions unless it can be tied to verified relay activity (e.g., only exclude peers that this node's own `ConversationP2P` instance recorded as the actual sender of this exact message/signature, via `stats.add_relayer` bookkeping tied to the authenticated sender of that specific message), rather than trusting the full hint chain embedded in the message payload for suppression logic against arbitrary connected peers.

### Proof of Concept
In `stackslib/src/net/tests/relay/epoch2x.rs`, construct two connected `PeerNetwork` test peers (or reuse existing harness), and:
1. Build a `StacksMessage` wrapping `StacksMessageType::Transaction(...)` whose `relayers` vector contains a single `RelayData` with `peer.public_key_hash` set to an uninvolved third neighbor's known `public_key_hash` (not equal to sender or receiver), and `seq`/`peer` fields otherwise valid so `check_relayer_cycles`/`check_relayers_remote` pass.
2. Feed this message into the receiving peer's `ConversationP2P::process_relayers`/push handler and confirm it is accepted (`true`/`Ok`) despite the third neighbor never having relayed anything.
3. Call `PeerNetwork::sample_broadcast_peers` (or `broadcast_message`) on the receiving node with that same `relay_hints`, and assert that the third neighbor's `NeighborKey` is excluded from the resulting recipient set / never receives `sign_and_forward`, even though it never actually relayed the message — demonstrating the broken equality.

    /// Verify that there are no cycles in our relayers list.
    /// Identify relayers by public key hash
    fn check_relayer_cycles(relayers: &[RelayData]) -> bool {
        let mut addrs = HashSet::new();
        for r in relayers.iter() {
            if addrs.contains(&r.peer.public_key_hash) {
                return false;
            }
            addrs.insert(r.peer.public_key_hash.clone());
        }
        true
    }

    /// Verify that we aren't in this relayers list
    fn check_relayers_remote(local_peer: &LocalPeer, relayers: &[RelayData]) -> bool {
        let addr = local_peer.to_neighbor_addr();
        for r in relayers.iter() {
            if r.peer.public_key_hash == addr.public_key_hash {
                return false;
            }
        }
        return true;
    }

    /// Check that a message was properly relayed.
    /// * there are no relay cycles
    /// * we didn't send this
    ///
    /// Update relayer statistics for this conversation
    fn process_relayers(
        &mut self,
        local_peer: &LocalPeer,
        preamble: &Preamble,
        relayers: &[RelayData],
    ) -> bool {
        if !ConversationP2P::check_relayer_cycles(relayers) {
            warn!(
                "Invalid relayers -- message from {:?} contains a cycle",
                self.to_neighbor_key()
            );
            return false;
        }

        if !ConversationP2P::check_relayers_remote(local_peer, relayers) {
            warn!(
                "Invalid relayers -- message originates from us ({})",
                local_peer.to_neighbor_addr()
            );
            return false;
        }

        for relayer in relayers.iter() {
            self.stats
                .add_relayer(&relayer.peer, (preamble.payload_len - 1) as u64);
        }

        return true;
    }
