### Title
Stale `total_stake` snapshot locked into QUIC connection context permanently misallocates stream throttling QoS - (File: streamer/src/nonblocking/swqos.rs)

### Summary
The Stake-Weighted QoS (`SwQos`) QUIC connection handler determines a connecting peer's `peer_type` classification and caches the network-wide `total_stake` value once, at connection-establishment time, inside `SwQosConnectionContext`. This cached value is then used for the entire lifetime of the long-lived QUIC connection to compute both the one-time max-concurrent-uni-streams grant and every subsequent per-stream throttling decision, even though the underlying `total_stake` denominator is refreshed independently every 5 seconds. This mirrors the report's root cause: a ratio-based quorum/threshold is snapshotted at "creation" time and never re-derived against the live total, so later checks are evaluated against a value that can be arbitrarily stale relative to current reality.

### Finding Description
`get_connection_stake()` reads the peer's stake and the *current* `total_stake` at the moment a connection is built: [1](#0-0) 

This snapshot is stored once in `SwQosConnectionContext` inside `build_connection_context()`, including the `peer_type` classification (`Staked`/`Unstaked` decided via `stake_ratio = stake / total_stake`) and the raw `total_stake` field: [2](#0-1) 

That cached `conn_context.total_stake` is then used to compute the one-time `max_uni_streams` grant for the connection: [3](#0-2) 

and it is also reused on every subsequent stream, for the life of the connection, to compute the throttling capacity via `max_streams_per_throttling_interval()` → `available_load_capacity_in_throttling_duration()`: [4](#0-3) [5](#0-4) 

Meanwhile, the actual `StakedNodes.total_stake()` denominator that this snapshot was drawn from is refreshed independently and continuously by `StakedNodesUpdaterService`, on a 5-second cycle, tracking the root bank's live epoch stake distribution: [6](#0-5) 

There is no mechanism that re-evaluates `peer_type` or `total_stake` for an already-open connection; the QUIC connection persists (subject only to unrelated pruning/idle-timeout logic) with its originally-cached, now potentially stale ratio. This is structurally identical to the Olympus bug: a ratio (`stake_ratio`, quorum) is computed once against a "total supply"/"total stake" value taken at a point in time, and is used unchanged for downstream admission/throughput decisions indefinitely, without ever being reconciled against the live total.

### Impact Explanation
Because `total_stake` (and the derived `peer_type`/QoS share) is fixed for the life of a connection while the real network `total_stake` moves continuously (delegations, deactivations, epoch boundary stake transitions, and node startup transients before `staked_nodes` is first populated), any unprivileged staked peer can open a TPU/TPU-forward QUIC connection at a moment when `total_stake` is comparatively low, lock in a favorable `stake_ratio` → `ConnectionPeerType::Staked` classification and a correspondingly large `max_uni_streams`/`max_streams_per_throttling_interval` allocation, and then keep that connection alive as `total_stake` subsequently grows. The peer permanently retains a QoS/stream-throughput allocation disproportionate to its true, current fractional stake — a QoS evasion of the stake-weighted admission design, achievable purely by an ordinary network peer with no validator/operator privilege, using only the standard TPU QUIC client path.

### Likelihood Explanation
`total_stake` legitimately fluctuates every epoch and is only re-sampled every 5 seconds server-side; QUIC connections used for TPU traffic are commonly kept open for extended periods to avoid handshake overhead, so the window during which a peer can "lock in" a favorable ratio and then benefit from it as stake shifts is realistic and requires no special timing precision — the peer simply needs to be connected while total_stake later increases (a routine, frequent occurrence on a live cluster).

### Recommendation
Periodically re-derive `peer_type` and `total_stake` for already-open connections (e.g., on a timer alongside the stream-load EMA refresh, or by re-querying `staked_nodes` on each `throttle_stream`/stream-open call) rather than caching it once in `SwQosConnectionContext` for the connection's entire lifetime, mirroring the fix pattern of periodically re-snapshotting/activating against the current total rather than a value fixed at admission time.

### Proof of Concept
1. Attacker holds a small amount of stake and observes (via public epoch stake data) that `total_stake` is currently comparatively low, or connects immediately as the validator boots (before `StakedNodesUpdaterService` completes its first refresh at `core/src/staked_nodes_updater_service.rs:32-39`).
2. Attacker opens a QUIC connection to the validator's TPU port; `build_connection_context()` computes `stake_ratio = stake/total_stake` using the momentarily-low `total_stake`, classifying the peer as `Staked` with a favorable ratio, and `cache_new_connection()` sets `max_uni_streams` accordingly (`streamer/src/nonblocking/swqos.rs:181-202`).
3. Attacker keeps the connection alive (standard QUIC keep-alive) while the cluster's real `total_stake` grows over subsequent epochs.
4. Every subsequent stream on that connection continues to be throttled using the original stale `conn_context.total_stake` (`streamer/src/nonblocking/swqos.rs:292-298`), so the attacker's allotted share of the staked throttling budget never shrinks to match their true, now much smaller, stake fraction — granting them a persistently outsized share of TPU stream throughput relative to honest peers who connect later at the correct, higher `total_stake`.

fn compute_max_allowed_uni_streams_with_rtt(
    rtt_millis: u32,
    peer_type: ConnectionPeerType,
    total_stake: u64,
) -> u32 {
    let streams = match peer_type {
        ConnectionPeerType::Staked(peer_stake) => {
            // No checked math for f64 type. So let's explicitly check for 0 here
            if total_stake == 0 || peer_stake > total_stake {
                warn!(
                    "Invalid stake values: peer_stake: {peer_stake:?}, total_stake: \
                     {total_stake:?}"
                );

                QUIC_MIN_STAKED_CONCURRENT_STREAMS
            } else {
                let delta = (QUIC_TOTAL_STAKED_CONCURRENT_STREAMS
                    - QUIC_MIN_STAKED_CONCURRENT_STREAMS) as f64;

                (((peer_stake as f64 / total_stake as f64) * delta) as u32
                    + QUIC_MIN_STAKED_CONCURRENT_STREAMS)
                    .clamp(
                        QUIC_MIN_STAKED_CONCURRENT_STREAMS,
                        QUIC_MAX_STAKED_CONCURRENT_STREAMS,
                    )
            }
        }
        ConnectionPeerType::Unstaked => QUIC_MAX_UNSTAKED_CONCURRENT_STREAMS,
    };
    // scale amount of streams based on RTT if RTT is larger than REFERENCE_RTT_MS
    // multiply first then divide to avoid rounding errors.
    (streams.saturating_mul(rtt_millis.clamp(REFERENCE_RTT_MS, MAX_RTT_MS))) / REFERENCE_RTT_MS
}

impl QosController<SwQosConnectionContext> for SwQos {
    fn build_connection_context(&self, connection: &Connection) -> SwQosConnectionContext {
        let remote_address = connection.remote_address();
        get_connection_stake(connection, &self.staked_nodes).map_or(
            SwQosConnectionContext {
                peer_type: ConnectionPeerType::Unstaked,
                total_stake: 0,
                remote_pubkey: None,
                in_staked_table: false,
                remote_address,
                stream_counter: None,
                last_update: Arc::new(AtomicU64::new(timing::timestamp())),
            },
            |(pubkey, stake, total_stake)| {
                // The heuristic is that the stake should be large enough to have 1 stream pass through within one throttle
                // interval during which we allow max (MAX_STREAMS_PER_MS * STREAM_THROTTLING_INTERVAL_MS) streams.

                let peer_type = {
                    let max_streams_per_ms = self.staked_stream_load_ema.max_streams_per_ms();
                    let min_stake_ratio =
                        1_f64 / (max_streams_per_ms * STREAM_THROTTLING_INTERVAL_MS) as f64;
                    let stake_ratio = stake as f64 / total_stake as f64;
                    if stake_ratio < min_stake_ratio {
                        // If it is a staked connection with ultra low stake ratio, treat it as unstaked.
                        ConnectionPeerType::Unstaked
                    } else {
                        ConnectionPeerType::Staked(stake)
                    }
                };

                SwQosConnectionContext {
                    peer_type,
                    total_stake,
                    remote_pubkey: Some(pubkey),
                    in_staked_table: false,
                    remote_address,
                    last_update: Arc::new(AtomicU64::new(timing::timestamp())),
                    stream_counter: None,
                }
            },
        )

    pub(crate) fn available_load_capacity_in_throttling_duration(
        &self,
        peer_type: ConnectionPeerType,
        total_stake: u64,
    ) -> u64 {
        match peer_type {
            ConnectionPeerType::Unstaked => self.max_unstaked_load_in_throttling_window,
            ConnectionPeerType::Staked(stake) => {
                if self.staked_throttling_enabled.load(Ordering::Relaxed) {
                    // 1 is added to `max_unstaked_load_in_throttling_window` to guarantee that staked
                    // clients get at least 1 more number of streams than unstaked connections.
                    self.max_staked_load_in_throttling_window
                        .saturating_mul(stake)
                        .checked_div(total_stake)
                        .unwrap_or(self.max_unstaked_load_in_throttling_window + 1)
                        .max(self.max_unstaked_load_in_throttling_window + 1)
                } else {
                    self.max_staked_load_in_throttling_window
                }
            }
        }
    }

const STAKE_REFRESH_CYCLE: Duration = Duration::from_secs(5);

pub struct StakedNodesUpdaterService {
    thread_hdl: JoinHandle<()>,
}

impl StakedNodesUpdaterService {
    pub fn new(
        exit: Arc<AtomicBool>,
        bank_forks: Arc<RwLock<BankForks>>,
        staked_nodes: Arc<RwLock<StakedNodes>>,
        staked_nodes_overrides: Arc<RwLock<HashMap<Pubkey, u64>>>,
    ) -> Self {
        let thread_hdl = Builder::new()
            .name("solStakedNodeUd".to_string())
            .spawn(move || {
                while !exit.load(Ordering::Relaxed) {
                    let stakes = {
                        let root_bank = bank_forks.read().unwrap().root_bank();
                        root_bank.current_epoch_staked_nodes()
                    };
                    let overrides = staked_nodes_overrides.read().unwrap().clone();
                    *staked_nodes.write().unwrap() = StakedNodes::new(stakes, overrides);
                    std::thread::sleep(STAKE_REFRESH_CYCLE);
                }
            })
            .unwrap();

        Self { thread_hdl }
    }
