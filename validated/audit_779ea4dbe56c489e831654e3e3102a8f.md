### Title
Unthrottled per-packet handshake processing allows spoofed-source flood to exhaust CPU and starve legitimate handshakes - (File: `handshake_manager.go`)

### Summary
The original report's bug class is "no upfront cost to reserve a resource lets an attacker occupy it and starve legitimate users." The closest reachable analog in nebula for an attacker with no CA-signed certificate is in the UDP handshake-intake path: `HandshakeManager.HandleIncoming` / `beginHandshake` perform no per-source rate limiting or proof-of-work before spending asymmetric crypto (Noise `ReadMessage`, which includes an X25519 DH) on every inbound stage-1 packet. Since UDP source addresses are trivially spoofable and `RemoteIndex==0` is the only structural gate, an attacker can flood many fabricated stage-1 packets (from many spoofed addresses) at effectively no cost, forcing the responder to repeatedly perform DH computations before any certificate is checked, degrading or blocking handshake processing for real peers.

### Finding Description
`HandleIncoming` gates stage-1 packets only on subtype and `RemoteIndex == 0`: [1](#0-0) 

It then unconditionally calls `beginHandshake`, which builds a brand-new `handshake.Machine` and calls `machine.ProcessPacket`, which invokes Noise's `ReadMessage` (an asymmetric DH + AEAD decrypt) *before* any certificate is validated: [2](#0-1) [3](#0-2) 

There is no per-source-IP counter, cookie/puzzle, or rate limiter anywhere in this path — a search of the codebase for rate-limiting primitives around handshake intake returns nothing relevant. The only pre-crypto check is `lighthouse.remote_allow_list`, which is permissive by default and, in any case, only filters known bad ranges rather than bounding request rate: [4](#0-3) 

This mirrors the reported bug's structure: a cheap, unauthenticated action (`setreservationforlongterm` with no deposit / a spoofed UDP stage-1 packet) forces the target to spend resources (blocked rental slot / CPU-bound DH computation) that legitimate users then have to compete for, with no cost imposed on the attacker to offset the abuse.

### Impact Explanation
Because source UDP addresses can be spoofed and each stage-1 packet costs the target CPU cycles for a DH operation before any certificate is verified, a moderate-rate flood of fabricated packets can consume the responder's CPU handling capacity, delaying or dropping legitimate handshake attempts — a remote resource-exhaustion/availability impact against the node's handshake path. This does not bypass authentication or decrypt traffic; it is a denial-of-service exposure analogous in structure (uncosted repeated resource consumption blocking honest users) to the reported finding.

### Likelihood Explanation
Likelihood is plausible but bounded: it requires sustained packet volume to have observable effect (a single fake packet only costs one DH operation), and nebula already drops many malformed shapes cheaply (unsupported subtype, non-zero `RemoteIndex` on stage-1). The remaining unmitigated cost is the DH + AEAD attempt on every well-formed-looking stage-1 packet regardless of eventual cert validity, with no rate limiting to cap this per source.

### Recommendation
Add a lightweight, pre-crypto anti-flood mechanism on the handshake intake path, e.g.:
- Per-source (and possibly global) rate limiting/backoff for stage-1 packets before invoking `beginHandshake`.
- A stateless cookie/puzzle-style response mechanism (as used by WireGuard) so the expensive DH step is deferred until the initiator proves it can receive traffic at the claimed source address.
- Metrics/alerting on stage-1 processing rate to detect flood conditions.

### Proof of Concept
Not applicable in the strict sense of a decisive PoC transaction (as in the original smart-contract finding) — this is a protocol-level resource-cost analysis. A conceptual PoC would involve sending a high rate of syntactically-valid `header.HandshakeIXPSK0` stage-1 UDP packets (`RemoteIndex=0`, `MessageCounter=1`) with random ephemeral keys from spoofed source addresses at a nebula listener and observing CPU usage on `beginHandshake`/`machine.ProcessPacket` versus successful legitimate handshake latency, using the existing e2e handshake test harness (e.g. patterns in `e2e/handshake_manager_test.go`) as a base for instrumentation. func (hm *HandshakeManager) HandleIncoming(via ViaSender, packet []byte, h *header.H) {
	// Gate on known handshake subtypes. Unknown subtypes (or future ones we
	// don't yet support) are dropped here rather than silently routed through
	// the IX path. Add a case when introducing a new pattern.
	switch h.Subtype {
	case header.HandshakeIXPSK0:
		// supported
	default:
		hm.l.Debug("dropping handshake with unsupported subtype",
			"from", via, "subtype", h.Subtype)
		return
	}

	// First remote allow list check before we know the vpnIp
	if !via.IsRelayed {
		if !hm.lightHouse.GetRemoteAllowList().AllowUnknownVpnAddr(via.UdpAddr.Addr()) {
			hm.l.Debug("lighthouse.remote_allow_list denied incoming handshake", "from", via)
			return
		}
	}

	// First message of a new handshake. The wire format requires RemoteIndex
	// to be zero here (the initiator has no responder index to fill in yet),
	// and generateIndex never allocates 0, so any non-zero RemoteIndex on a
	// stage-1 packet is malformed or someone probing for an index collision.
	// Drop without paying the cost of running noise on a pending Machine.
	if h.MessageCounter == 1 {
		if h.RemoteIndex != 0 {
			hm.l.Debug("dropping stage-1 handshake with non-zero RemoteIndex",
				"from", via, "remoteIndex", h.RemoteIndex)
			return
		}
		hm.beginHandshake(via, packet, h)
		return
	}

	// Continuation message must match a pending handshake by index.
	// Anything else is an orphaned packet (e.g., late retransmit after
	// timeout) and is dropped.
	if hh := hm.queryIndex(h.RemoteIndex); hh != nil {
		hm.continueHandshake(via, hh, packet)
		return
	}
}

// beginHandshake handles an incoming handshake packet that doesn't match any
// existing pending handshake. It creates a new responder Machine and processes
// the first message.
func (hm *HandshakeManager) beginHandshake(via ViaSender, packet []byte, h *header.H) {
	f := hm.f
	cs := f.pki.getCertState()

	v := cs.DefaultVersion()
	if cs.GetCredential(v) == nil {
		f.l.Error("Unable to handshake with host because no certificate is available",
			"from", via, "certVersion", v)
		return
	}

	machine, err := handshake.NewMachine(
		v, cs.GetCredential,
		hm.certVerifier(), func() (uint32, error) { return generateIndex(f.l) },
		false, header.HandshakeIXPSK0,
	)
	if err != nil {
		f.l.Error("Failed to create handshake machine", "from", via, "error", err)
		return
	}

	response, result, err := machine.ProcessPacket(nil, packet)
	if err != nil {
		f.l.Error("Failed to process handshake packet", "from", via, "error", err)
		return
	}

func (m *Machine) ProcessPacket(out, packet []byte) ([]byte, *Result, error) {
	if m.failed {
		return nil, nil, ErrMachineFailed
	}
	if len(packet) < header.Len {
		return nil, nil, ErrPacketTooShort
	}
	// Reject packets whose subtype doesn't match the one this Machine was
	// built for. A pending handshake that suddenly receives a different
	// subtype on its index is either a stray packet that matched by chance
	// or a peer protocol violation; drop it without failing the Machine so
	// the legitimate retransmit can still complete.
	if header.MessageSubType(packet[1]) != m.subtype {
		return nil, nil, ErrSubtypeMismatch
	}
	if m.result.Initiator && m.hs.MessageIndex() == 0 {
		m.failed = true
		return nil, nil, ErrInitiateNotCalled
	}

	// The (eKey, dKey) ordering here is correct for IX, where the initiator
	// completes the handshake by reading the responder's stage-2 message.
	// noise returns (cs1, cs2) where cs1 is the initiator->responder cipher.
	// For 3-message patterns where a responder finishes by reading the final
	// message, this ordering would be wrong; revisit when XX/pqIX lands.
	msg, eKey, dKey, err := m.hs.ReadMessage(nil, packet[header.Len:])
	if err != nil {
		// Noise ReadMessage failed. The noise library checkpoints and rolls back
		// on failure, so the Machine is still alive. The caller can retry with
		// a different packet.
		return nil, nil, fmt.Errorf("noise ReadMessage: %w", err)
	}
