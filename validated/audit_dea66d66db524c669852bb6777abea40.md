### Title
StackerDB chunk signature omits contract/StackerDB identity, enabling cross-contract replay - ([File: libstackerdb/src/libstackerdb.rs])

### Summary
`SlotMetadata::auth_digest()` computes the signed digest from only `slot_id`, `slot_version`, and `data_hash` — it never includes the target smart contract's identity (`QualifiedContractIdentifier`). A validly-signed chunk gossiped/relayed for one StackerDB instance (contract) can be replayed by anyone to a different StackerDB instance, as long as the same signer address owns a slot with a matching `slot_id` there and the version/data constraints line up. This mirrors the `preMint()` finding: a signature that omits the "contract" component can be replayed across sibling instances that share the same signer keys.

### Finding Description
The signed digest is built here: [1](#0-0) 

Verification (`SlotMetadata::verify`) only recovers the pubkey from this digest and compares its hash to the caller-supplied `principal` address — it has no knowledge of which contract it is being checked against: [2](#0-1) 

The contract binding is enforced only *externally*, by looking up the expected signer address for a given `(smart_contract_id, slot_id)` pair and checking whether that address matches the recovered key — but never checking that the signature was produced for *that* contract: [3](#0-2) [4](#0-3) 

This is explicitly acknowledged in the SQL schema comment for the `chunks` table: the signature covers `slot_id`, `version`, `data_hash`, but the `signer`/contract binding is "NOT covered by the signature": [5](#0-4) 

Consequently, if the same signer address is assigned the same `slot_id` in two different StackerDB contracts (which is the normal configuration for the Nakamoto signer set: each reward cycle has multiple parallel StackerDB contracts, e.g. `signer-<cycle>-0` and `signer-<cycle>-1`, populated from the same signer set/slot layout — see `signers-0-xxx.clar` / `signers-1-xxx.clar` and `chainstate/nakamoto/signer_set.rs`), a chunk signed for slot `k` in contract A is also a valid signature for slot `k` in contract B, because the digest never encodes which contract it belongs to.

### Impact Explanation
An attacker who observes a legitimately signed StackerDB chunk (chunks are broadcast/gossiped in the clear over the P2P network and served via the HTTP StackerDB endpoints) can resubmit the exact same `(slot_id, slot_version, sig, data)` tuple to a *different* StackerDB contract in which the same signer owns the same slot ID. `try_replace_chunk`/`validate_received_chunk` will accept it as a validly-signed write for that unrelated contract, because signature verification only checks the recovered pubkey against the *contract-specific* configured signer, not against a per-contract commitment inside the signature itself: [6](#0-5) 

This is an unauthenticated write of attacker-controlled (but originally legitimately-signed) data into a StackerDB contract the signer never intended it for, which can corrupt cross-lane signer-message consumption (e.g. `libsigner`'s message-lane filtering in `signer_message_payload_matches_lane`, `libsigner/src/events.rs:568-619`) — messages meant for one lane/contract can be forced to appear valid (with a matching payload-type byte crafted by the attacker within the replayed `data`) in another lane, potentially confusing signer-side consensus-adjacent logic that trusts "this chunk is signed by signer X for contract Y."

### Likelihood Explanation
Requires: (1) multiple StackerDB contracts sharing signer-to-slot assignments (true by design for the Nakamoto signer boot contracts across message lanes), and (2) attacker capturing a legitimately broadcast chunk (chunks are not confidential; StackerDB is a public gossip/replica system) and resubmitting it to a sibling contract with a valid (fresh) slot version there. No private key or privileged role is needed — replay only requires observing public network traffic and issuing an unprivileged `PUT chunk`/gossip push, which is within the "remote, unprivileged" analog criteria.

### Recommendation
Include the target `QualifiedContractIdentifier` (StackerDB contract identity) as part of `SlotMetadata::auth_digest()`, so signatures are bound to the specific StackerDB instance they were produced for, analogous to adding the contract address into the `preMint()` signature payload in the original report.

### Proof of Concept
1. Configure two StackerDB contracts, A and B, both assigning slot `0` to signer address `S` (this mirrors the real signer-set boot contracts, which assign identical slot layouts across parallel `signer-<cycle>-<message-id>` contracts).
2. Signer `S` legitimately signs and pushes chunk `(slot_id=0, slot_version=1, data=D)` to contract A via `StackerDBChunkData::sign` (`libstackerdb/src/libstackerdb.rs:226-231`).
3. Attacker observes this chunk (via P2P `StackerDBPushChunk` gossip or the HTTP GET chunk endpoint).
4. Attacker resubmits the identical `(slot_id=0, slot_version=1, sig, data=D)` tuple, but targeting contract B's `smart_contract_id`.
5. `PeerNetwork::validate_received_chunk` (or `StackerDBTx::try_replace_chunk`) looks up `get_slot_signer(B, 0)` → returns `S`; `slot_metadata.verify(&S)` succeeds because the digest never referenced contract A or B — the write is accepted into contract B's slot 0, even though `S` never intended to sign anything for contract B.     /// Get the digest to sign that authenticates this chunk data and metadata
    fn auth_digest(&self) -> Sha512Trunc256Sum {
        let mut hasher = Sha512_256::new();
        hasher.update(self.slot_id.to_be_bytes());
        hasher.update(self.slot_version.to_be_bytes());
        hasher.update(self.data_hash.0);
        Sha512Trunc256Sum::from_hasher(hasher)
    }

    /// Sign this slot metadata, committing to slot_id, slot_version, and
    /// data_hash.  Sets self.signature to the signature.
    /// Fails if the underlying crypto library fails
    pub fn sign(&mut self, privkey: &StacksPrivateKey) -> Result<(), Error> {
        let auth_digest = self.auth_digest();
        let sig = privkey
            .sign(&auth_digest.0)
            .map_err(|se| Error::SigningError(se.to_string()))?;

        self.signature = sig;
        Ok(())
    }

    /// Verify that a given principal signed this chunk metadata.
    /// Note that the address version is ignored.
    pub fn verify(&self, principal: &StacksAddress) -> Result<bool, Error> {
        let sigh = self.auth_digest();
        let pubk = StacksPublicKey::recover_to_pubkey_without_validating_low_s(
            sigh.as_bytes(),
            &self.signature,
        )
        .map_err(|ve| Error::VerifyingError(ve.to_string()))?;

        let pubkh = Hash160::from_node_public_key(&pubk);
        Ok(pubkh == *principal.bytes())
    }

    /// pushed to us (with [`PeerNetwork::handle_unsolicited_StackerDBPushChunk`])
    ///
    /// NOTE: does not check write frequency, since the caller has different ways of doing this.
    /// Returns:
    /// - Ok(true) if the chunk is valid
    /// - Ok(false) if the chunk is invalid
    /// - Err(..) on DB error
    pub fn validate_received_chunk(
        &self,
        smart_contract_id: &QualifiedContractIdentifier,
        config: &StackerDBConfig,
        data: &StackerDBChunkData,
        expected_versions: &[u32],
    ) -> Result<bool, net_error> {
        // validate -- must not exceed this replica's configured chunk size.
        if (data.data.len() as u64) > config.chunk_size {
            info!(
                "Received StackerDBChunk for {} ID {}, which is oversized: {} bytes (max {} bytes)",
                smart_contract_id,
                data.slot_id,
                data.data.len(),
                config.chunk_size
            );
            return Ok(false);
        }

        // validate -- must be a valid chunk
        let Some(expected_version) = expected_versions.get(data.slot_id as usize) else {
            info!(
                "Received StackerDBChunk for {} ID {}, which is too big ({})",
                smart_contract_id,
                data.slot_id,
                expected_versions.len()
            );
            return Ok(false);
        };

        // validate -- must be signed by the expected author
        let addr = match self
            .stackerdbs
            .get_slot_signer(smart_contract_id, data.slot_id)?
        {
            Some(addr) => addr,
            None => {
                return Ok(false);
            }
        };

        let slot_metadata = data.get_slot_metadata();
        if !slot_metadata.verify(&addr)? {
            info!(
                "StackerDBChunk for {} ID {} is not signed by {}",
                smart_contract_id, data.slot_id, &addr
            );
            return Ok(false);
        }
