### Title
Storage bloat via unlimited zero-fee low-liquidity market orders - (File: actuator/src/main/java/org/tron/core/actuator/MarketSellAssetActuator.java)

### Summary
`MarketSellAssetActuator` allows any account to place TRC10/TRX market orders with a sell/buy quantity as low as `1`, at a `MarketSellFee` that defaults to `0` TRX, permanently persisting each order into `MarketOrderStore`, `MarketAccountStore`, and (until matched/removed) `MarketPairToPriceStore`/`MarketPairPriceToOrderStore`.

### Finding Description
In `validate()`, the only lower-bound check on order size is `sellTokenQuantity <= 0 || buyTokenQuantity <= 0` — i.e., quantities of `1` are accepted; there is only an upper bound (`getMarketQuantityLimit()`), no minimum notional/dust threshold. [1](#0-0) 

Fee for placing an order is `dynamicStore.getMarketSellFee()`, which is initialized to `0L` by default (only settable via a committee proposal), so order creation can be essentially free of on-chain cost beyond bandwidth/energy for the transaction itself. [2](#0-1) [3](#0-2) 

Each call to `execute()` creates and permanently stores a new `MarketOrderCapsule` in `orderStore` via `createAndSaveOrder`, and updates `MarketAccountOrderCapsule` (which tracks a growing `total_count`/order id list) in `marketAccountStore`. If unmatched, the order is also inserted into `MarketPairToPriceStore` / `MarketPairPriceToOrderStore` (the order book) via `saveRemainOrder`. [4](#0-3) [5](#0-4) 

There is a per-account cap on **active** orders (`MAX_ACTIVE_ORDER_NUM`), enforced against `MarketAccountOrderCapsule.getCount()`. [6](#0-5) 

However this cap only limits *concurrently active* orders per single account — it does not limit the number of accounts an attacker can create/fund, nor does it prevent an attacker from repeatedly creating and matching/cancelling minimal (quantity=1) orders to free up the active-order slot and create a new dust order, each of which leaves a permanent `MarketOrderCapsule` record in `orderStore` (order records are never deleted from `orderStore`, only their `State` is updated to `INACTIVE`, e.g. via `MarketUtils.updateOrderState`). This is the direct analog of the Acala `deposit_dex_share` bug: no minimum-amount floor on a permissionless, effectively free, storage-writing operation.

### Impact Explanation
An unprivileged, cheap (near-zero marginal fee) transaction can permanently grow on-chain state (`MarketOrderStore`, `MarketAccountStore`, and transiently `MarketPairToPriceStore`/`MarketPairPriceToOrderStore`) with dust-quantity (as low as `1` unit) orders across many distinct token pairs and price points, since price buckets are derived from the specific sell/buy quantity ratio chosen by the attacker. Because `MarketSellFee` defaults to `0`, the attacker's cost is limited to normal transaction bandwidth/energy, not a fee proportional to the storage consumed. Over many transactions (and, if desired, many funded accounts to bypass the per-account active-order cap), this can bloat validator/full-node database size and increase maintenance/sync costs — a node-health/storage-bloat concern consistent with the referenced report's classification, though it does not directly enable theft of funds.

### Likelihood Explanation
Requires `ALLOW_MARKET_TRANSACTION` to be enabled by committee proposal (a precondition already assumed in-scope for this actuator), a minimal TRC10 asset balance or TRX balance of `1` unit, and the default `MarketSellFee = 0`. Any unprivileged account holding trivial token amounts can trigger this repeatedly; the barrier is only transaction bandwidth/energy cost and the per-account `MAX_ACTIVE_ORDER_NUM` cap on concurrently active orders (bypassable via matching/cancelling or using multiple accounts).

### Recommendation
Enforce a protocol-level minimum sell/buy token quantity (e.g., a `MARKET_MIN_QUANTITY` dynamic parameter, analogous to `MARKET_QUANTITY_LIMIT`) in `MarketSellAssetActuator.validate()`, and/or ensure `MarketSellFee` has a non-zero floor so dust order creation carries a real cost, and consider pruning/limiting terminal (`INACTIVE`) order records from `orderStore` retention.

### Proof of Concept
1. Committee enables `ALLOW_MARKET_TRANSACTION`; `MARKET_SELL_FEE` remains at its default `0`.
2. An attacker account with `sellTokenQuantity = 1`, `buyTokenQuantity = 1` (any distinct token pair, including TRX) calls `MarketSellAssetContract` repeatedly via `MarketSellAssetActuator`.
3. `validate()` passes because `sellTokenQuantity=1 > 0` and `buyTokenQuantity=1 > 0` satisfy the only lower-bound check (`actuator/src/main/java/org/tron/core/actuator/MarketSellAssetActuator.java:223-225`).
4. `execute()` persists a new `MarketOrderCapsule` into `orderStore` each time (`actuator/src/main/java/org/tron/core/actuator/MarketSellAssetActuator.java:147`), at zero incremental fee (`getMarketSellFee() == 0`).
5. Repeating across many token pairs/quantities (and/or multiple funded accounts to bypass `MAX_ACTIVE_ORDER_NUM`) accumulates a large number of permanent dust order records in state.

```java
  private MarketOrderCapsule createAndSaveOrder(AccountCapsule accountCapsule,
      MarketSellAssetContract contract) {
    MarketAccountOrderCapsule marketAccountOrderCapsule = marketAccountStore
        .getUnchecked(contract.getOwnerAddress().toByteArray());
    if (marketAccountOrderCapsule == null) {
      marketAccountOrderCapsule = new MarketAccountOrderCapsule(contract.getOwnerAddress());
    }

    // note: here use total_count
    byte[] orderId = MarketUtils
        .calculateOrderId(contract.getOwnerAddress(), sellTokenID, buyTokenID,
            marketAccountOrderCapsule.getTotalCount());
    MarketOrderCapsule orderCapsule = new MarketOrderCapsule(orderId, contract);

    long now = dynamicStore.getLatestBlockHeaderTimestamp();
    orderCapsule.setCreateTime(now);

    marketAccountOrderCapsule.addOrders(orderCapsule.getID());
    marketAccountOrderCapsule.setCount(marketAccountOrderCapsule.getCount() + 1);
    marketAccountOrderCapsule.setTotalCount(marketAccountOrderCapsule.getTotalCount() + 1);
    marketAccountStore.put(accountCapsule.createDbKey(), marketAccountOrderCapsule);
    orderStore.put(orderId, orderCapsule);

    return orderCapsule;
  }
```
