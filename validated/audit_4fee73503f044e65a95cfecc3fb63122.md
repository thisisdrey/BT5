### Title
Unbounded responder-side handshake processing allows a remote, uncertified attacker to trigger unbounded expensive Noise/crypto and certificate-parsing work per packet — ([File: handshake_manager.go])

### Summary
The external report's root cause is a missing cap check before an expensive, state-changing action (`AddEcosystemTokensMinted`) is performed, letting an unauthenticated/uncapped operation run past its intended limit and corrupt subsequent state. The reachable analog in Nebula is `HandshakeManager.HandleIncoming` / `beginHandshake`, which performs full Noise handshake and certificate-verification work for *every* inbound stage-1 packet with **no cap, rate limit, or per-source accounting** before doing that work — mirroring the "act first, check the cap later (or never)" pattern from the report.

### Finding Description
`readOutsidePackets` routes any packet with `h.Type == header.Handshake` straight to `f.handshakeManager.HandleIncoming` before any certificate or peer authentication has occurred: [1](#0-0) 

`HandleIncoming` only checks the subtype and (for non-relayed traffic) a remote allow-list; then any packet with `MessageCounter == 1` and `RemoteIndex == 0` — trivially forgeable by anyone, since the initiator always starts with these values — is dispatched to `beginHandshake` with no bound on how often this can happen from a given source or overall: [2](#0-1) 

`beginHandshake` unconditionally builds a new Noise `Machine`, performs a Diffie–Hellman/AEAD `ProcessPacket` operation, and (on success) parses/verifies the embedded certificate against the CA pool — all of this compute-intensive work happens before the caller is authenticated in any way: [3](#0-2) 

Unlike the outbound path, which is guarded by `HandshakeConfig.retries`, `tryInterval`, and `hh.counter` backoff, there is no analogous cap on the number of concurrent or per-second responder-side handshake attempts that can be forced by an unauthenticated remote peer. Contrast this with the report's bug class: an action (`AddEcosystemTokensMinted` / here, "run the full handshake+cert-verification pipeline") is performed without first checking a limiting condition (a minting cap / here, a rate or concurrency cap on unauthenticated handshake attempts), so the limiting condition is enforced too late or not at all.

### Impact Explanation
Because `beginHandshake` runs asymmetric crypto (X25519/AES or ChaCha) and certificate parsing/verification for every spoofed stage-1 packet regardless of source, an attacker with no CA-signed certificate can force the node to spend CPU on Noise handshake processing at an unbounded rate. This is a resource-exhaustion / remote DoS vector directly analogous to the report's "one block per month being compromised" — here, the single lighthouse/mesh node's packet-processing throughput for legitimate handshakes and traffic can be starved by attacker-controlled unauthenticated handshake floods, exactly because no cap check gates the expensive action before it runs.

### Likelihood Explanation
Reaching `beginHandshake` requires no certificate, no prior handshake state, and no knowledge of any secret — only a valid header with `MessageCounter == 1` and `RemoteIndex == 0`, which is the required wire format value anyway. This is trivially producible by any network-adjacent attacker, making the likelihood high.

### Recommendation
Introduce a cap/rate limit on responder-side handshake initiation before invoking `beginHandshake` — e.g., a per-source-address token bucket or a global cap on concurrent unauthenticated `Machine` instances mirroring the existing `HandshakeConfig.retries`/`tryInterval` backoff used for outbound handshakes — so the expensive crypto/cert-verification work is gated by the same kind of "check the cap first" discipline the report recommends for `AddEcosystemTokensMinted`.

### Proof of Concept
1. From an attacker-controlled host with no Nebula certificate, craft raw UDP packets with a valid Nebula header: `Type = Handshake`, `Subtype = HandshakeIXPSK0`, `RemoteIndex = 0`, `MessageCounter = 1`, followed by arbitrary/garbage or replayed noise-message bytes.
2. Send these packets at a high rate (varying source ports/addresses) toward a victim Nebula node's UDP listener.
3. Each packet reaches `HandleIncoming` → `beginHandshake` → `handshake.NewMachine(...).ProcessPacket(...)`, consuming CPU for Noise/crypto processing before any cert is verified, with no cap on concurrency or rate.
4. Observe CPU saturation / increased latency for legitimate handshake completion and data-plane traffic on the victim node, demonstrating the missing-cap resource-exhaustion condition. [4](#0-3)

```go
func (hm *HandshakeManager) HandleIncoming(via ViaSender, packet []byte, h *header.H) {
	// Gate on known handshake subtypes. Unknown subtypes (or future ones we
	// don't yet support) are dropped here rather than silently routed through
	// the IX path. Add a case when introducing a new pattern.
	switch h.Subtype {
	case header.HandshakeIXPSK0:
		// supported
	default:
		hm.l.Debug("dropping handshake with unsupported subtype",
			"from", via, "subtype", h.Subtype)
		return
	}

	// First remote allow list check before we know the vpnIp
	if !via.IsRelayed {
		if !hm.lightHouse.GetRemoteAllowList().AllowUnknownVpnAddr(via.UdpAddr.Addr()) {
			hm.l.Debug("lighthouse.remote_allow_list denied incoming handshake", "from", via)
			return
		}
	}

	// First message of a new handshake. The wire format requires RemoteIndex
	// to be zero here (the initiator has no responder index to fill in yet),
	// and generateIndex never allocates 0, so any non-zero RemoteIndex on a
	// stage-1 packet is malformed or someone probing for an index collision.
	// Drop without paying the cost of running noise on a pending Machine.
	if h.MessageCounter == 1 {
		if h.RemoteIndex != 0 {
			hm.l.Debug("dropping stage-1 handshake with non-zero RemoteIndex",
				"from", via, "remoteIndex", h.RemoteIndex)
			return
		}
		hm.beginHandshake(via, packet, h)
		return
	}
```

```go
func (hm *HandshakeManager) beginHandshake(via ViaSender, packet []byte, h *header.H) {
	f := hm.f
	cs := f.pki.getCertState()

	v := cs.DefaultVersion()
	if cs.GetCredential(v) == nil {
		f.l.Error("Unable to handshake with host because no certificate is available",
			"from", via, "certVersion", v)
		return
	}

	machine, err := handshake.NewMachine(
		v, cs.GetCredential,
		hm.certVerifier(), func() (uint32, error) { return generateIndex(f.l) },
		false, header.HandshakeIXPSK0,
	)
	if err != nil {
		f.l.Error("Failed to create handshake machine", "from", via, "error", err)
		return
	}

	response, result, err := machine.ProcessPacket(nil, packet)
	if err != nil {
		f.l.Error("Failed to process handshake packet", "from", via, "error", err)
		return
	}
```
