### Title
Path-containment check in ijar's zip extractor uses a substring prefix comparison instead of a directory-boundary comparison, allowing extraction outside the intended output root - (File: third_party/ijar/zip_main.cc)

### Summary
`UnzipProcessor::Process` in `third_party/ijar/zip_main.cc` is supposed to guarantee that no zip entry can be written outside the caller-supplied `output_root_` directory. It does so by normalizing both the target path and the root and then doing a raw string-prefix comparison:

```cpp
std::string normalized_root = normalize_path(output_root_);
std::string normalized = normalize_path(path);
if (normalized.compare(0, normalized_root.size(), normalized_root) != 0) {
  ...
  abort();
}
``` [1](#0-0) 

### Finding Description
`normalized.compare(0, normalized_root.size(), normalized_root)` only checks that `normalized` begins with the exact characters of `normalized_root`; it never verifies that the next character (if any) is a path separator or end-of-string. This is a classic boundary-check-without-a-delimiter bug: it behaves correctly for the intended "child directory" case but silently accepts a *sibling* directory whose name merely shares the prefix.

For example, if the extraction root is `output_root_ = "/tmp/extract"`, an archive entry with the crafted name `"../extract-evil/x"` produces (after `concat_path`) the raw path `"/tmp/extract/../extract-evil/x"`. After lexical normalization this collapses to `"/tmp/extract-evil/x"`. `normalized_root` is `"/tmp/extract"` (length 12). The comparison checks only the first 12 characters of `"/tmp/extract-evil/x"`, which are exactly `"/tmp/extract"` — so the containment check passes even though the file is written to `/tmp/extract-evil/x`, a directory entirely outside the intended `/tmp/extract` root.

This is directly analogous to the referenced CVE-2024-26795 bug class: an insufficiently precise boundary/offset check (missing the exact-boundary condition that should demarcate the legitimate region) lets attacker-controlled input escape the region the check was meant to bound. Here the "region" is the extraction output directory rather than a memory range, but the root cause — a prefix/offset comparison that omits the delimiter check — is the same class of defect.

The existing regression test `test_no_path_traversal` in `third_party/ijar/test/zip_test.sh` only exercises classic `"../"`-based traversal that fully escapes any shared prefix (`path_traversal_zip.jar`), and does not cover the sibling-directory-prefix bypass shown above, so it does not catch this variant. [2](#0-1) 

### Impact Explanation
An attacker who controls the contents of a zip archive that is extracted with this tool (e.g., a hostile origin server or compromised mirror serving a zip file consumed by a build, or any build action that shells out to Bazel's `zipper`/unzip binary built from this code) can write files to a directory adjacent to, but outside of, the intended extraction root. This is a containment/path-traversal write outside the intended output directory (CWE-22/CWE-706 boundary condition error), matching the "write or read outside the repository / exec root / output base" acceptance criterion.

### Likelihood Explanation
Exploitation requires the attacker to know (or guess) the basename of the extraction root directory well enough to craft a sibling name that is a superstring of it (e.g., root `extract` → sibling `extract-evil`). This is a real but non-trivial precondition, and it depends on how/where the `zipper`/ijar unzip binary is invoked with attacker-influenced zip content and a predictable/guessable output root path. I was not able to fully confirm, within the available context, that this exact C++ `UnzipProcessor` path is reachable from `http_archive`/`http_file` fetch-and-extract (Bazel's WORKSPACE/Bzlmod archive extraction appears to be implemented via a separate Java decompressor path that I could not locate in this repository snapshot — searches for `ZipDecompressor`, `StripPrefixedPath`, and similar Java classes returned no matches, likely due to index size limits excluding some file contents). It is confirmed reachable via the standalone `zipper` command-line tool exercised by `third_party/ijar/test/zip_test.sh`, and by any Bazel build rule or tool that shells out to it with attacker-influenced zip entries.

### Recommendation
Change the containment check to compare directory boundaries explicitly, e.g.:
```cpp
if (normalized.compare(0, normalized_root.size(), normalized_root) != 0 ||
    (normalized.size() > normalized_root.size() &&
     normalized[normalized_root.size()] != '/')) {
  ... abort();
}
```
or equivalently ensure `normalized_root` always ends with a separator before comparing, and add a regression test with a sibling-prefix entry name (e.g. `"../<root_basename>-evil/x"`) verifying extraction is rejected.

### Proof of Concept
Extend `third_party/ijar/test/zip_test.sh` with a case analogous to `test_no_path_traversal`, but using an archive entry whose relative path is `"../<basename_of_output_dir>-evil/pwned"` where `<basename_of_output_dir>` matches the extraction target directory's basename, then assert that no file is created outside the intended output directory. Given the analysis above, the existing `normalized.compare` boundary check would incorrectly accept this entry and write it into the sibling `-evil` directory, which a `JUnit`/shell-test harness (similar to `zip_test.sh`'s `test_no_path_traversal`) could assert against. ```text
void UnzipProcessor::Process(const char* filename, const u4 attr,
                             const u1* data, const size_t size) {
  mode_t perm = zipattr_to_perm(attr);
  bool isdir = zipattr_is_dir(attr);
  const char *output_file_name = filename;
  if (attr == 0) {
    // Fallback when the external attribute is not set.
    isdir = filename[strlen(filename)-1] == '/';
    perm = 0777;
  }

  if (flatten_) {
    if (isdir) {
      return;
    }
    const char *p = strrchr(filename, '/');
    if (p != NULL) {
      output_file_name = p + 1;
    }
  }

  if (verbose_) {
    printf("%c %o %s\n", isdir ? 'd' : 'f', perm, output_file_name);
  }
  if (extract_) {
    char path[PATH_MAX];
    if (!concat_path(path, sizeof(path), output_root_, output_file_name)) {
      abort();
    }
    std::string normalized_root = normalize_path(output_root_);
    std::string normalized = normalize_path(path);
    if (normalized.compare(0, normalized_root.size(), normalized_root) != 0) {
      fprintf(stderr,
              "paths in the zip may not end up outside of the output "
              "directory: %s vs "
              "%s\n",
              path, normalized.c_str());
      abort();
    }
    if (!make_dirs(path, perm) ||
        (!isdir && !write_file(path, perm, data, size))) {
      abort();
    }
  }
}
```
