## Confirmed: unbounded row growth in `attachments` table via `insert_instantiated_attachment`, with no hash validation on attacker responses

### Title
Unbounded, unauthenticated growth of `AtlasDB.attachments` (`was_instantiated=1`) via unverified `AttachmentRequest` responses - (`stackslib/src/net/atlas/download.rs`, `stackslib/src/net/atlas/db.rs`)

### Summary
`AttachmentsBatchStateContext::extend_with_attachments` inserts whatever `Attachment` content a peer returns for an `AttachmentRequest` into `self.attachments` without ever checking that `response.attachment.hash() == request.content_hash`. `AttachmentsDownloader::run` then unconditionally calls `AtlasDB::insert_instantiated_attachment` on every drained attachment, which does an `INSERT OR REPLACE INTO attachments (... was_instantiated=1 ...)` keyed by the attacker-controlled content's own hash. Unlike `insert_uninstantiated_attachment`, this path has no cap/eviction, so an attacker peer that gets selected as an attachment source can inject unique garbage content every round to grow the `attachments` table without bound.

### Finding Description
The broken equality is: *count of rows with `was_instantiated=1` should be bounded by real, on-chain committed content hashes (confirmed `AttachmentInstance` rows)*, but nothing enforces this.

Path:
1. `AttachmentsBatchStateContext::get_prioritized_attachments_requests` builds `AttachmentRequest { content_hash, sources, ... }` for a content hash referenced by a real `AttachmentInstance` (from on-chain BNS activity) [1](#0-0) .
2. When a response for that request succeeds, `AttachmentsBatchStateContext::extend_with_attachments` decodes the response and inserts `response.attachment` into `self.attachments: HashSet<Attachment>` **without ever comparing `response.attachment.hash()` to `request.content_hash`**: [2](#0-1) .
3. `AttachmentsDownloader::run`, on `AttachmentsBatchStateMachine::Done`, drains `context.attachments` and calls `network.atlasdb.insert_instantiated_attachment(&attachment)` for every one of them unconditionally, regardless of whether any `AttachmentInstance` actually matches that content's hash: [3](#0-2) .
4. `AtlasDB::insert_instantiated_attachment` performs `INSERT OR REPLACE INTO attachments (hash, content, was_instantiated, created_at) VALUES (?, ?, 1, ?)` keyed by `attachment.hash()` (the hash of the attacker's own bytes, not the requested `content_hash`), with no size cap and no eviction policy: [4](#0-3) .

This is structurally different from the uninstantiated path, which explicitly caps and evicts: `insert_uninstantiated_attachment` checks `count_uninstantiated_attachments()` against `atlas_config.max_uninstantiated_attachments` and evicts oldest rows before inserting [5](#0-4) . No equivalent cap exists for `was_instantiated=1` rows anywhere in `db.rs`.

Because the attacker's returned content need not match the requested `content_hash` at all, each round the attacker peer is selected as a download source it can return distinct garbage bytes, each producing a new row keyed by a new hash (since `INSERT OR REPLACE` only collides on identical content). This repeats every time real on-chain activity generates a batch of missing-attachment requests that the attacker peer is chosen to serve — an event the attacker does not need to control the timing of, only needs to be selected as a serving peer for some fraction of such requests over time.

### Impact Explanation
The attacker, as an unprivileged peer serving Atlas HTTP responses to `AttachmentRequest`s, causes arbitrary unauthenticated writes into the victim's `AtlasDB` sqlite file (`attachments` table, `was_instantiated=1`), with no bound tied to actual chain commitments. Repeated over time (each round the attacker wins selection with new garbage), this results in unbounded storage growth on disk — an unauthenticated write causing storage exhaustion, matching the Critical category ("unauthenticated/unauthorized write to state").

### Likelihood Explanation
Preconditions are modest: the attacker only needs to run a normal P2P peer that advertises an Atlas attachments inventory and gets included among `context.peers` sources for some `AttachmentRequest`s — a normal, unprivileged peer capability requiring no secret, no signature bypass, and no privileged role. Repeatability is bounded only by how often the attacker peer is chosen as a serving source across the network's ongoing legitimate attachment-instance activity, which recurs continuously as new blocks reference attachments. Attacker cost is minimal (respond with distinct garbage bytes per request).

### Recommendation
In `AttachmentsBatchStateContext::extend_with_attachments` (`stackslib/src/net/atlas/download.rs`), verify `response.attachment.hash() == request.content_hash` before inserting into `self.attachments`, discarding/penalizing (via `report.bump_failed_requests()`) any response whose content hash does not match the requested hash. Additionally, `AtlasDB::insert_instantiated_attachment` (`stackslib/src/net/atlas/db.rs`) should only ever be invoked for content that resolves an actual pending `AttachmentInstance`, and ideally the DB layer itself should reject/ignore inserts for hashes with no corresponding `attachment_instances` row rather than performing an unconditional `INSERT OR REPLACE`.

### Proof of Concept
Rust test in `stackslib/src/net/atlas/tests.rs` (or a new integration test) mimicking `AttachmentsDownloader::run`:
1. Set up an `AtlasDB` and queue a real `AttachmentInstance` with `content_hash = H_real` via `queue_attachment_instance` + mark checked (as in existing `test_evict_expired_unresolved_attachment_instances`).
2. Construct an `AttachmentsBatchStateContext` with one `AttachmentRequest{ content_hash: H_real, ... }` and a mock `BatchedRequestsResult` whose `succeeded` map contains a response decoding to `Attachment{ content: garbage_bytes_i }` (hash `H_i != H_real`), varying `garbage_bytes_i` across N iterations.
3. Call `extend_with_attachments` then simulate `AttachmentsDownloader::run`'s `Done` branch draining `context.attachments` into `insert_instantiated_attachment`.
4. Assert after N iterations: `atlas_db.count_uninstantiated_attachments() == 0` (per the question's claim) while `SELECT COUNT(*) FROM attachments WHERE was_instantiated=1` equals N and exceeds `SELECT COUNT(*) FROM attachment_instances` — demonstrating unbounded growth of instantiated rows uncorrelated with real committed `AttachmentInstance` rows, and that none of the injected rows ever set `is_available=1` on the real `H_real` instance (proving the pairing is also broken, not just storage).

    pub fn get_prioritized_attachments_requests(&self) -> BinaryHeap<AttachmentRequest> {
        let mut queue = BinaryHeap::new();
        let mut enqueued = HashSet::new();
        for ((contract_id, pages, _), peers_responses) in self.inventories.iter() {
            let missing_attachments = match self
                .attachments_batch
                .attachments_instances
                .get(contract_id)
            {
                None => continue,
                Some(missing_attachments) => missing_attachments,
            };
            // Note: we're getting missing_attachments (attachment_id: content_hash)
            for (attachment_index, content_hash) in missing_attachments.iter() {
                let page_index = attachment_index / AttachmentInstance::ATTACHMENTS_INV_PAGE_SIZE;
                // Since there's a limit in the number of pages that a node can request,
                // we can potentially have multiple inventory request at once.
                if !pages.contains(&page_index) {
                    continue;
                }

                if enqueued.contains(content_hash) {
                    debug!("Atlas: {} already enqueued", content_hash);
                    continue;
                }

                let mut sources = HashMap::new();
                let position_in_page =
                    attachment_index % AttachmentInstance::ATTACHMENTS_INV_PAGE_SIZE;

                for (peer_url, response) in peers_responses.iter() {
                    // Considering the response, look for the page with the index
                    // we're looking for.
                    let search_page = response.pages.iter().find(|page| page.index == page_index);

                    let has_attachment = search_page
                        .and_then(|search_page| {
                            search_page.inventory.get(position_in_page as usize)
                        })
                        .map(|result| *result == 1)
                        .unwrap_or(false);

                    if !has_attachment {
                        debug!(
                            "Atlas: peer does not have attachment ({}, {}) in its inventory {:?}",
                            page_index, position_in_page, response.pages
                        );
                        continue;
                    }

                    let report = self
                        .peers
                        .get(peer_url)
                        .expect("Atlas: unable to retrieve reliability report for peer");
                    sources.insert(peer_url.clone(), report.clone());
                }

                if sources.is_empty() {
                    warn!("Atlas: could not find a peer including attachment in its inventory");
                    continue;
                }

                // Success, we found at least one inventory including the attachment we're looking for.
                let request = AttachmentRequest {
                    sources,
                    content_hash: content_hash.clone(),
                    stacks_block_height: self.attachments_batch.stacks_block_height,
                    canonical_stacks_tip_height: self.attachments_batch.canonical_stacks_tip_height,
                };
                enqueued.insert(content_hash);
                queue.push(request);

            let report = self
                .peers
                .get_mut(request.get_url())

                r
            } else {
                report.bump_failed_requests();
                continue;
            };

            if let Ok(response) = response.decode_atlas_get_attachment() {
                self.attachments.insert(response.attachment);
                report.bump_successful_requests();
            } else {
                report.bump_failed_requests();
            }
        }

    pub fn insert_uninstantiated_attachment(
        &mut self,
        attachment: &Attachment,
    ) -> Result<(), db_error> {
        // Insert the new attachment
        let uninstantiated_attachments = self.count_uninstantiated_attachments()?;
        if uninstantiated_attachments >= self.atlas_config.max_uninstantiated_attachments {
            let to_delete =
                1 + uninstantiated_attachments - self.atlas_config.max_uninstantiated_attachments;
            self.evict_k_oldest_uninstantiated_attachments(to_delete)?;
        }

        let tx = self.tx_begin()?;
        let now = util::get_epoch_time_secs() as i64;
        let res = tx.execute(
            "INSERT OR REPLACE INTO attachments (hash, content, was_instantiated, created_at) VALUES (?, ?, 0, ?)",
            params![
                attachment.hash(),
                attachment.content,
                now,
            ],
        );
        res.map_err(db_error::SqliteError)?;
        tx.commit().map_err(db_error::SqliteError)?;
        Ok(())
    }
