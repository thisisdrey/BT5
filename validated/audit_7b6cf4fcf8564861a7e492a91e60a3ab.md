### Title
Unverified `RelayFromAddr` in `handleCreateRelayRequest` allows relay state poisoning with attacker-chosen addresses - ([File: relay_manager.go])

### Summary
`relayManager.HandleControlMsg` (relay_manager.go:298-342) unmarshals a `NebulaControl` message from an already-established (but not otherwise privileged) peer `h` and derives `RelayFromAddr`/`RelayToAddr` either from the v2 fields or, if the legacy v1 fields are used, by reconstructing them via `netAddrToProtoAddr(netip.AddrFrom4(b))` from the raw `OldRelayFromAddr`/`OldRelayToAddr` integers. In `handleCreateRelayRequest` (relay_manager.go:426-524), when the target address equals one of the local node's own addresses, the code calls `AddRelay(rm.l, h, f.hostMap, from, &m.InitiatorRelayIndex, TerminalType, Established)` using `from` directly, without ever checking that `from` is one of `h`'s certificate-verified `h.vpnAddrs`.

### Finding Description
`HandleControlMsg` only validates that `RelayFromAddr`/`RelayToAddr` are non-nil (relay_manager.go:322-334); it never cross-checks `RelayFromAddr` against the sending peer's verified identity (`h.vpnAddrs`, populated from the peer's certificate during the handshake). The version-detection branch itself (`if msg.OldRelayFromAddr > 0 || msg.OldRelayToAddr > 0`) is attacker-controlled trivia — since the entire `NebulaControl` payload comes from attacker-sent UDP bytes anyway, this branch doesn't add a new trust boundary, but it does confirm that both the v1 and v2 code paths funnel fully attacker-chosen bytes into `RelayFromAddr`/`RelayToAddr` (relay_manager.go:306-318).

In `handleCreateRelayRequest`, when the local node is the relay target (`f.myVpnAddrsTable.Contains(target)` at relay_manager.go:447), the code creates or reuses relay state keyed by `from` on host `h`'s `relayState` (relay_manager.go:448-487), and ultimately calls `AddRelay(..., h, ..., from, ...)` at relay_manager.go:482. Nowhere in this path is `from` checked against `h.vpnAddrs`. Any peer `h` with a legitimate (but unprivileged) tunnel to the victim can therefore claim an arbitrary `RelayFromAddr` and cause the victim to install a `Relay{Type: TerminalType, State: Established, PeerAddr: from}` entry attributing that `from` address to `h`, and reply with a `CreateRelayResponse` confirming it.

### Impact Explanation
This is remote hostmap/relay state poisoning: an attacker-controlled peer can inject arbitrary vpn addresses into the victim's relay routing table, associated with itself as the relay for that address, without any verification that it is authorized to represent that address. This can misdirect subsequent relay-routed handshake/data traffic intended for the spoofed address toward the attacker's `HostInfo`, and pollute relay bookkeeping (`hm.Relays`, `relayState`) with entries that do not correspond to any real, certificate-verified peer relationship. It does not, by itself, decrypt or forge the end-to-end encrypted tunnel data (which still requires the real peer's private key/certificate for an actual handshake to succeed), so the impact is scoped to relay-state/routing poisoning rather than full authentication bypass.

### Likelihood Explanation
Feasible with a single unprivileged, cert-holding peer that has any established tunnel to the victim — no lighthouse compromise, no CA control, and no additional privilege is required. The attacker simply crafts `NebulaControl` messages with `Type: CreateRelayRequest` and arbitrary `RelayFromAddr`/`OldRelayFromAddr` values while setting `RelayToAddr` to one of the victim's own addresses (which is discoverable/expected in normal use). This is repeatable and deterministic.

### Recommendation
In `handleCreateRelayRequest` (and `handleCreateRelayResponse`), require that `RelayFromAddr` (`from`) resolve to an address the sending `HostInfo` `h` is actually certified for (i.e., `slices.Contains(h.vpnAddrs, from)`), rejecting/logging the request otherwise, so relay routing state is only installed for addresses backed by the sender's verified certificate.

### Proof of Concept
Add a unit test in `relay_manager_test.go` (or extend `control_test.go`) that:
1. Establishes two real `HostInfo`s `A` and `B` with verified certs/`vpnAddrs`, mimicking a normal handshake.
2. From `A`, calls `rm.HandleControlMsg(hB, d, f)` where `d` marshals a `NebulaControl{Type: CreateRelayRequest, RelayFromAddr: <address not in hB.vpnAddrs>, RelayToAddr: <B's own address>}`.
3. Asserts that `hB.relayState.QueryRelayForByIp(from)` returns `ok == false` (i.e., no relay state should be created for an address not belonging to the verified sender), whereas the current code returns `ok == true` with `State: Established`, demonstrating the missing check. [1](#0-0) [2](#0-1)

func (rm *relayManager) HandleControlMsg(h *HostInfo, d []byte, f *Interface) {
	msg := &NebulaControl{}
	err := msg.Unmarshal(d)
	if err != nil {
		h.logger(f.l).Error("Failed to unmarshal control message", "error", err)
		return
	}

	var v cert.Version
	if msg.OldRelayFromAddr > 0 || msg.OldRelayToAddr > 0 {
		v = cert.Version1

		b := [4]byte{}
		binary.BigEndian.PutUint32(b[:], msg.OldRelayFromAddr)
		msg.RelayFromAddr = netAddrToProtoAddr(netip.AddrFrom4(b))

		binary.BigEndian.PutUint32(b[:], msg.OldRelayToAddr)
		msg.RelayToAddr = netAddrToProtoAddr(netip.AddrFrom4(b))
	} else {
		v = cert.Version2
	}

	// validate:
	switch msg.Type {
	case NebulaControl_CreateRelayRequest, NebulaControl_CreateRelayResponse:
		if msg.RelayFromAddr == nil {
			if f.l.Enabled(context.Background(), slog.LevelDebug) {
				h.logger(f.l).Debug("Control message received with nil RelayFromAddr", "type", msg.Type)
			}
			return
		} else if msg.RelayToAddr == nil {
			if f.l.Enabled(context.Background(), slog.LevelDebug) {
				h.logger(f.l).Debug("Control message received with nil RelayToAddr", "type", msg.Type)
			}
			return
		}
	}

	switch msg.Type {
	case NebulaControl_CreateRelayRequest:
		rm.handleCreateRelayRequest(v, h, f, msg)
	case NebulaControl_CreateRelayResponse:
		rm.handleCreateRelayResponse(v, h, f, msg)
	}
}

func (rm *relayManager) handleCreateRelayRequest(v cert.Version, h *HostInfo, f *Interface, m *NebulaControl) {
	//nil-checks for protoAddrToNetAddr handled by caller
	from := protoAddrToNetAddr(m.RelayFromAddr)
	target := protoAddrToNetAddr(m.RelayToAddr)

	logMsg := rm.l.With(
		"relayFrom", from,
		"relayTo", target,
		"initiatorRelayIndex", m.InitiatorRelayIndex,
		"vpnAddrs", h.vpnAddrs,
	)

	logMsg.Info("handleCreateRelayRequest")
	// Is the source of the relay me? This should never happen, but did happen due to
	// an issue migrating relays over to newly re-handshaked host info objects.
	if f.myVpnAddrsTable.Contains(from) {
		logMsg.Error("Discarding relay request from myself", "myIP", from)
		return
	}

	// Is the target of the relay me?
	if f.myVpnAddrsTable.Contains(target) {
		existingRelay, ok := h.relayState.QueryRelayForByIp(from)
		if ok {
			switch existingRelay.State {
			case Requested:
				ok = h.relayState.CompleteRelayByIP(from, m.InitiatorRelayIndex)
				if !ok {
					logMsg.Error("Relay State not found")
					return
				}
			case Established:
				if existingRelay.RemoteIndex != m.InitiatorRelayIndex {
					// We got a brand new Relay request, because its index is different than what we saw before.
					// This should never happen. The peer should never change an index, once created.
					logMsg.Error("Existing relay mismatch with CreateRelayRequest",
						"existingRemoteIndex", existingRelay.RemoteIndex)
					return
				}
			case Disestablished:
				if existingRelay.RemoteIndex != m.InitiatorRelayIndex {
					// We got a brand new Relay request, because its index is different than what we saw before.
					// This should never happen. The peer should never change an index, once created.
					logMsg.Error("Existing relay mismatch with CreateRelayRequest",
						"existingRemoteIndex", existingRelay.RemoteIndex)
					return
				}
				// Mark the relay as 'Established' because it's safe to use again
				h.relayState.UpdateRelayForByIpState(from, Established)
			case PeerRequested:
				// I should never be in this state, because I am terminal, not forwarding.
				logMsg.Error("Unexpected Relay State found",
					"existingRemoteIndex", existingRelay.RemoteIndex,
					"state", existingRelay.State)
			}
		} else {
			_, err := AddRelay(rm.l, h, f.hostMap, from, &m.InitiatorRelayIndex, TerminalType, Established)
			if err != nil {
				logMsg.Error("Failed to add relay", "error", err)
				return
			}
		}

		relay, ok := h.relayState.QueryRelayForByIp(from)
		if !ok {
			logMsg.Error("Relay State not found", "from", from)
			return
		}
