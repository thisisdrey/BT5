### Title
Unauthenticated remote `/shutdown` POST permanently terminates `SignerEventReceiver` - (File: `libsigner/src/events.rs`)

### Summary
`SignerEventReceiver::next_event` handles any HTTP POST to `/shutdown` by unconditionally setting `stop_signal` to `true` and returning `EventError::Terminated`, with no check on the caller's identity, source address, or possession of any secret. Any remote TCP client that can reach the signer's event-listener socket can send this single unauthenticated request and permanently halt the signer's event-processing loop.

### Finding Description
In `libsigner/src/events.rs`, `SignerEventReceiver::next_event` dispatches based solely on `request.url()`: [1](#0-0) 

There is no verification that the request originates from the legitimate `SignerStopSignaler::send` caller (which connects from the same process/node via `TcpStream::connect(self.local_addr)`): [2](#0-1) 

The equality `shutdown_authorized == request_came_from_local_stop_signaler` is never checked anywhere in the handler — the only test performed is `request.url() == "/shutdown"` combined with the method check (`request.method() != &HttpMethod::Post`), neither of which authenticates the sender. Once the stop signal is set, `is_stopped()` returns `true` [3](#0-2) , and `main_loop` breaks out permanently: [4](#0-3) . There is no reset path for `stop_signal` once set — the signer's event thread exits for good.

### Impact Explanation
Any unprivileged remote party capable of opening a TCP connection to the signer's bound event-receiver socket can send `POST /shutdown HTTP/1.1` and permanently stop that signer instance from receiving further block-validation responses, burn-block events, or StackerDB chunk events — effectively taking the signer offline until manually restarted. This is a single-message, unauthenticated, remote denial-of-service against a signer node, matching the "Critical - remote crash/unauthenticated DoS from few messages" category.

### Likelihood Explanation
The attacker needs no credentials, no RPC secret, no valid peer identity, and no StackerDB slot — only network reachability to the signer's configured event-receiver bind address/port. The action is a single, trivially repeatable HTTP POST; no race condition, timing, or state precondition is required beyond the socket being reachable.

### Recommendation
Restrict `/shutdown` handling to trusted local callers only, e.g., by binding the stop-signal listener to loopback only, using a distinct local IPC channel/Unix domain socket instead of the shared network HTTP endpoint, or requiring a per-process shared secret/token embedded in the `SignerStopSignaler` request and validated in `next_event` before honoring `/shutdown`.

### Proof of Concept
Add a test in `libsigner/src/tests/`: bind a `SignerEventReceiver` to `127.0.0.1:0`, spawn `main_loop` in a thread, then from an independent `TcpStream::connect` (not via `SignerStopSignaler`) send raw bytes `"POST /shutdown HTTP/1.1\r\nHost: ...\r\nContent-Length: 0\r\n\r\n"`. Assert that shortly after, `event_receiver.is_stopped()` returns `true` and a subsequent call to `next_event()` returns `Err(EventError::Terminated)`, confirming the shutdown was accepted from an arbitrary connection rather than only from `SignerStopSignaler::send`.
