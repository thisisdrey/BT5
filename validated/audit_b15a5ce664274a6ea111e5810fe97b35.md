## Analysis: Stale Bank Indices Used in marginfi Liquidation Health Checks

I found a direct analog of this bug class in the marginfi liquidation flow.

### Title
Liquidation health checks use stale, unaccrued share values for banks outside the liquidated pair, potentially blocking legitimate liquidations and allowing bad debt to accumulate - (File: `programs/marginfi/src/instructions/marginfi_account/liquidate.rs`)

### Summary
In `lending_account_liquidate`, interest is only accrued for the two banks directly involved in the liquidation (`asset_bank` and `liab_bank`), but the account health check that determines whether the liquidatee is actually liquidatable iterates over **all** of the liquidatee's active balances, using whatever share values happen to be cached in each of those other banks.

### Finding Description
`lending_account_liquidate` explicitly calls `accrue_interest` on only the two banks passed into the instruction: [1](#0-0) 

The pre-liquidation health check, however, is computed via `check_pre_liquidation_condition_and_get_account_health` → `get_health_components`, which loops over **every active balance** on the liquidatee's account (not just the asset/liab pair) and loads each corresponding bank to compute weighted collateral/liability values: [2](#0-1) 

Those weighted values are derived from `Bank.get_asset_amount`/`get_liability_amount`, which multiply raw shares by `self.asset_share_value` / `self.liability_share_value` — fields that are only advanced when `accrue_interest` runs for that specific bank. Every user-facing instruction (`deposit`, `withdraw`, `borrow`, `repay`, `close_balance`, `liquidate`) only calls `accrue_interest` for the bank(s) it directly touches, not for every bank in the caller's or counterparty's position set. This is the same root cause as the Compound/Morpho report: the liquidation-eligibility check walks all of a user's entered markets/balances, but the interest indices are refreshed for only a subset of them (the borrow/collateral pair), so markets/banks that haven't seen recent activity retain outdated share values.

### Impact Explanation
Because `asset_share_value`/`liability_share_value` only ever increase over time as interest accrues, a bank that hasn't been touched recently understates the true value of a user's position in that bank. If a liquidatee holds debt or collateral in a bank other than the two named in the liquidation call, and that bank has gone unaccrued, `get_health_components` will compute a stale (understated) liability or (understated) asset value for that position. This can make an actually-insolvent account appear healthy in `check_pre_liquidation_condition_and_get_account_health`, causing the instruction to revert with `MarginfiError::HealthyAccount` even though the account should be liquidatable — mirroring exactly the described Compound bug ("users may not be liquidated on Morpho that could be liquidated on Compound"). Delayed liquidation of an under-collateralized position allows the shortfall to grow, directly risking protocol insolvency/bad debt.

### Likelihood Explanation
This is reachable by any liquidator attempting to liquidate a multi-collateral/multi-debt marginfi account (a normal, unprivileged path) whenever one of the account's other banks has low activity (e.g., illiquid or unpopular markets, or Staked Collateral/JupLend/Drift-style banks that see infrequent interaction). The guide `guides/ADMIN/COLLECTING_FEES.md` explicitly acknowledges this staleness pattern exists in the protocol ("banks without much activity may have stale numbers until someone interacts with them"), confirming the underlying assumption is a known/expected protocol behavior rather than a hypothetical edge case. [3](#0-2) 

There is a mitigation path: a permissionless `lending_pool_accrue_bank_interest` instruction exists, so a sophisticated liquidator can pre-accrue every bank in the liquidatee's position set within the same transaction before calling liquidate. [4](#0-3) 
However, this is not automatic or enforced by the protocol, so ordinary liquidators/bots that don't compose these extra instructions for every position bank will systematically under-detect liquidatable accounts, exactly matching the "Medium" severity and remediation pattern of the referenced report.

### Recommendation
Within `check_pre_liquidation_condition_and_get_account_health` (and the equivalent post-liquidation check), call `accrue_interest` for every bank encountered while iterating the liquidatee's balances (not just asset/liab banks), or otherwise compute health using freshly-accrued share values rather than raw cached `asset_share_value`/`liability_share_value`. Alternatively, require/document that liquidators must always prepend `LendingPoolAccrueBankInterest` for every bank in the target account's position set, and consider enforcing this automatically inside the liquidation instruction rather than leaving it to the caller.

### Proof of Concept
1. User deposits collateral in Bank A and Bank C, borrows from Bank B.
2. No one interacts with Bank C for an extended period, so `Bank C.liability_share_value`/`asset_share_value` remains stale from an earlier point in time (lower than what true accrual would produce).
3. Price movements or continued borrowing make the user's true (fully-accrued) position insolvent (liabilities > assets).
4. A liquidator calls `lending_account_liquidate` with `asset_bank = A`, `liab_bank = B`; this only calls `accrue_interest` on banks A and B.
5. `check_pre_liquidation_condition_and_get_account_health` walks all of the user's balances, including Bank C, using Bank C's stale (understated) liability value.
6. The computed `account_health` comes out positive due to the understated liability in Bank C, and the call reverts with `HealthyAccount`, even though the account is genuinely undercollateralized once Bank C's interest is properly accrued. [5](#0-4)

pub fn check_pre_liquidation_condition_and_get_account_health<'info>(
    marginfi_account: &MarginfiAccount,
    remaining_ais: &'info [AccountInfo<'info>],
    liability_bank_pk: Option<&Pubkey>,
    health_cache: &mut Option<&mut HealthCache>,
    price_mode: HealthPriceMode<'_>,
    ignore_healthy: bool,
) -> MarginfiResult<(I80F48, I80F48, I80F48)> {
    check!(
        !marginfi_account.get_flag(ACCOUNT_IN_FLASHLOAN),
        MarginfiError::AccountInFlashloan
    );

    if let Some(bank_pk) = liability_bank_pk {
        let lending_account = &marginfi_account.lending_account;
        let liability_balance = lending_account
            .balances
            .iter()
            .find(|b| b.is_active() && b.bank_pk == *bank_pk)
            .ok_or(MarginfiError::LendingAccountBalanceNotFound)?;

        check!(
            !liability_balance.is_empty(BalanceSide::Liabilities),
            MarginfiError::NoLiabilitiesInLiabilityBank
        );

        check!(
            liability_balance.is_empty(BalanceSide::Assets),
            MarginfiError::AssetsInLiabilityBank
        );
    }

    // Get health components using heap reuse
    let (assets, liabs) = get_health_components(
        marginfi_account,
        remaining_ais,
        RequirementType::Maintenance,
        health_cache,
        price_mode,
    )?;

    let account_health = assets.checked_sub(liabs).ok_or_else(math_error!())?;
    let healthy = account_health > I80F48::ZERO;

    if let Some(cache) = health_cache.as_mut() {
        cache.set_healthy(healthy);
    }

    if healthy && !ignore_healthy {
        msg!(
            "pre_liquidation_health: {} ({} - {})",
            account_health,
            assets,
            liabs
        );
        return err!(MarginfiError::HealthyAccount);
    }

    Ok((account_health, assets, liabs))
