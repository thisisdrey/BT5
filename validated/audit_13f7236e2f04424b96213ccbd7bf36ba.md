### Title
Roaming anti-flap suppression trivially bypassed by never-repeating spoofed source addresses, enabling unbounded remote-address churn - (File: outside.go)

### Summary
`Interface.handleHostRoaming` only suppresses a roam if the new source address exactly equals `hostinfo.lastRoamRemote` (the single previously-seen address) within `RoamingSuppressSeconds`. It does not rate-limit roaming to *novel* addresses, so an attacker who forges a distinct source `via.UdpAddr` on every otherwise-valid packet can force `SetRemote` on every single packet, causing constant roam churn and misdirection of subsequent outbound traffic for that tunnel.

### Finding Description
In `outside.go`, `handleHostRoaming` is invoked from the packet-receive path once a packet decrypts successfully for an existing `hostinfo`: [1](#0-0) 

The suppression logic is:
```go
if !hostinfo.lastRoam.IsZero() && via.UdpAddr == hostinfo.lastRoamRemote && time.Since(hostinfo.lastRoam) < RoamingSuppressSeconds*time.Second {
    return // suppress
}
...
hostinfo.lastRoam = time.Now()
hostinfo.lastRoamRemote = curRemote
hostinfo.SetRemote(via.UdpAddr)
```
`lastRoamRemote` is set to the address the tunnel is roaming *away from* (i.e., the previous `curRemote`), and the suppression only fires if the *new* incoming address equals that single stored previous address (this is meant to stop back-and-forth flapping between two known endpoints, e.g. NAT rebinding oscillation). It performs no bound on the *number* of distinct new addresses accepted per unit time, nor any check like "was this exact new address roamed-to recently". If an attacker (per the stated precondition, on-path and able to get genuinely-decrypting ciphertext delivered under a spoofed/forged outer UDP source on each packet) presents a different `via.UdpAddr` on every packet, then `via.UdpAddr != curRemote` is true, `via.UdpAddr != lastRoamRemote` is also true every time (because `lastRoamRemote` only ever equals the *immediately preceding* remote, and the attacker never repeats an address), so the suppression branch is skipped every single time and `SetRemote` fires on every packet.

The only other gate is `f.lightHouse.GetRemoteAllowList().AllowAll(...)`, which is a static, admin-configured CIDR allow/deny list, not a rate limiter, so it does not stop an attacker whose spoofed addresses fall inside the allowed ranges (this matches the question's framing of "preferred range subnets").

### Impact Explanation
This is a remote hostmap state-poisoning issue: `hostinfo.remote` (the address Nebula will use for all subsequent outbound encrypted traffic to that peer) can be forced to thrash to attacker-chosen addresses on every packet, as long as the attacker can keep feeding distinctly-sourced, successfully-decrypting packets. The direct consequence is traffic misdirection/denial of service for the legitimate tunnel — the victim's outbound packets get sent to whatever bogus address the attacker last presented, rather than the real peer, and the `RoamingSuppressSeconds` anti-flap mechanism provides no protection against this because it is keyed off a single last-known address rather than a rate/frequency bound.

### Likelihood Explanation
Requires the stated precondition of an on-path attacker able to get genuinely-decrypting ciphertext to reach `readOutsidePackets`/`handleHostRoaming` while controlling/spoofing the outer UDP source address per packet — this is explicitly granted as a precondition in the question and is consistent with an on-path relay/MITM scenario where the attacker forwards real, still-fresh (monotonically increasing counter) ciphertext but forges the outer IP/UDP source on each forwarded packet. Given that precondition, the bypass is deterministic and trivially repeatable — every packet with a fresh address will always pass the check.

### Recommendation
Change the anti-flap logic so suppression is based on roam *frequency/rate*, not on equality to a single previous address — e.g., track a short-lived set/count of recent roam events (or a minimum interval between *any* roams, not just repeats of the exact previous address) and require a minimum number of consecutive/verified packets from the new address (or additional handshake-level reverification) before accepting a roam, especially when the new address differs from all recently seen addresses. Consider also binding `lastRoamRemote` tracking to a small recent-address history rather than only the immediately preceding one.

### Proof of Concept
Unit test in `hostmap_test.go`/`outside_test.go` style:
1. Construct an `Interface` with a `HostMap` and a `HostInfo` with a valid `ConnectionState`/decrypt setup (or directly unit test `handleHostRoaming` given it only depends on `hostinfo` and `via`).
2. Set `RoamingSuppressSeconds` to a large value (e.g. 60).
3. Call `handleHostRoaming(hostinfo, via)` in a loop with `via.UdpAddr` set to a new, never-before-used `netip.AddrPort` each iteration (e.g., `10.0.0.1:4242`, `10.0.0.2:4242`, `10.0.0.3:4242`, ...), all within the allow-list.
4. Assert that `hostinfo.GetRemote()` changes on every single iteration despite `RoamingSuppressSeconds` being large and despite calls happening within milliseconds of each other — proving the suppression window never engages because `via.UdpAddr` never equals `hostinfo.lastRoamRemote`.
5. Contrast with a second test where `via.UdpAddr` alternates between exactly two fixed addresses — showing suppression correctly kicks in for that back-and-forth case, confirming the gap is specific to novel-address churn.

func (f *Interface) handleHostRoaming(hostinfo *HostInfo, via ViaSender) {
	curRemote := hostinfo.GetRemote()
	if !via.IsRelayed && curRemote != via.UdpAddr {
		if !f.lightHouse.GetRemoteAllowList().AllowAll(hostinfo.vpnAddrs, via.UdpAddr.Addr()) {
			if f.l.Enabled(context.Background(), slog.LevelDebug) {
				hostinfo.logger(f.l).Debug("lighthouse.remote_allow_list denied roaming", "newAddr", via.UdpAddr)
			}
			return
		}

		if !hostinfo.lastRoam.IsZero() && via.UdpAddr == hostinfo.lastRoamRemote && time.Since(hostinfo.lastRoam) < RoamingSuppressSeconds*time.Second {
			if f.l.Enabled(context.Background(), slog.LevelDebug) {
				hostinfo.logger(f.l).Debug("Suppressing roam back to previous remote",
					"suppressSeconds", RoamingSuppressSeconds,
					"udpAddr", curRemote,
					"newAddr", via.UdpAddr,
				)
			}
			return
		}

		hostinfo.logger(f.l).Info("Host roamed to new udp ip/port.",
			"udpAddr", curRemote,
			"newAddr", via.UdpAddr,
		)
		hostinfo.lastRoam = time.Now()
		hostinfo.lastRoamRemote = curRemote
		hostinfo.SetRemote(via.UdpAddr)
	}

}
