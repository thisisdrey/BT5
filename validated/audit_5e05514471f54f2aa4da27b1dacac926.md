Based on my research, java-tron's TVM has a precompiled-contract call path with an explicit, self-acknowledged analog of the AvailBridge bug class: value (TRX or TRC10) is unconditionally transferred to a precompiled-contract address *before* that contract's logic executes, and the code comment itself flags this transfer as irreversible.

### Title
Value sent via CALL to a TVM precompiled contract address is unconditionally transferred and can become permanently stuck if the precompiled contract does not use or return it - (File: actuator/src/main/java/org/tron/core/vm/program/Program.java)

### Summary
In `Program.callToPrecompiledAddress`, any `msg.getEndowment()` (TRX or TRC10) attached to a `CALL`/`CALLTOKEN` targeting one of the built-in precompiled contract addresses (e.g. `ecRecover`, `sha256`, `batchValidateSign`, `RewardBalance`, `IsSrCandidate`, etc.) is transferred to that precompiled address *before* the precompiled logic runs, and the comment explicitly states this transfer "is not reversible by rollback." [1](#0-0) 

### Finding Description
When a smart contract issues a `CALL` (or `CALLTOKEN`) with a non-zero value against a precompiled-contract address, `exeCall` routes execution to `Program.callToPrecompiledAddress` instead of `callToAddress`. [2](#0-1) 

Inside `callToPrecompiledAddress`, the endowment is moved from the caller to the precompiled address via `MUtil.transfer` (for TRX) or direct token-balance mutation (for TRC10) unconditionally, prior to any check of whether the precompiled contract's `execute()` call succeeds: [3](#0-2) 

Only afterward is `contract.execute(data)` invoked. If it fails (`out.getLeft()` is `false`), the code simply pushes zero onto the stack and refunds energy — it does **not** revert or refund the endowment that was already transferred: [4](#0-3) 

None of the built-in precompiled contracts (`ECRecover`, `Sha256`, `Ripempd160`, `Identity`, `ModExp`, `BN128*`, `BatchValidateSign`, `ValidateMultiSign`, `RewardBalance`, `IsSrCandidate`, `VoteCount`, freeze/vote/resource query precompiles, etc.) implement any logic to consume, forward, or withdraw a received value — they are pure query/verification functions. [5](#0-4) 

Because a precompiled address has no associated contract code/account controllable by normal transactions (it is not a real deployed contract with a withdraw function), TRX or TRC10 tokens sent to it via `CALL`/`CALLTOKEN` with value are permanently locked at that address with no protocol-level mechanism to recover them — mirroring the AvailBridge pattern where an irreversible transfer occurs without any recorded means to refund the sender if the receiving side does not (or cannot) properly account for the value.

### Impact Explanation
Any unprivileged contract deployer/caller (via `TriggerSmartContract`) can accidentally or through poorly written Solidity code (e.g. `precompiledAddr.call.value(x)(...)`) send TRX/TRC10 to a precompiled address. That value is irrecoverably lost/burned outside the black-hole mechanism, and there is no accounting event, refund, or a "receiveETH"-style callback path that this repo needs — the funds simply vanish from the caller's control into an address nobody can spend from. This is a permanent freezing/loss-of-funds condition for the caller's assets, matching a Medium severity accepted-impact category (permanent freezing of user funds).

### Likelihood Explanation
Any contract on-chain that forwards `msg.value` blindly during a `.call{value: x}()` (a very common Solidity pattern, e.g. via low-level `call` or a fallback/proxy pattern) could unintentionally target a precompiled address, especially since precompiled addresses (0x1 through 0xa, and the 0x1000001+ range) are low, guessable, fixed addresses. It also can happen deliberately/accidentally in composed contract logic (e.g., a delegatecall/proxy resolving to a precompile address, or attacker-supplied address parameters). Given the number of precompiled entries (identity, ecrecover, batchValidateSign, reward/vote query contracts, resource-v2 query contracts, etc.), the surface for this to be hit is non-trivial, though it typically requires either developer error or an attacker crafting a malicious contract that forwards funds to one of these fixed addresses.

### Recommendation
In `Program.callToPrecompiledAddress`, either: (1) reject calls carrying non-zero endowment/value to precompiled addresses outright (revert/`stackPushZero` without transferring value), similar to how many EVM implementations disallow sending value to non-payable precompiles, or (2) refund the endowment back to the caller if the precompiled contract's `execute()` fails or if the specific precompile does not declare itself payable/value-consuming.

### Proof of Concept
1. Deploy a simple contract with a function: `function sink(address payable target) public payable { target.call.value(msg.value)(""); }` (Solidity ^0.4/^0.5 low-level call syntax as used elsewhere in this codebase's test suite, e.g. `TransferWhenDeployContract`/`EnergyOfTransferFailedTest` contracts referenced in `framework/src/test/java/org/tron/common/runtime/vm/TransferFailedEnergyTest.java`).
2. Call `sink` with `target = 0x0000000000000000000000000000000000000004` (the `Identity` precompile address, `identityAddr`) and a non-zero `callValue`.
3. Trace through `OperationActions.callAction` → `exeCall` → `Program.callToPrecompiledAddress`: the endowment transfer at lines 1712-1732 executes unconditionally, moving TRX from the caller's contract to the fixed identity-precompile address.
4. Confirm via `AccountStore` state that the precompile address's balance increased by the endowment, and there is no code path (actuator, precompile, or otherwise) that lets any account withdraw balance from that fixed address, permanently locking the funds. [6](#0-5)

  public void callToPrecompiledAddress(MessageCall msg,
      PrecompiledContracts.PrecompiledContract contract) {
    returnDataBuffer = null; // reset return buffer right before the call

    if (getCallDeep() == MAX_DEPTH) {
      stackPushZero();
      this.refundEnergy(msg.getEnergy().longValue(), " call deep limit reach");
      return;
    }

    Repository deposit = getContractState().newRepositoryChild();

    byte[] senderAddress = getContextAddress();
    byte[] contextAddress;
    if (msg.getOpCode() == Op.CALLCODE || msg.getOpCode() == Op.DELEGATECALL) {
      contextAddress = senderAddress;
    } else {
      contextAddress = msg.getCodeAddress().toTronAddress();
    }

    long endowment = msg.getEndowment().value().longValueExact();
    long senderBalance = 0;
    byte[] tokenId = null;

    checkTokenId(msg);
    boolean isTokenTransfer = isTokenTransfer(msg);
    // transfer TRX validation
    if (!isTokenTransfer) {
      senderBalance = deposit.getBalance(senderAddress);
    } else {
      // transfer trc10 token validation
      tokenId = String.valueOf(msg.getTokenId().longValue()).getBytes();
      senderBalance = deposit.getTokenBalance(senderAddress, tokenId);
    }
    if (senderBalance < endowment) {
      stackPushZero();
      refundEnergy(msg.getEnergy().longValue(), REFUND_ENERGY_FROM_MESSAGE_CALL);
      return;
    }
    byte[] data = this.memoryChunk(msg.getInDataOffs().intValue(),
        msg.getInDataSize().intValue());

    // Charge for endowment - is not reversible by rollback
    if (!ArrayUtils.isEmpty(senderAddress) && !ArrayUtils.isEmpty(contextAddress)
        && senderAddress != contextAddress && msg.getEndowment().value().longValueExact() > 0) {
      if (!isTokenTransfer) {
        try {
          MUtil.transfer(deposit, senderAddress, contextAddress,
              msg.getEndowment().value().longValueExact());
        } catch (ContractValidateException e) {
          throw new BytecodeExecutionException("transfer failure");
        }
      } else {
        try {
          VMUtils
              .validateForSmartContract(deposit, senderAddress, contextAddress, tokenId, endowment);
        } catch (ContractValidateException e) {
          throw new BytecodeExecutionException(VALIDATE_FOR_SMART_CONTRACT_FAILURE, e.getMessage());
        }
        deposit.addTokenBalance(senderAddress, tokenId, -endowment);
        deposit.addTokenBalance(contextAddress, tokenId, endowment);
      }
    }

    long requiredEnergy = contract.getEnergyForData(data);
    if (requiredEnergy > msg.getEnergy().longValue()) {
      // Not need to throw an exception, method caller needn't know that
      // regard as consumed the energy
      this.refundEnergy(0, CALL_PRE_COMPILED); //matches cpp logic
      this.stackPushZero();
    } else {
      // Delegate or not. if is delegated, we will use msg sender, otherwise use contract address
      if (msg.getOpCode() == Op.DELEGATECALL) {
        contract.setCallerAddress(getCallerAddress().toTronAddress());
      } else {
        contract.setCallerAddress(getContextAddress());
      }
      // this is the depositImpl, not contractState as above
      contract.setRepository(deposit);
      contract.setResult(this.result);
      contract.setConstantCall(isConstantCall());
      contract.setVmShouldEndInUs(getVmShouldEndInUs());
      Pair<Boolean, byte[]> out = contract.execute(data);

      if (out.getLeft()) { // success
        this.refundEnergy(msg.getEnergy().longValue() - requiredEnergy, CALL_PRE_COMPILED);
        this.stackPushOne();
        returnDataBuffer = out.getRight();
        deposit.commit();
      } else {
        // spend all energy on failure, push zero and revert state changes
        this.refundEnergy(0, CALL_PRE_COMPILED);
        this.stackPushZero();
        if (Objects.nonNull(this.result.getException())) {
          throw result.getException();
        }
      }
