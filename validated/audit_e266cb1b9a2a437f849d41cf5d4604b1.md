### Title
`TokenDiff::token_fee` fee waiver at `amount<=1` lets Nep245/Imt legs be split into unit-quantity intents to bypass the percentage fee - ([File: contracts/defuse/core/src/intents/token_diff.rs])

### Summary
`TokenDiff::token_fee` charges `Pips::ZERO` on any `Nep245`/`Imt` leg whose `|delta| <= 1`, and only applies `fee` once `amount > 1` [1](#0-0) . Since `execute_intent` computes the fee independently for each signed `TokenDiff` intent from its own leg's `delta.unsigned_abs()` with no aggregation across intents in the same batch or across a signer's history, an attacker can always structure a Nep245/Imt transfer of any total size as a sequence of `amount == 1` legs and pay `fee_ceil(1) == 0` on every leg instead of `fee_ceil(N)` on a single `N`-sized leg.

### Finding Description
The broken binding: for a Nep245 leg moving total quantity `N` of `token_id`, the protocol intends `total_fee(N) == Pips::fee_ceil(fee, N)` regardless of how the transfer is decomposed. In the code, `total_fee` is instead `Σ TokenDiff::token_fee(token_id, |delta_i|, fee).fee_ceil(|delta_i|)` summed over however many legs the attacker chooses to sign, computed independently per `TokenDiff` intent in `execute_intent`: [2](#0-1) 

Because `token_fee` returns `Pips::ZERO` whenever `amount <= 1` for `Nep245`/`Imt` token types [1](#0-0) , an attacker (or attacker + colluding counterparty, which can be the attacker's own second account) can sign `N` separate `TokenDiff` intents, each with `delta == -1` on the token being spent and a matching `+1`/`-1` pair on the other leg, instead of one intent with `delta == -N`. Each of the `N` legs independently hits the `amount <= 1` branch and contributes `0` to `fees_collected`, whereas a single `delta == -N` (`N > 1`) leg would hit the `fee` branch and pay `fee.fee_ceil(N)`.

No existing guard prevents this: `MultiPayload::verify`, nonce checks, and `TokenTransferMatcher::finalize_into`'s net-zero-per-token invariant only ensure the batch's total deltas per token sum to zero across all signers — they do not aggregate or otherwise cap the number of legs, nor do they compute fee based on the aggregate quantity transferred per token per signer. The fee computation in `execute_intent` is strictly local to a single intent's single delta.

### Impact Explanation
Protocol fee revenue on Nep245/Imt token flows can be driven to zero regardless of the actual value moved, matching the Critical category "protocol fees bypassed or over-collected." The fee collector (`engine.state.fee_collector()`) receives less than the protocol fee schedule dictates for legitimate transfers routed through Nep245/Imt tokens; this is repeatable by any signer for any Nep245/Imt `token_id` and any total size, limited only by the number of distinct signed intents (and their nonces/gas) the attacker is willing to submit in a batch. It does not, however, allow theft of funds not authorized by their owner, replay of a signature, or a batch imbalance the Verifier does not custody — it strictly under-collects the intended fee.

### Likelihood Explanation
Any unprivileged account can construct this without special roles: it only requires signing `N` `TokenDiff` intents instead of one, submitted together (or across several) `execute_intents`/`simulate_intents` calls, with a counterparty (which can be the attacker's own second account) providing the matching legs to satisfy the whole-batch net-zero invariant. Feasibility scales with the number of legs the attacker is willing to sign and pay gas for; the cost is linear in the degree of fee avoidance and grows with `N`, so this is most attractive on Nep245/Imt tokens whose per-unit value is high (e.g., a token type with 0 decimals or one representing a large fungible balance per unit) — for such tokens, splitting is cheap relative to the fee saved.

### Recommendation
Compute the Nep245/Imt fee waiver based on genuine indivisibility (e.g., only for `Nep171`-style unique items, or by consulting per-`token_id` metadata about whether the id represents a truly atomic NFT-like item) rather than purely on the numeric `amount` of a single intent's delta. Alternatively, remove or tighten the `amount > 1` threshold for `Nep245`/`Imt` so that fee is charged proportionally to the exact quantity moved regardless of how many separate intents/legs a signer uses.

### Proof of Concept
```rust
// crates/primitives/fees or contracts/defuse/core unit test
use defuse_fees::Pips;
use defuse_core::{token_id::nep245::Nep245TokenId, intents::token_diff::TokenDiff};

let nep245_id = Nep245TokenId::new("mt.near".parse().unwrap(), "ft1".to_string()).into();

assert_eq!(TokenDiff::token_fee(&nep245_id, 1, Pips::ONE_PERCENT), Pips::ZERO);
assert_eq!(TokenDiff::token_fee(&nep245_id, 2, Pips::ONE_PERCENT), Pips::ONE_PERCENT);
```
Sandbox-level PoC (`near-workspaces`), mirroring `tests/src/tests/defuse/intents/token_diff.rs::swap_many`:
1. Deploy Defuse with `Pips::ONE_PERCENT` fee; create two accounts `attacker_a` and `attacker_b` (attacker controls both), and deposit a Nep245 balance of `500` of `token_id` to `attacker_a`, and `500` of a second Nep245 `token_id2` to `attacker_b`.
2. Batch A: sign one `TokenDiff{ -500 token_id, +500 token_id2 }` from `attacker_a` and the mirror from `attacker_b`; execute; assert fee collector's `mt_balance_of(token_id)` equals `Pips::ONE_PERCENT.fee_ceil(500)`.
3. Batch B: sign 500 separate `TokenDiff{ -1 token_id, +1 token_id2 }` intents from `attacker_a` (distinct nonces) and 500 matching `+1/-1` intents from `attacker_b`; execute; assert fee collector's `mt_balance_of(token_id)` is `0`, while both attacker accounts end with the same net balance change as in Batch A.
4. This demonstrates the fee collector's balance differs (`0` vs `fee_ceil(500)`) for an identical net economic transfer, confirming the bypass.

    #[inline]
    pub fn token_fee(token_id: impl Into<TokenIdType>, amount: u128, fee: Pips) -> Pips {
        let token_id = token_id.into();
        match token_id {
            TokenIdType::Nep141 => {}
            TokenIdType::Nep245 | TokenIdType::Imt if amount > 1 => {}
            // do not take fees on NFTs and MTs with |delta| <= 1
            TokenIdType::Nep171 | TokenIdType::Nep245 | TokenIdType::Imt => return Pips::ZERO,
        }
        fee
    }
