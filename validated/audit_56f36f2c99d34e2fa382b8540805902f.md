### Title
Global `overall_connection_rate_limiter` in `run_server`/`setup_connection` has no per-peer-class fairness, letting a distributed unstaked flood starve legitimate staked-peer QUIC handshakes - ([File: streamer/src/nonblocking/quic.rs])

### Summary
`run_server` gates every incoming QUIC connection behind a single shared `TokenBucket` (`overall_connection_rate_limiter`, capacity/refill `MAX_CONNECTION_BURST`/`TOTAL_CONNECTIONS_PER_SECOND` = 1000/2500 per second) applied identically to all source IPs before any stake-based prioritization occurs. Because the per-IP `ConnectionRateLimiter` only throttles individual IPs (default `DEFAULT_MAX_CONNECTIONS_PER_IPADDR_PER_MINUTE` = 8/min, ×10 burst), an unprivileged attacker who spreads low-rate connection attempts across enough distinct source addresses (e.g., IPv6 rotation or NAT/residential proxy pools) can keep the global bucket permanently drained, causing `incoming.ignore()`/`close(CONNECTION_CLOSE_CODE_DISALLOWED, ...)` for all new connections — staked or unstaked alike — since stake awareness is only applied later, inside `qos.try_add_connection`, which never gets reached.

### Finding Description
In `run_server` (streamer/src/nonblocking/quic.rs), each incoming connection is checked in this order:
1. Global check: `if overall_connection_rate_limiter.current_tokens() == 0 { ... incoming.ignore(); continue; }` [1](#0-0)  — this is a single `Arc<TokenBucket>` shared across all peers, seeded with `TokenBucket::new(MAX_CONNECTION_BURST, MAX_CONNECTION_BURST, TOTAL_CONNECTIONS_PER_SECOND)` [2](#0-1) .
2. Per-IP check: `rate_limiter.is_allowed(&incoming.remote_address().ip())` [3](#0-2) , backed by `ConnectionRateLimiter`, a `KeyedRateLimiter<IpAddr>` keyed per source IP [4](#0-3) .

After a successful handshake, `setup_connection` consumes one token from the same global bucket again via `overall_connection_rate_limiter.consume_tokens(1)` [5](#0-4) , and only *after* this global gate does it call `qos.build_connection_context` / `qos.try_add_connection`, which is where stake-based classification (`ConnectionPeerType::Staked`/`Unstaked`) and per-class connection tables/limits actually apply [6](#0-5) .

Because the global bucket is consumed on a strict first-come basis with no separate quota or priority lane for staked traffic, an attacker who keeps per-IP arrival rates below the per-IP ceiling (`max_connections_per_ipaddr_per_min` × 10 burst) but sums to more than `TOTAL_CONNECTIONS_PER_SECOND` (2500/s) in aggregate can continuously exhaust `overall_connection_rate_limiter`. With the default per-IP allowance of ~1.33 sustained conn/s (8/min) per source, roughly ~1,900 distinct source IPs sending at just under their individual limits is sufficient to keep the shared bucket at zero, causing every other peer's new connection attempts — including staked validators reconnecting after a drop — to be rejected at line 347 or 495 before stake is ever evaluated.

### Impact Explanation
This is a network-reachable, unauthenticated denial-of-service against the TPU QUIC ingress: legitimate staked peers can be prevented from ever establishing new QUIC connections to a leader (e.g., after connection churn, restart, or normal reconnection), because the sole global admission gate treats all peer classes identically and is exhausted before any stake-based prioritization logic in `QosController`/`SimpleQos`/`swqos` runs. This falls into the validator/networking DoS bounty category (unstaked clients denying service to staked clients cluster-wide, without needing privileged access).

### Likelihood Explanation
Feasibility requires only an unprivileged remote attacker capable of originating traffic from many source addresses (trivial with an IPv6 /64 allocation, cheap residential proxy pools, or many cloud IPs) at a low per-IP rate under `DEFAULT_MAX_CONNECTIONS_PER_IPADDR_PER_MINUTE`. No stake, keys, or validator control are needed; it's a distributed but easily automatable volumetric attack pattern, sustained indefinitely as long as the attacker's aggregate rate exceeds 2500 conn/s.

### Recommendation
Partition the global admission budget by peer class (e.g., reserve a minimum share of `overall_connection_rate_limiter` tokens for staked-identified peers, or perform a lightweight stake lookup — via the retry-token/address-validation phase already used for handshake DoS protection — before the global token is consumed), so an unstaked flood cannot fully starve staked connection admission. Alternatively, split into two token buckets (staked-reserved and unstaked-shared) sized proportionally, checked in `run_server`/`setup_connection`.

### Proof of Concept
Integration/fuzz test plan (streamer/src/nonblocking/quic.rs test harness, using `setup_quic_server` helpers already present in the crate):
1. Spawn `run_server` (via existing `spawn_server`/test helpers) with default `QuicStreamerConfig` (`TOTAL_CONNECTIONS_PER_SECOND=2500`, `MAX_CONNECTION_BURST=1000`, `DEFAULT_MAX_CONNECTIONS_PER_IPADDR_PER_MINUTE=8`).
2. Spawn ~2000 simulated client tasks, each bound to a distinct source `IpAddr` (loopback alias range or mocked `SocketAddr`s if the test harness supports it), each issuing connection attempts at a rate just under 8/min per IP but collectively exceeding 2500/s.
3. Concurrently spawn a small number of "staked" client connections (registered in `StakedNodes`) attempting fresh handshakes throughout the attack window.
4. Assert: `stats.connection_rate_limited_across_all` (from `StreamerStats`) increases sharply during the attack, and the staked clients' connection success rate drops below an acceptable floor (e.g., <50%) purely due to the shared `overall_connection_rate_limiter`, independent of per-IP or stake-based limiters — demonstrating the fairness invariant violation.

/// Limits the rate of connections per IP address.
pub struct ConnectionRateLimiter {
    limiter: KeyedRateLimiter<IpAddr>,
}

/// The threshold of the size of the connection rate limiter map. When
/// the map size is above this, we will trigger a cleanup of older
/// entries used by past requests.
const CONNECTION_RATE_LIMITER_CLEANUP_SIZE_THRESHOLD: usize = 100_000;

impl ConnectionRateLimiter {
    /// Create a new rate limiter per IpAddr. The rate is specified as the count per minute to allow for
    /// less frequent connections. Higher limit also allows higher bursts.
    /// num_shards controls how many shards are used in the underlying dashmap,
    /// should be set >= number of contending threads.
    pub fn new(limit_per_minute: u64, max_burst: u64, num_shards: usize) -> Self {
        Self {
            limiter: KeyedRateLimiter::new(
                CONNECTION_RATE_LIMITER_CLEANUP_SIZE_THRESHOLD,
                TokenBucket::new(limit_per_minute, max_burst, limit_per_minute as f64 / 60.0),
                num_shards,
            ),
        }
    }
