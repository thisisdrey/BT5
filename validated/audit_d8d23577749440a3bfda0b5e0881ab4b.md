### Title
Unauthenticated `header.RecvError` packet triggers `closeTunnel` + `handshakeManager.DeleteHostInfo` without cryptographic proof of peer identity - ([File: outside.go])

### Summary
`Interface.handleRecvError` in `outside.go` accepts a `header.RecvError` packet and tears down a tunnel (`f.closeTunnel(hostinfo)` and `f.handshakeManager.DeleteHostInfo(hostinfo)`) based only on (1) a source-address match to the hostinfo's currently known remote and (2) a plaintext `RemoteIndex` header field, with no AEAD/cryptographic authentication of the sender.

### Finding Description
`readOutsidePackets` dispatches `header.RecvError` packets directly to `f.handleRecvError(via.UdpAddr, h)` before any decryption/authentication step, alongside `header.Handshake`, since these are explicitly treated as "Unencrypted packets" [1](#0-0) .

Inside `handleRecvError`, the only checks performed are:
1. A local rate/allow policy `f.acceptRecvErrorConfig.ShouldRecvError(addr)`.
2. A lookup of the hostinfo via `f.hostMap.QueryReverseIndex(h.RemoteIndex)` — a plaintext, attacker-supplied 32-bit index carried in every packet header (including ordinary encrypted data packets), so it is not secret.
3. A comparison `hr := hostinfo.GetRemote(); if hr.IsValid() && hr != addr { ...deny... }` — this only checks that the *source address* of the UDP packet matches the currently known remote for that hostinfo, which is a heuristic, not a cryptographic check.

If both the (guessable/observable) index and (spoofable) source address happen to match, the code proceeds directly to `f.closeTunnel(hostinfo)` and `f.handshakeManager.DeleteHostInfo(hostinfo)`, with no verification that the packet actually originated from the authenticated peer holding the negotiated symmetric keys [2](#0-1) . `closeTunnel` itself unconditionally calls `f.hostMap.DeleteHostInfo(hostInfo)` [3](#0-2) .

Contrast this with `header.CloseTunnel` and all other message types, which are only processed after successful `hostinfo.ConnectionState.Decrypt` (AEAD authentication) at `outside.go` lines 126-166 [4](#0-3) . `RecvError` is the sole state-destroying packet type exempted from this AEAD gate.

Because `RemoteIndex` is transmitted in cleartext in the header of every packet (handshake, message, etc.), any attacker capable of observing a single packet exchanged between the victim and its peer (e.g., on-path, or off-path with the ability to spoof the peer's source UDP address) can learn the correct index without brute-forcing it, and then send one spoofed `RecvError` packet from the peer's known address to trigger teardown.

### Impact Explanation
A single unauthenticated packet, requiring only knowledge of a peer's current public `AddrPort` and the cleartext `RemoteIndex` value (learnable from any observed packet on the tunnel), causes immediate deletion of hostmap and handshake-manager state for a targeted tunnel. This is a remote, unauthenticated denial-of-service/availability degradation: the victim must renegotiate a handshake, and repeated spoofed packets can be used to continuously prevent a stable tunnel from being maintained between two legitimate peers.

### Likelihood Explanation
Preconditions: attacker must (a) learn the victim's current UDP `AddrPort` (feasible via NAT/traffic observation, as noted in the prompt) and (b) obtain the correct `RemoteIndex`, which is sent in cleartext on the wire for every packet and thus does not require brute force if the attacker can observe any traffic on the path. The rate-limiting config (`ShouldRecvError`) may reduce repeatability/throttle the attack but does not add cryptographic authentication, so a single well-timed packet remains sufficient. Feasibility depends on the attacker's ability to spoof the source UDP address of the real peer (on-path attacker, or environments without egress/ingress filtering), which the audit rules explicitly place in scope.

### Recommendation
Do not perform any destructive hostmap/handshake-manager mutation based solely on an unauthenticated `RecvError` packet plus address/index matching. Options: (1) require `RecvError` handling to only mark the tunnel as suspect and force a new authenticated handshake attempt rather than deleting state outright, or (2) authenticate `RecvError` by signing/MACing it with the existing session key (if any) rather than relying purely on source-address correlation, or (3) require confirmation via a subsequent successful handshake before fully deleting the old hostinfo (soft-delete/quarantine instead of `DeleteHostInfo`).

### Proof of Concept
Integration test outline:
1. Establish two real Nebula `Interface` instances (A and B) with a working authenticated tunnel, so `hostMap` on A has a `HostInfo` for B with a known `RemoteIndex` and `GetRemote()` returning B's `AddrPort`.
2. Craft a raw UDP packet with `header.Encode(..., header.Version, header.RecvError, 0, <B's known RemoteIndex on A>, 0)` — no AEAD payload, no valid keys.
3. Using a raw/spoofed UDP socket (or a test harness that directly calls `f.handleRecvError(bAddrPort, h)` on A to simulate a spoofed source address matching B's `AddrPort`), send this single packet to A.
4. Assert that A's `hostMap` no longer contains the hostinfo for B (`QueryReverseIndex`/`QueryVpnAddr` returns nil) and that `handshakeManager` pending state for B was deleted — demonstrating `closeTunnel`/`DeleteHostInfo` fired without any AEAD-authenticated packet from B.
5. Expected (secure) behavior: the assertion should fail, i.e., tunnel state should not be destroyed without cryptographic proof of peer identity; the test demonstrates the current code violates that invariant.

func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
