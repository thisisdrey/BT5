### Title
Protocol fee bypass on NEP-245/IMT token diffs via unit-splitting - ([File: contracts/defuse/core/src/intents/token_diff.rs])

### Summary
`TokenDiff::token_fee` unconditionally zeroes the fee for `Nep245`/`Imt` legs whose absolute delta is `1`, and `TokenDiff::execute_intent` computes and accumulates `fees_collected` independently per `TokenDiff` intent rather than per aggregate negative delta across a batch/signer. An unprivileged signer can split a single bulk negative delta of size `N` on one `Nep245TokenId` into `N` separate `TokenDiff` intents (or entries across a batch) each with `delta == -1`, reducing the total fee owed from `Pips::fee_ceil(N) > 0` to `0`.

### Finding Description
The broken binding is: fee credited to `fee_collector` for token `T` should equal `Pips::fee_ceil` applied to the total negative delta of `T` moved by the signer in economically equivalent trades. Instead, the code computes: [1](#0-0) 
per `TokenDiff` intent, where `Self::token_fee` explicitly zeroes the fee whenever a `Nep245`/`Imt` leg has `amount <= 1`: [2](#0-1) 

Because `fee_ceil` rounds up (`fee_ceil(1)` would otherwise always equal `1` — the entire unit — for any nonzero fee), the amount<=1 exemption exists to avoid charging a full-unit fee on true NFT-like transfers. However, this exemption is evaluated purely per-`TokenDiff`-intent and per-token-entry; it does not track cumulative negative delta for the same `TokenId` across multiple intents in a signer's own `DefuseIntents` message or across a batch. A signer moving `N` units of a `Nep245TokenId` that in practice represents fungible value (not a genuine unique NFT) can submit `N` separate `TokenDiff` intents, each `{token_id: -1}`, in place of a single `{token_id: -N}` intent. Each intent independently hits the `amount > 1` false branch and returns `Pips::ZERO`, so `fees_collected` for `T` sums to `0` across all `N` intents, whereas a single `-N` intent would have incurred `Pips::fee_ceil(N) > 0`.

None of the existing guards address this: `MultiPayload::verify`, nonce/salt checks, and the batch-level netting invariant in `finalize()` only ensure signature validity and that all deltas across signers net to zero; they do not aggregate or re-derive fees from net per-token deltas. The netting/invariant check is orthogonal to the fee-collection logic, so a counterparty simply needs matching positive deltas within the same executed batch for the split trade to succeed with zero fee.

### Impact Explanation
`fee_collector` receives less (potentially zero) revenue than it would for an economically identical bulk trade, on any `Nep245`/`Imt` token whose per-unit value is non-trivial (e.g., an MT contract used to represent divisible/fungible balances at 0 decimals). This matches the "protocol fees bypassed" Critical category: no per-signer cap limits repetition, so the technique is repeatable across every trade and every `Nep245`/`Imt` `TokenId`, directly reducing protocol revenue without requiring any privileged role.

### Likelihood Explanation
The only precondition is that the signer's transferred `Nep245`/`Imt` asset is deployed/used with per-unit value greater than negligible (common for MT wrappers used as fungible tokens), and that the counterparty is willing to accept the same trade structured as many unit legs instead of one bulk leg (which requires no coordination beyond ordinary counterparty-matching already used for `TokenDiff` swaps). Cost to the attacker is only the added transaction size/gas for `N` intents in one signed payload; feasibility is high and fully repeatable.

### Recommendation
Aggregate the negative-delta amount per `TokenId` across the *entire* `DefuseIntents`/batch (or at minimum sum negative deltas for the same `TokenId` within the signer's message) before applying the `amount > 1` threshold in `TokenDiff::token_fee`, so that fee-exemption decisions are based on the true net amount moved rather than on artificially split per-intent legs.

### Proof of Concept
In `contracts/defuse/core/src/intents/token_diff.rs` tests module, add a test that:
1. Constructs a `Nep245TokenId` and a nonzero `Pips` fee.
2. Executes one `TokenDiff::execute_intent` with `diff = {token_id: -N}` (N > 1) and asserts `fees_collected.amount_for(&token_id) > 0`.
3. Executes `N` separate `TokenDiff::execute_intent` calls (or `N` intents in one `DefuseIntents` message via `Engine::execute_signed_intents`), each with `diff = {token_id: -1}`, and asserts the summed `fees_collected` across all `N` calls equals `0`.
4. Assert the two totals differ (`0 != Pips::fee_ceil(N)`), demonstrating the same net token movement produces divergent fee outcomes purely based on intent structuring.
