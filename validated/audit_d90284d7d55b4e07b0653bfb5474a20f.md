### Title
Clique `Snapshot.inturn` divides by the number of signers without guarding against zero, allowing a single remaining signer to crash every node — (File: `consensus/clique/snapshot.go`)

### Summary
`Snapshot.apply()` allows the signer set to shrink to zero members through the normal Clique voting mechanism, and `Snapshot.inturn()` unconditionally computes `number % uint64(len(signers))` with no check that `len(signers) > 0`. When the signer set becomes empty, this is an integer division by zero, which panics in Go and crashes the node processing/verifying the next header.

### Finding Description
The vote-tallying logic in `apply()` accepts a de-authorization vote once `tally.Votes > len(snap.Signers)/2`: [1](#0-0) 

When `len(snap.Signers) == 1` (the last remaining authorized signer), the threshold becomes `tally.Votes > 0`, i.e. a single vote is sufficient. The sole remaining signer can therefore cast a nonce-drop vote against itself (`header.Coinbase == signer`), which passes the tally check and executes `delete(snap.Signers, header.Coinbase)`, leaving `snap.Signers` empty. Nothing in `apply()`, `cast()`, or `verifyHeader()` rejects a vote that would remove the last signer.

Once the snapshot's `Signers` map is empty, any subsequent call to: [2](#0-1) 

executes `number % uint64(len(signers))` with `len(signers) == 0`, which is a division by zero and panics. This function is reached from two unprivileged consensus code paths:

- `calcDifficulty()` (used by `Prepare()` and `CalcDifficulty()`) when any node — including the attacker itself — tries to seal or compute the difficulty of the next block: [3](#0-2) 

- `verifySeal()`, called by every node while validating any subsequently received header, since it needs to determine whether the signer was "in turn": [4](#0-3) 

This mirrors the reported bug class: a denominator quantity (here, `len(signers)`, analogous to `totalSupply()`) is used unconditionally in a division without checking it can legitimately reach zero through normal protocol operation (voting), causing a revert/panic that halts core functionality (block validation/sealing) for every participant.

### Impact Explanation
Once the last signer votes itself out, the chain's signer set becomes permanently empty. The very next header that any node — including the attacker's own node — attempts to verify via `verifySeal()`, or that any node attempts to prepare/seal via `Prepare()`/`CalcDifficulty()`, triggers a divide-by-zero panic in `Snapshot.inturn()`. Because `verifyHeader`/`verifySeal` are invoked by the standard header-validation path used by every node processing new blocks, this crashes every Geth node following that Clique chain — a network-wide halt caused by a legitimate (though carelessly permitted) voting sequence, not by malformed data. This matches the "Critical" impact bar (a single block/header interaction that crashes or halts every node).

### Likelihood Explanation
This requires control of the single remaining authorized signer in a network that has (through prior voting, malice, key compromise, or simple misconfiguration) been reduced to one signer. Clique networks with a small or shrinking signer set (e.g., during decommissioning, migrations, or compromised keys) are realistically exposed. The bug is deterministic and requires no race condition — any client reaching zero signers will panic on the very next header verification or difficulty calculation.

### Recommendation
In `Snapshot.apply()`, reject a de-authorization vote (or any vote result) that would reduce `len(snap.Signers)` to zero, e.g.:
```go
if !tally.Authorize && len(snap.Signers) <= 1 {
    // do not allow removing the last signer
}
```
Additionally, add a defensive `len(signers) == 0` guard in `Snapshot.inturn()` to fail closed (return an explicit error/false) rather than panic, providing defense in depth even if the signer-set invariant is violated elsewhere.

### Proof of Concept
1. Start a Clique chain with a single active signer `S` (either from genesis with one signer, or after voting down to one signer through normal Clique voting).
2. Have `S` produce a block with `Coinbase = S` and `Nonce = nonceDropVote` (a self-deauthorization vote).
3. In `apply()`, `tally.Votes` becomes `1`, and since `len(snap.Signers) == 1`, the threshold `tally.Votes > len(snap.Signers)/2` (`1 > 0`) passes, so `S` is deleted from `snap.Signers`, leaving the signer set empty.
4. Any node (including `S` itself) now calls `verifySeal()` for the next header, or `Prepare()`/`CalcDifficulty()` to build the next block — both invoke `snap.inturn(...)`, which executes `number % uint64(len(signers))` with `len(signers) == 0`, causing an unrecoverable Go panic (`runtime error: integer divide by zero`) and crashing the node.

// inturn returns if a signer at a given block height is in-turn or not.
func (s *Snapshot) inturn(number uint64, signer common.Address) bool {
	signers, offset := s.signers(), 0
	for offset < len(signers) && signers[offset] != signer {
		offset++
	}
	return (number % uint64(len(signers))) == uint64(offset)
}

func (c *Clique) verifySeal(snap *Snapshot, header *types.Header, parents []*types.Header) error {
	// Verifying the genesis block is not supported
	number := header.Number.Uint64()
	if number == 0 {
		return errUnknownBlock
	}
	// Resolve the authorization key and check against signers
	signer, err := ecrecover(header, c.signatures)
	if err != nil {
		return err
	}
	if _, ok := snap.Signers[signer]; !ok {
		return errUnauthorizedSigner
	}
	for seen, recent := range snap.Recents {
		if recent == signer {
			// Signer is among recents, only fail if the current block doesn't shift it out
			if limit := uint64(len(snap.Signers)/2 + 1); seen > number-limit {
				return errRecentlySigned
			}
		}
	}
	// Ensure that the difficulty corresponds to the turn-ness of the signer
	if !c.fakeDiff {
		inturn := snap.inturn(header.Number.Uint64(), signer)
		if inturn && header.Difficulty.Cmp(diffInTurn) != 0 {
			return errWrongDifficulty
		}
		if !inturn && header.Difficulty.Cmp(diffNoTurn) != 0 {
			return errWrongDifficulty
		}
	}
	return nil
}

// CalcDifficulty is the difficulty adjustment algorithm. It returns the difficulty
// that a new block should have:
// * DIFF_NOTURN(2) if BLOCK_NUMBER % SIGNER_COUNT != SIGNER_INDEX

func (c *Clique) CalcDifficulty(chain consensus.ChainHeaderReader, time uint64, parent *types.Header) *big.Int {
	snap, err := c.snapshot(chain, parent.Number.Uint64(), parent.Hash(), nil)
	if err != nil {
		return nil
	}
	c.lock.RLock()
	signer := c.signer
	c.lock.RUnlock()
	return calcDifficulty(snap, signer)
}

func calcDifficulty(snap *Snapshot, signer common.Address) *big.Int {
	if snap.inturn(snap.Number+1, signer) {
		return new(big.Int).Set(diffInTurn)
	}
	return new(big.Int).Set(diffNoTurn)
}
