### Title
Fee evasion via single-unit `Nep245`/`Imt` `TokenDiff` splitting - (File: `contracts/defuse/core/src/intents/token_diff.rs`)

### Summary
`TokenDiff::execute_intent` computes the protocol fee independently for every intent instance, using `token_fee(token_id, |delta|, fee)`, which is hard-coded to return `Pips::ZERO` for `Nep245`/`Imt` tokens whenever `|delta| <= 1`. [1](#0-0)  By decomposing a large `Nep245`/`Imt` trade into many `|delta| == 1` `TokenDiff` legs instead of one `TokenDiff` with the aggregate delta, an attacker collects `total_fee_collected == 0` instead of `Pips::fee_ceil(fee, B)` that would be charged on the real economic volume `B`.

### Finding Description
The intended binding is: `fee_owed_on_volume(B) == sum_of_fees_actually_collected_over_the_batch(B)`, where `fee_owed_on_volume(B) = Pips::fee_ceil(protocol_fee, B)` for a `Nep245`/`Imt` token traded in aggregate volume `B > 1`.

In the actual code, `execute_intent` iterates `self.diff` per-`TokenDiff` instance and, for each negative-delta leg, computes the fee as:
```
let fee = Self::token_fee(token_id, amount, protocol_fee).fee_ceil(amount);
``` [2](#0-1) 
and `token_fee` explicitly zeroes the fee whenever the per-leg `amount <= 1` for `Nep245`/`Imt` token types:
```
TokenIdType::Nep245 | TokenIdType::Imt if amount > 1 => {}
// do not take fees on NFTs and MTs with |delta| <= 1
TokenIdType::Nep171 | TokenIdType::Nep245 | TokenIdType::Imt => return Pips::ZERO,
``` [3](#0-2) 

There is no aggregation performed across multiple `TokenDiff` intents within the same batch/payload before this per-leg check: each `TokenDiff` intent applies `internal_apply_deltas` to the signer's balance and computes its own fee independently in isolation. `execute_signed_intents` simply loops `execute_signed_intent` over the supplied `MultiPayload`s and calls `intents.execute_intent(...)` for each, with the only cross-intent invariant enforced being that all balance changes across the whole batch (deposits/withdrawals via `TokenTransferMatcher`) net to zero at `finalize()` — this invariant does not re-derive or re-check the fee owed on the true aggregate per-token volume. [4](#0-3) [5](#0-4) 

Exploit flow: an attacker (using either their own second account or a cooperating counterparty account) crafts a `MultiPayload` batch consisting of `B` separate `TokenDiff` intents, each with `{token: -1}` for the attacker's signer, matched by `B` corresponding `{token: +1}` legs from the counterparty side, so that the batch-level `TransferMatcher` invariant nets to zero for that token (satisfying `finalize()`). Every one of the `B` legs independently evaluates `token_fee(token_id, amount=1, fee)` which returns `Pips::ZERO`, so `fees_collected` stays `0` for the whole batch, whereas a single `TokenDiff` moving the same aggregate volume `B` would have charged `Pips::fee_ceil(protocol_fee, B) > 0`. None of the existing guards (`MultiPayload::verify`, nonce/salt checks, `TransferMatcher::finalize`, or the `checked_*` arithmetic) inspect or limit the granularity of `TokenDiff` legs per token, so nothing prevents this splitting.

### Impact Explanation
The `fee_collector` account receives strictly less than the fee owed on the actual traded/transferred volume of any `Nep245`/`Imt` token whenever that volume is expressed via many `|delta| == 1` legs instead of one aggregate leg, which matches the "protocol fees bypassed" Critical impact category. This is fully repeatable: any account holding an `Nep245`/`Imt` balance and any willing counterparty (including a second account controlled by the same attacker) can apply this to any amount `B` and any number of times, on any `Nep245`/`Imt` token id, at zero fee.

### Likelihood Explanation
Preconditions are modest: the attacker only needs a balance `B` of an `Nep245`/`Imt` token inside the Verifier and a counterparty willing to co-sign matching unit legs — which can simply be a second account controlled by the same attacker, requiring no cooperation from any third party. The only cost is constructing a batch with `B` `TokenDiff` entries (which can be packed into fewer signed `MultiPayload`s, each containing multiple `TokenDiff` intents), all executed atomically in one `execute_intents` call.

### Recommendation
Aggregate the `|delta|` per `(signer_id, token_id)` across all `TokenDiff` intents in the batch before evaluating `token_fee`/`fee_ceil`, rather than evaluating fee eligibility per individual `TokenDiff` leg. Alternatively, remove or tighten the `amount <= 1` fee exemption for `Nep245`/`Imt` token types so it cannot be trivially triggered by batching, e.g. by tracking cumulative per-token, per-signer volume within a single settlement and only exempting truly atomic 1-of-1 NFT semantics (`Nep171`), not fungible-like `Nep245`/`Imt` balances.

### Proof of Concept
`cargo test` in the `defuse-core` crate (or `tests/src/tests/defuse/intents/token_diff.rs` integration suite):
1. Set up two accounts (`signer`, `counterparty`) each with sufficient `Nep245` token balance `B` (e.g., `B = 100`), with a non-zero protocol `fee`.
2. Path A: `signer` signs a single `TokenDiff` `{token: -B}` matched by `counterparty`'s `TokenDiff` `{token: +B}` (plus reciprocal token to balance); execute via `execute_signed_intents`; assert `fees_collected == Pips::fee_ceil(fee, B)` and that `fee_collector` balance increased by that amount.
3. Path B: `signer` signs `B` separate `TokenDiff` intents `{token: -1}` each, matched by `counterparty`'s `B` separate `{token: +1}` intents (plus reciprocal legs), packed into the same `MultiPayload`/batch; execute via `execute_signed_intents`; assert total `fees_collected == 0` and `fee_collector` balance unchanged.
4. Assert `Path A fee_collected != Path B fee_collected` (specifically `Path B == 0 < Path A`), proving the fee binding `sum(Pips::fee_ceil per aggregate) == sum(fees actually collected)` is broken.

    fn execute_signed_intent(&mut self, signed: MultiPayload) -> Result<()> {
        // verify signed payload and get public key
        let public_key = signed.verify().ok_or(DefuseError::InvalidSignature)?;

        // calculate intent hash
        let hash = signed.hash();

        // extract NEP-413 payload
        let DefusePayload::<DefuseIntents> {
            signer_id,
            verifying_contract,
            deadline,
            nonce,
            message: intents,
        } = signed.extract_defuse_payload()?;

        // check recipient
        if verifying_contract != *self.state.verifying_contract() {
            return Err(DefuseError::WrongVerifyingContract);
        }

        self.inspector.on_deadline(deadline);

        // make sure message is still valid
        if deadline < Timestamp::now() {
            return Err(DefuseError::DeadlineExpired);
        }

        // make sure the account has this public key
        if !self.state.has_public_key(&signer_id, &public_key) {
            return Err(DefuseError::PublicKeyNotExist(signer_id, public_key));
        }

        // commit nonce
        self.verify_intent_nonce(nonce, deadline)?;
        self.state.commit_nonce(signer_id.clone(), nonce)?;

        intents.execute_intent(&signer_id, self, hash)?;
        self.inspector.on_intent_executed(&signer_id, hash, nonce);

        Ok(())
    }

    // Finalizes transfer of this token, or returns unmatched delta.
    // If returned delta is zero, then overflow happened
    pub fn finalize_into(self, token_id: &TokenId, transfers: &mut Transfers) -> Result<(), i128> {
        // sort deposits and withdrawals in descending order
        let [mut deposits, mut withdrawals] = [self.deposits, self.withdrawals].map(|amounts| {
            let mut amounts: Vec<_> = amounts.into_iter().collect();
            amounts.sort_unstable_by_key(|(_, amount)| Reverse(*amount));
            amounts.into_iter()
        });

        // take first sender and receiver
        let (mut deposit, mut withdraw) = (deposits.next(), withdrawals.next());

        // as long as there is both: sender and receiver
        while let Some(((sender, send), (receiver, receive))) =
            withdraw.as_mut().zip(deposit.as_mut())
        {
            // get min amount and transfer
            let transfer = (*send).min(*receive);
            transfers
                .transfer(sender.clone(), receiver.clone(), token_id.clone(), transfer)
                // no error can happen since we add only one transfer for each
                // combination of (sender, receiver, token_id)
                .unwrap_or_else(|| unreachable!());

            // subtract amount from sender and receiver
            *send = send.saturating_sub(transfer);
            *receive = receive.saturating_sub(transfer);

            if *send == 0 {
                // select next sender
                withdraw = withdrawals.next();
            }
            if *receive == 0 {
                // select next receiver
                deposit = deposits.next();
            }
        }

        // only sender(s) left
        if let Some((_, send)) = withdraw {
            return Err(withdrawals
                .try_fold(send, |total, (_, s)| total.checked_add(s))
                .and_then(|total| i128::try_from(total).ok())
                .and_then(i128::checked_neg)
                .unwrap_or_default());
        }
        // only receiver(s) left
        if let Some((_, receive)) = deposit {
            return Err(deposits
                .try_fold(receive, |total, (_, r)| total.checked_add(r))
                .and_then(|total| i128::try_from(total).ok())
                .unwrap_or_default());
        }

        Ok(())
    }
