### Title
Unauthenticated `RecvError` packet allows spoofing attacker to forcibly tear down an established tunnel - ([File: outside.go])

### Summary
The Sherlock report describes cross-chain functions that any unprivileged caller can invoke, and where the caller controls a "cancel" capability (as `delegate`) that lets it unilaterally abort an in-flight, state-changing message and desynchronize the two sides. The reachable analog in Nebula is `header.RecvError` handling: it is processed as an **unencrypted, pre-authentication** packet type, and its handler `f.closeTunnel(hostinfo)` unilaterally tears down an already-established, mutually authenticated tunnel based only on a spoofable UDP source check, with no certificate/handshake proof required from the sender of the `RecvError` packet itself.

### Finding Description
In `readOutsidePackets`, packets are parsed and dispatched by header type before decryption. `header.RecvError` is explicitly handled in the "Unencrypted packets" branch, bypassing the AEAD/handshake-authenticated path entirely: [1](#0-0) 

The handler, `handleRecvError`, looks up the hostinfo purely from the plaintext `RemoteIndex` field in the packet header and then tears down the tunnel: [2](#0-1) 

The only anti-spoofing check performed is comparing the UDP source address of the incoming packet to the currently known remote address of that hostinfo (`hr.IsValid() && hr != addr`). This is a plain source-IP/port comparison on a UDP packet — trivially spoofable by an off-path or on-path attacker who can also observe (or brute-force, given the 32-bit index space) a victim's `RemoteIndex`/remote UDP endpoint, neither of which requires possessing a CA-signed certificate or completing the Noise handshake. There is a rate-limit gate (`f.acceptRecvErrorConfig.ShouldRecvError(addr)`), but this only throttles the frequency of accepted `RecvError` packets per source address — it provides no cryptographic authentication of the sender's identity or right to close that specific tunnel.

This mirrors the report's root cause exactly: a message-cancellation primitive (`RecvError` → `closeTunnel`) is reachable and actionable by a party with no valid credential for the affected channel, and its effect is to unilaterally and irreversibly desynchronize state between the two "sides" (here, the two peers' hostmaps) that were previously in an authenticated, established state.

### Impact Explanation
An attacker with no valid certificate, no completed handshake, and no cryptographic material for the target tunnel can force `closeTunnel` on a live, mutually authenticated session between two legitimate peers by spoofing a UDP packet with type `header.RecvError` and the victim's `RemoteIndex`/apparent remote address. This causes:
- Loss of an established secure tunnel (denial of service / state poisoning), forcing renegotiation.
- Removal of the pending hostinfo (`handshakeManager.DeleteHostInfo`), which can be leveraged repeatedly to prevent two nodes from ever completing/maintaining a stable tunnel — directly analogous to the report's "contracts on the two chains being out of sync" impact, but expressed as persistent tunnel desynchronization/DoS between two nebula nodes.
- No packet forgery of the tunnel's actual data-plane traffic is required; only the cleartext header fields, which are guessable/observable, are needed.

### Likelihood Explanation
Likelihood is moderate-to-high for an attacker who can observe any traffic between the two peers (on-path, or via a compromised lighthouse/relay path they merely watch) since `RemoteIndex` and remote UDP endpoints are visible in plaintext headers of every packet exchanged. Even fully off-path, the 32-bit `RemoteIndex` space combined with the ability to try many source-spoofed guesses against a known peer UDP endpoint (which is often known/public for lighthouses) makes this feasible without needing to hold a valid Nebula certificate for either endpoint — satisfying the "no CA-signed certificate" reachability constraint.

### Recommendation
- Do not act on `RecvError` (or any pre-handshake/unencrypted control packet) using only a UDP source-address match. Require that these control signals be authenticated, e.g., via a MAC tied to session key material established at handshake time, or ignore/heavily rate-limit and require corroborating evidence (such as repeated round-trip failures) before tearing down an established tunnel.
- Bind acceptance of `RecvError` to a token/nonce derived from the current `ConnectionState` for that `hostinfo` rather than the plaintext `RemoteIndex` and spoofable source address alone.
- Consider tightening `acceptRecvErrorConfig` so that it is disabled by default for established, authenticated tunnels and only used during connection setup, minimizing the state-poisoning window.

### Proof of Concept
1. Establish two nebula nodes A and B with a completed handshake and active tunnel (data plane confirmed working).
2. As attacker C (no CA-issued certificate for this network), observe or infer B's `RemoteIndex` value as seen by A (visible in plaintext header of any UDP packet from B to A) and B's UDP source address/port.
3. Craft a raw UDP packet with header type `header.RecvError`, `RemoteIndex` set to the observed value, spoofing the source address to match B's known UDP endpoint, and send it to A.
4. A's `readOutsidePackets` routes this into `handleRecvError` without decryption; the address check passes (spoofed source matches), and A calls `f.closeTunnel(hostinfo)`, tearing down the live, authenticated tunnel and deleting pending hostinfo state — achieved entirely without holding any valid certificate or completing a handshake as B. func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
