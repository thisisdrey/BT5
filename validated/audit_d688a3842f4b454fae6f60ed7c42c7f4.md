## Finding

### Title
Leaked `EntryBytesBudget` reservation on PoH recording failure causes premature `MaxHeightReached` and reduced block capacity - (File: `core/src/banking_stage/consumer.rs`)

### Summary
The reported bug class is a "debit without corresponding credit-back" accounting error: `reduce_position` decremented `position.margin_amount` but never added the reduced amount back to `self.margin[...]`, permanently stranding funds. The Agave analog is in the leader's block-packing path: `EntryBytesBudget::reserve()` is called to reserve slot-entry-byte capacity before recording a transaction batch, but if the subsequent PoH recording attempt fails, the reserved bytes are never released back to the budget, while the transaction's *cost-tracker* accounting **is** correctly rolled back via `remove_added_transaction_costs`. This asymmetry means the entry-bytes budget for the slot is decremented (consumed) but never credited back on failure.

### Finding Description
In `execute_and_commit_transactions_locked` in `core/src/banking_stage/consumer.rs`, the entry-bytes budget is reserved just before invoking the PoH recorder: [1](#0-0) 

If recording fails for any reason, the code only reverses the cost-tracker bookkeeping via `remove_added_transaction_costs`, and never releases the bytes previously reserved from `bank.entry_bytes_budget()`: [2](#0-1) [3](#0-2) 

`EntryBytesBudget` itself exposes only a monotonically-increasing `reserve()` operation; there is no `release`/`unreserve` method anywhere in the codebase, and the consumed counter is only reset by constructing a brand-new `EntryBytesBudget` at the start of the next slot: [4](#0-3) [5](#0-4) 

Critically, PoH recording can fail for reasons other than genuine end-of-slot. `TransactionRecorder::record_transactions` maps a full or disconnected record channel to `PohRecorderError::ChannelFull` / `ChannelDisconnected`, and only `RecordSenderError::InactiveBankId`/`Shutdown` map to `MaxHeightReached`: [6](#0-5) 

This means a transient condition — the bounded record channel being momentarily full under heavy transaction load, which an unprivileged user can induce simply by saturating the leader with transactions via the normal ingest path — triggers the code path at consumer.rs:397 that reserves entry bytes for the batch, fails to record, reverses the cost-tracker state, but leaves the entry-bytes reservation permanently "spent" for the remainder of the slot. Because the bank/slot is not necessarily frozen or ended when this happens (unlike the true `MaxHeightReached` case), subsequent legitimate batches within the *same slot* will call `reserve()` again, compounding the leaked consumption. Once `entry_bytes_consumed` in `EntryBytesBudget` (a slot-scoped counter reset only on `Bank::new_from_parent`) accumulates enough leaked reservations, `reserve()` starts returning `ExceedsSlotLimit` — which is translated to `PohRecorderError::MaxHeightReached` — well before the slot's actual recorded-entry byte usage approaches `DEFAULT_MAX_ENTRY_BYTES_PER_SLOT` (20 MiB), or the shorter values used under slot-time-reduction feature gates.

### Impact Explanation
The effect is a self-inflicted, repeatable reduction of the leader's own block capacity: transactions that would otherwise fit within the slot's entry-bytes budget get spuriously rejected with `MaxHeightReached` once enough of the budget has been "leaked" by earlier failed (non-recorded) attempts, even though the entries were never actually written to PoH. This degrades transaction throughput for the affected leader slot and can be repeatedly triggered by an unprivileged sender who causes record-channel congestion (e.g., high-rate transaction submission), each failed record attempt (`ChannelFull`) draining budget that is never returned.

### Likelihood Explanation
This requires only ordinary transaction volume causing transient channel back-pressure on the bounded record channel — no special privileges, no malicious payload crafting, and no interaction with validator/operator-only code paths. Given sustained load, `ChannelFull` is a realistically reachable condition in `TransactionRecorder::record_transactions`, and every occurrence permanently consumes the reserved `entry_bytes` for that batch attempt for the rest of the slot.

### Recommendation
Add a corresponding "release"/"give back" operation to `EntryBytesBudget` (mirroring `CostTracker::remove`) and call it from the recording-failure branch in `execute_and_commit_transactions_locked` alongside `Self::remove_added_transaction_costs(bank, &transaction_costs)`, so that a failed (non-`MaxHeightReached`, or even `MaxHeightReached` originating purely from this reservation) recording attempt does not permanently consume slot entry-byte capacity that was never actually used for recorded entries.

### Proof of Concept
Not independently executed; the flaw is demonstrated by static code inspection: `EntryBytesBudget::reserve` has no paired decrement/release method anywhere in the codebase, and the only call site (`core/src/banking_stage/consumer.rs:371-380`) reserves unconditionally before recording, while the failure branch (`consumer.rs:397-414`) reverses cost-tracker state but omits any entry-bytes reversal. Combined with `TransactionRecorder::record_transactions` mapping transient `RecordSenderError::Full`/`Disconnected` conditions to non-`MaxHeightReached... ` wait: actually `Full`/`Disconnected` map to `ChannelFull`/`ChannelDisconnected` respectively (not `MaxHeightReached`), confirming recording can fail for reasons unrelated to true slot exhaustion, per `poh/src/transaction_recorder.rs:52-93`. I was unable to trace whether `consume_worker.rs`'s retry logic on `ChannelFull` reuses the same `entry_bytes` value on retry (which would compound the leak further); this would need to be confirmed by a background agent with full repository/test access.

#[derive(Debug)]
pub struct EntryBytesBudget {
    consumed: AtomicU64,
    slot_limit: u64,
}

impl EntryBytesBudget {
    pub const fn new(slot_limit: u64) -> Self {
        Self {
            consumed: AtomicU64::new(0),
            slot_limit,
        }
    }

    pub const fn slot_limit(&self) -> u64 {
        self.slot_limit
    }

    pub fn reserve(&self, bytes: u64) -> std::result::Result<(), EntryBytesReserveError> {
        loop {
            let current = self.consumed.load(Ordering::Acquire);
            let next = current.saturating_add(bytes);
            if next > self.slot_limit {
                return Err(EntryBytesReserveError::ExceedsSlotLimit);
            }

            if self
                .consumed
                .compare_exchange(current, next, Ordering::AcqRel, Ordering::Acquire)
                .is_ok()
            {
                return Ok(());
            }
        }
    }
}

    pub fn record_transactions(
        &self,
        bank_id: BankId,
        transactions: Vec<VersionedTransaction>,
    ) -> RecordTransactionsSummary {
        let mut record_transactions_timings = RecordTransactionsTimings::default();
        let mut starting_transaction_index = None;

        if !transactions.is_empty() {
            let (hash, hash_us) = measure_us!(hash_transactions(&transactions));
            record_transactions_timings.hash_us = Saturating(hash_us);

            let (res, poh_record_us) = measure_us!(self.record(bank_id, hash, transactions));
            record_transactions_timings.poh_record_us = Saturating(poh_record_us);

            match res {
                Ok(starting_index) => {
                    starting_transaction_index = starting_index;
                }
                Err(RecordSenderError::InactiveBankId | RecordSenderError::Shutdown) => {
                    return RecordTransactionsSummary {
                        record_transactions_timings,
                        result: Err(PohRecorderError::MaxHeightReached),
                        starting_transaction_index: None,
                    };
                }
                Err(RecordSenderError::Full) => {
                    return RecordTransactionsSummary {
                        record_transactions_timings,
                        result: Err(PohRecorderError::ChannelFull),
                        starting_transaction_index: None,
                    };
                }
                Err(RecordSenderError::Disconnected) => {
                    return RecordTransactionsSummary {
                        record_transactions_timings,
                        result: Err(PohRecorderError::ChannelDisconnected),
                        starting_transaction_index: None,
                    };
                }
            }
        }
