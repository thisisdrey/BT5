### Title
Protocol fee bypass on `Nep245`/`Imt` token diffs via unit-splitting across multiple `TokenDiff` intents in one batch - (`contracts/defuse/core/src/intents/token_diff.rs`)

### Summary
`TokenDiff::execute_intent` computes and collects the protocol fee independently for each individual `TokenDiff` intent, using `Self::token_fee(token_id, amount, fee)` which explicitly zeroes the fee for `Nep245`/`Imt`/`Nep171` tokens whenever the *per-intent* magnitude of the negative delta is `<= 1`. An unprivileged signer can pack `N` separate `TokenDiff` intents (or `N` signed payloads) into a single `execute_intents` call, each moving `-1` unit of the same `Nep245` token, instead of one intent moving `-N` units, and pay zero fee on all `N` units instead of `Pips::fee_ceil(fee, N)`.

### Finding Description
Binding claimed by the protocol design (and required for correct fee accounting): for token `T`, `sum(fees_collected_for_T_over_the_batch) == Pips::fee_ceil(protocol_fee, |aggregate_negative_delta_of_T_by_signer_in_batch|)`.

What the code actually enforces is strictly per-`TokenDiff`-intent: [1](#0-0) 

and the per-intent fee for a negative delta is: [2](#0-1) 

`token_fee` explicitly returns `Pips::ZERO` for `Nep171`/`Nep245`/`Imt` token types whenever `amount <= 1`, regardless of the configured `protocol_fee`. This exemption is applied per intent, not per aggregate flow of the token by the signer across the whole executed batch.

A single `MultiPayload` can carry many `TokenDiff` intents (`DefuseIntents.intents: Vec<Intent>`), all executed under one signature/nonce: [3](#0-2) [4](#0-3) 

and/or many separately signed `MultiPayload`s in one `execute_signed_intents` call: [5](#0-4) 

Cross-intent netting only happens at the `TransferMatcher`/`Deltas` level for actual token movement (balances), completely separate from fee computation, which already happened and was credited per intent inside `execute_intent`: [6](#0-5) 

Exploit: attacker signs one payload with `N=1000` `TokenDiff` intents, each `diff = {nep245_token_T: -1}`. A counterparty (or the attacker's own second account) supplies a single `TokenDiff` intent `diff = {nep245_token_T: +1000}` (positive deltas never pay fee, per `supply_delta`'s `else { Some(delta) }` branch and `execute_intent`'s `if *delta < 0` guard). The batch balances to zero and is accepted. Fee collected = `1000 * token_fee(T, 1, fee).fee_ceil(1) = 1000 * 0 = 0`, whereas expressing the same net transfer as one `TokenDiff{T: -1000}` intent yields `token_fee(T, 1000, fee).fee_ceil(1000) = protocol_fee.fee_ceil(1000)` (nonzero for any nonzero `protocol_fee`).

No existing guard prevents this: `execute_intent` only rejects `delta == 0` per token within a single intent, `MultiPayload::verify`/nonce/salt checks only bind the payload's authenticity, not the number or granularity of `TokenDiff` intents it carries, and there is no cross-intent aggregation before invoking `Pips::fee_ceil`.

### Impact Explanation
Value that should have flowed to `fee_collector` (protocol fees, from the signer's own negative-delta legs on `Nep245`/`Imt` tokens) is never credited; the attacker (or any pair of colluding/self-controlled accounts) permanently avoids the protocol fee that would otherwise apply on the aggregate amount. This matches the Critical category "protocol fees bypassed." It is fully repeatable across accounts, tokens (any `Nep245`/`Imt` token id), and batches, and scales linearly with the number of unit-sized `TokenDiff` legs the attacker is willing to include (bounded only by gas/tx size, which is a cost borne by the attacker, not a blocker).

### Likelihood Explanation
No privileged role is required — any signer with a `Nep245`/`Imt` balance in the Verifier and a willing (or self-controlled) counterparty for the offsetting positive delta can perform this. The only cost is the extra intents (more JSON/gas), which is cheap relative to the fee saved when `protocol_fee` and/or the traded amount is large. It requires no special timing, races, or victim cooperation beyond normal trade matching.

### Recommendation
Aggregate the negative-delta magnitude per `(signer, token_id)` across the whole batch (all `TokenDiff` intents in the `DefuseIntents`/across all signed payloads processed by `execute_signed_intents`) before applying `token_fee`/`fee_ceil`, or otherwise apply the `amount <= 1` NFT/MT fee exemption only when the token is verified to be a genuinely non-fungible, single-instance asset (e.g., restrict it to `Nep171`, and for `Nep245`/`Imt` compute the fee on the aggregate signer flow for that `token_id` within the batch rather than per-intent).

### Proof of Concept
`cargo test` (workspace `tests` crate, sandbox), sketch:
1. Deploy Verifier with `protocol_fee = Pips::ONE_PERCENT` and a fee collector account.
2. Create a `Nep245` multi-token contract, deposit `1000` units of `token_T` to attacker's Verifier balance, and `0` to counterparty.
3. Build batch A: one `TokenDiff{T: -1000, out_token: +X}` signed by attacker vs matching counterparty intent — assert collected fee for `T` equals `Pips::ONE_PERCENT.fee_ceil(1000)` (nonzero).
4. Build batch B: 1000 `TokenDiff` intents each `{T: -1, out_token_i: +x}` (or a single counter-intent `{T: +1000}`) packed into one signed `DefuseIntents`/`execute_intents` call — assert collected fee credited to `fee_collector` for `T` is `0`, not `Pips::ONE_PERCENT.fee_ceil(1000)`.
5. Assert the two batches move the same net `1000` units of `T` out of attacker's balance, proving identical economic effect with divergent fee outcomes — demonstrating the bypass.

    // Finalizes all transfers, or returns unmatched deltas.
    // If unmatched deltas overflow, then Err(None) is returned.
    pub fn finalize(self) -> Result<Transfers, InvariantViolated> {
        let mut transfers = Transfers::default();
        let mut deltas = TokenDeltas::default();
        for (token_id, transfer_matcher) in self.0 {
            if let Err(unmatched) = transfer_matcher.finalize_into(&token_id, &mut transfers)
                && (unmatched == 0 || deltas.apply_delta(token_id, unmatched).is_none())
            {
                return Err(InvariantViolated::Overflow);
            }
        }
        if !deltas.is_empty() {
            return Err(InvariantViolated::UnmatchedDeltas {
                unmatched_deltas: deltas,
            });
        }
        Ok(transfers)
    }
