### Title
Emissions during zero-supply windows are silently burned — reward tokens permanently stuck in `RewardsDistributor` - (File: `contracts/RewardsDistributor.sol`)

### Summary
`RewardsDistributor` accrues emissions continuously via a per-second `tokenSpeed`, but `_calculateTokenIndex()` returns a zero index delta whenever the reward-bearing token's `totalSupply()` is 0, while still advancing the stored `timestamp`. All reward tokens emitted during any window with zero supply are therefore never attributable to any account and remain locked in the contract with no recovery function. This is the same bug class as the Truflation `VirtualStakingRewards` report: rewards emitted while nobody is staked are irretrievable.

### Finding Description
The relevant logic is in `_calculateTokenIndex` at `contracts/RewardsDistributor.sol:197-212`:

```solidity
uint256 _deltaTimestamps = block.timestamp - uint256(_supplyState.timestamp);
if (_deltaTimestamps > 0 && _speed > 0) {
    uint256 _totalSupply = token_.totalSupply();
    uint256 _tokensAccrued = _deltaTimestamps * _speed;
    uint256 _ratio = _totalSupply > 0 ? _tokensAccrued.wadDiv(_totalSupply) : 0;
    _newIndex = (_supplyState.index + _ratio).toUint224();
    _newTimestamp = block.timestamp.toUint32();
}
```

When `token_.totalSupply() == 0`, `_ratio = 0` but `_newTimestamp` is still set to `block.timestamp` by `_updateTokenIndex()` (`RewardsDistributor.sol:271-282`). The elapsed `deltaTimestamps * speed` emissions for that window are erased: the index does not grow, and the timestamp resets, so the reward tokens that were notionally emitted during the empty-supply period can never be credited to anyone.

Concretely:

1. Governor (or Vesper sync via `syncTokenSpeed`) sets a nonzero `tokenSpeed` for a `DepositToken`/`DebtToken`.
2. The last holder fully withdraws/repays, so `token.totalSupply()` becomes 0 while `tokenSpeed` is still nonzero.
3. Time passes. Every call to `updateBeforeMintOrBurn`, `updateBeforeTransfer`, or `claimRewards` updates `timestamp` with `_ratio = 0`, discarding `deltaTimestamps * speed` reward tokens.
4. When a new staker joins, their accrued rewards start counting only from the new `timestamp`; all tokens emitted during the empty window remain in `RewardsDistributor` unclaimable by anyone.
5. `_transferRewardIfEnoughTokens` (`RewardsDistributor.sol:248-256`) is the only token outflow and only pays `tokensAccruedOf[account_]`; there is no sweep/recovery function, so the stranded balance is permanently locked.

Worse, the empty window's emissions are not even deferred — in Synthetix-style accounting the pre-supply emissions would roll forward into the next index accrual. Here they are truncated to zero, so the funds are stranded rather than redistributed to the next depositor.

### Impact Explanation
Reward tokens (e.g., the configured `rewardToken`) deposited into `RewardsDistributor` to fund emissions are permanently frozen whenever a rewarded token experiences any zero-supply interval while its speed is nonzero — including the period between speed activation and the first deposit, and after full exits. The impact is permanent freezing of unclaimed yield, proportional to `speed × duration of empty-supply windows`.

### Likelihood Explanation
Zero-supply windows are common: a newly registered reward token before its first deposit, or a market where all users exit collateral or repay all debt while emissions remain enabled. Any unprivileged user touching the contract (or the token hooks firing on mint/burn/transfer) advances the timestamp and cements the loss — the funds cannot be recovered by anyone. No attacker action is strictly required, but a griefing-free trigger is enough to make this a genuine fund-freezing flaw rather than an attack; severity is medium, matching the source report.

### Recommendation
Do not advance `_supplyState.timestamp` (or defer the accrual) when `_totalSupply == 0`, so emitted-but-undistributed rewards roll into the next nonzero-supply accrual instead of being dropped:

```solidity
if (_deltaTimestamps > 0 && _speed > 0) {
    uint256 _totalSupply = token_.totalSupply();
    if (_totalSupply == 0) return (0, 0); // keep timestamp; defer emissions
    ...
}
```

Alternatively, add an owner/governor-controlled sweep for undistributed reward balance.
