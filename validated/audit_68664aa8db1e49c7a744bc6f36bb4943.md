### Title
Unauthenticated stage-1 handshake packets force expensive Noise processing with no completion guarantee, enabling asymmetric-cost resource exhaustion - (File: handshake_manager.go)

### Summary
The GFX report describes an economic asymmetry: the `LimitOrderRegistry` owner spends real, non-refundable resources (gas to fulfill an order) before the counterparty (the user) is obligated to pay anything, and if the user simply abandons the flow, the owner has no way to recover the sunk cost. `HandshakeManager.beginHandshake` in Nebula has the identical asymmetric-cost shape at the network-protocol layer: any UDP sender (no CA-signed certificate required) can send a stage-1 handshake packet, and the responder allocates a `handshake.Machine`, runs `noise.ReadMessage` (an elliptic-curve Diffie-Hellman computation), and processes payload/cert-recombination logic — all before the peer has proven possession of a certificate the responder trusts. If the sender never follows through (spoofed source, or simply drops the flow after triggering the work), the responder has already paid the full cryptographic cost with no way to reclaim it, and nothing stops the same unauthenticated sender from repeating this indefinitely against many spoofed or unreachable "fake users."

### Finding Description
`HandshakeManager.HandleIncoming` gates a stage-1 packet (`MessageCounter == 1`) only on:
1. `h.Subtype` being a supported subtype,
2. the underlay remote-allow list (`AllowUnknownVpnAddr`), and
3. `RemoteIndex == 0`. [3](#0-2) 

None of these checks require the sender to prove any certificate ownership or perform comparable work. Once past them, `beginHandshake` unconditionally constructs a new `handshake.Machine` and calls `machine.ProcessPacket(nil, packet)`, which invokes `m.hs.ReadMessage(...)` — the Noise DH computation — prior to any certificate validation: [4](#0-3) [5](#0-4) 

Certificate verification (`validateCert`, which calls the CA-pool `verifier`) only happens after the DH step already succeeded, and even then only for the message pattern's payload-bearing stage: [6](#0-5) 

Because the DH computation is not preceded by any anti-amplification mechanism (no cookie, no proof-of-work, no per-source rate limit — confirmed absent in `handshake_manager.go` and `outside.go`), the responder incurs the full cost of the cryptographic step for every stage-1 packet it receives, regardless of whether the sender is a legitimate, certificate-holding peer or a completely unauthenticated attacker who never intends to complete the handshake. This mirrors the GFX finding precisely: the party doing useful work (owner / responder) bears a real, unrecoverable cost up front; the counterparty (user / attacker) can walk away at zero cost, at scale.

### Impact Explanation
An attacker with no valid Nebula certificate can trigger unbounded per-packet elliptic-curve computation on any reachable node by sending spoofed or throwaway stage-1 packets, without ever completing a handshake or being charged any cost. At sufficient volume this degrades or exhausts responder CPU, denying service to legitimate peers — a remote resource-exhaustion / DoS impact, directly analogous to the "owner incurs unrecoverable cost, attacker/user pays nothing" pattern in the source report.

### Likelihood Explanation
Likely reachable by any network-adjacent, unauthenticated attacker: sending a UDP stage-1 handshake packet requires no certificate, no prior handshake state, and can be trivially scripted or spoofed, since the source address is attacker-controlled at the underlay layer and only checked against a remote allow list (which most deployments leave permissive/default).

### Recommendation
Introduce a stateless anti-amplification defense before performing the Noise DH step in `beginHandshake` — e.g., a responder cookie/puzzle exchanged prior to running `ProcessPacket`, or a per-source-address rate limit on stage-1 handshake initiation — so an unauthenticated sender cannot force expensive cryptographic work at will without incurring comparable cost itself.

### Proof of Concept
1. Stand up a Nebula node with a normal certificate/CA configuration.
2. From an attacker host with no Nebula certificate, craft raw UDP packets matching the header shape validated in `readOutsidePackets`/`HandleIncoming` (`Type=Handshake`, `Subtype=HandshakeIXPSK0`, `MessageCounter=1`, `RemoteIndex=0`) carrying an arbitrary/garbage Noise `msg1` payload, as done for test injection in `TestHandshakeMessageCounter0Dropped`/`TestHandleIncomingDispatch` ( [7](#0-6) [8](#0-7) ).
3. Send a high volume of such packets from many spoofed source addresses; each one passes the `RemoteIndex==0` and allow-list checks and reaches `beginHandshake`, which allocates a `handshake.Machine` and performs `noise.ReadMessage` for every packet.
4. Observe responder CPU usage rise proportionally to attacker-sent packet volume, with zero cost or state ever kept by the attacker, since no completion is required.

func (hm *HandshakeManager) HandleIncoming(via ViaSender, packet []byte, h *header.H) {
	// Gate on known handshake subtypes. Unknown subtypes (or future ones we
	// don't yet support) are dropped here rather than silently routed through
	// the IX path. Add a case when introducing a new pattern.
	switch h.Subtype {
	case header.HandshakeIXPSK0:
		// supported
	default:
		hm.l.Debug("dropping handshake with unsupported subtype",
			"from", via, "subtype", h.Subtype)
		return
	}

	// First remote allow list check before we know the vpnIp
	if !via.IsRelayed {
		if !hm.lightHouse.GetRemoteAllowList().AllowUnknownVpnAddr(via.UdpAddr.Addr()) {
			hm.l.Debug("lighthouse.remote_allow_list denied incoming handshake", "from", via)
			return
		}
	}

	// First message of a new handshake. The wire format requires RemoteIndex
	// to be zero here (the initiator has no responder index to fill in yet),
	// and generateIndex never allocates 0, so any non-zero RemoteIndex on a
	// stage-1 packet is malformed or someone probing for an index collision.
	// Drop without paying the cost of running noise on a pending Machine.
	if h.MessageCounter == 1 {
		if h.RemoteIndex != 0 {
			hm.l.Debug("dropping stage-1 handshake with non-zero RemoteIndex",
				"from", via, "remoteIndex", h.RemoteIndex)
			return
		}
		hm.beginHandshake(via, packet, h)
		return
	}

func (hm *HandshakeManager) beginHandshake(via ViaSender, packet []byte, h *header.H) {
	f := hm.f
	cs := f.pki.getCertState()

	v := cs.DefaultVersion()
	if cs.GetCredential(v) == nil {
		f.l.Error("Unable to handshake with host because no certificate is available",
			"from", via, "certVersion", v)
		return
	}

	machine, err := handshake.NewMachine(
		v, cs.GetCredential,
		hm.certVerifier(), func() (uint32, error) { return generateIndex(f.l) },
		false, header.HandshakeIXPSK0,
	)
	if err != nil {
		f.l.Error("Failed to create handshake machine", "from", via, "error", err)
		return
	}

	response, result, err := machine.ProcessPacket(nil, packet)
	if err != nil {
		f.l.Error("Failed to process handshake packet", "from", via, "error", err)
		return
	}

func (m *Machine) ProcessPacket(out, packet []byte) ([]byte, *Result, error) {
	if m.failed {
		return nil, nil, ErrMachineFailed
	}
	if len(packet) < header.Len {
		return nil, nil, ErrPacketTooShort
	}
	// Reject packets whose subtype doesn't match the one this Machine was
	// built for. A pending handshake that suddenly receives a different
	// subtype on its index is either a stray packet that matched by chance
	// or a peer protocol violation; drop it without failing the Machine so
	// the legitimate retransmit can still complete.
	if header.MessageSubType(packet[1]) != m.subtype {
		return nil, nil, ErrSubtypeMismatch
	}
	if m.result.Initiator && m.hs.MessageIndex() == 0 {
		m.failed = true
		return nil, nil, ErrInitiateNotCalled
	}

	// The (eKey, dKey) ordering here is correct for IX, where the initiator
	// completes the handshake by reading the responder's stage-2 message.
	// noise returns (cs1, cs2) where cs1 is the initiator->responder cipher.
	// For 3-message patterns where a responder finishes by reading the final
	// message, this ordering would be wrong; revisit when XX/pqIX lands.
	msg, eKey, dKey, err := m.hs.ReadMessage(nil, packet[header.Len:])
	if err != nil {
		// Noise ReadMessage failed. The noise library checkpoints and rolls back
		// on failure, so the Machine is still alive. The caller can retry with
		// a different packet.
		return nil, nil, fmt.Errorf("noise ReadMessage: %w", err)
	}

func (m *Machine) validateCert(payload Payload) error {
	cred := m.getCred(m.myVersion)
	if cred == nil {
		m.failed = true
		return fmt.Errorf("%w: %v", ErrNoCredential, m.myVersion)
	}
	rc, err := cert.Recombine(
		cert.Version(payload.CertVersion),
		payload.Cert,
		m.hs.PeerStatic(),
		cred.Cert.Curve(),
	)
	if err != nil {
		m.failed = true
		return fmt.Errorf("recombine cert: %w", err)
	}

	if !bytes.Equal(rc.PublicKey(), m.hs.PeerStatic()) {
		m.failed = true
		return ErrPublicKeyMismatch
	}

	// Version negotiation, if the peer sent a different version and we have it, switch
	if rc.Version() != m.myVersion {
		if m.getCred(rc.Version()) != nil {
			m.myVersion = rc.Version()
		}
	}

	verified, err := m.verifier(rc)
	if err != nil {
		m.failed = true
		return fmt.Errorf("verify cert: %w", err)
	}

	m.result.RemoteCert = verified
	m.remoteCertSet = true
	return nil
