### Title
Non-canonical IPv6 encodings (NAT64 / IPv4-compatible) bypass `PeerAddress::is_in_private_range()`, letting a malicious StackerDB contract point nodes at internal targets - (File: `stacks-common/src/types/net.rs`)

### Summary
`PeerAddress::is_in_private_range()` is the single equality check the p2p/StackerDB code relies on to decide "is this address internal/unroutable, and therefore must be dropped or ignored." Just like the `dssrf` advisory shows for `is_url_safe`, this check only recognizes one canonical IPv6 encoding of a private/loopback address (`fc00::/7` and `::1`) and fails to recognize other IPv6 encodings that resolve to the very same private/loopback IPv4 host (NAT64 `64:ff9b::/96` and the deprecated IPv4-compatible `::a.b.c.d` form). That breaks the equality "private-looking address == treated as private," letting an attacker-controlled StackerDB smart contract smuggle a private/loopback destination past the filter used in `eval_hint_replicas`.

### Finding Description
`PeerAddress::is_in_private_range()`:
```
stacks-common/src/types/net.rs:201-213
pub fn is_in_private_range(&self) -> bool {
    if self.is_ipv4() {
        self.0[12] == 10
            || (self.0[12] == 172 && self.0[13] >= 16 && self.0[13] <= 31)
            || (self.0[12] == 192 && self.0[13] == 168)
            || self.0[12] == 127
    } else {
        // private address (fc00::/7) or localhost (::1)
        self.0[0] >= 0xfc || (self.0[0..15] == [0u8; 15] && self.0[15] == 1)
    }
}
```
`is_ipv4()` only recognizes the canonical `::ffff:0:0/96` mapped-IPv4 prefix (`stacks-common/src/types/net.rs:80-97`, checking bytes `0..12 == [.., 0xff, 0xff]`). Any other IPv6 encoding that embeds an IPv4 address falls into the `else` branch, which only checks `fc00::/7` (ULA) and the exact 16-byte `::1` pattern.

This means the following addresses are **not** classified as private, even though they encode a private/loopback IPv4 destination or a local IPv6 address:
- NAT64 well-known prefix `64:ff9b::7f00:1` (encodes `127.0.0.1`) - first byte is `0x00`, fails both branches.
- NAT64 local-use `64:ff9b:1::10.0.0.1` (RFC 8215, encodes an RFC1918 address) - same gap.
- IPv4-compatible IPv6 `::127.0.0.1` / `::10.0.0.1` (deprecated but still parseable) - all-zero prefix except the trailing IPv4 octets, so it neither matches `is_ipv4()` (wrong prefix) nor the `::1` exact-match check.
- Deprecated site-local `fec0::1` happens to be caught incidentally because `0xfec0` byte0 `0xfe >= 0xfc`, so that one is not exploitable here, but the NAT64/compat gap above is real and unguarded.

This filter is the security-relevant gate in `eval_hint_replicas`, which parses `hint-replicas` entries out of an on-chain StackerDB smart-contract config -- fully attacker-controlled data, since anyone can deploy a contract:
```

...

```
The 16 raw address bytes come directly from a Clarity list supplied in the contract (`stackslib/src/net/stackerdb/config.rs:289-320`), so an attacker fully controls the byte pattern, including choosing a NAT64/IPv4-compatible encoding of `127.0.0.1`, `169.254.169.254`, `10.0.0.1`, etc. Because the filter fails open for these encodings, the "private" hint replica is accepted and pushed into `hint_replicas`, which subsequently becomes a `NeighborAddress` that the StackerDB sync/neighbor-walk machinery will treat as a legitimate, non-private replica to add to the frontier and attempt to contact (`stackslib/src/net/stackerdb/sync.rs`, `stackslib/src/net/neighbors/walk.rs` use the same `is_in_private_range` gate at `stackslib/src/net/neighbors/walk.rs:693-695` to decide whether a reported address should be trusted/kept).

The equality being broken is exactly the one flagged in the external report: "this IPv6 bit pattern resolves to a private/loopback host" vs. "our filter recognizes it as private." Every code path that relies on `is_in_private_range()` as an SSRF/internal-network guard (StackerDB hint-replica filtering, and the private-neighbor gate reused by neighbor-walk address correction) inherits the gap.

### Impact Explanation
An unprivileged attacker who can deploy a Clarity contract (permissionless) can register a StackerDB config whose `hint-replicas` list contains a NAT64-encoded or IPv4-compatible-encoded loopback/link-local/RFC1918 address. Nodes that load this contract's StackerDB config will not filter it out as private, and will carry it forward as a normal, routable-looking replica address into their neighbor/StackerDB replica set. Whether this culminates in an actual outbound TCP connection to the embedded internal address depends on OS/network NAT64 behavior, but the classification step itself -- which is supposed to be the authoritative "is this internal" check -- is provably wrong for these inputs, and the same broken predicate is reused for the neighbor-address trust decision in `walk.rs`. This matches the "steering a node's view of the network via a mis-served/mis-trusted address" class of High-impact issue (non-canonical data treated as canonical), rather than a pure network-layer SSRF.

### Likelihood Explanation
Likelihood is moderate-to-high for the classification bug itself: crafting the 16 raw bytes for a NAT64 or IPv4-compatible encoding is trivial and requires no special privilege, only the ability to deploy any Clarity contract and register it as a StackerDB config, which is a normal, permissionless action in this codebase's threat model (`eval_hint_replicas` explicitly exists to sanitize contract-supplied data, and it fails to sanitize these specific encodings).

### Recommendation
Fix `PeerAddress::is_in_private_range()` (and its sibling helpers such as `is_loopback()`/`is_anynet()`) to canonicalize IPv6 addresses before classifying them: detect and unwrap NAT64 well-known/local-use prefixes (`64:ff9b::/96`, `64:ff9b:1::/48`) and IPv4-compatible addresses (`::a.b.c.d`, excluding `::` and `::1`), then re-run the IPv4 private-range check against the unwrapped address, in addition to covering `fe80::/10` explicitly rather than relying on incidental overlap with the `>= 0xfc` check. Apply the same canonicalization anywhere a remote-supplied `PeerAddress`/URL host is checked against "is this private" (i.e., `eval_hint_replicas` in `stackslib/src/net/stackerdb/config.rs` and the neighbor-address correction logic in `stackslib/src/net/neighbors/walk.rs`).

### Proof of Concept
1. Deploy any Clarity contract implementing the StackerDB trait, with a `hint-replicas` entry whose `addr` list encodes the bytes for `64:ff9b::7f00:1` (i.e. `[0x00,0x64,0xff,0x9b,0x00,0x00,0x00,0x00,0x00,0x00,0x00,0x00,0x7f,0x00,0x00,0x01]`) and a valid `port`/`public-key-hash`.
2. Register this contract as a StackerDB config source (as done in existing tests, e.g. `stackslib/src/net/stackerdb/tests/config.rs`).
3. Call `StackerDBConfig::eval_hint_replicas` (or the higher-level config-eval path in `stackslib/src/net/stackerdb/config.rs`) with this contract's hint-replica data.
4. Observe that `PeerAddress::is_in_private_range()` returns `false` for these bytes (unlike the equivalent `PeerAddress::from_ipv4(127,0,0,1)`, which correctly returns `true`), so the entry is *not* skipped and is added to the returned `hint_replicas` vector -- demonstrating the classification bypass that downstream code relies on to reject private/internal addresses.     /// Evaluate contract-given hint-replicas
    fn eval_hint_replicas(
        contract_id: &QualifiedContractIdentifier,
        hint_replicas_list: Vec<ClarityValue>,
    ) -> Result<Vec<NeighborAddress>, NetError> {
        let mut hint_replicas = vec![];
        for hint_replica_value in hint_replicas_list.into_iter() {
            let hint_replica_data = hint_replica_value.expect_tuple()?;

            let addr_byte_list = hint_replica_data
                .get("addr")
                .expect("FATAL: missing 'addr'")
                .clone()
                .expect_list()?;
            let port = hint_replica_data
                .get("port")
                .expect("FATAL: missing 'port'")
                .clone()
                .expect_u128()?;
            let pubkey_hash_bytes = hint_replica_data
                .get("public-key-hash")
                .expect("FATAL: missing 'public-key-hash")
                .clone()
                .expect_buff_padded(20, 0)?;

            let mut addr_bytes = vec![];
            for byte_val in addr_byte_list.into_iter() {
                let byte = byte_val.expect_u128()?;
                if byte > (u8::MAX as u128) {
                    let reason = format!(
                        "Contract {} stipulates an addr byte above u8::MAX",
                        contract_id
                    );
                    warn!("{}", &reason);
                    return Err(NetError::InvalidStackerDBContract(
                        contract_id.clone(),
                        reason,
                    ));
                }
                addr_bytes.push(byte as u8);
            }
            if addr_bytes.len() != 16 {
                let reason = format!(
                    "Contract {} did not stipulate a full 16-octet IP address",
                    contract_id
                );
                warn!("{}", &reason);
                return Err(NetError::InvalidStackerDBContract(
                    contract_id.clone(),
                    reason,
                ));
            }

            if port < 1024 || port > u128::from(u16::MAX - 1) {
                let reason = format!(
                    "Contract {} stipulates a port lower than 1024 or above u16::MAX - 1",
                    contract_id
                );
                warn!("{}", &reason);
                return Err(NetError::InvalidStackerDBContract(
                    contract_id.clone(),
                    reason,
                ));
            }
            // NOTE: port is now known to be in range [1024, 65535]

            let pubkey_hash_slice: &[u8; 20] = pubkey_hash_bytes
                .get(0..20)
                .and_then(|bytes| bytes.try_into().ok())
                .ok_or_else(|| {
                    let reason = format!("{contract_id} stipulates pubkey hash bytes length < 20");
                    warn!("{reason}");
                    NetError::InvalidStackerDBContract(contract_id.clone(), reason)
                })?;

            let peer_addr = PeerAddress::from_slice(&addr_bytes).expect("FATAL: not 16 bytes");
            if peer_addr.is_in_private_range() {
                debug!(
                    "Ignoring private IP address '{}' in hint-replicas",
                    &peer_addr.to_socketaddr(port as u16)
                );
                continue;
            }

            let naddr = NeighborAddress {
                addrbytes: peer_addr,
                port: port as u16,
                public_key_hash: Hash160(*pubkey_hash_slice),
            };
            hint_replicas.push(naddr);
        }
        Ok(hint_replicas)
    }
