### Title
Priority-floor bypass forces full `ed25519_verify_serial` signature verification on structurally-valid-but-unpriceable packets - ([File: core/src/sigverify.rs])

### Summary
`apply_priority_floor_to_batch` in `core/src/sigverify.rs` only drops a packet below the scheduler's priority floor if `calculate_priority_from_bytes` returns `Some(priority)`. Any packet for which pricing fails (returns `None`) is unconditionally kept (`any_kept = true`), even though the packet can still be structurally valid enough to reach real, expensive ed25519 signature verification in `sigverify::ed25519_verify_serial`. An unstaked attacker can craft packets that parse as a valid `SanitizedTransactionView` (so `verify_packet` performs actual elliptic-curve verification) but fail only at the later `transaction_configuration()` step (e.g. duplicate compute-budget instructions), guaranteeing `calculate_priority_from_bytes` returns `None` and the priority floor never discards them.

### Finding Description
The floor-check path is: [1](#0-0) 

`calculate_priority_from_bytes` computes priority by: parsing a `SanitizedTransactionView`, building a `RuntimeTransaction`, then calling `transaction_configuration(&bank.feature_set)`, and returns `None` if *any* of these three steps fails: [2](#0-1) 

`transaction_configuration()` for legacy/v0 messages runs `ComputeBudgetInstructionDetails::try_from`, which returns `Err(TransactionError::DuplicateInstruction(..))` when the compute-budget program instructions are duplicated (e.g. two `set_compute_unit_limit` instructions), independent of whether `SanitizedTransactionView` parsing succeeded: [3](#0-2) [4](#0-3) 

Critically, `verify_packet` in `perf/src/sigverify.rs` — the function actually invoked by `ed25519_verify_serial` — never calls `transaction_configuration()` at all. It only needs `SanitizedTransactionView::try_new_sanitized` to succeed, then performs a real `signature.verify(pubkey, message)` per signature, which is genuine elliptic-curve verification work regardless of whether the signature is valid: [5](#0-4) [6](#0-5) 

So an attacker can craft a packet whose message:
1. Parses successfully in `SanitizedTransactionView` (valid header/account-keys/instruction bounds), and
2. Contains duplicated compute-budget instructions (or another condition that only `transaction_configuration()`/`ComputeBudgetInstructionDetails` rejects), and
3. Carries arbitrary 64-byte "signature" blobs paired with attacker-chosen pubkeys (no need to own real keys — the verification is expected to fail, but the CPU cost is paid regardless).

For such packets, `calculate_priority_from_bytes` returns `None` → `apply_priority_floor_to_batch` falls into the `_ => any_kept = true` arm → the packet is never marked `discard` by the floor, no matter how large `floor` is or how saturated the scheduler is. The packet then proceeds unconditionally into `ed25519_verify_serial`, which performs real EC signature verification (`verify_packet`, `signature.verify(...)`) — the exact "expensive" work the priority floor exists to avoid under saturation. This is invoked from: [7](#0-6) 

The mechanism was designed to keep the floor and sigverify's cost model in agreement (`floor_priority_from_bytes_matches_typed_path` test), but that agreement only holds for packets where pricing succeeds; the "leave to downstream rejection" `None`-branch has no floor protection at all, and downstream (`ed25519_verify_serial`) does not gate on the same predicate (`transaction_configuration`) that caused the `None`.

### Impact Explanation
This is a QoS/priority-floor evasion: it allows an unstaked, unprivileged sender of TPU packets to force real ed25519 CPU verification work per crafted packet even while the scheduler is saturated and actively trying to shed low-value load via the priority floor (`SchedulerPriorityFloor`, `SaturationState`). Because the cost of constructing such a packet (bincode-serialize a message with duplicate compute-budget instructions plus junk signature bytes) is far cheaper than the elliptic-curve verification cost the leader must pay, this is a CPU amplification / underpriced pre-fee work vector against the sigverify stage, degrading verification throughput exactly when the node is trying to protect itself via the floor mechanism introduced in `core/src/sigverify.rs` / `scheduler_controller.rs`.

### Likelihood Explanation
No privileged access is required — only an open QUIC/UDP connection to the leader's TPU. Constructing a message that (a) parses as a valid `SanitizedTransactionView` and (b) fails only in `ComputeBudgetInstructionDetails::try_from` (duplicate compute-budget instruction) is straightforward and requires no valid keys or on-chain assets — the test suite itself demonstrates duplicate-instruction detection is trivial to trigger (`test_try_from_compute_unit_limit`, `test_try_from_request_heap`). This condition is reachable any time the priority floor is active (i.e., under exactly the saturation load an attacker is trying to induce/exploit), and is fully repeatable per packet.

### Recommendation
Make the floor-check and sigverify-check symmetric on failure: when `calculate_priority_from_bytes` returns `None` due to `transaction_configuration()`/sanitization failure (as opposed to a genuinely unparseable/short packet), treat the packet as droppable (assign it an effective priority of 0, or discard it directly) instead of unconditionally keeping it. Alternatively, have `verify_packet`/`ed25519_verify_serial` also validate `transaction_configuration()` (or reuse the already-computed view) before doing per-signature EC verification, so any packet that would fail `transaction_configuration()` is rejected before the expensive step, restoring the invariant that cheap-to-reject packets cannot force expensive crypto work.

fn apply_priority_floor_to_batch(
    batch: &mut PacketBatch,
    floor: u64,
    bank: &Bank,
) -> (usize, bool) {
    let mut dropped: usize = 0;
    let mut any_kept = false;
    for mut packet in batch.iter_mut() {
        if packet.meta().discard() {
            continue;
        }
        let Some(data) = packet.data(..) else {
            // Zero-length or otherwise unreadable: leave to downstream
            // stages to reject.
            any_kept = true;
            continue;
        };
        // Unparseable packets are kept and left for downstream rejection.
        match calculate_priority_from_bytes(bank, data) {
            Some(priority) if priority <= floor => {
                packet.meta_mut().set_discard(true);
                dropped = dropped.saturating_add(1);
            }
            _ => any_kept = true,
        }
    }
    (dropped, !any_kept)

fn verify_packet(packet: &mut PacketRefMut, reject_non_vote: bool, enable_tx_v1: bool) -> bool {
    // If this packet was already marked as discard, drop it
    if packet.meta().discard() {
        return false;
    }

    let Some(data) = packet.data(..) else {
        return false;
    };

    let (is_simple_vote_tx, verified) = {
        let Ok(view) = SanitizedTransactionView::try_new_sanitized(data, &sanitize_config()) else {
            return false;
        };

        if !enable_tx_v1 && matches!(view.version(), TransactionVersion::V1) {
            return false;
        }

        let is_simple_vote_tx = is_simple_vote_transaction_view(&view);
        if reject_non_vote && !is_simple_vote_tx {
            (is_simple_vote_tx, false)
        } else {
            let signatures = view.signatures();
            if signatures.is_empty() {
                (is_simple_vote_tx, false)
            } else {
                let message = view.message_data();
                let static_account_keys = view.static_account_keys();
                let verified = signatures
                    .iter()
                    .zip(static_account_keys.iter())
                    .all(|(signature, pubkey)| signature.verify(pubkey.as_ref(), message));
                (is_simple_vote_tx, verified)
            }
        }
    };

    if is_simple_vote_tx {
        packet.meta_mut().flags |= PacketFlags::SIMPLE_VOTE_TX;
    }

    verified
}

pub fn ed25519_verify_serial(batch: &mut PacketBatch, reject_non_vote: bool, enable_tx_v1: bool) {
    for mut packet in batch.iter_mut() {
        if !packet.meta().discard() && !verify_packet(&mut packet, reject_non_vote, enable_tx_v1) {
            packet.meta_mut().set_discard(true);
        }
    }
