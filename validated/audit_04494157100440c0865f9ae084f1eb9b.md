Audit Report

## Title
Missing slippage protection in Snowbridge `system-frontend` tip/fee swap allows extraction of user value via sandwich manipulation - (File: `bridges/snowbridge/pallets/system-frontend/src/lib.rs`)

## Summary
`swap_and_burn` in `pallet_system_frontend` converts a user-supplied tip/fee asset into Ether via `T::Swap::swap_exact_tokens_for_tokens(..., None, ...)`, passing `None` for `amount_out_min`. [1](#0-0)  This is reachable from the unprivileged `add_tip` extrinsic (any `ensure_signed` account) and the `register_token` extrinsic (any origin satisfying `RegisterTokenOrigin`), both of which withdraw and burn the user's asset regardless of the actual ether realized from the swap. [2](#0-1) [3](#0-2) 

## Finding Description
`do_swap_exact_tokens_for_tokens` in `pallet-asset-conversion` only checks the output against `amount_out_min` when it is `Some(_)`; when `None`, the minimum-output check is entirely skipped. [4](#0-3)  Since `swap_and_burn` always passes `None`, the AMM swap accepts whatever output the live pool reserves yield at execution time, with no floor. [5](#0-4)  Both public call paths — `add_tip` → `swap_fee_asset_and_burn` → `swap_and_burn`, and `register_token` → `swap_fee_asset_and_burn` → `swap_and_burn` — route arbitrary user-controlled amounts through this unprotected swap and then unconditionally burn the resulting `ether_gained` for teleport via `burn_for_teleport`, and use that same manipulated `ether_gained` value as the amount reported in the cross-chain `AddTip`/`RegisterToken` Transact call to BridgeHub. [6](#0-5)  An attacker with no special privilege can trade against the same `pallet-asset-conversion` pool immediately before and after the victim's transaction to depress the exchange rate, causing the victim's asset to be fully consumed while yielding a much smaller `ether_gained`, and pocketing the difference by reversing their own trade.

## Impact Explanation
This matches an allowed "runtime bug that compromises intended behavior" / "wrong payout amount" impact: the corrupted value is `ether_gained` computed in `swap_and_burn`, which becomes both the amount burned/teleported to Ethereum and the tip/registration-fee amount reported on BridgeHub via `EthereumSystemCall::AddTip { amount }` / `EthereumSystemCall::RegisterToken { amount }`. Victims lose value (full asset withdrawn, degraded ether output), and the relayer reward/registration-fee accounting on BridgeHub is under-funded relative to the user's actual contribution, without any admin, governance, or validator involvement — satisfying the unprivileged-attacker fund-loss/wrong-amount criterion.

## Likelihood Explanation
Exploitability requires only ordinary DEX sandwich mechanics against a `pallet-asset-conversion` pool between the tip/fee asset and Ether, with no special access, keys, or infrastructure control — any account able to submit `swap_exact_tokens_for_tokens` transactions can attempt this, particularly against thinly-liquid pools, making it a realistic and repeatable attack.

## Recommendation
Replace the hardcoded `None` in `swap_and_burn`'s call to `T::Swap::swap_exact_tokens_for_tokens` with a computed minimum output — e.g., via `quote_price_exact_tokens_for_tokens` plus a slippage tolerance, or by exposing an `amount_out_min` parameter on `add_tip`/`register_token` — and propagate `Some(min_out)` so the swap reverts via the existing `ProvidedMinimumNotSufficientForSwap` guard when pricing is unfavorable, before any withdrawal/burn occurs.

## Proof of Concept
1. Deploy/seed a `pallet-asset-conversion` pool between `tip_asset_location` and `ether_location` with modest liquidity.
2. Victim calls `add_tip(message_id, asset)`, intending to swap `asset` for ether via `swap_and_burn`.
3. Attacker front-runs with a large `swap_exact_tokens_for_tokens(tip_asset → ether)` to deplete the ether side of the pool.
4. Victim's `swap_and_burn` executes with `amount_out_min = None` at `substrate/frame/asset-conversion/src/lib.rs:987-1004`, succeeding despite the unfavorable price and returning a depressed `ether_gained`.
5. Attacker back-runs by reversing the swap (`ether → tip_asset`), capturing the price impact as profit.
6. Result: victim's asset is fully burned for teleport but the tip/registration amount reported to BridgeHub (`ether_gained`) is minimized — reproducible as a unit test asserting `ether_gained` is materially below the pre-attack spot-quote after simulating attacker sandwich trades around the `add_tip` call.

			tip_asset_location: Location,
			ether_location: Location,
			tip_amount: u128,
		) -> Result<u128, DispatchError> {
			// Swap tip asset to ether
			let swap_path = vec![tip_asset_location.clone(), ether_location.clone()];
			let who = T::AccountIdConverter::convert_location(&origin)
				.ok_or(Error::<T>::LocationConversionFailed)?;

			let ether_gained = T::Swap::swap_exact_tokens_for_tokens(
				who.clone(),
				swap_path,
				tip_amount,
				None, // No minimum amount required
				who,
				true,
			)?;

			// Burn the ether
			let ether_asset = Asset::from((ether_location.clone(), ether_gained));

			burn_for_teleport::<T::AssetTransactor>(&origin, &ether_asset)
				.map_err(|_| Error::<T>::BurnError)?;

			Ok(ether_gained)
		}

		fn swap_fee_asset_and_burn(
			origin: Location,
			fee_asset: Asset,
		) -> Result<u128, DispatchError> {
			let ether_location = T::EthereumLocation::get();
			let (fee_asset_location, fee_amount) = match fee_asset {
				Asset { id: AssetId(ref loc), fun: Fungible(amount) } => (loc, amount),
				_ => {
					tracing::debug!(target: LOG_TARGET, ?fee_asset, "error matching fee asset");
					return Err(Error::<T>::UnsupportedAsset.into());
				},
			};
			if fee_amount == 0 {
				return Ok(0);
			}

			let ether_gained = if *fee_asset_location != ether_location {
				Self::swap_and_burn(
					origin.clone(),
					fee_asset_location.clone(),
					ether_location,
					fee_amount,
				)
				.inspect_err(|&e| {
					tracing::debug!(target: LOG_TARGET, ?e, "error swapping asset");
				})?
			} else {
				burn_for_teleport::<T::AssetTransactor>(&origin, &fee_asset)
					.map_err(|_| Error::<T>::BurnError)?;
				fee_amount
			};
			Ok(ether_gained)
		}
