### Title
Unauthenticated `/shutdown` (and other event) endpoints in `SignerEventReceiver` allow remote DoS of the signer - (File: libsigner/src/events.rs)

### Summary
The `stacks-signer`'s HTTP event listener (`SignerEventReceiver`), which the `stacks-node` uses to push `StackerDBChunksEvent`, `BlockValidateResponse`, `BurnBlockEvent`, and `StacksBlockEvent` data, performs **no authentication whatsoever** on any incoming HTTP request. Any TCP peer that can reach the bound listening port can issue a single unauthenticated `POST /shutdown` request and immediately terminate the signer's event-processing loop.

### Finding Description
`SignerEventReceiver::next_event` in [1](#0-0)  dispatches purely on the request URL and method, with zero checks on the caller's identity, source, or any credential/header:

```rust
if request.url() == "/status" { ... }
if request.method() != &HttpMethod::Post { ... }
if request.url() == "/stackerdb_chunks") { process_event::<T, StackerDBChunksEvent>(request) }
else if request.url() == "/proposal_response" { ... }
else if request.url() == "/new_burn_block" { ... }
else if request.url() == "/shutdown" {
    event_receiver.stop_signal.store(true, Ordering::SeqCst);
    Err(EventError::Terminated)
}
``` [2](#0-1) 

There is no equivalent of the node's `auth_token`/`Authorization` header check found in the in-scope `stackslib/src/net/api/*` handlers (e.g. `postblock_v3.rs`, `blockreplay.rs`, `txsimulate.rs`, `postblock_proposal.rs`), all of which gate sensitive POST endpoints behind an `Authorization` header equality check [3](#0-2) . The signer's listener has no analogous gate at all: `decode_http_request`/`SignerHttpRequest` in `libsigner/src/http.rs` only parses method/path/headers, and `SignerEventReceiver` never inspects the `authorization` header before acting on `/shutdown`, `/stackerdb_chunks`, etc. [4](#0-3) 

Per the sample deployment configuration, the signer's listener is intended to be reachable from the node over the network (`endpoint = "127.0.0.1:30000"` on the node side referring to where it posts events) — but the actual bind address of the signer's own `HttpServer` is controlled by the signer's own `endpoint` config value, which operators may set to `0.0.0.0` (a non-loopback bind) to allow the node to reach it across hosts, as documented in `docs/signing.md` [5](#0-4) . Once bound on a non-loopback address, any remote unauthenticated client on the network can send:

```
POST /shutdown HTTP/1.1
Host: <signer-ip>:<port>
Connection: close
```

and the signer's `stop_signal` is immediately set, and `next_event` returns `Err(EventError::Terminated)`, which propagates out of the event loop and halts event processing — a full denial of service against the signer with a single unauthenticated packet.

This breaks the same class of trust-boundary equality/authorization the external report highlights (an endpoint fails open — with no comparison against any known secret at all, worse than a case-insensitive bypass) and reaches a Critical-tier impact ("remote crash/unauthenticated DoS from few messages").

### Impact Explanation
An unauthenticated, unprivileged network attacker who can reach the signer's HTTP port can:
- Terminate the signer's event-receiving loop with one `POST /shutdown`, stopping the signer from processing further `stackerdb_chunks`, `proposal_response`, `new_burn_block`, and `new_block` events pushed by the node.
- Repeat this indefinitely to keep the signer offline, degrading or halting its participation in block signing — directly affecting consensus availability, since signers are safety-critical participants in Nakamoto block finalization.

This matches the "Critical - remote crash/unauthenticated DoS from few messages" impact tier defined in scope.

### Likelihood Explanation
Likelihood is high wherever the signer's `endpoint` is bound to a non-loopback interface (which the shipped documentation explicitly supports/describes for multi-host signer/node deployments). No credentials, secret, or prior state are required — a single crafted HTTP request suffices. The attack requires no signing key, no valid StackerDB signature, and no privileged role.

### Recommendation
- Require a shared secret/token (mirroring the node's `connection_options.auth_token` pattern used in `postblock_v3.rs`/`blockreplay.rs`/`txsimulate.rs`) to be present and checked on all `SignerEventReceiver` HTTP routes, especially `/shutdown`.
- Alternatively/additionally, restrict the `/shutdown` route (and other event routes) to loopback-only by default, or require mutual TLS / IP allow-listing for non-loopback binds.
- Add explicit logging/rate-limiting for repeated unauthenticated shutdown attempts.

### Proof of Concept
1. Configure a `stacks-signer` with `endpoint = "0.0.0.0:30000"` (per `docs/signing.md` guidance for cross-host node/signer setups).
2. From a remote unprivileged host with network access to port 30000, send:
   ```
   printf 'POST /shutdown HTTP/1.1\r\nHost: victim:30000\r\nConnection: close\r\n\r\n' | nc victim-ip 30000
   ```
3. Observe that the signer's `stop_signal` is set (`libsigner/src/events.rs` lines 443-445), `next_event` returns `EventError::Terminated`, and the signer's event-processing loop halts — with no authentication check performed anywhere in the request path.

/// Returns (verb, path, table of headers, body_offset) on success
pub fn decode_http_request(payload: &[u8]) -> Result<SignerHttpRequest, EventError> {
    // realistically, there won't be more than 32 headers
    let mut headers_buf = [httparse::EMPTY_HEADER; MAX_HTTP_HEADERS];
    let mut req = httparse::Request::new(&mut headers_buf);
    let (verb, path, headers, body_offset) =
        if let Ok(httparse::Status::Complete(body_offset)) = req.parse(payload) {
            // version must be valid
            match req
                .version
                .ok_or(EventError::MalformedRequest("No HTTP version".to_string()))?
            {
                0 => {}
                1 => {}
                _ => {
                    return Err(EventError::MalformedRequest(
                        "Invalid HTTP version".to_string(),
                    ));
                }
            };

            let verb = req
                .method
                .ok_or(EventError::MalformedRequest("No HTTP method".to_string()))?
                .to_string();
            let path = req
                .path
                .ok_or(EventError::MalformedRequest("No HTTP path".to_string()))?
                .to_string();

            let mut headers: HashMap<String, String> = HashMap::new();
            for i in 0..req.headers.len() {
                let value = String::from_utf8(req.headers[i].value.to_vec()).map_err(|_e| {
                    EventError::MalformedRequest("Invalid HTTP header value: not utf-8".to_string())
                })?;
                if !value.is_ascii() {
                    return Err(EventError::MalformedRequest(
                        "Invalid HTTP request: header value is not ASCII-US".to_string(),
                    ));
                }
                if value.len() > MAX_HTTP_HEADER_LEN {
                    return Err(EventError::MalformedRequest(
                        "Invalid HTTP request: header value is too big".to_string(),
                    ));
                }

                let key = req.headers[i].name.to_string().to_lowercase();
                if headers.get(&key).is_some() {
                    return Err(EventError::MalformedRequest(format!(
                        "Invalid HTTP request: duplicate header \"{key}\""
                    )));
                }
                headers.insert(key, value);
            }
            (verb, path, headers, body_offset)
        } else {
            return Err(EventError::Deserialize(
                "Failed to decode HTTP headers".to_string(),
            ));
        };

    Ok(SignerHttpRequest::new(verb, path, headers, body_offset))
}
