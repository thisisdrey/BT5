The binding claimed—`TokenId::Nep171(...) != TokenId::Nep245(...)` for identical `(contract_id, token_id)` pairs—holds in all code paths.

**Verification of the binding:**

`TokenId` is a Rust `enum` with `#[derive(Clone, PartialEq, Eq, PartialOrd, Ord, Hash, ...)]` and explicit discriminants (`Nep141 = 0`, `Nep171 = 1`, `Nep245 = 2`, `Imt = 3`) [1](#0-0) . Since `PartialEq`/`Eq`/`Hash`/`Ord` are derived on the enum itself rather than on the string representation, any comparison, hashing, or ordering operation first discriminates by variant tag before comparing the inner struct fields. This means `TokenId::Nep171(Nep171TokenId{contract_id, nft_token_id})` and `TokenId::Nep245(Nep245TokenId{contract_id, mt_token_id})` can never be equal, hash to different buckets is not guaranteed but equality is guaranteed false, and they sort by discriminant first in `Ord` — regardless of whether the inner `(contract_id, sub_token)` pairs are identical strings.

The `Display`/`Debug` implementation also always writes the type prefix before the inner value: `write!(f, "{}:{}", TokenIdType::Nep171, token_id)` vs `write!(f, "{}:{}", TokenIdType::Nep245, token_id)` [2](#0-1) , and `FromStr` requires and preserves this prefix when parsing back [3](#0-2) . There is no code path where the prefix is stripped or the variant tag is dropped before a `token_balances` lookup, `TokenDiff` netting, or borsh (de)serialization — borsh serialization even encodes the discriminant explicitly (`borsh(use_discriminant = true)`, confirmed by the test's hardcoded discriminant bytes `01` for `nep171` vs `02` for `nep245`) [4](#0-3) .

Both `Nep171TokenId` and `Nep245TokenId` independently derive `PartialEq, Eq, PartialOrd, Ord, Hash` on their own struct fields [5](#0-4) [6](#0-5) , but since these are only reachable through the outer `TokenId` enum in all `token_balances`/`TokenDiff` maps, the outer variant discrimination is always applied first.

Since both sides of the equality match (the variants are always distinguished, with no code path that erases or bypasses the discriminant), there is no collision and no exploitable path for the described attack.
