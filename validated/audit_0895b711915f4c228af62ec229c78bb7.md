### Title
Unauthenticated remote shutdown of the signer's event receiver via `POST /shutdown` - (File: libsigner/src/events.rs)

### Summary
The signer's `SignerEventReceiver` treats any HTTP `POST /shutdown` request as authoritative, immediately setting the internal stop flag and returning `EventError::Terminated`, which causes `main_loop` to exit permanently. Because there is no authentication, signature, or shared-secret check on this endpoint, any TCP client that can reach the signer's event-listener port can silently and permanently halt the signer's event processing with a single crafted HTTP request.

### Finding Description
In `next_event`, the URL dispatch handles `/shutdown` with no authorization check at all: it directly stores `true` into `stop_signal` and returns `Err(EventError::Terminated)`. [1](#0-0) 

This is the exact same code path used internally by `SignerStopSignaler::send`, which is only meant to be called by the signer's own runloop when it wants to terminate its own event receiver thread; it works by opening a loopback `TcpStream` to itself and sending a raw, unauthenticated `POST /shutdown` request. [2](#0-1) 

However, nothing in `next_event` verifies that the connection actually originated from the internal stop-signaler (e.g., there's no shared secret, no loopback-only enforcement at the bind level, and `bind` simply opens an `HttpServer` on the configured listener address). [3](#0-2) 

The consuming loop, `EventReceiver::main_loop`, treats `EventError::Terminated` as a clean exit signal and `break`s out of the loop entirely, ending the thread. [4](#0-3) 

An attacker only needs network reachability to the bound event-listener address (whatever `[event_listener]` bind is configured to in `stacks-signer`'s config) and can send:
```
POST /shutdown HTTP/1.1\r\nHost: <addr>\r\nConnection: close\r\nContent-Length: 0\r\n\r\n
```
No body content is even validated — `next_event` matches on URL and method only, before any content is read for the `/shutdown` branch.

### Impact Explanation
A single unauthenticated HTTP request permanently terminates the signer's event-receiver thread. Once terminated, the signer no longer receives `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, or `/new_block` events forwarded from its Stacks node, effectively taking the signer offline for all consensus-relevant signing activity until the operator manually restarts the process. This is a remote, unauthenticated, single-message crash/DoS of a critical node role (a signer), which is repeatable at will and requires no special network position beyond reaching the configured listener port — matching the Critical "remote crash/unauthenticated DoS from few messages" category.

### Likelihood Explanation
- No authentication, secret, or signature is required.
- Requires only TCP reachability to the signer's event-receiver bind address; whether the default deployment binds to loopback-only or to a more permissive address is a deployment/config concern, but nothing in this code enforces loopback-only regardless of configuration.
- The attack is a single well-formed HTTP POST, reproducible at any time, and costs the attacker nothing.

### Recommendation
Do not use an externally reachable, unauthenticated `/shutdown` HTTP endpoint to signal internal thread termination. Options:
- Enforce that the event-receiver only binds to and accepts connections from `127.0.0.1`/localhost, and additionally verify the peer address of incoming `/shutdown` requests equals the receiver's own bind/loopback address before honoring it.
- Replace the HTTP-based stop signal with an in-process mechanism (e.g., a channel, condvar, or self-pipe) that does not require an externally reachable socket at all.
- If an HTTP-based stop must remain, require a shared secret/token generated at start-up and passed via header, validated before honoring `/shutdown`.

### Proof of Concept
```rust
// Rust test plan (net test) demonstrating unauthenticated remote shutdown
use std::net::{TcpStream, SocketAddr};
use std::io::Write;
use std::thread;
use std::sync::mpsc::channel;
use libsigner::{EventReceiver, SignerEventReceiver, SignerEvent};

#[test]
fn test_unauthenticated_shutdown_dos() {
    let mut ev: SignerEventReceiver<SomeSignerMessage> = SignerEventReceiver::new(false);
    let endpoint: SocketAddr = "0.0.0.0:31000".parse().unwrap(); // reachable, non-loopback bind
    ev.bind(endpoint).unwrap();

    let receiver_thread = thread::spawn(move || {
        ev.main_loop(); // should keep running until stop signal
    });

    // Attacker: unauthenticated remote client, no secret, no prior handshake
    let mut sock = TcpStream::connect(endpoint).unwrap();
    let req = "POST /shutdown HTTP/1.1\r\nHost: attacker\r\nConnection: close\r\nContent-Length: 0\r\n\r\n";
    sock.write_all(req.as_bytes()).unwrap();

    // Assert: main_loop exits (thread terminates) despite attacker having no credentials
    receiver_thread.join().expect("event receiver thread terminated by unauthenticated request");
    // Any subsequent legitimate /stackerdb_chunks or /new_burn_block POSTs are now silently dropped,
    // since the event-receiver thread no longer exists.
}
```
The assertion of interest is that `receiver_thread.join()` completes (i.e., `main_loop` broke out at `libsigner/src/events.rs:296-300`) purely as a result of the unauthenticated attacker request, with no signature/secret check ever performed at `libsigner/src/events.rs:443-445`.
