### Title
Fee-exemption threshold in `TokenDiff::token_fee` is bypassed by splitting a single Nep245/Nep171/Imt withdrawal into many `delta = -1` intents - (File: `contracts/defuse/core/src/intents/token_diff.rs`)

### Summary
`TokenDiff::execute_intent` computes the protocol fee independently for each `TokenDiff` intent in the batch, and `TokenDiff::token_fee` deliberately returns `Pips::ZERO` whenever the per-intent `amount <= 1` for `Nep171`/`Nep245`/`Imt` token types. Because `DefuseIntents::intents` is an unrestricted `Vec<Intent>` and each `TokenDiff.diff` entry is evaluated on its own per-intent `amount`, a signer can express one intended `delta = -1_000_000` leg on a Nep245 token as 1,000,000 separate `TokenDiff` intents each with `delta = -1`, driving every fee computation into the zero-fee branch.

### Finding Description
Binding: `sum(fees_collected across all TokenDiff intents in the batch on token T)` should equal `Pips::ONE_PERCENT.fee_ceil(1_000_000)` for a total signer outflow of 1,000,000 units of a Nep245 token `T`, matching what a single `TokenDiff{diff:{T:-1_000_000}}` intent would collect.

Code path:
- `TokenDiff::execute_intent` (`contracts/defuse/core/src/intents/token_diff.rs:41-104`) iterates `self.diff` entries and, for each negative `delta`, computes `fee = Self::token_fee(token_id, amount, protocol_fee).fee_ceil(amount)` using only that single intent's `amount` [1](#0-0) .
- `TokenDiff::token_fee` explicitly special-cases `Nep171 | Nep245 | Imt` with `amount <= 1` to return `Pips::ZERO`, intentionally documented as "do not take fees on NFTs and MTs with `|delta| <= 1`" [2](#0-1) .
- `DefuseIntents::intents` is an arbitrary-length `Vec<Intent>` executed sequentially with no per-token or per-batch fee accounting across intents [3](#0-2) [4](#0-3) .
- The batch-level invariant check (`TransferMatcher::finalize` in `contracts/defuse/core/src/engine/state/deltas.rs:265-283`) only verifies that the **sum of raw balance deltas** (post-fee, since fee is deducted via `internal_apply_deltas` before the matcher ever sees the delta) nets to zero across senders/receivers [5](#0-4) . It has no concept of "this token id had a cumulative delta of 1,000,000 across N intents, therefore the aggregate fee should have been X" — it is agnostic to how many intents produced a given net transfer.

Because the fee is computed strictly per-`TokenDiff`-intent on that intent's own `amount`, an attacker who wants to move out 1,000,000 units of a Nep245 leg can sign 1,000,000 separate `TokenDiff` intents (`diff = {T: -1}`, balanced elsewhere in the same `MultiPayload` batch or across payloads by a counterparty's matching `+1` deposits) inside one `DefuseIntents`/`MultiPayload`. Each individual intent call hits the `amount <= 1` branch of `token_fee`, returning `Pips::ZERO`, so `fee_ceil(1) = 0` for every leg, and the cumulative `fees_collected` credited to `fee_collector` is `0`, versus `Pips::ONE_PERCENT.fee_ceil(1_000_000) = 10_000` that a single unsplit `delta = -1_000_000` leg would owe.

No existing guard prevents this: `MultiPayload::verify`, nonce/salt checks, and `Lock` checks are orthogonal to fee accounting; `TransferMatcher::finalize` only enforces balance conservation, not fee correctness, and does so on already fee-adjusted deltas.

### Impact Explanation
The `fee_collector` is under-collected on every Nep245/Nep171/Imt-denominated trade that a user chooses to structure as many unit-sized `TokenDiff` legs instead of one, matching the "protocol fees bypassed" Critical impact category. This is fully repeatable by any signer, for any Nep245 token, and scales linearly with the number of split intents the attacker is willing to include in a batch (or across multiple sequential transactions/payloads, since the exemption is per-intent, not per-transaction) — the flaw is not limited to the one-transaction, 1,000,000-intent scenario in the prompt; smaller-scale splitting (e.g., splitting any `delta` into `N` unit legs, `N ≤` whatever the attacker can afford in gas) reproduces the same zero-fee effect for any total amount.

### Likelihood Explanation
Preconditions match an ordinary unprivileged Verifier user: the signer only needs a Verifier balance of the Nep245 token they want to move, and a counterparty (or their own second signed payload) supplying matching positive deltas to satisfy `TransferMatcher::finalize`'s net-zero requirement — this is exactly the same requirement any legitimate `TokenDiff` swap already has, so it's not a novel barrier. The only real cost is NEAR gas/storage for issuing many small intents; while the exact 1,000,000-leg example in one call is impractical under the ~300 Tgas per-transaction limit, the same bypass works at smaller scale (e.g., a few hundred or few thousand `delta=-1` legs across one or a few transactions), meaning the bug is exploitable well below the extreme figure used to illustrate it, and the "unbounded gas" exclusion in the rules does not eliminate the underlying fee-bypass logic flaw — it only affects how large a single demonstration batch can be.

### Recommendation
Compute and enforce the `Nep171/Nep245/Imt` no-fee exemption on the **aggregate net delta per (signer, token_id) across the whole batch/transfer-matcher pass**, not on each individual `TokenDiff` intent's own `amount`. Concretely, move the `amount <= 1` fee-exemption check to operate on the value tracked by `TokenTransferMatcher`/`TransferMatcher` (post-aggregation, pre-finalize) rather than inside `TokenDiff::execute_intent`, or cap the number of `TokenDiff` intents referencing the same `(signer_id, token_id)` pair within a batch, or compute fees once per unique `(token_id)` after summing all negative deltas contributed by a signer across the entire `DefuseIntents` sequence.

### Proof of Concept
```rust
// contracts/defuse/core/src/intents/token_diff.rs (new #[cfg(test)] case)
// Control: single TokenDiff with delta = -1_000_000 on a Nep245 token.
let fee = Pips::ONE_PERCENT;
let amount: u128 = 1_000_000;
let single_fee = TokenDiff::token_fee(&nep245_token_id, amount, fee).fee_ceil(amount);
assert_eq!(single_fee, fee.fee_ceil(amount)); // != 0

// Exploit: 1_000_000 TokenDiff intents, each delta = -1 on the same Nep245 token.
let mut total_fee: u128 = 0;
for _ in 0..amount {
    let per_leg_fee = TokenDiff::token_fee(&nep245_token_id, 1, fee).fee_ceil(1);
    total_fee += per_leg_fee;
}
assert_eq!(total_fee, 0); // binding broken: 0 != single_fee (10_000)
```
Sandbox-level proof (near-workspaces): sign one `MultiPayload::TonConnect` batch containing 1,000,000 (or a smaller feasible N, e.g. 1,000, with correspondingly scaled amount) `TokenDiff` intents each `{T: -1}` balanced by a counterparty's matching deposits, execute via `execute_intents`, then assert `mt_balance_of(fee_collector, T) == 0`; run a control test executing a single `TokenDiff{T: -N}` intent and assert `mt_balance_of(fee_collector, T) == Pips::ONE_PERCENT.fee_ceil(N)`, showing the two diverge.

    // Finalizes all transfers, or returns unmatched deltas.
    // If unmatched deltas overflow, then Err(None) is returned.
    pub fn finalize(self) -> Result<Transfers, InvariantViolated> {
        let mut transfers = Transfers::default();
        let mut deltas = TokenDeltas::default();
        for (token_id, transfer_matcher) in self.0 {
            if let Err(unmatched) = transfer_matcher.finalize_into(&token_id, &mut transfers)
                && (unmatched == 0 || deltas.apply_delta(token_id, unmatched).is_none())
            {
                return Err(InvariantViolated::Overflow);
            }
        }
        if !deltas.is_empty() {
            return Err(InvariantViolated::UnmatchedDeltas {
                unmatched_deltas: deltas,
            });
        }
        Ok(transfers)
    }
