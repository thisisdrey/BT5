### Title
Protocol fee bypass on Nep245/Imt `TokenDiff` intents via intent-splitting - ([File: contracts/defuse/core/src/intents/token_diff.rs])

### Summary
`TokenDiff::token_fee` decides whether a fee applies to a Nep245/Imt token by checking `amount > 1`, where `amount` is `delta.unsigned_abs()` of a single `TokenDiff` intent's own diff entry, not the aggregate negative exposure of that token across the whole `execute_intents` batch. By splitting one delta of `-2` into two signed `TokenDiff` intents of delta `-1` each (submitted together in the same `MultiPayload` batch), the signer causes `token_fee` to be evaluated twice with `amount == 1`, which returns `Pips::ZERO` both times, whereas a single `-2` intent would trigger the nonzero protocol fee.

### Finding Description
The binding that should hold is: `fee_collector_credit(token T, batch) == Pips::fee_ceil(protocol_fee, sum_of_negative_deltas_of_T_in_batch)`. The actual code computes the fee independently per `(TokenDiff intent, token)` pair: [1](#0-0) 

and the guard for Nep245/Imt is: [2](#0-1) 

`amount` here is `delta.unsigned_abs()` for a single intent's entry in `self.diff`, never aggregated across the intents in the batch (`Engine::execute_signed_intents` just loops `execute_signed_intent` for each `MultiPayload`, and `TokenDiff::execute_intent` computes and immediately deposits `fees_collected` per-call): [3](#0-2) 

So a signer who wants to move 2 units of a fee-bearing Nep245/Imt token can sign two `TokenDiff` intents with `diff = {T: -1}` instead of one intent with `diff = {T: -2}`. Each call to `token_fee(T, 1, fee)` falls into the `amount > 1` branch's `else` arm and returns `Pips::ZERO`, so `fee_ceil(1) == 0` for both intents, while the same total exposure packed into one intent (`amount == 2`) would return the real `fee` and produce a nonzero `fee_ceil(2)`.

The batch-level `TransferMatcher`/`finalize` invariant only enforces that total deposits equal total withdrawals per token across the whole batch (`InvariantViolated::UnmatchedDeltas`), it does not re-derive or enforce a minimum fee amount: [4](#0-3) . Nothing in `MultiPayload::verify`, nonce/salt checks, or `#[pause]`/`access_control_any` guards inspects aggregate per-token fee exposure across intents; they only validate signatures/nonces/deadlines, which are irrelevant to this arithmetic.

Because the counterparty side of a `TokenDiff` swap must supply exactly enough of the traded token to keep the batch invariant satisfied (via `TokenDiff::closure_delta`, which itself calls `token_fee` with the per-intent amount), splitting a trade into unit-sized legs lets the colluding parties (or the same signer acting as both sides for a self-trade) negotiate a fee-free exchange rate identical to what a `Pips::ZERO`-fee deployment would produce, silently discarding the fee that a single lump-sum intent would have generated.

### Impact Explanation
This under-collects protocol fees on any Nep245/Imt token whose per-unit atomic transfer would otherwise be free of fee but whose aggregate transferred amount in a batch is large. Repeating the pattern (many `-1` legs) lets a trader/solver pair move arbitrarily large multi-token amounts through the Verifier while the fee_collector only ever sees `Pips::ZERO` credited, i.e., "protocol fees bypassed", which is explicitly a listed Critical impact category. The blast radius is any Nep245/Imt token configured with a nonzero protocol fee; it does not touch other accounts' un-authorized funds and does not break signature/nonce/lock invariants, but it does directly reduce protocol revenue that is supposed to be enforced by `Self::token_fee`/`Pips::fee_ceil`.

### Likelihood Explanation
The attack requires no privileged role: any signer can construct and sign arbitrary numbers of `TokenDiff` intents off-chain for free and submit them together in one `execute_intents`/`simulate_intents` batch. It does require a counterparty (or the signer trading with themselves across two token types) to supply the matching deposits so the batch invariant balances — this is the same requirement any legitimate `TokenDiff` swap already has, so it adds no extra cost beyond gas for more intents in the batch. Splitting scales linearly with the number of intents, bounded only by gas/block limits, making it fully repeatable across accounts, tokens, and batches.

### Recommendation
Aggregate the negative exposure of each `TokenId` across all `TokenDiff` intents processed within the same `execute_intents` batch (per signer, or globally) before applying the `amount > 1` fee-exemption check for `Nep245`/`Imt`, rather than evaluating it per individual intent's own delta.

### Proof of Concept
Using the existing `tests/src/tests/defuse/intents/token_diff.rs` scaffolding (e.g. `swap_p2p`/`solver_user_closure` style) but with a `Nep245TokenId` instead of `Nep141TokenId` and a nonzero fee:
1. Deploy a mock MT contract and deposit 2 units of a semi-fungible `Nep245` token (amount can exceed 1) to `user1`, and enough of a counter-token to `user2`/solver.
2. Case A: sign a single `TokenDiff` for `user1` with `diff = {T: -2, X: +closure}` and a matching `TokenDiff` for the solver computed via `TokenDiff::closure_delta(&T, -2, fee)`. Execute via `execute_intents`; assert `fee_collector`'s `mt_balance_of(T)` increased by `fee.fee_ceil(2)` (nonzero for `fee > Pips::ZERO`).
3. Case B: sign two separate `TokenDiff` intents for `user1`, each `diff = {T: -1, X: +closure_delta(&T, -1, fee)}`, with matching solver intents computed the same way, all submitted in a single `execute_intents` batch. Assert `fee_collector`'s `mt_balance_of(T)` delta is `0`.
4. Assert the two `fee_collector` balance deltas differ (Case A > 0, Case B == 0) despite identical total exposure of 2 units of `T`, proving `token_fee`'s per-intent `amount > 1` guard is bypassable by splitting.

    // Finalizes all transfers, or returns unmatched deltas.
    // If unmatched deltas overflow, then Err(None) is returned.
    pub fn finalize(self) -> Result<Transfers, InvariantViolated> {
        let mut transfers = Transfers::default();
        let mut deltas = TokenDeltas::default();
        for (token_id, transfer_matcher) in self.0 {
            if let Err(unmatched) = transfer_matcher.finalize_into(&token_id, &mut transfers)
                && (unmatched == 0 || deltas.apply_delta(token_id, unmatched).is_none())
            {
                return Err(InvariantViolated::Overflow);
            }
        }
        if !deltas.is_empty() {
            return Err(InvariantViolated::UnmatchedDeltas {
                unmatched_deltas: deltas,
            });
        }
        Ok(transfers)
    }
