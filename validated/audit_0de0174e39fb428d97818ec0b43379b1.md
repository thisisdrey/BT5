### Title
SSRF-style abuse of peer-advertised `data_url` lets a remote peer make a Stacks node issue outbound HTTP requests to arbitrary internal/loopback/link-local addresses - (File: stackslib/src/net/chat.rs, stackslib/src/util_lib/strings.rs, stackslib/src/net/atlas/download.rs, stackslib/src/net/mempool/mod.rs)

### Summary
The external advisory concerns a headless-browser capture tool that failed to restrict page-initiated navigations/requests to `file://` URLs and non-public (loopback/private/link-local) IP addresses, allowing SSRF. The analogous bug class in this repo is that a remote, unauthenticated/unprivileged peer's self-reported `data_url` (sent in the `Handshake`/`HandshakeAccept` P2P message) is accepted with essentially no restriction on its target host, and this attacker-controlled string is later used by several in-scope subsystems (Atlas attachment fetch, mempool sync) to open outbound HTTP connections chosen entirely by the remote party.

### Finding Description
`HandshakeData::consensus_deserialize` in `stackslib/src/net/codec.rs` only rejects a zero port; it performs no validation of the `data_url` field's target address: [1](#0-0) 

`ConversationHttp::update_from_handshake_data` unconditionally copies this attacker-supplied `data_url` into peer state: [2](#0-1) 

The only sanity check anywhere in this code path, `UrlString::has_routable_host`, merely rejects the any-net addresses `0.0.0.0`/`::`; it does **not** reject loopback (`127.0.0.1`), RFC1918 private ranges, or link-local addresses (e.g. `169.254.169.254`, the common cloud metadata endpoint): [3](#0-2) 

This `data_url` is subsequently used to build outbound HTTP requests to the peer's advertised endpoint in multiple in-scope subsystems:
- Atlas attachment inventory/content requests build the request target directly from the peer's reported URL, `get_url()`/`make_request_type`, with no additional address-class filtering: [4](#0-3) 
- Mempool sync resolves and connects to the peer-supplied `data_url` (`mempool_sync_begin_resolve_data_url` / `mempool_sync_resolve_data_url`), using `PeerNetwork::try_get_url_ip` and the DNS client, again with no address-class filtering before connecting: [5](#0-4) [6](#0-5) 
- The final connection is made unconditionally via `connect_or_send_http_request` / `connect_http`, which take a raw `SocketAddr` and dial it without checking whether it is a global/public address: [7](#0-6) [8](#0-7) 

The equality that should hold but is broken here is: "a peer's advertised HTTP data endpoint should be restricted to a legitimate, globally-routable peer address" vs. what actually happens: "any string that parses as an http(s) URL without embedded credentials/query/fragment is accepted and dialed, including loopback/private/link-local targets." This mirrors the `only_global_lookup` gap described in the PlaywrightCapture advisory, just at the P2P-handshake layer instead of the browser-navigation layer.

### Impact Explanation
Any node that connects into the Stacks P2P network — no privileged role, secret, or key required beyond running a normal peer — can advertise a `data_url` pointing at an internal/loopback/link-local address (e.g. another service on the victim's host, an internal management endpoint, or a cloud metadata service at `169.254.169.254`). Victim nodes that select this peer during Atlas attachment sync or mempool sync will then issue outbound HTTP GET/POST requests to that address on the attacker's behalf. This is a classic SSRF: it lets a remote unprivileged party turn a victim Stacks node into a network proxy against its own internal network / localhost services, which can be used for internal port scanning/reconnaissance or interacting with internal-only HTTP APIs. Depending on deployment, this does not, by itself, exfiltrate response bodies back to the attacker (the responses are only interpreted internally as attachment/mempool-inventory HTTP responses), so the primary confirmed impact is unauthorized outbound requests to internal resources (SSRF write/GET amplification), rather than guaranteed data disclosure — this bounds the severity below "Critical" but keeps it in the "High" band consistent with the rules' "bounded compute DoS on a read endpoint" / non-canonical-serving class, since a victim node can be steered into wasting resources and probing internal endpoints under attacker control.

### Likelihood Explanation
Likelihood is fairly high for the mechanism to trigger: any node handshaking on the P2P network can set `data_url` to anything that parses as `http(s)://host[:port]/` without user/pass/query/fragment (enforced only by `parse_to_block_url`), and `has_routable_host` does not filter private/loopback/link-local ranges. The victim's neighbor-walk and mempool-sync/Atlas-sync logic will periodically pick this peer (if it is added to `PeerDB`/frontier), and thus will eventually dial the malicious target. However, actually causing the request requires the malicious peer to be selected as an active peer for a specific sync flow (mempool sync or Atlas attachment fetch), which needs at least one successful handshake and inclusion in the frontier/neighbor set — this is achievable by any peer but is not instantaneous, and it depends on the victim's sync scheduling picking that particular neighbor.

### Recommendation
Extend `UrlString::has_routable_host` (or add a new checked validation used at handshake-acceptance time in `stackslib/src/net/chat.rs::update_from_handshake_data`, and again just before dialing in `mempool_sync_begin_resolve_data_url`/`mempool_sync_resolve_data_url` and in Atlas's `Requestable::get_url` consumers) to reject resolved IP addresses that are loopback, private (RFC1918), link-local (including `169.254.0.0/16`), or otherwise non-global, mirroring the fix pattern from GHSA-687h-xw6f-q2qw's `only_global_lookup` routing check. This validation must be applied after DNS resolution (not just on the literal string), since a domain name can resolve to a private/loopback address.

### Proof of Concept
1. Stand up a malicious Stacks peer that completes the P2P handshake with a victim node, setting `HandshakeData.data_url` to `http://127.0.0.1:<victim-internal-port>/` or `http://169.254.169.254/latest/meta-data/` (see `stackslib/src/net/codec.rs:648-669` — only `port == 0` is rejected).
2. Ensure the malicious peer's handshake is accepted (`validate_handshake` in `stackslib/src/net/chat.rs:1047-1127` has no data_url restriction) and gets added to the victim's neighbor frontier via the normal neighbor-walk process (`stackslib/src/net/neighbors/walk.rs`).
3. Wait for/trigger the victim's Atlas attachment-batch sync or mempool sync to select this peer as a download source (`stackslib/src/net/atlas/download.rs:1104-1119`, `stackslib/src/net/mempool/mod.rs:211-315`).
4. Observe the victim node opening an outbound HTTP connection to the attacker-chosen internal/loopback/link-local address via `connect_or_send_http_request`/`connect_http` (`stackslib/src/net/httpcore.rs:1873-1911`, `stackslib/src/net/server.rs:114-150`), confirming SSRF against the victim's internal network from an unprivileged remote peer.

    /// Is this URL routable?
    /// i.e. is the host _not_ 0.0.0.0 or ::?
    pub fn has_routable_host(&self) -> bool {
        let url = match url::Url::parse(&self.to_string()) {
            Ok(x) => x,
            Err(_) => {
                // should be unreachable
                return false;
            }
        };
        match url.host_str() {
            Some(host_str) => {
                if host_str == "0.0.0.0" || host_str == "[::]" || host_str == "::" {
                    return false;
                } else {
                    return true;
                }
            }
            None => {
                return false;
            }
        }
    }

    /// Begin resolving the DNS host of a data URL for mempool sync.
    /// Returns Ok(None) if we're done syncing the mempool.
    /// Returns Ok(Some(..)) if we're not done, and can proceed
    /// Returns the new sync state -- either ResolveURL if we need to resolve a data URL,
    /// or SendQuery if we got the IP address and can just issue the query.
    #[cfg_attr(test, mutants::skip)]
    fn mempool_sync_begin_resolve_data_url(
        &self,
        network: &PeerNetwork,
        url_str: UrlString,
        dns_client_opt: &mut Option<&mut DNSClient>,
        page_id: &Txid,
    ) -> Result<Option<MempoolSyncState>, NetError> {
        // start resolving
        let url = url_str.parse_to_block_url()?;
        let port = match url.port_or_known_default() {
            Some(p) => p,
            None => {
                warn!("Unsupported URL {:?}: unknown port", &url);
                return Ok(None);
            }
        };

        // bare IP address?
        if let Some(addr) = PeerNetwork::try_get_url_ip(&url_str)? {
            return Ok(Some(MempoolSyncState::SendQuery(
                url_str,
                addr,
                page_id.clone(),
            )));
        } else if let Some(url::Host::Domain(domain)) = url.host() {
            if let Some(ref mut dns_client) = dns_client_opt {
                // begin DNS query
                match dns_client.queue_lookup(
                    domain,
                    port,
                    get_epoch_time_ms() + network.get_connection_opts().dns_timeout,
                ) {
                    Ok(_) => {}
                    Err(_) => {
                        warn!("Failed to queue DNS lookup on {}", &url_str);
                        return Ok(None);
                    }
                }
                return Ok(Some(MempoolSyncState::ResolveURL(
                    url_str,
                    DNSRequest::new(domain.to_string(), port, 0),
                    page_id.clone(),
                )));
            } else {
                // can't proceed -- no DNS client
                return Ok(None);
            }
        } else {
            // can't proceed
            return Ok(None);
        }
    }

    /// Resolve our picked mempool sync peer's data URL.
    /// Returns (true, ..) if we're done syncing the mempool.
    /// Returns (false, ..) if there's more to do
    /// Returns the socket addr if we ever succeed in resolving it.
    #[cfg_attr(test, mutants::skip)]
    fn mempool_sync_resolve_data_url(
        url_str: &UrlString,
        request: &DNSRequest,
        dns_client_opt: &mut Option<&mut DNSClient>,
    ) -> (bool, Option<SocketAddr>) {
        if let Ok(Some(addr)) = PeerNetwork::try_get_url_ip(url_str) {
            // URL contains an IP address -- go with that
            (false, Some(addr))
        } else if let Some(dns_client) = dns_client_opt {
            // keep trying to resolve
            match dns_client.poll_lookup(&request.host, request.port) {
                Ok(Some(dns_response)) => match dns_response.result {
                    Ok(mut addrs) => {
                        if let Some(addr) = addrs.pop() {
                            // resolved!
                            (false, Some(addr))
                        } else {
                            warn!("DNS returned no results for {url_str}");
                            (true, None)
                        }
                    }
                    Err(msg) => {
                        warn!("DNS failed to look up {url_str:?}: {msg}");
                        (true, None)
                    }
                },
                Ok(None) => {
                    // still in-flight
                    (false, None)
                }
                Err(e) => {
                    warn!("DNS lookup failed on {url_str:?}: {e:?}");
                    (true, None)
                }
            }
        } else {
            // can't do anything
            debug!("No DNS client, and URL contains a domain, so no mempool sync can happen");
            (true, None)
        }
    }

        data_url: UrlString,

    ) -> Result<usize, NetError> {
        PeerNetwork::with_network_state(self, |ref mut network, ref mut network_state| {
            PeerNetwork::with_http(network, |ref mut network, ref mut http| {
                match http.connect_http(
                    network_state,
                    network,
                    data_url.clone(),
                    addr,
                    Some(request.clone()),
                ) {
                    Ok(event_id) => Ok(event_id),
                    Err(NetError::AlreadyConnected(event_id, _)) => {
                        if let (Some(ref mut convo), Some(ref mut socket)) =

                            Err(NetError::PeerNotConnected(format!(
                                "HTTP failed to connect to {data_url}, {addr:?}",
                            )))
                        }
                    }
                    Err(e) => Err(e),
                }
            })
        })

    /// its origin.  Once connected, optionally send the given request.
    /// Idempotent -- will not re-connect if already connected and there is a free conversation channel open
    /// (will return Error::AlreadyConnected with the event ID)
    pub fn connect_http(
        &mut self,
        network_state: &mut NetworkState,
        network: &PeerNetwork,
        data_url: UrlString,
        addr: SocketAddr,
        request: Option<StacksHttpRequest>,
    ) -> Result<usize, net_error> {
        if let Some(event_id) = self.find_free_conversation(&data_url) {
            let http_nk = NeighborKey {
                peer_version: network.burnchain.peer_version,
                network_id: network.local_peer.network_id,
                addrbytes: PeerAddress::from_socketaddr(&addr),
                port: addr.port(),
            };
            return Err(net_error::AlreadyConnected(event_id, http_nk));
        }

        let sock = NetworkState::connect(
            &addr,
            network.connection_opts.socket_send_buffer_size,
            network.connection_opts.socket_recv_buffer_size,
        )?;

            network_state.register(self.http_server_handle, hint_event_id, &sock)?;

            next_event_id,
            (sock, Some(data_url), request, get_epoch_time_secs()),
        );
        Ok(next_event_id)
    }
