### Title
Missing Zero-Address Validation in `set_beneficiary_for_operator` Permanently Misdirects Operator Commission APT to `NULL_SHAREHOLDER` - (`File: aptos-move/framework/aptos-framework/sources/delegation_pool.move`)

---

### Summary

`delegation_pool::set_beneficiary_for_operator` accepts any `new_beneficiary` address, including `@0x0`, without validation. Because `@0x0` is the module's own `NULL_SHAREHOLDER` constant used for internal fee accounting, setting the beneficiary to `@0x0` causes all future operator commission shares to be credited to `NULL_SHAREHOLDER`. On the next permissionless `synchronize_delegation_pool` call where `pending_active == 0`, those shares are redeemed and redistributed to all delegators, permanently diverting the operator's commission APT.

---

### Finding Description

`delegation_pool.move` defines `NULL_SHAREHOLDER = @0x0` as a special internal address that temporarily holds `add_stake` fees: [1](#0-0) 

`set_beneficiary_for_operator` stores any caller-supplied address as the operator's commission recipient with no zero-address guard: [2](#0-1) 

Unlike the parallel function in `staking_contract.move` (which gates on `features::operator_beneficiary_change_enabled()`), the `delegation_pool` version has no feature flag and is always callable. [3](#0-2) 

When `synchronize_delegation_pool` runs, it calls `beneficiary_for_operator(stake::get_operator(pool_address))` and passes the result directly to `buy_in_active_shares` and `buy_in_pending_inactive_shares`: [4](#0-3) 

`beneficiary_for_operator` returns the stored value when a `BeneficiaryForOperator` resource exists, so after the operator sets it to `@0x0`, it returns `@0x0`: [5](#0-4) 

Commission shares are therefore bought in for `NULL_SHAREHOLDER`. On the next synchronization where `pending_active == 0`, the module redeems all `NULL_SHAREHOLDER` shares and distributes the underlying coins back into the pool as rewards for all delegators: [6](#0-5) 

The operator's commission is permanently redistributed to delegators.

The same root cause exists in `staking_contract::distribute_internal`, where `beneficiary_for_operator(operator)` returning `@0x0` causes `aptos_account::deposit_coins(@0x0, commission_coins)` — permanently locking APT at the zero address: [7](#0-6) 

---

### Impact Explanation

An operator who sets their beneficiary to `@0x0` (by mistake or misconfiguration) permanently loses all future commission APT. In the `delegation_pool` path, that commission is silently redistributed to delegators — an unauthorized reassignment of APT. In the `staking_contract` path, commission APT is deposited to the uncontrolled `@0x0` address and is permanently frozen. Both outcomes constitute direct, irreversible loss or unauthorized reassignment of on-chain APT.

---

### Likelihood Explanation

`set_beneficiary_for_operator` in `delegation_pool.move` is an unconditional public entry function callable by any operator at any time. A single mistaken or malformed transaction (e.g., passing a zero-initialized `AccountAddress` from an SDK) is sufficient. `synchronize_delegation_pool` is permissionless and is triggered automatically by `add_stake`, `unlock`, `withdraw`, and other common pool operations, so the commission loss occurs without any further attacker action.

---

### Recommendation

Add a zero-address assertion at the top of both `set_beneficiary_for_operator` functions before storing `new_beneficiary`:

```move
assert!(new_beneficiary != @0x0, error::invalid_argument(EINVALID_BENEFICIARY_ADDRESS));
```

Apply the same guard in `staking_contract::set_beneficiary_for_operator`.

---

### Proof of Concept

1. Operator deploys a delegation pool and begins validating (commission accumulates).
2. Operator calls `delegation_pool::set_beneficiary_for_operator(operator_signer, @0x0)`. No assertion fires; `BeneficiaryForOperator { beneficiary_for_operator: @0x0 }` is stored.
3. Any user calls `synchronize_delegation_pool(pool_address)` (or it is triggered implicitly by `add_stake`/`unlock`/`withdraw`).
4. Inside `synchronize_delegation_pool`, `beneficiary_for_operator(operator)` returns `@0x0`.
5. `buy_in_active_shares(pool, @0x0, commission_active)` credits commission shares to `NULL_SHAREHOLDER`.
6. On the next synchronization where `pending_active == 0`, `redeem_active_shares(pool, NULL_SHAREHOLDER, MAX_U64)` redeems those shares, distributing the commission APT to all delegators.
7. The operator receives zero commission; delegators receive an unauthorized windfall. The operator's commission APT is permanently and irreversibly misdirected. [2](#0-1) [8](#0-7)

```text
    public entry fun set_beneficiary_for_operator(
        operator: &signer,
        new_beneficiary: address
    ) acquires BeneficiaryForOperator {
        // The beneficiay address of an operator is stored under the operator's address.
        // So, the operator does not need to be validated with respect to a staking pool.
        let operator_addr = signer::address_of(operator);
        let old_beneficiary = beneficiary_for_operator(operator_addr);
        if (exists<BeneficiaryForOperator>(operator_addr)) {
            borrow_global_mut<BeneficiaryForOperator>(operator_addr).beneficiary_for_operator = new_beneficiary;
        } else {
            move_to(operator, BeneficiaryForOperator { beneficiary_for_operator: new_beneficiary });
        };

        emit(SetBeneficiaryForOperator {
            operator: operator_addr,
            old_beneficiary,
            new_beneficiary,
        });
    }
```

```text
    public entry fun synchronize_delegation_pool(
        pool_address: address
    ) acquires DelegationPool, GovernanceRecords, BeneficiaryForOperator, NextCommissionPercentage {
        assert_delegation_pool_exists(pool_address);
        let pool = borrow_global_mut<DelegationPool>(pool_address);
        let (
            lockup_cycle_ended,
            active,
            pending_inactive,
            commission_active,
            commission_pending_inactive
        ) = calculate_stake_pool_drift(pool);

        // zero `pending_active` stake indicates that either there are no `add_stake` fees or
        // previous epoch has ended and should release the shares owning the existing fees
        let (_, _, pending_active, _) = stake::get_stake(pool_address);
        if (pending_active == 0) {
            // renounce ownership over the `add_stake` fees by redeeming all shares of
            // the special shareholder, implicitly their equivalent coins, out of the active shares pool
            redeem_active_shares(pool, NULL_SHAREHOLDER, MAX_U64);
        };

        // distribute rewards remaining after commission, to delegators (to already existing shares)
        // before buying shares for the operator for its entire commission fee
        // otherwise, operator's new shares would additionally appreciate from rewards it does not own

        // update total coins accumulated by `active` + `pending_active` shares
        // redeemed `add_stake` fees are restored and distributed to the rest of the pool as rewards
        pool.active_shares.update_total_coins(active - commission_active);
        // update total coins accumulated by `pending_inactive` shares at current observed lockup cycle
        pending_inactive_shares_pool_mut(pool).update_total_coins(pending_inactive - commission_pending_inactive);

        // reward operator its commission out of uncommitted active rewards (`add_stake` fees already excluded)
        buy_in_active_shares(pool, beneficiary_for_operator(stake::get_operator(pool_address)), commission_active);
        // reward operator its commission out of uncommitted pending_inactive rewards
        buy_in_pending_inactive_shares(
            pool,
            beneficiary_for_operator(stake::get_operator(pool_address)),
            commission_pending_inactive
        );
```
