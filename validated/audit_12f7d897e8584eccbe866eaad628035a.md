### Title
`encoding/xml` `Encoder.EncodeToken` emits `StartElement`/`EndElement`/`Attr` names verbatim, allowing XML markup injection - ([File: src/encoding/xml/marshal.go])

### Summary
`Encoder.EncodeToken` validates `Comment` (`--` marker), `ProcInst` (`?>` marker), and `Directive` (`<`/`>` balance) content before emitting them, but performs no equivalent well-formedness check on `StartElement.Name.Local`/`.Space`, `EndElement.Name.Local`, or `Attr.Name.Local` beyond a check for emptiness. `writeStart` and `writeEnd` write these strings directly into the `<...>` markup with no escaping and no validation that they are legal XML `Name` productions, so an attacker-controlled name containing `<`, `>`, `"`, or whitespace is emitted as literal, unescaped XML structure.

### Finding Description
Attacker input reaches `Name.Local`/`Name.Space` of a `StartElement`, `EndElement`, or `Attr` that an application constructs from untrusted data and feeds to `(*Encoder).EncodeToken`. `EncodeToken`'s `StartElement` branch calls `p.writeStart(&t)` [1](#0-0) , which only rejects an empty `Local` and otherwise writes `start.Name.Local`, the namespace, and each attribute's `Name.Local`/`Value` (value escaped, but the *name* is not) straight into the byte stream [2](#0-1) . `writeEnd` behaves the same way for `EndElement`, writing `name.Local` unescaped [3](#0-2) . Contrast this with the sibling `Comment`, `ProcInst`, and `Directive` branches in the same switch, which explicitly scan for and reject embedded delimiter sequences (`--`, `?>`, mismatched `<`/`>`) before emission [4](#0-3) . There is no analogous check for element/attribute names, so a name such as `foo><injected/><bar` breaks out of the intended tag boundary and is reparsed as real markup by any downstream XML consumer — the same "verbatim `nodeName` injected into serialized markup" primitive described in the xmldom advisory (`&safe; <injected/> &x;` from an unvalidated `EntityReference.nodeName`).

### Impact Explanation
An application that unmarshals or otherwise derives a `Name` from untrusted input (e.g., building a `StartElement`/`Attr` dynamically from user-controlled tag/attribute names) and re-serializes it via `EncodeToken` can have the untrusted string escape the intended element/attribute boundary, injecting arbitrary child elements or attributes into the output XML document. Downstream consumers that reparse this output would see attacker-controlled elements that were never validated by the application's data model — an integrity/injection issue analogous to the reported CWE-116 (improper output neutralization) in xmldom. This is a documentation/library-behavior gap rather than a hard security bypass with existing exploited callers in the standard library itself, so it would likely be handled on Go's PUBLIC track pending confirmation from the Go security team, similar to how `Comment`/`ProcInst`/`Directive` protections were added specifically to close this exact class of issue for those token types.

### Likelihood Explanation
Exploitability requires an application to pass attacker-influenced strings as `Name.Local`/`Name.Space` into `StartElement`, `EndElement`, or `Attr` and then call `EncodeToken` directly (a supported, documented public API, not internal/test-only code) — analogous to xmldom's `createEntityReference(name)` being called with attacker-controlled `name`. This is a realistic pattern for applications generating XML from dynamic/templated tag names (e.g., converting JSON/user-supplied keys into XML element or attribute names) using the low-level `EncodeToken` API instead of struct-tag-based `Marshal`.

### Recommendation
Add a well-formedness check (e.g., using the existing `isName`/`isNameString` XML-Name validators already present in `xml.go`) for `StartElement.Name.Local`, `.Space`, `EndElement.Name.Local`, and each `Attr.Name.Local` inside `EncodeToken`, mirroring the existing marker checks for `Comment`, `ProcInst`, and `Directive`, and return an error if the name is not a valid XML `Name`.

### Proof of Concept
```go
package xml

import (
	"bytes"
	"strings"
	"testing"
)

func TestEncodeTokenNameInjection(t *testing.T) {
	var buf bytes.Buffer
	enc := NewEncoder(&buf)

	// Attacker-controlled "name" breaks out of the element boundary.
	injected := Name{Local: `root><injected/><x`}

	if err := enc.EncodeToken(StartElement{Name: injected}); err != nil {
		t.Fatalf("EncodeToken returned unexpected error: %v", err)
	}
	if err := enc.EncodeToken(EndElement{Name: injected}); err != nil {
		t.Fatalf("EncodeToken returned unexpected error: %v", err)
	}
	enc.Flush()

	out := buf.String()
	t.Logf("serialized: %s", out)

	// EXPECTED (if fixed): EncodeToken should reject the invalid name,
	// or the serializer should escape it so "<injected/>" never appears
	// as literal markup.
	if strings.Contains(out, "<injected/>") {
		t.Fatalf("XML markup injection: attacker-controlled name produced literal element: %s", out)
	}
}
```
Expected (current/vulnerable behavior): the test fails because `out` contains the literal, unescaped `<injected/>` element — i.e., `EncodeToken` neither rejects nor escapes the malformed name, reproducing the same "verbatim node-name markup injection" primitive as the xmldom advisory.

// writeStart writes the given start element.
func (p *printer) writeStart(start *StartElement) error {
	if start.Name.Local == "" {
		return fmt.Errorf("xml: start tag with no name")
	}

	p.tags = append(p.tags, start.Name)
	p.markPrefix()

	p.writeIndent(1)
	p.WriteByte('<')
	p.WriteString(start.Name.Local)

	if start.Name.Space != "" {
		p.WriteString(` xmlns="`)
		p.EscapeString(start.Name.Space)
		p.WriteByte('"')
	}

	// Attributes
	for _, attr := range start.Attr {
		name := attr.Name
		if name.Local == "" {
			continue
		}
		p.WriteByte(' ')
		if name.Space != "" {
			p.WriteString(p.createAttrPrefix(name.Space))
			p.WriteByte(':')
		}
		p.WriteString(name.Local)
		p.WriteString(`="`)
		p.EscapeString(attr.Value)
		p.WriteByte('"')
	}
	p.WriteByte('>')
	return nil
}

func (p *printer) writeEnd(name Name) error {
	if name.Local == "" {
		return fmt.Errorf("xml: end tag with no name")
	}
	if len(p.tags) == 0 || p.tags[len(p.tags)-1].Local == "" {
		return fmt.Errorf("xml: end tag </%s> without start tag", name.Local)
	}
	if top := p.tags[len(p.tags)-1]; top != name {
		if top.Local != name.Local {
			return fmt.Errorf("xml: end tag </%s> does not match start tag <%s>", name.Local, top.Local)
		}
		return fmt.Errorf("xml: end tag </%s> in namespace %s does not match start tag <%s> in namespace %s", name.Local, name.Space, top.Local, top.Space)
	}
	p.tags = p.tags[:len(p.tags)-1]

	p.writeIndent(-1)
	p.WriteByte('<')
	p.WriteByte('/')
	p.WriteString(name.Local)
	p.WriteByte('>')
	p.popPrefix()
	return nil
}
