### Title
Permissionless `accrueInterest()` calls compound debt at a frequency-dependent rate - (File: contracts/DebtToken.sol)

### Summary
`DebtToken._calculateInterestAccrual()` applies each elapsed interval to the previously stored `debtIndex` and `totalSupply_`, so every successful `accrueInterest()` call compounds all outstanding debt. Because `accrueInterest()` is permissionless and is also invoked by issuance, repayment, leverage minting, and liquidation paths, unrelated protocol activity or deliberate once-per-block calls changes borrowers’ effective APR from the configured linear rate to `∏(1 + ratePerSecond * Δt)`. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) [5](#0-4) 

### Finding Description
`interestRatePerSecond()` converts the configured APR into a per-second rate, and `_calculateInterestAccrual()` multiplies that elapsed rate by both the current total debt supply and the current debt index. [6](#0-5) [2](#0-1) 

After a call, the newly increased `totalSupply_` and `debtIndex` become the bases for the next call, producing a debt multiplier of `∏(1 + r * Δtᵢ)` rather than the intended `1 + r * ΣΔtᵢ`. [7](#0-6) [8](#0-7) 

`balanceOf()` then values a borrower’s stored principal using the ratio between the latest compounded index and their entry index, meaning global accrual frequency directly changes every borrower’s debt. [9](#0-8) [10](#0-9) 

The protocol’s own integration tests define the expected one-year result as `principal * (1 + interestRate)`, confirming that `interestRate` is intended to behave as linear APR rather than as a rate compounded at arbitrary transaction frequency. [11](#0-10) 

An unprivileged account can call `DebtToken.accrueInterest()` directly once per new timestamp, while normal calls to `issue()`, `repay()`, `repayAll()`, Smart Farming debt minting, and `Pool.liquidate()` also trigger compounding. [12](#0-11) [13](#0-12) [14](#0-13) [15](#0-14) 

### Impact Explanation
Borrowers are charged more than the configured APR whenever accrual happens more than once during an interest-rate period, and the excess debt is matched by synthetic tokens minted or accumulated for the fee collector. [16](#0-15) [17](#0-16) 

The excess can consume remaining borrowing capacity or make a borderline account unhealthy, after which `Pool.liquidate()` permits a third party to repay the inflated debt and seize collateral with the liquidation incentive. [18](#0-17) 

At the mainnet deployment script’s configured 1% APR, per-second compounding produces approximately `e^0.01 - 1 ≈ 1.005%`, compared with the expected `1%`, causing roughly a 0.5-basis-point overcharge on outstanding principal per year. [19](#0-18) [8](#0-7) 

The loss scales with aggregate debt and becomes materially larger for higher configured rates; at a 100% nominal APR, frequent accrual approaches `e - 1 ≈ 171.83%` annual growth instead of `100%`. [6](#0-5) [8](#0-7) [20](#0-19) 

### Likelihood Explanation
No privileged role, collateral, position, or protocol-specific prerequisite is needed to invoke `accrueInterest()`; the only restriction is that the block timestamp must exceed `lastTimestampAccrued`. [12](#0-11) 

Ordinary user activity also advances the compounding checkpoint because issuance, repayment, repayment-in-full, Smart Farming minting, and liquidation all call `accrueInterest()` internally. [3](#0-2) [4](#0-3) [14](#0-13) [5](#0-4) 

The attacker cannot fabricate timestamps and can compound at most once per block timestamp, so exploitation is bounded by the chain’s block cadence and is most profitable when targeting a borrower already close to liquidation. [21](#0-20) [22](#0-21) 

### Recommendation
Define whether `interestRate` is intended to be simple APR, periodic compound APR, or continuously compounded APR, then make the index calculation independent of call frequency.

For continuous compounding, calculate `debtIndex * exp(ratePerSecond * elapsed)` in fixed-point math for the entire elapsed interval rather than updating the index once per transaction. [2](#0-1) 

For fixed periodic compounding, calculate `debtIndex * rpow(1 + ratePerPeriod, elapsed / period)` and handle the remainder deterministically, rather than letting transaction boundaries define compounding periods. [8](#0-7) 

For non-compounding APR, replace the multiplicative global index with normalized debt shares or per-account elapsed-time accrual, because simply making `debtIndex` additive while retaining `principal * index / userIndex` would still produce incorrect interest for accounts entering after the index has grown. [9](#0-8) [10](#0-9) 

Add regression coverage comparing one-year, daily, per-block, and adversarially frequent accrual paths and asserting identical debt within the selected compounding model’s specified tolerance. [11](#0-10) 

### Proof of Concept
The following Foundry mainnet-fork test uses the deployed `USDCDepositToken_Pool1` and `MsUSDDebt_Pool1` proxies, opens a debt position, and compares a single annual accrual with daily accrual over the same elapsed time. [23](#0-22) [24](#0-23) 

```solidity
// test/foundry/DebtTokenFrequency.t.sol
// SPDX-License-Identifier: MIT
pragma solidity 0.8.24;

import {Test} from "forge-std/Test.sol";

interface IERC20 {
    function approve(address spender, uint256 amount) external returns (bool);
}

interface IDepositToken {
    function deposit(uint256 amount, address onBehalfOf) external returns (uint256);
}

interface IDebtToken {
    function issue(uint256 amount, address to) external returns (uint256, uint256);
    function accrueInterest() external;
    function balanceOf(address account) external view returns (uint256);
    function SECONDS_PER_YEAR() external view returns (uint256);
}

contract DebtTokenFrequencyTest is Test {
    address internal constant USDC = 0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48;
    address internal constant USDC_DEPOSIT = 0x1A9551de6d56f7768398a82aA2186624a43d89e3;
    address internal constant MSUSD_DEBT = 0x480e3178Fa102dF852643d47CAbdb9adf5dB0174;

    function test_AccrualFrequencyChangesDebt() public {
        address borrower = makeAddr("borrower");

        deal(USDC, borrower, 10_000e6);
        vm.startPrank(borrower);
        IERC20(USDC).approve(USDC_DEPOSIT, type(uint256).max);
        IDepositToken(USDC_DEPOSIT).deposit(10_000e6, borrower);
        IDebtToken(MSUSD_DEBT).issue(1_000e18, borrower);
        vm.stopPrank();

        IDebtToken debt = IDebtToken(MSUSD_DEBT);
        uint256 year = debt.SECONDS_PER_YEAR();

        uint256 snapshot = vm.snapshot();

        // One accrual checkpoint after one year: linear APR.
        vm.warp(block.timestamp + year);
        uint256 annualDebt = debt.balanceOf(borrower);

        assertTrue(vm.revertToState(snapshot));

        // Daily accrual checkpoints over the same elapsed year.
        uint256 elapsed;
        while (elapsed + 1 days <= year) {
            vm.warp(block.timestamp + 1 days);
            debt.accrueInterest();
            elapsed += 1 days;
        }

        if (elapsed < year) {
            vm.warp(block.timestamp + (year - elapsed));
            debt.accrueInterest();
        }

        uint256 periodicDebt = debt.balanceOf(borrower);

        // Daily compounding exceeds the configured linear APR.
        assertGt(periodicDebt, annualDebt);
    }
}
```
