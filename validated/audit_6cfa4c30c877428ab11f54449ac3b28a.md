### Title
Out-of-bounds read via unsigned integer underflow in `InputZipFile::EnsureRemaining` when parsing attacker-controlled ZIP central directory offsets - (File: `third_party/ijar/zip.cc`)

### Summary
`ijar`'s ZIP reader trusts the `local_header_offset` field from an untrusted ZIP central directory to reposition its read cursor, then relies on `EnsureRemaining()` to bound subsequent reads. That bounds check underflows on a crafted (out-of-range) offset, defeating the check it is supposed to provide and allowing multi-byte field reads (`get_u4le`, `get_u2le`) far outside the mapped input file.

### Finding Description
`InputZipFile::ProcessCentralDirEntry` reads `*offset = get_u4le(p);` directly from the central directory record with no validation against the file size [1](#0-0) . `ProcessNext` then uses this attacker-controlled offset to reposition the cursor: `p = zipdata_in_ + in_offset_ + offset;` before calling `EnsureRemaining(4, "signature")` and reading via `get_u4le(p)` [2](#0-1) .

The only guard, `EnsureRemaining`, computes:
```
size_t in_offset = p - zipdata_in_;
size_t remaining = input_file_->Length() - in_offset;
if (n > remaining) { ... error ... }
``` [3](#0-2) 

Because `in_offset` and `remaining` are `size_t` (unsigned), if the attacker-supplied `offset` pushes `p` beyond `zipdata_in_ + input_file_->Length()`, `in_offset > Length()` and the subtraction `Length() - in_offset` wraps around to a huge unsigned value. The subsequent check `n > remaining` is then always false, so the function reports success instead of erroring out. Parsing then proceeds via `get_u4le`/`get_u2le`/`get_u8le` (`third_party/ijar/common.h:39-72`) which dereference `p[0..n]` with no additional bounds checks, reading and advancing through memory well past the end of the mapped ZIP file — an out-of-bounds read directly analogous to the GPAC buffer-overflow class (a length/offset value taken from parsed input is used to index/read a buffer without a valid bounds check).

### Impact Explanation
This causes out-of-bounds reads beyond the mapped input file's buffer, which can crash the `ijar` process (denial of service for the build) or, depending on memory layout, cause the wild cursor to read adjacent heap/mapped memory and copy attacker-visible-length data into the tool's `filename`/`errmsg` buffers or the output artifact, potentially leaking process memory contents into build outputs or logs. Because `ijar` is invoked on arbitrary ZIP/JAR inputs (including third-party jars pulled into the build), a malicious jar can trigger this on the machine performing the build.

### Likelihood Explanation
Likelihood is high for triggering the crash/read: an attacker only needs to control the bytes of a ZIP file that `ijar` parses (e.g., a jar dependency), setting a central-directory `local_header_offset` field larger than the file length. No credentials, network position, or cooperation from Bazel's HTTP/download integrity layer is needed — this is a pure parser logic bug independent of checksum verification, since the ZIP content itself (whose bytes match a declared sha256) can still contain a malformed offset.

### Recommendation
Fix `EnsureRemaining` to avoid unsigned underflow, e.g.:
```cpp
int EnsureRemaining(size_t n, const char *state) {
  if (p < zipdata_in_ || (size_t)(p - zipdata_in_) > input_file_->Length()) {
    return error("Cursor out of file bounds at state=%s", state);
  }
  size_t in_offset = p - zipdata_in_;
  size_t remaining = input_file_->Length() - in_offset;
  if (n > remaining) {
    return error(...);
  }
  return 0;
}
```
Additionally, validate `offset` and `local_header_offset` against `input_file_->Length()` immediately after reading them in `ProcessCentralDirEntry` and before repositioning `p` in `ProcessNext`.

### Proof of Concept
A `BuildIntegrationTestCase`/unit test analogous to `src/tools/singlejar/output_jar_simple_test.cc:CreateZipWithMalformedExtraField` (which already demonstrates the pattern of crafting malformed ZIP metadata for testing) can be adapted for `third_party/ijar/zip.cc`:
1. Build a minimal valid ZIP with one entry.
2. In the Central Directory Header, set `local_header_offset` to a value larger than the total file length (e.g., `0xFFFFFFF0`).
3. Run `ijar`'s `InputZipFile::ProcessNext()` (via the `ijar` binary or a `IjarTests.java`-style harness under `third_party/ijar/test/`) on this crafted file.
4. Observe that `EnsureRemaining` fails to reject the out-of-range cursor (due to the underflow) and the subsequent `get_u4le(p)` reads out-of-bounds memory, causing a crash (ASan heap-buffer-overflow) or garbage signature interpretation instead of the expected "Premature end of file" error. bool InputZipFile::ProcessNext() {
  // Process the next entry in the central directory. Also make sure that the
  // content pointer is in sync.
  u8 compressed, uncompressed;
  u8 offset;
  if (!ProcessCentralDirEntry(central_dir_current_, &compressed, &uncompressed,
                              filename, PATH_MAX, &attr, &offset)) {
    return false;
  }

  // There might be an offset specified in the central directory that does
  // not match the file offset, so always update our pointer.
  p = zipdata_in_ + in_offset_ + offset;

  if (EnsureRemaining(4, "signature") < 0) {
    return false;
  }
  u4 signature = get_u4le(p);
  if (signature == LOCAL_FILE_HEADER_SIGNATURE) {
    if (ProcessLocalFileEntry(compressed, uncompressed) < 0) {
      return false;
    }
  } else {
    error("local file header signature for file %s not found\n", filename);
    return false;
  }

  return true;
}

bool InputZipFile::ProcessCentralDirEntry(const u1 *&p, u8 *compressed_size,
                                          u8 *uncompressed_size, char *filename,
                                          size_t filename_size, u4 *attr,
                                          u8 *offset) {
  u4 signature = get_u4le(p);

  if (signature != CENTRAL_FILE_HEADER_SIGNATURE) {
    if (signature != DIGITAL_SIGNATURE && signature != EOCD_SIGNATURE &&
        signature != ZIP64_EOCD_SIGNATURE) {
      error("invalid central file header signature: 0x%x\n", signature);
    }
    return false;
  }

  p += 16;  // skip to 'compressed size' field
  *compressed_size = get_u4le(p);
  *uncompressed_size = get_u4le(p);
  u2 file_name_length = get_u2le(p);
  u2 extra_field_length = get_u2le(p);
  u2 file_comment_length = get_u2le(p);
  p += 4;  // skip to external file attributes field
  *attr = get_u4le(p);
  *offset = get_u4le(p);
  {
    size_t len = (file_name_length < filename_size)
      ? file_name_length
      : (filename_size - 1);
    memcpy(reinterpret_cast<void*>(filename), p, len);
    filename[len] = 0;
  }
  p += file_name_length;
  const u1 *extra_p = p;
  p += extra_field_length;
  while (extra_p != p) {
    const u2 header_id = get_u2le(extra_p);
    const u2 data_size = get_u2le(extra_p);
    const u1 *extra = extra_p;
    extra_p += data_size;
    if (header_id == ZIP64_EXTRA_FIELD_TAG) {
      if (*uncompressed_size == U4_MAX) {
        *uncompressed_size = get_u8le(extra);
      }
      if (*compressed_size == U4_MAX) {
        *compressed_size = get_u8le(extra);
      }
      if (*offset == U4_MAX) {
        *offset = get_u8le(extra);
      }
    }
  }
  p += file_comment_length;
  return true;
}

inline u2 get_u2be(const u1 *&p) {

inline u2 get_u2le(const u1 *&p) {
    u4 x = (p[1] << 8) | p[0];
    p += 2;
    return x;
}

inline u4 get_u4be(const u1 *&p) {
    u4 x = (p[0] << 24) | (p[1] << 16) | (p[2] << 8) | p[3];
    p += 4;
    return x;
}

inline u4 get_u4le(const u1 *&p) {
    u4 x = (p[3] << 24) | (p[2] << 16) | (p[1] << 8) | p[0];
    p += 4;
    return x;
}

inline u8 get_u8le(const u1 *&p) {
  u4 lo = get_u4le(p);
  u4 hi = get_u4le(p);
  u8 x = ((u8)hi << 32) | lo;
  return x;
