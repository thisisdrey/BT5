### Title
RewardsDistributor credits `INITIAL_INDEX` worth of rewards to uninitialized accounts when an update is triggered in the same block the token speed is set - ([File: contracts/RewardsDistributor.sol](contracts/RewardsDistributor.sol))

### Summary
Analogous to CVE-2023-6683 — where `qemu_clipboard_request()` can be invoked before the one-time capability handshake initializes the clipboard peer, dereferencing NULL — `RewardsDistributor._calculateTokenDelta()` dereferences `accountIndexOf[token][account]` while it is still `0` (uninitialized) in the window where `tokenStates[token].index` equals exactly `INITIAL_INDEX`. The fallback that treats a `0` account index as `INITIAL_INDEX` only fires when the token index is *strictly greater* than `INITIAL_INDEX`, so an uninitialized account is credited `balance * INITIAL_INDEX` of accrued rewards instead of zero. [1](#0-0) 

### Finding Description
When the governor first enables rewards for a token, `_updateTokenSpeed()` stores `TokenState({index: INITIAL_INDEX /* 1e18 */, timestamp: block.timestamp})` and pushes the token into `tokens[]`. [2](#0-1) 

From that point, `claimRewards()` and `updateBeforeMintOrBurn()`/`updateBeforeTransfer()` enter their `index > 0` branches. [3](#0-2) [4](#0-3) 

In the same block (or before any later call that bumps the index), `_updateTokenIndex()` computes `_deltaTimestamps = block.timestamp - timestamp == 0`, so the stored index stays exactly `INITIAL_INDEX`. [5](#0-4) 

`_calculateTokenDelta()` then reads `accountIndexOf[token][account]`, which is `0` for any account that has never been checkpointed. The initialization fallback only applies when `_tokenIndex > INITIAL_INDEX`; when `_tokenIndex == INITIAL_INDEX`, `_accountIndex` remains `0` and `_deltaIndex = 1e18`, so `_tokensDelta = balance * 1e18` (i.e., the account's full token balance) is added to `tokensAccruedOf`. [6](#0-5) [7](#0-6) 

`claimRewards()` then pays out `tokensAccruedOf[account]` in `rewardToken` as long as the contract's balance covers it. [8](#0-7) 

### Impact Explanation
The reward-accrual invariant "an account accrues `balance * (indexNow - indexAtAccountCheckpoint)`" breaks because the account's checkpoint was never initialized before the index was dereferenced. An attacker holding `D` units of a freshly reward-enabled `DepositToken`/`DebtToken` receives `D` reward tokens (1:1, since `wadMul(1e18)` is identity) for free, immediately claimable up to the distributor's entire `rewardToken` balance. This is theft of unclaimed yield belonging to all legitimate depositors/borrowers: the attacker drains reward reserves that were funded for future distribution. The attack scales with attacker-held balance and can be repeated across multiple accounts/sybil positions, and across each token at the moment its speed is first set.

### Likelihood Explanation
- Attacker model fits: fully reachable by an unprivileged EOA via public `claimRewards(address, IERC20[])`, `updateBeforeMintOrBurn`, or any `DepositToken`/`DebtToken` transfer/mint that triggers the distributor hook.
- Pre-positioning is cheap: deposit collateral into a `DepositToken` *before* rewards are enabled (index stays `0`, `updateBeforeMintOrBurn` is a no-op, `accountIndexOf` stays `0`).
- The trigger only requires executing in the same block as a governor `updateTokenSpeed`/`updateTokenSpeeds`/`syncTokenSpeed` transaction (back-run it), before the first index bump; mempool observation of a public governance call is sufficient. Note `syncTokenSpeed` can be invoked by `tokenSpeedKeeper` (a keeper, not governor), which widens the set of observable triggering transactions. [9](#0-8) 
- No guard stops it: `claimRewards` is `nonReentrant` but unrestricted for claiming one's own accrual; `nonReentrant`, `whenNotPaused`, and `SynthContext` are irrelevant here.

### Recommendation
In `_calculateTokenDelta()`, treat an uninitialized account index as `INITIAL_INDEX` whenever the account has never been checkpointed, not only when the token index exceeds it:

```solidity
// contracts/RewardsDistributor.sol
if (_accountIndex == 0) {
    _accountIndex = _tokenIndex >= INITIAL_INDEX ? _tokenIndex : INITIAL_INDEX;
}
```

Alternatively, checkpoint `accountIndexOf` at `INITIAL_INDEX` in `updateBeforeMintOrBurn`/`updateBeforeTransfer` before any balance-affecting operation on a token whose state was just initialized, or start `_deltaIndex` accounting from `max(_accountIndex, INITIAL_INDEX)`.

### Proof of Concept
Foundry fork-style reproduction (Hardhat equivalent works with the existing fixture pattern in `test/RewardsDistributor.test.ts`):

```solidity
// Setup: pool, depositToken (msdX), rewardToken (MET) funded into rewardsDistributor.
// Attacker holds depositToken balance BEFORE rewards are enabled.
underlying.mint(attacker, 1000e18);
vm.prank(attacker);
msdX.deposit(1000e18); // tokenStates[msdX].index == 0 -> hook no-ops, accountIndexOf stays 0

// Fund the distributor
met.mint(address(rewardsDistributor), 1000e18);

// Governor enables speed; attacker back-runs in the SAME block.
vm.prank(governor);
rewardsDistributor.updateTokenSpeed(msdX, 1e12); // index = 1e18, timestamp = now

vm.prank(attacker);
rewardsDistributor.claimRewards(attacker, tokens); // tokens = [msdX]

// Assert: attacker received ~1000e18 MET despite zero time elapsed
assertGt(met.balanceOf(attacker), 0);
```

Root cause trace: `tokenStates[msdX].index == INITIAL_INDEX`, `_deltaTimestamps == 0` so `_updateTokenIndex` no-ops, `_calculateTokenDelta` skips the `_tokenIndex > INITIAL_INDEX` fallback, `_deltaIndex == 1e18`, `_tokensDelta == balanceOf(attacker)`, and `_transferRewardIfEnoughTokens` pays out. [10](#0-9) [11](#0-10) 

One caveat I could not fully verify within the available context: whether the deployed `DepositToken` blocks same-block withdrawal after `deposit()` via `_revertIfLocked`. If it does, the attacker must hold the deposit past the lock (or use multiple accounts), which raises capital requirements but does not remove the issue — the reward payout itself is same-block and the principal is recoverable afterward.

    function _calculateTokenIndex(
        TokenState memory _supplyState,
        IERC20 token_
    ) private view returns (uint224 _newIndex, uint32 _newTimestamp) {
        uint256 _speed = tokenSpeeds[token_];
        uint256 _deltaTimestamps = block.timestamp - uint256(_supplyState.timestamp);
        if (_deltaTimestamps > 0 && _speed > 0) {

            _newTimestamp = block.timestamp.toUint32();
        } else if (_deltaTimestamps > 0 && _supplyState.index > 0) {
            _newTimestamp = block.timestamp.toUint32();
        }
    }

    function _calculateTokenDelta(
        TokenState memory _tokenState,
        IERC20 token_,
        address account_
    ) private view returns (uint256 _tokenIndex, uint256 _tokensDelta) {
        _tokenIndex = _tokenState.index;
        uint256 _accountIndex = accountIndexOf[token_][account_];

        if (_accountIndex == 0 && _tokenIndex > INITIAL_INDEX) {
            _accountIndex = INITIAL_INDEX;
        }

        uint256 _deltaIndex = _tokenIndex - _accountIndex;
        _tokensDelta = token_.balanceOf(account_).wadMul(_deltaIndex);
    }
