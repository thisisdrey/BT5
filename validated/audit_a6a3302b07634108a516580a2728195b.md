### Title
Pingback handshake validation checks only the public-key hash, not the address, allowing an attacker to write a forged (pubkey_hash, victim_address) neighbor entry into `PeerDB` - ([File: stackslib/src/net/neighbors/walk.rs])

### Summary
`NeighborWalk::check_handshake_pubkey_hash` only verifies that `Hash160::from_node_public_key_buffer(&data.handshake.node_public_key)` equals `naddr.public_key_hash`; it never checks that `data.handshake.addrbytes`/`port` match the address that was actually dialed for the pingback (`naddr`). `pingback_handshakes_try_finish` then forwards the whole self-reported `data.handshake` (including the attacker-controlled `addrbytes`/`port`) into `NeighborDB::add_or_schedule_replace_neighbor`, which persists it verbatim into the `PeerDB` frontier via `PeerDB::insert_or_replace_peer`.

### Finding Description
The invariant that should hold before storing a neighbor record is: "the `addrbytes`/`port` written to the frontier for a given `public_key_hash` equal the address that was verified to be reachable and to respond with a key matching that hash." This invariant is broken:

- `check_handshake_pubkey_hash` (`stackslib/src/net/neighbors/walk.rs:1664-1680`) computes `neighbor_pubkey_hash` from `data.handshake.node_public_key` and compares only against `naddr.public_key_hash`. It never touches `data.handshake.addrbytes`/`port`. [1](#0-0) 
- `pingback_handshakes_try_finish` computes `peer_nk` from `data.handshake.addrbytes`/`port` purely for logging/lookup purposes, calls `check_handshake_pubkey_hash` (which ignores that address), and then unconditionally calls `self.neighbor_db.add_or_schedule_replace_neighbor(network, &message.preamble, &data.handshake, db_data, ...)`, passing the full self-reported `HandshakeData` (including `addrbytes`/`port`) through. [2](#0-1) 
- `PeerDBNeighborWalk::add_or_schedule_replace_neighbor` builds the `Neighbor` record via `Neighbor::load_and_update(&tx, preamble.peer_version, preamble.network_id, handshake)`, which derives the neighbor's `NeighborKey`/`addr` from the handshake's self-reported `addrbytes`/`port` fields, then calls `neighbor_from_handshake.save(...)` / `.save_update(...)`, which ultimately calls `PeerDB::insert_or_replace_peer`, writing that self-reported address into the `frontier` table. [3](#0-2) [4](#0-3) 

The actual TCP session for the pingback is established by the victim node dialing `naddr` (via `self.comms.neighbor_session_begin(network, &naddr)` in `pingback_handshakes_begin`), so the *transport* endpoint that answers is whatever peer legitimately owns/controls that `naddr` address — which can be an attacker-operated peer if the attacker previously caused `naddr` (with a matching `public_key_hash`) to be scheduled for pingback (e.g., by self-reporting that address in a prior unsolicited handshake or gossip entry). [5](#0-4) 

Because the attacker fully controls the payload of the `HandshakeAccept`/`StackerDBHandshakeAccept` it sends back over that legitimately-dialed connection, it can set `data.handshake.node_public_key` to match `naddr.public_key_hash` (satisfying the only check performed) while setting `data.handshake.addrbytes`/`port` to an arbitrary third-party victim IP:port. `check_handshake_pubkey_hash` passes, and the victim's IP:port is written into the responding node's `PeerDB` frontier, associated with the attacker's public key, with no verification that the victim's address was ever actually reachable, dialed, or responsive.

### Impact Explanation
A remote, unprivileged attacker (any peer that can get itself scheduled for a pingback handshake, e.g. by connecting inbound and self-reporting a reachable address) can cause an unauthenticated write of an arbitrary, attacker-chosen `(public_key_hash, victim_addrbytes, victim_port)` tuple into another node's `PeerDB` frontier table. This is an unauthenticated write to persistent node state as defined by the Critical category, and it is repeatable per pingback event/connection cycle. Downstream effects include the victim's IP:port being advertised in the frontier (and thus potentially re-gossiped to other peers via `GetNeighbors`/`Neighbors` exchanges), and future neighbor-walk attempts by the compromised node targeting the victim's address, since the record now exists in its frontier.

### Likelihood Explanation
Preconditions are modest and attacker-achievable without any privileged role: the attacker only needs to run its own peer, get itself into the local node's `network_pingbacks` map (by connecting inbound and providing a self-reported/gossiped `NeighborAddress` under its own control), then answer the resulting pingback dial with a crafted `HandshakeAccept`/`StackerDBHandshakeAccept` whose `node_public_key` hashes to `naddr.public_key_hash` (trivial, since the attacker controls both the key used to establish `naddr`'s hash and the handshake reply) but whose `addrbytes`/`port` name an arbitrary victim. No secret, signature over the address field, or additional authentication is required beyond what any peer already possesses to complete a normal handshake. The attack is repeatable at will and only requires reachability to the target node's P2P port.

### Recommendation
In `check_handshake_pubkey_hash` (and equivalently in the general handshake-accept path `handle_neighbor_handshake_accept`), additionally verify that `data.handshake.addrbytes`/`port` match the actually-dialed/verified address (`naddr.addrbytes`/`port`, or the underlying socket's peer address) before accepting the handshake, rejecting mismatches instead of silently persisting attacker-chosen address data. Alternatively, when storing the neighbor, use the verified connection address (`naddr`) rather than the self-reported `handshake.addrbytes`/`port` for the `PeerDB` key.

### Proof of Concept
Add a test in `stackslib/src/net/neighbors/walk.rs` (or a new test in `stackslib/src/net/tests/neighbors.rs`) that:
1. Constructs a `naddr: NeighborAddress` with `public_key_hash = Hash160::from_node_public_key(&attacker_pubkey)`.
2. Builds a `HandshakeAcceptData` whose `handshake.node_public_key` is `attacker_pubkey` (so `Hash160::from_node_public_key_buffer(...) == naddr.public_key_hash`) but whose `handshake.addrbytes`/`port` are set to an arbitrary "victim" `PeerAddress`/port unrelated to `naddr`.
3. Calls `NeighborWalk::check_handshake_pubkey_hash(&nk, &data, &naddr)` and asserts it returns `true` despite the address mismatch.
4. Calls `neighbor_db.add_or_schedule_replace_neighbor(...)` with this data and asserts that `PeerDB::get_peer(...)` (queried by the victim's `addrbytes`/`port`) now returns a `Neighbor` whose `public_key` is the attacker's key — demonstrating the forged frontier entry stored under the victim's address.

    fn check_handshake_pubkey_hash(
        nk: &NeighborKey,
        data: &HandshakeAcceptData,
        naddr: &NeighborAddress,
    ) -> bool {
        let neighbor_pubkey_hash =
            Hash160::from_node_public_key_buffer(&data.handshake.node_public_key);
        if neighbor_pubkey_hash != naddr.public_key_hash {
            debug!(
                "Neighbor {:?} had an unexpected pubkey hash: expected {:?} != {:?}",
                nk, &naddr.public_key_hash, &neighbor_pubkey_hash
            );
            return false;
        }

        true
    }

        replacements: &mut NeighborReplacements,

        let local_peer_str = format!("{:?}", network.get_local_peer());
        let tx = network.peerdb_tx_begin()?;
        let (mut neighbor_from_handshake, was_present) =
            Neighbor::load_and_update(&tx, preamble.peer_version, preamble.network_id, handshake)?;

        if was_present {
            test_debug!(
                "{}: already know about neighbor {:?}",
                &local_peer_str,
                &neighbor_from_handshake.addr
            );
            neighbor_from_handshake
                .save_update(&tx, db_data.map(|x| x.smart_contracts.as_slice()))?;
            tx.commit()?;

            // seen this neighbor before
            return Ok((false, neighbor_from_handshake));
        }

            "{}: new neighbor {:?}",
            &local_peer_str, &neighbor_from_handshake.addr
        );

        // didn't know about this neighbor yet. Try to add it.
        let added =
            neighbor_from_handshake.save(&tx, db_data.map(|x| x.smart_contracts.as_slice()))?;

        if added {
            // neighbor was new, and we had space to add it.
            tx.commit()?;
            return Ok((true, neighbor_from_handshake));
