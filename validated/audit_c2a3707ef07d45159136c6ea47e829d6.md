### Title
Unauthenticated `/shutdown` POST permanently kills SignerEventReceiver, dropping all future signer events - (File: libsigner/src/events.rs)

### Summary
The signer's event-receiver HTTP server accepts a `POST /shutdown` on its listening socket and immediately sets `stop_signal` to `true` with no authentication, size limit, or origin check. Any remote party with TCP reach to this port can permanently stop the signer's `main_loop`, silently dropping all subsequent legitimate `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, and `/new_block` events forwarded from the node.

### Finding Description
In `next_event` (`libsigner/src/events.rs:413-459`), requests are dispatched purely by URL path with no authentication check anywhere in the function. The `/shutdown` branch unconditionally executes `event_receiver.stop_signal.store(true, Ordering::SeqCst); Err(EventError::Terminated)` [1](#0-0) . Back in `main_loop` (`libsigner/src/events.rs:284-312`), an `Err(EventError::Terminated)` causes an immediate `break`, and the `is_stopped()` check at the top of the loop (via `stop_signal.load(Ordering::SeqCst)`) also prevents the loop from ever restarting [3](#0-2) . This is precisely the same mechanism intentionally used by the legitimate `SignerStopSignaler::send()` to shut the receiver down cleanly [4](#0-3) , but it is exposed on the wire with no distinguishing secret between a legitimate internal shutdown and an external attacker's POST.

The `auth_password`/`auth_token` pair documented in the sample configs only authenticates the signer's calls *into* the node's block-proposal RPC endpoint, not the node's push of events *into* this listener [5](#0-4) . Nothing in `next_event` validates a shared secret, source IP, or any header before honoring `/shutdown`.

### Impact Explanation
A single unauthenticated POST permanently disables a signer's event ingestion path: the `main_loop` thread exits and is never restarted (no supervising restart logic accompanies it in this file), so the signer stops receiving `StackerDBChunksEvent`, block-proposal validation responses, and burn/stacks block events from its node indefinitely, until the signer process is manually restarted. This is a valid-message-drop, unauthenticated DoS of the signer transport — matching the Critical "remote crash/unauthenticated DoS from few messages" category. Because signer participation is required for block signing, taking a signer's event pipe offline can degrade or deny that signer's contribution to the network.

### Likelihood Explanation
The only precondition is TCP reachability to the signer's configured `endpoint`. This is attacker-cheap: exactly one HTTP POST with no body and no valid session/credential is needed, and it is trivially repeatable against every reachable signer. The sample configuration ships with `endpoint = "0.0.0.0:30000"`, i.e., listening on all interfaces rather than localhost-only, making external reachability realistic depending on deployment/firewalling.

### Recommendation
Require the shared `auth_password`/`auth_token` (or an equivalent secret/HMAC) to be validated for the `/shutdown` path (and ideally all paths) in `next_event` before acting on it, or restrict the stop signal to a local-only mechanism (e.g., a Unix domain socket, an in-process channel, or checking `request.remote_addr()` against `127.0.0.1`) instead of an unauthenticated network path.

fn test_unauthenticated_shutdown_kills_receiver() {
    let mut receiver: SignerEventReceiver<SomeSignerMessageType> = SignerEventReceiver::new(false);
    let addr = receiver.bind("127.0.0.1:0".parse().unwrap()).unwrap();
    let (tx, rx) = std::sync::mpsc::channel();
    receiver.add_consumer(tx);

    let handle = std::thread::spawn(move || receiver.main_loop());

    // Attacker sends unauthenticated shutdown with no body, no credentials
    let mut stream = TcpStream::connect(addr).unwrap();

    drop(stream);

    // main_loop exits promptly
    handle.join().unwrap();

    // A subsequent legitimate event posted to the same port never arrives
    // (connection will fail/timeout since the HttpServer thread has stopped serving)
    let mut stream2 = TcpStream::connect(addr);
    assert!(stream2.is_err() || rx.try_recv().is_err());
}
