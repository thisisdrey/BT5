### Title
Unstaked connection table pruning runs before the per-peer connection cap is enforced, letting a single unstaked attacker force free evictions of other unstaked peers' connections - ([File: streamer/src/nonblocking/swqos.rs])

### Finding Description
`SwQos::prune_unstaked_connections_and_add_new_connection` unconditionally calls `prune_unstaked_connection_table` *before* attempting to add the caller's own connection: [1](#0-0) 

`prune_unstaked_connection_table` prunes the shared `unstaked_connection_table` down to 90% capacity via `ConnectionTable::prune_oldest` whenever `total_size >= max_unstaked_connections`, regardless of whether the new connection being processed will ultimately be accepted: [2](#0-1) 

The actual add attempt happens afterward in `cache_new_connection` → `ConnectionTable::try_add_connection`, which enforces `max_connections_per_unstaked_peer` per `ConnectionTableKey` (IP or pubkey) and rejects (and closes) the connection with `CONNECTION_CLOSE_CODE_TOO_MANY` if the caller's own key is already at capacity: [3](#0-2) 

`ConnectionTable::prune_oldest` evicts whole key-groups (i.e., all connections belonging to one IP/pubkey) purely by lowest `last_update`, with no notion of which peer triggered the prune: [4](#0-3) 

Exploit flow: once an unstaked attacker's own IP-keyed entry has reached `max_connections_per_unstaked_peer`, every additional QUIC connection the attacker opens from that same IP is doomed to be rejected by `try_add_connection`'s per-peer cap check. However, if `unstaked_connection_table.total_size` is already at or above `max_unstaked_connections` (a state that is normal/expected on a busy leader, since the table is shared across all unstaked peers), each such doomed attempt still triggers `prune_unstaked_connection_table`, which evicts the globally oldest 10% of table *entries* (potentially many distinct innocent unstaked peers, each losing all of their cached connections) before the attacker's own add is even attempted and rejected. The attacker pays only the cost of a QUIC handshake per attempt and gains nothing themselves, while other unstaked peers' active connections are evicted at no benefit to the network - this is a pure griefing amplification because a single failed connection attempt can cause eviction of multiple unrelated peers' connection-table entries at once (`PRUNE_TABLE_RATIO = 0.90`).

None of the existing guards prevent this: the per-peer cap (`max_connections_per_unstaked_peer`) only limits how many connections *that key* can hold, not whether a doomed attempt from that key can still trigger the shared-table prune; there is no check that the caller's own add will succeed before paying the eviction cost.

### Impact Explanation
This breaks the fairness invariant of the shared unstaked connection table: a single unpriviledged unstaked attacker IP, once at its own per-peer connection cap, can continue to spend cheap QUIC handshakes purely to force `prune_oldest` evictions of other unstaked peers' cached connections, without ever succeeding in adding a connection itself. This is an availability/fairness (QoS evasion) issue affecting legitimate unstaked senders' ability to retain TPU connections on a leader, falling under the DoS/QoS-fairness bounty category for the streamer/QUIC ingress path.

### Likelihood Explanation
Precondition is simply that `unstaked_connection_table.total_size >= max_unstaked_connections`, which is a routine, easily reached state under normal mainnet unstaked traffic load (the table is intentionally sized to be at or near capacity). No staked/gossip/peer privileges are required - only an unstaked remote client able to open repeated QUIC connections to the leader's public TPU port, which is exactly the attacker model in scope. The attack is trivially repeatable and requires no coordination beyond one IP.

### Recommendation
Reorder the logic in `prune_unstaked_connections_and_add_new_connection` (and the analogous staked-overflow path) so that the shared-table prune is only performed if the caller's own connection is actually eligible to be added (e.g., check the per-peer/per-key capacity for `conn_context`'s key against `max_connections_per_unstaked_peer` before calling `prune_unstaked_connection_table`), or perform the prune and add atomically such that a doomed add (rejected by `try_add_connection`'s per-peer cap) never causes the shared table to be pruned.

### Proof of Concept
Add a unit test in `streamer/src/nonblocking/swqos.rs` (or `quic.rs` alongside the existing `ConnectionTable` tests) that:
1. Constructs an `SwQos`/`ConnectionTable` with `max_connections_per_unstaked_peer = 1` and `max_unstaked_connections = N`.
2. Fills the table to `N` with `N` distinct legitimate unstaked IPs (1 connection each, staggered `last_update`).
3. From a single attacker IP, calls `try_add_connection` once (fills attacker's own cap of 1), then calls it again from the *same* attacker IP/key while the table is still at `total_size == N`.
4. Assert that despite the second attacker attempt being rejected by `try_add_connection`'s per-peer cap (returns `None`, connection closed with `CONNECTION_CLOSE_CODE_TOO_MANY`), `prune_unstaked_connection_table`/`prune_oldest` still ran and evicted the globally oldest legitimate entries (`table.total_size` dropped to ~90% of `N`), demonstrating that a doomed attacker connection attempt caused eviction of other unstaked peers' entries with zero benefit to the attacker.
5. Repeat the attacker-only doomed attempts in a loop while re-adding legitimate connections to refill the table, and assert legitimate peers' table share shrinks disproportionately relative to their own churn rate, confirming the fairness violation described in the question's fuzz/invariant proof idea.

    pub(crate) fn prune_oldest(&mut self, max_size: usize) -> usize {
        let mut num_pruned = 0;
        let key = |(_, connections): &(_, &Vec<_>)| {
            connections.iter().map(ConnectionEntry::last_update).min()
        };
        while self.total_size.saturating_sub(num_pruned) > max_size {
            match self.table.values().enumerate().min_by_key(key) {
                None => break,
                Some((index, connections)) => {
                    num_pruned += connections.len();
                    self.table.swap_remove_index(index);
                }
            }
        }
        self.total_size = self.total_size.saturating_sub(num_pruned);
        num_pruned
    }
