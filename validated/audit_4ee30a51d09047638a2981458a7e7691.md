### Title
Protocol fee bypass on NEP-245/IMT `TokenDiff` intents by splitting a large negative delta into unit `amount == 1` chunks - (File: contracts/defuse/core/src/intents/token_diff.rs)

### Summary
`TokenDiff::token_fee` waives fees on NEP-245/IMT assets whenever the *individual intent's* `unsigned_abs()` amount is `<= 1`. Since `TokenDiff::execute_intent` computes and collects the fee independently for each `TokenDiff` intent it processes (per `Intent` in a `DefuseIntents.intents` vector, or across multiple `MultiPayload`s in one `execute_intents` call) rather than on the aggregate net delta per `TokenId` across the whole batch, a signer can split one large negative MT/IMT delta into many `-1` deltas and pay zero fee on the aggregate transfer.

### Finding Description
The broken binding: `fee_owed_on_aggregate_negative_delta_for_TokenId(T) == sum_of_fees_collected_by_execute_intent_over_all_TokenDiff_intents_touching_T_in_the_batch`. This should hold for any decomposition of a fixed net transfer, but it does not.

`TokenDiff::execute_intent` iterates `self.diff` (a single intent's `BTreeMap<TokenId, i128>`) and, for each negative entry, computes the fee from that entry's own `amount = delta.unsigned_abs()`: [1](#0-0) 

`token_fee` explicitly exempts `Nep245`/`Imt` when `amount <= 1`: [2](#0-1) 

Because `Engine::execute_signed_intents` runs each `MultiPayload` (each carrying its own `DefuseIntents.intents: Vec<Intent>`) independently and calls `execute_intent` once per intent, fee computation never sees the total delta for a `TokenId` across the batch — only whatever amount is contained in one `TokenDiff.diff` entry: [3](#0-2) [4](#0-3) 

The only global constraint enforced across the batch is that per-`TokenId` deposits and withdrawals must net to zero, via `TransferMatcher`/`Deltas::finalize`: [5](#0-4) [6](#0-5) 

This constraint checks *balance conservation*, not fee correctness — it does not require that the fee charged matches what a single equivalent `TokenDiff` would have owed. So a signer holding NEP-245 balance `N > 1` of some sub-token can sign a single `MultiPayload` whose `DefuseIntents.intents` contains `N` separate `TokenDiff` intents, each `{token_id: -1, other_token_id: +k}`, with a counterparty contributing the matching `+N`/`-N*k` side in one or more intents. Each of the `N` intents individually satisfies `amount == 1`, so `token_fee` returns `Pips::ZERO` for every one of them, and `fees_collected` accumulates nothing for that `TokenId`, even though the real, aggregate transfer moved `N` units and would have incurred a nonzero fee had it been expressed as one `TokenDiff{token_id: -N, ...}`.

No existing guard prevents this: `MultiPayload::verify`, nonce/salt checks, and `TransferMatcher::finalize` all operate on signature validity and balance conservation, none of them re-derive or cap the fee based on aggregated deltas per token across intents in the batch.

### Impact Explanation
This is a protocol fee bypass matching the Critical category "protocol fees bypassed... for MT transfers." The fee that should have been credited to `fee_collector` via `internal_add_balance(fee_collector, fees_collected)` is never collected for the NEP-245/IMT leg of the trade, so value that should have accrued to the fee collector stays with the trading parties instead. The bypass is fully repeatable: any account holding a divisible NEP-245/IMT balance greater than 1 unit can apply this technique to any trade, on every `execute_intents` call, for any `Nep245`/`Imt` `TokenId`, with no bound other than batch/gas size for `N`. It does not require privileged roles, key compromise, or a locked account — any signer with a counterparty (which could itself be a colluding second key/account controlled by the same attacker, or a normal solver counterparty who is agnostic to how the maker split their side) can execute it.

### Likelihood Explanation
Preconditions are minimal and fully attacker-controlled: the attacker just needs (a) an NEP-245 or IMT balance `N > 1` in Defuse, (b) a willing counterparty for the other leg of the swap (a solver, or even the attacker's own second account), and (c) the ability to construct a `MultiPayload` with `N` `TokenDiff` intents (or spread across multiple signed payloads in one `execute_intents` call). No relayer key, DAO role, or upgrade capability is needed. Cost is bounded by NEAR gas for executing `N` intents in one transaction; this is directly proportional to how much fee is being avoided, but for realistic `N` (tens to low hundreds) fits comfortably within a single call's gas limit as evidenced by the referenced "swap_many" batch tests already exercising many `TokenDiff` intents in one payload.

### Recommendation
Compute the NEP-245/IMT fee-exemption threshold on the *net* delta per `TokenId` across the whole set of intents processed within `execute_signed_intents`/`Engine`, not per individual `TokenDiff` intent. Concretely, accumulate per-`TokenId` negative deltas in `Deltas`/`Engine` state before invoking `token_fee`, and only apply the `amount <= 1` exemption when the total negative delta for that `TokenId` in the entire batch (across all `TokenDiff` intents from all payloads) is `<= 1`. Alternatively, remove the amount-based exemption for `Nep245`/`Imt` entirely (charge the standard `fee` in all cases, matching NEP-141 behavior), eliminating the exploitable boundary condition.

    fn execute_signed_intent(&mut self, signed: MultiPayload) -> Result<()> {
        // verify signed payload and get public key
        let public_key = signed.verify().ok_or(DefuseError::InvalidSignature)?;

        // calculate intent hash
        let hash = signed.hash();

        // extract NEP-413 payload
        let DefusePayload::<DefuseIntents> {
            signer_id,
            verifying_contract,
            deadline,
            nonce,
            message: intents,
        } = signed.extract_defuse_payload()?;

        // check recipient
        if verifying_contract != *self.state.verifying_contract() {
            return Err(DefuseError::WrongVerifyingContract);
        }

        self.inspector.on_deadline(deadline);

        // make sure message is still valid
        if deadline < Timestamp::now() {
            return Err(DefuseError::DeadlineExpired);
        }

        // make sure the account has this public key
        if !self.state.has_public_key(&signer_id, &public_key) {
            return Err(DefuseError::PublicKeyNotExist(signer_id, public_key));
        }

        // commit nonce
        self.verify_intent_nonce(nonce, deadline)?;
        self.state.commit_nonce(signer_id.clone(), nonce)?;

        intents.execute_intent(&signer_id, self, hash)?;
        self.inspector.on_intent_executed(&signer_id, hash, nonce);

        Ok(())
    }

    // Finalizes all transfers, or returns unmatched deltas.
    // If unmatched deltas overflow, then Err(None) is returned.
    pub fn finalize(self) -> Result<Transfers, InvariantViolated> {
        let mut transfers = Transfers::default();
        let mut deltas = TokenDeltas::default();
        for (token_id, transfer_matcher) in self.0 {
            if let Err(unmatched) = transfer_matcher.finalize_into(&token_id, &mut transfers)
                && (unmatched == 0 || deltas.apply_delta(token_id, unmatched).is_none())
            {
                return Err(InvariantViolated::Overflow);
            }
        }
        if !deltas.is_empty() {
            return Err(InvariantViolated::UnmatchedDeltas {
                unmatched_deltas: deltas,
            });
        }
        Ok(transfers)
    }
