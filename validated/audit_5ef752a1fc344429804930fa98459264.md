### Title
Unbounded per-item resource consumption in `GetBlobs` RPC due to uncapped `RevisionPaths` batch - (File: `internal/gitaly/service/blob/get_blobs.go`)

### Summary
The `GetBlobs` RPC accepts a `repeated RevisionPath revision_paths` field [1](#0-0)  and, for every entry, performs a tree-walk lookup plus one or two `git-cat-file` object accesses, with no upper bound on the number of entries the caller may supply [2](#0-1) . This mirrors the reported bug class: iterating an attacker/user-controlled list and performing multiple expensive per-item lookups without any batch-size cap, which can exhaust server-side resources or a hard platform limit.

### Finding Description
`sendGetBlobsResponse` loops over `req.GetRevisionPaths()` with no length validation — `validateGetBlobsRequest` only checks that the list is non-empty and that each revision is a syntactically valid revision string; it never caps the number of entries [3](#0-2) .

For each entry, the handler calls `tef.FindByRevisionAndPath`, which resolves and parses an entire tree object via `git cat-file` (`TreeEntries`) unless the exact `(revision, dir)` pair was already cached in this request [4](#0-3) [5](#0-4) . If a caller supplies many distinct `(revision, path)` combinations (e.g., many different directories, or many different revisions), the tree cache provides no benefit and each entry triggers a fresh `git cat-file` object read and a full tree parse. Additionally, for every successfully resolved blob entry the handler performs a further `objectInfoReader.Info` call and, if it is a blob, a full/partial content read via `objectReader.Object` [6](#0-5) .

Because the `revision_paths` field is only bounded by gRPC's overall message-size limit (not by an item count), an attacker can pack a very large number of small `RevisionPath` entries (each just a short revision string and a path) into a single request, each of which forces a distinct, non-cached tree walk and object lookup. This is analogous to the reported `distribute_funds()` pattern of looping over an unbounded user-supplied set and doing multiple "storage" accesses per element without any batch cap.

### Impact Explanation
Each iteration spawns/interacts with the shared `git-cat-file` batch process associated with the request's `catfileCache.ObjectReader`/`ObjectInfoReader` [7](#0-6) , and each cache-miss walk parses a full tree object (`extractEntryInfoFromTreeData`) proportional to that tree's size [8](#0-7) . A single unary RPC with tens of thousands of distinct revision/path pairs can therefore consume large amounts of CPU and I/O on the Gitaly node processing an ordinary read RPC, degrading service for other tenants/repositories served by the same node (denial of service). This is reachable by any client authorized to call `GetBlobs` on a repository (an ordinary, unprivileged RPC consumer), not just a privileged actor.

### Likelihood Explanation
`GetBlobs` is a standard accessor RPC exposed to any client with repository read access (e.g., via GitLab's Gitaly client). Constructing a request with a large number of `RevisionPath` entries requires no special privileges — only knowledge of a repository's tree structure or (for the "missing" fast-path) arbitrary bogus paths, which still cause a tree lookup per unique `(revision, path)` pair before returning "not found." The request size limit is the standard gRPC max message size, which still permits tens of thousands of small string pairs.

### Recommendation
Introduce an explicit maximum on `len(req.GetRevisionPaths())` in `validateGetBlobsRequest` (mirroring pagination/limit patterns already used elsewhere in Gitaly, e.g. `ListRefsRequest.PaginationParameter` and `GetBlobsRequest.Limit` for byte size) [3](#0-2) . Consider also bounding the number of distinct `(revision, path)` cache misses processed per request or adding server-side request-cost accounting (e.g., total tree entries walked) so a single RPC cannot force unbounded git-object work.

### Proof of Concept
1. Identify or create a repository with at least one large tree (many directories/files) accessible to the caller.
2. Build a `GetBlobsRequest` whose `revision_paths` contains a very large number (e.g., 50,000+) of distinct `(revision, path)` pairs — either pointing at different valid paths under distinct directories to defeat the per-request tree cache, or simply non-existent paths under distinct directories, so `FindByRevisionAndPath` must invoke `TreeEntries`/`git cat-file` for each unique directory.
3. Send the single unary `GetBlobs` call to the target Gitaly node.
4. Observe that server CPU/time spent in `sendGetBlobsResponse` scales linearly (or worse) with the number of supplied entries, since there is no cap on `revision_paths` length, allowing a single request to occupy the RPC handler and underlying `git-cat-file` process for an extended duration and starve other RPCs sharing that Gitaly node's resources.

message GetBlobsRequest {
  // RevisionPath is a combination of revision and path. All objects reachable in the subdirectory of the treeish
  // will be returned.
  message RevisionPath {
    // revision is the revision that identifies the tree-ish. Must not be empty.
    string revision = 1;
    // path is the path relative to the treeish revision that shall be searched for a blob. If the path is empty the
    // root directory of the tree-ish will be searched.
    bytes path = 2;
  }

  // repository is the repository that shall be searched.
  Repository repository = 1[(target_repository)=true];
  // revision_paths identifies the set of revision/path pairs that shall be searched for blobs.
  repeated RevisionPath revision_paths = 2;
  // limit is the maximum number of bytes we want to receive. Use '-1' to get the full blobs no matter how big.
  int64 limit = 3;
}

func sendGetBlobsResponse(
	req *gitalypb.GetBlobsRequest,
	stream gitalypb.BlobService_GetBlobsServer,
	objectReader catfile.ObjectContentReader,
	objectInfoReader catfile.ObjectInfoReader,
) error {
	ctx := stream.Context()

	tef := catfile.NewTreeEntryFinder(objectReader)

	for _, revisionPath := range req.GetRevisionPaths() {
		revision := revisionPath.GetRevision()
		path := revisionPath.GetPath()

		if len(path) > 1 {
			path = bytes.TrimRight(path, "/")
		}

		treeEntry, err := tef.FindByRevisionAndPath(ctx, revision, string(path))
		if err != nil {
			return structerr.NewInternal("find by revision and path: %w", err)
		}

		response := &gitalypb.GetBlobsResponse{Revision: revision, Path: path}

		if treeEntry == nil || len(treeEntry.GetOid()) == 0 {
			if err := stream.Send(response); err != nil {
				return structerr.NewInternal("send: %w", err)
			}

			continue
		}

		response.Mode = treeEntry.GetMode()
		response.Oid = treeEntry.GetOid()

		if treeEntry.GetType() == gitalypb.TreeEntry_COMMIT {
			response.IsSubmodule = true
			response.Type = gitalypb.ObjectType_COMMIT

			if err := stream.Send(response); err != nil {
				return structerr.NewInternal("send: %w", err)
			}

			continue
		}

		objectInfo, err := objectInfoReader.Info(ctx, git.Revision(treeEntry.GetOid()))
		if err != nil {
			return structerr.NewInternal("read object info: %w", err)
		}

		response.Size = objectInfo.Size

		var ok bool
		response.Type, ok = treeEntryToObjectType[treeEntry.GetType()]

		if !ok {
			continue
		}

		if response.GetType() != gitalypb.ObjectType_BLOB {
			if err := stream.Send(response); err != nil {
				return structerr.NewInternal("send: %w", err)
			}
			continue
		}

		if err = sendBlobTreeEntry(response, stream, objectReader, req.GetLimit()); err != nil {
			return err
		}
	}

func (s *server) GetBlobs(req *gitalypb.GetBlobsRequest, stream gitalypb.BlobService_GetBlobsServer) error {
	if err := validateGetBlobsRequest(stream.Context(), s.locator, req); err != nil {
		return structerr.NewInvalidArgument("%w", err)
	}

	repo := s.localRepoFactory.Build(req.GetRepository())

	objectReader, cancel, err := s.catfileCache.ObjectReader(stream.Context(), repo)
	if err != nil {
		return structerr.NewInternal("creating object reader: %w", err)
	}
	defer cancel()

	objectInfoReader, cancel, err := s.catfileCache.ObjectInfoReader(stream.Context(), repo)
	if err != nil {
		return structerr.NewInternal("creating object info reader: %w", err)
	}
	defer cancel()

	return sendGetBlobsResponse(req, stream, objectReader, objectInfoReader)

func validateGetBlobsRequest(ctx context.Context, locator storage.Locator, req *gitalypb.GetBlobsRequest) error {
	if err := locator.ValidateRepository(ctx, req.GetRepository()); err != nil {
		return err
	}

	if len(req.GetRevisionPaths()) == 0 {
		return errors.New("empty RevisionPaths")
	}

	for _, rp := range req.GetRevisionPaths() {
		if err := git.ValidateRevision([]byte(rp.GetRevision())); err != nil {
			return err
		}
	}

	return nil
}

// FindByRevisionAndPath returns a TreeEntry struct for the object present at the revision/path pair.
func (tef *TreeEntryFinder) FindByRevisionAndPath(ctx context.Context, revision, path string) (*gitalypb.TreeEntry, error) {
	span, ctx := tracing.StartSpanIfHasParent(
		ctx,
		"catfile.FindByRevisionAndPatch",
		[]attribute.KeyValue{
			attribute.String("revision", revision),
			attribute.String("path", path),
		},
	)
	defer span.End()

	dir := pathPkg.Dir(path)
	cacheKey := revisionPath{revision: revision, path: dir}
	entries, ok := tef.treeCache[cacheKey]

	if !ok {
		var err error
		entries, err = TreeEntries(ctx, tef.objectReader, revision, dir)
		if err != nil {
			return nil, err
		}

		tef.treeCache[cacheKey] = entries
	}

	for _, entry := range entries {
		if string(entry.GetPath()) == path {
			return entry, nil
		}
	}

	return nil, nil
}

func extractEntryInfoFromTreeData(
	objectHash git.ObjectHash,
	treeData io.Reader,
	commitOid, rootPath, oid string,
) ([]*gitalypb.TreeEntry, error) {
	if len(oid) == 0 {
		return nil, fmt.Errorf("empty tree oid")
	}

	bufReader := bufio.NewReader(treeData)

	var entries []*gitalypb.TreeEntry
	oidBuf := &bytes.Buffer{}

	oidSize := int64(objectHash.Hash().Size())

	for {
		modeBytes, err := bufReader.ReadBytes(' ')
		if errors.Is(err, io.EOF) {
			break
		}
		if err != nil || len(modeBytes) <= 1 {
			return nil, fmt.Errorf("read entry mode: %w", err)
		}
		modeBytes = modeBytes[:len(modeBytes)-1]

		filename, err := bufReader.ReadBytes('\x00')
		if err != nil || len(filename) <= 1 {
			return nil, fmt.Errorf("read entry path: %w", err)
		}
		filename = filename[:len(filename)-1]

		oidBuf.Reset()
		if _, err := io.CopyN(oidBuf, bufReader, oidSize); err != nil {
			return nil, fmt.Errorf("read entry oid: %w", err)
		}

		treeEntry, err := git.NewTreeEntry(commitOid, rootPath, filename, oidBuf.Bytes(), modeBytes)
		if err != nil {
			return nil, fmt.Errorf("new entry info: %w", err)
		}

		entries = append(entries, treeEntry)
	}

	return entries, nil
}

// TreeEntries returns the entries of a tree in given revision and path.
func TreeEntries(
	ctx context.Context,
	objectReader ObjectContentReader,
	revision, path string,
) (_ []*gitalypb.TreeEntry, returnedErr error) {
	span, ctx := tracing.StartSpanIfHasParent(
		ctx,
		"catfile.TreeEntries",
		[]attribute.KeyValue{
			attribute.String("revision", revision),
			attribute.String("path", path),
		},
	)
	defer span.End()

	if path == "." {
		path = ""
	}

	// If we ask 'git cat-file' for a path outside the repository tree it
	// blows up with a fatal error. So, we avoid asking for this.
	if strings.HasPrefix(filepath.Clean(path), "../") {
		return nil, nil
	}

	treeObj, err := objectReader.Object(ctx, git.Revision(fmt.Sprintf("%s:%s", revision, path)))
	if err != nil {
		if errors.As(err, &NotFoundError{}) {
			return nil, nil
		}
		return nil, err
	}
