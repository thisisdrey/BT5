### Title
Unstaked attacker can saturate pre-handshake connection headroom via never-completed QUIC handshakes, denying TPU ingress to legitimate connections - (File: streamer/src/nonblocking/quic.rs)

### Summary
`ClientConnectionTracker::new` gates on `stats.open_connections` against `qos.max_concurrent_connections()` (a fixed `(max_staked+max_unstaked)*5/4` headroom) *before* any handshake work is performed, and the tracker slot is only released after `QUIC_CONNECTION_HANDSHAKE_TIMEOUT` (2s) elapses or the handshake completes/fails. Critically, both the per-IP (`ConnectionRateLimiter::is_allowed`) and global (`overall_connection_rate_limiter.current_tokens() == 0`) pre-handshake checks are read-only checks against token buckets that are only *consumed* after a handshake successfully completes (`register_connection` / `consume_tokens` in `setup_connection`, called only in the `Ok(new_connection)` branch). An attacker who never completes the handshake never triggers consumption of either bucket, so neither limiter throttles a flood of stalled connection attempts.

### Finding Description
The relevant code path in `run_server` (`streamer/src/nonblocking/quic.rs`): [1](#0-0) 

shows that:
1. `overall_connection_rate_limiter.current_tokens() == 0` is a pure read of bucket state — line 347.
2. `rate_limiter.is_allowed(&incoming.remote_address().ip())` is also a pure read: `ConnectionRateLimiter::is_allowed` returns `true` when the IP has no prior record (`None => true`), and only reflects actual token depletion caused by *prior successful* `register_connection` calls: [2](#0-1) .
3. Only after these reads pass does `ClientConnectionTracker::new(stats.clone(), qos.max_concurrent_connections())` run the actual admission-control gate against `open_connections`: [3](#0-2) .
4. The connection is then handed to `setup_connection`, which awaits the handshake under a `timeout(QUIC_CONNECTION_HANDSHAKE_TIMEOUT, connecting)` (2 seconds, not 1s as stated in the question): [4](#0-3)  and [5](#0-4) .
5. The two rate limiters are only *consumed* (i.e., mutated) in the `Ok(new_connection)` success branch, after the handshake has completed: `rate_limiter.register_connection(&from.ip())` and `overall_connection_rate_limiter.consume_tokens(1)`: [6](#0-5) . If the handshake times out (the `else` branch at the bottom of `setup_connection`), no consumption occurs at all: [7](#0-6) .

Because of this, an attacker who opens QUIC connection attempts and never lets them complete the handshake (e.g., sends only an `Initial` packet and stops responding, or blackholes further packets) never depletes either rate limiter, and thus is never subjected to the per-IP or global connection-attempt rate limiting the code comments claim to enforce ("rate-limit abusive peers by (control-asserted) ip" — line 339). The only gate that applies to such attempts is `ClientConnectionTracker::new`'s `open_connections` headroom check, and each stalled slot is held for up to `QUIC_CONNECTION_HANDSHAKE_TIMEOUT` (2s) before being released via `Drop for ClientConnectionTracker` (decrementing `open_connections`): [8](#0-7) .

By continuously opening new stalled connections at a rate sufficient to keep `open_connections` at/near `max_concurrent_connections()` (default `(2000+2000)*5/4 = 5000`, `streamer/src/nonblocking/swqos.rs` lines 518-522), an attacker can force `ClientConnectionTracker::new` to return `Err(())` for essentially all subsequent connection attempts, both from itself and from legitimate staked/unstaked peers, since the check is a single shared global counter with no per-source-IP quota at this stage. Legitimate connections get `incoming.refuse()`'d (`refused_connections_too_many_open_connections`) regardless of their eventual stake classification, because that classification (`qos.try_add_connection`) never runs — it happens only after the handshake succeeds inside `setup_connection`, well after the tracker/headroom gate.

### Impact Explanation
This is a full TPU QUIC ingress denial-of-service: legitimate staked and unstaked clients are unable to acquire a `ClientConnectionTracker` slot and thus cannot even begin a handshake, let alone get scheduled into the staked/unstaked connection tables used for transaction ingestion. This matches the Agave bounty category of validator DoS / QoS evasion, since the intended purpose of the 25% headroom (to "allow for handshake" overhead from legitimate clients) is consumed entirely by an attacker who is never subject to staked/unstaked classification.

### Likelihood Explanation
Preconditions are minimal and match the specified threat model: an unstaked remote attacker with the ability to open QUIC/UDP connections to the public TPU port and stall the handshake. No stake, no cluster privileges, no packet spoofing is required (a single real source IP works because `is_allowed` never depletes for an unregistered/never-completed-handshake IP). The attack is trivially repeatable: reconnect immediately after each ~2s timeout, or run many concurrent stalled connections to keep `open_connections` pinned near `max_concurrent_connections()`. The attacker's only real constraint is generating enough concurrent/successive connection attempts, which is cheap (no full handshake CPU/crypto cost is required from the attacker beyond an Initial packet).

### Recommendation
- Consume/rate-limit connection attempts against the per-IP and global buckets *before* granting a `ClientConnectionTracker` slot (i.e., on `Incoming` observation), rather than only after successful handshake completion, while still avoiding the ip-spoofing amplification concern noted in the code comment (e.g., by using a smaller, tightly-bounded "provisional" per-IP attempt budget that is independent from post-handshake accounting, or by requiring quinn's address-validation/Retry mechanism so an attacker must complete a round trip before a slot is consumed).
- Reserve a portion of `max_concurrent_connections()` headroom exclusively for handshake completion progress signals (e.g., peers that have already sent a Handshake packet) versus bare `Initial`-only attempts, so pure Initial floods cannot exhaust the entire headroom.
- Reduce `QUIC_CONNECTION_HANDSHAKE_TIMEOUT` further or add an aggressive per-IP concurrent "provisional" connection cap enforced at admission time (not just post-handshake), independent of whether the IP has ever completed a handshake.

### Proof of Concept
```rust
// streamer/src/nonblocking/quic.rs (test module)
//
// Goal: show that an attacker can occupy the entire `max_concurrent_connections()`
// headroom with never-completing handshakes and that a legitimate concurrent client
// is refused (`refused_connections_too_many_open_connections` increments) for the
// duration of the attack, while the per-IP/global rate limiters never fire for the
// attacker.
#[tokio::test(flavor = "multi_thread")]
async fn test_stalled_handshake_flood_starves_legitimate_connections() {
    let SpawnTestServerResult {
        join_handle, server_address, stats, cancel, ..
    } = setup_quic_server(
        None,
        QuicStreamerConfig::default_for_tests(),
        SwQosConfig {
            max_staked_connections: 4,
            max_unstaked_connections: 4,
            ..Default::default()
        },
    );
    // max_concurrent_connections() == (4+4)*5/4 == 10

    // Attacker: open `max_concurrent_connections` UDP sockets that send only an
    // Initial-like packet (or use a raw UDP socket bypassing quinn handshake logic)
    // and never respond further, so `setup_connection`'s `timeout(...)` will only
    // release the slot after QUIC_CONNECTION_HANDSHAKE_TIMEOUT.
    let mut attacker_sockets = Vec::new();
    for _ in 0..10 {
        let sock = tokio::net::UdpSocket::bind("0.0.0.0:0").await.unwrap();
        sock.send_to(b"\x00garbage_initial_packet", server_address).await.unwrap();
        attacker_sockets.push(sock);
    }

    // Give the server a moment to accept the Incoming and acquire trackers.
    tokio::time::sleep(Duration::from_millis(200)).await;
    assert_eq!(stats.open_connections.load(Ordering::Relaxed), 10);

    // Legitimate client attempts a real handshake while attacker holds all slots.
    let legit_client = make_client_endpoint(&server_address, None).await;
    // Expect this to fail/refuse because tracker slots are exhausted.
    tokio::time::sleep(Duration::from_millis(100)).await;
    assert!(
        stats.refused_connections_too_many_open_connections.load(Ordering::Relaxed) > 0,
        "legitimate connection should have been refused while attacker holds all tracker slots"
    );

    // Confirm the per-IP/global rate limiters never triggered for the attacker,
    // proving they are ineffective against stalled (never-completed) handshakes.
    assert_eq!(stats.connection_rate_limited_per_ipaddr.load(Ordering::Relaxed), 0);
    assert_eq!(stats.connection_rate_limited_across_all.load(Ordering::Relaxed), 0);

    cancel.cancel();
    join_handle.await.unwrap();
}
```
Expected assertions: `open_connections` reaches `max_concurrent_connections()` purely from attacker attempts; a concurrently attempted legitimate connection is refused (`refused_connections_too_many_open_connections` > 0); and neither `connection_rate_limited_per_ipaddr` nor `connection_rate_limited_across_all` increments for the attacker's flood, confirming those limiters do not mitigate never-completed-handshake floods.
