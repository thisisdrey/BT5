### Title
Zero-Share Buy-In in `staking_contract::add_distribution` Silently Loses Staker's Unlocked APT to Operator — (`File: aptos-move/framework/aptos-framework/sources/staking_contract.move`)

---

### Summary

`staking_contract::add_distribution` calls `pool_u64::buy_in` with the staker's unlock amount without checking whether the resulting share count is zero. When the distribution pool's share price is inflated (total_coins >> total_shares), a non-zero `coins_amount` can produce zero new shares. The pool's `total_coins` is still incremented, but the staker is never added to the shareholders list. When `distribute()` is called, the operator redeems all shares and receives all coins — including the staker's unlocked amount — while the staker receives nothing.

---

### Finding Description

**Root cause — `pool_u64::buy_in` does not guard against zero-share outcomes for non-zero input:** [1](#0-0) 

When `coins_amount > 0` but `amount_to_shares(coins_amount)` returns 0 (integer floor division), the function still increments `total_coins` by `coins_amount` and calls `add_shares(shareholder, 0)`. Because `new_shares == 0` and the shareholder is not already in the pool, `add_shares` silently does nothing — the shareholder is never registered. [2](#0-1) 

**Vulnerable call site — `add_distribution` in `staking_contract`:** [3](#0-2) 

`add_distribution` first calls `update_distribution_pool`, which sets `distribution_pool.total_coins` to the current pending-inactive stake (which may be inflated by accumulated rewards). It then calls `distribution_pool.buy_in(recipient, coins_amount)` with no check on the returned share count. If `coins_amount < total_coins / total_shares`, the staker receives zero shares.

**Share-price inflation path:** [4](#0-3) 

`update_distribution_pool` sets `total_coins` to the pending-inactive stake value (which grows with staking rewards) while `total_shares` stays fixed at the number of shares the operator bought when commission was first recorded. This inflates the share price over time.

**Consequence in `distribute_internal`:** [5](#0-4) 

The distribution loop iterates only over `distribution_pool.shareholders()`. Because the staker was never added to the shareholders list (zero shares), they are skipped entirely. The operator redeems all shares and receives all coins. The dust handler sends zero remaining coins to the staker.

**Contrast with the guarded path in `delegation_pool`:** [6](#0-5) 

`delegation_pool` explicitly returns early when `new_shares == 0`. `staking_contract` has no equivalent guard.

---

### Impact Explanation

A staker who calls `unlock_stake(amount)` where `amount < (pending_inactive / operator_shares)` will:
1. Have `amount` APT moved from active to pending-inactive (real coin movement).
2. Receive zero shares in the distribution pool (accounting failure).
3. Receive zero APT when `distribute()` is called.
4. The operator receives the staker's `amount` APT as part of their share redemption.

This is direct, permanent theft of staking balance from an unprivileged user transaction (`unlock_stake` is a public entry function callable by any staker).

---

### Likelihood Explanation

The share price inflates whenever staking rewards accumulate in the pending-inactive pool between `request_commission` calls and the next `distribute()`. The minimum exploitable amount equals `floor(pending_inactive / operator_shares)`. With a 10% commission rate and a pool that has doubled in value, the share price is 2 APT/share — any `unlock_stake` call with `amount = 1 APT` silently loses that APT to the operator. A malicious operator can maximize this window by delaying `distribute()` calls to let rewards inflate the share price before the staker unlocks.

---

### Recommendation

Add a zero-share guard in `add_distribution` (mirroring the pattern in `delegation_pool`):

```move
let new_shares = distribution_pool.amount_to_shares(coins_amount);
if (new_shares == 0) {
    // abort or refund: do not silently consume coins
    abort error::invalid_argument(EINSUFFICIENT_STAKE_AMOUNT)
};
distribution_pool.buy_in(recipient, coins_amount);
```

Alternatively, use a higher `scaling_factor` when creating the distribution pool (as `delegation_pool` uses `SHARES_SCALING_FACTOR = 10^16`) to reduce the granularity of rounding losses.

---

### Proof of Concept

```
1. Operator O and staker S create a staking contract with 10% commission.
2. Pool earns rewards; O calls request_commission_internal:
   - commission_amount = 100 APT unlocked → pending_inactive = 100 APT
   - distribution_pool: total_coins = 100, total_shares = 100 (1:1)
3. Time passes; pending_inactive grows to 200 APT (100% rewards).
4. S calls unlock_stake(1 APT):
   a. add_distribution is called:
      - update_distribution_pool sets total_coins = 200, total_shares = 100
        → share price = 2 APT/share
      - buy_in(S, 1 APT): amount_to_shares(1) = 1 * 100 / 200 = 0
        → total_coins becomes 201, total_shares stays 100
        → S is NOT added to shareholders list
   b. stake::unlock_with_cap(1 APT) moves 1 APT to pending_inactive.
5. Anyone calls distribute():
   - distribution_amount = 201 APT (200 rewards + 1 staker unlock)
   - update_distribution_pool sets total_coins = 201
   - Loop: O redeems 100 shares → gets 100 * 201 / 100 = 201 APT
   - S has 0 shares → skipped
   - Remaining coins = 0 → dust handler sends 0 to S
6. Result: S loses 1 APT; O gains 1 APT beyond their entitled commission.
```

    fun update_distribution_pool(
        distribution_pool: &mut Pool,
        updated_total_coins: u64,
        operator: address,
        commission_percentage: u64
    ) {
        // Short-circuit and do nothing if the pool's total value has not changed.
        if (distribution_pool.total_coins() == updated_total_coins) { return };

        // Charge all stakeholders (except for the operator themselves) commission on any rewards earnt relatively to the
        // previous value of the distribution pool.
        let shareholders = &distribution_pool.shareholders();
        shareholders.for_each_ref(
            |shareholder| {
                let shareholder: address = *shareholder;
                if (shareholder != operator) {
                    let shares = pool_u64::shares(distribution_pool, shareholder);
                    let previous_worth = pool_u64::balance(distribution_pool, shareholder);
                    let current_worth =
                        pool_u64::shares_to_amount_with_total_coins(
                            distribution_pool, shares, updated_total_coins
                        );
                    let unpaid_commission =
                        (current_worth - previous_worth) * commission_percentage / 100;
                    // Transfer shares from current shareholder to the operator as payment.
                    // The value of the shares should use the updated pool's total value.
                    let shares_to_transfer =
                        pool_u64::amount_to_shares_with_total_coins(
                            distribution_pool, unpaid_commission, updated_total_coins
                        );
                    pool_u64::transfer_shares(
                        distribution_pool, shareholder, operator, shares_to_transfer
                    );
                };
            }
        );

        distribution_pool.update_total_coins(updated_total_coins);
    }
