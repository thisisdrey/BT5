### Title
`StackerDBSession::get_chunks` omits the `STACKERDB_MAX_CHUNK_SIZE` bound that `get_latest_chunks` enforces, letting an oversized chunk from a malicious replica pass through unchecked - ([File: libsigner/src/session.rs])

### Summary
`StackerDBSession::get_latest_chunks` explicitly rejects (returns `None` for) any response body larger than `STACKERDB_MAX_CHUNK_SIZE`/`SIGNERS_STACKERDB_CHUNK_SIZE`, but the sibling method `get_chunks` (used for by-explicit-version fetches, and transitively by `get_chunk`) performs no such check and returns whatever bytes the remote host sent. This breaks the implicit file-wide invariant that any chunk exiting this module is size-bounded, because the guarantee is enforced in only one of the two code paths that produce `Vec<u8>` chunk payloads.

### Finding Description
`get_latest_chunks` computes a `limit` (either `SIGNERS_STACKERDB_CHUNK_SIZE` or `STACKERDB_MAX_CHUNK_SIZE`) and, after reading the HTTP body, explicitly checks `if body_bytes.len() > limit { None } else { Some(body_bytes) }` (`libsigner/src/session.rs:230-262`). `get_chunks`, which issues the same kind of GET to `stackerdb_get_chunk_path(...)` but with an explicit version, has no equivalent check — it unconditionally wraps the raw `body_bytes` in `Some(...)` regardless of size (`libsigner/src/session.rs:200-227`, specifically lines 212-223). Both methods share the same underlying `rpc_request`/`run_http_request` transport, which reads the full HTTP body into memory (`sock.read_to_end(&mut buf)` in `libsigner/src/http.rs:251`) without an overall byte cap for non-chunked responses (the `MAX_MESSAGE_LEN` cap in `decode_http_body` only applies when `Transfer-Encoding: chunked` is used, `libsigner/src/http.rs:196-217`). Thus a remote StackerDB host controlled by an attacker can return an arbitrarily large body on a version-qualified GET, and `get_chunks`/`get_chunk` will hand that oversized blob back to the caller as if it were a normal, size-validated chunk, while the exact same oversized body requested via `get_latest_chunks`/`get_latest_chunk` would be silently discarded as `None`. Any caller that mixes the two APIs (e.g., trying a specific version via `get_chunk` and falling back to `get_latest_chunk`) ends up treating data from the two paths as equally trustworthy, when only one path actually enforces the size bound.

### Impact Explanation
The immediate effect is a broken invariant inside `libsigner/src/session.rs` itself: not all `Vec<u8>` chunk payloads leaving the module are guaranteed to satisfy `len() <= STACKERDB_MAX_CHUNK_SIZE`. Whether this rises to Critical depends on what a downstream caller (outside this file, e.g., in `stacks-signer`) does with data obtained via `get_chunk`/`get_chunks` — if such code assumes the same size bound that `get_latest_chunk`/`get_latest` implicitly rely on, an oversized/malformed chunk could be stored, deserialized, or relayed without the expected bound, which is a plausible vector for a bounded-compute DoS or worse depending on the consumer. I could not fully trace every caller of `get_chunk`/`get_chunks` in this pass to confirm a Critical-grade consequence (e.g., unauthenticated write or crash) beyond the confirmed local inconsistency; that downstream trace is needed to pin the exact severity ceiling.

### Likelihood Explanation
Any StackerDB replica host that a signer or client connects to via `StackerDBSession` (attacker's own node, or a compromised/malicious node the signer is configured to query) can trivially return an oversized body to a version-qualified GET request — no authentication, secret, or privileged role is required beyond being a reachable HTTP responder on the configured host/port. The condition is deterministic and repeatable on every call to `get_chunks`/`get_chunk`.

### Recommendation
Apply the same size check used in `get_latest_chunks` to `get_chunks` in `libsigner/src/session.rs`, ideally by factoring the bound computation and enforcement into a single shared helper called by both methods so the guarantee cannot diverge again; additionally, enforce a hard cap in `run_http_request`/`decode_http_body` for non-chunked bodies (not just the chunked-transfer path) to prevent unbounded memory allocation regardless of which higher-level method is used.

// libsigner/src/session.rs (test module)
#[test]
fn get_chunks_accepts_oversized_body_that_get_latest_chunks_rejects() {
    use std::net::TcpListener;
    use std::io::Write;

    let big_body = vec![0u8; STACKERDB_MAX_CHUNK_SIZE as usize + 1024];

    // server 1: answers a get_chunks (by-version) request
    let listener1 = TcpListener::bind("127.0.0.1:0").unwrap();
    let addr1 = listener1.local_addr().unwrap();
    let body1 = big_body.clone();
    std::thread::spawn(move || {
        let (mut s, _) = listener1.accept().unwrap();
        let mut buf = [0u8; 4096];
        let _ = std::io::Read::read(&mut s, &mut buf);
        let resp = format!(
            "HTTP/1.1 200 OK\r\nContent-Length: {}\r\n\r\n",
            body1.len()
        );
        s.write_all(resp.as_bytes()).unwrap();
        s.write_all(&body1).unwrap();
    });
    let contract_id = QualifiedContractIdentifier::transient();
    let mut session1 = StackerDBSession::new(&addr1.to_string(), contract_id.clone(), Duration::from_secs(2));
    let result = session1.get_chunks(&[(0, 1)]).unwrap();
    // FAILS the invariant: get_chunks returns the oversized body unchecked
    assert_eq!(result[0].as_ref().unwrap().len(), big_body.len());

    // server 2: answers a get_latest_chunks request with the identical body
    let listener2 = TcpListener::bind("127.0.0.1:0").unwrap();
    let addr2 = listener2.local_addr().unwrap();
    let body2 = big_body.clone();
    std::thread::spawn(move || {
        let (mut s, _) = listener2.accept().unwrap();
        let mut buf = [0u8; 4096];
        let _ = std::io::Read::read(&mut s, &mut buf);
        let resp = format!(
            "HTTP/1.1 200 OK\r\nContent-Length: {}\r\n\r\n",
            body2.len()
        );
        s.write_all(resp.as_bytes()).unwrap();
        s.write_all(&body2).unwrap();
    });
    let mut session2 = StackerDBSession::new(&addr2.to_string(), contract_id, Duration::from_secs(2));
    let result2 = session2.get_latest_chunks(&[0]).unwrap();
    // get_latest_chunks correctly rejects the same oversized body
    assert!(result2[0].is_none());
}

    fn get_latest_chunks(&mut self, slot_ids: &[u32]) -> Result<Vec<Option<Vec<u8>>>, RPCError> {

            usize::try_from(STACKERDB_MAX_CHUNK_SIZE)
                .expect("infallible: StackerDB chunk size exceeds usize::MAX")

            let path = stackerdb_get_chunk_path(self.stackerdb_contract_id.clone(), *slot_id, None);

                Ok(body_bytes) => {
                    // Verify that the chunk is not too large

                        Some(body_bytes)

/// Decode an HTTP body, given the headers.
pub fn decode_http_body(headers: &HashMap<String, String>, mut buf: &[u8]) -> io::Result<Vec<u8>> {
    let chunked = if let Some(val) = headers.get("transfer-encoding") {
        val == "chunked"
    } else {
        false
    };

    let body = if chunked {
        // chunked encoding
        let ptr = &mut buf;
        let mut fd = HttpChunkedTransferReader::from_reader(ptr, MAX_MESSAGE_LEN.into());
        let mut decoded_body = vec![];
        fd.read_to_end(&mut decoded_body)?;
        decoded_body
    } else {
        // body is just as-is
        buf.to_vec()
    };

    Ok(body)
}
