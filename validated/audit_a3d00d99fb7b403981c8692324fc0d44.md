### Title
Unrestricted transport-helper schemes (`ext::`, `fd::`) in `FetchRemote.RemoteParams.Url` allow command execution - ([File: internal/gitaly/service/repository/fetch_remote.go])

### Summary
`FetchRemote`'s `buildCommandOpts` passes `RemoteParams.Url` directly into `remote.inmemory.url` git config without validating or restricting the URL scheme, and `validateFetchRemoteRequest` only checks the URL is non-empty. `git-fetch(1)` supports the `ext::<command>` and `fd::<n>` transport helpers, which by default are permitted for top-level, user-initiated invocations (Git only blocks them when `GIT_PROTOCOL_FROM_USER=0`, which Gitaly never sets), so a crafted URL such as `ext::sh -c "..."` results in Gitaly's git subprocess executing an arbitrary shell command.

### Finding Description
The request path is: `FetchRemote` (`internal/gitaly/service/repository/fetch_remote.go:30`) → `validateFetchRemoteRequest` (only checks `req.GetRemoteParams().GetUrl() == ""`, line 315) → `fetchRemoteAtomic` → `buildCommandOpts` (lines 260-304), which does `config = append(config, gitcmd.ConfigPair{Key: "remote.inmemory.url", Value: remoteURL})` (line 280) with `remoteURL` taken verbatim from `req.GetRemoteParams().GetUrl()` (line 261), unless `ResolvedAddress` is set (in which case `gitcmd.GetURLAndResolveConfig`/`getURLAndResolveConfigForURL` in `internal/git/gitcmd/command_resolve.go:81-105` does enforce a scheme allowlist of `http`/`https`/`git`). When `ResolvedAddress` is empty — the normal case for pull mirrors — no scheme check is performed at all. The resulting config is applied via `gitcmd.WithConfigEnv` to the `git fetch inmemory` invocation in `localrepo.Repo.FetchRemote` (`internal/git/localrepo/remote.go:79-138`), which builds no environment restricting protocols (no `GIT_PROTOCOL_FROM_USER`, no `protocol.*.allow` config). Git's own protection for `ext`/`file`/`fd`-style helpers is gated on `GIT_PROTOCOL_FROM_USER`, which Git itself only sets to `0` for *automatic* redirections (e.g. insteadOf rewrites, submodule recursion); a direct top-level `git fetch <url>` invocation—exactly what Gitaly performs—runs with the default "user" trust level, i.e. these protocols are allowed. Consequently `RemoteParams.Url = "ext::sh -c 'id>/tmp/pwn'"` reaches `git fetch` and is executed as a shell command by the `ext` transport helper inside the Gitaly process.

### Impact Explanation
This is remote command execution on the Gitaly host under the identity of the Gitaly process, matching GitLab's "RCE" bounty impact class — the highest severity category. Since `FetchRemote` runs as a mutator RPC with a quarantine directory and full transactional machinery, successful exploitation compromises the Gitaly node entirely (arbitrary file read/write, further pivoting, secrets exposure), well beyond repository-scoped impact.

### Likelihood Explanation
The precondition is that `RemoteParams.Url` is attacker-controlled when calling `FetchRemote`, e.g. via pull-mirror or repository-import configuration. Within the Gitaly repository/RPC itself, no scheme validation exists to prevent this, so if the calling layer permits an arbitrary URL, exploitation via this RPC is deterministic and repeatable. However, in the actual GitLab product, `RemoteParams.Url` for pull mirrors and imports is validated and sanitized by GitLab Rails (`Gitlab::UrlBlocker`) before the RPC is issued to Gitaly, restricting schemes to `http(s)`/`git`/`ssh`. Whether this question should be scored purely on Gitaly's lack of a defense-in-depth check, or rejected because the exploit depends on a hypothetical caller that skips Rails' existing URL validation, is the key uncertainty — the rules state to reject scenarios requiring "a bug in GitLab Rails ... rather than in Gitaly," and this specific Gitaly RPC is not normally callable with fully unsanitized user input without Rails already permitting it.

### Recommendation
Add an explicit scheme allowlist in `buildCommandOpts`/`validateFetchRemoteRequest` restricting `RemoteParams.Url` (and `CreateRepositoryFromURLRequest.Url`, `UpdateRemoteMirrorRequest.Remote.Url`, which share the same gap) to `http`, `https`, `git`, and `ssh` schemes (and SCP-like syntax), rejecting anything else (`ext`, `fd`, `file`, etc.) before constructing the git command. As defense-in-depth, also set `GIT_PROTOCOL_FROM_USER=0` and/or explicit `protocol.ext.allow=never`, `protocol.fd.allow=never`, `protocol.file.allow=never` config on all git subprocesses that consume externally-supplied URLs.

func buildCommandOpts(ctx context.Context, opts *localrepo.FetchOpts, req *gitalypb.FetchRemoteRequest) error {
	remoteURL := req.GetRemoteParams().GetUrl()
	var config []gitcmd.ConfigPair

	for _, refspec := range getRefspecs(req.GetRemoteParams().GetMirrorRefmaps()) {
		config = append(config, gitcmd.ConfigPair{
			Key: "remote.inmemory.fetch", Value: refspec,
		})
	}

	if resolvedAddress := req.GetRemoteParams().GetResolvedAddress(); resolvedAddress != "" {
		modifiedURL, resolveConfig, err := gitcmd.GetURLAndResolveConfig(remoteURL, resolvedAddress)
		if err != nil {
			return fmt.Errorf("couldn't get curloptResolve config: %w", err)
		}

		remoteURL = modifiedURL
		config = append(config, resolveConfig...)
	}

	config = append(config, gitcmd.ConfigPair{Key: "remote.inmemory.url", Value: remoteURL})

	if featureflag.FetchRemoteProactiveAuth.IsEnabled(ctx) {
		if u, err := url.Parse(remoteURL); err == nil && u.User != nil {
			password, _ := u.User.Password()
			if u.User.Username() != "" && password != "" {
				config = append(config, gitcmd.ConfigPair{
					Key:   "http.proactiveAuth",
					Value: "basic",
				})
			}
		}
	}

	if authHeader := req.GetRemoteParams().GetHttpAuthorizationHeader(); authHeader != "" {
		config = append(config, gitcmd.ConfigPair{
			Key:   fmt.Sprintf("http.%s.extraHeader", req.GetRemoteParams().GetUrl()),
			Value: "Authorization: " + authHeader,
		})
	}

	opts.CommandOptions = append(opts.CommandOptions, gitcmd.WithConfigEnv(config...))

	return nil
}

func getURLAndResolveConfigForURL(remoteURL, resolvedAddress string) (string, []ConfigPair, error) {
	u, err := url.ParseRequestURI(remoteURL)
	if err != nil {
		return "", nil, fmt.Errorf("couldn't parse remoteURL: %w", err)
	}

	port := u.Port()

	if port == "" {
		switch u.Scheme {
		case "http":
			port = "80"
		case "https":
			port = "443"
		case "git":
			port = "9418"
		default:
			return "", nil, fmt.Errorf("unknown schema provided: %s", u.Scheme)
		}
	}

	return remoteURL, []ConfigPair{
		{Key: "http.curloptResolve", Value: fmt.Sprintf("%s:%s:%s", u.Hostname(), port, resolvedAddress)},
	}, nil
}

func (repo *Repo) FetchRemote(ctx context.Context, remoteName string, opts FetchOpts) error {
	if err := validateNotBlank(remoteName, "remoteName"); err != nil {
		return err
	}

	var stderr bytes.Buffer
	if opts.Stderr == nil {
		opts.Stderr = &stderr
	}

	objectHash, err := repo.ObjectHash(ctx)
	if err != nil {
		return fmt.Errorf("detecting object hash: %w", err)
	}

	commandOptions := []gitcmd.CmdOpt{
		gitcmd.WithEnv(opts.Env...),
		gitcmd.WithStdout(opts.Stdout),
		gitcmd.WithStderr(opts.Stderr),
		gitcmd.WithConfig(gitcmd.ConfigPair{
			// Git is so kind to point out that we asked it to not show forced updates
			// by default, so we need to ask it not to do that.
			Key: "advice.fetchShowForcedUpdates", Value: "false",
		}),
		gitcmd.WithConfig(gitcmd.ConfigPair{
			// The patch series https://lore.kernel.org/git/20240910203835.2288291-1-bence@ferdinandy.com/
			// introduces new behaviour that automatically sets the local HEAD to the remote's HEAD during
			// a fetch. This happens when the mirror refspec is used to fetch into a bare repository, which
			// we use in operations like `FetchBundle`.
			//
			// Setting the remote's `followremotehead` config to "never" will disable the new behaviour. We
			// do this temporarily until we're sure the new behaviour doesn't have any consequences.
			Key: fmt.Sprintf("remote.%s.followremotehead", remoteName), Value: "never",
		}),
	}
	if opts.DisableTransactions {
		commandOptions = append(commandOptions, gitcmd.WithDisabledHooks())
	} else {
		commandOptions = append(commandOptions, gitcmd.WithRefTxHook(objectHash, repo))
	}
	commandOptions = append(commandOptions, opts.CommandOptions...)

	cmd, err := repo.Exec(ctx,
		gitcmd.Command{
			Name:  "fetch",
			Flags: opts.buildFlags(),
			Args:  []string{remoteName},
		},
		commandOptions...,
	)
	if err != nil {
		return err
	}

	if err := cmd.Wait(); err != nil {
		return FetchFailedError{errorWithStderr(err, stderr.Bytes())}
	}

	return nil
}
