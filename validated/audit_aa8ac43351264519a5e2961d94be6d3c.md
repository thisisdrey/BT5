### Title
Zero/uninitialized `accountIndexOf` mishandled when token index equals `INITIAL_INDEX`, letting any holder claim rewards equal to their full token balance - ([File: contracts/RewardsDistributor.sol])

### Summary
CVE-2020-9429 is a NULL-value-dereference crash: a data structure legitimately held a NULL and the code didn't handle it. The Metronome analog is in `RewardsDistributor._calculateTokenDelta` (`contracts/RewardsDistributor.sol:217-231`), where the "intentionally NULL" value is `accountIndexOf[token][account] == 0` (account never checkpointed). The fallback that substitutes `INITIAL_INDEX` only fires when `_tokenIndex > INITIAL_INDEX`; when the token index is still exactly `INITIAL_INDEX` (1e18), the delta becomes `1e18 - 0 = 1e18`, and `balance.wadMul(1e18)` credits the account its **entire token balance** as claimable rewards. [1](#0-0) 

### Finding Description
`_updateTokenSpeed` initializes a newly-listed token with `TokenState({index: INITIAL_INDEX, timestamp: now})` (`contracts/RewardsDistributor.sol:296-299`). At that moment `tokenStates[token].index == INITIAL_INDEX`, so the `index > 0` guards in `claimRewards`, `updateBeforeMintOrBurn`, and `updateBeforeTransfer` all pass (`contracts/RewardsDistributor.sol:156,176,187`).

In `_calculateTokenDelta`:

```solidity
uint256 _accountIndex = accountIndexOf[token_][account_];
if (_accountIndex == 0 && _tokenIndex > INITIAL_INDEX) {
    _accountIndex = INITIAL_INDEX;
}
uint256 _deltaIndex = _tokenIndex - _accountIndex;
_tokensDelta = token_.balanceOf(account_).wadMul(_deltaIndex);
```

If `_tokenIndex == INITIAL_INDEX` (i.e., no index accrual has occurred yet — `_calculateTokenIndex` leaves the index untouched when `_deltaTimestamps == 0` or `_speed` produces a zero ratio in the same block, lines 201-212) and the account's index is 0, then `_deltaIndex == INITIAL_INDEX` and `_tokensDelta == balanceOf(account)`. The account is credited rewards equal to 100% of its DepositToken/DebtToken balance.

`claimRewards` then pays out `tokensAccruedOf[account]` from the distributor's `rewardToken` balance (`contracts/RewardsDistributor.sol:248-256`).

### Impact Explanation
Theft of unclaimed yield: any account holding a deposit/debt token balance before its index is initialized can drain the distributor's `rewardToken` balance up to the size of that balance. The distributor's rewardToken reserves belong to all users who accrued rewards; the attacker extracts them without having accrued anything. This satisfies "direct theft of user funds / theft of unclaimed yield."

### Likelihood Explanation
Fully permissionless: `claimRewards(address, IERC20[])` is a public `nonReentrant` entry point with no role checks, and `updateBeforeMintOrBurn`/`updateBeforeTransfer` are callable by anyone per the NatSpec ("may be called by anyone", line 173). The attacker only needs to hold the DepositToken/DebtToken balance (a normal deposit) at the moment the governor lists the token or at any point where the stored index is still `INITIAL_INDEX` (e.g., same-block after `updateTokenSpeed`, or whenever `_speed`/`_deltaTimestamps` produced no index bump). No price manipulation, privileged role, or oracle fault is required; the only guard on payout is the distributor's rewardToken balance.

### Recommendation
Change the fallback so a zero account index is always initialized to the current token index, not only when it exceeds `INITIAL_INDEX`:

```solidity
if (_accountIndex == 0) {
    _accountIndex = _tokenIndex > INITIAL_INDEX ? INITIAL_INDEX : _tokenIndex;
}
```

Equivalently, clamp `_deltaIndex` to zero when `_accountIndex == 0`, since a first-time account can never have accrued rewards. Add a regression test calling `claimRewards` for an account holding tokens while `tokenStates[token].index == INITIAL_INDEX` and asserting zero payout.

### Proof of Concept
Hardhat-style sketch:

```ts
// pool, depositToken, rewardsDistributor, rewardToken deployed & wired
// 1. Alice deposits underlying → mints depositToken (token not yet reward-listed)
await depositToken.connect(alice).deposit(amount, alice.address);

// 2. Governor lists depositToken with a speed; index := INITIAL_INDEX (1e18)
await rewardsDistributor.connect(governor).updateTokenSpeed(depositToken.address, speed);

// 3. In the same block (deltaTimestamps == 0 → index stays == INITIAL_INDEX):
//    Alice's accountIndexOf == 0 → deltaIndex = 1e18 → accrued = her full balance
await rewardsDistributor.connect(alice).claimRewards(alice.address, [depositToken.address]);

// 4. tokensAccruedOf[alice] == depositToken.balanceOf(alice); rewardToken paid out
//    up to the distributor's rewardToken balance → assert alice rewardToken balance > 0
```

Invariant broken: reward accrual — an account with zero checkpoint history is credited 1:1 its token balance instead of zero.
