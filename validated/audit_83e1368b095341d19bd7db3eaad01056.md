Audit Report

## Title
Attacker-controlled remote fee amount is credited 1:1 as relayer reward without ETH→DOT conversion, draining the BridgeRelayers reward pot - (File: bridges/snowbridge/pallets/outbound-queue-v2/src/lib.rs)

## Summary
In `snowbridge-outbound-queue-v2`, the fee value that an unprivileged user encodes in the `PayFees` XCM instruction (denominated in 18-decimal Ether units) is extracted by `XcmConverter::extract_remote_fee` / `convert`, stored verbatim into `Message.fee`, propagated unchanged into `PendingOrder.fee`, and later paid out 1:1 as a relayer reward via `T::RewardPayment::register_reward` — with zero exchange-rate or decimal conversion. The sibling V1 `outbound-queue` pallet explicitly performs this conversion via `calculate_fee`/`convert_from_ether_decimals` using governance-set `PricingParameters`, but no equivalent mechanism exists anywhere in the V2 pipeline, allowing an attacker-controlled numeric value to be paid out at face value in the chain's native (10/12-decimal) reward currency.

## Finding Description
`XcmConverter::extract_remote_fee` reads the `fee_amount` straight from the user-supplied `PayFees` instruction, bounding it only by requiring `reserved_fee_amount >= fee_amount` and that the asset is Ether-Here — no bound tied to real gas cost: [1](#0-0) . This value is written unmodified into the constructed `Message.fee`: [2](#0-1) [3](#0-2) .

`do_process_message` in the V2 outbound-queue pallet decodes the `Message` and stores the same `fee` value directly into `PendingOrder`, with no recomputation: [4](#0-3) . When a relayer submits the delivery receipt, `process_delivery_receipt` reads `order.fee` and calls `T::RewardPayment::register_reward` with that raw value, again unconverted: [5](#0-4) .

By contrast, the V1 pallet's `Config` trait requires a `PricingParameters` type, and `calculate_fee` explicitly applies `exchange_rate`, `multiplier`, and `convert_from_ether_decimals` before any amount is used as a payable fee: [6](#0-5) . The V2 pallet's `Config` trait has no `PricingParameters`, `exchange_rate`, or decimals field at all: [7](#0-6) , and this is confirmed by the runtime wiring, where `snowbridge_pallet_outbound_queue::Config` for Runtime is given `type PricingParameters = EthereumSystem` and `type Decimals = ConstU8<12>` while `snowbridge_pallet_outbound_queue_v2::Config` for Runtime has neither: [8](#0-7) .

## Impact Explanation
`register_reward` credits `reward_account` in the pallet-relayers reward ledger (`bridges/modules/relayers`), which is a shared protocol resource independent of the actual per-message cost. Since `order.fee` is a raw, user-declared 18-decimal Ether figure passed straight into a reward system denominated in the chain's native balance (10-decimal DOT on Westend, per `currency::UNITS`), any user submitting an XCM with a normal-looking Ether fee produces a reward inflated by roughly the ETH/DOT decimal gap (10^6–10^8x) with no exchange-rate dampening, matching the "public underpriced work" / theft-of-unbacked-payout impact class for BridgeHub's own reward accounting.

## Likelihood Explanation
High. Constructing `WithdrawAsset(Ether: X) -> PayFees(Ether: X) -> ...` requires no privileged origin — the only constraint enforced by `extract_remote_fee` is `reserved_fee_amount >= fee_amount` and the asset being Ether-Here. Any account capable of sending a cross-chain transfer that reaches `EthereumBlobExporter`/`XcmConverter::convert` can set an inflated `X`, and any account (including the attacker) can subsequently call the public `submit_delivery_receipt` extrinsic once the message is verifiable on Ethereum to trigger the reward payout, with no relayer collusion, governance, or privileged-role assumption required.

## Recommendation
Add an exchange-rate/decimal-normalization step to the V2 pipeline — either introduce a `PricingParameters`/`exchange_rate` type to `snowbridge_pallet_outbound_queue_v2::Config` and apply the same conversion logic as `outbound-queue::calculate_fee`/`convert_from_ether_decimals` before storing `order.fee`, or independently recompute the reward from `T::GasMeter` and governance-configured pricing rather than trusting the XCM-declared `Message.fee`. At minimum, bound `order.fee` to a sane maximum derived from measured gas/weight.

## Proof of Concept
1. Attacker submits an XCM on AssetHub: `WithdrawAsset(Ether: 1_000_000_000_000_000_000) -> PayFees(Ether: 1_000_000_000_000_000_000) -> ... -> AliasOrigin -> DepositAsset -> SetTopic` (1 ETH in wei, a normal amount).
2. `XcmConverter::convert` stores `fee: 1_000_000_000_000_000_000` into `Message` (`bridges/snowbridge/primitives/outbound-queue/src/v2/converter/convert.rs:218-317`).
3. `do_process_message` stores `PendingOrder { fee: 1_000_000_000_000_000_000, .. }` (`bridges/snowbridge/pallets/outbound-queue-v2/src/lib.rs:426-436`).
4. After Ethereum-side execution, anyone calls `submit_delivery_receipt`, invoking `process_delivery_receipt`, which calls `T::RewardPayment::register_reward(&reward_account, DefaultRewardKind, 1_000_000_000_000_000_000)` (`lib.rs:462-473`), crediting a 10-decimal-denominated reward using a raw 18-decimal figure — vastly exceeding legitimate reward levels and draining the shared reward pot.

	/// Extract the fee asset item from PayFees(V5)
	fn extract_remote_fee(&mut self) -> Result<u128, XcmConverterError> {
		use XcmConverterError::*;
		let reserved_fee_assets = match_expression!(self.next()?, WithdrawAsset(fee), fee)
			.ok_or(WithdrawAssetExpected)?;
		ensure!(reserved_fee_assets.len() == 1, AssetResolutionFailed);
		let reserved_fee_asset =
			reserved_fee_assets.inner().first().cloned().ok_or(AssetResolutionFailed)?;
		let (reserved_fee_asset_id, reserved_fee_amount) = match reserved_fee_asset {
			Asset { id: asset_id, fun: Fungible(amount) } => Ok((asset_id, amount)),
			_ => Err(AssetResolutionFailed),
		}?;
		let fee_asset =
			match_expression!(self.next()?, PayFees { asset: fee }, fee).ok_or(InvalidFeeAsset)?;
		let (fee_asset_id, fee_amount) = match fee_asset {
			Asset { id: asset_id, fun: Fungible(amount) } => Ok((asset_id, *amount)),
			_ => Err(AssetResolutionFailed),
		}?;
		// Check the fee asset is Ether (XCM is evaluated in Ethereum context).
		ensure!(fee_asset_id.0 == Here.into(), InvalidFeeAsset);
		ensure!(reserved_fee_asset_id.0 == Here.into(), InvalidFeeAsset);
		ensure!(reserved_fee_amount >= fee_amount, InvalidFeeAsset);
		Ok(fee_amount)
	}

		/// Calculate total fee in native currency to cover all costs of delivering a message to the
		/// remote destination. See module-level documentation for more details.
		pub(crate) fn calculate_fee(
			gas_used_at_most: u64,
			params: PricingParameters<T::Balance>,
		) -> Fee<T::Balance> {
			// Remote fee in ether
			let fee = Self::calculate_remote_fee(
				gas_used_at_most,
				params.fee_per_gas,
				params.rewards.remote,
			);

			// downcast to u128
			let fee: u128 = fee.try_into().defensive_unwrap_or(u128::MAX);

			// multiply by multiplier and convert to local currency
			let fee = FixedU128::from_inner(fee)
				.saturating_mul(params.multiplier)
				.checked_div(&params.exchange_rate)
				.expect("exchange rate is not zero; qed")
				.into_inner();

			// adjust fixed point to match local currency
			let fee = Self::convert_from_ether_decimals(fee);

			Fee::from((Self::calculate_local_fee(), fee))
		}

		/// Calculate fee in remote currency for dispatching a message on Ethereum
		pub(crate) fn calculate_remote_fee(
			gas_used_at_most: u64,
			fee_per_gas: U256,
			reward: U256,
		) -> U256 {
			fee_per_gas.saturating_mul(gas_used_at_most.into()).saturating_add(reward)
		}

		/// The local component of the message processing fees in native currency
		pub(crate) fn calculate_local_fee() -> T::Balance {
			T::WeightToFee::weight_to_fee(
				&T::WeightInfo::do_process_message().saturating_add(T::WeightInfo::commit_single()),
			)
		}

		// 1 DOT has 10 digits of precision
		// 1 KSM has 12 digits of precision
		// 1 ETH has 18 digits of precision
		pub(crate) fn convert_from_ether_decimals(value: u128) -> T::Balance {
			let decimals = ETHER_DECIMALS.saturating_sub(T::Decimals::get()) as u32;
			let denom = 10u128.saturating_pow(decimals);
			value.checked_div(denom).expect("divisor is non-zero; qed").into()
		}
