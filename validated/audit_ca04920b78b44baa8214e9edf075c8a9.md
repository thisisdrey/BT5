### Title
Per-IP and global QUIC connection rate limiters only charge tokens after handshake completion, allowing unlimited pre-handshake CPU consumption via connection churn - (File: streamer/src/nonblocking/quic.rs)

### Summary
`ConnectionRateLimiter::is_allowed` and the global `overall_connection_rate_limiter` are only *peeked* (non-mutating) in `run_server` before a QUIC handshake is attempted, while the actual token debit (`register_connection` / `consume_tokens`) happens only in `setup_connection` after a handshake successfully completes. An attacker who aborts or never completes the handshake is never charged by either limiter, so `is_allowed` keeps returning `true` indefinitely for that IP, letting the attacker repeatedly trigger full handshake CPU work in the accept loop without ever tripping the per-IP or global rate limits.

### Finding Description
In `run_server`, for every incoming QUIC `Incoming` the server does two cheap, non-consuming checks before doing any expensive work: [1](#0-0) 
Both `overall_connection_rate_limiter.current_tokens()` and `rate_limiter.is_allowed(...)` only *read* the token bucket state — neither call decrements tokens. If they pass, `incoming.accept()` is called and `setup_connection` is spawned, which performs the actual QUIC/TLS handshake: [2](#0-1) 
The token buckets are only debited inside the `Ok(new_connection)` branch, i.e., *after* the handshake has fully completed: `rate_limiter.register_connection(&from.ip())` and `overall_connection_rate_limiter.consume_tokens(1)` at lines 483 and 495. Crucially, the failure paths — handshake error (`Err(e) => handle_connection_error(...)`) and handshake timeout (the final `else` branch incrementing `connection_setup_timeout`) — never call `register_connection` or `consume_tokens`: [3](#0-2) 

Because `ConnectionRateLimiter::is_allowed` treats "no record" or "current_tokens > 0" as allowed, and tokens are only ever removed by `register_connection` (called solely on handshake success): [4](#0-3) 
an attacker who deliberately drops the connection before or during the QUIC handshake (e.g., sends an `Initial` and never replies, or lets it hit `QUIC_CONNECTION_HANDSHAKE_TIMEOUT`) is never charged. Each such attempt still passes through `incoming.accept()` and spawns a `setup_connection` task that performs real TLS/QUIC crypto work on the accept loop's task pool for up to the handshake timeout, before being discarded uncharged. The only backpressure that exists for this pattern is the global (not per-IP) `ClientConnectionTracker::new(...)` slot cap tied to `qos.max_concurrent_connections()`, which a single attacking IP can fully occupy with churned, never-completing handshakes, since the per-IP and global rate limiters never engage against this traffic pattern.

### Impact Explanation
A single unstaked, unprivileged source IP can repeatedly open and abandon QUIC connections to the leader's public TPU port, forcing the accept loop to spend CPU on handshake crypto and to occupy the shared, IP-agnostic concurrent-connection slot pool (`ClientConnectionTracker`/`max_concurrent_connections`), while never being throttled by `ConnectionRateLimiter` or the global `overall_connection_rate_limiter`. This starves TPU capacity for legitimate unstaked senders sharing the same accept loop, matching the "unstaked connection/stream/per-IP QoS limits bypass leading to TPU capacity starvation" bounty category.

### Likelihood Explanation
This requires no stake, no special network position, and no cluster state — only the ability to open TCP/UDP connections to a leader's public TPU QUIC port and abort them before/at handshake completion, which is trivially scriptable and repeatable at line rate. The only limiting factor is the global concurrent-connection cap, but that itself is the resource being contended for, so the attack degrades service for all other unstaked peers rather than being blocked.

### Recommendation
Charge the per-IP (and/or global) rate limiter at connection-attempt time (before or immediately upon `incoming.accept()`), not only on successful handshake completion, so that repeated aborted/timed-out handshake attempts from the same IP are counted against that IP's quota. Alternatively, track and cap per-IP *outstanding/pending* handshake attempts (not just registered-complete connections) so that churn cannot bypass the per-IP `is_allowed` check.

```rust
// streamer/src/nonblocking/quic.rs (integration-style test)
// Simulate an attacker that opens many QUIC connections to the same
// server IP but always aborts before finishing the TLS handshake
// (drop the Connecting future / never send required certs), then
// verify:
// 1) rate_limiter.register_connection is never invoked for these attempts
//    (per-IP token count remains == max_burst)
// 2) `is_allowed` still returns true after e.g. 10_000 aborted attempts
// 3) stats.total_incoming_connection_attempts grows while
//    stats.connection_rate_limited_per_ipaddr stays at 0 for this IP,
//    demonstrating the accept loop absorbed the handshake CPU cost
//    without ever charging the per-IP limiter.
#[tokio::test(flavor = "multi_thread")]
async fn test_uncharged_handshake_churn_bypasses_per_ip_limit() {
    let limiter = ConnectionRateLimiter::new(/*limit_per_minute=*/5, /*max_burst=*/5, 4);
    let ip = IpAddr::V4(Ipv4Addr::new(10, 0, 0, 1));
    // Simulate N aborted handshakes: never call register_connection
    for _ in 0..10_000 {
        assert!(limiter.is_allowed(&ip), "per-IP limiter should have engaged but never does for aborted handshakes");
    }
    // Bucket should be fully intact since no successful handshake occurred
    assert_eq!(limiter.limiter.current_tokens(&ip), Some(5));
}
```

    /// Check if the connection from the said `ip` is allowed.
    /// Here we assume that only IPs with actual confirmed connections are stored in it,
    /// since we should only modify server state once source IP is verified
    pub fn is_allowed(&self, ip: &IpAddr) -> bool {
        // Check if we have records in the rate limiter for the given IP address
        match self.limiter.current_tokens(ip) {
            Some(r) => r > 0, // we have a record, and rate is not exceeded
            None => true,     // if we have not seen IP, allow connection request
        }
    }

    pub fn register_connection(&self, ip: &IpAddr) -> bool {
        if self.limiter.consume_tokens(*ip, 1).is_ok() {
            debug!("Request from IP {ip:?} allowed");
            true // Request allowed
        } else {
            debug!("Request from IP {ip:?} blocked");
            false // Request blocked
        }
    }
