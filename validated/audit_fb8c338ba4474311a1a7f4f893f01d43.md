### Title
Cross-chain transfers can remain locked when the destination bridged-in cap is reached - (File: `contracts/ProxyOFT.sol`)

### Summary
`ProxyOFT.sendFrom` burns the sender’s `SyntheticToken` before emitting the LayerZero message, while the destination-side `_creditTo` mints through `SyntheticToken.mint`. [1](#0-0)  If the destination’s `bridgedInSupply() + amount` exceeds `maxBridgedInSupply`, the mint reverts and the failed LayerZero message is only stored for a future retry. [2](#0-1) [3](#0-2)  There is no fallback path that returns the already-burned tokens on the source chain. [4](#0-3) 

### Finding Description
The source-side public entry point `ProxyOFT.sendFrom` calls `_send`, which debits the sender before sending the cross-chain payload. [5](#0-4) [6](#0-5)  `_debitFrom` verifies that the caller owns the tokens and that outbound bridging and the destination are enabled, then calls `syntheticToken.burn(from_, amount_)`. [7](#0-6)  For a ProxyOFT-initiated burn, `SyntheticToken._burn` increments `totalBridgedOut`, enforces `maxBridgedOutSupply`, and reduces `totalSupply`. [8](#0-7) 

On the destination chain, a valid `PT_SEND` message reaches `_sendAck`, which calls `_creditTo`; `ProxyOFT._creditTo` unconditionally calls `syntheticToken.mint(toAddress_, amount_)`. [9](#0-8) [10](#0-9)  `SyntheticToken._mint` increments `totalBridgedIn` and reverts with `SurpassMaxBridgingSupply` whenever the resulting net `bridgedInSupply()` is greater than `maxBridgedInSupply`. [11](#0-10) 

`NonblockingLzAppUpgradeable._blockingLzReceive` catches that failure and stores the payload hash in `failedMessages`, so delivery itself does not revert. [3](#0-2)  The public `retryMessage` function clears the stored hash and directly re-executes the same receive path, meaning it will revert again while the cap remains exhausted. [12](#0-11)  Neither `ProxyOFT._creditTo`, `SyntheticToken._mint`, nor `retryMessage` provides a cancellation or source-chain refund mechanism. [10](#0-9) [12](#0-11) 

### Impact Explanation
The bridge conservation invariant is temporarily violated because tokens are burned on the source chain but are not minted for the recipient on the destination chain. [1](#0-0)  The failed message can be retried only after destination net bridged-in supply decreases or the governor raises `maxBridgedInSupply`; until then, the user’s transferred funds remain inaccessible on both chains. [13](#0-12) [14](#0-13)  This causes temporary freezing of user funds and requires protocol intervention or later bridge activity if the cap remains exhausted. [12](#0-11) 

### Likelihood Explanation
Any unprivileged user can reach this state by successfully bridging enough tokens to consume the destination chain’s remaining `maxBridgedInSupply` allowance before another transfer arrives. [11](#0-10)  A griefer can deliberately front-run a victim’s inbound message with an inbound transfer that fills the cap, provided the attacker has sufficient source-chain synthetic tokens and outbound headroom. [15](#0-14) [16](#0-15)  The failure does not require a malicious endpoint, trusted remote, governor action, or disabled bridging flag because inbound `_creditTo` performs no bridging-active check and relies only on `SyntheticToken.mint`. [10](#0-9) [17](#0-16) 

### Recommendation
Add a pre-delivery availability check or a failed-transfer recovery path for transfers rejected by `SurpassMaxBridgingSupply`. [16](#0-15)  At minimum, retain the failed message without exposing a revert loop and provide a permissionless “return to source” mechanism that sends a compensating message back to the original sender or credits them through a dedicated refund flow. [12](#0-11)  Destination capacity should also be reserved or checked before `_debitFrom` burns the source-chain tokens, although LayerZero cannot guarantee that destination capacity remains available by execution time. [7](#0-6) 

### Proof of Concept
The following Foundry fork test impersonates the configured LayerZero endpoint only to deliver already-authenticated payloads and uses `trustedRemoteLookup` as the source address, matching the production `lzReceive` trust checks. [17](#0-16) 

```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity ^0.8.24;

import "forge-std/Test.sol";
import {ProxyOFT} from "contracts/ProxyOFT.sol";
import {SyntheticToken, SurpassMaxBridgingSupply} from "contracts/SyntheticToken.sol";

contract BridgedInCapLockTest is Test {
    uint16 constant PT_SEND = 0;

    function test_InboundCapLocksBurnedTransfer() public {
        vm.createSelectFork(vm.envString("DESTINATION_RPC_URL"));

        ProxyOFT dstOft = ProxyOFT(vm.envAddress("DESTINATION_PROXY_OFT"));
        SyntheticToken synth = SyntheticToken(dstOft.token());
        uint16 srcChainId = uint16(vm.envUint("SOURCE_LZ_CHAIN_ID"));

        bytes memory trustedRemote = dstOft.trustedRemoteLookup(srcChainId);
        address endpoint = address(dstOft.lzEndpoint());

        uint256 remainingCap =
            synth.maxBridgedInSupply() - synth.bridgedInSupply();
        require(remainingCap > 0, "destination cap already full");
        require(
            synth.maxTotalSupply() - synth.totalSupply() >= remainingCap,
            "total supply cap reached first"
        );

        // A prior public transfer legitimately consumes all remaining
        // destination bridged-in capacity.
        bytes memory fillPayload = abi.encode(
            PT_SEND,
            abi.encodePacked(address(0xA77A)),
            remainingCap
        );
        vm.prank(endpoint);
        dstOft.lzReceive(srcChainId, trustedRemote, 1, fillPayload);
        assertEq(synth.bridgedInSupply(), synth.maxBridgedInSupply());

        // The victim's corresponding source-chain sendFrom() already burned
        // amount tokens. Destination mint now exceeds maxBridgedInSupply.
        address victim = address(0xB0B);
        uint256 amount = 1;
        bytes memory victimPayload = abi.encode(
            PT_SEND,
            abi.encodePacked(victim),
            amount
        );

        vm.prank(endpoint);
        dstOft.lzReceive(srcChainId, trustedRemote, 2, victimPayload);

        bytes32 stored =
            dstOft.failedMessages(srcChainId, trustedRemote, 2);
        assertTrue(stored != bytes32(0));
        assertEq(synth.balanceOf(victim), 0);

        // Anyone may retry, but the same cap error makes the retry unusable.
        vm.expectRevert(SurpassMaxBridgingSupply.selector);
        dstOft.retryMessage(srcChainId, trustedRemote, 2, victimPayload);
    }
}
```

The second delivery succeeds at the endpoint layer while the token mint fails internally, leaving `failedMessages` populated and `victim` without destination tokens. [3](#0-2)  Calling `retryMessage` with the identical payload reaches `_creditTo` again and reverts until capacity becomes available. [12](#0-11)

    function _burn(address account_, uint256 amount_) private {
        if (account_ == address(0)) revert BurnFromTheZeroAddress();

        address _msgSender = _msgSender();

        if (_isMsgSenderProxyOFT(_msgSender)) {
            totalBridgedOut += amount_;
            if (bridgedOutSupply() > maxBridgedOutSupply) revert SurpassMaxBridgingSupply();
        } else if (_isMsgSenderAmo(_msgSender)) {
            // AMO can only burn from self address.
            // account_ should be AMO and in this case it is same as _msgSender()
            if (account_ != _msgSender) revert AmoInvalidAccount();

            amoSupply -= amount_;
        }

        uint256 _currentBalance = balanceOf[account_];
        if (_currentBalance < amount_) revert BurnAmountExceedsBalance();
        unchecked {
            balanceOf[account_] = _currentBalance - amount_;
            totalSupply -= amount_;
        }

        emit Transfer(account_, address(0), amount_);

    function retryMessage(uint16 _srcChainId, bytes calldata _srcAddress, uint64 _nonce, bytes calldata _payload) public payable virtual {
        // assert there is message to retry
        bytes32 payloadHash = failedMessages[_srcChainId][_srcAddress][_nonce];
        require(payloadHash != bytes32(0), "NonblockingLzApp: no stored message");
        require(keccak256(_payload) == payloadHash, "NonblockingLzApp: invalid payload");
        // clear the stored message
        failedMessages[_srcChainId][_srcAddress][_nonce] = bytes32(0);
        // execute the message. revert if it fails again
        _nonblockingLzReceive(_srcChainId, _srcAddress, _nonce, _payload);
        emit RetryMessageSuccess(_srcChainId, _srcAddress, _nonce, payloadHash);
