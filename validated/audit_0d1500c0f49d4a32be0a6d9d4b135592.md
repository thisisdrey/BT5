### Title
Interest rate config can be changed without first accruing pending interest, causing retroactive misapplication of the new rate to a stale time period - (File: `programs/marginfi/src/instructions/marginfi_group/configure_bank.rs` / `programs/marginfi/src/instructions/marginfi_group/configure_bank_lite.rs`)

### Summary
`lending_pool_configure_bank` and `lending_pool_configure_bank_interest_only` mutate a bank's `interest_rate_config` in place without first calling `accrue_interest`. Since `accrue_interest` charges the *entire* elapsed `time_delta` since `bank.last_update` using whatever `interest_rate_config` is active at the moment it runs, any config change made while `last_update` is stale causes the new rate to be retroactively applied to time that elapsed under the old rate.

### Finding Description
`lending_pool_configure_bank` calls `bank.configure(&bank_config)` directly, which updates `self.config.interest_rate_config` (and weights, risk tier, etc.) with no preceding accrual step: [1](#0-0) 

Likewise, `lending_pool_configure_bank_interest_only` updates `interest_rate_config` directly with no accrual call: [2](#0-1) 

Compare this to instructions that correctly call `accrue_interest` immediately before touching bank state that depends on `last_update`/rate curve, such as `lending_pool_accrue_bank_interest`: [3](#0-2) 

and `lending_pool_emissions_deposit`: [4](#0-3) 

The root of the bug is in `Bank::accrue_interest`, which computes a single `time_delta` covering the whole gap since `last_update` and applies the *current* `interest_rate_config` (fetched via `create_interest_rate_calculator`) uniformly across that entire span: [5](#0-4) 

This is structurally identical to the referenced Quill issue: `calcPendingSPYield` (an estimator that multiplies pending interest by a mutable split parameter) produces wrong results if the split is changed before the pending interest is realized. Here, `calc_interest_rate_accrual_state_changes` multiplies the *entire* un-accrued `time_delta` by the *current* rate curve; if the curve is swapped mid-interval (via `lending_pool_configure_bank` / `lending_pool_configure_bank_interest_only`) without first flushing (accruing) the interval up to that point, the new curve is illegitimately back-applied to time it was never in effect for.

### Impact Explanation
Whenever a bank goes without any balance-affecting transaction (deposit/withdraw/borrow/repay/liquidate/accrue) for some period, and the admin (or `delegate_curve_admin`) updates the interest rate curve during that gap, the next transaction that finally triggers `accrue_interest` will price the *entire* stale interval — including the portion that occurred before the config change — at the new rate. This directly changes the debt owed by every borrower and the yield earned by every lender/depositor in that bank for a period during which the old rate should have applied, i.e. an unauthorized retroactive change to core accounting state (`asset_share_value` / `liability_share_value`, and collected protocol/insurance fees) affecting unprivileged margin-account holders. Depending on the direction of the rate change, this can inflate borrower debt (risking unwarranted liquidations) or shortchange lenders (or the inverse), and it also affects `collected_group_fees_outstanding` / `collected_insurance_fees_outstanding`.

### Likelihood Explanation
This requires no attacker, only a normal (non-malicious) governance/curve-admin action: updating a bank's interest curve while the bank has been quiet (no interactions since `last_update`). Because interest curve changes are a routine operational lever and banks with lower activity can easily go stale between transactions, this is a realistic, frequently reachable condition rather than a purely theoretical one.

### Recommendation
In both `lending_pool_configure_bank` and `lending_pool_configure_bank_interest_only`, call `bank.accrue_interest(clock.unix_timestamp, &group, ...)` (and `bank.update_bank_cache(&group)`) to flush any pending interest at the *old* rate before applying the new `interest_rate_config`/other config changes, mirroring the pattern already used in `lending_pool_accrue_bank_interest` and `lending_pool_emissions_deposit`.

### Proof of Concept
1. Bank `B` has active borrowers/lenders; `last_update = t0`.
2. No user transacts with `B` for some period (no deposit/withdraw/borrow/repay/liquidate/accrue instruction is sent), so `last_update` remains `t0` even as the clock advances to `t1`.
3. Admin calls `lending_pool_configure_bank_interest_only` (or `lending_pool_configure_bank`) at `t1`, changing `interest_rate_config` (e.g., raising `zero_util_rate`/curve points). `bank.configure()`/the interest-only path writes the new config directly; `bank.last_update` is untouched, still `t0`.
4. At `t2`, any user action (e.g., a deposit) triggers `Bank::accrue_interest(t2, ...)`. `time_delta = t2 - t0` spans both the pre-change interval `[t0, t1]` and the post-change interval `[t1, t2]`, but the whole delta is computed using only the *new* `interest_rate_config` fetched via `create_interest_rate_calculator`.
5. Result: interest for `[t0, t1]` — which should have accrued under the old curve — is instead charged/credited at the new curve's rate, retroactively altering every user's `asset_share_value`/`liability_share_value` in bank `B` for a period during which the new rate was never actually in effect.

    ctx: Context<LendingPoolConfigureBankInterestOnly>,
    interest_rate_config: InterestRateConfigOpt,

    let mut bank = ctx.accounts.bank.load_mut()?;
    msg!(
        "Configuring bank: {:?} mint: {:?}",
        ctx.accounts.bank.key(),
        bank.mint
    );

    // If settings are frozen, interest rates can't update.
    if bank.get_flag(FREEZE_SETTINGS) {
        msg!("WARN: Bank settings frozen, did nothing.");
    } else {
        bank.config
            .interest_rate_config
            .update(&interest_rate_config);
        bank.config.interest_rate_config.validate()?;
        msg!("Bank configured!");
    }

pub fn lending_pool_accrue_bank_interest(
    ctx: Context<LendingPoolAccrueBankInterest>,
) -> MarginfiResult {
    let clock = Clock::get()?;
    let mut bank = ctx.accounts.bank.load_mut()?;
    let group = &ctx.accounts.group.load()?;

    bank.accrue_interest(
        clock.unix_timestamp,
        group,
        #[cfg(not(feature = "client"))]
        ctx.accounts.bank.key(),
    )?;

    // TODO see if we can recycle some things like the InterestRateCalc from accrue to save some CU
    bank.update_bank_cache(group)?;

    Ok(())
}

    fn accrue_interest(
        &mut self,
        current_timestamp: i64,
        group: &MarginfiGroup,
        #[cfg(not(feature = "client"))] bank: Pubkey,
    ) -> MarginfiResult<()> {
        #[cfg(all(not(feature = "client"), feature = "debug"))]
        sol_log_compute_units();

        let time_delta: u64 = (current_timestamp - self.last_update).try_into().unwrap();
        if time_delta == 0 {
            return Ok(());
        }

        let total_assets = self.get_asset_amount(self.total_asset_shares.into())?;
        let total_liabilities = self.get_liability_amount(self.total_liability_shares.into())?;

        self.last_update = current_timestamp;

        if (total_assets == I80F48::ZERO) || (total_liabilities == I80F48::ZERO) {
            #[cfg(not(feature = "client"))]
            emit!(LendingPoolBankAccrueInterestEvent {
                header: GroupEventHeader {
                    marginfi_group: self.group,
                    signer: None
                },
                bank,
                mint: self.mint,
                delta: time_delta,
                fees_collected: 0.,
                insurance_collected: 0.,
            });

            return Ok(());
        }
        let ir_calc = self
            .config
            .interest_rate_config
            .create_interest_rate_calculator(group);

        let InterestRateStateChanges {
            new_asset_share_value: asset_share_value,
            new_liability_share_value: liability_share_value,
            insurance_fees_collected,
            group_fees_collected,
            protocol_fees_collected,
        } = calc_interest_rate_accrual_state_changes(
            time_delta,
            total_assets,
            total_liabilities,
            &ir_calc,
            self.asset_share_value.into(),
            self.liability_share_value.into(),
        )?;
