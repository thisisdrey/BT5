### Title
Unauthenticated remote `/shutdown` HTTP route permanently kills the signer's event receiver - ([File: libsigner/src/events.rs])

### Summary
The `SignerEventReceiver::next_event` handler treats any `POST /shutdown` HTTP request on the signer's bound event port as a legitimate stop command, with no source verification, secret, or authentication of any kind. Any remote TCP peer that can reach the listening port can permanently disable the signer's event pipeline with a single crafted HTTP request.

### Finding Description
`next_event` dispatches on `request.url()` and, for `/shutdown`, unconditionally calls `event_receiver.stop_signal.store(true, Ordering::SeqCst)` and returns `Err(EventError::Terminated)`, with no check of the request body, source IP, or any shared secret. [1](#0-0)  The `stop_signal` is an `Arc<AtomicBool>` checked both at the top of `next_event` (`if event_receiver.is_stopped() { return Err(EventError::Terminated); }`) and in `EventReceiver::main_loop`, which treats `EventError::Terminated` as "we're done" and `break`s out of the loop permanently. [4](#0-3)  There is no equivalent of the `Content-Length`/body verification, HMAC, or shared-secret check that other event routes (`/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block`) at least perform via `process_event` (although those, too, lack auth — but this question is scoped to `/shutdown`). The intended caller is `SignerStopSignaler::send`, which is only supposed to be invoked locally by the same signer process via `RunningSigner::stop` or the SIGINT/SIGTERM handler in `libsigner/src/runloop.rs` (`set_runloop_signal_handler`), but nothing in the wire protocol restricts the route to loopback or the local process — it is a plain HTTP endpoint reachable by anyone who can open a TCP connection to the bound address. [5](#0-4) [6](#0-5)  Once `stop_signal` is set, `main_loop` exits for good — it is not idempotent/restart-safe by design — meaning the signer's node process will never receive `NewBlock`, `NewBurnBlock`, `StackerDBChunks`, or `BlockValidationResponse` events again for that receiver instance. This matches the developer-acknowledged risk noted when constructing `SpawnedSigner`, which explicitly warns that exposing the signer event port beyond a trusted local network can "expose sensitive data or functionalities to security risks." [7](#0-6) 

### Impact Explanation
A single unauthenticated `POST /shutdown` HTTP request permanently halts the signer's `main_loop` event-receiving thread. [8](#0-7)  This is a complete, repeatable (though only needs to fire once per receiver lifetime), critical denial-of-service against the signer's ability to observe StackerDB chunks, burn blocks, new Stacks blocks, and block validation responses coming from the node it's paired with — effectively taking that signer offline from the node's perspective while the process otherwise keeps running, silently. This matches the "Critical - remote crash/unauthenticated DoS from few messages" category.

### Likelihood Explanation
The only precondition is TCP reachability to the port opened by `SignerEventReceiver::bind`/`Signer::spawn`, which listens on `config.endpoint` (often configured to a non-loopback address so the node can reach it, and sometimes exposed further depending on operator network topology). [9](#0-8)  No authentication, secret, peer registration, or StackerDB slot ownership is required — this is a bare HTTP POST with an arbitrary body. Attacker cost is a single TCP connection and one HTTP request.

### Recommendation
Restrict the `/shutdown` route to loopback/local-process callers only (e.g., bind a separate local control socket or Unix domain socket for stop signaling instead of reusing the public HTTP event port), or require a per-process shared secret/token generated at startup and checked before honoring `/shutdown` (and ideally before honoring any state-mutating route on this port).

### Proof of Concept
Rust test plan: 1) construct a `SignerEventReceiver::<SignerMessage>::new(false)` and call `bind` on `127.0.0.1:<port>` (mirroring the existing `test_status_endpoint` pattern at [10](#0-9) ). 2) From a separate, unrelated `TcpStream::connect(endpoint)`, write raw bytes `"POST /shutdown HTTP/1.1\r\nHost: {endpoint}\r\nConnection: close\r\nContent-Length: 4\r\n\r\ntest"` with no prior handshake or credential. 3) Call `next_event()` on the receiver and assert it returns `Err(EventError::Terminated)`; then assert `receiver.is_stopped()` returns `true`. 4) Confirm that a subsequent legitimate `/stackerdb_chunks` POST from a second, "legitimate" client is never processed because `main_loop`/`next_event` immediately short-circuits with `Terminated` going forward.
