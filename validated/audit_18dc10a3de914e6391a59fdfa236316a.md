### Title
Uncaught out-of-bounds array read in `ValidateMultiSign` precompile signature-array extraction - (File: `actuator/src/main/java/org/tron/core/vm/PrecompiledContracts.java`)

### Summary
The CVE-2016-7175 bug class is a fixed-length-field parser (MAC address) that trusts attacker-controlled offsets/lengths and reads out of bounds, crashing the process. The `ValidateMultiSign` precompiled contract in java-tron has the same class of bug: it decodes a fixed-length signature array from calldata using attacker-controlled ABI offsets without validating them against the input buffer, and — unlike its sibling `BatchValidateSign` — does **not** wrap the extraction call in a catch-all exception handler.

### Finding Description
`ValidateMultiSign.execute()` parses the raw TVM call data into 32-byte words and then computes an index into that word array purely from attacker-supplied data: [1](#0-0) 

The extraction helpers `extractSigArray` / `extractBytesArray` use `words[offset].intValueSafe()` and `words[offset + i + 1].intValueSafe()` — values fully controlled by the caller of the precompile via the `data` bytes of a `validatemultisign` contract call — to index into the `words` array and to slice the raw `data` byte array: [2](#0-1) 

Only when `VMConfig.allowTvmSelfdestructRestriction()` is active is `sigArraySize` bounded (`> MAX_SIZE` check), and even then only the *declared length* is checked, not the offsets used to compute `bytesOffset` or the final slice bounds passed to `Arrays.copyOfRange` in `extractBytes`. A crafted offset can make `words[offset + i + 1]` throw `ArrayIndexOutOfBoundsException`, or make `extractBytes`'s `offset + len` exceed `data.length`, throwing from `Arrays.copyOfRange`.

Critically, in `ValidateMultiSign.execute()` this extraction call (line 1072-1074) happens **before** and **outside** the `try { ... } catch (Throwable t)` block that only wraps the later permission-weight logic (lines 1082-1118). This differs from `BatchValidateSign`, whose public `execute()` wraps the entire `doExecute()` call — including its own identical `extractSigArray`/`extractBytesArray` calls — in a catch-all `try/catch (Throwable t)`: [3](#0-2) 

So `ValidateMultiSign` has no equivalent protection for the array-index/slice computation.

### Impact Explanation
`ValidateMultiSign` is a TVM precompiled contract, reachable by any account that deploys or calls a smart contract invoking it (e.g. via `abi.staticcall` to the fixed precompile address, or a contract wrapper), i.e. by an unprivileged transaction broadcaster/contract caller. A malformed `sig` array offset triggers an uncaught `RuntimeException` (`ArrayIndexOutOfBoundsException`) inside the precompiled-contract `execute()` call. Depending on how far up the TVM execution stack this propagates before being caught, this ranges from an unhandled runtime exception during transaction processing (potential inconsistent state / unexpected DoS at block-application time) up to a crash if the exception is not caught anywhere above `Program`/`Runtime`. I could not fully verify within the available exploration whether an outer VM execution layer (e.g., `Program`/`Runtime.execute()`) generically catches all `Throwable` from precompiled-contract calls; if it does, the practical impact is limited to a reverted/failed transaction rather than a node crash, which would reduce this below the required severity bar.

### Likelihood Explanation
High reachability: this is exercised via a single TVM call to a fixed, publicly documented precompile address using attacker-fully-controlled calldata, requiring no special permission or state — only a signed transaction that triggers a contract call.

### Recommendation
Add explicit bounds validation before dereferencing `words[...]` and before calling `Arrays.copyOfRange` in `extractSigArray`/`extractBytesArray`/`extractBytes` (validate `offset`, `bytesOffset`, and `offset+len <= data.length` and `offset < words.length`), and/or wrap the entire `ValidateMultiSign.execute()` body in the same catch-all `Throwable` handling pattern already used in `BatchValidateSign.execute()`.

### Proof of Concept
Craft calldata for `validatemultisign(address,uint256,bytes32,bytes[])`-style ABI layout where the fourth word (signature-array offset pointer, index used at `words[3].intValueSafe() / WORD_SIZE`) points to a location such that `words[offset + i + 1]` exceeds `words.length`, or where the computed `bytesOffset` makes the slice end (`(bytesOffset + offset + 2) * WORD_SIZE + SIG_LENGTH`) exceed `rawData.length`. Invoke this precompile via a contract call (`STATICCALL`/`CALL` to the `ValidateMultiSign` precompile address) from any account; `extractSigArray`/`extractBytes` will throw an uncaught exception from within `ValidateMultiSign.execute()` (lines 1072-1074), which is not caught anywhere inside that method.

**Note on uncertainty:** I was not able to confirm, within the scope of this analysis, whether an outer exception handler in the TVM execution pipeline (e.g. `Program`, `Runtime`) generically catches `Throwable` from all precompiled-contract executions. If such a catch-all exists above `ValidateMultiSign.execute()`, the impact is limited to a failed/reverted transaction rather than node crash, and this finding would need to be downgraded accordingly.

  private static byte[][] extractSigArray(DataWord[] words, int offset, byte[] data) {
    if (offset > words.length - 1) {
      return new byte[0][];
    }
    int len = words[offset].intValueSafe();
    byte[][] bytesArray = new byte[len][];
    for (int i = 0; i < len; i++) {
      int bytesOffset = words[offset + i + 1].intValueSafe() / WORD_SIZE;
      bytesArray[i] = extractBytes(data, (bytesOffset + offset + 2) * WORD_SIZE,
          SIG_LENGTH);
    }
    return bytesArray;
  }

  private static byte[] extractBytes(byte[] data, int offset, int len) {
    return Arrays.copyOfRange(data, offset, offset + len);
  }
