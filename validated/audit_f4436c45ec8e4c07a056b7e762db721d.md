## Title
Out-of-bounds read when parsing ZIP central-directory extra fields in ijar - (File: `third_party/ijar/zip.cc`)

### Summary
`InputZipFile::ProcessCentralDirEntry` in [1](#0-0)  parses every field of a ZIP central-directory record (compressed/uncompressed size, file-name length, extra-field length, comment length, and then the extra-field TLV records themselves) directly from the mmap'd input buffer with **no bounds checking at all**. This is the ijar analog of the CVE-2018-11738 pattern in `ntfs_make_data_run`: a length field taken from attacker-controlled binary metadata is used to walk a cursor forward with no verification that the cursor stays inside the mapped region, producing an out-of-bounds read.

### Finding Description
Compare the two zip-parsing code paths shipped in this repo:

- `InputZipFile::ProcessLocalFileEntry` (used for *local* file headers) explicitly calls `EnsureRemaining()` before every variable-length read: [2](#0-1) .
- `singlejar`'s `ExtraField::find` (used when merging jars for deploy-jars) validates that each extra-field record fits within `[start, end)` before dereferencing it: [3](#0-2) .

`InputZipFile::ProcessCentralDirEntry`, however, has none of these checks:

```
p += 16;  // skip to 'compressed size' field
*compressed_size = get_u4le(p);
*uncompressed_size = get_u4le(p);
u2 file_name_length = get_u2le(p);
u2 extra_field_length = get_u2le(p);
u2 file_comment_length = get_u2le(p);
...
p += file_name_length;
const u1 *extra_p = p;
p += extra_field_length;
while (extra_p != p) {
  const u2 header_id = get_u2le(extra_p);
  const u2 data_size = get_u2le(extra_p);
  const u1 *extra = extra_p;
  extra_p += data_size;
  if (header_id == ZIP64_EXTRA_FIELD_TAG) { ... get_u8le(extra) ... }
}
p += file_comment_length;
``` [4](#0-3) 

`file_name_length`, `extra_field_length`, and the per-record `data_size` inside the extra-field loop are all attacker-controlled 16-bit values read straight from the archive. None of them is checked against the actual size of the mapped file (`input_file_->Length()`, obtained via `GetSize()` at [5](#0-4) ) or against the end of the central directory. A crafted entry can set `extra_field_length` (or a `data_size` inside it) large enough that `extra_p`/`p` walks past the end of the mmap'd region, after which `get_u2le`/`get_u4le`/`get_u8le` dereference memory outside the file mapping.

This function is invoked in a loop for *every* central-directory record by `ProcessNext()` ( [6](#0-5) ) and by `CalculateOutputLength()` ( [7](#0-6) ), which is the entry point ijar uses to strip a jar down to its interface (class-signature-only) form for use in Java compilation actions — i.e., it is run over jar files that can originate from external, attacker-influenced sources (`java_import`/`aar_import` prebuilt jars, maven artifacts fetched by download rules) that are pinned only by a `sha256`/`integrity` value on the exact bytes the attacker chose to publish. A pinned checksum authenticates that those specific bytes were fetched, but does nothing to stop the bytes themselves from containing a malformed ZIP central directory of this kind.

### Impact Explanation
Because `*compressed_size`/`*uncompressed_size`/`*offset` and the resulting cursor position feed into `ProcessLocalFileEntry`, `UncompressFile`, and `SkipFile` (which subsequently trust these attacker-influenced values, e.g. [8](#0-7) ), out-of-bounds bytes read from adjacent process memory can end up copied into the interface-jar contents written by the build (via `filename` buffer copy at [9](#0-8)  and downstream data copies), disclosing heap/mmap memory contents of the ijar process into a build artifact that is retained/inspected by the victim. In the worst case the walk exceeds the mapped pages entirely and crashes the process (denial of service on that build action).

### Likelihood Explanation
Any archive that becomes an input to an ijar action — including externally-sourced prebuilt jars pinned only by checksum — can trigger this path. Crafting a central-directory record with an oversized `extra_field_length` or a bogus extra-field `data_size` is trivial and entirely under the control of whoever publishes the archive that a victim's build later downloads and pins.

### Recommendation
Add the same bounds validation to `InputZipFile::ProcessCentralDirEntry` that already exists in `ProcessLocalFileEntry` (`EnsureRemaining`) and in `singlejar`'s `ExtraField::find`: verify `file_name_length`, `extra_field_length`, `file_comment_length`, and every extra-field `data_size` against the actual remaining bytes in the mapped central directory/file before advancing the cursor or dereferencing memory.

### Proof of Concept
Construct a minimal ZIP whose single central-directory record sets `extra_field_length` to a large value (e.g. `0xFFFF`) while the mapped file is only large enough to contain a few real bytes of extra-field data, mirroring the technique already used in `CreateZipWithMalformedExtraField()` for `singlejar` ( [10](#0-9) ), but feed it to the `ijar` binary (`InputZipFile::Open()` → `ProcessNext()`/`CalculateOutputLength()`) instead of `singlejar`. Running ijar over this crafted archive drives `ProcessCentralDirEntry`'s unbounded `while (extra_p != p)` loop and the unchecked `p += extra_field_length` past the mmap'd region, which can be observed via ASan/valgrind as a heap-buffer-overflow read, or as leaked bytes copied into the produced interface jar.

bool InputZipFile::ProcessCentralDirEntry(const u1 *&p, u8 *compressed_size,
                                          u8 *uncompressed_size, char *filename,
                                          size_t filename_size, u4 *attr,
                                          u8 *offset) {
  u4 signature = get_u4le(p);

  if (signature != CENTRAL_FILE_HEADER_SIGNATURE) {
    if (signature != DIGITAL_SIGNATURE && signature != EOCD_SIGNATURE &&
        signature != ZIP64_EOCD_SIGNATURE) {
      error("invalid central file header signature: 0x%x\n", signature);
    }
    return false;
  }

  p += 16;  // skip to 'compressed size' field
  *compressed_size = get_u4le(p);
  *uncompressed_size = get_u4le(p);
  u2 file_name_length = get_u2le(p);
  u2 extra_field_length = get_u2le(p);
  u2 file_comment_length = get_u2le(p);
  p += 4;  // skip to external file attributes field
  *attr = get_u4le(p);
  *offset = get_u4le(p);
  {
    size_t len = (file_name_length < filename_size)
      ? file_name_length
      : (filename_size - 1);
    memcpy(reinterpret_cast<void*>(filename), p, len);
    filename[len] = 0;
  }
  p += file_name_length;
  const u1 *extra_p = p;
  p += extra_field_length;
  while (extra_p != p) {
    const u2 header_id = get_u2le(extra_p);
    const u2 data_size = get_u2le(extra_p);
    const u1 *extra = extra_p;
    extra_p += data_size;
    if (header_id == ZIP64_EXTRA_FIELD_TAG) {
      if (*uncompressed_size == U4_MAX) {
        *uncompressed_size = get_u8le(extra);
      }
      if (*compressed_size == U4_MAX) {
        *compressed_size = get_u8le(extra);
      }
      if (*offset == U4_MAX) {
        *offset = get_u8le(extra);
      }
    }
  }
  p += file_comment_length;
  return true;
}

u8 InputZipFile::CalculateOutputLength() {
  const u1* current = central_dir_;

  u8 compressed_size = 0;
  u8 uncompressed_size = 0;
  u8 skipped_compressed_size = 0;
  u4 attr;
  u8 offset;
  char filename[PATH_MAX];

  while (true) {
    u8 file_compressed, file_uncompressed;
    if (!ProcessCentralDirEntry(current,
                                &file_compressed, &file_uncompressed,
                                filename, PATH_MAX, &attr, &offset)) {
      break;
    }

    if (processor->Accept(filename, attr)) {
      compressed_size += (u8) file_compressed;
      uncompressed_size += (u8) file_uncompressed;
    } else {
      skipped_compressed_size += file_compressed;
    }
  }

  // The worst case is when the output is simply the input uncompressed. The
  // metadata in the zip file will stay the same, so the file will grow by the
  // difference between the compressed and uncompressed sizes.
  return (u8) input_file_->Length() - skipped_compressed_size
      + (uncompressed_size - compressed_size);
}

  std::string zip_data;
  const std::string filename = "evil.bin";

  // 1. Local File Header (LFH)
  size_t lh_offset = zip_data.size();
  size_t lh_size = sizeof(LH) + filename.size();
  zip_data.resize(lh_offset + lh_size, 0);
  auto* lh = reinterpret_cast<LH*>(&zip_data[lh_offset]);
  lh->signature();
  lh->version(10);
  lh->file_name(filename.data(), filename.size());

  // 2. Extra field payload containing an oversized payload_size
  uint8_t ef_buffer[8] = {0};
  auto* ef1 = reinterpret_cast<ExtraField*>(ef_buffer);
  ef1->signature(0x000d);
  ef1->payload_size(0);

  auto* ef2 = reinterpret_cast<ExtraField*>(ef_buffer + ef1->size());
  ef2->signature(0xdead);
  ef2->payload_size(0xf000);  // Malformed size exceeding extra field buffer

  // 3. Central Directory Header (CDH)
  size_t cdh_offset = zip_data.size();
  size_t cdh_size = sizeof(CDH) + filename.size() + sizeof(ef_buffer);
  zip_data.resize(cdh_offset + cdh_size, 0);
  auto* cdh = reinterpret_cast<CDH*>(&zip_data[cdh_offset]);
  cdh->signature();
  cdh->version(20);
  cdh->version_to_extract(10);
  cdh->local_header_offset32(lh_offset);
  cdh->file_name(filename.data(), filename.size());
  cdh->extra_fields(ef_buffer, sizeof(ef_buffer));

  // 4. End of Central Directory (EOCD)
  size_t ecd_offset = zip_data.size();
  zip_data.resize(ecd_offset + sizeof(ECD), 0);
  auto* ecd = reinterpret_cast<ECD*>(&zip_data[ecd_offset]);
  ecd->signature();
  ecd->this_disk_entries16(1);
  ecd->total_entries16(1);
  ecd->cen_size32(cdh_size);
  ecd->cen_offset32(cdh_offset);

  return zip_data;
}
