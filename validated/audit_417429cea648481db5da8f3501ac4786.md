### Title
Integer-overflow unsafe cast in MVCC manifest chunk-offset parsing bypasses bounds checks - ([File: internal/git/mvcc/manifest.go])

### Summary
`ParseManifest` and its helper `parseChunks` parse an attacker/peer-influenced binary manifest by directly narrowing `uint64`/`uint32` file-offset and size fields read from the manifest bytes into Go `int` with `int(...)` casts, then using those `int` values as slice bounds without validating that the cast preserved the original magnitude/sign. [1](#0-0)  This mirrors the "unsafecast" bug class from the reported DeFi incident (an unchecked narrowing cast that violates an implicit invariant the surrounding logic relies on for a bounds/limit check), just applied to Gitaly's binary manifest parser instead of a smart contract.

### Finding Description
`parseChunks` reads each TOC entry's 64-bit big-endian offset and casts it straight to `int`:
```go
chunkOffsetInFile := int(binary.BigEndian.Uint64(data[chunkOffset+4 : chunkOffset+tocChunkSize]))
...
nextChunkOffsetInFile := int(binary.BigEndian.Uint64(data[nextChunkStart+4 : nextChunkStart+tocChunkSize]))
``` [2](#0-1) 

On 64-bit platforms `int` is 64 bits, so a crafted `uint64` value larger than `math.MaxInt64` (e.g. `0xFFFFFFFFFFFFFF9C`) converts to a *negative* `int` after the cast. The subsequent bounds check:
```go
if chunkOffsetInFile > dataEnd || nextChunkOffsetInFile > dataEnd || nextChunkOffsetInFile < chunkOffsetInFile {
    return nil, fmt.Errorf(...)
}
``` [3](#0-2) 
does not reject negative offsets — a negative value is always `<= dataEnd`, and two negative offsets can still satisfy `nextChunkOffsetInFile >= chunkOffsetInFile` (e.g. `-100` and `-50`). The resulting bogus, negative `manifestChunk.offset`/`size` is then propagated unchecked into `ParseManifest`, where it is used directly as a slice index/bound, e.g.:
```go
start := pathChunk.offset + i*pw
record := data[start : start+pw]
``` [4](#0-3) 
and for the OBJS/REFS chunks:
```go
m.objStart = int(binary.BigEndian.Uint32(data[objsChunk.offset : objsChunk.offset+4]))
``` [5](#0-4) 
A negative slice index/bound causes a Go runtime panic (`slice bounds out of range`), and the header's own `numChunks`/`pathWidth` fields (`data[5]`, `data[6]`) are similarly cast from a raw byte into `int` without cross-validation against `tocChunkSize`-derived bounds beyond the length check performed in `parseManifestHeader`. [6](#0-5) 

The manifest file is fetched from the pluggable `ObjectStorage` backend (`m.rs.ReadManifest`) and parsed unconditionally by `LocalCache.prepareManifestFile`, which is invoked from the gRPC `mvcc` middleware (`CacheInterceptor.buildCache` → `cache.Prepare`) on essentially every RPC against a repository using the MVCC reference backend. [7](#0-6) [8](#0-7)  Manifests are also re-parsed at commit time from a hash written by whatever process/client drove the write path. [9](#0-8) 

### Impact Explanation
If an attacker can influence the content of a manifest object stored in the MVCC object storage (or the manifest resolved via `ReadManifestPointer`/a client-supplied manifest hash used in `PrepareWithManifest`), a crafted TOC entry with an overflowing 64-bit offset defeats the offset/size validation in `parseChunks` and causes `ParseManifest` to compute negative slice bounds, panicking the goroutine handling the RPC. Since this runs inside the per-request MVCC cache-warming path invoked by the gRPC middleware for essentially all RPCs on an MVCC-backed repository, a successful crafted manifest can crash or otherwise abnormally terminate request handling — a denial-of-service of the RPC handler. [10](#0-9) 

### Likelihood Explanation
Exploitability depends on whether an ordinary user/client can get a manifest with attacker-controlled bytes parsed — e.g. via `PrepareWithManifest`'s client-supplied hash path ("used when the RPC already contains a manifest hash in the metadata") or by writing objects into the MVCC object storage backing a repository they can push/import into. [11](#0-10)  I was not able to fully trace, within the available index, exactly which external actor/RPC field supplies the manifest hash consumed by `PrepareWithManifest`/`ReadManifest`, nor confirm whether the object storage backend enforces integrity checks (beyond the SHA-256 trailer already validated in `ParseManifest`) that would prevent an attacker from injecting a crafted manifest blob. This is a gap in what the codebase index exposes, not a claim that the path is unreachable.

### Recommendation
Validate all narrowing casts from wire/file `uint32`/`uint64` values to `int` before use: reject values that don't round-trip (i.e., `uint64(int(x)) != x`) or that exceed `dataEnd`/`len(data)` as unsigned quantities prior to casting, rather than after. Perform all offset/size arithmetic and bounds comparisons in the wider unsigned type (or with explicit overflow-safe helpers) so a maliciously large 64-bit offset cannot become a negative `int`. Apply this to every offset/count derived from manifest bytes in `parseManifestHeader`, `parseChunks`, and `ParseManifest` (`chunkOffsetInFile`, `nextChunkOffsetInFile`, `m.objStart`, `m.objCount`, REFS `idx`). Add fuzz/unit tests specifically targeting overflow boundary values (`0xFFFFFFFFFFFFFFFF`-adjacent) for each cast site.

### Proof of Concept
Construct a manifest byte buffer with:
1. A valid 8-byte header (`"MVCC"`, version `1`, `numChunks = 1`, `pathWidth` in `[1,128]`, valid `hashAlgo`).
2. A single TOC entry (chunk id = `chunkIDPath`) whose 8-byte big-endian offset field encodes a value `> math.MaxInt64`, e.g. `0xFFFFFFFFFFFFFF9C` (which is `-100` once cast to `int64`).
3. A terminator TOC entry whose offset field encodes `0xFFFFFFFFFFFFFFCE` (`-50` once cast).
4. A valid trailing SHA-256 checksum over the payload.

Calling `mvcc.ParseManifest(data)` on this buffer passes the `parseChunks` bounds check (`-100 <= dataEnd`, `-50 <= dataEnd`, `-50 >= -100`), producing a `manifestChunk{offset: -100, size: 50}`. `ParseManifest` then computes `record := data[start : start+pw]` with a negative `start`, triggering a Go runtime panic (`slice bounds out of range`) instead of a clean parse error. [12](#0-11)

func parseManifestHeader(data []byte) (manifestHeader, error) {
	hdr := manifestHeader{
		magic:     data[:4],
		version:   data[4],
		numChunks: int(data[5]),
		pathWidth: int(data[6]),
		hashAlgo:  data[7],
	}

	if binary.BigEndian.Uint32(hdr.magic) != manifestMagic {
		return manifestHeader{}, errors.New("invalid manifest; missing magic number in header")
	}

	if hdr.version != manifestVersion {
		return manifestHeader{}, fmt.Errorf("unsupported manifest version %d", hdr.version)
	}

	if hdr.pathWidth == 0 || hdr.pathWidth > 128 {
		return manifestHeader{}, fmt.Errorf("manifest PATH record width must be between 0 and 128")
	}
	if hdr.hashAlgo != hashAlgoSHA1 && hdr.hashAlgo != hashAlgoSHA256 {
		return manifestHeader{}, fmt.Errorf("unsupported hash algorithm %d", hdr.hashAlgo)
	}

	tocSize := (hdr.numChunks + 1) * 12
	if len(data) < headerSize+tocSize+trailerSize {
		return manifestHeader{}, fmt.Errorf("manifest too short for %d-chunk TOC (%d bytes)", hdr.numChunks, len(data))
	}

	return hdr, nil
}

func parseChunks(data []byte, numChunks int) (*manifestChunks, error) {
	if numChunks <= 0 {
		return nil, errors.New("there must be at least one chunk besides the null terminator")
	}

	tocTerminator := headerSize + numChunks*12
	if binary.BigEndian.Uint32(data[tocTerminator:tocTerminator+4]) != 0 {
		return nil, fmt.Errorf("expected zero sentinel in TOC")
	}

	dataEnd := len(data) - trailerSize

	result := &manifestChunks{
		chunks:  make([]manifestChunk, numChunks),
		pathIdx: -1,
		objsIdx: -1,
		refsIdx: -1,
	}

	for i := range numChunks {
		// The TOC starts after the header
		chunkOffset := headerSize + i*tocChunkSize
		chunkID := binary.BigEndian.Uint32(data[chunkOffset : chunkOffset+4])
		chunkOffsetInFile := int(binary.BigEndian.Uint64(data[chunkOffset+4 : chunkOffset+tocChunkSize]))

		// Calculate the size of the chunk
		nextChunkStart := headerSize + (i+1)*tocChunkSize
		nextChunkOffsetInFile := int(binary.BigEndian.Uint64(data[nextChunkStart+4 : nextChunkStart+tocChunkSize]))

		if chunkOffsetInFile > dataEnd || nextChunkOffsetInFile > dataEnd || nextChunkOffsetInFile < chunkOffsetInFile {
			return nil, fmt.Errorf("chunk %d has out-of-bounds offsets [%d, %d)", i, chunkOffsetInFile, nextChunkOffsetInFile)
		}

		chunkSize := nextChunkOffsetInFile - chunkOffsetInFile

		result.chunks[i] = manifestChunk{
			id:     chunkID,
			offset: chunkOffsetInFile,
			size:   chunkSize,
		}

func (m *LocalCache) prepareManifestFile(ctx context.Context, hash string) (manifest *Manifest, err error) {
	// Construct the manifest path
	manifestFilePath := filepath.Join(m.storagePath, m.repositoryID, mvccCacheDir, "manifests", hash)

	// Verify if it already exists on the local filesystem or not
	existLocally, err := fileExist(manifestFilePath)
	if err != nil {
		return nil, fmt.Errorf("check if file exists: %w", err)
	}

	if !existLocally {
		// If it does not exist, read content from ObjectStorage
		manifestReader, err := m.rs.ReadManifest(ctx, m.repositoryID, hash)
		if err != nil {
			return nil, fmt.Errorf("read manifest file: %w", err)
		}

		defer func() {
			closeErr := manifestReader.Close()
			err = errors.Join(err, closeErr)
		}()

		// Create the manifest file on the local file system atomically. This is a protection against
		// potential concurrent requests trying to create the same manifest file.
		if err = createFileAtomic(ctx, manifestFilePath, manifestReader); err != nil {
			return nil, fmt.Errorf("write manifest: %w", err)
		}
	}

	// Now that it exist on disk, let's open the file.
	manifestFile, err := os.Open(manifestFilePath)
	if err != nil {
		return nil, fmt.Errorf("opening manifest %s: %w", manifestFilePath, err)
	}

	// Read the content in memory. These files should not be that large.
	// The Manifest parsing logic needs the whole file at once to parse it.
	manifestContent := bytes.Buffer{}
	_, err = manifestContent.ReadFrom(manifestFile)
	if err != nil {
		return nil, fmt.Errorf("reading manifest: %w", err)
	}

	// Return the parsed manifest
	return ParseManifest(manifestContent.Bytes())
}
```
