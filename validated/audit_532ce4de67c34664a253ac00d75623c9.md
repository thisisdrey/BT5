### Title
Incorrect length check in `MultiEd25519Signature::verify` blocks all valid k-of-n REST API submissions where k < n — (`api/types/src/transaction.rs`)

### Summary

The `VerifyInput::verify()` implementation for `MultiEd25519Signature` in the REST API types layer contains an incorrect length check that compares the total number of public keys (n) against the number of actual signing signatures (k). In any valid k-of-n MultiEd25519 scheme where k < n, this check always fails, permanently blocking REST API submission of such transactions.

### Finding Description

`MultiEd25519Signature` in the API layer is a struct with four fields: [1](#0-0) 

- `public_keys`: all **n** public keys in the multisig set
- `signatures`: only the **k** actual signing signatures (k ≤ n)
- `threshold`: the minimum k required
- `bitmap`: a 4-byte bitmask indicating which of the n keys signed

The `From` conversion that populates this struct from an on-chain authenticator correctly sets `signatures` to only the k signing signatures (via `sig.signatures()`), not all n: [2](#0-1) 

However, the `VerifyInput::verify()` implementation contains this check: [3](#0-2) 

This check requires `public_keys.len() == signatures.len()`, i.e., n == k. For any valid k-of-n scheme where k < n (the normal case — e.g., a 2-of-3 multisig), this condition is always false, and the function bails with an error before the transaction reaches the mempool.

The correct invariant is that the number of set bits in the bitmap equals the number of signatures: `bitmap.count_ones() == signatures.len()`. This is exactly what the downstream crypto verification enforces: [4](#0-3) 

The `bitmap` field exists precisely because k < n is the expected case. If all n signers were always required, the bitmap would be unnecessary.

### Impact Explanation

Any user with a k-of-n MultiEd25519 account where k < n (e.g., a 2-of-3 multisig) cannot submit transactions via the REST API. The `verify()` call is invoked in the transaction submission path (`api/src/transactions.rs`). The transaction is rejected at the API layer before reaching the mempool or VM, making the account's funds inaccessible through the standard REST API submission path.

### Likelihood Explanation

MultiEd25519 k-of-n accounts where k < n are the standard use case for multisig (e.g., 2-of-3, 3-of-5). Any such account attempting to submit a transaction via the REST API will be blocked. The bug is deterministic and affects all such accounts unconditionally.

### Recommendation

Replace the incorrect check:

```rust
// WRONG: compares total public keys (n) against signing signatures (k)
} else if self.public_keys.len() != self.signatures.len() {
    bail!("MultiEd25519 signature does not have the same number of signatures as public keys")
```

with the correct invariant that the bitmap's set-bit count matches the signature count:

```rust
// CORRECT: bitmap ones must equal the number of provided signatures
if self.bitmap.inner().len() == BITMAP_NUM_OF_BYTES {
    let ones = self.bitmap.inner().iter().map(|b| b.count_ones()).sum::<u32>() as usize;
    if ones != self.signatures.len() {
        bail!("MultiEd25519 bitmap set-bit count does not match number of signatures")
    }
}
```

The existing check `self.signatures.len() < self.threshold as usize` already enforces the threshold requirement and should be retained.

### Proof of Concept

1. Create a 2-of-3 MultiEd25519 account on Aptos mainnet (keys A, B, C; threshold = 2).
2. Construct a valid transaction signed by A and B (k=2, n=3). The on-chain `MultiEd25519Signature` has 2 signatures and a bitmap with bits 0 and 1 set.
3. Convert to the REST API JSON representation: `public_keys` has 3 entries, `signatures` has 2 entries, `bitmap` = `"0xc0000000"`.
4. Submit via `POST /v1/transactions`.
5. The API calls `verify()`, hits `self.public_keys.len() (3) != self.signatures.len() (2)`, and returns HTTP 400: `"MultiEd25519 signature does not have the same number of signatures as public keys"`.
6. The transaction is permanently blocked at the API layer; the account's funds are inaccessible via REST API. [5](#0-4)

impl VerifyInput for MultiEd25519Signature {
    fn verify(&self) -> anyhow::Result<()> {
        if self.public_keys.is_empty() {
            bail!("MultiEd25519 signature has no public keys")
        } else if self.signatures.is_empty() {
            bail!("MultiEd25519 signature has no signatures")
        } else if self.public_keys.len() > MAX_NUM_OF_KEYS {
            bail!(
                "MultiEd25519 signature has over the maximum number of public keys {}",
                MAX_NUM_OF_KEYS
            )
        } else if self.signatures.len() > MAX_NUM_OF_SIGS {
            bail!(
                "MultiEd25519 signature has over the maximum number of signatures {}",
                MAX_NUM_OF_SIGS
            )
        } else if self.public_keys.len() != self.signatures.len() {
            bail!(
                "MultiEd25519 signature does not have the same number of signatures as public keys"
            )
        } else if self.signatures.len() < self.threshold as usize {
            bail!("MultiEd25519 signature does not have enough signatures to pass the threshold")
        } else if self.threshold == 0 {
            bail!("MultiEd25519 signature threshold must be greater than 0")
        }
        for signature in self.signatures.iter() {
            if signature.inner().len() != ED25519_SIGNATURE_LENGTH {
                bail!("MultiEd25519 signature has a signature with the wrong signature length")
            }
        }
        for public_key in self.public_keys.iter() {
            if public_key.inner().len() != ED25519_PUBLIC_KEY_LENGTH {
                bail!("MultiEd25519 signature has a public key with the wrong public key length")
            }
        }

        if self.bitmap.inner().len() != BITMAP_NUM_OF_BYTES {
            bail!(
                "MultiEd25519 signature has an invalid number of bitmap bytes {} expected {}",
                self.bitmap.inner().len(),
                BITMAP_NUM_OF_BYTES
            );
        }

        Ok(())
    }
}
