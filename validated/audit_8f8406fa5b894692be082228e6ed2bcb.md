### Title
Per-connection unstaked stream throttling allows aggregate unstaked ingestion far beyond the intended 20% budget - ([File: streamer/src/nonblocking/stream_throttle.rs])

### Summary
`throttle_stream`/`ConnectionStreamCounter::reset_throttling_params_if_needed` enforce `max_unstaked_load_in_throttling_window` (derived from `MAX_UNSTAKED_TPS`) independently per connection-table key, with no global counter of aggregate unstaked stream ingestion. An attacker opening many concurrent unstaked connections from distinct source IPs, each staying just under the per-connection cap, can drive total unstaked stream ingestion far past the `EXPECTED_UNSTAKED_STREAMS_RATIO` (20%) design target embedded in `StakedStreamLoadEMA::new`.

### Finding Description
`StakedStreamLoadEMA::new` computes `max_unstaked_load_in_throttling_window = MAX_UNSTAKED_TPS * STREAM_THROTTLING_INTERVAL_MS / 1000` — a fixed per-connection cap of 20 streams / 100ms (200 streams/sec) — while `max_staked_load_in_ms` is sized by subtracting `EXPECTED_UNSTAKED_STREAMS_RATIO` (20%) from `max_streams_per_ms` [1](#0-0) . This 20% figure is only used to size the staked pool; it is never used to bound the sum of all unstaked connections' consumption.

Throttling is enforced entirely per `ConnectionStreamCounter`, which `throttle_stream` reads/reset via `reset_throttling_params_if_needed` and compares against `max_streams_per_throttling_interval` [2](#0-1) . Each unstaked connection (keyed by IP/pubkey via `ConnectionTableKey` in `try_add_connection`) gets its own independent `ConnectionStreamCounter` unless multiple connections share the same key [3](#0-2) . `increment_load` in `StakedStreamLoadEMA` only accumulates `load_in_recent_interval` for `peer_type.is_staked()` traffic; unstaked stream counts are never added to any shared/global counter that could throttle in aggregate [4](#0-3) .

With `DEFAULT_MAX_UNSTAKED_CONNECTIONS = 2000` (each from a distinct source IP so each gets its own connection-table entry/key, since `max_connections_per_unstaked_peer` limits connections per key but not total distinct keys) [5](#0-4) , an attacker with 2000 distinct unstaked source addresses each opening streams at just under 20/100ms could aggregate to `2000 * 200 = 400,000` streams/sec, versus the intended `20% * 500,000 = 100,000` streams/sec unstaked budget (`DEFAULT_MAX_STREAMS_PER_MS = 500` streams/ms) [6](#0-5) . This is 4x the design target and can approach or exceed the raw endpoint capacity, starving staked-sender stream capacity since QUIC uni-stream acceptance/read work is shared infrastructure that unstaked connections would monopolize before staked traffic is distinguished.

The existing `staked_throttling_enabled` mechanism only kicks in when the EMA of *staked* load crosses `staked_throttling_on_load_threshold`; it does not track or react to unstaked load at all, so a flood of unstaked streams does not by itself trigger any compensating throttle for unstaked connections beyond their already-generous fixed per-connection cap.

### Impact Explanation
This falls under the resource-exhaustion / QoS-evasion bounty category for the TPU QUIC ingest path: an unstaked, unprivileged attacker can consume disproportionate ingestion bandwidth/CPU (accepting and reading streams, sigverify queueing) relative to the documented 20% unstaked budget, degrading throughput available to staked senders and thus, at scale, transaction/vote propagation to the leader's TPU. This is a design-level QoS/ratio violation rather than a crash or consensus-safety bug — it does not corrupt state, bypass sigverify, or produce invalid blocks; the worst realistic outcome is degraded staked ingest during sustained multi-IP unstaked flooding, bounded by total connection-table capacity (`max_unstaked_connections`) and the endpoint's total stream/packet processing capacity.

### Likelihood Explanation
The precondition is establishing many distinct unstaked QUIC connections (up to `DEFAULT_MAX_UNSTAKED_CONNECTIONS = 2000`) from many source IPs/ports, each opening streams below the per-connection unstaked cap. This requires no stake, no keys, and no special validator behavior — only network-level ability to originate many connections (e.g., via distributed sources or spoofed source ports subject to normal QUIC handshake/connection-migration limits and `max_connections_per_ipaddr_per_min`). Achieving exactly 2000 *distinct* source identities is somewhat constrained by IP-based per-minute connection-rate and per-peer connection limits, but the design gap itself (no global unstaked stream budget enforcement) is real and directly demonstrable at smaller scale already breaching the 20% target with far fewer than 2000 connections (e.g., 500+ connections already exceed the target ratio).

### Recommendation
Introduce a global/aggregate unstaked stream-ingestion counter (analogous to `load_in_recent_interval` for staked load) inside `StakedStreamLoadEMA`, and have `available_load_capacity_in_throttling_duration` for `ConnectionPeerType::Unstaked` divide/cap based on current aggregate unstaked usage against the true `EXPECTED_UNSTAKED_STREAMS_RATIO * max_streams_per_ms` budget, rather than a fixed per-connection `MAX_UNSTAKED_TPS`. This makes the enforced 20% ratio a real global invariant instead of an aspirational per-connection sizing assumption.

### Proof of Concept
```rust
// streamer/src/nonblocking/stream_throttle.rs (new test)
#[test]
fn test_aggregate_unstaked_exceeds_expected_ratio() {
    let max_streams_per_ms = DEFAULT_MAX_STREAMS_PER_MS; // 500
    let load_ema = StakedStreamLoadEMA::new(
        Arc::new(StreamerStats::default()),
        DEFAULT_MAX_UNSTAKED_CONNECTIONS, // 2000
        max_streams_per_ms,
    );

    let per_conn_cap = load_ema.available_load_capacity_in_throttling_duration(
        ConnectionPeerType::Unstaked,
        10_000, // total_stake unused for unstaked
    );
    // per_conn_cap == 20 streams / 100ms per connection

    let num_connections = DEFAULT_MAX_UNSTAKED_CONNECTIONS as u64; // 2000
    let aggregate_streams_per_window = per_conn_cap * num_connections;
    let aggregate_streams_per_sec =
        aggregate_streams_per_window * 1000 / STREAM_THROTTLING_INTERVAL_MS;

    let intended_unstaked_budget_per_sec =
        (EXPECTED_UNSTAKED_STREAMS_RATIO * (max_streams_per_ms as f64) * 1000.0) as u64;

    // Demonstrates aggregate unstaked ingestion (400,000/sec) vastly exceeds
    // the intended 20% budget (100,000/sec) because throttling is per-connection.
    assert!(
        aggregate_streams_per_sec > intended_unstaked_budget_per_sec * 3,
        "aggregate unstaked throughput {aggregate_streams_per_sec} did not exceed \
         3x the intended budget {intended_unstaked_budget_per_sec}"
    );
}
```
This unit test uses only existing public constants/functions (`available_load_capacity_in_throttling_duration`, `DEFAULT_MAX_UNSTAKED_CONNECTIONS`, `DEFAULT_MAX_STREAMS_PER_MS`) to show the per-connection cap, when multiplied by the maximum number of concurrently permitted unstaked connections, yields aggregate throughput several times the `EXPECTED_UNSTAKED_STREAMS_RATIO` design target — confirming the missing global enforcement.

    pub(crate) fn reset_throttling_params_if_needed(&self) -> tokio::time::Instant {
        let last_throttling_instant = *self.last_throttling_instant.read().unwrap();
        if tokio::time::Instant::now().duration_since(last_throttling_instant)
            > STREAM_THROTTLING_INTERVAL
        {
            let mut last_throttling_instant = self.last_throttling_instant.write().unwrap();
            // Recheck as some other thread might have done throttling since this thread tried to acquire the write lock.
            if tokio::time::Instant::now().duration_since(*last_throttling_instant)
                > STREAM_THROTTLING_INTERVAL
            {
                *last_throttling_instant = tokio::time::Instant::now();
                self.stream_count.store(0, Ordering::Relaxed);
            }
            *last_throttling_instant
        } else {
            last_throttling_instant
        }
    }
}

pub(crate) async fn throttle_stream(
    stats: &StreamerStats,
    peer_type: ConnectionPeerType,
    remote_addr: std::net::SocketAddr,
    stream_counter: &Arc<ConnectionStreamCounter>,
    max_streams_per_throttling_interval: u64,
) {
    let throttle_interval_start = stream_counter.reset_throttling_params_if_needed();
    let streams_read_in_throttle_interval = stream_counter.stream_count.load(Ordering::Relaxed);
    if streams_read_in_throttle_interval >= max_streams_per_throttling_interval {
        // The peer is sending faster than we're willing to read. Sleep for what's
        // left of this read interval so the peer backs off.
        let throttle_duration =
            STREAM_THROTTLING_INTERVAL.saturating_sub(throttle_interval_start.elapsed());

        if !throttle_duration.is_zero() {
            debug!(
                "Throttling stream from {remote_addr:?}, peer type: {peer_type:?}, \
                 max_streams_per_interval: {max_streams_per_throttling_interval}, \
                 read_interval_streams: {streams_read_in_throttle_interval} throttle_duration: \
                 {throttle_duration:?}"
            );
            stats.throttled_streams.fetch_add(1, Ordering::Relaxed);
            match peer_type {
                ConnectionPeerType::Unstaked => {
                    stats
                        .throttled_unstaked_streams
                        .fetch_add(1, Ordering::Relaxed);
                }
                ConnectionPeerType::Staked(_) => {
                    stats
                        .throttled_staked_streams
                        .fetch_add(1, Ordering::Relaxed);
                }
            }
            sleep(throttle_duration).await;
        }
    }
