## Analog Found

### Title
Repeated-slash path bypass of `disabledApiList` HTTP API kill-switch - (File: `framework/src/main/java/org/tron/core/services/filter/HttpApiAccessFilter.java`)

### Summary
`HttpApiAccessFilter` is the servlet filter responsible for enforcing the operator-configured `disabledApiList` (a security/ops control letting a node operator turn off specific HTTP wallet APIs). It derives the API name to check by naive positional string-splitting of the request path after only dot-segment (`.`/`..`) normalization, rather than fully canonicalizing the path (e.g. collapsing repeated `/` separators). This mirrors the `@hono/node-server` `serveStatic` bug class: a security-relevant path check and the actual request-routing layer disagree on how to interpret non-canonical paths (repeated slashes), allowing the check to be bypassed while the underlying handler still executes.

### Finding Description
The filter is applied with a `/*` mapping on every HTTP API service (`FullNodeHttpApiService`, `HttpApiOnSolidityService`, `HttpApiOnPBFTService`) [1](#0-0) , and its decision logic is:

```java
private boolean isDisabled(String endpoint) {
  boolean disabled = false;
  try {
    endpoint = URI.create(endpoint).normalize().toString();
    List<String> disabledApiList = CommonParameter.getInstance().getDisabledApiList();
    if (!disabledApiList.isEmpty()) {
      disabled = disabledApiList.contains(endpoint.split("/")[2].toLowerCase(Locale.ROOT));
    }
  } catch (Exception e) { ... }
  return disabled;
}
``` [2](#0-1) 

`URI.normalize()` only resolves `.` and `..` segments per RFC 3986; it does **not** collapse empty path segments produced by repeated slashes (`//`). The existing regression test only validates dot-segment collapsing:
```java
url = "/wallet/a/../b/../getnowblock";   // -> normalized to /wallet/getnowblock, disabled=true
url = "/wallet/a/b/../getnowblock";      // -> normalized to /wallet/b/getnowblock (wrong index), disabled=false
``` [3](#0-2) 

There is no equivalent test or handling for a path such as `/wallet//getnowblock` or `//wallet/getnowblock`. In that case `endpoint.split("/")` produces an extra empty element (e.g. `["", "wallet", "", "getnowblock"]`), so `split("/")[2]` yields `""` instead of `"getnowblock"`, and the lookup in `disabledApiList` silently fails to match — the filter behaves as if the endpoint were not disabled. The same positional-index pattern (`getServletPath()` string compared/looked up without full slash-normalization) is repeated in the sibling `LiteFnQueryHttpFilter`, which restricts a fixed `Set<String>` of history-query APIs on lite full nodes using an exact `Set.contains(requestPath)` check [4](#0-3)  — this suffers the identical class of bug: any non-canonical variant of a restricted path (extra slash) will not be an exact `Set` member and will fall through to `filterChain.doFilter(...)`, i.e. bypass the restriction.

Both filters compute the checked string from `contextPath + request.getServletPath()`, i.e. whatever the Jetty dispatcher resolves as the matched path for the filter's own `/*` mapping — the same class of "one component computes/serves the request, another independently re-derives the identity of the endpoint for an access decision" mismatch described in the Hono advisory.

### Impact Explanation
`disabledApiList` and the lite-fullnode history-query filter are the only server-side kill-switches an operator has to turn off specific wallet HTTP endpoints (e.g. to reduce exposure of `getaccount`, `getnowblock`, market/exchange query APIs, or to prevent unauthorized use of a lite node beyond its supported query set). An unauthenticated remote client sending a request with a duplicated slash reaches a servlet that the operator explicitly intended to disable, undermining the operator's access-control configuration. This is a confidentiality/availability-control bypass, consistent with the "Medium" severity of the original advisory (informational/read exposure, no direct fund theft), and it maps cleanly to the allowed target of "HTTP … query paths into Wallet."

### Likelihood Explanation
Exploitation only requires appending an extra `/` to an already publicly reachable HTTP endpoint path — no authentication, no special network position, and no malicious peer/SR role is required. The primary uncertainty is whether Jetty's servlet dispatcher, given the deployed Jetty version's default `UriCompliance` mode, will still route a request containing `//` to the exact-path-registered servlet (e.g. `"/wallet/getnowblock"`) rather than rejecting it with 400/404 before the servlet executes. I was not able to confirm the exact Jetty version's ambiguous-path handling within the available index (the `framework/build.gradle` Jetty dependency version and any explicit `UriCompliance`/`HttpConfiguration` customization were not resolvable from the indexed content), so the concrete end-to-end reachability of a *still-served* disabled endpoint via this specific slash trick could not be fully verified from static analysis alone.

### Recommendation
- In `HttpApiAccessFilter.isDisabled` and `LiteFnQueryHttpFilter.doFilter`, fully canonicalize the path before deriving the API name/comparing against the restricted set: collapse consecutive slashes (e.g. `path.replaceAll("/{2,}", "/")`) in addition to the existing dot-segment normalization, and perform the disabled-API/lite-query match on the fully normalized, lower-cased path rather than by brittle positional array indexing.
- Add regression tests analogous to the existing `../` test but using `//`, `/./`, and mixed variants for both filters.
- Alternatively/additionally, configure Jetty's `HttpConfiguration`/`UriCompliance` to reject ambiguous paths (duplicate slashes) with a 400 response before any filter/servlet dispatch, ensuring routing and security-filter path interpretation cannot diverge.

### Proof of Concept
Given `disabledApiList = ["getnowblock"]` configured on a full node:
1. Normal disabled path is rejected:
   `GET /wallet/getnowblock` → `{"Error":"this API is unavailable due to config"}` (per existing test) [5](#0-4) 
2. Repeated-slash variant:
   `GET /wallet//getnowblock`
   - `isDisabled` normalizes to `"/wallet//getnowblock"` (no dot segments to collapse), then `split("/")` → `["", "wallet", "", "getnowblock"]`, so `split[2] == ""`, which is not in `disabledApiList` → filter allows the request through.
   - If Jetty's dispatcher still resolves this request to the `GetNowBlockServlet` registered at `/wallet/getnowblock`, the "disabled" API executes normally, bypassing the operator's configuration.
