### Title
Unvalidated array offsets in `ValidateMultiSign` precompile cause `ArrayIndexOutOfBoundsException` from crafted calldata - (`File: actuator/src/main/java/org/tron/core/vm/PrecompiledContracts.java`)

### Summary
`PrecompiledContracts.ValidateMultiSign.execute()` and the helper methods it calls (`extractBytesArray`, `extractBytes32Array`, `extractSigArray`) trust attacker-controlled offset/length words taken directly from the precompile's calldata to index into the `DataWord[] words` array, without validating that the resulting indices stay within `words.length`. This mirrors the CVE-2017-12618 bug class: a structured input (there, an SDBM database file; here, ABI-encoded precompile calldata) is consumed without validating internal length/offset fields, leading to out-of-bounds array access.

### Finding Description
`ValidateMultiSign.execute()` parses the raw calldata into 32-byte words and reads offsets/lengths directly from those words: [1](#0-0) 

The bounds-checking path (`isValidAbiEncoding`) is only invoked when `VMConfig.allowTvmOsaka()` is enabled: [2](#0-1) 

When that hard-fork flag is not active (e.g., an older/alternate chain configuration, or before the corresponding hard fork activates on mainnet), `words[3].intValueSafe() / WORD_SIZE` is used unchecked as an offset into `words[]`, and is passed into `extractSigArray`/`extractBytesArray`: [3](#0-2) 

`extractBytesArray`/`extractSigArray` only guard `offset > words.length - 1`, but subsequent reads at `words[offset + i + 1]`, `words[offset + bytesOffset + 1]`, and calls to `extractBytes(data, ..., bytesLen)` (which does an unchecked `Arrays.copyOfRange`) are not bounds-checked against `words.length` or `data.length`. A crafted `len`, `bytesOffset`, or `bytesLen` value can push these indices past the end of the arrays, throwing an uncaught `ArrayIndexOutOfBoundsException` or `IndexOutOfBoundsException` from `Arrays.copyOfRange`.

Critically, in `ValidateMultiSign.execute()` this extraction logic (lines 1057-1074) sits **outside** the `try { ... } catch (Throwable t)` block that wraps the permission-checking logic (line 1082 onward), so an exception thrown while extracting the signature array propagates unhandled out of the precompile's `execute()` method.

### Impact Explanation
`ValidateMultiSign` is the `validatemultisign` precompiled contract, reachable by any account that deploys a contract calling this precompile with attacker-supplied `bytes` (e.g. via a Solidity contract using `address(0x...).staticcall(...)` with permission id, message hash, and signature-array data all controllable by the caller). Any unprivileged transaction broadcaster can therefore trigger this by sending a contract-call transaction. An unhandled runtime exception surfacing out of a precompiled contract during TVM execution is not the expected control flow for contract execution failures (normal reverts return `Pair.of(false, ...)`), so this can manifest as an uncaught exception that escapes normal VM error handling, potentially crashing the transaction-processing thread or causing a node to halt/deny service while processing that transaction — a Medium-severity, crash/DoS class impact analogous to the original CVE's "cause a denial of service" outcome.

### Likelihood Explanation
Reaching this path only requires deploying/calling a smart contract that invokes the `validatemultisign` precompile with the fourth word (`words[3]`) or the signature-count/offset words set to out-of-range values relative to the total number of 32-byte words in the supplied data. No special privileges are needed — any signed transaction from a normal account can trigger this. The mitigating factor is that on networks where `VMConfig.allowTvmOsaka()` is active (i.e., the corresponding hard fork has been enabled), `isValidAbiEncoding` gates malformed data before reaching the extraction helpers, closing this specific path; likelihood is therefore contingent on the hard-fork/feature-flag state.

### Recommendation
- Make the `isValidAbiEncoding` (or an equivalent strict bounds check on all offsets/lengths against `words.length` and `data.length`) unconditional in `ValidateMultiSign.execute()` and `BatchValidateSign.doExecute()`, rather than gating it behind `VMConfig.allowTvmOsaka()`.
- Add explicit bounds validation inside `extractBytesArray`, `extractBytes32Array`, and `extractSigArray` for every computed index (`offset + i + 1`, `offset + bytesOffset + 1`) against `words.length`, and validate `bytesOffset`/`bytesLen` against `data.length` before calling `extractBytes`.
- Wrap the calldata-parsing/extraction section of `ValidateMultiSign.execute()` in the same `try/catch (Throwable)` used for the permission-checking logic so any parsing exception degrades to `Pair.of(true, DATA_FALSE)` instead of propagating.

### Proof of Concept
1. Deploy a contract that calls the `validatemultisign` precompiled contract address with calldata shorter than 4 words, or with `words[3]` set to a value whose `intValueSafe() / WORD_SIZE` offset exceeds the actual number of words in the calldata (e.g., pass only 4 words total but set `words[3]` to point far beyond the array).
2. Ensure the network/config has `VMConfig.allowTvmOsaka()` disabled (default/older configuration state), so the `isValidAbiEncoding` guard at [2](#0-1)  is skipped.
3. Broadcast the transaction; execution reaches `extractBytesArray`/`extractSigArray` at [4](#0-3) , where `words[offset + i + 1]` or `extractBytes(data, ...)` indexes past the end of the array, throwing an uncaught `ArrayIndexOutOfBoundsException`/`IndexOutOfBoundsException` that escapes the un-guarded region of `execute()` before the surrounding `try/catch` at line 1082.

  private static byte[][] extractBytesArray(DataWord[] words, int offset, byte[] data) {
    if (offset > words.length - 1) {
      return new byte[0][];
    }
    int len = words[offset].intValueSafe();
    byte[][] bytesArray = new byte[len][];
    for (int i = 0; i < len; i++) {
      int bytesOffset = words[offset + i + 1].intValueSafe() / WORD_SIZE;
      int bytesLen = words[offset + bytesOffset + 1].intValueSafe();
      bytesArray[i] = extractBytes(data, (bytesOffset + offset + 2) * WORD_SIZE,
          bytesLen);
    }
    return bytesArray;
  }

  private static byte[][] extractSigArray(DataWord[] words, int offset, byte[] data) {
    if (offset > words.length - 1) {
      return new byte[0][];
    }
    int len = words[offset].intValueSafe();
    byte[][] bytesArray = new byte[len][];
    for (int i = 0; i < len; i++) {
      int bytesOffset = words[offset + i + 1].intValueSafe() / WORD_SIZE;
      bytesArray[i] = extractBytes(data, (bytesOffset + offset + 2) * WORD_SIZE,
          SIG_LENGTH);
    }
    return bytesArray;
  }
