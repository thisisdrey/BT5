### Title
Unstaked attacker can saturate the global `max_concurrent_connections` slot pool via churned incomplete QUIC handshakes, starving staked TPU connections - (File: streamer/src/nonblocking/quic.rs)

### Summary
The QUIC ingress admission gate `ClientConnectionTracker::new` enforces a single, stake-agnostic global cap (`qos.max_concurrent_connections()`) before the handshake completes and before stake is known, and the per-IP/global connection rate limiters that are supposed to bound attempt rate are never actually consumed for connections that don't finish their handshake. An unstaked attacker can therefore keep the slot pool saturated indefinitely with churned, never-completing handshakes and cause legitimate staked connections to be refused via `refused_connections_too_many_open_connections`.

### Finding Description
In `run_server` (streamer/src/nonblocking/quic.rs), for every accepted `Incoming`, admission proceeds through three gates before any stake information is known:

1. Global rate limiter check (read-only): `overall_connection_rate_limiter.current_tokens() == 0` [1](#0-0) 
2. Per-IP rate limiter check (read-only): `rate_limiter.is_allowed(&incoming.remote_address().ip())` [2](#0-1) 
3. `ClientConnectionTracker::new(stats.clone(), qos.max_concurrent_connections())`, which increments a single global `open_connections` counter and refuses the connection if it is `>= max_concurrent_connections` [3](#0-2) [4](#0-3) 

Crucially, both rate limiters are only *consumed* (tokens actually deducted) after the handshake **succeeds**, inside `setup_connection`: `rate_limiter.register_connection(&from.ip())` and `overall_connection_rate_limiter.consume_tokens(1)` are called only in the `Ok(new_connection)` branch, post-handshake [5](#0-4) . The pre-acceptance checks (`current_tokens() == 0` and `is_allowed`) are read-only queries against `KeyedRateLimiter`/`TokenBucket` state and do not themselves deduct tokens [6](#0-5) . Consequently, an attacker whose handshake never completes never triggers token consumption on either rate limiter, so these limiters never actually throttle repeated incomplete-handshake attempts from the same IP.

The only real bound on outstanding half-open connections is the global `open_connections` counter gated by `ClientConnectionTracker`, capped at `qos.max_concurrent_connections()`, computed as `(max_staked_connections + max_unstaked_connections) * 5 / 4` with no stake partitioning [7](#0-6) . Each accepted `Incoming` that passes `ClientConnectionTracker::new` starts a `setup_connection` task that awaits the connection under `timeout(QUIC_CONNECTION_HANDSHAKE_TIMEOUT, connecting)`, where `QUIC_CONNECTION_HANDSHAKE_TIMEOUT = Duration::from_secs(2)` [8](#0-7) [9](#0-8) . If the peer never finishes the handshake, the timeout fires after 2 seconds, `outstanding_incoming_connection_attempts` is decremented, and `ClientConnectionTracker` is dropped, freeing the `open_connections` slot [10](#0-9) .

Because stake is only determined later via `get_connection_stake`/`build_connection_context`, which runs strictly after the handshake succeeds [11](#0-10) , an unstaked attacker's incomplete-handshake connections occupy the exact same undifferentiated `open_connections` pool that staked connections must pass through. By opening `max_concurrent_connections - 1` connections and deliberately never completing the TLS/QUIC handshake (e.g., sending only the Initial packet and then going silent, or dropping ACKs), the attacker occupies nearly the entire pool for just under 2 seconds each round, then re-opens a fresh batch immediately after each timeout window elapses (since per-IP/global limiters are not actually decremented for these attempts). A legitimate staked client's `Incoming` arriving during this window will fail `ClientConnectionTracker::new` and be refused via `incoming.refuse()`, incrementing `refused_connections_too_many_open_connections` [4](#0-3) , before it ever reaches the stake-aware admission logic in `SwQos::try_add_connection` that would normally prioritize/prune for stake [12](#0-11) .

### Impact Explanation
This is a connection-slot starvation / denial-of-TPU-ingress condition: an unstaked, unprivileged remote attacker can cause `refused_connections_too_many_open_connections` to trigger for legitimate staked validators attempting to submit transactions to the leader's TPU QUIC port, without ever needing to complete a handshake or prove stake. This falls under the Agave bounty category of QoS/DoS on validator networking ingress — denial of service against legitimate staked traffic via resource exhaustion of a shared, non-stake-partitioned admission slot pool.

### Likelihood Explanation
The attack requires no special privileges: only the ability to open QUIC connections to the leader's public TPU port and withhold handshake completion, which is entirely within the "unprivileged attacker" threat model. It is a single-actor, repeatable attack (no coordination or multiple validators needed), bounded only by the attacker's own network throughput and the 2-second handshake-timeout cadence. The bypass of the rate limiters' actual throttling (since `consume_tokens`/`register_connection` never fire for non-completing handshakes) makes the attack sustainable indefinitely without a growing IP-based backoff.

### Recommendation
Partition the `open_connections`/handshake-in-flight admission slots so that a reserved fraction is always available independent of unstaked-connection churn (e.g., separate incoming-handshake quotas for staked vs. unstaked candidates, or reserve headroom above `max_unstaked_connections` specifically for staked handshakes). Additionally, make the per-IP and global connection rate limiters actually consume a token at accept time (before/independent of handshake completion) rather than only on successful handshake, so that repeated incomplete-handshake attempts are throttled the same way completed ones are.

### Proof of Concept
Integration test outline (tokio, using the existing QUIC test harness in `streamer/src/nonblocking/quic.rs`/`swqos.rs` tests):
1. Start a `SwQos`-backed QUIC server with a small `max_staked_connections`/`max_unstaked_connections` so `max_concurrent_connections` is a manageable number (e.g., 10).
2. From an unstaked client identity, open `max_concurrent_connections - 1` QUIC connections to the server but deliberately stall each handshake (e.g., connect a raw UDP socket that sends only an Initial-shaped packet, or use a client endpoint configured to never respond to the server's Handshake flight) so each remains in-flight for close to `QUIC_CONNECTION_HANDSHAKE_TIMEOUT` (2s).
3. Immediately after issuing that burst, attempt a normal staked-client connection (with the appropriate keypair matching a staked entry in `StakedNodes`) and observe/measure whether it is accepted within `QUIC_CONNECTION_HANDSHAKE_TIMEOUT`.
4. Repeat the stalled-connection burst in a loop synchronized just after the previous batch's 2-second timeout expires (i.e., re-issue before `outstanding_incoming_connection_attempts` frees up meaningfully) and assert that `stats.refused_connections_too_many_open_connections` increments for the staked client's connection attempts, confirming denial of legitimate staked TPU ingress.

    /// Check the max_concurrent_connections limit and if it is within the limit
    /// create ClientConnectionTracker and increment open connection count. Otherwise returns Err
    fn new(stats: Arc<StreamerStats>, max_concurrent_connections: usize) -> Result<Self, ()> {
        let open_connections = stats.open_connections.fetch_add(1, Ordering::Relaxed);
        if open_connections >= max_concurrent_connections {
            stats.open_connections.fetch_sub(1, Ordering::Relaxed);
            debug!(
                "There are too many concurrent connections opened already: open: \
                 {open_connections}, max: {max_concurrent_connections}"
            );
            return Err(());
        }

        Ok(Self { stats })
    }

    pub fn is_allowed(&self, ip: &IpAddr) -> bool {
        // Check if we have records in the rate limiter for the given IP address
        match self.limiter.current_tokens(ip) {
            Some(r) => r > 0, // we have a record, and rate is not exceeded
            None => true,     // if we have not seen IP, allow connection request
        }
    }

    pub fn register_connection(&self, ip: &IpAddr) -> bool {
        if self.limiter.consume_tokens(*ip, 1).is_ok() {
            debug!("Request from IP {ip:?} allowed");
            true // Request allowed
        } else {
            debug!("Request from IP {ip:?} blocked");
            false // Request blocked
        }
    }

impl QosController<SwQosConnectionContext> for SwQos {
    fn build_connection_context(&self, connection: &Connection) -> SwQosConnectionContext {
        let remote_address = connection.remote_address();
        get_connection_stake(connection, &self.staked_nodes).map_or(
            SwQosConnectionContext {
                peer_type: ConnectionPeerType::Unstaked,
                total_stake: 0,
                remote_pubkey: None,
                in_staked_table: false,
                remote_address,
                stream_counter: None,
                last_update: Arc::new(AtomicU64::new(timing::timestamp())),
            },
            |(pubkey, stake, total_stake)| {
                // The heuristic is that the stake should be large enough to have 1 stream pass through within one throttle
                // interval during which we allow max (MAX_STREAMS_PER_MS * STREAM_THROTTLING_INTERVAL_MS) streams.

                let peer_type = {
                    let max_streams_per_ms = self.staked_stream_load_ema.max_streams_per_ms();
                    let min_stake_ratio =
                        1_f64 / (max_streams_per_ms * STREAM_THROTTLING_INTERVAL_MS) as f64;
                    let stake_ratio = stake as f64 / total_stake as f64;
                    if stake_ratio < min_stake_ratio {
                        // If it is a staked connection with ultra low stake ratio, treat it as unstaked.
                        ConnectionPeerType::Unstaked
                    } else {
                        ConnectionPeerType::Staked(stake)
                    }
                };

                SwQosConnectionContext {
                    peer_type,
                    total_stake,
                    remote_pubkey: Some(pubkey),
                    in_staked_table: false,
                    remote_address,
                    last_update: Arc::new(AtomicU64::new(timing::timestamp())),
                    stream_counter: None,
                }
            },
        )
    }
