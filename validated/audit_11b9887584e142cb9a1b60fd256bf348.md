## Title
Off-by-one boundary in the anti-replay window permanently blackholes message counter 0 as a false replay - (File: `bits.go`)

### Summary
`NewBits` seeds `bits[0] = 1` with the comment "There is no counter value 0, mark it to avoid counting a lost packet later," and `Check`/`Update` treat counter `0` as an already-received/duplicate value for the lifetime of the window (until it is naturally evicted). [1](#0-0)  This mirrors the reported bug class (an index/counter boundary starting at the wrong value, silently rejecting the legitimate "index 0" case) rather than proving a stronger authentication/decryption/replay bypass.

### Finding Description
`ConnectionState.Decrypt` and `ConnectionState.VerifyRelay` gate every inbound data-plane and relay-verification packet on `cs.window.Check(l, messageCounter)` before decrypting/authenticating, then call `cs.window.Update(...)` to record it. [2](#0-1)  `Bits.Check` explicitly reads the seeded marker bit for counter `0`: because `bits[0]` is pre-set to `1`, `Check(l, 0)` returns `false` (rejected as already-seen) during warmup, and `Update(l, 0)` hits the duplicate branch, confirmed by the test comments and assertions. [3](#0-2) [4](#0-3) 

The wire header carries `MessageCounter` as a full `uint64` with no reserved/forbidden value called out in the header format or `Encode`/`Parse` functions themselves. [5](#0-4)  The exclusion of counter `0` is therefore a `Bits`-internal implementation choice, not a documented protocol invariant enforced elsewhere, which is exactly the class of bug in the reference report: a boundary condition that silently excludes the valid "index/counter 0" case.

### Impact Explanation
If a legitimate `MessageCounter` of `0` were ever presented to `Decrypt`/`VerifyRelay` (e.g., during warmup, before `current` has advanced), it would be rejected with `ErrAlreadySeen` even though it was never actually received before, causing that packet to be dropped as a false-positive replay. This is a data-plane availability/robustness defect reachable purely from crafted or naturally-occurring packet counters, without requiring a CA-signed certificate to already hold a session (it only manifests once a session exists, so it is a robustness issue within an already-established connection rather than a new authentication bypass, decryption bypass, or firewall bypass).

### Likelihood Explanation
The current callers of `Bits` (`ConnectionState`, initialized from `handshake.Result.MessageIndex` via `newConnectionStateFromResult`) seed the counter starting no lower than `1` in practice, since the loop in that constructor runs `for i := uint64(1); i <= r.MessageIndex; i++`. [6](#0-5)  I could not fully verify, given the remaining exploration budget, whether any code path ever legitimately emits or requires `MessageCounter == 0` on the wire (e.g., via `noiseutil` cipher-state nonce sequencing or a future/alternate caller of `Bits`). Because of this, likelihood of practical exploitation as-is is uncertain/low, and the finding should be treated as a latent correctness hazard in the anti-replay primitive rather than a confirmed, actively-triggerable authentication/decryption bypass in the current call graph.

### Recommendation
- Remove the implicit "no counter 0" assumption from `Bits`: either reserve counter `0` explicitly at the protocol/handshake layer (document and enforce that message counters start at `1` everywhere they are generated) so `Bits` never needs to special-case it, or change `NewBits`/`Check`/`Update` so a first-ever counter of `0` is treated as valid received traffic rather than a pre-marked duplicate.
- Add an explicit unit test asserting that a *genuine* first packet with `MessageCounter == 0` is accepted (not just that it behaves as a duplicate), to make the intended semantics (valid vs. reserved) unambiguous, similar to how `TestBitsMarkerInvariant` currently only documents/asserts the exclusion. [7](#0-6) 

### Proof of Concept
1. Establish a Nebula tunnel between two peers and get a `ConnectionState` with a fresh `Bits` window (`NewBits(ReplayWindow)`), i.e., `current == 0`. [8](#0-7) 
2. Have the peer send (or an attacker on the wire replay/craft, if achievable) a data-plane packet whose header `MessageCounter` field is `0`. [9](#0-8) 
3. Observe that `ConnectionState.Decrypt` calls `cs.window.Check(l, 0)`, which returns `false` because `bits[0]` was pre-seeded to `1` in `NewBits`, causing the packet to be rejected with `ErrAlreadySeen` even though it was never actually seen. [1](#0-0) [10](#0-9) 
4. This matches `TestBitsMarkerInvariant`'s own assertions that `Check(l, 0)` is `false` at a fresh window. [11](#0-10)

func (b *Bits) strictlyWithinWindow(i uint64) bool {
	// Handle the case where the window hasn't slid yet. This avoids u64 underflow.
	inWarmup := b.current < b.length
	if i < b.length && inWarmup {
		return true
	}

	// Next, if the packet is in-window, see if we've seen it before
	if i > b.current-b.length {
		return true
	}
	return false //not within window!
}

// Check returns true if i is within (or way out in front of) the window, and not a replay
func (b *Bits) Check(l *slog.Logger, i uint64) bool {
	// If i is the next number, return true.
	if i > b.current {
		return true
	}

	if b.strictlyWithinWindow(i) {
		return !b.get(i)
	}

	// Not within the window
	if l.Enabled(context.Background(), slog.LevelDebug) {
		l.Debug("rejected a packet (top)", "current", b.current, "incoming", i)
	}
	return false
}

// TestBitsMarkerInvariant verifies the seeded bits[0]=1 marker behaves
// correctly across warmup and beyond. Update should never clear the marker
// during warmup (clearRange skips position 0 when startPos=1), and once
// current >= length the marker is no longer consulted by Check/Update on
// the live path — but it must still report counter 0 as a duplicate while
// we are in warmup.
func TestBitsMarkerInvariant(t *testing.T) {
	l := test.NewLogger()
	b := NewBits(8)

	// Counter 0 is the seeded marker; Check sees it as already received.
	assert.False(t, b.Check(l, 0))
	// Update(0) at current=0 hits the duplicate branch.
	b.dupeCounter.Clear()
	assert.False(t, b.Update(l, 0))
	assert.Equal(t, int64(1), b.dupeCounter.Count())

	// Walk forward through warmup; the marker must remain set.
	for n := uint64(1); n <= 7; n++ {
		assert.True(t, b.Update(l, n))
	}
	// Position 0 (the marker) should still read as set because we never
	// cleared it; Update(0) still looks like a duplicate.
	assert.False(t, b.Check(l, 0))

	// Cross into steady state with a unit advance to 8: pos=0, evicts the
	// marker bit. The lost-counter guard (i > b.length) is false (8 == 8),
	// so this advance does NOT charge a lost packet — exactly what the
	// marker is there to prevent.
	b.lostCounter.Clear()
	assert.True(t, b.Update(l, 8))
	assert.Equal(t, int64(0), b.lostCounter.Count())
	// The slot at pos 0 is now occupied by counter 8.
	assert.False(t, b.Check(l, 8))
}

type H struct {
	Version        uint8
	Type           MessageType
	Subtype        MessageSubType
	Reserved       uint16
	RemoteIndex    uint32
	MessageCounter uint64
}

// Encode uses the provided byte array to encode the provided header values into.
// Byte array must be capped higher than HeaderLen or this will panic
func Encode(b []byte, v uint8, t MessageType, st MessageSubType, ri uint32, c uint64) []byte {
	b = b[:Len]
	b[0] = v<<4 | byte(t&0x0f)
	b[1] = byte(st)
	binary.BigEndian.PutUint16(b[2:4], 0)
	binary.BigEndian.PutUint32(b[4:8], ri)
	binary.BigEndian.PutUint64(b[8:16], c)
	return b
}

// String creates a readable string representation of a header
func (h *H) String() string {
	if h == nil {
		return "<nil>"
	}
	return fmt.Sprintf("ver=%d type=%s subtype=%s reserved=%#x remoteindex=%v messagecounter=%v",
		h.Version, h.TypeName(), h.SubTypeName(), h.Reserved, h.RemoteIndex, h.MessageCounter)
}

// MarshalJSON creates a json string representation of a header
func (h *H) MarshalJSON() ([]byte, error) {
	return json.Marshal(m{
		"version":        h.Version,
		"type":           h.TypeName(),
		"subType":        h.SubTypeName(),
		"reserved":       h.Reserved,
		"remoteIndex":    h.RemoteIndex,
		"messageCounter": h.MessageCounter,
	})
}

// Encode turns header into bytes
func (h *H) Encode(b []byte) ([]byte, error) {
	if h == nil {
		return nil, errors.New("nil header")
	}

	return Encode(b, h.Version, h.Type, h.Subtype, h.RemoteIndex, h.MessageCounter), nil
}

// Parse is a helper function to parses given bytes into new Header struct
func (h *H) Parse(b []byte) error {
	if len(b) < Len {
		return ErrHeaderTooShort
	}
	// get upper 4 bytes
	h.Version = uint8((b[0] >> 4) & 0x0f)
	// get lower 4 bytes
	h.Type = MessageType(b[0] & 0x0f)
	h.Subtype = MessageSubType(b[1])
	h.Reserved = binary.BigEndian.Uint16(b[2:4])
	h.RemoteIndex = binary.BigEndian.Uint32(b[4:8])
	h.MessageCounter = binary.BigEndian.Uint64(b[8:16])
	return nil
}
