### Title
DNS TXT-query authorization bypass via UDP source-address spoofing - ([File: dns_server.go])

### Summary
`dnsServer.isSelfNebulaOrLocalhost` gates TXT/`QueryCert` responses (which leak a peer's or the lighthouse's own certificate JSON) purely on the textual source address reported by `dns.ResponseWriter.RemoteAddr()`. This value comes from a plain OS-level UDP socket (`dns.Server{Net: "udp"}`) that is entirely separate from nebula's encrypted/authenticated tunnel, so it carries no cryptographic binding to any handshake or certificate.

### Finding Description
The DNS responder is started as an ordinary Go `dns.Server` bound with `Net: "udp"` [1](#0-0) , listening on the address from `lighthouse.dns.host`/`lighthouse.dns.port` [2](#0-1) . This is a normal OS UDP socket, not nebula's own crypto/UDP transport — packets that hit it are handled by `handleDnsRequest` → `parseQuery` without ever passing through nebula's Noise handshake verification, AEAD packet authentication, or firewall/hostmap checks that gate `inside.go`/`outside.go` traffic [3](#0-2) .

For `dns.TypeTXT` queries, `parseQuery` gates access solely by calling `isSelfNebulaOrLocalhost(w.RemoteAddr().String())` [4](#0-3) . That function parses the address string and checks only two conditions: loopback, or membership in `cs.myVpnAddrsTable` (the local host's own configured VPN addresses) [5](#0-4) . There is no verification that the request actually arrived over an authenticated nebula tunnel, nor any correlation with `HostMap`/`ConnectionState`. If the gate passes, `QueryCert` returns either the local cert JSON (when the queried name maps to an address in `myVpnAddrsTable`) or a hostmap peer's cert JSON [6](#0-5) .

Because this is a bare UDP listener, `RemoteAddr()` reflects the IP header source address of the packet as delivered by the OS network stack — UDP being connectionless, the kernel performs no source-authenticity check. An off-path or on-path attacker who can get a UDP packet delivered to this socket with a forged source address equal to an entry of `cs.myVpnAddrsTable` (e.g., the lighthouse's own configured VPN IP) satisfies the gate with no CA-signed certificate, no completed Noise handshake, and no possession of any key material.

### Impact Explanation
Passing the gate discloses `hostinfo.GetCert()`/the local certificate's JSON via TXT record to an unauthenticated party [7](#0-6) . This is an authentication-bypass / information-disclosure issue: the "only nebula peers or localhost" invariant is supposed to be enforced cryptographically elsewhere in nebula (handshake + CA-signed cert verification), but here it is enforced only by a spoofable network-layer address check, which is inconsistent with nebula's overall trust model.

### Likelihood Explanation
Preconditions are exactly `lighthouse.serve_dns` and `lighthouse.am_lighthouse` both enabled, which is a supported/documented lighthouse-DNS configuration. Exploitability further depends on whether the attacker can get a spoofed-source UDP packet delivered to the listening socket (e.g., listener bound to `0.0.0.0`, or bound to the nebula tun IP but reachable because the OS accepts packets addressed to a locally-configured tun IP regardless of the ingress interface, absent strict reverse-path/martian filtering). This routing/reachability precondition is environment-dependent and could not be fully confirmed from the code alone — the exact bind address's exposure to spoofable ingress paths depends on host/network configuration not visible in this file.

### Recommendation
Do not use the unauthenticated UDP source address as an identity/authorization signal. Either (a) restrict the TXT/`QueryCert` gate to loopback only and require any peer-cert lookups to go through nebula's authenticated tunnel/hostmap path instead of raw DNS, or (b) bind the DNS listener strictly to loopback and have nebula peers reach it only through mechanisms that are cryptographically tied to an established, verified session (e.g., forwarding proxied through the encrypted tunnel rather than a raw OS socket).

### Proof of Concept
Unit test plan:
1. Construct a `dnsServer` with a `pki`/`CertState` whose `myVpnAddrsTable` contains a known address `V`.
2. Build a stub `dns.ResponseWriter` (`stubDNSWriter`) whose `RemoteAddr()` returns `netip.AddrPort` for `V` (simulating a forged UDP source address, with no underlying handshake or `HostMap` entry for `V`).
3. Send a `dns.TypeTXT` query for the lighthouse's own name (or a peer's name) via `parseQuery`.
4. Assert that `isSelfNebulaOrLocalhost` returns `true` and that the TXT answer in `m.Answer` contains the certificate JSON from `QueryCert`, demonstrating disclosure despite no authenticated nebula session backing the "remote" address.

func (d *dnsServer) QueryCert(data string) string {
	if len(data) < 2 {
		return ""
	}
	ip, err := netip.ParseAddr(data[:len(data)-1])
	if err != nil {
		return ""
	}

	// The hostmap only ever contains peers we have handshaked with, so it never carries an entry for ourselves.
	// Answer self lookups straight from the local cert state.
	if cs := d.certState(); cs != nil && cs.myVpnAddrsTable != nil && cs.myVpnAddrsTable.Contains(ip) {
		c := cs.GetDefaultCertificate()
		if c == nil {
			return ""
		}
		b, err := c.MarshalJSON()
		if err != nil {
			return ""
		}
		return string(b)
	}

	hostinfo := d.hostMap.QueryVpnAddr(ip)
	if hostinfo == nil {
		return ""
	}

	q := hostinfo.GetCert()
	if q == nil {
		return ""
	}

	b, err := q.Certificate.MarshalJSON()
	if err != nil {
		return ""
	}
	return string(b)
}

func (d *dnsServer) isSelfNebulaOrLocalhost(addr string) bool {
	a, _, _ := net.SplitHostPort(addr)
	b, err := netip.ParseAddr(a)
	if err != nil {
		return false
	}

	if b.IsLoopback() {
		return true
	}

	cs := d.certState()
	if cs == nil || cs.myVpnAddrsTable == nil {
		return false
	}
	//if we found it in this table, it's good
	return cs.myVpnAddrsTable.Contains(b)
}

func (d *dnsServer) handleDnsRequest(w dns.ResponseWriter, r *dns.Msg) {
	m := new(dns.Msg)
	m.SetReply(r)
	m.Compress = false

	switch r.Opcode {
	case dns.OpcodeQuery:
		d.parseQuery(m, w)
	}

	w.WriteMsg(m)
}
