### Title
Non-atomic multi-slot dedup check in `Deduper::dedup` allows concurrent identical packets to both bypass duplicate detection - ([File: perf/src/deduper.rs])

### Summary
`Deduper::dedup` implements duplicate detection as `K` independent atomic `fetch_or` operations on a shared bitset, one per hash function, but the overall "is this a duplicate" decision is the logical AND of all `K` slots already being set, which is not evaluated atomically as a whole. When two threads call `dedup` concurrently with byte-identical input, each thread deterministically computes the same `K` hash slots, and it is possible for thread A to win the race on slot 1 (observing `old & mask == 0`) while thread B independently wins the race on slot 2, so both calls return `false` (i.e., "not a duplicate") for what is the exact same data.

### Finding Description

Each `fetch_or` is individually atomic on its target `u64` word, so there is no "torn" read/write as literally described in the question — but that is not where the bug lies. The bug is that `out` (the final duplicate/non-duplicate verdict) is computed by combining the results of `K` separate, independently-raced atomic operations. For `K >= 2`, two threads racing on identical input can each "win" a different one of the `K` slots (each observing `old & mask == 0` on a different index), causing both calls to return `out == false` ("not duplicate") even though the input is byte-identical and only one thread should have won overall.

`dedup_packets_and_count_discards` calls `deduper.dedup(data)` per packet and only marks `discard` when `dedup` returns `true`: [2](#0-1) 

The `reset` function's own doc comment explicitly acknowledges that concurrent access to the shared bitset/state is only loosely synchronized ("Reset is not synchronized with concurrent `dedup()` calls... a caller can see an inconsistent snapshot"), confirming that `Deduper` is designed for concurrent multi-threaded access without a per-call atomicity guarantee across the `K` slots: [3](#0-2)

### Impact Explanation
If a shared `Deduper` instance is indeed invoked concurrently by multiple threads (the documented design intent per the `reset` doc comment, and the standard Agave sigverify worker-pool architecture), an unprivileged attacker who sends two byte-identical transaction packets on separate concurrent QUIC streams at the same instant could get both copies past the dedup filter and into `ed25519_verify_serial`/banking, resulting in duplicate account-lock/scheduling work and potentially duplicate PoH-recorded entries for a single client intent. This falls under a QoS-evasion / duplicate-processing bypass category, since ingress dedup is meant to deterministically collapse exact duplicates before they consume downstream verification and scheduling resources.

### Likelihood Explanation
The precondition (`K >= 2`, and two calls to `dedup` on identical data racing at truly the same instant, each winning a different one of the `K` slots) is a narrow timing window. It requires precise concurrent scheduling of two threads processing the exact byte-identical packet, which an attacker cannot directly control from network timing alone (it depends on internal thread scheduling of the sigverify/banking pipeline). The race is real and demonstrable in a tight multi-threaded stress test, but reliably exploiting it via two remote QUIC streams against a real leader (with its own OS/thread scheduling jitter) is far less deterministic than the isolated unit-test scenario the question proposes.

### Recommendation
Make the duplicate check-and-set atomic as a unit, e.g., by guarding each `dedup` call (or at least the check across all `K` slots) with a per-bucket/global lock, or by using a single CAS loop that only commits all `K` bit sets if none of them were already set and only reports "not duplicate" based on a single atomic decision point, rather than combining `K` independently-raced atomic results.

### Proof of Concept
Add a multi-threaded stress test to `perf/src/deduper.rs`'s test module:
```rust
#[test]
fn test_dedup_concurrent_identical_packet_race() {
    use std::sync::{Arc, Barrier};
    use std::thread;

    let mut rng = rand::rng();
    let deduper = Arc::new(Deduper::<2, [u8]>::new(&mut rng, NUM_BITS));
    let data: Arc<[u8]> = Arc::from(b"identical-payload-for-race".as_slice());

    const N: usize = 64;
    let barrier = Arc::new(Barrier::new(N));
    let mut handles = Vec::new();
    for _ in 0..N {
        let deduper = Arc::clone(&deduper);
        let data = Arc::clone(&data);
        let barrier = Arc::clone(&barrier);
        handles.push(thread::spawn(move || {
            barrier.wait();
            !deduper.dedup(&data) // true if this call reported "not duplicate"
        }));
    }
    let not_duplicate_count: usize = handles
        .into_iter()
        .map(|h| h.join().unwrap())
        .filter(|&is_new| is_new)
        .count();

    // Expected invariant: exactly one thread should observe "not duplicate".
    assert_eq!(not_duplicate_count, 1, "dedup allowed {not_duplicate_count} concurrent identical inputs to be treated as non-duplicate");
}
```
Expected result if the bug is present: `not_duplicate_count` is occasionally `> 1` under contention (flaky but reproducible with enough iterations/threads), demonstrating the K-slot race allows more than one "first sighting" verdict for identical data.

    pub fn dedup(&self, data: &T) -> bool {
        let mut out = true;
        let state = self.state.load();
        for random_state in state.random_states.iter() {
            let hash: u64 = random_state.hash_one(data) % self.num_bits;
            let index = (hash >> 6) as usize;
            let mask: u64 = 1u64 << (hash & 63);
            let old = self.bits[index].fetch_or(mask, Ordering::Relaxed);
            if old & mask == 0u64 {
                self.popcount.fetch_add(1, Ordering::Relaxed);
                out = false;
            }
        }
        out
    }

pub fn dedup_packets_and_count_discards<const K: usize>(
    deduper: &Deduper<K, [u8]>,
    batches: &mut [PacketBatch],
) -> u64 {
    batches
        .iter_mut()
        .flat_map(|batch| batch.iter_mut())
        .map(|mut packet| {
            if !packet.meta().discard()
                && packet
                    .data(..)
                    .map(|data| deduper.dedup(data))
                    .unwrap_or(true)
            {
                packet.meta_mut().set_discard(true);
            }
            u64::from(packet.meta().discard())
        })
        .sum()
}
