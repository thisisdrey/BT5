### Title
Integer sign-conversion in MVCC manifest chunk-offset parsing allows bypass of bounds checks - ([File: internal/git/mvcc/manifest.go])

### Summary
The manifest format used by Gitaly's MVCC backend stores chunk offsets as unsigned 64-bit big-endian integers, but `parseChunks` converts them directly to Go's signed `int` type before performing the bounds checks. This is the same class of bug as the reported `addSignedDelta` issue: a value is stored/transmitted in one width/signedness and is unsafely reinterpreted as another, causing a validation check that assumes normal ranges to silently pass on attacker-crafted extreme values.

### Finding Description
In `parseChunks`, each TOC entry's offset is read as a `uint64` and immediately cast to `int`: [1](#0-0) 

```go
chunkOffsetInFile := int(binary.BigEndian.Uint64(data[chunkOffset+4 : chunkOffset+tocChunkSize]))
...
nextChunkOffsetInFile := int(binary.BigEndian.Uint64(data[nextChunkStart+4 : nextChunkStart+tocChunkSize]))

if chunkOffsetInFile > dataEnd || nextChunkOffsetInFile > dataEnd || nextChunkOffsetInFile < chunkOffsetInFile {
    return nil, fmt.Errorf("chunk %d has out-of-bounds offsets [%d, %d)", i, chunkOffsetInFile, nextChunkOffsetInFile)
}
``` [2](#0-1) 

On the 64-bit platforms Gitaly runs on, Go's `int` is a 64-bit signed type. A `uint64` value at or above `2^63` (e.g. `0x8000000000000000`) converts to a **negative** `int` via two's-complement reinterpretation — this is exactly analogous to the `addSignedDelta` bug where a 128-bit signed/unsigned quantity is manipulated using untyped 256-bit assembly words, defeating the overflow/bounds check. Here, a crafted manifest can set `chunkOffsetInFile`/`nextChunkOffsetInFile` to a large `uint64` that decodes to a negative `int`. The subsequent bounds check `chunkOffsetInFile > dataEnd` is false for a negative value, and `nextChunkOffsetInFile < chunkOffsetInFile` can likewise be arranged to pass, letting the malformed offsets slip through validation.

Downstream, these unchecked (and now negative or otherwise out-of-range) offsets are used directly as slice bounds when reading PATH/OBJS/REFS chunk data: [3](#0-2) [4](#0-3) 

Slicing a Go byte slice with a negative index panics at runtime (`slice bounds out of range`), and this parsing code has no `recover()`.

### Impact Explanation
`ParseManifest` is invoked by `LocalCache.prepareManifestFile` and `LocalCache.putNewArtifacts` in the MVCC read/write cache path, on manifest content fetched from the durable object-storage backend and cached locally per repository: [5](#0-4) [6](#0-5) 

This is on the hot path of every MVCC-backed RPC (`Prepare`/`PrepareWithManifest` is called at the start of every accessor/mutator RPC per `doc/mvcc_rpc_flow.md`). If an attacker can influence the manifest content that gets parsed here — e.g., by controlling artifacts published through a mutator RPC that writes to the MVCC store, or by racing/replacing manifest content in the shared object-storage bucket that a compromised or misbehaving path writes to — a single malformed 8-byte offset field can crash the Gitaly process handling that repository's requests (unrecovered panic → process/goroutine crash), representing a DoS of the RPC handler. This matches the "DoS of a handler" acceptance criterion in the assignment.

### Likelihood Explanation
Likelihood is moderate to low: reaching this code path requires the attacker to get a crafted manifest byte stream parsed by `ParseManifest`, which in the current architecture is populated from the object-storage bucket (`ReadManifest`) rather than directly from arbitrary unauthenticated RPC input. It is not clear from the available code that an ordinary Git push/fetch client field can directly control the raw bytes of a stored manifest (this MVCC backend is still POC/experimental per `doc/mvcc_rpc_flow.md`). This reduces confidence that the path is reachable purely from an ordinary user's push/fetch/RPC field without another primitive to write malformed manifest bytes into storage first.

### Recommendation
- Validate the parsed `uint64` offset values against `int`/expected range *before* converting, e.g., reject any offset `> uint64(len(data))` while still in `uint64` form, and only then convert to `int`.
- Alternatively, keep offsets as `uint64` (or `int64` with an explicit `>= 0` check) throughout `manifestChunk`/`parseChunks`, and compare against `uint64(dataEnd)` rather than mixing signed/unsigned semantics.
- Add fuzz/unit tests feeding boundary values (`0`, `math.MaxUint32`, `math.MaxInt64`, `math.MaxUint64`) into the TOC offset fields to ensure `ParseManifest` returns an error rather than panicking.
- Wrap manifest parsing in a `recover()` at the RPC boundary as defense-in-depth so a single malformed manifest cannot take down the whole request-handling goroutine/process.

### Proof of Concept
1. Construct a manifest byte buffer using the header/TOC layout from `parseManifestHeader`/`parseChunks` (magic `MVCC`, version `1`, valid `pathWidth`/`hashAlgo`).
2. In the TOC entry for the PATH chunk, set the 8-byte offset field to `0x8000000000000000` (or any value `>= 2^63`).
3. Append a valid SHA-256 trailer computed over the payload so the checksum check in `ParseManifest` passes.
4. Call `mvcc.ParseManifest(body)` — the cast `int(binary.BigEndian.Uint64(...))` turns the offset negative, the bounds check `chunkOffsetInFile > dataEnd` is skipped, and the later `data[start : start+pw]` slice expression with negative `start` panics with `slice bounds out of range`, crashing the calling goroutine.

func parseChunks(data []byte, numChunks int) (*manifestChunks, error) {
	if numChunks <= 0 {
		return nil, errors.New("there must be at least one chunk besides the null terminator")
	}

	tocTerminator := headerSize + numChunks*12
	if binary.BigEndian.Uint32(data[tocTerminator:tocTerminator+4]) != 0 {
		return nil, fmt.Errorf("expected zero sentinel in TOC")
	}

	dataEnd := len(data) - trailerSize

	result := &manifestChunks{
		chunks:  make([]manifestChunk, numChunks),
		pathIdx: -1,
		objsIdx: -1,
		refsIdx: -1,
	}

	for i := range numChunks {
		// The TOC starts after the header
		chunkOffset := headerSize + i*tocChunkSize
		chunkID := binary.BigEndian.Uint32(data[chunkOffset : chunkOffset+4])
		chunkOffsetInFile := int(binary.BigEndian.Uint64(data[chunkOffset+4 : chunkOffset+tocChunkSize]))

		// Calculate the size of the chunk
		nextChunkStart := headerSize + (i+1)*tocChunkSize
		nextChunkOffsetInFile := int(binary.BigEndian.Uint64(data[nextChunkStart+4 : nextChunkStart+tocChunkSize]))

		if chunkOffsetInFile > dataEnd || nextChunkOffsetInFile > dataEnd || nextChunkOffsetInFile < chunkOffsetInFile {
			return nil, fmt.Errorf("chunk %d has out-of-bounds offsets [%d, %d)", i, chunkOffsetInFile, nextChunkOffsetInFile)
		}

		chunkSize := nextChunkOffsetInFile - chunkOffsetInFile

		result.chunks[i] = manifestChunk{
			id:     chunkID,
			offset: chunkOffsetInFile,
			size:   chunkSize,
		}

func (m *LocalCache) prepareManifestFile(ctx context.Context, hash string) (manifest *Manifest, err error) {
	// Construct the manifest path
	manifestFilePath := filepath.Join(m.storagePath, m.repositoryID, mvccCacheDir, "manifests", hash)

	// Verify if it already exists on the local filesystem or not
	existLocally, err := fileExist(manifestFilePath)
	if err != nil {
		return nil, fmt.Errorf("check if file exists: %w", err)
	}

	if !existLocally {
		// If it does not exist, read content from ObjectStorage
		manifestReader, err := m.rs.ReadManifest(ctx, m.repositoryID, hash)
		if err != nil {
			return nil, fmt.Errorf("read manifest file: %w", err)
		}

		defer func() {
			closeErr := manifestReader.Close()
			err = errors.Join(err, closeErr)
		}()

		// Create the manifest file on the local file system atomically. This is a protection against
		// potential concurrent requests trying to create the same manifest file.
		if err = createFileAtomic(ctx, manifestFilePath, manifestReader); err != nil {
			return nil, fmt.Errorf("write manifest: %w", err)
		}
	}

	// Now that it exist on disk, let's open the file.
	manifestFile, err := os.Open(manifestFilePath)
	if err != nil {
		return nil, fmt.Errorf("opening manifest %s: %w", manifestFilePath, err)
	}

	// Read the content in memory. These files should not be that large.
	// The Manifest parsing logic needs the whole file at once to parse it.
	manifestContent := bytes.Buffer{}
	_, err = manifestContent.ReadFrom(manifestFile)
	if err != nil {
		return nil, fmt.Errorf("reading manifest: %w", err)
	}

	// Return the parsed manifest
	return ParseManifest(manifestContent.Bytes())
}
