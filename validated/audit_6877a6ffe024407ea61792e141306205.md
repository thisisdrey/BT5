### Title
Missing signature re-verification in `ConversationP2P::validate_handshake`'s `Some(_)` branch allows unauthenticated re-keying of an established connection - (File: stackslib/src/net/chat.rs)

### Summary
`validate_handshake` only checks that a `Handshake` message is self-signed by its claimed `node_public_key` when the connection has **no** stored public key yet (the `None` branch). Once a key is stored (`Some(_)` branch), the function performs *no* cryptographic check that the new message was actually signed by the current key (or by the newly-claimed key) — it only checks outbound address/port. Combined with `handle_handshake`'s permissive gate (`!authenticated && disable_inbound_handshakes`), an attacker can push a follow-up `Handshake` claiming an arbitrary `node_public_key`, and `update_from_handshake_data` will blindly rebind the connection's identity to it.

### Finding Description
`handle_handshake` (stackslib/src/net/chat.rs:1214-1251) only rejects an unauthenticated handshake when `disable_inbound_handshakes` is set: [1](#0-0) 
With the default `disable_inbound_handshakes = false`, an unauthenticated `Handshake` message still flows into `validate_handshake`.

`validate_handshake` (stackslib/src/net/chat.rs:1047-1127) branches on whether the connection currently has a stored public key: [2](#0-1) 
- In the `None` branch, it verifies `message.verify_secp256k1(&handshake_data.node_public_key)` — i.e., proof that the sender possesses the private key for the *claimed* key.
- In the `Some(_)` branch, that proof-of-possession check is **absent**. It only validates the self-reported address/port, and only for outbound connections. There is no check that the message was signed by the previously-known key, nor by the newly-claimed key.

The function's own doc comment on `handle_handshake` promises the missing guarantee: "A handshake will only be accepted if we do not yet know the public key of this remote peer, **or if it is signed by the current public key**" (stackslib/src/net/chat.rs:1210-1211) — but this second condition is never enforced in code once a key is already stored, because the caller's `disable_inbound_handshakes` gate only fires when that flag is true.

Once `validate_handshake` returns `Ok(())`, `handle_handshake` unconditionally calls `update_from_handshake_data`: [3](#0-2) 
which rebinds `self.connection`'s public key to whatever `node_public_key` the message claims, with `updated = true` whenever the new key differs from the old one — regardless of who actually signed the message.

Exploit flow: attacker connects, sends handshake #1 self-signed with key A → connection binds to `Some(A)`. Attacker then sends handshake #2 with an arbitrary key B (can be self-signed with B, or even signed with garbage — it doesn't matter, since no signature check occurs in the `Some(_)` branch). Because `disable_inbound_handshakes=false`, `handle_handshake` doesn't reject the unauthenticated message; `validate_handshake`'s `Some(_)` branch has nothing to check for an inbound connection (address check is `self.stats.outbound`-gated); `update_from_handshake_data` rebinds the connection to key B. This can be repeated per-message with any key, and can occur before any `HandshakeAccept` round-trip confirms mutual session state, so `StackerDBHandshakeAccept`/data received afterward is trusted under whatever key last arrived.

### Impact Explanation
Any remote peer that opens a P2P connection can force the node's view of "this connection's peer identity" to churn to attacker-chosen public keys after the first handshake, without proving possession of the corresponding private key for subsequent claims. Because StackerDB replication/ownership state (`db_smart_contracts`, `update_from_stacker_db_handshake_data`) is keyed off the `ConversationP2P`'s current public key, an attacker can present a victim's/arbitrary public key as their own and have subsequent `StackerDBHandshakeAccept` data trusted under that spoofed identity — an unauthenticated write/claim against identity-keyed state. This is repeatable per message on the same TCP connection with no additional privilege, matching the "unauthenticated/unauthorized write to state" Critical category.

### Likelihood Explanation
Preconditions are minimal and match a default configuration: `disable_inbound_handshakes = false` (default), any inbound (or outbound-but-anynet) connection where at least one prior handshake has occurred so `get_public_key()` is `Some`. The attacker needs no secret, no privileged role, and only needs to send two ordinary `Handshake` P2P messages over a connection they legitimately opened — this is trivially reachable and repeatable.

### Recommendation
In `validate_handshake`'s `Some(_)` branch, require that the incoming message is either signed by the currently-known public key (matching the doc comment's stated intent) or, if a legitimate re-key is intended, require the same self-signature proof used in the `None` branch (`message.verify_secp256k1(&handshake_data.node_public_key)`) plus additional anti-replay/session-freshness binding (e.g., only permit re-key after a completed handshake round-trip, tied to the current session nonce) so identity cannot be swapped mid-session by an unauthenticated message alone. Also tighten `handle_handshake`'s gate so unauthenticated re-key attempts on an already-keyed connection are rejected independent of `disable_inbound_handshakes`.

### Proof of Concept
Rust test in `stackslib::net::chat` (or a new test module) using two real `ConversationP2P` instances wired to an in-memory socket pair (as existing chat.rs tests do):
1. Complete handshake #1: peer sends `Handshake` self-signed with keypair A; call `conversation.chat(...)` / directly invoke `handle_handshake`; assert `conversation.connection.get_public_key() == Some(A)`.
2. Without performing any `HandshakeAccept` round-trip, craft handshake #2: a `StacksMessage` with `HandshakeData.node_public_key = B` (a fresh random keypair), signed with B's private key (self-signed, satisfying "self-signed" wording), same conversation/connection object.
3. Feed it through `handle_handshake` (or the full `chat` dispatch) with `authenticated = false`, `disable_inbound_handshakes = false`.
4. Assert: `handle_handshake` returns `Ok(_)` (no `HandshakeReject`) and `conversation.connection.get_public_key() == Some(B)` — proving the connection identity churned to an unauthenticated, unrelated key without any signature check tying the new key to the connection's prior authenticated state.

            None => {
                // if we don't yet have a public key for this node, verify the message.
                // if it's improperly signed, it's probably a poorly-timed re-key request (but either way the message should be rejected)
                message
                    .verify_secp256k1(&handshake_data.node_public_key)
                    .map_err(|_e| {
                        debug!(
                            "{:?}: invalid handshake: not signed with given public key",
                            &self
                        );
                        net_error::InvalidMessage
                    })?;
            }
            Some(_) => {
                // for outbound connections, the self-reported address must match socket address if we already have a public key.
                // (not the case for inbound connections, since the peer socket address we see may
                // not be the same as the address the remote peer thinks it has).
                // The only exception to this is if the remote peer does not yet know its own
                // public IP address, in which case, its handshake addrbytes will be the
                // any-network bind address (0.0.0.0 or ::)
                if self.stats.outbound
                    && (!handshake_data.addrbytes.is_anynet()
                        && (self.peer_addrbytes != handshake_data.addrbytes
                            || self.peer_port != handshake_data.port))
                {
                    // wrong peer address
                    debug!(
                        "{:?}: invalid handshake -- wrong addr/port ({:?}:{:?})",
                        &self, &handshake_data.addrbytes, handshake_data.port
                    );
                    return Err(net_error::InvalidHandshake);
                }
            }
        };

    pub fn update_from_handshake_data(
        &mut self,
        preamble: &Preamble,
        handshake_data: &HandshakeData,
    ) -> Result<bool, net_error> {
        let pubk = handshake_data
            .node_public_key
            .to_public_key()
            .map_err(|e| net_error::DeserializeError(e.into()))?;

        self.peer_version = preamble.peer_version;
        self.peer_network_id = preamble.network_id;
        self.peer_services = handshake_data.services;
        self.peer_expire_block_height = handshake_data.expire_block_height;
        self.handshake_addrbytes = handshake_data.addrbytes.clone();
        self.handshake_port = handshake_data.port;
        self.data_url = handshake_data.data_url.clone();

        let mut updated = false;
        let cur_pubk_opt = self.connection.get_public_key();
        if let Some(cur_pubk) = cur_pubk_opt {
            if pubk != cur_pubk {
                debug!(
                    "{:?}: Upgrade key {:?} to {:?} expires {:?}",
                    &self,
                    &to_hex(&cur_pubk.to_bytes_compressed()),
                    &to_hex(&pubk.to_bytes_compressed()),
                    self.peer_expire_block_height
                );
                updated = true;
            }
        }

        self.connection.set_public_key(Some(pubk.clone()));

        Ok(updated)
    }
