CVE-2022-1622 is a C-language out-of-bounds read in libtiff's LZW decoder (`tif_lzw.c`), which is unrelated to Go's standard library since Go does not vendor or wrap libtiff. The closest Go analog is `compress/lzw`, used internally by `image/gif`'s decoder [1](#0-0) , but its `Reader.decode` maintains an explicit invariant (`hi < overflow`, bounded by `maxWidth`) that keeps all indices into the fixed-size `suffix`/`prefix` arrays (`[1 << maxWidth]`) within bounds [2](#0-1) . The code walking the prefix chain in the `code <= r.hi` branch is bounded by these same invariants, so it does not reproduce the OOB-read primitive from the libtiff advisory [3](#0-2) .

There is no crafted-input reachable path in `compress/lzw` or `image/gif` matching the CVE's out-of-bounds read primitive; the report does not translate to a proven Go vulnerability in this repository.

	// overflow is the code at which hi overflows the code width. It always
	// equals 1 << width.
	//
	// last is the most recently seen code, or decoderInvalidCode.
	//
	// An invariant is that hi < overflow.
	clear, eof, hi, overflow, last uint16

	// Each code c in [lo, hi] expands to two or more bytes. For c != hi:
	//   suffix[c] is the last of these bytes.
	//   prefix[c] is the code for all but the last byte.
	//   This code can either be a literal code or another code in [lo, c).
	// The c == hi case is a special case.
	suffix [1 << maxWidth]uint8
	prefix [1 << maxWidth]uint16
