### Title
Missing domain separation (contract/chain binding) and expiration in `ValidateMultiSign` precompile hash construction enables cross-contract signature replay - (File: actuator/src/main/java/org/tron/core/vm/PrecompiledContracts.java)

### Summary
The `ValidateMultiSign` precompiled contract (address `0x...a`, reachable by any smart contract at TVM opcode level) lets a contract verify that an account's active-permission signers have approved arbitrary caller-supplied `data`. The hash that signers actually sign is derived only from `(accountAddress, permissionId, data)` — it never binds to the calling contract's address, the chain/network id, or an expiration timestamp, mirroring exactly the `NodeRegistry.registerNodeFor` flaw where signed data omitted `registryID` and expiration.

### Finding Description
`ValidateMultiSign.execute()` builds the message hash as: [1](#0-0) 

`combine = address || permissionId || data`, then `hash = sha256(combine)`. This hash is passed to `recoverAddrBySign` and the recovered address's weight is checked against the account's `Permission` threshold: [2](#0-1) 

Nothing in this construction includes: the address of the calling/verifying contract (`this` / `getContextAddress()`), a chain identifier, or an expiration/nonce field. The precompile is registered and directly callable by any deployed contract once `allowTvmSolidity059` is on: [3](#0-2) [4](#0-3) 

Because the "domain" of what is being approved is left entirely to the `data` blob supplied by the *calling* contract, any signature a user produces to authorize an action in one dApp (e.g., "withdraw X to Y") can be replayed verbatim against any other TRON contract — or the same contract redeployed at a different address, or the same logic on a different TRON-based network — that happens to check the identical `(address, permissionId, data)` triplet via this precompile, since the precompile itself performs zero binding to caller identity or freshness. This is architecturally identical to the reported `registerNodeFor` issue: the signed payload lacks a registry/verifier identifier and an expiration, so the *contract itself* offers no replay protection and pushes that responsibility entirely (and silently) onto every downstream dApp author who may not realize they must independently embed their own contract address, chain id, and expiration inside `data`.

### Impact Explanation
If two contracts (e.g., a legitimate escrow/vault and an attacker-deployed contract, or the same contract's next version) use overlapping `data` encodings for authorization (a realistic scenario for common patterns like "approve transfer of amount N with nonce M"), a signature intended for one contract can be replayed to authorize the identical action in an unrelated contract without the signer's consent, enabling unauthorized account operations / fund movement approved via this multisig-check primitive. Because the precompile is a base building block advertised for permission/multisig verification, this silently undermines the security guarantee developers expect from "verify this account's signers approved this action," directly enabling theft or unauthorized operations on assets gated behind `ValidateMultiSign`.

### Likelihood Explanation
Any account/contract deployer can trigger this: no special privilege is required to call the precompile from a deployed TRC-20/DeFi/vault-style contract, and the flaw only manifests when a dApp's `data` encoding does not itself embed a contract-specific/chain-specific/expiring nonce — a common oversight given the precompile's documentation and tests do not surface this requirement.

### Recommendation
Bind the ValidateMultiSign hash to the calling contract's context and add expiration/nonce support at the precompile level (analogous to including `registryID`+expiration in the report's recommendation): incorporate `contract.getCallerAddress()`/context address and/or chain id into `combine`, and optionally accept and enforce an expiration timestamp field, so a signature cannot be validated by any contract other than the one it was created for, and cannot be replayed indefinitely.

### Proof of Concept
1. Deploy Contract A that calls `ValidateMultiSign(address, permissionId, data)` where `data = abi.encode(amount, nonce)` to authorize a withdrawal for `address`.
2. Signer produces signature over `sha256(address || permissionId || data)` intending to approve a withdrawal specifically in Contract A.
3. Attacker deploys Contract B with identical `data` encoding convention and calls `ValidateMultiSign` with the same `(address, permissionId, data)` and the *same* previously-observed signature (visible on-chain from Contract A's transaction).
4. `ValidateMultiSign` in Contract B returns `true` (weight satisfied) because the hash matches — the same signed authorization is accepted by an entirely unrelated, unintended contract, letting the attacker trigger a duplicate/unauthorized privileged action against `address`'s funds. [5](#0-4)

  public static class ValidateMultiSign extends PrecompiledContract {

    private static final int ENGERYPERSIGN = 1500;
    private static final int MAX_SIZE = 5;
    private static final int ABI_HEADER_WORDS = 5;
    private static final int ABI_ITEM_WORDS = 5;


    @Override
    public long getEnergyForData(byte[] data) {
      long cnt = (data.length / WORD_SIZE - 5) / 5;
      // one sign 1500, half of ecrecover
      return cnt * ENGERYPERSIGN;
    }

    @Override
    public Pair<Boolean, byte[]> execute(byte[] rawData) {
      if (VMConfig.allowTvmOsaka()
          && !isValidAbiEncoding(rawData, ABI_HEADER_WORDS, ABI_ITEM_WORDS)) {
        return Pair.of(false, EMPTY_BYTE_ARRAY);
      }
      DataWord[] words = DataWord.parseArray(rawData);
      byte[] address = words[0].toTronAddress();
      int permissionId = words[1].intValueSafe();
      byte[] data = words[2].getData();

      byte[] combine = ByteUtil.merge(address, ByteArray.fromInt(permissionId), data);
      byte[] hash = Sha256Hash.hash(CommonParameter
          .getInstance().isECKeyCryptoEngine(), combine);

      if (VMConfig.allowTvmSelfdestructRestriction()) {
        int sigArraySize = words[words[3].intValueSafe() / WORD_SIZE].intValueSafe();
        if (sigArraySize > MAX_SIZE) {
          return Pair.of(true, DATA_FALSE);
        }
      }
      byte[][] signatures = VMConfig.allowTvmSelfdestructRestriction() ?
          extractSigArray(words, words[3].intValueSafe() / WORD_SIZE, rawData) :
          extractBytesArray(words, words[3].intValueSafe() / WORD_SIZE, rawData);

      if (signatures.length == 0 || signatures.length > MAX_SIZE) {
        return Pair.of(true, DATA_FALSE);
      }

      AccountCapsule account = this.getDeposit().getAccount(address);
      if (account != null) {
        try {
          Permission permission = account.getPermissionById(permissionId);
          if (permission != null) {
            //calculate weight
            long totalWeight = 0L;
            List<byte[]> executedSignList = new ArrayList<>();
            for (byte[] sign : signatures) {
              byte[] recoveredAddr = recoverAddrBySign(sign, hash);

              sign = merge(recoveredAddr, sign);
              if (ByteArray.matrixContains(executedSignList, recoveredAddr)) {
                if (ByteArray.matrixContains(executedSignList, sign)) {
                  continue;
                }
                MUtil.checkCPUTime();
              }
              long weight = TransactionCapsule.getWeight(permission, recoveredAddr);
              if (weight == 0) {
                //incorrect sign
                return Pair.of(true, DATA_FALSE);
              }
              totalWeight += weight;
              executedSignList.add(sign);
              executedSignList.add(recoveredAddr);
            }

            if (totalWeight >= permission.getThreshold()) {
              return Pair.of(true, dataOne());
            }
          }
        } catch (Throwable t) {
          if (t instanceof OutOfTimeException) {
            throw t;
          }
          logger.info("ValidateMultiSign error:{}", t.getMessage());
        }
      }
      return Pair.of(true, DATA_FALSE);
    }
