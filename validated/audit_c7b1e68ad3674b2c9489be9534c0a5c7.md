### Title
Unauthenticated forged `/new_burn_block` event injection desynchronizes signer's burnchain view - (File: libsigner/src/events.rs)

### Summary
The signer's `SignerEventReceiver` HTTP server accepts POST requests to `/new_burn_block` and deserializes them directly into a `BurnBlockEvent`, whose `TryFrom<BurnBlockEvent> for SignerEvent<T>` implementation unconditionally returns `Ok`, with no signature, secret, or origin check anywhere in the receive path. Any TCP client that can reach the signer's listening endpoint can therefore inject an attacker-chosen `burn_height`, `burn_header_hash`, `consensus_hash`, and `parent_burn_block_hash`, which the signer runloop then writes into `SignerDB` and feeds into its local state machine as if it came from the trusted node.

### Finding Description
The claimed equality — "the burn-chain state the signer observes equals the burn-chain state the node actually processed" — is broken because nothing in the request path authenticates the sender. `SignerEventReceiver::next_event` routes any POST to `/new_burn_block` straight to `process_event::<T, BurnBlockEvent>` [1](#0-0) . `process_event` reads the raw body, ACKs unconditionally, and JSON-deserializes it into `BurnBlockEvent` with no header/token/signature check of any kind [2](#0-1) . `TryFrom<BurnBlockEvent> for SignerEvent<T>` then copies every field verbatim into `SignerEvent::NewBurnBlock` and always returns `Ok` [3](#0-2) . There is no `auth_token`/`Authorization` check anywhere in `libsigner/src/events.rs` — the `auth_token`/`auth_password` matching referenced in the node/signer sample configs is enforced elsewhere (RPC calls from signer→node), not on this inbound event listener. Downstream, `signer.rs` unconditionally persists the attacker-supplied fields via `signer_db.insert_burn_block(...)` and feeds them into `local_state_machine.bitcoin_block_arrival(...)`, which updates the signer's notion of the current burnchain tip [4](#0-3) .

### Impact Explanation
An attacker who can reach the signer's event-receiver TCP port can write arbitrary, non-canonical burn-block records into `SignerDB` and force the signer's local state machine to believe a forged/attacker-chosen burn block/consensus hash is the latest tip, desynchronizing the signer from the node's true chain view. This is repeatable per message (each POST produces a fresh forged `NewBurnBlock` event) and constitutes unauthenticated write to signer state, matching the "unauthenticated/unauthorized write to state" Critical category.

### Likelihood Explanation
The only precondition is network reachability to the signer's event-listener socket (the address the signer binds to, taken from its `endpoint` config, e.g. `127.0.0.1:30000` in the sample configs but operator-configurable and not required to be loopback-only). No secret, signature, peer key, or privileged role is needed — a bare `POST /new_burn_block` with a JSON body matching `BurnBlockEvent`'s shape suffices. Attacker cost is a single raw TCP/HTTP request, and the attack is trivially repeatable.

### Recommendation
Add authentication to the signer's event receiver (e.g., verify a shared secret/HMAC or the documented `auth_token` on every inbound request in `SignerEventReceiver::next_event`/`process_event`) before deserializing and forwarding events, and reject requests lacking valid credentials.

### Proof of Concept
1. Start a `SignerEventReceiver<T>` bound to a test socket via `bind()`.
2. From a plain `TcpStream` (no signer/node credentials), send:
```
POST /new_burn_block HTTP/1.1
Host: 127.0.0.1:PORT
Content-Type: application/json
Content-Length: <n>

{"burn_block_hash":"0x<attacker-chosen>","burn_block_height":999999,"consensus_hash":"0x<attacker-chosen>","parent_burn_block_hash":"0x<attacker-chosen>","reward_recipients":[],"reward_slot_holders":[],"burn_amount":0}
```
3. Call `next_event()` and assert it returns `Ok(SignerEvent::NewBurnBlock { burn_height: 999999, consensus_hash: <attacker-chosen>, .. })` — matching the exact forged fields, proving unauthenticated acceptance at `libsigner/src/events.rs:441-442` / `637-648`.

fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
