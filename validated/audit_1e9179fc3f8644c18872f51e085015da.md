### Title
Custom Hooks Environment Built From Unvalidated `GitObjectDirectory`/`GitAlternateObjectDirectories` — Path Traversal Into Quarantine Env - ([File: internal/gitaly/hook/custom.go])

### Summary
`GitLabHookManager.customHooksEnv` in `internal/gitaly/hook/custom.go` builds the `GIT_OBJECT_DIRECTORY` and `GIT_ALTERNATE_OBJECT_DIRECTORIES` environment variables for custom repository hooks by directly `filepath.Join`-ing `repoPath` with `payload.Repo.GetGitObjectDirectory()` / `payload.Repo.GetGitAlternateObjectDirectories()`, without ever passing these values through the same bounds-check that `Repo.ObjectDirectoryPath()` (`internal/git/localrepo/paths.go`) performs before using them.

### Finding Description
This mirrors the reported bug class: a security-relevant value (here, the quarantine/object-directory paths used to build a hook's execution environment) is used in its raw, pre-validation form instead of after being passed through the validation/normalization step that the codebase otherwise applies consistently.

Contrast the two code paths that consume `Repo.GitObjectDirectory` / `Repo.GitAlternateObjectDirectories`:

- `Repo.ObjectDirectoryPath()` (`internal/git/localrepo/paths.go:21-83`) carefully validates the object directory field with `storage.ValidateRelativePath` and an explicit quarantine-directory-prefix check before ever returning a path, rejecting traversal (`../bazqux.git`), escapes to storage root, or mismatched quarantine prefixes — this is exhaustively covered by `internal/git/localrepo/paths_test.go`. [1](#0-0) 

- `customHooksEnv()` (`internal/gitaly/hook/custom.go:164-190`), which constructs the environment for **custom** pre-receive/update/post-receive hook scripts, does none of this. It only checks whether `GIT_OBJECT_DIRECTORY`/`GIT_ALTERNATE_OBJECT_DIRECTORIES` are already present in `envs` (i.e. set by the real `git-receive-pack` process), and if absent, falls back to `filepath.Join(repoPath, payload.Repo.GetGitObjectDirectory())` / the alternate-directories loop, with no call to `storage.ValidateRelativePath` or any traversal/quarantine-prefix check: [2](#0-1) 

The `payload.Repo` value originates from `gitcmd.NewHooksPayload`, which copies `GitObjectDirectory`/`GitAlternateObjectDirectories` straight from the `storage.Repository` (i.e. the RPC's `Repository` message) without validation at that layer either: [3](#0-2) 

These two fields on `gitalypb.Repository` are ordinary, caller-settable protobuf fields (as demonstrated throughout the test suite, e.g. `repo.GitObjectDirectory = "object/dir"`), and are threaded from the RPC-provided repository into the hooks payload, then into `customHooksEnv`. Because the join in `customHooksEnv` happens on the raw, unvalidated field instead of the validated relative path (the same "operate on the value before it goes through the mandatory conversion/validation step" pattern from the external report), a value such as `GitObjectDirectory: "../../../etc"` can cause `GIT_OBJECT_DIRECTORY`/`GIT_ALTERNATE_OBJECT_DIRECTORIES` to point outside the repository — and even outside the storage root — when custom hook scripts execute.

### Impact Explanation
Custom hooks (admin-authored scripts in `custom_hooks/`) frequently invoke `git` sub-commands that honor `GIT_OBJECT_DIRECTORY`/`GIT_ALTERNATE_OBJECT_DIRECTORIES` from the environment. If these variables can be steered to an arbitrary path outside the intended quarantine/object directory, this constitutes cross-repository/storage object access and quarantine-boundary bypass: the hook's git invocations may read or write objects in directories the operation was never authorized to touch, potentially exposing data from unrelated repositories or corrupting object stores outside the target repository's boundary. This falls squarely under the accepted category "hook or quarantine bypass" / "cross-repository object access."

### Likelihood Explanation
The reachable path requires the caller to (a) trigger a mutator RPC that runs the receive-pack hook chain, and (b) supply values for `Repository.GitObjectDirectory` / `Repository.GitAlternateObjectDirectories` on the RPC request. In production deployments (fronted by Praefect/Rails), these fields are normally only populated internally as part of the quarantine/access-check loop, and requests carrying them are otherwise gated (`beginTransactionForRepository` in `internal/gitaly/storage/storagemgr/middleware.go` treats a populated `GitObjectDirectory`/`GitAlternateObjectDirectories` as evidence of a legitimate access-check loop-back and rejects such fields on mutator RPCs it doesn't recognize as accessor loop-backs). This built-in gating reduces — but given the proto fields are not access-check-signed and the validation asymmetry documented above is still real, it does not fully eliminate — the chance that a value reaches `customHooksEnv` without going through `ObjectDirectoryPath`'s validation.

### Recommendation
In `customHooksEnv` (`internal/gitaly/hook/custom.go`), validate `payload.Repo.GetGitObjectDirectory()` and each entry of `payload.Repo.GetGitAlternateObjectDirectories()` with the same logic used by `Repo.ObjectDirectoryPath()` (i.e., `storage.ValidateRelativePath` plus the quarantine-directory-prefix check) before joining them into `GIT_OBJECT_DIRECTORY` / `GIT_ALTERNATE_OBJECT_DIRECTORIES`, rather than performing the `filepath.Join` on the raw, unvalidated field values.

### Proof of Concept
Not independently verified end-to-end against a running server (index-only analysis); the following describes the code-level reproduction path:
1. Craft a mutator RPC (e.g. `SSHReceivePack`/`PostReceivePack`) whose `Repository` message sets `GitObjectDirectory: "../../../outside-storage/objects"` (and/or a matching `GitAlternateObjectDirectories` entry), attempting to bypass or spoof the internal quarantine loop-back gating in `beginTransactionForRepository`.
2. If the request reaches `preReceiveHook`/`customHooksEnv` without the real git process having already set `GIT_OBJECT_DIRECTORY`/`GIT_ALTERNATE_OBJECT_DIRECTORIES` in `envs`, `customHooksEnv` (`internal/gitaly/hook/custom.go:172-190`) will `filepath.Join(repoPath, "../../../outside-storage/objects")` and set it as `GIT_OBJECT_DIRECTORY` for the custom hook execution, unlike `ObjectDirectoryPath()` which would reject the same value.
3. Any custom hook script invoking `git` will operate against the attacker-influenced object directory instead of the intended quarantine directory.

func (repo *Repo) ObjectDirectoryPath(ctx context.Context) (string, error) {
	repoPath, err := repo.Path(ctx)
	if err != nil {
		return "", err
	}

	objectDirectoryPath := repo.GetGitObjectDirectory()
	if objectDirectoryPath == "" {
		return "", structerr.NewInvalidArgument("object directory path is not set")
	}

	storagePath, err := repo.locator.GetStorageByName(ctx, repo.GetStorageName())
	if err != nil {
		return "", fmt.Errorf("get storage by name: %w", err)
	}

	// Ensure the path points somewhere in the storage.
	relativeObjectDirectoryPath, err := storage.ValidateRelativePath(storagePath, filepath.Join(repoPath, objectDirectoryPath))
	if err != nil {
		return "", structerr.NewInvalidArgument("validate relative path: %w", err)
	}

	parentDir := filepath.Base(filepath.Dir(relativeObjectDirectoryPath))
	baseDir := filepath.Base(relativeObjectDirectoryPath)
	isTransactionQuarantineDir := (baseDir == "quarantine") || ((parentDir == "quarantine") && strings.HasPrefix(baseDir, "tmp_objdir"))

	// Transactions quarantine a repository by pointing the object directory to a 'quarantine' named
	// directory in the transaction's temporary directory. If the base directory is `quarantine`,
	// Git push may apply an additional layer of quarantine such as `/quarantine/tmp_objdir-incoming-Gbc29N`
	// so we don't assert the `/quarantine` being the last element of the path. We thus also check for
	// whether the parent directory is in `quarantine` and whether the base directory has the expected
	// `tmp_objdir` suffix.
	if !isTransactionQuarantineDir {
		// We need to check whether the relative object directory as given by the repository is
		// a valid path. This may either be a path in the Git repository itself, where it may either
		// point to the main object directory storage or to an object quarantine directory as
		// created by git-receive-pack(1). Alternatively, if that is not the case, then it may be a
		// manual object quarantine directory located in the storage's temporary directory. These
		// have a repository-specific prefix which we must check in order to determine whether the
		// quarantine directory does in fact belong to the repo at hand.
		if _, origError := storage.ValidateRelativePath(repoPath, objectDirectoryPath); origError != nil {
			tempDir, err := repo.locator.TempDir(repo.GetStorageName())
			if err != nil {
				return "", structerr.NewInvalidArgument("getting storage's temporary directory: %w", err)
			}

			expectedQuarantinePrefix := filepath.Join(tempDir, storage.QuarantineDirectoryPrefix(repo))
			absoluteObjectDirectoryPath := filepath.Join(repoPath, objectDirectoryPath)

			// The relative path is outside of the repository
			if !strings.HasPrefix(absoluteObjectDirectoryPath, expectedQuarantinePrefix) {
				return "", structerr.NewInvalidArgument("not a valid relative path: %w", origError)
			}
		}
	}

func (m *GitLabHookManager) customHooksEnv(ctx context.Context, payload gitcmd.HooksPayload, pushOptions []string, envs []string) ([]string, error) {
	repoPath, err := m.locator.GetRepoPath(ctx, payload.Repo, storage.WithRepositoryVerificationSkipped())
	if err != nil {
		return nil, err
	}

	customEnvs := append(command.AllowedEnvironment(envs), pushOptionsEnv(pushOptions)...)

	objectDirectory := env.ExtractValue(envs, "GIT_OBJECT_DIRECTORY")
	if objectDirectory == "" && payload.Repo.GetGitObjectDirectory() != "" {
		objectDirectory = filepath.Join(repoPath, payload.Repo.GetGitObjectDirectory())
	}
	if objectDirectory != "" {
		customEnvs = append(customEnvs, "GIT_OBJECT_DIRECTORY="+objectDirectory)
	}

	alternateObjectDirectories := env.ExtractValue(envs, "GIT_ALTERNATE_OBJECT_DIRECTORIES")
	if alternateObjectDirectories == "" && len(payload.Repo.GetGitAlternateObjectDirectories()) != 0 {
		var absolutePaths []string
		for _, alternateObjectDirectory := range payload.Repo.GetGitAlternateObjectDirectories() {
			absolutePaths = append(absolutePaths, filepath.Join(repoPath, alternateObjectDirectory))
		}
		alternateObjectDirectories = strings.Join(absolutePaths, ":")
	}
	if alternateObjectDirectories != "" {
		customEnvs = append(customEnvs, "GIT_ALTERNATE_OBJECT_DIRECTORIES="+alternateObjectDirectories)
	}
