### Title
Overpaid TRX in `ParticipateAssetIssueContract` Is Not Refunded on Non-Divisible Exchange Amounts - (File: `actuator/src/main/java/org/tron/core/actuator/ParticipateAssetIssueActuator.java`)

### Summary
`ParticipateAssetIssueActuator` lets any account buy an asset by sending an exact `amount` of TRX (`cost`), which is converted into token units using a fixed `trxNum`/`num` ratio with floor-division. The full `cost` is always transferred to the token issuer, but the buyer only receives the floor-divided (rounded-down) token amount. Any TRX portion of `cost` that doesn't correspond to a whole unit of tokens under the ratio is never returned to the buyer — this mirrors the reported `PythAggregator.updatePrice()` pattern of accepting overpayment without a refund path.

### Finding Description
In `execute()`, the actuator subtracts the full `cost` from the buyer and credits the full `cost` to the issuer's `toAccount` balance: [1](#0-0) [2](#0-1) 

The token amount actually delivered to the buyer is computed via `floorDiv(cost * num, trxNum)`, which truncates any remainder: [3](#0-2) 

`validate()` performs the same floor-division and only rejects the transaction if the resulting `exchangeAmount` is `<= 0` — it does not require `cost` to be an exact multiple of `trxNum`, and it computes no refund for the truncated remainder: [4](#0-3) 

Consequently, whenever `cost` is not an exact multiple of `trxNum` (relative to `num`), the buyer pays for `cost` sun but the issuer only gives up `floorDiv(cost*num, trxNum)` tokens — the buyer permanently loses the value of the truncated remainder (up to `trxNum - 1` sun worth, scaled by the exchange ratio) with no on-chain mechanism to reclaim it, while the issuer's `toAccount` balance is credited with the buyer's full, un-refunded payment. This is structurally identical to the reported bug class: a payable operation collects more value than is actually needed to satisfy the requested unit conversion, and the surplus is never returned to the payer.

### Impact Explanation
Any account can trigger a `ParticipateAssetIssueContract` transaction with an `amount` deliberately chosen to be non-divisible by the asset's `trxNum`, causing TRX to be transferred to the asset issuer without a corresponding, proportionate token allocation. This is a concrete, permanent loss of funds for the buyer (or, viewed from the issuer's side, an unbacked/uncompensated TRX credit), reachable via a single signed transaction from an unprivileged account, satisfying the "unauthorized ... theft or permanent freezing of funds" bar.

### Likelihood Explanation
This requires no special privileges — any account holding TRX can submit a `ParticipateAssetIssueContract` with an `amount` that isn't an exact multiple of the target asset's `trxNum`/`num` ratio (which is entirely plausible for ordinary users, and trivially triggerable by an attacker targeting their own funds or, more importantly, by any user unaware of the exact divisibility requirement). The actuator's `validate()` only guards against `exchangeAmount <= 0`, not against non-exact divisibility, so this path is always reachable.

### Recommendation
Either (a) reject participation transactions where `cost` is not an exact multiple of `trxNum` (i.e., require `multiplyExact(cost, num) % trxNum == 0`), or (b) compute the exact TRX cost needed for the floor-divided `exchangeAmount` and refund the difference back to the buyer instead of transferring the full, unadjusted `cost` to the issuer.

### Proof of Concept
1. An asset is issued with `trxNum = 100`, `num = 1` (as used in the existing `sameTokenNameCloseExchangeDevisibleTest`), meaning 100 sun buys 1 token unit.
2. A buyer submits `ParticipateAssetIssueContract` with `amount = 999` sun instead of a multiple of 100.
3. `execute()` computes `exchangeAmount = floorDiv(999 * 1, 100) = 9` tokens, and transfers the full `999` sun to the issuer's account, while the buyer only receives `9` tokens (worth `900` sun at the stated ratio) — the extra `99` sun is paid to the issuer with no tokens or refund corresponding to it.
