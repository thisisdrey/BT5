### Title
Protocol fee bypass on NEP-245/IMT `TokenDiff` legs via delta-splitting into unit (`|delta| == 1`) legs across a single payload - (File: `contracts/defuse/core/src/intents/token_diff.rs`)

### Summary
`TokenDiff::token_fee` waives the protocol fee for `TokenIdType::Nep245`/`TokenIdType::Imt` whenever the *per-intent* `amount <= 1`, but fee computation in `TokenDiff::execute_intent` is scoped to a single `TokenDiff` intent's own delta rather than to the aggregate volume moved for a `TokenId` across a `DefuseIntents` batch or across multiple `MultiPayload`s. Because a single signed payload can contain an arbitrary `Vec<Intent>` (`DefuseIntents::intents`) executed sequentially, and each `TokenDiff` intent is independently fee-assessed, an attacker can split any large NEP-245/IMT transfer into N separate `TokenDiff` intents each with `delta == -1` on the same `TokenId`, making every leg individually qualify for the `Pips::ZERO` NFT/MT exemption while the true aggregate `|delta|` moved is N (arbitrarily large).

### Finding Description
The broken binding is:

`sum_over_legs(fee_ceil(token_fee(token_id, |delta_leg|, protocol_fee), |delta_leg|))` should equal `fee_ceil(protocol_fee, sum_over_legs(|delta_leg|))` for the same underlying `token_id`/asset moved by the same signer in one logical batch — but it does not when legs are split to `|delta_leg| == 1`.

Code path:
- `TokenDiff::execute_intent` iterates `self.diff` (a single intent's map of `TokenId -> i128`) and computes fee per-token strictly from that intent's own `delta`: `Self::token_fee(token_id, amount, protocol_fee).fee_ceil(amount)` [1](#0-0) .
- `TokenDiff::token_fee` explicitly zeroes the fee for `Nep245`/`Imt` (and `Nep171`) when `amount <= 1`: `TokenIdType::Nep245 | TokenIdType::Imt if amount > 1 => {} ... TokenIdType::Nep171 | TokenIdType::Nep245 | TokenIdType::Imt => return Pips::ZERO` [2](#0-1) .
- A single signed payload's `DefuseIntents.intents` is a `Vec<Intent>` executed one by one in the same `execute_signed_intent` call, sharing one signature/nonce commit: `for intent in self.intents { intent.execute_intent(signer_id, engine, intent_hash)?; }` [3](#0-2) , and `Engine::execute_signed_intent` verifies the signature/nonce once for the whole `DefuseIntents` message before dispatching to all contained intents [4](#0-3) .
- There is no per-`TokenId` or per-signer aggregation of `delta`/fee across the intents in a batch (or across multiple `MultiPayload`s in `execute_signed_intents`) anywhere in the engine; `fees_collected` is accumulated only within a single `TokenDiff::execute_intent` call and reset per intent [5](#0-4) .

Exploit flow: the attacker (optionally self-dealing between two accounts they control, or paired with any counterparty willing to take the other side) constructs N `TokenDiff` intents in one `DefuseIntents.intents` list (or N separate signed `MultiPayload`s), each with `{ token_id_MT: -1, token_out: closure_delta(token_out, -1, fee) }`. Every leg passes `amount == 1 <= 1`, so `token_fee` returns `Pips::ZERO` and `fee_ceil` yields `0` for every leg. The counterparty side supplies matching positive deltas verified only by the global `TransferMatcher`/invariant check, which enforces net-zero balance changes but performs no fee reconciliation. Aggregate volume moved for that `TokenId` can be arbitrarily large while total `fees_collected` for it is exactly `0`, versus the non-zero fee that a single `TokenDiff` with `delta == -N` on the same `TokenId` would have incurred. `MultiPayload::verify`, nonce/salt checks, and `finalize`'s balance invariant do not address this because they check signature validity and net balance conservation, not fee correctness per unit of value moved.

### Impact Explanation
Protocol fees on NEP-245/IMT multi-token assets can be bypassed entirely by any unprivileged signer for any transfer volume, simply by structuring the trade as many unit legs instead of one aggregate leg. This directly matches the listed Critical category "protocol fees bypassed... for Nep245/Imt assets via delta-splitting." The fee collector (protocol) permanently loses fee revenue on any Nep245/Imt-denominated flow the attacker chooses to structure this way; the loss is proportional to volume and fully repeatable across accounts, tokens, and batches, since the exploit is just a client-side change in how the intent payload is built (no privileged role required).

### Likelihood Explanation
The only precondition is holding a Verifier balance of the NEP-245/IMT token to move and a counterparty (which can be the attacker's second account) to close the netting requirement — both trivially satisfiable by an unprivileged actor who can deposit their own MT and sign their own intents. The attacker cost is only the additional gas/compute of processing N intents in one execution instead of one (bounded by block/tx gas limits, but well within reach for realistically sized trades), which the rules explicitly do not treat as an exclusion for the fee-bypass impact itself. This is deterministic, requires no timing race or third-party cooperation beyond a willing/self-controlled counterparty, and is repeatable indefinitely.

### Recommendation
Compute and enforce the NEP-245/IMT fee waiver based on genuinely non-fungible semantics (e.g., only when the `TokenId`'s underlying multi-token is confirmed to be a supply-1 NFT-like unit, or by tracking a per-signer, per-`TokenId` aggregate `|delta|` across the whole `DefuseIntents`/batch before applying the `amount <= 1` exemption) rather than per-intent leg amount, so that splitting the same `TokenId` across multiple `TokenDiff` intents cannot reduce the assessed fee below what a single aggregated `TokenDiff` would incur.

### Proof of Concept
`cargo test` plan (unit-level, in `contracts/defuse/core/src/intents/token_diff.rs` or an integration test using the `Engine`/mock `State`/`Inspector`):
1. Build a mock `State` with sufficient balances for signer `A` in `TokenId::Nep245("mt.near:pool")` and counterparty `B` in `TokenId::Nep141("ftX")`, with `protocol_fee = Pips::ONE_PERCENT`.
2. Case 1 (baseline aggregate): sign one `DefuseIntents` containing a single `TokenDiff { diff: {mt_token: -1000, ftX: closure_delta(ftX, -1000*rate, fee)} }` from `A`, paired with `B`'s offsetting `TokenDiff`. Execute via `Engine::execute_signed_intents`; assert `fees_collected` for `mt_token` (as observed via `TokenDiffEvent`) is `fee.fee_ceil(1000) > 0`.
3. Case 2 (split): sign one `DefuseIntents` containing 1000 separate `TokenDiff` intents from `A`, each `{ mt_token: -1, ftX: closure_delta(ftX, -1, fee) }`, paired with matching legs from `B`. Execute via `Engine::execute_signed_intents`.
4. Assert: `sum(fees_collected for mt_token across all 1000 TokenDiffEvents) == 0`, while the total `|delta|` moved for `mt_token` is `1000`, identical to Case 1's aggregate volume.
5. Assert the binding fails: `0 != fee.fee_ceil(1000)`, demonstrating the fee bypass, and that final Verifier balances for `A`/`B` net exactly as in Case 1 (proving no fee was ever assessed despite identical economic transfer).

    fn execute_signed_intent(&mut self, signed: MultiPayload) -> Result<()> {
        // verify signed payload and get public key
        let public_key = signed.verify().ok_or(DefuseError::InvalidSignature)?;

        // calculate intent hash
        let hash = signed.hash();

        // extract NEP-413 payload
        let DefusePayload::<DefuseIntents> {
            signer_id,
            verifying_contract,
            deadline,
            nonce,
            message: intents,
        } = signed.extract_defuse_payload()?;

        // check recipient
        if verifying_contract != *self.state.verifying_contract() {
            return Err(DefuseError::WrongVerifyingContract);
        }

        self.inspector.on_deadline(deadline);

        // make sure message is still valid
        if deadline < Timestamp::now() {
            return Err(DefuseError::DeadlineExpired);
        }

        // make sure the account has this public key
        if !self.state.has_public_key(&signer_id, &public_key) {
            return Err(DefuseError::PublicKeyNotExist(signer_id, public_key));
        }

        // commit nonce
        self.verify_intent_nonce(nonce, deadline)?;
        self.state.commit_nonce(signer_id.clone(), nonce)?;

        intents.execute_intent(&signer_id, self, hash)?;
        self.inspector.on_intent_executed(&signer_id, hash, nonce);

        Ok(())
    }
