### Title
Oracle failure blocks collateral withdrawals and core `Pool` operations - (File: `contracts/Pool.sol`)

### Summary
`Pool.debtPositionOf` unconditionally queries `masterOracle` for every collateral and debt asset associated with an account. The call has no `try/catch`, fallback oracle, cached price, or degraded mode. If the configured oracle or one of its underlying feeds starts reverting, account health evaluation reverts for the whole account, including collateral that still has a working feed.

This is analogous to the reported Chainlink-feed denial issue: a single unavailable external price source propagates into withdrawals, issuance, swaps, leveraged positions, and liquidations.

### Finding Description
`Pool.debtPositionOf` calls `debtOf` and `depositOf`, which iterate over the account's debt and deposit token lists and directly call `IMasterOracle.quoteTokenToUsd` for each asset. [1](#0-0) [2](#0-1) [3](#0-2) 

`DepositToken.unlockedBalanceOf` always calls `debtPositionOf` before checking whether the account has zero debt. As a result, even a user with no debt cannot query their withdrawable balance or withdraw collateral while any relevant oracle quote is reverting. [4](#0-3)  `DepositToken.withdraw` reaches this path through `_revertIfLocked`. [5](#0-4) 

The same unchecked oracle dependency affects:

- `DebtToken.issue`, which calls `debtPositionOf` and then `quoteUsdToToken`. [6](#0-5) 
- `Pool.liquidate`, which calls `debtPositionOf`, `quoteTokenToUsd`, and `quoteLiquidateOut`. [7](#0-6) 
- `Pool.swap`, which calls `quoteSwapOut` and therefore `masterOracle().quote`. [8](#0-7) [9](#0-8) 
- `SmartFarmingManager.leverage` and `flashRepay`, both of which end at `pool.debtPositionOf`. [10](#0-9) [11](#0-10) 

`PoolRegistry.updateMasterOracle` allows governance to replace the oracle, but there is no user-level fallback or isolation from a single failing asset quote. [12](#0-11) 

### Impact Explanation
An unavailable oracle temporarily freezes user collateral and disables core protocol functions:

- Users cannot withdraw deposit tokens while `debtPositionOf` reverts.
- Users cannot issue new debt.
- Liquidators cannot liquidate unhealthy positions.
- Synthetic-token swaps cannot execute.
- Leverage and flash-repay workflows cannot complete their final health checks.

This is temporary rather than permanent because governance can update `masterOracle`, and the external oracle may recover. However, during the outage, collateral withdrawals and liquidation liveness are unavailable.

### Likelihood Explanation
The issue requires an external oracle dependency to revert or become unavailable. An unprivileged attacker cannot directly cause this condition through Metronome's public entry points, and the deployed oracle implementation is outside the in-scope production contracts. The Metronome-side flaw is nevertheless present: all account health and pricing calls are unconditional and uncaught, so any configured oracle failure becomes a protocol-wide accounting failure rather than being isolated to the affected asset.

### Recommendation
Add defensive oracle handling around external price calls:

1. Use per-asset `try/catch` wrappers when querying `IMasterOracle`.
2. Avoid reverting `unlockedBalanceOf` for accounts with zero debt before requiring collateral valuation.
3. Return an explicit unavailable-price status or track per-asset oracle failures instead of allowing one asset to revert the entire account evaluation.
4. Support a governance-configured fallback oracle or last-good-price policy with strict freshness and liquidation-safety bounds.
5. At minimum, prevent a failing oracle from blocking repayment and other debt-reducing paths where price valuation is not strictly required.

### Proof of Concept
A Foundry fork test can demonstrate the liveness failure by replacing the configured oracle with a reverting `IMasterOracle` implementation. Replacing the oracle in the test simulates the deployed oracle or one of its feeds becoming unavailable; it is not the attacker path.

```solidity
// test/foundry/poc/OracleDoS.t.sol
// SPDX-License-Identifier: MIT
pragma solidity 0.8.24;

import {Test} from "forge-std/Test.sol";
import {Pool} from "../../../contracts/Pool.sol";
import {PoolRegistry} from "../../../contracts/PoolRegistry.sol";
import {DepositToken} from "../../../contracts/DepositToken.sol";
import {DebtToken} from "../../../contracts/DebtToken.sol";
import {IERC20} from "../../../contracts/dependencies/openzeppelin/token/ERC20/IERC20.sol";
import {IMasterOracle} from "../../../contracts/interfaces/external/IMasterOracle.sol";

contract RevertingOracle is IMasterOracle {
    function quoteTokenToUsd(address, uint256) external pure returns (uint256) {
        revert("oracle unavailable");
    }

    function quoteUsdToToken(address, uint256) external pure returns (uint256) {
        revert("oracle unavailable");
    }

    function quote(address, address, uint256) external pure returns (uint256) {
        revert("oracle unavailable");
    }
}

contract OracleDoSTest is Test {
    Pool internal constant POOL = Pool(payable(0x574a32f1047C631653D9283d36e73cF9BA67B940));

    function test_oracleOutageBlocksWithdrawAndIssue() external {
        address alice = makeAddr("alice");
        PoolRegistry registry = PoolRegistry(address(POOL.poolRegistry()));

        DepositToken depositToken = DepositToken(address(POOL.getDepositTokens()[0]));
        IERC20 collateral = depositToken.underlying();

        deal(address(collateral), alice, 100 ether);

        vm.startPrank(alice);
        collateral.approve(address(depositToken), 100 ether);
        depositToken.deposit(100 ether, alice);
        vm.stopPrank();

        IMasterOracle previousOracle = registry.masterOracle();
        RevertingOracle revertingOracle = new RevertingOracle();

        address governor = registry.governor();
        vm.prank(governor);
        registry.updateMasterOracle(IMasterOracle(address(revertingOracle)));

        vm.startPrank(alice);

        vm.expectRevert("oracle unavailable");
        depositToken.withdraw(1 ether, alice);

        DebtToken debtToken = DebtToken(address(POOL.getDebtTokens()[0]));
        vm.expectRevert("oracle unavailable");
        debtToken.issue(1 ether, alice);

        vm.expectRevert("oracle unavailable");
        POOL.debtPositionOf(alice);

        vm.stopPrank();

        vm.prank(governor);
        registry.updateMasterOracle(previousOracle);
    }
}
```

Expected result: deposits can be made while the oracle is healthy, but `withdraw`, `issue`, and `debtPositionOf` all revert once the configured oracle reverts.
