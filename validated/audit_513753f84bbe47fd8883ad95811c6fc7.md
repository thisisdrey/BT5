Based on my investigation, `LinkRepositoryToObjectPool` accepts any target repository and any object pool within the same storage/partition without validating that the pool actually originated from or is related to that repository (e.g., verifying fork lineage or that the repository was the pool's origin). This confirms a valid analog to the stablecoin bug class: distinct, non-fungible entities (unrelated repositories' object graphs) are treated as freely interchangeable/joinable without a relationship check, at [1](#0-0) .

### Title
Object pool membership accepts unrelated repositories without verifying fork/origin relationship, enabling cross-repository object disclosure - (File: internal/gitaly/service/objectpool/link.go)

### Summary
`LinkRepositoryToObjectPool` links any target repository to any caller-specified object pool as long as both exist, without validating that the repository is actually a fork/descendant of the pool's origin repository. This treats unrelated repository object graphs as fungible/poolable, mirroring the reported bug class where distinct assets are wrongly assumed to be interchangeable.

### Finding Description
The RPC handler only validates that the target repository exists and resolves the pool via `s.poolForRequest`, then unconditionally calls `pool.Link(ctx, repo)`: [1](#0-0) 

The lower-level `Link` function in `internal/git/objectpool/link.go` writes the pool's path into the repository's `objects/info/alternates` file whenever the repository is not already linked, with no check that the repository was ever cloned from, or is otherwise related to, the pool's origin: [2](#0-1) 

`CreateObjectPool` similarly only requires an `origin` repository and a valid pool path (`storage.IsPoolRepository`), with no binding recorded between the pool and the origin that `LinkRepositoryToObjectPool` later enforces: [3](#0-2) 

Because Git alternates grant full read access to all objects in the linked directory (this is the entire point of object pools, per `doc/object_pools.md`), any two repositories placed in the same object pool become effectively "fungible" from an object-visibility standpoint — exactly analogous to the `StableVault` treating different stablecoins as 1:1 fungible without verifying their actual equivalence: [4](#0-3) 

### Impact Explanation
If an attacker-controlled or unrelated repository can be linked to an existing object pool (whose relative path/name they can guess or learn, e.g. via `GetObjectPool`), the objects of any other pool member become readable through the newly linked repository via the shared alternates directory — a cross-repository object disclosure. This breaks the isolation boundary between repositories/forks that Gitaly's storage model is expected to preserve, similar to how the `StableVault` finding broke the accounting isolation between distinct stablecoins.

### Likelihood Explanation
This RPC is a `MUTATOR` reachable via a crafted RPC field (`LinkRepositoryToObjectPoolRequest{Repository, ObjectPool}`) as documented in `proto/objectpool.proto`. Nothing in the Gitaly-layer validation (`s.locator.ValidateRepository`, `pool.Link`) ties the `object_pool` argument to the specific `repository` argument's ancestry; the relationship is only implicitly expected by convention (fork flow) rather than enforced. Exploitability depends on whether upstream layers (e.g., GitLab Rails authorization) independently enforce the fork relationship before invoking this RPC — within the Gitaly repo itself, no such binding check exists.

### Recommendation
Record the origin repository at `CreateObjectPool` time (e.g., persist the origin's identity alongside the pool) and have `LinkRepositoryToObjectPool` verify that the requested `repository` is a legitimate descendant/fork of that recorded origin (or otherwise explicitly authorized) before writing the alternates link, rather than accepting any existing pool path for any existing repository.

### Proof of Concept
1. Repository A is forked to create pool P via `CreateObjectPool{origin: A, object_pool: P}` [5](#0-4) .
2. An unrelated repository B (same storage) is created independently.
3. Call `LinkRepositoryToObjectPool{repository: B, object_pool: P}`; the handler only checks that B exists and P is a valid pool, then links B to P [1](#0-0) .
4. B's `objects/info/alternates` now points at P's object directory, and any objects present in P (originally from A) become readable through B via standard object-read RPCs (e.g. `GetBlob`, `TreeEntry`), even though B has no legitimate relationship with A.

func (s *server) LinkRepositoryToObjectPool(ctx context.Context, req *gitalypb.LinkRepositoryToObjectPoolRequest) (*gitalypb.LinkRepositoryToObjectPoolResponse, error) {
	repository := req.GetRepository()
	if err := s.locator.ValidateRepository(ctx, repository); err != nil {
		return nil, structerr.NewInvalidArgument("%w", err)
	}

	pool, err := s.poolForRequest(ctx, req)
	if err != nil {
		return nil, err
	}

	repo := s.localRepoFactory.Build(repository)

	if err := pool.Link(ctx, repo); err != nil {
		return nil, structerr.NewInternal("%w", err)
	}

	return &gitalypb.LinkRepositoryToObjectPoolResponse{}, nil

func Link(ctx context.Context, pool, repo *localrepo.Repo, txManager transaction.Manager) (returnedErr error) {
	altPath, err := repo.InfoAlternatesPath(ctx)
	if err != nil {
		return err
	}

	expectedRelPath, err := getRelativeObjectPath(ctx, pool, repo)
	if err != nil {
		return err
	}

	linked, err := linkedToRepository(ctx, pool, repo)
	if err != nil {
		return err
	}

	if linked {
		// When the repository is already linked to the repository, cast a vote to ensure the
		// repository is consistent with the other replicas.
		if err := transaction.VoteOnContext(ctx, txManager, voting.VoteFromData([]byte("repository linked")), voting.Synchronized); err != nil {
			return fmt.Errorf("vote on linked repository: %w", err)
		}

		return nil
	}

	alternatesWriter, err := safe.NewLockingFileWriter(altPath)
	if err != nil {
		return fmt.Errorf("creating alternates writer: %w", err)
	}
	defer func() {
		if err := alternatesWriter.Close(); err != nil && returnedErr == nil {
			returnedErr = fmt.Errorf("closing alternates writer: %w", err)
		}
	}()

	if _, err := io.WriteString(alternatesWriter, expectedRelPath); err != nil {
		return fmt.Errorf("writing alternates: %w", err)
	}

func (s *server) CreateObjectPool(ctx context.Context, in *gitalypb.CreateObjectPoolRequest) (*gitalypb.CreateObjectPoolResponse, error) {
	if in.GetOrigin() == nil {
		return nil, errMissingOriginRepository
	}

	poolRepo := in.GetObjectPool().GetRepository()
	if poolRepo == nil {
		return nil, errMissingPool
	}

	if !storage.IsPoolRepository(poolRepo) {
		return nil, errInvalidPoolDir
	}

	// repoutil.Create creates the repositories in a temporary directory. This means the repository is not created in the location
	// expected by the transaction manager. This makes sense without transactions, but with transactions, there's no real point in
	// doing so given a failed transaction's state is anyway removed. Creating the repository in a temporary directory is problematic
	// as the reference transaction hook is invoked for the repository from unexpected location, causing the transaction to fail to
	// associate the reference updates with the repository.
	//
	// Run the repository creation without the transaction in the context. The transactions reads the created repository's state from
	// the disk when committing it, so it's not necessary to capture the updates from the reference-transaction hook. This avoids the
	// problem for now, and later with transactions enabled by default we can stop creating repositories in unexpected locations.
	ctxWithoutTransaction := storage.ContextWithTransactionID(ctx, 0)
	if err := repoutil.Create(ctxWithoutTransaction, s.logger, s.locator, s.gitCmdFactory, s.catfileCache, s.txManager, s.repositoryCounter, poolRepo, func(poolRepo *gitalypb.Repository) error {
		if _, err := objectpool.Create(
			ctxWithoutTransaction,
			s.logger,
			s.locator,
			s.gitCmdFactory,
			s.catfileCache,
			s.txManager,
			s.housekeepingManager,
			&gitalypb.ObjectPool{
				Repository: poolRepo,
			},
			s.localRepoFactory.Build(in.GetOrigin()),
		); err != nil {
			return err
		}

		return nil
	}, repoutil.WithSkipInit()); err != nil {
		return nil, structerr.New("creating object pool: %w", err)
	}
