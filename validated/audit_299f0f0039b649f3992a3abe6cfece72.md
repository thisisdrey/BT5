### Title
Block/transaction-fee rewards paid to a witness with zero votes are permanently unaccounted for and unclaimable - ([File: chainbase/src/main/java/org/tron/core/store/DelegationStore.java])

### Summary
When a super representative (SR) produces a block, `MortgageService.payBlockReward`/`payTransactionFeeReward` unconditionally deposit reward funds into that witness's per-cycle reward bucket via `DelegationStore.addReward`, regardless of whether the witness currently has any voters. During Vi (reward-per-vote index) accumulation, if the witness's vote count for that cycle is `0`, the deposited reward is silently discarded instead of being redirected or refunded — analogous to the reported "emissions sent to empty vault forever locked" bug class, where funds credited to an entity with zero shares/votes become permanently unclaimable.

### Finding Description
`MortgageService.payReward` credits `value` (minus brokerage) into the witness's reward bucket for the current cycle unconditionally: [1](#0-0) 

That reward is later converted into a delta of the witness's reward-per-vote index (`Vi`) in `DelegationStore.accumulateWitnessVi`. If the witness has `voteCount == 0` for that cycle, the reward is simply dropped and `Vi` is only forwarded unchanged — the funds are never distributed to any voter, and there is no mechanism (burn, refund to witness, or forward to a future cycle) to recover them: [2](#0-1) 

The same skip-on-zero-vote pattern exists in the historical/batch computation path used for reward reads: [3](#0-2) 

and in `MortgageService.computeReward`, which explicitly `continue`s (skips) when `totalVote == 0`: [4](#0-3) 

Since block production and voting are decoupled (an SR/witness can be actively elected and producing blocks in a cycle while transiently having `0` votes recorded for that cycle, e.g. right after all voters withdraw/unvote before the cycle's Vi accumulation runs, or during migration windows), the reward amount recorded via `addReward` for that cycle/address key is written to the `DelegationStore` (`{cycle}-{address}-reward` key) but is never read again in any code path that would let a beneficiary claim it — `getReward` is only invoked once per cycle inside `accumulateWitnessVi`. This value remains permanently orphaned in the store, backing no claimable Vi delta.

### Impact Explanation
Reward funds credited via `payBlockReward`/`payTransactionFeeReward` to a witness with zero recorded votes in that cycle are permanently locked/unaccounted for: no voter can claim them (since Vi is not incremented) and the witness cannot claim them either through the standard vote-reward path. This constitutes a permanent freezing of funds within the reward accounting subsystem, matching the "Medium" severity class of the reference finding (irrecoverable emission/reward tokens accumulate over cycles, degrading the correctness of the total reward accounting and potentially causing sums of `Vi`-derived claims to diverge from actual funds paid out).

### Likelihood Explanation
This requires no privileged access — it can occur through the normal, permissionless flow of voting and unvoting (`VoteWitnessActuator`/`VoteWitnessProcessor`) combined with normal block production reward payout, which happens automatically every block/cycle for elected witnesses in `MortgageService`/`ConsensusDelegate` flows. Any witness that temporarily has zero votes for a given cycle while still producing blocks (a realistic and reachable state reachable purely by account holders unvoting via a standard transaction) triggers the loss.

### Recommendation
When `voteCount == 0` for a cycle in `DelegationStore.accumulateWitnessVi` (and the analogous logic in `RewardViCalService`/`MortgageService.computeReward`), do not silently drop the accumulated `reward`. Instead, either (a) carry the reward forward into the witness's own `allowance` directly (since no voter has a claim on it), or (b) roll it into the next cycle's reward pool so it is later distributed to whichever votes exist, ensuring the total reward paid out always equals total reward recorded.

### Proof of Concept
1. An SR (witness) has active votes and normal reward accrual for several cycles.
2. All voters call `VoteWitnessActuator`/`VoteWitnessProcessor` to withdraw their votes from that witness in the same cycle the witness produces blocks, driving `getWitnessVote(cycle, witness) == 0` for that cycle.
3. `MortgageService.payBlockReward`/`payTransactionFeeReward` still deposits reward for that cycle via `DelegationStore.addReward` (block production is independent of the just-updated vote state).
4. When `accumulateWitnessVi(cycle, witness, 0)` runs, `reward == 0 || voteCount == 0` branch is taken — the just-added reward is discarded from the Vi computation and never surfaces in any account's `queryReward`/`withdrawReward` result, permanently locking those funds in the store with no recovery path.

```java
  private long computeReward(long cycle, List<Pair<byte[], Long>> votes) {
    long reward = 0;
    for (Pair<byte[], Long> vote : votes) {
      byte[] srAddress = vote.getKey();
      long totalReward = delegationStore.getReward(cycle, srAddress);
      if (totalReward <= 0) {
        continue;
      }
      long totalVote = delegationStore.getWitnessVote(cycle, srAddress);
      if (totalVote == DelegationStore.REMARK || totalVote == 0) {
        continue;
      }
      long userVote = vote.getValue();
      double voteRate = (double) userVote / totalVote;
      reward += voteRate * totalReward;
    }
    return reward;
  }
```

```java
  public void accumulateWitnessVi(long cycle, byte[] address, long voteCount) {
    BigInteger preVi = getWitnessVi(cycle - 1, address);
    long reward = getReward(cycle, address);
    if (reward == 0 || voteCount == 0) { // Just forward pre vi
      if (!BigInteger.ZERO.equals(preVi)) { // Zero vi will not be record
        setWitnessVi(cycle, address, preVi);
      }
    } else { // Accumulate delta vi
      BigInteger deltaVi = BigInteger.valueOf(reward)
          .multiply(DECIMAL_OF_VI_REWARD)
          .divide(BigInteger.valueOf(voteCount));
      setWitnessVi(cycle, address, preVi.add(deltaVi));
    }
  }
```
