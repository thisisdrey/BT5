### Title
`pallet-scarcity::mint` permanently strands NFTs in purse keys that can never produce the `Origin::Nft` needed to move them - ([File: substrate/frame/scarcity/src/lib.rs])

### Summary
`pallet-scarcity`'s `mint`/`do_mint_inner` places an NFT into *any* `T::AccountId` supplied by the collection owner, with zero destination consent. The only ordinary way to move or burn that NFT afterward is the holder-signed `transfer`/`burn` extrinsics, and both of these are hard-gated on an `Origin::Nft` that can *only* be produced by the `AsScarcity` transaction extension validating a real signature from that account. If the destination account is one for which no private key exists or can ever sign (e.g. a `PalletId`-derived sovereign account, a precompiled/derived contract address, a burn address, or any keyless account computed by another pallet), the instance becomes structurally unrecoverable through the pallet's normal user-facing path — mirroring the `recoverERC721`/`RdpxV2Core` pattern where an asset is moved into a "trusted" account that has no logic to move it back out.

### Finding Description
`mint` is dispatched by an ordinary signed origin holding collection ownership — not root/governance — via: [1](#0-0) 

`do_mint`/`do_mint_inner` inserts the NFT directly into `NftsByOwner` for the caller-supplied `to` account with no consent check on `to`: [2](#0-1) [3](#0-2) 

The crate's own documentation acknowledges no destination consent exists, but asserts the holder can always recover by burning or transferring: [4](#0-3) 

That recovery path, however, is entirely dependent on the `AsScarcity` transaction extension converting a *signed* origin into `Origin::Nft` before the pallet's `transfer`/`burn` calls will even accept the request: [5](#0-4) 

`AsScarcity` requires the origin to be signed by the account currently holding the instance, and produces `CustomInvalidity::OriginToAsNftMustBeSigned` otherwise: [6](#0-5) 

If `to` is a keyless/derived account (any address for which the corresponding secret key does not exist — for example a `PalletId::into_account_truncating()` sovereign account belonging to *another* pallet, or any address computed as a hash with no matching private key), no signature can ever be produced for it. This means `transfer`/`burn` — the pallet's only unprivileged recovery mechanisms — are permanently unusable for that instance, exactly as `RdpxV2Core` in the external report has no logic to move an ERC721 it received. The only remaining path is `force_transfer`/`force_burn`, which are gated to the *current collection owner*, i.e., a different (and possibly unrelated or since-changed) privileged account — not the instance's nominal holder, and not guaranteed to exist or act.

### Impact Explanation
Any account can create a collection (`create_collection` is unprivileged) and then mint NFTs to arbitrary addresses. If a collection owner (attacker or accidentally) mints into a keyless/derived address, the resulting instance:
- Cannot be moved or burned by its "holder" (no one can sign for that account).
- Permanently occupies that purse key (`NftsByOwner`/`Instances`/`InstanceDeposits`/`InstanceMetadataCount` entries persist forever), consuming storage that can never be released except by the collection owner's privileged `force_burn`/`force_transfer`.
- If minted by a runtime integration (e.g. via `MintWithoutDeposit::mint_without_deposit`, used by higher-level game/contract logic) into a computed/derived beneficiary address that turns out to be keyless, the asset is permanently locked from an ordinary-user perspective — the exact "value gets stuck with no way to reclaim it" outcome the external report flags as High severity.

This breaks the pallet's own documented invariant ("the holder... can... transfer it away") and produces state that can never self-heal without out-of-band privileged intervention, matching the "permanent user-fund or bridge-state lock" impact class.

### Likelihood Explanation
Likelihood is high: minting is a normal, permissionless pallet operation (any account can be a collection owner), the `to` account is fully attacker/caller-controlled with no validation that it can ever produce a signature, and keyless/derived addresses are common and easy to construct (e.g., `PalletId` sovereign accounts, hashed/derived addresses used by other pallets or by contract/precompile integrations). No malicious validator, relayer, or governance action is required — only an ordinary signed call to `mint`.

### Recommendation
- Require the destination of `mint`/`force_transfer` to prove liveness/consent (e.g., a two-step accept, or restrict minting/force-transfer destinations to accounts with an existing System account / known-signable keys), or
- Provide an unprivileged, permissionless "reclaim" path analogous to `pallet-bounties::reclaim_bounty_funds` (see `prdoc/pr_11045.prdoc`) that lets the collection owner *or anyone* move a demonstrably orphaned instance (e.g., one held by a keyless/derived address) back to a recoverable account without depending on a signature from that address, and
- At minimum, update the module documentation to stop asserting unconditional holder recovery, and add a `try_state`/tooling check that flags instances held by accounts that cannot ever produce `Origin::Nft`.

### Proof of Concept
1. Attacker (or any unprivileged user) calls `create_collection` to become a collection owner (no permission needed).
2. Attacker calls `define_item` to register an item definition.
3. Attacker computes a keyless address, e.g. `SomeOtherPalletId::get().into_account_truncating()` (or any other address with no known private key, or a value derived purely from a hash with no corresponding key pair) — call it `to`.
4. Attacker calls `mint(origin, collection, item, to, vec![])` — succeeds per [1](#0-0) , `NftsByOwner::<T>::insert(&to, nft)` executes.
5. Anyone attempts `transfer`/`burn` as `to`: `AsScarcity` extension requires a signed transaction originating from `to`; since no private key exists for `to`, no valid signature can ever be produced, so validation always returns `InvalidTransaction::Custom(OriginToAsNftMustBeSigned)` — see [6](#0-5) .
6. The instance remains permanently recorded in `NftsByOwner`/`Instances` with no unprivileged recovery path, only recoverable by the collection owner's `force_transfer`/`force_burn` — a privileged action outside the instance holder's control, reproducing the "asset trapped with no recovery logic at destination" pattern from the external `recoverERC721` report.

		#[pallet::call_index(3)]
		#[pallet::weight(T::WeightInfo::transfer())]
		#[pallet::feeless_if(|origin: &OriginFor<T>, _to: &T::AccountId| -> bool {
			Pallet::<T>::is_nft_origin(origin)
		})]
		pub fn transfer(origin: OriginFor<T>, to: T::AccountId) -> DispatchResultWithPostInfo {
			let Ok(Origin::Nft { owner, nft }) = origin.into() else {
				return Err(DispatchError::BadOrigin.into());
			};
			ensure!(to != owner, Error::<T>::SelfTransfer);
			ensure!(!NftsByOwner::<T>::contains_key(&to), Error::<T>::AddressOccupied);

			let from = owner;
			let state_nonce =
				nft.state_nonce.checked_add(1).ok_or(Error::<T>::StateNonceOverflow)?;
			let nft = Nft { last_moved: T::UnixTime::now().as_secs(), state_nonce, ..nft };
			NftsByOwner::<T>::insert(&to, nft.clone());
			Instances::<T>::insert(nft.instance, &to);
			Self::deposit_event(Event::Transferred { instance: nft.instance, from, to });
			Ok(Pays::No.into())
		}

		/// Burn an NFT held by the `Origin::Nft` purse-key origin.
		///
		/// Item-definition supply counts minted-ever instances and is deliberately monotonic.
		/// Item metadata belongs to the definition and remains untouched. Instance metadata is
		/// removed and its exact deposits are released.
		#[pallet::call_index(4)]
		#[pallet::weight(T::WeightInfo::burn(T::MaxInstanceMetadata::get()))]
		#[pallet::feeless_if(|origin: &OriginFor<T>| -> bool {
			Pallet::<T>::is_nft_origin(origin)
		})]
		#[transactional]
		pub fn burn(origin: OriginFor<T>) -> DispatchResultWithPostInfo {
			let Ok(Origin::Nft { owner: _, nft }) = origin.into() else {
				return Err(DispatchError::BadOrigin.into());
			};
			let metadata_count = Self::do_burn(nft)?;
			Ok((Some(T::WeightInfo::burn(metadata_count)), Pays::No).into())
		}

/// An error reported while validating [`AsScarcity`].
#[repr(u8)]
pub enum CustomInvalidity {
	/// The purse-key authorization must begin with a signed origin.
	OriginToAsNftMustBeSigned = 0,
	/// The purse key is temporarily locked after a failed dispatch.
	NftTemporarilyLocked = 1,
	/// The purse key has no NFT to authorize the requested action.
	NoNft = 2,
	/// The transfer destination equals the current purse key.
	TransferToSelf = 3,
	/// The transfer destination already holds an NFT.
	DestinationOccupied = 4,
	/// The purse key holds a different instance or ownership-state revision.
	NftStateMismatch = 5,
}

impl From<CustomInvalidity> for TransactionValidityError {
	fn from(value: CustomInvalidity) -> Self {
		InvalidTransaction::Custom(value as u8).into()
	}
}
