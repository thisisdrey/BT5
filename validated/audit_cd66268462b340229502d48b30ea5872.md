Audit Report

## Title
Unbounded `block_numbers` array in `mmr_generateProof` RPC enables free, unbounded proof-generation work per request - ([File: substrate/client/merkle-mountain-range/rpc/src/lib.rs])

## Summary
The `MmrApiServer::generate_proof` handler forwards a caller-supplied `Vec<BlockNumber>` directly into `pallet_mmr::Pallet::generate_proof` with no length cap, and the underlying MMR logic performs an offchain-storage leaf lookup plus a proof-tree walk for every requested element, all on a JSON-RPC read path that is not gated by `DenyUnsafe`/`check_if_safe` and imposes no per-request cost accounting [5](#0-4) [6](#0-5) . This lets any unauthenticated RPC client force disproportionate CPU/IO work on a node by submitting a single call with a very large `block_numbers` array.

## Finding Description
`generate_proof` in the RPC layer accepts `block_numbers: Vec<NumberFor<Block>>` unmodified and passes it straight into the runtime API call with no size validation [3](#0-2) . That reaches `pallet_mmr::Pallet::generate_proof`, which maps every requested block number to a leaf index with no cap on input length [6](#0-5) . Each leaf index is converted to an MMR position, each position triggers an offchain-storage `get_elem` lookup, and the whole set is passed to `gen_proof`, whose cost scales with the number of requested leaves and MMR depth [7](#0-6) . By contrast, `state_getKeysPaged` explicitly enforces `STORAGE_KEYS_PAGED_MAX_COUNT` [2](#0-1) , and other RPC modules explicitly call `check_if_safe`/`DenyUnsafe` to gate expensive or sensitive calls [8](#0-7) , but `generate_proof` has neither protection. Node-level `deny_unsafe` classification only denies methods that explicitly call `check_if_safe`; since `generate_proof` never does, it remains callable on public interfaces regardless of `--rpc-methods` setting [4](#0-3) .

## Impact Explanation
MMR/BEEFY proofs served by this RPC underpin BEEFY light-client bridging (including Snowbridge's Polkadot→Ethereum proofs), so nodes exposing this endpoint are relied on by bridge relayers and light clients. Repeated calls with very large `block_numbers` arrays consume disproportionate CPU/IO relative to the request cost, degrading the node's ability to serve legitimate proof requests and, on relayer/bridge-facing nodes, potentially stalling bridge proof processing — matching the accepted "public underpriced work that ... stalls bridge processing" impact class. This is node/RPC-layer resource exhaustion, not a consensus, custody, or settlement-correctness break; it does not corrupt any on-chain state, balance, or proof-acceptance logic.

## Likelihood Explanation
Any node exposing this RPC to non-loopback interfaces accepts the call without a signature, fee, or special privilege, and the request cost is entirely attacker-controlled via array length; this is feasible and repeatable against any node/bridge-relayer endpoint with the default JSON-RPC service exposed.

## Recommendation
Add an explicit maximum-length check on `block_numbers` in `generate_proof` (and leaf counts in `generate_ancestry_proof`/`verify_proof`/`verify_proof_stateless`), mirroring the `STORAGE_KEYS_PAGED_MAX_COUNT` pattern, and consider adding `check_if_safe` gating or per-connection rate limiting for this and other unbounded-array read RPCs.

## Proof of Concept
Against any node exposing the default JSON-RPC set on a non-loopback interface:
```
curl -H 'Content-Type: application/json' -d '{
  "id":1, "jsonrpc":"2.0",
  "method":"mmr_generateProof",
  "params": [[1,2,3, ... , N],  N,  null]
}' http://NODE:9944
```
Setting `N` to a large value (bounded only by MMR leaf count / SCALE decode limits) forces the node to perform `N` offchain-storage lookups and MMR proof computations per call, repeatable indefinitely at no cost to the caller.

	pub fn generate_proof(
		&self,
		leaf_indices: Vec<NodeIndex>,
	) -> Result<(Vec<L>, LeafProof<HashOf<T, I>>), Error> {
		let positions = leaf_indices
			.iter()
			.map(|index| mmr_lib::leaf_index_to_pos(*index))
			.collect::<Vec<_>>();
		let store = <Storage<OffchainStorage, T, I, L>>::default();
		let leaves = positions
			.iter()
			.map(|pos| match store.get_elem(*pos) {
				Ok(Some(Node::Data(leaf))) => Ok(leaf),
				e => Err(Error::LeafNotFound.log_debug(e)),
			})
			.collect::<Result<Vec<_>, Error>>()?;

		let leaf_count = self.leaves;
		self.mmr
			.gen_proof(positions)
			.map_err(|e| Error::GenerateProof.log_error(e))
			.map(|p| LeafProof {
				leaf_indices,
				leaf_count,
				items: p.proof_items().iter().map(|x| x.hash()).collect(),
			})
			.map(|p| (leaves, p))
	}
