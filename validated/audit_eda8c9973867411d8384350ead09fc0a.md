**Reasoning summary:** The `HandleControlMsg` → `handleCreateRelayResponse` → `EstablishRelay` → `CompleteRelayByIdx` path is only reachable after `outside.go`'s `readOutsidePackets` has already looked up `hostinfo` by `h.RemoteIndex` via `f.hostMap.QueryIndex(h.RemoteIndex)` and successfully decrypted the packet with `hostinfo.ConnectionState.Decrypt(...)` [1](#0-0) . This AEAD decrypt only succeeds if the sender possesses the session keys derived from that specific handshake, so the `h *HostInfo` passed into `relayManager.HandleControlMsg` is cryptographically bound to the genuine peer of that session — it cannot be spoofed or substituted by guessing `InitiatorRelayIndex`/`ResponderRelayIndex` values from an unrelated attacker [2](#0-1) .

`CompleteRelayByIdx(localIdx, remoteIdx)` looks up the `Relay` by `localIdx` in `relayHostInfo.relayState.relayForByIdx`, a map that is private to that specific `HostInfo` [3](#0-2) . That `localIdx` value is generated by `AddRelay`/`generateIndex` on the initiator's side and is only ever transmitted directly to the chosen relay peer inside the `CreateRelayRequest.InitiatorRelayIndex` field sent over that peer's authenticated session [4](#0-3) . An outside attacker without that specific session's keys cannot produce a packet that decrypts into a valid `NebulaControl` for that `HostInfo`, so they cannot present a forged `InitiatorRelayIndex`/`ResponderRelayIndex` pair to `EstablishRelay` for a hostinfo/session they don't own.

The only party capable of supplying an arbitrary `ResponderRelayIndex` for that pairing is the legitimate relay peer that the initiator itself chose and already handshake-authenticated (since that peer was told the `InitiatorRelayIndex` directly, and is expected to choose its own local index — that's how the protocol is designed to work, not a bypass). Exploiting this would require treating that already-authenticated, initiator-chosen relay peer as malicious, which the rules explicitly disallow ("Never assume a malicious peer, malicious node, or compromised lighthouse"). Given the stated constraints (unprivileged attacker, no CA-signed cert, no compromised peer), there is no reachable path for an attacker to forge or replay a `CreateRelayResponse` against a `HostInfo`/index pair they do not already own the session keys for.

func (rs *RelayState) CompleteRelayByIdx(localIdx uint32, remoteIdx uint32) (*Relay, bool) {
	rs.Lock()
	defer rs.Unlock()
	r, ok := rs.relayForByIdx[localIdx]
	if !ok {
		return nil, false
	}
	newRelay := *r
	newRelay.State = Established
	newRelay.RemoteIndex = remoteIdx
	rs.relayForByIdx[r.LocalIndex] = &newRelay
	rs.relayForByAddr[r.PeerAddr] = &newRelay
	return &newRelay, true
}
