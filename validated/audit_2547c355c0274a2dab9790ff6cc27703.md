### Title
Unbounded recursion depth in `parse_json` via `serde_json::from_slice` causes remote stack-overflow DoS - (File: stackslib/src/net/http/common.rs)

### Summary
`parse_json` in `stackslib/src/net/http/common.rs` only checks the `Content-Type` header before handing the raw body directly to `serde_json::from_slice(body)`, with no recursion-depth limit of its own. Since `content-length`/byte-size caps enforced by individual handlers (e.g. `MAX_PAYLOAD_LEN` in `posttransaction.rs`) bound total bytes, not nesting depth, an attacker can construct a small payload (well under any byte cap) consisting of thousands of nested arrays (`[[[[...]]]]`), which will drive `serde_json`'s recursive-descent parser to recurse once per nesting level.

### Finding Description
`parse_json` (stackslib/src/net/http/common.rs:88-107) does:
```
let item_result: Result<T, serde_json::Error> = serde_json::from_slice(body);
```
with no wrapping deserializer that limits recursion depth, and no check on the *structure* of the body — only `preamble.content_type` is validated. Every caller (e.g. `RPCPostTransactionRequestHandler::parse_posttransaction_json` at `stackslib/src/net/api/posttransaction.rs:65-69`, and equivalent code in `poststackerdbchunk.rs`, `postblock_proposal.rs`, `txsimulate.rs`, `blocksimulate.rs`, etc.) enforces only a maximum **byte length** of the body (via `content_length` checks / `MAX_PAYLOAD_LEN`), not a maximum **nesting depth**. A body like `[[[[[...]]]]]]` with N nesting levels needs only ~2×N bytes total, so an attacker can encode tens of thousands of nesting levels while staying far under any handler's byte-length cap.

`serde_json`'s default deserializer uses recursive descent with one Rust stack frame consumed per array/object nesting level and no configurable/default recursion-depth limit (unlike, e.g., some other formats that impose one). This is a well-known upstream characteristic of `serde_json`. This means the equality "recursion_depth_during_parse == a value bounded independent of attacker-chosen nesting" does **not** hold — recursion depth is directly attacker-controlled via nesting depth, unbounded by any check in this repository's code.

### Impact Explanation
A remote, unprivileged party that can reach any RPC endpoint accepting `application/json` bodies (any endpoint using `parse_json`, e.g. `POST /v2/transactions`, `POST /v2/blocks`, StackerDB chunk posting, read-only call simulation endpoints) can send a single small HTTP request whose body is deeply nested JSON. This drives the parsing thread's stack to overflow, aborting the process (Rust stack overflow is not a catchable panic — it aborts the process). This crashes the node handling the request, is repeatable, and requires only a single message per crash — matching the **Critical: remote crash/unauthenticated DoS from few messages** category.

### Likelihood Explanation
- Preconditions: attacker only needs network reachability to the RPC/HTTP port; no secret, peer key, or StackerDB slot ownership required for endpoints that accept public JSON bodies (e.g. `posttransaction`, `poststackerdbchunk`'s JSON path if applicable, simulate endpoints).
- Attacker cost: trivial — a few kilobytes of nested brackets, well within existing per-handler byte caps.
- Remote reachability: yes, RPC ports are meant to be reachable by the public in many deployments (e.g. transaction submission).
- Repeatability: fully repeatable against any node exposing the endpoint.

### Recommendation
Enforce an explicit recursion/nesting depth limit in `parse_json` before or during deserialization — e.g. use `serde_json::Deserializer::from_slice(body).into_iter()` with a depth-tracking wrapper, or pre-scan the body to reject inputs exceeding a small maximum nesting depth (e.g. 128) prior to calling `serde_json::from_slice`. Alternatively, run JSON parsing in a bounded-stack worker or catch stack overflows via `stacker`-style guarded stacks used elsewhere in the codebase for recursive Clarity evaluation.

### Proof of Concept
```rust
// stackslib/src/net/http/common.rs (test module)
#[test]
fn test_parse_json_deep_nesting_stack_overflow() {
    let preamble = HttpResponsePreamble::new_for_test_json(); // JSON content-type
    let depth = 100_000usize;
    let mut body = Vec::with_capacity(depth * 2);
    body.extend(std::iter::repeat(b'[').take(depth));
    body.extend(std::iter::repeat(b']').take(depth));
    // Expect: process should return Err(Error::DecodeError(..)) gracefully.
    // Actual: this call causes a stack overflow and aborts the process
    // (not a catchable panic), rather than returning Err.
    let _ = parse_json::<serde_json::Value>(&preamble, &body);
}
```

```rust
pub fn parse_json<T: serde::de::DeserializeOwned>(
    preamble: &HttpResponsePreamble,
    body: &[u8],
) -> Result<T, Error> {
    // content-type has to be JSON
    if preamble.content_type != HttpContentType::JSON {
        return Err(Error::DecodeError(
            "Invalid content-type: expected application/json".to_string(),
        ));
    }

    let item_result: Result<T, serde_json::Error> = serde_json::from_slice(body);
    item_result.map_err(|e| {
        if e.is_eof() {
            Error::UnderflowError("Not enough bytes to parse JSON".to_string())
        } else {
            Error::DecodeError(format!("Failed to parse JSON: {:?}", &e))
        }
    })
}
```
