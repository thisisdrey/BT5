### Title
`Pool.liquidate` per-token debt-floor check combined with `maxLiquidable` cap permanently blocks valid liquidations of small debts — (File: contracts/Pool.sol)

### Summary
The reference bug blocks valid liquidations because the max-repayable amount is computed from an incomplete view of the borrower's debt (only borrows originated on the current chain, omitting destination-chain borrows). In Metronome, `Pool.liquidate` enforces two mutually-exclusive bounds computed from a per-token view of debt: `maxLiquidable` caps repayment to a fraction (50% on initialization) of the repaid synth's `DebtToken` balance, while the `debtFloorInUsd` check reverts whenever the remaining balance *of that same debt token only* is non-zero but below the floor. For any debt position in a single synthetic token whose USD value is below `2 * debtFloorInUsd`, no `amountToRepay_` exists that satisfies both checks, so the liquidation reverts unconditionally.

### Finding Description
`Pool.liquidate` performs:

```solidity
uint256 _debtTokenBalance = _debtToken.balanceOf(account_);

if (amountToRepay_.wadDiv(_debtTokenBalance) > maxLiquidable) {
    revert AmountGreaterThanMaxLiquidable();
}

if (debtFloorInUsd > 0) {
    uint256 _newDebtInUsd = masterOracle().quoteTokenToUsd(
        address(syntheticToken_),
        _debtTokenBalance - amountToRepay_
    );
    if (_newDebtInUsd > 0 && _newDebtInUsd < debtFloorInUsd) {
        revert RemainingDebtIsLowerThanTheFloor();
    }
}
``` [1](#0-0) 

The floor check evaluates the remaining debt *only of the repaid synthetic token* (`_debtTokenBalance - amountToRepay_`), not the account's aggregate debt from `debtOf(account_)`, which iterates all `debtTokensOfAccount`. [2](#0-1) 

With `maxLiquidable = 0.5e18` (set in `initialize`), repaying more than 50% reverts `AmountGreaterThanMaxLiquidable`. [3](#0-2)  Therefore any allowed repayment leaves ≥ 50% of the debt outstanding. If the token's debt is below `2 * debtFloorInUsd`, every allowed repayment leaves a remainder in `(0, debtFloorInUsd)`, reverting `RemainingDebtIsLowerThanTheFloor`. Full repayment is the only way to satisfy the floor but is forbidden by `maxLiquidable` — a dead zone with no valid input. The parallel `DebtToken.repay` floor check has the same per-token scope, so even voluntary full/partial repayment of dust debt by a third party reverts identically (only `repayAll`, which repays 100%, escapes — but liquidators cannot use it to seize collateral). [4](#0-3) 

Additionally, because the floor is measured per-token rather than against aggregate debt, a borrower with multiple debt tokens can be forced to fully zero one token even when total remaining debt is far above the floor — an over-restriction that further shrinks the feasible liquidation range beyond what `maxLiquidable` intends.

### Impact Explanation
While `debtFloorInUsd > 0` and `maxLiquidable < 1e18` (both true on the deployed configuration: `maxLiquidable` initializes to 50%), every unhealthy position whose per-synth debt is below `2 * debtFloorInUsd` cannot be liquidated at all. Any unprivileged liquidator calling `Pool.liquidate` with any `amountToRepay_` hits either `AmountGreaterThanMaxLiquidable` or `RemainingDebtIsLowerThanTheFloor`. Small bad debts are precisely the ones that become permanently stranded (dust positions are the least attractive and least repayable), leaving collateral locked against unrecoverable debt and degrading protocol solvency. The condition persists until interest accrual eventually lifts the debt above `2 * floor` or governance intervenes — i.e., temporary-to-permanent freezing of the liquidation path for a whole class of positions.

### Likelihood Explanation
Requires only: (a) `debtFloorInUsd > 0` (the feature exists and is governor-set; the code paths at `Pool.sol:571` and `DebtToken.sol:442` are live production code), and (b) any account holding an unhealthy position with a single-synth debt below twice the floor. No privileged actor, oracle manipulation, or external dependency is needed — the revert is deterministic for any liquidator. An attacker can also deliberately open minimum-size debts just above `debtFloorInUsd` (passing `_mint`'s floor check at `DebtToken.sol:583-588`) and let price drift push them underwater, manufacturing un-liquidatable bad debt. Caveat: if `debtFloorInUsd == 0` on a given deployment, the dead zone does not exist there; the exact deployed value could not be confirmed from the indexed contract source.

### Recommendation
- In `Pool.liquidate` (and `DebtToken.repay`), evaluate the floor against the account's *aggregate* remaining debt (`debtOf`) rather than the single repaid token, or exempt liquidation paths from the floor entirely.
- Alternatively, when `remaining <= debtFloorInUsd`, allow the liquidator to repay 100% of that token's debt (waive `maxLiquidable` for the final full-clearing repayment), mirroring `repayAll` semantics.
- Same fix pattern as the reference report: the bound must be computed from the complete debt picture, not a partial aggregation.

### Proof of Concept
Foundry sketch (Hardhat fork equivalent):

```solidity
// Assume: debtFloorInUsd = $100, maxLiquidable = 0.5e18 (Pool.initialize)
// 1. Alice deposits collateral, issues $120 of msUSD (passes DebtLowerThanTheFloor at mint).
// 2. Collateral price drops; debtPositionOf(alice) -> _isHealthy == false.
// 3. Liquidator calls pool.liquidate(msUSD, alice, X, depositToken):
//    - X = 120 (full): 120.wadDiv(120) = 1e18 > 0.5e18  -> AmountGreaterThanMaxLiquidable
//    - X = 60  (max allowed): remaining = 60 -> $60 < $100 and > 0 -> RemainingDebtIsLowerThanTheFloor
//    - Any X in (0, 60]: remaining in [60, 120), always > 0 and < floor -> same revert
// 4. No X exists: vm.expectRevert on every call. Liquidation impossible.
```

```solidity
function test_liquidateDeadZone() public {
    // debtFloorInUsd = 100e18; alice's msUSD debt = $120, unhealthy
    vm.prank(liquidator);
    vm.expectRevert(Pool.AmountGreaterThanMaxLiquidable.selector);
    pool.liquidate(msUsd, alice, 120e18, depositToken);   // > maxLiquidable

    vm.prank(liquidator);
    vm.expectRevert(Pool.RemainingDebtIsLowerThanTheFloor.selector);
    pool.liquidate(msUsd, alice, 60e18, depositToken);    // leaves $60 dust < floor
}
