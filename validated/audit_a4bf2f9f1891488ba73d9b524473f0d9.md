Based on the evidence gathered, this maps cleanly to the reported bug class. The `/wallet/getnodeinfo` (and its solidity/PBFT variants) is an unauthenticated HTTP query endpoint into the node's Wallet API surface that discloses detailed internal service information — directly analogous to CVE-2024-9802's conformance-validation endpoint disclosing service internals.

### Title
Unauthenticated `/wallet/getnodeinfo` HTTP endpoint discloses sensitive node configuration, version, and topology information - (File: framework/src/main/java/org/tron/core/services/http/GetNodeInfoServlet.java)

### Summary
The `GetNodeInfoServlet` backing `/wallet/getnodeinfo`, `/walletsolidity/getnodeinfo`, and the PBFT/Solidity wrapper variants serves the full `NodeInfo` object — including exact code version, P2P version, listening ports, peer/connection topology, JVM/machine details, and adaptive-energy/contract-creation config flags — to any anonymous caller, with no authentication or authorization check performed anywhere in the request path.

### Finding Description
`GetNodeInfoServlet.doGet` calls `NodeInfoService.getNodeInfo()` and serializes the result directly to the HTTP response with no access control beyond rate limiting (`RateLimiterServlet`) and the config-driven disabled-API blocklist in `HttpApiAccessFilter`, which is opt-out only and does not require auth. [1](#0-0) 

`NodeInfoService.getNodeInfo()` populates a response containing the exact running `Version.getVersion()` / `Version.VERSION_CODE`, P2P protocol version, listen port, backup port, discovery-enable flag, DB version, min/max time ratios, `allowCreationOfContracts`, `allowAdaptiveEnergy`, and connection/peer counts — none of which require any credential to view. [2](#0-1) 

This servlet is mapped as a fully public route in both the full node and solidity node HTTP services, including duplicate mappings across `/wallet/getnodeinfo` and `/walletsolidity/getnodeinfo`. [3](#0-2) 

The only gating logic present, `HttpApiAccessFilter.isDisabled`, is a config-driven denylist (`disabledApiList`) that is empty by default — it does not implement authentication, it only optionally blocks specific endpoint names if an operator explicitly configures them. [4](#0-3) 

The `MachineInfo` portion additionally leaks JVM heap/memory pool usage, thread counts, OS name/version, and (in the presence of a deadlock) full thread stack traces via `DeadLockThreadInfo.stackTrace`. [5](#0-4) 

### Impact Explanation
An unauthenticated remote attacker can fingerprint the exact `java-tron` build/version, P2P protocol version, and DB version running on a node, and combine this with exposed listener ports and peer/connection counts to select known exploits for that specific version, identify which nodes are reachable/alive, and map network topology for targeted attacks (e.g., prioritizing outdated nodes for known CVEs, or targeting SRs/witnesses by port/peer fingerprinting). This matches the CVE-2024-9802 bug class of an unauthenticated status/validation endpoint disclosing service internals (version, endpoints, running state) that aids further attacks, rather than causing direct fund loss.

### Likelihood Explanation
High likelihood: the endpoint requires no authentication, no signed transaction, and no special network position — a single unauthenticated `GET /wallet/getnodeinfo` HTTP request against any full node, solidity node, or PBFT node exposing the HTTP API is sufficient, and this is the default configuration unless an operator manually adds `getnodeinfo` to `disabledApiList`.

### Recommendation
Restrict `/wallet/getnodeinfo` (and its solidity/PBFT variants) to trusted/internal callers by default — e.g., require it to be explicitly enabled, gate it behind an allowlist/auth token, or strip version/port/peer-topology and JVM diagnostic fields from the response returned to public callers, keeping only non-sensitive block-height style information for anonymous requests.

### Proof of Concept
```
curl -s http://<full-node-host>:8090/wallet/getnodeinfo
```
This returns a JSON payload containing `configNodeInfo.codeVersion`, `configNodeInfo.p2pVersion`, `configNodeInfo.listenPort`, `configNodeInfo.dbVersion`, `configNodeInfo.allowCreationOfContracts`, `configNodeInfo.allowAdaptiveEnergy`, peer list details, and `machineInfo` (JVM/OS/thread data) — with no `Authorization` header or transaction signature required, as shown by the unauthenticated servlet flow in `GetNodeInfoServlet.doGet` → `NodeInfoService.getNodeInfo()`. @Component
@Slf4j(topic = "API")
public class GetNodeInfoServlet extends RateLimiterServlet {

  @Autowired
  private NodeInfoService nodeInfoService;

  protected void doGet(HttpServletRequest request, HttpServletResponse response) {
    try {
      NodeInfo nodeInfo = nodeInfoService.getNodeInfo();
      response.getWriter().println(JSON.toJSONString(nodeInfo));

    } catch (Exception e) {
      logger.error("", e);
      try {
        response.getWriter().println(Util.printErrorMsg(e));
      } catch (IOException ioe) {
        logger.debug("IOException: {}", ioe.getMessage());
      }
    }
  }

  private boolean isDisabled(String endpoint) {
    boolean disabled = false;

    try {
      endpoint = URI.create(endpoint).normalize().toString();
      List<String> disabledApiList = CommonParameter.getInstance().getDisabledApiList();
      if (!disabledApiList.isEmpty()) {
        disabled = disabledApiList.contains(endpoint.split("/")[2].toLowerCase(Locale.ROOT));
      }
    } catch (Exception e) {
      logger.warn("check isDisabled except, endpoint={}, {}", endpoint, e.getMessage());
    }

    return disabled;
  }
