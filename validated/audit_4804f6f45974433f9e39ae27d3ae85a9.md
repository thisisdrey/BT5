### Title
Unbounded goroutine/FD leak via stalled `CreateRepositoryFromBundle` stream - ([File: internal/gitaly/service/repository/create_repository_from_bundle.go])

### Summary
`CreateRepositoryFromBundle` reads the bundle body via a blocking `io.Copy` from a `streamio.Reader` wrapping `stream.Recv()`, with no context-based read deadline applied to that copy. An attacker who sends only the initial `Repository`-only request and then never sends further `Data` nor closes the stream keeps the server-side handler goroutine blocked in `io.Copy`, holding open the temp bundle file and temp directory indefinitely.

### Finding Description
`server.CreateRepositoryFromBundle` receives the first request, validates the repository, then hands a `streamio.NewReader` callback (which calls `stream.Recv()` on demand) into `repoutil.Create` → `Repo.CloneBundle` → `Repo.createTempBundle` [1](#0-0) . Inside `createTempBundle`, the server creates a temp directory/file with `tempdir.New` and `os.Create(bundlePath)`, then executes `io.Copy(file, reader)` [2](#0-1) . `io.Copy` blocks on `reader.Read`, which ultimately blocks on `stream.Recv()`. There is no `context.WithTimeout`/deadline wrapping this copy loop, and the gRPC server configuration only sets keepalive ping parameters (`grpc.KeepaliveParams{Time: 5*time.Minute}` and an enforcement policy), not a `MaxConnectionIdle`/`MaxConnectionAge` or any application-level idle timeout for this RPC [3](#0-2) . Contrast this with `SSHUploadArchive`, which explicitly integrates a timeout ticker in the server to enforce a negotiation timeout for a stalled client — that pattern is absent for `CreateRepositoryFromBundle` and `CloneBundle`'s bundle copy loop [4](#0-3) . Because gRPC streaming clients are not required to set a client-side deadline (and the RPC context used by Gitaly is derived from whatever context/deadline the client supplies), an attacker with ordinary push/pull access can open the stream, send the first message, and simply never call `Send`/`CloseSend`, keeping the goroutine, its open file descriptor, and its temp directory alive for as long as the underlying transport connection is not otherwise reaped.

### Impact Explanation
Each such connection consumes one server goroutine, one open file descriptor for the bundle temp file, and one temp directory in the storage location, none of which are bounded or reclaimed until the client disconnects or the TCP/HTTP2 connection is otherwise torn down. Repeating this from many concurrent connections/streams can exhaust Gitaly's goroutine and file-descriptor budget, degrading or crashing the RPC service for all tenants on that node — this matches a resource-exhaustion / denial-of-service-of-RPC-handler impact class.

### Likelihood Explanation
The precondition is only that the caller has ordinary push/pull-level access sufficient to invoke a gRPC RPC on Gitaly (no special role, no secret, no default-config assumption beyond "no idle timeout configured", which appears to be the actual default given the keepalive-only settings found). The exploit requires nothing more than opening a stream, sending one small message, and withholding further sends — trivially repeatable and scriptable in bulk, so likelihood is high assuming the underlying gRPC/HTTP2 layer does not itself impose a hard idle-stream timeout (which was not found in the reviewed server configuration).

### Recommendation
Wrap the bundle-copy read loop (or, more generally, the `stream.Recv()` calls following the first request in `CreateRepositoryFromBundle`, `FetchBundle`, and similar RPCs) with a per-request idle/read timeout, analogous to the timeout ticker used in `internal/gitaly/service/ssh` for `UploadArchive`, so that a Recv() that doesn't complete within a bounded window cancels the stream context and releases the goroutine/file/tempdir. Additionally, consider adding a server-wide `grpc.KeepaliveParams`/`MaxConnectionIdle` policy or a generic stream-idle-timeout interceptor to bound resource usage for all streaming RPCs that read attacker-controlled data.

	tmpDir, cleanup, err := tempdir.New(ctx, repo.GetStorageName(), repo.logger, repo.locator)
	if err != nil {
		return "", nil, fmt.Errorf("create temp bundle: %w", err)
	}

	bundlePath := filepath.Join(tmpDir.Path(), "repo.bundle")

	file, err := os.Create(bundlePath)
	if err != nil {
		cleanup() // Clean up if we fail after creating the temp directory
		return "", nil, fmt.Errorf("create temp bundle: %w", err)
	}
	defer func() {
		if err := file.Close(); err != nil && returnErr == nil {
			returnErr = fmt.Errorf("create temp bundle: %w", err)
		}
	}()
