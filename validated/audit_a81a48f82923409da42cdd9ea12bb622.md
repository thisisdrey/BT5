### Title
`Pool.swap` burns the user's input synth while minting zero output when the oracle quote rounds down to zero - ([File: contracts/Pool.sol](contracts/Pool.sol))

### Summary
`Pool.swap` unconditionally burns `amountIn_` of `syntheticTokenIn_` from the caller, then computes `_amountOut` via `masterOracle().quote(...)`. If the quote rounds down to `0` — which can happen when `syntheticTokenOut_` has few decimals and/or a high USD price relative to a small `amountIn_` — the user loses their entire input and receives nothing. There is no `minAmountOut` parameter and no `if (_amountOut == 0) revert` check, the exact same bug class as the Inverter `BancorFormula` rounding-to-zero finding.

### Finding Description

`swap` burns first, mints second, and never validates the quoted output:

```solidity
// contracts/Pool.sol:658-668
if (amountIn_ == 0 || amountIn_ > syntheticTokenIn_.balanceOf(_msgSender)) revert AmountInIsInvalid();

syntheticTokenIn_.burn(_msgSender, amountIn_);

(_amountOut, _fee) = quoteSwapOut(syntheticTokenIn_, syntheticTokenOut_, amountIn_);

if (_fee > 0) {
    syntheticTokenOut_.mint(_poolRegistry.feeCollector(), _fee);
}

syntheticTokenOut_.mint(_msgSender, _amountOut);
```

`quoteSwapOut` delegates to the oracle:

```solidity
// contracts/Pool.sol:513-517
_amountOut = _poolRegistry.masterOracle().quote(
    address(syntheticTokenIn_),
    address(syntheticTokenOut_),
    amountIn_
);
```

`SyntheticToken` supports arbitrary `decimals_` at initialization (e.g., a synth could be deployed with 6 or 8 decimals). `MasterOracle.quote` converts `amountIn_` (in tokenIn decimals) to USD and then to `syntheticTokenOut_` decimals; for a small `amountIn_` of a low-priced synth into a high-priced/low-decimal synth, integer division truncates the result to `0`. The caller still gets `syntheticTokenIn_.burn` executed at line 660 and receives a `mint` of `0` at line 668.

The same pattern exists symmetrically on the input side (`quoteSwapIn` can return `_amountIn == 0` or a `0` fee while the caller supplies a nonzero `amountOut_`), but `swap` is the reachable public entry point where loss is realized.

### Impact Explanation
Direct loss of user funds: the user's `amountIn_` synth is burned and they receive zero `syntheticTokenOut_` in return. The trade has no slippage/min-out protection at the contract level (`swap` takes only `amountIn_`), so the rounding loss is silently realized on-chain rather than reverting. Dust swaps become pure burns, reducing supply of `syntheticTokenIn_` without minting any `syntheticTokenOut_`.

### Likelihood Explanation
- Reachable by any unprivileged EOA via the public `Pool.swap` (guarded only by `whenNotShutdown`, `nonReentrant`, `onlyIfSyntheticTokenExists`, and the `isSwapActive` flag — none of which prevent a zero-output quote).
- No oracle manipulation is required: truncation is inherent to integer division in `MasterOracle.quote` whenever `amountIn_usd * 10^outDecimals / priceOut < 1`, e.g., a few wei of an msUSD-denominated synth into a high-value synth.
- Severity is bounded per-tx by the dust-sized loss (the amount that rounds to zero), but the function permits it unconditionally and users have no on-chain min-out guard.

### Recommendation
Add a nonzero-output check in `swap` (and/or inside `quoteSwapOut`), ideally before burning or via a `minAmountOut_` parameter:

```solidity
(_amountOut, _fee) = quoteSwapOut(syntheticTokenIn_, syntheticTokenOut_, amountIn_);
if (_amountOut == 0) revert AmountOutIsZero(); // burn already done; reorder or check first
```

Better: quote before burning and revert on `_amountOut == 0`, or accept a `minAmountOut_` slippage parameter so users control the minimum acceptable output. The same zero-check should be considered for the `_amountIn == 0` path implied by `quoteSwapIn`.

### Proof of Concept

```solidity
// Foundry-style PoC against deployed Metronome contracts
function testSwap_BurnsIn_MintsZero() public {
    // pool, msUSD (18 decimals, ~$1), msHIGH (e.g., 6 decimals, high USD price)
    address alice = makeAddr("alice");
    uint256 dust = 1e3; // tiny amountIn of msUSD

    // give alice some msUSD
    vm.startPrank(alice);
    msUSD.approve(address(pool), type(uint256).max);
    // acquire dust amount (e.g., via issue or transfer)
    deal(address(msUSD), alice, dust);

    uint256 balInBefore  = msUSD.balanceOf(alice);
    uint256 balOutBefore = msHIGH.balanceOf(alice);

    (uint256 quotedOut, ) = pool.quoteSwapOut(
        ISyntheticToken(address(msUSD)),
        ISyntheticToken(address(msHIGH)),
        dust
    );
    assertEq(quotedOut, 0); // oracle quote truncates to zero

    pool.swap(ISyntheticToken(address(msUSD)), ISyntheticToken(address(msHIGH)), dust);

    // alice lost dust of msUSD and received nothing
    assertEq(msUSD.balanceOf(alice), balInBefore - dust);
    assertEq(msHIGH.balanceOf(alice), balOutBefore); // 0 minted
    vm.stopPrank();
}
```

`quoteSwapOut` returning `0` while `swap` still executes `syntheticTokenIn_.burn(_msgSender, amountIn_)` demonstrates the invariant break: value conservation across the swap is violated — input is destroyed, no output is created.
