## Title
Unauthenticated handshake packets force full asymmetric Noise DH + certificate reconstruction at near-zero attacker cost, with the only designed anti-DoS mechanism (`Cookie`) never implemented - ([File: handshake/machine.go], [File: handshake_manager.go], [File: handshake/handshake.proto])

### Summary
The external report describes a cost formula (`calculateSpinCost`) that a caller can manipulate (via `_totalSlots`) to round down to zero, letting an attacker trigger unbounded, expensive Chainlink VRF calls while paying almost nothing, draining a shared subscription balance. Nebula has the same shape of asymmetry at its unauthenticated handshake entry point: `HandshakeManager.HandleIncoming` → `beginHandshake` runs a full Noise `ReadMessage` (asymmetric Diffie-Hellman) and certificate reconstruction (`cert.Recombine`) for **every** stage-1 packet before any certificate/CA verification succeeds, and the wire format's only reserved anti-DoS mechanism (`Cookie`) was "never implemented" and is silently skipped by the parser. An attacker with no CA-signed certificate can therefore force the responder to repeatedly pay full asymmetric-crypto cost for the price of sending small UDP packets.

### Finding Description
When a stage-1 handshake packet arrives, `HandshakeManager.HandleIncoming` dispatches straight to `beginHandshake` without any per-source cost/rate gate: [1](#0-0) 

`beginHandshake` builds a brand-new `handshake.Machine` and immediately calls `machine.ProcessPacket`, which performs `m.hs.ReadMessage(...)` - the Noise IX pattern's Diffie-Hellman step - **before** any certificate is checked: [2](#0-1) 

Only after this expensive DH operation succeeds does the code reach `m.processPayload` → `m.validateCert`, which reconstructs the certificate (`cert.Recombine`) and only then calls the `CertVerifier` that actually checks CA trust: [3](#0-2) 

Back in `beginHandshake`, only after `machine.ProcessPacket` returns is `hm.validatePeerCert` invoked to reject untrusted certs: [4](#0-3) 

The protocol's only designed defense against this kind of unauthenticated cost asymmetry - a `Cookie` field - was reserved for exactly this purpose but never implemented, and is silently accepted/ignored: [5](#0-4) 

The result mirrors the SpinLottery bug class: a cheap, attacker-controlled input (an arbitrary forged stage-1 UDP packet with any static key/cert bytes) causes the victim to pay a disproportionate, fixed cost (DH computation + cert parsing) with no CA-signed certificate required and no anti-abuse cost charged back to the sender, because the intended cost-imposing mechanism (`Cookie`) does not exist.

### Impact Explanation
Any unauthenticated attacker can flood a Nebula node with forged stage-1 handshake packets, each forcing a full X25519 DH operation and certificate parse on the responder before rejection. Because packet crafting/sending cost is negligible compared to elliptic-curve DH and cert reconstruction cost, this is a CPU-exhaustion amplification vector directly analogous to draining a shared paid resource (the Chainlink subscription in the original report) for near-zero attacker expenditure - here the "shared resource" is the node's CPU/handshake-processing capacity, degrading availability for legitimate peers.

### Likelihood Explanation
Likelihood is Medium-to-High: no privileged access, valid certificate, or prior trust relationship is required. An attacker only needs to know (or guess) a node's UDP listen address and send arbitrary stage-1-shaped packets; the header/subtype gating in `HandleIncoming` does not require a valid certificate before the DH step executes.

### Recommendation
Impose a real cost/verification step on the sender before performing expensive DH and certificate reconstruction, e.g. implement the previously-reserved `Cookie` anti-DoS mechanism (return-routability challenge) or add per-source-address rate limiting/backoff for stage-1 handshake processing in `HandshakeManager.HandleIncoming`/`beginHandshake`, so an unauthenticated peer cannot cheaply trigger unbounded asymmetric-crypto work.

### Proof of Concept
1. From an attacker-controlled host with no Nebula CA-signed certificate, craft minimal stage-1 handshake UDP packets: `header.Version`, `header.Handshake` type, `header.HandshakeIXPSK0` subtype, `RemoteIndex = 0`, `MessageCounter = 1`, followed by arbitrary Noise ciphertext bytes of the expected length (varying the ephemeral key bytes each time so `ReadMessage` doesn't short-circuit on identical state).
2. Send a high rate of such packets to the victim's listening UDP port.
3. Observe that `HandleIncoming` → `beginHandshake` → `machine.ProcessPacket` → `m.hs.ReadMessage` performs a full DH computation and, if the ciphertext parses, `cert.Recombine`/`validateCert` runs before the request is ultimately rejected in `hm.validatePeerCert` - all triggered by packets the attacker can generate at negligible cost and without ever presenting a CA-trusted certificate.

```go
func (m *Machine) validateCert(payload Payload) error {
	cred := m.getCred(m.myVersion)
	if cred == nil {
		m.failed = true
		return fmt.Errorf("%w: %v", ErrNoCredential, m.myVersion)
	}
	rc, err := cert.Recombine(
		cert.Version(payload.CertVersion),
		payload.Cert,
		m.hs.PeerStatic(),
		cred.Cert.Curve(),
	)
	if err != nil {
		m.failed = true
		return fmt.Errorf("recombine cert: %w", err)
	}

	if !bytes.Equal(rc.PublicKey(), m.hs.PeerStatic()) {
		m.failed = true
		return ErrPublicKeyMismatch
	}

	// Version negotiation, if the peer sent a different version and we have it, switch
	if rc.Version() != m.myVersion {
		if m.getCred(rc.Version()) != nil {
			m.myVersion = rc.Version()
		}
	}

	verified, err := m.verifier(rc)
	if err != nil {
		m.failed = true
		return fmt.Errorf("verify cert: %w", err)
	}

	m.result.RemoteCert = verified
	m.remoteCertSet = true
	return nil
```
