### Title
`DebtToken.balanceOf()` rounds user debt down and `_burn()`/`_mint()` rebase `principalOf` to the truncated value, forgiving debt dust in the user's favor - ([File: contracts/DebtToken.sol](contracts/DebtToken.sol))

### Summary
The M-3 bug class is "debt-denominated division rounds toward zero in the user's favor, so the protocol systematically under-collects debt." Metronome has the same class in `DebtToken`: the interest-bearing debt balance is computed as `(_principal * _debtIndex) / debtIndexOf[account_]` with plain truncation, and both `_burn` and `_mint` write that truncated value back to `principalOf`. Each debt mutation permanently erases up to ~1 wei of accrued debt per account per token, and `sum(balanceOf)` drifts below the `totalSupply_` on which protocol interest fee is minted.

### Finding Description
`balanceOf` computes the user's current debt (principal + accrued interest) by scaling stored principal by the ratio of the current `debtIndex` to the account's snapshot `debtIndexOf[account_]`:

```solidity
// contracts/DebtToken.sol
return (_principal * _debtIndex) / debtIndexOf[account_];   // line 205 — truncates
```

`_debtIndex / debtIndexOf >= 1` (the index only grows via `_calculateInterestAccrual`, lines 559–564), so the division truncates a quantity that is strictly a debt owed to the protocol. Rounding down reduces what the user owes — the same direction of error as the Notional finding.

The rounding is then cemented into storage. In `_burn` (reached via `Pool.repay` → `DebtToken.repay`/`repayAll`, or `Pool.liquidate` → `DebtToken.burn`):

```solidity
uint256 _accountBalance = balanceOf(account_);          // truncated value
principalOf[account_] = _accountBalance - amount_;      // line 532 — rebase loses the fractional debt
debtIndexOf[account_] = debtIndex;
```

and symmetrically in `_mint` (reached via `DebtToken.issue` and `DebtToken.mint`):

```solidity
uint256 _balanceBefore = balanceOf(account_);           // truncated value
principalOf[account_] = _balanceBefore + amount_;       // line 593
```

Every call to `issue`, `repay`, `repayAll`, or `liquidate` snapshots `principalOf` at the truncated balance, so the sub-wei remainder is permanently forgiven rather than carried forward. Meanwhile `totalSupply_` is updated by exact `amount_` values (lines 534, 590), so `totalSupply()` — which also accrues interest and is the basis for minting `pendingInterestFee` to `pool.feeCollector()` (line 174) — exceeds `sum(balanceOf)` by up to `N` wei across `N` debtor accounts per token.

### Impact Explanation
- Users repay slightly less than their true accrued debt on every repayment/liquidation; positions appear marginally healthier in `Pool.debtPositionOf`/`debtOf` which read `balanceOf`.
- The protocol mints interest fees against `totalSupply_` that is never fully collectible from the rounded-down `balanceOf` values — a persistent, accumulative solvency/under-collateralization leak, identical in nature (dust-level but additive) to the accepted M-3 finding.
- The truncation is repeatable and user-favorable: any unprivileged account holding debt triggers it through public `repay`/`issue`/`repayAll` paths; no privileged role needed.

### Likelihood Explanation
Triggering requires only that `debtIndex != debtIndexOf[account_]` (i.e., interest accrued since the user's last mint/burn) and a non-exact division — true for essentially every debt position once any time passes with `interestRate > 0`. The loss per operation is bounded by <1 wei of synthetic token per account per write, so it is a dust-scale, cumulative leak rather than a discrete theft — matching the original finding's severity profile. It cannot be amplified profitably per-transaction since each truncation is <1 wei and costs gas, but it is deterministic and accrues against the protocol at scale across all users and all debt tokens.

### Recommendation
Round debt balances up (in favor of the protocol) so truncated remainders remain collectible. For example, in `balanceOf` use ceiling division:

```solidity
uint256 _scaled = _principal * _debtIndex;
uint256 _index = debtIndexOf[account_];
return _scaled / _index + (_scaled % _index == 0 ? 0 : 1);
```

Note a subtlety: if `balanceOf` rounds up while `_burn` still debits `amount_` exactly, a user repaying `balanceOf` would hit `BurnAmountExceedsBalance`-style edge cases less often but `principalOf` could underflow conceptually — the safer complete fix is to keep `principalOf` as the exact ray-scaled debt share (store `_principal / debtIndex` or the raw scaled product) rather than rebasing it to the rounded balance on every write, mirroring Aave's scaled-balance model. Alternatively accept the truncation but document that dust debt is forgiven by design.

### Proof of Concept
Foundry-style sketch against the deployed `DebtToken` semantics (mock `pool`/`syntheticToken`/`masterOracle` or fork a deployment where a pool exists):

```solidity
// SPDX-License-Identifier: MIT
pragma solidity 0.8.24;
import "forge-std/Test.sol";

// Harness reproducing DebtToken's accounting
contract DebtMath is Test {
    uint256 debtIndex = 1e18;
    mapping(address => uint256) principalOf;
    mapping(address => uint256) debtIndexOf;
    uint256 totalSupply_;
    uint256 lastTimestampAccrued = block.timestamp;
    uint256 interestRate = 1e17; // 10% APR

    function _calc() internal view returns (uint256 interest, uint256 idx) {
        idx = debtIndex;
        uint256 ratePerSec = interestRate / 365 days;
        uint256 dt = block.timestamp - lastTimestampAccrued;
        uint256 r = ratePerSec * dt;
        if (r > 0) {
            interest = (r * totalSupply_) / 1e18;
            idx += (r * idx) / 1e18;
        }
    }

    function balanceOf(address a) public view returns (uint256) {
        uint256 p = principalOf[a];
        if (p == 0) return 0;
        (, uint256 idx) = _calc();
        return (p * idx) / debtIndexOf[a];      // current code: truncates
    }

    function _mint(address a, uint256 amt) internal {
        uint256 before_ = balanceOf(a);
        totalSupply_ += amt;
        principalOf[a] = before_ + amt;          // rebases to truncated balance
        debtIndexOf[a] = debtIndex;
    }

    function _burn(address a, uint256 amt) internal {
        uint256 bal = balanceOf(a);
        principalOf[a] = bal - amt;              // rebases to truncated balance
        debtIndexOf[a] = debtIndex;
        totalSupply_ -= amt;
    }

    function testTruncationForgivesDust() public {
        address bob = address(0xB0B);
        _mint(bob, 999);                         // odd amount so division has remainder
        debtIndexOf[bob] = debtIndex;
        vm.warp(block.timestamp + 365 days);     // index grows ~10%
        uint256 idx;
        { (, idx) = _calc(); }
        // true debt = 999 * idx / 1e18, which has a fractional remainder
        uint256 reported = balanceOf(bob);
        uint256 exact = (999 * idx + debtIndexOf[bob] - 1) / debtIndexOf[bob];
        assertLt(reported, exact);               // user owes less than exact debt
        _burn(bob, reported);
        assertEq(principalOf[bob], 0);           // remainder permanently forgiven
        // and totalSupply_ > sum(balanceOf) drift: interest minted to feeCollector
        // on totalSupply_ is never collectible from users
    }
}
```

Run: `forge test -vvv`. `balanceOf` returns a truncated value strictly below the exact (ceiling) debt, and after `repayAll`-equivalent `_burn` the dust is erased from `principalOf` while `totalSupply_` continues accruing protocol fee interest on the phantom remainder.
