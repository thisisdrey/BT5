### Title
SSRF and stderr/error-message secret leak via unauthenticated-URL fetch in CreateRepositoryFromSnapshot - (File: internal/gitaly/service/repository/create_repository_from_snapshot.go)

### Finding Description
`(*server).untar` builds an HTTP GET request directly from `in.GetHttpUrl()` and attaches `in.GetHttpAuth()` as the raw `Authorization` header with no allow-list, no restriction on scheme/host, and no check against loopback/link-local/metadata address ranges [1](#0-0) . The optional `ResolvedAddress` field, when supplied, is only validated to be a syntactically valid IP via `net.ParseIP` — no check excludes private, loopback, or link-local ranges such as `169.254.169.254` — and is used verbatim to dial the connection, explicitly to defeat DNS-based protections (comment says this is meant to avoid DNS rebinding, not SSRF containment) [2](#0-1) . The response body is piped directly into `tar -C path -xvf -` as stdin without any content-type/magic validation [3](#0-2) . The code comment itself acknowledges this is unhardened: "The received archive is trusted *a lot*... it should undergo a lot of hardening" [4](#0-3) .

However, on the exfiltration side, `tar`'s failure is only surfaced as `cmd.Wait()`'s error, wrapped as `structerr.NewInternal("extracting snapshot: %w", err)` [5](#0-4) [6](#0-5) . `command.Wait()`/exec errors in Gitaly's `command` package typically report only the exit status/short diagnostic (e.g. `exit status 2`), not the process's stdout/stderr content, and `tar`'s own stderr (from `-v`) is not captured into the returned error at all in this code — stdout/stderr of the subprocess are not wired to anything that gets echoed back to the RPC caller. So if the fetched content isn't a valid tar, tar fails and the caller learns only that extraction failed, not what bytes were fetched.

The more concrete "leak" path is different: if the attacker-controlled/targeted internal endpoint (e.g., a cloud metadata service) responds with content that `tar` can partially interpret as a valid archive (or the attacker controls a server designed to wrap secret bytes inside a valid tar structure — which requires them to already possess and format the secret, defeating the "extract secret via SSRF" premise), the extracted files become part of the newly created repository, which the attacker already owns and can read via normal repo access. That is a real "read what you fetched" primitive, but it depends entirely on the response being a well-formed tar archive controlled/known ahead of time — it does not extract or leak an *unknown* secret from an internal metadata endpoint, because arbitrary JSON/text metadata responses are not valid tar files and extraction will simply fail with a generic error.

### Impact Explanation
The genuine, demonstrable impact is SSRF: an attacker can make the Gitaly server issue an authenticated (attacker-supplied bearer/basic auth header) HTTP GET to an arbitrary internal address, including cloud metadata IPs, with no allow-list check on `HttpUrl` or the optional `ResolvedAddress`. This can be used to probe internal network reachability (via status codes/timeouts/connection errors returned in the structerr) and, if the target happens to return valid tar content, materialize that content into a repository the attacker controls. It does not, however, reliably exfiltrate arbitrary internal secrets through the tar/stderr path, because non-tar responses cause extraction to fail and only a generic "extracting snapshot" error is returned — raw response bytes are not echoed back in the RPC error text based on the code path shown.

### Likelihood Explanation
Reachability of this RPC by an unprivileged GitLab user, and whether GitLab Rails restricts/pre-validates `HttpUrl`/`HttpAuth` before calling Gitaly, could not be confirmed from within this repository — `CreateRepositoryFromSnapshot` is a Gitaly-side RPC and its actual exposure to end users (versus admin/import-only internal tooling) is determined by GitLab Rails, which is out of scope for this audit and not present in this repo's index. Within Gitaly itself, there is no SSRF allow-list at all, so if this RPC is reachable with attacker-controlled `HttpUrl`/`ResolvedAddress`, the SSRF surface described is real and unmitigated at the Gitaly layer.

### Recommendation
- Enforce an allow-list/deny-list on `HttpUrl` host resolution and any caller-supplied `ResolvedAddress`, rejecting loopback, link-local (169.254.0.0/16, fe80::/10), and RFC1918 ranges unless explicitly permitted by configuration.
- Validate that response content is a well-formed tar prior to piping to the `tar` subprocess, or use a Go tar reader library instead of shelling out, to avoid trusting arbitrary bytes as archive input.
- Confirm at the GitLab Rails layer that `CreateRepositoryFromSnapshot` is never reachable with user-controlled `HttpUrl`/`HttpAuth` for unprivileged import/fork flows; if it must be, add the SSRF containment described above in Gitaly since it is the last line of defense.

// newResolvedHTTPClient is a modified version of the httpClient variable but here we resolve the
// URL to predefined IP:PORT. This is to avoid DNS rebinding.
func newResolvedHTTPClient(httpAddress, resolvedAddress string) (*http.Client, error) {
	url, err := url.ParseRequestURI(httpAddress)
	if err != nil {
		return nil, structerr.NewInvalidArgument("parsing HTTP URL: %w", err)
	}

	port := url.Port()
	if port == "" {
		switch url.Scheme {
		case "http":
			port = "80"
		case "https":
			port = "443"
		default:
			return nil, structerr.NewInvalidArgument("unsupported schema %q", url.Scheme)
		}
	}

	// Sanity-check whether the resolved address is a valid IP address.
	if net.ParseIP(resolvedAddress) == nil {
		return nil, structerr.NewInvalidArgument("invalid resolved address %q", resolvedAddress)
	}

	transport := httpTransport.Clone()
	transport.DialContext = func(ctx context.Context, network, _ string) (net.Conn, error) {
		return httpTransport.DialContext(ctx, network, fmt.Sprintf("%s:%s", resolvedAddress, port))
	}

	return &http.Client{
		Transport: correlation.NewInstrumentedRoundTripper(otelhttp.NewTransport(transport)),
		// Here we directly return the `ErrUseLastResponse` to prevent redirects
		CheckRedirect: func(*http.Request, []*http.Request) error {
			return http.ErrUseLastResponse
		},
	}, nil
}

func (s *server) untar(ctx context.Context, path string, in *gitalypb.CreateRepositoryFromSnapshotRequest) error {
	req, err := http.NewRequestWithContext(ctx, "GET", in.GetHttpUrl(), nil)
	if err != nil {
		return structerr.NewInvalidArgument("Bad HTTP URL: %w", err)
	}

	client := httpClient
	if resolvedAddress := in.GetResolvedAddress(); resolvedAddress != "" {
		client, err = newResolvedHTTPClient(in.GetHttpUrl(), resolvedAddress)
		if err != nil {
			return structerr.NewInvalidArgument("creating resolved HTTP client: %w", err)
		}
	}

	if in.GetHttpAuth() != "" {
		req.Header.Set("Authorization", in.GetHttpAuth())
	}
