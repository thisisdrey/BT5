Audit Report

## Title
Unbounded-slippage swap in `SwapFirstAssetTrader::refund_weight` allows XCM fee refunds to be silently under-delivered — (File: `cumulus/primitives/utility/src/lib.rs`)

## Summary
`SwapFirstAssetTrader` is a `WeightTrader` that lets XCM users pay fees in a non-`Target` fungible asset by swapping it via `pallet_asset_conversion::SwapCredit` into the chain's `Target` asset. When unused weight is refunded, `refund_weight` swaps surplus `Target` credit back into the user's original asset by calling `SwapCredit::swap_exact_tokens_for_tokens(vec![Target::get(), refund_swap_asset], refund, None)` [1](#0-0) , passing `None` for `amount_out_min` and thus enforcing no floor on the amount returned to the user.

## Finding Description
`SwapCredit::swap_exact_tokens_for_tokens` explicitly supports an `Option<Balance>` `amount_out_min` for slippage protection [2](#0-1) , and the pallet's implementation only enforces the minimum when it is `Some`: `ensure!(amount_out_min.map_or(true, |a| amount_out >= a), ...)` [3](#0-2) . `SwapFirstAssetTrader::refund_weight` passes `None`, so this check is a no-op and whatever `amount_out` the pool produces at that instant is accepted unconditionally [4](#0-3) . This contrasts with `buy_weight` in the same struct, which uses `swap_tokens_for_exact_tokens` with an exact target `fee` amount, and with `SingleAssetExchangeAdapter::exchange_asset`, which supplies a concrete `Some(want_amount)` minimum for the analogous XCM `ExchangeAsset` path [5](#0-4) . No other check in `refund_weight` or its call site inspects the resulting refunded amount against an expectation before it is wrapped into `AssetsInHolding` and returned to the XCM originator.

## Impact Explanation
This breaks the value-conservation guarantee for cross-chain fee handling: any XCM message overpaying fees in a non-`Target` asset that triggers a refund is exposed to unconstrained AMM slippage on the reverse swap, so the beneficiary can receive an amount far below the fair-value refund with no error and no floor enforced. `SwapFirstAssetTrader` is a general-purpose utility shipped in `cumulus/primitives/utility`, so this affects any parachain runtime wiring it up as its `WeightTrader`.

## Likelihood Explanation
The vulnerable path executes automatically whenever unused weight remains after `buy_weight`, which is the common case for any XCM message with a generous `BuyExecution` weight limit — no privileged actor or governance action is required. An unprivileged actor can further reduce the payout by performing ordinary, publicly permitted swaps against the same `Target`/`refund_swap_asset` pool immediately prior to the refund swap within the same block, since execution ordering within a block is deterministic.

## Recommendation
Pass an explicit `Some(minimum_acceptable_amount)` into the reverse swap in `refund_weight`, derived the same way `buy_weight` bounds its swap (e.g., via `QuotePrice::quote_price_exact_tokens_for_tokens` computed before swapping). If the swap cannot meet that minimum, retain the refund in the `Target` asset or skip the refund rather than accepting an unconstrained AMM output.

## Proof of Concept
1. Configure a `Target`/`AssetA` pool in `pallet_asset_conversion` with shallow liquidity.
2. Send an XCM message with `BuyExecution { fees: (AssetA, large_amount), weight_limit }` where declared weight substantially exceeds actual consumed weight.
3. `SwapFirstAssetTrader::buy_weight` swaps `AssetA` into `Target` to cover `fee = WeightToFee::weight_to_fee(&weight)`.
4. After the short program executes, `refund_weight` is invoked for the unused weight, calling `SwapCredit::swap_exact_tokens_for_tokens(vec![Target, AssetA], refund, None)`.
5. Prior to this refund swap (same block, deterministic ordering), drain/skew the `Target`/`AssetA` pool via other permitted public swaps.
6. Observe the XCM originator receives an `AssetA` refund far below `WeightToFee::weight_to_fee(&weight)` worth, with no error, confirming the unbounded `None` `amount_out_min` allows silent value loss. This can be adapted from the existing test harness in `cumulus/primitives/utility/src/tests/swap_first.rs` (e.g. `buy_and_refund_twice_for_target`) by making the mock `Swap::swap_exact_tokens_for_tokens` model AMM-curve slippage instead of a fixed 1:1 rate.
