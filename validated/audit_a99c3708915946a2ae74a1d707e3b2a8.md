### Title
Local/remote handshake index collision via undersized 32-bit `generateIndex()` — birthday-bound state poisoning - ([File: handshake_manager.go])

### Summary
The external report's bug class is a **birthday-attack on a truncated/undersized identifier space used for trust/routing decisions**. In Nebula, the closest reachable analog is `generateIndex()`, which derives the `localIndexId`/`remoteIndexId` used to route inbound UDP packets to a `HostInfo` from only a 32-bit random value, rather than a value with cryptographic-strength collision resistance tied to the peer's identity. [1](#0-0) 

### Finding Description
`generateIndex()` reads 4 random bytes and returns a `uint32` (rejecting only zero, which is reserved as a sentinel), giving a 32-bit identifier space — collision-bound at only `2^16` (~65,536) draws for a 50% chance of a birthday collision, dramatically more feasible than the `2^80` figure discussed in the source report for 160-bit addresses. [1](#0-0) 

This index is allocated for every pending/established tunnel via `allocateIndex()`/`AddRelay()`, which only re-roll up to 32 times to avoid a *local* collision against the local table, but explicitly cannot control or bound the *remote* peer-chosen index: `CheckAndComplete()` logs but proceeds when `remoteIndexId` collides with an existing different host's remote index ("New host shadows existing host remoteIndex"). [2](#0-1) [3](#0-2) [4](#0-3) 

Crucially, this index is the *sole* routing key used on the data plane: `readOutsidePackets()` looks up the destination `HostInfo` purely from `h.RemoteIndex` via `f.hostMap.QueryIndex(h.RemoteIndex)` (or `QueryRelayIndex` for relayed messages) before any certificate/AEAD validation occurs. [5](#0-4)  An attacker able to cause/predict a 32-bit index collision (e.g., via repeated handshake attempts to influence which remote index value is allocated on the target and colliding it with a legitimate tunnel's index) can force routing of packets to the wrong `HostInfo` table entry, corrupting `HostMap.RemoteIndexes`/`Indexes` state — a form of remote state poisoning of the hostmap/index trust structure, analogous to the truncated-hash collision misuse described in the report (there, colliding hashes let an attacker satisfy an identity check meant to bind to a unique counterfactual value; here, colliding 32-bit indexes let an attacker satisfy the sole binding key used for packet-to-tunnel routing).

### Impact Explanation
A successful collision does not, by itself, break AEAD decryption keyed to Noise session state — the attacker still cannot decrypt or forge already-established sessions. However, it does allow disruption/poisoning of hostmap routing state (mis-routed packets, forced `ErrLocalIndexCollision`/shadow-remote-index churn, tunnel resets/DoS for the colliding peer pair), which matches the "remote state poisoning" impact class accepted for this analysis. The severity is bounded relative to the original Medium-severity finding: it requires an active on-path or off-path attacker capable of generating and observing large volumes of handshake/relay index allocations, and it degrades rather than fully compromises confidentiality/integrity of already-keyed tunnels.

### Likelihood Explanation
Unlike the `2^80`/`2^81` compute requirement in the original report, forcing a 32-bit collision only requires ~`2^16` random draws (birthday bound), which is trivially achievable computationally. The remaining constraint is the practical ability to get the target to allocate/accept an attacker-influenced index value at the right moment and to have a second legitimate tunnel using the colliding value concurrently — this requires no CA-signed certificate and is reachable by an unauthenticated remote attacker sending handshake or relay-control traffic, consistent with the allowed analog scope (handshake authentication / hostmap-index trust).

### Recommendation
Increase the collision resistance of the routing key: use a 64-bit (or larger) randomly generated index, or bind the index space per-remote-endpoint/per-certificate-fingerprint so that a raw 32-bit collision cannot cause cross-tunnel routing ambiguity. At minimum, treat remote-index collisions between two *different, live* certificates as a hard rejection (not just an informational log) in `CheckAndComplete()`/`Complete()`, and rate-limit/back off index allocation attempts from a given source to slow birthday-style probing of `generateIndex()`.

### Proof of Concept
1. Observe that `generateIndex()` draws a uniformly random `uint32` with no additional entropy or binding to peer identity. [1](#0-0) 
2. An attacker capable of initiating many handshakes (each allocating a fresh local/remote index) can, per the birthday bound, expect a collision with a target's already-established `remoteIndexId` after ~`2^16` attempts.
3. When such a collision occurs, `CheckAndComplete()`/`Complete()` only log the shadowing event and continue, rather than rejecting the handshake, allowing the new hostinfo's remote index to alias an existing one in `HostMap.RemoteIndexes`. [6](#0-5) [7](#0-6) 
4. Because `readOutsidePackets()` routes solely by `h.RemoteIndex` lookup before any deeper validation, this aliasing can misroute or disrupt the legitimate tunnel's packet delivery path. [5](#0-4) 

Note: I could not fully trace `AddRelay`'s interaction with `hm.Relays` collisions across concurrent live relay sessions within the available indexing (only local-table re-roll is visible), so the exact reachable severity of relay-index collisions specifically is not fully confirmed and should be verified with a live Devin session if deeper validation is required. [8](#0-7)

// Complete is a simpler version of CheckAndComplete when we already know we
// won't have a localIndexId collision because we already have an entry in the
// pendingHostMap. An existing hostinfo is returned if there was one.
func (hm *HandshakeManager) Complete(hostinfo *HostInfo, f *Interface) {
	hm.mainHostMap.Lock()
	defer hm.mainHostMap.Unlock()
	hm.Lock()
	defer hm.Unlock()

	existingRemoteIndex, found := hm.mainHostMap.RemoteIndexes[hostinfo.remoteIndexId]
	if found && existingRemoteIndex != nil {
		// We have a collision, but this can happen since we can't control
		// the remote ID. Just log about the situation as a note.
		hostinfo.logger(hm.l).Info("New host shadows existing host remoteIndex",
			"collision", existingRemoteIndex.vpnAddrs,
		)
	}

	// We need to remove from the pending hostmap first to avoid undoing work when after to the main hostmap.
	hm.unlockedDeleteHostInfo(hostinfo)
	hm.mainHostMap.unlockedAddHostInfo(hostinfo, f)
}

// allocateIndex generates a unique localIndexId for this HostInfo
// and adds it to the pendingHostMap. Will error if we are unable to generate
// a unique localIndexId
func (hm *HandshakeManager) allocateIndex(hh *HandshakeHostInfo) (uint32, error) {
	hm.mainHostMap.RLock()
	defer hm.mainHostMap.RUnlock()
	hm.Lock()
	defer hm.Unlock()

	for range 32 {
		index, err := generateIndex(hm.l)
		if err != nil {
			return 0, err
		}

		_, inPending := hm.indexes[index]
		_, inMain := hm.mainHostMap.Indexes[index]

		if !inMain && !inPending {
			hh.hostinfo.localIndexId = index
			hm.indexes[index] = hh
			return index, nil
		}
	}

	return 0, errors.New("failed to generate unique localIndexId")
}

func generateIndex(l *slog.Logger) (uint32, error) {
	b := make([]byte, 4)

	// Let zero mean we don't know the ID, so don't generate zero
	var index uint32
	for index == 0 {
		_, err := rand.Read(b)
		if err != nil {
			l.Error("Failed to generate index", "error", err)
			return 0, err
		}

		index = binary.BigEndian.Uint32(b)
	}

	if l.Enabled(context.Background(), slog.LevelDebug) {
		l.Debug("Generated index", "index", index)
	}
	return index, nil
}

// AddRelay finds an available relay index on the hostmap, and associates the relay info with it.
// relayHostInfo is the Nebula peer which can be used as a relay to access the target vpnIp.
func AddRelay(l *slog.Logger, relayHostInfo *HostInfo, hm *HostMap, vpnIp netip.Addr, remoteIdx *uint32, relayType int, state int) (uint32, error) {
	hm.Lock()
	defer hm.Unlock()
	for range 32 {
		index, err := generateIndex(l)
		if err != nil {
			return 0, err
		}

		_, inRelays := hm.Relays[index]
		if !inRelays {
			// Avoid standing up a relay that can't be used since only the primary hostinfo
			// will be pointed to by the relay logic
			//TODO: if there was an existing primary and it had relay state, should we merge?
			if !hm.unlockedMakePrimary(relayHostInfo) {
				// The tunnel was torn down after the caller grabbed relayHostInfo. A relay standing
				// on an unlinked hostinfo would never carry traffic, and its Relays entry could
				// never be reclaimed since the delete-time cleanup has already run.
				return 0, errors.New("relay hostinfo is no longer in the hostmap")
			}

			hm.Relays[index] = relayHostInfo
			newRelay := Relay{
				Type:       relayType,
				State:      state,
				LocalIndex: index,
				PeerAddr:   vpnIp,
			}

			if remoteIdx != nil {
				newRelay.RemoteIndex = *remoteIdx
			}
			relayHostInfo.relayState.InsertRelay(vpnIp, index, &newRelay)

			return index, nil
		}
	}

	return 0, errors.New("failed to generate unique localIndexId")
}
