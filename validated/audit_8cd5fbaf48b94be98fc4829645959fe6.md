### Title
Unauthenticated `RecvError` packet allows remote attacker to tear down / poison in-progress tunnel state - ([File: outside.go])

### Summary
`readOutsidePackets` dispatches `header.RecvError` packets straight to `handleRecvError` before any certificate, handshake, or AEAD authentication is performed on the sender. The only anti-spoofing check inside `handleRecvError` is a comparison against the hostinfo's already-known remote `netip.AddrPort`, which is skipped entirely whenever that address is not yet valid (e.g., mid-handshake) and is otherwise defeatable by a UDP source-address spoof combined with a known/guessed `RemoteIndex` (a 32-bit value carried in cleartext in every packet header). This mirrors the report's bug class: an attacker with no legitimate credential can perform an unauthenticated state-mutating action (`ERC20Guild.setPermissionUsed()` analog) that races ahead of / disrupts the legitimate protocol flow (`endProposal()` analog), poisoning shared session state and causing the intended operation (tunnel establishment/continuity) to fail.

### Finding Description
`readOutsidePackets` handles `header.RecvError` in the "Unencrypted packets" switch, dispatching to `f.handleRecvError` immediately after header parsing — well before any hostinfo/decryption/authentication step is applied to the rest of the packet types: [1](#0-0) 

`handleRecvError` then:
1. Gates only on a config toggle (`acceptRecvErrorConfig`), not on any cryptographic proof of sender identity.
2. Looks up the hostinfo purely by the attacker-supplied `h.RemoteIndex` field via `QueryReverseIndex`.
3. Only rejects the packet if the hostinfo's remote address is *already valid* and *does not match* the sender address (`hr.IsValid() && hr != addr`). If `hr` is not yet valid — which is the normal case for a pending/mid handshake, or any tunnel whose remote hasn't been pinned — the check is bypassed entirely.
4. On success, calls `f.closeTunnel(hostinfo)` and `f.handshakeManager.DeleteHostInfo(hostinfo)`, unconditionally destroying the session/handshake state. [2](#0-1) 

`RemoteIndex` is not secret or authenticated — it is a plaintext header field present on every packet a peer sends (including handshake responses), so any attacker who has observed even one packet exchanged with the target (or who brute-forces the 32-bit index space) can construct a spoofed `RecvError` packet. Because UDP is connectionless and the initial `RecvError` dispatch happens before any per-packet authentication, this is directly analogous to the reported bug class: an unauthenticated party invoking a state-mutating operation (here, tunnel teardown / pending-handshake deletion) that races and defeats the legitimate protocol completion, exactly as the original report describes `ERC20Guild.setPermissionUsed()` racing `endProposal()` to force a `ProposalState.Failed` outcome.

### Impact Explanation
A successful spoof causes `closeTunnel` and `DeleteHostInfo` to run on a victim's legitimate hostinfo/handshake state, tearing down active tunnels or repeatedly destroying in-flight handshakes for a targeted `RemoteIndex`. Because the "already established" anti-spoof check is bypassable whenever the remote's `netip.AddrPort` hasn't been pinned yet (mid-handshake), an attacker can specifically target hosts that are actively (re)establishing tunnels — directly poisoning that state and preventing the legitimate handshake/session from ever completing successfully, a remote denial-of-service / state-poisoning impact reachable without any CA-signed certificate.

### Likelihood Explanation
Exploitability depends on two factors that are both attacker-feasible: (1) learning a target's current `RemoteIndex`, which is transmitted unauthenticated and in cleartext on every packet (observable via any vantage point that sees traffic, or brute-forceable at low cost given only 32 bits and no rate limiting evident in `handleRecvError`), and (2) UDP source-address spoofing, which is possible on many networks that don't enforce BCP38/source validation, and is entirely unnecessary when the target hostinfo's remote address is not yet pinned (`hr.IsValid()` false). This makes the mid-handshake case realistically exploitable by a purely off-path, uncertificated attacker.

### Recommendation
Do not act on `RecvError` (or any state-destructive control packet) without cryptographic authentication tied to the specific tunnel/session, e.g., require the packet to be authenticated under the session's established AEAD key/counter (as is already done for `Message`/`Test`/`CloseTunnel` types), or otherwise strongly bind acceptance to a fresh nonce/challenge rather than solely to a plaintext index and an address comparison that can be trivially bypassed pre-handshake. At minimum, always enforce the address-match check regardless of whether `hr.IsValid()`, and rate-limit/back off repeated `RecvError` deletions per index to blunt brute force.

### Proof of Concept
1. Attacker observes or brute-forces a valid `RemoteIndex` value used by a host that is establishing (or re-establishing) a tunnel — feasible because the field is unauthenticated/cleartext, and the bypass check in `handleRecvError` doesn't apply while `hr` (remote address) is not yet valid: [3](#0-2) 
2. Attacker crafts a minimal UDP packet with `header.Version`, `Type = header.RecvError`, `RemoteIndex = <observed index>`, and sends it (optionally spoofing the victim's known peer's source address) to the target node's listen port.
3. `readOutsidePackets` routes it directly to `handleRecvError` without any decryption/authentication: [4](#0-3) 
4. `handleRecvError` finds the corresponding hostinfo via `QueryReverseIndex`, passes the (bypassable) address check, and calls `f.closeTunnel(hostinfo)` plus `f.handshakeManager.DeleteHostInfo(hostinfo)`, destroying the legitimate session/handshake state that the victim was trying to establish — analogous to the original report's frontrunning of `endProposal()` via unauthenticated `setPermissionUsed()` calls.

func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
