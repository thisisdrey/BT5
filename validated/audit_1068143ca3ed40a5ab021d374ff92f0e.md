### Title
Unbounded prefix scan in `DelegatedResourceAccountIndexStore.getWithPrefix` allows a single account to DoS the delegated-resource-index query APIs - (File: chainbase/src/main/java/org/tron/core/store/DelegatedResourceAccountIndexStore.java)

### Summary
`DelegatedResourceAccountIndexStore.getIndex`/`getV2Index` build a delegated-resource index by calling `getWithPrefix`, which performs a `prefixQuery` over all delegation records for the queried address and then sorts the full result set in memory. There is no limit on how many distinct delegation records a single account can accumulate, so a caller can grow this per-address dataset arbitrarily by issuing many cheap `DelegateResourceContract` transactions, and then any client of the public query APIs that resolve this index pays the full unbounded cost.

### Finding Description
`getWithPrefix` fetches every stored entry that matches `prefix + address` via `prefixQuery`, materializes it into an `ArrayList`, sorts it by timestamp, and maps it to a list of accounts — for both the "to" and "from" directions: [1](#0-0) 

This is invoked by `getIndex`/`getV2Index`, which are directly reachable from `Wallet.getDelegatedResourceAccountIndex` and `Wallet.getDelegatedResourceAccountIndexV2`: [2](#0-1) 

Those `Wallet` methods are exposed unauthenticated over HTTP (`GetDelegatedResourceAccountIndexServlet`, `GetDelegatedResourceAccountIndexV2Servlet`) and gRPC (`RpcApiService.getDelegatedResourceAccountIndex`/`V2`, and mirrored on the Solidity/PBFT interfaces): [3](#0-2) [4](#0-3) 

The number of records that can accumulate for a single address is unbounded: `DelegateResourceActuator.validate()` only requires `delegateBalance >= 1 TRX` and that owner/receiver differ and receiver exists — it never limits the count of distinct receiver addresses an owner can delegate to (or vice versa): [5](#0-4) 

Each successful delegation writes a new keyed record via `delegateV2`, which is exactly what `getWithPrefix`'s `prefixQuery` later has to scan and sort: [6](#0-5) [7](#0-6) 

An attacker only needs enough frozen V2 bandwidth/energy balance (1 TRX minimum per call, reusable across many distinct receiver addresses they control) to build up an arbitrarily large `from`/`to` index for their own address, then any external caller (or the frontend/monitoring tooling) querying that address's delegated-resource index pays for the full unbounded `prefixQuery` + sort on every request.

### Impact Explanation
Because the query cost (`prefixQuery` + `ArrayList` construction + full sort) grows linearly (and with sort, super-linearly) with the number of delegation records for the queried address, and that record count is fully attacker-controlled and unbounded, a malicious account can force expensive scans on the full node whenever the index is queried via HTTP, gRPC, or the Solidity/PBFT interfaces. This can degrade or exhaust node resources on the query path, denying that API to legitimate integrators and dashboards relying on `getdelegatedresourceaccountindex(v2)` — matching the "API the node can no longer serve" impact class.

### Likelihood Explanation
Reachable by any unprivileged account: it only requires normal `FreezeBalanceV2Contract`/`DelegateResourceContract` transactions (no special permission, no validator/witness role) to create many delegation entries, and the query endpoint itself is unauthenticated and requires no fee. The attack is entirely self-contained (attacker delegates from/to addresses they control) and does not depend on any other party's cooperation.

### Recommendation
Cap the number of distinct delegation records tracked per address (e.g., limit unique `to`/`from` accounts in `DelegateResourceActuator.validate()`), or change `getWithPrefix`/`getIndex`/`getV2Index` to support paginated/limited retrieval instead of loading and sorting the entire prefix-matched set in one unbounded call, and enforce that limit consistently on the write path (`delegateV2`) as well as the read path.

### Proof of Concept
1. Attacker controls address `A` (owner) with sufficient TRX frozen as V2 bandwidth/energy, and creates `N` receiver accounts `R1..RN` (or reuses `A` as receiver of `N` different delegators).
2. For each `Ri`, submit a `DelegateResourceContract` from `A` to `Ri` with `balance = 1 TRX` — `DelegateResourceActuator.validate()`/`execute()` accepts each of these with no cap on `N`, each writing new `V2_FROM_PREFIX`/`V2_TO_PREFIX` entries via `delegateV2`.
3. After accumulating a large `N` (e.g., tens of thousands), call the public API `/wallet/getdelegatedresourceaccountindexv2` (or the gRPC equivalent) with `value = A`.
4. `Wallet.getDelegatedResourceAccountIndexV2` → `DelegatedResourceAccountIndexStore.getV2Index` → `getWithPrefix` performs a `prefixQuery` over all `N` entries and sorts them in memory on every single request, consuming CPU/memory proportional to `N` and degrading the node's ability to serve this and possibly other queries.

  private DelegatedResourceAccountIndexCapsule getWithPrefix(byte[] fromPrefix, byte[] toPrefix, byte[] address) {
    DelegatedResourceAccountIndexCapsule tmpIndexCapsule =
        new DelegatedResourceAccountIndexCapsule(ByteString.copyFrom(address));

    byte[] key = Bytes.concat(fromPrefix, address);
    List<DelegatedResourceAccountIndexCapsule> tmpToList =
        new ArrayList<>(this.prefixQuery(key).values());
    tmpToList.sort(Comparator.comparing(DelegatedResourceAccountIndexCapsule::getTimestamp));
    List<ByteString> list = tmpToList.stream()
        .map(DelegatedResourceAccountIndexCapsule::getAccount).collect(Collectors.toList());
    tmpIndexCapsule.setAllToAccounts(list);

    key = Bytes.concat(toPrefix, address);
    List<DelegatedResourceAccountIndexCapsule> tmpFromList =
        new ArrayList<>(this.prefixQuery(key).values());
    tmpFromList.sort(Comparator.comparing(DelegatedResourceAccountIndexCapsule::getTimestamp));
    list = tmpFromList.stream().map(DelegatedResourceAccountIndexCapsule::getAccount).collect(
        Collectors.toList());
    tmpIndexCapsule.setAllFromAccounts(list);
    return tmpIndexCapsule;

    if (address == null || address.size() != DecodeUtil.ADDRESS_SIZE / 2) {
      return DelegatedResourceAccountIndex.getDefaultInstance();
    }
    DelegatedResourceAccountIndexCapsule accountIndexCapsule =
        chainBaseManager.getDelegatedResourceAccountIndexStore().getIndex(address.toByteArray());
    if (accountIndexCapsule != null) {
      return accountIndexCapsule.getInstance();
    } else {
      return DelegatedResourceAccountIndex.getDefaultInstance();
    }
  }
