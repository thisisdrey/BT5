Audit Report

## Title
Per-recipient staking reward transfer failures are silently swallowed, permanently losing nominator/validator payouts while the era page is marked as paid - (File: `substrate/frame/staking-async/src/pallet/impls.rs`)

## Summary
In `pallet-staking-async`, `do_payout_stakers_by_page` marks a given era/validator/page as claimed via `Eras::<T>::set_rewards_as_claimed(era, &stash, page)` before running the actual per-recipient payout loop. Inside that loop, `make_payout_from_provider` performs `T::Currency::transfer` from the era's `staker_rewards_pot` to the resolved payout account, and if that transfer returns `Err`, the error is only logged and `None` is returned, causing the caller to silently skip that recipient with no retry and no compensating state change.

## Finding Description
`do_payout_stakers_by_page` first validates the page hasn't been claimed and then unconditionally marks it claimed: [1](#0-0) 

Only after this irreversible claimed-marker is set does the function compute reward shares and call `payout_from_provider` (or the legacy mint path): [2](#0-1) 

`payout_from_provider` iterates the validator and each nominator, calling `make_payout_from_provider` for each and treating a `None` result (whether from a zero reward or a transfer failure) identically — simply skip, no event, continue: [3](#0-2) 

`make_payout_from_provider` performs the actual transfer and, on failure, only logs and returns `None`, discarding the error entirely: [4](#0-3) 

Because `Eras::<T>::set_rewards_as_claimed` was already invoked before this loop runs (line 386), and there is no un-claim or retry mechanism, a `payout_stakers`/`payout_stakers_by_page` call that hits a transfer failure for any nominator (or the validator itself) will: (a) return `Ok(...)` for the whole extrinsic, (b) leave the page permanently marked claimed, and (c) leave the reward amount stuck in `staker_rewards_pot` with no code path back to the affected stash. Re-invoking payout for the same era/page/stash is rejected by the `is_rewards_claimed` check at line 381, so the loss is permanent.

## Impact Explanation
This is a real value-conservation violation: staking reward payouts must settle exactly once to the rightful beneficiary, but on transfer failure the funds settle to nobody while the runtime records the page as fully paid, permanently locking the affected recipient's share in the era reward pot. This matches the accepted impact class of permanent user-fund lock / broken payout settlement, reachable via the public, unprivileged `payout_stakers`/`payout_stakers_by_page` extrinsics.

## Likelihood Explanation
No privileged actor is needed — `payout_stakers`/`payout_stakers_by_page` are callable by any signed account. `T::Currency::transfer` with `Preservation::Expendable` can fail under conditions such as the destination account lacking provider references needed to accept an incoming balance, or other fallible currency/consumer-reference states; the code's own explicit error-logging branch shows this failure mode is anticipated by the implementers, not a purely theoretical edge case.

## Recommendation
Do not call `Eras::<T>::set_rewards_as_claimed` unconditionally before payouts; instead, either propagate transfer failures so the whole page-claim is not committed (allowing retry), or record any transfer failure into a dedicated pending/unclaimed-reward storage entry keyed by (era, stash, page) that can later be retried or manually resolved, ensuring the claimed-page state and the actual balance movement never diverge.

## Proof of Concept
1. Set up a nominator whose `RewardDestination::Account` payout account is in a state where an incoming `Preservation::Expendable` transfer from the pot fails (e.g., the account cannot accept the increment under the runtime's provider/consumer-reference rules).
2. Call `payout_stakers`/`payout_stakers_by_page` for the era/validator/page containing this nominator as any unprivileged signed account.
3. Observe: the extrinsic returns `Ok`, `Eras::<T>::set_rewards_as_claimed` has already flagged the page as claimed (`substrate/frame/staking-async/src/pallet/impls.rs:386`), no `Rewarded` event is emitted for the failing nominator, and the balance is unchanged.
4. Attempt to re-call payout for the same era/page — it is rejected via the `is_rewards_claimed` check (`substrate/frame/staking-async/src/pallet/impls.rs:381`), confirming the reward is permanently unrecoverable through the normal payout flow.
