### Title
Unauthenticated `/new_block` HTTP POST forges `SignerEvent::NewBlock` into signer runloop - (File: libsigner/src/events.rs)

### Summary
`SignerEventReceiver::next_event` dispatches directly on `request.url()` without any authentication check, so anyone who can reach the signer's HTTP listener can POST to `/new_block` and inject an arbitrary `SignerEvent::NewBlock` into the signer's runloop. The sample signer config binds this listener to `0.0.0.0`, making it remotely reachable, and the only gate (`connection_options.auth_token`) is a node-side concept that is never enforced on this inbound path.

### Finding Description
`next_event` reads a raw HTTP request from `HttpServer::recv()` and dispatches purely on `request.url()` and `request.method()`, with no signature, token, or origin check anywhere in the function: [1](#0-0) 

For `/new_block`, it calls `process_event::<T, StacksBlockEvent>(request)`, which only reads the body, JSON-deserializes it into `StacksBlockEvent`, and converts it via `TryFrom` — again with no verification of origin, signature, or the `auth_token`: [2](#0-1) 

`StacksBlockEvent`'s fields (`index_block_hash`, `consensus_hash`, `block_hash`, `block_height`, `transactions`) are taken verbatim from the JSON body and mapped 1:1 into `SignerEvent::NewBlock`: [3](#0-2) 

This event is forwarded unchanged to the signer runloop via `forward_event`, and the runloop passes it straight to `Signer::process_event`, which in `handle_event_match` treats `SignerEvent::NewBlock` as ground truth that the node has processed and canonically accepted the block: it calls `local_state_machine.stacks_block_arrival(...)`, looks up the block by `signer_sighash`, and calls `block_info.mark_globally_accepted()` followed by `signer_db.insert_block(&block_info)`: [4](#0-3) 

The only authentication mechanism referenced in this codebase, `connection_options.auth_token`, is documented as securing signer→node requests (e.g. `/v3/block_proposal`, `/v2/blocks?broadcast=1`), not node→signer event delivery: [5](#0-4) 

Nothing in `libsigner/src/events.rs` reads or checks any `Authorization` header on inbound requests to the signer's event port. The sample signer binary config explicitly binds this listener on all interfaces: [6](#0-5) 

An attacker who can reach this bound port needs only to send a well-formed `POST /new_block` JSON body; there is no cryptographic or shared-secret check preventing it from being accepted as if it came from the node.

### Impact Explanation
An attacker who can reach the signer's event port can cause the signer to mark an arbitrary, attacker-chosen block (`consensus_hash`, `index_block_hash`/`block_id`) as globally accepted in the signer's local `signerdb`, and update `local_state_machine.stacks_block_arrival` state, all without any verification that the node actually processed such a block. This is an unauthenticated write to signer state driven entirely by attacker-controlled input, matching the "unauthenticated/unauthorized write to state" Critical category. It is repeatable per message and requires no privileged role — only network reachability to the bound listener.

### Likelihood Explanation
The precondition is that the signer's HTTP event-receiver port (bound per the operator's `endpoint` config, e.g. `0.0.0.0:30000` in the sample config) is reachable by the attacker. No secret, prior authentication, or StackerDB slot ownership is required to hit this endpoint or satisfy `process_event`'s only requirement (valid JSON matching `StacksBlockEvent`'s schema). This is directly reachable and repeatable with a single crafted HTTP POST per attempt.

### Recommendation
Require and verify a shared secret/bearer token (e.g. reusing `auth_token`/`auth_password`) on all inbound requests to `SignerEventReceiver`, checked in `next_event` before dispatching to `process_event`, and/or bind the listener to loopback-only by default with an explicit opt-in warning for any non-local binding.

fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}
