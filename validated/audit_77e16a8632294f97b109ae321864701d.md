## Finding

The vulnerability described is real and reachable: `TokenDiff::token_fee` exempts `Nep245`/`Imt` legs from any fee whenever the *per-intent* `amount <= 1`, and `TokenDiff::execute_intent` computes the fee independently for every intent rather than against any cumulative/aggregate transfer size. Splitting a bulk NEP-245/IMT movement into many `|delta| == 1` `TokenDiff` intents therefore drives the fee to zero for the whole batch, even though a single intent moving the same aggregate amount would pay `Pips::fee_ceil(amount)`.

### Title
Protocol fee bypass on NEP-245/IMT transfers via unit-size `TokenDiff` splitting - (File: `contracts/defuse/core/src/intents/token_diff.rs`)

### Summary
`TokenDiff::execute_intent` computes the protocol fee per intent using `Self::token_fee(token_id, delta.unsigned_abs(), protocol_fee)`, and `token_fee` returns `Pips::ZERO` for `Nep245`/`Imt` tokens whenever the per-intent `amount <= 1`. Because fee assessment never looks at an account's cumulative movement of a token across a batch, an unprivileged signer can restructure any NEP-245/IMT transfer of size `k` into `k` separate `TokenDiff` intents each moving `1` unit, causing `fees_collected` to be `0` for the entire batch instead of `Pips::fee_ceil(k)`.

### Finding Description
The broken binding: the protocol expects
`fees_collected[T] == Pips::fee_ceil(total negative movement of T by signer across the settlement)`,
but the actual implementation computes
`fees_collected[T] == Σ_i Pips::fee_ceil(|delta_i|)` per individual intent `i` [1](#0-0) .

`token_fee` special-cases `Nep245`/`Imt` (and `Nep171`) tokens: fee is only charged if `amount > 1`; otherwise `Pips::ZERO` is returned regardless of the configured protocol `fee`: [2](#0-1) .

Since this check is evaluated fresh for every `TokenDiff` intent (`amount = delta.unsigned_abs()` computed locally per intent, line 71), there is nothing preventing a signer from decomposing one `TokenDiff{T: -k, ...}` into `k` separate `TokenDiff{T: -1, ...}` intents, each of which independently satisfies `amount <= 1` and is charged `Pips::ZERO`.

The batch-level correctness check (`TransferMatcher::finalize`, invoked from `Engine::finalize`) only enforces that the *sum of all deltas per token across the whole batch nets to zero* between depositing and withdrawing accounts — it does not re-evaluate or aggregate fees, and it has no notion of "this is really one big transfer split into many legs" [3](#0-2) . `Engine::execute_signed_intent` processes each signed `MultiPayload`/intent independently and only performs nonce/signature/deadline checks — no cross-intent fee aggregation exists [4](#0-3) .

Attacker payload: the signer (optionally colluding with, or controlling, a second account acting as counterparty to satisfy the `TransferMatcher` zero-sum requirement for token `T`) submits `k` signed `MultiPayload`s in one `execute_intents`/`execute_signed_intents` call, each containing a `TokenDiff{diff: {T: -1, X: +x/k}}` (and matching `{T: +1, X: -x/k}` legs from the counterpart), instead of one `TokenDiff{diff: {T: -k, X: +x}}`. Every individual intent sees `amount == 1` for `T`, so `token_fee` returns `Pips::ZERO` on every leg, and `fees_collected` for `T` accumulates to `0` across the whole batch, whereas a single combined intent would have paid `Pips::fee_ceil(k)`.

No existing guard prevents this: `MultiPayload::verify`, nonce checks, and `TransferMatcher::finalize` all operate correctly and do not reference fee totals; they only ensure signature validity and that deltas sum to zero — orthogonal to fee computation.

### Impact Explanation
This under-collects protocol fees on any `Nep245`/`Imt` asset that is used with fungible-like (multi-unit) balances, matching the "protocol fees bypassed" Critical category. The fee collector configured via `engine.state.fee_collector()` receives strictly less than it is entitled to for the true aggregate volume moved; the shortfall scales with the size of the transfer being laundered and is fully repeatable across accounts, tokens (any `Nep245`/`Imt` token id), and batches — the attacker cost is limited to gas/signing overhead for `k` intents instead of `1`.

### Likelihood Explanation
Preconditions are minimal: any unprivileged signer holding a NEP-245/IMT balance, and a fee configuration with `fee > 0`, is sufficient. No special role, relayer key, or victim key is required. The attack can be carried out with a single account bouncing balance internally (no economic gain) or, to realize actual value transfer/laundering, with a second account under the attacker's own control acting as the matching counterparty for the `TransferMatcher` zero-sum requirement. This is straightforward to construct and requires no timing or race conditions — it is a deterministic per-intent evaluation gap.

### Recommendation
Compute the NEP-245/IMT fee-exemption threshold (and general fee) against the account's aggregate signed movement of a given `token_id` within the whole settlement (e.g., accumulate absolute negative deltas per `(signer_id, token_id)` across all intents in `execute_signed_intents`/`Engine`, and assess `token_fee`/`fee_ceil` once against that aggregate) rather than re-evaluating `amount <= 1` independently per intent. Alternatively, remove the `amount <= 1` exemption for `Nep245`/`Imt` token types entirely, since MT assets are not restricted to single-unit balances the way NFTs are.

    // Finalizes all transfers, or returns unmatched deltas.
    // If unmatched deltas overflow, then Err(None) is returned.
    pub fn finalize(self) -> Result<Transfers, InvariantViolated> {
        let mut transfers = Transfers::default();
        let mut deltas = TokenDeltas::default();
        for (token_id, transfer_matcher) in self.0 {
            if let Err(unmatched) = transfer_matcher.finalize_into(&token_id, &mut transfers)
                && (unmatched == 0 || deltas.apply_delta(token_id, unmatched).is_none())
            {
                return Err(InvariantViolated::Overflow);
            }
        }
        if !deltas.is_empty() {
            return Err(InvariantViolated::UnmatchedDeltas {
                unmatched_deltas: deltas,
            });
        }
        Ok(transfers)
    }

    fn execute_signed_intent(&mut self, signed: MultiPayload) -> Result<()> {
        // verify signed payload and get public key
        let public_key = signed.verify().ok_or(DefuseError::InvalidSignature)?;

        // calculate intent hash
        let hash = signed.hash();

        // extract NEP-413 payload
        let DefusePayload::<DefuseIntents> {
            signer_id,
            verifying_contract,
            deadline,
            nonce,
            message: intents,
        } = signed.extract_defuse_payload()?;

        // check recipient
        if verifying_contract != *self.state.verifying_contract() {
            return Err(DefuseError::WrongVerifyingContract);
        }

        self.inspector.on_deadline(deadline);

        // make sure message is still valid
        if deadline < Timestamp::now() {
            return Err(DefuseError::DeadlineExpired);
        }

        // make sure the account has this public key
        if !self.state.has_public_key(&signer_id, &public_key) {
            return Err(DefuseError::PublicKeyNotExist(signer_id, public_key));
        }

        // commit nonce
        self.verify_intent_nonce(nonce, deadline)?;
        self.state.commit_nonce(signer_id.clone(), nonce)?;

        intents.execute_intent(&signer_id, self, hash)?;
        self.inspector.on_intent_executed(&signer_id, hash, nonce);

        Ok(())
    }
