### Title
Unbounded-depth JSON recursion in the signer's unauthenticated event-observer HTTP server causes a remote stack-overflow crash - (File: `libsigner/src/events.rs`)

### Summary
`libsigner`'s `Cargo.toml` compiles `serde_json` with the `unbounded_depth` feature, which globally disables serde_json's default 128-level recursion guard for the whole crate. [1](#0-0)  The signer's event-observer HTTP server (`SignerEventReceiver`) binds a `tiny_http` listener on an operator-configured socket and, for `POST /stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, and `/new_block`, hands the raw request body straight to `serde_json::from_slice` via `process_event` with no authentication check. [2](#0-1) [3](#0-2)  Because the depth guard is disabled crate-wide, an attacker who can reach this port can send a JSON body with a deeply nested (or unknown, recursively-skipped) value and overflow the native call stack, aborting the process — a stronger, uncatchable analog of the axios `RangeError` DoS.

### Finding Description
The axios advisory's root cause is that a JSON/object walker recurses per nesting level with no depth bound, so attacker-controlled nesting exhausts the call stack and crashes the process.

The equivalent fault exists in this repo's signer event pipeline:
- `libsigner/Cargo.toml` declares:
  ```
  [dependencies.serde_json]
  version = "1.0"
  features = ["arbitrary_precision", "unbounded_depth"]
  ``` [1](#0-0) 
  The `unbounded_depth` feature removes serde_json's built-in recursion-limit check (which normally returns a catchable `Error::io_exceeded_depth`-style error after ~128 levels) for **every** deserialization performed anywhere in the crate — not just for `serde_json::Value`. Unlike the Clarity codebase's correct pattern of pairing `disable_recursion_limit()` with `serde_stacker::Deserializer` to safely spill recursion to the heap, [4](#0-3)  `libsigner` has no such heap-spilling guard anywhere (no `serde_stacker` dependency, no `deny_unknown_fields`, confirmed by searching the crate).
- `SignerEventReceiver::bind` opens a `tiny_http::HttpServer` on an operator-supplied `SocketAddr` (which can be a non-loopback interface). [5](#0-4) 
- `next_event` dispatches any POST to `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block` straight into `process_event::<T, E>(request)` with **no authentication/authorization check** of any kind (contrast with `/v3/block_proposal` in stackslib, which requires a password header). [6](#0-5) 
- `process_event` reads the full body and calls `serde_json::from_slice(body.as_bytes())` to deserialize it into the target event type `E` (`StackerDBChunksEvent`, `BlockValidateResponse`, `BurnBlockEvent`, `StacksBlockEvent`). [3](#0-2) 

Even though these target types are concrete structs (not arbitrary `serde_json::Value`), serde's generated `Deserialize` impls skip unrecognized/extra JSON fields using `IgnoredAny`, whose implementation in serde_json recursively walks the *actual* nested syntax of the skipped value regardless of the target schema. With the crate-wide recursion guard disabled by `unbounded_depth`, this walk has no depth ceiling, so a sufficiently deeply nested JSON value (either as the whole body, if the top-level type also has an object/array-shaped field, or embedded in an unrecognized extra field) drives the recursive descent parser to unbounded depth and overflows the native stack. A native Rust stack overflow is not a catchable `Result::Err` like the axios `RangeError` — it triggers an immediate process abort (SIGSEGV/stack-overflow abort), which is a strictly worse failure mode than the original advisory.

This breaks the "reachable, unauthenticated code path only requires a few crafted bytes" equality that the rules call out as Critical: an endpoint intended only to receive trusted node-pushed events instead accepts and fully parses arbitrary attacker-supplied bytes with no auth gate and no recursion bound.

### Impact Explanation
Any remote, unauthenticated party who can reach the signer's event-observer HTTP port (which listens on an operator-configured address that is not restricted to loopback by the code shown) can crash the running `stacks-signer` process with a single HTTP POST. Because signers are safety-critical participants in Nakamoto block signing, taking down signer processes network-wide via this same trivially-repeatable payload threatens signer availability and, by extension, block-production liveness. This matches the "Critical - remote crash/unauthenticated DoS from few messages" bucket.

### Likelihood Explanation
- No authentication is required to reach `process_event` for any of the four event routes. [7](#0-6) 
- The vulnerable dependency configuration (`unbounded_depth`) is a static, always-on Cargo feature — it is not a rare runtime configuration; it is compiled into every build of `libsigner`. [1](#0-0) 
- Exploitation only requires generating a deeply nested (or recursively-nested "extra field") JSON payload and sending it via one HTTP POST — no protocol handshake, key material, or privileged role is needed.
- The only mitigating factor is deployment-specific: if an operator strictly firewalls the event-observer port to `127.0.0.1` only, remote reachability is reduced to local processes. The code itself does not enforce this restriction.

### Recommendation
- Remove the `unbounded_depth` feature from `libsigner`'s `serde_json` dependency unless it is strictly required; if arbitrary-precision numeric handling needs unbounded_depth, pair it with `serde_stacker::Deserializer` (as already done correctly in `clarity/src/vm/database/structures.rs`) so deep recursion spills to the heap instead of overflowing the stack.
- Add an explicit maximum nesting/size check (e.g., using a depth-limited pre-scan or `Deserializer::disable_recursion_limit()` + `serde_stacker`) before parsing bodies in `process_event`.
- Add authentication/authorization (e.g., a shared secret/bearer token) to the signer event-observer HTTP endpoints, consistent with the pattern already used for `/v3/block_proposal` in stackslib.
- Bound the maximum accepted body size for these routes before attempting to parse it.

### Proof of Concept
```
POST /stackerdb_chunks HTTP/1.1
Host: <signer-event-observer-ip>:<port>
Content-Type: application/json
Content-Length: <len>

{"contract_id":"...", "modified_slots": [], "extra": [[[[[[[[[[[[[[[[[[[[ ... 100000+ nested arrays ... ]]]]]]]]]]]]]]]]]]]] }
```
Sending this to any reachable `SignerEventReceiver` listener causes `process_event::<T, StackerDBChunksEvent>` to call `serde_json::from_slice`, which recurses once per `[` while skipping the unrecognized `extra` field via `IgnoredAny`; with the crate's `unbounded_depth` feature enabled there is no depth cutoff, so sufficiently deep nesting (a few thousand levels, similar to the axios PoC's ~2500) overflows the native stack and aborts the `stacks-signer` process. This could not be fully executed in this environment (no filesystem/binary build access), so the exact minimum nesting depth needed to trigger the crash on this build's stack size is unverified and should be confirmed empirically by a Devin session with repo access.

fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

/// JSON deserialization helper for non-WASM targets.
#[cfg(not(target_family = "wasm"))]
fn deserialize_json<T: serde::de::DeserializeOwned>(json: &str) -> Result<T, VmExecutionError> {
    let mut deserializer = serde_json::Deserializer::from_str(json);

    // serde's default 128 depth limit can be exhausted by a 64-stack-depth AST, so
    // disable the recursion limit and let stacker spill the deserializer to the heap
    // instead of overflowing.
    deserializer.disable_recursion_limit();
    let deserializer = serde_stacker::Deserializer::new(&mut deserializer);

    T::deserialize(deserializer)
        .map_err(|_| VmInternalError::Expect("Failed to deserialize vm.Value".into()).into())
}
