Found: `Interface.myVpnNetworksTable`, `myVpnAddrsTable`, and `myBroadcastAddrsTable` are copied by value from `CertState` once, at `NewInterface` construction time, and are never refreshed when the PKI reloads a new certificate.

### Title
Interface caches `myVpnNetworksTable`/`myVpnAddrsTable`/`myBroadcastAddrsTable` from CertState only at construction, desyncing from `pki.getCertState()` after a certificate reload - (File: `interface.go`)

### Summary
`NewInterface` copies `myVpnNetworks`, `myVpnNetworksTable`, `myVpnAddrs`, `myVpnAddrsTable`, and `myBroadcastAddrsTable` out of the `CertState` returned by `pki.getCertState()` exactly once, at startup, into fields directly on the long-lived `Interface` struct. [1](#0-0) 

### Finding Description
`CertState` (and the values derived from the local certificate's `Networks()`/broadcast ranges) is designed to be swapped out live on a SIGHUP/config reload: `PKI.reloadCerts` builds a brand new `CertState` from disk and atomically stores it via `p.cs.Store(newState)`, and every consumer that needs the current picture is supposed to call `pki.getCertState()` fresh each time. [2](#0-1) [3](#0-2) 

The `Interface` object, however, snapshots the routing/address tables derived from the certificate at the moment it's constructed, rather than always deferring to `f.pki.getCertState()`: [4](#0-3) [5](#0-4) 

These copies (`f.myVpnNetworksTable`, `f.myVpnAddrsTable`, `f.myBroadcastAddrsTable`) are used directly during handshake processing to decide whether to accept a peer's advertised VPN network as valid, to refuse self-handshakes, and to compute common-network overlap - all reachable by any unauthenticated remote peer sending handshake packets, not just an already-trusted peer: [6](#0-5) [7](#0-6) 

By contrast, other paths in the codebase that need the *current* certificate's network set correctly re-fetch a fresh `CertState` on every access (e.g. `reloadFirewall`, `tryRehandshake`, `certVerifier`), and there is an explicit changelog entry and test (`TestReloadFirewall_CertUnsafeNetworksChanged`) proving the project already had to fix exactly this class of bug for the firewall's `unsafeNetworks`: [8](#0-7) [9](#0-8) [10](#0-9) 

The `Interface`'s own `myVpnNetworksTable`/`myVpnAddrsTable`/`myBroadcastAddrsTable` fields were never given the equivalent reload-and-swap treatment, so if an admin's certificate is renewed with a different set of VPN networks/addresses (a supported, explicitly-tested operation per `PKI.reloadCerts`'s "adding certs is fine" logic), the `Interface`'s cached tables silently diverge from the authoritative `CertState` that `HandshakeManager` uses elsewhere in the same code path (`f.myVpnAddrsTable`, `f.myVpnNetworksTable` at lines 901/918 vs. `cs := f.pki.getCertState()` used for credentials at line 651/703). [11](#0-10) [12](#0-11) 

This is the same bug class as the reported RubiconMarketAddress issue: a value is read once from an authoritative, independently-mutable source at construction time and cached in a sibling component's own instance field, and the two copies (`Interface.myVpnAddrsTable` vs. `CertState.myVpnAddrsTable` reachable via `pki.getCertState()`) get out of sync whenever the authoritative source changes, with no mitigation baked into `Interface`'s reload path.

### Impact Explanation
`myVpnAddrsTable`/`myVpnNetworksTable` gate the self-handshake refusal check and the "any VPN network in common" computation during handshake completion for both initiator and responder paths - logic exercised on every inbound handshake packet from any network peer, without requiring a valid CA-signed certificate to reach it (the check runs before/around remote-cert acceptance). If the local host's certificate networks are legitimately rotated (e.g. IP re-assignment via cert renewal) while the daemon is running, the interface's stale table can cause it to erroneously treat a remote host's now-legitimate overlapping VPN address as an unauthorized "self" range or to miscompute network-overlap decisions used for handshake completion, producing inconsistent trust/acceptance decisions relative to what the rest of the code (which consults the live `CertState`) believes is correct.

### Likelihood Explanation
Likelihood is moderate: it requires a certificate networks change on reload (an operator action, not attacker-controlled), but once that happens the desync is deterministic and persists for the life of the process (no restart-triggering condition exists), and the affected code path (`beginHandshake`/`continueHandshake`) is directly reachable by any remote peer sending handshake packets over the wire.

### Recommendation
Stop copying `myVpnNetworks`/`myVpnNetworksTable`/`myVpnAddrs`/`myVpnAddrsTable`/`myBroadcastAddrsTable` into `Interface` fields at construction. Instead, have all consumers (including `handshake_manager.go`'s `beginHandshake`/`continueHandshake`) read these tables from a freshly-fetched `f.pki.getCertState()` on each use, exactly as `reloadFirewall` and `tryRehandshake` already do for other certificate-derived values, so a certificate reload is reflected everywhere consistently.

### Proof of Concept
1. Start a node with a certificate covering `10.0.0.5/24`; `Interface.myVpnAddrsTable`/`myVpnNetworksTable` are populated from this at `NewInterface` time. [13](#0-12) 
2. Trigger `pki.reload` via SIGHUP/config reload with a new certificate whose `Networks()` legitimately differ (e.g., additional/renumbered VPN prefix) - `PKI.reloadCerts` accepts this ("adding certs is fine") and atomically stores the new `CertState`. [14](#0-13) [15](#0-14) 
3. A remote peer sends a handshake packet; `beginHandshake`/`continueHandshake` evaluate `f.myVpnAddrsTable.Contains(...)` / `f.myVpnNetworksTable.Contains(...)` using the interface's now-stale table instead of the current `CertState`, producing decisions inconsistent with the certificate that was actually just loaded. [6](#0-5)

    - port: any
      proto: any
      host: any
`

	require.NoError(t, cfg.LoadString(rawYAML))

	fw, err := NewFirewallFromConfig(l, pki.getCertState(), cfg)
	require.NoError(t, err)
	require.Equal(t, initialUnsafe, fw.unsafeNetworks)
