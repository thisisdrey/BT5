### Title
`vesting::distribute` State-Check Too Restrictive — Shareholders Permanently Lose Previously Unlocked APT After Contract Termination - (File: `aptos-move/framework/aptos-framework/sources/vesting.move`)

### Summary

`vesting::distribute` enforces `assert_active_vesting_contract`, which aborts unless the contract is in `VESTING_POOL_ACTIVE` state. After `terminate_vesting_contract` transitions the contract to `VESTING_POOL_TERMINATED`, any APT that shareholders had previously unlocked (via `vest()` or `unlock_rewards()`) but that is still in `pending_inactive` in the underlying stake pool — not yet withdrawable because the staking lockup has not expired — can never be distributed to those shareholders. The only post-termination exit is `admin_withdraw`, which sends all withdrawable funds to the admin-controlled `withdrawal_address`, not to the shareholders who earned them. The root cause is identical to the seeded bug: a wrapper function's state guard is narrower than the underlying operation actually requires.

---

### Finding Description

**State constants and guard:**

```
VESTING_POOL_ACTIVE     = 1
VESTING_POOL_TERMINATED = 2
``` [1](#0-0) 

`assert_active_vesting_contract` aborts unless `state == VESTING_POOL_ACTIVE`: [2](#0-1) 

`distribute` calls this guard unconditionally: [3](#0-2) 

`terminate_vesting_contract` calls `distribute` once (to flush currently-withdrawable coins), then sets `state = VESTING_POOL_TERMINATED` and calls `unlock_stake` on the remaining active balance: [4](#0-3) 

After that single `distribute` call, any coins that were already in `pending_inactive` (from earlier `vest()` / `unlock_rewards()` calls) but whose staking lockup has not yet expired are **not** withdrawable at termination time. They will become withdrawable only after the lockup expires.

The only post-termination function that can touch those coins is `admin_withdraw`, which requires `state == VESTING_POOL_TERMINATED` and routes everything to `withdrawal_address`: [5](#0-4) 

The underlying `withdraw_stake` helper has **no state restriction** of its own: [6](#0-5) 

So the invariant broken is: `distribute` is more restrictive than `withdraw_stake`, exactly mirroring the seeded pattern where `voteToVeto` was more restrictive than the underlying `veto`.

---

### Impact Explanation

Shareholders who called `vest()` or `unlock_rewards()` before termination moved APT from `active` into `pending_inactive` in the stake pool. Those coins are earmarked for those shareholders. After termination, `distribute` is permanently blocked by the `VESTING_POOL_ACTIVE` guard. When the lockup eventually expires, `admin_withdraw` sweeps all withdrawable coins — including the shareholders' previously unlocked APT — to `withdrawal_address`. Shareholders suffer a **permanent, irreversible loss of APT** with no on-chain recourse.

---

### Likelihood Explanation

The scenario is reachable by any unprivileged transaction sequence:

1. Any caller invokes `vest(contract_address)` or `unlock_rewards(contract_address)` — both are permissionless `public entry` functions — moving APT into `pending_inactive`.
2. Before the staking lockup expires, the admin calls `terminate_vesting_contract`.
3. After the lockup expires, `admin_withdraw` is called, draining the shareholders' coins to `withdrawal_address`.

No special privilege beyond being the admin (for step 2) is required, and the admin's ability to terminate is an expected, documented capability. The loss is triggered by the combination of the timing gap between unlock and lockup expiry, which is a normal operating condition (lockup periods are typically months long).

---

### Recommendation

Remove the `assert_active_vesting_contract` guard from `distribute`, or add a second allowed state:

```move
public entry fun distribute(contract_address: address) acquires VestingContract {
-   assert_active_vesting_contract(contract_address);
+   assert_vesting_contract_exists(contract_address);
+   let state = borrow_global<VestingContract>(contract_address).state;
+   assert!(
+       state == VESTING_POOL_ACTIVE || state == VESTING_POOL_TERMINATED,
+       error::invalid_state(EVESTING_CONTRACT_NOT_ACTIVE)
+   );
    ...
}
```

This mirrors the correct fix for the seeded bug: allow the operation in all states where the underlying mechanics are valid. The `withdraw_stake` helper already works correctly in both states; only the outer guard needs to be widened.

---

### Proof of Concept

```
1. Admin creates vesting contract; withdrawal_address = admin_wallet.
2. Epoch passes; stake pool earns rewards.
3. Anyone calls vest(contract_address)
      → staking_contract::unlock_stake moves R APT into pending_inactive.
      → Staking lockup = 30 days; R APT is NOT yet withdrawable.
4. Admin calls terminate_vesting_contract(admin, contract_address):
      a. distribute(contract_address) is called — inactive = 0, so nothing distributed.
      b. state = VESTING_POOL_TERMINATED.
      c. unlock_stake called on remaining active balance.
5. 30 days pass; lockup expires; R APT (+ new unlocked active) become inactive.
6. Admin calls admin_withdraw(admin, contract_address):
      → withdraw_stake pulls all inactive coins.
      → All coins deposited to withdrawal_address (admin_wallet).
7. Shareholders receive 0 APT from their previously unlocked rewards.
      → Permanent loss of R APT per shareholder, proportional to shares.
``` [7](#0-6) [8](#0-7) [3](#0-2) [9](#0-8) [10](#0-9)

    public entry fun terminate_vesting_contract(admin: &signer, contract_address: address) acquires VestingContract {
        assert_active_vesting_contract(contract_address);

        // Distribute all withdrawable coins, which should have been from previous rewards withdrawal or vest.
        distribute(contract_address);

        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        verify_admin(admin, vesting_contract);
        let (active_stake, _, pending_active_stake, _) = stake::get_stake(vesting_contract.staking.pool_address);
        assert!(pending_active_stake == 0, error::invalid_state(EPENDING_STAKE_FOUND));

        // Unlock all remaining active stake.
        vesting_contract.state = VESTING_POOL_TERMINATED;
        vesting_contract.remaining_grant = 0;
        unlock_stake(vesting_contract, active_stake);

        emit(
            Terminate {
                admin: vesting_contract.admin,
                vesting_contract_address: contract_address,
            },
        );
    }

    public entry fun admin_withdraw(admin: &signer, contract_address: address) acquires VestingContract {
        let vesting_contract = borrow_global<VestingContract>(contract_address);
        assert!(
            vesting_contract.state == VESTING_POOL_TERMINATED,
            error::invalid_state(EVESTING_CONTRACT_STILL_ACTIVE)
        );

        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        verify_admin(admin, vesting_contract);
        let coins = withdraw_stake(vesting_contract, contract_address);
        let amount = coin::value(&coins);
        if (amount == 0) {
            coin::destroy_zero(coins);
            return
        };
        aptos_account::deposit_coins(vesting_contract.withdrawal_address, coins);

        emit(
            AdminWithdraw {
                admin: vesting_contract.admin,
                vesting_contract_address: contract_address,
                amount,
            },
        );
    }
