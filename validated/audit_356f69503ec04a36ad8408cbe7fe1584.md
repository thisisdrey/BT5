### Title
RPC endpoints authenticate against a plaintext, unconstrained `auth_token` using bare equality, with no distinction between "auth disabled" and "auth token empty" - (File: `stackslib/src/net/api/postblock_proposal.rs`)

### Summary
Several privileged Stacks node RPC endpoints (`/v3/block_proposal`, `/v3/blocks/replay/*`, `/v3/blocks/simulate/*`, `/v3/contracts/fast-call-read/*`, `/v3/transactions/simulate`, and the `broadcast=1` path of `POST /v3/blocks`) gate access with a simple `authorization` header equality check against a single configured `auth_token` string. This mirrors the Traefik advisory's root cause class: a "not well-formed" security configuration (there, an incompletely specified `TLSOption`; here, an operator-supplied auth secret that is empty or otherwise degenerate) causes the route to be effectively exposed without meaningful authentication.

### Finding Description
Every one of these handlers implements the identical pattern: [1](#0-0) 

```
let Some(password) = &self.auth else {
    return Err(Error::Http(400, "Bad Request.".into()));
};
let Some(auth_header) = preamble.headers.get("authorization") else {
    return Err(Error::Http(401, "Unauthorized".into()));
};
if auth_header != password {
    return Err(Error::Http(401, "Unauthorized".into()));
}
```

The same construct appears in [2](#0-1) , [3](#0-2) , [4](#0-3) , [5](#0-4) , and, in a lighter-weight advisory form, gates the `broadcast=1` path of `postblock_v3.rs`: [6](#0-5) .

The equality being enforced is: `stored auth_token` == `client-supplied Authorization header`. This is exactly the "authenticated vs. stored" equality called out in the task rules. The bundled sample configs (which many operators copy verbatim) ship this secret as an **empty string** by default: [7](#0-6) [8](#0-7) 

```
[connection_options]
# WARNING: Must match the signer binary's `auth_password`.
auth_token = ""
```

If `auth_token = ""` is passed through to these handlers as `self.auth = Some(String::new())` (rather than being normalized to `None`), then any remote, unauthenticated client that sends an `authorization` header with an empty value satisfies `auth_header != password` as `false`, and is treated as fully authenticated for that endpoint — analogous to Traefik serving a route with an effectively empty/no-op TLSOption when the operator's configuration is malformed/degenerate.

### Impact Explanation
If this equality can be satisfied trivially (empty-vs-empty, or via a mis-set/blank `auth_token`), a remote unauthenticated attacker gains access to endpoints that are explicitly gated because they are expensive or privileged: block proposal validation (`/v3/block_proposal`, used by the miner-signer protocol), block replay/simulate (compute-heavy read endpoints), fast-call read-only contract calls, transaction simulation, and authenticated block broadcast. This matches the "High: bounded compute DoS on a read endpoint" / potential "auth bypass" impact bands in the task's rubric, since these endpoints would be reachable without the intended authorization gate.

### Likelihood Explanation
This is a **config-wiring hypothesis, not a fully confirmed root cause**. I was able to conclusively verify:
- All the affected handlers perform simple string equality with no length/entropy floor and no distinction between "no password configured" (`None`, which correctly returns 400) and "an empty password configured" (`Some("")`, whose behavior on comparison I could not fully trace end-to-end).
- The distributed sample configs literally set `auth_token = ""` as the shipped default for the signer node-side config, which is a strong incentive/likelihood factor if operators do not override it, unlike the miner sample which forces a placeholder value (`"<YOUR_AUTH_TOKEN>"`).

I was **not able to locate and inspect**, within the available tool budget, the exact code path in `stackslib/src/config/mod.rs` / `stackslib/src/net/api/mod.rs` / `stackslib/src/net/connection.rs` that converts the parsed `auth_token` config value into the `Option<String>` passed to these handlers' constructors, so I cannot confirm whether an empty-string config value is normalized to `None` (safe, fails closed as shown for the "no auth configured" branch) or preserved as `Some("")` (the fail-open condition). This is the missing link needed to fully prove the root cause with the same certainty as the Traefik advisory.

### Recommendation
- Trace and confirm how `auth_token` from `ConnectionOptions`/config is mapped into `RPCBlockProposalRequestHandler::new`, `RPCNakamotoBlockReplayRequestHandler::new`, etc. If an empty string is preserved as `Some(String::new())`, normalize it to `None` at config-load time so these endpoints deterministically return 400 ("not enabled") rather than silently accepting empty-value `authorization` headers.
- Reject/refuse to start (or emit a loud warning and disable the endpoint) if `auth_token` is set to the empty string, rather than treating it as a usable secret.
- Consider constant-time comparison for the token check in addition to the emptiness fix.

### Proof of Concept
Conceptual PoC (contingent on confirming the config-wiring gap above):
1. Start a node with `[connection_options] auth_token = ""` (as shipped in `sample/conf/mainnet-signer.toml`).
2. Send `POST /v3/block_proposal` (or any of the other gated endpoints) with header `authorization:` (empty value) and a valid JSON body.
3. If `self.auth == Some("")`, the check `auth_header != password` evaluates `"" != ""` = `false`, so the request is treated as authenticated and processed instead of being rejected with 401/400.

Because I could not confirm step 3's precondition (the config→handler wiring) within the available investigation budget, this finding should be treated as a **strong candidate requiring one more verification step** (reading `stackslib/src/config/mod.rs`'s auth_token parsing and `stackslib/src/net/api/mod.rs`'s handler-construction call sites) rather than a fully proven vulnerability.

        // if broadcast=1 is set, then the requester must be authenticated
        let mut broadcast = false;
        let mut authenticated = false;

        // look for authorization header
        if let Some(password) = &self.auth {
            if let Some(auth_header) = preamble.headers.get("authorization") {
                if auth_header != password {
                    return Err(Error::Http(401, "Unauthorized".into()));
                }
                authenticated = true;
            }
        }

        // see if broadcast=1 is set
        for (key, value) in form_urlencoded::parse(query.as_ref().unwrap_or(&"").as_bytes()) {
            if key == "broadcast" {
                broadcast = broadcast || value == "1";
            }
        }

        if broadcast && !authenticated {
            return Err(Error::Http(401, "Unauthorized".into()));
        }
