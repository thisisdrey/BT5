### Title
If a blocklistable collateral token (e.g. USDC) blocklists the `Treasury` contract, all withdrawals of that collateral permanently revert, freezing all user deposits - (File: contracts/Treasury.sol)

### Summary
`Treasury.pull()` performs the only outbound transfer of underlying collateral in the protocol. It is a plain `safeTransfer` from the `Treasury` address with no alternative redemption path, no `try/catch`, and no admin sweep function (`Treasury` does not inherit `TokenHolder`). If the underlying asset is a centrally-blocklisted token such as USDC and the token admin adds the `Treasury` address to its blocklist, every code path that pays out collateral reverts, permanently freezing all users' deposits of that asset.

### Finding Description
User collateral is custodied by `Treasury`, not by `DepositToken`. Every withdrawal ultimately calls `Treasury.pull()`, which executes `underlying().safeTransfer(to_, amount_)` from `Treasury`'s own balance: [1](#0-0) 

The callers are:

- `DepositToken.withdraw` → `_withdraw` → `_pool.treasury().pull(to_, _withdrawn)` [2](#0-1) 
- `DepositToken.withdrawFrom` and `flashWithdraw` (both funnel into `_withdraw`) [3](#0-2) 
- `VesperGateway.withdraw`, which calls `_depositToken.withdraw(...)` and then `vToken_.withdraw(...)` — a Vesper pool that itself holds USDC can also be bricked if the gateway/Vesper pool is blocklisted [4](#0-3) 

This is the same bug class as the source report: an external token admin's blocklist applied to a protocol-held contract address turns an internal accounting/liveness invariant into a permanent revert. There is no analogous `NonZeroBalance` gate here — instead there is no fallback at all. `Treasury.migrateTo()` is `onlyPool` and equally reverts on the same blocklisted `safeTransfer`, so even a privileged migration cannot rescue the funds, and `Treasury` lacks any `sweep`/recovery function for the underlying. [5](#0-4) 

### Impact Explanation
Permanent freezing of funds. Once `Treasury` is on the collateral token's blocklist, `_withdraw` reverts inside `pull` for every user and every amount, so 100% of that collateral's deposits become unrecoverable. Liquidation payouts (`Pool.liquidate` → `DepositToken.seize` transfers `msd` shares, but the seizer still must call `withdraw` to redeem underlying) remain frozen as well. The invariant broken is redemption: `msdToken` total supply stays backed on paper but is permanently unredeemable.

### Likelihood Explanation
Requires an external, trusted-token admin action (USDC/USDT-style blocklisting of the `Treasury` or of an integrated Vesper pool), which is not attacker-controlled — identical in nature to the source finding's precondition, hence Medium rather than High. No protocol modifier, pause flag, or reentrancy guard mitigates it; the revert occurs inside the external token call itself.

### Recommendation
Provide an exit path that does not route through the blocklisted `Treasury` address, e.g.:

- Let `pull` send funds via `call`-based recovery or allow `DepositToken` to transfer collateral it holds directly; or
- Add a governor-controlled mechanism that lets `msdToken` holders burn their shares in exchange for a claim on a *new* `Treasury` address (proportional claim), so `migrateTo` isn't the only option — note `migrateTo` itself reverts when `Treasury` is the blocklisted sender, so the mitigation must not rely on `Treasury` initiating transfers. A claim contract that pulls from `Treasury` is equally blocked; the realistic fix is for `Treasury` to remain the sender but for governance to rotate the `DepositToken`/`Treasury` such that redemption claims are settled by a fresh contract before blocklisting, plus monitoring/blocklist checks on `pull` to fail fast and alert.

### Proof of Concept
Foundry fork test (mainnet, USDC as underlying):

```solidity
// Fork mainnet where a Metronome pool has a USDC DepositToken (msdUSDC) with
// deposits custodied in Treasury.
function test_blacklistedTreasury_freezesWithdrawals() public {
    IERC20 usdc = IERC20(USDC);
    IDepositToken msdUSDC = pool.depositTokenOf(usdc);
    address treasury = address(pool.treasury());
    address alice = makeAddr("alice");

    // Alice deposits
    deal(USDC, alice, 1000e6);
    vm.startPrank(alice);
    usdc.approve(address(msdUSDC), 1000e6);
    msdUSDC.deposit(1000e6, alice);
    vm.stopPrank();

    // USDC admin blocklists the Treasury
    vm.prank(USDC_BLOCKLISTER);
    IFiatToken(USDC).blacklist(treasury);

    // Every withdrawal path now reverts inside Treasury.pull
    vm.startPrank(alice);
    vm.expectRevert(); // USDC: blacklisted
    msdUSDC.withdraw(1000e6, alice);
    vm.stopPrank();

    // Governance migration cannot rescue funds either: migrateTo sends from the blocklisted sender
    vm.expectRevert();
    vm.prank(address(pool));
    ITreasury(treasury).migrateTo(makeAddr("newTreasury"));
}
```
