### Title
Unstaked IP-churn Sybil attack exhausts shared global connection TokenBucket, starving all legitimate senders (including staked peers) - ([File: streamer/src/nonblocking/quic.rs])

### Summary
`run_server`/`setup_connection` in `streamer/src/nonblocking/quic.rs` enforce a per-IP `ConnectionRateLimiter` and a single shared `overall_connection_rate_limiter` (`TokenBucket::new(MAX_CONNECTION_BURST, MAX_CONNECTION_BURST, TOTAL_CONNECTIONS_PER_SECOND)` = 2500 conns/sec, burst 1000) that is checked/consumed *before* stake is determined. Because per-IP limiting only throttles a given IP once it has accumulated history, and unseen IPs are unconditionally allowed (`ConnectionRateLimiter::is_allowed` returns `true` when `None`), an unstaked attacker rotating across many distinct source IPs can collectively exhaust the shared 2500/s budget while every individual IP stays under its own per-minute cap, causing legitimate (including staked) connections to be rejected by the `overall_connection_rate_limiter.current_tokens() == 0` check.

### Finding Description

before any per-IP or per-stake distinction is made: [2](#0-1) 

`ConnectionRateLimiter::is_allowed` (streamer/src/nonblocking/connection_rate_limiter.rs:34-40) treats any IP it has not seen before as automatically allowed: [3](#0-2) 

The token consumption for the global bucket happens in `setup_connection` after handshake, again *before* stake/pubkey is resolved via `qos.build_connection_context` (which internally calls `get_connection_stake`): [4](#0-3) [5](#0-4) 

Because the global TokenBucket is a single shared resource consumed on a first-come-first-served basis regardless of the caller's IP or stake, an attacker that spreads connection attempts across N distinct (e.g. IPv6-churned) source addresses — each individually staying below its own `max_connections_per_ipaddr_per_min` cap (default config value, 10x burst allowed per `ConnectionRateLimiter::new`) — can collectively saturate `TOTAL_CONNECTIONS_PER_SECOND` (2500/s) and `MAX_CONNECTION_BURST` (1000). Once `overall_connection_rate_limiter.current_tokens() == 0`, *every* other connection attempt, including from previously legitimate, unseen, or even staked IPs, is rejected at line 347 in `run_server`, prior to any stake-based admission logic in `SwQos`. No existing check restores fairness: the per-IP limiter only bounds a single key's rate, not the number of distinct keys contending for the shared bucket, and stake-weighting (`SwQos::try_add_connection`) is applied only after the connection already passed the global gate.

### Impact Explanation
This causes denial of TPU connection admission for all legitimate senders — both unstaked and staked — because the same shared token bucket gates every incoming QUIC connection attempt regardless of identity or stake, and it is consumed before any staked/unstaked prioritization occurs. This matches the "TPU/QUIC ingress denial-of-service via connection-admission starvation" bounty category: an unprivileged, unstaked remote attacker can degrade transaction ingestion for the entire cluster leader without holding stake, by simply rotating source addresses (trivially done over IPv6 or via cheap proxy/NAT churn).

### Likelihood Explanation
Feasibility is high: IPv6 address space makes cheap, essentially unlimited source-address rotation trivial for an attacker (no stake or special network position required), and the per-IP rate limiter (`ConnectionRateLimiter`) explicitly treats first-seen IPs as unconditionally allowed, so an attacker never needs any single IP to exceed its individual quota — it only needs enough distinct IPs cumulatively producing ≥ ~2500 connection attempts/sec (plus the 1000 burst) to keep `overall_connection_rate_limiter` at zero tokens continuously. This requires no validator/leader control, no leaked keys, and only ordinary UDP/QUIC handshake attempts against the public TPU port.

### Recommendation
Do not gate all connections (staked and unstaked) on a single undifferentiated global TokenBucket before stake is known. Options: (1) split the global admission budget into staked-reserved and unstaked-reserved sub-budgets so an unstaked flood cannot exhaust capacity reserved for staked peers; (2) weight/throttle the global bucket's admission by a coarse Sybil-resistance signal (e.g., require handshake completion + apply harsher per-/24 or per-/64 subnet aggregate limits in addition to per-IP, since IPv6 rotation within an attacker-controlled subnet is cheap but subnet ownership is not); (3) move the global rate check to occur after cheap stake/pubkey resolution so staked connections can bypass or get priority over the shared unstaked budget.
