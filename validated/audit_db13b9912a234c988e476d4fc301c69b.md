## Title
Deleted account's postponed self-callback (AddKey/DeleteKey/DeployContract) silently executes against a freshly recreated account of the same name - `remove_account` (core/store/src/utils/mod.rs:505-575)

## Summary
`remove_account`, invoked by `action_delete_account` (`runtime/runtime/src/actions.rs:314-390`), deletes an account's `Account`, `ContractCode`, `AccessKey`/gas-key, and `ContractData` trie entries, but never touches the `PostponedReceipt`, `PendingDataCount`, or `PostponedReceiptId` entries keyed by that same `receiver_id`. If the account had a postponed multi-dependency `ActionReceipt` (e.g. from `promise.and()`) awaiting a still-missing `DataReceipt` at the moment of deletion, that receipt survives the deletion untouched. When the missing `DataReceipt` later arrives, `process_receipt`'s Data branch (`runtime/runtime/src/lib.rs:1367-1474`) will find the stale `PostponedReceiptId`/`PendingDataCount` entries, decrement to zero, and execute the resumed `ActionReceipt` against whatever account currently occupies that `account_id` — even if it is an entirely different (freshly recreated) account.

## Finding Description
`process_action_receipt` (`runtime/runtime/src/lib.rs:1593-1658`) stores a postponed receipt keyed purely by `receiver_id`/`receipt_id`, with associated `PendingDataCount{receiver_id, receipt_id}` and one `PostponedReceiptId{receiver_id, data_id}` per missing input data id (lines 1608-1654). None of these keys are namespaced by any "account generation" or creation nonce — they are tied only to the string `AccountId`.

`remove_account` (`core/store/src/utils/mod.rs:505-575`) only removes `TrieKey::Account`, `TrieKey::ContractCode`, access/gas keys, and `TrieKey::ContractData` for the account. It never iterates or removes `TrieKey::PostponedReceipt`, `TrieKey::PendingDataCount`, or `TrieKey::PostponedReceiptId` entries for that `receiver_id`. `action_create_account` (`runtime/runtime/src/actions.rs:167-210`) likewise performs no check for leftover postponed state before creating a brand-new `Account::new(...)` under the same id.

Exploit flow:
1. Attacker deploys a contract to account `A` that, on some call, issues `promise.and()` combining two promises whose results feed a callback action receipt on `A` containing e.g. `AddKeyAction` (adding an attacker-controlled full-access key) with `predecessor_id == receiver_id == A` — this is a completely ordinary self-callback pattern.
2. The callback `ActionReceipt` arrives at `A` with two unmet `input_data_ids`; `process_action_receipt` stores it as postponed with `PendingDataCount = 2`.
3. The first `DataReceipt` arrives, decrementing `PendingDataCount` to 1 (lib.rs:1456-1472) — the postponed receipt is not yet executed and stays in state.
4. Attacker submits a signed `DeleteAccountAction{beneficiary_id}` on `A` (self-deletion is always permitted to the account owner per `check_actor_permissions`, `actions.rs:761-776`, as long as `locked == 0`). `action_delete_account` calls `remove_account`, which clears `Account`/keys/code but leaves the postponed receipt, `PendingDataCount`, and the remaining `PostponedReceiptId{A, d2}` link in the trie.
5. Later, some other party (a victim) creates a fresh account also named `A` (e.g. it is a top-level or subaccount name that becomes available again once deleted) via `CreateAccountAction`/implicit transfer — `action_create_account` performs no lookup of stale postponed state for `A`.
6. The second `DataReceipt` (already in flight, or triggerable by the attacker if they control the counterpart promise) arrives at `A`. `process_receipt`'s Data branch finds `PostponedReceiptId{A, d2}`, decrements `PendingDataCount` from 1 to 0, loads the still-present `PostponedReceipt{A, receipt_id}`, and executes it via `apply_action_receipt` against the account that currently exists for `A` — the victim's new account.
7. Inside `apply_action`, `check_actor_permissions` (`actions.rs:739-785`) only compares `actor_id != account_id` as strings; since the stored receipt has `predecessor_id == receiver_id == "A"`, and the current receiver is again named `"A"`, the self-authorization check passes trivially even though the underlying account is a completely different entity now owned by the victim. The `AddKeyAction` executes, inserting the attacker's key into the victim's new account.

No existing check (signature, nonce, access-key permission, or account-existence check) catches this, because all of them validate against the `AccountId` string, not any notion of "this account instance." `check_account_existence` (`actions.rs:787-855`) only checks `account.is_some()`, which is true for the victim's fresh account.

## Impact Explanation
This is an authorization escalation across accounts: an attacker who once owned account `A` can plant a durable, dependency-gated callback (`AddKeyAction`/`DeployContractAction`/`DeleteKeyAction`) that resumes and executes against a *different* future owner of the same account name after deletion and recreation, without any signature or consent from the new owner. Concretely this lets the attacker seize control of (add a full-access key to) or overwrite the contract code of the victim's account, enabling theft of any funds subsequently deposited into it — matching the "authorization escalation across accounts or promises" bounty category.

## Likelihood Explanation
Preconditions are all within an unprivileged client's control: the attacker deploys their own contract to their own account, structures a `promise.and()` self-callback, self-deletes the account at the right moment, and controls (or can predict/trigger) delivery of the second data dependency. The only external dependency is that the account name become reusable by a third party afterward, which is a normal occurrence for many account-naming patterns (e.g., short/implicit/top-level names, or an attacker deliberately luring/tricking a victim into claiming the freed name). The attack is fully repeatable and requires no validator, node-operator, or privileged access — only ordinary signed transactions.

## Recommendation
`remove_account` should also purge any lingering `PostponedReceipt`, `PendingDataCount`, and `PostponedReceiptId` entries for the account being deleted (iterating the relevant trie prefixes analogous to how access keys and contract data are already swept), or alternatively `action_create_account`/implicit account creation should refuse to complete (or should first purge such stale entries) if any postponed-receipt state still exists for the target `account_id`. Either fix ensures no stale cross-generation ActionReceipt can resume execution against a semantically different account instance.

/// Removes account, code and all access keys and gas keys associated to it.
pub fn remove_account(
    state_update: &mut TrieUpdate,
    account_id: &AccountId,
) -> Result<RemoveAccountResult, StorageError> {
    state_update.remove(TrieKey::Account { account_id: account_id.clone() });
    state_update.remove(TrieKey::ContractCode { account_id: account_id.clone() });

    let mut gas_key_nonce_count: usize = 0;
    let mut gas_key_nonce_total_key_bytes: usize = 0;

    // Removing access keys and gas key nonces
    let lock = state_update.trie().lock_for_iter();
    let mut keys_to_remove: Vec<TrieKey> = Vec::new();
    for raw_key in state_update
        .locked_iter(&trie_key_parsers::get_raw_prefix_for_access_keys(account_id), &lock)?
    {
        let raw_key = raw_key?;
        let key_handle = trie_key_parsers::parse_key_handle_from_access_key_key(
            &raw_key, account_id,
        )
        .map_err(|_e| {
            StorageError::StorageInconsistentState(
                "Can't parse key handle from raw key for AccessKey".to_string(),
            )
        })?;
        let nonce_index =
            trie_key_parsers::parse_nonce_index_from_gas_key_key(&raw_key, account_id, &key_handle)
                .map_err(|_e| {
                    StorageError::StorageInconsistentState(
                        "Can't parse nonce index from raw key for AccessKey".to_string(),
                    )
                })?;
        if let Some(index) = nonce_index {
            gas_key_nonce_count += 1;
            gas_key_nonce_total_key_bytes += raw_key.len();
            keys_to_remove.push(TrieKey::gas_key_nonce(
                account_id.clone(),
                key_handle.clone(),
                index,
            ));
        } else {
            keys_to_remove.push(TrieKey::access_key(account_id.clone(), key_handle.clone()));
        }
    }
    drop(lock);

    for trie_key in keys_to_remove {
        state_update.remove(trie_key);
    }

    // Removing contract data
    let lock = state_update.trie().lock_for_iter();
    let data_keys = state_update
        .locked_iter(&trie_key_parsers::get_raw_prefix_for_contract_data(account_id, &[]), &lock)?
        .map(|raw_key| {
            trie_key_parsers::parse_data_key_from_contract_data_key(&raw_key?, account_id)
                .map_err(|_e| {
                    StorageError::StorageInconsistentState(
                        "Can't parse data key from raw key for ContractData".to_string(),
                    )
                })
                .map(Vec::from)
        })
        .collect::<Result<Vec<_>, _>>()?;
    drop(lock);

    for key in data_keys {
        state_update.remove(TrieKey::ContractData { account_id: account_id.clone(), key });
    }
    Ok(RemoveAccountResult { gas_key_nonce_count, gas_key_nonce_total_key_bytes })
}

pub(crate) fn action_create_account(
    fee_config: &RuntimeFeesConfig,
    account_creation_config: &AccountCreationConfig,
    account: &mut Option<Account>,
    actor_id: &mut AccountId,
    account_id: &AccountId,
    predecessor_id: &AccountId,
    result: &mut ActionResult,
) {
    if account_id.is_top_level() {
        if account_id.len() < account_creation_config.min_allowed_top_level_account_length as usize
            && predecessor_id != &account_creation_config.registrar_account_id
        {
            // A short top-level account ID can only be created registrar account.
            result.result = Err(ActionErrorKind::CreateAccountOnlyByRegistrar {
                account_id: account_id.clone(),
                registrar_account_id: account_creation_config.registrar_account_id.clone(),
                predecessor_id: predecessor_id.clone(),
            }
            .into());
            return;
        } else {
            // OK: Valid top-level Account ID
        }
    } else if !account_id.is_sub_account_of(predecessor_id) {
        // The sub-account can only be created by its root account. E.g. `alice.near` only by `near`
        result.result = Err(ActionErrorKind::CreateAccountNotAllowed {
            account_id: account_id.clone(),
            predecessor_id: predecessor_id.clone(),
        }
        .into());
        return;
    } else {
        // OK: Valid sub-account ID by proper predecessor.
    }

    *actor_id = account_id.clone();
    *account = Some(Account::new(
        Balance::ZERO,
        Balance::ZERO,
        AccountContract::None,
        fee_config.storage_usage_config.num_bytes_account,
    ));
}

pub(crate) fn action_delete_account(
    state_update: &mut TrieUpdate,
    account: &mut Option<Account>,
    actor_id: &mut AccountId,
    receipt: &Receipt,
    result: &mut ActionResult,
    account_id: &AccountId,
    delete_account: &DeleteAccountAction,
    config: &RuntimeConfig,
    current_protocol_version: ProtocolVersion,
) -> Result<(), StorageError> {
    let account_ref = account.as_ref().unwrap();
    let account_storage_usage = if ProtocolFeature::FixDeleteAccountGlobalContractStorageUsage
        .enabled(current_protocol_version)
    {
        let contract_storage = get_contract_storage_usage(state_update, account_id, account_ref)?;
        account_ref.storage_usage().saturating_sub(contract_storage)
    } else {
        // Legacy behavior: only subtracts local contract code, misses the
        // global contract identifier overhead.
        let account_storage_usage = account_ref.storage_usage();
        let code_len = get_code_len_or_default(
            state_update,
            account_id.clone(),
            account_ref.local_contract_hash().unwrap_or_default(),
        )?;
        debug_assert!(
            code_len == 0 || account_storage_usage > code_len,
            "account storage usage should be larger than code size. storage usage: {}, code size: {}",
            account_storage_usage,
            code_len
        );
        account_storage_usage.saturating_sub(code_len)
    };
    if account_storage_usage > Account::MAX_ACCOUNT_DELETION_STORAGE_USAGE {
        result.result =
            Err(ActionErrorKind::DeleteAccountWithLargeState { account_id: account_id.clone() }
                .into());
        return Ok(());
    }
    let gas_key_balance_to_burn = compute_gas_key_balance_sum(state_update, account_id)?;
    if gas_key_balance_to_burn > GasKeyInfo::MAX_BALANCE_TO_BURN {
        result.result = Err(ActionErrorKind::GasKeyBalanceTooHigh {
            account_id: account_id.clone(),
            public_key: None,
            balance: gas_key_balance_to_burn,
        }
        .into());
        return Ok(());
    }
    // We use current amount as a pay out to beneficiary.
    let account_balance = account_ref.amount();
    if account_balance > Balance::ZERO {
        result
            .new_receipts
            .push(Receipt::new_balance_refund(&delete_account.beneficiary_id, account_balance));
    }
    let remove_result = remove_account(state_update, account_id)?;
    result.tokens_burnt =
        result.tokens_burnt.checked_add(gas_key_balance_to_burn).ok_or_else(|| {
            StorageError::StorageInconsistentState("tokens_burnt overflow".to_string())
        })?;
    if remove_result.gas_key_nonce_count > 0 {
        let compute = storage_removes_compute(
            &config.wasm_config.ext_costs,
            remove_result.gas_key_nonce_count,
            remove_result.gas_key_nonce_total_key_bytes,
            AccessKey::NONCE_VALUE_LEN * remove_result.gas_key_nonce_count,
        );
        result.compute_usage = safe_add_compute(result.compute_usage, compute).map_err(|_| {
            StorageError::StorageInconsistentState("compute_usage overflow".to_string())
        })?;
    }
    *actor_id = receipt.predecessor_id().clone();
    *account = None;
    Ok(())
}

pub(crate) fn check_actor_permissions(
    action: &Action,
    account: &Option<Account>,
    actor_id: &AccountId,
    account_id: &AccountId,
) -> Result<(), ActionError> {
    match action {
        Action::DeployContract(_)
        | Action::Stake(_)
        | Action::AddKey(_)
        | Action::DeleteKey(_)
        | Action::DeployGlobalContract(_)
        | Action::UseGlobalContract(_)
        | Action::WithdrawFromGasKey(_) => {
            if actor_id != account_id {
                return Err(ActionErrorKind::ActorNoPermission {
                    account_id: account_id.clone(),
                    actor_id: actor_id.clone(),
                }
                .into());
            }
        }
        Action::DeleteAccount(_) => {
            if actor_id != account_id {
                return Err(ActionErrorKind::ActorNoPermission {
                    account_id: account_id.clone(),
                    actor_id: actor_id.clone(),
                }
                .into());
            }
            let account = account.as_ref().unwrap();
            if !account.locked().is_zero() {
                return Err(ActionErrorKind::DeleteAccountStaking {
                    account_id: account_id.clone(),
                }
                .into());
            }
        }
        Action::CreateAccount(_)
        | Action::FunctionCall(_)
        | Action::Transfer(_)
        | Action::TransferToGasKey(_) => (),
        Action::Delegate(_) | Action::DelegateV2(_) => (),
        Action::DeterministicStateInit(_) => (),
    };
    Ok(())
}

    fn process_action_receipt(
        &self,
        receipt: &Receipt,
        receipt_sink: &mut ReceiptSink,
        instant_receipts: &mut VecDeque<Receipt>,
        validator_proposals: &mut Vec<ValidatorStake>,
        state_update: &mut TrieUpdate,
        apply_state: &ApplyState,
        epoch_info_provider: &dyn EpochInfoProvider,
        pipeline_manager: &ReceiptPreparationPipeline,
        stats: &mut ChunkApplyStatsV1,
        account_id: &AccountId,
        action_receipt: VersionedActionReceipt<'_>,
        receipt_to_tx: &mut Vec<(CryptoHash, ReceiptToTxInfo)>,
    ) -> Result<Option<ExecutionOutcomeWithId>, RuntimeError> {
        let mut pending_data_count: u32 = 0;
        for data_id in action_receipt.input_data_ids() {
            if !has_received_data(state_update, account_id, *data_id)? {
                pending_data_count += 1;
                // The data for a given data_id is not available, so we save a link to this
                // receipt_id for the pending data_id into the state.
                set(
                    state_update,
                    TrieKey::PostponedReceiptId {
                        receiver_id: account_id.clone(),
                        data_id: *data_id,
                    },
                    receipt.receipt_id(),
                )
            }
        }

        if pending_data_count == 0 {
            // All input data is available. Executing the receipt. It will cleanup
            // input data from the state.
            return self
                .apply_action_receipt(
                    state_update,
                    apply_state,
                    pipeline_manager,
                    receipt,
                    receipt_sink,
                    instant_receipts,
                    validator_proposals,
                    stats,
                    epoch_info_provider,
                    receipt_to_tx,
                )
                .map(Some);
        } else {
            // Not all input data is available now.
            // Save the counter for the number of pending input data items into the state.
            set(
                state_update,
                TrieKey::PendingDataCount {
                    receiver_id: account_id.clone(),
                    receipt_id: *receipt.receipt_id(),
                },
                &pending_data_count,
            );
            // Save the receipt itself into the state.
            set_postponed_receipt(state_update, receipt);
        }

        Ok(None)
    }
