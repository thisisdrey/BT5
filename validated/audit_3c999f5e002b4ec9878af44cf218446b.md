The premise of this question is incorrect. `Amounts<T>` derives `Deserialize` directly as a transparent wrapper over `T` (e.g., `BTreeMap<TokenId, i128>`), with no custom deserialization logic that sums duplicate keys: [1](#0-0) 

Standard serde/serde_json map deserialization for duplicate JSON keys does **not** sum the values — it simply keeps the last occurrence (last-key-wins), overwriting earlier entries. `Amounts::with_apply_deltas` (the function referenced in the question) is a separate Rust-level combinator used only programmatically (e.g., in test code) to sum deltas across multiple `TokenDiff` intents; it is never invoked during JSON deserialization of a single `TokenDiff.diff` field, confirmed by the `#[serde_as(as = "Amounts<BTreeMap<_, DisplayFromStr>>")]` attribute on `diff` which relies on the plain derived `Deserialize`: [2](#0-1) 

Consequently, `TokenDiff::execute_intent`'s per-key zero check operates on exactly the same single collapsed value per `TokenId` that later flows into `internal_apply_deltas` and the `TransferMatcher`: [3](#0-2) 

There is no divergence between what the `if *delta == 0` guard sees and what `TransferMatcher::add_delta` sees — both consume the identical post-deserialization `BTreeMap<TokenId, i128>`. A JSON payload with duplicate keys for the same `TokenId` cannot register two separate deltas (e.g., -100 and +100) simultaneously; it collapses to a single last-value entry before any Rust code (including the zero check) ever runs. If that final value is non-zero, the check passes and `TransferMatcher` correctly registers exactly that non-zero value (no smuggled zero-net pair). If the final value is zero, the existing check correctly rejects it. The `test_transfers`/`test_unmatched` unit tests further confirm `TransferMatcher::finalize` requires deltas across all accounts to net to zero per token or it returns `InvariantViolated::UnmatchedDeltas`: [4](#0-3) [5](#0-4)

    // Finalizes all transfers, or returns unmatched deltas.
    // If unmatched deltas overflow, then Err(None) is returned.
    pub fn finalize(self) -> Result<Transfers, InvariantViolated> {
        let mut transfers = Transfers::default();
        let mut deltas = TokenDeltas::default();
        for (token_id, transfer_matcher) in self.0 {
            if let Err(unmatched) = transfer_matcher.finalize_into(&token_id, &mut transfers)
                && (unmatched == 0 || deltas.apply_delta(token_id, unmatched).is_none())
            {
                return Err(InvariantViolated::Overflow);
            }
        }
        if !deltas.is_empty() {
            return Err(InvariantViolated::UnmatchedDeltas {
                unmatched_deltas: deltas,
            });
        }
        Ok(transfers)
    }
