### Title
Stale stake-derived QoS classification allows de-staked/slashed peers to retain elevated QUIC connection privileges - (File: streamer/src/nonblocking/quic.rs, streamer/src/nonblocking/swqos.rs)

### Summary
The reported Venus bug class is: authorization state (`trustedRemoteLookup`) is checked once, a privileged/queued action is derived from that check, and if the authorization is later revoked, previously-derived state (the queued failed message) is still honored without re-validating current authorization. The closest reachable analog in the unprivileged QUIC/UDP streamer path is that a connection's stake-derived `ConnectionPeerType` (staked vs. unstaked, and the specific stake amount) is computed **once** at connection acceptance via `build_connection_context()` / `get_connection_stake()` [1](#0-0)  and then cached for the lifetime of the connection in `ConnectionEntry.peer_type` [2](#0-1) , without being re-validated against `StakedNodes` while the connection remains open.

### Finding Description
`StakedNodesUpdaterService` refreshes the global `staked_nodes` map every 5 seconds from the root bank's current epoch stakes [3](#0-2) . However, per-connection QoS state (`SwQosConnectionContext::peer_type`/`total_stake`, `SimpleQosConnectionContext::peer_type`) is derived only at connection-establishment time from a single lookup against `staked_nodes` [1](#0-0)  and then stored as an immutable field on `SwQosConnectionContext`/`ConnectionEntry` for the entire life of the QUIC connection [4](#0-3) [2](#0-1) .

This cached `peer_type` is subsequently used to determine `max_streams_per_throttling_interval` (stream-rate quota), `compute_max_allowed_uni_streams_with_rtt` (per-connection stream concurrency), and prune-eligibility/threshold in `prune_random` (staked connections are protected relative to their cached stake value) [5](#0-4) [6](#0-5) [7](#0-6) . There is no periodic re-check of the connection's stake against the live `staked_nodes` map, and no mechanism that closes or downgrades a connection when the underlying validator's stake is reduced or removed in a later epoch.

This is structurally the same bug pattern as the report: a privileged classification (`trustedRemoteLookup` entry / `ConnectionPeerType::Staked(stake)`) is captured at one point in time and continues to be honored for actions/behavior that occur after the classification would no longer hold if re-checked (`retryMessage()` / ongoing QUIC stream admission and pruning-resistance).

### Impact Explanation
If a validator's stake is reduced to zero or heavily slashed in a subsequent epoch (a normal, permissionless, protocol-level event — not an operator/admin action), any QUIC connection it opened before the stake change keeps its `ConnectionPeerType::Staked(old_stake)` classification for the connection's entire lifetime. This grants continued elevated stream throughput (`compute_max_allowed_uni_streams_with_rtt`, `available_load_capacity_in_throttling_duration`) and pruning resistance (`prune_random` compares against the now-stale, possibly much higher, stake value) relative to genuinely unstaked/low-stake peers. This is a QoS-evasion vector: an attacker who briefly holds/held stake can keep long-lived QUIC connections open to continue consuming a disproportionate share of the staked-connection quota and stream budget after their stake is gone, at the expense of legitimate staked or unstaked traffic.

### Likelihood Explanation
Stake changes across epoch boundaries are routine and permissionless (undelegate/deactivate stake, stake redistribution). Establishing a long-lived QUIC connection while staked and then keeping it open across an epoch boundary where stake drops requires no privileged access — any TPU/TPU-vote client can do this. The `StakedNodesUpdaterService` already demonstrates that the authoritative stake table changes every 5 seconds without any corresponding connection re-validation, so the staleness window can persist indefinitely as long as the connection is kept alive (bounded only by QUIC idle timeouts, not stake freshness).

### Recommendation
Periodically re-validate each open connection's stake against the current `staked_nodes` table (e.g., on a timer alongside `StakedNodesUpdaterService`'s refresh, or lazily on each `try_add_connection`/stream-accept event) and downgrade/reclassify or close connections whose backing stake has dropped, mirroring the recommendation in the report to explicitly re-check trust/authorization before honoring privileged behavior rather than relying on a value cached at connection-open time.

### Proof of Concept
Conceptual PoC (not exploiting a specific test, since no test in the indexed code exercises stake-decrease-after-connect):
1. Node A stakes enough lamports to qualify as `ConnectionPeerType::Staked(stake)` and opens a QUIC connection to a validator's TPU; `build_connection_context()` records `peer_type = Staked(stake)` for the connection [8](#0-7) .
2. Node A fully deactivates/withdraws its stake in the next epoch; after `StAKE_REFRESH_CYCLE` (5s) `staked_nodes` is updated to reflect `stake == 0` for Node A [3](#0-2) .
3. Node A keeps the existing QUIC connection open (no reconnection). Its `ConnectionEntry`/`SwQosConnectionContext` still carries the old `Staked(stake)` value, so it continues to receive the elevated `max_streams_per_throttling_interval` quota and `prune_random` protection computed from the stale stake, unlike a newly-connecting unstaked peer with identical (zero) current stake.

This cannot be fully confirmed against a runnable end-to-end test in the indexed snippets — I was not able to find a test in `streamer/src/nonblocking/quic.rs` or `swqos.rs` that specifically exercises "stake decreases while connection remains open," so the exact behavioral confirmation (e.g., whether some other component eventually kills the connection) would need to be verified by tracing the full connection lifecycle in a live/checked-out copy of the repo.

    pub(crate) fn prune_random(&mut self, sample_size: usize, threshold_stake: u64) -> usize {
        let num_pruned = std::iter::once(self.table.len())
            .filter(|&size| size > 0)
            .flat_map(|size| {
                let mut rng = rng();
                repeat_with(move || rng.random_range(0..size))
            })
            .map(|index| {
                let connection = self.table[index].first();
                let stake = connection.map(|connection: &ConnectionEntry<S>| connection.stake());
                (index, stake)
            })
            .take(sample_size)
            .min_by_key(|&(_, stake)| stake)
            .filter(|&(_, stake)| stake < Some(threshold_stake))
            .and_then(|(index, _)| self.table.swap_remove_index(index))
            .map(|(_, connections)| connections.len())
            .unwrap_or_default();
        self.total_size = self.total_size.saturating_sub(num_pruned);
        num_pruned
    }

pub struct StakedNodesUpdaterService {

impl StakedNodesUpdaterService {
    pub fn new(
        exit: Arc<AtomicBool>,
        bank_forks: Arc<RwLock<BankForks>>,
        staked_nodes: Arc<RwLock<StakedNodes>>,
        staked_nodes_overrides: Arc<RwLock<HashMap<Pubkey, u64>>>,
    ) -> Self {
        let thread_hdl = Builder::new()
            .name("solStakedNodeUd".to_string())
            .spawn(move || {
                while !exit.load(Ordering::Relaxed) {
                    let stakes = {
                        let root_bank = bank_forks.read().unwrap().root_bank();
                        root_bank.current_epoch_staked_nodes()
                    };
                    let overrides = staked_nodes_overrides.read().unwrap().clone();
                    *staked_nodes.write().unwrap() = StakedNodes::new(stakes, overrides);
                    std::thread::sleep(STAKE_REFRESH_CYCLE);
                }
            })
            .unwrap();

                remote_addr.port(),

                conn_context.peer_type(),
                conn_context.last_update.clone(),
                max_connections_per_peer,
                || Arc::new(ConnectionStreamCounter::new()),

            drop(connection_table_l);

            connection.set_max_concurrent_uni_streams(max_uni_streams);

                conn_context.total_stake,

    fn build_connection_context(&self, connection: &Connection) -> SwQosConnectionContext {
        let remote_address = connection.remote_address();
        get_connection_stake(connection, &self.staked_nodes).map_or(
            SwQosConnectionContext {
                peer_type: ConnectionPeerType::Unstaked,
                total_stake: 0,
                remote_pubkey: None,
                in_staked_table: false,
                remote_address,
                stream_counter: None,
                last_update: Arc::new(AtomicU64::new(timing::timestamp())),
            },
            |(pubkey, stake, total_stake)| {
                // The heuristic is that the stake should be large enough to have 1 stream pass through within one throttle
                // interval during which we allow max (MAX_STREAMS_PER_MS * STREAM_THROTTLING_INTERVAL_MS) streams.

                let peer_type = {
                    let max_streams_per_ms = self.staked_stream_load_ema.max_streams_per_ms();
                    let min_stake_ratio =
                        1_f64 / (max_streams_per_ms * STREAM_THROTTLING_INTERVAL_MS) as f64;
                    let stake_ratio = stake as f64 / total_stake as f64;
                    if stake_ratio < min_stake_ratio {
                        // If it is a staked connection with ultra low stake ratio, treat it as unstaked.
                        ConnectionPeerType::Unstaked
                    } else {
                        ConnectionPeerType::Staked(stake)
                    }
                };

                SwQosConnectionContext {
                    peer_type,
                    total_stake,
                    remote_pubkey: Some(pubkey),
                    in_staked_table: false,
                    remote_address,
                    last_update: Arc::new(AtomicU64::new(timing::timestamp())),
                    stream_counter: None,
                }
            },
        )
    }
