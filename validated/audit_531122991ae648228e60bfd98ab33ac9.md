Based on my research, I found a concrete, remotely-reachable analog: the Atlas attachment downloader resolves peer-supplied data URLs via DNS and then connects directly to whatever the resolver returns, with **no private/loopback/link-local IP filtering** anywhere in that path — unlike the analogous mempool-sync and neighbor-registration code paths in the same crate, which do filter on `PeerAddress::is_in_private_range()` before connecting.

### Title
Atlas attachment downloader SSRF: resolved DNS/data-URL addresses are never checked against `is_in_private_range()` before connecting - (File: `stackslib/src/net/atlas/download.rs`)

### Summary
`AttachmentsDownloader`/`AttachmentsBatchStateMachine` resolves attacker-influenced `UrlString` peer data URLs (obtained from other nodes' handshake/`data_url` gossip and stored in `AtlasDB`) through `BatchedDNSLookupsState::try_proceed`, which stores the raw resolved `SocketAddr`s in `dns_lookups` [1](#0-0) . These addresses are later handed to `PeerNetwork::begin_request`/`connect_or_send_http_request` to open a TCP connection and issue an HTTP GET for attachment inventories/data with no filtering step in between [2](#0-1) [3](#0-2) .

### Finding Description
Other similarly-shaped state machines in this codebase (mempool sync, neighbor registration/handshake, StackerDB replica selection) all gate on `PeerAddress::from_socketaddr(addr).is_in_private_range()` (or `NeighborKey`/`NeighborAddress` equivalents) immediately before establishing a connection or accepting a peer:
- Mempool sync explicitly checks `is_in_private_range()` on the resolved `addr` right before `mempool_sync_send_query` [4](#0-3) .
- Peer registration rejects private-range `NeighborKey`s unless `private_neighbors` is set [5](#0-4) .
- Neighbor-walk and StackerDB-sync neighbor selection filter private addresses the same way [6](#0-5) [7](#0-6) .

The Atlas attachment-download path has no such gate anywhere in its pipeline: `BatchedDNSLookupsState` resolves the domain and stores the raw `SocketAddr` list [1](#0-0) ; `BatchedRequestsState::try_proceed` (via `PeerNetwork::begin_request`) iterates those addresses and calls `network.connect_or_send_http_request(url, *addr, request)` directly [8](#0-7) ; `connect_or_send_http_request`/`connect_http` open a raw TCP socket to that address with no IP-class check [3](#0-2) [9](#0-8) . The equality that should hold — "an address only reachable if it passed the same private-range policy enforced everywhere else in `net/`" — is broken here: any data URL a remote peer can get into `AtlasDB`/gossip (any hostname the attacker controls) is dereferenced and connected to, including one that resolves to `127.0.0.1`, RFC1918 space, or link-local metadata endpoints such as `169.254.169.254`, regardless of the node's `private_neighbors`/`connection_opts` policy (which the rest of `net/` respects). This is the same class of bug as the reported `datamodel-code-generator` issue — an SSRF because a fetch target's resolved address is never validated against the node's private-network policy — except here the gap is not TOCTOU between two resolutions, but a total absence of the check on this one, single-resolution code path.

### Impact Explanation
An attacker-controlled or attacker-influenced Atlas `data_url` (advertised via handshake/gossip and persisted for attachment sourcing) causes the node to make outbound HTTP GET requests to attacker-chosen private/loopback/link-local addresses, including probing internal services and cloud metadata endpoints, and to parse+act on the HTTP response as attachment-inventory/attachment data. This matches the Critical bar of "unauthenticated ... memory disclosure" / SSRF-class reachable-from-remote-gossip impact, since it bypasses the private-IP policy that every other subsystem in `net/` enforces.

### Likelihood Explanation
Reachable by any remote, unprivileged peer that can get a `data_url` into the target's Atlas attachment/neighbor state (via ordinary handshake/gossip), and then advertise attachments with content the target will attempt to download from that URL — no special role or secret key is required, and `connection_opts.private_neighbors` (default `false`) is meant to prevent exactly this, but is not consulted on this path.

### Recommendation
Before calling `connect_or_send_http_request`/`connect_http` in the Atlas download state machines (`stackslib/src/net/atlas/download.rs`, `BatchedRequestsState::try_proceed`), filter resolved `SocketAddr`s the same way `mempool_sync_resolve_data_url`/`mempool_sync_send_query` do: reject addresses where `PeerAddress::from_socketaddr(addr).is_in_private_range()` unless `connection_opts.private_neighbors` is set, mirroring `stackslib/src/net/mempool/mod.rs:485-498`.

### Proof of Concept
1. Run a malicious Stacks node that handshakes with the target and advertises a `data_url` pointing at attacker-controlled DNS (e.g. `evil.example.com`), which resolves to a public IP the first few times any generic health check might occur but ultimately to `169.254.169.254` or `127.0.0.1` for the address actually used by the downloader.
2. Get an `AttachmentInstance`/inventory referencing that peer registered in the target's `AtlasDB` (via ordinary block/attachment gossip).
3. Observe the target's `AttachmentsDownloader` resolve the domain via `BatchedDNSLookupsState` and then issue `GET /v2/attachments/<hash>` (or the inventory endpoint) directly to the resolved private/loopback address via `connect_or_send_http_request`, with no `is_in_private_range` check anywhere in `stackslib/src/net/atlas/download.rs`.

    pub fn connect_or_send_http_request(
        &mut self,
        data_url: UrlString,
        addr: SocketAddr,
        request: StacksHttpRequest,
    ) -> Result<usize, NetError> {
        PeerNetwork::with_network_state(self, |ref mut network, ref mut network_state| {
            PeerNetwork::with_http(network, |ref mut network, ref mut http| {
                match http.connect_http(
                    network_state,
                    network,
                    data_url.clone(),
                    addr,
                    Some(request.clone()),
                ) {
                    Ok(event_id) => Ok(event_id),
                    Err(NetError::AlreadyConnected(event_id, _)) => {
                        if let (Some(ref mut convo), Some(ref mut socket)) =
                            http.get_conversation_and_socket(event_id)
                        {
                            convo.send_request(request)?;
                            HttpPeer::saturate_http_socket(socket, convo)?;
                            Ok(event_id)
                        } else {
                            debug!("HTTP failed to connect to {data_url}, {addr:?}");
                            Err(NetError::PeerNotConnected(format!(
                                "HTTP failed to connect to {data_url}, {addr:?}",
                            )))
                        }
                    }
                    Err(e) => Err(e),
                }
            })
        })
    }

    pub fn connect_http(
        &mut self,
        network_state: &mut NetworkState,
        network: &PeerNetwork,
        data_url: UrlString,
        addr: SocketAddr,
        request: Option<StacksHttpRequest>,
    ) -> Result<usize, net_error> {
        if let Some(event_id) = self.find_free_conversation(&data_url) {
            let http_nk = NeighborKey {
                peer_version: network.burnchain.peer_version,
                network_id: network.local_peer.network_id,
                addrbytes: PeerAddress::from_socketaddr(&addr),
                port: addr.port(),
            };
            return Err(net_error::AlreadyConnected(event_id, http_nk));
        }

        let sock = NetworkState::connect(
            &addr,
            network.connection_opts.socket_send_buffer_size,
            network.connection_opts.socket_recv_buffer_size,
        )?;
        let hint_event_id = network_state.next_event_id()?;
        let next_event_id =
            network_state.register(self.http_server_handle, hint_event_id, &sock)?;

        self.connecting.insert(
            next_event_id,
            (sock, Some(data_url), request, get_epoch_time_secs()),
        );
        Ok(next_event_id)
    }
