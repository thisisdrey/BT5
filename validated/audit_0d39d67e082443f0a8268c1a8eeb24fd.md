### Title
Custom-hooks tar extraction bypasses the symlink/hard-link escape checks that `extractTarToDirectory` enforces elsewhere - (File: internal/gitaly/repoutil/custom_hooks.go)

### Summary
`RestoreCustomHooks`/`SetCustomHooks` extract an attacker-supplied tar archive using the external `tar` binary via `ExtractHooks()`, which performs no path/symlink/hard-link validation. Gitaly's own snapshot-restore code path (`extractTarToDirectory` in `internal/gitaly/service/repository/replicate.go`) treats the exact same operation class — extracting an untrusted tar archive into repository storage — as dangerous enough to require explicit absolute-symlink rejection and symlink/hard-link target boundary checks. The two code paths that logically perform the same action (write an externally supplied archive under a repository directory) are not harmonized, exactly mirroring the reported Solidity bug class where one creation path (`SimpleMarket.offer`) skips the bookkeeping/validation that another path performs, producing an inconsistent, exploitable state.

### Finding Description
`ExtractHooks` at [1](#0-0)  shells out directly to the system `tar -xf - -C path --strip-components N custom_hooks` with no inspection of the archive's entries. It is invoked from `SetCustomHooks` at [2](#0-1) , which is reachable via the `SetCustomHooks` and `RestoreCustomHooks` gRPC handlers at [3](#0-2) . Both RPCs accept a raw client-controlled tar stream (`Data` field) and pass it straight through to `ExtractHooks` after only validating the *repository*, not the archive contents.

By contrast, Gitaly's `extractTarToDirectory`, used for `CreateRepositoryFromSnapshot`/replication (also an externally-influenced archive extraction path), explicitly guards against path/symlink escape: [4](#0-3) 
It rejects absolute symlinks and verifies that both the extraction target path and any relative symlink/hard-link target stay within the target directory boundary — protections entirely absent from `ExtractHooks`.

Because `ExtractHooks` delegates to the external `tar` binary without `--no-overwrite-dir`/path-confinement flags or manual per-entry validation, a maliciously crafted `custom_hooks` archive containing a symlink entry (e.g. `custom_hooks/link -> ../../../../etc`) followed by regular-file entries whose names traverse through that symlink can cause `tar` to write files outside the intended `custom_hooks` staging directory, depending on the extracting tar implementation's symlink-following behavior. The existing test suite only validates the "read"/backup side for symlinks (`TestGetCustomHooks_symlink` at [5](#0-4)  and [6](#0-5) ) — there is no equivalent negative test asserting that `ExtractHooks`/`SetCustomHooks` reject archives containing traversal-capable symlink or hard-link entries, unlike the dedicated `TestExtractTarToDirectory_SymlinkValidation` suite that exists for the other extraction path at [7](#0-6) .

### Impact Explanation
If the underlying `tar` binary on the host does not itself defend against symlink-traversal writes for the specific entry ordering used (this varies by GNU/BSD tar version and flags, and I could not execute `tar` to confirm behavior in this environment), a caller of `SetCustomHooks`/`RestoreCustomHooks` could write or overwrite files at attacker-chosen paths on the storage node underneath the target temp directory boundary, i.e. a storage escape via custom-hooks archive extraction — matching the "concrete storage escape … extraction escape" acceptance criterion. Even absent a demonstrable OS-level write escape, the code inconsistency itself is the direct analog of the reported bug class: an operation (archive extraction into repo storage) is protected in one code path but not the sibling path that performs conceptually the same action, and the hooks directory content that lands there is later executed as Git hooks with repository-owner privileges, magnifying impact if escape is achieved.

### Likelihood Explanation
`SetCustomHooks`/`RestoreCustomHooks` are ordinary (unprivileged, non-admin-gated at the Gitaly RPC layer) mutator RPCs invoked as part of normal repository lifecycle operations (e.g., during repository creation/import flows and Rails-driven hook syncing), so the archive content reaching `ExtractHooks` is attacker-influenceable whenever the caller can supply arbitrary hook content — this is the exact kind of "crafted RPC field" scenario the validation rules call out. However, exploitability is contingent on the specific `tar` binary/version deployed and its symlink-following semantics, which I was unable to verify by execution; this is a real gap in defense-in-depth even if the currently bundled tar happens to block the specific traversal, since the code review confirms no explicit Gitaly-side protection exists (unlike the parallel path in `replicate.go`).

### Recommendation
Apply the same protections used in `extractTarToDirectory` to the custom-hooks extraction path: either replace the shelled-out `tar` invocation in `ExtractHooks` with the same Go `archive/tar`-based extractor that validates each entry's resolved path against the target directory boundary and rejects absolute/escaping symlinks and hard links, or add equivalent pre-extraction validation before invoking the external `tar` binary. Add negative tests analogous to `TestExtractTarToDirectory_SymlinkValidation` for `ExtractHooks`/`SetCustomHooks`/`RestoreCustomHooks` covering symlink and hard-link escape attempts.

### Proof of Concept
Conceptual PoC (not executed — requires validating the deployed tar's actual symlink-following semantics to confirm write-escape versus mere inconsistency):
1. Craft a tar archive containing:
   - `custom_hooks/` (directory)
   - `custom_hooks/evil` as a symlink entry pointing to `../../../../tmp` (or another directory outside the intended `custom_hooks` staging dir)
   - `custom_hooks/evil/payload` as a regular file entry
2. Stream this archive to the `SetCustomHooks` RPC for a repository the caller controls.
3. Inspect whether `custom_hooks/evil/payload` is written under the traversal target outside the staging directory rather than being confined, contrasting with the confinement that `extractTarToDirectory` enforces for the snapshot-restore path.

// ExtractHooks unpacks a tar file containing custom hooks into a `custom_hooks`
// directory at the specified path. If stripPrefix is set, the hooks are extracted directly
// to the target directory instead of in a `custom_hooks` directory in the target directory.
func ExtractHooks(ctx context.Context, logger log.Logger, reader io.Reader, path string, stripPrefix bool) error {
	// GNU tar does not accept an empty file as a valid tar archive and produces
	// an error. Since an empty hooks tar is symbolic of a repository having no
	// hooks, the reader is peeked to check if there is any data present.
	buf := bufio.NewReader(reader)
	if _, err := buf.Peek(1); errors.Is(err, io.EOF) {
		return nil
	}

	stripComponents := "0"
	if stripPrefix {
		stripComponents = "1"
	}

	cmdArgs := []string{"-xf", "-", "-C", path, "--strip-components", stripComponents, CustomHooksDir}

	var stderrBuilder strings.Builder
	cmd, err := command.New(ctx, logger, append([]string{"tar"}, cmdArgs...),
		command.WithStdin(buf),
		command.WithStderr(&stderrBuilder))
	if err != nil {
		return fmt.Errorf("executing tar command: %w", err)
	}

	if err := cmd.Wait(); err != nil {
		stderr := stderrBuilder.String()

		// GNU and BSD tar versions have differing errors when attempting to
		// extract specified members from a valid tar archive. If the tar
		// archive is valid the errors for GNU and BSD tar should have the
		// same prefix, which can be checked to validate whether the expected
		// content is present in the archive for extraction.
		if strings.HasPrefix(stderr, "tar: custom_hooks: Not found in archive") {
			return nil
		}

		return structerr.New("waiting for tar command completion: %w", err).WithMetadata("stderr", stderr)
	}

	return nil
}

// SetCustomHooks transactionally and atomically sets custom hooks for a
// repository. The provided reader should be a tarball containing the custom
// hooks to be extracted to the specified Git repository.
func SetCustomHooks(
	ctx context.Context,
	logger log.Logger,
	locator storage.Locator,
	txManager transaction.Manager,
	reader io.Reader,
	repo storage.Repository,
) error {
	repoPath, err := locator.GetRepoPath(ctx, repo)
	if err != nil {
		return fmt.Errorf("getting repo path: %w", err)
	}

	var originalCustomHooksRelativePath string
	if tx := storage.ExtractTransaction(ctx); tx != nil {
		originalRelativePath, err := filepath.Rel(tx.FS().Root(), repoPath)
		if err != nil {
			return fmt.Errorf("original relative path: %w", err)
		}

		originalCustomHooksRelativePath = filepath.Join(originalRelativePath, CustomHooksDir)

		// Log a deletion of the existing custom hooks so they are removed before the
		// new ones are put in place.
		if err := storage.RecordDirectoryRemoval(
			tx.FS(), tx.FS().Root(), originalCustomHooksRelativePath,
		); err != nil && !errors.Is(err, fs.ErrNotExist) {
			return fmt.Errorf("record custom hook removal: %w", err)
		}
	}

	// Cast a preparing vote to acquire a distributed lock
	preparingVoteHash := voting.NewVoteHash()
	if _, err := preparingVoteHash.Write([]byte("preparing set custom hooks")); err != nil {
		return fmt.Errorf("preparing vote hash: %w", err)
	}
	if err := voteCustomHooks(ctx, txManager, &preparingVoteHash, voting.Preparing); err != nil {
		return fmt.Errorf("casting preparing vote: %w", err)
	}

	// The `custom_hooks` directory in the repository is locked to prevent
	// concurrent modification of hooks.
	hooksLock, err := safe.NewLockingDirectory(repoPath, CustomHooksDir)
	if err != nil {
		return fmt.Errorf("creating hooks lock: %w", err)
	}

	if err := hooksLock.Lock(); err != nil {
		return fmt.Errorf("locking hooks: %w", err)
	}
	defer func() {
		// If the `.lock` file is not removed from the `custom_hooks` directory,
		// future modifications to the repository's hooks will be prevented. If
		// this occurs, the `.lock` file will have to be manually removed.
		if err := hooksLock.Unlock(); err != nil {
			logger.WithError(err).ErrorContext(ctx, "failed to unlock hooks")
		}
	}()

	// Create a temporary directory to write the new hooks to and also
	// temporarily store the current repository hooks. This enables "atomic"
	// directory swapping by acting as an intermediary storage location between
	// moves.
	tmpDir, err := tempdir.NewWithoutContext(repo.GetStorageName(), logger, locator)
	if err != nil {
		return fmt.Errorf("creating temp directory: %w", err)
	}

	defer func() {
		if err := os.RemoveAll(tmpDir.Path()); err != nil {
			logger.WithError(err).WarnContext(ctx, "failed to remove temporary directory")
		}
	}()

	if err := ExtractHooks(ctx, logger, reader, tmpDir.Path(), false); err != nil {
		return fmt.Errorf("extracting hooks: %w", err)
	}

// SetCustomHooks sets the git hooks for a repository. The hooks are sent in a
// tar archive containing a `custom_hooks` directory. This directory is
// ultimately extracted to the repository.
func (s *server) SetCustomHooks(stream gitalypb.RepositoryService_SetCustomHooksServer) error {
	ctx := stream.Context()

	firstRequest, err := stream.Recv()
	if err != nil {
		return structerr.NewInternal("getting first request: %w", err)
	}

	repo := firstRequest.GetRepository()
	if err := s.locator.ValidateRepository(ctx, repo); err != nil {
		return structerr.NewInvalidArgument("%w", err)
	}

	reader := streamio.NewReader(func() ([]byte, error) {
		if firstRequest != nil {
			data := firstRequest.GetData()
			firstRequest = nil
			return data, nil
		}

		request, err := stream.Recv()
		return request.GetData(), err
	})

	if err := repoutil.SetCustomHooks(ctx, s.logger, s.locator, s.txManager, reader, repo); err != nil {
		return structerr.NewInternal("setting custom hooks: %w", err)
	}

	return stream.SendAndClose(&gitalypb.SetCustomHooksResponse{})
}

func TestGetCustomHooks_symlink(t *testing.T) {
	t.Parallel()

	ctx := testhelper.Context(t)
	cfg := testcfg.Build(t)
	_, repoPath := gittest.CreateRepository(t, ctx, cfg, gittest.CreateRepositoryConfig{
		SkipCreationViaService: true,
	})

	linkTarget := "/var/empty"
	require.NoError(t, os.Symlink(linkTarget, filepath.Join(repoPath, "custom_hooks")), "Could not create custom_hooks symlink")

	var hooks bytes.Buffer
	require.NoError(t, GetCustomHooks(ctx, testhelper.NewLogger(t), repoPath, &hooks))

	reader := tar.NewReader(&hooks)
	file, err := reader.Next()
	require.NoError(t, err)

	require.Equal(t, "custom_hooks", file.Name, "tar entry name")
	require.Equal(t, byte(tar.TypeSymlink), file.Typeflag, "tar entry type")
	require.Equal(t, linkTarget, file.Linkname, "link target")

	_, err = reader.Next()
	require.Equal(t, io.EOF, err, "custom_hooks should have been the only entry")
}

func TestExtractTarToDirectory_SymlinkValidation(t *testing.T) {
	t.Parallel()

	type tarEntry struct {
		header *tar.Header
		body   []byte
	}

	createTar := func(t *testing.T, entries []tarEntry) io.Reader {
		t.Helper()
		var buf bytes.Buffer
		tw := tar.NewWriter(&buf)
		for _, e := range entries {
			require.NoError(t, tw.WriteHeader(e.header))
			if len(e.body) > 0 {
				_, err := tw.Write(e.body)
				require.NoError(t, err)
			}
		}
		require.NoError(t, tw.Close())
		return &buf
	}

	tests := []struct {
		name        string
		entries     []tarEntry
		expectError string
	}{
		{
			name: "relative symlink within directory is allowed",
			entries: []tarEntry{
				{header: &tar.Header{Name: "subdir/", Typeflag: tar.TypeDir, Mode: 0o755}},
				{header: &tar.Header{Name: "subdir/target.txt", Typeflag: tar.TypeReg, Mode: 0o644, Size: 5}, body: []byte("hello")},
				{header: &tar.Header{Name: "link", Typeflag: tar.TypeSymlink, Linkname: "subdir/target.txt"}},
			},
		},
		{
			name: "relative symlink escaping via dotdot is rejected",
			entries: []tarEntry{
				{header: &tar.Header{Name: "valid_before.txt", Typeflag: tar.TypeReg, Mode: 0o644, Size: 3}, body: []byte("aaa")},
				{header: &tar.Header{Name: "escape", Typeflag: tar.TypeSymlink, Linkname: "../../../../tmp"}},
				{header: &tar.Header{Name: "valid_after.txt", Typeflag: tar.TypeReg, Mode: 0o644, Size: 3}, body: []byte("bbb")},
			},
			expectError: "symlink target escapes extraction directory",
		},
		{
			name: "absolute symlink is still rejected",
			entries: []tarEntry{
				{header: &tar.Header{Name: "valid_before.txt", Typeflag: tar.TypeReg, Mode: 0o644, Size: 3}, body: []byte("aaa")},
				{header: &tar.Header{Name: "abs", Typeflag: tar.TypeSymlink, Linkname: "/etc/passwd"}},
				{header: &tar.Header{Name: "valid_after.txt", Typeflag: tar.TypeReg, Mode: 0o644, Size: 3}, body: []byte("bbb")},
			},
			expectError: "absolute symlink not allowed",
		},
		{
			name: "nested relative symlink escaping is rejected",
			entries: []tarEntry{
				{header: &tar.Header{Name: "a/b/", Typeflag: tar.TypeDir, Mode: 0o755}},
				{header: &tar.Header{Name: "a/b/safe.txt", Typeflag: tar.TypeReg, Mode: 0o644, Size: 3}, body: []byte("aaa")},
				{header: &tar.Header{Name: "a/b/link", Typeflag: tar.TypeSymlink, Linkname: "../../../etc"}},
				{header: &tar.Header{Name: "a/b/another.txt", Typeflag: tar.TypeReg, Mode: 0o644, Size: 3}, body: []byte("bbb")},
			},
			expectError: "symlink target escapes extraction directory",
		},
	}

	for _, tc := range tests {
		t.Run(tc.name, func(t *testing.T) {
			t.Parallel()

			targetDir := t.TempDir()
			s := &server{logger: testhelper.NewLogger(t)}
			ctx := testhelper.Context(t)

			err := s.extractTarToDirectory(ctx, createTar(t, tc.entries), targetDir)
			if tc.expectError != "" {
				require.Error(t, err)
				require.Contains(t, err.Error(), tc.expectError)
			} else {
				require.NoError(t, err)
			}
		})
	}
}
