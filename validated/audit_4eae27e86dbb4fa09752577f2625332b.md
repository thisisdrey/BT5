Based on the investigation, I found a strong local analog in `pallet-psm`'s decimal-scaling logic.

### Title
`pallet-psm::redeem` omits the live-decimals drift check present in `mint`, allowing conversions to run on a stale decimals snapshot — ([File: substrate/frame/psm/src/lib.rs])

### Summary
The external Vader report describes a TWAP oracle miscalculating an exchange rate because it used the wrong quantity (`decimals()` instead of `10**decimals()`) when scaling between two token unit systems, corrupting a value used in a minting flow. The local analog is in `pallet-psm`, which converts between an "internal" (e.g. pUSD) asset and "external" stablecoins of arbitrary decimal precision. The pallet's own documentation states that **both** `mint` and `redeem` must reject with `DecimalsMismatch` if live asset metadata has drifted from the decimals snapshot taken at registration [1](#0-0) . The implementation only enforces this in `mint`, via `Self::ensure_decimals_match(...)` [2](#0-1) , but `redeem` reads the stale snapshot values directly with no live check at all: `let ext_decimals = external.decimals; let internal_decimals = info.internal_decimals;` [3](#0-2) .

### Finding Description
`ensure_decimals_match` is the guard designed to catch decimal drift: it compares the live `T::Fungibles::decimals(...)` for both the external and internal assets against the snapshot values stored in `ExternalAssetInfo`/`PsmInfo` at registration time, returning `Error::DecimalsMismatch` on divergence [4](#0-3) . `mint` calls this guard before doing any scaling arithmetic [5](#0-4) .

`redeem`, however, never calls it. It fetches `external` from `ExternalAssets` and immediately uses the stored (possibly stale) `external.decimals` and `info.internal_decimals` to drive `internal_to_external`/`external_to_internal` scaling and debt accounting [6](#0-5) . These helpers scale amounts by `10^|ext_decimals - internal_decimals|` [7](#0-6) , exactly mirroring the class of bug in the report: an amount is multiplied/divided by a decimals-derived scaling factor without first validating that the decimals figure used still matches on-chain reality.

Any asset whose owner can update its own `decimals` metadata via `pallet_assets::set_metadata` (permitted for the asset's registered owner with no PSM-level permission) [8](#0-7)  can create a divergence between the live decimals and the PSM's registration-time snapshot. Once that happens, `mint` correctly halts with `DecimalsMismatch`, but `redeem` keeps running the conversion math on the outdated snapshot with no re-validation, silently computing external-asset outputs and internal-debt reductions from a decimals value the pallet's own design says must be treated as untrusted at that point.

### Impact Explanation
Because `redeem` is a public, unprivileged, signed extrinsic on an accounting path that moves value out of the PSM reserve (`T::Fungibles::transfer` of `external_out`) and burns internal-asset supply (`T::Fungibles::burn_from`) [9](#0-8) , an incorrect scaling factor here directly corrupts the amount paid out to a user versus the amount of debt/internal asset actually retired. This can result in mispriced settlement (users receiving more or less external asset than their burned internal amount should be worth), or the reserve invariant checks (`ensure!(reserve < external_out ...)`) operating on numbers computed with an untrusted decimals assumption — a direct violation of the "conserve value and settle exactly once" pivot for asset accounting in this program's scope.

### Likelihood Explanation
The trigger requires only that decimals drift for a registered external asset, which the pallet's own migration/registration design (`AssetDecimals` snapshot, `DecimalsMismatch` runtime drift guard mentioned in the prdoc) explicitly anticipates as a real, expected event that pallets need to defend against — the prdoc's stated purpose is precisely to guard both `mint` and `redeem` against this. The missing check is a straightforward code/spec mismatch, not a hypothetical: any signed user calling `redeem` after such drift will exercise the unguarded path, no privileged or adversarial-infrastructure actor is required beyond the ordinary ability of a registered asset's owner to call the standard `set_metadata` extrinsic on their own asset.

### Recommendation
Add the same `Self::ensure_decimals_match(&info, &internal_asset, &external_asset, &external)?` check to `redeem` before computing `ext_decimals`/`internal_decimals`, mirroring `mint`, so that redemption halts with `Error::DecimalsMismatch` under drift exactly as documented, instead of silently continuing arithmetic on a stale snapshot.

### Proof of Concept
1. Register an external asset (e.g. `DAI_MOCK`, 18 decimals) with `pallet-psm`, snapshotting `external.decimals = 18`.
2. As the `DAI_MOCK` asset's registered owner, call `pallet_assets::set_metadata` to change its decimals field (e.g. to 6) [8](#0-7) .
3. Call `Psm::mint(...)` for that asset — it now fails with `Error::DecimalsMismatch` because `ensure_decimals_match` detects the live/snapshot divergence [10](#0-9) .
4. Call `Psm::redeem(...)` for the same asset with an existing internal balance — it succeeds despite the identical decimals divergence, since `redeem` never invokes `ensure_decimals_match` and instead scales with the stale `external.decimals`/`info.internal_decimals` snapshot values directly [11](#0-10) , producing an `external_out`/debt-reduction amount computed with a decimals assumption the pallet's own security model no longer trusts.

		pub(crate) fn external_to_internal(
			amount: BalanceOf<T>,
			ext_decimals: u8,
			internal_decimals: u8,
		) -> Result<BalanceOf<T>, Error<T>> {
			use core::cmp::Ordering::*;
			match ext_decimals.cmp(&internal_decimals) {
				Equal => Ok(amount),
				Less => {
					let diff = (internal_decimals - ext_decimals) as u32;
					let factor = Self::pow10(diff)?;
					amount.checked_mul(&factor).ok_or(Error::<T>::ConversionOverflow)
				},
				Greater => {
					let diff = (ext_decimals - internal_decimals) as u32;
					let factor = Self::pow10(diff)?;
					Ok(amount.checked_div(&factor).unwrap_or_else(BalanceOf::<T>::zero))
				},
			}
		}

		/// Verify the live decimals for an external still match the snapshot taken at
		/// registration on this PSM, and that the internal asset's live decimals still
		/// match the snapshot stored in [`PsmInfo`].
		pub(crate) fn ensure_decimals_match(
			info: &PsmInfo<T>,
			internal_asset: &T::AssetId,
			external_asset: &T::AssetId,
			external: &ExternalAssetInfo,
		) -> Result<(u8, u8), DispatchError> {
			ensure!(
				T::Fungibles::decimals(external_asset.clone()) == external.decimals,
				Error::<T>::DecimalsMismatch
			);
			ensure!(
				T::Fungibles::decimals(internal_asset.clone()) == info.internal_decimals,
				Error::<T>::DecimalsMismatch
			);
			Ok((external.decimals, info.internal_decimals))
		}
