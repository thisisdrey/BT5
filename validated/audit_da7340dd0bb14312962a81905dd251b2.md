### Title
Unstaked QoS per-peer connection limit is keyed by claimed pubkey, not source IP, allowing single-IP identity-spoofing to exhaust the global unstaked connection table - (streamer/src/nonblocking/swqos.rs)

### Summary
`SwQos::build_connection_context` reclassifies any staked identity whose `stake_ratio` is below `min_stake_ratio` to `ConnectionPeerType::Unstaked` while still keeping `remote_pubkey: Some(pubkey)` in the resulting `SwQosConnectionContext`. When admitting the connection, `cache_new_connection` builds the connection-table key via `ConnectionTableKey::new(remote_addr.ip(), conn_context.remote_pubkey)`, which keys by pubkey (not IP) whenever a pubkey is present. This lets a single IP address open unlimited distinct identities, each getting its own `max_connections_per_unstaked_peer` connection allotment in the shared `unstaked_connection_table`, instead of being capped as one IP-scoped peer.

### Finding Description
In `SwQos::build_connection_context` (`streamer/src/nonblocking/swqos.rs:302-342`), any presented pubkey with `stake_ratio < min_stake_ratio` (including pubkeys with zero/unknown stake) is classified `ConnectionPeerType::Unstaked`, but `remote_pubkey` remains `Some(pubkey)`: [1](#0-0) 

In `SwQos::cache_new_connection` (`streamer/src/nonblocking/swqos.rs:181-238`), the connection-table key is derived from `ConnectionTableKey::new(remote_addr.ip(), conn_context.remote_pubkey)` for both staked and unstaked admission paths: [2](#0-1) 

`max_connections_per_peer` is then looked up per `peer_type` (`max_connections_per_unstaked_peer` for `Unstaked`) and enforced against `connection_entry` count under that key in `ConnectionTable::try_add_connection` (`streamer/src/nonblocking/quic.rs:1008-1051`): [3](#0-2) 

Because the key prefers pubkey over IP whenever a pubkey is presented (confirmed by unit tests `test_prune_table_with_unique_pubkeys` and `test_prune_table_with_non_unique_pubkeys`, which show connections keyed purely by `ConnectionTableKey::Pubkey` bypass the per-peer cap that would otherwise apply to a shared IP key): [4](#0-3) [5](#0-4) 

A remote attacker connecting from a single IP with QUIC client certificates presenting distinct, self-signed Ed25519 keypairs will be assigned distinct `ConnectionTableKey::Pubkey(...)` entries in `unstaked_connection_table`, each independently permitted up to `max_connections_per_unstaked_peer` connections. This holds regardless of whether the pubkey is entirely unknown to `staked_nodes` (falls into the `map_or` default `Unstaked` branch with `remote_pubkey: None`, keyed by IP) or is a known low-stake pubkey below `min_stake_ratio` (keyed by pubkey, bypassing the IP-based cap). The attack path requires the latter: the attacker must present pubkeys that resolve via `get_connection_stake` to a nonzero (but sub-`min_stake_ratio`) stake entry in `staked_nodes` to obtain the pubkey-keyed connection-table slot instead of the IP-keyed one used for wholly unknown identities.

### Impact Explanation
This allows a single-IP attacker holding (or spoofing) many distinct low-stake identities to consume a disproportionate share of the shared `unstaked_connection_table` capacity (bounded overall by `max_unstaked_connections`), starving other legitimate unstaked/low-stake senders of connection slots on the TPU/TPU-forward QUIC ports. This falls under the "unprivileged client can bypass or unfairly capture connection/stream/per-IP QoS limits" bounty category. The impact is bounded by the cluster-wide `max_unstaked_connections` cap and by the shared `StakedStreamLoadEMA` stream-throughput throttling (which is not purely per-connection), so aggregate stream throughput may still be globally capped — but connection-slot exhaustion and unfair per-IP capture of connection capacity is real.

### Likelihood Explanation
Preconditions: attacker needs distinct pubkeys that map to nonzero-but-sub-`min_stake_ratio` stake entries in the current `staked_nodes` map (e.g., very small delegators) to be routed through the pubkey-keyed path rather than the IP-keyed "unknown identity" path. This is feasible since low-stake validator/vote identities are public information available via gossip/stake data, and an attacker only needs to control the corresponding keypair or present a matching certificate for identities where the private key is available; note only the ones the attacker actually controls a private key for can complete the QUIC TLS handshake, limiting real-world scale to the number of low-stake keypairs the attacker actually possesses. This is a moderate-likelihood, connection-admission-fairness issue rather than an easily-scriptable unbounded amplification.

### Recommendation
Key unstaked connection admission by source IP address unconditionally (ignore `remote_pubkey` for the `Unstaked` branch of `cache_new_connection`/`ConnectionTableKey` selection), so that `max_connections_per_unstaked_peer` is enforced per source IP regardless of how many distinct sub-threshold identities are presented from that IP.

### Proof of Concept
Integration test plan (extending `streamer/src/nonblocking/swqos.rs` test module):
1. Build `SwQos` with `max_connections_per_unstaked_peer = 1` and a `staked_nodes` map containing many distinct low-stake pubkeys, each with `stake_ratio` below `min_stake_ratio`.
2. From a single bound source IP, open M QUIC connections, each authenticated with a different low-stake keypair from the map.
3. Call `build_connection_context` + `try_add_connection` for each; assert that all M connections are admitted into `unstaked_connection_table` (each under a distinct `ConnectionTableKey::Pubkey`), exceeding `max_connections_per_unstaked_peer * 1` for that single IP — demonstrating the per-IP cap is bypassed.
4. Contrast with a control case using pubkeys entirely absent from `staked_nodes` (falls into the `None`-pubkey `Unstaked` branch, keyed by IP) and confirm only 1 connection is admitted, proving the differential behavior root-caused by the pubkey-based key in the sub-`min_stake_ratio` case.

    #[test]
    fn test_prune_table_with_unique_pubkeys() {
        agave_logger::setup();
        let cancel = CancellationToken::new();
        let mut table = ConnectionTable::new(ConnectionTableType::Unstaked, cancel);

        // We should be able to add more entries than max_connections_per_peer, since each entry is
        // from a different peer pubkey.
        let num_entries = 15;
        let max_connections_per_peer = 10;
        let stats = Arc::new(StreamerStats::default());

        let pubkeys: Vec<_> = (0..num_entries).map(|_| Pubkey::new_unique()).collect();
        for (i, pubkey) in pubkeys.iter().enumerate() {
            table
                .try_add_connection(
                    ConnectionTableKey::Pubkey(*pubkey),
                    0,
                    ClientConnectionTracker::new(stats.clone(), 1000).unwrap(),
                    None,
                    ConnectionPeerType::Unstaked,
                    Arc::new(AtomicU64::new(i as u64)),
                    max_connections_per_peer,
                    || Arc::new(NullStreamerCounter {}),
                )
                .unwrap();
        }

        let new_size = 3;
        let pruned = table.prune_oldest(new_size);
        assert_eq!(pruned, num_entries as usize - new_size);
        assert_eq!(table.table.len(), new_size);
        assert_eq!(table.total_size, new_size);
        for pubkey in pubkeys.iter().take(num_entries as usize).skip(new_size - 1) {
            table.remove_connection(ConnectionTableKey::Pubkey(*pubkey), 0, 0);
        }
        assert_eq!(table.total_size, 0);
        assert_eq!(stats.open_connections.load(Ordering::Relaxed), 0);
    }

    #[test]
    fn test_prune_table_with_non_unique_pubkeys() {
        agave_logger::setup();
        let cancel = CancellationToken::new();
        let mut table = ConnectionTable::new(ConnectionTableType::Unstaked, cancel);

        let max_connections_per_peer = 10;
        let pubkey = Pubkey::new_unique();
        let stats: Arc<StreamerStats> = Arc::new(StreamerStats::default());

        (0..max_connections_per_peer).for_each(|i| {
            table
                .try_add_connection(
                    ConnectionTableKey::Pubkey(pubkey),
                    0,
                    ClientConnectionTracker::new(stats.clone(), 1000).unwrap(),
                    None,
                    ConnectionPeerType::Unstaked,
                    Arc::new(AtomicU64::new(i as u64)),
                    max_connections_per_peer,
                    || Arc::new(NullStreamerCounter {}),
                )
                .unwrap();
        });

        // We should NOT be able to add more entries than max_connections_per_peer, since we are
        // using the same peer pubkey.
        assert!(
            table
                .try_add_connection(
                    ConnectionTableKey::Pubkey(pubkey),
                    0,
                    ClientConnectionTracker::new(stats.clone(), 1000).unwrap(),
                    None,
                    ConnectionPeerType::Unstaked,
                    Arc::new(AtomicU64::new(10)),
                    max_connections_per_peer,
                    || Arc::new(NullStreamerCounter {})
                )
                .is_none()
        );

        // We should be able to add an entry from another peer pubkey
        let num_entries = max_connections_per_peer + 1;
        let pubkey2 = Pubkey::new_unique();
        assert!(
            table
                .try_add_connection(
                    ConnectionTableKey::Pubkey(pubkey2),
                    0,
                    ClientConnectionTracker::new(stats.clone(), 1000).unwrap(),
                    None,
                    ConnectionPeerType::Unstaked,
                    Arc::new(AtomicU64::new(10)),
                    max_connections_per_peer,
                    || Arc::new(NullStreamerCounter {})
                )
                .is_some()
        );

        assert_eq!(table.total_size, num_entries);

        let new_max_size = 3;
        let pruned = table.prune_oldest(new_max_size);
        assert!(pruned >= num_entries - new_max_size);
        assert!(table.table.len() <= new_max_size);
        assert!(table.total_size <= new_max_size);

        table.remove_connection(ConnectionTableKey::Pubkey(pubkey2), 0, 0);
        assert_eq!(table.total_size, 0);
        assert_eq!(stats.open_connections.load(Ordering::Relaxed), 0);
    }
