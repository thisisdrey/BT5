### Title
Unauthenticated event ingestion in `SignerEventReceiver` allows forged StackerDB/burn-block/proposal-response events to be injected into the signer - (File: `libsigner/src/events.rs`)

### Summary
The signer's HTTP event listener (`SignerEventReceiver::next_event`) accepts and forwards `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, and `/new_block` POST bodies from *any* TCP client that can reach the bound address, with no authentication check whatsoever. The `auth_token`/`auth_password` shared secret documented throughout the config/docs as securing "the communication channel between this node and a connected `stacks-signer` instance" is never read or compared inside this receiver.

### Finding Description
`SignerEventReceiver::next_event` dispatches purely on HTTP method and URL path: [1](#0-0) 

For each recognized path it calls `process_event`, which reads the body, deserializes it as JSON, and converts it directly into a `SignerEvent` with no header or token validation: [2](#0-1) 

The resulting event is then handed straight to the signer runloop via `forward_event`: [3](#0-2) 

By contrast, the *node*-side endpoint that receives data from the signer (`/v3/block_proposal`) does enforce `auth_token` comparisons, as seen in `postblock_proposal.rs` and `httpcore.rs`/`net/api/mod.rs` (multiple `auth_token` matches). No equivalent check exists in `libsigner/src/events.rs` for the node→signer direction. The `auth_token`/`auth_password` documentation explicitly states it "secures the communication channel between this node and a connected `stacks-signer` instance" [4](#0-3)  and sample configs show the signer binding to `0.0.0.0:30000` — a non-loopback address reachable over the network [5](#0-4) .

This breaks the intended equality "event actually originated from the paired stacks-node" vs. "any request that hits the listening socket is treated as authentic." Since the receiver performs zero authentication (it only checks URL/method), any remote, unprivileged host that can reach the signer's event port can POST a forged `StackerDBChunksEvent`, `BlockValidateResponse`, `BurnBlockEvent`, or `StacksBlockEvent`, which is then queued and delivered to the signer's decision-making runloop as if it came from the legitimate node.

### Impact Explanation
This is an auth-gate that fails open at the transport layer: unauthenticated data is written directly into the signer's input channel, which feeds its state machine (`forward_event` → signer runloop). This matches the "Critical - unauthenticated/unauthorized write to state" bucket, since a remote unprivileged attacker can inject arbitrary forged StackerDB chunk events, burn-block events, and block-validation responses into the signer process without needing the node's private key or the shared `auth_token`.

### Likelihood Explanation
The signer event listener is commonly configured to bind on a non-loopback address (per the sample configs shown), and the receiver code path contains no authentication logic at all — it is a straightforward reachability issue, not a crypto/timing weakness. Any attacker with network access to the configured `endpoint` can trigger this without prior authentication or state.

### Recommendation
Add authentication to `SignerEventReceiver`'s HTTP handling (e.g., verify an `Authorization` header against the configured `auth_password`/`auth_token`, mirroring the check already present in `postblock_proposal.rs` for the node-side endpoint) before calling `process_event`/`forward_event`. Reject unauthenticated requests to `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, and `/new_block`.

### Proof of Concept
1. Configure a `stacks-signer` per `sample/conf/signer/mainnet-signer-conf.toml` with `endpoint = "0.0.0.0:30000"`.
2. From a separate, unauthenticated remote host, send:
   ```
   POST /new_burn_block HTTP/1.1
   Host: <signer-ip>:30000
   Content-Type: application/json
   Content-Length: <n>

   { ... forged BurnBlockEvent JSON ... }
   ```
3. `SignerEventReceiver::next_event` (libsigner/src/events.rs:437-457) routes this straight into `process_event::<T, BurnBlockEvent>`, which JSON-deserializes it and forwards it via `forward_event` into the signer runloop — with no check that the request came from the paired node or carried the shared `auth_token`.     fn next_event(&mut self) -> Result<SignerEvent<T>, EventError> {
        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)
            } else if request.url() == "/new_block" {
                process_event::<T, StacksBlockEvent>(request)
            } else {
                let url = request.url().to_string();
                debug!(
                    "[{:?}] next_event got request with unexpected url {}, return OK so other side doesn't keep sending this",
                    event_receiver.local_addr,
                    url
                );
                ack_dispatcher(request);
                Err(EventError::UnrecognizedEvent(url))
            }
        })?

    /// Forward an event
    /// Return true on success; false on error.
    /// Returning false terminates the event receiver.
    fn forward_event(&mut self, ev: SignerEvent<T>) -> bool {
        if self.out_channels.is_empty() {
            // nothing to do
            error!("No channels connected to event receiver");
            false
        } else if self.out_channels.len() == 1 {
            // avoid a clone
            if let Err(e) = self.out_channels[0].send(ev) {
                error!("Failed to send to signer runloop: {:?}", &e);
                return false;
            }
            true
        } else {
            for (i, out_channel) in self.out_channels.iter().enumerate() {
                if let Err(e) = out_channel.send(ev.clone()) {
                    error!("Failed to send to signer runloop #{}: {:?}", i, &e);
                    return false;
                }
            }
            true
        }
    }

#[cfg_attr(test, mutants::skip)]
fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}
