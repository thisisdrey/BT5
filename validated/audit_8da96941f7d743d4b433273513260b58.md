### Title
Unauthenticated overwrite of another peer's `PeerDB` frontier row via spoofed `HandshakeData.addrbytes/port` in neighbor-walk handshakes - ([File: stackslib/src/net/db.rs])

### Summary
`PeerDB::try_insert_peer`/`update_peer` key rows on `(network_id, addrbytes, port)` taken from `Neighbor.addr`, which in the neighbor-walk paths (`add_or_schedule_replace_neighbor`, `save_neighbor_from_handshake`) is built purely from the self-reported `HandshakeData.addrbytes`/`port` field of a `HandshakeAccept`/`Handshake` message, not from the TCP socket address that was actually dialed/verified. An attacker who is contacted as a "neighbor of a neighbor" (or via a pingback) can claim any arbitrary `addrbytes`/`port` B in its handshake reply and thereby overwrite an existing, unrelated peer B's `PeerDB` row with its own public key and expire_block.

### Finding Description
The claimed equality is: *the `PeerDB` row keyed by `(network_id, addrbytes, port)` corresponds to a peer that was actually verified to originate traffic from that `(addrbytes, port)`.* This equality is only enforced in one place: `ConversationP2P::validate_handshake` (`stackslib/src/net/chat.rs:1058-1092`), and only in the branch where `self.connection.get_public_key()` is `Some(_)` (i.e., we already have a cached public key for *this specific TCP connection*) *and* the connection `self.stats.outbound` is true: [1](#0-0) 

For any brand-new connection (public key not yet cached — the normal case for a first-time handshake with a previously-unknown or newly-dialed peer), this address-consistency check is entirely skipped; only the message signature over the self-declared `node_public_key` is verified [2](#0-1) .

Two neighbor-walk code paths rely on `HandshakeData.addrbytes/port` as the ground truth for the `PeerDB` key without any additional cross-check against the actually-dialed address:

1. `handle_neighbor_handshake_accept` (queries of `cur_neighbor`'s neighbors) calls `add_or_schedule_replace_neighbor(network, preamble, &data.handshake, ...)` directly, with no comparison of `data.handshake.addrbytes/port` to the `naddr` that was dialed: [3](#0-2) 

2. `pingback_handshakes_try_finish` only validates the public-key hash against `naddr`, never the address: [4](#0-3) 

`add_or_schedule_replace_neighbor` then calls `Neighbor::load_and_update`, which builds the `PeerDB` lookup key from `NeighborKey::from_handshake(peer_version, network_id, handshake_data)` — i.e. directly from the attacker-controlled `handshake_data.addrbytes/port`: [5](#0-4) 

If a row for that key already exists (`was_present == true`), it calls `neighbor_from_handshake.save_update(&tx, ...)`, which invokes `PeerDB::update_peer`, overwriting the existing row's `public_key`, `expire_block_height`, `asn`, `org`, etc., keyed only by `(network_id, addrbytes, port)`: [6](#0-5) [7](#0-6) [8](#0-7) 

`Neighbor::handshake_update` computes the ASN via `PeerDB::asn_lookup(conn, &handshake_data.addrbytes)` — again using the attacker's self-declared address, not the verified socket address — so the ASN/org stored under key B is not attributable to any verified network origin either: [9](#0-8) 

**Exploit flow**: Node N is walking its frontier and asks neighbor X (or receives a pingback) for X's neighbors, one of which resolves (via TCP) to attacker-controlled address C. N dials C, sends a `Handshake`. Attacker at C replies with `HandshakeAccept`/`StackerDBHandshakeAccept` whose `HandshakeData.addrbytes/port` is set to victim B's real, already-known address, signed with the attacker's own keypair. Since this is a fresh connection object, `validate_handshake`'s address-consistency check does not apply (no cached public key yet on that connection), so the message is accepted. `add_or_schedule_replace_neighbor` looks up `PeerDB` by `(network_id, B.addrbytes, B.port)`, finds the existing row for B, and overwrites it with the attacker's `public_key`/`expire_block`/ASN via `PeerDB::update_peer`, despite the attacker never having connected from B's address.

### Impact Explanation
This is an unauthenticated write to another peer's `PeerDB` frontier record: an attacker who never controls or connects from address B can clobber B's stored `public_key`, `expire_block`, and ASN/org fields with attacker-chosen values. Consequences include: N's future connections/handshake validation for B being keyed to the wrong public key (breaking legitimate re-handshakes with the real B, since `validate_handshake`'s "must be signed by current public key" check will now expect the attacker's key), corrupted frontier data influencing walk/peer-selection decisions (e.g. `asn_count`), and if `old_peer.public_key != neighbor.public_key`, `update_peer` also drops B's previously-announced StackerDB replication set (`PeerDB::drop_stacker_dbs`), disrupting legitimate StackerDB gossip for B. This is repeatable per targeted victim address/port and requires no privileged role — matching "unauthenticated/unauthorized write to state" (Critical).

### Likelihood Explanation
Preconditions: N must already have a `PeerDB` entry for victim B (a normal, common situation on a live network), and the attacker must get itself introduced into N's neighbor walk as a "neighbor of a neighbor" or targeted as a pingback candidate — both of which only require running an ordinary reachable P2P peer that another already-known neighbor of N will mention, or being independently discoverable/pingable by N. No secret, admin role, or privileged connection is needed; the attacker only needs to accept an inbound TCP connection from N and reply to a `Handshake` with a crafted, self-signed `HandshakeAccept`. This is a low-cost, remotely reachable, repeatable attack against any node performing routine neighbor-walk crawling.

### Recommendation
In `add_or_schedule_replace_neighbor`, `save_neighbor_from_handshake`, and the pingback-handshake handling path, require that `handshake_data.addrbytes`/`port` match the `NeighborAddress`/socket address that was actually dialed (the same check already applied to `cur_neighbor` in `handle_handshake_accept`, `stackslib/src/net/neighbors/walk.rs:705-715`), rejecting or discarding mismatches (except for the legitimate any-net/NAT exception already handled for `cur_neighbor`). Alternatively, key `PeerDB` writes from these code paths off the verified connection's actual peer address rather than the self-reported `HandshakeData.addrbytes/port`.

### Proof of Concept
Rust test plan (in `stackslib/src/net/neighbors/`):
1. Set up `PeerDBNeighborWalk`/`PeerDB` in memory; pre-insert a `Neighbor` row for victim `B = (network_id, addrbytes_B, port_B)` with a known `public_key_B`/`expire_block_B` via `PeerDB::try_insert_peer`.
2. Construct a `Preamble` and `HandshakeAcceptData` (or `HandshakeData`) whose `addrbytes`/`port` are set to `addrbytes_B`/`port_B`, signed with an attacker keypair `sk_attacker` (`node_public_key = pk_attacker`), simulating a reply received over a connection actually established to attacker address `C`.
3. Call `PeerDBNeighborWalk::add_or_schedule_replace_neighbor(&mut network, &preamble, &handshake, None, &mut replacements)` directly (bypassing `validate_handshake`'s outbound check by using a fresh `ConversationP2P`/connection with no cached public key, mirroring the real code path).
4. Assert: `PeerDB::get_peer(conn, network_id, &addrbytes_B, port_B).unwrap().unwrap().public_key == pk_attacker` and `expire_block == handshake.expire_block_height`, proving B's original `public_key_B`/`expire_block_B` were overwritten by attacker-controlled data despite the attacker never owning/connecting from `addrbytes_B`.

                .insert(neighbor.addr.clone(), neighbor.clone());

            self.frontier
                .insert(neighbor.addr.clone(), neighbor.clone());
        }

        self.resolved_handshake_neighbors.insert(naddr, neighbor);
        Ok(())

    /// Does a given handshakedata represent an expected public key hash?
    fn check_handshake_pubkey_hash(
        nk: &NeighborKey,
        data: &HandshakeAcceptData,
        naddr: &NeighborAddress,
    ) -> bool {
        let neighbor_pubkey_hash =
            Hash160::from_node_public_key_buffer(&data.handshake.node_public_key);
        if neighbor_pubkey_hash != naddr.public_key_hash {
            debug!(
                "Neighbor {:?} had an unexpected pubkey hash: expected {:?} != {:?}",
                nk, &naddr.public_key_hash, &neighbor_pubkey_hash
            );
            return false;
        }

        true
    }

    /// Finish up connecting to newly-discovered inbound peers
    pub fn pingback_handshakes_try_finish(
        &mut self,
        network: &mut PeerNetwork,
    ) -> Result<bool, net_error> {
        assert!(self.state == NeighborWalkState::PingbackHandshakesFinish);

        // see if we got any replies
        for (naddr, message) in self.comms.collect_replies(network).into_iter() {
            // if we got back a HandshakeAccept, and it's on the same chain as us, we're good!
            let (data, db_data) = match message.payload {
                StacksMessageType::HandshakeAccept(ref data) => {
                    debug!("{:?}: received HandshakeAccept from peer {:?}; now known to be routable from us", network.get_local_peer(), &message.to_neighbor_key(&data.handshake.addrbytes, data.handshake.port));
                    (data, None)
                }
                StacksMessageType::StackerDBHandshakeAccept(ref data, ref db_data) => {
                    debug!("{:?}: received StackerDBHandshakeAccept from peer {:?}; now known to be routable from us", network.get_local_peer(), &message.to_neighbor_key(&data.handshake.addrbytes, data.handshake.port));
                    (data, Some(db_data))
                }
                _ => {
                    let nkey = naddr.to_neighbor_key(network);
                    debug!(
                        "{:?}: Neighbor {:?} replied {:?} instead of pingback handshake",
                        network.get_local_peer(),

                        &message.get_message_name()

                    continue;

            self.neighbor_db.add_or_schedule_replace_neighbor(
                network,
                &message.preamble,
                &data.handshake,
                db_data,

            tx,
            neighbor.addr.network_id,
            &neighbor.addr.addrbytes,
            neighbor.addr.port,
