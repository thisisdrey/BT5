Unauthenticated `POST /shutdown` permanently halts the signer's event-listener - ([File: libsigner/src/events.rs])

### Summary
The `SignerEventReceiver::next_event` handler in `libsigner/src/events.rs` treats any TCP client that can reach the signer's event socket and send `POST /shutdown` as authorized to permanently stop the event receiver, with no signature, secret, or peer-identity check. Since the reference/sample signer config binds this socket to `0.0.0.0` (all interfaces), any remote unprivileged party can send one crafted HTTP request to permanently kill the signer's event ingestion.

### Finding Description
In `next_event`, the URL dispatch table treats `/shutdown` identically for any caller:
```rust
} else if request.url() == "/shutdown" {
    event_receiver.stop_signal.store(true, Ordering::SeqCst);
    Err(EventError::Terminated)
}
``` [1](#0-0) 

There is no check of source IP, no comparison against a shared secret/token, and no TLS client-cert or HMAC validation before flipping `stop_signal`. Compare this to the *intended* caller, `SignerStopSignaler::send`, which is only supposed to be invoked in-process by the signer's own runloop shutdown path and connects to `self.local_addr` to issue the same unauthenticated `POST /shutdown` request: [2](#0-1) 

Once `stop_signal` is `true`, `is_stopped()` returns true permanently (it's a one-way `AtomicBool` with no reset), causing `next_event` to return `EventError::Terminated` and `main_loop` to break out for good: [3](#0-2) [4](#0-3) 

The only "authentication" concept in the signer configuration (`auth_password`/`auth_token`) is used for the **node's RPC block-proposal endpoint**, not for the signer's own event-listener HTTP server, as documented in `docs/signing.md` and `sample/conf/signer/mainnet-signer-conf.toml`. The event-listener socket itself has no auth gate at the `tiny_http`/`HttpServer` layer in `bind`/`next_event`. The sample mainnet signer config binds this socket to `0.0.0.0:30000`, i.e., all interfaces, making it remotely reachable by design in the reference deployment: [5](#0-4) 

So the claimed equality — "only the node that owns this signer process may halt its event stream" — is false: any TCP peer that can open a connection to the bound event port and send a single well-formed `POST /shutdown` request achieves the same effect as the legitimate internal stop signaler, with no credential check whatsoever.

### Impact Explanation
A single unauthenticated HTTP request permanently disables the signer's ingestion of `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, and `/new_block` events from its node, since `main_loop` exits and is never restarted automatically. This stops the signer from seeing block proposals and StackerDB messages, effectively taking the signer offline from the node's perspective — a Critical unauthenticated, single-message remote DoS against a component central to block validation availability. It is fully repeatable against any signer whose event port is reachable, and does not require volumetric traffic — one crafted TCP request suffices.

### Likelihood Explanation
Preconditions: the attacker only needs network reachability to the signer's event-receiver port (as documented, `0.0.0.0:30000` in the sample/mainnet config) and the ability to open a TCP connection and send bytes — no RPC secret, no peer identity, no StackerDB slot ownership is required. Attacker cost is a single crafted `POST /shutdown` request. This is trivially repeatable and requires no privileged role, matching the "unprivileged remote party" threat model in scope.

### Recommendation
Remove the network-triggerable `/shutdown` HTTP route entirely, or gate it behind a check that the request originates from `127.0.0.1`/the loopback interface AND presents a shared secret established at bind-time (e.g., a random token known only to the in-process `SignerStopSignaler`). Prefer converting the stop mechanism to a purely in-process signal (e.g., a self-pipe/eventfd or a short-lived loopback-only listener bound after verifying `SO_REUSEADDR`/local peer address) rather than an HTTP endpoint reachable from the same socket that accepts node event POSTs.

### Proof of Concept
```rust
// libsigner/src/events.rs (test) or a new integration test
use std::net::{TcpStream, SocketAddr};
use std::io::Write;
use std::thread;

#[test]
fn test_unauthenticated_remote_shutdown() {
    let mut receiver: SignerEventReceiver<StacksTransaction> = SignerEventReceiver::new(false);
    let addr: SocketAddr = "127.0.0.1:0".parse().unwrap();
    let bound = receiver.bind(addr).unwrap();

    let handle = thread::spawn(move || receiver.main_loop());

    // Attacker: arbitrary remote peer, no auth token, no signer key
    let mut stream = TcpStream::connect(bound).unwrap();
    let body = "attacker shutdown";
    let req = format!(
        "POST /shutdown HTTP/1.1\r\nHost: {}\r\nConnection: close\r\nContent-Length: {}\r\n\r\n{}",
        bound, body.len(), body
    );
    stream.write_all(req.as_bytes()).unwrap();

    // main_loop should exit permanently after a single unauthenticated request
    handle.join().unwrap();

    // Subsequent legitimate /stackerdb_chunks posts are never processed because
    // the receiver thread has already terminated (main_loop returned).
}
```
Assertion point: `handle.join()` returns because `main_loop` breaks at `Err(EventError::Terminated) => break;` in [6](#0-5) , triggered solely by the unauthenticated store at [1](#0-0) .
