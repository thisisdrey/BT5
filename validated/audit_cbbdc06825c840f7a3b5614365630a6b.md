### Title
Linking a repository to itself as its own object pool corrupts the repository via a self-referential alternates loop and object loss - ([File: internal/git/objectpool/link.go])

### Summary
The `LinkRepositoryToObjectPool` RPC allows an ordinary caller to specify both `Repository` and `ObjectPool.Repository` as independent, unrestricted `gitalypb.Repository` messages (storage name + relative path). Neither the RPC handler nor `objectpool.Link()` validates that the two do not refer to the same physical repository. If a caller supplies identical values for both fields, the object pool "linking" logic will write a self-referential `objects/info/alternates` entry and then attempt to deduplicate the "member's" objects against the "pool" — which are the same objects on disk — corrupting or destroying the only copy of the repository's objects.

### Finding Description
`LinkRepositoryToObjectPool` resolves the `Repository` and the `ObjectPool` independently and calls `pool.Link(ctx, repo)`: [1](#0-0) 

The core `Link` function computes a relative path from the member repository's object directory to the pool's object directory and writes it into the member's `objects/info/alternates` file, then calls `removeMemberBitmaps(ctx, pool, repo)`: [2](#0-1) 

Nowhere in this path — nor in `linkedToRepository`, which only checks that the alternates content matches the expected relative object path — is there a check that `pool` and `repo` are not the same repository: [3](#0-2) 

If `Repository` and `ObjectPool.Repository` resolve to the same storage and relative path, `getRelativeObjectPath` will compute a path from the repository's own `objects` directory back to itself (effectively `.`), and this self-reference gets written into the repository's own `objects/info/alternates` file. Git's alternates mechanism assumes the alternate is a *separate* object store; self-referencing alternates create a degenerate/looping object search path. Combined with `removeMemberBitmaps` and the platform's subsequent housekeeping/repack behavior — which is designed to prune a pool member's now-"duplicate" objects because they are assumed to still be reachable via the (distinct) pool — a repository linked to itself this way can have its only copies of objects pruned away, since the "pool" it is deduplicating against is itself. This is the same bug class as the ResolvStakingV2 issue: an operation that legitimately treats two positions (source/target, member/pool) as distinct silently degenerates when they are made to be the same entity, and intermediate state (the object directory, the balance) is read/mutated inconsistently as a result, producing a corrupted final state.

### Impact Explanation
The impact is repository corruption / object loss reachable purely through the gRPC surface, not requiring any privileged access beyond what is normally needed to call `LinkRepositoryToObjectPool` (the same access level a user has for ordinary fork/object-pool workflows). Best case, the repository ends up with a nonsensical self-referential alternates file causing Git operations to behave incorrectly. Worst case, subsequent deduplication/repack logic removes the repository's only object copies, permanently destroying repository data and denying service on that repository (Git operations begin failing with "object not found" style errors). This matches the "storage escape / DoS of a handler" acceptance criteria — a crafted RPC field on an otherwise legitimate object-pool operation results in a corrupted, self-consistency-violating repository state.

### Likelihood Explanation
Likelihood is High for reachability: the `LinkRepositoryToObjectPoolRequest.Repository` and `ObjectPool.Repository` fields are both plain `Repository` messages (`StorageName` + `RelativePath`) supplied by the caller; nothing in `LinkRepositoryToObjectPool` (internal/gitaly/service/objectpool/link.go), nor in `objectpool.Link`, nor in `linkedToRepository` rejects the case where they are equal. The existing test suite for `Link` (unset repository, unset object pool, successful, already-linked, different-pool, no-clobber, transactional cases) contains no test for "repository equals its own object pool," suggesting this scenario is not defended against or exercised at all. I could not fully verify whether higher layers (e.g., `poolForRequest` in `internal/gitaly/service/objectpool/util.go`, or Rails-side pool path assignment) impose an out-of-band convention that pool paths and repository paths never collide; if such convention is enforced purely by caller discipline rather than by Gitaly's own validation, then any client with access to the raw gRPC API (not going through Rails/GitLab's conventional pool-path derivation) can trigger this condition directly.

### Recommendation
In `objectpool.Link` (and ideally also `CreateObjectPool`/`LinkRepositoryToObjectPool` at the RPC layer), explicitly reject requests where the object pool's repository and the target repository resolve to the same storage and relative path, mirroring the existing `storage.RepoPathEqual` helper already used elsewhere in the codebase for a conceptually similar same-repository check: [4](#0-3) [5](#0-4) 

```diff

+	if storage.RepoPathEqual(pool, repo) {
+		return fmt.Errorf("cannot link repository to itself as object pool")
+	}
```

### Proof of Concept
1. Create a repository `R` with some commits (`gittest.CreateRepository`, `gittest.WriteCommit`).
2. Call `LinkRepositoryToObjectPool` with:
   - `Repository = R`
   - `ObjectPool.Repository = R` (same `StorageName`/`RelativePath`)
3. Observe that `Link()` succeeds (no validation error), writing a self-referential path into `R/objects/info/alternates`.
4. Trigger repository housekeeping/repack (e.g., via `git gc`/`FetchIntoObjectPool`-style pruning as exercised in `TestDisconnectGitAlternates`, which shows that objects become inaccessible once the alternates link is removed after `git gc` has deduplicated against the "pool"): [6](#0-5) 
   With `R` and its own "pool" being identical, the same deduplication semantics cause `R`'s objects to be treated as redundant duplicates of "the pool" (itself), and after repacking/removal steps, `R` loses access to its own objects, corrupting the repository.

```go
func (s *server) LinkRepositoryToObjectPool(ctx context.Context, req *gitalypb.LinkRepositoryToObjectPoolRequest) (*gitalypb.LinkRepositoryToObjectPoolResponse, error) {
	repository := req.GetRepository()
	if err := s.locator.ValidateRepository(ctx, repository); err != nil {
		return nil, structerr.NewInvalidArgument("%w", err)
	}

	pool, err := s.poolForRequest(ctx, req)
	if err != nil {
		return nil, err
	}

	repo := s.localRepoFactory.Build(repository)

	if err := pool.Link(ctx, repo); err != nil {
		return nil, structerr.NewInternal("%w", err)
	}

	return &gitalypb.LinkRepositoryToObjectPoolResponse{}, nil
}
```

```go
func Link(ctx context.Context, pool, repo *localrepo.Repo, txManager transaction.Manager) (returnedErr error) {
	altPath, err := repo.InfoAlternatesPath(ctx)
	if err != nil {
		return err
	}

	expectedRelPath, err := getRelativeObjectPath(ctx, pool, repo)
	if err != nil {
		return err
	}

	linked, err := linkedToRepository(ctx, pool, repo)
	if err != nil {
		return err
	}

	if linked {
		// When the repository is already linked to the repository, cast a vote to ensure the
		// repository is consistent with the other replicas.
		if err := transaction.VoteOnContext(ctx, txManager, voting.VoteFromData([]byte("repository linked")), voting.Synchronized); err != nil {
			return fmt.Errorf("vote on linked repository: %w", err)
		}

		return nil
	}

	alternatesWriter, err := safe.NewLockingFileWriter(altPath)
	if err != nil {
		return fmt.Errorf("creating alternates writer: %w", err)
	}
	defer func() {
		if err := alternatesWriter.Close(); err != nil && returnedErr == nil {
			returnedErr = fmt.Errorf("closing alternates writer: %w", err)
		}
	}()

	if _, err := io.WriteString(alternatesWriter, expectedRelPath); err != nil {
		return fmt.Errorf("writing alternates: %w", err)
	}

	if err := transaction.CommitLockedFile(ctx, txManager, alternatesWriter); err != nil {
		return fmt.Errorf("committing alternates: %w", err)
	}

	if tx := storage.ExtractTransaction(ctx); tx != nil {
		alternatesRelativePath, err := filepath.Rel(tx.FS().Root(), altPath)
		if err != nil {
			return fmt.Errorf("rel alternates file: %w", err)
		}

		if err := tx.FS().RecordFile(alternatesRelativePath); err != nil {
			return fmt.Errorf("record alternates file")
		}
	}

	return removeMemberBitmaps(ctx, pool, repo)
}
```

```go
// linkedToRepository tests if a repository is linked to an object pool
func linkedToRepository(ctx context.Context, pool, repo *localrepo.Repo) (bool, error) {
	poolPath, err := pool.Path(ctx)
	if err != nil {
		return false, fmt.Errorf("getting object pool path: %w", err)
	}

	repoPath, err := repo.Path(ctx)
	if err != nil {
		return false, fmt.Errorf("getting repo path: %w", err)
	}

	altInfo, err := stats.AlternatesInfoForRepository(repoPath)
	if err != nil {
		return false, fmt.Errorf("getting alternates info: %w", err)
	}

	if !altInfo.Exists || len(altInfo.ObjectDirectories) == 0 {
		return false, nil
	}

	relPath := altInfo.ObjectDirectories[0]
	expectedRelPath, err := getRelativeObjectPath(ctx, pool, repo)
	if err != nil {
		return false, err
	}

	if relPath == expectedRelPath {
		return true, nil
	}

	if filepath.Clean(relPath) != filepath.Join(poolPath, "objects") {
		return false, fmt.Errorf("unexpected alternates content: %q", relPath)
	}

	return false, nil
}
```
