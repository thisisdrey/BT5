### Title
Unauthenticated `RecvError` spoofing check is skipped when a HostInfo has no confirmed remote, allowing remote tunnel teardown - (File: [outside.go](outside.go))

### Summary
The `handleRecvError` spoof-protection check compares the sender's UDP address against the tunnel's known remote, but the comparison is short-circuited by an `IsValid()` guard on the *stored* remote rather than being an unconditional authentication check. Analogous to the Vader `veto` bug — where a protection check inspected data that could structurally never contain the value being tested for, silently disabling the intended guard — this check disables the anti-spoofing comparison whenever `hostinfo.GetRemote()` has not yet been populated, letting any off-path attacker who can guess/observe a `RemoteIndex` tear down a tunnel with a forged, unencrypted `RecvError` packet.

### Finding Description
`RecvError` is one of only two unencrypted, pre-authentication message types dispatched directly out of `readOutsidePackets` before any certificate, hostmap, or Noise-authenticated state is consulted: [1](#0-0) 

`handleRecvError` is supposed to prevent an attacker from injecting one of these unauthenticated control packets to sever a tunnel that doesn't belong to them, by checking that the packet's source address matches the address currently associated with the hostinfo referenced by `RemoteIndex`: [2](#0-1) 

The critical line is:
```go
hr := hostinfo.GetRemote()
if hr.IsValid() && hr != addr {
    ...
    return
}
```
`GetRemote()` returns a zero-value `netip.AddrPort{}` (i.e. `IsValid() == false`) whenever the hostinfo's remote hasn't been set yet: [3](#0-2) 

Because the check is written as `hr.IsValid() && hr != addr`, the entire spoofing check evaluates to `false` — and the packet is accepted regardless of its actual source address — precisely in the state where the check matters most: before a remote address has been confirmed for that hostinfo (e.g. hosts reachable only via relay, or a tunnel mid-setup where `SetRemote` hasn't yet been called). This mirrors the root cause of the reported Vader bug: the intended guard inspects a field/state that, under a specific but reachable condition, can never satisfy the comparison, so the "protection" silently becomes a no-op rather than failing closed.

### Impact Explanation
An attacker who is not a certificate holder and has no established tunnel can send a single unencrypted UDP packet of type `header.RecvError` with a guessed/observed `RemoteIndex` to any node. If the targeted hostinfo's remote address is not yet set (a normal, reachable state for relayed or newly-forming tunnels), the address-spoofing check is bypassed entirely, and `f.closeTunnel(hostinfo)` plus `handshakeManager.DeleteHostInfo(hostinfo)` execute unconditionally — tearing down an active or forming tunnel. This is a remote, unauthenticated denial-of-service against tunnel availability, reachable without holding a CA-signed certificate, since `RecvError` is processed prior to any peer authentication.

### Likelihood Explanation
`RemoteIndex` values are 32-bit locally-generated identifiers, and this path is only exploitable while a hostinfo's remote is still unset (`!hr.IsValid()`) — a state that is common for relayed hosts (a `remote` may never be set for a relayed-only entry) and momentarily during handshake completion. The `send_recv_error`/`accept_recv_error` config already exists specifically because `RecvError` handling is recognized as an attacker-observable, spoofing-relevant surface (see `CHANGELOG.md` security note on `listen.send_recv_error`), which supports that this is a genuine, previously-flagged risk area rather than a purely theoretical one, though full exploitability depends on the attacker being able to obtain or brute-force a live `RemoteIndex`, which is not addressed by this check being present-but-defeatable.

### Recommendation
Change the guard to fail closed instead of skipping the comparison when no remote is known yet:
```go
hr := hostinfo.GetRemote()
if !hr.IsValid() || hr != addr {
    f.l.Info("Someone spoofing recv_errors?", "addr", addr, "hostinfoRemote", hr)
    return
}
```
This way, a `RecvError` cannot close a tunnel/hostinfo unless the sender's address is verified to match a previously-confirmed remote, removing the silent bypass for hosts with no set remote. Add a regression test (mirroring `TestFirewall_ConntrackSourceSpoofingAcrossPeers`-style tests already present in this codebase) that specifically exercises `handleRecvError` against a `HostInfo` whose `remote` has not been set, asserting the tunnel is NOT closed by a mismatched/forged address.

### Proof of Concept
1. Establish (or wait for) a hostinfo state where `hostinfo.GetRemote()` is still the zero value — e.g. a relay-only peer, or a tunnel mid-handshake before `SetRemote`/`RefreshFromHandshake` has run.
2. As an off-path attacker (no certificate, no established Noise session), send a raw UDP packet to the victim node containing only a Nebula header with `Type = header.RecvError` and `RemoteIndex` set to the target hostinfo's known/guessed remote index, from any spoofed source address.
3. `readOutsidePackets` dispatches this directly to `f.handleRecvError(via.UdpAddr, h)` without any cert/hostmap authentication (`outside.go:81-84`).
4. In `handleRecvError`, `hr := hostinfo.GetRemote()` returns an invalid `AddrPort`, so `hr.IsValid() && hr != addr` is `false`; the spoof check does not trigger.
5. `f.closeTunnel(hostinfo)` and `f.handshakeManager.DeleteHostInfo(hostinfo)` run, tearing down the tunnel — despite the packet not originating from the real remote.

```go
func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
```
