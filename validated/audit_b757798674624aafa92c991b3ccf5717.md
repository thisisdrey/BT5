### Title
Attacker permanently captures/denies all reward emissions by flash-inflating `DepositToken.totalSupply()` during `RewardsDistributor._calculateTokenIndex` - ([File: contracts/RewardsDistributor.sol](contracts/RewardsDistributor.sol))

### Summary
Analogous to the Napier `maxScale` donation-lock, `RewardsDistributor` computes the global reward index increment as `deltaTimestamp * speed / totalSupply` using the *live* `token_.totalSupply()`. An unprivileged attacker can atomically inflate that denominator — via a flash-loaned `DepositToken.deposit` (or any large deposit/withdraw loop) — so the index increment collapses toward zero for everyone, while the `updateBeforeMintOrBurn`/`updateBeforeTransfer` hooks and the permissionless `RewardsDistributor.updateBeforeMintOrBurn` entry point let the attacker force the index update precisely while supply is inflated. Legitimate holders' `tokensAccruedOf` therefore accrue ~0 (or the attacker captures the emission pro-rata), permanently stealing/freezing unclaimed yield — same bug class: an unprivileged donation/supply manipulation of a global accrual index that blocks users' yield claims.

### Finding Description
The accrual invariant that should hold is: index delta for a period is fixed at `Δt * speed` distributed pro-rata, independent of *when* the update is triggered. It breaks because `_calculateTokenIndex` reads the current, manipulable `totalSupply()` at update time (`contracts/RewardsDistributor.sol:204-207`), and `updateBeforeMintOrBurn` is callable by anyone (`contracts/RewardsDistributor.sol:175-180`) in addition to being invoked by every `DepositToken`/`DebtToken` mint/burn/transfer (`contracts/DepositToken.sol:124-131`, `contracts/DebtToken.sol:114-121`).

Attack (per accrual period):
1. Flash-borrow the deposit `underlying` (e.g., WETH/vaETH), call `DepositToken.deposit(amount, attacker)` — mints a huge `balanceOf[attacker]`, pushing `totalSupply` to `S >> normal` (`contracts/DepositToken.sol:211-237`, `_mint` at 469-489).
2. In a later block (or via a helper contract that keeps a persistent leveraged position and tops it up with flash loans each update), call `RewardsDistributor.updateBeforeMintOrBurn(depositToken, attacker)` (public, `RewardsDistributor.sol:175`). `_updateTokenIndex` computes `_ratio = (Δt * speed).wadDiv(S)` ≈ 0 → global `tokenStates.index` barely moves and `timestamp` is advanced, so the emission `Δt * speed` for that window is burned — no user can ever accrue it again (denial), or, if the attacker keeps the inflated balance, `attacker accrued = balance * ratio ≈ Δt * speed` — near-total capture of the emission (theft).
3. `DepositToken.withdraw(amount, attacker)` burns the msdTOKEN (after `updateBeforeMintOrBurn` runs with the still-inflated supply) and pulls the underlying back via `Treasury.pull` (`contracts/DepositToken.sol:536-554`), repaying the flash loan. Cost is only gas + deposit/withdraw fees.

For `DebtToken`-tracked rewards the same denial works through `accrueInterest`-inflated `totalSupply()` (interest accrual is virtual, not attacker-controllable), so the practical target is the `DepositToken` leg.

Modifiers checked: `updateBeforeMintOrBurn` has no access control; `deposit` is `whenNotPaused nonReentrant` only; `withdraw` only checks `_revertIfLocked` (no debt → fully unlocked, `DepositToken.sol:383-398`). Nothing requires the attacker to hold the supply across the whole period — only at the update instant.

### Impact Explanation
All reward emissions for manipulated windows are either permanently unclaimable by any holder (index timestamp advances without the index growing — the reward tokens remain stuck in the distributor) or are captured almost entirely by the attacker's transient balance. This is theft and/or permanent freezing of unclaimed yield for all depositors/debtors of the targeted token — the same impact as the Napier finding (holders cannot claim yield because a global index was manipulated).

### Likelihood Explanation
Requires only an EOA, a flash loan of the deposit underlying, and public entry points. Repeatable every block while rewards have nonzero `tokenSpeeds`. No privileged role needed. Deposit/withdraw fees (if configured >0) slightly raise the cost but are small versus cumulative emissions; with the common zero-fee config the attack is nearly free.

### Recommendation
- Use a manipulation-resistant supply for the index: e.g., update the index only inside the token's own mint/burn hooks (remove the permissionless `updateBeforeMintOrBurn`), or snapshot/time-weight `totalSupply` (e.g., accumulate `index += Δt*speed / supply` per-block via a supply checkpoint taken *before* same-tx changes, or compute with supply measured at `timestamp` start).
- Alternatively accrue rewards against `totalSupply` measured excluding balances minted within the same block/period, or restrict index updates to once per `speed`-emission epoch.
- Add a minimum supply / grace-period guard so `_ratio` cannot be diluted by transient mints.

### Proof of Concept
Hardhat (fork or local), targeting a pool where `DepositToken` `msdToken` has `tokenSpeeds[msdToken] > 0` in `RewardsDistributor` and an attacker flash-loan source for `underlying` (e.g., Balancer/Aave or `SmartFarmingManager.leverage`-equivalent funds):

```ts
// test/poc/RewardIndexDilution.tst.ts (sketch)
it('attacker suppresses reward index via flash deposit', async () => {
  // victim holds a normal deposit and would accrue `speed * dt`
  await depositToken.connect(victim).deposit(parseEther('10'), victim.address)

  // attacker flash-borrows `underlying`, deposits huge amount
  const huge = parseEther('100000')
  await flashLoan(underlying, huge, async () => {
    await underlying.connect(attacker).approve(depositToken.address, huge)
    await depositToken.connect(attacker).deposit(huge, attacker.address) // totalSupply -> ~huge
    attackerDepositBalance = await depositToken.balanceOf(attacker.address)
  })
  // NOTE: for cross-block emission capture, attacker keeps a leveraged/persistent
  // deposit (or repeats the flash-loan deposit each block) instead of repaying here.

  await increaseTimeOfNextBlock(100) // emission window: speed * 100 should accrue

  // attacker (or anyone) triggers index update while supply is inflated
  await depositToken.connect(attacker).deposit(huge, attacker.address) // fresh flash deposit
  await rewardsDistributor.updateBeforeMintOrBurn(depositToken.address, attacker.address)

  const { index } = await rewardsDistributor.tokenStates(depositToken.address)
  // ratio = (100 * speed) / huge  ~= 0  -> index ~unchanged from INITIAL_INDEX
  expect(index.sub(INITIAL_INDEX)).to.be.lt(parseEther('0.000001'))

  // victim accrued ~nothing; emission is permanently lost (timestamp advanced)
  await depositToken.connect(attacker).withdraw(await depositToken.balanceOf(attacker.address), attacker.address)
  await rewardsDistributor['claimRewards(address)'](victim.address)
  expect(await rewardToken.balanceOf(victim.address)).to.be.lt(expectedVictimReward.div(100))
  // and/or attacker captured ~ speed*100 reward tokens pro-rata
})
```

Key assertion: `tokenStates[depositToken].index` grows by `Δt*speed/totalSupply` evaluated at the inflated supply, so the period's rewards are never credited to honest holders — matching the report's "index locked, yield unclaimable" invariant break.
