### Title
`http_archive`'s `remote_file_urls` overlay accepts an empty per-file `integrity`/`sha256`, silently disabling verification for individual overlaid files while the rule is still treated as "reproducible" - ([File: tools/build_defs/repo/utils.bzl])

### Summary
`http_archive` lets a user overlay additional files fetched from arbitrary URLs on top of a verified archive via the `remote_file_urls` / `remote_file_integrity` attributes. `download_remote_files()` looks up the expected checksum per path with `ctx.attr.remote_file_integrity.get(path, "")` and passes that (possibly empty) integrity straight to `ctx.download()`. If the corresponding key is missing, or is explicitly set to `""` (an empty string is a valid Starlark string value and is accepted by `attr.string_dict()`), the download is performed with **no integrity check at all** for that specific file, exactly like `lend()` accepting `amount = 0` without validation. [1](#0-0) 

### Finding Description
`download_remote_files` is the implementation used by `http_archive` to fetch supplementary files (e.g., `BUILD.bazel`, `REPO.bazel`) from attacker-influenced mirror URLs, layered independently of the main archive's `sha256`/`integrity` attribute:

```
pending = {
    path: ctx.download(
        remote_file_urls,
        path,
        ...
        integrity = ctx.attr.remote_file_integrity.get(path, ""),
        block = False,
        executable = True,
    )
    for path, remote_file_urls in ctx.attr.remote_file_urls.items()
}
``` [2](#0-1) 

The `.get(path, "")` fallback silently substitutes an empty checksum whenever the user does not supply a matching entry in `remote_file_integrity` for a given `path` key present in `remote_file_urls`. `ctx.download()` treats an empty `sha256`/`integrity` as "no check requested" and will accept any bytes served by the URL, only computing and returning the actual digest afterwards for informational/reproducibility purposes — it does not fail the build. This is confirmed by the shell test that explicitly sets an empty per-file integrity and by the underlying repository_ctx.download API documentation, which defines `sha256`/`integrity` defaults as `''` (i.e., "unverified"). [3](#0-2) 

The Starlark `http_archive` implementation calls `download_remote_files(ctx)` right after extracting and verifying the main archive, and later reports "reproducibility" via `_update_http_archive_integrity_attrs`, which only forces attribute updates (and marks the repo non-reproducible) when the computed `remote_file_integrity` differs from what's currently declared — it never fails the build outright when integrity is empty or omitted: [4](#0-3) 

The plain-HTTP-without-checksum guard (`missing checksum` error, exempting localhost) that the test suite exercises applies to the top-level `ctx.download`/`http_archive` URL scheme validation, but the `remote_file_urls` overlay path goes through the same `ctx.download()` primitive and is only protected by that same "plain http requires checksum" heuristic, not by any requirement that `remote_file_integrity` be non-empty when supplied over HTTPS or when a URL scheme is otherwise trusted. An attacker who controls (or can MITM within the allowed scope, e.g., a compromised/hostile mirror the project already trusts for its `remote_file_urls`) one of these overlay URLs, when the repository author forgot — or a supply-chain actor strips — the corresponding `remote_file_integrity` entry, can serve arbitrary content (e.g., a rewritten `BUILD.bazel`/`REPO.bazel`) that gets written into the repository directory and used by the build unverified, exactly mirroring the "0 amount silently accepted" bug class: a value meant to gate an operation (checksum here, amount there) is allowed to be empty/zero and the code proceeds as if that were a valid, checked value.

### Impact Explanation
`BUILD.bazel`/`REPO.bazel` (or any other overlay path) content fetched via `remote_file_urls` becomes untrusted-yet-unverified input that is materialized directly into the external repository directory and interpreted as build metadata (targets, repo mapping) for the consuming workspace. Unlike the primary archive (which is normally checksum-pinned via `sha256`/`integrity`), the overlay path silently degrades to unauthenticated content whenever its own integrity entry is missing/empty, defeating the "declared checksum should stop a hostile origin" invariant for that specific artifact even when the rest of the `http_archive` invocation looks fully pinned.

### Likelihood Explanation
Requires only that a repository rule author (or an entry propagated by a module extension/registry) uses `remote_file_urls` without fully populating `remote_file_integrity` for every key — a state that is easy to reach accidentally, since Bazel does not error out; it just downgrades the rule to non-reproducible and continues. No local machine access or MITM against a properly pinned channel is needed: the attacker only needs control of content served at one of the declared `remote_file_urls` mirrors (a supply-chain style compromise), which matches the allowed attacker model.

### Recommendation
In `download_remote_files` (`tools/build_defs/repo/utils.bzl`), fail fast (or refuse the download) instead of falling back to `""` when a `path` in `remote_file_urls` has no corresponding non-empty entry in `remote_file_integrity`, mirroring the existing hard requirement already used for `remote_module_file_integrity` (`fail("remote_module_file_integrity must be set when remote_module_file_urls is set")`). At minimum, `http_archive`'s reproducibility bookkeeping should be changed to hard-fail (not just mark non-reproducible) when any `remote_file_urls` entry lacks a checksum, consistent with treating a zero/empty verification value as an explicit error rather than a silently-accepted default.

### Proof of Concept
Reachable via the existing shell test harness pattern; convert `test_overlay_remote_file_without_integrity`/`test_overlay_remote_file_with_empty_integrity` in `src/test/shell/bazel/external_remote_file_test.sh` into a negative test: serve a *different*, malicious `BUILD.bazel` from the overlay URL after the first successful, non-reproducible build, then rebuild — the build succeeds without any checksum-mismatch error even though the overlay content changed, whereas an equivalent tampering against the main archive (which has `integrity` set) fails hard. This demonstrates that the `remote_file_urls` overlay path can be used to inject unverified content as long as its own `remote_file_integrity` entry is omitted or empty. [5](#0-4)

def download_remote_files(ctx, auth = None):
    """Utility function for downloading remote files.

    This rule is intended to be used in the implementation function of
    a repository rule. It assumes the parameters `remote_file_urls` and
    `remote_file_integrity` to be present in `ctx.attr`.

    Existing files will be overwritten.

    Args:
      ctx: The repository context of the repository rule calling this utility
        function.
      auth: An optional dict specifying authentication information for some of the URLs.

    Returns:
        dict mapping file paths to a download info.
    """
    pending = {
        path: ctx.download(
            remote_file_urls,
            path,
            canonical_id = ctx.attr.canonical_id,
            auth = get_auth(ctx, remote_file_urls) if auth == None else auth,
            integrity = ctx.attr.remote_file_integrity.get(path, ""),
            block = False,
            # Overlaid files may be shell scripts.
            executable = True,
        )
        for path, remote_file_urls in ctx.attr.remote_file_urls.items()
    }

    # Wait until the requests are done
    return {path: token.wait() for path, token in pending.items()}

def _update_http_archive_integrity_attrs(ctx, attrs, integrity):
    integrity_override = {}

    # We don't need to override the integrity attribute if sha256 is already specified.
    # remote_module_file_integrity is for internal use by Bazel only and always
    # set correctly.
    if not ctx.attr.sha256 and not ctx.attr.integrity:
        integrity_override["integrity"] = integrity.archive
    if ctx.attr.remote_file_integrity != integrity.remote_files:
        integrity_override["remote_file_integrity"] = integrity.remote_files
    if ctx.attr.remote_patches != integrity.remote_patches:
        integrity_override["remote_patches"] = integrity.remote_patches
    if not integrity_override:
        return ctx.repo_metadata(reproducible = True)
    return ctx.repo_metadata(attrs_for_reproducibility = update_attrs(ctx.attr, attrs.keys(), integrity_override))

def _http_archive_impl(ctx):
    """Implementation of the http_archive rule."""
    if ctx.attr.build_file and ctx.attr.build_file_content:
        fail("Only one of build_file and build_file_content can be provided.")

    if ctx.attr.strip_prefix and ctx.attr.strip_components:
        fail("Only one of strip_prefix and strip_components can be provided.")

    source_urls = _get_source_urls(ctx)
    download_info = ctx.download_and_extract(
        source_urls,
        ctx.attr.add_prefix,
        ctx.attr.sha256,
        ctx.attr.type,
        ctx.attr.strip_prefix,
        strip_components = ctx.attr.strip_components,
        canonical_id = ctx.attr.canonical_id or get_default_canonical_id(ctx, source_urls),
        auth = get_auth(ctx, source_urls),
        integrity = ctx.attr.integrity,
    )
    workspace_and_buildfile(ctx)

    remote_files_info = download_remote_files(ctx)
    remote_patches_info = patch(ctx)
    symlink_files(ctx)

    integrity = struct(
        archive = download_info.integrity,
        remote_files = {path: info.integrity for path, info in remote_files_info.items()},
        remote_patches = {url: info.integrity for url, info in remote_patches_info.items()},
    )

    return _update_http_archive_integrity_attrs(ctx, _http_archive_attrs, integrity)
