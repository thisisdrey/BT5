### Title
Zero-fee PSM mint/redeem cycle allows an unprivileged attacker to permanently occupy the debt ceiling and DoS minting - (File: `substrate/frame/psm/src/lib.rs`)

### Summary
The Peg Stability Module (`pallet-psm`) exposes public `mint` and `redeem` extrinsics that are gated only by an aggregate debt ceiling (`PsmInfo::max_debt`) and a per-external-asset ceiling (`max_asset_debt`). When an admin sets `MintingFee`/`RedemptionFee` to `0` for a pair (a legitimate, intended configuration to encourage adoption or maintain a tight peg), any unprivileged user can mint up to the ceiling and hold that position indefinitely at zero net cost, permanently blocking all other users' `mint` calls with `Error::ExceedsMaxPsmDebt`. This is structurally the same broken invariant as the Beedle report: a protocol-level decision to set a fee to `0` turns a normally self-limiting operation (locking capacity that should cost something) into a free, indefinitely sustainable denial-of-service against a public entry point.

### Finding Description
`mint` checks both the aggregate ceiling and the per-asset ceiling before minting: [1](#0-0) 

```rust
let fee_rate = MintingFee::<T>::get(&internal_asset, &external_asset);
ensure!(fee_rate <= max_fee, Error::<T>::FeeTooHigh);
let fee = fee_rate.mul_ceil(internal_equivalent);
let internal_to_user = internal_equivalent.saturating_sub(fee);

let current_total_psm_debt = Self::total_psm_debt(&internal_asset);
ensure!(
    current_total_psm_debt.saturating_add(internal_equivalent) <= info.max_debt,
    Error::<T>::ExceedsMaxPsmDebt
);

let current_debt = PsmDebt::<T>::get(&internal_asset, &external_asset);
let max_debt = Self::max_asset_debt(&internal_asset, &external_asset, &info);
let new_debt = current_debt.saturating_add(internal_equivalent);
ensure!(new_debt <= max_debt, Error::<T>::ExceedsMaxPsmDebt);
``` [2](#0-1) 

`PsmDebt` only decreases when the position holder calls `redeem`, which — like `mint` — deducts a fee computed purely from `RedemptionFee` with no time-based decay or holding cost: [3](#0-2) 

```rust
ensure!(internal_amount >= info.min_swap_amount, Error::<T>::BelowMinimumSwap);
let fee_rate = RedemptionFee::<T>::get(&internal_asset, &external_asset);
ensure!(fee_rate <= max_fee, Error::<T>::FeeTooHigh);
let fee = fee_rate.mul_ceil(internal_amount);
...
let current_debt = PsmDebt::<T>::get(&internal_asset, &external_asset);
ensure!(current_debt >= effective_internal_net, Error::<T>::InsufficientReserve);
```

Unlike Beedle's lending flow, there is no interest that accrues over time here — the only "cost" of holding a mint position is the `RedemptionFee`/`MintingFee` themselves. When both are configured to `0` (a supported, intended admin operation via `set_minting_fee`/`set_redemption_fee`, as documented in the pallet's own README), a `mint` → hold → `redeem` → `mint` cycle costs the attacker nothing beyond gas and momentarily bonding their own external asset, which they always get back in full. The attacker can therefore:
1. Mint up to `max_debt`/`max_asset_debt` for a given `(internal_asset, external_asset)` pair.
2. Never redeem (or redeem and immediately re-mint), keeping `PsmDebt` pinned at the ceiling.
3. Every subsequent legitimate `mint` call from any other user reverts with `Error::ExceedsMaxPsmDebt`, indefinitely.

This is precisely the Beedle bug class: setting a fee parameter to `0` removes the economic disincentive that normally makes exhausting a shared, capacity-limited resource (pool liquidity in Beedle, debt ceiling in PSM) costly, letting an unprivileged actor permanently deny the operation to everyone else. No front-running of any specific victim transaction is required — the attacker can occupy the ceiling proactively at any time and simply choose not to release it, which is a stronger and more persistent DoS than the front-run scenario in the original report.

### Impact Explanation
This compromises the intended behavior of the PSM pallet: minting (external → internal) becomes permanently unavailable for a given instance/asset pair whenever fees are `0`, at zero cost to the attacker. Since the PSM's stated purpose is to provide continuous arbitrage-based peg support, denying `mint` defeats that purpose and can be sustained indefinitely by a single unprivileged account, without needing any malicious admin, validator, collator, or relayer.

### Likelihood Explanation
Likelihood is conditional on an admin setting `MintingFee`/`RedemptionFee` to `0` for a pair — a supported, non-malicious configuration explicitly enabled by `set_minting_fee`/`set_redemption_fee`. Given that configuration, exploitation requires only a single signed `mint` call sized to the ceiling and no special timing, making it trivially and repeatably executable by any account with enough external-asset liquidity (which is returned via `redeem`).

### Recommendation
- Do not allow `MintingFee` and `RedemptionFee` to both be `0` simultaneously for the same pair, or enforce a protocol-level minimum fee floor independent of the configured `Permill` value.
- Alternatively, introduce a minimum holding period, a per-account ceiling share, or a decay/cooldown mechanism so that occupying the debt ceiling is not costless and cannot be held indefinitely by a single account.
- Consider exempting the ceiling check from being fully consumable by a single account, or adding a queue/priority mechanism so legitimate minters are not entirely blocked by one large zero-fee position.

### Proof of Concept
1. Admin creates a PSM instance for `internal_asset` with `max_debt = M` and approves `external_asset` with `AssetCeilingWeight` such that `max_asset_debt = M` (single external asset).
2. Admin calls `set_minting_fee(internal_asset, external_asset, Permill::zero())` and `set_redemption_fee(internal_asset, external_asset, Permill::zero())`.
3. Attacker funds themselves with `M` external_asset (equivalent) and calls:
```rust
Psm::mint(
    RuntimeOrigin::signed(attacker),
    internal_asset,
    external_asset,
    external_amount_equivalent_to(M),
    Permill::zero(),
)?;
```
   This succeeds and sets `PsmDebt::<T>::get(internal_asset, external_asset) == max_asset_debt`, per [4](#0-3) .
4. Any other user (e.g. `alice`) calling `mint` for the same pair now reverts with `Error::ExceedsMaxPsmDebt` for as long as the attacker holds the position, per the ceiling checks at [5](#0-4) .
5. Attacker never redeems (or redeems and immediately re-mints, since `redeem` also costs `0` fee per [6](#0-5) ), sustaining the DoS indefinitely at no net cost.
