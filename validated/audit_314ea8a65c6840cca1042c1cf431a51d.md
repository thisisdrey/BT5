## Title
Protocol fee on NEP-245/IMT `TokenDiff` trades can be fully bypassed by splitting one large negative delta into many unit (`amount == 1`) deltas - (File: `contracts/defuse/core/src/intents/token_diff.rs`)

### Summary
`TokenDiff::token_fee` waives the fee entirely whenever the *absolute delta of a single intent* on a NEP-245 (or IMT) token is `<= 1`, regardless of how many such unit-sized intents are batched together for the same signer and token. Because `TokenDiff::execute_intent` computes and collects fees independently for each intent, a signer can split one 1000-unit NEP-245 trade into 1000 unit-delta `TokenDiff` intents (either as 1000 sub-intents in one signed payload, or as 1000 separately signed `MultiPayload`s in one batch) and pay zero fee, whereas a single `-1000` intent would pay `fee.fee_ceil(1000)`.

### Finding Description
The broken binding: `fees_collected[T]` after processing a batch should equal `Pips::fee_ceil(total_negative_delta_of_T_in_batch, protocol_fee)`. In the code, it instead equals `Σ over each individual TokenDiff intent of token_fee(T, |delta_i|, protocol_fee).fee_ceil(|delta_i|)`.

`TokenDiff::execute_intent` (contracts/defuse/core/src/intents/token_diff.rs:59-78) iterates the diff map of a *single* intent, and for every negative delta calls:

```rust
let amount = delta.unsigned_abs();
let fee = Self::token_fee(token_id, amount, protocol_fee).fee_ceil(amount);
``` [1](#0-0) 

`token_fee` (contracts/defuse/core/src/intents/token_diff.rs:206-217) has a per-intent `amount` threshold:

```rust
pub fn token_fee(token_id: impl Into<TokenIdType>, amount: u128, fee: Pips) -> Pips {
    let token_id = token_id.into();
    match token_id {
        TokenIdType::Nep141 => {}
        TokenIdType::Nep245 | TokenIdType::Imt if amount > 1 => {}
        // do not take fees on NFTs and MTs with |delta| <= 1
        TokenIdType::Nep171 | TokenIdType::Nep245 | TokenIdType::Imt => return Pips::ZERO,
    }
    fee
}
``` [2](#0-1) 

This "no fee on single-unit NFT/MT transfers" rule was presumably intended for genuinely indivisible NFT-like items, but NEP-245 (`Nep245TokenId`) is also used for fungible multi-token balances (e.g. wrapped verifier positions, as seen in `contracts/escrow-swap` tests using `Nep245TokenId` to represent verifier-custodied fungible balances). The threshold is evaluated **per `TokenDiff` intent, per token**, not aggregated across the batch or across a signer's intents.

`Engine::execute_signed_intents` loops over each `MultiPayload` and calls `execute_signed_intent`, which independently verifies, checks nonce, and executes `intents.execute_intent(...)` per payload [3](#0-2) . `DefuseIntents::execute_intent` simply loops calling `intent.execute_intent` for each sub-intent [4](#0-3) . Neither loop aggregates deltas by token before computing fees — only `Engine::finalize` checks that the **net supply** balances to zero across the whole batch (via `Deltas::finalize`), it does not re-derive or enforce the correct fee [5](#0-4) .

Exploit: the signer (attacker) constructs either
- one signed `DefusePayload<DefuseIntents>` with 1000 `TokenDiff` sub-intents, each `diff == {nep245_token: -1, other_token: +k}` (self-consistent unit swaps summing to the intended 1000/total trade), or
- 1000 separately signed `MultiPayload`s (distinct nonces) with the same unit diffs, bundled into one `execute_intents` call,

so that every individual `TokenDiff::execute_intent` call sees `amount == 1` for the NEP-245 token, `token_fee` returns `Pips::ZERO`, and `fees_collected` stays empty for that token in every single call. The overall batch invariant (sum of deltas nets to zero, accounted for the — now zero — fee) still passes, because `finalize` only checks the total, not what the fee *should* have been. No guard (`has_public_key`, `verify_intent_nonce`, `commit_nonce`, `finalize`'s invariant check) inspects aggregate traded amount per token across intents/payloads to prevent this.

### Impact Explanation
The fee_collector under-collects protocol fees on any NEP-245/IMT-denominated trade that is split into unit-sized `TokenDiff` legs; a party trading 1000 units pays 0 fee instead of `protocol_fee.fee_ceil(1000)`. This is repeatable for any account, any NEP-245/IMT `TokenId`, and any trade size (arbitrarily large trades can be split into arbitrarily many unit legs at the cost of extra intents/signatures, which is cheap and requires no privileged role). This matches the "protocol fees bypassed" Critical category explicitly listed in scope, since value that should flow to the fee_collector never leaves the trading parties' balances.

### Likelihood Explanation
Preconditions are minimal: the attacker only needs a Verifier balance of the NEP-245/IMT token they want to trade and a positive `protocol_fee` (precondition explicitly given). No role, relayer key, or DAO action is required — the attacker signs their own payload(s) and calls `execute_intents`/`simulate_intents` themselves. Splitting one trade into N unit legs costs only extra payload size/gas, well within a single transaction's gas budget for realistic N. This is fully repeatable across accounts, tokens, and batches.

### Recommendation
Compute `token_fee`'s NFT/MT "no-fee" exemption based on the token's semantics (e.g., is it enumerable as `amount == total_supply == 1`, or does the token type itself declare non-fungibility), not on the per-intent traded `amount`, or alternatively aggregate all negative deltas per `(signer, token_id)` across the whole batch before applying the `amount > 1` threshold, so splitting into unit-sized legs cannot change the total fee owed.

### Proof of Concept
`cargo test` (workspace `tests` crate, near-workspaces sandbox), extending `tests/src/tests/defuse/intents/token_diff.rs`:
1. Deploy Defuse with `protocol_fee = Pips::ONE_PERCENT` (or any nonzero fee), fee_collector account.
2. Create a NEP-245 token id (`Nep245TokenId`) and deposit 1000 units to `signer`, plus deposit matching counter-token to a `counterparty`/solver to satisfy the invariant.
3. **Baseline**: sign a single `TokenDiff { diff: {nep245_token: -1000, other_token: +X} }` from `signer` matched with a counterparty `TokenDiff` that closes the batch invariant (using `TokenDiff::closure_delta`). Execute via `execute_intents`. Assert `fee_collector`'s balance of `nep245_token` == `fee.fee_ceil(1000)` (nonzero).
4. **Split**: sign 1000 `TokenDiff` sub-intents (in one payload or 1000 signed payloads with distinct nonces), each `{nep245_token: -1, other_token: +x_i}`, summing to the same net trade, matched by counterparty legs so the batch invariant holds. Execute via `execute_intents`.
5. Assert `fee_collector`'s balance of `nep245_token` after step 4 == `0`, while `signer`'s net balance change and `counterparty`'s net balance change are identical to step 3's (same effective trade).
6. Assert `0 != fee.fee_ceil(1000)`, proving the fee actually collected diverges from the fee that should have been collected for the same net trade, demonstrating the bypass.

    fn execute_signed_intent(&mut self, signed: MultiPayload) -> Result<()> {
        // verify signed payload and get public key
        let public_key = signed.verify().ok_or(DefuseError::InvalidSignature)?;

        // calculate intent hash
        let hash = signed.hash();

        // extract NEP-413 payload
        let DefusePayload::<DefuseIntents> {
            signer_id,
            verifying_contract,
            deadline,
            nonce,
            message: intents,
        } = signed.extract_defuse_payload()?;

        // check recipient
        if verifying_contract != *self.state.verifying_contract() {
            return Err(DefuseError::WrongVerifyingContract);
        }

        self.inspector.on_deadline(deadline);

        // make sure message is still valid
        if deadline < Timestamp::now() {
            return Err(DefuseError::DeadlineExpired);
        }

        // make sure the account has this public key
        if !self.state.has_public_key(&signer_id, &public_key) {
            return Err(DefuseError::PublicKeyNotExist(signer_id, public_key));
        }

        // commit nonce
        self.verify_intent_nonce(nonce, deadline)?;
        self.state.commit_nonce(signer_id.clone(), nonce)?;

        intents.execute_intent(&signer_id, self, hash)?;
        self.inspector.on_intent_executed(&signer_id, hash, nonce);

        Ok(())
    }

impl ExecutableIntent for DefuseIntents {
    fn execute_intent<S, I>(
        self,
        signer_id: &AccountIdRef,
        engine: &mut Engine<S, I>,
        intent_hash: [u8; 32],
    ) -> Result<()>
    where

        I: Inspector,

            intent.execute_intent(signer_id, engine, intent_hash)?;
