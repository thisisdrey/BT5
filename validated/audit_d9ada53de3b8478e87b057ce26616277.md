### Title
Snowbridge v2 outbound queue pays relayer rewards for failed Ethereum executions - (File: `bridges/snowbridge/pallets/outbound-queue-v2/src/lib.rs`)

### Summary
The external report’s core bug is a missing state check before a payout: a position is liquidated, but the protection-claim path does not notice and still injects funds, leaving them trapped. The local analog is in the Snowbridge v2 outbound queue: a delivery receipt carries a `success` flag that reports whether the message actually executed on Ethereum, but `process_delivery_receipt` never reads it. It registers the relayer reward and deletes the `PendingOrder` for any valid receipt, so a message that reverts on Ethereum (`success == false`) is still paid. The attacker primitive is an unprivileged relayer calling `submit_delivery_receipt` with a valid proof of a failed delivery and then claiming the fee.

### Finding Description
The Ethereum gateway emits `InboundMessageDispatched(nonce, topic, success, reward_address)`, so the bridge explicitly records whether execution succeeded. [1](#0-0)  That `success` value is decoded into `DeliveryReceipt.success`. [2](#0-1)  The public extrinsic `submit_delivery_receipt` verifies the proof, converts the log to a `DeliveryReceipt`, and forwards it to `process_delivery_receipt`. [3](#0-2)  `process_delivery_receipt` only checks that the log came from the configured gateway and that a `PendingOrder` exists for the nonce; it then registers the order’s fee as a relayer reward and removes the order. [4](#0-3)  The `success` field is never consulted, so a failed execution is treated the same as a successful one. [5](#0-4) 

### Impact Explanation
This is an unbacked bridge reward payout. A relayer can be paid the full message fee even though the message did not achieve its intended effect on Ethereum. If failed deliveries are cheap to produce or common, the bridge’s reward pool / sovereign account is drained, and relayers are incentivized to relay failing traffic. It falls under the Polkadot SDK impact gate for “theft or unbacked mint or unlock” and “duplicate settlement or payout” in bridge reward flows. [6](#0-5) 

### Likelihood Explanation
The path is public and unprivileged: any signed account can call `submit_delivery_receipt`. Producing the proof does not require a malicious Ethereum node, collator, or governance actor; it only requires observing a real `InboundMessageDispatched` event on Ethereum and relaying it. The nonce check prevents double-claiming the same receipt, but it does not stop the first claim for a reverted message.

### Recommendation
In `process_delivery_receipt`, branch on `receipt.success` before registering the reward. If `success == false`, either skip the reward and remove the pending order, or pay a reduced/different reward and document the semantics. If the intended design is to pay for delivery regardless of execution outcome, the `success` field should be removed from the reward path and the behavior documented; otherwise the current code is a live vulnerability.

### Proof of Concept
```rust
// On Ethereum, a Snowbridge v2 outbound message with nonce N and fee F is dispatched
// but the inner call reverts, so the gateway emits:
// InboundMessageDispatched(nonce=N, topic=..., success=false, reward_address=...)

// Any relayer observes the event, builds an EventProof, and submits:
EthereumOutboundQueueV2::submit_delivery_receipt(
    RuntimeOrigin::signed(relayer),
    Box::new(event_proof),
);

// Inside the extrinsic:
let receipt = DeliveryReceipt::try_from(&event.event_log).unwrap(); // receipt.success == false
Self::process_delivery_receipt(relayer, receipt).unwrap();

// process_delivery_receipt does:
//   ensure!(gateway correct);
//   let order = PendingOrders::get(nonce).unwrap(); // order.fee == F
//   RewardPayment::register_reward(&reward_account, DefaultRewardKind::get(), F);
//   PendingOrders::remove(nonce);

// The relayer then calls:
BridgeRelayers::claim_rewards(RuntimeOrigin::signed(relayer), BridgeReward::Snowbridge);
// and receives F even though the message execution failed.
```
