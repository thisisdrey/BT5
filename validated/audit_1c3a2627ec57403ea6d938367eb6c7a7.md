## Analysis

The D-Bus CVE describes a crash caused by a peer sending an ancillary/control message with attached file descriptors in an unexpected format (malformed `SCM_RIGHTS`-style payload). The closest Go analog is `syscall.ParseUnixRights`, which decodes the `SCM_RIGHTS` ancillary data returned by `Recvmsg`/`ReadMsgUnix` from a Unix-domain socket peer. [1](#0-0) 

`ParseUnixRights` sizes its output slice with `len(m.Data)>>2` (integer division that silently truncates when the data length is not a multiple of 4), but its copy loop steps `i` by 4 up to `len(m.Data)` and writes to `fds[j]` unconditionally, causing an index-out-of-range panic whenever `m.Data` is not a multiple of 4 bytes long. `m.Data` itself is bounded only by `ParseSocketControlMessage`, which accepts any `Header.Len` between `SizeofCmsghdr` and the buffer length without requiring 4-byte alignment. [2](#0-1) 

Both `net.UnixConn.ReadMsgUnix` and raw `syscall.Recvmsg` deliver attacker-controlled out-of-band bytes directly into this code path, and existing tests exercise exactly this flow (parsing `SCM_RIGHTS` ancillary data received from a peer over a `Socketpair`/Unix socket). [3](#0-2) [4](#0-3) 

### Title
Out-of-bounds slice write panic in `syscall.ParseUnixRights` on malformed `SCM_RIGHTS` ancillary data length - (File: src/syscall/sockcmsg_unix.go)

### Summary
`syscall.ParseUnixRights` computes its output slice length as `len(m.Data)>>2`, truncating any remainder, but its fill loop iterates over the full `len(m.Data)` in 4-byte steps and unconditionally indexes into that under-sized slice. A Unix-domain-socket peer that sends an `SCM_RIGHTS` control message whose data length is not a multiple of 4 (a "message with attached file descriptors in an unexpected format", directly analogous to CVE-2022-42012's D-Bus crash) causes any Go program that parses received ancillary data with this function to panic with an index-out-of-range error.

### Finding Description
An ordinary local peer connects to a Unix-domain socket and calls the raw `sendmsg(2)`/`Sendmsg` syscall with a crafted `SOL_SOCKET`/`SCM_RIGHTS` control message whose `Cmsghdr.Len` yields a `Data` payload of, e.g., 3, 5, 6, or 7 bytes (i.e., not divisible by 4) rather than using the well-formed `syscall.UnixRights` encoder. The victim program calls `net.UnixConn.ReadMsgUnix` or `syscall.Recvmsg`, then `syscall.ParseSocketControlMessage(oob)` — which only validates `h.Len >= SizeofCmsghdr` and `h.Len <= len(b)`, not 4-byte alignment (`src/syscall/sockcmsg_unix.go:54-60`) — and finally `syscall.ParseUnixRights(&scm)` on the resulting `SocketControlMessage`. Inside `ParseUnixRights`, `fds := make([]int, len(m.Data)>>2)` under-allocates relative to the loop bound `i < len(m.Data)` stepping by 4, so the last iteration(s) write to `fds[j]` beyond the allocated length, triggering `panic: runtime error: index out of range`.

### Impact Explanation
A malicious but unprivileged local peer can crash any Go server or daemon that receives and parses SCM_RIGHTS/file-descriptor-passing messages over a Unix-domain socket (a common pattern for privilege-separated helpers, container runtimes, or IPC daemons written in Go), producing a denial of service via panic. This is analogous to CVE-2022-42012's "authenticated attacker can cause dbus-daemon ... to crash by sending a message with attached file descriptors in an unexpected format." This would fall under Go's PUBLIC track as a real, input-triggerable panic in a standard-library parsing function reachable from untrusted peer data.

### Likelihood Explanation
Any process capable of connecting to the target's Unix-domain socket (which does not require special privilege beyond filesystem/socket access — analogous to an "authenticated" D-Bus peer) can trigger this by using raw `sendmsg` with a hand-crafted control message instead of the standard `syscall.UnixRights` helper. This is straightforward to construct and does not require huge input or resource exhaustion — a single malformed message is sufficient.

### Recommendation
In `ParseUnixRights` (`src/syscall/sockcmsg_unix.go`), validate that `len(m.Data)` is a non-negative multiple of 4 before indexing, returning `EINVAL` otherwise, e.g.:
```go
func ParseUnixRights(m *SocketControlMessage) ([]int, error) {
	if m.Header.Level != SOL_SOCKET {
		return nil, EINVAL
	}
	if m.Header.Type != SCM_RIGHTS {
		return nil, EINVAL
	}
	if len(m.Data)%4 != 0 {
		return nil, EINVAL
	}
	fds := make([]int, len(m.Data)/4)
	...
}
```

```go
package syscall_test

import (
	"syscall"
	"testing"

// TestParseUnixRightsMalformedLength demonstrates a panic in
// syscall.ParseUnixRights when the SCM_RIGHTS control message data
// length is not a multiple of 4, analogous to CVE-2022-42012's
// "message with attached file descriptors in an unexpected format".
func TestParseUnixRightsMalformedLength(t *testing.T) {
	defer func() {
		if r := recover(); r == nil {
			t.Fatal("expected panic due to malformed SCM_RIGHTS data length, got none")
		}
	}()

	m := syscall.SocketControlMessage{
		Header: syscall.Cmsghdr{
			Level: syscall.SOL_SOCKET,
			Type:  syscall.SCM_RIGHTS,
		},
		Data: make([]byte, 3), // not a multiple of 4
	}

	// Should return an error, but instead panics: index out of range.
	_, _ = syscall.ParseUnixRights(&m)
}
```

```go
// ParseUnixRights decodes a socket control message that contains an
// integer array of open file descriptors from another process.
func ParseUnixRights(m *SocketControlMessage) ([]int, error) {
	if m.Header.Level != SOL_SOCKET {
		return nil, EINVAL
	}
	if m.Header.Type != SCM_RIGHTS {
		return nil, EINVAL
	}
	fds := make([]int, len(m.Data)>>2)
	for i, j := 0, 0; i < len(m.Data); i += 4 {
		fds[j] = int(*(*int32)(unsafe.Pointer(&m.Data[i])))
		j++
	}
	return fds, nil
}
```
