Found it. `handleRecvError` in `outside.go` is reachable entirely pre-authentication — it is dispatched straight out of `readOutsidePackets` for `header.RecvError` packets before any index/hostinfo/ConnectionState lookup, and it never verifies a certificate, HMAC, or cryptographic binding to the tunnel.

### Title
Unauthenticated RecvError packets allow remote tunnel-teardown / state poisoning without a valid certificate - (File: `outside.go`)

### Summary
`RecvError` packets are handled before any handshake or decryption step, and the only "check" performed is a plaintext UDP source-address match against the last known remote endpoint of the tunnel that owns the guessed index. An attacker with no CA-signed certificate — anyone who can send raw UDP to the listen port — can guess/enumerate remote indexes and spoof the source address to force `closeTunnel` on an active tunnel.

### Finding Description
`readOutsidePackets` dispatches `header.RecvError` to `f.handleRecvError` immediately after header parsing, prior to any `hostMap.QueryIndex` gating that other message types go through for real payload decryption: [1](#0-0) 

`handleRecvError` itself performs no cryptographic verification. It only checks a config toggle (`acceptRecvErrorConfig`) and then compares the packet's plaintext source `netip.AddrPort` against the hostinfo's currently recorded remote: [2](#0-1) 

Because `h.RemoteIndex` is a 32-bit value chosen by `generateIndex` and is not secret (it is visible on the wire on every packet of a tunnel, and is not bound to any secret/HMAC in the `RecvError` message itself), an attacker who has observed any traffic for a target index, or who simply brute-forces the 32-bit space, can forge a `RecvError` packet from a spoofed UDP source address matching `hostinfo.GetRemote()`. The check `hr.IsValid() && hr != addr` is exactly the kind of ad hoc "who is calling" check the reported bug class flags as insufficient — it relies on unauthenticated, spoofable UDP source-address matching rather than certificate/HMAC-based authentication, and it accepts an unauthenticated "cancel this trade/relationship" message the same way MarginRouter accepted unauthenticated swap instructions.

This directly matches the "no entry checks" bug class from the external report, mapped onto Nebula's remote-state-trust surface: a message type that mutates tunnel/hostmap state (`f.closeTunnel(hostinfo)` and `f.handshakeManager.DeleteHostInfo(hostinfo)`) is processed without verifying the sender holds a CA-signed certificate for the claimed identity.

### Impact Explanation
An off-path/unauthenticated attacker can force termination of an established, authenticated Nebula tunnel between two legitimate peers by spoofing a UDP packet, causing denial of service / repeated tunnel teardown and re-handshake churn. This is a remote state-poisoning primitive reachable without any certificate.

### Likelihood Explanation
Likelihood is moderate: it requires UDP source-address spoofing (feasible on many networks, especially if attacker is on-path or the underlying network doesn't filter spoofed source IPs) and knowledge/guessing of `RemoteIndex`, which is observable from any sniffed packet of the target tunnel and is only 32 bits (brute-forceable). `acceptRecvErrorConfig` defaults per `recvErrorConfig` in `interface.go` and, unless set to `recvErrorNever`, this path is live by default for at least private/all endpoints.

### Recommendation
Do not act on `RecvError` based on plaintext source-address matching alone. Require the `RecvError` message (or an equivalent authenticated control message) to be cryptographically bound to the tunnel it claims to terminate — e.g., only honor it if it arrives protected by the existing tunnel's AEAD key/counter (similar to how `Control`/`CloseTunnel` messages are decrypted with `hostinfo.ConnectionState` before being acted upon), or require a fresh nonce signed/MACed with the session key so a spoofed/off-path attacker without knowledge of `dKey`/`eKey` cannot trigger it.

### Proof of Concept
1. Establish a legitimate tunnel between hosts A and B; observe any UDP packet exchanged to learn B's `RemoteIndex` (visible in cleartext header) and A's/B's `netip.AddrPort`.
2. Craft a `header.RecvError` packet (`header.Encode(..., header.RecvError, 0, observedIndex, 0)`) as done in `sendRecvError`.
3. Send it via UDP to B, spoofing the source address to match A's currently known remote endpoint (or simply send from A's actual network path if attacker is on-path/NAT-shared).
4. B's `handleRecvError` finds the hostinfo by `QueryReverseIndex`, sees `hr == addr`, and calls `f.closeTunnel(hostinfo)` plus `hm.DeleteHostInfo(hostinfo)`, tearing down the tunnel without any certificate check — reference code: [3](#0-2) .

func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
