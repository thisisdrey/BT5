Go's `encoding/xml` package, which is the closest analog to a general-purpose XML parser in this repository, does not implement DTD-based external entity resolution at all. The decoder's `rawToken` function treats `<!DOCTYPE ...>`, `<!ENTITY ...>`, and other markup declarations as opaque `Directive` tokens that are captured verbatim for the caller but never interpreted or resolved [1](#0-0) . Only the five predefined XML entities (`lt`, `gt`, `amp`, `apos`, `quot`) and entries in the caller-supplied `Decoder.Entity` map are expanded by the `text` function; there is no mechanism to register or resolve `SYSTEM`/`PUBLIC` external entities that would cause the parser to fetch a local file or a URL [2](#0-1) . This is corroborated by the package tests, which show that `<!DOCTYPE [<!ENTITY ...>]>` constructs are round-tripped as plain `Directive` byte strings rather than acted upon [3](#0-2) .

Because the reported CVE-2012-5656 is specifically about an XXE primitive — a parser resolving an externally-declared entity (`SYSTEM`/`PUBLIC`) to read arbitrary local files during rasterization — and Go's `encoding/xml` decoder has no code path that performs DTD/external-entity resolution or file/URL fetching based on `<!ENTITY>` declarations, there is no matching primitive to prove root cause against in this repository's production Go source.

	var trunc int
