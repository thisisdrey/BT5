### Title
Unauthenticated `POST /shutdown` permanently halts signer event ingestion - (File: libsigner/src/events.rs)

### Summary
`SignerEventReceiver::next_event` handles the `/shutdown` URL by unconditionally setting `stop_signal` to `true` and returning `EventError::Terminated`, with no authentication, secret, or source-IP check of any kind. Any TCP client that can reach the signer's event-receiver bind address can send a single HTTP POST to permanently stop the signer's event-processing `main_loop`.

### Finding Description
The intended invariant is that only the node operator (or the co-located `stacks-node` configured to post events, or the signer's own internal `SignerStopSignaler`) should be able to terminate the event receiver. The code breaks this: in `next_event`, every branch of the URL dispatch (`/status`, `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/shutdown`, `/new_block`) is reachable to any caller who completes an HTTP request against the bound socket, with the only gating being `request.method() != &HttpMethod::Post`. The `/shutdown` branch performs no signature check, no shared-secret check, and no peer-address check:

```rust
} else if request.url() == "/shutdown" {
    event_receiver.stop_signal.store(true, Ordering::SeqCst);
    Err(EventError::Terminated)
}
``` [1](#0-0) 

This is the exact same mechanism used internally by `SignerStopSignaler::send`, which crafts a raw `POST /shutdown HTTP/1.1` request over a `TcpStream` to itself to wake up the blocking `next_event` call and stop the loop [2](#0-1) . Because the HTTP server has no notion of caller identity, any remote client capable of forming that exact same request against the exposed port achieves the identical effect.

Once `stop_signal` is `true`, `is_stopped()` returns `true` [3](#0-2) , and `main_loop` immediately breaks and exits on its next iteration check [4](#0-3) , permanently ending event ingestion for that signer process (no auto-restart logic exists in this file).

### Impact Explanation
A single unauthenticated HTTP POST terminates the signer's `main_loop`, which is the sole path for the signer to observe StackerDB chunk events, block-validation responses, burn-block events, and new-block events from the node. Once stopped, the signer stops responding to block proposals/signing duties until the operator manually restarts the process, an unauthenticated remote denial-of-service consistent with the "Critical - remote crash/unauthenticated DoS from few messages" category. This is repeatable trivially by resending the same request whenever the process is restarted.

### Likelihood Explanation
Preconditions are minimal: the attacker only needs TCP reachability to the signer's configured event-receiver bind address and the ability to send a well-formed HTTP/1.1 POST request; no key, slot ownership, RPC secret, or admin role is required. The attack costs a single short TCP connection and is fully repeatable. Real-world likelihood depends on whether the operator has restricted this bind address to a private/loopback interface via firewalling or configuration; the code itself provides no such protection, so any deployment that exposes this address beyond a trusted network segment is immediately vulnerable.

### Recommendation
Add authentication to the event-receiver HTTP endpoints, at minimum for `/shutdown`: require a shared secret/token configured out-of-band between the node and the signer (e.g., an `Authorization` header checked against a locally configured value), or restrict acceptance of `/shutdown` (and ideally all POST endpoints) to loopback/allow-listed peer addresses via `request.remote_addr()`. At minimum, gate `/shutdown` behind a value only known to the legitimate stop-signaler.

### Proof of Concept
```rust
// In libsigner::events tests
#[test]
fn unauthenticated_remote_shutdown() {
    let mut receiver = SignerEventReceiver::<StacksBlockEvent /* or relevant T */>::new(false);
    let addr = receiver.bind("127.0.0.1:0".parse().unwrap()).unwrap();

    let handle = std::thread::spawn(move || {
        // simulate main_loop: call next_event in a loop
        let _ = receiver.next_event(); // should return Err(Terminated) after attack
        assert!(receiver.is_stopped());
    });

    // Attacker: no credentials, just a raw TCP connection
    let mut stream = TcpStream::connect(addr).unwrap();
    let req = "POST /shutdown HTTP/1.1\r\nHost: x\r\nConnection: close\r\nContent-Length: 0\r\n\r\n";
    stream.write_all(req.as_bytes()).unwrap();

    handle.join().unwrap();
}
```

    fn main_loop(&mut self) {
        loop {
            if self.is_stopped() {
                info!("Event receiver stopped");
                break;
            }
            let next_event = match self.next_event() {
                Ok(event) => event,
                Err(EventError::UnrecognizedEvent(..)) => {
                    // got an event that we don't care about (not a problem)
                    continue;
                }
                Err(EventError::Terminated) => {
                    // we're done
                    info!("Caught termination signal");
                    break;
                }
                Err(e) => {
                    warn!("Failed to receive next event: {:?}", &e);
                    continue;
                }
            };
            if !self.forward_event(next_event) {
                info!("Failed to forward event");
                break;
            }
        }
        info!("Event receiver main loop exit");
    }
