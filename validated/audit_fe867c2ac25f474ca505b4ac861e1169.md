### Title
LinkRepositoryToObjectPool grants cross-repository object access without ownership verification - (File: internal/gitaly/service/objectpool/link.go)

### Summary
`LinkRepositoryToObjectPool` accepts two independent, caller-supplied repository references — `repository` (the target to be linked) and `object_pool` (the pool to link to) — and unconditionally links them without verifying that the object pool actually belongs to, or was derived from, the target repository. This mirrors the Yieldy `burn()` bug class: a privileged mutating operation trusts a caller-supplied "victim" argument (the object pool) instead of scoping the action to a resource the caller is authorized over.

### Finding Description
The gRPC handler only validates that `repository` is a well-formed repository and that a pool object resolves from the request; it performs no check binding the pool to the repository's project/fork lineage: [1](#0-0) 

The core `Link` function then writes the pool's object directory path directly into the target repository's `objects/info/alternates` file as soon as `s.locator.ValidateRepository` and `poolForRequest` succeed, with no ownership relationship check between `pool` and `repo`: [2](#0-1) 

Because Git's alternates mechanism makes every object in the alternate (pool) directory transparently readable from the linked repository (as documented in `object_quarantine.md` and exercised by `TestDisconnectGitAlternates`), any repository that can be linked to an arbitrary pool gains read access to all of that pool's objects: [3](#0-2) 

The proto definitions confirm both fields are independently attacker/caller-influenceable request fields rather than values Gitaly itself derives from a verified relationship: [4](#0-3) 

The only correctness checks performed elsewhere in the object-pool/alternate code path are limited to path-escape and partition-locality validation (e.g. `getAlternatePartitionID`, `ValidateRelativePath`), not to authorization/ownership between the two repositories: [5](#0-4) 

### Impact Explanation
If a caller (or a component acting on a caller's behalf, e.g. via a forged/duplicated internal API call, replication path, or a bug in the caller-side authorization that supplies this field) can control the `object_pool` value of a `LinkRepositoryToObjectPoolRequest` independent of the actual fork/pool relationship of `repository`, it can link its own repository to an arbitrary victim object pool on the same storage/partition. Deduplication of objects from that point onward exposes all of the pool's objects (commits, blobs, trees — potentially private source code) to the linked repository, which can then read them via ordinary Git/RPC object access. This is a cross-repository object disclosure, directly analogous to `burn()` letting `MINTER_BURNER_ROLE` operate on an arbitrary address instead of only the caller's own balance.

### Likelihood Explanation
`LinkRepositoryToObjectPool` is a `MUTATOR` RPC reachable through the normal fork-creation flow (`CreateFork` → `CreateObjectPool` → `LinkRepositoryToObjectPool`), and Gitaly's own handler code performs no defense-in-depth check that the `object_pool` argument is actually associated with the `repository` argument — it fully trusts the caller (typically GitLab Rails) to only ever send matched pairs. Any way for that trust boundary to be bypassed or misused (compromised/impersonated internal API caller, logic bug upstream, or a Praefect/replication path that reconstructs the pool reference, as seen in `replicator.go`) directly triggers the cross-repository read.

### Recommendation
Enforce, within Gitaly itself, that a `LinkRepositoryToObjectPool` request's `object_pool` is verified to be an object pool that the target `repository` is legitimately entitled to join (e.g., by checking recorded pool membership/ancestry, such as via the partition/fork registry) rather than trusting the caller-supplied pair unconditionally, similar to how `getAlternatePartitionID` already restricts alternates to single, non-self, non-chained references.

### Proof of Concept
1. Create repository `A` (attacker-controlled) and repository `V` with a private object pool `P` (e.g., `V`'s fork network) not related to `A`.
2. Issue `LinkRepositoryToObjectPool(repository=A, object_pool=P)` through any code path capable of supplying arbitrary `object_pool` values (e.g., a caller impersonating/duplicating the internal Rails→Gitaly call, or a replication/import flow that reconstructs the pool reference as in `internal/praefect/replicator.go` lines 134-151).
3. Gitaly's handler validates only that `A` and `P` are valid repositories (`internal/gitaly/service/objectpool/link.go`) and calls `Link`, which writes `P`'s object directory into `A`'s `objects/info/alternates` (`internal/git/objectpool/link.go`).
4. Any Git/RPC read against `A` (e.g., `GetBlob`, `TreeEntry`) can now resolve objects that physically reside only in `P`, disclosing `V`'s objects to the attacker.

func (s *server) LinkRepositoryToObjectPool(ctx context.Context, req *gitalypb.LinkRepositoryToObjectPoolRequest) (*gitalypb.LinkRepositoryToObjectPoolResponse, error) {
	repository := req.GetRepository()
	if err := s.locator.ValidateRepository(ctx, repository); err != nil {
		return nil, structerr.NewInvalidArgument("%w", err)
	}

	pool, err := s.poolForRequest(ctx, req)
	if err != nil {
		return nil, err
	}

	repo := s.localRepoFactory.Build(repository)

	if err := pool.Link(ctx, repo); err != nil {
		return nil, structerr.NewInternal("%w", err)
	}

	return &gitalypb.LinkRepositoryToObjectPoolResponse{}, nil
}

func Link(ctx context.Context, pool, repo *localrepo.Repo, txManager transaction.Manager) (returnedErr error) {
	altPath, err := repo.InfoAlternatesPath(ctx)
	if err != nil {
		return err
	}

	expectedRelPath, err := getRelativeObjectPath(ctx, pool, repo)
	if err != nil {
		return err
	}

	linked, err := linkedToRepository(ctx, pool, repo)
	if err != nil {
		return err
	}

	if linked {
		// When the repository is already linked to the repository, cast a vote to ensure the
		// repository is consistent with the other replicas.
		if err := transaction.VoteOnContext(ctx, txManager, voting.VoteFromData([]byte("repository linked")), voting.Synchronized); err != nil {
			return fmt.Errorf("vote on linked repository: %w", err)
		}

		return nil
	}

	alternatesWriter, err := safe.NewLockingFileWriter(altPath)
	if err != nil {
		return fmt.Errorf("creating alternates writer: %w", err)
	}
	defer func() {
		if err := alternatesWriter.Close(); err != nil && returnedErr == nil {
			returnedErr = fmt.Errorf("closing alternates writer: %w", err)
		}
	}()

	if _, err := io.WriteString(alternatesWriter, expectedRelPath); err != nil {
		return fmt.Errorf("writing alternates: %w", err)
	}

func TestDisconnectGitAlternates(t *testing.T) {
	t.Parallel()

	ctx := testhelper.Context(t)
	cfg, repoProto, repoPath, _, client := setup(t, ctx)
	repo := localrepo.NewTestRepo(t, cfg, repoProto)

	commitID := gittest.WriteCommit(t, cfg, repoPath, gittest.WithBranch("main"))
	gittest.Exec(t, cfg, "-C", repoPath, "repack", "-Ad")

	// We create the object pool, link the original repository to it and then repack the pool
	// member. As the linking step should've pulled all objects into the pool, the repack should
	// get rid of the now-duplicate objects in the repository in favor of the pooled ones.
	_, pool, _ := createObjectPool(t, ctx, cfg, repoProto)
	require.NoError(t, pool.Link(ctx, repo))
	gittest.Exec(t, cfg, "-C", repoPath, "gc")

	// Corrupt the repository to check that the commit we have created can no longer be read.
	// This is done to ensure that the object really only exists in the pool repository now.
	altPath, err := repo.InfoAlternatesPath(ctx)
	require.NoError(t, err)
	require.NoError(t, os.Remove(altPath))
	gittest.RequireObjectNotExists(t, cfg, repoPath, commitID)

	// Recreate the alternates link and assert that we can now read the commit again.
	require.NoError(t, pool.Link(ctx, repo))
	require.FileExists(t, altPath, "objects/info/alternates should be back")
	gittest.RequireObjectExists(t, cfg, repoPath, commitID)

	// At this point we know that the repository has access to the commit, but only if
	// objects/info/alternates is in place.
	_, err = client.DisconnectGitAlternates(ctx, &gitalypb.DisconnectGitAlternatesRequest{Repository: repoProto})
	require.NoError(t, err)

	// Check that the object can still be found, even though objects/info/alternates is gone.
	// This is the purpose of DisconnectGitAlternates.
	commitClient := gitalypb.NewCommitServiceClient(gittest.DialService(t, ctx, cfg))
	gittest.RequireObjectExistsAPI(t, ctx, commitClient, repoProto, commitID)

func (pa *partitionAssigner) getAlternatePartitionID(ctx context.Context, relativePath string, recursiveCall bool, partitionHint storage.PartitionID) (storage.PartitionID, error) {
	alternate, err := gitstorage.ReadAlternatesFile(filepath.Join(pa.storagePath, relativePath))
	if err != nil {
		return 0, fmt.Errorf("read alternates file: %w", err)
	}

	if recursiveCall {
		// recursive being true indicates we've arrived here through another repository's alternate.
		// Repositories in Gitaly should only have a single alternate that points to the repository's
		// pool. Chains of alternates are unexpected and could go arbitrarily long, so fail the operation.
		return 0, storage.ErrAlternateHasAlternate
	}

	// The relative path should point somewhere within the same storage.
	alternateRelativePath, err := storage.ValidateRelativePath(
		pa.storagePath,
		// Take the relative path to the repository, not 'repository/objects'.
		filepath.Dir(
			// The path in alternates file points to the object directory of the alternate
			// repository. The path is relative to the repository's own object directory.
			filepath.Join(relativePath, "objects", alternate),
		),
	)
	if err != nil {
		return 0, fmt.Errorf("validate relative path: %w", err)
	}

	if alternateRelativePath == relativePath {
		// The alternate must not point to the repository itself. Not only is it non-sensical
		// but it would also cause a dead lock as the repository is locked during this call
		// already.
		return 0, storage.ErrAlternatePointsToSelf
	}
