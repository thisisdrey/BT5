### Title
Missing `supportUnfreezeDelay` feature-gate check in `FreezeBalanceV2Processor` allows TVM-triggered FreezeV2 to bypass committee-controlled activation - (File: actuator/src/main/java/org/tron/core/vm/nativecontract/FreezeBalanceV2Processor.java)

### Summary
The FreezeBalanceV2 feature is gated by the `supportUnfreezeDelay()` dynamic-properties flag, which must be explicitly turned on by the committee before FreezeV2/UnfreezeV2 transactions are supported. This check is enforced in the ordinary transaction path (`FreezeBalanceV2Actuator`) but is missing from the smart-contract-triggered native path (`FreezeBalanceV2Processor`), which is reachable by any account issuing a `freezeBalanceV2` call from a deployed contract.

### Finding Description
`FreezeBalanceV2Actuator.validate` explicitly checks the feature flag before allowing a `FreezeBalanceV2Contract` transaction to proceed: [1](#0-0) 

However, `FreezeBalanceV2Processor.validate`, which is invoked from the TVM when a smart contract calls the `freezeBalanceV2` opcode/precompile via `Program`, performs address/account/amount/resource-type validation but never checks `dynamicStore.supportUnfreezeDelay()`: [2](#0-1) 

This is the same bug class as the reported issue: a gating flag ("market pause" analog here is the `supportUnfreezeDelay`/FreezeV2-activation flag) is correctly enforced on one entry point (the ordinary actuator/transaction path, analogous to `Market.newRental`) but omitted on a second entry point that reaches the same state-mutating logic (the TVM native-contract path, analogous to `Market.updateTimeHeldLimit`/`exit`/`collectRentAllCards` bypassing `Treasury.payRent`'s missing `marketPaused` check).

### Impact Explanation
If the committee has not yet enabled FreezeV2/unfreeze-delay support on the network (`supportUnfreezeDelay() == false`), ordinary users are blocked from creating FreezeV2 freezes via the transaction API, but a smart contract can still invoke the native `freezeBalanceV2` action and successfully mutate frozen-balance/vote/total-weight state through `FreezeBalanceV2Processor.execute`, since `validate` never rejects it. This lets FreezeV2 semantics (and the associated resource/vote accounting) be activated network-wide ahead of the committee's intended rollout schedule, undermining the feature-flag/committee-governance guarantee and potentially causing resource-weight/vote accounting to diverge from the intended activation state across nodes.

### Likelihood Explanation
Reachable by any unprivileged account that deploys a contract using the TVM's native freeze precompile — no special privilege is required, and the flag omission is a straightforward code-review-verifiable gap (present in one validate path, absent in the sibling path).

### Recommendation
Add the same `supportUnfreezeDelay()` check to `FreezeBalanceV2Processor.validate` (and audit `UnfreezeBalanceV2Processor.validate` for the same omission) so both the transaction-actuator and TVM native-contract paths enforce identical committee-controlled feature gates before mutating frozen-balance/weight state.

### Proof of Concept
1. On a network where the committee proposal enabling `supportUnfreezeDelay` (FreezeV2) has not been approved, confirm that submitting a `FreezeBalanceV2Contract` transaction directly is rejected with "Not support FreezeV2 transaction, need to be opened by the committee" per `FreezeBalanceV2Actuator.validate` [1](#0-0) .
2. Deploy a contract that invokes the TVM `freezeBalanceV2` native action (via `Program`), which routes to `FreezeBalanceV2Processor.validate`/`execute` — observe that the call succeeds because no equivalent flag check exists there [2](#0-1) , demonstrating the bypass of the intended feature gate.

  public void validate(FreezeBalanceV2Param param, Repository repo) throws ContractValidateException {
    if (repo == null) {
      throw new ContractValidateException(STORE_NOT_EXIST);
    }

    byte[] ownerAddress = param.getOwnerAddress();
    if (!DecodeUtil.addressValid(ownerAddress)) {
      throw new ContractValidateException("Invalid address");
    }
    AccountCapsule ownerCapsule = repo.getAccount(ownerAddress);
    if (ownerCapsule == null) {
      String readableOwnerAddress = StringUtil.createReadableString(ownerAddress);
      throw new ContractValidateException(
          ACCOUNT_EXCEPTION_STR + readableOwnerAddress + "] does not exist");
    }
    long frozenBalance = param.getFrozenBalance();
    if (frozenBalance <= 0) {
      throw new ContractValidateException("FrozenBalance must be positive");
    } else if (frozenBalance < TRX_PRECISION) {
      throw new ContractValidateException("FrozenBalance must be greater than or equal to 1 TRX");
    } else if (frozenBalance > ownerCapsule.getBalance()) {
      throw new ContractValidateException(
          "FrozenBalance must be less than or equal to accountBalance");
    }

    // validate arg @resourceType
    switch (param.getResourceType()) {
      case BANDWIDTH:
      case ENERGY:
        break;
      case TRON_POWER:
        if (!repo.getDynamicPropertiesStore().supportAllowNewResourceModel()) {
          throw new ContractValidateException(
              "Unknown ResourceCode, valid ResourceCode[BANDWIDTH、ENERGY]");
        }
        break;
      default:
        if (repo.getDynamicPropertiesStore().supportAllowNewResourceModel()) {
          throw new ContractValidateException(
              "Unknown ResourceCode, valid ResourceCode[BANDWIDTH、ENERGY、TRON_POWER]");
        } else {
          throw new ContractValidateException(
              "Unknown ResourceCode, valid ResourceCode[BANDWIDTH、ENERGY]");
        }
    }

    if (repo.isSelfDestructed(ownerAddress)) {
      MUtil.checkCPUTimeForFreezeV2AfterSelfDestruct();
    }
  }
