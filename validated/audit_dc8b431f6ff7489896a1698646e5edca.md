### Title
Per-connection unstaked stream throttle cap is not scaled by connection count, letting unstaked TPS budget be multiplied by connection count - (File: streamer/src/nonblocking/stream_throttle.rs)

### Summary
`StakedStreamLoadEMA::available_load_capacity_in_throttling_duration` returns a fixed `max_unstaked_load_in_throttling_window` (derived from a global `MAX_UNSTAKED_TPS` constant) as the `max_streams_per_throttling_interval` passed into `throttle_stream` for *every* unstaked connection independently, via each connection's own `ConnectionStreamCounter` and `last_throttling_instant`. [1](#0-0)  Because the cap is not divided by the number of concurrently open unstaked connections, an attacker opening many unstaked connections up to `max_unstaked_connections` can have each connection independently hit the same 20-streams/100ms cap, so aggregate accepted stream throughput scales roughly linearly with connection count rather than being bounded by a single shared unstaked budget.

### Finding Description
The throttling window per unstaked connection is computed once as a global constant: [2](#0-1) 
`max_unstaked_load_in_throttling_window = MAX_UNSTAKED_TPS * STREAM_THROTTLING_INTERVAL_MS / 1000` = `200 * 100 / 1000 = 20` streams per 100ms. [3](#0-2) 

This single number is returned unconditionally for `ConnectionPeerType::Unstaked` from `available_load_capacity_in_throttling_duration`, regardless of how many unstaked connections currently exist: [1](#0-0) 

`SwQos::max_streams_per_throttling_interval` calls this per-connection function and passes the result into `throttle_stream` on `on_new_stream`, using the connection's *own* `ConnectionStreamCounter` (with its own `last_throttling_instant` and `stream_count`): [4](#0-3) [5](#0-4) 

`throttle_stream` and `reset_throttling_params_if_needed` operate entirely on this per-connection state — there is no shared/global counter across unstaked connections that would cap aggregate throughput: [6](#0-5) 

Because `last_throttling_instant` and `stream_count` live in each connection's own `ConnectionStreamCounter` (created per-connection when added to the unstaked connection table), each connection resets and refills its own 20-stream budget every 100ms independently of all other connections. The only cross-connection limit is `max_unstaked_connections`, which bounds connection *count*, not aggregate stream rate. Thus if `N` unstaked connections are open simultaneously (up to `max_unstaked_connections`), the achievable aggregate throughput is `N * 20 streams / 100ms`, not the single `MAX_UNSTAKED_TPS` (200 TPS) implied by the constant's name/comment ("Max TPS allowed for unstaked connection" — but in practice enforced per connection, not per cluster/IP/aggregate).

### Impact Explanation
This allows an unstaked, unprivileged attacker to multiply the effective unstaked ingress budget by the number of connections it can open (bounded by `max_unstaked_connections`), producing an aggregate stream/packet ingress rate far above what the constant name suggests was intended as a cluster-wide unstaked cap. This falls under QoS/rate-limit evasion leading to unbounded-relative-to-intent packet ingress pressure on downstream sigverify/banking stages, consistent with a "QoS evasion" bounty category.

### Likelihood Explanation
Feasible with no privileges: the attacker only needs to open up to `max_unstaked_connections` unstaked QUIC connections to the TPU port and drive uni-directional streams on each right after the 100ms interval boundary, repeating every `STREAM_THROTTLING_INTERVAL`. No staking, gossip, or config access is required — this is directly reachable from the public unstaked ingress path (`SwQos::try_add_connection` → `on_new_stream` → `throttle_stream`). [7](#0-6) 

### Recommendation
Enforce unstaked throughput with a shared, connection-count-aware budget rather than a fixed per-connection window: e.g., divide `max_unstaked_load_in_throttling_window` by the current number of active unstaked connections, or maintain a single global/per-IP `AtomicU64` counter (and shared `last_throttling_instant`) that all unstaked connections decrement against inside `throttle_stream`, so the aggregate unstaked stream rate is bounded by `MAX_UNSTAKED_TPS` regardless of connection count.

### Proof of Concept
Integration test plan (in `streamer/src/nonblocking/stream_throttle.rs` test module or a new integration test):
1. Construct `StakedStreamLoadEMA` with `DEFAULT_MAX_UNSTAKED_CONNECTIONS` and default streams/ms as in existing `test_max_streams_for_unstaked_connection`.
2. Instantiate `N` independent `ConnectionStreamCounter`s (simulating `N` unstaked connections).
3. For each of the `N` counters, spawn a task that calls `throttle_stream` in a loop right after `reset_throttling_params_if_needed()` resets (i.e., synchronized at `STREAM_THROTTLING_INTERVAL` boundaries), incrementing `stream_count` up to `max_streams_per_throttling_interval` (20) before sleeping.
4. Measure aggregate accepted streams across all `N` tasks over several throttling intervals.
5. Assert: aggregate accepted-streams/sec ≈ `N * 20 / 0.1s`, i.e., far exceeds `MAX_UNSTAKED_TPS` (200) once `N > 1`, demonstrating the cap is per-connection, not cluster/global-wide as intended.

    pub(crate) fn available_load_capacity_in_throttling_duration(
        &self,
        peer_type: ConnectionPeerType,
        total_stake: u64,
    ) -> u64 {
        match peer_type {
            ConnectionPeerType::Unstaked => self.max_unstaked_load_in_throttling_window,
            ConnectionPeerType::Staked(stake) => {
                if self.staked_throttling_enabled.load(Ordering::Relaxed) {
                    // 1 is added to `max_unstaked_load_in_throttling_window` to guarantee that staked
                    // clients get at least 1 more number of streams than unstaked connections.
                    self.max_staked_load_in_throttling_window
                        .saturating_mul(stake)
                        .checked_div(total_stake)
                        .unwrap_or(self.max_unstaked_load_in_throttling_window + 1)
                        .max(self.max_unstaked_load_in_throttling_window + 1)
                } else {
                    self.max_staked_load_in_throttling_window
                }
            }
        }
    }

impl ConnectionStreamCounter {
    pub fn new() -> Self {
        Self {
            stream_count: AtomicU64::default(),
            last_throttling_instant: RwLock::new(tokio::time::Instant::now()),
        }
    }

    /// Reset the counter and last throttling instant and
    /// return last_throttling_instant regardless it is reset or not.
    pub(crate) fn reset_throttling_params_if_needed(&self) -> tokio::time::Instant {
        let last_throttling_instant = *self.last_throttling_instant.read().unwrap();
        if tokio::time::Instant::now().duration_since(last_throttling_instant)
            > STREAM_THROTTLING_INTERVAL
        {
            let mut last_throttling_instant = self.last_throttling_instant.write().unwrap();
            // Recheck as some other thread might have done throttling since this thread tried to acquire the write lock.
            if tokio::time::Instant::now().duration_since(*last_throttling_instant)
                > STREAM_THROTTLING_INTERVAL
            {
                *last_throttling_instant = tokio::time::Instant::now();
                self.stream_count.store(0, Ordering::Relaxed);
            }
            *last_throttling_instant
        } else {
            last_throttling_instant
        }
    }
}

pub(crate) async fn throttle_stream(
    stats: &StreamerStats,
    peer_type: ConnectionPeerType,
    remote_addr: std::net::SocketAddr,
    stream_counter: &Arc<ConnectionStreamCounter>,
    max_streams_per_throttling_interval: u64,
) {
    let throttle_interval_start = stream_counter.reset_throttling_params_if_needed();
    let streams_read_in_throttle_interval = stream_counter.stream_count.load(Ordering::Relaxed);
    if streams_read_in_throttle_interval >= max_streams_per_throttling_interval {
        // The peer is sending faster than we're willing to read. Sleep for what's
        // left of this read interval so the peer backs off.
        let throttle_duration =
            STREAM_THROTTLING_INTERVAL.saturating_sub(throttle_interval_start.elapsed());

        if !throttle_duration.is_zero() {
            debug!(
                "Throttling stream from {remote_addr:?}, peer type: {peer_type:?}, \
                 max_streams_per_interval: {max_streams_per_throttling_interval}, \
                 read_interval_streams: {streams_read_in_throttle_interval} throttle_duration: \
                 {throttle_duration:?}"
            );
            stats.throttled_streams.fetch_add(1, Ordering::Relaxed);
            match peer_type {
                ConnectionPeerType::Unstaked => {
                    stats
                        .throttled_unstaked_streams
                        .fetch_add(1, Ordering::Relaxed);
                }
                ConnectionPeerType::Staked(_) => {
                    stats
                        .throttled_staked_streams
                        .fetch_add(1, Ordering::Relaxed);
                }
            }
            sleep(throttle_duration).await;
        }
    }
}
