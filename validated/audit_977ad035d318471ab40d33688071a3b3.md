Based on my investigation, this is a real, exploitable resource-exhaustion path.

### Title
Unstaked client can starve the global QUIC connection-tracker capacity via idle established connections - (File: streamer/src/nonblocking/quic.rs)

### Summary
`ClientConnectionTracker::new` enforces a global cap (`qos.max_concurrent_connections()`) on `stats.open_connections` before any per-connection stream activity occurs, and this slot is only released when the underlying `ConnectionEntry`/`Connection` is dropped. Because the server relies solely on QUIC's transport-level idle timeout (`QUIC_MAX_TIMEOUT` = 30s) rather than an application-level "must open a stream" timeout, an attacker can hold connections open indefinitely (via PING keep-alives) or cycle them just under 30s, occupying tracker slots without ever sending a stream, and starve legitimate senders with `refused_connections_too_many_open_connections`.

### Finding Description
In `streamer/src/nonblocking/quic.rs::run_server`, after passing the overall/per-IP rate limiters, the server calls:
```rust

    ClientConnectionTracker::new(stats.clone(), qos.max_concurrent_connections())
else {
    stats.refused_connections_too_many_open_connections.fetch_add(1, Ordering::Relaxed);
    incoming.refuse();
    continue;
};
``` [1](#0-0) 

`ClientConnectionTracker::new` increments `stats.open_connections` and only fails once `open_connections >= max_concurrent_connections`; it is decremented solely on `Drop`: [2](#0-1) 

The tracker is stored in `ConnectionEntry` as `_client_connection_tracker`, dropped only when the entry is removed from the connection table (via `remove_connection`, pruning, or connection close): [3](#0-2) 

After the handshake completes (`setup_connection`) and passes `try_add_connection`, `handle_connection` enters a loop waiting on `connection.accept_uni()` with no timeout — it only exits on a stream arriving, connection error, or task cancellation: [4](#0-3) 

There is no "must open a stream within N seconds" enforcement anywhere in this path; the *only* backstop is the QUIC transport idle timeout configured server-side as `QUIC_MAX_TIMEOUT = Duration::from_secs(30)`: [5](#0-4) [6](#0-5) 

Because idle timeout in QUIC is a network-activity-based transport timer (reset by any packet including PING frames), a fully attacker-controlled client can suppress the timeout indefinitely by sending periodic pings while never opening a stream — this is legitimate QUIC protocol behavior, not blocked by any check in `handle_connection` or `setup_connection`. Even absent that, an attacker can simply reconnect just under 30s repeatedly ("churn") to keep occupying slots continuously, as the question's preconditions state. Since the global tracker check in `ClientConnectionTracker::new` happens *before* the QoS-specific per-table logic (`try_add_connection`, pruning via `prune_random`/`prune_oldest` in `swqos.rs`/`simple_qos.rs`), those table-level pruning defenses never get a chance to intervene — a legitimate connection is refused immediately with `refused_connections_too_many_open_connections` once the global counter is saturated, regardless of per-IP/per-pubkey table state.

### Impact Explanation
This starves the shared, global connection-tracker capacity (`qos.max_concurrent_connections()`), causing legitimate unstaked and even staked senders' new connection attempts to be refused (`refused_connections_too_many_open_connections`), denying TPU access. This matches the Agave bounty category of QoS evasion / unfair resource starvation of shared capacity independent of packet or stream volume — the attacker consumes tracker slots using zero application-level bandwidth.

### Likelihood Explanation
Feasible for a fully unprivileged, unstaked attacker: it only requires completing QUIC handshakes (which the per-IP `ConnectionRateLimiter` and overall `TokenBucket` already gate, but an attacker with many source IPs or patient churn can accumulate up to the global cap over time), and then either sending keep-alive PINGs (standard QUIC client behavior, not attacker-specific) or reconnecting just under the 30-second idle window. No stake, no key material, no special server config is required — only sustained IP diversity or slow churn under existing per-IP/global connection-rate limits, exactly as described in the question's preconditions.

### Recommendation
Add an application-level "time-to-first-stream" timeout in `handle_connection` (e.g., wrap the first `connection.accept_uni()` iteration in a `tokio::time::timeout` shorter than `QUIC_MAX_TIMEOUT`, closing the connection if no stream arrives) so idle connections that never send data release their `ClientConnectionTracker` slot promptly. Additionally, consider making the global `max_concurrent_connections` check itself subject to eviction/pruning (e.g., preferentially evict oldest/no-stream connections) rather than a hard refuse, so genuine QoS-based prioritization (stake, recency) also applies at the global tracker level, not just within per-IP/per-pubkey tables.

### Proof of Concept
Integration test plan (Rust, `tokio::test`, using existing `setup_quic_server`/`make_client_endpoint` helpers from `streamer/src/nonblocking/quic.rs` tests):
```rust
#[tokio::test(flavor = "multi_thread")]
async fn test_idle_connections_exhaust_global_tracker() {
    // Configure a small max_concurrent_connections (e.g. via qos config)
    let SpawnTestServerResult { server_address, stats, cancel, .. } =
        setup_quic_server(None, QuicStreamerConfig::default_for_tests(), SwQosConfig {
            /* set max_unstaked/staked connections small, e.g. total = N */
            ..Default::default()
        });

    // Open N idle connections from distinct source ports/addresses, never open a stream
    let mut conns = vec![];
    for _ in 0..N {
        let conn = make_client_endpoint(&server_address, None).await;
        conns.push(conn); // hold, do not open_uni()
    }

    // A subsequent legitimate connection attempt should be refused
    let extra = make_client_endpoint(&server_address, None).await;
    // Assert extra connection is refused / closed immediately
    assert_ne!(stats.refused_connections_too_many_open_connections.load(Ordering::Relaxed), 0);

    // Wait past QUIC_MAX_TIMEOUT (30s) for idle connections to be reaped
    tokio::time::sleep(QUIC_MAX_TIMEOUT + Duration::from_secs(1)).await;

    // Now a new legitimate connection should succeed
    let recovered = make_client_endpoint(&server_address, None).await;
    // assert success, e.g. can open_uni() and send data
    cancel.cancel();
}
```
Expected assertions: `refused_connections_too_many_open_connections` increments while idle connections occupy all `max_concurrent_connections` slots; capacity is only restored after `QUIC_MAX_TIMEOUT` elapses (or sooner only if a stream-open timeout were added per the recommendation, which currently does not exist).

    /// create ClientConnectionTracker and increment open connection count. Otherwise returns Err
    fn new(stats: Arc<StreamerStats>, max_concurrent_connections: usize) -> Result<Self, ()> {
        let open_connections = stats.open_connections.fetch_add(1, Ordering::Relaxed);
        if open_connections >= max_concurrent_connections {
            stats.open_connections.fetch_sub(1, Ordering::Relaxed);
            debug!(
                "There are too many concurrent connections opened already: open: \

            );
            return Err(());
        }

        Ok(Self { stats })

impl<S: OpaqueStreamerCounter> ConnectionEntry<S> {
    fn new(
        cancel: CancellationToken,
        peer_type: ConnectionPeerType,
        last_update: Arc<AtomicU64>,
        port: u16,
        client_connection_tracker: ClientConnectionTracker,
        connection: Option<Connection>,
        stream_counter: Arc<S>,
    ) -> Self {
        Self {
            cancel,
            peer_type,
            last_update,
            port,
            _client_connection_tracker: client_connection_tracker,
            connection,
            stream_counter,
        }
    }

    fn last_update(&self) -> u64 {
        self.last_update.load(Ordering::Relaxed)
    }

    fn stake(&self) -> u64 {
        match self.peer_type {
            ConnectionPeerType::Unstaked => 0,
            ConnectionPeerType::Staked(stake) => stake,
        }
    }
}

impl<S: OpaqueStreamerCounter> Drop for ConnectionEntry<S> {
    fn drop(&mut self) {

                CONNECTION_CLOSE_CODE_DROPPED_ENTRY.into(),
                CONNECTION_CLOSE_REASON_DROPPED_ENTRY,
            );
        }
        self.cancel.cancel();
    }
}
