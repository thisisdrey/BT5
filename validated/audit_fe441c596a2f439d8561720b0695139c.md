**Reasoning summary:**

The premise conflates two unrelated mechanisms that do not actually interact the way the question describes. In this codebase:

1. `g1_multiexp` in `runtime/near-vm-runner/src/logic/alt_bn128.rs` is a pure cryptographic helper with no gas accounting of its own; gas is charged exactly once via the VM logic's host-function cost accounting (base + per-element cost), which is the single metering point regardless of caller. [1](#0-0) 

2. The NEAR Wallet Contract (`runtime/near-wallet-contract`) is an ordinary WASM smart contract used for eth-implicit accounts; it does not implement any separate "gas reservation for meta-tx verification" that competes with the runtime's gas metering. Its only gas-related logic is a simple comparison check — it verifies that the transaction's attached prepaid gas is sufficient to cover the user-requested Ethereum gas limit, but it does not itself deduct or reserve gas twice: [2](#0-1) 

3. Protocol-level meta-transactions (`DelegateAction`/`DelegateV2`) are handled natively in `runtime/runtime/src/actions.rs::apply_delegate_action`, which computes prepaid send fees and required cost for the spawned receipt exactly once, incrementing `gas_used`/`gas_burnt` a single time for those fees: [3](#0-2) 

4. When a contract like the Wallet Contract forwards an inner `FunctionCall` action (e.g., to invoke `alt_bn128_g1_multiexp`), that becomes a distinct receipt with its own independently allocated prepaid gas from the total transaction gas — this is normal NEAR receipt composition, not "double deduction" of the same cost. The existing meta-tx test (`test-loop-tests/src/tests/meta_tx.rs`) demonstrates the relayer pays gas exactly once end-to-end. [4](#0-3) 

There is no code path in which `alt_bn128_g1_multiexp`'s gas cost is subtracted twice from prepaid gas by both the wallet contract and the "outer runtime" — no such dual-accounting mechanism exists. The scenario as described is not supported by any reachable code path in this repository.

pub(crate) fn g1_multiexp(
    elements: &[[u8; G1_MULTIEXP_ELEMENT_SIZE]],
) -> Result<[u8; POINT_SIZE], InvalidInput> {
    let elements: Vec<(bn::G1, bn::Fr)> = elements
        .iter()
        .map(|chunk| {
            let (g1, fr) = stdx::split_array(chunk);
            let g1 = decode_g1(g1)?;
            let fr = decode_fr(fr)?;
            Ok((g1, fr))
        })
        .collect::<Result<Vec<_>, InvalidInput>>()?;

    let res = bn::G1::multiexp(&elements);

    Ok(encode_g1(res))
}
