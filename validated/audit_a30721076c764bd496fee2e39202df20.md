### Title
Protocol fee bypass on NEP-245/IMT `TokenDiff` intents via single-unit delta decomposition - (`contracts/defuse/core/src/intents/token_diff.rs`)

### Summary
`TokenDiff::token_fee` waives the protocol fee for `Nep245`/`Imt` token ids whenever the per-leg `amount <= 1`. Because fees are computed independently for each `TokenDiff` intent (and each intent's `diff` map holds one delta per token id), an unprivileged signer can decompose one large NEP-245 token_in amount into `N` separate `TokenDiff` intents (or `N` distinct token ids) each carrying `delta.unsigned_abs() == 1`, driving every leg's fee to `Pips::ZERO` while the economically equivalent single-delta trade would have paid `protocol_fee.fee_ceil(N)`.

### Finding Description
The broken binding: for a signer moving a total NEP-245/IMT `token_in` quantity `N` (`N > 1`) at `protocol_fee = Pips::P > 0`,

`Σ_{i=1..N} TokenDiff::token_fee(token_id_i, 1, P).fee_ceil(1)` should equal `P.fee_ceil(N)` (the fee that would be collected if the same aggregate outflow were expressed as one delta), but it does not.

Code path:
- `TokenDiff::execute_intent` (`contracts/defuse/core/src/intents/token_diff.rs:41-104`) iterates `self.diff` (a `BTreeMap<TokenId, i128>` for *that single intent only*) and, for each negative delta, computes `let fee = Self::token_fee(token_id, amount, protocol_fee).fee_ceil(amount);` at line 72, where `amount = delta.unsigned_abs()`.
- `TokenDiff::token_fee` (`contracts/defuse/core/src/intents/token_diff.rs:206-216`) returns `Pips::ZERO` for `TokenIdType::Nep245 | TokenIdType::Imt` whenever `amount <= 1`, only applying the real `fee` when `amount > 1`.
- A signed payload's intent list is a plain `Vec<Intent>` (`DefuseIntents::intents`, `contracts/defuse/core/src/intents/mod.rs:30-37`), executed sequentially by `DefuseIntents::execute_intent` (`contracts/defuse/core/src/intents/mod.rs:97-113`) with **no aggregation across intents**. Each `TokenDiff` in that list gets its own fresh `fees_collected` computed strictly from its own `diff` map (lines 56-79).

Exploit: the signer holds an NEP-245 balance of `N` units (either as `N` units of one token id split via `N` prior mint/transfer legs, or as `N` distinct token ids each holding balance 1) inside the Verifier. Instead of signing one `TokenDiff` with `{token_id: -N, out_token: +Z}` (which would trigger `token_fee` returning `protocol_fee` since `amount = N > 1`, costing `protocol_fee.fee_ceil(N)`), the signer packs `N` `TokenDiff` intents into a single `DefuseIntents` payload (one nonce, one signature), each `{token_id_i: -1, out_token: +z_i}` with `Σ z_i = Z`. Every leg computes `amount = 1`, so `token_fee` returns `Pips::ZERO` and `fee_ceil(1) = 0` for all `N` legs. The aggregate token_in delta and token_out delta across the batch match the single-intent case exactly (same net balance change for the signer and the same amount owed to any counter-party liquidity providing `Z`), but `fees_collected` credited to `engine.state.fee_collector()` via `internal_add_balance` (lines 96-101) is `0` instead of `protocol_fee.fee_ceil(N)`.

No existing guard prevents this: `MultiPayload::verify`/nonce checks only ensure the payload is validly signed and not replayed, they do not constrain the granularity of intents in `DefuseIntents.intents`; the invariant check (`TransferMatcher`/`closure_deltas`) only verifies that deltas net to zero across the whole batch, not that fees were computed on the aggregate amount. The `amount > 1` guard in `token_fee` is explicitly designed to exempt genuine single-unit NFT/MT transfers from fees, but it is evaluated per-`TokenDiff`-intent, not per aggregate token_in movement, so it can be trivially defeated by decomposition.

### Impact Explanation
The `fee_collector`'s expected revenue on NEP-245/IMT `token_in` legs is under-collected: any signer trading `N` units of a NEP-245/IMT token can reduce their fee from `protocol_fee.fee_ceil(N)` to `0` simply by splitting the trade into `N` single-unit `TokenDiff` intents within one signed payload. This is repeatable by any account, on any NEP-245/IMT token id, for any batch size `N`, and scales linearly with the value diverted from `fee_collector`. This matches the "protocol fees bypassed" Critical impact category since value that should have been credited to `fee_collector` is instead retained by the signer.

### Likelihood Explanation
No special privileges are required — only an unprivileged signer with an NEP-245/IMT balance inside the Verifier and `engine.state.fee() > Pips::ZERO`. Constructing `N` single-delta `TokenDiff` intents inside one `DefuseIntents.intents` array under a single signature/nonce is straightforward client-side JSON/payload construction, no extra gas-limited loop beyond normal intent execution costs, and is fully repeatable across accounts/tokens/batches.

### Recommendation
Compute the NEP-245/IMT fee exemption based on the aggregate negative delta per token id (or per underlying MT contract) across the entire `DefuseIntents`/batch being executed, not per individual `TokenDiff` intent's own `diff` map. Alternatively, remove or tighten the `amount <= 1` exemption so it only applies to token ids whose supply is inherently 1-of-a-kind (true NFTs), and always charge `protocol_fee` on `Nep245`/`Imt` deltas regardless of leg size when the same signer's cumulative token_in for that token id across the batch exceeds 1.

### Proof of Concept
`near-workspaces` sandbox test (extending `tests/src/tests/defuse/intents/token_diff.rs`):
1. Set `Env::builder().fee(Pips::ONE_PERCENT)` (or any `Pips > 0`).
2. Deploy an NEP-245-compatible MT source (e.g. via `mt_transfer_call` into the Verifier, as in `simulate_mt_withdraw_intent`) so `user1` holds `N = 10` units of a single NEP-245 `token_id` (or 10 distinct NEP-245 token ids each with balance 1) plus a counter-liquidity account providing the matched `out_token`.
3. **Baseline**: sign and execute ONE `TokenDiff` `{token_id: -10, out_token: +Z}` (paired with a counter-order); read `fee_collector`'s `out_token`/`token_id` balance delta — assert it equals `Pips::ONE_PERCENT.fee_ceil(10)`.
4. **Exploit**: reset state; sign and execute ONE `DefuseIntents` payload containing 10 separate `TokenDiff` intents `{token_id: -1, out_token: +z_i}` (paired with matching counter-order legs summing to the same `Z`); read `fee_collector`'s balance delta — assert it equals `0`.
5. Assert the two `fee_collector` balances differ (`baseline_fee > 0`, `split_fee == 0`) despite identical aggregate signer balance changes, proving the fee bypass.
