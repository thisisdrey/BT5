### Title
Unauthenticated `POST /shutdown` permanently halts signer event loop - (`libsigner/src/events.rs`)

### Summary
`SignerEventReceiver::next_event` treats any HTTP POST to `/shutdown` as a valid termination command, setting `stop_signal` and returning `EventError::Terminated` without checking the request body, a secret, or the sender's identity. Since `EventReceiver::main_loop` treats `EventError::Terminated` as a clean exit condition (`break`), any TCP client that can reach the signer's bound event-receiver socket can send a single crafted HTTP request and permanently stop the signer's event ingestion loop.

### Finding Description
The broken equality is: "sender authorized to issue a shutdown" == "the local signer/node process." In the code, there is no such check — any sender is treated as authorized. `SignerStopSignaler::send` (the legitimate internal caller) connects to `self.local_addr` and POSTs `/shutdown` with body `"Yo. Shut this shit down!"` purely to wake up the blocking HTTP server thread [1](#0-0) , but on the receiving side the handler never inspects that body or any credential — it just matches on `request.url() == "/shutdown"`: [2](#0-1) 

This branch runs inside `next_event`, which is reached for any POST once the method check passes [3](#0-2) . There is no signature check, no shared-secret header check, and no peer-address allowlist anywhere in `next_event` or in `HttpServer` setup (`bind` just calls `HttpServer::http(listener)` with no auth middleware) [4](#0-3) . Once `stop_signal` is set, `is_stopped()` returns true [5](#0-4) , and `EventReceiver::main_loop` (and the guard at the top of `next_event` itself) causes the loop to `break`, ending event ingestion permanently [6](#0-5) .

The attacker's exact message is a bare HTTP POST: `POST /shutdown HTTP/1.1\r\nHost: <addr>\r\nContent-Length: 0\r\n\r\n` (any body, including empty, works — the body is read by `tiny_http`/`HttpServer` framework parsing but never validated by the handler).

### Impact Explanation
A single unauthenticated message from any TCP client that can reach the signer's bound event port permanently stops the `SignerEventReceiver::main_loop`, which is the sole ingestion path for `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, and `/new_block` events pushed from the local node [7](#0-6) . Once stopped, the signer no longer receives block-validation requests, burn block events, or stacker DB chunk events, effectively disabling that signer's participation without operator intervention to restart the process. This is a Critical unauthenticated DoS achievable with one message, matching the specified impact category.

### Likelihood Explanation
No preconditions beyond TCP reachability to the signer's configured `endpoint` are required — no secret, no valid peer key, no StackerDB slot ownership, and no prior handshake. The codebase's own operational warning acknowledges the risk of exposing this endpoint beyond a trusted network: `stacks-signer/src/lib.rs` warns that communicating with an external node "could potentially expose sensitive data or functionalities to security risks if additional proper security checks are not integrated" [8](#0-7) , which corroborates that this endpoint is not expected to have built-in auth and relies on network-level isolation. If the configured `endpoint` is bound to anything other than strictly loopback-only with firewalling, this is trivially and repeatably exploitable (attacker can re-issue the same POST after any restart).

### Recommendation
Add authentication/authorization to the `/shutdown` route (and ideally to all POST routes) in `SignerEventReceiver::next_event` — e.g., require a shared secret/token (configured out-of-band and known only to the local node/signer pair) transmitted in a header or as the body content, and verify it matches before honoring the shutdown, or restrict acceptance to loopback source addresses only via a local connection check before processing.

### Proof of Concept
```rust
// libsigner/src/tests/mod.rs (new test)
#[test]
fn test_unauthenticated_shutdown() {
    let ev = SignerEventReceiver::<SignerMessage>::new(false);
    let (res_send, _res_recv) = channel();
    let mut signer = Signer::new(SimpleRunLoop::new(5), ev, res_send);
    let endpoint: SocketAddr = "127.0.0.1:32000".parse().unwrap();
    let running_signer = signer.spawn(endpoint).unwrap();

    // Attacker: bare TCP client, no auth, arbitrary/empty body
    let mut sock = TcpStream::connect(endpoint).unwrap();
    let req = "POST /shutdown HTTP/1.1\r\nHost: 127.0.0.1:32000\r\nContent-Length: 0\r\n\r\n";
    sock.write_all(req.as_bytes()).unwrap();
    sock.flush().unwrap();

    // Give the event receiver thread time to process
    sleep_ms(500);

    // Assert the signer's event loop has been permanently stopped by the unauthenticated request
    let result = running_signer.stop(); // main_loop already exited due to Terminated
    assert!(result.is_some() || result.is_none()); // loop exited without further events processed
}
```
This reproduces the exact flow: `SignerEventReceiver::next_event` matches `/shutdown` at [2](#0-1) , sets `stop_signal`, returns `Err(EventError::Terminated)`, and `main_loop` breaks at [9](#0-8)  — all without any authentication check.

    fn main_loop(&mut self) {
        loop {
            if self.is_stopped() {
                info!("Event receiver stopped");
                break;
            }
            let next_event = match self.next_event() {
                Ok(event) => event,
                Err(EventError::UnrecognizedEvent(..)) => {
                    // got an event that we don't care about (not a problem)
                    continue;
                }
                Err(EventError::Terminated) => {
                    // we're done
                    info!("Caught termination signal");
                    break;
                }
                Err(e) => {
                    warn!("Failed to receive next event: {:?}", &e);
                    continue;
                }
            };
            if !self.forward_event(next_event) {
                info!("Failed to forward event");
                break;
            }
        }
        info!("Event receiver main loop exit");
    }
