### Title
Silent APT Loss in `delegation_pool::add_stake` When `buy_in_active_shares` Returns Zero Shares — (`File: aptos-move/framework/aptos-framework/sources/delegation_pool.move`)

---

### Summary

In `delegation_pool::add_stake`, APT is transferred from the delegator to the pool and staked **before** shares are allocated. When the deposited amount is smaller than the current share price (causing `amount_to_shares` to round down to zero), `buy_in_active_shares` silently returns 0 without crediting any shares. For an existing delegator whose prior balance already satisfies `assert_min_active_balance`, the transaction succeeds and the deposited APT is permanently lost — redistributed as phantom "rewards" to all other shareholders at the next synchronization.

---

### Finding Description

`add_stake` executes in this order:

```
// 1. Coins leave the delegator unconditionally
aptos_account::transfer(delegator, pool_address, amount);          // line 1500
stake::add_stake(&retrieve_stake_pool_owner(pool), amount);        // line 1501

// 2. Shares are allocated — but may silently return 0
buy_in_active_shares(pool, delegator_address, amount - add_stake_fee); // line 1504

// 3. Guard only checks existing balance, not whether new shares were issued
assert_min_active_balance(pool, delegator_address);                // line 1505
``` [1](#0-0) 

Inside `buy_in_active_shares`:

```move
let new_shares = pool.active_shares.amount_to_shares(coins_amount);
// No need to buy 0 shares.
if (new_shares == 0) { return 0 };          // early exit — buy_in never called
...
pool.active_shares.buy_in(shareholder, coins_amount);
``` [2](#0-1) 

`amount_to_shares` (from `pool_u64_unbound`) computes:

```
coins_amount * total_shares / total_coins   (integer division, rounds down)
``` [3](#0-2) 

This returns 0 whenever `coins_amount < total_coins / total_shares` (i.e., the deposited amount is less than the current share price). When that happens, `buy_in` is never called, so:

- The pool_u64's `total_coins` is **not** updated.
- The actual staked APT **does** increase (via `stake::add_stake`).
- At the next `synchronize_delegation_pool`, the discrepancy is treated as rewards and distributed to all shareholders.

`assert_min_active_balance` only checks whether the delegator's **existing** balance meets the minimum:

```move
fun assert_min_active_balance(pool: &DelegationPool, delegator_address: address) {
    let balance = pool.active_shares.balance(delegator_address);
    assert!(balance >= MIN_COINS_ON_SHARES_POOL, ...);
}
``` [4](#0-3) 

For a **new** delegator (zero existing shares), this check fails → transaction aborts → coin transfer reverts → no loss. For an **existing** delegator whose prior balance already satisfies the minimum, the check passes, the transaction commits, and the deposited APT is gone.

---

### Impact Explanation

An existing delegator permanently loses APT equal to the amount they deposited (up to `total_coins / total_shares` − 1 octas per call). The lost coins are silently redistributed as rewards to all other shareholders. This constitutes direct, unprivileged theft of staking balances from user-controlled on-chain assets.

The corrupted value is: `delegator's APT balance` decreases by `amount`; `delegator's share count` is unchanged; `pool's actual staked coins` increases by `amount` without a corresponding pool_u64 accounting entry.

---

### Likelihood Explanation

**Conditions required:**

1. The delegator must already hold shares worth ≥ `MIN_COINS_ON_SHARES_POOL` (so `assert_min_active_balance` passes).
2. The deposited `amount - add_stake_fee` must be less than the current share price (`total_coins / total_shares`).

The share price starts at 1:1 and grows with each epoch of staking rewards (~1% per epoch). After sufficient epochs, the share price exceeds small deposit amounts. An attacker can also accelerate inflation by directly sending APT to the pool address (bypassing `add_stake`), which increases `total_coins` in the underlying stake pool without updating pool_u64 accounting, raising the effective share price at the next synchronization.

The delegation pool uses `pool_u64_unbound` with a default scaling factor of 1. [5](#0-4) [6](#0-5) 

Likelihood is **low-to-medium**: requires an inflated share price and an existing delegator, but both conditions are achievable on a long-running mainnet pool.

---

### Recommendation

1. **Revert if zero shares are issued**: In `buy_in_active_shares`, if `new_shares == 0` and `coins_amount > 0`, abort the transaction rather than silently returning 0. This ensures the coin transfer at line 1500 is also reverted.

2. **Enforce minimum deposit relative to share price**: Before transferring coins, assert that `amount_to_shares(amount - add_stake_fee) > 0`, so the transaction fails early with a clear error before any funds move.

3. **Reorder operations**: Move `aptos_account::transfer` and `stake::add_stake` to occur **after** share allocation is confirmed to be non-zero, so a failed share calculation always reverts the coin transfer.

---

### Proof of Concept

```
Setup:
- Pool has been running for many epochs; share price = S (total_coins / total_shares)
- Delegator D already has shares worth 15 APT (> MIN_COINS_ON_SHARES_POOL = 10 APT)
- Attacker or natural growth has inflated S to, e.g., 100 octas per share

Attack:
1. D calls add_stake(pool_address, 50) with amount = 50 octas
2. Line 1500: 50 octas transferred from D to pool_address ✓
3. Line 1501: 50 octas staked ✓
4. Line 1504: buy_in_active_shares(pool, D, 50)
   → amount_to_shares(50) = 50 * total_shares / total_coins = 0  (rounds down)
   → returns 0 without calling buy_in
5. Line 1505: assert_min_active_balance → D's existing balance = 15 APT ≥ 10 APT → passes
6. Transaction commits. D loses 50 octas. Pool's actual stake increases by 50 octas.
7. Next synchronize_delegation_pool: 50 octas appear as "rewards", distributed to all shareholders.

Result: D's 50 octas are permanently redistributed to other shareholders.
```

The same pattern applies to `reactivate_stake` at line 1601, which also calls `buy_in_active_shares` after coins have already been moved via `stake::reactivate_stake`. [7](#0-6)

    public fun amount_to_shares_with_total_coins(self: &Pool, coins_amount: u64, total_coins: u64): u128 {
        // No shares yet so amount is worth the same number of shares.
        if (self.total_coins == 0 || self.total_shares == 0) {
            // Multiply by scaling factor to minimize rounding errors during internal calculations for buy ins/redeems.
            // This can overflow but scaling factor is expected to be chosen carefully so this would not overflow.
            (coins_amount as u128) * (self.scaling_factor as u128)
        } else {
            // Shares price = total_coins / total existing shares.
            // New number of shares = new_amount / shares_price = new_amount * existing_shares / total_amount.
            // We rearrange the calc and do multiplication first to avoid rounding errors.
            self.multiply_then_divide(coins_amount as u128, self.total_shares, total_coins as u128)
        }
