### Title
Unauthenticated `RecvError` packet allows remote tunnel teardown without a valid certificate - (File: `outside.go`)

### Summary
Nebula's `header.RecvError` control message is processed entirely outside the Noise/AEAD-authenticated packet path. `readOutsidePackets` dispatches `RecvError` packets straight to `handleRecvError` before any decryption, certificate check, or replay-window validation is performed [1](#0-0) . `handleRecvError` only checks a config toggle and a comparison of the claimed source `netip.AddrPort` against the value cached in `hostinfo.GetRemote()`, then unconditionally tears the tunnel down via `f.closeTunnel(hostinfo)` [2](#0-1) . This mirrors the Broker bug class in the external report: one unauthenticated/unverified signal path is able to unilaterally disable an entire established session (the tunnel), with no certificate, no AEAD authentication, and no nonce/replay protection standing between an attacker and the teardown action.

### Finding Description
The `RecvError` message type is handled in the "Unencrypted packets" branch of `readOutsidePackets`, alongside `Handshake`:

```go
switch h.Type {
case header.Handshake:
    f.handshakeManager.HandleIncoming(via, packet, h)
    return

case header.RecvError:
    f.handleRecvError(via.UdpAddr, h)
    return
}
``` [1](#0-0) 

Unlike `header.Message`/`header.LightHouse`/`header.Test`/`header.CloseTunnel`/`header.Control`, which all require `hostinfo.ConnectionState.Decrypt` to succeed (AEAD authentication tied to the peer's certificate-derived keys and protected by the replay window `cs.window.Check`/`Update`) before being acted on [3](#0-2) [4](#0-3) , `RecvError` packets carry no AEAD tag and are 16 bytes of unauthenticated header only. `handleRecvError`'s only gate against forgery is:

```go
hr := hostinfo.GetRemote()
if hr.IsValid() && hr != addr {
    f.l.Info("Someone spoofing recv_errors?", ...)
    return
}
f.closeTunnel(hostinfo)
hm.DeleteHostInfo(hostinfo)
``` [5](#0-4) 

This is a comparison against the UDP source `netip.AddrPort` reported by the kernel for the incoming datagram — it is not a cryptographic proof of identity. UDP source addresses are attacker-controllable for on-path attackers/off-path spoofers, and `RecvError` packets require only knowledge of the victim's currently-assigned `RemoteIndex` (a 32-bit value carried in cleartext on every packet the victim sends/receives) to target a specific `HostInfo` via `f.hostMap.QueryReverseIndex(h.RemoteIndex)`. Both the send and accept sides of this feature default to `"always"` (`recvErrorAlways`), so this path is live in the default configuration [6](#0-5) .

The result: an attacker who can observe (or spoof from) the legitimate remote's `ip:port` and learn a live `RemoteIndex` can forge a `RecvError` packet that forces `f.closeTunnel(hostinfo)` and `hm.DeleteHostInfo(hostinfo)`, tearing down the tunnel — no certificate, no CA-pool verification, no handshake, and no AEAD/replay protection are involved at any point in this control path.

### Impact Explanation
This lets a remote, unauthenticated attacker forcibly disable an existing, fully-authenticated Nebula tunnel between two legitimate peers, exactly analogous to how `GnosisTrade.settle()` could unilaterally flip `Broker.disabled` and deny service to unrelated legitimate flows until manual intervention. Here the "disabling" action is `closeTunnel`/`DeleteHostInfo`, i.e. remote state poisoning of the hostmap/tunnel state, causing repeated denial-of-service against a given host pair with no valid certificate required. It also enables a low-cost DoS amplification vector on the responder host.

### Likelihood Explanation
Requires no CA-signed certificate, no valid handshake, and no participation in the actual tunnel: only the ability to send (or spoof) a UDP packet with the victim's current source `ip:port` and any `RemoteIndex` value the attacker knows or brute-forces (32 bits, but only needs to match one of the target's *sender-assigned* indices, which are observable from any relayed/overheard traffic or by an attacker on the network path). This is reachable purely from the network, matching the "attacker with no CA-signed certificate" scope.

### Recommendation
Do not act on `RecvError` unless it can be tied to authenticated traffic: e.g., require the sender to prove knowledge of a recent AEAD-authenticated packet counter/nonce for that index, or move `RecvError` handling behind a lightweight authenticated-but-unencrypted MAC (similar to the relay `VerifyRelay` frames) rather than trusting the raw UDP source-address comparison. At minimum, rate-limit and require additional corroboration (e.g., recent successful decrypt from that same index) before calling `closeTunnel`.

### Proof of Concept
1. Attacker observes traffic between A and B (or is on-path), learning B's `RemoteIndex` value as seen in packets sent from A→B (present in cleartext header on every packet) and B's currently reported UDP `ip:port`.
2. Attacker crafts a `header.RecvError` packet: `header.Encode(buf, header.Version, header.RecvError, 0, <A's index as known by B>, 0)` and sends it to B, spoofing the source address to A's `ip:port` (or replaying from an on-path vantage point).
3. `readOutsidePackets` routes it directly to `f.handleRecvError(via.UdpAddr, h)` without decrypting anything.
4. Because `via.UdpAddr` matches `hostinfo.GetRemote()`, the check passes, and B calls `f.closeTunnel(hostinfo)` plus deletes the pending hostinfo — tearing down the tunnel without either side authenticating the request.

func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
```

func (cs *ConnectionState) Decrypt(l *slog.Logger, messageCounter uint64, out []byte, packet []byte, nb []byte) ([]byte, error) {
	var err error
	cs.decryptLock.Lock()
	result := cs.window.Check(l, messageCounter)
	cs.decryptLock.Unlock()
	if !result {
		return nil, ErrAlreadySeen
	}

	out, err = cs.dKey.DecryptDanger(out, packet[:header.Len], packet[header.Len:], messageCounter, nb)
	if err != nil {
		return nil, err
	}

	cs.decryptLock.Lock()
	result = cs.window.Update(l, messageCounter)
	cs.decryptLock.Unlock()
	if !result {
		return nil, ErrAlreadySeen
	}
	return out, nil
}

func (f *Interface) reloadSendRecvError(c *config.C) {
	if c.InitialLoad() || c.HasChanged("listen.send_recv_error") {
		stringValue := c.GetString("listen.send_recv_error", "always")

		switch stringValue {
		case "always":
			f.sendRecvErrorConfig = recvErrorAlways
		case "never":
			f.sendRecvErrorConfig = recvErrorNever
		case "private":
			f.sendRecvErrorConfig = recvErrorPrivate
		default:
			if c.GetBool("listen.send_recv_error", true) {
				f.sendRecvErrorConfig = recvErrorAlways
			} else {
				f.sendRecvErrorConfig = recvErrorNever
			}
		}

	}
