### Title
Signer's event-observer HTTP endpoint accepts unauthenticated callbacks, allowing forged block-validation and StackerDB events to be injected - (File: `libsigner/src/events.rs`)

### Summary
`SignerEventReceiver::next_event()` in `libsigner/src/events.rs` accepts any HTTP POST to `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, and `/new_block` and converts the JSON body directly into a trusted `SignerEvent`, with no verification of who sent the request. This is the same bug class as the reported finding: a callback consumer has no way to authenticate the initiator, so anyone able to reach the listening socket can impersonate the Stacks node and inject state into the signer.

### Finding Description
The signer runs an HTTP server (`SignerEventReceiver`) that is meant to receive event-observer callbacks exclusively from its paired Stacks node, as configured via `endpoint` in the signer config (frequently bound to `0.0.0.0:PORT`, e.g. `sample/conf/signer/mainnet-signer-conf.toml`).

`next_event()` dispatches based solely on URL path, with zero authentication check on the connection or request: [1](#0-0) 

It calls `process_event::<T, E>(request)`, which reads the body, deserializes it as JSON, and converts it straight into a `SignerEvent` — again, no signature, token, or peer-identity check is performed: [2](#0-1) 

Compare this to `stackslib`'s StackerDB replication path, where every chunk carries a `SlotMetadata`/signature that is cryptographically verified against the expected slot owner before being trusted (`validate_received_chunk`): [3](#0-2) 

The equality that should hold — "event received on this HTTP endpoint" == "event actually emitted by our configured, trusted stacks node" — is not enforced anywhere in the signer's event-receiving path. There is no shared secret, HMAC, mTLS, or IP allow-list check comparable to the `auth_password`/`auth_token` mechanism that exists for the *signer→node RPC* direction (`stacks-signer/src/client/stacks_client.rs`, `stackslib/src/net/api/postblock_proposal.rs`); that mechanism protects RPC calls *into* the node, not callbacks *into* the signer.

While `StackerDBChunksEvent` chunks do carry a `StackerDBChunkData` with a `sig` field that later gets checked against the expected slot signer elsewhere in the pipeline, the other event types accepted by this same unauthenticated endpoint — `BlockValidateResponse` (`/proposal_response`), `BurnBlockEvent` (`/new_burn_block`), and `StacksBlockEvent` (`/new_block`) — carry no such per-message cryptographic authentication at the transport/endpoint level. They are trusted purely because they arrived on the right path.

The code even documents the operators' own awareness of this gap: [4](#0-3) 

### Impact Explanation
A remote, unauthenticated attacker who can reach the signer's bound event-observer port (which the sample configs explicitly bind to `0.0.0.0`) can POST a forged `BlockValidateResponse` to `/proposal_response`. This is consumed by `Signer::handle_block_validate_response` in `stacks-signer/src/v0/signer.rs`, which feeds directly into the signer's block acceptance/rejection decision logic (out of scope to detail further per rules, but the trust boundary itself is in scope: the HTTP intake layer). Likewise, forged `BurnBlockEvent`/`StacksBlockEvent` payloads let an attacker desynchronize the signer's view of chain state (burn height, block info) from actual chain state — an unauthenticated write to signer-local state via a forged/unauthenticated event, matching the "unauthenticated/unauthorized write to state" Critical impact category.

### Likelihood Explanation
Any host with network access to the signer's listening port can trigger this with a single crafted HTTP POST — no cryptographic material, node secret, or privileged role is required. The risk is heightened by default sample configurations binding the listener to `0.0.0.0`, and by the explicit warning in `stacks-signer/src/lib.rs` acknowledging that additional security controls (e.g., firewalling) are the operator's responsibility rather than being enforced by the code itself.

### Recommendation
Add message-level authentication to the event-observer callback path so the signer can verify the initiator is the paired stacks node, analogous to the `auth_token`/`auth_password` mechanism already used for the reverse direction: e.g., require and verify a shared-secret header (HMAC over the body) on every request in `SignerEventReceiver::next_event()`/`process_event()` before converting the body into a trusted `SignerEvent`, and reject requests that fail this check. Alternatively/additionally, bind by default to loopback and document that exposing the endpoint beyond localhost without additional authentication is unsafe.

### Proof of Concept
1. Configure a signer with its `endpoint` reachable over the network (as in `sample/conf/signer/mainnet-signer-conf.toml`, which binds `0.0.0.0:30000`).
2. From an unrelated host, send:
```
POST /proposal_response HTTP/1.1
Host: <signer-ip>:30000
Content-Type: application/json
Content-Length: <n>

{ ... forged BlockValidateResponse JSON ... }
```
3. `SignerEventReceiver::next_event()` (`libsigner/src/events.rs:437-458`) routes this to `process_event::<T, BlockValidateResponse>`, which deserializes it with no sender verification and forwards it as a trusted `SignerEvent::BlockValidationResponse` into the signer's runloop, exactly as the legitimate node's own POST would.

    fn next_event(&mut self) -> Result<SignerEvent<T>, EventError> {
        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)
            } else if request.url() == "/new_block" {
                process_event::<T, StacksBlockEvent>(request)
            } else {
                let url = request.url().to_string();
                debug!(
                    "[{:?}] next_event got request with unexpected url {}, return OK so other side doesn't keep sending this",
                    event_receiver.local_addr,
                    url
                );
                ack_dispatcher(request);
                Err(EventError::UnrecognizedEvent(url))
            }
        })?

fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}
