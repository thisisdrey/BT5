### Title
Flash-loan inflated `totalSupply` poisons the shared reward index in `RewardsDistributor.updateBeforeMintOrBurn`, permanently destroying all users' unclaimed yield - (File: contracts/RewardsDistributor.sol)

### Summary
`RewardsDistributor.updateBeforeMintOrBurn(IERC20,address)` is permissionless and snapshots the global reward index using the token's *current* `totalSupply()`. An unprivileged attacker can flash-loan the underlying asset, deposit it into a Pool to momentarily inflate a `DepositToken`'s supply, call `updateBeforeMintOrBurn` so the index checkpoint is computed against the inflated supply (reward ratio ≈ 0 while `timestamp` advances to `block.timestamp`), then withdraw. The entire reward emission accrued since the last checkpoint is permanently diluted to ~0 for every holder — an on-chain analog of anonymous cache poisoning: a crafted request writes poisoned shared state that all other users consume.

### Finding Description
`claimRewards` / `updateBeforeMintOrBurn` / `updateBeforeTransfer` all funnel into `_updateTokenIndex`, which computes:

- `_tokensAccrued = (block.timestamp - timestamp) * tokenSpeeds[token_]`
- `_ratio = _tokensAccrued.wadDiv(token_.totalSupply())`
- `tokenStates[token_] = {index + _ratio, block.timestamp}` [1](#0-0) 

Because `updateBeforeMintOrBurn` is `external` with no access control (`// This function also may be called by anyone`), anyone can force this checkpoint at a moment of their choosing [2](#0-1) . `totalSupply` is read live, so inflating `DepositToken` supply via a same-transaction flash-loaned deposit makes `_ratio` arbitrarily small while `timestamp` is committed to storage. The elapsed reward period is consumed with ~no index increase. There is no way to re-attribute the skipped emissions — they are never credited to `tokensAccruedOf` for any account [3](#0-2) .

### Impact Explanation
Permanent loss of unclaimed yield for all suppliers/borrowers of the targeted token. Emissions `deltaTimestamp * speed` that should have been distributed over the elapsed period are effectively burned (the `rewardToken` stays in the distributor but no account index ever captures it). Repeatable: the attacker can poison every index checkpoint, keeping effective distribution near zero for as long as they sustain the attack. This breaks the reward-accrual invariant, matching "anonymous cache poisoning": the poisoned checkpoint (`index`/`timestamp`) is shared state consumed by every subsequent claim.

### Likelihood Explanation
- Fully unprivileged: `updateBeforeMintOrBurn` has no modifier; only requires `tokenStates[token_].index > 0` (i.e., a registered reward token).
- Attacker supply inflation: flash-loan underlying → `Pool.deposit` (mints `DepositToken`, raising `totalSupply`) → `updateBeforeMintOrBurn` → withdraw/repay within the same tx. Cost is gas plus deposit/withdraw fees, if any.
- Prerequisites/uncertainties: the `DepositToken` must allow same-block deposit+withdraw (if `_revertIfLocked`/a lock period is enabled for that pool the withdraw leg fails — this is a per-pool config I could not fully verify from the index); profit is griefing-class (yield destroyed, not stolen by the attacker), though an attacker holding most real supply could poison checkpoints to suppress others' accrual while their own accrued `tokensAccruedOf` remains claimable.

### Recommendation
- Restrict `updateBeforeMintOrBurn`/`updateBeforeTransfer` to `DepositToken`/`DebtToken` contracts (the doc comment says they are "called by" those tokens — enforce it), or
- make `_calculateTokenIndex` resistant to intra-transaction supply manipulation (e.g., snapshot supply at last checkpoint, use time-weighted supply, or a TWAP-style supply oracle).

```text
    function _calculateTokenIndex(
        TokenState memory _supplyState,
        IERC20 token_
    ) private view returns (uint224 _newIndex, uint32 _newTimestamp) {
        uint256 _speed = tokenSpeeds[token_];
        uint256 _deltaTimestamps = block.timestamp - uint256(_supplyState.timestamp);
        if (_deltaTimestamps > 0 && _speed > 0) {
            uint256 _totalSupply = token_.totalSupply();
            uint256 _tokensAccrued = _deltaTimestamps * _speed;
            uint256 _ratio = _totalSupply > 0 ? _tokensAccrued.wadDiv(_totalSupply) : 0;
            _newIndex = (_supplyState.index + _ratio).toUint224();
            _newTimestamp = block.timestamp.toUint32();
        } else if (_deltaTimestamps > 0 && _supplyState.index > 0) {
            _newTimestamp = block.timestamp.toUint32();
        }
    }
```
