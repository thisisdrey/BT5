### Title
`ObjectPoolStateManager` accounting is never updated on `LinkRepositoryToObjectPool`, `DisconnectGitAlternates`, `CreateObjectPool`, or `DeleteObjectPool` - ([File: internal/gitaly/service/objectpool/])

### Summary
Gitaly maintains a relational accounting layer, `relational.ObjectPoolStateManager`, whose job is to track object-pool membership (`NotifyCreatePool`, `NotifyDeletePool`, `NotifyLinkRepository`, `NotifyUnlinkRepository`) in a persistent store (`PoolStore`) separate from the on-disk `objects/info/alternates` state [1](#0-0) . This is analogous to `LoanManager.loanLiquidation()` in the Gondi report: an authoritative bookkeeping call that must be invoked whenever the underlying resource state changes, or the accounting layer silently diverges from reality.

### Finding Description
The `objectPoolStateManager` is wired into the `objectpool` gRPC server as a dependency [2](#0-1) , but a repo-wide search shows `NotifyLinkRepository`, `NotifyUnlinkRepository`, `NotifyCreatePool`, and `NotifyDeletePool` are referenced only inside `state_manager.go` and its own unit test — they are never called from any of the actual RPC handlers that mutate pool state:

- `CreateObjectPool` calls `objectpool.Create` and only updates the *migration* state manager (`s.migrationStateManager.RecordKeyCreation`), never `s.objectPoolStateManager.NotifyCreatePool` [3](#0-2) .
- `DeleteObjectPool` calls `repoutil.Remove` and only updates the migration state manager (`RecordKeyDeletion`), never `s.objectPoolStateManager.NotifyDeletePool` [4](#0-3) .
- `LinkRepositoryToObjectPool` calls `pool.Link(ctx, repo)` which only performs the on-disk alternates write and transaction voting; it never touches `objectPoolStateManager` at all [5](#0-4) [6](#0-5) .
- `DisconnectGitAlternates` calls `objectpool.Disconnect`, which similarly only manipulates the alternates file and votes, with no call into `objectPoolStateManager.NotifyUnlinkRepository` [7](#0-6) [8](#0-7) .

The only place `PoolStore` (the underlying accounting store) is actually populated is via an out-of-band, best-effort `ScanPoolMetadata` filesystem walk that infers pool relationships by reading `objects/info/alternates` off disk after the fact [9](#0-8) . There is no live, synchronous accounting update tied to the actual mutating RPCs the same way `loanLiquidation()` was supposed to be tied to `settleWithBuyout()`.

### Impact Explanation
Any ordinary user-driven fork/pool workflow — `CreateObjectPool`, `LinkRepositoryToObjectPool` (issued automatically on repository fork), `DisconnectGitAlternates`, and `DeleteObjectPool` — mutates the real on-disk pool/member relationship without the relational accounting layer (`PoolStore`/`ObjectPoolStateManager`) ever being told. Any feature, migration, or safety check that relies on `PoolStore` to know the current set of pool members (for example, to prevent deleting a pool that still has members, or to know which repositories need object-pool-aware housekeeping/migration handling) will operate on stale or entirely empty accounting data. This can lead to a pool being deleted while it still has live members (silently corrupting those members, per the explicit comment in `DeleteObjectPool` for the on-disk case), or migration/housekeeping decisions being made based on incorrect pool membership. Because the underlying store starts populated only by the asynchronous `ScanPoolMetadata` best-effort scan (with its own error-recording path for "broken pools"), the state manager's data can be permanently absent or arbitrarily delayed relative to the true, immediately-effective object pool relationship.

### Likelihood Explanation
The gap is triggered by ordinary, expected use of the public `ObjectPoolService` RPCs — no privileged access, malicious peer, or crafted payload is required. Every `CreateObjectPool`/`LinkRepositoryToObjectPool`/`DisconnectGitAlternates`/`DeleteObjectPool` call, which are part of Gitaly's routine fork and object-pool lifecycle, exercises this gap deterministically and unconditionally, since the notification calls are entirely absent from the code paths rather than conditionally skipped.

### Recommendation
Wire the `ObjectPoolStateManager` notifications directly into the mutating RPC handlers so the accounting store is updated transactionally/synchronously with the actual state change, mirroring how `loanLiquidation()` should be invoked from every code path that settles/liquidates a loan:
- Call `objectPoolStateManager.NotifyCreatePool` in `CreateObjectPool` after `objectpool.Create` succeeds.
- Call `objectPoolStateManager.NotifyDeletePool` in `DeleteObjectPool` after `repoutil.Remove` succeeds (and ideally verify no live members remain before deleting).
- Call `objectPoolStateManager.NotifyLinkRepository` from `LinkRepositoryToObjectPool` (or inside `objectpool.Link`) after the alternates file is committed.
- Call `objectPoolStateManager.NotifyUnlinkRepository` from `DisconnectGitAlternates` (or inside `objectpool.Disconnect`) after the alternates removal is committed.

### Proof of Concept
1. Create a repository and an object pool via `CreateObjectPool`, then link the repository via `LinkRepositoryToObjectPool` (both succeed, and the on-disk `objects/info/alternates` correctly points at the pool, as verified by `TestLink` in `internal/git/objectpool/link_test.go`).
2. Query the relational `PoolStore` (e.g. via `ListPoolMembers`) for the pool's members immediately after step 1 — it returns no members because `NotifyLinkRepository` was never invoked by the `LinkRepositoryToObjectPool` RPC path.
3. Similarly, call `DeleteObjectPool` on a pool that still has members linked on disk. `objectPoolStateManager.NotifyDeletePool` is never called, so the relational store is not updated, while the actual repository is removed and any remaining alternates-linked members become corrupt, per the documented risk in `DeleteObjectPool`'s handler comment and RPC docstring [10](#0-9) .

// Link will link the given repository to the object pool. This is done by writing the object pool's
// path relative to the repository into the repository's "alternates" file. This does not trigger
// deduplication, which is the responsibility of the caller.
func Link(ctx context.Context, pool, repo *localrepo.Repo, txManager transaction.Manager) (returnedErr error) {
	altPath, err := repo.InfoAlternatesPath(ctx)
	if err != nil {
		return err
	}

	expectedRelPath, err := getRelativeObjectPath(ctx, pool, repo)
	if err != nil {
		return err
	}

	linked, err := linkedToRepository(ctx, pool, repo)
	if err != nil {
		return err
	}

	if linked {
		// When the repository is already linked to the repository, cast a vote to ensure the
		// repository is consistent with the other replicas.
		if err := transaction.VoteOnContext(ctx, txManager, voting.VoteFromData([]byte("repository linked")), voting.Synchronized); err != nil {
			return fmt.Errorf("vote on linked repository: %w", err)
		}

		return nil
	}

	alternatesWriter, err := safe.NewLockingFileWriter(altPath)
	if err != nil {
		return fmt.Errorf("creating alternates writer: %w", err)
	}
	defer func() {
		if err := alternatesWriter.Close(); err != nil && returnedErr == nil {
			returnedErr = fmt.Errorf("closing alternates writer: %w", err)
		}
	}()

	if _, err := io.WriteString(alternatesWriter, expectedRelPath); err != nil {
		return fmt.Errorf("writing alternates: %w", err)
	}

	if err := transaction.CommitLockedFile(ctx, txManager, alternatesWriter); err != nil {
		return fmt.Errorf("committing alternates: %w", err)
	}

	if tx := storage.ExtractTransaction(ctx); tx != nil {
		alternatesRelativePath, err := filepath.Rel(tx.FS().Root(), altPath)
		if err != nil {
			return fmt.Errorf("rel alternates file: %w", err)
		}

		if err := tx.FS().RecordFile(alternatesRelativePath); err != nil {
			return fmt.Errorf("record alternates file")
		}
	}

	return removeMemberBitmaps(ctx, pool, repo)
}

func Disconnect(ctx context.Context, f storage.FS, repo *localrepo.Repo, logger log.Logger, txManager transaction.Manager) error {
	repoPath, err := repo.Path(ctx)
	if err != nil {
		return err
	}

	altInfo, err := stats.AlternatesInfoForRepository(repoPath)
	if err != nil {
		return err
	}

	// If the repository does not have an alternates file or if alternate file does not contain
	// object directories, there is not an object pool repository to disconnect from and no need to
	// continue.
	if !altInfo.Exists || len(altInfo.ObjectDirectories) == 0 {
		// When a repository is not linked to any alternates, ensure the repository is consistent
		// with other replicas.
		if err := transaction.VoteOnContext(ctx, txManager, voting.VoteFromData([]byte("no alternates")), voting.Synchronized); err != nil {
			return fmt.Errorf("vote on missing alternates: %w", err)
		}

		return nil
	}

	// Acquire distributed lock
	if err := transaction.VoteOnContext(ctx, txManager, voting.VoteFromData([]byte("migrate objects")), voting.Preparing); err != nil {
		return fmt.Errorf("preparatory vote for migrating objects: %w", err)
	}

	if err := transaction.VoteOnContext(ctx, txManager, voting.VoteFromData([]byte("migrate objects")), voting.Prepared); err != nil {
		return fmt.Errorf("preparatory vote for migrating objects: %w", err)
	}

	// A repository should only ever be linked to a single alternate object directory. If the
	// repository links to multiple object directories, the repository is in an invalid state.
	if len(altInfo.ObjectDirectories) > 1 {
		return errors.New("multiple alternate object directories")
	}

	// If the alternate object directory entry does not exist on disk, the repository's Git
	// alternates file is in an invalid state.
	altObjectDir := altInfo.AbsoluteObjectDirectories()[0]
	altObjectDirStats, err := os.Stat(altObjectDir)
	if err != nil {
		return err
	}

	// If the alternate object directory is not a directory, the repository's Git alternates file is
	// in an invalid state.
	if !altObjectDirStats.IsDir() {
		return errors.New("alternate object entry is not a directory")
	}

	objectFiles, err := findObjectFiles(altObjectDir)
	if err != nil {
		return err
	}

	repositoryRelativePath, err := filepath.Rel(f.Root(), repoPath)
	if err != nil {
		return fmt.Errorf("repository relative path: %w", err)
	}

	for _, path := range objectFiles {
		sourceRelativePath, err := filepath.Rel(f.Root(), filepath.Join(altObjectDir, path))
		if err != nil {
			return fmt.Errorf("source relative path: %w", err)
		}
		targetRelativePath := filepath.Join(repositoryRelativePath, "objects", path)

		if err := storage.MkdirAll(f, filepath.Dir(targetRelativePath)); err != nil {
			return err
		}

		if err := storage.Link(f, sourceRelativePath, targetRelativePath); err != nil {
			if errors.Is(err, fs.ErrExist) {
				continue
			}

			return err
		}
	}

	if err := transaction.VoteOnContext(ctx, txManager, voting.VoteFromData([]byte("migrate objects")), voting.Committed); err != nil {
		return fmt.Errorf("committed vote for migrating objects: %w", err)
	}

	altFile, err := repo.InfoAlternatesPath(ctx)
	if err != nil {
		return err
	}

	backupFile, err := newBackupFile(altFile)
	if err != nil {
		return err
	}

	return removeAlternatesIfOk(ctx, repo, altFile, backupFile, logger, txManager)
}

func (s *server) ScanPoolMetadata(req *gitalypb.ScanPoolMetadataRequest, stream gitalypb.InternalGitaly_ScanPoolMetadataServer) error {
	ctx := stream.Context()
	storageName := req.GetStorageName()

	storagePath, err := s.locator.GetStorageByName(ctx, storageName)
	if err != nil {
		return structerr.NewInvalidArgument("get storage: %w", err)
	}

	processPoolMember := processPoolMemberFunc(ctx, storagePath, storageName, s.poolStore, s.logger, stream)

	if err := walk.FindRepositories(ctx, s.locator, storageName, processPoolMember); err != nil {
		return structerr.NewInternal("%w", err)
	}

	return nil
}

func processPoolMemberFunc(
	ctx context.Context,
	storagePath, storageName string,
	poolStore relational.PoolStore,
	logger log.Logger,
	stream gitalypb.InternalGitaly_ScanPoolMetadataServer,
) func(relPath string, _ fs.FileInfo) error {
	invalidPools := make(map[string]bool)

	return func(relPath string, fi fs.FileInfo) error {
		repoPath := filepath.Join(storagePath, relPath)

		altInfo, err := stats.AlternatesInfoForRepository(repoPath)
		if err != nil {
			return fmt.Errorf("read alternates for %q: %w", relPath, err)
		}

		if !altInfo.Exists || len(altInfo.ObjectDirectories) == 0 {
			return nil
		}

		absPoolPaths := altInfo.AbsoluteObjectDirectories()
		if len(absPoolPaths) == 0 {
			return nil
		}

		poolObjectDir := absPoolPaths[0]
		poolRepoPath := filepath.Dir(poolObjectDir)

		poolDiskPath, err := filepath.Rel(storagePath, poolRepoPath)
		if err != nil {
			return fmt.Errorf("compute relative path for pool %q (repo %q): %w", poolRepoPath, relPath, err)
		}
		poolDiskPath = filepath.ToSlash(poolDiskPath)

		// We could encounter the same invalid pool multiple times.
		if invalidPools[poolDiskPath] {
			recordBrokenPool(ctx, poolStore, logger, storageName, relPath, poolDiskPath)
			return nil
		}

		if err := storage.ValidateGitDirectory(poolRepoPath); err != nil {
			invalidPools[poolDiskPath] = true
			recordBrokenPool(ctx, poolStore, logger, storageName, relPath, poolDiskPath)
			return nil
		}

		return stream.Send(&gitalypb.ScanPoolMetadataResponse{
			RelativePath: relPath,
			PoolDiskPath: poolDiskPath,
		})
	}
}
