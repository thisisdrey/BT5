### Title
Permissionless `migrate_coin_store_to_fungible_store` Bypasses `TransferRef`-Gated Frozen-Flag Invariant on Any Account's Primary Fungible Store — (File: `aptos-move/framework/aptos-framework/sources/coin.move`)

---

### Summary

`migrate_coin_store_to_fungible_store<CoinType>` is a `public entry fun` that accepts a raw `vector<address>` with **no signer parameter**, making it callable by any unprivileged account for any target address. Internally it calls `maybe_convert_to_fungible_store`, which propagates the `CoinStore.frozen` flag to the primary fungible store via `fungible_asset::set_frozen_flag_internal` — a `public(friend)` function that mutates `FungibleStore.frozen` **without a `TransferRef`**. This violates the formally stated framework invariant that frozen-flag changes require a valid `TransferRef`, and enables an unprivileged caller to unfreeze a frozen primary fungible store (or force-freeze an unfrozen one) for any account on mainnet.

---

---

### Impact Explanation

**Unfreeze bypass (primary impact):**

If a victim's primary fungible store is frozen by the `TransferRef` holder (e.g., the framework freezes an APT store for compliance) while the victim's `CoinStore<CoinType>` is **not** frozen, any unprivileged attacker can call:

```
migrate_coin_store_to_fungible_store<AptosCoin>([victim_address])
```

The migration reads `CoinStore.frozen = false`, compares it to `primary_store.frozen = true`, and calls `set_frozen_flag_internal(store, false)` — **unfreezing the primary fungible store without a `TransferRef`**. The victim can then freely transfer APT, bypassing the freeze entirely.

**Forced freeze (secondary impact):**

Conversely, if a victim's `CoinStore<CoinType>` is frozen (by the `FreezeCapability` holder) but their primary fungible store is not, an attacker triggers migration to freeze the primary fungible store, locking the victim's assets in the new format without the `TransferRef` holder's action.

Both outcomes represent unauthorized modification of a user's fungible store frozen state — a direct asset-control impact (permanent freeze or freeze bypass of APT/fungible assets).

---

### Likelihood Explanation

The `CoinStore` and primary fungible store frozen flags can diverge in realistic mainnet scenarios:

1. The framework (or coin issuer) freezes the primary fungible store via `TransferRef` before the account has migrated its `CoinStore` — a natural ordering during the Coin→FA migration period.
2. For non-APT coins, the `FreezeCapability<CoinType>` and the FA `TransferRef` may be held by different parties, making desynchronization more likely.
3. The victim themselves can exploit this to self-unfreeze by calling `migrate_to_fungible_store` (which also calls `maybe_convert_to_fungible_store` with no frozen-state guard).

The migration period is active on mainnet, making this window exploitable today.

---

### Recommendation

1. **Add an owner check** to `migrate_coin_store_to_fungible_store` so only the account owner can trigger migration for their own address (matching `migrate_to_fungible_store`'s signer requirement).
2. **Do not overwrite a pre-existing primary fungible store's frozen flag** during migration. Only propagate `CoinStore.frozen` when the primary fungible store is being created for the first time by the migration. If the store already exists, leave its frozen state untouched.

---

### Proof of Concept

```
State before:
  victim: CoinStore<AptosCoin> { coin: 1000 APT, frozen: false }
  victim: PrimaryFungibleStore<APT> { balance: 500 APT, frozen: true }
    (frozen by framework via TransferRef for compliance)

Attacker submits:
  0x1::coin::migrate_coin_store_to_fungible_store<0x1::aptos_coin::AptosCoin>(
      accounts = [victim_address]
  )

Execution of maybe_convert_to_fungible_store:
  1. move_from<CoinStore<AptosCoin>>(victim) → { coin: 1000, frozen: false }
  2. ensure_primary_store_exists(victim, apt_metadata) → existing store (frozen=true)
  3. unchecked_deposit_with_no_events(store, coin_to_fungible_asset(coin))
  4. frozen(false) != is_frozen(store)(true) → set_frozen_flag_internal(store, false)
     ← PRIMARY FUNGIBLE STORE IS NOW UNFROZEN, no TransferRef used

State after:
  victim: PrimaryFungibleStore<APT> { balance: 1500 APT, frozen: false }
  victim can now freely transfer APT, bypassing the compliance freeze
``` [8](#0-7)

    fun maybe_convert_to_fungible_store<CoinType>(
        account: address
    ) acquires CoinStore, CoinConversionMap, CoinInfo {
        if (exists<CoinStore<CoinType>>(account)) {
            let CoinStore<CoinType> { coin, frozen, deposit_events, withdraw_events } =
                move_from<CoinStore<CoinType>>(account);
            if (is_coin_initialized<CoinType>() && coin.value > 0) {
                let metadata = ensure_paired_metadata<CoinType>();
                let store =
                    primary_fungible_store::ensure_primary_store_exists(
                        account, metadata
                    );

                event::emit(
                    CoinStoreDeletion {
                        coin_type: type_info::type_name<CoinType>(),
                        event_handle_creation_address: guid::creator_address(
                            event::guid(&deposit_events)
                        ),
                        deleted_deposit_event_handle_creation_number: guid::creation_num(
                            event::guid(&deposit_events)
                        ),
                        deleted_withdraw_event_handle_creation_number: guid::creation_num(
                            event::guid(&withdraw_events)
                        )
                    }
                );

                if (coin.value == 0) {
                    destroy_zero(coin);
                } else {
                    fungible_asset::unchecked_deposit_with_no_events(
                        store.object_address(),
                        coin_to_fungible_asset(coin)
                    );
                };

                // Note:
                // It is possible the primary fungible store may already exist before this function call.
                // In this case, if the account owns a frozen CoinStore and an unfrozen primary fungible store, this

                // `frozen` semantic as consistent as possible.

                    fungible_asset::set_frozen_flag_internal(store, frozen);
                }
            } else {
                destroy_zero(coin);
            };
            event::destroy_handle(deposit_events);
            event::destroy_handle(withdraw_events);
        };
    }
