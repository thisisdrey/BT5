Audit Report

## Title
Unauthenticated, unbounded `Tips` storage growth via `add_tip` for arbitrary/non-existent nonces - ([File: bridges/snowbridge/pallets/inbound-queue-v2/src/lib.rs])

## Summary
The `Tips` storage map in the Snowbridge inbound-queue-v2 pallet is keyed by an arbitrary, caller-supplied `u64` nonce, and `AddTip::add_tip` only checks that the nonce has not already been marked as processed via `Nonce::<T>::get(nonce)` — it never verifies that a message with that nonce was actually emitted by the Ethereum Gateway or will ever be submitted. Any signed account on Asset Hub can reach this through the public `snowbridge-pallet-system-frontend::add_tip` extrinsic, which swaps a small fee asset for Ether and forwards an `EthereumSystemCall::AddTip` XCM `Transact` to Bridge Hub, permanently inserting entries into `Tips` for nonces that may never correspond to a real message.

## Finding Description
`Tips` is declared as `StorageMap<_, Blake2_128Concat, u64, u128, OptionQuery>` [1](#0-0) , with no bound on the keyspace and no reconciliation against actual inbound message nonces at insertion time.

The only entry into this map, `AddTip::add_tip`, validates solely that `amount > 0` and that the nonce has not yet been consumed via the `Nonce` sparse bitmap — it performs no check that a message with that nonce exists, was ever committed on Ethereum, or falls within any plausible range of the current nonce watermark [2](#0-1) .

This is reachable from any signed account via `snowbridge_pallet_system_frontend::add_tip`, which requires only `ensure_signed(origin)` and a swappable fee asset, then forwards the tip details to Bridge Hub via XCM `Transact` [3](#0-2) .

The only place a `Tips` entry is ever removed is in `process_message`, which takes and clears the entry for a nonce exactly when a real message with that nonce is submitted and processed via `submit` [4](#0-3) . There is no other cleanup path, no root/admin call to purge stale entries, and no bound on the cardinality of the `Tips` map (full `u64` keyspace). Entries created for nonces that will never be used by a real Ethereum-originated message (e.g., far-future/arbitrary values) can never be reclaimed, since `process_message` only clears the entry matching the exact nonce of a message that is actually verified and processed.

## Impact Explanation
This matches the accepted impact category of "public underpriced work that degrades block production or stalls bridge processing." An unprivileged signed account, at the cost of burning a small nonzero amount of Ether (obtained via swap), can permanently grow Bridge Hub's `Tips` storage with entries that will never be cleared, since cleanup only occurs on actual message processing for the exact nonce. This is repeatable indefinitely and is not bounded by real bridge traffic, resulting in unbounded on-chain state growth from an unprivileged, public extrinsic.

## Likelihood Explanation
High. The path is fully public: `snowbridge-pallet-system-frontend::add_tip` requires only `ensure_signed` and a nonzero swappable fee asset amount; `AddTip::add_tip` on the receiving side enforces only `amount > 0` and `!Nonce::<T>::get(nonce)`, both trivially satisfiable for an arbitrary/never-used nonce. No coordination with actual bridge relayers or Ethereum activity is required, and the action can be repeated indefinitely across the full `u64` nonce space.

## Recommendation
Bound the acceptable nonce range in `AddTip::add_tip` (e.g., relative to the last known/consumed nonce or a validated upper watermark), require the nonce to correspond to an already-observed/committed outbound message before accepting a tip, and/or add a permissioned or time-bounded mechanism to reap stale `Tips` entries that are never claimed by `process_message`.

## Proof of Concept
1. Attacker holds a small balance of an asset swappable to Ether via `T::Swap` on Asset Hub.
2. Attacker calls `snowbridge_pallet_system_frontend::add_tip(message_id = <arbitrary/never-to-be-used nonce>, asset = <minimal amount>)`.
3. `swap_fee_asset_and_burn` swaps and burns the asset for a small nonzero Ether amount, and the pallet forwards `EthereumSystemCall::AddTip { sender, message_id, amount }` via XCM `Transact` to Bridge Hub.
4. On Bridge Hub, `AddTip::add_tip` checks only `amount > 0` and `!Nonce::<T>::get(nonce)` (both true for a fabricated nonce) and inserts into `Tips::<T>`.
5. Because no real message with that nonce is ever submitted via `submit`, this `Tips::<T>` entry is never read or removed by `process_message`.
6. Repeating with new arbitrary nonces grows `Tips` storage on Bridge Hub without bound, at minimal per-call cost.

		pub fn process_message(relayer: T::AccountId, message: Message) -> DispatchResult {
			// Verify that the message was submitted from the known Gateway contract
			ensure!(T::GatewayAddress::get() == message.gateway, Error::<T>::InvalidGateway);

			let (nonce, relayer_fee) = (message.nonce, message.relayer_fee);

			// Verify the message has not been processed
			ensure!(!Nonce::<T>::get(nonce), Error::<T>::InvalidNonce);

			// Mark message as received
			Nonce::<T>::set(nonce);

			let message_id = T::MessageProcessor::process_message(relayer.clone(), message)
				.map_err(|e| match e {
					MessageProcessorError::ProcessMessage(e) => e,
					MessageProcessorError::ConvertMessage(e) => Error::<T>::from(e).into(),
					MessageProcessorError::SendMessage(e) => Error::<T>::from(e).into(),
				})?;

			// Pay relayer reward
			let tip = Tips::<T>::take(nonce).unwrap_or_default();
			let total_tip = relayer_fee.saturating_add(tip);
			if total_tip > 0 {
				T::RewardPayment::register_reward(&relayer, T::DefaultRewardKind::get(), total_tip);
			}

			// Emit event with the message_id
			Self::deposit_event(Event::MessageReceived { nonce, message_id });

			Ok(())
		}

	impl<T: Config> AddTip for Pallet<T> {
		fn add_tip(nonce: u64, amount: u128) -> Result<(), AddTipError> {
			ensure!(amount > 0, AddTipError::AmountZero);
			// If the nonce is already processed, return an error
			ensure!(!Nonce::<T>::get(nonce.into()), AddTipError::NonceConsumed);
			// Otherwise add the tip.
			Tips::<T>::mutate(nonce, |tip| {
				*tip = Some(tip.unwrap_or_default().saturating_add(amount));
			});
			return Ok(());
		}
	}
