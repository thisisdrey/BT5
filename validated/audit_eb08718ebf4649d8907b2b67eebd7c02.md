### No vulnerability found for this question.

**Analysis summary:**

The `gitaly-servers` gRPC metadata consumed by `storage.ExtractGitalyServer(ctx, repo.GetStorageName())` in [1](#0-0)  is not attacker-controllable data smuggled through the RPC's `Repository` message. It is a trusted, server-generated context value injected by GitLab Rails/Praefect using `storage.InjectGitalyServers` [2](#0-1) , populated from the operator's own known storage-to-address/token configuration — not from any field the requester supplies. The design doc confirms this metadata channel exists specifically so that a trusted proxy (Praefect) can tell Gitaly how to reach a legitimate peer node/token pair [3](#0-2) .

What the attacker actually controls in a request like `FetchSourceBranchRequest.SourceRepository` is only the `storage_name`/`relative_path` string used as a *lookup key* into that trusted map [4](#0-3) . They cannot inject arbitrary key→address/token entries into `gitaly-servers` metadata itself, since that metadata is not derived from the RPC body — `ExtractGitalyServers` reads it strictly from incoming gRPC metadata set by the trusted caller [5](#0-4) . At best, picking a different (but still operator-configured) `storage_name` just resolves to the legitimate address/token for that already-known storage — the same "internal Gitaly-to-Gitaly" shared secret used for any inter-node call to that storage, not a repository-scoped credential. Subsequent operations (`ResolveRevision`, `HasBranches`, etc.) still take the explicit `Repository` object supplied in the request (i.e., the attacker's own repo) [6](#0-5) , so no cross-repository object disclosure occurs beyond what the caller already legitimately references.

Exploiting this would require the attacker to forge/replace the `gitaly-servers` metadata on a request actually reaching Gitaly — which requires either a compromised Praefect/Rails peer, MITM, or direct unauthenticated gRPC access bypassing GitLab's normal request path, all of which are explicitly excluded by the rules (no malicious peer, no MITM, no non-default config, unprivileged attacker only). This is a trust-boundary/config-trust design, not a Gitaly code bug reachable by an unprivileged GitLab user.

// ExtractGitalyServers extracts `storage.GitalyServers` from an incoming context.
func ExtractGitalyServers(ctx context.Context) (gitalyServersInfo GitalyServers, err error) {
	md, ok := metadata.FromIncomingContext(ctx)
	if !ok {
		return nil, ErrEmptyMetadata
	}

	gitalyServersJSONEncoded := md["gitaly-servers"]
	if len(gitalyServersJSONEncoded) == 0 {
		return nil, fmt.Errorf("empty gitaly-servers metadata")
	}

	if err := unmarshalGitalyServers(gitalyServersJSONEncoded[0], &gitalyServersInfo); err != nil {
		return nil, err
	}
	return gitalyServersInfo, err
}
```

// InjectGitalyServers injects gitaly-servers metadata into an outgoing context
func InjectGitalyServers(ctx context.Context, name, address, token string) (context.Context, error) {
	gitalyServers := GitalyServers{
		name: {
			Address: address,
			Token:   token,
		},
	}

	gitalyServersJSON, err := json.Marshal(gitalyServers)
	if err != nil {
		return nil, err
	}

	return metadata.AppendToOutgoingContext(ctx, "gitaly-servers", base64.StdEncoding.EncodeToString(gitalyServersJSON)), nil
}
```
