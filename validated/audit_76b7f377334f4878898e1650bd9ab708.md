### Title
Stale stake snapshot in QUIC stake-weighted QoS causes persistent QoS misclassification - (File: `streamer/src/nonblocking/swqos.rs`)

### Summary
The stake-weighted QoS controller (`SwQos`) computes a connection's `peer_type` (Staked/Unstaked classification) and `total_stake` exactly once, at connection establishment time in `build_connection_context()`, and caches them in `SwQosConnectionContext` for the entire lifetime of the QUIC connection. This is structurally the same bug class as the reported `expiredOiUsd` issue: a value derived from a mutable, time-varying reference ("stake distribution" here, "collateral price" there) is captured once and never rescaled to the current reference, even though the code paths that consume it are exercised continuously as the reference changes.

### Finding Description
`build_connection_context()` calls `get_connection_stake()` once when a connection is accepted and derives `peer_type` and `total_stake` from the stake snapshot at that instant: [1](#0-0) 

This `SwQosConnectionContext` (containing `peer_type` and `total_stake`) is then reused, without ever being refreshed, for every subsequent QoS decision on that connection for its entire lifetime:
- `cache_new_connection()` uses the cached `total_stake`/`peer_type` to compute `max_uni_streams`, set once via `connection.set_max_concurrent_uni_streams()`: [2](#0-1) 
- `max_streams_per_throttling_interval()` recomputes the allowed stream budget on every new stream (`on_new_stream`), but still keys off the stale `conn_context.total_stake` and `conn_context.peer_type` captured at connect time: [3](#0-2) [4](#0-3) 

`staked_nodes` (the `Arc<RwLock<StakedNodes>>` behind `get_connection_stake`) is expected to change every epoch as stakes are activated/deactivated/redistributed, but nothing in `SwQos` re-derives `peer_type`/`total_stake` for already-established connections; only `on_stream_accepted`/`on_stream_error`/`on_stream_closed` update the global EMA load state, not the per-connection stake snapshot. As with the audited `addPriceImpactOpenInterest()` bug — where `expiredOiUsd` is stored against an old `collateralPriceUsd` and never rescaled to the current price before being consumed — here the per-connection `total_stake`/`peer_type` is stored against the stake distribution at connect time and never rescaled to the current distribution before being consumed by `compute_max_allowed_uni_streams_with_rtt()` and `available_load_capacity_in_throttling_duration()`.

### Impact Explanation
A validator's connection classified as `Staked(stake)` with a favorable `stake_ratio` at connect time (e.g., immediately after a large stake activation, or before a delegation is deactivated/slashed/moved) retains that classification and its associated `max_uni_streams` and throttling budget for as long as the QUIC connection stays alive (idle timeout 30s, but extendable via keep-alive traffic indefinitely). Conversely, a connection that was classified `Unstaked` because `stake_ratio` fell below `min_stake_ratio` at connect time will never be promoted to `Staked` even if the peer's stake subsequently grows, and a connection whose stake becomes disproportionate to the current `total_stake` (e.g., total stake grows across an epoch) keeps its original, now-inaccurate, budget ratio. This allows a peer to continue consuming stream/bandwidth quota inconsistent with its real, current stake weight — a QoS evasion relative to the intended stake-weighted admission model — for the duration of long-lived connections.

### Likelihood Explanation
Stake redistribution across epoch boundaries is a routine, expected occurrence, and QUIC connections in the TPU/TPU-forwards paths can remain open well beyond a single epoch boundary via keep-alives, so the staleness window is realistic and not a contrived edge case. However, the actual delta in allocated streams before the connection naturally cycles (idle timeout, client reconnect, or explicit pruning under load) bounds the severity, which is why this is assessed as Medium rather than higher.

### Recommendation
Periodically re-derive `peer_type`/`total_stake` for long-lived connections (e.g., on each new stream or on a fixed interval) by re-querying `get_connection_stake()` against the current `staked_nodes` snapshot, and recompute `max_uni_streams`/throttling budget accordingly, analogous to how the audit recommends rescaling `expiredOiUsd` by the ratio of current to stored collateral price before use.

### Proof of Concept
1. Establish a QUIC connection to the TPU quic streamer while the peer's `stake_ratio` (relative to current `total_stake`) is just below `min_stake_ratio`, causing `build_connection_context()` to classify it `ConnectionPeerType::Unstaked`. [5](#0-4) 
2. Keep the connection alive using QUIC keep-alives across an epoch boundary in which total network stake decreases (or the peer's own stake increases), such that, were the classification recomputed now, the peer would qualify as `Staked` with a higher throughput allocation than the `Unstaked` bucket allows — or vice versa, a `Staked` peer keeps a favorable high-throughput classification even after its stake is withdrawn.
3. Observe that `max_streams_per_throttling_interval()` and the fixed `max_uni_streams` set once via `connection.set_max_concurrent_uni_streams()` never reflect the new stake state, since `conn_context.total_stake`/`conn_context.peer_type` are never refreshed after `build_connection_context()`. [6](#0-5)

impl QosController<SwQosConnectionContext> for SwQos {
    fn build_connection_context(&self, connection: &Connection) -> SwQosConnectionContext {
        let remote_address = connection.remote_address();
        get_connection_stake(connection, &self.staked_nodes).map_or(
            SwQosConnectionContext {
                peer_type: ConnectionPeerType::Unstaked,
                total_stake: 0,
                remote_pubkey: None,
                in_staked_table: false,
                remote_address,
                stream_counter: None,
                last_update: Arc::new(AtomicU64::new(timing::timestamp())),
            },
            |(pubkey, stake, total_stake)| {
                // The heuristic is that the stake should be large enough to have 1 stream pass through within one throttle
                // interval during which we allow max (MAX_STREAMS_PER_MS * STREAM_THROTTLING_INTERVAL_MS) streams.

                let peer_type = {
                    let max_streams_per_ms = self.staked_stream_load_ema.max_streams_per_ms();
                    let min_stake_ratio =
                        1_f64 / (max_streams_per_ms * STREAM_THROTTLING_INTERVAL_MS) as f64;
                    let stake_ratio = stake as f64 / total_stake as f64;
                    if stake_ratio < min_stake_ratio {
                        // If it is a staked connection with ultra low stake ratio, treat it as unstaked.
                        ConnectionPeerType::Unstaked
                    } else {
                        ConnectionPeerType::Staked(stake)
                    }
                };

                SwQosConnectionContext {
                    peer_type,
                    total_stake,
                    remote_pubkey: Some(pubkey),
                    in_staked_table: false,
                    remote_address,
                    last_update: Arc::new(AtomicU64::new(timing::timestamp())),
                    stream_counter: None,
                }
            },
        )
