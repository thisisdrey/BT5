Audit Report

## Title
Snowbridge Outbound Queue V2 accepts user-controlled `fee` and `gas` values with no on-chain minimum check, allowing underpriced messages to consume the shared per-block Ethereum delivery capacity - ([File: bridges/snowbridge/pallets/outbound-queue-v2/src/lib.rs])

## Summary
The V2 outbound queue admission path never computes or enforces a minimum fee against the real Ethereum gas cost of a message, unlike V1's `calculate_fee`. `SendMessage::validate` in `send_message_impl.rs` only checks payload size, `fee_amount` in the XCM converter is taken verbatim from the user-supplied `PayFees` asset, and for `Command::CallContract` the "maximum gas" itself is taken directly from the user's `gas_limit`, so a caller can submit `fee = 0`/negligible messages that still occupy the fixed `MaxMessagesPerBlock` capacity and permanently unresolved `PendingOrders` entries.

## Finding Description
`Pallet::validate` for V2 (`bridges/snowbridge/pallets/outbound-queue-v2/src/send_message_impl.rs:23-32`) only enforces `MaxMessagePayloadSize` and returns the `Message` itself as the ticket — no `Fee` is computed or returned, unlike V1's `send_message_impl.rs`/`calculate_fee`. [1](#0-0) 

The `fee` field stored in `Message` comes straight from `extract_remote_fee`, which reads the `PayFees` asset amount attached by the user in their own XCM, only checking that it is Ether and that the reserved amount covers it — not that it covers any real execution cost. [2](#0-1) [3](#0-2) [4](#0-3) 

`EthereumBlobExporter::validate` (the entry point from XCM) calls `converter.convert()` and then `OutboundQueue::validate(&message)`, with no fee-floor check inserted anywhere in this path. [5](#0-4) 

`do_process_message` in the pallet takes the decoded `fee` unmodified and stores it into `PendingOrder{fee, ...}`, with the real per-command gas computed via `T::GasMeter::maximum_dispatch_gas_used_at_most`, but there is no comparison between `fee` and the computed `gas`/cost anywhere in this function. [6](#0-5) 

For `Command::CallContract`, `ConstantGasMeter::maximum_dispatch_gas_used_at_most` returns `*gas_limit` directly from user input, unlike the other commands which use protocol-fixed constants. [7](#0-6) 

I checked the other plausible enforcement points: `snowbridge_pallet_system_v2::Pallet` (governance-only extrinsics such as `upgrade`/`set_operating_mode`/`register_token`, not a path for unprivileged user transfers) has no fee-floor logic, and `PausableExporter`/`EthereumBlobExporter` only check pause state and message structure, not fee adequacy. [8](#0-7) [9](#0-8)  No enforcement point exists in the reachable path from an unprivileged user's XCM through `EthereumBlobExporter` → `XcmConverter::convert` → `OutboundQueue::validate`/`deliver` → `do_process_message`.

## Impact Explanation
Because admission has no fee floor, an unprivileged user can submit `CallContract` (or other-command) messages with `fee = 0` or negligible amounts, each consuming one of the fixed `MaxMessagesPerBlock` slots enforced in `do_process_message`'s `Yield` check. [10](#0-9)  Relayers are paid from `order.fee` in `process_delivery_receipt` (only if `order.fee > 0`), so there is no incentive to relay zero/low-fee messages; they remain in `PendingOrders` indefinitely, and each such message still occupies committing capacity and MessageLeaves/Messages storage per block, degrading throughput available to legitimately-priced bridge traffic. [11](#0-10)  This matches the impact gate's "public underpriced work that degrades block production or stalls bridge processing."

## Likelihood Explanation
This is reachable by any unprivileged user constructing a valid XCM through the standard `ExportMessage`/`InitiateTransfer`-style path to Bridge Hub, requiring no relayer, validator, or governance action — only that the caller can produce a valid `WithdrawAsset`/`PayFees`/`AliasOrigin`/`DepositAsset`/`SetTopic` sequence recognized by `XcmConverter::convert`, which is exactly the mechanism ordinary users use to bridge to Ethereum. [12](#0-11)  No additional privileged step is needed, and the attack is trivially repeatable across blocks.

## Recommendation
Reinstate an on-chain fee floor for V2 analogous to V1's `calculate_fee`: in `do_process_message` (or earlier, in `validate`), compute a minimum required fee from `T::GasMeter::maximum_dispatch_gas_used_at_most(command)` — capping/bounding the user-supplied `gas_limit` for `Command::CallContract` to a governance-set maximum — multiplied by a governance-controlled `fee_per_gas`/pricing parameter, and reject the message with `ensure!(fee >= min_fee, ...)` if the attached `fee` (or `fee_amount` from the XCM) is insufficient, mirroring the protection that already exists in the V1 outbound queue.

## Proof of Concept
1. An attacker submits an XCM to Asset Hub containing `WithdrawAsset`, `PayFees` with a negligible/zero fee amount, `AliasOrigin`, `DepositAsset`, a `Transact` encoding `ContractCall::V1` with a large `gas` value, and `SetTopic`.
2. `XcmConverter::convert` extracts `fee_amount` from the negligible `PayFees` asset and builds a `Command::CallContract { gas, ... }` with the attacker's `gas` value, with no check that `fee_amount` covers `gas`. [13](#0-12) 
3. `EthereumBlobExporter::validate` calls `OutboundQueue::validate(&message)`, which only checks payload size and accepts the ticket. [1](#0-0) 
4. `deliver` enqueues the message; `do_process_message` decodes it, computes `gas = T::GasMeter::maximum_dispatch_gas_used_at_most(&command)` (equal to the attacker's `gas_limit`), and stores `PendingOrder{fee: 0-or-negligible, ...}`, consuming one `MaxMessagesPerBlock` slot. [14](#0-13) 
5. Repeating this across blocks fills committing capacity with unprofitable messages that no rational relayer delivers (since `process_delivery_receipt` pays `order.fee`, here ~0), leaving them stuck in `PendingOrders` and degrading throughput for legitimately-priced messages.

	fn extract_remote_fee(&mut self) -> Result<u128, XcmConverterError> {
		use XcmConverterError::*;
		let reserved_fee_assets = match_expression!(self.next()?, WithdrawAsset(fee), fee)
			.ok_or(WithdrawAssetExpected)?;
		ensure!(reserved_fee_assets.len() == 1, AssetResolutionFailed);
		let reserved_fee_asset =
			reserved_fee_assets.inner().first().cloned().ok_or(AssetResolutionFailed)?;
		let (reserved_fee_asset_id, reserved_fee_amount) = match reserved_fee_asset {
			Asset { id: asset_id, fun: Fungible(amount) } => Ok((asset_id, amount)),
			_ => Err(AssetResolutionFailed),
		}?;
		let fee_asset =
			match_expression!(self.next()?, PayFees { asset: fee }, fee).ok_or(InvalidFeeAsset)?;
		let (fee_asset_id, fee_amount) = match fee_asset {
			Asset { id: asset_id, fun: Fungible(amount) } => Ok((asset_id, *amount)),
			_ => Err(AssetResolutionFailed),
		}?;
		// Check the fee asset is Ether (XCM is evaluated in Ethereum context).
		ensure!(fee_asset_id.0 == Here.into(), InvalidFeeAsset);
		ensure!(reserved_fee_asset_id.0 == Here.into(), InvalidFeeAsset);
		ensure!(reserved_fee_amount >= fee_amount, InvalidFeeAsset);
		Ok(fee_amount)
	}

	pub fn convert(&mut self) -> Result<Message, XcmConverterError> {
		// Get fee amount
		let fee_amount = self.extract_remote_fee()?;

		// Get ENA reserve asset from WithdrawAsset.
		let mut enas =
			match_expression!(self.peek(), Ok(WithdrawAsset(reserve_assets)), reserve_assets);
		if enas.is_some() {
			let _ = self.next();
		}

		// Get PNA reserve asset from ReserveAssetDeposited
		let pnas = match_expression!(
			self.peek(),
			Ok(ReserveAssetDeposited(reserve_assets)),
			reserve_assets
		);
		if pnas.is_some() {
			let _ = self.next();
		}

		// Try to get ENA again if it is after PNA
		if enas.is_none() {
			enas =
				match_expression!(self.peek(), Ok(WithdrawAsset(reserve_assets)), reserve_assets);
			if enas.is_some() {
				let _ = self.next();
			}
		}
		// Check AliasOrigin.
		let origin_location = match_expression!(self.next()?, AliasOrigin(origin), origin)
			.ok_or(AliasOriginExpected)?;

		// Validate the AliasOrigin using the configured AllowedAliasOrigin filter.
		// This provides a mechanism for the runtime to restrict which origins
		// are permitted to alias, providing defense-in-depth against
		// unprivileged alias attempts.
		ensure!(AllowedAliasOrigin::contains(origin_location), InvalidOrigin);

		let origin = AgentIdOf::convert_location(origin_location).ok_or(InvalidOrigin)?;

		let (deposit_assets, beneficiary) = match_expression!(
			self.next()?,
			DepositAsset { assets, beneficiary },
			(assets, beneficiary)
		)
		.ok_or(DepositAssetExpected)?;

		// assert that the beneficiary is AccountKey20.
		let recipient = match_expression!(
			beneficiary.unpack(),
			(0, [AccountKey20 { network, key }])
				if self.network_matches(network),
			H160(*key)
		)
		.ok_or(BeneficiaryResolutionFailed)?;

		let mut commands: Vec<Command> = Vec::new();

		// ENA transfer commands
		if let Some(enas) = enas {
			commands.append(&mut self.extract_ethereum_native_assets(
				enas,
				deposit_assets,
				recipient,
			)?);
		}

		// PNA transfer commands
		if let Some(pnas) = pnas {
			commands.append(&mut self.extract_polkadot_native_assets(
				pnas,
				deposit_assets,
				recipient,
			)?);
		}

		// Transact commands
		let transact_call = match_expression!(self.peek(), Ok(Transact { call, .. }), call);
		if let Some(transact_call) = transact_call {
			let _ = self.next();
			let transact =
				ContractCall::decode_all(&mut transact_call.clone().into_encoded().as_slice())
					.map_err(|_| TransactDecodeFailed)?;
			match transact {
				ContractCall::V1 { target, calldata, gas, value } => commands
					.push(Command::CallContract { target: target.into(), calldata, gas, value }),
			}
		}

		ensure!(commands.len() > 0, NoCommands);

		// ensure SetTopic exists
		let topic_id = match_expression!(self.next()?, SetTopic(id), id).ok_or(SetTopicExpected)?;

		let message = Message {
			id: (*topic_id).into(),
			origin,
			fee: fee_amount,
			commands: BoundedVec::try_from(commands).map_err(|_| TooManyCommands)?,
		};

		// All xcm instructions must be consumed before exit.
		if self.next().is_ok() {
			return Err(EndOfXcmMessageExpected);
		}

		Ok(message)
	}

impl GasMeter for ConstantGasMeter {
	fn maximum_dispatch_gas_used_at_most(command: &Command) -> u64 {
		match command {
			Command::SetOperatingMode { .. } => 40_000,
			Command::Upgrade { initializer, .. } => {
				// total maximum gas must also include the gas used for updating the proxy before
				// the the initializer is called.
				50_000 + initializer.maximum_required_gas
			},
			Command::UnlockNativeToken { .. } => 200_000,
			Command::RegisterForeignToken { .. } => 1_200_000,
			Command::MintForeignToken { .. } => 100_000,
			Command::CallContract { gas: gas_limit, .. } => *gas_limit,
		}
	}
}
