The nonce namespace is per-`account_id`, not per-`(account_id, public_key)`. `Account` stores a single `nonces: MaybeLegacyAccountNonces` field keyed only by `account_id`, entirely independent from `public_keys`/`public_keys_added` sets [1](#0-0) . `commit_nonce` is invoked in `execute_signed_intent` after `has_public_key` validates the specific key, but it operates purely on `signer_id` and writes to that account's single nonce bitmap, with no reference to which key produced the signature [2](#0-1) . The underlying `Nonces::commit` sets a bit in a `BitMap256` and returns `DefuseError::NonceUsed` if already set, regardless of caller identity [3](#0-2) . Both the production `Contract::commit_nonce` and the `CachedState::commit_nonce` implementations look up the account solely by `account_id` before delegating to the same per-account nonce store [4](#0-3) [5](#0-4) .

Since `add_public_key` only mutates the `public_keys` set on the same `Account` object and never touches or namespaces `nonces` [6](#0-5) , adding a second key to an account does not create a new nonce namespace. Committing nonce `N` under key A sets the bit for `N` on that account; a subsequent attempt to commit the same `N` under key B for the same `account_id` reads the same bitmap, finds the bit already set, and returns `Err(DefuseError::NonceUsed)`. The binding `commit_nonce(signer_id, N)` success count == 1 regardless of which public key signed holds correctly in the code as written; there is no bug allowing the nonce to settle once per key.
