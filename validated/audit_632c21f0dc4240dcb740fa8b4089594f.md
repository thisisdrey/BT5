### Title
Unauthenticated `/shutdown` endpoint permanently kills the signer's event-receiver loop - ([File: libsigner/src/events.rs])

### Summary
The `SignerEventReceiver::next_event` handler treats any HTTP POST to `/shutdown` as a valid termination command with no signature, secret, or origin check. Any remote party able to reach the signer's event-receiver TCP port can send a single crafted POST request to permanently stop the signer's `main_loop`, halting all future block-proposal validation responses and StackerDB message processing.

### Finding Description
The intended equality is: "the party authorized to halt the signer's event loop" == "the local node operator/co-located Stacks node process." The code breaks this equality. In [1](#0-0) , the branch handling `request.url() == "/shutdown"` unconditionally executes `event_receiver.stop_signal.store(true, Ordering::SeqCst); Err(EventError::Terminated)` with no check of any secret, signature, or peer identity — unlike the legitimate stop path via `SignerStopSignaler::send`, which is only reachable from in-process code holding the `Arc<AtomicBool>` (see [2](#0-1) ) but which itself works simply by POSTing to `/shutdown` over the loopback-reachable TCP listener — i.e., the "authorization" for this action is nothing more than "can open a TCP connection and speak minimal HTTP to this port," which any remote attacker with network reachability also satisfies.

`Err(EventError::Terminated)` is then caught in `EventReceiver::main_loop` at [3](#0-2) , which breaks out of the loop, ending the event-receiver thread for good. Since `is_stopped()` reads the same `stop_signal` ( [4](#0-3) ), the receiver will also refuse further work if a request slips in before the thread fully exits. This endpoint requires no `Content-Type`, no body validation, and no auth header — the sample legitimate caller itself sends only a plain HTTP POST with an arbitrary text body ( [5](#0-4) ), confirming there is no secret embedded in the request that a remote attacker could not trivially replicate.

None of the existing guards apply here: `MAX_MESSAGE_LEN`/payload caps and `process_event`'s JSON deserialization checks ( [6](#0-5) ) are irrelevant because the `/shutdown` path never calls `process_event` at all — it short-circuits before any payload parsing or validation.

### Impact Explanation
Once triggered, the signer's event-receiver thread exits permanently; the signer no longer receives `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, or `/new_block` events pushed by its co-located Stacks node. This effectively takes the signer offline for block proposal validation and StackerDB gossip participation until an operator manually restarts the process — a single unauthenticated POST causes complete denial of service, matching the "Critical - remote crash/unauthenticated DoS from few messages" category. Repeated exploitation simply requires resending the same POST after each restart.

### Likelihood Explanation
The only precondition is TCP reachability to the signer's configured event-receiver bind address/port from a peer that is not the local Stacks node. The stacks-signer crate itself acknowledges this exposure risk in its startup warning at [7](#0-6) , which explicitly cautions operators about exposing this endpoint to untrusted networks — confirming there is no built-in authentication and that reachability from outside localhost is a real, anticipated operational configuration risk. Attacker cost is a single raw HTTP POST; no cryptographic material, StackerDB slot ownership, or privileged role is needed.

### Recommendation
Require the `/shutdown` (and ideally all node→signer event) endpoints to authenticate the caller, e.g., via a shared secret/HMAC header configured between the Stacks node and signer, or restrict `bind()` to loopback-only and document/enforce that the listener must never be exposed beyond localhost or a firewalled private link. At minimum, gate the `/shutdown` branch in `next_event` on a pre-shared token compared in constant time.

### Proof of Concept
Rust test (analogous to existing `test_status_endpoint` in `libsigner/src/tests/mod.rs`):
1. Spawn a `Signer` with `SignerEventReceiver::new(false)` bound to a local test port via `signer.spawn(endpoint)`.
2. From a separate `TcpStream::connect(endpoint)` (simulating a remote attacker, not the node), send:
   `POST /shutdown HTTP/1.1\r\nHost: <endpoint>\r\nConnection: close\r\nContent-Length: 4\r\n\r\ntest`
3. Assert that `running_signer.stop()` join completes quickly (event thread already exited) or, more directly, call `SignerEventReceiver::next_event()` in a unit test after simulating the same raw request against `http_server`, asserting it returns `Err(EventError::Terminated)` and that `receiver.is_stopped()` is `true` — with no credentials supplied anywhere in the request, mirroring the assertion structure already used in `test_status_endpoint` ( [8](#0-7) ).

fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}

#[test]
fn test_status_endpoint() {
    let ev = SignerEventReceiver::new(false);
    let (res_send, _res_recv) = channel();
    let max_events = 1;
    let mut signer = Signer::new(SimpleRunLoop::new(max_events), ev, res_send);
    let endpoint: SocketAddr = "127.0.0.1:31000".parse().unwrap();

    // Spawn the signer first so the HTTP server is listening before the mock client connects
    let running_signer = signer.spawn(endpoint).unwrap();

    // simulate a node that's trying to push data
    let mock_stacks_node = thread::spawn(move || {
        let mut sock = TcpStream::connect(endpoint).unwrap();
        let req = format!("GET /status HTTP/1.1\r\nHost: {endpoint}\r\nConnection: close\r\n\r\n");

        sock.write_all(req.as_bytes()).unwrap();
        let mut buf = [0; 128];
        let _ = sock.read(&mut buf).unwrap();
        let res_str = std::str::from_utf8(&buf).unwrap();
        let expected_status_res = "HTTP/1.1 200 OK\r\n";
        assert_eq!(expected_status_res, &res_str[..expected_status_res.len()]);
        sock.flush().unwrap();
    });
    sleep_ms(3000);
    let accepted_events = running_signer.stop().unwrap();

    let sent_events: Vec<SignerEvent<SignerMessage>> = vec![SignerEvent::StatusCheck];

    assert_eq!(sent_events, accepted_events);
    mock_stacks_node.join().unwrap();
}
