Audit Report

## Title
Reward payout marks era page as claimed even when the underlying token transfer to the payee silently fails, permanently losing staker/validator rewards - (File: substrate/frame/staking-async/src/pallet/impls.rs)

## Summary
`do_payout_stakers_by_page` calls `Eras::<T>::set_rewards_as_claimed(era, &stash, page)` before performing any actual token transfers, and explicitly documents that "no errors allowed after this point." The subsequent transfer-based payout functions, `make_payout_from_provider` and `transfer_validator_incentive`, swallow any `T::Currency::transfer` failure by logging it and returning `None`/emitting an informational event, never propagating a `DispatchError`. As a result, a payee whose transfer fails (e.g., due to `Preservation::Expendable` rejecting a sub-existential-deposit credit to a reaped/zero-provider account) permanently loses that reward while the page is irrevocably marked claimed.

## Finding Description
In `do_payout_stakers_by_page`, the claim-tracking state is committed at `Eras::<T>::set_rewards_as_claimed(era, &stash, page)` prior to computing or transferring any rewards, with the code comment "Input data seems good, no errors allowed after this point" confirming that failures downstream cannot cause the extrinsic to fail. The actual transfers happen later via `payout_from_provider`, which calls `make_payout_from_provider` for the validator and each nominator in a loop; on any individual transfer failure, `make_payout_from_provider` logs an error and returns `None`, and the caller only uses the `Some`/`None` result to decide whether to emit a `Rewarded` event, never aborting or reverting. `transfer_validator_incentive` behaves identically for the validator incentive pot, converting a failed transfer into a `defensive!` log, an `Unexpected`-style event, and a `return`, again without affecting the overall dispatch result. Because `Preservation::Expendable` is used, crediting an amount below the existential deposit to an account with zero provider references is rejected by the balances pallet, which is a realistic, attacker-uninvolved condition for small nominator rewards or reaped accounts. Once the page is marked claimed, `AlreadyClaimed` blocks any future retry for that (era, validator, page), and the leftover pot balance is eventually swept by `EraRewardManager::drain` to `T::UnclaimedRewardHandler` once `HistoryDepth` expires, never reaching the rightful payee.

## Impact Explanation
This is a permanent, unbacked loss of legitimately earned staking rewards for the affected beneficiary, matching the "payout state must only advance after ... settlement succeed[s] atomically" and "conserve value and settle exactly once to the rightful beneficiary" pivots. The claimed-state advances unconditionally regardless of whether the currency transfer that constitutes the actual settlement succeeded, and the pallet provides no per-payee retry or recovery mechanism — the stranded funds are ultimately drained to a handler account rather than refunded to the affected staker/validator.

## Likelihood Explanation
No privileged access or malicious behavior is required. Any account-lifecycle condition that causes `T::Currency::transfer(..., Preservation::Expendable)` to fail — most plausibly a small/dust reward destined for a fully reaped account with zero providers, or any other legitimate transfer rejection — triggers this path. `payout_stakers`/`payout_stakers_by_page` are public extrinsics callable by anyone for any (era, validator, page) within `HistoryDepth`, making this readily and repeatedly reachable in a live network with many small nominators.

## Recommendation
Do not mark `ClaimedRewards` for a page until every transfer attempted within it has succeeded, or defer the claim-marking until after `payout_from_provider`/`payout_legacy_mint` complete and propagate any transfer failure as a `DispatchError` rather than converting it to `None`. Alternatively, maintain a per-payee pending/failed record enabling a future retry or an explicit withdrawal path for the affected account, instead of allowing `EraRewardManager::drain` to sweep the stranded balance to `UnclaimedRewardHandler`.

## Proof of Concept
1. Nominator `S` has `RewardDestination::Account(A)` where `A` has zero free balance and zero provider references.
2. For era `E`/page `P`, `S`'s computed `nominator_reward` is smaller than the existential deposit.
3. Any account calls `payout_stakers_by_page(validator_stash, E, P)`.
4. `do_payout_stakers_by_page` immediately calls `Eras::<T>::set_rewards_as_claimed(E, &validator_stash, P)` at substrate/frame/staking-async/src/pallet/impls.rs:386, before any transfers occur.
5. Later, `payout_from_provider` → `make_payout_from_provider` calls `T::Currency::transfer(&staker_rewards_pot, &A, nominator_reward, Preservation::Expendable)`, which fails because `A` cannot be credited below ED with zero providers.
6. The error is logged, `None` is returned, no `Rewarded` event is emitted for `A`, but the extrinsic still returns `Ok(...)`.
7. A subsequent call to `payout_stakers_by_page` for the same `(E, validator_stash, P)` returns `Error::<T>::AlreadyClaimed`, permanently blocking recovery; `nominator_reward` remains in the era pot until swept by `EraRewardManager::drain` to `T::UnclaimedRewardHandler`.

	fn make_payout_from_provider(
		era: EraIndex,
		stash: &T::AccountId,

	/// Drains an era pot's remaining balance to the unclaimed reward handler.
	///
	/// The pot account itself is kept alive (provider retained) so the same slot
	/// can be reused by a future era. No-op if the pot was never created (e.g.
	/// the era ran in legacy minting mode).
	pub(crate) fn drain(era: EraIndex, kind: RewardKind) {
		let pot_account = T::RewardPots::pot_account(RewardPot::Era(era, kind));

		// Skip if pot was never created (legacy mode doesn't create pots).
		if frame_system::Pallet::<T>::providers(&pot_account) == 0 {
			return;
		}

		let remaining = T::Currency::balance(&pot_account);

		if remaining.is_zero() {
			return;
		}

		match T::Currency::withdraw(
			&pot_account,
			remaining,
			Precision::BestEffort,
			Preservation::Expendable,
			Fortitude::Force,
		) {
			Ok(credit) => {
				T::UnclaimedRewardHandler::on_unbalanced(credit);

					debug,

					remaining,
					era,
					kind
				);
			},
			Err(e) => {
				defensive!("Failed to withdraw unclaimed rewards from era pot");
				log!(
					error,
					"Era {:?} {:?}: unclaimed reward withdrawal failed: {:?}",
					era,
					kind,
					e
				);
			},
		}
	}
