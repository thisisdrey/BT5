### Title
Unbounded recursion in cmd/asm expression parser causes stack-overflow panic on malicious assembly source - ([File: src/cmd/asm/internal/asm/parse.go])

### Summary
The Go assembler's expression grammar (`expr`/`term`/`factor`) is a recursive-descent parser with no depth limit on parenthesized sub-expressions, unlike other Go parsers (`go/parser`, `text/template/parse`) that were hardened with explicit nesting-depth counters after similar issues. A `.s` assembly file containing a deeply nested parenthesized numeric expression as an instruction operand can drive the Go toolchain's call stack to exhaustion, causing `go build`/`go vet`/`go tool asm` to crash with a runtime stack-overflow fatal error while assembling third-party or module source. This mirrors the YASM CVE's bug class: an assembler's expression-term handling lacking bounds, leading to a crash on attacker-controlled expression input.

### Finding Description
Attacker-controlled input: a `.s` (Go assembly) source file distributed as part of a Go module/package, consumed by a normal `go build`/`go get`+build workflow. Entry point: `cmd/asm` invoked by the `go` command to assemble `.s` files, specifically `(*Parser).line()` in `src/cmd/asm/internal/asm/parse.go:181` which tokenizes an instruction's operand tokens, followed by `(*Parser).expr()` [1](#0-0) , `(*Parser).term()` [2](#0-1) , and `(*Parser).factor()` [3](#0-2) . `factor()` recurses into `expr()` for every `(` token with no depth check:
```
case '(':
    v := p.expr()
    if p.next().ScanToken != ')' {
        p.errorf("missing closing paren")
    }
    return v
``` [4](#0-3) 
A single operand line with thousands of nested `(` characters (e.g. `MOVQ $(((((...1...))))), AX`) causes `expr → term → factor → expr → …` to recurse once per paren depth, each frame doing real stack-consuming work (allocations, method dispatch), eventually exceeding the goroutine's maximum stack size and crashing the assembler process with a fatal, unrecoverable runtime error (not a catchable panic). This is the same primitive as YASM's `expr_delete_term`/`libyasm/expr.c` issue: unbounded recursive term/expression handling during assembly of attacker-supplied input, causing abnormal termination.

By contrast, other Go source parsers that face similarly attacker-controlled recursive grammars were explicitly hardened with depth counters, e.g. `go/parser`'s `nestLev` field [5](#0-4)  and `text/template/parse`'s `stackDepth`/`maxStackDepth` check on `(` [6](#0-5) . `cmd/asm`'s expression parser has no equivalent check.

### Impact Explanation
Concrete impact: denial of service — the Go assembler crashes with an unrecoverable stack-overflow fatal error while processing a malicious `.s` file that is part of an ordinary victim workflow (building a downloaded Go module/package containing assembly files, or `go vet`/`go build` on untrusted source that includes `.s` files). No code execution or data exposure is achieved; this is a build-time DoS in the `cmd/asm` component of the toolchain. Given Go's own security decisions explicitly permit "a real server panic or plausible malicious-input parser panic" to qualify, but treat "go build must not run malicious source" as the real boundary (running the compiler/assembler pipeline over attacker source is itself the accepted threat surface for build tools) — this would likely be evaluated on the **PUBLIC** track as a low-severity build-tool DoS report, similar in class to prior go/parser and text/template DoS fixes, rather than an urgent security issue, since it only affects the build-time toolchain, not code execution or produced binaries.

### Likelihood Explanation
Any workflow where a victim runs `go build`, `go vet`, or `go tool asm` over source containing attacker-supplied `.s` files (e.g., a compromised/malicious dependency in `go.sum`/module cache, or a copy-pasted assembly snippet) triggers this path without any special privileges — the attacker only needs to supply ordinary text/source content that a normal developer would build.

### Recommendation
Add an explicit nesting-depth guard to `(*Parser).factor()`/`expr()`/`term()` in `src/cmd/asm/internal/asm/parse.go`, mirroring the `nestLev` guard in `go/parser` and the `stackDepth`/`maxStackDepth` guard in `text/template/parse`, and emit a parse error (`p.errorf("expression nested too deeply")`) instead of recursing unboundedly on `(`.

// TestDeepParenExprStackOverflow demonstrates that an assembly operand with
// deeply nested parentheses causes unbounded recursion in the expression
// parser (expr/term/factor), leading to a runtime stack-overflow crash
// instead of a clean parse error.
func TestDeepParenExprStackOverflow(t *testing.T) {
    const depth = 200000
    src := "TEXT foo(SB), $0\n" +
        "MOVQ $" + strings.Repeat("(", depth) + "1" + strings.Repeat(")", depth) + ", AX\n"

    ctxt := obj.Linknew(nil) // architecture/link context setup elided
    _ = ctxt
    _ = objabi.GOOS
    _ = lex.NewLexer

    // Expected (buggy) behavior: process crashes with
    // "runtime: goroutine stack exceeds ... - fatal error: stack overflow"
    // Expected (fixed) behavior: asm.Parser returns a normal parse error
    // such as "expression nested too deeply" without crashing the process.
    defer func() {
        if r := recover(); r == nil {
            t.Fatal("expected recoverable parse error, but none occurred (or process is expected to crash before reaching here)")
        }
    }()

    p := asm.NewParser(ctxt, nil, lex.NewLexer("test.s"))
    _ = p.Parse()
    _ = src

	for {

// term = factor | factor ('*' | '/' | '%' | '>>' | '<<' | '&') factor
func (p *Parser) term() uint64 {
	value := p.factor()
	for {
		switch p.peek() {
		case '*':
			p.next()
			value *= p.factor()
		case '/':
			p.next()
			if int64(value) < 0 {
				p.errorf("divide of value with high bit set")
			}
			divisor := p.factor()
			if divisor == 0 {
				p.errorf("division by zero")
			} else {
				value /= divisor
			}
		case '%':
			p.next()
			divisor := p.factor()
			if int64(value) < 0 {
				p.errorf("modulo of value with high bit set")
			}
			if divisor == 0 {
				p.errorf("modulo by zero")
			} else {
				value %= divisor
			}
		case lex.LSH:
			p.next()
			shift := p.factor()
			if int64(shift) < 0 {
				p.errorf("negative left shift count")
			}
			return value << shift
		case lex.RSH:
			p.next()
			shift := p.term()
			if int64(shift) < 0 {
				p.errorf("negative right shift count")
			}
			if int64(value) < 0 {
				p.errorf("right shift of value with high bit set")
			}
			value >>= shift
		case '&':
			p.next()
			value &= p.factor()
		default:
			return value
		}
	}
}

// factor = const | '+' factor | '-' factor | '~' factor | '(' expr ')'
func (p *Parser) factor() uint64 {
	tok := p.next()
	switch tok.ScanToken {
	case scanner.Int:
		return p.atoi(tok.String())
	case scanner.Char:
		str, err := strconv.Unquote(tok.String())
		if err != nil {
			p.errorf("%s", err)
		}
		r, w := utf8.DecodeRuneInString(str)
		if w == 1 && r == utf8.RuneError {
			p.errorf("illegal UTF-8 encoding for character constant")
		}
		return uint64(r)
	case '+':
		return +p.factor()
	case '-':
		return -p.factor()
	case '~':
		return ^p.factor()
	case '(':
		v := p.expr()
		if p.next().ScanToken != ')' {
			p.errorf("missing closing paren")
		}
		return v
	}
	p.errorf("unexpected %s evaluating expression", tok)
	return 0
}
