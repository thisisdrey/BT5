Audit Report

## Title
Incomplete `on_withdraw` notification in `do_withdraw_unbonded` leaves nomination-pools' `TotalValueLocked` permanently stale when the ledger is killed - (File: `substrate/frame/staking/src/pallet/impls.rs`)

## Summary
`do_withdraw_unbonded` computes `value = old_total - new_total` for the `on_withdraw` notification purely from the balance removed by `consolidate_unlocked`, but when the remaining `ledger.active` is below the existential deposit (or zero) with no unlocking chunks left, `kill_stash` destroys that entire remaining `new_total` without it ever being included in the notification. Since `pallet-nomination-pools`' `TotalValueLocked` is decremented solely via the `on_withdraw` hook, this residual dust amount is never subtracted, permanently inflating `TotalValueLocked` relative to the pool's real staked balance.

## Finding Description
The code at `substrate/frame/staking/src/pallet/impls.rs:193-233` shows the exact flow: `old_total` is captured before `consolidate_unlocked`; `new_total = ledger.total` is captured after consolidation (which still includes the leftover dust `active` balance, since consolidation only removes matured `unlocking` chunks). If `ledger.unlocking.is_empty()` and `ledger.active < ed` (or zero), `Self::kill_stash(&ledger.stash, num_slashing_spans)` is invoked, which via `Ledger::kill` removes the `Ledger`, `Bonded`, and `Payee` entries and clears the stake lock — fully destroying `new_total` worth of staked balance: [1](#0-0) 

The notification logic afterward only computes `value = old_total - new_total` and fires `on_withdraw(controller, value)` — i.e., only the amount consolidated out of `unlocking`, not the additionally destroyed `new_total` dust from `kill_stash`. This exact code (including the `if ledger.unlocking.is_empty() && (ledger.active < ed || ledger.active.is_zero())` kill branch and the unconditional `if new_total < old_total { ... on_withdraw(...) }` notification using only `old_total - new_total`) is present verbatim in the repository, confirming the described root cause.

`pallet-nomination-pools` defines `on_withdraw` in `substrate/frame/nomination-pools/src/lib.rs` and uses it to decrement `TotalValueLocked`, with no independent reconciliation path once a ledger is deleted — so any amount destroyed by `kill_stash` but excluded from the notification is permanently unaccounted for.

## Impact Explanation
`TotalValueLocked` is a cached, protocol- and user-facing invariant intended as an upper bound on the sum of all pool members' balances. This bug causes it to permanently overstate the pool's true staked balance whenever a bonded stash (including nomination-pools' own bonded pool accounts) is killed with non-zero pre-kill dust that was previously counted toward TVL. This falls within the "runtime bugs that compromise intended behavior" and "permanent... state lock/corruption of a documented accounting invariant" category of the impact gate, since the drift is irreversible and accumulates over time across many pools/unbonding cycles, degrading the correctness of any downstream logic (fee calculation, pool health checks, TVL-gated features) relying on this value.

## Likelihood Explanation
This is reachable via the ordinary, unprivileged `withdraw_unbonded` extrinsic (or a pool's `withdraw_unbonded`/`pool_withdraw_unbonded` calling into `do_withdraw_unbonded`), requiring no privileged origin, malicious peer, or governance action — only that a staker's active balance falls below the existential deposit with all `unlocking` chunks matured/consolidated. This is a common, deterministic real-world scenario (e.g., a nomination-pool member fully unbonding such that the pool's bonded stash or an individual stash ends up dusted), making the issue systemic and repeatable rather than a rare edge case.

## Recommendation
When the `kill_stash` branch is taken in `do_withdraw_unbonded`, the value passed to `on_withdraw` (and the `Withdrawn` event) should reflect the entire remaining `total` being destroyed, not just `old_total - new_total`. Concretely, compute the notified value as the full pre-withdrawal `old_total` (i.e., treat the post-kill total as `0`) whenever `kill_stash` executes, ensuring `TotalValueLocked` is decremented by the complete amount released in that call.

## Proof of Concept
1. Create a nomination pool; have a member fully unbond such that the pool's bonded stash's `active` balance after unbonding is below `ExistentialDeposit`, with the unlocking chunk eligible to mature.
2. Advance eras until the unlocking chunk matures (so `consolidate_unlocked` empties `unlocking`), leaving `ledger.active` as dust below ED and `new_total == ledger.active` (nonzero).
3. Record `TotalValueLocked::<T>::get()` before calling `withdraw_unbonded`.
4. Call `withdraw_unbonded`; observe `kill_stash` executes (destroying the dust `active` balance and lock), but `on_withdraw` is only invoked with `old_total - new_total` (the previously-unlocking amount), excluding the dust `new_total`.
5. Compare `TotalValueLocked::<T>::get()` after the call — it remains higher than the pool's actual remaining staked balance (now zero) by exactly the unreported dust amount, demonstrating the permanent staleness of `TotalValueLocked`.

```rust
	pub(super) fn do_withdraw_unbonded(
		controller: &T::AccountId,
		num_slashing_spans: u32,
	) -> Result<Weight, DispatchError> {
		let mut ledger = Self::ledger(Controller(controller.clone()))?;
		let (stash, old_total) = (ledger.stash.clone(), ledger.total);
		if let Some(current_era) = CurrentEra::<T>::get() {
			ledger = ledger.consolidate_unlocked(current_era)
		}
		let new_total = ledger.total;

		let ed = asset::existential_deposit::<T>();
		let used_weight =
			if ledger.unlocking.is_empty() && (ledger.active < ed || ledger.active.is_zero()) {
				// This account must have called `unbond()` with some value that caused the active
				// portion to fall below existential deposit + will have no more unlocking chunks
				// left. We can now safely remove all staking-related information.
				Self::kill_stash(&ledger.stash, num_slashing_spans)?;

				T::WeightInfo::withdraw_unbonded_kill(num_slashing_spans)
			} else {
				// This was the consequence of a partial unbond. just update the ledger and move on.
				ledger.update()?;

				// This is only an update, so we use less overall weight.
				T::WeightInfo::withdraw_unbonded_update(num_slashing_spans)
			};

		// `old_total` should never be less than the new total because
		// `consolidate_unlocked` strictly subtracts balance.
		if new_total < old_total {
			// Already checked that this won't overflow by entry condition.
			let value = old_total.defensive_saturating_sub(new_total);
			Self::deposit_event(Event::<T>::Withdrawn { stash, amount: value });

			// notify listeners.
			T::EventListeners::on_withdraw(controller, value);
		}

		Ok(used_weight)
	}
```
