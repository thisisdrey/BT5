## Title
Protocol fee on NEP‑245/IMT `TokenDiff` intents can be bypassed by splitting a trade into unit-sized deltas - (File: `contracts/defuse/core/src/intents/token_diff.rs`)

### Summary
`TokenDiff::token_fee` waives the protocol fee entirely whenever the `|delta|` of a single NEP-245 (`Nep245`) or IMT token in one `TokenDiff` intent is `<= 1`. Because the fee is evaluated per intent/per-token-delta rather than on the economic volume actually being traded, a signer can split what would otherwise be one large, fee-bearing `TokenDiff` into many separate `TokenDiff` intents that each move exactly `1` unit of the same NEP-245/IMT token. The aggregate trade volume and resulting balance change are identical to a single large `TokenDiff`, but the total protocol fee collected drops to zero. This is the same class of bug as the Astaria finding: two code paths that are supposed to enforce the same economic constraint (fee-on-volume) diverge once the "conversion" between "one big diff" and "N unit-sized diffs" is not 1:1 in terms of fee applied.

### Finding Description
`TokenDiff::execute_intent` computes fees per-token, per-intent, using `Self::token_fee(token_id, amount, protocol_fee).fee_ceil(amount)`, where `amount` is `delta.unsigned_abs()` of that single `TokenDiff`'s entry: [1](#0-0) 

`token_fee` explicitly zeroes the fee for `Nep245`/`Imt` token types whenever the amount involved is `<= 1`: [2](#0-1) 

The comment states the intent is "do not take fees on NFTs and MTs with `|delta| <= 1`" — reasonable for genuine NFT-like single-unit transfers, but NEP-245 (`nep245`) and IMT tokens are semi-fungible/fungible multi-tokens that can carry arbitrary quantities. There is no aggregation of deltas across intents in the same signed payload, nor across multiple signed payloads processed in the same `execute_intents` call: [3](#0-2) 

Each `Intent` (including each `TokenDiff`) in `DefuseIntents.intents` is dispatched and executed independently: [4](#0-3) 

Consequently, a user/solver wanting to move `N` units of a NEP-245/IMT token can either:
* submit **one** `TokenDiff` with `delta = -N` (or `+N`) — fee = `fee_ceil(N)` charged, or
* submit **N** `TokenDiff` intents, each with `delta = ±1` for the same token — fee = `0` on every single one, because `token_fee` sees `amount == 1` each time.

Both paths produce the exact same final balance change for the signer (and, in a swap, for the counterparty), but the fee owed to the protocol differs from `fee_ceil(N)` down to `0`. This mirrors the reported Astaria bug: two logically-equivalent ways to achieve the same balance delta (deposit vs. mint / one intent vs. many) are checked with different, non-equivalent rules, and the attacker simply picks the path that evades the constraint.

### Impact Explanation
This breaks the "fees owed versus fees collected" invariant explicitly called out as Critical impact: an unprivileged party (any signer, in particular a solver executing `TokenDiff` swaps) can systematically avoid the protocol fee on NEP-245/IMT token trades of any size by structuring their intents as a sequence of unit deltas instead of one aggregate delta. The fee collector (`engine.state.fee_collector()`) receives strictly less than intended, directly reducing protocol revenue with no counterbalancing cost to the attacker beyond needing to construct/sign more intents (which is cheap, since NEP-245/IMT multi-token balances and their deltas are ordinary state updates, not requiring extra transfers).

### Likelihood Explanation
Likelihood is high for any deployment that enables the `imt` feature or that has real trading volume in NEP-245-wrapped tokens (e.g. multi-token wrapped assets, or IMT-issued tokens) and that relies on `TokenDiff` protocol fees as a revenue source: solvers optimizing for their own P&L have a direct financial incentive to split trades into unit deltas, and doing so requires no special privilege — only the ability to sign and submit `DefuseIntents` normally available to every account.

### Recommendation
Do not key the fee exemption for NEP-245/IMT tokens off the `|delta|` of a single `TokenDiff` entry. Either:
- remove the amount-based exemption for `Nep245`/`Imt` entirely and rely solely on `TokenIdType::Nep171` (true 1-of-1 NFTs) for the fee-free path, or
- if a fee-free path for very small MT/IMT amounts is desired, aggregate deltas per `(token_id, signer_id)` across the whole batch of intents being executed (or track cumulative per-nonce/per-payload volume) before applying the exemption threshold, so that splitting a trade into many unit-sized intents cannot reduce the total fee below what a single equivalent-volume `TokenDiff` would have paid.

### Proof of Concept
Given `fee = Pips::ONE_PERCENT` and an NEP-245 token `mt.near:ft1`:

1. Single-intent trade: signer submits one `TokenDiff { diff: {mt_token: -1000, ft2: +X} }`. `token_fee` sees `amount = 1000 > 1` → normal `fee` applies, `fee_ceil(1000)` is deducted as protocol fee (see `token_fee` and `fee_ceil` at [2](#0-1)  and [5](#0-4) ).
2. Split-intent trade: signer instead submits 1000 separate `TokenDiff` intents (can be bundled into one or more `DefuseIntents` payloads and executed via `execute_intents`), each `{diff: {mt_token: -1, ft2: +x}}`. For every one of them, `token_fee` sees `amount == 1` → returns `Pips::ZERO`, so `fee_ceil(1) = 0` on each. Summed over the whole batch, total fee collected = `0`, versus `fee_ceil(1000)` in scenario 1, despite moving the identical aggregate amount of `mt_token` and the identical counter-asset.

This can be reproduced by extending the existing unit test scaffolding in `contracts/defuse/core/src/intents/token_diff.rs` (`closure_delta`/`closure_deltas_nonoverlapping` tests already exercise `Nep245TokenId` deltas) to compare `token_fee` output for one `TokenDiff` with `delta = -N` against `N` separate `TokenDiff`s with `delta = -1` each, and observing the aggregate fee mismatch.

    pub fn token_fee(token_id: impl Into<TokenIdType>, amount: u128, fee: Pips) -> Pips {
        let token_id = token_id.into();
        match token_id {
            TokenIdType::Nep141 => {}
            TokenIdType::Nep245 | TokenIdType::Imt if amount > 1 => {}
            // do not take fees on NFTs and MTs with |delta| <= 1
            TokenIdType::Nep171 | TokenIdType::Nep245 | TokenIdType::Imt => return Pips::ZERO,
        }
        fee
    }
