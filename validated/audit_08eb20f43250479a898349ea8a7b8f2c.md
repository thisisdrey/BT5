### Title
Unauthenticated forged `SignerEvent::MinerMessages` injection via missing chunk signature check in `.miners` StackerDB event path - (File: libsigner/src/events.rs)

### Summary
The `TryFrom<StackerDBChunksEvent> for SignerEvent<T>` implementation's `MINERS_NAME` branch deserializes `StackerDBChunkData.data` directly into a signer message without ever calling `chunk.recover_pk()` or `chunk.verify()`, unlike the parallel `SIGNERS_NAME` branch which explicitly recovers and checks the signer's public key. Any party able to reach the signer's bound event-receiver HTTP port can POST a crafted `StackerDBChunksEvent` for the `.miners` contract with an empty/garbage `sig` and have the signer runloop treat the payload as an authentic miner message.

### Finding Description

`StackerDBChunkData` itself carries a `sig: MessageSignature` field intended to authenticate `(slot_id, slot_version, data_hash)` against the slot owner's public key via `recover_pk()`/`verify()`, defined in `libstackerdb/src/libstackerdb.rs:233-244`. [4](#0-3)  The `MINERS_NAME` branch never invokes these checks, so an attacker's `sig` (even `MessageSignature::empty()`) is accepted unconditionally as long as `T::consensus_deserialize` succeeds on the attacker-supplied `data` bytes.

Exploit flow: attacker connects directly to the TCP port bound by `SignerEventReceiver::bind()` and issues an HTTP POST to `/stackerdb_chunks` with a JSON body encoding a `StackerDBChunksEvent{ contract_id: <boot .miners contract>, modified_slots: [StackerDBChunkData{ slot_id, slot_version, sig: MessageSignature::empty(), data: <attacker-crafted consensus-serialized SignerMessage> }] }`. This reaches `next_event` → URL match `/stackerdb_chunks` → `process_event::<T, StackerDBChunksEvent>` → the vulnerable `TryFrom` arm, producing `SignerEvent::MinerMessages(vec![<forged message>])` with no signature having been checked anywhere in this path.

### Impact Explanation
The signer runloop receives forged miner-authored messages (e.g., `BlockPushed`/`MockProposal` payloads, depending on `T`) as if they were legitimately signed and stored by a `.miners` slot owner. This is an unauthenticated write of attacker-controlled data into the signer's internal event stream, matching the "Critical - unauthenticated/unauthorized write to state" category. The attack is fully repeatable per TCP connection/POST and is bounded to whatever this specific signer instance's runloop does when consuming `MinerMessages` — it does not require compromising the P2P network, StackerDB replication, or any peer's key.

### Likelihood Explanation
- Preconditions: the signer's event-receiver TCP port (bound via `SignerEventReceiver::bind()`) must be reachable by the attacker; no localhost/firewall restriction is enforced in this code path itself.
- No signer/tip/reward-cycle state is required — this is a pure parsing/dispatch bug that fires regardless of chain state.
- No secret, key, or privileged role is needed; the attacker only needs a TCP connection and the ability to craft an HTTP POST with valid JSON matching `StackerDBChunksEvent`'s schema.
- Cost is trivial (single HTTP request), and it is repeatable indefinitely.

### Recommendation
In the `MINERS_NAME` branch of `TryFrom<StackerDBChunksEvent> for SignerEvent<T>`, require `chunk.verify(&expected_miner_addr)` (or equivalent `recover_pk()` + address/allow-list check against the current miner's registered key) before deserializing `chunk.data`, mirroring the `SIGNERS_NAME` branch's `recover_pk()` gate, and drop/skip chunks whose signature does not recover to an authorized signer.

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}
