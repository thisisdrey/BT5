## Analysis

I confirmed a genuine analog to the reported bug class in `LinkRepositoryToObjectPool`.

`internal/gitaly/service/objectpool/link.go` accepts an attacker/caller-controlled `ObjectPool.Repository.RelativePath` in the request and only validates it via `objectpool.FromProto`, which checks:
1. `storage.IsPoolRepository(proto.GetRepository())` — a **regex-based naming-convention check** (`internal/gitaly/storage/repository_path.go`), and
2. `pool.IsValid(ctx)` — merely confirms the target directory `locator.ValidateRepository` succeeds, i.e. it is *some* valid Git repository at that path. [1](#0-0) [2](#0-1) 

Neither check verifies that the supplied pool is the *legitimate* pool for the caller's fork/repository network — exactly the same class of flaw as the Solidity report, where a constructor trusted a supplied pool address by only checking token-format properties (`token0`/`token1`) instead of proving the pool's provenance (e.g. via factory `getPool()`). Here, Gitaly trusts any path that merely *looks like* a pool (matches `@pools/xx/yy/<sha256>.git` or the Praefect pool regex) and *is* a git repo, then unconditionally links the caller's repository to it: [3](#0-2) 

`objectpool.Link` then writes that pool's relative path into the caller's `objects/info/alternates` file, making all of the pool's objects visible to the linked repository via `git cat-file`, fetch, etc.: [4](#0-3) 

### Title
Object pool legitimacy is verified only by naming convention, not by provenance, in `LinkRepositoryToObjectPool` - (File: internal/git/objectpool/pool.go)

### Summary
`LinkRepositoryToObjectPool` links a caller-specified repository to a caller-specified `ObjectPool`. The only validation performed on the supplied pool is that its relative path matches a regex naming pattern (`IsPoolRepository`) and that a valid Git repository exists there (`IsValid`/`ValidateRepository`). There is no check that the object pool is actually the pool that belongs to the caller's fork network / origin repository. This mirrors the reported Solidity issue where a pool's legitimacy was inferred from superficial properties of the object rather than being cryptographically/structurally tied to its claimed origin.

### Finding Description
`objectpool.FromProto` (`internal/git/objectpool/pool.go:46-91`) resolves the pool purely from the `StorageName`/`RelativePath` given in the request, and validates it with:
- `storage.IsPoolRepository()` — a regex match against `@pools/xx/yy/<sha>.git` or the Praefect `@cluster/pools/...` pattern, which only constrains the *shape* of the path, not its relationship to any specific origin repository.
- `pool.IsValid(ctx)` — confirms the directory is a well-formed Git repository, again with no tie to a specific origin.

`LinkRepositoryToObjectPool` (`internal/gitaly/service/objectpool/link.go`) then calls `pool.Link(ctx, repo)`, which writes the pool's object directory (relative path) into the target repository's `objects/info/alternates` file (`internal/git/objectpool/link.go:19-66`), after which all objects reachable in the pool become visible to any RPC operating on the linked repository (commit reads, blob reads, archive generation, etc.). Nowhere in this call chain is there a check that the object pool was created from, or is otherwise authorized for, the specific `Repository` being linked — any two repositories that satisfy the naming/validity checks can be paired.

### Impact Explanation
If this RPC is reachable with attacker- or tenant-controlled `ObjectPool.Repository.RelativePath` values (e.g., a compromised/buggy caller on the Rails side, or any client with access to the internal ObjectPoolService that can enumerate/guess existing pool paths — pool paths are derived deterministically from a SHA256 hash of the repository ID for Praefect pools, `internal/gitaly/storage/repository_path.go:57-59`), a repository could be linked to an unrelated project's object pool. This would expose that pool's objects (potentially private repository history/blobs) to the newly linked repository via `git cat-file`/fetch/archive, i.e., cross-repository object disclosure across tenant boundaries — analogous to the reported "malicious pool" cross-contamination risk.

### Likelihood Explanation
Exploitability depends on whether an ordinary/unprivileged actor can reach `LinkRepositoryToObjectPool` with an arbitrary pool path. In the current GitLab architecture this RPC is normally invoked internally by Rails as part of the fork-creation workflow with server-generated paths, which somewhat limits reachability. However, Praefect pool paths are deterministically derived (`DerivePoolPath`, a SHA256 hash of a sequential integer repository ID), making them enumerable/guessable, and the Gitaly-side code itself performs no authorization tie between the caller's `Repository` and the `ObjectPool`. I could not fully verify from the indexed code whether any additional authorization/ownership check exists upstream (e.g., in Rails) that would prevent supplying an arbitrary but validly-shaped pool path — this should be confirmed with a full review of call sites.

### Recommendation
- When linking a repository to a pool, verify that the pool is the one actually associated with the repository's fork network (e.g., cross-check against a `ForkNetworkMember`/origin registry rather than trusting the naming convention alone).
- Consider deriving/validating the expected pool path server-side from the repository's own metadata instead of accepting an arbitrary `ObjectPool.Repository` in the request.
- At minimum, log/audit pool-linking operations and rate-limit/permission-gate the `LinkRepositoryToObjectPool` and `CreateObjectPool` RPCs to trusted internal callers only.

### Proof of Concept
1. Attacker (or compromised internal caller) determines/guesses the relative path of an existing object pool belonging to a private/unrelated project (deterministic for Praefect pools via `DerivePoolPath(repositoryID)`, or via the Rails-style SHA256 naming for `@pools/xx/yy/<sha>.git`).
2. Attacker calls `LinkRepositoryToObjectPool` with `Repository` set to a repository they control and `ObjectPool.Repository.RelativePath` set to the guessed/unrelated pool path.
3. `objectpool.FromProto` accepts the pool because it matches the naming regex and is a valid Git repository (`internal/git/objectpool/pool.go:46-91`).
4. `pool.Link` writes the pool's object directory into the attacker's repository's alternates file (`internal/git/objectpool/link.go:19-66`).
5. Attacker can now read any object reachable from the pool (e.g., via `GetBlob`, `TreeEntry`, `GetArchive`) through their own linked repository, exposing objects from the unrelated pool/project.

// FromProto returns an object pool object from its Protobuf representation. This function verifies
// that the object pool exists and is a valid pool repository.
func FromProto(
	ctx context.Context,
	logger log.Logger,
	locator storage.Locator,
	gitCmdFactory gitcmd.CommandFactory,
	catfileCache catfile.Cache,
	txManager transaction.Manager,
	housekeepingManager housekeepingmgr.Manager,
	proto *gitalypb.ObjectPool,
) (*ObjectPool, error) {
	poolPath, err := locator.GetRepoPath(ctx, proto.GetRepository(), storage.WithRepositoryVerificationSkipped())
	if err != nil {
		return nil, err
	}

	if !storage.IsPoolRepository(proto.GetRepository()) {
		// When creating repositories in the ObjectPool service we will first create the
		// repository in a temporary directory. So we need to check whether the path we see
		// here is in such a temporary directory and let it pass.
		tempDir, err := locator.TempDir(proto.GetRepository().GetStorageName())
		if err != nil {
			return nil, fmt.Errorf("getting temporary storage directory: %w", err)
		}

		if !strings.HasPrefix(poolPath, tempDir) {
			return nil, ErrInvalidPoolDir
		}
	}

	pool := &ObjectPool{
		Repo:                localrepo.New(logger, locator, gitCmdFactory, catfileCache, proto.GetRepository()),
		logger:              logger,
		locator:             locator,
		gitCmdFactory:       gitCmdFactory,
		txManager:           txManager,
		housekeepingManager: housekeepingManager,
	}

	if !pool.IsValid(ctx) {
		return nil, ErrInvalidPoolRepository
	}

	return pool, nil
}

// IsRailsPoolRepository returns whether the repository is a pool repository generated by Rails.
func IsRailsPoolRepository(repo Repository) bool {
	matches := railsPoolDirRegexp.FindStringSubmatch(repo.GetRelativePath())
	if matches == nil || !strings.HasPrefix(matches[3], matches[1]+matches[2]) {
		return false
	}

	return true
}

// IsPraefectPoolRepository returns whether the repository is a Praefect generated object pool repository.
func IsPraefectPoolRepository(repo Repository) bool {
	return praefectPoolDirRegexp.MatchString(repo.GetRelativePath())
}

// IsPoolRepository returns whether the repository is an object pool.
func IsPoolRepository(repo Repository) bool {
	return IsRailsPoolRepository(repo) || IsPraefectPoolRepository(repo)
}

import (

func (s *server) LinkRepositoryToObjectPool(ctx context.Context, req *gitalypb.LinkRepositoryToObjectPoolRequest) (*gitalypb.LinkRepositoryToObjectPoolResponse, error) {
	repository := req.GetRepository()
	if err := s.locator.ValidateRepository(ctx, repository); err != nil {
		return nil, structerr.NewInvalidArgument("%w", err)
	}

	pool, err := s.poolForRequest(ctx, req)
	if err != nil {
		return nil, err
	}

	repo := s.localRepoFactory.Build(repository)

	if err := pool.Link(ctx, repo); err != nil {
		return nil, structerr.NewInternal("%w", err)
	}

	return &gitalypb.LinkRepositoryToObjectPoolResponse{}, nil
}

func (o *ObjectPool) Link(ctx context.Context, repo *localrepo.Repo) error {
	return Link(ctx, o.Repo, repo, o.txManager)
}

// Link will link the given repository to the object pool. This is done by writing the object pool's
// path relative to the repository into the repository's "alternates" file. This does not trigger
// deduplication, which is the responsibility of the caller.
func Link(ctx context.Context, pool, repo *localrepo.Repo, txManager transaction.Manager) (returnedErr error) {
	altPath, err := repo.InfoAlternatesPath(ctx)
	if err != nil {
		return err
	}

	expectedRelPath, err := getRelativeObjectPath(ctx, pool, repo)
	if err != nil {
		return err
	}

	linked, err := linkedToRepository(ctx, pool, repo)
	if err != nil {
		return err
	}

	if linked {
		// When the repository is already linked to the repository, cast a vote to ensure the
		// repository is consistent with the other replicas.
		if err := transaction.VoteOnContext(ctx, txManager, voting.VoteFromData([]byte("repository linked")), voting.Synchronized); err != nil {
			return fmt.Errorf("vote on linked repository: %w", err)
		}

		return nil
	}

	alternatesWriter, err := safe.NewLockingFileWriter(altPath)
	if err != nil {
		return fmt.Errorf("creating alternates writer: %w", err)
	}
	defer func() {
		if err := alternatesWriter.Close(); err != nil && returnedErr == nil {
			returnedErr = fmt.Errorf("closing alternates writer: %w", err)
		}
	}()

	if _, err := io.WriteString(alternatesWriter, expectedRelPath); err != nil {
