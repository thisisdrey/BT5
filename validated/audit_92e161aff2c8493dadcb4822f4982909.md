### Title
`unbond` burns member points while dissolving zero underlying balance on heavily-slashed pools - ([File: substrate/frame/nomination-pools/src/lib.rs])

### Summary
The `Pallet::unbond` extrinsic in `pallet-nomination-pools` converts a member's `unbonding_points` into a balance via `BondedPool::dissolve`, which internally calls `points_to_balance` → `Pallet::point_to_balance`. When a pool has been heavily slashed such that `points > balance` (value per point < 1), a small `unbonding_points` amount can truncate to `0` balance. The call proceeds anyway: the member's active points are permanently reduced and 0-value points are issued into the unbonding sub-pool, mirroring the `AToken.redeem()` bug where shares are burned but zero underlying is paid out.

### Finding Description
`unbond` computes: [1](#0-0) 

`bonded_pool.dissolve(unbonding_points)` computes `balance = self.points_to_balance(points)` and then unconditionally subtracts `points` from `self.points`, regardless of whether `balance` is zero: [2](#0-1) 

`points_to_balance` delegates to `Pallet::point_to_balance`, which performs integer division `(current_balance * points) / current_points` and truncates towards zero when the ratio is small: [3](#0-2) 

The guard function `ok_to_unbond_with` only checks that the *remaining* balance after unbonding satisfies `MinJoinBond`/`depositor_min_bond`, or that the unbond is a full unbond — it never checks that the *dissolved* (`unbonding_balance`) amount itself is non-zero: [4](#0-3) 

Back in `unbond`, the truncated `unbonding_balance` (possibly `0`) is passed to `T::StakeAdapter::unbond` and used to `issue` points into the era's `UnbondPool`, and `member.try_unbond` decrements the member's real points by the full `unbonding_points` requested: [5](#0-4) 

This is the structural analog of the `AToken.redeem()` bug: shares (points) are burned from the caller, but the exchange leg (`unbonding_balance` transferred into the unbonding sub-pool / staking unbond) can be zero, permanently destroying the caller's claim on pool value without compensating them. Unlike `do_remove_liquidity` in `pallet-asset-conversion`, which explicitly guards `!amount1.is_zero()` / `!amount2.is_zero()` before burning LP tokens, and unlike the PSM `redeem` path which reverts with `AmountTooSmallAfterConversion` on truncation, `unbond` in nomination-pools has no equivalent `ensure!(!unbonding_balance.is_zero(), ...)` check.

### Impact Explanation
A member who unbonds a small number of points from a pool that has suffered a large slash (points≫balance) can have their `points` permanently reduced while receiving `0` balance credited to any unbonding sub-pool and `0` passed to the underlying staking unbond. This is a direct, uncompensated loss of stake value for the caller — a value-conservation violation in the staking/pool accounting layer, consistent with the "Balances, ... staking, pools, ... must conserve value and settle exactly once" pivot criterion.

### Likelihood Explanation
Requires a pool that has already been slashed enough to push the balance/points ratio below 1 (i.e., `points > balance`), then any member calling `unbond` with a `points` amount small enough for `(balance * points) / total_points` to truncate to zero. This is a normal, unprivileged user action (no malicious peer/validator/relayer needed) — it is fully triggerable by any pool member after an ordinary slashing event, especially in pools with fine-grained unbonding by many small stakers.

### Recommendation
Add an explicit guard in `BondedPool::dissolve` (or in `ok_to_unbond_with` / `unbond`) rejecting unbonds whose resulting `unbonding_balance` (from `points_to_balance`) is zero while `unbonding_points` is non-zero, e.g. `ensure!(!unbonding_balance.is_zero(), Error::<T>::AmountTooSmallToUnbond)`, analogous to the `!amount1.is_zero()` check already present in `pallet-asset-conversion::do_remove_liquidity`.

### Proof of Concept
1. Create a pool and have members join such that `bonded_pool.points` is large relative to `bonded_pool` bonded balance.
2. Trigger a slash via the staking mock (`StakingMock::slash_by`) large enough that `active_stake / points` ratio drops below `1`, e.g. balance=100, points=1000 (as demonstrated by test helpers in `substrate/frame/nomination-pools/src/tests.rs:626-660` showing `point_to_balance` truncation to `0` for small `points` when `balance < points`).
3. Call `Pools::unbond(origin, member_account, small_points)` with `small_points` chosen so `(balance * small_points) / total_points == 0` (integer truncation), while `small_points < member.active_points()` and passing the `ok_to_unbond_with` partial-unbond minimum-bond check (e.g. remaining balance still ≥ `MinJoinBond`).
4. Observe: the call succeeds (`Ok(())`), `member.points` decreases by `small_points`, `Event::Unbonded { balance: 0, points: small_points_issued_maybe_0, .. }` is emitted, but no real value moved into the unbonding sub-pool or was released from `StakeAdapter` — the member has irrecoverably lost claim on `small_points` worth of pool points for zero balance in return.

		// NOTE: do not optimize by removing `balance`. it must be computed before mutating

		let balance = self.points_to_balance(points);

	fn ok_to_unbond_with(
		&self,
		caller: &T::AccountId,
		target_account: &T::AccountId,
		target_member: &PoolMember<T>,
		unbonding_points: BalanceOf<T>,
	) -> Result<(), DispatchError> {
		let is_permissioned = caller == target_account;
		let is_depositor = *target_account == self.roles.depositor;
		let is_full_unbond = unbonding_points == target_member.active_points();

		let balance_after_unbond = {
			let new_depositor_points =
				target_member.active_points().saturating_sub(unbonding_points);
			let mut target_member_after_unbond = (*target_member).clone();
			target_member_after_unbond.points = new_depositor_points;
			target_member_after_unbond.active_balance()
		};

		// any partial unbonding is only ever allowed if this unbond is permissioned.
		ensure!(
			is_permissioned || is_full_unbond,
			Error::<T>::PartialUnbondNotAllowedPermissionlessly
		);

		// any unbond must comply with the balance condition:
		ensure!(
			is_full_unbond ||
				balance_after_unbond >=
					if is_depositor {
						Pallet::<T>::depositor_min_bond()
					} else {
						MinJoinBond::<T>::get()
					},
			Error::<T>::MinimumBondNotMet
		);

	fn point_to_balance(
		current_balance: BalanceOf<T>,
		current_points: BalanceOf<T>,
		points: BalanceOf<T>,
	) -> BalanceOf<T> {
		let u256 = T::BalanceToU256::convert;
		let balance = T::U256ToBalance::convert;
		if current_balance.is_zero() || current_points.is_zero() || points.is_zero() {
			// There is nothing to unbond
			return Zero::zero();
		}

		// Equivalent of (current_balance / current_points) * points
		balance(
			u256(current_balance)
				.saturating_mul(u256(points))
				// We check for zero above
				.div(u256(current_points)),
		)
	}
