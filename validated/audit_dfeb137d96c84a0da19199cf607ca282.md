This resolve_deposit_internal / mt_resolve_transfer pattern is exactly the correct check-effects-interaction design (credit/debit committed before the cross-contract call; the resolve callback only refunds up to `min(requested, deposited, balance_left)`), which explicitly guards against the balance being spent in between (the `balance_left` cap). This is the standard NEAR NEP-141/171/245 escrow pattern and is not vulnerable to the Solidity-style mid-call reentrancy described in the external report, because NEAR has no synchronous cross-contract reentrancy — a contract's own state changes within a receipt are fully committed before any scheduled `Promise`/callback executes in a later receipt.
