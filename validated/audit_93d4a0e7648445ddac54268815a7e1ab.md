Audit Report

## Title
Bridged local assets keep an untrusted `Freezer`/`Admin` role that can permanently freeze bridge-locked balances - ([File: bridges/snowbridge/runtime/runtime-common/src/v2/register_token.rs])

## Summary
`LocalAssetOwner::try_origin` only checks that the calling account equals the `pallet_assets` Owner of an asset before allowing that asset to be registered for bridging to Ethereum via `register_token`. It never inspects or clears the asset's independent `Freezer`/`Admin` roles, which by default (via permissionless `pallet_assets::create`) are held by the same account as Owner. Once the asset is bridged and value accumulates in the Ethereum sovereign account on Asset Hub, the asset creator retains permanent freeze rights and can call `freeze`/`freeze_asset` to lock the sovereign account or any bridging user's account, permanently blocking bridge settlement/redemption.

## Finding Description
`LocalAssetOwner::try_origin` in `bridges/snowbridge/runtime/runtime-common/src/v2/register_token.rs` (lines 85-96) resolves the asset owner via `AssetInspect::owner(asset_id)` and only requires `who == owner`; it performs no verification of the `Freezer` or `Admin` roles. This type is instantiated as part of `RegisterTokenOrigin` in `cumulus/parachains/runtimes/assets/asset-hub-westend/src/bridge_to_ethereum_config.rs` (lines 50-68), alongside `ForeignAssetOwner`, which has the analogous limitation for foreign assets.

`pallet_assets::create` is permissionless and by default sets Owner, Issuer, Admin, and Freezer to the creator (documented in `substrate/frame/assets/src/lib.rs` lines 85-126). `freeze` (lines 1192-1216) and `freeze_asset` (lines 1265-1280) both gate solely on `origin == d.freezer`, with no relationship enforced against the Owner role that `LocalAssetOwner` checks.

The `register_token` extrinsic (`bridges/snowbridge/pallets/system-frontend/src/lib.rs`, lines 225-252) calls `T::RegisterTokenOrigin::ensure_origin`, which succeeds under `LocalAssetOwner` purely because `who == owner`, and proceeds to register the asset with BridgeHub for bridging to Ethereum. After users bridge funds and value accumulates in the Ethereum sovereign account on Asset Hub (as modeled in the existing test `cumulus/parachains/integration-tests/emulated/tests/bridges/bridge-hub-westend/src/tests/snowbridge_v2_inbound.rs` lines 766-778), the original creator — who still holds the unrestricted `Freezer` role — can call `freeze` against the sovereign/reserve account or any victim account, or `freeze_asset` against the whole asset class, at will.

No existing guard in the registration path checks or requires that Freezer/Admin be relinquished, burned, or bound to an immutable authority before an asset is accepted for cross-chain bridging.

## Impact Explanation
This allows an unprivileged, ordinary user (the asset creator, not governance/validator/relayer) to permanently freeze bridge-locked balances and/or arbitrary bridging users' balances of that asset, blocking all Ethereum-bound settlement or return-transfers. This matches the "permanent user-fund or bridge-state lock" category in the impact gate, since the corrupted state is the frozen `AccountStatus`/`AssetStatus` on the specific asset, directly blocking payout/redemption for anyone holding or bridging that asset (including the Ethereum sovereign reserve account).

## Likelihood Explanation
Fully feasible with only public dispatchables and no privileged role: `pallet_assets::create` (permissionless) → `register_token` (passes `LocalAssetOwner` check trivially) → wait for bridge liquidity/users → `freeze`/`freeze_asset` (gated only by `d.freezer`, which the attacker controls by default). No collusion, leaked keys, or governance/admin abuse required.

## Recommendation
Before accepting an asset into `RegisterTokenOrigin` (`LocalAssetOwner`/`ForeignAssetOwner`), require that the asset's `Freezer` and `Admin` roles be relinquished/burned or bound to a fixed, non-freezable sentinel account, e.g. by checking `pallet_assets::roles::Inspect` for freezer/admin equality to a known immutable authority, or requiring the asset's team to call `set_team` to give up these rights prior to/at registration time.

## Proof of Concept
1. Attacker calls `pallet_assets::create(origin=Attacker, id=X, admin=Attacker, min_balance=1)`; Attacker becomes Owner/Admin/Issuer/Freezer of asset `X`.
2. Attacker calls `SnowbridgeSystemFrontend::register_token(origin=Attacker, asset_id=X, ...)`; `LocalAssetOwner::try_origin` passes since `who == owner`.
3. Victims bridge asset `X` to Ethereum; local balances accumulate in the Ethereum sovereign account, mirroring the pattern in `snowbridge_v2_inbound.rs` lines 766-778.
4. Attacker calls `pallet_assets::freeze(origin=Attacker, id=X, who=<ethereum_sovereign>)` or `freeze_asset(origin=Attacker, id=X)`.
5. Subsequent transfer/burn/redeem operations on asset `X` fail with `Error::Frozen`, permanently locking bridged funds without any governance, admin, or relayer involvement.

	fn try_origin(
		origin: RuntimeOrigin,
		asset_location: &L,
	) -> Result<Self::Success, RuntimeOrigin> {
		let who = ensure_signed(origin.clone()).map_err(|_| origin.clone())?;
		let asset_id = MatchAssetId::convert(asset_location).ok_or_else(|| origin.clone())?;
		let owner = AssetInspect::owner(asset_id.into()).ok_or_else(|| origin.clone())?;
		if who != owner {
			return Err(origin);
		}
		Ok(who.into())
	}

			origin: OriginFor<T>,
			asset_id: Box<VersionedLocation>,
			metadata: AssetMetadata,
			fee_asset: Asset,
		) -> DispatchResult {
			ensure!(!Self::export_operating_mode().is_halted(), Error::<T>::Halted);

			let asset_location: Location =
				(*asset_id).try_into().map_err(|_| Error::<T>::UnsupportedLocationVersion)?;
			let origin_location = T::RegisterTokenOrigin::ensure_origin(origin, &asset_location)?;

			let ether_gained = if origin_location.is_here() {
				// Root origin/location does not pay any fees/tip.
				0
			} else {
				Self::swap_fee_asset_and_burn(origin_location.clone(), fee_asset)?
			};

			let call = Self::build_register_token_call(
				origin_location.clone(),
				asset_location,
				metadata,
				ether_gained,
			)?;

			Self::send_transact_call(origin_location, call)
		}
