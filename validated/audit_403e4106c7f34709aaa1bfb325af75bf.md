### Title
Contract self-destruct permanently freezes unclaimed voting reward for balances frozen via `FreezeBalanceV2` - (File: `actuator/src/main/java/org/tron/core/vm/program/Program.java`)

### Summary
The `SUICIDE` opcode handler in `Program.java` transfers a contract's `FreezeV2` (v2 freeze) balances to the inheritor and marks the contract self-destructed, but never calls `VoteRewardUtil.withdrawReward()`/`withdrawRewardAndCancelVote()` to flush the owner's outstanding voting reward before wiping its vote/frozen-v2 state. This is structurally the same bug class as the reported `withdraw()`/`claim()` issue: a destructive, one-shot operation (burn the veNFT / self-destruct the contract) is performed without first fully draining the reward accounting state tied to that identity, permanently freezing any reward that was still pending.

### Finding Description
When a contract self-destructs with `SUICIDE` and TVM freeze v2 is enabled, `transferFrozenV2BalanceToInheritor()` is invoked to move the owner's `FreezeV2` entries and matured `UnfrozenV2` balance to the inheritor, then clears the owner's freeze/vote-adjacent state via `clearOwnerFreezeV2()`: [1](#0-0) 

Compare this to the sibling helper `withdrawRewardAndCancelVote()`, which is the *correct* pattern used elsewhere for account-state-destroying operations — it explicitly calls `VoteRewardUtil.withdrawReward(owner, repo)` first to flush the owner's outstanding TVM-vote reward (`allowance`) into balance, and only then clears votes/`oldTronPower`: [2](#0-1) 

`transferFrozenV2BalanceToInheritor()` does not call `VoteRewardUtil.withdrawReward()` anywhere before clearing `FreezeV2`/`UnfrozenV2` state via `clearOwnerFreezeV2()`: [3](#0-2) 

Reward accrual for TVM-vote (`VoteRewardUtil.computeReward`) is driven by delta-VI accumulated per witness across cycles, tracked via `beginCycle`/`endCycle` on the owner's repository-level cycle bookkeeping: [4](#0-3) 

If the owner contract has outstanding votes and accrued-but-unclaimed reward (`allowance`) at the moment of `SUICIDE`, that reward is stored on the `AccountCapsule`'s `allowance` field and in the `beginCycle`/`endCycle` cycle pointers. `clearOwnerFreezeV2()` wipes the frozen/unfrozen bookkeeping without ever calling `VoteRewardUtil.withdrawReward()` to settle the pending reward into balance, and the account's votes are not cleared either (unlike `withdrawRewardAndCancelVote()`, which explicitly clears votes and cancels tron power). Once self-destructed, the caller has no further way to invoke `withdrawReward()`/`queryReward()` against that (now-emptied) owner identity from this code path to retrieve the pending `allowance`, since the account's resource/vote basis for further accrual has been erased by `clearOwnerFreezeV2()` while historic un-flushed cycle reward is left stranded.

### Impact Explanation
This causes permanent freezing of funds: TRX-denominated voting rewards (the `allowance` field, which is spendable via `WithdrawRewardProcessor`/`WithdrawBalanceActuator`) that had accrued for the self-destructing contract prior to the `SUICIDE` call become unreachable because the reward-flush step present in the analogous `withdrawRewardAndCancelVote()` path is missing from `transferFrozenV2BalanceToInheritor()`. This matches the "Permanent freezing of unclaimed yield" impact class from the reference report, mapped onto java-tron's TVM-vote reward accounting and reachable by any contract deployer/caller that triggers `SUICIDE` on a contract holding `FreezeV2` balances with active votes.

### Likelihood Explanation
Reachable by any unprivileged account: deploy a contract, freeze TRX via `FreezeBalanceV2Contract`, vote for a witness (accruing TVM-vote reward across cycles), then call `SUICIDE` from within the contract while `VMConfig.allowTvmFreezeV2()` is enabled. No special privileges are required, and the TVM freeze v2/vote feature is a standard on-chain capability once the corresponding proposal is enabled network-wide.

### Recommendation
In `transferFrozenV2BalanceToInheritor()` (or its caller before `clearOwnerFreezeV2()` is applied), call `VoteRewardUtil.withdrawReward(ownerAddr, repo)` first to flush pending reward into the owner's `allowance`/balance, and transfer that residual balance to the inheritor together with votes cancellation, mirroring the pattern already implemented in `withdrawRewardAndCancelVote()`.

### Proof of Concept
Conceptual PoC (not executed — could not run a live node in this environment):
1. Enable `allowTvmFreezeV2` and `allowTvmVote` via the relevant `DynamicPropertiesStore` proposals.
2. Deploy a contract `C`.
3. From `C`, freeze TRX via the TVM `freezeBalanceV2` native contract call, then `vote` for one or more witnesses.
4. Advance several maintenance cycles so `VoteRewardUtil` accrues delta-VI reward into `C`'s `allowance` (verifiable via `VoteRewardUtil.queryReward(C, repo)` returning > 0, or the `queryRewardBalance` TVM opcode).
5. From `C`, invoke `SUICIDE` (self-destruct) to another address while `C` still has unclaimed reward and active votes.
6. Observe that `clearOwnerFreezeV2()` executes without any preceding `VoteRewardUtil.withdrawReward()` call, and that `C`'s account state (post `markSelfDestruct`) no longer allows retrieval of the previously accrued `allowance`/reward — contrasted with calling `withdrawReward()` explicitly beforehand, which would have flushed and preserved it in balance.

Note: I could not verify with a live test run inside this environment whether a later legacy `SUICIDE` path (pre-freeze-v2) or account-removal logic elsewhere fully deletes the `AccountCapsule` (which would make the loss unconditional) versus merely leaving `allowance` stranded but nominally still present in the DB entry under `ownerAddr`; a Devin session with repo access and test execution would be needed to confirm the exact on-chain observable state of `allowance` post-`SUICIDE` and to build a runnable JUnit PoC analogous to `FreezeV2Test`/`ProgramResultTest`.

  private long transferFrozenV2BalanceToInheritor(byte[] ownerAddr, byte[] inheritorAddr, Repository repo) {
    AccountCapsule ownerCapsule = repo.getAccount(ownerAddr);
    AccountCapsule inheritorCapsule = repo.getAccount(inheritorAddr);
    long now = repo.getHeadSlot();

    // transfer frozen resource
    ownerCapsule.getFrozenV2List().stream()
        .filter(freezeV2 -> freezeV2.getAmount() > 0)
        .forEach(
            freezeV2 -> {
              switch (freezeV2.getType()) {
                case BANDWIDTH:
                  inheritorCapsule.addFrozenBalanceForBandwidthV2(freezeV2.getAmount());
                  break;
                case ENERGY:
                  inheritorCapsule.addFrozenBalanceForEnergyV2(freezeV2.getAmount());
                  break;
                case TRON_POWER:
                  inheritorCapsule.addFrozenForTronPowerV2(freezeV2.getAmount());
                  break;
              }
            });

    // merge usage
    BandwidthProcessor bandwidthProcessor = new BandwidthProcessor(ChainBaseManager.getInstance());
    bandwidthProcessor.updateUsageForDelegated(ownerCapsule);
    ownerCapsule.setLatestConsumeTime(now);
    if (ownerCapsule.getNetUsage() > 0) {
      bandwidthProcessor.unDelegateIncrease(inheritorCapsule, ownerCapsule,
          ownerCapsule.getNetUsage(), BANDWIDTH, now);
    }

    EnergyProcessor energyProcessor =
        new EnergyProcessor(
            repo.getDynamicPropertiesStore(), ChainBaseManager.getInstance().getAccountStore());
    energyProcessor.updateUsage(ownerCapsule);
    ownerCapsule.setLatestConsumeTimeForEnergy(now);
    if (ownerCapsule.getEnergyUsage() > 0) {
      energyProcessor.unDelegateIncrease(inheritorCapsule, ownerCapsule,
          ownerCapsule.getEnergyUsage(), ENERGY, now);
    }

    // withdraw expire unfrozen balance
    long nowTimestamp = repo.getDynamicPropertiesStore().getLatestBlockHeaderTimestamp();
    long expireUnfrozenBalance =
        ownerCapsule.getUnfrozenV2List().stream()
            .filter(
                unFreezeV2 ->
                    unFreezeV2.getUnfreezeAmount() > 0 && unFreezeV2.getUnfreezeExpireTime() <= nowTimestamp)
            .mapToLong(Protocol.Account.UnFreezeV2::getUnfreezeAmount)
            .sum();
    if (expireUnfrozenBalance > 0) {
      inheritorCapsule.setBalance(inheritorCapsule.getBalance() + expireUnfrozenBalance);
      increaseNonce();
      addInternalTx(null, ownerAddr, inheritorAddr, expireUnfrozenBalance, null,
          "withdrawExpireUnfreezeWhileSuiciding", nonce, null);
    }
    clearOwnerFreezeV2(ownerCapsule);
    repo.updateAccount(ownerCapsule.createDbKey(), ownerCapsule);
    repo.updateAccount(inheritorCapsule.createDbKey(), inheritorCapsule);
    return expireUnfrozenBalance;
  }

  private void withdrawRewardAndCancelVote(byte[] owner, Repository repo) {
    VoteRewardUtil.withdrawReward(owner, repo);

    AccountCapsule ownerCapsule = repo.getAccount(owner);
    if (!ownerCapsule.getVotesList().isEmpty()) {
      VotesCapsule votesCapsule = repo.getVotes(owner);
      if (votesCapsule == null) {
        votesCapsule = new VotesCapsule(ByteString.copyFrom(owner),
            ownerCapsule.getVotesList());
      } else {
        votesCapsule.clearNewVotes();
      }
      ownerCapsule.clearVotes();
      ownerCapsule.setOldTronPower(0);
      repo.updateVotes(owner, votesCapsule);
    }
    try {
      long balance = ownerCapsule.getBalance();
      long allowance = ownerCapsule.getAllowance();
      ownerCapsule.setInstance(ownerCapsule.getInstance().toBuilder()
          .setBalance(addExact(balance, allowance, VMConfig.disableJavaLangMath()))
          .setAllowance(0)
          .setLatestWithdrawTime(getTimestamp().longValue() * 1000)
          .build());
      repo.updateAccount(ownerCapsule.createDbKey(), ownerCapsule);
    } catch (ArithmeticException e) {
      throw new BytecodeExecutionException("Suicide: balance and allowance out of long range.");
    }
  }

  public static void withdrawReward(byte[] address, Repository repository) {
    if (!VMConfig.allowTvmVote()) {
      return;
    }
    AccountCapsule accountCapsule = repository.getAccount(address);
    long beginCycle = repository.getBeginCycle(address);
    long endCycle = repository.getEndCycle(address);
    long currentCycle = repository.getDynamicPropertiesStore().getCurrentCycleNumber();
    long reward = 0;
    if (beginCycle > currentCycle || accountCapsule == null) {
      return;
    }
    if (beginCycle == currentCycle) {
      AccountCapsule account = repository.getAccountVote(beginCycle, address);
      if (account != null) {
        return;
      }
    }
    if (beginCycle + 1 == endCycle && beginCycle < currentCycle) {
      AccountCapsule account = repository.getAccountVote(beginCycle, address);
      if (account != null) {
        reward = computeReward(beginCycle, endCycle, account, repository);
        adjustAllowance(address, reward, repository);
        reward = 0;
      }
      beginCycle += 1;
    }
    endCycle = currentCycle;
    if (CollectionUtils.isEmpty(accountCapsule.getVotesList())) {
      repository.updateBeginCycle(address, endCycle + 1);
      return;
    }
    if (beginCycle < endCycle) {
      reward += computeReward(beginCycle, endCycle, accountCapsule, repository);
      adjustAllowance(address, reward, repository);
    }
    repository.updateBeginCycle(address, endCycle);
    repository.updateEndCycle(address, endCycle + 1);
    repository.updateAccountVote(address, endCycle, accountCapsule);
  }
