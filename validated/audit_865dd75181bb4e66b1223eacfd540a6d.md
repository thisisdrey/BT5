## Title
StackerDB `write_freq` rate limit is never enforced at write time, allowing any valid slot signer to bypass the configured per-slot write throttle - (File: `stackslib/src/net/stackerdb/db.rs`)

### Summary
`StackerDBConfig::write_freq` is documented as the smart contract's control over "how often a slot can be written to (in wall-clock time)" [1](#0-0)  and is stored as "minimum wall-clock time between writes to the same slot" [2](#0-1) . However, the actual chunk-write authorization function, `StackerDBTx::try_replace_chunk`, never checks it — only chunk size, slot existence, signature, staleness, and `max_writes` are enforced. This is directly analogous to the reported Aragon issue: a configuration value that is supposed to gate a repeatable, funded/authorized action is silently not enforced at the point where the action is actually committed, letting an authorized party (any valid slot signer, not an admin) act far outside the intended cadence.

### Finding Description
`try_replace_chunk` is the single choke point used to persist a chunk both from the unauthenticated-but-signed HTTP `POST /v2/stackerdb/.../chunks` endpoint [3](#0-2)  and from the P2P relay path (`process_stacker_db_chunks`) that broadcasts newly stored chunks to the network [4](#0-3) . Its implementation only performs these checks: [5](#0-4) 

There is no comparison against `slot_validation.write_time` and `self.config.write_freq` anywhere in this function, even though `SlotValidation`/`write_time` is tracked and persisted (`write_time` column is written on every `insert_chunk` call) [6](#0-5) .

The only place `write_freq` is consulted is in the *pull* sync scheduler, `StackerDBSync::add_scheduled_chunk_priorities` (in `sync.rs`), where it is merely used as a hint to skip trying to *fetch* a chunk that was written too recently — it never blocks a slot owner from *writing* a new version: [7](#0-6) 

`validate_received_chunk`, used for both StackerDBChunkInv sanity checks and the FutureView-Nack buffering path, explicitly documents that it "does not check write frequency, since the caller has different ways of doing this" [8](#0-7)  — but the actual persistence gate (`try_replace_chunk`) has no such alternate enforcement, so the invariant is dropped entirely on the write side.

### Impact Explanation
Any of the addresses in a StackerDB's `signers` list (e.g. any signer configured in `.signers-0-*`/`.signers-1-*`/`.miners` StackerDB contracts, which can include many low-weight signers) can submit new chunk versions to their own slot as fast as the network/RPC layer allows, up to `max_writes`, completely ignoring the smart contract's configured `write_freq` throttle. Each accepted write is broadcast network-wide via `StackerDBPushChunk` to peer nodes (`process_stacker_db_chunks` → `p2p.broadcast_message`) [9](#0-8) , and is also relayed by any receiving node that stores it. This lets a legitimate but abusive signer defeat the intended pacing control and drive a burst of authenticated, network-propagated chunk writes/broadcasts far above the rate the StackerDB operator configured, amplifying P2P and disk-write load across every replica of that StackerDB in the network.

### Likelihood Explanation
Any node operator who controls a signer key already entitled to write to a slot (which, for `.signers-*` StackerDBs, is potentially every registered signer, including small-weight ones) can trigger this merely by submitting successive valid chunk versions with increasing `slot_version` back-to-back; no special privilege beyond normal slot ownership is required, and no client-side throttling exists to prevent it.

### Recommendation
Enforce `write_freq` in `StackerDBTx::try_replace_chunk` by comparing the current time against `slot_validation.write_time + self.config.write_freq` and rejecting (e.g. with `net_error::TooFrequentSlotWrites`, which already exists as an error variant [10](#0-9)  but is apparently unused in the write path) if the slot was written too recently, mirroring the existing `max_writes`/staleness checks.

### Proof of Concept
1. Configure/observe a StackerDB contract (e.g. one of the `.signers-*` control contracts) whose `stackerdb-get-config` returns a nonzero `write-freq` (e.g. `u120`), confirmed to be parsed into `StackerDBConfig.write_freq` [11](#0-10) .
2. As a valid slot signer for that DB, issue a `POST /v2/stackerdb/{address}/{contract}/chunks` request signed for `slot_version = 1`; it is accepted [12](#0-11) .
3. Immediately (no delay) issue a second request for `slot_version = 2` with a valid signature; because `try_replace_chunk` never checks `write_freq`, this is accepted too, well within the configured throttle window — confirmed by the fact that the existing unit test `test_stackerdb_insert_query_chunks`/`test_reconfigure_stackerdb` set `write_freq = 120` seconds but never assert a rejection based on it [13](#0-12) .
4. Repeat up to `max_writes` times in a tight loop; each accepted write is broadcast to the P2P network as a new `StackerDBPushChunk` message.

    pub fn try_replace_chunk(
        &self,
        smart_contract: &QualifiedContractIdentifier,
        slot_desc: &SlotMetadata,
        chunk: &[u8],
    ) -> Result<(), net_error> {
        // Check per-replica chunk-size cap.
        if (chunk.len() as u64) > self.config.chunk_size {
            return Err(net_error::StackerDBChunkTooBig(chunk.len()));
        }

        let slot_validation = self
            .get_slot_validation(smart_contract, slot_desc.slot_id)?
            .ok_or(net_error::NoSuchSlot(
                smart_contract.clone(),
                slot_desc.slot_id,
            ))?;

        if !slot_desc.verify(&slot_validation.signer)? {
            return Err(net_error::BadSlotSigner(
                slot_validation.signer,
                slot_desc.slot_id,
            ));
        }
        if slot_desc.slot_version <= slot_validation.version {
            return Err(net_error::StaleChunk {
                supplied_version: slot_desc.slot_version,
                latest_version: slot_validation.version,
            });
        }
        if slot_desc.slot_version > self.config.max_writes {
            return Err(net_error::TooManySlotWrites {
                supplied_version: slot_desc.slot_version,
                latest_version: slot_validation.version,
                max_writes: self.config.max_writes,
            });
        }
        self.insert_chunk(smart_contract, slot_desc, chunk)
    }

impl StackerDBConfig {
    /// Check that a smart contract is consistent with being a StackerDB controller.
    /// Returns Ok(..) if the contract is valid
    /// Returns Err(reason) if the contract is invalid.  A human-readable reason will be given.
    fn is_contract_valid(epoch: &StacksEpochId, analysis: ContractAnalysis) -> Result<(), String> {
        for (name, expected_args, expected_return) in REQUIRED_FUNCTIONS.iter() {
            let func = if let Some(f) = analysis.read_only_function_types.get(name) {
                f
            } else if let Some(f) = analysis.public_function_types.get(name) {
                f
            } else {
                let reason = format!("Contract is missing function '{name}'");
                return Err(reason);
            };

            let FunctionType::Fixed(func) = func else {
                return Err(format!("Function '{name}' must be a fixed function"));
            };

            if func.args.len() != expected_args.len() {
                let reason = format!(
                    "Function '{name}' has an invalid signature: it must have {} args (got {})",
                    expected_args.len(),
                    func.args.len(),
                );
                return Err(reason);
            }
            for (actual_arg, expected_arg) in func.args.iter().zip(expected_args.iter()) {
                if !actual_arg
                    .signature
                    .admits_type(epoch, expected_arg)
                    .unwrap_or(false)
                {
                    return Err(format!("Function '{name}' has an invalid argument type: expected {expected_arg}, got {actual_arg}"));
                }
            }

            if !expected_return
                .admits_type(epoch, &func.returns)
                .unwrap_or(false)
            {
                return Err(format!("Function '{name}' has an invalid return type: expected {expected_return}, got {}", &func.returns));
            }
        }
        Ok(())
    }
