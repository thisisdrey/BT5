### Title
Reward index rounding dust permanently locks reward tokens in `RewardsDistributor` - (File: contracts/RewardsDistributor.sol)

### Summary
`RewardsDistributor` distributes a fixed emission (`tokenSpeeds[token] * elapsedTime`) via a global supply index. Both index-update steps round down: `_calculateTokenIndex` uses `wadDiv` (floor) to compute the per-supply index increment, and `_calculateTokenDelta` uses `wadMul` (floor) to convert the index delta into per-account rewards. Every rounding residual accrues to nobody: the corresponding reward tokens sit in the contract's `rewardToken` balance but are never reflected in any `tokensAccruedOf` entry, so they are permanently undistributable dust — the same bug class as the Fenix epoch-reward remainder.

### Finding Description
In `_calculateTokenIndex`, the global index increment is computed as:

```solidity
uint256 _tokensAccrued = _deltaTimestamps * _speed;
uint256 _ratio = _totalSupply > 0 ? _tokensAccrued.wadDiv(_totalSupply) : 0;
_newIndex = (_supplyState.index + _ratio).toUint224();
```

`wadDiv` floors the result (`contracts/RewardsDistributor.sol:204-207`). Then in `_calculateTokenDelta` each user's share is `token_.balanceOf(account_).wadMul(_deltaIndex)`, also floored (`contracts/RewardsDistributor.sol:229-230`). The sum of all floored user deltas is strictly less than `_tokensAccrued` for that period; the shortfall remains in `rewardToken.balanceOf(distributor)` but is never tracked by `tokenStates.index` or `tokensAccruedOf`. Unlike the contract balance check in `_transferRewardIfEnoughTokens` (`contracts/RewardsDistributor.sol:248-255`), there is no mechanism to roll the remainder into a future period — the leftover is invisible to the accounting forever.

### Impact Explanation
Unclaimed yield is permanently frozen. Reward tokens were transferred into the contract to be distributed, but the floored remainder for every index update interval is unclaimable by any account and cannot be recovered (there is no sweep/rescue for `rewardToken`). The loss scales with total supply and update frequency — each `_updateTokenIndex` call (triggered permissionlessly via `updateBeforeMintOrBurn`, `updateBeforeTransfer`, or `claimRewards`, `contracts/RewardsDistributor.sol:175-192`) discards up to ~`totalSupply/1e18` reward units in `wadDiv` rounding plus per-user `wadMul` residuals. This matches the Fenix finding's "higher supply → more dust lost" characterization.

### Likelihood Explanation
Certain to occur on every index update where `_tokensAccrued * 1e18` is not an exact multiple of `totalSupply` — i.e., virtually always in practice. No privileged action required; the rounding happens automatically as normal deposits/borrows trigger `updateBeforeMintOrBurn`/`updateBeforeTransfer`. Severity is limited because each individual loss is sub-wei-scale relative to emissions, but it is cumulative and permanent.

### Recommendation
Track undistributed remainder explicitly, e.g., store a `carry`/`remainder` accumulator per token: compute `_ratio = (_tokensAccrued + remainder).wadDiv(_totalSupply)` and persist the new remainder `(_tokensAccrued + remainder) - _ratio.wadMul(_totalSupply)` so rounding dust rolls into the next accrual window instead of being stranded.

### Proof of Concept
Foundry-style fork test demonstrating the invariant `Σ tokensAccruedOf + contractDust == emitted` is violated:

```solidity
// Setup: pool with one DepositToken, RewardsDistributor with speed > 0,
// distributor funded with R reward tokens.
uint256 supply = 3333333333333333333; // deliberately non-divisible total supply
deal(address(depositToken), alice, supply); // sole holder

vm.warp(t0 + 1 days);
// permissionless trigger
rewardsDistributor.updateBeforeMintOrBurn(IERC20(address(depositToken)), alice);
rewardsDistributor.claimRewards(alice);

uint256 emitted = tokenSpeed * 1 days;
uint256 paid = rewardToken.balanceOf(alice);
uint256 stuck = rewardToken.balanceOf(address(rewardsDistributor));

assertGt(stuck, 0);               // dust remainder, never claimable
assertLt(paid, emitted);          // alice is sole supplier yet got < emitted
// Re-run: any subsequent accrual leaves additional dust; `stuck` only grows.
```

With a single holder receiving the entire index delta, `paid` still falls short of `emitted` by the compounded `wadDiv`/`wadMul` floor residuals, and `stuck` is unrecoverable by any public entry point.
