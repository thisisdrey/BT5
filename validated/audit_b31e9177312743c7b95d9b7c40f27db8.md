### Title
Checksum-based replica consistency verification silently ignores refs outside a hard-coded allow-list, letting replicas permanently diverge undetected - (File: internal/git/checksum.go)

### Summary
Gitaly's `CalculateChecksum` RPC produces a repository "fingerprint" that Praefect treats as authoritative proof that a replica's data matches another replica's (analogous to how the Linea contract treated `finalBlockNumber` as authoritative proof that all block data had been submitted). The checksum, however, is computed only over a hard-coded subset of ref namespaces. Any reference outside that allow-list is silently excluded from the hash. Praefect's crash-recovery logic (`recoverPendingTransaction`) and its checksum-based consistency checks use checksum equality as the sole criterion for deciding a secondary is "updated" and needs no repair — exactly the same class of bug as the audit finding: a derived/aggregate value is trusted as a complete proof of correctness for an operation, but the underlying check does not actually cover all the data it is supposed to attest to.

### Finding Description
`Checksum.Add`/`Checksum.AddBytes` only XOR in references whose names match: [1](#0-0) 

`refsAllowed` covers only `HEAD`, `refs/heads`, `refs/tags`, `refs/keep-around`, `refs/merge-requests`, `refs/environments`, and `refs/notes`. Any other reference namespace (e.g. custom internal refs, `refs/pipelines`, `refs/gitlab/*`, or any arbitrary ref name a client is permitted to push) is skipped entirely when computing the checksum, as confirmed by the RPC implementation and its own test suite noting the ambiguity: [2](#0-1) [3](#0-2) 

This checksum is used by Praefect as the ground truth for whether two replicas of a repository hold identical state. In particular, the new crash-recovery path added to reconcile transactions that reached quorum but never got a persisted generation bump queries every expected voter's checksum, treats the primary's checksum as authoritative, and marks any secondary whose checksum matches as `updated` (needing no replication) while only secondaries with a *different* checksum are queued for repair: [4](#0-3) 

The same checksum-equality pattern (`CalculateChecksum` on both sides, compare strings) is relied on elsewhere in Praefect for detecting replicas that need replication, e.g. `RepositoryReplicas`/`InfoService`: [5](#0-4) 

Because refs outside `refsAllowed` never contribute to the checksum, an ordinary user who can push or otherwise write a reference in an excluded namespace to only one replica (e.g. during a network partition, a partial write, or a targeted write via `WriteRef`/`UpdateReferences`) will cause that replica to silently diverge from its peers while `CalculateChecksum` still reports identical values. Both the periodic consistency verifier and the crash-recovery reconciliation described above will conclude "no discrepancy, no repair needed," so the divergent state is never healed by replication and persists indefinitely.

### Impact Explanation
This breaks Praefect's core data-integrity guarantee: that all storages behind a virtual storage either match or get automatically repaired via replication. A replica can be permanently corrupted/divergent for any ref outside the allow-listed namespaces without any alerting or self-healing mechanism ever detecting it, because the very tool used to detect and drive repair (`CalculateChecksum`) is blind to that data. If that stale replica is later promoted to primary (e.g. during failover) or is read from directly, it can silently serve incorrect/missing reference data — a durable data-loss/data-integrity condition, directly analogous to the original bug where the prover could silently skip finalizing certain block data because the check that was supposed to catch it (`finalBlockNumber` continuity) didn't actually enforce coverage of all submitted data.

### Likelihood Explanation
Any ref name outside the seven allow-listed prefixes is affected; GitLab and its Gitaly clients create and mutate numerous ref namespaces beyond `refs/heads`/`refs/tags`/etc. (e.g. custom internal refs used by various features), and any of these can diverge across nodes due to partial writes, race conditions, or targeted single-node writes through RPCs such as `WriteRef`/`UpdateReferences`. No privileged access or malicious peer is required — an ordinary write path combined with an already-possible partial-write/partition scenario is sufficient to trigger silent, permanent divergence that the consistency machinery cannot detect.

### Recommendation
Broaden `Checksum`'s coverage so that it accounts for all references in the repository (or, at minimum, document and enforce that Praefect's consistency/repair mechanisms are only valid for the allow-listed namespaces and must not be relied upon as a general correctness proof). Concretely:
- Remove or generalize the `refsAllowed` filter in `internal/git/checksum.go` so that the checksum is a function of the full reference set (or explicitly of every namespace Praefect needs to keep consistent).
- In `recoverPendingTransaction` and the periodic verifier, do not treat checksum equality as sufficient proof of full consistency unless the checksum is guaranteed to cover every reference namespace actually written by Gitaly/GitLab.
- Add regression tests that create refs outside the current allow-list on only one replica and assert that Praefect's crash-recovery and verifier flows detect the divergence and schedule replication.

### Proof of Concept
1. Set up a Praefect virtual storage with a primary and at least one secondary Gitaly node.
2. Push a commit and create a reference in a namespace not covered by `refsAllowed`, e.g. `refs/custom/marker`, to the primary only (simulate a partial replication failure or directly use `WriteRef`/`UpdateReferences` against just the primary storage, bypassing the secondary).
3. Call `CalculateChecksum` against both the primary and secondary — the checksums will be identical because `refs/custom/marker` is filtered out by `refsAllowed`.
4. Trigger Praefect's crash-recovery path (`RecoverPendingTransactions`) or the periodic consistency verifier for this repository.
5. Observe that the secondary is classified as `updated` (no replication scheduled) even though it is missing `refs/custom/marker`, demonstrating that the checksum-based consistency check accepts an incomplete/incorrect final state as valid, mirroring the original "incorrect final block number can be finalized" defect where a derived value was trusted without verifying it actually reflects all submitted data.

var refsAllowed = regexp.MustCompile(`HEAD|(refs/(heads|tags|keep-around|merge-requests|environments|notes)/)`)

// Checksum is a hash representation of all references in a repository.
// Checksum must not be copied after first use.
type Checksum struct {
	sum big.Int
}

// AddBytes adds a reference to the checksum that is a line in the output format of `git-show-ref`.
func (c *Checksum) AddBytes(line []byte) {
	if !refsAllowed.Match(line) {
		return
	}

	h := sha1.New()
	// hash.Hash will never return an error.
	_, _ = h.Write(line)

	c.update(h.Sum(nil))
}

// Add adds a reference to the checksum.
func (c *Checksum) Add(ref Reference) {
	if !refsAllowed.MatchString(ref.Name.String()) {
		return
	}

	h := sha1.New()
	// hash.Hash will never return an error.
	_, _ = fmt.Fprintf(h, "%s %s", ref.Target, ref.Name)

	c.update(h.Sum(nil))
}

func (s *server) CalculateChecksum(ctx context.Context, in *gitalypb.CalculateChecksumRequest) (*gitalypb.CalculateChecksumResponse, error) {
	repoProto := in.GetRepository()
	if err := s.locator.ValidateRepository(ctx, repoProto); err != nil {
		return nil, structerr.NewInvalidArgument("%w", err)
	}

	repo := s.localRepoFactory.Build(repoProto)
	repoPath, err := repo.Path(ctx)
	if err != nil {
		return nil, err
	}

	cmd, err := repo.Exec(ctx, gitcmd.Command{
		Name: "show-ref",
		Flags: []gitcmd.Option{
			gitcmd.Flag{Name: "--head"},
		},
	}, gitcmd.WithSetupStdout())
	if err != nil {
		return nil, structerr.NewInternal("gitCommand: %w", err)
	}

	var checksum git.Checksum

	scanner := bufio.NewScanner(cmd)
	for scanner.Scan() {
		checksum.AddBytes(scanner.Bytes())
	}

	if err := scanner.Err(); err != nil {
		return nil, structerr.NewInternal("%w", err)
	}

	if err := cmd.Wait(); checksum.IsZero() || err != nil {
		if s.isValidRepo(ctx, repo) {
			return &gitalypb.CalculateChecksumResponse{Checksum: git.ZeroChecksum}, nil
		}

		return nil, structerr.NewDataLoss("not a git repository '%s'", repoPath)
	}

	return &gitalypb.CalculateChecksumResponse{Checksum: hex.EncodeToString(checksum.Bytes())}, nil
}
