### Title
Stale `PromiseYieldReceipt` survives `DeleteAccount` and can be resumed against a recreated account of the same name, escalating privileges across account ownership - ([File: runtime/runtime/src/lib.rs])

### Summary
The `PromiseYield` receipt handler in `process_receipt` unconditionally persists the receipt keyed only by `receiver_id` + `data_id` via `set_promise_yield_receipt`, with no check that the receiving account currently exists or is the same account instance that created the yield. `action_delete_account`'s underlying `remove_account` helper does not clean up `TrieKey::PromiseYieldReceipt` (or related `PromiseYieldTimeout`/`PromiseYieldStatus` entries) when an account is deleted, so a yield receipt created by an attacker-controlled account outlives that account's deletion and can later be resumed against a different, unrelated account that happens to reuse the same account name.

### Finding Description
`process_receipt`'s `PromiseYield` arm stores the incoming receipt with no existence or ownership check: [1](#0-0) 

`set_promise_yield_receipt` writes it keyed purely by `receiver_id` (an `AccountId` string) and `data_id`, with no notion of "account incarnation": [2](#0-1) 

`action_delete_account` calls `remove_account`, which only removes `TrieKey::Account`, `TrieKey::ContractCode`, access/gas keys, and `TrieKey::ContractData` — it never touches `TrieKey::PromiseYieldReceipt`, `TrieKey::PromiseYieldTimeout`, or `TrieKey::PromiseYieldStatus`: [3](#0-2) [4](#0-3) 

When a `PromiseResume` receipt later arrives, the runtime looks up the yield receipt purely by `(account_id, data_id)` and executes it via `apply_action_receipt` if found, again with no check that this is the same account instance that originally staged the yield: [5](#0-4) 

Since NEAR account names are string identifiers with no generation counter, once account `X` is deleted and a parent later recreates `X` (a normal, legitimate `CreateAccount` action under that parent), the new account inherits the pre-existing `TrieKey::PromiseYieldReceipt{ receiver_id: X, data_id }` entry left behind by the original (deleted) owner. The attacker, having recorded `data_id` at yield-creation time, can submit a `PromiseResume`/`promise_yield_resume` action referencing that `data_id`; `apply_action_receipt` will execute the attacker-authored action list against whatever account currently occupies name `X` (the new, legitimate owner), because `apply_action_receipt` fetches `account_id` fresh from state at execution time and applies the actions to it regardless of which entity actually authorized the receipt's creation.

### Impact Explanation
This is an authorization-escalation vulnerability: a receipt's privileged action list (e.g., `Stake`, `AddKey`) can be made to execute against a legitimate account owner's account after that owner has done nothing wrong other than reusing an account name previously deleted by an attacker. This matches NEAR's "authorization escalation across accounts or promises" bounty category, since the victim's account can have keys added or stake actions triggered without their consent.

### Likelihood Explanation
The precondition is that the attacker is the original creator of a sub-account `X`, which is trivially achievable by any unprivileged account (create sub-account, deploy a contract, self-yield a privileged action, record `data_id`, delete account). The remaining precondition — that the same account name `X` gets recreated later by an unrelated party under the same parent — is not guaranteed but is plausible in ecosystems that recycle short/descriptive sub-account names (e.g., after a user abandons a sub-account name and a different legitimate party registers it later). Cost to the attacker is minimal (a few cheap transactions); the attack is fully repeatable for any sub-account name pattern the attacker anticipates being reused.

### Recommendation
- In `remove_account` (or `action_delete_account`), also remove any `TrieKey::PromiseYieldReceipt`, `TrieKey::PromiseYieldStatus`, and pending `TrieKey::PromiseYieldTimeout` entries scoped to the deleted `account_id` before completing deletion.
- Alternatively/additionally, in the `PromiseYield` and `PromiseResume` arms of `process_receipt`, verify `get_account(state_update, receiver_id)` exists before storing/resuming a yield receipt, and tie the receipt to some account-incarnation identifier (e.g., account creation nonce/hash) that changes across delete/recreate cycles, rejecting resumes whose incarnation doesn't match.

### Proof of Concept
Integration test (test-loop or runtime integration test) plan:
1. Signer A creates sub-account `X` under a shared parent, deploys a contract that calls `promise_yield_create` targeting itself with an action list containing `Stake` or `AddKey`; capture the returned `data_id`.
2. Signer A submits `DeleteAccount(X, beneficiary=A)`; verify `X` is removed from state but assert (via direct trie inspection) that `TrieKey::PromiseYieldReceipt{ receiver_id: X, data_id }` is still present.
3. Signer B (unrelated) submits `CreateAccount(X)` under the same parent and deploys their own contract to `X`.
4. Signer A submits a `promise_yield_resume`-style receipt referencing the previously captured `data_id` targeting `X`.
5. Assert that the stale receipt executes, and that the resulting `AddKey`/`Stake` action is applied to Signer B's newly created account `X` — demonstrating unauthorized privilege injection into an account the attacker no longer owns.

pub fn set_promise_yield_receipt(state_update: &mut TrieUpdate, receipt: &Receipt) {
    match receipt.versioned_receipt() {
        VersionedReceiptEnum::PromiseYield(action_receipt) => {
            assert!(action_receipt.input_data_ids().len() == 1);
            let key = TrieKey::PromiseYieldReceipt {
                receiver_id: receipt.receiver_id().clone(),
                data_id: action_receipt.input_data_ids()[0],
            };
            set(state_update, key, receipt);
        }
        _ => unreachable!("Expected PromiseYield receipt"),
    }
}

/// Removes account, code and all access keys and gas keys associated to it.
pub fn remove_account(
    state_update: &mut TrieUpdate,
    account_id: &AccountId,
) -> Result<RemoveAccountResult, StorageError> {
    state_update.remove(TrieKey::Account { account_id: account_id.clone() });
    state_update.remove(TrieKey::ContractCode { account_id: account_id.clone() });

    let mut gas_key_nonce_count: usize = 0;
    let mut gas_key_nonce_total_key_bytes: usize = 0;

    // Removing access keys and gas key nonces
    let lock = state_update.trie().lock_for_iter();
    let mut keys_to_remove: Vec<TrieKey> = Vec::new();
    for raw_key in state_update
        .locked_iter(&trie_key_parsers::get_raw_prefix_for_access_keys(account_id), &lock)?
    {
        let raw_key = raw_key?;
        let key_handle = trie_key_parsers::parse_key_handle_from_access_key_key(
            &raw_key, account_id,
        )
        .map_err(|_e| {
            StorageError::StorageInconsistentState(
                "Can't parse key handle from raw key for AccessKey".to_string(),
            )
        })?;
        let nonce_index =
            trie_key_parsers::parse_nonce_index_from_gas_key_key(&raw_key, account_id, &key_handle)
                .map_err(|_e| {
                    StorageError::StorageInconsistentState(
                        "Can't parse nonce index from raw key for AccessKey".to_string(),
                    )
                })?;
        if let Some(index) = nonce_index {
            gas_key_nonce_count += 1;
            gas_key_nonce_total_key_bytes += raw_key.len();
            keys_to_remove.push(TrieKey::gas_key_nonce(
                account_id.clone(),
                key_handle.clone(),
                index,
            ));
        } else {
            keys_to_remove.push(TrieKey::access_key(account_id.clone(), key_handle.clone()));
        }
    }
    drop(lock);

    for trie_key in keys_to_remove {
        state_update.remove(trie_key);
    }

    // Removing contract data
    let lock = state_update.trie().lock_for_iter();
    let data_keys = state_update
        .locked_iter(&trie_key_parsers::get_raw_prefix_for_contract_data(account_id, &[]), &lock)?
        .map(|raw_key| {
            trie_key_parsers::parse_data_key_from_contract_data_key(&raw_key?, account_id)
                .map_err(|_e| {
                    StorageError::StorageInconsistentState(
                        "Can't parse data key from raw key for ContractData".to_string(),
                    )
                })
                .map(Vec::from)
        })
        .collect::<Result<Vec<_>, _>>()?;
    drop(lock);

    for key in data_keys {
        state_update.remove(TrieKey::ContractData { account_id: account_id.clone(), key });
    }
    Ok(RemoveAccountResult { gas_key_nonce_count, gas_key_nonce_total_key_bytes })
}

pub(crate) fn action_delete_account(
    state_update: &mut TrieUpdate,
    account: &mut Option<Account>,
    actor_id: &mut AccountId,
    receipt: &Receipt,
    result: &mut ActionResult,
    account_id: &AccountId,
    delete_account: &DeleteAccountAction,
    config: &RuntimeConfig,
    current_protocol_version: ProtocolVersion,
) -> Result<(), StorageError> {
    let account_ref = account.as_ref().unwrap();
    let account_storage_usage = if ProtocolFeature::FixDeleteAccountGlobalContractStorageUsage
        .enabled(current_protocol_version)
    {
        let contract_storage = get_contract_storage_usage(state_update, account_id, account_ref)?;
        account_ref.storage_usage().saturating_sub(contract_storage)
    } else {
        // Legacy behavior: only subtracts local contract code, misses the
        // global contract identifier overhead.
        let account_storage_usage = account_ref.storage_usage();
        let code_len = get_code_len_or_default(
            state_update,
            account_id.clone(),
            account_ref.local_contract_hash().unwrap_or_default(),
        )?;
        debug_assert!(
            code_len == 0 || account_storage_usage > code_len,
            "account storage usage should be larger than code size. storage usage: {}, code size: {}",
            account_storage_usage,
            code_len
        );
        account_storage_usage.saturating_sub(code_len)
    };
    if account_storage_usage > Account::MAX_ACCOUNT_DELETION_STORAGE_USAGE {
        result.result =
            Err(ActionErrorKind::DeleteAccountWithLargeState { account_id: account_id.clone() }
                .into());
        return Ok(());
    }
    let gas_key_balance_to_burn = compute_gas_key_balance_sum(state_update, account_id)?;
    if gas_key_balance_to_burn > GasKeyInfo::MAX_BALANCE_TO_BURN {
        result.result = Err(ActionErrorKind::GasKeyBalanceTooHigh {
            account_id: account_id.clone(),
            public_key: None,
            balance: gas_key_balance_to_burn,
        }
        .into());
        return Ok(());
    }
    // We use current amount as a pay out to beneficiary.
    let account_balance = account_ref.amount();
    if account_balance > Balance::ZERO {
        result
            .new_receipts
            .push(Receipt::new_balance_refund(&delete_account.beneficiary_id, account_balance));
    }
    let remove_result = remove_account(state_update, account_id)?;
    result.tokens_burnt =
        result.tokens_burnt.checked_add(gas_key_balance_to_burn).ok_or_else(|| {
            StorageError::StorageInconsistentState("tokens_burnt overflow".to_string())
        })?;
    if remove_result.gas_key_nonce_count > 0 {
        let compute = storage_removes_compute(
            &config.wasm_config.ext_costs,
            remove_result.gas_key_nonce_count,
            remove_result.gas_key_nonce_total_key_bytes,
            AccessKey::NONCE_VALUE_LEN * remove_result.gas_key_nonce_count,
        );
        result.compute_usage = safe_add_compute(result.compute_usage, compute).map_err(|_| {
            StorageError::StorageInconsistentState("compute_usage overflow".to_string())
        })?;
    }
    *actor_id = receipt.predecessor_id().clone();
    *account = None;
    Ok(())
}
