Confirmed: `SwQosConnectionContext` is built once per connection in `build_connection_context()` [1](#0-0)  and its `total_stake` (and derived `peer_type`) is cached for the connection's entire lifetime. `on_new_stream` reuses this same cached `total_stake` on every subsequent stream via `max_streams_per_throttling_interval()`, which never re-reads `staked_nodes` again [2](#0-1) . The per-stream quota is derived from `stake / total_stake` at connect time [3](#0-2) .

### Title
Stale cached `total_stake` in QUIC connection context lets a validator's stream quota drift from its fair share as cluster stake changes - (File: `streamer/src/nonblocking/swqos.rs`)

### Summary
`SwQos::build_connection_context` snapshots `total_stake` once when a QUIC connection is established and stores it in `SwQosConnectionContext`. This value is never refreshed for the lifetime of the connection, even though `staked_nodes` (and therefore the cluster's real total stake) changes continuously as epochs roll over and delegations move. Every subsequent stream on that connection is throttled using this stale denominator.

### Finding Description
`get_connection_stake` reads the live `total_stake` from `StakedNodes` at connection-open time [4](#0-3) . This value is baked into `SwQosConnectionContext::total_stake` inside `build_connection_context` [5](#0-4) , which also determines `peer_type` (Staked vs. Unstaked) based on the stake ratio computed against that one-time `total_stake`. For every stream opened afterward, `on_new_stream` calls `max_streams_per_throttling_interval`, which calls `available_load_capacity_in_throttling_duration(peer_type, conn_context.total_stake)` — always using the value captured at connection open, never the current `staked_nodes.total_stake()` [2](#0-1) , [3](#0-2) .

This is structurally the same root cause as the MasterChef finding: a shared, mutable "total" denominator (`totalPoints` there, cluster `total_stake` here) that is used to compute a peer's proportional share, where the share-holder's own recorded state is not recalculated when the denominator changes elsewhere in the system.

### Impact Explanation
Because QUIC connections are typically long-lived, a validator/peer that opens a connection when cluster `total_stake` is low gets a favorable (larger) `stake / total_stake` ratio baked into its quota. If total stake subsequently grows (new stake delegated, new epoch), that peer's allowed streams-per-throttling-interval remains computed against the old, smaller `total_stake`, granting it a disproportionately larger stream quota than its true current stake share — a QoS/rate-limit evasion relative to other peers who connect later at the updated (larger) total stake. Conversely, if a peer's own stake decreases after connecting, it keeps enjoying the higher quota computed at connect time until it disconnects and reconnects. This skews the fairness guarantees the stake-weighted QoS system is designed to enforce, and lets one connection consume more than its fair share of `QUIC_TOTAL_STAKED_CONCURRENT_STREAMS` capacity for the life of the connection.

### Likelihood Explanation
`staked_nodes` (hence `total_stake`) is a value that changes at every epoch boundary and can shift materially over a connection's lifetime, and QUIC connections used for `quic_streamer_tpu`/`quic_streamer_tpu_forwards` are held open for extended periods rather than per-transaction [6](#0-5) . No special privilege is required to trigger this — any peer opening a long-lived connection is affected/benefits automatically, so likelihood of the drift occurring is high, though the resulting fairness skew is bounded by `QUIC_MAX_STAKED_CONCURRENT_STREAMS` and the ratio drift magnitude.

### Recommendation
Periodically refresh `conn_context.total_stake` (and re-derive `peer_type`) from the live `staked_nodes` snapshot — e.g., on each `on_new_stream` call or on a fixed refresh interval similar to `update_ema_if_needed` — rather than caching it once at connection establishment, so that stream quotas track the current cluster stake distribution instead of a point-in-time snapshot.

### Proof of Concept
1. Peer P connects to `quic_streamer_tpu` when `staked_nodes.total_stake()` = `T0`, with P's stake = `S`. `build_connection_context` computes `peer_type = Staked(S)` and caches `total_stake = T0` in `SwQosConnectionContext` [5](#0-4) .
2. Cluster total stake grows to `T1 >> T0` (new delegations/epoch change) while P's connection stays open (no reconnect).
3. P opens further streams; `on_new_stream` → `max_streams_per_throttling_interval` still uses cached `T0`, so P's quota is `max_staked_load * S / T0`, larger than the fair `max_staked_load * S / T1` it should get under current cluster conditions [2](#0-1) , [3](#0-2) .
4. P thus retains an inflated share of the staked stream budget relative to other, freshly-connected peers at the same true stake, for as long as the connection is kept alive — a fairness/QoS-evasion gap directly analogous to the MasterChef stale-denominator bug.

impl QosController<SwQosConnectionContext> for SwQos {
    fn build_connection_context(&self, connection: &Connection) -> SwQosConnectionContext {
        let remote_address = connection.remote_address();
        get_connection_stake(connection, &self.staked_nodes).map_or(
            SwQosConnectionContext {
                peer_type: ConnectionPeerType::Unstaked,
                total_stake: 0,
                remote_pubkey: None,
                in_staked_table: false,
                remote_address,
                stream_counter: None,
                last_update: Arc::new(AtomicU64::new(timing::timestamp())),
            },
            |(pubkey, stake, total_stake)| {
                // The heuristic is that the stake should be large enough to have 1 stream pass through within one throttle
                // interval during which we allow max (MAX_STREAMS_PER_MS * STREAM_THROTTLING_INTERVAL_MS) streams.

                let peer_type = {
                    let max_streams_per_ms = self.staked_stream_load_ema.max_streams_per_ms();
                    let min_stake_ratio =
                        1_f64 / (max_streams_per_ms * STREAM_THROTTLING_INTERVAL_MS) as f64;
                    let stake_ratio = stake as f64 / total_stake as f64;
                    if stake_ratio < min_stake_ratio {
                        // If it is a staked connection with ultra low stake ratio, treat it as unstaked.
                        ConnectionPeerType::Unstaked
                    } else {
                        ConnectionPeerType::Staked(stake)
                    }
                };

                SwQosConnectionContext {
                    peer_type,
                    total_stake,
                    remote_pubkey: Some(pubkey),
                    in_staked_table: false,
                    remote_address,
                    last_update: Arc::new(AtomicU64::new(timing::timestamp())),
                    stream_counter: None,
                }
            },
        )
    }

    pub(crate) fn available_load_capacity_in_throttling_duration(
        &self,
        peer_type: ConnectionPeerType,
        total_stake: u64,
    ) -> u64 {
        match peer_type {
            ConnectionPeerType::Unstaked => self.max_unstaked_load_in_throttling_window,
            ConnectionPeerType::Staked(stake) => {
                if self.staked_throttling_enabled.load(Ordering::Relaxed) {
                    // 1 is added to `max_unstaked_load_in_throttling_window` to guarantee that staked
                    // clients get at least 1 more number of streams than unstaked connections.
                    self.max_staked_load_in_throttling_window
                        .saturating_mul(stake)
                        .checked_div(total_stake)
                        .unwrap_or(self.max_unstaked_load_in_throttling_window + 1)
                        .max(self.max_unstaked_load_in_throttling_window + 1)
                } else {
                    self.max_staked_load_in_throttling_window
                }
            }
        }
    }

pub fn get_connection_stake(
    connection: &Connection,
    staked_nodes: &RwLock<StakedNodes>,
) -> Option<(Pubkey, u64, u64)> {
    let pubkey = get_remote_pubkey(connection)?;
    debug!("Peer public key is {pubkey:?}");
    let staked_nodes = staked_nodes.read().unwrap();
    Some((
        pubkey,
        staked_nodes.get_node_stake(&pubkey)?,
        staked_nodes.total_stake(),
    ))
}
