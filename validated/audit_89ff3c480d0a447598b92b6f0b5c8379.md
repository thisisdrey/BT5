### Title
Repaid debt can be less than accrued debt because `balanceOf` truncates and `_burn` erases the remainder — (File: contracts/DebtToken.sol)

### Summary
`DebtToken.balanceOf` computes a user's current debt as `principalOf[account] * debtIndex / debtIndexOf[account]` using truncating integer division, so it under-reports the true (fractional) debt. Both `repay` and `repayAll` burn only that truncated amount, and `_burn` then resets `debtIndexOf[account] = debtIndex`, permanently discarding the fractional remainder. This is the same bug class as the JUSD report: the repaid amount can be strictly less than the borrowed-plus-accrued amount.

### Finding Description
- `balanceOf` returns `(_principal * _debtIndex) / debtIndexOf[account_]`, which rounds down by up to 1 wei per snapshot. [1](#0-0) 
- `repayAll` repays exactly `balanceOf(onBehalfOf_)` and `repay` accepts any amount up to `balanceOf`, so the user can always settle using only the truncated figure. [2](#0-1) [3](#0-2) 
- In `_burn`, after subtracting `amount_` from the truncated balance, the code writes `debtIndexOf[account_] = debtIndex`, which re-anchors the user's snapshot. Any residual fraction that truncation dropped can never be recovered — it is erased rather than carried. [4](#0-3) 
- Symmetrically, `_mint` stores `principalOf[account_] = balanceOf(account_) + amount_` using the truncated balance, so an account that issues new debt before repaying also has its previously dropped fraction wiped. [5](#0-4) 

Because the index ratio `debtIndex / debtIndexOf` almost never divides the principal evenly once interest accrues, essentially every repay or re-issue that is not exactly at accrual time drops a sub-wei remainder in the borrower's favor. The `wadDiv`-based `quoteRepayOut` can also round the repaid debt up to half a wei in the borrower's favor. [6](#0-5) 

### Impact Explanation
Each `repay`/`repayAll` lets a borrower extinguish up to ~1 wei of real debt without paying it, and each `_burn`/`_mint` snapshot forfeits the fractional remainder permanently. Aggregated across all users and every repay/issue cycle over the life of a pool, the protocol accumulates unrecoverable bad debt in the synthetic token: `totalSupply_` under-counts the sum of true liabilities, so synthetic-token redemptions/collateral backing are implicitly short by the cumulative dust. This matches the reported JUSD invariant break (repay < borrow).

### Likelihood Explanation
The loss is triggered by ordinary, unprivileged flows: any borrower calling `DebtToken.repay`, `repayAll`, or issuing new debt via `Pool.issue`/`SmartFarmingManager.leverage` once `debtIndex` has advanced causes truncation. No privileged role, oracle manipulation, or special configuration is needed; it occurs whenever `principal * debtIndex` is not divisible by `debtIndexOf`, which is the common case. The per-operation loss is bounded by ~1 wei, so realizing a material loss requires volume and repetition (which an attacker can automate at near-zero marginal principal cost via repeated borrow/repay), keeping severity moderate rather than critical.

### Recommendation
Track debt with enough precision that truncation cannot be exploited, e.g.:
- Round `balanceOf` up (ceiling division: `(_principal * _debtIndex + debtIndexOf - 1) / debtIndexOf`) so borrowers always repay at least the true debt, or
- Keep the existing floor value for display but carry the fractional remainder into `principalOf` when re-snapshotting (`_burn`/`_mint`) instead of silently dropping it.

### Proof of Concept
Hardhat-style reproduction against the deployed `DebtToken` (pseudocode, run on a fork):

```ts
// 1. user deposits collateral and issues debt via Pool / DebtToken.issue
await depositToken.deposit(collateralAmount, user.address);
await debtToken.issue(borrowAmount, user.address);

// 2. advance time so debtIndex grows
await time.increase(30 * 24 * 3600);
await debtToken.accrueInterest();

// 3. true debt has a fractional component:
//    trueDebt = principal * debtIndex / debtIndexOf (non-integer)
//    balanceOf(user) = floor(trueDebt)
const reportedDebt = await debtToken.balanceOf(user.address);

// 4. user repays exactly reportedDebt via repayAll (or repay with that amount)
//    mint/transfer enough synthetic token to user first
await debtToken.repayAll(user.address);

// 5. Observation: the fraction (trueDebt - reportedDebt) was never paid and
//    debtIndexOf was reset inside _burn, so it is unrecoverable.
//    Repeating issue -> accrue -> repayAll N times leaks ~<1 wei of debt each
//    iteration without any privileged access.
```

The invariant violated is debt conservation: `sum(balanceOf)` after full repayment can fall below `totalSupply_`'s economically owed amount because truncation is materialized into `principalOf`/`debtIndexOf` on every write. [7](#0-6) [8](#0-7)
