### Title
Missing L2 sequencer-uptime check allows stale-price swaps, issuances and liquidations - (File: contracts/Pool.sol)

### Summary
The upstream Arcadia finding reports that oracle reads on L2 lack a Chainlink sequencer-uptime check, so a down sequencer leaves the protocol consuming stale prices. The same pattern exists in Metronome: every oracle-priced path goes through `IMasterOracle` (`quote`, `quoteTokenToUsd`, `quoteUsdToToken`), and neither the interface nor any consuming contract (`Pool`, `DebtToken`, `SmartFarmingManager`) performs a sequencer-uptime check — a repo-wide search for `sequencer`, `SequencerUptimeFeed`, and grace-period logic returns zero matches [1](#0-0) . The protocol is deployed on Optimism, Base, Hemi and Swell, i.e. L2s where the sequencer-down scenario applies .

### Finding Description
All pricing flows through `masterOracle().quote(...)` with no freshness or sequencer check at the consumer level:

- `Pool.quoteSwapOut` / `quoteSwapIn` price swaps purely via `masterOracle().quote`, and `swap` executes against that quote with only `whenNotShutdown` + `nonReentrant` guards [2](#0-1) [3](#0-2) .
- `Pool.liquidate` prices seized collateral via `quoteLiquidateOut → masterOracle().quote`, gated only by a health check that itself reads the same (stale) oracle via `debtPositionOf` [4](#0-3) [5](#0-4) .
- `DebtToken.issue`/health checks value deposits and debt via `quoteTokenToUsd`/`quoteUsdToToken` through `pool.masterOracle()` [6](#0-5) .

There is no `sequencerNotDown`-style modifier anywhere; whether stale prices are rejected depends entirely on the external `MasterOracle`/underlying feed, which for Chainlink on L2 returns the last answer pushed before the sequencer went down and does not revert.

### Impact Explanation
While the sequencer is down, real market prices move but the L2 feed is frozen. On restart (or during the downtime window via L1-force-included txs on OP-stack chains):

- An unprivileged user can call `Pool.swap` to trade a depreciated synth for a stable one at the stale pre-crash rate, draining value from the pool/bad-debt ledger.
- A borrower can call `DebtToken.issue` to mint synths against collateral whose real value has dropped, creating undercollateralized debt → protocol insolvency.
- `Pool.liquidate` seizes collateral at stale rates, over- or under-seizing versus real value.

This breaks the solvency/liquidation-bounds invariant and enables direct theft of collateral value, matching the accepted impact classes.

### Likelihood Explanation
Sequencer outages on Optimism/Base have occurred historically and the vulnerable window is bounded (until the feed is updated after restart), so likelihood is moderate — typical Medium, same as the source finding. No privileged action is needed; all entry points are public and the guards present (`whenNotShutdown`, `nonReentrant`, existence checks, `isSwapActive`) do not address oracle freshness.

### Recommendation
When deploying on L2s, wrap oracle consumption with a sequencer-uptime check — e.g., read the canonical `SequencerUptimeFeed`, require `answer == 0` and `block.timestamp - startedAt > gracePeriod` — inside `MasterOracle.quote`/`getPriceInUsd` (or as a modifier on `Pool.swap`, `Pool.liquidate`, `DebtToken.issue`), and define chain-specific stale periods so a frozen feed reverts instead of serving stale prices.

### Proof of Concept
A Foundry fork test on Optimism/Base (mirroring `test/foundry/poc/TBY.t.sol` which already forks mainnet and impersonates `MASTER_ORACLE_GOVERNOR`/`SYNTH_GOVERNOR` at `test/foundry/poc/TBY.t.sol:97-121`):

1. Fork Optimism at a block, open a healthy position via `msdWETH.deposit` + `msUSDDebt.issue`.
2. `vm.mockCall` on the Chainlink aggregator's `latestRoundData` to return a stale `updatedAt` (or warp past the feed heartbeat) simulating the post-downtime frozen price; note no revert occurs since nothing checks sequencer status.
3. Show `pool.swap(msETH, msUSD, amount)` executes at the stale quote while the real market price has moved (assert `quoteSwapOut` output equals the stale rate, ignoring any new price).
4. Alternatively show `pool.liquidate` seizes collateral priced by `masterOracle().quote` at the stale rate.

Key assertion: no `sequencer`-related revert exists — the only staleness defenses observed are test-side `updateDefaultStalePeriod`/`price-too-behind` behaviors of pull oracles, not an uptime-feed check.
