### Title
Withdrawing all assets or closing a balance zeroes out `emissions_outstanding` without settling it, causing permanent loss of accrued emissions - ([File: programs/marginfi/src/state/marginfi_account.rs])

### Summary
The reported bug class is: burning/removing the entirety of a user's position wipes out accrued-but-unclaimed rewards tied to that position, because the reward bookkeeping lives on the same record that gets zeroed when the position is fully closed. In marginfi-v2, the analogous asset is `Balance.emissions_outstanding`, an I80F48 field that accrues a user's unclaimed emissions for a given bank position. `BalanceImpl::close()` [1](#0-0)  unconditionally resets the entire `Balance` struct (including `emissions_outstanding`) to `Balance::empty_deactivated()`, which explicitly zeroes `emissions_outstanding` [2](#0-1) .

### Finding Description
`BankAccountWrapper::withdraw_all` — used by `lending_account_withdraw` (and the Drift/JupLend/Kamino withdraw-all analogs) — calls `balance.close()` after zeroing out the asset shares, with no check or settlement of `emissions_outstanding` beforehand [3](#0-2) . Likewise, `BankAccountWrapper::close_balance` (used by `lending_account_close_balance`) accounts for outstanding asset/liability shares as dust, but never checks or settles `emissions_outstanding` before calling `balance.close()` [4](#0-3) [5](#0-4) .

Notably, the error enum already defines `CannotCloseOutstandingEmissions` — "Cannot close balance because of outstanding emissions" — indicating the protocol's own design intent that a balance must not be closed while it still holds unclaimed emissions [6](#0-5) . However, this error is never referenced anywhere in the current program instruction logic (`close_balance.rs`, `withdraw.rs`, or `marginfi_account.rs`) — it only appears in `errors.rs` and in a test helper file — meaning the intended guard is not wired into either `withdraw_all()` or `close_balance()`.

This mirrors the reported bug class exactly: a holder who fully exits a position (analogous to "burning all tokens") permanently loses the reward/payout balance that had already accrued to them (analogous to "payouts for distributions while frozen"), because the accrual record is destroyed along with the position rather than being paid out or preserved first.

### Impact Explanation
If `emissions_outstanding` is not settled/claimed before a user calls `withdraw_all` or `close_balance`, the accrued emissions value is silently discarded — this is a direct, unrecoverable loss of funds owed to the user (permanent loss of reward/payout that no other on-chain mechanism can recover once the `Balance` record is reset to `empty_deactivated()`). Because `withdraw_all` is the common/preferred method for fully exiting a bank position (explicitly used and tested in numerous flows, e.g. `tests/specs/basic/09_withdraw_repay.spec.ts` and the Drift/JupLend/Kamino harvesting tests), this is a broadly reachable path for ordinary, unprivileged users, not an edge case requiring a privileged actor.

### Likelihood Explanation
High reachability: `lending_account_withdraw` with `withdraw_all = true` and `lending_account_close_balance` are both ordinary, permissionless user-authority instructions exercised routinely (e.g., to fully exit a bank or to clean up empty balance slots before hitting the 16-balance limit). Any bank with non-zero `emissions_rate` where the user has not proactively claimed emissions before their final withdraw/close action would trigger this loss. I could not verify from the code reviewed whether emissions settlement is performed by a separate, always-preceding instruction in the client-side transaction flow (e.g., an emissions-withdraw ix bundled before every withdraw_all/close_balance by convention) — this is the main open uncertainty. If such settlement is not enforced on-chain (as the missing `CannotCloseOutstandingEmissions` guard suggests), a user who forgets or is not aware they must claim emissions first will lose them with no recourse.

### Recommendation
Add an on-chain check (using the already-defined `MarginfiError::CannotCloseOutstandingEmissions`) in both `BankAccountWrapper::withdraw_all` and `BankAccountWrapper::close_balance` (and any other code path that calls `Balance::close()`) that either:
- reverts if `balance.emissions_outstanding` is non-zero (forcing the caller to claim emissions first), or
- automatically settles/transfers the outstanding emissions to the user as part of the same instruction before zeroing the balance.

### Proof of Concept
Not independently reproduced with a running test due to tool/iteration limits; the finding is based on direct code inspection showing:
1. `Balance::empty_deactivated()` zeroes `emissions_outstanding` [2](#0-1) .
2. `BalanceImpl::close()` unconditionally invokes this reset [1](#0-0) .
3. `withdraw_all()` and `close_balance()` call `balance.close()` without any check/settlement of `emissions_outstanding` [7](#0-6) [8](#0-7) .
4. `MarginfiError::CannotCloseOutstandingEmissions` exists but is unreferenced anywhere in instruction logic [6](#0-5) .

A concrete PoC would deposit into a bank with `emissions_rate > 0`, allow emissions to accrue into `emissions_outstanding` on the user's balance, then call `lending_account_withdraw` with `withdraw_all = true` (or `lending_account_close_balance`) without first claiming emissions, and assert that `emissions_outstanding` is lost (zeroed) with no compensating transfer to the user.

        let bank = &mut self.bank;

    pub fn close_balance(&mut self, in_receivership: bool) -> MarginfiResult<()> {
        let balance = &mut self.balance;
        let bank = &mut self.bank;

        let current_liability_amount =
            bank.get_liability_amount(balance.liability_shares.into())?;
        let current_asset_amount = bank.get_asset_amount(balance.asset_shares.into())?;

        check!(
            current_liability_amount.is_zero_with_tolerance(ZERO_AMOUNT_THRESHOLD),
            MarginfiError::IllegalBalanceState,
            "Balance has existing debt"
        );

        check!(
            current_asset_amount.is_zero_with_tolerance(ZERO_AMOUNT_THRESHOLD),
            MarginfiError::IllegalBalanceState,
            "Balance has existing assets"
        );

        let asset_shares: I80F48 = balance.asset_shares.into();
        let liability_shares: I80F48 = balance.liability_shares.into();
        // Counters are incremented in `*_balance_internal` when shares cross
        // `ZERO_AMOUNT_THRESHOLD` upward; match that condition so we don't
        // double-decrement positions that already crossed downward earlier.
        let had_assets = asset_shares.is_positive_with_tolerance(ZERO_AMOUNT_THRESHOLD);
        let had_liabs = liability_shares.is_positive_with_tolerance(ZERO_AMOUNT_THRESHOLD);

        balance.close()?;

        if in_receivership {
            bank.cache.clear_liquidation_price_cache_locked();
        }

        // Asset-side dust = real tokens still in the liquidity vault that the
        // user never withdrew. Route to `collected_insurance_fees_outstanding`
        // so vault content stays fully accounted for, mirroring the fractional-
        // remainder handling in `withdraw_all`.
        if current_asset_amount > I80F48::ZERO {
            bank.collected_insurance_fees_outstanding =
                I80F48::from(bank.collected_insurance_fees_outstanding)
                    .checked_add(current_asset_amount)
                    .ok_or_else(math_error!())?
                    .into();
        }

        bank.change_asset_shares(-asset_shares, false)?;
        // Liability-side dust = bad debt the borrower never repaid. Decrementing
        // here makes the loss explicit instead of leaving phantom shares in
        // `total_liability_shares` that would compound interest indefinitely.
        bank.change_liability_shares(-liability_shares, true)?;

        if had_assets {
            bank.decrement_lending_position_count();
        }
        if had_liabs {
            bank.decrement_borrowing_position_count();
        }

        Ok(())
    }

pub fn lending_account_close_balance(ctx: Context<LendingAccountCloseBalance>) -> MarginfiResult {
    let LendingAccountCloseBalance {
        marginfi_account,
        bank: bank_loader,
        group: marginfi_group_loader,
        ..
    } = ctx.accounts;

    let mut marginfi_account = marginfi_account.load_mut()?;
    let mut bank = bank_loader.load_mut()?;

    check!(
        !marginfi_account.get_flag(ACCOUNT_DISABLED),
        MarginfiError::AccountDisabled
    );

    let group = &*marginfi_group_loader.load()?;
    bank.accrue_interest(
        Clock::get()?.unix_timestamp,
        group,
        #[cfg(not(feature = "client"))]
        bank_loader.key(),
    )?;

    bank.update_bank_cache(group)?;

    let in_receivership = marginfi_account.get_flag(ACCOUNT_IN_RECEIVERSHIP);
    let lending_account: &mut marginfi_type_crate::types::LendingAccount =
        &mut marginfi_account.lending_account;
    let mut bank_account =
        BankAccountWrapper::find(&bank_loader.key(), &mut bank, lending_account)?;

    bank_account.close_balance(in_receivership)?;
    lending_account.sort_balances();
    marginfi_account.sync_indexer_flags();
    marginfi_account.last_update = Clock::get()?.unix_timestamp as u64;

    Ok(())
}
