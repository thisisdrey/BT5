### Title
Protocol fee on `Nep245`/`Imt` token legs can be bypassed by splitting a transfer into unit-sized (`|delta| <= 1`) `TokenDiff` intents - ([File: contracts/defuse/core/src/intents/token_diff.rs])

### Summary
`TokenDiff::token_fee` exempts `Nep245`/`Imt` (and `Nep171`) legs from any fee whenever the *per-intent* `amount <= 1`, and this check is evaluated independently for each `TokenDiff::execute_intent` call rather than on the aggregate negative delta of a token across a batch/account. An attacker can split any transfer of N units of a `Nep245`/`Imt` token into N separate unit-sized `TokenDiff` intents (each `delta == -1`), each individually falling under the exemption, so the total fee collected drops to zero instead of `Pips::fee_ceil(fee, N)`.

### Finding Description
The broken binding: for a signer moving `N` units of `Nep245TokenId(mt.near, X)` out through `TokenDiff` intents, the intended fee credited to `fee_collector` should be `Pips::fee_ceil(protocol_fee, N)` (fee on the net negative delta of that token across the batch). The observed fee, when the same `N` is split across `N` separate `delta == -1` `TokenDiff` intents, is `0`.

Root cause is in `TokenDiff::token_fee`: [1](#0-0) 
which special-cases `Nep245`/`Imt`/`Nep171` to `Pips::ZERO` whenever `amount <= 1`. This function is invoked once per `(token_id, delta)` entry inside a single `TokenDiff::execute_intent` call, using only that entry's own `amount = delta.unsigned_abs()`: [2](#0-1) 

Each `TokenDiff` intent (and each signed `MultiPayload`) is processed independently by the engine — `execute_signed_intents` loops over payloads, verifies signature/public key, commits the (distinct) nonce, then dispatches to `intents.execute_intent`: [3](#0-2) 

There is no code anywhere in this path that sums negative deltas for the same `TokenId` across multiple intents/payloads before calling `token_fee`; the check `amount > 1` only ever sees the amount of the single delta entry currently being processed. Consequently, an attacker holding 2 units of `Nep245TokenId(mt.near, X)` can either:
- submit two `TokenDiff` intents (distinct nonces, same signer, same or different `MultiPayload`s) each with `diff = {token_id: -1, ...}`, or
- even a single `MultiPayload` whose `DefuseIntents` batches two `TokenDiff` intents each with `delta == -1` on the same `token_id`.

In both cases, `token_fee` returns `Pips::ZERO` twice (amount=1 each time), so `fees_collected` per intent is `0`, and the total credited to `engine.state.fee_collector()` is `0`, versus `fee.fee_ceil(2) > 0` (assuming `protocol_fee > 0`) for the equivalent single `delta == -2` intent.

None of the existing guards prevent this: `MultiPayload::verify`/`has_public_key` only authenticate the signer, `verify_intent_nonce`/`commit_nonce` only prevent replay (distinct nonces are legitimately allowed for the same signer), and `Deltas::finalize`/`Transfers` only check that the batch's net balance changes are conserved — they do not re-derive or enforce a minimum fee based on the aggregate size of same-token legs. Nothing generalizes the check beyond a single intent's single map entry.

This generalizes beyond `delta == -2`: any transfer of `N` units of a `Nep245`/`Imt` token can be fully de-fee'd by decomposing it into `N` unit legs, each independently valid and exempted.

### Impact Explanation
Protocol fees intended to be collected on `Nep245`/`Imt` token legs are systematically bypassed for any signer willing to split a transfer into unit-sized `TokenDiff` intents. This directly matches the Critical category "protocol fees bypassed or over-collected" — value (fee revenue) that should flow to `fee_collector` never leaves the trading counterpart's balance, at no cost to the attacker beyond additional (attacker-paid) gas/transaction overhead. The bypass is fully repeatable across any account, any `Nep245`/`Imt` token, and any transfer size (not limited to N=2), so the blast radius is systemic wherever `protocol_fee > 0` applies to MT/IMT legs.

### Likelihood Explanation
Preconditions are minimal and fully within an unprivileged user's control: the attacker only needs to hold the `Nep245`/`Imt` balance they intend to move and sign the required `TokenDiff` intents themselves (no counterparty cooperation is strictly needed if the diff nets balances they control, or a cooperating counterparty for a genuine trade). Splitting one intent into N unit-sized intents costs only marginally more gas/signing overhead, which is negligible against saved fees for any transfer of meaningful value. This is trivially and repeatedly exploitable.

### Recommendation
Compute the fee-exemption/`amount` threshold on the aggregate negative delta for each distinct `TokenId` across the entire batch (or track cumulative fee-free amount per token per signer within a bounded window), rather than per individual `TokenDiff` intent entry. Alternatively, remove the `amount <= 1` fee exemption for `Nep245`/`Imt` altogether, or apply it only when the *signer's total remaining balance change for that token across the whole execution* is `<= 1`.

### Proof of Concept
```rust
// contracts/defuse/core/src/intents/token_diff.rs (or an engine-level integration test)

#[test]
fn fee_bypass_via_unit_splitting() {
    let token_id: TokenId = Nep245TokenId::new(
        "mt.near".parse::<AccountId>().unwrap(),
        "ft1".to_string(),
    ).into();
    let fee = Pips::ONE_PERCENT; // protocol_fee > 0

    // Binding under test:
    // sum(fee collected for two `delta=-1` TokenDiff intents on `token_id`)
    //   == fee.fee_ceil(2)      (expected)
    // vs
    //   == 0                    (observed, demonstrating bypass)

    let single_intent_fee = TokenDiff::token_fee(token_id.clone(), 2, fee).fee_ceil(2);
    assert!(single_intent_fee > 0);

    let split_fee_1 = TokenDiff::token_fee(token_id.clone(), 1, fee).fee_ceil(1);
    let split_fee_2 = TokenDiff::token_fee(token_id.clone(), 1, fee).fee_ceil(1);
    let total_split_fee = split_fee_1 + split_fee_2;

    assert_eq!(split_fee_1, 0);
    assert_eq!(split_fee_2, 0);
    assert_eq!(total_split_fee, 0);

    // demonstrates inequality: total_split_fee (0) != single_intent_fee (fee.fee_ceil(2) > 0)
    assert_ne!(total_split_fee, single_intent_fee);
}
```
For a full end-to-end proof, this should be extended into a `near-workspaces` sandbox test that: (1) deposits 2 units of a `Nep245TokenId(mt.near, X)` to a signer, (2) executes a `MultiPayload` with one `TokenDiff` intent `delta = -2` and observes `fee_collector`'s credited balance equals `fee.fee_ceil(2)`, then (3) resets state and executes two `MultiPayload`s (or two `TokenDiff` intents in one payload, distinct nonces if in separate payloads) each `delta = -1` on the same `token_id`, and observes `fee_collector`'s credited balance is `0`, asserting the two runs diverge.

    fn execute_signed_intent(&mut self, signed: MultiPayload) -> Result<()> {
        // verify signed payload and get public key
        let public_key = signed.verify().ok_or(DefuseError::InvalidSignature)?;

        // calculate intent hash
        let hash = signed.hash();

        // extract NEP-413 payload
        let DefusePayload::<DefuseIntents> {
            signer_id,
            verifying_contract,
            deadline,
            nonce,
            message: intents,
        } = signed.extract_defuse_payload()?;

        // check recipient
        if verifying_contract != *self.state.verifying_contract() {
            return Err(DefuseError::WrongVerifyingContract);
        }

        self.inspector.on_deadline(deadline);

        // make sure message is still valid
        if deadline < Timestamp::now() {
            return Err(DefuseError::DeadlineExpired);
        }

        // make sure the account has this public key
        if !self.state.has_public_key(&signer_id, &public_key) {
            return Err(DefuseError::PublicKeyNotExist(signer_id, public_key));
        }

        // commit nonce
        self.verify_intent_nonce(nonce, deadline)?;
        self.state.commit_nonce(signer_id.clone(), nonce)?;

        intents.execute_intent(&signer_id, self, hash)?;
        self.inspector.on_intent_executed(&signer_id, hash, nonce);

        Ok(())
    }
