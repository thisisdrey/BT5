### Title
Cross-contract StackerDB chunk replay due to missing contract binding in `SlotMetadata::auth_digest` - (File: `libstackerdb/src/libstackerdb.rs`)

### Summary
`SlotMetadata::auth_digest` computes the signed digest from only `slot_id`, `slot_version`, and `data_hash`, omitting the StackerDB `smart_contract` identifier. `StackerDBTx::try_replace_chunk` verifies the signature only against the slot's `signer` address for the target contract, so a chunk validly signed for slot N in contract A is also a valid signature for slot N in contract B whenever the same address is registered as slot N's signer in both contracts' `stacker_db_configs`.

### Finding Description
The intended authentication scope for a chunk write is `(contract, slot_id, slot_version, data_hash)`, but `auth_digest` only binds `(slot_id, slot_version, data_hash)`: [1](#0-0) 

`SlotMetadata::sign`/`verify` and `StackerDBChunkData::sign`/`verify`/`recover_pk` all route through this same digest, so the contract identifier never enters the signed material: [2](#0-1) [3](#0-2) 

On the write path, `StackerDBTx::try_replace_chunk(smart_contract, slot_desc, chunk)` uses `smart_contract` only to resolve which DB row/table to check version/signer against (`get_slot_validation`), and then verifies the signature with `slot_desc.verify(&slot_validation.signer)`, which is exactly the contract-agnostic digest above: [4](#0-3) 

Both the RPC POST-chunk handler and the P2P gossip/relay handler call `try_replace_chunk` per-contract with attacker/peer-supplied `StackerDBChunkData`, and successful writes are re-broadcast network-wide: [5](#0-4) [6](#0-5) 

Exploit flow: attacker owns slot 3 in contract A (signer address `X`) and observes that `X` is also configured as slot 3's signer in contract B (a realistic scenario since signer sets for consecutive reward-cycle StackerDB contracts are frequently derived from the same address ordering, causing address-to-slot-index reuse across contracts). Attacker signs `StackerDBChunkData{slot_id:3, slot_version:5, data}` once for contract A. This exact wire message (unmodified `sig`) is then POSTed/gossiped against contract B. `try_replace_chunk(&sc_B, &md, &data)` resolves `sc_B`'s slot 3 signer as `X`, calls `slot_desc.verify(&X)`, which recomputes the same contract-agnostic digest and recovers `X` — verification succeeds even though the message was never signed for contract B. The chunk is written into contract B's StackerDB and rebroadcast to the network as if legitimately produced for B.

### Impact Explanation
This allows unauthenticated/unauthorized write of forged content into a StackerDB contract the attacker did not intend to write to (or in cases where the attacker doesn't even hold a key for contract B directly under a different identity, if slot ownership overlaps by coincidence of address reuse across configs) and causes that forged chunk to propagate network-wide via `process_stacker_db_chunks`'s broadcast. This matches the Critical category "unauthenticated/unauthorized write to state or StackerDB, network-wide propagation of forged data."

### Likelihood Explanation
Requires that the same signer address is configured as the same slot index's owner in two different StackerDB contracts simultaneously loaded via `stacker_db_configs`. This is plausible in real signer-set deployments (e.g., recurring signer sets across consecutive reward-cycle StackerDB contracts producing identical address ordering / slot assignment). No privileged access is needed beyond legitimately owning one slot; the attacker only replays their own previously-produced, validly-signed message against a different, remotely reachable P2P/RPC endpoint.

### Recommendation
Include the `QualifiedContractIdentifier` (and ideally the reward-cycle/DB configuration hint) in `SlotMetadata::auth_digest`, e.g. hash `smart_contract.to_string().as_bytes()` (or its serialized bytes) alongside `slot_id`, `slot_version`, and `data_hash`, and thread the contract identifier into `sign`/`verify` calls so a chunk signature is cryptographically bound to the specific StackerDB contract it targets.

### Proof of Concept
Rust test in `stackslib/src/net/stackerdb/tests/db.rs` style:
1. Create two `StackerDBs` (or two `QualifiedContractIdentifier`s `sc_a`, `sc_b`) each configured via `create_stackerdb` with the same `StacksAddress` (from private key `pk`) as slot 3's signer.
2. Build `chunk_data = StackerDBChunkData{slot_id:3, slot_version:5, data}` and `chunk_data.sign(&pk)`.
3. Call `tx.try_replace_chunk(&sc_a, &chunk_data.get_slot_metadata(), &chunk_data.data)` — succeeds (expected).
4. Call `tx.try_replace_chunk(&sc_b, &chunk_data.get_slot_metadata(), &chunk_data.data)` using the *same unmodified* `chunk_data`/`sig` — assert this also returns `Ok(())`, proving the signature intended only for `sc_a` is accepted for `sc_b`. This assertion succeeding demonstrates the missing contract binding described above (`libstackerdb/src/libstackerdb.rs:160-166`).

    pub fn sign(&mut self, privkey: &StacksPrivateKey) -> Result<(), Error> {
        let auth_digest = self.auth_digest();
        let sig = privkey
            .sign(&auth_digest.0)
            .map_err(|se| Error::SigningError(se.to_string()))?;

        self.signature = sig;
        Ok(())
    }

    /// Verify that a given principal signed this chunk metadata.
    /// Note that the address version is ignored.
    pub fn verify(&self, principal: &StacksAddress) -> Result<bool, Error> {
        let sigh = self.auth_digest();
        let pubk = StacksPublicKey::recover_to_pubkey_without_validating_low_s(
            sigh.as_bytes(),
            &self.signature,
        )
        .map_err(|ve| Error::VerifyingError(ve.to_string()))?;

        let pubkh = Hash160::from_node_public_key(&pubk);
        Ok(pubkh == *principal.bytes())
    }
}

    pub fn try_replace_chunk(
        &self,
        smart_contract: &QualifiedContractIdentifier,
        slot_desc: &SlotMetadata,
        chunk: &[u8],
    ) -> Result<(), net_error> {
        // Check per-replica chunk-size cap.
        if (chunk.len() as u64) > self.config.chunk_size {
            return Err(net_error::StackerDBChunkTooBig(chunk.len()));
        }

        let slot_validation = self
            .get_slot_validation(smart_contract, slot_desc.slot_id)?
            .ok_or(net_error::NoSuchSlot(
                smart_contract.clone(),
                slot_desc.slot_id,
            ))?;

        if !slot_desc.verify(&slot_validation.signer)? {
            return Err(net_error::BadSlotSigner(
                slot_validation.signer,
                slot_desc.slot_id,
            ));
        }
        if slot_desc.slot_version <= slot_validation.version {
            return Err(net_error::StaleChunk {
                supplied_version: slot_desc.slot_version,
                latest_version: slot_validation.version,
            });
        }
        if slot_desc.slot_version > self.config.max_writes {
            return Err(net_error::TooManySlotWrites {
                supplied_version: slot_desc.slot_version,
                latest_version: slot_validation.version,
                max_writes: self.config.max_writes,
            });
        }
        self.insert_chunk(smart_contract, slot_desc, chunk)
    }
