### Title
VotePacketReceiver::buffer_packet_batch ingests sigverify-failed (discard-flagged) vote packets into VoteStorage - (File: core/src/banking_stage/vote_packet_receiver.rs)

### Summary
`SigVerifyWorkerPool::run_transaction_task` verifies each packet in a batch with `ed25519_verify_serial`, which marks *individual* failed packets with `packet.meta_mut().set_discard(true)` while leaving the rest of the batch intact [1](#0-0) , and the batch is only fully dropped when the entire batch fails (`discard_or_dedup_fail == batch_len`) or no packet passed at all (`num_valid_packets == 0`) [2](#0-1) [3](#0-2) . A mixed batch (one valid + N forged-signature vote packets) is therefore forwarded whole to `tpu_vote_sender` with per-packet discard flags set. `VotePacketReceiver::buffer_packet_batch` then iterates every packet in that `BankingPacketBatch` and processes/inserts it into `VoteStorage` **without ever checking `packet.meta().discard()`**, unlike the sibling `forwarding_stage.rs::buffer_packet_batches`, which explicitly filters via `initial_packet_meta_filter` on the discard flag before use [4](#0-3) .

### Finding Description
`buffer_packet_batch` in `core/src/banking_stage/vote_packet_receiver.rs` loops `for packet in packet_batch.iter()`, extracts `packet.data(..)`, sanitizes it via `SanitizedTransactionView::try_new_sanitized`, and if it parses/sanitizes successfully calls `vote_storage.insert_packet(vote_source, packet)` — at no point is `packet.meta().discard()` consulted [5](#0-4) . `packet.meta().discard()` is a separate metadata flag from packet data availability (as confirmed by the comment in `forwarding_stage.rs`: "packet.meta().discard() was already checked. If not discarded, packet MUST have data") [6](#0-5) , meaning a packet whose signature verification failed still carries fully-readable (attacker-controlled) transaction bytes and will pass through `data(..)` unaffected.

Upstream, `SigVerifyWorkerPool::run_transaction_task` runs `ed25519_verify_serial` per-packet and marks only the failing packets discarded, not the whole batch [7](#0-6) ; it forwards the batch to `banking_stage_sender`/`tpu_vote_sender` as soon as at least one packet in the batch is valid [8](#0-7) . Since `VotePacketReceiver` is the direct consumer of that `tpu_vote_sender` channel via `VoteWorker::run` → `tpu_receiver.receive_and_buffer_packets` → `receive_until_and_buffer` → `buffer_packet_batch` [9](#0-8) [10](#0-9) , any forged-signature packet co-located in the same batch as one legitimate valid vote reaches `VoteStorage::insert_packet` unfiltered.

An unprivileged attacker connecting to the TPU-vote QUIC/UDP port can trivially construct such a mixed batch: send one syntactically-valid signed vote transaction plus N packets with tampered/forged signatures for the same underlying message/batch. Because the discard flag is per-packet and the batch is not entirely dropped, all N forged packets pass into `VoteStorage` unauthenticated.

### Impact Explanation
Unauthenticated/forged vote transaction data enters `VoteStorage` and is subsequently consumed by `VoteWorker`/`Consumer` for potential inclusion or processing in leader block-building logic, violating the stated invariant that "no path marks a packet verified without checking it." This is a signature-verification bypass at the vote-ingestion boundary — data that sigverify explicitly rejected is still treated as buffered vote data downstream, which is a verification-bypass class finding under the Agave bounty categories.

### Likelihood Explanation
Highly feasible and repeatable: the attacker needs only an unstaked QUIC/UDP connection to the TPU-vote port, no cluster stake, no config, and no operator collusion. Constructing a batch containing one valid signature and arbitrary forged signatures is a normal client operation (just corrupt the signature bytes of extra packets). The condition (`discard_or_dedup_fail != batch_len` and `num_valid_packets != 0`) is trivially satisfied by including exactly one valid packet.

### Recommendation
Add a `!packet.meta().discard()` guard in `VotePacketReceiver::buffer_packet_batch` before parsing/inserting each packet (mirroring `forwarding_stage.rs`'s `initial_packet_meta_filter` check), so that packets marked discarded by sigverify are always skipped regardless of the rest of the batch's status.

### Proof of Concept
Integration test outline (extends existing test scaffolding in `core/src/banking_stage/vote_packet_receiver.rs` tests module):
```rust
#[test]
fn test_buffer_packet_batch_skips_discarded_packets() {
    let keypairs = ValidatorVoteKeypairs::new_rand();
    // valid vote packet
    let valid_packet = packet_from_slots(vec![(1, 1)], &keypairs, None);
    // forged/corrupted-signature packet built the same way, then tamper its signature bytes
    let mut forged_packet = packet_from_slots(vec![(2, 1)], &keypairs, None);
    // simulate sigverify having flagged it as failed (as ed25519_verify_serial would):
    forged_packet.meta_mut().set_discard(true);

    let (sender, receiver) = bounded(1024);
    sender.send(Arc::new(PacketBatch::from(vec![valid_packet, forged_packet]))).unwrap();

    let mut vote_receiver = VotePacketReceiver::new(receiver, Arc::new(HashSet::new()));
    let (bank, _bank_forks) = /* build test bank with vote accounts */;
    let mut vote_storage = VoteStorage::new(&bank);
    let mut banking_stage_stats = BankingStageStats::new();
    let mut slot_metrics_tracker = LeaderSlotMetricsTracker::default();

    vote_receiver.receive_and_buffer_packets(
        &mut vote_storage, &mut banking_stage_stats, &mut slot_metrics_tracker, VoteSource::Tpu,
    ).unwrap();

    // Expected (fixed) behavior: only the valid packet is buffered.
    assert_eq!(vote_storage.len(), 1);
    // Current (vulnerable) behavior: len() == 2, i.e., the discard-flagged forged packet
    // was also inserted, proving the bypass.
}
```
This directly demonstrates that `buffer_packet_batch` currently inserts discard-flagged packets into `VoteStorage`, confirming the bypass without requiring the full `SigVerifyStage` wiring (since the discard flag itself is the exact artifact `ed25519_verify_serial` produces on verification failure).

pub fn ed25519_verify_serial(batch: &mut PacketBatch, reject_non_vote: bool, enable_tx_v1: bool) {
    for mut packet in batch.iter_mut() {
        if !packet.meta().discard() && !verify_packet(&mut packet, reject_non_vote, enable_tx_v1) {
            packet.meta_mut().set_discard(true);
        }
    }

    fn buffer_packet_batch(
        &self,
        packet_batch: &BankingPacketBatch,
        sanitize_config: &SanitizeConfig,
        vote_storage: &mut VoteStorage,
        vote_source: VoteSource,
        slot_metrics_tracker: &mut LeaderSlotMetricsTracker,
        stats: &mut ReceiveAndBufferStats,
    ) {
        stats.num_packets_received += packet_batch.len();

        for packet in packet_batch.iter() {
            let Some(packet_data) = packet.data(..) else {
                continue;
            };

            match SanitizedTransactionView::try_new_sanitized(
                packet_bytes(packet, packet_data),
                sanitize_config,
            ) {
                Ok(packet) => {
                    if self.should_filter_packet(&packet) {
                        stats.packet_stats.filtered_account_key_count += 1;
                        continue;
                    }

                    stats.num_buffered_packets += 1;
                    let vote_insertion_metrics = vote_storage.insert_packet(vote_source, packet);
                    slot_metrics_tracker.accumulate_vote_insertion_metrics(&vote_insertion_metrics);
                    stats.dropped_packets_count += vote_insertion_metrics.total_dropped_packets();
                }
                Err(err) => {
                    stats.errors += 1;
                    match err {
                        TransactionViewError::AddressLookupMismatch => {}
                        TransactionViewError::ParseError | TransactionViewError::SanitizeError => {
                            stats.packet_stats.failed_sanitization_count += 1
                        }
                    }
                }
            }
        }
    }
