### Title
`UserApplyPatch` writes new commit objects directly into the live object database instead of a quarantine directory, unlike every other object-creating mutation RPC - ([File: internal/gitaly/service/operations/apply_patch.go])

### Summary
Every other object-creating write RPC in `internal/gitaly/service/operations` (`UserFFBranch`, `UserCreateTag`, `userSquash`, `userCommitFiles`, `UserCherryPick`, `UserRevert`, `UserMergeBranch`, `UserRebaseConfirmable`, etc.) stages newly created objects in a quarantine directory via `s.quarantinedRepo()` before running hooks, and only calls `quarantineDir.Migrate(ctx)` to move them into the repository's real object directory after the reference update / hooks succeed. `UserApplyPatch` is missing this quarantine step entirely — it is the "missing modifier" analog to the Sherlock finding, where one function in a family of otherwise-uniform functions omits a step (there `gemCollecting`, here quarantine staging) that all its siblings perform.

### Finding Description
In `internal/gitaly/service/operations/apply_patch.go`, `userApplyPatch()` builds the repository directly from the request with no quarantine wrapper: [1](#0-0) 

It then writes tree/commit objects for each patch straight into that non-quarantined repo via `applyPatchesWithIndex` → `applyPatchToTreeish` → `repo.WriteCommit(...)`: [2](#0-1) 

Finally it calls `s.updateReferenceWithHooks(ctx, header.GetRepository(), header.GetUser(), nil, targetBranch, patchedCommit, currentCommit)`, passing `nil` for the quarantine directory argument: [3](#0-2) 

Compare this to every sibling RPC, which all call `s.quarantinedRepo(ctx, ...)` first, perform all object creation against the returned `quarantineRepo`, and pass the resulting `quarantineDir` into `updateReferenceWithHooks`, e.g. `UserFFBranch`: [4](#0-3) [5](#0-4) 

and `UserCreateTag`: [6](#0-5) [7](#0-6) 

The shared helper that all these RPCs use is: [8](#0-7) 

The quarantine mechanism exists precisely so that objects created by an RPC are isolated in a temporary alternate object directory and only migrated into the real object directory (`quarantineDir.Migrate(ctx)`) after the pre-receive/update hooks accept the change — this lets a custom `pre-receive` hook see and reject the objects (via `gitcmd.WithRefTxHook`/hook environment) without those objects ever having landed in the permanent object store, as confirmed by the "uses quarantine repo" test for `ResolveConflicts` that explicitly checks no new objects remain after a hook rejects the change: [9](#0-8) 

Because `UserApplyPatch` skips quarantine, the commit/tree objects for every parsed patch are written directly to the repository's primary object directory *before* `updateReferenceWithHooks` runs the pre-receive hook. If the custom hook denies the update, or `updateReferenceWithHooks` fails/errors for any other reason (race on ref update, transaction abort, etc.), the already-written commit and tree objects are never quarantined and are never cleaned up — they permanently pollute the repository's real object database, unlike every sibling RPC which cleans them up implicitly by simply discarding the (never-migrated) quarantine directory via `defer cleanup()`.

### Impact Explanation
This causes unauthorized/rejected object persistence: an ordinary user invoking `UserApplyPatch` with a patch series that is ultimately rejected by a `pre-receive` custom hook (or that races/fails on the reference update) leaves orphaned, unreachable commit and tree objects permanently in the repository's live `objects/` directory. This breaks the security invariant (enforced everywhere else in this RPC family and explicitly tested for) that objects created by a rejected mutation must never reach the real object store — it undermines repository administrators' ability to rely on `pre-receive` hooks as a gate against unwanted object creation, can be used to smuggle unreviewed blob/commit content into a project's object database (later reachable via crafted refs or dangling-object grafting techniques), and produces unbounded storage growth/DoS potential from repeated rejected calls since no cleanup path exists for these non-quarantined objects.

### Likelihood Explanation
High reachability: `UserApplyPatch` is a standard, unprivileged-facing gRPC mutation RPC reachable by any client authorized to write to the target repository (the same trust level as `UserCommitFiles`, `UserMergeBranch`, etc.), and repositories commonly have custom `pre-receive` hooks configured by administrators specifically to reject certain content. Triggering the bug requires no special conditions beyond a patch series and a hook (or unrelated failure) that causes `updateReferenceWithHooks` to return an error after objects have already been written — a normal, expected code path.

### Recommendation
Refactor `userApplyPatch` to obtain a quarantined repository the same way all sibling RPCs do:
1. Call `quarantineDir, quarantineRepo, cleanup, err := s.quarantinedRepo(ctx, header.GetRepository())`, `defer cleanup()`.
2. Perform `applyPatchesWithIndex` and all tree/commit writes against `quarantineRepo` instead of `repo`.
3. Pass `quarantineDir` (not `nil`) into `s.updateReferenceWithHooks(...)` so the migration only occurs after hooks/voting succeed, matching the pattern in `ff_branch.go`, `tags.go`, `squash.go`, and `commit_files.go`.

### Proof of Concept
1. Create a repository with a custom `pre-receive` hook that always exits non-zero (rejecting every push), similar to the existing test setup for `ResolveConflicts`: [10](#0-9) 
2. Record the object count in the repository (`git rev-list --objects --all`).
3. Call `UserApplyPatch` with a valid mailbox-format patch targeting a branch in that repository.
4. Observe the RPC fails with a custom-hook-denied error (as expected), but the object count in the repository has increased — new commit/tree objects created by `applyPatchesWithIndex`/`repo.WriteCommit` remain in the real object directory, whereas the equivalent test for `ResolveConflicts` (which does use quarantine) asserts `objectsAfter == objectsBefore` in this exact scenario: [11](#0-10)

func (s *Server) applyPatchesWithIndex(
	ctx context.Context,
	repo *localrepo.Repo,
	parentCommitID git.ObjectID,
	committerSignature git.Signature,
	stream gitalypb.OperationService_UserApplyPatchServer,
) (git.ObjectID, error) {
	tempDir, err := repo.StorageTempDir()
	if err != nil {
		return "", fmt.Errorf("locating temporary directory: %w", err)
	}

	workDir, err := os.MkdirTemp(tempDir, "apply-patch-")
	if err != nil {
		return "", fmt.Errorf("creating work directory: %w", err)
	}
	defer func() {
		_ = os.RemoveAll(workDir)
	}()

	mboxReader := streamio.NewReader(func() ([]byte, error) {
		req, err := stream.Recv()
		return req.GetPatches(), err
	})

	patches, err := splitAndParseMailbox(ctx, repo, mboxReader, workDir)
	if err != nil {
		return "", fmt.Errorf("parsing mailbox: %w", err)
	}

	currentCommitID := parentCommitID
	for i, patch := range patches {
		perPatchWorkdir := filepath.Join(workDir, strconv.Itoa(i))
		if err := os.Mkdir(perPatchWorkdir, mode.Directory); err != nil {
			return "", fmt.Errorf("creating work directory for patch %d: %w", i, err)
		}

		treeID, err := applyPatchToTreeish(ctx, repo, perPatchWorkdir, currentCommitID, patch)
		if err != nil {
			var conflictErr *localrepo.MergeTreeConflictError
			if errors.As(err, &conflictErr) {
				return "", structerr.NewFailedPrecondition("Patch failed at %04d %s: %w", i+1, patch.subject, err)
			}

			return "", fmt.Errorf("applying patch %d: %w", i+1, err)
		}

		_ = os.RemoveAll(perPatchWorkdir)

		authorDate := patch.authorDate
		if authorDate.IsZero() {
			authorDate = committerSignature.When
		}

		commitMessage := patch.subject + "\n"
		if body := strings.Trim(patch.body, "\n"); body != "" {
			commitMessage += "\n" + body + "\n"
		}

		commitID, err := repo.WriteCommit(ctx, localrepo.WriteCommitConfig{
			Parents:        []git.ObjectID{currentCommitID},
			TreeID:         treeID,
			AuthorName:     patch.authorName,
			AuthorEmail:    patch.authorEmail,
			AuthorDate:     authorDate,
			CommitterName:  committerSignature.Name,
			CommitterEmail: committerSignature.Email,
			CommitterDate:  committerSignature.When,
			Message:        commitMessage,
		})
		if err != nil {
			return "", fmt.Errorf("committing patch %d: %w", i+1, err)
		}

		currentCommitID = commitID
	}

func (s *Server) quarantinedRepo(ctx context.Context, repo *gitalypb.Repository) (*quarantine.Dir, *localrepo.Repo, func(), error) {
	quarantineDir, cleanup, err := quarantine.New(ctx, repo, s.logger, s.locator)
	if err != nil {
		return nil, nil, nil, structerr.NewInternal("creating object quarantine: %w", err)
	}

	quarantineRepo := s.localRepoFactory.Build(quarantineDir.QuarantinedRepo())
	return quarantineDir, quarantineRepo, cleanup, nil
}
