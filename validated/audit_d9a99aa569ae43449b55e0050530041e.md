### Title
Fee waiver on NEP-245/IMT `TokenDiff` legs with `amount <= 1` lets attackers move unlimited volume fee-free by splitting trades - ([File: contracts/defuse/core/src/intents/token_diff.rs])

### Summary
`TokenDiff::token_fee()` waives the protocol fee entirely whenever a NEP-245 (multi-token) or IMT leg has `|delta| <= 1`. Because the fee check is evaluated per-`TokenDiff`-intent rather than against the aggregate economic value exchanged, an attacker can split any large NEP-245/IMT swap into many unit-sized (`delta == ±1`) `TokenDiff` intents that net to the same total transfer, paying zero protocol fee on the whole trade instead of `fee_ceil(total_amount)`.

### Finding Description
`TokenDiff::execute_intent` computes the fee to collect purely from the magnitude of the negative delta declared in *that single intent*: [1](#0-0) 

The per-token fee rate itself is determined by `token_fee()`: [2](#0-1) 

For `TokenIdType::Nep245` and `TokenIdType::Imt`, the fee is forced to `Pips::ZERO` whenever the delta amount in that intent is `<= 1`. This waiver is legitimate for genuinely atomic single-unit transfers (e.g., NFT-like items), but nothing ties it to the *total* volume moved by a signer for that token — only to the size of the individual `TokenDiff.diff` entry being executed.

Settlement correctness (conservation) is enforced globally across the whole batch of signed intents via `TransferMatcher`/`Deltas::finalize()`, which only checks that summed deltas per token net to zero across all intents in the call — it has no concept of "fee owed per total volume": [3](#0-2) 

Because of this, an attacker (as maker, or self-trading as both maker and taker, or colluding with a second account) can decompose a NEP-245/IMT trade of size `N` into `N` separate signed `TokenDiff` intents, each with `delta = -1` on the token being given up and a matching `delta = +1` counter-leg from the counterparty, submitted together in one `execute_intents`/`MultiPayload` batch (or across several calls). Each of the `N` legs independently qualifies for the `amount <= 1` fee waiver, so `fees_collected` is `0` for every leg, and the fee collector's balance receives nothing for the entire `N`-unit trade — whereas an equivalent single `TokenDiff` intent moving `N` units at once would have incurred `fee.fee_ceil(N)`.

This breaks the "fees owed versus fees collected" invariant: the economically-equivalent trade of size `N` should collect a non-zero fee (for `N>1`, since `token_fee` only zeroes fee when `amount<=1`), but the value actually collected is `0` because the protocol evaluates the fee waiver per-intent instead of per aggregate transferred value.

### Impact Explanation
This is a systemic fee-bypass: any user trading NEP-245 or IMT-denominated assets through the intents settlement engine can avoid the protocol fee entirely for arbitrarily large amounts by chunking the swap into unit-sized legs, which matches the "fees owed versus fees collected" boundary explicitly called out as Critical impact ("fees bypassed or over-collected"). It causes concrete, quantifiable loss of protocol revenue proportional to trade volume, with no privileged role, DAO action, or victim key required — only ordinary signed intents from the attacker's own account(s).

### Likelihood Explanation
Likelihood is high: constructing multiple `TokenDiff` intents with `delta = ±1` and batching them in a single `execute_intents`/`MultiPayload` call (or across sequential calls, since fee is evaluated per-intent regardless of batching) requires no special permissions — any account holding NEP-245/IMT balances in the intents contract can do this. The only cost to the attacker is additional transaction/gas overhead for signing and submitting more intents, which is a modest, predictable cost relative to the fee saved on large trades.

### Recommendation
Do not waive the fee purely based on the per-intent delta magnitude for NEP-245/IMT tokens. Options:
- Base the `amount <= 1` fee waiver on the *token's own supply/decimals semantics* (e.g., only waive fee for tokens that are provably non-fungible, i.e., truly unit-supply NFTs), rather than on the transient size of a single `TokenDiff` leg.
- If the waiver is meant only to avoid dust/rounding issues, apply it consistently by tracking per-signer, per-token cumulative volume within a settlement (or globally, e.g., over a time window) rather than per individual intent, so splitting into many unit legs cannot zero out the aggregate fee.
- Alternatively, remove the `amount <= 1` special case for `Nep245`/`Imt` and require callers to specify whether a given `TokenId` behaves as fungible (fee always applies) or non-fungible (fee never applies), removing amount-dependent branching entirely.

### Proof of Concept
1. Deploy the defuse contract with a non-zero `fee` (`Pips`) and a NEP-245/IMT token registered as a tradable `TokenId` (`TokenIdType::Nep245` or `Imt`).
2. Attacker account `A` (optionally colluding with `B`, or trading with itself across separate signed intents/nonces) wants to swap `N` units of NEP-245 token `X` for token `Y`.
3. Instead of signing one `TokenDiff` intent `{X: -N, Y: +M}` (which would incur `fee.fee_ceil(N)` per `token_fee()`/`execute_intent` at [4](#0-3) ), `A` signs `N` separate `TokenDiff` intents, each `{X: -1, Y: +M/N}`, matched by `N` corresponding counter-leg intents from `B` (or from `A`'s own second signed nonce) each `{X: +1, Y: -M/N}`.
4. Submit all `2N` intents together via `execute_intents`. Each leg has `amount == 1` on token `X` (NEP-245/IMT), so `token_fee()` returns `Pips::ZERO` for every leg, and `fees_collected` stays empty for all `N` iterations of the loop at [5](#0-4) .
5. `TransferMatcher::finalize()` nets the `N` unit deltas per account into the same aggregate transfers as the single large trade would have produced, so the batch passes the conservation invariant with no error, but `engine.state.fee_collector()` receives `0` fee total for the `N`-unit trade, versus `fee.fee_ceil(N) > 0` that a single un-split `TokenDiff` of the same size would have paid.

    // Finalizes all transfers, or returns unmatched deltas.
    // If unmatched deltas overflow, then Err(None) is returned.
    pub fn finalize(self) -> Result<Transfers, InvariantViolated> {
        let mut transfers = Transfers::default();
        let mut deltas = TokenDeltas::default();
        for (token_id, transfer_matcher) in self.0 {
            if let Err(unmatched) = transfer_matcher.finalize_into(&token_id, &mut transfers)
                && (unmatched == 0 || deltas.apply_delta(token_id, unmatched).is_none())
            {
                return Err(InvariantViolated::Overflow);
            }
        }
        if !deltas.is_empty() {
            return Err(InvariantViolated::UnmatchedDeltas {
                unmatched_deltas: deltas,
            });
        }
        Ok(transfers)
    }
}
