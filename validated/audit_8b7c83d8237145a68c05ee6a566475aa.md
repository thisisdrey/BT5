### Title
Check-then-act race in replay-window verification permits duplicate packet reprocessing across concurrent reader routines - (File: connection_state.go)

### Summary
`ConnectionState.Decrypt` (and `VerifyRelay`) split the anti-replay bookkeeping into two separately-locked steps with the AEAD decryption in between: `window.Check()` is called and the lock released, decryption happens unlocked, then `window.Update()` is called under the lock again. This is the same "check state, perform an unprotected side-effecting operation, then commit state" pattern that made the Curves.sol reentrancy bug possible: an operation is authorized based on a pre-side-effect state snapshot, but the state that would prevent the operation from being repeated is not committed until after the side effect runs, leaving a window in which the same authorization can be granted twice.

### Finding Description
`Decrypt` in [1](#0-0)  performs:
1. `decryptLock.Lock(); result := cs.window.Check(...); decryptLock.Unlock()`
2. AEAD `DecryptDanger` (no lock held)
3. `decryptLock.Lock(); result = cs.window.Update(...); decryptLock.Unlock()`

`VerifyRelay` has the identical structure at [2](#0-1) .

Because the lock is released between `Check` and `Update`, this is a classic TOCTOU/check-then-act race, not an atomic check-and-set. When Nebula is configured with `routines`/`listen.batch` > 1 (multi-queue UDP reading), multiple goroutines call `readOutsidePackets` → `hostinfo.ConnectionState.Decrypt` concurrently for packets that land on the same underlay socket set, as shown by the `f.routines` fan-out in `run()`/`listenOut` at [3](#0-2) , feeding into `outside.go`'s `readOutsidePackets` at [4](#0-3) .

If a remote peer (or an on-path attacker who does not need a valid CA-signed certificate — replay only requires capturing/duplicating a previously-observed ciphertext packet on the wire, e.g. via UDP retransmission at the network layer) causes the *same* message counter to be delivered to two different reader routines before either finishes, both goroutines can pass `Check` (since the bit for that counter has not yet been set), both successfully decrypt the same valid ciphertext, and only the loser of the race on `Update` is rejected — after already having decrypted and, depending on caller path, delivered the plaintext once. This defeats the intended one-shot guarantee of the anti-replay window and allows the exact same on-wire message to be accepted and processed by the packet-handling logic more than once.

This mirrors the reported bug class precisely: an authorization check is performed against state that is separated by an unlocked "external effect" (here, decryption/processing) from the final state commit (`Update`), so a second concurrent execution can slip through the gap before the state guarding against duplicates is actually persisted.

### Impact Explanation
A successful race lets an attacker who can duplicate/replay a captured ciphertext packet at the UDP layer force the same authenticated message to be delivered twice into `handleOutsideMessagePacket`/`handleOutsideRelayPacket`/`lhf.HandleRequest` processing paths, undermining the nonce-based anti-replay guarantee that `ReplayWindow`/`Bits` is specifically designed to enforce. Depending on downstream idempotency this can lead to duplicate tunnel packet delivery, duplicate control-message processing (e.g., relay establishment control messages routed through `header.Control` in `outside.go`), or other state confusion from replayed application data — a remote state-poisoning/replay-bypass impact reachable without holding a CA-signed certificate, only requiring interception/duplication of already-observed ciphertext.

### Likelihood Explanation
Exploitability depends on the deployment running with `routines > 1` (or `listen.batch/tun.routines` > 1), which fans inbound UDP reads across multiple goroutines sharing the same `HostInfo`/`ConnectionState`. Given that configuration, the race window between `Check` and `Update` is real (the lock is explicitly dropped for the decrypt call, per the code), and an attacker only needs to get the OS/network layer to deliver two copies of the same UDP datagram in close succession (trivial to do on-path, or via off-path duplicate injection since Nebula runs over UDP). This is a genuine, but timing-dependent, concurrency bug — likelihood is moderate and scales with reader routine count and attacker's ability to inject duplicate packets in a tight window.

### Recommendation
Combine the check and update into a single atomic critical section instead of two separately-locked steps around the unlocked decrypt call, e.g. hold `decryptLock` (or a per-counter reservation) across `Check`, decrypt, and `Update`, or restructure `Bits` to support a single `CheckAndReserve`/`CheckAndCommit` operation performed while the lock is held for the whole sequence, with decrypt work retried/aborted safely if reservation fails. At minimum, perform `Check` immediately followed by a provisional `set`/reservation under the same lock acquisition before releasing it for decryption, then finalize or roll back after decrypt completes.

### Proof of Concept
Not independently reproducible without running the live multi-routine binary; the race requires: (1) starting Nebula with `routines` (or legacy `tun.routines`/`listen.routines`) > 1 so multiple goroutines call `ConnectionState.Decrypt` concurrently for the same `HostInfo`, and (2) delivering two copies of the same captured ciphertext UDP datagram to the underlay socket in quick succession so both reader goroutines' `Check` calls race before either `Update` commits. The code path enabling this is shown at [1](#0-0)  and the concurrent-reader fan-out at [3](#0-2) .

func (cs *ConnectionState) Decrypt(l *slog.Logger, messageCounter uint64, out []byte, packet []byte, nb []byte) ([]byte, error) {
	var err error
	cs.decryptLock.Lock()
	result := cs.window.Check(l, messageCounter)
	cs.decryptLock.Unlock()
	if !result {
		return nil, ErrAlreadySeen
	}

	out, err = cs.dKey.DecryptDanger(out, packet[:header.Len], packet[header.Len:], messageCounter, nb)
	if err != nil {
		return nil, err
	}

	cs.decryptLock.Lock()
	result = cs.window.Update(l, messageCounter)
	cs.decryptLock.Unlock()
	if !result {
		return nil, ErrAlreadySeen
	}
	return out, nil
}

func (cs *ConnectionState) VerifyRelay(l *slog.Logger, messageCounter uint64, packet []byte, nb []byte) error {
	cs.decryptLock.Lock()
	result := cs.window.Check(l, messageCounter)
	cs.decryptLock.Unlock()
	if !result {
		return ErrAlreadySeen
	}

	signedPayload := packet[:len(packet)-cs.dKey.Overhead()]
	signatureValue := packet[len(packet)-cs.dKey.Overhead():]
	_, err := cs.dKey.DecryptDanger(nil, signedPayload, signatureValue, messageCounter, nb)
	if err != nil {
		return err
	}

	cs.decryptLock.Lock()
	result = cs.window.Update(l, messageCounter)
	cs.decryptLock.Unlock()
	if !result {
		return ErrAlreadySeen
	}

	return nil
}

func (f *Interface) run() {
	// Launch n queues to read packets from udp
	for i := 0; i < f.routines; i++ {
		f.wg.Go(func() {
			f.listenOut(i)
		})
	}

	// Launch n queues to read packets from tun dev
	for i := 0; i < f.routines; i++ {
		f.wg.Go(func() {
			f.listenIn(f.readers[i], i)
		})
	}

}

func (f *Interface) wait() error {
	f.wg.Wait()
	if e := f.fatalErr.Load(); e != nil {
		return *e
	}
	return nil
}

// onFatal stores the first fatal reader error, and calls triggerShutdown if it was the first one
func (f *Interface) onFatal(err error) {
	swapped := f.fatalErr.CompareAndSwap(nil, &err)
	if !swapped {
		return
	}
	if f.triggerShutdown != nil {
		f.triggerShutdown()
	}
}

func (f *Interface) listenOut(i int) {
	var li udp.Conn
	if i > 0 {
		li = f.writers[i]
	} else {
		li = f.outside
	}

	ctCache := firewall.NewConntrackCacheTicker(f.ctx, f.l, f.conntrackCacheTimeout)
	lhh := f.lightHouse.NewRequestHandler()
	plaintext := make([]byte, udp.MTU)
	h := &header.H{}
	fwPacket := &firewall.Packet{}
	nb := make([]byte, 12, 12)

	err := li.ListenOut(func(fromUdpAddr netip.AddrPort, payload []byte) {
		f.readOutsidePackets(ViaSender{UdpAddr: fromUdpAddr}, plaintext[:0], payload, h, fwPacket, lhh, nb, i, ctCache.Get())
	})

	// An error after teardown began is shutdown noise, the closed flag covers resources
	// Close releases itself and the cancelled ctx covers ones torn down by their owners
	// reacting to it, like the user device pipes
	if err != nil && !f.closed.Load() && f.ctx.Err() == nil {
		f.l.Error("Error while reading inbound packet, closing", "error", err)
		f.onFatal(err)
	}

	f.l.Debug("underlay reader is done", "reader", i)
}
