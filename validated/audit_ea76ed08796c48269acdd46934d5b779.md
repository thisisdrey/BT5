## Analog Found

### Title
Integer Overflow in `VOTEWITNESS` Energy Metering Enables Energy-Charge Bypass / Memory-Exhaustion DoS - (File: `actuator/src/main/java/org/tron/core/vm/EnergyCost.java`)

### Summary
The CVE-2021-28025 bug class is an integer-overflow in a length/size computation that a local, low-privilege caller can trigger to cause a denial of service. In java-tron, the `VOTEWITNESS` TVM opcode's energy-cost calculation performs the analogous overflow: it multiplies attacker-controlled 256-bit stack values using `DataWord.mul()`, which wraps around silently instead of throwing, just like the unsigned/size-field overflow in Qt's `qsvghandler.cpp`.

### Finding Description
`EnergyCost.getVoteWitnessCost` and `getVoteWitnessCost2` compute the memory-expansion cost for the `VOTEWITNESS` opcode by taking attacker-supplied `DataWord` values straight off the EVM/TVM stack and multiplying them by the word size using `DataWord.mul()`: [1](#0-0) 

Because `DataWord` represents a fixed 256-bit value, `mul()` performs modular arithmetic and silently wraps on overflow rather than raising an error, exactly analogous to the fixed-size integer overflow that caused the Qt SVG DoS. This is confirmed by the project's own regression tests, which state the bug explicitly: [2](#0-1) 

A newer BigInteger-based cost function, `getVoteWitnessCost3`, was added specifically to detect this overflow and throw `Program.OutOfMemoryException`, but it is only used when `VMConfig.allowTvmOsaka()` is enabled; otherwise the vulnerable `cost2` (wrapping) path is used unconditionally: [3](#0-2) [4](#0-3) 

The actual opcode execution path (`voteWitnessAction`) pops the witness/amount array offsets and lengths independently via `intValueSafe()` and passes them to `program.voteWitness(...)`, so the real memory footprint requested by the opcode is driven by the raw (non-multiplied) stack values, while the energy charged for that memory is computed via the wrap-prone multiplication above: [5](#0-4) 

Because the two computations (energy cost vs. actual memory extension) diverge whenever the crafted length causes `DataWord.mul()` to overflow, a contract can obtain a systematically under-charged memory-expansion price for `VOTEWITNESS`, defeating the energy-metering protection that is supposed to bound `Memory.extend()` calls (see `checkMemorySize`/`MEM_LIMIT` guard in the same file): [6](#0-5) 

### Impact Explanation
Energy metering is the core resource-exhaustion defense for all TVM opcodes. An overflow that causes the mem-energy cost formula to wrap to a small value while the opcode is still permitted to request/extend memory undermines that defense for `VOTEWITNESS`, allowing an attacker-crafted contract call to under-pay for memory operations. Depending on how far the divergence propagates into `Program.voteWitness`'s actual array processing, this can enable memory-exhaustion style resource abuse within a single transaction, which is the same DoS bug class as the CVE. This is reachable by any account able to deploy/call a contract that executes the `VOTEWITNESS` opcode — no special privilege required.

### Likelihood Explanation
Reaching this code only requires deploying a smart contract that executes `VOTEWITNESS` with crafted stack operands (very large length/offset words) and calling it — an action any unprivileged transaction broadcaster/contract deployer can perform. The project's own tests demonstrate the overflow is trivially reproducible with a single `DataWord` value of `0xFF...FF`, and note that the wrap is only guarded when `allowTvmOsaka` (TIP-7883) is active, so on any deployment where that config is not yet enabled the vulnerable arithmetic path is exercised unconditionally.

### Recommendation
- Ensure `getVoteWitnessCost`/`getVoteWitnessCost2` never rely on `DataWord.mul()` (256-bit wraparound arithmetic) for cost-relevant size math; migrate all VOTEWITNESS energy accounting to the BigInteger-based `getVoteWitnessCost3` logic unconditionally (not gated behind `allowTvmOsaka`), or add explicit overflow checks before/after the multiplication in the legacy paths.
- Audit `Program.voteWitness` to confirm the real memory/array allocation is bounded independently of the (possibly wrapped) energy charge, and add a hard cap consistent with `MEM_LIMIT` regardless of which cost function computed the charge.
- Apply the same audit to any other opcode-cost helper in `EnergyCost.java` that still uses `DataWord.mul()`/`add()` on user-controlled stack words instead of `BigInteger` arithmetic.

### Proof of Concept
1. Deploy a contract whose bytecode executes `VOTEWITNESS` with a witness-array-length word set to `0xFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFF` (as used in `VoteWitnessCost3Test.testLargeArrayLengthOverflow`), while `allowTvmOsaka` is disabled (default/legacy behavior), so the node dispatches to `getVoteWitnessCost2`.
2. `DataWord.mul(wordSize)` silently wraps, so `calcMemEnergy` computes a small/near-zero memory cost instead of throwing `Program.Exception.memoryOverflow`, unlike the `cost3` path which is proven (in the same test) to throw `Program.OutOfMemoryException` for this exact input.
3. The transaction is charged the (incorrect) small energy fee for `VOTEWITNESS`'s memory expansion while `voteWitnessAction` proceeds to call `program.voteWitness` with the raw (unmultiplied) large length obtained via `intValueSafe()`, decoupling actual resource use from the energy paid.

**Note:** I was unable to inspect the body of `Program.voteWitness` (not present in the indexed excerpts) to confirm the exact downstream memory-allocation behavior once the mismatched length reaches it; this affects the precise severity (energy-bypass vs. full OOM crash) and should be verified directly in a full checkout of `actuator/src/main/java/org/tron/core/vm/program/Program.java`.

    if (!VMConfig.allowEnergyAdjustment()) {
      return getVoteWitnessCost(program);
    }

    Stack stack = program.getStack();
    long oldMemSize = program.getMemSize();
    DataWord amountArrayLength = stack.get(stack.size() - 1).clone();
    DataWord amountArrayOffset = stack.get(stack.size() - 2);
    DataWord witnessArrayLength = stack.get(stack.size() - 3).clone();
    DataWord witnessArrayOffset = stack.get(stack.size() - 4);

    DataWord wordSize = new DataWord(DataWord.WORD_SIZE);

    amountArrayLength.mul(wordSize);
    amountArrayLength.add(wordSize); // dynamic array length is at least 32 bytes
    BigInteger amountArrayMemoryNeeded = memNeeded(amountArrayOffset, amountArrayLength);

    witnessArrayLength.mul(wordSize);
    witnessArrayLength.add(wordSize); // dynamic array length is at least 32 bytes
    BigInteger witnessArrayMemoryNeeded = memNeeded(witnessArrayOffset, witnessArrayLength);

    return VOTE_WITNESS + calcMemEnergy(oldMemSize,
        (amountArrayMemoryNeeded.compareTo(witnessArrayMemoryNeeded) > 0
            ? amountArrayMemoryNeeded : witnessArrayMemoryNeeded), 0, Op.VOTEWITNESS);

  private static long calcMemEnergy(long oldMemSize, BigInteger newMemSize,
                             long copySize, int op) {
    long energyCost = 0;

    checkMemorySize(op, newMemSize);

    // memory SUN consume calc
    long memoryUsage = (newMemSize.longValueExact() + 31) / 32 * 32;
    if (memoryUsage > oldMemSize) {
      long memWords = (memoryUsage / 32);
      long memWordsOld = (oldMemSize / 32);
      long memEnergy = (MEMORY * memWords + memWords * memWords / 512)
          - (MEMORY * memWordsOld + memWordsOld * memWordsOld / 512);
      energyCost += memEnergy;
    }

    if (copySize > 0) {
      long copyEnergy = COPY_ENERGY * ((copySize + 31) / 32);
      energyCost += copyEnergy;
    }
    return energyCost;
  }

  private static void checkMemorySize(int op, BigInteger newMemSize) {
    if (newMemSize.compareTo(MEM_LIMIT) > 0) {
      throw Program.Exception.memoryOverflow(op);
    }
  }

  public static void voteWitnessAction(Program program) {
    if (program.isStaticCall()) {
      throw new Program.StaticCallModificationException();
    }

    int amountArrayLength = program.stackPop().intValueSafe();
    int amountArrayOffset = program.stackPop().intValueSafe();
    int witnessArrayLength = program.stackPop().intValueSafe();
    int witnessArrayOffset = program.stackPop().intValueSafe();

    boolean result = program.voteWitness(witnessArrayOffset, witnessArrayLength,
        amountArrayOffset, amountArrayLength);
    program.stackPush(result ? DataWord.ONE() : DataWord.ZERO());
    program.step();
  }
