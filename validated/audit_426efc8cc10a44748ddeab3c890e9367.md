## Title
Protocol fee on token swaps can be bypassed by structuring high-value NEP-245/IMT transfers with `|delta| == 1` - (File: `contracts/defuse/core/src/intents/token_diff.rs`)

### Summary
The `TokenDiff::token_fee` function in the Verifier's swap-intent engine unconditionally waives the protocol fee for `Nep245` (Multi-Token) and `Imt` (Intent-Mintable Token) legs of a swap whenever the transferred amount is `<= 1`. This mirrors the Footium bug class: one asset representation (`Nep141`, fungible) always pays the protocol fee, while a structurally similar but differently-typed asset representation (`Nep245`/`Imt` with unit amount) is fee-exempt by construction, even though nothing in the token model guarantees that a `Nep245`/`Imt` token with `amount == 1` is a true 1-of-1 NFT rather than a high-value, low-decimals fungible position.

### Finding Description
`TokenDiff::token_fee` decides whether a fee applies purely from the `TokenIdType` and the numeric size of the delta: [1](#0-0) 

```rust
pub fn token_fee(token_id: impl Into<TokenIdType>, amount: u128, fee: Pips) -> Pips {
    let token_id = token_id.into();
    match token_id {
        TokenIdType::Nep141 => {}
        TokenIdType::Nep245 | TokenIdType::Imt if amount > 1 => {}
        // do not take fees on NFTs and MTs with |delta| <= 1
        TokenIdType::Nep171 | TokenIdType::Nep245 | TokenIdType::Imt => return Pips::ZERO,
    }
    fee
}
```

This function is invoked from `supply_delta`/`closure_supply_delta`, which are the sole gate used by the multi-party swap engine (`closure_deltas`/`closure`) to compute how much fee is skimmed on every negative (token-in) leg of a `TokenDiff` intent. `Nep141` (standard fungible tokens) always pay `fee`. `Nep171` (true 1-of-1 NFTs) never pay a fee, which is defensible since an NFT position cannot be fractionally taxed. But `Nep245` (defuse's own NEP-245 multi-token type, used both for wrapping externally bridged assets and for representing arbitrary intent-mintable assets, see `crates/primitives/token-id/src/nep245.rs`) and `Imt` (`crates/primitives/token-id/src/imt.rs`, "Intent mintable token") are exempted from the fee purely because the observed `amount` in a given swap leg happens to be `1`.

Nothing in the `Nep245TokenId`/`ImtTokenId` definitions constrains the "per-unit value" of these token types the way NEP-171 constrains NFTs to be non-fungible. A `Nep245`/`Imt` token can be minted/configured with arbitrarily few decimals (or none), so that a single logical "share", "position", or "wrapped basket" unit represents an economically large amount of value. A counterparty structuring a swap so that the valuable leg is expressed as `delta == 1` of such a token entirely escapes the protocol fee (`Pips::ZERO`), while the exact same economic value moved as a `Nep141` (or as a `Nep245`/`Imt` amount `> 1`) would be fully taxed. This is the same class of bug as the Footium report: a fee mechanism that is enforced on one asset representation (players/`Nep141`) but silently skipped for a structurally adjacent representation (clubs/`Nep245` & `Imt` bundles), letting users repackage the transfer to bypass protocol royalties.

### Impact Explanation
This directly breaks the "fees owed versus fees collected" invariant called out as in-scope Critical impact: the protocol's `FeesConfig.fee` (set via `contracts/defuse/src/contract/fees.rs`) is meant to apply to value moved through swap intents, but any value that can be denominated as a `Nep245`/`Imt` token with unit deltas is collected with zero fee, regardless of magnitude. Since `IMT` tokens exist specifically to represent intent-native, arbitrarily-defined assets (`crates/primitives/token-id/src/imt.rs:7` "Intent mintable token"), and `Nep245` wraps externally bridged assets, an attacker (or any solver/market maker) that controls the minting parameters of such a token (decimals/denomination) can consistently route high-value swaps through unit-amount `Nep245`/`Imt` legs to avoid paying the protocol fee that `FeesManager` configured, directly reducing protocol revenue with no compensating control.

### Likelihood Explanation
Likelihood is high for any actor who mints or uses `Imt`/`Nep245` tokens with coarse denomination (few or zero decimals): any `TokenDiff` intent where the `Nep245`/`Imt` leg's delta is `1` automatically gets `Pips::ZERO` regardless of counter-value, and this is reachable by ordinary unprivileged users signing intents through the standard `execute_intents` path — no privileged role, relayer key, or upgrade is required.

### Recommendation
Do not infer "NFT-like, therefore fee-exempt" purely from the numeric magnitude of the delta for `Nep245`/`Imt` token types. Either (a) only exempt `Nep245` tokens from fees when the underlying token is provably non-fungible (e.g., carry an explicit NFT/1-of-1 flag validated at mint/registration time, as is done structurally for `Nep171`), or (b) apply the same fee schedule to `Nep245`/`Imt` deltas as to `Nep141` regardless of amount, and only special-case true `Nep171` NFTs.

### Proof of Concept
1. A user (or colluding minter) creates/uses an `Imt` token (`ImtTokenId`) or a bridged `Nep245` token configured with 0 decimals such that `1` unit represents a large economic value (e.g., equivalent to 10,000 USDC).
2. The user submits a `TokenDiff` intent (via `execute_intents`) swapping `Nep141` USDC for `-1` delta of this `Imt`/`Nep245` token (i.e., moving the whole high-value position in a single unit).
3. `TokenDiff::supply_delta` calls `token_fee(TokenIdType::Imt, amount=1, fee)`, which matches the `amount > 1` guard as false and falls into the exemption arm, returning `Pips::ZERO` for that leg. See [2](#0-1) .
4. The swap settles with the full configured protocol `fee` (from `contracts/defuse/src/contract/fees.rs`) charged on the `Nep141` leg but zero fee on the `Imt`/`Nep245` leg carrying the actual high value — net protocol fee collected is less than what `FeesManager` intended for the value transferred, mirroring "selling the club to bypass the per-player royalty."

    fn supply_delta(token_id: &TokenId, delta: i128, fee: Pips) -> Option<i128> {
        if delta < 0 {
            // fee is taken only on negative deltas (i.e. token_in)
            delta.checked_mul_div_ceil(
                Self::token_fee(token_id, delta.unsigned_abs(), fee)
                    .invert()
                    .as_pips()
                    .into(),
                Pips::MAX.as_pips().into(),
            )
        } else {
            // token_out
            Some(delta)
        }
    }
