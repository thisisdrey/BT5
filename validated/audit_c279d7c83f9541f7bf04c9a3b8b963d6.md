### Title
Malicious peer can indefinitely stall unconfirmed tenure block downloads by returning empty tenure bodies - ([File: stackslib/src/net/download/nakamoto/tenure_downloader_unconfirmed.rs])

### Summary
`try_accept_unconfirmed_tenure_blocks` returns `Ok(None)` without changing `self.state` when the decoded block list is empty, so a peer can answer every `GetUnconfirmedTenureBlocks` request with a 200 OK / empty body forever. Since `send_next_download_request` derives the request purely from `self.state`, the state machine keeps re-issuing the identical request to the same peer with no forward-progress guarantee at this layer.

### Finding Description
In `try_accept_unconfirmed_tenure_blocks` [1](#0-0) , when `tenure_blocks.is_empty()` the function returns `Ok(None)` immediately, before the block responsible for updating `self.state` (`self.state = NakamotoUnconfirmedDownloadState::GetUnconfirmedTenureBlocks(next_block_id)` at line 628, or transitioning to `Done` at line 596) ever executes. The state remains `GetUnconfirmedTenureBlocks(last_block_id)` unchanged.

`handle_next_download_response` calls this method directly on a `GetUnconfirmedTenureBlocks` response and propagates `Ok(None)` [2](#0-1) . `send_next_download_request` then builds the next request via `make_next_download_request`, which for `GetUnconfirmedTenureBlocks(tip_block_id)` returns the exact same `new_get_nakamoto_tenure` request for the same `tip_block_id` [3](#0-2) . The only exit conditions in `send_next_download_request` are an in-flight request already pending, or the neighbor being flagged dead/broken by the connection-liveness/timeout machinery in `NeighborRPC` [4](#0-3)  — neither of which is triggered by a peer that keeps responding with valid, empty 200 OK bodies, since each response resets the request/response cycle rather than timing out.

This is a genuine broken invariant: the docstring of `try_accept_unconfirmed_tenure_blocks` says "Returns Ok(None) if there are still blocks to fetch, in which case, the caller should call `send_next_download_request()`" [5](#0-4) , but the empty-body branch never actually advances the fetch pointer (`last_block_id` stays the same), so "still blocks to fetch" is untrue — nothing changed and the same request will be sent again.

### Impact Explanation
A single malicious/misbehaving peer holding an open, authenticated P2P/RPC connection can keep this particular `NakamotoUnconfirmedTenureDownloader` instance permanently in the `GetUnconfirmedTenureBlocks` state by returning empty responses to `/v3/tenures/:id`, preventing that download slot from ever completing or falling back to another peer via this code path alone. This matches the "bounded compute DoS on a read endpoint" category (High), not Critical: it does not crash the node, corrupt state, or forge data — it only wastes a download slot/connection against one peer at low, bounded cost per round trip.

### Likelihood Explanation
Preconditions: attacker only needs an existing authenticated connection to the victim node and must be selected as a download peer for an unconfirmed tenure — both achievable by any unprivileged peer that gossips/participates normally. Attacker cost per response is minimal (empty payload). Repeatable indefinitely as long as the connection stays alive and is not flagged dead/broken by unrelated liveness checks (e.g. TCP-level timeouts, unrelated request/response округ mechanisms) that this per-request logic does not enforce.

### Recommendation
In `try_accept_unconfirmed_tenure_blocks`, treat an empty `tenure_blocks` response on a `GetUnconfirmedTenureBlocks` request as a protocol violation (return `Err(NetError::InvalidMessage)`) rather than `Ok(None)`, since a well-behaved peer should never return zero blocks for an outstanding, non-`Done` unconfirmed tenure request. Alternatively, add an explicit retry/attempt counter or elapsed-time budget per `(peer, block_id)` pair in the state machine so that repeated empty responses eventually cause the peer to be dropped via `neighbor_rpc.add_dead`/`DropReason`.

    pub fn send_next_download_request(
        &self,
        network: &mut PeerNetwork,
        neighbor_rpc: &mut NeighborRPC,
    ) -> Result<(), NetError> {
        if neighbor_rpc.has_inflight(&self.naddr) {
            debug!("Peer {} has an inflight request", &self.naddr);
            return Ok(());
        }
        if neighbor_rpc.is_dead_or_broken(network, &self.naddr) {
            return Err(NetError::PeerNotConnected(format!("Failed to send next unconfirmed download request to {:?}: connection is dead or broken", &self.naddr)));
        }

        let Some(peerhost) = NeighborRPC::get_peer_host(network, &self.naddr) else {
            // no conversation open to this neighbor
            neighbor_rpc.add_dead(
                network,
                &self.naddr,
                DropReason::DeadConnection("No authenticated connection open".into()),
                DropSource::NakamotoUnconfirmedTenureDownloader,
            );
            return Err(NetError::PeerNotConnected(format!(
                "No authenticated connection open to {:?} for unconfirmed tenure download",
                &self.naddr
            )));
        };

        let Some(request) = self.make_next_download_request(peerhost) else {
            // treat this downloader as still in-flight since the overall state machine will need
            // to keep it around long enough to convert it into a tenure downloader for the highest
            // complete tenure.
            return Ok(());
        };

        neighbor_rpc.send_request(network, self.naddr.clone(), request)?;
        Ok(())
    }
