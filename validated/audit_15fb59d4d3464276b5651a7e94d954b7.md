Based on analysis of `commission_split()` in `runtime/src/inflation_rewards/mod.rs`, this is not a real vulnerability. Every `expect()`/`checked_*` call in the function is guaranteed to succeed by the type bounds of its inputs, not by attacker-controlled runtime values.

**Analysis:**

The function signature is `fn commission_split(commission_bps: u16, on: u64) -> (u64, u64, bool)` [1](#0-0) .

It first clamps the commission to `commission_bps.min(MAX_BPS)` where `MAX_BPS = 10_000`, so in the `split` arm, `split` is provably in the range `[1, 9999]` regardless of how large `commission_bps` (a `u16`, max 65535) actually is [2](#0-1) .

- `mine = on.checked_mul(u128::from(split)).expect(...)`: `on` is widened to `u128` from a `u64` (max ≈1.8×10¹⁹), and `split ≤ 9999`, so the product is at most ≈1.8×10²³ — far below `u128::MAX` (≈3.4×10³⁸). The `checked_mul` can never return `None`, so the `expect` can never panic [3](#0-2) .
- `theirs`'s `MAX_BPS.checked_sub(split)`: since `split ≤ 9999 < MAX_BPS = 10000`, this subtraction never underflows, so the `expect("commission cannot be greater than MAX_BPS")` never panics [4](#0-3) .
- The final `mine as u64` / `theirs as u64` casts are safe: `mine`/`theirs` are each `on * bps / MAX_BPS` with `bps ≤ MAX_BPS`, so each result is bounded by `on ≤ u64::MAX`; and Rust's `as` numeric casts never panic in any build profile regardless [5](#0-4) .

The sibling function `commission_split_preserve_lamports` has the identical structural guarantee: `staker_bps ≤ MAX_BPS - 1`, so `staker_rewards < on`, making the final `on.checked_sub(staker_rewards).expect(...)` unconditionally safe [6](#0-5) .

There is no combination of `u16` and `u64` inputs (the full domain of both parameters) that can trip any of these `expect`/`checked_*` calls — the safety is structural/type-bound, not dependent on runtime magnitude within those types. This matches the code comments explicitly documenting these invariants ("multiplication of a u64 and u16 should not overflow", "commission cannot be greater than MAX_BPS", "staker rewards cannot exceed total rewards").

fn commission_split_preserve_lamports(commission_bps: u16, on: u64) -> (u64, u64, bool) {
    const MAX_BPS: u16 = 10_000;
    const MAX_BPS_U128: u128 = MAX_BPS as u128;
    match commission_bps.min(MAX_BPS) {
        0 => (0, on, false),
        MAX_BPS => (on, 0, false),
        split => {
            let staker_bps = MAX_BPS
                .checked_sub(split)
                .expect("commission cannot be greater than MAX_BPS");
            let staker_rewards = u128::from(on)
                .checked_mul(u128::from(staker_bps))
                .expect("multiplication of a u64 and u16 should not overflow")
                / MAX_BPS_U128;
            let staker_rewards = staker_rewards as u64;
            let voter_rewards = on
                .checked_sub(staker_rewards)
                .expect("staker rewards cannot exceed total rewards");

            (voter_rewards, staker_rewards, true)
        }
    }
