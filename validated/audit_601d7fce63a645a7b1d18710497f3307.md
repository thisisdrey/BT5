### Title
`cleanup_by_prefix` removes the entire 256-bit nonce word, resurrecting other unexpired nonces sharing the same `NoncePrefix` for signature replay - (File: `crates/bitmap/src/b256.rs`)

### Summary
`BitMap256::cleanup_by_prefix` deletes the whole 32-byte bitmap word keyed by the 248-bit `NoncePrefix`, rather than clearing only the single bit corresponding to the nonce being garbage-collected. Since `GarbageCollector::cleanup_nonces` only validates the cleanability (expiry/salt) of the *specific* nonce it was asked to clean, cleaning up one expired nonce silently clears the bit of any other still-valid, unexpired nonce that happens to share the same top-248-bit prefix, making that other nonce reusable.

### Finding Description
Broken binding: `is_used(n2)` before GC cleanup of `n1` == `is_used(n2)` after GC cleanup of `n1`, when `n2` is unexpired/valid-salted and shares `n1`'s `NoncePrefix`. This equality is violated.

Nonces are stored as `BitMap256<T>` keyed by `NoncePrefix = U248` (top 248 bits of the 256-bit nonce), with each 32-byte value being a bitmap of the 256 possible last-byte values [1](#0-0) . `set_bit`/`get_bit`/`clear_bit` correctly manipulate individual bits within the word [2](#0-1) , but `cleanup_by_prefix` does not target a single bit — it removes the entire map entry for that prefix:

```rust
pub fn cleanup_by_prefix(&mut self, prefix: U248) -> bool {
    self.0.remove(&prefix).is_some()
}
``` [3](#0-2) 

This is invoked unconditionally through `Nonces::cleanup_by_prefix` [4](#0-3) , `Account::cleanup_nonce_by_prefix` [5](#0-4) , and ultimately by `GarbageCollector::cleanup_nonces`, which only checks that the *single nonce passed in* is expired/invalid-salted before wiping the whole prefix word:

```rust
fn cleanup_nonces(&mut self, nonces: Vec<(AccountId, Vec<AsBase64<Nonce>>)>) {
    for (account_id, nonces) in nonces {
        for nonce in nonces.into_iter().map(AsBase64::into_inner) {
            if !self.is_nonce_cleanable(nonce) { continue; }
            let [prefix @ .., _] = nonce;
            let _ = State::cleanup_nonce_by_prefix(self, &account_id, prefix);
        }
    }
}
``` [6](#0-5) 

`is_nonce_cleanable` only inspects `n1`'s own deadline/salt validity [7](#0-6)  — it never checks whether other bits in the same word (i.e., other nonces sharing the prefix) are still valid.

Exploit flow:
1. Attacker crafts `n1` and `n2` = same top-248-bit prefix, differing only in the last byte (bit position).
2. Attacker signs two `DefuseIntents` payloads using `n1` and `n2` respectively (each with a valid salt and deadline), and submits both via `execute_intents`. Both `commit_nonce` calls succeed since they set distinct bits in the same word via `set_bit` [8](#0-7) , and both intents settle (funds move for both).
3. `n1`'s deadline expires (or its salt is invalidated) while `n2`'s deadline is still valid.
4. A `GarbageCollector`/`DAO` role holder legitimately calls `cleanup_nonces` for the now-expired `n1` (normal maintenance, no malicious role holder needed).
5. `cleanup_nonce_by_prefix` removes the *entire* bitmap word for the shared prefix, clearing `n2`'s bit too, even though `n2` is still valid/unexpired.
6. Attacker resubmits their original signed payload for `n2`. `verify_intent_nonce` passes (deadline/salt still valid) and `commit_nonce` succeeds because `is_used(n2)` now returns `false`. The intent settles a second time.

This does not require the attacker to hold any role — only an honest `GarbageCollector`/`DAO` performing its normal, documented job (`cleanup_nonces`) is needed as a side channel; the attacker's actions (choosing colliding nonces, signing, submitting) are all unprivileged.

None of the existing guards catch this: `MaybeLegacyNonces::commit`/`is_used` only look at `BitMap256` state which has already been corrupted by the removal [9](#0-8) ; `verify_intent_nonce` re-validates deadline/salt of the nonce itself, which is still valid for `n2` [10](#0-9) ; `is_nonce_cleanable` never considers sibling bits in the word [7](#0-6) .

### Impact Explanation
A previously-settled, still-unexpired nonce (`n2`) becomes reusable, allowing the attacker's original signed `MultiPayload` for `n2` to be resubmitted and settle a second time — moving/crediting funds twice off a single signature. This matches the Critical category "one signed payload settling more than once." The blast radius scales with the number of nonces the attacker can arrange to collide under a shared 248-bit prefix and is repeatable across accounts/tokens/batches, though it is bounded by naturally occurring GC cleanup cycles (or by the attacker choosing an already-expired nonce to pair with a long-lived one, then waiting for the routine cleanup call).

### Likelihood Explanation
The attacker only needs to: (1) generate two nonces sharing the top 248 bits (trivial — choose any 31-byte prefix, vary only the last byte), (2) have sufficient balance to sign two valid intents, (3) wait for the normal expiry of `n1` and a routine `cleanup_nonces` call by the `GarbageCollector`/`DAO` (a documented, expected maintenance action, not an adversarial one). No special privileges, roles, or victim keys are required by the attacker. Feasibility is high given `cleanup_nonces` is designed to be called periodically for storage hygiene.

### Recommendation
Change `BitMap256::cleanup_by_prefix` (and its callers) to only clear the specific bit belonging to the nonce being cleaned rather than removing the entire prefix word — e.g., by tracking per-bit expiry/salt metadata, or by iterating and clearing only bits whose corresponding full nonce is independently verified cleanable before removing the underlying map entry (only removing the whole entry once all 256 bits are confirmed cleanable/unused).

### Proof of Concept
```rust
// crates/bitmap/src/b256.rs (or contracts/defuse/core/src/nonce/mod.rs)
#[test]
fn cleanup_by_prefix_resurrects_sibling_nonce() {
    let mut m = BitMap256::<HashMap<U248, U256>>::default();

    let prefix: U248 = [0u8; 31];
    let mut n1: U256 = [0u8; 32];
    n1[31] = 0; // bit 0
    let mut n2: U256 = [0u8; 32];
    n2[31] = 1; // bit 1, same prefix

    assert!(!m.set_bit(n1));
    assert!(!m.set_bit(n2));
    assert!(m.get_bit(n1));
    assert!(m.get_bit(n2)); // n2 committed and still "valid/unused-again-safe"

    // GC cleans up only n1's prefix because n1 is "cleanable" (expired)
    assert!(m.cleanup_by_prefix(prefix));

    // BROKEN BINDING: n2 was never individually determined to be cleanable,
    // yet its bit was cleared too.
    assert!(!m.get_bit(n2)); // FAILS the intended invariant: should still be true
}
```
Full end-to-end proof (sandbox/near-workspaces, mirroring `tests/src/tests/defuse/accounts/nonces.rs`):
1. Create user, get `current_salt`.
2. Craft `n1`/`n2` = `[prefix(31 bytes) || last_byte]` with distinct last bytes, `n1` deadline `now + 1s`, `n2` deadline `now + 1h`.
3. Sign and `execute_intents` two `DefuseIntents` (each moving real balance) using `n1` and `n2`; assert both settle (balances change) and `is_nonce_used(n1) == true`, `is_nonce_used(n2) == true`.
4. Sleep past `n1`'s deadline.
5. Grant `Role::GarbageCollector` to some account (simulating normal ops) and call `cleanup_nonces([(user, [n1])])`.
6. Assert `is_nonce_used(n2) == false` (flipped from `true` — binding violated) even though `n2`'s deadline has not passed.
7. Resubmit the original signed `MultiPayload` for `n2` via `execute_intents`; assert it succeeds and the balance delta is applied a second time — proving double settlement of a single signature.

    fn verify_intent_nonce(&self, nonce: Nonce, intent_deadline: Timestamp) -> Result<()> {
        let Some(nonce) = VersionedNonce::maybe_from(nonce) else {
            return Ok(());
        };

        match nonce {
            VersionedNonce::V1(SaltedNonce {
                salt,
                nonce: ExpirableNonce { deadline, .. },
            }) => {
                if !self.state.is_valid_salt(salt) {
                    return Err(DefuseError::InvalidSalt);
                }

                if intent_deadline > deadline {
                    return Err(DefuseError::DeadlineGreaterThanNonce);
                }

                if deadline < Timestamp::now() {
                    return Err(DefuseError::NonceExpired);
                }
            }
        }

        Ok(())
    }
