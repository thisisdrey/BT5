The `checkLastBlockAction` bug pattern (a bypassable per-`msg.sender` same-block guard that can be circumvented by transferring the asset to another address) does not have a reachable analog in this repository. I searched for:

- Any block-number-keyed caller-state mapping analogous to `_callerLastBlockAction` — none exists; the codebase uses OpenZeppelin's `ReentrancyGuardTransient` (`nonReentrant`) for reentrancy protection in `Loans.sol`, `LoansExchange.sol`, and `PortfolioVault.sol`, which is a transient-storage lock scoped to the call, not a per-address/per-block flag that could be bypassed by transferring tokens/shares to a different address [1](#0-0) .
- The vault's async deposit/redeem flow, which is the closest conceptual analog to "deposit then withdraw in the same block." Redemption shares are locked via an actual `safeTransferFrom` into vault custody at `requestRedeem` time (not a block-number flag), and claiming requires manager approval (`approveRedemption`) plus NAV freshness checks — there is no same-block deposit/withdraw restriction to bypass in the first place, since the flow is inherently multi-step and manager-gated [2](#0-1) .
- `LoansExchange.createOffer`/`acceptOffer`, which lock NFTs to the exchange rather than relying on a bypassable per-block caller flag [3](#0-2) .

Since no scoped contract implements a bypassable same-block caller-tracking modifier, and the actual protections (transient reentrancy guards, custody-based locking, manager-gated approvals) are not defeated by transferring the underlying asset to a different address, there is no reachable analog of this bug class in the current scope.

  function requestRedeem(
    uint256 shares,
    address controller,
    address owner
  ) external nonReentrant whenNotPaused onlyAccountOrOperator(owner) returns (uint256 requestId) {
    require(controller != address(this), InvalidController());
    _requireInvestor(controller);
    require(shares > 0, ZeroAmount());

    // Lock shares by transferring from owner to vault
    IERC20(address(shareToken)).safeTransferFrom(owner, address(this), shares);

    pendingRedeemShares[controller] += shares;

    emit RedeemRequest(controller, owner, 0, msg.sender, shares);
    return 0;
  }
