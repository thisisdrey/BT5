### Title
Unbounded object transfer during FetchRemote dry-run fills quarantine directory and exhausts shared storage-shard disk - (File: internal/gitaly/service/repository/fetch_remote.go)

### Summary
`fetchRemoteAtomic` performs `git-fetch(1)` with `DryRun: true` purely to defer reference updates, not to limit the amount of data transferred; the attacker-controlled remote (set via `RemoteParams.Url`) can still stream an arbitrarily large packfile that is written in full into the per-request quarantine directory before any check occurs. No size cap, disk-quota check, or streaming limit exists in this path, so a malicious/attacker-controlled remote can exhaust the storage shard shared by other repositories.

### Finding Description
`fetchRemoteAtomic` builds `localrepo.FetchOpts` with `DryRun: true` and `Porcelain: true` [1](#0-0) , then creates a quarantine directory via `quarantine.New` and runs `quarantineRepo.FetchRemote(ctx, "inmemory", opts)` [2](#0-1) . The code comment itself explains that `--dry-run` only suppresses reference updates — object data is still received in full: "Git objects are received without performing reference updates" [3](#0-2) . The remote URL, resolved address, refspecs, and auth are all attacker-influenced request fields consumed in `buildCommandOpts` [4](#0-3) .

`quarantine.New` creates a temp directory under the storage's `+gitaly/tmp` path with no size limit, quota check, or disk-space pre-check [5](#0-4) . No code in `fetch_remote.go`, `quarantine.go`, or the git command factory enforces a pack size cap (`pack.packSizeLimit`), an unpack limit (`transfer.unpackLimit`), or a disk quota before/while writing fetched objects; the only bound on the operation is the caller-supplied RPC timeout (`req.GetTimeout()`), which is wall-clock time, not a byte-size limit [6](#0-5) . `validateFetchRemoteRequest` only checks that the repository is valid and the remote URL is non-empty — it performs no size/quota validation [7](#0-6) .

Because storages are shared across many repositories/tenants, a single `FetchRemote` (or GitLab pull-mirroring / project-import-by-URL flow that triggers it) pointed at an attacker-controlled Git server can write an effectively unbounded amount of duplicate/incompressible blob data into `<storage>/+gitaly/tmp/quarantine-*` before any hook, fsck, or reference-update logic runs, consuming the shard's disk and causing ENOSPC failures for unrelated repositories on the same storage.

### Impact Explanation
This is a resource-exhaustion / Denial-of-Service of the Gitaly RPC handler and, transitively, of every other repository on the same storage shard, since Gitaly storages are multi-tenant. It matches the "DoS of an RPC handler" / cross-tenant resource-isolation-failure class called out in scope. The blast radius is bounded to whichever physical storage the victim's repository lives on, but within that shard it can cause writes to fail for many unrelated projects/users until disk is freed or the offending quarantine directory is cleaned up.

### Likelihood Explanation
Feasibility depends on an attacker being able to get Gitaly to run `FetchRemote` (or the equivalent import/mirror RPC) against a server they control. This is realistic for project import-by-URL and pull-mirror configuration, both of which let a project owner supply an arbitrary remote URL that Rails eventually turns into a `FetchRemoteRequest`. The exploit is fully repeatable (the attacker just needs to keep the remote connection open and streaming data, or re-trigger the mirror periodically) and requires no special privilege beyond normal project-creation/import ability. The main uncertainty is whether GitLab Rails enforces a repository-size quota or bandwidth cap *before* invoking this RPC for a given plan/namespace — that enforcement, if any, lives outside this repository (Rails) and could not be verified from the Gitaly codebase alone.

### Recommendation
Enforce a hard limit on the amount of data/objects that can be received per fetch before it is queued to the quarantine directory — e.g., pass a `pack.packSizeLimit` / `fetch.unpackLimit` config to the `git-fetch` invocation in `buildCommandOpts`, and/or monitor the quarantine directory's growth during the fetch (aborting the subprocess) once it exceeds a configurable per-request/per-storage cap. Additionally, perform a pre-flight disk-space check via `DiskStatistics`-style logic and periodically re-check available space while the fetch is in flight, aborting the transfer and cleaning up the quarantine directory when a safety threshold is crossed.

func buildCommandOpts(ctx context.Context, opts *localrepo.FetchOpts, req *gitalypb.FetchRemoteRequest) error {
	remoteURL := req.GetRemoteParams().GetUrl()
	var config []gitcmd.ConfigPair

	for _, refspec := range getRefspecs(req.GetRemoteParams().GetMirrorRefmaps()) {
		config = append(config, gitcmd.ConfigPair{
			Key: "remote.inmemory.fetch", Value: refspec,
		})
	}

	if resolvedAddress := req.GetRemoteParams().GetResolvedAddress(); resolvedAddress != "" {
		modifiedURL, resolveConfig, err := gitcmd.GetURLAndResolveConfig(remoteURL, resolvedAddress)
		if err != nil {
			return fmt.Errorf("couldn't get curloptResolve config: %w", err)
		}

		remoteURL = modifiedURL
		config = append(config, resolveConfig...)
	}

	config = append(config, gitcmd.ConfigPair{Key: "remote.inmemory.url", Value: remoteURL})

	if featureflag.FetchRemoteProactiveAuth.IsEnabled(ctx) {
		if u, err := url.Parse(remoteURL); err == nil && u.User != nil {
			password, _ := u.User.Password()
			if u.User.Username() != "" && password != "" {
				config = append(config, gitcmd.ConfigPair{
					Key:   "http.proactiveAuth",
					Value: "basic",
				})
			}
		}
	}

	if authHeader := req.GetRemoteParams().GetHttpAuthorizationHeader(); authHeader != "" {
		config = append(config, gitcmd.ConfigPair{
			Key:   fmt.Sprintf("http.%s.extraHeader", req.GetRemoteParams().GetUrl()),
			Value: "Authorization: " + authHeader,
		})
	}

	opts.CommandOptions = append(opts.CommandOptions, gitcmd.WithConfigEnv(config...))

	return nil
}

func (s *server) validateFetchRemoteRequest(ctx context.Context, req *gitalypb.FetchRemoteRequest) error {
	if err := s.locator.ValidateRepository(ctx, req.GetRepository()); err != nil {
		return structerr.NewInvalidArgument("%w", err)
	}

	if req.GetRemoteParams() == nil {
		return structerr.NewInvalidArgument("missing remote params")
	}

	if req.GetRemoteParams().GetUrl() == "" {
		return structerr.NewInvalidArgument("blank or empty remote URL")
	}

	return nil
}

func New(ctx context.Context, repo *gitalypb.Repository, logger log.Logger, locator storage.Locator) (*Dir, func(), error) {
	repoPath, err := locator.GetRepoPath(ctx, repo, storage.WithRepositoryVerificationSkipped())
	if err != nil {
		return nil, nil, structerr.NewInternal("getting repo path: %w", err)
	}

	quarantineDir, cleanup, err := tempdir.NewWithPrefix(ctx, repo.GetStorageName(),
		storage.QuarantineDirectoryPrefix(repo), logger, locator)
	if err != nil {
		return nil, nil, fmt.Errorf("creating quarantine: %w", err)
	}

	quarantinedRepo, err := Apply(repoPath, repo, quarantineDir.Path())
	if err != nil {
		cleanup() // Clean up if we fail after creating the temp directory
		return nil, nil, err
	}

	return &Dir{
		repo:            repo,
		quarantinedRepo: quarantinedRepo,
		locator:         locator,
		dir:             quarantineDir,
	}, cleanup, nil
}
