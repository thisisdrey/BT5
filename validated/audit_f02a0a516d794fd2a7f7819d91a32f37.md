### Title
Unauthenticated `/shutdown` POST terminates signer's event-processing loop - ([File: libsigner/src/events.rs])

### Summary
The `next_event` handler in `SignerEventReceiver` unconditionally sets `stop_signal` to `true` and returns `EventError::Terminated` for any HTTP POST to `/shutdown`, with no check of body content, source, or credential. Since `main_loop` exits on `EventError::Terminated`, any remote TCP client that can reach the bound event-receiver address can permanently stop the signer's event processing with a single request.

### Finding Description
In `SignerEventReceiver::next_event`, the branch handling `/shutdown` does:
```rust
} else if request.url() == "/shutdown" {
    event_receiver.stop_signal.store(true, Ordering::SeqCst);
    Err(EventError::Terminated)
``` [1](#0-0) 
There is no validation of the request body, no signature, no secret/token check, and no check that the connection originates from the local node process. This differs from the intended design implied by `SignerStopSignaler::send`, which is the *only* legitimate caller expected to invoke this — it works by connecting a `TcpStream` to `self.local_addr` and POSTing to `/shutdown`:
```rust
fn send(&mut self) {
    self.stop_signal.store(true, Ordering::SeqCst);
    if let Ok(mut stream) = TcpStream::connect(self.local_addr) {
        let body = "Yo. Shut this shit down!".to_string();
        let req = format!(
            "POST /shutdown HTTP/1.1\r\nHost: {}\r\nConnection: close\r\nContent-Length: {}\r\nContent-Type: text/plain\r\n\r\n{}",
            self.local_addr, body.len(), body
        );
        ...
``` [2](#0-1) 
Nothing in this code ties the ability to invoke the stop to that specific in-process caller — the HTTP server bound via `bind()` accepts POSTs from any TCP client that can reach the listening socket, and `next_event` matches purely on `request.url() == "/shutdown"` regardless of who sent it.
`is_stopped()` reads the same `stop_signal` and `main_loop` checks it every iteration and also treats `Err(EventError::Terminated)` from `next_event` as a break condition:
```rust
Err(EventError::Terminated) => {
    info!("Caught termination signal");
    break;
}
``` [3](#0-2) 
So a single crafted `POST /shutdown` (any body, even empty) from an unprivileged remote TCP client causes `main_loop` to break immediately, permanently halting the signer's ingestion of StackerDB chunks, block-validation responses, and burn/stacks block events until the process is manually restarted.

### Impact Explanation
This is an unauthenticated, single-message remote DoS: one attacker-controlled POST to `/shutdown` on the signer's bound event-receiver port stops the signer's `main_loop` for good (`is_stopped()` becomes permanently `true`), so the signer stops observing `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, and `/new_block` events from its node. This matches the "Critical - remote crash/unauthenticated DoS from few messages" category, since it silences the signer's participation in the network with a single HTTP request and no credential.

### Likelihood Explanation
Preconditions: the attacker only needs TCP reachability to the address that the signer's event receiver is bound to (this is the same address the node's event dispatcher is configured to POST events to, per `bind()`); no signer key, no P2P handshake, no RPC secret, and no privileged role are required. Attacker cost is a single HTTP POST reproducible at will (the attack is trivially repeatable — as long as the receiver were somehow restarted, immediately re-sendable). Exploitability depends only on network-level reachability of that endpoint, which is an operational/deployment consideration but the code itself contains no authentication gate whatsoever.

### Recommendation
Restrict `/shutdown` handling to genuinely local/internal callers only: e.g., require the request to originate from a loopback-only bound socket (bind the event receiver strictly to `127.0.0.1`/an internal-only interface), or better, replace the HTTP-triggered shutdown with an in-process signal (e.g., a channel/mpsc sender passed directly to `SignerStopSignaler`, or a Unix pipe/local socket) rather than exposing it over the same HTTP surface reachable by the node/network. If HTTP must be kept, add a shared secret/token check on `/shutdown` (similar to RPC auth patterns elsewhere in the codebase) before honoring the stop request.

### Proof of Concept
```rust
// libsigner/src/events.rs (test-style PoC)
#[test]
fn test_unauthenticated_shutdown_dos() {
    use std::net::TcpStream;
    use std::io::Write;
    use std::thread;

    let mut receiver: SignerEventReceiver<crate::v0::messages::SignerMessage> =
        SignerEventReceiver::new(false);
    let addr = receiver.bind("127.0.0.1:0".parse().unwrap()).unwrap();
    let (tx, _rx) = std::sync::mpsc::channel();
    receiver.add_consumer(tx);

    let handle = thread::spawn(move || receiver.main_loop());

    // Unprivileged remote client: no credential, no signature, arbitrary body.
    let mut stream = TcpStream::connect(addr).unwrap();
    let body = "anything";
    let req = format!(
        "POST /shutdown HTTP/1.1\r\nHost: {}\r\nConnection: close\r\nContent-Length: {}\r\n\r\n{}",
        addr, body.len(), body
    );
    stream.write_all(req.as_bytes()).unwrap();

    // main_loop should exit promptly with no credential presented.
    handle.join().unwrap();
    // (Assertion: thread joins => main_loop broke on EventError::Terminated
    //  triggered purely by the unauthenticated remote POST.)
}
```
The crash/stop site is exactly `event_receiver.stop_signal.store(true, Ordering::SeqCst); Err(EventError::Terminated)` at [1](#0-0) , reached from any remote TCP POST with no guard in place.
