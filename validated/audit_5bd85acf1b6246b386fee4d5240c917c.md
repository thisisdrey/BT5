### Abandoned Cashflows in NAV De-curation - (`contracts/PortfolioVault.sol`)

### Summary
In the `PortfolioVault` contract, removing a loan from the curated NAV list (`_navLoanIds`) via `removeLoansFromNav()` or implicitly via `transferLoans()` without first calling `collectCashflows()` causes the accumulated interest and principal for that loan to be permanently excluded from the vault's Net Asset Value (NAV). Since `collectCashflows()` reverts if a loan is not in the curated list, once a loan is removed, its pending cashflows can no longer be pulled into the vault's liquidity, leading to a material loss of value for vault shareholders.

### Finding Description
The `PortfolioVault` calculates its NAV based on a curated list of loans `_navLoanIds` [1](#0-0) . The `collectCashflows()` function is the only mechanism for the vault to pull interest and principal from the `Loans` contract into its own `assetToken` balance [2](#0-1) . 

However, `collectCashflows()` explicitly requires that every `loanId` passed to it must be present in the curated NAV list [3](#0-2) . If a `PORTFOLIO_MANAGER` removes a loan from the NAV list using `removeLoansFromNav()` [4](#0-3)  or if a loan is transferred out via `transferLoans()` [5](#0-4) , any interest or principal already allocated to that loan in the `Loans` ledger but not yet withdrawn is abandoned. 

Because the loan is no longer in `_navLoanIds`, `collectCashflows()` will revert with `LoanNotInNav` [6](#0-5) . Even if the vault still owns the NFT (in the case of `removeLoansFromNav`), the cashflows are trapped in the `Loans` contract and are no longer reflected in the `lastNav` calculation [7](#0-6) .

### Impact Explanation
This results in a material corruption of the vault's NAV and a loss of investor entitlement. Shareholders who redeem their shares after a loan is de-curated will receive less value than they are entitled to because the abandoned interest/principal is no longer counted as part of the vault's assets. This mirrors the "interest burning" bug where value meant for holders is lost due to incorrect accounting/state transitions during removal.

### Likelihood Explanation
High. It is a common operational sequence for a manager to remove or transfer loans. If the protocol does not enforce cashflow collection before de-curation, the value will be lost.

### Recommendation
Modify `removeLoansFromNav` and `transferLoans` to either:
1. Automatically call `collectCashflows` for the affected loans before removal.
2. Check if there are any outstanding withdrawable balances in `Loans.getLoanValues()` and revert if the balances are non-zero.

### Proof of Concept
1. A `PortfolioVault` owns a loan that has accrued $1,000 in interest (allocated in `Loans.sol`).
2. The current `lastNav` includes this $1,000 (as `investorInterestWithdrawable` from `getLoanValues`).
3. The `PORTFOLIO_MANAGER` calls `removeLoansFromNav([loanId])`.
4. The loan is removed from `_navLoanIds`. `lastNav` is invalidated.
5. On the next `updateNav`, the $1,000 is no longer included because the loan is not in the curated list.
6. The manager attempts to call `collectCashflows([loanId])` to recover the money.
7. The call reverts with `LoanNotInNav`. The $1,000 is trapped and the NAV is permanently reduced.

  function collectCashflows(
    uint64[] calldata loanIds,
    bytes32 ref
  ) external nonReentrant whenNotPaused returns (InvestorWithdrawalResult[] memory loanWithdrawals) {
    _requireManagerRole();
    _requireIdleNav();

    // Reject loans excluded from NAV; their cashflows would otherwise inflate NAV via idleLiquidity.
    uint256 length = loanIds.length;
    for (uint256 i; i < length; ++i) {
      require(_navLoanIndex[loanIds[i]] != 0, LoanNotInNav());
    }

    loanWithdrawals = loans.investorWithdraw(loanIds, uint48(block.timestamp), ref);

    // Mutates idleLiquidity and per-loan ledger state without bumping the ownership nonce.
    _invalidateNav();

    emit CashflowsCollected(loanWithdrawals);
  }
