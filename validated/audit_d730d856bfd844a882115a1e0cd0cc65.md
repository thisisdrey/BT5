### Title
Unauthenticated `GET /status` reconnaissance chained with unauthenticated `POST /shutdown` DoS on signer event receiver - (File: `libsigner/src/events.rs`)

### Summary
`SignerEventReceiver::next_event` dispatches on HTTP method/URL with no authentication check whatsoever, so any TCP peer that can reach the signer's event-receiver port can send `GET /status` to confirm the listener is alive and then send `POST /shutdown` to permanently terminate the receiver's event loop. Both requests are single, self-contained messages requiring no secret, signature, or prior state.

### Finding Description
In `EventReceiver::next_event` [1](#0-0) , the very first branch handles `request.url() == "/status"` for any HTTP method, responds `"OK"`, and returns `SignerEvent::StatusCheck` without checking any credential, source address, or header. Immediately after, the dispatcher checks `request.method() != &HttpMethod::Post` and then matches `/shutdown`: [2](#0-1) 

which sets `event_receiver.stop_signal.store(true, Ordering::SeqCst)` and returns `Err(EventError::Terminated)`. No authentication, source-IP allowlist, or shared secret is consulted anywhere in this function before performing either action. The main loop propagates the effect: on the next iteration, `next_event` immediately checks `is_stopped()` and returns `Err(EventError::Terminated)` [3](#0-2) , and `main_loop` breaks out entirely on receiving `Terminated` [4](#0-3) , permanently stopping the signer's event-processing thread until process restart.

An attacker's exact sequence:
1. `GET /status HTTP/1.1` (any/no body) → server replies `200 OK` → confirms the listener is live and accepting requests (reconnaissance).
2. `POST /shutdown HTTP/1.1` with a `Content-Length` and arbitrary body (the same format the legitimate internal `SignerStopSignaler::send` uses, see [5](#0-4) ) → sets the stop flag → receiver thread exits.

Both are ordinary single HTTP requests against the bound port; no signature check, no `MAX_MESSAGE_LEN` enforcement, and no auth gate exists in this code path to block them.

### Impact Explanation
The `POST /shutdown` request permanently kills the signer's `SignerEventReceiver` main loop, meaning the signer node stops receiving StackerDB chunk events, block-validation responses, burn-block events, and new-block events from the Stacks node it monitors. This is a remote unauthenticated DoS achievable with a single crafted HTTP message, matching the "Critical - remote crash/unauthenticated DoS from few messages" category. The `GET /status` step adds no additional technical impact beyond confirming reachability/liveness before firing the kill shot, but it precisely combines with the shutdown to make the DoS deterministic and effortless for the attacker (confirm-then-kill in two messages).

### Likelihood Explanation
The only precondition is TCP reachability to the signer's event-receiver bind address/port; the `bind()` implementation opens a plain HTTP server with no TLS or credential requirement [6](#0-5) . Any party who can open a TCP connection and send raw bytes to that port — with no RPC secret, no StackerDB slot key, no admin role — can perform both requests. The attack is trivially repeatable and costs nothing beyond two short HTTP requests.

### Recommendation
Require an authentication mechanism (e.g., a shared secret configured out-of-band between the Stacks node and the signer, checked via a header or bearer token) before honoring `/status` and, especially, `/shutdown`. At minimum, restrict `/shutdown` to loopback/internal callers or require a token matching what `SignerStopSignaler::send` generates internally, and consider removing the plaintext `/shutdown` HTTP endpoint entirely in favor of an in-process-only stop mechanism (e.g., a Unix socket or the existing `AtomicBool` accessed only via API, not network).

### Proof of Concept
```rust
// libsigner/src/tests/mod.rs style test
use std::io::{Read, Write};
use std::net::TcpStream;

#[test]
fn test_status_then_unauthenticated_shutdown() {
    let mut event_receiver: SignerEventReceiver<SignerMessage> = SignerEventReceiver::new(false);
    let addr = event_receiver.bind("127.0.0.1:0".parse().unwrap()).unwrap();

    // Step 1: recon via GET /status
    let mut stream = TcpStream::connect(addr).unwrap();
    stream.write_all(b"GET /status HTTP/1.1\r\nHost: x\r\nConnection: close\r\n\r\n").unwrap();
    let ev = event_receiver.next_event().unwrap();
    assert_eq!(ev, SignerEvent::StatusCheck);

    // Step 2: unauthenticated POST /shutdown from the same "attacker"
    let mut stream2 = TcpStream::connect(addr).unwrap();
    let body = "die";
    let req = format!(
        "POST /shutdown HTTP/1.1\r\nHost: x\r\nConnection: close\r\nContent-Length: {}\r\n\r\n{}",
        body.len(), body
    );
    stream2.write_all(req.as_bytes()).unwrap();

    // Receiver is now permanently terminated
    let res = event_receiver.next_event();
    assert!(matches!(res, Err(EventError::Terminated)));
}
```
This demonstrates that an unprivileged remote party, with no secret or credential, can confirm liveness and then permanently kill the signer's event stream using only two plain HTTP messages.
