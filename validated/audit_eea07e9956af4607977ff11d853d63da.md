### Title
Unauthenticated forged `BlockValidateResponse` injection via `/proposal_response` on the signer's event-receiver HTTP listener - ([File: libsigner/src/events.rs])

### Summary
The `SignerEventReceiver`'s HTTP listener accepts any POST to `/proposal_response` and deserializes the body directly as `BlockValidateResponse` with no signature, MAC, or auth-header check, then unconditionally converts it into `SignerEvent::BlockValidationResponse` and forwards it to the signer runloop as if it came from the node's own block-validation logic.

### Finding Description
`SignerEventReceiver::next_event` in `libsigner/src/events.rs` (lines 413-459) dispatches based solely on URL path: `/proposal_response` → `process_event::<T, BlockValidateResponse>(request)` (line 440). `process_event` (lines 519-542) reads the raw HTTP body, `serde_json::from_slice`s it into `BlockValidateResponse`, and calls `TryFrom<BlockValidateResponse> for SignerEvent<T>` (lines 627-635), which unconditionally wraps it: `Ok(SignerEvent::BlockValidationResponse(block_validate_response))`. There is no signature, HMAC, or `Authorization` header verification anywhere in this file, nor in the outbound event-dispatcher code that the node uses to legitimately POST these responses (`stacks-node/src/event_dispatcher.rs` / `event_dispatcher/*`, which contains no auth header at all for this channel). The equality "every `BlockValidationResponse` forwarded to the runloop == a response actually produced by this node's own validation logic" is broken: any TCP client that can reach the bound socket (`endpoint = "0.0.0.0:30000"` per `sample/conf/signer/mainnet-signer-conf.toml`, explicitly bindable on all interfaces) can POST an arbitrary JSON `BlockValidateOk`/`BlockValidateReject` body and have it injected verbatim as if the node validated it. The `auth_token`/`auth_password` setting documented in `stackslib/src/config/mod.rs` (lines 3799-3816) only secures the *node's* RPC endpoints (e.g. `/v3/block_proposal`, `/v2/blocks?broadcast=1`); it is never checked on this signer-side listener.

### Impact Explanation
An attacker who can reach the signer's bound endpoint can forge a fabricated block-validation verdict (accept or reject) for any block, causing the signer runloop to act on a verdict that was never produced by real block-validation logic. This is a Critical unauthenticated write into the signer's decision pipeline — a forged/injected message accepted as canonical node output, repeatable on every TCP connection to the listening port, requiring no privileged role, secret, or prior handshake. This matches the required Critical impact category: "unauthenticated/unauthorized write to state" via forged validation verdicts feeding the signing runloop.

### Likelihood Explanation
Preconditions: reachability to the `SignerEventReceiver`'s bound TCP port. Reference configs explicitly show `endpoint = "0.0.0.0:30000"` (all-interfaces bind) in `sample/conf/signer/mainnet-signer-conf.toml`; `SpawnedSigner::new` even warns operators about exposing this listener to non-local networks (`stacks-signer/src/lib.rs` lines 125-132), acknowledging the listener is unauthenticated by design and dangerous if reachable remotely. No secret, signature, or slot ownership is required — the attacker just needs to complete a TCP connection and send a well-formed HTTP POST with JSON body; this is trivially repeatable.

### Recommendation
Add authentication to the `SignerEventReceiver`'s HTTP listener: require and verify a shared-secret `Authorization` header (reusing the existing `auth_token`/`auth_password` config values) on every incoming request in `next_event`/`process_event` before deserializing and converting the body into a `SignerEvent`, rejecting any request lacking a valid token with 401 before parsing.

### Proof of Concept
```rust
// libsigner/src/tests/mod.rs (concept)
use std::net::TcpStream;
use std::io::Write;
use libsigner::events::{SignerEventReceiver, EventReceiver};

#[test]
fn test_forged_proposal_response_injection() {
    let mut receiver = SignerEventReceiver::<SignerMessageV0>::new(false);
    let addr = receiver.bind("127.0.0.1:0".parse().unwrap()).unwrap();

    // Attacker, with no credentials, connects directly and POSTs a synthetic
    // BlockValidateResponse::Ok payload.
    let mut stream = TcpStream::connect(addr).unwrap();
    let body = serde_json::to_string(&forged_block_validate_ok()).unwrap();
    let req = format!(
        "POST /proposal_response HTTP/1.1\r\nHost: {addr}\r\nContent-Length: {}\r\nContent-Type: application/json\r\n\r\n{}",
        body.len(), body
    );
    stream.write_all(req.as_bytes()).unwrap();

    // Node-side call: next_event() returns the forged verdict verbatim,
    // with no signature/auth check anywhere in the path.
    let event = receiver.next_event().unwrap();
    assert!(matches!(event, SignerEvent::BlockValidationResponse(_)));
}
```
This demonstrates `next_event()` returning `SignerEvent::BlockValidationResponse` built entirely from attacker-controlled bytes with no verification of origin.
