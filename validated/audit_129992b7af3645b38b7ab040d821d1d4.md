### Title
Chained liquidations by seizing the highest `collateralFactor` collateral exceed `maxLiquidable` - (File: contracts/Pool.sol)

### Summary
`Pool.liquidate` lets the liquidator choose which `DepositToken` to seize, enforces the `maxLiquidable` cap only per call, and only requires the position to be unhealthy *before* the liquidation — there is no post-liquidation health check. When a victim holds multiple collaterals, a liquidator can deliberately seize the collateral with the highest `collateralFactor`, which removes the most weighted issuable power per unit of debt repaid. If `collateralFactor * (1 + liquidatorIncentive + protocolFee) > 1`, the position remains unhealthy after the call, so the liquidation can be repeated until the victim's collateral is almost fully drained — far beyond the intended `maxLiquidable` (default 50%) bound.

### Finding Description
In `Pool.liquidate` (`contracts/Pool.sol:537-596`):

- The liquidator passes `depositToken_` freely (`onlyIfDepositTokenExists` only checks it is a registered collateral).
- Health is checked once before seizing: `debtPositionOf` computes `_isHealthy = _debtInUsd <= _issuableLimitInUsd` where `_issuableLimitInUsd` is the sum of `depositUsd * collateralFactor` per asset (`Pool.sol:264`, `Pool.sol:286`).
- The only size limit is `amountToRepay_.wadDiv(_debtTokenBalance) > maxLiquidable` (`Pool.sol:567`), which is measured against the *current* debt balance per call.
- `quoteLiquidateOut` seizes `repayValue * (1 + protocolFee + liquidatorIncentive)` worth of the chosen collateral (`Pool.sol:451-472`), and `depositToken_.seize` removes it from the victim.
- There is no check that the position is healthy (or healthier) after the call — unlike `DebtToken.issue`/withdraw paths that require post-action health.

Concretely, repaying `R` USD of debt reduces `_debtInUsd` by `R` but reduces `_issuableLimitInUsd` by `R * (1 + fees) * CF_chosen`. If `CF_chosen > 1 / (1 + fees)` (e.g. CF = 0.95 with total liquidation fees ≈ 4%), the issuable limit falls *faster* than the debt, so the victim is still liquidatable and the call can be chained. By repeatedly seizing the highest-CF collateral, the liquidator bypasses the intended 50% cap; the same trick fails if forced to seize the lowest-CF collateral, since the limit then falls slower than the debt and the position heals. This is the identical mechanism as the Wise Lending M-09 finding: identical pre-only health check, per-call fraction cap, and liquidator-chosen collateral.

Additionally, unlike Wise Lending, Metronome has no "bad debt → full liquidation" distinction at all — `maxLiquidable` applies uniformly — so exceeding it via chaining is a direct violation of the only liquidation bound the protocol enforces. The `debtFloorInUsd` check (`Pool.sol:571-579`) only constrains the residual debt size and does not prevent chaining.

### Impact Explanation
A liquidator can seize substantially more than `maxLiquidable` (50%) of a victim's collateral while the position is only mildly underwater, extracting the liquidation incentive on each chained call. The victim suffers liquidation penalties on a much larger share of their position than the protocol intends — direct loss of user funds proportional to `(totalSeized - maxLiquidable-worth) * incentive`.

### Likelihood Explanation
Requires: (a) a victim with ≥2 deposit tokens where a high-CF token satisfies `CF > 1/(1+fees)`; (b) the position becoming unhealthy. Metronome lists volatile collaterals (WETH, wstETH, cbETH) alongside stablecoins (USDC, DAI) whose deployed collateral factors are typically high (0.9+), so condition (a) is plausible on deployed pools — though the exact deployed `collateralFactor`/`liquidatorIncentive` values were not fully verifiable from the indexed deployment artifacts (the init args are embedded in proxy deployment data not exposed in the ABI JSONs), the structural condition is the same one the Wise Lending judge accepted as plausible "by chance." The liquidator is unprivileged and needs only the synth to repay, obtainable via `DebtToken.issue` on their own position or `Pool.swap`.

### Recommendation
- Enforce a post-liquidation invariant: after `seize`, recompute `debtPositionOf(account_)` and revert (or require the position to be healthy) if the liquidation did not restore health — this caps effective liquidation at the amount needed to heal the position.
- Alternatively, order collateral seizure by ascending `collateralFactor`, or compute `maxLiquidable` against the total seized across a liquidation sequence rather than per call.

### Proof of Concept
Fork-test outline (Hardhat, mirroring `test/Pool.test.ts` liquidation setup):

```ts
// victim deposits two collaterals:
//  - highCF token (e.g. USDC deposit token, CF = 0.95) worth X
//  - lowCF  token (e.g. WETH deposit token, CF = 0.60) worth X
// victim issues msUSD up to ~98% of issuableLimit
// oracle price drop on lowCF token -> debt > issuableLimit (unhealthy)

// Liquidator (owns msUSD from own position / swap):
// loop:
//   pool.liquidate(msUSD, victim, debtToken.balanceOf(victim) * maxLiquidable, highCFDepositToken)
// until AmountIsTooHigh / balance exhausted
// assert totalRepaid > 0.5 * initialDebt   // exceeds intended cap
// assert still-unhealthy between calls, i.e. PositionIsHealthy never reverts

// Control: liquidate seizing lowCFDepositToken once ->
//   position becomes healthy; subsequent liquidate() reverts PositionIsHealthy
```

Key assertion: `sum(amountToRepay) / initialDebt > maxLiquidable` while all calls succeeded — demonstrating the bound was bypassed purely by collateral choice, with no privileged role, no oracle manipulation, and no reentrancy.

Caveat: the chained-liquidation condition `CF * (1 + fees) > 1` must be confirmed against the deployed `collateralFactor` of the chosen `DepositToken` and `feeProvider.liquidationFees()`; if all deployed collaterals satisfy `CF * (1+fees) <= 1`, the per-call seize always heals the position and this reduces to non-exploitable. The code itself contains no guard either way, so the finding stands as a missing-invariant issue on the liquidation path. [1](#0-0) [2](#0-1) [3](#0-2)

    function liquidate(
        ISyntheticToken syntheticToken_,
        address account_,
        uint256 amountToRepay_,
        IDepositToken depositToken_
    )
        external
        override
        whenNotShutdown
        nonReentrant
        onlyIfSyntheticTokenExists(syntheticToken_)
        onlyIfDepositTokenExists(depositToken_)
        returns (uint256 _totalSeized, uint256 _toLiquidator, uint256 _fee)
    {
        address _msgSender = _msgSender();

        if (amountToRepay_ == 0) revert AmountIsZero();
        if (_msgSender == account_) revert CanNotLiquidateOwnPosition();

        IDebtToken _debtToken = debtTokenOf[syntheticToken_];
        _debtToken.accrueInterest();

        (bool _isHealthy, , , , ) = debtPositionOf(account_);

        if (_isHealthy) {
            revert PositionIsHealthy();
        }

        uint256 _debtTokenBalance = _debtToken.balanceOf(account_);

        if (amountToRepay_.wadDiv(_debtTokenBalance) > maxLiquidable) {
            revert AmountGreaterThanMaxLiquidable();
        }

        if (debtFloorInUsd > 0) {
            uint256 _newDebtInUsd = masterOracle().quoteTokenToUsd(
                address(syntheticToken_),
                _debtTokenBalance - amountToRepay_
            );
            if (_newDebtInUsd > 0 && _newDebtInUsd < debtFloorInUsd) {
                revert RemainingDebtIsLowerThanTheFloor();
            }
        }

        (_totalSeized, _toLiquidator, _fee) = quoteLiquidateOut(syntheticToken_, amountToRepay_, depositToken_);

        if (_totalSeized > depositToken_.balanceOf(account_)) {
            revert AmountIsTooHigh();
        }

        syntheticToken_.burn(_msgSender, amountToRepay_);
        _debtToken.burn(account_, amountToRepay_);
        depositToken_.seize(account_, _msgSender, _toLiquidator);

        if (_fee > 0) {
            depositToken_.seize(account_, _poolRegistry.feeCollector(), _fee);
        }

        emit PositionLiquidated(_msgSender, account_, syntheticToken_, amountToRepay_, _totalSeized, _fee);
    }
