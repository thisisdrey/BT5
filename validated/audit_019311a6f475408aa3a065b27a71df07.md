### Title
Nep245/Imt protocol fee bypass via splitting `TokenDiff` amounts into unit (`amount == 1`) legs across multiple intents in one batch - (`contracts/defuse/core/src/intents/token_diff.rs`)

### Finding Description

The intended fee invariant is: for token `T`, `fees_collected[T] == fee.fee_ceil(total negative exposure to T in the batch)`. In practice, `TokenDiff::token_fee` is evaluated **independently per `TokenDiff` intent, per token, using only that single intent's `delta`** — not any aggregate exposure: [1](#0-0) 

The fee-exemption match arm treats any Nep245/Imt leg with `amount <= 1` as a "single NFT-like unit" and charges `Pips::ZERO`, but only charges `fee` when `amount > 1`: [2](#0-1) 

Since a `MultiPayload` batch can contain many separately signed `TokenDiff` intents, and each is fee-evaluated in isolation inside its own `execute_intent` call via `Engine::execute_signed_intent` → `intents.execute_intent`, an attacker holding balance `N` of a Nep245 token can split a withdrawal of `N` units into `N` separate signed `TokenDiff` intents, each with `delta == -1` on the same `token_id`. Each individual call to `token_fee(token_id, 1, fee)` hits the `amount > 1` guard as false, returning `Pips::ZERO`, so `fee_ceil(1) == 0` every time. Doing it as one intent with `delta == -2` (or `-N`) instead hits `amount > 1 => {}` and pays real `fee.fee_ceil(N)`.

Attacker's exact construction: sign `k` separate `MultiPayload`s (or `k` separate `Intents::TokenDiff` intents within one batch) from the same or a colluding second account, each `{ token_id: T (Nep245), delta: -1 }` paired with an offsetting counter-leg (e.g. `+1` unit of another token they also control, matched by a second attacker-controlled account's mirrored diffs) so that `TransferMatcher::finalize` still nets every token to zero across the whole batch (required, since `execute_intents` panics/reverts on `InvariantViolated` per `contracts/defuse/src/contract/intents/mod.rs` line 27-30). None of `MultiPayload::verify`, nonce/salt checks, `Lock`, or `TransferMatcher::finalize` inspect the *fee* correctness — they only verify signatures, nonces, and that deltas net to zero; they have no concept of "this could have been one bigger intent."

### Impact Explanation

Fees credited to `fee_collector` for token `T` are systematically under-collected relative to the true aggregate negative exposure to `T` in the batch, i.e. `Σ fees_collected[T]` over unit-split legs `== 0` while a single-shot `delta=-N` leg would yield `fee.fee_ceil(N) > 0` for any `fee > 0` and `N > 1`. This is value that legitimately belonged to the protocol (`fee_collector`) that never gets credited — matching the "protocol fees bypassed" Critical category. It is fully repeatable: any signer with any Nep245/Imt balance and any counterparty (including a second self-controlled account) can apply this to every trade, scaling linearly with the number of unit-split legs the attacker is willing to sign (bounded practically by gas/tx-size limits, but trivially demonstrable with `N=2`, i.e. two legs).

### Likelihood Explanation

Preconditions are minimal and fully attacker-controlled: possession of ≥2 units of a Nep245 (or Imt) token balance in the Verifier, ability to sign `TokenDiff` intents (any account can do this), and any counterparty providing offsetting legs (which can be a second account the same attacker also controls, since `execute_intents`/`TransferMatcher` only require batch-wide netting, not economically meaningful counterparties). No privileged role, relayer key, or DAO action is needed. Cost is just gas for one extra signed intent per unit split, so it's cheap and directly repeatable.

### Recommendation

Compute the Nep245/Imt fee-exemption threshold and fee amount against the aggregate negative delta for a given `token_id` across the entire batch (or at minimum across all `TokenDiff` intents from the same `signer_id` within the batch) rather than per individual `TokenDiff` intent leg, e.g. by pre-summing all negative deltas per `token_id` in `Engine::execute_signed_intents` before applying `TokenDiff::token_fee`, or by disallowing splitting the same token's exposure across multiple intents within one execution.

        if self.diff.is_empty() {

        }

        let protocol_fee = engine.state.fee();
        let mut fees_collected: Amounts = Amounts::default();

        for (token_id, delta) in &self.diff {
            if *delta == 0 {
                return Err(DefuseError::InvalidIntent);

                .state
                .internal_apply_deltas(signer_id, [(token_id.clone(), *delta)])?;

                // collect fee

impl Intents for Contract {
    #[pause(name = "intents")]
    fn execute_intents(&mut self, signed: Vec<MultiPayload>) {
        if let Some(event) = Engine::new(self, ExecuteInspector::default())
            .execute_signed_intents(signed)
            .unwrap_or_else(|e| e.panic())
            .as_mt_event()
        {
            // NOTE: Not all `mt_transfer` events are refundable, but it's safe to check them
            // all at once since non-refundable transfers only increase the potential refund
            // log size without affecting correctness. This can actually prevent resolve transfer
            // from failing due to too long event log !!!
            event
                .check_refund()
                .unwrap_or_else(|err| err.panic())
                .emit();
        }
    }
