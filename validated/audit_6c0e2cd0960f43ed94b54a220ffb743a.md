### Title
Bazel's `git_repository`/`new_git_repository` force `protocol.file.allow=always` for submodule updates, re-enabling attacker-controlled local-file reads outside the checkout - (File: `tools/build_defs/repo/git_worker.bzl`)

### Summary
When `init_submodules`/`recursive_init_submodules` is set on `git_repository`/`new_git_repository`, Bazel unconditionally runs `git submodule update` with `-c protocol.file.allow=always`, which disables Git's own default protection against local-clone/`file://` submodule attacks. Since the `.gitmodules` file (including any submodule `url =` entries) is part of the fetched commit/tag/branch tree, its contents are fully attacker-controlled whenever the fetched ref comes from an untrusted or externally influenced source (a public mirror, a compromised upstream, or a PR/branch built by CI). With `protocol.file.allow=always` forced, Git will happily perform a local "file" clone of an arbitrary path specified by the attacker's `.gitmodules`, which — combined with Git's local-clone hardlink/symlink optimization (the exact class of bug that upstream Git disabled `file://` for by default, e.g. via GHSA/CVE-2022-39253-style local-clone symlink issues) — lets the attacker cause files to be read/linked from outside the intended checkout directory into the build tree.

### Finding Description
`update_submodules` in [1](#0-0)  always injects `-c protocol.file.allow=always` before running `git submodule update --init [--recursive] --checkout --force`, regardless of whether the fetched repository is trusted:

```
def update_submodules(ctx, git_repo, recursive = False):
    if recursive:
        _git_maybe_shallow(ctx, git_repo, "-c", "protocol.file.allow=always", "submodule", "update", "--init", "--recursive", "--checkout", "--force")
    else:
        _git_maybe_shallow(ctx, git_repo, "-c", "protocol.file.allow=always", "submodule", "update", "--init", "--checkout", "--force")
```

The comment references bazelbuild/bazel#17040, indicating this override was added purely to keep submodule updates functioning after upstream Git changed the default to reject `file://` submodule URLs for security reasons.

`.gitmodules` is ordinary tracked content inside the fetched commit/tag/branch, so once `git_repo()` (called from `_update` in the same file, [2](#0-1)  ) resets to the attacker-influenced `reset_ref` and runs `update_submodules`, any submodule URL the attacker placed in `.gitmodules` — including a local/`file://`-style URL — is honored. Because `git_repository` has no content checksum mechanism (unlike `http_archive`'s `sha256`), the "commit" pin only fixes *which* commit is fetched, not that the source of that commit is trustworthy; an outsider who controls a branch/tag/PR that a build fetches (or who compromises/typosquats a mirror at the configured `remote`) fully controls that commit's `.gitmodules` content.

### Impact Explanation
Forcing `protocol.file.allow=always` reopens the exact class of Git behavior upstream disabled by default: a malicious `.gitmodules` submodule URL pointing at a local path can trigger Git's local-clone fast path, which under certain conditions (symlinks/hardlinks within the attacker-controlled "submodule directory" content) can cause Git to read or link file contents from outside the checkout it is supposed to be confined to. This is a read-outside-the-intended-repository primitive that undermines the "content stays contained" invariant relied on by Bazel's repository fetch machinery, potentially exposing local files on the build machine (source of other targets, credentials or config files sitting on the host filesystem, etc.) into the fetched repository/build tree.

### Likelihood Explanation
Any Bazel workspace using `git_repository`/`new_git_repository` with `init_submodules = True` or `recursive_init_submodules = True` (a common attribute) against a `remote` that is a public/shared repository, a mirror, or a CI job that builds from external branches/PRs is exposed. The attacker only needs write access to content that is eventually checked out by the build (a branch, tag, or fork the CI resolves) — no access to the victim's machine, credentials, or trusted root BUILD/.bzl files is required, since only the fetched repository's own `.gitmodules` needs to be malicious. The override is applied unconditionally and by default, with no flag to opt out.

### Recommendation
Stop forcing `protocol.file.allow=always` for arbitrary/untrusted remotes. At minimum:
- Only allow `protocol.file.allow` for submodule paths that resolve within the already-cloned repository/checkout directory (mirroring the `strip_prefix` containment checks already done in `tools/build_defs/repo/git.bzl`), rather than globally re-enabling local-clone semantics.
- Prefer `http_archive` (which supports `sha256` integrity) over `git_repository` for untrusted sources, and document the risk of `init_submodules`/`recursive_init_submodules` with non-fully-trusted remotes.
- Consider validating/rejecting `.gitmodules` entries with `file://`/local-path submodule URLs unless explicitly opted into by the rule invoker.

### Proof of Concept
A `src/test/shell/bazel/starlark_git_repository_test.sh`-style integration test can demonstrate the issue:
1. Create an "attacker" git repo whose tracked tree includes a `.gitmodules` file with a submodule entry `url = file:///<path-to-a-secret-directory-outside-the-checkout>` (using a directory containing a marker file/symlink outside the intended workspace tree, mirroring the existing `test_git_repository_submodules` test scaffold at [3](#0-2) ).
2. Configure `git_repository(name="victim", remote="<attacker_repo_dir>", commit="<attacker_commit>", init_submodules=True)` in `MODULE.bazel`.
3. Run `bazel build //...` and observe that Bazel's forced `-c protocol.file.allow=always` ( [4](#0-3) ) allows the local-file submodule clone to succeed and the marker file from outside the checkout directory to appear inside `external/+git_repository+victim`, whereas with default Git settings (`protocol.file.allow=user`) the clone would be refused.

def update_submodules(ctx, git_repo, recursive = False):
    if recursive:
        # "protocol.file.allow=always" allows the submodule command clone from a local directory.
        # It's necessary for Git 2.38.1 and assoicated backport versions.
        # See https://github.com/bazelbuild/bazel/issues/17040

        _git_maybe_shallow(ctx, git_repo, "-c", "protocol.file.allow=always", "submodule", "update", "--init", "--checkout", "--force")

git_repository = use_repo_rule('@bazel_tools//tools/build_defs/repo:git.bzl', 'git_repository')

exports_files(['outer_planets.BUILD'])

filegroup(
