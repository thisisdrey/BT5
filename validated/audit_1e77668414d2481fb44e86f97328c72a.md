## Finding: Unauthenticated handshake-replay can perpetually poison a target's learned remote address via `SetRemoteIfPreferred`

### Title
Unauthenticated Replay of a Captured Stage-1 Handshake Packet Lets an Attacker Perpetually Reset a Peer's Preferred Remote Address - ([File: handshake_manager.go])

### Summary
The Sherlock bug class is: a state field (`lockedUntil`) that is meant to protect a legitimate actor (`feeRecipient`) gets reset every time an *unprivileged* action fires, and an attacker can trigger that action indefinitely to keep the legitimate actor locked out forever. The Nebula analog is the `ErrAlreadySeen` branch of the handshake responder path: replaying a previously observed (byte-identical) stage-1 handshake packet — something that requires no CA-signed certificate of the attacker's own, only capture/replay capability plus UDP source spoofing — repeatedly invokes `SetRemoteIfPreferred`, which unconditionally overwrites the target's tracked "preferred remote" address whenever the spoofed source falls in a preferred range, with no anti-replay or roam-suppression guard on this code path.

### Finding Description
When a stage-1 handshake packet arrives and `CheckAndComplete` finds a byte-identical `HandshakePacket[handshakePacketStage0]` already stored for an existing tunnel, it returns `ErrAlreadySeen` without validating that the sender is anything more than "produced these same bytes again": [1](#0-0) 

`handleCheckAndCompleteError` then reacts to `ErrAlreadySeen` by calling `existing.SetRemoteIfPreferred(f.hostMap, via)`, driven purely by the `via` (attacker-controlled/spoofable UDP source) of this replayed packet: [2](#0-1) 

`SetRemoteIfPreferred` unconditionally calls `SetRemote(via.UdpAddr)` whenever the incoming source address falls in a "preferred range" and the current remote does not, with no rate limiting or suppression: [3](#0-2) 

This is distinct from the equivalent post-authentication roaming path (`handleHostRoaming`, only reachable after a successful `Decrypt` of a data packet, i.e. requiring valid session keys derived from a CA-signed cert), which does have suppression via `lastRoam`/`lastRoamRemote`/`RoamingSuppressSeconds`: [4](#0-3) 

The `ErrAlreadySeen` path has no such guard, so an attacker who has captured one legitimate stage-1 packet (e.g. by being on-path once, or observing traffic) can replay those exact bytes from a spoofed UDP source address that lies inside a preferred CIDR, and the responder will happily flip its outbound "preferred remote" toward that spoofed address every time — with no certificate check on the replay itself, since the branch is taken before any new noise processing occurs.

### Impact Explanation
By repeatedly resending the captured msg1 bytes from a spoofed source in the preferred range, an attacker can continuously pin/poison the responder's `remote` field for a legitimate peer's `HostInfo`, causing subsequent outbound data-plane traffic destined for the real peer to be redirected to the attacker-chosen address instead — denying the legitimate peer connectivity indefinitely, mirroring the "perpetually locked resource via repeated benign-looking reset" pattern from the source report (there: `lockedUntil` reset via mint; here: preferred-remote reset via handshake replay). This is a remote state poisoning / traffic redirection impact reachable without any CA-signed certificate.

### Likelihood Explanation
Requires: (1) capturing one legitimate stage-1 handshake packet (byte-for-byte), and (2) the ability to spoof a UDP source address inside one of the node's configured `preferred_ranges` (commonly private/overlay subnets, which are often satisfiable on shared LAN/cloud VPC segments). Both capabilities are attacker-side network primitives, not cryptographic identity — no cert issuance by the CA is needed, making this reachable by a certificate-less attacker as required.

### Recommendation
Do not let the `ErrAlreadySeen` replay-detection branch drive `SetRemoteIfPreferred`/`SetRemote` based solely on matching stored ciphertext-adjacent handshake bytes plus an unauthenticated `via` address. Either (a) drop the remote-address update entirely on this path and only allow roaming reassessment on the already-suppressed, post-decryption `handleHostRoaming` path, or (b) apply the same `lastRoam`/`RoamingSuppressSeconds` throttling used in `handleHostRoaming` to the `ErrAlreadySeen` handling in `handleCheckAndCompleteError`.

### Proof of Concept
1. Attacker passively captures a legitimate stage-1 handshake UDP packet sent by peer `me` to responder `them` (byte-identical payload, header, and index).
2. Attacker repeatedly re-injects that identical packet toward `them`, spoofing the UDP source address to some address inside `them`'s configured `preferred_ranges` (distinct from `me`'s real current address, e.g. `preferred_ranges: ["10.0.0.0/8"]`).
3. `them`'s `CheckAndComplete` matches the stored `HandshakePacket[handshakePacketStage0]` byte-for-byte and returns `ErrAlreadySeen` (see `handshake_manager.go:436-444`).
4. `handleCheckAndCompleteError` calls `existing.SetRemoteIfPreferred(f.hostMap, via)` with the spoofed `via`, and since the spoofed source is "preferred" while the current remote is not, `SetRemote(via.UdpAddr)` fires (see `handshake_manager.go:1104-1113`, `hostmap.go:787-823`).
5. `them`'s outbound tunnel traffic to `me` is now redirected toward the attacker-spoofed address; repeating steps 2–4 on any attempt by the real `me` to re-establish the correct remote perpetually re-poisons it.

// SetRemoteIfPreferred returns true if the remote was changed. The lastRoam
// time on the HostInfo will also be updated.
func (i *HostInfo) SetRemoteIfPreferred(hm *HostMap, via ViaSender) bool {
	if via.IsRelayed {
		return false
	}

	currentRemote := i.GetRemote()
	if !currentRemote.IsValid() {
		i.SetRemote(via.UdpAddr)
		return true
	}

	// NOTE: We do this loop here instead of calling `isPreferred` in
	// remote_list.go so that we only have to loop over preferredRanges once.
	newIsPreferred := false
	for _, l := range hm.GetPreferredRanges() {
		// return early if we are already on a preferred remote
		if l.Contains(currentRemote.Addr()) {
			return false
		}

		if l.Contains(via.UdpAddr.Addr()) {
			newIsPreferred = true
		}
	}

	if newIsPreferred {
		// Consider this a roaming event
		i.lastRoam = time.Now()
		i.lastRoamRemote = currentRemote

		i.SetRemote(via.UdpAddr)

		return true
	}

	return false
}

func (f *Interface) handleHostRoaming(hostinfo *HostInfo, via ViaSender) {
	curRemote := hostinfo.GetRemote()
	if !via.IsRelayed && curRemote != via.UdpAddr {
		if !f.lightHouse.GetRemoteAllowList().AllowAll(hostinfo.vpnAddrs, via.UdpAddr.Addr()) {
			if f.l.Enabled(context.Background(), slog.LevelDebug) {
				hostinfo.logger(f.l).Debug("lighthouse.remote_allow_list denied roaming", "newAddr", via.UdpAddr)
			}
			return
		}

		if !hostinfo.lastRoam.IsZero() && via.UdpAddr == hostinfo.lastRoamRemote && time.Since(hostinfo.lastRoam) < RoamingSuppressSeconds*time.Second {
			if f.l.Enabled(context.Background(), slog.LevelDebug) {
				hostinfo.logger(f.l).Debug("Suppressing roam back to previous remote",
					"suppressSeconds", RoamingSuppressSeconds,
					"udpAddr", curRemote,
					"newAddr", via.UdpAddr,
				)
			}
			return
		}

		hostinfo.logger(f.l).Info("Host roamed to new udp ip/port.",
			"udpAddr", curRemote,
			"newAddr", via.UdpAddr,
		)
		hostinfo.lastRoam = time.Now()
		hostinfo.lastRoamRemote = curRemote
		hostinfo.SetRemote(via.UdpAddr)
	}
