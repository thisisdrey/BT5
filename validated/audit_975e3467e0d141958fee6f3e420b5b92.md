### Title
Global unstaked-agnostic `overall_connection_rate_limiter` can be exhausted by a many-IP unstaked attacker, starving staked/legitimate peers' new TPU connections - ([File: streamer/src/nonblocking/quic.rs])

### Summary
`run_server`'s incoming-connection loop first checks a single global `TokenBucket` (`overall_connection_rate_limiter`, capacity `MAX_CONNECTION_BURST` = 1000, refill `TOTAL_CONNECTIONS_PER_SECOND` = 2500/s) before any per-IP or per-stake check is possible, and the token is actually consumed in `setup_connection` only after a completed handshake, regardless of stake. Since stake identity cannot be known until after the TLS handshake completes, this global limiter is by design applied uniformly to staked and unstaked peers alike, so a distributed unstaked attacker with many real source IPs can consume the shared budget and cause new connection attempts from legitimate/staked peers to be dropped (`incoming.ignore()`) during that window.

### Finding Description
In `run_server`, before any identity/stake information is available, the code checks the shared bucket: [1](#0-0) 
only afterwards applying the per-IP `rate_limiter.is_allowed` check: [2](#0-1) 
The actual token consumption of `overall_connection_rate_limiter` happens later in `setup_connection`, only after a full QUIC handshake succeeds: [3](#0-2) 
Stake is only determined afterwards via `get_connection_stake`, which requires a completed connection and TLS certificate extraction: [4](#0-3) 

The constants bounding the shared bucket are modest and global to the whole endpoint: [5](#0-4) 

Because the limiter is a single `TokenBucket` shared across all source IPs and all peers (staked or not), and because stake cannot be evaluated pre-handshake, an unstaked attacker who controls (or rotates through) enough distinct real IPs (each completing a legitimate QUIC handshake, since blind IP spoofing cannot complete a handshake and thus cannot consume this token) can consistently keep the bucket at zero. When `overall_connection_rate_limiter.current_tokens() == 0`, the pre-check at line 347 rejects **every** subsequent incoming connection attempt including from staked, previously-unconnected peers, before any per-IP or per-stake logic runs. This is an explicitly acknowledged design tradeoff in the code's own comment (lines 331-340): the pre-authentication "shed fast" policy intentionally cannot distinguish stake before a peer proves address ownership via handshake completion.

### Impact Explanation
Scoped impact is TPU-wide new-connection starvation: once the shared bucket is exhausted, staked validators/forwarders attempting to open **new** QUIC connections to that leader's TPU (e.g., when leader rotates and they must establish a fresh connection) will have their `Incoming` ignored regardless of stake, denying them TPU capacity for that throttling window. This matches the compute-budget/QoS bounty category "unprivileged client can bypass/unfairly capture connection... QoS limits and starve legitimate senders of TPU capacity." Already-established persistent connections are unaffected, limiting the blast radius to new connection setup during attack windows, but this still degrades availability for validators onboarding to a new leader during sustained attack traffic.

### Likelihood Explanation
Feasibility requires the attacker to originate real (non-spoofed, response-receiving) traffic from many distinct IPs, since token consumption occurs only after full handshake completion — this rules out cheap off-path IP spoofing but is achievable via botnets, cloud IP rotation, or IPv6 address-range abuse, none of which require stake, keys, or privileged access. The bucket is small (burst 1000, sustained 2500/s) relative to plausible botnet/NAT-pool scale, making sustained saturation realistic and repeatable for the duration of an attack campaign.

### Recommendation
Not applicable per this audit's scope guidance — the underlying tradeoff (no stake information is available pre-handshake) is explicitly documented as an intentional design decision in the code itself rather than an overlooked bug, and mitigating it (e.g., via address validation/retry tokens, per-source-subnet budgets, or reserving budget headroom for previously-seen staked IPs) would be a design change rather than a straightforward fix; a Devin implementation plan is not included here per instructions since this is an audit/answer-only response.

#[tokio::test]
async fn test_rate_limiting() {
    let SpawnTestServerResult {
        join_handle: server_handle,
        receiver,
        server_address,
        stats: _stats,
        cancel,
    } = setup_quic_server(
        None,
        QuicStreamerConfig {
            max_connections_per_ipaddr_per_min: 1,
            ..QuicStreamerConfig::default_for_tests()
        },
        SwQosConfig {
            max_connections_per_unstaked_peer: 100,
            ..Default::default()
        },
    );

    // open a connection to consume the limit
    let connection_to_reach_limit = make_client_endpoint(&server_address, None).await;
    drop(connection_to_reach_limit);

    // Setup sending transactions which are full packets in size
    let transaction_size = 1024;
    let expected_num_transactions: usize = 16;
    let SpawnTransactionGenerator {
        transaction_receiver,
        transaction_sender_shutdown,
        ..
    } = spawn_transaction_sender(
        transaction_size,
        expected_num_transactions,
        Duration::from_millis(100),
    );

    let (scheduler_handle, _update_certificate_sender, scheduler_cancel) =
        setup_connection_worker_scheduler(server_address, transaction_receiver, None).await;

    let actual_num_packets =
        count_received_packets_for(receiver, transaction_size, TEST_MAX_TIME).await;
    assert_eq!(actual_num_packets, 0);

    // Stop the sender.
    transaction_sender_shutdown.await;

    // And the scheduler.
    scheduler_cancel.cancel();
    let stats = join_scheduler(scheduler_handle).await;

    assert!(
        stats
            == SendTransactionStatsNonAtomic {
                connection_error_timed_out: 1,
                ..Default::default()
            }
    );

    // Stop the server.
    cancel.cancel();
    server_handle.await.unwrap();
}
