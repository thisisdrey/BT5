Found the analog: `handleRecvError` in `outside.go` is the closest match to the HyVM `callcode`/`selfdestruct` bug class — an unrestricted, low-privilege operation reachable by a fully unauthenticated attacker (a bare `RecvError` header, no handshake, no cert, no encryption) that directly tears down (destroys) an established tunnel/session state, mirroring how `callcode`+`selfdestruct` let an unauthenticated caller destroy the HyVM contract and, combined with a second issue, silently break a victim's in-flight operations.

### Title
Unauthenticated RecvError packet allows any attacker to tear down another host's live tunnel - (File: outside.go)

### Summary
`readOutsidePackets` dispatches `header.RecvError` packets to `f.handleRecvError` before any packet is decrypted, verified, or tied to a completed handshake [1](#0-0) . `handleRecvError` looks up the target tunnel purely by the attacker-supplied `h.RemoteIndex` (a 32-bit value carried in the plaintext header) via `QueryReverseIndex`, and if the tunnel's currently known remote UDP address happens to match the sender's `addr` — which an attacker can trivially satisfy from an unauthenticated, off-path or same-network vantage point by simply sending from/spoofing that same source address — it calls `f.closeTunnel(hostinfo)`, immediately destroying the tunnel state [2](#0-1) .

### Finding Description
This is structurally analogous to the HyVM `callcode` finding: HyVM exposed `callcode` with no restriction, letting anyone destroy the shared contract state via `selfdestruct`. Here, Nebula exposes the `RecvError` message type with no cryptographic authentication requirement at all — it's handled in the "Unencrypted packets" branch of `readOutsidePackets`, alongside `Handshake` [3](#0-2) . The only "check" is `hr.IsValid() && hr != addr` — comparing the tunnel's currently recorded remote `UdpAddr` against the packet's source address [4](#0-3) . This is not an authentication check; it is a UDP source-address match, which is spoofable by any attacker capable of sending UDP datagrams toward the target (on-path attacker, or off-path when source validation of UDP is weak, e.g. via NAT/firewall traversal paths that Nebula itself is designed to punch through). Once that weak check passes, `closeTunnel` unconditionally destroys the `HostInfo` from the hostmap and clears learned lighthouse state [5](#0-4) , exactly the "destroy the shared, trusted state used by all subsequent operations" pattern the HyVM report describes for `callcode`+`selfdestruct`.

### Impact Explanation
An attacker with no valid CA-signed certificate and no completed handshake can force-terminate an already-established, mutually-authenticated tunnel between two legitimate peers simply by guessing/observing the `RemoteIndex` (32-bit, sent in cleartext on every packet) and spoofing the source address the victim currently associates with its peer. This causes an immediate denial of service: the victim's live tunnel is torn down, in-flight application traffic is dropped, and — mirroring the HyVM exploit scenario where destroying HyVM silently breaks a victim's pending operation — any time-sensitive operation relying on that tunnel (e.g., a control-plane update, a monitoring heartbeat, or reconnection logic) is disrupted without the victim's true peer having done anything wrong.

### Likelihood Explanation
`RecvError` handling is gated only by `ShouldRecvError(addr)`, a rate/config gate, not authentication [6](#0-5) . `RemoteIndex` values are transmitted unencrypted on every data-plane packet, so an attacker positioned to observe any traffic between the peers (or who can brute-force/guess the 32-bit index) can construct a valid-looking `RecvError` packet without needing any certificate, key material, or completed Noise handshake. This keeps the attack within reach of a certificate-less attacker, matching the required threat model.

### Recommendation
- Short term: Require `RecvError` to be authenticated (e.g., signed/MAC'd with the tunnel's established keys, or only accepted from within an already-encrypted channel) before triggering `closeTunnel`, rather than relying on a spoofable source-address comparison.
- Long term: Audit all unauthenticated/unencrypted packet types (`RecvError`, hole-punch, handshake stage-1) for state-mutating side effects and document why each mutation is safe to leave pre-authentication, similar to the HyVM recommendation to document every opcode's justification.

### Proof of Concept
1. Establish a legitimate tunnel between hosts A and B; record B's `localIndexId` (visible in every plaintext Nebula header as `RemoteIndex` from A's perspective).
2. From attacker-controlled host C, spoof or otherwise send UDP traffic with source address equal to A's currently known address (the address B has stored via `hostinfo.GetRemote()`), and craft a `header.RecvError` packet with `RemoteIndex` set to B's index for A's tunnel.
3. Send it to B. `handleRecvError` finds the matching `HostInfo` via `QueryReverseIndex`, the address check passes because the source address matches what B has cached, and B calls `closeTunnel`, destroying the tunnel state without any cryptographic proof of identity from the sender [7](#0-6) .

	if final {

func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
