Based on my analysis, this scenario is not exploitable due to NEAR's execution model.

### Analysis

`ImtMint::execute_intent` (`contracts/defuse/core/src/intents/imt.rs:42-72`) calls `engine.state.imt_mint(...)`, which synchronously calls `self.mint(receiver_id, tokens, memo)` (the balance credit) and *then*, only if a `notification` is present, calls `self.notify_on_transfer(...)` [1](#0-0) . All of `Engine::execute_signed_intents` — every intent in the batch, plus `Deltas::finalize()` / `TransferMatcher::finalize()` which computes and validates net transfers — runs entirely in-memory, synchronously, within a single function call before `execute_intents` (the contract entrypoint) ever returns [2](#0-1) [3](#0-2) .

The `notify_on_transfer` implementation does not await the promise; it `.detach()`es it [4](#0-3) . On NEAR, a detached/scheduled `Promise` (the `mt_on_transfer` call to the attacker's receiver contract) does not execute during the current receipt/call. It is scheduled as a *separate, later receipt* that only runs after the current receipt — including all of `execute_intents`'s balance mutations and `finalize()` invariant checks — has fully completed and its state changes have been committed to the contract's persistent storage. There is no cooperative/synchronous call-stack reentrancy possible in the NEAR runtime the way there is on EVM; the callee cannot "pause" the in-flight `ImtMint` settlement mid-way and reenter `execute_intents`/`ft_withdraw`/`*_resolve_*` while the debit/credit is uncommitted, because no such uncommitted window is externally observable — it's confined to synchronous in-process execution.

Any callback the attacker's contract makes from `mt_on_transfer` back into `execute_intents` therefore executes strictly *after* the original `ImtMint`'s mint has already been fully applied and committed on-chain, as a wholly separate, independently-authorized call (requiring its own valid signed `MultiPayload` to move any further funds). This is also demonstrated by the existing test `imt_mint_intent_with_msg_to_receiver_smc` in `tests/src/tests/defuse/intents/imt_mint.rs`, where the receiver stub's return value only affects a *refund* mechanism for `Transfer` (via `mt_resolve_transfer`, which is `#[private]` and thus not directly callable by the attacker) [5](#0-4)  — `ImtMint` itself has no resolve/refund callback at all, so there's no additional credit path to double up against.

Since the mint's balance change is committed before any promise carrying attacker-controlled logic fires, the binding "balance changes committed by the receipt == balance changes the signed intents authorize" cannot be violated by a re-entrant callee call, regardless of what JSON the attacker's contract returns.

    fn execute_signed_intent(&mut self, signed: MultiPayload) -> Result<()> {
        // verify signed payload and get public key
        let public_key = signed.verify().ok_or(DefuseError::InvalidSignature)?;

        // calculate intent hash
        let hash = signed.hash();

        // extract NEP-413 payload
        let DefusePayload::<DefuseIntents> {
            signer_id,
            verifying_contract,
            deadline,
            nonce,
            message: intents,
        } = signed.extract_defuse_payload()?;

        // check recipient
        if verifying_contract != *self.state.verifying_contract() {
            return Err(DefuseError::WrongVerifyingContract);
        }

        self.inspector.on_deadline(deadline);

        // make sure message is still valid
        if deadline < Timestamp::now() {
            return Err(DefuseError::DeadlineExpired);
        }

        // make sure the account has this public key
        if !self.state.has_public_key(&signer_id, &public_key) {
            return Err(DefuseError::PublicKeyNotExist(signer_id, public_key));
        }

        // commit nonce
        self.verify_intent_nonce(nonce, deadline)?;
        self.state.commit_nonce(signer_id.clone(), nonce)?;

        intents.execute_intent(&signer_id, self, hash)?;
        self.inspector.on_intent_executed(&signer_id, hash, nonce);

        Ok(())
    }

    #[inline]
    fn verify_intent_nonce(&self, nonce: Nonce, intent_deadline: Timestamp) -> Result<()> {
        let Some(nonce) = VersionedNonce::maybe_from(nonce) else {
            return Ok(());
        };

        match nonce {
            VersionedNonce::V1(SaltedNonce {
                salt,
                nonce: ExpirableNonce { deadline, .. },
            }) => {
                if !self.state.is_valid_salt(salt) {
                    return Err(DefuseError::InvalidSalt);
                }

                if intent_deadline > deadline {
                    return Err(DefuseError::DeadlineGreaterThanNonce);
                }

                if deadline < Timestamp::now() {
                    return Err(DefuseError::NonceExpired);
                }
            }
        }

        Ok(())
    }
