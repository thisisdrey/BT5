### Title
StackerDB chunk signatures omit the target contract/message-type, enabling cross-contract replay writes - (File: `libstackerdb/src/libstackerdb.rs`)

### Summary
`SlotMetadata::auth_digest()` computes the digest a signer's ECDSA signature is verified against using only `slot_id`, `slot_version`, and `data_hash` — it never includes the StackerDB contract (message type) the chunk is destined for. Because the Nakamoto signer set assigns the *same* `slot_id` to the *same* signer address across every sibling `signers-<N>-<M>` StackerDB contract in a reward cycle, a signature that is valid for one message-type contract is also valid for a completely different message-type contract owned by the same signer. This is the same root cause as the Meson report: an ECDSA digest that fails to unambiguously bind the message's context/type, allowing a signature captured in one context to be replayed in another.

### Finding Description
The signing/verification digest is:
```rust
fn auth_digest(&self) -> Sha512Trunc256Sum {
    let mut hasher = Sha512_256::new();
    hasher.update(self.slot_id.to_be_bytes());
    hasher.update(self.slot_version.to_be_bytes());
    hasher.update(self.data_hash.0);
    Sha512Trunc256Sum::from_hasher(hasher)
}
``` [1](#0-0) 

Signing and verification both operate solely on this digest: [2](#0-1) 

`PeerNetwork::validate_received_chunk` looks up the slot's authorized signer *for the contract named in the incoming message* and then calls `slot_metadata.verify(&addr)`, which only recomputes the context-free digest above — the contract/StackerDB identity is never mixed into what is actually signed: [3](#0-2) 

Crucially, every message-type-specific contract for a given signer set (`signers-<cycle_mod>-<message_id>`) draws its slot list from the *same shared* `stackerdb-signer-slots-0`/`stackerdb-signer-slots-1` variable in the `.signers` boot contract, so a signer occupies the identical `slot_id` in all of them: [4](#0-3) 

This is confirmed by the test that checks all `signers-<set>-<message_id>` contracts return the identical, position-sorted slot list for every message type: [5](#0-4) 

The write path that an attacker (any relaying peer or unsolicited-push sender) can drive is `handle_unsolicited_StackerDBPushChunk`, which takes `chunk_data.contract_id` straight from the attacker-supplied message and dispatches to `validate_received_chunk`/`try_replace_chunk` for that contract, with no binding between the contract named in the envelope and what was actually signed: [6](#0-5) 

Because `(slot_id, slot_version, data_hash)` is contract-agnostic, an attacker who observes any legitimately signed `StackerDBChunkData` broadcast for signer `S` in contract `A` (e.g. `signers-0-1`, a `BlockResponse` contract) can repackage the exact same `slot_id`/`slot_version`/`sig`/`data` inside a `StackerDBPushChunkData` whose `contract_id` is a *different* sibling contract `B` (e.g. `signers-0-2`, a `BlockProposal` contract) for the same signer set. Since `S` occupies the same `slot_id` in `B`, `get_slot_signer(B, slot_id)` returns the same address, and `slot_metadata.verify()` recomputes the identical digest and validates against the replayed signature — without the attacker ever holding `S`'s private key.

### Impact Explanation
This is an unauthenticated/unauthorized write to StackerDB state: an attacker with no privileged key can force arbitrary (previously-observed) signer-authored bytes into the wrong message-type slot of a sibling StackerDB contract, overwriting or corrupting that signer's legitimate data there and/or advancing that slot's Lamport clock (`slot_version`) toward `max_writes`, degrading or denying that signer's ability to publish to the targeted contract until the reward cycle rotates. This matches the "Critical: unauthenticated/unauthorized write to state or StackerDB" category, since correctness of StackerDB writes (an equality between the identity a signature authenticates and the state it is permitted to modify) is broken.

### Likelihood Explanation
Exploitation requires only passively observing one legitimately signed/broadcast `StackerDBChunkData` for the target signer (chunks are gossiped in plaintext over the p2p network and served in inventories) and re-sending it wrapped in a `StackerDBPushChunkData` naming a sibling contract. No cryptographic material, admin role, or the signer's key is needed — only network connectivity to a node, which is the required threat model for this exercise.

### Recommendation
Bind the StackerDB contract identifier (and ideally an explicit message-type tag) into the signed digest, e.g.:
```rust
hasher.update(smart_contract_id.serialize_to_vec());
hasher.update(self.slot_id.to_be_bytes());
hasher.update(self.slot_version.to_be_bytes());
hasher.update(self.data_hash.0);
```
and thread the target contract into `SlotMetadata::sign`/`verify`/`auth_digest` so a signature over one StackerDB contract's slot cannot be replayed against any other contract, even when the same signer owns the same numeric `slot_id` in both.

### Proof of Concept
1. Observe (via normal p2p gossip) a valid `StackerDBPushChunkData` for signer `S`, contract `A = signers-0-1`, containing `chunk_data = {slot_id: k, slot_version: v, sig, data}`.
2. Confirm from the `.signers` boot contract that `S` also owns `slot_id = k` in sibling contract `B = signers-0-2` (guaranteed, since both contracts share `stackerdb-signer-slots-0`, see `stackslib/src/chainstate/stacks/boot/signers.clar` lines 1-43).
3. Craft `StackerDBPushChunkData { contract_id: B, rc_consensus_hash: <current>, chunk_data }` reusing the *same* `slot_id`, `slot_version`, `sig`, and `data` from step 1 unmodified.
4. Send it to any node as an unsolicited `StackerDBPushChunk`. `handle_unsolicited_StackerDBPushChunk` → `validate_received_chunk` resolves `get_slot_signer(B, k) == S`, then `slot_metadata.verify(&S)` recomputes the same context-free digest as in `A` and succeeds, so the node accepts and stores/relays the chunk into `B`'s slot `k` — a write the attacker was never authorized to make into contract `B`.

    /// Sign this slot metadata, committing to slot_id, slot_version, and
    /// data_hash.  Sets self.signature to the signature.
    /// Fails if the underlying crypto library fails
    pub fn sign(&mut self, privkey: &StacksPrivateKey) -> Result<(), Error> {
        let auth_digest = self.auth_digest();
        let sig = privkey
            .sign(&auth_digest.0)
            .map_err(|se| Error::SigningError(se.to_string()))?;

        self.signature = sig;
        Ok(())
    }

    /// Verify that a given principal signed this chunk metadata.
    /// Note that the address version is ignored.
    pub fn verify(&self, principal: &StacksAddress) -> Result<bool, Error> {
        let sigh = self.auth_digest();
        let pubk = StacksPublicKey::recover_to_pubkey_without_validating_low_s(
            sigh.as_bytes(),
            &self.signature,
        )
        .map_err(|ve| Error::VerifyingError(ve.to_string()))?;

        let pubkh = Hash160::from_node_public_key(&pubk);
        Ok(pubkh == *principal.bytes())
    }

                    stackerdb_config,
                    &chunk_data.chunk_data,
                    &data.slot_versions,

fn signers_db_get_slots() {
    let stacker_1 = TestStacker::from_seed(&[3, 4]);
    let stacker_2 = TestStacker::from_seed(&[5, 6]);

    let (mut peer, test_signers, latest_block_id, _) = prepare_signers_test(
        function_name!(),
        vec![],

        None,

    let private_key = peer.config.private_key.clone();

    let mut expected_signers: Vec<_> =
        [&stacker_1.signer_private_key, &stacker_2.signer_private_key]
            .iter()
            .map(|sk| {
                let pk = Secp256k1PublicKey::from_private(sk);
                let pk_bytes = pk.to_bytes_compressed();
                let signer_addr = StacksAddress::p2pkh(false, &pk);
                let stackerdb_entry = TupleData::from_data(vec![
                    (
                        ClarityName::from_literal("signer"),
                        PrincipalData::from(signer_addr).into(),
                    ),
                    (ClarityName::from_literal("num-slots"), Value::UInt(1)),
                ])
                .unwrap();
                (pk_bytes, stackerdb_entry)
            })
            .collect();

    // should be sorted by the pk bytes
    expected_signers.sort_by_key(|x| x.0.clone());
    let expected_stackerdb_slots = Value::cons_list_unsanitized(
        expected_signers
            .into_iter()
            .map(|(_pk, entry)| Value::from(entry))
            .collect(),
    )
    .unwrap();

    for signer_set in 0..2 {
        for message_id in 0..SIGNER_SLOTS_PER_USER {
            let contract_name =
                ContractName::try_from(format!("signers-{}-{}", &signer_set, &message_id)).unwrap();
            let signers = readonly_call(
                &mut peer,
                &latest_block_id,
                contract_name.clone(),
                ClarityName::from_literal("stackerdb-get-signer-slots"),
                vec![],
            )
            .expect_result_ok()
            .unwrap();

            debug!("Check .{}", contract_name);
            if signer_set == 0 {
                assert_eq!(signers.expect_list().unwrap(), vec![]);
            } else {
                assert_eq!(signers, expected_stackerdb_slots);
            }
