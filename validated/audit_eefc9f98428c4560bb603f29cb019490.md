### Title
Unauthenticated `RecvError` packet allows a remote-address spoofer to unilaterally destroy another party's established tunnel state - ([File: outside.go])

### Summary
Nebula processes `header.RecvError` packets before any decryption, certificate check, or possession-of-key proof [1](#0-0) . `handleRecvError` looks up the hostinfo purely by the numeric `RemoteIndex` field taken from the plaintext header, compares the packet's source `netip.AddrPort` against the hostinfo's currently cached remote address, and if they match (or if no remote is yet cached) it immediately tears down the tunnel via `f.closeTunnel(hostinfo)` and `f.handshakeManager.DeleteHostInfo(hostinfo)` [2](#0-1) . This mirrors the reported bug class: a party with no legitimate claim on the victim's identity/session (no CA-signed certificate, no possession of the tunnel's symmetric keys) can force destruction of state belonging to a legitimate, unrelated peer, exactly as the `DegenERC20.burn()` owner could destroy Bob's tokens without Bob's consent or any cryptographic proof of authorization.

### Finding Description
`RecvError` is dispatched in `readOutsidePackets` at the very top of the switch on `h.Type`, alongside `Handshake`, i.e. before the packet passes through `hostinfo.ConnectionState.Decrypt` or any AEAD/authentication check [1](#0-0) . The only "authentication" performed is a source-IP/port equality check against `hostinfo.GetRemote()` [3](#0-2) . Because Nebula runs over UDP, `via.UdpAddr` is fully attacker-controlled (there is no return-routability/handshake proof tied to this code path), so an attacker capable of spoofing the victim's currently-known remote UDP source address — or attacking before a remote has been learned (`hr` invalid) — can trigger `closeTunnel` + `DeleteHostInfo` on a hostinfo that belongs to two entirely different, legitimate certificate holders, without holding any certificate signed by the network's CA at all.

This is analogous to the reported `burn()` issue: a "privileged" code path (here, "someone who claims to be the previously-seen remote address") can unilaterally destroy state (a live, authenticated tunnel) belonging to other users, with no requirement that the destroying party ever proved possession of a matching certificate or private key.

### Impact Explanation
Successful exploitation forces termination of an established, authenticated Nebula tunnel between two legitimate nodes. This is a remote state-poisoning/denial-of-service primitive: it can be used to repeatedly disrupt tunnels network-wide, disable inter-node connectivity, or push tunnels into constant rehandshake loops, degrading availability for hosts that never violated protocol trust rules. Unlike the CA blocklist mechanism (an intended, trusted administrative action), this teardown is triggered by an entity that need not present or control a valid Nebula certificate at all.

### Likelihood Explanation
Exploitation requires the ability to spoof (or guess) the exact source `netip.AddrPort` that a target hostinfo currently believes is its peer's remote address — a classic UDP source-address spoofing requirement. This is nontrivial on networks with anti-spoofing (BCP38) egress filtering, but readily achievable on many networks, from compromised routers, or in scenarios where the real remote endpoint has not yet been learned (`hr.IsValid() == false`), in which case the check is skipped entirely and any spoofed packet succeeds. The codebase already treats this as a known risk area — it exposes `listen.accept_recv_error` / `send_recv_error` config knobs (`recvErrorAlways`, `recvErrorNever`, `recvErrorPrivate`) precisely because of this trust concern [4](#0-3)  — but the default/"always" mode still permits the described bypass.

### Recommendation
Require cryptographic binding for `RecvError` handling instead of relying solely on the plaintext source address comparison: e.g., require the `RemoteIndex` to also match a recently transmitted local packet's index/counter that was authenticated, or require `RecvError` acceptance only from remotes for which a valid nonce/challenge-response has been completed, similar to how `CloseTunnel` messages are authenticated as encrypted `Message`-type packets rather than a bare unauthenticated header. At minimum, default `listen.accept_recv_error` to the most restrictive setting (`never` or `private`) and document that `always` accepts unauthenticated remote-triggered teardown.

### Proof of Concept
1. Establish a legitimate tunnel between `A` and `B`; `A`'s hostmap now has a hostinfo for `B` with `RemoteIndex = X` and cached remote `B_addr`.
2. Attacker `E` (holding no CA-signed certificate, or none at all) crafts a plaintext `header.H` packet with `Type = header.RecvError`, `RemoteIndex = X`, sourced from a spoofed UDP address equal to `B_addr` (or sent before `A` has learned `B`'s remote, in the pending-handshake window).
3. `E` sends this packet to `A`.
4. `readOutsidePackets` routes it directly to `f.handleRecvError` without decryption [5](#0-4) ; the address check passes (spoofed match, or `hr` not yet valid) [3](#0-2) ; `A` calls `closeTunnel(hostinfo)` and `handshakeManager.DeleteHostInfo(hostinfo)`, destroying `A`'s tunnel state for `B` [6](#0-5)  — with no cryptographic proof `E` is `B` or any authorized party.

Note: I could not fully verify the exact semantics/default state of `hostinfo.GetRemote()` (i.e., precisely when `hr.IsValid()` is false in practice) within the available indexed context, so the "no remote learned yet" sub-case above should be validated directly against `hostmap.go`'s `HostInfo.remote` handling in a full checkout before treating it as a guaranteed unconditional bypass.

```go
func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
```

```go
type recvErrorConfig uint8

const (
	recvErrorAlways recvErrorConfig = iota
	recvErrorNever
	recvErrorPrivate
)

func (s recvErrorConfig) ShouldRecvError(endpoint netip.AddrPort) bool {
	switch s {
	case recvErrorPrivate:
		return endpoint.Addr().IsPrivate()
	case recvErrorAlways:
		return true
	case recvErrorNever:
		return false
	default:
		panic(fmt.Errorf("invalid recvErrorConfig value: %d", s))
	}
}
```
