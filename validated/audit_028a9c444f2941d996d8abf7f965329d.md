### Title
Per-connection QUIC stream-rate throttle state resets on reconnect, allowing unstaked/staked clients to evade `SwQos`/`SimpleQos` stream throttling - ([File: streamer/src/nonblocking/quic.rs])

### Summary
The GoGoPool `RewardsStartTime` bug is a case where per-actor time-window state is not preserved across a "close/reopen" cycle, letting the actor reset the state that gates a rate/eligibility window and thereby escape a control meant to persist across their lifecycle. The analogous pattern in agave exists in the QUIC streamer's per-peer stream throttling: the `ConnectionStreamCounter` (which enforces the intra-connection stream-rate limit) is stored on the `ConnectionTable` keyed by peer (IP or pubkey) and is destroyed whenever the last live connection entry for that key is removed. Any unprivileged client (staked or unstaked) that closes its connection and reopens a new one gets a **fresh** throttle counter with `stream_count = 0` and a freshly-started throttling interval, instead of inheriting the accumulated/rate-limited state, letting them exceed the intended per-peer stream cap by cycling connections.

### Finding Description
The QUIC stream throttle is implemented by `ConnectionStreamCounter`, which tracks `stream_count` and `last_throttling_instant`: [1](#0-0) 

This counter is shared across all currently-open connection entries for a given key (IP or pubkey) and is only created when the `ConnectionTable` has *no* existing entries for that key — `try_add_connection` calls `connection_entry.first()` to reuse the counter, falling back to a fresh one via `stream_counter_factory` if the entry list is empty: [2](#0-1) 

When a connection is closed, `remove_connection` deletes that specific entry, and once the last entry for a key is gone, the whole `IndexMap` row (and with it, the shared `ConnectionStreamCounter`, since it was only referenced by those entries) is dropped: [3](#0-2) 

Both `SwQos::remove_connection` and `SimpleQos::remove_connection` invoke this same table-level removal after a connection finishes: [4](#0-3) [5](#0-4) 

The throttling itself is enforced in `throttle_stream`, which resets `stream_count` to 0 only after `STREAM_THROTTLING_INTERVAL` (100ms) has elapsed since `last_throttling_instant`: [6](#0-5) 

Because a brand-new `ConnectionStreamCounter` is created (with `stream_count = 0` and `last_throttling_instant = now`) any time a peer's connection table row is fully emptied — whether by graceful close, error, idle timeout, or intentional client-side disconnect/reconnect — a client can restart its throttling window on demand simply by tearing down and re-establishing its QUIC connection, rather than being bound by the persistent per-peer throttle the mechanism is designed to enforce.

### Impact Explanation
This is a QoS-evasion vulnerability: the stream-rate throttle (`max_streams_per_throttling_interval`, computed from stake ratio and RTT in `SwQos`, or from `max_streams_per_second` in `SimpleQos`) is meant to bound how fast any single peer can push streams/transactions into the TPU pipeline. By deliberately cycling connections, a client can repeatedly reset its throttle state, sending bursts up to the throttle cap once per reconnect instead of once per persistent-connection lifetime — effectively getting a higher steady-state throughput than the configured per-peer limit intends, at the node's expense (extra QUIC handshakes/CPU, and disproportionate TPU stream admission versus honest peers who keep one connection open). This falls under "QoS evasion," one of the explicitly acceptable impact categories.

### Likelihood Explanation
Reachability requires no privilege: this streamer path processes ordinary QUIC/TPU connections from any client (staked or unstaked), matching the "unprivileged-user analog" scope. However, the practical severity is bounded by two independent, correctly-implemented outer controls that are keyed strictly by source IP and apply before a connection is even accepted:
- The per-IP `ConnectionRateLimiter` (`DEFAULT_MAX_CONNECTIONS_PER_IPADDR_PER_MINUTE = 8`, with a 10x burst allowance) [7](#0-6) 
- The global `overall_connection_rate_limiter` (2500 connections/sec) [8](#0-7) 

Since new connections are capped at ~8/min per IP (bursts aside), an attacker cannot reconnect fast enough (sub-100ms) to continuously bypass the 100ms throttling window at scale; the achievable throughput gain from this technique alone is limited under default configuration, though it still represents a real deviation from intended QoS semantics and could matter more under configurations with higher `max_connections_per_ipaddr_per_min` or if combined with the burst allowance and multiple distinct client identities/pubkeys.

### Recommendation
Persist per-peer throttle state independent of individual connection-entry lifetime — e.g., key `ConnectionStreamCounter` (and its `last_throttling_instant`) in a separate map from the `ConnectionTable`'s live-connection entries, with its own TTL/reset policy decoupled from connection close/reopen events, so that closing and reopening a QUIC connection cannot reset the stream-rate throttling window for that IP/pubkey.

### Proof of Concept
1. Configure/observe defaults: `max_connections_per_unstaked_peer` allows at least 1 connection at a time for a peer key.
2. Client opens a QUIC connection to the TPU port and sends streams until it hits `max_streams_per_throttling_interval` and gets throttled by `throttle_stream` (streams start sleeping).
3. Instead of waiting out the 100ms `STREAM_THROTTLING_INTERVAL`, the client closes the connection (triggers `remove_connection` → `ConnectionTable::remove_connection`, which empties the table row for that key and drops the shared `ConnectionStreamCounter`).
4. Client immediately reconnects (within the per-IP rate-limiter's allowance). `try_add_connection` finds no existing entry for the key, so `stream_counter_factory` creates a fresh `ConnectionStreamCounter` with `stream_count = 0`.
5. Client can immediately send another full burst of streams up to `max_streams_per_throttling_interval` without waiting for the original throttle window to expire, repeating this cycle up to the per-IP connection-rate-limiter's burst allowance. [9](#0-8) [3](#0-2)

#[derive(Debug)]
pub struct ConnectionStreamCounter {
    pub(crate) stream_count: AtomicU64,
    last_throttling_instant: RwLock<tokio::time::Instant>,
}

impl OpaqueStreamerCounter for ConnectionStreamCounter {}

impl ConnectionStreamCounter {
    pub fn new() -> Self {
        Self {
            stream_count: AtomicU64::default(),
            last_throttling_instant: RwLock::new(tokio::time::Instant::now()),
        }
    }

    /// Reset the counter and last throttling instant and
    /// return last_throttling_instant regardless it is reset or not.
    pub(crate) fn reset_throttling_params_if_needed(&self) -> tokio::time::Instant {
        let last_throttling_instant = *self.last_throttling_instant.read().unwrap();
        if tokio::time::Instant::now().duration_since(last_throttling_instant)
            > STREAM_THROTTLING_INTERVAL
        {
            let mut last_throttling_instant = self.last_throttling_instant.write().unwrap();
            // Recheck as some other thread might have done throttling since this thread tried to acquire the write lock.
            if tokio::time::Instant::now().duration_since(*last_throttling_instant)
                > STREAM_THROTTLING_INTERVAL
            {
                *last_throttling_instant = tokio::time::Instant::now();
                self.stream_count.store(0, Ordering::Relaxed);
            }
            *last_throttling_instant
        } else {
            last_throttling_instant
        }
    }

pub(crate) async fn throttle_stream(
    stats: &StreamerStats,
    peer_type: ConnectionPeerType,
    remote_addr: std::net::SocketAddr,
    stream_counter: &Arc<ConnectionStreamCounter>,
    max_streams_per_throttling_interval: u64,
) {
    let throttle_interval_start = stream_counter.reset_throttling_params_if_needed();
    let streams_read_in_throttle_interval = stream_counter.stream_count.load(Ordering::Relaxed);
    if streams_read_in_throttle_interval >= max_streams_per_throttling_interval {
        // The peer is sending faster than we're willing to read. Sleep for what's
        // left of this read interval so the peer backs off.
        let throttle_duration =
            STREAM_THROTTLING_INTERVAL.saturating_sub(throttle_interval_start.elapsed());

        if !throttle_duration.is_zero() {
            debug!(
                "Throttling stream from {remote_addr:?}, peer type: {peer_type:?}, \
                 max_streams_per_interval: {max_streams_per_throttling_interval}, \
                 read_interval_streams: {streams_read_in_throttle_interval} throttle_duration: \
                 {throttle_duration:?}"
            );
            stats.throttled_streams.fetch_add(1, Ordering::Relaxed);
            match peer_type {
                ConnectionPeerType::Unstaked => {
                    stats
                        .throttled_unstaked_streams
                        .fetch_add(1, Ordering::Relaxed);
                }
                ConnectionPeerType::Staked(_) => {
                    stats
                        .throttled_staked_streams
                        .fetch_add(1, Ordering::Relaxed);
                }
            }
            sleep(throttle_duration).await;
        }
    }
}

    pub(crate) fn try_add_connection<F: FnOnce() -> Arc<S>>(
        &mut self,
        key: ConnectionTableKey,
        port: u16,
        client_connection_tracker: ClientConnectionTracker,
        connection: Option<Connection>,
        peer_type: ConnectionPeerType,
        last_update: Arc<AtomicU64>,
        max_connections_per_peer: usize,
        stream_counter_factory: F,
    ) -> Option<(Arc<AtomicU64>, CancellationToken, Arc<S>)> {
        let connection_entry = self.table.entry(key).or_default();
        let has_connection_capacity = connection_entry
            .len()
            .checked_add(1)
            .map(|c| c <= max_connections_per_peer)
            .unwrap_or(false);
        if has_connection_capacity {
            let cancel = self.cancel.child_token();
            let stream_counter = connection_entry
                .first()
                .map(|entry| entry.stream_counter.clone())
                .unwrap_or_else(stream_counter_factory);
            connection_entry.push(ConnectionEntry::new(
                cancel.clone(),
                peer_type,
                last_update.clone(),
                port,
                client_connection_tracker,
                connection,
                stream_counter.clone(),
            ));
            self.total_size += 1;
            Some((last_update, cancel, stream_counter))
        } else {
            if let Some(connection) = connection {
                connection.close(
                    CONNECTION_CLOSE_CODE_TOO_MANY.into(),
                    CONNECTION_CLOSE_REASON_TOO_MANY,
                );
            }
            None
        }
    }

    // Returns number of connections that were removed
    pub(crate) fn remove_connection(
        &mut self,
        key: ConnectionTableKey,
        port: u16,
        stable_id: usize,
    ) -> usize {
        if let Entry::Occupied(mut e) = self.table.entry(key) {
            let e_ref = e.get_mut();
            let old_size = e_ref.len();

            e_ref.retain(|connection_entry| {
                // Retain the connection entry if the port is different, or if the connection's
                // stable_id doesn't match the provided stable_id.
                // (Some unit tests do not fill in a valid connection in the table. To support that,
                // if the connection is none, the stable_id check is ignored. i.e. if the port matches,
                // the connection gets removed)
                connection_entry.port != port
                    || connection_entry
                        .connection
                        .as_ref()
                        .and_then(|connection| (connection.stable_id() != stable_id).then_some(0))
                        .is_some()
            });
            let new_size = e_ref.len();
            if e_ref.is_empty() {
                e.swap_remove_entry();
            }
            let connections_removed = old_size.saturating_sub(new_size);
            self.total_size = self.total_size.saturating_sub(connections_removed);
            connections_removed
        } else {
            0
        }
    }
