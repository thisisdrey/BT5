### Title
Unsanitized shell `tar` extraction of an attacker/URL-controlled archive in `CreateRepositoryFromSnapshot` allows path traversal on the Gitaly server - (File: `internal/gitaly/service/repository/create_repository_from_snapshot.go`)

### Summary
`CreateRepositoryFromSnapshot` fetches an archive from an arbitrary, caller-supplied URL and extracts it with the system `tar` binary directly into the destination repository directory, without any validation of the entries contained in the archive (path traversal, symlinks, hard links). This mirrors the report's root-cause pattern of a shared/critical operation ("extract snapshot into repo") being implemented through two divergent code paths where one path enforces the necessary safety checks and the other does not — exactly like `repayBorrowInternal()` silently applying same-chain accounting logic to a cross-chain caller without validating context.

### Finding Description
`untar()` builds an HTTP request from `in.GetHttpUrl()` (an RPC field taken from `CreateRepositoryFromSnapshotRequest`), optionally pins the destination to `in.GetResolvedAddress()` to mitigate DNS-rebinding, and then pipes the raw HTTP response body straight into the external `tar` command: [1](#0-0) 

```go
cmd, err := command.New(ctx, s.logger, []string{"tar", "-C", path, "-xvf", "-"}, command.WithStdin(rsp.Body))
```

No inspection is performed on the tar entries before extraction: no rejection of `../` sequences in member names, no rejection of absolute/`..`-escaping symlink or hard-link targets, and no `--no-same-owner`/path-confinement flags are passed to `tar`. `path` is a validated internal repository directory [2](#0-1) , but the *contents* of the archive being extracted into it are fully attacker-controlled by whoever supplies `HttpUrl`/`HttpAuth` in the RPC request.

The code even self-documents that this path is unhardened: [3](#0-2) 
```go
// The archive contains a partial git repository, missing a config file and
// other important items. ...
// NOTE: The received archive is trusted *a lot*. Before pointing this RPC
// at endpoints not under our control, it should undergo a lot of hardening.
```

This is in stark contrast to Gitaly's own hardened snapshot-extraction implementation used for internal node-to-node replication (`extractSnapshot`/`extractTarToDirectory` in `internal/gitaly/service/repository/replicate.go`), which explicitly validates every extracted path and every symlink/hard-link target against the destination directory boundary before writing: [4](#0-3) [5](#0-4) 

Because `CreateRepositoryFromSnapshot` delegates instead to the raw system `tar -xvf -`, none of these protections apply: a crafted archive with a member name such as `../../../../home/git/.ssh/authorized_keys` or a symlink member pointing outside `path` followed by a regular-file member written "through" that symlink can write or overwrite files outside the intended repository directory on the Gitaly host.

### Impact Explanation
An attacker who can influence the `HttpUrl` (and control the server that services it, or perform a MITM against an already-untrusted-by-design fetch) supplied to `CreateRepositoryFromSnapshot` can achieve arbitrary file write on the Gitaly node's filesystem, outside of the target repository directory (classic "Tarslip"/zip-slip via tar). This can lead to remote code execution (e.g., overwriting hook scripts, cron files, or SSH authorized_keys) or corruption of unrelated repositories/storage state on the node, i.e., storage escape and potential further compromise.

### Likelihood Explanation
The RPC field `HttpUrl` (and `HttpAuth`) is fully attacker-influenceable input to the handler; the code comment explicitly acknowledges the archive is "trusted a lot" and warns that this RPC must not be pointed at endpoints "not under our control," which flags this as an existing risk given any downstream caller (e.g., import/snapshot-restore tooling) that lets an end user or external system influence the source URL. The lack of parity with the hardened `extractTarToDirectory` implementation elsewhere in the same codebase confirms this is a genuine gap rather than an intentionally accepted trust boundary specific to a fully-trusted internal-only caller.

### Recommendation
Replace the shell-out to system `tar` in `untar()` with the same hardened, Go-native extraction logic already used in `extractTarToDirectory` (path confinement checks for regular files/directories, symlink target resolution/boundary checks, hard-link target boundary checks, rejection of absolute symlinks) so both snapshot-extraction code paths enforce identical containment guarantees. At minimum, validate every tar header name and link target against the destination directory boundary before invoking `tar`, or pipe the archive through the existing safe extractor instead of the external binary.

### Proof of Concept
1. Host an HTTP server returning a tar stream containing a directory traversal entry, e.g. a member named `../../../../tmp/pwned` (or a symlink member `link -> ../../../tmp` followed by a regular file `link/pwned`).
2. Call `CreateRepositoryFromSnapshot` with `HttpUrl` pointing at that server (optionally `ResolvedAddress` set to the server's IP to pass DNS-rebinding checks).
3. Observe that `tar -C <repoPath> -xvf -` extracts the malicious entry outside `<repoPath>`, e.g. creating/overwriting `/tmp/pwned` on the Gitaly host, confirming the path-traversal/file-write escape (compare with `TestExtractTarToDirectory_SymlinkValidation` in `replicate_test.go`, which shows the equivalent attack is explicitly blocked in the parallel, hardened code path).

func (s *server) untar(ctx context.Context, path string, in *gitalypb.CreateRepositoryFromSnapshotRequest) error {
	req, err := http.NewRequestWithContext(ctx, "GET", in.GetHttpUrl(), nil)
	if err != nil {
		return structerr.NewInvalidArgument("Bad HTTP URL: %w", err)
	}

	client := httpClient
	if resolvedAddress := in.GetResolvedAddress(); resolvedAddress != "" {
		client, err = newResolvedHTTPClient(in.GetHttpUrl(), resolvedAddress)
		if err != nil {
			return structerr.NewInvalidArgument("creating resolved HTTP client: %w", err)
		}
	}

	if in.GetHttpAuth() != "" {
		req.Header.Set("Authorization", in.GetHttpAuth())
	}

	rsp, err := client.Do(req)
	if err != nil {
		return structerr.NewInternal("HTTP request failed: %w", err)
	}
	defer rsp.Body.Close()

	if rsp.StatusCode < http.StatusOK || rsp.StatusCode >= http.StatusMultipleChoices {
		return structerr.NewInternal("HTTP server: %s", rsp.Status)
	}

	cmd, err := command.New(ctx, s.logger, []string{"tar", "-C", path, "-xvf", "-"}, command.WithStdin(rsp.Body))
	if err != nil {
		return err
	}

	return cmd.Wait()

// extractTarToDirectory extracts a tar archive to the specified directory using Go's tar package
func (s *server) extractTarToDirectory(ctx context.Context, reader io.Reader, targetDir string) error {
	targetDir = filepath.Clean(targetDir)
	tarReader := tar.NewReader(reader)

	for {
		select {
		case <-ctx.Done():
			return ctx.Err()
		default:
		}

		header, err := tarReader.Next()
		if err == io.EOF {
			break // End of archive
		}
		if err != nil {
			return fmt.Errorf("reading tar header: %w", err)
		}

		targetPath := filepath.Join(targetDir, header.Name)

		if !strings.HasPrefix(targetPath, targetDir+string(os.PathSeparator)) &&
			targetPath != targetDir {
			return fmt.Errorf("invalid file path in tar: %s", header.Name)
		}
