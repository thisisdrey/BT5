### Title
`FindLicense` response cache keyed only by repository path and commit OID, ignoring quarantine/object-directory context - ([File: internal/gitaly/service/repository/license.go])

### Summary
This is a valid analog. `AutoRange.execute()` trusted a per-key cached value (`positionConfigs[tokenId]`) without revalidating that the security context that produced it (the current token owner) still matches the context of use. In Gitaly, `internal/unarycache.Cache.GetOrCompute()` similarly caches a computed RPC response keyed only by `(repoPath, key)` and serves it to any later caller with a matching key, without accounting for the additional security-relevant context (`GitObjectDirectory` / `GitAlternateObjectDirectories`, i.e. object quarantine) present on the `*gitalypb.Repository` used to compute the cached value.

### Finding Description
`unarycache.Cache.GetOrCompute` derives its cache key purely from `repo.Path(ctx)` (storage name + relative path) and the caller-supplied `Key`: ` [1](#0-0) `. `repo.Path(ctx)` in turn resolves only storage name and relative path via the locator, and does not include the repository's `GitObjectDirectory`/`GitAlternateObjectDirectories` fields, which is exactly the mechanism used for Git's object quarantine: ` [2](#0-1) `.

`FindLicense` uses this cache, keyed by `(repoPath, headOID)`, to store and serve a `*gitalypb.FindLicenseResponse` computed by walking tree/blob objects of the resolved `HEAD` commit through the given `*localrepo.Repo`: ` [3](#0-2) `. The generator function (`findLicense`) reads files via `repo.ReadObjectWithLimit` and lists tree entries via `git ls-tree`, both of which are executed against whatever object directory/alternates are configured on the `*gitalypb.Repository` passed in — including a quarantine directory if one is set: ` [4](#0-3) [5](#0-4) `.

Because the cache key omits quarantine/alternate-object-directory information, a response computed while objects were only visible through a quarantine directory (e.g. during a `pre-receive` check on an in-flight push, where Rails forwards the quarantined `*gitalypb.Repository` to Gitaly RPCs, as documented in `doc/object_quarantine.md`: ` [6](#0-5) `) is indistinguishable, from the cache's point of view, from a response computed against the merged main object directory. This mirrors the `AutoRange` bug class: a value cached under a coarse key is reused across a change in the actual security/data context (quarantine vs. non-quarantine, or "old owner" vs. "new owner"), without any check that the context is still the same.

The Gitaly `catfile.ProcessCache` (`internal/git/catfile/cache.go`) shows the correct pattern by contrast: its cache key explicitly includes `repoObjDir` and `repoAltDir` in addition to storage/relative path, precisely to prevent quarantine cross-contamination: ` [7](#0-6) `. `unarycache.Cache` does not follow this pattern.

### Impact Explanation
If a commit is only reachable through a quarantine directory (e.g. objects belonging to a push still under `pre-receive` review, or a push that is ultimately rejected and whose quarantine directory is deleted), a `FindLicense` call issued in that quarantined context populates the shared, server-wide cache under key `(repoPath, headOID)`. Any subsequent unrelated caller (a different unprivileged user/RPC on the very same repository path, hitting the same key) that queries `FindLicense` for that same commit OID afterwards receives the previously cached result computed from now possibly-nonexistent (rejected/garbage-collected) object data, without Gitaly re-reading the actual current repository state. This can serve stale or logically-invalid results tied to content that was never accepted into the repository, similar in spirit to `AutoRange` executing based on a stale config set under a different security context. Because `licenseCache` is a single, server-lifetime cache shared across all repositories on the server (constructed once in `server.go`), this staleness is not scoped per-RPC or per-quarantine-session.

### Likelihood Explanation
Reaching this requires only an ordinary user-triggered push (to create quarantined objects) plus a caller invoking `FindLicense` against the same repository/commit OID while the object is quarantine-only, followed by another `FindLicense` call for the same OID after the quarantine is torn down. `FindLicense` is a plain gRPC RPC that Rails can call with any `*gitalypb.Repository`, including a quarantined one, mirroring the same quarantine-passing pattern already tested elsewhere in the codebase (e.g. `TestGetObjectDirectorySize_quarantine`, `TestCache_ObjectReader_quarantine`). No special privilege is needed beyond normal push/API access.

### Recommendation
Include the repository's `GitObjectDirectory` and `GitAlternateObjectDirectories` (or an equivalent quarantine/session identifier) in the `unarycache.cacheKey`, analogous to how `catfile.ProcessCache`'s `key` struct incorporates `repoObjDir`/`repoAltDir`. Alternatively, disable caching entirely whenever the repository message carries a non-empty `GitObjectDirectory`/quarantine directory, so that quarantined computations are never persisted into the shared, long-lived cache.

### Proof of Concept
1. Push a commit containing a `LICENSE` file to a repository such that it is only present in the push's quarantine directory (i.e., before `pre-receive` accepts it), and have GitLab/Rails invoke `FindLicense` on the quarantined `*gitalypb.Repository` for that commit OID as part of a pre-merge/pre-accept check.
2. `unarycache.Cache.GetOrCompute` computes and caches the license response under key `(storage/relativePath, headOID)`, using `internal/git/localrepo/paths.go`'s `Path()` which ignores `GitObjectDirectory`.
3. Cause the push to be rejected (or otherwise have the quarantine directory cleaned up) so the underlying objects are removed and never merged into the main object directory.
4. Have any other (unprivileged) caller invoke `FindLicense` on the same repository non-quarantined `*gitalypb.Repository` for the same commit OID (if it can be referenced, e.g. via a differently-named ref, fork, or resubmitted push reusing the same tree/commit content) — the cache returns the previously computed result from step 2 without re-validating that the object is actually reachable/present in the current, non-quarantined repository state.

func (s *server) FindLicense(ctx context.Context, req *gitalypb.FindLicenseRequest) (*gitalypb.FindLicenseResponse, error) {
	repository := req.GetRepository()
	if err := s.locator.ValidateRepository(ctx, repository); err != nil {
		return nil, structerr.NewInvalidArgument("%w", err)
	}
	repo := s.localRepoFactory.Build(repository)

	headOID, err := repo.ResolveRevision(ctx, "HEAD")
	if err != nil {
		if errors.Is(err, git.ErrReferenceNotFound) {
			return &gitalypb.FindLicenseResponse{}, nil
		}
		return nil, structerr.NewInternal("cannot find HEAD revision: %w", err)
	}

	response, err := s.licenseCache.GetOrCompute(ctx, repo, headOID)
	if err != nil {
		return nil, err
	}

	return response, nil
}

#### Putting it all together

1. `git receive-pack` receives a push
1. `git receive-pack` [creates a quarantine directory `objects/incoming-$RANDOM`](https://gitlab.com/gitlab-org/git/-/blob/v2.24.0/builtin/receive-pack.c#L1715)
1. `git receive-pack` [configures the unpack process](https://gitlab.com/gitlab-org/git/-/blob/v2.24.0/builtin/receive-pack.c#L1721) to write objects into the quarantine directory
1. `git receive-pack` unpacks the objects into the quarantine directory
1. `git receive-pack` [runs the `pre-receive` hook](https://gitlab.com/gitlab-org/git/-/blob/v2.24.0/builtin/receive-pack.c#L1498) with special `GIT_OBJECT_DIRECTORY` and `GIT_ALTERNATE_OBJECT_DIRECTORIES` environment variables that add the quarantine directory to the search path
1. If the `pre-receive` hook rejects the push, `git receive-pack` removes the quarantine directory and its contents. The push is aborted.
1. If the `pre-receive` hook passes, `git receive-pack` [merges the quarantine directory into the main object directory](https://gitlab.com/gitlab-org/git/-/blob/v2.24.0/builtin/receive-pack.c#L1510).
1. `git receive-pack` enters the ref update transaction

Note that by the time the `update` hook runs, the quarantine directory
has already been merged into the main object directory so it no longer
matters. The same goes for the `post-receive` hook which runs even
later.

Because `pre-receive` has the special quarantine configuration data in
environment variables, any `git` process spawned by `pre-receive` will
inherit the quarantine config and will be able to see the objects that
are being pushed.

	sessionID   string

func newCacheKey(sessionID string, repo storage.Repository) (key, bool) {
	if sessionID == "" {
		return key{}, false
	}

	return key{
		sessionID:   sessionID,
		repoStorage: repo.GetStorageName(),
		repoRelPath: repo.GetRelativePath(),
		repoObjDir:  repo.GetGitObjectDirectory(),
		repoAltDir:  strings.Join(repo.GetGitAlternateObjectDirectories(), ","),
	}, true
}
