## Title
Missing internal reward settlement in `FreezeBalanceV2Actuator` before TRON_POWER/vote-weight change - (File: `actuator/src/main/java/org/tron/core/actuator/FreezeBalanceV2Actuator.java`)

### Summary
`FreezeBalanceV2Actuator.execute` mutates an account's frozen balance and TRON_POWER weight but, unlike every sibling actuator that changes an account's voting power (`UnfreezeBalanceActuator`, `UnfreezeBalanceV2Actuator`, `VoteWitnessActuator`, `WithdrawBalanceActuator`, and the TVM equivalents `UnfreezeBalanceProcessor`/`UnfreezeBalanceV2Processor`/`VoteWitnessProcessor`/`WithdrawRewardProcessor`), it never calls `MortgageService.withdrawReward(ownerAddress)` before modifying state.

### Finding Description
The reward accounting model in `MortgageService`/`VoteRewardUtil` works like an accumulator (`Vi`) system analogous to `accumulatedRewardsPerShare` in the reported bug: `delegationStore.getWitnessVi(cycle, srAddress)` accumulates reward-per-vote, and `withdrawReward()` snapshots the account's current vote list into `delegationStore.setAccountVote(endCycle, address, accountCapsule)` together with `beginCycle`/`endCycle` bookkeeping, exactly the "userRewardDebt" analog described in the report: [1](#0-0) 

Every actuator/processor that changes an account's voting-relevant state (frozen balance clearing votes, delegating/undelegating resources that reduce usable TronPower, or explicitly changing votes) is required to call `withdrawReward` first so the reward snapshot reflects the state *before* the change: [2](#0-1) [3](#0-2) [4](#0-3) 

`FreezeBalanceV2Actuator.execute`, however, directly increases `frozenBalance`/TRON_POWER weight and updates `dynamicStore` total weights without ever calling `mortgageService.withdrawReward(ownerAddress)`: [5](#0-4) 

For the `TRON_POWER` resource branch specifically, freezing increases `accountCapsule.getAllTronPower()`/`getTronPower()`, which is the quantity later compared against total votes in `VoteWitnessProcessor.execute` (`sum > tronPower` check) and in `UnfreezeBalanceProcessor`/`UnfreezeBalanceV2Actuator`'s vote-adjustment logic. Because `withdrawReward` is skipped here, the account's `beginCycle`/`endCycle`/`accountVote` snapshot is not refreshed at the moment the TronPower base changes, unlike every other code path that mutates the same underlying account capsule referenced by the reward accumulator.

### Impact Explanation
This mirrors the audit finding's root cause class: a state-changing operation that should trigger reward settlement (`_updateInternalRewardState` / `withdrawReward`) before mutating the balance/weight basis, but does not. In java-tron this could allow a validator/voter to freeze additional TRON_POWER mid-cycle and, on a later `VoteWitnessContract` or unfreeze action, have vote/tron-power comparisons and cycle-boundary snapshots operate on an inconsistent reward state, leading to incorrect reward accrual/reward debt for the affected account across cycle boundaries — an accounting-correctness bug affecting reward distribution (fund misallocation risk), reachable purely from a signed `FreezeBalanceV2Contract` transaction.

### Likelihood Explanation
High reachability: `FreezeBalanceV2Contract` is a standard, unprivileged, broadcastable transaction type executed by `FreezeBalanceV2Actuator`, which any account holder can send at any time, including immediately before/after votes and cycle-boundary maintenance. No special permissions are required.

### Recommendation
Call `chainBaseManager.getMortgageService().withdrawReward(ownerAddress)` at the start of `FreezeBalanceV2Actuator.execute`, before frozen balance/weight mutation and before `accountStore.put(...)`, consistent with the pattern used in `UnfreezeBalanceActuator`, `UnfreezeBalanceV2Actuator`, `VoteWitnessActuator`, and `WithdrawBalanceActuator`, so the account's reward snapshot (`beginCycle`, `endCycle`, `accountVote`) is settled prior to any change to the underlying voting-power basis.

### Proof of Concept
Note: I was unable to fully trace whether `FreezeBalanceV2Actuator`'s TRON_POWER branch is later read by `VoteRewardUtil`/`MortgageService.computeReward` in a way that produces a demonstrably wrong non-zero reward delta without further runtime tracing (this would require executing the full maintenance/reward cycle in a test harness, which was not available in this read-only investigation). The concrete, code-confirmed fact is the structural inconsistency: `FreezeBalanceV2Actuator` is the only TronPower/frozen-balance-mutating actuator in the codebase that omits the `mortgageService.withdrawReward` call that all its siblings perform, matching the exact bug class ("internal reward state not updated before a state-changing user action") described in the source report.   public void withdrawReward(byte[] address) {
    if (!dynamicPropertiesStore.allowChangeDelegation()) {
      return;
    }
    AccountCapsule accountCapsule = accountStore.get(address);
    long beginCycle = delegationStore.getBeginCycle(address);
    long endCycle = delegationStore.getEndCycle(address);
    long currentCycle = dynamicPropertiesStore.getCurrentCycleNumber();
    long reward = 0;
    if (beginCycle > currentCycle || accountCapsule == null) {
      return;
    }
    if (beginCycle == currentCycle) {
      AccountCapsule account = delegationStore.getAccountVote(beginCycle, address);
      if (account != null) {
        return;
      }
    }
    //withdraw the latest cycle reward
    if (beginCycle + 1 == endCycle && beginCycle < currentCycle) {
      AccountCapsule account = delegationStore.getAccountVote(beginCycle, address);
      if (account != null) {
        reward = computeReward(beginCycle, endCycle, account);
        adjustAllowance(address, reward);
        reward = 0;
        logger.info("Latest cycle reward {}, {}.", beginCycle, account.getVotesList());
      }
      beginCycle += 1;
    }
    //
    endCycle = currentCycle;
    if (CollectionUtils.isEmpty(accountCapsule.getVotesList())) {
      delegationStore.setBeginCycle(address, endCycle + 1);
      return;
    }
    if (beginCycle < endCycle) {
      reward += computeReward(beginCycle, endCycle, accountCapsule);
      adjustAllowance(address, reward);
    }
    delegationStore.setBeginCycle(address, endCycle);
    delegationStore.setEndCycle(address, endCycle + 1);
    delegationStore.setAccountVote(endCycle, address, accountCapsule);
    logger.info("Adjust {} allowance {}, now currentCycle {}, beginCycle {}, endCycle {}, "
            + "account vote {}.", Hex.toHexString(address), reward, currentCycle,
        beginCycle, endCycle, accountCapsule.getVotesList());
  }

  @Override
  public boolean execute(Object result) throws ContractExeException {
    TransactionResultCapsule ret = (TransactionResultCapsule) result;
    if (Objects.isNull(ret)) {
      throw new RuntimeException(ActuatorConstant.TX_RESULT_NULL);
    }

    long fee = calcFee();
    final FreezeBalanceV2Contract freezeBalanceV2Contract;
    AccountStore accountStore = chainBaseManager.getAccountStore();
    DynamicPropertiesStore dynamicStore = chainBaseManager.getDynamicPropertiesStore();
    try {
      freezeBalanceV2Contract = any.unpack(FreezeBalanceV2Contract.class);
    } catch (InvalidProtocolBufferException e) {
      logger.debug(e.getMessage(), e);
      ret.setStatus(fee, code.FAILED);
      throw new ContractExeException(e.getMessage());
    }
    AccountCapsule accountCapsule = accountStore.get(freezeBalanceV2Contract.getOwnerAddress().toByteArray());

    if (dynamicStore.supportAllowNewResourceModel()
        && accountCapsule.oldTronPowerIsNotInitialized()) {
      accountCapsule.initializeOldTronPower();
    }

    long frozenBalance = freezeBalanceV2Contract.getFrozenBalance();
    long newBalance = accountCapsule.getBalance() - frozenBalance;

    switch (freezeBalanceV2Contract.getResource()) {
      case BANDWIDTH:
        long oldNetWeight = accountCapsule.getFrozenV2BalanceWithDelegated(BANDWIDTH) / TRX_PRECISION;
        accountCapsule.addFrozenBalanceForBandwidthV2(frozenBalance);
        long newNetWeight = accountCapsule.getFrozenV2BalanceWithDelegated(BANDWIDTH) / TRX_PRECISION;
        dynamicStore.addTotalNetWeight(newNetWeight - oldNetWeight);
        break;
      case ENERGY:
        long oldEnergyWeight = accountCapsule.getFrozenV2BalanceWithDelegated(ENERGY) / TRX_PRECISION;
        accountCapsule.addFrozenBalanceForEnergyV2(frozenBalance);
        long newEnergyWeight = accountCapsule.getFrozenV2BalanceWithDelegated(ENERGY) / TRX_PRECISION;
        dynamicStore.addTotalEnergyWeight(newEnergyWeight - oldEnergyWeight);
        break;
      case TRON_POWER:
        long oldTPWeight = accountCapsule.getTronPowerFrozenV2Balance() / TRX_PRECISION;
        accountCapsule.addFrozenForTronPowerV2(frozenBalance);
        long newTPWeight = accountCapsule.getTronPowerFrozenV2Balance() / TRX_PRECISION;
        dynamicStore.addTotalTronPowerWeight(newTPWeight - oldTPWeight);
        break;
      default:
        logger.debug("Resource Code Error.");
    }

    accountCapsule.setBalance(newBalance);
    accountStore.put(accountCapsule.createDbKey(), accountCapsule);

    ret.setStatus(fee, code.SUCESS);

    return true;
  }
