### Title
Protocol fee bypass on `TokenIdType::Nep245`/`Imt` diffs by splitting a single `TokenDiff` into N unit-sized legs - ([File: contracts/defuse/core/src/intents/token_diff.rs])

### Summary
`TokenDiff::token_fee` waives fees whenever the per-leg `amount <= 1` for `Nep245`/`Imt` (and always for `Nep171`) token ids, and this check is evaluated independently for every `TokenDiff` intent leg with no aggregation across intents or across the batch. An unprivileged signer can pack `N` separate `TokenDiff` intents (each `diff = {token_id: -1}`) into a single signed `MultiPayload`'s `DefuseIntents.intents` list, moving the exact same net `-N` balance that a single `TokenDiff{diff: {token_id: -N}}` would move, but paying `Pips::ZERO` fee on every leg instead of `Pips::fee_ceil(protocol_fee, N)`.

### Finding Description
The broken binding: for a Nep245 token `T` and protocol_fee `p>0`, the protocol intends
`sum_over_batch(fees credited to fee_collector for T) == Pips::fee_ceil(p, sum_of_|negative deltas of T|)`.

The actual code computes the fee independently for each `(token_id, delta)` pair inside a single `TokenDiff::execute_intent` call: [1](#0-0) 
using `token_fee`: [2](#0-1) 
which explicitly returns `Pips::ZERO` whenever `amount <= 1` for `Nep245`/`Imt` token ids. There is no accumulation of deltas for the same `(signer, token_id)` pair across multiple `TokenDiff` intents in the same `DefuseIntents` list, nor across multiple `MultiPayload`s in one `execute_intents` call — each `Intent::TokenDiff` variant is dispatched and executed independently: [3](#0-2) [4](#0-3) 

The only later cross-check, `TransferMatcher::finalize`, verifies that deposits and withdrawals (including the fee-collector deposit that was already made per-leg) net to zero across the whole batch — it enforces conservation of the ledger, not correctness of the fee amount: [5](#0-4) 
Since the fee_collector deposit of `0` is itself already balanced (0 in, 0 out), this invariant check passes trivially and does not detect the missing fee.

Attacker's exact payload: sign one `MultiPayload` whose `DefuseIntents.intents` contains `N` `TokenDiff` entries, each `{diff: {token_id: -1}, memo: None, referral: None}` for the same `Nep245TokenId`, submitted via `execute_intents`. Each leg independently satisfies `amount == 1`, so `token_fee` returns `Pips::ZERO` for all `N` legs, giving `fees_collected` empty/zero, whereas the equivalent single-leg `TokenDiff{diff: {token_id: -N}}` (N>1) hits the `amount > 1` branch and pays `fee.fee_ceil(N)`.

None of the listed guards (`MultiPayload::verify`, `has_public_key`, `verify_intent_nonce`, nonce commit, salt validity, `TransferMatcher::finalize`, `#[pause]`) check or aggregate the magnitude of deltas per token across legs/intents before applying the fee-exemption threshold, so the divergence is not prevented.

### Impact Explanation
Value that should be credited to `engine.state.fee_collector()` (a fee due to the protocol on real value moved through the Verifier) is instead retained by the attacker/signer. This directly matches the Critical category "protocol fees bypassed". The bypass is fully repeatable: any account holding `>= N` units of any Nep245/Imt token can zero out fees on arbitrarily large aggregate transfers of that token by chunking into unit legs, for any `N`, across any Nep245 token id, at will, whenever `protocol_fee > 0`.

### Likelihood Explanation
Preconditions are trivial and fully within an unprivileged signer's control: hold `N` units of a Nep245/Imt token inside the Verifier, and `protocol_fee > 0` (a normal deployment configuration). The attacker cost is just constructing `N` `TokenDiff` entries in a single signed `DefuseIntents` payload (or splitting across multiple signed payloads) and paying the linear-in-`N` gas cost of the transaction — no special role, relayer key, or additional signature is required beyond the signer's own key. This is highly feasible and repeatable per account/token/batch.

### Recommendation
Aggregate negative deltas per `(signer_id, token_id)` across the entire batch (all `TokenDiff` intents dispatched within a single `execute_signed_intents` call, or at minimum within a single `DefuseIntents.intents` list) before applying the `amount > 1` fee-exemption threshold in `TokenDiff::token_fee`, so the threshold check and `fee_ceil` are computed on the summed magnitude rather than per-leg amount. Alternatively, remove the per-amount fee exemption for Nep245/Imt entirely and instead charge fee unconditionally (accepting rounding), or track cumulative per-token deltas at the `Engine`/`Deltas` level and only skip fee when the *net* per-token delta across the whole transaction is `<= 1`.

### Proof of Concept
```rust
// pseudocode / near-workspaces sandbox test outline in tests/src/tests/defuse/intents/token_diff.rs

// setup: env with protocol_fee = Pips::ONE_PERCENT (or any >0), fee_collector set,
// user holds N units of an Nep245 token (e.g., mt.near#nft1) inside the Verifier.

// Case A: single TokenDiff, delta = -N (N > 1)
let signed_a = user.sign_defuse_payload_default(&env.defuse, [TokenDiff {
    diff: TokenDeltas::default().with_apply_deltas([(mt_token_id.clone(), -(N as i128))]).unwrap(),
    memo: None, referral: None,
}]).await.unwrap();
env.defuse_execute_intents(env.defuse.contract_id(), [signed_a]).await.unwrap();
let fee_balance_a = env.mt_balance_of(env.defuse.contract_id(), fee_collector.account_id(), &mt_token_id).await;
assert_eq!(fee_balance_a, fee.fee_ceil(N)); // expected nonzero fee

// Case B (reset state): N separate TokenDiff legs, each delta = -1, same token, single signed payload
let intents: Vec<TokenDiff> = (0..N).map(|_| TokenDiff {
    diff: TokenDeltas::default().with_apply_deltas([(mt_token_id.clone(), -1i128)]).unwrap(),
    memo: None, referral: None,
}).collect();
let signed_b = user.sign_defuse_payload_default(&env.defuse, intents).await.unwrap();
env.defuse_execute_intents(env.defuse.contract_id(), [signed_b]).await.unwrap();
let fee_balance_b = env.mt_balance_of(env.defuse.contract_id(), fee_collector.account_id(), &mt_token_id).await;

// Binding check: same net signer debit (N units), but fees differ
assert_eq!(fee_balance_b, 0);
assert_ne!(fee_balance_a, fee_balance_b); // proves fee bypass: 0 != fee.fee_ceil(N) for fee>0, N>1
```

    // Finalizes all transfers, or returns unmatched deltas.
    // If unmatched deltas overflow, then Err(None) is returned.
    pub fn finalize(self) -> Result<Transfers, InvariantViolated> {
        let mut transfers = Transfers::default();
        let mut deltas = TokenDeltas::default();
        for (token_id, transfer_matcher) in self.0 {
            if let Err(unmatched) = transfer_matcher.finalize_into(&token_id, &mut transfers)
                && (unmatched == 0 || deltas.apply_delta(token_id, unmatched).is_none())
            {
                return Err(InvariantViolated::Overflow);
            }
        }
        if !deltas.is_empty() {
            return Err(InvariantViolated::UnmatchedDeltas {
                unmatched_deltas: deltas,
            });
        }
        Ok(transfers)
    }
