The binding described in the question actually holds correctly, and the alleged divergence does not exist.

**Trace of the code path:**

`Engine::execute_signed_intents` loops over each signed payload calling `execute_signed_intent`, which mutates the in-memory `Deltas<S>` wrapper (via `state.mint/burn/add_delta` etc., which forward to the underlying `S: State`, i.e., the real `Contract` storage struct), and only calls `self.finalize()` once at the very end: [1](#0-0) [2](#0-1) 

`TransferMatcher::finalize` returns `Err(InvariantViolated::Overflow)` when `apply_delta` overflows, exactly as described: [3](#0-2) 

For the real `execute_intents` entry point, `Engine::new(self, ...)` wraps the **live contract state** (`self`, i.e. `&mut Contract`), so intent execution during the loop directly mutates the contract's persistent `token_balances`-equivalent storage fields (through `S::mint`/`S::burn`/etc.) as each intent is processed — not just an in-memory copy. However, `execute_intents` immediately panics on any `Err`, including `DefuseError::InvariantViolated`: [4](#0-3) 

On NEAR, a panic inside a contract function call aborts the entire receipt execution and reverts **all** storage writes performed during that call — this is standard NEAR runtime semantics (transactional state per function call), not something the contract needs to implement itself. Thus even though balance mutations for earlier intents were written into the (cached, in-memory-during-execution) contract state before `finalize()` ran, none of them are committed to on-chain storage when the call panics.

This is directly confirmed by the existing sandbox test, which forces exactly the `Overflow`/`UnmatchedDeltas` scenario and asserts that on-chain balances are unchanged after the reverted call: [5](#0-4) 

**Regarding `simulate_intents`:** this is a separate, explicitly non-mutating view-only path. It runs the engine against `self.cached()` (a read-only/cached view, not live storage) and explicitly catches `DefuseError::InvariantViolated(v)` to report it as data in `SimulationOutput.invariant_violated`, rather than panicking: [6](#0-5)

    // Finalizes all transfers, or returns unmatched deltas.
    // If unmatched deltas overflow, then Err(None) is returned.
    pub fn finalize(self) -> Result<Transfers, InvariantViolated> {
        let mut transfers = Transfers::default();
        let mut deltas = TokenDeltas::default();
        for (token_id, transfer_matcher) in self.0 {
            if let Err(unmatched) = transfer_matcher.finalize_into(&token_id, &mut transfers)
                && (unmatched == 0 || deltas.apply_delta(token_id, unmatched).is_none())
            {
                return Err(InvariantViolated::Overflow);
            }
        }
        if !deltas.is_empty() {
            return Err(InvariantViolated::UnmatchedDeltas {
                unmatched_deltas: deltas,
            });
        }
        Ok(transfers)
    }
}

    #[pause(name = "intents")]
    fn simulate_intents(&self, signed: Vec<MultiPayload>) -> SimulationOutput {
        let mut inspector = SimulateInspector::default();
        let engine = Engine::new(self.cached(), &mut inspector);

        let invariant_violated = match engine.execute_signed_intents(signed) {
            // do not log transfers
            Ok(_) => None,
            Err(DefuseError::InvariantViolated(v)) => Some(v),
            Err(err) => err.panic(),
        };

        SimulationOutput {
            report: inspector.into_report(),
            invariant_violated,
            state: StateOutput {
                fee: self.fee(),
                current_salt: self.salts.current(),
            },
        }
    }
