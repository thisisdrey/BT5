### Title
Roam-suppression bypass allows unbounded remote-address churn via 3+ address round-robin - (File: outside.go)

### Summary
`handleHostRoaming` only suppresses roaming when the new source address equals `hostinfo.lastRoamRemote` (the single previously-recorded prior address) within `RoamingSuppressSeconds`. It does not rate-limit roaming generally, so an attacker who can send valid session-decryptable packets from more than two distinct source addresses in round-robin (e.g., A→B→C→A→B→C...) causes `SetRemote` to be invoked on every single packet, since the "two-steps-back" address never matches the currently-arriving address in a 3+ cycle.

### Finding Description
In `outside.go:264-294`, `Interface.handleHostRoaming` performs: [1](#0-0) 

The suppression check at line 274 only compares `via.UdpAddr` against `hostinfo.lastRoamRemote`, which is set to whatever `curRemote` was *immediately before the previous roam* [2](#0-1) . This design correctly defeats a strict two-address ping-pong (A,B,A,B,...): after the first roam A→B, `lastRoamRemote=A`; a subsequent packet from A matches `lastRoamRemote` and is suppressed for `RoamingSuppressSeconds` (2 seconds, defined at `hostmap.go:35` as `const RoamingSuppressSeconds = 2`).

However, with three or more rotating addresses (A,B,C,A,B,C,...), `lastRoamRemote` is always the address from two steps back, which never equals the address of the current packet in a 3-cycle. Tracing the sequence:
- via A: roam X→A, `lastRoamRemote=X`
- via B: `B != lastRoamRemote(X)` → roam A→B, `lastRoamRemote=A`
- via C: `C != lastRoamRemote(A)` → roam B→C, `lastRoamRemote=B`
- via A: `A != lastRoamRemote(B)` → roam C→A, `lastRoamRemote=C`
- ... repeats indefinitely, never suppressed.

Every iteration calls `hostinfo.SetRemote(via.UdpAddr)` and logs "Host roamed to new udp ip/port" [3](#0-2) , meaning the suppression mechanism provides no rate-limit against this pattern at all — it only handles the narrow two-address flap case it was apparently designed for (per the comment at `hostmap.go:33-35`: "How long we should prevent roaming back to the previous IP... helps prevent flapping due to packets already in flight").

This is reachable from `readOutsidePackets` on every successfully decrypted packet (`outside.go:135`) and from the relay path (`outside.go:180`), for both `Message` and `Test` (`TestReply`) packet types, meaning an attacker who already holds valid session keys (or can otherwise get authenticated ciphertext accepted, e.g., via spoofed UDP source address against a real peer's counter/AEAD-authenticated packet — UDP source addresses are trivially spoofable and are not part of the AEAD associated data) can trigger continuous `SetRemote` churn.

### Impact Explanation
Each unsuppressed roam mutates `hostinfo.remote` state via `SetRemote`, which affects the hostmap's remote-address bookkeeping and future packet routing/allow-list decisions, and logs an event per packet. Continuous forced roaming with attacker-chosen addresses causes state churn/poisoning on the hostinfo remote address and can be used as a low-cost DoS/wedge vector against legitimate connectivity for that tunnel (real traffic delivery is disrupted while the hostinfo's remote keeps getting overwritten by attacker-controlled addresses), matching the "remote state poisoning" / "DoS via roam flapping" bounty category referenced in the question.

### Likelihood Explanation
Exploitability requires only that the attacker be able to present valid, session-decryptable packets while spoofing distinct source UDP addresses (source-address spoofing over UDP is generally feasible and is exactly the scenario the roaming feature and its suppression logic are meant to guard against — the check's entire purpose is defending against attacker/network-controlled address changes on an already-authenticated tunnel). No certificate forgery, CA compromise, or key material beyond what's assumed by the question is needed. The bypass requires only 3 distinct source addresses cycling in round-robin, which is trivial to automate and fully repeatable — every single packet after the third is unsuppressed.

### Recommendation
Replace the single-previous-address comparison with a proper rate limit that is independent of which specific address is used — e.g., track `lastRoam` time only and suppress *any* remote change (regardless of `via.UdpAddr` value) within `RoamingSuppressSeconds` of the last roam, or maintain a small recent-address history/rate counter (e.g., token bucket per hostinfo) so no more than N roams are permitted per suppression window regardless of how many distinct addresses are used.

### Proof of Concept
Unit test plan for `handleHostRoaming` (in `outside_test.go` or similar):
1. Construct an `Interface` with a permissive `RemoteAllowList` (`AllowAll` returns true) and a `HostInfo` with an initial `remote` set to address `X`.
2. Call `f.handleHostRoaming(hostinfo, ViaSender{UdpAddr: A})`, then `handleHostRoaming(hostinfo, ViaSender{UdpAddr: B})`, then `handleHostRoaming(hostinfo, ViaSender{UdpAddr: C})`, then repeat `A, B, C, A, B, C` in quick succession (all within `RoamingSuppressSeconds`).
3. Instrument/spy on `hostinfo.SetRemote` (or check `hostinfo.remote` after each call) and assert it changes on every call in the 3-cycle sequence — i.e., `SetRemote` call count equals the number of `handleHostRoaming` invocations (no suppression), demonstrating the suppression logic fails to bound churn for ≥3 rotating addresses, in contrast to the strict `A,B,A,B` sequence where the 3rd+ calls are correctly suppressed.

func (f *Interface) handleHostRoaming(hostinfo *HostInfo, via ViaSender) {
	curRemote := hostinfo.GetRemote()
	if !via.IsRelayed && curRemote != via.UdpAddr {
		if !f.lightHouse.GetRemoteAllowList().AllowAll(hostinfo.vpnAddrs, via.UdpAddr.Addr()) {
			if f.l.Enabled(context.Background(), slog.LevelDebug) {
				hostinfo.logger(f.l).Debug("lighthouse.remote_allow_list denied roaming", "newAddr", via.UdpAddr)
			}
			return
		}

		if !hostinfo.lastRoam.IsZero() && via.UdpAddr == hostinfo.lastRoamRemote && time.Since(hostinfo.lastRoam) < RoamingSuppressSeconds*time.Second {
			if f.l.Enabled(context.Background(), slog.LevelDebug) {
				hostinfo.logger(f.l).Debug("Suppressing roam back to previous remote",
					"suppressSeconds", RoamingSuppressSeconds,
					"udpAddr", curRemote,
					"newAddr", via.UdpAddr,
				)
			}
			return
		}

		hostinfo.logger(f.l).Info("Host roamed to new udp ip/port.",
			"udpAddr", curRemote,
			"newAddr", via.UdpAddr,
		)
		hostinfo.lastRoam = time.Now()
		hostinfo.lastRoamRemote = curRemote
		hostinfo.SetRemote(via.UdpAddr)
	}

}
