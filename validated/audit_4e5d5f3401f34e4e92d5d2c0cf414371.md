### Title
Pack-objects hook buffers and hashes full request stdin to disk before the concurrency limiter is applied - ([File: internal/gitaly/service/hook/pack_objects.go])

### Summary
`packObjectsHook`, the handler backing `PackObjectsHookWithSidechannel` (invoked by `gitaly-hooks` on every `git-upload-pack`/`git-receive-pack` negotiation), performs a full unbounded disk-buffering and SHA-256 hashing pass over the client-controlled request body *before* the request is ever subjected to `s.packObjectsLimiter`, the concurrency limiter specifically designed to bound pack-objects load.

### Finding Description
`packObjectsHook` first calls `s.computeCacheKey(ctx, req, stdinReader)` unconditionally for every request: [1](#0-0) 

`computeCacheKey` calls `bufferStdin`, which copies the *entire* stdin stream (the "want"/negotiation payload sent to `git-pack-objects`, fully attacker-influenced in size via the ref/oid list negotiated during clone/fetch) into a newly created temp file while simultaneously hashing it, with no size limit whatsoever: [2](#0-1) [3](#0-2) 

Only *after* this disk I/O and hashing has completed does the code reach `s.packObjectsCache.Fetch(...)`, and only inside that closure — and only for non-loopback remote IPs — is `s.runPackObjectsLimited` invoked, which is the sole place `s.packObjectsLimiter.Limit(...)` (the `ConcurrencyLimiter`/queue gate meant to bound concurrent pack-objects executions) is applied: [4](#0-3) [5](#0-4) 

The `ConcurrencyLimiter.Limit`/`keyedConcurrencyLimiter.acquire` mechanism was purpose-built to cap in-flight and queued pack-objects work per key (remote IP/repo/user) exactly to prevent this class of resource-exhaustion: [6](#0-5) [7](#0-6) 

This is the same root-cause pattern as the referenced Sherlock finding: an expensive, resource-consuming step (buffering + hashing an entire caller-supplied payload to disk) is executed *before* the gate that is supposed to bound resource consumption for that exact operation, so the protection is charged too late to actually stop the cost from being incurred.

### Impact Explanation
Every `PostUploadPack`/`SSHUploadPack`/`PostReceivePack` request that reaches the pack-objects hook triggers this pre-limiter disk write and hash computation regardless of how many pack-objects executions are already in flight or queued. An ordinary authenticated client performing many concurrent clone/fetch/push negotiations with large negotiation payloads can force Gitaly to create many temporary files and perform CPU-bound hashing work concurrently, unconstrained by `packObjectsLimiter`'s queue length/concurrency caps — exhausting temp-disk space, file descriptors, and CPU on the node, causing a denial of service that slows or stalls the Gitaly process for other clients on the same repository/node. This mirrors the "cheaper than expected DoS" impact of the original bug: the limiter exists but is bypassed for the actual costly portion of the work.

### Likelihood Explanation
Likelihood is high: the vulnerable code path is on the default request path for every clone/fetch/push (it backs `PackObjectsHookWithSidechannel`, invoked by Gitaly's own git hooks during normal negotiation), requires no special privileges beyond being able to issue Git operations against a repository, and requires no malicious peer/MITM/leaked-token conditions — only an ordinary user issuing many concurrent Git operations with sizable negotiation input.

### Recommendation
Move (or duplicate) the concurrency/queue admission check in `packObjectsHook` to occur before `computeCacheKey`/`bufferStdin` executes, or impose a hard size limit on stdin read within `bufferStdin` prior to buffering, so that the expensive disk-write/hash step is itself gated by `packObjectsLimiter` (or a lightweight pre-check) rather than being performed unconditionally for every incoming request.

### Proof of Concept
Not executed against a live system; derived from static analysis of the call order in `packObjectsHook` (internal/gitaly/service/hook/pack_objects.go:47-90) showing `computeCacheKey`/`bufferStdin` execute unconditionally prior to any call into `runPackObjectsLimited`/`packObjectsLimiter.Limit`, which is the only enforcement point for the pack-objects concurrency/queue limit (internal/limiter/concurrency_limiter.go:197-241).

func (s *server) computeCacheKey(ctx context.Context, req *gitalypb.PackObjectsHookWithSidechannelRequest, stdinReader io.Reader) (string, io.ReadCloser, error) {
	cacheHash := sha256.New()

	repository := req.GetRepository()
	if tx := storage.ExtractTransaction(ctx); tx != nil {
		// The cache uses the requests as the keys. As the request's repository in the RPC handler has been rewritten
		// to point to the transaction's repository, the handler sees each request as different even if they point to
		// the same repository. Restore the original request to ensure identical requests get the same key.
		repository = tx.OriginalRepository(req.GetRepository())
	}

	cacheKeyPrefix, err := protojson.Marshal(&gitalypb.PackObjectsHookWithSidechannelRequest{
		Repository:  repository,
		Args:        req.GetArgs(),
		GitProtocol: req.GetGitProtocol(),
	})
	if err != nil {
		return "", nil, err
	}
	if _, err := cacheHash.Write(cacheKeyPrefix); err != nil {
		return "", nil, err
	}
	stdin, err := bufferStdin(stdinReader, cacheHash)
	if err != nil {
		return "", nil, err
	}
	cacheKey := hex.EncodeToString(cacheHash.Sum(nil))
	return cacheKey, stdin, nil
}

}

func bufferStdin(r io.Reader, h hash.Hash) (_ io.ReadCloser, err error) {
	f, err := os.CreateTemp("", "PackObjectsHook-stdin")
	if err != nil {
		return nil, err
	}
	defer func() {
		if err != nil {
			f.Close()
		}
	}()

	if err := os.Remove(f.Name()); err != nil {
		return nil, err
	}

	_, err = io.Copy(f, io.TeeReader(r, h))
	if err != nil {
		return nil, err
	}

	if _, err := f.Seek(0, io.SeekStart); err != nil {
		return nil, err
	}

	return f, nil
}

// acquire tries to acquire the semaphore. It may fail if the admission queue is full or if the max
// queue-time ticker ticks before acquiring a concurrency token.
func (sem *keyedConcurrencyLimiter) acquire(ctx context.Context, limitingKey string) (returnedErr error) {
	if sem.queueTokens != nil {
		// Try to acquire the queueing token. The queueing token is used to control how many
		// callers may wait for the concurrency token at the same time. If there are no more
		// queueing tokens then this indicates that the queue is full and we thus return an
		// error immediately.
		if err := sem.queueTokens.TryAcquire(); err != nil {
			return err
		}
		// We have acquired a queueing token, so we need to release it if acquiring
		// the concurrency token fails. If we succeed to acquire the concurrency
		// token though then we retain the queueing token until the caller signals
		// that the concurrency-limited function has finished. As a consequence the
		// queue token is returned together with the concurrency token.
		//
		// A simpler model would be to just have `maxQueueLength` many queueing
		// tokens. But this would add concurrency-limiting when acquiring the queue
		// token itself, which is not what we want to do. Instead, we want to admit
		// as many callers into the queue as the queue length permits plus the
		// number of available concurrency tokens allows.
		defer func() {
			if returnedErr != nil {
				sem.queueTokens.Release()
			}
		}()
	}

	// We are queued now, so let's tell the monitor. Furthermore, even though we're still
	// holding the queueing token when this function exits successfully we also tell the monitor
	// that we have exited the queue. It is only an implementation detail anyway that we hold on
	// to the token, so the monitor shouldn't care about that.
	sem.monitor.Queued(ctx, limitingKey, sem.queueLength())
	defer sem.monitor.Dequeued(ctx)

	if sem.maxQueueWait != 0 {
		if sem.setWaitTimeoutContext != nil {
			ctx = sem.setWaitTimeoutContext()
		} else {
			var cancel context.CancelFunc
			ctx, cancel = context.WithTimeout(ctx, sem.maxQueueWait)
			defer cancel()
		}
	}

	// Try to acquire the concurrency token now that we're in the queue.
	return sem.concurrencyTokens.Acquire(ctx)
}

func (c *ConcurrencyLimiter) Limit(ctx context.Context, limitingKey string, f LimitedFunc) (interface{}, error) {
	span, ctx := tracing.StartSpanIfHasParent(
		ctx,
		"limiter.ConcurrencyLimiter.Limit",
		[]attribute.KeyValue{
			attribute.String("key", limitingKey),
		},
	)
	defer span.End()

	if c.currentLimit() <= 0 {
		return f()
	}

	sem := c.getConcurrencyLimit(limitingKey)
	defer c.putConcurrencyLimit(limitingKey)

	start := time.Now()

	if err := sem.acquire(ctx, limitingKey); err != nil {
		queueTime := time.Since(start)
		switch {
		case errors.Is(err, ErrMaxQueueSize):
			c.monitor.Dropped(ctx, limitingKey, sem.queueLength(), sem.inProgress(), queueTime, "max_size")
			return nil, structerr.NewResourceExhausted("%w", ErrMaxQueueSize).WithDetail(&gitalypb.LimitError{
				ErrorMessage: err.Error(),
				RetryAfter:   durationpb.New(0),
			})
		case errors.Is(err, ErrMaxQueueTime):
			c.monitor.Dropped(ctx, limitingKey, sem.queueLength(), sem.inProgress(), queueTime, "max_time")
			return nil, structerr.NewResourceExhausted("%w", ErrMaxQueueTime).WithDetail(&gitalypb.LimitError{
				ErrorMessage: err.Error(),
				RetryAfter:   durationpb.New(0),
			})
		default:
			c.monitor.Dropped(ctx, limitingKey, sem.queueLength(), sem.inProgress(), queueTime, "other")
			return nil, fmt.Errorf("unexpected error when dequeueing request: %w", err)
		}
	}
	defer sem.release()

	c.monitor.Enter(ctx, sem.inProgress(), time.Since(start))
	defer c.monitor.Exit(ctx)
	return f()
}
