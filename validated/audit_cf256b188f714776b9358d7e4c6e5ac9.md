### Title
Missing per-state request timeout in `NakamotoTenureDownloadState::GetTenureStartBlock` (and other states) allows a single slow-responding peer to permanently occupy a tenure-download slot - ([File: stackslib/src/net/download/nakamoto/tenure_downloader.rs])

### Summary
`NakamotoTenureDownloader` records the millisecond timestamp a `GetTenureStartBlock`/`GetTenureEndBlock`/`GetTenureBlocks` request began, but that timestamp is only ever used for debug logging, never compared against an elapsed-time bound to force the request to fail. Combined with `NakamotoTenureDownloaderSet::make_tenure_downloaders` popping a tenure from the schedule once *any* downloader exists for it, a single unresponsive peer can permanently "claim" a specific tenure's download slot and prevent any other (honest) peer from ever being tried for it.

### Finding Description
`NakamotoTenureDownloadState::GetTenureStartBlock(StacksBlockId, u128)` stores a start timestamp [1](#0-0) . The constant `WAIT_FOR_TENURE_END_BLOCK_TIMEOUT` is defined [2](#0-1)  but is never referenced anywhere else in this file (or its containing module) — the timestamp field is used only for computing an elapsed-time value to print in a debug log line, e.g. in `handle_next_download_response` for `GetTenureStartBlock`: `get_epoch_time_ms().saturating_sub(*start_request_time)` [3](#0-2) . There is no code path in `NakamotoTenureDownloader` that checks "has too much time elapsed since `start_request_time`" and aborts/marks the connection dead as a result.

The completion mechanism that would clear an in-flight request is `NeighborRPC::poll_next_reply`/`collect_replies`, which only resolves once the HTTP response is fully decoded, or errors out if the socket itself dies (`convo`/`socket` disappear) [4](#0-3) . A peer that keeps the TCP connection alive and trickles bytes (or simply withholds the response body while keeping the connection non-idle) causes `convo.is_idle()` to stay `false` and `try_get_response()` to keep returning `None`, so `poll_next_reply` returns `Ok(None)` indefinitely [5](#0-4) . `NeighborRPC::has_inflight` therefore stays `true` forever for that peer [6](#0-5) , `handle_next_download_response` is never invoked, and `downloader.idle` never becomes `true` (it is only set in that handler) [7](#0-6) .

Because `NakamotoTenureDownloaderSet::make_tenure_downloaders` skips assigning any other peer to a tenure once a downloader (even a stuck one) already exists for it — `if self.has_downloader_for_tenure(ch) { schedule.pop_front(); continue; }` — the tenure entry is simply discarded from the schedule rather than retried with a different, honest peer [8](#0-7) . `try_resume_peer` and `clear_available_peers` only reassign/free peers whose downloader is `idle`, which this stuck downloader never becomes [9](#0-8) . `run()` itself only clears a peer via `is_dead_or_broken`, which is set solely by the socket-level connection dying, not by any elapsed-time bound on the pending request [10](#0-9) .

An attacker who runs their own P2P peer, gets legitimately selected as an available data-source for a canonical tenure (i.e., is in the `available` map used by `make_tenure_downloaders`), accepts the `GET /v3/blocks/{block_id}` (tenure-start) request, and then never completes the HTTP response, causes the victim's downloader/peer slot for that specific tenure to be occupied indefinitely with `idle=false`, with no existing check in this code path forcing expiration.

### Impact Explanation
The specific canonical tenure assigned to the malicious peer is denied — the scheduler discards it from the retry queue rather than trying another (honest) peer that may also serve it, since `has_downloader_for_tenure` is true for as long as the stuck downloader entry exists. This is a targeted, repeatable availability denial for a chosen tenure's sync progress using a single connection and a single accepted HTTP request, matching an unauthenticated-DoS-from-few-messages profile against the download/backfill path of a node.

### Likelihood Explanation
Preconditions: attacker must run a peer that is authenticated at the P2P layer and be selected as a data source for the targeted tenure (this is routine for any peer serving Nakamoto inventory data, no privileged role or secret required). Attacker cost is a single open HTTP connection where they stall the tenure-start (or tenure-end/tenure-blocks) response indefinitely. It is fully remote and repeatable against successive tenures if the peer is re-selected.

### Recommendation
Add an explicit elapsed-time check against `start_request_time` for all three states (`GetTenureStartBlock`, `GetTenureEndBlock`, `GetTenureBlocks`), comparable to `WAIT_FOR_TENURE_END_BLOCK_TIMEOUT`, and mark the peer dead/broken (and requeue the tenure for other peers) once the bound is exceeded — either inside `NakamotoTenureDownloader` (checked each `run_downloads` tick) or inside `NeighborRPC`/`poll_next_reply` as a generic inflight-request deadline.

### Proof of Concept
Rust test plan (net module test, e.g. added near `tenure_downloader_set` tests):
1. Construct a `NakamotoTenureDownloaderSet` and a `NakamotoTenureDownloader` in `GetTenureStartBlock(block_id, get_epoch_time_ms())` state, assigned to a mock `naddr`.
2. Mock `NeighborRPC` (or the underlying `PeerNetwork`/HTTP conversation) so that `has_inflight(&naddr)` always returns `true` and `is_dead_or_broken` always returns `false` (simulating a peer that accepted the request and never completes it).
3. Call `NakamotoTenureDownloaderSet::run(...)` repeatedly across many simulated ticks (e.g., advancing a mocked clock well past any reasonable timeout, such as `WAIT_FOR_TENURE_END_BLOCK_TIMEOUT` equivalent).
4. Assert: `downloader.idle == false` remains true across all ticks, `self.peers.contains_key(&naddr)` remains true, and `neighbor_rpc.is_dead_or_broken(...)` is never asserted `true` for `naddr` absent an explicit elapsed-time check — i.e., no code path in `tenure_downloader.rs`/`tenure_downloader_set.rs` transitions the downloader out of this state or frees the slot purely due to elapsed time.

    fn poll_next_reply(
        network: &mut PeerNetwork,
        naddr: &NeighborAddress,
        event_id: usize,
        request_opt: &mut Option<StacksHttpRequest>,
    ) -> Result<Option<StacksHttpResponse>, NetError> {
        PeerNetwork::with_http(network, |network, http| {
            // make sure we're connected
            let (Some(ref mut convo), Some(ref mut socket)) =
                http.get_conversation_and_socket(event_id)
            else {
                if http.is_connecting(event_id) {
                    debug!(
                        "{:?}: HTTP event {} is not connected yet",
                        &network.local_peer, event_id
                    );
                    return Ok(None);
                } else {
                    // conversation died
                    debug!("{:?}: HTTP event {} hung up", &network.local_peer, event_id);
                    return Err(NetError::PeerNotConnected(format!("HTTP connection to {naddr} (event {event_id}) hung up -- no connection established and not connecting")));
                }
            };

            // drive socket I/O
            if let Some(request) = request_opt.take() {
                let res = convo.send_request(request.clone());
                if let Err(NetError::InProgress) = res {
                    // try again -- another state machine is using this conversation
                    request_opt.replace(request);
                }
            };
            HttpPeer::saturate_http_socket(socket, convo)?;

            // see if we got any data
            let Some(http_response) = convo.try_get_response() else {
                if !convo.is_idle() {
                    // still waiting
                    debug!(
                        "{:?}: HTTP event {} is still waiting for a response",
                        &network.local_peer, event_id
                    );
                }
                return Ok(None);
            };

            Ok(Some(http_response))
        })
    }

    pub fn try_resume_peer(&mut self, naddr: NeighborAddress) -> bool {
        debug!("Try resume {}", &naddr);
        if let Some(idx) = self.peers.get(&naddr) {
            let Some(Some(_downloader)) = self.downloaders.get(*idx) else {
                return false;
            };

            debug!(
                "Peer {naddr} already bound to downloader for {}",
                &_downloader.tenure_id_consensus_hash
            );
            return true;
        }
        for (i, downloader_opt) in self.downloaders.iter_mut().enumerate() {
            let Some(downloader) = downloader_opt else {
                continue;
            };
            if !downloader.idle {
                continue;
            }
            debug!(
                "Assign peer {naddr} to work on downloader for {} in state {}",
                &downloader.tenure_id_consensus_hash, &downloader.state
            );
            downloader.naddr = naddr.clone();
            self.peers.insert(naddr, i);
            return true;
        }
        return false;
    }

    /// Deschedule peers that are bound to downloader slots that are either vacant or correspond to

    pub fn clear_available_peers(&mut self) {
        let mut idled: Vec<NeighborAddress> = vec![];

            let Some(downloader_opt) = self.downloaders.get(*i) else {

        }
