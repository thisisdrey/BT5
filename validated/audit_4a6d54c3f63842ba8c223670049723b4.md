### Title
Unauthenticated `/new_burn_block` HTTP endpoint lets any TCP peer forge `SignerEvent::NewBurnBlock` into the signer runloop - ([File: libsigner/src/events.rs])

### Summary
`SignerEventReceiver::bind` opens a plain `tiny_http` server on a configured socket with no authentication, IP allowlist, or provenance check. `next_event` routes any POST to `/new_burn_block` straight into `process_event::<T, BurnBlockEvent>`, which JSON-deserializes the request body and hands it to `TryFrom<BurnBlockEvent> for SignerEvent<T>`, a pure field copy with no validation against the node's actual burnchain state.

### Finding Description
The broken equality: `SignerEvent::NewBurnBlock{burn_height, consensus_hash, burn_header_hash, parent_burn_block_hash}` forwarded to the signer runloop should equal the burnchain state observed by the node's own indexer/event-dispatcher, but instead it equals whatever the HTTP request body says.

Code path:
- `SignerEventReceiver::bind` (libsigner/src/events.rs:404-408) just calls `HttpServer::http(listener)` — no credential, secret header, or peer-address check is installed anywhere in this file or in `next_event`.
- `next_event` (libsigner/src/events.rs:413-459) dispatches purely on `request.url()`; for `/new_burn_block` it calls `process_event::<T, BurnBlockEvent>(request)` with zero authentication gate (contrast only `/status` and `/shutdown` get special handling, and neither of those authenticates either).
- `process_event` (libsigner/src/events.rs:519-542) reads the raw body and does `serde_json::from_slice::<BurnBlockEvent>(body)`, then `json_event.try_into()`.
- `TryFrom<BurnBlockEvent> for SignerEvent<T>` (libsigner/src/events.rs:637-649) is a direct, unchecked field copy:
```rust
Ok(SignerEvent::NewBurnBlock {
    burn_height: burn_block_event.burn_block_height,
    received_time: SystemTime::now(),
    burn_header_hash: burn_block_event.burn_block_hash,
    consensus_hash: burn_block_event.consensus_hash,
    parent_burn_block_hash: burn_block_event.parent_burn_block_hash,
})
```
There is no signature, no cross-check against a locally-tracked burnchain tip, no shared-secret header check, and no peer-address restriction anywhere on this path (confirmed by searching the file and the surrounding `stacks-signer` config/lib code for any `Authorization`/secret/allowlist logic — none exists in `libsigner/src/events.rs`, and no such gate was found in `stacks-signer/src/config.rs` or `stacks-signer/src/lib.rs`).

Attacker exploit: any TCP client that can reach the port passed to `bind()` sends:
```
POST /new_burn_block HTTP/1.1
Host: <signer-ip>:<port>
Content-Type: application/json
Content-Length: <n>

{"burn_block_hash":"...","burn_block_height":999999,"reward_recipients":[],"reward_slot_holders":[],"burn_amount":0,"consensus_hash":"<attacker-chosen>","parent_burn_block_hash":"..."}
```
`process_event` deserializes this and `TryFrom` faithfully forwards the attacker-chosen `burn_height`/`consensus_hash` into `SignerEvent::NewBurnBlock`, which `forward_event` sends unmodified to the signer's out-channels / runloop.

### Impact Explanation
The signer runloop consumes `SignerEvent::NewBurnBlock` as ground truth about burnchain progress (used to drive state-machine transitions such as burn-height tracking / tenure-change logic in `stacks-signer/src/v0/signer_state.rs`). An attacker with only network access to this listening socket can inject an arbitrary, never-actually-observed burn height, consensus hash, and header hash into that state machine — this is unauthenticated write of forged state into the signer's decision pipeline, matching the "Critical: unauthenticated/unauthorized write to state" category. It is trivially repeatable (one HTTP POST per forged event) and requires no session, no valid StackerDB slot, no key.

### Likelihood Explanation
Preconditions are minimal: the attacker only needs TCP reachability to whatever address/port the signer operator passed to `SignerEventReceiver::bind` (the address the node's event-observer is configured to POST to). No secret, peer authentication, or privileged role is required by the code in this file. Attacker cost is a single crafted HTTP POST; the attack is fully repeatable. The only mitigating factor — not evidenced in this file or the config code I could inspect — would be network-level protections (firewalling this port to localhost/node-only), but that is an operational/deployment control, not a code-level guard, and the question's precondition explicitly grants "network access to the port bound by `SignerEventReceiver::bind`."

### Recommendation
Add an authentication mechanism to `SignerEventReceiver`/`process_event` (e.g., a shared secret/HMAC header configured between the node's event dispatcher and the signer, verified before deserializing the body) and/or bind the listener to a loopback/private interface by default with an explicit opt-in for exposing it further. At minimum, verify a per-request signature or token in `next_event` before calling `process_event`, and reject requests from unexpected peer addresses when a token is not configured.

### Proof of Concept

2. From an unauthenticated `TcpStream`/`reqwest` client, send:

Assert the consumer channel receives `SignerEvent::NewBurnBlock{burn_height: 123456789, consensus_hash: <attacker chosen>, ..}` — i.e. `assert_eq!(event, SignerEvent::NewBurnBlock{burn_height:123456789, consensus_hash: attacker_hash, ...})`, proving the forged JSON was accepted with no provenance check.
```rust
fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}
```
