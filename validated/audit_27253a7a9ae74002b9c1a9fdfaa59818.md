### Title
JSON-RPC API layer completely bypasses the `node.disabledApi` access-control list enforced on HTTP/gRPC - (File: `framework/src/main/java/org/tron/core/services/jsonrpc/FullNodeJsonRpcHttpService.java`)

### Summary
java-tron lets operators disable specific wallet API methods node-wide via `node.disabledApi`, intending to block public exposure of sensitive endpoints (e.g. `broadcasttransaction`, `gettransactionbyid`, `getaccount`). This restriction is enforced only for the HTTP and gRPC transports, not for the Ethereum-compatible JSON-RPC transport, so the same functionality remains fully reachable by any anonymous client through JSON-RPC method names, silently bypassing the administrator's intended lockdown — structurally the same bug class as CVE-2021-39870, where a security-relevant server setting was bypassed via a different API entry point.

### Finding Description
The `disabledApi` list is enforced by two dedicated filters:
- `HttpApiAccessFilter`, added as a servlet filter for the FullNode/Solidity/PBFT HTTP services [1](#0-0) 
- `RpcApiAccessInterceptor`, added as a gRPC server interceptor for the corresponding gRPC services [2](#0-1) 

In contrast, `FullNodeJsonRpcHttpService` (and its Solidity/PBFT JSON-RPC counterparts) only registers `HttpInterceptor` as a filter — it never adds `HttpApiAccessFilter` or any equivalent check against `CommonParameter.getInstance().getDisabledApiList()`: [3](#0-2) 

`JsonRpcServlet.doPost` dispatches every request straight into the `TronJsonRpc`/`TronJsonRpcImpl` implementation via jsonrpc4j's `JsonRpcServer`, with no call to `isDisabled(...)` anywhere in the path [4](#0-3) .

This gap is explicitly acknowledged in the shipped configuration documentation: "Disabled API list (works for http, rpc and pbft, not jsonrpc)" [5](#0-4) , confirming the design leaves JSON-RPC completely outside the access-control mechanism rather than it being an incidental oversight.

Because many JSON-RPC methods in `TronJsonRpcImpl` (e.g. `eth_sendRawTransaction`, which wraps the same broadcast path as the HTTP `broadcasttransaction`/gRPC endpoint) expose equivalent functionality to the corresponding disableable HTTP/gRPC methods [6](#0-5) , an operator who disables a sensitive method (for example to stop public transaction broadcast, account queries, or transaction lookups from being publicly served) has no way to actually prevent that operation once `node.jsonrpc.httpFullNodeEnable` is turned on, since it is reachable through the un-gated JSON-RPC endpoint.

### Impact Explanation
An operator who explicitly disables an API endpoint via `node.disabledApi` for security or operational reasons (e.g. to stop public nodes from processing/broadcasting transactions, or to avoid leaking account/transaction data) is silently unprotected if JSON-RPC is also enabled, because the equivalent Ethereum JSON-RPC method still serves the disabled functionality. This is "an API the node can no longer serve as intended" per the disclosed configuration, and for endpoints tied to transaction broadcast/account operations it can enable unauthorized use of functionality the operator believed was blocked.

### Likelihood Explanation
Any anonymous client that can reach the JSON-RPC HTTP port (enabled by default configuration guidance and commonly turned on for Ethereum-tooling compatibility) can trivially invoke the "disabled" functionality with a normal JSON-RPC call — no special privileges, keys, or crafted low-level requests are required, only knowledge that `node.jsonrpc` is enabled alongside a `disabledApi` entry.

### Recommendation
Add a JSON-RPC-aware access filter (mirroring `HttpApiAccessFilter`/`RpcApiAccessInterceptor`) to `FullNodeJsonRpcHttpService`, `JsonRpcServiceOnSolidity`, and the PBFT JSON-RPC service that maps JSON-RPC method names to their equivalent disableable HTTP/gRPC method names and rejects calls present in `CommonParameter.getInstance().getDisabledApiList()`, and update `reference.conf` accordingly once fixed.

### Proof of Concept
1. Configure `node.disabledApi = ["broadcasttransaction"]` and enable JSON-RPC (`node.jsonrpc.httpFullNodeEnable = true`).
2. Confirm HTTP `POST /wallet/broadcasttransaction` now returns `{"Error":"this API is unavailable due to config"}` per `HttpApiAccessFilter.isDisabled` [7](#0-6) .
3. Send the same transaction via JSON-RPC `eth_sendRawTransaction` to the `/jsonrpc` endpoint on the same node — it succeeds and is processed by `TronJsonRpcImpl`, since `JsonRpcServlet` never consults `disabledApiList` [4](#0-3) .

  private boolean isDisabled(String endpoint) {
    boolean disabled = false;

    try {
      endpoint = URI.create(endpoint).normalize().toString();
      List<String> disabledApiList = CommonParameter.getInstance().getDisabledApiList();
      if (!disabledApiList.isEmpty()) {
        disabled = disabledApiList.contains(endpoint.split("/")[2].toLowerCase(Locale.ROOT));
      }
    } catch (Exception e) {
      logger.warn("check isDisabled except, endpoint={}, {}", endpoint, e.getMessage());
    }

    return disabled;
  }

  @Override
  public <ReqT, RespT> Listener<ReqT> interceptCall(ServerCall<ReqT, RespT> call,
      Metadata headers,
      ServerCallHandler<ReqT, RespT> next) {

    String endpoint = call.getMethodDescriptor().getFullMethodName();

    try {
      if (isDisabled(endpoint)) {
        call.close(Status.UNAVAILABLE
            .withDescription("this API is unavailable due to config"), headers);
        return new ServerCall.Listener<ReqT>() {};

      } else {
        return next.startCall(call, headers);
      }
    } catch (Exception e) {
      logger.error("check rpc api access Error: {}", e.getMessage());
      return next.startCall(call, headers);
    }
  }

  @Override
  protected void doPost(HttpServletRequest req, HttpServletResponse resp) throws IOException {
    CommonParameter parameter = CommonParameter.getInstance();

    // Transport IOException from readBody propagates as HTTP 500 (genuine IO failure).
    byte[] body = readBody(req.getInputStream());
    JsonNode rootNode;
    try {
      rootNode = MAPPER.readTree(body);
      if (rootNode == null || rootNode.isMissingNode()) {
        writeJsonRpcError(resp, JsonRpcError.PARSE_ERROR, "JSON parse error", null, false);
        return;
      }
    } catch (JsonProcessingException e) {
      if (e instanceof StreamConstraintsException) {
        writeJsonRpcError(resp, JsonRpcError.PARSE_ERROR, e.getMessage(), null, false);
      } else {
        writeJsonRpcError(resp, JsonRpcError.PARSE_ERROR, "JSON parse error", null, false);
      }
      return;
    }

    if (!rootNode.isObject() && !rootNode.isArray()) {
      writeJsonRpcError(resp, JsonRpcError.INVALID_REQUEST, "Invalid Request", null, false);
      return;
    }

    boolean isBatch = rootNode.isArray();
    if (isBatch && rootNode.isEmpty()) {
      writeJsonRpcError(resp, JsonRpcError.INVALID_REQUEST, "Invalid Request", null, false);
      return;
    }
    int batchSize = parameter.getJsonRpcMaxBatchSize();
    if (isBatch && batchSize > 0 && rootNode.size() > batchSize) {
      writeJsonRpcError(resp, JsonRpcError.EXCEED_LIMIT,
          "Batch size " + rootNode.size() + " exceeds the limit of " + batchSize, null, true);
      return;
    }

    int maxResponseSize = parameter.getJsonRpcMaxResponseSize();
    if (isBatch) {
      handleBatch(resp, rootNode, maxResponseSize);
    } else {
      handleSingle(req, resp, rootNode, body, maxResponseSize);
    }
  }
