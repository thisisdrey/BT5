## Analysis

The Vibe report's core broken invariant is: **two independent minting entry points share the same explicit-ID keyspace, but neither reserves/checks against the other, so an unprivileged mint into that space permanently blocks the intended fixed-ID mint.**

The direct local analog is in `pallet-nfts`, which exposes two independent, unprivileged/semi-privileged mint entry points that write into the *same* `Item` storage keyspace keyed only by `(collection, item)`, with no reservation mechanism between them:

- `mint()` [1](#0-0)  — when a collection's `mint_settings.mint_type` is `MintType::Public` [2](#0-1) , *any signed account* may pick an arbitrary, still-unused `item` ID and mint it to any account, subject only to price/start/end checks.
- `mint_pre_signed()` [3](#0-2)  — redeems an off-chain, Issuer-signed voucher (`PreSignedMint`) that names a specific `item` ID meant for a specific future claimant [4](#0-3) .

Both funnel into `Pallet::do_mint`, whose only ID-collision guard is a bare existence check: [5](#0-4) 

This check has no concept of "reserved for a pending voucher" — it only knows whether the ID is *currently* occupied. `do_mint_pre_signed` performs no additional ID-availability pre-check of its own before delegating to `do_mint` [6](#0-5) .

### Title
Public `mint` can permanently squat an item ID promised by an unredeemed `mint_pre_signed` voucher - (File: `substrate/frame/nfts/src/features/create_delete_item.rs`)

### Summary
`pallet-nfts` allows a collection to simultaneously run `MintType::Public` open minting (via `mint`) and Issuer-authorized off-chain vouchers for specific item IDs (via `mint_pre_signed`). Both paths write into the identical `Item::<T,I>` keyspace guarded only by the `AlreadyExists` existence check in `do_mint`. There is no reservation of the IDs referenced by outstanding, unredeemed `PreSignedMint` vouchers, so any unprivileged account can call the permissionless `mint()` with the exact `item` ID a voucher promises, permanently preventing that voucher from ever being redeemed — mirroring the Vibe `NFTMintSaleMultiple`/`mintWithId` collision exactly: the sale/voucher path with a fixed ID conflicts with an independent, uncoordinated mint path over the same ID space.

### Finding Description
`mint()` lets any signed caller select an arbitrary `item` ID under `MintType::Public` [1](#0-0) , and only rejects it if that exact ID is already occupied [7](#0-6) . Separately, collection issuers hand out off-chain-signed `PreSignedMint { collection, item, ... }` vouchers naming a specific `item` ID for later redemption via `mint_pre_signed` [4](#0-3) . `do_mint_pre_signed` validates the signature, deadline, `only_account`, and Issuer role of the signer, but never checks whether the named `item` is still available before calling `do_mint`, which will simply fail with `AlreadyExists` if the slot is gone [6](#0-5) . Since collections are free to enable public minting alongside voucher-based reserved/allowlist minting for the same item-ID range, there is no code path preventing an outsider from minting into the reserved range first. This is functionally identical to the reported bug class: two independent mint mechanisms sharing one ID space with no cross-reservation, so the fixed-ID path is denied once the ID is taken elsewhere.

### Impact Explanation
Once a voucher's target `item` ID is squatted by an unrelated public mint, the voucher becomes permanently unredeemable — `mint_pre_signed` will forever return `Error::AlreadyExists` for that ID, since NFT item IDs in this pallet are never reassigned or freed for that purpose. Any off-chain payment, allowlist commitment, or metadata/traits binding tied to that specific ID by the collection issuer is permanently locked out for the intended recipient, which the impact gate captures as "permanent user-fund or bridge-state lock" / "duplicate settlement" risk (the issuer must either refund off-chain or attempt a new voucher, but the promised on-chain artifact for that ID is gone). This requires no privileged, governance, validator, or relayer role — only an ordinary signed account interacting with two standard, permissionless pallet-nfts entry points.

### Likelihood Explanation
Likelihood is high wherever a runtime/collection configures both `MintType::Public` and issues `mint_pre_signed` vouchers for the same collection (a realistic and commonly recommended pattern: public sale + allowlist/reserved vouchers). No special timing, mempool visibility, or coordination with a specific victim transaction is required — the attacker only needs the target ID (which is typically embedded in publicly shared voucher metadata/marketing) and can act any time before redemption, not just in a race against a pending transaction.

### Recommendation
Introduce an ID-reservation mechanism so IDs referenced by outstanding signed vouchers cannot be minted through any other path (e.g., track reserved IDs per collection, or restrict `MintType::Public` to a disjoint ID range/namespace from IDs distributed via `mint_pre_signed`), and have `do_mint_pre_signed` re-validate reservation state, not merely rely on the generic `AlreadyExists` check in `do_mint`.

### Proof of Concept
1. Collection owner (Issuer) configures `mint_settings.mint_type = MintType::Public` (see `mint_should_work` test toggling this) [8](#0-7) .
2. Issuer signs an off-chain `PreSignedMint { collection: 0, item: 99, only_account: Some(Alice), ... }` intended for Alice, as in `pre_signed_mints_should_work` [9](#0-8) .
3. Before Alice redeems it, attacker Bob calls `Nfts::mint(origin=Bob, collection=0, item=99, mint_to=Bob, witness=None)`, which succeeds because item `99` is currently unused and `MintType::Public` permits any caller to choose it.
4. Alice later calls `Nfts::mint_pre_signed(origin=Alice, mint_data, signature, issuer)`; `do_mint` now hits `ensure!(!Item::<T,I>::contains_key(0, 99), Error::AlreadyExists)` and reverts permanently — the voucher can never be redeemed for item `99` again.

	pub(crate) fn do_mint_pre_signed(
		mint_to: T::AccountId,
		mint_data: PreSignedMintOf<T, I>,
		signer: T::AccountId,
	) -> DispatchResult {
		let PreSignedMint {
			collection,
			item,
			attributes,
			metadata,
			deadline,
			only_account,
			mint_price,
		} = mint_data;
		let metadata = Self::construct_metadata(metadata)?;

		ensure!(
			attributes.len() <= T::MaxAttributesPerCall::get() as usize,
			Error::<T, I>::MaxAttributesLimitReached
		);
		if let Some(account) = only_account {
			ensure!(account == mint_to, Error::<T, I>::WrongOrigin);
		}

		let now = T::BlockNumberProvider::current_block_number();
		ensure!(deadline >= now, Error::<T, I>::DeadlineExpired);

		ensure!(
			Self::has_role(&collection, &signer, CollectionRole::Issuer),
			Error::<T, I>::NoPermission
		);

		let item_config = ItemConfig { settings: Self::get_default_item_settings(&collection)? };
		Self::do_mint(
			collection,
			item,
			Some(mint_to.clone()),
			mint_to.clone(),
			item_config,
			|collection_details, _| {
				if let Some(price) = mint_price {
					T::Currency::transfer(
						&mint_to,
						&collection_details.owner,
						price,
						ExistenceRequirement::KeepAlive,
					)?;
				}
				Ok(())
			},
		)?;
