This confirms the analysis. There are only two entry points that can trigger `check_cleanup`:

1. `w_execute_signed` → `execute_signed` → `self.0.nonces.commit(...)` which calls `check_cleanup()` internally, but this **requires a valid signature** verified via `S::verify_request_msg(&self.0.public_key, &msg, proof)` [1](#0-0) 
2. `w_execute_extension` → `execute_extension` which calls `self.0.nonces.check_cleanup()`, but this **requires the caller to be an already-enabled extension**, checked via `self.check_extension_enabled(&extension_id)?` against `env::predecessor_account_id()` [2](#0-1) 

An unprivileged attacker (no wallet private key, not an added extension) has **no reachable entrypoint** to trigger `check_cleanup`/rotation at all, which already defeats the premise of the question.

### No vulnerability found for this question.

Additionally, even setting aside the access-control gap, the rotation mechanism itself is safe by construction:

- `check_cleanup` rotates `current`→`old` and clears `old` purely as a function of `Timestamp::now()` versus `last_cleaned_at`, and never advances faster than real elapsed time — an attacker cannot make it happen "earlier" than the natural schedule permits, since `last_cleaned_at` is only ever set to the actual current timestamp [3](#0-2) 
- `commit` independently bounds validity via `created_at`: `now - self.timeout.min(timeout) <= created_at && created_at <= now`, so a nonce's message is only valid within at most one `wallet.timeout` window after `created_at` [4](#0-3) 
- Because `old` is only fully cleared once `last_cleaned_at` is stale by `2*timeout`, and that staleness can only reflect genuine elapsed wall-clock time (since every commit refreshes `last_cleaned_at` via `check_cleanup`), any nonce moved into `old` survives at least one full `timeout` after entering `old` — strictly longer than the message's own `created_at`-bounded validity window. So the bit can never be cleared before the corresponding request has already become independently invalid via the `created_at` check, and a bit-cleared replay is caught by the `ExpiredOrFuture` check instead [5](#0-4) 

The invariant "a nonce is discarded only after every request that could carry it has expired" holds by the dual-window design, and there is no reachable path for an unprivileged attacker to trigger rotation/cleanup in the first place.

    #[cfg(feature = "std")]
    pub fn check_cleanup(&mut self) {
        let now = Timestamp::now();
        let last_valid_nonce_at = now - self.timeout;

        // check if it's time to rotate
        if self.last_cleaned_at < last_valid_nonce_at {
            // rotate current -> old
            self.old = std::mem::take(&mut self.current);
            // check if `2 * timeout` has passed since last rotation
            if self.last_cleaned_at < last_valid_nonce_at - self.timeout {
                // cleanup old nonces
                self.old = BitMap::new(BTreeMap::new());
            }
            // update last rotation time
            self.last_cleaned_at = now;
        }
    }
