### Title
Protocol swap fee on NEP-245/IMT tokens can be bypassed by splitting a `TokenDiff` withdrawal into unit-sized legs - ([File: contracts/defuse/core/src/intents/token_diff.rs])

### Summary
`TokenDiff::token_fee` waives the protocol fee for `TokenIdType::Nep245`/`Imt` whenever the *per-intent* delta magnitude is `<= 1`. Because the fee is computed independently for every signed `TokenDiff` intent rather than on the net amount moved by a signer for a token across the whole `MultiPayload` batch, an attacker can split one N-unit transfer into N unit-sized `TokenDiff` intents (each still balanced against a matching counter-leg so the batch invariant holds) and pay zero fee instead of `protocol_fee.fee_ceil(N)`.

### Finding Description
Binding claimed to hold: `sum(fees_collected for token_id across batch) == protocol_fee.fee_ceil(N)` for a total signer outflow of `N` units of an NEP-245/IMT token.

Code path:
- `TokenDiff::execute_intent` ( [1](#0-0) ) loops over each `(token_id, delta)` pair *within a single signed `TokenDiff`* and, for negative deltas, computes `Self::token_fee(token_id, amount, protocol_fee).fee_ceil(amount)` using only that intent's own `amount = |delta|`.
- `TokenDiff::token_fee` explicitly zeroes the fee for `Nep245`/`Imt` tokens when `amount <= 1`: [2](#0-1) .
- `fee_ceil` on `Pips::ZERO` always returns `0`: [3](#0-2) .
- Batch-wide consistency is enforced only by `TransferMatcher::finalize`, which checks that deposits and withdrawals net to zero per token across the whole batch (raising `InvariantViolated::UnmatchedDeltas` otherwise): [4](#0-3) . This invariant only constrains balances, not fees — it has no knowledge of, and does not aggregate, the fee already taken per-intent.

Exploit: The signer (optionally using a second self-controlled account as the balancing counterparty, since positive deltas never pay fees per line 70 `if *delta < 0`) submits one `MultiPayload` batch containing:
- N separate signed `TokenDiff{diff: {token_id: -1}}` intents (distinct nonces, same signer), and
- one or more positive-delta `TokenDiff` intents from a counterpart account summing to `+N` for the same `token_id`, so `TransferMatcher::finalize` sees a net-zero flow and does not revert.

Each of the N unit legs computes `token_fee(token_id, 1, protocol_fee) = Pips::ZERO`, so `fees_collected` for that token is `0` for every leg, and the batch total is `0`. Had the same signer submitted a single `TokenDiff{diff: {token_id: -N}}` instead, `token_fee(token_id, N, protocol_fee)` returns `protocol_fee` (since `N > 1`), and `fee_ceil(N) >= 1` for any `protocol_fee > 0`. No existing guard (`MultiPayload::verify`, nonce/salt checks, `TransferMatcher::finalize`) inspects or aggregates per-signer/per-token fee amounts across intents in a batch, so the divergence is not caught.

### Impact Explanation
The `fee_collector` account is under-credited: it receives `0` instead of `protocol_fee.fee_ceil(N)` in NEP-245/IMT token balance that it should have custodied under the protocol's fee model. This is repeatable for any NEP-245/IMT token, any signer, and any batch size, with no upper bound on how much fee revenue can be diverted — matching the explicitly listed Critical category "protocol fees bypassed."

### Likelihood Explanation
Preconditions are trivially met by any unprivileged user: hold N units of an NEP-245/IMT token in the Verifier, and know `protocol_fee` (a public, readable `FeesConfig.fee` value) is `> 0`. The attacker only needs to sign N nonce-distinct `TokenDiff` intents themselves (or coordinate with a second self-controlled account to satisfy the zero-sum invariant) and submit them together via `execute_intents`. Cost is only the linearly larger transaction/gas size for N legs versus one; there is no other barrier or role requirement.

### Recommendation
Compute the NEP-245/IMT fee-exemption threshold on the aggregated net delta per `(signer_id, token_id)` across the whole `MultiPayload`/batch, not on the magnitude of each individual `TokenDiff` intent's delta. Alternatively, remove the `amount <= 1` special case for `Nep245`/`Imt` and apply `fee_ceil` unconditionally (with a minimum fee floor), or track cumulative unit-leg amounts per signer/token within `Deltas`/`TransferMatcher` before deciding whether the exemption applies.

### Proof of Concept
`cargo test` in `tests/src/tests/defuse/intents/token_diff.rs` (or a new sandbox test):
1. Set `protocol_fee = Pips::ONE_PERCENT` (or any `> 0`), deploy an NEP-245/IMT token, deposit `N = 10` units to `user1`, and set up `user2` as counterparty holding a balancing token/no-op deposit.
2. Case A (single leg): `user1` signs one `TokenDiff{diff: {mt_token_id: -10, other_token: <matching positive>}}`; `user2` signs the matching `+10`/`-other` counter-leg. Execute via `execute_intents`. Assert `fee_collector` balance for `mt_token_id` equals `protocol_fee.fee_ceil(10)` (`> 0`).
3. Case B (split legs): `user1` signs 10 separate `TokenDiff{diff: {mt_token_id: -1}}` intents (10 distinct nonces/payloads); `user2` signs a matching `+10` (or 10x `+1`) counter-leg(s) for the same token to satisfy `TransferMatcher::finalize`. Execute via `execute_intents` in one batch.
4. Assert `fee_collector` balance for `mt_token_id` after Case B is `0`, demonstrating `0 != protocol_fee.fee_ceil(10)` and confirming the binding fails.

    // Finalizes all transfers, or returns unmatched deltas.
    // If unmatched deltas overflow, then Err(None) is returned.
    pub fn finalize(self) -> Result<Transfers, InvariantViolated> {
        let mut transfers = Transfers::default();
        let mut deltas = TokenDeltas::default();
        for (token_id, transfer_matcher) in self.0 {
            if let Err(unmatched) = transfer_matcher.finalize_into(&token_id, &mut transfers)
                && (unmatched == 0 || deltas.apply_delta(token_id, unmatched).is_none())
            {
                return Err(InvariantViolated::Overflow);
            }
        }
        if !deltas.is_empty() {
            return Err(InvariantViolated::UnmatchedDeltas {
                unmatched_deltas: deltas,
            });
        }
        Ok(transfers)
    }
