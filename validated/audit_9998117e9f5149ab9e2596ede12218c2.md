## Finding

### Title
Front-running `handle_bankruptcy()` allows depositors to dodge socialized bad-debt losses - ([File: programs/marginfi/src/instructions/marginfi_group/handle_bankruptcy.rs])

### Summary
`lending_pool_handle_bankruptcy` atomically and unpredictably slashes `asset_share_value` for every depositor in a bank via `Bank::socialize_loss()` once a bankrupt account's uncovered bad debt exceeds the insurance fund. Because the loss is applied instantly and in full at the moment the instruction lands, any depositor who observes (or anticipates) an incoming bankruptcy settlement can race it with a plain withdrawal and fully escape their pro-rata share of the loss, shifting a larger haircut onto the remaining depositors — the same "sudden, unpredictable, atomic loss socialization" bug class described in the referenced report for `unlockDeposit()`.

### Finding Description
When a marginfi account is bankrupt, `lending_pool_handle_bankruptcy` computes `bad_debt`, covers as much as possible from the insurance vault, and then calls `bank.socialize_loss(socialized_loss)` to cover the remainder: [1](#0-0) 

`socialize_loss` immediately reduces `asset_share_value` (dividing the total remaining value by `total_asset_shares`) for the *entire* bank in a single atomic step: [2](#0-1) 

The `BANKRUPTCY.md` guide confirms this is intentional design: any depositor still holding shares when the instruction executes "eats" the haircut: [3](#0-2) 

Because `lending_account_withdraw` is a normal, unprivileged, permissionless user action that simply debits `asset_shares` at the *current* (pre-bankruptcy) `asset_share_value`: [4](#0-3) 

a depositor who can predict or observe that `handle_bankruptcy` is about to fire (e.g. after watching a large liquidation drain a borrower's collateral, or after `handle_bankruptcy` is submitted but not yet landed) can submit a withdraw with a higher priority fee (or via Jito bundle ordering) to land first, cash out at the pre-haircut share value, and completely avoid the loss that `socialize_loss` would otherwise have applied to their shares. Every unit of value they extract this way increases the deficit that must be spread across the depositors who remain, since `total_asset_shares` shrinks by the escaping shares while `loss_amount` (the unpaid bad debt) stays fixed. Notably, when `PERMISSIONLESS_BAD_DEBT_SETTLEMENT_FLAG` is set on a bank, `handle_bankruptcy` itself can be triggered by any unprivileged signer, making the entire race (both the withdrawal escape and the triggering of settlement) achievable without any privileged access.

### Impact Explanation
This does not require corrupting the accounting itself; instead it lets an unprivileged actor unilaterally shift bad debt away from themselves and onto remaining, unaware depositors — the remaining lenders in the bank end up absorbing a strictly larger haircut than their fair pro-rata share, directly worsening insolvency exposure for those who did not (or could not) race the transaction. This matches the "insolvency/bad debt" impact category: the loss borne by the bank's remaining depositors is provably higher than it should be, and value is transferred away from them to the front-runner.

### Likelihood Explanation
Likelihood is Medium: it requires (1) an observer monitoring bankrupt accounts/liquidations in the target bank and (2) the ability to land a withdraw transaction ahead of or in the same window as `handle_bankruptcy`. Given `handle_bankruptcy` can be permissionlessly triggered on flagged banks, and bankruptcy events are visible on-chain once liquidation has zeroed a borrower's collateral (before anyone actually calls `handle_bankruptcy`), a motivated depositor watching the bank has a window to react and withdraw before the socialization lands, similar to how the original report's attacker could front-run `unlockDeposit()`.

### Recommendation
Avoid instantaneous full-loss application in a single atomic step triggered by a third party. Options include: (1) socializing the loss gradually (e.g., accruing it over subsequent `accrue_interest` calls rather than a single share-value cut), or (2) snapshotting/quarantining the affected bank's liquidity (briefly pausing new withdrawals) once an account is confirmed bankrupt and before `handle_bankruptcy` settles, so depositors cannot exit at the stale, pre-loss share price.

### Proof of Concept
1. Borrower B in Bank X becomes bankrupt (assets nulled via price crash/liquidation) — this state is observable on-chain by inspecting the account and bank health.
2. Depositor D, a normal lender in Bank X, sees the bankrupt account and knows/anticipates `lending_pool_handle_bankruptcy` will be called soon (whether by admin, risk admin, or — if `PERMISSIONLESS_BAD_DEBT_SETTLEMENT_FLAG` is set — by anyone, including D themselves after front-running).
3. D submits `lending_account_withdraw` for their full deposit with an elevated priority fee to land before the bankruptcy-settlement transaction.
4. D's withdrawal executes at the current (pre-haircut) `asset_share_value`, fully redeeming their shares.
5. `lending_pool_handle_bankruptcy` then executes `socialize_loss`, dividing the same absolute bad debt across a now-smaller `total_asset_shares` (D's shares removed), producing a lower `new_share_value` for all remaining depositors than would have resulted had D's shares still been present — i.e., remaining depositors bear a strictly larger loss than their fair share, and D bears none.

    fn socialize_loss(&mut self, loss_amount: I80F48) -> MarginfiResult<bool> {
        let mut kill_bank = false;
        let total_asset_shares: I80F48 = self.total_asset_shares.into();
        let old_asset_share_value: I80F48 = self.asset_share_value.into();

        // Compute total "old" value of shares
        let total_value: I80F48 = total_asset_shares
            .checked_mul(old_asset_share_value)
            .ok_or_else(math_error!())?;

        // Subtract loss, clamping at zero (i.e. assets < liabilities, the bank is wiped out)
        if total_value <= loss_amount {
            self.asset_share_value = I80F48::ZERO.into();
            // This state is irrecoverable, the bank is dead.
            kill_bank = true;
        } else {
            // otherwise subtract then redistribute
            let new_share_value: I80F48 = (total_value - loss_amount)
                .checked_div(total_asset_shares)
                .ok_or_else(math_error!())?;
            self.asset_share_value = new_share_value.into();
            // Sanity check: should be unreachable.
            if new_share_value == I80F48::ZERO {
                kill_bank = true;
            }
        }

        Ok(kill_bank)
    }

* If bank's insurance fund > liabilities, then the insurance fund is used to repay the user's liability.
* If the bank's insurance fund is not sufficient, the remainder will be covered by taking liquidity
  out of the bank, reducing the asset share value. This socializes the loss to all remaining
  depositors.
* If the bank's insurance fund and liquidity are not sufficient (super-bankruptcy), the bank is
  killed. The asset share value is set to zero, wiping out all holdings for all other depositors.
