This confirms the vulnerability: the sample config explicitly binds this signer's event endpoint to `0.0.0.0:30000` (all interfaces), meaning it is reachable from the network, not just localhost.

The `auth_password`/`auth_token` mechanism referenced in the docs only authenticates the **signer→node** RPC/StackerDB direction; it does not gate the **node→signer** event-receiver HTTP server at all — there's no auth check anywhere in `next_event()` before dispatching on `request.url()`.

### Title
Unauthenticated `/shutdown` HTTP endpoint permanently halts signer event loop - (`libsigner/src/events.rs`)

### Summary
`SignerEventReceiver::next_event` in `libsigner/src/events.rs` handles a plain `POST /shutdown` request by unconditionally setting `stop_signal` and returning `EventError::Terminated`, with no signature, token, or peer-identity check of any kind. Since `main_loop` treats `EventError::Terminated` as a clean exit and breaks, any remote party that can reach the signer's event-receiver port (which sample configs bind to `0.0.0.0`) can permanently kill the signer's event loop with a single crafted TCP/HTTP request.

### Finding Description
The claimed equality/fault holds: the shutdown control-plane action (`event_receiver.stop_signal.store(true, Ordering::SeqCst); Err(EventError::Terminated)`) is taken purely based on `request.url() == "/shutdown"` and `request.method() == Post`, with no check that the request originated from the trusted stacks-node's event dispatcher. [1](#0-0)  There is no `auth_password`/token comparison, no source-IP allowlist, and no signature verification anywhere in `next_event()` before this branch is reached — the same handler also processes `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, and `/new_block` without any auth gate. [2](#0-1) 

`main_loop`, which drives the receiver in its own thread, treats `Err(EventError::Terminated)` as a normal termination signal and `break`s out, ending the loop for good. [3](#0-2)  This is precisely the mechanism the legitimate `SignerStopSignaler::send()` uses internally — it also just POSTs `/shutdown` over a plain `TcpStream` to `local_addr` with no credentials. [4](#0-3)  The attacker only needs to reproduce that exact same unauthenticated HTTP request.

The `endpoint` this server binds to is configured by the operator and the shipped sample config explicitly sets it to `0.0.0.0:30000` (all interfaces), confirming this is intended to be a listening network service, not merely loopback-only. [5](#0-4)  The `auth_password`/`auth_token` pair documented for signer↔node coordination only protects the signer's outbound RPC calls to the node's block-proposal endpoint; it is never checked by this inbound event-receiver HTTP server.

### Impact Explanation
A single unauthenticated `POST /shutdown` HTTP request permanently terminates the signer's event-receiver thread, which stops `main_loop` and the ability to forward `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, and `/new_block` events into the signer run loop via `forward_event` [6](#0-5) . This effectively takes the signer offline from block-validation/signing participation until manually restarted — a Critical unauthenticated DoS achievable with one message, matching the rules' "Critical - remote crash/unauthenticated DoS from few messages" category.

### Likelihood Explanation
No preconditions beyond network reachability to the configured signer `endpoint` port; the sample/production config binds it to `0.0.0.0`. [5](#0-4)  The attacker needs no RPC secret, StackerDB slot, or peer key — just the ability to open a TCP connection and send bytes, which matches the assumed unprivileged attacker capability. The attack is repeatable trivially (though after the first success the server is already down) and costs one HTTP request.

### Recommendation
Require authentication on the event-receiver HTTP server, at minimum a shared-secret header/token (reusing or introducing an `auth_password`-equivalent check) compared before acting on `/shutdown` (and ideally all other event endpoints too), or bind the receiver to loopback only by default and document/enforce that it must not be exposed on `0.0.0.0` in production, and/or replace the HTTP-based stop signal with a local-only IPC mechanism (e.g., a Unix domain socket, or an in-process channel) that isn't reachable over the network at all.

    /// Return true on success; false on error.
    /// Returning false terminates the event receiver.
    fn forward_event(&mut self, ev: SignerEvent<T>) -> bool {
        if self.out_channels.is_empty() {
            // nothing to do
            error!("No channels connected to event receiver");
            false
        } else if self.out_channels.len() == 1 {
            // avoid a clone
            if let Err(e) = self.out_channels[0].send(ev) {
                error!("Failed to send to signer runloop: {:?}", &e);
                return false;
            }
            true
        } else {
            for (i, out_channel) in self.out_channels.iter().enumerate() {
                if let Err(e) = out_channel.send(ev.clone()) {
                    error!("Failed to send to signer runloop #{}: {:?}", i, &e);
                    return false;
                }
            }
            true
        }
    }
