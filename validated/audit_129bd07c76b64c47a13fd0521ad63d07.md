### Title
Bridging to `address(0)` is accepted by `ProxyOFT.sendFrom`, but can never be delivered - (`contracts/ProxyOFT.sol`)

### Summary
`ProxyOFT.sendFrom` accepts an unrestricted destination address, including `address(0)`. The source-chain transfer burns the sender’s synthetic tokens before emitting the LayerZero message, while the destination path ultimately calls `SyntheticToken._mint`, which rejects the zero address. The failed message is stored under its immutable payload hash, so the public retry path can only replay the same permanently reverting payload.

### Finding Description
The user-facing `ProxyOFT.sendFrom(address,uint16,address,uint256)` encodes `to_` directly into `_toAddress` without checking `to_ != address(0)` [1](#0-0) . `_send` debits the sender before sending the cross-chain payload [2](#0-1) .

The debit path validates sender ownership, bridging status, and destination-chain support, then burns the synthetic token [3](#0-2) . No validation rejects a zero destination before the burn.

On receipt, `_sendAck` decodes the recipient and calls `_creditTo` [4](#0-3) . `ProxyOFT._creditTo` forwards that recipient directly to `SyntheticToken.mint` [5](#0-4) , while `_mint` explicitly rejects `address(0)` [6](#0-5) .

Because delivery is wrapped by the nonblocking receiver, the failed packet is stored as `keccak256(_payload)` [7](#0-6) . `retryMessage` requires the identical payload and executes it again, so it can never change the zero recipient and will always revert [8](#0-7) .

### Impact Explanation
The user’s tokens are burned on the source chain, but the corresponding mint on the destination chain cannot succeed. This produces a permanent loss of the bridged amount and consumes the failed-message slot with an unrecoverable payload.

The strongest impacted flow is a user or integration calling the exposed `sendFrom`/`sendFrom` overload with `to_ = address(0)` or otherwise forwarding an unchecked recipient. No privileged role is required to initiate the transfer; the sender only needs to own the amount being bridged.

### Likelihood Explanation
The recipient parameter is fully user-controlled. `sendFrom` validates the spender, bridge pause state, and supported destination chain, but not the recipient. Integrations can also expose the inherited raw LayerZero `sendFrom` interface, which accepts arbitrary `_toAddress` bytes [9](#0-8) .

The issue does not let an attacker burn another user’s tokens: `_debitFrom` requires `_msgSender() == from_` [10](#0-9) . Likelihood is therefore limited to mistaken or unsafe callers/integrations, but once initiated the loss is deterministic and unrecoverable.

### Recommendation
Reject invalid recipients before debiting or burning the synthetic token.

At minimum, in `ProxyOFT.sendFrom` and/or `_debitFrom`, decode or receive the destination as `address` and enforce:

```solidity
if (to_ == address(0)) revert AddressIsNull();
```

For the inherited raw `sendFrom` path, validate that `_toAddress` decodes to a non-zero address before `_debitFrom` is executed. Consider rejecting protocol-controlled destination contracts as well if they are not intended recipients.

### Proof of Concept
A Foundry fork test can demonstrate the stuck packet without requiring a malicious privileged actor:

```solidity
uint16 constant SRC_CHAIN = /* source LZ chain id */;
uint16 constant DST_CHAIN = /* destination LZ chain id */;
uint16 constant PT_SEND = 0;

// Source chain fork.
ProxyOFT srcOft = ProxyOFT(sourceProxyOft);
SyntheticToken srcToken = srcOft.syntheticToken();
address user = /* holder */;

uint256 amount = 100 ether;
uint256 beforeBalance = srcToken.balanceOf(user);

vm.prank(user);
srcOft.sendFrom{value: nativeFee}(
    user,
    DST_CHAIN,
    address(0),
    amount
);

assertEq(srcToken.balanceOf(user), beforeBalance - amount);

// Destination chain fork.
ProxyOFT dstOft = ProxyOFT(destinationProxyOft);
address endpoint = address(dstOft.lzEndpoint());

bytes memory payload = abi.encode(
    PT_SEND,
    abi.encodePacked(address(0)),
    amount
);

bytes memory sourceRemote = abi.encodePacked(sourceProxyOft);

// Simulate the configured endpoint delivering the exact packet.
vm.prank(endpoint);
dstOft.lzReceive(SRC_CHAIN, sourceRemote, nonce, payload);

// The message is stored, but retrying the immutable payload always reverts.
vm.expectRevert(SyntheticToken.MintToTheZeroAddress.selector);
dstOft.retryMessage(SRC_CHAIN, sourceRemote, nonce, payload);
```

The source burn succeeds at `contracts/ProxyOFT.sol:81`, while every destination delivery attempt reaches the zero-address rejection at `contracts/SyntheticToken.sol:334`, leaving no way to recover the bridged amount.

```text
    function retryMessage(uint16 _srcChainId, bytes calldata _srcAddress, uint64 _nonce, bytes calldata _payload) public payable virtual {
        // assert there is message to retry
        bytes32 payloadHash = failedMessages[_srcChainId][_srcAddress][_nonce];
        require(payloadHash != bytes32(0), "NonblockingLzApp: no stored message");
        require(keccak256(_payload) == payloadHash, "NonblockingLzApp: invalid payload");
        // clear the stored message
        failedMessages[_srcChainId][_srcAddress][_nonce] = bytes32(0);
        // execute the message. revert if it fails again
        _nonblockingLzReceive(_srcChainId, _srcAddress, _nonce, _payload);
        emit RetryMessageSuccess(_srcChainId, _srcAddress, _nonce, payloadHash);
```
