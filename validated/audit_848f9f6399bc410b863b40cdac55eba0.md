### Title
Unprivileged Forced Migration of Arbitrary Accounts' `CoinStore` to `FungibleStore` Without Owner Consent — (`aptos-move/framework/aptos-framework/sources/coin.move`)

---

### Summary

`migrate_coin_store_to_fungible_store<CoinType>` is a `public entry fun` that accepts only a `vector<address>` — no signer — allowing any unprivileged caller to irreversibly migrate the `CoinStore` of arbitrary victim accounts to a primary `FungibleStore`, destroy their legacy event handles, and silently overwrite the frozen flag of their FA store, all without the account owner's knowledge or consent.

---

### Finding Description

`coin.move` exposes two migration entry points side by side:

```move
// Voluntary — requires the account's own signer
public entry fun migrate_to_fungible_store<CoinType>(
    account: &signer
) acquires CoinStore, CoinConversionMap, CoinInfo {
    let account_addr = signer::address_of(account);
    maybe_convert_to_fungible_store<CoinType>(account_addr);
}

// Batch — NO signer, any caller, any addresses
public entry fun migrate_coin_store_to_fungible_store<CoinType>(
    accounts: vector<address>
) acquires CoinStore, CoinConversionMap, CoinInfo {
    accounts.for_each(|account| {
        maybe_convert_to_fungible_store<CoinType>(account);
    });
}
``` [1](#0-0) 

The first function correctly gates on `&signer`. The second function has **no authorization check whatsoever** — no signer, no capability, no owner assertion. Any account on mainnet can submit a transaction calling `0x1::coin::migrate_coin_store_to_fungible_store<T>` with an arbitrary list of victim addresses.

`maybe_convert_to_fungible_store` performs the following irreversible state mutations on each victim:

1. **Destroys the `CoinStore<CoinType>` resource** via `move_from<CoinStore<CoinType>>(account)` — permanent, cannot be re-created.
2. **Creates a primary `FungibleStore`** for the victim if one does not already exist.
3. **Moves the coin balance** into the FA store via `unchecked_deposit_with_no_events`.
4. **Overwrites the FA store's frozen flag** to match the CoinStore's frozen flag: `if (frozen != fungible_asset::is_frozen(store)) { fungible_asset::set_frozen_flag_internal(store, frozen); }` — this can freeze or unfreeze the victim's primary FA store.
5. **Destroys the victim's legacy deposit and withdraw event handles** permanently. [2](#0-1) 

The frozen-flag overwrite path calls `set_frozen_flag_internal`, which directly mutates `FungibleStore.frozen` without any capability check: [3](#0-2) 

---

### Impact Explanation

**Unauthorized state modification of user-controlled on-chain assets:**

- **Irreversible CoinStore destruction**: The victim's `CoinStore` is permanently removed. Any application, wallet, or protocol that reads or writes `CoinStore<CoinType>` for the victim will find it gone.

- **Frozen-flag overwrite — freeze path**: If a victim holds a frozen `CoinStore` (frozen=true) alongside an unfrozen primary FA store (frozen=false), the attacker triggers migration and the FA store becomes frozen. The victim can no longer send or receive the asset through the FA interface. For APT, this means the victim cannot pay gas fees or transfer APT via the FA path. The code comment at line 707–711 explicitly acknowledges this side-effect as intentional for the voluntary case, but it becomes an attack vector when triggered by a third party.

- **Frozen-flag overwrite — unfreeze path**: Conversely, if the victim's primary FA store has been frozen (e.g., by the coin issuer via `TransferRef`) while the CoinStore remains unfrozen, the attacker triggers migration and the FA store is unfrozen — bypassing the issuer's freeze.

- **Event handle destruction**: The victim's legacy deposit/withdraw event handles are permanently destroyed, breaking any off-chain monitoring or protocol integration that relies on them. [4](#0-3) 

---

### Likelihood Explanation

- The entry function is `public` and callable by any account with no preconditions beyond gas.
- The SDK builder already exposes `coin_migrate_coin_store_to_fungible_store` as a first-class transaction builder, making it trivially scriptable.
- The only precondition for the frozen-flag impact is that the victim has both a `CoinStore` and a primary FA store with mismatched frozen flags — a realistic state during the ongoing coin-to-FA migration period on mainnet.
- The attacker pays only gas; there is no economic barrier. [5](#0-4) 

---

### Recommendation

Add an authorization check so that only the account owner can trigger migration for their own account. The simplest fix mirrors the existing `migrate_to_fungible_store` pattern:

```move
// Option A: require each account to sign (breaks batch semantics)
public entry fun migrate_coin_store_to_fungible_store<CoinType>(
    account: &signer
) acquires CoinStore, CoinConversionMap, CoinInfo {
    maybe_convert_to_fungible_store<CoinType>(signer::address_of(account));
}

// Option B: keep batch but assert caller == each target address,
// or restrict to a privileged framework signer
public entry fun migrate_coin_store_to_fungible_store<CoinType>(
    aptos_framework: &signer,
    accounts: vector<address>
) acquires CoinStore, CoinConversionMap, CoinInfo {
    system_addresses::assert_aptos_framework(aptos_framework);
    accounts.for_each(|account| {
        maybe_convert_to_fungible_store<CoinType>(account);
    });
}
```

### Proof of Concept

**Attacker preconditions**: Any funded mainnet account. No special keys or capabilities required.

**Victim preconditions**: Victim holds `CoinStore<AptosCoin>` (frozen=true, e.g., previously frozen by framework) and a primary APT FA store (frozen=false).

**Attack steps**:

1. Attacker constructs a transaction:
   ```
   function: 0x1::coin::migrate_coin_store_to_fungible_store
   type_args: [0x1::aptos_coin::AptosCoin]
   args: [[victim_address_1, victim_address_2, ...]]
   ```

2. Attacker submits via `POST /transactions` (BCS or JSON).

3. On execution, for each victim:
   - `CoinStore<AptosCoin>` is destroyed (`move_from`)
   - Primary FA store is created/fetched
   - APT balance is moved to FA store
   - `set_frozen_flag_internal(store, true)` is called — victim's primary APT FA store is now frozen
   - Deposit/withdraw event handles are destroyed

4. **Result**: Victim's primary APT FA store is permanently frozen. Victim cannot transfer APT or pay gas through the FA interface. The `CoinStore` is gone and cannot be restored. [5](#0-4) [2](#0-1)

    fun maybe_convert_to_fungible_store<CoinType>(
        account: address
    ) acquires CoinStore, CoinConversionMap, CoinInfo {
        if (exists<CoinStore<CoinType>>(account)) {
            let CoinStore<CoinType> { coin, frozen, deposit_events, withdraw_events } =
                move_from<CoinStore<CoinType>>(account);
            if (is_coin_initialized<CoinType>() && coin.value > 0) {
                let metadata = ensure_paired_metadata<CoinType>();
                let store =
                    primary_fungible_store::ensure_primary_store_exists(
                        account, metadata
                    );

                event::emit(
                    CoinStoreDeletion {
                        coin_type: type_info::type_name<CoinType>(),
                        event_handle_creation_address: guid::creator_address(
                            event::guid(&deposit_events)
                        ),
                        deleted_deposit_event_handle_creation_number: guid::creation_num(
                            event::guid(&deposit_events)
                        ),
                        deleted_withdraw_event_handle_creation_number: guid::creation_num(
                            event::guid(&withdraw_events)
                        )
                    }
                );

                if (coin.value == 0) {
                    destroy_zero(coin);
                } else {
                    fungible_asset::unchecked_deposit_with_no_events(
                        store.object_address(),
                        coin_to_fungible_asset(coin)
                    );
                };

                // Note:
                // It is possible the primary fungible store may already exist before this function call.
                // In this case, if the account owns a frozen CoinStore and an unfrozen primary fungible store, this
                // function would convert and deposit the rest coin into the primary store and freeze it to make the
                // `frozen` semantic as consistent as possible.
                if (frozen != fungible_asset::is_frozen(store)) {
                    fungible_asset::set_frozen_flag_internal(store, frozen);
                }
            } else {
                destroy_zero(coin);
            };
            event::destroy_handle(deposit_events);
            event::destroy_handle(withdraw_events);
        };
    }
