### Title
DPoS voter reward index (Vi) is snapshotted using end-of-cycle vote weight, letting a last-block voter capture a full cycle's already-accrued SR reward pool - ([File: consensus/src/main/java/org/tron/consensus/dpos/MaintenanceManager.java])

### Summary
The reward-sharing mechanism for SR voters accrues block/transaction-fee rewards into a per-cycle pool (`delegationStore.addReward`) continuously as blocks are produced, but only "settles" that pool into a per-witness value-index (`Vi`) once, at the maintenance boundary, using whatever vote weight exists *at that instant*. Any voter — including one who only cast a vote in the last block of the cycle — is credited a full share of the entire cycle's accumulated reward once the boundary is crossed, exactly the "credit assets that haven't been proportionally earned yet" pattern described in the external report (deposit right before the harvest event, then withdraw disproportionate share of pending value).

### Finding Description
Rewards for a super representative are accumulated block-by-block for the *current* cycle via `MortgageService.payReward` → `delegationStore.addReward(cycle, witnessAddress, value)` [1](#0-0) .

This accumulated, not-yet-distributed reward pool is only converted into a per-voter claim once per cycle, in `MaintenanceManager.doMaintenance()`, which calls `delegationStore.accumulateWitnessVi(curCycle, witness.createDbKey(), witness.getVoteCount())` using the witness's `getVoteCount()` *as it stands at the maintenance boundary* — after all votes cast throughout the entire cycle have already been merged in: [2](#0-1) 

The `Vi` accumulation itself divides the whole cycle's reward by that single end-of-cycle vote count and adds the delta to every voter's index, uniformly for the whole cycle: [3](#0-2) 

A voter's claimable reward for a cycle range is computed purely from the delta of `Vi` between `beginCycle-1` and `endCycle-1` multiplied by the voter's vote count — with no weighting by *when* within the cycle the vote was cast: [4](#0-3) 

Critically, `VoteWitnessActuator`/`VoteWitnessProcessor` apply a vote change immediately in the same block it is submitted, with no lock-up or minimum holding period before the vote counts for `Vi` purposes — the new vote is merged into `VotesCapsule.newVotes` and taken into account by `countVote()` at the very next maintenance: [5](#0-4) [6](#0-5) 

Because TRON already requires TRX to be frozen to obtain "tron power," an attacker who holds (or briefly acquires) frozen balance can send a `VoteWitnessContract` transaction in the final block before a maintenance cycle boundary, redirecting votes toward a witness that has accumulated a large unclaimed reward pool for that cycle. At the boundary, `accumulateWitnessVi` divides that pool by the *new* total vote count (which now includes the attacker's freshly-added votes) and credits the delta uniformly to every voter, including the attacker, for the *entire* cycle — even though the attacker's vote was economically present for only a fraction of a block. The attacker can then immediately redirect votes elsewhere (or unfreeze after the standard freeze period) having captured reward that honest long-term voters otherwise would have received a larger proportional share of.

### Impact Explanation
This dilutes genuine SR voters' rewards and lets an attacker with capital extract value from a reward pool they did not proportionally contribute vote weight toward for the duration it accrued — a concrete theft/unbacked-distribution of funds from other voters via the on-chain, unprivileged `VoteWitnessContract` path (also reachable through the TVM `vote`/native contract path in `VoteWitnessProcessor`). This matches "unauthorized account operation / theft of funds" criteria.

### Likelihood Explanation
Likelihood is high for any account that already holds frozen TRX (tron power) and is timing votes around the publicly known, deterministic maintenance interval (`consensusDelegate.getNextMaintenanceTime()`), which is a fixed, predictable schedule. No special privileges are required — this is reachable by any ordinary account via a single `VoteWitnessContract` transaction (or TVM `vote()` call). The reward is proportionally larger for witnesses/cycles with larger unclaimed pools and lower existing vote counts, consistent with the report's emphasis that impact scales with unclaimed-reward size and deposit size.

### Recommendation
Time-weight `Vi` accumulation (or vote credit) within a cycle so that a voter's share of a cycle's reward reflects the duration/weight that vote was actually in effect during the cycle, rather than snapshotting only the vote count present at the maintenance boundary. Alternatively, apply new votes only starting from the *next* cycle (delay their effect on `Vi` accrual) so that a vote cast mid- or late-cycle cannot retroactively claim reward accrued before it existed.

### Proof of Concept
1. Attacker freezes TRX ahead of time to obtain tron power (a normal, permissionless operation via `FreezeBalanceV2Actuator`/`FreezeBalanceActuator`).
2. Attacker observes (via public chain state) that SR `W` has accumulated a large `delegationStore.getReward(currentCycle, W)` pool as the cycle nears `consensusDelegate.getNextMaintenanceTime()`.
3. In the last block(s) of the cycle, attacker submits `VoteWitnessContract` (or calls TVM `vote()`) directing large vote weight to `W`; this is applied immediately in `VoteWitnessActuator.countVoteAccount` / `VoteWitnessProcessor.execute`.
4. At the maintenance boundary, `MaintenanceManager.doMaintenance()` calls `accumulateWitnessVi(curCycle, W, witness.getVoteCount())` — where `witness.getVoteCount()` now includes the attacker's newly added votes — dividing the entire cycle's reward pool by this new total and crediting delta-`Vi` to all voters including the attacker for the whole cycle.
5. Attacker calls `withdrawReward`/`WithdrawBalanceActuator` (or TVM `withdrawReward()`) to claim the `allowance` credited via `MortgageService.computeReward`, receiving a share of a reward pool that accrued almost entirely before the attacker's vote existed.
6. Attacker can then redirect votes away from `W` in the next cycle, repeating the strategy against other witnesses with large pending pools.

  private void payReward(byte[] witnessAddress, long value) {
    long cycle = dynamicPropertiesStore.getCurrentCycleNumber();
    int brokerage = delegationStore.getBrokerage(cycle, witnessAddress);
    double brokerageRate = (double) brokerage / 100;
    long brokerageAmount = (long) (brokerageRate * value);
    value -= brokerageAmount;
    delegationStore.addReward(cycle, witnessAddress, value);
    adjustAllowance(witnessAddress, brokerageAmount);
  }

  private long computeReward(long beginCycle, long endCycle, AccountCapsule accountCapsule) {
    if (beginCycle >= endCycle) {
      return 0;
    }

    long reward = 0;
    long newAlgorithmCycle = dynamicPropertiesStore.getNewRewardAlgorithmEffectiveCycle();
    List<Pair<byte[], Long>> srAddresses = accountCapsule.getVotesList().stream()
        .map(vote -> new Pair<>(vote.getVoteAddress().toByteArray(), vote.getVoteCount()))
        .collect(Collectors.toList());
    if (beginCycle < newAlgorithmCycle) {
      long oldEndCycle = min(endCycle, newAlgorithmCycle,
          dynamicPropertiesStore.disableJavaLangMath());
      reward = getOldReward(beginCycle, oldEndCycle, srAddresses);
      beginCycle = oldEndCycle;
    }
    if (beginCycle < endCycle) {
      for (Pair<byte[], Long>  vote : srAddresses) {
        byte[] srAddress = vote.getKey();
        BigInteger beginVi = delegationStore.getWitnessVi(beginCycle - 1, srAddress);
        BigInteger endVi = delegationStore.getWitnessVi(endCycle - 1, srAddress);
        BigInteger deltaVi = endVi.subtract(beginVi);
        if (deltaVi.signum() <= 0) {
          continue;
        }
        long userVote = vote.getValue();
        reward += deltaVi.multiply(BigInteger.valueOf(userVote))
            .divide(DelegationStore.DECIMAL_OF_VI_REWARD).longValue();
      }
    }
    return reward;
  }

  private Map<ByteString, Long> countVote(VotesStore votesStore) {
    final Map<ByteString, Long> countWitness = Maps.newHashMap();
    Iterator<Entry<byte[], VotesCapsule>> dbIterator = votesStore.iterator();
    long sizeCount = 0;
    while (dbIterator.hasNext()) {
      Entry<byte[], VotesCapsule> next = dbIterator.next();
      VotesCapsule votes = next.getValue();
      votes.getOldVotes().forEach(vote -> {
        ByteString voteAddress = vote.getVoteAddress();
        long voteCount = vote.getVoteCount();
        if (countWitness.containsKey(voteAddress)) {
          countWitness.put(voteAddress, countWitness.get(voteAddress) - voteCount);
        } else {
          countWitness.put(voteAddress, -voteCount);
        }
      });
      votes.getNewVotes().forEach(vote -> {
        ByteString voteAddress = vote.getVoteAddress();
        long voteCount = vote.getVoteCount();
        if (countWitness.containsKey(voteAddress)) {
          countWitness.put(voteAddress, countWitness.get(voteAddress) + voteCount);
        } else {
          countWitness.put(voteAddress, voteCount);
        }
      });
      sizeCount++;
      votesStore.delete(next.getKey());
    }
    logger.info("There is {} new votes in this epoch", sizeCount);
    return countWitness;
  }

  public void accumulateWitnessVi(long cycle, byte[] address, long voteCount) {
    BigInteger preVi = getWitnessVi(cycle - 1, address);
    long reward = getReward(cycle, address);
    if (reward == 0 || voteCount == 0) { // Just forward pre vi
      if (!BigInteger.ZERO.equals(preVi)) { // Zero vi will not be record
        setWitnessVi(cycle, address, preVi);
      }
    } else { // Accumulate delta vi
      BigInteger deltaVi = BigInteger.valueOf(reward)
          .multiply(DECIMAL_OF_VI_REWARD)
          .divide(BigInteger.valueOf(voteCount));
      setWitnessVi(cycle, address, preVi.add(deltaVi));
    }
  }

  private void countVoteAccount(VoteWitnessContract voteContract) {
    AccountStore accountStore = chainBaseManager.getAccountStore();
    VotesStore votesStore = chainBaseManager.getVotesStore();
    MortgageService mortgageService = chainBaseManager.getMortgageService();
    byte[] ownerAddress = voteContract.getOwnerAddress().toByteArray();

    VotesCapsule votesCapsule;

    //
    mortgageService.withdrawReward(ownerAddress);

    AccountCapsule accountCapsule = accountStore.get(ownerAddress);

    DynamicPropertiesStore dynamicStore = chainBaseManager.getDynamicPropertiesStore();
    if (dynamicStore.supportAllowNewResourceModel()
        && accountCapsule.oldTronPowerIsNotInitialized()) {
      accountCapsule.initializeOldTronPower();
    }

    if (!votesStore.has(ownerAddress)) {
      votesCapsule = new VotesCapsule(voteContract.getOwnerAddress(),
          accountCapsule.getVotesList());
    } else {
      votesCapsule = votesStore.get(ownerAddress);
    }

    accountCapsule.clearVotes();
    votesCapsule.clearNewVotes();

    voteContract.getVotesList().forEach(vote -> {
      logger.debug("countVoteAccount, address[{}]",
          ByteArray.toHexString(vote.getVoteAddress().toByteArray()));

      votesCapsule.addNewVotes(vote.getVoteAddress(), vote.getVoteCount());
      accountCapsule.addVotes(vote.getVoteAddress(), vote.getVoteCount());
    });

    accountStore.put(accountCapsule.createDbKey(), accountCapsule);
    votesStore.put(ownerAddress, votesCapsule);
  }
