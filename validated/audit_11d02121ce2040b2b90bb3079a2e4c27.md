### Title
Firewall conntrack fast-path grants indefinite passage without re-validating the peer's current certificate identity - (File: `firewall.go`)

### Summary
`Firewall.inConns` caches a per-flow authorization decision in `FirewallConntrack.Conns`, keyed only by the 4-tuple (`firewall.Packet`: local/remote addr, local/remote port, protocol). The decision to allow the flow is re-validated against the peer's *current* certificate (`h.ConnectionState.peerCert`) only when the firewall's `rulesVersion` counter has changed (i.e., on a config reload). If the peer's certificate identity changes for any other reason — most notably a rehandshake that installs a new `ConnectionState`/`peerCert` on the same `HostInfo`/vpn address — the stale conntrack entry keeps passing traffic with no re-check against the new identity, exactly mirroring the reported bug class: a permission decision is made once against a point-in-time identity snapshot and never re-verified after that identity changes.

### Finding Description
`Firewall.Drop` checks `f.inConns(fp, h, caPool, localCache)` before ever consulting the rule table on the fast path: [1](#0-0) 

`inConns` looks up the conntrack entry by the 4-tuple only. If `c.rulesVersion == f.rulesVersion` it returns `true` immediately — it does **not** call `table.match` again, meaning `h.ConnectionState.peerCert` is not consulted at all on this common path: [2](#0-1) 

The conn record itself stores no reference to which certificate/fingerprint originally authorized the flow, only `rulesVersion`, `incoming`, and `Expires`: [3](#0-2) 

Re-validation is tied exclusively to the firewall config's `rulesVersion`, which is only bumped by `reloadFirewall` on a config change: [4](#0-3) 

However, a peer's identity can change independently of any local firewall config reload — a rehandshake replaces `hostinfo.ConnectionState` (and thus `peerCert`) with a fresh certificate while `f.rulesVersion` stays the same: [5](#0-4) 

Once the tunnel is rebuilt with a *different* certificate (e.g., a rotated cert that dropped a firewall-relevant group, or a cert that a stricter ruleset would reject), any already-established conntrack entry for that vpn address's 4-tuples continues to pass packets without checking the new certificate, because `inConns` only re-checks `table.match` when `rulesVersion` differs — never when the peer's certificate itself differs. This is architecturally the same flaw as the reported `BlackGovernor` bug: the authorization check (`_getVotes`/cert-group match) is evaluated once against an identity snapshot, the snapshot changes (NFT transfer / cert rehandshake), and the cached "already authorized" state is trusted forever afterward instead of being re-derived from the current identity.

### Impact Explanation
A host whose certificate is later downgraded, rotated to drop a required firewall group, or even blocklisted (`connection_manager.go`'s `isInvalidCertificate` only tears down the tunnel for `pki.disconnect_invalid`/blocklist cases, and even then only for the *host-level* certificate check, not per-flow conntrack) can retain unauthorized network access through firewall-allowed flows established under its earlier certificate. This is a firewall bypass: traffic that should be dropped under the current, correct identity/ruleset match continues to be allowed as long as the 4-tuple and `rulesVersion` are unchanged, which can persist for the full TCP/UDP/default conntrack timeout (`TCPTimeout`, `UDPTimeout`, `DefaultTimeout`).

### Likelihood Explanation
Rehandshakes happen routinely (cert renewal, roaming, connection manager–triggered rehandshake in `tryRehandshake`), so the window in which a stale, cert-blind conntrack entry can be exploited is not a rare edge case — it exists on essentially every certificate rotation event and is only closed by an explicit firewall config reload or conntrack entry expiry, not by identity change itself.

### Recommendation
Re-validate the conntrack entry's `table.match` against the *current* `h.ConnectionState.peerCert` whenever the associated `HostInfo`'s certificate/fingerprint differs from what was recorded at `addConn` time (store the authorizing certificate fingerprint in `conn`, and compare it in `inConns`, not just `rulesVersion`). Alternatively, invalidate/re-check relevant conntrack entries for a `HostInfo` whenever its `ConnectionState` is replaced by a rehandshake.

### Proof of Concept
Conceptual reproduction using existing test scaffolding (`firewall_test.go` conventions):
1. Build `HostInfo` `h` with `ConnectionState.peerCert` = cert A, which is in group `"trusted"`; add a firewall rule allowing group `"trusted"`.
2. Call `fw.Drop(flow, true, h, cp, nil)` — passes, and `addConn` records the conntrack entry at the current `rulesVersion` (no cert reference stored).
3. Simulate a rehandshake: replace `h.ConnectionState` with a new `ConnectionState{peerCert: certB}` where `certB` is NOT in group `"trusted"` (mirroring a real cert rotation/downgrade), without touching `fw.rulesVersion`.
4. Call `fw.Drop(flow, true, h, cp, nil)` again with the same 4-tuple — `inConns` finds `c.rulesVersion == f.rulesVersion`, skips `table.match`, and returns `true`, allowing the packet despite `certB` failing the rule that would otherwise produce `ErrNoMatchingRule`.

This is directly analogous to `firewall_test.go`'s existing `TestFirewall_DropConntrackReload`, which demonstrates re-validation *only* happens on `rulesVersion` bump (config reload) and not on a peer identity/certificate change: [6](#0-5)

func (f *Firewall) inConns(fp firewall.Packet, h *HostInfo, caPool *cert.CAPool, localCache firewall.ConntrackCache) bool {
	if localCache != nil {
		if _, ok := localCache[fp]; ok {
			return true
		}
	}
	conntrack := f.Conntrack
	conntrack.Lock()

	// Purge every time we test
	ep, has := conntrack.TimerWheel.Purge()
	if has {
		f.evict(ep)
	}

	c, ok := conntrack.Conns[fp]

	if !ok {
		conntrack.Unlock()
		return false
	}

	if c.rulesVersion != f.rulesVersion {
		// This conntrack entry was for an older rule set, validate
		// it still passes with the current rule set
		table := f.OutRules
		if c.incoming {
			table = f.InRules
		}

		// We now know which firewall table to check against
		if !table.match(fp, c.incoming, h.ConnectionState.peerCert, caPool) {
			if f.l.Enabled(context.Background(), slog.LevelDebug) {
				h.logger(f.l).Debug("dropping old conntrack entry, does not match new ruleset",
					"fwPacket", fp,
					"incoming", c.incoming,
					"rulesVersion", f.rulesVersion,
					"oldRulesVersion", c.rulesVersion,
				)
			}
			delete(conntrack.Conns, fp)
			conntrack.Unlock()
			return false
		}

		if f.l.Enabled(context.Background(), slog.LevelDebug) {
			h.logger(f.l).Debug("keeping old conntrack entry, does match new ruleset",
				"fwPacket", fp,
				"incoming", c.incoming,
				"rulesVersion", f.rulesVersion,
				"oldRulesVersion", c.rulesVersion,
			)
		}

		c.rulesVersion = f.rulesVersion
	}

	switch fp.Protocol {
	case firewall.ProtoTCP:
		c.Expires = time.Now().Add(f.TCPTimeout)
	case firewall.ProtoUDP:
		c.Expires = time.Now().Add(f.UDPTimeout)
	default:
		c.Expires = time.Now().Add(f.DefaultTimeout)
	}

	conntrack.Unlock()

	if localCache != nil {
		localCache[fp] = struct{}{}
	}

	return true
}

func (f *Interface) reloadFirewall(c *config.C) {
	cs := f.pki.getCertState()
	curCert := cs.getCertificate(cert.Version2)
	if curCert == nil {
		curCert = cs.getCertificate(cert.Version1)
	}

	// The firewall builds its routableNetworks set from the certificate's UnsafeNetworks at construction.
	// Check to see if that set has changed, and if so, rebuild the firewall.
	certUnsafeChanged := curCert != nil && !slices.Equal(curCert.UnsafeNetworks(), f.firewall.unsafeNetworks)

	if !c.HasChanged("firewall") && !certUnsafeChanged {
		f.l.Debug("No firewall config change detected")
		return
	}

	fw, err := NewFirewallFromConfig(f.l, cs, c)
	if err != nil {
		f.l.Error("Error while creating firewall during reload", "error", err)
		return
	}

	oldFw := f.firewall
	conntrack := oldFw.Conntrack
	conntrack.Lock()
	defer conntrack.Unlock()

	fw.rulesVersion = oldFw.rulesVersion + 1
	// If rulesVersion is back to zero, we have wrapped all the way around. Be
	// safe and just reset conntrack in this case.
	if fw.rulesVersion == 0 {
		f.l.Warn("firewall rulesVersion has overflowed, resetting conntrack",
			"firewallHashes", fw.GetRuleHashes(),
			"oldFirewallHashes", oldFw.GetRuleHashes(),
			"rulesVersion", fw.rulesVersion,
		)
	} else {
		fw.Conntrack = conntrack
	}

func TestFirewall_DropConntrackReload(t *testing.T) {
	ob := &bytes.Buffer{}
	l := test.NewLoggerWithOutput(ob)
	myVpnNetworksTable := new(bart.Lite)
	myVpnNetworksTable.Insert(netip.MustParsePrefix("1.1.1.1/8"))

	p := firewall.Packet{
		LocalAddr:  netip.MustParseAddr("1.2.3.4"),
		RemoteAddr: netip.MustParseAddr("1.2.3.4"),
		LocalPort:  10,
		RemotePort: 90,
		Protocol:   firewall.ProtoUDP,
		Fragment:   false,
	}
	network := netip.MustParsePrefix("1.2.3.4/24")

	c := cert.CachedCertificate{
		Certificate: &dummyCert{
			name:     "host1",
			networks: []netip.Prefix{network},
			groups:   []string{"default-group"},
			issuer:   "signer-shasum",
		},
		InvertedGroups: map[string]struct{}{"default-group": {}},
	}
	h := HostInfo{
		ConnectionState: &ConnectionState{
			peerCert: &c,
		},
		vpnAddrs: []netip.Addr{network.Addr()},
	}
	h.buildNetworks(myVpnNetworksTable, c.Certificate)

	fw := NewFirewall(l, time.Second, time.Minute, time.Hour, c.Certificate)
	require.NoError(t, fw.AddRule(true, firewall.ProtoAny, 0, 0, []string{"any"}, "", "", "", "", ""))
	cp := cert.NewCAPool()

	// Drop outbound
	assert.Equal(t, fw.Drop(p, false, &h, cp, nil), ErrNoMatchingRule)
	// Allow inbound
	resetConntrack(fw)
	require.NoError(t, fw.Drop(p, true, &h, cp, nil))
	// Allow outbound because conntrack
	require.NoError(t, fw.Drop(p, false, &h, cp, nil))

	oldFw := fw
	fw = NewFirewall(l, time.Second, time.Minute, time.Hour, c.Certificate)
	require.NoError(t, fw.AddRule(true, firewall.ProtoAny, 10, 10, []string{"any"}, "", "", "", "", ""))
	fw.Conntrack = oldFw.Conntrack
	fw.rulesVersion = oldFw.rulesVersion + 1

	// Allow outbound because conntrack and new rules allow port 10
	require.NoError(t, fw.Drop(p, false, &h, cp, nil))

	oldFw = fw
	fw = NewFirewall(l, time.Second, time.Minute, time.Hour, c.Certificate)
	require.NoError(t, fw.AddRule(true, firewall.ProtoAny, 11, 11, []string{"any"}, "", "", "", "", ""))
	fw.Conntrack = oldFw.Conntrack
	fw.rulesVersion = oldFw.rulesVersion + 1

	// Drop outbound because conntrack doesn't match new ruleset
	assert.Equal(t, fw.Drop(p, false, &h, cp, nil), ErrNoMatchingRule)
}
