### Title
RCE via unhardened `tar` extraction of an attacker/network-influenced HTTP snapshot in `CreateRepositoryFromSnapshot` - (File: internal/gitaly/service/repository/create_repository_from_snapshot.go)

### Summary
`CreateRepositoryFromSnapshot` fetches an archive from a caller-supplied `HttpUrl` and pipes the HTTP response body directly into the external `tar -C <path> -xvf -` binary with no validation of archive entries (no path-traversal, symlink, or hardlink checks), unlike the hardened Go-based extractor used elsewhere in the codebase for a very similar snapshot-replication path.

### Finding Description
The RPC handler `CreateRepositoryFromSnapshot` builds a fresh repository directory and calls `s.untar` to populate it from an HTTP source: [1](#0-0) 

`untar` issues an HTTP GET to `in.GetHttpUrl()` (optionally pinned to `ResolvedAddress` to mitigate DNS rebinding) and streams the response body straight into the system `tar` binary: [2](#0-1) 

Critically, the code itself documents that the archive is not safe to trust:
```go
// NOTE: The received archive is trusted *a lot*. Before pointing this RPC
// at endpoints not under our control, it should undergo a lot of hardening.
``` [3](#0-2) 

This is the exact bug class from the external report: a component fetches a payload from a network-controlled/spoofable HTTP endpoint and blindly executes/extracts it without validating its contents, resulting in code/data being written under attacker control. Unlike the analogous snapshot-extraction path used for Gitaly-to-Gitaly replication (`internal/gitaly/service/repository/replicate.go`), which was hardened with explicit checks against absolute symlinks, `..`-escapes, and hardlink targets escaping the destination directory: [4](#0-3) 

`CreateRepositoryFromSnapshot`'s `untar` performs none of these checks — it delegates entirely to the system `tar` binary with `-xvf`, which (depending on the platform tar implementation) can follow/create symlinks, overwrite arbitrary files via `../` path components, or write outside the target `path` if the server hosting `HttpUrl` (or a party able to influence DNS/routing to it, or an SSRF-redirected internal target) returns a malicious archive.

### Impact Explanation
A malicious or compromised HTTP endpoint reachable via the caller-supplied `HttpUrl` can supply a tar archive with path-traversal entries or symlinks to overwrite arbitrary files on the Gitaly host outside the intended repository directory (e.g., planting/overwriting `hooks/` executables, SSH keys, or other filesystem content reachable by the Gitaly process), which can escalate to remote code execution when Gitaly next executes a hook or git operation against the tampered files.

### Likelihood Explanation
Exploitation requires the RPC caller to control (or the resolved endpoint to serve) a malicious tar payload for the `HttpUrl`/`ResolvedAddress` pair — this is directly analogous to the H1 report's pattern of an installer blindly fetching and extracting attacker-served content from a network endpoint. The DNS-rebinding mitigation (`ResolvedAddress` pinning) only addresses IP-spoofing of the target host; it does nothing to validate the archive's contents once fetched, so any endpoint that can be reached (intentionally or via SSRF/compromise) can serve a hostile archive.

### Recommendation
Replace the shell-out to system `tar -xvf -` in `untar` with the same hardened, Go-native extraction routine used in `replicate.go`'s `extractTarToDirectory`/`extractFile` (which rejects absolute symlinks, validates that all resolved paths — including symlink and hardlink targets — remain within the destination directory, and applies file-mode/ownership sanitization) before this RPC is exposed to any endpoint not fully trusted and operator-controlled.

### Proof of Concept
1. Stand up an HTTP server that returns a crafted tar archive containing an entry like `../../../etc/cron.d/evil` or a symlink entry pointing outside the target directory.
2. Call `CreateRepositoryFromSnapshot` with `HttpUrl` pointing at that server (and, if required, `ResolvedAddress` set to the server's IP).
3. Observe that `untar` pipes the response directly to `tar -C <repoPath> -xvf -` with no path/symlink validation, as shown in `internal/gitaly/service/repository/create_repository_from_snapshot.go` lines 115–118, potentially writing/overwriting files outside `repoPath`.

func (s *server) untar(ctx context.Context, path string, in *gitalypb.CreateRepositoryFromSnapshotRequest) error {
	req, err := http.NewRequestWithContext(ctx, "GET", in.GetHttpUrl(), nil)
	if err != nil {
		return structerr.NewInvalidArgument("Bad HTTP URL: %w", err)
	}

	client := httpClient
	if resolvedAddress := in.GetResolvedAddress(); resolvedAddress != "" {
		client, err = newResolvedHTTPClient(in.GetHttpUrl(), resolvedAddress)
		if err != nil {
			return structerr.NewInvalidArgument("creating resolved HTTP client: %w", err)
		}
	}

	if in.GetHttpAuth() != "" {
		req.Header.Set("Authorization", in.GetHttpAuth())
	}

	rsp, err := client.Do(req)
	if err != nil {
		return structerr.NewInternal("HTTP request failed: %w", err)
	}
	defer rsp.Body.Close()

	if rsp.StatusCode < http.StatusOK || rsp.StatusCode >= http.StatusMultipleChoices {
		return structerr.NewInternal("HTTP server: %s", rsp.Status)
	}

	cmd, err := command.New(ctx, s.logger, []string{"tar", "-C", path, "-xvf", "-"}, command.WithStdin(rsp.Body))
	if err != nil {
		return err
	}

	return cmd.Wait()
```

func (s *server) CreateRepositoryFromSnapshot(ctx context.Context, in *gitalypb.CreateRepositoryFromSnapshotRequest) (*gitalypb.CreateRepositoryFromSnapshotResponse, error) {
	repository := in.GetRepository()
	if err := s.locator.ValidateRepository(ctx, repository, storage.WithSkipRepositoryExistenceCheck()); err != nil {
		return nil, structerr.NewInvalidArgument("%w", err)
	}

	if err := repoutil.Create(ctx, s.logger, s.locator, s.gitCmdFactory, s.catfileCache, s.txManager, s.repositoryCounter, repository, func(repo *gitalypb.Repository) error {
		path, err := s.locator.GetRepoPath(ctx, repo, storage.WithRepositoryVerificationSkipped())
		if err != nil {
			return structerr.NewInternal("getting repo path: %w", err)
		}

		// The archive contains a partial git repository, missing a config file and
		// other important items. Initializing a new bare one and extracting the
		// archive on top of it ensures the created git repository has everything
		// it needs (especially, the config file and hooks directory).
		//
		// NOTE: The received archive is trusted *a lot*. Before pointing this RPC
		// at endpoints not under our control, it should undergo a lot of hardening.
		if err := s.untar(ctx, path, in); err != nil {
			return structerr.NewInternal("extracting snapshot: %w", err)
		}

		return nil
	}); err != nil {
		return nil, structerr.NewInternal("creating repository: %w", err)
	}
