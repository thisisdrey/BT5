I found a strong analog to the reported bug class. The `handleRecvError` function in `outside.go` checks `hr.IsValid() && hr != addr` — mirroring the original bug's pattern of only validating one branch of a condition while leaving the other (the "no remote set yet" case) completely unchecked.

### Title
`handleRecvError()` skips remote-address validation when `hostinfo.remote` is unset, allowing unauthenticated tunnel teardown - (File: `outside.go`)

### Summary
`handleRecvError()` is reachable pre-authentication: `RecvError` is an unencrypted header type dispatched directly from `readOutsidePackets()` before any certificate or handshake state is required [1](#0-0) . It looks up the target `HostInfo` purely by the attacker-controlled `RemoteIndex` field in the cleartext header and then decides whether to tear the tunnel down based on a conditional address check [2](#0-1) .

### Finding Description
The relevant check is:
```go
hr := hostinfo.GetRemote()
if hr.IsValid() && hr != addr {
    f.l.Info("Someone spoofing recv_errors?", ...)
    return
}
f.closeTunnel(hostinfo)
```
This mirrors the structure of the reported `rescueTokens()` bug: a security-relevant guard is applied only in one branch of the condition (`totalStakers > 0` / here `hr.IsValid()`), while the other branch — where the guard variable is in its "empty" state (`totalStakers == 0` / here `hr` unset, i.e. `!hr.IsValid()`) — has **no check at all**. Any `HostInfo` for a pending or newly-created tunnel where `remote` has not yet been set (e.g. right after `StartHandshake`, before `SetRemote` is called, or a relay-only tunnel that never adopts a direct remote) will have `hr.IsValid() == false`. In that state, the source-address comparison is bypassed entirely, and any attacker who can (a) determine or guess a live `RemoteIndex` (32-bit values allocated by `generateIndex`, observable on the wire since the header is sent in cleartext for every handshake/message packet) can forge a `RecvError` packet from an arbitrary spoofed UDP source and unconditionally trigger `f.closeTunnel(hostinfo)` plus deletion from the pending handshake map [3](#0-2) .

The `acceptRecvErrorConfig` gate only restricts based on the source IP class (`always`/`never`/`private`) and by default is `always`, so it provides no protection against this specific bypass [4](#0-3) .

### Impact Explanation
An attacker with no CA-signed certificate and no valid handshake state can forcibly close/reset any tunnel or pending handshake whose `HostInfo.remote` has not yet been populated, simply by spoofing a `RecvError` packet with a guessed/observed `RemoteIndex`. This is a remote state-poisoning / denial-of-service primitive: it can disrupt handshake establishment, force repeated re-handshakes, and (per the `ErrExistingHostInfo`/`ErrAlreadySeen` interaction in `HandleIncoming`) potentially be combined with race conditions during handshake setup to disrupt legitimate connections. This directly matches the reported bug class of "condition only enforced in one branch, unconditionally bypassed in the other."

### Likelihood Explanation
`RemoteIndex` values are transmitted unencrypted in every packet header (`header.RemoteIndex`), so a network observer or on-path/off-path attacker can harvest them without needing to complete a handshake or hold any certificate [5](#0-4) . The condition on `hr.IsValid()` naturally holds true immediately after a handshake begins (before `SetRemote` is invoked) and for relay-associated hosts, making the vulnerable window realistically reachable rather than purely theoretical.

### Recommendation
Change the check so that an unset remote does not bypass validation — either reject `RecvError` packets outright when `hostinfo.GetRemote()` is invalid (since there is nothing trustworthy to compare against), or require that the `RecvError` sender address matches the current *pending* handshake source (`via`/last-known address) even when `remote` hasn't been promoted yet:
```go
hr := hostinfo.GetRemote()
if !hr.IsValid() || hr != addr {
    f.l.Info("Rejecting recv_error: no verified remote or mismatch", "addr", addr)
    return
}
f.closeTunnel(hostinfo)
```

### Proof of Concept
1. Attacker passively observes (or otherwise learns) a `RemoteIndex` associated with a `HostInfo` that has not yet called `SetRemote` (e.g., immediately after `StartHandshake` initiates but before the peer's address is confirmed, or a host reachable only via relay).
2. Attacker crafts a `header.RecvError` packet with that `RemoteIndex` and sends it from an arbitrary spoofed source address to the victim's UDP listener.
3. `readOutsidePackets()` dispatches it to `handleRecvError()` without any authentication [6](#0-5) .
4. `f.hostMap.QueryReverseIndex(h.RemoteIndex)` resolves the target `HostInfo`; since `hr.IsValid()` is false, the spoofing check is skipped and `f.closeTunnel(hostinfo)` executes unconditionally, tearing down the tunnel/pending handshake.

```go
func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
```

```go
// Parse is a helper function to parses given bytes into new Header struct
func (h *H) Parse(b []byte) error {
	if len(b) < Len {
		return ErrHeaderTooShort
	}
	// get upper 4 bytes
	h.Version = uint8((b[0] >> 4) & 0x0f)
	// get lower 4 bytes
	h.Type = MessageType(b[0] & 0x0f)
	h.Subtype = MessageSubType(b[1])
	h.Reserved = binary.BigEndian.Uint16(b[2:4])
	h.RemoteIndex = binary.BigEndian.Uint32(b[4:8])
	h.MessageCounter = binary.BigEndian.Uint64(b[8:16])
	return nil
}
```
