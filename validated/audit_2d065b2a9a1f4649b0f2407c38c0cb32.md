## Analysis

The reported bug class (attacker-controlled value flowing unsanitized into a `GIT_*` environment variable that Git subprocess trust) has a concrete, reachable analog in Gitaly.

### Root cause

Gitaly builds the `GIT_OBJECT_DIRECTORY` / `GIT_ALTERNATE_OBJECT_DIRECTORIES` environment variables for **every** git subprocess it spawns for a repository-scoped RPC directly from the client-supplied `Repository.GitObjectDirectory` / `Repository.GitAlternateObjectDirectories` proto fields, via `alternates.Env()`: [1](#0-0) 

This is invoked from `ExecCommandFactory.newCommand`, the central function used to spawn essentially all git subprocesses in Gitaly: [2](#0-1) 

Unlike `localrepo.Repo.ObjectDirectoryPath()`, which validates the object directory stays within the storage root via `storage.ValidateRelativePath` and enforces a quarantine-prefix check: [3](#0-2) 

`alternates.Env()` performs **no bounds checking at all** — it simply does `filepath.Join(repoPath, dir)` on every string supplied in `GitAlternateObjectDirectories`, including `..`-traversal or (since `filepath.Join` on an absolute string leaves it absolute-ish) attacker-chosen paths.

### Reachability from an ordinary/unprivileged client

Normally `GitObjectDirectory`/`GitAlternateObjectDirectories` are meant to only be set by Gitaly itself (quarantine) or looped back from Rails' access-check callback. The transaction middleware explicitly documents and only partially guards this: [4](#0-3) 

For **mutator** RPCs, setting these fields is rejected (`ErrQuarantineConfiguredOnMutator`). But for **accessor** (read-only) RPCs — e.g. `CommitService.FindCommit`, `TreeEntry`, `GetBlob`, `ListAllCommits`, etc. — a request that sets a non-empty `GitObjectDirectory`/`GitAlternateObjectDirectories` bypasses the normal `locator.ValidateRepository` / transaction-snapshot rewriting path entirely and is dispatched to the handler almost as-is (only requiring the client to also set the `relative-path-bin` gRPC metadata header, which is not otherwise authenticated as coming from Rails): [5](#0-4) 

The handler then resolves the real repo path via `locator.GetRepoPath` (which only validates `StorageName`/`RelativePath`, not the object-directory fields) and passes the repository straight into `ExecCommandFactory.newCommand`, which unconditionally injects the attacker-supplied `GitAlternateObjectDirectories` into `GIT_ALTERNATE_OBJECT_DIRECTORIES` for the git subprocess.

### Title
Unvalidated `GitAlternateObjectDirectories`/`GitObjectDirectory` RPC fields injected into `GIT_ALTERNATE_OBJECT_DIRECTORIES`/`GIT_OBJECT_DIRECTORY` env vars, bypassing storage confinement — (File: `internal/git/alternates/alternates.go`, `internal/git/gitcmd/command_factory.go`)

### Summary
`alternates.Env()`, used by `ExecCommandFactory.newCommand` for every git subprocess spawned against a repository, constructs `GIT_OBJECT_DIRECTORY`/`GIT_ALTERNATE_OBJECT_DIRECTORIES` from the client-supplied `Repository.GitObjectDirectory`/`GitAlternateObjectDirectories` proto fields without any path-containment validation, unlike the parallel, properly-validated `localrepo.Repo.ObjectDirectoryPath()` code path.

### Finding Description
`alternates.Env(repoPath, objectDirectory, alternateObjectDirectories)` simply `filepath.Join`s the repository path with each attacker-supplied string and emits it as an environment variable value with no check that the result stays inside the storage root [1](#0-0) . This function is called unconditionally whenever a repository is passed to `newCommand` [2](#0-1) , i.e. for nearly every git subprocess Gitaly spawns.

While these fields are intended to only be populated by Gitaly's own quarantine mechanism, the transaction middleware's handling of RPCs carrying non-empty `GitObjectDirectory`/`GitAlternateObjectDirectories` treats the request as an already-quarantined access-check loop-back from Rails and skips normal repository validation for **accessor** RPCs, forwarding the client-controlled fields straight to the RPC handler [4](#0-3) . This bypass is gated only by the presence of the `relative-path-bin` metadata header [5](#0-4) , which is not cryptographically tied to a real Rails-originated request — any gRPC client that can reach Gitaly directly can set it.

This is the same bug class as the `last-commit-log` report: an environment variable that controls git's object-resolution search path is populated from unsanitized, externally-controllable input and handed straight to a `git` subprocess invocation.

### Impact Explanation
By crafting an accessor RPC with `Repository.GitAlternateObjectDirectories` set to a path-traversal or absolute string (e.g. `"../../../other-repo/objects"`), an attacker can make Gitaly search another repository's (or any accessible directory's) loose objects/packs when serving the RPC's underlying git subprocess. This enables cross-repository object disclosure — reading blobs/commits/trees from repositories the caller should not have object-level access to — and Gitaly reveals the content back to the caller through the RPC's normal response.

### Likelihood Explanation
Requires the attacker to be a gRPC client capable of calling any repository-scoped accessor RPC (i.e. essentially any authenticated Gitaly client, not admin-privileged), able to set an arbitrary `Repository` message and a metadata header on their own request. No token leakage, MITM, or malicious peer/node is required — this is directly reachable via a crafted RPC field, matching the validation criteria.

### Recommendation
Apply the same bounds-checking used in `localrepo.Repo.ObjectDirectoryPath()` (`storage.ValidateRelativePath` plus quarantine-prefix verification) inside `alternates.Env()` / `ExecCommandFactory.newCommand` before emitting `GIT_OBJECT_DIRECTORY`/`GIT_ALTERNATE_OBJECT_DIRECTORIES`, and/or authenticate the `relative-path-bin` metadata / quarantine loop-back path so that only genuine Rails access-check callbacks (not arbitrary clients) can populate these fields on accessor RPCs.

### Proof of Concept
1. Call any accessor RPC (e.g. `CommitService.FindCommit`) with:
   - `Repository.GitObjectDirectory` / `GitAlternateObjectDirectories` set to a path traversal string such as `"../../victim-repo/objects"` (relative to the target repo path).
   - gRPC metadata `relative-path-bin` set to the target repository's relative path (satisfies `restoreSnapshotRelativePath`'s requirement).
2. The middleware bypasses transaction/path validation because the object-directory fields are non-empty and the RPC is an accessor [6](#0-5) .
3. The RPC handler resolves the repo via `locator.GetRepoPath` (only checks storage/relative path) and invokes a git subprocess through `ExecCommandFactory.newCommand`, which injects `GIT_ALTERNATE_OBJECT_DIRECTORIES=<repoPath>/../../victim-repo/objects` into the process environment [2](#0-1) .
4. Git resolves objects from the victim repository's object directory, and the response returned by the RPC can leak that content to the caller.

// Env returns the alternate object directory environment variables.
func Env(repoPath, objectDirectory string, alternateObjectDirectories []string) []string {
	var env []string
	if objectDirectory != "" {
		env = append(env, fmt.Sprintf("GIT_OBJECT_DIRECTORY=%s", filepath.Join(repoPath, objectDirectory)))
	}

	if len(alternateObjectDirectories) > 0 {
		var dirsList []string

		for _, dir := range alternateObjectDirectories {
			dirsList = append(dirsList, filepath.Join(repoPath, dir))
		}

		env = append(env, fmt.Sprintf("GIT_ALTERNATE_OBJECT_DIRECTORIES=%s", strings.Join(dirsList, ":")))
	}

	return env
}

func restoreSnapshotRelativePath(ctx context.Context, methodInfo protoregistry.MethodInfo, req proto.Message) (proto.Message, error) {
	// Rails sends RPCs from its access checks with quarantine applied. The quarantine paths are relative to the
	// snapshot repository of the original transaction. While the relative path of the request is the original relative
	// path of the repository before snapshotting, Rails sends the snapshot repository's path in a header. For the
	// quarantine paths to apply correctly, we must thus rewrite the request to point to the snapshot repository here.
	snapshotRelativePath := metadata.GetValue(ctx, MetadataKeySnapshotRelativePath)
	if snapshotRelativePath == "" {
		return nil, ErrQuarantineWithoutSnapshotRelativePath
	}

	rewrittenReq, targetRepo, err := rewritableRequest(methodInfo, req)
	if err != nil {
		return nil, fmt.Errorf("rewritable request: %w", err)
	}

	targetRepo.RelativePath = snapshotRelativePath

	return rewrittenReq, nil
}
