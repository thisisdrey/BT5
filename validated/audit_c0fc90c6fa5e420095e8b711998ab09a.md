### Title
Path-boundary check in tar-based repository snapshot extraction is defeated by depth-shifting symlinks - ([File: internal/gitaly/service/repository/replicate.go])

### Summary
`extractTarToDirectory()` (called from `extractSnapshot()`, itself invoked by `createFromSnapshot()` during `ReplicateRepository`/repository-fork snapshot restoration) validates that each tar entry stays inside the extraction root by comparing a *lexically joined* path string against `targetDir`. This mirrors the analog-report's flaw: a safety flag/check (`_solverFulfilled` in the report; the `strings.HasPrefix(...)` boundary check here) is computed once from an assumed state and is never re-validated against the *actual* state, which other operations in the same call (earlier tar entries creating symlinks) can still change. [1](#0-0) 

### Finding Description
`extractTarToDirectory` processes tar entries sequentially and, for `TypeSymlink` and `TypeReg`/`TypeLink` entries, computes the destination path purely as a string via `filepath.Join(targetDir, header.Name)` / `filepath.Join(filepath.Dir(targetPath), header.Linkname)`, then checks `strings.HasPrefix(resolvedPath, targetDir+separator)`. [2](#0-1) 

This arithmetic assumes that every intermediate path component named in the tar header (e.g. `a` in `a/b/link`) corresponds to a *real* directory of the same nesting depth on disk. However, an earlier tar entry in the very same archive can make `a` a **symlink** to `.` (or to any other in-bounds location), which passes the boundary check for that entry (`resolvedTarget == targetDir`) exactly like `reconcile()` in the reported bug transiently satisfies `deficit <= surplus`. Once `a` is a symlink, the *lexical* nesting depth used to validate a subsequent entry named e.g. `a/x/y/z/link` (nominal depth 4, relative target with 4 `..` segments resolving lexically back to `targetDir`, and thus accepted) diverges from the *real* on-disk depth, since the OS resolves `a` to `targetDir` itself when creating `a/x/y/z/link`, making the real containing directory `targetDir/x/y/z` — one level shallower than assumed. The symlink is therefore created with a target string carrying one `..` too many relative to its real location, causing it to resolve outside `targetDir` when later followed (e.g. by Git or by later tar entries writing through it), even though the code's check reported the destination as safely inside `targetDir` at creation time.

Just as in `reconcile()`/`validateBalances()`, where `_borrow()`/`_contribute()` can still mutate `deposits`/`withdrawals` after the “fulfilled” flag was latched, here an in-progress extraction can still mutate the directory tree's *real* topology (via symlinks) after a given entry's boundary check was latched as “safe”, invalidating the assumption baked into later checks in the same operation. No entry re-validates the destination using the actual resolved filesystem path (`os.Lstat`/`filepath.EvalSymlinks`) at the time of the write.

### Impact Explanation
An attacker who can control the source repository content that is later replicated/forked (custom hooks and other repository content are tarred with symlinks preserved, per the existing `GetCustomHooks`/`custom_hooks` symlink-preservation logic) can craft an archive that plants a symlink escaping the intended extraction directory on the destination Gitaly node during snapshot-based replication/forking. This is a storage-boundary escape: file writes or subsequently-followed symlinks (e.g. custom hooks executed later) can land outside the target repository's own storage path, which is explicitly one of the accepted vulnerability classes (concrete storage escape via extraction).

### Likelihood Explanation
Exploitation requires the attacker to control the tar stream fed into `extractTarToDirectory`, i.e. control of a source repository whose snapshot is later replicated or used to seed a fork (`ReplicateRepository`, fork creation). Ordinary repository owners already have the ability to create arbitrary symlinks inside a repository (as demonstrated by `TestGetCustomHooks_symlink`), so the necessary preconditions (repository content with attacker-chosen symlink chains) are reachable without special privileges. The remaining barrier is that the destination Gitaly node must run the snapshot-extraction code path, which happens as part of normal replication/fork operations rather than requiring a compromised peer.

### Recommendation
Do not rely on lexical string-prefix comparisons of Join()-ed paths to bound tar extraction. Instead:
- Resolve each destination's real parent directory with `os.Lstat`/`filepath.EvalSymlinks` before creating any entry, and reject if any component of the resolved parent chain is a symlink (or if the resolved real path is outside `targetDir`).
- Alternatively, track which paths within the archive have been created as symlinks and reject any subsequent entry whose declared path traverses through a symlinked component, or extract using a helper that opens directories with `O_NOFOLLOW`/`openat`-style semantics (as done by hardened tar extractors) so that symlink components can never be silently substituted for real directories.
- As a defense in depth, re-validate the destination path *after* resolving symlinks immediately before the write syscall (`os.Symlink`, `os.OpenFile`, `os.Link`), not only at the string-construction step.

### Proof of Concept
Within a single tar stream passed to `extractTarToDirectory` (e.g. via a maliciously-crafted repository whose snapshot/custom-hooks content is later extracted during replication or fork):
1. `TypeDir "x/"`, `TypeDir "x/y/"`, `TypeDir "x/y/z/"` — create 3 real nested directories under `targetDir`.
2. `TypeSymlink Name="a", Linkname="."` — passes the check (`resolvedTarget == targetDir`), creating `targetDir/a` as a symlink pointing to `targetDir` itself.
3. `TypeSymlink Name="a/x/y/z/link", Linkname="../../../../etc"` — the code computes `Dir(targetPath) = filepath.Join(targetDir, "a/x/y/z")` lexically (nominal depth 4) and `resolvedTarget = filepath.Join(that, "../../../../etc")`, which lexically cancels back to `filepath.Join(targetDir, "etc")` inside bounds — **check passes**. But because `a` is really a symlink to `targetDir`, the OS actually creates the new symlink file inside the real directory `targetDir/x/y/z` (depth 3, not 4), so the stored link target `../../../../etc` resolves, when followed, to one directory **above** `targetDir` plus `etc` — escaping the sandbox.
4. Any later access that follows `targetDir/a/x/y/z/link` (or `targetDir/x/y/z/link`, its real location) accesses/executes content outside the intended repository storage directory. [3](#0-2)

// extractTarToDirectory extracts a tar archive to the specified directory using Go's tar package
func (s *server) extractTarToDirectory(ctx context.Context, reader io.Reader, targetDir string) error {
	targetDir = filepath.Clean(targetDir)
	tarReader := tar.NewReader(reader)

	for {
		select {
		case <-ctx.Done():
			return ctx.Err()
		default:
		}

		header, err := tarReader.Next()
		if err == io.EOF {
			break // End of archive
		}
		if err != nil {
			return fmt.Errorf("reading tar header: %w", err)
		}

		targetPath := filepath.Join(targetDir, header.Name)

		if !strings.HasPrefix(targetPath, targetDir+string(os.PathSeparator)) &&
			targetPath != targetDir {
			return fmt.Errorf("invalid file path in tar: %s", header.Name)
		}

		switch header.Typeflag {
		case tar.TypeDir:
			if err := os.MkdirAll(targetPath, os.FileMode(header.Mode)); err != nil {
				return fmt.Errorf("creating directory %s: %w", targetPath, err)
			}

		case tar.TypeReg:
			if err := s.extractFile(ctx, tarReader, targetPath, header); err != nil {
				return fmt.Errorf("extracting file %s: %w", targetPath, err)
			}

		case tar.TypeSymlink:
			if filepath.IsAbs(header.Linkname) {
				return fmt.Errorf("absolute symlink not allowed: %s -> %s", header.Name, header.Linkname)
			}

			// Resolve the relative symlink target from the symlink's parent directory
			// and verify it stays within the extraction boundary, consistent with the
			// hard link validation below.
			resolvedTarget := filepath.Join(filepath.Dir(targetPath), header.Linkname)
			if !strings.HasPrefix(resolvedTarget, targetDir+string(os.PathSeparator)) &&
				resolvedTarget != targetDir {
				return fmt.Errorf("symlink target escapes extraction directory: %s -> %s", header.Name, header.Linkname)
			}
