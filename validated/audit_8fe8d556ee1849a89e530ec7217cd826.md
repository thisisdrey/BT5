### Title
RewardsDistributor accrues rewards on interest-inflated DebtToken balance, letting borrowers drain the reward pool - ([File: contracts/RewardsDistributor.sol](contracts/RewardsDistributor.sol))

### Summary
`RewardsDistributor._calculateTokenDelta` computes a user's reward delta as `token_.balanceOf(account_).wadMul(deltaIndex)` using the account's *current* token balance. For `DepositToken` this is a static share count and is correct because every mint/burn/transfer checkpoints the account first. For `DebtToken`, however, `balanceOf` grows continuously with accrued interest (`principalOf * debtIndex / debtIndexOf`), and `accrueInterest()` — which mutates `debtIndex`/`totalSupply_` — never calls `updateBeforeMintOrBurn` on the rewards distributor. The result is that the reward index delta accrued over a period is multiplied by a balance that includes interest that was not outstanding for most of that period, over-paying borrowers relative to every other reward token holder and to the intended per-second accounting.

### Finding Description
In `RewardsDistributor.sol:217-231`, `_calculateTokenDelta` reads `accountIndexOf[token_][account_]` and computes:

```solidity
uint256 _deltaIndex = _tokenIndex - _accountIndex;
_tokensDelta = token_.balanceOf(account_).wadMul(_deltaIndex);
```

In `DebtToken.sol`, `balanceOf` returns `principalOf[account] * debtIndex / debtIndexOf[account]` and `accrueInterest()` (lines 156-180) increases `debtIndex` without notifying any rewards distributor. The only reward hooks are `updateRewardsBeforeMintOrBurn(account_)` inside `_mint` (line 577) and `_burn` (line 525), and `issue`/`mint`/`repay`/`repayAll` paths — but pure interest accrual between those events is invisible to the distributor.

Attack sequence (fully unprivileged):

1. Attacker calls `DebtToken.issue(amount_, attacker)` from a sufficiently collateralized position, minting a large debt position (reward hook records `accountIndexOf` correctly — fine so far).
2. Time passes. Interest accrues on `debtIndex`; `accrueInterest()` is called by any pool interaction but never checkpoints `accountIndexOf` in `RewardsDistributor`.
3. Attacker calls `RewardsDistributor.claimRewards(attacker, [debtToken])` (or the permissionless `updateBeforeMintOrBurn(debtToken, attacker)`). `_updateTokensAccruedOf` multiplies the whole elapsed `deltaIndex` by the interest-inflated `balanceOf`, crediting rewards as if the interest had been outstanding for the entire period.
4. `_transferRewardIfEnoughTokens` pays out, or (once the distributor balance is exhausted) silently skips payment for everyone else (`amount_ <= _balance` check at lines 248-256), freezing honest users' accrued yield.

Deployed configuration shows `RewardsDistributor` tracks debt tokens (`test/RewardDistributor.test.ts` uses `debtToken1`, `debtToken2` as reward tokens, and `tokens[]`/`tokenSpeeds` include them), so this is a live surface.

### Impact Explanation
Direct theft of the reward token balance held by `RewardsDistributor`. The attacker captures reward tokens proportional to interest they never "held" during the accrual window. Because rewards come from a finite distributor balance and `_transferRewardIfEnoughTokens` silently does nothing when underfunded, over-claims by borrowers cause permanent freezing of unclaimed yield for all other users of every reward token (rewards are pooled into a single `tokensAccruedOf` accounting across all tokens).

### Likelihood Explanation
Requires only: (a) a DebtToken listed in `tokens[]` with `tokenSpeeds > 0`, and (b) `interestRate > 0` so `debtIndex` grows — both true in normal operation (interest rate is set at initialization and is non-zero on any active synth market). The attacker needs a healthy debt position, obtainable by anyone via `issue()` with collateral. No privileged role, oracle manipulation, or flash loan is needed; impact scales with borrow size, interest rate, and elapsed time.

### Recommendation
Before computing reward deltas, force a debt-index checkpoint or exclude debt-token interest from reward accounting:
- In `DebtToken.accrueInterest()`, call `updateBeforeMintOrBurn` is infeasible per-account; instead, make `RewardsDistributor` treat `principalOf[account]` (constant between mint/burn events) rather than `balanceOf` as the reward base for debt tokens, or
- Track a per-account scaled balance (`principalOf[account] / debtIndexOf[account]`) for reward accrual so interest growth does not inflate rewards, and
- In `_transferRewardIfEnoughTokens`, revert or emit an explicit underfunding event instead of silently skipping payment.

### Proof of Concept
```solidity
// Fork test: mainnet RewardsDistributor + DebtToken (msUSD debt token)
// Assume alice deposits collateral and issues max debt on day 0.

function test_rewardInflationViaInterest() public {
    // Day 0: alice issues debt (accountIndexOf recorded, balance = P)
    vm.prank(alice);
    debtToken.issue(debtAmount, alice);          // hooks rewards correctly

    uint256 idx0 = rewardsDistributor.accountIndexOf(debtToken, alice); // = current token index

    // Warp 30 days; interest accrues on debtIndex, no reward checkpoint
    vm.warp(block.timestamp + 30 days);
    debtToken.accrueInterest();                  // grows debtIndex, no reward hook

    uint256 inflatedBalance = debtToken.balanceOf(alice); // P * (1 + r*t)

    // Alice claims: delta computed on inflated balance for whole 30 days
    vm.prank(alice);
    rewardsDistributor.claimRewards(alice, tokens);

    // Expected fair reward ~ P * deltaIndex; actual ~ P*(1+r*t) * deltaIndex
    uint256 overpaid = rewardsDistributor.tokensAccruedOf(alice);
    // overpaid > speed * 30d * (P / totalSupply) by a factor of (1 + interestRate*30d)
    // Repeatable every period; drains distributor so later claimRewards()
    // calls for honest users hit `amount_ > _balance` and pay nothing.
}
```

Invariant broken: reward accrual conservation — total distributed rewards should equal `speed * elapsed` allocated pro-rata to balances that existed during the window; using post-interest `balanceOf` retroactively mints reward entitlement on interest that was not outstanding.
