## Finding

### Title
Unchecked null dereference of `Repository.getContract()` result during CALL/DELEGATECALL/CALLCODE/STATICCALL execution - (File: `actuator/src/main/java/org/tron/core/vm/program/Program.java`)

### Summary
`Program.callToAddress()` fetches a callee contract's metadata via `Repository.getContract(codeAddress)` and immediately dereferences the result without a null check, mirroring the CVE-2023-52883 bug class ("resource may be NULL" object dereferenced without a guard).

### Finding Description
In `Program.callToAddress(MessageCall msg)`, when the TVM executes a `CALL`/`CALLCODE`/`DELEGATECALL`/`STATICCALL` targeting `codeAddress`, the code checks only whether an `AccountCapsule` exists for that address before fetching its code: [1](#0-0) 

If the fetched `programCode` is non-empty, the method proceeds to build a nested `Program` and — only when the `allowTvmCompatibleEvm` chain parameter is enabled — sets the contract version by directly chaining `.getContractVersion()` onto the return value of `invoke.getDeposit().getContract(codeAddress)`, with no null check: [2](#0-1) 

`RepositoryImpl.getContract(byte[] address)` explicitly returns `null` when no `ContractCapsule` is found in the cache, parent repository, or the underlying `ContractStore`: [3](#0-2) 

This is the same bug class as the kernel CVE: an object reference obtained from a store/lookup (`abo->tbo.resource` in the kernel, `ContractCapsule` here) is used without verifying non-null before calling a method on it.

### Impact Explanation
An uncaught `NullPointerException` inside TVM opcode execution (`Program`) during block application could abort transaction/block processing for any full node that reaches this code path while `allowTvmCompatibleEvm` is active, potentially causing a node crash or halt during block validation — matching the "node crash or halt" acceptance criterion.

### Likelihood Explanation
The reachability of the null branch depends on whether `getCode(codeAddress)` can return non-empty bytecode for an address while `getContract(codeAddress)` simultaneously returns null. In the normal contract-creation and self-destruct flows (`createContractImpl`, `deleteContract`, `commitContractCache`/`commitCodeCache`), code and contract-metadata records are written and deleted together, which would make this state hard to reach through ordinary transaction flows. I was not able to fully trace every code path (e.g., interactions between `CodeStore` and `ContractStore` under partial commits, revoking-DB rollbacks, or `newRepositoryChild` cache layering) before running out of investigation budget, so I cannot conclusively confirm an unprivileged, single-transaction trigger for this null state. This significantly lowers confidence relative to a fully proven finding.

### Recommendation
Add an explicit null check on the result of `getContract(codeAddress)` before calling `.getContractVersion()`, e.g. skip setting `contractVersion` (or default to version 0) when the contract capsule is absent, mirroring the null-safety pattern already used a few lines above for `accountCapsule`.

### Proof of Concept
Not able to construct a concrete, verified single-transaction trigger within the available investigation budget — see Likelihood Explanation. A live-node/unit-test reproduction targeting a `codeAddress` whose `CodeStore` entry exists without a corresponding `ContractStore` entry (if such a state is reachable) would be required to confirm exploitability.

---
**Note on confidence:** Because I could not fully verify whether the null state at this dereference is reachable from an unprivileged single transaction (this would require deeper tracing of `CodeStore`/`ContractStore` write/delete symmetry and cache-layer interactions in `RepositoryImpl`), this finding should be treated as a plausible but not fully confirmed analog. I recommend a Devin session with full repository/tooling access to trace all code paths that populate `CodeStore` and `ContractStore` and confirm or rule out the desynchronized state.

  @Override
  public ContractCapsule getContract(byte[] address) {
    Key key = Key.create(address);
    if (contractCache.containsKey(key)) {
      return new ContractCapsule(contractCache.get(key).getValue());
    }

    ContractCapsule contractCapsule;
    if (parent != null) {
      contractCapsule = parent.getContract(address);
    } else {
      contractCapsule = getContractStore().get(address);
    }

    if (contractCapsule != null) {
      contractCache.put(key, Value.create(contractCapsule));
    }
    return contractCapsule;
  }
