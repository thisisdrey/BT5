### Title
Unbounded body read via attacker-declared `Content-Length` in `process_event` causes single-message memory-exhaustion DoS on signer's event endpoint - ([File: libsigner/src/events.rs])

### Summary
`SignerEventReceiver::bind` opens a plain `tiny_http` HTTP server with no authentication, and `process_event` reads the request body via `request.as_reader().read_to_string(&mut body)` with no length cap. Because `tiny_http`'s reader streams exactly as many bytes as the client-declared `Content-Length` header specifies, a single POST to `/stackerdb_chunks` (or any of the other event routes) with a huge declared `Content-Length` forces the process to allocate and read an attacker-chosen amount of memory before any validation occurs.

### Finding Description
The broken equality is: bytes read by `read_to_string` should be bounded by a constant such as `MAX_MESSAGE_LEN`, but instead equals whatever `Content-Length` the client declares. In `libsigner/src/events.rs`, `SignerEventReceiver::bind` (`events.rs:404-408`) binds a `tiny_http::Server` directly with no size limits or auth. `next_event` (`events.rs:413-459`) dispatches any POST to `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, or `/new_block` straight into `process_event::<T, E>(request)` (`events.rs:519-542`). That function does:
```rust
let mut body = String::new();
if let Err(e) = request.as_reader().read_to_string(&mut body) { ... }
```
`request.as_reader()` returns `tiny_http`'s internal reader, which reads from the socket according to the parsed `Content-Length` header value (or chunked transfer-encoding) with no upper bound enforced by this call site. Unlike the node's own HTTP body decoding path in `libsigner/src/http.rs::decode_http_body` (`http.rs:197-217`), which explicitly wraps chunked bodies in `HttpChunkedTransferReader::from_reader(ptr, MAX_MESSAGE_LEN.into())`, `process_event` bypasses any `MAX_MESSAGE_LEN`/`BLOCK_RESPONSE_DATA_MAX_SIZE`-style cap. A client can send `Content-Length: <huge number>` followed by that many bytes (or keep the connection open trickling bytes) to force the process to grow `body: String` to that size, consuming memory/CPU with a single request, before `serde_json::from_slice` or any signature/auth check ever runs.

### Impact Explanation
A single crafted POST can force unbounded memory allocation in the `stacks-signer` process handling event-dispatcher callbacks, leading to OOM/crash or severe resource exhaustion — an unauthenticated, single-message DoS against the signer's local event-receiver process. This matches the "Critical - remote crash/unauthenticated DoS from few messages" category. It is trivially repeatable (send again after respawn/reconnect) and requires no valid signature, node secret, or StackerDB slot ownership — any TCP client that can reach the bound listener socket can trigger it.

### Likelihood Explanation
No authentication or shared secret gates the event-receiver's HTTP endpoint at this layer (`events.rs:404-408`), and there is no reachability restriction enforced in code — the bind address is whatever is configured. Exploitation cost is a single POST request with a large `Content-Length` header; no chain state, epoch, or peer relationship is required. This makes the attack cheap and highly likely wherever the event port is reachable from outside strict localhost-only network policy.

### Recommendation
Cap the body read in `process_event` by checking the `Content-Length` header against `MAX_MESSAGE_LEN` (or an appropriate signer-message-size constant such as `BLOCK_RESPONSE_DATA_MAX_SIZE`) before reading, and use a bounded reader (e.g., `Read::take(MAX_MESSAGE_LEN)`) instead of `read_to_string` directly on the raw request reader, rejecting/erroring out requests that exceed the cap.

### Proof of Concept
In `libsigner`'s test module (e.g., `libsigner/src/tests/mod.rs` or a new test in `events.rs`), spin up a `SignerEventReceiver` bound to `127.0.0.1:0`, then open a `TcpStream` to it and send:
```
POST /stackerdb_chunks HTTP/1.1\r\nHost: x\r\nContent-Length: 9999999999\r\nContent-Type: application/json\r\n\r\n
```
followed by a very large or endless stream of bytes (or just the declared length without sending enough real bytes to observe the reader blocking/allocating). Assert that `process_event` either errors immediately once the declared length exceeds `MAX_MESSAGE_LEN` (expected fix) or, on current code, that the call proceeds to allocate proportional to `Content-Length` (demonstrating the unbounded read), which can be observed via memory growth or a hang while `read_to_string` waits for/consumes the declared length of bytes. fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}

/// Decode an HTTP body, given the headers.
pub fn decode_http_body(headers: &HashMap<String, String>, mut buf: &[u8]) -> io::Result<Vec<u8>> {
    let chunked = if let Some(val) = headers.get("transfer-encoding") {
        val == "chunked"
    } else {
        false
    };

    let body = if chunked {
        // chunked encoding
        let ptr = &mut buf;
        let mut fd = HttpChunkedTransferReader::from_reader(ptr, MAX_MESSAGE_LEN.into());
        let mut decoded_body = vec![];
        fd.read_to_end(&mut decoded_body)?;
        decoded_body
    } else {
        // body is just as-is
        buf.to_vec()
    };

    Ok(body)
}
