### Title
Fee bypass via batch-splitting a fungible NEP-245/IMT amount into unit-sized `TokenDiff` intents - (File: `contracts/defuse/core/src/intents/token_diff.rs`)

### Finding Description

The binding that should hold is: **fee owed on a cumulative negative delta of `N` units of a fee-bearing `Nep245`/`Imt` token == fee actually collected when that same net movement of `N` units is expressed as a batch of intents in one signed payload.** Instead, `TokenDiff::execute_intent` computes and collects the fee independently per `Intent::TokenDiff` entry, using only that single intent's `|delta|` for the `amount` argument to `Self::token_fee`: [1](#0-0) 

`token_fee` special-cases `TokenIdType::Nep171`, and `Nep245`/`Imt` when `amount <= 1`, returning `Pips::ZERO`, i.e. the "NFT/unit" exemption: [2](#0-1) 

The exemption is evaluated **per intent, not per batch or per token across the whole payload**. `DefuseIntents` (and thus one signed `DefusePayload`/one signature) carries a `Vec<Intent>` executed sequentially, each independently dispatched to `TokenDiff::execute_intent`: [3](#0-2) [4](#0-3) 

An unprivileged signer holding `N` units of a `Nep245TokenId` (multi-token semi-fungible asset) can sign a single `DefusePayload` containing `N` separate `TokenDiff` intents, each with `diff = {token_id: -1}` (and any matching positive-delta intents needed to satisfy the batch's net-zero invariant enforced later by `TransferMatcher::finalize`). Because each intent's own `amount` is `1`, `token_fee` returns `Pips::ZERO` for every one of the `N` intents, so `fees_collected` stays `0` for that token across the whole payload. Compare this to a single `TokenDiff` intent with `diff = {token_id: -N}`: `token_fee` takes the `fee` branch (amount > 1) and `fee_ceil(N)` is charged and added to `fees_collected`, then credited to the fee collector via `internal_add_balance`.

`TransferMatcher`/`Deltas::finalize` only checks that the **net token deltas across the whole batch sum to zero** (or reflect legitimate transfers); it has no knowledge of, and does not re-derive, the fee that should have been charged on the aggregate negative delta — it operates purely on already-fee-adjusted deltas that were applied to balances during `internal_apply_deltas` in the per-intent loop. [5](#0-4) 

None of the existing guards (`MultiPayload::verify`, nonce/salt checks, `TransferMatcher::finalize`'s invariant check) inspect whether a large fungible-style movement of a `Nep245`/`Imt` token has been artificially fragmented into unit-sized diffs to dodge `token_fee`'s multiplier; the invariant check only cares about zero-sum balancing, not about fee correctness across fragmented intents.

### Impact Explanation

The fee collector (`engine.state.fee_collector()`) under-collects protocol fees on any `Nep245`/`Imt`-denominated trade that a solver/user is willing to fragment into unit increments within one signed payload, while the counterparty side of the trade (and the signer's own balance movements) proceed exactly as they would in the unfragmented case. This is a direct, repeatable "protocol fees bypassed" condition (matches the Critical category "protocol fees bypassed or over-collected"), exploitable by any signer for every `Nep245`/`Imt` token that has nonzero configured fee, with no privileged role required, and repeatable across accounts/tokens/batches without limit (bounded only by payload size / intents count, which is not in scope to assess as a resource-exhaustion concern here — the fee-evasion economics stand regardless of how many unit intents are packed).

### Likelihood Explanation

Preconditions: attacker must hold (or route through a matched counterparty) balance of a `Nep245`/`Imt` token subject to nonzero `Pips` fee, and must be able to construct/sign a `DefuseIntents` payload with multiple `TokenDiff` entries — both are freely available to any unprivileged signer via `execute_intents`/`simulate_intents`. Attacker cost is just the extra payload size (more `Intent::TokenDiff` entries in one `Vec`), no additional signature cost since one signature covers the whole `DefuseIntents` message. This is fully feasible and repeatable at will, with no protocol countermeasure to detect or forbid fragmentation of a single logical transfer into unit deltas.

### Recommendation

Compute and charge the fee based on the **aggregate negative delta per `TokenId` across the entire batch/payload** (e.g. accumulate deltas per token per signer across all `TokenDiff` intents in a `DefuseIntents` before evaluating `token_fee`'s `amount` threshold), rather than per-intent `|delta|`. Alternatively, remove or tighten the NFT/MT `amount <= 1` exemption so it cannot be trivially satisfied by intent fragmentation (e.g. base the exemption on whether the `TokenId` is truly non-fungible/unique-supply rather than on the numeric delta observed in a single intent).

    // Finalizes all transfers, or returns unmatched deltas.
    // If unmatched deltas overflow, then Err(None) is returned.
    pub fn finalize(self) -> Result<Transfers, InvariantViolated> {
        let mut transfers = Transfers::default();
        let mut deltas = TokenDeltas::default();
        for (token_id, transfer_matcher) in self.0 {
            if let Err(unmatched) = transfer_matcher.finalize_into(&token_id, &mut transfers)
                && (unmatched == 0 || deltas.apply_delta(token_id, unmatched).is_none())
            {
                return Err(InvariantViolated::Overflow);
            }
        }
        if !deltas.is_empty() {
            return Err(InvariantViolated::UnmatchedDeltas {
                unmatched_deltas: deltas,
            });
        }
        Ok(transfers)
    }
