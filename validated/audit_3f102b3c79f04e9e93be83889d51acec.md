### Title
`Pool.swap` burns the caller's input tokens but can mint zero output tokens, permanently destroying user funds - ([File: contracts/Pool.sol](contracts/Pool.sol))

### Summary
`Pool.swap` first burns `amountIn_` of the caller's `syntheticTokenIn_`, then computes `_amountOut` via `masterOracle().quote(...)` minus a swap fee, and mints it — with no check that `_amountOut > 0`. When the oracle quote rounds to zero (tiny `amountIn_`, large decimals/price skew between the two synthetics, or a same-transaction manipulated vault-share oracle), the user's input is burned and they receive nothing, permanently losing funds.

### Finding Description
In `Pool.swap` the input tokens are destroyed before the output quote is computed:

- `syntheticTokenIn_.burn(_msgSender, amountIn_)` runs at [1](#0-0) 
- `quoteSwapOut` computes `_amountOut = masterOracle().quote(...)` and subtracts `_fee = _amountOut.wadMul(_swapFee)` at [2](#0-1) 
- `syntheticTokenOut_.mint(_msgSender, _amountOut)` executes unconditionally at [3](#0-2) 

`masterOracle().quote` does a fixed-point conversion `amountIn * priceIn / priceOut` which truncates toward zero; for any `(amountIn, priceRatio)` where the product is below 1 output unit, `_amountOut == 0`. This mirrors the USSD `mintForToken` bug class exactly: funds are pulled/burned first, output is computed second, and zero output is silently accepted. Notably, the USSD recommendation (`require(stableCoinAmount > 0)`) is absent here.

The deployed synthetics have heterogeneous decimals and very different USD prices (e.g., an 18-decimal msETH-priced unit vs. a 6-decimal msUSD-priced unit, or shares of vault-based collateral priced through `MasterOracle`). `quote` in Metronome's `MasterOracle` traverses underlying asset prices — including vault-share pricing — which can be skewed in the same transaction by an AMM trade or donation, pushing a marginal swap's output to exactly 0.

### Impact Explanation
A user calling `swap` with an `amountIn_` whose oracle-priced output truncates to zero loses their entire `syntheticTokenIn_` balance transferred: it is burned, `SyntheticTokenSwapped` emits `amountOut = 0`, and no token can ever be redeemed. This is direct, permanent destruction of user funds — identical in effect to the reported "deposit collateral, mint zero tokens" loss. An attacker can also grief by exploiting same-tx oracle skew so a victim's pending swap (e.g., routed via `Operator.execute` gateways) outputs zero.

### Likelihood Explanation
- Reachable from a public, unprivileged entry point: only `whenNotShutdown`, `nonReentrant`, `isSwapActive`, and token-existence checks gate `swap` — none of which prevent a zero output.
- Requires either (a) small `amountIn_` relative to the price ratio (user error — same likelihood class as the medium-severity original), or (b) an attacker manipulating the oracle-quoted price within the same transaction, which the rules explicitly permit.
- No min-out/slippage parameter exists on `swap`, so the caller has no on-chain protection.

### Recommendation
Revert when the computed output is zero (and ideally add a `minAmountOut` parameter):

```solidity
(_amountOut, _fee) = quoteSwapOut(syntheticTokenIn_, syntheticTokenOut_, amountIn_);
if (_amountOut == 0) revert AmountIsZero();
```

applied before minting in `swap` at contracts/Pool.sol:662-668.

### Proof of Concept
Fork-based Hardhat test sketch against the deployed mainnet `Pool`:

```solidity
// mainnet fork, real Pool + MasterOracle + msUSD/msXXX synthetics
// attacker/victim holds a tiny amount of a high-priced synthetic
uint256 amountIn = 1; // 1 wei of a low-value-denominated synthetic
syntheticTokenIn.approve(address(pool), amountIn);

(uint256 quoted,) = pool.quoteSwapOut(syntheticTokenIn, syntheticTokenOut, amountIn);
assertEq(quoted, 0); // quote truncates to zero

uint256 balBefore = syntheticTokenIn.balanceOf(victim);
pool.swap(syntheticTokenIn, syntheticTokenOut, amountIn);

assertEq(syntheticTokenIn.balanceOf(victim), balBefore - amountIn); // burned
assertEq(syntheticTokenOut.balanceOf(victim), 0);                  // nothing minted
```

Optionally precede the swap with a same-transaction AMM trade/donation that skews the `MasterOracle` vault-share price of `syntheticTokenOut_`'s underlying so that a previously nonzero quote truncates to 0.
