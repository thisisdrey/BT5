### Title
Unauthenticated remote DoS via `/shutdown` endpoint in `SignerEventReceiver::next_event` - (File: libsigner/src/events.rs)

### Summary
The signer's HTTP event-receiver dispatch table in `next_event` maps the URL `/shutdown` directly to setting `stop_signal` and returning `EventError::Terminated`, with no check of the request's source or any secret/credential. Any TCP client that can reach the bound event-receiver port can terminate the signer's event-processing loop with a single `POST /shutdown` request.

### Finding Description
In `SignerEventReceiver::next_event` (`libsigner/src/events.rs`), the request dispatch is a pure string match on `request.url()`: [1](#0-0) 
There is no authentication, secret token, or origin check anywhere in this function or in `with_server`/`bind` — `bind` simply opens a plain `tiny_http` `HttpServer` on the configured socket address: [2](#0-1) 
The `/shutdown` branch unconditionally does `event_receiver.stop_signal.store(true, Ordering::SeqCst)` and returns `Err(EventError::Terminated)`. In `main_loop`, `EventError::Terminated` causes an immediate `break`, ending the event receiver thread permanently (there is no re-bind/restart logic shown in this file): [3](#0-2) 

Notably, the legitimate internal use of this mechanism (`SignerStopSignaler::send`) crafts exactly this same unauthenticated HTTP request to trigger shutdown from within the same process: [4](#0-3) 
This demonstrates that the `/shutdown` path was designed to be triggered by a bare, unauthenticated `POST /shutdown` — the same request any external TCP peer can send. No signature, no header, no shared secret, and no loopback-only check exists at this layer to distinguish the legitimate internal caller from an external attacker.

### Impact Explanation
Any remote party that can open a TCP connection to the signer's event-receiver port and send `POST /shutdown HTTP/1.1` (with any or no body) causes the signer's `stop_signal` to be set and its `main_loop` to break, permanently halting further event processing (miner/burn/stackerdb chunk/block-proposal events will no longer be received or acted on) until the operator manually restarts the signer process. This is a single-message, unauthenticated denial-of-service against a signer node, matching the "Critical – remote crash/unauthenticated DoS from few messages" category. It does not forge or corrupt consensus state, but it can silence a signer's participation in block validation/signing, which is high-impact for network liveness/security if reachable.

### Likelihood Explanation
- Attacker needs only network (TCP) reachability to the event-receiver's bound address/port — no RPC secret, no StackerDB slot ownership, no peer identity is required.
- Cost is a single crafted HTTP request; fully repeatable against every reconnect/restart.
- Real-world exposure depends on deployment: if the signer's event endpoint is bound to a non-loopback address (e.g., `0.0.0.0` or a routable interface, as is common for split node/signer deployments where the node forwards events over the network to a separately hosted signer), the port is remotely reachable by anyone, satisfying the threat model's "attacker can open a TCP connection to whatever address the signer's `HttpServer::http(listener)` is bound to" precondition.

### Recommendation
Require an out-of-band shared secret or authentication for state-changing endpoints on this listener — at minimum, gate `/shutdown` (and ideally all POST endpoints) behind a pre-shared token compared in constant time, or restrict the shutdown mechanism to a loopback-only control channel/local socket that is not exposed on the same interface as node-forwarded event traffic. Do not rely on URL-string equality alone as the trust boundary for terminating the process.

### Proof of Concept
```rust
// libsigner/src/events.rs (new test in `mod tests`)
use std::net::{TcpStream, TcpListener};
use std::io::Write;
use std::sync::mpsc::channel;
use std::thread;

#[test]
fn unauthenticated_remote_shutdown() {
    let mut receiver: SignerEventReceiver<crate::v0::messages::SignerMessage> =
        SignerEventReceiver::new(false);
    let addr: std::net::SocketAddr = "127.0.0.1:0".parse().unwrap(); // use an ephemeral, then reconnect via bound addr
    let bound = receiver.bind(addr).unwrap();
    let (tx, _rx) = channel();
    receiver.add_consumer(tx);

    // Simulate an "attacker" with no credentials sending POST /shutdown directly.
    let attacker_thread = thread::spawn(move || {
        let mut stream = TcpStream::connect(bound).unwrap();
        let body = "";
        let req = format!(
            "POST /shutdown HTTP/1.1\r\nHost: {}\r\nConnection: close\r\nContent-Length: {}\r\n\r\n{}",
            bound, body.len(), body
        );
        stream.write_all(req.as_bytes()).unwrap();
    });

    // next_event should observe the forged shutdown and return Terminated
    let result = receiver.next_event();
    attacker_thread.join().unwrap();

    assert!(matches!(result, Err(EventError::Terminated)));
    assert!(receiver.is_stopped()); // stop_signal was flipped by an unauthenticated peer
}
```
This reproduces the exact code path: `next_event` → `with_server` closure → `request.url() == "/shutdown"` branch at `libsigner/src/events.rs:443-445`, asserting the resulting `Err(EventError::Terminated)` and `is_stopped() == true` caused purely by an unauthenticated TCP client.
