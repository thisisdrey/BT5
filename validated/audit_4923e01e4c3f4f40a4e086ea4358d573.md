This maps well to the reported bug class: an unbounded, unpaginated data structure grows via ordinary user actions (force-pushes to a pool member causing dangling objects) and is entirely reprocessed by a privileged/maintenance RPC (`FetchIntoObjectPool`) on every subsequent invocation, with no mechanism to prune or bound it, similar to the `allPairs`/`setPeriodSize` pattern in the report (repeated `createPair` calls, then an unbounded loop in `setPeriodSize`).

### Title
Unbounded growth of `refs/dangling/*` references permanently degrades and can DoS `FetchIntoObjectPool` housekeeping - ([File: internal/git/objectpool/fetch.go])

### Summary
`ObjectPool.FetchFromOrigin` (invoked by the unprivileged/ordinary-user-reachable `FetchIntoObjectPool` RPC whenever a fork's pool is refreshed) prunes pool references and then runs `git fsck --connectivity-only --dangling` to detect dangling objects, creating one `refs/dangling/$OID` reference per dangling object via `rescueDanglingObjects` [1](#0-0) . There is no cap, batching, or cleanup mechanism for this reference namespace — every dangling object ever produced by a force-push/prune in any pool member accumulates forever in the pool as demonstrated in the design docs [2](#0-1) .

### Finding Description
Any ordinary user who can push to a fork that is a member of an object pool can trigger `FetchFromOrigin` via `FetchIntoObjectPool`, which prunes references (`pruneReferences`) and then re-fetches from the origin with pruning enabled [3](#0-2) . Repeated force-pushes create repeated batches of now-unreferenced ("dangling") objects, and each such batch is permanently kept alive in the pool by creating a new `refs/dangling/$OID` reference for every dangling object found by `git fsck` [4](#0-3) . This is the same "unbounded loop over storage-controlled state" pattern as the report: the `allPairs` array grows via unprivileged `createPair` calls, and a maintenance function (`setPeriodSize`) later iterates the entire array in one shot. Here, the `refs/dangling/` namespace grows via unprivileged force-pushes, and every subsequent `FetchIntoObjectPool` call must scan and process the *entire* namespace (via `fsck --dangling`, `for-each-ref`, `pack-refs`, and `git-repack`) with no ability to reduce it, exactly as flagged in Gitaly's own documentation: "For busy repositories, we generate loads of dangling references... Fetches into the object pool and repacking of references can thus become quite expensive" [5](#0-4) .

### Impact Explanation
As the dangling-reference set grows without bound, every future `FetchIntoObjectPool` call (and the pool's housekeeping/repack cycle) becomes progressively more expensive: `git fsck --dangling`, `git for-each-ref` in `logStats`, and `git-pack-refs`/`git-repack` during housekeeping all must process every dangling reference [6](#0-5) . Eventually this can make pool housekeeping so slow that it exceeds RPC or worker timeouts, permanently degrading the pool's fetch/repack maintenance for all members, similar to how the report's `setPeriodSize` becomes uncallable once `allPairs` grows past the gas limit. Because there is no mechanism inside Gitaly to remove `refs/dangling/*` entries (they are intentionally kept forever as a safety net), the condition is not self-healing.

### Likelihood Explanation
This requires no privileged access: any user capable of pushing (including force-pushing) to a fork/pool-member repository whose pool is periodically refreshed via `FetchIntoObjectPool` can repeatedly force-push and delete/overwrite branches to generate dangling objects. Over many pool-refresh cycles the dangling-reference count accumulates monotonically, so likelihood of eventually reaching a degraded/DoS state scales directly with how often the attacker can force-push and how often the pool is refreshed — a plausible and easily automatable pattern for a busy or targeted fork.

### Recommendation
Bound the growth of `refs/dangling/*`: e.g., cap the number of dangling refs created per fetch cycle, batch/paginate `fsck`/`for-each-ref` processing of the dangling namespace, or introduce a safe, well-reasoned expiration/garbage-collection policy for dangling refs (with adequate safety margins for concurrent pool member reads) rather than keeping every dangling object alive indefinitely. At minimum, add metrics/alerts and a hard ceiling so a single member's force-push behavior cannot unboundedly inflate pool housekeeping cost.

### Proof of Concept
1. Create an object pool and link a repository to it as described in `doc/object_pools.md`.
2. In the pool member, repeatedly: push a branch with a large tree/commit, then force-push a divergent history so the previous commit/tree/blobs become unreachable.
3. After each round, call `FetchIntoObjectPool`; observe `rescueDanglingObjects` creates a growing number of `refs/dangling/$OID` entries that are never removed [7](#0-6) .
4. Repeat at scale; observe `logStats`'s `for-each-ref` scan and pool housekeeping (`pack-refs`/`repack`) durations grow proportionally to the accumulated dangling reference count, with no cap on that growth [8](#0-7) .

// rescueDanglingObjects creates refs for all dangling objects if finds
// with `git fsck`, which converts those objects from "dangling" to
// "not-dangling". This guards against any object ever being deleted from
// a pool repository. This is a defense in depth against accidental use
// of `git prune`, which could remove Git objects that a pool member
// relies on. There is currently no way for us to reliably determine if
// an object is still used anywhere, so the only safe thing to do is to
// assume that every object _is_ used.
func (o *ObjectPool) rescueDanglingObjects(ctx context.Context) (returnedErr error) {
	stderr := &bytes.Buffer{}
	fsck, err := o.Repo.Exec(ctx, gitcmd.Command{
		Name:  "fsck",
		Flags: []gitcmd.Option{gitcmd.Flag{Name: "--connectivity-only"}, gitcmd.Flag{Name: "--dangling"}},
	},
		gitcmd.WithStderr(stderr),
		gitcmd.WithSetupStdout(),
	)
	if err != nil {
		return err
	}

	updater, err := updateref.New(ctx, o.Repo, updateref.WithDisabledTransactions())
	if err != nil {
		return err
	}
	defer func() {
		if err := updater.Close(); err != nil && returnedErr == nil {
			returnedErr = fmt.Errorf("cancel updater: %w", err)
		}
	}()

	if err := updater.Start(); err != nil {
		return fmt.Errorf("start reference transaction: %w", err)
	}

	objectHash, err := o.ObjectHash(ctx)
	if err != nil {
		return fmt.Errorf("detecting object hash: %w", err)
	}

	scanner := bufio.NewScanner(fsck)
	for scanner.Scan() {
		split := strings.SplitN(scanner.Text(), " ", 3)
		if len(split) != 3 {
			continue
		}

		if split[0] != "dangling" {
			continue
		}

		danglingObjectID, err := objectHash.FromHex(split[2])
		if err != nil {
			return fmt.Errorf("parsing object ID %q: %w", split[2], err)
		}

		ref := git.ReferenceName(danglingObjectNamespace + split[2])
		if err := updater.Create(ref, danglingObjectID); err != nil {
			return err
		}
	}

func (o *ObjectPool) logStats(ctx context.Context, when string) error {
	fields := log.Fields{
		"when": when,
	}

	repoInfo, err := stats.RepositoryInfoForRepository(ctx, o.Repo)
	if err != nil {
		return fmt.Errorf("deriving repository info: %w", err)
	}
	fields["repository_info"] = repoInfo

	forEachRef, err := o.Repo.Exec(ctx, gitcmd.Command{
		Name:  "for-each-ref",
		Flags: []gitcmd.Option{gitcmd.Flag{Name: "--format=%(objecttype)%00%(refname)"}},
		Args:  []string{"refs/"},
	}, gitcmd.WithSetupStdout())
	if err != nil {
		return fmt.Errorf("spawning for-each-ref: %w", err)
	}

	var danglingTypes, normalTypes referencedObjectTypes
	scanner := bufio.NewScanner(forEachRef)
	for scanner.Scan() {
		objectType, refname, found := bytes.Cut(scanner.Bytes(), []byte{0})
		if !found {
			continue
		}

		types := &normalTypes
		if bytes.HasPrefix(refname, []byte(danglingObjectNamespace)) {
			types = &danglingTypes
		}

		switch {
		case bytes.Equal(objectType, []byte("blob")):
			types.Blobs++
		case bytes.Equal(objectType, []byte("commit")):
			types.Commits++
		case bytes.Equal(objectType, []byte("tag")):
			types.Tags++
		case bytes.Equal(objectType, []byte("tree")):
			types.Trees++
		}
	}

	if err := scanner.Err(); err != nil {
		return fmt.Errorf("scanning references: %w", err)
	}
	if err := forEachRef.Wait(); err != nil {
		return fmt.Errorf("waiting for for-each-ref: %w", err)
	}

	fields["references.dangling"] = danglingTypes
	fields["references.normal"] = normalTypes

	o.logger.WithFields(fields).InfoContext(ctx, "pool dangling ref stats")

	return nil
}
