### Title
Graduation Permanently Blocked by Pre-Creating the DEX Pool — (`aptos-move/move-examples/bonding_curve_launchpad/sources/liquidity_pairs.move`)

---

### Summary

The `graduate` function in `liquidity_pairs.move` calls `router::create_pool_coin<AptosCoin>(fa_object_metadata, false)` to create an APT/FA pool on the external DEX. Because `router::create_pool_coin` is a permissionless `public entry` function and `liquidity_pool::create` aborts if the named-object pool already exists, any unprivileged actor can pre-create the pool before graduation occurs. Once the pool exists, every swap that would push APT reserves above `APT_LIQUIDITY_THRESHOLD` permanently reverts, the bonding curve can never graduate, and the FA remains permanently frozen for external transfers.

---

### Finding Description

**Root cause — `graduate` assumes the DEX pool does not yet exist:** [1](#0-0) 

```move
fun graduate(...) {
    liquidity_pair.is_enabled = false;
    liquidity_pair.is_frozen = false;
    // ← aborts if pool already exists
    router::create_pool_coin<AptosCoin>(fa_object_metadata, false);
    ...
}
```

`graduate` is called unconditionally from `swap_apt_to_fa` whenever `apt_updated_reserves > APT_LIQUIDITY_THRESHOLD`: [2](#0-1) 

**The DEX pool creation is permissionless:**

`router::create_pool_coin` is a `public entry` function with no access control: [3](#0-2) 

It delegates to `liquidity_pool::create`, which calls `create_lp_token` → `object::create_named_object`. `create_named_object` aborts with `EOBJECT_EXISTS` if an `ObjectCore` already exists at the deterministic pool address: [4](#0-3) [5](#0-4) 

**The FA address is publicly computable:**

The FA metadata object address is derived deterministically from `name` and `symbol` via `get_fa_obj_address`, which is a `#[view]` function: [6](#0-5) 

A griefer can compute the FA metadata address off-chain and call `router::create_pool_coin<AptosCoin>(fa_metadata, false)` at any time before graduation.

---

### Impact Explanation

Once the pool is pre-created:

1. Every call to `swap_apt_to_fa` that would push `apt_updated_reserves` above `APT_LIQUIDITY_THRESHOLD` reverts permanently — the bonding curve is wedged at the threshold.
2. `liquidity_pair.is_frozen` is never set to `false` (only done inside `graduate`), so the FA remains permanently frozen for external transfers. Users can only interact with it through the bonding curve's own swap functions.
3. The FA can never graduate to the external DEX, permanently denying the intended protocol lifecycle.

The FA tokens held by users are permanently non-transferable outside the launchpad, matching the "permanent freezing of fungible assets" impact category.

---

### Likelihood Explanation

- The attack requires a single, cheap, permissionless transaction (`router::create_pool_coin`) callable by any account.
- The target FA address is publicly computable from the `name` and `symbol` strings, which are emitted in the `FungibleAssetCreated` event.
- The attack window is the entire period from FA creation until graduation (potentially hours or days of trading).
- No special privileges, tokens, or capital are required.

---

### Recommendation

In `graduate`, replace the unconditional `router::create_pool_coin` call with a conditional check:

```move
// Only create the pool if it does not already exist
let (pool_exists, _) = liquidity_pool::liquidity_pool_address_safe(
    coin_wrapper::get_wrapper<AptosCoin>(), fa_object_metadata, false
);
if (!pool_exists) {
    router::create_pool_coin<AptosCoin>(fa_object_metadata, false);
};
```

Additionally, add slippage protection to `add_liquidity_coin_entry_transfer_ref` (currently `amount_1_min: 0, amount_2_min: 0`) so that if the pool was pre-seeded with liquidity at a manipulated price, the graduation transaction reverts rather than providing LP at an unfavorable rate.

---

### Proof of Concept

1. Alice calls `bonding_curve_launchpad::create_fa_pair(...)` to create `SheepyCoin/SHEEP`.
2. Bob (griefer) reads the `FungibleAssetCreated` event, computes `fa_metadata = get_fa_obj_address("SheepyCoin", "SHEEP")`, and calls:
   ```
   router::create_pool_coin<AptosCoin>(fa_metadata, false)
   ```
   This creates the APT/SHEEP pool on the external DEX. Cost: gas only.
3. Trading continues on the bonding curve. When cumulative APT swaps push `apt_updated_reserves` above `APT_LIQUIDITY_THRESHOLD = 600_000_000_000`, `swap_apt_to_fa` triggers `graduate`.
4. `graduate` calls `router::create_pool_coin<AptosCoin>(fa_metadata, false)` → `liquidity_pool::create` → `create_named_object` → **aborts with `EOBJECT_EXISTS`**.
5. The entire `swap_apt_to_fa` transaction reverts. Any subsequent swap that would cross the threshold also reverts.
6. `is_frozen` is never cleared. SHEEP tokens are permanently frozen for external transfers. The bonding curve is permanently stuck.
