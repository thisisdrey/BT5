### Title
Protocol fees on `Nep245`/`Imt` token trades can be bypassed by splitting a `TokenDiff` into unit-sized (`|delta| == 1`) legs - (File: contracts/defuse/core/src/intents/token_diff.rs)

### Summary
`TokenDiff::token_fee` deliberately waives the protocol fee whenever the absolute delta on a `Nep245` or `Imt` token in a single `TokenDiff` intent is `1` or less, to avoid meaningless rounding on indivisible unit transfers. Because fee assessment is performed strictly per-token-per-intent rather than on the account's aggregate traded volume, an attacker can decompose an arbitrarily large `Nep245`/`Imt` trade into many separate `TokenDiff` intents each moving exactly `1` unit, and pay zero fee on the entire volume, while the same volume moved in one intent would be fee-bearing.

### Finding Description
In `execute_intent` for `TokenDiff`, the fee is computed independently for every negative delta encountered in that single intent's `diff` map: [1](#0-0) 

The fee rate itself is determined by `token_fee`, which explicitly zeroes the fee for `Nep245`/`Imt` tokens when the per-intent amount is `<= 1`: [2](#0-1) 

There is no tracking of cumulative volume moved by an account/token pair across multiple `TokenDiff` intents within the same `execute_intents`/`MultiPayload` batch (or across separate calls). Consequently, the binding "fees owed" (based on true traded volume) versus "fees collected" (based on the artificially fragmented per-intent amount) is broken: a signer can settle N units of a fee-bearing `Nep245`/`Imt` token via N intents of `delta = ±1` each, matched against N counter-legs, and the `fees_collected` accumulator in every single execution stays `Pips::ZERO`, so `internal_add_balance` to the fee collector is never invoked.

### Impact Explanation
This crosses the "fees owed versus fees collected" boundary called out as in-scope: the protocol under-collects fees it is otherwise entitled to on `Nep245`/`Imt` trades, while the attacker (a solver or any pair of colluding accounts) keeps the full amount that would otherwise have gone to `fee_collector`. This matches the Critical impact category "fees bypassed or over-collected".

### Likelihood Explanation
Any unprivileged account pair that wants to trade a `Nep245` or `Imt` token can trivially construct N unit-sized `TokenDiff` intents instead of one, and submit them together in a single `execute_intents`/`simulate_intents` call (or sequentially). No special role, relayer key, or victim cooperation is needed—both counterparties are complicit attackers who mutually benefit from fee avoidance. The only cost is additional signing/verification overhead per unit, which is a fixed, bounded cost unrelated to gas exhaustion concerns.

### Recommendation
Assess the fee based on the fungible unit's economically meaningful traded volume rather than per-intent granularity for `Nep245`/`Imt` tokens: e.g., only waive the fee for token IDs that are truly non-fungible (NFT-like, single-supply), or track/aggregate volume per signer/token across the intents in an execution batch before deciding whether the `<= 1` waiver applies.

### Proof of Concept
1. Configure `defuse` with a non-zero `fee` in `FeesConfig` (see `FeesManager::set_fee` in `contracts/defuse/src/contract/fees.rs`).
2. Two accounts, Alice and Bob, want to swap `1000` units of a `Nep245` token A for `1000` units of `Nep245` token B.
3. Instead of one `TokenDiff` per account with `diff = {A: -1000, B: 1000}` (which would incur `token_fee(A, 1000, fee) = fee`), they each sign 1000 separate `TokenDiff` intents with `diff = {A: -1, B: 1}` / `{A: 1, B: -1}`.
4. Submit all 2000 signed intents together via `execute_intents`.
5. For every intent, `token_fee` returns `Pips::ZERO` because `amount <= 1` for the `Nep245` type, so `fees_collected` stays empty and `internal_add_balance` to the fee collector is never called — the full 1000-unit trade settles with zero protocol fee, whereas the equivalent single-intent trade would have paid `fee_ceil(1000)`.

    pub fn token_fee(token_id: impl Into<TokenIdType>, amount: u128, fee: Pips) -> Pips {
        let token_id = token_id.into();
        match token_id {
            TokenIdType::Nep141 => {}
            TokenIdType::Nep245 | TokenIdType::Imt if amount > 1 => {}
            // do not take fees on NFTs and MTs with |delta| <= 1
            TokenIdType::Nep171 | TokenIdType::Nep245 | TokenIdType::Imt => return Pips::ZERO,
        }
        fee
    }
