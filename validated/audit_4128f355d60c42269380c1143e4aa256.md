The reported bug is specific to As4626.sol's queued-redemption vault pattern, where `_withdraw()` uses `AsMaths.min(last.sharePrice, request.sharePrice)` as a "worst price" for a pending withdrawal request, and `last.sharePrice` is not corrected afterward, causing `sharePrice()`/`totalAccountedAssets()` to drift.

marginfi-v2 has no analogous mechanism. Bank accounting is share-value based and updated deterministically on every state-changing instruction:

- `Bank::accrue_interest` recomputes and stores `asset_share_value`/`liability_share_value` directly from `total_assets`/`total_liabilities` every time it runs, with no separate "worst price" or queued-request price used elsewhere. [1](#0-0) 
- Withdrawals (`lending_account_withdraw`) call `bank.accrue_interest()` first, then compute `share_amount` directly via `bank_account.withdraw()` using the just-updated `asset_share_value` — there is no separate withdrawal request object carrying a stale price that later gets compared/min'd against a "current" price. [2](#0-1) 
- Even the admin-only `super_admin_withdraw` path recomputes `asset_share_value` immediately from `assets_after / total_asset_shares` in the same instruction, with no deferred/queued price. [3](#0-2) 
- The JupLend integration (`juplend_withdraw`) does use an exchange-price-based share/asset conversion, but this is a direct, synchronous conversion against the freshly-refreshed `token_exchange_price` (via `cpi_update_rate()`), not a stored/pending "worst-of" price; the resulting rounding loss is small, bounded, and explicitly tested/asserted as expected behavior rather than an unbounded, uncorrected drift. [4](#0-3) [5](#0-4) 

There is no pending-withdrawal-request/queue construct in marginfi-v2's core margin account, bank, liquidation, or JupLend/Kamino/Drift integration paths that stores a stale share price and later reconciles it incorrectly against a "worst of" comparison, so the described root cause (stale `last.sharePrice` not reflecting the actual worst-price withdrawal) does not reproduce in this codebase.

                    signer: None
                },

                mint: self.mint,

                fees_collected: 0.,
                insurance_collected: 0.,
            });

            insurance_fees_collected,
            group_fees_collected,
