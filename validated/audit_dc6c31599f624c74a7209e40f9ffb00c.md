Audit Report

## Title
On-demand spot-traffic decay formula omits the base term, letting an attacker crash blockspace pricing to near-floor with a single call - (File: `polkadot/runtime/parachains/src/on_demand/mod.rs`)

## Summary
`Pallet::calculate_spot_traffic` correctly implements the increasing branch as `traffic * (1 + diff + diff²/2)`, but the decreasing branch computes `traffic * (diff − diff²/2)` instead of the intended `traffic * (1 − diff + diff²/2)`. [1](#0-0)  This means any under-target queue utilization causes `traffic` (and hence `spot_price`) to collapse toward zero rather than decaying gently, since the multiplier becomes the raw deviation `diff` instead of a near-unity factor centered at `1`.

## Finding Description
The increasing (`positive`) branch mirrors `pallet_transaction_payment`'s `TargetedFeeAdjustment` pattern, multiplying `traffic` by `(1 + queue_util_diff + div_by_two)`: [2](#0-1) 

The decreasing branch omits the `One::one()` term entirely: [3](#0-2) 

Since `queue_util_diff` is a `Perbill`-derived `FixedU128` in `[0,1]`, for any partial under-utilization (e.g. `diff = 0.1`), the correct decay multiplier should be close to `1` (e.g. `≈0.905`), but the buggy code instead computes `diff − div_by_two ≈ 0.095`, i.e. it multiplies `traffic` directly by the deviation magnitude rather than by a value near unity. This produces an almost-instant ~90% collapse of `traffic` for only a 10% under-utilization in a single block, instead of the intended gradual reduction.

`traffic` feeds directly into `spot_price` computation in `do_place_order`, which gates and prices `place_order_allow_death`/`place_order_with_credits`, both public, unprivileged extrinsics: [4](#0-3) 

The existing unit tests (`spot_traffic_can_decrease`, `spot_traffic_decreases_over_time`) only exercise `diff = 1.0` (fully empty queue vs. 100% target) with `variability = 100%`, where the buggy formula `diff − diff²/2` and the intended `1 − diff + diff²/2` numerically coincide (`0.5` for both when `diff=1`), masking the discrepancy for any smaller/partial `diff`: [5](#0-4) 

## Impact Explanation
The on-demand pricing mechanism exists to ramp price up during congestion and decay it gradually back toward the floor when demand subsides, preserving anti-congestion economics. The verified bug inverts the decay guarantee: any modest under-utilization (e.g. queue draining from full to 40% against a 50% target) causes `traffic` to crash almost instantly toward `TrafficDefaultValue` in a single block instead of the intended gentle reduction, since the multiplier used is the raw deviation `diff` rather than a value near `1`. This allows subsequent orders to be charged a near-minimum `spot_price` (derived from `on_demand_base_fee`) far below the intended congestion-adjusted price, matching the "public underpriced work that degrades block production" impact category in the gate.

## Likelihood Explanation
The bug requires no privileged access — it is triggered purely by normal queue dynamics (orders draining or a brief pause in ordering), which any account interacting with `place_order_allow_death`/`place_order_with_credits` can passively or actively induce. No governance, validator, or malicious peer/relayer assumptions are needed; the miscalculation occurs automatically inside `update_spot_traffic` on every block via `on_initialize`, and is exploitable by any actor wishing to buy blockspace at depressed prices simply by waiting for a below-target block.

## Recommendation
Rewrite the decreasing branch to center the multiplier at `1`, matching the structure of the increasing branch, e.g.:
```rust
let new_traffic = One::one()
    .saturating_sub(queue_util_diff)
    .saturating_add(div_by_two)
    .saturating_mul(traffic);
```
Add regression tests with `diff < 1` (partial under-utilization) and `variability < 100%` to catch this asymmetry, since the current tests only cover the `diff = 1.0` edge case where the bug is numerically masked.

## Proof of Concept
1. Configure `on_demand_target_queue_utilization = 50%`, `on_demand_fee_variability = 100%`, `queue_capacity = 100`.
2. Elevate `traffic` to `100` via prior congestion.
3. Let queue drain to `queue_size = 40` (`diff = 10%`, below target, negative branch executes).
4. Compute `var_times_qud = 0.1`, `div_by_two ≈ 0.005`.
   - Actual code: `new_traffic = (0.1 − 0.005) * 100 ≈ 9.5` (~90% collapse).
   - Intended: `new_traffic = (1 − 0.1 + 0.005) * 100 ≈ 90.5` (~10% reduction).
5. Extend `spot_traffic_can_decrease`/`spot_traffic_decreases_over_time` in `polkadot/runtime/parachains/src/on_demand/tests.rs` with `queue_size = 40, queue_capacity = 100, target = 50%` to observe the ~10x discrepancy directly in a unit test, confirming `spot_price = traffic.saturating_mul_int(on_demand_base_fee)` is priced far below the intended congestion-adjusted value after only one under-target block.

fn spot_traffic_can_decrease() {

		100u32,
		0u32,
		Perbill::from_percent(100),

	}
