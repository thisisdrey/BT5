### Title
Bankruptcy permanently disables a `MarginfiAccount` with no path to ever close it, permanently locking the account's rent and PDA slot - ([File: programs/marginfi/src/state/marginfi_account.rs])

### Summary
This is the closest reachable analog to the reported bug class: once a `MarginfiAccount` reaches a terminal "disabled" state through `handle_bankruptcy`, there is no instruction path — permissioned or permissionless — that can ever close it. Both closing instructions (`marginfi_account_close` and `admin_close_account`) unconditionally require the account to *not* be disabled, so a bankrupted account (empty of any balances, with no debt) remains open on-chain forever, permanently locking its rent-exempt SOL and, for PDA-based accounts, its `(group, authority, account_index, third_party_id)` seed slot.

### Finding Description
`lending_pool_handle_bankruptcy` sets `ACCOUNT_DISABLED` on the account being resolved as part of normal, expected bad-debt handling: [1](#0-0) 

`MarginfiAccountImpl::can_be_closed` is the single gate used by both closing instructions, and it hard-requires the account to not carry the `ACCOUNT_DISABLED` flag, in addition to having empty balances: [2](#0-1) 

The user-authority close path enforces this same invariant with no override: [3](#0-2) 

The permissionless "sweep" close path (intended precisely to reclaim rent for stale/empty accounts after 60 days of inactivity) enforces the identical `can_be_closed()` check, so it is blocked by the same flag: [4](#0-3) 

There is no instruction anywhere in the program that clears `ACCOUNT_DISABLED` once bankruptcy sets it (the flag comments confirm it is meant to be a durable, protocol-set marker, and the fuzz-invariant tests explicitly note that `ACCOUNT_DISABLED` is excluded from the "must never be stuck" invariant checks precisely because bankruptcy is expected to leave it set): [5](#0-4) 

This is structurally the same bug class as the external report: a normal, in-scope protocol flow (bankruptcy resolution, analogous to "auction rejected") drives an account/pool into a terminal default/disabled state, and afterward every closing path is guarded by a check that this exact state fails, with no conditional escape hatch or alternate closing instruction (analogous to `PoolBase.sol`'s `close()`/`allowWithdrawalAfterNoAuction()` both reverting on a rejected auction).

### Impact Explanation
After `handle_bankruptcy` runs (which can be permissionless when `PERMISSIONLESS_BAD_DEBT_SETTLEMENT_FLAG` is set on the bank, per the bankruptcy guide), the affected `MarginfiAccount`:
- Can never be closed by its own authority via `marginfi_account_close`.
- Can never be closed permissionlessly via `admin_close_account`, even though that instruction exists specifically to reclaim rent from empty/inactive accounts.
- Permanently locks the account's rent-exempt SOL balance (paid originally by the account's fee payer at `MarginfiAccountInitialize`).
- For PDA-derived accounts, permanently occupies the `(group, authority, account_index, third_party_id)` seed, since a new account can't be initialized at the same PDA while the old (disabled) account still exists.

This satisfies the "permanent lock/freeze" impact bar: real user funds (rent) and a real on-chain resource (the PDA account slot) become unrecoverable through any code path, with no admin override, migration route, or sweep mechanism provided.

### Likelihood Explanation
Bankruptcy is documented as rare but is an intended, reachable part of the bank/lending lifecycle (triggered by illiquid assets, oracle gaps, or under-serviced liquidations), and can be executed permissionlessly for banks configured with `PERMISSIONLESS_BAD_DEBT_SETTLEMENT_FLAG`. Any account that goes through this path — which requires no special privilege from the affected user and is a normal (if infrequent) outcome of risk management — is deterministically and permanently affected. This is not a mocked-only or purely theoretical condition; it is exercised directly in the project's own test suite (`programs/marginfi/tests/admin_actions/bankruptcy_auth.rs`, `programs/marginfi/tests/admin_actions/bankruptcy.rs`), which confirms `ACCOUNT_DISABLED` is set and never cleared.

### Recommendation
Add an explicit, gated closing path for accounts disabled purely by bankruptcy (as opposed to disabled for other reasons, e.g. mid-flashloan/receivership), for example:
- Extend `can_be_closed()` (or add a bankruptcy-specific bypass) to permit closing when `ACCOUNT_DISABLED` is set solely due to `indexer_flags.has_been_bankrupted == 1`, all balances are empty, and no other blocking flags/records are present.
- Alternatively, add a dedicated `admin_close_bankrupt_account` (or extend `admin_close_account`) instruction that allows the permissionless/admin sweep to reclaim rent from disabled-and-empty bankrupt accounts after some cooldown, mirroring the existing 60-day inactivity sweep design.
- Document this terminal state and its rent-recovery mechanism explicitly in `guides/RISK_AND_LIQUIDATORS/BANKRUPTCY.md` and `guides/DEVELOPERS_INTEGRATORS/ACCOUNT_LIFECYCLE.md`.

### Proof of Concept
1. Set up a bank with `PERMISSIONLESS_BAD_DEBT_SETTLEMENT_FLAG` (or use the group admin/risk admin).
2. Create a borrower `MarginfiAccount`, deposit collateral, borrow against it (see `programs/marginfi/tests/admin_actions/bankruptcy.rs` / `bankruptcy_auth.rs` fixtures for exact setup).
3. Drive the account's equity below `BANKRUPT_THRESHOLD` with liabilities exceeding assets (e.g. via `nullify_assets_for_bank`, as done in `programs/marginfi/tests/admin_actions/actions_during_pause.rs:711`).
4. Call `lending_pool_handle_bankruptcy`; observe `account_flags` now includes `ACCOUNT_DISABLED` (see assertion at `programs/marginfi/tests/admin_actions/bankruptcy_auth.rs:216`) and all liability/asset shares are zeroed.
5. Attempt `marginfi_account_close` from the authority: fails, `can_be_closed()` returns `false` because `is_disabled == true` (`programs/marginfi/src/instructions/marginfi_account/close.rs:26-29`).
6. Wait 60+ days and attempt `admin_close_account` permissionlessly: fails for the same reason (`programs/marginfi/src/instructions/marginfi_account/admin_close.rs:26-30`).
7. No other program instruction exists to clear `ACCOUNT_DISABLED` for a bankrupted account — the account and its rent are permanently stuck.

pub fn close_account(ctx: Context<MarginfiAccountClose>) -> MarginfiResult {
    let marginfi_account = &ctx.accounts.marginfi_account.load()?;

    if marginfi_account.get_flag(ACCOUNT_FROZEN) {
        return err!(MarginfiError::AccountFrozen);
    }

    check!(
        marginfi_account.liquidation_record == Pubkey::default(),
        MarginfiError::IllegalAction,
        "Close liquidation record before closing account"
    );

    check!(
        marginfi_account.active_orders == 0,
        MarginfiError::IllegalAction,
        "Close all active orders before closing account"
    );

    check!(
        marginfi_account.can_be_closed(),
        MarginfiError::IllegalAction,
        "Account cannot be closed"
    );

    Ok(())
}
```

pub fn admin_close_account(ctx: Context<AdminCloseAccount>) -> MarginfiResult {
    let marginfi_account = ctx.accounts.marginfi_account.load()?;
    let clock = Clock::get()?;
    let elapsed = clock
        .unix_timestamp
        .saturating_sub(marginfi_account.last_update as i64);
    let is_inactive = elapsed > 60 * SECONDS_PER_DAY;

    check!(
        marginfi_account.can_be_closed() && is_inactive,
        MarginfiError::IllegalAction,
        "Account is not eligible for close (not empty or active within 60d)"
    );

    check!(
        !marginfi_account.get_flag(ACCOUNT_IN_DELEVERAGE)
            && !marginfi_account.get_flag(ACCOUNT_IN_ORDER_EXECUTION)
            && marginfi_account.active_orders == 0
            && marginfi_account.liquidation_record == Pubkey::default(),
        MarginfiError::IllegalAction,
        "Account cannot be closed"
    );
```
