### Title
Empty repository relative path silently disables per-repository concurrency limiting - ([File: internal/grpc/middleware/limithandler/middleware.go])

### Summary
`LimitConcurrencyByRepo` derives the concurrency-limiter lock key from `info.Repository.GetRelativePath()`, and both the unary and streaming interceptors treat an empty lock key as "do not limit at all" rather than as an error, mirroring the Vyper `@nonreentrant("")` class of bug where an empty guard key silently produces no protection instead of failing safe.

### Finding Description
`LimitConcurrencyByRepo` computes the per-repository lock key purely from the request's `Repository.GetRelativePath()` field: [1](#0-0) 

Both the `UnaryInterceptor` and the stream `RecvMsg` handler then explicitly special-case an empty key as "skip the limiter entirely": [2](#0-1) [3](#0-2) 

This is structurally identical to the Vyper flaw: a lock/guard mechanism keyed by a string, where the empty-string case is treated as "no lock configured" and the enforcement path is bypassed rather than rejected. Here, `GetLockKey` returning `""` is used both (a) as the legitimate signal "the RPC has no target repository, don't limit" and (b) indistinguishably as the case "the RPC does have a repository message but its `relative_path` field is empty." Since these interceptors run in the gRPC middleware chain before service-level input validation executes inside the handler, a request carrying a `Repository` message with an empty `relative_path` (a value fully controllable by any authenticated client issuing an ordinary RPC) causes `lockKey == ""`, and the request is dispatched to the handler with **no concurrency limiting applied at all** — including bypassing the default, hardcoded `ReplicateRepository` limiter that is set up specifically to prevent unbounded concurrent replication load: [4](#0-3) 

### Impact Explanation
Any RPC that is normally protected by `LimitConcurrencyByRepo`-based concurrency limiting (per-RPC queues/semaphores meant to bound concurrent expensive operations such as `ReplicateRepository`, pack-objects-style RPCs, etc.) loses that protection whenever the request's repository message has an empty `relative_path`. An ordinary client can issue a flood of such requests, all keyed to the same empty string, completely unthrottled, exhausting Gitaly worker resources (CPU, memory, disk I/O) — a denial-of-service against the RPC-handler resource-limiting layer that the middleware exists to enforce. This matches the accepted "DoS of a handler" impact category.

### Likelihood Explanation
Reaching this path requires only sending a well-formed gRPC request to any RPC using `LimitConcurrencyByRepo` with the repository's `relative_path` field left empty. No privileged position, malicious peer, or leaked credentials are needed — this is exactly the kind of "ordinary user / crafted RPC field" input the review scope targets. The main uncertainty (not fully verifiable from the available index) is which specific production RPCs are registered with `LimitConcurrencyByRepo` as their `GetLockKey` and whether earlier validation middleware (e.g., a repository-existence or `relative_path`-non-empty check) runs *before* this interceptor in the chain for those RPCs; I was not able to confirm the exact interceptor ordering in `internal/gitaly/server/server.go` before running out of iterations.

### Recommendation
Distinguish "no repository present" from "repository present but with an empty/invalid relative path" in `LimitConcurrencyByRepo` (and any other `GetLockKey` implementation), and treat the latter as a request error (fail closed) rather than silently disabling the limiter — e.g., return a sentinel error or reject the request when `info.Repository != nil && info.Repository.GetRelativePath() == ""`, instead of returning `""` and having the interceptors interpret that as "skip limiting."

### Proof of Concept
1. Identify an RPC configured with `LimitConcurrencyByRepo` as its `GetLockKey` (e.g., one governed by `cfg.Concurrency` or the default `ReplicateRepository` limiter) and call it with a `Repository{ storage_name: "<valid>", relative_path: "" }`.
2. `requestinfohandler.Extract(ctx)` returns a non-nil `info` (since a `Repository` message is present), so `LimitConcurrencyByRepo` returns `info.Repository.GetRelativePath()` = `""`.
3. In `UnaryInterceptor`/`RecvMsg`, `lockKey == ""` triggers the early bypass branch, so `limiter.Limit(...)` is never invoked for this call.
4. Repeat the same request concurrently in a tight loop; because the concurrency limiter is skipped for every such call (they all key to `""` and hit the bypass branch, not merely share one bucket), the configured concurrency/queue caps for that RPC are never enforced, allowing unbounded concurrent execution of the (potentially expensive) handler.

// LimitConcurrencyByRepo implements GetLockKey by using the repository path as lock.
func LimitConcurrencyByRepo(ctx context.Context) string {
	if info := requestinfohandler.Extract(ctx); info != nil {
		return info.Repository.GetRelativePath()
	}

	return ""
}

func (c *LimiterMiddleware) UnaryInterceptor() grpc.UnaryServerInterceptor {
	return func(ctx context.Context, req interface{}, info *grpc.UnaryServerInfo, handler grpc.UnaryHandler) (interface{}, error) {
		lockKey := c.getLockKey(ctx)
		if lockKey == "" {
			return handler(ctx, req)
		}

		// Check if request is authenticated
		limiter := c.methodLimiters[info.FullMethod]
		unauthLimiter, ok := c.methodLimitersUnauthenticated[info.FullMethod]
		if !auth.IsAuthenticated(ctx) && ok {
			limiter = unauthLimiter
		}

		if limiter == nil {
			// No concurrency limiting
			return handler(ctx, req)
		}

		return limiter.Limit(ctx, lockKey, func() (interface{}, error) {
			return handler(ctx, req)
		})
	}
}

func (w *wrappedStream) RecvMsg(m interface{}) error {
	if err := w.ServerStream.RecvMsg(m); err != nil {
		return err
	}

	// Only perform limiting on the first request of a stream
	if !w.initial {
		return nil
	}

	w.initial = false

	ctx := w.Context()

	lockKey := w.limiterMiddleware.getLockKey(ctx)
	if lockKey == "" {
		return nil
	}

	// Check if request is authenticated

	if !auth.IsAuthenticated(ctx) && ok {
		limiter = unauthLimiter
	}

	if limiter == nil {
		// No concurrency limiting
		return nil
	}
