### Title
Unauthenticated `RecvError` message allows a certless remote to poison hostmap state and force-close another peer's tunnel - (File: outside.go)

### Summary
The `handleRecvError` function processes `RecvError` packets before any certificate or handshake authentication occurs. It looks up a live tunnel purely by the plaintext `RemoteIndex` field from the packet header and the observed UDP source address, then tears the tunnel down if those two values line up — with no cryptographic proof that the sender is the legitimate remote peer.

### Finding Description
`RecvError` (`header.RecvError`) is one of the packet types dispatched in `readOutsidePackets` before any decryption or cert verification takes place, alongside `Handshake`: [1](#0-0) 

`handleRecvError` is the handler invoked for these unauthenticated packets: [2](#0-1) 

The only two inputs used to authorize the state-changing action (`closeTunnel` + `DeleteHostInfo`) are:
1. `h.RemoteIndex` — a 32-bit value taken straight from the **plaintext** header (`h.RemoteIndex = binary.BigEndian.Uint32(b[4:8])`), which is sent unencrypted in the header of *every* Nebula packet type: [3](#0-2) 
2. `addr` — the UDP source address of the received packet, which is attacker-controllable via IP/UDP source spoofing since UDP is connectionless and Nebula's transport does not authenticate `RecvError` packets at all.

The mitigating check is:
```go
hr := hostinfo.GetRemote()
if hr.IsValid() && hr != addr {
    // reject as spoofed
}
f.closeTunnel(hostinfo)
```
This only rejects the packet if the hostinfo's cached remote address is set and mismatches the spoofed source. It does **not** verify that the sender possesses the peer's cryptographic keys or CA-signed certificate — the same architectural gap the external report identifies in `BribeVault.depositBribeERC20`, where a caller-supplied identifier (`bribeIdentifier`/briber) is trusted to authorize an action on someone else's resource without an ownership/authentication check tying the identifier to the actor. Here the "identifier" is `RemoteIndex` plus a spoofable source address, and the "resource" being manipulated is another peer's live, already-authenticated tunnel state.

Because `RemoteIndex` travels in cleartext on every packet (data, control, lighthouse, handshake), any network observer (or an attacker who can passively see traffic between two Nebula nodes, e.g., an on-path/adjacent-network attacker with no CA-issued certificate of their own) can learn a target's active `RemoteIndex` and forge a `RecvError` packet with a spoofed source `AddrPort` matching the real remote's known address, causing `handleRecvError` to call `f.closeTunnel(hostinfo)` and `f.handshakeManager.DeleteHostInfo(hostinfo)` on a legitimate tunnel.

### Impact Explanation
An attacker with no valid Nebula certificate can forcibly and repeatedly tear down established tunnels between legitimate peers by replaying/forging a single unauthenticated 16-byte header, causing denial of service and forcing costly re-handshakes network-wide. This maps to the "remote state poisoning" impact class: an unauthenticated party manipulates authoritative tunnel state (`HostMap`/`HandshakeManager`) belonging to two other, fully-authenticated parties, exactly mirroring how the BribeVault bug let an unrelated party manipulate another depositor's funds/state using a trusted-but-unvalidated identifier.

### Likelihood Explanation
Likelihood is moderate-to-high in threat models where the attacker can (a) observe network traffic (shared LAN, ISP-level, or otherwise on-path) to learn the plaintext `RemoteIndex`, and (b) spoof UDP source addresses, which is commonly feasible on unfiltered UDP paths (no BCP38 egress filtering) or is trivial for an attacker anywhere on the path between the two peers. `send_recv_error`/`accept_recv_error` config knobs (`recvErrorAlways`/`recvErrorNever`/`recvErrorPrivate`) only gate whether errors are emitted/accepted by endpoint privacy classification, not by authentication, so a misconfigured or default-permissive deployment remains exposed.

### Recommendation
Do not allow `RecvError` (or any pre-authentication packet type) to trigger destructive state changes based solely on an unauthenticated index + observed source address match. Require the `RecvError` message to be authenticated (e.g., MAC'd/encrypted using the existing tunnel's derived key, or accompanied by a proof tied to the `ConnectionState`) before acting on it, or at minimum rate-limit/ignore `RecvError` unless the source address exactly matches a previously roamed/validated remote and additional replay/nonce protection is enforced.

### Proof of Concept
1. Establish two legitimate Nebula nodes A and B with a valid CA and complete a handshake, creating an established tunnel with some `RemoteIndex` value `R` (visible in the plaintext header of every subsequent packet exchanged, e.g., `Message`/`Test`/`LightHouse` types).
2. As an attacker (no CA cert, only network visibility) capture one packet on the wire between A and B to learn `R` (`h.RemoteIndex`).
3. Craft an unencrypted `RecvError` packet: `header.Encode(buf, header.Version, header.RecvError, 0, R, 0)`.
4. Spoof the UDP source address to match B's known `AddrPort` and send this crafted packet to A.
5. In `handleRecvError` (outside.go:541), `f.hostMap.QueryReverseIndex(R)` resolves A's hostinfo for B; `hr := hostinfo.GetRemote()` equals the spoofed `addr`, so the spoof check passes, and `f.closeTunnel(hostinfo)` plus `f.handshakeManager.DeleteHostInfo(hostinfo)` execute — tearing down the legitimate A↔B tunnel without either party's cryptographic participation.

func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}

type H struct {
	Version        uint8
	Type           MessageType
	Subtype        MessageSubType
	Reserved       uint16
	RemoteIndex    uint32
	MessageCounter uint64
}

// Encode uses the provided byte array to encode the provided header values into.
// Byte array must be capped higher than HeaderLen or this will panic
func Encode(b []byte, v uint8, t MessageType, st MessageSubType, ri uint32, c uint64) []byte {
	b = b[:Len]
	b[0] = v<<4 | byte(t&0x0f)
	b[1] = byte(st)
	binary.BigEndian.PutUint16(b[2:4], 0)
	binary.BigEndian.PutUint32(b[4:8], ri)
	binary.BigEndian.PutUint64(b[8:16], c)
	return b
}

// String creates a readable string representation of a header
func (h *H) String() string {
	if h == nil {
		return "<nil>"
	}
	return fmt.Sprintf("ver=%d type=%s subtype=%s reserved=%#x remoteindex=%v messagecounter=%v",
		h.Version, h.TypeName(), h.SubTypeName(), h.Reserved, h.RemoteIndex, h.MessageCounter)
}

// MarshalJSON creates a json string representation of a header
func (h *H) MarshalJSON() ([]byte, error) {
	return json.Marshal(m{
		"version":        h.Version,
		"type":           h.TypeName(),
		"subType":        h.SubTypeName(),
		"reserved":       h.Reserved,
		"remoteIndex":    h.RemoteIndex,
		"messageCounter": h.MessageCounter,
	})
}

// Encode turns header into bytes
func (h *H) Encode(b []byte) ([]byte, error) {
	if h == nil {
		return nil, errors.New("nil header")
	}

	return Encode(b, h.Version, h.Type, h.Subtype, h.RemoteIndex, h.MessageCounter), nil
}

// Parse is a helper function to parses given bytes into new Header struct
func (h *H) Parse(b []byte) error {
	if len(b) < Len {
		return ErrHeaderTooShort
	}
	// get upper 4 bytes
	h.Version = uint8((b[0] >> 4) & 0x0f)
	// get lower 4 bytes
	h.Type = MessageType(b[0] & 0x0f)
	h.Subtype = MessageSubType(b[1])
	h.Reserved = binary.BigEndian.Uint16(b[2:4])
	h.RemoteIndex = binary.BigEndian.Uint32(b[4:8])
	h.MessageCounter = binary.BigEndian.Uint64(b[8:16])
