I found one notable candidate worth flagging: `CreateRepositoryFromSnapshot`'s `untar` explicitly documents that "the received archive is trusted *a lot*" without hardening against malicious archive content, but let me verify whether this constitutes a genuine, reachable, unvalidated-input analog before drawing a conclusion.## Finding

### Title
Unvalidated tar archive extraction leads to path traversal in `CreateRepositoryFromSnapshot` - (File: `internal/gitaly/service/repository/create_repository_from_snapshot.go`)

### Summary
Similar to the Solidity report where `mintDefault()` skipped `computeCollateralOrlvlUSDAmount()` and let raw user-supplied fields (`lvlusd_amount`, `collateral_amount`) reach the minting logic unchecked, Gitaly's `CreateRepositoryFromSnapshot` RPC fetches an archive from a caller-supplied `HttpUrl` and pipes its raw bytes directly into `tar -xvf -` without ever validating the entries contained in that archive.

### Finding Description
The RPC handler `(*server).CreateRepositoryFromSnapshot` validates the *repository* target, but not the *archive content* it is about to extract: [1](#0-0) 

The actual extraction is done in `untar()`, which streams the HTTP response body straight into the standard system `tar` binary: [2](#0-1) 

No archive-entry validation (e.g., rejecting `../` path components, absolute paths, symlinks, or hardlinks pointing outside `path`) is performed before invoking `tar -C path -xvf -`. The code comment itself acknowledges this gap explicitly: [3](#0-2) 

This is analogous to the `mintDefault()` bug: a security-critical operation (writing files onto disk / minting tokens) is performed on fully attacker-influenced input (`in.GetHttpUrl()`/tar stream contents; `lvlusd_amount`/`collateral_amount`) without first routing it through a validating function that would normally have caught the malicious values (`computeCollateralOrlvlUSDAmount()` in the Solidity case; an entry-sanitizing tar extractor in the Gitaly case).

Contrast this with the rest of the codebase, where the pattern is to always call `storage.ValidateRelativePath` or `storage.ValidateGitDirectory` before trusting a path, as seen throughout `internal/git/localrepo/paths.go` and `internal/gitaly/storage/locator.go`: [4](#0-3) 

`untar()` bypasses this pattern entirely by delegating path handling to the external `tar` binary on unsanitized archive content.

### Impact Explanation
If the archive fetched from `HttpUrl` (or an HTTP endpoint reachable via SSRF, since `HttpUrl`/`ResolvedAddress` are also caller-controlled) contains entries with `../` sequences, absolute paths, or symlinks, `tar -xvf -` will write files outside of the newly created repository directory, anywhere the Gitaly process has filesystem permissions. This can corrupt or overwrite arbitrary files on the Gitaly storage node (e.g. other repositories' data, Gitaly configuration, or hooks), constituting a storage escape / arbitrary file write. It could also be leveraged to plant malicious custom hooks in other repositories, escalating to remote code execution when those hooks are triggered.

### Likelihood Explanation
`CreateRepositoryFromSnapshot` is invoked as part of ordinary repository-import/move workflows (e.g., GitLab-initiated repository moves between Gitaly nodes) where the value of `HttpUrl` and the served archive content are effectively controlled by whichever endpoint is designated as the snapshot source. Since the archive content is not attacker-input-validated at all (per the code's own comment), any workflow that lets an untrusted or compromised source serve the snapshot immediately triggers unrestricted extraction. No additional privilege beyond triggering an import/move (a fairly ordinary operation) is required.

### Recommendation
Do not delegate directly to the external `tar` binary on unvalidated input. Either:
1. Use a Go tar extraction routine that explicitly validates each header's `Name`/`Linkname` resolves within `path` (rejecting `..`, absolute paths, and symlinks/hardlinks escaping the target directory) before extraction, mirroring the pattern used by `storage.ValidateRelativePath`; or
2. Pass hardening flags to the `tar` invocation (e.g., restricting extraction to regular files, disabling absolute/parent-path entries) and post-validate that all extracted paths remain within `path`.

### Proof of Concept
1. Set up (or compromise) an HTTP endpoint that `CreateRepositoryFromSnapshotRequest.HttpUrl` points to.
2. Serve a tar archive containing an entry such as `../../../another-repo/custom_hooks/pre-receive` (or an absolute path `/var/opt/gitlab/git-data/repositories/.../custom_hooks/pre-receive`) with executable content.
3. Invoke `CreateRepositoryFromSnapshot` targeting a new repository; `untar()` executes `tar -C <new-repo-path> -xvf -` on the malicious stream, causing the crafted file to be written outside the intended repository directory since no entry-path validation occurs before or during extraction.

func (s *server) untar(ctx context.Context, path string, in *gitalypb.CreateRepositoryFromSnapshotRequest) error {
	req, err := http.NewRequestWithContext(ctx, "GET", in.GetHttpUrl(), nil)
	if err != nil {
		return structerr.NewInvalidArgument("Bad HTTP URL: %w", err)
	}

	client := httpClient
	if resolvedAddress := in.GetResolvedAddress(); resolvedAddress != "" {
		client, err = newResolvedHTTPClient(in.GetHttpUrl(), resolvedAddress)
		if err != nil {
			return structerr.NewInvalidArgument("creating resolved HTTP client: %w", err)
		}
	}

	if in.GetHttpAuth() != "" {
		req.Header.Set("Authorization", in.GetHttpAuth())
	}

	rsp, err := client.Do(req)
	if err != nil {
		return structerr.NewInternal("HTTP request failed: %w", err)
	}
	defer rsp.Body.Close()

	if rsp.StatusCode < http.StatusOK || rsp.StatusCode >= http.StatusMultipleChoices {
		return structerr.NewInternal("HTTP server: %s", rsp.Status)
	}

	cmd, err := command.New(ctx, s.logger, []string{"tar", "-C", path, "-xvf", "-"}, command.WithStdin(rsp.Body))
	if err != nil {
		return err
	}

	return cmd.Wait()

// ValidateRelativePath validates a relative path by joining it with rootDir and verifying the result
// is either rootDir or a path within rootDir. Returns clean relative path from rootDir to relativePath
// or an ErrRelativePathEscapesRoot if the resulting path is not contained within rootDir.
func ValidateRelativePath(rootDir, relativePath string) (string, error) {
	absPath := filepath.Join(rootDir, relativePath)
	if rootDir != absPath && !strings.HasPrefix(absPath, rootDir+string(os.PathSeparator)) {
		return "", ErrRelativePathEscapesRoot
	}

	return filepath.Rel(rootDir, absPath)
}
