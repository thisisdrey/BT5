### Title
Unsigned integer underflow in housekeeping repack heuristic via crafted multi-pack-index (DoS/resource-exhaustion) - (File: internal/git/housekeeping/optimization_strategy.go)

### Summary
`HeuristicalOptimizationStrategy.ShouldRepackObjects` computes `untrackedPackfiles := s.info.Packfiles.Count - s.info.Packfiles.MultiPackIndex.PackfileCount` using unsigned `uint64` subtraction with no bounds check, mirroring the exact bug class fixed upstream in kaspanet/rusty-kaspa's `estimate_block_count()` (unchecked subtraction replaced with `saturating_sub()`). [2](#0-1) 

### Finding Description
`Packfiles.MultiPackIndex.PackfileCount` is parsed verbatim from the on-disk `multi-pack-index` file's binary header (`packfileCount := binary.BigEndian.Uint32(midxHeader[8:12])`) with no validation that this value corresponds to the number of `.pack` files actually present in the repository's `objects/pack` directory. [3](#0-2) 

`Packfiles.Count`, on the other hand, is derived independently by counting `pack-*.pack` files found on disk. [4](#0-3) 

If an attacker can write a `multi-pack-index` file whose embedded `PackfileCount` exceeds the real, on-disk `Packfiles.Count`, the subtraction `s.info.Packfiles.Count - s.info.Packfiles.MultiPackIndex.PackfileCount` underflows (both are `uint64`), wrapping around to a value near `math.MaxUint64`. This is reachable via `CreateRepositoryFromSnapshot`, whose handler extracts an HTTP-fetched TAR archive directly into the freshly created repository path and is explicitly documented as untrusted content ("the received archive is trusted *a lot*... it should undergo a lot of hardening"), and via the equivalent `ReplicateRepository`/`extractSnapshot` path that also extracts a streamed TAR into the repository directory. [5](#0-4) [6](#0-5) 

A nearby, structurally identical unchecked subtraction exists a few lines earlier in the same function: `nonCruftPackfilesCount := s.info.Packfiles.Count - s.info.Packfiles.CruftCount`, which is also derived from independently-computed, attacker-influenceable directory-scan counters (`CruftCount` increments per `.mtimes`-tagged packfile). [7](#0-6) [8](#0-7) 

### Impact Explanation
The resulting near-`MaxUint64` `untrackedPackfiles` value will always satisfy `untrackedPackfiles > uint64(actualLimit)`, forcing `ShouldRepackObjects` to return `true, geometricRepackCfg` on every housekeeping pass regardless of actual repository state. This forces repeated, unnecessary `git-repack(1)` invocations (and multi-pack-index/bitmap rewrites) on every housekeeping cycle for the affected repository, which scales with total object count and can be used to sustain excessive CPU/IO load on the Gitaly node — a repeated-DoS-of-housekeeping condition rather than a crash, since Go does not panic on unsigned wraparound (unlike Rust, where the analogous bug caused a literal panic).

### Likelihood Explanation
Reaching this path requires the ability to invoke `CreateRepositoryFromSnapshot` (or the internal `ReplicateRepository` snapshot-extraction path) with attacker-influenced archive contents, which is explicitly called out in code comments as an insufficiently hardened, "trusted a lot" surface, making a crafted `multi-pack-index` with an inflated packfile count plausible for any caller with access to that RPC/replication flow.

### Recommendation
Use `Packfiles.Count - min(Packfiles.Count, MultiPackIndex.PackfileCount)` or Go 1.21+ style saturating subtraction (e.g., a small `saturatingSub(a, b uint64) uint64` helper returning 0 when `b > a`) for both `untrackedPackfiles` and `nonCruftPackfilesCount` in `internal/git/housekeeping/optimization_strategy.go`. Additionally, validate at parse time in `MultiPackIndexInfoForPath` that a MIDX's declared `PackfileCount` does not exceed a sane bound (or cross-check it against the actual packfile count) before trusting it for heuristic decisions.

### Proof of Concept
1. Craft a repository snapshot archive containing: a small number of real `pack-*.pack`/`.idx` files (e.g., 1) plus a hand-crafted `objects/pack/multi-pack-index` file with a valid `MIDX` signature/version but with the 4-byte packfile-count field (bytes 8–11) set to a large value (e.g., `0xFFFFFFFF`).
2. Serve this archive over HTTP and call `CreateRepositoryFromSnapshot` with `http_url` pointing at it (or drive it through `ReplicateRepository`'s snapshot extraction).
3. On the next housekeeping/optimization pass, `PackfilesInfoForRepository` reports `Packfiles.Count = 1` and `MultiPackIndex.PackfileCount = 0xFFFFFFFF`; `ShouldRepackObjects` then computes `1 - 0xFFFFFFFF` as `uint64`, which underflows to a huge value, guaranteeing `untrackedPackfiles > actualLimit` and triggering a geometric repack on effectively every housekeeping run for that repository.

func (s *server) untar(ctx context.Context, path string, in *gitalypb.CreateRepositoryFromSnapshotRequest) error {
	req, err := http.NewRequestWithContext(ctx, "GET", in.GetHttpUrl(), nil)
	if err != nil {
		return structerr.NewInvalidArgument("Bad HTTP URL: %w", err)
	}

	client := httpClient
	if resolvedAddress := in.GetResolvedAddress(); resolvedAddress != "" {
		client, err = newResolvedHTTPClient(in.GetHttpUrl(), resolvedAddress)
		if err != nil {
			return structerr.NewInvalidArgument("creating resolved HTTP client: %w", err)
		}
	}

	if in.GetHttpAuth() != "" {
		req.Header.Set("Authorization", in.GetHttpAuth())
	}

	rsp, err := client.Do(req)
	if err != nil {
		return structerr.NewInternal("HTTP request failed: %w", err)
	}
	defer rsp.Body.Close()

	if rsp.StatusCode < http.StatusOK || rsp.StatusCode >= http.StatusMultipleChoices {
		return structerr.NewInternal("HTTP server: %s", rsp.Status)
	}

	cmd, err := command.New(ctx, s.logger, []string{"tar", "-C", path, "-xvf", "-"}, command.WithStdin(rsp.Body))
	if err != nil {
		return err
	}

	return cmd.Wait()
}

func (s *server) extractSnapshot(ctx context.Context, source, target *gitalypb.Repository) error {
	repoClient, err := s.newRepoClient(ctx, source.GetStorageName())
	if err != nil {
		return fmt.Errorf("new client: %w", err)
	}

	stream, err := repoClient.GetSnapshot(ctx, &gitalypb.GetSnapshotRequest{Repository: source})
	if err != nil {
		return fmt.Errorf("get snapshot: %w", err)
	}

	// We need to catch a possible 'invalid repository' error from GetSnapshot. On an empty read,
	// we read the first message from the stream here to get access to the possible 'invalid repository' error.
	firstBytes, err := stream.Recv()
	if err != nil {
		switch {
		case structerr.GRPCCode(err) == codes.NotFound && strings.Contains(err.Error(), "GetRepoPath: not a git repository:"):
			// The error condition exists for backwards compatibility purposes, only,
			// and can be removed in the next release.
			return ErrInvalidSourceRepository
		case structerr.GRPCCode(err) == codes.NotFound && strings.Contains(err.Error(), storage.ErrRepositoryNotFound.Error()):
			return ErrInvalidSourceRepository
		case structerr.GRPCCode(err) == codes.FailedPrecondition && strings.Contains(err.Error(), storage.ErrRepositoryNotValid.Error()):
			return ErrInvalidSourceRepository
		default:
			return fmt.Errorf("first snapshot read: %w", err)
		}
	}

	snapshotReader := io.MultiReader(
		bytes.NewReader(firstBytes.GetData()),
		streamio.NewReader(func() ([]byte, error) {
			resp, err := stream.Recv()
			return resp.GetData(), err
		}),
	)

	targetPath, err := s.locator.GetRepoPath(ctx, target, storage.WithRepositoryVerificationSkipped())
	if err != nil {
		return fmt.Errorf("target path: %w", err)
	}

	// Extract tar using Go's tar package
	if err := s.extractTarToDirectory(ctx, snapshotReader, targetPath); err != nil {
		return fmt.Errorf("extract tar: %w", err)
	}

	return nil
}
