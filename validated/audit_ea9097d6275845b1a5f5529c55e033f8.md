Audit Report

## Title
Permanent, irreversible loss of issuance/inflation in `pallet-dap::drip_issuance` when elapsed time exceeds `MaxElapsedPerDrip` - (File: substrate/frame/dap/src/lib.rs)

## Summary
`Pallet::<T>::drip_issuance()`, invoked from `on_initialize` every block, computes `elapsed = now - LastIssuanceTimestamp`, clamps it to `T::MaxElapsedPerDrip` when exceeded, mints/distributes issuance only for the clamped amount, but then unconditionally advances the checkpoint `LastIssuanceTimestamp` to `now` rather than `last + max_elapsed`. Any interval in which block production or `on_initialize` execution is delayed beyond the configured ceiling silently and permanently discards the uncredited remainder of issuance for that interval, reducing intended rewards distributed to stakers, validator incentive pots, and other `BudgetAllocation` recipients.

## Finding Description
In `drip_issuance`: [1](#0-0) 

The clamp branch emits `Event::Unexpected(UnexpectedKind::ElapsedClamped { actual_elapsed, ceiling })` and reduces `elapsed` to `max_elapsed`, but the very next line sets `LastIssuanceTimestamp::<T>::put(now)` using the actual, unclamped wall-clock time rather than `last.saturating_add(max_elapsed)`. This means the interval `[last + max_elapsed, now]` is never minted in this or any future call, because the next drip's `elapsed` computation starts from `now`, not from the point actually credited.

This is confirmed by the pallet's own test suite, which asserts this exact discard behavior as the expected outcome: [2](#0-1) 

With `MaxElapsedPerDrip = 600_000ms` and an actual elapsed of `1_200_000ms`, only `600_000ms` worth of issuance (`1000` units) is minted and the remaining `600_000ms` is dropped — `LastIssuanceTimestamp` becomes `now`, not `last + 600_000`.

The project's own prdoc documents the identical root cause for the one-shot migration path and states the fix (a catch-up drip) was applied only there: [3](#0-2) 

That fix did not touch the regular `drip_issuance` hook shown above, which retains the drop-on-clamp behavior for every subsequent stall exceeding `MaxElapsedPerDrip`.

## Impact Explanation
`drip_issuance` is called unconditionally from `on_initialize` on every block: [4](#0-3) . Any real-world stall in block production or delayed `on_initialize` execution beyond the configured `MaxElapsedPerDrip` ceiling causes a permanent reduction in minted issuance, since `mint_and_distribute` feeds staker/validator/incentive/treasury pots via `BudgetAllocation`. This matches the allowed impact class "runtime bugs that compromise intended behavior" (loss of yield to stakers/reward recipients). No privileged actor or attacker action is required — the bug is triggered automatically by any qualifying elapsed-time gap, which is a legitimate concern for the "intended behavior" of the issuance/inflation mechanism.

## Likelihood Explanation
Under normal cadence, `elapsed` rarely approaches `MaxElapsedPerDrip`, but any stall longer than the ceiling (congestion, extended runtime-upgrade windows, `on_initialize` weight exhaustion, network partitions) triggers the loss deterministically and is directly reproduced by the pallet's own `elapsed_ceiling_is_applied` test. This is a reachable, non-privileged, self-triggering condition rather than a purely theoretical scenario.

## Recommendation
On clamping, advance `LastIssuanceTimestamp` by the credited amount (`last.saturating_add(max_elapsed)`) instead of setting it to `now`, so the uncredited remainder is preserved and picked up (subject to the same ceiling, potentially across multiple subsequent drips) rather than being permanently discarded.

## Proof of Concept
The existing test `elapsed_ceiling_is_applied` already reproduces this exact scenario end-to-end: [2](#0-1) . It sets `MaxElapsedPerDrip = 600_000ms`, advances the mock clock by `1_200_000ms`, and confirms only `1000` units (the clamped `600_000ms` equivalent) are minted instead of `2000` units (the full `1_200_000ms` equivalent), with `LastIssuanceTimestamp` left at `now` rather than `last + 600_000`, permanently losing the remaining `600_000ms` worth of issuance for all future drips.

```rust
		pub(crate) fn drip_issuance() -> Weight {
			let now_moment = T::Time::now();
			let now: u64 = now_moment.saturated_into();
			let last = LastIssuanceTimestamp::<T>::get();
			let mut elapsed = now.saturating_sub(last);

			let cadence = T::IssuanceCadence::get();
			if cadence > 0 && elapsed < cadence {
				return T::DbWeight::get().reads(2);
			}

			// First block after genesis: initialize timestamp, don't drip.
			// For existing chains, use `migrations::MigrateV1ToV2` to seed this
			// value from ActiveEra.start so this branch is never hit post-upgrade.
			if last == 0 {
				LastIssuanceTimestamp::<T>::put(now);
				return T::DbWeight::get().reads_writes(2, 2);
			}

			// Apply safety ceiling on elapsed time.
			let max_elapsed = T::MaxElapsedPerDrip::get();
			if elapsed > max_elapsed {
				Self::deposit_event(Event::Unexpected(UnexpectedKind::ElapsedClamped {
					actual_elapsed: elapsed,
					ceiling: max_elapsed,
				}));
				elapsed = max_elapsed;
			}

			// Always advance the clock so elapsed time doesn't accumulate across skipped drips.
			LastIssuanceTimestamp::<T>::put(now);

			let _ = Self::mint_and_distribute(elapsed);
			T::WeightInfo::drip_issuance()
		}
```

```rust
fn elapsed_ceiling_is_applied() {

		assert_ok!(Dap::set_budget_allocation(RuntimeOrigin::root(), allocs));

		let buffer = Dap::buffer_account();

		// WHEN: 20 minutes pass but MaxElapsedPerDrip = 600_000ms (10 minutes)
		// Without clamping: 1_200_000ms → TestIssuanceCurve returns 2000
		// With clamping: 600_000ms → TestIssuanceCurve returns 1000
		advance_time_and_drip(1_200_000);

		// THEN: issuance based on clamped elapsed (1000, not 2000)
		assert_eq!(Balances::balance(&buffer) - buffer_before, 1000);

				actual_elapsed: 1_200_000,
				ceiling: 600_000,

		);
	});
```

```text
title: '[DAP] Catch-up drip on V1->V2 migration'
doc:
- audience: Runtime Dev
  description: |-
    The DAP V2 migration seeded `LastIssuanceTimestamp` to a point in the past
    (typically the active era start) so the next regular drip would credit
    elapsed time back to that point. That elapsed is then clamped by
    `MaxElapsedPerDrip`, so only up to one cap's worth of inflation is actually
    credited on the first drip, and the rest is silently dropped.

    This migration now performs a one-shot catch-up drip for the full
    `[last_inflation, now]` window and seeds `LastIssuanceTimestamp` to `now`, so
    regular drips start a fresh cadence from this point.
```
