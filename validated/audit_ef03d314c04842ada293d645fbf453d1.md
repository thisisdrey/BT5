### Title
Unauthenticated pre-verification handshake flood forces costly Noise/crypto work with no anti-DoS throttling - ([File: handshake_manager.go])

### Summary
The external report describes a griefing attack where an attacker forces a contract to repeatedly perform an expensive, avoidable operation (removing liquidity from a pool) purely to waste resources/fees, with no lasting cost to the attacker, because no cheaper/short-circuiting check runs first. The reachable analog in this codebase is the responder path for incoming stage-1 handshake packets: `HandshakeManager.beginHandshake` unconditionally allocates a new Noise `handshake.Machine` and runs full asymmetric handshake crypto (`machine.ProcessPacket`) for every syntactically-valid stage-1 packet, before any certificate/authentication check succeeds, and with no rate limiting or anti-DoS cookie mechanism in place.

### Finding Description
Incoming packets are dispatched in `HandshakeManager.HandleIncoming`. For a first-of-handshake message (`h.MessageCounter == 1`), the only gating checks are: subtype must be `header.HandshakeIXPSK0`, the sender must pass the (default permissive) remote allow list, and `h.RemoteIndex` must be zero. [1](#0-0) 

None of these checks require possession of a CA-signed certificate — an attacker with any raw UDP socket can trivially satisfy them by crafting a well-formed header. Once past those checks, `beginHandshake` is invoked unconditionally: [2](#0-1) 

This function allocates a brand-new `handshake.Machine` and calls `machine.ProcessPacket`, which performs a full Noise `ReadMessage` (elliptic-curve Diffie-Hellman plus AEAD decryption attempt) *before* any peer certificate is validated: [3](#0-2) 

Only after this expensive cryptographic work completes does the code check for a certificate and validate it via `hm.validatePeerCert`; if that fails (as it always will for an attacker with no CA-issued certificate), all of the work is discarded: [4](#0-3) 

There is no per-source-IP or per-attempt rate limiting protecting this path, and the protocol's own documentation confirms an anti-DoS mechanism was designed but never implemented: [5](#0-4) 

This is structurally the same "griefing" pattern as the external report: a cheap-for-the-attacker action (send a forged stage-1 UDP packet) forces the target to eagerly perform a comparatively expensive, ultimately wasted operation (Noise DH + AEAD + Machine allocation), instead of first doing a cheap check (verifying possession of a CA-signed certificate/cookie) that would short-circuit the cost before committing resources — mirroring the recommendation in the report ("fulfill from balance / cheap check first before the costly operation").

### Impact Explanation
An attacker with no valid CA-signed certificate can repeatedly send spoofed stage-1 handshake packets to a nebula node, each forcing allocation of a new `handshake.Machine` and a full asymmetric Noise handshake step (ECDH + AEAD) that is discarded once certificate validation fails. Because there is no cookie/rate-limit gate (explicitly noted as never implemented) and no per-source throttling in `HandleIncoming`/`beginHandshake`, this can be repeated at line rate from spoofed or real source addresses, degrading or exhausting responder CPU and creating a remote, pre-authentication denial-of-service condition — impact is Medium/High depending on deployment exposure (any node accepting handshakes from unknown addresses, i.e., not restricted by `remote_allow_list`).

### Likelihood Explanation
Likelihood is High: no CA-signed certificate or prior trust relationship is required, the attack packet is trivial to construct (satisfy header parsing and `RemoteIndex == 0`), and the default configuration does not require a restrictive `remote_allow_list`. The condition is directly reachable over UDP from any network position that can reach the listener.

### Recommendation
Introduce a lightweight, stateless anti-DoS check (e.g., the reserved `Cookie` mechanism referenced in `handshake/handshake.proto`, or a proof-of-work/return-routability token) that must be validated *before* allocating a `handshake.Machine` or performing any Noise cryptographic operation in `beginHandshake`. At minimum, add per-source-address rate limiting on stage-1 (`MessageCounter == 1`) handshake initiation in `HandshakeManager.HandleIncoming` so that the expensive `ProcessPacket` crypto path cannot be triggered at unbounded rate by unauthenticated senders.

### Proof of Concept
1. From an attacker-controlled host with no CA-issued nebula certificate, craft UDP packets matching the wire header for `header.Handshake` / `header.HandshakeIXPSK0`, with `RemoteIndex = 0` and `MessageCounter = 1`, and an arbitrary/garbage Noise payload of sufficient length to pass `len(packet) < header.Len` checks.
2. Send a high rate of such packets (varying source ports/spoofed addresses) to a nebula node's listening UDP port.
3. Observe (per `handshake_manager.go` beginHandshake/`handshake/machine.go` ProcessPacket) that each packet causes allocation of a new `handshake.Machine` and a full Noise `ReadMessage` (DH + AEAD) call before the certificate check in `validatePeerCert` rejects the packet — confirming resource consumption occurs prior to any authentication, with no rate limiting to bound the attack (uncertain/unverified: exact measured CPU impact and whether OS-level UDP socket buffering mitigates volume in practice — this would require load-testing on an actual deployment, which is outside what static code review can confirm).

func (hm *HandshakeManager) HandleIncoming(via ViaSender, packet []byte, h *header.H) {
	// Gate on known handshake subtypes. Unknown subtypes (or future ones we
	// don't yet support) are dropped here rather than silently routed through
	// the IX path. Add a case when introducing a new pattern.
	switch h.Subtype {
	case header.HandshakeIXPSK0:
		// supported
	default:
		hm.l.Debug("dropping handshake with unsupported subtype",
			"from", via, "subtype", h.Subtype)
		return
	}

	// First remote allow list check before we know the vpnIp
	if !via.IsRelayed {
		if !hm.lightHouse.GetRemoteAllowList().AllowUnknownVpnAddr(via.UdpAddr.Addr()) {
			hm.l.Debug("lighthouse.remote_allow_list denied incoming handshake", "from", via)
			return
		}
	}

	// First message of a new handshake. The wire format requires RemoteIndex
	// to be zero here (the initiator has no responder index to fill in yet),
	// and generateIndex never allocates 0, so any non-zero RemoteIndex on a
	// stage-1 packet is malformed or someone probing for an index collision.
	// Drop without paying the cost of running noise on a pending Machine.
	if h.MessageCounter == 1 {
		if h.RemoteIndex != 0 {
			hm.l.Debug("dropping stage-1 handshake with non-zero RemoteIndex",
				"from", via, "remoteIndex", h.RemoteIndex)
			return
		}
		hm.beginHandshake(via, packet, h)
		return
	}

func (hm *HandshakeManager) beginHandshake(via ViaSender, packet []byte, h *header.H) {
	f := hm.f
	cs := f.pki.getCertState()

	v := cs.DefaultVersion()
	if cs.GetCredential(v) == nil {
		f.l.Error("Unable to handshake with host because no certificate is available",
			"from", via, "certVersion", v)
		return
	}

	machine, err := handshake.NewMachine(
		v, cs.GetCredential,
		hm.certVerifier(), func() (uint32, error) { return generateIndex(f.l) },
		false, header.HandshakeIXPSK0,
	)
	if err != nil {
		f.l.Error("Failed to create handshake machine", "from", via, "error", err)
		return
	}

	response, result, err := machine.ProcessPacket(nil, packet)
	if err != nil {
		f.l.Error("Failed to process handshake packet", "from", via, "error", err)
		return
	}

func (m *Machine) ProcessPacket(out, packet []byte) ([]byte, *Result, error) {
	if m.failed {
		return nil, nil, ErrMachineFailed
	}
	if len(packet) < header.Len {
		return nil, nil, ErrPacketTooShort
	}
	// Reject packets whose subtype doesn't match the one this Machine was
	// built for. A pending handshake that suddenly receives a different
	// subtype on its index is either a stray packet that matched by chance
	// or a peer protocol violation; drop it without failing the Machine so
	// the legitimate retransmit can still complete.
	if header.MessageSubType(packet[1]) != m.subtype {
		return nil, nil, ErrSubtypeMismatch
	}
	if m.result.Initiator && m.hs.MessageIndex() == 0 {
		m.failed = true
		return nil, nil, ErrInitiateNotCalled
	}

	// The (eKey, dKey) ordering here is correct for IX, where the initiator
	// completes the handshake by reading the responder's stage-2 message.
	// noise returns (cs1, cs2) where cs1 is the initiator->responder cipher.
	// For 3-message patterns where a responder finishes by reading the final
	// message, this ordering would be wrong; revisit when XX/pqIX lands.
	msg, eKey, dKey, err := m.hs.ReadMessage(nil, packet[header.Len:])
	if err != nil {
		// Noise ReadMessage failed. The noise library checkpoints and rolls back
		// on failure, so the Machine is still alive. The caller can retry with
		// a different packet.
		return nil, nil, fmt.Errorf("noise ReadMessage: %w", err)
	}
