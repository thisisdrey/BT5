### Title
Unauthenticated voting/stop injection on Praefect's `RefTransaction` service enables cross-transaction interference and DoS - (File: internal/praefect/server.go)

### Summary
Praefect's `RefTransaction` gRPC service (`VoteTransaction` / `StopTransaction`) is meant to be used exclusively by Gitaly storage nodes voting on their own reference-transactions over a dedicated backchannel connection. However, the same service is *also* registered directly on Praefect's main, client-facing gRPC server, protected only by the shared Praefect authentication token rather than a check that the caller is an actual Gitaly-node backchannel peer. Any caller holding that shared token (the same token used for ordinary repository RPCs) can therefore call `VoteTransaction`/`StopTransaction` with an arbitrary `transaction_id` and `node` name, injecting fabricated votes/stops into transactions it does not own — closely analogous to the reported "unprotected event emission" bug class where anyone can emit fraudulent events that mislead or DoS the system.

### Finding Description
The `RefTransaction` service is intended to be invoked only from Gitaly nodes participating in a specific transaction, via Praefect's backchannel connection: [1](#0-0) 

This purpose is explicit in the docs: "the Git hook talk directly to Praefect" over a token-authenticated backchannel connection, and the transaction service exists solely so that participating Gitaly nodes can vote on a specific transaction they were assigned: [2](#0-1) 

Critically, the exact same `RefTransactionServer` implementation is *also* registered directly on Praefect's main gRPC server (`NewGRPCServer`/`registerServices`), which is the same server that proxies ordinary client RPCs (`RepositoryService`, `OperationService`, etc.) and is guarded only by the generic Praefect auth-token interceptor: [3](#0-2) [4](#0-3) 

The `VoteTransaction`/`StopTransaction` handlers perform no additional authorization check — they take `transaction_id`, `node`, `phase` and `reference_updates_hash` directly from the request and forward them to the transaction manager without verifying that the caller is the legitimate voter (e.g. via `backchannel.GetPeerID`, as is done for the analogous `SignalPostReceiveReady` RPC): [5](#0-4) 

Compare this to the pattern used to fix the identical class of issue for `SignalPostReceiveReady`, which explicitly checks `backchannel.GetPeerID(ctx)` and rejects calls from ordinary clients: [6](#0-5) 

The underlying vote-processing logic identifies voters purely by the caller-supplied `node` string and disallows re-voting once a vote is registered for that node ("changing current vote is not allowed"), meaning a first attacker-submitted vote for a given node name can pre-empt/lock out the legitimate storage node's real vote: [7](#0-6) 

### Impact Explanation
An attacker who holds a valid Praefect client auth token (the same token normal GitLab/Workhorse/gitlab-shell clients use — not a Gitaly-node-only secret) can call `VoteTransaction`/`StopTransaction` on transactions belonging to other users' in-flight pushes:
- Guessing/observing a `transaction_id` (or brute-forcing the ID space) lets the attacker cast a bogus vote impersonating one of the real voters (`node` name = storage name), causing that storage's legitimate vote to be rejected once it arrives ("changing current vote is not allowed"), which can fail or corrupt quorum outcomes for unrelated repositories' transactions.
- Calling `StopTransaction` on arbitrary transaction IDs allows an attacker to gracefully abort other users' in-flight reference-transactions, causing denial-of-service against unrelated pushes across the whole Gitaly Cluster.
This is a cross-tenant/cross-repository interference and DoS vector reachable from any authenticated-but-unprivileged client of Praefect, not just from Gitaly cluster nodes as intended.

### Likelihood Explanation
Likelihood is moderate: exploitation requires the attacker to already hold a valid Praefect client auth token (which ordinary GitLab-integrated clients possess) and to know or guess a live `transaction_id` (an integer, generated per the docs "randomly... to avoid collisions", but the ID space and any leakage channels were not verified in this review). No additional secret tied to backchannel/node identity is required, unlike the corresponding `SignalPostReceiveReady` RPC which was hardened specifically against this scenario.

### Recommendation
Restrict `VoteTransaction` and `StopTransaction` on the main Praefect gRPC server so they are only reachable via the backchannel connection from legitimate Gitaly storage nodes, mirroring the fix applied to `SignalPostReceiveReady` (`backchannel.GetPeerID(ctx)` check), or remove the duplicate registration of `RefTransactionServer` in `registerServices` in `internal/praefect/server.go` so the service is exposed only through `NewBackchannelServerFactory`. Additionally, validate that the `node` in a vote request matches the peer identity of the backchannel connection rather than trusting an attacker-suppliable string.

### Proof of Concept
1. Obtain a valid Praefect client authentication token (the standard token used for ordinary Gitaly Cluster client RPCs).
2. Observe or infer an in-flight `transaction_id` for a push being processed by the cluster (e.g., via timing or ID-space characteristics, not verified in this review).
3. Call `gitalypb.NewRefTransactionClient(conn).VoteTransaction(ctx, &gitalypb.VoteTransactionRequest{TransactionId: <observed_id>, Node: "<real-storage-name>", ReferenceUpdatesHash: <arbitrary_hash>})` directly against Praefect's main gRPC endpoint (not the backchannel) — this succeeds because the endpoint is registered in `registerServices` (`internal/praefect/server.go:228`) and only checks the generic auth token.
4. When the legitimate Gitaly storage node later attempts to cast its real vote for the same `node`/transaction, it is rejected with "changing current vote is not allowed" (`internal/praefect/transactions/subtransaction.go:163`), causing the legitimate transaction to fail/abort — a denial of service against an unrelated user's push.
5. Alternatively, call `StopTransaction` with the observed `transaction_id` to unilaterally abort the transaction for all participating nodes.

func NewBackchannelServerFactory(logger log.Logger, refSvc gitalypb.RefTransactionServer, registry *sidechannel.Registry) backchannel.ServerFactory {
	logMsgProducer := loghandler.MessageProducer(
		loghandler.PropagationMessageProducer(grpcmwlogrus.DefaultMessageProducer),
		structerr.FieldsProducer,
	)

	return func() backchannel.Server {
		lm := listenmux.New(insecure.NewCredentials())
		lm.Register(sidechannel.NewServerHandshaker(registry))
		srv := grpc.NewServer(
			grpc.StatsHandler(tracing.NewGRPCServerStatsHandler()),
			grpc.ChainUnaryInterceptor(
				commonUnaryServerInterceptors(logger.WithField("component", "backchannel.PraefectServer"), logMsgProducer)...,
			),
			grpc.Creds(lm),
		)
		gitalypb.RegisterRefTransactionServer(srv, refSvc)
		grpcprometheus.Register(srv)
		return srv
	}

#### Transaction Service

To let Praefect know about reference transactions, the
[transaction service](https://gitlab.com/gitlab-org/gitaly/-/blob/master/proto/transaction.proto)
was implemented. The service has a single RPC `VoteTransaction` to vote on a
transaction created by Praefect.

Each transaction gets the following information at creation time:

- Each transaction is identified by a transaction identifier, which is simply an
  integer that gets randomly generated by the transaction service when `Create`
  is called and is returned to the caller. Both `Start` and `Cleanup` requests
  are required to pass along this identifier. This identifier generated at
  random in contrast to being a sequence counter to avoid collisions.

- Each transaction has a fixed set of voters allowed to take part in the
  transaction. Each voter has a name (which needs to be unique and is typically
  the Gitaly storage name) as well as a number of votes it has. The number of
  votes needs to be in the range of `[0,MAX_UINT32]`. The total number of votes
  must be non-zero.

// VoteTransaction is called by a client who's casting a vote on a reference
// transaction, blocking until a vote across all participating nodes has been
// completed.
func (s *Server) VoteTransaction(ctx context.Context, in *gitalypb.VoteTransactionRequest) (*gitalypb.VoteTransactionResponse, error) {
	vote, err := voting.VoteFromHash(in.GetReferenceUpdatesHash())
	if err != nil {
		return nil, structerr.NewInvalidArgument("invalid reference update hash: %w", err)
	}
	if err := s.txMgr.VoteTransaction(ctx, in.GetTransactionId(), in.GetRepository().GetStorageName(),
		in.GetRepository().GetRelativePath(), in.GetNode(), in.GetPhase(), vote); err != nil {
		switch {
		case errors.Is(err, transactions.ErrNotFound):
			return nil, structerr.NewNotFound("%w", err)
		case errors.Is(err, transactions.ErrTransactionCanceled):
			return nil, structerr.NewCanceled("%w", err)
		case errors.Is(err, transactions.ErrTransactionStopped):
			return &gitalypb.VoteTransactionResponse{
				State: gitalypb.VoteTransactionResponse_STOP,
			}, nil
		case errors.Is(err, transactions.ErrTransactionFailed):
			return &gitalypb.VoteTransactionResponse{
				State: gitalypb.VoteTransactionResponse_ABORT,
			}, nil
		default:
			return nil, structerr.NewInternal("%w", err)
		}
	}

	return &gitalypb.VoteTransactionResponse{
		State: gitalypb.VoteTransactionResponse_COMMIT,
	}, nil
}

// SignalPostReceiveReady signals that Praefect has completed transaction coordination
// and the PostReceiveHook can proceed with calling Rails. This RPC is only callable via
// Praefect's backchannel to prevent abuse.
func (s *server) SignalPostReceiveReady(
	ctx context.Context,
	req *gitalypb.SignalPostReceiveReadyRequest,
) (*gitalypb.SignalPostReceiveReadyResponse, error) {
	// Validate that the request is coming via Praefect's backchannel.
	// This prevents external callers from unblocking arbitrary transactions.
	if _, err := backchannel.GetPeerID(ctx); err != nil {
		return nil, structerr.NewPermissionDenied("SignalPostReceiveReady can only be called via Praefect backchannel")
	}

	// Validate transaction ID is non-zero to prevent abuse.
	if req.GetTransactionId() == 0 {
		return nil, structerr.NewInvalidArgument("transaction_id must be non-zero")
	}
