### Title
Handshake replay with spoofed source address can hijack a peer's trusted remote address ([File: handshake_manager.go], [File: hostmap.go])

### Summary
Nebula's handshake retransmission handling authenticates a duplicate handshake message purely by comparing raw packet bytes, not by re-verifying that the sender currently controls the claimed network address. An attacker who captures a legitimate stage-0 handshake packet off the wire can replay it later from a spoofed UDP source address that happens to fall inside a host's `preferred_ranges`, and the responder will treat this as a "roaming" event and redirect its trusted remote address for that peer to the attacker-controlled address — without ever presenting a valid CA-signed certificate or possessing the peer's private key.

### Finding Description
When a duplicate handshake stage-0 packet arrives, `CheckAndComplete` in `handshake_manager.go` detects it purely via byte-equality of the cached handshake payload, not via any renewed proof-of-origin: [1](#0-0) 

If this matches, the error `ErrAlreadySeen` propagates to `handleCheckAndCompleteError`, which calls `existing.SetRemoteIfPreferred(f.hostMap, via)`: [2](#0-1) 

`SetRemoteIfPreferred` in `hostmap.go` decides whether to "roam" the trusted remote address for this host purely by checking if the *claimed source address of the current UDP packet* (`via.UdpAddr`) falls in a locally configured preferred CIDR range — with no cryptographic binding between that address and the handshake content: [3](#0-2) 

The security-relevant fact being checked ("is this packet really coming from where it claims to?") is validated only by matching stale, previously-observed ciphertext bytes against an incoming UDP datagram's reported source IP — a value fully controlled by the network layer and, on many networks, spoofable. This is the same class of bug as the ParaSpace flashloan finding: a security decision (auction "recovery" / here, "remote address is trustworthy") is based on a momentary, replayable signal (byte-identical handshake packet from a "preferred" address) rather than continuous cryptographic proof that the current sender actually possesses the session's private key material for that specific network position. Just as the ParaSpace attacker could flash the health-factor check true for a single transaction and revert it immediately after, an attacker here can flash a "preferred-range packet from a captured legitimate handshake" and have the hostmap durably record a poisoned remote address as a result.

### Impact Explanation
Successful exploitation lets an unauthenticated, non-CA-signed attacker corrupt the `RemoteList`/`HostInfo.remote` state (`i.SetRemote(via.UdpAddr)` at `hostmap.go:817`) for an existing, already-authenticated tunnel. Because subsequent encrypted data-plane traffic is addressed using this `remote` value (`GetRemote()`), the victim will begin sending ciphertext to the attacker's spoofed address instead of the legitimate peer, causing a silent denial-of-service / traffic black-holing condition for that tunnel — a form of remote state poisoning reachable without ever holding a valid certificate.

### Likelihood Explanation
The attacker only needs to (1) capture one legitimate handshake stage-0 packet (feasible for any on-path or lighthouse-adjacent observer, since handshake packets are sent over UDP in the clear at the network layer even though their payload is encrypted with Noise), and (2) replay it with a spoofed source UDP address inside the target's configured `preferred_ranges` (commonly private ranges like RFC1918 space, which are often broadly configured). UDP source spoofing is well known to be feasible in many network topologies (LANs, misconfigured egress filtering, or where the attacker is on-path). No cryptographic material or CA-signed certificate is required.

### Recommendation
Do not let `ErrAlreadySeen`-triggered roaming decisions in `handleCheckAndCompleteError`/`SetRemoteIfPreferred` be driven solely by (a) byte-equality of a replayable handshake payload and (b) an unauthenticated UDP source address. Bind roaming decisions to freshness (e.g., require the duplicate to arrive within a bounded, recent replay window tied to the original handshake, and rate/velocity-limit roam events) and, where possible, require a new authenticated exchange (e.g., a signed keepalive/test packet round-trip) from the new address before durably updating `HostInfo.remote`, rather than trusting the raw UDP source of a replayed handshake packet.

### Proof of Concept
1. Attacker passively captures a legitimate `stage0` handshake UDP packet sent by Host A to Host B (e.g., via network tap, ARP spoofing on a shared LAN, or router compromise).
2. Attacker waits, then sends the exact same captured packet bytes to Host B, spoofing the UDP source address to be `X`, where `X` falls inside Host B's configured `preferred_ranges` (e.g. `10.0.0.0/8`).
3. `HandshakeManager.beginHandshake` → `CheckAndComplete` finds `bytes.Equal(...)` true against the existing `HostInfo` for Host A and returns `ErrAlreadySeen`.
4. `handleCheckAndCompleteError` calls `existing.SetRemoteIfPreferred(f.hostMap, via)` with `via.UdpAddr.Addr() == X`; since `X` is in `preferredRanges` and the current remote is not, `SetRemoteIfPreferred` roams and calls `i.SetRemote(X:port)`.
5. Host B's `HostInfo` for Host A now has its trusted `remote` set to the attacker-controlled address `X`, and all subsequent encrypted traffic intended for Host A is sent to `X` instead — achieved without the attacker ever presenting a CA-signed certificate.

// SetRemoteIfPreferred returns true if the remote was changed. The lastRoam
// time on the HostInfo will also be updated.
func (i *HostInfo) SetRemoteIfPreferred(hm *HostMap, via ViaSender) bool {
	if via.IsRelayed {
		return false
	}

	currentRemote := i.GetRemote()
	if !currentRemote.IsValid() {
		i.SetRemote(via.UdpAddr)
		return true
	}

	// NOTE: We do this loop here instead of calling `isPreferred` in
	// remote_list.go so that we only have to loop over preferredRanges once.
	newIsPreferred := false
	for _, l := range hm.GetPreferredRanges() {
		// return early if we are already on a preferred remote
		if l.Contains(currentRemote.Addr()) {
			return false
		}

		if l.Contains(via.UdpAddr.Addr()) {
			newIsPreferred = true
		}
	}

	if newIsPreferred {
		// Consider this a roaming event
		i.lastRoam = time.Now()
		i.lastRoamRemote = currentRemote

		i.SetRemote(via.UdpAddr)

		return true
	}

	return false
}
