## Finding: Protocol fees bypassed via unit-splitting of NEP-245/IMT `TokenDiff` trades

**Binding under test:** `sum(fees_collected credited to fee_collector across N TokenDiff intents each with delta=-1) == protocol_fee.fee_ceil(10_000)` (fee on aggregate `-10_000` delta on a single Nep245/Imt token).

### Title
Protocol fee on `Nep245`/`Imt` `TokenDiff` trades can be reduced to zero by splitting into unit-delta intents - ([File: contracts/defuse/core/src/intents/token_diff.rs])

Note: the file cited in the question, `crates/near/nep245/src/receiver.rs`, only declares the `ext_contract` NEP-245 receiver trait [1](#0-0)  and contains no fee logic whatsoever. The actual fee computation this question describes lives in `TokenDiff::execute_intent` / `TokenDiff::token_fee`.

### Summary
`TokenDiff::token_fee` deliberately charges `Pips::ZERO` on `Nep245`/`Imt` tokens whenever the per-intent `amount <= 1`, a carve-out intended for atomic NFT-like transfers. Because fees are computed independently **per `TokenDiff` intent** (not aggregated per batch, per account, or per token across the whole `MultiPayload`/`execute_intents` call), a signer can decompose one economically large NEP-245/IMT trade into many separate unit-delta `TokenDiff` intents and pay zero protocol fee on the whole trade.

### Finding Description
In `TokenDiff::execute_intent`, for every negative delta in a *single* `TokenDiff.diff` map, the fee is computed independently: [2](#0-1) 

`token_fee` zeroes the fee for `Nep245`/`Imt` (and `Nep171`) token types whenever `amount <= 1`: [3](#0-2) 

There is no per-batch, per-account, or per-token aggregation of amounts before this check is applied — `execute_signed_intents` simply loops over each signed `MultiPayload` and executes its `intents` list, each `TokenDiff` computing/collecting fees independently: [4](#0-3) 

Settlement correctness (the `TransferMatcher`) only requires that, across the *whole* batch, total deposits and withdrawals per token id net to zero (`TransferMatcher::finalize`) — it has no notion of "this token amount belongs to one logical trade" and does not re-derive or check fee amounts: [5](#0-4) 

**Exploit flow:** An attacker (optionally colluding with, or itself controlling, a counterparty account — both unprivileged) wants to trade 10,000 units of a `Nep245`/`Imt` token (which can represent a wrapped fungible NEP-141 balance, as demonstrated by `mt_transfer_call` wrapping in `tests/src/tests/defuse/tokens/nep245/mod.rs`) for some other token. Instead of signing one `TokenDiff` with `diff = {tokenX: -10_000, tokenY: +Z}`, which would charge `fee = protocol_fee.fee_ceil(10_000)`, the attacker (and counterparty) sign 10,000 separate `MultiPayload`s, each containing a `TokenDiff` with `diff = {tokenX: -1, tokenY: +z}` (`z` chosen so 10,000 legs net the same overall trade). Each intent independently hits `amount == 1`, so `token_fee` returns `Pips::ZERO` and `fees_collected` is empty for every leg. The batch as a whole still balances (`TransferMatcher::finalize` succeeds because total withdrawals/deposits of `tokenX`/`tokenY` net to zero across the 10,000 legs), so `execute_intents` succeeds without reverting, and `fee_collector`'s balance receives 0 instead of `protocol_fee.fee_ceil(10_000)`.

None of the existing guards prevent this: `MultiPayload::verify`, `has_public_key`, nonce/salt checks, and `TransferMatcher::finalize` all validate signature/replay/balance-invariant correctness but never re-derive or bound the fee based on the aggregate economic size of the trade.

### Impact Explanation
`fee_collector` (the protocol) receives less than the fee it is entitled to on the aggregate trade — potentially the entire fee, reduced to zero — for any `Nep245`/`Imt`-typed token, including MT-wrapped representations of NEP-141 fungible tokens. This is repeatable for every trade and every account, and scales to arbitrarily large notional volumes since the “amount <= 1” carve-out applies uniformly regardless of how many unit-legs are chained. This matches the "protocol fees bypassed" Critical category.

### Likelihood Explanation
No special privileges, roles, or victim keys are needed — only the ability to sign multiple `MultiPayload`s with valid nonces/deadlines (cheap, since nonces are attacker-chosen 15-byte random values plus a salt as shown in `crates/testing/sandbox/src/extensions/defuse/nonce.rs`). The only cost is the linear increase in number of intents/payloads and the associated NEAR gas for `execute_intents`, which per the audit rules is explicitly excluded from being used to dismiss this finding (gas cost is not "denial of service" here — it's the attacker's own cost of exploiting a value-bypass, not a resource-exhaustion attack on the protocol). The technique is fully mechanical and requires no market timing or races.

### Recommendation
Compute/enforce the `amount > 1` fee-exemption threshold based on cumulative net exposure per `(signer, token_id)` (or globally per `token_id`) across the whole executed batch/transaction, not per individual `TokenDiff` intent; alternatively, remove or tighten the NFT/MT zero-fee carve-out so it only applies to token ids whose supply/semantics are inherently non-fractional (true NFTs), not to `Nep245`/`Imt` ids that can represent large fungible-style balances.

### Proof of Concept
`cargo test` plan (near-workspaces sandbox, in `tests/src/tests/defuse/intents/token_diff.rs` style):
1. Configure `FeesConfig { fee: Pips::ONE_PERCENT, fee_collector }` (nonzero fee).
2. Wrap/mint a `Nep245` (or `Imt`) token so `user1` holds 10,000 units and `user2` holds a matching counter-asset.
3. **Baseline:** sign a single `TokenDiff` batch pair with `diff = {tokenX: -10_000, tokenY: +Z}` / `{tokenX: +10_000_closure, tokenY: -Z}`; execute via `execute_intents`; assert `fee_collector`'s `tokenX` balance increases by `Pips::ONE_PERCENT.fee_ceil(10_000)`.
4. **Exploit:** reset balances; sign 10,000 separate `MultiPayload`s each with `TokenDiff{diff: {tokenX: -1, tokenY: +z}}` from `user1` and matching `+1/-z` legs from `user2`, each with a unique nonce; call `env.defuse_execute_intents(...)` with the full vector of 10,000 payloads.
5. Assert: `fee_collector`'s `tokenX` balance delta is `0`, not `Pips::ONE_PERCENT.fee_ceil(10_000)`, demonstrating the binding `sum(fees_collected) == protocol_fee.fee_ceil(10_000)` is violated (`0 != fee_ceil(10_000)`).

    pub fn execute_signed_intents(
        mut self,
        signed: impl IntoIterator<Item = MultiPayload>,
    ) -> Result<Transfers> {
        for signed in signed {
            self.execute_signed_intent(signed)?;
        }
        self.finalize()
    }

    fn execute_signed_intent(&mut self, signed: MultiPayload) -> Result<()> {
        // verify signed payload and get public key
        let public_key = signed.verify().ok_or(DefuseError::InvalidSignature)?;

        // calculate intent hash
        let hash = signed.hash();

        // extract NEP-413 payload
        let DefusePayload::<DefuseIntents> {
            signer_id,
            verifying_contract,
            deadline,
            nonce,
            message: intents,
        } = signed.extract_defuse_payload()?;

        // check recipient
        if verifying_contract != *self.state.verifying_contract() {
            return Err(DefuseError::WrongVerifyingContract);
        }

        self.inspector.on_deadline(deadline);

        // make sure message is still valid
        if deadline < Timestamp::now() {
            return Err(DefuseError::DeadlineExpired);
        }

        // make sure the account has this public key
        if !self.state.has_public_key(&signer_id, &public_key) {
            return Err(DefuseError::PublicKeyNotExist(signer_id, public_key));
        }

        // commit nonce
        self.verify_intent_nonce(nonce, deadline)?;
        self.state.commit_nonce(signer_id.clone(), nonce)?;

        intents.execute_intent(&signer_id, self, hash)?;
        self.inspector.on_intent_executed(&signer_id, hash, nonce);

        Ok(())
    }

    // Finalizes all transfers, or returns unmatched deltas.
    // If unmatched deltas overflow, then Err(None) is returned.
    pub fn finalize(self) -> Result<Transfers, InvariantViolated> {
        let mut transfers = Transfers::default();
        let mut deltas = TokenDeltas::default();
        for (token_id, transfer_matcher) in self.0 {
            if let Err(unmatched) = transfer_matcher.finalize_into(&token_id, &mut transfers)
                && (unmatched == 0 || deltas.apply_delta(token_id, unmatched).is_none())
            {
                return Err(InvariantViolated::Overflow);
            }
        }
        if !deltas.is_empty() {
            return Err(InvariantViolated::UnmatchedDeltas {
                unmatched_deltas: deltas,
            });
        }
        Ok(transfers)
    }
