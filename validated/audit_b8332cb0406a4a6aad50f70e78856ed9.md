### Title
Unauthenticated event ingestion on the stacks-signer's HTTP receiver allows forged node events (StackerDB chunks, block-validation responses, new-block/burn-block notifications) - (File: `libsigner/src/events.rs`)

### Summary
`SignerEventReceiver::next_event` (`libsigner/src/events.rs:413-458`) accepts and processes any HTTP POST to `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, and `/new_block` with **no authentication, no source-address check, and no signature verification of the request itself**. The handler only checks the HTTP method and URL path, then deserializes the JSON body directly into a `SignerEvent` and forwards it unmodified to the signer runloop via `forward_event`.

### Finding Description
The event receiver's `next_event` (`libsigner/src/events.rs:413-458`) dispatches based purely on `request.url()`:
```
if request.url() == "/stackerdb_chunks" {
    process_event::<T, StackerDBChunksEvent>(request)
} else if request.url() == "/proposal_response" {
    process_event::<T, BlockValidateResponse>(request)
} else if request.url() == "/new_burn_block" {
    process_event::<T, BurnBlockEvent>(request)
} ...
```
`process_event` (`libsigner/src/events.rs:519-542`) reads the body and does `serde_json::from_slice`, then `try_into()`, with **no check of caller identity, no shared secret, no signature, no TLS/mTLS, and no IP allow-list**. Anyone able to reach this listening port can therefore inject arbitrary `StackerDBChunksEvent`, `BlockValidateResponse`, `BurnBlockEvent`, or `StacksBlockEvent` payloads, which are forwarded verbatim to the signer's decision loop as if the trusted Stacks node had sent them.

Compounding this, the sample/default configuration binds this listener to all interfaces rather than loopback: `sample/conf/signer/mainnet-signer-conf.toml:39` sets `endpoint = "0.0.0.0:30000"`, and `sample/conf/testnet-signer.toml:36` binds `127.0.0.1:30000` (inconsistent across samples), showing the wildcard-bind pattern is a supported/documented configuration, not merely a theoretical one. `libsigner/src/lib.rs` (`SpawnedSigner::new`) even emits an explicit warning acknowledging this exposure ("It's important to exercise caution if you are communicating with an external node ... this could potentially expose sensitive data or functionalities to security risks if additional proper security checks are not integrated"), confirming the developers are aware no in-band protection exists.

This is directly analogous to the reported Rancher CSRF/cross-site-hijacking bug class: an unauthenticated network actor can submit state-affecting "requests" (there, WebSocket commands against the Kubernetes API; here, HTTP POSTs against the signer's event endpoint) that get treated as legitimate, trusted input purely because they arrived on the right socket/path, breaking the equality "came from the trusted node" vs "came from anyone who can reach the port."

Note: this analysis is limited to the transport/authentication layer of the receiver, per the in-scope rules; the downstream signer decision logic that consumes these events is explicitly out of scope, so the ultimate blast radius of a forged `BlockValidateResponse` or `StackerDBChunksEvent` (e.g., whether it can influence signing) was not further investigated here. ### Impact Explanation
This meets the Critical bar of "unauthenticated/unauthorized write to state" and "network-wide propagation of forged data": the signer's internal event stream — which normally only reflects verified data from its paired Stacks node — can be populated with attacker-forged `StackerDBChunksEvent`/`BlockValidateResponse`/block/burn-block events by any host that can reach the bound port (which per sample configuration may be `0.0.0.0`, i.e. any network-reachable attacker, not merely localhost). This is a state-injection primitive into the signer's trusted input channel.

### Likelihood Explanation
Likelihood is high wherever the endpoint is reachable beyond loopback (as the mainnet sample config demonstrates is a supported deployment), since exploitation requires nothing more than crafting an HTTP POST with a JSON body matching the expected event schema — no credentials, keys, or privileged network position are needed.

### Recommendation
Require the event receiver to authenticate the sender of `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, and `/new_block` requests (e.g., a shared bearer token mirrored from `connection_options.auth_token`, or restricting/verifying the peer address), consistent with how the node's own RPC handlers (e.g. `postblock_v3.rs`, `postblock_proposal.rs`) already gate sensitive POST endpoints behind an `authorization` header comparison. Additionally, default and document the listener bind address to loopback-only unless explicit, informed opt-in to a wider bind is configured with authentication enabled.

### Proof of Concept
1. Start a `stacks-signer` configured per `sample/conf/signer/mainnet-signer-conf.toml` (`endpoint = "0.0.0.0:30000"`).
2. From any host that can reach `<signer-ip>:30000`, send:
```
POST /stackerdb_chunks HTTP/1.1
Host: <signer-ip>:30000
Content-Type: application/json
Content-Length: <n>

{ ...forged StackerDBChunksEvent JSON... }
```
3. Observe (per `libsigner/src/events.rs:437-438`) that `process_event::<T, StackerDBChunksEvent>` deserializes and forwards this to the signer runloop with no authentication check, identical to a legitimate push from the paired node. [4](#0-3)

    fn next_event(&mut self) -> Result<SignerEvent<T>, EventError> {
        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)
            } else if request.url() == "/new_block" {
                process_event::<T, StacksBlockEvent>(request)
            } else {
                let url = request.url().to_string();
                debug!(
                    "[{:?}] next_event got request with unexpected url {}, return OK so other side doesn't keep sending this",
                    event_receiver.local_addr,
                    url
                );
                ack_dispatcher(request);
                Err(EventError::UnrecognizedEvent(url))
            }
        })?

fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}
