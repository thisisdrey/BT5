### Title
Unauthenticated remote `/shutdown` POST terminates the signer's event receiver — ([File: libsigner/src/events.rs])

### Summary
`SignerEventReceiver::bind()` opens a plain `tiny_http::Server` with no authentication of the connecting peer, and `next_event()` treats any `POST /shutdown` as equivalent to the node's own internal stop-signal request. Any remote TCP client that can reach the signer's event-listener port can terminate the signer's event loop with a single crafted HTTP request.

### Finding Description
The claimed equality — "every command the signer's event loop obeys == a command issued by the locally configured node" — is broken because the handler at `libsigner/src/events.rs:437-457` dispatches purely on HTTP method + URL path with no check of the peer's identity, source IP, or any shared secret: [1](#0-0) 

is reached identically whether the request comes from the legitimate node-side `SignerStopSignaler::send()` (`libsigner/src/events.rs:376-396`, which itself just opens a `TcpStream` and writes a raw `POST /shutdown` request with no auth token) or from an arbitrary attacker who does the exact same thing. There is no signature, no `auth_password` check (that password is only used for the node's block-proposal RPC endpoint, per `stacks-signer/src/config.rs` / `mainnet-signer-conf.toml`, not for the signer's own event listener), and no peer allowlist in `bind()` (`libsigner/src/events.rs:404-408`) or in `next_event()`.

Once `stop_signal.store(true, Ordering::SeqCst)` executes, `is_stopped()` (`libsigner/src/events.rs:462-464`) becomes `true`, and `main_loop()` (`libsigner/src/runloop.rs` / `libsigner/src/events.rs:284-312`) exits on its next iteration, permanently silencing that signer's event stream until an operator manually restarts the process.

The reachability of this path is not merely theoretical: the shipped reference config `sample/conf/signer/mainnet-signer-conf.toml:39` sets `endpoint = "0.0.0.0:30000"` — i.e., the signer is documented to listen on all interfaces, not just loopback — and `stacks-signer/src/lib.rs:125-132` explicitly warns operators that "communicating with an external node...could potentially expose sensitive data or functionalities to security risks if additional proper security checks are not integrated," acknowledging the lack of an authentication layer on this listener.

### Impact Explanation
A remote, unprivileged attacker with plain TCP reachability to the signer's bound event port can send one crafted HTTP POST to permanently stop that signer's `main_loop()`, cutting off its stream of `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, and `/new_block` events from the node. Since signer consensus/proposal-validation participation depends on receiving these events, this is a single-message, repeatable, unauthenticated remote DoS against a signer — matching the "Critical: remote crash/unauthenticated DoS from few messages" category.

### Likelihood Explanation
No privileged role, secret, or prior state is required — only a raw TCP connection to the configured `endpoint` port, which per the shipped sample config binds to `0.0.0.0`. The attack is a single, trivially repeatable HTTP request and costs nothing to the attacker.

### Recommendation
Add authentication to the signer's event listener (e.g., require a shared secret/HMAC per request, mirroring the node's `auth_password`, or bind to loopback-only and require the node to reach it via a secured tunnel), and specifically gate `/shutdown` behind that check rather than accepting it from any TCP peer.

### Proof of Concept
```rust
// libsigner/src/tests/mod.rs style test
let ev = SignerEventReceiver::<SignerMessage>::new(false);
let (res_send, _res_recv) = channel();
let mut signer = Signer::new(SimpleRunLoop::new(1), ev, res_send);
let endpoint: SocketAddr = "127.0.0.1:31001".parse().unwrap();
let running_signer = signer.spawn(endpoint).unwrap();

// attacker, unrelated to SignerStopSignaler, opens its own raw TCP connection
let mut attacker_sock = TcpStream::connect(endpoint).unwrap();
let req = "POST /shutdown HTTP/1.1\r\nHost: attacker\r\nConnection: close\r\nContent-Length: 0\r\n\r\n";
attacker_sock.write_all(req.as_bytes()).unwrap();

sleep_ms(1000);
// main_loop has exited solely due to the attacker's message
let accepted_events = running_signer.stop().unwrap(); // returns immediately, no legitimate stop() ever called
```
This demonstrates `is_stopped()` (`libsigner/src/events.rs:462`) becomes `true` from an attacker-originated request alone.
