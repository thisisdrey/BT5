I'll investigate whether there's a genuine, reachable analog in Gitaly for this bug class (unbounded/unchecked numeric parameter leading to underflow/DoS), rather than assume one exists.### Title
Missing upper-bound enforcement on per-extension patch byte limits allows unbounded patch buffering - (File: internal/gitaly/diff/diff.go)

### Summary
`DiffService.CommitDiff` lets a caller supply per-file-extension overrides for the maximum patch size via `CommitDiffRequest.MaxPatchBytesForFileExtension`. While the top-level `MaxPatchBytes` value is clamped to a hard-coded upper bound (`maxPatchBytesUpperBound = 512000`), the individual values inside the `MaxPatchBytesForFileExtension` map are copied verbatim from the request and are never bounded, letting a caller effectively disable the patch-size cap for any chosen file extension.

### Finding Description
`enforceUpperBound()` is the single place in the diff parser meant to keep every limit within a sane, hard-coded ceiling: [1](#0-0) 

It clamps `MaxFiles`, `MaxLines`, `MaxBytes`, `SafeMax*` and `MaxPatchBytes`, but it does **not** iterate over or clamp the values inside `MaxPatchBytesForFileExtension`. That map is populated directly from unauthenticated-repo-scoped, but otherwise ordinary, user RPC input in `CommitDiff`: [2](#0-1) 

The effective per-file cap used while parsing a patch is computed by `maxPatchBytesForCurrentFile`/`maxPatchBytesFor`, which prefers the extension-specific override over `MaxPatchBytes` with no re-validation: [3](#0-2) 

Because `readNextDiff`/`consumeChunkLine` append every line of the current file's patch into `diff.Patch` in memory before the size check in `Parse()` is even evaluated, an attacker-chosen extension entry set to a very large value (e.g. `math.MaxInt32`) removes the intended 500 KB safety ceiling for any commit diff whose changed files use that extension: [4](#0-3) [5](#0-4) 

This is structurally the same bug class as the reported finding: a numeric limit/fee-like parameter that is supposed to be bounded by validation logic, but one code path (the per-extension override map) escapes that bound-checking, letting the caller push the value to an extreme and defeat the safety mechanism.

### Impact Explanation
`CommitDiff` is invoked for ordinary diff-viewing operations (e.g., viewing a merge request diff), reachable by any client authorized to call the RPC on a repository. By crafting a `CommitDiffRequest` with `EnforceLimits = true` and a `MaxPatchBytesForFileExtension` entry set to a huge value for an extension that matches a very large file in the repository (e.g. a large generated/binary-like text file committed with that extension), a caller can force Gitaly to buffer the entire patch for that file in memory and stream it back, bypassing the operator-intended 500 KB per-file patch cap. Repeated or concurrent requests against large files amplify memory and CPU consumption on the Gitaly node, degrading availability for other tenants sharing the node — a resource-exhaustion DoS of the diff RPC handler, analogous to the unbounded-fee DoS in the reference report.

### Likelihood Explanation
The bug is directly reachable by any client permitted to call `DiffService/CommitDiff` with no need for elevated privileges — only a repository the caller can already read and a commit pair whose diff includes a large file of an attacker-chosen extension. No leaked tokens, malicious peers, or dependency issues are required, and the request field involved (`MaxPatchBytesForFileExtension`) is explicitly part of the public request message, making exploitation straightforward once the field is discovered (it is present in the generated proto).

### Recommendation
Extend `enforceUpperBound()` (or the point where `MaxPatchBytesForFileExtension` is populated in `commit_diff.go`) to clamp every value in the map to `maxPatchBytesUpperBound`, exactly as is already done for `MaxPatchBytes`:
```go
for ext, size := range limit.MaxPatchBytesForFileExtension {
    limit.MaxPatchBytesForFileExtension[ext] = min(size, maxPatchBytesUpperBound)
}
```
This restores the intended invariant that no per-file patch limit, regardless of source, can exceed the hard-coded safety ceiling.

### Proof of Concept
1. Identify a commit range in a target repository where a changed file has a large patch (e.g. > 500 KB) and a known extension (e.g. `.txt`).
2. Call `DiffService.CommitDiff` with:
   - `EnforceLimits = true`
   - `MaxPatchBytes = 1024` (small, irrelevant since it will be overridden)
   - `MaxPatchBytesForFileExtension = {"txt": 2147483647}`
3. Observe that `enforceUpperBound()` clamps nothing in the map (verified at `internal/gitaly/diff/diff.go:278-287`), so `maxPatchBytesForCurrentFile()` returns `2147483647` for `.txt` files, and the parser buffers the entire multi-hundred-KB/MB patch into `diff.Patch` rather than truncating it at 500 KB, streaming the oversized patch back to the client and consuming server memory proportional to the file's actual diff size instead of the intended cap.

func maxPatchBytesFor(maxPatchBytes int, maxBytesForExtension map[string]int, toPath []byte) int {
	if len(maxBytesForExtension) > 0 {
		fileName := filepath.Base(string(toPath))
		key := filepath.Ext(fileName)

		if key == "" {
			key = fileName
		}

		if limitForExtension, ok := maxBytesForExtension[key]; ok {
			return limitForExtension
		}
	}

	return maxPatchBytes
}

func consumeChunkLine(reader *bufio.Reader, diff *Diff, skipPatch, updateStats bool) error {
	// The code that follows would be much simpler if we used
	// bufio.Reader.ReadBytes, but that allocates an intermediate copy of
	// each line which adds up to a lot of allocations. By using ReadSlice we
	// can copy bytes into currentDiff.Patch without intermediate
	// allocations.
	var byteCount int
	for done := false; !done; {
		line, err := reader.ReadSlice('\n')
		if updateStats && byteCount == 0 && len(line) > 0 {
			if line[0] == '+' {
				diff.LinesAdded++
			} else if line[0] == '-' {
				diff.LinesRemoved++
			}
		}
		byteCount += len(line)

		switch {
		case errors.Is(err, bufio.ErrBufferFull):
			// long line: keep reading
		case err != nil && !errors.Is(err, io.EOF):
			return fmt.Errorf("read chunk line: %w", err)
		default:
			done = true
		}

		if !skipPatch {
			diff.Patch = append(diff.Patch, line...)
		}
	}

	if updateStats {
		diff.byteCount += byteCount
		diff.lineCount++
	}

	return nil
}
