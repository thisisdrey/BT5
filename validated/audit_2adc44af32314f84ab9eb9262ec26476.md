### Title
Stale per-block `index-cache-` allows overvaluation of zToken collateral after `socialize-debt`, enabling under-collateralized borrows/avoided liquidation - (File: `mainnet/contracts/market/v0-4-market.clar`)

### Summary
`market.clar` caches vault `{index, lindex}` per `{timestamp, aid}` to save cross-contract calls within the same block. `vault-*.clar` `socialize-debt` writes down `lindex` directly and outside of the normal `accrue` flow, but does not invalidate the market's cache entry for that block. Any other operation in the same block that reads collateral/debt notional value for a zToken (`zsBTC`, `zSTX`, etc.) will get a cache HIT and reuse the pre-loss `lindex`, overvaluing that collateral relative to its true post-loss redemption value.

### Finding Description
`accrue-and-cache` in the market contract keys the cache purely on `{ timestamp: stacks-block-time, aid: aid }` and returns the cached `{index, lindex}` on any hit, without ever revalidating against the vault's actual current state: [1](#0-0) 

This cache is used by both debt notional valuation (via `accrue-and-cache` inside `calculate-asset-notional-value`) and by collateral valuation for rehypothecated zTokens (`accrue-collateral-asset` maps a zToken back to its underlying vault id and calls `accrue-and-cache`), so a single cached `lindex` per `(timestamp, aid)` backs every health check, borrow, and liquidation valuation of that asset for the rest of the block: [2](#0-1) 

`socialize-debt` on the vault side, however, mutates `lindex` directly to write down the redemption value after a bad-debt loss, and critically does **not** go through `accrue` first (unlike `system-borrow`/`system-repay`, which call `(try! (accrue))`): [3](#0-2) 

Because the market's `index-cache-` map is never told about this direct `lindex` write-down (there is no `map-delete`/`map-set` call from `socialize-debt` back into the market's cache), any prior cache entry for `{timestamp, aid}` populated earlier in the same block by an unrelated user's operation remains valid and stale. Every subsequent call to `accrue-and-cache` for that `aid` within the same block returns the old, higher `lindex`, even though the vault's true, discounted `lindex` is now lower. Mainnet's vault contracts (e.g. `v0-vault-sbtc.clar`, confirmed to contain an equivalent `socialize-debt` implementation) exhibit the same pattern.

This is structurally the same root cause as the referenced report: a value that should be recomputed per-operation (transaction-scoped gas usage / here, the true post-loss `lindex`) is instead served from a coarser, shared scope (cumulative block gas / here, a per-block timestamp cache) that does not track intra-block state changes performed by a different code path.

### Impact Explanation
Rehypothecated zToken collateral value is derived from `lindex` (`normalize (* actual price) decimals true`, where `actual` scales with the cached `lindex`/`index`). If `lindex` is not written down in the cache after `socialize-debt`, a zToken's on-chain collateral valuation in the same block remains higher than its true redemption value. This lets a position:
- borrow against overvalued zToken collateral beyond what the discounted vault backing actually supports (theft of funds / protocol insolvency), or
- avoid a liquidation that should have been triggered by the newly-discounted collateral value (temporary freezing of funds for other users / bad debt is not properly cleared).

Both fall within Critical/High impact (theft of funds at rest, protocol insolvency, or temporary freezing of funds).

### Likelihood Explanation
`socialize-debt` is a DAO/permissioned-triggered event (not attacker-controlled), but its downstream effect — a stale cached `lindex` — is exploitable by any ordinary user who transacts against the same asset within the same block/timestamp window (a single Stacks block can contain many transactions and `stacks-block-time` is constant for all of them). No DAO compromise or malicious registry update is required to exploit the resulting stale-cache window; only the timing coincidence of a `socialize-debt` call and a subsequent same-block borrow/health-check for the same `aid`.

### Recommendation
Invalidate (or refresh) the market's `index-cache-` entry for the affected `aid` whenever `socialize-debt` (or any other vault state mutation outside the standard `accrue` path) changes `lindex`/`index`, e.g. by having `socialize-debt` call into the market to `map-delete`/overwrite the current-timestamp cache entry, or by having `accrue-and-cache` always re-read authoritative vault state (a version/nonce check) instead of trusting a purely timestamp-keyed cache.

### Proof of Concept
1. Block at timestamp `T`. User A performs an operation involving `zsBTC` collateral, causing `market.clar` to call `accrue-and-cache(sBTC)` and cache `{index, lindex: L0}` at `{timestamp: T, aid: sBTC}`.
2. Later in the same block `T`, a DAO-triggered `socialize-debt` call on `vault-sbtc` writes down `lindex` to `L1 < L0` to reflect a bad-debt loss (per `local-testing/contracts/vault/vault-sbtc.clar:946-969`), but the market's cache entry for `{T, sBTC}` is untouched.
3. Still in block `T`, User B (or User A again) borrows against `zsBTC` collateral. `market.clar`'s `accrue-collateral-asset`/`accrue-and-cache` hits the cache and returns the stale `L0` instead of `L1`, overvaluing the `zsBTC` collateral.
4. User B's health check passes and/or borrow amount is computed against an inflated collateral value, allowing extraction of more debt than the true (post-loss) collateral backing supports.

```text
(define-private (accrue-and-cache (aid uint))
  (let ((cache-key { timestamp: stacks-block-time, aid: aid })
        (cached? (map-get? index-cache cache-key)))

    (match cached?
      ;; cache HIT: return cached value (1 read only)
      cached-indexes (ok cached-indexes)

      ;; cache MISS: accrue and cache (vault-accrue now returns indexes)
      (let ((indexes (try! (vault-accrue aid))))
        ;; store in cache
        (map-set index-cache cache-key indexes)
        (ok indexes)))))
```

```text
(define-public (socialize-debt (scaled-amount uint))
  (let ((scaled-principal (var-get principal-scaled))
        (borrowed (var-get total-borrowed))
        (idx (var-get index))
        (current-assets (var-get assets))
        (current-lindex (var-get lindex))
        (old-total-assets (total-assets))
        (debt-reduction (mul-div-down scaled-amount idx INDEX-PRECISION))
        (principal-reduction (if (> scaled-principal u0)
                                (mul-div-down scaled-amount borrowed scaled-principal)
                                u0))
        ;; Write down lindex proportionally to loss in total-assets
        (new-lindex (if (and (> old-total-assets u0) (> old-total-assets debt-reduction))
                       (mul-div-down current-lindex (- old-total-assets debt-reduction) old-total-assets)
                       u0)))

    (try! (check-caller-auth))
    (asserts! (> scaled-amount u0) ERR-AMOUNT-ZERO)

    (var-set lindex new-lindex)
    (var-set principal-scaled (if (> scaled-principal scaled-amount) (- scaled-principal scaled-amount) u0))
    (var-set total-borrowed (if (> borrowed principal-reduction) (- borrowed principal-reduction) u0))
    (var-set assets (if (> current-assets principal-reduction) (- current-assets principal-reduction) u0))
```
