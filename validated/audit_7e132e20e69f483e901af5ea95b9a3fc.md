### Title
Unauthenticated repository-path squatting via `CreateRepository`/`repoutil.Create` permanently blocks legitimate repository creation (DoS) - (File: `internal/gitaly/repoutil/create.go`)

### Summary
Any Gitaly client that can invoke `RepositoryService.CreateRepository` (or any other RPC that funnels through `repoutil.Create`, e.g. `CreateFork`, `CreateRepositoryFromBundle`, `CreateRepositoryFromURL`, `ReplicateRepository`) can pre-create an empty, default repository at a target relative path before the legitimate creation request for that same path arrives. Because `repoutil.Create` treats "path already exists" as a terminal, non-retriable `AlreadyExists` error and never overwrites or reconciles pre-existing content, the real creation flow (fork, mirror import, URL import, snapshot replication) permanently fails for that path, exactly mirroring the referenced Curves bug class: an unprivileged actor forcing a resource into a default/locked state before its rightful owner acts, permanently disabling the intended initialization path.

### Finding Description
`repoutil.Create` is the single choke point used to create Gitaly repositories with "race-free" semantics: [1](#0-0) 

The comment states the invariant explicitly: "The repository will only be created if it doesn't yet exist... Otherwise, the target path of the new repository will not be modified." If `os.Stat(targetPath)` succeeds, it immediately returns `structerr.NewAlreadyExists("repository exists already")` with no further action, and the caller RPC surfaces this as a hard failure.

This function backs several RPCs reachable by ordinary Gitaly clients:
- `CreateRepository` [2](#0-1) 
- `CreateFork` [3](#0-2) 
- `CreateRepositoryFromBundle` [4](#0-3) 
- `ReplicateRepository`'s snapshot-based creation path (`createFromSnapshot`) [5](#0-4) 

Because `CreateRepository` itself takes an arbitrary caller-supplied `RelativePath` with only syntactic validation (`ValidateRepository` with `WithSkipRepositoryExistenceCheck`), and Gitaly enforces no per-path ownership/ACL of its own (that logic lives in the layer calling Gitaly), any client capable of reaching the Repository service can issue `CreateRepository` for a relative path that another workflow (fork, import, snapshot-based replication) is about to use for the *same* path. The test suite confirms the exact failure mode when a target path is pre-populated before `CreateFork` runs — the create step unconditionally fails with `AlreadyExists`, whether the pre-existing content is an empty dir, a non-empty dir, or a stray file: [6](#0-5) 

Unlike the Curves `withdraw(amount=0)` bug — where the attacker-triggered branch silently deployed a permanent default-named token before the rightful subject acted — here the attacker-triggered branch (an early, unauthorized `CreateRepository` call) doesn't silently succeed with defaults; instead it deterministically **locks out** the rightful creation flow for that path with a hard `AlreadyExists` error, and Gitaly provides no self-healing/reconciliation for that state (the caller must notice the failure and manually intervene, e.g. `RemoveRepository`, before retrying).

### Impact Explanation
This is a denial-of-service against repository creation/import/fork/replication for any relative path an attacker can predict or control before the legitimate operation runs:
- Forks (`CreateFork`) targeting a known relative path can be blocked indefinitely.
- Mirror/URL imports (`CreateRepositoryFromURL`, `CreateRepositoryFromBundle`) can be pre-empted with an empty squatter repository, causing import failures that look like generic infrastructure errors to operators.
- Cross-node replication (`ReplicateRepository`'s snapshot creation branch) for a not-yet-existing target path can similarly be blocked.

The resulting failure is silent from the victim's point of view (a generic `AlreadyExists`/`Internal` error), making it hard to diagnose, and requires an administrator to detect and remove the squatter repository before the legitimate operation can proceed — an operational DoS with no self-recovery, analogous to the permanent lock-in described in the source report.

### Likelihood Explanation
Exploitability depends entirely on whether the attacker can predict or influence the target relative path before the legitimate creation call is made. Gitaly performs no ownership check of relative paths at this layer — enforcement of "who is allowed to create what path" is deferred entirely to the caller (e.g., Rails/Praefect routing), so from Gitaly's own reachable RPC surface this is unauthenticated-at-this-layer path squatting. Likelihood is therefore moderate-to-high specifically in deployments/topologies where the relative/replica path is predictable (e.g., sequential or otherwise guessable identifiers) or where a race exists between a fork/import request and any other actor's ability to call `CreateRepository` for the same storage/path before it. It is lower in strict deployments where an intermediary enforces per-path authorization prior to reaching Gitaly, since Gitaly itself is the last line of defense here, not the first.

### Recommendation
- Do not treat "target path already exists" as an unconditional terminal failure without any recourse; consider adding an idempotency/ownership token (e.g., binding creation to the same original request's transaction/lock rather than a bare `os.Stat`) so that a spurious/foreign pre-creation cannot permanently squat a path meant for a specific fork/import/replication operation.
- Where feasible, push relative-path reservation/authorization checks earlier (at the layer that owns path allocation) so that `CreateRepository` cannot be called out-of-band for a path that is not yet "claimed" by the legitimate workflow.
- Emit an actionable, distinguishable error (already partially done via `AlreadyExists`) together with additional context (e.g., who/when created the conflicting path) to make it easier for operators to detect and remediate squatting quickly, reducing the DoS window.

### Proof of Concept
1. Attacker (or any process able to reach the Gitaly `RepositoryService`) predicts/knows the future relative path `P` that will be used for a legitimate fork/import (e.g., `gittest.NewRepositoryName`-style deterministic or externally-known path).
2. Attacker calls `CreateRepository({Repository: {StorageName: S, RelativePath: P}})`. This succeeds and creates an empty bare repo at `P` via `repoutil.Create`. [7](#0-6) 
3. The legitimate operation later calls `CreateFork`/`CreateRepositoryFromURL`/`CreateRepositoryFromBundle`/`ReplicateRepository` targeting the same `{S, P}`.
4. `repoutil.Create` sees the path already exists and returns `AlreadyExists("repository exists already")`, exactly as exercised by the existing test `TestCreateFork_targetExists` (empty target directory case): [8](#0-7) 
5. The legitimate fork/import/replication permanently fails until an administrator manually removes the squatter repository and retries — the analog of the Curves bug's permanent default-state lock-in.

// Create will create a new repository in a race-free way with proper transactional semantics. The
// repository will only be created if it doesn't yet exist and if nodes which take part in the
// transaction reach quorum. Otherwise, the target path of the new repository will not be modified.
// The repository can optionally be seeded with contents
func Create(
	ctx context.Context,
	logger log.Logger,
	locator storage.Locator,
	gitCmdFactory gitcmd.CommandFactory,
	catfileCache catfile.Cache,
	txManager transaction.Manager,
	repoCounter *counter.RepositoryCounter,
	repository storage.Repository,
	seedRepository func(repository *gitalypb.Repository) error,
	options ...CreateOption,
) error {
	targetPath, err := locator.GetRepoPath(ctx, repository, storage.WithRepositoryVerificationSkipped())
	if err != nil {
		return structerr.NewInvalidArgument("locate repository: %w", err)
	}

	// The repository must not exist on disk already, or otherwise we won't be able to
	// create it with atomic semantics.
	if _, err := os.Stat(targetPath); !errors.Is(err, fs.ErrNotExist) {
		if err == nil {
			return structerr.NewAlreadyExists("repository exists already")
		}

		return fmt.Errorf("pre-lock stat: %w", err)
	}

func (s *server) CreateRepositoryFromBundle(stream gitalypb.RepositoryService_CreateRepositoryFromBundleServer) error {
	ctx := stream.Context()

	firstRequest, err := stream.Recv()
	if err != nil {
		return structerr.NewInternal("first request failed: %w", err)
	}

	repo := firstRequest.GetRepository()
	if err := s.locator.ValidateRepository(ctx, repo, storage.WithSkipRepositoryExistenceCheck()); err != nil {
		return structerr.NewInvalidArgument("%w", err)
	}

	firstRead := false
	bundleReader := streamio.NewReader(func() ([]byte, error) {
		if !firstRead {
			firstRead = true
			return firstRequest.GetData(), nil
		}

		request, err := stream.Recv()
		return request.GetData(), err
	})

	if err := repoutil.Create(ctx, s.logger, s.locator, s.gitCmdFactory, s.catfileCache, s.txManager, s.repositoryCounter, repo, func(repo *gitalypb.Repository) error {
		if err := s.localRepoFactory.Build(repo).CloneBundle(ctx, bundleReader); err != nil {
			return structerr.NewInternal("cloning bundle: %w", err)
		}

		return nil
	}, repoutil.WithSkipInit()); err != nil {
		return structerr.NewInternal("creating repository: %w", err)
	}
