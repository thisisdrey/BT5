### Title
Protocol fee bypass on NEP-245/IMT `TokenDiff` intents by splitting a negative delta into multiple unit-sized (`|delta|<=1`) intents - ([File: contracts/defuse/core/src/intents/token_diff.rs])

### Summary
`TokenDiff::execute_intent` computes the fee independently per intent using `Self::token_fee(token_id, amount, fee)`, and for `Nep245`/`Imt` token types this function returns `Pips::ZERO` whenever the per-intent `|delta| <= 1`. By splitting a single negative delta (e.g. `-2`) into multiple separate signed `TokenDiff` intents each with `|delta| == 1`, an attacker (optionally coordinating with a second attacker-controlled account as counterparty) causes the fee-skip rule to trigger on every leg, resulting in `0` fee collected instead of `Pips::fee_ceil(fee, 2)` that a single combined `{T: -2}` diff would owe.

### Finding Description
The broken binding: `fee_collector_balance_after(T) == Pips::fee_ceil(fee, total_negative_volume(T, batch))`. Actual: `fee_collector_balance_after(T) == 0` when the same total negative volume is split across multiple unit-sized `TokenDiff` intents.

Root cause is in `TokenDiff::token_fee`: [1](#0-0) 

and how it's invoked per-intent in `execute_intent`: [2](#0-1) 

Fee computation is entirely local to a single `TokenDiff::execute_intent` call — `fees_collected` is a fresh `Amounts::default()` created inside the function and there is no aggregation of `|delta|` across multiple `TokenDiff` intents in the same `MultiPayload`, across multiple `MultiPayload`s in the same batch, or even across multiple intents from the same signer. Each `MultiPayload` is processed independently by `execute_signed_intent`, and each `Intent::TokenDiff` inside it invokes `execute_intent` fresh: [3](#0-2) 

Attacker's payload: two separately signed `MultiPayload`s from account A, each containing a single `TokenDiff{diff: {T: -1}}` (T being a NEP-245 `TokenId`), plus one signed `MultiPayload` from account B containing `TokenDiff{diff: {T: 2}}`. `internal_apply_deltas` nets A's balance down by 2 total and B's up by 2 total, satisfying the zero-sum invariant enforced by `finalize`/`Deltas`, so none of `MultiPayload::verify`, `verify_intent_nonce`, `MaybeLegacyNonces::commit`, or the balance-invariant checks in `finalize` catch this, since they only enforce signature validity, nonce uniqueness, and net-zero balance changes — none of which are violated. The only place fee enforcement happens is `Self::token_fee(...).fee_ceil(amount)` computed with `amount = 1` on each leg, which for `TokenIdType::Nep245` explicitly matches the `if amount > 1 => {}` branch falling through only when `amount > 1`; with `amount == 1` it hits the `TokenIdType::Nep171 | TokenIdType::Nep245 | TokenIdType::Imt => return Pips::ZERO` arm, skipping the fee entirely on both legs.

### Impact Explanation
The Verifier's fee collector receives zero fee on a trade of NEP-245/IMT tokens that would otherwise owe `Pips::fee_ceil(fee, 2)` (or more, for larger splits), for any account willing to split trades into unit-sized `TokenDiff` legs. This is repeatable for any NEP-245 or IMT token, any batch size, and any account pair, and scales linearly with the number of unit splits — an attacker can fully bypass protocol fees on arbitrarily large NEP-245/IMT volumes by decomposing every trade into `|delta| == 1` legs. This matches the "protocol fees bypassed" Critical impact category since the fee_collector is systematically underpaid relative to what a single combined diff would owe.

### Likelihood Explanation
Preconditions are trivial: both accounts merely need existing Verifier balances of the NEP-245/IMT token being traded (no privileged role, no relayer key, no upgrade needed) and `fee > 0`. The attacker only pays standard NEAR gas for extra intents/signatures — a cost that becomes negligible relative to the avoided fee for any non-trivial trade size or when repeated across many trades. This is fully feasible and trivially repeatable by any unprivileged signer.

### Recommendation
Aggregate `|delta|` per `TokenId` across all `TokenDiff` intents processed within the same execution (or at minimum within the same `MultiPayload`/signer) before applying `Self::token_fee`'s unit-exemption rule, so that fee exemption for NEP-245/IMT is based on total negative volume of that token moved by the signer in the batch, not the per-intent delta. Alternatively, remove or tighten the `amount <= 1` fee exemption for `Nep245`/`Imt` token types, since MT balances are not inherently NFT-like singular units and can be freely fragmented.

### Proof of Concept
`cargo test` plan (near-workspaces sandbox, in `tests/src/tests/defuse/intents/token_diff.rs` style):
1. Set up Verifier with `fee > 0`, deploy a NEP-245 multi-token contract, credit account A and B with balances of token `T` (>=2 units) inside the Verifier.
2. Scenario 1 (baseline): execute a batch with A's single `TokenDiff{diff: {T: -2}}` and B's `TokenDiff{diff: {T: 2}}`. Assert `fee_collector` NEP-245 balance for `T` equals `Pips::fee_ceil(fee, 2)`.
3. Scenario 2 (split): execute a batch with A's two separately-signed `TokenDiff{diff: {T: -1}}` intents and B's `TokenDiff{diff: {T: 2}}`. Assert `fee_collector` NEP-245 balance for `T` equals `0`.
4. Assert `Scenario1_fee_collected != Scenario2_fee_collected` (specifically `Scenario2 == 0 < Scenario1`), proving the fee is bypassed by splitting, despite both batches producing identical net balance changes for A and B.

        mut self,
        signed: impl IntoIterator<Item = MultiPayload>,

        for signed in signed {
            self.execute_signed_intent(signed)?;
        }
        self.finalize()
    }

    fn execute_signed_intent(&mut self, signed: MultiPayload) -> Result<()> {
        // verify signed payload and get public key
        let public_key = signed.verify().ok_or(DefuseError::InvalidSignature)?;

        // calculate intent hash
        let hash = signed.hash();

        // extract NEP-413 payload
        let DefusePayload::<DefuseIntents> {
            signer_id,
            verifying_contract,
            deadline,
            nonce,
            message: intents,
        } = signed.extract_defuse_payload()?;

        // check recipient
        if verifying_contract != *self.state.verifying_contract() {
            return Err(DefuseError::WrongVerifyingContract);
        }

        self.inspector.on_deadline(deadline);

        // make sure message is still valid
        if deadline < Timestamp::now() {
            return Err(DefuseError::DeadlineExpired);
        }

        // make sure the account has this public key
        if !self.state.has_public_key(&signer_id, &public_key) {
            return Err(DefuseError::PublicKeyNotExist(signer_id, public_key));
        }

        // commit nonce
        self.verify_intent_nonce(nonce, deadline)?;
        self.state.commit_nonce(signer_id.clone(), nonce)?;

        intents.execute_intent(&signer_id, self, hash)?;
        self.inspector.on_intent_executed(&signer_id, hash, nonce);

        Ok(())
    }
