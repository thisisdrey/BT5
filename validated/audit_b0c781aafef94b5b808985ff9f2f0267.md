### Title
Unauthenticated remote `/shutdown` POST permanently halts `SignerEventReceiver` event loop - (File: `libsigner/src/events.rs`)

### Summary
`SignerEventReceiver::next_event` dispatches purely on the HTTP request path string with no check of caller identity, secret, or source. A POST to `/shutdown` sets `stop_signal` and returns `EventError::Terminated`, which `main_loop` treats as a clean exit, permanently ending the signer's event stream.

### Finding Description
In `next_event`, after confirming the method is POST, the handler matches `request.url()` against a fixed set of strings including `"/shutdown"`: [1](#0-0) . When the URL is `/shutdown`, it unconditionally stores `true` into `event_receiver.stop_signal` and returns `Err(EventError::Terminated)` — no signature, shared secret, or peer-address check gates this branch [2](#0-1) . `main_loop` interprets `EventError::Terminated` as "we're done" and breaks out of the loop entirely, permanently disabling event processing (`is_stopped()` will also short-circuit any subsequent `next_event` call) [3](#0-2) [4](#0-3) . `bind` simply opens an `HttpServer` on the configured `SocketAddr` with no additional access control layer [5](#0-4) . The intended caller of `/shutdown` is the signer's own `SignerStopSignaler::send`, which connects to `self.local_addr` and issues the same unauthenticated `POST /shutdown` request [6](#0-5)  — meaning the "authorization" for this endpoint is implicitly "can reach the bound TCP port," not "is the signer's own process." Any TCP client able to reach the bound address can send the identical bytes and achieve the same effect.

### Impact Explanation
A single crafted `POST /shutdown` HTTP/1.1 request permanently terminates the `SignerEventReceiver` main loop, which is the channel through which the signer receives StackerDB chunk events, block proposal responses, burn-block events, and new-block events. Once stopped, the signer stops responding to node-driven signing events, which can prevent it from validating/signing legitimate blocks — an unauthenticated remote DoS against a single signer with one HTTP request, matching the "Critical - remote crash/unauthenticated DoS from few messages" category, provided the listening socket is reachable from the attacker's network position.

### Likelihood Explanation
Exploitability is entirely dependent on how `bind`'s `SocketAddr` is configured for a given deployment (`endpoint` setting in `stacks-signer/src/config.rs`). If the signer binds the event-receiver socket to `127.0.0.1`/loopback only (the conventional deployment pattern, since this port is meant to receive events only from the local co-located Stacks node's event dispatcher), the attack is not remotely reachable and this finding does not apply to that configuration. If an operator binds to a non-loopback address (e.g., `0.0.0.0` or a routable interface, perhaps to allow a remote node to post events), any unprivileged remote TCP client could send the shutdown request with no cost beyond one TCP connection. I was not able to fully confirm the default/documented binding recommendation for `endpoint` in `stacks-signer/src/config.rs` within the available tool budget, so the real-world default exposure is uncertain.

### Recommendation
Require the same authentication used elsewhere between the node and signer (e.g., a shared secret header, mTLS, or an HMAC over the request body) before honoring `/shutdown` (and ideally all state-changing paths), or restrict `bind` to loopback-only unless explicitly overridden with a documented warning. At minimum, validate the source `request.remote_addr()` against an allow-list of the paired node's address before acting on `/shutdown`.

### Proof of Concept
```rust
// libsigner/src/events.rs (test module)
use std::net::{TcpListener, TcpStream};
use std::io::Write;

#[test]
fn unauthenticated_remote_shutdown() {
    let mut receiver: SignerEventReceiver<SomeSignerMessageType> = SignerEventReceiver::new(false);
    let addr = receiver.bind("127.0.0.1:0".parse().unwrap()).unwrap();

    // Simulate a plain, unauthenticated remote TCP client with no shared secret.
    let mut stream = TcpStream::connect(addr).unwrap();
    let body = "attacker-controlled";
    let req = format!(
        "POST /shutdown HTTP/1.1\r\nHost: {}\r\nConnection: close\r\nContent-Length: {}\r\n\r\n{}",
        addr, body.len(), body
    );
    stream.write_all(req.as_bytes()).unwrap();

    // next_event should now return Terminated, and is_stopped() becomes true,
    // with no credential ever presented.
    let result = receiver.next_event();
    assert!(matches!(result, Err(EventError::Terminated)));
    assert!(receiver.is_stopped());
}
```
This exercises the exact path `http_server.recv()` → `request.url() == "/shutdown"` → `stop_signal.store(true, ...)` → `Err(EventError::Terminated)` at [2](#0-1) , demonstrating that any TCP peer reaching the bound socket — not just the paired node — can halt the signer's event loop.
