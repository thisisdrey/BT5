### Title
Roaming trust check only rate-limits flapping back to the *same* prior remote, letting a spoofing attacker redirect a tunnel to an unlimited sequence of new addresses - ([File: outside.go])

### Summary
Nebula's `handleHostRoaming` updates a tunnel's trusted remote UDP address as soon as a packet decrypts successfully, and its only anti-flood safeguard (`RoamingSuppressSeconds`) suppresses roaming *back to the address that was just replaced*, not roaming to a *new* address each time. This mirrors the ParaSpace oracle flaw: a guard that only bounds a single step (or a single repeated value) can be walked around by an attacker who supplies a sequence of distinct "legitimate-looking" inputs, each of which individually satisfies the check.

### Finding Description
When a decrypted data/control packet arrives, `readOutsidePackets` calls `f.handleHostRoaming(hostinfo, via)` immediately after `hostinfo.ConnectionState.Decrypt` succeeds: [1](#0-0) 

`handleHostRoaming` then updates `hostinfo`'s trusted remote to the packet's source address (`via.UdpAddr`), subject only to the remote allow list and a suppression window: [2](#0-1) 

The suppression clause is:
```go
if !hostinfo.lastRoam.IsZero() && via.UdpAddr == hostinfo.lastRoamRemote && time.Since(hostinfo.lastRoam) < RoamingSuppressSeconds*time.Second {
    // suppress
}
```
This only fires when the *incoming* address equals `hostinfo.lastRoamRemote` (the address that was just displaced). It does nothing to limit how often the host roams to a *different* new address. Each individual roam is "valid" (the packet decrypted, the address passed the allow list), exactly like each individual `setPrice()` call in the oracle report was "valid" (within `maxPriceDeviation` of the prior value) — but a sequence of individually-valid single steps can drive the trusted state arbitrarily far, arbitrarily fast, with no aggregate/time-window limit.

The trust decision that gates a roam is nothing more than "an AEAD tag and a fresh replay counter validated" (`ConnectionState.Decrypt`, `bits.go`/`connection_state.go`), which is not bound to the UDP source address at all: [3](#0-2) 

Because the ciphertext itself carries no source-address binding, any party positioned to observe (on-path) or otherwise obtain distinct in-flight ciphertexts for a tunnel — without ever possessing the tunnel's key material or a CA-signed certificate — can re-inject each captured packet once from a different spoofed UDP source address. Each such injected packet, so long as its counter has not yet been consumed by the real path, will decrypt successfully and immediately relocate `hostinfo`'s trusted remote via `SetRemote`, because the suppression check only blocks *returning* to `lastRoamRemote`, never blocks moving to a *new* address.

### Impact Explanation
An attacker able to inject or race spoofed-source copies of legitimately captured ciphertext can repeatedly and rapidly redirect where a peer sends all subsequent tunnel traffic, since `SetRemote` overwrites the active path with no cumulative rate limit beyond the single-address suppression window. This is a remote state-poisoning / traffic-redirection primitive against the hostmap's peer-address trust, comparable in kind to the referenced report's "price can deviate by much more than the intended cap because the cap is checked per-step instead of over an elapsed-time window."

### Likelihood Explanation
Exploitation requires the ability to observe or race genuine encrypted traffic and re-inject it with a different spoofed source (a realistic capability for an on-path or off-path UDP-spoofing attacker on the underlay network), but does not require possession of the tunnel keys, a CA-signed certificate, or breaking the AEAD. The `lighthouse.remote_allow_list` can narrow the set of source addresses that are eligible, but by default (and in many deployments) this allow list is permissive, so the missing aggregate rate limit remains directly reachable.

### Recommendation
Rate-limit roaming based on elapsed time / roam count regardless of whether the new address matches `lastRoamRemote`, e.g., require a minimum interval between *any* two roam events (not just a return to the same address), or require multiple consecutive packets from the new address before promoting it, mirroring the report's recommendation to bound state changes by elapsed time rather than by comparing only to the immediately prior value.

### Proof of Concept
1. Establish a tunnel between `me` and `them`.
2. As an on-path attacker, capture a data packet `P1` sent from `them`'s real address `A0`.
3. Re-inject `P1` unmodified except for its UDP source, spoofed as `A1`. Because `Decrypt`/`bits.go` only checks the AEAD tag and replay counter (not source IP), this succeeds and `handleHostRoaming` promotes `A1` to `hostinfo`'s trusted remote (`RoamingSuppressSeconds` does not apply, since `lastRoamRemote` was still `A0`).
4. Capture a fresh packet `P2` and re-inject spoofed as `A2`; again, the check only ever compares against the single prior address (`A1`), so it passes.
5. Repeating this with any sequence of distinct spoofed source addresses roams `hostinfo`'s trusted remote arbitrarily often and arbitrarily far, with no aggregate throttle, exactly analogous to chaining multiple in-cap `setPrice()` calls to defeat a single-step deviation cap.

func (f *Interface) handleHostRoaming(hostinfo *HostInfo, via ViaSender) {
	curRemote := hostinfo.GetRemote()
	if !via.IsRelayed && curRemote != via.UdpAddr {
		if !f.lightHouse.GetRemoteAllowList().AllowAll(hostinfo.vpnAddrs, via.UdpAddr.Addr()) {
			if f.l.Enabled(context.Background(), slog.LevelDebug) {
				hostinfo.logger(f.l).Debug("lighthouse.remote_allow_list denied roaming", "newAddr", via.UdpAddr)
			}
			return
		}

		if !hostinfo.lastRoam.IsZero() && via.UdpAddr == hostinfo.lastRoamRemote && time.Since(hostinfo.lastRoam) < RoamingSuppressSeconds*time.Second {
			if f.l.Enabled(context.Background(), slog.LevelDebug) {
				hostinfo.logger(f.l).Debug("Suppressing roam back to previous remote",
					"suppressSeconds", RoamingSuppressSeconds,
					"udpAddr", curRemote,
					"newAddr", via.UdpAddr,
				)
			}
			return
		}

		hostinfo.logger(f.l).Info("Host roamed to new udp ip/port.",
			"udpAddr", curRemote,
			"newAddr", via.UdpAddr,
		)
		hostinfo.lastRoam = time.Now()
		hostinfo.lastRoamRemote = curRemote
		hostinfo.SetRemote(via.UdpAddr)
	}

}

func (cs *ConnectionState) Decrypt(l *slog.Logger, messageCounter uint64, out []byte, packet []byte, nb []byte) ([]byte, error) {
	var err error
	cs.decryptLock.Lock()
	result := cs.window.Check(l, messageCounter)
	cs.decryptLock.Unlock()
	if !result {
		return nil, ErrAlreadySeen
	}

	out, err = cs.dKey.DecryptDanger(out, packet[:header.Len], packet[header.Len:], messageCounter, nb)
	if err != nil {
		return nil, err
	}

	cs.decryptLock.Lock()
	result = cs.window.Update(l, messageCounter)
	cs.decryptLock.Unlock()
	if !result {
		return nil, ErrAlreadySeen
	}
	return out, nil
}
