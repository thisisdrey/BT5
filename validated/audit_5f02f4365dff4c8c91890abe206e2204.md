This confirms the finding. The signer's `endpoint` config is explicitly documented as bindable to `0.0.0.0:30000` (e.g. `sample/conf/signer/mainnet-signer-conf.toml` line 39, `endpoint = "0.0.0.0:30000"`), meaning the event receiver socket can be exposed on all network interfaces, not just localhost. The warning in `stacks-signer/src/lib.rs` even explicitly acknowledges risk of exposing this socket externally, but only warns about "sensitive data" exposure, not about the unauthenticated shutdown vector.

There is no authentication check anywhere in `next_event` before the URL dispatch — `/status`, `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/shutdown`, and `/new_block` are all matched purely on the request path with zero secret/token verification, confirmed by the full body of `next_event` at [1](#0-0) . The legitimate internal use of this endpoint is `SignerStopSignaler::send`, which connects to `self.local_addr` and POSTs `/shutdown` purely to wake up the blocking `http_server.recv()` call so the atomic `stop_signal` can be checked [2](#0-1) . But this same mechanism is reachable by any TCP client, since the branch `else if request.url() == "/shutdown"` unconditionally sets `stop_signal` to true and returns `Err(EventError::Terminated)` regardless of who sent the request [3](#0-2) . `main_loop` treats `EventError::Terminated` as a clean exit and `break`s out of the loop permanently [4](#0-3) , after which no further `next_event()` calls ever occur, so no future `SignerEvent` (block proposals, StackerDB chunks, burn blocks) is ever forwarded to the runloop until the process is restarted.

### Title
Unauthenticated remote shutdown of signer's event-receiver loop via `POST /shutdown` - ([File: libsigner/src/events.rs])

### Summary
`SignerEventReceiver::next_event` matches on `request.url() == "/shutdown"` with no authentication, secret, or peer-identity check before setting `stop_signal` and returning `EventError::Terminated`. Any TCP client that can reach the signer's bound event-receiver port (which per documented sample configs can be bound to `0.0.0.0`) can send a single unauthenticated `POST /shutdown HTTP/1.1` request to permanently halt the signer's event stream.

### Finding Description
The equality the code assumes — "only the local stacks-node that owns this signer's `SignerStopSignaler` may terminate its event stream" — is violated because `next_event` performs no authentication before dispatching on the URL path. The intended flow is `SignerStopSignaler::send` opening a loopback `TcpStream` to `self.local_addr` and POSTing `/shutdown` [5](#0-4) . However, the actual server-side handler in `next_event` treats any connection making this request identically: [3](#0-2) . There is no shared-secret, auth-header, or source-IP check anywhere before this branch (the same `next_event` function that handles `/status`, `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block` also has no such check for those paths, but this question is scoped to `/shutdown`). Once `stop_signal` is set to `true`, `main_loop` sees `Err(EventError::Terminated)` and does `break`, exiting the loop for good [6](#0-5) . Because `SignerEventReceiver::bind` accepts any `SocketAddr` supplied via config (`endpoint`), and the shipped sample config for mainnet explicitly sets `endpoint = "0.0.0.0:30000"` [7](#0-6) , this port is remotely reachable by design in documented deployments, matching the "connect to a node's bound port and send arbitrary bytes" attacker model.

### Impact Explanation
A single `POST /shutdown` HTTP request from any unprivileged remote client that can reach the bound endpoint permanently kills the signer's event-receiver main loop. After this, `SignerEventReceiver::next_event` is never invoked again, so block proposals, StackerDB chunk events, burn-block events, and new-block events from the local stacks-node are silently dropped forever, requiring a manual process restart to recover. This is an unauthenticated, single-message, permanent Denial of Service on the signer's block-processing pipeline, matching the "Critical - remote crash/unauthenticated DoS from few messages" category, and is fully repeatable against any signer instance whose `endpoint` is reachable.

### Likelihood Explanation
No precondition beyond network reachability to the bound `endpoint` port is required — no auth token, no signer key, no StackerDB slot ownership, no privileged role. The attack is a single, trivially-constructed HTTP POST with any body (attacker cost is negligible), and documented sample configuration explicitly binds this listener to `0.0.0.0`, making it remotely reachable in realistic deployments as warned (informally) in `SpawnedSigner::new`'s log warning [8](#0-7) .

### Recommendation
Require a shared secret or authentication token (e.g., reuse `auth_password`/similar mechanism already used between node and signer) on the `/shutdown` endpoint, or restrict the stop-signal mechanism to an in-process signal (e.g., a self-pipe/local channel) instead of a network-reachable HTTP route, or bind the shutdown-capable listener only to loopback and validate the peer address before honoring `/shutdown`.

```rust
// In libsigner/src/events.rs test module or a new integration test:
#[test]
fn test_unauthenticated_remote_shutdown() {
    let mut receiver: SignerEventReceiver<StacksMessage /* or any T */> =
        SignerEventReceiver::new(false);
    let addr = "127.0.0.1:0".parse().unwrap();
    let bound_addr = receiver.bind(addr).unwrap();

    // Spawn main_loop in a thread with a channel consumer
    let (tx, _rx) = std::sync::mpsc::channel();
    receiver.add_consumer(tx);
    let handle = std::thread::spawn(move || {
        receiver.main_loop();
    });

    // Simulate an unprivileged remote attacker: no secret, no auth header
    let mut stream = std::net::TcpStream::connect(bound_addr).unwrap();
    let body = "attacker shutdown";
    let req = format!(
        "POST /shutdown HTTP/1.1\r\nHost: {bound_addr}\r\nConnection: close\r\nContent-Length: {}\r\n\r\n{body}",
        body.len()
    );
    stream.write_all(req.as_bytes()).unwrap();

    // main_loop should exit (break) permanently after a single unauthenticated request
    handle.join().unwrap(); // returns because main_loop hit `Err(EventError::Terminated) => break`
    // Any subsequent legitimate node POST to /stackerdb_chunks etc. would never be processed again.
}
```
The assertion point is that `main_loop` returns/exits (the thread `join()`s) after exactly one crafted, unauthenticated request, and `is_stopped()` on the receiver's `stop_signal` reads `true` — with zero prior legitimate traffic and no secret presented.
