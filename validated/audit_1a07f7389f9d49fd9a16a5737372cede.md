### Title
Unauthenticated event injection on the signer's HTTP event listener - ([File: libsigner/src/events.rs])

### Summary
`SignerEventReceiver::next_event` dispatches incoming HTTP POST requests purely by URL path (`/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block`) with no check on the identity of the connecting client. Any TCP-reachable party that can open a connection to the signer's bound listener address can POST a forged JSON body that deserializes into a `StackerDBChunksEvent` and is forwarded directly into the signer's runloop as if it came from the trusted local `stacks-node`.

### Finding Description
The broken equality claimed is: "the sender of an HTTP POST to `/stackerdb_chunks` == the configured local stacks-node process." In `SignerEventReceiver::next_event` [1](#0-0) , the handler calls `http_server.recv()` and then dispatches purely on `request.url()` and `request.method()` — there is no check of `request.remote_addr()`, no shared-secret/HMAC header validation, and no mTLS. When the path is `/stackerdb_chunks`, `process_event::<T, StackerDBChunksEvent>(request)` is invoked [2](#0-1) .

`process_event` reads the raw HTTP body and deserializes it with `serde_json::from_slice::<StackerDBChunksEvent>`, with no authentication of the origin, before converting it via `TryInto<SignerEvent<T>>` [3](#0-2) . The resulting `SignerEvent` is then pushed straight to `forward_event`, which sends it to the signer runloop's channel [4](#0-3) .

For a forged `contract_id` matching `MINERS_NAME`, the `TryFrom<StackerDBChunksEvent>` implementation deserializes attacker-controlled `chunk.data` directly with `T::consensus_deserialize`, with **no signature verification at all** on the miner lane [5](#0-4) . For the `SIGNERS_NAME` lane, the code does call `chunk.recover_pk()`, but since the attacker constructs the entire `StackerDBChunkData` structure themselves (including the signature bytes), this recovers whatever public key corresponds to a signature the attacker freely chooses — it does not verify the sender is an actual, network-legitimate StackerDB slot holder [6](#0-5) .

The only authentication token present in the system (`auth_password` / `auth_token`) protects the opposite direction — the signer's calls into the node's block-validation RPC — and is not checked anywhere on the signer's own inbound event listener [7](#0-6) . The sample/reference configuration shipped in this repo even binds the signer's listener to `0.0.0.0:30000` [8](#0-7) , i.e., all interfaces, making the endpoint reachable from the network with no additional privilege required.

### Impact Explanation
Any remote party that can reach the signer's bound port can, with no credentials at all, inject arbitrary `SignerEvent::MinerMessages` or `SignerEvent::SignerMessages` into the signer's runloop, entirely bypassing the actual StackerDB replication/gossip layer. This is an unauthenticated write into the signer's internal event stream, satisfying the "unauthenticated/unauthorized write to state" Critical category — the write goes directly to the process's decision-input channel rather than to on-chain StackerDB state, but it fully spoofs what the signer believes it received from the node/StackerDB. This is repeatable per TCP connection/POST with no rate limiting beyond what `tiny_http` itself provides.

### Likelihood Explanation
Preconditions: the attacker needs only TCP reachability to the signer's configured `endpoint` address (the value passed to `SignerEventReceiver::bind`). No node RPC secret, no StackerDB slot ownership, and no signing key are required, since the endpoint performs zero origin/auth checks on inbound HTTP requests [1](#0-0) . The shipped reference config binds this listener on `0.0.0.0`, which is exactly the deployment pattern documented in this repo's own sample configs [8](#0-7) , making the attack trivially reachable in such deployments. Attack cost is a single crafted HTTP POST; it is fully repeatable.

### Recommendation
Add an authentication mechanism to the signer's inbound event HTTP server — e.g., require the same shared secret already used for `auth_password`/`auth_token` to be presented as a header on every POST to `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, and `/new_block`, and reject requests that don't present the correct token before the body is even parsed. Additionally, document/enforce that the signer's `endpoint` should default to a loopback bind rather than `0.0.0.0`.

```rust
use std::io::Write;
use std::net::TcpStream;
use libsigner::{SignerEventReceiver, EventReceiver};

#[test]
fn foreign_client_can_inject_stackerdb_chunks_event() {
    let mut receiver: SignerEventReceiver<SomeSignerMessage> = SignerEventReceiver::new(false);
    let addr = receiver.bind("127.0.0.1:0".parse().unwrap()).unwrap();

    // "Foreign" thread simulating an attacker with no credentials
    let attacker = std::thread::spawn(move || {
        let forged_body = serde_json::json!({
            "contract_id": "SP000000000000000000002Q6VF78.signers-1-1",
            "modified_slots": [ /* attacker-crafted chunk with self-signed signature */ ]
        }).to_string();
        let mut stream = TcpStream::connect(addr).unwrap();
        let req = format!(
            "POST /stackerdb_chunks HTTP/1.1\r\nHost: {addr}\r\nContent-Length: {}\r\nContent-Type: application/json\r\n\r\n{}",
            forged_body.len(), forged_body
        );
        stream.write_all(req.as_bytes()).unwrap();
    });

    // No peer-address / auth check occurs here:
    let event = receiver.next_event().unwrap();
    // assert event is accepted as SignerEvent::SignerMessages{..} despite
    // originating from an unauthenticated foreign TCP client, proving
    // next_event() never validates request.remote_addr() or any shared secret.
    attacker.join().unwrap();
}
```

```rust
    fn next_event(&mut self) -> Result<SignerEvent<T>, EventError> {
        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)
            } else if request.url() == "/new_block" {
                process_event::<T, StacksBlockEvent>(request)
            } else {
                let url = request.url().to_string();
                debug!(
                    "[{:?}] next_event got request with unexpected url {}, return OK so other side doesn't keep sending this",
                    event_receiver.local_addr,
                    url
                );
                ack_dispatcher(request);
                Err(EventError::UnrecognizedEvent(url))
            }
        })?
    }
```

```rust
    fn forward_event(&mut self, ev: SignerEvent<T>) -> bool {
        if self.out_channels.is_empty() {
            // nothing to do
            error!("No channels connected to event receiver");
            false
        } else if self.out_channels.len() == 1 {
            // avoid a clone
            if let Err(e) = self.out_channels[0].send(ev) {
                error!("Failed to send to signer runloop: {:?}", &e);
                return false;
            }
            true
        } else {
            for (i, out_channel) in self.out_channels.iter().enumerate() {
                if let Err(e) = out_channel.send(ev.clone()) {
                    error!("Failed to send to signer runloop #{}: {:?}", i, &e);
                    return false;
                }
            }
            true
        }
    }
```

```rust
fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}
```
