### Title
Unauthenticated `RecvError` Control Packets Allow Any Remote Attacker to Force-Close Established Nebula Tunnels - ([File: outside.go])

### Summary
`header.RecvError` control packets are processed by `handleRecvError` before any certificate or cryptographic authentication takes place, and are accepted from any UDP source that supplies a matching 32-bit tunnel index. This lets a remote attacker with no CA-signed certificate tear down an already-established tunnel between two legitimate nebula nodes.

### Finding Description
Similar to the `collectPositionSwapFee` report — where a function meant to be restricted to a privileged caller (the fund manager) had no caller check — Nebula's `RecvError` handling path is meant to only accept teardown signals from a genuine tunnel peer, but the check performed is weak and, in one branch, skipped entirely.

In `readOutsidePackets`, `header.RecvError` is dispatched immediately after header parsing and before the packet has gone through any decryption or certificate validation step: [1](#0-0) 

`handleRecvError` then looks up the hostinfo purely by the plaintext `RemoteIndex` field from the header, and only guards against spoofing when the tunnel's current remote address happens to be valid: [2](#0-1) 

The only checks performed are:
1. `f.acceptRecvErrorConfig.ShouldRecvError(addr)` — a static config gate (`always`/`never`/`private`), not an authentication check.
2. `hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)` — a lookup keyed only on the 32-bit index, which is transmitted unencrypted in every packet header and is therefore observable to any on-path or off-path observer, or bruteforceable.
3. `if hr.IsValid() && hr != addr` — spoofing detection that is entirely skipped when the tunnel's remote address (`hr`) is not yet valid (e.g., during roaming/early tunnel life), and otherwise relies solely on comparing the UDP source address, which is trivially forgeable over UDP.

None of these steps involve verifying a CA-signed certificate, a MAC, or any cryptographic proof of tunnel membership — mirroring the missing `onlyManager` check in the original report, but here the "caller" that should be authenticated is the remote peer, and the "privileged function" is `f.closeTunnel(hostinfo)` plus `f.handshakeManager.DeleteHostInfo(hostinfo)`.

### Impact Explanation
A successful call triggers `f.closeTunnel(hostinfo)` and deletes the pending handshake state, forcibly terminating an active tunnel between two nebula nodes. This is a remote denial-of-service / state-poisoning primitive: an attacker holding no CA-signed certificate at all can disrupt overlay connectivity between arbitrary pairs of legitimate nodes by sending spoofed, unauthenticated `RecvError` packets, provided they can supply/guess the correct `RemoteIndex`.

### Likelihood Explanation
`RemoteIndex` is sent in cleartext in every nebula packet header, so any attacker capable of observing even a single packet on the path (or performing traffic analysis) obtains a valid index; even a blind off-path attacker only needs to guess/brute a 32-bit value and forge a UDP source address, which is straightforward over UDP without additional filtering. The `acceptRecvErrorConfig` setting can reduce exposure (e.g. `recvErrorPrivate`/`recvErrorNever`) but the default and `recvErrorAlways` configurations leave this fully exposed, and the spoof check is bypassable whenever the hostinfo's remote address is not yet marked valid.

### Recommendation
Do not act on `RecvError` solely based on index + best-effort address comparison. Either bind acceptance to a value only the true peer could produce (e.g., a token derived from the current session key, or requiring the packet to be verifiable under the existing tunnel's established keys) or discontinue trusting `RecvError` for hostinfo teardown from non-established sessions. At minimum, closing the tunnel should never occur when `hr` is invalid, since this removes the only spoofing check present, and rate limiting / additional corroboration (e.g., only accept after repeated genuine send failures observed locally) should be applied.

### Proof of Concept
1. Observe or determine the `RemoteIndex` of an active tunnel between node A and node B (visible in cleartext in the header of any packet exchanged, or guessable).
2. As an attacker holding no CA-signed certificate, craft a UDP packet with `header.RecvError` type/subtype and the observed `RemoteIndex`, sourced from a spoofed UDP address matching (or simply sent before roaming stabilizes so `hr` is invalid) node B's known/expected UDP endpoint.
3. Send this packet to node A.
4. `readOutsidePackets` dispatches it to `handleRecvError` prior to any decryption/cert check; `QueryReverseIndex` finds the hostinfo, the spoof check is bypassed (or defeated via UDP source spoofing), and `f.closeTunnel(hostinfo)` plus `handshakeManager.DeleteHostInfo` execute, tearing down the legitimate A↔B tunnel without the attacker ever presenting a valid certificate.

func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
