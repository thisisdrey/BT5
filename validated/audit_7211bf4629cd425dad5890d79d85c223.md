### Title
Unvalidated tar path in `extractArchive` allows path traversal during WAL log-entry replay - (File: `internal/cli/gitaly/subcmd_recovery_replay.go`)

### Summary
`extractArchive` in `internal/cli/gitaly/subcmd_recovery_replay.go` extracts a tar stream (used when replaying WAL log entries during recovery) by joining `header.Name` directly onto the destination path without verifying that the resulting path stays within the target directory. This is the same class of "insufficient guard before performing a resource operation" flaw as the external report — the reported bug consists of a loop finishing without checking whether the operation's precondition (`_amount == 0` / "path stays within boundary") actually held, and here the extraction loop likewise finishes writing files without validating a boundary condition on `target`.

### Finding Description
`extractArchive` builds `target := filepath.Join(path, header.Name)` and then unconditionally creates directories (`tar.TypeDir`) or opens/writes files (`tar.TypeReg`) at `target`: [1](#0-0) 

Unlike the sibling function `extractTarToDirectory` in `internal/gitaly/service/repository/replicate.go`, which explicitly validates that every `targetPath` (including symlink and hardlink targets) stays under `targetDir` before writing: [2](#0-1) 

`extractArchive` has no equivalent `strings.HasPrefix(target, path+string(os.PathSeparator))` check. A tar header name containing `../` sequences (e.g. `../../etc/foo`) will cause `filepath.Join(path, header.Name)` to resolve outside of `path`, and the function will happily `os.MkdirAll` or `os.OpenFile`/`io.Copy` to that escaped location. This function is invoked from `processLogEntry`, which reads WAL log entry archives during `gitaly recovery replay`: [3](#0-2) 

### Impact Explanation
If the tar archive being replayed originates from or can be influenced by a source outside of the trusted control plane (e.g. a corrupted/tampered WAL archive, a backup fetched from a possibly-compromised sink, or a log entry replicated from a byzantine/faulty node), the crafted tar entries can write or overwrite arbitrary files on the Gitaly host filesystem outside the intended recovery directory — a storage escape analogous to the "no bound-check before completing the operation" pattern in the report. This is a concrete extraction-escape bug class explicitly listed as acceptable evidence.

### Likelihood Explanation
Exploitability depends on how trusted the WAL archive input is at the point `extractArchive` runs; if archive contents can be influenced by a replicated/relayed log entry (e.g. through a compromised or misbehaving peer in a multi-node WAL replication setup, or through a corrupted backup restore path), the extraction path is directly reachable without requiring any privileged local access — it is reached simply by the `gitaly recovery replay` operational flow.

### Recommendation
Apply the same boundary validation used in `extractTarToDirectory` to `extractArchive`: after computing `target`, verify `strings.HasPrefix(filepath.Clean(target), filepath.Clean(path)+string(os.PathSeparator)) || target == path` before performing any `MkdirAll`/`OpenFile` operation, and reject the entry (returning an error) otherwise.

### Proof of Concept
1. Construct a tar stream containing a header with `Name: "../../../../tmp/evil"` and `Typeflag: tar.TypeReg`.
2. Feed this tar stream as the `reader` argument to `extractArchive(reader, path)` (reachable via `processLogEntry` during `gitaly recovery replay`).
3. Observe that `target := filepath.Join(path, header.Name)` resolves to `/tmp/evil`, outside `path`, and `os.OpenFile`/`io.Copy` write attacker-controlled content there — unlike the guarded twin function `extractTarToDirectory`, which would reject this with `"invalid file path in tar"`.

func extractArchive(reader io.Reader, path string) error {
	tr := tar.NewReader(reader)
	for {
		header, err := tr.Next()
		if err == io.EOF {
			break
		}
		if err != nil {
			return fmt.Errorf("read tar header: %w", err)
		}

		target := filepath.Join(path, header.Name)
		switch header.Typeflag {
		case tar.TypeDir:
			if err := os.MkdirAll(target, mode.Directory); err != nil {
				return fmt.Errorf("create directory: %w", err)
			}
		case tar.TypeReg:
			f, err := os.OpenFile(target, os.O_CREATE|os.O_RDWR, os.FileMode(header.Mode))
			if err != nil {
				return fmt.Errorf("create file: %w", err)
			}
			if _, err := io.Copy(f, tr); err != nil {
				f.Close()
				return fmt.Errorf("write file content: %w", err)
			}
			f.Close()
		default:
			return fmt.Errorf("tar header type not supported: %d", header.Typeflag)
		}
	}
