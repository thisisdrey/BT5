Confirmed: transaction IDs are generated by a simple incrementing `atomic.AddUint64` counter [1](#0-0) , not randomly as the design doc claims [2](#0-1) , and `StopTransaction` takes only a bare `transaction_id` with no repository or node ownership check whatsoever [3](#0-2) [4](#0-3) .

### Title
Cross-repository reference-transaction hijacking via predictable transaction IDs in Praefect's `RefTransaction` service - (File: internal/praefect/transactions/manager.go)

### Summary
Praefect's `RefTransaction` gRPC service (`VoteTransaction`/`StopTransaction`) identifies in-flight reference transactions solely by a sequential `uint64` ID, with no verification that the calling voter is actually one of the nodes registered to that transaction, and no binding of the `transaction_id` to the `Repository` field the client also supplies. Any Gitaly node's reference-transaction hook — invoked automatically for every ordinary git push — can supply an arbitrary `transaction_id`/`node` pair and thereby vote on, stop, or lock the repo-write-lock of a transaction belonging to a completely different, concurrent push from another user/repository.

### Finding Description
`Manager.RegisterTransaction` allocates transaction IDs from a simple, unauthenticated, monotonically increasing counter shared across the whole Praefect process and all virtual storages/repositories: [5](#0-4) 

The corresponding gRPC handlers accept this ID directly from the caller with no cross-check against the caller's identity or repository: [6](#0-5) [7](#0-6) 

Internally, `voteTransaction` and `StopTransaction` look the transaction up purely by numeric ID in a global map (`mgr.transactions[transactionID]`) and act on it — including acquiring/renewing/releasing the per-repository write lock — without validating that `node` is actually one of the transaction's registered voters for that particular repository, or that `storageName`/`repoRelativePath` match the transaction that was actually registered for this ID: [8](#0-7) [4](#0-3) 

`transaction.vote()`/`cancelNodeVoter()` only validate that the `node` string exists in that particular transaction's voter map [9](#0-8) , but crucially this is the *only* check — nothing ties the RPC caller (a specific Gitaly node acting on behalf of a specific ongoing push) to that transaction ID in the first place. This mirrors the reported bug class exactly: an authorized-but-unrelated actor (any Gitaly node handling any push) can act (vote/stop) on a resource (an in-flight reference transaction) that belongs to someone else, because the access check validates only "is this a legitimate voter name" rather than "is this the transaction that was actually created for my push."

This RPC path is reached automatically and unconditionally as part of an ordinary user's push: every git push drives the `reference-transaction` hook, which calls `ReferenceTransactionHook` on Gitaly [10](#0-9) , which votes via the backchannel using the `transaction_id`/`node` embedded in the hooks payload [11](#0-10) . Because IDs are sequential, a pusher on one repository can trivially predict the IDs of concurrent transactions belonging to unrelated pushes on other repositories in the same cluster and call `StopTransaction`/`VoteTransaction` against them.

### Impact Explanation
An unprivileged user who can push to any repository served by the cluster (via their own, legitimately-triggered hook invocation) can:
- Call `StopTransaction` with a guessed/adjacent `transaction_id` to prematurely abort other users' unrelated, concurrent pushes cluster-wide, causing `ABORT`/`STOP` on Gitaly nodes and failing legitimate pushes (`transaction.go:125-137`, `manager.go:228-251`).
- Call `VoteTransaction` with a mismatched `storageName`/`repoRelativePath` but a valid guessed `transaction_id` to acquire/renew/release another repository's write lock, potentially causing serialization interference or unlocking a lock prematurely for concurrent writers (`manager.go:154-177`, `manager.go:272-306`).

This is a cluster-wide denial-of-service on Gitaly Cluster's write path, exploitable by any ordinary authenticated Git user with push access to at least one repository — no special privilege beyond normal push access is required.

### Likelihood Explanation
Likelihood is high in a busy cluster: transaction IDs are sequential (`atomic.AddUint64`), so an attacker simply needs to register/observe one transaction (via their own push) to know a tight, low-entropy range of concurrently active IDs to brute-force against `StopTransaction`/`VoteTransaction`. No cryptographic secret, token, or repository ownership binding gates the call.

### Recommendation
- Short term: bind each transaction to the repository (`storageName`/`repoRelativePath`) it was registered for, and reject `VoteTransaction`/`StopTransaction`/`CancelTransactionNodeVoter` calls whose `Repository` field does not match the transaction's registered repository.
- Long term: replace the sequential counter with a cryptographically random, unguessable transaction identifier (as the design doc claims is already the case), and additionally authenticate the calling Gitaly node/backchannel against the specific set of voters registered for the transaction, rather than trusting any caller that can supply a valid `node` name string.

### Proof of Concept
1. Attacker (or any user with push access to `repo-attacker.git`) pushes to trigger a normal reference-transaction hook; Praefect registers a transaction and returns e.g. `transaction_id = N` via `RegisterTransaction` (`manager.go:94-108`).
2. Concurrently, victim pushes to `repo-victim.git`, and Praefect registers transaction `N+1` for it (same global sequence).
3. Attacker's hook process (or any process with backchannel access, since IDs need not even be observed from their own push — nearby IDs can simply be brute-forced) calls:
   ```
   RefTransaction.StopTransaction(&StopTransactionRequest{TransactionId: N+1})
   ```
   using the handler at `internal/praefect/service/transaction/server.go:63-77`, which forwards straight to `Manager.StopTransaction` (`manager.go:228-251`) with no ownership check.
4. The victim's in-flight transaction is put into `transactionStopped` state; any pending/future votes on it return `STOP`, and the victim's push may fail or behave unexpectedly, while the attacker's own push completes normally — reproducing the reported "cancel anyone else's pending operation" DoS pattern in Gitaly Cluster's transaction subsystem.

func (mgr *Manager) RegisterTransaction(ctx context.Context, voters []Voter, threshold uint) (Transaction, CancelFunc, error) {
	mgr.lock.Lock()
	defer mgr.lock.Unlock()

	transactionID := atomic.AddUint64(&mgr.idSequence, 1)

	transaction, err := newTransaction(transactionID, voters, threshold)
	if err != nil {
		return nil, nil, err
	}

	if _, ok := mgr.transactions[transactionID]; ok {
		return nil, nil, errors.New("transaction exists already")
	}
	mgr.transactions[transactionID] = transaction

func (mgr *Manager) voteTransaction(ctx context.Context, transactionID uint64, storageName, repoRelativePath, node string,
	phase gitalypb.VoteTransactionRequest_Phase, vote voting.Vote,
) (returnedErr error) {
	mgr.lock.Lock()
	transaction, ok := mgr.transactions[transactionID]
	mgr.lock.Unlock()

	if !ok {
		return fmt.Errorf("%w: %d", ErrNotFound, transactionID)
	}

	err := mgr.lockRepoForTransaction(ctx, transactionID, storageName, repoRelativePath, phase)
	if err != nil {
		return fmt.Errorf("lock transaction %d: %w", transactionID, err)
	}
	defer func() {
		mgr.unlockRepoForTransaction(ctx, transactionID, returnedErr, phase)
	}()
	if err := transaction.vote(ctx, node, vote); err != nil {
		return err
	}

	return nil
}

func (mgr *Manager) StopTransaction(ctx context.Context, transactionID uint64) error {
	mgr.lock.Lock()
	transaction, ok := mgr.transactions[transactionID]
	if ok {
		// Release while holding mgr.lock so a concurrent voteTransaction
		// can't acquire a fresh repo lock between this release and stop.
		mgr.releaseRepoLock(transactionID)
	}
	mgr.lock.Unlock()

	if !ok {
		return fmt.Errorf("%w: %d", ErrNotFound, transactionID)
	}
	if err := transaction.stop(); err != nil {
		return err
	}

	mgr.logger.WithFields(log.Fields{
		"transaction.id": transactionID,
	}).DebugContext(ctx, "VoteTransaction: transaction stopped")
	mgr.counterMetric.WithLabelValues("stopped").Inc()

	return nil
}

// VoteTransaction is called by a client who's casting a vote on a reference
// transaction, blocking until a vote across all participating nodes has been
// completed.
func (s *Server) VoteTransaction(ctx context.Context, in *gitalypb.VoteTransactionRequest) (*gitalypb.VoteTransactionResponse, error) {
	vote, err := voting.VoteFromHash(in.GetReferenceUpdatesHash())
	if err != nil {
		return nil, structerr.NewInvalidArgument("invalid reference update hash: %w", err)
	}
	if err := s.txMgr.VoteTransaction(ctx, in.GetTransactionId(), in.GetRepository().GetStorageName(),
		in.GetRepository().GetRelativePath(), in.GetNode(), in.GetPhase(), vote); err != nil {
		switch {
		case errors.Is(err, transactions.ErrNotFound):
			return nil, structerr.NewNotFound("%w", err)
		case errors.Is(err, transactions.ErrTransactionCanceled):
			return nil, structerr.NewCanceled("%w", err)
		case errors.Is(err, transactions.ErrTransactionStopped):
			return &gitalypb.VoteTransactionResponse{
				State: gitalypb.VoteTransactionResponse_STOP,
			}, nil
		case errors.Is(err, transactions.ErrTransactionFailed):
			return &gitalypb.VoteTransactionResponse{
				State: gitalypb.VoteTransactionResponse_ABORT,
			}, nil
		default:
			return nil, structerr.NewInternal("%w", err)
		}
	}

	return &gitalypb.VoteTransactionResponse{
		State: gitalypb.VoteTransactionResponse_COMMIT,
	}, nil
}

// StopTransaction is called by a client who wants to gracefully stop a
// transaction. All voters waiting for quorum will be stopped and new votes
// will not get accepted anymore. It is fine to call this RPC multiple times on
// the same transaction.
func (s *Server) StopTransaction(ctx context.Context, in *gitalypb.StopTransactionRequest) (*gitalypb.StopTransactionResponse, error) {

		case errors.Is(err, transactions.ErrNotFound):

			return &gitalypb.StopTransactionResponse{}, nil
		default:
			return nil, structerr.NewInternal("%w", err)

// Transaction is an interface for transactions.
type Transaction interface {
	// ID returns the ID of the transaction which uniquely identifies the transaction.
	ID() uint64
	// CountSubtransactions counts the number of subtransactions.
	CountSubtransactions() int
	// State returns the state of each voter part of the transaction.
	State() (map[string]VoteResult, error)
	// DidVote returns whether the given node has cast a vote.
	DidVote(string) bool
}

// transaction is a session where a set of voters votes on one or more
// subtransactions. Subtransactions are a sequence of sessions, where each node
// needs to go through the same sequence and agree on the same thing in the end
// in order to have the complete transaction succeed.
type transaction struct {
	id        uint64
	threshold uint
	voters    []Voter

	lock            sync.Mutex
	state           transactionState
	subtransactions []*subtransaction
