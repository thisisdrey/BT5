### Title
`TokenDiff` fee for Nep245/Imt tokens can be bypassed by splitting a transfer into multiple unit (`|delta|==1`) intents - ([File: contracts/defuse/core/src/intents/token_diff.rs])

### Finding Description
The binding that should hold is: `fee_charged_for_moving_N_units(T) == Pips::fee_ceil(N)` regardless of how the N units are split across intents in a single `execute_intents` batch. The code breaks this binding because `TokenDiff::token_fee` is evaluated strictly per-intent, using only the `amount` (i.e. `|delta|`) present in that single `TokenDiff`'s diff map for that token: [1](#0-0) 

and the fee is computed inside `TokenDiff::execute_intent`, per `(token_id, delta)` entry of `self.diff`, with no visibility into any other intent in the batch: [2](#0-1) 

For `TokenIdType::Nep245`/`Imt`, `token_fee` returns `Pips::ZERO` whenever `amount <= 1`, and returns the protocol `fee` only when `amount > 1`. A single `TokenDiff` with `delta = -N` (`N>1`) on a Nep245 token has `amount = N > 1`, so it pays `fee_ceil(N)`. But if the same net transfer of `N` units is expressed as `N` separate `TokenDiff` intents (each `delta = -1`), each independently calls `token_fee(id, 1, fee)`, which always evaluates `amount == 1` and returns `Pips::ZERO`. `execute_intents` loops over the signed payloads/intents and calls `execute_intent` independently for each; there is no batch-level aggregation of deltas per token across intents before the fee is computed, so the fee logic that is a "per-atomic-intent, amount<=1 exempt" heuristic is trivially defeated by chunking.

Attacker payload: sign `N` `TokenDiff` intents (in one or several `MultiPayload`s, using either fresh nonces or one payload with `N` diff intents on the same token) each with `diff = {mt_token_id: -1, other_token_id: +x_i}`, matched against a counterparty or arranged so the net signer balance change equals what a single `delta=-N` intent would have produced. Submit them all in one `execute_intents(Vec<MultiPayload>)` call. Each `TokenDiff::execute_intent` call sees `amount==1` and contributes `0` to `fees_collected`, so `fee_collector` receives nothing, whereas the equivalent single intent would have paid `fee_ceil(N)`.

No existing guard (`MultiPayload::verify`, nonce checks, `Lock`, `TransferMatcher::finalize`, `checked_*` arithmetic) intervenes here — the divergence is purely in `token_fee`'s decision being made independently per intent with no batch-wide accounting.

### Impact Explanation
This under-collects protocol fees owed to `fee_collector` for Nep245/Imt token transfers/trades, letting an unprivileged signer move an arbitrary multiple of MT/NFT-collection units at zero protocol fee simply by splitting the transfer into unit-sized `TokenDiff` intents, whereas the equivalent single intent would be charged `fee_ceil(N)`. This is repeatable for any account, any Nep245/Imt token, and any batch size `N`, and matches the explicitly listed Critical category "protocol fees bypassed or over-collected."

### Likelihood Explanation
The only precondition is holding `N` unit balances (or an arranged counter-flow) of a Nep245/Imt token and the ability to sign `N` `TokenDiff` intents — both trivially available to any unprivileged signer. The attacker cost is only the marginal on-chain execution cost of a larger `Vec<MultiPayload>`/intents batch (which is explicitly out of scope to reject as "DoS/gas"), not any privileged capability. This is fully feasible and repeatable.

### Recommendation
Compute `token_fee` based on the aggregated net delta per `(signer, token_id)` across the entire batch of intents processed within a single `execute_intents` call (or eliminate the `amount > 1` unit-exemption threshold entirely and rely purely on `fee_ceil` rounding), rather than evaluating the threshold independently per `TokenDiff` intent.

### Proof of Concept
`cargo test` in `contracts/defuse` (or `tests/src/tests/defuse/intents/token_diff.rs`) sandbox test:
1. Scenario A: signer submits one `MultiPayload` containing a single `TokenDiff` intent with `diff = {nep245_token: -N, ft_token: +M}` (N>1), executed via `execute_intents`. Assert `fee_collector`'s mt balance for `nep245_token` increases by `Pips::fee_ceil(N)` (nonzero for `fee>0`).
2. Scenario B: same signer, same net starting/ending balances, but submit `N` separately-signed `MultiPayload`s (or `N` `TokenDiff` intents in one payload), each `diff = {nep245_token: -1, ft_token: +(M/N)}`, in one `execute_intents(vec![...])` call. Assert `fee_collector`'s mt balance for `nep245_token` remains unchanged (`0` fee collected) despite the signer's net balance change being identical to Scenario A.
3. Assert the two `fee_collector` balances differ, proving the fee is bypassed by chunking the same net transfer across multiple intents/payloads in a single batch.
