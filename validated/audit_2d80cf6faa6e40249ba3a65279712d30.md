The reported Sui bug class — a rate change applied retroactively to a time period that should have used the *old* rate — has a direct analog in marginfi-v2's bank interest-rate configuration flow.

## Title
Interest-rate/fee config changes are applied retroactively to unaccrued interest, misappropriating value between borrowers, lenders, and fee recipients - (File: `programs/marginfi/src/state/bank.rs`)

### Summary
`Bank::configure` and `lending_pool_configure_bank_interest_only` mutate `self.config.interest_rate_config` in place without first calling `accrue_interest()` to settle interest owed under the *old* rate for the time elapsed since `last_update`. The next time `accrue_interest` runs (which can be triggered permissionlessly, or automatically by any deposit/withdraw/borrow/repay/liquidate), it computes `time_delta = current_timestamp - self.last_update` and applies the brand-new interest-rate config over the *entire* delta — including the portion of time that occurred before the config change took effect.

### Finding Description
`accrue_interest` in [1](#0-0)  computes the elapsed time since the bank's `last_update` and then builds the interest-rate calculator strictly from the bank's *current* config: [2](#0-1) 

There is no snapshot of the config that was in effect at `last_update`, and no partial accrual is performed when the config changes mid-period. Both admin config paths update the interest rate config directly without accruing first:

- `Bank::configure` (used by `lending_pool_configure_bank`): [3](#0-2) 
- `lending_pool_configure_bank_interest_only` (delegate_curve_admin path): [4](#0-3) 

Neither instruction calls `bank.accrue_interest(...)` before overwriting `self.config.interest_rate_config`. Contrast this with `lending_pool_emissions_deposit`, which correctly calls `accrue_interest` before mutating any bank economics: [5](#0-4) 

Because `accrue_interest` is triggered permissionlessly (directly via `lending_pool_accrue_bank_interest`, and implicitly on every deposit/withdraw/borrow/repay/liquidate), any subsequent unprivileged interaction with the bank after a rate change will apply the *new* rate retroactively to the entire unaccrued window, not just the portion of time after the change — the exact same bug class as the reported Sui `advance_epoch` commission issue (new rate used instead of old rate for a period during which the old rate should have applied).

### Impact Explanation
Interest accrual directly drives `asset_share_value`/`liability_share_value` and the fee accumulators (`collected_group_fees_outstanding`, `collected_insurance_fees_outstanding`, `collected_program_fees_outstanding`) for the whole pool: [6](#0-5) . Misapplying the new rate to a stale time window:
- Overcharges or undercharges every borrower in the bank for interest that should have accrued under the old curve/fee parameters — an unauthorized state change to lender/borrower share values.
- Miscollects insurance/group/protocol fees for that stretch of time, which can starve the insurance fund (weakening bad-debt backstop capacity) or over/under-pay the group, all through the core accounting path.
- Because triggering the recalculation is permissionless, any user can "lock in" the mispriced accrual simply by depositing/borrowing/withdrawing/repaying right after an admin changes rates — no special privilege is needed to realize the effect on their own or others' balances.

### Likelihood Explanation
Interest-rate/fee configuration changes are a normal, expected operational action (the guide documents delegate curve admins routinely adjusting curve/fee parameters), and any bank with outstanding elapsed time since its last accrual (which is virtually always, since accrual only happens on interaction) will hit this path the next time anyone touches the bank. No attacker collusion with the admin is required — the miscalculation happens automatically as a consequence of the existing incorrect ordering of operations, matching the "cc4aaaa" root cause pattern of using the new rate for a period that should still use the old rate.

### Recommendation
Before mutating `self.config.interest_rate_config` (in both `Bank::configure` and `lending_pool_configure_bank_interest_only`), call `bank.accrue_interest(current_timestamp, group, ...)` to settle all interest and fees under the *old* config first, updating `last_update`. Only then apply the new interest-rate config, so that the new rate only ever applies to time elapsed after the change.

### Proof of Concept
1. Bank has `last_update = T0`. No interaction occurs for a long interval.
2. At `T1` (e.g., 30 days later), `delegate_curve_admin` calls `lending_pool_configure_bank_interest_only` to raise `protocol_ir_fee`/`hundred_util_rate` (or any admin calls `lending_pool_configure_bank` to change `interest_rate_config`). This updates config directly per [7](#0-6)  without accruing interest — `last_update` remains `T0`.
3. Any user (permissionlessly) calls `lending_pool_accrue_bank_interest` (or triggers accrual via deposit/borrow/etc.) at `T1`.
4. `accrue_interest` computes `time_delta = T1 - T0` (the full 30-day window) and calculates state changes using the **new** config from step 2, per [8](#0-7) , applying the new rate/fees over the entire 30-day period instead of only from `T1` onward.
5. Resulting `asset_share_value`/`liability_share_value` and fee accumulators reflect the wrong rate for 30 days worth of interest that should have used the pre-change config — an incorrect, unauthorized re-pricing of every depositor/borrower position and fee split in the bank.

```rust
    fn accrue_interest(
        &mut self,
        current_timestamp: i64,
        group: &MarginfiGroup,
        #[cfg(not(feature = "client"))] bank: Pubkey,
    ) -> MarginfiResult<()> {
        #[cfg(all(not(feature = "client"), feature = "debug"))]
        sol_log_compute_units();

        let time_delta: u64 = (current_timestamp - self.last_update).try_into().unwrap();
        if time_delta == 0 {
            return Ok(());
        }

        let total_assets = self.get_asset_amount(self.total_asset_shares.into())?;
        let total_liabilities = self.get_liability_amount(self.total_liability_shares.into())?;

        self.last_update = current_timestamp;

        if (total_assets == I80F48::ZERO) || (total_liabilities == I80F48::ZERO) {
            #[cfg(not(feature = "client"))]
            emit!(LendingPoolBankAccrueInterestEvent {
                header: GroupEventHeader {
                    marginfi_group: self.group,
                    signer: None
                },
                bank,
                mint: self.mint,
                delta: time_delta,
                fees_collected: 0.,
                insurance_collected: 0.,
            });

            return Ok(());
        }
        let ir_calc = self
            .config
            .interest_rate_config
            .create_interest_rate_calculator(group);

        let InterestRateStateChanges {
            new_asset_share_value: asset_share_value,
            new_liability_share_value: liability_share_value,
            insurance_fees_collected,
            group_fees_collected,
            protocol_fees_collected,
        } = calc_interest_rate_accrual_state_changes(
            time_delta,
            total_assets,
            total_liabilities,
            &ir_calc,
            self.asset_share_value.into(),
            self.liability_share_value.into(),
        )?;
```

```rust
pub fn lending_pool_configure_bank_interest_only(
    ctx: Context<LendingPoolConfigureBankInterestOnly>,
    interest_rate_config: InterestRateConfigOpt,
) -> MarginfiResult {
    let mut bank = ctx.accounts.bank.load_mut()?;
    msg!(
        "Configuring bank: {:?} mint: {:?}",
        ctx.accounts.bank.key(),
        bank.mint
    );

    // If settings are frozen, interest rates can't update.
    if bank.get_flag(FREEZE_SETTINGS) {
        msg!("WARN: Bank settings frozen, did nothing.");
    } else {
        bank.config
            .interest_rate_config
            .update(&interest_rate_config);
        bank.config.interest_rate_config.validate()?;
        msg!("Bank configured!");
    }

    Ok(())
}
```
