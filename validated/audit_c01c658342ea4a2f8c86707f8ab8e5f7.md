### Title
DoS in `vesting::distribute()` via Single Shareholder Deposit Failure Blocking All Shareholders — (`aptos-move/framework/aptos-framework/sources/vesting.move`)

---

### Summary

The `vesting::distribute()` function iterates over every shareholder in a vesting contract and calls `aptos_account::deposit_coins` for each one inside a single atomic loop. If any one deposit aborts, the entire transaction reverts. Because the shareholder list is fixed at contract creation and cannot be skipped, a single shareholder whose account is configured to reject direct coin transfers can permanently block all other shareholders from ever receiving their vested APT. The same structural flaw propagates into `distribute_many()`, `vest_many()`, and `unlock_rewards_many()`.

---

### Finding Description

`vesting::distribute()` withdraws all unlocked stake from the staking pool into a local `Coin<AptosCoin>` value and then distributes it to every shareholder in a `for_each_ref` loop:

```move
// File: aptos-move/framework/aptos-framework/sources/vesting.move, lines 730-740
let grant_pool = &vesting_contract.grant_pool;
let shareholders = &grant_pool.shareholders();
shareholders.for_each_ref(|shareholder| {
    let shareholder = *shareholder;
    let shares = pool_u64::shares(grant_pool, shareholder);
    let amount = pool_u64::shares_to_amount_with_total_coins(grant_pool, shares, total_distribution_amount);
    let share_of_coins = coin::extract(&mut coins, amount);
    let recipient_address = get_beneficiary(vesting_contract, shareholder);
    aptos_account::deposit_coins(recipient_address, share_of_coins);
});
```

`aptos_account::deposit_coins` contains the following guard:

```move
// File: aptos-move/framework/aptos-framework/sources/aptos_account.move, lines 123-127
if (!coin::is_account_registered<CoinType>(to)) {
    assert!(
        can_receive_direct_coin_transfers(to),
        error::permission_denied(EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS)
    );
    coin::register<CoinType>(&create_signer(to));
};
```

If a recipient account **exists** (so the auto-create path is skipped) but is **not registered for `AptosCoin`**, and the account has called `set_allow_direct_coin_transfers(false)` (setting `DirectTransferConfig.allow_arbitrary_coin_transfers = false`), then `can_receive_direct_coin_transfers` returns `false` and the call aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS`. Because Move transactions are atomic, the entire `distribute()` call reverts — including the coins already extracted from the pool for earlier shareholders.

Accounts created via `account::create_account` (the lower-level primitive, not `aptos_account::create_account`) are **not** automatically registered for `AptosCoin`. A shareholder whose address was created this way can call `set_allow_direct_coin_transfers(false)` at any time after being enrolled in the vesting contract, permanently wedging `distribute()` for every other shareholder.

The same root cause affects the batch wrappers:

```move
// File: aptos-move/framework/aptos-framework/sources/vesting.move, lines 759-768
public entry fun distribute_many(contract_addresses: vector<address>) acquires VestingContract {
    ...
    contract_addresses.for_each_ref(|contract_address| {
        let contract_address = *contract_address;
        distribute(contract_address);   // one abort kills the whole batch
    });
}
```

And `vest_many` / `unlock_rewards_many` have the identical pattern:

```move
// lines 707-716 (vest_many) and 643-652 (unlock_rewards_many)
contract_addresses.for_each_ref(|contract_address| {
    vest(*contract_address);          // or unlock_rewards(...)
});
```

Additionally, `terminate_vesting_contract` calls `distribute()` internally before unlocking remaining stake, so a wedged `distribute()` also permanently blocks contract termination and the admin's ability to recover funds via `admin_withdraw`.

---

### Impact Explanation

- **Permanent DoS of `distribute()`**: All shareholders in the affected vesting contract are unable to receive any vested APT or staking rewards for as long as the blocking condition persists. The coins remain locked in the staking pool.
- **Blocked termination**: `terminate_vesting_contract` calls `distribute()` first; if `distribute()` reverts, the admin cannot terminate the contract or call `admin_withdraw` to recover funds.
- **Cascading effect in `distribute_many()`**: A single blocked contract in a batch call causes all other contracts in the same batch to also fail to distribute.
- **Funds are not stolen but are permanently inaccessible** to all shareholders until the blocking account registers for APT or re-enables direct transfers — an action only the blocking account holder can take.

---

### Likelihood Explanation

The trigger requires a shareholder whose account was created via `account::create_account` (not `aptos_account::create_account`) and who subsequently calls `set_allow_direct_coin_transfers(false)`. Both are unprivileged, on-chain actions. The vesting contract's `create_vesting_contract` does not validate that shareholders are registered for APT. The attack is deliberate (griefing) rather than accidental, but it is reachable from a normal user transaction with no special permissions.

---

### Recommendation

1. **Isolate per-shareholder failures**: Wrap each `deposit_coins` call in a pattern that records failed distributions for later individual redemption rather than aborting the entire loop.
2. **Validate at enrollment**: In `create_vesting_contract`, assert that every shareholder address is registered for `AptosCoin` (or use `aptos_account::assert_account_is_registered_for_apt`).
3. **Pull-over-push for distributions**: Instead of pushing coins to all shareholders in one transaction, allow each shareholder to individually claim their share, eliminating the all-or-nothing atomicity risk.

---

### Proof of Concept

1. **Setup**: Admin creates a vesting contract with two shareholders: `alice` (normal account, registered for APT) and `bob` (account created via `account::create_account`, **not** registered for APT).

2. **Attack**: `bob` calls `set_allow_direct_coin_transfers(false)` on his account. This sets `DirectTransferConfig { allow_arbitrary_coin_transfers: false }` for `bob`'s address.

3. **Trigger**: Anyone calls `vesting::distribute(contract_address)` after the lockup expires and coins are withdrawable.

4. **Execution path**:
   - `withdraw_stake` succeeds; coins are extracted from the staking pool.
   - The loop reaches `bob`'s entry: `aptos_account::deposit_coins(bob, share_of_coins)`.
   - `coin::is_account_registered<AptosCoin>(bob)` → `false`.
   - `can_receive_direct_coin_transfers(bob)` → `false` (because `allow_arbitrary_coin_transfers = false`).
   - `assert!` fires → abort with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS`.
   - Entire transaction reverts; `alice` receives nothing.

5. **Persistence**: Every subsequent call to `distribute(contract_address)` follows the same path and aborts. `terminate_vesting_contract` also aborts because it calls `distribute` internally. All shareholders' vested APT remains locked indefinitely.

    public entry fun terminate_vesting_contract(admin: &signer, contract_address: address) acquires VestingContract {
        assert_active_vesting_contract(contract_address);

        // Distribute all withdrawable coins, which should have been from previous rewards withdrawal or vest.
        distribute(contract_address);

        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        verify_admin(admin, vesting_contract);
        let (active_stake, _, pending_active_stake, _) = stake::get_stake(vesting_contract.staking.pool_address);
        assert!(pending_active_stake == 0, error::invalid_state(EPENDING_STAKE_FOUND));

        // Unlock all remaining active stake.
        vesting_contract.state = VESTING_POOL_TERMINATED;
        vesting_contract.remaining_grant = 0;
        unlock_stake(vesting_contract, active_stake);

        emit(
            Terminate {
                admin: vesting_contract.admin,
                vesting_contract_address: contract_address,
            },
        );
    }
