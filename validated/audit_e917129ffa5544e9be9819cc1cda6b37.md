### Title
Object Pool Creation DOS via Predictable Deterministic Pool Path Pre-Creation - (File: internal/git/objectpool/create.go)

### Summary
`objectpool.Create` and `repoutil.Create` both use an existence-check-then-create pattern: they `os.Stat` the target path and error out with `AlreadyExists`/`FailedPrecondition` if anything is already present there, rather than atomically claiming the path. This mirrors the Solana Phoenix "Account Creation DOS" bug class, where a primitive fails permanently if the target location is already occupied before the legitimate owner acts. [3](#0-2) [4](#0-3) 

### Finding Description
Praefect derives object pool disk paths deterministically from a purely numeric, sequentially-assigned repository ID: `DerivePoolPath(id) = @cluster/pools/<sha256(id)[0:1]>/<sha256(id)[1:2]>/<id>`. [1](#0-0) 

Because repository IDs are sequential/predictable, an ordinary authenticated user who can call `CreateRepository`/`CreateFork` (both of which take an arbitrary, caller-supplied `RelativePath` guarded only by generic path-traversal/format checks, not by ownership of the derived pool path) can pre-create a directory at the exact future `@cluster/pools/.../<future-id>` path for a repository ID that has not been allocated yet, or occupy the path with any other Rails/GitLab-side actor that shares access to the same virtual storage. When GitLab/Rails later triggers `CreateObjectPool` for the fork network that legitimately needs that ID, `objectpool.Create` performs only a pre-existence `os.Stat` check and immediately returns `FailedPrecondition("target path exists already")` — it never attempts to reclaim, validate ownership of, or clean up the pre-existing directory. [3](#0-2) [5](#0-4) 

This is structurally identical to the reported bug class: a primitive that should atomically claim a resource instead unconditionally fails when something already occupies the target, and the target's identity (address/path) is predictable/derivable in advance by an unprivileged party, enabling front-running/blocking of legitimate creation.

### Impact Explanation
If exploitable, this permanently prevents the fork network for that specific future repository ID from ever getting deduplicated storage via an object pool, since `CreateObjectPool` will fail with `FailedPrecondition` indefinitely (there is no automatic reclamation of paths pre-occupied by unrelated content) — increasing storage costs and reducing efficiency of forks for the victim project. It is a denial-of-service of a specific mutating RPC handler for a targeted target repository, not RCE or data corruption of already-existing repos.

### Likelihood Explanation
Exploitability hinges on two conditions I could **not fully verify** with the available code index:
1. Whether an ordinary Gitaly RPC caller (unprivileged, non-Rails-internal actor) can actually specify an arbitrary `@cluster/pools/...` relative path in a `CreateRepository`/`CreateFork`/`CreateObjectPool` request and have it accepted, given `errInvalidPoolDir` validation in `internal/gitaly/service/objectpool/create.go` enforces subdirectory-hash-prefix matching for Rails-style pool paths, but I did not find equivalent validation blocking arbitrary Praefect-style `@cluster/pools/<id>` paths from being pre-created via `CreateRepository` (which does not require `IsPoolRepository`).
2. Whether repository IDs are predictable enough in practice (sequential counters) for an attacker to reliably pre-guess a specific victim's future ID before the real `CreateObjectPool` call races it.

Given Gitaly's threat model treats Rails/authenticated GitLab users, not fully untrusted external parties, as the primary caller of repository-management RPCs, likelihood is **low-to-moderate** and requires further confirmation via a live Devin session with full repo/test access.

### Recommendation
- Before returning `FailedPrecondition`/`AlreadyExists` in `objectpool.Create`/`repoutil.Create`, validate that any pre-existing content at the target path is actually a valid, unrelated Git repository (not just "is there anything at all") and consider whether it's safe to reclaim empty/orphaned directories.
- Ensure that arbitrary user-controlled `CreateRepository`/`CreateFork` requests cannot target `@cluster/pools/...` or other reserved deterministic-path namespaces at all — add a positive check rejecting attempts to create ordinary repositories under path prefixes reserved for internally-derived IDs (mirrors the existing `errInvalidPoolDir` validation, but applied to reserved namespace collision rather than just naming convention).
- Consider adopting the "transfer/allocate" pattern from the remediation model: separate the "reserve the ID/slot" step (atomic, e.g. via the Praefect repository-ID sequence/DB) from the "create content at path" step, so pre-occupied paths can be detected and cleaned up by the legitimate owner of that reserved ID rather than failing permanently.

### Proof of Concept
Not independently reproduced — this analog requires exercising the actual gRPC surface with a live Praefect+Gitaly cluster (specifically confirming (a) that `CreateRepository`/`CreateFork` accept and act on an arbitrary caller-supplied `@cluster/pools/<future-id>` relative path without rejecting it as reserved, and (b) that a subsequent legitimate `CreateObjectPool` call for that repository ID is permanently blocked by the `os.Stat` pre-check in `internal/git/objectpool/create.go:42-48`). This should be validated in a Devin session with full test-harness access before treating it as confirmed.

// DerivePoolPath derives an object pools's disk storage path from its repository ID. The repository ID
// is hashed with SHA256 and the first four hex digits of the hash are used as the two subdirectories to
// ensure even distribution into subdirectories. The format is @cluster/pools/ab/cd/<repository-id>. The pools
// have a different directory prefix from other repositories so Gitaly can identify them in OptimizeRepository
// and avoid pruning them.
func DerivePoolPath(repositoryID int64) string {
	return deriveDiskPath(praefectPoolPathPrefix, repositoryID)
}

func deriveDiskPath(prefixDir string, repositoryID int64) string {
	hasher := sha256.New()
	// String representation of the ID is used to make it easier to derive the replica paths with
	// external tools. The error is ignored as the hash.Hash interface is documented to never return
	// an error.
	hasher.Write([]byte(strconv.FormatInt(repositoryID, 10)))
	hash := hasher.Sum(nil)
	return filepath.Join(prefixDir, fmt.Sprintf("%x/%x/%d", hash[0:1], hash[1:2], repositoryID))
```

func (s *server) CreateObjectPool(ctx context.Context, in *gitalypb.CreateObjectPoolRequest) (*gitalypb.CreateObjectPoolResponse, error) {
	if in.GetOrigin() == nil {
		return nil, errMissingOriginRepository
	}

	poolRepo := in.GetObjectPool().GetRepository()
	if poolRepo == nil {
		return nil, errMissingPool
	}

	if !storage.IsPoolRepository(poolRepo) {
		return nil, errInvalidPoolDir
	}

	// repoutil.Create creates the repositories in a temporary directory. This means the repository is not created in the location
	// expected by the transaction manager. This makes sense without transactions, but with transactions, there's no real point in
	// doing so given a failed transaction's state is anyway removed. Creating the repository in a temporary directory is problematic
	// as the reference transaction hook is invoked for the repository from unexpected location, causing the transaction to fail to
	// associate the reference updates with the repository.
	//
	// Run the repository creation without the transaction in the context. The transactions reads the created repository's state from
	// the disk when committing it, so it's not necessary to capture the updates from the reference-transaction hook. This avoids the
	// problem for now, and later with transactions enabled by default we can stop creating repositories in unexpected locations.
	ctxWithoutTransaction := storage.ContextWithTransactionID(ctx, 0)
	if err := repoutil.Create(ctxWithoutTransaction, s.logger, s.locator, s.gitCmdFactory, s.catfileCache, s.txManager, s.repositoryCounter, poolRepo, func(poolRepo *gitalypb.Repository) error {
		if _, err := objectpool.Create(
			ctxWithoutTransaction,
			s.logger,
			s.locator,
			s.gitCmdFactory,
			s.catfileCache,
			s.txManager,
			s.housekeepingManager,
			&gitalypb.ObjectPool{
				Repository: poolRepo,
			},
			s.localRepoFactory.Build(in.GetOrigin()),
		); err != nil {
			return err
		}

		return nil
	}, repoutil.WithSkipInit()); err != nil {
		return nil, structerr.New("creating object pool: %w", err)
	}
```
