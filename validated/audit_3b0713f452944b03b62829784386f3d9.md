## Title
QUIC connections retain stale stake-derived QoS privileges after a node is unstaked, allowing removed/reduced-stake peers to keep evading throttling - ([File: streamer/src/nonblocking/swqos.rs])

### Summary
This is a valid analog to the reported bug class: an entity's privileged state ("verified"/"staked") is captured once and never re-checked against the live authoritative source, so once the entity is removed from that privileged set, it keeps benefiting from the stale, more favorable treatment for the remainder of its lifetime (a long-lived QUIC connection instead of a "removed artist" stake position).

### Finding Description
`SwQos::build_connection_context()` derives a peer's `ConnectionPeerType` (`Staked(stake)`/`Unstaked`) and `total_stake` a single time, from a snapshot of `staked_nodes` taken via `get_connection_stake()` when the connection is accepted: [1](#0-0) [2](#0-1) 

This one-time-derived `SwQosConnectionContext` (containing `peer_type` and `total_stake`) is stored for the entire lifetime of the QUIC connection and reused on every subsequent operation:
- `cache_new_connection()` uses `conn_context.peer_type()`/`conn_context.total_stake` to compute `max_uni_streams` via `compute_max_allowed_uni_streams_with_rtt()`, and to select `max_connections_per_staked_peer` vs `max_connections_per_unstaked_peer`. [3](#0-2) 
- `max_streams_per_throttling_interval()` / `available_load_capacity_in_throttling_duration()` recompute the per-stream throttling budget on every stream using the same stale `conn_context.peer_type` and `conn_context.total_stake` captured at connect time. [4](#0-3) [5](#0-4) 
- `on_stream_accepted()` still increments the staked EMA load counter using the captured `peer_type`, further preserving its "staked" classification for load-sharing purposes. [6](#0-5) 

Meanwhile, the authoritative `staked_nodes` table is refreshed independently and periodically by `StakedNodesUpdaterService`, every `STAKE_REFRESH_CYCLE` (5 seconds), pulling from the root bank's current epoch stakes: [7](#0-6) 

Because `get_connection_stake()`/`build_connection_context()` is only invoked once, at connection accept time, and the resulting `peer_type`/`total_stake` are never re-derived from the live `staked_nodes` map for the life of the connection, a node that becomes fully unstaked, has its stake reduced, or is otherwise removed from the current stake set continues to be treated as `ConnectionPeerType::Staked(old_stake)` for as long as it can keep its QUIC connection alive (subject only to QUIC idle timeouts/connection limits, not stake re-validation). This mirrors the reported bug class precisely: the "verified" (privileged) status is checked only at entry, and removal from that privileged set is never propagated to already-granted state, so the removed entity keeps accruing the associated benefit.

### Impact Explanation
A peer that loses its stake (fully unstaked, or has stake moved/redelegated) can retain, for the duration of an already-open QUIC connection:
- Elevated `max_concurrent_uni_streams` (computed once from the stale stake value via `compute_max_allowed_uni_streams_with_rtt`),
- A higher `max_connections_per_staked_peer` limit rather than the tighter unstaked limit,
- A higher per-100ms stream throttling budget from `available_load_capacity_in_throttling_duration`, computed using the stale `stake`/`total_stake` ratio, and
- Continued classification as "staked" load for EMA/staked-throttling purposes, competing unfairly against currently legitimately-staked peers for the shared staked bandwidth budget.

This is a QoS evasion: a since-removed/low-stake peer keeps consuming a disproportionate share of the validator's ingest capacity that should be reserved for genuinely staked peers, degrading fairness of transaction ingestion (analogous to the removed artist continuing to accrue inflated rewards it is no longer entitled to).

### Likelihood Explanation
The condition requires only that a peer maintain a long-lived QUIC connection (which QUIC/quinn naturally supports via idle timeouts and keep-alives) across a stake change that is picked up by `StakedNodesUpdaterService`'s 5-second refresh cycle, or across an epoch boundary where the peer's stake goes to zero. This can happen incidentally during normal validator/stake-account operation (undelegating, deactivating stake) without any attacker action, and can be trivially prolonged by an adversarial peer keeping its connection open as long as possible after voluntarily/knowingly reducing its stake. No special privileges are needed to establish or hold the connection.

### Recommendation
Periodically re-derive `peer_type`/`total_stake` for open connections against the current `staked_nodes` snapshot (e.g., on each new stream, or via a background sweep of `ConnectionTable` entries), rather than caching it once in `SwQosConnectionContext` for the connection's entire lifetime. At minimum, `max_streams_per_throttling_interval()`/`increment_load()` should re-fetch current stake for the peer's pubkey rather than reuse the value captured at `build_connection_context()` time, and connections belonging to now-unstaked pubkeys should be demoted/evicted similarly to how `SimpleQosBanlist`/pruning logic handles other removals.

### Proof of Concept
1. Node `N` connects to the TPU QUIC endpoint while it holds stake `S`; `SwQos::build_connection_context()` records `ConnectionPeerType::Staked(S)` and `total_stake` in `SwQosConnectionContext`, cached in the `ConnectionEntry`/`ConnectionTable`.
2. `N`'s stake is deactivated/undelegated to 0 (or greatly reduced) in a subsequent epoch. `StakedNodesUpdaterService` updates the shared `staked_nodes` map accordingly after up to 5 seconds.
3. `N` keeps its already-established QUIC connection alive (via keep-alives) rather than reconnecting.
4. For every new stream on that connection, `throttle_stream()` is gated by `max_streams_per_throttling_interval()` → `available_load_capacity_in_throttling_duration(conn_context.peer_type, conn_context.total_stake)`, which still uses the original, stale `Staked(S)`/`total_stake` values from step 1, since `conn_context` is never refreshed from `staked_nodes`.
5. `N` therefore keeps receiving a staked-tier stream budget, staked connection-count limits, and staked-tier stream caps indefinitely, despite no longer holding stake, as long as the connection is not dropped.

impl QosController<SwQosConnectionContext> for SwQos {
    fn build_connection_context(&self, connection: &Connection) -> SwQosConnectionContext {
        let remote_address = connection.remote_address();
        get_connection_stake(connection, &self.staked_nodes).map_or(
            SwQosConnectionContext {
                peer_type: ConnectionPeerType::Unstaked,
                total_stake: 0,
                remote_pubkey: None,
                in_staked_table: false,
                remote_address,
                stream_counter: None,
                last_update: Arc::new(AtomicU64::new(timing::timestamp())),
            },
            |(pubkey, stake, total_stake)| {
                // The heuristic is that the stake should be large enough to have 1 stream pass through within one throttle
                // interval during which we allow max (MAX_STREAMS_PER_MS * STREAM_THROTTLING_INTERVAL_MS) streams.

                let peer_type = {
                    let max_streams_per_ms = self.staked_stream_load_ema.max_streams_per_ms();
                    let min_stake_ratio =
                        1_f64 / (max_streams_per_ms * STREAM_THROTTLING_INTERVAL_MS) as f64;
                    let stake_ratio = stake as f64 / total_stake as f64;
                    if stake_ratio < min_stake_ratio {
                        // If it is a staked connection with ultra low stake ratio, treat it as unstaked.
                        ConnectionPeerType::Unstaked
                    } else {
                        ConnectionPeerType::Staked(stake)
                    }
                };

                SwQosConnectionContext {
                    peer_type,
                    total_stake,
                    remote_pubkey: Some(pubkey),
                    in_staked_table: false,
                    remote_address,
                    last_update: Arc::new(AtomicU64::new(timing::timestamp())),
                    stream_counter: None,
                }
            },
        )
    }

    pub(crate) fn available_load_capacity_in_throttling_duration(
        &self,
        peer_type: ConnectionPeerType,
        total_stake: u64,
    ) -> u64 {
        match peer_type {
            ConnectionPeerType::Unstaked => self.max_unstaked_load_in_throttling_window,
            ConnectionPeerType::Staked(stake) => {
                if self.staked_throttling_enabled.load(Ordering::Relaxed) {
                    // 1 is added to `max_unstaked_load_in_throttling_window` to guarantee that staked
                    // clients get at least 1 more number of streams than unstaked connections.
                    self.max_staked_load_in_throttling_window
                        .saturating_mul(stake)
                        .checked_div(total_stake)
                        .unwrap_or(self.max_unstaked_load_in_throttling_window + 1)
                        .max(self.max_unstaked_load_in_throttling_window + 1)
                } else {
                    self.max_staked_load_in_throttling_window
                }
            }
        }
    }

const STAKE_REFRESH_CYCLE: Duration = Duration::from_secs(5);

pub struct StakedNodesUpdaterService {
    thread_hdl: JoinHandle<()>,
}

impl StakedNodesUpdaterService {
    pub fn new(
        exit: Arc<AtomicBool>,
        bank_forks: Arc<RwLock<BankForks>>,
        staked_nodes: Arc<RwLock<StakedNodes>>,
        staked_nodes_overrides: Arc<RwLock<HashMap<Pubkey, u64>>>,
    ) -> Self {
        let thread_hdl = Builder::new()
            .name("solStakedNodeUd".to_string())
            .spawn(move || {
                while !exit.load(Ordering::Relaxed) {
                    let stakes = {
                        let root_bank = bank_forks.read().unwrap().root_bank();
                        root_bank.current_epoch_staked_nodes()
                    };
                    let overrides = staked_nodes_overrides.read().unwrap().clone();
                    *staked_nodes.write().unwrap() = StakedNodes::new(stakes, overrides);
                    std::thread::sleep(STAKE_REFRESH_CYCLE);
                }
            })
            .unwrap();

        Self { thread_hdl }
    }
