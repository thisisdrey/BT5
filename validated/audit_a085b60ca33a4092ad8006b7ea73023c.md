Verified against the actual code: `SignerEventReceiver::next_event` in `libsigner/src/events.rs` handles the `/shutdown` URL match with no authentication whatsoever, and any POST body content is irrelevant.

### Title
Unauthenticated remote `/shutdown` POST permanently halts signer's event-processing loop - (File: libsigner/src/events.rs)

### Summary
The signer's bound HTTP event server dispatches on `request.url()` without any check of the request's source, credentials, or content. A POST to `/shutdown` unconditionally sets `stop_signal` and returns `EventError::Terminated`, which propagates to `EventReceiver::main_loop` and terminates it, so any remote client that can reach the bound event port can permanently kill the signer's event loop with one message.

### Finding Description
In `next_event`, the dispatch logic is: [1](#0-0) 
There is no verification of the request's origin, no secret/token check, and no distinction between the co-located node process and any other TCP client — the same code path is used both by the legitimate node (via `SignerStopSignaler::send`, which itself just opens a `TcpStream` to `local_addr` and POSTs `/shutdown` with a plaintext body) and by an arbitrary remote attacker. Once `event_receiver.stop_signal.store(true, Ordering::SeqCst)` runs and `EventError::Terminated` is returned, `EventReceiver::main_loop` matches `Err(EventError::Terminated)` and breaks out of its loop: [2](#0-1) 
The claimed equality `shutdown_authorized == request_authenticated` does not exist anywhere in the code — there is simply no authorization gate on this endpoint at all. The code comments/warnings in `stacks-signer/src/lib.rs` acknowledge this risk generally ("communicating with an external node... could potentially expose sensitive data or functionalities to security risks") but no enforcement is implemented. [3](#0-2) 

### Impact Explanation
Any TCP client able to reach the signer's bound event HTTP port (the address configured via `config.endpoint`, e.g. `Signer::spawn(bind_addr)`) can send a single unauthenticated `POST /shutdown` and permanently stop the signer's event-receiver thread. Once `next_event` returns `Terminated`, `main_loop` exits and no further node events (`/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block`) will ever be forwarded to the signer runloop, effectively disabling that signer's participation in block validation/signing until manually restarted. This matches "Critical – remote crash/unauthenticated DoS from few messages" (here, exactly one message).

### Likelihood Explanation
The attacker needs no credentials, no privileged role, and no prior state — only TCP reachability to the signer's event-listener port. Repeatability is trivial (a single crafted HTTP request). The main precondition is that the port is exposed beyond localhost/firewalled access, which depends on deployment configuration, but the code itself enforces no restriction, so any operator relying on network-level ACLs alone is exposed if that control is misconfigured or bypassed (e.g., a shared or containerized network where the listener is reachable from more than the local node process).

### Recommendation
Add authentication/authorization to the `/shutdown` (and ideally all) endpoints in `SignerEventReceiver::next_event` — e.g., a shared secret/token known only to the co-located node, mutual TLS, or a loopback-only bind combined with verifying the peer address of the underlying `TcpStream` equals `127.0.0.1`/configured trusted node address before honoring `/shutdown`.

### Proof of Concept
Rust test in `libsigner/src/tests/mod.rs` style (mirroring `test_status_endpoint`):
1. Spawn a `SignerEventReceiver`/`Signer` bound to `127.0.0.1:<port>` via `signer.spawn(endpoint)`.
2. From a separate thread simulating an unauthenticated remote attacker, open a raw `TcpStream::connect(endpoint)` and write `"POST /shutdown HTTP/1.1\r\nHost: ...\r\nConnection: close\r\nContent-Length: 0\r\n\r\n"` with no credentials/headers proving node identity.
3. Assert that shortly after, `event_receiver.is_stopped()` (or observing `running_signer.stop()`/`join()` returns promptly instead of hanging) confirms `stop_signal` was set and `main_loop` exited — i.e., the signer thread already terminated before any legitimate shutdown was issued by the actual node.
