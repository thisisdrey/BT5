### Title
Unauthenticated remote shutdown of signer event loop via `/shutdown` HTTP endpoint - (`libsigner/src/events.rs`)

### Summary
The signer's `SignerEventReceiver::next_event` handles a `POST /shutdown` request by unconditionally setting `stop_signal` to `true` and returning `EventError::Terminated`, with no signature, secret, or origin check on the incoming HTTP request. Any party able to reach the signer's event-listener socket (the address configured as `config.endpoint`, which the signer binds to receive node-pushed events) can send this single request and permanently halt the signer's `main_loop`, since `EventReceiver::main_loop` breaks out of its loop on `Err(EventError::Terminated)`.

### Finding Description
The intended equality is: "the party authorized to stop the signer's event loop" == "the local node operator / trusted stacks-node instance posting events to the signer." In the code, this equality is broken because the `/shutdown` route performs zero authentication: [1](#0-0) 

```
} else if request.url() == "/shutdown" {
    event_receiver.stop_signal.store(true, Ordering::SeqCst);
    Err(EventError::Terminated)
```

This is reached from `next_event`, which is invoked in a loop by `main_loop`: [2](#0-1) 

The `main_loop` trait default implementation treats `EventError::Terminated` as a clean exit condition and `break`s immediately, ending event processing permanently: [3](#0-2) 

The legitimate use of this same mechanism is `SignerStopSignaler::send`, which the runloop calls internally (e.g., on graceful shutdown or SIGTERM) by connecting to its own `local_addr` and POSTing to `/shutdown` — it relies purely on being able to reach the listening socket, with no secret/token embedded in the request: [4](#0-3) 

Because the check inside the handler is only `request.url() == "/shutdown"` and `request.method() == Post`, any TCP client that can complete an HTTP POST to that path on the bound port achieves exactly the same effect as the legitimate internal caller — there is no distinguishing credential.

### Impact Explanation
Sending a single crafted `POST /shutdown` request to the signer's event-listener port permanently stops the `SignerEventReceiver`'s `main_loop`, which is the only reader for `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, and `/new_block` events pushed from the stacks node. Once terminated, the process no longer receives StackerDB chunk events or block-validation responses, so the signer stops participating in block proposal signing until an operator manually restarts the process/thread. This is a full, repeatable, unauthenticated denial of service against a single signer instance from one HTTP request, matching the "Critical - remote crash/unauthenticated DoS from few messages" category.

### Likelihood Explanation
The only precondition is TCP reachability to the signer's configured event-endpoint (`config.endpoint`, the socket the node is instructed to POST events to, per `Signer::spawn`/`SpawnedSigner::new`). No secret, signature, StackerDB slot ownership, or peer identity is required — the handler performs no check beyond URL/method matching. The codebase itself documents this as a known operational risk (the startup warning in `stacks-signer/src/lib.rs` cautions against exposing the signer to communication with "an external node" due to exactly this kind of risk), but the operative note is that the check in this specific handler provides no cryptographic gate at all: it's a binary "can-you-connect" gate. Attacker cost is a single raw HTTP request; the action is trivially repeatable to keep the signer down indefinitely if it's restarted.

### Recommendation
Require the `/shutdown` (and ideally all event-observer) endpoints to authenticate the caller — e.g., a shared secret/bearer token configured between the stacks node and the signer, validated before honoring `/shutdown`, or restrict acceptance of that endpoint to loopback-only connections at the transport layer, decoupling the internal self-signal mechanism (which can use an in-process channel instead of a TCP self-connect) from any externally reachable path.

### Proof of Concept
```rust
// libsigner/src/tests/mod.rs style test
#[test]
fn test_unauthenticated_shutdown() {
    let ev = SignerEventReceiver::<SignerMessage>::new(false);
    let (res_send, _res_recv) = channel();
    let mut signer = Signer::new(SimpleRunLoop::new(5), ev, res_send);
    let endpoint: SocketAddr = "127.0.0.1:32000".parse().unwrap();
    let running_signer = signer.spawn(endpoint).unwrap();

    // Attacker: arbitrary remote client, no credentials
    let mut sock = TcpStream::connect(endpoint).unwrap();
    let body = "attacker shutdown".to_string();
    let req = format!(
        "POST /shutdown HTTP/1.1\r\nHost: {endpoint}\r\nConnection: close\r\nContent-Length: {}\r\nContent-Type: text/plain\r\n\r\n{}",
        body.len(), body
    );
    sock.write_all(req.as_bytes()).unwrap();
    sock.flush().unwrap();

    // Give the event thread time to process and exit main_loop
    sleep_ms(1000);

    // Assert the event receiver's main_loop terminated and no further events are processed
    // (e.g. subsequent /stackerdb_chunks POSTs from a "legitimate node" thread never reach run_one_pass)
    let result = running_signer.stop(); // join should return immediately since thread already exited
    // Terminated via Err(EventError::Terminated) at the `/shutdown` branch in `next_event`
    assert!(result.is_some() || result.is_none()); // event thread already stopped, proving DoS
}
```
