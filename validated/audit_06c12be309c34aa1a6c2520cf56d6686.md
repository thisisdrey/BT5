Audit Report

## Title
Unbounded slippage in `SwapFirstAssetTrader::refund_weight` lets an attacker sandwich XCM fee refunds and drain refunded value via the AssetConversion pool - (File: cumulus/primitives/utility/src/lib.rs)

## Summary
`SwapFirstAssetTrader::refund_weight` swaps the unused `Target`-asset fee credit back into the user's original payment asset via `SwapCredit::swap_exact_tokens_for_tokens(vec![Target::get(), refund_swap_asset], refund, None)`, passing `None` as `amount_out_min` and therefore accepting any nonzero output [1](#0-0) . This contrasts with `buy_weight`, which correctly requests an exact output amount via `swap_tokens_for_exact_tokens` [2](#0-1) , and with the analogous `correct_and_deposit_fee` refund path elsewhere in the codebase, which quotes a minimum via `quote_price_exact_tokens_for_tokens` and passes `Some(refund_asset_amount)` [3](#0-2) .

## Finding Description
`pallet_asset_conversion`'s swap implementation only enforces a minimum-output check when `amount_out_min` is `Some(_)`; when `None`, the `ProvidedMinimumNotSufficientForSwap` guard is skipped entirely [4](#0-3) . The pool being swapped against is the standard, permissionless `AssetConversion` pool, tradable by any account via the public `swap_exact_tokens_for_tokens`/`swap_tokens_for_exact_tokens` dispatchables [5](#0-4) . `SwapFirstAssetTrader` is wired into the live XCM `Trader` configuration of `asset-hub-rococo`, `asset-hub-westend`, `penpal`, and the staking-async parachain runtime, confirmed by direct references in each `xcm_config.rs` [6](#0-5) , so `refund_weight` executes on ordinary XCM traffic whenever weight fees are overestimated (a routine occurrence) and a refund in a non-`Target` asset is due.

## Impact Explanation
Because the swap-back accepts any output, an attacker who manipulates the pool's reserves immediately before the refund swap executes can force the refund conversion to yield far less than fair value, capturing the spread while the legitimate refund recipient receives a diminished (or negligible) amount. This is value non-conservation in a public AMM settlement path reachable by unprivileged actors — the corrupted value is the refunded amount of the user's original fee-payment asset credited back from `refund_weight`.

## Likelihood Explanation
Exploitation requires only ordinary, permissionless capabilities: observing a pending XCM message that will trigger a fee refund, and submitting swap transactions against the same public `AssetConversion` pool before and after the refund executes within the same or adjacent blocks. No validator, collator, governance, or relayer privilege is needed, and refunds from weight overestimation are common in practice, making this a realistically repeatable and low-cost attack for any external actor able to time transaction submission around observable XCM execution.

## Recommendation
In `refund_weight`, quote the expected output via `QuotePrice::quote_price_exact_tokens_for_tokens(Target::get(), refund_swap_asset, refund_amount, true)` and pass `Some(quoted_min)` (with a bounded tolerance) as `amount_out_min` to `swap_exact_tokens_for_tokens`, mirroring the existing pattern in `correct_and_deposit_fee`. On swap failure or insufficient quote, retain the credit in `total_fee` as already implemented in the error branch.

## Proof of Concept
1. Deploy a runtime using `SwapFirstAssetTrader` as XCM `Trader` with an `AssetConversion` pool between `Target` and a foreign/local asset (as in `asset-hub-rococo`/`asset-hub-westend`/`penpal`/staking-async parachain `xcm_config.rs`).
2. Attacker monitors for an incoming XCM message that overpays fees in the foreign asset (common due to conservative fee estimation).
3. Immediately before the message executes, attacker calls the public `swap_tokens_for_exact_tokens` dispatchable to skew the `Target`→foreign-asset exchange rate unfavorably.
4. The XCM message executes; `buy_weight` withdraws the exact fee; the unused portion triggers `refund_weight`, which calls `SwapCredit::swap_exact_tokens_for_tokens(vec![Target, foreign], refund, None)`, accepting the skewed, undervalued output [1](#0-0) .
5. Attacker reverses the initial swap, restoring the pool and pocketing the spread extracted from the undervalued refund.
