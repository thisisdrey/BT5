No vulnerability found for this question.

Analysis: The closest candidate in this codebase is `crypto/ecdsa`'s legacy signing path (`signLegacy` in [1](#0-0) ), which for non-standard curves calls `c.ScalarBaseMult(k.Bytes())` where `k` is the secret nonce, using the generic `CurveParams.ScalarMult`/`ScalarBaseMult` implementation in [2](#0-1) . That generic implementation is variable-time (branches on each bit of the secret scalar via `b&0x80`), which superficially resembles the CVE-2020-12401 pattern of losing constant-time nonce handling.

However, this does not qualify as an analog vulnerability because:
1. It is explicitly and prominently documented, not an accidental regression. The package doc states "Operations involving private keys are implemented using constant-time algorithms, as long as an `elliptic.Curve` returned by `elliptic.P224`, `elliptic.P256`, `elliptic.P384`, or `elliptic.P521` is used" [3](#0-2) , and `CurveParams` itself is documented as "a generic, non-constant time implementation" whose use with custom curves "is not guaranteed to provide any security property" [4](#0-3) .
2. The four standard/production curves (P224, P256, P384, P521) route through `matchesSpecificCurve` to constant-time nistec implementations instead [5](#0-4) , and the primary `SignASN1`/`Sign` entry points dispatch those curves to the FIPS constant-time path (`signFIPS` → `ecdsa.Sign` using `bigmod`-based nistec scalar arithmetic) [6](#0-5) .
3. CVE-2020-12401 was about an *accidental* removal of padding that had been added specifically to enforce constant-time behavior on a security-critical path — i.e., a regression in intended protection. Here there is no such regression: the non-constant-time behavior for custom curves is by design, clearly labeled deprecated, and not the path used by any standard/FIPS-approved curve. This is intended, documented behavior for a legacy/opt-in feature, not a hidden defect matching the CVE's root cause.

Given the strict rule to reject hypothetical application misuse and already-documented/expected behavior rather than stretch an analogy, no qualifying vulnerability was found.

// ScalarMult implements [Curve.ScalarMult].
//
// Deprecated: the [CurveParams] methods are deprecated and are not guaranteed to
// provide any security property. For ECDH, use the [crypto/ecdh] package.
// For ECDSA, use the [crypto/ecdsa] package with a [Curve] value returned directly
// from [P224], [P256], [P384], or [P521].
func (curve *CurveParams) ScalarMult(Bx, By *big.Int, k []byte) (*big.Int, *big.Int) {
	// If there is a dedicated constant-time implementation for this curve operation,
	// use that instead of the generic one.
	if specific, ok := matchesSpecificCurve(curve); ok {
		return specific.ScalarMult(Bx, By, k)
	}
	panicIfNotOnCurve(curve, Bx, By)

	Bz := new(big.Int).SetInt64(1)
	x, y, z := new(big.Int), new(big.Int), new(big.Int)

	for _, b := range k {
		for range 8 {
			x, y, z = curve.doubleJacobian(x, y, z)
			if b&0x80 == 0x80 {
				x, y, z = curve.addJacobian(Bx, By, Bz, x, y, z)
			}
			b <<= 1
		}
	}

	return curve.affineFromJacobian(x, y, z)
}

func (curve *CurveParams) ScalarBaseMult(k []byte) (*big.Int, *big.Int) {
