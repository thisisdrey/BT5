## #Vulnerability found for this question.

### Title
Protocol fee bypass on `Nep245`/`Imt` transfers via unit-delta `TokenDiff` splitting - (File: `contracts/defuse/core/src/intents/token_diff.rs`)

### Summary
`TokenDiff::token_fee` computes the fee independently for each `TokenDiff` intent, based solely on that intent's own `|delta|` for a given `TokenId`, and returns `Pips::ZERO` whenever `amount <= 1` for `Nep245`/`Imt` tokens. Because fee computation is never aggregated across multiple `TokenDiff` intents in the same batch/payload, an attacker can split a large multi-token (MT) transfer into N intents of `delta == ±1` each, paying zero fee in total, whereas the same net movement executed as a single intent would incur the protocol fee.

### Finding Description
The broken binding: `fee(net_delta_on_TokenId)` (fee that would be charged if the whole amount were transferred in one `TokenDiff`) should equal `sum(fee(delta_i))` across the N intents that jointly realize the same net transfer. They diverge because `token_fee` is evaluated per-intent on `amount = delta.unsigned_abs()` for that single call: [1](#0-0) 

and `TokenDiff::execute_intent` calls it once per `(token_id, delta)` pair within a single `TokenDiff`, with no state carried between separate `TokenDiff` intents (each has its own local `fees_collected`): [2](#0-1) 

Intents are executed strictly sequentially with no cross-intent aggregation for fee purposes, both within one `DefuseIntents` payload: [3](#0-2) 

and across multiple signed payloads in one `execute_intents`/`simulate_intents` call: [4](#0-3) 

Exploit flow: attacker (or attacker + colluding/self-controlled counterparty) holds N units of an MT `TokenId` (`Nep245`/`Imt`). Instead of signing one `TokenDiff` with `delta = -N` (which would incur `fee.fee_ceil(N) > 0`), they sign N `TokenDiff` intents (which can all be bundled into a single `DefuseIntents` message and single signature, or across separate payloads in the same `execute_intents`/`simulate_intents` batch) each with `delta = -1` on the same `token_id`, matched by counterpart intents with `delta = +1`. For each of the N intents, `token_fee` sees `amount == 1`, falls into the `TokenIdType::Nep171 | TokenIdType::Nep245 | TokenIdType::Imt => return Pips::ZERO` arm, so `fee_ceil(1) == 0` every time. `internal_apply_deltas` still moves the token unit by unit, and `Deltas::finalize`/`TransferMatcher` nets these into the same aggregate real transfer of N units that a single large `TokenDiff` would have produced — but with zero fee collected instead of `fee.fee_ceil(N)`.

No existing guard prevents this: `MultiPayload::verify`, nonce/salt checks, and the invariant check in `finalize` all validate signature/replay/balance-neutrality, not fee correctness; they do not require deltas to be batched or fee to be computed on an aggregate.

### Impact Explanation
Protocol fees are bypassed entirely on arbitrarily large `Nep245`/`Imt` (multi-token) transfers by decomposing them into unit-sized `TokenDiff` deltas, at the cost of a larger message/more entries in the intents array (not more signatures, since multiple `TokenDiff` intents can be packed in one signed `DefuseIntents` payload). This is repeatable across any account, any `Nep245`/`Imt` `TokenId`, and any batch, and directly falls under the Critical category "protocol fees bypassed... entirely on a large trade," diverting revenue that should go to `fee_collector`.

### Likelihood Explanation
The attacker needs only: (1) unprivileged Verifier balances of an MT (`Nep245`/`Imt`) token, (2) a counterparty (can be a second account they control, i.e., self-trading) willing to sign matching unit deltas, and (3) the ability to construct a `MultiPayload`/`DefuseIntents` message with N `TokenDiff` intents — all standard, permissionless operations (`execute_intents`/`simulate_intents` are open to any caller). No role, relayer key, or DAO action is required. The only cost is message size/gas for N intents, which scales linearly and is fully attacker-controlled and payable by the attacker.

### Recommendation
Compute and charge the protocol fee on the aggregate net `delta` per `(signer, token_id)` across all `TokenDiff` intents in the entire execution batch (or at least require the `amount <= 1` fee-exemption threshold to be evaluated against the signer's *cumulative* negative delta on that `TokenId` within a single `execute_signed_intents` call), rather than per individual intent's `|delta|`.

### Proof of Concept
`cargo test` (integration test under `tests/src/tests/defuse/intents/token_diff.rs` style, using `env.simulate_intents`/`env.defuse_execute_intents`):
1. Setup: create `user1`, `user2`; deploy an MT contract; deposit `N = 100` units of `nep245_token_id` to `user1`'s Verifier balance.
2. Path A ("split"): build a single `DefuseIntents` (or one `MultiPayload` batch) containing `N` `TokenDiff` intents from `user1`, each `{nep245_token_id: -1}`, matched by `N` `TokenDiff` intents from `user2`, each `{nep245_token_id: +1}` (plus whatever counter-token they exchange for, netted to zero). Execute via `env.defuse_execute_intents`. Assert `fee_collector` balance on `nep245_token_id` == 0.
3. Path B ("single"): reset state, execute one `TokenDiff` from `user1` `{nep245_token_id: -100}` matched with one from `user2` `{nep245_token_id: +100}` with a nonzero `fee` configured (`Env::builder().fee(Pips::ONE_PERCENT)`). Assert `fee_collector` balance on `nep245_token_id` == `fee.fee_ceil(100) > 0`.
4. Assert the two `fee_collector` balances differ (0 vs > 0) despite identical net token movement (100 units), proving fee bypass via `TokenDiff::token_fee`'s per-intent `amount <= 1` exemption (`contracts/defuse/core/src/intents/token_diff.rs:206-216`).

    pub fn execute_signed_intents(
        mut self,
        signed: impl IntoIterator<Item = MultiPayload>,
    ) -> Result<Transfers> {
        for signed in signed {
            self.execute_signed_intent(signed)?;
        }
        self.finalize()
    }

    fn execute_signed_intent(&mut self, signed: MultiPayload) -> Result<()> {
        // verify signed payload and get public key
        let public_key = signed.verify().ok_or(DefuseError::InvalidSignature)?;

        // calculate intent hash
        let hash = signed.hash();

        // extract NEP-413 payload
        let DefusePayload::<DefuseIntents> {
            signer_id,
            verifying_contract,
            deadline,
            nonce,
            message: intents,
        } = signed.extract_defuse_payload()?;

        // check recipient
        if verifying_contract != *self.state.verifying_contract() {
            return Err(DefuseError::WrongVerifyingContract);
        }

        self.inspector.on_deadline(deadline);

        // make sure message is still valid
        if deadline < Timestamp::now() {
            return Err(DefuseError::DeadlineExpired);
        }

        // make sure the account has this public key
        if !self.state.has_public_key(&signer_id, &public_key) {
            return Err(DefuseError::PublicKeyNotExist(signer_id, public_key));
        }

        // commit nonce
        self.verify_intent_nonce(nonce, deadline)?;
        self.state.commit_nonce(signer_id.clone(), nonce)?;

        intents.execute_intent(&signer_id, self, hash)?;
        self.inspector.on_intent_executed(&signer_id, hash, nonce);

        Ok(())
    }
