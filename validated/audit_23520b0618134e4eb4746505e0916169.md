### Title
Unbounded `VotesStore` Full-Scan on Every `GetPaginatedNowWitnessList` API Call Enables Cheap DoS of Node Query Service - (File: framework/src/main/java/org/tron/core/Wallet.java)

### Summary
The `GetPaginatedNowWitnessList` HTTP/gRPC endpoint recomputes real-time witness vote counts on **every single call** by fully iterating the entire `VotesStore`, a global key-value store where any account can cheaply create a new entry by casting a vote for as little as 1 vote-power (1 TRX of frozen/staked balance). Unlike the reviewed leveraged-pool commit queue, this queue is not bounded per epoch, is scanned on-demand by an unprivileged API caller rather than only by a keeper, and grows every time an attacker casts a new vote from a fresh account, making the per-request cost of this public query endpoint attacker-controlled and unbounded.

### Finding Description
`Wallet.getPaginatedNowWitnessList()` is invoked directly from the HTTP servlet `GetPaginatedNowWitnessListServlet` (`doGet`/`doPost` call `wallet.getPaginatedNowWitnessList(offset, limit)`) and from the corresponding gRPC service in `RpcApiService.java`, both fully public, unauthenticated query paths. [1](#0-0) 

Inside `Wallet.getPaginatedNowWitnessList`, before any pagination/sorting is applied, the method calls a private `countVote(votesStore)` helper that performs a **full iteration over every entry in `VotesStore`** to compute the net vote-count delta since the last maintenance cycle: [2](#0-1) [3](#0-2) 

This is the exact same full-store scan pattern used inside consensus maintenance processing (`MaintenanceManager.doMaintenance()`), which additionally deletes each entry it visits during the maintenance-only path: [4](#0-3) 

Crucially, `VotesStore` entries are keyed by voter address and are populated on every successful `VoteWitnessContract` execution, one entry per unique voter, regardless of how small the vote amount is. `VoteWitnessActuator.validate()` only requires `voteCount > 0` per witness and that the total votes (in TRX units) do not exceed the voter's tron power — there is no minimum stake or fee beyond the cost of freezing enough TRX to obtain at least 1 vote-power (as little as 1,000,000 sun / 1 TRX): [5](#0-4) [6](#0-5) 

An attacker can therefore create a large number of distinct accounts (each requiring only a minimal TRX freeze), have each cast a trivial vote, and thereby inflate `VotesStore` with an arbitrarily large number of entries within a single maintenance epoch. Because `getPaginatedNowWitnessList` is called synchronously for every incoming query (not throttled to once per epoch like the maintenance-triggered `countVote`), the node performs an O(N) full LevelDB/RocksDB iteration of attacker-inflated size on every request until the next maintenance cycle clears the store. Repeated invocation of this public API by the same attacker (or by many legitimate clients unknowingly triggering it) compounds CPU and I/O cost, degrading or blocking the node's ability to serve this and other API requests — mirroring the underlying bug class in the external report: an unprivileged party can cheaply populate a shared, unbounded queue that a critical path must fully scan.

### Impact Explanation
This does not directly move funds, but it does allow an unprivileged transaction broadcaster to inflict a Denial-of-Service on a node's public query API by making a shared, publicly-computed data structure (`VotesStore`) grow without bound at negligible cost per entry, and by causing every subsequent call to a heavily-used read API to perform full-store scans. Sustained abuse can starve HTTP/gRPC handler threads or I/O bandwidth on affected full nodes/solidity nodes, denying legitimate wallet/exchange clients access to witness/voting data — an availability impact on the node's ability to serve API requests, consistent with the "no longer serve an API" acceptance criterion.

### Likelihood Explanation
Likelihood is high relative to cost: any account holder can freeze a small amount of TRX to gain vote power and submit `VoteWitnessContract` transactions; each new voter address adds exactly one entry to `VotesStore`. Scripting thousands of cheap accounts and vote transactions across a maintenance epoch is inexpensive compared to the resulting per-request cost multiplier on the `GetPaginatedNowWitnessList` endpoint, which any anonymous API client can invoke repeatedly and freely (subject only to whatever rate limiting `RateLimiterServlet` applies, which is generic request-rate limiting, not tied to the size of the underlying data scanned).

### Recommendation
- Cache the computed `countVote(votesStore)` result (or the aggregated per-witness delta) and refresh it incrementally as new votes arrive, rather than re-scanning the entire `VotesStore` on every API call.
- Consider bounding/pruning `VotesStore` growth within an epoch, e.g., by enforcing a minimum vote-power threshold or restricting the number of new voter entries processed per query.
- Alternatively, compute and publish the "real-time" vote counts once per fixed short interval (independent of request volume) and serve cached results to API callers, decoupling per-request cost from the size of `VotesStore`.

### Proof of Concept
1. Programmatically create N new accounts, each freezing the minimum TRX needed to obtain ≥1 vote-power (`FreezeBalanceV2Contract`).
2. From each account, submit a `VoteWitnessContract` transaction with `vote_count = 1` for any registered witness, satisfying `VoteWitnessActuator.validate()`'s only checks (non-zero vote count, vote count ≤ tron power).
3. Each such transaction creates a distinct entry in `VotesStore` (keyed by voter address) via `countVoteAccount`/`VoteWitnessProcessor.execute`.
4. Repeat for a large N (e.g., tens of thousands) within a single maintenance interval before `MaintenanceManager.doMaintenance()` clears the store.
5. Issue repeated calls to `GET /wallet/getpaginatednowwitnesslist` (or the equivalent gRPC `GetPaginatedNowWitnessList`); each call triggers a full O(N) iteration of `VotesStore` inside `Wallet.countVote`, measurably increasing response latency and node CPU/I/O load in proportion to attacker-controlled N.

  private Map<ByteString, Long> countVote(VotesStore votesStore) {
    // Initialize a result map to store vote changes for each witness
    Map<ByteString, Long> countWitness = Maps.newHashMap();

    // VotesStore is a key-value store, where the key is the address of the voter
    Iterator<Entry<byte[], VotesCapsule>> dbIterator = votesStore.iterator();

    while (dbIterator.hasNext()) {
      Entry<byte[], VotesCapsule> next = dbIterator.next();
      VotesCapsule votes = next.getValue();

      /**
       * VotesCapsule contains two lists:
       * - Old votes: Last votes from the previous epoch, updated in maintenance period
       * - New votes: Latest votes in current epoch, updated after each vote transaction
       */
      votes.getOldVotes().forEach(vote -> {
        ByteString voteAddress = vote.getVoteAddress();
        long voteCount = vote.getVoteCount();
        countWitness.put(voteAddress,
            countWitness.getOrDefault(voteAddress, 0L) - voteCount);
      });
      votes.getNewVotes().forEach(vote -> {
        ByteString voteAddress = vote.getVoteAddress();
        long voteCount = vote.getVoteCount();
        countWitness.put(voteAddress,
            countWitness.getOrDefault(voteAddress, 0L) + voteCount);
      });
    }
    return countWitness;
  }

  private Map<ByteString, Long> countVote(VotesStore votesStore) {
    final Map<ByteString, Long> countWitness = Maps.newHashMap();
    Iterator<Entry<byte[], VotesCapsule>> dbIterator = votesStore.iterator();
    long sizeCount = 0;
    while (dbIterator.hasNext()) {
      Entry<byte[], VotesCapsule> next = dbIterator.next();
      VotesCapsule votes = next.getValue();
      votes.getOldVotes().forEach(vote -> {
        ByteString voteAddress = vote.getVoteAddress();
        long voteCount = vote.getVoteCount();
        if (countWitness.containsKey(voteAddress)) {
          countWitness.put(voteAddress, countWitness.get(voteAddress) - voteCount);
        } else {
          countWitness.put(voteAddress, -voteCount);
        }
      });
      votes.getNewVotes().forEach(vote -> {
        ByteString voteAddress = vote.getVoteAddress();
        long voteCount = vote.getVoteCount();
        if (countWitness.containsKey(voteAddress)) {
          countWitness.put(voteAddress, countWitness.get(voteAddress) + voteCount);
        } else {
          countWitness.put(voteAddress, voteCount);
        }
      });
      sizeCount++;
      votesStore.delete(next.getKey());
    }
    logger.info("There is {} new votes in this epoch", sizeCount);
    return countWitness;
  }

  private void countVoteAccount(VoteWitnessContract voteContract) {
    AccountStore accountStore = chainBaseManager.getAccountStore();
    VotesStore votesStore = chainBaseManager.getVotesStore();
    MortgageService mortgageService = chainBaseManager.getMortgageService();
    byte[] ownerAddress = voteContract.getOwnerAddress().toByteArray();

    VotesCapsule votesCapsule;

    //
    mortgageService.withdrawReward(ownerAddress);

    AccountCapsule accountCapsule = accountStore.get(ownerAddress);

    DynamicPropertiesStore dynamicStore = chainBaseManager.getDynamicPropertiesStore();
    if (dynamicStore.supportAllowNewResourceModel()
        && accountCapsule.oldTronPowerIsNotInitialized()) {
      accountCapsule.initializeOldTronPower();
    }

    if (!votesStore.has(ownerAddress)) {
      votesCapsule = new VotesCapsule(voteContract.getOwnerAddress(),
          accountCapsule.getVotesList());
    } else {
      votesCapsule = votesStore.get(ownerAddress);
    }

    accountCapsule.clearVotes();
    votesCapsule.clearNewVotes();

    voteContract.getVotesList().forEach(vote -> {
      logger.debug("countVoteAccount, address[{}]",
          ByteArray.toHexString(vote.getVoteAddress().toByteArray()));

      votesCapsule.addNewVotes(vote.getVoteAddress(), vote.getVoteCount());
      accountCapsule.addVotes(vote.getVoteAddress(), vote.getVoteCount());
    });

    accountStore.put(accountCapsule.createDbKey(), accountCapsule);
    votesStore.put(ownerAddress, votesCapsule);
  }
