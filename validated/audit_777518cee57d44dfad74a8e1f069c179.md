### Title
Positions can be opened at the exact liquidation threshold, making them immediately liquidatable on any price movement - ([File: contracts/DebtToken.sol](contracts/DebtToken.sol), [File: contracts/Pool.sol](contracts/Pool.sol))

### Summary
Metronome uses a single solvency check — `Pool.debtPositionOf`, which defines `_isHealthy` as `_debtInUsd <= _issuableLimitInUsd` — for both issuing new debt (`DebtToken.issue`) and for determining whether a position can be liquidated (`Pool.liquidate`). There is no separate, more conservative initial-margin requirement. A user can therefore issue synthetic debt up to 100% of their collateral-factor-weighted limit, at which point the position sits exactly on the liquidation boundary and becomes liquidatable on the smallest unfavorable oracle price update or accrued-interest tick.

### Finding Description
`Pool.debtPositionOf` computes `_isHealthy = _debtInUsd <= _issuableLimitInUsd`, where `_issuableLimitInUsd` is the sum of each deposit's USD value times its `collateralFactor` (`Pool.sol:248-288`). `DebtToken.issue` caps minting to `amount_ <= quoteUsdToToken(syntheticToken, _issuableInUsd)` (`DebtToken.sol:254-260`), so a user may mint debt until `_debtInUsd == _issuableLimitInUsd`. `Pool.liquidate` reverts only when the position is healthy, i.e., when `_debtInUsd <= _issuableLimitInUsd` still holds (`Pool.sol:559-563`). Both paths therefore share the identical threshold; no margin exists between "maximum allowed issuance" and "liquidatable". The same applies to increasing risk on an existing position via `DebtToken.mint`/leverage paths that end in the same `debtPositionOf` check, and to `DepositToken` withdrawals, which are bounded by the same `_issuableInUsd` accounting. Unlike Aloe's TWAP caveat, Metronome's `issue` itself enforces the check so a same-transaction manipulation cannot bypass it — but the missing initial-vs-maintenance margin separation is identical. Any single-block interest accrual or a minimal collateral/synth price drift pushes the freshly opened position into liquidatable state, where `quoteLiquidateOut` seizes collateral scaled by `liquidatorIncentive` plus `protocolFee` (`Pool.sol:455-471`).

### Impact Explanation
A user who mints near the limit is liquidated almost immediately after opening or increasing a position. The liquidation seizes `(1 + liquidatorIncentive + protocolFee) × repaid value` of their collateral (`Pool.sol:455-471`), so the user permanently loses that premium portion of their funds to the liquidator and fee collector far sooner than a reasonable borrower expects. This is a direct loss of user collateral that a separate initial margin would prevent, matching the Medium-severity classification of the analogous Aloe finding. The protocol and liquidators are not harmed; the loss falls on the borrower.

### Likelihood Explanation
Issuance up to the exact limit is common behavior (users routinely borrow the maximum shown by `debtPositionOf`/`_issuableInUsd`, and UI/max-mint helpers encourage it). Volatile collaterals plus per-second interest accrual (`DebtToken._calculateInterestAccrual`) mean the threshold can be crossed within seconds of `issue`, requiring only ordinary price movement — no attacker action is needed, and any permissionless liquidator can immediately call `Pool.liquidate`. Deployment configs confirm live `liquidatorIncentive`/`protocolFee` parameters and a single `debtPositionOf` health source across chains.

### Recommendation
Introduce a distinct initial-margin requirement stricter than the liquidation threshold: e.g., add a `issuanceFactor`/`initialCollateralFactor` (lower than `collateralFactor`) per `DepositToken`, compute a separate `_issuanceLimitInUsd` in `Pool.depositOf`/`debtPositionOf`, and enforce it in `DebtToken.issue`/`DebtToken.mint` and in `DepositToken.withdraw` while keeping `liquidate` on the maintenance (`collateralFactor`) threshold.

### Proof of Concept
Hardhat (fork or local), patterned on `test/Pool.test.ts`:

```ts
// alice deposits MET and mints msETH up to the full issuable limit
const { _issuableInUsd } = await pool.debtPositionOf(alice.address);
const maxIssuable = await masterOracle.quoteUsdToToken(msEth.address, _issuableInUsd);
await msEthDebtToken.connect(alice).issue(maxIssuable, alice.address); // succeeds, HF == 1.0 exactly

// smallest price shift (or a single accrueInterest tick) makes her liquidatable
await masterOracle.updatePrice(met.address, metPrice.mul(999).div(1000)); // -0.1%
const { _isHealthy } = await pool.debtPositionOf(alice.address);
expect(_isHealthy).to.eq(false); // liquidatable immediately after opening

// liquidator seizes collateral with incentive
const toRepay = await pool.quoteLiquidateMax(msEth.address, alice.address, msdMET.address);
await pool.connect(liquidator).liquidate(msEth.address, alice.address, toRepay, msdMET.address);
// alice loses (1 + liquidatorIncentive + protocolFee) × repaid value of collateral
```
