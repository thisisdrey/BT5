### Title
Unauthenticated `POST /v3/blocks/upload/` triggers network-wide block relay regardless of `broadcast` flag - (File: stackslib/src/net/api/postblock_v3.rs)

### Summary
`RPCPostBlockRequestHandler::try_handle_request` gates the call to `node.set_relay_message(StacksMessageType::NakamotoBlocks(...))` solely on `data_resp.accepted`, ignoring `self.broadcast`/authentication state entirely. An attacker who omits the `broadcast=1` query parameter (and thus needs no `authorization` secret per `try_parse_request`) can still cause the node to relay their block to the P2P network as soon as it is locally accepted.

### Finding Description
In `try_parse_request` (lines 99-122), the `authorization` header is checked against `self.auth` only if present, and the request is rejected with 401 only `if broadcast && !authenticated`. If the caller never sets `broadcast=1`, `authenticated` remains `false` and the request proceeds unauthenticated, storing `self.broadcast = Some(false)`.

In `try_handle_request` (lines 179-202), after `Relayer::process_new_nakamoto_block_ext` returns an accept/reject decision, the code does:
```
if data_resp.accepted {
    node.set_relay_message(StacksMessageType::NakamotoBlocks(NakamotoBlocksData {
        blocks: vec![block],
    }));
}
``` [1](#0-0) 

This check uses only `data_resp.accepted`, not `self.broadcast` nor any authentication flag. The `self.broadcast` value is only forwarded into `process_new_nakamoto_block_ext` as an internal announcement/instrumentation flag [2](#0-1) , and is never consulted again before the relay decision. Consequently, any block that the chainstate independently accepts (e.g., a block that is well-formed and buildable on the current tip, or otherwise passes the staging acceptance criteria in `Relayer::process_new_nakamoto_block_ext`) will be relayed to the P2P network via `set_relay_message`, even though the HTTP request carried no `broadcast=1` and no `authorization` header.

### Impact Explanation
This allows an unauthenticated remote peer to force the target node to gossip an attacker-supplied `NakamotoBlocksData` message to the rest of the network on the node's behalf, using the target node's identity/reputation as the relay origin. This is a network-wide propagation of data the attacker was never authorized to broadcast, matching the "network-wide propagation of forged data" Critical category — the propagation-gate bypass is the vulnerability, independent of whether the block content itself is separately validated by consensus logic downstream (consensus validation internals are out of scope, but the broadcast permission bypass itself is in scope).

### Likelihood Explanation
The endpoint is a standard RPC surface (`/v3/blocks/upload/`) reachable by any unprivileged remote party with network access to the node's RPC port. No secret/authorization header is required as long as `broadcast` is omitted or `0`. The only precondition is that the submitted block is accepted by `Relayer::process_new_nakamoto_block_ext` (i.e., builds validly on chainstate) — this is achievable by any attacker capable of producing a locally-valid Nakamoto block, and the action is repeatable for each new valid block the attacker can construct.

### Recommendation
Change the relay gate to require both local acceptance and explicit authorized broadcast intent, e.g.:
```rust
if data_resp.accepted && self.broadcast.unwrap_or(false) {
    node.set_relay_message(...)
}
```
Since `try_parse_request` already enforces `authenticated` whenever `broadcast` is true, gating on `self.broadcast` alone restores the intended authorization semantics.

### Proof of Concept
Add a test in `stackslib/src/net/api/tests/postblock_v3.rs` (or extend existing test harness for this handler) that:
1. Constructs `RPCPostBlockRequestHandler` with `auth = Some("secret".into())`.
2. Builds a `StacksHttpRequest` for `POST /v3/blocks/upload/` with no query string and no `authorization` header, carrying a validly-formed Nakamoto block byte payload that `Relayer::process_new_nakamoto_block_ext` will accept against the test chainstate/tip.
3. Calls `try_parse_request` (should succeed, since `broadcast=false` skips the 401 check) then `try_handle_request` against a `StacksNodeState` wired to a mock/spy that records calls to `set_relay_message`.
4. Asserts `data_resp.accepted == true` and asserts `set_relay_message` was called with `StacksMessageType::NakamotoBlocks(..)` despite `broadcast` being absent and no auth header supplied — demonstrating the missing `self.broadcast` check at line 198 of `postblock_v3.rs`.
