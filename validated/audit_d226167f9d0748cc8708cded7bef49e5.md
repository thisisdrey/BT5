### Title
Housekeeping stats-cache permanently disables repository size safety-net after a single accessor RPC - ([File: internal/grpc/middleware/housekeeping/middleware.go])

### Summary
`Middleware.scheduleHousekeepingIfNeeded` caches, in `m.statsCache`, the fact that a repository's file/directory count has been checked, and never re-evaluates it for the remaining lifetime of the Gitaly process. This mirrors the `endRewardTime()` bug class in the referenced report: a value/decision is computed once and cached indefinitely (well beyond a safe validity window) even though the underlying repository state can keep changing, so the cached "already checked" state silently becomes stale and the corrective action (scheduling housekeeping) that depends on it is never re-triggered.

### Finding Description
The `Middleware` struct holds `statsCache *sync.Map` keyed by `repoKey{storage, relativePath}` [1](#0-0) . On every accessor RPC (`protoregistry.OpAccessor`), `scheduleHousekeepingIfNeeded` is invoked [2](#0-1) . The function itself explicitly documents that the calculation is intended to run "only once per application restart" for repositories that don't otherwise trigger housekeeping via write operations [3](#0-2) :

```go
func (m *Middleware) scheduleHousekeepingIfNeeded(ctx context.Context, key repoKey, targetRepo *gitalypb.Repository) {
	if _, statsChecked := m.statsCache.Load(key); !statsChecked {
		...
		m.statsCache.Store(key, struct{}{})
		totalCount := repoStats.DirectoryCount + repoStats.FileCount
		ops := m.operationsExceedingStatThreshold(totalCount)
		if len(ops) > 0 {
			m.scheduleHousekeeping(ctx, targetRepo, true)
		}
	}
}
``` [4](#0-3) 

Once `key` is stored in `statsCache` (even the very first time the file/directory count happens to be below `StatThreshold`, e.g. default `1000` from `DefaultMiddlewareConfig` [5](#0-4) ), the walk is never performed again for that repository, no matter how much it subsequently grows through accessor-triggered channels (e.g. object pool alternates, replication, WAL apply, or other paths that don't route through the `OpMutator` branch that independently drives `scheduleHousekeeping`/`pendingOperations`). The cache has no TTL, no invalidation on repository changes, and no reset short of a full process restart.

This is directly analogous to the reported `endRewardTime()` issue: a value is cached for a period assumed to be "safe" (there, `updateCadence`; here, "for the life of the process"), but the underlying state used to compute correctness of that cached value (loose object/file counts vs. `rewardsPerSecond`/registered rewards) can change in the interim, and the code has no mechanism to detect or correct for that drift.

### Impact Explanation
The `scheduleHousekeepingIfNeeded` path is explicitly the fallback safety-net for repositories whose growth isn't otherwise captured by the mutator-driven `writeCount` heuristic in `scheduleHousekeeping`/`pendingOperations` [6](#0-5) . Permanently disabling this safety-net after a single, possibly-early, below-threshold check means loose objects, packfiles, or filesystem entries can accumulate unchecked for the remaining lifetime of the Gitaly process for any repository that isn't independently housekept via the mutator path. Over time this can degrade Gitaly's filesystem performance (very large directories, `git` operations linear in loose object count) and consume disk space, which is a resource-exhaustion/availability concern for the Gitaly node — but it is a gradual degradation rather than an immediately reachable crash or object-boundary escape.

### Likelihood Explanation
The condition is reached deterministically: any repository that receives at least one accessor RPC before it grows will have `statsCache` populated, and subsequent growth via any path not captured by the `OpMutator` write-count logic will never be re-assessed. However, in practice most repository growth in Gitaly happens through RPCs classified as `OpMutator`, which are independently tracked by `scheduleHousekeeping`'s `writeCount`/`RPCInterval` logic, so this gap is narrower than the referenced financial-contract bug and mainly affects repositories whose growth is driven by mechanisms outside the mutator interceptor's visibility (e.g., pool/alternate object sharing, out-of-band replication).

### Recommendation
Do not use a permanent, unbounded cache to gate the stats walk. Either (a) remove the "once per process" cache and instead re-run the (cheap, bounded) stat check periodically or with a TTL, similar to the retry logic recommended for the `endRewardTime()` finding, or (b) invalidate/refresh the `statsCache` entry whenever `scheduleHousekeeping` observes writes for the same `repoKey`, so the safety-net can be re-armed once file/directory counts are expected to have changed again.

### Proof of Concept
1. Start Gitaly and perform any accessor RPC (e.g. `RepositoryExists`) against a small, freshly-created repository R, causing `scheduleHousekeepingIfNeeded` to walk R, find total count below `StatThreshold` (1000 by default), and store `key` in `statsCache`.
2. Grow R's file/directory count past the threshold purely through means that do not go through `OpMutator` RPCs on this Gitaly node (e.g., linking many repositories to R as an object pool member so R accumulates additional on-disk objects via alternates, or via out-of-band replication/WAL apply).
3. Continue issuing only accessor RPCs against R. Because `key` is already present in `statsCache`, `scheduleHousekeepingIfNeeded` immediately returns without re-walking the repository or ever calling `scheduleHousekeeping`, so the stat-based housekeeping trigger never fires for R for the remaining lifetime of the process, regardless of how large it grows.

// pendingOperations returns operations that have exceeded their RPC interval thresholds.
func (m *Middleware) pendingOperations(a *activity, force bool) []config.OperationType {
	var pending []config.OperationType

	for _, op := range allOperations {
		thresholds := m.getThresholds(op)
		lastRun := a.writeCountAtLastRun[op]
		writesSinceLastRun := a.writeCount - lastRun

		if force || writesSinceLastRun > thresholds.RPCInterval {
			pending = append(pending, op)
		}
	}

	return pending
}

// operationsExceedingStatThreshold returns operations whose stat threshold is exceeded.
func (m *Middleware) operationsExceedingStatThreshold(statCount int) []config.OperationType {
	var ops []config.OperationType

	for _, op := range allOperations {
		thresholds := m.getThresholds(op)
		if statCount > thresholds.StatThreshold {
			ops = append(ops, op)
		}
	}

	return ops
}

// scheduleHousekeepingIfNeeded walks the repository path to gather file and directory counts,
// and schedules housekeeping if the total count exceeds the configured threshold.
// Uses a sync.Map cache to track repositories where statistics have been calculated, ensuring
// the calculation occurs only once per application restart. This targets accessor RPCs for
// repositories that don't trigger housekeeping through write operations, where a single stats
// check per restart is sufficient for low-activity repos.
func (m *Middleware) scheduleHousekeepingIfNeeded(ctx context.Context, key repoKey, targetRepo *gitalypb.Repository) {
	if _, statsChecked := m.statsCache.Load(key); !statsChecked {
		localRepo := m.localRepoFactory.Build(targetRepo)
		repositoryPath, err := localRepo.Path(ctx)
		if err != nil {
			if errors.Is(err, storage.ErrRepositoryNotFound) {
				return
			}
			m.logger.WithError(err).ErrorContext(ctx, "housekeeping: find repo path")
			return
		}

		repoStats := snapshot.RepositoryStatistics{}
		if err := snapshot.WalkPathForStats(ctx, repositoryPath, &repoStats); err != nil {
			m.logger.WithError(err).ErrorContext(ctx, "calculate repository statistics")
			return
		}

		m.logger.WithFields(log.Fields{
			"repository_stats": map[string]any{
				"directory_count": repoStats.DirectoryCount,
				"file_count":      repoStats.FileCount,
			},
		}).InfoContext(ctx, "collected repository statistics")

		m.statsCache.Store(key, struct{}{})
		totalCount := repoStats.DirectoryCount + repoStats.FileCount
		ops := m.operationsExceedingStatThreshold(totalCount)
		if len(ops) > 0 {
			m.scheduleHousekeeping(ctx, targetRepo, true)
		}
	}
