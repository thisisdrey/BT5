Confirmed: `HttpServer` is `tiny_http::Server` and `SignerEventReceiver` uses it with no read-timeout configuration.### Title
Unauthenticated single-slow-POST DoS stalls the sole event-receiver thread - (File: `libsigner/src/events.rs`)

### Summary
`SignerEventReceiver::bind` starts a `tiny_http::Server` (`HttpServer::http(listener)`) with no read timeout configured, and `main_loop`/`next_event` process requests strictly sequentially on a single thread. A remote attacker who can reach the signer's event-receiver port can send a POST with an inflated `Content-Length` and withhold the body, causing `process_event`'s `request.as_reader().read_to_string(&mut body)` to block indefinitely and starve all subsequent legitimate node-originated events.

### Finding Description
`bind` creates the HTTP server directly from `tiny_http::Server::http(listener)` with no timeout wrapping: [1](#0-0) . The receiver's `main_loop` is a simple sequential loop that calls `next_event()` once per iteration and only proceeds after it returns: [2](#0-1) . This loop runs on a single dedicated `event_receiver` thread spawned by `Signer::spawn`, with no worker pool: [3](#0-2) .

`next_event` blocks on `http_server.recv()` until a request's headers are fully received, then dispatches based on URL to `process_event` for `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, and `/new_block`: [4](#0-3) . `process_event` then reads the full body via `request.as_reader().read_to_string(&mut body)`: [5](#0-4) . `tiny_http` (declared as a dependency, version `0.12`) parses headers and returns the request as soon as headers are complete; the body is read lazily by the caller via the returned reader, consistent with `Content-Length` semantics [6](#0-5) .

An attacker's message: open a TCP connection to the bound event-receiver port, send valid HTTP headers for `POST /stackerdb_chunks` (or any of the other three routes) with `Content-Length: 1000000`, then send zero or one byte of body and stop sending — never closing the connection. `http_server.recv()` returns the request once headers are parsed, `next_event` dispatches to `process_event`, and `read_to_string` blocks waiting for the declared `Content-Length` bytes that never arrive, with no read timeout configured anywhere in this path. Because the receiver thread runs one request at a time (`main_loop` calls `next_event()` synchronously in a loop), this single blocked call prevents `next_event` from ever returning to accept or process any further request — including legitimate events from the actual Stacks node (block proposals, burn block/stacks block notifications, stackerdb chunks) — for as long as the attacker holds the connection open.

No authentication, secret, or signature check gates this path: `next_event` only checks the URL and HTTP method before calling `process_event`, with no length caps or timeouts. `MAX_MESSAGE_LEN`/per-field caps found elsewhere in the RPC-server (`stackslib/src/net/http`) do not apply to this separate `libsigner` HTTP server implementation.

### Impact Explanation
A single unauthenticated remote message can indefinitely stall the entire signer event pipeline (an availability DoS), preventing the signer from receiving/proposing/validating blocks or receiving burn-block/stacks-block notifications from its local node, effectively taking the signer offline until the attacker's connection is forcibly terminated (e.g., OS-level TCP timeout or process restart). This matches "Critical - remote crash/unauthenticated DoS from few messages" since it is a bounded, repeatable (attacker can simply reconnect after being killed) denial of service triggered by exactly one crafted request with no privilege, secret, or prior state required.

### Likelihood Explanation
The only precondition is network reachability to the event-receiver's bind address/port (the signer's HTTP endpoint that the node is configured to POST events to); no authentication, valid StackerDB slot, signature, or node secret is needed. The attacker cost is a single TCP connection and a short crafted HTTP header. The attack is trivially repeatable against any signer whose event-receiver port is exposed to the attacker (e.g., not restricted to localhost/loopback via firewall/network policy — reachability is stated as a precondition in this question, not evaluated here).

### Recommendation
Configure a per-connection/per-request read timeout on the `tiny_http::Server`/incoming stream (e.g., via `HttpServer::http_with_config` or manually setting a socket read timeout on accepted connections), and/or bound the amount of time `read_to_string` in `process_event` is allowed to block (read with a deadline, or read in a loop with `set_read_timeout` and abort/close the connection on timeout). Additionally consider validating `Content-Length` against a maximum allowed payload size before reading, and moving to a request-handling model that can service multiple connections independently (e.g., a small thread/worker pool or non-blocking I/O) so one slow/malicious peer cannot stall unrelated legitimate requests.

    fn main_loop(&mut self) {
        loop {
            if self.is_stopped() {
                info!("Event receiver stopped");
                break;
            }
            let next_event = match self.next_event() {
                Ok(event) => event,
                Err(EventError::UnrecognizedEvent(..)) => {
                    // got an event that we don't care about (not a problem)
                    continue;
                }
                Err(EventError::Terminated) => {
                    // we're done
                    info!("Caught termination signal");
                    break;
                }
                Err(e) => {
                    warn!("Failed to receive next event: {:?}", &e);
                    continue;
                }
            };
            if !self.forward_event(next_event) {
                info!("Failed to forward event");
                break;
            }
        }
        info!("Event receiver main loop exit");
    }

    fn next_event(&mut self) -> Result<SignerEvent<T>, EventError> {
        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)
            } else if request.url() == "/new_block" {
                process_event::<T, StacksBlockEvent>(request)
            } else {
                let url = request.url().to_string();
                debug!(
                    "[{:?}] next_event got request with unexpected url {}, return OK so other side doesn't keep sending this",
                    event_receiver.local_addr,
                    url
                );
                ack_dispatcher(request);
                Err(EventError::UnrecognizedEvent(url))
            }
        })?
    }
