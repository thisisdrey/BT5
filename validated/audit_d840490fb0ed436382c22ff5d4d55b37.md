### Title
Protocol fee bypass on `Nep245`/`Imt` `TokenDiff` swaps via unit-amount leg splitting - ([File: contracts/defuse/core/src/intents/token_diff.rs])

### Summary
`TokenDiff::token_fee` waives the fee whenever a single `TokenDiff` leg's `|delta| <= 1` for `Nep245`/`Imt`/`Nep171` tokens. Because fees are computed independently per `TokenDiff` intent and intents are executed in a simple loop with no aggregation across intents in the same `MultiPayload`, an unprivileged signer can split any large `Nep245`/`Imt` swap into N legs of `delta = ±1` and pay zero fee in total, whereas an equivalent single-leg swap of the same total amount would pay `protocol_fee.fee_ceil(N)`.

### Finding Description
The broken binding: `sum(fee_ceil per split leg) == protocol_fee.fee_ceil(N)` for an economically equivalent transfer of `N` units of the same `Nep245`/`Imt` token — this equality is false; the split-batch side evaluates to `0`.

Root cause is in `TokenDiff::token_fee`: [1](#0-0) 
For `TokenIdType::Nep245`/`Imt`, the fee is only applied `if amount > 1`; otherwise `Pips::ZERO` is returned regardless of the configured `fee`. This is invoked per `TokenDiff` intent inside `execute_intent`: [2](#0-1) 
Each `TokenDiff` intent's fee is computed solely from that intent's own `delta.unsigned_abs()`; there is no accumulation of amounts across multiple `TokenDiff` intents targeting the same token in the same batch.

`DefuseIntents::execute_intent` simply iterates the intent list and executes each independently, with no merging/deduplication of `TokenDiff` intents on the same token: [3](#0-2) 

Exploit: the attacker (holding ≥50 units of a `Nep245` token, e.g. a wrapped FT represented as an MT token as shown in existing cross-contract MT transfer flows) signs one `MultiPayload` containing 50 `TokenDiff` intents, each with `diff = {token_id: -1, counter_token_id: +k}` instead of one `TokenDiff` with `diff = {token_id: -50, counter_token_id: +50k}`. In `execute_intent`, each of the 50 legs computes `Self::token_fee(token_id, 1, protocol_fee)`, which hits the `amount <= 1` branch and returns `Pips::ZERO`, so `fee_ceil(1)` on `Pips::ZERO` is `0` for every leg. The matching positive legs needed to keep the batch's global balance invariant (`TransferMatcher`) at zero can come from a counterparty (a second self-controlled account, or a cooperating solver) providing the offsetting `+1` legs, which themselves are not negative deltas and are never fee-charged. No existing guard (`MultiPayload::verify`, nonce checks, `TransferMatcher::finalize`) aggregates amounts by token across intents, so nothing prevents or detects this decomposition.

### Impact Explanation
`engine.state.fee_collector()` receives 0 fees instead of `protocol_fee.fee_ceil(50)` (or more, for larger N) that would be collected from an equivalent unsplit swap. This directly matches the Critical category "protocol fees bypassed" — expected protocol revenue is lost on every `Nep245`/`Imt` swap the attacker chooses to decompose. The attack is fully repeatable per account, per token, and per batch, and scales linearly with the number of legs the attacker is willing to include (bounded only by gas/tx size, not by protocol logic).

### Likelihood Explanation
Preconditions are trivial for any unprivileged user: hold the token being swapped, sign one `MultiPayload` with N `TokenDiff` intents instead of one, and have a counterparty (which can be a second account the attacker also controls) provide the offsetting unit-amount legs. No roles, relayer keys, or special contract states are required, and the cost is only the marginal gas of extra intents in the same transaction/batch.

### Recommendation
Compute the `Nep245`/`Imt`/`Nep171` fee waiver based on the aggregated per-token, per-signer amount across all `TokenDiff` intents within the same `MultiPayload`/execution context, not per individual intent leg, or remove the unconditional `amount <= 1` waiver for `Nep245`/`Imt` (fungible-capable) token types and only apply it for genuinely non-fungible `Nep171` tokens.

### Proof of Concept
`cargo test` (sandbox, `near-workspaces`) comparing:
1. Signer swaps `-50` of a `Nep245` token in a single `TokenDiff` against a counterparty; assert `TokenDiffEvent.fees_collected` for that token equals `protocol_fee.fee_ceil(50)` (nonzero, with `fee_collector` configured to a nonzero `Pips`).
2. Same signer, same total volume, but signs one `MultiPayload` with 50 separate `TokenDiff` intents each with `delta = -1` on the same `Nep245` token_id, matched by 50 offsetting `+1` counterparty legs; assert the sum of `fees_collected` across all emitted `TokenDiffEvent`s for that token is `0`.
3. Assert `(1) != (2)`, proving the fee-collector balance divergence for economically identical trades.
