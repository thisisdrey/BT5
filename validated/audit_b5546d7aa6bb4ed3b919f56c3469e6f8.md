### Title
No vulnerability - bandwidth request bucketing is priority-independent of receipt sizing - (File: runtime/runtime/src/bandwidth_scheduler/scheduler.rs)

### Summary
The premise that an attacker can craft receipt sizes to make `get_receipt_group_sizes_for_buffer_to_shard`/`generate_bandwidth_request` push a link into a permanently favored priority bucket is false. Priority in `process_bandwidth_requests` is keyed strictly by the link's persisted `allowance` scalar, not by the shape or size of the request's `requested_values_bitmap`.

### Finding Description
`process_bandwidth_requests` buckets requests by `self.get_allowance(&request.link)` [1](#0-0) , and processes the highest-allowance bucket first [2](#0-1) . This `allowance` is a per-`(sender,receiver)` link scalar stored in `link_allowances`, entirely separate from any request's byte size, bitmap shape, or `BandwidthRequestValues`. `SchedulerBandwidthRequest::new` only converts the `requested_values_bitmap` into a queue of *bandwidth increases* (how much more to request), not into any priority signal [3](#0-2) .

Every link — including both an attacker-controlled `A→C` link and a legitimate `B→C` link — receives an identical `fair_link_bandwidth = max_shard_bandwidth / num_shards` increase to its allowance every height in `increase_allowances`, capped at `max_allowance` [4](#0-3) [5](#0-4) . Whenever a link is actually granted bandwidth, `try_grant_bandwidth` immediately decreases that specific link's allowance by the granted amount via `decrease_allowance`, and the residual request is re-queued at the link's new, lower allowance [6](#0-5) [7](#0-6) .

Consequently, a link (e.g. `A→C`) that is repeatedly granted large amounts of bandwidth has its allowance repeatedly drained, while a link (`B→C`) that is granted less accumulates allowance up toward `max_allowance` at the same fixed per-height rate as every other link, independent of how "mixed" or "genuine" its senders are. There is no code path by which shaping receipt sizes/groups to hit specific `BandwidthRequestValues` bitmap bits can raise a link's priority bucket beyond what its actual allowance state dictates — the bitmap only determines *how much* is requested, not *when* it is served relative to other links. The algorithm is explicitly documented and designed as a fair token-bucket precisely to prevent this class of starvation [8](#0-7) .

### Impact Explanation
None. The described attack requires the attacker to control the *priority key* (allowance) via request shaping, but the priority key is a persisted, per-link scalar governed only by the grant history of that specific link and a uniform per-height increment shared by all links. No unprivileged transaction input (receipt size, count, or bitmap shape) can bypass this and does not achieve any starvation beyond what the fairness algorithm already accounts for and bounds via `max_allowance`.

### Likelihood Explanation
Not applicable — the described mechanism to bias bucket priority via receipt sizing does not exist in the code.

    /// Increase allowance on the link, but don't exceed the maximum allowance.
    fn increase_allowance(&mut self, link: &ShardLink, increase: Bandwidth) {
        let current_allowance = self.get_allowance(link);
        let mut new_allowance = current_allowance.saturating_add(increase);
        if new_allowance > self.params.max_allowance {

    /// Try to grant some bandwidth on the link.
    /// On success returns TryGrantOutcome::Granted
    /// If granting more bandwidth is not possible because of some restrictions, returns TryGrantOutcome::NotGranted.
    fn try_grant_bandwidth(&mut self, link: &ShardLink, bandwidth: Bandwidth) -> TryGrantOutcome {
        if !self.is_link_allowed(link) {
            // Not allowed to send anything on this link. Receiver is too congested or had a missing chunk.
            return TryGrantOutcome::NotGranted;
        }

        let sender_budget = self.sender_budget.get(&link.sender).copied().unwrap_or(0);
        let receiver_budget = self.receiver_budget.get(&link.receiver).copied().unwrap_or(0);

        if sender_budget < bandwidth || receiver_budget < bandwidth {
            // Sender or receiver can't send this much as they would go over the per-shard budget.
            return TryGrantOutcome::NotGranted;
        }

        // Ok, grant the bandwidth
        self.sender_budget.insert(link.sender, sender_budget - bandwidth);
        self.receiver_budget.insert(link.receiver, receiver_budget - bandwidth);
        self.decrease_allowance(link, bandwidth);
        self.grant_more_bandwidth(link, bandwidth);

        TryGrantOutcome::Granted
    }

impl SchedulerBandwidthRequest {
    pub fn new(
        sender_shard: ShardId,
        bandwidth_request: &BandwidthRequest,
        params: &BandwidthSchedulerParams,
        layout: &ShardLayout,
    ) -> Option<Self> {
        let Ok(sender_index) = layout.get_shard_index(sender_shard) else {
            // Request from a shard that is not in the current set of shards.
            return None;
        };
        let Ok(receiver_index) = layout.get_shard_index(bandwidth_request.to_shard.into()) else {
            // Request to a shard that is not in the current set of shards.
            return None;
        };
        let link = ShardLink::new(sender_index, receiver_index);

        let mut bandwidth_increases = VecDeque::new();

        // Keeps track of the total bandwidth that would be granted by the requested increases.
        // Base bandwidth is already granted on all links, so we start with that.
        let mut current_total = params.base_bandwidth;

        let request_values = BandwidthRequestValues::new(params).values;
        for bit_idx in 0..bandwidth_request.requested_values_bitmap.len() {
            if !bandwidth_request.requested_values_bitmap.get_bit(bit_idx) {
                continue;
            }

            // Request for the total value of bandwidth that should be granted on the link.
            let requested_value = request_values[bit_idx];
            if requested_value <= current_total {
                continue;
            }
            // Convert the absolute value to a bandwidth increase.
            bandwidth_increases.push_back(requested_value - current_total);
            current_total = requested_value;
        }

        if bandwidth_increases.is_empty() {
            return None;
        }

        Some(Self { link, bandwidth_increases })
    }
