### Title
Vote-classification check validates only the program ID, not vote instruction validity, letting any transaction hijack the reserved vote-processing pipeline - ([File: perf/src/sigverify.rs])

### Summary
`is_simple_vote_transaction_view` in `perf/src/sigverify.rs` (and its twin `is_simple_vote_transaction` in `runtime-transaction/src/runtime_transaction/transaction_view.rs`) determines whether a packet is a "simple vote transaction" by checking only structural properties (≤2 signatures, legacy message, exactly one instruction, and that the instruction's program id equals `solana_sdk_ids::vote::id()`). It never checks that the instruction data actually deserializes into a valid vote instruction (e.g., `TowerSync`/`Vote`).

### Finding Description
`fn is_simple_vote_transaction_view<D: TransactionData>(view: &SanitizedTransactionView<D>) -> bool` [1](#0-0)  flags a packet as `SIMPLE_VOTE_TX` purely on shape/program-id, unlike `solana_vote_parser::is_valid_vote_only_transaction`, which additionally deserializes the instruction data and requires `ix.is_single_vote_state_update()` [2](#0-1) . The weaker check is the one actually used to route and gate packets: it sets the packet's vote flag in `verify_packet` [3](#0-2) , and this flag/derived classification is propagated as a trusted override (`is_simple_vote_tx: Option<bool>`) into `RuntimeTransaction` construction without re-validation [4](#0-3)  and in `transaction_view.rs` [5](#0-4) .

This is structurally the same bug class as the reported SuperVaultAggregator issue: two verification paths exist (a strict, "real" vote validity check in `vote_parser.rs`, and a lax structural-only check in `sigverify.rs`/`transaction_view.rs`), and the system relies on the lax one to grant access to a privileged/reserved resource — here, the dedicated vote-processing pipeline (`VoteWorker`, `VotePacketReceiver`, `VoteStorage`) that is completely separate from ordinary fee-market transaction processing [6](#0-5) . `VoteWorker::consume_scan_should_process_packet` even asserts the packet passed `view.is_simple_vote_transaction()` but performs no deeper vote-instruction validation before treating it as a vote for buffering/consumption purposes [7](#0-6) .

An unprivileged network peer can craft a legacy, single-signature (or two-signature) transaction with exactly one instruction whose `program_id_index` points at the vote program but whose instruction `data` is garbage (fails to deserialize as any real `VoteInstruction`). This transaction:
- Passes `is_simple_vote_transaction_view` / `is_simple_vote_transaction` (program id + shape only).
- Gets flagged `PacketFlags::SIMPLE_VOTE_TX` and is routed to the vote-only ingestion/processing path (`VotePacketReceiver`/`VoteWorker`) rather than the regular, fee-competitive banking-stage/forwarding path.
- Is excluded from prioritization-fee-cache accounting, since `PrioritizationFeeCache::update` explicitly skips any transaction where `is_simple_vote_transaction()` is true [8](#0-7) .

Note: in this codebase's current cost-tracker, votes are explicitly costed under the *same* block/account limits as regular transactions (`test_cost_tracker_vote_transactions_use_regular_limits` confirms votes no longer get a separately-sized/cheaper cost bucket) [9](#0-8) , so the earlier-generation "underpriced vote cost limit" bypass is not exploitable here. The remaining, still-live impact is misrouting/pipeline-isolation abuse and prioritization-fee-accounting evasion, not a cost-limit bypass.

### Impact Explanation
Any unprivileged transaction sender can inject packets that masquerade as votes into the validator's dedicated vote-ingestion pipeline (`VotePacketReceiver`/`VoteWorker`/`VoteStorage`), which is architecturally isolated from and prioritized differently than ordinary user transactions, without needing to construct an actual, functionally meaningful vote. This lets an attacker consume vote-lane processing/buffering capacity that is meant exclusively for cluster consensus vote traffic, and separately allows such spoofed "vote" transactions to silently bypass prioritization-fee-cache accounting used for the transaction-fee floor [8](#0-7) , an unintended asymmetric routing/QoS advantage available to any network peer.

### Likelihood Explanation
Exploitability requires no special stake, keys, or privileges — only crafting a standard legacy transaction with one instruction targeting the vote program ID and arbitrary payload data, which is trivial for any client capable of submitting packets to the TPU vote port or gossip.

### Recommendation
Align the fast-path classification used at sigverify/transaction-construction time with the stricter semantic validation already implemented in `solana_vote_parser::is_valid_vote_only_transaction` (deserializing and checking `is_single_vote_state_update()`), or otherwise ensure that any transaction admitted into the reserved vote pipeline is confirmed as a genuine vote instruction before it is exempted from prioritization-fee accounting or routed away from the standard fee-market path.

### Proof of Concept
1. Construct a legacy `Transaction` with a single `CompiledInstruction` whose `program_id_index` resolves to `solana_sdk_ids::vote::id()` and whose `data` is arbitrary bytes that do not deserialize into any `VoteInstruction` variant.
2. Sign it with 1–2 valid signer(s) so it passes basic sanitize/signature checks (`verify_packet` only checks the raw ed25519 signature, not vote semantics) [10](#0-9) .
3. Submit the packet; `is_simple_vote_transaction_view` returns `true` purely from shape/program-id, setting `PacketFlags::SIMPLE_VOTE_TX` [11](#0-10) .
4. Observe the transaction is routed to `VoteWorker`'s dedicated vote pipeline (`tpu_receiver`/`storage`) [6](#0-5)  and is excluded from `PrioritizationFeeCache::update` [8](#0-7) , despite not being a real vote — demonstrating the classification-check bypass reachable by any unprivileged sender.

fn verify_packet(packet: &mut PacketRefMut, reject_non_vote: bool, enable_tx_v1: bool) -> bool {
    // If this packet was already marked as discard, drop it
    if packet.meta().discard() {
        return false;
    }

    let Some(data) = packet.data(..) else {
        return false;
    };

    let (is_simple_vote_tx, verified) = {
        let Ok(view) = SanitizedTransactionView::try_new_sanitized(data, &sanitize_config()) else {
            return false;
        };

        if !enable_tx_v1 && matches!(view.version(), TransactionVersion::V1) {
            return false;
        }

        let is_simple_vote_tx = is_simple_vote_transaction_view(&view);
        if reject_non_vote && !is_simple_vote_tx {
            (is_simple_vote_tx, false)
        } else {
            let signatures = view.signatures();
            if signatures.is_empty() {
                (is_simple_vote_tx, false)
            } else {
                let message = view.message_data();
                let static_account_keys = view.static_account_keys();
                let verified = signatures
                    .iter()
                    .zip(static_account_keys.iter())
                    .all(|(signature, pubkey)| signature.verify(pubkey.as_ref(), message));
                (is_simple_vote_tx, verified)
            }
        }
    };

    if is_simple_vote_tx {
        packet.meta_mut().flags |= PacketFlags::SIMPLE_VOTE_TX;
    }

    verified
}

fn is_simple_vote_transaction_view<D: TransactionData>(view: &SanitizedTransactionView<D>) -> bool {
    // vote could have 1 or 2 sigs; zero sig has already been excluded by sanitization.
    if view.num_signatures() > 2 {
        return false;
    }

    // simple vote should only be legacy message
    if !matches!(view.version(), TransactionVersion::Legacy) {
        return false;
    }

    // skip if has more than 1 instruction
    if view.num_instructions() != 1 {
        return false;
    }

    let mut instructions = view.instructions_iter();
    let Some(instruction) = instructions.next() else {
        return false;
    };
    if instructions.next().is_some() {
        return false;
    }

    let program_id_index = usize::from(instruction.program_id_index);
    let Some(program_id) = view.static_account_keys().get(program_id_index) else {
        return false;
    };

    *program_id == solana_sdk_ids::vote::id()
}

/// Check if a transaction is a valid vote-only transaction.
/// A valid vote-only transaction must:
/// 1. Have exactly one instruction
/// 2. That instruction must be to the vote program
/// 3. That instruction must be a single vote state update (UpdateVoteState, TowerSync, etc.)
pub fn is_valid_vote_only_transaction(tx: &impl SVMTransaction) -> bool {
    let mut instructions = tx.program_instructions_iter();

    let Some((program_id, instruction)) = instructions.next() else {
        return false;
    };

    if instructions.next().is_some() {
        return false;
    }

    if !solana_sdk_ids::vote::check_id(program_id) {
        return false;
    }

    limited_deserialize::<VoteInstruction>(instruction.data, solana_packet::PACKET_DATA_SIZE as u64)
        .map(|ix| ix.is_single_vote_state_update())
        .unwrap_or(false)
}

        return None;

    }

    Some(view)
