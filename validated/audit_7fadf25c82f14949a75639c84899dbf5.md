### Title
Commission Recipient Misdirection After `switch_operator` Bypasses Operator Beneficiary — (`File: aptos-move/framework/aptos-framework/sources/staking_contract.move`)

---

### Summary

In `aptos_framework::staking_contract`, when a staker calls `switch_operator`, the pending commission for the old operator is queued into the distribution pool under the old operator's address. After the switch, all subsequent calls to `distribute_internal` use the **new operator** as the `operator` parameter. The beneficiary-redirect guard (`if (recipient == operator)`) then silently fails to fire for the old operator's commission entry, causing those APT coins to be deposited directly to the old operator's address instead of to `beneficiary_for_operator(old_operator)`.

---

### Finding Description

`distribute_internal` contains a single guard that redirects commission to the operator's beneficiary:

```move
if (recipient == operator) {
    recipient = beneficiary_for_operator(operator);
};
``` [1](#0-0) 

The `operator` parameter is whatever address the staking contract is currently keyed by. Inside `switch_operator`, the sequence is:

1. `distribute_internal(staker_address, old_operator, &mut staking_contract)` — flushes any already-inactive stake, correctly using `old_operator`.
2. `request_commission_internal(old_operator, &mut staking_contract)` — enqueues `old_operator` as a distribution-pool recipient for the accrued commission.
3. The staking contract is re-keyed to `new_operator` via `staking_contracts.add(new_operator, staking_contract)`. [2](#0-1) 

After the lockup period expires, anyone calls `distribute(staker, new_operator)`, which invokes `distribute_internal(staker, new_operator, staking_contract)`. At that point the distribution pool still holds `old_operator` as a shareholder. The guard evaluates `old_operator == new_operator` → **false**, so `recipient` is never replaced with `beneficiary_for_operator(old_operator)`. The commission is deposited directly to `old_operator`. [3](#0-2) 

`request_commission_internal` always records the commission under the operator address passed to it:

```move
add_distribution(operator, staking_contract, operator, commission_amount);
``` [4](#0-3) 

The same path is reachable through `vesting::update_operator`, which calls `staking_contract::switch_operator` on behalf of the vesting contract signer. [5](#0-4) 

---

### Impact Explanation

Any operator who has called `set_beneficiary_for_operator` to redirect their commission to a separate account (e.g., a company treasury, a multisig, or a smart-contract wallet) will have the commission accrued at the moment of `switch_operator` silently sent to their own operator address instead. The beneficiary receives nothing for that distribution cycle. Because `distribute` is a permissionless entry function, the incorrect deposit is irreversible once executed. The magnitude equals the full commission amount outstanding at the time of the operator switch — potentially large for high-value staking pools.

---

### Likelihood Explanation

`switch_operator` and `switch_operator_with_same_commission` are public entry functions callable by any staker at any time. [6](#0-5) [7](#0-6) 

The `operator_beneficiary_change_enabled` feature flag is already live on mainnet (it is checked only in `set_beneficiary_for_operator`, not in `distribute_internal`). Any staker who legitimately switches operators while the old operator has a beneficiary set will trigger the misdirection without any malicious intent.

---

### Recommendation

In `distribute_internal`, replace the hard equality check against the current `operator` parameter with a lookup that resolves the beneficiary for **any** recipient that has one registered, regardless of whether it matches the current operator key:

```move
// Before (broken after switch_operator):
if (recipient == operator) {
    recipient = beneficiary_for_operator(operator);
};

// After (correct):
recipient = beneficiary_for_operator(recipient);
```

`beneficiary_for_operator` already returns the address itself when no beneficiary is set, so this change is backward-compatible and requires no additional guards. [1](#0-0) 

---

### Proof of Concept

1. **Setup**: Staker S creates a staking contract with operator O1 at 10 % commission. O1 calls `set_beneficiary_for_operator(B)` so all commission should flow to address B.
2. **Accrue rewards**: One epoch passes; the stake pool earns rewards. O1's accrued commission is non-zero.
3. **Switch operator**: S calls `switch_operator(S, O1, O2, 10)`.
   - `distribute_internal(S, O1, contract)` runs — distribution pool is empty, nothing sent.
   - `request_commission_internal(O1, contract)` enqueues `old_operator = O1` in the distribution pool with the full commission amount.
   - The contract is re-keyed to O2.
4. **Lockup expires**: The lockup period ends; the commission becomes inactive/withdrawable.
5. **Distribute**: Anyone calls `distribute(S, O2)`.
   - `distribute_internal(S, O2, contract)` runs.
   - Distribution pool shareholder = O1; `operator` parameter = O2.
   - Guard: `O1 == O2` → false → beneficiary redirect skipped.
   - `aptos_account::deposit_coins(O1, commission)` executes.
6. **Result**: B's balance is unchanged; O1 received the commission that should have gone to B. [8](#0-7)

    fun distribute_internal(
        staker: address,
        operator: address,
        staking_contract: &mut StakingContract,
    ) acquires BeneficiaryForOperator {
        let pool_address = staking_contract.pool_address;
        // Create the Staker resource if it doesn't exist to backfill the Staker resource for each pool.
        if (!exists<Staker>(pool_address)) {
            let pool_signer =
                &account::create_signer_with_capability(&staking_contract.signer_cap);
            move_to(pool_signer, Staker { staker });
        };
        let (_, inactive, _, pending_inactive) = stake::get_stake(pool_address);
        let total_potential_withdrawable = inactive + pending_inactive;
        let coins =
            stake::withdraw_with_cap(
                &staking_contract.owner_cap, total_potential_withdrawable
            );
        let distribution_amount = coin::value(&coins);
        if (distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };

        let distribution_pool = &mut staking_contract.distribution_pool;
        update_distribution_pool(
            distribution_pool,
            distribution_amount,
            operator,
            staking_contract.commission_percentage
        );

        // Buy all recipients out of the distribution pool.
        while (distribution_pool.shareholders_count() > 0) {
            let recipients = distribution_pool.shareholders();
            let recipient = recipients[0];
            let current_shares = distribution_pool.shares(recipient);
            let amount_to_distribute =
                distribution_pool.redeem_shares(recipient, current_shares);
            // If the recipient is the operator, send the commission to the beneficiary instead.
            if (recipient == operator) {
                recipient = beneficiary_for_operator(operator);
            };
            aptos_account::deposit_coins(
                recipient, coin::extract(&mut coins, amount_to_distribute)
            );

            emit(
                Distribute {
                    operator,
                    pool_address,
                    recipient,
                    amount: amount_to_distribute
                }
            );
