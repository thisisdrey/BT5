Confirmed: intents within a `DefuseIntents` batch are executed independently in a loop, with no aggregation of `TokenDiff` deltas across separate `TokenDiff` intents in the same signed payload. `TokenDiff::token_fee` is evaluated per-intent using only that single intent's `delta.unsigned_abs()`, so splitting one net negative delta across multiple `TokenDiff` intents each with `amount == 1` avoids the `amount > 1` fee condition for NEP-245/IMT tokens.### Title
Protocol fee bypassed for NEP-245/IMT tokens via intent splitting across multiple `TokenDiff` intents in one signed `MultiPayload` - (File: `contracts/defuse/core/src/intents/token_diff.rs`)

### Summary
`TokenDiff::execute_intent` computes the fee for each `TokenDiff` intent independently, using only that intent's own `delta.unsigned_abs()` for the `amount > 1` guard in `TokenDiff::token_fee`. Because a signed `MultiPayload`/`DefuseIntents` batch can contain multiple `TokenDiff` intents on the same NEP-245/IMT `token_id`, a signer can split a net negative delta of magnitude `N > 1` into `N` separate `TokenDiff` intents each with `amount == 1`, causing `token_fee` to return `Pips::ZERO` for every one of them and completely bypassing the fee that should be charged on the batch's aggregate negative exposure.

### Finding Description
The binding that should hold is: `fee_collector` credit for token `T` after the batch == `Pips::fee_ceil` applied to the **batch-aggregate** negative delta of `T` for that signer. Instead, the actual code computes fees per-`TokenDiff`-intent.

In `contracts/defuse/core/src/intents/token_diff.rs`, `ExecutableIntent for TokenDiff::execute_intent` iterates only over `self.diff` (the deltas contained in *this single* `TokenDiff` intent): [1](#0-0) 

For each negative delta it calls `Self::token_fee(token_id, amount, protocol_fee).fee_ceil(amount)` where `amount = delta.unsigned_abs()` — scoped to that one intent's delta: [2](#0-1) 

`token_fee` itself only looks at the passed-in `amount` for the single call: [3](#0-2) 

For `TokenIdType::Nep245`/`Imt`, if `amount <= 1` it returns `Pips::ZERO` — no fee at all.

Crucially, `DefuseIntents::execute_intent` and `Intent::execute_intent` process a `Vec<Intent>` (which can contain multiple `TokenDiff` entries) in a simple sequential loop, each intent fully independent, with no cross-intent netting or accumulation of `amount` per `token_id`: [4](#0-3) 

So an attacker signs one `MultiPayload` whose `DefuseIntents.intents` contains two `TokenDiff` intents:
- `TokenDiff { diff: { T: -1, other: +k1 } }`
- `TokenDiff { diff: { T: -1, other: +k2 } }`

Each is evaluated separately: `amount = 1` in both cases, so `token_fee` returns `Pips::ZERO` twice, and `fees_collected` for `T` stays `0` in both intents. The signer's balance in `T` is still reduced by `2` in total (via two separate `internal_apply_deltas` calls), matching what a single `TokenDiff{T: -2}` would produce balance-wise, but the fee that a single-intent `-2` delta would have incurred (`token_fee(..., amount=2, ...).fee_ceil(2)`, non-zero once `protocol_fee > 0`) is never charged.

None of the existing guards catch this: `MultiPayload::verify`, nonce/signature checks, and `Lock`/`TransferMatcher` all operate on balances and authorization, not on fee aggregation; the fee-scoping bug is purely local to `TokenDiff::execute_intent`'s per-intent `amount` computation.

### Impact Explanation
Protocol fees on NEP-245/IMT token diffs are systematically under-collected (down to zero) whenever a signer splits a negative delta ≥ 2 into multiple unit (`amount == 1`) `TokenDiff` intents within one signed batch. This is a direct fee bypass: `fee_collector` receives less (or none) of the value it is entitled to for those swaps, while the signer's counterparties/`other` token credits are computed as if the trade were fee-exempt. This matches the "protocol fees bypassed" Critical impact category. It's repeatable by any signer, on any NEP-245/IMT token id, in any batch, at no additional cost beyond adding intents to the same payload.

### Likelihood Explanation
Preconditions are trivial: any unprivileged account holding ≥2 units of an NEP-245 (or IMT) token id and a counterparty/`other` token to receive can sign one `MultiPayload` with two (or more) `TokenDiff` intents each with `amount == 1` on the same `token_id`. No special roles or relayer keys are needed; this is fully within the described attacker capability (crafting and submitting arbitrary `MultiPayload` batches via `execute_intents`). The exploit is deterministic and repeatable across tokens/accounts.

### Recommendation
Aggregate `TokenDiff` deltas per `token_id` across all `TokenDiff` intents within the same executed batch (e.g., accumulate all negative deltas for each `token_id` signer-wide during `DefuseIntents`/batch execution) before evaluating `TokenDiff::token_fee`'s `amount > 1` condition and computing `fee_ceil`, rather than evaluating fee eligibility per individual `TokenDiff` intent.

impl ExecutableIntent for DefuseIntents {
    fn execute_intent<S, I>(
        self,
        signer_id: &AccountIdRef,
        engine: &mut Engine<S, I>,
        intent_hash: [u8; 32],
    ) -> Result<()>
    where
        S: State,
        I: Inspector,
    {
        for intent in self.intents {
            intent.execute_intent(signer_id, engine, intent_hash)?;
        }
        Ok(())
    }
}

impl ExecutableIntent for Intent {
    fn execute_intent<S, I>(
        self,
        signer_id: &AccountIdRef,
        engine: &mut Engine<S, I>,
        intent_hash: [u8; 32],
    ) -> Result<()>
    where
        S: State,
        I: Inspector,
    {
        match self {
            Self::AddPublicKey(intent) => intent.execute_intent(signer_id, engine, intent_hash),
            Self::RemovePublicKey(intent) => intent.execute_intent(signer_id, engine, intent_hash),
            Self::Transfer(intent) => intent.execute_intent(signer_id, engine, intent_hash),
            Self::FtWithdraw(intent) => intent.execute_intent(signer_id, engine, intent_hash),
            Self::NftWithdraw(intent) => intent.execute_intent(signer_id, engine, intent_hash),
            Self::MtWithdraw(intent) => intent.execute_intent(signer_id, engine, intent_hash),
            Self::NativeWithdraw(intent) => intent.execute_intent(signer_id, engine, intent_hash),
            Self::StorageDeposit(intent) => intent.execute_intent(signer_id, engine, intent_hash),
            Self::TokenDiff(intent) => intent.execute_intent(signer_id, engine, intent_hash),
            Self::SetAuthByPredecessorId(intent) => {
                intent.execute_intent(signer_id, engine, intent_hash)
            }
            Self::AuthCall(intent) => intent.execute_intent(signer_id, engine, intent_hash),
            #[cfg(feature = "imt")]
            Self::ImtMint(intent) => intent.execute_intent(signer_id, engine, intent_hash),
            #[cfg(feature = "imt")]
            Self::ImtBurn(intent) => intent.execute_intent(signer_id, engine, intent_hash),
        }
    }
}
