### Title
Malformed calldata to the `ValidateMultiSign` TVM precompile causes an uncaught exception when TIP-854/Osaka is not active - (File: actuator/src/main/java/org/tron/core/vm/PrecompiledContracts.java)

### Summary
The GD Graphics Library CVE describes a crafted-input parser that reads fixed offsets/lengths out of an untrusted buffer without validating that the buffer is large enough, causing an out-of-bounds read and a crash. The same bug class — decoding fixed-offset/length-prefixed fields from attacker-controlled bytes without a length precheck — exists in java-tron's `ValidateMultiSign` precompiled contract, which any contract deployer/caller can reach via a `CALL`/`STATICCALL` to its fixed address from Solidity contract code.

### Finding Description
`ValidateMultiSign` is a TVM precompiled contract (address exposed via `PrecompiledContracts.getContractForAddress`, gated by `VMConfig.allowTvmSolidity059()`) that decodes calldata using assumed fixed head/tail word layout (`H` head words + `I` words per signature entry) before performing signature verification [1](#0-0) . A dedicated test explicitly documents that prior to TIP-854/Osaka activation, this decoder has **no outer catch**, and malformed (too-short or misaligned) calldata causes the decoder itself to throw a `RuntimeException` while parsing fixed offsets — this is the "pre-activation failure mode the TIP explicitly preserves": [2](#0-1) 

The equivalent `BatchValidateSign` contract shows the same class of bug and the same pre-Osaka gap: a companion test (`testTip854RejectsMalformedCalldata`) only asserts the safe rejection behavior *after* `VMConfig.initAllowTvmOsaka(1)` is enabled, i.e. the guard is a new addition and not the historical behavior [3](#0-2) . This mirrors the TGA `read_header_tga` bug class: header-driven, fixed-offset parsing of attacker-supplied bytes without an upfront total-length/bounds check, deferring bounds enforcement to per-field array accesses that throw once calldata is shorter than the offsets assume.

Both `ValidateMultiSign` and `BatchValidateSign` are reachable from an unprivileged contract call: any deployed contract can `CALL` these fixed precompile addresses with attacker-controlled `data`, and any externally-owned account can trigger this by calling into such a contract with a crafted transaction.

### Impact Explanation
When the exception escapes uncaught (pre-Osaka/legacy path, which is the default unless `allowTvmSolidity059`'s successor flag `allowTvmOsaka` is enabled), a `RuntimeException` propagates out of `execute()`. Depending on how the caller (outer `CALL` opcode handling in `Program`/`OperationActions.callToPrecompiledAddress`) handles exceptions bubbling from a precompile's `execute()`, this can either (a) cause the enclosing transaction to abort with an unexpected internal error rather than a clean revert, or (b) in the worst case escape the per-transaction execution sandbox and disrupt block processing/node availability, since this is not a graceful `Program.Exception` but a raw `RuntimeException` from array/offset arithmetic. The `testTip854OuterFrameContainment` test suite that verifies the outer CALL frame stays clean and exception-free is scoped explicitly to the **post**-Osaka guarded path [4](#0-3) , implying the pre-activation path lacks this containment guarantee. This is a Medium-severity DoS analog: an unprivileged transaction/contract caller can trigger an unhandled exception mid-VM-execution using nothing but a short byte array as calldata to a fixed, always-reachable precompile address.

### Likelihood Explanation
Likelihood is high for triggering the malformed-input condition itself (trivial — any short/misaligned byte array as calldata), but the resulting *impact* depends on whether `allowTvmOsaka`/TIP-854 is active on the target network. On networks/chain configurations where this proposal has not yet activated, the vulnerable legacy decode path is live and reachable by any contract call, requiring no special privilege — only a signed transaction invoking a `CALL` to the fixed precompile address with attacker-chosen bytes.

### Recommendation
- Ensure the same input-shape validation guard added for TIP-854 (checking `data.length` against the assumed head/tail word layout before any offset-based `System.arraycopy`/field extraction) is unconditionally enforced in `ValidateMultiSign`/`BatchValidateSign`, independent of the `allowTvmOsaka` feature flag, or backport the check to all supported protocol versions.
- Wrap the legacy decode path in a try/catch that maps any parsing failure to `Pair.of(false, EMPTY_BYTE_ARRAY)` consistent with the "precompile must not throw" invariant now documented for the post-activation code, matching the containment behavior already verified for the guarded path in `OperationsTest.testTip854OuterFrameContainment`.
- Audit other precompiles with fixed-offset `System.arraycopy` calls over attacker data (e.g., `VerifyMintProof`, `VerifyTransferProof` in the same file) to confirm they perform an exact-length check before offset arithmetic — several already do (`data.length != SIZE`), but any that infer offsets from data-derived counts (as `VerifyTransferProof` does with `spendCount`/`receiveCount`) should be re-verified for bounds enforcement before every `arraycopy`.

### Proof of Concept
1. Deploy or call any contract capable of issuing a raw `CALL`/`STATICCALL` (or use a test harness as in `ValidateMultiSignContractTest`) targeting the `ValidateMultiSign` precompile address on a chain where `allowTvmOsaka` is not yet enabled.
2. Supply calldata shorter than `(5 + 1) * 32` bytes (i.e., fewer than the assumed head words), for example `new byte[(5 + 1) * 32]` truncated or misaligned as done in `testTip854PreActivationNoOp`.
3. Observe that `contract.execute(data)` throws a `RuntimeException` from within the offset-based decoder rather than returning `Pair.of(false, EMPTY_BYTE_ARRAY)`, as confirmed by the test's own comment: "a too-short input raises inside the decoder; that is the documented pre-activation failure mode" [5](#0-4) .

Note: I was unable to view the exact body of `ValidateMultiSign.execute()`/its internal decoder within the size limits of this session (only the surrounding test file and the dispatch table in `getContractForAddress` were retrievable in full); a Devin session with full file access would be needed to pinpoint the exact line(s) performing the unchecked `arraycopy`/offset math and to confirm precisely how the resulting exception propagates through `Program.callToPrecompiledAddress`.

  // TIP-854: after activation, batchValidateSign (H=5, I=6) must reject calldata
  // whose byte length is incompatible with the (words - 5) / 6 shape the per-call
  // energy formula already assumes, returning (false, empty). The guard lives in
  // doExecute(); the outer try/catch does not mask it because the guard does not
  // throw (pure arithmetic + a static getter).
  @Test
  public void testTip854RejectsMalformedCalldata() {
    contract.setVmShouldEndInUs(System.nanoTime() / 1000 + 2_000_000);
    VMConfig.initAllowTvmOsaka(1);
    try {
      // Bucket 1: 32-aligned head + sub-word trailing bytes (r=1, r=31).
      for (int r : new int[]{1, 31}) {
        byte[] data = new byte[(5 + 6) * 32 + r];
        Pair<Boolean, byte[]> ret = contract.execute(data);
        Assert.assertFalse("non-32-aligned len=" + data.length, ret.getLeft());
        Assert.assertSame(ByteUtil.EMPTY_BYTE_ARRAY, ret.getRight());
      }
      // Bucket 2: fewer than the static head's 5 words.
      for (int bytes : new int[]{0, 32, 64, 96, 128}) {
        Pair<Boolean, byte[]> ret = contract.execute(new byte[bytes]);
        Assert.assertFalse("len=" + bytes + " < 5 words", ret.getLeft());
        Assert.assertSame(ByteUtil.EMPTY_BYTE_ARRAY, ret.getRight());
      }
      // Bucket 3: 32-aligned but tail not a multiple of I=6 words (k = 1..5).
      for (int k = 1; k <= 5; k++) {
        byte[] data = new byte[(5 + k) * 32];
        Pair<Boolean, byte[]> ret = contract.execute(data);
        Assert.assertFalse("aligned bad-tail k=" + k, ret.getLeft());
        Assert.assertSame(ByteUtil.EMPTY_BYTE_ARRAY, ret.getRight());
      }
      // Null calldata: explicit spec clause.
      Pair<Boolean, byte[]> ret = contract.execute(null);
      Assert.assertFalse("null calldata", ret.getLeft());
      Assert.assertSame(ByteUtil.EMPTY_BYTE_ARRAY, ret.getRight());
    } finally {
      VMConfig.initAllowTvmOsaka(0);
    }

  // batchValidateSign with malformed calldata must (a) push 0 onto the outer
  // stack, (b) leave the outer frame free of any propagated exception, and
  // (c) allow the outer frame to continue executing afterwards.
  @Test
  public void testTip854OuterFrameContainment() throws ContractValidateException {
    byte prePrefixByte = DecodeUtil.addressPreFixByte;
    DecodeUtil.addressPreFixByte = Constant.ADD_PRE_FIX_BYTE_MAINNET;
    VMConfig.initAllowTvmOsaka(1);
    try {
      for (PrecompiledContracts.PrecompiledContract contract :
          new PrecompiledContracts.PrecompiledContract[]{
              new PrecompiledContracts.ValidateMultiSign(),
              new PrecompiledContracts.BatchValidateSign()}) {
        invoke = new ProgramInvokeMockImpl();
        InternalTransaction interTrx = new InternalTransaction(
            Protocol.Transaction.getDefaultInstance(),
            InternalTransaction.TrxType.TRX_UNKNOWN_TYPE);
        program = new Program(new byte[0], new byte[0], invoke, interTrx);
        // inDataSize=0 ⇒ data=[] ⇒ fewer than H=5 head words ⇒ guard rejects.
        MessageCall messageCall = new MessageCall(
            Op.CALL, new DataWord(10000),
            DataWord.ZERO(), DataWord.ZERO(),
            DataWord.ZERO(), DataWord.ZERO(),
            DataWord.ZERO(), DataWord.ZERO(),
            DataWord.ZERO(), false);
        program.callToPrecompiledAddress(messageCall, contract);

        Assert.assertNull(contract.getClass().getSimpleName()
                + ": outer frame must not inherit an exception",
            program.getResult().getException());
        Assert.assertEquals(contract.getClass().getSimpleName() + ": inner CALL pushes 0",
            DataWord.ZERO(), program.getStack().pop());
        // Outer frame continues: another stack op works without throwing.
        program.stackPush(new DataWord(1));
        Assert.assertEquals(new DataWord(1), program.getStack().pop());

      VMConfig.initAllowTvmOsaka(0);
