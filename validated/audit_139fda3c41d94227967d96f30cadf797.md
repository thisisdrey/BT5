### Title
Splitting a token delta across multiple `TokenDiff` intents in one signed payload bypasses the NFT/MT fee-exemption threshold, causing protocol fees to be under-collected - (File: contracts/defuse/core/src/intents/token_diff.rs)

### Summary
`TokenDiff::execute_intent` computes and waives fees strictly per-intent, based on the magnitude of the delta declared inside that single `TokenDiff` (`Self::token_fee(token_id, amount, protocol_fee)`), rather than on the net delta of a `TokenId` across the whole batch/payload. Because `DefuseIntents` allows a signer to bundle an arbitrary list of `Intent`s (including several `TokenDiff`s on the same `TokenId`) under one signature, an attacker can split any Nep245/Imt outflow into a sequence of `delta = -1` `TokenDiff` intents, each of which independently satisfies the `amount <= 1` fee-exemption rule, letting arbitrarily large negative deltas on that token id escape fees entirely.

### Finding Description
The intended binding (as documented by the code comment "do not take fees on NFTs and MTs with `|delta| <= 1`") is that a fee should apply whenever the true amount moving out of the signer's account for a token exceeds 1 unit. The actual binding implemented is:

`fee_for_intent = Pips::token_fee(token_id, |delta_in_this_TokenDiff|, protocol_fee).fee_ceil(|delta_in_this_TokenDiff|)`

evaluated once per `TokenDiff::execute_intent` call [1](#0-0) , and the exemption itself: [2](#0-1) 

The exemption is keyed on the `amount` local to that single intent's delta, not on the net/aggregate delta for the `TokenId` across all `TokenDiff`s executed for that signer in the batch. `DefuseIntents` permits a signer to submit an arbitrary `Vec<Intent>` in one signed `MultiPayload` [3](#0-2) , and each `Intent::TokenDiff` is dispatched to `TokenDiff::execute_intent` independently, so an attacker holding `N` units of a Nep245/Imt token can encode `N` separate `TokenDiff` intents, each with `diff = { T: -1, ... }`, in one signature. Each call sees `amount = 1`, hits the `TokenIdType::Nep245 | TokenIdType::Imt` branch with `amount <= 1`, and returns `Pips::ZERO`, so `fees_collected` for `T` accumulates `0` per intent instead of the `fee_ceil` that would have applied had the same `-N` delta been declared in a single `TokenDiff`. No other guard (`MultiPayload::verify`, `has_public_key`, nonce checks, `TransferMatcher::finalize`) inspects or aggregates fees across intents in the same payload/batch — those mechanisms only prevent double-signing/double-spend, not fee-splitting.

### Impact Explanation
The fee collector (`engine.state.fee_collector()`) receives strictly less than `Pips::fee_ceil` on the true negative delta of a Nep245/Imt token whenever the delta is split into unit-sized `TokenDiff` intents. This is a direct, repeatable, protocol-fee-bypass: any signer can zero out fees on arbitrarily large Nep245/Imt token outflows simply by restructuring their own signed intent list, with no extra signatures, no counterparty cooperation beyond normal matching, and no additional on-chain cost beyond marginally larger payload size/gas. This matches the "protocol fees bypassed" Critical category since it is value (fee revenue) that never reaches `fee_collector` despite genuine token outflow from the signer's Verifier balance.

### Likelihood Explanation
Preconditions are minimal: the attacker only needs a Nep245 (or Imt) balance in the Verifier and the ability to construct their own `DefuseIntents`/`MultiPayload` (fully within an unprivileged signer's normal capability). No role, relayer key, or victim key is required. The attack is trivially repeatable across any Nep245/Imt token and any batch, and scales with the number of unit-delta intents included, so cost to the attacker (extra payload size) is negligible.

### Recommendation
Compute and net the fee-exemption threshold per `TokenId` across the whole batch (i.e., aggregate all `TokenDiff` deltas for the same signer/token before applying the `amount <= 1` NFT/MT exemption), rather than per individual `TokenDiff` intent. Alternatively, restrict the `amount <= 1` exemption to intents whose underlying token amount granularity is provably 1 (true NFTs), and always charge fees on Nep245/Imt deltas above a cumulative per-signer/per-batch threshold, or disallow multiple `TokenDiff` intents on the same `TokenId` from the same signer within a batch.

### Proof of Concept
`cargo test` plan (near-workspaces sandbox), added under `tests/src/tests/defuse/intents/token_diff.rs`:
1. Deploy Verifier contract with `protocol_fee > 0` and a Nep245 token contract; deposit 2 units of a Nep245 `TokenId` `T` to `user`.
2. Sign a single `MultiPayload` from `user` containing `DefuseIntents { intents: [TokenDiff{diff: {T: -1}}, TokenDiff{diff: {T: -1}}] }` (plus any balancing positive-delta counterparty intent needed to satisfy `TransferMatcher::finalize`, e.g. a second signer routing `+2` of `T` elsewhere, or wrap both `TokenDiff`s for the same signer against a matching solver as in existing `simulate_token_diff_intent` pattern).
3. Call `execute_intents` with this payload.
4. Assert `mt_balance_of(fee_collector, T) == 0` even though `user`'s balance of `T` decreased by 2, i.e., `fees_collected(T) == Pips::ZERO + Pips::ZERO != Pips::fee_ceil(2)`.
5. Contrast with a control test where the same `-2` delta is declared in a single `TokenDiff{diff: {T: -2}}`, asserting `mt_balance_of(fee_collector, T) == Pips::fee_ceil(2) > 0`, demonstrating the divergence caused purely by splitting the same net delta across two intents in one signed payload.

impl ExecutableIntent for Intent {
    fn execute_intent<S, I>(
        self,
        signer_id: &AccountIdRef,
        engine: &mut Engine<S, I>,
        intent_hash: [u8; 32],
    ) -> Result<()>
    where
        S: State,
        I: Inspector,
    {
        match self {
            Self::AddPublicKey(intent) => intent.execute_intent(signer_id, engine, intent_hash),
            Self::RemovePublicKey(intent) => intent.execute_intent(signer_id, engine, intent_hash),
            Self::Transfer(intent) => intent.execute_intent(signer_id, engine, intent_hash),
            Self::FtWithdraw(intent) => intent.execute_intent(signer_id, engine, intent_hash),
            Self::NftWithdraw(intent) => intent.execute_intent(signer_id, engine, intent_hash),
            Self::MtWithdraw(intent) => intent.execute_intent(signer_id, engine, intent_hash),
            Self::NativeWithdraw(intent) => intent.execute_intent(signer_id, engine, intent_hash),
            Self::StorageDeposit(intent) => intent.execute_intent(signer_id, engine, intent_hash),
            Self::TokenDiff(intent) => intent.execute_intent(signer_id, engine, intent_hash),
            Self::SetAuthByPredecessorId(intent) => {
                intent.execute_intent(signer_id, engine, intent_hash)
            }
            Self::AuthCall(intent) => intent.execute_intent(signer_id, engine, intent_hash),
            #[cfg(feature = "imt")]
            Self::ImtMint(intent) => intent.execute_intent(signer_id, engine, intent_hash),
            #[cfg(feature = "imt")]
            Self::ImtBurn(intent) => intent.execute_intent(signer_id, engine, intent_hash),
        }
    }
}
