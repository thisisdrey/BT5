### Title
Relay control messages accept an attacker-supplied `RelayFromAddr` without binding it to the authenticated sender's certificate identity - ([File: relay_manager.go])

### Summary
`relayManager.HandleControlMsg` and `handleCreateRelayRequest`/`handleCreateRelayResponse` build relay state and reply to `CreateRelayRequest`/`CreateRelayResponse` control messages using the `RelayFromAddr`/`RelayToAddr` fields taken directly from the (already-decrypted, but attacker-controllable payload) `NebulaControl` message, without ever verifying that the claimed `RelayFromAddr` equals the actual, certificate-verified VPN address of the peer (`h.vpnAddrs[0]`) that sent the message over the authenticated tunnel.

### Finding Description
`HandleControlMsg` is invoked with `h *HostInfo`, which is the already-authenticated peer whose identity was fixed during the Noise/cert handshake (`h.vpnAddrs`). However, when dispatching to `handleCreateRelayRequest`/`handleCreateRelayResponse`, the code trusts `m.RelayFromAddr`/`m.RelayToAddr` — fields fully controlled by the sender inside the message body — as the source-of-truth for "who is asking to relay from where": [1](#0-0) 

Inside `handleCreateRelayRequest`, `from` is derived solely from the message field and is only checked against `f.myVpnAddrsTable` (is it me?) and `f.myVpnAddrsTable.Contains(target)` (am I the target?). There is no check `from == h.vpnAddrs[0]`: [2](#0-1) 

This is structurally the same bug class as the `buyLoan` report: a function mutates protocol state (there, `pools[poolId]`/loan ownership; here, `HostMap.Relays`, `relayState` tables, and `AddRelay`) based on a caller-supplied identifier (there, `poolId`/pool token config; here, `RelayFromAddr`/`RelayToAddr`) instead of verifying that identifier matches the entity that is cryptographically authorized to make the claim (there, the real pool owner and the loan's actual tokens; here, the authenticated peer `h`'s real VPN identity). Because `AddRelay` and the various `relayState` mutation helpers (`InsertRelay`, `CompleteRelayByIdx`, `UpdateRelayForByIpState`) are keyed off attacker-supplied `from`/`target` values, a malicious but validly-certificated peer `h` could claim `RelayFromAddr` = some other real node's VPN address, causing the relay/forwarding node to install relay routing state associating `h`'s tunnel with a spoofed VPN identity it does not own.

### Impact Explanation
An authenticated peer can poison relay routing state on a forwarder/terminal relay node by asserting an arbitrary `RelayFromAddr` that isn't its own verified VPN address, similar to how the `buyLoan` bug let an attacker inject unverified identifiers into privileged state transitions. This can misdirect relayed traffic (forwarding relay entries keyed by spoofed `from`) or create relay table entries inconsistent with actual certificate identity, undermining the "mutually authenticated" guarantee Nebula's relay layer is supposed to provide on top of the underlying handshake.

### Likelihood Explanation
Reachable by any peer that has completed a normal handshake and is allowed to relay (`use_relays`/`am_relay`) — no CA-signed certificate forgery is required, only a standard valid certificate for the attacking node itself, and no additional privilege is needed to send `Control`/`CreateRelayRequest` messages once a tunnel exists.

### Recommendation
In `handleCreateRelayRequest` and `handleCreateRelayResponse` (and `HandleControlMsg`'s dispatch), verify that `RelayFromAddr` (or `OldRelayFromAddr`) equals one of `h.vpnAddrs` — the certificate-verified identity of the authenticated sender — before using it to install or update `Relay`/`relayState` entries, mirroring how `buyLoan` should have checked `pools[poolId].lender == msg.sender` and token compatibility before mutating pool/loan state.

### Proof of Concept
Not runnable without the full harness; conceptually: peer `A` establishes a normal authenticated tunnel to relay node `R` (its real identity is `A`'s cert VPN IP). `A` sends a `CreateRelayRequest` control message with `RelayFromAddr` set to `B`'s VPN address (some other real node) and `RelayToAddr` set to `victim`. `handleCreateRelayRequest` on `R` processes this using `from = B`, `target = victim`, entering the branch that assumes `victim` is `R` itself, and calls `AddRelay(..., from, ...)` — installing relay state associating `B` (not `A`) with the relay-to-`victim` path, entirely based on `A`'s unverified claim. func (rm *relayManager) HandleControlMsg(h *HostInfo, d []byte, f *Interface) {
	msg := &NebulaControl{}
	err := msg.Unmarshal(d)
	if err != nil {
		h.logger(f.l).Error("Failed to unmarshal control message", "error", err)
		return
	}

	var v cert.Version
	if msg.OldRelayFromAddr > 0 || msg.OldRelayToAddr > 0 {
		v = cert.Version1

		b := [4]byte{}
		binary.BigEndian.PutUint32(b[:], msg.OldRelayFromAddr)
		msg.RelayFromAddr = netAddrToProtoAddr(netip.AddrFrom4(b))

		binary.BigEndian.PutUint32(b[:], msg.OldRelayToAddr)
		msg.RelayToAddr = netAddrToProtoAddr(netip.AddrFrom4(b))
	} else {
		v = cert.Version2
	}

	// validate:
	switch msg.Type {
	case NebulaControl_CreateRelayRequest, NebulaControl_CreateRelayResponse:
		if msg.RelayFromAddr == nil {
			if f.l.Enabled(context.Background(), slog.LevelDebug) {
				h.logger(f.l).Debug("Control message received with nil RelayFromAddr", "type", msg.Type)
			}
			return
		} else if msg.RelayToAddr == nil {
			if f.l.Enabled(context.Background(), slog.LevelDebug) {
				h.logger(f.l).Debug("Control message received with nil RelayToAddr", "type", msg.Type)
			}
			return
		}
	}

	switch msg.Type {
	case NebulaControl_CreateRelayRequest:
		rm.handleCreateRelayRequest(v, h, f, msg)
	case NebulaControl_CreateRelayResponse:
		rm.handleCreateRelayResponse(v, h, f, msg)
	}
}

func (rm *relayManager) handleCreateRelayRequest(v cert.Version, h *HostInfo, f *Interface, m *NebulaControl) {
	//nil-checks for protoAddrToNetAddr handled by caller
	from := protoAddrToNetAddr(m.RelayFromAddr)
	target := protoAddrToNetAddr(m.RelayToAddr)

	logMsg := rm.l.With(
		"relayFrom", from,
		"relayTo", target,
		"initiatorRelayIndex", m.InitiatorRelayIndex,
		"vpnAddrs", h.vpnAddrs,
	)

	logMsg.Info("handleCreateRelayRequest")
	// Is the source of the relay me? This should never happen, but did happen due to
	// an issue migrating relays over to newly re-handshaked host info objects.
	if f.myVpnAddrsTable.Contains(from) {
		logMsg.Error("Discarding relay request from myself", "myIP", from)
		return
	}

	// Is the target of the relay me?
	if f.myVpnAddrsTable.Contains(target) {
		existingRelay, ok := h.relayState.QueryRelayForByIp(from)
		if ok {
			switch existingRelay.State {
			case Requested:
				ok = h.relayState.CompleteRelayByIP(from, m.InitiatorRelayIndex)
				if !ok {
					logMsg.Error("Relay State not found")
					return
				}
			case Established:
				if existingRelay.RemoteIndex != m.InitiatorRelayIndex {
					// We got a brand new Relay request, because its index is different than what we saw before.
					// This should never happen. The peer should never change an index, once created.
					logMsg.Error("Existing relay mismatch with CreateRelayRequest",
						"existingRemoteIndex", existingRelay.RemoteIndex)
					return
				}
			case Disestablished:
				if existingRelay.RemoteIndex != m.InitiatorRelayIndex {
					// We got a brand new Relay request, because its index is different than what we saw before.
					// This should never happen. The peer should never change an index, once created.
					logMsg.Error("Existing relay mismatch with CreateRelayRequest",
						"existingRemoteIndex", existingRelay.RemoteIndex)
					return
				}
				// Mark the relay as 'Established' because it's safe to use again
				h.relayState.UpdateRelayForByIpState(from, Established)
			case PeerRequested:
				// I should never be in this state, because I am terminal, not forwarding.
				logMsg.Error("Unexpected Relay State found",
					"existingRemoteIndex", existingRelay.RemoteIndex,
					"state", existingRelay.State)
			}
		} else {
			_, err := AddRelay(rm.l, h, f.hostMap, from, &m.InitiatorRelayIndex, TerminalType, Established)
			if err != nil {
				logMsg.Error("Failed to add relay", "error", err)
				return
			}
		}

		relay, ok := h.relayState.QueryRelayForByIp(from)
		if !ok {
			logMsg.Error("Relay State not found", "from", from)
			return
