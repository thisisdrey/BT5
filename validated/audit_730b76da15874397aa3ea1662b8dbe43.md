### Title
Deferred `deleteContract()` in `TransactionTrace.finalization()` destroys accounts/contracts recreated at the same address after SELFDESTRUCT within the same transaction - ([File: chainbase/src/main/java/org/tron/core/db/TransactionTrace.java])

### Summary
`Program.suicide()` (the legacy, non-restricted SELFDESTRUCT path, used when `VMConfig.allowTvmSelfdestructRestriction()` is not enforced) records the destructed address into `ProgramResult.deleteAccounts` [1](#0-0) . This list is only consumed once, at the very end of the whole top-level transaction, in `TransactionTrace.finalization()`, which unconditionally wipes the account/code/abi/contract store entries for every address ever added to `deleteAccounts` during the transaction's execution [2](#0-1) . Because the check happens only after all internal calls/`CREATE`/`CREATE2` have already run and been committed via `rootRepository.commit()` in `VMActuator` [3](#0-2) , an address that self-destructs and is then legitimately re-deployed to (via `CREATE2` at a deterministic, colliding address) within the same transaction still gets deleted at finalization, erasing the freshly created contract's balance, code, ABI and account row.

### Finding Description
The delete-on-finalization design assumes an address in `deleteAccounts` is dead for the remainder of the transaction, but nothing prevents that same address from being reused by a subsequent `CREATE`/`CREATE2` in the same transaction:

1. `suicideAction`/`suicide()` marks the contract self-destructed and appends its address to the deferred delete set: `getContractState().markSelfDestruct(owner); getResult().addDeleteAccount(this.getContractAddress());` [4](#0-3) .
2. Execution continues in the same top-level transaction. A later internal call (e.g. from a factory contract) performs `CREATE2` at that exact same address (deterministic address derivation makes this reachable by any deployer who controls the salt/init-code), depositing new balance, code and storage there.
3. `VM.play()`/`VMActuator` finishes the whole call tree and calls `rootRepository.commit()`, which persists the *new* contract's account, code and storage into the underlying stores [3](#0-2) .
4. `TransactionTrace.finalization()` then iterates the *entire transaction's* `getDeleteAccounts()` set and calls `deleteContract(address)`, which does `abiStore.delete(address); codeStore.delete(address); accountStore.delete(address); contractStore.delete(address);` directly against the persisted stores [5](#0-4) .

Because step 4 has no knowledge of, or check against, the fact that the address was recreated in step 2/3, it deletes the newly deployed (and just-committed) contract account — including any TRX balance sent to it during recreation — rather than the stale, already-destructed one. This is functionally the same bug class as the kernel `tc_new_tfilter` UAF: a deferred cleanup operation acts on a stale reference/identity (the address) after the underlying object it originally pointed to has been freed and a *new* object has been allocated in its place, and the cleanup destroys the new object instead of being scoped to the one it was originally meant for.

Note that `Program.suicide2()` (used when `VMConfig.allowTvmSelfdestructRestriction()` is active, i.e. EIP‑6780‑style semantics) only calls `getResult().addDeleteAccount(...)` implicitly through `suicide()` when `isNewContract(owner)` is true, and otherwise just marks self-destruct without deleting [6](#0-5) . This narrows — but does not eliminate — the reachable window: the vulnerable full-delete path is exercised whenever the chain has not (yet) activated `allowTvmSelfdestructRestriction`, or whenever the destroyed contract is itself "new" in the current transaction (created-then-destroyed-then-recreated all within one transaction is exactly the scenario that triggers `addDeleteAccount`).

### Impact Explanation
Any unprivileged contract deployer/caller can construct a single transaction that: (a) triggers SELFDESTRUCT on a contract address, and (b) redeploys a funded contract to the same address via `CREATE2` later in the same transaction. Once the transaction finalizes, the redeployed contract's account (and its balance, code, storage entries reachable through the account) is deleted from the persistent stores even though it was validly created and committed. This results in:
- Permanent loss/freezing of funds sent to the recreated contract (the TRX transferred to fund the new deployment is credited to the account during commit, then the account record is erased — funds become unaccounted/unbacked in the ledger).
- Corruption of a live contract's on-chain state/code without any subsequent transaction being able to interact with it (deployment silently vanishes), which can be leveraged to defraud counterparties who observed a successful deployment/funding within the same transaction (e.g., wallets, exchanges, or other contracts relying on the recreated contract's persisted balance).

### Likelihood Explanation
The trigger requires only a single, unprivileged, self-crafted transaction (a factory-style contract) that self-destructs and then `CREATE2`s a replacement at the same address — well within reach of any transaction broadcaster/contract deployer with no special privileges, matching the required threat model. It does depend on `allowTvmSelfdestructRestriction` not fully blocking the delete path for the specific scenario (destroy-then-recreate of a contract that is "new" within the transaction, which is exactly the case `isNewContract` is designed to catch and still route through `suicide()`/`addDeleteAccount`), so likelihood is tied to that fork/parameter configuration and to being able to reliably produce an address collision via `CREATE2` — both of which are attacker-controlled and achievable off-chain before submission.

### Recommendation
`TransactionTrace.finalization()`/`deleteContract()` should not perform address-keyed deletion based solely on a set collected before/at the end of the transaction; it must check whether the address was recreated (i.e., whether `Repository.isNewContract(address)` remains true and the account currently committed at that address post-dates the self-destruct event) before deleting, or the deletion should be applied immediately/atomically within the same repository frame as the SELFDESTRUCT rather than deferred to the top-level transaction finalization. At minimum, before calling `deleteContract(address)` in `TransactionTrace.finalization()`, re-verify that the current `accountStore`/`contractStore` entry for that address is still the one that existed at self-destruct time (e.g., by comparing a stored snapshot/version or checking that no `CREATE`/`CREATE2` has re-populated it after the self-destruct in the same transaction).

### Proof of Concept
1. Deploy a `Factory` contract `F`.
2. From `F`, call `create2(0, initCode, salt)` to deploy contract `C` at deterministic address `A`, sending it `X` TRX.
3. Still within the *same* top-level transaction (e.g., via `F`'s constructor/fallback orchestrating multiple internal calls, or by having `C` self-destruct and be redeployed inside one call chain triggered by a single external transaction):
   a. Call `C.selfdestruct(beneficiary)` — this appends `A` to `ProgramResult.deleteAccounts` via `Program.suicide()` [4](#0-3) .
   b. Call `F.create2(...)` again with the same `salt`/`initCode` to redeploy `C` at the same address `A`, funding it with `Y` TRX.
4. Submit the single transaction containing steps 2–3b.
5. After the transaction is applied, inspect `accountStore.get(A)` / `contractStore.get(A)`: `TransactionTrace.finalization()` will have called `deleteContract(A)` [2](#0-1) [5](#0-4) , erasing the newly-committed `C` and the `Y` TRX that was just deposited into it, despite `C` having been successfully redeployed and funded in the same transaction.

(Because full step-through of the `CREATE2` address-derivation and `VMConfig.allowTvmSelfdestructRestriction` fork-gating code paths could not be exhaustively traced in this session, the exact fork-activation conditions under which `suicide()` vs. `suicide2()` is invoked for a "destroy-then-recreate-in-same-tx" contract should be independently confirmed by a Devin session with full repository access before treating this as fully proven on the current mainnet configuration.)

  public void suicide(DataWord obtainerAddress) {

    byte[] owner = getContextAddress();
    byte[] obtainer = obtainerAddress.toTronAddress();

    if (VMConfig.allowTvmVote()) {
      withdrawRewardAndCancelVote(owner, getContractState());
    }

    long balance = getContractState().getBalance(owner);

    if (logger.isDebugEnabled()) {
      logger.debug("Transfer to: [{}] heritage: [{}]",
          Hex.toHexString(obtainer),
          balance);
    }

    increaseNonce();

    InternalTransaction internalTx = addInternalTx(null, owner, obtainer, balance, null,
        "suicide", nonce, getContractState().getAccount(owner).getAssetMapV2());

    int ADDRESS_SIZE = VMUtils.getAddressSize();
    if (FastByteComparisons.compareTo(owner, 0, ADDRESS_SIZE, obtainer, 0, ADDRESS_SIZE) == 0) {
      // if owner == obtainer just zeroing account according to Yellow Paper
      getContractState().addBalance(owner, -balance);
      byte[] blackHoleAddress = getContractState().getBlackHoleAddress();
      if (VMConfig.allowTvmTransferTrc10()) {
        getContractState().addBalance(blackHoleAddress, balance);
        MUtil.transferAllToken(getContractState(), owner, blackHoleAddress);
      }
    } else {
      createAccountIfNotExist(getContractState(), obtainer);
      try {
        MUtil.transfer(getContractState(), owner, obtainer, balance);
        if (VMConfig.allowTvmTransferTrc10()) {
          MUtil.transferAllToken(getContractState(), owner, obtainer);
        }
      } catch (ContractValidateException e) {
        if (VMConfig.allowTvmConstantinople()) {
          throw new TransferException(
              "transfer all token or transfer all trx failed in suicide: %s", e.getMessage());
        }
        throw new BytecodeExecutionException("transfer failure");
      }
    }
    if (VMConfig.allowTvmFreeze()) {
      byte[] blackHoleAddress = getContractState().getBlackHoleAddress();
      if (FastByteComparisons.isEqual(owner, obtainer)) {
        transferDelegatedResourceToInheritor(owner, blackHoleAddress, getContractState());
      } else {
        transferDelegatedResourceToInheritor(owner, obtainer, getContractState());
      }
    }
    if (VMConfig.allowTvmFreezeV2()) {
      byte[] Inheritor =
          FastByteComparisons.isEqual(owner, obtainer)
              ? getContractState().getBlackHoleAddress()
              : obtainer;
      long expireUnfrozenBalance = transferFrozenV2BalanceToInheritor(owner, Inheritor, getContractState());
      if (expireUnfrozenBalance > 0 && internalTx != null) {
        internalTx.setValue(internalTx.getValue() + expireUnfrozenBalance);
      }
    }

    getContractState().markSelfDestruct(owner);
    getResult().addDeleteAccount(this.getContractAddress());
  }

  public void suicide2(DataWord obtainerAddress) {
    byte[] owner = getContextAddress();

    if (getContractState().isSelfDestructed(obtainerAddress.toTronAddress())) {
      MUtil.checkCPUTimeForSelfDestructedBeneficiary();
    }

    boolean isNewContract = getContractState().isNewContract(owner);
    if (isNewContract) {
      suicide(obtainerAddress);
      return;
    }

    byte[] obtainer = obtainerAddress.toTronAddress();

    long balance = getContractState().getBalance(owner);

    if (logger.isDebugEnabled()) {
      logger.debug("Transfer to: [{}] heritage: [{}]",
          Hex.toHexString(obtainer),
          balance);
    }

    increaseNonce();

    InternalTransaction internalTx = addInternalTx(null, owner, obtainer, balance, null,
        "suicide", nonce, getContractState().getAccount(owner).getAssetMapV2());

    if (FastByteComparisons.isEqual(owner, obtainer)) {
      getContractState().markSelfDestruct(owner);
      return;
    }

    if (VMConfig.allowTvmVote()) {
      withdrawRewardAndCancelVote(owner, getContractState());
      balance = getContractState().getBalance(owner);
      if (internalTx != null && balance != internalTx.getValue()) {
        internalTx.setValue(balance);
      }
    }

    // transfer balance and trc10
    createAccountIfNotExist(getContractState(), obtainer);
    try {
      MUtil.transfer(getContractState(), owner, obtainer, balance);
      if (VMConfig.allowTvmTransferTrc10()) {
        MUtil.transferAllToken(getContractState(), owner, obtainer);
      }
    } catch (ContractValidateException e) {
      if (VMConfig.allowTvmConstantinople()) {
        throw new TransferException(
            "transfer all token or transfer all trx failed in suicide: %s", e.getMessage());
      }
      throw new BytecodeExecutionException("transfer failure");
    }

    // transfer freeze
    if (VMConfig.allowTvmFreeze()) {
      transferDelegatedResourceToInheritor(owner, obtainer, getContractState());
    }

    // transfer freezeV2
    if (VMConfig.allowTvmFreezeV2()) {
      long expireUnfrozenBalance =
          transferFrozenV2BalanceToInheritor(owner, obtainer, getContractState());
      if (expireUnfrozenBalance > 0 && internalTx != null) {
        internalTx.setValue(internalTx.getValue() + expireUnfrozenBalance);
      }
    }

    getContractState().markSelfDestruct(owner);
  }
