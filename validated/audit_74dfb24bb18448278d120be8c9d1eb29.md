## #Vulnerability found for this question

### Title
Bank-level `Paused` state blocks repayment while interest continues to accrue via the permissionless `lending_pool_accrue_bank_interest` crank - ([File: programs/marginfi/src/instructions/marginfi_group/accrue_bank_interest.rs])

### Summary
When a group admin puts an individual `Bank` into the `Paused` operational state, `lending_account_repay` (and deposit/withdraw/borrow/liquidate) are blocked for that bank, but the permissionless `lending_pool_accrue_bank_interest` instruction is *not* gated on the bank's operational state — only on the group-wide protocol pause flag. This lets interest keep compounding on a bank whose borrowers are locked out of repaying, which is exactly the bug class described in the external report (VaultController `pay_interest()` accruing while repay is blocked).

### Finding Description
Every bank tracks an `operational_state` (`BankConfig.operational_state`) that gates user-facing instructions via `validate_bank_state()`: [1](#0-0) 

`lending_account_repay` enforces `InstructionKind::FailsInPausedState`, so once a bank is `Paused`, borrowers cannot repay it: [2](#0-1) 

The `BANK_STATE.md` guide confirms this is by design — `Paused` blocks deposit/borrow/withdraw/repay/liquidate for that bank: [3](#0-2) [4](#0-3) 

However, the permissionless `LendingPoolAccrueBankInterest` instruction's account validation only checks the group-wide protocol pause flag (`is_protocol_paused()`), and never calls `validate_bank_state` or checks `bank.config.operational_state` at all: [5](#0-4) 

The interest-accrual math itself is purely time-based (`current_timestamp - self.last_update`), so any caller — permissionlessly — can advance `last_update` and compound the liability share value on a bank that is simultaneously `Paused` for repayment: [6](#0-5) 

The existing test suite only verifies that accrual is blocked under the *group-wide* `panic_pause` (protocol-level pause): [7](#0-6) 

There is no equivalent test or code path preventing `lending_pool_accrue_bank_interest` while a specific `Bank` is set to `BankOperationalState::Paused` by the group admin. This is the same root cause pattern as the reported bug: a precursor "pause" state blocks user repayment while a separate, unguarded interest-accrual path keeps running.

### Impact Explanation
A borrower on a bank that the admin pauses (e.g., during an incident investigation, or simply left `Paused` from initial setup with existing balances carried over from a prior `Operational` period) cannot repay their debt while it is `Paused`, yet anyone can permissionlessly crank `lending_pool_accrue_bank_interest` on that same bank, continuously compounding the borrower's liability share value. If the pause persists (there is no time limit on bank-level pause, unlike the rate-limited protocol-wide `panic_pause`), the borrower's health can deteriorate to the point of triggering liquidation once the bank returns to `Operational` — a state change entirely outside the borrower's control, with real economic loss (excess interest charged, potential liquidation and loss of collateral). Liquidation itself is also blocked in `Paused` state, so the debt keeps growing unchecked and unresolved until the admin unpauses, at which point the borrower may already be insolvent.

### Likelihood Explanation
Bank-level `Paused` is a normal, frequently-used admin lever (new banks start `Paused`, and it's the documented tool for "emergency: halt all activity on a bank while investigating an issue"). Unlike group-wide `panic_pause`, it has no built-in duration cap or rate limit, so an admin could reasonably leave a bank paused for an extended period while borrowers with existing positions are trapped and interest keeps accruing via the always-permissionless crank. No special privilege is needed to trigger the accrual — any address can call `lending_pool_accrue_bank_interest`.

### Recommendation
Gate `LendingPoolAccrueBankInterest` (or `Bank::accrue_interest`) on the bank's own `operational_state`, not just the group-wide pause flag — e.g., skip/reject accrual when `bank.config.operational_state == BankOperationalState::Paused`, mirroring the block already applied to repay/withdraw/borrow/liquidate for that bank. As the external report recommends, avoid making interest-rate calculation a hard precursor to other operations; instead simply freeze `last_update` (or skip the state changes) while the bank is paused, and resume accrual only once it returns to `Operational`/`ReduceOnly`.

### Proof of Concept
1. Admin creates a `Bank` and sets `operational_state = Operational`; a lender deposits, a borrower deposits collateral and borrows against the bank.
2. Admin sets the bank to `Paused` via `lending_pool_configure_bank` (as in `programs/marginfi/tests/misc/operational_state.rs::marginfi_group_bank_paused_should_error`).
3. Borrower calls `lending_account_repay` → fails with `MarginfiError::BankPaused` (per `repay.rs` line 68).
4. Any address (permissionless) submits `LendingPoolAccrueBankInterest { group, bank }` repeatedly over time — this succeeds because the instruction's only constraint is `!group.load()?.is_protocol_paused()` (`accrue_bank_interest.rs` lines 30-35), which is unaffected by the bank's own `Paused` state.
5. `Bank::accrue_interest` advances `last_update` and compounds `liability_share_value` for the borrower's debt every time it's called, with no check on `bank.config.operational_state` (`bank.rs` lines 511-528).
6. Borrower's liability grows while they remain unable to repay (step 3 continues to fail); once admin sets the bank back to `Operational`, the borrower may be immediately liquidatable due to the accrued interest during the pause window.

pub fn validate_bank_state(bank: &Bank, kind: InstructionKind) -> MarginfiResult {
    if bank.config.operational_state == BankOperationalState::KilledByBankruptcy {
        return err!(MarginfiError::BankKilledByBankruptcy);
    }
    // Bank exists but has not completed one-time setup (e.g. JupLend seed deposit). Block every
    // operation until init runs.
    if bank.config.operational_state == BankOperationalState::Uninitialized {
        return err!(MarginfiError::BankUninitialized);
    }

    match kind {
        InstructionKind::FailsInReduceState if bank.config.operational_state.is_reduce_only() => {
            return err!(MarginfiError::BankReduceOnly);
        }

        InstructionKind::FailsInPausedState
            if bank.config.operational_state == BankOperationalState::Paused =>
        {
            return err!(MarginfiError::BankPaused);
        }

/// Permissionless `lending_pool_accrue_bank_interest` is rejected while the protocol is paused.
#[tokio::test]
async fn accrue_bank_interest_blocked_during_pause() -> anyhow::Result<()> {
    let test_f = TestFixture::new(Some(TestSettings::all_banks_payer_not_admin())).await;

    let usdc_bank = test_f.get_bank(&BankMint::Usdc);

    // Sanity check: accrue works while unpaused.
    test_f.marginfi_group.try_accrue_interest(usdc_bank).await?;

    // Pause and propagate so the group cache reflects the paused state.
    test_f.marginfi_group.try_panic_pause().await?;
    test_f.marginfi_group.try_propagate_fee_state().await?;

    let marginfi_group = test_f.marginfi_group.load().await;
    assert!(marginfi_group.panic_state_cache.is_paused_flag());

    // While paused, the permissionless crank must be rejected.
    let result = test_f.marginfi_group.try_accrue_interest(usdc_bank).await;

    assert_custom_error!(result.unwrap_err(), MarginfiError::ProtocolPaused);

    Ok(())
}
