### Title
Unauthenticated remote `/shutdown` POST permanently terminates the signer's event receiver - (File: libsigner/src/events.rs)

### Summary
`SignerEventReceiver::next_event` dispatches purely on `request.url()` string equality with no check of the peer's socket address, no shared secret, and no signature verification. Any TCP client that can reach the bound event-receiver port can send `POST /shutdown` and permanently flip `stop_signal` to `true`, terminating the receiver's main loop.

### Finding Description
In `libsigner/src/events.rs`, `SignerEventReceiver::next_event` (lines 413-459) reads an HTTP request from `http_server.recv()` and branches solely on `request.url()`:
```
} else if request.url() == "/shutdown" {
    event_receiver.stop_signal.store(true, Ordering::SeqCst);
    Err(EventError::Terminated)
}
``` [1](#0-0) 
There is no verification of the request's origin (no comparison to the node's loopback/peer address), no bearer token, and no signature on the body. The only mechanism intended to invoke this path is `SignerStopSignaler::send`, which itself just opens a new `TcpStream` to `self.local_addr` and POSTs `/shutdown` [2](#0-1) . Nothing distinguishes this "legitimate" internal caller from an arbitrary external client — the signaler and an attacker both just connect a TCP socket and send the same bytes. Once `stop_signal` is `true`, `is_stopped()` returns true [3](#0-2) , and `main_loop` breaks out permanently on its next iteration [4](#0-3) . There is no path to reset `stop_signal` back to `false`, so this is a one-shot, permanent denial of service on the signer's event ingestion — the signer will never again receive stacker-db chunks, proposal responses, burn-block or block events, effectively taking it offline for consensus/signing purposes until restarted.

### Impact Explanation
A single unauthenticated POST to the event-receiver's listener causes the signer process's event-receiving thread to exit its main loop, cutting off all node→signer event delivery (`stackerdb_chunks`, `proposal_response`, `new_burn_block`, `new_block`). This matches the Critical category: "remote crash/unauthenticated DoS from few messages." It is fully repeatable against every signer instance whose event-receiver port is reachable by the attacker, and requires exactly one crafted HTTP request.

### Likelihood Explanation
The attacker needs no credentials, no valid peer/slot ownership, and no privileged role — only TCP reachability to the port the signer binds via `SignerEventReceiver::bind` (the same port the node is configured to POST events to). The attacker cost is a single raw HTTP POST. Whether this is practically exploitable depends on network exposure of that endpoint (e.g., bound to `0.0.0.0` vs. `127.0.0.1` in the operator's config), but the code itself provides zero authentication regardless of bind address, so any reachable path is fully exploitable with no additional guard to bypass.

### Recommendation
Do not expose an unauthenticated `/shutdown` endpoint over the network. Options: (1) verify the request originates from the same loopback address the receiver is bound to (reject `/shutdown` from any non-local peer), (2) require a per-process shared secret/token generated at startup and passed only to the in-process `SignerStopSignaler`, or (3) replace the HTTP-based stop signal with an in-process channel/condvar rather than a network round-trip, eliminating the network attack surface entirely.

        body.len(), body
    );
    stream.write_all(req.as_bytes()).unwrap();

    handle.join().unwrap();
    // Assert: receiver's main_loop would now break permanently, no further events processed.
}
