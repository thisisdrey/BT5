### Title
Emissions accrued while a reward token's total supply is zero are permanently trapped in `RewardsDistributor` - ([File: contracts/RewardsDistributor.sol](contracts/RewardsDistributor.sol))

### Summary
The analog to the MuteAmplifier finding — where `claimFees()` is only invoked inside a timestamp-gated `if` so fees accruing after `endTime` are never collected — is `RewardsDistributor._calculateTokenIndex`. When `token_.totalSupply() == 0`, the accrued-emission ratio is computed as `0`, but `_newTimestamp` is still advanced to `block.timestamp`. The `delta * speed` emissions for that entire zero-supply window are silently discarded: the index never captures them and the state timestamp moves forward, so they can never be retroactively credited.

### Finding Description
In `_calculateTokenIndex` (contracts/RewardsDistributor.sol:197-212):

```solidity
uint256 _deltaTimestamps = block.timestamp - uint256(_supplyState.timestamp);
if (_deltaTimestamps > 0 && _speed > 0) {
    uint256 _totalSupply = token_.totalSupply();
    uint256 _tokensAccrued = _deltaTimestamps * _speed;
    uint256 _ratio = _totalSupply > 0 ? _tokensAccrued.wadDiv(_totalSupply) : 0;
    _newIndex = (_supplyState.index + _ratio).toUint224();
    _newTimestamp = block.timestamp.toUint32();
}
```

When `_totalSupply == 0`, `_ratio` is set to `0`, yet `_newTimestamp` is still returned, and `_updateTokenIndex` (lines 271-282) writes `_supplyState.timestamp = _newTimestamp`. The `_tokensAccrued` computed for that window is never represented in the index and the window is "burned" from the timeline — identical in spirit to the MuteAmplifier modifier advancing `_mostRecentValueCalcTime` past `endTime` while skipping `claimFees()`.

Emissions continue because `tokenSpeeds[token_]` stays positive (it is only zeroed by `syncTokenSpeed` when the underlying Vesper `periodFinish` passes, or by governor action — neither is guaranteed to fire before a zero-supply window occurs). A zero-supply window is trivially reachable: the last depositor calling `DepositToken.withdraw`/`burn` (an unprivileged public action) drives the share `totalSupply` to `0` while `speed > 0` and the timestamp was last updated. Any subsequent `updateBeforeMintOrBurn`, `updateBeforeTransfer`, or `claimRewards` call advances the timestamp with zero index accrual for the elapsed period.

The corresponding reward tokens still sit in the `RewardsDistributor` balance (pulled from Vesper yield via `Treasury`), but no index delta ever allocates them to an account, and `tokensAccruedOf` is the only path that authorizes transfers in `_transferRewardIfEnoughTokens` (lines 248-256). There is no sweep/recovery function in the contract — the tokens are stuck permanently.

### Impact Explanation
Reward tokens that should be distributed to depositors/debtors are permanently frozen inside `RewardsDistributor`. This is direct loss/trapping of unclaimed yield, matching the M-06 impact class (fees trapped in the pair instead of going to users).

### Likelihood Explanation
Requires no privileged actor: ordinary withdraws can bring a tracked token's `totalSupply` to 0 while `tokenSpeeds` remains positive (the keeper-sync and governor updates are not atomic with withdrawals). Every second of zero supply permanently discards `speed` tokens worth of emissions. The amount lost is unbounded and grows the longer supply stays at zero.

### Recommendation
Do not advance `tokenStates[token_].timestamp` (or equivalently, keep accruing `_tokensAccrued` into a pending bucket) when `totalSupply == 0` and `speed > 0`. Concretely, in `_calculateTokenIndex`, only return `_newTimestamp` together with a nonzero window accrual, or skip the timestamp update when `_totalSupply == 0` so the emissions carry over to the next non-zero-supply update — mirroring the M-06 recommendation to move the fee collection outside the gated `if`.

### Proof of Concept
Hardhat, mirroring `test/RewardDistributor.test.ts` setup with `msdTOKEN1` smock-faked:

```ts
it('loses emissions during zero-supply window', async function () {
  await rewardDistributor.updateTokenSpeed(msdTOKEN1.address, parseEther('1'))

  // Last user withdraws -> totalSupply = 0 while speed > 0
  msdTOKEN1.totalSupply.returns(0)
  msdTOKEN1.balanceOf.returns(0)
  await increaseTimeOfNextBlock(100) // 100 tokens emitted, uncredited
  await rewardDistributor.updateBeforeMintOrBurn(msdTOKEN1.address, alice.address)

  // Alice deposits; supply becomes non-zero
  msdTOKEN1.totalSupply.returns(parseEther('100'))
  msdTOKEN1.balanceOf.returns(parseEther('100'))
  await increaseTimeOfNextBlock(10)
  await mine()

  // Only 10 tokens claimable; the 100 emitted during zero supply are unclaimable forever
  expect(await rewardDistributor['claimable(address)'](alice.address)).to.eq(parseEther('10'))
})
```
