### Title
Bad debt from fully-insolvent positions is never absorbed — residual debt keeps accruing interest forever - ([File: contracts/Pool.sol](contracts/Pool.sol))

### Summary
`Pool.liquidate` caps a liquidation at the borrower's remaining deposit-token balance (`_totalSeized > depositToken_.balanceOf(account_)` reverts with `AmountIsTooHigh`). When a position is deeply underwater (collateral USD value < debt USD value), a liquidator can at best seize the entire collateral via `quoteLiquidateMax`, but the residual `DebtToken` balance is left on the account. There is no bad-debt socialization/write-off path anywhere: `DebtToken.accrueInterest` continues to grow this unbacked debt indefinitely, and `SyntheticToken` supply that was minted against it remains outstanding. This is the same bug class as the Aloe `Borrower.sol` report — collateral exhausted, debt non-zero, nothing further done.

### Finding Description
- `Pool.liquidate` (contracts/Pool.sol:537-596) burns `amountToRepay_` of the synthetic token from the liquidator, burns the same amount of `DebtToken` from the borrower, and seizes deposit tokens. Any repay amount whose seized value exceeds `depositToken_.balanceOf(account_)` reverts, so the maximum cleanable debt is `quoteLiquidateMax(syntheticToken_, account_, depositToken_)`, which only covers the collateral's value.
- The protocol's own test suite demonstrates the end state: after a max liquidation of an underwater position, `msdMET.balanceOf(alice)` is ~0 while `msEthDebtToken.balanceOf(alice)` remains `> 0` and `_isHealthy` is still `false` (test/Pool.test.ts:791-819, 821-871).
- That residual balance is not inert. `DebtToken.accrueInterest`/`balanceOf` grow the debt via the interest index (contracts/DebtToken.sol), so the hole compounds. `debtPositionOf` keeps counting it, but there is no function to burn the remainder without a corresponding synthetic-token repayment — i.e., no way to write off the loss.
- Because the corresponding `SyntheticToken` amount stays in circulation with zero collateral behind it, aggregate synthetic supply exceeds collateral backing, and the gap widens with interest.

### Impact Explanation
Protocol insolvency that grows over time: every underwater position that is liquidated to completion leaves phantom debt that keeps accruing interest. The synthetic tokens minted against that debt remain circulating unbacked, diluting the effective collateral backing of all other synthetic holders/depositors. As in the original report, accumulating such positions risks honest users being unable to exit at oracle parity (e.g., `Pool.swap` out at full value, or full redemption of collateral) because total obligations exceed total collateral.

### Likelihood Explanation
Any sharp market decline in a collateral asset (a real price move, not oracle manipulation) pushes positions below 100% collateralization. Liquidators are rationally incentivized to take the collateral (they get `liquidatorIncentive`), but once collateral is exhausted nothing removes the residual debt — the borrower never repays (repaying costs more than the zero collateral they would unlock). No privileged action is required to reach this state; the E2E/unit tests already produce it deterministically.

### Recommendation
When a liquidation leaves an account with zero (or dust) collateral across all `depositTokensOfAccount` but non-zero `DebtToken` balance, close the position: burn the residual debt and mark the loss (e.g., socialize it via the interest index/fees, or track it explicitly as bad debt) instead of letting `accrueInterest` compound an unbacked obligation. A `badDebtOf`/`writeOff` path callable once `depositOf(account) == 0` and `debtOf(account) > 0` would bound the loss.

### Proof of Concept
Reproducible with the existing Hardhat suite — `test/Pool.test.ts` "when the position is unhealthy (collateral:debt < 1)" already encodes it:

1. Alice deposits MET collateral and issues `msETH` debt.
2. `masterOracle.updatePrice(met, toUSD('0.50'))` crashes collateral value so `_debtInUsd > _depositInUsd`.
3. Liquidator calls `pool.liquidate(msEth, alice, await pool.quoteLiquidateMax(msEth, alice, msdMET), msdMET)`.
4. Assert: `msdMET.balanceOf(alice) ≈ 0`, `msEthDebtToken.balanceOf(alice) > 0`.
5. `time.increase(...)`, call `msEthDebtToken.accrueInterest()`, and observe `msEthDebtToken.balanceOf(alice)` grows — dead debt compounding with no collateral, while the minted `msETH` remains in circulation unbacked.
