### Title
Reward computation loop unbounded by governance cycle count can lock witness/voter rewards - ([File: chainbase/src/main/java/org/tron/core/service/MortgageService.java])

### Summary
`MortgageService.withdrawReward()`/`queryReward()` — invoked on every `VoteWitnessContract`, `UnfreezeBalanceContract`, `UnfreezeBalanceV2Contract`, and `WithdrawBalanceContract` transaction — computes rewards by iterating once per maintenance cycle between the account's `beginCycle` and the current cycle when the legacy reward-optimization flag is not active, mirroring the "expensive unbounded loop locks rewards" bug class from the reported Depositor.sol issue.

### Finding Description
`MortgageService.computeReward(long beginCycle, long endCycle, AccountCapsule accountCapsule)` splits the reward window at `newAlgorithmCycle` and, for the portion before that cycle, calls `getOldReward(beginCycle, oldEndCycle, srAddresses)`: [1](#0-0) 

`getOldReward` falls back to a per-cycle loop when `allowOldRewardOpt()` is not enabled (rather than the precomputed Vi-based O(1) path): [2](#0-1) 

This loop runs `for (long cycle = begin; cycle < end; cycle++) { reward += computeReward(cycle, votes); }`, and for each cycle it iterates the account's entire vote list (`computeReward(cycle, votes)`): [3](#0-2) 

Crucially, this whole path is triggered from `withdrawReward(address)`, which is called unconditionally by common actuators any time an account touches its votes/freeze state: [4](#0-3) [5](#0-4) [6](#0-5) [7](#0-6) 

Unlike the account's vote list (which is bounded to `MAX_VOTE_NUMBER = 30`, enforced in `VoteWitnessActuator.validate()`), the number of *cycles* an account can accumulate between `beginCycle` and `currentCycle` is **not bounded**. A voter or SR simply refraining from calling `WithdrawBalanceContract`/`UnfreezeBalanceContract`/`VoteWitnessContract` for a long time (maintenance cycles occur roughly every 6 hours by default) lets `endCycle - beginCycle` grow without limit, so `getOldReward`'s loop cost is `O(cycles × votes)`.

### Impact Explanation
If `allowOldRewardOpt` (a chain parameter set via a proposal) is not active for a given account's reward window, any transaction that triggers `withdrawReward` (vote, unfreeze, or withdraw-balance) for that account must execute this unbounded cycle loop. Once the number of unclaimed cycles is large enough that the loop's energy/time cost exceeds the transaction/block energy limit, the account can no longer successfully execute `WithdrawBalanceContract`, `VoteWitnessContract`, or `UnfreezeBalance(V2)Contract` — permanently freezing that account's accrued voting reward and blocking any action that also needs to touch votes/freeze, consistent with the reported "rewards can get locked" impact class.

### Likelihood Explanation
Reaching this state requires no privileged access — it is driven entirely by an account's own inaction (not calling reward-related contracts) combined with the chain's current committee parameter state for `allowOldRewardOpt`/`NEW_REWARD_ALGORITHM_EFFECTIVE_CYCLE`. I was unable to fully verify from static analysis whether `allowOldRewardOpt` is enabled on the current mainnet/committee default (the getter is defined in `DynamicPropertiesStore` and toggled via `ProposalUtil`/`ProposalService`, but I could not confirm today's live proposal state), so this analog's exploitability is contingent on that governance flag remaining disabled for the affected cycle range, which I could not conclusively determine within available tooling.

### Recommendation
- Bound the number of cycles processed per call to `getOldReward` (e.g., cap or paginate) so a single transaction can never be asked to iterate an unbounded cycle range.
- Ensure `allowOldRewardOpt`/`RewardViCalService` precomputation is mandatory (not merely a toggle) once `NEW_REWARD_ALGORITHM_EFFECTIVE_CYCLE` is reached, or provide a separate maintenance-triggered/administrative path to advance `beginCycle` without requiring the full per-cycle reward computation in the same transaction as an unrelated user action.

### Proof of Concept
1. An account accumulates votes and never calls `WithdrawBalanceContract`, `UnfreezeBalanceContract`, `UnfreezeBalanceV2Contract`, or re-votes, while `allowOldRewardOpt` remains disabled for that account's cycle range.
2. Over many maintenance cycles, `delegationStore.getEndCycle(address)` stays near the account's last interaction while `dynamicPropertiesStore.getCurrentCycleNumber()` advances, widening `endCycle - beginCycle`.
3. When the account finally issues any of the above transactions, `MortgageService.withdrawReward` → `computeReward` → `getOldReward` executes a loop of length `endCycle - beginCycle`, each iteration re-scanning up to 30 votes and doing store reads (`chainbase/src/main/java/org/tron/core/service/MortgageService.java:260-269` and `171-188`).
4. Once the accumulated cycle count is large enough, the transaction's resource consumption exceeds allowed limits and the transaction fails, leaving the account unable to withdraw its reward or otherwise adjust its votes/freeze state.

  public void withdrawReward(byte[] address) {
    if (!dynamicPropertiesStore.allowChangeDelegation()) {
      return;
    }
    AccountCapsule accountCapsule = accountStore.get(address);
    long beginCycle = delegationStore.getBeginCycle(address);
    long endCycle = delegationStore.getEndCycle(address);
    long currentCycle = dynamicPropertiesStore.getCurrentCycleNumber();
    long reward = 0;
    if (beginCycle > currentCycle || accountCapsule == null) {
      return;
    }
    if (beginCycle == currentCycle) {
      AccountCapsule account = delegationStore.getAccountVote(beginCycle, address);
      if (account != null) {
        return;
      }
    }
    //withdraw the latest cycle reward
    if (beginCycle + 1 == endCycle && beginCycle < currentCycle) {
      AccountCapsule account = delegationStore.getAccountVote(beginCycle, address);
      if (account != null) {
        reward = computeReward(beginCycle, endCycle, account);
        adjustAllowance(address, reward);
        reward = 0;
        logger.info("Latest cycle reward {}, {}.", beginCycle, account.getVotesList());
      }
      beginCycle += 1;
    }
    //
    endCycle = currentCycle;
    if (CollectionUtils.isEmpty(accountCapsule.getVotesList())) {
      delegationStore.setBeginCycle(address, endCycle + 1);
      return;
    }
    if (beginCycle < endCycle) {
      reward += computeReward(beginCycle, endCycle, accountCapsule);
      adjustAllowance(address, reward);
    }
    delegationStore.setBeginCycle(address, endCycle);
    delegationStore.setEndCycle(address, endCycle + 1);
    delegationStore.setAccountVote(endCycle, address, accountCapsule);
    logger.info("Adjust {} allowance {}, now currentCycle {}, beginCycle {}, endCycle {}, "
            + "account vote {}.", Hex.toHexString(address), reward, currentCycle,
        beginCycle, endCycle, accountCapsule.getVotesList());
  }

  private long computeReward(long cycle, List<Pair<byte[], Long>> votes) {
    long reward = 0;
    for (Pair<byte[], Long> vote : votes) {
      byte[] srAddress = vote.getKey();
      long totalReward = delegationStore.getReward(cycle, srAddress);
      if (totalReward <= 0) {
        continue;
      }
      long totalVote = delegationStore.getWitnessVote(cycle, srAddress);
      if (totalVote == DelegationStore.REMARK || totalVote == 0) {
        continue;
      }
      long userVote = vote.getValue();
      double voteRate = (double) userVote / totalVote;
      reward += voteRate * totalReward;
    }
    return reward;
  }

      return 0;

        .collect(Collectors.toList());

          dynamicPropertiesStore.disableJavaLangMath());

      beginCycle = oldEndCycle;

  private long getOldReward(long begin, long end, List<Pair<byte[], Long>> votes) {
    if (dynamicPropertiesStore.allowOldRewardOpt()) {
      return rewardViCalService.getNewRewardAlgorithmReward(begin, end, votes);
    }
    long reward = 0;
    for (long cycle = begin; cycle < end; cycle++) {
      reward += computeReward(cycle, votes);
    }
    return reward;
  }

    }

    if (!votesStore.has(ownerAddress)) {

    accountCapsule.clearVotes();
    votesCapsule.clearNewVotes();

          ByteArray.toHexString(vote.getVoteAddress().toByteArray()));

      accountCapsule.addVotes(vote.getVoteAddress(), vote.getVoteCount());
    });
