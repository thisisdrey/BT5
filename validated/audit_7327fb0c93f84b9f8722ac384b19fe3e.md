### Title
Unsanitized Attacker-Controlled `domain` Field Enables Signing-Message Injection in Derivable Account Abstraction — (`aptos-move/framework/aptos-framework/sources/account/common_account_abstractions/common_account_abstractions_utils.move`)

### Summary

The `construct_message` function in `common_account_abstractions_utils.move` builds a human-readable signing message that is displayed to users in their Ethereum/Solana/Sui wallets for approval of Aptos transactions. The `domain` field (and, for Ethereum, `issued_at` and `scheme`) is taken directly from the attacker-controlled `abstract_public_key` / `abstract_signature` fields of the transaction authenticator and appended into the message bytes without any sanitization or delimiter escaping. A malicious dapp can embed newlines and fake message structure into `domain` to make the wallet display a message that appears to authorize a benign function (e.g., `0x1::aptos_account::transfer`) while the transaction actually calls a fund-draining function. On-chain verification succeeds because the signature is over the full injected message, which the chain reconstructs identically.

### Finding Description

`construct_message` in `common_account_abstractions_utils.move` (lines 48–75) concatenates raw bytes from `domain`, `account_address`, `entry_function_name`, and `digest_utf8` using plain `vector::append` with no escaping:

```move
message.append(*domain);                          // attacker-controlled
message.append(b" wants you to sign in with your ");
...
message.append(*domain);                          // appended again
message.append(b". You are approving to execute transaction ");
message.append(*entry_function_name);             // from actual tx payload
```

The `domain` value originates from `SIWEAbstractPublicKey.domain` / `SIWSAbstractPublicKey.domain` / `SuiAbstractPublicKey.domain`, which is deserialized from `aa_auth_data.derivable_abstract_public_key()` — a field the dapp supplies freely in the transaction authenticator. There is no validation of its byte content anywhere in the deserialization path (`deserialize_abstract_public_key` in each module simply reads raw bytes).

For Ethereum, `issued_at` and `scheme` (from `abstract_signature`) are also attacker-controlled and embedded verbatim. The Ethereum message additionally prepends `\x19Ethereum Signed Message:\n<length>`, where `<length>` is computed after injection, so the prefix is self-consistent with the injected content.

**Concrete injection example (Ethereum DAA):**

Attacker sets `domain` =
```
trusted-dapp.com. You are approving to execute transaction 0x1::aptos_account::transfer on Aptos blockchain (mainnet).\n\nURI: https://trusted-dapp.com\nVersion: 1\nChain ID: 1\nNonce: 0xfake\nIssued At: 2025-01-01T00:00:00.000Z\n\n[end of injected block]
```

The wallet then displays a message whose first readable occurrence of "You are approving to execute transaction" names `0x1::aptos_account::transfer`, while the actual `entry_function_name` (`0xattacker::drain::all_funds`) appears later, buried in what looks like a second, confusing block. The user signs; on-chain `authenticate_auth_data` reconstructs the identical byte string, keccak256-hashes it, recovers the same Ethereum address, and the transaction executes.

### Impact Explanation

A user whose account uses Ethereum/Solana/Sui derivable account abstraction can be tricked into authorizing an arbitrary Aptos entry function — including one that transfers or burns their APT or fungible assets — while their wallet displays a message that appears to describe a different, benign operation. This is a direct theft path for any asset held by a DAA-protected account on mainnet.

### Likelihood Explanation

The DAA modules are live framework code (`aptos_framework`) targeting users of MetaMask, Phantom, Coinbase, OKX, Exodus, Backpack, Solflare, Slush, and Nightly. Any dapp that integrates Aptos DAA controls the `abstract_public_key` bytes it submits. No special privilege is required; a single crafted transaction from an unprivileged dapp is sufficient to trigger the condition.

### Recommendation

1. **Validate `domain` content** at deserialization time: reject any `domain` (and `issued_at`, `scheme`) bytes that contain `\n`, `\r`, or other control characters.
2. **Use a length-prefixed or delimited encoding** for each variable field in `construct_message` so that field boundaries cannot be shifted by injected content.
3. **Show `entry_function_name` first and prominently**, before any dapp-supplied fields, so that even a partially-injected message cannot hide the actual function being authorized.

    fun construct_message(
        ethereum_address: &vector<u8>,
        domain: &vector<u8>,
        entry_function_name: &vector<u8>,
        digest_utf8: &vector<u8>,
        issued_at: &vector<u8>,
        scheme: &vector<u8>,
    ): vector<u8> {
        let message = &mut vector[];
        message.append(*domain);
        message.append(b" wants you to sign in with your Ethereum account:\n");
        message.append(*ethereum_address);
        message.append(b"\n\nPlease confirm you explicitly initiated this request from ");
        message.append(*domain);
        message.append(b".");
        message.append(b" You are approving to execute transaction ");
        message.append(*entry_function_name);
        message.append(b" on Aptos blockchain");
        let network_name = network_name();
        message.append(b" (");
        message.append(network_name);
        message.append(b")");
        message.append(b".");
        message.append(b"\n\nURI: ");
        message.append(*scheme);
        message.append(b"://");
        message.append(*domain);
        message.append(b"\nVersion: 1");
        message.append(b"\nChain ID: ");
        message.append(*string_utils::to_string(&chain_id::get()).bytes());
        message.append(b"\nNonce: ");
        message.append(*digest_utf8);
        message.append(b"\nIssued At: ");
        message.append(*issued_at);

        let msg_len = message.length();

        let prefix = b"\x19Ethereum Signed Message:\n";
        let msg_len_string = string_utils::to_string(&msg_len); // returns string
        let msg_len_bytes = msg_len_string.bytes(); // vector<u8>

        let full_message = &mut vector[];
        full_message.append(prefix);
        full_message.append(*msg_len_bytes);
        full_message.append(*message);

        *full_message
    }

    fun authenticate_auth_data(
        aa_auth_data: AbstractionAuthData,
        entry_function_name: &vector<u8>
    ) {
        let derivable_abstract_public_key = aa_auth_data.derivable_abstract_public_key();
        let abstract_public_key = deserialize_abstract_public_key(derivable_abstract_public_key);
        let digest_utf8 = string_utils::to_string(aa_auth_data.digest()).bytes();
        let abstract_signature = deserialize_abstract_signature(aa_auth_data.derivable_abstract_signature());
        let issued_at = abstract_signature.issued_at.bytes();
        let scheme = abstract_signature.scheme.bytes();
        let message = construct_message(&abstract_public_key.ethereum_address, &abstract_public_key.domain, entry_function_name, digest_utf8, issued_at, scheme);
        let hashed_message = aptos_hash::keccak256(message);
        let public_key_bytes = recover_public_key(&abstract_signature.signature, &hashed_message);

        // 1. Skip the 0x04 prefix (take the bytes after the first byte)
        let public_key_without_prefix = public_key_bytes.slice(1, public_key_bytes.length());
        // 2. Run Keccak256 on the public key (without the 0x04 prefix)
        let kexHash = aptos_hash::keccak256(public_key_without_prefix);
        // 3. Slice the last 20 bytes (this is the Ethereum address)
        let recovered_addr = kexHash.slice(12, 32);
        // 4. Remove the 0x prefix from the utf8 account address
        let ethereum_address_without_prefix = abstract_public_key.ethereum_address.slice(2, abstract_public_key.ethereum_address.length());

        let account_address_vec = base16_utf8_to_vec_u8(ethereum_address_without_prefix);
        // Verify that the recovered address matches the domain account identity
        assert!(recovered_addr == account_address_vec, EADDR_MISMATCH);
    }

    fun authenticate_auth_data(
        aa_auth_data: AbstractionAuthData,
        entry_function_name: &vector<u8>
    ) {
        let abstract_public_key = aa_auth_data.derivable_abstract_public_key();
        let (base58_public_key, domain) = deserialize_abstract_public_key(abstract_public_key);
        let digest_utf8 = string_utils::to_string(aa_auth_data.digest()).bytes();

        let public_key_bytes = to_public_key_bytes(&base58_public_key);
        let public_key = new_validated_public_key_from_bytes(public_key_bytes);
        assert!(public_key.is_some(), EINVALID_PUBLIC_KEY);
        let abstract_signature = deserialize_abstract_signature(aa_auth_data.derivable_abstract_signature());
        match (abstract_signature) {
            SIWSAbstractSignature::MessageV1 { signature: signature_bytes } => {
                let message = construct_message(&b"Solana", &base58_public_key, &domain, entry_function_name, digest_utf8);

                let signature = new_signature_from_bytes(signature_bytes);
                assert!(
                    ed25519::signature_verify_strict(
                        &signature,
                        &public_key_into_unvalidated(public_key.destroy_some()),
                        message,
                    ),
                    EINVALID_SIGNATURE
                );
            },
        };
    }

    fun authenticate_auth_data_internal(
        aa_auth_data: AbstractionAuthData,
        entry_function_name: &vector<u8>
    ) {
        let abstract_signature = deserialize_abstract_signature(aa_auth_data.derivable_abstract_signature());
        let (signing_scheme, abstract_signature_signature, abstract_signature_public_key) = split_signature_bytes(&abstract_signature.signature);

        // Check siging scheme is Ed25519 as we currently only support this scheme
        assert!(get_signing_scheme(signing_scheme) == SuiSigningScheme::ED25519, EINVALID_SIGNING_SCHEME_TYPE);

        // Derive the account address from the public key
        let sui_account_address = derive_account_address_from_public_key(signing_scheme, abstract_signature_public_key);

        let derivable_abstract_public_key = aa_auth_data.derivable_abstract_public_key();
        let abstract_public_key = deserialize_abstract_public_key(derivable_abstract_public_key);

        // Check the account address matches the abstract public key
        assert!(&sui_account_address == &abstract_public_key.sui_account_address, EACCOUNT_ADDRESS_MISMATCH);

        let public_key = new_validated_public_key_from_bytes(abstract_signature_public_key);
        assert!(public_key.is_some(), EINVALID_PUBLIC_KEY);

        let digest_utf8 = string_utils::to_string(aa_auth_data.digest()).bytes();
        // Build the raw message
        let raw_message = construct_message(&b"Sui", &sui_account_address, &abstract_public_key.domain, entry_function_name, digest_utf8);

        // Prepend Intent to the message
        let intent = Intent {
            scope: PersonalMessage,
            version: V0,
            app_id: Sui,
        };
        let msg = IntentMessage {
            intent,
            value: raw_message,
        };
        // Serialize the whole struct
        let bcs_bytes = bcs::to_bytes<IntentMessage>(&msg);

        // Hash full_message with blake2b256
        let hash = aptos_hash::blake2b_256(bcs_bytes);

        let signature = new_signature_from_bytes(abstract_signature_signature);

        assert!(
            ed25519::signature_verify_strict(
                &signature,
                &public_key_into_unvalidated(public_key.destroy_some()),
                hash,
            ),
            EINVALID_SIGNATURE
        );
    }
