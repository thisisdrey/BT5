Audit Report

## Title
`pallet_dap::drip_issuance` permanently forfeits inflation time when clamped by `MaxElapsedPerDrip`, under-issuing budget-recipient rewards - (File: `substrate/frame/dap/src/lib.rs`)

## Summary
`drip_issuance` computes `elapsed = now - LastIssuanceTimestamp`, clamps it to `T::MaxElapsedPerDrip` for the mint calculation, but then unconditionally writes `LastIssuanceTimestamp = now` instead of `last + elapsed` (using the clamped value). Whenever real elapsed time exceeds the ceiling (e.g., a chain stall, long block-production gap, or upgrade freeze), the un-minted remainder beyond `MaxElapsedPerDrip` is silently and permanently lost from the accounting instead of being carried forward to the next drip.

## Finding Description
In [2](#0-1) , when `elapsed > max_elapsed`, `elapsed` is clamped for the purpose of `mint_and_distribute(elapsed)`, but `LastIssuanceTimestamp::<T>::put(now)` is called using the *unclamped* `now`, not `last.saturating_add(elapsed)`. This means the difference `(now - last) - max_elapsed` is never accounted for in any future drip: the next call's `elapsed` calculation starts fresh from `now`. The inline comment "Always advance the clock so elapsed time doesn't accumulate across skipped drips" confirms this is the exact mechanism causing the loss — it explicitly prevents carry-forward rather than merely bounding a single drip's mint size. `mint_and_distribute` itself, at [3](#0-2) , only mints `IssuanceCurve::issue(total_issuance, elapsed)` for the clamped `elapsed`, with no mechanism to later claim the dropped remainder.

## Impact Explanation
Every registered `BudgetRecipient` (staker reward pot, validator incentive pot, DAP buffer) permanently loses its proportional share of any un-minted remainder whenever a stall exceeding `MaxElapsedPerDrip` occurs, because the checkpoint no longer reflects the point up to which inflation was actually minted. This is a runtime bug that compromises the intended behavior of the token issuance/inflation schedule, causing deterministic and unrecoverable under-issuance to reward recipients as soon as any gap between `on_initialize` executions exceeds the configured ceiling.

## Likelihood Explanation
The clamp path triggers purely from elapsed wall-clock time between two `on_initialize` executions — a byproduct of normal chain operation (stalls, long block gaps, upgrade freezes) rather than any privileged, malicious, or externally-triggered action. `MaxElapsedPerDrip` is a real configured runtime parameter (confirmed in `substrate/frame/dap/src/mock.rs`), and the pallet even emits a dedicated `ElapsedClamped` event anticipating this condition, confirming it is a designed-for, reachable code path rather than an unreachable edge case.

## Recommendation
On clamp, advance `LastIssuanceTimestamp` only by the amount of elapsed time actually passed to `mint_and_distribute`: replace `LastIssuanceTimestamp::<T>::put(now)` with `LastIssuanceTimestamp::<T>::put(last.saturating_add(elapsed))` (using the already-clamped `elapsed`). This preserves the un-accounted remainder so it is picked up on the next drip while still bounding any single drip's mint size via the existing ceiling.

## Proof of Concept
1. Configure `IssuanceCadence = 60_000` and `MaxElapsedPerDrip = 600_000` as in `substrate/frame/dap/src/mock.rs`.
2. Set `LastIssuanceTimestamp = T0`.
3. Advance `T::Time` to `T0 + 1_200_000` before the next `drip_issuance` call (simulating a stall).
4. `drip_issuance` computes `elapsed = 1_200_000`, clamps to `600_000` (`ElapsedClamped` emitted), calls `mint_and_distribute(600_000)`, then sets `LastIssuanceTimestamp = T0 + 1_200_000`.
5. Confirm the remaining 600_000ms of intended inflation is never minted in this or any subsequent call, since `LastIssuanceTimestamp` already reflects the full elapsed wall-clock time rather than `T0 + 600_000`.

			// For existing chains, use `migrations::MigrateV1ToV2` to seed this

				LastIssuanceTimestamp::<T>::put(now);
				return T::DbWeight::get().reads_writes(2, 2);
			}

			// Apply safety ceiling on elapsed time.
			let max_elapsed = T::MaxElapsedPerDrip::get();

					actual_elapsed: elapsed,
					ceiling: max_elapsed,

		}
