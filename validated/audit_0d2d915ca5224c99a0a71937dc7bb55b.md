### Title
Spoofed RecvError packets let an unauthenticated attacker force-close a victim's established tunnel - ([File: outside.go])

### Summary
`handleRecvError` in `outside.go` tears down a live tunnel in response to a plaintext, unauthenticated `header.RecvError` packet whose only binding checks are a rate-limit predicate and a comparison of the source UDP address against the hostinfo's last-known remote address. Both of these checks are defeatable by an attacker who never needs to hold a CA-signed certificate, since `RecvError` packets are dispatched before any handshake, decryption, or certificate validation takes place.

### Finding Description
`readOutsidePackets` dispatches `header.RecvError` packets straight to `f.handleRecvError` before any tunnel lookup by index, decryption, or certificate check occurs: [1](#0-0) 

`handleRecvError` then:
1. Applies only a rate/allow predicate (`ShouldRecvError`), not an identity check.
2. Looks up the target hostinfo purely by the attacker-supplied `h.RemoteIndex` (a 32-bit value carried in the cleartext header on every packet of a tunnel, so it is observable by any on-path or off-path attacker who can see even a single legitimate packet).
3. Compares the packet's source `netip.AddrPort` to the hostinfo's cached remote endpoint. Because this arrives over UDP, the source address is attacker-controlled/spoofable and provides no cryptographic binding.
4. On a match it calls `f.closeTunnel(hostinfo)` and deletes the pending handshake state, unconditionally tearing down the victim's tunnel: [2](#0-1) 

This is analogous to the Ammplify root cause pattern described in the report: an attacker with no special privilege can, via a value they can reasonably obtain/spoof (the Maker `recipient`/asset-quota vs. here the `RemoteIndex`/spoofed source address), unilaterally mutate another party's protected state — in Ammplify a victim's asset quota, here a victim's live tunnel/hostinfo — without any consent or authentication check, causing denial of core functionality (in Ammplify, blocked position creation; here, forced tunnel/handshake teardown that must be re-established).

### Impact Explanation
An attacker who can spoof UDP packets (trivial on UDP, and RemoteIndex values are visible in the cleartext header of every wire packet a victim exchanges) can repeatedly force-close active Nebula tunnels for a targeted peer, causing a persistent, easily automated denial of service against otherwise legitimate, authenticated tunnels — the victim must renegotiate on every forged RecvError, and the attacker can simply repeat the attack. No CA-signed certificate or valid peer identity is required to mount this; the attacker only needs to be able to send crafted UDP datagrams to the victim's listen port with an observed `RemoteIndex` and a spoofed source address.

### Likelihood Explanation
- No certificate, handshake completion, or decryption capability is required — the packet type is handled unconditionally before authentication.
- `RemoteIndex` values are sent in cleartext on every data/handshake packet of the targeted tunnel, so any passive observer of even one packet (or a colluding low-privilege network position) can learn a valid index to target.
- UDP source-address spoofing is a well-known, low-cost primitive; the only mitigating control (`hr.IsValid() && hr != addr`) relies on the untrusted, unauthenticated source address as its sole binding factor.
- `ShouldRecvError` is a rate/allow gate, not an authentication mechanism, and doesn't prevent a single well-timed spoofed teardown per allowed interval.

### Recommendation
- Do not treat plaintext `RecvError` as authoritative for tearing down an established tunnel. At minimum, require that the RecvError acknowledgement be delivered over an already-authenticated channel (e.g., accept it only if it can be tied to a recent packet actually sent by this process to that remote index/address, using a locally-generated nonce/challenge) rather than trusting attacker-supplied `RemoteIndex` + spoofable source `AddrPort`.
- Consider rate-limiting/backoff plus requiring a matching, unpredictable per-tunnel token in the RecvError payload instead of relying solely on address-equality of a UDP source, which grants no authentication guarantee.
- Alternatively, do not fully tear down (`closeTunnel` + delete handshake state) on a single unauthenticated RecvError; instead treat it as a soft hint that triggers re-verification (e.g., an authenticated probe/keepalive) before disestablishing the tunnel.

### Proof of Concept
Conceptual (cannot be executed here, but derivable directly from the code path):
1. Attacker passively observes or otherwise learns the `RemoteIndex` used by an established Nebula tunnel between victim A and peer B (values appear in the cleartext Nebula header of every packet A sends/receives).
2. Attacker crafts a UDP packet with `header.RecvError` type, `RemoteIndex` set to the observed value, and spoofs the source IP:port to match peer B's last-known remote endpoint as cached in A's hostinfo (`hostinfo.GetRemote()`).
3. Attacker sends this packet to A's listening UDP port.
4. `readOutsidePackets` → `f.handleRecvError` passes the rate-limit check, finds the hostinfo via `QueryReverseIndex(h.RemoteIndex)`, finds the spoofed address matches the cached remote, and calls `f.closeTunnel(hostinfo)` plus `f.handshakeManager.DeleteHostInfo(hostinfo)`.
5. A's tunnel to B is torn down; repeating this indefinitely denies A and B a stable tunnel. [2](#0-1) [3](#0-2)

func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
