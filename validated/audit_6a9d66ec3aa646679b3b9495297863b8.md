### Title
`/v3/health` serves a Stacks tip height forged via an unauthenticated HTTP response header, not any signed peer attestation - (File: stackslib/src/net/api/gethealth.rs)

### Summary
`RPCGetHealthRequestHandler::try_handle_request` serves `network.highest_stacks_neighbor` verbatim as `max_stacks_neighbor_address` / `max_stacks_height_of_neighbors`. That field is populated in `ConversationHttp::chat` purely from the `X-Canonical-Stacks-Tip-Height` header of an HTTP response the node received from a peer it queried, with no signature, no handshake verification, and no cross-check against any inventory or block data.

### Finding Description
`RPCGetHealthRequestHandler::try_handle_request` reads `network.highest_stacks_neighbor` and returns it directly to any caller of `GET /v3/health` with no further validation: [1](#0-0) 

`highest_stacks_neighbor` is only ever written by `StacksNodeState::update_highest_stacks_neighbor`, which is called from `ConversationHttp::chat` whenever the node's HTTP-peer connection receives a `StacksHttpMessage::Response`: [2](#0-1) 

The value stored is `resp.preamble().get_canonical_stacks_tip_height()` — a plain HTTP response header value, not a field from any consensus-serialized, signed P2P message (`Handshake`, `HandshakeAccept`, `Nack`, or an inventory reply). `update_highest_stacks_neighbor` itself performs no authentication check, only a "is it higher" comparison: [3](#0-2) 

The struct field comment even documents this design as coming "via RPC responses," not via any signed handshake or inventory data: [4](#0-3) 

Any remote peer that the victim node opens an outbound HTTP conversation with (e.g., during normal peer-to-peer HTTP interactions handled by `ConversationHttp`) can set an arbitrary `X-Canonical-Stacks-Tip-Height` value on its response. That number — together with the peer's address — is stored unconditionally (as long as it's higher than the current cached value) and later served to any unauthenticated client of `/v3/health` as if it reflected a real, attested peer height. There is no signature check anywhere in this path (`ConversationHttp::chat` → `update_highest_stacks_neighbor` → `gethealth.rs`), so the claimed equality "served height == a height attested by a signed peer message" is false: it is only ever backed by an arbitrary HTTP header from a peer the node happened to converse with.

Note: the exploitation mechanism differs from what the question describes (P2P `Handshake`/`Nack` exchange) — the actual root cause is the unauthenticated HTTP response header consumed in the RPC/HTTP conversation layer, not the P2P messaging layer. The underlying broken equality and root cause (unvalidated peer-supplied height reaching `/v3/health` with no signature check) are the same as alleged.

### Impact Explanation
Any attacker-controlled peer the node exchanges HTTP responses with (e.g., a peer running its own Stacks node/HTTP server that the victim contacts) can force the victim's `/v3/health` endpoint to report an arbitrary, attacker-chosen `max_stacks_height_of_neighbors` and `max_stacks_neighbor_address`, and a correspondingly forged `difference_from_max_peer`. This is state served (a health/sync-status figure) that no canonical block or authenticated peer claim ever committed to, matching the "serving non-canonical state as canonical" High-severity category. Operators/monitoring tooling that rely on `/v3/health` to judge whether a node is behind the network tip can be misled (falsely reported as far behind, or falsely reported as caught up), repeatable on every subsequent higher-height response from the same or another malicious peer.

### Likelihood Explanation
The attacker needs no privileged role, no RPC secret, and no signing key — it only needs to run its own peer/HTTP endpoint that the victim node establishes an outbound HTTP conversation with, and reply with a crafted `X-Canonical-Stacks-Tip-Height` header. This is well within the "run their own peer, gossip messages" unprivileged capability. The cost is a single crafted response header per update, fully repeatable, and the RPC port `/v3/health` is reachable by anyone. No special network or peer state is required beyond the node having conversed with the attacker's endpoint at least once.

### Recommendation
Do not update `highest_stacks_neighbor` from unauthenticated HTTP response headers. If the intent is to reflect only genuinely-observed, verifiable peer heights, derive this value only from signed/verified sources (e.g., processed and validated blocks/tenures, or heights corroborated by the peer's actual inventory data validated against its handshake-established identity), and bound/sanity-check the claimed height against the local burnchain view before accepting it.

### Proof of Concept

1. Set up two `TestPeer`s connected via `ConversationHttp` (as in existing `net::tests::mod` HTTP conversation tests).
2. Have peer 1 (attacker-controlled) send an HTTP response to peer 2 with a crafted `X-Canonical-Stacks-Tip-Height` header set to an arbitrary large value (e.g., `u64::MAX - 1`), not corresponding to peer 1's actual chain state.
3. Drive `ConversationHttp::chat` on peer 2's side to process the response — this triggers `node.update_highest_stacks_neighbor(&peer_1_addr, Some(forged_height))`.
4. Assert `peer_2.network.highest_stacks_neighbor == Some((peer_1_addr, forged_height))` — confirming no signature/authentication gate exists between the crafted header and the stored value: [2](#0-1) 
5. Issue `GET /v3/health` against peer 2 and assert `RPCGetHealthResponse::max_stacks_height_of_neighbors == forged_height` and `max_stacks_neighbor_address == Some(peer_1_addr.to_string())`, per the read path in `gethealth.rs`: [5](#0-4)

    pub fn update_highest_stacks_neighbor(
        &mut self,
        new_address: &SocketAddr,
        new_height: Option<u64>,
    ) {
        self.with_node_state(|network, _, _, _, _| {
            if let Some(new_height) = new_height {
                let current_height = network
                    .highest_stacks_neighbor
                    .as_ref()
                    .map(|(_addr, height)| *height)
                    .unwrap_or(0);

                if new_height > current_height {
                    network.highest_stacks_neighbor = Some((*new_address, new_height));
                }
            }
        });
    }
