### Title
`unlockedBalanceOf()` grants each DepositToken the full account-wide issuable headroom, letting a multi-collateral borrower withdraw the same margin once per collateral type - ([File: contracts/DepositToken.sol](contracts/DepositToken.sol))

### Summary
The bug-class analog of "multiple liens on the same NFT, one claimant withdraws the shared asset" is Metronome's shared borrowing headroom: `unlockedBalanceOf()` computes the withdrawable amount for a single `DepositToken` using the account-wide `_issuableInUsd` returned by `pool.debtPositionOf()`. Because `withdraw()` / `withdrawFrom()` / `transfer()` only enforce `_revertIfLocked(account, amount)` against that per-token figure, a user holding several collateral types can withdraw up to `issuableUsd / collateralFactor` worth from **each** deposit token, multiplying the intended headroom and leaving the debt undercollateralized.

### Finding Description
`unlockedBalanceOf` returns `Math.min(balanceOf[account], quoteUsdToToken(underlying, _issuableInUsd.wadDiv(collateralFactor)))` whenever `_debtInUsd > 0` [1](#0-0) . `_issuableInUsd` is the account-global remaining minting capacity — a single resource shared by all of the user's deposit positions, exactly like the single NFT shared by multiple `Lien`s in the Particle report.

`withdraw()` calls `_revertIfLocked(_msgSender, amount_)` which compares `amount_` to this per-token unlocked value [2](#0-1) [3](#0-2) . There is no cross-token accounting: after withdrawing the full headroom from deposit token A, the headroom check on deposit token B recomputes `unlockedBalanceOf` from the same unchanged debt position (withdrawing collateral does not reduce `_debtInUsd`, and `_issuableInUsd` as computed by `debtPositionOf` reflects capacity, not already-consumed allowance). Each token therefore independently authorizes a withdrawal sized to the whole shared margin.

The code acknowledges the gap implicitly: `_withdraw` "doesn't check if the amount is unlocked" [4](#0-3) , and the only lock enforcement is the per-token `_revertIfLocked` on `withdraw`, `transfer`, and `transferFrom` [5](#0-4) .

### Impact Explanation
An attacker deposits two collateral types (e.g., `vaETH` and `vaUSDC` deposit tokens, both registered in `Pool`), mints synth debt leaving issuable headroom `H`, then calls `withdraw(H/CF_A)` on deposit token A and `withdraw(H/CF_B)` on deposit token B. Total collateral withdrawn is up to `2·H/CF` while only `H/CF` was safe. The resulting position has debt exceeding what remaining collateral supports — protocol insolvency / bad debt that `Pool.liquidate` cannot recover, while the attacker keeps both the minted synth and the excess collateral. This is direct theft of funds backed by the protocol's solvency invariant.

### Likelihood Explanation
Fully unprivileged: only requires `deposit()`, `DebtToken.mint`/`Pool` mint path, and two public `withdraw()` calls — no flash loan, no oracle manipulation, no privileged role. Conditions: account must hold ≥2 deposit-token collateral positions and have `_issuableInUsd > 0` (i.e., be under-borrowed relative to max). No modifier stops it: `whenNotShutdown`, `nonReentrant`, and `onlyIfDepositTokenExists` all pass; the `PositionIsNotHealthy` end-check in `SmartFarmingManager.flashRepay` does not apply to direct `withdraw()` calls [6](#0-5) .

Caveat: I was unable to read `Pool.debtPositionOf` within the tool budget to confirm `_issuableInUsd` is strictly `maxIssuable − debt` with no per-withdrawal side effects. If `debtPositionOf` already accounts for collateral being withdrawn (it cannot — it takes no token argument), the analog fails. The structure of `unlockedBalanceOf` strongly indicates the check is stateless and identical for every token at the same debt position.

### Recommendation
Either compute unlocked balance against a margin consumed globally, or (simpler and matching the mitigation style of the reference fix) make `withdraw()`/`transfer()` verify post-condition health: after `_withdraw`, call `pool.debtPositionOf(account)` and revert `NotEnoughFreeBalance`/`PositionIsNotHealthy` if `!_isHealthy`. Alternatively, cap per-call withdrawal by requiring `_issuableInUsd` be recomputed against the hypothetical post-withdrawal position rather than the current one.

### Proof of Concept
Hardhat sketch (fork or existing fixtures in `test/DepositToken.test.ts`):

```typescript
// two registered deposit tokens: depositTokenA (underlying A), depositTokenB (underlying B)
// CF_A = CF_B = 0.8e18
await underlyingA.mint(attacker.address, parseEther('1000'))
await underlyingB.mint(attacker.address, parseUnits('1000', 6))
await depositTokenA.connect(attacker).deposit(amountA, attacker.address)
await depositTokenB.connect(attacker).deposit(amountB, attacker.address)

// mint synth debt so that issuableInUsd == H (e.g. borrow $400 on $2000 collateral @ CF 0.8)
await msUSD.connect(attacker).mint(...) // via DebtToken.mint / Pool
const [, , debtUsd, , issuableUsd] = await pool.debtPositionOf(attacker.address)
// issuableUsd = H > 0

// each token reports unlocked ≈ H / CF
const unlockedA = await depositTokenA.unlockedBalanceOf(attacker.address)
const unlockedB = await depositTokenB.unlockedBalanceOf(attacker.address)
// unlockedA ≈ unlockedB ≈ H/CF — the SAME shared headroom counted twice

await depositTokenA.connect(attacker).withdraw(unlockedA, attacker.address)
await depositTokenB.connect(attacker).withdraw(unlockedB, attacker.address)
// no revert: each call only checked its own token's unlockedBalanceOf

const [isHealthy, , debtUsdAfter, ,] = await pool.debtPositionOf(attacker.address)
expect(isHealthy).to.eq(false)          // position undercollateralized
// attacker retains minted msUSD + withdrawn collateral of ~2·H/CF → bad debt for the protocol
```

Expected result: both withdrawals succeed and `debtPositionOf` reports an unhealthy/insolvent account, demonstrating withdrawal of collateral beyond the shared borrowing headroom — the same invariant break as `withdrawNftWithInterest` draining an NFT that still backs another lien.

```text
    function unlockedBalanceOf(address account_) public view override returns (uint256 _unlockedBalance) {
        IPool _pool = pool;

        (, , uint256 _debtInUsd, , uint256 _issuableInUsd) = _pool.debtPositionOf(account_);

        if (_debtInUsd == 0) {
            return balanceOf[account_];
        }

        if (_issuableInUsd > 0) {
            _unlockedBalance = Math.min(
                balanceOf[account_],
                _pool.masterOracle().quoteUsdToToken(address(underlying), _issuableInUsd.wadDiv(collateralFactor))
            );
        }
    }
```
