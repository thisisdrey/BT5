## Analysis

The Chainlink report's core broken invariant: individual field-level sanity checks (`price > 0`, round non-stale) were substituted for validating that the *final derived value* used by downstream logic is actually meaningful — allowing a superficially "valid" oracle read to still yield a corrupted/unsafe result that the caller trusts blindly.

The direct local analog is in Snowbridge's outbound-queue fee pricing: `PricingParameters::validate()` only checks that each raw governance-set field is individually non-zero, but `Pallet::<T>::calculate_fee` performs a chain of multiplication/division/truncating conversions on those fields, and the pallet never re-validates the *computed* remote fee before using it to price a permissionless, public message-send operation.

### Title
Snowbridge outbound-queue `calculate_fee` can silently derive a zero remote fee from valid `PricingParameters`, allowing underpriced public Ethereum-bound messages - (File: bridges/snowbridge/pallets/outbound-queue/src/lib.rs)

### Summary
`snowbridge_pallet_outbound_queue::Pallet::calculate_fee` computes the DOT fee charged to any user (via `send_message_impl::validate`, reachable from XCM `ExportMessage`/reserve-transfer flows to Ethereum) using a sequence of `FixedU128` arithmetic and an integer-division decimal conversion. `PricingParameters::validate()` (`bridges/snowbridge/primitives/core/src/pricing.rs:39-56`) only checks that `exchange_rate`, `fee_per_gas`, `rewards.local`, `rewards.remote`, and `multiplier` are individually non-zero — mirroring the oracle bug's "field-level, not derived-value" validation gap. It never checks that the *output* fee charged to the user is non-zero/sufficient.

### Finding Description
In `calculate_fee` (`bridges/snowbridge/pallets/outbound-queue/src/lib.rs:368-393`):
```rust
let fee: u128 = fee.try_into().defensive_unwrap_or(u128::MAX);
let fee = FixedU128::from_inner(fee)
    .saturating_mul(params.multiplier)
    .checked_div(&params.exchange_rate)
    .expect("exchange rate is not zero; qed")
    .into_inner();
let fee = Self::convert_from_ether_decimals(fee);
```
and `convert_from_ether_decimals` (lines 414-418):
```rust
pub(crate) fn convert_from_ether_decimals(value: u128) -> T::Balance {
    let decimals = ETHER_DECIMALS.saturating_sub(T::Decimals::get()) as u32;
    let denom = 10u128.saturating_pow(decimals);
    value.checked_div(denom).expect("divisor is non-zero; qed").into()
}
```
This is a truncating integer division. The pallet's own test suite proves the failure mode: `test_calculate_fees_with_valid_exchange_rate_but_remote_fee_calculated_as_zero` (`bridges/snowbridge/pallets/outbound-queue/src/test.rs:303-319`) feeds fully-valid, non-zero `PricingParameters` and gets `fee.remote == 0`, with the test comment explicitly stating: *"Though none zero pricing params the remote fee calculated here is invalid which should be avoided."* The bug is confirmed but the fix (rejecting/clamping a zero derived fee) was never implemented in `calculate_fee`/`validate()` — only asserted-away in a unit test comment.

`send_message_impl::validate` (`bridges/snowbridge/pallets/outbound-queue/src/send_message_impl.rs:41-74`) uses this fee unconditionally to price and admit *any* caller's message into the outbound queue — there is no re-check that `fee.remote > 0` (or above some minimum) before returning `Ok((ticket, fee))`.

### Impact Explanation
When governance sets a low `fee_per_gas`/`rewards.remote` combined with a large `exchange_rate` denominator relative to `T::Decimals` (a legitimate, non-zero configuration that passes `validate()`), the truncating division can zero out the remote-fee component entirely for cheap commands. Because there is no re-validation of the derived value, any permissionless caller can then have messages delivered to Ethereum without paying the relayer reward/gas-refund component (`params.rewards.remote`/`fee_per_gas`) that the fee is supposed to cover. This is public underpriced work: it lets unprivileged users spam the outbound queue / drive Ethereum-side processing without paying for the relayer incentive baked into the message (the `reward` field stored per-message on line 350 is a fixed constant regardless of the fee actually collected from the sender, so the bridge/relayer subsidy comes from elsewhere while callers pay nothing for it), degrading bridge economics and potentially stalling relayer processing once incentives no longer cover Ethereum gas costs.

### Likelihood Explanation
Requires no attacker privilege beyond being any account that can call `pallet_xcm`/asset-transfer paths that route through `SnowbridgeExporter`/`EthereumBlobExporter::deliver` — an ordinary user action. Triggering the zero-fee condition only requires governance-configured `PricingParameters` (which pass `validate()`) to fall into a numeric range where `remote fee-in-ether * 10^18 decimals / 10^(18-T::Decimals)` rounds to zero — realistic for low-gas commands under normal parameter tuning, and already demonstrated by the repo's own test.

### Recommendation
Extend `PricingParameters::validate()` (or add a post-computation check inside `calculate_fee`) to assert the *derived* `fee.remote` is non-zero (and ideally bounded above a configured minimum) before it is used to admit a message, mirroring Chainlink's recommendation to validate the oracle's final output rather than only its raw inputs. Reject/round-up (rather than truncate) in `convert_from_ether_decimals`, or fail `send_message_impl::validate` with `SendError` if the computed remote fee is zero.

### Proof of Concept
1. Set `PricingParameters { exchange_rate: FixedU128::from_rational(1,1), fee_per_gas: 1, rewards: Rewards{ local:1, remote:1 }, multiplier: FixedU128::from_rational(1,1) }` — passes `validate()`.
2. Call `OutboundQueue::calculate_fee(gas_used, price_params)` as in `bridges/snowbridge/pallets/outbound-queue/src/test.rs:303-319`.
3. Observed: `fee.remote == 0` while `fee.local` remains non-zero — confirming a valid-but-derived-zero fee is accepted and would flow unchanged through `send_message_impl::validate` to admit the message for delivery. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3)

		/// Calculate total fee in native currency to cover all costs of delivering a message to the
		/// remote destination. See module-level documentation for more details.
		pub(crate) fn calculate_fee(
			gas_used_at_most: u64,
			params: PricingParameters<T::Balance>,
		) -> Fee<T::Balance> {
			// Remote fee in ether
			let fee = Self::calculate_remote_fee(
				gas_used_at_most,
				params.fee_per_gas,
				params.rewards.remote,
			);

			// downcast to u128
			let fee: u128 = fee.try_into().defensive_unwrap_or(u128::MAX);

			// multiply by multiplier and convert to local currency
			let fee = FixedU128::from_inner(fee)
				.saturating_mul(params.multiplier)
				.checked_div(&params.exchange_rate)
				.expect("exchange rate is not zero; qed")
				.into_inner();

			// adjust fixed point to match local currency
			let fee = Self::convert_from_ether_decimals(fee);

			Fee::from((Self::calculate_local_fee(), fee))
		}

		/// Calculate fee in remote currency for dispatching a message on Ethereum
		pub(crate) fn calculate_remote_fee(
			gas_used_at_most: u64,
			fee_per_gas: U256,
			reward: U256,
		) -> U256 {
			fee_per_gas.saturating_mul(gas_used_at_most.into()).saturating_add(reward)
		}

		/// The local component of the message processing fees in native currency
		pub(crate) fn calculate_local_fee() -> T::Balance {
			T::WeightToFee::weight_to_fee(
				&T::WeightInfo::do_process_message().saturating_add(T::WeightInfo::commit_single()),
			)
		}

	fn validate(
		message: &Message,
	) -> Result<(Self::Ticket, Fee<<Self as SendMessageFeeProvider>::Balance>), SendError> {
		// The inner payload should not be too large
		let payload = message.command.abi_encode();
		ensure!(
			payload.len() < T::MaxMessagePayloadSize::get() as usize,
			SendError::MessageTooLarge
		);

		// Ensure there is a registered channel we can transmit this message on
		ensure!(T::Channels::contains(&message.channel_id), SendError::InvalidChannel);

		// Generate a unique message id unless one is provided
		let message_id: H256 = message
			.id
			.unwrap_or_else(|| unique((message.channel_id, &message.command)).into());

		let gas_used_at_most = T::GasMeter::maximum_gas_used_at_most(&message.command);
		let fee = Self::calculate_fee(gas_used_at_most, T::PricingParameters::get());

		let queued_message: VersionedQueuedMessage = QueuedMessage {
			id: message_id,
			channel_id: message.channel_id,
			command: message.command.clone(),
		}
		.into();
		// The whole message should not be too large
		let encoded = queued_message.encode().try_into().map_err(|_| SendError::MessageTooLarge)?;

		let ticket = Ticket { message_id, channel_id: message.channel_id, message: encoded };

		Ok((ticket, fee))
	}
