CVE-2022-37704 describes a privilege-escalation flaw specific to the Amanda backup software's SUID helper `/lib/amanda/rundump`, which passes attacker-controlled arguments to `/usr/sbin/dump` as root. This is an application-level design flaw in Amanda's own SUID wrapper, not a defect in the Go language, standard library, or toolchain [1](#0-0) .

The closest related code in this repository is the Go runtime's own SUID-protection test suite, which verifies that Go programs correctly detect and react to being run as setuid (resetting `GOTRACEBACK` and closing missing standard file descriptors) rather than being vulnerable to it [2](#0-1) [3](#0-2) . This exists specifically to defend Go binaries against the risk of privileged execution rather than to introduce it. Similarly, `os/exec` explicitly documents that it does not invoke a shell and does not expand globs, redirections, or other shell features, so it cannot be tricked the way Amanda's `rundump` was into constructing a dangerous privileged command line from unsanitized input [4](#0-3) .

There is no Go stdlib code path here that (a) runs a Go-supplied SUID/privileged wrapper, (b) accepts unprivileged/attacker-controlled arguments, and (c) forwards them to another privileged executable — which is the exact bug class in the CVE. The `syscall` package tests around `Credential`, `AmbientCaps`, and setuid binaries are test-only exercises of privilege-dropping/escalation primitives used correctly, not reachable via any unprivileged input from an untrusted caller [5](#0-4) . No analogous, currently-exploitable, unfixed vulnerability of this class exists in this codebase.

	// Alpine does not output groups; see https://golang.org/issue/19938.
