### Title
Storage-quota accounting bypass via unfiltered snapshot extraction feeding real disk usage that is excluded from `RepositorySize`/`RepositoryInfo`/`GetObjectDirectorySize` — ([File: internal/gitaly/service/repository/create_repository_from_snapshot.go])

### Summary
Gitaly's size-reporting RPCs (`RepositorySize`, `GetObjectDirectorySize`, `RepositoryInfo`) compute a repository's disk usage from a read-only "snapshot" whose contents are restricted by a strict regex allowlist of expected Git file names when WAL/transactions are enabled. Any file that lands on disk but does not match this allowlist is silently excluded from the reported size, even though it consumes real storage — an accounting mismatch structurally analogous to the Maple `triggerDefault` bug, where `collateral()` returns an incomplete/cached value instead of the real on-disk balance. `CreateRepositoryFromSnapshot` extracts an attacker/caller-supplied TAR archive (fetched from a caller-controlled `http_url`) directly onto disk with only path-traversal checks and no validation that entries match Git's expected object/ref layout, so it is a concrete way to place "unaccounted" bytes into a repository that are excluded from size accounting.

### Finding Description
`RepositorySize`, `GetObjectDirectorySize`, and `RepositoryInfo` compute usage by walking a directory and summing file sizes via `dirSizeInBytes`, using `snapshot.NewDefaultFilter(ctx)` as the walk filter itself (which passes almost everything): [1](#0-0) [2](#0-1) 

However, under WAL/transaction management, these RPCs don't walk the real repository directory — they walk a *read-only snapshot* built by `snapshot.Manager`. That snapshot's contents are restricted by `NewRegexSnapshotFilter()` when the `SnapshotFilter` feature flag is enabled: [3](#0-2) 

The regex filter only admits a fixed, narrow set of well-known Git paths (`config`, `HEAD`, `packed-refs`, `objects/<xx>/<hash>`, `objects/pack/*.{pack,idx,rev,bitmap}`, `refs/*`, `reftable/*`, `custom_hooks/*`, etc.): [4](#0-3) 

Any on-disk file that does not match one of these patterns (e.g. `.keep`/`.mtime` sidecar files, stray/garbage files, non-standard directories) is dropped from the snapshot and therefore from the reported size — confirmed by tests: a 5 KiB "garbage" file written directly into the repo is counted in the non-WAL size but *not* counted when WAL/snapshot-filter is active: [5](#0-4) 
and a garbage loose-object-shaped file's `LooseObjectsGarbageCount` differs identically based on WAL: [6](#0-5) 

This mirrors the reported bug class exactly: the "accounting getter" (`RepositorySize`/`RepositoryInfo`, standing in for `MapleLoanLike.collateral()`) reports a filtered/idealized view instead of the true on-disk resource state, so real, disk-consuming data becomes "unaccounted."

The concrete injection vector is `CreateRepositoryFromSnapshot`, which fetches a TAR archive from a caller-supplied `http_url` and extracts it verbatim via `tar -C path -xvf -`, with the code's own comment stating the archive is "trusted *a lot*" and needs hardening before being pointed at untrusted endpoints: [7](#0-6) [8](#0-7) 

Unlike the internal `GetSnapshot` RPC (which only emits objects/refs discovered via `CreateSnapshot`), `CreateRepositoryFromSnapshot`'s extraction path performs no filename/pattern validation of the archive's entries — only a symlink/hardlink/path-prefix escape check is present in the equivalent Go-based extractor used by replication: [9](#0-8) 

An archive containing arbitrarily-named large files anywhere under the target repository directory will be written to disk in full but, once the repository is managed under WAL with `SnapshotFilter` enabled, those bytes will not be reflected in `RepositorySize`, `RepositoryInfo`, or `GetObjectDirectorySize` responses.

### Impact Explanation
GitLab's storage-quota/namespace usage enforcement is built on top of Gitaly's size-reporting RPCs. If actual on-disk bytes can be made invisible to `RepositorySize`/`RepositoryInfo`, an actor who controls the snapshot source URL for `CreateRepositoryFromSnapshot` (or any other path that can place non-conforming files into a WAL-managed repository) can inflate real storage consumption on the storage backend while the reported/billed size stays artificially low — a storage-quota bypass and disk-exhaustion/DoS vector against the storage node, independent of GitLab's enforced per-namespace limits.

### Likelihood Explanation
`CreateRepositoryFromSnapshot` is a MUTATOR RPC that takes `http_url`/`http_auth`/`resolved_address` directly as caller-supplied fields: [10](#0-9) 
It is used in repository import/replication flows; whoever controls the value of `http_url` (or a maliciously served TAR at that URL) fully controls the archive contents extracted onto Gitaly's storage. The undercounting itself requires WAL + the `SnapshotFilter` feature flag to be active (an increasingly common default), which is a code-level condition, not an attacker action, so likelihood of the underlying discrepancy existing is high wherever these are enabled; the likelihood of actually exploiting `CreateRepositoryFromSnapshot` depends on whether an untrusted or attacker-influenced source is reachable in a given deployment, which the code comment itself calls out as unsafe.

### Recommendation
Make size/usage accounting consistent with actual on-disk state instead of a filtered view: either (a) compute `RepositorySize`/`RepositoryInfo`/`GetObjectDirectorySize` against the real repository directory (not the regex-filtered snapshot) when precision matters for quota enforcement, or (b) validate/reject extracted archive entries in `CreateRepositoryFromSnapshot`/`extractTarToDirectory` against the same allowlist used by `NewRegexSnapshotFilter`, so that no file can persist on disk that is invisible to the accounting path. At minimum, harden `CreateRepositoryFromSnapshot` per its own TODO comment before exposing it to any externally influenced `http_url`.

### Proof of Concept
1. Enable WAL/transactions with the `SnapshotFilter` feature flag enabled for a repository's storage.
2. Call `CreateRepositoryFromSnapshot` with `http_url` pointing to a TAR archive containing, in addition to a valid minimal Git repo layout, a large file at a non-conforming path (e.g. `objects/large-blob-not-a-hash` or `some-garbage-file` at repo root).
3. Observe the file is written to disk in full by `tar -xvf` (or the Go extractor in `replicate.go`), consuming real storage.
4. Call `RepositorySize`/`RepositoryInfo`/`GetObjectDirectorySize` on the resulting repository — the reported size excludes the injected file's bytes, as reproduced by the existing test `TestRepositorySize_normalRepository` and `TestRepositoryInfo`'s "repository with garbage" case which show identical files counted without WAL/snapshot-filter but excluded with it: [11](#0-10) [12](#0-11)

func (s *server) RepositorySize(ctx context.Context, in *gitalypb.RepositorySizeRequest) (*gitalypb.RepositorySizeResponse, error) {
	repository := in.GetRepository()
	if err := s.locator.ValidateRepository(ctx, repository); err != nil {
		return nil, structerr.NewInvalidArgument("%w", err)
	}
	repo := s.localRepoFactory.Build(repository)

	path, err := repo.Path(ctx)
	if err != nil {
		return nil, err
	}

	filter := snapshot.NewDefaultFilter(ctx)
	sizeInBytes, err := dirSizeInBytes(path, filter)
	if err != nil {
		return nil, fmt.Errorf("calculating directory size: %w", err)
	}

	return &gitalypb.RepositorySizeResponse{Size: sizeInBytes / 1024}, nil
}

func dirSizeInBytes(dirPath string, filter snapshot.Filter) (int64, error) {
	var totalSize int64

	if err := filepath.WalkDir(dirPath, func(path string, d fs.DirEntry, err error) error {
		if err != nil {
			// It can happen that we try to walk a directory like the object shards or
			// an empty reference directory that gets deleted concurrently. This is fine
			// and expected to happen, so let's ignore any such errors.
			if errors.Is(err, os.ErrNotExist) {
				return nil
			}

			return err
		}

		if d.IsDir() {
			return nil
		}

		relPath, err := filepath.Rel(dirPath, path)
		if err != nil {
			return fmt.Errorf("calculating path relative to repo root: %w", err)
		}

		if !filter.Matches(relPath) {
			return nil
		}

		fi, err := d.Info()
		if err != nil {
			// The file may have been concurrently removed.
			if errors.Is(err, os.ErrNotExist) {
				return nil
			}

			return fmt.Errorf("retrieving file info: %w", err)
		}

		totalSize += fi.Size()

		return nil
	}); err != nil {
		return 0, fmt.Errorf("walking directory: %w", err)
	}

	return totalSize, nil
}

func (s *server) untar(ctx context.Context, path string, in *gitalypb.CreateRepositoryFromSnapshotRequest) error {
	req, err := http.NewRequestWithContext(ctx, "GET", in.GetHttpUrl(), nil)
	if err != nil {
		return structerr.NewInvalidArgument("Bad HTTP URL: %w", err)
	}

	client := httpClient
	if resolvedAddress := in.GetResolvedAddress(); resolvedAddress != "" {
		client, err = newResolvedHTTPClient(in.GetHttpUrl(), resolvedAddress)
		if err != nil {
			return structerr.NewInvalidArgument("creating resolved HTTP client: %w", err)
		}
	}

	if in.GetHttpAuth() != "" {
		req.Header.Set("Authorization", in.GetHttpAuth())
	}

	rsp, err := client.Do(req)
	if err != nil {
		return structerr.NewInternal("HTTP request failed: %w", err)
	}
	defer rsp.Body.Close()

	if rsp.StatusCode < http.StatusOK || rsp.StatusCode >= http.StatusMultipleChoices {
		return structerr.NewInternal("HTTP server: %s", rsp.Status)
	}

	cmd, err := command.New(ctx, s.logger, []string{"tar", "-C", path, "-xvf", "-"}, command.WithStdin(rsp.Body))
	if err != nil {
		return err
	}

	return cmd.Wait()
}

	if err := s.locator.ValidateRepository(ctx, repository, storage.WithSkipRepositoryExistenceCheck()); err != nil {
		return nil, structerr.NewInvalidArgument("%w", err)
	}

	if err := repoutil.Create(ctx, s.logger, s.locator, s.gitCmdFactory, s.catfileCache, s.txManager, s.repositoryCounter, repository, func(repo *gitalypb.Repository) error {
		path, err := s.locator.GetRepoPath(ctx, repo, storage.WithRepositoryVerificationSkipped())
		if err != nil {
			return structerr.NewInternal("getting repo path: %w", err)
		}

		// The archive contains a partial git repository, missing a config file and
		// other important items. Initializing a new bare one and extracting the
		// archive on top of it ensures the created git repository has everything
		// it needs (especially, the config file and hooks directory).

		// NOTE: The received archive is trusted *a lot*. Before pointing this RPC
		// at endpoints not under our control, it should undergo a lot of hardening.
		if err := s.untar(ctx, path, in); err != nil {
			return structerr.NewInternal("extracting snapshot: %w", err)
		}

		return nil
	}); err != nil {
		return nil, structerr.NewInternal("creating repository: %w", err)

// extractTarToDirectory extracts a tar archive to the specified directory using Go's tar package
func (s *server) extractTarToDirectory(ctx context.Context, reader io.Reader, targetDir string) error {
	targetDir = filepath.Clean(targetDir)
	tarReader := tar.NewReader(reader)

	for {
		select {
		case <-ctx.Done():
			return ctx.Err()
		default:
		}

		header, err := tarReader.Next()
		if err == io.EOF {
			break // End of archive
		}
		if err != nil {
			return fmt.Errorf("reading tar header: %w", err)
		}

		targetPath := filepath.Join(targetDir, header.Name)

		if !strings.HasPrefix(targetPath, targetDir+string(os.PathSeparator)) &&
			targetPath != targetDir {
			return fmt.Errorf("invalid file path in tar: %s", header.Name)
		}

		switch header.Typeflag {
		case tar.TypeDir:
			if err := os.MkdirAll(targetPath, os.FileMode(header.Mode)); err != nil {
				return fmt.Errorf("creating directory %s: %w", targetPath, err)
			}

		case tar.TypeReg:
			if err := s.extractFile(ctx, tarReader, targetPath, header); err != nil {
				return fmt.Errorf("extracting file %s: %w", targetPath, err)
			}

		case tar.TypeSymlink:
			if filepath.IsAbs(header.Linkname) {
				return fmt.Errorf("absolute symlink not allowed: %s -> %s", header.Name, header.Linkname)
			}

			// Resolve the relative symlink target from the symlink's parent directory
			// and verify it stays within the extraction boundary, consistent with the
			// hard link validation below.
			resolvedTarget := filepath.Join(filepath.Dir(targetPath), header.Linkname)
			if !strings.HasPrefix(resolvedTarget, targetDir+string(os.PathSeparator)) &&
				resolvedTarget != targetDir {
				return fmt.Errorf("symlink target escapes extraction directory: %s -> %s", header.Name, header.Linkname)
			}

			// Remove existing file/symlink if it exists
			if err := os.Remove(targetPath); err != nil && !os.IsNotExist(err) {
				return fmt.Errorf("removing existing file for symlink %s: %w", targetPath, err)
			}

			if err := os.Symlink(header.Linkname, targetPath); err != nil {
				return fmt.Errorf("creating symlink %s -> %s: %w", targetPath, header.Linkname, err)
			}

		case tar.TypeLink:
			linkTarget := filepath.Join(targetDir, header.Linkname)

			if !strings.HasPrefix(linkTarget, targetDir+string(os.PathSeparator)) &&
				linkTarget != targetDir {
				return fmt.Errorf("invalid hard link target: %s", header.Linkname)
			}

			// Remove existing file if it exists
			if err := os.Remove(targetPath); err != nil && !os.IsNotExist(err) {
				return fmt.Errorf("removing existing file for hard link %s: %w", targetPath, err)
			}

			if err := os.Link(linkTarget, targetPath); err != nil {
				return fmt.Errorf("creating hard link %s -> %s: %w", targetPath, linkTarget, err)
			}

		default:
			// Skip unsupported file types (devices, FIFOs, etc.)
			s.logger.WithField("file", header.Name).WithField("type", header.Typeflag).
				WarnContext(ctx, "skipping unsupported file type in tar archive")
		}

		if header.Typeflag == tar.TypeReg || header.Typeflag == tar.TypeDir {
			if err := os.Chmod(targetPath, os.FileMode(header.Mode)); err != nil {
				return fmt.Errorf("setting permissions for %s: %w", targetPath, err)
			}
		}
	}

	return nil
}

// CreateRepositoryFromSnapshotRequest is a request for the CreateRepositoryFromSnapshot RPC.
message CreateRepositoryFromSnapshotRequest {
  // repository indicates where the new repo should be created. The storage_name and
  // relative_path attributes must be provided.
  Repository repository = 1 [(target_repository)=true];
  // http_url is the full URL of the location of the snapshot TAR.
  string http_url = 2;
  // http_auth is the value of the Authorization header to send to http_url.
  string http_auth = 3;
  // resolved_address holds the resolved IP address of the remote_url. This is
  // used to avoid DNS rebinding by mapping the url to the resolved address.
  // Only IPv4 dotted decimal ("192.0.2.1"), IPv6 ("2001:db8::68"), or IPv4-mapped
  // IPv6 ("::ffff:192.0.2.1") forms are supported.
  // Works with HTTP/HTTPS protocols.
  // Optional.
  string resolved_address = 5;

  // http_host has been removed in favor of ResolvedAddress.
  reserved 4;
  reserved "http_host";
}
