### Title
Unauthenticated `/shutdown` HTTP request permanently kills the signer's event-receiver thread - (File: libsigner/src/events.rs)

### Summary
`SignerEventReceiver::next_event` matches `request.url() == "/shutdown"` and, if true, unconditionally stores `true` into `stop_signal` and returns `Err(EventError::Terminated)`, with no authentication, secret, or origin check whatsoever. Anyone able to open a TCP connection to the signer's event-receiver bind address and send a single `POST /shutdown` HTTP request can permanently terminate `main_loop`, since `EventReceiver::main_loop` breaks out of its loop on `Err(EventError::Terminated)`.

### Finding Description
In `libsigner/src/events.rs`, `next_event` dispatches purely on exact string match of `request.url()`: [1](#0-0) 
There is no check of the request's source address, no shared secret, no header validation — any TCP client that completes tiny_http's minimal HTTP parsing and sends `POST /shutdown` reaches the `stop_signal.store(true, Ordering::SeqCst)` line. This is exactly the same code path used internally by `SignerStopSignaler::send`, which itself opens a plain `TcpStream` to `self.local_addr` and writes a raw `POST /shutdown ...` request with no credentials: [2](#0-1) 
Once `stop_signal` is set, `is_stopped()` returns `true` and `main_loop` exits on the next iteration: [3](#0-2) 
Note: the claim about a query string (`/shutdown?ignored=1`) or embedded CRLF causing the match is not correct — the check is exact string equality, so appending a query string would actually cause a **miss** (falling into the "unrecognized url" branch, which just acks and returns `UnrecognizedEvent`, not `Terminated`). The exploitable request is the plain, unmodified `POST /shutdown`, which is already unauthenticated by design.

### Impact Explanation
A single unauthenticated HTTP POST to `/shutdown` permanently terminates the signer's event-receiver main loop. Since this loop is what receives StackerDB chunk events, block-validation responses, burn-block events, and new-block events from the node, killing it stops the signer from processing any further node-driven events until the process/thread is restarted. This is a one-message, repeatable-on-restart DoS with zero authentication, matching the "Critical - remote crash/unauthenticated DoS from few messages" category — but only if the attacker can reach the port at all (see Likelihood).

### Likelihood Explanation
The endpoint in question is **not** the stacks-node's P2P or RPC port; it is a separate HTTP listener bound by the signer process itself, at an address given by the signer's own `endpoint`/event-receiver configuration (see `stacks-signer/src/config.rs`). The node's event-observer subsystem is configured to POST events to this address. This bind address is typically configured to a private/internal address reachable only by the co-located node, not to the public internet. Under this repo's stated threat model — "any remote party who can connect to a node's P2P or RPC port" — the signer's private event-receiver socket is a distinct listener whose exposure depends entirely on operator network configuration/firewalling, not on any check enforced by this code. If an operator binds this listener on a publicly reachable interface, the DoS is trivially exploitable by anyone reaching that port; if bound to loopback/internal network as intended, it is not remotely reachable at all. The code itself provides no defense-in-depth (no shared secret, no source-IP allowlist), so the finding is real as a missing authentication control on `/shutdown`, but its remote exploitability is conditional on deployment/network topology rather than being guaranteed reachable via the node's public P2P/RPC ports as the strict threat model requires.

### Recommendation
Require a shared secret or token (e.g., matching the node's configured `auth_token`/RPC secret) on the `/shutdown` path, or restrict acceptance of the `/shutdown` request to loopback connections only (check `request.remote_addr()` against `127.0.0.1`/`::1`) before honoring the stop signal. Alternatively, replace the wake-via-HTTP-POST mechanism with an OS-level mechanism (e.g., a self-pipe or a dedicated loopback-only control socket) that cannot be reached over the network at all.

### Proof of Concept
```rust
// libsigner/src/events.rs (test module)
#[test]
fn shutdown_requires_no_auth() {
    let mut receiver: SignerEventReceiver<crate::v0::messages::SignerMessage> =
        SignerEventReceiver::new(false);
    let addr = receiver.bind("127.0.0.1:0".parse().unwrap()).unwrap();

    // Attacker: plain TCP connection, no secret, no special headers.
    let mut stream = std::net::TcpStream::connect(addr).unwrap();
    stream.write_all(
        b"POST /shutdown HTTP/1.1\r\nHost: x\r\nContent-Length: 0\r\n\r\n"
    ).unwrap();

    let result = receiver.next_event();
    assert!(matches!(result, Err(EventError::Terminated)));
    assert!(receiver.is_stopped());
}
```
