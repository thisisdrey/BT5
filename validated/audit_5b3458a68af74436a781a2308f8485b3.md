### Title
Handshake stage-1 (msg1) packets carry no freshness/expiry bound, allowing indefinite delayed replay to establish an authenticated tunnel - ([File: handshake_manager.go])

### Summary
The reported issue is that `encodeTransactionData()` hashes transaction data with no deadline, so a validly-signed message stays usable forever until consumed once, allowing an old/stale signature to be replayed at an inconvenient time. The equivalent pattern in Nebula is the handshake stage-1 message (`msg1`): its validity is bound only by the signing certificate's `NotBefore`/`NotAfter` (which is typically long-lived, e.g. months), and by nothing else. There is no handshake-message-level timestamp, nonce-expiry, or deadline that limits how long after capture a stage-1 packet may be replayed to a *different* recipient (or the same recipient after its own pending-handshake state has expired) to complete a full, authenticated tunnel.

### Finding Description
`HandshakeManager.HandleIncoming` in `handshake_manager.go` treats every inbound `MessageCounter == 1` packet with `RemoteIndex == 0` as a brand-new handshake attempt and calls `beginHandshake`, which runs `machine.ProcessPacket` and, on success, validates the peer certificate and installs a new `HostInfo` via `CheckAndComplete`. [1](#0-0) [2](#0-1) 

The only anti-replay logic applied to this message is `CheckAndComplete`, which deduplicates only against handshake packets *already recorded for that specific responder's hostmap entry* (an identical byte-for-byte match, or an older `lastHandshakeTime` for the same vpn address). [3](#0-2) 

There is no check anywhere in this path that the packet's embedded `payload.Time` (`HandshakeTime`) is recent relative to `time.Now()` on the receiver. The e2e test `TestHandshakeLateResponse` explicitly documents and asserts this: after a handshake times out and is abandoned by the initiator, the *stale* captured `msg1` is later delivered to the responder and "they create a tunnel" — i.e., an old, previously-abandoned handshake message is fully accepted and completes a new tunnel establishment on the responder side. [4](#0-3) 

The freshness of the message is therefore bounded only by the long-lived host/CA certificate expiry window (`Expired()` checks in `cert/cert_v1.go` / `cert/cert_v2.go`), not by anything intrinsic to the handshake message itself: [5](#0-4) 

This mirrors exactly the reported bug class: a signed piece of data (`encodeTransactionData()`'s hash / here, the Noise handshake message authenticated by the embedded certificate) remains "valid" and can be consumed at any time up to a distant expiry, with no shorter deadline binding its use to the moment it was produced.

### Impact Explanation
An attacker who can observe/capture UDP traffic (no CA-signed certificate of their own required) can record a legitimate `msg1` handshake packet and replay it to the intended responder (or to a lighthouse-reachable path) far later than intended — well after the initiator gave up and moved on, or after network conditions changed — to force a new authenticated tunnel to be created using the original initiator's identity and certificate. Because there is no message-level deadline, this is a valid, fully-authenticated handshake from the responder's perspective; it just resurfaces stale intent, potentially at a time chosen by the attacker, creating an unexpected tunnel/state on the responder and consuming handshake/hostmap resources, or reviving a captured session context the operator believed to be dead. This is a state-poisoning/replay concern rather than a full authentication bypass, since it still requires a previously legitimately signed packet from a real certificate holder, and the responder's own outbound message to the "revived" tunnel goes to whatever address is bound in the packet.

### Likelihood Explanation
Likelihood is moderate: it requires the attacker to intercept a real handshake packet in transit (passive on-path observation of UDP is realistic for an unauthenticated network attacker) and then choose to replay it later. No cryptographic break or valid certificate is needed by the attacker — only capture-and-replay capability, which is exactly the reachable analog class described in scope (handshake authentication / nonce-replay handling reachable without a CA-signed certificate).

### Recommendation
Add a bounded validity window to the handshake payload's `Time` field: reject stage-1 (and other) handshake messages whose `payload.Time` is older than a configurable maximum skew/deadline (similar in spirit to the report's recommendation to add a deadline to `encodeTransactionData()`), in addition to the existing certificate expiry and per-responder dedup checks in `CheckAndComplete`. This closes the gap where message freshness is otherwise bounded only by the (typically long) certificate lifetime.

### Proof of Concept
1. Capture a legitimate `msg1` from Initiator A to Responder B (e.g., via passive UDP capture).
2. Wait past A's own handshake retry/timeout window (so A believes the handshake attempt is dead) — as demonstrated by `TestHandshakeLateResponse`. [6](#0-5) 
3. Replay the captured `msg1` to B at an attacker-chosen later time.
4. Observe that B's `HandshakeManager.HandleIncoming` → `beginHandshake` → `CheckAndComplete` accepts it and creates a new tunnel/hostinfo, exactly as the test asserts ("Deliver old msg1 to them, they create a tunnel"), with no check on the age of `payload.Time`. [1](#0-0)

func (hm *HandshakeManager) HandleIncoming(via ViaSender, packet []byte, h *header.H) {
	// Gate on known handshake subtypes. Unknown subtypes (or future ones we
	// don't yet support) are dropped here rather than silently routed through
	// the IX path. Add a case when introducing a new pattern.
	switch h.Subtype {
	case header.HandshakeIXPSK0:
		// supported
	default:
		hm.l.Debug("dropping handshake with unsupported subtype",
			"from", via, "subtype", h.Subtype)
		return
	}

	// First remote allow list check before we know the vpnIp
	if !via.IsRelayed {
		if !hm.lightHouse.GetRemoteAllowList().AllowUnknownVpnAddr(via.UdpAddr.Addr()) {
			hm.l.Debug("lighthouse.remote_allow_list denied incoming handshake", "from", via)
			return
		}
	}

	// First message of a new handshake. The wire format requires RemoteIndex
	// to be zero here (the initiator has no responder index to fill in yet),
	// and generateIndex never allocates 0, so any non-zero RemoteIndex on a
	// stage-1 packet is malformed or someone probing for an index collision.
	// Drop without paying the cost of running noise on a pending Machine.
	if h.MessageCounter == 1 {
		if h.RemoteIndex != 0 {
			hm.l.Debug("dropping stage-1 handshake with non-zero RemoteIndex",
				"from", via, "remoteIndex", h.RemoteIndex)
			return
		}
		hm.beginHandshake(via, packet, h)
		return
	}

// CheckAndComplete checks for any conflicts in the main and pending hostmap
// before adding hostinfo to main. If err is nil, it was added. Otherwise err will be:
//
// ErrAlreadySeen if we already have an entry in the hostmap that has seen the
// exact same handshake packet
//
// ErrExistingHostInfo if we already have an entry in the hostmap for this
// VpnIp and the new handshake was older than the one we currently have
//
// ErrLocalIndexCollision if we already have an entry in the main or pending
// hostmap for the hostinfo.localIndexId.
func (hm *HandshakeManager) CheckAndComplete(hostinfo *HostInfo, handshakePacket uint8, f *Interface) (*HostInfo, error) {
	hm.mainHostMap.Lock()
	defer hm.mainHostMap.Unlock()
	hm.Lock()
	defer hm.Unlock()

	// Check if we already have a tunnel with this vpn ip
	existingHostInfo, found := hm.mainHostMap.Hosts[hostinfo.vpnAddrs[0]]
	if found && existingHostInfo != nil {
		// Is it just a delayed handshake packet? Check every hostinfo we hold for this address.
		for _, testHostInfo := range hm.mainHostMap.unlockedGetHostList(hostinfo.vpnAddrs[0]) {
			if bytes.Equal(hostinfo.HandshakePacket[handshakePacket], testHostInfo.HandshakePacket[handshakePacket]) {
				return testHostInfo, ErrAlreadySeen
			}
		}

		// Is this a newer handshake?
		if existingHostInfo.lastHandshakeTime >= hostinfo.lastHandshakeTime && !existingHostInfo.ConnectionState.initiator {
			return existingHostInfo, ErrExistingHostInfo
		}

		existingHostInfo.logger(hm.l).Info("Taking new handshake")
	}

func (hm *HandshakeManager) beginHandshake(via ViaSender, packet []byte, h *header.H) {
	f := hm.f
	cs := f.pki.getCertState()

	v := cs.DefaultVersion()
	if cs.GetCredential(v) == nil {
		f.l.Error("Unable to handshake with host because no certificate is available",
			"from", via, "certVersion", v)
		return
	}

	machine, err := handshake.NewMachine(
		v, cs.GetCredential,
		hm.certVerifier(), func() (uint32, error) { return generateIndex(f.l) },
		false, header.HandshakeIXPSK0,
	)
	if err != nil {
		f.l.Error("Failed to create handshake machine", "from", via, "error", err)
		return
	}

	response, result, err := machine.ProcessPacket(nil, packet)
	if err != nil {
		f.l.Error("Failed to process handshake packet", "from", via, "error", err)
		return
	}

	if result == nil {
		// Multi-message pattern: the responder Machine would need to be
		// registered in hm.indexes so a future inbound packet finds it via
		// continueHandshake. The current manager doesn't do that yet, so
		// fail loudly rather than silently dropping the in-flight handshake.
		// TODO: support multi-message responder flows (XX, pqIX, etc.).
		// See also the IX-shaped cipher key assignment in handshake.Machine.
		f.l.Error("multi-message handshake responder is not supported",
			"from", via, "error", handshake.ErrMultiMessageUnsupported)
		return
	}

	remoteCert := result.RemoteCert
	if remoteCert == nil {
		f.l.Error("Handshake did not produce a peer certificate", "from", via)
		return
	}

	// Validate peer identity
	vpnAddrs, anyVpnAddrsInCommon, ok := hm.validatePeerCert(via, remoteCert)
	if !ok {
		return
	}

func TestHandshakeLateResponse(t *testing.T) {
	t.Parallel()
	// After a handshake times out, a late response should be silently ignored
	// with no new tunnels created.

	ca, _, caKey, _ := cert_test.NewTestCaCert(cert.Version1, cert.Curve_CURVE25519, time.Now(), time.Now().Add(10*time.Minute), nil, nil, []string{})
	myControl, myVpnIpNet, _, _ := newSimpleServer(cert.Version1, ca, caKey, "me", "10.128.0.1/24", m{
		"handshakes": m{
			"try_interval": "200ms",
			"retries":      2,
		},
	})
	theirControl, theirVpnIpNet, theirUdpAddr, _ := newSimpleServer(cert.Version1, ca, caKey, "them", "10.128.0.2/24", nil)

	myControl.InjectLightHouseAddr(theirVpnIpNet[0].Addr(), theirUdpAddr)

	myControl.Start()
	theirControl.Start()

	t.Log("Trigger handshake from me")
	myControl.InjectTunPacket(BuildTunUDPPacket(theirVpnIpNet[0].Addr(), 80, myVpnIpNet[0].Addr(), 80, []byte("Hi")))

	t.Log("Grab msg1 but don't deliver")
	msg1 := myControl.GetFromUDP(true)

	t.Log("Wait for handshake to time out")
	for i := 0; i < 5; i++ {
		time.Sleep(300 * time.Millisecond)
		myControl.GetFromUDP(false)
	}

	t.Log("Confirm no pending handshakes remain")
	assert.Empty(t, myControl.ListHostmapHosts(true))

	t.Log("Deliver old msg1 to them, they create a tunnel")
	theirControl.InjectUDPPacket(msg1)
	resp := theirControl.GetFromUDP(true)
	assert.NotNil(t, resp)
