### Title
Unbounded stale-data accumulation lets a low-privilege pusher DoS repository housekeeping - ([File: internal/git/housekeeping/clean_stale_data.go])

### Summary
The external report describes a state-growth DoS: an unprivileged actor cheaply creates many "requests" (unstake requests) that a privileged batch operation (`cancelUnfinalizedRequests`) must later enumerate and clean up, causing out-of-gas/partial-completion failures. The closest concrete analog in Gitaly is `housekeeping.CleanStaleData`, the maintenance routine invoked as part of `OptimizeRepository`, which walks and removes stale temporary Git artifacts. The number of stale artifacts an ordinary, unprivileged pushing client can leave behind (temporary objects, `tmp_objdir*` quarantine directories, broken loose references, stale reference locks, packfile `.keep` locks) is unbounded, and the cleanup routine that must enumerate and delete them has no cap on the number of entries it processes in a single run.

### Finding Description
`housekeeping.DefaultStaleDataCleanup()` registers a set of `FindStaleFileFunc`s that scan the repository's `objects` and `refs` trees for artifacts left behind by Git subprocesses that were interrupted (client aborts a push mid-stream, connection killed, etc.): [1](#0-0) 

These finder functions perform full, unbounded filesystem walks/reads of the `objects` and `refs` directories: [2](#0-1) [3](#0-2) [4](#0-3) 

`RepositoryManager.CleanStaleData` aggregates every entry found by every finder into a single `entriesToPrune` slice and then removes them one-by-one via `os.RemoveAll`, with no limit on the number of entries and no early-exit/context check inside the loop: [5](#0-4) 

Each individual stale artifact (a `tmp_` temporary object, a `tmp_objdir-*` quarantine directory, a stale reference lock, a `.keep` packfile lock) is trivially and cheaply created by an ordinary, authenticated pushing user: Git's own `git-receive-pack` process creates one quarantine directory and any number of loose object temp files per push attempt, and simply aborting the push (client disconnect) before completion is enough to leave the artifact behind, exactly as the code's own comments acknowledge ("When git crashes or a node reboots, it may happen that it leaves behind empty references... We thus clean them up") — no elevated privilege is required, only the ability to push (or attempt to push) repeatedly. [6](#0-5) 

Because there is no rate limit, quota, or cap on how many such artifacts a single repository can accumulate before `CleanStaleData` (invoked automatically as part of the `OptimizeRepository` MAINTENANCE RPC/housekeeping cycle) runs, a pushing user who repeatedly performs push attempts that are aborted mid-transfer can cause the number of stale files/directories to grow without bound. This is directly analogous to the reported bug class: cheap, repeated, unprivileged actions (there: creating unstake requests; here: aborting pushes) inflate a list that a later maintenance/admin-triggered batch process (there: `cancelUnfinalizedRequests`; here: `CleanStaleData`/`OptimizeRepository`) must fully enumerate and process without any per-run cap.

### Impact Explanation
`OptimizeRepository` acquires a per-repository "housekeeping running" lock via `tryRunningHousekeeping` before running `CleanStaleData`; while that lock is held, all other concurrent optimization/housekeeping requests for the same repository return early as no-ops: [7](#0-6) 

If an attacker inflates the number of stale entries to a large number, the unbounded `WalkDir`/`ReadDir` scans and the subsequent unbounded, sequential `os.RemoveAll` loop can make a single housekeeping run take substantially longer (or fail partway due to I/O errors, permission issues, etc., which are only logged and counted as `staleDataType["failures"]++` without aborting), effectively denying/delaying:
- timely repacking, commit-graph generation, and reference packing for the repository (since these all execute only after `CleanStaleData` completes in `optimizeRepository`), degrading repository performance for legitimate users, and
- other maintenance triggers for the same repository, which are silently skipped due to the concurrency lock while the oversized cleanup is in progress.

This is a resource-exhaustion / availability impact on Gitaly's maintenance subsystem triggered entirely by ordinary git push activity, without requiring any privileged actor, leaked token, or malicious peer.

### Likelihood Explanation
Likelihood is moderate: producing a single stale artifact requires only initiating a push and aborting it (or otherwise causing `git-receive-pack`/`git-fetch-pack` to be killed) before quarantine merge/cleanup completes — an action fully within reach of any authenticated user with push access, at the cost of a small amount of bandwidth/CPU per attempt, mirroring the "additional gas costs for sending transactions" cost model in the original report. Reaching a scale where housekeeping meaningfully degrades requires many repeated attempts (hundreds to thousands), which is plausible given automation, but the resulting impact is a maintenance slowdown/DoS rather than a data-corruption or auth-bypass issue, and the code already includes generous grace periods (24h for files, 72h for directories) that limit — but do not cap the count of — accumulated artifacts.

### Recommendation
- Add a hard cap on the number of stale entries processed per `CleanStaleData` invocation (e.g., process in bounded batches with `context` cancellation checks between batches), and emit a distinct metric/log warning when the cap is hit so operators can detect abuse.
- Consider rate-limiting or capping the number of concurrent/aborted push attempts (quarantine directory creations) per repository per unit time to bound artifact creation at the source.
- Ensure the `os.RemoveAll` loop in `CleanStaleData` respects `ctx.Done()` so a housekeeping run can be interrupted rather than running unbounded.

### Proof of Concept
1. As an ordinary user with push access to a repository, repeatedly initiate `git push` with a moderately sized payload and forcibly terminate/disconnect the client connection after Git has begun writing objects into the quarantine directory (`objects/tmp_objdir-incoming-*`) but before the push completes. Repeat hundreds/thousands of times, scripted, at low cost.
2. Each aborted push leaves behind a `tmp_objdir-*` quarantine directory and/or `tmp_*` loose-object files under `objects/`, as acknowledged by `FindTemporaryObjectDirectories`/`FindTemporaryObjects` in [8](#0-7) .
3. After the grace period elapses (24h for files / 72h for directories, per `deleteTempFilesOlderThanDuration`/`deleteTempObjectDirectoriesOlderThanDuration`), trigger (or wait for the automatic scheduling of) `OptimizeRepository`. Observe that `CleanStaleData`'s `os.ReadDir`/`filepath.WalkDir` scans and the unbounded `for _, path := range entriesToPrune { os.RemoveAll(path) }` loop in [5](#0-4)  take proportionally longer as the number of accumulated artifacts grows, delaying completion of housekeeping (repacking, commit-graph writing, ref packing) for the repository and blocking concurrent housekeeping attempts on it via the `tryRunningHousekeeping` lock.

// FindTemporaryObjects find temporary objects of a repository. Those objects are created by some git processes
// and are sure to be removed when the processes are done.
func FindTemporaryObjects(ctx context.Context, repoPath string) ([]string, error) {
	var temporaryObjects []string

	if err := filepath.WalkDir(filepath.Join(repoPath, "objects"), func(path string, dirEntry fs.DirEntry, err error) error {
		if err != nil {
			if errors.Is(err, fs.ErrPermission) || errors.Is(err, fs.ErrNotExist) {
				return nil
			}
			return err
		}

		// Tmp object dirs are handled in FindTemporaryObjectDirectories
		if dirEntry.IsDir() {
			return nil
		}

		isStale, err := isStaleTemporaryObject(dirEntry)
		if err != nil {
			if errors.Is(err, fs.ErrNotExist) {
				return nil
			}

			return fmt.Errorf("checking for stale temporary object: %w", err)
		}

		if !isStale {
			return nil
		}

		temporaryObjects = append(temporaryObjects, path)

		return nil
	}); err != nil {
		return nil, fmt.Errorf("walking object directory: %w", err)
	}

	return temporaryObjects, nil
}

func isStaleTemporaryObject(dirEntry fs.DirEntry) (bool, error) {
	// Check the entry's name first so that we can ideally avoid stat'ting the entry.
	if !strings.HasPrefix(dirEntry.Name(), "tmp_") {
		return false, nil
	}

	fi, err := dirEntry.Info()
	if err != nil {
		return false, err
	}

	if time.Since(fi.ModTime()) <= deleteTempFilesOlderThanDuration {
		return false, nil
	}

	return true, nil
}

// FindTemporaryObjectDirectories finds temporary object directories created by Git processes.
// These directories are typically prefixed with "tmp_obj_" and should be cleaned up when stale.
func FindTemporaryObjectDirectories(ctx context.Context, repoPath string) ([]string, error) {
	var temporaryDirectories []string
	objectsPath := filepath.Join(repoPath, "objects")

	entries, err := os.ReadDir(objectsPath)
	if err != nil {
		if errors.Is(err, fs.ErrNotExist) {
			return nil, nil
		}
		return nil, fmt.Errorf("reading objects directory: %w", err)
	}

	for _, entry := range entries {
		if !entry.IsDir() {
			continue
		}

		if !strings.HasPrefix(entry.Name(), "tmp_objdir") {
			continue
		}

		dirPath := filepath.Join(objectsPath, entry.Name())
		dirInfo, err := entry.Info()
		if err != nil {
			if errors.Is(err, fs.ErrNotExist) {
				continue
			}
			return nil, fmt.Errorf("getting directory info: %w", err)
		}

		// Use a longer grace period for directories (72 hours vs 24 hours for files)
		if time.Since(dirInfo.ModTime()) <= deleteTempObjectDirectoriesOlderThanDuration {
			continue
		}

		temporaryDirectories = append(temporaryDirectories, dirPath)
	}

	return temporaryDirectories, nil
}

// FindBrokenLooseReferences return the list of broken refs. A ref is considered to be broken when the loose ref file is
// empty. We don't validate the existence of referred objects.
func FindBrokenLooseReferences(ctx context.Context, repoPath string) ([]string, error) {
	var brokenRefs []string
	if err := filepath.WalkDir(filepath.Join(repoPath, "refs"), func(path string, dirEntry fs.DirEntry, err error) error {
		if err != nil {
			if errors.Is(err, fs.ErrPermission) || errors.Is(err, fs.ErrNotExist) {
				return nil
			}
			return err
		}

		if dirEntry.IsDir() {
			return nil
		}

		fi, err := dirEntry.Info()
		if err != nil {
			if errors.Is(err, fs.ErrNotExist) {
				return nil
			}

			return fmt.Errorf("statting loose ref: %w", err)
		}

		// When git crashes or a node reboots, it may happen that it leaves behind empty
		// references. These references break various assumptions made by git and cause it
		// to error in various circumstances. We thus clean them up to work around the
		// issue.
		if fi.Size() > 0 || time.Since(fi.ModTime()) < brokenRefsGracePeriod {
			return nil
		}

		brokenRefs = append(brokenRefs, path)

		return nil
	}); err != nil {
		return nil, fmt.Errorf("walking references: %w", err)
	}

	return brokenRefs, nil
}
