### Title
Shell Command Injection via `patch_cmds`/non-native `patch()` in `utils.bzl` when patch metadata comes from an untrusted registry/module - (File: tools/build_defs/repo/utils.bzl)

### Summary
`patch()` in `tools/build_defs/repo/utils.bzl`, used by `http_archive`/`http_repository`/Bzlmod's `archive_override`/module extensions, builds a shell command string with `.format()` string interpolation and runs it through `bash -c` when the non-native patch path is taken (custom `patch_tool`) or when `patch_cmds`/`patch_cmds_win` are used [1](#0-0) .

### Finding Description
When `patch_tool` is set (non-default) the code falls back to constructing a shell command via string formatting:
```
command = "{patchtool} {patch_args} < {patchfile}".format(...)
st = ctx.execute([bash_exe, "-c", command], working_directory = patch_directory or "")
``` [2](#0-1) 
`patch_args` is escaped with naive single-quote wrapping (`"'%s'" % arg`), which does **not** protect against an argument containing a single quote itself (classic shell-escaping bug: `'` inside `arg` breaks out of the quoted string). `patch_args` is attacker-controllable in scenarios where an `http_archive`/module extension resolves these values from a Bzlmod registry entry, lockfile-controlled module extension, or repository rule invoked transitively from an untrusted dependency's `MODULE.bazel`/extension logic, i.e., data an unprivileged attacker who publishes a module/registry entry can supply. Similarly, `patch_cmds`/`patch_cmds_win` are executed directly via `bash -c cmd` / `powershell /c cmd` with no additional sandboxing beyond the extraction dir [3](#0-2) .

This mirrors the reported bug class exactly: an insufficiently-validated string field (`filename` in the advisory; here `patch_args`) is concatenated into a shell command string and executed, allowing shell metacharacters to escape the intended single argument and run arbitrary commands.

### Impact Explanation
If a malicious dependency (module or `http_archive`-based repo whose attrs are populated from registry-provided data such as `patch_args`) sets a `patch_args` entry containing a single quote followed by shell metacharacters (e.g. `-p1' ; touch /tmp/pwned #`), the resulting bash command becomes `patch -p1' ; touch /tmp/pwned #' < <patchfile>`, executing arbitrary shell commands on the machine running the build — outside the intended file-modification action, during repository fetch. This is remote code execution reachable purely from published dependency metadata, matching the "High" severity RCE class in the report.

### Likelihood Explanation
This code path is only reached when `patch_tool` is explicitly set to something other than the default `"patch"` (disabling the native-patch fast path via `_use_native_patch`), so exploitation requires a dependency author to set a non-default `patch_tool` alongside a crafted `patch_args` value, or to use `patch_cmds`/`patch_cmds_win` (which is a fully expected/attacker-reachable path since it's raw shell text meant to be executed). Both `patch_tool`/`patch_args` and `patch_cmds` are standard attributes exposed on `http_archive` and various repo rules, and their values can originate from a Bazel registry module's `MODULE.bazel`/patch specification, which is attacker-controlled content in this analog's threat model (an outsider publishing a module/registry entry). No sha256/integrity check applies to these string attribute values (those checks only protect archive bytes, not the shell-invocation arguments) — so nothing in the current codebase stops this.

### Recommendation
- Do not embed `patch_args`/`patch_tool`/`patchfile` into a formatted shell string executed via `bash -c`. Instead invoke the patch tool directly as an argument list: `ctx.execute([patch_tool] + patch_args + [str(ctx.path(patchfile))], ...)`, redirecting file input via `ctx.execute`'s working directory/exec facilities or reading and piping content without shell interpretation.
- If shell redirection (`<`) is unavoidable, use a robust POSIX shell-escaping routine (matching the one used for `daemonize.cc`'s `ShellEscape`, cf. [4](#0-3) ) rather than naive `'%s'` wrapping that breaks on embedded single quotes.
- Document/require that `patch_cmds`/`patch_cmds_win`/`patch_args`/`patch_tool` sourced from third-party registries or module extensions be treated as fully untrusted and warn or reject non-default `patch_tool` combined with externally-supplied `patch_args` unless explicitly opted in by the root module.

### Proof of Concept
A `BuildIntegrationTestCase`/`src/test/shell/bazel/external_patching_test.sh`-style test can demonstrate the injection:
```
cat > repo.bzl <<'EOF'
load("@bazel_tools//tools/build_defs/repo:utils.bzl", "patch")

def _impl(ctx):
    ctx.file("BUILD", "")
    ctx.file("dummy.patch", "")
    patch(
        ctx,
        patches = ["dummy.patch"],
        patch_tool = "patch",  # non-default path forces string-built command
        patch_args = ["-p1' ; touch /tmp/worked ; echo '"],
    )

my_repo = repository_rule(implementation = _impl)
EOF
```
Building a target depending on `my_repo` results in `/tmp/worked` being created, proving that a single crafted `patch_args` string breaks out of the naive quoting in [2](#0-1)  and executes arbitrary shell commands during repository fetch, analogous to the `pi_video_recording` `/api/record/start` filename-injection RCE.

static char* ShellEscape(const char* arg) {
  if (!arg) {
    return NULL;
  }

  if (!ShellEscapeNeeded(arg)) {
    return strdup(arg);
  }

  bool has_single_quotes = false;
  for (size_t i = 0; arg[i]; i++) {
    if (arg[i] == '\'') {
      has_single_quotes = true;
      break;
    }
  }

  if (!has_single_quotes) {
    // When there are no single quotes, we can just escape the string with
    // single quotes.
    char* escaped_string;
    asprintf(&escaped_string, "'%s'", arg);
    return escaped_string;
  }

  // For all other cases, we wrap everything in double quotes.
  size_t escaped_len = 0;

  for (size_t i = 0; arg[i]; i++) {
    switch (arg[i]) {
      case '\\':
      case '$':
      case '"':
      case '`':
        escaped_len++;
    }
    escaped_len++;
  }

  char* escaped_string = (char*)malloc(
      escaped_len +
      3);  // +2 for double quotes, and +1 for the null terminator.

  size_t j = 0;
  escaped_string[j++] = '"';
  for (size_t i = 0; arg[i]; i++) {
    switch (arg[i]) {
      case '\\':
      case '$':
      case '"':
      case '`':
        escaped_string[j++] = '\\';
    }
    escaped_string[j++] = arg[i];
  }
  escaped_string[j++] = '"';
  escaped_string[j] = '\0';

  return escaped_string;
}
