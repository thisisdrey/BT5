### Title
Object-pool detection logic silently picks the first alternate object directory instead of enforcing exclusivity - ([File: internal/git/objectpool/pool.go], [File: internal/git/objectpool/link.go], [File: internal/gitaly/service/internalgitaly/scan_pool_metadata.go])

### Summary
Multiple Gitaly subsystems that determine a repository's object pool from its `objects/info/alternates` file blindly take the first entry (`AbsoluteObjectDirectories()[0]` / `ObjectDirectories[0]`) whenever the file contains one or more lines, instead of validating that exactly one alternate exists. This mirrors the `BondOracleAdapter.getPool` bug class: a selection routine picks a "winner" among multiple candidates using positional/priority heuristics rather than verifying the candidate set is well-formed, so an attacker-influenced candidate can be silently preferred.

### Finding Description
`stats.AlternatesInfoForRepository` (`internal/git/stats/repository_info.go:644-668`) parses the `objects/info/alternates` file and returns **all** lines as `ObjectDirectories`, with no restriction on count [1](#0-0) . Three separate pool-related code paths consume this struct and take only index `[0]`, implicitly assuming a single alternate without checking it:

- `objectpool.FromRepo`, which derives the `ObjectPool` proto used by `GetObjectPool`/replication/housekeeping RPCs: [2](#0-1) 
- `objectpool.linkedToRepository`, used to decide whether `Link` needs to (re)write the alternates file: [3](#0-2) 
- `processPoolMemberFunc` in the `ScanPoolMetadata` RPC, which records which pool a repository belongs to for the Rails/pool metadata store: [4](#0-3) 

By contrast, the WAL partition assigner's alternate resolution (`internal/gitaly/storage/gitstorage/alternates.go` `ReadAlternatesFile`, used by `internal/gitaly/storage/storagemgr/partition_assigner.go:317-360`) explicitly rejects more than one alternate line via `ErrMultipleAlternates` [5](#0-4) . Meanwhile Git's own alternate resolution as reimplemented in `internal/git/dirs.go`'s `altObjectDirs` recursively processes **every** line of the alternates file to build the real object search path used for `git cat-file`/`git fsck` etc. [6](#0-5) 

This produces three different interpretations of the same file across the codebase: (1) strict single-alternate enforcement (partition assigner), (2) "first line wins, rest silently ignored" (pool detection/linking/scan), and (3) "every line is an active alternate" (actual git object resolution). A repository whose alternates file contains two lines — e.g., a first line pointing at a legitimate/expected pool directory and a second line pointing at an unrelated, attacker-reachable object directory within the same storage root — would be recorded by `ScanPoolMetadata`/`FromRepo`/`linkedToRepository` as belonging only to the first (expected) pool, while Git itself, and thus every actual read/write git operation against that repository, would additionally read and be influenced by objects living under the second, unaccounted-for directory.

### Impact Explanation
Because pool-membership bookkeeping (`ScanPoolMetadata`, `FromRepo`, `Link`) disagrees with the real alternate object search path Git uses, a repository can be made to actually source objects from a directory that Gitaly's pool-tracking, quota/authorization, or deduplication logic never sees or validates against `locator.ValidateRepository`/`ErrInvalidPoolRepository` checks in `FromRepo` (`internal/git/objectpool/pool.go:159-168`). This is a variant of the reported bug class ("selection logic picks a candidate based on positional/priority heuristics instead of validating the candidate set"), applied here to object-pool/alternates isolation, one of the explicitly in-scope categories. The practical effect is cross-repository object visibility/DoS-relevant inconsistency between what Gitaly's metadata layer believes is the pool relationship and what Git's runtime alternate chasing actually does, undermining the isolation guarantees object pools are supposed to provide.

### Likelihood Explanation
Likelihood is moderate to low given the current constraints I could verify: under normal Gitaly-driven flows (`objectpool.Link`), only a single alternates line is ever written [7](#0-6) , so a repository would need its `objects/info/alternates` file to already contain multiple lines through some other means (e.g., replication/snapshot restore of a repository whose alternates file was crafted elsewhere, or an internal/administrative path that copies repository directories verbatim) for this discrepancy to be triggered. I was not able to fully confirm, within the tool budget available, an unprivileged, purely RPC-driven path (fetch/push/import) by which an ordinary user can get a two-line alternates file written into a repository without going through `objectpool.Link`. This should be treated as an open question requiring further investigation of `CreateRepositoryFromSnapshot`, `ReplicateRepository`, and bundle-import code paths.

### Recommendation
Make alternate-file interpretation consistent everywhere it is used for pool determination: have `objectpool.FromRepo`, `linkedToRepository`, and `processPoolMemberFunc` reuse the strict, single-alternate-enforcing `gitstorage.ReadAlternatesFile` (which returns `ErrMultipleAlternates`) instead of unconditionally indexing `[0]` into `stats.AlternatesInfoForRepository`'s results. Any repository whose alternates file contains more than one entry should be treated as invalid/corrupt for pool-linking and metadata-scanning purposes, consistent with the partition assigner's existing behavior, rather than silently accepting the first line as authoritative.

### Proof of Concept
Not independently reproduced against a running Gitaly instance within this analysis; the code-path divergence itself (single-index access in `pool.go`/`link.go`/`scan_pool_metadata.go` vs. full multi-line processing in `dirs.go` vs. strict rejection in `gitstorage/alternates.go`) is directly demonstrated by the cited line ranges above.

// ReadAlternatesFile returns the repository's alternate object directory paths
// from '<repo>/objects/infop/alternates' and returns them. Returns a wrapped
// fs.ErrNotExist if the file doesn't exist.
func ReadAlternatesFile(repoPath string) ([]string, error) {
	file, err := os.Open(AlternatesFilePath(repoPath))
	if err != nil {
		return nil, fmt.Errorf("open: %w", err)
	}
	defer file.Close()

	var alternatePaths []string
	scanner := bufio.NewScanner(file)
	for scanner.Scan() {
		line := scanner.Bytes()

		switch {
		case len(line) == 0:
			// Empty lines are skipped by Git.
			continue
		case bytes.HasPrefix(line, []byte("#")):
			// Lines starting with a '#' are comments and thus need to be skipped.
			continue
		default:
			alternatePaths = append(alternatePaths, scanner.Text())
		}
	}

	if err := scanner.Err(); err != nil {
		return nil, fmt.Errorf("scanning alternate paths: %w", err)
	}

	return alternatePaths, nil
}

// ReadAlternatesFile reads the alternates file from the given repository. ErrNoAlternate is returned if the
// file doesn't exist or didn't contain an alternate. ErrMultipleAlternates is returned if the
// repository had multiple alternates.
func ReadAlternatesFile(repositoryPath string) (string, error) {
	alternates, err := stats.ReadAlternatesFile(repositoryPath)
	if err != nil {
		if errors.Is(err, fs.ErrNotExist) {
			return "", ErrNoAlternate
		}

		return "", fmt.Errorf("read alternates file: %w", err)
	}

	if len(alternates) == 0 {
		return "", ErrNoAlternate
	} else if len(alternates) > 1 {
		// Repositories shouldn't have more than one alternate given they should only be
		// linked to a single pool at most.
		return "", ErrMultipleAlternates
	}

	return alternates[0], nil
}

func altObjectDirs(ctx context.Context, logger log.Logger, storagePrefix, objDir string, depth int) ([]string, error) {
	const maxAlternatesDepth = 5 // Taken from https://github.com/git/git/blob/v2.23.0/sha1-file.c#L575
	if depth > maxAlternatesDepth {
		logger.WithField("objdir", objDir).WarnContext(ctx, "ignoring deeply nested alternate object directory")
		return nil, nil
	}

	fi, err := os.Stat(objDir)
	if os.IsNotExist(err) {
		logger.WithField("objdir", objDir).WarnContext(ctx, "object directory not found")
		return nil, nil
	}
	if err != nil {
		return nil, err
	}
	if !fi.IsDir() {
		return nil, nil
	}

	dirs := []string{objDir}

	alternates, err := os.ReadFile(filepath.Join(objDir, "info", "alternates"))
	if os.IsNotExist(err) {
		return dirs, nil
	}
	if err != nil {
		return nil, err
	}

	for _, newDir := range strings.Split(string(alternates), "\n") {
		if len(newDir) == 0 || newDir[0] == '#' {
			continue
		}

		if !filepath.IsAbs(newDir) {
			newDir = filepath.Join(objDir, newDir)
		}

		if !strings.HasPrefix(newDir, storagePrefix) {
			return nil, alternateOutsideStorageError(newDir)
		}

		nestedDirs, err := altObjectDirs(ctx, logger, storagePrefix, newDir, depth+1)
		if err != nil {
			return nil, err
		}

		dirs = append(dirs, nestedDirs...)
	}

	return dirs, nil
}
