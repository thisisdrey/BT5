### Title
Unchecked array index in `extractBytes32Array` causes `ArrayIndexOutOfBoundsException` on attacker-controlled precompiled-contract input - (File: actuator/src/main/java/org/tron/core/vm/PrecompiledContracts.java)

### Summary
`PrecompiledContracts.extractBytes32Array(DataWord[] words, int offset)` decodes an ABI-encoded `bytes32[]` array from a `DataWord[]` derived from a precompiled contract's `execute(byte[] data)` input, but unlike its sibling helpers it performs no bounds validation of `offset` or the derived length against `words.length` before indexing.

### Finding Description
`extractBytes32Array` reads the declared array length from `words[offset]` and then loops reading `words[offset + i + 1]` for `i` in `[0, len)` without ever checking that `offset` or `offset + i + 1` stay within `words.length`: [1](#0-0) 

This is inconsistent with the neighboring helpers `extractBytesArray` and `extractSigArray`, both of which explicitly guard against an out-of-range `offset` before dereferencing `words[offset]`: [2](#0-1) [3](#0-2) 

Because `offset` and the array length `len` are both derived from attacker-supplied calldata bytes to a precompiled contract (reached through the TVM `CALL`/`STATICCALL` opcode to a precompile address, or via a smart-contract-triggering transaction), a caller can supply an `offset` close to `words.length` or a `len` value large enough that `offset + i + 1` exceeds `words.length`, causing an unchecked `ArrayIndexOutOfBoundsException` when `words[offset]` or `words[offset + i + 1]` is accessed. This mirrors the CVE-2026-22047 bug class in `SIccCalcOp::Describe()`: a length/offset value taken from untrusted, attacker-supplied binary input is used directly to index into an array without a bounds check, causing an out-of-bounds read.

I was not able to fully trace the exact precompiled-contract call site that invokes `extractBytes32Array` within the available search iterations (only 2 references were located: the definition and one call site, but the call-site body was not retrieved before the iteration budget was exhausted). This is a gap in my verification — the root-cause defect in `extractBytes32Array` itself is confirmed by direct code inspection, but I cannot cite the exact calling precompile method/line here.

### Impact Explanation
An unhandled `ArrayIndexOutOfBoundsException` thrown deep inside TVM precompiled-contract execution, if not caught by the surrounding VM exception handling, can abort transaction processing in an unexpected way. If the exception is not uniformly caught and converted into a normal EVM revert (as Java runtime exceptions are for many VM code paths), this can lead to inconsistent execution results between nodes (potential chain split) or an unhandled crash of the node process while processing an untrusted, attacker-crafted transaction — a Medium/High severity issue depending on whether the exception propagates past the VM's generic exception handling.

### Likelihood Explanation
Reachable by any account that can send a transaction invoking a smart contract that calls into the relevant precompiled contract with crafted `data`, i.e., no special privileges required — analogous to an unprivileged contract deployer/caller in the given threat model.

### Recommendation
Add the same offset/length bounds validation used in `extractBytesArray`/`extractSigArray` to `extractBytes32Array`: verify `offset >= 0 && offset < words.length` before reading `words[offset]`, and verify `offset + len < words.length` (or bound `len` against `words.length - offset - 1`) before the loop executes, returning an empty array (or throwing a normal `Program.Exception`) instead of allowing raw array indexing with attacker-controlled values.

    int len = words[offset].intValueSafe();
    byte[][] bytes32Array = new byte[len][];

      bytes32Array[i] = words[offset + i + 1].getData();

    if (offset > words.length - 1) {
      return new byte[0][];
    }
    int len = words[offset].intValueSafe();
    byte[][] bytesArray = new byte[len][];
    for (int i = 0; i < len; i++) {
      int bytesOffset = words[offset + i + 1].intValueSafe() / WORD_SIZE;
      int bytesLen = words[offset + bytesOffset + 1].intValueSafe();
      bytesArray[i] = extractBytes(data, (bytesOffset + offset + 2) * WORD_SIZE,
          bytesLen);
    }
    return bytesArray;
  }
