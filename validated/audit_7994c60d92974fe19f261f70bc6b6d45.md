### Title
Quarantine directory validation in `ObjectDirectoryPath` uses a predictable, guessable prefix checked with `strings.HasPrefix`, allowing crafted `git_object_directory` values to bypass quarantine-path validation - (File: `internal/git/localrepo/paths.go`)

### Summary
The Curves report's root cause is a *deterministic, attacker-computable identifier* ("CURVES N", where N is a predictable counter) that is checked for uniqueness/validity using a simple string comparison, letting a user pre-empt or collide with it. The equivalent pattern in Gitaly is `ObjectDirectoryPath`'s validation of a repository's object-directory override against an expected "quarantine" directory name, where the expected name is a deterministic SHA1-based hash of the repository's relative path (public/known information to any caller who knows the relative path) and the containment check is done with `strings.HasPrefix` rather than exact/segment-aware path comparison.

### Finding Description
`storage.QuarantineDirectoryPrefix` computes a "secret-looking" but fully deterministic value from only the repository's relative path: [1](#0-0) 

Any caller who knows (or controls) the `relative_path` of a `Repository` message can independently compute this exact same prefix client-side — it is not a secret, random, or server-generated token; it is `sha1("<relative_path>")[:8]`, hex-encoded and wrapped as `quarantine-<hash>-`.

`ObjectDirectoryPath` then uses this predictable value to decide whether a caller-supplied `GitObjectDirectory` field (part of the standard `Repository` protobuf message sent on virtually every RPC, see `git_object_directory` / `git_alternate_object_directories` in `proto/shared.proto`) is a legitimate transaction/hook quarantine directory: [2](#0-1) 

The check is a `strings.HasPrefix(absoluteObjectDirectoryPath, expectedQuarantinePrefix)` — a raw substring/prefix comparison on a path string, not a proper path-segment-bound comparison. Because:
1. the "secret" prefix is fully derivable by the caller from public information (their own repo's relative path), and
2. the match is a loose string-prefix test rather than an exact directory-name or path-segment match,

a caller can construct (or has *already* have write access to, e.g. via the storage's temp directory used by unrelated legitimate temp-directory helpers such as `tempdir.NewWithPrefix` in `internal/tempdir/tempdir.go`) a sibling directory name that shares the same string prefix as the legitimate quarantine directory but is not actually the transaction-created quarantine directory. `os.MkdirTemp(root, prefix)` in `tempdir.newDirectory` appends a random suffix directly onto whatever prefix is given, so a directory such as `quarantine-<hash>-evilXXXXXX` created by an unrelated legitimate temp-dir consumer, or a name deliberately colliding with the prefix pattern, would satisfy the `HasPrefix` check for a *different* repository sharing the same 8-byte SHA1 truncation, or for a maliciously staged directory that merely begins with the expected string.

This mirrors the Curves bug class precisely: a deterministic "next" identifier (there, an incrementing counter; here, a truncated hash of a known input) is relied upon as an implicit authorization/validation token, and the comparison used to validate it (exact-equality of symbol there, `HasPrefix` here) is not robust against a caller who can compute or approximate the same identifier.

### Impact Explanation
If exploited, a caller could get Gitaly to treat an attacker-influenced directory as if it were the repository's legitimate quarantine object directory, potentially causing Gitaly to read or accept objects from an unintended location (`ObjectDirectoryPath` is used to resolve the effective object directory for object lookups/writes). At minimum, since the prefix is only 8 bytes of a truncated SHA1 (16 hex chars) and matched with a permissive `HasPrefix`, this weakens the intended guarantee described in the code's own comment ("these have a repository-specific prefix which we must check in order to determine whether the quarantine directory does in fact belong to the repo at hand") — the check does not actually provide that guarantee against a party who can predict or brute-force-collide the prefix or control adjacent directory names in the shared per-storage temp directory.

### Likelihood Explanation
The relative path of a repository is either known to its own operators/pushers or discoverable, making the "secret" prefix trivially computable by the very party whose requests are being validated. The temp directory (`locator.TempDir`) is shared across many concurrent operations (quarantines, hook restores, repository removals, etc. — see `internal/tempdir/tempdir.go` and `internal/gitaly/repoutil/remove.go`), increasing the chance of directory names that legitimately or maliciously satisfy the loose prefix check. This is reachable from ordinary RPC paths that set `GitObjectDirectory` on a `Repository` message, without requiring any special privilege beyond ordinary repository access.

### Recommendation
- Replace the `strings.HasPrefix` string check with an exact match on the parsed path segment (e.g., verify that `filepath.Base` of the quarantine directory equals `expectedQuarantinePrefix + <opaque-random-suffix>` using `filepath.Rel`/segment splitting, not raw substring containment).
- Consider deriving the quarantine directory name from a value that is not purely a function of caller-known input (e.g., mix in a per-transaction random nonce known only to Gitaly, or the full untruncated hash) so the expected prefix cannot be pre-computed or approximated by the caller.
- Add defense-in-depth by verifying the quarantine directory was actually created and registered by the current transaction (e.g., checked against an in-memory/transaction-scoped registry) instead of relying solely on filename pattern matching.

### Proof of Concept
Conceptual PoC (illustrates the collision, not a full working exploit given available tooling):
1. Attacker knows/controls a repository with `RelativePath = "attacker/repo.git"`.
2. Compute `expectedQuarantinePrefix = "quarantine-" + hex(sha1("attacker/repo.git")[:8]) + "-"` exactly as `storage.QuarantineDirectoryPrefix` does — this is fully public computation, requiring only the known relative path, matching the deterministic construction shown in the test vectors: [3](#0-2) 
3. Craft or locate a directory inside the storage's shared temp directory (`locator.TempDir`) whose name starts with this exact string (e.g., by racing directory creation via another temp-dir consumer that uses attacker-influenced prefixes, or via any RPC that lets the attacker choose a temp-dir prefix).
4. Send an RPC setting `Repository.GitObjectDirectory` to point at that crafted path.
5. `ObjectDirectoryPath` will pass the `strings.HasPrefix` check in `internal/git/localrepo/paths.go:71` even though the directory is not the transaction's genuine quarantine directory, since the prefix check does not validate the directory boundary or verify a nonce that only the legitimate transaction possesses.

// QuarantineDirectoryPrefix returns a prefix for use in the temporary directory. The prefix is
// based on the relative repository path and will stay stable for any given repository. This allows
// us to verify that a given quarantine object directory indeed belongs to the repository at hand.
// Ideally, this function would directly be located in the quarantine module, but this is not
// possible due to cyclic dependencies.
func QuarantineDirectoryPrefix(repo Repository) string {
	hash := [20]byte{}
	if repo != nil {
		hash = sha1.Sum([]byte(repo.GetRelativePath()))
	}
	return fmt.Sprintf("quarantine-%x-", hash[:8])
}

func TestQuarantineDirectoryPrefix(t *testing.T) {
	// An nil repository works alright, even if nonsensical.
	require.Equal(t, "quarantine-0000000000000000-", QuarantineDirectoryPrefix(nil))

	// A repository with only a relative path.
	require.Equal(t, "quarantine-8843d7f92416211d-", QuarantineDirectoryPrefix(&gitalypb.Repository{

	}))
