Audit Report

## Title
`payout_stakers` marks era/page rewards as claimed before the pot-to-staker transfer is confirmed to succeed, permanently stranding staker rewards on transfer failure - (File: substrate/frame/staking-async/src/pallet/impls.rs)

## Summary
In `pallet-staking-async`'s non-minting ("DAP") reward mode, `do_payout_stakers_by_page` calls `Eras::<T>::set_rewards_as_claimed(era, &stash, page)` unconditionally before any actual balance transfer from the era's staker-rewards pot to payees is attempted [1](#0-0) . The actual transfer happens later per-payee inside `make_payout_from_provider`, and if `T::Currency::transfer(&staker_rewards_pot, &payout_account, amount, Preservation::Expendable)` fails, the function only logs the error and returns `None`, without reverting the claimed flag or propagating any error from the dispatchable [2](#0-1) .

## Finding Description
`do_payout_stakers_by_page` sets the page as claimed at line 386, then continues to compute `validator_staker_payout_for_page` and iterate over nominators in `payout_from_provider`, calling `make_payout_from_provider` for each payee [3](#0-2) . Inside `make_payout_from_provider`, a failed `T::Currency::transfer` call is logged and the function returns `None`, which is a value silently dropped by the caller (no event, no error, no rollback) [4](#0-3) . Because the claimed-flag mutation happens before and independently of the transfer outcome, and because failures degrade to a silent `None` rather than a `DispatchError`, the extrinsic returns `Ok(...)` and the page becomes permanently `AlreadyClaimed`, with no retry mechanism analogous to the `Pay` trait's `Attempted`/`check_status`/`retry_payment` flow used elsewhere in the codebase (e.g. treasury/bounties) [5](#0-4) .

The claimed feeding path (`snapshot_era_rewards`) that funds the era pot also silently swallows transfer failures, zeroing `actual_staker`/`actual_incentive` on error while depositing that zero into an `EraRewardAllocation` that later drives `ErasValidatorReward`, corroborating the possibility of an underfunded era pot relative to promised payouts [6](#0-5) .

## Impact Explanation
If the era's staker-rewards pot balance is less than what per-page computed payouts require (through legitimate `Preservation::Preserve`/dust effects during snapshotting, rounding drift across `Perbill` splits over many pages/nominators, or a partially-failed `snapshot_era_rewards`), affected nominators/validators are permanently marked `AlreadyClaimed` while never receiving their tokens. This is a genuine, permanent, unbacked loss of staker reward funds with no recovery path from the extrinsic itself — falling under "permanent user-fund lock" in the impact gate, since it silently and irreversibly denies rightful beneficiaries their reward.

## Likelihood Explanation
The failure path is reachable purely through internal balance-arithmetic conditions (dust, rounding across `Perbill` splits, `Preservation::Preserve` vs `Expendable` boundary effects) rather than requiring any malicious actor, governance action, or privileged capability. `payout_stakers`/`payout_stakers_by_page` is a permissionless, signed-origin-only extrinsic callable by anyone routinely as the default reward-payout path when `DisableMinting = true`. However, I was not able to construct or run a concrete numeric reproduction within this read-only investigation to confirm how large a dust/rounding gap must be in a realistic configuration (`MaxExposurePageSize`, real `Perbill` splits) to force `T::Currency::transfer`'s `Preservation::Expendable` call to actually fail in practice — this would require exercising `substrate/frame/staking-async/src/tests/payout_stakers.rs` with an intentionally underfunded pot, which is unverified.

## Recommendation
Do not call `Eras::<T>::set_rewards_as_claimed` until the transfer(s) for the page are confirmed successful, or make the claim atomic with the transfer outcome — e.g., propagate errors from `make_payout_from_provider` up through `do_payout_stakers_by_page` and abort/roll back the page's claim on failure rather than degrading silently to `None`. Alternatively, adopt a two-phase `Pay`-trait-like state machine (`Attempted` → `check_status` → `Succeeded`/`Failed`, with `retry_payment`) as used by `pallet-treasury`/bounties, so a failed transfer leaves the page retryable. At minimum, add a `try_state` invariant asserting that the sum implied by the claimed-rewards bitmap never exceeds actual paid-out balance from the pot.

## Proof of Concept
Conceptual reproduction path (not executed):
1. Configure `DisableMinting = true` (DAP mode) as in `substrate/frame/staking-async/src/tests/payout_stakers.rs`.
2. Arrange for the era's staker-rewards pot (`RewardPot::Era(era, RewardKind::StakerRewards)`) to hold less than the sum of per-page payouts implied by `ErasValidatorReward`/`get_paged_exposure` for a page, e.g. by reducing the pot balance below the computed page payout between snapshot and `payout_stakers` call.
3. Call `payout_stakers(origin, validator_stash, era)` as any signed account for the affected page.
4. Observe `Eras::<T>::set_rewards_as_claimed` executes unconditionally at [7](#0-6) , then `make_payout_from_provider`'s transfer fails and silently returns `None` at [4](#0-3) .
5. Result: extrinsic returns `Ok(...)`, staker balance unchanged, but the page is flagged claimed; subsequent calls fail with `Error::<T>::AlreadyClaimed`, permanently denying the reward.

This numeric feasibility (how easily the pot can actually become underfunded relative to computed payouts under `Preservation::Expendable`) is unverified and would require running the existing test harness with a deliberately underfunded pot.

	/// Payout stakers from an era reward pot (transfer-based, no minting).
	fn payout_from_provider(
		era: EraIndex,
		stash: &T::AccountId,
		validator_payout: BalanceOf<T>,
		exposure: &crate::PagedExposure<T::AccountId, BalanceOf<T>>,
		overview_own: BalanceOf<T>,
		total_nominator_payout: BalanceOf<T>,
	) -> u32 {
		let mut nominator_payout_count: u32 = 0;

		if let Some((amount, dest)) = Self::make_payout_from_provider(era, stash, validator_payout)
		{
			Self::deposit_event(Event::<T>::Rewarded { stash: stash.clone(), dest, amount });
		}

		let total_nominator_stake = exposure.total().saturating_sub(overview_own);
		for nominator in exposure.others().iter() {
			let nominator_exposure_part =
				Perbill::from_rational(nominator.value, total_nominator_stake);
			let nominator_reward: BalanceOf<T> =
				nominator_exposure_part.mul_floor(total_nominator_payout);

			if let Some((amount, dest)) =
				Self::make_payout_from_provider(era, &nominator.who, nominator_reward)
			{
				nominator_payout_count.saturating_inc();
				Self::deposit_event(Event::<T>::Rewarded {
					stash: nominator.who.clone(),
					dest,
					amount,
				});
			}
		}

		nominator_payout_count
	}
