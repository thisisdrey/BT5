### Title
Unauthenticated `RecvError` packets can tear down an established tunnel by address-spoofing alone - (File: outside.go)

### Summary
The external report describes a class of bug where one code path pre-emptively writes a terminal/derived state (`Settled`) without recording *why* it got there, and a second, independent code path consumes only that coarse status flag to authorize a privileged action — bypassing the extra check the original state transition was supposed to require. The Nebula analog is the `RecvError` control-message handler: it is processed **before** any packet decryption/authentication (unlike `Message`, `LightHouse`, `Test`, `CloseTunnel`, `Control` types, which are all AEAD-decrypted first), and the only "check" performed afterwards is a plaintext source-address match against the value cached in the `HostInfo`. That address match plays the same role as the loose `offerStatus == Settled` check in the report: it is necessary-looking but insufficient, and it authorizes tearing down real tunnel state.

### Finding Description
In `readOutsidePackets`, `header.RecvError` is dispatched immediately, before the encrypted/authenticated packet path: [1](#0-0) 

`handleRecvError` then validates the packet using only a plaintext source-address comparison against the `HostInfo`'s last known remote, with no cryptographic authentication of the message itself: [2](#0-1) 

If the address matches (or there is no address recorded yet — `hr.IsValid()` is false), the handler unconditionally calls `f.closeTunnel(hostinfo)` and `f.handshakeManager.DeleteHostInfo(hostinfo)`, destroying an authenticated, active tunnel: [3](#0-2) 

The gating before this is only a config-driven rate-limit acceptance check (`acceptRecvErrorConfig.ShouldRecvError`), not a certificate or session-key check: [4](#0-3) 

This mirrors the report's root cause: a status/consequence produced by one flow (`abortAskOffer` setting `Settled`) is treated by a downstream consumer (`closeBidTaker`) as sufficient proof of the specific precondition it actually needs (a genuine maker settlement), when it isn't. Here, "the packet type is `RecvError` and the source IP matches" is treated as sufficient proof that the legitimate remote peer lost its receive state, when it is not — no possession of the session's Noise keys or the peer's CA-signed certificate is required to produce that plaintext condition, only a spoofed/guessed UDP header at the right `RemoteIndex`.

### Impact Explanation
An attacker who does not hold a CA-signed certificate for the mesh, but who can (a) observe or guess a victim's 32-bit local index (echoed in cleartext handshake/message headers and by design not secret) and (b) send a UDP datagram appearing to originate from the victim's current remote address (source-address spoofing is possible on many networks/paths that don't enforce BCP38, or simply an on-path/off-path attacker without a Nebula identity), can force `closeTunnel` + `DeleteHostInfo` on the target's real hostinfo. This is a remote state-poisoning / denial-of-service primitive against an already-established, mutually authenticated tunnel, achievable entirely from the pre-authentication packet path (the `header.RecvError` case is handled before `hostinfo.ConnectionState.Decrypt`), consistent with the allowed impact categories (remote state poisoning / firewall-adjacent session teardown).

### Likelihood Explanation
Reaching this code requires only: knowledge of the target's UDP endpoint (learnable via lighthouse queries, which are also not authenticated against a specific requester's identity beyond remote-allow-list IP filtering) and the `RemoteIndex` for an active session (visible in any packet header on the wire, including ones an off-path attacker might capture, or brute-forceable across the 32-bit space with less friction than forging a Noise/AEAD packet). No CA-signed certificate, private key, or completed handshake is required by the attacker to reach and trigger `handleRecvError`. The `acceptRecvErrorConfig.ShouldRecvError` gate is a rate/enable check, not an authentication check.

### Recommendation
Do not act on `RecvError` based solely on address/index matching. At minimum:
- Require `RecvError` handling to be authenticated (e.g., embed a MAC keyed by the session's Noise keys, or require the sender to additionally prove receipt of a fresh nonce/challenge) before calling `closeTunnel`/`DeleteHostInfo`.
- Alternatively, treat `RecvError` as an advisory-only signal that triggers a re-handshake/keepalive probe rather than an unconditional teardown, so a spoofed packet can at most trigger extra traffic, not loss of an authenticated tunnel.

### Proof of Concept
1. Establish a normal tunnel between `A` and `B`; observe (or infer) `B`'s `localIndexId` for the tunnel with `A` from any packet header sent over the path (headers are cleartext: version/type/subtype/index/counter).
2. From attacker `M` (no CA cert, no Noise keys), craft a UDP packet to `A`'s listener with:
   - source IP:port spoofed to `B`'s currently-recorded remote (`hr` in `handleRecvError`), or sent while `A` has no remote recorded for `B` yet,
   - `header.H{Type: header.RecvError, RemoteIndex: <B's index at A>}`.
3. `A`'s `readOutsidePackets` dispatches this directly to `handleRecvError` without decrypting or authenticating it: [5](#0-4) .
4. `handleRecvError` finds the hostinfo by reverse index, sees the (spoofed) address matches (or is unset), and calls `closeTunnel` + `DeleteHostInfo`, destroying `A`'s real, authenticated tunnel to `B`: [6](#0-5) .
5. `A` must now redo a full handshake with `B`, and repeated forged `RecvError` packets can indefinitely disrupt the tunnel — all without `M` ever possessing a certificate signed by the network's CA.

func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
