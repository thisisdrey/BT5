### Title
Unstaked peer connection cap evaded via per-connection pubkey rotation (self-signed TLS cert spoofing) - (streamer/src/nonblocking/swqos.rs)

### Summary
`SwQos::cache_new_connection` derives the `ConnectionTableKey` used to enforce `max_connections_per_unstaked_peer` from `ConnectionTableKey::new(remote_addr.ip(), conn_context.remote_pubkey)`, where `remote_pubkey` is extracted from the client's self-signed QUIC/TLS certificate via `get_connection_stake`. Because an unstaked client fully controls the keypair used to generate that certificate, it can present a fresh pubkey on every connection attempt, causing each connection to look like a "new peer" with zero prior connections, defeating the per-peer cap while a single source IP accumulates many entries in the shared `unstaked_connection_table`.

### Finding Description
`SwQos::try_add_connection` and `cache_new_connection` compute the per-peer limit key as: [1](#0-0) 
`ConnectionTableKey::new(remote_addr.ip(), conn_context.remote_pubkey)` is passed to `ConnectionTable::try_add_connection` together with `max_connections_per_peer` (which is `self.config.max_connections_per_unstaked_peer` for unstaked peers). `conn_context.remote_pubkey` comes from `get_connection_stake(connection, &self.staked_nodes)`, populated in `build_connection_context`: [2](#0-1) 
Because the pubkey is read out of the client's own (self-signed) TLS certificate rather than any authenticated/staked identity, an unstaked attacker can generate a brand-new keypair for every QUIC handshake from the same source IP. Each such connection carries a distinct `remote_pubkey`, so `ConnectionTableKey::new` produces a distinct key per connection. Since the per-peer cap in `ConnectionTable::try_add_connection` counts entries under a single key, a never-before-seen key always starts at 0 prior connections and is never rejected by `max_connections_per_unstaked_peer`, regardless of how many connections the same IP has already opened under other spoofed pubkeys.

The only remaining backstop is the global unstaked table size limit, enforced via `prune_unstaked_connection_table`/`prune_oldest` against `self.config.max_unstaked_connections`: [3](#0-2) 
This is a *global* LRU-style cap shared by all unstaked IPs, not a per-source-IP cap. Consequently, a single attacking IP that rotates pubkeys can consume connections up to the entire global `max_unstaked_connections` budget (evicting the oldest entries, which may belong to other legitimate unstaked peers) instead of being restricted to `max_connections_per_unstaked_peer`, because there is no IP-keyed accounting anywhere in this path — only pubkey-keyed per-peer accounting and a global total.

### Impact Explanation
This is a QoS/connection-limit evasion: a single unprivileged, unstaked remote IP can occupy a disproportionate share (up to the full `max_unstaked_connections` global slot pool) of a leader's unstaked QUIC connection capacity by trivially minting new self-signed keypairs per connection, instead of being bounded to `max_connections_per_unstaked_peer` connections. This degrades or starves other legitimate unstaked senders' ability to obtain TPU connection slots, matching the "QoS evasion / unfair capture of connection or per-IP limits" bounty category referenced in the question.

### Likelihood Explanation
Feasibility is high: generating fresh Ed25519 keypairs and building a new self-signed QUIC client certificate per connection is cheap and requires no special privileges, staking, or validator control — only network access to the leader's public TPU QUIC port. The attack is fully repeatable and scriptable (open connection → distinct keypair → repeat), with no rate limiting on pubkey generation itself.

### Recommendation
Enforce the unstaked per-peer connection cap using a key that includes the source IP unconditionally (e.g., always cap connections per `IpAddr` for unstaked peers, in addition to or instead of per-pubkey), so that pubkey rotation cannot reset the counted connection count for a given source IP. Concretely, change `ConnectionTableKey::new` usage (or add a parallel accounting structure) so `max_connections_per_unstaked_peer` is applied against `ConnectionTableKey::IP(remote_addr.ip())` for `ConnectionPeerType::Unstaked`, reserving pubkey-based keying only for connections whose stake has actually been verified (staked peers).

### Proof of Concept
Rust integration test plan (in `streamer/src/nonblocking/swqos.rs` test module, using `dev-context-only-utils` test helpers already present, e.g. `SwQosConfig::default_for_tests`):
1. Construct an `SwQos` with `SwQosConfig { max_connections_per_unstaked_peer: 1, max_unstaked_connections: 100, .. }`.
2. Simulate N (e.g. 10) unstaked connection attempts from the *same* `remote_address.ip()` but with a distinct freshly-generated `Pubkey` in `conn_context.remote_pubkey` for each (mirroring what a self-signed cert rotation produces via `get_connection_stake`).
3. Call `SwQos::try_add_connection` for each simulated connection context.
4. Assert (expected failing invariant): total accepted connections whose `remote_address.ip()` equals the attacker IP should be capped at `max_connections_per_unstaked_peer` (i.e., 1). The current implementation will instead accept up to `min(N, max_unstaked_connections)` connections, demonstrating the per-IP cap bypass.
5. A companion fuzz/property test can assert: for any sequence of connection attempts from a fixed IP with distinct pubkeys, `count_connections_with_ip(ip) <= max_connections_per_unstaked_peer` — this invariant currently fails.

    fn prune_unstaked_connection_table(
        &self,
        unstaked_connection_table: &mut ConnectionTable<ConnectionStreamCounter>,
        max_unstaked_connections: usize,
        stats: Arc<StreamerStats>,
    ) {
        if unstaked_connection_table.total_size >= max_unstaked_connections {
            // Prune the connection table down to 90% capacity
            const PRUNE_TABLE_RATIO: f64 = 0.90;
            let max_connections = (PRUNE_TABLE_RATIO * (max_unstaked_connections as f64)) as usize;
            let num_pruned = unstaked_connection_table.prune_oldest(max_connections);
            stats
                .num_evictions_unstaked
                .fetch_add(num_pruned, Ordering::Relaxed);
        }
    }

    async fn prune_unstaked_connections_and_add_new_connection(
        &self,
        client_connection_tracker: ClientConnectionTracker,
        connection: &Connection,
        connection_table: Arc<Mutex<ConnectionTable<ConnectionStreamCounter>>>,
        max_connections: usize,
        conn_context: &SwQosConnectionContext,
    ) -> Result<
        (
            Arc<AtomicU64>,
            CancellationToken,
            Arc<ConnectionStreamCounter>,
        ),
        ConnectionHandlerError,
    > {
        let stats = self.stats.clone();
        if max_connections > 0 {
            let mut connection_table = connection_table.lock().await;
            self.prune_unstaked_connection_table(&mut connection_table, max_connections, stats);
            self.cache_new_connection(
                client_connection_tracker,
                connection,
                connection_table,
                conn_context,
            )

            connection.close(
                CONNECTION_CLOSE_CODE_DISALLOWED.into(),
                CONNECTION_CLOSE_REASON_DISALLOWED,
            );
            Err(ConnectionHandlerError::ConnectionAddError)
        }
    }

    fn build_connection_context(&self, connection: &Connection) -> SwQosConnectionContext {
        let remote_address = connection.remote_address();
        get_connection_stake(connection, &self.staked_nodes).map_or(
            SwQosConnectionContext {
                peer_type: ConnectionPeerType::Unstaked,
                total_stake: 0,
                remote_pubkey: None,
                in_staked_table: false,
                remote_address,
                stream_counter: None,
                last_update: Arc::new(AtomicU64::new(timing::timestamp())),
            },
            |(pubkey, stake, total_stake)| {
                // The heuristic is that the stake should be large enough to have 1 stream pass through within one throttle
                // interval during which we allow max (MAX_STREAMS_PER_MS * STREAM_THROTTLING_INTERVAL_MS) streams.

                let peer_type = {
                    let max_streams_per_ms = self.staked_stream_load_ema.max_streams_per_ms();
                    let min_stake_ratio =
                        1_f64 / (max_streams_per_ms * STREAM_THROTTLING_INTERVAL_MS) as f64;
                    let stake_ratio = stake as f64 / total_stake as f64;
                    if stake_ratio < min_stake_ratio {
                        // If it is a staked connection with ultra low stake ratio, treat it as unstaked.
                        ConnectionPeerType::Unstaked
                    } else {
                        ConnectionPeerType::Staked(stake)
                    }
                };

                SwQosConnectionContext {
                    peer_type,
                    total_stake,
                    remote_pubkey: Some(pubkey),
                    in_staked_table: false,
                    remote_address,
                    last_update: Arc::new(AtomicU64::new(timing::timestamp())),
                    stream_counter: None,
                }
            },
        )
    }
