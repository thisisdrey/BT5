Based on my analysis of the marginfi-v2 fee-accounting architecture, this bug class does not have a valid unprivileged-user analog in the marginfi codebase.

**Why the analog doesn't transfer:**

In Portfolio.sol, the protocol fee is (a) credited as a registry balance claim AND (b) simultaneously reinvested into the AMM's virtual reserves (`virtualX`/`virtualY`), inflating LP claims on the same underlying tokens without a matching increase to the global reserve — a genuine double-count.

marginfi's interest/fee model is structurally different and explicitly designed to avoid this pattern:

1. During `accrue_interest`, `liability_share_value` grows by the full `borrowing_rate_apr` (which includes insurance/group/protocol fee components), while `asset_share_value` grows only by the `lending_rate_apr` (fee-free). The gap between these is what funds the separately tracked `collected_insurance_fees_outstanding`, `collected_group_fees_outstanding`, and `collected_program_fees_outstanding` fields — it is never added a second time into `asset_share_value`/`total_asset_shares`, so LPs cannot double-claim it. [1](#0-0) [2](#0-1) 

2. The codebase contains explicit invariant tests confirming that `total_assets + fees_collected - total_liabilities` is conserved across accrual (i.e., fees are subtracted from net assets exactly once, not reinvested into share value), which is precisely the invariant that was broken in the Portfolio.sol bug. [3](#0-2) [4](#0-3) 

3. Outstanding fees are only realized as actual token movements via the permissionless `lending_pool_collect_bank_fees` instruction, which transfers `min(outstanding, available_liquidity)` from the `liquidity_vault` to the insurance/fee/program destinations and decrements the outstanding counters — there is no "reinvestment" step that simultaneously credits the fee to a claimable balance and folds it back into pool shares. [5](#0-4) 

4. The origination fee path (the closest analog to a "swap fee") likewise only adds to `collected_group_fees_outstanding`/`collected_program_fees_outstanding` as a claim against the liquidity vault; it does not also inflate `total_asset_shares` or any LP-facing reserve.
