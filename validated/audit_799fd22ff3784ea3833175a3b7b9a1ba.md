## Title
Semantic overloading of `AddCA`'s error return conflates "CA rejected" with "CA added but expired" - (File: cert/ca_pool.go)

### Summary
`CAPool.AddCA` uses its single `error` return value to mean two different things: (1) the CA was rejected and never added to the pool, and (2) the CA was successfully added to the pool but is currently expired. Standard Go convention treats a non-nil error as "the operation did not take effect," but here `ErrExpired` is returned *after* the CA has already been inserted into `ncp.CAs`. This is the same class of bug as the reported Audius `No` outcome overload: a single sentinel value stands for two materially different states, which is confusing for callers and creates exactly the kind of trap that leads to regressions.

### Finding Description
In `cert/ca_pool.go`, `AddCA` does: [1](#0-0) 

```go
func (ncp *CAPool) AddCA(c Certificate) error {
	if !c.IsCA() { ... }
	if !c.CheckSignature(c.PublicKey()) { ... }
	...
	ncp.CAs[sum] = cc          // <-- CA is added to the pool here

	if c.Expired(time.Now()) {
		return fmt.Errorf("%s: %w", c.Name(), ErrExpired)   // <-- but an error is still returned
	}
	return nil
}
```

Every other failure branch (`ErrNotCA`, `ErrNotSelfSigned`, fingerprint failure) returns *before* `ncp.CAs[sum] = cc` runs, so for those paths "error returned" correctly means "not added." Only the `ErrExpired` branch breaks that invariant: the CA is inserted into the trust pool's map, and the returned error is purely informational about its expiry state, not about whether it was trusted/added.

This overload is deliberately exploited at exactly one call site, `cmd/nebula-cert/verify.go`: [2](#0-1) 

```go
caPool, err := cert.NewCAPoolFromPEMReader(caReader)
if err != nil && !errors.Is(err, cert.ErrExpired) {
	return fmt.Errorf("error while adding ca cert to pool: %w", err)
}
```

That code has to special-case `ErrExpired` to avoid discarding a pool that actually succeeded in loading CAs. Any other current or future caller of `AddCA`/`AddCAFromPEM`/`NewCAPoolFromPEMReader` that follows the normal Go idiom ("if err != nil, treat as not-applied") will incorrectly assume an expired CA was never added to the trust pool, when in fact `ncp.CAs` now contains it and it remains usable by `GetCAForCert`/`verify` for validating certificate chains until/unless the caller separately checks expiry again (`verify` in `ca_pool.go` does check `signer.Certificate.Expired(now)` at cert-verification time, but that's a second, independent check that a caller relying purely on `AddCA`'s error would not know is necessary).

### Impact Explanation
The direct impact is limited to confusion/maintenance risk rather than an immediate bypass in the current codebase, because the one production caller (`verify.go`) and `CAPool.verify()` both re-check expiry independently at certificate-verification time. However, this is precisely the "semantic overload" bug class from the report: a caller of `AddCA` (or a future refactor of `NewCAPoolFromPEMReader`) that reasonably treats a non-nil error as "operation failed, CA not trusted" will silently miss that the CA is in fact live in the pool. If a future code path builds a `CAPool` and short-circuits on `AddCA` error without the `errors.Is(err, ErrExpired)` special case (e.g., a new consumer of the `cert` package, or an internal refactor of PKI reload logic), it could either (a) leak a CA into the trust pool it believed it discarded, or (b) discard a pool it believed was populated - either of which is a certificate-verification-bypass or CA-pool-trust-confusion risk reachable purely from processing an attacker-influenceable CA bundle (e.g., during PKI reload/config parsing), with no valid, non-expired CA-signed certificate required to trigger the ambiguous state.

### Likelihood Explanation
Low-to-moderate. It requires a code path that adds CA certificates to a `CAPool` and does not replicate the same `errors.Is(err, cert.ErrExpired)` carve-out that `verify.go` uses. Today only one call site exists and it handles this correctly, so there is no exploitable path in the current binary. The likelihood is about future regressions/new callers (library consumers of `github.com/slackhq/nebula/cert`, or PKI reload code) misinterpreting the return value, matching the report's own framing ("may open the door to regressions in future updates").

### Recommendation
Split the overloaded return value the same way the original report recommends splitting the `No` outcome:
- Do not return an error from `AddCA` for the "added but expired" case; instead, return `nil` (added successfully) and expose the expiry state via a separate mechanism, e.g. a method like `(*CAPool) IsCAExpired(fingerprint string) bool`, or a `Warnings []error` field on `NewCAPoolFromPEMReader`.
- Alternatively, introduce a distinct error type/wrapper (e.g., `ErrCAAddedButExpired`) that is clearly *not* `errors.Is(err, ErrExpired)`-equivalent to a "totally rejected" error, and document that callers must check for it before treating a non-nil `AddCA` error as "not added."
- Update `cmd/nebula-cert/verify.go` and any other caller accordingly, and add a doc comment on `AddCA` explicitly stating the current dual meaning until it's fixed.

### Proof of Concept
```go
ca, _, caKey, _ := NewTestCaCert(Version2, Curve_CURVE25519,
    time.Now().Add(-2*time.Hour), time.Now().Add(-1*time.Hour), // already-expired validity window
    nil, nil, nil)

pool := cert.NewCAPool()
err := pool.AddCA(ca)
// err != nil (ErrExpired) — a caller using the standard Go idiom below
// wrongly assumes the CA was never added:
if err != nil {
    // "not added" assumption — WRONG: ca is already in pool.CAs
}

fp, _ := ca.Fingerprint()
_, stillThere := pool.CAs[fp]
fmt.Println(stillThere) // true — CA is fully present in the trust pool despite the "error"
```
This demonstrates that `err != nil` from `AddCA` does not reliably mean "not added to pool," confirming the semantic overload.

```go
// AddCA verifies a Nebula CA certificate and adds it to the pool.
func (ncp *CAPool) AddCA(c Certificate) error {
	if !c.IsCA() {
		return fmt.Errorf("%s: %w", c.Name(), ErrNotCA)
	}

	if !c.CheckSignature(c.PublicKey()) {
		return fmt.Errorf("%s: %w", c.Name(), ErrNotSelfSigned)
	}

	sum, err := c.Fingerprint()
	if err != nil {
		return fmt.Errorf("could not calculate fingerprint for provided CA; error: %w; %s", err, c.Name())
	}

	cc := &CachedCertificate{
		Certificate:    c,
		Fingerprint:    sum,
		InvertedGroups: make(map[string]struct{}),
	}

	for _, g := range c.Groups() {
		cc.InvertedGroups[g] = struct{}{}
	}

	ncp.CAs[sum] = cc

	if c.Expired(time.Now()) {
		return fmt.Errorf("%s: %w", c.Name(), ErrExpired)
	}

	return nil
```
