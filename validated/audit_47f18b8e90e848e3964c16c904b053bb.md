### Title
Permissionless `LendingPoolEmissionsDeposit` allows first-depositor share-value inflation / donation attack on marginfi banks - (File: `programs/marginfi/src/instructions/marginfi_group/configure_bank.rs`)

### Summary
`lending_pool_emissions_deposit` is a fully unprivileged, signer-only instruction that lets any user transfer tokens of the bank's own mint directly into the bank's `liquidity_vault` and, in the same call, force-recompute `bank.asset_share_value` from `(current_assets + donated_amount) / total_asset_shares` [1](#0-0) . This is the on-chain equivalent of the reported "send tokens to the vault + `UpdateVaultBalance`" primitive that skews the share-to-asset ratio without going through the normal minting path.

### Finding Description
The instruction's accounts require only a `Signer` `depositor` and a same-mint `emissions_funding_account`; there is no admin/authority check [2](#0-1) . Any user can call it against any bank that already has `total_asset_shares > 0` [3](#0-2) .

The handler transfers `amount` tokens into the liquidity vault and then recomputes the share value directly as `assets_after / total_asset_shares`, mutating `bank.asset_share_value` in place [4](#0-3) . Critically, this donation does **not** mint any new `asset_shares` to the caller — it only re-prices existing shares. If the attacker is the bank's only/first depositor (arranged by depositing a small amount first), 100% of the donated value re-prices onto the attacker's own shares.

Deposits elsewhere convert `value` into shares via straightforward division `get_asset_shares(value) = value / asset_share_value` [5](#0-4) , with no virtual-shares/decimal-offset protection against a heavily inflated `asset_share_value`. This is the same `increase_balance_internal` path used by normal `deposit`/`juplend_deposit` flows [6](#0-5) .

Sequence:
1. Attacker deposits a small amount `X` into a fresh/near-empty bank, becoming (effectively) sole shareholder with `X` shares at `asset_share_value = 1`.
2. Attacker calls `lending_pool_emissions_deposit` with a large donation `D`, forcing `asset_share_value` to jump to `(X + D) / X`.
3. A victim deposits `Y` tokens. Their minted shares are `Y / asset_share_value = Y·X / (X + D)`, which can be driven arbitrarily small relative to `Y` if `D >> X`.
4. Attacker (holding essentially all of `X` shares) can withdraw, redeeming a share of the pooled assets (including the victim's `Y`) disproportionate to their true economic contribution, capturing most of the value the victim deposited.

### Impact Explanation
This allows an unprivileged attacker to manipulate a bank's `asset_share_value` accounting to disadvantage subsequent depositors and redirect their deposited value to the attacker's own position — a form of unauthorized value transfer/theft within the bank's core accounting mechanism, matching the reported bug class (share/PPS inflation harming the first/early depositor). It directly touches `bank.asset_share_value` and `total_asset_shares`, the fields the fuzz-suite's own solvency invariant treats as sacrosanct [7](#0-6) .

### Likelihood Explanation
Likelihood is constrained by economics rather than access control: the attacker must actually own and irrevocably donate real tokens (`D`) to achieve the price skew, and I80F48 has fine (48-bit) fractional precision, so achieving a complete "round-to-zero" theft of a normal-sized victim deposit requires an extremely large, costly donation. It is most practical against low-liquidity/newly created banks where `X` (existing shares) is tiny, making the required `D` to skew pricing meaningfully smaller. The instruction itself is permissionless and requires no special role, satisfying the "unprivileged user, bank/core-accounting path" scope.

### Recommendation
- Prevent unprivileged callers from repricing `asset_share_value` via direct donation; if `lending_pool_emissions_deposit` must remain permissionless, require it to mint corresponding shares to the depositor (treat it as a normal deposit) rather than silently re-pricing all existing shares, or restrict it to an authorized emissions/rewards role.
- Enforce a minimum bank-level deposit/seed amount (e.g., a protocol/admin-seeded initial deposit that is permanently locked) before permissionless share-repricing operations are allowed, mirroring the ERC-4626 "dead shares" mitigation referenced in the external report.
- Consider adding virtual shares/asset offsets to `get_asset_shares`/`get_asset_amount` to bound the impact of small `total_asset_shares` denominators.

### Proof of Concept
1. Group admin creates a new bank `B` for mint `M`.
2. Attacker deposits `X = 1` unit into `B` via the standard `deposit` instruction, becoming the bank's only depositor (`total_asset_shares = 1`, `asset_share_value = 1`).
3. Attacker calls `lending_pool_emissions_deposit(bank=B, mint=M, amount=D)` with a large `D`, funded from the attacker's own token account, targeting `B.liquidity_vault` [8](#0-7) . This sets `asset_share_value = (X + D) / X`.
4. Victim, unaware of the manipulated price, deposits `Y` tokens into `B`. Per `get_asset_shares`, they receive only `Y·X / (X + D)` shares [5](#0-4) , i.e., a share count that undervalues their true deposit.
5. Attacker withdraws their `X` shares, which now represent `X · asset_share_value = X + D` (approximately the full pool including part of the victim's deposit `Y`), realizing a gain funded by the victim's under-priced deposit.

```rust
pub fn lending_pool_emissions_deposit(
    ctx: Context<LendingPoolEmissionsDeposit>,
    amount: u64,
) -> MarginfiResult {
    if amount == 0 {
        return Ok(());
    }

    let clock = Clock::get()?;
    let mut bank = ctx.accounts.bank.load_mut()?;
    let group = ctx.accounts.group.load()?;

    utils::validate_bank_state(&bank, utils::InstructionKind::FailsIfPausedOrReduceState)?;

    // Reject mints with non-zero transfer fees or active transfer hooks.
    let mint_ai = ctx.accounts.mint.to_account_info();
    check!(
        !utils::nonzero_fee(mint_ai.clone(), clock.epoch)?,
        MarginfiError::InvalidTransfer
    );
    check!(
        !utils::has_transfer_hook(mint_ai)?,
        MarginfiError::InvalidTransfer
    );

    let total_asset_shares = I80F48::from(bank.total_asset_shares);
    check!(
        total_asset_shares > I80F48::ZERO,
        MarginfiError::EmissionsUpdateError
    );

    bank.accrue_interest(
        clock.unix_timestamp,
        &group,
        #[cfg(not(feature = "client"))]
        ctx.accounts.bank.key(),
    )?;

    transfer_checked(
        CpiContext::new(
            ctx.accounts.token_program.key(),
            TransferChecked {
                from: ctx.accounts.emissions_funding_account.to_account_info(),
                to: ctx.accounts.liquidity_vault.to_account_info(),
                authority: ctx.accounts.depositor.to_account_info(),
                mint: ctx.accounts.mint.to_account_info(),
            },
        ),
        amount,
        ctx.accounts.mint.decimals,
    )?;

    let total_assets = bank.get_asset_amount(total_asset_shares)?;
    let updated_total_assets = total_assets
        .checked_add(I80F48::from_num(amount))
        .ok_or_else(math_error!())?;

    bank.asset_share_value = updated_total_assets
        .checked_div(total_asset_shares)
        .ok_or_else(math_error!())?
        .into();
```

```rust
pub fn assert_bank_solvency(trident: &mut Trident, bank_pk: Pubkey, tolerance: I80F48) {
    let bank = trident
        .get_account_with_type::<Bank>(&bank_pk, None)
        .expect("bank account must deserialize");

    let asset_share_value = from_wrapped(bank.asset_share_value.value);
    let liability_share_value = from_wrapped(bank.liability_share_value.value);
    let total_asset_shares = from_wrapped(bank.total_asset_shares.value);
    let total_liability_shares = from_wrapped(bank.total_liability_shares.value);

    let total_deposits = total_asset_shares
        .checked_mul(asset_share_value)
        .expect("total_deposits overflow");
    let total_liabilities = total_liability_shares
        .checked_mul(liability_share_value)
        .expect("total_liabilities overflow");

    let outstanding_fees = from_wrapped(bank.collected_group_fees_outstanding.value)
        + from_wrapped(bank.collected_insurance_fees_outstanding.value)
        + from_wrapped(bank.collected_program_fees_outstanding.value);

    let vault_balance = I80F48::from_num(token_balance(trident, bank.liquidity_vault));
    let net_vault = vault_balance - outstanding_fees;
    let net_book = total_deposits - total_liabilities;

    let drift = (net_vault - net_book).abs();

    invariant!(
        drift <= tolerance,
        "bank solvency drift > {tolerance} units. bank: {bank_pk}\n  vault_balance: {vault_balance}\n  outstanding_fees: {outstanding_fees}\n  net_vault (vault - fees): {net_vault}\n  total_deposits: {total_deposits}\n  total_liabilities: {total_liabilities}\n  net_book (deposits - liabs): {net_book}\n  drift: {drift}"
    );
```
