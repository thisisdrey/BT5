### Title
Non-atomic `updateMasterOracle()` allows sandwiching oracle-priced `Pool.swap()` to drain backing collateral - ([File: contracts/PoolRegistry.sol](contracts/PoolRegistry.sol))

### Summary
Metronome prices every synth-to-synth exchange through a single mutable `masterOracle` stored in `PoolRegistry`, and `swap()` remains fully callable while the governor replaces that oracle. `PoolRegistry.updateMasterOracle()` writes `masterOracle` in one non-atomic transaction with no pause requirement and no consistency check against current pool state. An unprivileged attacker who observes the pending `updateMasterOracle` transaction can front-run it by buying the synth whose price will rise (selling the synth whose price will fall) at the old oracle's prices, and back-run it by reversing the swap at the new oracle's prices. The profit is paid out of the Treasury's real collateral backing other users' deposits. This is the same bug class as `YuzuILP.updatePool()`: a privileged function that blindly overwrites pricing/accounting state while user operations priced off that state remain live.

### Finding Description
`PoolRegistry.updateMasterOracle()` simply stores the new oracle: [1](#0-0) 

There is no `whenPaused`, no `isSwapActive` check, no timelock, and no verification that in-flight prices are consistent with the incoming oracle. Meanwhile `Pool.swap()` quotes both legs through `poolRegistry.masterOracle()` each call, so the exchange rate between any two synthetic tokens changes discontinuously in the block where the oracle is swapped out. `Pool.toggleIsSwapActive()` exists precisely to gate swaps but is not required around the oracle update [2](#0-1) .

By contrast, the codebase's analogous pricing state in `DebtToken.updateInterestRate()` is protected: it calls `accrueInterest()` inside the same transaction, checkpointing the debt index before mutating the rate [3](#0-2) . `updateMasterOracle` has no equivalent checkpoint or gating because the "index" here is external (the oracle's quoted prices), so the price discontinuity is directly sandwichable.

Attack trace (unprivileged EOA):
1. Victim and other LPs hold collateral backing msUSD/msETH debt positions; `isSwapActive == true`.
2. Governor (or ops multisig) submits `poolRegistry.updateMasterOracle(newOracle)` where `newOracle` quotes msETH 5% higher than the old oracle (e.g., feed upgrade, price-source migration, or deployment of a corrected oracle).
3. Attacker front-runs: `pool.swap(msUSD, msETH, amountIn)` acquiring msETH at the old (cheap) price. No collateral or position is needed to swap — only synth balance, obtainable via `DebtToken.issue()` against deposited collateral or via `SmartFarmingManager.flashIssue` [4](#0-3) .
4. `updateMasterOracle` executes.
5. Attacker back-runs: `pool.swap(msETH, msUSD, amountIn)` at the new price, ending with ~5% more msUSD. Redeems/withdraws the profit as underlying collateral from the Treasury.

### Impact Explanation
Direct theft of user funds / protocol insolvency. `Pool.swap` is zero-sum against the pool's collateral backing: synths minted against real deposits are exchanged at oracle parity. The arbitrage between the pre-update and post-update price extracts the price delta times swap size from the Treasury, diluting honest depositors' `DepositToken` exchange rate. Profit scales with attacker capital (flash-leveraged via `flashIssue`), bounded only by swap liquidity and the price divergence between the two oracle configurations — which can be large for oracle migrations, feed changes, or collateral re-pricing, not just stale-price drift.

### Likelihood Explanation
Medium. It requires a pending `updateMasterOracle` (or any other governor price-config change, e.g. `updateSwapper`/`updateFeeProvider` affecting quotes) to be observable in the mempool, plus a meaningful price delta between old and new oracle outputs. Oracle rotations/migrations are real operational events, the attacker needs no privilege and no oracle manipulation, and swap is not paused during the transition. Profit is zero if prices are identical, so exploitation is opportunistic rather than constant — matching Medium likelihood.

### Recommendation
Make pricing-relevant admin updates atomic with respect to user operations:

- Call `Pool.toggleIsSwapActive()` (and gate `deposit`/`withdraw`/`issue`/`liquidate` if their quotes depend on `masterOracle`) around `updateMasterOracle` — i.e., require swaps to be inactive when the oracle is replaced, or perform pause → update → verify → unpause in a single batched/multisig transaction.
- Alternatively add a short post-update cooldown on `swap()`/`deposit`/`withdraw` (e.g., `lastOracleUpdateTimestamp` check) so operators can verify state consistency before user flow resumes.
- Submit the update via private mempool / MEV-protected relay, or add a sanity check in `updateMasterOracle` comparing old vs new quotes for all registered synths and reverting if divergence exceeds a threshold.

### Proof of Concept
Reproducible as a Hardhat fork test against the repo's own deploy fixtures (mainnet deployments include `PoolRegistry`/`Pool`/`MasterOracle`):

```solidity
// test_audit_sandwichOracleUpdate — Foundry-style outline
// Setup (mirroring test/Pool.test.ts fixtures):
//   alice deposits collateral, issues msUSD; pool has Treasury-backed liquidity.
//   oldOracle quotes msETH = $2000; newOracle quotes msETH = $2100 (5% jump).

// 1. Governor broadcasts updateMasterOracle(newOracle) — mempool visible.

// 2. Attacker front-runs:
(uint256 msEthOut,) = pool.swap(msUSD, msETH, 1_000_000e18);
//    -> receives msETH valued at old $2000 price.

// 3. Governor tx lands:
poolRegistry.updateMasterOracle(newOracle);

// 4. Attacker back-runs:
(uint256 msUsdOut,) = pool.swap(msETH, msUSD, msEthOut);
//    -> msUSD received valued at new $2100 price.

// 5. assertGt(msUsdOut - 1_000_000e18, 0) ~ +5% minus swap fees;
//    attacker then withdraws profit as underlying collateral via
//    DepositToken.withdraw / redeem, draining Treasury backing.
```

Note on uncertainty: I did not fully trace `Pool.swap`'s fee accounting (`FeeProvider.swapFees`) — the swap fee (max 25% per `MAX_FEE_VALUE`) reduces but does not eliminate the arbitrage whenever the oracle price delta exceeds the round-trip fee [5](#0-4) . The exact profit bound should be confirmed in the fork test with production fee parameters.
