### Title
Firewall rules scoped by `ca_name` match any CA that shares that name, not the specific trusted CA - (File: firewall.go)

### Summary
Nebula firewall rules can be scoped to a specific Certificate Authority using `ca_name` (as opposed to `ca_sha`, which pins an exact CA fingerprint). Internally, this scoping is resolved by CA *name* string, not by CA identity (fingerprint). Because the `CAPool` never enforces that CA names are unique [1](#0-0) , an attacker who can get a certificate signed by *any* CA that shares the name of the intended trusted CA will satisfy a `ca_name`-scoped firewall rule meant to restrict access to a single, specific CA — mirroring the GMX bug class where an identifier assumed to uniquely represent one entity (ETH-collateral) is silently shared by two logically distinct roles (long/short), breaking an invariant the validation logic depends on.

### Finding Description
`AddFirewallRulesFromConfig` requires that at least one of `host, group, cidr, local_cidr, ca_name, or ca_sha` be provided for a rule [2](#0-1) , and forwards `r.CAName`/`r.CASha` into `fw.AddRule` [3](#0-2) .

At match time, `FirewallCA.match` resolves a peer's CA scope in three steps: check the "any" rule set, check `CAShas` keyed by the certificate issuer fingerprint, and — critically — resolve the peer's signer via `caPool.GetCAForCert(c.Certificate)` and then index `CANames` by `s.Certificate.Name()` (the signer's *name string*, not its fingerprint): [4](#0-3) 

The `CAPool` that supplies `GetCAForCert` stores CAs keyed by their SHA fingerprint, and `AddCA` performs no check that a newly added CA's `Name()` is unique across the pool: [5](#0-4) 

`GetCAForCert` itself only looks up by `Issuer` (a fingerprint), and returns whichever `CachedCertificate` is stored under that fingerprint, with no name-uniqueness constraint enforced anywhere in this path: [6](#0-5) 

Consequently, `fc.CANames[s.Certificate.Name()]` is a name-keyed lookup table. If an operator loads two (or more) CAs into the trusted `CAPool` that happen to share the same `Name` field — which is attacker/operator-controlled free text on the CA cert, not a cryptographic identity — a firewall rule written as `ca_name: "trusted-ca"` will match traffic from peers whose certificates were signed by *either* CA, even though the rule author intended to scope trust to one specific CA. This breaks the implicit invariant that "ca_name uniquely identifies a specific issuing authority," in the same way the GMX bug broke the invariant that "the reserved-USD side calculation is only valid when the two collateral tokens are distinct" — the underlying identifier (CA name / collateral token) is silently shared between two logically distinct trust roots (or market sides), and the enforcement logic never re-validates that assumption.

### Impact Explanation
This is a firewall-bypass class issue: it can cause a `ca_name`-scoped inbound/outbound rule to incorrectly authorize a peer whose certificate was issued by a CA the rule author did not intend to trust for that traffic, provided that CA's `Name` field collides with the intended one. In multi-CA Nebula deployments (e.g., federated networks, CAs issued by different teams/tenants sharing a naming convention, or an attacker who can get a rogue-but-otherwise-validly-signed CA loaded into the pool with a colliding name), this can allow unauthorized lateral traffic to pass the firewall that should have been restricted to a single, specific CA's certificate holders.

### Likelihood Explanation
Exploitability depends on an operator loading multiple CAs with colliding `Name` fields into the same `CAPool`, or an attacker being able to introduce a CA with a chosen name into that pool (e.g., via CA rotation processes, multi-tenant CA bundles, or config error). This is not the classic "malicious peer holding a valid cert from the intended CA" scenario excluded by the rules; it specifically targets the ca_name → CA identity resolution logic that firewall.go relies on, which is reachable purely through configuration/certificate content rather than by already holding a CA-signed cert from the intended issuer.

### Recommendation
Resolve `ca_name` firewall scoping by mapping name → fingerprint at CA-pool construction time and reject (or explicitly warn on and disambiguate) duplicate CA names, or internally convert `ca_name` rules to a set of concrete CA fingerprints at config-load time instead of doing a live name lookup in `FirewallCA.match`. This removes the possibility of trust conflation between differently-fingerprinted CAs that merely share a display name.

### Proof of Concept
1. Generate two independent CA key pairs, both with `Name = "trusted-ca"` (different fingerprints).
2. Load both CAs into the `pki.ca` bundle used to build the `CAPool` on a Nebula node.
3. Configure a firewall rule: `ca_name: "trusted-ca"` intended to allow traffic only from hosts whose certs are signed by CA #1.
4. Issue a host certificate signed by CA #2 (also named `"trusted-ca"`).
5. Complete a handshake and send traffic matching the rule's port/proto; per `FirewallCA.match` [4](#0-3) , the peer's signer is resolved via `caPool.GetCAForCert` (fingerprint-keyed) and then looked up in `CANames` by name, so the CA #2-signed peer is incorrectly matched against the rule meant only for CA #1, and the traffic is allowed instead of dropped.

// AddCA verifies a Nebula CA certificate and adds it to the pool.
func (ncp *CAPool) AddCA(c Certificate) error {
	if !c.IsCA() {
		return fmt.Errorf("%s: %w", c.Name(), ErrNotCA)
	}

	if !c.CheckSignature(c.PublicKey()) {
		return fmt.Errorf("%s: %w", c.Name(), ErrNotSelfSigned)
	}

	sum, err := c.Fingerprint()
	if err != nil {
		return fmt.Errorf("could not calculate fingerprint for provided CA; error: %w; %s", err, c.Name())
	}

	cc := &CachedCertificate{
		Certificate:    c,
		Fingerprint:    sum,
		InvertedGroups: make(map[string]struct{}),
	}

	for _, g := range c.Groups() {
		cc.InvertedGroups[g] = struct{}{}
	}

	ncp.CAs[sum] = cc

	if c.Expired(time.Now()) {
		return fmt.Errorf("%s: %w", c.Name(), ErrExpired)
	}

	return nil
}

// GetCAForCert attempts to return the signing certificate for the provided certificate.
// No signature validation is performed
func (ncp *CAPool) GetCAForCert(c Certificate) (*CachedCertificate, error) {
	issuer := c.Issuer()
	if issuer == "" {
		return nil, fmt.Errorf("no issuer in certificate")
	}

	signer, ok := ncp.CAs[issuer]
	if ok {
		return signer, nil
	}

	return nil, ErrCaNotFound
}

func (fc *FirewallCA) match(p firewall.Packet, c *cert.CachedCertificate, caPool *cert.CAPool) bool {
	if fc == nil {
		return false
	}

	if fc.Any.match(p, c) {
		return true
	}

	if t, ok := fc.CAShas[c.Certificate.Issuer()]; ok {
		if t.match(p, c) {
			return true
		}
	}

	s, err := caPool.GetCAForCert(c.Certificate)
	if err != nil {
		return false
	}

	return fc.CANames[s.Certificate.Name()].match(p, c)
}
