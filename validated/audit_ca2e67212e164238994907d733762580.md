### Title
Attacker-controlled `num_nonces` in a `GasKeyFunctionCall`/`GasKeyFullAccess` `AddKey` action can overflow `u64` and panic via `.unwrap()` in `gas_key_add_key_exec_fee`/`permission_exec_fees` - (File: runtime/runtime/src/config.rs, core/parameters/src/cost.rs)

### Finding Description
`permission_exec_fees` in `runtime/runtime/src/config.rs` computes the exec fee for an `AddKey` action. [1](#0-0) 
For `GasKeyFullAccess`/`GasKeyFunctionCall` permissions it calls `gas_key_add_key_exec_fee(fees, account_id.len(), public_key.trie_id_len(), gas_key_info.num_nonces)` and then unconditionally `.checked_add(...).unwrap()`s the result onto `key_fee`. [2](#0-1) 

`gas_key_add_key_exec_fee` itself multiplies the attacker-supplied `num_nonces` by fee constants twice, each guarded only with `.unwrap()` rather than a checked/result-propagating path: [3](#0-2) 

`num_nonces` (of type `NonceIndex`) is a field the sender sets directly inside the `GasKeyInfo` attached to the `AddKey` action's `GasKeyFullAccess`/`GasKeyFunctionCall` permission — it is a declared count, not derived from or bounded by the actually-serialized action bytes, so it is not implicitly capped by the ~4MB transaction/action size limit that bounds e.g. `method_names` byte totals. Its only bound is the numeric range of its underlying integer type. If `num_nonces` is chosen near the top of that range, `gas_key_nonce_write_base.exec_fee().checked_mul(num_nonces)` or the second `checked_mul` (`(nonce_key_len + NONCE_VALUE_LEN) * gas_key_byte * num_nonces`) can overflow `u64`, and the `.unwrap()` calls turn that into a panic.

This function is reached from `calculate_tx_cost` (`runtime/runtime/src/config.rs:434`) during `total_prepaid_exec_fees`, which is itself part of computing the price of converting the submitted transaction into a receipt — an apply-time code path executed for every ordinary transaction that adds such a key. [4](#0-3) 

Although `calculate_tx_cost` returns `Result<TransactionCost, IntegerOverflowError>` and most of its top-level additions use `checked_add_result`, the inner per-action fee computation (`exec_fee`/`permission_exec_fees`) returns a bare `ParameterCost` and relies on raw `.unwrap()` calls internally, so an overflow here is **not** converted into the `IntegerOverflowError` that the outer function is designed to propagate — it panics instead.

### Impact Explanation
An unprivileged sender that funds an account and submits a `TransactionV1` containing an `AddKey` action with `GasKeyFunctionCall`/`GasKeyFullAccess` permission and a maximal `num_nonces` value can trigger a panic while the runtime is computing the transaction's cost during apply. This matches the "shard-halting panic" / Liveness impact category, since the panic occurs on a Rust `.unwrap()` in the apply path rather than being converted into a rejected-transaction error.

### Likelihood Explanation
Preconditions are limited to: an unprivileged, funded NEAR account, the `GasKeys` protocol feature enabled, and constructing a single `AddKey` action with a large `num_nonces`. No special access, validator role, or race condition is required, and the transaction can be repeated cheaply, making this straightforward to reproduce if `num_nonces`'s type width and the fee constants indeed allow the multiplication to exceed `u64::MAX`. The exact feasibility depends on the concrete bit width of `NonceIndex` and mainnet values of `gas_key_nonce_write_base`/`gas_key_byte`, which I was not able to fully confirm from the available index (the `NonceIndex` type definition and any additional `num_nonces` bound/validation in `access_keys.rs`/`action_validation.rs` were not found within the tool budget for this session).

### Recommendation
Replace the internal `.unwrap()` calls in `gas_key_add_key_exec_fee` (`core/parameters/src/cost.rs:886-904`) and `permission_exec_fees` (`runtime/runtime/src/config.rs:375-413`) with checked arithmetic that propagates `IntegerOverflowError`, matching the pattern already used in `calculate_tx_cost`. Additionally, enforce an explicit upper bound on `num_nonces` during action validation (independent of type range) so that the product with fee constants cannot approach `u64::MAX`.

### Proof of Concept
Unit test in `runtime/runtime/src/config.rs` (or a new test module) that:
1. Builds a `RuntimeConfig`/`RuntimeFeesConfig` with realistic (or `test()`) fee values for `gas_key_nonce_write_base` and `gas_key_byte`.
2. Constructs an `AddKeyAction` with `AccessKeyPermission::GasKeyFullAccess(GasKeyInfo { num_nonces: <max value for NonceIndex>, .. })`.
3. Calls `permission_exec_fees(&permission, &config, &account_id, &public_key)` directly (bypassing the panic-prone `.unwrap()`s by first patching them to `checked_*_result`).
4. Asserts the function returns `Err(IntegerOverflowError)` instead of panicking, confirming the fix, and that the pre-fix code panics without it (documented via `#[should_panic]` on the unmodified code, then removed after the fix).

fn permission_exec_fees(
    permission: &AccessKeyPermission,
    config: &RuntimeConfig,
    account_id: &AccountId,
    public_key: &PublicKey,
) -> ParameterCost {
    let fees = &config.fees;
    let key_fee = match permission {
        AccessKeyPermission::FunctionCall(perm)
        | AccessKeyPermission::GasKeyFunctionCall(_, perm) => {
            let num_bytes = perm
                .method_names
                .iter()
                // Account for null-terminating characters.
                .map(|name| name.as_bytes().len() as u64 + 1)
                .sum::<u64>();
            let base_fee = fees.fee(ActionCosts::add_function_call_key_base).exec_fee();
            let byte_fee = fees.fee(ActionCosts::add_function_call_key_byte).exec_fee();
            let all_bytes_fee = byte_fee.checked_mul(num_bytes).unwrap();
            base_fee.checked_add(all_bytes_fee).unwrap()
        }
        AccessKeyPermission::FullAccess | AccessKeyPermission::GasKeyFullAccess(_) => {
            fees.fee(ActionCosts::add_full_access_key).exec_fee()
        }
    };
    // Additional costs for adding an access key with GasKeyFunctionCall or GasKeyFullAccess permissions.
    let gas_key_info = match permission {
        AccessKeyPermission::GasKeyFullAccess(info)
        | AccessKeyPermission::GasKeyFunctionCall(info, _) => info,
        _ => return key_fee,
    };
    let nonce_fee = gas_key_add_key_exec_fee(
        fees,
        account_id.len(),
        public_key.trie_id_len(),
        gas_key_info.num_nonces,
    );
    key_fee.checked_add(nonce_fee.total()).unwrap()
}

pub fn gas_key_add_key_exec_fee(
    cfg: &RuntimeFeesConfig,
    account_id_len: usize,
    public_key_len: usize,
    num_nonces: NonceIndex,
) -> GasKeyAddFee {
    let num_nonces = num_nonces as u64;
    let base =
        cfg.fee(ActionCosts::gas_key_nonce_write_base).exec_fee().checked_mul(num_nonces).unwrap();
    let nonce_key_len =
        access_key_key_len(account_id_len, public_key_len) + std::mem::size_of::<NonceIndex>();
    let per_byte = cfg
        .fee(ActionCosts::gas_key_byte)
        .exec_fee()
        .checked_mul((nonce_key_len + AccessKey::NONCE_VALUE_LEN) as u64)
        .unwrap()
        .checked_mul(num_nonces)
        .unwrap();
    GasKeyAddFee { base, per_byte }
