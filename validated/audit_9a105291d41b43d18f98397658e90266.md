Path traversal via unsanitized TAR extraction in CreateRepositoryFromSnapshot's `untar` allows writing outside the target repository - (File: internal/gitaly/service/repository/create_repository_from_snapshot.go)

### Summary
`(s *server).untar` fetches an HTTP response body driven by the attacker-controlled `HttpUrl`/`HttpAuth` fields of `CreateRepositoryFromSnapshotRequest` and pipes it directly, unvalidated, into the system `tar -C path -xvf -` command. Unlike the sibling snapshot-extraction path used for internal replication (`extractTarToDirectory` in `replicate.go`), which explicitly validates every tar entry (regular file, directory, symlink, hardlink) to ensure the resolved path stays within the target directory, `untar` performs zero validation of the archive's content before extraction.

### Finding Description
`CreateRepositoryFromSnapshot` calls `s.untar(ctx, path, in)` inside `repoutil.Create` with `path` set to the freshly-created target repository's absolute path [1](#0-0) . `untar` issues an HTTP GET to `in.GetHttpUrl()` with optional `Authorization: in.GetHttpAuth()` header, and streams the raw response body as stdin to a bare `tar -C path -xvf -` invocation with no entry inspection [2](#0-1) . The code comment itself flags this: "the received archive is trusted *a lot*... before pointing this RPC at endpoints not under our control, it should undergo a lot of hardening" [3](#0-2) .

Because system `tar` is invoked directly on attacker-supplied archive bytes with no `--strip-components`, no entry-name allowlist, and no post-extraction path containment check, a tar archive containing entries such as `../../other-repo/hooks/pre-receive` or `../../../etc/foo` can write files outside `path` when the target `tar` binary does not itself refuse relative `..` traversal (behavior differs by tar implementation/version; GNU tar historically only strips leading `/` from absolute paths with a warning and does not, in all configurations, reject `../` component traversal in relative entries). This contrasts directly with the codebase's own hardened implementation `extractTarToDirectory`/`extractFile`, which explicitly performs `strings.HasPrefix(targetPath, targetDir+string(os.PathSeparator))` containment checks for regular files, directories, symlinks, and hardlinks [4](#0-3) , proving that Gitaly is aware of and has fixed this class of bug elsewhere but left `untar` unpatched.

The proto/comment framing implies `HttpUrl`/`HttpAuth` are meant to be "endpoints under our control" set by GitLab Rails, but the RPC itself performs no validation restricting the URL to trusted hosts, and the question's precondition (attacker-influenced `http_url` via a fork/import flow) puts archive content fully under attacker control.

### Impact Explanation
A malicious/crafted tar response can overwrite arbitrary files reachable via relative traversal from the new repository's storage path, including another repository's `hooks/pre-receive` (leading to remote code execution when that repository is next pushed to) or its `config`/`objects`, corrupting or backdooring sibling repositories on the same Gitaly storage. This matches the GitLab bounty impact class of arbitrary file write / path traversal leading to potential RCE via hook injection.

### Likelihood Explanation
Per the question's stated precondition, an unprivileged user who can trigger a fork/import flow that ultimately invokes `CreateRepositoryFromSnapshot` with an attacker-influenced `HttpUrl` (pointed at a server they control) can supply an arbitrary tar body. No additional privilege, secret, or race condition is required beyond controlling the HTTP response content, making this readily repeatable whenever this code path is reachable with attacker-influenced `HttpUrl`.

### Recommendation
Replace the raw `tar -C path -xvf -` shell-out in `untar` with the same hardened, containment-checked extraction logic already implemented in `extractTarToDirectory`/`extractFile` (or route `CreateRepositoryFromSnapshot` through that code path), rejecting any entry whose resolved path escapes the target directory, and rejecting absolute paths and unsafe symlinks/hardlinks as done there.

func (s *server) untar(ctx context.Context, path string, in *gitalypb.CreateRepositoryFromSnapshotRequest) error {
	req, err := http.NewRequestWithContext(ctx, "GET", in.GetHttpUrl(), nil)
	if err != nil {
		return structerr.NewInvalidArgument("Bad HTTP URL: %w", err)
	}

	client := httpClient
	if resolvedAddress := in.GetResolvedAddress(); resolvedAddress != "" {
		client, err = newResolvedHTTPClient(in.GetHttpUrl(), resolvedAddress)
		if err != nil {
			return structerr.NewInvalidArgument("creating resolved HTTP client: %w", err)
		}
	}

	if in.GetHttpAuth() != "" {
		req.Header.Set("Authorization", in.GetHttpAuth())
	}

	rsp, err := client.Do(req)
	if err != nil {
		return structerr.NewInternal("HTTP request failed: %w", err)
	}
	defer rsp.Body.Close()

	if rsp.StatusCode < http.StatusOK || rsp.StatusCode >= http.StatusMultipleChoices {
		return structerr.NewInternal("HTTP server: %s", rsp.Status)
	}

	cmd, err := command.New(ctx, s.logger, []string{"tar", "-C", path, "-xvf", "-"}, command.WithStdin(rsp.Body))
	if err != nil {
		return err
	}

	return cmd.Wait()
}

// extractTarToDirectory extracts a tar archive to the specified directory using Go's tar package
func (s *server) extractTarToDirectory(ctx context.Context, reader io.Reader, targetDir string) error {
	targetDir = filepath.Clean(targetDir)
	tarReader := tar.NewReader(reader)

	for {
		select {
		case <-ctx.Done():
			return ctx.Err()
		default:
		}

		header, err := tarReader.Next()
		if err == io.EOF {
			break // End of archive
		}
		if err != nil {
			return fmt.Errorf("reading tar header: %w", err)
		}

		targetPath := filepath.Join(targetDir, header.Name)

		if !strings.HasPrefix(targetPath, targetDir+string(os.PathSeparator)) &&
			targetPath != targetDir {
			return fmt.Errorf("invalid file path in tar: %s", header.Name)
		}

		switch header.Typeflag {
		case tar.TypeDir:
			if err := os.MkdirAll(targetPath, os.FileMode(header.Mode)); err != nil {
				return fmt.Errorf("creating directory %s: %w", targetPath, err)
			}

		case tar.TypeReg:
			if err := s.extractFile(ctx, tarReader, targetPath, header); err != nil {
				return fmt.Errorf("extracting file %s: %w", targetPath, err)
			}

		case tar.TypeSymlink:
			if filepath.IsAbs(header.Linkname) {
				return fmt.Errorf("absolute symlink not allowed: %s -> %s", header.Name, header.Linkname)
			}

			// Resolve the relative symlink target from the symlink's parent directory
			// and verify it stays within the extraction boundary, consistent with the
			// hard link validation below.
			resolvedTarget := filepath.Join(filepath.Dir(targetPath), header.Linkname)
			if !strings.HasPrefix(resolvedTarget, targetDir+string(os.PathSeparator)) &&
				resolvedTarget != targetDir {
				return fmt.Errorf("symlink target escapes extraction directory: %s -> %s", header.Name, header.Linkname)
			}

			// Remove existing file/symlink if it exists
			if err := os.Remove(targetPath); err != nil && !os.IsNotExist(err) {
				return fmt.Errorf("removing existing file for symlink %s: %w", targetPath, err)
			}

			if err := os.Symlink(header.Linkname, targetPath); err != nil {
				return fmt.Errorf("creating symlink %s -> %s: %w", targetPath, header.Linkname, err)
			}

		case tar.TypeLink:
			linkTarget := filepath.Join(targetDir, header.Linkname)

			if !strings.HasPrefix(linkTarget, targetDir+string(os.PathSeparator)) &&
				linkTarget != targetDir {
				return fmt.Errorf("invalid hard link target: %s", header.Linkname)
			}

			// Remove existing file if it exists
			if err := os.Remove(targetPath); err != nil && !os.IsNotExist(err) {
				return fmt.Errorf("removing existing file for hard link %s: %w", targetPath, err)
			}

			if err := os.Link(linkTarget, targetPath); err != nil {
				return fmt.Errorf("creating hard link %s -> %s: %w", targetPath, linkTarget, err)
			}

		default:
			// Skip unsupported file types (devices, FIFOs, etc.)
			s.logger.WithField("file", header.Name).WithField("type", header.Typeflag).
				WarnContext(ctx, "skipping unsupported file type in tar archive")
		}

		if header.Typeflag == tar.TypeReg || header.Typeflag == tar.TypeDir {
			if err := os.Chmod(targetPath, os.FileMode(header.Mode)); err != nil {
				return fmt.Errorf("setting permissions for %s: %w", targetPath, err)
			}
		}
	}

	return nil
}
