### Title
Per-IP QoS/connection-rate limiting is keyed by exact `IpAddr` with no subnet/prefix aggregation, allowing IPv6 /64 address rotation to bypass fair-share limits - (File: streamer/src/nonblocking/connection_rate_limiter.rs)

### Summary
`ConnectionRateLimiter::is_allowed`/`register_connection` and the downstream unstaked connection-table QoS enforce limits keyed strictly by the literal source `IpAddr`, with no CIDR/prefix grouping for IPv6. An unprivileged attacker who controls (or is delegated, as is standard practice by most cloud/ISP providers) an IPv6 /64 block can trivially generate an effectively unbounded number of distinct source addresses, each of which gets a fresh `TokenBucket` with full burst allowance, letting the attacker capture a disproportionate share of the shared global connection budget and the fixed `max_unstaked_connections` pool at the expense of other legitimate unstaked/staked senders.

### Finding Description
`ConnectionRateLimiter` wraps a `KeyedRateLimiter<IpAddr>` and performs `is_allowed`/`register_connection` lookups strictly by the exact `IpAddr` extracted from `incoming.remote_address().ip()`: [1](#0-0) [2](#0-1) 

Because the key stripping only removes the port (`.ip()`), rotating ephemeral **source ports on the same IPv4/IPv6 address does not bypass the limiter** — that part of the threat is already mitigated, since all traffic from one address maps to the same token bucket. Likewise, pure IP spoofing cannot register a connection, because `register_connection` is only invoked in `setup_connection` after the QUIC handshake (`connecting.await`) succeeds — an attacker must genuinely own/route the source address to complete the handshake: [3](#0-2) 

However, there is no aggregation of IPv6 addresses by network prefix (e.g., /64) anywhere in `streamer` or `net-utils` — a grep across the streamer crate for `/64`, `Ipv6`, `subnet`, `prefix` found no such logic. `KeyedRateLimiter<K>` (in `net-utils/src/token_bucket.rs`) is a generic keyed map that creates a brand-new, fully-refilled `TokenBucket` (cloned from `prototype_bucket`) the first time any given key is seen: [4](#0-3) 

Since an IPv6 /64 gives an attacker 2^64 distinct legitimately-routable source addresses (a block size commonly delegated to a single customer by cloud/ISP providers with no additional cost or verification), the attacker can open real, fully-handshaked QUIC connections from an effectively unlimited rotating set of addresses in that block. Each new address is treated by `ConnectionRateLimiter` as "not seen" (`None => true` in `is_allowed`), so `register_connection` succeeds and yields a fresh, full token bucket (`limit_per_minute * 10` burst) every time, defeating the intended per-source cap (`max_connections_per_ipaddr_per_min`) configured in `run_server`: [5](#0-4) 

The `CONNECTION_RATE_LIMITER_CLEANUP_SIZE_THRESHOLD` (100,000) only bounds the `KeyedRateLimiter`'s internal DashMap size via LazyLRU eviction (`maybe_shrink`); it does not prevent new distinct-address buckets from being created, and under attacker-driven address churn it actively evicts older (potentially legitimate) entries to make room: [6](#0-5) [7](#0-6) 

The remaining defense is `overall_connection_rate_limiter`, a single shared `TokenBucket` checked in `run_server` and again in `setup_connection`: [8](#0-7) [9](#0-8) 
This is a *global* budget shared by all senders, not a per-source cap — so an attacker who evades the per-IP limiter via address rotation can consume a disproportionate share of this shared quota, denying acceptance opportunities to legitimate unstaked/staked senders using single, stable IPs. Downstream stake-weighted QoS (`SwQos`, `streamer/src/nonblocking/swqos.rs`) further gates connections through `max_unstaked_connections` (a fixed global cap) and `max_connections_per_unstaked_peer`; I was unable to fully confirm within the available context whether `ConnectionTableKey` used by `ConnectionTable` for the per-unstaked-peer cap groups by IP or Pubkey (this needs further verification via full file read of `streamer/src/nonblocking/quic.rs` for `ConnectionTableKey`), but the confirmed per-IP connection rate limiter itself is sufficient evidence of the QoS-evasion vector described.

### Impact Explanation
This falls under "unfairly capture connection/stream/per-IP QoS limits and starve legitimate senders of TPU capacity" — an unstaked attacker with a single IPv6 /64 delegation (no stake, no special config) can multiply its effective connection-acceptance rate against a leader's TPU QUIC endpoint far beyond `max_connections_per_ipaddr_per_min`, consuming a disproportionate share of the shared `overall_connection_rate_limiter` budget and the fixed unstaked connection pool, degrading TPU stream capacity available to honest unstaked and staked senders.

### Likelihood Explanation
Feasibility is high: IPv6 /64 (or larger) delegation to a single customer is the norm for most cloud providers and residential ISPs, requiring no privileged access, stake, or gossip/peer control — only routine QUIC client connections to a public TPU port. The attack is fully repeatable and scales linearly with the number of distinct source addresses used, bounded only by the shared global rate limiter, not by the intended per-source cap.

### Recommendation
Aggregate IPv6 keys in `ConnectionRateLimiter` (and any downstream per-peer connection tables) by network prefix (e.g., /64 or configurable subnet mask) rather than exact address equality, so that an entire delegated block shares one token bucket / connection quota. For IPv4, continue keying by exact address (already correct since /32 is the typical allocation unit), but consider similarly normalizing by a coarser mask if smaller allocations become relevant. Additionally, consider making the global `overall_connection_rate_limiter` stake-aware or splitting it into staked/unstaked sub-budgets so that unstaked address churn cannot crowd out staked traffic.

```rust
#[tokio::test]
async fn test_ipv6_64_subnet_bypasses_per_ip_limit() {
    use std::net::Ipv6Addr;

    // limit_per_minute=3, max_burst=3 -> mirrors run_server's per-IP config shape
    let limiter = ConnectionRateLimiter::new(3, 3, 4);

    // Simulate an attacker rotating through addresses within a single /64
    // (fixed /64 prefix, varying host bits) -- all "distinct" addresses,
    // but attacker-controlled from one delegated block.
    let base: u128 = 0x2001_0db8_0000_0001_0000_0000_0000_0000;
    let mut total_accepted = 0usize;
    for host_suffix in 0u128..10_000 {
        let ip = IpAddr::V6(Ipv6Addr::from(base | host_suffix));
        assert!(limiter.is_allowed(&ip), "fresh address always allowed");
        assert!(
            limiter.register_connection(&ip),
            "fresh address always accepted, bypassing per-IP burst of 3"
        );
        total_accepted += 1;
    }

    // Expected (bug): total_accepted == 10_000 (bounded only by attacker's
    // ability to generate addresses within the /64, not by limit_per_minute).
    // Desired invariant (fix target): total_accepted should be bounded by
    // limit_per_minute * num_distinct_/64_prefixes, i.e. == 3 here since
    // all addresses share one /64.
    assert_eq!(
        total_accepted, 10_000,
        "demonstrates unbounded acceptance across one attacker-controlled /64, \
         far exceeding the intended per-source burst of 3"
    );
}
```
Expected result today: the assertion passes, showing that 10,000 "distinct" addresses from a single /64 all get accepted despite a configured burst limit of 3 per IP — confirming the bypass. After applying a /64-aware key normalization fix, this test should be updated to assert acceptance is capped at `limit_per_minute`/`max_burst` for the whole /64 prefix.

```rust
    pub fn is_allowed(&self, ip: &IpAddr) -> bool {
        // Check if we have records in the rate limiter for the given IP address
        match self.limiter.current_tokens(ip) {
            Some(r) => r > 0, // we have a record, and rate is not exceeded
            None => true,     // if we have not seen IP, allow connection request
        }
    }

    pub fn register_connection(&self, ip: &IpAddr) -> bool {
        if self.limiter.consume_tokens(*ip, 1).is_ok() {
            debug!("Request from IP {ip:?} allowed");
            true // Request allowed
        } else {
            debug!("Request from IP {ip:?} blocked");
            false // Request blocked
        }
    }
```

```rust
    pub fn consume_tokens(&self, key: K, request_size: u64) -> Result<u64, u64> {
        let (entry_added, res) = {
            let bucket = self.data.entry(key);
            match bucket {
                Entry::Occupied(entry) => (false, entry.get().consume_tokens(request_size)),
                Entry::Vacant(entry) => {
                    // if the key is not in the LRU, we need to allocate a new bucket
                    let bucket = self.prototype_bucket.clone();
                    let res = bucket.consume_tokens(request_size);
                    entry.insert(bucket);
                    (true, res)
                }
            }
```

```rust
    #[allow(clippy::arithmetic_side_effects)]
    fn maybe_shrink(&self) {
        let mut actual_len = 0;
        let target_shard_size = self.target_capacity / self.data.shards().len();
        if target_shard_size == 0 {
            return;
        }
        let mut entries = Vec::with_capacity(target_shard_size * 2);
        for shardlock in self.data.shards() {
            let mut shard = shardlock.write();

            if shard.len() <= target_shard_size * 3 / 2 {
                actual_len += shard.len();
                continue;
            }
            entries.clear();
            entries.extend(
                shard.drain().map(|(key, value)| {
                    (key, value.get().last_update.load(Ordering::SeqCst), value)
                }),
            );

            entries.select_nth_unstable_by_key(target_shard_size, |(_, last_update, _)| {
                Reverse(*last_update)
            });

            shard.extend(
                entries
                    .drain(..)
                    .take(target_shard_size)
                    .map(|(key, _last_update, value)| (key, value)),
            );
            debug_assert!(shard.len() <= target_shard_size);
            actual_len += shard.len();
        }
        self.approx_len.store(actual_len, Ordering::Relaxed);
    }
```
