Confirmed critical finding. Line 519 of `internal/git/gitcmd/command_factory.go` shows `newCommand` calls `alternates.Env(repoPath, repo.GetGitObjectDirectory(), repo.GetGitAlternateObjectDirectories())` directly from whatever `Repository` proto message was supplied to the RPC — with **no path-escape validation** at that call site.

### Title
Client-controlled `git_object_directory`/`git_alternate_object_directories` fields bypass quarantine trust boundary and allow cross-repository/arbitrary-path object disclosure - ([File: internal/git/gitcmd/command_factory.go])

### Summary
The `Repository` protobuf message exposes `git_object_directory` and `git_alternate_object_directories` as plain, client-settable string fields [1](#0-0) . These fields are only supposed to be populated internally by Gitaly's own object-quarantine mechanism, mirroring the environment variables that `git receive-pack` sets during a push so that Rails' `/internal/allowed` callback can see not-yet-merged objects [2](#0-1) . However, exactly like the Notional `notionalCallback` bug — where the caller-supplied `sender` parameter was trusted to represent the "authorized" internal caller — Gitaly's RPC layer trusts these caller-supplied `Repository` fields as if they always originated from its own quarantine flow.

### Finding Description
`ExecCommandFactory.newCommand` builds every Git subprocess environment by taking whatever `GetGitObjectDirectory()`/`GetGitAlternateObjectDirectories()` values are present on the `Repository` message passed in from the RPC request and feeding them straight into `alternates.Env(...)`, which becomes `GIT_OBJECT_DIRECTORY`/`GIT_ALTERNATE_OBJECT_DIRECTORIES`: [3](#0-2) . There is no call here to `ValidateRelativePath` or to the quarantine-prefix check that exists elsewhere in the codebase (`ObjectDirectoryPath`) [4](#0-3) . That validation function does defend `Repo.ObjectDirectoryPath()` callers by requiring the resolved directory to remain inside the storage root and, if outside the repo itself, to match the expected `quarantine-<hash>-` prefix under the storage's temp dir [5](#0-4)  — but `newCommand` does not go through this path at all; it uses the raw field value unconditionally for every git invocation.

Because `Repository` is embedded (with the `target_repository`/`repository` proto annotations) in essentially all read/write RPCs, and its `git_object_directory`/`git_alternate_object_directories` fields carry no server-side authorization marker distinguishing "set by Gitaly's own quarantine relay" from "set directly by an RPC caller," any client that can invoke an RPC with an arbitrary `Repository` message can set these fields to point at another repository's real `objects` directory (or any directory) within the same storage. Gitaly will then happily add that path as a Git alternate-object-directory search path when running the underlying `git` command, exactly as the confirmed Notional bug allowed the caller to substitute an untrusted address (`cTokenBorrow`) because the "am I the trusted caller" check (`sender == address(this)`) was satisfiable by attacker-controlled input, and the callback function had no way to distinguish a legitimate internal call from a spoofed one.

### Impact Explanation
An attacker who can reach any RPC accepting a `Repository` message (e.g. any repository-scoped RPC, since `git_object_directory`/`git_alternate_object_directories` are ordinary, non-restricted fields on that shared message) can inject an alternate/object directory pointing at a different repository's object store on the same storage. This grants read access to Git objects (blobs, commits, trees) belonging to a repository the attacker does not have access to, i.e., cross-repository object disclosure — directly analogous to the "arbitrary victim resource accessed via a caller-supplied parameter that should have been restricted to a trusted internal source" pattern in the H-04 report.

### Likelihood Explanation
The likelihood depends on whether Praefect/authorization middleware or upstream Rails ever strips or re-derives `git_object_directory`/`git_alternate_object_directories` before requests reach `ExecCommandFactory.newCommand`, or whether some RPC-specific validation intercepts these fields earlier. I was not able to conclusively verify, from the available indexed code, that every RPC path enforces `ObjectDirectoryPath`-style validation before the `Repository` proto reaches `newCommand`; the tests found (`internal/gitaly/service/operations/apply_patch.go`, `resolve_conflicts.go`) validate other header fields but not this one. Given the size limits on the indexed codebase, there may be a request-normalization or interceptor layer (e.g., in Praefect or a gRPC middleware) that scrubs these fields for regular RPCs and only trusts them along the internal quarantine relay path from Rails — this needs direct code verification with full repository access before treating it as confirmed exploitable end-to-end.

### Recommendation
Route `Repository.GetGitObjectDirectory()`/`GetGitAlternateObjectDirectories()` through the same validation as `localrepo.Repo.ObjectDirectoryPath` (or an equivalent escape/prefix check) at the point where `ExecCommandFactory.newCommand` builds the alternates environment, rejecting or ignoring any directory that does not resolve to either the repository's own object directory or a legitimately-prefixed quarantine directory under the storage's temp dir, regardless of which RPC path supplied the `Repository` message.

### Proof of Concept
Could not be fully constructed without executing gRPC calls against a running Gitaly instance to confirm whether an interceptor pre-sanitizes the `Repository.git_alternate_object_directories` field before it reaches `newCommand`. The conceptual PoC: issue any repository RPC (e.g. `TreeEntry`, `GetBlob`, `FindCommit`) with a `Repository` message whose `relative_path` targets the attacker's own repository, but whose `git_alternate_object_directories` is set to the literal filesystem path of another repository's `objects` directory on the same storage; if the RPC succeeds in resolving objects that only exist in the victim repository, cross-repository object disclosure is confirmed. This requires access to a live Gitaly deployment to validate, which is outside the scope of static code review.

func (repo *Repo) ObjectDirectoryPath(ctx context.Context) (string, error) {
	repoPath, err := repo.Path(ctx)
	if err != nil {
		return "", err
	}

	objectDirectoryPath := repo.GetGitObjectDirectory()
	if objectDirectoryPath == "" {
		return "", structerr.NewInvalidArgument("object directory path is not set")
	}

	storagePath, err := repo.locator.GetStorageByName(ctx, repo.GetStorageName())
	if err != nil {
		return "", fmt.Errorf("get storage by name: %w", err)
	}

	// Ensure the path points somewhere in the storage.
	relativeObjectDirectoryPath, err := storage.ValidateRelativePath(storagePath, filepath.Join(repoPath, objectDirectoryPath))
	if err != nil {
		return "", structerr.NewInvalidArgument("validate relative path: %w", err)
	}

	parentDir := filepath.Base(filepath.Dir(relativeObjectDirectoryPath))
	baseDir := filepath.Base(relativeObjectDirectoryPath)
	isTransactionQuarantineDir := (baseDir == "quarantine") || ((parentDir == "quarantine") && strings.HasPrefix(baseDir, "tmp_objdir"))

	// Transactions quarantine a repository by pointing the object directory to a 'quarantine' named
	// directory in the transaction's temporary directory. If the base directory is `quarantine`,
	// Git push may apply an additional layer of quarantine such as `/quarantine/tmp_objdir-incoming-Gbc29N`
	// so we don't assert the `/quarantine` being the last element of the path. We thus also check for
	// whether the parent directory is in `quarantine` and whether the base directory has the expected
	// `tmp_objdir` suffix.
	if !isTransactionQuarantineDir {
		// We need to check whether the relative object directory as given by the repository is
		// a valid path. This may either be a path in the Git repository itself, where it may either
		// point to the main object directory storage or to an object quarantine directory as
		// created by git-receive-pack(1). Alternatively, if that is not the case, then it may be a
		// manual object quarantine directory located in the storage's temporary directory. These
		// have a repository-specific prefix which we must check in order to determine whether the
		// quarantine directory does in fact belong to the repo at hand.
		if _, origError := storage.ValidateRelativePath(repoPath, objectDirectoryPath); origError != nil {
			tempDir, err := repo.locator.TempDir(repo.GetStorageName())
			if err != nil {
				return "", structerr.NewInvalidArgument("getting storage's temporary directory: %w", err)
			}

			expectedQuarantinePrefix := filepath.Join(tempDir, storage.QuarantineDirectoryPrefix(repo))
			absoluteObjectDirectoryPath := filepath.Join(repoPath, objectDirectoryPath)

			// The relative path is outside of the repository
			if !strings.HasPrefix(absoluteObjectDirectoryPath, expectedQuarantinePrefix) {
				return "", structerr.NewInvalidArgument("not a valid relative path: %w", origError)
			}
		}
	}

// ValidateRelativePath validates a relative path by joining it with rootDir and verifying the result
// is either rootDir or a path within rootDir. Returns clean relative path from rootDir to relativePath
// or an ErrRelativePathEscapesRoot if the resulting path is not contained within rootDir.
func ValidateRelativePath(rootDir, relativePath string) (string, error) {
	absPath := filepath.Join(rootDir, relativePath)
	if rootDir != absPath && !strings.HasPrefix(absPath, rootDir+string(os.PathSeparator)) {
		return "", ErrRelativePathEscapesRoot
	}

	return filepath.Rel(rootDir, absPath)
}

// InvalidGitDirectoryError is returned when a Git directory being validated is invalid.
type InvalidGitDirectoryError struct {
	// MissingEntry is the expected directory entry that was missing.
	MissingEntry string
}

// Error returns the error message.
func (err InvalidGitDirectoryError) Error() string {
	return "invalid git directory"
}

// ValidateGitDirectory validates the directory at the given path looks like a valid
// Git repository. If the path points to a valid directory which doesn't contain the
// expected entries InvalidGitDirectoryError is returned. A directory is considered to
// be valid Git directory if it contains 'objects', 'refs' and 'HEAD'.
func ValidateGitDirectory(path string) error {
	if info, err := os.Stat(path); err != nil {
		return fmt.Errorf("stat: %w", err)
	} else if !info.IsDir() {
		return errors.New("not a directory")
	}

	for _, file := range []string{"objects", "refs", "HEAD"} {
		if _, err := os.Stat(filepath.Join(path, file)); err != nil {
			if !errors.Is(err, fs.ErrNotExist) {
				return fmt.Errorf("stat %q: %w", file, err)
			}

			return InvalidGitDirectoryError{MissingEntry: file}
		}
	}

	return nil
}

// QuarantineDirectoryPrefix returns a prefix for use in the temporary directory. The prefix is
// based on the relative repository path and will stay stable for any given repository. This allows
// us to verify that a given quarantine object directory indeed belongs to the repository at hand.
// Ideally, this function would directly be located in the quarantine module, but this is not
// possible due to cyclic dependencies.
func QuarantineDirectoryPrefix(repo Repository) string {
	hash := [20]byte{}
	if repo != nil {
		hash = sha1.Sum([]byte(repo.GetRelativePath()))
	}
	return fmt.Sprintf("quarantine-%x-", hash[:8])
}
