### Title
Predictable destination-IP hash for XDP TX queue selection allows unprivileged attackers to collide their egress bucket with a targeted peer's, degrading that peer's TPU response delivery - ([File: streamer/src/quic_socket.rs])

### Summary
`QuicXdpSender::try_send` selects the AF_XDP TX queue for a peer's outbound QUIC traffic using `sender_key = fold_xor(destination_ip_key(&destination)) as usize` when `xdp_sender.len() > 1`. Because this hash is a public, non-keyed, easily invertible function of only the destination IPv4 address, an attacker can cheaply pick/rotate their own connecting source IPs so their induced egress traffic (ACKs/retransmits) lands on the same TX queue bucket as a targeted peer, exhausting that shared `TxSender` channel and causing legitimate responses to that peer to be dropped via `TrySendError::Full`.

### Finding Description
`QuicXdpSender::try_send` in [1](#0-0)  computes the queue index for every outbound QUIC datagram purely from the destination address: [2](#0-1) 

`fold_xor` is a cheap, unkeyed 32→32 bit XOR-fold (`x ^= x>>16; x ^= x>>8;`), and `destination_ip_key` is simply `u32::from(ip)`. The final bucket is `sender_key % xdp_sender.len()` inside `XdpSender::try_send` [3](#0-2) . This mapping is entirely deterministic and public (it ships in the open-source binary), and it depends only on the *destination* IP of a UDP/QUIC datagram the validator sends — i.e., the IP of the remote peer the leader is talking to.

An unstaked/unprivileged remote client connects to the leader's public TPU QUIC port, which is served through `QuicXdpTxSocket`/`QuicXdpSender` for egress [4](#0-3) . The attacker fully controls the "destination IP" value used for the hash, because that value is simply the attacker's own connecting client IP address — they may cheaply acquire/rotate many source IPs (or, since the space is a mod over `xdp_sender.len()` which is typically small, single-digit to low tens of queues, they don't even need to search hard: a handful of leased IPs will very likely produce a collision by chance, and computing the exact colliding value requires no more than evaluating the trivial fold function offline). Once an attacker IP is confirmed to land in the same bucket `k` as a target peer's IP (e.g., another validator or RPC node that legitimately receives TPU responses from this leader), the attacker floods that connection with malformed/loss-inducing traffic to force the QUIC stack to generate a disproportionate amount of egress retransmissions/ACKs, all funneled into the same `TxSender<BytesTxPacket>` bounded channel for queue `k` (`tx_loop::channel(tx_channel_cap)` in [5](#0-4) ). Once that channel saturates, `TxSender::try_send` returns `TrySendError::Full` for *any* caller enqueuing to bucket `k` [6](#0-5) , including packets destined for the innocent peer whose IP also hashes to `k`; those packets are silently dropped (`Ok(())` path swallows the drop in `QuicXdpTxSocket::try_send` mapping to `io::ErrorKind::WouldBlock` in [7](#0-6) , and dropped items are shunted to a drop queue in [8](#0-7) ).

No existing control mitigates this specific cross-flow contention: the stake-weighted QoS/connection-throttling logic in `streamer/src/nonblocking/swqos.rs` and `stream_throttle.rs` governs *ingress* stream/connection admission per peer, not which shared egress TX ring a peer's *responses* land on. The queue-selection hash itself has no keying, salting, or per-node secret, so it cannot be defended against without a code change.

### Impact Explanation
This is a QoS-evasion / selective-DoS finding: an unprivileged remote party can, without any staked/leader/gossip privilege, deliberately colocate their own egress bucket with an arbitrary target peer's egress bucket and use their own permitted (if throttled) traffic to starve that one shared `TxLoop::run` queue, degrading TPU response delivery (ACKs, connection-close, retransmissions) specifically to that targeted peer while leaving other queues/peers unaffected. This matches the "QoS evasion" bounty category because the per-queue isolation is nominally meant to preserve per-peer ordering/fairness on egress but provides no actual protection against a deliberately engineered bucket collision from an attacker who does not need any elevated privilege.

### Likelihood Explanation
Preconditions are easy to satisfy: `xdp_sender.len() > 1` requires only that the operator configured more than one XDP TX queue (a common performance configuration, not a special/insecure config). The hash function `fold_xor`/`destination_ip_key` is public source code with no secret key, so any attacker can compute the target bucket for a known victim IP and then either brute-force cheap source IPs (from cloud providers, VPNs, etc.) until one collides, or simply rely on the ~1/`num_queues` natural collision probability across a modest number of concurrently-open connections from different IPs. The attack is fully repeatable and requires no more than standard QUIC/UDP client capability against the public TPU port.

### Recommendation
Do not derive TX-queue selection from a value fully controlled and predictable by remote peers. Options:
- Mix in a per-process/per-node random secret (e.g., `RandomState`/keyed SipHash) when hashing the destination IP, so attackers cannot predict or engineer collisions with a target peer's bucket.
- Alternatively, size/isolate TX channel capacity or apply per-source-IP fairness/backpressure within each queue so that one abusive flow cannot starve out unrelated destinations sharing the same bucket.
- Consider hashing on `(destination_ip, destination_port)` combined with a random seed to widen the entropy space and eliminate straightforward pre-image/collision search.

### Proof of Concept
Rust unit test (add to `streamer/src/quic_socket.rs` test module) demonstrating deterministic, attacker-computable collisions:
```rust
#[test]
fn attacker_can_predict_and_collide_tx_queue_bucket() {
    use std::net::{IpAddr, Ipv4Addr, SocketAddr};

    fn bucket(ip: Ipv4Addr, num_queues: usize) -> usize {
        let dest = SocketAddr::V4(std::net::SocketAddrV4::new(ip, 8009));
        fold_xor(destination_ip_key(&dest)) as usize % num_queues
    }

    let num_queues = 8; // typical multi-queue XDP config
    let victim_ip: Ipv4Addr = "203.0.113.42".parse().unwrap(); // target peer's known IP
    let target_bucket = bucket(victim_ip, num_queues);

    // Attacker brute-forces candidate source IPs offline (no privilege needed,
    // fold_xor/destination_ip_key are public, unkeyed functions).
    let mut colliding_ip = None;
    for last_octet in 1u8..=255 {
        let candidate = Ipv4Addr::new(198, 51, 100, last_octet);
        if bucket(candidate, num_queues) == target_bucket {
            colliding_ip = Some(candidate);
            break;
        }
    }

    assert!(
        colliding_ip.is_some(),
        "attacker trivially finds a source IP colliding with victim's TX queue bucket"
    );
}
```
Integration-level PoC plan: instantiate `Transmitter::build` with `num_queues > 1` and small `tx_channel_cap`; create two `QuicXdpSender`-equivalent sends, one to `victim_ip` and one to `colliding_ip`; flood sends to `colliding_ip`'s bucket until `TrySendError::Full` is observed, then assert that a subsequent send to `victim_ip` also returns `TrySendError::Full`, confirming cross-victim starvation via bucket collision, while sends to an IP hashing to a different bucket succeed unaffected.

            Some(IpAddr::V6(_)) => {

                ));
            }
            None => None,
        };

        debug_assert!(
            t.segment_size.is_none(),
            "GSO segmentation is disabled for AF_XDP sends, but segment_size is {:?}",
            t.segment_size
        );

        let payload = Bytes::copy_from_slice(t.contents);
        match self
            .xdp_sender
            .try_send(src_ip, t.destination, t.ecn, payload)
        {
            Ok(()) => Ok(()),
            Err(TrySendError::Full(_)) => Err(io::ErrorKind::WouldBlock.into()),
            Err(TrySendError::Disconnected(_)) => Err(io::ErrorKind::BrokenPipe.into()),
        }
    }

    fn try_send(
        &self,
        src_ip: Option<Ipv4Addr>,
        destination: SocketAddr,
        ecn: Option<QuinnEcnCodepoint>,
        payload: Bytes,
    ) -> Result<(), TrySendError<BytesTxPacket>> {
        // Keep packets for the same remote IP on the same XDP TX queue when there is more than
        // one queue. Avoid hashing entirely for the common single-sender case.
        let sender_key = if self.xdp_sender.len() == 1 {
            0
        } else {
            fold_xor(destination_ip_key(&destination)) as usize

        // port from `self.src_addr`.
        let src_addr = SocketAddrV4::new(src_ip, self.src_addr.port());
        let ecn = ecn.map(quinn_ecn_to_xdp);

        let mut packet = BytesTxPacket::new(src_addr, destination, ecn, payload);
        packet.set_allow_mtu_overflow(true);
        self.xdp_sender.try_send(sender_key, packet)
    }

impl<T> TxSender<T> {
    pub fn try_send(&self, item: T) -> Result<(), TrySendError<T>> {
        if self.queue.receivers.load(Ordering::Relaxed) == 0 {
            return Err(TrySendError::Disconnected(item));
        }
        self.queue.queue.push(item).map_err(TrySendError::Full)
    }
}
