**Analysis:** The binding claimed — sum of `token_balances` change for token X == 0 independent of token Y — is enforced by construction, not merely by convention.

`TransferMatcher` is `HashMap<TokenId, TokenTransferMatcher>` [1](#0-0) . Every `deposit`/`withdraw`/`add_delta` call routes through `self.0.entry_or_default(token_id)`, so all deltas for a given `TokenId` are accumulated into that token's own `TokenTransferMatcher` instance, never touching another token's entry [2](#0-1) .

`finalize` iterates `self.0` per `(token_id, transfer_matcher)` pair and calls `transfer_matcher.finalize_into(&token_id, &mut transfers)` on each `TokenTransferMatcher` value independently — the value is moved (`self.0` consumed by value in the `for` loop), so each `TokenTransferMatcher`'s `deposits`/`withdrawals` (both scoped as private fields on that struct) are matched only against each other, never against another token's maps [3](#0-2) . Inside `finalize_into`, the matching loop pairs `deposits` and `withdrawals` that belong to the *same* `self` (i.e., same token), and any unmatched leftover for that token is folded into `deltas.apply_delta(token_id, unmatched)` keyed by that specific `token_id` [4](#0-3) . There is no shared mutable state or global counter that could let a leftover deposit of token X satisfy a leftover withdrawal of token Y.

The existing unit test `test_unmatched` already demonstrates exactly the attack scenario described (multiple tokens `ft1`/`ft2` with per-account deltas that only individually don't balance) and asserts `finalize()` returns `InvariantViolated::UnmatchedDeltas` with per-token unmatched amounts (`ft1: -3`, `ft2: -1`), confirming no cross-token netting occurs [5](#0-4) . Scaling this to 50 tokens does not change the mechanism — each `TokenTransferMatcher` remains self-contained per `TokenId`, so 50 independent `finalize_into` calls cannot bleed across each other. This is a structural (type-level) guarantee, not a logic bug, and the regression guard already exists in the test suite.

    pub fn finalize_into(self, token_id: &TokenId, transfers: &mut Transfers) -> Result<(), i128> {
        // sort deposits and withdrawals in descending order
        let [mut deposits, mut withdrawals] = [self.deposits, self.withdrawals].map(|amounts| {
            let mut amounts: Vec<_> = amounts.into_iter().collect();
            amounts.sort_unstable_by_key(|(_, amount)| Reverse(*amount));
            amounts.into_iter()
        });

        // take first sender and receiver
        let (mut deposit, mut withdraw) = (deposits.next(), withdrawals.next());

        // as long as there is both: sender and receiver
        while let Some(((sender, send), (receiver, receive))) =
            withdraw.as_mut().zip(deposit.as_mut())
        {
            // get min amount and transfer
            let transfer = (*send).min(*receive);
            transfers
                .transfer(sender.clone(), receiver.clone(), token_id.clone(), transfer)
                // no error can happen since we add only one transfer for each
                // combination of (sender, receiver, token_id)
                .unwrap_or_else(|| unreachable!());

            // subtract amount from sender and receiver
            *send = send.saturating_sub(transfer);
            *receive = receive.saturating_sub(transfer);

            if *send == 0 {
                // select next sender
                withdraw = withdrawals.next();
            }
            if *receive == 0 {
                // select next receiver
                deposit = deposits.next();
            }
        }

        // only sender(s) left
        if let Some((_, send)) = withdraw {
            return Err(withdrawals
                .try_fold(send, |total, (_, s)| total.checked_add(s))
                .and_then(|total| i128::try_from(total).ok())
                .and_then(i128::checked_neg)
                .unwrap_or_default());
        }
        // only receiver(s) left
        if let Some((_, receive)) = deposit {
            return Err(deposits
                .try_fold(receive, |total, (_, r)| total.checked_add(r))
                .and_then(|total| i128::try_from(total).ok())
                .unwrap_or_default());
        }

        Ok(())
    }
