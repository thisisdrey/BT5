Based on the code, the "huge/attacker-controlled timeout" framing in the question is incorrect — `yield_timeout_length_in_blocks` is a fixed `RuntimeConfig` parameter (`core/parameters/res/runtime_configs/parameters.yaml`), computed as `apply_state.block_height + config.wasm_config.limit_config.yield_timeout_length_in_blocks` in [1](#0-0) , not something an attacker can inflate. However, tracing the actual account-deletion interaction with pending yields surfaces a real, distinct bug in the same area.

### Title
Deleting an account with a pending `PromiseYield`/`PromiseResume` leaves orphaned trie state and loses the attached yield deposit - ([File: core/store/src/utils/mod.rs])

### Summary
`remove_account` (invoked by `action_delete_account`) removes the `Account`, `ContractCode`, access/gas keys, and `ContractData` entries for a deleted account, but never removes `TrieKey::PromiseYieldReceipt`, `PromiseYieldStatus`, or `YieldIdToDataId`/`DataIdToYieldId` entries keyed by that account. Since a `PromiseYield` receipt's `receiver_id` is always the creating account itself, an attacker can create a yield (optionally attaching a deposit via `promise_yield_create_with_id`) and then delete the same account, leaving the parked receipt and its attached balance permanently orphaned in state.

### Finding Description
`promise_yield_create`/`promise_yield_create_with_id` create a receipt whose `receiver_id` equals `self.context.current_account_id` — i.e., the yield always targets the creating account [2](#0-1) . This receipt is stored under `TrieKey::PromiseYieldReceipt { receiver_id, data_id }` and a companion `PromiseYieldStatus` entry, and (for `_with_id`) a `YieldIdToDataId`/`DataIdToYieldId` mapping, all keyed by the same account id [3](#0-2) .

`promise_yield_create_with_id` optionally deducts an `amount` directly from the calling contract's own balance at creation time and embeds it as the `deposit` of the parked callback's `FunctionCall` action [4](#0-3) ; this is confirmed by `create_with_id_deducts_attached_amount`, which shows the contract's on-chain balance is reduced immediately by `attached` [5](#0-4) .

Nothing in `action_delete_account` checks for or cleans up pending yields before deleting the account [6](#0-5) . `remove_account` only sweeps `Account`, `ContractCode`, access/gas keys, and `ContractData`; it never iterates or removes `PromiseYieldReceipt`/`PromiseYieldStatus`/yield-id-mapping keys for the account [7](#0-6) . The account's *current* balance is refunded to `beneficiary_id` via `Receipt::new_balance_refund`, but the already-deducted yield deposit is not part of that current balance — it lives only inside the un-executed `PromiseYieldReceipt` in trie.

When the pre-existing `PromiseYieldTimeout` queue entry later expires, `resolve_promise_yield_timeouts` finds `state_update.contains_key(&promise_yield_key)` still true (since it was never cleaned up) and synthesizes a `PromiseResume` addressed back to the now-deleted account [8](#0-7) . That resume, once processed, looks up and executes the still-present parked receipt against an account that no longer exists, so the `FunctionCall` action's deposit and the account context are inconsistent with a real, live account — the deposit was already stripped out of the token supply's live balance ledger and has no live account to land back on.

### Impact Explanation
This matches "permanent freezing/loss of user funds": the deposit attached to `promise_yield_create_with_id` is deducted from the account's live balance at creation time but is never returned when the account self-deletes before resume/timeout, since `remove_account` does not sweep `PromiseYieldReceipt`/`PromiseYieldStatus` state. It also leaves permanently unreachable/undeletable trie state (the receipt is keyed to an account id that will never exist again to resume it), which is a lesser but related state-bloat issue.

### Likelihood Explanation
Fully reachable by an unprivileged actor: fund an account, deploy a contract, call `promise_yield_create_with_id` with a non-zero `amount`, then submit `DeleteAccount` for the same account (either same wasm execution via a batched promise, or a follow-up transaction) before the fixed protocol timeout elapses or before calling resume. No special permissions, validator access, or misconfiguration are required — only ordinary transactions.

### Recommendation
`remove_account` should also enumerate and remove any `PromiseYieldReceipt`/`PromiseYieldStatus`/`YieldIdToDataId`/`DataIdToYieldId` entries for the account being deleted (mirroring how access keys and contract data are swept), refunding any embedded deposit/gas back to the deleting account's beneficiary before the account is removed. Alternatively, `action_delete_account` should reject deletion (similar to the existing staking-lock check) while the account has outstanding pending yields.

### Proof of Concept
Integration/runtime test plan (apply-path, akin to existing `test-loop-tests/src/tests/yield_timeouts.rs` helpers):
1. Deploy `rs_contract` to a funded test account.
2. Call `call_promise` with a `yield_create_with_id` op attaching a non-zero `amount` (as in `create_with_id_deducts_attached_amount`), recording the balance before/after to confirm the deposit was deducted from the live account balance.
3. In a subsequent receipt/transaction, submit `Action::DeleteAccount` for that same account with a distinct beneficiary.
4. Assert: (a) the beneficiary receives only the account's *residual* balance, not the yield's attached deposit; (b) `TrieKey::PromiseYieldReceipt`/`PromiseYieldStatus` for the deleted account are still present in state after deletion (using `get_all_promise_yield_timeouts`-style helpers); (c) advance blocks past `yield_timeout_length_in_blocks` and confirm `resolve_promise_yield_timeouts` still emits a `PromiseResume` for the deleted account, and trace whether the attached deposit is refunded anywhere or is simply lost, and whether `apply` panics or produces `StorageInconsistentState`.

pub(crate) fn action_delete_account(
    state_update: &mut TrieUpdate,
    account: &mut Option<Account>,
    actor_id: &mut AccountId,
    receipt: &Receipt,
    result: &mut ActionResult,
    account_id: &AccountId,
    delete_account: &DeleteAccountAction,
    config: &RuntimeConfig,
    current_protocol_version: ProtocolVersion,
) -> Result<(), StorageError> {
    let account_ref = account.as_ref().unwrap();
    let account_storage_usage = if ProtocolFeature::FixDeleteAccountGlobalContractStorageUsage
        .enabled(current_protocol_version)
    {
        let contract_storage = get_contract_storage_usage(state_update, account_id, account_ref)?;
        account_ref.storage_usage().saturating_sub(contract_storage)
    } else {
        // Legacy behavior: only subtracts local contract code, misses the
        // global contract identifier overhead.
        let account_storage_usage = account_ref.storage_usage();
        let code_len = get_code_len_or_default(
            state_update,
            account_id.clone(),
            account_ref.local_contract_hash().unwrap_or_default(),
        )?;
        debug_assert!(
            code_len == 0 || account_storage_usage > code_len,
            "account storage usage should be larger than code size. storage usage: {}, code size: {}",
            account_storage_usage,
            code_len
        );
        account_storage_usage.saturating_sub(code_len)
    };
    if account_storage_usage > Account::MAX_ACCOUNT_DELETION_STORAGE_USAGE {
        result.result =
            Err(ActionErrorKind::DeleteAccountWithLargeState { account_id: account_id.clone() }
                .into());
        return Ok(());
    }
    let gas_key_balance_to_burn = compute_gas_key_balance_sum(state_update, account_id)?;
    if gas_key_balance_to_burn > GasKeyInfo::MAX_BALANCE_TO_BURN {
        result.result = Err(ActionErrorKind::GasKeyBalanceTooHigh {
            account_id: account_id.clone(),
            public_key: None,
            balance: gas_key_balance_to_burn,
        }
        .into());
        return Ok(());
    }
    // We use current amount as a pay out to beneficiary.
    let account_balance = account_ref.amount();
    if account_balance > Balance::ZERO {
        result
            .new_receipts
            .push(Receipt::new_balance_refund(&delete_account.beneficiary_id, account_balance));
    }
    let remove_result = remove_account(state_update, account_id)?;
    result.tokens_burnt =
        result.tokens_burnt.checked_add(gas_key_balance_to_burn).ok_or_else(|| {
            StorageError::StorageInconsistentState("tokens_burnt overflow".to_string())
        })?;
    if remove_result.gas_key_nonce_count > 0 {
        let compute = storage_removes_compute(
            &config.wasm_config.ext_costs,
            remove_result.gas_key_nonce_count,
            remove_result.gas_key_nonce_total_key_bytes,
            AccessKey::NONCE_VALUE_LEN * remove_result.gas_key_nonce_count,
        );
        result.compute_usage = safe_add_compute(result.compute_usage, compute).map_err(|_| {
            StorageError::StorageInconsistentState("compute_usage overflow".to_string())
        })?;
    }
    *actor_id = receipt.predecessor_id().clone();
    *account = None;
    Ok(())
}

/// Removes account, code and all access keys and gas keys associated to it.
pub fn remove_account(
    state_update: &mut TrieUpdate,
    account_id: &AccountId,
) -> Result<RemoveAccountResult, StorageError> {
    state_update.remove(TrieKey::Account { account_id: account_id.clone() });
    state_update.remove(TrieKey::ContractCode { account_id: account_id.clone() });

    let mut gas_key_nonce_count: usize = 0;
    let mut gas_key_nonce_total_key_bytes: usize = 0;

    // Removing access keys and gas key nonces
    let lock = state_update.trie().lock_for_iter();
    let mut keys_to_remove: Vec<TrieKey> = Vec::new();
    for raw_key in state_update
        .locked_iter(&trie_key_parsers::get_raw_prefix_for_access_keys(account_id), &lock)?
    {
        let raw_key = raw_key?;
        let key_handle = trie_key_parsers::parse_key_handle_from_access_key_key(
            &raw_key, account_id,
        )
        .map_err(|_e| {
            StorageError::StorageInconsistentState(
                "Can't parse key handle from raw key for AccessKey".to_string(),
            )
        })?;
        let nonce_index =
            trie_key_parsers::parse_nonce_index_from_gas_key_key(&raw_key, account_id, &key_handle)
                .map_err(|_e| {
                    StorageError::StorageInconsistentState(
                        "Can't parse nonce index from raw key for AccessKey".to_string(),
                    )
                })?;
        if let Some(index) = nonce_index {
            gas_key_nonce_count += 1;
            gas_key_nonce_total_key_bytes += raw_key.len();
            keys_to_remove.push(TrieKey::gas_key_nonce(
                account_id.clone(),
                key_handle.clone(),
                index,
            ));
        } else {
            keys_to_remove.push(TrieKey::access_key(account_id.clone(), key_handle.clone()));
        }
    }
    drop(lock);

    for trie_key in keys_to_remove {
        state_update.remove(trie_key);
    }

    // Removing contract data
    let lock = state_update.trie().lock_for_iter();
    let data_keys = state_update
        .locked_iter(&trie_key_parsers::get_raw_prefix_for_contract_data(account_id, &[]), &lock)?
        .map(|raw_key| {
            trie_key_parsers::parse_data_key_from_contract_data_key(&raw_key?, account_id)
                .map_err(|_e| {
                    StorageError::StorageInconsistentState(
                        "Can't parse data key from raw key for ContractData".to_string(),
                    )
                })
                .map(Vec::from)
        })
        .collect::<Result<Vec<_>, _>>()?;
    drop(lock);

    for key in data_keys {
        state_update.remove(TrieKey::ContractData { account_id: account_id.clone(), key });
    }
    Ok(RemoveAccountResult { gas_key_nonce_count, gas_key_nonce_total_key_bytes })
}
