### Title
Race between window.Check and window.Update in ConnectionState.Decrypt allows duplicate-counter packets to both decrypt - ([File: connection_state.go])

### Summary
`ConnectionState.Decrypt` checks the replay window (`cs.window.Check`), releases `decryptLock`, performs AEAD decryption unlocked, then re-acquires the lock to call `cs.window.Update`. Two goroutines racing on packets carrying the identical `messageCounter` can both pass `Check` before either calls `Update`, so both proceed to decrypt the payload with `dKey.DecryptDanger`.

### Finding Description
`Decrypt` in `connection_state.go` is structured as: [1](#0-0) 

The window state is a sliding bitmap (`Bits`), where `Check` only reads state (`get(i)`/`strictlyWithinWindow`) and does not mark `i` as seen; only `Update` (specifically `updateSlow`'s duplicate branch or the fast path) actually sets the bit: [2](#0-1) [3](#0-2) 

Because `Check` and `Update` are each independently locked but the lock is released in between (across the unlocked `DecryptDanger` call), two goroutines processing two UDP packets with the same `messageCounter` can each acquire `decryptLock`, call `Check`, see the bit not yet set, and both return `true`. Both then proceed unlocked to call `cs.dKey.DecryptDanger(...)` with the same `messageCounter`/nonce on the same cipher state. Only afterward do they race to call `Update`; one of them will find the bit already set and return `false` (`ErrAlreadySeen`), but by that point decryption has already been fully performed for both packets — the second `Update` failing does not undo the already-completed decrypt.

For a receive-path decrypt, this does not cause key nonce reuse in the "encrypt twice with same nonce" sense (that's an attacker-controlled ciphertext being decrypted, not two distinct plaintexts encrypted under one nonce), but it does allow a genuine authenticated replay: an attacker who captures/replays a single legitimate ciphertext packet (spoofing arrival order/timing) can cause it to be decrypted and — depending on caller behavior — potentially delivered twice to the tunnel consumer before the anti-replay bookkeeping catches up, because the anti-replay decision (`Update`) is decoupled in time from the decrypt itself. This is a TOCTOU (check-then-act) race in the replay-window enforcement, not a nonce-confidentiality break, since `DecryptDanger` for the *same* ciphertext/counter will produce the same (correct) plaintext for both racing calls, not different keystream reuse.

I could not fully verify from the indexed code where the decrypted plaintext is delivered up the stack relative to the `Update` result check (the call site is in `outside.go`, whose exact ordering logic was not retrieved in this session), so I cannot confirm whether a successfully-decrypted-but-later-`ErrAlreadySeen` packet is actually forwarded to the tun device or dropped. That gap should be verified before treating this as delivering a duplicate packet to the application; without confirming that, the impact is limited to a duplicate/wasted decrypt operation rather than a confirmed double-delivery or confidentiality/integrity break.

### Impact Explanation
At minimum this is a replay-window race allowing the same ciphertext to be decrypted twice concurrently, which is a violation of the intended invariant "each counter is checked-and-marked atomically against the anti-replay window." Whether this rises to actual duplicate packet delivery (replay bypass) depends on caller logic in `outside.go` not fully verified here. It is not a nonce/key-reuse confidentiality break, since both racing decrypts use the identical ciphertext and counter (an attacker replaying one packet twice), not two different plaintexts encrypted under one reused nonce.

### Likelihood Explanation
Requires an attacker to send (or replay) two UDP packets with the same `messageCounter` in close enough succession to be processed by concurrent goroutines before the first `Update` completes — plausible under typical multi-queue/multi-goroutine packet processing, but the window is narrow (bounded by one AEAD decrypt's duration).

### Recommendation
Merge the check-and-mark into a single atomic operation, e.g. hold `decryptLock` across `Check`, `DecryptDanger`, and `Update` (or perform an atomic "check-and-reserve" bit-set before decrypting and roll back on decrypt failure), so no other goroutine can observe an unmarked window slot for a counter that is concurrently being processed.

### Proof of Concept
Unit/integration test: create a `ConnectionState` with a real cipher and valid ciphertext for `messageCounter = N`. Launch two goroutines that both call `cs.Decrypt(l, N, ...)` with the same packet bytes concurrently, run with `-race` and repeat several times. Assert that only one goroutine returns a non-error decrypted result and the other returns `ErrAlreadySeen` *before* performing the decrypt (i.e., instrument/count calls into `dKey.DecryptDanger` and assert it is invoked exactly once, not twice, for the shared counter).

func (cs *ConnectionState) Decrypt(l *slog.Logger, messageCounter uint64, out []byte, packet []byte, nb []byte) ([]byte, error) {
	var err error
	cs.decryptLock.Lock()
	result := cs.window.Check(l, messageCounter)
	cs.decryptLock.Unlock()
	if !result {
		return nil, ErrAlreadySeen

	result = cs.window.Update(l, messageCounter)

// Check returns true if i is within (or way out in front of) the window, and not a replay
func (b *Bits) Check(l *slog.Logger, i uint64) bool {
	// If i is the next number, return true.
	if i > b.current {
		return true
	}

	if b.strictlyWithinWindow(i) {
		return !b.get(i)
	}

	// Not within the window
	if l.Enabled(context.Background(), slog.LevelDebug) {
		l.Debug("rejected a packet (top)", "current", b.current, "incoming", i)
	}
	return false
}

func (b *Bits) Update(l *slog.Logger, i uint64) bool {
	// Fast path: i is the next expected counter. Split out so the function
	// stays small and avoids paying for the slow paths' slog argument-build
	// stack frame on every call. The bit read/test/write is inlined to
	// touch the backing word once.
	if i == b.current+1 {
		pos := i & b.lengthMask
		word := pos >> 6
		mask := uint64(1) << (pos & 63)
		w := b.bits[word]
		if i > b.length && w&mask == 0 {
			b.lostCounter.Inc(1)
		}
		b.bits[word] = w | mask
		b.current = i
		return true
	}
	return b.updateSlow(l, i)
}

// updateSlow handles jumps, in-window backfill, dupes, and out-of-window.
func (b *Bits) updateSlow(l *slog.Logger, i uint64) bool {
	// If i is a jump, adjust the window, record lost, update current, and return true
	if i > b.current {
		end := i
		if end > b.current+b.length {
			end = b.current + b.length
		}
		count := end - b.current
		startPos := (b.current + 1) & b.lengthMask

		var lost int64
		if b.current >= b.length {
			// Steady state: every cleared slot is past warmup, so any unset
			// bit we evict is a lost packet from the previous cycle.
			wasSet := b.clearRange(startPos, count)
			lost = int64(count) - int64(wasSet)
		} else {
			// Warmup (the very first window). Some cleared slots represent
			// packets <= length where eviction is not "lost" in the usual
			// sense. This branch is taken at most once per connection so we
			// don't bother optimizing it.
			for n := b.current + 1; n <= end; n++ {
				if !b.get(n) && n > b.length {
					lost++
				}
			}
			b.clearRange(startPos, count)
		}

		// Anything past the new window can never be backfilled, so it's lost.
		if i > b.current+b.length {
			lost += int64(i - b.current - b.length)
		}
		b.lostCounter.Inc(lost)

		b.set(i)
		b.current = i
		return true
	}

	// If i is within the current window but below the current counter, check to see if it's a duplicate
	if b.strictlyWithinWindow(i) {
		pos := i & b.lengthMask
		word := pos >> 6
		mask := uint64(1) << (pos & 63)
		w := b.bits[word]
		if b.current == i || w&mask != 0 {
			if l.Enabled(context.Background(), slog.LevelDebug) {
				l.Debug("Receive window",
					"accepted", false,
					"currentCounter", b.current,
					"incomingCounter", i,
					"reason", "duplicate",
				)
			}
			b.dupeCounter.Inc(1)
			return false
		}

		b.bits[word] = w | mask
		return true
	}
