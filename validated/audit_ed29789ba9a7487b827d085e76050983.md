### Title
Stake classification for QUIC connections is cached at connection-establishment and never rechecked, letting deactivated/withdrawn stake keep staked-tier QoS for the connection's lifetime - (File: streamer/src/nonblocking/swqos.rs)

### Summary
This maps the report's root cause — a privilege threshold check that is evaluated once and never re-applied when the underlying value changes — onto agave's stake-weighted QUIC QoS (SWQoS) path. `SwQosConnectionContext` (peer_type/total_stake) is computed once in `build_connection_context` at connection setup and then reused for the entire life of the connection.

### Finding Description
`SwQos::build_connection_context` looks up the peer's current stake via `get_connection_stake` and decides `ConnectionPeerType::Staked(stake)` vs `Unstaked`, comparing the peer's stake ratio against `min_stake_ratio` at that single point in time [1](#0-0) . This `SwQosConnectionContext` (containing `peer_type` and `total_stake`) is stored and reused for admission control, per-peer connection limits, and stream-throughput limits for the whole lifetime of the QUIC connection: `cache_new_connection` uses `conn_context.peer_type()` and `conn_context.total_stake` to size `max_uni_streams` and pick `max_connections_per_peer` [2](#0-1) , and `max_streams_per_throttling_interval` continues to use the same cached `peer_type`/`total_stake` to compute available stream load capacity for every subsequent stream on that connection [3](#0-2) . There is no mechanism found in `SwQos`/`swqos.rs` that re-queries `staked_nodes` or rebuilds `SwQosConnectionContext` mid-connection to reflect a stake decrease (e.g., deactivation, withdrawal, or delegation to another validator) that occurs after the connection was accepted.

### Impact Explanation
Because the staked/unstaked classification and the associated elevated concurrent-stream/connection limits (`QUIC_MAX_STAKED_CONCURRENT_STREAMS`, `max_connections_per_staked_peer`, staked share of `available_load_capacity_in_throttling_duration`) are fixed at connection time [4](#0-3) , a peer that held sufficient stake when it opened its QUIC connection retains staked-tier QoS treatment even after its stake later drops below the threshold used to distinguish staked vs. unstaked traffic. This is a QoS-evasion condition: an attacker (or a legitimately-staked node that later unstakes) can keep an open connection alive to continue enjoying disproportionately higher stream/connection quotas than currently-staked peers, degrading fairness of TPU packet admission for genuinely staked validators, an unprivileged-reachable QoS bypass in the QUIC/UDP streamer path.

### Likelihood Explanation
Any remote peer can trigger this by opening a QUIC connection while staked (or via a stake-ratio computation that is momentarily favorable) and then keeping the connection open across a stake change; no validator/operator privilege is required to exploit the staleness, only ordinary participation in staking/unstaking, which is fully within reach of an unprivileged network participant.

### Recommendation
Periodically re-evaluate `peer_type`/`total_stake` for long-lived connections (e.g., on an interval similar to `STREAM_LOAD_EMA_INTERVAL_MS` used elsewhere in `stream_throttle.rs`) instead of relying solely on the value captured once in `build_connection_context`, and downgrade/close connections whose backing stake has dropped, mirroring the mitigation of rechecking the balance/threshold each time votes/permissions are evaluated in the original report.

### Proof of Concept
Not independently executed; based on static code inspection of `streamer/src/nonblocking/swqos.rs` (`build_connection_context`, `cache_new_connection`, `max_streams_per_throttling_interval`) showing `SwQosConnectionContext` is constructed once and never refreshed while the QUIC connection persists [5](#0-4) . I was not able to fully verify within the available searches whether any higher-level component (outside `swqos.rs`/`quic.rs`) periodically tears down and re-admits connections based on updated `staked_nodes` state; this should be confirmed with a deeper repo-wide search or a live Devin session before treating this as fully conclusive.

fn compute_max_allowed_uni_streams_with_rtt(
    rtt_millis: u32,
    peer_type: ConnectionPeerType,
    total_stake: u64,
) -> u32 {
    let streams = match peer_type {
        ConnectionPeerType::Staked(peer_stake) => {
            // No checked math for f64 type. So let's explicitly check for 0 here
            if total_stake == 0 || peer_stake > total_stake {
                warn!(
                    "Invalid stake values: peer_stake: {peer_stake:?}, total_stake: \
                     {total_stake:?}"
                );

                QUIC_MIN_STAKED_CONCURRENT_STREAMS
            } else {
                let delta = (QUIC_TOTAL_STAKED_CONCURRENT_STREAMS
                    - QUIC_MIN_STAKED_CONCURRENT_STREAMS) as f64;

                (((peer_stake as f64 / total_stake as f64) * delta) as u32
                    + QUIC_MIN_STAKED_CONCURRENT_STREAMS)
                    .clamp(
                        QUIC_MIN_STAKED_CONCURRENT_STREAMS,
                        QUIC_MAX_STAKED_CONCURRENT_STREAMS,
                    )
            }
        }
        ConnectionPeerType::Unstaked => QUIC_MAX_UNSTAKED_CONCURRENT_STREAMS,
    };
    // scale amount of streams based on RTT if RTT is larger than REFERENCE_RTT_MS
    // multiply first then divide to avoid rounding errors.
    (streams.saturating_mul(rtt_millis.clamp(REFERENCE_RTT_MS, MAX_RTT_MS))) / REFERENCE_RTT_MS
}

impl QosController<SwQosConnectionContext> for SwQos {
    fn build_connection_context(&self, connection: &Connection) -> SwQosConnectionContext {
        let remote_address = connection.remote_address();
        get_connection_stake(connection, &self.staked_nodes).map_or(
            SwQosConnectionContext {
                peer_type: ConnectionPeerType::Unstaked,
                total_stake: 0,
                remote_pubkey: None,
                in_staked_table: false,
                remote_address,
                stream_counter: None,
                last_update: Arc::new(AtomicU64::new(timing::timestamp())),
            },
            |(pubkey, stake, total_stake)| {
                // The heuristic is that the stake should be large enough to have 1 stream pass through within one throttle
                // interval during which we allow max (MAX_STREAMS_PER_MS * STREAM_THROTTLING_INTERVAL_MS) streams.

                let peer_type = {
                    let max_streams_per_ms = self.staked_stream_load_ema.max_streams_per_ms();
                    let min_stake_ratio =
                        1_f64 / (max_streams_per_ms * STREAM_THROTTLING_INTERVAL_MS) as f64;
                    let stake_ratio = stake as f64 / total_stake as f64;
                    if stake_ratio < min_stake_ratio {
                        // If it is a staked connection with ultra low stake ratio, treat it as unstaked.
                        ConnectionPeerType::Unstaked
                    } else {
                        ConnectionPeerType::Staked(stake)
                    }
                };

                SwQosConnectionContext {
                    peer_type,
                    total_stake,
                    remote_pubkey: Some(pubkey),
                    in_staked_table: false,
                    remote_address,
                    last_update: Arc::new(AtomicU64::new(timing::timestamp())),
                    stream_counter: None,
                }
            },
        )
    }
