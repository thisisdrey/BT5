### Title
`Pool.swap()` exposes users to unlimited slippage — no min-amount-out or deadline parameter - (File: contracts/Pool.sol)

### Summary
`Pool.swap()` burns a user's synthetic tokens and mints a different synthetic token priced purely by `masterOracle().quote()` at execution time. The function accepts no `amountOutMin` slippage parameter and no expiration deadline, so a transaction delayed in the mempool or intentionally held/reordered by a validator can execute at a worse oracle price than the user expected, minting fewer tokens. This is the same bug class as `USSD.mintForToken()`: an oracle-priced swap/mint with no user-defined slippage bound.

### Finding Description
`Pool.swap` signature (`contracts/Pool.sol:642-653`) takes only `syntheticTokenIn_`, `syntheticTokenOut_`, and `amountIn_`:

```solidity
function swap(
    ISyntheticToken syntheticTokenIn_,
    ISyntheticToken syntheticTokenOut_,
    uint256 amountIn_
) external override whenNotShutdown nonReentrant ... {
    ...
    syntheticTokenIn_.burn(_msgSender, amountIn_);
    (_amountOut, _fee) = quoteSwapOut(syntheticTokenIn_, syntheticTokenOut_, amountIn_);
    if (_fee > 0) syntheticTokenOut_.mint(_poolRegistry.feeCollector(), _fee);
    syntheticTokenOut_.mint(_msgSender, _amountOut);
}
```

`quoteSwapOut` (`contracts/Pool.sol:508-525`) prices the output solely via `masterOracle().quote(tokenIn, tokenOut, amountIn_)` minus `feeProvider.swapFees(...)`. There is no comparison of `_amountOut` against a user-supplied minimum, and no `deadline` check anywhere in the path. The modifiers (`whenNotShutdown`, `nonReentrant`, `onlyIfSyntheticTokenExists`, `isSwapActive`) gate liveness and validity of the tokens, but none bound the execution price or time.

Notably, the protocol's own `SmartFarmingManager` acknowledges this risk class for external DEX swaps — `flashRepay` enforces `swapAmountOutMin_` (`contracts/SmartFarmingManager.sol:126`) and `leverage` enforces `depositAmountMin_` — yet the core `Pool.swap` oracle-priced exchange offers no equivalent protection.

### Impact Explanation
A user calling `swap` commits `amountIn_` tokens to be burned at a price determined at inclusion time. If the oracle price of the output synth rises (or input synth falls) between signing and execution — due to natural mempool delay or a validator/sequencer deliberately holding the transaction — the user receives fewer tokens with no ability to revert. The user loses funds equal to the adverse price movement; the loss is unbounded because no minimum output is enforceable. This is direct loss of user funds, matching the accepted impact criteria.

### Likelihood Explanation
Any EOA can call `swap` directly; no privileged role is needed. Exploitation requires only that the oracle price moves adversely while the victim's tx is pending — a routine occurrence during volatility or gas spikes, and trivially exploitable by a block builder/validator that can delay ordering. If any configured oracle route (e.g., a vault-share or DEX-derived price in `MasterOracle`) is manipulable within a transaction, an attacker can also sandwich the victim's `swap` between price-moving AMM trades, converting incidental slippage into deterministic theft.

### Recommendation
Add a `uint256 amountOutMin_` (and optionally `uint256 deadline_`) parameter to `Pool.swap` and revert if `block.timestamp > deadline_` or `_amountOut < amountOutMin_`, consistent with the slippage checks already used in `SmartFarmingManager.flashRepay`/`leverage`. Update `IPool.swap` accordingly.

### Proof of Concept
```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.0;

import "forge-std/Test.sol";
import {IPool} from "../contracts/interfaces/IPool.sol";
import {ISyntheticToken} from "../contracts/interfaces/ISyntheticToken.sol";
import {IMasterOracle} from "../contracts/interfaces/external/IMasterOracle.sol";

contract PoolSwapSlippageTest is Test {
    // Fork a chain where Pool is deployed (e.g., base/mainnet deployments/*)
    IPool pool;          // deployed Pool proxy
    ISyntheticToken in_;  // e.g. msUSD
    ISyntheticToken out_; // e.g. msETH
    address alice = address(0xA11CE);

    function test_swapNoSlippageProtection() public {
        uint256 amountIn = 1_000e18;
        deal(address(in_), alice, amountIn);

        // Quoted output at time T (user signs tx expecting this)
        (uint256 quotedOut, ) = pool.quoteSwapOut(in_, out_, amountIn);

        // Simulate adverse oracle move while tx sits in mempool:
        // e.g., output token's oracle price doubles (or is manipulated
        // same-tx via an AMM-priced oracle source).
        vm.mockCall(
            address(pool.masterOracle()),
            abi.encodeWithSelector(IMasterOracle.quote.selector, address(in_), address(out_), amountIn),
            abi.encode(quotedOut / 2) // 50% worse price
        );

        vm.prank(alice);
        (uint256 amountOut, ) = pool.swap(in_, out_, amountIn); // no minOut param exists

        // User receives half of what they expected; tx cannot revert
        assertEq(amountOut, quotedOut / 2);
        assertEq(in_.balanceOf(alice), 0);
        assertEq(out_.balanceOf(alice), quotedOut / 2);
    }
}
```
The test demonstrates that `swap` has no mechanism for the caller to bound `_amountOut`: once the oracle price moves, the burned `amountIn_` yields arbitrarily fewer output tokens and the call still succeeds.
