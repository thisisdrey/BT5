### No vulnerability found for this question.

The premise is technically incorrect: `Promise::new(withdraw.receiver_id).transfer(withdraw.amount)` in `Contract::do_native_withdraw` schedules a bare `Transfer` action, not a `FunctionCall` action [1](#0-0) . A NEAR `Transfer` action only credits the receiver account's balance at the protocol/runtime level; it does not invoke any contract code, wasm entrypoint, or `receiver_id`'s deployed logic, regardless of what contract is deployed there. There is no mechanism for a deployed "gas-burning" contract to intercept or consume gas on a plain balance transfer — that only applies to `FunctionCall` actions (e.g. `ft_transfer_call`, `mt_batch_transfer_call`, which are used elsewhere in this codebase and do carry that class of risk for callback gas, but not for `do_native_withdraw`).

Since no receiver code executes, the receipt cannot "run out of gas" due to attacker logic in a deployed contract at `receiver_id`; the only way this transfer fails is if `receiver_id` does not exist as an account, which is already documented as an accepted, unrefunded failure mode in `NativeWithdraw`'s doc comment [2](#0-1) . The gas allocated to this promise (`DO_NATIVE_WITHDRAW_GAS = Gas::from_tgas(12)`, `with_unused_gas_weight(0)`) is irrelevant to this scenario since it's a static-cost transfer, not something an attacker-controlled contract can loop against [3](#0-2) .

The `wNEAR_debited(signer) == NEAR_delivered(receiver_id)` equality can only be broken by the pre-existing, documented risk that `receiver_id` doesn't exist as an account (causing the transfer to fail and NEAR to be irrecoverably burned/returned to the contract without refund to the signer) — not by an attacker deploying gas-burning code, since no code execution is possible on a `Transfer` action.

```rust
    fn native_withdraw(&mut self, owner_id: &AccountIdRef, withdraw: NativeWithdraw) -> Result<()> {
        self.withdraw(
            owner_id,
            [(
                Nep141TokenId::new(self.wnear_id().into_owned()).into(),
                withdraw.amount.as_yoctonear(),
            )],
            Some("withdraw"),
            false,
        )?;

        ext_wnear::ext(self.wnear_id.clone())
            .with_attached_deposit(NearToken::from_yoctonear(1))
            .with_static_gas(NEAR_WITHDRAW_GAS)
            // do not distribute remaining gas here
            .with_unused_gas_weight(0)
            .near_withdraw(U128(withdraw.amount.as_yoctonear()))
            .then(
                // do_native_withdraw only after unwrapping NEAR
                Self::ext(env::current_account_id())
                    .with_static_gas(Self::DO_NATIVE_WITHDRAW_GAS)
                    // do not distribute remaining gas here
                    .with_unused_gas_weight(0)
                    .do_native_withdraw(withdraw),
            )
            .detach();

        Ok(())
    }
```
