### Title
Gitaly `WriteRef`/`SetDefaultBranch` lets HEAD be pointed at a non-existent or non-commit reference, bricking default-branch operations - (File: internal/git/localrepo/refs.go)

### Summary
The `RepositoryService.WriteRef` RPC allows any caller with write access to set `HEAD` to an arbitrary reference name. The underlying implementation, `Repo.SetDefaultBranch`, only checks that the *name string* is syntactically well-formed and explicitly documents that it does **not** verify the target reference exists or resolves to a valid commit object. This mirrors the OpenQ bug class: a function performs a shallow, "generic" format/interface check (valid ref-name syntax) instead of the stronger semantic check actually required downstream (target must exist and be a usable commit-ish), so a value that passes the loose check later breaks every operation that assumes HEAD is well-formed.

### Finding Description
`Repo.SetDefaultBranch` validates only the ref name format via `git.ValidateReference`, and its own doc comment states it "will not verify the reference actually exists": [1](#0-0) 

This is invoked directly from the `WriteRef` RPC whenever the client sets `Ref == "HEAD"`, using `req.GetRevision()` verbatim as the new symbolic target: [2](#0-1) 

`validateWriteRefRequest` only calls `git.ValidateRevision` (a syntax check) on the `revision` bytes when the ref is `HEAD` — unlike the non-HEAD path (`updateRef`), which resolves the revision with `repo.ResolveRevision(... + "^{object}")` to confirm the target object actually exists before committing the update: [3](#0-2) [4](#0-3) 

The test suite confirms this asymmetry is intentional and reproducible: setting HEAD to `refs/heads/non_existent_ref` succeeds without error and HEAD ends up dangling: [5](#0-4) 

This is the same bug shape as the OpenQ report: `_receiveERC20`'s type check ("does this address respond to `transferFrom`/`balanceOf`?") is weaker than what payout requires ("must be a real ERC20 with `transfer`"), so a wrong-typed token is accepted at funding time and breaks all subsequent payouts. Here, `SetDefaultBranch`'s check ("is this a syntactically valid ref name?") is weaker than what every downstream consumer of HEAD requires ("must resolve to an existing commit"), so a dangling/invalid HEAD is accepted at write time and breaks all subsequent operations that dereference the default branch.

### Impact Explanation
Once HEAD points to a non-existent reference (or, since resolution isn't checked, potentially to a non-commit object), any operation depending on `git.DefaultRef`/HEAD resolution — checkouts, archive generation, browsing the default branch, clone's initial checkout, and any RPC that calls `GetDefaultBranch`/`HeadReference` and expects a resolvable commit — starts failing for that repository. This is a repository-wide denial-of-service condition reachable by any ordinary user with push/write access via a single gRPC field (`WriteRefRequest.Revision`), e.g. by racing a "change default branch" action against deletion of the target branch, or simply supplying a reference name that never existed.

### Likelihood Explanation
Likelihood is high given the code path is a single-field, unauthenticated-at-the-Gitaly-layer RPC call (`WriteRef` with `Ref == "HEAD"`) with no verification that the target reference exists, and this is exercised in normal "set default branch" flows (e.g. from GitLab's UI/API) as well as directly through the Gitaly RPC surface.

### Recommendation
Apply the same resolution/existence check used in the non-HEAD path (`updateRef`'s `repo.ResolveRevision(revision + "^{object}")`, ideally `^{commit}`) to the HEAD/`SetDefaultBranch` path before committing the symbolic-ref update, rejecting revisions that do not resolve to an existing commit object.

### Proof of Concept
1. Create a repository with at least one commit and branch `main`.
2. Call `WriteRef` with `Ref = "HEAD"`, `Revision = "refs/heads/does-not-exist"`.
3. Observe the call succeeds (per `TestRepo_SetDefaultBranch`'s "unknown ref" case), and `HeadReference` now returns the dangling target.
4. Subsequent operations relying on HEAD resolving to a commit (checkout, archive, default-branch browsing) fail until an operator issues another `WriteRef` call pointing HEAD at a valid, existing commit reference.

// SetDefaultBranch sets the repository's HEAD to point to the given reference.

func (repo *Repo) SetDefaultBranch(ctx context.Context, txManager transaction.Manager, reference git.ReferenceName) error {
	if err := git.ValidateReference(reference.String()); err != nil {
		return fmt.Errorf("%q is a malformed refname", reference)
	}

	return repo.setDefaultBranchWithUpdateRef(ctx, reference)
}

func (s *server) writeRef(ctx context.Context, req *gitalypb.WriteRefRequest) error {
	repo := s.localRepoFactory.Build(req.GetRepository())

	if string(req.GetRef()) == "HEAD" {
		if err := repo.SetDefaultBranch(ctx, s.txManager, git.ReferenceName(req.GetRevision())); err != nil {
			return fmt.Errorf("setting default branch: %w", err)
		}

		return nil
	}

	return updateRef(ctx, repo, req)
}

func validateWriteRefRequest(ctx context.Context, locator storage.Locator, req *gitalypb.WriteRefRequest) error {
	if err := locator.ValidateRepository(ctx, req.GetRepository()); err != nil {
		return err
	}
	if err := git.ValidateRevision(req.GetRef()); err != nil {
		return fmt.Errorf("invalid ref: %w", err)
	}
	if err := git.ValidateRevision(req.GetRevision()); err != nil {
		return fmt.Errorf("invalid revision: %w", err)
	}
	if len(req.GetOldRevision()) > 0 {
		if err := git.ValidateRevision(req.GetOldRevision()); err != nil {
			return fmt.Errorf("invalid OldRevision: %w", err)
		}
	}

	if !bytes.Equal(req.GetRef(), []byte("HEAD")) && !bytes.HasPrefix(req.GetRef(), []byte("refs/")) {
		return fmt.Errorf("ref has to be a full reference")
	}
	return nil
