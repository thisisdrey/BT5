## Analysis

The ERC-7683 report describes a class of bug where a critical field (a destination/target reference) is populated without the validation/derivation logic that a sibling, "correct" implementation uses elsewhere in the same codebase — leading to a functional/security break at that specific call site while the rest of the code path uses the right approach.

The closest concrete analog in this Gitaly checkout is in the tar-extraction routines used by the `gitaly recovery replay` and `gitaly recovery restore` CLI commands. Gitaly already has a "correct" implementation of safe tar extraction — `extractTarToDirectory` in [1](#0-0)  — which explicitly validates that every `TypeDir`/`TypeReg` entry's `targetPath`, as well as symlink and hardlink targets, remain prefixed by `targetDir` before touching the filesystem. However, the two "recovery" extraction helpers omit this validation entirely.

`extractArchive` in [2](#0-1)  computes `target := filepath.Join(path, header.Name)` and immediately calls `os.MkdirAll`/`os.OpenFile` on it with no containment check.

Similarly, `extractBackup` in [3](#0-2)  computes `targetPath := filepath.Join(destDir, header.Name)` and writes to it without verifying the result stays inside `destDir`.

Both are reachable from crafted archive content: `extractArchive` is fed by WAL log entry archives pulled from the archival log-entry store during `gitaly recovery replay` (`processLogEntry` → `extractArchive`, see [4](#0-3) ), and `extractBackup` is fed by backup archives pulled from the configured backup sink during `gitaly recovery restore` (see [5](#0-4) ). Both sinks are external storage locations (backup bucket / archival log store) that Gitaly trusts implicitly at extraction time, unlike `CreateRepositoryFromSnapshot`'s `untar` helper, which shells out to the real `tar` binary (which refuses `..` path components) rather than Go's raw `archive/tar` package.

### Title
Path traversal in Gitaly disaster-recovery tar extraction due to missing containment validation - (File: internal/cli/gitaly/subcmd_recovery_replay.go, internal/cli/gitaly/subcmd_recovery_restore.go)

### Summary
The `gitaly recovery replay` and `gitaly recovery restore` administrative commands extract tar archives (WAL log-entry archives and partition backup archives, respectively) using hand-rolled `archive/tar` loops that join `header.Name` directly onto the destination directory without verifying the resulting path stays within that directory. A sibling extraction routine in the same codebase, `extractTarToDirectory` (used by `GetSnapshot`/`CreateFromSnapshot` replication), already implements exactly this containment check for regular files, directories, symlinks, and hardlinks — the recovery-path helpers were not updated to match it.

### Finding Description
`extractArchive` (`subcmd_recovery_replay.go`) and `extractBackup` (`subcmd_recovery_restore.go`) both do:
```go
target := filepath.Join(path, header.Name)
```
and then unconditionally call `os.MkdirAll(target, ...)` or `os.OpenFile(target, os.O_CREATE|os.O_WRONLY|os.O_TRUNC, ...)` and copy the tar entry's content into it. Neither function checks that `target`/`targetPath` is still prefixed by the intended staging/destination directory, which is exactly the check present in `extractTarToDirectory`:
```go
if !strings.HasPrefix(targetPath, targetDir+string(os.PathSeparator)) &&
    targetPath != targetDir {
    return fmt.Errorf("invalid file path in tar: %s", header.Name)
}
``` [6](#0-5) 

Because `filepath.Join` cleans `..` segments arithmetically (e.g. `filepath.Join("/tmp/staging", "../../etc/cron.d/evil")` resolves outside `/tmp/staging`), a tar entry whose `header.Name` contains `../` sequences will cause both recovery helpers to create files or directories outside the intended staging directory (`tempDir`/`stagingDir` in the replay path, or `partitionTempDir` in the restore path). In the restore path, the extracted output is subsequently moved into the live storage root with `moveRepositoryToStorage` (`os.Rename`), meaning a crafted backup archive can plant arbitrary files anywhere writable by the Gitaly process before the restore even completes.

### Impact Explanation
**Medium-High.** Anyone able to place a crafted archive in the trusted backup sink or the archival WAL log-entry store consumed by `gitaly recovery restore`/`gitaly recovery replay` can write arbitrary files to arbitrary filesystem locations reachable by the Gitaly process (subject to OS permissions), analogous to a classic "Zip Slip" vulnerability. This can corrupt unrelated storages, overwrite configuration, or plant executable content depending on where the traversal lands.

### Likelihood Explanation
**Medium.** These commands are administrative disaster-recovery tools, not directly exposed to unauthenticated pushers/fetchers, so exploitation requires the attacker to have (or obtain) write access to the archival log store or backup bucket that feeds these commands — a trust boundary that is plausible in multi-tenant or compromised-storage-credential scenarios, and is exactly the kind of boundary the sibling `extractTarToDirectory` implementation was hardened against.

### Recommendation
Apply the same containment validation used in `extractTarToDirectory` (`internal/gitaly/service/repository/replicate.go`) to `extractArchive` and `extractBackup`: after computing the joined path, verify it is still prefixed by the intended root directory (and reject/clean any symlink or hardlink targets that escape it) before creating directories/files or writing content.

### Proof of Concept
1. Craft a tar archive whose entry `header.Name` is `../../../../tmp/evil/payload` (`tar.TypeReg`).
2. Place this archive where `gitaly recovery restore` reads its "latest backup" from (the backup sink location resolved via the partition manifest), or where `gitaly recovery replay` reads WAL log entries from (the archival log-entry store).
3. Run `gitaly recovery restore --config <cfg> --storage <name> --partition <id>` (or `recovery replay`).
4. `extractBackup`/`extractArchive` will call `filepath.Join(destDir, "../../../../tmp/evil/payload")`, resolving outside `destDir`, and write attacker-controlled content to `/tmp/evil/payload` (or any other path reachable via `../` traversal) instead of confining it to the staging directory.

// extractTarToDirectory extracts a tar archive to the specified directory using Go's tar package
func (s *server) extractTarToDirectory(ctx context.Context, reader io.Reader, targetDir string) error {
	targetDir = filepath.Clean(targetDir)
	tarReader := tar.NewReader(reader)

	for {
		select {
		case <-ctx.Done():
			return ctx.Err()
		default:
		}

func extractArchive(reader io.Reader, path string) error {
	tr := tar.NewReader(reader)
	for {
		header, err := tr.Next()
		if err == io.EOF {
			break
		}
		if err != nil {
			return fmt.Errorf("read tar header: %w", err)
		}

		target := filepath.Join(path, header.Name)
		switch header.Typeflag {
		case tar.TypeDir:
			if err := os.MkdirAll(target, mode.Directory); err != nil {
				return fmt.Errorf("create directory: %w", err)
			}
		case tar.TypeReg:
			f, err := os.OpenFile(target, os.O_CREATE|os.O_RDWR, os.FileMode(header.Mode))
			if err != nil {
				return fmt.Errorf("create file: %w", err)
			}
			if _, err := io.Copy(f, tr); err != nil {
				f.Close()
				return fmt.Errorf("write file content: %w", err)
			}
			f.Close()
		default:
			return fmt.Errorf("tar header type not supported: %d", header.Typeflag)
		}
	}

	return nil
}

// extractBackup extracts the contents of a backup tar file to the specified directory.
// It returns any error encountered during extraction.
func extractBackup(reader io.Reader, destDir string) (string, error) {
	var repoRelPath string
	tarReader := tar.NewReader(reader)
	for {
		header, err := tarReader.Next()
		if err != nil {
			if errors.Is(err, io.EOF) {
				break
			}

			return repoRelPath, fmt.Errorf("read tar header: %w", err)
		}

		targetPath := filepath.Join(destDir, header.Name)

		switch header.Typeflag {
		case tar.TypeDir:
			if err := os.MkdirAll(targetPath, os.FileMode(header.Mode)); err != nil {
				return repoRelPath, fmt.Errorf("create directory %s: %w", header.Name, err)
			}

			if strings.HasSuffix(targetPath, ".git") {
				repoRelPath, err = filepath.Rel(filepath.Join(destDir, "fs"), targetPath)
				if err != nil {
					return repoRelPath, fmt.Errorf("find rel path: %w", err)
				}
			}
		case tar.TypeReg:
			if err := os.MkdirAll(filepath.Dir(targetPath), mode.Directory); err != nil {
				return repoRelPath, fmt.Errorf("create parent directory for %s: %w", header.Name, err)
			}

			file, err := os.OpenFile(targetPath, os.O_CREATE|os.O_WRONLY|os.O_TRUNC, os.FileMode(header.Mode))
			if err != nil {
				return repoRelPath, fmt.Errorf("create file %s: %w", header.Name, err)
			}

			if _, err := io.Copy(file, tarReader); err != nil {
				return repoRelPath, fmt.Errorf("write file %s: %w", header.Name, errors.Join(err, file.Close()))
			}

			if err := file.Close(); err != nil {
				return repoRelPath, fmt.Errorf("close file %s: %w", header.Name, err)
			}
		default:
			return repoRelPath, fmt.Errorf("unsupported file type %d for %s", header.Typeflag, header.Name)
		}
	}

	return repoRelPath, nil
}
