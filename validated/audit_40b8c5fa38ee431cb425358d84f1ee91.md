### Title
Unauthenticated `/shutdown` HTTP endpoint permits any remote party reaching the signer event port to permanently halt event processing - (File: libsigner/src/events.rs)

### Summary
The `SignerEventReceiver::next_event` handler dispatches on URL path only, with no secret, token, or peer-identity check. Any TCP client that can connect to the bound event-listener port and send `POST /shutdown` will flip the shared `stop_signal` atomic, causing every subsequent `next_event()` call to return `Err(EventError::Terminated)` and the signer's main run loop to exit.

### Finding Description
The intended trust boundary is that only the process's own `SignerStopSignaler` (constructed via `get_stop_signaler`, `libsigner/src/events.rs:499-508`) should be able to terminate the event receiver — this is the "who may terminate == owner of `SignerStopSignaler`" equality the question references. `SignerStopSignaler::send` (visible at `events.rs:380-394`) implements this intended path by opening a `TcpStream` to `self.local_addr` and sending a raw `POST /shutdown ...` HTTP request with no authentication token embedded in the body or headers.

Because the actual dispatch logic in `next_event` (`events.rs:413-458`) only inspects `request.url()`, any client — not just the internal `SignerStopSignaler` — that can open a TCP connection to the bound HTTP port and send a syntactically valid `POST /shutdown` request will hit the exact same branch at `events.rs:443-445`:
```rust
} else if request.url() == "/shutdown" {
    event_receiver.stop_signal.store(true, Ordering::SeqCst);
    Err(EventError::Terminated)
}
```
There is no comparison of source IP/socket, no shared secret, no header check — the equality "sender is the legitimate local stop-signaler" is never actually verified; the code conflates "URL matches /shutdown" with "caller is authorized to shut down," breaking the intended authentication invariant. Once `stop_signal` is set, `is_stopped()` (`events.rs:462-464`) returns true on every future call, and `next_event` immediately short-circuits to `Err(EventError::Terminated)` at `events.rs:416-418`, without even reading further connections. The consuming run loop (`libsigner/src/runloop.rs`) treats `EventError::Terminated` as a signal to break its main loop, permanently disabling event ingestion for that signer process until manual restart.

### Impact Explanation
A single unauthenticated HTTP POST from any TCP peer able to reach the signer's event listener port permanently stops that signer's event-processing loop — this is a remote, unauthenticated, one-message denial of service against the signer, matching the "Critical: remote crash/unauthenticated DoS from few messages" category. The signer stops relaying/processing StackerDB chunks, block proposals, and burn block events; if the port is reachable by any external attacker (rather than only the local node as intended), this is a full and repeatable DoS with attacker cost of exactly one crafted HTTP request per signer instance.

### Likelihood Explanation
Precondition is that the attacker must be able to reach the TCP port the `SignerEventReceiver` binds to (`bind`, `events.rs:404-408`). No secret, peer identity, StackerDB slot, or any privileged role is required — only network reachability to the port. The action is a single well-formed HTTP `POST /shutdown` request, trivially crafted, with no cost beyond one TCP connection.

### Recommendation
Add authentication to the `/shutdown` endpoint: e.g. bind the event listener to loopback only by default and document/enforce it, and/or require a per-process shared secret/token generated at startup and passed by `SignerStopSignaler`, verified in the `/shutdown` branch before setting `stop_signal`. Reject the request (e.g., respond 403) if the secret is missing or incorrect instead of trusting URL match alone.
