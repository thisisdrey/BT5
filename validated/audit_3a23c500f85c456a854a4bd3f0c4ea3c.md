### Title
Underwater liquidations leave unbacked bad debt with no loss socialization or cover mechanism, silently diluting synthetic-token backing - ([File: contracts/Pool.sol])

### Summary
`Pool.liquidate` seizes at most the account's entire `DepositToken` balance (`_totalSeized > balanceOf` reverts at `Pool.sol:583`) but burns only `amountToRepay_` of `DebtToken` debt (`Pool.sol:588`). When collateral value falls below debt, a maximal liquidation via `quoteLiquidateMax` empties the user's collateral while a positive debt balance remains forever (`test/Pool.test.ts:807-815`). There is no mechanism anywhere in the codebase (treasury cover, insurance fund, or spreading losses over other depositors/synth holders — grep for `badDebt|cover|shortfall|socializ` yields nothing in `contracts/`) to absorb or socialize this deficit. This is the exact analog of the reported bug class: losses are not distributed; synth supply stays fully circulating while the collateral backing it is gone.

### Finding Description
- `Pool.liquidate` requires the position to be unhealthy (`Pool.sol:559-563`), enforces `maxLiquidable` (`Pool.sol:567`), computes `quoteLiquidateOut` purely from oracle prices (`Pool.sol:581`), caps seizure at the account's `depositToken_.balanceOf` (`Pool.sol:583-585`), then burns synth + debt and seizes collateral (`Pool.sol:587-593`).
- `quoteLiquidateMax` explicitly returns the minimum of "repay amount that seizes all collateral" and `debt * maxLiquidable` (`Pool.sol:429-439`), i.e. it is designed to let a liquidator wipe the collateral while debt is left over.
- In the under-collateralized test scenario (MET price 0.50, collateral:debt < 1), after a max liquidation `msdMET.balanceOf(alice) ≈ 0` while `msEthDebtToken.balanceOf(alice) > 0` and `debtPositionOf` still reports unhealthy (`test/Pool.test.ts:807-815`). That residual debt is unrecoverable: no collateral remains to seize, and there is no function to write it off, cover it from treasury, or haircut other users.
- The minted `msEth`/`msUSD` remains fully in circulation and swappable at oracle price via `Pool.swap` (`Pool.sol:642-660`), so the deficit is quietly borne by all other synthetic-token holders and by new minters/depositors who enter after the loss — identical to new `aETH` stakers unknowingly absorbing slashing losses in the original report.

### Impact Explanation
Protocol insolvency: total outstanding synthetic supply exceeds the value of total collateral claim. Holders of the synthetic asset, liquidity providers, and new depositors absorb the loss rather than it being distributed at the time it occurs. Redemption parity (last-out-of-the-door problem) is broken — late redeemers effectively hold the unbacked residue since the defaulting account's debt can never be repaid and its collateral is zero. Impact class: protocol insolvency (accepted).

### Likelihood Explanation
No privileged actor is needed: any user deposits collateral, issues up to the collateral-factor limit via `DebtToken.issue`, and after a legitimate market drawdown of the collateral asset their position goes underwater (the repo's own test uses a single oracle price update, `test/Pool.test.ts:774-780`). Liquidators are economically motivated to take only `quoteLiquidateMax` — seizing 100% of collateral while repaying only part of the debt — leaving guaranteed residual bad debt. No modifier blocks this path: `whenNotShutdown`, `nonReentrant`, token-existence checks all pass. Repeated across volatile collateral or interest accrual on `DebtToken`, the deficit accumulates.

### Recommendation
Add a bad-debt mechanism: e.g., when a liquidation seizes the full remaining collateral and debt remains, write off the residual debt (`DebtToken.burn` of the remainder) and account for the shortfall against a protocol reserve/insurance fund, or socialize it by reducing claimable value (e.g., a global debt haircut index or minting fee surplus). Also track a per-pool `unbackedDebt` accumulator so `debtPositionOf`/issuance quotes reflect the true backing and new users are not silently exposed to pre-existing losses.

### Proof of Concept
The existing test suite already demonstrates it. Hardhat repro (adapted from `test/Pool.test.ts:773-819`):

```ts
// given: alice deposits MET, issues max msETH at CF limit
await msdMET.connect(alice).deposit(userDepositAmount, alice.address)
await msEthDebtToken.connect(alice).issue(userMintAmount, alice.address)

// when: MET price drops to 0.50 USD -> debt > collateral
await masterOracle.updatePrice(met.address, toUSD('0.50'))
expect(await pool.debtOf(alice.address)).gt(
  (await pool.debtPositionOf(alice.address))._depositInUsd
)

// liquidator repays the maximum allowed
const amountToRepay = await pool.quoteLiquidateMax(msEth.address, alice.address, msdMET.address)
await pool.connect(liquidator).liquidate(msEth.address, alice.address, amountToRepay, msdMET.address)

// then: all collateral seized, but bad debt remains forever
expect(await msdMET.balanceOf(alice.address)).closeTo(0, 1600)
expect(await msEthDebtToken.balanceOf(alice.address)).gt(0)        // unrecoverable bad debt
expect((await pool.debtPositionOf(alice.address))._isHealthy).false
// the repaid msETH is burned, but the unbacked remainder stays circulating
// across other holders; no function exists to cover or socialize it
```

On a fork, the same is achievable without mocking: deposit a volatile collateral, mint at the limit, wait for a legitimate price decline (or accrue `DebtToken` interest until underwater), then execute `pool.quoteLiquidateMax` + `pool.liquidate`. The residual `debtToken` balance with zero collateral constitutes permanent protocol insolvency.
