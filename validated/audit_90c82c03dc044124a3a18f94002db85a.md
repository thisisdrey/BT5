### Title
Global free-bandwidth pool (`publicNetLimit`) can be drained by any account to DoS zero-balance transaction submitters - (File: chainbase/src/main/java/org/tron/core/db/BandwidthProcessor.java)

### Summary
The Axelar finding describes a shared, epoch-based (6h) `flowLimit` that any large holder can exhaust at the start of each window, blocking every other user's cross-chain transfer on that lane until the next epoch. java-tron has a structurally identical pattern: a single network-wide, time-windowed bandwidth pool (`publicNetLimit`/`publicNetUsage`/`publicNetTime`) that every unprivileged account's free-bandwidth transactions draw from, and which resets on a fixed decay window. Any account can consume the entire shared pool early in the window, causing subsequent callers who rely on free bandwidth (typically zero/low-balance accounts) to be denied service until the pool decays back.

### Finding Description
`BandwidthProcessor.useFreeNet()` first checks the caller's individual `freeNetLimit`, then checks a second, *global* limit shared across the whole chain: [1](#0-0) 

The relevant fields are `publicNetLimit`, `publicNetUsage`, and `publicNetTime`, all stored in `DynamicPropertiesStore` and shared by every account on the network. When a transaction's byte cost exceeds the currently available slice of this global pool (`publicNetLimit - newPublicNetUsage`), `useFreeNet` returns `false` and the caller falls through to `useTransactionFee`; if the account has insufficient TRX balance to pay for bandwidth, the transaction is rejected with `AccountResourceInsufficientException`: [2](#0-1) 

Usage of the pool decays over a fixed time window via `increase()`, exactly analogous to the Axelar `TokenManager` epoch reset: [3](#0-2) 

Because `publicNetLimit` is a single shared bucket (not per-account), any address — including brand-new, unfunded accounts created purely to broadcast free transactions — can repeatedly submit minimal transactions that consume `bytesSize` against the shared `publicNetUsage` counter until the pool is exhausted for the current window. This mirrors the Axelar bug precisely: a single actor draining a shared, periodically-resetting capacity limit denies the resource to everyone else relying on it until the window rolls over.

### Impact Explanation
Once `publicNetUsage` reaches `publicNetLimit`, every account that depends on the free-bandwidth tier (most commonly newly created or low-balance wallets that have not frozen TRX for bandwidth) can no longer get free bandwidth for the remainder of the window. If such accounts also lack sufficient TRX balance to pay `getTransactionFee() * bytesSize`, their transactions are outright rejected (`AccountResourceInsufficientException`), meaning they cannot broadcast any transaction — a genuine, if temporary, denial of service against the node's public-facing transaction submission path. This impacts protocol availability/liveness for a class of legitimate unprivileged users, consistent with the "function of the protocol or its availability could be impacted" criterion used in the referenced Axelar judgment (Medium).

### Likelihood Explanation
The attack requires no special privilege — any account (even a freshly created, unfunded one, subject only to account-creation cost) can send bandwidth-consuming transactions that draw from the shared pool. Since `publicNetLimit` is typically configured to a modest global value relative to overall network transaction volume, an attacker with a modest number of low-cost transactions per window can exhaust it cheaply, similarly to how the Axelar attacker cheaply exhausts the 6-hour `flowLimit`. This is directly analogous in mechanism and cost profile to the reported bug.

### Recommendation
Consider one or more of:
1. Moving away from (or supplementing) a single global free-bandwidth bucket toward a per-account or per-time-slice quota that cannot be monopolized by a handful of addresses.
2. Introducing a minimal cost/fee floor on transactions that consume the shared `publicNetLimit`, so exhausting it is not near-zero-cost (mirrors the Chainlink CCIP bps-fee mitigation proposed in the original report).
3. Prioritizing or reserving a portion of `publicNetLimit` for genuinely new/unique accounts (e.g., rate-limited by account age or a Sybil-resistant heuristic) to reduce the blast radius of a single actor.

### Proof of Concept
1. Observe current `DynamicPropertiesStore.getPublicNetLimit()` / `getPublicNetUsage()` / `getPublicNetTime()` values at the start of a window (`increase()` window defined by `ChainConstant.WINDOW_SIZE_MS`).
2. From any number of low/zero-balance accounts, repeatedly broadcast minimal-cost transactions (e.g., simple TRX transfers) that hit `useFreeNet()` in `BandwidthProcessor.consume()`.
3. Each transaction increases `publicNetUsage` via `increase(publicNetUsage, bytes, publicNetTime, now)` as shown in `BandwidthProcessor.java` lines 506-547, without requiring the sender to hold TRX for fees (since it's served from the free/public pool).
4. Continue until `newPublicNetUsage` approaches `publicNetLimit`; at that point `useFreeNet` starts returning `false` for all other accounts for the remainder of the window (`chainbase/src/main/java/org/tron/core/db/BandwidthProcessor.java` lines 513-518, 526-531).
5. Any subsequent zero/low-balance account attempting to submit a transaction now fails `useFreeNet`, falls through to `useTransactionFee`, and if it lacks TRX, the whole `consume()` path throws `AccountResourceInsufficientException` (lines 172-176), denying it service until the window's decay restores capacity.

  private boolean useFreeNet(AccountCapsule accountCapsule, long bytes, long now) {

    long freeNetLimit = chainBaseManager.getDynamicPropertiesStore().getFreeNetLimit();
    long freeNetUsage = accountCapsule.getFreeNetUsage();
    long latestConsumeFreeTime = accountCapsule.getLatestConsumeFreeTime();
    long newFreeNetUsage = increase(freeNetUsage, 0, latestConsumeFreeTime, now);

    if (bytes > (freeNetLimit - newFreeNetUsage)) {
      logger.debug("Free net usage is running out."
              + " Bytes: {}, freeNetLimit: {}, newFreeNetUsage: {}.",
          bytes, freeNetLimit, newFreeNetUsage);
      return false;
    }

    long publicNetLimit = chainBaseManager.getDynamicPropertiesStore().getPublicNetLimit();
    long publicNetUsage = chainBaseManager.getDynamicPropertiesStore().getPublicNetUsage();
    long publicNetTime = chainBaseManager.getDynamicPropertiesStore().getPublicNetTime();

    long newPublicNetUsage = increase(publicNetUsage, 0, publicNetTime, now);

    if (bytes > (publicNetLimit - newPublicNetUsage)) {
      logger.debug("Free public net usage is running out."
              + " Bytes: {}, publicNetLimit: {}, newPublicNetUsage: {}.",
          bytes, publicNetLimit, newPublicNetUsage);
      return false;
    }

  protected long increase(long lastUsage, long usage, long lastTime, long now, long windowSize) {
    long averageLastUsage;
    long averageUsage;
    if (hardenCalculation()) {
      BigInteger biPrecision = BigInteger.valueOf(precision);
      BigInteger biWindowSize = BigInteger.valueOf(windowSize);
      averageLastUsage = divideCeilExact(
          BigInteger.valueOf(lastUsage).multiply(biPrecision), biWindowSize);
      averageUsage = divideCeilExact(
          BigInteger.valueOf(usage).multiply(biPrecision), biWindowSize);
    } else {
      averageLastUsage = divideCeil(lastUsage * precision, windowSize);
      averageUsage = divideCeil(usage * precision, windowSize);
    }

    if (lastTime != now) {
      assert now > lastTime;
      if (lastTime + windowSize > now) {
        long delta = now - lastTime;
        double decay = (windowSize - delta) / (double) windowSize;
        averageLastUsage = round(averageLastUsage * decay,
            this.disableJavaLangMath());
      } else {
        averageLastUsage = 0;
      }
    }
    averageLastUsage += averageUsage;
    return getUsage(averageLastUsage, windowSize);
  }
