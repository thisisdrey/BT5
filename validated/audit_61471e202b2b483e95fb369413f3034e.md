### Title
Borrower can keep calling `accrueInterest()` every block so accrued interest rounds to zero and `lastTimestampAccrued` is still advanced - ([File: contracts/DebtToken.sol](contracts/DebtToken.sol))

### Summary
`DebtToken.accrueInterest()` is a permissionless public function that unconditionally updates `lastTimestampAccrued = block.timestamp` even when the computed `_interestAmountAccrued` rounds down to zero. Because interest is calculated linearly from `lastTimestampAccrued`, an attacker can call `accrueInterest()` every block so that `interestRatePerSecond * delta * totalSupply` stays below the `wadMul` rounding threshold, permanently preventing any interest from accruing on their debt.

### Finding Description
In `contracts/DebtToken.sol:156-180`, `accrueInterest()` does:

```solidity
if (block.timestamp == _lastTimestampAccrued) {
    return;
}
lastTimestampAccrued = block.timestamp;   // updated unconditionally

if (_interestAmountAccrued > 0) {
    totalSupply_ += _interestAmountAccrued;
    debtIndex = _debtIndex;
    ...
}
```

The timestamp is persisted at line 167 regardless of whether any interest was accrued. In `_calculateInterestAccrual()` (lines 551-566):

```solidity
uint256 _interestRateToAccrue = interestRatePerSecond() * (block.timestamp - _lastTimestampAccrued);
if (_interestRateToAccrue > 0) {
    _interestAmountAccrued = _interestRateToAccrue.wadMul(totalSupply_);
    _debtIndex += _interestRateToAccrue.wadMul(_debtIndex);
}
```

`wadMul` divides by `1e18`, so if `interestRatePerSecond * deltaT * totalSupply < 1e18` (or `< 0.5e18` under half-up), `_interestAmountAccrued == 0` — yet the elapsed time window is still consumed because `lastTimestampAccrued` was already advanced. `interestRatePerSecond = interestRate / SECONDS_PER_YEAR` (line 319-321), so per-second rate is tiny.

Reachability: `accrueInterest()` has no access-control modifier — any EOA can call it directly, every block, at trivial gas cost. Every subsequent `balanceOf` / `debtPositionOf` / liquidation check computes interest only from the reset `lastTimestampAccrued`, so the attacker's debt stays at principal as long as they keep poking.

Feasibility per block: for a synthetic token with 8 decimals (e.g. an msBTC-style synth), even a debt of thousands of units (`totalSupply ≈ 1e11`) yields `interestRatePerSecond (≈3e9 at 10% APR) * 12s * 1e11 ≈ 3.6e12 << 0.5e18`, rounding to zero. For 18-decimal synths the attacker can repay down to a small debt (below `debtFloorInUsd` only constrains minting, not the residual after repay), spam `accrueInterest`, then re-borrow — or simply grief a low-TVL market where `totalSupply_` is small. On 2-second-block L2s (Optimism, Base — both deployed per `deployments/`) the rounding window is even easier to sustain.

### Impact Explanation
The interest-accrual invariant breaks: borrowers' real debt never grows despite a nonzero `interestRate`. The protocol loses the interest fee stream (`syntheticToken.mint(pool.feeCollector(), ...)` never executes), and, more importantly, debt positions that should become unhealthy and liquidatable remain artificially healthy — enabling effective theft of the unpaid interest and weakening solvency accounting (`Pool.debtOf`, `debtPositionOf`).

### Likelihood Explanation
The call is free of modifiers, reentrancy risk, or cost beyond gas; on L2s gas is negligible. The only requirement is keeping `rate * dt * totalSupply` below the wad rounding bound each call, which is realistic for low-decimal synths or low-debt pools. It requires continuous per-block poking (a simple bot), matching the medium severity of the original report.

### Recommendation
Only advance `lastTimestampAccrued` when interest was actually accrued, or track a separate `lastNonZeroAccrualTimestamp` used to compute `deltaT`. Alternatively accumulate the sub-wad remainder (`pendingInterestFee`-style accumulator for the truncated fraction) so truncation does not discard elapsed time.

### Proof of Concept
Hardhat test sketch against the existing test harness (`test/DebtToken.test.ts` fixtures):

```typescript
it('griefs interest accrual by poking every block', async function () {
  await msUSDDebt.connect(user1).issue(principal, user1.address);
  await msUSDDebt.updateInterestRate(parseEther('0.1')); // 10% APR

  // attacker pokes accrueInterest() every block for a year
  const blocks = 1000; // representative sample
  for (let i = 0; i < blocks; i++) {
    await time.increase(12);          // one block
    await msUSDDebt.accrueInterest(); // permissionless poke, rounds to 0
    // shrink debt via repay so totalSupply_ * rate*dt stays < 0.5e18,
    // or use an 8-decimal synth debt token where normal supply already truncates
  }

  const debt = await msUSDDebt.balanceOf(user1.address);
  // debt == principal: no interest accrued despite ~blocks*12s elapsed
  expect(debt).eq(principal);
  // feeCollector received nothing
  expect(await msUSD.balanceOf(feeCollector.address)).eq(0);
});
```

The deterministic check: after each call `lastTimestampAccrued == block.timestamp` while `totalSupply_` and `debtIndex` are unchanged — directly observable via the public getters `lastTimestampAccrued()`, `totalSupply()`, `debtIndex()`.
