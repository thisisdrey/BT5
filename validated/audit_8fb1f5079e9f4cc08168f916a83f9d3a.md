### Title
Unauthenticated JSON-RPC clients can permanently exhaust the `eth_newFilter`/`eth_newBlockFilter` filter tables, denying filter service to all clients - (File: `framework/src/main/java/org/tron/core/services/jsonrpc/TronJsonRpcImpl.java`)

### Summary
`TronJsonRpcImpl` stores every filter created via `eth_newFilter` / `eth_newBlockFilter` in a `ConcurrentHashMap` keyed by filter ID, and only removes an entry when the client explicitly calls `eth_uninstallFilter`. Each `FilterResult` subclass carries an `isExpire()` flag that is supposed to signal staleness, but nothing in the codebase ever calls `isExpire()` to sweep and evict abandoned filters. An anonymous caller can create filters up to the configured cap and never poll or uninstall them, permanently filling the map and blocking all other clients (including legitimate ones) from creating new filters — directly analogous to the python-socketio issue where partial binary messages accumulate in memory because nothing purges them when the client stops cooperating.

### Finding Description
`newFilter` and `newBlockFilter` insert a `LogFilterAndResult`/`BlockFilterAndResult` into `eventFilter2ResultFull`/`blockFilter2ResultFull` (or the Solidity-node equivalents), gated only by a size check against `maxLogFilterNum`/`maxBlockFilterNum`: [1](#0-0) [2](#0-1) 

Removal only happens through an explicit `eth_uninstallFilter` call: [3](#0-2) 

Each filter tracks an expiry timestamp via `FilterResult.updateExpireTime()`/`isExpire()`: [4](#0-3) 

However, `isExpire()` is never invoked anywhere in the server: there is no scheduled sweep task, and neither `getFilterChanges` nor `getFilterLogs` check or act on expiry — they only call `updateExpireTime()` to refresh it: [5](#0-4) 

Because `isExpire()` has no caller, expired filters remain in `eventFilter2ResultFull`/`blockFilter2ResultFull` forever unless the creator voluntarily uninstalls them. Since these maps are size-capped rather than count-per-client-capped, and creation requires no authentication (JSON-RPC has no auth by default), a single anonymous client can create `maxLogFilterNum` + `maxBlockFilterNum` filters, abandon the connection, and the filter tables stay permanently full — blocking `eth_newFilter`/`eth_newBlockFilter` for every other client on that node indefinitely (`JsonRpcExceedLimitException`).

### Impact Explanation
This denies the `eth_newFilter`/`eth_newBlockFilter` JSON-RPC API to all clients of the affected full/solidity node for as long as the node runs (no automatic recovery, since nothing purges the maps), which satisfies "an API the node can no longer serve." It does not affect consensus, funds, or block production, but it is a persistent, remotely triggerable denial of a public JSON-RPC surface with no authentication required, requiring only trivial repeated calls and disconnects/silence.

### Likelihood Explanation
High: `eth_newFilter`/`eth_newBlockFilter` are reachable by any anonymous JSON-RPC client (no signed transaction or account needed), the cap check is a simple size comparison with no per-IP/per-connection quota, and the only mitigation (config-level `maxLogFilterNum`/`maxBlockFilterNum`) merely bounds *how much* memory/slots get consumed, not *whether* they get reclaimed. Reaching and holding the cap requires nothing more than issuing the calls in a loop and never calling `eth_uninstallFilter`.

### Recommendation
- Add a scheduled sweep (similar in spirit to how `PendingManager`/`Manager` time out stale pending transactions) that periodically iterates `eventFilter2ResultFull/Solidity` and `blockFilter2ResultFull/Solidity`, calls the existing `isExpire()`, and evicts expired entries.
- Optionally enforce a per-remote-address or per-connection filter quota in addition to the global cap, so one anonymous caller cannot occupy the entire table.

### Proof of Concept
1. Configure a full node with JSON-RPC enabled (default has no authentication).
2. From an anonymous client, repeatedly call `eth_newFilter` (and/or `eth_newBlockFilter`) until `maxLogFilterNum`/`maxBlockFilterNum` is reached; never call `eth_uninstallFilter` or poll `eth_getFilterChanges`/`eth_getFilterLogs`.
3. Wait past `EXPIRE_SECONDS` (5 minutes) — the created filters become "expired" per `FilterResult.isExpire()`, but observe that subsequent `eth_newFilter` calls from any client (including legitimate ones) still fail with `JsonRpcExceedLimitException` because nothing ever purges the expired entries from `eventFilter2Result`/`blockFilter2Result`.
4. The node's filter-creation API remains unusable for all clients until the process is restarted.

  @Override
  public boolean uninstallFilter(String filterId) throws ItemNotFoundException,
      JsonRpcMethodNotFoundException {
    disableInPBFT("eth_uninstallFilter");

    Map<String, BlockFilterAndResult> blockFilter2Result;
    Map<String, LogFilterAndResult> eventFilter2Result;
    if (getSource() == RequestSource.FULLNODE) {
      blockFilter2Result = blockFilter2ResultFull;
      eventFilter2Result = eventFilter2ResultFull;
    } else {
      blockFilter2Result = blockFilter2ResultSolidity;
      eventFilter2Result = eventFilter2ResultSolidity;
    }

    filterId = ByteArray.fromHex(filterId);
    if (eventFilter2Result.containsKey(filterId)) {
      eventFilter2Result.remove(filterId);
    } else if (blockFilter2Result.containsKey(filterId)) {
      blockFilter2Result.remove(filterId);
    } else {
      throw new ItemNotFoundException(FILTER_NOT_FOUND);
    }

    return true;
  }

public abstract class FilterResult<T> {

  private long expireTimeStamp;

  @Getter
  protected BlockingQueue<T> result;

  public void updateExpireTime() {
    expireTimeStamp = System.currentTimeMillis() + TronJsonRpcImpl.EXPIRE_SECONDS * 1000;
  }

  public boolean isExpire() {
    return expireTimeStamp < System.currentTimeMillis();
  }
