### Title
Protocol fee bypass via unit-splitting of NEP-245/IMT `TokenDiff` intents - (File: contracts/defuse/core/src/intents/token_diff.rs)

### Summary
`TokenDiff::token_fee` waives the protocol fee whenever a single `TokenDiff` intent's `|delta|` for a `Nep245` or `Imt` token is `<= 1`. Because the fee is computed per-intent on that intent's own delta magnitude rather than on the signer's aggregate net negative delta for that token across the batch, a signer can split one large `token_in` transfer into many unit-sized (`delta = -1`) `TokenDiff` intents and pay zero fee in total, instead of `Pips::fee_ceil(N)` for a single `N`-unit intent.

### Finding Description
The binding that should hold is:
`sum_over_batch(fees_credited_to_fee_collector for token T) == Pips::fee_ceil(sum_over_batch(negative deltas of T))`.

In `TokenDiff::execute_intent` [1](#0-0) , for each negative delta the fee is computed independently as `Self::token_fee(token_id, amount, protocol_fee).fee_ceil(amount)` where `amount` is that single intent's `delta.unsigned_abs()`, and immediately credited to `fee_collector` [2](#0-1) . There is no aggregation of the signer's total negative delta for a given `token_id` across the intents in a `MultiPayload`.

`TokenDiff::token_fee` explicitly returns `Pips::ZERO` for `Nep245`/`Imt` tokens whenever the per-intent amount is `<= 1`: [3](#0-2) 

Settlement of the aggregate deltas across a batch happens later in `TransferMatcher::finalize`, which only cares that deposits and withdrawals of a token net to zero across the whole batch — it has no knowledge of, nor any interaction with, the fee that was already taken (or not taken) per-intent [4](#0-3) . So the fee-bypass happens strictly at the per-intent stage, before matching, and matching cannot detect or correct it.

Exploit: an attacker holding `N` units of a `Nep245` (or `Imt`) token, with `protocol_fee > 0`, signs `N` separate `TokenDiff` intents (each with a distinct `Nonce`, same key) each with `diff = {token_id: -1, ...counter_token: +k}` instead of one intent with `diff = {token_id: -N, ...counter_token: +N*k}`. In each of the `N` calls to `TokenDiff::execute_intent`, `amount = 1`, so `token_fee` returns `Pips::ZERO`, and `fee_ceil(1) == 0` regardless of `protocol_fee`. Total fee credited to `fee_collector` = 0. A single intent with `delta = -N` would have paid `Pips::fee_ceil(N) > 0` for any `protocol_fee > 0` and `N` large enough that the true fee is non-zero.

None of the existing guards prevent this: `MultiPayload::verify` and nonce checks only ensure authenticity/replay-protection of each signed intent, not fee-equivalence across split intents; `TransferMatcher::finalize` only verifies zero-sum settlement per token, not fee correctness; there is no code anywhere that sums a signer's negative deltas per token across a batch before computing the fee.

### Impact Explanation
This is a protocol fee bypass: the `fee_collector` under-collects fees on every `Nep245`/`Imt`-denominated `token_in` transfer whose signer chooses to split it into unit legs, for any nonzero `protocol_fee`. It is fully repeatable — any account holding any amount of a semi-fungible NEP-245 token can always drive the collected fee for that trade to zero by splitting it into `N` unit legs (cost: `N` intents in one `MultiPayload`, no extra token cost, just extra payload size/gas). This matches the "protocol fees bypassed" Critical category from the rules.

### Likelihood Explanation
Preconditions are minimal and fully within an unprivileged signer's control: hold `N` units of any `Nep245` (or `Imt`) token in the Verifier, have `protocol_fee > 0` (the default operating condition), and sign `N` `TokenDiff` intents with distinct nonces under the same key in a single `MultiPayload`/batch (a normal, unrestricted usage pattern). No role, relayer key, or victim key is required. The attack is trivially repeatable across accounts, tokens, and batches, and costs the attacker nothing beyond normal transaction gas.

### Recommendation
Compute the fee on the *aggregate* per-signer, per-token negative delta across the whole batch (or across all `TokenDiff` intents that share the same signer within one `execute_intents` call) rather than on each individual intent's per-leg amount, before applying the `Nep245`/`Imt` `amount <= 1` waiver. Alternatively, restrict the `amount <= 1` fee waiver so it only applies when the token's underlying supply for that `token_id` is provably non-fungible (e.g., total supply == 1), or require the fee calculation to use the cumulative signer delta for that `token_id` tracked across the `Deltas`/`TransferMatcher` state before fee waiver decisions are made.

### Proof of Concept
`cargo test` plan (near-workspaces sandbox, matching repo's existing `tests/src/tests/defuse/intents/token_diff.rs` harness style):
1. Deploy a NEP-245 (MT) contract, mint `N = 100` units of a single semi-fungible `token_id` to `attacker`, deposit into Defuse Verifier. Set `protocol_fee = Pips::ONE_PERCENT` (or any `> 0`).
2. **Baseline**: sign and execute a single `TokenDiff` intent `{token_id: -100, counter_token: +k}` (with a matching counterparty leg to satisfy `TransferMatcher::finalize`). Assert `fee_collector`'s balance of `token_id` after execution equals `Pips::ONE_PERCENT.fee_ceil(100)` (> 0).
3. **Reset state** (fresh Verifier/account or new token_id) and repeat with `attacker` holding another `100` units of the same/second `token_id`.
4. **Exploit**: sign `100` separate `TokenDiff` intents, each `{token_id: -1, counter_token: +k/100}`, each with a distinct nonce, submitted in one `MultiPayload` to `execute_intents`, with matching counterparty legs summing to the same aggregate. Assert `fee_collector`'s balance of `token_id` after execution equals `0`.
5. Final assertion: baseline fee (`> 0`) != exploit fee (`0`) for the same aggregate transferred amount `N=100`, proving `sum(fees_credited) == Pips::fee_ceil(total negative delta)` fails (LHS=0, RHS>0).

    pub fn finalize(self) -> Result<Transfers, InvariantViolated> {
        let mut transfers = Transfers::default();
        let mut deltas = TokenDeltas::default();
        for (token_id, transfer_matcher) in self.0 {
            if let Err(unmatched) = transfer_matcher.finalize_into(&token_id, &mut transfers)
                && (unmatched == 0 || deltas.apply_delta(token_id, unmatched).is_none())
            {
                return Err(InvariantViolated::Overflow);
            }
        }
        if !deltas.is_empty() {
            return Err(InvariantViolated::UnmatchedDeltas {
                unmatched_deltas: deltas,
            });
        }

    }
