### Title
`unlockedBalanceOf` understates withdrawable collateral via a token→USD→token double conversion that rounds down — ([File: contracts/DepositToken.sol])

### Summary
The same bug class as the external report — a withdrawable amount computed by converting collateral value into an intermediate unit and back — exists in `DepositToken.unlockedBalanceOf()`. A user's free collateral is priced token→USD in `Pool.depositOf()`, scaled by the collateral factor, netted against debt in `Pool.debtPositionOf()`, and then converted back USD→token via `MasterOracle.quoteUsdToToken()`. Each division in that chain rounds down (or the `wadDiv` half-up is erased by the subsequent oracle division), so the computed withdrawable balance is strictly less than the mathematically entitled amount. `withdraw()`/`transfer()` then enforce this understated cap through `_revertIfLocked`, leaving a small amount of collateral locked even though the position would remain at exactly the collateral-factor limit.

### Finding Description
`unlockedBalanceOf` computes the transferable/withdrawable balance as:

```solidity
// contracts/DepositToken.sol:383-398
(, , uint256 _debtInUsd, , uint256 _issuableInUsd) = _pool.debtPositionOf(account_);
...
_unlockedBalance = Math.min(
    balanceOf[account_],
    _pool.masterOracle().quoteUsdToToken(address(underlying), _issuableInUsd.wadDiv(collateralFactor))
);
```

The conversion chain mirrors the reported `ETH→SD→ETH` pattern:

1. `Pool.depositOf()` (contracts/Pool.sol:274-288) prices the deposit token balance via `quoteTokenToUsd(underlying, balance)` — token→USD, truncating division — then applies `wadMul(collateralFactor)`.
2. `Pool.debtPositionOf()` (contracts/Pool.sol:262-265) subtracts `_debtInUsd`, which itself is summed from `quoteTokenToUsd` over each `DebtToken.balanceOf()` (contracts/Pool.sol:227-237); `balanceOf` truncates via `(_principal * _debtIndex) / debtIndexOf` (contracts/DebtToken.sol:205).
3. `unlockedBalanceOf` converts the remaining USD headroom back into underlying units with `quoteUsdToToken` — another truncating division.

Because value crosses the unit boundary twice (underlying→USD→underlying) with floor rounding at each hop, `unlockedBalanceOf` returns less than `balance * cf`/`price` would yield directly. The `withdraw()` path calls `_revertIfLocked(_msgSender, amount_)` before `_withdraw`, so any attempt to withdraw the true entitled amount reverts.

### Impact Explanation
A leveraged-position holder who wants to withdraw collateral down to the exact collateral-factor limit cannot do so: a small amount of underlying remains `locked` even though withdrawing it would leave the position healthy per the same `debtPositionOf` math. To free the dust the user must over-repay debt, and `repay`/`repayAll` charge a `repayFee` on the gross amount (`quoteRepayOut`, contracts/DebtToken.sol:401-409), converting the rounding shortfall into a real fee cost. Magnitude per call is dust-scale (bounded by ~1 wei of underlying per collateral token per account), identical in character to the accepted Stader finding. Note the dust is not permanently lost — repaying all debt to zero short-circuits to `return balanceOf[account_]` — so this is a temporary locking plus forced extra repayment rather than theft.

### Likelihood Explanation
It triggers deterministically for any user whose withdrawable amount lands on the rounding boundary, which is effectively every user withdrawing their maximum (`withdraw(unlockedBalanceOf(...))` is the documented usage in the E2E tests). It requires no privileged actor and no oracle manipulation; it is inherent to the deployed math. Its practical impact is bounded by wei-scale amounts per collateral type, so while always present, the absolute loss is small — matching the original report's "small amount of ETH" classification.

### Recommendation
Round the withdrawable computation in the user's favor, analogous to the upstream fix: compute the unlocked amount directly in underlying units, or round up the intermediate result. Concretely, in `DepositToken.unlockedBalanceOf` use a ceiling division for the USD→token conversion, e.g. `(usdAmount * 10**underlyingDecimals + price - 1) / price` semantics, or have `MasterOracle` expose a `quoteUsdToTokenRoundUp`. Alternatively, compare in USD space inside `_revertIfLocked` rather than token space to avoid the double conversion entirely.

### Proof of Concept
Hardhat fork test sketch (Optimism fork, matching `test/E2E.optimism.next.test.ts` setup):

```ts
it('understates unlockedBalanceOf due to token->USD->token rounding', async () => {
  // alice deposits USDC and issues max msUSD
  await usdc.connect(alice).approve(msdUSDC.address, MaxUint256);
  await msdUSDC.deposit(parseUnits('1000', 6), alice.address);

  const { _issuableInUsd } = await pool.debtPositionOf(alice.address);
  const maxIssuable = await masterOracle.quoteUsdToToken(msUSD.address, _issuableInUsd);
  await msUSDDebt.issue(maxIssuable, alice.address); // position now at CF limit

  // Nothing should be unlocked: healthy boundary => unlocked == 0. Now repay 1 wei
  // of debt to create headroom; unlocked should equal headroom/CF in underlying.
  await msUSDDebt.repay(alice.address, 1);

  const { _issuableInUsd: headroom } = await pool.debtPositionOf(alice.address);
  const cf = await msdUSDC.collateralFactor();
  const unlocked = await msdUSDC.unlockedBalanceOf(alice.address);

  // Ideal unlocked (exact math): headroom * 1e18 / cf priced back to USDC.
  const ideal = await masterOracle.quoteUsdToToken(usdc.address, headroom.mul(parseEther('1')).div(cf));
  // Observed: unlocked <= ideal, and strict < whenever the wadDiv(1e18 + b/2)/b
  // half-up is erased by truncating oracle division:
  expect(unlocked).to.be.lte(ideal);
  // withdraw(unlocked + k) reverts with the lock check even though the
  // post-withdraw position is exactly at the CF limit per debtPositionOf:
  await expect(msdUSDC.withdraw(unlocked.add(1), alice.address)).to.be.reverted; // LockedBalance / _revertIfLocked
});
```

Caveat I could not verify within the available iterations: the exact rounding direction inside `MasterOracle.quoteUsdToToken`/`quoteTokenToUsd` (and whether vault-share collaterals such as `vaETH`/`vaWSTETH` add a second share↔underlying conversion hop, which would compound the loss). If the oracle rounds *up* on `quoteUsdToToken`, the finding weakens to a `wadDiv` half-up vs. truncating `balanceOf` discrepancy — the fork PoC is the decisive check.
