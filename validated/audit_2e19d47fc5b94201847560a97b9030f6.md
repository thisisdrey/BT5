### Title
StackerDB signer revocation is silently skipped when a contract's signer set becomes empty, letting removed signers keep write access forever - ([File: stackslib/src/net/stackerdb/mod.rs])

### Summary
`StackerDBs::create_or_reconfigure_stackerdbs` only calls `reconfigure_stackerdb` (which rewrites slot ownership) when the freshly-read contract config is non-empty and different from the stored config. If the controlling contract legitimately reports an empty signer list for a StackerDB (a normal state, not an error), the node keeps the previous signer set active indefinitely, so a signer that has been removed from the canonical on-chain set retains the ability to write StackerDB chunks that other nodes will accept and relay.

### Finding Description
`create_or_reconfigure_stackerdbs` decides whether to persist a freshly-evaluated `StackerDBConfig` (`new_config`) over the currently stored one (`stackerdb_config`): [1](#0-0) 

The guard is:
```rust
} else if (new_config != stackerdb_config && !new_config.signers.is_empty())
    || (new_config == stackerdb_config
        && new_config.signers.len() != self.get_slot_versions(&stackerdb_contract_id)?.len())
{
    // only reconfigure if the config has changed ...
    self.reconfigure_stackerdb(&stackerdb_contract_id, &new_config)
}
```
This means: reconfiguration to a new, *empty* signer set is never applied when the stored config was previously non-empty, because the `!new_config.signers.is_empty()` check blocks the first branch, and the second branch requires `new_config == stackerdb_config` (which won't hold when signers shrink from non-empty to empty).

Crucially, an empty signer list is a legitimate, expected contract response, not merely an error fallback. The `.signers` boot contract explicitly returns an empty stackerdb list when there is no reward-cycle participation: [2](#0-1) 

and this is stored via `stackerdb-set-signer-slots` in the Clarity contract: [3](#0-2) 

`StackerDBConfig::from_smart_contract` faithfully evaluates this contract state through `eval_signer_slots`, returning `signers = []` whenever the contract reports no entries — this is not an artificial `noop()` fallback: [4](#0-3) 

Because the reconfigure guard refuses to apply an empty `new_config.signers`, the node's persisted `slot_validation.signer` mapping (used to authorize writes) is never cleared for these slots: [5](#0-4) 

so the previous (now-revoked) signer's signature continues to satisfy `try_replace_chunk`'s `slot_desc.verify(&slot_validation.signer)` check, and the chunk is accepted, stored, and gossiped to the rest of the network via the normal StackerDB push/inventory-sync machinery, which relies on this same stored `slot_validation.signer` for chunk acceptance: [6](#0-5) 

The existing comment even documents that this guard was added as a targeted fix for issue #5142 ("a stackerdb could never shrink"), but the fix over-corrects: it prevents shrinking to zero unconditionally rather than only in genuine read-failure scenarios, breaking the equality between the canonical on-chain signer set and the node's locally enforced signer set. [7](#0-6) 

### Impact Explanation
This lets a removed StackerDB signer keep authoring chunks that every node accepts as canonical and propagates network-wide, i.e. non-canonical (stale) signer state is served as canonical StackerDB content. This matches the High-impact bucket ("serving non-canonical state as canonical"): it is a state divergence between the smart contract's authoritative signer set and what every replica actually enforces, propagated automatically across the network without any attacker action beyond continuing to sign with a key that was supposed to be revoked.

### Likelihood Explanation
The triggering condition — a StackerDB contract's signer-slot function legitimately returning an empty list after previously returning a non-empty one — is a normal operational transition (e.g., a reward cycle with no participation, as implemented by the `.signers` boot contract itself), not a rare error path. Every node running `refresh_stacker_db_configs`/`create_or_reconfigure_stackerdbs` on such a transition is affected identically, so the divergence is deterministic and network-wide rather than requiring a race or privileged access.

### Recommendation
Distinguish "contract legitimately reports empty signers" from "config read failed" explicitly (e.g., propagate a distinct error/`Option` rather than collapsing both into an empty `Vec`), and always reconfigure (including shrinking to zero slots) when a successful read reports a changed signer set, regardless of whether the new set is empty. Reserve the "skip reconfigure" behavior strictly for read failures (`Err(..)` from `from_smart_contract`), not for a successful `Ok` response with zero signers.

### Proof of Concept
1. Deploy/observe a StackerDB-controlled contract (e.g. `.signers-0-...`) whose backing state (via `.signers`) has a non-empty signer set for cycle N (slots assigned to signer `S`).
2. Transition to cycle N+1 where `has_participation` is false, causing `update_signers` to set the stackerdb list to `vec![]` on-chain.
3. On any node, `refresh_stacker_db_configs` → `create_or_reconfigure_stackerdbs` evaluates `new_config.signers == []`, `stackerdb_config.signers` = previous non-empty set: the `else if` condition is false, so `reconfigure_stackerdb` is never called; the DB retains `slot_validation.signer = S` for the old slots.
4. Signer `S` (now removed from the canonical set) signs and pushes a new chunk with an incremented `slot_version` for its old slot; `try_replace_chunk`/`validate_received_chunk` on all replicas still authorize it via the stale `slot_validation.signer`, and it is stored and gossiped as valid.

    fn eval_signer_slots(
        chainstate: &mut StacksChainState,
        burn_dbconn: &dyn BurnStateDB,
        contract_id: &QualifiedContractIdentifier,
        tip: &StacksBlockId,
    ) -> Result<Vec<(StacksAddress, u32)>, NetError> {
        let value = chainstate.eval_read_only(
            burn_dbconn,
            tip,
            contract_id,
            &format!("({STACKERDB_SLOTS_FUNCTION})"),
        )?;

        let result = value.expect_result()?;
        let slot_list = match result {
            Err(err_val) => {
                let err_code = err_val.expect_u128()?;
                let reason = format!(
                    "Contract {} failed to run `stackerdb-get-signer-slots`: error u{}",
                    contract_id, &err_code
                );
                warn!("{}", &reason);
                return Err(NetError::InvalidStackerDBContract(
                    contract_id.clone(),
                    reason,
                ));
            }
            Ok(ok_val) => ok_val.expect_list()?,
        };

        let mut total_num_slots = 0u32;
        let mut ret = vec![];
        for slot_value in slot_list.into_iter() {
            let (addr, num_slots) =
                Self::parse_slot_entry(slot_value, contract_id).map_err(|e| {
                    warn!("Failed to parse StackerDB slot entry: {}", &e);
                    NetError::InvalidStackerDBContract(contract_id.clone(), e)
                })?;

            if num_slots > STACKERDB_INV_MAX {
                let reason = format!(
                    "Contract {} stipulated more than maximum number of slots for one signer ({})",
                    contract_id, STACKERDB_INV_MAX
                );
                warn!("{}", &reason);
                return Err(NetError::InvalidStackerDBContract(
                    contract_id.clone(),
                    reason,
                ));
            }

            total_num_slots =
                total_num_slots
                    .checked_add(num_slots)
                    .ok_or(NetError::OverflowError(format!(
                        "Contract {} stipulates more than u32::MAX slots",
                        &contract_id
                    )))?;

            if total_num_slots > STACKERDB_INV_MAX {
                let reason = format!(
                    "Contract {contract_id} stipulated more than the maximum number of slots"
                );
                warn!("{reason}");
                return Err(NetError::InvalidStackerDBContract(
                    contract_id.clone(),
                    reason,
                ));
            }

            ret.push((addr, num_slots));
        }
        Ok(ret)
    }
