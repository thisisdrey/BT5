### Title
Windows WFP Bypass Grants Unconditional, Unscoped Override of Host Firewall Policy - ([File: wfp/wfp_windows.go])

### Summary
Nebula's Windows build installs WFP `PERMIT` filters for the tun interface and UDP listener port using the `FWPM_FILTER_FLAG_CLEAR_ACTION_RIGHT` flag, which strips the host administrator's ability to override the permit with any WDF rule at the same arbitration weight. This is enabled by default (`tun.windows_bypass_wdf` / `listen.windows_bypass_wdf` both default `true`) and grants a broader capability than necessary to establish nebula connectivity, mirroring the reported "superfluous permission" bug class: an unnecessarily broad, unscoped grant is requested/enabled by default when a narrower one would suffice, expanding the attacker-reachable surface without a corresponding functional requirement.

### Finding Description
`wfp.PermitInterface` and `wfp.PermitUDPPort` build filters with the `fwpmFilterFlagClearActionRight` (`0x8`) flag set, explicitly to prevent "lower-priority filters in other sublayers, notably Windows Defender Firewall's MPSSVC_WF sublayer, ... from overriding this PERMIT" even though they "share our 0xFFFF weight" [1](#0-0) . This flag is applied unconditionally to both the interface-scoped filter [2](#0-1)  and the UDP-port-scoped filter [3](#0-2) .

These filters sit at `FWPM_LAYER_ALE_AUTH_RECV_ACCEPT_V4/V6`, a layer below Windows Defender Firewall, so "any WDF inbound rules you rely on for either will no longer apply" once installed [4](#0-3) . Both bypass toggles default to `true` and are wired in unconditionally unless an operator opts out:
- Interface bypass: `bypassWDF: c.GetBool("tun.windows_bypass_wdf", true)` [5](#0-4) , installed on `Activate()` [6](#0-5) .
- Listener bypass: `c.GetBool("listen.windows_bypass_wdf", true)` in `bypassConn.ReloadConfig`, which installs a UDP-port-scoped permit for the bound listener port on first reload [7](#0-6) .

The CHANGELOG confirms this is a deliberate, documented breaking change: "Nebula now installs WFP PERMIT filters for the nebula adapter and the listener port by default. WFP sits below Windows Defender Firewall, so any WDF inbound rules you rely on for either will no longer apply." [8](#0-7) 

The functional need is only to let nebula's own UDP traffic reach the process (which then applies its own certificate/handshake-based firewall in `Firewall.Drop`) even when a restrictive WDF policy is in place. That goal only requires a `PERMIT` at sufficient weight to win arbitration against a *default* WDF block — it does not require stripping the administrator's ability to install an explicit, higher-intent WDF *block* rule targeting the same adapter/port. By setting `ClearActionRight`, nebula grants itself a strictly broader capability (unconditional override of the OS firewall layer for that adapter/port) than what is functionally necessary, which is precisely the "superfluous permission" pattern from the reference report: a capability broader than what the feature needs, enabled by default, expanding attack surface if the binary or its config is compromised or if an operator's WDF policy is silently defeated.

### Impact Explanation
Any unauthenticated attacker who can route UDP packets to the host's public/listening address benefits from this bypass before nebula's own certificate/handshake-based `Firewall.Drop` check runs — the WFP permit operates purely on protocol/port/interface match, with no cert or handshake validation [9](#0-8) . This defeats any host-level defense-in-depth (WDF rules) an operator has configured to restrict inbound exposure of the listener port or adapter, regardless of the administrator's intent, because `ClearActionRight` is unconditionally applied rather than scoped to only override a default-allow/default-deny baseline. This increases the remotely-reachable attack surface of the nebula process (packet parsing, handshake state machine) to any network attacker who would otherwise have been blocked by the host firewall.

### Likelihood Explanation
This is default-enabled (`true`) on every Windows install without an opt-in step, so the exposure is present in the default configuration, matching the shipped-by-default nature of the reference "superfluous permission" finding.

### Recommendation
Do not set `FWPM_FILTER_FLAG_CLEAR_ACTION_RIGHT` on the bypass filters; instead rely on a sufficiently high weight to win arbitration against WDF's default block behavior while allowing an administrator's explicit, higher-priority WDF block rule to still take precedence. At minimum, this should not be default-on; require explicit opt-in (`tun.windows_bypass_wdf` / `listen.windows_bypass_wdf` default `false`) so operators consciously choose to grant this broader host-firewall-override capability, consistent with the principle of least privilege referenced in the analog report.

### Proof of Concept
1. On a default Windows nebula install (`tun.windows_bypass_wdf` and `listen.windows_bypass_wdf` left at default `true`), configure Windows Defender Firewall with an explicit inbound block rule for the nebula listener UDP port or the wintun adapter.
2. Start nebula; `installInterfaceBypass` and `wrapWithWDFBypass` install `ClearActionRight` `PERMIT` filters at `FWPM_LAYER_ALE_AUTH_RECV_ACCEPT_V4/V6` [10](#0-9) [11](#0-10) .
3. Send unsolicited UDP packets from an attacker-controlled address (no nebula CA-signed certificate) to the listener port; observe that despite the administrator's WDF block rule, packets reach the nebula UDP listener and are processed by nebula's packet handling because the OS-level block is overridden — confirming the host firewall enforcement was bypassed unconditionally rather than only in the absence of an explicit administrator policy.

```go
func (b *bypassConn) ReloadConfig(c *config.C) {
	b.installOnce.Do(func() {
		if !c.GetBool("listen.windows_bypass_wdf", true) {
			return
		}
		addr, err := b.Conn.LocalAddr()
		if err != nil {
			b.l.Warn("Failed to query listener port for WFP bypass", "error", err)
			return
		}
		s, err := wfp.PermitUDPPort(addr.Port())
		if err != nil {
			b.l.Warn("Failed to install WFP bypass filters for listener", "error", err)
			return
		}
		b.l.Info("Installed WFP filters bypassing Windows Defender Firewall on UDP listener port",
			"port", addr.Port())
		b.session = s
	})
```
