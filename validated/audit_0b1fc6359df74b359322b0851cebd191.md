Given the constraints, I found a genuine local analog rooted in the added "deferred dispatch" feature of `pallet-whitelist` (introduced by `prdoc/pr_11336.prdoc` [1](#0-0) ), which opens a governance-only call to arbitrary signed relayers without tightening the trust assumptions the original weight-witness parameter relied on.

### Title
Unbounded relayer-supplied `call_weight_witness` in permissionless `pallet_whitelist::dispatch_whitelisted_call` enables free, oversized-weight extrinsics that degrade block production - (File: `substrate/frame/whitelist/src/lib.rs`)

### Summary
The AMM report's core lesson is that a parameter meant to bound/validate an operation (`deadline`) was instead derived from data the caller/miner fully controls at execution time, making the "check" meaningless and letting an adversary submit a transaction whose effective validity is entirely attacker-timed. The local analog is `pallet_whitelist`'s new deferred-dispatch relay path: the extrinsic's declared weight (`call_weight_witness`), which the `#[pallet::weight(...)]` annotation feeds directly into pre-dispatch block-weight accounting, is supplied by an arbitrary unprivileged "relayer" and is only checked as a *lower* bound on the real call weight, never an upper bound, while the relayer pays no fee (`Pays::No`).

### Finding Description
`dispatch_whitelisted_call` was extended so that, once a privileged origin has deferred a call hash (`defer_dispatch`) and later whitelists it (`whitelist_call`), **any signed account** can call `dispatch_whitelisted_call(call_hash, call_encoded_len, call_weight_witness)` to trigger the actual root dispatch [2](#0-1) . The relayer supplies `call_weight_witness` themselves, and the pallet's extrinsic weight is computed straight from that caller-controlled value:

```rust
#[pallet::weight(
    T::WeightInfo::dispatch_whitelisted_call(*call_encoded_len)
        .saturating_add(*call_weight_witness)
)]
``` [3](#0-2) 

Inside the call body, the only validation performed against this witness is:
```rust
ensure!(
    call.get_dispatch_info().call_weight.all_lte(call_weight_witness),
    Error::<T>::InvalidCallWeightWitness
);
``` [4](#0-3) 

This only guarantees the witness is *at least* the real weight — there is no upper-bound sanity check tying the witness to the call's actual measured weight. Combined with the relayer path being fee-free (`Pays::No` per line 237, 276), an unprivileged signed account can pick any pending deferred+whitelisted call and submit it with an inflated `call_weight_witness` (up to just under `BlockWeights::max_block`, which `frame_system::CheckWeight` will still accept), causing the extrinsic's pre-dispatch weight to occupy a large fraction of the block's weight budget while the real dispatched call underneath is cheap. This mirrors the AMM bug's essence: a critical bound/validation parameter is accepted from an untrusted party with only a one-sided (lower-bound-only) check, so it fails to constrain the caller the way the original design (governance-only caller) implicitly assumed.

In the original (pre-PR) `pallet-whitelist`, `dispatch_whitelisted_call` was only reachable by `T::DispatchWhitelistedOrigin` (a trusted/privileged origin), so a self-inflicted bad witness was a non-issue. The deferred-dispatch feature widened the caller set to any signed account without adding a corresponding upper-bound check on the witness, which is exactly the "public wrapper widens the caller/execution surface without proportionally tightening validation" pattern called out in the Polkadot SDK Pivots.

### Impact Explanation
An unprivileged account can consume a disproportionate share of a block's declared weight budget for a nominal actual execution cost, and does so **without paying any transaction fee** (`Pays::No`), directly matching "public underpriced work that degrades block production." Because `apply_extrinsics` fits transactions into a block using their pre-dispatch declared weight before execution [5](#0-4) , an inflated witness can crowd out other legitimate transactions from the same block while the caller incurs no cost.

### Likelihood Explanation
Exploitation requires only a signed account and knowledge of a currently deferred+whitelisted `call_hash` (publicly visible via `DispatchDeferred`/`CallWhitelisted` events and storage). No governance, validator, collator, or relayer-trust assumption is required — any ordinary user racing to be first to relay a pending governance-approved call can set the witness arbitrarily high. The exploit is bounded to one occurrence per governance-created deferred entry (since `clean_and_dispatch` clears state after execution), which limits it to opportunistic rather than continuous abuse, but it requires no privileged access to trigger.

### Recommendation
Bound `call_weight_witness` on both sides: require it to be tightly close to (not just greater than or equal to) the call's actual measured weight (e.g., re-derive/verify weight server-side instead of trusting caller input), or restrict the free/relayer path to a whitelist of low-risk calls, or charge fees proportional to the declared witness regardless of relayer status so an inflated witness is economically penalized rather than free.

### Proof of Concept
1. Privileged origin calls `dispatch_whitelisted_call(call_hash_of_cheap_call, len, weight)` before the call is whitelisted → creates a `DeferredDispatch` entry with an expiry window (`defer_dispatch`, lines 318-330).
2. Privileged origin later calls `whitelist_call(call_hash)`, and the preimage is noted.
3. Any signed account (attacker) calls `dispatch_whitelisted_call(call_hash, correct_len, call_weight_witness = just-under-max-block-weight)`.
4. `ensure_signed_deferred_dispatch` passes (entry exists, not expired, call is whitelisted) (lines 345-362).
5. The `ensure!(call_weight <= call_weight_witness, ...)` check passes trivially since the real call's weight is far below the attacker's inflated witness (lines 230-234).
6. The extrinsic is dispatched with `Pays::No`, consuming its declared (inflated) weight from the block's weight budget for free, while the actual dispatched call (e.g., a cheap `remark`) executes with negligible real cost.

		#[pallet::call_index(2)]
		#[pallet::weight(
			T::WeightInfo::dispatch_whitelisted_call(*call_encoded_len)
				.saturating_add(*call_weight_witness)
		)]
		pub fn dispatch_whitelisted_call(
			origin: OriginFor<T>,
			call_hash: T::Hash,
			call_encoded_len: u32,
			call_weight_witness: Weight,
		) -> DispatchResultWithPostInfo {
			let relayer = match T::DispatchWhitelistedOrigin::try_origin(origin) {
				Ok(_) if WhitelistedCall::<T>::contains_key(call_hash) => None,
				Ok(_) => {
					Self::defer_dispatch(call_hash)?;
					return Ok(Some(T::WeightInfo::defer_dispatch(0)).into());
				},
				Err(dispatch_origin) => {
					Some(Self::ensure_signed_deferred_dispatch(dispatch_origin, call_hash)?)
				},
			};

			let call_data = T::Preimages::fetch(&call_hash, Some(call_encoded_len))
				.map_err(|_| Error::<T>::UnavailablePreImage)?;

			let call = <T as Config>::RuntimeCall::decode_all_with_depth_limit(
				frame::deps::frame_support::MAX_EXTRINSIC_DEPTH,
				&mut &call_data[..],
			)
			.map_err(|_| Error::<T>::UndecodableCall)?;

			ensure!(
				call.get_dispatch_info().call_weight.all_lte(call_weight_witness),
				Error::<T>::InvalidCallWeightWitness
			);

			// Relayer isn't charged; the privileged direct path still pays.
			let pays_fee = if relayer.is_some() { Pays::No } else { Pays::Yes };

			let call_actual_weight = Self::clean_and_dispatch(call_hash, call);
			if let Some(who) = relayer {
				Self::deposit_event(Event::<T>::DeferredDispatchExecuted { call_hash, who });
			}

			let actual_weight = call_actual_weight.map(|w| {
				w.saturating_add(T::WeightInfo::dispatch_whitelisted_call(call_encoded_len))
			});
			Ok(PostDispatchInfo { actual_weight, pays_fee })
		}
