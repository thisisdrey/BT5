### Title
Reftable parser performs unchecked, attacker-influenced length arithmetic on variable-length fields, causing an index-out-of-range panic and RPC handler DoS - (File: internal/git/reftable/reftable.go)

### Summary
Gitaly's own Go implementation of the Git reftable binary format (`internal/git/reftable/reftable.go`) decodes variable-length integers and byte spans read directly from on-disk reftable files without validating that the derived offsets and lengths stay within the bounds of the source buffer. A crafted or corrupted reftable file can drive `prefixLength`, `suffixLength`, or the peeled/target OID length past the end of `src`, causing a Go slice-bounds-out-of-range panic. This mirrors the reported Solidity issue, where a loose length check (`>= 32` instead of `== 32`) let attacker-influenced data reach a decode path that panics/reverts instead of failing gracefully, resulting in denial of service of the calling function/handler.

### Finding Description
`getVarInt` only bounds-checks the *byte index* while walking the continuation bits of a var-int (`start > blockEnd`), but never validates the resulting decoded `val` (length) against the remaining buffer size: [1](#0-0) 

That unchecked length is then used directly for slicing in `getRefsFromBlock`: [2](#0-1) 

and again for hash/target extraction: [3](#0-2) 

Specifically:
- `refname := prefix[:prefixLength] + string(src[idx:idx+suffixLength])` — `prefixLength` is not checked against `len(prefix)`, and `idx+suffixLength` is not checked against `len(src)`.
- `src[idx : idx+uint(hashSize)]` for regular/peeled references, and `src[idx : idx+size]` for symrefs, similarly trust attacker-controlled offsets/lengths without bounds checks.

`parseRefBlock` computes `RestartStart` from an on-disk restart count with no sanity check that it lies within the block, which can also drive `idx`/`b.RestartStart` out of range before the loop even begins: [4](#0-3) 

Because Go performs no automatic bounds clamping, any of these out-of-range slice expressions triggers a runtime panic (`index out of range` / `slice bounds out of range`) rather than a graceful error return — directly analogous to `abi.decode` reverting when `data.length` exceeds the expected size due to a loose `>=` check instead of `==`.

### Impact Explanation
`Table.GetReferences()` (which drives this vulnerable code path) is invoked whenever Gitaly needs to enumerate references from a reftable-backed repository, e.g. in `ReferencesInfoForRepository` (used by repository info/statistics paths) and in test/production helpers that read back reftable state after transactions: [5](#0-4) [6](#0-5) 

A repository whose `reftable/` directory contains a malformed table file — for example one introduced through repository import/fork/replication where raw repository bytes are copied without being re-validated by the `git` binary itself — will cause any Gitaly code path that calls into this parser to panic. Existing tests already demonstrate that reftable file bytes can be manipulated and still be considered a "reference" the code must parse (see the `CalculateChecksum` "invalid reference" test, which patches raw reftable bytes on disk): [7](#0-6) 

A panic in an RPC-serving goroutine, if not caught by a recovery interceptor, crashes the request (and potentially the process/goroutine group), producing a denial-of-service condition for the handler processing that repository — consistent with the DoS class described in the source report.

### Likelihood Explanation
Reaching this code requires a repository using the reftable reference backend that contains a reftable file with tampered/corrupted length fields. This can occur via fork/import/replication flows where repository files are copied verbatim into Gitaly-managed storage before any Gitaly-side parsing occurs, or via storage corruption. Since gitaly's own Go parser (not `git` itself) performs the decoding, it does not benefit from Git's native input validation, making it the weaker link when handling this binary format from an unprivileged storage-path perspective.

### Recommendation
Harden `getVarInt`, `getRefsFromBlock`, and `parseRefBlock` to validate all derived lengths and offsets against the actual buffer bounds (`len(src)` and `len(prefix)`) before slicing, returning a descriptive parse error instead of allowing an out-of-bounds slice expression to panic — mirroring the recommended fix of replacing a loose bound check with a strict, buffer-size-aware validation before consuming the decoded length.

### Proof of Concept
1. Create a repository using the reftable backend.
2. Directly edit the on-disk reftable file under `reftable/` (as already done in `TestCalculateChecksum`'s "invalid reference" case) to inflate a suffix-length or prefix-length var-int field beyond the remaining block/buffer size, instead of merely substituting equal-length bytes.
3. Trigger any RPC/code path that calls `reftable.ParseTable(...).GetReferences()` (e.g., repository info/statistics computation) against that repository.
4. Observe a runtime panic (`slice bounds out of range`) originating in `getRefsFromBlock`/`getVarInt`, crashing or aborting the handling goroutine instead of returning a controlled error.

func (t *Table) getVarInt(src []byte, start uint, blockEnd uint) (uint, uint, error) {
	var val uint

	val = uint(src[start]) & 0x7f

	for (uint(src[start]) & 0x80) > 0 {
		start++
		if start > blockEnd {
			return 0, 0, fmt.Errorf("exceeded block length")
		}

		val = ((val + 1) << 7) | (uint(src[start]) & 0x7f)
	}

	return start + 1, val, nil
}

// parseRefBlock parses a block and if it is a ref block, provides
// all the reference updates.
func (t *Table) parseRefBlock(src []byte, headerOffset, blockStart, blockEnd uint) ([]git.Reference, error) {
	currentBS := t.extractBlockLen(src, blockStart+headerOffset)

	fullBlockSize := t.blockSize
	if fullBlockSize == 0 {
		fullBlockSize = currentBS
	} else if currentBS < fullBlockSize && currentBS < (blockEnd-blockStart) && src[blockStart+currentBS] != 0 {
		fullBlockSize = currentBS
	}

	b := &block{
		BlockStart:    blockStart + headerOffset,
		FullBlockSize: fullBlockSize,
	}

	if err := binary.Read(bytes.NewBuffer(src[blockStart+currentBS-2:]), binary.BigEndian, &b.RestartCount); err != nil {
		return nil, fmt.Errorf("reading restart count: %w", err)
	}

	b.RestartStart = blockStart + currentBS - 2 - 3*uint(b.RestartCount)

	return t.getRefsFromBlock(src, b)
}
