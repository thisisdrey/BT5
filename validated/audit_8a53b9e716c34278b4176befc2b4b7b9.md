## Finding: Protocol Fee on `TokenDiff` Swaps Can Be Fully Evaded by Trading Exactly 1 Unit of a `Nep245`/`Imt` Asset

### Summary
The `TokenDiff` intent's fee logic exempts `Nep245` (multi-token) and `Imt` (intent-mintable) token legs from the protocol fee whenever the traded amount is `<= 1` unit. Since the on-chain "unit" granularity of a `Nep245`/`Imt` token is arbitrary and can represent an economically large amount of value (e.g., a coarsely-denominated wrapped position, vault share, or a token deliberately minted by its own `Imt` minter with high per-unit value), any unprivileged user can structure a `TokenDiff` swap so that the negative-delta leg is exactly `1` unit, bypassing the protocol fee entirely — directly analogous to the reported `desc.effectiveOutputAmount` fee-evasion pattern, where choosing a value just under a hard threshold skips fee collection.

### Finding Description
`TokenDiff::execute_intent` computes the protocol fee per token leg only for negative deltas (`token_in`), using `token_fee()`: [1](#0-0) 

`token_fee()` explicitly zeroes the fee for `Nep245`/`Imt` (and always for `Nep171`) tokens whenever the traded amount is `1` or less: [2](#0-1) 

This threshold is denominated in raw integer units of the `TokenId`, not in any normalized value. For `Nep245` tokens (wrapped multi-token balances, e.g. shares of a vault/pool or another nested intents contract) and for `Imt` tokens (synthetic tokens freely minted via `ImtMint` by any signer, with no fixed decimals or backing requirement — see `ImtMint::execute_intent` at `contracts/defuse/core/src/intents/imt.rs:42-72`), the "1 unit" quantum is entirely determined by how the token was minted/denominated. A user (either the `Imt` minter themselves, or any counterparty trading a coarsely-denominated `Nep245` asset) can therefore choose to move exactly `1` unit of such a token as the `token_in` leg of a `TokenDiff`, guaranteeing `token_fee()` returns `Pips::ZERO` for that leg — regardless of the swap's real economic size.

This mirrors the reported bug class exactly: the fee is a step function gated on a raw magnitude threshold (`amount > 1`) rather than being proportional to value, so an attacker picks the input just below the threshold to avoid paying any fee — the same mechanism as picking `effectiveOutputAmount`/slippage just low enough to dodge `GluexRouter`'s routing fee.

### Impact Explanation
This lets any unprivileged solver/trader evade the protocol fee (`engine.state.fee()`) on the `Nep245`/`Imt` leg of a `TokenDiff` swap while still settling real value via the balanced counter-leg, directly reducing protocol fee revenue without any authorization from `Role::FeesManager`/DAO. Per the stated impact criteria, "fees bypassed" is a Critical-class outcome since `fees_collected` in `TokenDiffEvent` (and the amount deposited to `engine.state.fee_collector()`) will be `0` for a leg carrying non-trivial value.

### Likelihood Explanation
Any two parties can pre-arrange a `TokenDiff` swap (a common intent pattern, as shown in the `solver_user_closure`/`swap_many` tests) where one leg is a `Nep245`-typed token with coarse unit granularity or an `Imt` token minted by one of the parties, with a delta of exactly `-1`. No special privileges, timing, or race conditions are required — it's a simple choice of the swap parameters at signing time.

### Recommendation
Compute the fee based on value/normalized amount rather than a hard-coded raw unit threshold, or remove the blanket `amount <= 1` exemption for `Nep245`/`Imt` and instead scope any dust exemption to token types/registries where 1 raw unit is guaranteed to be economically negligible (e.g., true NFTs via `Nep171`), not to `Nep245`/`Imt` whose per-unit value is unconstrained.

### Proof of Concept
1. User `M` signs `ImtMint { tokens: {"share": 1}, receiver_id: M }`, minting a single unit of `imt:M:share` to themselves — no collateral required (`contracts/defuse/core/src/intents/imt.rs:42-72`).
2. `M` and counterparty `B` (who holds real `nep141:usdc.near` balance) sign a matched pair of `TokenDiff` intents:
   - `M`: `diff = { imt:M:share: -1, nep141:usdc.near: +1_000_000 }`
   - `B`: `diff = { imt:M:share: +1, nep141:usdc.near: -1_000_000 }`
3. On `execute_intents`, for `M`'s leg, `token_fee(imt:M:share, amount=1, fee)` returns `Pips::ZERO` (per `contracts/defuse/core/src/intents/token_diff.rs:210-216`), so no fee is collected on that leg even though it's paired against `1_000_000` USDC of real value; `B`'s negative delta is on `usdc` (Nep141, not exempt) and would incur the normal fee only on that leg, so the party who structures which side carries the negative delta on the `Imt`/`Nep245` token controls whether that portion of value is fee-exempt.
4. Repeating/parametrizing this pattern lets solvers systematically route the higher-value side of a swap through a `Nep245`/`Imt` leg pinned at `amount = 1` to avoid the fee on that leg, confirmed by `fees_collected` in the emitted `TokenDiffEvent` being `0` for that token.

    pub fn token_fee(token_id: impl Into<TokenIdType>, amount: u128, fee: Pips) -> Pips {
        let token_id = token_id.into();
        match token_id {
            TokenIdType::Nep141 => {}
            TokenIdType::Nep245 | TokenIdType::Imt if amount > 1 => {}
            // do not take fees on NFTs and MTs with |delta| <= 1
            TokenIdType::Nep171 | TokenIdType::Nep245 | TokenIdType::Imt => return Pips::ZERO,
        }
        fee
    }
