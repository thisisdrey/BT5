### Title
Unauthenticated `/shutdown` endpoint on the signer's event listener allows any remote peer to halt signer event processing - ([File: libsigner/src/events.rs])

### Summary
`SignerEventReceiver` (the HTTP server a `stacks-signer` process binds to receive events pushed by its paired `stacks-node`) exposes a `/shutdown` route that unconditionally sets the receiver's stop flag and terminates its main loop on any HTTP POST, with no authentication, token, or peer-origin check. The reachable-write-without-authorization equality the external report's bug class targets — "authenticated caller vs. any caller" — is broken here: the intended caller is only the node's own `SignerStopSignaler`, but the wire protocol has no way to distinguish it from an arbitrary remote client.

### Finding Description
`SignerEventReceiver::next_event` dispatches incoming HTTP requests purely by URL path, with zero authentication check on any route (`/status`, `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block`, `/shutdown`): [1](#0-0) 

The `/shutdown` branch immediately flips the stop flag and returns a termination error, with no signature, password, or session check whatsoever: [2](#0-1) 

This is the exact same mechanism the legitimate `SignerStopSignaler::send()` uses to terminate the receiver from within the same node — a plain, unauthenticated `POST /shutdown` over TCP: [3](#0-2) 

`main_loop()` checks `is_stopped()` on every iteration and breaks out as soon as `next_event()` returns `EventError::Terminated`: [4](#0-3) 

The node-side `auth_token`/signer-side `auth_password` pairing documented as securing signer↔node coordination is only enforced on RPC endpoints exposed by the **node** (e.g., `fast-call-read`, `block_proposal`), which explicitly check an `authorization` header against a configured password: [5](#0-4) 

No equivalent check exists anywhere in the signer's own event-ingestion path (`libsigner/src/events.rs`, `libsigner/src/http.rs`), and the node's outbound event-dispatch worker that POSTs to the observer endpoint does not add any `Authorization` header either, confirming the event listener was never gated by that token in the first place: [6](#0-5) 

### Impact Explanation
Any remote party that can reach the TCP port the signer's event listener is bound to (per `docs/signing.md`, `endpoint = "0.0.0.0:30000"`-style bindings are used in several sample configs, and the port is a general listening socket, not restricted to loopback) can send a bare unauthenticated `POST /shutdown` and stop the signer's event-processing loop. This halts delivery of `stackerdb_chunks`, `proposal_response`, and `new_burn_block`/`new_block` events into the signer's runloop, effectively taking a consensus-participating signer offline until an operator manually restarts it. This is a remote, unauthenticated denial-of-service achievable with a single crafted HTTP request — matching the "Critical: remote crash/unauthenticated DoS from few messages" impact tier.

### Likelihood Explanation
High. The attack requires only network reachability to the signer's bound event-listener address and a single well-formed HTTP POST with no body, headers, signature, or prior handshake — no secret material, no timing, no race condition.

### Recommendation
Require an authentication check on the `/shutdown` route (and ideally all `SignerEventReceiver` routes) before acting on it, e.g. reuse the existing `auth_password`/token mechanism already defined for signer↔node coordination, or restrict the shutdown mechanism to an in-process/local-only channel (e.g., a Unix socket or the existing `AtomicBool` shared directly with the owning thread) instead of an unauthenticated network-reachable HTTP endpoint.

### Proof of Concept
1. Start a `stacks-signer` with its event listener bound to a network-reachable address (per sample configs, e.g. `endpoint = "0.0.0.0:30000"`).
2. From any remote host with network access to that port, send:
```
POST /shutdown HTTP/1.1
Host: <signer-ip>:30000
Connection: close
Content-Length: 0

```
3. `SignerEventReceiver::next_event` matches `/shutdown`, sets `stop_signal` to `true`, and returns `Err(EventError::Terminated)`; `main_loop()` observes this and exits, permanently halting further event ingestion for that signer process (matching the code path shown at `libsigner/src/events.rs:443-445` and `libsigner/src/events.rs:282-312`).

    /// Main loop for the receiver.

    fn main_loop(&mut self) {
        loop {
            if self.is_stopped() {
                info!("Event receiver stopped");
                break;
            }
            let next_event = match self.next_event() {
                Ok(event) => event,
                Err(EventError::UnrecognizedEvent(..)) => {
                    // got an event that we don't care about (not a problem)
                    continue;
                }
                Err(EventError::Terminated) => {
                    // we're done
                    info!("Caught termination signal");
                    break;
                }
                Err(e) => {
                    warn!("Failed to receive next event: {:?}", &e);
                    continue;
                }
            };
            if !self.forward_event(next_event) {
                info!("Failed to forward event");
                break;
            }
        }
        info!("Event receiver main loop exit");
    }
