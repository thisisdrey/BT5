### Title
Unauthenticated event-injection into `SignerEventReceiver`'s HTTP listener allows forged burn-block/block state to be pushed into the signer - (File: `libsigner/src/events.rs`)

### Summary
`SignerEventReceiver` (used by `stacks-signer`) runs a plain `tiny_http` server that accepts `POST` requests on `/stackerdb_chunks`, `/new_burn_block`, `/new_block`, `/proposal_response`, and `/shutdown` with **no authentication, no Origin/Referer check, and no source verification of any kind**. Any of these routes that carries content the signer treats as chain-state (`/new_burn_block`, `/new_block`) is forwarded to the signer runloop as trusted data with zero cryptographic validation, mirroring the CSRF bug class in the report: a mutating endpoint that accepts state-changing requests from any party that can reach the socket, without verifying the caller is the legitimate peer (the node).

### Finding Description
`SignerEventReceiver::next_event` in [1](#0-0)  dispatches incoming HTTP requests purely by URL path and verb — it never inspects `Authorization`, `Origin`, `Referer`, or any other header that would tie the request to the expected sender (the local `stacks-node`'s event dispatcher). Contrast this with the node-side `/v3/block_proposal` handler, which enforces an `auth_token`/password check before accepting a mutating POST, as seen in [2](#0-1)  and the `auth_token` config field documented at [3](#0-2) . No equivalent gate exists on the signer's event listener.

For `/new_burn_block` and `/new_block`, `process_event` reads the body, deserializes it as JSON, and converts it directly into a `SignerEvent` with no signature or provenance check at all: [4](#0-3) [5](#0-4) [6](#0-5) 

Compare this to `/stackerdb_chunks`, where at least the *signer-message* payloads go through `chunk.recover_pk()` (an ECDSA recovery, not a verified check against the expected StackerDB slot owner) before being forwarded — see [7](#0-6) . `NewBurnBlock` and `NewBlock` have no such check whatsoever: whatever JSON arrives on the socket is trusted as the "burn height", "consensus hash", "burn header hash" and "transactions" the signer believes are canonical.

The listener binds to a configurable socket per [8](#0-7) , and per the signer/node coordination docs this "endpoint" is expected to be reachable by the paired node — e.g. `endpoint = "127.0.0.1:30000"` / `endpoint = "0.0.0.0:30000"` in [9](#0-8) . Whether bound to loopback or a wider interface, any process (or, if loopback, any local browser tab per the CSRF report's bug class) capable of opening a TCP connection to that port can submit a forged `POST /new_burn_block` or `POST /new_block` request and have it accepted verbatim — there is no equality check between "authenticated sender" and "the node that is supposed to be feeding this signer," which is exactly the class of fault flagged in the external report (mutating endpoint reachable without Origin/Referer/auth validation).

### Impact Explanation
This breaks the "authenticated vs. stored/trusted" equality: unauthenticated data becomes indistinguishable from data legitimately pushed by the local node. Forged `NewBurnBlock`/`NewBlock` events are injected straight into the signer's event stream and change its local view of burnchain height, consensus hash, and even transaction lists, without any signature over that data. Since this data feeds into the signer's state (burnchain view, tenure timers, etc.), this is a request-smuggling-style unauthorized write to signer-local state from an unauthorized party — matching the "unauthenticated/unauthorized write to state" impact tier.

### Likelihood Explanation
Likelihood depends on network reachability to the signer's event-listener port. Nothing in the code path restricts callers by origin, source IP, or credential — the check is entirely path/verb-based. On any deployment where this port is reachable by more than the exact paired node process (e.g., bound non-strictly to loopback, or reachable by other local processes/containers), exploitation requires only crafting a simple HTTP POST — no cryptographic material and no privileged role are needed.

### Recommendation
Add an explicit authentication check (e.g., a shared secret/token akin to `auth_token` used on `/v3/block_proposal`) to `SignerEventReceiver::next_event`/`process_event` before accepting any mutating POST, and reject requests whose `Origin`/`Referer` (if present) do not match the expected node origin. At minimum, `/new_burn_block` and `/new_block` should require the same authenticated channel as `/stackerdb_chunks`'s signer-message path, rather than trusting arbitrary JSON bodies.

### Proof of Concept
1. Start a `stacks-signer` instance with its event-listener bound per configuration (e.g., `endpoint = "0.0.0.0:30000"`, per [9](#0-8) ).
2. From any host/process that can reach that port (no credentials), send:
```
POST /new_burn_block HTTP/1.1
Host: <signer-ip>:30000
Content-Type: application/json
Content-Length: <n>

{"burn_block_height": 999999, "burn_block_hash": "0x..", "consensus_hash": "0x..", "parent_burn_block_hash": "0x.."}
```
3. `SignerEventReceiver::next_event` routes this to `process_event::<T, BurnBlockEvent>` ( [10](#0-9) ), which deserializes and converts it into `SignerEvent::NewBurnBlock` with no validation ( [5](#0-4) ), and forwards it to the signer runloop as if it came from the trusted local node.

    fn next_event(&mut self) -> Result<SignerEvent<T>, EventError> {
        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)
            } else if request.url() == "/new_block" {
                process_event::<T, StacksBlockEvent>(request)
            } else {
                let url = request.url().to_string();
                debug!(
                    "[{:?}] next_event got request with unexpected url {}, return OK so other side doesn't keep sending this",
                    event_receiver.local_addr,
                    url
                );
                ack_dispatcher(request);
                Err(EventError::UnrecognizedEvent(url))
            }
        })?

fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
