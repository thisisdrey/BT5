### Title
Unauthenticated POST to signer's `SignerEventReceiver` HTTP endpoints allows injection of forged `SignerEvent`s - (File: `libsigner/src/events.rs`)

### Summary
`SignerEventReceiver::next_event` dispatches `/proposal_response`, `/new_burn_block`, and `/new_block` POST requests straight into `process_event::<T, E>()`, which only calls `serde_json::from_slice` on the raw request body and converts it into a `SignerEvent`. There is no signature, shared-secret, or peer-identity check anywhere in this path, so any TCP peer that can reach the bound listener (which the reference/sample configs bind to `0.0.0.0:30000`) can post an arbitrary JSON body and have it accepted as a genuine node-originated event.

### Finding Description
The broken equality: every `SignerEvent` consumed by the signer runloop is assumed to have been genuinely emitted by the trusted node's event-dispatcher (as configured via `[[events_observer]] endpoint`), but `SignerEventReceiver::next_event` enforces no such binding.

Code path: `next_event` receives an HTTP request from `tiny_http::HttpServer` and dispatches purely by `request.url()`: [1](#0-0) 

Each branch calls `process_event::<T, E>(request)`, which reads the raw body and deserializes it with `serde_json::from_slice` — no header, token, or origin check is performed before or after: [2](#0-1) 

The resulting typed value is converted via `TryFrom` directly into `SignerEvent::BlockValidationResponse`, `SignerEvent::NewBurnBlock { burn_height, burn_header_hash, consensus_hash, ... }`, or `SignerEvent::NewBlock { block_id, consensus_hash, block_height, transactions, ... }`: [3](#0-2) [4](#0-3) 

These events are then forwarded unchanged to the signer's runloop via `forward_event`: [5](#0-4) 

By contrast, the `auth_password`/`auth_token` pairing documented in the signer/node configs only secures the *outbound* direction (signer → node RPC, e.g. block-proposal validation calls), not the inbound direction where the node (or an attacker) pushes events into the signer's listener: [6](#0-5) 
The sample node-side config binds this listener to all interfaces by default: [7](#0-6) 

Nothing in `bind()`, `with_server()`, or `next_event()` checks the peer's source address, a shared secret header, or any HMAC/signature over the body before accepting `/proposal_response`, `/new_burn_block`, or `/new_block` payloads: [8](#0-7) 

### Impact Explanation
A remote unprivileged party who can open a TCP connection to the signer's listener port can inject forged `BurnBlockEvent`, `StacksBlockEvent`, or `BlockValidateResponse` JSON bodies. These become `SignerEvent::NewBurnBlock` (attacker-chosen `burn_height`, `consensus_hash`, `burn_header_hash`), `SignerEvent::NewBlock` (attacker-chosen `block_id`, `consensus_hash`, `block_height`, `transactions`), or `SignerEvent::BlockValidationResponse` values that are handed to the signer's decision-making runloop as if the configured node had genuinely emitted them. This is an unauthenticated write into the signer's consensus-adjacent decision inputs, repeatable per TCP connection, matching the "unauthenticated/unauthorized write to state" Critical category.

### Likelihood Explanation
No signer-side or connection-options secret, peer-identity check, or TLS/mTLS gate exists in this code path; the only requirement is TCP reachability of the bound `endpoint`. Sample and reference configs bind this port to `0.0.0.0`, and nothing in `libsigner` restricts source IPs. The attacker needs no privileged role, no RPC secret, and no StackerDB slot — only network reachability to the port, making this trivially repeatable with a single crafted HTTP POST per event.

### Recommendation
Require the signer's event-receiver HTTP endpoints to authenticate the sender before deserializing/dispatching — e.g., verify a shared secret/HMAC header (reusing or mirroring `auth_token`/`auth_password` but applied to the inbound direction), and/or restrict `bind()` to loopback-only with an explicit opt-in for remote binding plus mandatory authentication, rejecting any POST to `/proposal_response`, `/new_burn_block`, `/new_block`, `/stackerdb_chunks` that lacks a valid credential before calling `process_event`.

    /// Errors are recoverable -- the caller should call this method again even if it returns an
    /// error.
    fn next_event(&mut self) -> Result<SignerEvent<T>, EventError> {
        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)
            } else if request.url() == "/new_block" {
                process_event::<T, StacksBlockEvent>(request)
            } else {
                let url = request.url().to_string();
                debug!(
                    "[{:?}] next_event got request with unexpected url {}, return OK so other side doesn't keep sending this",
                    event_receiver.local_addr,
                    url
                );
                ack_dispatcher(request);
                Err(EventError::UnrecognizedEvent(url))
            }
        })?
    }

    fn forward_event(&mut self, ev: SignerEvent<T>) -> bool {
        if self.out_channels.is_empty() {
            // nothing to do
            error!("No channels connected to event receiver");
            false
        } else if self.out_channels.len() == 1 {
            // avoid a clone
            if let Err(e) = self.out_channels[0].send(ev) {
                error!("Failed to send to signer runloop: {:?}", &e);
                return false;
            }
            true
        } else {
            for (i, out_channel) in self.out_channels.iter().enumerate() {
                if let Err(e) = out_channel.send(ev.clone()) {
                    error!("Failed to send to signer runloop #{}: {:?}", i, &e);
                    return false;
                }
            }
            true
        }
    }

fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}
