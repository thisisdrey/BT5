### Title
Half-open QUIC connection flood from a single IP starves the shared `ClientConnectionTracker` pool because rate limiters only activate post-handshake - (File: streamer/src/nonblocking/quic.rs)

### Summary
In `run_server`, both the global `overall_connection_rate_limiter` and the per-IP `ConnectionRateLimiter` are only *consulted* (read-only, non-consuming checks) before the handshake, while tokens are only actually *consumed* (`register_connection` / `consume_tokens`) in `setup_connection` after the QUIC handshake completes. An attacker who never completes the handshake therefore never gets rate-limited, and can repeatedly acquire `ClientConnectionTracker` slots (a resource pool shared across peer types, gated only by `qos.max_concurrent_connections()`) from many ephemeral source ports on one IP, holding each slot for up to `QUIC_CONNECTION_HANDSHAKE_TIMEOUT` before it's freed and immediately re-acquired.

### Finding Description
In `run_server` [1](#0-0) , incoming connections are checked against `overall_connection_rate_limiter.current_tokens() == 0` and `rate_limiter.is_allowed(&ip)`. Both are pure reads of current bucket state - they do not consume tokens. Token consumption only happens later, inside `setup_connection`, after the handshake succeeds: `rate_limiter.register_connection(&from.ip())` and `overall_connection_rate_limiter.consume_tokens(1)` [2](#0-1) .

This is a deliberate design choice, documented in the code comment: "attempting to be smarter before a peer has asserted control over their ip address by completing the retry challenge creates a scenario whereby peers can attack one another via ip spoofing" [3](#0-2) . However, the practical consequence is that an attacker who never completes the handshake is invisible to both rate limiters, no matter how many connection attempts they generate from the same source IP (using different ephemeral ports), because `is_allowed`/`current_tokens` never observe any consumption from that attacker's traffic.

The only pre-handshake gate is `ClientConnectionTracker::new(stats.clone(), qos.max_concurrent_connections())` [4](#0-3) , which increments a single global `stats.open_connections` counter shared by both staked and unstaked peer types (peer-type classification only happens later, in `try_add_connection`, after the handshake). Once `open_connections >= max_concurrent_connections` [5](#0-4) , `incoming.refuse()` is called and `refused_connections_too_many_open_connections` is incremented for the connection attempt - meaning legitimate new connections (both staked and unstaked) are rejected while the pool is full.

Each acquired slot is held for at most `QUIC_CONNECTION_HANDSHAKE_TIMEOUT` (2 seconds) via `timeout(QUIC_CONNECTION_HANDSHAKE_TIMEOUT, connecting).await` in `setup_connection` [6](#0-5)  before being dropped (freeing the tracker slot via `Drop for ClientConnectionTracker` [7](#0-6) ). An attacker only needs to send enough of a QUIC Initial packet to make `incoming.accept()` succeed and never respond further; the connection will occupy a tracker slot for the full 2-second window at essentially no bandwidth/compute cost to the attacker, and can be refilled indefinitely at a rate exceeding `max_concurrent_connections / QUIC_CONNECTION_HANDSHAKE_TIMEOUT` using distinct ephemeral source ports from a single IP (no spoofing or stake required).

### Impact Explanation
This matches the scoped "ingress buffer/connection-tracker exhaustion halting new legitimate connections into banking" impact. While memory growth is bounded (capped by `max_concurrent_connections`), the shared pool being exhausted by an unstaked/unauthenticated attacker denies *both* staked and unstaked legitimate clients the ability to open new TPU QUIC connections for the duration of the flood, since `ClientConnectionTracker` allocation happens before any stake-based differentiation.

### Likelihood Explanation
Feasible with a single unstaked attacker machine using ephemeral source ports against the public TPU QUIC port; no stake, spoofing, or protocol compliance beyond sending an Initial packet is required. The attack is continuous/repeatable as long as the attacker sustains a connection-attempt rate exceeding the natural drain rate of the tracker pool (pool_size / 2s).

### Recommendation
Bound the number of concurrently outstanding *pre-handshake* attempts per source IP (not just globally), and/or apply the per-IP/global rate limiters as a consuming check at accept time (before allocating a `ClientConnectionTracker` slot) rather than only after handshake completion, accepting the documented spoofing tradeoff for a lightweight, cheap-to-verify per-IP cap (e.g., token consumption on `incoming.accept()` with a coarse per-IP ceiling, independent of full handshake completion).

### Proof of Concept
Integration test plan (tokio):
1. Start `run_server`/`setup_quic_server` with a small `max_concurrent_connections` (e.g. via `SwQosConfig::default_for_tests()`).
2. From a single loopback IP, spawn N > `max_concurrent_connections` `quinn::Endpoint::connect` calls bound to distinct local ports, but drop/ignore the resulting `Connecting` future immediately after issuing it (never await completion), simulating never-completing handshakes.
3. Concurrently, attempt a legitimate `make_client_endpoint` connection and complete it fully.
4. Assert that `stats.refused_connections_too_many_open_connections` increases proportionally to N while the legitimate connection experiences `connection_setup_timeout`/refusal or is delayed beyond `QUIC_CONNECTION_HANDSHAKE_TIMEOUT`, demonstrating slot starvation, and confirm `stats.connection_rate_limited_per_ipaddr`/`connection_rate_limited_across_all` remain 0 for the attacker's half-open connections (proving the rate limiters never triggered).

impl ClientConnectionTracker {
    /// Check the max_concurrent_connections limit and if it is within the limit
    /// create ClientConnectionTracker and increment open connection count. Otherwise returns Err
    fn new(stats: Arc<StreamerStats>, max_concurrent_connections: usize) -> Result<Self, ()> {
        let open_connections = stats.open_connections.fetch_add(1, Ordering::Relaxed);
        if open_connections >= max_concurrent_connections {
            stats.open_connections.fetch_sub(1, Ordering::Relaxed);
            debug!(
                "There are too many concurrent connections opened already: open: \
                 {open_connections}, max: {max_concurrent_connections}"
            );
            return Err(());
        }

        Ok(Self { stats })
    }
}
