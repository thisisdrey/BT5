## Title
Oracle assumes 1 stSTXbtc (liquid-staked-STX-with-BTC-yield wrapper) equals 1 STX, inflating collateral valuation - (File: `mainnet/contracts/proposals/mainnet/v0-init.clar`, `mainnet/contracts/utility/v0-1-data.clar`, `mainnet/contracts/market/v0-4-market.clar`)

### Summary
The stSTXbtc asset is registered in the oracle with a raw STX/USD Pyth feed and `callcode: none`, meaning the market prices 1 `stSTXbtc` as exactly 1 STX with no conversion ratio applied — the same category of error as H-8's "1 SY == 1 Yield Token" assumption in the Pendle oracle.

### Finding Description
`stSTXbtc` is documented as a distinct wrapper: "Liquid staked STX (BTC yield)" with "Purpose: Liquid staking with BTC-denominated yield" [1](#0-0) . Unlike `stSTX`, which is registered with `callcode: (some CALLCODE-STSTX)` so that a live ratio (`call-ststx-ratio`) is applied on top of the raw STX price before it's used [2](#0-1) , `stSTXbtc` (Asset ID 10) is registered with the raw `STX-FEED-ID` and `callcode: none`:

```
;; Asset ID 10: stSTXbtc
(try! (contract-call? .assets insert STSTXBTC-TOKEN
  { type: TYPE-PYTH, ident: STX-FEED-ID, callcode: none, max-staleness: MAX-STALENESS }))
``` [3](#0-2) 

This is mirrored exactly in the price-lookup helper, which hard-codes the STX Pyth price as the price of `stSTXbtc` with no exchange-rate query at all, in contrast to the `stSTX` branch a few lines above which explicitly multiplies by `(unwrap-panic (get-ststx-ratio))`:

```clarity
;; stSTX - STX price x stSTX ratio
(if (is-eq aid stSTX) 
    (let ((stx-price (default-to u0 (get-pyth-price PYTH-STX)))
          (ratio (unwrap-panic (get-ststx-ratio))))
      (mul-div-down stx-price ratio STSTX-RATIO-DECIMALS))
...
;; stSTXbtc - BTC price (liquid staked STX with BTC yield)
(if (is-eq aid stSTXbtc) (default-to u0 (get-pyth-price PYTH-STX))
``` [4](#0-3) 

The zstSTXbtc vault-share price simply layers a liquidity index on top of that same unconverted STX price: [5](#0-4) 

Even the on-chain oracle callcode dispatcher in `market.clar`/`v0-4-market.clar` treats `stSTXbtc` as needing no base transformation — `CALLCODE-ZSTSTXBTC` only applies the liquidity-index (`resolve-ztoken`) step, never any stSTXbtc-specific exchange-rate resolver, whereas the analogous `zstSTX` path chains `resolve-ststx` before `resolve-ztoken`:

```clarity
(if (is-eq cc CALLCODE-ZSTSTX) (resolve-ztoken (try! (resolve-ststx p)) stSTX)
...
(if (is-eq cc CALLCODE-ZSTSTXBTC) (resolve-ztoken p stSTXbtc)
``` [6](#0-5) 

There is no `call-ststxbtc-ratio`, `get-ststxbtc-ratio`, or equivalent function anywhere in the codebase — a grep for "stSTXbtc" ratio-style helpers returns nothing besides the `stSTX` ratio calls, confirming stSTXbtc's real exchange rate against STX (or BTC) is never fetched on-chain. Because stSTXbtc is a liquid-staking wrapper (analogous to Pendle's SY token in the H-8 report), its actual redemption value per unit of STX is not guaranteed to be exactly 1:1; it can drift due to staking rewards, protocol fees, or yield-realization mechanics of the underlying liquid-staking system, exactly as Pendle's SY-to-yield-token redemption can deviate from 1:1 due to swaps/fees during redemption.

### Impact Explanation
If stSTXbtc's true value diverges from raw STX price (which is expected behavior for any liquid-staking-derivative wrapper that accrues yield relative to its peg), the market overvalues (or undervalues) all collateral denominated in `stSTXbtc` and `zstSTXbtc`. Both are enabled for use as collateral (`zstSTXbtc` collateral-only per the initialization proposal) [7](#0-6) . An inflated price lets borrowers post less real value than the protocol believes it holds, letting them borrow more than their collateral is actually worth against other vaults (STX, sBTC, USDC, USDH), directly threatening protocol solvency and creating bad debt risk when the mismatch is later realized (e.g., at liquidation or on redemption) — this lands squarely in the "protocol insolvency" Critical/High impact class from unpriced collateral overvaluation.

### Likelihood Explanation
This is not an attacker-triggered exploit requiring special preconditions — it is a structural mispricing baked into the oracle configuration and price-computation code that is active for every valuation of `stSTXbtc`/`zstSTXbtc` collateral in health checks, borrowing, and liquidation math. Any ordinary user who supplies `stSTXbtc` as collateral benefits (or the protocol suffers) whenever the wrapper's true exchange rate to STX departs even slightly from 1:1, which is expected over time for a yield-bearing wrapper token.

### Recommendation
Query the actual stSTXbtc exchange rate (analogous to `call-ststx-ratio`/`resolve-ststx`) from the stSTXbtc contract (or an appropriate rate oracle) and apply it as a callcode transformation before using the raw STX price, exactly as is already done for `stSTX`/`zstSTX`. Do not rely on the assumption that 1 stSTXbtc == 1 STX.

### Proof of Concept
Not directly executable from the indexed contract set (the underlying `ststxbtc-token-v2` contract's actual exchange-rate/redemption function is external/mainnet-only and not available in this repo, per `;; @mainnet:` comments referencing `'SP4SZE494VC2YC5JYG7AYFQ44F5Q4PYV7DVMDPBG.ststxbtc-token-v2`) [8](#0-7) . The root-cause code path (oracle registration with `callcode: none` and hardcoded `get-pyth-price PYTH-STX` for `stSTXbtc`) is confirmed directly in-repo as cited above; a full PoC demonstrating the actual magnitude of stSTXbtc/STX rate drift would require the external stSTXbtc contract's real exchange-rate history, which is outside indexed contents.

(define-private (resolve-ztoken (p uint) (aid uint))
  (let ((cached (unwrap! (get-cached-indexes aid) ERR-ORACLE-CALLCODE))
        (cached-lindex (get lindex cached))
        (scaled (* p cached-lindex)))
    (ok (div-down scaled INDEX-PRECISION))))

(define-private (resolve-callcode (p uint) (callcode (optional (buff 1))))
  (let ((cc (unwrap! callcode (ok p))))
    (if (is-eq cc CALLCODE-STSTX) (resolve-ststx p)
    (if (is-eq cc CALLCODE-ZSTX) (resolve-ztoken p STX)
    (if (is-eq cc CALLCODE-ZSBTC) (resolve-ztoken p sBTC)
    (if (is-eq cc CALLCODE-ZSTSTX) (resolve-ztoken (try! (resolve-ststx p)) stSTX)
    (if (is-eq cc CALLCODE-ZUSDC) (resolve-ztoken p USDC)
    (if (is-eq cc CALLCODE-ZUSDH) (resolve-ztoken p USDH)
    (if (is-eq cc CALLCODE-ZSTSTXBTC) (resolve-ztoken p stSTXbtc)
