### Title
Unauthenticated stage-1 handshake packets force full Noise/cert-verification cost with no rate limiting - (File: handshake_manager.go)

### Summary
`HandshakeManager.HandleIncoming` → `beginHandshake` in `handshake_manager.go` accepts any UDP packet claiming to be a stage-1 (`MessageCounter == 1`) handshake and, after only cheap header/allow-list checks, always constructs a new `handshake.Machine` and runs the full Noise `ReadMessage` plus certificate verification path via `machine.ProcessPacket`. This is analogous to the reported Story bug class: functions reachable by an unauthenticated caller that trigger expensive backend/consensus-layer work with no cost-gating (`chargeFee`) or rate limiting, allowing cheap spam of expensive resource consumption.

### Finding Description
`beginHandshake` is invoked directly from `HandshakeManager.HandleIncoming` for every inbound packet whose header decodes as `header.Handshake`/`header.HandshakeIXPSK0` with `MessageCounter == 1` and `RemoteIndex == 0`: [1](#0-0) 

The only gating before the expensive path is:
1. subtype check,
2. an optional `remote_allow_list` IP check (skipped entirely for relayed packets), and
3. `RemoteIndex == 0`.

None of these require possession of a CA-signed certificate — they are pure header/IP checks that an attacker fully controls (spoofable subtype/fields, and for relayed traffic the allow-list check is bypassed altogether): [2](#0-1) 

Once past these checks, `beginHandshake` unconditionally allocates a new `handshake.Machine` and calls `machine.ProcessPacket`, which performs Noise Diffie-Hellman/AEAD operations (`m.hs.ReadMessage`) and certificate reconstruction/verification (`m.processPayload` / `CertVerifier`) — the expensive cryptographic work — before any peer identity has been established: [3](#0-2) [4](#0-3) 

Because certificate/identity verification only happens as a side effect of processing the message (`remoteCert := result.RemoteCert`, `hm.validatePeerCert`), a peer with no valid CA-signed certificate can send arbitrary garbage stage-1 packets and force the responder to run the full crypto/verification pipeline on each one, since the entry point commits to this work before any authentication succeeds: [5](#0-4) 

There is no rate limiter, per-source cookie/proof-of-work challenge, or per-IP budget anywhere in `HandshakeManager` guarding this path (confirmed by the absence of any rate/limiter/cookie logic in `handshake_manager.go`), so the cost of each spoofed handshake attempt is asymmetric: trivial to send, expensive to process.

### Impact Explanation
An attacker with no valid Nebula certificate — i.e., someone who has never joined the mesh and holds no CA-signed cert — can send a stream of forged stage-1 handshake UDP packets to any reachable Nebula node. Each packet forces the target to perform Noise handshake state-machine setup and cryptographic operations (`ReadMessage`), consuming CPU that would otherwise service legitimate handshakes and traffic. This directly parallels the "spamming the CL" impact in the reported bug — cheap-to-send but costly-to-process calls with no fee/cost gate — resulting in denial-of-service / resource exhaustion on the target node, matching the reported severity class (`AC:L/AX:L ... A:H`, availability impact, no confidentiality/integrity impact).

### Likelihood Explanation
High. No secret material, valid certificate, or prior handshake state is required to reach `beginHandshake` — only a correctly shaped header (`Type=Handshake`, `Subtype=HandshakeIXPSK0`, `MessageCounter=1`, `RemoteIndex=0`) is needed, all of which are attacker-controlled and easily crafted from any UDP-reachable host (or via a relay, which additionally skips the allow-list check).

### Recommendation
Add a lightweight, pre-crypto cost gate to `HandleIncoming`/`beginHandshake` for stage-1 packets, analogous to adding the missing `chargeFee` modifier in the Story fix — e.g., a per-source-IP token-bucket rate limiter, or a stateless retry/cookie mechanism (as used by other Noise-based protocols such as WireGuard's cookie-reply-under-load) that must be satisfied before committing to `handshake.NewMachine`/`ProcessPacket`, so unauthenticated peers cannot force expensive crypto+cert-verification work at will.

### Proof of Concept
1. From a host with no CA-signed certificate for the target mesh, craft raw UDP packets with a valid Nebula header: `Type = header.Handshake`, `Subtype = header.HandshakeIXPSK0`, `MessageCounter = 1`, `RemoteIndex = 0`, followed by arbitrary/garbage Noise payload bytes.
2. Send a high-rate flood of these packets to the target node's listen port.
3. Observe that each packet reaches `HandshakeManager.beginHandshake` (per `handshake_manager.go:151-185, 701-726`), which allocates a `handshake.Machine` and executes `ProcessPacket`/`ReadMessage` for every packet regardless of validity, consuming CPU with no rate limit or per-source cost accounting — reproducing the "spam without cost" condition described in the source report.

func (hm *HandshakeManager) HandleIncoming(via ViaSender, packet []byte, h *header.H) {
	// Gate on known handshake subtypes. Unknown subtypes (or future ones we
	// don't yet support) are dropped here rather than silently routed through
	// the IX path. Add a case when introducing a new pattern.
	switch h.Subtype {
	case header.HandshakeIXPSK0:
		// supported
	default:
		hm.l.Debug("dropping handshake with unsupported subtype",
			"from", via, "subtype", h.Subtype)
		return
	}

	// First remote allow list check before we know the vpnIp
	if !via.IsRelayed {
		if !hm.lightHouse.GetRemoteAllowList().AllowUnknownVpnAddr(via.UdpAddr.Addr()) {
			hm.l.Debug("lighthouse.remote_allow_list denied incoming handshake", "from", via)
			return
		}
	}

	// First message of a new handshake. The wire format requires RemoteIndex
	// to be zero here (the initiator has no responder index to fill in yet),
	// and generateIndex never allocates 0, so any non-zero RemoteIndex on a
	// stage-1 packet is malformed or someone probing for an index collision.
	// Drop without paying the cost of running noise on a pending Machine.
	if h.MessageCounter == 1 {
		if h.RemoteIndex != 0 {
			hm.l.Debug("dropping stage-1 handshake with non-zero RemoteIndex",
				"from", via, "remoteIndex", h.RemoteIndex)
			return
		}
		hm.beginHandshake(via, packet, h)
		return
	}

func (hm *HandshakeManager) beginHandshake(via ViaSender, packet []byte, h *header.H) {
	f := hm.f
	cs := f.pki.getCertState()

	v := cs.DefaultVersion()
	if cs.GetCredential(v) == nil {
		f.l.Error("Unable to handshake with host because no certificate is available",
			"from", via, "certVersion", v)
		return
	}

	machine, err := handshake.NewMachine(
		v, cs.GetCredential,
		hm.certVerifier(), func() (uint32, error) { return generateIndex(f.l) },
		false, header.HandshakeIXPSK0,
	)
	if err != nil {
		f.l.Error("Failed to create handshake machine", "from", via, "error", err)
		return
	}

	response, result, err := machine.ProcessPacket(nil, packet)
	if err != nil {
		f.l.Error("Failed to process handshake packet", "from", via, "error", err)
		return
	}

func (m *Machine) ProcessPacket(out, packet []byte) ([]byte, *Result, error) {
	if m.failed {
		return nil, nil, ErrMachineFailed
	}
	if len(packet) < header.Len {
		return nil, nil, ErrPacketTooShort
	}
	// Reject packets whose subtype doesn't match the one this Machine was
	// built for. A pending handshake that suddenly receives a different
	// subtype on its index is either a stray packet that matched by chance
	// or a peer protocol violation; drop it without failing the Machine so
	// the legitimate retransmit can still complete.
	if header.MessageSubType(packet[1]) != m.subtype {
		return nil, nil, ErrSubtypeMismatch
	}
	if m.result.Initiator && m.hs.MessageIndex() == 0 {
		m.failed = true
		return nil, nil, ErrInitiateNotCalled
	}

	// The (eKey, dKey) ordering here is correct for IX, where the initiator
	// completes the handshake by reading the responder's stage-2 message.
	// noise returns (cs1, cs2) where cs1 is the initiator->responder cipher.
	// For 3-message patterns where a responder finishes by reading the final
	// message, this ordering would be wrong; revisit when XX/pqIX lands.
	msg, eKey, dKey, err := m.hs.ReadMessage(nil, packet[header.Len:])
	if err != nil {
		// Noise ReadMessage failed. The noise library checkpoints and rolls back
		// on failure, so the Machine is still alive. The caller can retry with
		// a different packet.
		return nil, nil, fmt.Errorf("noise ReadMessage: %w", err)
	}

	// From here on, noise state has advanced. Any error is fatal.
	flags := m.peerMsgFlags()

	if err := m.processPayload(msg, flags); err != nil {
		return nil, nil, err
	}
