The strongest and most concrete "no access control before performing a destructive action" analog in this codebase is `Interface.handleRecvError` in `outside.go`.

### Title
Unauthenticated `RecvError` packet allows remote tunnel teardown / DoS via guessable index and spoofable source address - ([File: outside.go])

### Summary
`RecvError` packets are processed by `Interface.readOutsidePackets` before any cryptographic verification of the sender takes place, and `handleRecvError` tears down an active tunnel (`f.closeTunnel(hostinfo)` + `f.handshakeManager.DeleteHostInfo(hostinfo)`) based only on a 32-bit `RemoteIndex` lookup and a loose source-address comparison, with no proof that the sender possesses a valid certificate or Noise session key for that tunnel.

### Finding Description
In `readOutsidePackets`, `header.RecvError` is dispatched immediately in the "Unencrypted packets" switch, prior to any handshake or decryption step: [1](#0-0) 

`handleRecvError` then looks the tunnel up purely by `h.RemoteIndex` (a value carried in the clear in every packet header on the wire) and validates the sender only by comparing the observed source `netip.AddrPort` against the tunnel's currently known remote — a check that is bypassed entirely if the tunnel's remote is not yet marked valid, and otherwise only requires matching a spoofable UDP source address: [2](#0-1) 

No certificate, Noise handshake, or AEAD-authenticated proof is required to trigger `closeTunnel`/`DeleteHostInfo` — this mirrors the root cause of the referenced report: an operation with real state-changing impact on a victim's session is reachable by any attacker who can supply an identifier associated with the victim (there, a receiver address for `deposit`/`mint`; here, the victim's `RemoteIndex` and endpoint address), without any check that the caller is the legitimate counterparty.

### Impact Explanation
An attacker with no CA-signed certificate — someone who is neither an authenticated Nebula peer nor a lighthouse — can force termination of any live tunnel between two legitimate nodes if they can (a) observe the target's `RemoteIndex` (trivial: it is sent unencrypted in the header of every handshake/data packet crossing the path, so any on-path observer, or anyone who can see even one packet, learns it) and (b) send a UDP packet appearing to originate from the peer's known remote address (UDP source-address spoofing is possible on many networks lacking egress/ingress filtering, and is trivially satisfied whenever the target hostinfo's remote has not yet been confirmed, since the check is skipped when `hr.IsValid()` is false). This yields a remote, unauthenticated DoS that repeatedly severs tunnels, forcing costly re-handshakes and disrupting connectivity — a direct parallel to the front-running DoS in the original finding, where lack of access control let an attacker cheaply disrupt another user's legitimate operation.

### Likelihood Explanation
Rate limiting exists via `f.acceptRecvErrorConfig.ShouldRecvError(addr)` [3](#0-2) , which reduces (but does not eliminate) repeat abuse from the same source address, and the sender address check partially mitigates blind off-path spoofing once a remote is established. However, the underlying design gap — accepting a destructive, state-changing signal with no cryptographic authentication, keyed only off a value that travels in cleartext — remains a legitimate, reachable weakness for on-path attackers, attackers who can observe traffic, or attackers on networks without BCP38 filtering, all of whom hold no valid Nebula certificate.

### Recommendation
Require cryptographic authentication before acting on `RecvError` (e.g., only accept it embedded in an AEAD-authenticated message tied to the session, or require a fresh authenticated handshake/challenge before tearing down state), rather than relying solely on index lookup plus a soft source-address match. At minimum, tighten `handleRecvError` so it never proceeds when `hr.IsValid()` is false, and consider requiring corroborating evidence (e.g., a valid, recent message counter) before calling `closeTunnel`.

### Proof of Concept
1. Passively observe a single packet (or the handshake) between victim nodes A and B to learn A's `RemoteIndex` value for the A→B tunnel (sent in cleartext in the header of every packet, per `header.Encode`).
2. Craft a `header.RecvError` packet with that `RemoteIndex`, per the format used in `sendRecvError`: [4](#0-3) 
3. Send it to A's UDP listener with a spoofed source address equal to B's endpoint (or, if A's remote for that hostinfo is not yet confirmed, from any address).
4. A's `handleRecvError` finds the hostinfo via `QueryReverseIndex`, passes the address check (or skips it), and calls `f.closeTunnel(hostinfo)` plus `f.handshakeManager.DeleteHostInfo(hostinfo)`, tearing down the tunnel without any proof the packet came from an authenticated peer.

func (f *Interface) sendRecvError(endpoint netip.AddrPort, index uint32) {

func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
