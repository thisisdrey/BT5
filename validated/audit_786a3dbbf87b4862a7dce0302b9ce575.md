## Title
No validation of client-supplied `GitObjectDirectory`/`GitAlternateObjectDirectories` fields before being used to construct Git's object-directory environment - (File: internal/git/gitcmd/command_factory.go)

### Summary
`gitalypb.Repository` exposes two fields, `GitObjectDirectory` and `GitAlternateObjectDirectories`, that are meant to be populated only internally by Gitaly's own object-quarantine mechanism (or looped back from Rails after an access check tied to a specific pre-receive quarantine). However, these are ordinary, unauthenticated protobuf fields that any RPC caller can set on almost any `Repository` message sent to Gitaly. The path that actually uses these values to spawn Git subprocesses, `alternates.Env` invoked from `ExecCommandFactory.newCommand`, performs **no path validation** on them, unlike the dedicated `ObjectDirectoryPath` helper used by a handful of specific RPCs.

### Finding Description
Every Git command Gitaly spawns for a repository-scoped RPC goes through `ExecCommandFactory.newCommand`, which builds the object-directory environment like this: [1](#0-0) 

That in turn calls `alternates.Env`, which simply joins the caller-supplied strings onto the repository path with no bounds checking at all: [2](#0-1) 

There is no `..` traversal check, no absolute-path rejection, and no check that the resulting path stays inside the repository, the storage root, or even the machine's storage hierarchy. This is in sharp contrast with the *other* code path Gitaly has for handling the same fields, `localrepo.Repo.ObjectDirectoryPath`, which is used only by specific RPCs (e.g. `GetObjectDirectorySize`) and does perform careful validation — it requires the resolved path to stay inside the repository or to match the repository's own quarantine-temp-dir prefix: [3](#0-2) 

`storage.Locator.ValidateRepository`, which every accessor/mutator handler calls to validate the incoming `Repository` message, does not validate these two fields at all — it only checks `StorageName`/`RelativePath`: [4](#0-3) 

The transaction middleware is aware that these fields are supposed to originate only from Gitaly's own quarantine/Rails loop-back, as the comment states, but it only rejects the case where a **mutator** RPC carries them; an **accessor** RPC carrying them is simply treated as an already-quarantined request and run non-transactionally, without re-validating the object-directory path for escape: [5](#0-4) 

Because nearly every accessor RPC (blob/commit/ref/tree lookups, etc.) ultimately spawns a Git command via `ExecCommandFactory.newCommand`, and that code path never calls the validated `ObjectDirectoryPath`/`ValidateRelativePath` logic, an attacker who can call any such RPC directly (bypassing Rails/Workhorse, e.g. a client with direct Gitaly/Praefect network access, or any RPC where the fields are not stripped before being forwarded) can set `GitObjectDirectory` or `GitAlternateObjectDirectories` to `../<other-repo>/objects`, an absolute path, or any other filesystem location and have Git search that directory for objects on every subsequent invocation for that request.

This is analogous to the TBTC bug: a field/parameter that is only supposed to be populated by a privileged, controlled path (Rails' access-check callback / Gitaly's own quarantine setup, analogous to `DepositFactory`) is instead accepted from any caller with no enforcement that the value actually originated from that privileged flow, and the consuming code performs no defensive validation of its own.

### Impact Explanation
An attacker able to send a crafted `Repository` message (with `GitObjectDirectory`/`GitAlternateObjectDirectories` populated) to any accessor RPC that ends up spawning a Git subprocess through `ExecCommandFactory.newCommand` can:
- Redirect Git's object lookup to an arbitrary directory on the Gitaly host (`GIT_OBJECT_DIRECTORY`/`GIT_ALTERNATE_OBJECT_DIRECTORIES`), enabling cross-repository object access — reading loose objects/packs that belong to a completely unrelated repository on the same storage, which the strict validation in `ObjectDirectoryPath` was specifically designed to prevent for other RPCs.
- Potentially exfiltrate blob/commit/tree contents from repositories the caller has no authorization to access, since object retrieval RPCs (e.g., commit/blob read RPCs) would happily serve back objects found via the injected object directory.

### Likelihood Explanation
Likelihood depends on how much of the Repository message is sanitized before reaching Gitaly on typical GitLab-driven flows (Workhorse/Rails may not forward arbitrary client-supplied `git_object_directory`/`git_alternate_object_directories` fields), so exploitability is highest for callers with direct gRPC access to Gitaly/Praefect (e.g., other internal services, a compromised client with network reach, or any code path that forwards these Repository sub-fields from client input without stripping them). The inconsistency between the strict validation in `localrepo.Repo.ObjectDirectoryPath` and the complete absence of validation in `alternates.Env`/`ExecCommandFactory.newCommand` demonstrates the project itself intended for these fields to be validated, but missed enforcing it uniformly on the actual command-spawning path.

### Recommendation
Apply the same relative-path/escape validation used in `localrepo.Repo.ObjectDirectoryPath` (or equivalent `storage.ValidateRelativePath` checks against both the repository path and the storage root, plus quarantine-prefix checks) inside `alternates.Env`/`ExecCommandFactory.newCommand` before using `GitObjectDirectory`/`GitAlternateObjectDirectories` to build the Git process environment, so that these fields cannot cause Git to search directories outside of the repository or a legitimately-provisioned quarantine directory, regardless of which RPC is being invoked.

### Proof of Concept
Not independently executed; based on static code review: an accessor RPC (e.g., any `CommitService`/`RefService`/`BlobService` RPC) invoked with a `Repository{StorageName: "default", RelativePath: "victim.git", GitAlternateObjectDirectories: ["../other-repo.git/objects"]}` would cause `ExecCommandFactory.newCommand` to set `GIT_ALTERNATE_OBJECT_DIRECTORIES=<storage>/victim.git/../other-repo.git/objects` via `alternates.Env`, with no rejection, letting the spawned Git process resolve/read objects belonging to `other-repo.git`.

// Env returns the alternate object directory environment variables.
func Env(repoPath, objectDirectory string, alternateObjectDirectories []string) []string {
	var env []string
	if objectDirectory != "" {
		env = append(env, fmt.Sprintf("GIT_OBJECT_DIRECTORY=%s", filepath.Join(repoPath, objectDirectory)))
	}

	if len(alternateObjectDirectories) > 0 {
		var dirsList []string

		for _, dir := range alternateObjectDirectories {
			dirsList = append(dirsList, filepath.Join(repoPath, dir))
		}

		env = append(env, fmt.Sprintf("GIT_ALTERNATE_OBJECT_DIRECTORIES=%s", strings.Join(dirsList, ":")))
	}

	return env
}

// ObjectDirectoryPath returns the full path of the object directory. The errors returned are gRPC
// errors with relevant error codes and should be passed back to gRPC without further decoration.
func (repo *Repo) ObjectDirectoryPath(ctx context.Context) (string, error) {
	repoPath, err := repo.Path(ctx)
	if err != nil {
		return "", err
	}

	objectDirectoryPath := repo.GetGitObjectDirectory()
	if objectDirectoryPath == "" {
		return "", structerr.NewInvalidArgument("object directory path is not set")
	}

	storagePath, err := repo.locator.GetStorageByName(ctx, repo.GetStorageName())
	if err != nil {
		return "", fmt.Errorf("get storage by name: %w", err)
	}

	// Ensure the path points somewhere in the storage.
	relativeObjectDirectoryPath, err := storage.ValidateRelativePath(storagePath, filepath.Join(repoPath, objectDirectoryPath))
	if err != nil {
		return "", structerr.NewInvalidArgument("validate relative path: %w", err)
	}

	parentDir := filepath.Base(filepath.Dir(relativeObjectDirectoryPath))
	baseDir := filepath.Base(relativeObjectDirectoryPath)
	isTransactionQuarantineDir := (baseDir == "quarantine") || ((parentDir == "quarantine") && strings.HasPrefix(baseDir, "tmp_objdir"))

	// Transactions quarantine a repository by pointing the object directory to a 'quarantine' named
	// directory in the transaction's temporary directory. If the base directory is `quarantine`,
	// Git push may apply an additional layer of quarantine such as `/quarantine/tmp_objdir-incoming-Gbc29N`
	// so we don't assert the `/quarantine` being the last element of the path. We thus also check for
	// whether the parent directory is in `quarantine` and whether the base directory has the expected
	// `tmp_objdir` suffix.
	if !isTransactionQuarantineDir {
		// We need to check whether the relative object directory as given by the repository is
		// a valid path. This may either be a path in the Git repository itself, where it may either
		// point to the main object directory storage or to an object quarantine directory as
		// created by git-receive-pack(1). Alternatively, if that is not the case, then it may be a
		// manual object quarantine directory located in the storage's temporary directory. These
		// have a repository-specific prefix which we must check in order to determine whether the
		// quarantine directory does in fact belong to the repo at hand.
		if _, origError := storage.ValidateRelativePath(repoPath, objectDirectoryPath); origError != nil {
			tempDir, err := repo.locator.TempDir(repo.GetStorageName())
			if err != nil {
				return "", structerr.NewInvalidArgument("getting storage's temporary directory: %w", err)
			}

			expectedQuarantinePrefix := filepath.Join(tempDir, storage.QuarantineDirectoryPrefix(repo))
			absoluteObjectDirectoryPath := filepath.Join(repoPath, objectDirectoryPath)

			// The relative path is outside of the repository
			if !strings.HasPrefix(absoluteObjectDirectoryPath, expectedQuarantinePrefix) {
				return "", structerr.NewInvalidArgument("not a valid relative path: %w", origError)
			}
		}
	}

	fullPath := filepath.Join(repoPath, objectDirectoryPath)
	if _, err := os.Stat(fullPath); os.IsNotExist(err) {
		return "", structerr.NewNotFound("object directory does not exist: %q", fullPath)
	}

	return fullPath, nil
}
