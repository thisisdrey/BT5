### Title
RewardsDistributor credits accounts the full `INITIAL_INDEX` delta, letting an attacker drain the entire reward-token balance - ([File: contracts/RewardsDistributor.sol](contracts/RewardsDistributor.sol))

### Summary
CVE-2015-3193 is a math-implementation bug where arithmetic produces a silently wrong output. The Metronome analog is in `RewardsDistributor._calculateTokenDelta`: the guard that initializes a fresh account's index uses a strict `>` comparison against `INITIAL_INDEX`, so while a token's global index still equals `INITIAL_INDEX` (the window between `updateTokenSpeed` adding the token and the first index accrual), an account with `accountIndex == 0` gets `_deltaIndex = INITIAL_INDEX` instead of `0`, producing a wildly incorrect accrual equal to the account's full deposit/debt token balance.

### Finding Description
When the governor enables rewards for a token, `_updateTokenSpeed` stores `TokenState({index: INITIAL_INDEX, timestamp: now})` where `INITIAL_INDEX = 1e18` [1](#0-0) . Any later call into `claimRewards` / `updateBeforeMintOrBurn` / `updateBeforeTransfer` (all callable by anyone or triggered by normal token transfers/mints) reaches `_calculateTokenDelta` [2](#0-1) :

```solidity
if (_accountIndex == 0 && _tokenIndex > INITIAL_INDEX) {
    _accountIndex = INITIAL_INDEX;
}
uint256 _deltaIndex = _tokenIndex - _accountIndex;
_tokensDelta = token_.balanceOf(account_).wadMul(_deltaIndex);
```

Because the check is `>` rather than `>=`, when `_tokenIndex == INITIAL_INDEX` (e.g., same block as `updateTokenSpeed`, or before `delta * speed / totalSupply` produces a nonzero ratio) the fallback never applies, `_accountIndex` stays `0`, and `_deltaIndex = 1e18`. `wadMul(balance, 1e18) = balance`, so the account is credited `tokensAccruedOf[account] = balance` — one reward unit per wei of deposit-token balance [3](#0-2) . `claimRewards` then pays out `min(accrued, rewardToken.balanceOf(this))` via `_transferRewardIfEnoughTokens` [4](#0-3) .

### Impact Explanation
An unprivileged attacker holding any amount of a reward-enabled DepositToken (deposited before the token was added) can call the public `claimRewards(attacker, [depositToken])` in the same block the governor enables rewards, or before the global index first increases. The incorrect delta credits them `balance` reward tokens, and the transfer empties the distributor's reward balance — direct theft of unclaimed yield belonging to all suppliers/borrowers. The attacker can size their deposit so the credited amount exactly fits the contract balance.

### Likelihood Explanation
The trigger requires acting while the global index is still exactly `INITIAL_INDEX`. `updateTokenSpeed`/`updateTokenSpeeds` transactions are visible in the mempool, and an attacker can back-run them in the same block (`_deltaTimestamps == 0` means `_updateTokenIndex` writes nothing, keeping index at `INITIAL_INDEX`) [5](#0-4) . Even in later blocks, if `speed` or elapsed time is small enough that `_ratio` rounds to 0, the window persists. No privileged role, oracle manipulation, or malicious infrastructure is needed — just a deposit-token balance and one public call.

### Recommendation
Change the initialization guard in `_calculateTokenDelta` to cover the boundary: `if (_accountIndex == 0 && _tokenIndex >= INITIAL_INDEX) _accountIndex = INITIAL_INDEX;` or equivalently set `_accountIndex = _tokenIndex` (or `INITIAL_INDEX`) whenever it is 0, since `tokenStates[token_].index == 0` paths are already filtered by callers. Add a test where an account with an existing balance is updated while `index == INITIAL_INDEX` and assert `tokensDelta == 0`.

### Proof of Concept
```typescript
// Hardhat, fork or unit-test setup with a real DepositToken + RewardsDistributor
it("drains reward balance via INITIAL_INDEX delta", async () => {
  // setup: pool, depositToken (msdMET), rewardsDistributor with rewardToken funding
  await depositToken.connect(alice).deposit(parseEther("100"), alice.address); // before rewards enabled
  await rewardToken.mint(rewardsDistributor.address, parseEther("1000"));

  // governor enables rewards; index = INITIAL_INDEX = 1e18, timestamp = now
  await rewardsDistributor.connect(governor).updateTokenSpeed(depositToken.address, 1);

  // same block: attacker (alice) claims. index == INITIAL_INDEX => deltaIndex = 1e18
  const tx = rewardsDistributor.claimRewards(alice.address, [depositToken.address]);
  await expect(tx).to.emit(rewardsDistributor, "RewardClaimed")
    .withArgs(alice.address, parseEther("100")); // credited full balance, not ~0
});
```
