This maps well onto the described bug class: an unauthenticated action that trusts external input (an address / index) to mutate protected state, without any cryptographic membership check tying that input to an already-verified identity.

### Title
Unauthenticated `RecvError` control packets allow remote tunnel teardown via a weak address-trust check - (`outside.go`)

### Summary
`ControllerFactory.set_debt_ceiling` mints stablecoins to an arbitrary address with no check that the address belongs to the authorized set (Controllers/PegKeepers). The nebula analog is `Interface.handleRecvError`, which mutates protected tunnel state (tearing down an established, cert-authenticated session) based on an unauthenticated, unencrypted `header.RecvError` packet, gated only by a UDP source-address equality check that has no cryptographic binding to the sender's identity — the same "trust an externally supplied input without verifying its membership in the authorized set" pattern.

### Finding Description
`RecvError` packets are processed before any decryption or handshake authentication — they are handled in the unencrypted-packet switch in `readOutsidePackets` alongside `Handshake` packets: [1](#0-0) 

`handleRecvError` looks up the hostinfo purely from the attacker-supplied `RemoteIndex` field of the packet header via `QueryReverseIndex`, and the only "authorization" check performed is that the packet's source `AddrPort` matches the currently known remote for that hostinfo: [2](#0-1) 

```go
hr := hostinfo.GetRemote()
if hr.IsValid() && hr != addr {
    f.l.Info("Someone spoofing recv_errors?", ...)
    return
}
f.closeTunnel(hostinfo)
f.handshakeManager.DeleteHostInfo(hostinfo)
```

This check is not a cryptographic proof of identity — it is a plain comparison of the packet's UDP source `netip.AddrPort` against a value that (a) can be spoofed on UDP by an off-path attacker, and (b) is `!hr.IsValid()` for hosts that have no remote set yet, in which case the check is skipped entirely. There is no verification that the sender is the actual authenticated peer (no cert, no handshake, no MAC/AEAD check) — exactly like `set_debt_ceiling` trusting a caller-supplied address without checking it against the authorized Controller/PegKeeper set. The only gating value, `RemoteIndex`, is a 32-bit locally-allocated index and is disclosed in-the-clear on outgoing traffic, making it discoverable to a passive on-path observer or brute-forceable by an attacker who has no valid certificate at all.

The changelog corroborates this control message's known-weak trust model, e.g. `Valid recv_error packets were incorrectly marked as spoofing and ignored (#482)` and `Disable sending recv_error messages when a packet is received outside the allowable counter window (#1459)`, both underscoring that `RecvError` handling has been a source of prior spoofing/trust issues: [3](#0-2) [4](#0-3) 

### Impact Explanation
An attacker with no CA-signed certificate and no established tunnel can forge a single unauthenticated `RecvError` UDP packet (spoofing the victim's known peer's source address, and guessing/observing the `RemoteIndex`) to force `f.closeTunnel(hostinfo)` and `f.handshakeManager.DeleteHostInfo(hostinfo)` on the target, tearing down an already-authenticated tunnel. This is a remote state-poisoning / denial-of-service primitive reachable purely from the network, requiring no cryptographic material — matching the "admin trusts unchecked address" bug class's core weakness: a privileged/stateful action gated by data that isn't cryptographically tied to an authorized identity.

### Likelihood Explanation
Likelihood is constrained by needing to know/guess a valid `RemoteIndex` and spoof the current remote `AddrPort`, both of which are feasible for a network-adjacent or on-path attacker (UDP source spoofing is well known to be trivial for many network positions), and by default `send_recv_error`/`accept_recv_error` settings which are enabled unless explicitly restricted via `listen.send_recv_error`/`listen.accept_recv_error`.

### Recommendation
Require `RecvError` to be authenticated the same way other post-handshake control traffic is (e.g., MAC/AEAD-protected using the tunnel's derived keys, or discard `RecvError` entirely if it cannot be tied to a valid `ConnectionState`), rather than relying on a raw source-address equality check. At minimum, treat `RecvError` teardown as a hint that must be corroborated by other signals (e.g., no valid traffic within X seconds) instead of acting immediately on a bare unauthenticated UDP packet.

### Proof of Concept
1. Attacker observes (or on-path sniffs) traffic between `me` and `them`, learning `them`'s current `RemoteIndex` value used by `me` (visible in cleartext in header fields of ordinary traffic) and `me`'s current UDP `AddrPort`.
2. Attacker crafts a `header.RecvError` packet with `RemoteIndex` set to the observed index, sourced (spoofed) from `me`'s `AddrPort`, and sends it to `them`.
3. `them.handleRecvError` finds the hostinfo via `QueryReverseIndex(h.RemoteIndex)`, the address check passes because the spoofed source matches the stored remote, and `them` tears down the tunnel via `f.closeTunnel(hostinfo)` and deletes handshake state — a full unauthenticated remote tunnel-teardown, as demonstrated conceptually by the checked-in `TestCloseTunnelAuthenticated` test that exercises the analogous bogus `CloseTunnel` packet path ( [5](#0-4) ) — but for `RecvError` there is no per-hostinfo authenticated MAC at all, so the equivalent spoof succeeds instead of being rejected.

func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
