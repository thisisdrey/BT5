Audit Report

## Title
Reward payout marks era page as claimed even when the underlying token transfer to the payee silently fails, permanently losing staker/validator rewards - (File: `substrate/frame/staking-async/src/pallet/impls.rs`)

## Summary
`do_payout_stakers_by_page` calls `Eras::<T>::set_rewards_as_claimed(era, &stash, page)` unconditionally near the start of the function, before any reward transfers are attempted, and the subsequent `Currency::transfer` calls inside `make_payout_from_provider` and `transfer_validator_incentive` swallow failures (logging and emitting an `Unexpected`/`ValidatorIncentiveTransferFailed` event) instead of propagating a `DispatchError`. The extrinsic thus always succeeds and the page/era is permanently marked claimed regardless of whether any individual payee actually received their transfer.

## Finding Description
`do_payout_stakers_by_page` marks the page claimed via `Eras::<T>::set_rewards_as_claimed(era, &stash, page)` and then proceeds to compute and distribute payouts. When using the non-minting path (`use_dap_payout`), `payout_from_provider` loops over the validator and every nominator, calling `make_payout_from_provider`. That function performs `T::Currency::transfer(&staker_rewards_pot, &payout_account, amount, Preservation::Expendable)`; on error it only logs and returns `None`, giving the caller no way to distinguish "reward was zero/opted out" from "transfer failed." `transfer_validator_incentive` follows the identical pattern for the validator's incentive pot. Neither failure aborts the extrinsic, and `do_payout_stakers_by_page`/`Ok(...)` is returned unconditionally. Because `Preservation::Expendable` is used, a transfer to a payee account that would end up below the existential deposit (e.g., a reaped account or dust reward) fails outright rather than partially crediting, which is a predictable, unprivileged failure mode reachable by anyone calling the public `payout_stakers`/`payout_stakers_by_page` extrinsics. Since `ClaimedRewards` was already committed before the transfer executes, the affected (era, validator, page) can never be retried, and the un-transferred balance remains in the era's reward pot until it is eventually swept via `EraRewardManager::drain` to `T::UnclaimedRewardHandler`, never reaching the rightful payee.

## Impact Explanation
This is an unbacked, unrecoverable loss of legitimately earned staking rewards for any payee whose account cannot currently accept the exact transfer amount under `Preservation::Expendable` (e.g., dust amounts to a fully reaped account). The page is irreversibly marked claimed so the payout can never be retried, and the stranded funds are ultimately redirected away from the rightful beneficiary to `UnclaimedRewardHandler` once `HistoryDepth` expires. This matches the required pivot that "payout state must only advance after ... settlement succeed[s] atomically" and the impact gate for permanent user-fund loss.

## Likelihood Explanation
No privileged access, governance action, or malicious behavior is required. Ordinary account-lifecycle conditions common in a live staking system (small/dust nominator rewards, reaped accounts, accounts with zero provider references) trigger the failure. The affected extrinsics (`payout_stakers`, `payout_stakers_by_page`) are public and callable by anyone for any eligible era/validator/page, making the condition easily and repeatedly reproducible.

## Recommendation
Do not call `set_rewards_as_claimed` until settlement of all transfers in the page has been confirmed, or propagate transfer failures from `make_payout_from_provider`/`transfer_validator_incentive` as a `DispatchError` that aborts the extrinsic (reverting the claimed-state write) instead of silently swallowing them. Alternatively, retain a per-payee "pending"/"failed" record enabling a future retry or dedicated withdrawal instead of unconditionally sweeping the leftover pot balance via `EraRewardManager::drain`.

## Proof of Concept
1. Let nominator stash `S`'s `RewardDestination::Account(A)` reference account `A` with zero free balance and zero provider references (fully reaped).
2. Let `S`'s prorated `nominator_reward` for era `E`/page `P` be below the existential deposit.
3. Call `payout_stakers_by_page(validator_stash, E, P)` as any signed account.
4. `do_payout_stakers_by_page` calls `Eras::<T>::set_rewards_as_claimed(E, &validator_stash, P)` at line 386, then proceeds to `payout_from_provider` → `make_payout_from_provider`, whose `T::Currency::transfer(..., Preservation::Expendable)` fails because crediting `A` below ED with no providers is rejected.
5. The error is logged; no `Rewarded` event is emitted for `A`; the extrinsic still returns `Ok(...)`.
6. `ClaimedRewards` for `(E, validator_stash, P)` is permanently set — the page can never be paid out again — while `nominator_reward` remains stranded in the era pot until `EraRewardManager::drain` eventually diverts it to `T::UnclaimedRewardHandler`, never reaching `A`.
