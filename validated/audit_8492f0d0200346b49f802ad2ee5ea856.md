### Title
Deleting an account leaves its `PromiseYieldReceipt`/`PromiseYieldStatus`/yield-id-mapping trie entries intact, letting a stale self-authenticated `FunctionCall` fire against whatever contract later occupies that account id - (File: runtime/runtime/src/actions.rs, core/store/src/utils/mod.rs, runtime/runtime/src/lib.rs)

### Finding Description
`promise_yield_create` (`runtime/vm-runner` logic, wired through `ext.rs::create_promise_yield_receipt`, `runtime/runtime/src/ext.rs:353-369`) writes a `TrieKey::PromiseYieldReceipt{receiver_id, data_id}` (the parked `FunctionCall` action receipt) and a `TrieKey::PromiseYieldStatus{receiver_id, data_id}` marker, and registers a global, index-keyed `TrieKey::PromiseYieldTimeout{index}` entry via `enqueue_promise_yield_timeout` (`core/store/src/utils/mod.rs:181-198`) containing `{account_id, data_id, expires_at}`.

`action_delete_account` (`runtime/runtime/src/actions.rs:314-391`) calls `remove_account` (`core/store/src/utils/mod.rs:505-575`) to wipe an account's state, but `remove_account` only removes `TrieKey::Account`, `ContractCode`, `AccessKey`/`GasKeyNonce`, and `ContractData` entries. It never removes `PromiseYieldReceipt`, `PromiseYieldStatus`, `YieldIdToDataId`/`DataIdToYieldId`, nor the global `PromiseYieldTimeout` queue entry pointing at that account.

Consequently, after `X` is deleted and later recreated (via `CreateAccount`), the stale parked receipt still exists at `TrieKey::PromiseYieldReceipt{X, data_id}`. When the yield's timeout eventually fires, `resolve_promise_yield_timeouts` (`runtime/runtime/src/lib.rs:3009-3104`) checks only `state_update.contains_key(&promise_yield_key, ...)` (`lib.rs:3051`) — with no check that the account is the same instance that created the yield — and, finding it present, synthesizes a `PromiseResume{data: None}` receipt destined to `X` (predecessor_id == receiver_id == X). This is delivered through `VersionedReceiptEnum::PromiseResume` in `process_receipt` (`lib.rs:1500-1568`), which looks up the still-present `PromiseYieldReceipt`, clears its bookkeeping, and executes the parked `FunctionCall` via `apply_action_receipt` against whatever account/contract currently exists at `X`. Since the parked receipt's `predecessor_id` was set to `account_id.clone()` at creation time (`runtime/runtime/src/function_call.rs:187-194`, i.e., the account that called `promise_yield_create`, which equals `X`), the resulting call arrives with `predecessor_id == receiver_id == X`, passing any `assert_self()`-style gate in whatever contract now occupies `X`, even though that contract's current owner never issued or authorized that call.

None of the existing checks (signature, nonce, access-key permission, receipt size/validation) address this because the call is synthesized entirely by the protocol's own timeout machinery from state the deletion path failed to purge; no attacker transaction is needed at the moment of exploitation.

### Impact Explanation
This is authorization escalation across "promise/account lifetime" boundaries: a `FunctionCall` chosen while an old contract occupied account `X` (with a chosen `method_name`/`args`) executes with self-call credentials against the new contract deployed at `X`, bypassing that new contract's `assert_self()`-gated admin logic without any action from the new deployer/owner. Depending on what admin method name collides, this can be used to corrupt or take over the new contract's state, matching NEAR's "authorization escalation across accounts/promises" bounty category, with potential for fund theft/freezing if the colliding method controls custody logic.

### Likelihood Explanation
The precondition is that account `X` is deleted and then recreated (by the same signer/subaccount owner, or via legitimate account-name transfer/reuse patterns) with a new contract before or after the pending yield's `yield_timeout_length_in_blocks` window elapses (timeout firing is automatic, no attacker transaction required at trigger time). Attacker cost is minimal: one `promise_yield_create` call, one `DeleteAccount`, one `CreateAccount`+`DeployContract` — all ordinary, unprivileged transactions. The main practical constraint is a method-name collision between the pre-deletion and post-recreation contracts' self-gated entrypoints, which narrows but does not eliminate real-world exploitability (e.g., common admin method names, or an attacker deliberately naming their new contract's method to match one they previously registered a yield against).

### Recommendation
When `remove_account` deletes an account, also purge any account-scoped yield state: iterate and remove `TrieKey::PromiseYieldReceipt{account_id, *}`, `TrieKey::PromiseYieldStatus{account_id, *}`, and `TrieKey::YieldIdToDataId`/`DataIdToYieldId` entries for that account, and mark any outstanding `PromiseYieldTimeout` queue entries for it as cancelled (e.g., by checking account existence, not just receipt-key presence, in `resolve_promise_yield_timeouts`, or by writing a tombstone at delete time that suppresses resume delivery for that account's yields).

### Proof of Concept
Integration/test-loop test spanning two `apply()` calls:
1. Create account `X`, deploy a contract exposing `call_yield_create_return_promise`-style logic that calls `promise_yield_create` targeting `X` itself with `method_name = "admin_reset"`.
2. Submit `DeleteAccount(X)` in the same or next chunk.
3. Submit `CreateAccount(X)` + `DeployContract` with a new contract exposing `admin_reset` gated by `predecessor_id() == receiver_id()` (self-only), which mutates a state flag when called.
4. Advance blocks past `yield_timeout_length_in_blocks`.
5. Assert: (a) `get_promise_yield_receipt`/`get_promise_yield_status` for `(X, data_id)` are still present in state immediately after step 2 (proving `remove_account` didn't clear them); (b) after the timeout fires and its `PromiseResume` receipt is applied, the new contract's `admin_reset` executed and mutated its state, despite the new deployer never calling it. pub fn enqueue_promise_yield_timeout(
    state_update: &mut TrieUpdate,
    promise_yield_indices: &mut PromiseYieldIndices,
    account_id: AccountId,
    data_id: CryptoHash,
    expires_at: BlockHeight,
) {
    set(
        state_update,
        TrieKey::PromiseYieldTimeout { index: promise_yield_indices.next_available_index },
        &PromiseYieldTimeout { account_id, data_id, expires_at },
    );
    promise_yield_indices.next_available_index = promise_yield_indices
        .next_available_index
        .checked_add(1)
        .expect("Next available index for PromiseYield timeout queue exceeded the integer limit");
}

/// Removes account, code and all access keys and gas keys associated to it.
pub fn remove_account(
    state_update: &mut TrieUpdate,
    account_id: &AccountId,
) -> Result<RemoveAccountResult, StorageError> {
    state_update.remove(TrieKey::Account { account_id: account_id.clone() });
    state_update.remove(TrieKey::ContractCode { account_id: account_id.clone() });

    let mut gas_key_nonce_count: usize = 0;
    let mut gas_key_nonce_total_key_bytes: usize = 0;

    // Removing access keys and gas key nonces
    let lock = state_update.trie().lock_for_iter();
    let mut keys_to_remove: Vec<TrieKey> = Vec::new();
    for raw_key in state_update
        .locked_iter(&trie_key_parsers::get_raw_prefix_for_access_keys(account_id), &lock)?
    {
        let raw_key = raw_key?;
        let key_handle = trie_key_parsers::parse_key_handle_from_access_key_key(
            &raw_key, account_id,
        )
        .map_err(|_e| {
            StorageError::StorageInconsistentState(
                "Can't parse key handle from raw key for AccessKey".to_string(),
            )
        })?;
        let nonce_index =
            trie_key_parsers::parse_nonce_index_from_gas_key_key(&raw_key, account_id, &key_handle)
                .map_err(|_e| {
                    StorageError::StorageInconsistentState(
                        "Can't parse nonce index from raw key for AccessKey".to_string(),
                    )
                })?;
        if let Some(index) = nonce_index {
            gas_key_nonce_count += 1;
            gas_key_nonce_total_key_bytes += raw_key.len();
            keys_to_remove.push(TrieKey::gas_key_nonce(
                account_id.clone(),
                key_handle.clone(),
                index,
            ));
        } else {
            keys_to_remove.push(TrieKey::access_key(account_id.clone(), key_handle.clone()));
        }
    }
    drop(lock);

    for trie_key in keys_to_remove {
        state_update.remove(trie_key);
    }

    // Removing contract data
    let lock = state_update.trie().lock_for_iter();
    let data_keys = state_update
        .locked_iter(&trie_key_parsers::get_raw_prefix_for_contract_data(account_id, &[]), &lock)?
        .map(|raw_key| {
            trie_key_parsers::parse_data_key_from_contract_data_key(&raw_key?, account_id)
                .map_err(|_e| {
                    StorageError::StorageInconsistentState(
                        "Can't parse data key from raw key for ContractData".to_string(),
                    )
                })
                .map(Vec::from)
        })
        .collect::<Result<Vec<_>, _>>()?;
    drop(lock);

    for key in data_keys {
        state_update.remove(TrieKey::ContractData { account_id: account_id.clone(), key });
    }
    Ok(RemoveAccountResult { gas_key_nonce_count, gas_key_nonce_total_key_bytes })
}

fn resolve_promise_yield_timeouts(
    processing_state: &mut ApplyProcessingReceiptState,
    receipt_sink: &mut ReceiptSink,
    compute_limit: u64,
) -> Result<ResolvePromiseYieldTimeoutsResult, RuntimeError> {
    let mut state_update = &mut processing_state.state_update;
    let total = &mut processing_state.total;
    let apply_state = &processing_state.apply_state;

    let mut promise_yield_indices: PromiseYieldIndices =
        get(state_update, &TrieKey::PromiseYieldIndices)?.unwrap_or_default();
    let initial_promise_yield_indices = promise_yield_indices.clone();
    let mut new_receipt_index: usize = 0;

    let mut processed_yield_timeouts = vec![];
    let yield_processing_start = std::time::Instant::now();
    while promise_yield_indices.first_index < promise_yield_indices.next_available_index {
        if total.compute >= compute_limit || state_update.trie.check_proof_size_limit_exceed() {
            break;
        }

        let queue_entry_key =
            TrieKey::PromiseYieldTimeout { index: promise_yield_indices.first_index };

        let queue_entry =
            get::<PromiseYieldTimeout>(state_update, &queue_entry_key)?.ok_or_else(|| {
                StorageError::StorageInconsistentState(format!(
                    "PromiseYield timeout queue entry #{} should be in the state",
                    promise_yield_indices.first_index
                ))
            })?;

        // Queue entries are ordered by expires_at
        if queue_entry.expires_at > apply_state.block_height {
            break;
        }

        // Check if the yielded promise still needs to be resolved
        let promise_yield_key = TrieKey::PromiseYieldReceipt {
            receiver_id: queue_entry.account_id.clone(),
            data_id: queue_entry.data_id,
        };
        if state_update.contains_key(&promise_yield_key, AccessOptions::DEFAULT)? {
            let new_receipt_id = create_receipt_id_from_receipt_id(
                &queue_entry.data_id,
                apply_state.block_height,
                new_receipt_index,
            );
            new_receipt_index += 1;

            // Create a PromiseResume receipt to resolve the timed-out yield.
            let resume_receipt = Receipt::V0(ReceiptV0 {
                predecessor_id: queue_entry.account_id.clone(),
                receiver_id: queue_entry.account_id.clone(),
                receipt_id: new_receipt_id,
                receipt: ReceiptEnum::PromiseResume(DataReceipt {
                    data_id: queue_entry.data_id,
                    data: None,
                }),
            });

            // Record a ReceiptToTx entry for the new resume receipt. The parent is the
            // yield receipt that is being timed out.
            if processing_state.apply_state.save_receipt_to_tx {
                let yield_receipt: Receipt = get_pure(state_update, &promise_yield_key)?
                    .expect("promise yield receipt should exist since contains_key was true");
                processing_state.receipt_to_tx.push((
                    new_receipt_id,
                    ReceiptToTxInfo::V1(ReceiptToTxInfoV1 {
                        origin: ReceiptOrigin::FromReceipt(ReceiptOriginReceipt {
                            parent_receipt_id: *yield_receipt.receipt_id(),
                            parent_predecessor_id: yield_receipt.predecessor_id().clone(),
                        }),
                        receiver_account_id: queue_entry.account_id.clone(),
                        shard_id: processing_state.apply_state.shard_id,
                    }),
                ));
            }

            // The receipt is destined for the local shard and will be placed in the outgoing
            // receipts buffer. It is possible that there is already an outgoing receipt resolving
            // this yield if `yield_resume` was invoked by some receipt which was processed in
            // the current chunk. The ordering will be maintained because the receipts are
            // destined for the same shard; the timeout will be processed second and discarded.
            receipt_sink.forward_or_buffer_receipt(
                resume_receipt,
                apply_state,
                &mut state_update,
            )?;
        }
