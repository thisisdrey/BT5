### Title
Handshake-stage retransmit path lets a spoofed UDP source roam an established tunnel's remote via `SetRemoteIfPreferred` - (File: handshake_manager.go)

### Summary
When the responder receives a retransmitted (duplicate) stage-0/stage-1 handshake message for an already-completed tunnel, `CheckAndComplete` returns `ErrAlreadySeen`, and `handleCheckAndCompleteError` unconditionally calls `existing.SetRemoteIfPreferred(f.hostMap, via)` using the packet's *source address* rather than any freshly-verified session proof [1](#0-0) . Because the "already seen" check only recognizes that this handshake was previously completed (the message content, including cert signature, was cryptographically valid the first time it was sent), a byte-identical replay of a captured handshake packet reproduces the same successful validation outcome even when resent from a different, spoofed source address.

### Finding Description
`SetRemoteIfPreferred` changes `HostInfo.remote` purely based on whether the packet's source address falls in a configured preferred range and whether the *current* remote does not, with no additional cryptographic binding to the new address [2](#0-1) . This function is invoked from the `ErrAlreadySeen` branch of `handleCheckAndCompleteError`, which fires on the responder side after the peer certificate has already been validated once for the original handshake [3](#0-2) .

Because the message is a byte-identical replay of a packet the genuine peer already sent (same ephemeral keys, same signed certificate blob), the Noise state machine's cryptographic checks pass identically to the first time, and the code path only decides "this is a duplicate/retransmit" — it does not re-verify that the *current* sender at the *current* source address is the genuine peer. An attacker who has captured one legitimate stage-0/stage-1 packet can resend those exact bytes from a spoofed UDP source: if that spoofed address lies in a configured `preferred_ranges` CIDR and the tunnel's current remote is not already in a preferred range, `SetRemoteIfPreferred` returns `true` and rewrites `HostInfo.remote` to the attacker-chosen address, updates `lastRoam`, and the code notifies the peer via a `Test` packet [4](#0-3) .

The invariant "remote changes only on cryptographically verified traffic from the genuine peer" is broken in the specific sense that the *source-address* portion of "who sent this" is never re-authenticated on the replay — only the previously-produced handshake bytes are, which prove the certificate/keys are genuine but say nothing about who is transmitting them now.

### Impact Explanation
This is a remote-state-poisoning / roam-hijack: an attacker can, once, redirect where an established tunnel's peer thinks the counterpart address is, provided (a) they possess a byte-identical captured handshake packet, (b) a `preferred_ranges` is configured, and (c) the current remote is not already inside a preferred range. The effect is traffic misdirection (outbound encrypted packets sent to the attacker's chosen preferred-range address) — not decryption or forgery, since the attacker still lacks the Noise session keys to decrypt or inject data-plane traffic. The realistic impact is availability/redirection (a targeted denial-of-service against the tunnel by causing outbound packets to go to a wrong address) rather than confidentiality/integrity compromise.

### Likelihood Explanation
The attack requires possession of a previously captured, valid handshake packet (an on-path or passive-capture position at least once), a network configuration that defines `preferred_ranges`, and a tunnel whose current remote happens to sit outside those ranges. These are non-trivial but plausible preconditions in real deployments (e.g., roaming clients moving from a public address to a LAN listed in preferred ranges). The attack is a one-shot move per handshake completion (subsequent replays cannot move the remote further once it is inside a preferred range, per the early-return check at line 803-805 of `hostmap.go`).

### Recommendation
Do not use raw UDP source address plus "already seen" handshake status as sufficient proof of roaming. Options: require a freshly-verified, non-replayable proof (e.g., a fresh Noise message/counter, or a time-boxed nonce) before invoking `SetRemoteIfPreferred` from the `ErrAlreadySeen` handshake path, or restrict this roam-on-retransmit behavior to cases where the retransmitted packet was not observed before within the replay/dedup window (i.e., only roam on truly novel handshake attempts, not exact duplicates), consistent with how data-plane roaming trusts only freshly-decrypted traffic.

### Proof of Concept
Integration test plan (extends `e2e/handshake_manager_test.go` style tests):
1. Establish a completed tunnel between `hostA` and `hostB`, with `hostB` configured with a `preferred_ranges` CIDR that does not include `hostA`'s current remote.
2. Capture the exact `HandshakePacket[handshakePacketStage0]`/`stage1` bytes sent by `hostA` during the original handshake.
3. After the tunnel is Established (`hostB`'s `HostInfo.GetRemote()` equals `hostA`'s original address), replay the captured bytes from a new `AddrPort` inside the preferred range, spoofing the source.
4. Assert that before the fix, `hostB`'s hostmap entry's `CurrentRemote`/`GetRemote()` changes to the spoofed address (`SetRemoteIfPreferred` returns `true`), and `lastRoam` is updated — demonstrating unauthenticated redirection.
5. After applying the recommended fix, assert `GetRemote()` remains unchanged for the replayed duplicate packet.

func (i *HostInfo) SetRemoteIfPreferred(hm *HostMap, via ViaSender) bool {
	if via.IsRelayed {
		return false
	}

	currentRemote := i.GetRemote()
	if !currentRemote.IsValid() {
		i.SetRemote(via.UdpAddr)
		return true
	}

	// NOTE: We do this loop here instead of calling `isPreferred` in
	// remote_list.go so that we only have to loop over preferredRanges once.
	newIsPreferred := false
	for _, l := range hm.GetPreferredRanges() {
		// return early if we are already on a preferred remote
		if l.Contains(currentRemote.Addr()) {
			return false
		}

		if l.Contains(via.UdpAddr.Addr()) {
			newIsPreferred = true
		}
	}

	if newIsPreferred {
		// Consider this a roaming event
		i.lastRoam = time.Now()
		i.lastRoamRemote = currentRemote

		i.SetRemote(via.UdpAddr)

		return true
	}

	return false
}
