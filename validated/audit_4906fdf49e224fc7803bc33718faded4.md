### Title
Flash-deposited supply permanently dilutes `RewardsDistributor` index, destroying all holders' accrued yield - (File: contracts/RewardsDistributor.sol)

### Summary
`RewardsDistributor._calculateTokenIndex` distributes the elapsed `tokenSpeed` emission pro-rata over `token_.totalSupply()` **at update time**. `updateBeforeMintOrBurn` and `updateBeforeTransfer` are permissionless, so any EOA can flash-deposit a huge amount into a `DepositToken` (inflating `totalSupply`), trigger the index update, and immediately withdraw. The index delta for the entire period since the last update is compressed to ~0, permanently destroying the rewards that honest holders accrued over that window. The reward tokens remain stranded in the distributor — the emission for that period is credited to no one.

### Finding Description
In `RewardsDistributor.sol:197-212`, the per-second reward emission is converted into an index delta as `_tokensAccrued.wadDiv(_totalSupply)`, where `_totalSupply = token_.totalSupply()` is read at the moment the update executes — not averaged or snapshotted over the accrual window.

`updateBeforeMintOrBurn` (`RewardsDistributor.sol:175-180`) and `updateBeforeTransfer` (`:186-192`) have no access control (the NatSpec even says it "may be called by anyone"), and `claimRewards` (`:150-168`) is likewise callable by anyone for anyone.

A deposit path is fully permissionless: `DepositToken.deposit` (`DepositToken.sol:211-237`) mints shares via `_mint` (`:469-489`), which only touches `updateRewardsBeforeMintOrBurn` before increasing `totalSupply`. `withdraw` (`:406-412`) burns via `_burn` and has no time-lock — only `unlockedBalanceOf` health check, which passes when the attacker has no debt. Deposit/withdraw fees, if configured nonzero, only reduce the attacker's cost slightly; on deployments where `depositFee`/`withdrawFee` are 0 the attack is free aside from the flash-loan fee.

Attack sequence in a single transaction:
1. Flash-borrow a large amount of the deposit-token underlying (e.g., WETH for `msdWETH`).
2. `depositToken.deposit(flashAmount, attacker)` — `totalSupply` grows by orders of magnitude.
3. `rewardsDistributor.updateBeforeMintOrBurn(msdToken, victim)` (or `claimRewards(victim)`). `_updateTokenIndex` runs with the inflated `totalSupply`, so `_ratio = deltaTime * speed / hugeSupply ≈ 0`. The index advances negligibly for a window that may span hours/days if updates were infrequent.
4. `depositToken.withdraw(balance, attacker)`, repay the flash loan.

The accrued index for the whole elapsed window is permanently lost: when honest users later call `updateBeforeMintOrBurn`, their `tokensDelta = balance * (newIndex - accountIndex)` excludes the diluted emission, and the corresponding reward tokens sit unclaimable in the distributor (only `claimRewards` moves them out, and only up to credited `tokensAccruedOf`).

Modifiers that do not stop this: `nonReentrant` on `claimRewards` (no reentrancy needed), `whenNotPaused`/`onlyIfDepositTokenIsActive` (normal operation), `maxTotalSupply` cap (attacker sizes the loan under it), and the per-account index bookkeeping (correctly computed, just on a poisoned `totalSupply`).

### Impact Explanation
Permanent loss of unclaimed yield for all suppliers/borrowers of the targeted token. The emission for the elapsed window is credited to nobody and the reward tokens are frozen in the contract. Repeating the attack each block (or whenever a stale index accumulates, e.g., long gaps between user transactions — exactly the low-activity condition of a niche collateral) continuously wipes accrued rewards. The attacker need not profit directly; however, a competing large holder can also use this to boost their own relative share of future emissions, and the stranded rewards may only be recoverable by governance rescue, satisfying the "permanent freezing of unclaimed yield" impact.

### Likelihood Explanation
Requires only an unprivileged EOA with flash-loan access and one public call. No privileged role, no oracle dependency, no timing edge beyond a stale index (which is the norm — index only updates when someone interacts). Cost is a flash-loan fee and deposit/withdraw fees if nonzero; these are frequently 0 on Metronome deployments. The main limitation is `maxTotalSupply` headroom, which is typically large relative to existing TVL for new collaterals.

### Recommendation
Snapshot a dilution-resistant accrual base: e.g., store `totalSupply` at the last index update and use the *minimum* (or a TWAP) of supply across the window, or compute the index increment lazily per-account using their stored balance at last update rather than current `totalSupply`. Simpler mitigations: restrict `updateBeforeMintOrBurn`/`updateBeforeTransfer` to the Pool's registered DepositToken/DebtToken callers (they already call these hooks internally), and/or enforce a minimum holding period / cooldown between `deposit` and `withdraw` so flash supply cannot straddle an index update.

### Proof of Concept
```solidity
// SPDX-License-Identifier: MIT
// Foundry fork test — contracts/RewardsDistributor.sol index dilution
function test_flashDilution_stealsAccruedEmission() public {
    // Setup: governor set tokenSpeed for msdWETH = 1e18 rewards/sec.
    // Alice holds 100 msdWETH; index last updated 1 day ago (stale).

    uint256 accruedExpected =
        rewardsDistributor.claimable(alice); // ~86_400 * speed * aliceShare > 0
    assertGt(accruedExpected, 0);

    // Attacker: flash-borrow underlying, inflate supply, force index update
    vm.startPrank(attacker);
    weth.approve(address(msdWETH), type(uint256).max);
    uint256 flash = 1_000_000 ether; // >> real totalSupply (~100)
    deal(address(weth), attacker, flash);

    msdWETH.deposit(flash, attacker);                       // totalSupply now ~1e6+100
    rewardsDistributor.updateBeforeMintOrBurn(
        IERC20(address(msdWETH)), alice);                   // index delta ~0 for whole day
    msdWETH.withdraw(msdWETH.balanceOf(attacker), attacker);// exit, repay flash
    vm.stopPrank();

    // Alice's accrued rewards for the entire day are destroyed
    assertLt(rewardsDistributor.claimable(alice), accruedExpected / 1000);
    // The missing emission is stranded: distributor balance exceeds sum of claimables
}
```
