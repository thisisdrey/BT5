### Title
Bridge-in mint to the zero address permanently blocks the LayerZero channel and burns in-flight and subsequent transfers - ([File: contracts/ProxyOFT.sol](contracts/ProxyOFT.sol))

### Summary
The external report describes a DoS caused by failure to validate external input (CWE-20). The Metronome analog lives in the OFT receive path: `ProxyOFT._creditTo` unconditionally calls `SyntheticToken.mint`, which reverts for `to == address(0)` (`MintToTheZeroAddress`), for an inactive token, or when `bridgedInSupply() > maxBridgedInSupply`. None of these conditions are validated before the payload is committed on the source chain, and any unprivileged user fully controls `to_` via `ProxyOFT.sendFrom`.

### Finding Description
`ProxyOFT.sendFrom(address,uint16,address,uint256)` encodes an arbitrary attacker-chosen `to_` into the LayerZero payload (`abi.encodePacked(to_)`) with no zero-address check. [1](#0-0)  On the destination chain, `ComposableOFTCoreUpgradeable._nonblockingLzReceive` → `_sendAck` decodes `toAddress` and calls `_creditTo`, which calls `syntheticToken.mint(toAddress_, amount_)`. [2](#0-1)  `SyntheticToken._mint` reverts with `MintToTheZeroAddress` when `account_ == address(0)`, and also reverts when `isActive == false`, `bridgedInSupply() > maxBridgedInSupply` (`SurpassMaxBridgingSupply`), or `totalSupply > maxTotalSupply` (`SurpassMaxSynthSupply`). [3](#0-2) 

In LayerZero v1's nonblocking pattern, a reverting receive is stored as a failed message, and **all subsequent nonces on that (srcChain, path) are blocked** until the message is cleared by `retryMessage` (which keeps reverting for `to == 0` / inactive token) or by the privileged `forceResumeReceive`. There is no cap check or recipient check on the debit side, so a 1-wei send to `address(0)` suffices to brick the channel.

### Impact Explanation
Temporary-to-permanent freezing of user funds and bridge liveness loss:

- A single cheap send (`amount_ = 1`, `to_ = address(0)`) burns the dust on the source chain and permanently stalls every subsequent inbound bridge message on that source chain/path. Users who call `sendFrom` afterwards have their synth burned on the source chain while the mint can never execute.
- `forceResumeReceive` clears the stuck nonce *without executing it*, so the blocked transfer's tokens are destroyed (burned on source, never minted) — a loss of user funds. The attacker can immediately re-brick the channel after each resume at negligible cost.
- Even without `address(0)`, the same blocking occurs organically or adversarially via `SurpassMaxBridgingSupply`/`SurpassMaxSynthSupply` whenever an in-flight amount exceeds remaining headroom, with no pre-flight validation to prevent it.

The broken invariant is bridge conservation/liveness: burned-on-source tokens are not matched by minted-on-destination tokens, and the nonce-ordered channel halts.

### Likelihood Explanation
Reachable by any EOA holding a dust amount of the synthetic token through the public `sendFrom` entry point; no privileged role, oracle manipulation, or flash loan is needed. The only costs are the LZ fee and a trivial token amount. Deployed `ProxyOFT` contracts on mainnet/optimism/base/hemi all share this code path. Note: whether retry of a queued-but-not-stored message ordering blocks strictly as described depends on the deployed LZ v1 endpoint behavior (`LzApp` stored-payload blocking is the standard v1 semantics used here), which should be confirmed against the pinned `NonblockingLzAppUpgradeable` dependency — I could not fully verify the endpoint's `forceResumeReceive` semantics within this index.

### Recommendation
- In `ProxyOFT._debitFrom`/`sendFrom`, revert early if `toAddress_.toAddress(0) == address(0)`.
- Prefer a pattern where credit failures do not wedge the channel: e.g., credit to a fallback/recovery address or record the amount in a claimable balance when `mint` would revert (cap exceeded / token inactive), rather than letting the receive throw.
- Document and monitor cap headroom so legit bridge-ins are not blocked by `maxBridgedInSupply`/`maxTotalSupply`.

    function _mint(address account_, uint256 amount_) private onlyIfSyntheticTokenIsActive {
        if (account_ == address(0)) revert MintToTheZeroAddress();

        address _msgSender = _msgSender();

        if (_isMsgSenderProxyOFT(_msgSender)) {
            totalBridgedIn += amount_;
            if (bridgedInSupply() > maxBridgedInSupply) revert SurpassMaxBridgingSupply();
        } else if (_isMsgSenderAmo(_msgSender)) {
            amoSupply += amount_;
            if (amoSupply > maxAmoSupply) revert SurpassMaxAmoSupply();
        }

        totalSupply += amount_;
        if (totalSupply > maxTotalSupply) revert SurpassMaxSynthSupply();
        balanceOf[account_] += amount_;
        emit Transfer(address(0), account_, amount_);
    }
