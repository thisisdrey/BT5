### Title
DoS via unbounded tar/compression-bomb extraction in `ExtractHooks` before any size/entry validation - (File: internal/gitaly/repoutil/custom_hooks.go)

### Summary
`ExtractHooks` pipes attacker-controlled stream data directly into `tar -xf - -C <tmp> --strip-components N custom_hooks` without any limit on the number of tar entries, per-entry declared size, or total decompressed output, and without disabling automatic compression auto-detection (`-xf` lets GNU tar transparently decompress gzip/bzip2/xz input). Any authenticated user with `SetCustomHooks`/`RestoreCustomHooks` access to a repo they control can stream a small, highly compressible archive (a classic decompression bomb) or an archive containing many nested `custom_hooks/...` entries and cause `tar` to write an effectively unbounded amount of data/inodes to the storage's temp directory before any hash/vote or size check occurs.

### Finding Description
`SetCustomHooks`/`RestoreCustomHooks` gRPC handlers (`internal/gitaly/service/repository/set_custom_hooks.go`) stream request `Data` chunks directly into a `streamio.Reader`, which is passed unmodified to `repoutil.SetCustomHooks` → `repoutil.ExtractHooks`. [1](#0-0) 

Inside `ExtractHooks`, the reader is only peeked for EOF (to detect an empty archive) and then handed straight to `tar` as stdin: `cmdArgs := []string{"-xf", "-", "-C", path, "--strip-components", stripComponents, CustomHooksDir}`. There is no cap on the number of entries, no per-file or archive-wide size limit, and no `--exclude` or path/entry validation. [2](#0-1) 

Because `tar -xf -` performs automatic compression-format detection, a small gRPC stream payload can contain a gzip/bzip2/xz-compressed tar with highly repetitive content (classic "zip/tar bomb"), which expands to an enormous size on disk during extraction. Extraction to `tmpDir.Path()` happens in `SetCustomHooks` before the `hooksLock`, `newDirectoryVote` hashing, or `voteCustomHooks` prepared/committed voting logic runs, meaning disk/inode exhaustion occurs unconditionally as a side effect of merely invoking the RPC — it is not gated behind any consensus/commit step. [3](#0-2) 

No other layer intercepts this: `s.locator.ValidateRepository` only validates the repository reference, not the tar payload; there is no `io.LimitReader`, message-size accounting, or entry-count cap anywhere in this code path.

### Impact Explanation
An attacker who owns a repository (standard push/RPC access) can exhaust the disk and/or inode capacity of the Gitaly storage shard hosting that repository by sending a compact but maliciously crafted tar/gzip archive to `SetCustomHooks` or `RestoreCustomHooks`. Because storage is shared across many repositories on the same Gitaly node/shard, this can cause write failures and service degradation for other, unrelated repositories on that storage — a resource-exhaustion / DoS impact of an RPC handler.

### Likelihood Explanation
This requires only the ability to call `SetCustomHooks`/`RestoreCustomHooks` on a repository the attacker controls (standard authenticated non-admin capability, e.g. via GitLab Rails triggering this on the user's own project, or direct RPC access if permitted). Crafting a tar/gzip bomb is straightforward and well-documented, and the RPC accepts arbitrary streamed bytes as tar data with no special preconditions or non-default configuration required. This is easily repeatable.

### Recommendation
- Do not stream attacker data directly into `tar` with unrestricted auto-detection; disable compression auto-detection or explicitly reject compressed input for custom hooks, since custom hooks are expected to be an uncompressed tar of small files/scripts.
- Enforce hard limits before/while extracting: maximum total decompressed size, maximum per-file size, and maximum entry count (e.g., by wrapping the tar output check with `pledge`-like resource limits, using `--exclude`, or extracting via a Go tar reader that enforces a running byte/entry counter and aborts once exceeded, e.g., wrap `reader` in `io.LimitReader` sized to a sane maximum hook-archive size, and use an in-process tar/gzip reader instead of shelling out to `tar` so limits can be enforced entry-by-entry).
- Apply `ulimit`/cgroup-based disk quotas or dedicated scratch space with quota enforcement for temp extraction directories used for hook uploads.
- Reject archives whose entries fall outside the `custom_hooks/` prefix or exceed a configured nesting/name-length limit.

```go
// internal/gitaly/repoutil/custom_hooks_bomb_test.go
func TestExtractHooks_TarBomb(t *testing.T) {
    ctx := testhelper.Context(t)
    logger := testhelper.NewLogger(t)
    tmp := t.TempDir()

    // Build a small gzip-compressed tar containing one file with highly
    // repetitive content that gzip compresses extremely well but expands
    // to a very large size on disk (e.g. 500MB from a few KB payload).
    var buf bytes.Buffer
    gz := gzip.NewWriter(&buf)
    tw := tar.NewWriter(gz)
    repetitive := bytes.Repeat([]byte{0}, 500*1024*1024) // 500MB of zeros
    hdr := &tar.Header{
        Name: "custom_hooks/pre-receive",
        Mode: 0o755,
        Size: int64(len(repetitive)),
    }
    require.NoError(t, tw.WriteHeader(hdr))
    _, err := tw.Write(repetitive)
    require.NoError(t, err)
    require.NoError(t, tw.Close())
    require.NoError(t, gz.Close())
    // buf is only a few KB due to gzip compression of all-zero data.

    err = ExtractHooks(ctx, logger, &buf, tmp, false)
    require.NoError(t, err)

    fi, err := os.Stat(filepath.Join(tmp, "custom_hooks", "pre-receive"))
    require.NoError(t, err)
    require.Equal(t, int64(500*1024*1024), fi.Size())
    // Assert: a few-KB gRPC payload produced 500MB on disk with no limit enforced.
}
```
This demonstrates that `ExtractHooks` will happily expand a small compressed stream into a very large file on disk, confirming the absence of any size cap prior to/during extraction, reachable via `SetCustomHooksRequest`/`RestoreCustomHooksRequest` streamed data.

```go
func (s *server) SetCustomHooks(stream gitalypb.RepositoryService_SetCustomHooksServer) error {
	ctx := stream.Context()

	firstRequest, err := stream.Recv()
	if err != nil {
		return structerr.NewInternal("getting first request: %w", err)
	}

	repo := firstRequest.GetRepository()
	if err := s.locator.ValidateRepository(ctx, repo); err != nil {
		return structerr.NewInvalidArgument("%w", err)
	}

	reader := streamio.NewReader(func() ([]byte, error) {
		if firstRequest != nil {
			data := firstRequest.GetData()
			firstRequest = nil
			return data, nil
		}

		return request.GetData(), err
	})

		return structerr.NewInternal("setting custom hooks: %w", err)
	}

	return stream.SendAndClose(&gitalypb.SetCustomHooksResponse{})
```

```go
func ExtractHooks(ctx context.Context, logger log.Logger, reader io.Reader, path string, stripPrefix bool) error {
	// GNU tar does not accept an empty file as a valid tar archive and produces
	// an error. Since an empty hooks tar is symbolic of a repository having no
	// hooks, the reader is peeked to check if there is any data present.
	buf := bufio.NewReader(reader)
	if _, err := buf.Peek(1); errors.Is(err, io.EOF) {
		return nil
	}

	stripComponents := "0"
	if stripPrefix {
		stripComponents = "1"
	}

	cmdArgs := []string{"-xf", "-", "-C", path, "--strip-components", stripComponents, CustomHooksDir}

	var stderrBuilder strings.Builder
	cmd, err := command.New(ctx, logger, append([]string{"tar"}, cmdArgs...),
		command.WithStdin(buf),
		command.WithStderr(&stderrBuilder))
	if err != nil {
		return fmt.Errorf("executing tar command: %w", err)
	}

	if err := cmd.Wait(); err != nil {
		stderr := stderrBuilder.String()

		// GNU and BSD tar versions have differing errors when attempting to
		// extract specified members from a valid tar archive. If the tar
		// archive is valid the errors for GNU and BSD tar should have the
		// same prefix, which can be checked to validate whether the expected
		// content is present in the archive for extraction.
		if strings.HasPrefix(stderr, "tar: custom_hooks: Not found in archive") {
			return nil
		}

		return structerr.New("waiting for tar command completion: %w", err).WithMetadata("stderr", stderr)
	}

	return nil
```
