### Title
Out-of-bounds read (ArrayIndexOutOfBoundsException) when scanning shielded TRC20 logs with attacker-crafted short log data - (File: `framework/src/main/java/org/tron/core/Wallet.java`)

### Summary
`Wallet.getNoteTxFromLogListByOvk` (and its `ByIvk` counterpart) slice fixed-size fields out of a TRC20 event log's raw `data` field using `ByteArray.subArray(logData, start, end)` without first validating that `logData` is long enough, unlike the sibling `logType == 4` branch in the same method which explicitly checks `logData.length` before slicing.

### Finding Description
For `logType` 1–3 (note-producing shielded TRC20 events), the code immediately does: [1](#0-0) 
without any `logData.length` check, whereas the `logType == 4` branch a few lines below defends against short input: [2](#0-1) 

`ByteArray.subArray` performs no bounds checking at all — it blindly calls `System.arraycopy` with the caller-supplied offsets: [3](#0-2) 

`logData` originates from `TransactionInfo.Log.getData()`, i.e., raw event data emitted by an arbitrary smart contract during execution. Any unprivileged account can deploy a contract that emits a log with topics matching the "shielded TRC20" signature detection (`getShieldedTRC20LogType`) but with a `data` payload shorter than the 788 bytes the parser expects (`pos(32)+cm(32)+cv(32)+epk(32)+c_enc(580)+c_out(80)`). When any client subsequently calls the shielded-TRC20 note scanning API over that block range, the node throws an unhandled `ArrayIndexOutOfBoundsException`, which is the same class of bug as the reported `tiffcrop` out-of-bounds read triggered by crafted, under-sized structured input.

### Impact Explanation
The scanning entry point is reachable through the public HTTP/gRPC API surface (`ScanShieldedTRC20NotesByOvkServlet` / the corresponding gRPC `scanShieldedTRC20NotesByOvk`/`ByIvk` calls into `Wallet.queryTRC20NoteByIvk` → `getNoteTxFromLogListByOvk`/`ByIvk`), which is present on full nodes, PBFT nodes and solidity nodes: [4](#0-3) [5](#0-4) 
An unauthenticated/any caller who knows (or brute-forces/observes) an `ovk`/`ivk` for a shielded pool, or a node operator running routine wallet scans, will have the query crash with an uncaught runtime exception for any block range containing the attacker's malicious log — denial of service for that API request path, consistent with "API the node can no longer serve" impact criteria.

### Likelihood Explanation
Likelihood is high: any address can deploy a contract and emit an event, no special privileges or SR/witness status are required, and the shielded-TRC20 log type detection only needs to match topic conventions loosely enough to be reached (logType 1–3), not need to be cryptographically valid, since the length check occurs (or rather doesn't occur) before any decryption is attempted.

### Recommendation
Add an explicit `logData.length` bounds check before slicing for `logType` 1–3 in `getNoteTxFromLogListByOvk` and `getNoteTxFromLogListByIvk`, mirroring the guard already present for `logType == 4`, and/or make `ByteArray.subArray` itself bounds-checked and throw a caught/expected exception (e.g., `IndexOutOfBoundsException` handled at the call site) instead of allowing an uncaught `ArrayIndexOutOfBoundsException` to propagate to the API layer.

### Proof of Concept
1. Deploy a contract that emits a log whose topics satisfy `getShieldedTRC20LogType(...)` returning 1, 2, or 3 for a chosen `shieldedTRC20ContractAddress`, but with `data` shorter than 708/788 bytes (e.g., 32 bytes).
2. Call the public `scanshieldedtrc20notesbyovk` (or `byivk`) HTTP/gRPC endpoint with a block range covering that transaction, any `ovk`/`ivk`.
3. `Wallet.queryTRC20NoteByIvk` → `getNoteTxFromLogListByOvk`/`ByIvk` executes `ByteArray.subArray(logData, 128, 708)` (or similar) on the short array, throwing `ArrayIndexOutOfBoundsException`, failing the API request/crashing the handling thread.

Note: I was unable to fully trace `getShieldedTRC20LogType`'s exact topic-matching criteria within the available index (its implementation body was not returned by search), so the precise topic values required to hit the `logType` 1–3 branches are unconfirmed here — this should be verified directly in the repository before treating the PoC as fully concrete.

  private DecryptNotesTRC20 queryTRC20NoteByIvk(long startNum, long endNum,
      byte[] shieldedTRC20ContractAddress, byte[] ivk, byte[] ak, byte[] nk)
      throws BadItemException, ZksnarkException, ContractExeException {
    if (!(startNum >= 0 && endNum > startNum && endNum - startNum <= 1000)) {
      throw new BadItemException(
          SHIELDED_TRANSACTION_SCAN_RANGE);
    }

    DecryptNotesTRC20.Builder builder = DecryptNotesTRC20.newBuilder();
    BlockList blockList = this.getBlocksByLimitNext(startNum, endNum - startNum);
    for (Block block : blockList.getBlockList()) {
      for (Transaction transaction : block.getTransactionsList()) {
        TransactionCapsule transactionCapsule = new TransactionCapsule(transaction);
        byte[] txId = transactionCapsule.getTransactionId().getBytes();
        TransactionInfo info = this.getTransactionInfoById(ByteString.copyFrom(txId));
        DecryptNotesTRC20.NoteTx.Builder noteBuilder;
        if (!Objects.isNull(info)) {
          List<TransactionInfo.Log> logList = info.getLogList();
          if (!Objects.isNull(logList)) {
            Optional<DecryptNotesTRC20.NoteTx> noteTx;
            int index = 0;
            for (TransactionInfo.Log log : logList) {
              int logType = getShieldedTRC20LogType(log, shieldedTRC20ContractAddress);
              // Only note-producing log types (1..3) advance the note index;
              // TokenBurn (4) and NoteSpent (5) do not emit a leaf.
              if (logType > 0 && logType < 4) {
                noteBuilder = DecryptNotesTRC20.NoteTx.newBuilder();
                noteBuilder.setTxid(ByteString.copyFrom(txId));
                noteBuilder.setIndex(index);
                index += 1;
                noteTx = getNoteTxFromLogListByIvk(noteBuilder, log, ivk, ak, nk,
                    shieldedTRC20ContractAddress, logType);
                noteTx.ifPresent(builder::addNoteTxs);
              }
            }
          }
        }
      } //end of transaction
    } //end of blocklist
    return builder.build();
  }

  public static byte[] subArray(byte[] input, int start, int end) {
    byte[] result = new byte[end - start];
    System.arraycopy(input, start, result, 0, end - start);
    return result;
  }
