### Title
Unbounded recursive-descent expression parsing in the Go assembler causes stack overflow on malicious `.s` source - ([File: src/cmd/asm/internal/asm/parse.go])

### Summary
The Go assembler's constant-expression parser (`expr`/`term`/`factor` in `cmd/asm/internal/asm`) is a classic mutually-recursive descent parser with no recursion-depth limit, structurally identical to the yasm `parse_expr1` bug (nested-parenthesis recursion → stack overflow). Unlike `go/parser` and `text/template/parse`, which were hardened against exactly this bug class with explicit nesting-depth counters (`maxNestLev`/`incNestLev`, `maxStackDepth`), `cmd/asm`'s `factor()` has no such guard, so a deeply parenthesized immediate operand in assembly source can exhaust the goroutine stack while `go build`/`go tool asm` parses it.

### Finding Description
Attacker input: a `.s` assembly source file (e.g., shipped inside a Go module or package that a victim builds) containing an instruction whose immediate operand is a deeply nested parenthesized constant expression, such as `MOVQ $(((((...1...))))), AX`.

Entry point: `Parser.operand` at [1](#0-0)  calls `p.expr()` to evaluate the immediate constant. `expr()` calls `term()`, which calls `factor()`: [2](#0-1) 

`factor()`'s `'('` case recurses back into `p.expr()` for every opening parenthesis, and `expr()`/`term()` recurse back into `factor()` for unary `+`, `-`, `~`: [3](#0-2) [4](#0-3) 

Failed check: there is no counter analogous to `go/parser`'s `nestLev`/`maxNestLev` ( [5](#0-4) ) or `text/template/parse`'s `stackDepth`/`maxStackDepth` ( [6](#0-5) [7](#0-6) ) limiting how deep `factor()`/`expr()`/`term()` may recurse.

Sink: unbounded native-stack recursion → stack overflow, which Go turns into a fatal, unrecoverable runtime crash (`fatal error: stack overflow`), not a normal `panic` that can be caught.

### Impact Explanation
An attacker who supplies a Go package/module containing a crafted `.s` file (a normal, unprivileged victim workflow: `go build`, `go vet`, `go test`, or any tool that compiles the package) can crash the assembler process compiling that package, denying the build. This falls under Go's Security Decisions as an in-scope "plausible malicious-input parser panic/crash" during `go build` of untrusted source, the same class of issue `go/parser` and `text/template/parse` were explicitly hardened against. It is a PUBLIC-track availability/DoS issue against the build toolchain, not authentication/integrity bypass or code execution.

### Likelihood Explanation
Victim workflow: any developer or CI system building a Go module that includes attacker-supplied or third-party `.s` assembly files (common in low-level/runtime-adjacent packages) is affected the moment `go build`/`go tool asm` parses the malicious operand — no special privileges are required, only that the victim compiles the package.

### Recommendation
Add an explicit recursion/nesting-depth counter to `Parser.expr`/`term`/`factor` (mirroring `go/parser`'s `incNestLev`/`decNestLev`/`maxNestLev` pattern), and call `p.errorf` (which reports a normal compile error rather than crashing) once the limit is exceeded, before recursing further.

func TestExprDeepNestingStackOverflow(t *testing.T) {
	// Construct $(((((...1...))))) with enough nesting to blow the goroutine stack.
	depth := 200000
	expr := strings.Repeat("(", depth) + "1" + strings.Repeat(")", depth)

	p := NewParser(nil, nil, nil)
	p.start(lex.Tokenize(expr))

	// This is expected to trigger unbounded recursion in factor()->expr()->factor()
	// and crash the process with "fatal error: stack overflow" instead of
	// returning a parse error, because there is no depth limit analogous to
	// go/parser's maxNestLev.
	_ = p.expr()
}

func (p *Parser) expr() uint64 {
	value := p.term()
	for {
		switch p.peek() {
		case '+':

		case '-':

func (p *Parser) term() uint64 {
	value := p.factor()
	for {
		switch p.peek() {
		case '*':
			p.next()
			value *= p.factor()
		case '/':
			p.next()
			if int64(value) < 0 {
				p.errorf("divide of value with high bit set")
			}
			divisor := p.factor()
			if divisor == 0 {
				p.errorf("division by zero")
			} else {
				value /= divisor
			}
		case '%':
			p.next()
			divisor := p.factor()
			if int64(value) < 0 {
				p.errorf("modulo of value with high bit set")
			}
			if divisor == 0 {
				p.errorf("modulo by zero")
			} else {
				value %= divisor
			}
		case lex.LSH:
			p.next()
			shift := p.factor()
			if int64(shift) < 0 {
				p.errorf("negative left shift count")
			}
			return value << shift
		case lex.RSH:
			p.next()
			shift := p.term()
			if int64(shift) < 0 {
				p.errorf("negative right shift count")
			}
			if int64(value) < 0 {
				p.errorf("right shift of value with high bit set")
			}
			value >>= shift
		case '&':
			p.next()
			value &= p.factor()
		default:
			return value
		}
	}
}

// factor = const | '+' factor | '-' factor | '~' factor | '(' expr ')'
func (p *Parser) factor() uint64 {
	tok := p.next()
	switch tok.ScanToken {
	case scanner.Int:
		return p.atoi(tok.String())
	case scanner.Char:
		str, err := strconv.Unquote(tok.String())
		if err != nil {
			p.errorf("%s", err)
		}
		r, w := utf8.DecodeRuneInString(str)
		if w == 1 && r == utf8.RuneError {
			p.errorf("illegal UTF-8 encoding for character constant")
		}
		return uint64(r)
	case '+':
		return +p.factor()
	case '-':
		return -p.factor()
	case '~':
		return ^p.factor()
	case '(':
		v := p.expr()
		if p.next().ScanToken != ')' {
			p.errorf("missing closing paren")
		}
		return v
	}
	p.errorf("unexpected %s evaluating expression", tok)
	return 0
}
