### Title
DelegateAction replay via same-block AddKey nonce reset after key delete+recreate (same public key) - (File: runtime/runtime/src/actions.rs, runtime/runtime/src/access_keys.rs)

### Summary
`validate_delegate_action_key` only compares a `DelegateAction`'s nonce against the *currently stored* `access_key.nonce` row for `(sender_id, public_key)`. When the sender's own `DeleteKey`+`AddKey` (re-adding the identical public key) executes in the same block after a `DelegateAction` has already consumed a nonce, the freshly-created access key's nonce is reset to a fixed, height-derived value `(block_height - 1) * ACCESS_KEY_NONCE_RANGE_MULTIPLIER` that is unrelated to the highest nonce previously consumed by that same public key. A relayer holding the already-consumed `SignedDelegateAction` bytes can resubmit them; if the original delegate nonce falls inside the reset window `((block_height-1)*1e6, block_height*1e6)` — which is exactly the range legitimate wallets naturally pick nonces from at that block height — the stale nonce becomes valid again and the delegated actions execute a second time.

### Finding Description
- `apply_delegate_action` calls `validate_delegate_action_key`, which fetches the access key strictly from current trie state via `get_access_key(state_update, sender_id, public_key)` and compares the delegate nonce against `access_key.nonce` (`current_nonce`): [1](#0-0) 
- The only anti-replay guard is `delegate_nonce.nonce() <= current_nonce` → reject, and an upper bound `apply_state.block_height * ACCESS_KEY_NONCE_RANGE_MULTIPLIER`: [2](#0-1) 
- On success, `access_key.nonce` is bumped to the delegate nonce and persisted: [3](#0-2) 
- `action_delete_key`/`delete_regular_key` fully removes the access-key row (and thus its nonce) from the trie: [4](#0-3) 
- `action_add_key`/`add_regular_key` does not check whether the public key being re-added was previously used and does not preserve any watermark of nonces that key ever consumed; it simply seeds a fresh nonce based only on the current block height: [5](#0-4) 
- The seeding formula is: [6](#0-5) 

Exploit flow:
1. At block height H, sender signs a `DelegateAction` with nonce `N` for access key `K` (public key `pk`), satisfying `old_current_nonce < N < H*1e6` (the standard wallet convention biases signed nonces toward `H*1e6 + small_offset`, so `N` is typically close to `H*1e6`).
2. Relayer submits it; `validate_delegate_action_key` succeeds, sets `access_key.nonce = N`, and the inner actions execute once (e.g., a `Transfer` draining sender funds, forwarded with `sender_id` as predecessor). Relayer retains the raw signed bytes.
3. In the same block H, the sender independently performs `DeleteKey(pk)` followed by `AddKey(pk, ...)` re-adding the identical public key for unrelated reasons (e.g., permission change script that removes and reinserts the same key pair). This deletes the access-key row (losing the watermark `N`) and reseeds it with `initial_nonce_value(H) = (H-1)*1e6`.
4. If `N > (H-1)*1e6` — true whenever the original signed nonce was chosen close to `H*1e6` as is conventional — then `N > current_nonce` again, so the relayer's cached, already-executed `DelegateAction` bytes pass `validate_delegate_action_key` a second time and the inner actions are re-forwarded/executed.

This breaks the "authorization exactness" invariant documented on the `nonce` field itself ("Nonce to ensure that the same delegate action is not sent twice by a relayer"): [7](#0-6) . Existing replay tests only cover the straightforward case where the *same* access key row persists across resubmission attempts (`test_validate_delegate_action_key_update_nonce`, `gas_keys.rs` replay test), not the delete+recreate-same-pubkey-in-same-block race: [8](#0-7) [9](#0-8) 

### Impact Explanation
This is a double-spend/replay of an authorized action: the relayer, an unrelated unprivileged party, can cause the sender-authorized `DelegateAction` inner actions (which run with `sender_id` as predecessor — e.g., transfers, function calls with side effects) to execute twice without a fresh signature from the sender for the second run. If the delegated actions include a `Transfer` or a state-mutating contract call, this directly causes duplicate debits from the sender's account/state, i.e., unintended loss of funds or duplicated contract side effects, matching the "double-spend/replay" bounty category.

### Likelihood Explanation
Preconditions are narrow but reachable without any privileged access: the sender must reuse the *exact same public key* in a `DeleteKey`+`AddKey` pair within the same block height as the original `DelegateAction` consumption, and the delegate nonce must fall in the `((H-1)*1e6, H*1e6)` window — which is the normal range wallets pick nonces from. The relayer needs no cooperation beyond having cached the original signed bytes (which it necessarily has, since it was the original submitter). The scenario does not require the sender's intent to enable replay; it can occur as a side effect of any legitimate same-block key-rotation-with-identical-keypair operation coinciding with meta-transaction relaying. Reproducibility is deterministic given the described block-height/nonce alignment.

### Recommendation
Do not reset a newly (re-)added access key's nonce purely from the current block height when the exact same public key was previously used on that account; either forbid re-adding the same public key after deletion within a bounded height window unless the new nonce floor is provably above any nonce that key row could have reached, or persist a per-account/per-pubkey monotonic "highest historical nonce" watermark independent of key existence (e.g., keep a tombstone entry) and seed new nonces from `max(initial_nonce_value(block_height), watermark + 1)`.

### Proof of Concept
Test-loop integration test:
1. Create sender and relayer accounts; add a full-access key `pk` to sender.
2. At block height H, sender signs `DelegateActionV2` with `nonce = H*1_000_000 - 1` (or any value confirmed `< H*1e6` and `> (H-1)*1e6`) wrapping a `Transfer` to a receiver; relayer submits via `Action::DelegateV2`. Assert success and receiver balance increased by the transfer amount.
3. In the same block height H, sender submits `DeleteKey(pk)` followed by `AddKey(pk, AccessKey::full_access())` (same public key) in a single transaction (or two txs at the same height).
4. Relayer resubmits the identical cached `SignedDelegateAction` from step 2 in a new outer transaction at the same block height H.
5. Assert the second submission's outcome is `SuccessValue`, not `DelegateActionInvalidNonce`, and that the receiver's balance increased by the transfer amount a second time — proving the delegated `Transfer` executed twice from a single sender authorization.

pub(crate) fn initial_nonce_value(block_height: BlockHeight) -> Nonce {
    // Set default nonce for newly created access key to avoid transaction hash collision.
    // See <https://github.com/near/nearcore/issues/3779>.
    (block_height - 1) * near_primitives::account::AccessKey::ACCESS_KEY_NONCE_RANGE_MULTIPLIER
}

pub(crate) fn action_delete_key(
    config: &RuntimeConfig,
    state_update: &mut TrieUpdate,
    account: &mut Account,
    result: &mut ActionResult,
    account_id: &AccountId,
    delete_key: &DeleteKeyAction,
) -> Result<(), RuntimeError> {
    let access_key = get_access_key(state_update, account_id, &delete_key.public_key)?;
    if let Some(access_key) = access_key {
        if let Some(gas_key_info) = access_key.gas_key_info() {
            delete_gas_key(
                config,
                state_update,
                account,
                result,
                account_id,
                &delete_key.public_key,
                &access_key,
                gas_key_info,
            )?;
        } else {
            delete_regular_key(
                &config.fees,
                state_update,
                account,
                account_id,
                &delete_key.public_key,
                &access_key,
            );
        }
    } else {
        result.result = Err(ActionErrorKind::DeleteKeyDoesNotExist {
            public_key: delete_key.public_key.clone().into(),
            account_id: account_id.clone(),
        }
        .into());
    }
    Ok(())
}

fn delete_gas_key(
    config: &RuntimeConfig,
    state_update: &mut TrieUpdate,
    account: &mut Account,
    result: &mut ActionResult,
    account_id: &AccountId,
    public_key: &PublicKey,
    access_key: &AccessKey,
    gas_key_info: &GasKeyInfo,
) -> Result<(), RuntimeError> {
    if gas_key_info.balance > GasKeyInfo::MAX_BALANCE_TO_BURN {
        result.result = Err(ActionErrorKind::GasKeyBalanceTooHigh {
            account_id: account_id.clone(),
            public_key: Some(Box::new(public_key.clone())),
            balance: gas_key_info.balance,
        }
        .into());
        return Ok(());
    }
    result.tokens_burnt =
        result.tokens_burnt.checked_add(gas_key_info.balance).ok_or(IntegerOverflowError)?;
    let num_nonces = gas_key_info.num_nonces as usize;
    for i in 0..gas_key_info.num_nonces {
        remove_gas_key_nonce(state_update, account_id.clone(), public_key.clone(), i);
    }
    let nonce_key_len = gas_key_nonce_key_len(account_id, &public_key.into());
    let nonce_remove_compute = storage_removes_compute(
        &config.wasm_config.ext_costs,
        num_nonces,
        nonce_key_len * num_nonces,
        AccessKey::NONCE_VALUE_LEN * num_nonces,
    );
    result.compute_usage = safe_add_compute(result.compute_usage, nonce_remove_compute)?;
    remove_access_key(state_update, account_id.clone(), public_key.clone());
    account.set_storage_usage(account.storage_usage().saturating_sub(gas_key_storage_cost(
        &config.fees,
        public_key,
        access_key,
        gas_key_info.num_nonces,
    )));
    Ok(())
}

fn add_regular_key(
    fee_config: &RuntimeFeesConfig,
    state_update: &mut TrieUpdate,
    account: &mut Account,
    account_id: &AccountId,
    public_key: &PublicKey,
    access_key: &AccessKey,
    block_height: BlockHeight,
) -> Result<(), StorageError> {
    let mut access_key = access_key.clone();
    access_key.nonce = initial_nonce_value(block_height);
    set_access_key(state_update, account_id.clone(), public_key.clone(), &access_key);

    account.set_storage_usage(
        account
            .storage_usage()
            .checked_add(access_key_storage_usage(fee_config, public_key, &access_key))
            .ok_or_else(|| {
                StorageError::StorageInconsistentState(format!(
                    "Storage usage integer overflow for account {}",
                    account_id
                ))
            })?,
    );
    Ok(())
}
