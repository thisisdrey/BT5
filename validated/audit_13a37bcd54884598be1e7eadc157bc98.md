## Title
Fee bypass on `TokenDiff` swaps for NEP-245/IMT tokens with unit-value >1 raw unit - (File: `contracts/defuse/core/src/intents/token_diff.rs`)

### Summary
`TokenDiff::token_fee()` waives the protocol fee entirely whenever the traded delta of a `Nep245` or `Imt` token is `<= 1` raw unit, on the (mistaken) assumption that such a small delta can only represent an NFT-like, negligible-value transfer. But unlike `Nep171` (true NFTs, always amount `1`), both `Nep245` (wrapped multi-tokens from any external MT contract) and `Imt` (freely mintable, minter-defined tokens) can represent arbitrarily large economic value in a single raw unit, since their "amount" granularity is entirely controlled by the token's own contract/minter and not tied to a fixed indivisible item.

### Finding Description
`TokenDiff::token_fee()` returns `Pips::ZERO` for `Nep245`/`Imt` tokens whenever `amount <= 1`: [1](#0-0) 

This is applied per-token, per-signer, on the negative ("token_in") side of every `TokenDiff` intent: [2](#0-1) 

For `Nep171` NFTs the amount is always exactly `1` by protocol definition, so the waiver is harmless. However:
- `Nep245TokenId` wraps balances from an arbitrary external multi-token contract with a caller-chosen `mt_token_id`/decimals scheme — a token can legitimately be configured so that "1 unit" is worth an arbitrarily large amount (analogous to a 0-decimal, high-unit-price ERC20/MT). [3](#0-2) 
- `Imt` tokens are minted freely by any account via `ImtMint`, with the minter fully controlling supply/denomination of their own namespace. [4](#0-3) 

Because `token_fee()` only inspects the raw numeric `amount`, not the underlying value, any signer can structure a `TokenDiff` so that the "in" leg for a high-value `Nep245`/`Imt` token has magnitude exactly `1`, causing `fee_ceil()` to be skipped for that entire leg regardless of the actual value transferred: [5](#0-4) 

### Impact Explanation
This directly breaks the "fees owed versus fees collected" binding called out as Critical impact: the protocol fee that should be collected on the value moved through the `TokenDiff` intent is bypassed whenever the negative-delta leg for a `Nep245`/`Imt` token equals `1` raw unit, independent of that unit's real value. No DAO, role holder, or privileged actor is required — any unprivileged user can deposit (via `mt_transfer_call`) or mint (`ImtMint`) a token denominated so that one unit carries large value, then route it through `TokenDiff` fee-free.

### Likelihood Explanation
High likelihood: constructing a `Nep245` wrapped token or `Imt` token with coarse (1-unit) denomination requires no special privilege — depositing any external multi-token contract's asset via `mt_transfer_call`, or minting an `Imt` token via the self-service `ImtMint` intent, both of which are unauthenticated, ordinary user flows. No signature bypass, race condition, or unusual timing is needed; the fee waiver triggers deterministically whenever `amount <= 1`.

### Recommendation
Remove the amount-based fee waiver for `Nep245` and `Imt` token types (only `Nep171` should be exempt, since its amount is protocol-fixed at `1`), or replace the heuristic with an explicit indivisible-item flag carried by the token id/metadata rather than inferring "negligible value" from raw unit count.

### Proof of Concept
1. Attacker deposits (or mints via `ImtMint`) a `Nep245`/`Imt` token configured with 1 unit representing large value (e.g., wrap a 0-decimal external MT token whose single unit is priced highly, or mint an `Imt` token intended to represent a large notional amount as "1 unit").
2. Attacker (or attacker + counterparty) constructs a `TokenDiff` intent where the negative delta on that token is exactly `-1`.
3. `TokenDiff::execute_intent` computes `Self::token_fee(token_id, 1, protocol_fee)`, which returns `Pips::ZERO` per the match arm at `contracts/defuse/core/src/intents/token_diff.rs:211-213`, so no fee is added to `fees_collected` for that leg, even though the swap moves the full (large) value of the token. [6](#0-5)
