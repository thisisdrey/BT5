### Title
`LinkRepositoryToObjectPool` trusts a client-supplied `object_pool` reference based only on a path-naming pattern, enabling cross-repository object disclosure - (File: internal/gitaly/service/objectpool/util.go, internal/gitaly/storage/repository_path.go, internal/git/objectpool/pool.go)

### Summary
`LinkRepositoryToObjectPool` accepts an arbitrary, fully client-controlled `object_pool` repository reference and links the target repository's Git alternates to it after only checking that the reference's *path* matches a naming regex and that *some* Git directory exists there — never verifying that the pool is the one actually associated with (i.e. cloned from) the repository being linked. This is structurally analogous to the reported `LiquidationPairFactory` bug, where an arbitrary `_source` address was accepted as a legitimate vault merely because it "existed" in the factory's registry check, without verifying the deeper trust relationship.

### Finding Description
The RPC handler `LinkRepositoryToObjectPool` [1](#0-0)  takes the `object_pool` field straight from the request and resolves it via `poolForRequest` → `objectpool.FromProto` [2](#0-1) .

`FromProto` performs exactly two checks on the caller-supplied pool reference:
1. `storage.IsPoolRepository(proto.GetRepository())`, a **purely syntactic regex match** on the relative path (`@pools/xx/xx/<sha>.git` or the Praefect cluster pool pattern) [3](#0-2) , with no fallback allowing temp-dir paths.
2. `pool.IsValid(ctx)`, which only calls `locator.ValidateRepository`, confirming the path exists on disk and looks like *a* Git repository (has `objects`, `refs`, `HEAD`) [4](#0-3) [5](#0-4) .

Neither check verifies that this specific pool was actually created from (and is authorized to be linked with) the specific `repository` field of the same request. Any Git object pool that happens to satisfy the naming pattern anywhere in the same storage can be supplied. Once `Link` runs [6](#0-5) , it writes an `objects/info/alternates` entry in the target repository pointing at the supplied pool's object directory with no further ownership check — `getRelativeObjectPath`/`linkedToRepository` merely compute/compare a relative path, they never assert that the pool actually derives from the target repo [7](#0-6) .

This mirrors the external report's root cause precisely: a factory/registry-style existence check ("is this address a pair created by our factory" / "does this path look like a pool") is substituted for an authorization check ("is this the pool that legitimately belongs to this vault/repository"), letting the caller redirect a sensitive resource relationship (fund flow / object visibility) to an attacker-chosen target that merely passes the superficial shape check.

### Impact Explanation
Git alternates grant read access to all objects in the alternate directory, without further access control. Successfully linking a repository to a foreign pool it doesn't legitimately belong to (either an unrelated pool from a different fork tree, or one containing private history) means any process or Git client that reads through the "linked" repository — e.g. via `git cat-file`, blob/commit fetch RPCs, or a subsequent `git clone`/`git fetch` of the linked repo — can retrieve objects from the foreign pool, constituting cross-repository disclosure of potentially private repository data. This is a direct match for the "cross-repository object access" bug class explicitly accepted for this analysis.

### Likelihood Explanation
`object_pool` is a fully attacker/client-controlled field of the RPC request (`LinkRepositoryToObjectPoolRequest.object_pool`) with `additional_repository` annotation [8](#0-7) , meaning the value isn't otherwise pinned to the `repository` field's own derived pool path by the RPC contract or handler logic; the association is done client-side. Any caller with access to the ObjectPoolService (which GitLab Rails and Praefect exercise on behalf of ordinary fork/import operations) can supply a different, syntactically-valid pool path. Because the naming pattern only requires knowledge/discovery of a valid pool's disk path/hash (which may be derivable from repository/project IDs, as seen in `DerivePoolPath`/hash-based scheme [9](#0-8) ), exploitability depends on how well pool paths are kept secret and on the trust boundary of the RPC caller. This is not exploitable directly from an anonymous push/fetch, but is reachable via a "crafted RPC field" from any actor who can invoke `LinkRepositoryToObjectPoolRequest`, which is the intended scope per the validation rules.

### Recommendation
`FromProto`/`poolForRequest` should not treat "matches a pool path naming pattern and exists on disk" as sufficient authorization. Instead:
- Cross-check that the supplied `object_pool` reference is the pool actually recorded as belonging to (or previously created for) the `repository` in the same request, e.g. via Praefect's/Rails' persisted repository-to-pool mapping, or by deriving the expected pool path deterministically from the repository's own ID/relative path rather than trusting the caller-supplied path.
- At minimum, verify a stronger relationship (e.g. that the pool was created via `CreateObjectPool` with this repository as `origin`) before allowing `Link` to write the alternates entry.

### Proof of Concept
1. Attacker (or a caller with access to `ObjectPoolService`) determines/guesses the disk-relative path of a pool repository belonging to a different, private repository tree (path only needs to match `@pools/xx/xx/<sha>.git` or the Praefect cluster pool regex and be a valid Git dir — no ownership binding is enforced) [10](#0-9) .
2. Attacker calls `LinkRepositoryToObjectPool` with `repository` set to a repo they control and `object_pool` set to the foreign pool's reference.
3. `poolForRequest`/`FromProto` accepts the pool because it passes the naming-pattern + `ValidateRepository` checks only [11](#0-10) .
4. `Link` writes `objects/info/alternates` in the attacker's repository pointing to the foreign pool's `objects` directory [12](#0-11) .
5. Attacker fetches/clones from their own repository, and Git transparently serves objects from the foreign pool's object store, disclosing private repository content.

func (s *server) LinkRepositoryToObjectPool(ctx context.Context, req *gitalypb.LinkRepositoryToObjectPoolRequest) (*gitalypb.LinkRepositoryToObjectPoolResponse, error) {
	repository := req.GetRepository()
	if err := s.locator.ValidateRepository(ctx, repository); err != nil {
		return nil, structerr.NewInvalidArgument("%w", err)
	}

	pool, err := s.poolForRequest(ctx, req)
	if err != nil {
		return nil, err
	}

	repo := s.localRepoFactory.Build(repository)

	if err := pool.Link(ctx, repo); err != nil {
		return nil, structerr.NewInternal("%w", err)
	}

	return &gitalypb.LinkRepositoryToObjectPoolResponse{}, nil
}

func (s *server) poolForRequest(ctx context.Context, req PoolRequest) (*objectpool.ObjectPool, error) {
	pool, err := objectpool.FromProto(ctx, s.logger, s.locator, s.gitCmdFactory, s.catfileCache, s.txManager, s.housekeepingManager, req.GetObjectPool())
	if err != nil {
		if errors.Is(err, objectpool.ErrInvalidPoolDir) {
			return nil, errInvalidPoolDir
		}

		if errors.Is(err, objectpool.ErrInvalidPoolRepository) {
			return nil, structerr.NewFailedPrecondition("%w", err)
		}

		return nil, structerr.NewInternal("%w", err)
	}

	return pool, nil

// IsRailsPoolRepository returns whether the repository is a pool repository generated by Rails.
func IsRailsPoolRepository(repo Repository) bool {
	matches := railsPoolDirRegexp.FindStringSubmatch(repo.GetRelativePath())
	if matches == nil || !strings.HasPrefix(matches[3], matches[1]+matches[2]) {
		return false
	}

	return true
}

// IsPraefectPoolRepository returns whether the repository is a Praefect generated object pool repository.
func IsPraefectPoolRepository(repo Repository) bool {
	return praefectPoolDirRegexp.MatchString(repo.GetRelativePath())
}

// IsPoolRepository returns whether the repository is an object pool.
func IsPoolRepository(repo Repository) bool {
	return IsRailsPoolRepository(repo) || IsPraefectPoolRepository(repo)
}

func Link(ctx context.Context, pool, repo *localrepo.Repo, txManager transaction.Manager) (returnedErr error) {
	altPath, err := repo.InfoAlternatesPath(ctx)
	if err != nil {
		return err
	}

	expectedRelPath, err := getRelativeObjectPath(ctx, pool, repo)
	if err != nil {
		return err
	}

	linked, err := linkedToRepository(ctx, pool, repo)
	if err != nil {
		return err
	}

	if linked {
		// When the repository is already linked to the repository, cast a vote to ensure the
		// repository is consistent with the other replicas.
		if err := transaction.VoteOnContext(ctx, txManager, voting.VoteFromData([]byte("repository linked")), voting.Synchronized); err != nil {
			return fmt.Errorf("vote on linked repository: %w", err)
		}

		return nil
	}

	alternatesWriter, err := safe.NewLockingFileWriter(altPath)
	if err != nil {
		return fmt.Errorf("creating alternates writer: %w", err)
	}
	defer func() {
		if err := alternatesWriter.Close(); err != nil && returnedErr == nil {
			returnedErr = fmt.Errorf("closing alternates writer: %w", err)
		}
	}()

	if _, err := io.WriteString(alternatesWriter, expectedRelPath); err != nil {
		return fmt.Errorf("writing alternates: %w", err)
	}

	if err := transaction.CommitLockedFile(ctx, txManager, alternatesWriter); err != nil {
		return fmt.Errorf("committing alternates: %w", err)
	}

	if tx := storage.ExtractTransaction(ctx); tx != nil {
		alternatesRelativePath, err := filepath.Rel(tx.FS().Root(), altPath)
		if err != nil {
			return fmt.Errorf("rel alternates file: %w", err)
		}

		if err := tx.FS().RecordFile(alternatesRelativePath); err != nil {
			return fmt.Errorf("record alternates file")
		}
	}

	return removeMemberBitmaps(ctx, pool, repo)
}

func getRelativeObjectPath(ctx context.Context, pool, repo *localrepo.Repo) (string, error) {
	poolPath, err := pool.Path(ctx)
	if err != nil {
		return "", fmt.Errorf("getting object pool path: %w", err)
	}

	repoPath, err := repo.Path(ctx)
	if err != nil {
		return "", fmt.Errorf("getting repository path: %w", err)
	}

	relPath, err := filepath.Rel(filepath.Join(repoPath, "objects"), poolPath)
	if err != nil {
		return "", err
	}

	return filepath.Join(relPath, "objects"), nil
}

}
