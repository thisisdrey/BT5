### Title
Unauthenticated HTTP event ingestion in the signer's `SignerEventReceiver` allows forged event injection and remote shutdown — (File: `libsigner/src/events.rs`)

### Summary
`SignerEventReceiver::next_event` in `libsigner/src/events.rs` accepts and processes any HTTP POST to `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block`, and `/shutdown` without validating any `Authorization`/auth-token header, even though the node/signer configuration explicitly documents an `auth_token`/`auth_password` pair that is supposed to gate this channel.

### Finding Description
The signer runs a bare `tiny_http` server (`self.http_server`) and its request dispatcher only branches on HTTP method and URL path: [1](#0-0) 
There is no check of any header, token, or credential before the request body is parsed and converted into a `SignerEvent`: [2](#0-1) 
The `/shutdown` path is handled the same way — no authentication is checked before it sets `stop_signal` and terminates the receiver loop: [3](#0-2) 

Documentation states that `auth_password` (signer side) and `[connection_options] auth_token` (node side) "must match" as a security control coordinating the node and the signer: [4](#0-3) 
and sample configs surface `auth_token`/`auth_password` as if it were an enforced credential: [5](#0-4) 

However, `grep` across `libsigner/**` finds zero references to `auth_token`, `auth_password`, or `Authorization` — the receiving side (`SignerEventReceiver`) never checks any such value. This breaks the intended equality "request came from the paired/authenticated node" vs. "request came from any TCP peer that can reach the bound port" (by default `0.0.0.0:30000` per the sample config). Any host that can reach the signer's event port can POST a forged `StackerDBChunksEvent`, `BlockValidateResponse`, `BurnBlockEvent`, or `StacksBlockEvent`, which is parsed and forwarded into the signer's runloop exactly as if it came from the legitimate, paired stacks-node — or can silently shut the signer process down via `/shutdown`.

### Impact Explanation
- Unauthenticated remote DoS: any network peer reaching the bound port can hit `/shutdown` and terminate the signer's event receiver loop with a single unauthenticated POST — "Critical: remote crash / unauthenticated DoS from few messages."
- Unauthenticated write of forged data into signer state: a forged `StackerDBChunksEvent`/`BlockValidateResponse` is fed into `TryFrom<StackerDBChunksEvent> for SignerEvent<T>` and forwarded to the signer runloop as legitimate node-originated data: [6](#0-5) 
This matches the report's "unauthenticated/unauthorized write to state" impact category, since the intended trust boundary (only the paired node may push events) is not enforced at the transport layer.

### Likelihood Explanation
The signer's event endpoint is meant to bind on a configurable address; sample configs bind to `0.0.0.0:30000`, which is reachable from any host that can route to it (e.g., same LAN, cloud security group misconfiguration, or a compromised adjacent service). No secret, node key, or privileged role is required to exploit this — only network reachability to the configured port, satisfying the "remote, unprivileged" requirement.

### Recommendation
Enforce the documented `auth_token`/`auth_password` as an actual authentication check in `SignerEventReceiver::next_event` (or `process_event`) before parsing/dispatching any request, e.g., verifying an `Authorization` header/shared secret constant-time comparison, and reject/respond 401 otherwise, especially before acting on `/shutdown`.

### Proof of Concept
1. Start `stacks-signer` with its HTTP event listener bound per `mainnet-signer-conf.toml` (e.g., `0.0.0.0:30000`).
2. From any host that can reach that port, send an unauthenticated POST:
   `curl -X POST http://<signer-host>:30000/shutdown` — the signer's event receiver loop terminates immediately (matches the code path at `libsigner/src/events.rs:443-445`, no credential required).
3. Similarly, POST a crafted JSON body to `/stackerdb_chunks` matching the `StackerDBChunksEvent` schema; it is deserialized and forwarded into the signer runloop as if it came from the paired node (`libsigner/src/events.rs:437-438`, `544-567`), with no origin verification.

Note: I could not find any authentication enforcement code elsewhere in the indexed `libsigner` sources; if such a check exists in code not covered by the index, this finding should be reverified, but no citation supports its existence based on available search results.

    fn next_event(&mut self) -> Result<SignerEvent<T>, EventError> {
        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)
            } else if request.url() == "/new_block" {
                process_event::<T, StacksBlockEvent>(request)
            } else {
                let url = request.url().to_string();
                debug!(
                    "[{:?}] next_event got request with unexpected url {}, return OK so other side doesn't keep sending this",
                    event_receiver.local_addr,
                    url
                );
                ack_dispatcher(request);
                Err(EventError::UnrecognizedEvent(url))
            }
        })?
    }

fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}
