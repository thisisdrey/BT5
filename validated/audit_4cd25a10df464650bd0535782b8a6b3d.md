## Title
Wrong base fee used in EIP-7918 blob "reserve price" comparison causes consensus-divergent `excessBlobGas` — (File: `consensus/misc/eip4844/eip4844.go`)

## Summary
`calcExcessBlobGas` implements the post-Osaka EIP-7918 reserve-price branch by comparing `BLOB_BASE_COST * base_fee` against the blob base fee. The spec's reserve price is defined in terms of the **current block's** `base_fee_per_gas` (the header being built/verified), but the go-ethereum implementation instead multiplies `BLOB_BASE_COST` by `parent.BaseFee` — the **previous** block's base fee. This mirrors the Opus bug class: the wrong variable is substituted into a threshold comparison (`threshold` instead of `ltv`), here `parent.BaseFee` instead of `header.BaseFee`, causing the "which branch of the formula applies" decision to be computed against a stale value.

## Finding Description
`CalcExcessBlobGas` is defined to take only `parent` and `headTimestamp`, deliberately discarding the current header's `BaseFee`: [1](#0-0) 

Inside `calcExcessBlobGas`, the EIP-7918 reserve-price check is performed using `parent.BaseFee`: [2](#0-1) 

```go
if isOsaka {
    var (
        baseCost     = big.NewInt(params.BlobBaseCost)
        reservePrice = baseCost.Mul(baseCost, parent.BaseFee)
        blobPrice    = bcfg.blobPrice(parentExcessBlobGas)
    )
    if reservePrice.Cmp(blobPrice) > 0 {
        scaledExcess := parentBlobGasUsed * uint64(bcfg.Max-bcfg.Target) / uint64(bcfg.Max)
        return parentExcessBlobGas + scaledExcess
    }
}
```

The important detail is that when this function is invoked from block-building/verification, the *current* block's `BaseFee` has already been computed (via `eip1559.CalcBaseFee(config, parent)`) before `CalcExcessBlobGas` is called — e.g. in the miner: [3](#0-2) 

and in header verification, `VerifyEIP4844Header` is handed both `parent` and `header` but only forwards `header.Time`, never `header.BaseFee`: [4](#0-3) 

So the correct, already-available current-block base fee is silently replaced by the parent's (stale) base fee for the reserve-price comparison. Because EIP-1559 base fee moves every block based on the parent's gas usage, `parent.BaseFee` and the current block's `BaseFee` regularly diverge — and near the reserve-price crossover point, that divergence flips which formula branch (`reservePrice > blobPrice` vs. not) is taken, producing a different `excessBlobGas` value than a spec-conformant implementation would compute for the identical block.

A repo-local comment even documents that the implementation "requires parent.BaseFee to be properly set" for this calculation, confirming this is the value actually consumed, rather than the header's own base fee: [5](#0-4) 

## Impact Explanation
`excessBlobGas` is a consensus-critical header field. `VerifyEIP4844Header` rejects a header if `*header.ExcessBlobGas != expectedExcessBlobGas`: [6](#0-5) 

If Geth's `expectedExcessBlobGas` diverges from what other, spec-compliant clients compute (because they correctly use the current header's base fee rather than the parent's), then:
- A block considered valid by other clients could be rejected by Geth (DoS on Geth), or
- A block Geth proposes/accepts with its self-computed `excessBlobGas` could be rejected by every other client, since it does not match the value they derive from the true spec formula.

Either direction is a mainnet consensus split for any block whose parent/current base fee move places the reserve-price comparison on opposite sides of the threshold depending on which base fee is used — satisfying the "Critical: consensus split where Geth accepts/rejects a block other clients treat oppositely" bar. This also directly feeds `CalcBlobFee`/blob gas pricing used throughout `core`, `miner`, and `eth/gasprice`, so the wrong value also miscalculates blob gas fees paid/burned for every blob transaction in the affected block once Osaka activates.

## Likelihood Explanation
This is deterministic and requires no adversarial input beyond ordinary blob-gas market movement: any block sequence around the Osaka activation where blob gas usage is near/above target and the parent-to-header base fee delta straddles the reserve-price/blob-price crossover will trigger divergent computation. Given base fee updates every block under EIP-1559, and blob markets frequently operate near their target, this is a routine — not contrived — scenario once the Osaka fork (and EIP-7918) is live on mainnet.

## Recommendation
Thread the current header's `BaseFee` through to `calcExcessBlobGas` (rather than reusing `parent.BaseFee`) so the reserve-price comparison matches the EIP-7918 formula's use of the block-being-computed's base fee:
```go
func CalcExcessBlobGas(config *params.ChainConfig, parent, header *types.Header) uint64 {
    ...
    return calcExcessBlobGas(isOsaka, bcfg, parent, header.BaseFee)
}
```
and update all call sites (`VerifyEIP4844Header`, `miner/worker.go`, `internal/ethapi/simulate.go`, `eth/gasprice/feehistory.go`, `cmd/evm/internal/t8ntool/execution.go`) to supply the current header's base fee instead of relying on `parent.BaseFee`.

## Proof of Concept
1. Construct `parent` header at Osaka activation with `parent.BaseFee = B1`, `parent.ExcessBlobGas = E`, `parent.BlobGasUsed` at or above target, such that `blobPrice(E) ≈ BLOB_BASE_COST * B1` (i.e., right at the crossover).
2. Let the actual/new block's base fee `B2 = eip1559.CalcBaseFee(config, parent)` differ from `B1` (guaranteed whenever `parent.GasUsed != parentGasTarget`), such that `BLOB_BASE_COST * B2` falls on the opposite side of `blobPrice(E)` from `BLOB_BASE_COST * B1`.
3. A spec-conformant client computes `excessBlobGas` using `reserve_price = BLOB_BASE_COST * B2` (current header's base fee) and takes one formula branch.
4. Geth, via `calcExcessBlobGas`, computes `reservePrice = BLOB_BASE_COST * B1` (parent's stale base fee) — landing on the other branch — producing a different `excessBlobGas` value in the block header.
5. When this block is exchanged between Geth and any spec-correct client, one side will reject it via the `VerifyEIP4844Header` excessBlobGas mismatch check, causing a fork/consensus split.

```go
func VerifyEIP4844Header(config *params.ChainConfig, parent, header *types.Header) error {
	if header.Number.Uint64() != parent.Number.Uint64()+1 {
		panic("bad header pair")
	}

	bcfg, err := latestBlobConfig(config, header.Time)
	if err != nil {
		panic("called before EIP-4844 is active")
	}

	if header.ExcessBlobGas == nil {
		return errors.New("header is missing excessBlobGas")
	}
	if header.BlobGasUsed == nil {
		return errors.New("header is missing blobGasUsed")
	}

	// Verify that the blob gas used remains within reasonable limits.
	if *header.BlobGasUsed > bcfg.maxBlobGas() {
		return fmt.Errorf("blob gas used %d exceeds maximum allowance %d", *header.BlobGasUsed, bcfg.maxBlobGas())
	}
	if *header.BlobGasUsed%params.BlobTxBlobGasPerBlob != 0 {
		return fmt.Errorf("blob gas used %d not a multiple of blob gas per blob %d", *header.BlobGasUsed, params.BlobTxBlobGasPerBlob)
	}

	// Verify the excessBlobGas is correct based on the parent header
	expectedExcessBlobGas := CalcExcessBlobGas(config, parent, header.Time)
	if *header.ExcessBlobGas != expectedExcessBlobGas {
		return fmt.Errorf("invalid excessBlobGas: have %d, want %d", *header.ExcessBlobGas, expectedExcessBlobGas)
	}
	return nil
```

```go
func CalcExcessBlobGas(config *params.ChainConfig, parent *types.Header, headTimestamp uint64) uint64 {
	isOsaka := config.IsOsaka(config.LondonBlock, headTimestamp)
	bcfg, err := latestBlobConfig(config, headTimestamp)
	if err != nil {
		panic("calculating excess blob gas on nil blob config")
	}
	return calcExcessBlobGas(isOsaka, bcfg, parent)
}
```
