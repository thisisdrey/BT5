### Title
Unprotected/Permissionless `init_global_fee_state` Allows Front-Running to Hijack Global Fee Admin and Fee Wallet - ([File: programs/marginfi/src/instructions/marginfi_group/init_global_fee_state.rs])

### Summary
The `init_global_fee_state` instruction, which creates the singular, program-wide `FeeState` PDA and sets its `global_fee_admin` and `global_fee_wallet` fields, is callable by any signer with no restriction on who may invoke it. Because the `FeeState` account is a PDA derived solely from `FEE_STATE_SEED` (one per program, ever), whoever's transaction lands first permanently becomes the `global_fee_admin` and receives all protocol fees. This mirrors the Rocket Pool `RocketStorage` finding: a state-defining initialization step that should only be reachable by the deployer/guardian is left open to any account during the window before the legitimate deployment transaction executes.

### Finding Description
`initialize_fee_state` accepts an arbitrary `admin_key` and `fee_wallet` argument and writes them directly into the `FeeState` account with no `has_one`, `require!`, or upgrade-authority check on the caller: [1](#0-0) 

The account constraints only require a `Signer` `payer` and use Anchor's `init` (create-once) semantics on the PDA seeds `[FEE_STATE_SEED]`: [2](#0-1) 

The instruction handler in `lib.rs` documents this as "(Runs once per program)" but enforces nothing programmatically — it is purely a comment, not an access-control check: [3](#0-2) 

Since `FeeState` is a PDA with fixed seeds and no bump-authority validation tying it to the program's upgrade authority or any known "guardian" pubkey, and since Anchor's `init` constraint will succeed for the *first* transaction that lands regardless of sender, any account can call `init_global_fee_state` with itself as `admin_key` and its own wallet as `fee_wallet` before the legitimate deployer's transaction is confirmed. This is exactly the bug class described in the Rocket Pool report: an unprotected, first-writer-wins initialization step exploitable during the deployment window, allowing an attacker to seize a critical privileged role (here, `global_fee_admin`) that subsequently controls protocol-wide fee configuration (`edit_global_fee_state`, gated only by `has_one = global_fee_admin`): [4](#0-3) 

Once hijacked, the attacker-controlled `global_fee_admin` can call `edit_global_fee_state` to redirect `global_fee_wallet` and adjust `program_fee_fixed`/`program_fee_rate`, capturing protocol-wide fee revenue that flows into the `fee_state_cache` used by every `MarginfiGroup`.

### Impact Explanation
If exploited during (re)deployment (e.g., on a new cluster, or if the FeeState PDA needs to be recreated after a migration), an attacker who front-runs `init_global_fee_state` obtains permanent, un-recoverable control of `global_fee_admin` and `global_fee_wallet`. Because `FeeState` can only be `init`'d once per program (PDA uniqueness), this is not remediable without a program upgrade/migration, and it lets the attacker redirect all protocol program fees to their own wallet and adjust fee parameters, directly resulting in theft of protocol fee revenue and an unauthorized state change to a program-wide privileged role.

### Likelihood Explanation
This requires the attacker to observe/front-run a live, unconfirmed `init_global_fee_state` transaction on-chain (mempool/leader-schedule monitoring), which is feasible for any deployment of marginfi to a new cluster or in disaster-recovery/migration scenarios where the PDA must be re-initialized. Given marginfi is a high-profile, high-TVL protocol, motivation for a targeted attacker exists, matching the Rocket Pool report's threat model precisely (unprotected setup transactions during a non-atomic deployment sequence).

### Recommendation
Restrict `init_global_fee_state` (and similarly `init_global_fee_state_v2`) so it can only be executed by a known, trusted principal — e.g., require the payer/caller to equal the program's upgrade authority (checked via the `BPFLoaderUpgradeable` program state) or a hardcoded "guardian" pubkey compiled into the program, analogous to the Rocket Pool fix that requires calls to originate from the deployer/guardian during initialization. Alternatively, require that this instruction can only be invoked once as part of an atomically-bundled deployment transaction that also verifies the signer against an expected constant.

### Proof of Concept
1. Deployer publishes the marginfi program to a new cluster (or a migration requires the `FeeState` PDA to be created).
2. Attacker observes the mempool/upcoming slot for a transaction calling `init_global_fee_state` (or simply races to call it first if no one else has).
3. Attacker submits `init_global_fee_state(admin_key = attacker_pubkey, fee_wallet = attacker_wallet, ...)` targeting the same PDA `[FEE_STATE_SEED]` before the legitimate deployer's transaction lands.
4. Because `fee_state` uses Anchor's `init` (create-once semantics) and there is no signer restriction in `InitFeeState`, the attacker's transaction succeeds and permanently sets `fee_state.global_fee_admin = attacker_pubkey`.
5. Attacker now calls `edit_global_fee_state` (which only checks `has_one = global_fee_admin`) to redirect `global_fee_wallet` to an attacker-controlled account and adjust `program_fee_fixed`/`program_fee_rate`, capturing protocol fee revenue going forward.

pub fn initialize_fee_state(
    ctx: Context<InitFeeState>,
    admin_key: Pubkey,
    fee_wallet: Pubkey,
    bank_init_flat_sol_fee: u32,
    liquidation_flat_sol_fee: u32,
    order_init_flat_sol_fee: u32,
    program_fee_fixed: WrappedI80F48,
    program_fee_rate: WrappedI80F48,
    liquidation_max_fee: WrappedI80F48,
    order_execution_max_fee: WrappedI80F48,
) -> Result<()> {
    let mut fee_state = ctx.accounts.fee_state.load_init()?;
    fee_state.global_fee_admin = admin_key;
    fee_state.global_fee_wallet = fee_wallet;
    fee_state.key = ctx.accounts.fee_state.key();
    fee_state.bank_init_flat_sol_fee = bank_init_flat_sol_fee;
    fee_state.bump_seed = ctx.bumps.fee_state;
    fee_state.program_fee_fixed = program_fee_fixed;
    fee_state.program_fee_rate = program_fee_rate;
    fee_state.liquidation_max_fee = liquidation_max_fee;
    fee_state.liquidation_flat_sol_fee = liquidation_flat_sol_fee;
    fee_state.order_execution_max_fee = order_execution_max_fee;
    fee_state.order_init_flat_sol_fee = order_init_flat_sol_fee;

    Ok(())
}
