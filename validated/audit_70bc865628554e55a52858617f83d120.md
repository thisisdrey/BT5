Based on my investigation, I found a real issue, but it's not in `MarshalPayload` — that function only serializes outgoing handshake payloads and has no attacker-reachable path to session teardown. The actual reachable teardown path is `handleRecvError` in `outside.go`, triggered by `header.RecvError` packets, which matches the "teardown/recv-error style packet" exploit idea in the question.

### Title
Unauthenticated `RecvError` packet can tear down an established session without proving key possession - (File: outside.go)

### Summary
`Interface.handleRecvError` closes an active tunnel based solely on an unauthenticated `header.RecvError` packet whose `RemoteIndex` matches a live session's local index, with only a weak source-address check (skipped entirely if the hostinfo's remote is not yet "valid") rather than cryptographic proof that the sender holds the session's Noise keys.

### Finding Description
In `readOutsidePackets` (outside.go:81-83), a packet with `h.Type == header.RecvError` is dispatched directly to `f.handleRecvError(via.UdpAddr, h)` before any decryption or authentication — `RecvError` packets are explicitly unencrypted (comment at outside.go:75 "Unencrypted packets"). `handleRecvError` (outside.go:541-575) looks up the session by `f.hostMap.QueryReverseIndex(h.RemoteIndex)`, and the only anti-spoofing check is:
```go
hr := hostinfo.GetRemote()
if hr.IsValid() && hr != addr {
    ...return
}
f.closeTunnel(hostinfo)
f.handshakeManager.DeleteHostInfo(hostinfo)
``` [1](#0-0) 
This check only compares the UDP source address against the last known remote — it does not authenticate that the sender possesses the session's Noise keys. UDP source addresses are trivially spoofable from an unprivileged network position, and if `hr.IsValid()` is false (e.g., before the host has roamed/been confirmed), the check is skipped entirely. An attacker who can guess or observe a live session's local index (`h.RemoteIndex`, a 32-bit value carried on-wire in every packet to that peer) and spoof the UDP source address can force `closeTunnel` and `handshakeManager.DeleteHostInfo`, tearing down the tunnel and forcing re-handshake — all without ever completing a Noise handshake or proving key possession.

The related `header.CloseTunnel` message type (outside.go:164-166) *is* properly authenticated, since it flows through the encrypted `Decrypt` path first (outside.go:126) — only `RecvError` bypasses this.

### Impact Explanation
This is a denial-of-service that lets an unprivileged network attacker tear down another host's live Nebula tunnel by spoofing a single unencrypted UDP packet, matching the "Denial of service tearing down another host's tunnel from an unprivileged network position" impact category referenced in the question.

### Likelihood Explanation
Feasible: `RecvError` handling is gated by `f.acceptRecvErrorConfig.ShouldRecvError(addr)` (outside.go:542), which in default/permissive configurations can allow processing from arbitrary addresses; the index value is a 32-bit local index that is observable on the wire for any traffic to/from the target and thus not secret. Feasibility of exact source-address spoofing depends on network path (return-routability is not required since this is a fire-and-forget UDP packet), which is consistent with the "spoofed source addresses" attacker capability allowed by the rules.

### Recommendation
Require cryptographic authentication before acting on `RecvError` (and any other teardown-triggering unencrypted packet types) — e.g., only process it if it can be tied to a valid, freshly authenticated exchange, or better, deprecate unauthenticated `RecvError` teardown entirely in favor of the already-authenticated `CloseTunnel` message, and make the reverse-index lookup optionally rate-limited/challenge-based rather than relying on UDP source-address equality as a security boundary.

### Proof of Concept
Integration test plan (extending patterns in `e2e/handshakes_test.go` / `e2e/tunnels_test.go`):
1. Establish two nodes A and B with a completed, authenticated tunnel (confirm data-plane traffic flows).
2. From a third, unauthenticated UDP socket, spoof the source address to match B's known address and send a `header.RecvError` packet to A with `RemoteIndex` set to the local index A uses for its session with B (observed from a captured packet header).
3. Assert that A's `hostMap` no longer contains the hostinfo for B (`closeTunnel` was invoked) even though no Noise handshake message was ever exchanged by the attacker — i.e., the session was torn down without proof of key possession.
4. As a control, repeat with an incorrect `RemoteIndex` and confirm no teardown occurs, and repeat with `hr.IsValid()==false` (pre-roam state) to show the address check is bypassed entirely in that state. [2](#0-1) [3](#0-2)

func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
