Confirmed: `SwapFirstAssetTrader` is wired into live parachain runtimes' XCM configs — asset-hub-rococo, asset-hub-westend, penpal, and staking-async parachain — as the trader for weight/fee handling.Audit Report

## Title
`SwapFirstAssetTrader::refund_weight` executes the fee-refund swap with `amount_out_min = None`, allowing pool-price manipulation to drain the swap pool during XCM weight refunds - (File: `cumulus/primitives/utility/src/lib.rs`)

## Summary
`SwapFirstAssetTrader` swaps a non-`Target` fee asset into `Target` during `buy_weight` using an exact-output swap, but on the refund path it swaps `Target` back into the original asset via `SwapCredit::swap_exact_tokens_for_tokens(vec![Target::get(), refund_swap_asset], refund, None)` with the minimum-output parameter hard-coded to `None`. [1](#0-0)  Every other swap invocation in the same struct and in `pallet_asset_conversion` enforces a non-zero output/input bound, making this refund path the only unprotected swap-consuming call.

## Finding Description
`buy_weight` converts the sender's asset into exactly `fee` amount of `Target` using `swap_tokens_for_exact_tokens`, which inherently bounds the input consumed. [2](#0-1)  `refund_weight`, executed automatically by the XCM executor when weight is unused, extracts `refund_amount` from `total_fee` (in `Target`) and swaps it back to `refund_swap_asset` with no floor on the output: [3](#0-2) 

`pallet_asset_conversion`'s underlying pools are permissionless constant-product AMMs; `do_swap_exact_tokens_for_tokens` only checks `amount_out_min` if one was actually supplied, and skips the check entirely when `None` is passed — which is exactly the case here. [4](#0-3)  Any account can shift pool reserves via ordinary permissionless `add_liquidity`/`remove_liquidity`/`swap_exact_tokens_for_tokens` calls, as shown by `do_add_liquidity`'s unrestricted access pattern. [5](#0-4)  Since the refund swap is deterministic and triggered as part of normal XCM processing, an attacker can manipulate the `(Target, refund_swap_asset)` pool reserves immediately before the refund executes, forcing the unbounded swap to execute at an arbitrarily bad rate and extracting value from liquidity providers.

## Impact Explanation
This is a genuine, reachable defect: the fee-refund swap in a public, unprivileged, automatically-triggered XCM code path lacks the minimum-output protection that the pallet enforces on the equivalent code path when a bound is supplied, and that `buy_weight` achieves implicitly via exact-output swapping. `SwapFirstAssetTrader` is confirmed wired into live runtime configs as the XCM weight trader in `asset-hub-rococo`, `asset-hub-westend`, `penpal`, and the staking-async parachain. [6](#0-5) [7](#0-6) [8](#0-7) [9](#0-8)  This enables value extraction from AMM liquidity providers via sandwich-style manipulation, matching the "public underpriced work" / value-conservation-violation impact class in the required Impact Gate.

## Likelihood Explanation
Exploitation requires only ordinary, unprivileged capabilities: an attacker constructs an XCM message paying fees in a non-`Target` asset with weight overpayment (to trigger a subsequent refund), and either front-runs/sandwiches the refund with an ordinary permissionless `swap_exact_tokens_for_tokens`/liquidity call on the relevant pool, or otherwise arranges for the pool state to be skewed at refund time. No relayer, validator, governance, or privileged role is required, and the refund path executes deterministically whenever unused weight exists after `buy_weight`, so the vulnerable code is reliably reachable from ordinary XCM traffic.

## Recommendation
Pass a computed `amount_out_min` to `swap_exact_tokens_for_tokens` in `refund_weight`, derived from a fresh `QuotePrice::quote_price_exact_tokens_for_tokens` call with an acceptable tolerance, mirroring the bound already implicit in `buy_weight`'s exact-output swap; if the achievable output falls below this bound, return the refund back into `total_fee` (as already done on the `Err` branch) rather than executing an unbounded swap.

## Proof of Concept
1. Configure a runtime with `SwapFirstAssetTrader<Target, AssetConversion, ...>` as the XCM `WeightTrader` (e.g., asset-hub-westend style config referencing `cumulus/parachains/runtimes/assets/asset-hub-westend/src/xcm_config.rs`).
2. Submit an XCM program paying fees in `AssetX` (≠ `Target`) with an amount larger than the exact weight fee, so `buy_weight` swaps exactly `fee` into `Target` and holds the remainder in `total_fee` pending refund.
3. Before the refund executes (same block/earlier extrinsic), call `AssetConversion::swap_exact_tokens_for_tokens` or add/remove liquidity to skew the `(Target, AssetX)` pool reserves unfavorably for a subsequent `Target -> AssetX` swap.
4. When the XCM executor invokes `refund_weight`, observe that `SwapCredit::swap_exact_tokens_for_tokens(vec![Target, AssetX], refund, None)` executes at the manipulated price with no floor, verifiable by comparing resulting `AssetX` payout against the pre-manipulation expected constant-product price — demonstrating value extraction from pool reserves.

	fn refund_weight(&mut self, weight: Weight, _context: &XcmContext) -> Option<AssetsInHolding> {
		log::trace!(
			target: "xcm::weight",
			"SwapFirstAssetTrader::refund_weight weight: {:?}, self.total_fee: {:?}",
			weight,
			self.total_fee,
		);
		if weight.is_zero() || self.total_fee.peek().is_zero() {
			// noting to refund.
			return None;
		}
		let refund_asset = if let Some(asset) = &self.last_fee_asset {
			// create an initial zero refund in the asset used in the last `buy_weight`.
			(asset.clone(), Fungible(0)).into()
		} else {
			return None;
		};
		let refund_amount = WeightToFee::weight_to_fee(&weight);
		if refund_amount >= self.total_fee.peek() {
			// not enough was paid to refund the `weight`.
			return None;
		}

		let refund_swap_asset = FungiblesAssetMatcher::matches_fungibles(&refund_asset)
			.map(|(a, _)| a.into())
			.ok()?;

		let refund = self.total_fee.extract(refund_amount);
		let refund = match SwapCredit::swap_exact_tokens_for_tokens(
			vec![Target::get(), refund_swap_asset],
			refund,
			None,
		) {
			Ok(refund_in_target) => refund_in_target,
			Err((refund, _)) => {
				// return an attempted refund back to the `total_fee`.
				let _ = self.total_fee.subsume(refund).map_err(|refund| {
					// error may occur if `total_fee.asset` differs from `refund.asset`, which does
					// not apply in this context.
					defensive!(
						"`total_fee.asset` must be equal to `refund.asset`",
						(self.total_fee.asset(), refund.asset())
					);
				});
				return None;
			},
		};
