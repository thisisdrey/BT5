### Title
Unauthenticated write to Signer event pipeline via `SignerEventReceiver` HTTP listener - ([File: libsigner/src/events.rs])

### Summary
The `SignerEventReceiver::next_event()` handler in `libsigner/src/events.rs`, which processes inbound HTTP POSTs to `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, and `/new_block`, performs **no authentication check** of any kind before deserializing and forwarding the event body into the signer runloop. This is inconsistent with every comparable privileged RPC surface in `stackslib/src/net/api/**` (e.g. `postblock_proposal.rs`, `txsimulate.rs`, `blockreplay.rs`), all of which require an `authorization` header to match a configured password/token before processing the request.

### Finding Description
`SignerEventReceiver::bind()` opens a plain `tiny_http` server on the configured `endpoint` [1](#0-0) . `next_event()` then dispatches incoming requests purely by URL path — `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block`, `/status`, `/shutdown` — with no header, token, or origin check anywhere in the function [2](#0-1) . `process_event()` simply reads the body, ACKs the sender, and deserializes JSON into the corresponding event type, again with no authentication gate [3](#0-2) .

Contrast this with the node-side RPC handlers in scope, which explicitly require and check a shared secret before honoring privileged requests, e.g. `postblock_v3.rs`'s broadcast gate [4](#0-3)  and `blockreplay.rs`'s unconditional password check [5](#0-4) . The documentation even instructs operators to configure a shared `auth_token`/`auth_password` between the node and the signer [6](#0-5) , but this secret is only used to authenticate the node's node→signer calls at the HTTP client layer elsewhere in `stackslib`; it is never checked by `SignerEventReceiver` itself. The equality that should hold — "this event was authentically produced by the local trusted Stacks node" — is never verified; any TCP client able to reach the bound listener can produce well-formed JSON for any of these four endpoints and have it treated as if it came from the node.

### Impact Explanation
Since `SignerEvent::SignerMessages`, `SignerEvent::BlockValidationResponse`, `SignerEvent::NewBurnBlock`, and `SignerEvent::NewBlock` are fed directly into the signer's `run_one_pass` runloop [7](#0-6) , an attacker who can reach this HTTP port can inject arbitrary/forged events into the signer state machine without needing any node or signer key. Depending on deployment (any binding other than a strictly firewalled loopback interface — which is a deployment assumption, not something the code enforces), this can drive the signer into acting on forged `BlockValidationResponse` or fabricated burn/tenure events, i.e., "network-wide propagation of forged data" / "unauthenticated write to state" into the signer's decision inputs. The severity depends on what downstream validation (if any) individual `SignerMessage`/`StackerDBChunksEvent` payloads receive once inside the runloop, which is signer decision logic and out of scope here — but the transport-layer authentication gap itself is a clear, in-scope defect.

### Likelihood Explanation
Exploitability requires network reachability to the `SignerEventReceiver`'s bound socket. The default sample configs bind it to `127.0.0.1`, but the code performs no origin/token check and the operator docs themselves warn: "exercise caution if you are communicating with an external node ... this could potentially expose sensitive data or functionalities to security risks if additional proper security checks are not integrated" [8](#0-7) . This warning corroborates that the code provides no protection of its own and relies entirely on network topology — any misconfiguration (non-loopback bind, container/NAT exposure, SSRF from a compromised co-located service) makes this remotely, unauuthenticatedly exploitable.

### Recommendation
Add a mandatory shared-secret (or mTLS) check in `SignerEventReceiver::next_event()`/`process_event()`, mirroring the `authorization` header validation already used in `stackslib/src/net/api/postblock_v3.rs` and `blockreplay.rs`, so that requests to `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, and `/new_block` are rejected unless they carry a valid token matching the signer's configured `auth_password`.

### Proof of Concept
1. Start a `stacks-signer` instance with its event listener bound per its `endpoint` config.
2. From any host that can reach that TCP port (not just the paired node), send:
```
POST /stackerdb_chunks HTTP/1.1
Host: <signer-endpoint>
Content-Type: application/json
Content-Length: <n>

{"contract_id": "...", "modified_slots": [ ... forged StackerDBChunkData ... ]}
```
No `authorization` header or token is required — `next_event()` dispatches straight to `process_event::<T, StackerDBChunksEvent>(request)` and forwards the resulting `SignerEvent` to the runloop, as demonstrated (without any auth headers) by the existing test harness that feeds chunks over a raw `TcpStream` [9](#0-8) .

    fn next_event(&mut self) -> Result<SignerEvent<T>, EventError> {
        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)
            } else if request.url() == "/new_block" {
                process_event::<T, StacksBlockEvent>(request)
            } else {
                let url = request.url().to_string();
                debug!(
                    "[{:?}] next_event got request with unexpected url {}, return OK so other side doesn't keep sending this",
                    event_receiver.local_addr,
                    url
                );
                ack_dispatcher(request);
                Err(EventError::UnrecognizedEvent(url))
            }
        })?
    }

fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}

    fn main_loop<EVST: EventStopSignaler>(
        &mut self,
        event_recv: Receiver<SignerEvent<T>>,
        result_send: Sender<R>,
        mut event_stop_signaler: EVST,
    ) -> Option<R> {
        info!("Signer runloop begin");
        loop {
            let poll_timeout = self.get_event_timeout();
            let next_event_opt = match event_recv.recv_timeout(poll_timeout) {
                Ok(event) => Some(event),
                Err(RecvTimeoutError::Timeout) => None,
                Err(RecvTimeoutError::Disconnected) => {
                    info!("Event receiver disconnected");
                    return None;
                }
            };
            if let Some(final_state) = self.run_one_pass(next_event_opt, &result_send) {
                info!("Runloop exit; signaling event-receiver to stop");
                event_stop_signaler.send();
                return Some(final_state);
            }
        }
    }
