Audit Report

## Title
Collection Admin/Issuer/Freezer roles are not reset on `transfer_ownership`, letting a former owner retain control of an NFT collection - (File: substrate/frame/nfts/src/features/transfer.rs)

## Summary
`do_transfer_ownership` in `pallet-nfts` mutates only `details.owner` (and deposit/`CollectionAccount` bookkeeping) but never clears `CollectionRoleOf`, unlike `do_set_team` which explicitly calls `Self::clear_roles(&collection)` before installing a new role set. Because downstream privileged extrinsics (e.g., lock/freeze operations in `features/lock.rs` and attribute operations in `features/attributes.rs`) gate on `has_role(&collection, &origin, CollectionRole::Admin/Freezer/Issuer)` rather than on `details.owner`, any account the prior owner appointed as Issuer/Admin/Freezer via `set_team` remains fully privileged after ownership passes to a new owner. The identical gap exists in `pallet-uniques::transfer_ownership`, which updates `details.owner` without touching `issuer`/`admin`/`freezer`.

## Finding Description
`do_transfer_ownership` (substrate/frame/nfts/src/features/transfer.rs, lines 124-162) performs `ensure!(origin == details.owner, ...)`, `repatriate_reserved`, updates `CollectionAccount`, and sets `details.owner = new_owner`, but never calls `Self::clear_roles(&collection)`. This is directly confirmed by reading the function body: no reference to `CollectionRoleOf` or `clear_roles` appears anywhere in `transfer.rs`. By contrast, `do_set_team` (substrate/frame/nfts/src/features/roles.rs, lines 38-88) is the only call site in the pallet that invokes `clear_roles` (line 78) to remove stale `CollectionRoleOf` entries before writing new ones. A repo-wide check confirms `clear_roles` is only called from `roles.rs` and `create_delete_collection.rs` (collection destruction), never from `transfer.rs`. Meanwhile, `has_role(&collection, &origin, CollectionRole::...)` checks are used independently of `owner` in `features/lock.rs` and `features/attributes.rs`, confirming that role-gated extrinsics do not re-derive authorization from `details.owner`. Since `CollectionRoleOf` is a storage map keyed by `(collection, account)` independent of `Collection`'s `owner` field, a role assigned under a previous owner persists verbatim across a `transfer_ownership` call.

## Impact Explanation
This matches the "runtime bugs that compromise intended behavior" / "unauthorized execution or origin escalation" impact class: a new owner acquiring a collection via `transfer_ownership` reasonably expects exclusive administrative control, but a former owner's previously appointed Admin/Issuer/Freezer accounts retain the ability to lock collection settings, freeze items/collections, or perform issuer-gated attribute changes without the new owner's consent. The root cause is a missing state-clearing step in an ordinary, unprivileged extrinsic path, not privileged governance/admin misuse, so it is in scope.

## Likelihood Explanation
Likelihood is high and requires no privileged actors: any collection owner can call the standard public extrinsics `set_team` (assigning Issuer/Admin/Freezer, ordinarily to themselves or a trusted party) followed by `transfer_ownership`/`accept_ownership` to a new owner. No malicious peer, validator, relayer, or leaked key is needed — the exploit is a self-contained two-step sequence of standard, publicly documented calls executable entirely by the account currently holding the collection.

## Recommendation
In `do_transfer_ownership` (and the analogous `pallet-uniques::transfer_ownership`), call `Self::clear_roles(&collection)` (or reset `issuer`/`admin`/`freezer` fields) as part of the ownership transfer, unless the new owner explicitly opts to retain the existing team via an additional flag/consent step similar to `set_accept_ownership`.

## Proof of Concept
1. Owner A creates a collection via `Nfts::create(A, A, config)`.
2. A calls `Nfts::set_team(A, collection, Some(A), Some(A), Some(A))`, populating `CollectionRoleOf(collection, A) = Issuer|Admin|Freezer` (substrate/frame/nfts/src/features/roles.rs lines 70-83).
3. B calls `set_accept_ownership(B, Some(collection))`; A calls `transfer_ownership(A, collection, B)`. `do_transfer_ownership` sets `details.owner = B` but leaves `CollectionRoleOf(collection, A)` untouched (substrate/frame/nfts/src/features/transfer.rs lines 134-161).
4. A, though no longer owner, still passes `has_role(&collection, &A, CollectionRole::Freezer/Admin/Issuer)` checks in `features/lock.rs`/`features/attributes.rs` and can lock/freeze the collection or mint/set attributes without B's consent. [1](#0-0) [2](#0-1) [3](#0-2)

	pub(crate) fn do_transfer_ownership(
		origin: T::AccountId,
		collection: T::CollectionId,
		new_owner: T::AccountId,
	) -> DispatchResult {
		// Check if the new owner is acceptable based on the collection's acceptance settings.
		let acceptable_collection = OwnershipAcceptance::<T, I>::get(&new_owner);
		ensure!(acceptable_collection.as_ref() == Some(&collection), Error::<T, I>::Unaccepted);

		// Try to retrieve and mutate the collection details.
		Collection::<T, I>::try_mutate(collection, |maybe_details| {
			let details = maybe_details.as_mut().ok_or(Error::<T, I>::UnknownCollection)?;
			// Check if the `origin` is the current owner of the collection.
			ensure!(origin == details.owner, Error::<T, I>::NoPermission);
			if details.owner == new_owner {
				return Ok(());
			}

			// Move the deposit to the new owner.
			T::Currency::repatriate_reserved(
				&details.owner,
				&new_owner,
				details.owner_deposit,
				Reserved,
			)?;

			// Update account ownership information.
			CollectionAccount::<T, I>::remove(&details.owner, &collection);
			CollectionAccount::<T, I>::insert(&new_owner, &collection, ());

			details.owner = new_owner.clone();
			OwnershipAcceptance::<T, I>::remove(&new_owner);
			frame_system::Pallet::<T>::dec_consumers(&new_owner);

			// Emit `OwnerChanged` event.
			Self::deposit_event(Event::OwnerChanged { collection, new_owner });
			Ok(())
		})
	}

	pub(crate) fn do_set_team(
		maybe_check_owner: Option<T::AccountId>,
		collection: T::CollectionId,
		issuer: Option<T::AccountId>,
		admin: Option<T::AccountId>,
		freezer: Option<T::AccountId>,
	) -> DispatchResult {
		Collection::<T, I>::try_mutate(collection, |maybe_details| {
			let details = maybe_details.as_mut().ok_or(Error::<T, I>::UnknownCollection)?;
			let is_root = maybe_check_owner.is_none();
			if let Some(check_origin) = maybe_check_owner {
				ensure!(check_origin == details.owner, Error::<T, I>::NoPermission);
			}

			let roles_map = [
				(issuer.clone(), CollectionRole::Issuer),
				(admin.clone(), CollectionRole::Admin),
				(freezer.clone(), CollectionRole::Freezer),
			];

			// only root can change the role from `None` to `Some(account)`
			if !is_root {
				for (account, role) in roles_map.iter() {
					if account.is_some() {
						ensure!(
							Self::find_account_by_role(&collection, *role).is_some(),
							Error::<T, I>::NoPermission
						);
					}
				}
			}

			let roles = roles_map
				.into_iter()
				.filter_map(|(account, role)| account.map(|account| (account, role)))
				.collect();

			let account_to_role = Self::group_roles_by_account(roles);

			// Delete the previous records.
			Self::clear_roles(&collection)?;

			// Insert new records.
			for (account, roles) in account_to_role {
				CollectionRoleOf::<T, I>::insert(&collection, &account, roles);
			}

			Self::deposit_event(Event::TeamChanged { collection, issuer, admin, freezer });
			Ok(())
		})
	}

	pub(crate) fn clear_roles(collection_id: &T::CollectionId) -> Result<(), DispatchError> {
		let res = CollectionRoleOf::<T, I>::clear_prefix(
			&collection_id,
			CollectionRoles::max_roles() as u32,
			None,
		);
		ensure!(res.maybe_cursor.is_none(), Error::<T, I>::RolesNotCleared);
		Ok(())
	}

	/// Returns true if a specified account has a provided role within that collection.
	///
	/// - `collection_id`: A collection to check the role in.
	/// - `account_id`: An account to check the role for.
	/// - `role`: A role to validate.
	///
	/// Returns `true` if the account has the specified role, `false` otherwise.
	pub(crate) fn has_role(
		collection_id: &T::CollectionId,
		account_id: &T::AccountId,
		role: CollectionRole,
	) -> bool {
		CollectionRoleOf::<T, I>::get(&collection_id, &account_id)
			.map_or(false, |roles| roles.has_role(role))
	}
