### Title
Liquidation bound is a fixed fraction of debt, not the amount needed to restore health — liquidators seize excess collateral and positions can be liquidated at the same ratio used for minting - ([File: contracts/Pool.sol](contracts/Pool.sol))

### Summary
In Taurus the liquidation cap was expressed as a target collateralization ratio (130%) strictly above the borrow threshold (120%), letting a liquidation overshoot health. Metronome's `Pool.liquidate` has the same bug class with a different shape: the only cap on `amountToRepay_` is `maxLiquidable` (a fixed fraction of the debt token balance, default `0.5e18` = 50%), completely decoupled from the amount needed to make `debtPositionOf` healthy again. There is also no buffer between the minting threshold and the liquidation threshold — both are `debtInUsd <= issuableLimitInUsd` — so a position that just minted at the limit is instantly liquidatable on the next oracle tick.

### Finding Description
Health and issuability share one invariant. `debtPositionOf` computes `_isHealthy = _debtInUsd <= _issuableLimitInUsd` where `_issuableLimitInUsd = Σ depositInUsd * collateralFactor` [1](#0-0) . `DebtToken.issue`/`mint` revert unless the position is healthy after minting, and `liquidate` reverts only when the position is already healthy [2](#0-1) . The sole liquidation bound is `amountToRepay_.wadDiv(_debtTokenBalance) > maxLiquidable` [3](#0-2) , with `maxLiquidable` initialized to 50% and updatable to 1e18 (100%) [4](#0-3) . The seized amount is `quote(repaid) * (1 + liquidatorIncentive + protocolFee)` [5](#0-4) , so every unit of repayment beyond the health-restoring amount transfers bonus collateral to the liquidator.

Concretely: a borrower with debt $101 against an issuable limit of $100 is unhealthy by $1. A liquidator may repay up to 50% (or 100%) of the $101 debt, seizing ~$50–$100 of collateral plus incentive, pushing the position far above the ratio required to mint — i.e., most of the repaid amount corresponds to liquidating an already-healthy sub-position, exactly the Taurus "119% → 130%" overshoot.

### Impact Explanation
Borrowers lose materially more collateral than necessary to restore solvency: each excess repaid dollar costs them `1 + liquidatorIncentive + protocolFee` in seized collateral via `depositToken_.seize(account_, _msgSender, _toLiquidator)` [6](#0-5) . Combined with the zero buffer between mint and liquidation thresholds, a user minting near the limit can be liquidated in the very next oracle update and over-liquidated in a single call. This is direct, involuntary transfer of user collateral to an unprivileged liquidator.

### Likelihood Explanation
Any EOA holding the synthetic asset can call `Pool.liquidate` — it is public, `nonReentrant` and `whenNotShutdown` only [7](#0-6) . Positions only need to drift $1 below the limit, which ordinary price movement causes routinely; liquidators are economically motivated to repay the maximum allowed. No privileged role is required.

### Recommendation
Cap `amountToRepay_` at the amount that restores `_debtInUsd <= _issuableLimitInUsd` (accounting for the collateral seized, not just debt burned, since seizure lowers the limit too). Additionally, introduce a buffer between the mint health threshold and the liquidation threshold (e.g., require `debt > issuableLimit * 1.0x` before liquidation while minting requires `debt <= issuableLimit`), or apply a lower effective collateral factor for new issuance.

### Proof of Concept
Using the existing Hardhat setup in `test/Pool.test.ts` (which already makes Alice unhealthy by lowering the MET oracle price and liquidates via `pool.connect(liquidator).liquidate(...)`) [8](#0-7) :

```ts
// Alice: deposit MET, issue msETH so debt == issuableLimit (collateral factor boundary)
// 1) Drop MET price by 1 wei so Alice is *marginally* unhealthy:
//    debtInUsd = issuableLimitInUsd + epsilon
await masterOracle.updatePrice(met.address, marginallyLowerPrice)

// 2) quoteLiquidateMax returns ~50% of Alice's entire debt,
//    far more than the epsilon needed to restore health
const amountToRepay = await pool.quoteLiquidateMax(msEth.address, alice.address, msdMET.address)
expect(amountToRepay).to.be.closeTo(userMintAmount.div(2), 1)

// 3) Liquidator repays it; Alice loses ~50% of collateral + incentive
await pool.connect(liquidator).liquidate(msEth.address, alice.address, amountToRepay, msdMET.address)

// 4) Assert overshoot: post-liquidation collateralization is far above
//    the limit required to mint (debt << issuableLimit)
const {_debtInUsd, _issuableLimitInUsd} = await pool.debtPositionOf(alice.address)
expect(_issuableLimitInUsd).to.be.gt(_debtInUsd.mul(2)) // overshot healthy ratio
```

A second PoC for the missing buffer: have Alice mint exactly to `issuableLimitInUsd`, update the oracle price down by one tick in the same block, and call `liquidate` — it succeeds even though she borrowed moments ago.
