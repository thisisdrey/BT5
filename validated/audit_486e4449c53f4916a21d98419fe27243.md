### Title
Unauthenticated remote `/shutdown` POST permanently terminates `SignerEventReceiver` event loop - ([File: libsigner/src/events.rs])

### Summary
The `SignerEventReceiver::next_event` handler in `libsigner/src/events.rs` treats any HTTP POST to `/shutdown` as a legitimate stop signal, with no verification that the request originates from the local `SignerStopSignaler` rather than an arbitrary remote TCP peer. Any client able to reach the signer's bound event-listener socket can send this request and permanently halt the signer's event stream.

### Finding Description
In `next_event`, the dispatch logic checks only the URL path and HTTP method, not the caller's identity or any shared secret: [1](#0-0) 

```
} else if request.url() == "/shutdown" {
    event_receiver.stop_signal.store(true, Ordering::SeqCst);
    Err(EventError::Terminated)
```

There is no comparison against a token, no check of the peer's source address against `self.local_addr`/loopback, and no distinction between the legitimate caller (`SignerStopSignaler::send`, which connects to `self.local_addr` from the same process) and any other TCP client that connects to the bound `HttpServer`. The equality "request came from the trusted local stop-signaler" is never evaluated anywhere in this function or in `SignerEventReceiver`/`HttpServer` setup — the handler only inspects `request.url()` and `request.method()`. `SignerStopSignaler::send` itself is just a normal `TcpStream::connect` + raw HTTP POST with no authentication material embedded: [2](#0-1) 

Any TCP peer that can open a connection to the signer's event socket and send `POST /shutdown HTTP/1.1` with a `Content-Length` header (body content is irrelevant) will trigger `stop_signal.store(true, ...)` and return `Err(EventError::Terminated)`, which `main_loop` treats as a clean exit: [3](#0-2) 

Once `is_stopped()` returns true, every subsequent call to `next_event` short-circuits with `Err(EventError::Terminated)` before even calling `http_server.recv()`, so the receiver never processes another event, effectively killing the signer's ability to receive `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block`, and `/status` events from the node it is paired with.

### Impact Explanation
A single crafted HTTP request permanently disables the signer's event-receiving thread, which is how the signer learns of block proposals, StackerDB chunk updates, and burn/Stacks block events from its paired node. This is a remote, unauthenticated, single-message denial-of-service against the signer process — matching the "Critical: remote crash/unauthenticated DoS from few messages" category, since it silently removes a signer from the signing set until the operator manually restarts it.

### Likelihood Explanation
The only precondition is TCP reachability to the signer's configured event-listener endpoint (`config.endpoint`, bound via `SpawnedSigner::new` / `Signer::spawn`). No secret, no valid signature, no StackerDB slot ownership, and no prior state is required — a bare TCP connection with a well-formed POST request suffices, and the attack is trivially repeatable against any signer whose event port is reachable (e.g., not strictly firewalled to loopback).

### Recommendation
Restrict `/shutdown` handling: either bind the event-receiver socket to loopback only and reject non-loopback peers, or require a locally-generated shared secret/token known only to `SignerStopSignaler` (e.g., generated at `bind()` time and passed to `SignerStopSignaler::new`), checked in `next_event` before honoring `/shutdown`. Reject the request (e.g., respond 403 and continue looping) if the check fails, rather than storing `stop_signal = true` unconditionally.

### Proof of Concept
1. Start a `SignerEventReceiver` via `bind()` on `127.0.0.1:<port>` as in `libsigner/src/tests/mod.rs::test_simple_signer`.
2. From a separate, unrelated `TcpStream::connect` (simulating a remote attacker, not via `SignerStopSignaler`), send:
   `POST /shutdown HTTP/1.1\r\nHost: 127.0.0.1:<port>\r\nConnection: close\r\nContent-Length: 4\r\n\r\ntest`
3. Assert `event_receiver.is_stopped() == true` immediately after the request is processed.
4. Assert a subsequent call to `event_receiver.next_event()` returns `Err(EventError::Terminated)` without ever calling `http_server.recv()` again, confirming the event loop is permanently halted by an unauthenticated third party.
