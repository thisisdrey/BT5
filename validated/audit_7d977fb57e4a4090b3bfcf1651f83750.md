### Title
Unauthenticated remote shutdown of signer event loop via `POST /shutdown` - (`File: libsigner/src/events.rs`)

### Summary
`SignerEventReceiver::next_event` treats any HTTP request whose `request.url()` equals `/shutdown` as a legitimate shutdown command, regardless of sender identity. A remote party who can reach the signer's event-listener TCP port can send a single `POST /shutdown` request to permanently halt the signer's `main_loop`, requiring an external process restart to recover.

### Finding Description
In `SignerEventReceiver::next_event`, incoming HTTP requests are dispatched purely by URL string comparison, with no authentication check of any kind: [1](#0-0) 

When `request.url() == "/shutdown"`, the code unconditionally does `event_receiver.stop_signal.store(true, Ordering::SeqCst)` and returns `Err(EventError::Terminated)`. This is the exact code path used internally by `SignerStopSignaler::send` to gracefully shut down the receiver from the same process: [2](#0-1) 

However, nothing in `next_event` verifies that the `/shutdown` request originated from the signer's own `SignerStopSignaler` (e.g., no shared secret, no loopback-only check, no correlation token in the body). Any TCP client that can complete an HTTP/1.1 request to this port — the same port that the stacks-node event dispatcher posts `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block` events to — can trigger the exact same code path.

Once `stop_signal` is set, `is_stopped()` returns `true`: [3](#0-2) 

and `EventReceiver::main_loop` breaks out of its loop on `Err(EventError::Terminated)`: [4](#0-3) 

After this, the signer stops ingesting all further block proposals, StackerDB chunks, and burn-block events until the operator restarts the process. No signature, secret, or origin check exists anywhere in this dispatch logic to distinguish an operator-issued shutdown from an attacker's forged one.

### Impact Explanation
A single unauthenticated HTTP POST permanently disables a signer's event ingestion pipeline (block proposals, signer/miner StackerDB messages, burn block notifications), effectively taking that signer offline from the node's perspective until manually restarted. This matches "Critical - remote crash/unauthenticated DoS from few messages" since exactly one crafted message suffices and it is fully repeatable against every signer reachable on this port.

### Likelihood Explanation
The precondition is simply TCP reachability to the signer's event-receiver port — the same port the local stacks-node event-observer posts to. No secret, peer identity, StackerDB slot ownership, or any privileged role is required; the attacker only needs to open a TCP connection and send `POST /shutdown HTTP/1.1` with a `Content-Length` header. This is trivially repeatable and costs nothing beyond one TCP round trip.

### Recommendation
Do not accept `/shutdown` (or any control-plane action) from arbitrary remote peers. Options: bind/restrict the event-receiver socket to localhost only and ensure operational deployment enforces that; require a shared secret/token in the shutdown request that only the local `SignerStopSignaler` knows (e.g., an HMAC or bearer token bound to the process at startup); or replace the HTTP-based stop signal with an OS-level/local-only IPC mechanism instead of an unauthenticated network endpoint.

### Proof of Concept

```rust
// libsigner/src/events.rs (test module)
use std::net::{TcpStream, TcpListener};
use std::io::Write;

#[test]
fn test_unauthenticated_shutdown() {
    let mut receiver: SignerEventReceiver<v0::messages::SignerMessage> =
        SignerEventReceiver::new(false);
    let addr = "127.0.0.1:0".parse().unwrap();
    let bound_addr = receiver.bind(addr).unwrap();

    // Attacker: raw socket, no auth, no knowledge of any secret
    let mut stream = TcpStream::connect(bound_addr).unwrap();
    let body = "attacker controlled";
    let req = format!(
        "POST /shutdown HTTP/1.1\r\nHost: {}\r\nConnection: close\r\nContent-Length: {}\r\n\r\n{}",
        bound_addr, body.len(), body
    );
    stream.write_all(req.as_bytes()).unwrap();

    let result = receiver.next_event();
    assert!(matches!(result, Err(EventError::Terminated)));
    assert!(receiver.is_stopped());
}
```
This reproduces the exact path in `next_event` (`libsigner/src/events.rs:443-445`) where the URL-only comparison sets `stop_signal` and returns `EventError::Terminated`, which `main_loop` then treats as a legitimate termination signal.

```rust
    fn main_loop(&mut self) {
        loop {
            if self.is_stopped() {
                info!("Event receiver stopped");
                break;
            }
            let next_event = match self.next_event() {
                Ok(event) => event,
                Err(EventError::UnrecognizedEvent(..)) => {
                    // got an event that we don't care about (not a problem)
                    continue;
                }
                Err(EventError::Terminated) => {
                    // we're done
                    info!("Caught termination signal");
                    break;
                }
                Err(e) => {
                    warn!("Failed to receive next event: {:?}", &e);
                    continue;
                }
            };
            if !self.forward_event(next_event) {
                info!("Failed to forward event");
                break;
            }
        }
```
