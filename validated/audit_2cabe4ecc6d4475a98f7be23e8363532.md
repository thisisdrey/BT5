Audit Report

## Title
Nominator/validator reward permanently lost when settlement transfer fails after payout state is marked claimed - (File: substrate/frame/staking-async/src/pallet/impls.rs)

## Summary
In `do_payout_stakers_by_page`, `Eras::<T>::set_rewards_as_claimed(era, &stash, page)` is executed unconditionally at line 386 before the actual reward settlement transfer is performed, and the subsequent `make_payout_from_provider` transfer (`T::Currency::transfer`) failure at lines 602-616 is only logged and swallowed by returning `None`, never propagated as an error from the dispatchable. Because the claim marker is already persisted, the affected stash's reward for that era/page becomes permanently unclaimable and the corresponding funds remain stranded in the era reward pot account.

## Finding Description
The dispatchables `payout_stakers` and `payout_stakers_by_page` are public, unprivileged, callable by any signed account for any validator/era/page via `ensure_signed(origin)?` followed by `Self::do_payout_stakers(...)`. [1](#0-0) 

Inside `do_payout_stakers_by_page`, the code checks `is_rewards_claimed`, and if not already claimed, immediately calls `Eras::<T>::set_rewards_as_claimed(era, &stash, page)` at line 386 — before the exposure is even loaded and well before any transfer occurs. [2](#0-1) 

The actual settlement then proceeds through `payout_from_provider`, which calls `make_payout_from_provider` for the validator and each nominator and only emits a `Rewarded` event when it returns `Some`; if it returns `None`, the loop simply continues to the next nominator with no error surfaced. [3](#0-2) 

`make_payout_from_provider` performs a real `T::Currency::transfer(&staker_rewards_pot, &payout_account, amount, Preservation::Expendable)`. If this transfer fails (e.g., `FundsUnavailable`, an existential-deposit violation under `Preservation::Expendable`, or a frozen/locked destination account from another pallet), the error is only logged via `log!(error, ...)` and the function returns `None` — no `DispatchError` is ever bubbled up. [4](#0-3) 

`do_payout_stakers_by_page` ultimately returns `Ok(Some(T::WeightInfo::payout_stakers_alive_staked(nominator_payout_count)).into())` regardless of whether any individual `make_payout_from_provider` call failed. [5](#0-4) 

Since the claim marker was already persisted before the transfer was attempted, and there is no `with_transaction`-style rollback wrapping the settlement logic (unlike `pallet-message-queue`, which explicitly wraps each message's processing in `storage::with_transaction` and rolls back on error), any subsequent call to `payout_stakers`/`payout_stakers_by_page` for the same `(era, stash, page)` will immediately fail with `Error::<T>::AlreadyClaimed`, permanently preventing recovery of the affected reward. [6](#0-5) 

This directly violates the required invariant that "payout state must only advance after ... settlement succeed atomically" — the claim marker advances unconditionally, decoupled from whether the individual settlement transfer it is supposed to back actually succeeded.

## Impact Explanation
This matches the allowed impact category of "permanent user-fund lock" achievable via public, unprivileged extrinsics. Any account whose reward destination is, or becomes, in a state that causes `Currency::transfer` to fail (e.g., insufficient balance to satisfy the existential deposit under `Preservation::Expendable` for a fresh account, or a freeze/lock imposed by another pallet) will have that specific reward silently and permanently lost the moment anyone triggers the payout for that page — the caller does not need to be the affected nominator, and no privileged action is required.

## Likelihood Explanation
Likelihood is moderate to high: `Currency::transfer` failures under `Preservation::Expendable` are readily triggerable — e.g. a nominator whose account balance sits at or near the existential deposit, or one whose funds are frozen/locked by an unrelated pallet, will fail the reward transfer. Because `payout_stakers`/`payout_stakers_by_page` are permissionless and callable by anyone for any validator/era/page, an attacker (or simply an unlucky combination of account state) can force this condition without needing a malicious validator, relayer, or governance actor, and the resulting loss is not confined to a single accidental occurrence but is systematically reproducible for any account meeting the failure condition.

## Recommendation
Do not persist `set_rewards_as_claimed` until settlement transfers have been attempted and their outcome is known. Specifically:
- Defer marking the page/era as claimed until after the transfer loop completes, or
- On a per-account transfer failure, retain that specific share as unclaimed (e.g., a per-page "unclaimed remainder" storage item sweepable via a dedicated recovery dispatchable) rather than silently dropping it while marking the whole page claimed, or
- Propagate transfer failures (or partial-success information) from `do_payout_stakers_by_page` so callers/affected nominators are aware and the page is not marked fully claimed until all shares have successfully settled.

## Proof of Concept
1. A validator has at least one nominator `N` whose payout destination account balance/lock state causes `T::Currency::transfer(..., Preservation::Expendable)` to return an `Err` (e.g., account below existential deposit for a fresh destination, or frozen by another pallet's lock).
2. Any signed account calls `Staking::payout_stakers_by_page(origin, validator_stash, era, page)`.
3. `Eras::<T>::set_rewards_as_claimed(era, &stash, page)` executes at impls.rs:386; `payout_from_provider` runs and `make_payout_from_provider` for `N` hits the `Err` branch at impls.rs:602-616, logs the error, and returns `None` — no `Rewarded` event for `N`, no error surfaced; the extrinsic still returns `Ok`.
4. Any subsequent call to `payout_stakers_by_page` for the same `(era, validator_stash, page)` immediately fails with `Error::<T>::AlreadyClaimed` (impls.rs:381-384), permanently preventing `N` from ever receiving that reward, which remains stranded in the era's staker-reward pot account.

	/// Payout stakers from an era reward pot (transfer-based, no minting).
	fn payout_from_provider(
		era: EraIndex,
		stash: &T::AccountId,
		validator_payout: BalanceOf<T>,
		exposure: &crate::PagedExposure<T::AccountId, BalanceOf<T>>,
		overview_own: BalanceOf<T>,
		total_nominator_payout: BalanceOf<T>,
	) -> u32 {
		let mut nominator_payout_count: u32 = 0;

		if let Some((amount, dest)) = Self::make_payout_from_provider(era, stash, validator_payout)
		{
			Self::deposit_event(Event::<T>::Rewarded { stash: stash.clone(), dest, amount });
		}

		let total_nominator_stake = exposure.total().saturating_sub(overview_own);
		for nominator in exposure.others().iter() {
			let nominator_exposure_part =
				Perbill::from_rational(nominator.value, total_nominator_stake);
			let nominator_reward: BalanceOf<T> =
				nominator_exposure_part.mul_floor(total_nominator_payout);

			if let Some((amount, dest)) =
				Self::make_payout_from_provider(era, &nominator.who, nominator_reward)
			{
				nominator_payout_count.saturating_inc();
				Self::deposit_event(Event::<T>::Rewarded {
					stash: nominator.who.clone(),
					dest,
					amount,
				});
			}
		}

		nominator_payout_count
	}
