### Title
`git_repository`'s `strip_prefix` protection only blocklists Git metadata, letting a malicious remote's tree content bypass containment during checkout reshuffling - (File: `tools/build_defs/repo/git.bzl`)

### Summary
`git_repository`'s `_clone_or_update_repo` implements a `recoverERC20`-style "cleanup" routine: after cloning an attacker-controlled remote, it moves the `strip_prefix` subtree up and deletes everything else in the checkout, similar to how `recoverERC20` was meant to sweep out "everything except a fixed exclusion list." Just as `recoverERC20` only excluded `stakingToken` and forgot `rewardsToken`, this routine only excludes the `.git` metadata directory from being treated as the `strip_prefix` target - it does not validate the *contents* being moved/relinked, which are entirely attacker-controlled (they come from the cloned repo, i.e., untrusted origin content).

### Finding Description
`_clone_or_update_repo` [1](#0-0)  resolves `strip_prefix` to a realpath and only checks two things: (1) that it doesn't escape the checkout directory, and (2) that it isn't the `.git` metadata path itself, via a hardcoded blocklist check [2](#0-1) . It then performs the "recovery" step: renaming the selected subtree aside, deleting every other top-level entry, and re-parenting each child of the subtree back up to the checkout root [3](#0-2) .

Crucially, the entries iterated in the final loop (`strip_prefix_tmp_path.readdir()`) are attacker-supplied tree entries from the cloned repository - an unprivileged party controlling the remote (or a branch that CI builds) fully controls their names and types, including symlinks. `ctx.rename` operates on the directory entry itself, not its resolved target, so a malicious repo can commit a symlink (e.g., named `BUILD.bazel`, `WORKSPACE`, or any build-relevant filename) whose target is an absolute path or an out-of-tree relative path (`../../etc`). This symlink survives the strip-prefix reshuffle and lands directly at the top of the external repository, exactly like `recoverERC20`'s missing check let arbitrary "non-excluded" tokens be swept to the attacker.

### Impact Explanation
Because the exclusion check is scoped only to `.git`, and not to path types (symlinks) or destinations, a hostile Git remote/branch can place a symlink in the checked-out tree that, once "recovered" to the repository root by this logic, resolves outside the external repository directory or the output base when later read by build actions consuming that repository (e.g., via `glob`, `exports_files`, or a `BUILD` file baked in by the same commit). This is a containment break: the invariant that repository rule outputs stay inside `output_base/external/<repo>` is violated by attacker-supplied tree content that the "cleanup" step (renaming subtree, deleting siblings) does not sanitize.

### Likelihood Explanation
Low-to-Medium. This requires: (a) use of `git_repository` (not `http_archive`, which is preferred), (b) `strip_prefix` set to a subdirectory (a common pattern for monorepos), and (c) an untrusted or compromised remote/branch, matching the threat model of "an outsider who publishes content a victim's build consumes" (a hostile Git server or a compromised/malicious branch that CI builds against). Bazel's default flags do not add extra symlink-target validation in this code path, and `commit`-pinning does not mitigate this because the symlink content is part of the pinned commit itself if the remote is compromised, or is fully attacker-chosen if the branch is untrusted.

### Recommendation
When re-parenting entries out of the `strip_prefix` subtree (lines 80-81), do not blindly trust directory-entry types: reject or refuse to move entries that are symlinks resolving outside the checkout directory (mirroring the same `startswith(checkout_realpath)` containment check already applied to `strip_prefix_path` itself), or resolve and re-create symlinks relative to the destination rather than preserving attacker-chosen absolute/relative targets verbatim.

### Proof of Concept
A `src/test/shell/bazel/git_repository_test.sh`-style JUnit/shell reproduction:
1. Create a git repository with a top-level directory `pkg/` (used as `strip_prefix`) and, alongside it, plant a symlink at the checkout root e.g. `pkg/evil -> /tmp/outside_dir` (or `../../../../tmp/outside_dir`), plus a legitimate `BUILD` file inside `pkg/`.
2. Configure `git_repository(name="ext", remote="<path to malicious repo>", strip_prefix="pkg")`.
3. Run `bazel build @ext//:all` and confirm that after fetch, `output_base/external/ext/evil` is a symlink resolving outside `output_base/external/ext`, i.e., outside the repository directory - demonstrating the containment break, analogous to how `recoverERC20`'s incomplete check let the owner drain `rewardsToken`.

**Uncertainty note:** I could not retrieve version-control history (`get_blame`) for this file within the available iterations, so I cannot confirm whether this `.git`-metadata check was added specifically in response to a prior symlink/path-traversal incident, nor whether a newer unindexed revision of `git_repository`/`git_worker.bzl` already adds symlink-target validation during the strip-prefix reshuffle. I recommend a Devin session with full repository and history access to verify against the current `git_worker.bzl` clone logic and any related symlink-containment checks before treating this as a confirmed, unmitigated finding.

def _clone_or_update_repo(ctx):
    if ((ctx.attr.tag and ctx.attr.commit) or
        (ctx.attr.tag and ctx.attr.branch) or
        (ctx.attr.commit and ctx.attr.branch)):
        fail("At most one of commit, tag, or branch may be provided")

    checkout_path = _checkout_path(ctx)
    git_ = git_repo(ctx, str(checkout_path))

    if ctx.attr.strip_prefix:
        strip_prefix_path = checkout_path.get_child(ctx.attr.strip_prefix)
        if not strip_prefix_path.exists:
            fail("strip_prefix at {} does not exist in repo".format(ctx.attr.strip_prefix))
        if not strip_prefix_path.is_dir:
            fail("strip_prefix at {} is not a directory".format(ctx.attr.strip_prefix))

        strip_prefix_path = strip_prefix_path.realpath
        checkout_realpath = checkout_path.realpath
        strip_prefix_realpath = str(strip_prefix_path).lower()
        git_metadata_path = str(checkout_realpath.get_child(".git")).lower()
        if (strip_prefix_realpath == git_metadata_path or
            strip_prefix_realpath.startswith(git_metadata_path + "/")):
            fail("strip_prefix at {} refers to Git metadata".format(ctx.attr.strip_prefix))
        if strip_prefix_path != checkout_realpath:
            if not str(strip_prefix_path).startswith(str(checkout_realpath) + "/"):
                fail("strip_prefix at {} escaped the checkout directory".format(ctx.attr.strip_prefix))

            existing_entries = {
                entry.basename.lower(): True
                for entry in checkout_path.readdir() + strip_prefix_path.readdir()
            }
            strip_prefix_tmp_name = ".bazel_git_strip_prefix"
            for _ in existing_entries:
                if strip_prefix_tmp_name not in existing_entries:
                    break
                strip_prefix_tmp_name += "_"
            strip_prefix_tmp_path = checkout_path.get_child(strip_prefix_tmp_name)

            # Keep the selected subtree while removing the rest of the checkout.
            ctx.rename(strip_prefix_path, strip_prefix_tmp_path)
            for entry in checkout_path.readdir():
                if entry.basename != strip_prefix_tmp_name:
                    ctx.delete(entry)
            for entry in strip_prefix_tmp_path.readdir():
                ctx.rename(entry, checkout_path.get_child(entry.basename))
            ctx.delete(strip_prefix_tmp_path)
