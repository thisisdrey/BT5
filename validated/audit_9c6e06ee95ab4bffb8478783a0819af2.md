### Title
Netrc `default` machine credentials leak to any URL in a repository rule's `urls` list, including attacker-controlled mirrors - (File: tools/build_defs/repo/utils.bzl)

### Summary
`use_netrc` in `tools/build_defs/repo/utils.bzl` computes an authentication dict for a list of URLs from a parsed `.netrc` file. When a URL's host has no explicit `machine` entry, the function silently falls back to the `.netrc` "default" entry (empty-string key) and attaches those credentials to that URL anyway. Since `http_archive`/`http_file`/`http_jar` build their download URL list by concatenating `url` and `urls` (which is explicitly documented as a place to list untrusted mirrors/fallbacks), any URL in that combined list that isn't recognized in `.netrc` still receives the default credentials.

### Finding Description
`use_netrc(netrc, urls, patterns)` iterates every URL and resolves the auth entry with: [1](#0-0) 

If the URL's host is not an explicit `machine` in the netrc file, and a default entry (`""`) exists, that default entry's login/password is used *for that host regardless of what host it is*. This is invoked from `get_auth`, which is called with the full combined URL list from `_get_source_urls` (i.e., `ctx.attr.url` + `ctx.attr.urls`): [2](#0-1) 

`http.bzl` explicitly documents `urls` as a place to add alternative/mirror URLs, "tried in order until one succeeds": [3](#0-2) 

Combined with `get_auth`'s use of `use_netrc`: [4](#0-3) 

the net effect is: a user (or CI environment) that maintains a `.netrc` "default" entry (a common pattern for a catch-all token, e.g. for an internal mirror or GitHub) will have that credential attached to *every* URL Bazel tries for a repository rule — including any additional mirror/fallback URL that is attacker-supplied (e.g., published in a third-party registry's `source.json` `mirror_urls`, or added by an extension/module the user depends on). The existing test suite only exercises hosts that are *absent* from netrc with no default entry present (`evil.com` correctly gets no auth in `test_use_netrc`), but does not cover the "default machine + unrelated attacker host" case, so the unscoped fallback is not validated against.

This breaks the "credentials are host-scoped" invariant: `use_netrc`'s per-host matching is bypassed by the default-machine fallback, sending secrets to hosts they were never intended for.

### Impact Explanation
An attacker who controls one of the fallback/mirror URLs consumed by a repository rule (a scenario explicitly enabled by the `urls` attribute and by registry `source.json`/`mirror_urls` entries) can receive Basic-Auth credentials or bearer tokens that the victim configured for an unrelated "default" machine. This is credential exfiltration to an attacker-controlled host, not merely a download failure — matching the required impact class (credential exfiltration).

### Likelihood Explanation
Requires the victim to have a `.netrc` default entry (common in CI for blanket API tokens) and to fetch from a rule/extension whose `urls`/`mirror_urls` include or can be caused to include a non-matching (attacker) host. No MITM, no malicious peer, and no access to the victim's machine is needed — the attacker only needs to be one of the URLs/mirrors the build already consumes.

### Recommendation
`use_netrc` should not apply the default (`""`) machine's credentials to hosts that don't explicitly appear in the `.netrc` file when the URL list mixes trusted primary hosts with externally-supplied mirror/fallback hosts; at minimum, document and gate this behavior so callers can opt out of default-credential fallback for untrusted mirror lists, and add a regression test analogous to `test_use_netrc` that includes a `.netrc` `default` entry alongside an unrelated attacker host URL to assert credentials are NOT leaked.

```text
    """Utility function to obtain the correct auth dict for a list of urls from .netrc file.

    Support optional netrc and auth_patterns attributes if available.

    Args:
      ctx: The repository context of the repository rule calling this utility
        function.
      urls: the list of urls to read

    Returns:
      the auth dict which can be passed to repository_ctx.download

    if hasattr(ctx.attr, "netrc") and ctx.attr.netrc:
        netrc = read_netrc(ctx, ctx.attr.netrc)
```

```text
def _get_source_urls(ctx):
    """Returns source urls provided via the url, urls attributes.

    Also checks that at least one url is provided."""
    if not ctx.attr.url and not ctx.attr.urls:
        fail("At least one of url and urls must be provided")

    source_urls = []
    if ctx.attr.urls:
        source_urls = ctx.attr.urls
    if ctx.attr.url:
        source_urls = [ctx.attr.url] + source_urls
    return source_urls
```
