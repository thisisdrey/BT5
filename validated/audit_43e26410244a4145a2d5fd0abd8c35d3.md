### Title
Hardcoded `eth_wallet_global_contract_hash` mismatch would permanently strand funds sent to every future ETH-implicit account - (File: `runtime/near-wallet-contract/src/lib.rs`)

### Summary
`eth_wallet_global_contract_hash(chain_id)` returns hardcoded 32-byte constants for `MAINNET`/`MOCKNET` and `TESTNET` [2](#0-1) . This value is used as the `GlobalContractIdentifier::CodeHash` that every newly created ETH-implicit account points to via `AccountContract::Global(global_contract_hash)` [1](#0-0) . This is directly analogous to the reported `POOL_INIT_CODE_HASH` bug: a compile-time hash constant that must equal the hash of specific bytecode (the actual deployed global Wallet Contract wasm) in order for the content-addressed lookup to resolve.

### Finding Description
Global contracts in nearcore are content-addressed: `GlobalContractIdentifier::CodeHash` is resolved by looking up `TrieKey::GlobalContractCode{identifier}` in the trie, and this only succeeds if a global contract with exactly that hash was previously deployed via `DeployGlobalContract` (see `GlobalContractAccessExt::hash`/`code` at `runtime/runtime/src/contract_code.rs:91-117`) [3](#0-2) . Because `eth_wallet_global_contract_hash` is a hardcoded literal rather than being derived from the actual wallet-contract wasm bytes at build/deploy time, if it does not exactly match the hash of the wallet contract wasm that is actually deployed on-chain as a global contract, every ETH-implicit account created afterward is permanently assigned a dangling `AccountContract::Global(hash)` reference to code that does not exist in the trie.

### Impact Explanation
Unlike the Uniswap/TangleSwap analog (where a wrong `POOL_INIT_CODE_HASH` merely reverts `mint()` calls, a pure availability bug with no funds at risk since the pool never gets created and users' deposits are never sent), the nearcore analog is strictly worse: an ETH-implicit account is created and funded by a `Transfer` action *before* anyone can verify the wallet contract is resolvable [4](#0-3) . Once created with a dangling global-contract hash, the account can never execute `rlp_execute` (the only way to move funds out, per the docs at `docs/DataStructures/Account.md:121`) because the runtime cannot fetch/compile code for a hash that isn't in global contract storage. The account cannot be deleted (ETH-implicit accounts cannot have a full access key added, per the same doc), so any balance sent to it is permanently frozen with no recovery path — a genuine "permanent freezing of funds" outcome, not just a reverted mint.

### Likelihood Explanation
This requires the hardcoded constant to actually diverge from the deployed wallet contract wasm — e.g., through a version mismatch between the `near-wallet-contract` crate (which embeds `res/wallet_contract_mainnet.wasm`/`res/wallet_contract_testnet.wasm`) and whichever wasm blob was actually pushed on-chain via `DeployGlobalContract` under `EthImplicitGlobalContract`. The repo's own tests only assert internal self-consistency (`test_eth_wallet_global_contract_hash_values` checks the constant against itself, not against an independently-deployed on-chain global contract) [5](#0-4) , so there is no automated on-chain cross-check preventing this divergence once the feature is live. It is a deployment/release-process risk rather than something an attacker can trigger directly, similar to the original TangleSwap finding being triggered by an incorrect artifact at compile time rather than by attacker input.

### Recommendation
Add an on-chain/CI invariant that verifies the constants returned by `eth_wallet_global_contract_hash` for each chain match the hash of an actually-deployed global contract before/at the point `EthImplicitGlobalContract` is activated for that chain (e.g., a protocol-upgrade migration check, or deriving the hash directly from the embedded wasm bytes via `ContractCode::hash()` on `MAINNET`/`TESTNET` statics instead of literal byte arrays, mirroring how `wallet_contract_magic_bytes` already derives its hash from `read_contract().hash()`) [6](#0-5) .

### Proof of Concept
1. Ship a nearcore release where `eth_wallet_global_contract_hash(MAINNET)` (the hardcoded literal at `runtime/near-wallet-contract/src/lib.rs:92-96`) does not match the hash of the wallet-contract wasm actually pushed via `DeployGlobalContract` for mainnet.
2. Any user sends a `Transfer` to a fresh `0x...` ETH-implicit account id; `action_implicit_account_creation_transfer` creates it with `AccountContract::Global(<mismatched hash>)` and the deposit is debited from the sender and credited to the new account [7](#0-6) .
3. Any subsequent `rlp_execute` call (or any function call) against that account fails because the global contract code for that hash cannot be found in the trie (`GlobalContractAccessExt::code`/`hash` return `StorageInconsistentState`/`None`) [3](#0-2) .
4. Because ETH-implicit accounts cannot receive a full-access key or be deleted, the deposited balance is permanently unspendable.

impl GlobalContractAccessExt for GlobalContractIdentifier {
    fn hash(self, store: &TrieUpdate, access: AccessOptions) -> Result<CryptoHash, StorageError> {
        if let GlobalContractIdentifier::CodeHash(hash) = self {
            return Ok(hash);
        }
        let key = TrieKey::GlobalContractCode { identifier: self.into() };
        let value_ref =
            store.get_ref(&key, KeyLookupMode::MemOrFlatOrTrie, access)?.ok_or_else(|| {
                let TrieKey::GlobalContractCode { identifier } = key else { unreachable!() };
                StorageError::StorageInconsistentState(format!(
                    "Global contract identifier not found {:?}",
                    identifier
                ))
            })?;
        Ok(value_ref.value_hash())
    }

    fn code(self, store: &TrieUpdate) -> Result<Option<ContractCode>, StorageError> {
        let key = TrieKey::GlobalContractCode { identifier: self.clone().into() };
        let code_hash = match self {
            GlobalContractIdentifier::AccountId(_) => None,
            GlobalContractIdentifier::CodeHash(hash) => Some(hash),
        };
        let code = store.get(&key, AccessOptions::DEFAULT)?;
        Ok(code.map(|code| ContractCode::new(code, code_hash)))
    }
}
