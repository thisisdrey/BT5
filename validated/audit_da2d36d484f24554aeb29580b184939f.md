### Title
Global oldest-first eviction in unstaked `ConnectionTable::prune_oldest` lets many-IP churn attacker evict legitimate unstaked connections - (File: streamer/src/nonblocking/quic.rs)

### Summary
`SwQos::try_add_connection` routes every unstaked (and stake-rejected staked) connection through `prune_unstaked_connections_and_add_new_connection`, which calls `prune_unstaked_connection_table` → `ConnectionTable::prune_oldest` once `max_unstaked_connections` is reached. `prune_oldest` selects the globally least-recently-updated entry across the whole table regardless of source key, so an attacker who continuously opens (and abandons) fresh connections from many different source IPs will always be "newer" than a legitimate, longer-lived unstaked connection, causing the legitimate connection to be repeatedly selected for eviction.

### Finding Description
The unstaked connection admission path is:
`setup_connection` (streamer/src/nonblocking/quic.rs:512-519) → `SwQos::try_add_connection` (`ConnectionPeerType::Unstaked` branch, streamer/src/nonblocking/swqos.rs:415-437) → `prune_unstaked_connections_and_add_new_connection` (streamer/src/nonblocking/swqos.rs:258-290) → `prune_unstaked_connection_table` (streamer/src/nonblocking/swqos.rs:241-256) → `ConnectionTable::prune_oldest` (streamer/src/nonblocking/quic.rs:964-980).

`prune_oldest` computes, for every key (IP or pubkey) in the `IndexMap`, the minimum `last_update` timestamp among its connections, and repeatedly evicts the whole entry with the globally smallest `last_update` until the table shrinks to `max_size` (90% of `max_unstaked_connections`, per `PRUNE_TABLE_RATIO` in `prune_unstaked_connection_table`). This eviction is purely LRU by timestamp and has **no per-source fairness weighting** — unlike the staked table's `prune_random`, which samples candidates and only evicts the lowest-stake one among the sample (streamer/src/nonblocking/quic.rs:986-1006), the unstaked table has no analogous protection because there is no stake to weigh against.

`last_update` is refreshed via `conn_context.last_update` set at connection-context build time (`build_connection_context`, streamer/src/nonblocking/swqos.rs:302-313) and is the timestamp used purely for ordering, not fairness across distinct source keys. An attacker controlling many source IPs can:
1. Saturate `unstaked_connection_table` to `max_unstaked_connections`.
2. Continuously open new short-lived connections from many attacker-controlled IPs. Each new connection has a `last_update` newer than any of the legitimate long-lived, less-frequently-refreshed connections.
3. Each new attacker connection triggers `prune_unstaked_connection_table`, which evicts the globally-oldest entry — which, given attacker churn, will consistently be a legitimate client's entry rather than one of the attacker's newest ones.

Existing defenses do not stop this given the attacker model (many distinct source IPs):
- `ConnectionRateLimiter` (streamer/src/nonblocking/connection_rate_limiter.rs) is keyed **per IP address**, so it does not limit a multi-IP attacker's aggregate churn rate.
- `overall_connection_rate_limiter` (a global `TokenBucket`, `TOTAL_CONNECTIONS_PER_SECOND = 2500.0`, `MAX_CONNECTION_BURST = 1000`, streamer/src/nonblocking/quic.rs:73-76) caps the total connection rate across all sources, but it is set high enough (2500/s sustained, burst of 1000) that a multi-IP attacker can still churn through unstaked slots continuously and repeatedly trigger `prune_oldest`, since it only throttles handshake admission, not eviction fairness once inside the QoS layer.
- `try_add_connection`'s `max_connections_per_peer` check limits connections per single key, but does not protect against churn across many distinct keys.

### Impact Explanation
This matches the "QoS evasion"/DoS category: legitimate unstaked senders (e.g., regular RPC/wallet clients without stake) can be perpetually starved of TPU access because their connections are continuously evicted in favor of newer, disposable attacker connections, even though the attacker gains no lasting connection themselves (their connections are also short-lived/abandoned) — the net effect is degraded/denied service to legitimate unstaked traffic, which is within the bounty's QoS-enforcement-fairness scope. This does not cause block invalidity, panics, or memory exhaustion; the impact is capacity denial for unstaked senders at the leader's TPU port.

### Likelihood Explanation
Preconditions are readily attacker-controlled: (1) reaching `max_unstaked_connections` is a normal operating condition under load and easily forced by the attacker itself opening many connections; (2) sustaining churn from many source IPs is feasible for any attacker with access to a modest IP pool (cloud/proxy/botnet), well within the "unprivileged, many source IPs" threat model given in the prompt; (3) the eviction mechanism (`prune_oldest`) has no additional gate beyond QUIC handshake completion and rate limiters that are per-IP or globally permissive (2500 conn/s). The attack is fully repeatable indefinitely as long as churn continues, with no cooldown or fairness recovery mechanism visible in `ConnectionTable`.

### Recommendation
Introduce fairness into unstaked eviction similar to `prune_random`'s protection for staked peers: e.g., sample-based random eviction among unstaked entries rather than strict oldest-first, or weight eviction by "age since connection created" combined with number of connections already owned by that source recently, or require a minimum connection age before an unstaked entry is eligible for pruning (grace period), so brand-new churned connections are pruned before older, presumably legitimate ones. Additionally, consider tracking per-source-IP admission counts within short windows (independent of `ConnectionRateLimiter`'s per-IP token bucket) with a global fairness cap based on subnet/IP diversity heuristics to blunt multi-IP churn.

### Proof of Concept
Rust unit test extending the existing `streamer/src/nonblocking/quic.rs` test module (`test_prune_table_with_ip`), simulating one legitimate long-lived IP and many distinct churning attacker IPs:

```rust
#[test]
fn test_prune_oldest_churn_evicts_legitimate_connection() {
    use std::net::Ipv4Addr;
    let cancel = CancellationToken::new();
    let mut table = ConnectionTable::new(ConnectionTableType::Unstaked, cancel);
    let max_connections_per_peer = 10;
    let stats = Arc::new(StreamerStats::default());
    let max_unstaked_connections = 10;

    // Legitimate client connects first (oldest last_update = 0).
    let legit_ip = IpAddr::V4(Ipv4Addr::new(10, 0, 0, 1));
    table
        .try_add_connection(
            ConnectionTableKey::IP(legit_ip),
            1,
            ClientConnectionTracker::new(stats.clone(), 1000).unwrap(),
            None,
            ConnectionPeerType::Unstaked,
            Arc::new(AtomicU64::new(0)),
            max_connections_per_peer,
            || Arc::new(NullStreamerCounter {}),
        )
        .unwrap();

    // Fill remaining unstaked capacity with attacker connections at increasing timestamps.
    for i in 1..max_unstaked_connections {
        let ip = IpAddr::V4(Ipv4Addr::new(10, 0, 0, (i + 1) as u8));
        table
            .try_add_connection(
                ConnectionTableKey::IP(ip),
                1,
                ClientConnectionTracker::new(stats.clone(), 1000).unwrap(),
                None,
                ConnectionPeerType::Unstaked,
                Arc::new(AtomicU64::new(i as u64)),
                max_connections_per_peer,
                || Arc::new(NullStreamerCounter {}),
            )
            .unwrap();
    }

    // Simulate churn: attacker opens 50 more connections from fresh IPs, one at a time,
    // each triggering prune_oldest down to 90% capacity (mirrors prune_unstaked_connection_table).
    for round in 0..50 {
        const PRUNE_TABLE_RATIO: f64 = 0.90;
        let max_connections = (PRUNE_TABLE_RATIO * (max_unstaked_connections as f64)) as usize;
        table.prune_oldest(max_connections);

        let attacker_ip = IpAddr::V4(Ipv4Addr::new(11, 0, 0, (round % 250) as u8));
        table
            .try_add_connection(
                ConnectionTableKey::IP(attacker_ip),
                1,
                ClientConnectionTracker::new(stats.clone(), 1000).unwrap(),
                None,
                ConnectionPeerType::Unstaked,
                Arc::new(AtomicU64::new((max_unstaked_connections + round) as u64)),
                max_connections_per_peer,
                || Arc::new(NullStreamerCounter {}),
            )
            .unwrap();
    }

    // Assert: the legitimate long-lived IP has been evicted, proving churn from
    // many attacker IPs starves the legitimate unstaked connection indefinitely.
    assert!(
        !table.table.contains_key(&ConnectionTableKey::IP(legit_ip)),
        "expected legitimate connection to be pruned out under sustained multi-IP churn"
    );
}
```

Expected result: the assertion passes, demonstrating the legitimate connection is evicted and never survives churn cycles, confirming `prune_oldest`'s lack of per-source fairness allows unbounded starvation of legitimate unstaked clients.
