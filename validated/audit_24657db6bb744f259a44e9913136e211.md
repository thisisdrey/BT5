### Title
Old Operator's Commission Bypasses Beneficiary After `switch_operator` — (`File: aptos-move/framework/aptos-framework/sources/staking_contract.move`)

---

### Summary

In `staking_contract.move`, `distribute_internal` redirects commission to a beneficiary only when `recipient == operator` (the parameter passed in). After `switch_operator` is called, the distribution pool retains a pending entry keyed to the **old** operator, but all future `distribute` calls pass the **new** operator as the `operator` parameter. The identity check never fires for the old operator's entry, so the old operator's commission is sent directly to the old operator's address — bypassing the beneficiary they registered via `set_beneficiary_for_operator`. The beneficiary loses APT they are entitled to.

---

### Finding Description

**Root-cause invariant (analog to H-2):** A single-key lookup (`if (recipient == operator)`) is used to decide whether to redirect a distribution to a beneficiary. After an operator switch, the distribution pool contains an entry keyed to the *old* operator, but the lookup key is the *new* operator. The mismatch causes the beneficiary redirect to be silently skipped.

**Step-by-step trace:**

1. **`set_beneficiary_for_operator`** stores `BeneficiaryForOperator { beneficiary_for_operator: B }` under `old_operator`'s address. [1](#0-0) 

2. **`switch_operator`** calls `request_commission_internal(old_operator, &mut staking_contract)`, which calls `add_distribution(old_operator, staking_contract, old_operator, commission_amount)` — inserting `old_operator` as a shareholder in the distribution pool — and then calls `stake::unlock_with_cap` to begin unlocking the commission. The commission is **not yet withdrawable** (subject to lockup). [2](#0-1) [3](#0-2) 

3. **`switch_operator`** then re-keys the staking contract under `new_operator`. [4](#0-3) 

4. After the lockup period ends, anyone calls `distribute(staker, new_operator)`, which calls `distribute_internal(staker, new_operator, staking_contract)` with `operator = new_operator`. [5](#0-4) 

5. Inside `distribute_internal`, the loop iterates over distribution pool shareholders. `old_operator` is a shareholder. The beneficiary redirect check is:
   ```move
   if (recipient == operator) {
       recipient = beneficiary_for_operator(operator);
   };
   ```
   Since `recipient = old_operator` and `operator = new_operator`, the condition is **false**. The commission is deposited directly to `old_operator`, not to `B`. [6](#0-5) 

The `beneficiary_for_operator` lookup is never consulted for `old_operator`'s pending distribution entry. [7](#0-6) 

---

### Impact Explanation

The beneficiary `B` of `old_operator` loses the APT commission that was earned and unlocked during the `switch_operator` call. The commission is instead deposited to `old_operator` directly. For large staking pools with significant accumulated rewards, this can be a material loss of APT. The beneficiary has no recourse — the funds are already transferred.

---

### Likelihood Explanation

The trigger sequence is entirely composed of legitimate, unprivileged on-chain operations:
- `set_beneficiary_for_operator` (operator's own action, enabled on mainnet)
- `switch_operator` (staker's own action)
- `distribute` (permissionless, callable by anyone)

Any staker who switches operators while the old operator has a registered beneficiary will trigger this. The `switch_operator_with_same_commission` entry point follows the same code path and is equally affected. [8](#0-7) 

---

### Recommendation

In `distribute_internal`, the beneficiary redirect must check against the **recipient's own** beneficiary, not only against the current `operator` parameter. Change:

```move
// Before (broken):
if (recipient == operator) {
    recipient = beneficiary_for_operator(operator);
};
```

to:

```move
// After (fixed):
recipient = beneficiary_for_operator(recipient);
```

This makes the redirect unconditional for any recipient who has a registered beneficiary, regardless of whether they are the current or a former operator. The `beneficiary_for_operator` function already returns the address itself when no beneficiary is set, so this is safe for all recipients including the staker. [9](#0-8) 

---

### Proof of Concept

```
1. Staker S creates staking contract with operator O1 (10% commission).
2. O1 calls set_beneficiary_for_operator(B).
   → BeneficiaryForOperator[O1] = B
3. Stake pool earns rewards R. Commission = R * 10% = C.
4. S calls switch_operator(S, O1, O2, 10%).
   → distribute_internal(S, O1, ...) runs: no inactive stake yet, nothing distributed.
   → request_commission_internal(O1, ...):
       add_distribution(O1, contract, O1, C)   ← O1 added to distribution pool
       stake::unlock_with_cap(C, ...)           ← C begins unlocking
   → contract re-keyed under O2.
5. Lockup period ends. C becomes withdrawable (inactive).
6. Anyone calls distribute(S, O2).
   → distribute_internal(S, O2, contract) with operator = O2.
   → Loop: recipient = O1, shares = C.
   → Check: O1 == O2? NO.
   → aptos_account::deposit_coins(O1, C).   ← C goes to O1, not B.
7. B receives 0 APT. O1 receives C APT they should have forwarded to B.
```

The beneficiary `B` loses `C` APT. The amount scales with pool size and commission rate.

    public entry fun set_beneficiary_for_operator(
        operator: &signer, new_beneficiary: address
    ) acquires BeneficiaryForOperator {
        assert!(
            features::operator_beneficiary_change_enabled(),
            std::error::invalid_state(EOPERATOR_BENEFICIARY_CHANGE_NOT_SUPPORTED)
        );
        // The beneficiay address of an operator is stored under the operator's address.
        // So, the operator does not need to be validated with respect to a staking pool.
        let operator_addr = signer::address_of(operator);
        let old_beneficiary = beneficiary_for_operator(operator_addr);
        if (exists<BeneficiaryForOperator>(operator_addr)) {
            borrow_global_mut<BeneficiaryForOperator>(operator_addr).beneficiary_for_operator =
                new_beneficiary;
        } else {
            move_to(
                operator,
                BeneficiaryForOperator { beneficiary_for_operator: new_beneficiary }
            );
        };

        emit(
            SetBeneficiaryForOperator {
                operator: operator_addr,
                old_beneficiary,
                new_beneficiary
            }
        );
    }
