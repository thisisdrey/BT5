### Title
Unauthenticated `RecvError` packet spoofing allows remote tunnel teardown without any CA-signed certificate - (File: `outside.go`)

### Summary
Nebula's `RecvError` control message is processed as a completely unauthenticated, unencrypted packet type. Any network attacker who can observe (or brute-force) a victim's plaintext `RemoteIndex` — a value carried in the clear in every Nebula packet header — and spoof a UDP source address can forge a `RecvError` packet that forces the receiving node to tear down an active, legitimately-negotiated tunnel. No certificate, no handshake, and no cryptographic proof of relationship to the tunnel is required to trigger this state change.

### Finding Description
Incoming UDP packets are dispatched in `readOutsidePackets` immediately after header parsing, before any certificate/connection-state check: [1](#0-0) 

For `header.RecvError`, the packet is routed straight to `f.handleRecvError` with no decryption, no AEAD tag, and no association to a Noise session: [2](#0-1) 

The only "authentication" performed is comparing the packet's source `netip.AddrPort` against the hostinfo's currently recorded remote (`hr`). If `hr` is not yet valid (e.g. the tunnel is relayed, or the direct remote hasn't been learned yet) or if the attacker can also spoof the UDP source address to match `hr`, the check is bypassed entirely: [3](#0-2) 

Critically, the `RemoteIndex` value needed to target a specific tunnel is not secret — it is transmitted in cleartext in the wire header on every packet, including ordinary encrypted data-plane traffic: [4](#0-3) [5](#0-4) 

So any party positioned to see one packet exchange between two Nebula peers (or one that can brute-force the 32-bit index) learns the exact `RemoteIndex` needed, and — combined with UDP source-address spoofing, which requires no cryptographic material at all — can construct a valid-looking `RecvError` packet that the target will act on: [6](#0-5) 

This mirrors the reported bug class: a party with no privileged standing (in the original report, no ownership over `FraxSwapFactory`; here, no CA-issued certificate) can unilaterally force a state change in a system component (a fee-bearing pool / an authenticated tunnel) that only a privileged actor was intended to control, and the legitimate participants bear the cost (lost trading fees / lost connectivity, forced re-handshake) until something is done about it.

### Impact Explanation
An attacker who is not a member of the Nebula network (holds no CA-signed certificate) can:
- Tear down arbitrary active tunnels between two legitimate, mutually-authenticated peers by replaying an observed or guessed `RemoteIndex` in a forged, unauthenticated `RecvError` packet.
- Force the affected node to call `f.closeTunnel(hostinfo)` and delete pending handshake state via `hm.DeleteHostInfo`, degrading availability and forcing costly re-handshakes.
- Repeat this continuously to keep a target peer pair from maintaining a stable tunnel, a persistent denial-of-service against the encrypted overlay — accomplished purely from outside the trust boundary the certificate/CA system is meant to enforce.

### Likelihood Explanation
- The `RemoteIndex` is not secret; it is sent in plaintext in every packet header, so any on-path observer (no cert, no compromise of a peer) can harvest it.
- UDP source-address spoofing to satisfy the `hr != addr` check is a well-known low-effort technique, and the check is skipped altogether when `hr` isn't yet populated (e.g., relayed hosts, or the window between handshake completion and remote confirmation).
- The 32-bit `RemoteIndex` space is also brute-forceable for pure off-path attackers over time, since `handleRecvError` performs a cheap map lookup (`QueryReverseIndex`) with no rate limiting shown in the reviewed code.
- The default configuration (`listen.accept_recv_error: always`, per `reloadAcceptRecvError`) accepts these packets from any endpoint unless an operator explicitly restricts it, so the vulnerable path is live by default: [7](#0-6) 

### Recommendation
- Bind `RecvError` acceptance to cryptographic proof of relationship to the tunnel rather than a bare index/source-address comparison — e.g., require the `RecvError` to be authenticated (signed/MACed with a key derived from the tunnel's Noise session) so an attacker without the session key cannot forge it.
- At minimum, do not treat an invalid/unset `hr` as "no check needed"; instead require additional corroborating evidence (e.g., recent legitimate traffic timing, rate limiting per source, or requiring the packet to be encrypted under the tunnel's cipher state) before tearing down a tunnel.
- Consider deprecating the plaintext teardown-by-index mechanism in favor of an authenticated control message, consistent with how other state-changing operations (handshake completion, cert validation) require verified identity.

### Proof of Concept
1. Two Nebula peers `A` and `B` complete a handshake and establish a tunnel; `A` learns its `HostInfo.localIndexId` (its own `RemoteIndex` as seen by `B`) which appears in cleartext in every subsequent packet header from `B` (or vice versa), per `header.H.Parse`.
2. An attacker `E`, holding no CA-signed certificate, passively observes one UDP packet between `A` and `B` (e.g., on a shared network segment, or via a compromised router/ISP hop) and extracts the plaintext `RemoteIndex`.
3. `E` crafts a raw UDP packet: header with `Type = header.RecvError`, `RemoteIndex` = the harvested index, and spoofs the source address to match what `A` currently believes is `B`'s remote (`hostinfo.GetRemote()`), or simply sends it when that field is not yet populated (relay/pending state).
4. `A` receives the packet in `readOutsidePackets`, routes it to `handleRecvError`, finds the matching hostinfo via `QueryReverseIndex`, the spoof check passes (address matches or `hr` was invalid), and `A` calls `closeTunnel`/`DeleteHostInfo`, terminating the legitimate tunnel to `B` — achieved entirely without possessing any Nebula certificate.

```go
func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
```

```go
func (h *H) Parse(b []byte) error {
	if len(b) < Len {
		return ErrHeaderTooShort
	}
	// get upper 4 bytes
	h.Version = uint8((b[0] >> 4) & 0x0f)
	// get lower 4 bytes
	h.Type = MessageType(b[0] & 0x0f)
	h.Subtype = MessageSubType(b[1])
	h.Reserved = binary.BigEndian.Uint16(b[2:4])
	h.RemoteIndex = binary.BigEndian.Uint32(b[4:8])
	h.MessageCounter = binary.BigEndian.Uint64(b[8:16])
	return nil
}
```

```go
func (f *Interface) reloadAcceptRecvError(c *config.C) {
	if c.InitialLoad() || c.HasChanged("listen.accept_recv_error") {
		stringValue := c.GetString("listen.accept_recv_error", "always")

		switch stringValue {
		case "always":
			f.acceptRecvErrorConfig = recvErrorAlways
		case "never":
			f.acceptRecvErrorConfig = recvErrorNever
		case "private":
			f.acceptRecvErrorConfig = recvErrorPrivate
		default:
			if c.GetBool("listen.accept_recv_error", true) {
				f.acceptRecvErrorConfig = recvErrorAlways
			} else {
				f.acceptRecvErrorConfig = recvErrorNever
			}
		}

		f.l.Info("Loaded accept_recv_error config", "acceptRecvError", f.acceptRecvErrorConfig.String())
	}
}
```
