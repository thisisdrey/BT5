### Title
Reward accrual desync: DebtToken balances grow via interest without triggering `updateBeforeMintOrBurn`, causing `RewardsDistributor` to misattribute accrued rewards - (File: contracts/RewardsDistributor.sol)

### Summary
`RewardsDistributor` assumes a token's `balanceOf` only changes through calls into `updateBeforeMintOrBurn`/`updateBeforeTransfer` (i.e., the stored `accountIndexOf` stays in sync with actual balances). `DebtToken.balanceOf` returns a continuously growing amount (`principalOf * debtIndex / debtIndexOf`), and `accrueInterest()` grows `totalSupply_` and every holder's balance without calling any reward hook. This is the same bug class as M-07: a user's balance changed underneath a stored accounting snapshot, so the stored index/entitlement and the live balance desync — one side (rewards entitlement vs. total supply) is evaluated against stale data of the other.

### Finding Description
In `RewardsDistributor._calculateTokenDelta` ( [1](#0-0) ), accrued rewards are computed as `token_.balanceOf(account_).wadMul(_deltaIndex)`, i.e., the *current* balance is multiplied by the whole index delta accumulated since the last hook call.

For `DepositToken` this is safe because every balance mutation goes through `updateRewardsBeforeMintOrBurn`/`updateRewardsBeforeTransfer` ( [2](#0-1) [3](#0-2) ).

For `DebtToken`, `balanceOf` grows every block via interest ( [4](#0-3) ) and `accrueInterest()` mutates `totalSupply_`/`debtIndex` with no reward-distributor update at all ( [5](#0-4) ). Between `_updateTokensAccruedOf` calls the account's balance drifts, so:

- A holder whose debt balance grew via interest is credited `balanceOf(t1) × deltaIndex` — rewards for the entire past period computed on the inflated balance, diluting other deposit/debt token holders' yield.
- A user who repays debt mid-period has the delta computed on the reduced balance, forfeiting rewards they earned while the larger balance was outstanding — even though `repay`/`repayAll`/`burn` call the hook only for that account and the index delta already moved.

`updateBeforeMintOrBurn` is permissionless ( [6](#0-5) ), so an attacker can time the update to maximize capture (e.g., call it right after `accrueInterest` has grown their balance, then `repay`).

### Impact Explanation
Theft/misallocation of unclaimed yield (an accepted impact class): whenever a reward speed (`tokenSpeeds[debtToken]`) is non-zero for a `DebtToken` — the code explicitly supports registering debt tokens (`tokens()` array, tests accrue rewards on `debtToken1`/`debtToken2`), interest accrual inflates the claimer's reward share at the expense of all other accounts, and repayers permanently lose rewards already earned.

### Likelihood Explanation
Requires a `DebtToken` to have non-zero reward speed in a `RewardsDistributor` — a supported configuration path (`updateTokenSpeed` accepts any token; tests register debt tokens). Attack path is fully unprivileged: `accrueInterest`, `repay`, and `updateBeforeMintOrBurn` are all public. No privileged actor, oracle manipulation, or governance action needed. The magnitude scales with interest rate and elapsed time; pools with idle periods accrue the largest deltas.

### Recommendation
Either exclude `DebtToken` from reward distribution (its `balanceOf` is virtual and drifts without hook calls), or change `RewardsDistributor` to accrue against `principalOf` / hook `accrueInterest` so that interest-driven balance changes settle accrued rewards before the balance moves — mirroring the M-07 fix of keeping stored accounting in sync with balance changes.

### Proof of Concept
```solidity
// Hardhat/fork-style PoC, mirrors test/RewardDistributor.test.ts setup
// given: rewardsDistributor has tokenSpeed(debtToken) = 1e18 wei/s, alice issued debt at t0

// t0: alice issues 100e18 debt; hook sets accountIndexOf[debtToken][alice] = current index
await debtToken.connect(alice).issue(ethers.utils.parseEther('100'), alice.address);

// interest rate > 0; advance 10 blocks -> alice.balanceOf grows via interest with NO hook call
await increaseTimeOfNextBlock(10);
const balBefore = await debtToken.balanceOf(alice.address);   // e.g. 100e18 * (1 + r*10)

// trigger index update for alice only (public function)
await rewardsDistributor.updateBeforeMintOrBurn(debtToken.address, alice.address);

// accrued uses the interest-inflated balance over the whole 10s delta:
// tokensAccruedOf[alice] = balBefore * deltaIndex, although her balance was < balBefore for most of the period
const accrued = await rewardsDistributor.tokensAccruedOf(alice.address);
// assert: accrued > speed * 10s * (trueTimeWeightedShare) -> excess stolen from other holders

// symmetric loss case: bob repays debt mid-window; delta computed on reduced balance
// -> tokensAccruedOf[bob] undercounts rewards earned while his larger balance was outstanding
```

Invariant broken: reward accrual (`tokensAccruedOf`/`accountIndexOf`) must equal time-weighted actual balances; interest accrual and repayment break that by changing `balanceOf` without settling the index first.
