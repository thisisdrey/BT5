### Title
Cross-repository object-directory quarantine confusion via unverified `GitObjectDirectory` basename check - ([File: internal/git/localrepo/paths.go])

### Summary
`Repo.ObjectDirectoryPath` in [1](#0-0)  accepts a client-influenced `GitObjectDirectory` value and, instead of always verifying that the path belongs to the *target* repository, takes a "shortcut": if the resolved relative path's basename is literally `quarantine` (or the parent is `quarantine` and the basename starts with `tmp_objdir`), it treats it as a legitimate transaction quarantine directory and skips the ownership check entirely (`isTransactionQuarantineDir` branch at [2](#0-1) ). This mirrors the reported bug class: a decision ("is this the router's own proxy-TON wallet / this repo's own quarantine dir") is made purely by matching a superficial attribute (receiver address / directory basename) instead of verifying the actual backing resource is bound to the caller's own context.

### Finding Description
`ObjectDirectoryPath` first ensures the path is inside the storage root via `storage.ValidateRelativePath(storagePath, ...)` [3](#0-2) , which only guarantees the path does not escape the storage, not that it belongs to the requesting repository. It then computes `isTransactionQuarantineDir` purely from the basename pattern and, when true, **never** validates that the directory was actually created for this repository/transaction: the ownership check (matching against `storage.QuarantineDirectoryPrefix(repo)`, which is derived from a hash of the repository's own relative path, see [4](#0-3) ) is only performed in the `!isTransactionQuarantineDir` branch [5](#0-4) .

The `GitObjectDirectory` field and the snapshot relative-path header (`MetadataKeySnapshotRelativePath`) that feed this code path are attacker-influenceable for accessor (read-only) RPCs: the transaction middleware explicitly special-cases requests where `GitObjectDirectory`/`GitAlternateObjectDirectories` are already set, treating them as “looped back from Rails’ access checks” and running them **non-transactionally**, without re-validating that the quarantine belongs to the repository — mutators are rejected, but accessors are allowed through unchanged [6](#0-5) . The comment in the code itself acknowledges this is an assumption, not an enforced invariant: “This property is violated in tests which manually configure the object directory… we’ll leave this unaddressed for now” [7](#0-6) .

As a result, a caller of any accessor RPC that exposes `GitObjectDirectory` on the `Repository` message (e.g. `GetObjectDirectorySize`, tested with quarantine handling in [8](#0-7) ) can set `GitObjectDirectory` to a path whose basename is `quarantine` (or `quarantine/tmp_objdir-*`) that does not actually belong to their own repository/transaction, and `ObjectDirectoryPath` will accept it without checking that it was allocated for the caller's transaction — unlike the parallel “manual quarantine” path, which does enforce the repository-specific hash prefix.

### Impact Explanation
This is a storage/quarantine-isolation bypass analogous to the reported "receiver check without verifying the underlying resource matches" bug: the check that gates trust (basename == `quarantine`) is decoupled from the check that should establish ownership (prefix hash tied to the requesting repository's relative path). If an attacker can reference another concurrently-running transaction's quarantine directory (which contains freshly pushed, not-yet-verified/committed objects, potentially from a different, private repository), read-only RPCs would then serve or compute over object data that does not belong to the calling repository, constituting cross-repository object/data disclosure.

### Likelihood Explanation
Exploitability is limited by the difficulty of an attacker learning or guessing another transaction's temporary quarantine directory name/location on the storage, and I was not able to fully verify (within the scope of this analysis) the exact randomness/predictability of the temporary directory naming produced by `tempdir.NewWithPrefix`, nor confirm a concrete accessor RPC that returns full object contents (as opposed to only aggregate size) through this path. This uncertainty tempers the likelihood, but the code path itself is real and the missing ownership check is a genuine logic gap, not a hypothetical one — the existing test suite in [9](#0-8)  only exercises the intended “happy path” (a quarantine that does belong to the repository) and does not test the case of a foreign quarantine directory that merely matches the basename pattern.

### Recommendation
In `ObjectDirectoryPath` ( [2](#0-1) ), always validate that a quarantine directory — whether matched via the `isTransactionQuarantineDir` heuristic or the manual-prefix path — is bound to the specific repository/transaction being served, e.g. by requiring the transaction-quarantine directory path to also carry (or be looked up against) the repository-specific `QuarantineDirectoryPrefix` rather than relying solely on the generic basename pattern `quarantine`/`tmp_objdir-*`. Additionally, tighten `transactionalizeRequest`/`beginTransactionForRepository` in [6](#0-5)  so that a client-supplied `GitObjectDirectory` is only trusted when it can be cryptographically/structurally tied to the transaction the caller is authorized for, closing the gap acknowledged in the existing code comment.

### Proof of Concept
Conceptual (not fully verified end-to-end due to index limitations on temp-directory naming internals):
1. Attacker starts a push to repo A, creating a transaction quarantine directory such as `<storage>/tx-tmp-A/quarantine/tmp_objdir-incoming-XXXX` (per [10](#0-9) ).
2. As soon as/while it exists, attacker (or colluding second identity) issues an accessor RPC (e.g. `GetObjectDirectorySize`) for a different repository B they control, setting `Repository.GitObjectDirectory` to a relative path that resolves to repo A's `quarantine/tmp_objdir-incoming-XXXX` directory, and supplying the `relative-path-bin` metadata header with repo B's snapshot relative path so `restoreSnapshotRelativePath` accepts it non-transactionally ( [11](#0-10) ).
3. `ObjectDirectoryPath` classifies this as `isTransactionQuarantineDir` purely from the basename and skips the prefix-ownership check, returning the path unchanged.
4. The RPC handler then operates on repo A's in-flight quarantine objects while believing it is operating within repo B's authorized scope, disclosing information about repo A's push contents to the caller of repo B's RPC.

// ObjectDirectoryPath returns the full path of the object directory. The errors returned are gRPC
// errors with relevant error codes and should be passed back to gRPC without further decoration.
func (repo *Repo) ObjectDirectoryPath(ctx context.Context) (string, error) {
	repoPath, err := repo.Path(ctx)
	if err != nil {
		return "", err
	}

	objectDirectoryPath := repo.GetGitObjectDirectory()
	if objectDirectoryPath == "" {
		return "", structerr.NewInvalidArgument("object directory path is not set")
	}

	storagePath, err := repo.locator.GetStorageByName(ctx, repo.GetStorageName())
	if err != nil {
		return "", fmt.Errorf("get storage by name: %w", err)
	}

	// Ensure the path points somewhere in the storage.
	relativeObjectDirectoryPath, err := storage.ValidateRelativePath(storagePath, filepath.Join(repoPath, objectDirectoryPath))
	if err != nil {
		return "", structerr.NewInvalidArgument("validate relative path: %w", err)
	}

	parentDir := filepath.Base(filepath.Dir(relativeObjectDirectoryPath))
	baseDir := filepath.Base(relativeObjectDirectoryPath)
	isTransactionQuarantineDir := (baseDir == "quarantine") || ((parentDir == "quarantine") && strings.HasPrefix(baseDir, "tmp_objdir"))

	// Transactions quarantine a repository by pointing the object directory to a 'quarantine' named
	// directory in the transaction's temporary directory. If the base directory is `quarantine`,
	// Git push may apply an additional layer of quarantine such as `/quarantine/tmp_objdir-incoming-Gbc29N`
	// so we don't assert the `/quarantine` being the last element of the path. We thus also check for
	// whether the parent directory is in `quarantine` and whether the base directory has the expected
	// `tmp_objdir` suffix.
	if !isTransactionQuarantineDir {
		// We need to check whether the relative object directory as given by the repository is
		// a valid path. This may either be a path in the Git repository itself, where it may either
		// point to the main object directory storage or to an object quarantine directory as
		// created by git-receive-pack(1). Alternatively, if that is not the case, then it may be a
		// manual object quarantine directory located in the storage's temporary directory. These
		// have a repository-specific prefix which we must check in order to determine whether the
		// quarantine directory does in fact belong to the repo at hand.
		if _, origError := storage.ValidateRelativePath(repoPath, objectDirectoryPath); origError != nil {
			tempDir, err := repo.locator.TempDir(repo.GetStorageName())
			if err != nil {
				return "", structerr.NewInvalidArgument("getting storage's temporary directory: %w", err)
			}

			expectedQuarantinePrefix := filepath.Join(tempDir, storage.QuarantineDirectoryPrefix(repo))
			absoluteObjectDirectoryPath := filepath.Join(repoPath, objectDirectoryPath)

			// The relative path is outside of the repository
			if !strings.HasPrefix(absoluteObjectDirectoryPath, expectedQuarantinePrefix) {
				return "", structerr.NewInvalidArgument("not a valid relative path: %w", origError)
			}
		}
	}

// QuarantineDirectoryPrefix returns a prefix for use in the temporary directory. The prefix is
// based on the relative repository path and will stay stable for any given repository. This allows
// us to verify that a given quarantine object directory indeed belongs to the repository at hand.
// Ideally, this function would directly be located in the quarantine module, but this is not
// possible due to cyclic dependencies.
func QuarantineDirectoryPrefix(repo Repository) string {
	hash := [20]byte{}
	if repo != nil {
		hash = sha1.Sum([]byte(repo.GetRelativePath()))
	}
	return fmt.Sprintf("quarantine-%x-", hash[:8])
}

func restoreSnapshotRelativePath(ctx context.Context, methodInfo protoregistry.MethodInfo, req proto.Message) (proto.Message, error) {
	// Rails sends RPCs from its access checks with quarantine applied. The quarantine paths are relative to the
	// snapshot repository of the original transaction. While the relative path of the request is the original relative
	// path of the repository before snapshotting, Rails sends the snapshot repository's path in a header. For the
	// quarantine paths to apply correctly, we must thus rewrite the request to point to the snapshot repository here.
	snapshotRelativePath := metadata.GetValue(ctx, MetadataKeySnapshotRelativePath)
	if snapshotRelativePath == "" {
		return nil, ErrQuarantineWithoutSnapshotRelativePath
	}

	rewrittenReq, targetRepo, err := rewritableRequest(methodInfo, req)
	if err != nil {
		return nil, fmt.Errorf("rewritable request: %w", err)
	}

	targetRepo.RelativePath = snapshotRelativePath

	return rewrittenReq, nil
}

func New(ctx context.Context, repo *gitalypb.Repository, logger log.Logger, locator storage.Locator) (*Dir, func(), error) {
	repoPath, err := locator.GetRepoPath(ctx, repo, storage.WithRepositoryVerificationSkipped())
	if err != nil {
		return nil, nil, structerr.NewInternal("getting repo path: %w", err)
	}

	quarantineDir, cleanup, err := tempdir.NewWithPrefix(ctx, repo.GetStorageName(),
		storage.QuarantineDirectoryPrefix(repo), logger, locator)
	if err != nil {
		return nil, nil, fmt.Errorf("creating quarantine: %w", err)
	}

	quarantinedRepo, err := Apply(repoPath, repo, quarantineDir.Path())
	if err != nil {
		cleanup() // Clean up if we fail after creating the temp directory
		return nil, nil, err
	}

	return &Dir{
		repo:            repo,
		quarantinedRepo: quarantinedRepo,
		locator:         locator,
		dir:             quarantineDir,
	}, cleanup, nil
}
