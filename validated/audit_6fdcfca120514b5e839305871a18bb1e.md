## Analog Identified: Roaming trust accepts an authenticated packet's source address without binding it to that address

### Title
Host roaming accepts any address that carries a validly-authenticated packet, allowing address-spoofing replay to hijack a tunnel's trusted remote — ([File: outside.go])

### Summary
The external report's root cause is that a signature is computed over data that does not include the identity of the party presenting it (the executor address), so a valid signature can be replayed from a different address and be treated as equally authoritative. Nebula's `handleHostRoaming` has the analogous flaw: the AEAD authentication tag over a data-plane packet only covers the Nebula header and ciphertext, never the sender's actual UDP source address, yet `handleHostRoaming` treats "this packet decrypted correctly" as sufficient proof that "the peer is now reachable at `via.UdpAddr`" and updates the tunnel's trusted remote accordingly.

### Finding Description
In `outside.go`, `readOutsidePackets` decrypts a data-plane packet via `hostinfo.ConnectionState.Decrypt`, which validates authenticity using `dKey.DecryptDanger(out, packet[:header.Len], packet[header.Len:], messageCounter, nb)` [1](#0-0)  — the associated data is only `packet[:header.Len]` (type/subtype/remoteIndex/counter), never the sender's network address. Immediately after a successful decrypt, `f.handleHostRoaming(hostinfo, via)` is called using `via.UdpAddr`, the address the packet arrived from, and unconditionally learns it as the new trusted remote when it differs from the current one and passes the `remote_allow_list` check: [2](#0-1) 

Because the AEAD tag never binds the packet to the specific address it was sent to/from, any party who can capture (or otherwise obtain) one legitimate, still-fresh ciphertext for a tunnel — and present/replay it from a different source address before the real copy is consumed by the replay window — causes the victim to move its trusted remote to that address. The `remote_allow_list` gate only filters address ranges, not identity, and `lastRoam`/`RoamingSuppressSeconds` only rate-limit flapping, not authenticity of the roam. This mirrors the reported bug class precisely: the authenticated payload lacks a binding to "who/where is presenting it," so it can be replayed from another address and accepted as trustworthy.

### Impact Explanation
A successful spoofed roam redirects one victim's tunnel traffic to an address the attacker controls (or to an unrelated third party as a reflection/DoS), effectively hijacking the encrypted tunnel's destination without needing a CA-signed certificate or ever completing a handshake. This can be used to blackhole traffic (denial of service) or, if the attacker can also receive on the claimed address, to intercept subsequently mis-routed application data.

### Likelihood Explanation
Exploitation requires only network position to capture one packet and the ability to send a spoofed-source UDP packet (or otherwise deliver traffic tagged with a different `via.UdpAddr`, e.g., via relayed/duplicated ingestion paths) before the legitimate packet with that counter is consumed. No valid certificate, private key, or completed handshake is required — the attacker is replaying data they merely intercepted. This is a moderate bar (on-path or spoof-capable position), consistent with a Medium/High-likelihood classification similar to the original report.

### Recommendation
Do not treat the mere successful decryption of a data-plane packet as proof that a given address is a member of the tunnel's legitimate path. Options:
- Require additional confirmation before roaming (e.g., only roam once packets are decrypted from a new address for messages the peer explicitly acknowledges, or bind address-transition intent into the AEAD associated data, similar to binding `msg.sender` into the signed hash in the report).
- At minimum, require a fresh, unused message counter combined with rate-limited/strict promotion criteria (e.g., mutual confirmation via a `Test`/ping-pong round trip from the new address) before committing to a roam, rather than acting on the first packet observed from a new source.

### Proof of Concept
1. Attacker positions on-path (or otherwise captures) one legitimate encrypted data-plane packet `P` (header + ciphertext) sent by peer B to peer A, with message counter `c` not yet consumed by A's replay window.
2. Attacker relays/replays `P` to A from spoofed source address `X` before the genuine copy (sent to A's real address) arrives or is processed.
3. `readOutsidePackets` decrypts `P` successfully (AEAD only authenticates header+ciphertext, not source address) and calls `handleHostRoaming(hostinfo, via{UdpAddr: X})`.
4. Since `X` differs from `hostinfo.GetRemote()` and passes the `remote_allow_list`, `handleHostRoaming` calls `hostinfo.SetRemote(X)`, and A begins sending subsequent tunnel traffic for B to address `X` instead of B's real address. [2](#0-1) [1](#0-0)

func (cs *ConnectionState) Decrypt(l *slog.Logger, messageCounter uint64, out []byte, packet []byte, nb []byte) ([]byte, error) {
	var err error
	cs.decryptLock.Lock()
	result := cs.window.Check(l, messageCounter)
	cs.decryptLock.Unlock()
	if !result {
		return nil, ErrAlreadySeen
	}

	out, err = cs.dKey.DecryptDanger(out, packet[:header.Len], packet[header.Len:], messageCounter, nb)
	if err != nil {
		return nil, err
	}

	result = cs.window.Update(l, messageCounter)
	cs.decryptLock.Unlock()
	if !result {
		return nil, ErrAlreadySeen
	}

func (f *Interface) handleHostRoaming(hostinfo *HostInfo, via ViaSender) {
	curRemote := hostinfo.GetRemote()
	if !via.IsRelayed && curRemote != via.UdpAddr {
		if !f.lightHouse.GetRemoteAllowList().AllowAll(hostinfo.vpnAddrs, via.UdpAddr.Addr()) {
			if f.l.Enabled(context.Background(), slog.LevelDebug) {
				hostinfo.logger(f.l).Debug("lighthouse.remote_allow_list denied roaming", "newAddr", via.UdpAddr)
			}
			return
		}

		if !hostinfo.lastRoam.IsZero() && via.UdpAddr == hostinfo.lastRoamRemote && time.Since(hostinfo.lastRoam) < RoamingSuppressSeconds*time.Second {
			if f.l.Enabled(context.Background(), slog.LevelDebug) {
				hostinfo.logger(f.l).Debug("Suppressing roam back to previous remote",
					"suppressSeconds", RoamingSuppressSeconds,
					"udpAddr", curRemote,
					"newAddr", via.UdpAddr,
				)
			}
			return
		}

		hostinfo.logger(f.l).Info("Host roamed to new udp ip/port.",
			"udpAddr", curRemote,
			"newAddr", via.UdpAddr,
		)
		hostinfo.lastRoam = time.Now()
		hostinfo.lastRoamRemote = curRemote
		hostinfo.SetRemote(via.UdpAddr)
	}
