## Title
Permanently unrecoverable user funds in `LostTips` storage with no redemption/withdrawal extrinsic - (File: bridges/snowbridge/pallets/system-v2/src/lib.rs)

## Summary
`pallet_system_frontend::add_tip` on AssetHub swaps/burns a user's asset for Ether via `swap_fee_asset_and_burn` before the tip is even dispatched to BridgeHub. On BridgeHub, `snowbridge_pallet_system_v2::add_tip` attempts to attribute that Ether amount to a relayer reward via `InboundQueue::add_tip`/`OutboundQueue::add_tip`; on failure (e.g., nonce already consumed or order not found), the amount is written into `LostTips::<T>` instead of refunded, and no extrinsic anywhere in the pallet or its callers ever reads or pays out this map.

## Finding Description
The storage comment itself documents the gap: `LostTips` is meant to "support implementing a recovery method in the future," but no such method exists [1](#0-0) . The value is destroyed before failure is even known: `swap_fee_asset_and_burn` either swaps the tip asset for Ether and burns it via `swap_and_burn`, or burns it directly via `burn_for_teleport` [2](#0-1) , and this happens unconditionally inside `add_tip` on the frontend pallet before the cross-chain call is even sent [3](#0-2) . On BridgeHub, `snowbridge_pallet_system_v2::add_tip` only records the loss into `LostTips` on failure and never refunds it [4](#0-3) . The underlying `InboundQueue::add_tip` implementation confirms the rejection condition is ordinary and unprivileged: it simply checks `Nonce::<T>::get(nonce)` and returns `AddTipError::NonceConsumed` if the nonce was already processed [5](#0-4) . A grep across the repository for `withdraw_lost_tips`, `reclaim_tip`, `redeem_tip`, `claim_lost`, or any read/removal of `LostTips` (`take`/`remove`) returns no matches, confirming this is a write-only storage map with no redemption path.

## Impact Explanation
Any unprivileged AssetHub user who tips a nonce that is already consumed, not yet known, or otherwise rejected loses the corresponding swapped/burned asset value permanently, since it is recorded only in `LostTips` and there is no call path to recover it. This matches the "permanent user-fund lock" impact bucket in the Polkadot SDK Impact Gate, since real economic value (the burned/swapped asset amount) is irrecoverably locked in a dead-end storage map for the affected account.

## Likelihood Explanation
High and unprivileged: the existing unit test `add_tip_inbound_fails_when_nonce_is_consumed` [6](#0-5)  and the emulated integration test `tip_to_invalid_nonce_is_added_to_lost_tips` [7](#0-6)  both demonstrate that tipping a stale/invalid nonce is trivially reachable via ordinary use (no privileged actor, no race condition needed beyond normal timing between tip submission and message processing).

## Recommendation
Implement the documented recovery path: add a permissioned extrinsic (restricted to the original `sender`, or an automatic XCM-based refund back to the originating chain/account) that reads and zeroes `LostTips::<T>::get(&sender)` and settles the value back to the user. Alternatively, validate nonce/order existence on BridgeHub before the frontend pallet burns/swaps the asset, so failure is detected prior to irreversible value destruction.

## Proof of Concept
1. On AssetHub, call `EthereumSystemFrontend::add_tip(origin=signed(Alice), message_id=Outbound(N), asset)` with `N` a nonce that does not exist or is already processed.
2. `swap_fee_asset_and_burn` burns/swaps Alice's asset for Ether and teleports it cross-chain [8](#0-7) .
3. On BridgeHub, `EthereumSystemV2::add_tip` calls `InboundQueue::add_tip`/`OutboundQueue::add_tip`, which returns `Err(AddTipError::NonceConsumed)` for the already-processed nonce.
4. `LostTips::<T>::mutate(&sender, ...)` records the amount and `TipProcessed { success: false }` is emitted [9](#0-8) .
5. As confirmed by the integration test, `LostTips::<bridge_hub_westend_runtime::Runtime>::get(relayer)` is now non-zero [10](#0-9) , and no extrinsic in the codebase ever reads or pays this value back to Alice.

		pub fn add_tip(
			origin: OriginFor<T>,
			sender: AccountIdOf<T>,
			message_id: MessageId,
			amount: u128,
		) -> DispatchResult {
			T::FrontendOrigin::ensure_origin(origin)?;

			let result = match message_id {
				Inbound(nonce) => <T as pallet::Config>::InboundQueue::add_tip(nonce, amount),
				Outbound(nonce) => <T as pallet::Config>::OutboundQueue::add_tip(nonce, amount),
			};

			if let Err(ref e) = result {
				tracing::debug!(target: LOG_TARGET, ?e, ?message_id, ?amount, "error adding tip");
				LostTips::<T>::mutate(&sender, |lost_tip| {
					*lost_tip = lost_tip.saturating_add(amount);
				});
			}

			Self::deposit_event(Event::<T>::TipProcessed {
				sender,
				message_id,
				amount,
				success: result.is_ok(),
			});

			Ok(())
		}

		fn swap_fee_asset_and_burn(
			origin: Location,
			fee_asset: Asset,
		) -> Result<u128, DispatchError> {
			let ether_location = T::EthereumLocation::get();
			let (fee_asset_location, fee_amount) = match fee_asset {
				Asset { id: AssetId(ref loc), fun: Fungible(amount) } => (loc, amount),
				_ => {
					tracing::debug!(target: LOG_TARGET, ?fee_asset, "error matching fee asset");
					return Err(Error::<T>::UnsupportedAsset.into());
				},
			};
			if fee_amount == 0 {
				return Ok(0);
			}

			let ether_gained = if *fee_asset_location != ether_location {
				Self::swap_and_burn(
					origin.clone(),
					fee_asset_location.clone(),
					ether_location,
					fee_amount,
				)
				.inspect_err(|&e| {
					tracing::debug!(target: LOG_TARGET, ?e, "error swapping asset");
				})?
			} else {
				burn_for_teleport::<T::AssetTransactor>(&origin, &fee_asset)
					.map_err(|_| Error::<T>::BurnError)?;
				fee_amount
			};
			Ok(ether_gained)
		}
