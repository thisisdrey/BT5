## Finding

### Title
Signer event receiver HTTP endpoint accepts unauthenticated event POSTs, forging stackerdb_chunks/block/burn-block events into the signer runloop - (File: libsigner/src/events.rs)

### Summary
The stacks-core project documents a security invariant that requires a shared secret (`auth_token` on the node side / `auth_password` on the signer side) to gate communication between a Stacks node and a signer's event listener [1](#0-0) , and this is reiterated in every sample config (`auth_token` / `auth_password` "must match") [2](#0-1) [3](#0-2) . However, `SignerEventReceiver::next_event`, which implements the actual HTTP handling for the signer's listening socket, never inspects any Authorization/auth token on the incoming request — it only checks the HTTP method and URL path before dispatching the body to `process_event` for `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, and `/new_block` [4](#0-3) . A grep across `libsigner/src/events.rs` for any auth/password/Authorization handling returns no matches, confirming the transport layer performs no authentication check at all.

### Finding Description
This mirrors the reported bug class: a documented invariant ("the value/field must be validated consistently with the chosen path") is never actually enforced in code, breaking an equality the system relies on — here, "authenticated sender == trusted node" is assumed but never checked. `EventReceiver::main_loop` simply loops calling `next_event()` and forwards whatever is returned to the signer runloop via `forward_event` [5](#0-4) . `next_event()` binds an `HttpServer` and, for any POST to a recognized URL, deserializes the body directly into a `SignerEvent<T>` with no verification that the sender possesses the configured `auth_token`/`auth_password` [6](#0-5) . Because sample configs bind this listener on `0.0.0.0` (e.g., `endpoint = "0.0.0.0:30000"` in the signing doc) [7](#0-6) , any network-reachable, unauthenticated peer can POST a forged `StackerDBChunksEvent`, `BlockValidateResponse`, `BurnBlockEvent`, or `StacksBlockEvent` payload and have it accepted and forwarded into the signer's decision-making input stream exactly as if it originated from the trusted node.

### Impact Explanation
This is an unauthenticated write into the signer's runloop input channel: an attacker who can reach the signer's bound port can inject forged `SignerEvent` data (StackerDB chunk events, burn block events, proposal responses) without any credential check, despite the system's documented security model explicitly relying on a shared `auth_token`/`auth_password` to prevent this. This matches the "unauthenticated/unauthorized write to state" and "network-wide propagation of forged data" impact categories, since forged StackerDB chunk events delivered this way are indistinguishable at the transport layer from genuine node-relayed events.

### Likelihood Explanation
Likelihood is high for any deployment binding the event receiver to a non-loopback address, since the check is entirely absent rather than merely misconfigured — no configuration can enable per-request authentication because the code path does not read or compare any token. This is a remote, few-message trigger (any authenticated-looking HTTP POST), requiring no admin/node secret and no privileged position, only network reachability to the signer's endpoint (a configuration many operators may loosen for containerized/remote signer setups, as `0.0.0.0` bindings appear in the docs themselves).

### Recommendation
Have `SignerEventReceiver::next_event` (and `process_event`) validate a shared-secret header/token against the configured `auth_password` before deserializing and forwarding any event body, rejecting requests that lack a valid token with a 401/403 response, mirroring the auth enforcement already documented as required between node and signer.

### Proof of Concept
1. Start a signer with `SignerEventReceiver` bound to a reachable address (e.g., `0.0.0.0:30000` per `docs/signing.md`).
2. From an arbitrary unauthenticated host, POST a crafted JSON body to `http://<signer-ip>:30000/stackerdb_chunks` with `Content-Type: application/json`, mimicking `StackerDBChunksEvent`'s JSON shape (as done by the legitimate test harness in `libsigner/src/tests/mod.rs` `test_simple_signer`, which sends the exact same unauthenticated raw HTTP request) [8](#0-7) .
3. Observe that `next_event()` accepts the POST, deserializes it via `process_event::<T, StackerDBChunksEvent>`, and forwards it to the signer runloop with no token check [9](#0-8) .

Note: I could not confirm within this investigation whether any auth check is layered at a level above `libsigner` (e.g., in `stacks-signer`'s own wrapping of the HTTP server) since `stacks-signer/src/config.rs` references `auth_password` only for config parsing per the grep hits, not request validation; a Devin session with full repo access should verify there is no such check elsewhere before treating this as fully confirmed.

```rust
    /// Main loop for the receiver.
    /// Typically, this is started in a separate thread.
    fn main_loop(&mut self) {
        loop {
            if self.is_stopped() {
                info!("Event receiver stopped");
                break;
            }
            let next_event = match self.next_event() {
                Ok(event) => event,
                Err(EventError::UnrecognizedEvent(..)) => {
                    // got an event that we don't care about (not a problem)
                    continue;
                }
                Err(EventError::Terminated) => {
                    // we're done
                    info!("Caught termination signal");
                    break;
                }
                Err(e) => {
                    warn!("Failed to receive next event: {:?}", &e);
                    continue;
                }
            };
            if !self.forward_event(next_event) {
                info!("Failed to forward event");
                break;
            }
        }
        info!("Event receiver main loop exit");
    }
}
```

```rust
    fn next_event(&mut self) -> Result<SignerEvent<T>, EventError> {
        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)
            } else if request.url() == "/new_block" {
                process_event::<T, StacksBlockEvent>(request)
            } else {
                let url = request.url().to_string();
                debug!(
                    "[{:?}] next_event got request with unexpected url {}, return OK so other side doesn't keep sending this",
                    event_receiver.local_addr,
                    url
                );
                ack_dispatcher(request);
                Err(EventError::UnrecognizedEvent(url))
            }
        })?
    }
```

```rust
fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}
```
