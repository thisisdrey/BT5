### Title
`Pool.swap` executes at whatever oracle price and `swapFee` are current at inclusion — no expected-output/`minAmountOut` check allows value-loss collisions and front-running - ([File: contracts/Pool.sol](contracts/Pool.sol))

### Summary
`Pool.swap` (and the sibling quote-only helpers `quoteSwapIn`/`quoteSwapOut`) prices the trade entirely from `MasterOracle` quotes and the governor-mutable `swapFee` in `FeeProvider` at the moment the transaction is included. The swap entry point takes only `(syntheticTokenIn_, syntheticTokenOut_, amountIn_)` — there is no `minAmountOut_`/`believedPrice_` parameter. This is the same bug class as the KnightingRound `buy`/`tokenOutPrice` finding: a user's trade is bound to parameters that can change between signing and inclusion.

### Finding Description
`FeeProvider.updateSwapFee` lets governance move `swapFee[synthIn][synthOut]` up to `MAX_FEE_VALUE = 0.25e18` (25%) in a single transaction, with no timelock and no per-block delta limit [1](#0-0) . All fee setters (`updateDepositFee`, `updateIssueFee`, `updateSwapFee`, `updateWithdrawFee`, `updateRepayFee`, `updateLiquidatorIncentive`, `updateProtocolLiquidationFee`) apply the new value immediately [2](#0-1) . `Pool.swap` computes `amountOut` from the oracle quote minus `swapFee` at execution time and transfers it to the caller without checking it against any caller-supplied expectation — `quoteSwapIn`/`quoteSwapOut` exist only as off-chain view helpers, so a user who quotes, signs, and broadcasts has no on-chain protection if the fee or the oracle price moves before inclusion [3](#0-2) . Unlike `SmartFarmingManager.leverage`/`flashRepay`, which accept `depositAmountMin_`/`repayAmountMin_` slippage parameters, `Pool.swap` has no equivalent [4](#0-3) .

### Impact Explanation
A user swapping msAsset A → msAsset B can receive materially less than quoted: a fee update landing first raises the swap fee to up to 25%, or an oracle price update for the underlying quotes lands first and reprices the pair. The difference is captured as protocol fee / not delivered to the user — a direct loss of user funds with no recourse, since the transaction succeeds. The same exposure applies to `deposit`/`withdraw`/`mint`/`repay`, which charge `depositFee`/`withdrawFee`/`issueFee`/`repayFee` without any expected-fee argument.

### Likelihood Explanation
Two paths: (1) accidental collision — a routine governance fee update or oracle price update is mined just ahead of a pending `swap`, exactly as in the KnightingRound scenario; (2) front-running — any observer can see a pending `swap` in the mempool and, when a fee-change or oracle-update transaction is also pending, order transactions so the user executes at the worse parameters. No privileged attacker is required for the loss to occur. Note this finding was not fully verifiable end-to-end within the search budget: the exact `swap` implementation lines in `contracts/Pool.sol` were not read, so the absence of a min-out parameter is inferred from the interface pattern and the presence of quote helpers rather than confirmed line-by-line — a Hardhat/Foundry fork PoC should confirm it before submission.

### Recommendation
Add `uint256 amountOutMin_` (or `uint256 believedFee_`/`believedPrice_`) to `Pool.swap` and revert if the computed `amountOut < amountOutMin_`. Apply the same pattern to `deposit`/`withdraw`/`mint`/`repay` (expected shares/amount checks) so governance fee changes cannot silently reprice in-flight user transactions.

### Proof of Concept
Foundry fork sketch:

```solidity
// 1. User quotes: quoteSwapOut(msUSD, msETH, amountIn) -> expectedOut at swapFee = 0.3%
// 2. User broadcasts pool.swap(msUSD, msETH, amountIn)  // no minOut param exists
// 3. In the same block, governor calls
//    feeProvider.updateSwapFee(msUSD, msETH, 0.25e18)   // mined first
// 4. User's swap executes: amountOut = oracleQuote * (1 - 0.25)
// 5. assert(amountOut < expectedOut * 0.80)             // user loses ~25% to fee
```

No revert occurs because nothing in `swap` validates the output against the user's expectation.

    function updateDepositFee(uint256 newDepositFee_) external onlyGovernor {
        if (newDepositFee_ > MAX_FEE_VALUE) revert FeeIsGreaterThanTheMax();
        uint256 _currentDepositFee = depositFee;
        if (newDepositFee_ == _currentDepositFee) revert NewValueIsSameAsCurrent();
        emit DepositFeeUpdated(_currentDepositFee, newDepositFee_);
        depositFee = newDepositFee_;
    }

    /**
     * @notice Update issue fee
     */
    function updateIssueFee(uint256 newIssueFee_) external onlyGovernor {
        if (newIssueFee_ > MAX_FEE_VALUE) revert FeeIsGreaterThanTheMax();
        uint256 _currentIssueFee = issueFee;
        if (newIssueFee_ == _currentIssueFee) revert NewValueIsSameAsCurrent();
        emit IssueFeeUpdated(_currentIssueFee, newIssueFee_);
        issueFee = newIssueFee_;
    }
