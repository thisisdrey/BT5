### Title
Handshake-abandoning connection churn from a single IP exhausts the global concurrent-connection slot pool before per-IP rate limiting is ever charged - ([File: streamer/src/nonblocking/quic.rs])

### Summary
`run_server` reserves a `ClientConnectionTracker` slot and increments `outstanding_incoming_connection_attempts` for every incoming QUIC handshake attempt, but only checks per-IP admission via the non-consuming `rate_limiter.is_allowed()` call at that point. `rate_limiter.register_connection()`, the call that actually consumes a token from the per-IP `ConnectionRateLimiter`, only runs inside `setup_connection` after the handshake completes successfully. An attacker that opens many QUIC connections and abandons them before the handshake finishes never triggers `register_connection`, so the per-IP limiter never records these attempts, while each attempt still occupies a `ClientConnectionTracker` slot (bounded globally, not per-IP) for up to `QUIC_CONNECTION_HANDSHAKE_TIMEOUT`.

### Finding Description
In `run_server` (`streamer/src/nonblocking/quic.rs`), the admission sequence for each incoming connection is: [1](#0-0) 
1. Global `overall_connection_rate_limiter.current_tokens()` check.
2. `rate_limiter.is_allowed(&ip)` — a **read-only** check of the per-IP `ConnectionRateLimiter` that does not consume a token: [2](#0-1) 
3. `ClientConnectionTracker::new(stats, qos.max_concurrent_connections())` — this enforces a **global** cap (`stats.open_connections` vs. `max_concurrent_connections`), not a per-IP cap: [3](#0-2) 
4. `outstanding_incoming_connection_attempts` is incremented, and the handshake is spawned via `setup_connection`.

Only inside `setup_connection`, after `timeout(QUIC_CONNECTION_HANDSHAKE_TIMEOUT, connecting).await` succeeds, is `rate_limiter.register_connection(&from.ip())` called to actually consume the per-IP token: [4](#0-3) . If the attacker drops the connection before the handshake completes (or lets it hit the timeout), `connecting_result` is `Err`, `register_connection` is never invoked, and `outstanding_incoming_connection_attempts` is simply decremented without the per-IP limiter ever being charged: [5](#0-4) .

Since `is_allowed()` only reflects previously *registered* (completed) connections and never blocks based on in-flight attempts, a single attacker IP can open a number of concurrent half-open QUIC connections up to the `ClientConnectionTracker`'s global `max_concurrent_connections` limit (which is deliberately global to allow bursts across all peers, staked and unstaked) without ever being penalized by the per-IP `ConnectionRateLimiter`. Each such attempt still occupies a global connection-tracker slot for the full `QUIC_CONNECTION_HANDSHAKE_TIMEOUT` window. This is not blocked by any other guard: the `overall_connection_rate_limiter` is shared cluster-wide and does not distinguish by IP either, and the design comment in `run_server` explicitly acknowledges only IP addresses that have "asserted control" (completed handshake) are charged, by design, to avoid punishing spoofed IPs — but this leaves the *global* `ClientConnectionTracker`/`outstanding_incoming_connection_attempts` pool exposed to a single real (non-spoofed) attacker repeating unfinished handshakes.

### Impact Explanation
By continuously opening and dropping QUIC connections mid-handshake, a single unstaked attacker IP can occupy a large fraction of the global concurrent-connection tracker slots (`max_concurrent_connections`, shared across all peer types) for `QUIC_CONNECTION_HANDSHAKE_TIMEOUT` per attempt, causing legitimate staked and unstaked peers' connection attempts to be refused via `refused_connections_too_many_open_connections`. This matches Agave's "Loss of availability"/DoS bounty category: a single unprivileged remote client can degrade TPU QUIC ingress availability for all other clients without ever being penalized by the IP-scoped rate limiter, since the accounting for per-IP abuse (`ConnectionRateLimiter::register_connection`) is deferred to post-handshake and thus evaded by handshake abandonment.

### Likelihood Explanation
This requires only an unstaked remote client capable of sending QUIC `Initial` packets and aborting before the handshake resolves — no stake, keys, or special privileges are needed. It is fully repeatable: the attacker can loop this indefinitely by opening new source ports/`Connecting` handles and letting each hit the `QUIC_CONNECTION_HANDSHAKE_TIMEOUT`, keeping the global `ClientConnectionTracker` near-saturated. The main constraint is the `overall_connection_rate_limiter` (`MAX_CONNECTION_BURST` / `TOTAL_CONNECTIONS_PER_SECOND`), which is a global token bucket shared by all IPs, so the actual achievable throughput of half-open connections depends on those constants; I was unable to confirm their exact values in this pass, which affects the precise magnitude of the achievable global-slot occupation, but the structural gap between the non-consuming `is_allowed()` pre-check and the consuming `register_connection()` post-handshake check is confirmed in the code.

### Recommendation
Track in-flight (not-yet-registered) connection attempts per source IP and count them against that IP's admission budget before granting a `ClientConnectionTracker` slot — e.g., reserve/charge a token in `ConnectionRateLimiter` (or a separate in-flight-attempts counter keyed by IP) at accept time and release it if the handshake fails, rather than only consuming on successful handshake. Alternatively, bound `outstanding_incoming_connection_attempts` per source IP independently of the global `max_concurrent_connections` limit so that no single IP can consume more than a fixed fraction of the pending-handshake slot pool.

### Proof of Concept
Integration test plan (extends existing tests like `test_rate_limiting` in `streamer/src/nonblocking/quic.rs` / `tpu-client-next/tests/connection_workers_scheduler_test.rs`):
```rust
#[tokio::test(flavor = "multi_thread")]
async fn test_half_open_connection_churn_evades_per_ip_limit() {
    let SpawnTestServerResult { join_handle, stats, server_address, cancel, .. } =
        setup_quic_server(
            None,
            QuicStreamerConfig::default_for_tests(),
            SwQosConfig { max_connections_per_unstaked_peer: 8, ..Default::default() },
        );

    // Repeatedly open a connection from the same IP and drop it before the
    // handshake resolves (e.g. by closing the client endpoint immediately
    // after calling `connect`, without awaiting completion).
    for _ in 0..1000 {
        let client_socket = bind_to_localhost_unique().unwrap();
        let endpoint = quinn::Endpoint::new(EndpointConfig::default(), None, client_socket, Arc::new(TokioRuntime)).unwrap();
        let connecting = endpoint.connect(server_address, "localhost").unwrap();
        drop(connecting); // abandon before handshake completes
    }

    // Expected (vulnerable) result: connection_rate_limited_per_ipaddr stays
    // at 0 or very low, while outstanding_incoming_connection_attempts and/or
    // refused_connections_too_many_open_connections grow, showing the per-IP
    // limiter was evaded while global slot capacity was consumed.
    assert_eq!(stats.connection_rate_limited_per_ipaddr.load(Ordering::Relaxed), 0);
    assert!(stats.refused_connections_too_many_open_connections.load(Ordering::Relaxed) > 0
        || stats.outstanding_incoming_connection_attempts.load(Ordering::Relaxed) > 0);

    cancel.cancel();
    join_handle.await.unwrap();
}
```
This demonstrates that the per-IP `ConnectionRateLimiter` (`connection_rate_limited_per_ipaddr`) is never incremented despite heavy repeated connection churn from one IP, while global resource-consumption counters grow, confirming the evasion of per-IP accounting via handshake abandonment.

    fn new(stats: Arc<StreamerStats>, max_concurrent_connections: usize) -> Result<Self, ()> {

                "There are too many concurrent connections opened already: open: \

    /// Check if the connection from the said `ip` is allowed.
    /// Here we assume that only IPs with actual confirmed connections are stored in it,
    /// since we should only modify server state once source IP is verified
    pub fn is_allowed(&self, ip: &IpAddr) -> bool {
        // Check if we have records in the rate limiter for the given IP address
        match self.limiter.current_tokens(ip) {
            Some(r) => r > 0, // we have a record, and rate is not exceeded
            None => true,     // if we have not seen IP, allow connection request
        }
