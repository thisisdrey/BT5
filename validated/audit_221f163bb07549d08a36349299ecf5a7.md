### Title
Credential Disclosure via Unsanitized `FetchRemote` Error Message - ([File: internal/gitaly/service/repository/fetch_remote.go])

### Summary
`FetchRemote` builds the `remote.inmemory.url` git config directly from the caller-supplied `RemoteParams.Url`, including any embedded `user:pass` userinfo, and forwards raw `git-fetch` stderr into the gRPC error returned to the client without ever calling `helper.SanitizeString`/`SanitizeError`. When the fetch fails, git's own fatal error commonly echoes the configured remote URL verbatim (including credentials) into stderr, and that stderr is embedded unmodified in the `structerr.NewInternal` response.

### Finding Description
`buildCommandOpts` takes `req.GetRemoteParams().GetUrl()` unmodified and sets it as `remote.inmemory.url` via `gitcmd.WithConfigEnv` (`GIT_CONFIG_VALUE_N`), with no stripping of userinfo: [1](#0-0) 

This is unlike `CreateRepositoryFromURL`'s `cloneFromURLCommand`, which explicitly parses the URL, extracts `u.User`, converts it into an `Authorization: Basic` header, and sets `u.User = nil` before the URL is ever passed to git: [2](#0-1) 

`FetchRemote`/`fetchRemoteAtomic` has no equivalent stripping — the raw, credentialed URL is what git actually sees. When `quarantineRepo.FetchRemote` fails, the raw stderr captured from the git subprocess is placed directly into the returned error with no sanitization: [3](#0-2) 

`helper.SanitizeString`/`SanitizeError` exist specifically to strip credentials from URL-bearing strings, but a repository-wide search confirms they are defined only in `internal/helper/security.go` and referenced only from their own test file — they are never called from any RPC handler, including `fetch_remote.go`, `update_remote_mirror.go`, or `find_remote_root_ref.go`. [4](#0-3) 

`UpdateRemoteMirror` has the analogous pattern: it also sets `remote.<name>.url` from the raw `remote.GetUrl()` without stripping userinfo. [5](#0-4) 

Since git's `fatal: unable to access '<url>'`/`Could not resolve host`/authentication-failure messages typically include the exact configured remote URL, a credentialed pull-mirror URL that fails to fetch (bad ref, unreachable host, or auth failure) will have its full `https://user:secret@host/...` form appear in Gitaly's returned stderr, and thence in the gRPC error surfaced up through GitLab Rails.

### Impact Explanation
The RPC error can echo the literal userinfo-embedded remote URL back to whichever caller/UI surface displays the RPC error (e.g. mirror "last error" messages, import failure banners), which is broader-audience than the confidentiality boundary intended for the mirror credential (e.g. shared/service credentials configured by one maintainer but whose failure text may be visible to other project members or logged in less-trusted sinks). This matches GitLab's credential/secrets-disclosure impact class rather than the caller's own knowledge of a credential they typed, because the failure path (`fetchRemoteAtomic`/error propagation) is the exact code responsible for guarding secret material in errors, and it fails to do so despite Gitaly having a dedicated (but unused) sanitizer for this purpose.

### Likelihood Explanation
Any user who can configure a pull mirror or trigger a `FetchRemote`/`UpdateRemoteMirror` operation with a credentialed URL (a standard, supported GitLab mirroring feature) and can force a fetch failure (wrong ref, unreachable/typo host, expired token) will reliably reproduce the leak — no special privilege, race condition, or non-default configuration is required.

### Recommendation
Strip URL userinfo before using it as `remote.inmemory.url`/`remote.<name>.url` (mirroring what `cloneFromURLCommand` already does, converting to an `Authorization` header) in `fetch_remote.go`'s `buildCommandOpts` and in `internal/gitaly/service/remote/update_remote_mirror.go`. Additionally, apply `helper.SanitizeError`/`SanitizeString` to any stderr/error text before it is embedded into `structerr.NewInternal`/`WithMetadata` responses across `fetch_remote.go`, `update_remote_mirror.go`, and `find_remote_root_ref.go`.

func buildCommandOpts(ctx context.Context, opts *localrepo.FetchOpts, req *gitalypb.FetchRemoteRequest) error {
	remoteURL := req.GetRemoteParams().GetUrl()
	var config []gitcmd.ConfigPair

	for _, refspec := range getRefspecs(req.GetRemoteParams().GetMirrorRefmaps()) {
		config = append(config, gitcmd.ConfigPair{
			Key: "remote.inmemory.fetch", Value: refspec,
		})
	}

	if resolvedAddress := req.GetRemoteParams().GetResolvedAddress(); resolvedAddress != "" {
		modifiedURL, resolveConfig, err := gitcmd.GetURLAndResolveConfig(remoteURL, resolvedAddress)
		if err != nil {
			return fmt.Errorf("couldn't get curloptResolve config: %w", err)
		}

		remoteURL = modifiedURL
		config = append(config, resolveConfig...)
	}

	config = append(config, gitcmd.ConfigPair{Key: "remote.inmemory.url", Value: remoteURL})

// SanitizeString will clean password and tokens from URLs, and replace them
// with [FILTERED].
func SanitizeString(str string) string {
	return hostPattern.ReplaceAllString(str, "$1[FILTERED]@$3$4")
}

// SanitizeError does the same thing as SanitizeString but for error types
func SanitizeError(err error) error {
	return errors.New(SanitizeString(err.Error()))
}
