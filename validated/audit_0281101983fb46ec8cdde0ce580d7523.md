### Title
`PostUploadPackWithSidechannel` performs no negotiation timeout/boundary-packet enforcement, unlike the equivalent SSH path - ([File: internal/gitaly/service/smarthttp/upload_pack.go])

### Summary
The SSH upload-pack path (`internal/gitaly/service/ssh/upload_pack.go` → `runUploadCommand`) wraps the client's negotiation stdin in a `pktline.NewReadMonitor` that is bound to a configurable `Timeout.UploadPackNegotiation` (10m default) and cancels the RPC if the `done`/flush boundary packet is not observed in time. `PostUploadPackWithSidechannel`'s `runUploadPack` in `internal/gitaly/service/smarthttp/upload_pack.go` has no equivalent mechanism — it feeds the raw sidechannel stream directly into `git upload-pack --stateless-rpc` stdin with no timeout ticker or read monitor.

### Finding Description
In `runUploadPack` [1](#0-0) , the client-controlled sidechannel reader is passed straight to `gitcmd.WithStdin(stdin)` for the spawned `git upload-pack --stateless-rpc` process, with only a `TeeReader`/`statsCollector` attached for logging metrics — no timeout or monitor is installed on the negotiation phase.

By contrast, the SSH implementation explicitly documents and implements a negotiation timeout to bound how long a client can keep sending pktlines without terminating negotiation: [2](#0-1) , gated by `cfg.Timeout.UploadPackNegotiation` (default 10 minutes) [3](#0-2)  and wired through `uploadPackRequestTimeoutTickerFactory` in `internal/gitaly/service/ssh/server.go` [4](#0-3) .

Separately, the actual pktline parsing that Gitaly does perform (for stats/metrics, in `stats.PackfileNegotiation.Parse`) is memory-bounded: each pktline is capped at `pktline.MaxPktSize` (65520 bytes) via the scanner buffer [5](#0-4) , and the parser only increments integer counters (`Wants`, `Haves`, `PayloadSize`, `Packets`) per packet rather than accumulating unbounded slices [6](#0-5) , so this part is not a memory-unbounded structure. The actual CPU/algorithmic cost of a flood of "have" lines is delegated to the `git upload-pack` binary itself (an upstream Git behavior, not Gitaly code), which is out of scope per the audit rules ("bug in git itself rather than Gitaly").

The concrete Gitaly-specific gap is the missing negotiation-phase timeout enforcement on the smarthttp/sidechannel path: absent an active client "done"/flush, the negotiation can be held open indefinitely, tying up the `git upload-pack` child process, the sidechannel connection, and the RPC handler goroutine for as long as the surrounding gRPC/HTTP context permits.

### Impact Explanation
An unprivileged user who can fetch/clone a repository they can access can open `PostUploadPackWithSidechannel` and stream negotiation packets (or simply stall) without completing negotiation. Unlike the SSH path, there is no Gitaly-side timeout to bound this, so the spawned `git upload-pack` process, its stdin pipe goroutine, and the sidechannel connection can be held open far longer than intended, tying up a process slot and file descriptors per concurrent request. This matches the DoS/resource-exhaustion bounty class, though the impact is bounded by whatever HTTP/gRPC-level timeouts are enforced upstream by Workhorse/GitLab Rails (outside Gitaly), somewhat limiting severity relative to a fully unbounded memory-growth bug.

### Likelihood Explanation
Any authenticated user capable of triggering a smarthttp fetch/clone (owns or has read access to a repository) can drive this path with attacker-controlled pktline data and timing, requiring no special role, secret, or non-default configuration. Repeatability is straightforward: open multiple concurrent `PostUploadPackWithSidechannel` calls and withhold the negotiation-terminating packet.

### Recommendation
Wire the same negotiation timeout mechanism used in SSH (`pktline.NewReadMonitor` plus `Timeout.UploadPackNegotiation`) into `runUploadPack` in `internal/gitaly/service/smarthttp/upload_pack.go`, so that if the client does not send a `done`/flush boundary packet within the configured window, the RPC is canceled the same way it is for SSH.

// runUploadCommand runs an uploading command like git-upload-pack(1) or git-upload-archive(1). It serves multiple
// purposes:
//
//   - It sets up a large buffer reader such that we can write the data more efficiently.
//
//   - It logs how many bytes have been sent.
//
//   - It installs a timeout such that we can address time-of-check-to-time-of-use-style races. Otherwise it would be
//     possible to open the connection early, keep it open for an extended amount of time, and only do the negotiation of
//     what is to be sent at a later point when permissions of the user might have changed.
func (s *server) runUploadCommand(
	rpcContext context.Context,
	repo gitcmd.RepositoryExecutor,
	stdin io.Reader,
	stdout, stderr io.Writer,
	timeoutTicker helper.Ticker,
	boundaryPacket []byte,
	sc gitcmd.Command,
	opts ...gitcmd.CmdOpt,
) error {
	ctx, cancelCtx := context.WithCancel(rpcContext)
	defer cancelCtx()

	var stderrBuilder strings.Builder
	stderr = io.MultiWriter(stderr, &stderrBuilder)

	stdoutCounter := &helper.CountingWriter{W: stdout}
	// Use large copy buffer to reduce the number of system calls
	stdout = &largeBufferReaderFrom{Writer: stdoutCounter}

	stdinPipe, monitor, cleanup, err := pktline.NewReadMonitor(ctx, stdin, s.logger)
	if err != nil {
		return fmt.Errorf("create monitor: %w", err)
	}

	cmd, err := repo.Exec(ctx, sc, append([]gitcmd.CmdOpt{
		gitcmd.WithStdin(stdinPipe),
		gitcmd.WithStdout(stdout),
		gitcmd.WithStderr(stderr),
		gitcmd.WithFinalizer(func(context.Context, *command.Command) { cleanup() }),
	}, opts...)...)
	stdinPipe.Close() // this now belongs to cmd
	if err != nil {
		cleanup()
		return fmt.Errorf("starting command: %w", err)
	}

	go monitor.Monitor(ctx, boundaryPacket, timeoutTicker, cancelCtx)

func (n *PackfileNegotiation) Parse(body io.Reader, opts ...ParsePackfileNegotiationOption) error {
	defer func() { _, _ = io.Copy(io.Discard, body) }()
	config := parsePackfileNegotiationConfig{}
	for _, opt := range opts {
		opt(&config)
	}

	scanner := pktline.NewScanner(body)

	for ; scanner.Scan(); n.Packets++ {
		pkt := scanner.Bytes()
		data := text.ChompBytes(pktline.Data(pkt))
		split := strings.Split(data, " ")
		n.PayloadSize += int64(len(data))

		done := false

		lineFirstPart := split[0]

		// commands are in the form `command=<name>` so it does not fit well
		// into the switch case below. So we handle them here.
		// The commands we look for are the ones described here:
		// https://git-scm.com/docs/protocol-v2#_command_request
		// We are also interested in the `bundle-uri` commandm, which is
		// explained here:
		// https://git-scm.com/docs/bundle-uri#_implementation_plan
		if command, ok := strings.CutPrefix(lineFirstPart, "command="); ok {
			n.Command = command
			continue
		} else if agent, ok := strings.CutPrefix(lineFirstPart, "agent="); ok {
			n.UserAgent = agent
			continue
		}

		switch lineFirstPart {
		case "ref-prefix":
			if config.parseLsRefsPipelineRefPrefixes && len(split) == 2 && n.Command == "ls-refs" && pipelineRefPrefixRegex.MatchString(split[1]) {
				n.PipelineRefPrefixes++
			}
		case "want":
			if len(split) < 2 {
				return fmt.Errorf("invalid 'want' for packet %d: %v", n.Packets, data)
			}
			if len(split) > 2 && n.Caps != nil {
				return fmt.Errorf("capabilities announced multiple times in packet %d: %v", n.Packets, data)
			}

			n.Wants++
			if len(split) > 2 {
				n.Caps = split[2:]
				for _, cap := range n.Caps {
					if agent, ok := strings.CutPrefix(cap, "agent="); ok {
						n.UserAgent = agent
						break
					}
				}
			}
		case "shallow":
			if len(split) != 2 {
				return fmt.Errorf("invalid 'shallow' for packet %d: %v", n.Packets, data)
			}
			n.Shallows++
		case "deepen", "deepen-since", "deepen-not":
			if len(split) != 2 {
				return fmt.Errorf("invalid 'deepen' for packet %d: %v", n.Packets, data)
			}
			n.Deepen = data
		case "filter":
			if len(split) != 2 {
				return fmt.Errorf("invalid 'filter' for packet %d: %v", n.Packets, data)
			}
			n.Filter = split[1]
		case "have":
			if len(split) != 2 {
				return fmt.Errorf("invalid 'have' for packet %d: %v", n.Packets, data)
			}
			n.Haves++
		case "done":
			done = true
		}

		if done {
			break
		}
	}

func testUploadPackWithSidechannelTimeout(t *testing.T, ctx context.Context, opts ...testcfg.Option) {
	t.Parallel()

	cfg := testcfg.Build(t, opts...)

	cfg.SocketPath = runSSHServerWithOptions(t, cfg, []ServerOpt{
		WithUploadPackRequestTimeoutTickerFactory(func() helper.Ticker {
			// Create a ticker that will immediately tick when getting reset so that the
			// server-side can observe this as an emulated timeout.
			ticker := helper.NewManualTicker()
			ticker.ResetFunc = func() {
				ticker.Tick()
			}
			return ticker
		}),
	})

	repo, repoPath := gittest.CreateRepository(t, testhelper.Context(t), cfg)
	gittest.WriteCommit(t, cfg, repoPath, gittest.WithBranch("main"))

	ctx, cancel := context.WithCancel(ctx)
	defer cancel()

	registry := sidechannel.NewRegistry()
	client := newSSHClientWithSidechannel(t, ctx, registry, cfg.SocketPath)

	ctx, waiter := sidechannel.RegisterSidechannel(ctx, registry, func(clientConn *sidechannel.ClientConn) (returnedErr error) {
		// Discard all data and block on the connection closing. The client says nothing
		// back to the server and doesn't finish the negotiation. This leads to the server
		// closing the connections once the negotiation timeout fires.
		_, err := io.Copy(io.Discard, clientConn)
		assert.NoError(t, err)
		return nil
	})
	defer testhelper.MustClose(t, waiter)

	_, err := client.SSHUploadPackWithSidechannel(ctx, &gitalypb.SSHUploadPackWithSidechannelRequest{
		Repository: repo,
	})

	// Because the client says nothing, the server would block. Because of
	// the timeout, it won't block forever, and return with a non-zero exit
	// code instead.
	testhelper.RequireGrpcError(t, structerr.NewDeadlineExceeded("running upload-pack: waiting for negotiation: context canceled"), err)
