### Title
Unauthenticated `RecvError` packets let a spoofing attacker force victim tunnel teardown and costly re-handshake - (File: outside.go)

### Summary
Nebula's `RecvError` control message is processed in the cleartext, pre-decryption fast path of `readOutsidePackets`, and the only anti-spoofing check in `handleRecvError` is a comparison of the UDP source address against the hostinfo's last-known remote endpoint — not a cryptographic MAC, signature, or session-bound token. An attacker who can spoof (or otherwise present) that source `netip.AddrPort` can force a legitimate hostinfo to be torn down and its pending-handshake state deleted, at negligible cost to the attacker, while the victim (and honest peer) must redo the full authenticated Noise handshake.

### Finding Description
Inbound `RecvError` packets are dispatched before any certificate/key material is required: [1](#0-0) 

`handleRecvError` looks up the hostinfo by `h.RemoteIndex` and only guards against spoofing by comparing the packet's source address to the currently known remote address of that hostinfo: [2](#0-1) 

```go
hr := hostinfo.GetRemote()
if hr.IsValid() && hr != addr {
    f.l.Info("Someone spoofing recv_errors?", ...)
    return
}
f.closeTunnel(hostinfo)
f.handshakeManager.DeleteHostInfo(hostinfo)
```

Two properties combine to make this exploitable without holding a CA-signed certificate:
1. The 16-byte Nebula header — including `RemoteIndex` (`Version`, `Type`, `Subtype`, `RemoteIndex`, `MessageCounter`) — is never encrypted; it is parsed straight off the wire for every packet type, including ordinary `Message` traffic [3](#0-2) . Any network-level observer (on-path or off-path with knowledge of the UDP conversation) can read a victim's active `RemoteIndex` values from legitimate traffic without ever completing a handshake.
2. The only authentication of a `RecvError` sender is a check on the observed UDP source `AddrPort`, which is attacker-controllable via IP/UDP source spoofing — there is no cryptographic binding to the peer's certificate or session keys, unlike ordinary data-plane and `CloseTunnel` messages which are only actioned after `ConnectionState.Decrypt` succeeds (see the AEAD-protected `CloseTunnel` path a few lines above `case header.CloseTunnel:` in the same switch) [4](#0-3) .

This is the direct code-level analog of the reported "cheap path forces victim into an expensive corrective action" pattern: just as a borrower can call `forceRepay` to shift redemption cost onto the lender, here an attacker who never had to complete a Noise handshake (no cert, no cost) can send one tiny unauthenticated `RecvError` UDP datagram to unilaterally destroy an established, authenticated tunnel on both the recipient and (via handshake manager cleanup) impose the burden of a brand-new full handshake on the legitimate peer, who bears all the cryptographic/authentication cost of recovery.

### Impact Explanation
Successful exploitation causes remote state poisoning / denial of service: an established, mutually-authenticated tunnel is unilaterally torn down (`f.closeTunnel(hostinfo)`) and the handshake bookkeeping is cleared (`f.handshakeManager.DeleteHostInfo(hostinfo)`), forcing the legitimate host to re-run the full certificate-validated Noise IX handshake to restore connectivity. Repeated forged `RecvError` packets let an attacker persistently disrupt a target's tunnels at essentially zero cost to themselves, without ever presenting a CA-signed certificate.

### Likelihood Explanation
The attacker needs only: (a) visibility of a victim's `RemoteIndex` (trivially obtainable by observing any single cleartext-header packet exchanged with that peer, since the header is never encrypted), and (b) the ability to send a UDP packet whose source `AddrPort` matches the peer's expected remote (achievable via source-address spoofing, a well-known UDP weakness, or from a position that can already reach that path). No certificate, handshake completion, or decryption capability is required, making this reachable by exactly the class of unauthenticated attacker the scope specifies.

### Recommendation
Do not authorize `closeTunnel`/`DeleteHostInfo` based solely on the untrusted UDP source address matching a cached remote. Either bind `RecvError` acceptance to a value only the legitimate peer could produce (e.g., an authenticated/MACed control message using the session's established AEAD keys, similar to how `CloseTunnel` is only honored post-decryption elsewhere in the switch), or require a nonce/challenge-response tied to the current session before acting on it. At minimum, rate-limit and corroborate `RecvError` with additional cryptographic proof of peer identity before tearing down state, closing the asymmetry where an unauthenticated actor can impose full re-handshake cost on an authenticated victim for free.

### Proof of Concept
1. Attacker passively observes (or otherwise learns) one UDP packet between victim `A` and peer `B`; from its unencrypted header extracts `RemoteIndex` as seen by `A` for the tunnel to `B` (header parsing occurs before any decryption, per `readOutsidePackets`).
2. Attacker crafts a 16-byte `header.RecvError` packet with that `RemoteIndex`, encoded via `header.Encode` (matching what `sendRecvError` produces) — no cert, no Noise state, no encryption needed.
3. Attacker spoofs the UDP source address to match `B`'s address as currently known to `A` (`hostinfo.GetRemote()`), and sends the forged packet to `A`.
4. `A`'s `handleRecvError` finds the matching hostinfo, sees `hr == addr`, and calls `f.closeTunnel(hostinfo)` plus `f.handshakeManager.DeleteHostInfo(hostinfo)`, destroying the authenticated tunnel and forcing `A` to redo the full handshake with `B` to reconnect — at attacker cost of a single spoofed unauthenticated datagram.

```go
func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
```
