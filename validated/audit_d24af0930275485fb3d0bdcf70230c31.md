### Title
StackerDB push-chunk inventory reply reports a chunk version as accepted before it is actually persisted, serving unconfirmed state as canonical - (File: stackslib/src/net/stackerdb/mod.rs)

### Summary
`PeerNetwork::handle_unsolicited_StackerDBPushChunk` patches the in-memory `StackerDBChunkInvData.slot_versions` entry to the *pushed* chunk's version and immediately signs and sends this inventory back to the sender as an acknowledgment — before the chunk has actually been validated end-to-end and written to the StackerDB via `try_replace_chunk`. Actual storage is deferred to the relayer (`(false, true)` return value forwards the message for later processing in `relay.rs`).

### Finding Description
`make_StackerDBChunksInv_or_Nack` builds an inventory reply from the *currently persisted* slot versions read from disk via `self.stackerdbs.get_slot_versions(contract_id)`. [1](#0-0) 

In `handle_unsolicited_StackerDBPushChunk`, once `validate_received_chunk` (a stateless, in-memory check of signature/size/version bounds) passes, the code directly overwrites the freshly-computed inventory entry with the *pushed, not-yet-stored* version and treats the chunk as accepted for the purposes of the ack: [2](#0-1) 

The actual commit to the on-disk StackerDB (`StackerDBTx::try_replace_chunk`, which enforces the authoritative `slot_version <= slot_validation.version` stale check and persists the row) happens later, out of band, when the message is forwarded to the relayer (`return Ok((false, true))` at line 870, `stackslib/src/net/relay.rs` processes the actual storage). No code path in `handle_unsolicited_StackerDBPushChunk` ties the ack’s reported version to the success of that later write.

This breaks the same class of equality violated in the referenced report: a tracked "high-water"/accepted value is advanced speculatively/optimistically rather than being derived from (and gated on) the actually-committed state. Here, the analogous equality is "advertised inventory version" vs. "version actually persisted in the StackerDB".

If, for any reason, the deferred storage step in the relayer does not go through for that chunk (duplicate/overtaken write, contention, chunk dropped for unrelated relay-layer reasons, process restart between ack and processing, etc.), the node has already told the remote peer that it holds the newer version. Any peer that reads this ack as ground truth (and any future `StackerDBGetChunksInv` reply this node's own peer state may echo before disk state is confirmed) is being served state that has not actually been committed.

### Impact Explanation
This falls into the "serving non-canonical state as canonical" / "false inventory" bucket. A node's replicas rely on `StackerDBChunkInvData` to decide what to fetch and what to consider already-replicated. If this node claims (via the immediate ack) to have version `N` while it never actually stores it, other honest replicas can skip pushing/re-requesting that chunk to/from this node, resulting in the chunk silently failing to propagate through this replica while the network believes it has been replicated — a bounded-but-real correctness/availability issue in the gossip layer, consistent with the "High" tier (steering peers based on false inventory).

### Likelihood Explanation
The optimistic patch happens on every unsolicited push-chunk that passes the stateless `validate_received_chunk` check, i.e., on the common/expected path, not an edge case. Reaching the discrepancy requires the deferred relay-layer storage step to not succeed for the chunk in question (e.g., a race with another slot write, node restart, or relay-layer processing being skipped/dropped) — a remote, unprivileged peer can trigger the send but cannot directly force the storage failure, so likelihood is moderate rather than trivially high.

### Recommendation
Do not populate/send the ack's `slot_versions` entry with the pushed chunk's version until the chunk has actually been durably stored (i.e., only report the version once `try_replace_chunk` succeeds, or defer sending the ack until storage completes, re-reading `get_slot_versions` afterward).

### Proof of Concept
1. An unprivileged peer opens a p2p connection and sends an unsolicited `StackerDBPushChunk` for a valid, existing StackerDB slot with a strictly newer, correctly-signed version.
2. `handle_unsolicited_StackerDBPushChunk` calls `validate_received_chunk`, which only checks signature/size/monotonic-version-vs-last-known-inventory — no disk write occurs here. [3](#0-2) 
3. The code immediately sets `*slot_version = chunk_data.chunk_data.slot_version;` in the reply payload and (if `send_reply`) signs and sends this inventory back to the sender as confirmation, while the actual persistence is deferred to the relayer via the `(false, true)` return. [4](#0-3) 
4. If the deferred relay-layer write for that chunk does not complete (e.g., a competing writer wins the same slot in `try_replace_chunk`'s `slot_version <= slot_validation.version` stale check), the node has already advertised a version it never actually stored, and subsequent honest peers relying on the ack will treat this replica's inventory as canonical though it does not match on-disk state.

    pub fn validate_received_chunk(
        &self,
        smart_contract_id: &QualifiedContractIdentifier,
        config: &StackerDBConfig,
        data: &StackerDBChunkData,
        expected_versions: &[u32],
    ) -> Result<bool, net_error> {
        // validate -- must not exceed this replica's configured chunk size.
        if (data.data.len() as u64) > config.chunk_size {
            info!(
                "Received StackerDBChunk for {} ID {}, which is oversized: {} bytes (max {} bytes)",
                smart_contract_id,
                data.slot_id,
                data.data.len(),
                config.chunk_size
            );
            return Ok(false);
        }

        // validate -- must be a valid chunk
        let Some(expected_version) = expected_versions.get(data.slot_id as usize) else {
            info!(
                "Received StackerDBChunk for {} ID {}, which is too big ({})",
                smart_contract_id,
                data.slot_id,
                expected_versions.len()
            );
            return Ok(false);
        };

        // validate -- must be signed by the expected author
        let addr = match self
            .stackerdbs
            .get_slot_signer(smart_contract_id, data.slot_id)?
        {
            Some(addr) => addr,
            None => {
                return Ok(false);
            }
        };

        let slot_metadata = data.get_slot_metadata();
        if !slot_metadata.verify(&addr)? {
            info!(
                "StackerDBChunk for {} ID {} is not signed by {}",
                smart_contract_id, data.slot_id, &addr
            );
            return Ok(false);
        }

        // validate -- must be the current or newer version
        if data.slot_version < *expected_version {
            info!(
                "Received StackerDBChunk for {} ID {} version {}, which is stale (expected {})",
                smart_contract_id, data.slot_id, data.slot_version, *expected_version
            );
            return Ok(false);
        }

        // validate -- must not exceed max writes
        if data.slot_version > config.max_writes {
            info!(
                "Write count exceeded for StackerDBChunk for {} ID {} version {} (max is {})",
                smart_contract_id, data.slot_id, data.slot_version, config.max_writes
            );
            return Ok(false);
        }

        Ok(true)
    }
