### Title
Improper array index validation in `extractBytes32Array` allows out-of-bounds crash via `batchvalidatesign`/`validatemultisign` TVM precompiles - (File: `actuator/src/main/java/org/tron/core/vm/PrecompiledContracts.java`)

### Summary
`BatchValidateSign.doExecute` and `ValidateMultiSign.execute` decode ABI-encoded calldata into a `DataWord[]` and pass an attacker-controlled offset/length into `extractBytes32Array`, which performs no bounds checking on the array index it computes, unlike its sibling helpers `extractBytesArray`/`extractSigArray`.

### Finding Description
`extractBytes32Array` reads a length word directly from attacker-controlled calldata and then indexes into the `words` array using that length without ever checking it against `words.length`: [1](#0-0) 

Contrast this with `extractBytesArray` and `extractSigArray`, which explicitly guard the starting `offset`: [2](#0-1) 

`extractBytes32Array` is reachable from the `BatchValidateSign` precompile, where `words[2].intValueSafe() / WORD_SIZE` (an offset derived from raw calldata) and the length word at that offset (also raw calldata) are passed straight through with no upper bound check before the accompanying "sigArraySize"/"addrArraySize" `MAX_SIZE` check only applies when `allowTvmSelfdestructRestriction()` is active: [3](#0-2) 

This precompile is invoked via a `CALL`/`STATICCALL` from any TVM contract (deployed by any unprivileged account), i.e. reachable from a single signed `TriggerSmartContract` transaction with attacker-supplied calldata. The energy calculation `getEnergyForData` only checks `data.length`, not the internal offset/length fields, so energy metering does not prevent a crafted, small-length input from encoding a huge offset/length that indexes far outside `words.length`, producing an `ArrayNegativeArraySizeException` or `ArrayIndexOutOfBoundsException` at `words[offset].intValueSafe()` or `words[offset + i + 1]`.

Whether this manifests as a full node crash depends on exception handling: `BatchValidateSign.execute` wraps `doExecute` in a `try/catch (Throwable t)` that catches all exceptions and returns `DATA_FALSE`, which appears to neutralize the crash for `BatchValidateSign` specifically: [4](#0-3) 

However, `ValidateMultiSign.execute`, which also calls the unchecked `extractBytesArray`/`extractSigArray` (bounds-checked) but computes `words[3].intValueSafe() / WORD_SIZE` directly as an index into `words` before any bounds check, at line 1067, is not wrapped in the same outer try/catch for that specific line: [5](#0-4) 

An `ArrayIndexOutOfBoundsException` thrown at `words[words[3].intValueSafe() / WORD_SIZE]` (before entering the `try` block at line 1082) would propagate up as an unhandled `RuntimeException` out of the precompile.

### Impact Explanation
If an uncaught `RuntimeException`/`ArrayIndexOutOfBoundsException` propagates out of a precompiled contract during transaction execution in `Program`/VM interpreter, node behavior depends on how the VM's exception wrapper classifies it — TVM is generally designed to convert unexpected runtime exceptions into reverts (see the existing `EnergyWhenAssertStyleTest` tests which show `IllegalOperationException` being generated for `ArrayIndexOutOfBoundsException`-class errors), so this may only cause a revert rather than a node crash. I could not fully verify with certainty (given available context) whether the VM's outer exception handling in `Program`/`VMActuator` catches raw `ArrayIndexOutOfBoundsException` thrown directly from `PrecompiledContracts` execution paths outside the `Program.Exception` wrapper hierarchy, versus letting it propagate to `Manager`/block application and potentially halting block processing for all nodes that execute the same transaction (a determinism/consensus-halt risk) if unhandled consistently across all nodes.

### Likelihood Explanation
Moderate. Reaching `ValidateMultiSign`'s precompile at address requires an unprivileged contract deployer to call it via `STATICCALL`/`CALL` from Solidity/TVM bytecode (no special privilege needed) with crafted calldata. Constructing calldata where `words[3]`'s value, once divided by `WORD_SIZE`, yields an index `>= words.length` is straightforward and directly attacker-controlled.

### Recommendation
Add explicit bounds checks in `extractBytes32Array` (mirroring `extractBytesArray`/`extractSigArray`'s `offset > words.length - 1` guard) and validate the offset computed from `words[3].intValueSafe() / WORD_SIZE` in `ValidateMultiSign.execute` before using it to index `words`, before any array indexing occurs, and confirm/harden that the VM's precompile call path converts arbitrary `RuntimeException` types (not just `Program.Exception` subclasses) into reverts uniformly across the codebase rather than allowing propagation into `Manager`/block application.

### Proof of Concept
Craft ABI calldata for `validatemultisign(address,uint256,bytes32,bytes[])` such that the `bytes[]` array head (word at index 3, i.e. offset 96) encodes an offset value whose `value/32` exceeds the total number of 32-byte words present in the actual calldata (e.g., set the offset field to a very large value like `0x00...7fffffff` while the actual calldata buffer is short). This drives `words[words[3].intValueSafe() / WORD_SIZE]` at line 1067 in `PrecompiledContracts.java` to throw `ArrayIndexOutOfBoundsException`, outside of the method's `try` block, and observe whether the transaction reverts cleanly or an unhandled exception propagates further up the execution stack (requires runtime verification, which I could not perform, to conclusively determine the resulting node behavior).

  private static byte[][] extractBytesArray(DataWord[] words, int offset, byte[] data) {
    if (offset > words.length - 1) {
      return new byte[0][];
    }
    int len = words[offset].intValueSafe();
    byte[][] bytesArray = new byte[len][];
    for (int i = 0; i < len; i++) {
      int bytesOffset = words[offset + i + 1].intValueSafe() / WORD_SIZE;
      int bytesLen = words[offset + bytesOffset + 1].intValueSafe();
      bytesArray[i] = extractBytes(data, (bytesOffset + offset + 2) * WORD_SIZE,
          bytesLen);
    }
    return bytesArray;
  }

  private static byte[][] extractSigArray(DataWord[] words, int offset, byte[] data) {
    if (offset > words.length - 1) {
      return new byte[0][];
    }
    int len = words[offset].intValueSafe();
    byte[][] bytesArray = new byte[len][];
    for (int i = 0; i < len; i++) {
      int bytesOffset = words[offset + i + 1].intValueSafe() / WORD_SIZE;
      bytesArray[i] = extractBytes(data, (bytesOffset + offset + 2) * WORD_SIZE,
          SIG_LENGTH);
    }
    return bytesArray;
  }
