### Title
Vesting `distribute()` Permanently Blocked by Shareholder Opting Out of Direct Coin Transfers — (`aptos-move/framework/aptos-framework/sources/vesting.move`)

---

### Summary

The `distribute` function in `vesting.move` pushes APT to every shareholder in a single atomic transaction using `aptos_account::deposit_coins`. If any one shareholder's deposit reverts — because they have no `CoinStore<AptosCoin>` and have explicitly set `allow_arbitrary_coin_transfers = false` — the entire transaction reverts. All other shareholders are blocked from receiving their vested APT, and the vesting contract cannot be terminated, permanently freezing the staking balance.

---

### Finding Description

**Root cause — `create_vesting_contract` does not validate shareholders**

`create_vesting_contract` validates the `withdrawal_address` with `assert_account_is_registered_for_apt` but performs no equivalent check on the individual shareholders:

```move
assert_account_is_registered_for_apt(withdrawal_address);   // ✓ validated
assert!(shareholders.length() > 0, ...);
// shareholders themselves are never validated ✗
``` [1](#0-0) 

**Push-based distribution iterates all shareholders atomically**

`distribute` extracts coins from the staking pool and then loops over every shareholder, calling `aptos_account::deposit_coins` for each one:

```move
shareholders.for_each_ref(|shareholder| {
    ...
    let recipient_address = get_beneficiary(vesting_contract, shareholder);
    aptos_account::deposit_coins(recipient_address, share_of_coins);  // ← can abort
});
``` [2](#0-1) 

**`deposit_coins` aborts when the recipient has opted out**

`deposit_coins` checks whether the recipient has a `CoinStore<CoinType>`. If not, it checks `can_receive_direct_coin_transfers`. If the recipient has called `set_allow_direct_coin_transfers(false)`, the function aborts:

```move
if (!coin::is_account_registered<CoinType>(to)) {
    assert!(
        can_receive_direct_coin_transfers(to),
        error::permission_denied(EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS)
    );
    ...
};
``` [3](#0-2) 

`set_allow_direct_coin_transfers` is an unprivileged entry function callable by any account: [4](#0-3) 

**The developers already recognised this risk for beneficiaries but not for original shareholders**

The `set_beneficiary` function explicitly guards against this with the comment: *"This is a requirement so distribute() wouldn't fail and block all other accounts from receiving APT if one beneficiary is not registered."*

```move
assert_account_is_registered_for_apt(new_beneficiary);
``` [5](#0-4) 

No equivalent guard exists for the original shareholders supplied at contract creation.

**`terminate_vesting_contract` is also blocked**

`terminate_vesting_contract` calls `distribute` internally before terminating, so the admin cannot terminate the contract and recover funds via `admin_withdraw` while the distribution is blocked: [6](#0-5) 

---

### Impact Explanation

A single shareholder who (a) has no `CoinStore<AptosCoin>` (e.g., a resource account created without registering for APT, or an account created post-FA-migration that only has a primary fungible store) and (b) calls the unprivileged `set_allow_direct_coin_transfers(false)` can cause every call to `distribute` to revert. Because `distribute` is atomic and push-based, all other shareholders are denied their vested APT. Because `terminate_vesting_contract` internally calls `distribute`, the admin cannot terminate the contract and recover funds via `admin_withdraw`. The staking balance is effectively frozen.

The admin can mitigate by calling `set_beneficiary` to redirect the problematic shareholder's share to a valid address, but this requires the admin to identify the problem and act. If the admin is unresponsive, or if the problematic shareholder is the admin, the funds are permanently locked.

---

### Likelihood Explanation

- Any shareholder can call `set_allow_direct_coin_transfers(false)` without any privilege.
- Resource accounts and accounts created without explicitly registering for `AptosCoin` (e.g., post-FA-migration accounts that only have a primary fungible store) will not have a `CoinStore<AptosCoin>`, satisfying the second condition.
- The vesting contract supports up to 30 shareholders (`MAXIMUM_SHAREHOLDERS = 30`), increasing the attack surface.
- The attack is cheap: one transaction to opt out, then any subsequent `distribute` call by anyone triggers the revert.

---

### Recommendation

1. **Validate shareholders at creation time** — add `assert_account_is_registered_for_apt(shareholder)` inside the `for_each_ref` loop in `create_vesting_contract`, mirroring the existing check on `withdrawal_address` and the guard in `set_beneficiary`.

2. **Switch to a pull-based distribution model** — instead of pushing to all shareholders atomically, record each shareholder's claimable balance and let them withdraw individually. This isolates failures to the individual claimant.

3. **Alternatively, skip failed deposits** — use a try-catch pattern (if available in the Move version) or pre-validate each recipient before extracting coins, so a single bad recipient does not block the rest.

---

### Proof of Concept

1. Admin creates a vesting contract with two shareholders: `@alice` (normal account) and `@resource_acct` (a resource account with no `CoinStore<AptosCoin>`).
2. `@resource_acct` calls `aptos_account::set_allow_direct_coin_transfers(false)`.
3. Time passes; vesting period elapses; `vest(contract_address)` is called successfully.
4. Anyone calls `distribute(contract_address)`.
5. The loop reaches `@resource_acct`; `deposit_coins` aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS`.
6. The entire transaction reverts; `@alice` receives nothing.
7. Admin calls `terminate_vesting_contract` — it internally calls `distribute`, which again reverts.
8. Admin cannot call `admin_withdraw` because the contract state is never set to `VESTING_POOL_TERMINATED`.
9. All APT in the staking pool is permanently inaccessible unless the admin calls `set_beneficiary` to redirect `@resource_acct`'s share.

    public entry fun set_allow_direct_coin_transfers(
        account: &signer, allow: bool
    ) acquires DirectTransferConfig {
        let addr = signer::address_of(account);
        if (exists<DirectTransferConfig>(addr)) {
            let direct_transfer_config = borrow_global_mut<DirectTransferConfig>(addr);
            // Short-circuit to avoid emitting an event if direct transfer config is not changing.
            if (direct_transfer_config.allow_arbitrary_coin_transfers == allow) { return };

            direct_transfer_config.allow_arbitrary_coin_transfers = allow;

            emit(
                DirectCoinTransferConfigUpdated {
                    account: addr,
                    new_allow_direct_transfers: allow
                }
            );
        } else {
            let direct_transfer_config = DirectTransferConfig {
                allow_arbitrary_coin_transfers: allow,
                update_coin_transfer_events: new_event_handle<
                    DirectCoinTransferConfigUpdatedEvent>(account)
            };
            emit(
                DirectCoinTransferConfigUpdated {
                    account: addr,
                    new_allow_direct_transfers: allow
                }
            );
            move_to(account, direct_transfer_config);
        };
    }
