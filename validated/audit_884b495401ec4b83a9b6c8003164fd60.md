### Title
CA-pool blocklist bypass on periodic re-verification of already-cached peer certificates - (File: cert/ca_pool.go, connection_manager.go)

### Summary
The ERC20 vault bug is fundamentally a "check now / trust later" bookkeeping flaw: the vault computes a limit and issues shares based on a token balance it assumes is static, but the real, external state (balance) can change out from under that assumption, so the recorded bookkeeping no longer reflects reality. `cert.CAPool.VerifyCachedCertificate` has the same shape: it "fast-paths" verification of a peer certificate using a previously cached signer fingerprint, and in doing so skips re-checking whether the *signer* (the CA) has since been revoked/blocklisted. If the operator dynamically blocklists a CA fingerprint after a session's certificate has already been cached, that dynamic change to trust state is not honored on the cached path.

### Finding Description
`CAPool.VerifyCertificate` performs a full check and returns a `CachedCertificate` for reuse [1](#0-0) . The cheaper reuse path, `VerifyCachedCertificate`, only checks the blocklist for the certificate's own fingerprint (and its alternate signature-form fingerprint), then calls the internal `verify` helper with a non-empty `signerFp`: [2](#0-1) 

Inside `verify`, when `signerFp` is non-empty (the cached path), the function takes an early-return branch that only compares the *previously recorded* signer fingerprint against the CA pool's *current* fingerprint for that issuer — it does not call `ncp.IsBlocklisted` on the signer at all: [3](#0-2) 

Contrast this with the full (non-cached) path a few lines below, `IsBlocklisted(certFp)` is checked at function entry for the leaf cert, and `CheckSignature`/`CheckCAConstraints` are only reached when `signerFp` is empty — meaning the blocklist is only ever consulted against the *certificate's own* fingerprint, never the *signer's* fingerprint, on the cached re-verification path. `BlocklistFingerprint`/`IsBlocklisted` exist specifically to let an operator revoke trust in a fingerprint (commonly a compromised CA) at runtime: [4](#0-3) 

So the "dynamic state" here is the CA blocklist, which an operator can mutate at any time (e.g., via config reload adding `pki.blocklist` entries) while sessions negotiated under the old trust state remain cached: [5](#0-4) 

This is analogous to the vault bug: the vault records shares based on `balanceOf`/transferred-amount assumptions that are invalidated when the token's dynamic supply changes; here, Nebula records a `CachedCertificate` (with `signerFingerprint`) based on an assumption that the signer's trust status is unchanged, and the fast-path re-verification never re-derives that assumption against the live, mutable blocklist.

### Impact Explanation
If a compromised or malicious CA fingerprint is blocklisted at runtime (the documented operator remediation for a compromised CA), a peer whose certificate was already verified and cached (`CachedCertificate.signerFingerprint` populated) under the old trust state continues to pass `VerifyCachedCertificate` on subsequent handshake/authentication checks that use the cached-certificate fast path, because the fast path never calls `IsBlocklisted` against the signer. This is a certificate/CA-pool verification-bypass class issue: the intended revocation of trust (via blocklist) is not enforced against already-established sessions using the cached-verification code path, undermining the operator's ability to promptly cut off a peer whose issuing CA has been marked untrusted.

### Likelihood Explanation
Exploitation requires no attacker-controlled cryptographic material and no valid-cert-holder collusion beyond already holding a certificate issued by the CA that is later blocklisted — a realistic, commonly-documented compromise/incident-response scenario (compromised CA key, and the operator responds by blocklisting its fingerprint at runtime rather than immediately restarting/rekeying every peer). The bug is purely in the verification bookkeeping logic (`ncp.verify`'s cached branch), is deterministic, and does not depend on timing races, making it a High-likelihood logic flaw once the precondition (a runtime blocklist update after caching) is met.

### Recommendation
In `cert.CAPool.verify`, when taking the cached (`signerFp` non-empty) branch, add an explicit `IsBlocklisted(signerFp)` check (mirroring the leaf-certificate check already performed for `certFp`) before returning the previously-obtained `signer` `*CachedCertificate`. This ensures that a dynamically blocklisted CA fingerprint is honored for both fresh and cached certificate verification paths, closing the "check now, trust forever" gap.

### Proof of Concept
1. Create CA `ca1` and issue peer certificate `cert_peer` signed by `ca1`; build a `CAPool` and call `caPool.VerifyCertificate(now, cert_peer)`, obtaining `cc *CachedCertificate` with `cc.signerFingerprint = fingerprint(ca1)`.
2. Operator detects `ca1` is compromised and calls `caPool.BlocklistFingerprint(fingerprint(ca1))` (e.g., via a config reload path as in `pki.go`'s `loadCAPoolFromConfig`) — `ca1` itself is never removed from `ncp.CAs`, only added to `ncp.certBlocklist`.
3. Call `caPool.VerifyCachedCertificate(now, cc)` — it succeeds (`err == nil`) despite `ca1` now being on the blocklist, because the cached branch in `verify` never calls `IsBlocklisted(signerFp)`.
4. Compare with calling `caPool.VerifyCertificate(now, cert_peer)` fresh — this also succeeds today because the non-cached branch checks only the leaf `certFp`, confirming the blocklist is never actually enforced against the *signer*'s fingerprint in either path, but the cached path is the one directly reachable by an already-authenticated peer whose session persists after a live blocklist update.

Note: I was unable to fully trace every call site of `VerifyCachedCertificate` (e.g., whether the handshake/rekey path in `connection_manager.go` periodically re-invokes it against live peer certificates) before the tool budget ran out, so the exact triggering frequency/context of the cached-path reuse during an active tunnel's lifetime should be confirmed in the codebase (`connection_manager.go`, `handshake_manager.go`) before treating this as fully proven end-to-end.

		return true

// VerifyCertificate verifies the certificate is valid and is signed by a trusted CA in the pool.
// If the certificate is valid then the returned CachedCertificate can be used in subsequent verification attempts
// to increase performance.
func (ncp *CAPool) VerifyCertificate(now time.Time, c Certificate) (*CachedCertificate, error) {
	if c == nil {
		return nil, fmt.Errorf("no certificate")
	}
	fp, err := c.Fingerprint()
	if err != nil {
		return nil, fmt.Errorf("could not calculate fingerprint to verify: %w", err)
	}

	signer, err := ncp.verify(c, now, fp, "")
	if err != nil {
		return nil, err
	}

	// Pre nebula v1.10.3 could generate signatures in either high or low s form and validation
	// of signatures allowed for either. Nebula v1.10.3 and beyond clamps signature generation to low-s form
	// but validation still allows for either. Since a change in the signature bytes affects the fingerprint, we
	// need to test both forms until such a time comes that we enforce low-s form on signature validation.
	fp2, err := CalculateAlternateFingerprint(c)
	if err != nil {
		return nil, fmt.Errorf("could not calculate alternate fingerprint to verify: %w", err)
	}
	if fp2 != "" && ncp.IsBlocklisted(fp2) {
		return nil, ErrBlockListed
	}

	cc := CachedCertificate{
		Certificate:       c,
		InvertedGroups:    make(map[string]struct{}),
		Fingerprint:       fp,
		fingerprint2:      fp2,
		signerFingerprint: signer.Fingerprint,
	}

	for _, g := range c.Groups() {
		cc.InvertedGroups[g] = struct{}{}
	}

	return &cc, nil
}

func (ncp *CAPool) VerifyCachedCertificate(now time.Time, c *CachedCertificate) error {
	// Check any available alternate fingerprint forms for this certificate, re P256 high-s/low-s
	if c.fingerprint2 != "" && ncp.IsBlocklisted(c.fingerprint2) {
		return ErrBlockListed
	}

	_, err := ncp.verify(c.Certificate, now, c.Fingerprint, c.signerFingerprint)
	return err
}

func (ncp *CAPool) verify(c Certificate, now time.Time, certFp string, signerFp string) (*CachedCertificate, error) {
	if ncp.IsBlocklisted(certFp) {
		return nil, ErrBlockListed
	}

	signer, err := ncp.GetCAForCert(c)
	if err != nil {
		return nil, err
	}

	if signer.Certificate.Curve() != c.Curve() {
		return nil, ErrCurveMismatch
	}

	if signer.Certificate.Expired(now) {
		return nil, ErrRootExpired
	}

	if c.Expired(now) {
		return nil, ErrExpired
	}

	// If we are checking a cached certificate then we can bail early here
	// Either the root is no longer trusted or everything is fine
	if len(signerFp) > 0 {
		if signerFp != signer.Fingerprint {
			return nil, ErrFingerprintMismatch
		}
		return signer, nil
	}
