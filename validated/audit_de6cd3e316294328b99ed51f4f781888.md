### Title
Unbounded body read in `process_event` allows single-request memory-exhaustion DoS on signer event port - (`libsigner/src/events.rs`)

### Summary
`process_event::<T, E>` calls `request.as_reader().read_to_string(&mut body)` with no size cap before any JSON parsing occurs, so a single `POST /stackerdb_chunks` (or `/proposal_response`, `/new_burn_block`, `/new_block`) request with a very large declared body forces the signer's event-receiver thread to allocate memory proportional to the entire streamed body before any validation is applied. Unlike the RPC/relay HTTP paths in this repo, which bound body size via `stacks_common::codec::MAX_MESSAGE_LEN` (see `libsigner/src/http.rs::decode_http_body`), the `tiny_http`-based event receiver in `libsigner/src/events.rs` applies no such cap.

### Finding Description
`SignerEventReceiver::next_event` (`libsigner/src/events.rs:413-459`) dispatches any `POST` to `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, or `/new_block` straight to `process_event::<T, E>` with no authentication, no secret check, and no size validation of any kind — only the URL path and HTTP method are inspected.

Inside `process_event` (`libsigner/src/events.rs:519-542`):
```rust
let mut body = String::new();
if let Err(e) = request.as_reader().read_to_string(&mut body) { ... }
```
`read_to_string` reads until EOF of the request body reader, which `tiny_http` sizes according to the client-supplied `Content-Length` (or chunked-encoding terminator). There is no equivalent of `MAX_MESSAGE_LEN`/`read_next_at_most` applied to bound the number of bytes read before `serde_json::from_slice` is even attempted at line 536. Contrast this with `libsigner/src/http.rs:196-217` (`decode_http_body`), which explicitly wraps chunked bodies in `HttpChunkedTransferReader::from_reader(ptr, MAX_MESSAGE_LEN.into())` to cap allocation — that cap simply isn't present on this code path.

Because the event port binds to a configured listener address (`SignerEventReceiver::bind`, `libsigner/src/events.rs:404-408`) and performs no authentication of the connecting peer, any TCP peer able to reach that address can open a connection, send a crafted `POST /stackerdb_chunks` request with a large `Content-Length`, and stream that many bytes; the process will buffer the entire body into `body: String` in memory before any size/validity check is performed.

### Impact Explanation
A single unauthenticated request can force the signer process's event-receiver thread to allocate memory proportional to the attacker-supplied body size (limited only by what the attacker is willing/able to stream), with no cap enforced anywhere on this ingestion path. This can exhaust process/host memory and crash or degrade the signer, which is a remote unauthenticated DoS reachable from a single request/connection — matching the Critical "remote crash/unauthenticated DoS from few messages" category. It is trivially repeatable across reconnections.

### Likelihood Explanation
Preconditions are minimal: the attacker only needs network reachability to the signer's bound event-receiver address/port (no secret, no peer key, no StackerDB slot ownership, no privileged role required, since `next_event` performs no authentication of the caller). Cost to the attacker is proportional to the bytes they choose to send (a few hundred MB is enough to be meaningful on a constrained host), and the attack is fully repeatable per TCP connection.

### Recommendation
Bound the event body read the same way other HTTP paths in this repo do: check `Content-Length` (and reject/close on chunked bodies without a declared bound) against a `MAX_MESSAGE_LEN`-style constant before reading, and/or use a bounded reader (`Read::take(MAX_MESSAGE_LEN)`) instead of `read_to_string` with no limit in `process_event`, rejecting requests whose declared or observed body size exceeds the cap before buffering further.

```rust
// libsigner/src/events.rs — illustrative Rust test plan
#[test]
fn test_process_event_unbounded_body() {
    let mut receiver: SignerEventReceiver<StacksMessage> = SignerEventReceiver::new(false);
    let addr = receiver.bind("127.0.0.1:0".parse().unwrap()).unwrap();

    let handle = std::thread::spawn(move || {
        // blocks in process_event on read_to_string with no cap
        let _ = receiver.next_event();
    });

    let mut stream = TcpStream::connect(addr).unwrap();
    let big_len: usize = 500 * 1024 * 1024; // 500MB, attacker-chosen
    let header = format!(
        "POST /stackerdb_chunks HTTP/1.1\r\nHost: {addr}\r\nContent-Length: {big_len}\r\nContent-Type: application/json\r\n\r\n"
    );
    stream.write_all(header.as_bytes()).unwrap();

    // Stream big_len bytes from a single connection.
    let chunk = vec![b'a'; 1024 * 1024];
    for _ in 0..(big_len / chunk.len()) {
        stream.write_all(&chunk).unwrap();
    }

    // Assert: server-side process memory (RSS) grows by ~big_len bytes
    // in `body: String` inside `process_event` before any size check or
    // JSON parse failure is returned — i.e., no MAX_MESSAGE_LEN-style
    // rejection occurs prior to full buffering, unlike
    // libsigner/src/http.rs::decode_http_body which caps at MAX_MESSAGE_LEN.
    handle.join().unwrap();
}
```

```rust
fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}
```

```rust
/// Decode an HTTP body, given the headers.
pub fn decode_http_body(headers: &HashMap<String, String>, mut buf: &[u8]) -> io::Result<Vec<u8>> {
    let chunked = if let Some(val) = headers.get("transfer-encoding") {
        val == "chunked"
    } else {
        false
    };

    let body = if chunked {
        // chunked encoding
        let ptr = &mut buf;
        let mut fd = HttpChunkedTransferReader::from_reader(ptr, MAX_MESSAGE_LEN.into());
        let mut decoded_body = vec![];
        fd.read_to_end(&mut decoded_body)?;
        decoded_body
    } else {
        // body is just as-is
        buf.to_vec()
    };

    Ok(body)
}
```
