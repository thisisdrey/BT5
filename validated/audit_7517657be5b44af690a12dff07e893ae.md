### Title
Protocol fee on NEP-245/IMT tokens bypassed via unit-delta chunking of `TokenDiff` intents - ([File: contracts/defuse/core/src/intents/token_diff.rs])

### Summary
`TokenDiff::token_fee` waives the fee on `Nep245`/`Imt` legs whenever the *per-intent* `unsigned_abs()` of the signed delta is `<= 1`, and this check is evaluated independently for every separately-signed `TokenDiff` intent inside a batch rather than against the account's aggregate exposure for that token in the batch. An unprivileged signer can therefore decompose an arbitrarily large NEP-245/IMT balance into `B` separate `delta = -1` `TokenDiff` intents (each with its own nonce), submit them together in one `execute_intents([...])` call matched against a counterparty's offsetting `+1` legs, and have `Pips::fee_ceil` compute `0` fee on every leg, draining the whole balance while `fee_collector` receives nothing.

### Finding Description
The broken binding: `fee_collector` credit for the token should equal `Pips::fee_ceil(protocol_fee, B)` for a net `-B` exposure by the signer on that token in a batch; observed credit is `0`.

Root cause is in `TokenDiff::token_fee`: [1](#0-0) 
For `TokenIdType::Nep245 | TokenIdType::Imt`, the fee is waived whenever `amount <= 1`, and `amount` here is `delta.unsigned_abs()` taken from a single `TokenDiff::diff` entry: [2](#0-1) 
Each `TokenDiff::execute_intent` call is invoked independently per signed `MultiPayload` via `Engine::execute_signed_intent` / `execute_signed_intents`, with no cross-intent, cross-payload aggregation of the signer's exposure on a given `TokenId` before the fee check runs: [3](#0-2) 
The only invariant enforced across the whole batch is that summed deltas net to zero (checked in `finalize`); this says nothing about fee correctness, so `B` distinct `-1` legs from the attacker, matched against a counterparty's aggregated `+B` leg (or its own `B` distinct `+1` legs), balance the ledger while every attacker leg independently qualifies for the `amount <= 1` exemption.

Attacker payload: sign `B` separate `DefuseIntents { intents: [TokenDiff { diff: {token_id: -1}, .. }] }` payloads (each with a fresh valid nonce, generated locally — no relayer or role required), and submit them as `Vec<MultiPayload>` to `execute_intents` together with a counterparty (which can be a second account controlled by the same attacker) whose `TokenDiff` legs supply the matching `+1`/aggregate `+B` credit. Existing guards (`verify`, `has_public_key`, `verify_intent_nonce`, `commit_nonce`, `finalize`'s zero-sum invariant) all pass because each individual signature, nonce and net-zero balance condition is legitimately satisfied — none of them examine cumulative per-token exposure for fee purposes.

### Impact Explanation
`fee_collector` is denied the `protocol_fee` share (e.g. `Pips::ONE_PERCENT`) it is otherwise entitled to on any NEP-245/IMT-denominated trade, for the *entire* traded amount, not just a rounding remainder — this is systemic, not a rounding edge case. The attacker's own funds are never burned; they retain full swap value from the counterparty while the protocol's expected fee revenue on the leg is reduced to zero. This is repeatable for any account, any `Nep245TokenId`/`Imt` token, and any balance size, matching the "protocol fees bypassed" Critical category.

### Likelihood Explanation
No special role, relayer key, or victim key is needed — an attacker signs their own intents (optionally self-dealing across two accounts they control) with locally-generated nonces and submits a single `execute_intents` call. The only cost is `B` extra intents' worth of transaction size/gas within one call, which is a normal, unrestricted operation. This is fully feasible today and reproducible in a `near-workspaces`/sandbox test.

### Recommendation
Compute the fee-exemption threshold against the signer's *aggregate* negative exposure per `TokenId` across the whole intent batch (or per execution context) rather than per individual `TokenDiff::diff` entry, e.g. by tracking cumulative `|delta|` per `(signer_id, token_id)` in `Engine`/`Deltas` before applying `token_fee`'s `amount <= 1` exemption, so that splitting a large trade into many unit legs cannot escape the fee that would apply to the equivalent single large trade.

### Proof of Concept
`cargo test` (sandbox) plan:
1. Deploy Defuse with `protocol_fee = Pips::ONE_PERCENT`; create attacker account `A` and counterparty `C` (can be attacker's second account); deposit `B` (e.g. `B = 1000`) units of a `Nep245TokenId` (MT) into `A`, and sufficient NEP-141 balance into `C`.
2. Sign `B` distinct `MultiPayload`s from `A`, each containing one `TokenDiff{ diff: {mt_token: -1, ft_token: +ft_per_unit} }` with a fresh nonce, plus one (or `B`) `MultiPayload`(s) from `C` supplying the matching `{mt_token: +B, ft_token: -B*ft_per_unit}` aggregate.
3. Call `execute_intents` once with all `B (+1)` `MultiPayload`s.
4. Assert `fee_collector`'s post-balance for `mt_token` equals its pre-balance (i.e., `0` fee collected), while asserting the invariant-net-zero swap succeeded and `A`'s `mt_token` balance dropped by `B` and `C`'s rose by `B` — demonstrating `fee_collector credit == 0 != Pips::fee_ceil(protocol_fee, B)`.

    pub fn execute_signed_intents(
        mut self,
        signed: impl IntoIterator<Item = MultiPayload>,
    ) -> Result<Transfers> {
        for signed in signed {
            self.execute_signed_intent(signed)?;
        }
        self.finalize()
    }

    fn execute_signed_intent(&mut self, signed: MultiPayload) -> Result<()> {
        // verify signed payload and get public key
        let public_key = signed.verify().ok_or(DefuseError::InvalidSignature)?;

        // calculate intent hash
        let hash = signed.hash();

        // extract NEP-413 payload
        let DefusePayload::<DefuseIntents> {
            signer_id,
            verifying_contract,
            deadline,
            nonce,
            message: intents,
        } = signed.extract_defuse_payload()?;

        // check recipient
        if verifying_contract != *self.state.verifying_contract() {
            return Err(DefuseError::WrongVerifyingContract);
        }

        self.inspector.on_deadline(deadline);

        // make sure message is still valid
        if deadline < Timestamp::now() {
            return Err(DefuseError::DeadlineExpired);
        }

        // make sure the account has this public key
        if !self.state.has_public_key(&signer_id, &public_key) {
            return Err(DefuseError::PublicKeyNotExist(signer_id, public_key));
        }

        // commit nonce
        self.verify_intent_nonce(nonce, deadline)?;
        self.state.commit_nonce(signer_id.clone(), nonce)?;

        intents.execute_intent(&signer_id, self, hash)?;
        self.inspector.on_intent_executed(&signer_id, hash, nonce);

        Ok(())
    }
