### Title
Firewall CA-based rules resolve trust by mutable certificate `Name` instead of a unique fingerprint, allowing cross-CA rule bypass - (File: firewall.go)

### Summary
Nebula's firewall supports pinning rules to a specific issuing CA via two mechanisms: `ca_sha` (the CA's cryptographic fingerprint) and `ca_name` (the CA's human-readable `Name` field). `AddRule`/`AddFirewallRulesFromConfig` accept either value without validating that it uniquely and unambiguously identifies one CA, and `FirewallCA.match` resolves `ca_name` rules by looking up the signer's `Certificate.Name()` string in the `CANames` map rather than its fingerprint. [1](#0-0) [2](#0-1) 

### Finding Description
`FirewallCA.addRule` stores rules under `fc.CAShas[caSha]` (keyed by the CA's unique fingerprint) and separately under `fc.CANames[caName]` (keyed by the CA's `Name` string): [3](#0-2) 

At match time, `FirewallCA.match` resolves the *name*-based path by asking the CA pool for the signer of the peer's certificate and then looking that signer's `Name()` up in `CANames`: [4](#0-3) 

The `Name` field of a nebula CA certificate is an arbitrary string chosen by whoever generated the CA with `nebula-cert ca -name ...` — it is not cryptographically bound to the CA's key, and `AddCA`/`NewCAPoolFromPEMReader` (`cert/ca_pool.go`) impose no uniqueness constraint across CAs loaded into the same `CAPool` (a pool commonly holds more than one root, e.g. during CA rotation, per `loadCAPoolFromConfig` in `pki.go`). [5](#0-4) [6](#0-5) 

This is the same root-cause pattern as the referenced VE3DRewardPool report: a trust-relevant lookup table is keyed by an operator-supplied identifier that is never checked for collision against an existing entry, so an administrative action (adding a second CA to the trust pool, or reusing a default/generic CA name such as `"test ca"`/`"nebula root ca"` used throughout `cert_test` helpers and default `nebula-cert` output) causes two conceptually distinct trust domains to be merged under one map key. Once that happens, `firewall.go`'s `ca_name`-based rule silently grants to peers authenticated by the wrong CA the same access intended only for peers under the CA the administrator meant to name.

Unlike the `ca_sha` path, which is anchored to a value that cannot collide without a hash collision, `ca_name` has no such guarantee, and there is no warning or sanity check (`AddFirewallRulesFromConfig`'s `r.sanity()` check does not cover this) at config-load time to catch two configured/loaded CAs sharing a name. [7](#0-6) 

### Impact Explanation
If an operator's CA pool (`pki.ca`) ever contains two different CAs whose `Name()` strings collide — a realistic scenario since CA names are free-form and organizations frequently reuse defaults or short names during CA rotation, multi-tenant setups, or when merging PEM bundles from different sources — a firewall rule intended to restrict traffic to hosts certified by one specific CA (`ca_name: root01`) will also admit any peer whose certificate was signed by the *other* CA that happens to share that name. This is a concrete firewall/authorization-enforcement bypass: traffic that should have been dropped is instead allowed because the enforcement decision is keyed on a non-unique, admin-controlled string rather than the CA's unique fingerprint.

### Likelihood Explanation
The precondition is administrative, not attacker-controlled: it requires (a) an admin config mistake or organizational practice that loads two differently-keyed CAs sharing the same `Name` into one pool, and (b) use of `ca_name` (rather than `ca_sha`) in a firewall rule. Both are plausible/likely given `ca_name` is documented and used in real configs and default CA names are commonly reused across environments (as seen even in this codebase's own test helpers, which default to `"test ca"`). No attacker action is needed to create the collision — only to hold a cert from the "wrong" but still pool-trusted CA, which is a much weaker bar than compromising the intended CA itself.

### Recommendation
- Prefer resolving `ca_name` rules to a fingerprint at config-load time (resolve the name to the matching CA(s) in the pool once, and reject/warn if more than one CA in the pool shares the same `Name`), rather than doing a live name lookup in `FirewallCA.match`.
- At minimum, have `loadCAPoolFromConfig` / `AddCA` detect and warn (or fail) when two CAs added to the same pool have identical `Name()` values, mirroring the mitigation recommended in the referenced report ("check that there is no mistake or malicious value added").
- Recommend operators use `ca_sha` instead of `ca_name` for security-sensitive firewall rules, and document that `ca_name` is not a unique identifier.

### Proof of Concept
1. Generate two independent CAs, `caA` and `caB`, both created with the same `-name root01` (e.g. via `cmd/nebula-cert` `ca` subcommand, matching `Name: *cf.name` in `cmd/nebula-cert/ca.go:275`).
2. Configure `pki.ca` to include both `caA` and `caB` PEM blocks (a supported, common CA-rotation configuration handled by `loadCAPoolFromConfig`, `pki.go:525-571`), so `CAPool.CAs` contains both under their distinct fingerprints.
3. Configure a firewall rule intended to allow only hosts signed by `caA`: `ca_name: root01`.
4. Issue a leaf certificate signed by `caB` (the "wrong" CA) for a host that should not be trusted by this rule.
5. When that host connects, `FirewallCA.match` calls `caPool.GetCAForCert(c.Certificate)` to find its signer (`caB`), then looks up `fc.CANames["root01"]` — which matches, because the rule was stored under the same name string regardless of which CA fingerprint it came from — and the traffic is allowed even though it was only supposed to be allowed for `caA`-signed peers. 			}

		}
		if err != nil {
			return fmt.Errorf("%s rule #%v; %s %s", table, i, errPort, err)
		}

				return fmt.Errorf("%s rule #%v; local_cidr did not parse; %s", table, i, err)
			}
		}

			l.Warn("firewall rule sanity check",
				"table", table,
				"rule", i,
				"warning", warning,
			)
		}

		err = fw.AddRule(inbound, proto, startPort, endPort, r.Groups, r.Host, r.Cidr, r.LocalCidr, r.CAName, r.CASha)
		if err != nil {
			return fmt.Errorf("%s rule #%v; `%s`", table, i, err)
		}
	}

func (fc *FirewallCA) addRule(f *Firewall, groups []string, host string, cidr, localCidr, caName, caSha string) error {
	fr := func() *FirewallRule {
		return &FirewallRule{
			Hosts:  make(map[string]*firewallLocalCIDR),
			Groups: make([]*firewallGroups, 0),
			CIDR:   new(bart.Table[*firewallLocalCIDR]),
		}
	}

	if caSha == "" && caName == "" {
		if fc.Any == nil {
			fc.Any = fr()
		}

		return fc.Any.addRule(f, groups, host, cidr, localCidr)
	}

	if caSha != "" {
		if _, ok := fc.CAShas[caSha]; !ok {
			fc.CAShas[caSha] = fr()
		}
		err := fc.CAShas[caSha].addRule(f, groups, host, cidr, localCidr)
		if err != nil {
			return err
		}
	}

	if caName != "" {
		if _, ok := fc.CANames[caName]; !ok {
			fc.CANames[caName] = fr()
		}
		err := fc.CANames[caName].addRule(f, groups, host, cidr, localCidr)
		if err != nil {
			return err
		}
	}

	return nil
}

func (fc *FirewallCA) match(p firewall.Packet, c *cert.CachedCertificate, caPool *cert.CAPool) bool {
	if fc == nil {
		return false
	}

	if fc.Any.match(p, c) {
		return true
	}

	if t, ok := fc.CAShas[c.Certificate.Issuer()]; ok {
		if t.match(p, c) {
			return true
		}
	}

	s, err := caPool.GetCAForCert(c.Certificate)
	if err != nil {
		return false
	}

	return fc.CANames[s.Certificate.Name()].match(p, c)
}

// AddCA verifies a Nebula CA certificate and adds it to the pool.
func (ncp *CAPool) AddCA(c Certificate) error {
	if !c.IsCA() {
		return fmt.Errorf("%s: %w", c.Name(), ErrNotCA)
	}

	if !c.CheckSignature(c.PublicKey()) {
		return fmt.Errorf("%s: %w", c.Name(), ErrNotSelfSigned)
	}

	sum, err := c.Fingerprint()
	if err != nil {
		return fmt.Errorf("could not calculate fingerprint for provided CA; error: %w; %s", err, c.Name())
	}

	cc := &CachedCertificate{
		Certificate:    c,
		Fingerprint:    sum,
		InvertedGroups: make(map[string]struct{}),
	}

	for _, g := range c.Groups() {
		cc.InvertedGroups[g] = struct{}{}
	}

	ncp.CAs[sum] = cc

	if c.Expired(time.Now()) {
		return fmt.Errorf("%s: %w", c.Name(), ErrExpired)
	}

	return nil
}

func loadCAPoolFromConfig(l *slog.Logger, c *config.C) (*cert.CAPool, error) {
	caPathOrPEM := c.GetString("pki.ca", "")
	if caPathOrPEM == "" {
		return nil, errors.New("no pki.ca path or PEM data provided")
	}

	var caReader io.ReadCloser
	var err error

	if strings.Contains(caPathOrPEM, "-----BEGIN") {
		caReader = io.NopCloser(strings.NewReader(caPathOrPEM))
	} else {
		caReader, err = os.Open(caPathOrPEM)
		if err != nil {
			return nil, fmt.Errorf("unable to read pki.ca file %s: %s", caPathOrPEM, err)
		}
	}
	defer caReader.Close()

	caPool, err := cert.NewCAPoolFromPEMReader(caReader)
	if errors.Is(err, cert.ErrExpired) {
		var expired int
		for _, crt := range caPool.CAs {
			if crt.Certificate.Expired(time.Now()) {
				expired++
				l.Warn("expired certificate present in CA pool", "cert", crt)
			}
		}

		if expired >= len(caPool.CAs) {
			return nil, errors.New("no valid CA certificates present")
		}

	} else if err != nil {
		return nil, fmt.Errorf("error while adding CA certificate to CA trust store: %s", err)
	}

	bl := c.GetStringSlice("pki.blocklist", []string{})
	if len(bl) > 0 {
		for _, fp := range bl {
			caPool.BlocklistFingerprint(fp)
		}

		l.Info("Blocklisted certificates", "fingerprintCount", len(bl))
	}

	return caPool, nil
