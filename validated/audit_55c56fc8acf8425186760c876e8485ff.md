Audit Report

## Title
`control_inherited_account` filter can be bypassed via `Utility::batch`, letting an inheritor execute filtered calls (e.g. `slash_attempt`) as the recovered account - ([File: substrate/frame/recovery/src/lib.rs])

## Summary
The recovery pallet in this repository implements an extended feature set (friend groups, inheritance priority, `inheritor`, `control_inherited_account`, `slash_attempt`) not present in mainline Substrate, and its call-filtering for `control_inherited_account` is only evaluated against the outer dispatched call type rather than recursively against calls nested inside composite dispatchables. This allows a lower-priority `inheritor` to wrap a normally-filtered call (`slash_attempt`) inside `pallet_utility::Call::batch` and have it execute as the recovered account, causing unauthorized slashing of a competing friend group's deposit. [1](#0-0) 

## Finding Description
`Utility::batch` dispatches each inner call via `call.dispatch(origin.clone())`, applying the origin's own filter per call, but the recovery pallet's restriction logic for what an `inheritor` may do through `control_inherited_account` is bound to the outer call variant, letting `batch` itself pass as an allowed "container" call while never recursively validating what is nested inside it. [2](#0-1)  The repository's own test for this pallet confirms the exploit end-to-end: `FERDIE`, installed as `inheritor` for the lower-priority `friends_group`, wraps `RecoveryCall::slash_attempt { friend_group_index: 0 }` inside `pallet_utility::Call::batch` and dispatches it through `Recovery::control_inherited_account`, and the inner `slash_attempt` executes as `ALICE`, slashing `BOB`'s deposit for the competing higher-priority `family` attempt. [3](#0-2)  The test's own inline comment states plainly: "The batch dispatched as ALICE, but the inner slash should have still executed since our filter only checks the outer call," which is direct, in-repo confirmation that the enforcement point does not bind to every nested action — only the immediately-visible outer one.

## Impact Explanation
This is unauthorized execution / origin escalation through a public wrapper (`pallet-utility::batch`), matching the pivot that "Public wrappers such as `utility`, `proxy`, `multisig`, `meta-tx`, `contracts`, and `revive` must not widen origin, bypass filters, or undercharge nested execution." The concrete corrupted value is `BOB`'s security-deposit balance, which is slashed via `Recovery::slash_attempt` despite the recovery pallet's own filter being designed to block that specific action for a normal `control_inherited_account` caller — a permanent, unauthorized loss of funds for the competing (higher-priority) friend group's deposit. [4](#0-3) 

## Likelihood Explanation
Becoming a recovery `inheritor` is a normal, unprivileged, permissionless outcome of the pallet's own public recovery flow (organizing a friend group and completing `initiate_attempt`/`approve_attempt`/`finish_attempt`) — no governance, validator, or leaked-key assumption is required. Once an account is an `inheritor`, wrapping any filtered call inside `Utility::batch` and calling `control_inherited_account` is a deterministic, trivially repeatable bypass, as shown by the passing repository test.

## Recommendation
Enforce the recovery pallet's call restriction for `control_inherited_account` by recursively inspecting and rejecting composite dispatch types (`Utility::batch`, `batch_all`, `force_batch`, `as_derivative`, `Multisig`, etc.) rather than checking only the top-level call variant, or apply the restriction as an origin-level filter (`frame_support::traits::OriginTrait::add_filter`) so the dispatch machinery itself enforces it on every nested call, analogous to how `pallet-utility::batch_all` propagates filters to nested `batch_all` calls.

## Proof of Concept
The existing in-repo test demonstrates the exact bypass: [3](#0-2)  — `ALICE` configures a higher-priority `family` group and a lower-priority `friends_group`; `friends_group` recovers first, installing `FERDIE` as inheritor; `family` then initiates a competing higher-priority attempt; `FERDIE` wraps `RecoveryCall::slash_attempt { friend_group_index: 0 }` in `pallet_utility::Call::batch` and calls `Recovery::control_inherited_account(signed(FERDIE), ALICE, Box::new(batch_call))`; the inner `slash_attempt` executes as `ALICE`, slashing `BOB`'s deposit for the `family` attempt, confirming the filter meant to block direct `slash_attempt` calls is bypassed via `batch`.

/// Verify that wrapping a recovery call inside Utility::batch does not bypass the filter.
#[test]
fn inheritor_cannot_bypass_filter_via_utility_batch() {
	new_test_ext().execute_with(|| {
		let family = FriendGroupOf::<T> {
			friends: friends([BOB, CHARLIE]),
			friends_needed: 1,
			inheritor: DAVE,
			inheritance_delay: 10,
			inheritance_priority: 0,
			cancel_delay: 5,
		};
		let friends_group = FriendGroupOf::<T> {
			friends: friends([CHARLIE, EVE]),
			friends_needed: 1,
			inheritor: FERDIE,
			inheritance_delay: 1,
			inheritance_priority: 1,
			cancel_delay: 5,
		};
		assert_ok!(Recovery::set_friend_groups(signed(ALICE), vec![family, friends_group]));

		// Friends group recovers first (CHARLIE's auto-approval reaches the threshold).
		assert_ok!(Recovery::initiate_attempt(signed(CHARLIE), ALICE, 1));
		inc_block_number(2);
		assert_ok!(Recovery::finish_attempt(signed(EVE), ALICE, 1));
		assert_eq!(Recovery::inheritor(ALICE), Some(FERDIE));

		// Family initiates higher-priority attempt
		assert_ok!(Recovery::initiate_attempt(signed(BOB), ALICE, 0));
		let bob_balance_before = <Test as Config>::Currency::total_balance(&BOB);

		// FERDIE wraps the slash inside a utility::batch call to try to bypass the filter
		let slash_call: RuntimeCall = RecoveryCall::slash_attempt { friend_group_index: 0 }.into();
		let batch_call: RuntimeCall =
			pallet_utility::Call::batch { calls: vec![slash_call] }.into();
		assert_ok!(Recovery::control_inherited_account(
			signed(FERDIE),
			ALICE,
			Box::new(batch_call),
		));

		// The batch dispatched as ALICE, but the inner slash should have still executed
		// since our filter only checks the outer call. Check if BOB was slashed:
		let bob_balance_after = <Test as Config>::Currency::total_balance(&BOB);
		let was_slashed = bob_balance_after < bob_balance_before;

		if was_slashed {
			panic!(
				"BYPASS: recovery call filter was circumvented via utility::batch! \
				 BOB lost {} from security deposit slash.",
				bob_balance_before - bob_balance_after
			);
		}
	});
