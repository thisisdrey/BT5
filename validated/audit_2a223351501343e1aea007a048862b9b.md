### Title
Unauthenticated single-connection DoS on Signer event loop via slow/incomplete HTTP request to `SignerEventReceiver` - (File: libsigner/src/events.rs)

### Summary
`SignerEventReceiver::bind` starts a `tiny_http` `HttpServer` with no read timeout, and `next_event`/`main_loop` run in a single dedicated thread that calls `http_server.recv()` synchronously in a loop. Because `tiny_http::Server::recv()` performs blocking request-line/header parsing on the calling thread with no per-connection timeout configured anywhere in this code path, a remote unauthenticated peer that opens a TCP connection to the signer's event-ingestion port and sends non-HTTP bytes (or a partial request) without closing the socket can make `recv()` block indefinitely.

### Finding Description
`SignerEventReceiver::bind` [1](#0-0)  calls `HttpServer::http(listener)` without setting a socket-level read timeout on the listener or accepted connections. `next_event` then calls `http_server.recv()` directly inside `with_server`, and only checks `is_stopped()` *before* the blocking call, not while it is in progress [2](#0-1) . The `main_loop` trait default implementation drives this in a single thread with no concurrency: it checks `is_stopped()`, then calls `next_event()`, and only after that returns does it loop back to check `is_stopped()` again [3](#0-2) . In `Signer::spawn`, exactly one thread (`event_receiver:{bind_port}`) is spawned to run this `main_loop`, so there is no other thread available to service subsequent connections while the first one is being parsed [4](#0-3) .

`tiny_http`'s `Server::recv()` accepts a connection and performs blocking reads to parse the HTTP request line/headers on the calling thread; it applies no timeout unless the caller explicitly sets one on the socket, which this code does not do. An attacker who opens a TCP connection to the signer's bound address and sends bytes that never form a complete/valid HTTP request line (e.g., raw garbage with no CRLF, or a request line kept dangling by trickling bytes) and never closes the socket will cause the parse inside `recv()` to block forever (or until an OS-level TCP timeout, which is not attacker-controlled and can be avoided by keeping the connection alive with periodic bytes/keepalives).

While this one connection is stuck, `next_event()` never returns, so `main_loop` never loops back to check `is_stopped()` nor processes any subsequent request. This starves all legitimate node-dispatcher POSTs (`/new_block`, `/new_burn_block`, `/stackerdb_chunks`, `/proposal_response`, `/status`) from ever being received by the signer, since they are all serialized through this single `recv()` call.

None of the existing guards apply here: there is no auth/secret required to reach this endpoint (this is the signer's *inbound* event listener that the local node pushes to, but nothing enforces that only the local node can connect — any TCP peer that can reach the bound address can connect), `MAX_MESSAGE_LEN`/body-size checks only apply after a full HTTP request is parsed (in `process_event`, invoked only after `recv()` returns), and `is_stopped()` provides no help since it's not polled during the blocking call.

### Impact Explanation
A single malformed/incomplete TCP connection permanently (until manually killed) blocks the signer's only event-ingestion thread, preventing it from processing all subsequent legitimate events from the Stacks node (new blocks, burn blocks, stacker-DB chunks, block-validation responses). This is an unauthenticated, remote, single-message denial of service against the signer's event pipeline — matching the "Critical: remote crash/unauthenticated DoS from few messages" category. It does not corrupt or forge chain state, but it can stall a signer's participation in block signing indefinitely.

### Likelihood Explanation
- No privileged role, secret, or prior state is required — any TCP client that can route to the signer's event-receiver bind address can trigger it.
- Attacker cost is a single open socket and a few non-HTTP bytes (or none at all beyond a valid connect).
- Fully repeatable, and does not require volume/bandwidth (a single connection suffices), so it is not excluded by the "volumetric DDoS" exclusion.
- The main precondition is remote reachability of the signer's event-receiver port, which is the intended interface for the node-to-signer POST callbacks and is explicitly noted in the codebase's own warning about exposing this listener to non-local/external networks [5](#0-4) .

### Recommendation
Set an explicit read/parse timeout on accepted connections (or on the `tiny_http` server) so a stalled/incomplete request cannot block `recv()` indefinitely, and/or run multiple worker threads consuming `http_server.recv()` concurrently (as `tiny_http` supports) so one slow/malicious connection cannot starve the whole receiver. Additionally, poll `is_stopped()`/incoming connections with a bounded timeout (e.g., use `try_recv()` in a loop with a timeout) rather than an unbounded blocking `recv()`.

### Proof of Concept
```rust
use std::net::{SocketAddr, TcpStream};
use std::io::Write;
use std::time::Duration;
use std::thread;

use libsigner::{EventReceiver, SignerEventReceiver};

#[test]
fn test_malformed_connection_blocks_receiver() {
    let addr: SocketAddr = "127.0.0.1:31337".parse().unwrap();
    let mut receiver = SignerEventReceiver::<StacksBlockEvent>::new(false); // pseudo-type
    receiver.bind(addr).unwrap();

    // Attacker: open connection, send non-HTTP garbage, never close.
    let mut evil = TcpStream::connect(addr).unwrap();
    evil.write_all(b"NOT_HTTP_GARBAGE_NO_CRLF").unwrap();
    // deliberately do NOT send \r\n\r\n or close the socket

    // Legitimate node request, sent after the attacker's connection.
    let (tx, rx) = std::sync::mpsc::channel();
    let handle = thread::spawn(move || {
        let ev = receiver.next_event(); // should have processed the evil conn's recv() first
        tx.send(ev).ok();
    });

    // Assert: legitimate event never arrives within a bounded timeout,
    // proving next_event()/recv() is stuck on the malformed connection.
    let result = rx.recv_timeout(Duration::from_secs(5));
    assert!(result.is_err(), "next_event() should be stuck on the malformed connection, but returned");
}
```
Note: full confirmation of `tiny_http`'s exact internal blocking/timeout behavior on malformed input would require inspecting the vendored `tiny_http` crate source directly (not present in this repo's indexed files, only referenced via `Cargo.lock`); this analysis relies on `tiny_http`'s documented single-threaded, timeout-less blocking `recv()` semantics combined with the single-threaded consumption pattern shown in `libsigner/src/events.rs` and `libsigner/src/runloop.rs`.

        loop {

                    continue;
                }

                    continue;
                }
            };

                info!("Failed to forward event");
                break;
            }
        }
