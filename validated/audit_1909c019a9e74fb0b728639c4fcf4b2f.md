### Title
Missing path traversal validation on `BackupId` in `RestoreRepository` allows cross-repository backup restore - (File: `internal/gitaly/service/repository/restore_repository.go`)

### Summary
`validateRestoreRepositoryRequest` calls `backup.ValidatePathPrefix` on `PathPrefix` but performs no equivalent validation on `BackupId`, even though `BackupId` is used unsanitized in path construction by `manifestPath`/`ReadManifest`. An attacker who can call `RestoreRepository` for their own repository can supply a `BackupId` containing `../` sequences to make the manifest lookup resolve outside the intended `manifests/<storage>/<relative_path>/` subtree.

### Finding Description
`RestoreRepository` validates the `Repository`/`VanityRepository` relative paths via `s.locator.ValidateRepository` and validates `PathPrefix` via `backup.ValidatePathPrefix`, but never validates `in.GetBackupId()`: [1](#0-0) 

The unvalidated `BackupID` flows into `manager.Restore`, which passes it directly to `mgr.locator.Find(ctx, req.VanityRepository, req.BackupID, locatorOpts...)`: [2](#0-1) 

`ManifestLocator.Find` forwards `backupID` unchanged to `ReadManifest`: [3](#0-2) 

`ReadManifest` builds the manifest path with `manifestPath(repo, backupID, cfg.pathPrefix)`, which does `path.Join(manifestDirectory(repo, backupPathPrefix), backupID+".toml")`: [4](#0-3) [5](#0-4) 

`path.Join` lexically cleans `..` components, so a `BackupId` such as `../../../<other-storage>/<other-repo>.git/<real-backup-id>` collapses the manifest path to point at a different storage/repository subtree (or, with enough `../`, outside the `manifests/` root entirely), while `manifestDirectory` (built from the attacker's own validated `VanityRepository`) provides no containment because `path.Join` does not clamp to that prefix. In contrast, `backup.ValidatePathPrefix` explicitly rejects any component that is `.`/`..`-only, showing the codebase is aware of this class of risk for `PathPrefix` but the same check was not applied to `BackupID`: [6](#0-5) 

Once a manifest belonging to another repository is loaded this way, `Manager.Restore` proceeds to restore refs/bundle and, notably, extract the custom hooks tar archive (`restoreCustomHooks`) from the paths recorded in that foreign manifest into the attacker's own repository: [7](#0-6) 

### Impact Explanation
An attacker can trigger `RestoreRepository` on their own (attacker-owned) repository while supplying a crafted `BackupId` with `../` sequences, causing Gitaly to locate and load a manifest (and subsequently the bundle/refs/custom-hooks archive it references) belonging to a different repository/tenant on the same backup storage. This results in cross-tenant backup content being pulled into the attacker's repository — enabling disclosure of another tenant's Git history/refs and injection of that tenant's custom hooks into the attacker's repository (or vice versa, depending on how the manifest paths resolve). This matches GitLab's cross-repository/tenant data disclosure and hook-injection impact classes.

### Likelihood Explanation
Preconditions are modest and match the threat model: server-side backups must be configured (`s.backupSink`/`s.backupLocator` non-nil, a supported but not exotic deployment mode) and the attacker only needs the ability to invoke `RestoreRepository` for a repository they already control — no elevated privileges, secrets, or additional access. The `BackupId` field is fully attacker-controlled and reaches the path-join logic with zero sanitization, so the primitive is straightforward and repeatable.

### Recommendation
Apply the same validation used for `PathPrefix` to `BackupID` in `validateRestoreRepositoryRequest` (e.g., extend/reuse `backup.ValidatePathPrefix`-style logic, or a dedicated `ValidateBackupID` that rejects empty components, `.`/`..` components, absolute paths, and path separators beyond what's expected for a backup ID) before it is passed to `manager.Restore`. Additionally, consider hardening `manifestPath`/`ReadManifest` (and other `Locator` methods keyed on `backupID`) to verify the resolved path stays within `manifestDirectory(repo, pathPrefix)` as a defense-in-depth check.

	return nil

// ValidatePathPrefix validates that the backup path prefix is safe for use in path construction.
// It rejects absolute paths and paths containing ".." to prevent directory traversal attacks.
// Returns ErrInvalidPathPrefix if validation fails.
func ValidatePathPrefix(prefix string) error {
	if prefix == "" {
		// Empty prefix is allowed
		return nil
	}

	if filepath.IsAbs(prefix) {
		return fmt.Errorf("%w: must be a relative path", ErrInvalidPathPrefix)
	}

	for _, part := range strings.Split(prefix, "/") {
		if part == "" || strings.Trim(part, ".") == "" {
			return fmt.Errorf("%w: must be a clean relative path without traversal", ErrInvalidPathPrefix)
		}
	}

	return nil
}

// ReadManifest reads a manifest from the sink for the specified backup ID.
func (l ManifestLoader) ReadManifest(ctx context.Context, repo storage.Repository, backupID string, opts ...Option) (*Backup, error) {
	cfg := applyOptions(opts)
	f, err := l.sink.GetReader(ctx, manifestPath(repo, backupID, cfg.pathPrefix))
	if err != nil {
		return nil, fmt.Errorf("read manifest: %w", err)
	}
	defer f.Close()

	var backup Backup

	if err := toml.NewDecoder(f).Decode(&backup); err != nil {
		return nil, fmt.Errorf("read manifest: %w", err)
	}

	backup.ID = backupID
	backup.Repository = repo

	return &backup, nil
}

func TestValidatePathPrefix(t *testing.T) {
	tests := []struct {
		name      string
		prefix    string
		expectErr bool
		errMsg    string
	}{
		{
			name:      "empty prefix is valid",
			prefix:    "",
			expectErr: false,
		},
		{
			name:      "single directory",
			prefix:    "2026",
			expectErr: false,
		},
		{
			name:      "nested relative path",
			prefix:    "backups/monthly/2024-03",
			expectErr: false,
		},
		{
			name:      "absolute path with leading slash",
			prefix:    "/tmp/backups",
			expectErr: true,
			errMsg:    "must be a relative path",
		},
		{
			name:      "directory traversal with ..",
			prefix:    "backups/../../../etc",
			expectErr: true,
			errMsg:    "must be a clean relative path without traversal",
		},
		{
			name:      "directory traversal at start",
			prefix:    "../backups",
			expectErr: true,
			errMsg:    "must be a clean relative path without traversal",
		},
		{
			name:      "directory traversal in middle",
			prefix:    "backups/../other",
			expectErr: true,
			errMsg:    "must be a clean relative path without traversal",
		},
		{
			name:      "dot path",
			prefix:    ".",
			expectErr: true,
			errMsg:    "must be a clean relative path without traversal",
		},
		{
			name:      "path with special characters",
			prefix:    "2024-03_11.Feb",
			expectErr: false,
		},
		{
			name:      "trailing slash",
			prefix:    "backups/",
			expectErr: true,
			errMsg:    "must be a clean relative path without traversal",
		},
		{
			name:      "double slash",
			prefix:    "backups//2024",
			expectErr: true,
			errMsg:    "must be a clean relative path without traversal",
		},
		{
			name:      "dot-dot only",
			prefix:    "..",
			expectErr: true,
			errMsg:    "must be a clean relative path without traversal",
		},
		{
			name:      "triple dots component",
			prefix:    "backups/.../feb",
			expectErr: true,
			errMsg:    "must be a clean relative path without traversal",

				}
			} else {
				require.NoError(t, err)
			}
		})
	}
