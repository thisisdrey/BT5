### Title
ETH-implicit accounts created with an unregistered global wallet-contract hash permanently freeze funds - (File: `runtime/runtime/src/actions.rs`)

### Summary
This is a direct analog of the reported issue: `VibeERC721` depends on an external `OPERATOR_FILTER_REGISTRY` that may not be deployed on a new network, silently breaking core functionality. In nearcore, ETH-implicit account creation depends on a global contract (the "Wallet Contract") that is referenced only by a hard-coded code hash, and that hash is never checked for existence at account-creation time. On any network where that global contract has not actually been deployed, funds sent to create an ETH-implicit account become permanently unusable.

### Finding Description
When an ETH-implicit account (`0x...` account ID) is created via a `Transfer` action, `action_implicit_account_creation_transfer` sets its contract to `AccountContract::Global(global_contract_hash)`, where `global_contract_hash = eth_wallet_global_contract_hash(&chain_id)`: [1](#0-0) 

`eth_wallet_global_contract_hash` hard-codes hashes for `MAINNET`/`MOCKNET`/`TESTNET` only; for any other `chain_id` (i.e. any new/custom network) it falls back to the hash of the locally embedded `LOCALNET` wallet contract code: [2](#0-1) 

Unlike `use_global_contract`, which explicitly verifies the global contract's presence in the trie before attaching it to an account (`GlobalContractDoesNotExist` on failure): [3](#0-2) 

`action_implicit_account_creation_transfer` performs **no such check**. It unconditionally sets `AccountContract::Global(global_contract_hash)` on the new account, regardless of whether any account has actually deployed that code as a global contract via `DeployGlobalContract`.

Further compounding this, `RuntimeContractIdentifier::resolve` for a `GlobalContractIdentifier::CodeHash` returns the hash immediately without any existence check: [4](#0-3) 

So the missing-contract condition is not detected at creation, and is only discovered later, when someone actually tries to call the account (e.g., via `rlp_execute`), at which point `RuntimeContractExt::get_code` returns `None` because `ContractStorage::get` finds nothing for that hash: [5](#0-4) 

By this point the account is already created and funded, and since ETH-implicit accounts never receive an access key (only the Wallet Contract mediates all their actions per NEP-518), the account can never be:
- Called (no deployed code exists under that hash on this chain).
- Emptied via a signed transaction (no access key exists to authorize `Transfer`/`DeleteAccount`/`AddKey`, as demonstrated by the existing rejection test for eth-implicit accounts lacking keys): [6](#0-5) 

### Impact Explanation
Any deposit sent to create an ETH-implicit account on a network whose `chain_id` is not `mainnet`/`testnet`/`mocknet` — i.e., essentially every fresh/custom/private nearcore deployment — is permanently and irrecoverably frozen unless the network operator happens to deploy a global contract whose code hash exactly equals the embedded `LOCALNET` wallet-contract binary's hash. This satisfies the "permanent freezing of funds" impact criterion: the balance is locked in an account with no access key and no functioning contract code, with no path (transaction type or admin override) to recover it.

### Likelihood Explanation
This triggers automatically and deterministically whenever the `EthImplicitGlobalContract` protocol feature is active (base protocol per `protocol-model/spec/accounts-keys.md`) and any ordinary user (not an operator, not a validator) sends a `Transfer` to an ETH-implicit account ID on a network where the wallet-contract global contract has not been deployed with the exact expected hash. No privileged action or malicious behavior is required — it is the default behavior on any new network unless the operator proactively deploys the specific global contract, mirroring exactly the reported "registry may be missing on a new network" bug class.

### Recommendation
Before setting `AccountContract::Global(global_contract_hash)` in `action_implicit_account_creation_transfer`, verify that a global contract with that hash actually exists in the trie (the same check `use_global_contract` already performs). If absent, either reject the implicit-account creation with an explicit error (refunding the transfer) or fall back to the legacy embedded-local-code path instead of silently referencing a non-existent global contract.

### Proof of Concept
1. Launch a fresh nearcore network with `chain_id` set to something other than `mainnet`, `testnet`, or `mocknet` (e.g., `chain_id = "my-new-chain"`), with the `EthImplicitGlobalContract` feature active and genesis not deploying any global contract.
2. As an ordinary user, derive an ETH-implicit account ID from any Secp256k1 key (`derive_eth_implicit_account_id`).
3. Send a `Transfer` action from a funded named account to this ETH-implicit account ID. `action_implicit_account_creation_transfer` creates the account with `AccountContract::Global(eth_wallet_global_contract_hash("my-new-chain"))`, i.e., `LOCALNET`'s wallet contract hash, which was never deployed on this chain — the transaction succeeds and the deposit is now held by the account.
4. Attempt to interact with the account (e.g., call `rlp_execute` via a `FunctionCall`, or attempt to move funds out). This fails because no contract code exists under that hash (`RuntimeContractExt::get_code` returns `None`), and there is no access key to authorize a direct `Transfer`/`DeleteAccount`/`AddKey` from the account (as shown by `test_transaction_from_eth_implicit_account_fail`).
5. The deposited balance remains permanently stuck in the account with no recovery path.

pub(crate) fn use_global_contract(
    state_update: &mut TrieUpdate,
    account_id: &AccountId,
    account: &mut Account,
    contract_identifier: &GlobalContractIdentifier,
    result: &mut ActionResult,
) -> Result<(), RuntimeError> {
    let key = TrieKey::GlobalContractCode { identifier: contract_identifier.clone().into() };
    if !state_update.contains_key(&key, AccessOptions::DEFAULT)? {
        result.result = Err(ActionErrorKind::GlobalContractDoesNotExist {
            identifier: contract_identifier.clone(),
        }
        .into());
        return Ok(());
    }
    clear_account_contract_storage_usage(state_update, account_id, account)?;
    if account.contract().is_local() {
        state_update.remove(TrieKey::ContractCode { account_id: account_id.clone() });
    }

/// Test that transactions from ETH-implicit accounts are rejected.
#[test]
fn test_transaction_from_eth_implicit_account_fail() {
    let genesis = Genesis::test(vec!["test0".parse().unwrap(), "test1".parse().unwrap()], 1);
    let mut env = TestEnv::builder(&genesis.config).nightshade_runtimes(&genesis).build();
    let genesis_block = env.clients[0].chain.get_block_by_height(0).unwrap();
    let chain_id = &genesis.config.chain_id;
    let deposit_for_account_creation = Balance::from_near(1);
    let mut height = 1;
    let blocks_number = 5;
    let signer1 = InMemorySigner::test_signer(&"test1".parse().unwrap());

    let secret_key = SecretKey::from_seed(KeyType::SECP256K1, "test");
    let public_key = secret_key.public_key();
    let eth_implicit_account_id = derive_eth_implicit_account_id(public_key.unwrap_as_secp256k1());
    let eth_implicit_account_signer =
        InMemorySigner::from_secret_key(eth_implicit_account_id.clone(), secret_key).into();

    // Send money to ETH-implicit account, invoking its creation.
    let send_money_tx = SignedTransaction::send_money(
        1,
        "test1".parse().unwrap(),
        eth_implicit_account_id.clone(),
        &signer1,
        deposit_for_account_creation,
        *genesis_block.hash(),
    );
    // Check for tx success status and get new block height.
    height = check_tx_processing(&mut env, send_money_tx, height, blocks_number);
    let block = env.clients[0].chain.get_block_by_height(height - 1).unwrap();

    // Try to send money from ETH-implicit account using `(block_height - 1) * 1e6` as a nonce.
    // That would be a good nonce for any access key, but the transaction should fail nonetheless because there is no access key.
    let nonce = (height - 1) * AccessKey::ACCESS_KEY_NONCE_RANGE_MULTIPLIER;
    let send_money_from_eth_implicit_account_tx = SignedTransaction::send_money(
        nonce,
        eth_implicit_account_id.clone(),
        "test0".parse().unwrap(),
        &eth_implicit_account_signer,
        Balance::from_yoctonear(100),
        *block.hash(),
    );
    let response =
        env.rpc_handlers[0].process_tx(send_money_from_eth_implicit_account_tx, false, false);
    let expected_tx_error = ProcessTxResponse::InvalidTx(InvalidTxError::InvalidAccessKeyError(
        InvalidAccessKeyError::AccessKeyNotFound {
            account_id: eth_implicit_account_id.clone(),
            public_key: public_key.clone().into(),
        },
    ));
    assert_eq!(response, expected_tx_error);

    // Try to delete ETH-implicit account. Should fail because there is no access key.
    let delete_eth_implicit_account_tx = SignedTransaction::delete_account(
        nonce,
        eth_implicit_account_id.clone(),
        eth_implicit_account_id.clone(),
        "test0".parse().unwrap(),
        &eth_implicit_account_signer,
        *block.hash(),
    );
    let response = env.rpc_handlers[0].process_tx(delete_eth_implicit_account_tx, false, false);
    assert_eq!(response, expected_tx_error);

    // Try to add an access key to the ETH-implicit account. Should fail because there is no access key.
    let add_access_key_to_eth_implicit_account_tx = SignedTransaction::from_actions(
        nonce,
        eth_implicit_account_id.clone(),
        eth_implicit_account_id.clone(),
        &eth_implicit_account_signer,
        vec![Action::AddKey(Box::new(AddKeyAction {
            public_key,
            access_key: AccessKey::full_access(),
        }))],
        *block.hash(),
    );
    let response =
        env.rpc_handlers[0].process_tx(add_access_key_to_eth_implicit_account_tx, false, false);
    assert_eq!(response, expected_tx_error);

    // Try to deploy the Wallet Contract again to the ETH-implicit account. Should fail because there is no access key.
    let magic_bytes = wallet_contract_magic_bytes(&chain_id);
    let wallet_contract_code = wallet_contract(*magic_bytes.hash()).unwrap().code().to_vec();
    let add_access_key_to_eth_implicit_account_tx = SignedTransaction::from_actions(
        nonce,
        eth_implicit_account_id.clone(),
        eth_implicit_account_id,
        &eth_implicit_account_signer,
        vec![Action::DeployContract(DeployContractAction { code: wallet_contract_code })],
        *block.hash(),
    );
    let response =
        env.rpc_handlers[0].process_tx(add_access_key_to_eth_implicit_account_tx, false, false);
    assert_eq!(response, expected_tx_error);
}
