### Title
Fee bypass on `Nep245`/`Imt` token transfers via unit-splitting `TokenDiff` intents in one `execute_signed_intents` call - (File: `contracts/defuse/core/src/intents/token_diff.rs`)

### Summary
`TokenDiff::token_fee` waives the protocol fee entirely for `Nep245`/`Imt` (and `Nep171`) token deltas whose `amount <= 1`, and this exemption is evaluated independently for each `TokenDiff` intent rather than for the aggregate amount of a token moved by a signer across the whole `execute_signed_intents` call. By splitting a single `-N` delta on a `Nep245`/`Imt` token into `N` separate signed `TokenDiff` intents each with `delta == -1` on the same `token_id`, the same signer pays zero total fee for moving `N` units, whereas submitting the same net movement as one `TokenDiff` would incur `protocol_fee.fee_ceil(N)`.

### Finding Description
The binding that should hold is: total `fees_collected` added to `fee_collector` for token `T` across the whole `execute_signed_intents` call == `protocol_fee.fee_ceil(sum of all negative deltas of T across all intents in the call)`.

In `TokenDiff::execute_intent`, the fee is computed per intent, per token, from the `amount` present in *that single intent's* diff: [1](#0-0) 

and the exemption threshold is applied on that same per-intent `amount`: [2](#0-1) 

`Engine::execute_signed_intents` simply iterates over the signed payloads and calls `execute_signed_intent` for each one, dispatching to `TokenDiff::execute_intent` independently; there is no cross-intent, cross-payload accumulation of the negative delta per `(signer, token)` before fee calculation: [3](#0-2) 

Consequently, an attacker (the signer, using their own key/nonces) can:
1. Sign `TokenDiff` intent A: `diff = { token_id: -1, other_token: +x }`
2. Sign `TokenDiff` intent B (different nonce, different `intent_hash`): `diff = { token_id: -1, other_token: +x }`
3. Submit both in the same `MultiPayload` batch to `execute_intents`/`execute_signed_intents`, matched against a counterparty (or another own intent) supplying the offsetting `+2` on `token_id` and `-2x` on `other_token` to satisfy `TransferMatcher::finalize`'s zero-sum invariant.

Each of A and B individually has `amount == 1` for `token_id`, so `Self::token_fee(token_id, 1, protocol_fee)` returns `Pips::ZERO` for both, and `fees_collected` is `0` for `token_id` in both intents. The combined effect moves `2` units of `token_id` out of the signer's balance with `0` total fee collected, while a single `TokenDiff` with `delta = -2` on the same token would have collected `protocol_fee.fee_ceil(2)` (nonzero for any `protocol_fee > 0`, e.g. `fee_ceil(2)` at `Pips::ONE_PERCENT` = `1`).

None of the existing guards — `MultiPayload::verify`, `has_public_key`, `verify_intent_nonce`, `commit_nonce`, `TransferMatcher::finalize` (which only enforces net-zero token movement across the batch, not fee correctness), or `checked_*` arithmetic — check or restrict the sum of per-token negative deltas across intents/payloads for fee purposes. The `-1`-unit fee exemption is a legitimate design choice for a single intent (to avoid disproportionate `fee_ceil` rounding on dust transfers), but it is not scoped to prevent trivial replay via splitting.

### Impact Explanation
This is a protocol-fee under-collection: `fee_collector` receives strictly less than `protocol_fee.fee_ceil(total negative delta)` for `Nep245`/`Imt` tokens whenever the mover is willing to split their transfer into unit-sized intents within one batch. This directly matches the audit's Critical category "protocol fees bypassed or over-collected." The attacker (any signer who can produce and batch multiple self-signed intents) repeatably avoids fees on arbitrarily large multi-token transfers by decomposing them into `N` unit-delta intents, at the cost of only extra transaction/gas overhead and needing a counterparty (which can be their own additional intents or a cooperating solver) to balance the `TransferMatcher` invariant. Blast radius is limited to `Nep245`/`Imt` (and trivially `Nep171`, which is inherently unit-sized) token fee revenue; NEP-141 tokens are unaffected because `token_fee` always returns the full `fee` for `Nep141` regardless of amount.

### Likelihood Explanation
Preconditions are minimal: the attacker only needs their own signer key, some balance of a `Nep245`/`Imt` token in the Verifier, and a counterparty (a taker/solver, or another self-signed intent) willing to provide the matching offsetting deltas so `TransferMatcher::finalize` succeeds. No privileged role, relayer key, or DAO/role holder access is required — this is directly reachable via `execute_intents`/`simulate_intents` with an ordinary `MultiPayload` batch. It is fully repeatable per batch and scales linearly with the number of unit-sized intents the attacker is willing to sign and submit.

### Recommendation
Aggregate the negative delta per `(signer_id, token_id)` across all `TokenDiff` intents within a single `execute_signed_intents` call (e.g., accumulate into the `Deltas`/`TransferMatcher` state before applying the `amount <= 1` fee exemption), and compute/collect the fee once against that aggregated amount, rather than per individual `TokenDiff` intent.

    pub fn execute_signed_intents(
        mut self,
        signed: impl IntoIterator<Item = MultiPayload>,
    ) -> Result<Transfers> {
        for signed in signed {
            self.execute_signed_intent(signed)?;
        }
        self.finalize()
    }

    fn execute_signed_intent(&mut self, signed: MultiPayload) -> Result<()> {
        // verify signed payload and get public key
        let public_key = signed.verify().ok_or(DefuseError::InvalidSignature)?;

        // calculate intent hash
        let hash = signed.hash();

        // extract NEP-413 payload
        let DefusePayload::<DefuseIntents> {
            signer_id,
            verifying_contract,
            deadline,
            nonce,
            message: intents,
        } = signed.extract_defuse_payload()?;

        // check recipient
        if verifying_contract != *self.state.verifying_contract() {
            return Err(DefuseError::WrongVerifyingContract);
        }

        self.inspector.on_deadline(deadline);

        // make sure message is still valid
        if deadline < Timestamp::now() {
            return Err(DefuseError::DeadlineExpired);
        }

        // make sure the account has this public key
        if !self.state.has_public_key(&signer_id, &public_key) {
            return Err(DefuseError::PublicKeyNotExist(signer_id, public_key));
        }

        // commit nonce
        self.verify_intent_nonce(nonce, deadline)?;
        self.state.commit_nonce(signer_id.clone(), nonce)?;

        intents.execute_intent(&signer_id, self, hash)?;
        self.inspector.on_intent_executed(&signer_id, hash, nonce);

        Ok(())
    }
