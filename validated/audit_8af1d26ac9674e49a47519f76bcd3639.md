### Title
Unauthenticated `/shutdown` HTTP endpoint permanently halts the signer's event loop - (File: libsigner/src/events.rs)

### Summary
`SignerEventReceiver::next_event` treats a bare `POST /shutdown` on its bound HTTP listener as equivalent to the internal `SignerStopSignaler::send()` call, setting the shared `stop_signal` atomic and returning `EventError::Terminated`, which causes `main_loop` to exit. There is no token, secret, or origin check distinguishing this control-plane request from any other TCP client that can reach the listening port, and the documented sample config binds the listener to `0.0.0.0`, i.e., non-loopback.

### Finding Description
The intended invariant is that only the signer's own process (via `SignerStopSignaler`, obtained internally from `get_stop_signaler()` after a signal handler or supervising code decides to terminate) can trigger a shutdown of the event-receiver loop. Instead, `next_event` implements this by listening for a plain, unauthenticated HTTP `POST /shutdown` request on the same TCP listener that receives StackerDB chunks, block proposals, and burn-block events from the node [5](#0-4) . Any TCP peer that can reach the bound address can send:
```
POST /shutdown HTTP/1.1
Host: <addr>
Connection: close
Content-Length: 0

```
and the handler unconditionally executes `event_receiver.stop_signal.store(true, Ordering::SeqCst); Err(EventError::Terminated)` without checking the request's source, headers, or any authentication material [6](#0-5) . This propagates to `EventReceiver::main_loop`, which matches `Err(EventError::Terminated)` and `break`s the loop, ending event processing for the entire signer [7](#0-6) . Every other handled route (`/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block`) similarly has no auth check at this layer either, but they only affect data ingestion; `/shutdown` uniquely offers a direct, single-message kill switch. The legitimate caller path, `SignerStopSignaler::send`, is just a convenience wrapper that opens a TCP connection to `self.local_addr` and issues the identical unauthenticated HTTP request [2](#0-1)  — it carries no secret, so an external attacker can forge the exact same bytes.

### Impact Explanation
Any remote TCP peer that can reach the signer's bound event-receiver port can send one `POST /shutdown` request to permanently stop that signer instance's event-processing loop, matching the "Critical - remote crash/unauthenticated DoS from few messages" category. Once stopped, the signer stops receiving StackerDB chunks, block proposals, and burn-block notifications from the node, effectively taking that signer offline until manually restarted; this is repeatable against every restart if the port remains reachable. The sample configuration for the signer binary explicitly documents binding the listener to `0.0.0.0:30000` rather than loopback [3](#0-2) , and the codebase itself carries a runtime warning acknowledging the risk of exposing the endpoint beyond a trusted local network [8](#0-7) .

### Likelihood Explanation
The only precondition is bare TCP reachability to the bound listener socket, which per the shipped sample config is `0.0.0.0:<port>` (not restricted to loopback) [3](#0-2) . No credentials, StackerDB slot ownership, or any privileged role are required — the attacker cost is a single raw HTTP POST, and the action is trivially repeatable against every future restart of the signer as long as the port stays reachable.

### Recommendation
Gate the `/shutdown` route (and ideally all control-plane routes) behind the same authentication mechanism already used for other privileged operations (e.g., a shared secret/auth token compared via constant-time comparison), or bind the event-receiver listener to loopback only and require any remote shutdown signal to be relayed through an authenticated channel. At minimum, require a token known only to the process/operator invoking `get_stop_signaler`/`SignerStopSignaler::send`, checked inside `next_event` before honoring `/shutdown`.

### Proof of Concept
Rust test in `libsigner::events::tests` (or an integration test) that:
1. Constructs a `SignerEventReceiver<T>`, calls `bind(addr)` with `addr = 127.0.0.1:0` (or an externally-reachable test interface to emulate remote reachability), and spawns `main_loop` in a thread with a channel consumer attached via `add_consumer`.
2. From a separate, unrelated `TcpStream::connect(addr)` (not via `SignerStopSignaler::send`), writes the raw bytes `"POST /shutdown HTTP/1.1\r\nHost: x\r\nConnection: close\r\nContent-Length: 0\r\n\r\n"`.
3. Joins the `main_loop` thread and asserts it returns (loop exited) within a bounded timeout, proving `next_event` returned `Err(EventError::Terminated)` at `libsigner/src/events.rs:443-445` and `main_loop` broke at `libsigner/src/events.rs:296-300`, despite the shutdown request never going through `get_stop_signaler`/`SignerStopSignaler::send`.
