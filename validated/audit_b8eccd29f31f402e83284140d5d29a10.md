### Title
Unauthenticated `recv_error` packet triggers unconditional tunnel teardown - (File: outside.go)

### Summary
`readOutsidePackets` dispatches `header.RecvError` packets to `handleRecvError` *before* any certificate-based authentication or decryption takes place [1](#0-0) . `handleRecvError` performs an unconditional, state-changing action — closing the tunnel and deleting the pending handshake — based solely on a 32-bit index match and a plaintext UDP source-address comparison, with no cryptographic proof that the sender holds the peer's CA-signed certificate [2](#0-1) .

### Finding Description
Similar to the `MarginTradingHook.refundNative` finding — where a side effect (unwrapping/sending native tokens) is executed unconditionally at the end of a call regardless of whether it is relevant to that call, letting an unrelated third party trigger a disruptive effect on someone else's flow — `handleRecvError` executes an unconditional, disruptive side effect (`f.closeTunnel(hostinfo)` plus `f.handshakeManager.DeleteHostInfo(hostinfo)`) purely as a result of receiving a `RecvError` packet type, gated only by:
1. `f.acceptRecvErrorConfig.ShouldRecvError(addr)` — a local policy check, not an authentication check.
2. `hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)` — a lookup keyed on the attacker-supplied `RemoteIndex` field from the packet header.
3. `hr.IsValid() && hr != addr` — a comparison against the plaintext, unauthenticated UDP source address recorded for that hostinfo.

Crucially, this entire path executes in `readOutsidePackets` in the block reserved for "Unencrypted packets" [3](#0-2) , i.e., before `hostinfo.ConnectionState.Decrypt` is ever invoked [4](#0-3) . There is no AEAD tag, no Noise handshake state, and no certificate check involved in this dispatch — an attacker without a CA-signed certificate can reach it as long as they can guess or observe a valid `RemoteIndex` (a 32-bit value transmitted in the clear on every packet header) and can send a UDP packet that appears to originate from the victim's currently-recorded remote address.

### Impact Explanation
Any party that is not a certificate holder for the mesh — reachable purely by crafting a bare header — can force `closeTunnel` on an arbitrary live tunnel and clear its pending handshake state, exactly mirroring the report's DOS class ("small/unrelated messages force a disruptive, unconditional side effect on someone else's session"). This is a remote state-poisoning / DOS primitive: it forcibly tears down established Nebula tunnels and pending handshakes without requiring the attacker to complete a handshake or present a valid certificate.

### Likelihood Explanation
Exploitability depends on two attacker capabilities: (1) guessing/observing the 32-bit `RemoteIndex` (feasible for an on-path or off-path attacker who has previously observed any packet from the target, since indexes are sent unencrypted in every header), and (2) making the packet appear to originate from the victim's recorded remote UDP address (trivial for on-path attackers, and for off-path attackers on networks that do not filter UDP source-address spoofing). The code comment `"Someone spoofing recv_errors?"` at `outside.go:565` [5](#0-4)  indicates the developers were aware address spoofing is a live threat model for this exact packet type, but the code only *logs* a message and returns when addresses mismatch — it does not add any cryptographic binding when they do match. This confirms likelihood is non-trivial in exactly the class the report identifies (dust/unrelated-input causing unconditional destructive side effects).

### Recommendation
Do not allow an unauthenticated, pre-decryption packet type to trigger destructive, unconditional state changes (`closeTunnel`/`DeleteHostInfo`) based solely on index + plaintext address matching. Options:
- Require `RecvError` handling to additionally validate a value that can only be produced/derived by a party holding the established Noise/cipher state for that hostinfo (e.g., a MAC over the error using an already-derived session key), rather than trusting index+source-address alone.
- Alternatively, treat `RecvError`-triggered closes as advisory only (e.g., speeding up re-handshake attempts) without deleting the existing hostinfo/pending handshake state outright, so a spoofed packet cannot fully sever a working tunnel.
- Continue defaulting `listen.send_recv_error` / `acceptRecvErrorConfig` to restrictive settings, and document clearly (as the CHANGELOG security note for #670 already does [6](#0-5) ) that enabling this feature trades off exposure to this exact spoofing/DOS class.

### Proof of Concept
1. Attacker (no CA cert) passively observes or otherwise learns a target's `remoteIndexId` value from any Nebula header on the wire (it is transmitted in cleartext in every packet, including `Test`/`Message` packets).
2. Attacker crafts a bare header-only UDP datagram with `Type = header.RecvError`, `RemoteIndex` set to the observed value, and sends it from a source address matching (or believed to match, e.g., if on-path or via spoofing) the victim's currently recorded remote address for that hostinfo.
3. `readOutsidePackets` routes the packet directly to `f.handleRecvError(via.UdpAddr, h)` without any decryption or certificate check [7](#0-6) .
4. `handleRecvError` finds the hostinfo via `QueryReverseIndex(h.RemoteIndex)`, confirms `hr == addr`, and unconditionally calls `f.closeTunnel(hostinfo)` and `f.handshakeManager.DeleteHostInfo(hostinfo)` [8](#0-7) , tearing down the victim's tunnel without any proof of certificate ownership.

func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
