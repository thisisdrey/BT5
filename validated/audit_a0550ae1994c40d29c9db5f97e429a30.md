### Title
Quadratic-time edge lookup in `internal/profile.Graph` construction enables CPU-exhaustion DoS on attacker-supplied pprof profiles - ([File: src/internal/profile/graph.go])

### Summary
`internal/profile`'s `NewGraph` builds a call graph from a parsed pprof profile by repeatedly calling `Node.AddToEdgeDiv`, which resolves the edge between two nodes via `EdgeMap.FindTo`, a **linear scan** over the node's existing out-edge slice. Just like `AttributesListener::findTargetAndDirection()` in league/commonmark walking the entire sibling list outward for every attribute node (Θ(N) per node, Θ(N²) overall), a profile whose samples cause one location to accumulate many distinct successor edges triggers an O(N) `FindTo` scan on every new edge insertion, giving Θ(N²) total cost for N distinct edges from a single node — driven entirely by attacker-controlled profile content, not by any legitimate program behavior size limit.

### Finding Description
An untrusted pprof profile (`.pprof` protobuf, gzip-optional) is decoded by `profile.Parse` (`src/internal/profile/profile.go:124`) into a `Profile` with `Sample`/`Location`/`Line` slices fully attacker-controlled. Tooling that visualizes or reports on such a profile (e.g. `go tool pprof`, or any service/tool built on `internal/profile`/`google/pprof` that accepts a profile file/URL from a user and renders a call graph) calls `NewGraph(prof, o)` in `src/internal/profile/graph.go:243`.

Inside `NewGraph`, for every sample and every consecutive pair of stack frames, `parent.AddToEdgeDiv(n, dw, w, residual, ...)` is invoked (`src/internal/profile/graph.go:291`). `AddToEdgeDiv` (`src/internal/profile/graph.go:93`) calls `n.Out.FindTo(to)`:

```go
func (em EdgeMap) FindTo(n *Node) *Edge {
	for _, e := range em {
		if e.Dest == n {
			return e
		}
	}
	return nil
}
```

`FindTo` scans the entire `EdgeMap` slice — unconditionally, with no size cap, exactly mirroring the sibling-walk in the CommonMark advisory. If an attacker crafts a profile where one `Location`/parent node is followed (across many distinct samples) by a large number of *distinct* destination locations, each insertion into that node's `Out` `EdgeMap` requires scanning all previously inserted edges before appending a new one (`em.Add` at line 107-108, called after a failed `FindTo`). Building up M distinct out-edges on one node thus costs Θ(M²), not Θ(M). This is unconditional — there is no allow-list, cap, or hardening comparable to what would gate the walk.

### Impact Explanation
This is a CPU-exhaustion (algorithmic complexity) denial-of-service: a maliciously constructed but structurally valid pprof profile, small in encoded size, can force `NewGraph` to spend quadratic time relative to the number of distinct call edges fanning out from a single location, hanging any tool or service (pprof visualization backends, profile-analysis dashboards) that parses and graphs untrusted profiles. It is availability-only (no confidentiality/integrity impact), matching CWE-407 in the source advisory. Under Go's security triage this would be a **PUBLIC**-track algorithmic-complexity report rather than an urgent memory-safety/RCE issue.

### Likelihood Explanation
The victim workflow is: a user (or automated tool) obtains a profile from an untrusted or semi-trusted source (a shared `.pprof` file, an uploaded profile in a continuous-profiling dashboard, or a profile fetched from a remote URL via `go tool pprof http://...`) and runs it through graph construction to render a report or flame graph. No special privileges are required by the attacker — they only need to supply the profile bytes, which is analogous to "ordinary user data" or a "published artifact consumed by a normal victim workflow." The likelihood is bounded mainly by how the encoded profile is delivered to a victim (email attachment, download link, profile-sharing service), which is a normal, low-friction distribution path.

### Recommendation
Replace the linear `EdgeMap.FindTo` scan with an O(1) map lookup keyed by destination `*Node` (e.g., maintain `map[*Node]*Edge` alongside/instead of the `[]*Edge` slice for `Out`/`In`), so that `AddToEdgeDiv` resolves and inserts edges in amortized O(1) regardless of fan-out size. Additionally, `NewGraph`/`profile.Parse` callers that accept untrusted profiles should bound the number of distinct locations/samples processed before graph construction.

### Proof of Concept
```go
package profile

import (
	"testing"
	"time"
)

// TestNewGraph_QuadraticEdgeLookup demonstrates that FindTo's linear scan
// makes edge-map construction quadratic in the number of distinct
// successor edges fanning out from a single node, all driven by
// attacker-supplied Sample/Location data.
func TestNewGraph_QuadraticEdgeLookup(t *testing.T) {
	const n = 6000 // distinct callee locations from one "parent" location

	prof := &Profile{
		SampleType: []*ValueType{{Type: "samples", Unit: "count"}},
	}

	// One shared "hub" location that will accumulate n distinct out-edges.
	hub := &Location{ID: 1, Line: []Line{{Function: &Function{Name: "hub"}}}}
	prof.Location = append(prof.Location, hub)

	for i := 0; i < n; i++ {
		leaf := &Location{
			ID:   uint64(i + 2),
			Line: []Line{{Function: &Function{Name: "leaf"}}}, // distinct Function per leaf forces distinct Node
		}
		leaf.Line[0].Function.Name = "leaf" + string(rune(i)) // ensure distinct NodeInfo
		prof.Location = append(prof.Location, leaf)

		// Each sample walks hub -> leaf, creating one new distinct out-edge
		// from hub's Node, forcing FindTo to scan an ever-growing slice.
		prof.Sample = append(prof.Sample, &Sample{
			Location: []*Location{leaf, hub}, // last-two-frames edge: hub -> leaf
			Value:    []int64{1},
		})
	}

	opt := &Options{SampleValue: func(v []int64) int64 { return v[0] }}

	start := time.Now()
	NewGraph(prof, opt)
	elapsed := time.Since(start)

	// With O(1) edge lookup this completes quickly; the quadratic FindTo
	// scan makes it take substantially longer as n grows. This assertion
	// documents the expected (buggy) quadratic blow-up threshold.
	if elapsed > 2*time.Second {
		t.Fatalf("NewGraph took %v for %d distinct out-edges from one node; "+
			"quadratic EdgeMap.FindTo scan suspected", elapsed, n)
	}
}
```
