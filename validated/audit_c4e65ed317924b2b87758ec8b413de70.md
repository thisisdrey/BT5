### Title
Signer event-receiver HTTP endpoint accepts unauthenticated `BlockValidateResponse` / StackerDB-chunk events from any TCP peer, letting an attacker who can reach the port forge node-validation results and signer messages - (File: `libsigner/src/events.rs`)

### Summary
`SignerEventReceiver::bind`/`next_event` opens a plain `tiny_http` server and dispatches on URL path (`/proposal_response`, `/stackerdb_chunks`, `/new_burn_block`, `/new_block`) with **no authentication of the caller** — no shared secret, no TLS client cert, no peer-address allow-list. The protocol *assumes* the only party that will ever POST to this socket is the local trusted stacks-node event dispatcher, but it never verifies that assumption, analogous to the report's pattern of "protocol assumes X pays/holds the bond but never checks that X actually is the one."

### Finding Description
`SignerEventReceiver::bind()` just starts an `HttpServer::http(listener)` with no auth layer: [1](#0-0) 

`next_event()` dispatches purely by URL, and any of these routes is processed for *any* connecting client: [2](#0-1) 

`process_event` deserializes the raw POST body straight into the target event type and converts it into a `SignerEvent`, with zero verification that the sender is the stacks node: [3](#0-2) 

The `/proposal_response` route feeds directly into `SignerEvent::BlockValidationResponse(BlockValidateResponse)`, which downstream signer logic treats as *the node's authoritative verdict* on whether a proposed block is valid — but nothing ties this HTTP request to the actual node process. The code comment in `stacks-signer/src/lib.rs` even acknowledges the risk explicitly: [4](#0-3) 

For the `/stackerdb_chunks` route, `TryFrom<StackerDBChunksEvent> for SignerEvent<T>` recovers a public key from whatever signature is attached to a chunk (`chunk.recover_pk()`), which always succeeds for a well-formed 65-byte signature (ECDSA recovery does not fail on a "wrong" signer — it simply returns whichever key would satisfy that signature): [5](#0-4) 

This is by itself not exploitable for the miner-message lane because downstream consumers re-derive/re-check the expected signer (e.g., `stackerdb_listener.rs` looks up the known `signer_entries` by `slot_id` rather than trusting the embedded pk), so that particular sub-path is not directly forgeable. The genuinely unauthenticated, high-impact surface is `BlockValidateResponse` injection via `/proposal_response`, since there is no independent secondary check comparable to the `signer_entries` lookup used for stackerdb messages — the signer's runloop consumes the `BlockValidationResponse` event as coming from the node.

### Impact Explanation
An unauthenticated attacker capable of establishing a TCP connection to the signer's event-receiver bind address can POST a forged JSON body to `/proposal_response` claiming a malicious or invalid block was validated as `Valid` by the node. Since the signer's runloop uses this event to decide whether to countersign a block proposal, this can induce a signer to sign a block that was never actually validated by the local node — an unauthenticated write into signer decision state and a potential path to propagating an improperly-validated ("non-canonical") block as if it were canonical/valid. This satisfies the High/Critical bar of "unauthenticated/unauthorized write to state" feeding directly into signature/consensus-adjacent decisions.

### Likelihood Explanation
Exploitability depends entirely on network exposure of the signer's bind address: if the signer binds to `127.0.0.1` and the node/signer run in a trust boundary that no external attacker can reach, this is not remotely exploitable. However, the endpoint performs no authentication regardless of configuration, so any misconfiguration (binding to a non-loopback interface, container/network setups exposing the port, or an attacker who has landed on the same host/network segment) is sufficient — and the code's own warning (`stacks-signer/src/lib.rs:125-132`) confirms this is a recognized, non-theoretical operational risk rather than merely a best-practice nitpick.

### Recommendation
Add authentication to the event-receiver HTTP path — e.g., a shared secret/HMAC header or mTLS between the stacks-node event dispatcher and the signer's event receiver — and reject/verify the source, rather than relying solely on network-layer trust. At minimum, `BlockValidateResponse` events should be bound to a specific in-flight request (e.g., correlated by a nonce/request id issued by the signer when it submitted the proposal for validation) so an unsolicited POST cannot be accepted as a valid verdict.

### Proof of Concept
1. Start a `stacks-signer` instance with its event-receiver bound to an address reachable by the attacker (e.g., non-loopback interface, or same host as another compromised process).
2. From an unauthenticated client, send:
   ```
   POST /proposal_response HTTP/1.1
   Host: <signer-endpoint>
   Content-Type: application/json
   Content-Length: <n>

   { ... forged BlockValidateResponse JSON claiming a chosen block is Valid ... }
   ```
3. Observe (via `process_event::<T, BlockValidateResponse>` in `libsigner/src/events.rs`) that the body is deserialized and converted into `SignerEvent::BlockValidationResponse` and forwarded to the signer runloop with no verification that it originated from the local node, as shown at `libsigner/src/events.rs:413-458` and `519-542`.

    fn next_event(&mut self) -> Result<SignerEvent<T>, EventError> {
        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)
            } else if request.url() == "/new_block" {
                process_event::<T, StacksBlockEvent>(request)
            } else {
                let url = request.url().to_string();
                debug!(
                    "[{:?}] next_event got request with unexpected url {}, return OK so other side doesn't keep sending this",
                    event_receiver.local_addr,
                    url
                );
                ack_dispatcher(request);
                Err(EventError::UnrecognizedEvent(url))
            }
        })?

fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}
