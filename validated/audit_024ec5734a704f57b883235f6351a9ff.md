### Title
`collateral-remove` skips all health checks when a user's outstanding debt is filtered out by the enabled-asset mask - ([File: mainnet/contracts/market/v0-4-market.clar])

### Summary
`canHedge()` in the referenced report becomes unreliable because it derives "current" state from an incomplete view (ignoring pending position requests), leading to a wrong pass/fail decision on a safety gate. The same bug class exists in Zest's `collateral-remove`: the "does this account have debt" decision is derived from a position view that is filtered to only *enabled* assets, not the account's full/actual debt. If the account's only debt happens to sit in a disabled debt asset, the filtered view reports zero debt, and the function takes the branch that skips all price resolution and health checks entirely.

### Finding Description
In `collateral-remove`, the account's position is fetched via the enabled-only helper and used to decide whether any health checking is required at all: [1](#0-0) 

```
(position (try! (get-position account)))
(has-debt (> (len (get debt position)) u0))
```

`get-position` explicitly restricts the returned position to the **enabled bitmap**, not the account's full debt/collateral state: [2](#0-1) 

```
(define-private (get-position (account principal)) ;; enabled only
  (let ((mask (get-enabled-bitmap)))
    (contract-call? .market-vault get-position account mask)))

(define-private (get-full-position (account principal)) ;; all collaterals
  (contract-call? .market-vault get-position account MAX-U64))
```

`collateral-remove` then branches entirely on `has-debt`: [3](#0-2) 

- If `has-debt` is `true`, it accrues, resolves prices, computes collateral/debt USD, and asserts `is-healthy` both pre- and post-removal.
- If `has-debt` is `false` ("NO DEBT: Skip price resolution entirely"), it calls `market-vault collateral-remove` directly with **no health check at all**, matching the test's documented expectation that "no debt = no health check": [4](#0-3) 

The problem: `has-debt` is computed from the *enabled-asset-filtered* position, not the account's real, full debt (`get-full-position`, using `MAX-U64`). Any asset that has been administratively disabled for the market (via the asset registry's enabled bitmap) is excluded from `get-position`'s debt list even though the account's actual scaled-debt balance for that asset in `market-vault` is untouched. If a borrower's only outstanding debt is denominated in an asset that is subsequently disabled, `has-debt` evaluates to `false`, and `collateral-remove` takes the "NO DEBT" branch — allowing the borrower to withdraw **all** collateral with zero health verification while a real, unrepaid debt still exists in `market-vault`.

This mirrors the report's root cause exactly: a security-critical branch decision (`canHedge` / `has-debt`) is computed from a partial/stale view of state (ignoring the pending increase/decrease request / ignoring debt masked out by the enabled bitmap) rather than the complete, authoritative state (`get-full-position` / including the pending request), producing an incorrect gating decision.

### Impact Explanation
If the health-check bypass is reachable, a borrower can strip all collateral backing an existing debt, leaving the vault with unbacked debt (bad debt) that must eventually be socialized against suppliers. This is theft of/at protocol insolvency risk to LP funds at rest, since debt remains outstanding with no collateral to seize on liquidation — landing on the Critical impact class (protocol insolvency / theft of user funds at rest via unbacked debt).

### Likelihood Explanation
This requires only two ordinary conditions: (1) a debt asset later gets its enabled flag toggled off in the asset registry (a normal, sanctioned DAO/admin lifecycle action, not a compromise), and (2) an existing borrower whose only debt is in that asset calls the unprivileged, public `collateral-remove` entry point. No DAO compromise, oracle manipulation, or privileged action by the attacker is needed — the attacker is an ordinary principal exploiting the mismatch between the enabled-mask-filtered `has-debt` flag and the account's true debt state tracked in `market-vault`.

### Recommendation
Compute `has-debt` (and any other decision that gates whether health checks run) from the account's full, unfiltered debt state (`get-full-position` / `MAX-U64` mask) rather than the enabled-only `get-position`. If an asset is disabled, its outstanding debt must still be counted for the purpose of deciding whether to run health checks and for computing debt-value in that check, exactly as the report recommended including the pending request in `canHedge`'s hedge calculation.

### Proof of Concept
1. Borrower deposits sBTC as collateral and borrows against `USDH` (an asset currently enabled) via `borrow`.
2. DAO/admin later disables `USDH` in the asset registry (removing it from `get-enabled-bitmap`) — a normal governance action, e.g. to sunset an asset.
3. Borrower calls `collateral-remove` for their sBTC collateral. `get-position` returns a position with `debt: []` because `USDH` debt is filtered out by the disabled-asset mask, so `has-debt` is `false`.
4. `collateral-remove` takes the "NO DEBT" branch (line 1163-1169 in `v0-4-market.clar`), skipping all price resolution and `is-healthy` checks, and calls `market-vault collateral-remove` directly, releasing 100% of the sBTC collateral to the borrower.
5. The borrower now holds a fully unsecured `USDH` debt in `market-vault`, which is never repaid — resulting in bad debt for the `USDH` vault's suppliers.

(define-public (collateral-remove (ft <ft-trait>) (amount uint) (receiver (optional principal)) (price-feeds (optional (list 3 (buff 8192)))))
  (let ((ft-address (contract-of ft))
        (asset (try! (get-asset ft-address)))
        (asset-id (get id asset))
        (account contract-caller)
        (collateral-receiver (match receiver recv recv contract-caller))
        (position (try! (get-position account)))
        (has-debt (> (len (get debt position)) u0)))

    (asserts! (> amount u0) ERR-AMOUNT-ZERO)

    (if has-debt
        ;; HAS DEBT: Full flow with price resolution and health checks
        (let ((is-collateral-enabled (get collateral asset))
              (feeds-check (try! (write-feeds price-feeds)))
              (position-mask (get mask position))
              (pos-full (if is-collateral-enabled position (try! (get-full-position account))))
              (u-debt (accrue-user-debts (get debt pos-full)))
              (u-coll (accrue-user-collateral (get collateral pos-full)))
              (assets (get-assets position-mask))
              (curr-coll-aid (find-collateral-amount (get collateral position) asset-id))
              (removing-all (is-eq amount curr-coll-aid))
              (current-group (try! (get-egroup position-mask)))
              (current-ltvb (buff-to-uint-be (get LTV-BORROW current-group)))
              (notional-valued-assets (get-notional-evaluation { position: position, assets: assets }))
              (collateral-value (get collateral notional-valued-assets))
              (debt-value (get debt notional-valued-assets))
              (removed-asset-value (find-and-resolve-asset-value assets asset-id amount true)))

          (asserts! (is-healthy collateral-value debt-value current-ltvb) ERR-UNHEALTHY)
          (asserts!
            (if is-collateral-enabled
                (let ((t (asserts! (>= collateral-value removed-asset-value) ERR-INSUFFICIENT-COLLATERAL))
                      (post-removal-collateral-value (- collateral-value removed-asset-value)))
                  (if removing-all
                      (let ((future-mask (bit-and position-mask (bit-not (pow u2 asset-id)))))
                        (try! (is-healthy-with-mask post-removal-collateral-value debt-value future-mask)))
                      (is-healthy post-removal-collateral-value debt-value current-ltvb)))
                (let ((oracle-data (get oracle asset))
                      (price (unwrap! (price-resolve oracle-data) ERR-DISABLED-COLLATERAL-PRICE-FAILED))
                      (decimals (get decimals asset))
                      (user-amount (find-collateral-amount (get collateral pos-full) asset-id))
                      (disabled-notional (normalize (* user-amount price) decimals false))
                      (removal-notional (normalize (* amount price) decimals true))
                      (total-collateral-value (+ collateral-value disabled-notional)))
                  (asserts! (>= total-collateral-value removal-notional) ERR-INSUFFICIENT-COLLATERAL)
                  (is-healthy (- total-collateral-value removal-notional) debt-value current-ltvb)))
            ERR-UNHEALTHY)

          (let ((result (try! (contract-call? .v0-market-vault collateral-remove account amount ft asset-id collateral-receiver))))
            (print { action: "collateral-remove", caller: contract-caller,
                     data: { account: account, receiver: collateral-receiver, asset-id: asset-id,
                             asset-addr: ft-address, amount: amount, updated-collateral-amount: result,
                             position-collateral-usd: collateral-value, position-debt-usd: debt-value }})
            (ok result)))

        ;; NO DEBT: Skip price resolution entirely
        (let ((result (try! (contract-call? .v0-market-vault collateral-remove account amount ft asset-id collateral-receiver))))
          (print { action: "collateral-remove", caller: contract-caller,
                   data: { account: account, receiver: collateral-receiver, asset-id: asset-id,
                           asset-addr: ft-address, amount: amount, updated-collateral-amount: result,
                           position-collateral-usd: u0, position-debt-usd: u0 }})
          (ok result)))))
