### Title
Push-Payment Distribution Permanently Freezes Staker APT When Operator Sets Unregistered/Opted-Out Beneficiary — (`File: aptos-move/framework/aptos-framework/sources/staking_contract.move`)

---

### Summary

`staking_contract::distribute_internal()` pushes APT directly to every recipient in the distribution pool via `aptos_account::deposit_coins`. The operator's commission share is redirected to whatever address the operator registered via `set_beneficiary_for_operator`. That setter performs **no validation** that the beneficiary can actually receive APT. If `deposit_coins` aborts for the beneficiary, the entire distribution transaction reverts, permanently trapping the staker's unlocked stake inside the contract.

`vesting::distribute()` has the identical push-payment loop and the identical risk for initial shareholders, who are also never validated at contract-creation time.

---

### Impact Explanation

**Permanent freezing of APT staking / vesting balances.**

Once `distribute_internal` reverts, the unlocked coins remain inside the staking contract's stake pool. There is no escape hatch: the staker cannot call `distribute` successfully, cannot switch operators (which internally calls `distribute_internal`), and cannot recover their principal. All APT that has been unlocked from the stake pool is permanently inaccessible.

For `vesting::distribute`, a single blocked shareholder (or their beneficiary) causes the entire distribution to revert, freezing every other shareholder's vested APT as well.

---

### Likelihood Explanation

**Staking contract path — operator-triggered, unprivileged:**

1. Operator calls `set_beneficiary_for_operator(operator, bad_addr)` where `bad_addr` has previously called `set_allow_direct_coin_transfers(false)` and does not hold a legacy `CoinStore<AptosCoin>` (possible for accounts created after the FA migration that never registered the old coin store).
2. Anyone calls `staking_contract::distribute(staker, operator)`.
3. `deposit_coins(bad_addr, commission)` aborts → entire tx reverts.
4. Staker's unlocked APT is permanently frozen.

The operator is an unprivileged on-chain actor; no governance or admin key is required. The staker has no recourse once the beneficiary is set to a blocking address.

**Vesting contract path — shareholder-triggered:**

A shareholder who was enrolled at contract creation can call `set_allow_direct_coin_transfers(false)` at any time after enrollment. On the next `distribute()` call their share of coins cannot be deposited, reverting the entire distribution for all shareholders.

---

### Recommendation

1. **`staking_contract::set_beneficiary_for_operator`**: Add the same guard already present in `vesting::set_beneficiary`:
   ```move
   aptos_account::assert_account_is_registered_for_apt(new_beneficiary);
   ``` [1](#0-0) 

2. **`vesting::create_vesting_contract`**: Validate each shareholder address for APT registration at contract creation, mirroring the check already applied to `withdrawal_address`. [7](#0-6) 

3. **Long-term (pull-payment pattern)**: Credit unlocked coins to an internal ledger keyed by recipient address; let each recipient claim their own share. This eliminates the single-point-of-failure in the push loop and is the exact mitigation recommended in the original Sherlock report.

---

### Proof of Concept

```
// Setup
1. staker creates staking contract with operator, 100 APT, 10% commission
2. operator joins validator set; stake earns rewards → pool = 110 APT
3. operator calls request_commission → 1 APT unlocked for operator
4. stake::fast_forward_to_unlock(pool_address)

// Attack
5. operator calls set_beneficiary_for_operator(operator, @bad_addr)
   where @bad_addr has:
     - called set_allow_direct_coin_transfers(false)
     - no CoinStore<AptosCoin> (FA-only account)

// Trigger
6. anyone calls staking_contract::distribute(staker_addr, operator_addr)
   → distribute_internal() enters while loop
   → recipient = beneficiary_for_operator(operator) = @bad_addr
   → deposit_coins(@bad_addr, 1 APT)
       → coin::is_account_registered<AptosCoin>(@bad_addr) == false
       → can_receive_direct_coin_transfers(@bad_addr) == false
       → ABORT: EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS
   → entire tx reverts; staker's 109 APT permanently frozen in stake pool
``` [8](#0-7) [9](#0-8)

    public entry fun set_beneficiary_for_operator(
        operator: &signer, new_beneficiary: address
    ) acquires BeneficiaryForOperator {
        assert!(
            features::operator_beneficiary_change_enabled(),
            std::error::invalid_state(EOPERATOR_BENEFICIARY_CHANGE_NOT_SUPPORTED)
        );
        // The beneficiay address of an operator is stored under the operator's address.
        // So, the operator does not need to be validated with respect to a staking pool.
        let operator_addr = signer::address_of(operator);
        let old_beneficiary = beneficiary_for_operator(operator_addr);
        if (exists<BeneficiaryForOperator>(operator_addr)) {
            borrow_global_mut<BeneficiaryForOperator>(operator_addr).beneficiary_for_operator =
                new_beneficiary;
        } else {
            move_to(
                operator,
                BeneficiaryForOperator { beneficiary_for_operator: new_beneficiary }
            );
        };

        emit(
            SetBeneficiaryForOperator {
                operator: operator_addr,
                old_beneficiary,
                new_beneficiary
            }
        );
    }
