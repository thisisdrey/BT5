### Title
Yield from rebasing/appreciating LST underlyings (stSTX, stSTXbtc) is not captured by vault accounting once borrowed - lenders miss the accrued gains - (File: `mainnet/contracts/vault/v0-vault-ststx.clar`, `mainnet/contracts/vault/v0-vault-ststxbtc.clar`)

### Summary
The `vault-ststx` and `vault-ststxbtc` reserves wrap liquid-staking-derivative tokens (`ststx-token`, `ststxbtc-token-v2`) whose value/balance grows over time from staking rewards. The vault's share-price math (`total-assets`, `convert-to-shares-preview`, `convert-to-assets-preview`) is driven entirely by an internally tracked `assets` variable and a protocol-set interest-rate index, completely decoupled from the actual underlying token balance (`ubalance`). Any yield the underlying token accrues while it sits in a borrower's wallet after `system-borrow` is never reflected back into the vault's `assets`/index accounting, so lenders never receive it - the same root cause identified in the Sentiment M-5 report (shares/debt tracked as fixed amounts, independent of the actual token balance changes that occur in the holder's account).

### Finding Description
The vault tracks value purely through an internal ledger: [1](#0-0) 

`ubalance()` (the actual on-chain balance of the underlying held by the vault) is defined but is not used to compute `total-assets`, `get-available-assets`, or share conversion: [2](#0-1) [3](#0-2) 

When a market contract borrows on behalf of a user via `system-borrow`, the underlying asset is transferred out to `receiver` (the borrowing user's own address), and the debt owed is tracked solely via `principal-scaled`/`index`, unrelated to the actual behavior of the token once outside the vault: [4](#0-3) 

Repayment (`system-repay`) likewise computes `capped-amount`/`principal-repaid`/`interest-paid` purely from the index-based debt formula, with no reconciliation against any appreciation the underlying token might have generated for the borrower while it was held in their wallet: [5](#0-4) 

Because `ststx-token` / `ststxbtc-token-v2` are liquid-staking-derivative tokens whose value accrues to whoever holds the balance (analogous to Aave's rebasing aTokens in the referenced report), any staking-reward growth that occurs on the borrowed tokens while they are in the borrower's wallet is captured entirely by the borrower. The vault's `index`/`assets` bookkeeping, which is the only source of yield for zstSTX/zstSTXbtc holders, is set by the protocol's own utilization-based interest curve and has no channel to receive that externally-accrued value. The lenders (zstSTX/zstSTXbtc holders) therefore permanently miss out on yield that should have accrued to the pool while the asset was on loan - exactly the "lender misses out on gains that accrued to the borrower's account" pattern from the referenced Sentiment finding.

### Impact Explanation
This is a theft of unclaimed yield (High): depositors of `vault-ststx`/`vault-ststxbtc` are entitled to appreciation on the underlying LST while it is deployed (whether idle in the vault or lent out), but the accounting model only ever credits interest computed from the protocol-set borrow curve. Value generated externally on the underlying token while held by a borrower is diverted away from lenders with no mechanism to reclaim it, resulting in permanent loss of yield to the vault's LPs.

### Likelihood Explanation
Likelihood is moderate-to-high for the affected LST vaults specifically: any ordinary user who opens a leveraged/borrow position sourced from `vault-ststx` or `vault-ststxbtc` and holds the borrowed tokens in their wallet (rather than immediately using them) benefits from any staking-reward accrual on that balance, at no cost beyond the protocol's stated borrow-interest rate. No special privileges, DAO compromise, or flashloans are required - a normal borrow call through the market contract is sufficient to reach this path.

### Recommendation
Do not treat LST underlyings whose value accrual is captured by the token balance itself (rather than purely by external market pricing observed via oracle) as ordinary fixed-value collateral for vault accounting purposes. If a rebasing/appreciating token's growth is not observable/oracle-priced, either (a) route all yield of the underlying strictly through the vault's own index (never transferring the actual yield-bearing token out to end-user wallets during borrow), or (b) periodically reconcile `assets`/`total-assets` against `ubalance()` and mint the resulting delta as index growth so that any externally-accrued appreciation is captured by the pool rather than by whichever address is currently holding the token.

### Proof of Concept
1. A user opens a debt position against `vault-ststx` through the market contract, which calls `system-borrow`, transferring `ststx-token` to the user's wallet. [6](#0-5) 
2. The user holds the `ststx-token` balance in their own wallet rather than immediately spending it. If `ststx-token` distributes staking rewards to holders (balance growth/appreciation independent of the vault's index), the user's holding of the borrowed token appreciates for free.
3. When the user eventually repays via `system-repay`, the debt owed is computed strictly from `principal-scaled`/`index`, with no term reflecting any extra value the token accrued while out of the vault. [5](#0-4) 
4. The vault's `assets`/`total-assets`, which solely determine zstSTX share price for lenders, never receive credit for that externally-accrued value, since neither `total-assets` nor `accrue` ever consult `ubalance()`. [1](#0-0) 

Note: full confirmation that `ststx-token`/`ststxbtc-token-v2` implement balance-increasing rebasing/appreciation (as opposed to pure market-price appreciation observed only via oracle) requires inspecting those external token contracts, which are out of the indexed production repo scope (`mainnet/contracts/**`) - they are referenced only by principal address in these vault files.

(define-public (system-repay (amount uint))
  (let (
        (states (var-get pause-states))
        (u (try! (accrue)))
        (scaled-principal (var-get principal-scaled))
        (idx (var-get index))
        (debt (total-debt))
        (total-borrowed-amount (var-get total-borrowed))
        (capped-amount (if (> amount debt) debt amount))
        (principal-reduction (calc-principal-ratio-reduction capped-amount scaled-principal debt))
        (capped-reduction (if (> principal-reduction scaled-principal) scaled-principal principal-reduction))
        (updated-scaled-principal (- scaled-principal capped-reduction))
        (principal-repaid (mul-div-down capped-amount total-borrowed-amount debt))
        (interest-paid (- capped-amount principal-repaid))
        (total-borrowed-new (if (> total-borrowed-amount principal-repaid) (- total-borrowed-amount principal-repaid) u0)))

    (try! (check-caller-auth))
    (asserts! (not (get repay states)) ERR-PAUSED)
    (asserts! (> amount u0) ERR-AMOUNT-ZERO)

    (try! (receive-underlying capped-amount tx-sender))
    (var-set principal-scaled updated-scaled-principal)
    (var-set total-borrowed total-borrowed-new)
    (var-set assets (+ (var-get assets) interest-paid))
