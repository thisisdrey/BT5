Confirmed: `Amounts::sub` uses `checked_sub` via `CheckedSub`, mutating the same in-memory map sequentially for every intent in the batch [1](#0-0) , and `Contract::internal_sub_balance` operates directly on `owner.token_balances` (the live account state, not a pre-batch snapshot), returning `DefuseError::BalanceOverflow` if the balance is insufficient at the time of each call [2](#0-1) . Since `Engine::execute_signed_intents` processes each `MultiPayload` sequentially against this same mutable state before finalizing [3](#0-2) , a second debit of the same `TokenId` in the same batch is checked against the balance *after* the first debit already applied — there is no stale-snapshot re-validation gap to exploit.

### Binding
`sum(internal_sub_balance debits for token T from owner O across the batch) == starting_balance(O, T) - final_balance(O, T)`, and per-withdraw, `used <= amount.0` (the amount already debited for that specific withdraw), so `sum(used across all *_resolve_withdraw settlements for T) <= sum(debits for T)`. Tracing both the debit path and the resolve path shows this holds:

- The `amount.0` passed into `ft_resolve_withdraw`/`mt_resolve_withdraw`/`nft_resolve_withdraw` is fixed at intent-execution time (before any promise is scheduled) and is exactly what was already subtracted via `withdraw()` → `internal_sub_balance` [4](#0-3) .
- In the resolver, `used` is always `.min(amount.0)` or capped at `amount.0`, and any unused portion is refunded back into the Verifier's own `token_balances` (re-credited), never exceeding what was debited [5](#0-4) .
- The `Err(_) => amount.0` branch cited in the prompt is the documented NEP-141 gas-insufficiency workaround: it assumes the transfer succeeded (no refund) rather than crediting the sender an extra refund on top of a transfer that may have actually gone through [6](#0-5) . This branch can only make `used == amount.0` (i.e., no re-credit), never `used > amount.0`. It cannot inflate assets released beyond what was already debited from the Verifier's ledger.
- The gas allocated to `ft_resolve_withdraw`/`mt_resolve_withdraw` (`FT_RESOLVE_WITHDRAW_GAS`, `mt_resolve_withdraw_gas(...)`) is a contract-defined constant, not attacker-supplied, so an unprivileged caller submitting a `MultiPayload` cannot control or reduce the gas given to the resolver callback [7](#0-6) .

Both sides of the equality match before and after: the sequential, in-place `checked_sub` prevents any double-debit within a batch, and each async withdraw's resolver can only settle for `<= amount.0` already reserved for it, with any shortfall refunded back to the Verifier ledger. No combination of intents in a single `MultiPayload` batch, and no gas-starvation of the resolver (which the attacker cannot control), produces `sum(used) > sum(debited)`.

### No vulnerability found for this question.

The premise that `internal_sub_balance` relies on a "stale snapshot" is incorrect — it operates on live, sequentially-updated account state within the batch, so conservation across the batch is enforced at debit time, and the resolver-side gas-insufficiency fallback cannot release more than was already debited.

    fn internal_sub_balance(
        &mut self,
        owner_id: &AccountIdRef,
        tokens: impl IntoIterator<Item = (TokenId, u128)>,
    ) -> Result<()> {

            .get_mut()
            .ok_or_else(|| DefuseError::AccountLocked(owner_id.to_owned()))?;

            if amount == 0 {
                return Err(DefuseError::InvalidIntent);
            }

            owner
                .token_balances
                .sub(token_id.clone(), amount)
                .ok_or(DefuseError::BalanceOverflow)?;
        }

        Ok(())
    }

    fn execute_signed_intent(&mut self, signed: MultiPayload) -> Result<()> {
        // verify signed payload and get public key
        let public_key = signed.verify().ok_or(DefuseError::InvalidSignature)?;

        // calculate intent hash
        let hash = signed.hash();

        // extract NEP-413 payload
        let DefusePayload::<DefuseIntents> {
            signer_id,
            verifying_contract,
            deadline,
            nonce,
            message: intents,
        } = signed.extract_defuse_payload()?;

        // check recipient
        if verifying_contract != *self.state.verifying_contract() {
            return Err(DefuseError::WrongVerifyingContract);
        }

        self.inspector.on_deadline(deadline);

        // make sure message is still valid
        if deadline < Timestamp::now() {
            return Err(DefuseError::DeadlineExpired);
        }

        // make sure the account has this public key
        if !self.state.has_public_key(&signer_id, &public_key) {
            return Err(DefuseError::PublicKeyNotExist(signer_id, public_key));
        }

        // commit nonce
        self.verify_intent_nonce(nonce, deadline)?;
        self.state.commit_nonce(signer_id.clone(), nonce)?;

        intents.execute_intent(&signer_id, self, hash)?;
        self.inspector.on_intent_executed(&signer_id, hash, nonce);

        Ok(())
    }

    fn ft_resolve_withdraw(
        &mut self,
        token: AccountId,
        sender_id: AccountId,
        amount: U128,
        is_call: bool,
    ) -> U128 {
        let used = if is_call {
            // `ft_transfer_call` returns successfully transferred amount
            match promise_result_checked_json::<U128>(0) {
                Ok(Ok(used)) => used.0.min(amount.0),
                Ok(Err(_deserialize_err)) => 0,
                // do not refund on failed `ft_transfer_call` due to
                // NEP-141 vulnerability: `ft_resolve_transfer` fails to
                // read result of `ft_on_transfer` due to insufficient gas
                Err(_) => amount.0,
            }
        } else {
            // `ft_transfer` returns empty result on success
            if promise_result_checked_void(0).is_ok() {
                amount.0
            } else {
                0
            }
        };

        let refund = amount.0.saturating_sub(used);
        if refund > 0 {
            self.deposit(
                sender_id,
                [(Nep141TokenId::new(token).into(), refund)],
                Some(REFUND_MEMO),
            )
            .unwrap_or_else(|err| err.panic());
        }

        U128(used)
    }
