Audit Report

## Title
Fee-calculation rounding lets Snowbridge outbound messages be dispatched to Ethereum with a zero remote-fee charge - ([File: bridges/snowbridge/pallets/outbound-queue/src/lib.rs])

## Summary
`Pallet::<T>::calculate_fee` computes the remote (Ethereum-side) fee component by chaining two floor-division operations — `checked_div(&params.exchange_rate)` and the `checked_div(denom)` inside `convert_from_ether_decimals` — when converting an ether-denominated wei amount into native DOT/KSM decimals. [1](#0-0) [2](#0-1)  This truncation can drive the collected `fee.remote` to zero while the message is still enqueued via `SendMessage::validate`, which uses whatever `calculate_fee` returns with no minimum-fee floor or zero-fee rejection, and `do_process_message` unconditionally commits a nonzero `reward` obligation to the message dispatched to Ethereum regardless of what was actually collected. [3](#0-2) [4](#0-3) 

## Finding Description
The pallet's own regression test demonstrates the exact defect: with non-zero `exchange_rate = 1/1`, `fee_per_gas = 1`, `reward = 1`, `multiplier = 1/1`, and `gas_used = 250000`, `calculate_fee` returns `fee.remote == 0`, and the test's own comment states this is "invalid ... which should be avoided." [5](#0-4)  There is no guard anywhere in `validate` or `calculate_fee` that rejects or floors a zero remote fee before the message is queued and later committed with a real `reward` promise via `do_process_message`. [6](#0-5) 

However, whether this is practically triggerable depends entirely on governance-configured `PricingParameters` (`exchange_rate`, `fee_per_gas`, `rewards.remote`, `multiplier`), which are set via `EthereumSystem`/governance, not by an unprivileged caller. Looking at the actual Rococo bridge-hub runtime configuration, the deployed defaults are far from the pathological test values: `exchange_rate = 1/400`, `fee_per_gas = gwei(20)`, `rewards = { local: 1 * UNITS, remote: meth(1) }`, `multiplier = 1/1`, with `Decimals = 12`. [7](#0-6)  Under these realistic, non-degenerate parameters, the numerator (`gas * fee_per_gas + reward`, on the order of `meth(1)` = 10^15 wei plus gas costs) divided by `exchange_rate` (1/400) and then by `10^6` (`ETHER_DECIMALS(18) - Decimals(12)`) does not trivially collapse to zero — the test's zero-fee scenario requires an artificially degenerate combination (`exchange_rate=1`, `fee_per_gas=1`, `reward=1`) that is not representative of any pricing parameters actually configured in-repo for a live bridge-hub runtime.

An unprivileged sender cannot set `exchange_rate`, `fee_per_gas`, or `rewards.remote` themselves — these are governance/root-controlled via `snowbridge_pallet_system`. The claim's exploit path therefore requires governance to have already misconfigured pricing parameters into a degenerate range; it is not something an ordinary user can trigger purely through public extrinsics against the values actually shipped in this repository's runtimes. The rounding defect is real and acknowledged by the pallet's own test as an "invalid" outcome that "should be avoided," but reaching it in production requires the pricing parameters themselves to already be in a state that produces near-zero fees — a governance-configuration precondition, not a bug an external, unprivileged attacker can independently manufacture.

## Impact Explanation
The underlying arithmetic defect (floor-division across an 8-order-of-magnitude decimals gap without a ceiling-round or minimum-fee floor) is a genuine, acknowledged code smell in `calculate_fee`/`convert_from_ether_decimals`, and could in principle allow underpriced dispatches if governance ever configures pricing parameters into the degenerate range demonstrated by the pallet's own test. That said, given the actual pricing parameters configured for the bridge-hub runtimes in this repository, the truncation-to-zero condition is not reachable by an ordinary unprivileged sender under realistic governance-set values, so this does not currently constitute an attacker-triggerable exploit within the scope of "public underpriced work" absent a separate governance misconfiguration, which the validation rules require to be excluded as a root cause.

## Likelihood Explanation
Low under the actual repository-configured pricing parameters; the degenerate values needed to zero out `fee.remote` (`exchange_rate=1/1`, `fee_per_gas=1`, `reward=1`) do not match any pricing parameters set in the bridge-hub runtime configs reviewed in this repository. Triggering the bug in production would require governance to first misconfigure `PricingParameters` into a degenerate range, which is a privileged-governance precondition explicitly out of scope per the validation rules ("privileged governance or admin abuse as the root cause" is to be discarded).

## Recommendation
Independent of scope determination, it would still be good practice to make `calculate_fee` and `convert_from_ether_decimals` ceiling-divide (or explicitly reject) rather than floor-divide, and add an `ensure!(fee.remote > 0)` / minimum-fee floor in `validate`, to make the fee model robust even against future or accidental pricing-parameter misconfiguration.

## Proof of Concept
The pallet's own unit test `test_calculate_fees_with_valid_exchange_rate_but_remote_fee_calculated_as_zero` reproduces the zero-fee outcome under degenerate parameters. [5](#0-4)  No equivalent reproduction exists using the pricing parameters actually configured for a live bridge-hub runtime in this repository. [8](#0-7)

		pub(crate) fn do_process_message(
			_: ProcessMessageOriginOf<T>,
			mut message: &[u8],
		) -> Result<bool, ProcessMessageError> {
			use ProcessMessageError::*;

			// Yield if the maximum number of messages has been processed this block.
			// This ensures that the weight of `on_finalize` has a known maximum bound.
			ensure!(
				MessageLeaves::<T>::decode_len().unwrap_or(0) <
					T::MaxMessagesPerBlock::get() as usize,
				Yield
			);

			// Decode bytes into versioned message
			let versioned_queued_message: VersionedQueuedMessage =
				VersionedQueuedMessage::decode(&mut message).map_err(|_| Corrupt)?;

			// Convert versioned message into latest supported message version
			let queued_message: QueuedMessage =
				versioned_queued_message.try_into().map_err(|_| Unsupported)?;

			// Obtain next nonce
			let nonce = <Nonce<T>>::try_mutate(
				queued_message.channel_id,
				|nonce| -> Result<u64, ProcessMessageError> {
					*nonce = nonce.checked_add(1).ok_or(Unsupported)?;
					Ok(*nonce)
				},
			)?;

			let pricing_params = T::PricingParameters::get();
			let command = queued_message.command.index();
			let params = queued_message.command.abi_encode();
			let max_dispatch_gas =
				T::GasMeter::maximum_dispatch_gas_used_at_most(&queued_message.command);
			let reward = pricing_params.rewards.remote;

			// Construct the final committed message
			let message = CommittedMessage {
				channel_id: queued_message.channel_id,
				nonce,
				command,
				params,
				max_dispatch_gas,
				max_fee_per_gas: pricing_params
					.fee_per_gas
					.try_into()
					.defensive_unwrap_or(u128::MAX),
				reward: reward.try_into().defensive_unwrap_or(u128::MAX),
				id: queued_message.id,
			};

			// ABI-encode and hash the prepared message
			let message_abi_encoded = ethabi::encode(&[message.clone().into()]);
			let message_abi_encoded_hash = <T as Config>::Hashing::hash(&message_abi_encoded);

			Messages::<T>::append(Box::new(message));
			MessageLeaves::<T>::append(message_abi_encoded_hash);

			Self::deposit_event(Event::MessageAccepted { id: queued_message.id, nonce });

			Ok(true)
		}

		/// Calculate total fee in native currency to cover all costs of delivering a message to the
		/// remote destination. See module-level documentation for more details.
		pub(crate) fn calculate_fee(
			gas_used_at_most: u64,
			params: PricingParameters<T::Balance>,
		) -> Fee<T::Balance> {
			// Remote fee in ether
			let fee = Self::calculate_remote_fee(
				gas_used_at_most,
				params.fee_per_gas,
				params.rewards.remote,
			);

			// downcast to u128
			let fee: u128 = fee.try_into().defensive_unwrap_or(u128::MAX);

			// multiply by multiplier and convert to local currency
			let fee = FixedU128::from_inner(fee)
				.saturating_mul(params.multiplier)
				.checked_div(&params.exchange_rate)
				.expect("exchange rate is not zero; qed")
				.into_inner();

			// adjust fixed point to match local currency
			let fee = Self::convert_from_ether_decimals(fee);

			Fee::from((Self::calculate_local_fee(), fee))
		}

		// 1 KSM has 12 digits of precision
		// 1 ETH has 18 digits of precision
		pub(crate) fn convert_from_ether_decimals(value: u128) -> T::Balance {
			let decimals = ETHER_DECIMALS.saturating_sub(T::Decimals::get()) as u32;
			let denom = 10u128.saturating_pow(decimals);
			value.checked_div(denom).expect("divisor is non-zero; qed").into()
		}

	fn validate(
		message: &Message,
	) -> Result<(Self::Ticket, Fee<<Self as SendMessageFeeProvider>::Balance>), SendError> {
		// The inner payload should not be too large
		let payload = message.command.abi_encode();
		ensure!(
			payload.len() < T::MaxMessagePayloadSize::get() as usize,
			SendError::MessageTooLarge
		);

		// Ensure there is a registered channel we can transmit this message on
		ensure!(T::Channels::contains(&message.channel_id), SendError::InvalidChannel);

		// Generate a unique message id unless one is provided
		let message_id: H256 = message
			.id
			.unwrap_or_else(|| unique((message.channel_id, &message.command)).into());

		let gas_used_at_most = T::GasMeter::maximum_gas_used_at_most(&message.command);
		let fee = Self::calculate_fee(gas_used_at_most, T::PricingParameters::get());

		let queued_message: VersionedQueuedMessage = QueuedMessage {
			id: message_id,
			channel_id: message.channel_id,
			command: message.command.clone(),
		}
		.into();
		// The whole message should not be too large
		let encoded = queued_message.encode().try_into().map_err(|_| SendError::MessageTooLarge)?;

		let ticket = Ticket { message_id, channel_id: message.channel_id, message: encoded };

		Ok((ticket, fee))
	}

#[test]
fn test_calculate_fees_with_valid_exchange_rate_but_remote_fee_calculated_as_zero() {
	new_tester().execute_with(|| {
		let gas_used: u64 = 250000;
		let price_params: PricingParameters<<Test as Config>::Balance> = PricingParameters {
			exchange_rate: FixedU128::from_rational(1, 1),
			fee_per_gas: 1_u32.into(),
			rewards: Rewards { local: 1_u32.into(), remote: 1_u32.into() },
			multiplier: FixedU128::from_rational(1, 1),
		};
		let fee = OutboundQueue::calculate_fee(gas_used, price_params.clone());
		assert_eq!(fee.local, 698000000);
		// Though none zero pricing params the remote fee calculated here is invalid
		// which should be avoided
		assert_eq!(fee.remote, 0);
	});
}
