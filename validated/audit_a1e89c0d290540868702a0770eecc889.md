### Title
Unauthenticated `/shutdown` HTTP route lets any peer stop a signer's event receiver - (File: `libsigner/src/events.rs`)

### Summary
The signer's local HTTP event server, `SignerEventReceiver`, exposes an unauthenticated `/shutdown` route. Any POST to this route sets the internal stop flag and terminates the receiver's `main_loop`, exactly analogous to rendertron's unauthenticated `_ah/stop` route that let any remote caller kill the Chrome render service.

### Finding Description
`SignerEventReceiver::next_event` dispatches on the request URL without checking the caller's identity or any credential/signature: [1](#0-0) 

Compare the intended, "legitimate" caller: `SignerStopSignaler::send` builds the exact same unauthenticated request (`POST /shutdown`) that any TCP client could construct and send: [2](#0-1) 

There is no check that the request came from the local node process or any expected peer — the handler only inspects `request.url()` and `request.method()`, so the equality that should hold ("only the co-located stacks-node may terminate this signer's listener") is not enforced; any TCP peer able to reach the bound address can trigger it. This mirrors the rendertron flaw class: a control/shutdown route reachable without authentication.

Other routes on this same listener (`/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block`) are similarly unauthenticated, but those merely feed events into the signer's processing pipeline (garbage in is filtered downstream by StackerDB/signature checks). The `/shutdown` route is unique in that it directly disables the receiver with a single, trivially-forged request and no downstream validation at all — this is the closest and most severe analog to the rendertron bug.

### Impact Explanation
If the signer's HTTP listener address (`endpoint` in `stacks-signer/src/config.rs`) is bound to an interface reachable by other machines (not strictly `127.0.0.1`), a remote unauthenticated attacker can send one POST request to `/shutdown` and immediately stop the signer's event receiver thread. Because `main_loop` (in `libsigner/src/events.rs`, lines 284-312, implemented against the `EventReceiver` trait) exits on `EventError::Terminated`, the signer stops receiving block proposals, burn-block events, and StackerDB chunk events from the node — a denial of service against signer participation with a single crafted packet. This matches the "Critical - remote crash/unauthenticated DoS from few messages" bucket in scope.

### Likelihood Explanation
Exploitability depends entirely on network exposure of the signer's event-receiver bind address. If deployment binds it to loopback only, the route is unreachable externally and the issue is moot; if an operator binds it more broadly (e.g., to allow the node and signer to run on separate hosts), it becomes trivially exploitable by anyone who can reach that port — no authentication, keys, or protocol handshake required, unlike the `/stackerdb_chunks` etc. routes where forged content is at least filtered by downstream signature checks.

### Recommendation
- Require that `/shutdown` (and ideally all routes on this listener) only be honored from a loopback/trusted-peer source, or bind the event-receiver socket to loopback only by default with a hard warning against widening it.
- Add a shared secret / token check between the node and the signer's event server before honoring `/shutdown`, similar to how the upstream rendertron fix added an auth check to `_ah/stop` (GHSA-4q69-q4q7-x82c fix in GoogleChrome/rendertron#88).
- At minimum, document and enforce that this listener must never be exposed beyond the local trust boundary between the co-located node and signer processes.

### Proof of Concept
Given the signer's event-receiver address `HOST:PORT` (from `stacks-signer` config `endpoint`), any remote client can terminate the receiver with:
```
printf 'POST /shutdown HTTP/1.1\r\nHost: HOST:PORT\r\nConnection: close\r\nContent-Length: 4\r\nContent-Type: text/plain\r\n\r\ntest' | nc HOST PORT
```
This reproduces exactly the code path taken by `SignerStopSignaler::send` [3](#0-2)  and triggers the same branch in `next_event` [4](#0-3) , stopping the receiver's `main_loop`.
