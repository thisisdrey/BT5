### Title
Symlink-following write of attacker-triggered VM execution trace files - (File: actuator/src/main/java/org/tron/core/vm/VMUtils.java)

### Summary
`VMUtils.createProgramTraceFile`/`saveProgramTraceFile` writes VM execution trace JSON to a predictable, shared path (`./vm_trace/<txHash>.json`) without checking whether the target is a symbolic link, and then opens it with a plain `FileOutputStream` that follows symlinks. This is the same bug class as CVE-2011-2185 (Fabric writing to predictable names in a shared `/tmp` without symlink checks): a local attacker who can pre-plant a symlink at the predictable trace path can redirect the node's write to an arbitrary file the node process can write to.

### Finding Description
When VM tracing is enabled (`VMConfig.vmTrace()`), every VM execution triggered by a transaction (contract call or contract creation) ends by calling `VMUtils.saveProgramTraceFile(txHash, traceContent)` from `VMActuator.finalization`: [1](#0-0) 

`saveProgramTraceFile` delegates to `createProgramTraceFile`, which builds the output `File` from an attacker-influenced, low-entropy component (the transaction hash) inside a fixed relative directory, `./vm_trace`: [2](#0-1) 

Note the check at line 60: `if (file.isFile() && file.canWrite())` — both `File.isFile()` and `File.canWrite()` follow symbolic links, so a pre-existing symlink at that path is silently accepted as the write target. The subsequent write uses a plain, non-exclusive `FileOutputStream(file)`: [3](#0-2) 

This mirrors the Fabric CVE-2011-2185 pattern exactly: a well-known, predictable filename in a shared, writable directory, written without `O_NOFOLLOW`/`O_EXCL` semantics or an `lstat`-based symlink check. The codebase already hardened an analogous pattern elsewhere — `WalletUtils.writeWalletFile` uses `Files.createTempFile` + atomic rename with owner-only permissions, and `KeystoreCliUtils.readKeystoreFile`/`readRegularFile` explicitly call `Files.readAttributes(..., LinkOption.NOFOLLOW_LINKS)` and refuse symlinks: [4](#0-3) 

`VMUtils.createProgramTraceFile` was not given the same treatment.

### Impact Explanation
On a node shared with other local users/processes (a realistic deployment for public-facing full nodes, exchange gateways, or multi-tenant hosting), a co-resident attacker can pre-create a symlink at `./vm_trace/<txHash>.json` pointing at a sensitive file the node process can write (e.g. a config file, another node's data file, or any file writable by the node's OS user). By then broadcasting/triggering a transaction whose hash is known in advance (transaction hashes are deterministic and can be precomputed before broadcast) that exercises the traced VM path, the attacker causes the node to overwrite the symlink target with VM trace content it does not expect. This can corrupt node configuration or data, causing a crash/halt of the node process, i.e. an availability impact on infrastructure operated by exchanges, wallets, or other node operators depending on this feature being enabled.

### Likelihood Explanation
Exploitation requires: (1) `vm.trace=true` (a node operator config flag) to be enabled, and (2) the attacker having local filesystem access to the node's working directory to pre-plant the symlink — the same precondition as the original Fabric advisory (local multi-user access to a shared temp location). It does not require any special on-chain privilege: any address able to deploy or call a contract can trigger the trace write with a transaction hash it controls/predicts. This narrows applicability mostly to shared-hosting/multi-tenant node deployments, which is a realistic but not universal deployment model, hence Medium rather than High likelihood.

### Recommendation
Harden `VMUtils.createProgramTraceFile` the same way `WalletUtils.writeWalletFile` and `KeystoreCliUtils` already are:
- Check the target path's `BasicFileAttributes` with `LinkOption.NOFOLLOW_LINKS` and refuse (or delete-then-recreate) if it is a symlink.
- Open the file via `Files.newOutputStream(path, StandardOpenOption.CREATE, StandardOpenOption.WRITE, LinkOption.NOFOLLOW_LINKS)` or write to a per-write random/temp filename and atomically rename into place, instead of a plain `FileOutputStream` on a name derived only from the tx hash.

### Proof of Concept
1. Enable VM tracing on a node (`vm.trace=true`) that is co-located with an untrusted local user, or simulate the unit-level condition directly against `VMUtils`.
2. Precompute the hash of a transaction the attacker is about to broadcast (deterministic given raw data), then before broadcasting, create `./vm_trace/<txHash>.json` as a symlink to a target file the node process can write, e.g. `ln -s /path/to/target.file ./vm_trace/<txHash>.json`.
3. Broadcast the contract-call/creation transaction so it is executed by the node with `vm.trace=true`; `VMActuator.finalization` calls `VMUtils.saveProgramTraceFile(txHash, traceContent)`.
4. Observe `createProgramTraceFile` passes the `file.isFile() && file.canWrite()` check (both follow the symlink) and `writeStringToFile` overwrites the symlink target with attacker-influenced trace JSON, confirming the symlink-follow write.

```java
  private static File createProgramTraceFile(String txHash) {
    File result = null;

    if (VMConfig.vmTrace()) {

      File file = new File(new File("./", "vm_trace"), txHash + ".json");

      if (file.exists()) {
        if (file.isFile() && file.canWrite()) {
          result = file;
        }
      } else {
        try {
          file.getParentFile().mkdirs();
          if (!file.createNewFile()) {
            logger.error("failed to create file {}", file.getPath());
          }
          result = file;
        } catch (IOException e) {
          // ignored
        }
      }
    }

    return result;
  }
```

```java
  private static void writeStringToFile(File file, String data) {
    OutputStream out = null;
    try {
      out = new FileOutputStream(file);
      if (data != null) {
        out.write(data.getBytes("UTF-8"));
      }
    } catch (Exception e) {
      logger.error(format("Cannot write to file '%s': ", file.getAbsolutePath()), e);
    } finally {
      closeQuietly(out);
    }
  }

  public static void saveProgramTraceFile(String txHash, String content) {
    File file = createProgramTraceFile(txHash);
    if (file != null) {
      writeStringToFile(file, content);
    }
  }
```
