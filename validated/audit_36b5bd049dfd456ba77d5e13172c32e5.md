### Title
Unauthenticated write endpoints on the signer's event-receiver HTTP server accept forged StackerDB/block/burn events from any network peer - (File: libsigner/src/events.rs)

### Summary
The `stacks-signer` process runs an embedded HTTP server (`SignerEventReceiver`) that the Stacks node is supposed to POST events to (StackerDB chunk updates, block proposals, burn blocks, new blocks). The signing/documentation model assumes this channel is protected by a shared `auth_token`/`auth_password` configured on both sides, but the receiver implementation never validates any credential on inbound requests, so any TCP peer that can reach the bound port can inject fabricated events into the signer's decision pipeline.

### Finding Description
`docs/signing.md` explicitly documents `auth_token` (node) / `auth_password` (signer) as a required, matching secret intended to authenticate this channel: [1](#0-0) . However, `SignerEventReceiver::next_event` in `libsigner/src/events.rs` never reads or checks any `authorization` header, token, or peer credential before dispatching to `process_event`: [2](#0-1) . The dispatch is purely based on URL path match (`/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block`, `/shutdown`), and `process_event` just JSON-deserializes the body and converts it into a `SignerEvent` that is forwarded to the signer's runloop with no origin check: [3](#0-2) . Even the `/shutdown` path is reachable without authentication and directly sets the stop signal, terminating the event receiver: [4](#0-3) . A grep across `libsigner/**` for `auth_password`, `authorization`, or `Authorization` returns zero matches, confirming no authentication code path exists on the receiving side at all.

This breaks the intended equality "event genuinely originated from the paired, authenticated Stacks node" vs. "event accepted and forwarded into the signer's decision-making state" — any attacker on the local network segment (or anyone who can reach the configured `bind_addr`, which per the sample configs is often `0.0.0.0:30000`) can POST crafted `StackerDBChunksEvent`, `BlockValidateResponse`, `BurnBlockEvent`, or `StacksBlockEvent` payloads and have them treated as legitimate node-originated events by the signer.

### Impact Explanation
This is an unauthenticated write into the signer's internal event/decision state — directly matching the "Critical: unauthenticated/unauthorized write to state" and "network-wide propagation of forged data" categories. Forged `StackerDBChunksEvent`/`BlockValidateResponse`/burn-block events being accepted as genuine node signals can desynchronize or corrupt a signer's view of chain/tenure state, potentially influencing block signing decisions across the affected signer, and the unauthenticated `/shutdown` endpoint is a trivial remote DoS against the signer's event pipeline (a few HTTP requests suffice, no volumetric flooding required).

### Likelihood Explanation
High. No credentials, signatures, or special network position are needed — only network reachability to the signer's configured listener port (documented default binds such as `127.0.0.1:30000`/`0.0.0.0:30000` in sample configs are common in real deployments, and misconfiguration to a non-loopback interface is plausible). The attack requires only a handful of crafted HTTP POST requests, well within scope rules (not volumetric).

### Recommendation
Add authentication enforcement to `SignerEventReceiver::next_event` (or the underlying HTTP handling) mirroring the node-side `auth_token`/`auth_password` mechanism used elsewhere in `stackslib/src/net/api/*` (e.g., the `authorization` header check pattern seen in `postblock_proposal.rs`, `blockreplay.rs`, `blocksimulate.rs`, `fastcallreadonly.rs`). Reject any request lacking a valid, constant-time-compared `authorization` header before deserializing/dispatching the body, and require the same protection for the `/shutdown` path.

### Proof of Concept
1. Deploy `stacks-signer` with `auth_password` configured per `docs/signing.md`, binding its event receiver to a reachable interface (e.g., `0.0.0.0:30000` per sample configs).
2. From an unrelated host (not the paired stacks-node), send: `POST /stackerdb_chunks HTTP/1.1` with a crafted JSON body matching `StackerDBChunksEvent`'s schema, and no `authorization` header.
3. Observe in `libsigner/src/events.rs::next_event` that the request is accepted (`request.method() == Post` and `request.url() == "/stackerdb_chunks"`), passed to `process_event::<T, StackerDBChunksEvent>`, and forwarded via `forward_event` into the signer's runloop — with no rejection based on missing/incorrect credentials.
4. Similarly, `POST /shutdown` with any body immediately sets `stop_signal` and terminates the receiver loop, demonstrating remote unauthenticated DoS.

    /// Wait for the node to post something, and then return it.
    /// Errors are recoverable -- the caller should call this method again even if it returns an
    /// error.
    fn next_event(&mut self) -> Result<SignerEvent<T>, EventError> {
        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)
            } else if request.url() == "/new_block" {
                process_event::<T, StacksBlockEvent>(request)
            } else {
                let url = request.url().to_string();
                debug!(
                    "[{:?}] next_event got request with unexpected url {}, return OK so other side doesn't keep sending this",
                    event_receiver.local_addr,
                    url
                );
                ack_dispatcher(request);
                Err(EventError::UnrecognizedEvent(url))
            }
        })?

fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}
