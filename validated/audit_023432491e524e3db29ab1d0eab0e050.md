### Title
Per-repository RPC concurrency limiter is silently bypassed when the target repository field cannot be resolved, allowing unlimited concurrent calls for that key - (File: internal/grpc/middleware/limithandler/middleware.go, internal/grpc/middleware/requestinfohandler/requestinfohandler.go)

### Summary
The reported ZcToken bug is a class of "unresolved/zero state used silently instead of failing," which causes a downstream computation to quietly no-op (0 tokens returned) rather than reverting. The analogous pattern in Gitaly is `LimitConcurrencyByRepo`, the lock-key function used by the per-repository concurrency limiter: if the repository cannot be resolved from the request, it silently returns an empty string, and the limiter middleware treats an empty lock key as "skip limiting entirely" rather than falling back to a safe default or rejecting the request.

### Finding Description
`LimitConcurrencyByRepo` extracts the repository's relative path from `requestinfohandler.Extract(ctx)`: [1](#0-0) 

`RequestInfo.Repository` is populated in `extractRequestInfo` only when `mi.TargetRepo(reqMsg)` succeeds for a `ScopeRepository` method: [2](#0-1) 

If `TargetRepo` returns an error (e.g., the repository message is unset/nil, malformed, or the target extension resolution fails for a particular request shape), `i.Repository` stays `nil`, so `LimitConcurrencyByRepo` returns `""` via `info.Repository.GetRelativePath()` (nil-safe getter returning zero value).

Both the unary and streaming interceptors then treat an empty lock key as "no limiting should happen at all": [3](#0-2) [4](#0-3) 

This mirrors the ZcToken flaw exactly in structure: a value that should represent "the resolved resource" (maturityRate / repository path) defaults to a zero/empty value when unset, and that zero value is used directly in a critical calculation/gate (`previewWithdraw` uses `maturityRate`; the interceptor uses `lockKey == ""`) instead of being treated as an error condition or a safe fallback. The result is not "wrong output" but "no gating at all" — i.e., the concurrency limiter is a no-op for that request.

### Impact Explanation
The per-repository concurrency limiter exists specifically to bound how many concurrent expensive Git operations (e.g., repository RPCs) can execute against a given repository, protecting the node from resource exhaustion. Any ordinary, unprivileged client that can cause `TargetRepo(reqMsg)` extraction to fail for a repository-scoped RPC (for example, by sending a request where the repository-typed field is left unset/zero on a method registered as `ScopeRepository`, or any other request shape that causes the target-repository accessor to return an error) causes the lock key to resolve to `""`. The interceptor then calls `handler(ctx, req)` directly, completely bypassing the queue/semaphore logic, `maxQueueLength`, and `maxQueueWait` enforcement for that call. An attacker can flood the server with such requests without ever being queued or rejected via `ErrMaxQueueSize`/`ErrMaxQueueTime`, defeating the RPC-handler resource-limiting mechanism that other, well-formed requests are subject to.

### Likelihood Explanation
This requires only an ordinary/unprivileged gRPC client sending a request to a repository-scoped RPC where the request-level accessor used by `mi.TargetRepo` cannot resolve a `*gitalypb.Repository` (e.g., missing/zero-value repository field, or any parse/extension-resolution failure path in the registry). No malicious peer, privileged actor, or MITM position is needed — this is directly reachable from a standard, authenticated (or per-method unauthenticated) gRPC call to Gitaly. The likelihood of triggering the "unset lock key" branch depends on how easy it is to submit a request whose repository field fails extraction while the RPC handler itself still performs meaningful work (or errors out late after having consumed resources); this needs to be verified per RPC method registration, which I was not able to fully enumerate.

### Recommendation
Do not treat an empty/unresolved lock key as "skip limiting." Instead:
1. When `requestinfohandler.Extract(ctx)` returns `nil` or `Repository` is `nil`/unset for a method registered with `ScopeRepository`, either reject the request early (as an invalid-argument, consistent with how the actual RPC handler would reject a missing repository) before it reaches the limiter, or fall back to a bounded default/global limiter key rather than bypassing limiting entirely.
2. Ensure `GetLockKey` implementations distinguish between "this method is legitimately not repository-scoped" (fine to skip) and "this method is repository-scoped but resolution failed" (should not skip), so failures fail closed instead of open.
3. Add explicit test coverage in `internal/grpc/middleware/limithandler` for the case where a repository-scoped RPC is invoked with an unresolvable/empty repository, asserting that concurrency limiting still applies (or the request is rejected) rather than silently bypassing the limiter.

### Proof of Concept
Conceptual reproduction (exact request shapes to trigger `TargetRepo` failure were not fully verified from the available index and would need confirmation in a live environment):
1. Identify a gRPC method registered with `protoregistry.ScopeRepository`.
2. Send a request where the repository-typed field normally used for `TargetRepo` extraction is left as its zero value / unset in a way that makes `mi.TargetRepo(reqMsg)` return an error (rather than a valid but empty `*gitalypb.Repository`).
3. Observe that `extractRequestInfo` leaves `i.Repository == nil` [5](#0-4) .
4. `LimitConcurrencyByRepo` then returns `""` [6](#0-5) .
5. The unary/stream interceptor calls `handler(ctx, req)` without going through `limiter.Limit(...)`, i.e., without any concurrency/queue enforcement [7](#0-6) .
6. Repeating step 2 concurrently many times demonstrates unrestrained concurrent execution against the node, unlike well-formed requests which are subject to `ConcurrencyLimiter.Limit` (queueing, `ErrMaxQueueSize`, `ErrMaxQueueTime`) as shown in [8](#0-7) .

// LimitConcurrencyByRepo implements GetLockKey by using the repository path as lock.
func LimitConcurrencyByRepo(ctx context.Context) string {
	if info := requestinfohandler.Extract(ctx); info != nil {
		return info.Repository.GetRelativePath()
	}

	return ""
}

func (c *LimiterMiddleware) UnaryInterceptor() grpc.UnaryServerInterceptor {
	return func(ctx context.Context, req interface{}, info *grpc.UnaryServerInfo, handler grpc.UnaryHandler) (interface{}, error) {
		lockKey := c.getLockKey(ctx)
		if lockKey == "" {
			return handler(ctx, req)
		}

		// Check if request is authenticated
		limiter := c.methodLimiters[info.FullMethod]
		unauthLimiter, ok := c.methodLimitersUnauthenticated[info.FullMethod]
		if !auth.IsAuthenticated(ctx) && ok {
			limiter = unauthLimiter
		}

		if limiter == nil {
			// No concurrency limiting
			return handler(ctx, req)
		}

		return limiter.Limit(ctx, lockKey, func() (interface{}, error) {
			return handler(ctx, req)
		})
	}
}

func (c *ConcurrencyLimiter) Limit(ctx context.Context, limitingKey string, f LimitedFunc) (interface{}, error) {
	span, ctx := tracing.StartSpanIfHasParent(
		ctx,
		"limiter.ConcurrencyLimiter.Limit",
		[]attribute.KeyValue{
			attribute.String("key", limitingKey),
		},
	)
	defer span.End()

	if c.currentLimit() <= 0 {
		return f()
	}

	sem := c.getConcurrencyLimit(limitingKey)
	defer c.putConcurrencyLimit(limitingKey)

	start := time.Now()

	if err := sem.acquire(ctx, limitingKey); err != nil {
		queueTime := time.Since(start)
		switch {
		case errors.Is(err, ErrMaxQueueSize):
			c.monitor.Dropped(ctx, limitingKey, sem.queueLength(), sem.inProgress(), queueTime, "max_size")
			return nil, structerr.NewResourceExhausted("%w", ErrMaxQueueSize).WithDetail(&gitalypb.LimitError{
				ErrorMessage: err.Error(),
				RetryAfter:   durationpb.New(0),
			})
		case errors.Is(err, ErrMaxQueueTime):
			c.monitor.Dropped(ctx, limitingKey, sem.queueLength(), sem.inProgress(), queueTime, "max_time")
			return nil, structerr.NewResourceExhausted("%w", ErrMaxQueueTime).WithDetail(&gitalypb.LimitError{
				ErrorMessage: err.Error(),
				RetryAfter:   durationpb.New(0),
			})
		default:
			c.monitor.Dropped(ctx, limitingKey, sem.queueLength(), sem.inProgress(), queueTime, "other")
			return nil, fmt.Errorf("unexpected error when dequeueing request: %w", err)
		}
	}
	defer sem.release()

	c.monitor.Enter(ctx, sem.inProgress(), time.Since(start))
	defer c.monitor.Exit(ctx)
	return f()
}
