### Title
Zero-valued remote delivery fee is silently accepted by `OutboundQueue::validate`, enabling underpriced Snowbridge message delivery - (File: `bridges/snowbridge/pallets/outbound-queue/src/lib.rs`)

### Summary
The Snowbridge outbound-queue fee model is structurally analogous to the Tellor pricing bug: a computed numeric value derived from external/adjustable parameters is trusted and used downstream without validating it against the "zero" edge case, even though the code's own test suite proves that edge case is reachable with otherwise valid parameters.

### Finding Description
`calculate_fee` computes the remote (Ethereum-side) fee by combining `gas_used_at_most`, `fee_per_gas`, `reward`, dividing by the `exchange_rate`, and converting from 18-decimal Ether precision down to the local currency's decimals: [1](#0-0) 

`PricingParameters::validate()` only checks that the raw governance-set fields (`exchange_rate`, `fee_per_gas`, `rewards.local/remote`, `multiplier`) are individually non-zero: [2](#0-1) 

However, the *derived* `fee.remote` returned by `calculate_fee` is not re-validated after the arithmetic (`saturating_mul`, `checked_div`, integer decimal conversion via `convert_from_ether_decimals`). The pallet's own test demonstrates that with fully valid, non-zero `PricingParameters`, the computed `fee.remote` can still be `0` due to rounding/truncation in `convert_from_ether_decimals`'s `checked_div`: [3](#0-2) 

This `fee` is then returned directly to `SendMessage::validate` in `send_message_impl.rs`, which enqueues the message (via `deliver`) with **no check that the returned `fee.remote` (or `fee.local`) is non-zero** before proceeding to `T::MessageQueue::enqueue_message`: [4](#0-3) 

The Tellor analog: the audited contract trusted a computed price/timestamp from an external source without checking for the degenerate zero case before using it downstream (`_denominationPricing`). Here, the outbound queue trusts a computed fee from governance-controlled `PricingParameters` without checking for the degenerate zero case before enqueueing work for relayers to execute on Ethereum.

### Impact Explanation
If `fee.remote` rounds to `0` (as proven possible by the existing unit test with valid parameters), a user can pay effectively no fee to cover the relayer's gas cost on Ethereum for dispatching the message, while `T::GasMeter::maximum_dispatch_gas_used_at_most` still bounds real gas consumption on the remote side. This is public underpriced work: any unprivileged account can submit a message whose actual remote execution cost is not covered by the collected `reward`, degrading relayer incentives and potentially stalling bridge message processing if relayers stop servicing unrewarded messages, consistent with the "public underpriced work that degrades block production or stalls bridge processing" impact category for Snowbridge delivery flow.

### Likelihood Explanation
The degenerate zero-fee condition is not a hypothetical: it is directly exercised and asserted by `test_calculate_fees_with_valid_exchange_rate_but_remote_fee_calculated_as_zero` with an `exchange_rate` of `1` and `fee_per_gas` of `1`, both of which pass `PricingParameters::validate()`. Any parameter combination near the low end of `fee_per_gas`/`reward` relative to `exchange_rate` and decimal-conversion divisor can reproduce this, and no code path rejects it before enqueueing.

### Recommendation
In `Pallet::<T>::calculate_fee` (or immediately in `SendMessage::validate`), assert/ensure that the computed `Fee { local, remote }` has `remote > 0` (and ideally `local > 0`) before returning it, rejecting the message (`SendError`) if the fee rounds down to zero rather than silently permitting free delivery.

### Proof of Concept
Using the existing test harness in `bridges/snowbridge/pallets/outbound-queue/src/test.rs`:
1. Set `PricingParameters { exchange_rate: FixedU128::from_rational(1,1), fee_per_gas: 1u32.into(), rewards: Rewards { local: 1, remote: 1 }, multiplier: FixedU128::from_rational(1,1) }` — this passes `validate()`.
2. Call `OutboundQueue::calculate_fee(gas_used, price_params)` with `gas_used = 250000` as in the existing test.
3. Observe `fee.remote == 0` (already asserted at line 317 of `test.rs`), confirming a message can be validated/enqueued via `send_message_impl::validate` → `deliver` with zero remote fee collected, i.e., underpriced work reaching the message queue. [3](#0-2)

		pub(crate) fn calculate_fee(
			gas_used_at_most: u64,
			params: PricingParameters<T::Balance>,
		) -> Fee<T::Balance> {
			// Remote fee in ether
			let fee = Self::calculate_remote_fee(
				gas_used_at_most,
				params.fee_per_gas,
				params.rewards.remote,
			);

			// downcast to u128
			let fee: u128 = fee.try_into().defensive_unwrap_or(u128::MAX);

			// multiply by multiplier and convert to local currency
			let fee = FixedU128::from_inner(fee)
				.saturating_mul(params.multiplier)
				.checked_div(&params.exchange_rate)
				.expect("exchange rate is not zero; qed")
				.into_inner();

			// adjust fixed point to match local currency
			let fee = Self::convert_from_ether_decimals(fee);

			Fee::from((Self::calculate_local_fee(), fee))
		}

fn test_calculate_fees_with_valid_exchange_rate_but_remote_fee_calculated_as_zero() {
	new_tester().execute_with(|| {
		let gas_used: u64 = 250000;
		let price_params: PricingParameters<<Test as Config>::Balance> = PricingParameters {
			exchange_rate: FixedU128::from_rational(1, 1),
			fee_per_gas: 1_u32.into(),
			rewards: Rewards { local: 1_u32.into(), remote: 1_u32.into() },
			multiplier: FixedU128::from_rational(1, 1),
		};
		let fee = OutboundQueue::calculate_fee(gas_used, price_params.clone());
		assert_eq!(fee.local, 698000000);
		// Though none zero pricing params the remote fee calculated here is invalid
		// which should be avoided
		assert_eq!(fee.remote, 0);
	});
}

	fn validate(
		message: &Message,
	) -> Result<(Self::Ticket, Fee<<Self as SendMessageFeeProvider>::Balance>), SendError> {
		// The inner payload should not be too large
		let payload = message.command.abi_encode();
		ensure!(
			payload.len() < T::MaxMessagePayloadSize::get() as usize,
			SendError::MessageTooLarge
		);

		// Ensure there is a registered channel we can transmit this message on
		ensure!(T::Channels::contains(&message.channel_id), SendError::InvalidChannel);

		// Generate a unique message id unless one is provided
		let message_id: H256 = message
			.id
			.unwrap_or_else(|| unique((message.channel_id, &message.command)).into());

		let gas_used_at_most = T::GasMeter::maximum_gas_used_at_most(&message.command);
		let fee = Self::calculate_fee(gas_used_at_most, T::PricingParameters::get());

		let queued_message: VersionedQueuedMessage = QueuedMessage {
			id: message_id,
			channel_id: message.channel_id,
			command: message.command.clone(),
		}
		.into();
		// The whole message should not be too large
		let encoded = queued_message.encode().try_into().map_err(|_| SendError::MessageTooLarge)?;

		let ticket = Ticket { message_id, channel_id: message.channel_id, message: encoded };

		Ok((ticket, fee))
	}

	fn deliver(ticket: Self::Ticket) -> Result<H256, SendError> {
		let origin = AggregateMessageOrigin::Snowbridge(ticket.channel_id);

		if ticket.channel_id != PRIMARY_GOVERNANCE_CHANNEL {
			ensure!(!Self::operating_mode().is_halted(), SendError::Halted);
		}

		let message = ticket.message.as_bounded_slice();

		T::MessageQueue::enqueue_message(message, origin);
		Self::deposit_event(Event::MessageQueued { id: ticket.message_id });
		Ok(ticket.message_id)
	}
