### Title
Unauthenticated Denial-of-Service via `/shutdown` HTTP Route in `SignerEventReceiver` - (File: libsigner/src/events.rs)

### Summary
`SignerEventReceiver::next_event` dispatches HTTP requests purely on `request.url()` string matching, with no verification of the sender's identity, origin, or possession of any secret. Any TCP client that can reach the signer's bound event-receiver port can POST to `/shutdown` and unconditionally set `stop_signal` to `true`, permanently halting the signer's event loop.

### Finding Description
The dispatcher in `next_event` (libsigner/src/events.rs:413-458) checks only the HTTP method and URL path before acting: [1](#0-0) 
There is no authentication middleware, shared secret, `Authorization` header check, or peer-address allowlist anywhere in this file — a grep for `Authorization`, `auth_token`, `shared_secret`, `X-Auth` in `libsigner/` returns nothing. The intended caller is `SignerStopSignaler::send`, which connects to `self.local_addr` and issues a raw `POST /shutdown` request with an arbitrary body: [2](#0-1) 
This is the *only* legitimate producer of that request, but nothing in the receiver enforces that the request actually originated from that internal call path or from `127.0.0.1` — `tiny_http`'s `Request` object is dispatched to the handler with no origin check performed by this code. Consequently, any attacker who can open a TCP connection to the bound event port (`bind()` at libsigner/src/events.rs:404-408 does not restrict the listen address, and deployment commonly binds this to a locally reachable interface) can send the same three lines of raw HTTP and reach the `stop_signal.store(true, Ordering::SeqCst)` call directly, matching the trigger of the legitimate stop signaler exactly.

### Impact Explanation
A successful POST to `/shutdown` causes `is_stopped()` to return `true` on the next loop iteration, which makes `next_event` return `Err(EventError::Terminated)` (libsigner/src/events.rs:416-418) and halts the signer's `main_loop`. This is a single-message, remotely triggerable, permanently effective (until process restart) denial of service against an individual signer's participation in the network — matching the Critical category of "remote crash/unauthenticated DoS from few messages."

### Likelihood Explanation
No credentials, secrets, or privileged roles are required — only TCP reachability to the signer event port, which the finding text itself notes is not enforced to be local-only by the code. The attack is a single crafted HTTP POST, trivially repeatable against any signer whose event port is reachable, and costs the attacker essentially nothing.

### Recommendation
Add authentication/authorization to the event receiver's HTTP handling, e.g., require a shared secret/token in a header that only the local node process knows and validate it before acting on `/shutdown` (and ideally all other routes), and/or explicitly bind and restrict the listener to loopback and validate the peer's socket address before processing state-changing requests like `/shutdown`.

### Proof of Concept
1. Start a `SignerEventReceiver` and call `bind()` on a test address.
2. Spawn a thread calling `next_event()` in a loop.
3. From a separate `TcpStream::connect` (simulating an unauthenticated remote attacker, not going through `SignerStopSignaler`), send:
```
POST /shutdown HTTP/1.1\r\nHost: <addr>\r\nConnection: close\r\nContent-Length: 4\r\nContent-Type: text/plain\r\n\r\npwnd
```
4. Assert `event_receiver.is_stopped()` (or the shared `Arc<AtomicBool>` stop_signal) becomes `true`, and that subsequent `next_event()` calls return `Err(EventError::Terminated)`, with no credential ever presented.
