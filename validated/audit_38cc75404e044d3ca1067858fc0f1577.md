### Title
Silent authentication bypass on nil AEAD cipher state in `DecryptDanger` — ([File: noiseutil/aesgcm.go], [File: noiseutil/chachapoly.go])

### Summary
`CipherStateAESGCM.DecryptDanger` and `CipherStateChaChaPoly.DecryptDanger` both special-case a nil receiver by returning `[]byte{}, nil` instead of an error, meaning "no cipher available" is reported as a *successful* decrypt/authentication with empty plaintext rather than a failure. [1](#0-0) [2](#0-1) 

This mirrors the report's bug class: a call that can fail is treated as successful by its caller because the failure is signaled through a "soft" return value instead of a proper error, and callers that only check `err != nil` are fooled.

### Finding Description
`ConnectionState.Decrypt` and `ConnectionState.VerifyRelay` both call `cs.dKey.DecryptDanger(...)` and treat any non-nil `err` as an authentication/decrypt failure: [3](#0-2) [4](#0-3) 

`cs.dKey` is a `noiseutil.CipherState` interface value built from the Noise handshake result via `noiseutil.NewCipherState`: [5](#0-4) [6](#0-5) 

If a `*CipherStateAESGCM` or `*CipherStateChaChaPoly` pointer stored inside that interface value is `nil` (a non-nil interface holding a nil concrete pointer — Go permits calling methods on it without a runtime panic), then `DecryptDanger` silently returns `([]byte{}, nil)` instead of an error. The AEAD `Open` authentication step (which is the actual integrity/authenticity check for the Noise transport) is skipped entirely in that branch. Both `Overhead()` and `EncryptDanger` correctly guard the nil case by either returning `0` or an explicit error, but `DecryptDanger` is inconsistent and returns a fabricated success.

### Impact Explanation
If this nil-receiver path is reachable with attacker-controlled input (e.g., a corrupted/partial handshake completion path that leaves `dKey` as a nil-typed `CipherState`, or any future refactor that constructs a `ConnectionState`/relay verifier from an incompletely-initialized key), the data-plane decrypt/verify path would accept forged or garbage ciphertext as authenticated, returning empty data as "successfully decrypted" instead of rejecting it. This is the same class of bug as the source-report's "unhandled `false` return treated as success": a caller-visible non-error result masking a failure/invalid state, here in the transport authentication path rather than a token transfer.

### Likelihood Explanation
This is a defensive/guard branch, not on the common handshake-success path — under normal operation `NewCipherState` always wraps a real `*noise.CipherState` produced by a completed Noise handshake, and `Result.EKey`/`Result.DKey` are populated together as an invariant enforced in `handshake/machine.go`. I could not fully trace every code path that could leave `dKey`/`eKey` as a nil-wrapped `CipherState` reaching `ConnectionState` in the current codebase within the available exploration; this would need to be confirmed by an engineer with direct code execution/testing access. The bug is real and present in the code as written, but I cannot confirm from static reading alone whether an external attacker can force this nil condition today. It should be treated as a defense-in-depth / code-quality issue at minimum, and a potential remote-authentication-bypass if any call path can leave the cipher unset.

### Recommendation
Make `DecryptDanger`'s nil-receiver behavior consistent with `EncryptDanger`: return a non-nil error (e.g. `errors.New("no cipher state available to decrypt")`) instead of `[]byte{}, nil`, in both `noiseutil/aesgcm.go` and `noiseutil/chachapoly.go`. This ensures any caller that only checks `err != nil` cannot be misled into treating a missing/uninitialized cipher as a verified, authenticated decrypt.

### Proof of Concept
```go
// noiseutil/aesgcm.go
var s *CipherStateAESGCM // nil concrete pointer
var cs CipherState = s   // non-nil interface, nil underlying pointer
out, err := cs.DecryptDanger(nil, []byte("ad"), []byte("forged-ciphertext"), 42, make([]byte, 12))
// out == []byte{}, err == nil  -> caller's `if err != nil { return err }` check in
// connection_state.go's Decrypt/VerifyRelay does NOT fire, treating a missing
// cipher state as a successfully authenticated empty message.

// NewCipherState wraps the post-handshake noise.CipherState in the per-cipher type that matches cipherFunc.
// cipherFunc must be the same cipher used to build the noise CipherSuite that produced s.
func NewCipherState(s *noise.CipherState, cipherFunc noise.CipherFunc) CipherState {
	switch cipherFunc.CipherName() {
	case CipherAESGCM.CipherName():
		return NewCipherStateAESGCM(s)
	case noise.CipherChaChaPoly.CipherName():
		return NewCipherStateChaChaPoly(s)
	default:
		panic(fmt.Sprintf("noiseutil: unsupported cipher %q", cipherFunc.CipherName()))
	}
}
