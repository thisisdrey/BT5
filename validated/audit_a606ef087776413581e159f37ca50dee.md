## Title
Feeless `AsScarcity` transfer lets an unprivileged attacker sandwich a victim's NFT move and turn the pallet's own anti-abuse backoff lock against the victim - (File: `substrate/frame/scarcity/src/extension.rs`)

### Summary
`pallet-scarcity`'s `AsScarcity` transaction extension implements a "coinage" NFT model where each purse key can hold at most one NFT. Whether a transfer to a given destination succeeds depends entirely on whether that destination purse key is currently empty at the moment of *dispatch*, not at the moment the sender's transaction was validated. An unprivileged third party can occupy the intended destination between the victim's validation and the victim's dispatch (a same-block race the extension explicitly anticipates), causing the victim's transfer to fail. Because the destination-occupying transfer is itself feeless (`Pays::No`) and costs the attacker nothing, the attack can be repeated at zero cost — mirroring the C4 "NFT withdrawal grief" pattern where a griefer sandwiches a victim's action to force a revert with no economic loss to themselves. Here the effect is worse: the pallet's own failed-dispatch penalty (an exponentially growing lockout) is applied to the *victim*, not the attacker.

### Finding Description
`AsScarcity::validate` pre-checks the destination purse key so that "ordinary user error is rejected at the pool and never reaches dispatch", explicitly acknowledging dispatch-time checks exist only for "genuine same-block races": [1](#0-0) 

The actual authorization removes the NFT from `NftsByOwner` in `prepare()` before dispatch: [2](#0-1) 

The dispatched `transfer` call re-checks destination occupancy at execution time: [3](#0-2) 

If dispatch fails for any reason (including `AddressOccupied`), `post_dispatch_details` restores the victim's NFT but also inserts an **exponentially growing backoff lock** on the victim's account: [4](#0-3) [5](#0-4) 

Because a plain transfer via `AsScarcity` is `Pays::No` (feeless) whenever the origin is the `Nft` origin, and the destination-occupancy check (`AddressOccupied`/`DestinationOccupied`) requires no special permission — any purse holder can move their own NFT to any empty target address at zero fee — an attacker can:

1. Observe the victim's signed `transfer(to = target)` in the mempool (it validated successfully because `target` was empty at that time).
2. Before the victim's extrinsic executes in the block, submit (and get included ahead of it) their own feeless `transfer(to = target)`, occupying `target`.
3. The victim's dispatch then hits `ensure!(!NftsByOwner::<T>::contains_key(&to), Error::<T>::AddressOccupied)` and fails.
4. `post_dispatch_details` restores the victim's NFT to their own purse key **but locks that purse key** with `Locked::<T>::insert(&owner, failed_dispatch_lock(...))`, whose duration doubles on every consecutive failure (`multiplier = 2^retries`).
5. The attacker can move their NFT away from `target` (again feeless) and repeat step 2 on every subsequent retry, since each retry is itself validated when `target` happens to be free and then raced again at dispatch time.

The attacker never loses anything: they still own their own NFT throughout, pay no fees (the whole point of `AsScarcity`'s feeless design), and only need to win block-inclusion ordering — exactly the "no economic benefit, pure grief" pattern from the source report, except here the pallet's defensive mechanism (the backoff lock, designed to punish genuine dispatch failures/attackers) is inverted and punishes the honest victim instead of the attacker.

### Impact Explanation
This is a public-entrypoint, unprivileged, zero-cost griefing vector against a runtime pallet's NFT transfer path. A victim attempting to move an NFT to any specific address can be indefinitely blocked, with their own account accumulating an exponentially growing lockout (`until = now + 2^(retries-1) * LockPeriod`) that they did not cause and cannot avoid short of choosing an unpredictable destination. Repeated griefing escalates the victim's lock duration without bound, degrading availability of a core dispatchable (`transfer`) for a targeted account. This matches the "public underpriced work that degrades... processing" and "permanent user-fund... lock" categories in spirit: the NFT's mobility to the chosen destination is effectively locked out at the attacker's whim, at no cost to the attacker, using only signed transactions from an unprivileged account.

### Likelihood Explanation
The attack requires no privileged role, no validator/collator/relayer collusion, and no admin action — only an unprivileged account holding (or able to acquire) an NFT, and the ability to observe the victim's pending transaction and win block-inclusion ordering (a capability available to any block-producing-adjacent actor or via standard mempool-observation front-running, which the extension's own doc comments acknowledge as an expected "same-block race" scenario). The feeless nature of the transfer means the attack has no economic cost ceiling, so it can be repeated as many times as desired.

### Recommendation
- Do not penalize the *account whose NFT was consumed in `prepare()`* for a dispatch failure caused by a race on the *destination*, since the failure is not attributable to the sender's own state. Consider keying the backoff lock to whichever party actually caused the invalid state transition, or only applying the lock when the pre-dispatch state (destination occupancy) matches what was true at `prepare()` time.
- Re-validate destination occupancy identically at `prepare()`/before consuming the source NFT and at `transfer()`'s execution so the two checks cannot be independently raced.
- Consider allowing an explicit, once-per-instance "reserved slot" or nonce-bound destination commitment so a third party cannot preempt a specific target address between validation and dispatch.

### Proof of Concept
1. Attacker `A` and victim `V` each own one NFT (`nft_A`, `nft_V`), and `target` is currently empty.
2. `V` submits a signed `Call::transfer { to: target }` via `AsScarcity`; `validate()` passes because `NftsByOwner::<T>::contains_key(target) == false` at that moment (see `extension.rs:237-239`).
3. Before `V`'s extrinsic is included, `A` submits `Call::transfer { to: target }` for `nft_A` and it lands earlier in the block (or in a prior block), setting `NftsByOwner::<T>::get(target) == Some(nft_A)`.
4. `V`'s `transfer` dispatches; `ensure!(!NftsByOwner::<T>::contains_key(&to), Error::<T>::AddressOccupied)` fails (`lib.rs:595`).
5. `post_dispatch_details` restores `nft_V` to `V`'s purse and inserts `Locked::<T>::insert(V, LockInfo { retries: 1, until: now + LockPeriod })` (`extension.rs:290-296`).
6. `A` moves `nft_A` off `target` (feeless), and repeats steps 2-5 whenever `V` retries, doubling `V`'s lock duration each time, at zero cost to `A`.

	fn failed_dispatch_lock(previous: Option<LockInfo>) -> LockInfo {
		let retries = previous.map(|lock| lock.retries.saturating_add(1)).unwrap_or(1);
		let exponent = retries.saturating_sub(1);
		let multiplier = 2u64.saturating_pow(u32::from(exponent).min(63));
		LockInfo {
			retries,
			until: T::UnixTime::now()
				.as_secs()
				.saturating_add(multiplier.saturating_mul(T::LockPeriod::get())),
		}
	}
}

	fn prepare(
		self,
		val: Self::Val,
		_origin: &<T as frame_system::Config>::RuntimeOrigin,
		_call: &<T as frame_system::Config>::RuntimeCall,
		_info: &DispatchInfoOf<<T as frame_system::Config>::RuntimeCall>,
		_len: usize,
	) -> Result<Self::Pre, TransactionValidityError> {
		match val {
			Val::NotUsing => Ok(Pre::NotUsing),
			Val::UsingNft { owner, instance, state_nonce } => {
				let nft = NftsByOwner::<T>::try_mutate_exists(
					&owner,
					|maybe_nft| -> Result<Nft, TransactionValidityError> {
						let nft = maybe_nft.as_ref().ok_or(CustomInvalidity::NoNft)?;
						if nft.instance != instance || nft.state_nonce != state_nonce {
							return Err(CustomInvalidity::NftStateMismatch.into());
						}
						// Dispatch assumes the source purse is empty. Taking the NFT here
						// prevents same-block double use and lets post-dispatch restore the exact
						// pre-state if dispatch fails.
						Ok(maybe_nft.take().expect("NFT existence checked above; qed"))
					},
				)?;
				Ok(Pre::UsingNft { owner, nft })
			},
		}
	}

	fn post_dispatch_details(
		pre: Self::Pre,
		_info: &DispatchInfoOf<<T as frame_system::Config>::RuntimeCall>,
		_post_info: &PostDispatchInfoOf<<T as frame_system::Config>::RuntimeCall>,
		_len: usize,
		result: &DispatchResult,

		if let Pre::UsingNft { owner, nft } = pre {
			if result.is_err() {
				NftsByOwner::<T>::insert(&owner, nft);
				Locked::<T>::insert(&owner, Self::failed_dispatch_lock(Locked::<T>::get(&owner)));
			} else {
				Locked::<T>::remove(&owner);
			}
		}
		Ok(Weight::zero())
	}

		pub fn transfer(origin: OriginFor<T>, to: T::AccountId) -> DispatchResultWithPostInfo {
			let Ok(Origin::Nft { owner, nft }) = origin.into() else {
				return Err(DispatchError::BadOrigin.into());
			};
			ensure!(to != owner, Error::<T>::SelfTransfer);
			ensure!(!NftsByOwner::<T>::contains_key(&to), Error::<T>::AddressOccupied);

			let from = owner;
			let state_nonce =
				nft.state_nonce.checked_add(1).ok_or(Error::<T>::StateNonceOverflow)?;
			let nft = Nft { last_moved: T::UnixTime::now().as_secs(), state_nonce, ..nft };
			NftsByOwner::<T>::insert(&to, nft.clone());
			Instances::<T>::insert(nft.instance, &to);
			Self::deposit_event(Event::Transferred { instance: nft.instance, from, to });
			Ok(Pays::No.into())
		}
