### Title
RCE via unrestricted Git transport helpers (`ext::`/`fd::`) in user-controlled remote URLs - (File: `internal/gitaly/service/repository/fetch_remote.go`)

### Summary
`FetchRemote`, `FindRemoteRootRef`, and `CreateRepositoryFromURL` accept an attacker/user-controlled `url` field from an RPC request and pass it, unfiltered, as the value of `remote.<name>.url` (or as an `git clone` positional argument) to a `git` subprocess. Unlike the `logkitty` case where a raw string is spliced into a shell command, here the "insecure formatting" is that Gitaly performs no scheme allow-listing before handing the URL to Git. Git itself supports the `ext::<command>` (and `fd::`) remote helper, which executes an arbitrary shell command string embedded in the URL. Because Gitaly never restricts the set of allowed transports (no `GIT_ALLOW_PROTOCOL`/`protocol.allow`/`protocol.ext.allow` configuration is set anywhere in `internal/git/gitcmd`), a client that can set `RemoteParams.Url` on a mutator RPC can achieve command execution on the Gitaly host.

### Finding Description
In `buildCommandOpts` the raw URL from the request is used directly as a Git config value without validating its scheme: [1](#0-0) 

The only URL handling that inspects the scheme is `GetURLAndResolveConfig`, and it is only invoked when a `resolved_address` is supplied (an optional field, purely used to prevent DNS-rebinding for the four hardcoded schemes `http`, `https`, `git`, `ssh`); when it is *not* set (the common case), the URL passes through untouched: [2](#0-1) 

`validateFetchRemoteRequest` only checks that the URL is non-empty — it does not validate the scheme at all: [3](#0-2) 

The resulting config is injected via safe `GIT_CONFIG_KEY_N`/`GIT_CONFIG_VALUE_N` environment variables (avoiding classic `-c` argv injection): [4](#0-3) 

but this only protects against Git *option* injection — it does nothing to prevent Git from honoring the `ext::` transport helper syntax embedded inside the URL value itself once Git parses `remote.inmemory.url`. `git-fetch(1)`/`git-clone(1)` natively interpret a URL of the form `ext::sh -c "..."` as an instruction to spawn the given shell command as the "remote" transport. Because Gitaly's `commandDescriptions` and flag/positional-argument validation layer (`internal/git/gitcmd/command_description.go`, `internal/git/gitcmd/command.go`) only guards against argv-based flag/option injection — it has no denylist/allowlist for Git's own protocol whitelisting mechanism: [5](#0-4) 

I found no occurrence of `GIT_ALLOW_PROTOCOL`, `protocol.allow`, or `protocol.ext.allow` anywhere in `internal/git/gitcmd`, confirming the transport is not restricted by Gitaly's global Git configuration.

### Impact Explanation
If reachable with an unrestricted URL, this is a direct remote command execution primitive on the Gitaly server process — the same class of vulnerability as the `logkitty` report ("user input formatted inside a command that will be executed without any check"), except here the "command formatting" abuse vector is Git's own `ext::` remote helper syntax rather than a shell string. An attacker able to control `RemoteParams.Url` on `FetchRemote` (e.g., via a GitLab pull-mirror configuration, or via `FindRemoteRootRef`/`UpdateRemoteMirror`, or `CreateRepositoryFromURL`) could execute arbitrary commands as the Gitaly service user, leading to full storage compromise across all repositories on that node (cross-repository object access, credential disclosure of other repos' HTTP auth tokens, and further lateral movement).

### Likelihood Explanation
Reaching `FetchRemote`/`CreateRepositoryFromURL` normally requires the caller to be a privileged internal actor (GitLab Rails, not an anonymous end-user) because these RPCs are protected by Gitaly's standard auth token. However, GitLab exposes pull-mirror URL configuration to project maintainers/owners through the product UI, and that value flows unmodified into `RemoteParams.Url`. Since the report explicitly restricts scope to "ordinary user's push, fetch, fork, import, or crafted RPC field" and pull-mirror URL is exactly such an ordinary-user-controlled RPC field forwarded by GitLab, likelihood is assessed as reasonably high for a determined user with mirror-configuration permissions, though it depends on GitLab-side scheme validation not being present or bypassable (this repo does not contain that layer, so it cannot be verified here — flagged as uncertain).

### Recommendation
Add an explicit allow-list of accepted URL schemes (`http`, `https`, `git`, `ssh`, and scp-like syntax) in `validateFetchRemoteRequest` (and equivalent validators for `CreateRepositoryFromURL`/`FindRemoteRootRef`/`UpdateRemoteMirror`) before the URL reaches Git, rejecting anything else (in particular `ext::`, `fd::`, `file://` where inappropriate). Additionally, set `GIT_ALLOW_PROTOCOL`/`protocol.ext.allow=never` and `protocol.fd.allow=never` globally in the command factory's default Git configuration in `internal/git/gitcmd/command_factory.go` as defense-in-depth so no code path can inadvertently allow dangerous transports.

### Proof of Concept
1. As a user capable of setting a pull-mirror/remote URL (or directly calling the `FetchRemote` RPC with a valid Gitaly auth token), send:
```
FetchRemoteRequest{
  Repository: <any accessible repo>,
  RemoteParams: &Remote{
    Url: "ext::sh -c \"touch /tmp/HACKED\"",
  },
}
```
2. Gitaly sets `remote.inmemory.url=ext::sh -c "touch /tmp/HACKED"` via `GIT_CONFIG_VALUE_N` and runs `git fetch inmemory ...`.
3. Git's `ext` transport helper invokes `sh -c "touch /tmp/HACKED"` on the Gitaly host, confirming arbitrary command execution.

Note: I could not verify from this repository alone whether GitLab's Rails layer independently sanitizes mirror URLs before calling this RPC — that validation, if it exists, lives outside `gitaly--015`. This is flagged as an open uncertainty affecting the practical likelihood assessment.

```go
func buildCommandOpts(ctx context.Context, opts *localrepo.FetchOpts, req *gitalypb.FetchRemoteRequest) error {
	remoteURL := req.GetRemoteParams().GetUrl()
	var config []gitcmd.ConfigPair

	for _, refspec := range getRefspecs(req.GetRemoteParams().GetMirrorRefmaps()) {
		config = append(config, gitcmd.ConfigPair{
			Key: "remote.inmemory.fetch", Value: refspec,
		})
	}

	if resolvedAddress := req.GetRemoteParams().GetResolvedAddress(); resolvedAddress != "" {
		modifiedURL, resolveConfig, err := gitcmd.GetURLAndResolveConfig(remoteURL, resolvedAddress)
		if err != nil {
			return fmt.Errorf("couldn't get curloptResolve config: %w", err)
		}

		remoteURL = modifiedURL
		config = append(config, resolveConfig...)
	}

	config = append(config, gitcmd.ConfigPair{Key: "remote.inmemory.url", Value: remoteURL})
```

```go
func (s *server) validateFetchRemoteRequest(ctx context.Context, req *gitalypb.FetchRemoteRequest) error {
	if err := s.locator.ValidateRepository(ctx, req.GetRepository()); err != nil {
		return structerr.NewInvalidArgument("%w", err)
	}

	if req.GetRemoteParams() == nil {
		return structerr.NewInvalidArgument("missing remote params")
	}

	if req.GetRemoteParams().GetUrl() == "" {
		return structerr.NewInvalidArgument("blank or empty remote URL")
	}

	return nil
}
```

```go
func GetURLAndResolveConfig(remoteURL string, resolvedAddress string) (string, []ConfigPair, error) {
	if remoteURL == "" {
		return "", nil, fmt.Errorf("URL is empty")
	}

	if resolvedAddress == "" {
		return "", nil, fmt.Errorf("resolved address is empty")
	}

	resolvedIP := net.ParseIP(resolvedAddress)
	if resolvedIP == nil {
		return "", nil, fmt.Errorf("resolved address has invalid IPv4/IPv6 address")
	}

	switch {
	case strings.HasPrefix(remoteURL, "http://"), strings.HasPrefix(remoteURL, "https://"), strings.HasPrefix(remoteURL, "git://"):
		return getURLAndResolveConfigForURL(remoteURL, resolvedAddress)
	case strings.HasPrefix(remoteURL, "ssh://"):
		return getURLAndResolveConfigForSSH(remoteURL, resolvedAddress)
	default:
		return getURLAndResolveConfigForSCP(remoteURL, resolvedAddress)
	}
```

```go
// ConfigPair is a GlobalOption that can be passed to Git commands to inject per-command config
// entries via the `git -c` switch.
type ConfigPair = config.GitConfig

// ConfigPairsToGitEnvironment converts the given config pairs into a set of environment variables
// that can be injected into a Git executable.
func ConfigPairsToGitEnvironment(configPairs []ConfigPair) []string {
	env := make([]string, 0, len(configPairs)*2+1)

	for i, configPair := range configPairs {
		env = append(env,
			fmt.Sprintf("GIT_CONFIG_KEY_%d=%s", i, configPair.Key),
			fmt.Sprintf("GIT_CONFIG_VALUE_%d=%s", i, configPair.Value),
		)
	}

	return append(env, fmt.Sprintf("GIT_CONFIG_COUNT=%d", len(configPairs)))
}
```
