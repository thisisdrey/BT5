### No vulnerability found for this question.

`Pips::invert` correctly computes `MAX - fee` [1](#0-0)  and `TokenDiff::supply_delta` applies it as `delta * (MAX - fee) / MAX` via `checked_mul_div_ceil`, exactly matching the claimed binding, with no divergence introduced by the inversion itself [2](#0-1) .

The only way `fee` could approach `Pips::MAX` is through `FeesManager::set_fee`, which is gated by `#[access_control_any(roles(Role::DAO, Role::FeesManager))]` and requires `assert_one_yocto()`, making it unreachable for an unprivileged signer [3](#0-2) . `TokenDiff::execute_intent` only reads the fee via `engine.state.fee()`, it never lets the signer supply or influence the fee value used in `supply_delta`/`token_fee` [4](#0-3) .

Since no unprivileged path exists to set or influence `protocol_fee`, the described vector is confirmed non-adversarial per the question's own binding condition, and there is no exploitable path for an unprivileged attacker.

```rust
    /// Returns total supply delta from token delta
    #[inline]
    fn supply_delta(token_id: &TokenId, delta: i128, fee: Pips) -> Option<i128> {
        if delta < 0 {
            // fee is taken only on negative deltas (i.e. token_in)
            delta.checked_mul_div_ceil(
                Self::token_fee(token_id, delta.unsigned_abs(), fee)
                    .invert()
                    .as_pips()
                    .into(),
                Pips::MAX.as_pips().into(),
            )
        } else {
            // token_out
            Some(delta)
        }
    }
```
