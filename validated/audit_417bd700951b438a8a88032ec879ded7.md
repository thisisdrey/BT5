### Title
Attacker-Controlled `data_url` in Handshake Enables SSRF via Block/Microblock Download and Neighbor RPC - (File: stackslib/src/net/chat.rs, stackslib/src/net/download/epoch2x.rs, stackslib/src/net/neighbors/rpc.rs)

### Summary
A remote peer can advertise an arbitrary `data_url` in its P2P `Handshake` message. This URL is accepted with only superficial validation (scheme/host/username/query/fragment checks) and is later used, without any private/loopback/link-local IP filtering, as the destination for outbound HTTP block/microblock downloads (`stackslib/src/net/download/epoch2x.rs`) and for `NeighborRPC` requests (`stackslib/src/net/neighbors/rpc.rs`). This is a server-side request forgery: the victim node can be made to issue outbound HTTP GET/POST requests to attacker-chosen internal addresses (e.g., `127.0.0.1`, RFC1918 ranges, cloud metadata IPs), unlike the mempool-sync code path which explicitly blocks private ranges.

### Finding Description
`HandshakeData.data_url` is fully attacker-controlled and is validated only by `UrlString::parse_to_block_url`, which checks scheme (`http`/`https`), absence of userinfo, and absence of query/fragment — it does **not** reject private, loopback, link-local, or metadata-service addresses: [1](#0-0) 

The value is stored on the conversation (`convo.data_url`) after handshake processing and later resolved to a `SocketAddr` in `try_decode_data_url_ipaddr`/`try_resolve_data_url_host`, without any private-range filter: [2](#0-1) 

This `data_url` is then used directly to build block/microblock download requests: [3](#0-2) 

and dispatched via `PeerNetwork::begin_request` → `connect_or_send_http_request` → `connect_http`, which opens a raw TCP connection to the resolved address and sends a crafted `StacksHttpRequest` with no private-IP check anywhere in this path: [4](#0-3) [5](#0-4) [6](#0-5) 

The same unfiltered `convo.data_url`/`data_ip` is used by `NeighborRPC::send_request` (used for Nakamoto-era RPC calls to neighbors): [7](#0-6) 

By contrast, the mempool-sync code path explicitly recognizes this danger and blocks private-range destinations before connecting, unless `private_neighbors` is enabled: [8](#0-7) 

The existence of this check in one path but not the others (block/microblock download, neighbor RPC) indicates an inconsistency/omission rather than an intentional design choice, breaking the intended invariant that "the node will avoid initiating connections to peers/URLs with private IPs" unless the user opts in via `private_neighbors`: [9](#0-8) 

### Impact Explanation
A malicious peer that establishes a P2P handshake with the victim node (no special privilege beyond speaking the P2P handshake protocol) can set its `data_url` to point at an internal-only or loopback service. When the victim later attempts to download a block/microblock from this peer (a common, automatic operation) or issue a Neighbor RPC, the node will connect to and send an HTTP request toward the attacker-chosen address/port, carrying node-crafted headers/paths. This can be used to:
- Probe or interact with internal services not otherwise reachable from the network (port scanning, triggering internal admin actions).
- Reach loopback services on the node's own host (e.g., other local daemons, RPC endpoints bound to `127.0.0.1`) bypassing network-level access controls.
- Potentially exfiltrate information if any part of the internal response leaks back through error logging/metrics that are externally observable, though blind SSRF is already impactful as a confused-deputy request forgery against the node's own trust boundary.

This qualifies as a High-impact issue: an unauthenticated/low-privilege remote peer forces the node into unauthorized outbound network actions against internal-only targets, a capability the maintainers already recognized as dangerous (given the explicit mitigation in mempool sync).

### Likelihood Explanation
Likelihood is high: any peer that can complete (or attempt) a Handshake can set an arbitrary `data_url`; there is no signature or endorsement of the URL beyond the peer's own handshake signature (which only proves peer identity, not URL legitimacy). Block/microblock downloading and Nakamoto neighbor RPC calls are routine, automatic node behaviors that will use this attacker-supplied URL without operator interaction.

### Recommendation
Apply the same private/loopback/link-local IP filtering used in mempool sync (`PeerAddress::is_in_private_range()` gated by `connection_opts.private_neighbors`) uniformly to every code path that resolves and connects to a peer-supplied `data_url`, specifically:
- `stackslib/src/net/download/epoch2x.rs::begin_request` / `connect_or_send_http_request`.
- `stackslib/src/net/neighbors/rpc.rs::send_request`.
- Any other consumer of `convo.data_url`/`data_ip` (e.g., `stackerdb` sync paths) should be audited for the same check.

### Proof of Concept
1. Attacker node completes a valid P2P handshake with the victim, setting `HandshakeData.data_url` to `http://127.0.0.1:<internal-port>/` or an RFC1918 address hosting an internal service.
2. Attacker advertises blocks/microblocks (or otherwise causes the victim to want data from this peer) so that `BlockDownloader::block_dns_lookups_begin`/`dns_lookups_begin` resolves this literal IP (`epoch2x.rs:308-362`, no DNS needed since it's a bare IP) and enqueues a `BlockRequestKey` using this URL (`epoch2x.rs:1452-1468`).
3. `PeerNetwork::begin_request` pops the request and calls `connect_or_send_http_request(url, addr, request)` (`epoch2x.rs:1916-1957`), which opens a TCP connection to `127.0.0.1:<internal-port>` and sends a crafted Stacks HTTP request (`httpcore.rs:1873-1911`, `server.rs:118-150`) — with no check against `is_in_private_range()`.
4. Compare against `mempool_sync_send_query`, which would have refused to connect to this same private address (`mempool/mod.rs:485-498`), confirming the block-download/RPC paths lack the equivalent guard.

impl UrlString {
    /// Determine that the UrlString parses to something that can be used to fetch blocks via HTTP(S).
    /// A block URL must be an HTTP(S) URL without a query or fragment, and without a login.
    pub fn parse_to_block_url(&self) -> Result<url::Url, codec_error> {
        // even though this code uses from_utf8_unchecked() internally, we've already verified that
        // the bytes in this string are all ASCII.
        let url = url::Url::parse(&self.to_string())
            .map_err(|e| codec_error::DeserializeError(format!("Invalid URL: {:?}", &e)))?;

        if url.scheme() != "http" && url.scheme() != "https" {
            return Err(codec_error::DeserializeError(format!(
                "Invalid URL: invalid scheme '{}'",
                url.scheme()
            )));
        }

        if !url.username().is_empty() || url.password().is_some() {
            return Err(codec_error::DeserializeError(
                "Invalid URL: must not contain a username/password".to_string(),
            ));
        }

        if url.host_str().is_none() {
            return Err(codec_error::DeserializeError(
                "Invalid URL: no host string".to_string(),
            ));
        }

        if url.query().is_some() {
            return Err(codec_error::DeserializeError(
                "Invalid URL: query strings not supported for block URLs".to_string(),
            ));
        }

        if url.fragment().is_some() {
            return Err(codec_error::DeserializeError(
                "Invalid URL: fragments are not supported for block URLs".to_string(),
            ));
        }

        Ok(url)
    }

impl PeerNetwork {
    /// Send a (non-blocking) HTTP request to a remote peer.
    /// Returns the event ID on success.
    #[cfg_attr(test, mutants::skip)]
    pub fn connect_or_send_http_request(
        &mut self,
        data_url: UrlString,
        addr: SocketAddr,
        request: StacksHttpRequest,
    ) -> Result<usize, NetError> {
        PeerNetwork::with_network_state(self, |ref mut network, ref mut network_state| {
            PeerNetwork::with_http(network, |ref mut network, ref mut http| {
                match http.connect_http(
                    network_state,
                    network,
                    data_url.clone(),
                    addr,
                    Some(request.clone()),
                ) {
                    Ok(event_id) => Ok(event_id),
                    Err(NetError::AlreadyConnected(event_id, _)) => {
                        if let (Some(ref mut convo), Some(ref mut socket)) =
                            http.get_conversation_and_socket(event_id)
                        {
                            convo.send_request(request)?;
                            HttpPeer::saturate_http_socket(socket, convo)?;
                            Ok(event_id)
                        } else {
                            debug!("HTTP failed to connect to {data_url}, {addr:?}");
                            Err(NetError::PeerNotConnected(format!(
                                "HTTP failed to connect to {data_url}, {addr:?}",
                            )))
                        }
                    }
                    Err(e) => Err(e),
                }
            })
        })
    }

    pub fn connect_http(
        &mut self,
        network_state: &mut NetworkState,
        network: &PeerNetwork,
        data_url: UrlString,
        addr: SocketAddr,
        request: Option<StacksHttpRequest>,
    ) -> Result<usize, net_error> {
        if let Some(event_id) = self.find_free_conversation(&data_url) {
            let http_nk = NeighborKey {
                peer_version: network.burnchain.peer_version,
                network_id: network.local_peer.network_id,
                addrbytes: PeerAddress::from_socketaddr(&addr),
                port: addr.port(),
            };
            return Err(net_error::AlreadyConnected(event_id, http_nk));
        }

        let sock = NetworkState::connect(
            &addr,
            network.connection_opts.socket_send_buffer_size,
            network.connection_opts.socket_recv_buffer_size,
        )?;
        let hint_event_id = network_state.next_event_id()?;
        let next_event_id =
            network_state.register(self.http_server_handle, hint_event_id, &sock)?;

        self.connecting.insert(
            next_event_id,
            (sock, Some(data_url), request, get_epoch_time_secs()),
        );
        Ok(next_event_id)
    }
