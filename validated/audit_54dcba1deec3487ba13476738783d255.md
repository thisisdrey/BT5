### Title
Users can withdraw debt-locked collateral through `NativeTokenGateway.withdraw` - ([File: contracts/NativeTokenGateway.sol](contracts/NativeTokenGateway.sol))

### Summary
`NativeTokenGateway.withdraw` transfers a user’s `DepositToken` shares to the gateway and then calls `DepositToken.withdraw` as the gateway. `DepositToken.withdraw` evaluates whether the unlocked balance is sufficient using the gateway—not the original borrower—so a borrower can withdraw collateral that is supposed to secure their outstanding debt and leave the pool insolvent. [1](#0-0) [2](#0-1) 

### Finding Description
The gateway first transfers `amount_` deposit tokens from the user to itself. [3](#0-2) 

It then calls `_depositToken.withdraw(amount_, address(this))`. Inside `DepositToken.withdraw`, `_msgSender()` is the gateway, and `_revertIfLocked(_msgSender, amount_)` checks the gateway’s debt position instead of the user’s. [4](#0-3) [2](#0-1) 

Because the gateway normally has no Metronome debt, `unlockedBalanceOf(gateway)` returns its full transferred deposit-token balance. The withdrawal therefore burns the gateway-held shares and pulls underlying collateral from the treasury even though the user retains their debt position. [5](#0-4) [6](#0-5) 

The same account-substitution pattern exists in `VesperGateway.withdraw`, which also moves user shares to the gateway and invokes `DepositToken.withdraw` from the gateway address. [7](#0-6) 

### Impact Explanation
An unprivileged borrower can remove all collateral backing an open debt position without repaying the debt. This breaks the solvency invariant that withdrawals must preserve `debt <= collateralFactor * collateralValue`, turning collateralized debt into bad debt and causing direct protocol insolvency. [8](#0-7) [6](#0-5) 

### Likelihood Explanation
Only normal ERC20 approval and two public calls are required: `approve(gateway, shares)` followed by `NativeTokenGateway.withdraw(pool, shares)`. No privileged actor, oracle manipulation, flash loan, malicious LayerZero endpoint, or nonstandard collateral behavior is needed. [1](#0-0) 

The relevant gateway path is guarded only by pool registration and a gateway-level transient reentrancy lock; neither checks the original user’s resulting health. `DepositToken.withdraw` also does not check the beneficiary or initiator because it assumes the token owner is the caller. [1](#0-0) [2](#0-1) 

### Recommendation
Do not withdraw through an intermediary address after transferring shares. Either:

- Make the gateway call a dedicated function that validates and burns collateral against the original user while sending proceeds to the gateway.
- Or pass the original account through the withdrawal path and call `_revertIfLocked(originalUser, amount_)` before burning.
- After every gateway withdrawal, additionally verify `pool.debtPositionOf(originalUser)` remains healthy.

Apply the same correction to `VesperGateway.withdraw`. [7](#0-6) 

### Proof of Concept
The following Hardhat/Foundry-style sequence demonstrates the invariant break on a mainnet fork using deployed contract addresses:

```solidity
// pool: registered Pool
// debtToken: debt token for an issued synthetic asset
// syntheticToken: issued synthetic asset
// depositToken: DepositToken whose underlying is WETH/nativeToken
// gateway: PoolRegistry.nativeTokenGateway()
// user: attacker-controlled account with collateral and debt

uint256 shares = depositToken.balanceOf(user);

// The user's shares are locked by outstanding debt.
assertLt(depositToken.unlockedBalanceOf(user), shares);
assertGt(debtToken.balanceOf(user), 0);

// Gateway is approved to receive deposit-token shares.
depositToken.approve(address(gateway), shares);

uint256 treasuryBefore = depositToken.underlying().balanceOf(
    address(pool.treasury())
);
uint256 userNativeBefore = user.balance;
uint256 userDebtBefore = debtToken.balanceOf(user);

// Gateway takes custody of shares and withdraws using its own
// account context, bypassing the user's lock check.
gateway.withdraw(pool, shares);

// User received native collateral while retaining the debt.
assertGt(user.balance, userNativeBefore);
assertEq(debtToken.balanceOf(user), userDebtBefore);
assertLt(
    depositToken.underlying().balanceOf(address(pool.treasury())),
    treasuryBefore
);

(bool healthy,,,,) = pool.debtPositionOf(user);
assertFalse(healthy); // Protocol now holds debt without collateral.
```

The critical trace is `NativeTokenGateway.withdraw -> DepositToken.transferFrom(user, gateway) -> DepositToken.withdraw`, where `DepositToken.withdraw` checks `unlockedBalanceOf(gateway)` rather than `unlockedBalanceOf(user)`. [1](#0-0) [2](#0-1)
