Audit Report

## Title
Unvalidated, User-Controlled `gas` Field in Snowbridge V2 `CallContract` Command Enables Underpriced Ethereum Dispatch Work - (File: `bridges/snowbridge/primitives/outbound-queue/src/v2/message.rs`)

## Summary
In the Snowbridge V2 outbound XCM converter, the `gas` field of a `ContractCall::V1` `Transact` payload is decoded from attacker-controlled XCM bytes and passed unbounded into `Command::CallContract`, which `ConstantGasMeter::maximum_dispatch_gas_used_at_most` then returns verbatim as `*gas_limit` with no cap. This value is completely decoupled from the `fee` computed by `extract_remote_fee()`, which derives from a separate, independently attacker-chosen `PayFees`/reserved-asset amount, so a message can declare an arbitrarily large dispatch-gas budget while paying an arbitrarily small fee.

## Finding Description
`XcmConverter::convert` in `bridges/snowbridge/primitives/outbound-queue/src/v2/converter/convert.rs` decodes the `Transact` call bytes into `ContractCall::V1 { target, calldata, gas, value }` and pushes `Command::CallContract { gas, .. }` with no bound check on `gas` (lines 294-305 of that file). `ConstantGasMeter::maximum_dispatch_gas_used_at_most` in `bridges/snowbridge/primitives/outbound-queue/src/v2/message.rs` (lines 289-306) returns `*gas_limit` unchanged for `Command::CallContract`, in contrast to every other command variant, which uses a fixed, hard-coded gas constant. The `fee` attached to the message is computed earlier in `convert()` via `extract_remote_fee()`, purely from the `WithdrawAsset`/`PayFees` Ether amounts in the message, with no cross-check against the `gas` value declared later in the same message. [1](#0-0) [2](#0-1) [3](#0-2) 

Critically, the reachability premise of this claim — that `AllowedAliasOrigin` permits ordinary, unprivileged parachain-origin senders — is confirmed by the actual production runtime configuration. `bridge-hub-westend`'s `SnowbridgeExporterV2` type instantiates `EthereumBlobExporterV2` with `AllowedAliasOrigin = EverythingBut<Equals<AssetHubLocation>>`, i.e., **any** location except Asset Hub itself is permitted to alias, which was intentionally designed to let AH act as a proxy for arbitrary bridged/sibling-chain origins per the documented `AliasOrigin` semantics. [4](#0-3)  This is a deliberate defense-in-depth measure against origin-spoofing of the AH sovereign account specifically, not a general privilege gate [5](#0-4) , meaning any non-AH origin permitted through XCM (including ordinary sibling parachain-sourced, non-governance flows) can reach the `CallContract` path.

I was unable to fully verify within available tool budget whether `bridges/snowbridge/pallets/outbound-queue-v2/src/lib.rs`'s `do_process_message`/validate logic imposes any additional bound on `max_dispatch_gas` or cross-checks it against the committed `fee` before committing the message on-chain; grep results for `max_dispatch_gas`/`MaxDispatchGas` in that pallet returned only a single unexamined match, and I could not read the file contents to confirm the absence of such a check due to tool errors in the final iteration. Based on all code paths I could inspect (`convert.rs`, `message.rs`, `mod.rs` of the v2 primitives crate), no such check exists in the conversion or gas-metering logic itself.

## Impact Explanation
This matches the "public underpriced work" class in the impact gate: the promised Ethereum-side dispatch-gas budget (`max_dispatch_gas`, sourced from `Command::CallContract.gas`) is not backed by a commensurate fee, since `gas` and `fee` derive from two independent user-controlled inputs with no cross-validation. This can degrade the bridge's economic model for relayers processing `CallContract` messages, and is reachable via the standard XCM `Transact`/`AliasOrigin`/`InitiateTransfer` flow available to any non-AH origin permitted by the `EverythingBut<Equals<AssetHubLocation>>` filter in the production `bridge-hub-westend` runtime.

## Likelihood Explanation
Medium-to-high. The `AllowedAliasOrigin` filter in the live runtime is confirmed to be broad (`EverythingBut<Equals<AssetHubLocation>>`), so the claim's premise that unprivileged, non-AH origins can reach `CallContract` is substantiated by the actual runtime code, not speculation. The remaining uncertainty is whether `outbound-queue-v2` pallet-level logic (unverified due to tooling limits in this session) independently caps `max_dispatch_gas` or requires `fee` to scale with `gas`; if no such pallet-level check exists, the finding is fully live.

## Recommendation
- Enforce an explicit maximum bound on `ContractCall::V1.gas` (e.g. a `MaxCallContractGas` config constant) in `XcmConverter::convert` before constructing `Command::CallContract`.
- Tie the fee/reward computation to the declared `gas`, analogous to `fee_per_gas` usage elsewhere, so that `fee < gas * fee_per_gas` is rejected rather than treating `fee` and `gas` as independent inputs.
- Add regression tests in `bridges/snowbridge/primitives/outbound-queue/src/v2/converter/tests.rs` asserting that oversized `gas` values are rejected, or that fee is validated against declared gas at conversion time.

## Proof of Concept
1. From any parachain origin permitted by `AllowedAliasOrigin` (i.e., any location other than Asset Hub itself, per the live `bridge-hub-westend` config), construct an XCM with `WithdrawAsset`, `PayFees` (minimal Ether amount), `AliasOrigin`, `DepositAsset`, and a `Transact` instruction whose call decodes to `ContractCall::V1 { target, calldata: vec![], value: 0, gas: u64::MAX }`, followed by `SetTopic`.
2. Submit via `PolkadotXcm::execute`/`send`, following the pattern used in `cumulus/parachains/integration-tests/emulated/tests/bridges/bridge-hub-westend/src/tests/snowbridge_v2_outbound.rs` (lines 543-572), but with `gas: u64::MAX` and a minimal `PayFees` amount instead of `gas: 40000`.
3. `XcmConverter::convert` accepts the message and constructs `Command::CallContract { gas: u64::MAX, .. }` with no bound check.
4. `ConstantGasMeter::maximum_dispatch_gas_used_at_most` returns `u64::MAX` verbatim for this command, demonstrating the decoupling between the promised gas work and the paid fee.
