### Title
CA-pool time bound checks fail closed, permanently disabling all handshakes and connections network-wide when the root CA passes `NotAfter`/`NotBefore` - ([File: cert/ca_pool.go])

### Summary
Nebula's certificate verification path unconditionally rejects a certificate if its signing root CA is expired (or not yet valid) relative to local wall-clock time, with no fallback, grace period, or secondary trust path. This is the same failure pattern as the reported oracle bug: a hard bound check (`minPrice <= price <= maxPrice`) that, once the real-world value legitimately moves outside the hardcoded range, causes the core function (swaps / here, handshakes) to fail for everyone, network-wide, with no recovery mechanism.

### Finding Description
`CAPool.verify` performs an unconditional, hard-fail time check against the root CA before any per-certificate reasoning: [1](#0-0) 

```
if signer.Certificate.Expired(now) {
    return nil, ErrRootExpired
}
if c.Expired(now) {
    return nil, ErrExpired
}
```

`Expired` is a strict `NotBefore`/`NotAfter` bound check with no tolerance: [2](#0-1) 

This `verify` function is reached from every handshake, via `HandshakeManager.certVerifier`, which is invoked for every incoming/outgoing handshake attempt using `time.Now()`: [3](#0-2) 

and from `handshake.Machine.validateCert`, which fails the entire handshake state machine (`m.failed = true`) if verification errors: [4](#0-3) 

Once a root CA certificate crosses its `NotAfter` boundary (or, symmetrically, if clock skew pushes `now` before `NotBefore`), `signer.Certificate.Expired(now)` becomes `true` for *every* certificate ever issued by that CA. There is no secondary CA fallback, no cached-good-price-style "keep the last valid state," and no grace window — exactly the same rigid design choice the audit criticized in `Unitas.sol`'s `_checkPrice`. The `loadCAPoolFromConfig` startup path shows Nebula is aware CAs can be individually expired and tolerates *some* expired CAs at load time only if others remain valid, but the runtime per-handshake check has no equivalent tolerance — it is a flat go/no-go gate with a single global variable (wall-clock `now`) as the sole input, with no bounds correction or secondary oracle equivalent, unlike what the sponsor discussion in the referenced report recommended ("use a secondary oracle... store the last fetched value").

The blast radius is compounded by `connection_manager`'s periodic re-verification: `isInvalidCertificate` (in `connection_manager.go`, `disconnectInvalid`) re-checks live tunnels' peer certificates against the current CA pool and tears down connections whose certs no longer verify, meaning this isn't limited to blocking *new* handshakes — established tunnels get disconnected too once the root passes its bound, mirroring the oracle bug's total core-functionality outage ("core functionality... will fail to work... any token they fetch depegs").

### Impact Explanation
Once the CA's `NotAfter` is reached (a deterministic, externally-observable event, not requiring any attacker action — same class of triggering condition as the price depeg in the referenced report), the entire mesh becomes unable to establish or maintain any tunnel: every certificate ever signed by that CA is rejected at every handshake and at every periodic revalidation. This is a full network-wide denial of service of Nebula's core function (secure tunnel establishment/authentication), reachable without possessing any valid CA-signed certificate, since the failure occurs deterministically for anyone attempting a handshake once the time bound is crossed. It also affects clock-skew edge cases symmetrically for `NotBefore`.

### Likelihood Explanation
This condition is deterministic and inevitable over the CA's lifetime (every deployed nebula network eventually crosses its CA's `NotAfter` unless proactively rotated), and clock-skew-triggered `NotBefore` failures are plausible in any fleet with imperfect time sync. Unlike a targeted exploit, likelihood here is "eventually certain" rather than probabilistic, which matches the "medium, acknowledged, won't-fix, but real" characterization in the referenced report — the protocol/operator is expected to rotate CAs proactively, but the code offers no automatic mitigation, grace period, or secondary trust anchor if that operational discipline lapses.

### Recommendation
- Support and exercise multi-CA overlap so a new CA is trusted well before the old one's `NotAfter`, with tooling/warnings that fire before the boundary is reached (the codebase already supports multiple CAs in a pool; the gap is the lack of automated warning/rotation enforcement or grace-period tolerance in `verify`/`Expired`).
- Consider a configurable grace window (analogous to storing a last-known-good state) for root CA expiry so that a lapsed rotation degrades gracefully (e.g. warn + continue for a bounded period) rather than hard-failing every handshake and tearing down every live tunnel immediately.
- Emit proactive, loud operational alerts (already partially present via `l.Warn("expired certificate present in CA pool", ...)` in `pki.go`) well ahead of `NotAfter`, and ensure `isInvalidCertificate`'s teardown-on-CA-expiry behavior is prominently documented as an operational hazard.

### Proof of Concept
1. Stand up a Nebula network signed by a CA certificate with a `NotAfter` set to `T`.
2. Allow wall-clock time to pass `T` without rotating/adding a new trusted CA to `pki.ca`.
3. Observe: `CAPool.verify` returns `ErrRootExpired` for every certificate signed by that CA (`cert/ca_pool.go:224-226`), so `HandshakeManager.certVerifier` fails all new handshakes (`handshake_manager.go:1161-1166`, `handshake/machine.go:371-379`), and `connection_manager`'s periodic `disconnectInvalid` check tears down existing tunnels whose peer certs no longer verify. The entire mesh loses all connectivity simultaneously and permanently until an administrator manually rotates the CA — the direct network-authentication analog of "if any stable depegs, oracle will fail, disabling swaps."

```go
func (ncp *CAPool) verify(c Certificate, now time.Time, certFp string, signerFp string) (*CachedCertificate, error) {
	if ncp.IsBlocklisted(certFp) {
		return nil, ErrBlockListed
	}

	signer, err := ncp.GetCAForCert(c)
	if err != nil {
		return nil, err
	}

	if signer.Certificate.Curve() != c.Curve() {
		return nil, ErrCurveMismatch
	}

	if signer.Certificate.Expired(now) {
		return nil, ErrRootExpired
	}

	if c.Expired(now) {
		return nil, ErrExpired
	}
```
