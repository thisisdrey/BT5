### Title
Missing `chain_id` in `SignerCapabilityOfferProofChallengeV2` Enables Cross-Chain Signature Replay to Hijack Mainnet Account Signer Capability — (`aptos-move/framework/aptos-framework/sources/account/account.move`)

---

### Summary

`SignerCapabilityOfferProofChallengeV2`, the signed message used in `offer_signer_capability`, omits a `chain_id` field. Its sibling struct `RotationCapabilityOfferProofChallengeV2` was explicitly upgraded to include `chain_id` to prevent cross-chain replay, but the signer-capability variant was never given the same fix. An attacker who obtains a victim's valid `offer_signer_capability` signature from any other Aptos network (testnet, devnet) can replay it on mainnet to register themselves as the authorized signer for the victim's account, then call `create_authorized_signer` to obtain a live signer and drain all assets.

---

### Finding Description

`RotationCapabilityOfferProofChallengeV2` carries a `chain_id` field and its comment explicitly states this was added to prevent replay:

```move
/// This V2 struct adds the `chain_id` and `source_address` to the challenge message,
/// which prevents replaying the challenge message.
struct RotationCapabilityOfferProofChallengeV2 has drop {
    chain_id: u8,
    sequence_number: u64,
    source_address: address,
    recipient_address: address,
}
``` [1](#0-0) 

`SignerCapabilityOfferProofChallengeV2`, however, has no `chain_id`:

```move
struct SignerCapabilityOfferProofChallengeV2 has copy, drop {
    sequence_number: u64,
    source_address: address,
    recipient_address: address,
}
``` [2](#0-1) 

`offer_signer_capability` constructs this challenge and verifies the signature without any chain binding:

```move
let proof_challenge = SignerCapabilityOfferProofChallengeV2 {
    sequence_number: get_sequence_number(source_address),
    source_address,
    recipient_address,
};
verify_signed_message(
    source_address, account_scheme, account_public_key_bytes, signer_capability_sig_bytes, proof_challenge);
``` [3](#0-2) 

The `verify_signed_message` helper uses `ed25519::signature_verify_strict_t` / `multi_ed25519::signature_verify_strict_t`, which prepend a BCS type-name domain separator (`aptos_framework::account::SignerCapabilityOfferProofChallengeV2`). This type name is identical on every Aptos network, so it provides no chain binding. [4](#0-3) 

Once the replayed signature is accepted, `offer_signer_capability` writes the attacker's address into the victim's `signer_capability_offer.for` slot. The attacker then calls `create_authorized_signer`, which returns a live `signer` for the victim's address:

```move
public fun create_authorized_signer(account: &signer, offerer_address: address): signer acquires Account {
    ...
    assert!(account_resource.signer_capability_offer.for.contains(&addr), ...);
    create_signer(offerer_address)
}
``` [5](#0-4) 

---

### Impact Explanation

With a live `signer` for the victim's mainnet account, the attacker can execute arbitrary Move entry functions as the victim: transfer APT, transfer fungible assets, rotate the authentication key (locking the victim out permanently), publish modules under the victim's address, or interact with any protocol that accepts a signer. This constitutes direct theft and permanent freezing of user-controlled on-chain assets.

---

### Likelihood Explanation

The precondition is that the victim has previously signed a `SignerCapabilityOfferProofChallengeV2` on any non-mainnet Aptos network (testnet chain_id=2, devnet chain_id=34, etc.) with the same `sequence_number` as their mainnet account. This is trivially satisfied for any account that has never transacted on mainnet (sequence_number=0 on both networks). Developers and power users routinely test on testnet before mainnet, making this a realistic and common scenario. The attacker only needs to observe the testnet transaction (public mempool/explorer) to extract the signature bytes.

---

### Recommendation

Add `chain_id: u8` to `SignerCapabilityOfferProofChallengeV2` and populate it from `chain_id::get()` inside `offer_signer_capability`, exactly as was done for `RotationCapabilityOfferProofChallengeV2`:

```move
struct SignerCapabilityOfferProofChallengeV2 has copy, drop {
    chain_id: u8,          // <-- add this
    sequence_number: u64,
    source_address: address,
    recipient_address: address,
}
```

```move
let proof_challenge = SignerCapabilityOfferProofChallengeV2 {
    chain_id: chain_id::get(),   // <-- add this
    sequence_number: get_sequence_number(source_address),
    source_address,
    recipient_address,
};
``` [6](#0-5) 

---

### Proof of Concept

1. Alice holds a mainnet account at address `A` with `sequence_number = 0`.
2. Alice also has a testnet account at the same address `A` (same keypair, `sequence_number = 0`).
3. On testnet, Alice legitimately calls `offer_signer_capability` to offer Bob (`B`) signer capability. The signed `SignerCapabilityOfferProofChallengeV2` is `{ sequence_number: 0, source_address: A, recipient_address: B }`. The signature `σ` is visible in the testnet transaction.
4. Attacker (controlling address `B`) submits a mainnet transaction calling `offer_signer_capability(alice_signer, σ, 0, alice_pk, B)`.
5. Mainnet `offer_signer_capability` reconstructs `{ sequence_number: 0, source_address: A, recipient_address: B }` — identical bytes to the testnet challenge — and `verify_signed_message` accepts `σ`.
6. Alice's mainnet `Account.signer_capability_offer.for` is now set to `B`.
7. Attacker calls `create_authorized_signer(&bob_signer, A)` and receives a `signer` for address `A`.
8. Attacker calls `aptos_account::transfer(&victim_signer, attacker_address, balance)` to drain Alice's mainnet APT. [7](#0-6)

    public entry fun offer_signer_capability(
        account: &signer,
        signer_capability_sig_bytes: vector<u8>,
        account_scheme: u8,
        account_public_key_bytes: vector<u8>,
        recipient_address: address
    ) acquires Account {
        let source_address = signer::address_of(account);
        ensure_resource_exists(source_address);
        assert!(exists_at(recipient_address), error::not_found(EACCOUNT_DOES_NOT_EXIST));

        // Proof that this account intends to delegate its signer capability to another account.
        let proof_challenge = SignerCapabilityOfferProofChallengeV2 {
            sequence_number: get_sequence_number(source_address),
            source_address,
            recipient_address,
        };
        verify_signed_message(
            source_address, account_scheme, account_public_key_bytes, signer_capability_sig_bytes, proof_challenge);

        // Update the existing signer capability offer or put in a new signer capability offer for the recipient.
        let account_resource = &mut Account[source_address];
        account_resource.signer_capability_offer.for.swap_or_fill(recipient_address);
    }

    public fun verify_signed_message<T: drop>(
        account: address,
        account_scheme: u8,
        account_public_key: vector<u8>,
        signed_message_bytes: vector<u8>,
        message: T,
    ) acquires Account {
        let auth_key = get_authentication_key(account);
        // Verify that the `SignerCapabilityOfferProofChallengeV2` has the right information and is signed by the account owner's key
        if (account_scheme == ED25519_SCHEME) {
            let pubkey = ed25519::new_unvalidated_public_key_from_bytes(account_public_key);
            let expected_auth_key = ed25519::unvalidated_public_key_to_authentication_key(&pubkey);
            assert!(
                auth_key == expected_auth_key,
                error::invalid_argument(EWRONG_CURRENT_PUBLIC_KEY),
            );

            let signer_capability_sig = ed25519::new_signature_from_bytes(signed_message_bytes);
            assert!(
                ed25519::signature_verify_strict_t(&signer_capability_sig, &pubkey, message),
                error::invalid_argument(EINVALID_PROOF_OF_KNOWLEDGE),
            );
        } else if (account_scheme == MULTI_ED25519_SCHEME) {
            let pubkey = multi_ed25519::new_unvalidated_public_key_from_bytes(account_public_key);
            let expected_auth_key = multi_ed25519::unvalidated_public_key_to_authentication_key(&pubkey);
            assert!(
                auth_key == expected_auth_key,
                error::invalid_argument(EWRONG_CURRENT_PUBLIC_KEY),
            );

            let signer_capability_sig = multi_ed25519::new_signature_from_bytes(signed_message_bytes);
            assert!(
                multi_ed25519::signature_verify_strict_t(&signer_capability_sig, &pubkey, message),
                error::invalid_argument(EINVALID_PROOF_OF_KNOWLEDGE),
            );
        } else {
            abort error::invalid_argument(EINVALID_SCHEME)
        };
    }
