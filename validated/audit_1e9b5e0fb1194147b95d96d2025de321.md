### Title
Guard Representative (genesis witness) reward tokens are permanently locked because `WithdrawBalanceActuator`/`WithdrawRewardProcessor` unconditionally block withdrawal - ([File: actuator/src/main/java/org/tron/core/actuator/WithdrawBalanceActuator.java])

### Summary
This is the strongest reachable analog to the reported `VotingPool` bug class ("asset is credited into an address by the staking/voting mechanism, but the withdrawal path for that address has no mechanism to release it, so it is permanently locked"). In java-tron, any ordinary account can `VoteWitnessContract` for a Guard Representative (a genesis witness, "GR"). The reward-accrual code path (`MortgageService.payReward`/`payStandbyWitness`, `IncentiveManager.reward`, block-reward payout in `Manager.payReward`) credits TRX into the GR account's `allowance` field with no check for GR status. However, the only two code paths that convert `allowance` into spendable `balance` — `WithdrawBalanceActuator` and the TVM `WithdrawRewardProcessor` — both explicitly reject the withdrawal if the address is a genesis witness.

### Finding Description
Reward crediting is unconditional with respect to GR status:
- `MortgageService.payReward` adds brokerage to `allowance` via `adjustAllowance` for any witness address, including GRs: [1](#0-0) 
- `IncentiveManager.reward` (standby-witness incentive paid at every maintenance cycle) also unconditionally increases `allowance` for any witness in the top‑127 list, regardless of GR status: [2](#0-1) 
- Block reward payout (`Manager.payReward`) similarly credits allowance with no GR check: [3](#0-2) 

But the withdrawal side explicitly forbids GRs from ever converting that allowance to spendable balance:
- `WithdrawBalanceActuator.validate()` throws when the owner address matches a genesis-block witness: [4](#0-3) 
- The TVM-native equivalent `WithdrawRewardProcessor.validate()` enforces the identical restriction for the `withdrawreward()` opcode path reachable from any smart contract: [5](#0-4) 

This is confirmed by the existing unit test `isGR`, which shows that after `allowance` is credited to a genesis-witness address, `WithdrawBalanceActuator.execute()` always throws `ContractValidateException` ("... is a guard representative and is not allowed to withdraw Balance"), leaving the `allowance` field permanently non-zero and unreachable by any transaction type: [6](#0-5) 

The vote-driven reward path (`MortgageService.withdrawReward`/`VoteRewardUtil.withdrawReward`, reachable by anyone voting for a GR and later triggering reward computation) also has no GR check before moving computed reward into `allowance`: [7](#0-6)  — meaning ordinary voters can cause a GR's `allowance` to grow, and that TRX becomes permanently stuck since no actuator will ever let the GR withdraw it. `MaintenanceManager.tryRemoveThePowerOfTheGr()` only clears the GR's voting power going forward, it does not resolve the already-accrued allowance, and does not run before the very first maintenance cycle, leaving a window in which votes/brokerage/standby rewards can accrue against the GR.

### Impact Explanation
TRX that is deducted from the reward pool (transaction fee pool, block-reward budget, or a witness's own vote-based reward pool) via `payReward`/`incentiveManager.reward`/`VoteRewardUtil` ends up recorded solely in a genesis witness's `allowance` field, and there is no reachable transaction type or TVM opcode that can move it into spendable `balance`. This constitutes permanent freezing of funds (TRX that was legitimately earned/allocated becomes unbacked and unusable), matching the "permanent freezing of funds" impact bucket in the rules. The impact is systemic rather than attacker-profitable, but it matches exactly the root-cause pattern of the referenced report: a token/asset flows into an account through the normal reward/staking mechanism, and the corresponding withdrawal mechanism has an unconditional block that never releases it.

### Likelihood Explanation
The precondition (a genesis witness receiving votes, block production, or brokerage) is a normal, unprivileged interaction — any account can call `VoteWitnessContract` for any registered witness, including a GR, and normal chain operation (block production, maintenance cycles) triggers `payReward`/`IncentiveManager.reward`. No malicious/privileged actor is required; this can occur through ordinary, expected usage of the vote/reward system. However, whether this is "already accounted for" by design (GRs are documented as ineligible to receive rewards, and in practice their voting power may be near-zero after the very first maintenance cycle via `tryRemoveThePowerOfTheGr`) is not fully verifiable from the indexed code alone — the exact timing/ordering guarantee that GRs can never accrue meaningful allowance before their power is removed could not be conclusively confirmed.

### Recommendation
Either (a) prevent GR addresses from accruing `allowance` at all in `payReward`, `IncentiveManager.reward`, `Manager.payReward`, and `VoteRewardUtil`/`MortgageService.withdrawReward` (skip accrual for GR addresses symmetric with the withdrawal-side check), or (b) provide an explicit mechanism (e.g., a committee/self proposal, or redirecting to the black-hole/burn address, or an admin recovery path) to release/burn/redistribute allowance already accrued to GR addresses so it is not permanently stranded.

### Proof of Concept
1. Genesis witness GR1 (from `common/src/main/resources/reference.conf`, e.g. `THKJYuUmMKKARNf7s2VT51g5uPY6KEqnat`) starts with initial `voteCount` and is registered in `WitnessStore`.
2. Before/until `tryRemoveThePowerOfTheGr()` has fully zeroed GR voting power, any account submits `VoteWitnessContract` votes for GR1 (or GR1 remains in the top‑127 witness/standby list and receives `payStandbyWitness`/block-reward payouts).
3. `MortgageService.payReward`/`IncentiveManager.reward`/`Manager.payReward` credit TRX into GR1's `allowance` field (as demonstrated deterministically in the existing test `WithdrawBalanceActuatorTest.isGR`, which manually sets `allowance` via `MortgageService.adjustAllowance` to simulate this state).
4. Any transaction attempting to withdraw this allowance — `WithdrawBalanceContract` via `WithdrawBalanceActuator`, or the TVM `withdrawreward()` opcode via `WithdrawRewardProcessor` — is rejected with `ContractValidateException("... is a guard representative and is not allowed to withdraw Balance")`, leaving the TRX permanently stuck in `allowance` with no other code path in the indexed sources to release it.

  private void payReward(byte[] witnessAddress, long value) {
    long cycle = dynamicPropertiesStore.getCurrentCycleNumber();
    int brokerage = delegationStore.getBrokerage(cycle, witnessAddress);
    double brokerageRate = (double) brokerage / 100;
    long brokerageAmount = (long) (brokerageRate * value);
    value -= brokerageAmount;
    delegationStore.addReward(cycle, witnessAddress, value);
    adjustAllowance(witnessAddress, brokerageAmount);
  }

  public void withdrawReward(byte[] address) {
    if (!dynamicPropertiesStore.allowChangeDelegation()) {
      return;
    }
    AccountCapsule accountCapsule = accountStore.get(address);
    long beginCycle = delegationStore.getBeginCycle(address);
    long endCycle = delegationStore.getEndCycle(address);
    long currentCycle = dynamicPropertiesStore.getCurrentCycleNumber();
    long reward = 0;
    if (beginCycle > currentCycle || accountCapsule == null) {
      return;
    }
    if (beginCycle == currentCycle) {
      AccountCapsule account = delegationStore.getAccountVote(beginCycle, address);
      if (account != null) {
        return;
      }
    }
    //withdraw the latest cycle reward
    if (beginCycle + 1 == endCycle && beginCycle < currentCycle) {
      AccountCapsule account = delegationStore.getAccountVote(beginCycle, address);
      if (account != null) {
        reward = computeReward(beginCycle, endCycle, account);
        adjustAllowance(address, reward);
        reward = 0;
        logger.info("Latest cycle reward {}, {}.", beginCycle, account.getVotesList());
      }
      beginCycle += 1;
    }
    //
    endCycle = currentCycle;
    if (CollectionUtils.isEmpty(accountCapsule.getVotesList())) {
      delegationStore.setBeginCycle(address, endCycle + 1);
      return;
    }
    if (beginCycle < endCycle) {
      reward += computeReward(beginCycle, endCycle, accountCapsule);
      adjustAllowance(address, reward);
    }
    delegationStore.setBeginCycle(address, endCycle);
    delegationStore.setEndCycle(address, endCycle + 1);
    delegationStore.setAccountVote(endCycle, address, accountCapsule);
    logger.info("Adjust {} allowance {}, now currentCycle {}, beginCycle {}, endCycle {}, "
            + "account vote {}.", Hex.toHexString(address), reward, currentCycle,
        beginCycle, endCycle, accountCapsule.getVotesList());
  }

  public void reward(List<ByteString> witnesses) {
    if (consensusDelegate.allowChangeDelegation()) {
      return;
    }
    if (witnesses.size() > WITNESS_STANDBY_LENGTH) {
      witnesses = witnesses.subList(0, WITNESS_STANDBY_LENGTH);
    }
    long voteSum = 0;
    for (ByteString witness : witnesses) {
      voteSum += consensusDelegate.getWitness(witness.toByteArray()).getVoteCount();
    }
    if (voteSum <= 0) {
      return;
    }
    long totalPay = consensusDelegate.getWitnessStandbyAllowance();
    for (ByteString witness : witnesses) {
      byte[] address = witness.toByteArray();
      long pay = (long) (consensusDelegate.getWitness(address).getVoteCount() * ((double) totalPay
          / voteSum));
      AccountCapsule accountCapsule = consensusDelegate.getAccount(address);
      accountCapsule.setAllowance(accountCapsule.getAllowance() + pay);
      consensusDelegate.saveAccount(accountCapsule);
    }
  }

  @Test
  public void isGR() {
    Witness w = Args.getInstance().getGenesisBlock().getWitnesses().get(0);
    byte[] address = w.getAddress();
    AccountCapsule grCapsule = new AccountCapsule(ByteString.copyFromUtf8("gr"),
        ByteString.copyFrom(address), AccountType.Normal, initBalance);
    dbManager.getAccountStore().put(grCapsule.createDbKey(), grCapsule);
    long now = System.currentTimeMillis();
    dbManager.getDynamicPropertiesStore().saveLatestBlockHeaderTimestamp(now);

    try {
      dbManager.getMortgageService()
          .adjustAllowance(dbManager.getAccountStore(), address, allowance);
    } catch (BalanceInsufficientException e) {
      fail("BalanceInsufficientException");
    }
    AccountCapsule accountCapsule = dbManager.getAccountStore().get(address);
    Assert.assertEquals(accountCapsule.getAllowance(), allowance);

    WitnessCapsule witnessCapsule = new WitnessCapsule(ByteString.copyFrom(address), 100,
        "http://google.com");

    dbManager.getAccountStore().put(address, accountCapsule);
    dbManager.getWitnessStore().put(address, witnessCapsule);

    WithdrawBalanceActuator actuator = new WithdrawBalanceActuator();
    actuator.setChainBaseManager(dbManager.getChainBaseManager())
        .setAny(getContract(ByteArray.toHexString(address)));

    TransactionResultCapsule ret = new TransactionResultCapsule();
    Assert.assertTrue(dbManager.getWitnessStore().has(address));

    try {
      actuator.validate();
      actuator.execute(ret);
      fail("cannot run here.");

    } catch (ContractValidateException e) {
      String readableOwnerAddress = StringUtil.createReadableString(address);
      Assert.assertTrue(e instanceof ContractValidateException);
      Assert.assertEquals("Account[" + readableOwnerAddress
          + "] is a guard representative and is not allowed to withdraw Balance", e.getMessage());
    } catch (ContractExeException e) {
      Assert.assertFalse(e instanceof ContractExeException);
    }
  }
