## Analysis

The strongest analog to the iccDEV `CIccXmlArrayType::ParseText()` heap-buffer-overflow (an OOB read caused by trusting an attacker-declared element/size field without validating it against the actual remaining buffer) is in Bazel's `ijar` ZIP central-directory parser, `InputZipFile::ProcessCentralDirEntry()` in [1](#0-0) . `ijar` is the tool Bazel invokes to build interface jars from arbitrary input jars (including third-party jars fetched via `http_jar`/`http_archive`/Maven-style artifacts), so it directly parses attacker-influenced ZIP bytes.

### Title
Heap-buffer-overflow (OOB read) in `InputZipFile::ProcessCentralDirEntry` ZIP64 extra-field parsing - (File: `third_party/ijar/zip.cc`)

### Summary
`ProcessCentralDirEntry` reads a ZIP64 "extra field" entry's `data_size` field and, if the `header_id` equals `ZIP64_EXTRA_FIELD_TAG`, unconditionally reads up to 24 bytes (`get_u8le` called up to three times) from the `extra` pointer — without ever checking that `data_size` (or the remaining bytes up to `p`) is large enough to contain those 24 bytes.

### Finding Description
In the central directory entry parser:
```
while (extra_p != p) {
    const u2 header_id = get_u2le(extra_p);
    const u2 data_size = get_u2le(extra_p);
    const u1 *extra = extra_p;
    extra_p += data_size;
    if (header_id == ZIP64_EXTRA_FIELD_TAG) {
      if (*uncompressed_size == U4_MAX) *uncompressed_size = get_u8le(extra);
      if (*compressed_size == U4_MAX) *compressed_size = get_u8le(extra);
      if (*offset == U4_MAX) *offset = get_u8le(extra);
    }
}
``` [2](#0-1) 

`data_size` is fully attacker-controlled (it comes straight from the crafted ZIP bytes) and is never validated to be at least 8/16/24 bytes before the code reads that many bytes starting at `extra`. Unlike `EnsureRemaining()`, which is used elsewhere in this same class to bound-check reads against the mmap'd file length (e.g. `EnsureRemaining(file_name_length_, ...)` in `ProcessLocalFileEntry`, `third_party/ijar/zip.cc:360-369`), no such check exists here. If `*uncompressed_size`/`*compressed_size`/`*offset` in the central-directory record are set to `U4_MAX` (a standard ZIP64 marker) while the corresponding extra-field payload is declared with a `data_size` smaller than required (or zero), `get_u8le` reads 8 bytes past the true bounds of the extra field, and potentially past the end of the memory-mapped input file (`MappedInputFile`), producing an out-of-bounds heap read — directly analogous to `CIccXmlArrayType::ParseText()` trusting a declared element count/size over the actual buffer contents.

The input file is memory-mapped (`MappedInputFile input_file_`), the central directory pointer walks over attacker-supplied bytes, and no other layer re-validates the extra field's internal `data_size` against the ZIP central-directory `extra_field_length` before this loop consumes it.

### Impact Explanation
An attacker who serves a maliciously crafted (but otherwise structurally valid) jar/zip file at a dependency URL — for example via `http_jar`, `http_archive`, or a Maven/BCR mirror where no `sha256`/`integrity` is pinned, which Bazel's own docs flag as "a security risk" and "non-hermetic" [3](#0-2)  — can trigger this path when Bazel runs `ijar` to build an interface jar from that dependency during a `java_library`/`java_import` compile action. The result is a heap OOB read in a native tool executed as part of the build, which can crash the build process (denial of service) or, depending on memory layout, leak adjacent heap contents into the read fields, which then feed into interface-jar generation.

### Likelihood Explanation
Reaching this code path requires only that Bazel run `ijar` over a zip/jar file whose bytes the attacker controls — a common scenario for any external Java dependency without a pinned/enforced checksum, or where the attacker is the legitimate publisher of a package version being fetched for the first time. Crafting a ZIP central directory record with `compressed_size`/`uncompressed_size`/`offset` set to `0xFFFFFFFF` and a truncated ZIP64 extra field is a small, well-understood ZIP structural manipulation, requiring no cryptographic bypass.

### Recommendation
In `InputZipFile::ProcessCentralDirEntry`, before reading the ZIP64 extra field payload, validate `data_size >= 8` (or `>= 24` when all three `U4_MAX` fields are present) and that `extra + data_size <= p` (i.e., within the declared `extra_field_length` region), mirroring the bounds checks already used in `singlejar`'s extra-field handling (`ziph::byte_ptr(ef) + ef->size() > ziph::byte_ptr(ef_end)` check) [4](#0-3) . Reject or error out on malformed/undersized ZIP64 extra fields instead of reading past them.

### Proof of Concept
Construct a ZIP file whose central directory contains one entry with:
- `compressed_size32 = uncompressed_size32 = 0xFFFFFFFF` (ZIP64 markers),
- an extra field with `header_id = 0x0001` (`ZIP64_EXTRA_FIELD_TAG`) and `data_size = 0` (or any value < 24),
- no actual trailing payload bytes (extra field ends at/near the mapped file boundary).

Running `ijar` (or any Bazel build action that invokes it, e.g. compiling against a `java_import`/`http_jar` target pointing at this file) over this crafted archive drives execution into `ProcessCentralDirEntry`, where `get_u8le(extra)` reads 8–24 bytes past the declared/available extra-field bytes, which can be verified with ASan as a heap-buffer-overflow read, analogous to the `CreateZipWithMalformedExtraField()` test helper already present in the codebase for a related (but distinct, bounds-checked) code path in `output_jar_simple_test.cc` [5](#0-4) ; an equivalent JUnit/`BuildIntegrationTestCase` targeting `ijar`'s `ProcessCentralDirEntry` (rather than singlejar's already-guarded path) would demonstrate the missing bound check concretely.

bool InputZipFile::ProcessCentralDirEntry(const u1 *&p, u8 *compressed_size,
                                          u8 *uncompressed_size, char *filename,
                                          size_t filename_size, u4 *attr,
                                          u8 *offset) {
  u4 signature = get_u4le(p);

  if (signature != CENTRAL_FILE_HEADER_SIGNATURE) {
    if (signature != DIGITAL_SIGNATURE && signature != EOCD_SIGNATURE &&
        signature != ZIP64_EOCD_SIGNATURE) {
      error("invalid central file header signature: 0x%x\n", signature);
    }
    return false;
  }

  p += 16;  // skip to 'compressed size' field
  *compressed_size = get_u4le(p);
  *uncompressed_size = get_u4le(p);
  u2 file_name_length = get_u2le(p);
  u2 extra_field_length = get_u2le(p);
  u2 file_comment_length = get_u2le(p);
  p += 4;  // skip to external file attributes field
  *attr = get_u4le(p);
  *offset = get_u4le(p);
  {
    size_t len = (file_name_length < filename_size)
      ? file_name_length
      : (filename_size - 1);
    memcpy(reinterpret_cast<void*>(filename), p, len);
    filename[len] = 0;
  }
  p += file_name_length;
  const u1 *extra_p = p;
  p += extra_field_length;
  while (extra_p != p) {
    const u2 header_id = get_u2le(extra_p);
    const u2 data_size = get_u2le(extra_p);
    const u1 *extra = extra_p;
    extra_p += data_size;
    if (header_id == ZIP64_EXTRA_FIELD_TAG) {
      if (*uncompressed_size == U4_MAX) {
        *uncompressed_size = get_u8le(extra);
      }
      if (*compressed_size == U4_MAX) {
        *compressed_size = get_u8le(extra);
      }
      if (*offset == U4_MAX) {
        *offset = get_u8le(extra);
      }
    }
  }
  p += file_comment_length;
  return true;
}

std::string CreateZipWithMalformedExtraField() {
  std::string zip_data;
  const std::string filename = "evil.bin";

  // 1. Local File Header (LFH)
  size_t lh_offset = zip_data.size();
  size_t lh_size = sizeof(LH) + filename.size();
  zip_data.resize(lh_offset + lh_size, 0);
  auto* lh = reinterpret_cast<LH*>(&zip_data[lh_offset]);
  lh->signature();
  lh->version(10);
  lh->file_name(filename.data(), filename.size());

  // 2. Extra field payload containing an oversized payload_size
  uint8_t ef_buffer[8] = {0};
  auto* ef1 = reinterpret_cast<ExtraField*>(ef_buffer);
  ef1->signature(0x000d);
  ef1->payload_size(0);

  auto* ef2 = reinterpret_cast<ExtraField*>(ef_buffer + ef1->size());
  ef2->signature(0xdead);
  ef2->payload_size(0xf000);  // Malformed size exceeding extra field buffer

  // 3. Central Directory Header (CDH)
  size_t cdh_offset = zip_data.size();
  size_t cdh_size = sizeof(CDH) + filename.size() + sizeof(ef_buffer);
  zip_data.resize(cdh_offset + cdh_size, 0);
  auto* cdh = reinterpret_cast<CDH*>(&zip_data[cdh_offset]);
  cdh->signature();
  cdh->version(20);
  cdh->version_to_extract(10);
  cdh->local_header_offset32(lh_offset);
  cdh->file_name(filename.data(), filename.size());
  cdh->extra_fields(ef_buffer, sizeof(ef_buffer));

  // 4. End of Central Directory (EOCD)
  size_t ecd_offset = zip_data.size();
  zip_data.resize(ecd_offset + sizeof(ECD), 0);
  auto* ecd = reinterpret_cast<ECD*>(&zip_data[ecd_offset]);
  ecd->signature();
  ecd->this_disk_entries16(1);
  ecd->total_entries16(1);
  ecd->cen_size32(cdh_size);
  ecd->cen_offset32(cdh_offset);

  return zip_data;
}
