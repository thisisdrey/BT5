### Title
Custom hooks symlinks are faithfully archived and re-extracted across repositories, breaking repository isolation - ([File: internal/gitaly/repoutil/custom_hooks.go], [File: internal/archive/tar_builder.go])

### Summary
`SetCustomHooks` extracts an attacker-supplied tar into a repository's `custom_hooks/` directory using plain `tar -xf` with no symlink or path validation, allowing an attacker to plant a symlink pointing outside the repository. `GetCustomHooks` then archives that directory via `archive.WriteTarball`, which sets `allowSymlinks = true` and faithfully serializes the symlink (target and all) into the outbound tar, and the same unguarded `ExtractHooks` routine is used by restore/replication flows to recreate it verbatim in a second, unrelated repository.

### Finding Description
`SetCustomHooks` (`internal/gitaly/repoutil/custom_hooks.go:100`) calls `ExtractHooks` (`internal/gitaly/repoutil/custom_hooks.go:55`), which shells out to `tar -xf - -C <path> --strip-components ... custom_hooks` [1](#0-0) . GNU tar recreates symlink tar entries verbatim (it does not follow or validate the link target), so an attacker who owns the source repository can push a tar containing `custom_hooks/pre-receive -> /some/outside/path` and have `SetCustomHooks` place that exact symlink inside their own repository's `custom_hooks/` directory. Nothing in `SetCustomHooks` inspects the extracted tree for symlinks or validates that entries stay within the repo before moving/renaming the directory into place (lines 174-223) [2](#0-1) .

When `GetCustomHooks` is later invoked (e.g. as part of `BackupRepository`/`localRepository.GetCustomHooks`), it calls `archive.WriteTarball(ctx, logger, writer, repoPath, CustomHooksDir)` [3](#0-2) . `WriteTarball` explicitly sets `builder.allowSymlinks = true` [4](#0-3) , and `TarBuilder.RecursiveDir`/`entry` faithfully copies the symlink type and its `os.Readlink` target into the tar header without any check that the link resolves inside the repo [5](#0-4) [6](#0-5) .

This outbound tarball is exactly what gets streamed by `RepositoryService.GetCustomHooks`/used by `BackupRepository`, and is consumed by `RestoreCustomHooks`/`RepositoryService.SetCustomHooks` on a different (target) repository, which again goes through the same unguarded `ExtractHooks` (`tar -xf`) with no symlink or target-path validation. The result is that a symlink whose target is entirely attacker-controlled (and may point outside any repository, e.g. to another path on the Gitaly node) is faithfully recreated inside the `custom_hooks` directory of a second, victim repository during backup/restore or fork/replication flows that copy custom hooks between repos (`internal/backup/repository.go` `GetCustomHooks`/`SetCustomHooks` wrappers, `internal/gitaly/service/repository/replicate.go`). None of `storage.ValidateRelativePath`, tar extraction path checks, or symlink-target validation are applied anywhere in this pipeline.

### Impact Explanation
This breaks repository isolation for hook content across copy operations: a symlink placed by the attacker in their own repository's `custom_hooks/` can end up materialized inside an unrelated victim repository's `custom_hooks/` directory after a backup+restore or fork/replicate cycle. Since Gitaly hooks execution (`internal/gitaly/hook/custom.go`) later reads and runs entries under `custom_hooks/`, a dangling or attacker-influenced symlink surviving in another repository's hook directory is a concrete cross-repository content-injection / repository-isolation violation, matching the "cross-repository objects/metadata disclosed" and "hook bypass" impact classes.

### Likelihood Explanation
The attacker only needs to own/control a source repository (unprivileged capability) and be able to invoke `SetCustomHooks` on it (already an exposed RPC), then rely on a normal backup/restore, fork, or replication workflow to copy the hooks to another repository — no special config, admin role, or peer compromise is required. This is fully repeatable and deterministic given GNU tar's verbatim symlink handling and the explicit `allowSymlinks = true` in `WriteTarball`.

### Recommendation
Reject or strip symlinks (and other non-regular files) when extracting attacker-supplied hook tarballs in `ExtractHooks`/`SetCustomHooks`, and/or set `allowSymlinks = false` (or apply target-path validation restricting links to stay within the extracted `custom_hooks` tree) in `archive.WriteTarball` when it is used for cross-repository copy operations such as backup/restore and replication.

// Pseudocode outline for internal/gitaly/repoutil/custom_hooks_test.go style test
func TestCustomHooksSymlinkEscapesToVictimRepo(t *testing.T) {
    // 1. Build a tar containing custom_hooks/pre-receive as a symlink to "/etc/passwd"
    var buf bytes.Buffer
    tw := tar.NewWriter(&buf)
    tw.WriteHeader(&tar.Header{
        Name:     "custom_hooks/pre-receive",
        Typeflag: tar.TypeSymlink,
        Linkname: "/etc/passwd",
        Mode:     0777,
    })
    tw.Close()

    // 2. SetCustomHooks on attacker's own repo (repoA)
    require.NoError(t, repoutil.SetCustomHooks(ctx, logger, locator, txManager, &buf, repoA))

    // 3. GetCustomHooks (simulating BackupRepository) archives repoA's hooks
    var out bytes.Buffer
    require.NoError(t, repoutil.GetCustomHooks(ctx, logger, repoAPath, &out))

    // 4. RestoreCustomHooks (simulating RestoreRepository) extracts into repoB
    require.NoError(t, repoutil.ExtractHooks(ctx, logger, &out, repoBPath, false))

    // 5. Assert repoB now contains a symlink resolving outside repoBPath
    link, err := os.Readlink(filepath.Join(repoBPath, "custom_hooks", "pre-receive"))
    require.NoError(t, err)
    require.Equal(t, "/etc/passwd", link) // FAIL expected: escaping symlink must not be present
}

func WriteTarball(ctx context.Context, logger log.Logger, writer io.Writer, path string, members ...string) error {
	builder := NewTarBuilder(path, writer)
	builder.allowSymlinks = true

	for _, member := range members {
		_ = builder.RecursiveDir(member, "", true)
	}

func (t *TarBuilder) entry(fi os.FileInfo, filename string, r io.Reader) error {
	if !fi.Mode().IsRegular() && !fi.Mode().IsDir() {
		if !t.allowSymlinks && fi.Mode()&fs.ModeSymlink != 0 {
			return fmt.Errorf("unsupported mode for %v: %v", filename, fi.Mode())
		}
	}

	var link string
	if fi.Mode()&fs.ModeSymlink != 0 {
		var err error
		link, err = os.Readlink(t.join(filename))
		if err != nil {
			return err
		}
	}
