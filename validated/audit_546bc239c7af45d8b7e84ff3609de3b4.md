### Title
SR can front-run the reward-cycle snapshot by raising `UpdateBrokerageContract` commission right before `MaintenanceManager.doMaintenance()` locks it in for voters who already committed votes - ([File: actuator/src/main/java/org/tron/core/actuator/UpdateBrokerageActuator.java])

### Summary
`UpdateBrokerageContract`/`UpdateBrokerageActuator` lets any witness change its "brokerage" (commission) percentage with no rate limit, no delay, and no binding to the votes already cast for it. The value that ultimately determines how a voting cycle's reward is split between the witness and its voters is whatever brokerage value is stored at the moment `MaintenanceManager.doMaintenance()` snapshots it for `nextCycle` - a value the witness fully controls and can change in the very last block before that snapshot, after voters have already locked in their votes for that period. This mirrors the reported `RFPSimpleStrategy.allocate()` bug class: a party can advertise a favorable rate to attract counterparties, then swap it for a worse rate right before the value is "locked in" by another actor's/on-chain action, with no slippage/consistency check to protect the counterparty.

### Finding Description
- `UpdateBrokerageActuator.execute()` unconditionally overwrites the witness's brokerage value with `delegationStore.setBrokerage(ownerAddress, brokerage)`, which stores into the special `cycle = -1` bucket: [1](#0-0) [2](#0-1) 
- There is no limit on how frequently `UpdateBrokerageContract` can be submitted, and `validate()` only checks address validity, the 0-100 range, and that the witness/account exist - nothing ties the change to a cooldown or to already-cast votes: [3](#0-2) 
- The value actually used to split rewards for a given cycle is captured once per maintenance interval: `MaintenanceManager.doMaintenance()` copies the current ("-1" bucket) brokerage into `nextCycle` for every active witness: [4](#0-3) 
- `MortgageService.payReward()` later uses the cycle-specific brokerage recorded at that snapshot time to compute how much of each block/fee reward the witness keeps versus how much is credited to voters: [5](#0-4) 
- Voters, however, commit votes well in advance of the maintenance boundary and cannot see (or react within the same block window to) a last-second brokerage change; the reward accounting for a cycle is locked via `withdrawReward()`/`AccountVote` bookkeeping tied to `beginCycle`/`endCycle`, which spans a full cycle and offers no visibility into the exact block at which `doMaintenance()` will run and snapshot the rate: [6](#0-5) 

This is directly analogous to the reported bug: `registerRecipient()`/bid value can be freely rewritten right up until `allocate()` "locks it in", with no check that the locked-in value matches what the counterparty expected. Here, the "bid" is the SR's advertised brokerage rate, and the "allocate()" moment is the maintenance-triggered snapshot into `nextCycle`.

### Impact Explanation
A malicious or opportunistic SR/witness can advertise a low commission (e.g., 0-5%) to attract voters seeking maximum staking yield, then submit `UpdateBrokerageContract` with `brokerage = 100` in the last block before the maintenance cycle boundary. All voters who already voted for that witness in prior cycles have their rewards for the upcoming cycle computed with the new, much higher brokerage, redirecting nearly all of the block/vote reward that would have gone to voters into the witness's own allowance via `adjustAllowance(witnessAddress, brokerageAmount)`. This is a redirection of expected staking rewards away from voters to the witness - an unbacked/misappropriated distribution of funds that voters have no on-chain mechanism to prevent or detect in time, since votes span a full cycle and cannot be withdrawn instantly to avoid the change.

### Likelihood Explanation
The action requires only a single signed `UpdateBrokerageContract` transaction from the witness's own key - fully reachable by an unprivileged (from the protocol's perspective, any account that happens to be a witness) transaction broadcaster with no special permissions beyond being a registered witness. There is no cooldown, delay, or commitment mechanism, so timing the transaction just before a known/predictable maintenance boundary is straightforward and repeatable every cycle.

### Recommendation
Introduce a delay/timelock for brokerage changes so a new rate only takes effect starting some number of cycles in the future (e.g., N+2 rather than the immediate next cycle), giving voters a window to react. Alternatively, rate-limit brokerage changes (e.g., once per cycle, or bound the maximum delta per change) and/or emit the pending rate publicly ahead of the cycle boundary so `doMaintenance()` snapshots a value that was visible for a full prior cycle, closing the "advertise low, snapshot high" front-running window.

### Proof of Concept
1. Witness W registers and calls `UpdateBrokerageContract{brokerage=0}` - `UpdateBrokerageActuator.execute()` stores `brokerage=0` in `delegationStore` cycle `-1` bucket.
2. Voters see the 0% commission and vote for W across one or more cycles; `withdrawReward()`/`setAccountVote()` locks in their vote state for the cycle window.
3. Immediately before `MaintenanceManager.doMaintenance()` runs (a publicly known, fixed interval), W submits another `UpdateBrokerageContract{brokerage=100}`.
4. `doMaintenance()` executes `delegationStore.setBrokerage(nextCycle, witness.createDbKey(), delegationStore.getBrokerage(witness.createDbKey()))`, snapshotting `100` for `nextCycle`.
5. For that entire cycle, `MortgageService.payReward()` computes `brokerageAmount = 100% * value`, so voters who already committed votes for W receive `0` reward for that cycle while W's allowance absorbs the full block/fee reward - with no way for voters to have prevented or reacted to the change in time.

  @Override
  public boolean validate() throws ContractValidateException {
    if (this.any == null) {
      throw new ContractValidateException(ActuatorConstant.CONTRACT_NOT_EXIST);
    }
    if (chainBaseManager == null) {
      throw new ContractValidateException(ActuatorConstant.STORE_NOT_EXIST);
    }
    DynamicPropertiesStore dynamicStore = chainBaseManager.getDynamicPropertiesStore();
    AccountStore accountStore = chainBaseManager.getAccountStore();
    WitnessStore witnessStore = chainBaseManager.getWitnessStore();
    if (!dynamicStore.allowChangeDelegation()) {
      throw new ContractValidateException(
          "contract type error, unexpected type [UpdateBrokerageContract]");
    }

    if (!this.any.is(UpdateBrokerageContract.class)) {
      throw new ContractValidateException(
          "contract type error, expected type [UpdateBrokerageContract], real type[" + any
              .getClass() + "]");
    }
    final UpdateBrokerageContract updateBrokerageContract;
    try {
      updateBrokerageContract = any.unpack(UpdateBrokerageContract.class);
    } catch (InvalidProtocolBufferException e) {
      logger.debug(e.getMessage(), e);
      throw new ContractValidateException(e.getMessage());
    }
    byte[] ownerAddress = updateBrokerageContract.getOwnerAddress().toByteArray();
    int brokerage = updateBrokerageContract.getBrokerage();

    if (!DecodeUtil.addressValid(ownerAddress)) {
      throw new ContractValidateException("Invalid ownerAddress");
    }

    if (brokerage < 0 || brokerage > ActuatorConstant.ONE_HUNDRED) {
      throw new ContractValidateException("Invalid brokerage");
    }

    WitnessCapsule witnessCapsule = witnessStore.get(ownerAddress);
    if (witnessCapsule == null) {
      throw new ContractValidateException("Not existed witness:" + Hex.toHexString(ownerAddress));
    }

    AccountCapsule account = accountStore.get(ownerAddress);
    if (account == null) {
      throw new ContractValidateException("Account does not exist");
    }

    return true;

  private void payReward(byte[] witnessAddress, long value) {
    long cycle = dynamicPropertiesStore.getCurrentCycleNumber();
    int brokerage = delegationStore.getBrokerage(cycle, witnessAddress);
    double brokerageRate = (double) brokerage / 100;
    long brokerageAmount = (long) (brokerageRate * value);
    value -= brokerageAmount;
    delegationStore.addReward(cycle, witnessAddress, value);
    adjustAllowance(witnessAddress, brokerageAmount);
  }

  public void withdrawReward(byte[] address) {
    if (!dynamicPropertiesStore.allowChangeDelegation()) {
      return;
    }
    AccountCapsule accountCapsule = accountStore.get(address);
    long beginCycle = delegationStore.getBeginCycle(address);
    long endCycle = delegationStore.getEndCycle(address);
    long currentCycle = dynamicPropertiesStore.getCurrentCycleNumber();
    long reward = 0;
    if (beginCycle > currentCycle || accountCapsule == null) {
      return;
    }
    if (beginCycle == currentCycle) {
      AccountCapsule account = delegationStore.getAccountVote(beginCycle, address);
      if (account != null) {
        return;
      }
    }
    //withdraw the latest cycle reward
    if (beginCycle + 1 == endCycle && beginCycle < currentCycle) {
      AccountCapsule account = delegationStore.getAccountVote(beginCycle, address);
      if (account != null) {
        reward = computeReward(beginCycle, endCycle, account);
        adjustAllowance(address, reward);
        reward = 0;
        logger.info("Latest cycle reward {}, {}.", beginCycle, account.getVotesList());
      }
      beginCycle += 1;
    }
    //
    endCycle = currentCycle;
    if (CollectionUtils.isEmpty(accountCapsule.getVotesList())) {
      delegationStore.setBeginCycle(address, endCycle + 1);
      return;
    }
    if (beginCycle < endCycle) {
      reward += computeReward(beginCycle, endCycle, accountCapsule);
      adjustAllowance(address, reward);
    }
    delegationStore.setBeginCycle(address, endCycle);
    delegationStore.setEndCycle(address, endCycle + 1);
    delegationStore.setAccountVote(endCycle, address, accountCapsule);
    logger.info("Adjust {} allowance {}, now currentCycle {}, beginCycle {}, endCycle {}, "
            + "account vote {}.", Hex.toHexString(address), reward, currentCycle,
        beginCycle, endCycle, accountCapsule.getVotesList());
  }
