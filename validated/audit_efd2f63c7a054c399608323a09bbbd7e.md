### Title
Unbounded memory allocation from unvalidated CODECOPY/EXTCODECOPY length causes node OutOfMemoryError (DoS) - (File: actuator/src/main/java/org/tron/core/vm/OperationActions.java)

### Summary
The CVE describes NTP's refclock driver trusting an attacker-controlled `datalen` value and using it directly to size/copy a buffer, causing a crash. The java-tron TVM opcode handlers `codeCopyAction` and `extCodeCopyAction` have the analogous bug-class: an attacker-controlled length taken from the EVM/TVM stack is used to allocate a byte array *before* it is validated/clamped against the actual code size.

### Finding Description
In `codeCopyAction`, the length operand popped from the stack is converted with `DataWord.intValueSafe()`, then immediately used to allocate a buffer, with bounds-checking against the actual code length only applied afterward to the `arraycopy` call, not to the allocation itself: [1](#0-0) 

The identical pattern exists in `extCodeCopyAction` for arbitrary external contract code: [2](#0-1) 

`intValueSafe()` does not reject "negative" stack values by returning a small/zero value — it clamps any value that doesn't fit as a positive 32-bit int (including values whose sign bit would make them appear negative) to `Integer.MAX_VALUE`: [3](#0-2) 

This means a contract can push a length word like `0xFFFF...FFFF` and the two opcode handlers will attempt `new byte[Integer.MAX_VALUE]` — approximately a 2 GB heap allocation — regardless of the true code size, before any range clamp against `fullCode.length` is applied to the copy. Allocation failures throw `java.lang.OutOfMemoryError`, which is a `Error`, not a `RuntimeException`.

The VM interpreter loop only catches `RuntimeException`, `JVMStackOverFlowException`, `OutOfTimeException`, and `StackOverflowError` around opcode execution and around the whole `play()` method: [4](#0-3) 

No `OutOfMemoryError` (or generic `Throwable`/`Error`) handling exists in this path, and a repository-wide search found no catch for `OutOfMemoryError` anywhere in the VM/actuator execution stack (only unrelated matches in `start.sh` and `RLP.java`). An uncaught `Error` thrown mid-opcode-execution will propagate out of `VM.play()` and `VMActuator.execute()` uncontrolled, unlike the graceful `RuntimeException` handling that normally reverts just the failing transaction.

### Impact Explanation
Because `Error` is unchecked and not covered by the existing `catch (RuntimeException e)` blocks, this can escape the per-transaction fault isolation that normally converts VM failures into a reverted transaction. Depending on the calling thread (block-application / transaction-processing thread in `Manager`), an uncaught `Error` can abort in-flight block processing or destabilize the node process, and repeated triggering (e.g., in bursts of transactions or during re-execution/sync) causes repeated large transient allocations that pressure the JVM heap, both of which fall under the "node crash or halt" impact category.

### Likelihood Explanation
`CODECOPY` and `EXTCODECOPY` are ordinary, unprivileged TVM opcodes reachable by any address that can deploy or call a smart contract — no special privilege, SR/witness role, or victim interaction is required. The only cost to the attacker is the energy for the opcode itself; the oversized-length allocation happens unconditionally inside the handler regardless of the actual code length, so a single crafted transaction/contract call is sufficient to trigger the allocation attempt.

### Recommendation
Clamp/validate the requested `lengthData` against the actual `fullCode.length` (and available memory-expansion energy cost) *before* allocating the destination array, mirroring the safe pattern already used in `ProgramInvokeImpl.getDataCopy` where the copy size is derived and validated prior to allocation: [5](#0-4) 
Additionally, consider handling `OutOfMemoryError`/`Error` at the VM boundary (`VM.play` / `VMActuator.execute`) to fail the transaction safely rather than allow an unchecked `Error` to propagate.

### Proof of Concept
1. Deploy or call any contract whose bytecode contains, e.g.:
   `PUSH32 0xFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFF` (length)
   `PUSH1 0x00` (code/mem offset)
   `PUSH1 0x00` (mem offset)
   `CODECOPY` (or push a target address and use `EXTCODECOPY`)
2. When `codeCopyAction`/`extCodeCopyAction` executes, `lengthData` resolves via `intValueSafe()` to `Integer.MAX_VALUE`, and `new byte[lengthData]` is executed unconditionally, attempting a ~2 GB allocation.
3. On a node without sufficient free heap, this throws `OutOfMemoryError`, which is not caught by any handler in `VM.play()`/`VMActuator.execute()`, propagating as an unchecked `Error` out of normal transaction-failure handling.

  public static void codeCopyAction(Program program) {
    byte[] fullCode = program.getCode();

    int memOffset = program.stackPop().intValueSafe();
    int codeOffset = program.stackPop().intValueSafe();
    int lengthData = program.stackPop().intValueSafe();

    int sizeToBeCopied = lengthData;
    if ((long) codeOffset + lengthData > fullCode.length) {
      sizeToBeCopied = fullCode.length < codeOffset ? 0 : fullCode.length - codeOffset;
    }

    byte[] codeCopy = new byte[lengthData];

    if (codeOffset < fullCode.length) {
      System.arraycopy(fullCode, codeOffset, codeCopy, 0, sizeToBeCopied);
    }

    program.memorySave(memOffset, codeCopy);
    program.step();

   * In case of int overflow returns Integer.MAX_VALUE otherwise works as #intValue()

  public int intValueSafe() {
    int bytesOccupied = bytesOccupied();
    int intValue = intValue();
    if (bytesOccupied > 4 || intValue < 0) {
      return Integer.MAX_VALUE;
    }
    return intValue;
  }

  public static void play(Program program, JumpTable jumpTable) {
    try {
      long factor = DYNAMIC_ENERGY_FACTOR_DECIMAL;
      long energyUsage = 0L;
      // hoist once per execution: avoids a per-opcode VMConfig.current() thread-local lookup
      final boolean allowDynamicEnergy = VMConfig.allowDynamicEnergy();

      if (allowDynamicEnergy) {
        factor = program.updateContextContractFactor();
      }

      while (!program.isStopped()) {
        if (VMConfig.vmTrace()) {
          program.saveOpTrace();
        }

        try {
          Operation op = jumpTable.get(program.getCurrentOpIntValue());
          if (!op.isEnabled()) {
            throw Program.Exception.invalidOpCode(program.getCurrentOp());
          }
          program.setLastOp((byte) op.getOpcode());

          /* stack underflow/overflow check */
          program.verifyStackSize(op.getRequire());
          program.verifyStackOverflow(op.getRequire(), op.getRet());

          String opName = Op.getNameOf(op.getOpcode());
          /* spend energy before execution */
          long energy = op.getEnergyCost(program);
          if (allowDynamicEnergy) {
            long actualEnergy = energy;
            // CALL Ops have special calculation on energy.
            if (CALL_OPS.contains(op.getOpcode())) {
              actualEnergy = energy
                  - program.getAdjustedCallEnergy().longValueSafe()
                  - program.getCallPenaltyEnergy();
            }
            energyUsage += actualEnergy;

            if (factor > DYNAMIC_ENERGY_FACTOR_DECIMAL) {
              long penalty;

              // CALL Ops have special calculation on energy.
              if (CALL_OPS.contains(op.getOpcode())) {
                penalty = program.getCallPenaltyEnergy();
              } else {
                penalty = energy * factor / DYNAMIC_ENERGY_FACTOR_DECIMAL - energy;
                if (penalty < 0) {
                  penalty = 0;
                }
                energy += penalty;
              }

              program.spendEnergyWithPenalty(energy, penalty, opName);
            } else {
              program.spendEnergy(energy, opName);
            }

          } else {
            program.spendEnergy(energy, opName);
          }


          /* check if cpu time out */
          program.checkCPUTimeLimit(opName);

          /* exec op action */
          op.execute(program);

          program.setPreviouslyExecutedOp((byte) op.getOpcode());
        } catch (RuntimeException e) {
          logger.info("VM halted: [{}]", e.getMessage());
          if (!(e instanceof TransferException)) {
            program.spendAllEnergy();
          }
          //program.resetFutureRefund();
          program.stop();
          throw e;
        } finally {
          program.fullTrace();
        }
      }

      if (allowDynamicEnergy) {
        program.addContextContractUsage(energyUsage);
      }

    } catch (JVMStackOverFlowException | OutOfTimeException e) {
      throw e;
    } catch (RuntimeException e) {
      // https://openjdk.org/jeps/358
      // https://bugs.openjdk.org/browse/JDK-8220715
      // since jdk 14, the NullPointerExceptions message is not empty
      if (e instanceof NullPointerException || StringUtils.isEmpty(e.getMessage())) {
        logger.warn("Unknown Exception occurred, tx id: {}",
            Hex.toHexString(program.getRootTransactionId()), e);
        program.setRuntimeFailure(new RuntimeException("Unknown Exception"));
      } else {
        program.setRuntimeFailure(e);
      }
    } catch (StackOverflowError soe) {
      logger.info("\n !!! StackOverflowError: update your java run command with -Xss !!!\n", soe);
      throw new JVMStackOverFlowException();
    }
  }

  public byte[] getDataCopy(DataWord offsetData, DataWord lengthData) {

    int offset = offsetData.intValueSafe();
    int length = lengthData.intValueSafe();

    byte[] data = new byte[length];

    if (msgData == null) {
      return data;
    }
    if (offset > msgData.length) {
      return data;
    }
    if (offset + length > msgData.length) {
      length = msgData.length - offset;
    }

    System.arraycopy(msgData, offset, data, 0, length);

    return data;
  }
