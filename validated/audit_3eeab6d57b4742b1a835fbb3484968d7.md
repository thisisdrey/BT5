### Title
Unauthenticated `recv_error` packet enables spoofed teardown of legitimate tunnels - (File: outside.go)

### Summary
The Canto report describes a hook (`PostTxProcessing`) that lets a code path unrelated to the caller's actual intent (Turnstile interaction) tear down/revert a transaction because of an internal condition it doesn't control. The nebula analog is `Interface.handleRecvError`, which processes an entirely unauthenticated, unencrypted control packet (`header.RecvError`) and, based on nothing but a UDP source-address string match, tears down an established, legitimately-authenticated tunnel between two valid peers.

### Finding Description
`readOutsidePackets` dispatches `header.RecvError` packets to `handleRecvError` *before* any certificate or AEAD verification is performed: [1](#0-0) 

`handleRecvError` then looks up the hostinfo by the (unauthenticated) `RemoteIndex` field taken straight from the packet header, and compares the packet's *source* `netip.AddrPort` against the hostinfo's currently known remote address as the only check before tearing the tunnel down: [2](#0-1) 

Because UDP has no source-address authentication at the transport layer, and because `RecvError` packets are deliberately unencrypted (needed since they signal "I have no session to decrypt this"), an attacker with no CA-signed certificate and no participation in the mesh can craft a bare `header.RecvError` packet, spoof the UDP source `IP:port` of one of the two legitimate peers (obtainable by observing traffic or via NAT-mapping knowledge), and send it to the other peer. If `f.acceptRecvErrorConfig.ShouldRecvError(addr)` allows it — which is `recvErrorAlways` by default per the code comment in `interface.go` (`recvErrorAlways recvErrorConfig = iota`) — the victim's stack accepts the forged packet, matches the spoofed address against `hostinfo.GetRemote()`, and calls `f.closeTunnel(hostinfo)` plus `f.handshakeManager.DeleteHostInfo(hostinfo)`, destroying a fully authenticated, encrypted, currently-in-use tunnel: [3](#0-2) 

This mirrors the Canto bug class precisely: a narrow, unrelated signal (a "receiver had no session" hint, analogous to a zero-fee CSR distribution error) is allowed to unconditionally destroy legitimate, unrelated state (a working tunnel/transaction) with no independent verification that the party triggering the destructive path is actually authorized to do so.

### Impact Explanation
An attacker who never possesses a CA-signed certificate can forcibly tear down any active nebula tunnel between two legitimate, fully-authenticated peers by spoofing a single UDP packet, so long as they can guess or observe the peers' UDP `IP:port` pair (feasible off standard-path if the source network does not do egress/ingress filtering, or on-path). This is a remote denial-of-service against legitimate, unrelated traffic — the victim tunnel is destroyed and both sides must re-handshake, causing outage/latency for real inter-node traffic that never touched the attacker.

### Likelihood Explanation
Likelihood is moderate-to-high in networks that don't strictly enforce BCP38 (source-address) egress filtering, since: (1) `recv_error` acceptance defaults to `always`, (2) no certificate, no valid session key, and no packet body beyond the fixed header are required, and (3) the only gate is a source-address string compare which spoofing bypasses entirely. It requires knowing (or guessing) the target's currently active UDP source/dest 4-tuple, which is attainable by an on-path observer or a peer that recently was in the mesh but had its remote address recorded, but is not trivial for a fully blind off-path attacker over the public internet.

### Recommendation
- Do not act on `recv_error` based solely on UDP source-address match; require it to be tied to information the sender could only know if it recently held a valid session (e.g., accept it only for a short window after a decrypt failure was observed for that specific packet exchange, or authenticate it with a lightweight per-tunnel token/HMAC keyed off the last known session material) rather than a bare index+source compare.
- Consider defaulting `accept_recv_error` to something more conservative than `always` (e.g. `private`/`never`) so operators must opt in to trusting an unauthenticated signal to destroy tunnel state, consistent with the existing CHANGELOG note that `recv_error` already trades off exposure for convenience.
- Rate-limit / require corroboration (e.g. multiple consecutive out-of-session receive failures reported by the actual data path) before tearing down an established tunnel on the basis of a `recv_error`.

### Proof of Concept
1. Establish a real, working nebula tunnel between hosts A and B (both hold valid CA-signed certs).
2. As attacker M (no certificate), observe or infer A's and B's active UDP `IP:port` pair for the tunnel (e.g. via traffic observation, prior mesh membership, or NAT knowledge).
3. Craft a bare header-only UDP packet with `Type = header.RecvError` and `RemoteIndex` set to B's local index for the A↔B hostinfo (index values are short and can be brute-forced/observed), and spoof the source address to A's UDP address, sending it to B.
4. B's `readOutsidePackets` dispatches to `handleRecvError` without any cert/AEAD check; since the spoofed source matches `hostinfo.GetRemote()` and `acceptRecvErrorConfig` is `always` by default, B calls `f.closeTunnel(hostinfo)` and deletes the pending hostinfo, killing the tunnel to A even though M never authenticated to the mesh. func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
```go
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
```

```go
type recvErrorConfig uint8

const (
	recvErrorAlways recvErrorConfig = iota
	recvErrorNever
	recvErrorPrivate
)

func (s recvErrorConfig) ShouldRecvError(endpoint netip.AddrPort) bool {
	switch s {
	case recvErrorPrivate:
		return endpoint.Addr().IsPrivate()
	case recvErrorAlways:
		return true
	case recvErrorNever:
		return false
	default:
		panic(fmt.Errorf("invalid recvErrorConfig value: %d", s))
	}
}
```
