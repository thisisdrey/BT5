Confirmed. `verify_nonce` at `runtime/runtime/src/verifier.rs:211-235` checks `tx_nonce > current_nonce` (Monotonic) with an upper bound of `block_height * 1_000_000`, but the "current_nonce" is whatever is currently stored in the per-index `GasKeyNonce` trie entry — it has no memory of nonce values consumed by a *prior incarnation* of the same public key.

### Title
Gas-key nonce reseed on same-block DeleteKey+AddKey enables replay of an already-billed gas-key transaction - (File: runtime/runtime/src/access_keys.rs)

### Summary
`add_gas_key` seeds every `GasKeyNonce[i]` to `initial_nonce_value(block_height) = (block_height - 1) * 1_000_000` regardless of any nonce value already consumed for that same public key earlier in the *same* block. An attacker who deletes and immediately recreates their own gas key within the block in which a gas-key nonce was just consumed can roll the per-index nonce back below the already-used value, then successfully resubmit the original signed transaction later and have it re-verified and re-executed.

### Finding Description
`add_gas_key` (`runtime/runtime/src/access_keys.rs:194-228`) unconditionally seeds every nonce index with `initial_nonce_value(block_height)` (`access_keys.rs:46-50`), using the block height of the *current* apply pass. `action_delete_key` → `delete_gas_key` (`access_keys.rs:52-92`, `93-134`) removes all `GasKeyNonce` entries for the key with no persisted memory of previously issued/consumed values. There is no cross-check tying the reseeded value to any nonce that has already been consumed for that `(account_id, public_key, nonce_index)` triple.

`verify_and_charge_gas_key_tx_ephemeral` (`runtime/runtime/src/verifier.rs:370-479`) authorizes a gas-key transaction purely by comparing `tx_nonce` against the currently-stored `current_nonce` fetched via `get_gas_key_nonce`, using `verify_nonce` (`verifier.rs:211-235`), which only requires `tx_nonce > current_nonce` (Monotonic mode) and `tx_nonce < block_height * 1_000_000`.

Exploit flow:
1. Attacker's gas key `PK` (owned by attacker's own account) with `num_nonces = k` is used at block height `H` to submit a gas-key transaction with `nonce_index = 0`, `nonce = N`, where `(H-1)*1_000_000 < N < H*1_000_000`. It executes successfully; `GasKeyNonce[0] = N`.
2. Within the same block height `H` (a second transaction signed with a regular/full-access key of the same account, submitted in the same or a different chunk at height `H`), the attacker submits `[DeleteKey(PK), AddKey(PK, GasKeyFullAccess{num_nonces=k})]`. `delete_gas_key` removes the old nonce entries; `add_gas_key` reseeds `GasKeyNonce[0..k]` to `initial_nonce_value(H) = (H-1)*1_000_000`, which is strictly less than `N`.
3. At any later block height `H' > H`, the attacker resubmits (or a relayer resubmits) the exact same signed transaction bytes from step 1 (nonce_index 0, nonce N). `get_gas_key_nonce` now returns the reseeded value `(H-1)*1_000_000 < N`, so `verify_nonce` passes (`N > (H-1)*1_000_000` and `N < H'*1_000_000`), and the transaction is re-verified, re-charged, and re-executed as a brand-new receipt.

Existing checks do not stop this: nonce monotonicity is checked only against the live stored value, not against a historical high-water mark; the intra-chunk duplicate-transaction-hash filter (`skip_duplicate_txs` in `runtime/runtime/src/lib.rs`) is scoped to a single chunk's transaction batch and does not persist across blocks, so a resubmission in a later block/chunk is not caught by it.

### Impact Explanation
This is a genuine double-execution/replay of a gas-metered transaction: the original transaction's actions (e.g., a `Transfer` or `FunctionCall`) are executed a second time via a freshly derived receipt, without the signer having ever signed a "new" instruction. This falls under double-spend/replay of value — a NEAR bounty category for direct fund loss/duplication, since any deposit-carrying or contract-invoking action tied to that nonce/nonce_index can be re-billed and re-executed against the receiver.

### Likelihood Explanation
Preconditions are fully within an ordinary attacker's control: they only need their own account, a gas key they created, and the ability to submit ordinary transactions (AddKey/DeleteKey/gas-key transfer/function-call) to a public RPC. No validator, peer, or privileged access is required. The attack is deterministic and repeatable for any gas key and any nonce index the attacker controls, as long as they can arrange for the delete+recreate transaction to land in the same block height as the transaction whose nonce they want to later replay — feasible by simply submitting both transactions to RPC in quick succession.

### Recommendation
When reseeding gas-key nonces in `add_gas_key`, do not use a value that can regress below a nonce already consumed for that same `(account_id, public_key, nonce_index)`. Track (or read back) the highest nonce ever used for that key/index — e.g., persist a per-account/per-key "last used nonce" watermark independent of key deletion, or seed using `max(initial_nonce_value(block_height), previous_highest_nonce + 1)`—so that deleting and recreating a gas key within the same block (or any subsequent block) can never produce a seed lower than a nonce value already consumed by a prior incarnation of that key.

### Proof of Concept
Unit test plan (in `runtime/runtime/src/access_keys.rs` / `runtime/runtime/src/verifier.rs` test modules, mirroring `test_gas_key_tx_nonce_updated` and `test_add_gas_key`):
1. Set up an account with a gas key `PK`, `num_nonces = 1`, at block height `H`, funded with a gas-key balance.
2. Call `validate_verify_and_charge_transaction` (or `verify_and_charge_gas_key_tx_ephemeral` directly) with `nonce_index=0`, `nonce = N` where `(H-1)*1_000_000 < N < H*1_000_000`; assert success and that `get_gas_key_nonce(.., 0)` is updated to `N`.
3. At the same block height `H`, call `action_delete_key` for `PK`, then `action_add_key` re-adding `PK` as a gas key with `num_nonces=1`.
4. Assert `get_gas_key_nonce(.., 0)` is now `initial_nonce_value(H) = (H-1)*1_000_000`, which is `< N`.
5. Re-invoke `verify_and_charge_gas_key_tx_ephemeral`/`validate_verify_and_charge_transaction` with the *same* `nonce_index=0`, `nonce=N` (optionally at a later `block_height = H+1`). Assert it returns `TxVerdict::Success` instead of `InvalidNonce` — demonstrating the previously-consumed nonce is accepted a second time, i.e., the same billed transaction can be re-verified/re-executed.
