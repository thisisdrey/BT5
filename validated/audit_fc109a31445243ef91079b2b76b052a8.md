### Title
Unauthenticated forged miner messages accepted via `/stackerdb_chunks` due to missing signature check on `MINERS_NAME` branch - (File: libsigner/src/events.rs)

### Summary
`SignerEventReceiver` binds a plain, unauthenticated `tiny_http` server and, for any POST to `/stackerdb_chunks`, deserializes the JSON body into a `StackerDBChunksEvent` and passes it to `TryFrom<StackerDBChunksEvent> for SignerEvent<T>`. In the miner (`MINERS_NAME`) branch, chunk data is fed directly into `T::consensus_deserialize` without ever calling `chunk.recover_pk()`, unlike the sibling `SIGNERS_NAME` branch which explicitly recovers and validates the signer's public key before accepting a chunk.

### Finding Description
The broken equality: every `SignerEvent::MinerMessages` reaching the signer runloop is supposed to originate from a chunk that was actually signed by a legitimate StackerDB slot owner of the miners contract. In `libsigner/src/events.rs`, `TryFrom<StackerDBChunksEvent>::try_from` at lines 549-567 handles the case `event.contract_id.name.as_str() == MINERS_NAME`: [1](#0-0) 
by looping over `event.modified_slots` and calling `T::consensus_deserialize(&mut chunk.data.as_slice())` directly, pushing the result into `messages`, with no call to `chunk.recover_pk()` and no signature check at all. This is in stark contrast to the very next branch for `SIGNERS_NAME` contracts (lines 568+), which explicitly does `let Ok(pk) = chunk.recover_pk() else { ... return None; };` before accepting a chunk's payload: [2](#0-1) 

The `next_event` handler in `EventReceiver::next_event` (`fn bind`, `fn next_event`) shows the HTTP server accepts any POST to `/stackerdb_chunks` with no auth header, secret, or peer-identity check: [3](#0-2) 
The body is parsed straight from `serde_json::from_slice` in `process_event`, with no origin verification: [4](#0-3) 

An attacker who can open a raw TCP connection to the bound event-receiver port can therefore POST a JSON body such as `{"contract_id":<miners boot contract>,"modified_slots":[{"slot_id":0,"slot_version":1,"data":<serialized SignerMessage bytes>,"signature":[0u8;65]}]}`. Because the signature field is never inspected in the miner branch, `T::consensus_deserialize` will happily parse the attacker-controlled bytes as a valid `SignerMessage`, and `SignerEvent::MinerMessages(messages)` will be forwarded to the runloop as if the message had been legitimately posted by the node from a chunk actually written to StackerDB by an authorized miner slot holder.

### Impact Explanation
This is an unauthenticated write into the signer's `MinerMessages` event stream: an attacker can inject arbitrary forged "miner" instructions/messages into a signer's decision pipeline without holding any StackerDB slot key or any node secret, purely by reaching the event-receiver's HTTP port. This matches "Critical — unauthenticated write to state or StackerDB" / spoofed data accepted as authentic, and is repeatable per TCP connection/POST.

However, this is caveated by the reachability question below.

### Likelihood Explanation
The critical caveat: this port is not the node's P2P or RPC port. `SignerEventReceiver` is bound by the *signer* process to receive event-dispatcher callbacks pushed by its associated stacks-node (typically configured to listen on a loopback or private address, and reachable only from the node it is paired with via the node's `event_observer` config). The attacker model given in the rules is scoped to "any remote party who can connect to a node's P2P or RPC port... own a StackerDB slot... gossip messages" — it does not establish that the signer's event-receiver bind address is reachable by an arbitrary remote unprivileged party under the defined threat model, since that endpoint is an internal-plane channel between a node and its signer, not the public P2P/RPC surface. Whether this port is exposed to the public internet is purely an operator/network-topology configuration matter, not a code-level authentication defect distinguishable from "the operator exposed a private control channel publicly." If the operator does expose it, the missing signature check is real and directly exploitable with no other precondition (no valid slot, no key, no secret needed) — but that reachability precondition falls outside the specified in-scope attacker capabilities (P2P/RPC reachability, slot ownership, gossip), which is explicitly not the same network location as this endpoint.

### Recommendation
Add signature verification identical to the `SIGNERS_NAME` branch to the `MINERS_NAME` branch in `libsigner/src/events.rs`: call `chunk.recover_pk()` and verify the recovered key is an authorized slot owner for the miners contract before calling `T::consensus_deserialize`, discarding any chunk that fails recovery/verification, mirroring the existing logic at lines 596-610.

### Proof of Concept
Not applicable as a valid finding under the specified threat model — see Likelihood Explanation. If the endpoint's reachability were in scope, a Rust test would: bind a `SignerEventReceiver<SignerMessage>`, craft a `StackerDBChunkData` with `signature = [0u8;65]` and a validly-encoded `SignerMessage` in `.data`, wrap it in `StackerDBChunksEvent{contract_id: boot_code_id(MINERS_NAME, is_mainnet), modified_slots: vec![chunk]}`, POST it as JSON to `/stackerdb_chunks` on the bound address, and assert `SignerEvent::MinerMessages` is emitted despite the all-zero signature — demonstrating the missing `recover_pk()` check contrasted with the `SIGNERS_NAME` path.

where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}
