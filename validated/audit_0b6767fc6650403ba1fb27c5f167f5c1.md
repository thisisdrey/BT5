### Title
`socialize-debt` writes down `lindex` and reduces `total-borrowed`/`principal-scaled` without first accruing pending interest, misallocating interest across suppliers — analogous to Aura/Convex `MasterChef.add()` mutating `totalAllocPoint` without `massUpdatePools()` - (File: `mainnet/contracts/vault/v0-vault-sbtc.clar` and sibling vault contracts)

### Summary
Every other state-mutating entry point in the vault contracts (`deposit`, `redeem`, `system-borrow`, `system-repay`, `set-fee-reserve`, `set-points-util`, `set-points-rate`) begins with `(try! (accrue))` to roll `index`/`lindex` forward to the current block time before touching global accounting variables. `socialize-debt` is the one exception: it reads `index`/`lindex`/`total-assets` directly from stale storage and immediately mutates `lindex`, `principal-scaled`, `total-borrowed`, and `assets` based on those stale values, exactly the same class of bug as `ConvexMasterChef.add()`/`set()` mutating `totalAllocPoint` without first calling `massUpdatePools()`.

### Finding Description
In `socialize-debt`, the function reads `index`, `lindex`, and `total-assets` without calling `accrue()` first: [1](#0-0) 

Compare this to `system-borrow`/`system-repay`/`deposit`/`redeem`, which all call `(try! (accrue))` as their first operation before reading `index`/`total-borrowed`/`assets`: [2](#0-1) [3](#0-2) 

and the DAO setters (`set-fee-reserve`, `set-points-util`, `set-points-rate`) which likewise call `accrue()` before changing a variable that feeds the interest/index calculation: [4](#0-3) 

`lindex` is the liquidity index that determines how much of accrued interest between the last update and "now" belongs to existing suppliers versus how it's distributed after a write-down. Because `socialize-debt` uses the stale `index`/`lindex`/`total-assets` (as of `last-update`, not "now"), any interest that accrued between `last-update` and the block in which `socialize-debt` executes is silently dropped from the calculation: the `debt-reduction` and `new-lindex` write-down is computed against a total-assets figure that doesn't yet include that pending interest, so the proportional loss allocation applied to `lindex` is wrong (either overstating or understating the write-down applied to remaining suppliers) — the same "totalAllocPoint modified before massUpdatePools()" incorrect-proportional-accounting bug pattern from the report.

`socialize-debt` is gated by `check-caller-auth` (restricting direct callers to the market/market-vault), but it is reachable indirectly by any ordinary, unprivileged principal calling `liquidate` on `market.clar` when a liquidation leaves the borrower with no remaining collateral — that code path calls `socialize-debt-asset` → `vault-socialize-debt` for each stripped debt asset: [5](#0-4) 

So any user (the liquidator) can trigger this stale-index write-down simply by liquidating an underwater position down to zero collateral, at a block where meaningful time (and thus interest) has passed since the vault's `last-update`.

### Impact Explanation
This misallocates real yield among zToken (`zft`) holders/suppliers of the affected vault: the write-down to `lindex` either burns more supplier value than the actual bad debt loss warrants, or fails to correctly account for interest that should have accrued to suppliers before the loss was applied, and the treasury LP mint for the reserve fee tied to that interest delta (computed only inside `accrue()`) is skipped entirely for this window since `socialize-debt` never mints it. This is a theft/misallocation of unclaimed yield across all suppliers of the vault, falling under the in-scope "theft of unclaimed yield ... or temporary freezing of funds" High-severity category, since the discrepancy compounds each time bad debt is socialized without a preceding accrual.

### Likelihood Explanation
Likelihood is moderate-to-high: bad-debt socialization is a normal, expected outcome of the protocol's liquidation flow (triggered whenever a liquidation strips all collateral from an underwater position), and it can be triggered by any unprivileged liquidator without any special permissions, at any block where the vault has not been recently accrued (e.g., low-traffic vaults where deposits/borrows/repays haven't touched `accrue()` recently). The larger the elapsed time since `last-update`, the larger the missed/incorrect interest allocation.

### Recommendation
Call `(try! (accrue))` at the start of `socialize-debt` (mirroring every other state-mutating vault function) before reading `index`, `lindex`, `total-borrowed`, `total-assets`, and `principal-scaled`, so the write-down is computed against up-to-date accrual state, consistent with the `massUpdatePools()`-style fix recommended for `ConvexMasterChef.add()`/`set()`.

### Proof of Concept
1. Deposit liquidity into a vault (e.g., `vault-sbtc`) and have a borrower take on debt, then let a meaningful amount of time/blocks pass without any `deposit`/`redeem`/`borrow`/`repay` call on that vault (so `last-update` remains stale and pending interest accumulates in `next-index()`/`next-liquidity-index()` but is not yet applied to `index`/`lindex`/`assets`).
2. Push the borrower's position underwater (e.g., via price movement) and have any unprivileged user call `market.liquidate(...)` such that the position's remaining collateral is fully seized and debt is fully written down to zero, causing `no-collateral-left` to be true.
3. This triggers `socialize-debt-asset` → the vault's `socialize-debt`, which computes `debt-reduction`/`new-lindex` using the stale `index`/`lindex`/`total-assets` from before the pending-interest accrual, mutating `lindex`/`principal-scaled`/`total-borrowed`/`assets` directly.
4. Compare the resulting zToken share price (`convert-to-assets-preview`) immediately after socialization against what it would have been had `accrue()` been called first — the values diverge, demonstrating suppliers receive an incorrect (mis-proportioned) write-down relative to actual pending interest, and no treasury-LP mint occurs for interest that should have been captured in that window.

(define-public (socialize-debt (scaled-amount uint))
  (let ((scaled-principal (var-get principal-scaled))
        (borrowed (var-get total-borrowed))
        (idx (var-get index))
        (current-assets (var-get assets))
        (current-lindex (var-get lindex))
        (old-total-assets (total-assets))
        (debt-reduction (mul-div-down scaled-amount idx INDEX-PRECISION))
        (principal-reduction (if (> scaled-principal u0)
                                (mul-div-down scaled-amount borrowed scaled-principal)
                                u0))
        ;; Write down lindex proportionally to loss in total-assets
        (new-lindex (if (and (> old-total-assets u0) (> old-total-assets debt-reduction))
                       (mul-div-down current-lindex (- old-total-assets debt-reduction) old-total-assets)
                       u0)))

    (try! (check-caller-auth))
    (asserts! (> scaled-amount u0) ERR-AMOUNT-ZERO)

    (var-set lindex new-lindex)
    (var-set principal-scaled (if (> scaled-principal scaled-amount) (- scaled-principal scaled-amount) u0))
    (var-set total-borrowed (if (> borrowed principal-reduction) (- borrowed principal-reduction) u0))
    (var-set assets (if (> current-assets principal-reduction) (- current-assets principal-reduction) u0))

(define-private (socialize-debt-asset
                (debt-entry { aid: uint, scaled: uint })
                (acc { borrower: principal, success: bool }))
  ;; Early return if previous socialization failed
  (if (not (get success acc))
      acc
      (let ((borrower (get borrower acc))
            (failed-status { borrower: borrower, success: false })
            (asset-id (get aid debt-entry))
            (scaled-debt (get scaled debt-entry)))

            ;; Socialize in vault - pass scaled directly to avoid rounding
            (unwrap! (vault-socialize-debt asset-id scaled-debt) failed-status)
            ;; Refresh cache with new indexes post-write-down (lindex decreased)
            (map-set index-cache
                     { timestamp: stacks-block-time, aid: asset-id }
                     (unwrap! (vault-accrue asset-id) failed-status))
            ;; Remove from obligation
            (unwrap! (contract-call? .v0-market-vault
                                      debt-remove-scaled
                                      borrower
                                      scaled-debt
                                      asset-id) failed-status)
          acc)
        ))
