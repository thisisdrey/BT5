### Title
StackerDBListener aborts its run loop on a well-formed signer message whose slot_id is absent from the cached signer_entries map - ([File: stacks-node/src/nakamoto_node/stackerdb_listener.rs])

### Summary
`StackerDBListener::run` processes `SignerMessageV0::BlockResponse` messages read from the `signers-N-M` StackerDB contract. For each parsed message it does `let Some(signer_entry) = &self.signer_entries.get(&slot_id) else { return Err(NakamotoNodeError::SignerSignatureError(...)) };` at `stacks-node/src/nakamoto_node/stackerdb_listener.rs:373-377`. Unlike almost every other malformed/unexpected-condition branch in the same loop (which log a warning and `continue`), this one propagates an `Err` out of `run()`, terminating the entire listener thread/loop for the remainder of the tenure.

### Finding Description
This mirrors the reported bug class: a data source (`LegacyMessagePasser` calls / here, `StackerDB` chunk writes to the `signers-*` contract) is consumed under an assumption that every observed record corresponds 1:1 with an expected, pre-computed set (`slotsAct` vs `slotsInp` in the OP report; `modified_slots` vs `signer_entries` here). When that assumption is violated, the code does not gracefully skip the offending record — it aborts the whole process instead of continuing degraded operation.

`self.signer_entries` is built once at `StackerDBListener::new` time from the `reward_set.signers()` list [1](#0-0) , and is keyed by the slot index derived from that fixed reward-set ordering. The chunks actually delivered from StackerDB, however, are keyed by `chunk.slot_id` as reported by `event.modified_slots` (i.e., whatever the StackerDB replica says the slot ID is for a stored, signed chunk) [2](#0-1) . The main loop then does:

```
for (slot_id, _pk, message) in messages.into_iter() {
    let Some(signer_entry) = &self.signer_entries.get(&slot_id) else {
        return Err(NakamotoNodeError::SignerSignatureError(
            "Signer entry not found".into(),
        ));
    };
    ...
}
``` [3](#0-2) 

Any legitimate StackerDB chunk write that (a) is validly signed by *some* registered signer (satisfying `try_replace_chunk`'s signature/version checks in `stackslib/src/net/stackerdb/db.rs`) but (b) is stored under a `slot_id` this listener instance doesn't have an entry for — e.g., a stale/reconfigured reward-set snapshot, a signer set membership change race between reward cycles, or a mismatch between the miner's locally cached `signer_entries` and the live StackerDB slot layout — causes `run()` to return `Err`, which per the call chain terminates the polling loop entirely: `debug!("StackerDBListener: received node exit request. Aborting")`-style early returns elsewhere are graceful, but this one is not caught and retried; contrast with the `Some(_) else { continue; }` handling used for every neighboring failure mode in the same function (e.g. `signer_entry` lookup failure vs. `blocks.get_mut` miss at line 400, or `signer_pubkey` parse failure at 378-383, both of which just `continue`/log).

Once `run()` returns `Err`, the listener stops consuming signer messages for the remainder of the tenure — analogous to the migration halting in the OP report — requiring the miner to rebuild/restart the listener (if such recovery exists) rather than simply dropping the one bad/racy chunk.

### Impact Explanation
This breaks the availability of block-signature aggregation for the tenure: once the listener errors out, the miner stops accepting/counting signer `BlockResponse` messages via this channel, which can prevent block finalization/signing progress for that tenure until the coordinator/listener is restarted. This maps to the "bounded compute DoS on a read endpoint" / degraded processing category rather than a full network-wide compromise, since it affects only the local miner's listener thread and requires a legitimately-signed-but-slot-mismatched chunk (no forged signature is needed, just a stale/mismatched slot mapping). This is a High-severity availability issue for that node's tenure-coordination logic, not a crash of the whole node process and not unauthorized state mutation.

### Likelihood Explanation
Reaching this precise state requires the signer set indexing between the locally cached `signer_entries` (fixed at listener construction from the reward set) and the currently-active `slot_id`s actually being written into the `signers-N-M` StackerDB contract to diverge — e.g., during a reward-cycle-boundary reconfiguration, or if a compromised/faulty signer that is still a valid slot owner writes to a slot ID your local snapshot doesn't recognize. This is plausible during churn near reward-cycle boundaries but not trivially triggerable by an arbitrary unauthenticated attacker with no signer standing at all (the write must first pass `try_replace_chunk`'s signature check against the slot's registered owner). It's a mid-likelihood implementation robustness gap rather than a directly attacker-crafted forgery.

### Recommendation
Change the `signer_entries.get(&slot_id)` miss branch to log a warning and `continue` (as is done for every other similar "unexpected data" branch in this loop), instead of returning `Err` and aborting the entire listener run loop. This preserves availability by dropping/ignoring the single unrecognized message rather than halting all signature processing for the tenure.

### Proof of Concept
1. Start a `StackerDBListener` for reward cycle `N` with `signer_entries` built from a given `reward_set` snapshot (`stacks-node/src/nakamoto_node/stackerdb_listener.rs:227-239`).
2. Have a StackerDB replica hold a validly-signed chunk (passes `try_replace_chunk`'s owner-signature check in `stackslib/src/net/stackerdb/db.rs`) at a `slot_id` that is not a key in the listener's `signer_entries` map (e.g. due to a reconfiguration between when the listener snapshot was taken and when the StackerDB event fires).
3. Deliver that chunk as a `StackerDBChunksEvent` to the listener's receiver.
4. Observe `run()` hit the `let Some(signer_entry) = &self.signer_entries.get(&slot_id) else { return Err(...) }` branch and return `Err(NakamotoNodeError::SignerSignatureError(...))`, terminating the listener loop instead of skipping the one unrecognized message.
