### Title
Unauthenticated signer event-receiver blindly trusts forged `StackerDBChunksEvent` bodies, allowing forged miner/block data to bypass StackerDB chunk-signature validation - (File: libsigner/src/events.rs)

### Summary
`SignerEventReceiver::next_event()` accepts and processes any HTTP POST to `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, and `/new_block` with no authentication or origin check, then converts the JSON body directly into a `SignerEvent` and forwards it to the signer's core runloop. For the `.miners` contract lane, the conversion path performs **no cryptographic signature verification at all** on the embedded chunk data before treating it as an authentic miner message.

### Finding Description
The `SignerEventReceiver` binds a bare `tiny_http`-based HTTP server and accepts any POST request without checking that it originated from the local, trusted stacks-node event dispatcher: [1](#0-0) 

Requests to `/stackerdb_chunks` are deserialized directly from the request body and converted via `TryFrom<StackerDBChunksEvent> for SignerEvent<T>`: [2](#0-1) 

Inside that conversion, chunks destined for the `.miners` boot contract are accepted as `MinerMessages` using only `consensus_deserialize` — with **no signature check whatsoever**: [3](#0-2) 

This is a broken "authenticated-and-stored vs. served-as-authentic" equality: on the legitimate path, a chunk only reaches this event because the stacks-node's `StackerDBs::try_replace_chunk` already verified `SlotMetadata::verify()` against the registered slot owner before storing and dispatching the event (see `stackslib/src/net/stackerdb/db.rs::try_replace_chunk`, which calls `slot_desc.verify(&slot_validation.signer)` before any chunk is persisted). However, the `SignerEventReceiver` HTTP endpoint has no mechanism to guarantee that an incoming `/stackerdb_chunks` POST actually originated from that trusted node pipeline — it accepts the payload from whatever TCP client reaches the bound port and skips straight to trusting the contained data as validated/stored miner content.

By contrast, the `signers-*` lane in the same function does at least call `chunk.recover_pk()` to obtain *some* public key, and downstream consumers such as `stacks-signer/src/v0/signer.rs` additionally check `is_valid_signer(&signer_address)` before acting on the message — but the `.miners` lane has neither of these mitigations, so a forged, syntactically-well-formed miner message (e.g., a `BlockProposal`) is passed through completely unauthenticated into `SignerEvent::MinerMessages`, which is subsequently processed by the signer runloop as if it were a genuine proposal from the network's miner.

### Impact Explanation
This breaks the "served as canonical/authentic" guarantee for data feeding directly into the block-signing decision pipeline. Any remote party capable of reaching a signer's event-receiver HTTP port (a value determined by the operator's network exposure/firewalling, not by protocol-level authentication) can inject arbitrary, unsigned "miner messages" that the signer will treat identically to messages that the node validated against the real miner's registered key. Given that signer proposal handling is the entry point that ultimately drives whether a signer participates in signing a block, unauthenticated forged input at this boundary is a high-severity issue: it removes the cryptographic authentication step that the rest of the StackerDB/relay pipeline (`SlotMetadata::verify`, `try_replace_chunk`) is designed to enforce for exactly this class of data.

### Likelihood Explanation
Exploitability depends entirely on whether the signer's event-receiver bind address is reachable by a remote/untrusted party (e.g., bound to a non-loopback interface, or reachable through misconfigured network/firewall rules — a common operational reality for node/signer deployments that aren't hardened to bind strictly to `127.0.0.1`). Given the code performs **zero authentication** on the endpoint itself (no shared secret, no source-IP allow-list, no mTLS) and **zero signature verification** on the miner-message lane specifically, likelihood is high wherever the receiver port is not perfectly firewalled — and the protocol code provides no defense-in-depth to fall back on if that perimeter control fails.

### Recommendation
1. Require the `.miners` lane in `TryFrom<StackerDBChunksEvent> for SignerEvent<T>` to verify each chunk's signature against the actual registered miner public key (mirroring the check already done in `stacks-node/src/nakamoto_node/stackerdb_listener.rs` for block responses) before constructing `MinerMessages`.
2. Add authentication to the `SignerEventReceiver` HTTP endpoint itself (e.g., a pre-shared token/HMAC header set by the node's event dispatcher and validated on receipt, and/or binding restricted to loopback plus a documented requirement to firewall the port) so that forged HTTP POSTs from unauthenticated remote sources cannot reach the event-processing pipeline at all.
3. Apply the same `is_valid_signer`/registered-key verification pattern already used for the `signers-*` lane to the `.miners` lane for defense-in-depth.

### Proof of Concept
1. Identify a signer node with `SignerEventReceiver` bound to a network-reachable address (its bind address is operator-configured; no protocol-level restriction exists).
2. Craft a `StackerDBChunksEvent` JSON body whose `contract_id` is the `.miners` boot contract and whose `modified_slots` contains an arbitrary `StackerDBChunkData` with unsigned/self-signed payload bytes that `consensus_deserialize` can parse as a valid miner message type (e.g., a `BlockProposal`).
3. POST this JSON directly to the signer's `http://<signer-host>:<port>/stackerdb_chunks` endpoint.
4. Because `TryFrom<StackerDBChunksEvent>` for the `.miners` lane only calls `T::consensus_deserialize` with no signature check (`libsigner/src/events.rs` lines 549-567), the forged message is emitted as `SignerEvent::MinerMessages(..)` and forwarded to the signer runloop identically to a message that the real stacks-node would only have produced after verifying `SlotMetadata::verify()` against the actual miner's slot signer.

            if event_receiver.is_stopped() {

            }
            debug!("Request handling");

            debug!("Got request"; "method" => %request.method(), "path" => request.url());

                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)
            } else if request.url() == "/new_block" {
                process_event::<T, StacksBlockEvent>(request)

                Err(EventError::UnrecognizedEvent(url))
            }

fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}
