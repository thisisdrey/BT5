### Title
Closing a bank permanently strands uncollected protocol/insurance/group fees - ([File: programs/marginfi/src/instructions/marginfi_group/close_bank.rs])

### Summary
`lending_pool_close_bank` closes a `Bank` account (returning rent to the admin) once it has no open positions and zero asset/liability shares. It never checks or sweeps `collected_group_fees_outstanding`, `collected_insurance_fees_outstanding`, or `collected_program_fees_outstanding` before destroying the account. This is the direct on-chain analog of the reported `Raises.sol` `close()` bug: a state transition (Active raise → Funded / operational bank → closed) is performed without first moving accrued protocol fees into a retrievable balance, permanently stranding them.

### Finding Description
`lending_pool_close_bank` performs these checks before closing the bank account via `close = admin`: [1](#0-0) 

It validates `CLOSE_ENABLED_FLAG`, zero open positions, zero `total_asset_shares`/`total_liability_shares`, and zero `emissions_remaining` — but it does **not** check `bank.collected_group_fees_outstanding`, `bank.collected_insurance_fees_outstanding`, or `bank.collected_program_fees_outstanding`.

These three fields accumulate real, uncollected token value sitting in the bank's `liquidity_vault` (per `guides/ADMIN/COLLECTING_FEES.md` and `accrue_interest` in `programs/marginfi/src/state/bank.rs`): [2](#0-1) 

They are only ever moved out of the liquidity vault by the permissionless `LendingPoolCollectBankFees` instruction, which requires loading the live `Bank` account to authenticate the vault-authority PDA signer (via `bank.load()?.liquidity_vault_authority_bump`): [3](#0-2) 

`LendingPoolCloseBank`'s account set only includes the `bank` account itself (with `close = admin`) — it never references `liquidity_vault`, `fee_vault`, or `insurance_vault`, so those SPL token accounts are not closed or swept: [4](#0-3) 

Once the `Bank` account is closed (Anchor zeroes/reallocates the account and marks it closed), any later attempt to run `LendingPoolCollectBankFees` (or any instruction that derives the vault authority bump from `bank.load()`) fails because the account no longer deserializes as a valid `Bank`. There is no admin-only "sweep orphaned fees" instruction and no way to reconstruct the required bump/authority once the account data is gone. Any tokens sitting in `liquidity_vault` corresponding to outstanding fee buckets — and the `liquidity_vault`/`fee_vault`/`insurance_vault` SPL accounts themselves — become permanently orphaned and unrecoverable.

This mirrors the external report precisely: a legitimate, permission-checked state transition (`Raises.close()` Active→Funded / `lending_pool_close_bank` Operational→closed) advances state without first crediting/collecting accrued protocol fees, permanently locking them in a contract-controlled balance that becomes unreachable after the transition.

### Impact Explanation
This causes a permanent, unrecoverable loss/lock of protocol funds:
- Group fees (owed to the marginfi group/admin), insurance fees (owed to the insurance vault, used to cover future bad debt), and program fees (owed to the program owner/global fee wallet) can all be lost.
- The loss is irreversible: once the `Bank` account is closed, there is no remaining code path capable of authorizing a transfer out of the associated `liquidity_vault`, since the vault authority's bump seed can only be sourced from the (now-destroyed) `Bank` account.
- While this requires the bank to reach the closable state (`CLOSE_ENABLED_FLAG` set, zero positions/shares) and requires the admin to trigger closure without first calling the permissionless `LendingPoolCollectBankFees`, this is an easily reachable and realistic operational sequence — the admin has no explicit warning or on-chain check preventing it, and `LendingPoolCollectBankFees` is a separate instruction that is easy to omit.

### Likelihood Explanation
Fees accrue continuously via `accrue_interest` any time the bank is touched (borrow, repay, deposit, withdraw), so it's plausible for a bank nearing wind-down (last depositor withdraws, driving `total_asset_shares`/`total_liability_shares` to zero) to still have nonzero outstanding fee buckets from interest accrued up to that point. If the admin then calls `lending_pool_close_bank` (a normal part of the documented bank lifecycle — see `guides/ADMIN/BANK_STATE.md` "Closure" step) without first running `LendingPoolCollectBankFees`, the funds are lost. This is a realistic, unprivileged-observable outcome even though the closing action itself is admin-gated: any group admin performing routine bank decommissioning without the extra fee-collection step triggers the bug, and no compensating on-chain control exists to prevent or reverse it.

### Recommendation
In `lending_pool_close_bank`, before closing the bank, either:
1. Require `bank.collected_group_fees_outstanding`, `bank.collected_insurance_fees_outstanding`, and `bank.collected_program_fees_outstanding` to be zero (with the same `check!`/tolerance pattern already used for asset/liability shares), forcing the admin to run `LendingPoolCollectBankFees` first; or
2. Have `lending_pool_close_bank` itself sweep any outstanding fee amounts from the `liquidity_vault` into the `fee_vault`/`insurance_vault`/`fee_ata` (mirroring the logic in `lending_pool_collect_bank_fees`) prior to closing, so no value can be stranded regardless of admin ordering.

### Proof of Concept
1. Group admin creates a bank with `CLOSE_ENABLED_FLAG` set (default for banks created ≥0.1.4).
2. Users deposit/borrow, and time passes so that `accrue_interest` accumulates nonzero values in `collected_group_fees_outstanding` / `collected_insurance_fees_outstanding` / `collected_program_fees_outstanding` (see `programs/marginfi/src/state/bank.rs` lines 578-602), while the corresponding token amount sits in the bank's `liquidity_vault`.
3. All borrowers repay and all depositors withdraw, driving `total_asset_shares` and `total_liability_shares` to zero — satisfying `lending_pool_close_bank`'s checks in `programs/marginfi/src/instructions/marginfi_group/close_bank.rs` lines 27-37 — but the admin does **not** call `LendingPoolCollectBankFees` first.
4. Admin calls `lending_pool_close_bank`. The instruction only checks position counts, shares, and emissions (lines 22-41), passes, and the `Bank` account is closed (`close = admin`).
5. The `liquidity_vault` (and `fee_vault`/`insurance_vault`) SPL accounts remain on-chain holding the uncollected fee tokens, but any subsequent call to `LendingPoolCollectBankFees` for this bank fails because `bank: AccountLoader<'info, Bank>` can no longer deserialize the closed account, and no bump/authority can be re-derived without it — permanently locking the fee tokens.
