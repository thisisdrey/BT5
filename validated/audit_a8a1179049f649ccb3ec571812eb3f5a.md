## Title
Missing Authentication on the Signer's HTTP Event-Receiver Endpoint Allows Unauthenticated Injection of Forged StackerDB/Block-Proposal Events - (File: `libsigner/src/events.rs`)

### Summary
`SignerEventReceiver` (used by `stacks-signer`) opens a plain HTTP server that accepts unauthenticated `POST` requests on `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block`, and `/shutdown`, and feeds the parsed bodies directly into the signer's runloop as trusted `SignerEvent`s. There is no check that the request actually originated from the paired `stacks-node` process (no token, no peer-address restriction, no mTLS). Any host that can reach the listening socket can POST a crafted JSON body and have it treated as a genuine event from the node, analogous to the Pion DTLS defect where post-handshake data was accepted without checking that it was actually authenticated.

### Finding Description
`SignerEventReceiver::bind` simply starts an HTTP listener on the configured `endpoint` with no authentication layer: [1](#0-0) 

`next_event` dispatches based solely on the URL path, with no verification of the request's source or any shared secret/authorization header: [2](#0-1) 

Even the `/shutdown` path terminates the receiver loop for anyone who can reach the socket. Compare this to the *node-side* RPC surface (block proposal endpoint), which is explicitly gated by an `auth_token`/`auth_password` shared secret documented in `docs/signing.md` and the sample configs: [3](#0-2) 

That secret protects the *node's* proposal-validation RPC, but it is never checked on the *signer's* inbound event listener — the direction this report is about. The reference signer config even binds this listener to all interfaces by default: [4](#0-3) 

Once a `/stackerdb_chunks` body is accepted, chunk contents are converted into `SignerEvent`s. For the `signers-*` boot contract, the code recovers *whatever* public key produced a valid ECDSA signature over the chunk (`chunk.recover_pk()`), but does not check that this key belongs to the actual registered signer for that `slot_id`/reward cycle before emitting a `SignerMessages` event upstream: [5](#0-4) 

Because the HTTP endpoint itself performs no origin authentication, and the payload-decoding path performs no binding of the recovered key to the expected signer set, a remote unauthenticated party that can reach the signer's event port can supply arbitrary, self-signed StackerDB chunks/proposal responses that are indistinguishable, at this layer, from data legitimately relayed by the paired `stacks-node`. This breaks the intended trust equality "message came from my paired node's already-validated dispatch" vs. "message came from anyone who can open a TCP connection to this port."

### Impact Explanation
This is an authentication-bypass class issue (CWE-287) on the signer's local control-plane channel: the signer's runloop is meant to trust only events forwarded by its own paired node (which already performs chunk/slot-signer verification before dispatching), but the receiver enforces no such trust boundary. An attacker reaching the port can inject forged `/stackerdb_chunks`, `/proposal_response`, or `/new_burn_block` events, or trivially DoS the signer via unauthenticated `/shutdown`. Depending on deployment (the shipped reference config binds `0.0.0.0`), this is reachable by any network-adjacent or (if misconfigured/exposed) remote host, matching the "unauthenticated/unauthorized write to state" and "auth bypass" impact tiers called out in scope.

### Likelihood Explanation
Likelihood is high wherever the event listener is reachable beyond loopback: no credentials, tokens, or TLS are required, and the sample/reference config for the signer binary explicitly binds `0.0.0.0:30000`. Even when documentation recommends binding to `127.0.0.1`, the code provides no enforcement or warning, and nothing prevents operators (or containerized/proxied deployments) from exposing the port.

### Recommendation
Add an authentication mechanism to `SignerEventReceiver`'s HTTP server analogous to the node's existing `auth_token`/`auth_password` scheme: require and verify a shared secret (e.g., an `Authorization` header or bearer token) on every inbound request before processing, and reject/ignore unauthenticated requests. Additionally, consider validating that `signers-*` chunk signer keys are members of the currently registered signer set before converting them into `SignerEvent::SignerMessages`, rather than only checking that *some* valid signature exists.

### Proof of Concept
1. Deploy `stacks-signer` with the reference config (`endpoint = "0.0.0.0:30000"`, as shipped in `sample/conf/signer/mainnet-signer-conf.toml`).
2. From a remote host with no knowledge of any secret, connect to `<signer-ip>:30000` and issue:
   ```
   POST /stackerdb_chunks HTTP/1.1
   Host: <signer-ip>:30000
   Content-Type: application/json
   Content-Length: <N>

   {"contract_id": "...signers-0-3...", "modified_slots": [ ... self-signed chunk data ... ]}
   ```
3. `SignerEventReceiver::next_event` (libsigner/src/events.rs:413-458) processes the body without any authentication check, converts it via `TryFrom<StackerDBChunksEvent>` (lines 544-624), and forwards it into the signer runloop as a legitimate `SignerEvent::SignerMessages`, indistinguishable from data sent by the real, paired stacks-node.

    /// Errors are recoverable -- the caller should call this method again even if it returns an
    /// error.
    fn next_event(&mut self) -> Result<SignerEvent<T>, EventError> {
        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)
            } else if request.url() == "/new_block" {
                process_event::<T, StacksBlockEvent>(request)
            } else {
                let url = request.url().to_string();
                debug!(
                    "[{:?}] next_event got request with unexpected url {}, return OK so other side doesn't keep sending this",
                    event_receiver.local_addr,
                    url
                );
                ack_dispatcher(request);
                Err(EventError::UnrecognizedEvent(url))
            }
        })?
