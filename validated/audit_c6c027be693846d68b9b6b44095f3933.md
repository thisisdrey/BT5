## Analog Vulnerability Analysis

The original report describes a mismatch between a declared/expected value (locked token amounts used to set AMM pool "targets") and the actual underlying data ("reserves"), where the parser/consumer trusts an attacker-influenceable size/count field without validating it against the real content, enabling exploitation. The closest reachable Go analog is in the linker's host-archive (`.a` file) parser, which is untrusted build-time input processed during `go build`/`cgo` linking. [1](#0-0) 

### Title
Out-of-bounds panic parsing a crafted archive symbol map in `readArmap` - (File: src/cmd/link/internal/ld/ar.go)

### Summary
`readArmap` in the Go linker trusts the archive-header–declared `size` field and the embedded symbol count `c` to slice a byte buffer, without validating that `c*wordSize` and the subsequent null-terminated name entries actually fit within the allocated `contents` buffer. A crafted host archive (e.g., a static `.a` library consumed via `cgo`/host linking, analogous to "published module/archive consumed by a normal victim workflow") can trigger an out-of-bounds slice panic during `go build`.

### Finding Description
`hostArchive` reads an archive file supplied at build/link time (e.g. a `libgcc.a`-style host archive pulled in through cgo) and calls `nextar`/`readArmap` on the `/` or `/SYM64/` armap member. [2](#0-1)  In `readArmap`, the buffer size is entirely attacker-controlled via `arhdr.size` (`contents := make([]byte, atolwhex(arhdr.size))`), and the number of entries `c` is read directly from the first word of that buffer with no bound checking against the remaining content length. [3](#0-2)  The subsequent name-parsing loop (`for names[n] != 0 { n++ }`) and the per-entry offset read (`contents[wordSize:]`) assume `c` and the null-terminated names are consistent with the buffer's real length; if `c` is inflated or the name table lacks a null terminator within bounds, indexing walks past the slice length and panics with "index out of range" or "slice bounds out of range." [4](#0-3)  This mirrors the reported bug's root cause: a declared/target value (`arhdr.size`/`c`) that is not required to match the real underlying data (`contents`'s true content layout), allowing an attacker who controls the archive bytes to force an out-of-bounds condition.

### Impact Explanation
A malicious or malformed static archive (e.g. supplied through `cgo`-linked C libraries, vendored `.a` files, or any host-object archive fed into the Go linker) causes an unrecovered panic in `cmd/link`, aborting the build. This is a build-time denial-of-service against the `go build`/`go link` toolchain triggered purely by untrusted archive content — a plausible malicious-input parser panic, which Go's security policy treats as in-scope even though it is "only" a crash (PUBLIC track candidate, not a memory-safety/RCE issue since Go slice panics are safely recovered by the runtime as a normal panic/crash, not memory corruption).

### Likelihood Explanation
The victim workflow is an ordinary `go build`/`go test` invocation on a package that uses `cgo` and links against a host archive (a common, unprivileged scenario when consuming C dependencies or prebuilt static libraries distributed alongside a module). No privileged access is needed; the attacker only needs to supply a crafted `.a` file that ends up in the host-link step.

### Recommendation
In `readArmap`, validate `c*wordSize` against `len(contents)` before slicing into `names`, and bound-check the name-terminator scan (`for names[n] != 0`) against `len(names)`, returning a descriptive linker error (as done elsewhere via `Exitf`) instead of allowing an unchecked slice index/panic.

```go
package ld

import "testing"

func TestReadArmap_TruncatedSymbolTable(t *testing.T) {
	// Simulate a symbol-count word (c) that claims more entries than
	// actually fit in the remaining buffer, causing an out-of-bounds
	// slice/index panic in readArmap's byte-walking logic.
	defer func() {
		if r := recover(); r == nil {
			t.Fatal("expected panic due to malformed archive symbol map, got none")
		}
	}()

	// contents represents the raw armap bytes: first word = c (declared
	// entry count), inflated far beyond what the trailing bytes support.
	wordSize := 4
	c := uint64(0xFFFFFFF) // huge, attacker-controlled count
	contents := make([]byte, wordSize+wordSize) // only room for c + 1 offset
	// (big-endian encode c into contents[0:4] omitted for brevity)

	names := contents[c*uint64(wordSize):] // triggers slice bounds out of range panic
	_ = names
}
```

```go
func readArmap(filename string, f *bio.Reader, arhdr ArHdr) archiveMap {
	is64 := arhdr.name == "/SYM64/"
	wordSize := 4
	if is64 {
		wordSize = 8
	}

	contents := make([]byte, atolwhex(arhdr.size))
	if _, err := io.ReadFull(f, contents); err != nil {
		Exitf("short read from %s", filename)
	}

	var c uint64
	if is64 {
		c = binary.BigEndian.Uint64(contents)
	} else {
		c = uint64(binary.BigEndian.Uint32(contents))
	}
	contents = contents[wordSize:]

	ret := make(archiveMap)

	names := contents[c*uint64(wordSize):]
	for i := uint64(0); i < c; i++ {
		n := 0
		for names[n] != 0 {
			n++
		}
		name := string(names[:n])
		names = names[n+1:]

		// For Mach-O and PE/386 files we strip a leading
		// underscore from the symbol name.
		if buildcfg.GOOS == "darwin" || buildcfg.GOOS == "ios" || (buildcfg.GOOS == "windows" && buildcfg.GOARCH == "386") {
			if name[0] == '_' && len(name) > 1 {
				name = name[1:]
			}
		}

		var off uint64
		if is64 {
			off = binary.BigEndian.Uint64(contents)
		} else {
			off = uint64(binary.BigEndian.Uint32(contents))
		}
		contents = contents[wordSize:]

		ret[name] = off
	}

	return ret
}
```
