## Title
Neighbor-of-neighbor and pingback handshake acceptance stores self-reported `HandshakeData.addrbytes`/`port` in the peer frontier without binding it to the address that actually answered - ([File: stackslib/src/net/db.rs], [File: stackslib/src/net/neighbors/walk.rs], [File: stackslib/src/net/chat.rs])

### Summary
When a node walks its peer graph, it dials `NeighborAddress`es it learned from `NeighborsData` gossip or from a pingback hint, and treats whichever `HandshakeAccept` comes back as authoritative for that connection. The resulting `Neighbor`'s address key is built purely from the `HandshakeData.addrbytes`/`port` fields inside the reply — a self-reported value the remote peer fully controls — and is written straight into `PeerDB`'s `frontier` table without ever checking it against the socket/address that was actually dialed. Only the "primary current-neighbor" handshake path enforces such a check; the "neighbor-of-neighbor" and "pingback" paths do not.

### Finding Description
The broken equality is: **identity stored in `frontier` (`addrbytes`, `port`, `network_id`) must equal the identity of the endpoint that produced the signature**, i.e. the address actually dialed/reached. This equality holds for the primary walk step but not for the two secondary handshake paths:

- `Neighbor::load_and_update` (`stackslib/src/net/chat.rs:475-516`) builds the stored `NeighborKey` via `NeighborKey::from_handshake(peer_version, network_id, handshake_data)` — i.e. purely from the self-reported `HandshakeData.addrbytes`/`port` inside the signed payload, not from the TCP endpoint that was contacted. [1](#0-0) 
- In the "current neighbor" walk step, `handle_handshake_accept` explicitly guards against mismatches: `if self.walk_outbound && neighbor_from_handshake.addr != self.cur_neighbor.addr { ... return Err(...) }`. [2](#0-1) 
- However, for **neighbors-of-neighbors** (`handle_neighbor_handshake_accept`), the actually-dialed `naddr` is never compared to `data.handshake.addrbytes/port`; the handshake data is passed straight to `add_or_schedule_replace_neighbor`. [3](#0-2) 
- For **pingback handshakes** (new inbound peers we ping back), the only check performed is `check_handshake_pubkey_hash`, which validates the public-key hash against the expected `NeighborAddress`, but never the claimed `addrbytes`/`port`. [4](#0-3) 
- `add_or_schedule_replace_neighbor` then calls `Neighbor::load_and_update` (rebuilding the key from `handshake_data`) and, for new peers, `neighbor_from_handshake.save(...)`. [5](#0-4) 
- `Neighbor::save` calls `PeerDB::try_insert_peer` (`stackslib/src/net/db.rs:1452-1488`), which — if the (network_id, addrbytes, port) key is new and a slot is free — calls `PeerDB::insert_or_replace_peer` (`stackslib/src/net/db.rs:1091-1133`), writing `neighbor.addr.addrbytes`/`port` (the unverified, self-reported values) into the `frontier` table. [6](#0-5) [7](#0-6) 

The attacker's exact message: an attacker who is either (a) an existing `cur_neighbor` gossiping a `NeighborAddress` pointing at their own second controlled endpoint (naddr), or (b) any inbound connector who later responds to a pingback dial, replies to the resulting `Handshake` request with a `HandshakeAccept`/`StackerDBHandshakeAccept` whose embedded `HandshakeData.addrbytes`/`port` names a victim IP/port (or any arbitrary address) instead of the address actually dialed. The message is signed correctly by the attacker's real `node_public_key` — that signature only proves authorship of the payload bytes, never a binding between the claimed `addrbytes`/`port` and the TCP endpoint that produced it. Because neither `handle_neighbor_handshake_accept` nor `pingback_handshakes_try_finish` cross-checks the claimed address against the dialed `naddr`, the forged (victim) address/port pair is persisted in the local node's `frontier` table.

Existing guards that do NOT stop this:
- `filter_sensible_neighbors` only drops `is_anynet()`/private-range addresses, not arbitrary spoofed public addresses. [8](#0-7) 
- The addr-mismatch guard only exists on the `walk_outbound && cur_neighbor` path, not on neighbor-of-neighbor or pingback paths. [2](#0-1) 
- `check_handshake_pubkey_hash` validates only the public-key hash, not the address. [9](#0-8) 

### Impact Explanation
A remote attacker's node can cause a victim's `PeerDB.frontier` table to contain a forged `Neighbor` record keyed by an address/port the attacker does not control (e.g. a victim service or arbitrary IP), with the attacker's real public key attached. This forged record is durable, persisted peer state, and it is subsequently gossiped to other nodes on the network via `NeighborsData` in response to `GetNeighbors` requests, propagating the phantom/forged address network-wide. This is an unauthenticated write of forged network topology into persistent state with network-wide propagation potential, matching the Critical severity bucket.

### Likelihood Explanation
No privileged role or secret is required. The attacker only needs to run one (or two, for the neighbor-of-neighbor variant) ordinary P2P peer(s) that a victim node will walk to — a trivial precondition since Stacks nodes routinely crawl their known frontier and gossip-derived addresses. The attacker fully controls the `HandshakeData` payload it sends back over its own legitimately-established connection, so exploitation cost is a single crafted, validly-signed message; it is repeatable for each new address the attacker wishes to inject.

### Recommendation
In `handle_neighbor_handshake_accept` (`stackslib/src/net/neighbors/walk.rs`) and `pingback_handshakes_try_finish`, verify that `data.handshake.addrbytes`/`port` match the `naddr`/`nk` that was actually dialed and that responded (as already done for `handle_handshake_accept`'s `walk_outbound` case), rejecting or overriding to the observed connection address when they differ (similar to the existing private/anynet override logic in `handle_handshake_accept`). Only persist the observed reachable address into `PeerDB`, not attacker-supplied self-reported coordinates, unless equality with the dialed address is confirmed.

### Proof of Concept
Rust test plan in `stackslib::net::neighbors` (or a lower-level `db.rs` unit test mirroring `test_try_insert_peer`):
1. Build a `HandshakeData` whose `addrbytes`/`port` point to a "victim" address/port distinct from the socket address used to establish the connection (mirrors `PeerDB::try_insert_peer` test scaffolding at `stackslib/src/net/db.rs:2213-2324`).
2. Simulate `handle_neighbor_handshake_accept`/`add_or_schedule_replace_neighbor` (`stackslib/src/net/neighbors/db.rs:368-427`) being invoked with `preamble` from a connection dialed at a different `naddr`, and this forged `HandshakeData`.
3. Assert `PeerDB::get_peer(conn, network_id, &victim_addrbytes, victim_port)` (`stackslib/src/net/db.rs`) returns `Some(neighbor)` — i.e. the victim's un-controlled address/port is now present in `frontier`, proving unauthenticated forged-topology insertion.

                .insert(neighbor.addr.clone(), neighbor.clone());

            // frontier maintenance
            self.frontier
                .insert(neighbor.addr.clone(), neighbor.clone());
        }

        self.resolved_handshake_neighbors.insert(naddr, neighbor);
        Ok(())
    }

    fn check_handshake_pubkey_hash(
        nk: &NeighborKey,
        data: &HandshakeAcceptData,
        naddr: &NeighborAddress,
    ) -> bool {
        let neighbor_pubkey_hash =
            Hash160::from_node_public_key_buffer(&data.handshake.node_public_key);
        if neighbor_pubkey_hash != naddr.public_key_hash {
            debug!(
                "Neighbor {:?} had an unexpected pubkey hash: expected {:?} != {:?}",
                nk, &naddr.public_key_hash, &neighbor_pubkey_hash
            );
            return false;
        }

        true
    }

                db_data,

    fn add_or_schedule_replace_neighbor(
        &self,
        network: &mut PeerNetwork,
        preamble: &Preamble,
        handshake: &HandshakeData,
        db_data: Option<&StackerDBHandshakeData>,
        replacements: &mut NeighborReplacements,
    ) -> Result<(bool, Neighbor), net_error> {
        let local_peer_str = format!("{:?}", network.get_local_peer());
        let tx = network.peerdb_tx_begin()?;
        let (mut neighbor_from_handshake, was_present) =
            Neighbor::load_and_update(&tx, preamble.peer_version, preamble.network_id, handshake)?;

        if was_present {
            test_debug!(
                "{}: already know about neighbor {:?}",
                &local_peer_str,
                &neighbor_from_handshake.addr
            );
            neighbor_from_handshake
                .save_update(&tx, db_data.map(|x| x.smart_contracts.as_slice()))?;
            tx.commit()?;

            // seen this neighbor before
            return Ok((false, neighbor_from_handshake));
        }

        debug!(
            "{}: new neighbor {:?}",
            &local_peer_str, &neighbor_from_handshake.addr
        );

        // didn't know about this neighbor yet. Try to add it.
        let added =
            neighbor_from_handshake.save(&tx, db_data.map(|x| x.smart_contracts.as_slice()))?;

        if added {
            // neighbor was new, and we had space to add it.
            tx.commit()?;
            return Ok((true, neighbor_from_handshake));
        }

    pub fn try_insert_peer(
        tx: &Transaction,
        neighbor: &Neighbor,
        stacker_dbs: &[QualifiedContractIdentifier],
    ) -> Result<bool, db_error> {
        let present = PeerDB::has_peer(
            tx,
            neighbor.addr.network_id,
            &neighbor.addr.addrbytes,
            neighbor.addr.port,
        )?;
        if present {
            // already here
            PeerDB::update_peer(tx, neighbor)?;
            PeerDB::update_peer_stacker_dbs(tx, neighbor, stacker_dbs)?;
            return Ok(true);
        }

        let slots = PeerDB::peer_slots(
            tx,
            neighbor.addr.network_id,
            &neighbor.addr.addrbytes,
            neighbor.addr.port,
        )?;
        for slot in slots.iter() {
            let used_slot = PeerDB::has_peer_at(tx, neighbor.addr.network_id, *slot)?;
            if !used_slot {
                // have a spare slot!
                PeerDB::insert_or_replace_peer(tx, neighbor, *slot)?;
                PeerDB::insert_or_replace_stacker_dbs(tx, *slot, stacker_dbs)?;
                return Ok(true);
            }
        }

        // no slots free
        return Ok(false);
    }
