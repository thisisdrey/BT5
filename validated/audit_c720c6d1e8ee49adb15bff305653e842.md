### Title
`RewardsDistributor` credits a first-time holder rewards equal to their full token balance when the supply index is pinned at `INITIAL_INDEX` - (File: `contracts/RewardsDistributor.sol`)

### Summary

`INITIAL_INDEX` (`1e18`) is overloaded: it means "no accrual has happened yet" for the token, but `_calculateTokenDelta` only resets a fresh account's index when the token index is **strictly greater** than `INITIAL_INDEX`. While a reward-enabled DepositToken/DebtToken has zero `totalSupply`, `_calculateTokenIndex` adds a `0` ratio each update, leaving `tokenStates[token_].index` pinned at exactly `1e18`. Any account that holds the token while this is true receives `_tokensDelta = balance.wadMul(1e18) = balance`, i.e. reward tokens equal to its entire deposit/debt balance, with zero elapsed accrual.

### Finding Description [1](#0-0) 

```solidity
_tokenIndex = _tokenState.index;
uint256 _accountIndex = accountIndexOf[token_][account_];

if (_accountIndex == 0 && _tokenIndex > INITIAL_INDEX) {
    _accountIndex = INITIAL_INDEX;
}

uint256 _deltaIndex = _tokenIndex - _accountIndex;
_tokensDelta = token_.balanceOf(account_).wadMul(_deltaIndex);
```

When `tokenIndex == INITIAL_INDEX` and `accountIndex == 0`, the guard fails (strict `>`), so `_accountIndex` stays `0`, `_deltaIndex == 1e18`, and `_tokensDelta` equals the holder's full balance.

The index stays at `1e18` whenever `totalSupply == 0`, because `_calculateTokenIndex` computes `_ratio = 0` and writes back `index = 1e18` while refreshing `timestamp`: [2](#0-1) 

`claimRewards` then happily accrues for any token whose stored index is non-zero: [3](#0-2) 

and pays out via `_transferRewardIfEnoughTokens`, which transfers `min(accrued, distributorBalance)`: [4](#0-3) 

### Impact Explanation

Direct theft of unclaimed yield: a single attacker transaction (flash-loan underlying → `Pool.deposit` → `RewardsDistributor.claimRewards`) sets `tokensAccruedOf[attacker]` to the attacker's (arbitrarily large, flash-boosted) deposit balance and immediately transfers out up to the distributor's entire `rewardToken` balance — rewards owed to all other users. The same applies to DebtToken balances via `flashIssue`/leverage.

### Likelihood Explanation

The pinned-index state occurs naturally whenever a speed-enabled reward token has zero supply: a newly listed deposit/debt token before its first deposit, or any market that has been fully withdrawn. The token is registered with `index = INITIAL_INDEX` the moment `updateTokenSpeed` sets a non-zero speed ( [5](#0-4) ), and index only moves once `speed * dt / totalSupply > 0`. No privileged or malicious actor is required at claim time; `claimRewards` is permissionless and the attacker supplies only their own account address and token list.

### Recommendation

In `_calculateTokenDelta`, treat `accountIndex == 0` as "initialize to current index" unconditionally (`_accountIndex = _tokenIndex`), or change the guard to `>= INITIAL_INDEX` so a first-time holder never accrues a delta against the sentinel base index. Alternatively, do not accrue when the index has never advanced past `INITIAL_INDEX`.

### Proof of Concept

Foundry fork-style sketch:

```solidity
// Assume: governor enabled reward speed for depositToken while its totalSupply == 0
// (index pinned at INITIAL_INDEX). Distributor holds rewardToken balance B.

function test_pinnedIndexDrainsRewards() public {
    uint256 flashAmount = 1_000_000e18;

    // 1. Flash-borrow underlying
    underlying.mint(attacker, flashAmount);

    vm.startPrank(attacker);
    underlying.approve(address(depositToken), flashAmount);

    // 2. Deposit -> attacker now holds flashAmount of depositToken
    depositToken.deposit(flashAmount);

    // 3. Claim: index still == 1e18 (supply was 0 until just now, dt == 0 or ratio == 0)
    IERC20[] memory toks = new IERC20[](1);
    toks[0] = IERC20(address(depositToken));
    distributor.claimRewards(attacker, toks);

    // tokensAccruedOf[attacker] == flashAmount (wadMul(1e18)); payout = min(accrued, B)
    assertEq(rewardToken.balanceOf(attacker),
             Math.min(flashAmount, rewardToken.balanceOf(address(distributor))));
    vm.stopPrank();
}
```

Uncertain: whether a deployed pool currently has a speed-enabled token at zero supply was not verifiable from the index alone, but the condition is reachable through normal operations (new listing / fully withdrawn market), and the same-block window after `updateTokenSpeed` provides an additional trigger.

    function _calculateTokenIndex(
        TokenState memory _supplyState,
        IERC20 token_
    ) private view returns (uint224 _newIndex, uint32 _newTimestamp) {
        uint256 _speed = tokenSpeeds[token_];
        uint256 _deltaTimestamps = block.timestamp - uint256(_supplyState.timestamp);
        if (_deltaTimestamps > 0 && _speed > 0) {
            uint256 _totalSupply = token_.totalSupply();
            uint256 _tokensAccrued = _deltaTimestamps * _speed;
            uint256 _ratio = _totalSupply > 0 ? _tokensAccrued.wadDiv(_totalSupply) : 0;
            _newIndex = (_supplyState.index + _ratio).toUint224();
            _newTimestamp = block.timestamp.toUint32();
        } else if (_deltaTimestamps > 0 && _supplyState.index > 0) {
            _newTimestamp = block.timestamp.toUint32();
        }
    }
