### Title
Inconsistent self-destruct guard allows stake/vote/delegation native contracts to operate on an already self-destructed (logically freed) account within the same transaction - (File: actuator/src/main/java/org/tron/core/vm/nativecontract/UnfreezeBalanceV2Processor.java, DelegateResourceProcessor.java, UnDelegateResourceProcessor.java, VoteWitnessProcessor.java, CancelAllUnfreezeV2Processor.java)

### Summary
The CVE describes a Linux kernel use-after-free where an object (`nft_rule`) is destroyed while a stale reference to it is still used through `NFTA_RULE_CHAIN_ID`. The analogous pattern in java-tron is an account capsule that has been logically "freed" via `SELFDESTRUCT` (marked with `markSelfDestruct`) but is not yet physically deleted from the account store until the transaction commits — while several TVM native-contract processors continue to read and mutate this logically-destroyed account's stake/vote/delegation fields without checking its self-destructed status.

### Finding Description
When a TVM contract executes `SELFDESTRUCT`, `Program.suicide2` only calls `getContractState().markSelfDestruct(owner)`; the actual removal from `AccountStore`/`ContractStore` (`RepositoryImpl.deleteContract`) is deferred to commit time, well after execution of the current call frame. [1](#0-0) [2](#0-1) 

This means within the same transaction, subsequent native contract invocations against the same address are executed against an account object that is logically dead but still readable/writable — a pattern structurally analogous to referencing memory after it has been logically freed but before the underlying deallocation completed.

The codebase already recognizes this class of bug and has patched exactly one processor, `FreezeBalanceV2Processor`, to detect and specially handle the self-destructed state: [3](#0-2) 

However, the sibling processors that mutate the same class of stake/vote/delegation state on an `AccountCapsule` do **not** perform this check:
- `UnfreezeBalanceV2Processor.validate`/`execute` — no `isSelfDestructed` check, mutates `totalNetWeight`/`totalEnergyWeight`/`totalTronPowerWeight` and vote state. [4](#0-3) 
- `DelegateResourceProcessor.validate`/`execute` — no check, moves frozen-V2 balance into `DelegatedResourceCapsule` and adjusts receiver's acquired balance. [5](#0-4) 
- `UnDelegateResourceProcessor.validate`/`execute` — no check, similarly mutates weights and delegated-resource state. [6](#0-5) 
- `VoteWitnessProcessor.validate`/`execute` — no check at all, directly mutates votes based on `tronPower` derived from the (soon to be deleted) account. [7](#0-6) 
- `CancelAllUnfreezeV2Processor.validate`/`execute` — checks only `hasInvalidDelegatedV2`, not self-destruct status, and re-adds frozen balances / total weights. [8](#0-7) 

Because `deleteContract` (which removes the account from `AccountStore`) executes only once at commit, calling any of these unguarded native contracts against a self-destructed address within the same transaction/call context can permanently adjust global accounting fields such as `totalNetWeight`, `totalEnergyWeight`, and `totalTronPowerWeight` in `DynamicPropertiesStore`, and vote tallies in `VotesCapsule`, based on state belonging to an account that will subsequently vanish. These global weight adjustments are not reversed when the account is deleted, since `deleteContract` simply removes the account/code/contract entries without correcting the aggregate weight counters: [9](#0-8) 

### Impact Explanation
If reachable, this would let an attacker permanently desynchronize `totalNetWeight`/`totalEnergyWeight`/`totalTronPowerWeight` from the sum of live accounts' actual frozen balances (an "unbacked" resource-accounting condition), and could corrupt vote tallies used for SR election — a `Medium`-`High` impact under the "unbacked balance" / "unauthorized account operation" categories called out in the validation rubric.

### Likelihood Explanation
I was not able to fully confirm, within the available investigation budget, whether the TVM opcode dispatcher / native-contract entry point actually permits invoking these native contracts (`UNFREEZEBALANCEV2`, `DELEGATERESOURCE`, `UNDELEGATERESOURCE`, `VOTEWITNESS`, `CANCELALLUNFREEZEV2`) against an address for which `markSelfDestruct` has already been recorded earlier in the same transaction (e.g., via a re-entrant call from the self-destructing contract before it returns, or via a subsequent contract call in the same transaction targeting the same address). The existence of a fix in exactly one analogous processor (`FreezeBalanceV2Processor`, backed by `StakeV2AfterSelfDestructTest`) strongly suggests the underlying reachability was previously demonstrated for at least one native contract, but I could not verify equivalent PoC-level reachability for the other five processors in this session.

### Recommendation
Add the same `repo.isSelfDestructed(ownerAddress)` guard (and associated CPU-time/behavior handling, mirroring `MUtil.checkCPUTimeForFreezeV2AfterSelfDestruct`) to `UnfreezeBalanceV2Processor`, `DelegateResourceProcessor`, `UnDelegateResourceProcessor`, `VoteWitnessProcessor`, and `CancelAllUnfreezeV2Processor`, or alternatively make `deleteContract` immediately synchronous with `markSelfDestruct` so no native contract can observe or mutate a self-destructed account's stake/vote state within the same transaction.

### Proof of Concept
Not fully constructed — a concrete PoC would require confirming the TVM call path that allows invoking one of the unguarded native contracts against `owner` after `Program.suicide2` has marked it self-destructed but before the enclosing transaction commits (e.g., via a crafted contract that calls a precompiled "unfreeze/vote/delegate" native contract on itself immediately after emitting `SELFDESTRUCT`, or via reentrancy from the inheritor account). This reachability step is the main open item; the `StakeV2AfterSelfDestructTest.java` test file confirms the general "operate after self-destruct" scenario is a recognized, previously-fixed bug class for `FreezeBalanceV2Processor`, which is why the same gap in the sibling processors is flagged here. [10](#0-9)

      throw new ContractValidateException("Invalid unfreeze operation, unfreezing times is over limit");
    }
    switch (param.getResourceType()) {
      case BANDWIDTH:
        // validate frozen balance
        if (!this.checkExistFrozenBalance(accountCapsule, Common.ResourceCode.BANDWIDTH)) {
          throw new ContractValidateException("no frozenBalance(BANDWIDTH)");
        }
        break;
      case ENERGY:
        // validate frozen balance
        if (!this.checkExistFrozenBalance(accountCapsule, Common.ResourceCode.ENERGY)) {
          throw new ContractValidateException("no frozenBalance(ENERGY)");

          if (!this.checkExistFrozenBalance(accountCapsule, Common.ResourceCode.TRON_POWER)) {
            throw new ContractValidateException("no frozenBalance(TRON_POWER)");
          }
        } else {
          throw new ContractValidateException("Unknown ResourceCode, valid ResourceCode[BANDWIDTH、ENERGY]");
        }
        break;
      default:
        if (dynamicStore.supportAllowNewResourceModel()) {
          throw new ContractValidateException("Unknown ResourceCode, valid ResourceCode[BANDWIDTH、ENERGY、TRON_POWER]");
        } else {
          throw new ContractValidateException("Unknown ResourceCode, valid ResourceCode[BANDWIDTH、ENERGY]");
        }
    }

    if (!checkUnfreezeBalance(accountCapsule, param.getUnfreezeBalance(), param.getResourceType())) {
      throw new ContractValidateException(
          "Invalid unfreeze_balance, [" + param.getUnfreezeBalance() + "] is invalid");
    }

    if (accountCapsule.hasInvalidDelegatedV2()) {
      MUtil.checkCPUTimeForInvalidDelegatedV2Balance();
    }
  }

    }

      throw new ContractValidateException("delegateBalance must be greater than or equal to 1 TRX");

    switch (param.getResourceType()) {

          throw new ContractValidateException(

        }
      }
      break;
      case ENERGY: {
        EnergyProcessor processor =
            new EnergyProcessor(dynamicStore, ChainBaseManager.getInstance().getAccountStore());
        processor.updateUsage(ownerCapsule);

        long energyUsage = (long) (ownerCapsule.getEnergyUsage() * TRX_PRECISION * ((double)
            (repo.getTotalEnergyWeight()) / dynamicStore.getTotalEnergyCurrentLimit()));

        long v2EnergyUsage = getV2EnergyUsage(ownerCapsule, energyUsage, disableJavaLangMath);

        if (ownerCapsule.getFrozenV2BalanceForEnergy() - v2EnergyUsage < delegateBalance) {
          throw new ContractValidateException(
                  "delegateBalance must be less than or equal to available FreezeEnergyV2 balance");
        }
      }
      break;
      default:
        throw new ContractValidateException(
            "Unknown ResourceCode, valid ResourceCode[BANDWIDTH、ENERGY]");
    }

    byte[] receiverAddress = param.getReceiverAddress();

  public void execute(VoteWitnessParam param, Repository repo) throws ContractExeException {
    byte[] ownerAddress = param.getVoterAddress();
    VoteRewardUtil.withdrawReward(ownerAddress, repo);

    AccountCapsule accountCapsule = repo.getAccount(ownerAddress);

    VotesCapsule votesCapsule = repo.getVotes(ownerAddress);
    if (votesCapsule == null) {
      votesCapsule = new VotesCapsule(ByteString.copyFrom(ownerAddress),
          accountCapsule.getVotesList());
    }

    accountCapsule.clearVotes();
    votesCapsule.clearNewVotes();

    Map<ByteString, Long> voteMap = new HashMap<>();
    Iterator<Protocol.Vote> iterator = param.getVotes().iterator();
    try {
      long sum = 0;
      while (iterator.hasNext()) {
        Protocol.Vote vote = iterator.next();

        byte[] witnessAddress = vote.getVoteAddress().toByteArray();
        /*
          Already covered while doing maintenance in MaintenanceManager.java, for tvm performance,
          we remove the account check
         */
//        if (repo.getAccount(witnessAddress) == null) {
//          throw new ContractValidateException(
//              ACCOUNT_EXCEPTION_STR + StringUtil.encode58Check(witnessAddress) + NOT_EXIST_STR);
//        }
        if (repo.getWitness(witnessAddress) == null) {
          throw new ContractExeException(
              WITNESS_EXCEPTION_STR + StringUtil.encode58Check(witnessAddress) + NOT_EXIST_STR);
        }

        long voteCount = vote.getVoteCount();
        if (voteCount < 0) {
          throw new ContractExeException("Vote count must not be less than 0");
        } else if (voteCount == 0) {
          iterator.remove();
        } else {
          sum = LongMath.checkedAdd(sum, voteCount);
          // merge vote for same witness
          voteMap.put(vote.getVoteAddress(),
              LongMath.checkedAdd(voteMap.getOrDefault(vote.getVoteAddress(), 0L), voteCount));
        }
      }

      long tronPower;
      if (repo.getDynamicPropertiesStore().supportUnfreezeDelay()
          && repo.getDynamicPropertiesStore().supportAllowNewResourceModel()) {
        tronPower = accountCapsule.getAllTronPower();
      } else {
        tronPower = accountCapsule.getTronPower();
      }
      sum =  LongMath.checkedMultiply(sum, TRX_PRECISION);
      if (sum > tronPower) {
        throw new ContractExeException(
            "The total number of votes[" + sum + "] is greater than the tronPower[" + tronPower
                + "]");
      }
    } catch (ArithmeticException e) {
      throw new ContractExeException(e.getMessage());
    }

    for (Map.Entry<ByteString, Long> entry : voteMap.entrySet()) {
      accountCapsule.addVotes(entry.getKey(), entry.getValue());
      votesCapsule.addNewVotes(entry.getKey(), entry.getValue());
    }
    repo.updateAccount(accountCapsule.createDbKey(), accountCapsule);
    repo.updateVotes(ownerAddress, votesCapsule);
  }

  public Map<String, Long> execute(CancelAllUnfreezeV2Param param, Repository repo) throws ContractExeException {
    Map<String, Long> result = new HashMap<>();
    byte[] ownerAddress = param.getOwnerAddress();
    AccountCapsule ownerCapsule = repo.getAccount(ownerAddress);
    long now = repo.getDynamicPropertiesStore().getLatestBlockHeaderTimestamp();
    long withdrawExpireBalance = 0L;
    for (Protocol.Account.UnFreezeV2 unFreezeV2: ownerCapsule.getUnfrozenV2List()) {
      if (unFreezeV2.getUnfreezeExpireTime() > now) {
        String resourceName = unFreezeV2.getType().name();
        result.put(resourceName, result.getOrDefault(resourceName, 0L) + unFreezeV2.getUnfreezeAmount());

        updateFrozenInfoAndTotalResourceWeight(ownerCapsule, unFreezeV2, repo);
      } else {
        // withdraw
        withdrawExpireBalance += unFreezeV2.getUnfreezeAmount();
      }
    }
    if (withdrawExpireBalance > 0) {
      ownerCapsule.setBalance(ownerCapsule.getBalance() + withdrawExpireBalance);
    }
    ownerCapsule.clearUnfrozenV2();

    repo.updateAccount(ownerCapsule.createDbKey(), ownerCapsule);

    result.put(VMConstant.WITHDRAW_EXPIRE_BALANCE, withdrawExpireBalance);
    return result;
  }
