### Title
Unsafe `int(uint64)` cast in MVCC manifest chunk-offset parsing allows negative offsets that bypass bounds checks, causing an out-of-bounds slice panic (DoS) - (File: internal/git/mvcc/manifest.go)

### Summary
`ParseManifest` in [1](#0-0)  parses a binary MVCC manifest whose chunk table stores 8-byte big-endian offsets. `parseChunks` converts each offset with an unchecked `int(binary.BigEndian.Uint64(...))` cast [2](#0-1) . Because Go's `int` is a signed 64-bit type on the platforms Gitaly targets, a `uint64` value with its high bit set (≥ `2^63`) reinterprets as a negative `int` after this cast — the same class of bug as the reported Solidity issue, where a value is unsafely narrowed/reinterpreted into a smaller/signed type without a `SafeCast`-style range check before the cast.

### Finding Description
The chunk-table validation that follows the cast only rejects offsets that are numerically *greater* than the data length:

```go
chunkOffsetInFile := int(binary.BigEndian.Uint64(data[chunkOffset+4 : chunkOffset+tocChunkSize]))
...
nextChunkOffsetInFile := int(binary.BigEndian.Uint64(data[nextChunkStart+4 : nextChunkStart+tocChunkSize]))

if chunkOffsetInFile > dataEnd || nextChunkOffsetInFile > dataEnd || nextChunkOffsetInFile < chunkOffsetInFile {
    return nil, fmt.Errorf("chunk %d has out-of-bounds offsets [%d, %d)", i, chunkOffsetInFile, nextChunkOffsetInFile)
}
``` [3](#0-2) 

A negative `chunkOffsetInFile` (produced by a raw `uint64` value ≥ `2^63`) is never `> dataEnd`, so this check silently passes it through. The resulting `manifestChunk.offset` is negative and is later used directly to slice the manifest byte buffer in `ParseManifest`, e.g.:

```go
start := pathChunk.offset + i*pw
record := data[start : start+pw]
``` [4](#0-3) 

or when reading the OBJS chunk:
```go
m.objStart = int(binary.BigEndian.Uint32(data[objsChunk.offset : objsChunk.offset+4]))
``` [5](#0-4) 

Slicing a Go `[]byte` with a negative index is not a memory-safety hole (Go bounds-checks slices), but it triggers a runtime panic (`slice bounds out of range`) instead of the graceful error path the rest of the function otherwise uses everywhere else.

The 32-byte SHA-256 trailer check earlier in `ParseManifest` only proves the bytes are self-consistent; it does not constrain any of the encoded offset/size fields to sane, non-negative ranges relative to Go's `int` semantics [6](#0-5) .

### Impact Explanation
`ParseManifest` is invoked on every RPC that touches a repository on the MVCC reference backend, via `LocalCache.prepare` → `prepareManifestFile`, which reads the manifest either from local disk or from `RemoteStorage.ReadManifest` (S3-backed) and feeds the bytes straight into `ParseManifest` [7](#0-6) . Manifests are the mechanism describing the on-disk/S3 location of every pack and reftable artifact for a repository snapshot, i.e. exactly the "storage-path resolution" surface for MVCC repositories. Any component able to place a self-consistent (checksum-matching) but structurally malicious manifest blob under the content-addressed `manifests/<sha>` path — or reference such a manifest hash through the per-request `Pin` mechanism used to propagate a manifest hash from an originating RPC into subsequent hook-triggered Gitaly calls, per [8](#0-7)  — can force a Gitaly RPC handler to panic while resolving artifact paths for that repository, crashing the goroutine (and, absent panic recovery around the whole call chain, potentially the process), denying service on that repository/node.

### Likelihood Explanation
Triggering the negative-offset path requires the attacker to control (or influence the generation of) a full manifest byte stream whose SHA-256 trailer matches — a normal user's push/write RPC does route through `SerializeManifest`/`Session.Publish`, which is where manifest bytes for a repository are produced and durably stored, before later being re-read and parsed by every subsequent RPC via `prepare`/`prepareManifestFile`. `SerializeManifest` itself won't emit negative offsets under any reasonable input, so exploitation would rely on a different, unvalidated manifest-writing path (or a corrupted/attacker-supplied blob placed under a valid content-addressed key) reaching `ParseManifest`. This narrows practical exploitation relative to the impact, but the missing check is a genuine, unguarded defect on a code path that is unconditionally exercised on every MVCC-backend RPC.

### Recommendation
- Validate that both `chunkOffsetInFile` and `nextChunkOffsetInFile` are non-negative immediately after conversion, before using them in the `> dataEnd` / `< chunkOffsetInFile` comparisons (e.g. `if chunkOffsetInFile < 0 || nextChunkOffsetInFile < 0 { return error }`).
- Prefer an explicit, checked conversion (mirroring the report's fix of adopting `SafeCast`): reject any raw `uint64` offset that exceeds `math.MaxInt64` (or, more simply, that exceeds `len(data)`) before casting to `int`, e.g. using `bits.LeadingZeros64` or a manual `if raw > uint64(math.MaxInt) { return error }` guard.
- Apply the same guard to the `uint32`-derived `objStart`/`objCount`/REFS index conversions for defense in depth, even though `int` is 64-bit wide enough there to avoid sign flips.

### Proof of Concept
1. Construct a manifest body with a valid header/magic/version and a single-chunk TOC.
2. Set the chunk's offset field (the 8-byte big-endian value at `data[chunkOffset+4 : chunkOffset+12]`) to `0xFFFFFFFFFFFFFFFF` (or any value ≥ `2^63`).
3. Recompute and append the trailing SHA-256 checksum over the crafted bytes (as `resign` does in the test helpers, e.g. [9](#0-8) ), so the checksum validation in `ParseManifest` passes.
4. Call `mvcc.ParseManifest(craftedBytes)`. The `int(uint64(...))` conversion yields a negative `chunkOffsetInFile`, which passes the `> dataEnd` bounds check, and the subsequent `data[start:start+pw]` slice operation panics with "slice bounds out of range" instead of returning the expected parse error.

// ParseManifest parses an MVCC manifest body in binary chunk-based format
// (starting with "MVCC" magic).
func ParseManifest(data []byte) (*Manifest, error) {
	if len(data) == 0 {
		return &Manifest{}, fmt.Errorf("empty manifest")
	}

	if len(data) < headerSize+trailerSize {
		return &Manifest{}, fmt.Errorf("binary manifest too short (%d bytes)", len(data))
	}

	// Validate trailing SHA-256 checksum.
	payloadEnd := len(data) - trailerSize
	want := sha256.Sum256(data[:payloadEnd])
	if !bytes.Equal(want[:], data[payloadEnd:]) {
		return nil, fmt.Errorf("manifest checksum mismatch")
	}

	header, err := parseManifestHeader(data)
	if err != nil {
		return nil, err
	}

	chunks, err := parseChunks(data, header.numChunks)
	if err != nil {
		return nil, err
	}

// prepareManifestFile will read the manifest file defined by `hash` and return its parsed form.
// If the manifest file already exist on the local filesystem, the file is read from the filesystem.
// Else, the manifest file is fetched from ObjectStorage and then created on the local filesystem for future use.
func (m *LocalCache) prepareManifestFile(ctx context.Context, hash string) (manifest *Manifest, err error) {
	// Construct the manifest path
	manifestFilePath := filepath.Join(m.storagePath, m.repositoryID, mvccCacheDir, "manifests", hash)

	// Verify if it already exists on the local filesystem or not
	existLocally, err := fileExist(manifestFilePath)
	if err != nil {
		return nil, fmt.Errorf("check if file exists: %w", err)
	}

	if !existLocally {
		// If it does not exist, read content from ObjectStorage
		manifestReader, err := m.rs.ReadManifest(ctx, m.repositoryID, hash)
		if err != nil {
			return nil, fmt.Errorf("read manifest file: %w", err)
		}

		defer func() {
			closeErr := manifestReader.Close()
			err = errors.Join(err, closeErr)
		}()

		// Create the manifest file on the local file system atomically. This is a protection against
		// potential concurrent requests trying to create the same manifest file.
		if err = createFileAtomic(ctx, manifestFilePath, manifestReader); err != nil {
			return nil, fmt.Errorf("write manifest: %w", err)
		}
	}

	// Now that it exist on disk, let's open the file.
	manifestFile, err := os.Open(manifestFilePath)
	if err != nil {
		return nil, fmt.Errorf("opening manifest %s: %w", manifestFilePath, err)
	}

	// Read the content in memory. These files should not be that large.
	// The Manifest parsing logic needs the whole file at once to parse it.
	manifestContent := bytes.Buffer{}
	_, err = manifestContent.ReadFrom(manifestFile)
	if err != nil {
		return nil, fmt.Errorf("reading manifest: %w", err)
	}

	// Return the parsed manifest
	return ParseManifest(manifestContent.Bytes())
}

// resign recomputes the trailing SHA-256 checksum in place after a body has
// been mutated, so tests can target validation past the checksum gate.
func resign(body []byte) {
	payloadEnd := len(body) - trailerSize
	trailer := sha256.Sum256(body[:payloadEnd])
	copy(body[payloadEnd:], trailer[:])
