### Title
Missing private-IP check when connecting to peer-advertised `data_url` in `NeighborRPC::send_request` allows authenticated-peer SSRF via DNS - (File: `stackslib/src/net/neighbors/rpc.rs`)

### Summary
`NeighborRPC::send_request` (used by the Nakamoto tenure/block downloader to fetch data from peers over HTTP) connects to whatever address the remote peer's advertised `data_url` resolves to, without ever checking whether that resolved address is private/loopback. Every other place in the codebase that resolves a peer-supplied hostname to an IP explicitly re-checks `is_in_private_range()` immediately before using it to connect (`can_register_peer` in `stackslib/src/net/p2p.rs:1918`, and the mempool sync path in `stackslib/src/net/mempool/mod.rs:488-498`). This RPC path skips that check entirely.

### Finding Description
A remote peer's HTTP "data URL" is self-reported during the P2P handshake and can contain a DNS hostname (`stacks_common::types::net::PeerHost`/`UrlString`). The conversation resolves this hostname once via the async `DNSClient` in `ConversationP2P::try_resolve_data_url_host` (`stackslib/src/net/chat.rs:2800-2866`) and caches the result in `convo.data_ip`. Because it is a plain hostname, the peer fully controls the authoritative DNS answer and can return any IP address at resolution time, including `127.0.0.1` or an RFC1918/internal address, and can rotate the answer at will (TTL=0) — the classic DNS-rebinding precondition described in the reported advisory.

That cached `data_ip` is then handed to `NeighborRPC::send_request`:

```
stackslib/src/net/neighbors/rpc.rs:195-241

    ...
    let data_addr = if let Some(ip) = convo.data_ip {
        ip
    } else if convo.waiting_for_dns() { ... } else { ... };
    ...
    http.connect_http(network_state, network, data_url, data_addr, None)
    ...

```

There is no check here of the form `!connection_opts.private_neighbors && PeerAddress::from_socketaddr(&data_addr).is_in_private_range()` that exists in every analogous path:
- `stackslib/src/net/p2p.rs:1917-1924` (`can_register_peer`) blocks P2P connections to private ranges unless `private_neighbors` is set.
- `stackslib/src/net/mempool/mod.rs:485-498` (`do_mempool_sync`/`SendQuery` state) explicitly re-checks `is_in_private_range()` on the resolved `addr` right before issuing the HTTP mempool-sync request, precisely because the address came from an untrusted, DNS-resolved `data_url`.

`NeighborRPC::send_request` is the transport used by the Nakamoto tenure/block downloader (`stackslib/src/net/download/nakamoto/tenure_downloader.rs`, `tenure_downloader_unconfirmed.rs`, `tenure_downloader_set.rs`, `download_state_machine.rs`) to fetch tenure/block data over HTTP from neighbors the node has already authenticated at the P2P layer. Because `data_ip` is resolved independently of, and later than, the P2P-layer address check, and because that resolution is never re-validated against the private-range denylist, a fully remote, unprivileged (any node can become a "neighbor" simply by completing a handshake) attacker can steer this HTTP fetch to an internal-only address.

### Impact Explanation
This breaks the equality the rest of the codebase enforces ("no HTTP/P2P traffic is intentionally sent to private-range addresses unless explicitly configured"): the DNS-resolved connect-time address is trusted without being checked against the same denylist. An authenticated but otherwise unprivileged peer can point its `data_url` at a hostname it controls in DNS, having it resolve to `127.0.0.1:<port>` or another internal address reachable only from the victim node (e.g., another locally-bound RPC/API service on the operator's host or LAN). The node will then issue Nakamoto tenure/block-fetch HTTP requests to that address and process whatever comes back as if it were peer data, and connection/response behavior is observable by the attacker (timing/response differences), giving a limited but real internal network reconnaissance/request-forgery primitive gated only by an existing but unauthenticated/low-trust P2P handshake — no admin role or secret key required.

### Likelihood Explanation
Likelihood is bounded by having to become a "neighbor" of the target (trivial — merely complete a P2P handshake, no allow-listing needed by default) and controlling DNS for a hostname advertised as the node's `data_url`. Both preconditions are attacker-controlled and require no special privileges, matching the "no admin rights, no non-default configuration" precondition pattern from the advisory. The classic DNS-rebinding race (TTL 0, alternate answers) is not even strictly required here since there is no first "safe" check at all to race against — the resolved address is used unconditionally, making exploitation simpler than the reference report's TOCTOU.

### Recommendation
In `stackslib/src/net/neighbors/rpc.rs::send_request`, mirror the check already present in `stackslib/src/net/p2p.rs::can_register_peer` and `stackslib/src/net/mempool/mod.rs`: before calling `http.connect_http(...)`, verify `network.get_connection_opts().private_neighbors || !PeerAddress::from_socketaddr(&data_addr).is_in_private_range()`, and reject/mark-broken the neighbor otherwise. Ideally, centralize this check inside `HttpPeer::connect_http` (or `PeerNetwork::connect_or_send_http_request`) so every caller that connects to a peer-resolved `data_ip` (including future callers) gets the guard automatically rather than relying on each call site to remember it.

### Proof of Concept
1. Stand up a malicious peer node whose Handshake advertises `data_url = "http://attacker-controlled.example.com:20443"`.
2. Configure the authoritative DNS for `attacker-controlled.example.com` to answer with `127.0.0.1` (or an internal RFC1918 address reachable from the victim, e.g. an internal admin API bound to the victim's loopback/LAN interface).
3. Get the victim node to treat the malicious node as an authenticated neighbor (default handshake, no special config) and to select it as a source for a Nakamoto tenure/block download (`tenure_downloader*.rs` via `NeighborRPC`).
4. Observe that `ConversationP2P::try_resolve_data_url_host` (`chat.rs`) resolves and caches `data_ip = 127.0.0.1:20443` (or the internal address), and `NeighborRPC::send_request` (`rpc.rs:195-241`) calls `connect_http` with that address with no private-range check — unlike the equivalent mempool-sync path, which would have rejected it at `stackslib/src/net/mempool/mod.rs:488-498`.     fn try_resolve_data_url_host(
        &mut self,
        dns_client_opt: &mut Option<&mut DNSClient>,
        dns_timeout: u128,
    ) {
        if self.data_ip.is_some() {
            return;
        }
        if self.data_url.is_empty() {
            return;
        }
        if let Some(ipaddr) = Self::try_decode_data_url_ipaddr(&self.data_url) {
            // don't need to resolve!
            debug!(
                "{}: Resolved data URL {} to {}",
                &self, &self.data_url, &ipaddr
            );
            self.data_ip = Some(ipaddr);
            return;
        }

        let Some(dns_client) = dns_client_opt else {
            return;
        };
        if get_epoch_time_ms() < self.dns_deadline {
            return;
        }
        if let Some(dns_request) = self.dns_request.take() {
            // perhaps resolution completed?
            match dns_client.poll_lookup(&dns_request.host, dns_request.port) {
                Ok(query_result_opt) => {
                    // just take one of the addresses, if there are any
                    self.data_ip =
                        query_result_opt.and_then(|query_result| match query_result.result {
                            Ok(mut ips) => ips.pop(),
                            Err(e) => {
                                warn!(
                                    "{}: Failed to resolve data URL {}: {:?}",
                                    self, &self.data_url, &e
                                );

                                // don't try again
                                self.dns_deadline = u128::MAX;
                                None
                            }
                        });
                    if let Some(ip) = self.data_ip.as_ref() {
                        debug!("{}: Resolved data URL {} to {}", &self, &self.data_url, &ip);
                    } else {
                        info!(
                            "{}: Failed to resolve URL {}: no IP addresses found",
                            &self, &self.data_url
                        );
                    }
                    // don't try again
                    self.dns_deadline = u128::MAX;
                }
                Err(e) => {
                    warn!("DNS lookup failed on {}: {:?}", &self.data_url, &e);

                    // don't try again
                    self.dns_deadline = u128::MAX;
                }
            }
        }
