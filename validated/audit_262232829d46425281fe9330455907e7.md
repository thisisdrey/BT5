## Analog Found: Unstaked QUIC Connection-Table Exhaustion via IP-Sybil Bypass of Per-IP Rate Limiting

### Title
DoS of unstaked TPU/TPU-forward QUIC clients via connection-table filling that only costs distinct source IPs, not stake - ([File: streamer/src/nonblocking/swqos.rs])

### Summary
The `delegation_service` report describes a bounded pool (`MAX_NUMBER_OF_DELEGATIONS`) that an unprivileged attacker can fill with fake entries, denying service to legitimate users, and made effectively free by bypassing a minimum stake/amount requirement. Agave's QUIC streamer has a structurally identical pattern: the `unstaked_connection_table` is bounded by `max_unstaked_connections`, admission to it requires *no stake at all* by design, and the only friction against Sybil-filling it is a per-source-IP token-bucket rate limiter that is trivially bypassed by an attacker who controls many IPv4/IPv6 addresses.

### Finding Description
`SwQos::try_add_connection` routes any `ConnectionPeerType::Unstaked` connection into `unstaked_connection_table`, bounded by `max_unstaked_connections` (`DEFAULT_MAX_UNSTAKED_CONNECTIONS = 2000`) [1](#0-0) . When the table is at/above capacity, `prune_unstaked_connection_table` evicts the **oldest** connections down to 90% capacity — it has no way to distinguish a real client from an attacker-controlled connection, because unstaked peers carry no stake signal [2](#0-1) .

The only gate preventing a single attacker from opening unlimited unstaked connections is `ConnectionRateLimiter`, a per-`IpAddr` token bucket (`max_connections_per_ipaddr_per_min`, default 8/min with a 10x burst allowance) [3](#0-2) [4](#0-3) . This limiter is keyed strictly on `IpAddr`, checked once pre-handshake (`is_allowed`) and once post-handshake (`register_connection`) [5](#0-4) [6](#0-5) .

Because the gate is per-address rather than per-stake or per-identity-with-cost, an attacker who owns (or spoofs, for IPv6) a block of addresses can generate as many distinct-IP QUIC connections as needed to keep the unstaked table saturated with churn, at effectively zero cost — exactly analogous to how the `delegation_service` attacker used the min-delegation-amount bypass to make filling `MAX_NUMBER_OF_DELEGATIONS` free. Real unstaked clients competing for the same 2000 slots get bumped by `prune_oldest`/rejected via `connection_add_failed_unstaked_node`, denying them the ability to submit transactions over the unstaked TPU/TPU-forward path.

### Impact Explanation
Legitimate low-stake/unstaked clients (which is the primary intended user population for the unstaked pool) can be persistently starved from submitting transactions through the QUIC streamer, since the table is continuously refreshed with attacker connections from diverse IPs. This is a QoS-evasion / DoS impact matching the accepted impact categories (QoS evasion against an unprivileged path). It does not affect staked/weighted admission (`prune_random` uses `threshold_stake`, unforgeable), so the blast radius is scoped to the unstaked connection pool, but that pool is explicitly meant to allow permissionless client access.

### Likelihood Explanation
The attack requires only network access and control of many source IP addresses — no stake, no fees, and no privileged role. IPv6 address abundance (a single attacker typically controls a /64 or larger allocation) makes the per-IP rate limiter economically negligible to bypass at the volumes needed to keep 2000 slots saturated with the default `max_connections_per_ipaddr_per_min = 8` and burst headroom. This is realistically exploitable by any unprivileged network participant.

### Recommendation
Strengthen admission/eviction for the unstaked table beyond per-IP token-bucket rate limiting, e.g.:
- Bind the rate limiter to a coarser network prefix (e.g., /56 or /48 IPv6 subnet, and consider ASN/subnet-based limiting) rather than a single address, to raise the cost of Sybil IP generation.
- Consider a lightweight per-connection cost (e.g., proof-of-work/challenge or minimum client-visible cost) before granting a slot in the unstaked table, analogous to imposing a `min_delegation_amount` in the referenced report, so that filling the pool is not free even under IP diversity.
- Track and rate-limit the total churn rate of the unstaked table itself (e.g., cap number of prune+admit cycles per unit time) so a fast-churning Sybil attacker cannot keep evicting the same seats.

### Proof of Concept
1. Attacker acquires or spoofs many distinct source IPs (trivial with an IPv6 allocation).
2. From each IP, open QUIC connections at up to `max_connections_per_ipaddr_per_min` (default 8/min, burst up to 80) to the validator's unstaked-facing QUIC endpoint (TPU/TPU-forward when `ConnectionPeerType::Unstaked`), see admission path in `SwQos::try_add_connection` [1](#0-0) .
3. Repeat across enough distinct IPs to exceed `max_unstaked_connections` (2000 by default), causing `prune_unstaked_connection_table` to continuously evict oldest entries and admit new attacker connections [2](#0-1) .
4. A genuine unstaked client attempting to connect either fails admission (`connection_add_failed_unstaked_node`) or gets evicted shortly after joining, unable to reliably submit transactions through the unstaked path.

        &self,
        unstaked_connection_table: &mut ConnectionTable<ConnectionStreamCounter>,
        max_unstaked_connections: usize,
        stats: Arc<StreamerStats>,
    ) {
        if unstaked_connection_table.total_size >= max_unstaked_connections {
            // Prune the connection table down to 90% capacity
            const PRUNE_TABLE_RATIO: f64 = 0.90;
            let max_connections = (PRUNE_TABLE_RATIO * (max_unstaked_connections as f64)) as usize;
            let num_pruned = unstaked_connection_table.prune_oldest(max_connections);
            stats
                .num_evictions_unstaked
                .fetch_add(num_pruned, Ordering::Relaxed);
        }
    }
