### Title
Closing a lending account balance discards `emissions_outstanding` without claiming it - ([File: programs/marginfi/src/state/marginfi_account.rs])

### Summary
The external report describes a class of bug where resetting/closing a position's state (locked balance = 0, but not fully finalized) causes previously-accrued rewards to become permanently unclaimable because the closing path does not settle or protect the pending reward balance before wiping it. Marginfi's lending-account balance-closing path has the same defect: `Balance::close()` unconditionally zeroes `emissions_outstanding` when a balance is deactivated, and neither `close_balance()` nor `withdraw_all()`/`repay_all()` verify that `emissions_outstanding` is zero (or settle it) before calling `close()`.

### Finding Description
`Balance::close()` resets the balance struct to `Balance::empty_deactivated()`, which hardcodes `emissions_outstanding: WrappedI80F48::from(I80F48::ZERO)`: [1](#0-0) 

This `close()` is called from `BankAccountWrapper::close_balance()`, `withdraw_all()`, and `repay_all()` in `marginfi_account.rs`. None of these functions check the balance's `emissions_outstanding` field before wiping it: [2](#0-1) [3](#0-2) 

Notably, the program defines a dedicated error variant seemingly intended to prevent exactly this scenario: [4](#0-3) 

However, `CannotCloseOutstandingEmissions` is never referenced by any `check!()` call in the closing instructions I could locate (`lending_account_close_balance`, `withdraw_all`, `repay_all`, `purge_delev_balance`), i.e. the guard the error was designed for appears to be missing from the actual close paths: [5](#0-4) 

This mirrors the reported bug class: user-triggered state transitions (`withdraw_all`, `close_balance`, `repay_all` — analogous to `withdraw()`/`merge()`/`split()` for veKITTEN) leave the position "closed" from the perspective of the core accounting, but a component of value that was legitimately owed to the user (pending emissions, analogous to `RebaseReward`) is discarded rather than paid out or preserved for later claim.

### Impact Explanation
Any user who has accrued `emissions_outstanding` on a balance and then calls `lending_account_close_balance` (or fully withdraws/repays such that the balance auto-closes via `withdraw_all`/`repay_all`) permanently loses that emissions value — it is neither transferred to the user nor tracked anywhere else; it simply vanishes when the struct is overwritten with `empty_deactivated()`. This is a permanent, unrecoverable loss of legitimately earned rewards for the account owner, triggered entirely by their own unprivileged actions, with no admin or attacker interaction required — which is a "permanent lock/freeze"/loss-of-funds class impact.

### Likelihood Explanation
Likelihood is high for accidental triggering: any normal user who withdraws/repays their full position (a very common action) while unclaimed emissions are outstanding will trigger this loss without any warning, since the intended guard (`CannotCloseOutstandingEmissions`) does not appear to be wired into the actual closing code paths.

### Recommendation
Before calling `balance.close()` in `close_balance()`, `withdraw_all()`, and `repay_all()`, check that `balance.emissions_outstanding` is zero (or below dust threshold) and return `MarginfiError::CannotCloseOutstandingEmissions` if not — forcing the user (or an accompanying instruction in the same transaction) to settle/claim emissions first, consistent with what the existing error variant implies was originally intended.

### Proof of Concept
1. User deposits into a bank with an active emissions campaign; over time `balance.emissions_outstanding` accrues to a nonzero value (see `type-crate/src/types/user_account.rs:300-301` field definition, and `programs/marginfi/tests/misc/regression.rs:104-107` for real observed nonzero values).
2. User calls `lending_account_withdraw` with `withdraw_all = true` (or repays all liabilities), which internally calls `BankAccountWrapper::withdraw_all()`/`repay_all()` → `balance.close()`. [6](#0-5) 
3. `balance.close()` overwrites the balance with `Balance::empty_deactivated()`, zeroing `emissions_outstanding` without transferring or preserving that value anywhere. [1](#0-0) 
4. The user's previously accrued, legitimately-earned emissions are now permanently gone; no instruction exists to recover them from a closed/deactivated balance slot.

pub fn lending_account_close_balance(ctx: Context<LendingAccountCloseBalance>) -> MarginfiResult {
    let LendingAccountCloseBalance {
        marginfi_account,
        bank: bank_loader,
        group: marginfi_group_loader,
        ..
    } = ctx.accounts;

    let mut marginfi_account = marginfi_account.load_mut()?;
    let mut bank = bank_loader.load_mut()?;

    check!(
        !marginfi_account.get_flag(ACCOUNT_DISABLED),
        MarginfiError::AccountDisabled
    );

    let group = &*marginfi_group_loader.load()?;
    bank.accrue_interest(
        Clock::get()?.unix_timestamp,
        group,
        #[cfg(not(feature = "client"))]
        bank_loader.key(),
    )?;

    bank.update_bank_cache(group)?;

    let in_receivership = marginfi_account.get_flag(ACCOUNT_IN_RECEIVERSHIP);
    let lending_account: &mut marginfi_type_crate::types::LendingAccount =
        &mut marginfi_account.lending_account;
    let mut bank_account =
        BankAccountWrapper::find(&bank_loader.key(), &mut bank, lending_account)?;

    bank_account.close_balance(in_receivership)?;
    lending_account.sort_balances();
    marginfi_account.sync_indexer_flags();
    marginfi_account.last_update = Clock::get()?.unix_timestamp as u64;

    Ok(())
}
