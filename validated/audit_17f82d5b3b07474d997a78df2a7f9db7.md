## Title
Unauthenticated `RecvError` message can unlimited-times tear down relayed tunnels because the anti-spoofing check is bypassed when `HostInfo.remote` is never set — ([File: outside.go])

## Summary
The external report's bug class is "an unrestricted, un-gated write path lets an entity mutate trust-relevant state (an address mapping) an unlimited number of times without any authorization check." The closest reachable analog in nebula is `Interface.handleRecvError` in `outside.go`, which processes the fully unauthenticated `header.RecvError` UDP message type and tears down (deletes) a `HostInfo` based on nothing but a guessed/observed 32-bit index, gated only by a best-effort address comparison that is silently skipped whenever the target `HostInfo.remote` was never set — which is always true for relay-only tunnels.

## Finding Description
`RecvError` is one of only two message types dispatched in `readOutsidePackets` before any decryption or certificate check is performed: [1](#0-0) 

`handleRecvError` is the sole gate against spoofing: [2](#0-1) 

The only defense is:
```go
hr := hostinfo.GetRemote()
if hr.IsValid() && hr != addr {
    // reject as spoofed
    return
}
f.closeTunnel(hostinfo)
```
This defense depends entirely on `hostinfo.remote` having been previously populated. `SetRemote` (called from `handleHostRoaming` and from the handshake path) is explicitly skipped for relayed traffic: [3](#0-2) [4](#0-3) 

Both call sites guard the `SetRemote`/roaming update with `if !via.IsRelayed`. For a tunnel that only ever communicates through a relay (no direct UDP path — a normal, supported nebula topology), `hostinfo.remote` (`GetRemote()`) never becomes valid, so `hr.IsValid()` is permanently `false` and the address check in `handleRecvError` is unconditionally bypassed. `RemoteIndex` (the index embedded in the header) is a 32-bit value transmitted in cleartext on every packet for that tunnel, so anyone who can observe or capture a single packet (an on-path attacker, a curious relay operator, or a passive network observer) can forge unlimited `RecvError` packets from any spoofed source address and repeatedly force `closeTunnel` + `DeleteHostInfo` on that hostinfo — with zero certificate, zero handshake, and zero rate limiting.

This mirrors the report's root cause pattern precisely: a state-mutating operation intended to be restricted (only the genuine remote peer should be able to signal "I lost my session, tear it down") has no effective enforcement and can be invoked an unlimited number of times by an unauthorized party.

## Impact Explanation
An attacker with no CA-signed nebula certificate can persistently and repeatedly destroy relay-based tunnels between arbitrary nebula peers, causing continuous denial of service (the tunnel must be re-handshaked every time), and because `handleRecvError` also purges the pending handshake manager entry, it accelerates re-handshake churn, amplifying the effect. This is remote state poisoning of `HostMap` reachable purely at the UDP/header-parsing layer, before any certificate or handshake authentication takes place — squarely in scope as a firewall/handshake/hostmap trust-boundary bypass.

## Likelihood Explanation
Exploitability requires only: (1) knowledge of a valid `RemoteIndex` for a relay-only tunnel (observable in cleartext from any packet of that tunnel, e.g. by the relay node itself, or any passive/on-path observer), and (2) the ability to send arbitrary UDP packets to the target's listen port. No cryptographic material, certificate, or successful handshake is required. This is a realistic and repeatable attack for any deployment that uses relays (a first-class, documented nebula feature), making likelihood moderate-to-high in relay-heavy deployments.

## Recommendation
Do not rely solely on `hr.IsValid()` before applying the spoof check in `handleRecvError`. For relayed hostinfos (no direct known remote), either: (1) require `via.IsRelayed`/relay-index correlation before honoring a `RecvError` for that hostinfo, (2) drop `RecvError` entirely for hostinfos that have no verified direct remote, or (3) require some proof of possession (e.g., only accept `RecvError` from the same underlying relay session/relay index that is actively forwarding for that hostinfo) rather than an unauthenticated raw index match.

## Proof of Concept
1. Establish (or observe) a relay-only tunnel between peer A and peer B through relay R (A and B have no direct UDP path, satisfying nebula's relay feature).
2. Capture/observe any packet of that tunnel to learn the `RemoteIndex` embedded in the plaintext `header.H` (present in every nebula packet, including `RecvError`, `Message`, etc., per `header/header.go`).
3. From an attacker-controlled UDP source (spoofed or real, off the CA trust boundary — no certificate needed), craft a `header.H{Type: header.RecvError, RemoteIndex: <observed index>}` and send it to A's listen port.
4. Because `A`'s `HostInfo.remote` for this relay-only session was never set (`SetRemote` is skipped for `via.IsRelayed`), `hr.IsValid()` is `false` in `handleRecvError`, so the spoof check is bypassed and `f.closeTunnel(hostinfo)` executes, tearing down the tunnel.
5. Repeat step 3 indefinitely — nothing in the code path rate-limits or re-authenticates this action, matching the "unlimited unauthorized overwrite" bug class from the report, here manifesting as unlimited unauthorized tunnel/state destruction.

```go
func (f *Interface) handleHostRoaming(hostinfo *HostInfo, via ViaSender) {
	curRemote := hostinfo.GetRemote()
	if !via.IsRelayed && curRemote != via.UdpAddr {
		if !f.lightHouse.GetRemoteAllowList().AllowAll(hostinfo.vpnAddrs, via.UdpAddr.Addr()) {
			if f.l.Enabled(context.Background(), slog.LevelDebug) {
				hostinfo.logger(f.l).Debug("lighthouse.remote_allow_list denied roaming", "newAddr", via.UdpAddr)
			}
			return
		}

		if !hostinfo.lastRoam.IsZero() && via.UdpAddr == hostinfo.lastRoamRemote && time.Since(hostinfo.lastRoam) < RoamingSuppressSeconds*time.Second {
			if f.l.Enabled(context.Background(), slog.LevelDebug) {
				hostinfo.logger(f.l).Debug("Suppressing roam back to previous remote",
					"suppressSeconds", RoamingSuppressSeconds,
					"udpAddr", curRemote,
					"newAddr", via.UdpAddr,
				)
			}
			return
		}

		hostinfo.logger(f.l).Info("Host roamed to new udp ip/port.",
			"udpAddr", curRemote,
			"newAddr", via.UdpAddr,
		)
		hostinfo.lastRoam = time.Now()
		hostinfo.lastRoamRemote = curRemote
		hostinfo.SetRemote(via.UdpAddr)
	}
```

```go
func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
```
