### Title
LPs can front-run bad-debt socialization by redeeming vault shares before `liquidate()` writes down `lindex` - (File: `mainnet/contracts/vault/v0-vault-stx.clar`, `mainnet/contracts/market/v0-4-market.clar`)

### Summary
Zest's vaults (`v0-vault-stx.clar`, `v0-vault-sbtc.clar`, `v0-vault-ststx.clar`, `v0-vault-usdc.clar`, `v0-vault-usdh.clar`, `v0-vault-ststxbtc.clar`) socialize bad debt by marking down the `lindex` liquidity index inside `socialize-debt`, which is only invoked as an internal step of `liquidate()` in `v0-4-market.clar` when a borrower's position has no collateral left. Any depositor who sees an under-collateralized `liquidate()` transaction sitting in the mempool can submit a `redeem()` with a higher fee to exit at the pre-write-down NAV before the socialization lands, shifting their share of the loss onto remaining LPs — the same front-running class as the Hubble `InsuranceFund.withdraw()` vs `seizeBadDebt()` race.

### Finding Description
`socialize-debt` reduces `lindex` proportionally to the loss and is guarded only by `check-caller-auth` (restricted to the market contract), not by any time delay: [1](#0-0) 

It is called from `socialize-debt-asset` only when `liquidate()` determines the borrower has `no-collateral-left`, all inside the single `liquidate()` transaction: [2](#0-1) [3](#0-2) 

Meanwhile `redeem()` on every vault is a completely permissionless, immediate withdrawal priced from the *current* `assets`/`total-supply` state via `convert-to-assets-preview`, with no cooldown, request/claim step, or check for pending bad-debt events: [4](#0-3) 

Because Stacks transactions are ordered by fee within a block (and the sequence of which tx executes first is influenced by the fee/nonce ordering a miner chooses), an LP who observes a pending `liquidate()` call that will trigger `bad-debt-socialized: true` can submit `redeem()` for their full share balance with a higher fee. If it lands first, their shares are burned and paid out using the pre-write-down `assets`/`total-supply` ratio, and only the LPs who remain in the vault after that redemption absorb the `lindex` markdown from `socialize-debt`. This is functionally identical to the Hubble `InsuranceFund` root cause: a public, immediately-effective withdrawal path race against a public, immediately-effective loss-realization path, both keyed off the same shared pool.

### Impact Explanation
This lands on the "temporary freezing of funds" / value-shifting impact for the vault's remaining LPs — the socialized loss that should be spread pro-rata across all liquidity providers at the time of the bad debt is instead disproportionately (or entirely) absorbed by whoever fails to exit before the `liquidate()` transaction executes, while the front-running LP extracts full NAV despite the loss being imminent and predictable. In insolvency scenarios (bad debt exceeding available buffer) this can also push the vault to a state where remaining LPs bear insolvency they did not consent to, since exiting depositors are not required to share in the write-down that was already "in flight" in the mempool.

### Likelihood Explanation
Any `liquidate()` call that fully liquidates a position (`no-collateral-left` true) is publicly visible in the mempool with `bad-debt-socialized: true` outcome deterministic from on-chain state (price, collateral factor, debt), making it straightforward for an LP (or a bot monitoring the vaults) to detect and front-run with a `redeem()` at higher fee. No special privileges are needed — only a vault share balance and the ability to pay a higher transaction fee, so likelihood is moderate-to-high whenever bad debt events occur.

### Recommendation
Decouple share pricing from redemption timing for pending bad-debt events, e.g.:
- Introduce a two-step withdrawal (request + delayed claim) similar to the original Hubble recommendation, so `redeem()` cannot be priced and settled atomically ahead of a bad-debt event already committed on-chain.
- Alternatively, have `liquidate()` reserve/lock the affected vault's redemptions (or snapshot NAV) before the collateral/debt legs execute, ensuring `socialize-debt`'s write-down is applied to the exact set of shares outstanding at position-liquidation time.
- Consider applying the loss markdown pro-rata to all shares outstanding as of the block/transaction that triggered the liquidation, rather than allowing same-block reordering to change who bears it.

### Proof of Concept
1. Borrower B holds a position in `v0-4-market.clar` that is undercollateralized and will fully liquidate with zero collateral left, guaranteeing `bad-debt-socialized: true` and a call into `vault-socialize-debt` → `socialize-debt` on e.g. `v0-vault-stx.clar`.
2. Liquidator L broadcasts `liquidate(borrower: B, ...)`.
3. LP holding shares in the same vault observes L's pending transaction, computes that `lindex` will be written down, and submits `redeem(amount: <full balance>, min-out: 0, recipient: LP)` with a higher fee than L's transaction.
   - `redeem` at [5](#0-4)  computes `inkind` via `convert-to-assets-preview` against the current (pre-loss) `assets`/`total-supply`.
4. LP's `redeem()` is included first, burning shares at full NAV and paying out before `lindex` is discounted.
5. L's `liquidate()` transaction executes next, and `socialize-debt` at [1](#0-0)  writes down `lindex` based on the now-smaller pool of remaining shares, so the LP who exited pays none of the loss while the remaining LPs' shares are devalued more than they would have been had the exiting LP still been part of the pool.

(define-public (socialize-debt (scaled-amount uint))
  (let ((scaled-principal (var-get principal-scaled))
        (borrowed (var-get total-borrowed))
        (idx (var-get index))
        (current-assets (var-get assets))
        (current-lindex (var-get lindex))
        (old-total-assets (total-assets))
        (debt-reduction (mul-div-down scaled-amount idx INDEX-PRECISION))
        (principal-reduction (if (> scaled-principal u0)
                                (mul-div-down scaled-amount borrowed scaled-principal)
                                u0))
        ;; Write down lindex proportionally to loss in total-assets
        (new-lindex (if (and (> old-total-assets u0) (> old-total-assets debt-reduction))
                       (mul-div-down current-lindex (- old-total-assets debt-reduction) old-total-assets)
                       u0)))

    (try! (check-caller-auth))
    (asserts! (> scaled-amount u0) ERR-AMOUNT-ZERO)

    (var-set lindex new-lindex)
    (var-set principal-scaled (if (> scaled-principal scaled-amount) (- scaled-principal scaled-amount) u0))
    (var-set total-borrowed (if (> borrowed principal-reduction) (- borrowed principal-reduction) u0))
    (var-set assets (if (> current-assets principal-reduction) (- current-assets principal-reduction) u0))

(define-private (socialize-debt-asset
                (debt-entry { aid: uint, scaled: uint })
                (acc { borrower: principal, success: bool }))
  ;; Early return if previous socialization failed
  (if (not (get success acc))
      acc
      (let ((borrower (get borrower acc))
            (failed-status { borrower: borrower, success: false })
            (asset-id (get aid debt-entry))
            (scaled-debt (get scaled debt-entry)))

            ;; Socialize in vault - pass scaled directly to avoid rounding
            (unwrap! (vault-socialize-debt asset-id scaled-debt) failed-status)
            ;; Refresh cache with new indexes post-write-down (lindex decreased)
            (map-set index-cache
                     { timestamp: stacks-block-time, aid: asset-id }
                     (unwrap! (vault-accrue asset-id) failed-status))
            ;; Remove from obligation
            (unwrap! (contract-call? .v0-market-vault
                                      debt-remove-scaled
                                      borrower
                                      scaled-debt
                                      asset-id) failed-status)
          acc)
        ))
