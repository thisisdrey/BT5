### Title
Stale `total_stake` / `peer_type` snapshot in `SwQosConnectionContext` causes incorrect (stale-boundary) stream-quota allocation for staked QUIC connections - (File: streamer/src/nonblocking/swqos.rs)

### Summary
`SwQos::build_connection_context` computes a connection's `peer_type` (`Staked(stake)` vs `Unstaked`) and captures `total_stake` exactly once, when the QUIC connection is first accepted. This snapshot is then reused for the entire lifetime of the connection to compute the stake-proportional stream quota (`available_load_capacity_in_throttling_duration`) and the per-RTT concurrent-stream cap (`compute_max_allowed_uni_streams_with_rtt`). Neither value is recomputed as the cluster's stake distribution changes over time, even though `StakedNodesUpdaterService` refreshes the live `StakedNodes`/`total_stake` every 5 seconds. This mirrors the LayerEdge root cause: a ranking/boundary quantity (`old_t1+old_t2` vs `new_t1+new_t2`) is computed once and never re-derived against the *current* state for already-existing entries, so already-established participants keep operating against a stale boundary instead of the up-to-date one.

### Finding Description
`SwQosConnectionContext` stores `peer_type: ConnectionPeerType` and `total_stake: u64` as fixed fields populated by `build_connection_context`: [1](#0-0) 

The classification of a connection as `Staked(stake)` vs treated as `Unstaked` depends on `stake_ratio = stake / total_stake` compared against a `min_stake_ratio` derived from `max_streams_per_ms`: [2](#0-1) 

Both the RTT-scaled concurrent-uni-stream cap and the throttling-window quota are then derived directly from this frozen `total_stake` for the life of the connection: [3](#0-2) [4](#0-3) [5](#0-4) 

Meanwhile, the authoritative stake table is refreshed independently, every `STAKE_REFRESH_CYCLE` (5s), from the root bank: [6](#0-5) 

Because `conn_context.total_stake` (and the derived `peer_type` boundary decision) is fixed at connect time, a long-lived QUIC connection's proportional share `stake / total_stake` is computed against an outdated denominator. If total cluster stake later rises (new stake enters, or stake redistributes upward), all pre-existing connections continue to compute their quota using the smaller, stale `total_stake`, giving them a disproportionately larger fraction of the fixed `max_staked_load_in_throttling_window`/stream budget than newly-connecting, correctly-computed peers — analogous to the "boundary shift not applied to already-classified entries" root cause in the LayerEdge report, but manifesting as unfair QoS allocation rather than interest. Conversely, if total stake falls, existing connections are throttled more strictly than warranted relative to freshly-computed peers, i.e., they receive strictly less quota than they are currently entitled to — the direct analog of "some users receive less" from the referenced report.

### Impact Explanation
This is a QoS-fairness/evasion issue reachable by any regular (unprivileged) TPU client establishing a long-lived QUIC connection to a validator's `SwQos`-governed streamer port. Depending on the direction of stake churn during a connection's lifetime, an existing connection is either:
- Under-throttled relative to its current, true stake share (quota computed against a stale, smaller `total_stake`), letting it consume more of the shared `max_staked_load_in_throttling_window` than newly-connecting peers with correctly-computed shares — a QoS evasion vector that can degrade throughput fairness for other staked senders, or
- Over-throttled relative to its current, true stake share (stale, larger `total_stake` denominator), depriving that validator of the stream bandwidth it is currently entitled to.

Neither case causes a node panic, deadlock, or invalid recorded block; it is a resource-fairness degradation limited to the QUIC/TPU streaming layer, bounded by the periodic connection churn (`prune_random`/`prune_oldest`, connection-table pruning) and by the 5-second stake refresh cadence, so the magnitude is limited but persists for the lifetime of long-lived connections between stake refreshes/reconnections.

### Likelihood Explanation
This requires no special privilege — any staked TPU client establishing and holding open a QUIC connection while cluster stake shifts (which happens naturally every epoch/every 5s refresh) will trigger this staleness. It does not require malicious crafting, only ordinary passage of time combined with normal stake movement, making it a "theoretically reachable, low-severity, always-present staleness" rather than an exploit requiring adversarial action to construct extreme unfairness (an attacker would need to hold a connection open across a stake shift to gain a deliberate unfair advantage, which is plausible but the gain is bounded by the existing per-connection/per-IP pruning and throttling caps).

### Recommendation
Recompute (or periodically refresh) `total_stake` and the derived `peer_type`/quota classification from the live `StakedNodes` table when computing throttling decisions per stream, rather than freezing them in `SwQosConnectionContext` at connection-accept time. At minimum, `max_streams_per_throttling_interval` and `compute_max_allowed_uni_streams_with_rtt` should read the current `staked_nodes.total_stake()` at each throttling decision point instead of the value captured once in `build_connection_context`.

### Proof of Concept
Conceptual (not exploit code, given the bounded/low-severity nature and staleness-based root cause):
1. Validator A connects via QUIC/TPU as a staked peer when cluster `total_stake = T0`; `SwQosConnectionContext{peer_type: Staked(s), total_stake: T0}` is fixed, per [2](#0-1) .
2. Over subsequent epochs, cluster `total_stake` grows to `T1 > T0` (or shrinks to `T1 < T0`) via `StakedNodesUpdaterService`, [7](#0-6) .
3. Validator A's connection remains open (not pruned) and keeps using `T0` in `available_load_capacity_in_throttling_duration(peer_type, T0)`, [4](#0-3) , and in `compute_max_allowed_uni_streams_with_rtt(rtt, peer_type, T0)`, [3](#0-2) , while a freshly-connecting Validator B with identical stake `s` computes its quota against the current `T1`, yielding a different (higher or lower) quota than Validator A for the same actual stake proportion.

Given the modest, bounded impact and reliance on ordinary time-based staleness rather than a demonstrable panic/DoS/verification bypass, confidence in this being a high-severity finding is limited; it is presented as the closest structurally-analogous, in-scope, unprivileged-reachable QoS-fairness issue to the reported LayerEdge boundary-staleness root cause.

fn compute_max_allowed_uni_streams_with_rtt(
    rtt_millis: u32,
    peer_type: ConnectionPeerType,
    total_stake: u64,
) -> u32 {
    let streams = match peer_type {
        ConnectionPeerType::Staked(peer_stake) => {
            // No checked math for f64 type. So let's explicitly check for 0 here
            if total_stake == 0 || peer_stake > total_stake {
                warn!(
                    "Invalid stake values: peer_stake: {peer_stake:?}, total_stake: \
                     {total_stake:?}"
                );

                QUIC_MIN_STAKED_CONCURRENT_STREAMS
            } else {
                let delta = (QUIC_TOTAL_STAKED_CONCURRENT_STREAMS
                    - QUIC_MIN_STAKED_CONCURRENT_STREAMS) as f64;

                (((peer_stake as f64 / total_stake as f64) * delta) as u32
                    + QUIC_MIN_STAKED_CONCURRENT_STREAMS)
                    .clamp(
                        QUIC_MIN_STAKED_CONCURRENT_STREAMS,
                        QUIC_MAX_STAKED_CONCURRENT_STREAMS,
                    )
            }
        }
        ConnectionPeerType::Unstaked => QUIC_MAX_UNSTAKED_CONCURRENT_STREAMS,
    };
    // scale amount of streams based on RTT if RTT is larger than REFERENCE_RTT_MS
    // multiply first then divide to avoid rounding errors.
    (streams.saturating_mul(rtt_millis.clamp(REFERENCE_RTT_MS, MAX_RTT_MS))) / REFERENCE_RTT_MS
}

    fn build_connection_context(&self, connection: &Connection) -> SwQosConnectionContext {
        let remote_address = connection.remote_address();
        get_connection_stake(connection, &self.staked_nodes).map_or(
            SwQosConnectionContext {
                peer_type: ConnectionPeerType::Unstaked,
                total_stake: 0,
                remote_pubkey: None,
                in_staked_table: false,
                remote_address,
                stream_counter: None,
                last_update: Arc::new(AtomicU64::new(timing::timestamp())),
            },
            |(pubkey, stake, total_stake)| {
                // The heuristic is that the stake should be large enough to have 1 stream pass through within one throttle
                // interval during which we allow max (MAX_STREAMS_PER_MS * STREAM_THROTTLING_INTERVAL_MS) streams.

                let peer_type = {
                    let max_streams_per_ms = self.staked_stream_load_ema.max_streams_per_ms();
                    let min_stake_ratio =
                        1_f64 / (max_streams_per_ms * STREAM_THROTTLING_INTERVAL_MS) as f64;
                    let stake_ratio = stake as f64 / total_stake as f64;
                    if stake_ratio < min_stake_ratio {
                        // If it is a staked connection with ultra low stake ratio, treat it as unstaked.
                        ConnectionPeerType::Unstaked
                    } else {
                        ConnectionPeerType::Staked(stake)
                    }
                };

                SwQosConnectionContext {
                    peer_type,
                    total_stake,
                    remote_pubkey: Some(pubkey),
                    in_staked_table: false,
                    remote_address,
                    last_update: Arc::new(AtomicU64::new(timing::timestamp())),
                    stream_counter: None,
                }
            },

    pub(crate) fn available_load_capacity_in_throttling_duration(
        &self,
        peer_type: ConnectionPeerType,
        total_stake: u64,
    ) -> u64 {
        match peer_type {
            ConnectionPeerType::Unstaked => self.max_unstaked_load_in_throttling_window,
            ConnectionPeerType::Staked(stake) => {
                if self.staked_throttling_enabled.load(Ordering::Relaxed) {
                    // 1 is added to `max_unstaked_load_in_throttling_window` to guarantee that staked
                    // clients get at least 1 more number of streams than unstaked connections.
                    self.max_staked_load_in_throttling_window
                        .saturating_mul(stake)
                        .checked_div(total_stake)
                        .unwrap_or(self.max_unstaked_load_in_throttling_window + 1)
                        .max(self.max_unstaked_load_in_throttling_window + 1)
                } else {
                    self.max_staked_load_in_throttling_window
                }
            }
        }
    }

const STAKE_REFRESH_CYCLE: Duration = Duration::from_secs(5);

pub struct StakedNodesUpdaterService {
    thread_hdl: JoinHandle<()>,
}

impl StakedNodesUpdaterService {
    pub fn new(
        exit: Arc<AtomicBool>,
        bank_forks: Arc<RwLock<BankForks>>,
        staked_nodes: Arc<RwLock<StakedNodes>>,
        staked_nodes_overrides: Arc<RwLock<HashMap<Pubkey, u64>>>,
    ) -> Self {
        let thread_hdl = Builder::new()
            .name("solStakedNodeUd".to_string())
            .spawn(move || {
                while !exit.load(Ordering::Relaxed) {
                    let stakes = {
                        let root_bank = bank_forks.read().unwrap().root_bank();
                        root_bank.current_epoch_staked_nodes()
                    };
                    let overrides = staked_nodes_overrides.read().unwrap().clone();
                    *staked_nodes.write().unwrap() = StakedNodes::new(stakes, overrides);
                    std::thread::sleep(STAKE_REFRESH_CYCLE);
                }
            })
            .unwrap();

        Self { thread_hdl }
    }
