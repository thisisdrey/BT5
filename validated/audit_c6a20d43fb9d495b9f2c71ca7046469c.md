### Title
Unauthenticated remote shutdown of the `stacks-signer` event receiver via `POST /shutdown` - (File: libsigner/src/events.rs)

### Summary
The `stacks-signer` binary runs an HTTP server (`SignerEventReceiver`) that the `stacks-node` posts events to. This server exposes a `/shutdown` route that terminates the signer's event-processing thread on receipt of a single unauthenticated `POST` request. Unlike the node-side `/v3/block_proposal` endpoint, which is gated by `auth_token`, this signer-side listener performs no authentication, and per the shipped reference configs it binds to `0.0.0.0`, making it reachable by any network peer that can route to the port.

### Finding Description
`SignerEventReceiver::next_event` dispatches on the request URL. For `/shutdown` it unconditionally sets the stop flag and returns `EventError::Terminated`, with no signature, token, or origin check: [1](#0-0) 

Compare this to the other data-bearing routes (`/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block`), which at least require `POST` and go through `process_event`, and ultimately whatever payload validation exists downstream — the `/shutdown` route has no such gate at all.

The default `main_loop` implementation for any `EventReceiver` breaks out entirely once `EventError::Terminated` is observed, ending the receiver thread for good: [2](#0-1) 

The reference signer configuration binds this listener to all interfaces, not just loopback: [3](#0-2) 

The project's own documentation warns that the signer socket is not designed to be exposed but does not describe any authentication mechanism protecting it: [4](#0-3) 

This mirrors the reported bug class (an unauthenticated request forcing a state-stopping action) but is stronger than a CSRF issue: there is no session/cookie context to forge here — the endpoint is simply open to any remote unauthenticated client, so a normal HTTP client (no victim browser or CSRF token bypass needed) suffices.

### Impact Explanation
A single unauthenticated `POST /shutdown` from any host that can reach the configured `endpoint` port permanently stops the `SignerEventReceiver`'s main loop. Once stopped, the signer process no longer receives `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, or `/new_block` events from its associated Stacks node, silently blinding that signer to block proposals and StackerDB pushes until the operator manually restarts it. This is a remote, unauthenticated, single-request DoS against a component that participates in block signing/consensus availability, matching the "Critical – remote crash/unauthenticated DoS from few messages" impact bucket.

### Likelihood Explanation
High. Exploitation requires only network reachability to the signer's bind address/port and a single crafted HTTP POST — no cryptographic material, node secret, or privileged role is needed. Given the shipped sample configs bind to `0.0.0.0`, any signer operator following the reference config without an additional firewall/reverse-proxy layer is exposed.

### Recommendation
Require the same authentication used elsewhere in the signer/node protocol (e.g., the shared `auth_password`/`auth_token`) before honoring `/shutdown`, or remove the network-triggerable shutdown path entirely and rely solely on the in-process `SignerStopSignaler` (which already uses a loopback connection under the hood) for local, non-network-exposed termination. At minimum, default `endpoint` bind guidance should be loopback-only, and the code should reject `/shutdown` requests not originating from `127.0.0.1`.

### Proof of Concept
Given a running `stacks-signer` with `endpoint = "0.0.0.0:30000"` (as in the shipped `mainnet-signer-conf.toml`), any remote host can terminate it with:
```
printf 'POST /shutdown HTTP/1.1\r\nHost: target:30000\r\nConnection: close\r\nContent-Length: 0\r\n\r\n' | nc target 30000
```
This matches the test harness's own use of the same technique to validate the stop-signaler path (`libsigner/src/events.rs:382-393`), confirming the request format is sufficient to trip the `stop_signal` and terminate `main_loop`. [5](#0-4)
