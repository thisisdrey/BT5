This confirms the exact code: `ProxyType::NonTransfer::filter` at [1](#0-0)  excludes `Balances`, `Assets`, `NftFractionalization`, `Nfts`, `Uniques`, `Scheduler`, `Treasury`, `Vesting::vested_transfer`, `ConvictionVoting`, `Referenda`, and `Whitelist`, but does not mention `AssetConversion` at all, meaning `RuntimeCall::AssetConversion(..)` calls fall through to `true` (permitted) under `NonTransfer`. The pallet is indeed present and configured in this runtime as confirmed by the 25 matches for `AssetConversion`/swap calls in the same file. This is a genuine, exploitable access-control gap: a `NonTransfer` proxy delegate can call `pallet_asset_conversion`'s swap extrinsics with an arbitrary `send_to` beneficiary, moving the proxied account's `Balances`/`Assets` holdings to an account of the delegate's choosing — a direct value-transfer capability that the filter's name and intent explicitly claim to deny. This matches the "public wrappers such as `proxy` must not widen origin or bypass filters" pivot in the required-impact rules, and constitutes unauthorized execution / origin escalation with real fund-loss risk.

Audit Report

## Title
Missing `AssetConversion` entry in `ProxyType::NonTransfer` filter permits value transfer by a "non-transfer" proxy - (File: `cumulus/parachains/runtimes/assets/asset-hub-westend/src/lib.rs`)

## Summary
`ProxyType::NonTransfer::filter` is intended to prevent a proxy delegate from moving the proxied account's value, implemented as a negated `matches!` over an explicit block-list of value-transferring `RuntimeCall` variants. `pallet_asset_conversion`'s swap extrinsics, which take an arbitrary `send_to: AccountId` and settle swapped tokens/native balance to that account, are absent from the block-list, so they evaluate to `true` (permitted) under `NonTransfer`.

## Finding Description
At [1](#0-0) , `ProxyType::NonTransfer => !matches!(c, RuntimeCall::Balances{..} | RuntimeCall::Assets{..} | ... | RuntimeCall::Whitelist(..))` returns `true` (allowed) for any `RuntimeCall` variant not explicitly listed. `RuntimeCall::AssetConversion(..)` is not present in this list, despite `pallet_asset_conversion` being configured in this same runtime, so its swap calls (`swap_exact_tokens_for_tokens`, `swap_tokens_for_exact_tokens`) are treated as non-transfer even though they move the caller's `Balances`/`Assets` holdings to an arbitrary `send_to` beneficiary. This block-list approach requires manual, exhaustive maintenance against every value-moving pallet, and `AssetConversion` was omitted.

## Impact Explanation
A delegate holding only a `NonTransfer` proxy over a victim account — a proxy type specifically granted under the assumption it cannot move funds — can invoke `AssetConversion::swap_exact_tokens_for_tokens` (or the exact-output variant) via `pallet_proxy::proxy`, swapping the victim's `Balances`/`Assets` and directing the output to an account the delegate controls. This is unauthorized execution via origin escalation through the public `proxy` wrapper, resulting in direct fund loss/misdirection to the wrong beneficiary from the proxied account.

## Likelihood Explanation
The only precondition is holding a `NonTransfer` proxy delegation, which is a commonly granted, ostensibly "safe" proxy type. `pallet-proxy::proxy` is a standard public extrinsic, and `pallet_asset_conversion` is deployed and reachable in this runtime, so the exploit path requires no privileged role, governance action, or infrastructure compromise — it is directly reachable by any unprivileged account with proxy delegation configured.

## Recommendation
Add `RuntimeCall::AssetConversion(..)` to the `ProxyType::NonTransfer` exclusion match in `cumulus/parachains/runtimes/assets/asset-hub-westend/src/lib.rs`, alongside `Balances`, `Assets`, `Nfts`, etc. Additionally, add a test that enumerates all `RuntimeCall` variants capable of moving value (e.g., any call accepting a `send_to`/`beneficiary`/`dest` parameter) and asserts they are excluded under `NonTransfer`, to prevent future pallet additions from silently bypassing this filter.

## Proof of Concept
1. Account `A` calls `pallet_proxy::add_proxy(delegate = B, proxy_type = ProxyType::NonTransfer, delay = 0)`.
2. `B` calls `pallet_proxy::proxy(real = A, force_proxy_type = None, call = RuntimeCall::AssetConversion(pallet_asset_conversion::Call::swap_exact_tokens_for_tokens { path: [WND, USDT], amount_in: A_FULL_BALANCE, amount_out_min: 0, send_to: B, keep_alive: false }))`.
3. `InstanceFilter::filter` evaluates `ProxyType::NonTransfer` against the call; since `RuntimeCall::AssetConversion(..)` is absent from the block-list at lines 834-849, `!matches!(...)` returns `true`, and the call dispatches with `A`'s origin.
4. `A`'s WND balance is swapped and the resulting USDT is sent to `B`, demonstrating value leaving `A`'s account under a proxy grant explicitly intended to be non-transfer.
