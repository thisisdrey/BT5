Audit Report

## Title
Reentrant `seal_instantiate` at a colliding deterministic address runs a duplicate constructor frame in `pallet-contracts` - (File: `substrate/frame/contracts/src/exec.rs`)

## Summary
`pallet-contracts`'s `Stack::push_frame` only persists a frame's `ContractInfo` into `ContractInfoOf<T>` when the top frame's `entry_point == ExportedFunction::Call`, never for `ExportedFunction::Constructor` frames. Because `ContractInfo::new` only guards against duplicates by checking `ContractInfoOf::<T>::contains_key`, an address that is still mid-construction is invisible to this guard, so a reentrant `seal_instantiate` that resolves (via the deterministic, non-nonce-based `DefaultAddressGenerator::contract_address`) to that same address can push a second `Constructor` frame for the same account while the first is still active on the call stack.

## Finding Description
`ContractInfo::new` checks only on-chain storage for a duplicate account: `<ContractInfoOf<T>>::contains_key(account)` [1](#0-0) . `push_frame` only writes the current top frame's cached `ContractInfo` into that storage map when the top frame is a `Call`, explicitly skipping this for `Constructor` frames ("We do not store on instantiate...") [2](#0-1) , and then unconditionally builds and pushes the new frame via `new_frame`/`ContractInfo::new` with no check against other `Constructor` frames already on `self.frames` [3](#0-2) . Address derivation is purely a hash of `(deploying_address, code_hash, input_data, salt)`, with no nonce component, so it is fully deterministic and repeatable across calls [4](#0-3) .

This allows the following reentrant path: a deployed contract `F` (acting as a factory, already committed to storage) is called and instantiates a new contract `G` with `(code_hash, input_data, salt)`, pushing a `Constructor` frame for `G`'s deterministic address — but `G`'s `ContractInfo` is only cached in the frame, not written to `ContractInfoOf`. If `G`'s constructor reenters `F` (a `Call` frame, permitted since `F` already exists and allows reentry), and `F` again calls `seal_instantiate` with the identical `(code_hash, input_data, salt)`, the address computation reproduces the exact same address for `G`. `ContractInfo::new`'s storage-only check passes because `G` was never persisted, and a second `Constructor` frame is pushed for the same `account_id` while the first is still active — exactly the class of bug fixed in `pallet-revive`, whose `push_frame` now explicitly scans `self.frames()` for an existing `Constructor` frame with the same `account_id` before allowing the push [5](#0-4) , and whose prdoc documents this exact root cause and fix [6](#0-5) . No equivalent guard exists in `pallet-contracts::exec::Stack::push_frame`.

## Impact Explanation
Two overlapping `Constructor` frames for one account allow duplicated/aliased storage-deposit accounting (`nested_storage`) and child-trie state for a single account, since both nested `with_transaction` commits will write/overwrite the same account's `ContractInfo`, `code_hash`, and storage-deposit bookkeeping. This breaks the invariant that "contract-held value must conserve value and settle exactly once" and that nested execution accounting must not be undercharged or duplicated, matching the accepted impact class of runtime bugs that compromise intended contract-execution behavior.

## Likelihood Explanation
The exploit path requires only unprivileged, ordinary contract deployment: an attacker deploys a factory contract `F` and a colluding contract `G` whose constructor reenters `F` to trigger a second `seal_instantiate` call with identical `(code_hash, input_data, salt)`, no governance, validator, or off-chain privilege is needed. `pallet-contracts` is actively part of this repository, and the fact that the identical vulnerability class was recently and deliberately fixed in the sibling `pallet-revive` (with an explicit frame-stack scan added to `push_frame`) confirms both the exploitability and the narrow, well-understood nature of the missing guard, which was never backported to `pallet-contracts`.

## Recommendation
Add the same guard as `pallet-revive`'s `push_frame`: before pushing a new `Constructor` frame in `pallet-contracts::exec::Stack::push_frame`, walk `self.frames()` (and `self.first_frame`) and reject the instantiate with `Error::<T>::DuplicateContract` if any existing frame already has `entry_point == ExportedFunction::Constructor` for the same `account_id`.

## Proof of Concept
1. Deploy contract `F` (factory) normally so its `ContractInfo` is committed to `ContractInfoOf`.
2. Deploy contract `G` whose constructor, when reentered via a call from `F`, will trigger `F` to instantiate a contract with the same `(code_hash, input_data, salt)` that produced `G`'s own address.
3. Call `F`, which calls `seal_instantiate(code_hash, input_data, salt)` to create `G` — this pushes a `Constructor` frame for `G`'s deterministic address without persisting `G`'s `ContractInfo`.
4. `G`'s constructor reenters `F` via `seal_call`; `F` calls `seal_instantiate` again with the identical `(code_hash, input_data, salt)`, reproducing `G`'s exact address.
5. `ContractInfo::new`'s `contains_key` check on `ContractInfoOf` passes (since `G` was never persisted), and a second `Constructor` frame is pushed for the same `account_id`, producing duplicated/corrupted storage-deposit and child-trie state upon both frames committing.

		frame_args: FrameArgs<T, E>,
		value_transferred: BalanceOf<T>,
		gas_meter: &mut GasMeter<T>,
		gas_limit: Weight,
		storage_meter: &mut storage::meter::GenericMeter<T, S>,
		deposit_limit: BalanceOf<T>,
		determinism: Determinism,
		read_only: bool,
	) -> Result<(Frame<T>, E, Option<u64>), ExecError> {
		let (account_id, contract_info, executable, delegate_caller, entry_point, nonce) =
			match frame_args {
				FrameArgs::Call { dest, cached_info, delegated_call } => {
					let contract = if let Some(contract) = cached_info {
						contract
					} else {
						<ContractInfoOf<T>>::get(&dest).ok_or(<Error<T>>::ContractNotFound)?
					};

					let (executable, delegate_caller) =
						if let Some(DelegatedCall { executable, caller }) = delegated_call {
							(executable, Some(caller))
						} else {
							(E::from_storage(contract.code_hash, gas_meter)?, None)
						};

					(dest, contract, executable, delegate_caller, ExportedFunction::Call, None)
				},
				FrameArgs::Instantiate { sender, nonce, executable, salt, input_data } => {
					let account_id = Contracts::<T>::contract_address(
						&sender,
						&executable.code_hash(),
						input_data,
						salt,
					);
					let contract = ContractInfo::new(&account_id, nonce, *executable.code_hash())?;
					(
						account_id,
						contract,
						executable,
						None,
						ExportedFunction::Constructor,
						Some(nonce),
					)
				},
			};

		// `Relaxed` will only be ever set in case of off-chain execution.
		// Instantiations are never allowed even when executing off-chain.
		if !(executable.is_deterministic() ||
			(matches!(determinism, Determinism::Relaxed) &&
				matches!(entry_point, ExportedFunction::Call)))
		{
			return Err(Error::<T>::Indeterministic.into());
		}

		let frame = Frame {
			delegate_caller,
			value_transferred,
			contract_info: CachedContract::Cached(contract_info),
			account_id,
			entry_point,
			nested_gas: gas_meter.nested(gas_limit),
			nested_storage: storage_meter.nested(deposit_limit),
			allows_reentry: true,
			read_only,
		};

		Ok((frame, executable, nonce))
	}

	fn push_frame(
		&mut self,
		frame_args: FrameArgs<T, E>,

			(&frame.contract_info, frame.entry_point)
		{
			<ContractInfoOf<T>>::insert(frame.account_id.clone(), contract.clone());

impl<T: Config> AddressGenerator<T> for DefaultAddressGenerator {
	/// Formula: `hash("contract_addr_v1" ++ deploying_address ++ code_hash ++ input_data ++ salt)`
	fn contract_address(
		deploying_address: &T::AccountId,
		code_hash: &CodeHash<T>,
		input_data: &[u8],
		salt: &[u8],
	) -> T::AccountId {
		let entropy = (b"contract_addr_v1", deploying_address, code_hash, input_data, salt)
			.using_encoded(T::Hashing::hash);
		Decode::decode(&mut TrailingZeroInput::new(entropy.as_ref()))
			.expect("infinite length input; no invalid inputs for type; qed")
	}
