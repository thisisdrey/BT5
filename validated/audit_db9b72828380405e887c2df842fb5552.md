## Title
Handshake responder-identity check performed after `SetRemote`/`InsertRelayTo` already mutate trusted state - (`File: handshake_manager.go`)

### Summary
`continueHandshake` mirrors the accounting-order bug in the report: it commits trust-relevant state (`hostinfo.SetRemote(...)`, which calls `RemoteList.LearnRemote`, or `hostinfo.relayState.InsertRelayTo(...)`) *before* it verifies that the certificate returned in the handshake actually belongs to the vpn address the initiator intended to reach (`correctHostResponded`). [1](#0-0) 

### Finding Description
In `continueHandshake`, once `machine.ProcessPacket` returns a `result` (i.e. the handshake cryptographically completed and produced *some* validly-signed peer certificate), the code immediately does:

```go
if !via.IsRelayed {
    hostinfo.SetRemote(via.UdpAddr)
} else {
    hostinfo.relayState.InsertRelayTo(via.relayHI.vpnAddrs[0])
}
```
before it checks whether the responding certificate's vpn address actually matches the address the initiator meant to handshake with (`correctHostResponded`, computed afterward). [2](#0-1) 

`SetRemote` calls `i.remotes.LearnRemote(i.vpnAddrs[0], remote)`, which writes the attacker-controlled `via.UdpAddr` into the `RemoteList` cache keyed by the *intended* target's vpn address (`hostinfo.vpnAddrs[0]` at this point is still the original target, since `hostinfo.vpnAddrs` is only reassigned to the (possibly wrong) responder's addresses later, on line 941 for the reject path or line 966 for the accept path). [3](#0-2) [4](#0-3) [5](#0-4) 

Only after this state mutation does the code discover that the wrong host responded, and only then attempts remediation by calling `remotes.BlockRemote(via)` on the *same* `RemoteList` object it just poisoned. [6](#0-5) 

`BlockRemote` mitigates most of the damage for non-relayed handshakes by filtering the learned address out of the deduplicated `addrs` list during the next `Rebuild`/`unlockedCollect` pass. [7](#0-6) [8](#0-7)  However:

- `BlockRemote` is a no-op for relayed handshakes (`if bad.IsRelayed { return }`), meaning for relayed wrong-responder handshakes, no equivalent block is ever applied to compensate for `InsertRelayTo` having already been called. [9](#0-8) 
- The underlying `cache[ownerVpnIp].v4/v6.learned` field itself is never cleared to its prior value — only filtered from the derived list, so any code path that reads the raw cache directly (e.g. `CopyCache`, used for diagnostics/admin API) still reports the attacker's address as "learned" for the legitimate vpn address. [10](#0-9) 
- The ordering itself is a structural violation of the same principle the external report flags: state that other logic (subsequent address selection, relay trust) depends on is committed using data that has not yet been authorized/verified for that specific binding, and correctness is retroactively patched rather than prevented up front.

### Impact Explanation
For the non-relayed path, the `BlockRemote` cleanup largely neutralizes exploitation for the deduplicated address selection used by `ForEach`/`CopyAddrs` (confirmed by the project's own e2e regression tests for this exact scenario, e.g. `TestWrongResponderHandshakeStaticHostMap`, `TestHandshakeWrongResponderPacketStore`). [11](#0-10) [12](#0-11) 

For the relayed path, however, `InsertRelayTo` establishes relay trust on `hostinfo.relayState` and `BlockRemote` is explicitly a no-op for relayed traffic, so there is no analogous corrective step for the relay-trust side effect. If `hostinfo` were reused rather than deleted (or if a race allows other code to observe `relayState` before `DeleteHostInfo` completes), a wrong/impersonating relay-responder could get its address entered into relay trust state without an equivalent block.

### Likelihood Explanation
Exploitation requires an attacker who can respond to (or relay-inject a response to) a stage-1 handshake initiated toward a legitimate peer with their own validly-signed certificate for a *different* address — essentially the same race/impersonation precondition the project's own "wrong responder" tests already exercise. This is reachable by any network-adjacent attacker without needing a CA-signed cert for the victim's identity, only their own valid cert, matching the allowed threat model (handshake authentication / hostmap-relay address trust).

### Recommendation
Move `hostinfo.SetRemote(via.UdpAddr)` / `hostinfo.relayState.InsertRelayTo(...)` to occur *after* the `correctHostResponded` check succeeds, mirroring the report's mitigation of moving the state-mutating call to after validation rather than before-and-patch. If a relay-side equivalent of `BlockRemote` is needed to preserve the current side-effect ordering, add one and remove the relay no-op exemption; otherwise fully defer the mutation.

### Proof of Concept
1. Initiator `me` starts a handshake toward `them`'s vpn address, but the lighthouse cache (attacker-controlled or race-won) briefly points at `evil`'s UDP address instead of `them`'s.
2. `evil` completes a valid Noise handshake using its own legitimately-signed certificate (for its own vpn address, not `them`'s).
3. In `continueHandshake`, `result` is non-nil, so `hostinfo.SetRemote(via.UdpAddr)` executes immediately, calling `LearnRemote` and writing `evil`'s UDP address into the `RemoteList` cache keyed by `them`'s vpn address — before `correctHostResponded` is computed.
4. The subsequent `vpnNetworks` loop determines `evil`'s cert networks don't match `hostinfo.vpnAddrs[0]` (`them`), so `correctHostResponded` is false, triggering `DeleteHostInfo` + `BlockRemote(via)` on the shared `RemoteList`.
5. For a non-relayed run this is masked by `BlockRemote` filtering (see existing e2e tests), but for the relayed variant (`via.IsRelayed == true`), `hostinfo.relayState.InsertRelayTo(via.relayHI.vpnAddrs[0])` was called at step 3's equivalent branch, and `BlockRemote` no-ops for relayed traffic, leaving no compensating control over the already-mutated relay trust state. [13](#0-12) [9](#0-8)

// LearnRemote locks and sets the learned slot for the owner vpn ip to the provided addr
// Currently this is only needed when HostInfo.SetRemote is called as that should cover both handshaking and roaming.
// It will mark the deduplicated address list as dirty, so do not call it unless new information is available
func (r *RemoteList) LearnRemote(ownerVpnIp netip.Addr, remote netip.AddrPort) {
	r.Lock()
	defer r.Unlock()
	if remote.Addr().Is4() {
		r.unlockedSetLearnedV4(ownerVpnIp, netAddrToProtoV4AddrPort(remote.Addr(), remote.Port()))
	} else {
		r.unlockedSetLearnedV6(ownerVpnIp, netAddrToProtoV6AddrPort(remote.Addr(), remote.Port()))
	}
}

// CopyCache locks and creates a more human friendly form of the internal address cache.
// This may contain duplicates and blocked addresses
func (r *RemoteList) CopyCache() *CacheMap {
	r.RLock()
	defer r.RUnlock()

	cm := make(CacheMap)
	getOrMake := func(vpnIp string) *Cache {
		c := cm[vpnIp]
		if c == nil {
			c = &Cache{
				Learned:  make([]netip.AddrPort, 0),
				Reported: make([]netip.AddrPort, 0),
				Relay:    make([]netip.Addr, 0),
			}
			cm[vpnIp] = c
		}
		return c
	}

	for owner, mc := range r.cache {
		c := getOrMake(owner.String())

		if mc.v4 != nil {
			if mc.v4.learned != nil {
				c.Learned = append(c.Learned, protoV4AddrPortToNetAddrPort(mc.v4.learned))
			}

			for _, a := range mc.v4.reported {
				if a == nil {
					continue
				}
				c.Reported = append(c.Reported, protoV4AddrPortToNetAddrPort(a))
			}
		}

		if mc.v6 != nil {
			if mc.v6.learned != nil {
				c.Learned = append(c.Learned, protoV6AddrPortToNetAddrPort(mc.v6.learned))
			}

			for _, a := range mc.v6.reported {
				if a == nil {
					continue
				}
				c.Reported = append(c.Reported, protoV6AddrPortToNetAddrPort(a))
			}
		}

		if mc.relay != nil {
			for _, a := range mc.relay.relay {
				c.Relay = append(c.Relay, a)
			}
		}
	}

	return &cm
}

// BlockRemote locks and records the address as bad, it will be excluded from the deduplicated address list
func (r *RemoteList) BlockRemote(bad ViaSender) {
	if bad.IsRelayed {
		return
	}

	r.Lock()
	defer r.Unlock()

	// Check if we already blocked this addr
	if r.unlockedIsBad(bad.UdpAddr) {
		return
	}

	// We copy here because we are taking something else's memory and we can't trust everything
	r.badRemotes = append(r.badRemotes, bad.UdpAddr)

	// Mark the next interaction must recollect/dedupe
	r.shouldRebuild = true
}

func TestHandshakeWrongResponderPacketStore(t *testing.T) {
	t.Parallel()
	// Verify that when the wrong host responds, the cached packets are
	// transferred to the new handshake, the evil tunnel is closed, evil's
	// address is blocked, and the correct tunnel is eventually established.

	ca, _, caKey, _ := cert_test.NewTestCaCert(cert.Version1, cert.Curve_CURVE25519, time.Now(), time.Now().Add(10*time.Minute), nil, nil, []string{})
	myControl, myVpnIpNet, myUdpAddr, _ := newSimpleServer(cert.Version1, ca, caKey, "me", "10.128.0.100/24", nil)
	theirControl, theirVpnIpNet, theirUdpAddr, _ := newSimpleServer(cert.Version1, ca, caKey, "them", "10.128.0.99/24", nil)
	evilControl, evilVpnIpNet, evilUdpAddr, _ := newSimpleServer(cert.Version1, ca, caKey, "evil", "10.128.0.2/24", nil)

	myControl.InjectLightHouseAddr(theirVpnIpNet[0].Addr(), evilUdpAddr)

	r := router.NewR(t, myControl, theirControl, evilControl)
	defer r.RenderFlow()

	myControl.Start()
	theirControl.Start()
	evilControl.Start()

	t.Log("Send multiple packets to them (cached during handshake)")
	myControl.InjectTunPacket(BuildTunUDPPacket(theirVpnIpNet[0].Addr(), 80, myVpnIpNet[0].Addr(), 80, []byte("packet1")))
	myControl.InjectTunPacket(BuildTunUDPPacket(theirVpnIpNet[0].Addr(), 80, myVpnIpNet[0].Addr(), 80, []byte("packet2")))

	t.Log("Route until evil tunnel is closed")
	h := &header.H{}
	r.RouteForAllExitFunc(func(p *udp.Packet, c *nebula.Control) router.ExitType {
		if err := h.Parse(p.Data); err != nil {
			panic(err)
		}
		if h.Type == header.CloseTunnel && p.To == evilUdpAddr {
			return router.RouteAndExit
		}
		return router.KeepRouting
	})

	t.Log("Verify evil's address is blocked in the new pending handshake")
	pendingHI := myControl.GetHostInfoByVpnAddr(theirVpnIpNet[0].Addr(), true)
	if pendingHI != nil {
		assert.NotContains(t, pendingHI.RemoteAddrs, evilUdpAddr,
			"evil's address should be blocked")
	}

	t.Log("Inject correct lighthouse addr for them")
	myControl.InjectLightHouseAddr(theirVpnIpNet[0].Addr(), theirUdpAddr)

	t.Log("Route until cached packets arrive at the real them")
	p := r.RouteForAllUntilTxTun(theirControl)
	assert.NotNil(t, p, "a cached packet should be delivered to the correct host")

	t.Log("Verify the correct host has a tunnel")
	assertHostInfoPair(t, myUdpAddr, theirUdpAddr, myVpnIpNet, theirVpnIpNet, myControl, theirControl)

	t.Log("Verify no hostinfo artifacts from evil remain")
	assert.Nil(t, myControl.GetHostInfoByVpnAddr(evilVpnIpNet[0].Addr(), true),
		"no pending hostinfo for evil")
	assert.Nil(t, myControl.GetHostInfoByVpnAddr(evilVpnIpNet[0].Addr(), false),
		"no main hostinfo for evil")

	myControl.Stop()
	theirControl.Stop()
	evilControl.Stop()
}
