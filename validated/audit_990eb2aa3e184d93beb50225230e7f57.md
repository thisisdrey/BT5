### Title
Uninitialized reward accounts receive the full initial index as claimable rewards - (File: `contracts/RewardsDistributor.sol`)

### Summary
`RewardsDistributor` treats an account with no recorded index as starting at `INITIAL_INDEX` only when the global token index is **greater than** `INITIAL_INDEX`. When a newly enabled reward token still has `tokenStates[token].index == INITIAL_INDEX`, the account index remains zero, producing a `deltaIndex` of `1e18` and crediting the account with `balanceOf(account) * 1` reward tokens. An attacker can trigger this through the public `updateBeforeMintOrBurn()` function and then claim through `claimRewards()` [1](#0-0) [2](#0-1) .

### Finding Description
The reward-account initialization check uses `>` rather than `>=`:

```solidity
if (_accountIndex == 0 && _tokenIndex > INITIAL_INDEX) {
    _accountIndex = INITIAL_INDEX;
}
uint256 _deltaIndex = _tokenIndex - _accountIndex;
_tokensDelta = token_.balanceOf(account_).wadMul(_deltaIndex);
```

At token initialization, `_tokenIndex == INITIAL_INDEX`, so the fallback is skipped. An account with `accountIndexOf[token][account] == 0` therefore receives `_deltaIndex == INITIAL_INDEX == 1e18`, causing `_tokensDelta` to equal its whole tracked-token balance [2](#0-1) .

`updateBeforeMintOrBurn()` is explicitly public and callable for any account, so the attacker does not need the tracked token itself to call back into the distributor [3](#0-2) . `claimRewards()` then transfers `tokensAccruedOf[account]` when the distributor balance is sufficient [4](#0-3) [5](#0-4) .

### Impact Explanation
An unprivileged attacker holding `B` units of a newly indexed `DepositToken` can claim `B` reward tokens immediately, without waiting for the configured reward speed to accrue anything. This violates the reward-accounting invariant and directly steals rewards reserved for legitimate participants. The payout is limited by the distributor’s reward-token balance and by the attacker’s tracked-token balance.

### Likelihood Explanation
The bug requires a tracked token whose `tokenStates[token].index` is still `INITIAL_INDEX`, such as immediately after normal reward-token activation. The attacker must already hold, or acquire before the first index update, a qualifying `DepositToken` balance. No privileged attacker, oracle manipulation, malformed contract callback, or failed external dependency is required after that configuration exists.

### Recommendation
Initialize first-time accounts when `_tokenIndex >= INITIAL_INDEX`, or explicitly initialize `accountIndexOf` to the current token index before computing a delta. A conservative fix is:

```solidity
if (_accountIndex == 0 && _tokenIndex >= INITIAL_INDEX) {
    _accountIndex = INITIAL_INDEX;
}
```

Alternatively, make `_updateTokensAccruedOf()` treat `accountIndexOf[token][account] == 0` as “initialize at current index” for every nonzero token index.

### Proof of Concept
The following Foundry-style fork test demonstrates the state transition after a reward token is initialized:

```solidity
function test_initialIndexGrantsBalanceAsRewards() public {
    RewardsDistributor distributor = RewardsDistributor(DISTRIBUTOR);
    IERC20 rewardToken = distributor.rewardToken();
    IERC20 trackedToken = IERC20(TRACKED_DEPOSIT_TOKEN);
    address attacker = makeAddr("attacker");

    // Give the attacker a tracked DepositToken balance through Pool/DepositToken
    // before reward accrual begins.
    uint256 held = acquireDepositToken(trackedToken, attacker);
    uint256 reserve = rewardToken.balanceOf(address(distributor));
    vm.assume(held > 0 && held <= reserve);

    // Normal reward activation leaves token index at INITIAL_INDEX.
    vm.prank(distributor.governor());
    distributor.updateTokenSpeed(trackedToken, 1);
    (uint224 index,) = distributor.tokenStates(trackedToken);
    assertEq(index, distributor.INITIAL_INDEX());

    // Permissionless account update credits held * 1e18 / 1e18 == held.
    vm.startPrank(attacker);
    distributor.updateBeforeMintOrBurn(trackedToken, attacker);
    distributor.claimRewards(attacker);
    vm.stopPrank();

    assertEq(rewardToken.balanceOf(attacker), held);
}
```
