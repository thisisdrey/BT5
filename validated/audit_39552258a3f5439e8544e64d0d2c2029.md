Audit Report

## Title
System precompile (`0x900`) is missing the `PrecompileDelegateDenied` guard applied to every other caller-sensitive precompile - (File: `substrate/frame/revive/src/precompiles/builtin/system.rs`)

## Summary
`Stack::caller()` resolves to the *original delegating caller* when the current top frame is a delegate-call frame [1](#0-0) , exactly the "code address vs execution address" confusion previously identified and fixed for the assets, asset-conversion, XCM, and vesting precompiles via a `PrecompileDelegateDenied`/`is_delegate_call()` guard [2](#0-1) [3](#0-2) . The System builtin precompile's `call` implementation has no equivalent guard, so `callerIsOrigin`, `callerIsRoot`, and `ownCodeHash` all consume `env.caller()`/`caller_is_origin`/`caller_is_root` unguarded against delegate-call framing [4](#0-3) .

## Finding Description
The prior fixes explicitly state the motivation: "Delegatecall to precompiles allows a malicious contract to execute precompile logic in a misleading caller context... There is no legitimate use case for delegatecalling into these precompiles" [5](#0-4) , and this was applied uniformly to assets, asset-conversion, XCM, and vesting precompiles, plus the Storage precompile's inverse (delegatecall-required) invariant [6](#0-5) . The System precompile's `call` function at `substrate/frame/revive/src/precompiles/builtin/system.rs` handles `callerIsOrigin`, `callerIsRoot`, and `ownCodeHash` by reading `env.caller_is_origin(true)`, `env.caller_is_root(true)`, and `env.caller()` respectively, with zero delegate-call check anywhere in the match arms [7](#0-6) . Because `Stack::caller()` substitutes in the original external caller's `Origin` whenever `self.top_frame().delegate` is `Some(...)` [1](#0-0) , an intermediary contract that is delegatecalled-into and then calls System's `callerIsRoot()`/`callerIsOrigin()`/`ownCodeHash()` will report the *original* caller's identity/code hash rather than its own, letting the intermediary impersonate a trusted caller when a downstream contract gates privileged logic on these results.

## Impact Explanation
This matches the "unauthorized execution or origin escalation" impact category: any consuming contract that trusts System precompile's `callerIsOrigin`, `callerIsRoot`, or `ownCodeHash` output for authorization decisions can be misled by a malicious intermediary contract that delegatecalls into `0x900`, causing the authorization check to reflect the wrong (original, more-privileged) caller's identity instead of the true immediate caller [4](#0-3) .

The `terminate` sub-case (self-destruct/fund movement) is not conclusively established as vulnerable: the `terminate` arm only checks `env.is_read_only()` [8](#0-7) , but I was unable to confirm within tool budget whether `env.terminate_caller()` in `exec.rs` independently re-checks delegate-call framing before executing the self-destruct, despite a suggestively-named guard string appearing in `substrate/frame/revive/src/tests/sol/terminate.rs`. This sub-case should be treated as unresolved rather than confirmed.

## Likelihood Explanation
Exploiting the identity-leak sub-case (`callerIsOrigin`/`callerIsRoot`/`ownCodeHash`) requires only an unprivileged contract deployer crafting a delegatecall to the fixed precompile address `0x900` from any contract the victim trusts to make bounded external calls — no privileged actor, relayer, or governance action is needed. This is directly analogous to, and uses the identical mechanism as, the already-patched assets/asset-conversion/XCM/vesting precompile bugs [5](#0-4) .

## Recommendation
Add the same `PrecompileDelegateDenied`/`is_delegate_call()` guard used by the assets, asset-conversion, XCM, and vesting precompiles to the top of `System::call` in `substrate/frame/revive/src/precompiles/builtin/system.rs`, following the pattern in `polkadot/xcm/pallet-xcm/precompiles/src/lib.rs` [2](#0-1) , and add a `delegatecall_is_rejected` regression test mirroring the existing suites, while separately auditing `terminate_caller` in `exec.rs` to confirm or add an independent delegate-call check for the `terminate` path.

## Proof of Concept
1. Deploy an intermediary `Caller`-style contract exposing `delegateCall(address callee, bytes data, uint64 gas)`, matching the fixture used in the XCM precompile's own delegatecall-rejection test.
2. From this contract, delegatecall to `0x0000...0900` (System precompile) invoking `callerIsRoot()` or `ownCodeHash()`.
3. Because `Stack::caller()` resolves to the original external caller under delegate-call framing [1](#0-0) , the intermediary obtains identity/root attestations belonging to the original caller instead of itself, reproducing the same "impersonate the trusted caller" pattern the other precompile fixes addressed [4](#0-3) .
