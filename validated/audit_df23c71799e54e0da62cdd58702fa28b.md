## Analysis

The Spartan `Router.addDividend` bug is a class of vulnerability where a small, easily-reset rolling statistic (the last 20 trades' `normalAverageFee`) gates a much larger resource payout, and an unprivileged actor can cheaply drive that statistic toward zero before triggering the payout, capturing a disproportionate share of a shared resource.

The closest reachable analog in this codebase is the **stake-weighted QoS (`SwQoS`) load EMA** used by the QUIC streamer to gate whether staked stream bandwidth is rationed proportionally to stake.

### Title
Stake-weighted QoS throttling can be evaded via EMA decay/reset, granting disproportionate (non-stake-proportional) QUIC stream bandwidth - (File: `streamer/src/nonblocking/stream_throttle.rs`)

### Summary
`StakedStreamLoadEMA` computes a single, server-wide exponential moving average of staked-peer stream load over a short (`STREAM_LOAD_EMA_INTERVAL_COUNT` = 40 samples of `STREAM_LOAD_EMA_INTERVAL_MS` = 5ms, i.e. ~200ms) window, and uses that average as a binary switch (`staked_throttling_enabled`) that decides whether staked connections are limited proportionally to their stake or are each granted the server's *entire* staked capacity window unthrottled.

### Finding Description
`StakedStreamLoadEMA::update_ema` recomputes the EMA from `load_in_recent_interval`, which is only incremented for staked peers via `increment_load` when a new stream is accepted [1](#0-0) . The EMA decays toward zero whenever no staked load is observed, since `ema_function(ema, 0)` is applied repeatedly for missed intervals [2](#0-1) . When the resulting EMA falls below `staked_throttling_on_load_threshold` (95% of the max staked load in an EMA interval), `staked_throttling_enabled` flips to `false` [3](#0-2) .

The consequence of this flag is decided in `available_load_capacity_in_throttling_duration`: when throttling is *disabled*, a staked connection is granted the entire `max_staked_load_in_throttling_window` regardless of its own stake weight; only when throttling is *enabled* is capacity scaled by `stake / total_stake` [4](#0-3) . This value directly feeds `SwQos::max_streams_per_throttling_interval` used to gate each new stream [5](#0-4)  and [6](#0-5) .

This mirrors the report's bug class exactly: a single global rolling average over a very short window (~200ms / 40 samples, analogous to the 20-trade window) gates a resource-allocation decision (stake-proportional vs. unthrottled bandwidth), and it can be driven toward its low state cheaply (simply not sending streams, which costs nothing) by any staked peer connecting to the server, then exploited by bursting streams while the EMA is still low and the "unthrottled/disabled" branch is in effect.

### Impact Explanation
A low-stake attacker who is nonetheless classified as `ConnectionPeerType::Staked` (their stake ratio only needs to clear `min_stake_ratio` in `SwQos::build_connection_context`, a very low bar: `1 / (max_streams_per_ms * STREAM_THROTTLING_INTERVAL_MS)` [7](#0-6) ) can time their stream bursts to windows where the shared EMA has decayed below threshold, obtaining the server's *entire* `max_staked_load_in_throttling_window` capacity instead of their fair stake-weighted share. This breaks the intended stake-weighted QoS fairness guarantee that is meant to prevent low-stake or unstaked actors from consuming disproportionate leader bandwidth relative to high-stake validators, and can be used to starve legitimate higher-stake traffic (votes, transactions) of stream capacity during the attacker's burst windows, i.e. QoS evasion.

### Likelihood Explanation
Exploitation requires only a QUIC connection with some minimal delegated/self stake (no special validator role) and control of send timing — both are available to any unprivileged network participant. The EMA window is short (~200ms) and decays quickly to zero absent staked traffic, making the "quiet-then-burst" pattern straightforward and repeatable, similar to how the original bug repeatedly reset `normalAverageFee` with cheap operations before extracting value.

### Recommendation
- Compute stake-weighted capacity based on cumulative/volume-based tracking over a longer, harder-to-manipulate window rather than a short, globally-shared, easily-decayed EMA that toggles a binary throttling mode.
- Avoid a hard on/off transition for `staked_throttling_enabled`; instead, always scale allowed capacity by stake ratio (with a floor), so that low EMA periods do not let any single staked connection claim the full server capacity irrespective of its stake.
- Consider per-connection (not only global) load tracking so a peer cannot benefit from the aggregate EMA being low due to other peers' inactivity.

### Proof of Concept
1. Attacker acquires or is delegated stake just above `min_stake_ratio` so their connection is classified `ConnectionPeerType::Staked` rather than `Unstaked`.
2. Attacker opens a QUIC connection to a target TPU server and sends no streams for ≥ `STREAM_LOAD_EMA_INTERVAL_COUNT * STREAM_LOAD_EMA_INTERVAL_MS` (~200ms) while the server's aggregate staked load is low, letting `current_load_ema` decay via repeated `ema_function(ema, 0)` calls below `staked_throttling_on_load_threshold`, so `staked_throttling_enabled` becomes `false`.
3. Attacker bursts as many streams as allowed within one `STREAM_THROTTLING_INTERVAL` (100ms); because throttling is disabled, `available_load_capacity_in_throttling_duration` returns the full `max_staked_load_in_throttling_window` for the attacker's connection rather than a stake-proportional fraction.
4. Attacker repeats the quiet-then-burst cycle to sustain outsized bandwidth consumption relative to their actual stake, at the expense of fair, stake-proportional access for genuinely high-stake peers.

        // if time_since_last_update_ms > STREAM_LOAD_EMA_INTERVAL_MS, there might be intervals where ema was not updated.
        // count how many updates (1 + missed intervals) are needed.

            time_since_last_update_ms.saturating_sub(1) / u128::from(STREAM_LOAD_EMA_INTERVAL_MS);

            load_in_recent_interval,
        );

        for _ in 0..num_extra_updates {
            updated_load_ema = Self::ema_function(updated_load_ema, 0);

                break;

    pub(crate) fn available_load_capacity_in_throttling_duration(
        &self,
        peer_type: ConnectionPeerType,
        total_stake: u64,
    ) -> u64 {
        match peer_type {
            ConnectionPeerType::Unstaked => self.max_unstaked_load_in_throttling_window,
            ConnectionPeerType::Staked(stake) => {
                if self.staked_throttling_enabled.load(Ordering::Relaxed) {
                    // 1 is added to `max_unstaked_load_in_throttling_window` to guarantee that staked
                    // clients get at least 1 more number of streams than unstaked connections.
                    self.max_staked_load_in_throttling_window
                        .saturating_mul(stake)
                        .checked_div(total_stake)
                        .unwrap_or(self.max_unstaked_load_in_throttling_window + 1)
                        .max(self.max_unstaked_load_in_throttling_window + 1)
                } else {
                    self.max_staked_load_in_throttling_window
                }
            }
        }
    }
