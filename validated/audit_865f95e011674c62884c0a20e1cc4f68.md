## Analysis

The DODO bug pattern is: a security check is gated on one field/flag (`zrc20 == _ETH_ADDRESS_`), and when that gate is satisfied, a *different*, unauthenticated, attacker-supplied value is trusted for the actual state-changing action (withdrawing real tokens) — i.e., the validated condition and the value actually acted upon are not the same thing.

The closest reachable analog in Nebula that fits the "no CA-signed certificate required" constraint is in the unauthenticated `RecvError` packet path.

### Title
Anti-spoofing check for `RecvError` packets is bypassed whenever the target's remote address is not yet known, allowing an unauthenticated attacker to tear down victim tunnels - (File: `outside.go`)

### Summary
`header.RecvError` packets are processed before any certificate, HostInfo, or handshake validation occurs. The only defense against a forged `RecvError` is a comparison between the packet's source address and the currently-recorded remote address of the targeted `HostInfo`. That comparison is skipped whenever the recorded remote address is not yet "valid" (e.g. before the tunnel has fully roamed/confirmed a remote, or after certain resets), meaning the gate that is supposed to authenticate the sender never actually executes.

### Finding Description
In `outside.go`, `RecvError` is dispatched immediately after header parsing, with no hostinfo/cert gating at all: [1](#0-0) 

The handler is `handleRecvError`: [2](#0-1) 

The only anti-spoofing logic is:
```go
hr := hostinfo.GetRemote()
if hr.IsValid() && hr != addr {
    f.l.Info("Someone spoofing recv_errors?", ...)
    return
}
f.closeTunnel(hostinfo)
```
This mirrors the DODO root cause exactly: the code validates the sender's address only when a side condition (`hr.IsValid()`) happens to be true. When `hr.IsValid()` is `false` — i.e. no remote has been recorded yet for that `HostInfo`, which happens in normal operation while a handshake/roam is in flight — the entire spoof check short-circuits to "not spoofed," and the attacker-supplied `addr` and `h.RemoteIndex` (both fully attacker-controlled on an unauthenticated packet type) are trusted to identify and tear down a real tunnel via `f.closeTunnel(hostinfo)` and `f.handshakeManager.DeleteHostInfo(hostinfo)`.

The `RemoteIndex` field used to look up the victim `HostInfo` (`f.hostMap.QueryReverseIndex(h.RemoteIndex)`) travels in the cleartext header of every Nebula packet, so any attacker capable of observing traffic on the path (no CA cert, no handshake, no decryption needed) can learn valid indices, and combine that with plain UDP source-address spoofing to forge a `RecvError` packet.

### Impact Explanation
An attacker with no certificate and no established tunnel can inject a single spoofed `RecvError` UDP datagram that forces `closeTunnel` and `DeleteHostInfo` on a legitimate peer's HostInfo whenever that HostInfo's remote address is not yet marked "valid" (during initial handshake completion windows, roaming, or after certain resets). This is a remote state-poisoning / denial-of-service primitive: it can repeatedly disrupt tunnel establishment between two legitimate nodes without ever holding a valid certificate, purely by crafting header fields — the same class of bug as the report (validate on a convenient flag, but trust an attacker-supplied value for the actual privileged operation).

### Likelihood Explanation
Exploitability depends on: (1) knowing/observing a target's `RemoteIndex`, which is transmitted unencrypted in every packet header and thus learnable by any on-path or off-path observer capable of capturing/guessing traffic between the endpoints, and (2) hitting the window where `hr.IsValid()` is false. This window is not rare — it exists during ordinary handshake-in-progress and roaming states — making the condition realistically reachable, though it does require some timing/observation, unlike the DODO bug which needed zero preconditions.

### Recommendation
Do not treat "remote not yet valid" as equivalent to "sender authenticated." `handleRecvError` should either: (a) refuse to act on `RecvError` when `hr` is not yet valid (treat unknown-remote as fail-closed rather than fail-open), or (b) bind acceptance of `RecvError` to some other verified property of the tunnel (e.g., require a matching, still-live remote index *and* that the index/HostInfo state supports a meaningful remote comparison) instead of allowing the check to no-op.

### Proof of Concept
1. Node A begins a handshake or roam to Node B such that `hostinfo.GetRemote()` for the relevant `HostInfo` on Node B (or A) is momentarily invalid/unset.
2. Attacker C, without any CA-signed certificate, crafts a raw UDP packet with `header.Type = header.RecvError` and `RemoteIndex` set to the local index that Node B (or A) is using for the handshake in progress (observed from the plaintext header of prior packets on the path).
3. Attacker sends this packet to the victim's listening UDP port from an arbitrary spoofed source address.
4. In `handleRecvError`, `hr.IsValid()` is `false`, so the spoof check is skipped entirely; `f.closeTunnel(hostinfo)` and `hm.DeleteHostInfo(hostinfo)` execute, tearing down the in-progress tunnel/handshake state without any cryptographic authentication of the attacker. [2](#0-1) [1](#0-0)

func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
