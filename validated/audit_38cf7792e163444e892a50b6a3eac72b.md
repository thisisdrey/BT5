Audit Report

## Title
`InboundLane::receive_message` rejects same-relayer messages with `TooManyUnrewardedRelayers` before checking whether the message would merge into the existing back entry - ([File: bridges/modules/messages/src/inbound_lane.rs])

## Summary
`receive_message` enforces `data.relayers.len() >= max_unrewarded_relayer_entries()` unconditionally before determining whether the incoming message's relayer matches `data.relayers.back()`. Because merging into the existing back entry via `note_dispatched_message()` does not increase `relayers.len()`, this ordering spuriously rejects otherwise-valid, correctly-sequenced messages from the same relayer that is already the last entry in the queue.

## Finding Description
The check sequence in `receive_message` is: nonce validation, then the capacity guard `if data.relayers.len() as MessageNonce >= self.storage.max_unrewarded_relayer_entries() { return ReceptionResult::TooManyUnrewardedRelayers; }`, and only afterward the logic that decides whether to extend `data.relayers.back_mut()` for a matching relayer or push a new entry [1](#0-0) . Since a message from the same relayer as the current back entry only calls `entry.messages.note_dispatched_message()` and never grows `data.relayers`, the capacity guard is stricter than necessary: it rejects a class of messages that provably cannot violate the "at most N entries" invariant documented on `InboundLaneData::relayers` [2](#0-1) . The existing nonce and unconfirmed-message checks do not compensate for this, since they run independently of relayer identity.

## Impact Explanation
When the unrewarded-relayer set reaches `max_unrewarded_relayer_entries`, a relayer that is the current back-entry relayer and continues to deliver strictly sequential messages is rejected even though its message would not increase the size of the bounded set. This spuriously stalls dispatch/progress of the inbound lane's `last_delivered_nonce` for a legitimate, correctly-ordered message, matching the "stalls bridge processing" class of impact. The rejection is not permanent: once a `receive_messages_delivery_proof` confirmation clears older entries, the same nonce can be resubmitted and will succeed, so this is a recoverable processing stall rather than a permanent fund or state lock.

## Likelihood Explanation
No malicious actor is required; a lane with one or few active relayers under sustained load (a supported operational mode per the doc comment "Multiple dispatches from the same relayer are allowed") will reach this state naturally whenever confirmations lag behind deliveries. The condition is a normal operating state, not a contrived edge case, and any correctly-behaving relayer submitting sequential messages through the public message-delivery extrinsic can trigger it.

## Recommendation
Reorder the checks so the capacity guard only fires when the incoming message would create a new relayer entry:
```rust
let would_extend_existing_entry = data
    .relayers
    .back()
    .map_or(false, |entry| entry.relayer == *relayer_at_bridged_chain);

if !would_extend_existing_entry
    && data.relayers.len() as MessageNonce >= self.storage.max_unrewarded_relayer_entries()
{
    return ReceptionResult::TooManyUnrewardedRelayers;
}
```
This preserves the bound on `relayers.len()` for genuinely new entries while permitting same-relayer merges even at capacity.

## Proof of Concept
1. Configure a lane with `max_unrewarded_relayer_entries = N` and fill `data.relayers` to length `N` with `N` distinct relayers delivering nonces `1..N`, following the pattern in `fails_to_receive_messages_above_unrewarded_relayer_entries_limit_per_lane` [3](#0-2) .
2. Have the relayer of `relayers.back()` submit the next sequential nonce `N+1`.
3. Expected: the message dispatches and merges into the existing back entry via `note_dispatched_message()` since `relayers.len()` is unchanged.
4. Actual: `receive_message` returns `ReceptionResult::TooManyUnrewardedRelayers` at the capacity check before ever reaching the back-entry merge logic, blocking a message that would not have grown the bounded relayer set.
