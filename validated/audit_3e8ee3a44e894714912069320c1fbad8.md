### Title
Pre-handshake `ClientConnectionTracker` ceiling can be saturated by never-completing QUIC handshakes, starving legitimate connections before QoS classification - ([File: streamer/src/nonblocking/quic.rs])

### Summary
`run_server` acquires a global `ClientConnectionTracker` (bounded by `qos.max_concurrent_connections()`, e.g. `(max_staked_connections + max_unstaked_connections) * 5 / 4` in `SwQos`/`SimpleQos`) *before* the QUIC handshake completes and *before* any per-IP/per-stake QoS classification occurs. The per-IP and global connection rate limiters that are checked in this same loop do not actually gate this pre-handshake tracker acquisition, because they only *consume* tokens once the handshake succeeds (`rate_limiter.register_connection` / `overall_connection_rate_limiter.consume_tokens` in `setup_connection`), not when the `Incoming` is accepted. An attacker who never completes the handshake can therefore repeatedly acquire trackers up to the ceiling, causing `refused_connections_too_many_open_connections` to reject legitimate connection attempts of any (staked or unstaked) peer type.

### Finding Description
In `run_server` (`streamer/src/nonblocking/quic.rs:254-412`), for every incoming QUIC `Incoming`:
1. `overall_connection_rate_limiter.current_tokens() == 0` is checked (line 347) — this is a read-only check, it does not consume a token.
2. `rate_limiter.is_allowed(&incoming.remote_address().ip())` is checked (line 359) — `ConnectionRateLimiter::is_allowed` (`streamer/src/nonblocking/connection_rate_limiter.rs:34-40`) is also read-only: it returns `true` for any IP it has never seen tokens consumed for.
3. Only after passing both checks does the code call `ClientConnectionTracker::new(stats.clone(), qos.max_concurrent_connections())` (line 371-372), which increments the global `open_connections` counter and enforces the ceiling (`streamer/src/nonblocking/quic.rs:236-251`). If the ceiling is exceeded, `refused_connections_too_many_open_connections` is incremented and the connection is refused (lines 373-378).
4. The tracker is handed to `setup_connection` (`quic.rs:456-543`), which awaits the handshake for up to `QUIC_CONNECTION_HANDSHAKE_TIMEOUT` (2 seconds, `quic.rs:80`). **Only if the handshake completes** does the code call `rate_limiter.register_connection(&from.ip())` (line 483) and `overall_connection_rate_limiter.consume_tokens(1)` (line 495) — i.e., the token-*consuming* calls that would actually throttle repeated attempts.
5. If the handshake never completes (attacker stalls/never responds), `setup_connection` simply logs `connection_setup_timeout` and drops the `ClientConnectionTracker`, freeing one slot — but no rate-limiter tokens were ever consumed for that attempt, and `is_allowed`/`current_tokens` checks upstream never saw any depletion either.

Consequence: the per-IP and global rate limiters are effectively no-ops against an attacker who never finishes the handshake, since they only inspect/consume state that is updated post-handshake. The only real gate against this attack is the *count* of currently outstanding trackers versus `qos.max_concurrent_connections()`. That ceiling is intentionally sized as `(max_staked_connections + max_unstaked_connections) * 5 / 4` (see `streamer/src/nonblocking/swqos.rs:518-522` and `streamer/src/nonblocking/simple_qos.rs:422-425`, both commented "Allow 25% more connections than required to allow for handshake"), i.e. only ~25% headroom over the total steady-state connection budget. An attacker can hold that entire headroom occupied with stalled handshakes (reissuing new `Incoming` attempts, e.g. new connection IDs/ports, as old trackers expire every ~2s) and keep `open_connections` pinned near the ceiling indefinitely. Because the tracker/ceiling check happens strictly before `qos.build_connection_context` / `qos.try_add_connection` (where stake-based classification and per-peer limits are applied), this starves *all* legitimate connection attempts — staked and unstaked alike — indiscriminately, which is a stronger denial than the per-IP/per-stake QoS system is designed to permit.

### Impact Explanation
This is a pre-classification, indiscriminate denial-of-service against the TPU QUIC ingress: legitimate staked and unstaked senders alike get `Incoming::refuse()`'d via `refused_connections_too_many_open_connections`, before stake is even known. Given the connection budget headroom is only 25% of total capacity, and each attack "slot" costs the attacker only a single unresponded QUIC Initial packet held for ≤2 seconds, this is a very cheap resource-exhaustion vector at the connection-admission layer, undermining the "connection limits enforced per source and cannot be evaded by connection churn" invariant. This falls under Agave's DoS/QoS-evasion bounty category (ingress/QoS bypass causing unbounded resource exhaustion against a leader's TPU QUIC endpoint).

### Likelihood Explanation
Preconditions match the stated unprivileged threat model exactly: the attacker only needs to open QUIC/UDP flows to the leader's public TPU port and withhold handshake completion (or complete only the TLS ClientHello/Initial exchange without finishing e.g. never sending the Finished message, or a raw crafted Initial-only sender). No stake, gossip, or config access is required. The attack is repeatable indefinitely by continuously issuing fresh half-open attempts (~2-second intervals) to keep `open_connections` pinned near the ceiling; the size of the ceiling (25% margin) makes this feasible from a small number of source addresses/ports.

### Recommendation
Rate-limit or throttle pre-handshake `Incoming`/tracker acquisition itself (not only post-handshake success) — e.g., consume a token from the per-IP and global rate limiters at `Incoming` acceptance time rather than only after a successful handshake, and/or maintain a separate, smaller cap on the number of *un-completed* handshakes per IP so that a single or few source IPs cannot occupy a large fraction of the global `max_concurrent_connections` headroom. Consider shrinking `QUIC_CONNECTION_HANDSHAKE_TIMEOUT` further or making the handshake-headroom fraction itself rate-limited per IP.

### Proof of Concept
Integration test plan (extends existing `streamer::nonblocking::testing_utilities::setup_quic_server` harness used throughout `streamer/src/nonblocking/quic.rs` tests):
```rust
#[tokio::test(flavor = "multi_thread")]
async fn test_stalled_handshakes_exhaust_open_connection_ceiling() {
    // Configure a server with a small max_staked/unstaked connection budget
    // so max_concurrent_connections() (1.25x) is small and reachable quickly.
    let SpawnTestServerResult { server_address, stats, cancel, join_handle, .. } =
        setup_quic_server(
            None,
            QuicStreamerConfig::default_for_tests(),
            SwQosConfig {
                max_staked_connections: 4,
                max_unstaked_connections: 4,
                ..Default::default()
            },
        );
    // max_concurrent_connections() == (4+4)*5/4 == 10

    // Attacker: open raw UDP sockets sending QUIC Initial packets (or quinn
    // endpoints that connect but never let the handshake finish, e.g. by
    // dropping the client endpoint immediately after connect() is issued
    // but before await completes) from a couple of IPs/ports, repeatedly,
    // to keep ~10 handshakes perpetually "in flight" near
    // QUIC_CONNECTION_HANDSHAKE_TIMEOUT.
    for _ in 0..10 {
        tokio::spawn(async move {
            let ep = make_client_endpoint(&server_address, None).await;
            // never await connect completion / drop endpoint without finishing handshake
            std::mem::forget(ep); // or hold without progressing handshake
        });
    }
    tokio::time::sleep(Duration::from_millis(500)).await;

    // Legitimate client attempts a connection concurrently and should be refused.
    let legit = make_client_endpoint(&server_address, None).await; // expect failure/refusal

    assert!(
        stats.refused_connections_too_many_open_connections.load(Ordering::Relaxed) > 0,
        "expected legitimate connection to be refused due to saturated open-connection ceiling"
    );

    cancel.cancel();
    join_handle.await.unwrap();
}
```
Expected assertion: `stats.refused_connections_too_many_open_connections` increments for the legitimate attempt while the attacker-held slots are still within `QUIC_CONNECTION_HANDSHAKE_TIMEOUT`, demonstrating that a handful of stalled handshakes exhaust the global ceiling ahead of QoS/stake classification.
