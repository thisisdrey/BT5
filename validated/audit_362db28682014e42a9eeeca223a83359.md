### Title
Unvalidated `GitObjectDirectory`/`GitAlternateObjectDirectories` fields let attacker point Git subprocesses outside repository/storage via `alternates.Env` - (File: internal/git/alternates/alternates.go)

### Summary
`alternates.Env` builds `GIT_OBJECT_DIRECTORY`/`GIT_ALTERNATE_OBJECT_DIRECTORIES` by doing a raw `filepath.Join(repoPath, objectDirectory)` with no bounds checking, and this is the function `gitcmd.ExecCommandFactory.newCommand` uses for every git subprocess spawned for a request. Unlike `localrepo.Repo.ObjectDirectoryPath`, which explicitly calls `storage.ValidateRelativePath` before trusting `GitObjectDirectory`, the command-execution path has no equivalent guard, so a malicious relative path such as `../../<victim>/objects` in the `Repository` message escapes the intended repository/storage tree for the lifetime of the git subprocess.

### Finding Description
`alternates.Env` is the sink: [1](#0-0) 

It is invoked unconditionally for every git subprocess that has a repository attached: [2](#0-1) 

`repo.GetGitObjectDirectory()`/`repo.GetGitAlternateObjectDirectories()` come straight from the client-supplied `gitalypb.Repository` message with no length/prefix/traversal check: [3](#0-2) 

Contrast this with `localrepo.Repo.ObjectDirectoryPath`, which is a *separate* helper used by only a few handlers (e.g. `GetObjectDirectorySize`) that explicitly validates the path with `storage.ValidateRelativePath` and a quarantine-prefix check before trusting it: [4](#0-3) 

That validation is not applied on the generic command-execution path (`newCommand`/`alternates.Env`), so any RPC handler that simply runs a git command against the request's repository is exposed.

The one gate that exists is in the transaction middleware, and it is bypassable by an external, unprivileged caller: if `GitObjectDirectory`/`GitAlternateObjectDirectories` is set on a mutator, the request is rejected, but on an accessor (read) RPC the middleware assumes this is a legitimate Rails-mediated quarantine callback and only requires the `relative-path-bin` metadata header to be present — it does not validate its origin or content: [5](#0-4) [6](#0-5) 

Since gRPC metadata is entirely attacker-controlled on a direct call, an attacker can set this header themselves (no Rails mediation is needed, matching the precondition), satisfying `restoreSnapshotRelativePath` and causing the request to be run **non-transactionally** with the object-directory fields untouched. The handler then calls into `gitcmd`, which spawns git with `alternates.Env(repoPath, objectDirectory, alternateObjectDirectories)` computed with no traversal check.

### Impact Explanation
This enables cross-repository object disclosure: by pointing `GIT_ALTERNATE_OBJECT_DIRECTORIES` at another repository's `objects` directory (reachable via a `../../` relative traversal from the attacker's own `repoPath`), the attacker's own read RPC (e.g. `FindCommit`, `CommitLanguages`, any command that shells out to git) will be able to locate and serve loose objects/packs belonging to a different repository on the same storage, provided the attacker can supply or discover the matching object ID. Pointing it at a large/slow filesystem path also enables resource-exhaustion/DoS of the RPC handler and any git subprocess pool sharing that connection. This matches GitLab's "cross-repository object access" / "DoS of an RPC handler" bounty impact classes.

### Likelihood Explanation
The attacker only needs: (1) their own regular gRPC access to any Gitaly RPC that operates on a `Repository` message and shells out to git, (2) the ability to set the `git_object_directory`/`git_alternate_object_directories` fields directly (they are ordinary proto fields, not derived server-side), and (3) the ability to set the `relative-path-bin` gRPC metadata header themselves to satisfy the transaction-middleware's quarantine-callback check. All of this is available to an unprivileged, authenticated GitLab user with normal RPC access — no Rails mediation, admin role, or secret is required.

### Recommendation
Validate `GitObjectDirectory` and each entry of `GitAlternateObjectDirectories` with `storage.ValidateRelativePath` (or the equivalent logic already implemented in `localrepo.Repo.ObjectDirectoryPath`) inside `alternates.Env`/`gitcmd.ExecCommandFactory.newCommand` before joining them onto `repoPath`, rejecting any value that escapes the repository/storage root or the expected quarantine-directory prefix. Additionally, do not trust a client-supplied `relative-path-bin` metadata header as sufficient proof that a request is a legitimate Rails quarantine callback.

### Proof of Concept
Unit-test style PoC for the sink:
```go
func TestAlternates_Env_TraversalNotValidated(t *testing.T) {
    env := alternates.Env("/storage/repo.git", "", []string{"../../../victim-repo/objects"})
    // Currently succeeds and returns an escaping path with no error:
    require.Contains(t, env[0], "GIT_ALTERNATE_OBJECT_DIRECTORIES=")
    require.NotContains(t, env[0], "/storage/repo.git/../../../victim-repo") // fails today - no rejection
}
```

RPC-level PoC: call any read RPC (e.g. `CommitService.FindCommit`) directly against Gitaly with:
- `Repository{RelativePath: "<own-repo>", GitAlternateObjectDirectories: ["../../../<victim-repo-relative-path>/objects"]}`
- gRPC metadata `relative-path-bin: "<own-repo>"`

Expected (secure) behavior: request rejected with `InvalidArgument` (path escapes storage root). Actual current behavior: request proceeds, and the resulting git subprocess is launched with `GIT_ALTERNATE_OBJECT_DIRECTORIES` pointing outside the caller's own repository.

// Env returns the alternate object directory environment variables.
func Env(repoPath, objectDirectory string, alternateObjectDirectories []string) []string {
	var env []string
	if objectDirectory != "" {
		env = append(env, fmt.Sprintf("GIT_OBJECT_DIRECTORY=%s", filepath.Join(repoPath, objectDirectory)))
	}

	if len(alternateObjectDirectories) > 0 {
		var dirsList []string

		for _, dir := range alternateObjectDirectories {
			dirsList = append(dirsList, filepath.Join(repoPath, dir))
		}

		env = append(env, fmt.Sprintf("GIT_ALTERNATE_OBJECT_DIRECTORIES=%s", strings.Join(dirsList, ":")))
	}

	return env
}

func restoreSnapshotRelativePath(ctx context.Context, methodInfo protoregistry.MethodInfo, req proto.Message) (proto.Message, error) {
	// Rails sends RPCs from its access checks with quarantine applied. The quarantine paths are relative to the
	// snapshot repository of the original transaction. While the relative path of the request is the original relative
	// path of the repository before snapshotting, Rails sends the snapshot repository's path in a header. For the
	// quarantine paths to apply correctly, we must thus rewrite the request to point to the snapshot repository here.
	snapshotRelativePath := metadata.GetValue(ctx, MetadataKeySnapshotRelativePath)
	if snapshotRelativePath == "" {
		return nil, ErrQuarantineWithoutSnapshotRelativePath
	}

	rewrittenReq, targetRepo, err := rewritableRequest(methodInfo, req)
	if err != nil {
		return nil, fmt.Errorf("rewritable request: %w", err)
	}

	targetRepo.RelativePath = snapshotRelativePath

	return rewrittenReq, nil
}
