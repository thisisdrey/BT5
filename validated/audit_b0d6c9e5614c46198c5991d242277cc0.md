### Title
Account owner permission can be irrecoverably set to an uncontrolled/zero address, permanently locking the account - (File: actuator/src/main/java/org/tron/core/actuator/AccountPermissionUpdateActuator.java)

### Summary
`AccountPermissionUpdateActuator` lets an account owner replace its `Owner`, `Witness`, and `Active` permissions with an arbitrary set of key addresses and weights via `AccountPermissionUpdateContract`. The only address-format check performed is `DecodeUtil.addressValid`, which merely validates length and prefix byte, not that the address is reachable/controllable by any known private key. This mirrors the reported issue class: a privileged party can point a critical control field (there: `marketOwner`; here: the account's `Owner` permission keys) to `address(0)` or any other address nobody holds the key for, permanently freezing the account's ability to satisfy its own permission threshold — analogous to the market being permanently unusable.

### Finding Description
`checkPermission()` in the actuator enforces structural constraints only: key count bounds, distinct addresses, positive weights, threshold > 0, and `weightSum >= threshold` [2](#0-1) . It calls `DecodeUtil.addressValid(key.getAddress().toByteArray())` per key [3](#0-2) , but that function only checks that the address is 21 bytes and starts with the correct network prefix byte [1](#0-0) . It never checks whether the address is the all-zero address, whether it belongs to an existing/controllable account, or whether the signer proves ownership of the new key(s) (e.g. via a co-signature from the new key). 

`validate()` in the same actuator likewise only checks `ownerAddress` (the *account being updated*) for validity, not the new permission key addresses' liveness [4](#0-3) . `execute()` then unconditionally applies the new permissions via `account.updatePermissions(...)` [5](#0-4) [6](#0-5) .

Consequently, an account owner (using a single self-signed `AccountPermissionUpdateContract`, i.e. under the existing owner permission threshold) can set the new `Owner` permission's key(s) to `address(0)` (or any address for which nobody holds the private key), with `threshold` still satisfiable on paper (`weightSum >= threshold`), but which no one can ever sign for again. This is the exact structural analog of the reported bug: a single privileged transaction sets a critical control field to an address that provably cannot originate future transactions, permanently freezing subsequent control of the account (its `Owner` permission, and therefore its ability to update its own `Active`/`Witness` permissions or perform any operation gated by the `Owner` permission, such as recovering from the mistake).

Note: this is distinct from the interesting special-case protection in `Manager.resetBlackholeAccountPermission()`, which deliberately sets the black-hole account's owner permission to the zero address as intentional, one-time chain-genesis logic [7](#0-6)  — that is an intentional design choice for the black-hole account specifically, not a general-purpose safeguard preventing normal user accounts from bricking themselves via `AccountPermissionUpdateContract`.

### Impact Explanation
If an account's `Owner` permission keys are set to unreachable addresses, the account permanently loses the ability to execute any transaction that requires `Owner`-level authorization for that account, most notably any future `AccountPermissionUpdateContract` needed to fix the mistake. Any funds, frozen/staked TRX, delegated resources, voting rights, or witness role tied to that account become effectively frozen forever, since no one can produce the signature(s) required to reach the (unreachable) threshold. This matches the "permanent freezing of funds" bar for Medium/High severity established by the analog report.

### Likelihood Explanation
Reaching this state requires the account owner itself to submit a self-signed `AccountPermissionUpdateContract` (an ordinary, unprivileged transaction any account holder can broadcast once multi-sign is enabled via `getAllowMultiSign() == 1`) [8](#0-7) . This can happen accidentally (typo'd address, copy-paste error, or a poorly designed wallet/dApp flow) or could be exploited by a malicious dApp that convinces a user to sign a permission update pointing to an address the dApp controls, or, worst case, that nobody controls at all. There is no confirmation step (e.g., requiring the new key to co-sign) before the permission takes effect.

### Recommendation
In `AccountPermissionUpdateActuator.checkPermission()` (or `validate()`), reject permission keys that are the all-zero address (and optionally addresses with no known/derivable public key), and/or require that at least one key in the new `Owner` permission be able to co-sign the very transaction that installs it, so users cannot atomically transfer control to a key they don't hold. At minimum, explicitly disallow the zero address as a permission key address, mirroring the recommended fix in the analog report (`require(_newOwner != address(0))`).

### Proof of Concept
1. Enable multi-sign (`AllowMultiSign = 1`, already required by `validate()`).
2. Owner account `A` (with default single-key `Owner` permission) submits an `AccountPermissionUpdateContract` self-signed with its current key, setting:
   - `owner` permission: single key = `0x410000000000000000000000000000000000000000` (zero address with TRON prefix byte), `weight = 1`, `threshold = 1`.
   - a valid `active` permission (required for `validate()` to pass).
3. `validate()` passes: `DecodeUtil.addressValid` accepts the zero address as long as it has correct length/prefix `actuator/src/main/java/org/tron/core/actuator/AccountPermissionUpdateActuator.java:105-108` and `common/src/main/java/org/tron/common/utils/DecodeUtil.java:15-33`; `weightSum(1) >= threshold(1)` passes.
4. `execute()` calls `account.updatePermissions(...)`, overwriting `A`'s `Owner` permission with the zero-address key `chainbase/src/main/java/org/tron/core/capsule/AccountCapsule.java:1301-1320`.
5. From this point on, no transaction requiring `A`'s `Owner` permission (including a corrective `AccountPermissionUpdateContract`) can ever be validly signed, since nobody holds the private key for the zero address — `A`'s owner-controlled funds/resources are permanently frozen.

  public static boolean addressValid(byte[] address) {
    if (ArrayUtils.isEmpty(address)) {
      logger.warn("Warning: Address is empty !!");
      return false;
    }

      logger.warn(
          "Warning: Address length need " + ADDRESS_SIZE + " but " + address.length

      return false;
    }

          + address[0] + " !!");
      return false;
    }
    return true;
  }

  private boolean checkPermission(Permission permission) throws ContractValidateException {
    DynamicPropertiesStore dynamicStore = chainBaseManager.getDynamicPropertiesStore();
    if (permission.getKeysCount() > dynamicStore.getTotalSignNum()) {
      throw new ContractValidateException("number of keys in permission should not be greater "
          + "than " + dynamicStore.getTotalSignNum());
    }
    if (permission.getKeysCount() == 0) {
      throw new ContractValidateException("key's count should be greater than 0");
    }
    if (permission.getType() == PermissionType.Witness && permission.getKeysCount() != 1) {
      throw new ContractValidateException("Witness permission's key count should be 1");
    }
    if (permission.getThreshold() <= 0) {
      throw new ContractValidateException("permission's threshold should be greater than 0");
    }
    String name = permission.getPermissionName();
    if (!StringUtils.isEmpty(name) && name.length() > 32) {
      throw new ContractValidateException("permission's name is too long");
    }
    //check owner name ?
    if (permission.getParentId() != 0) {
      throw new ContractValidateException("permission's parent should be owner");
    }

    long weightSum = 0;
    List<ByteString> addressList = permission.getKeysList()
        .stream()
        .map(x -> x.getAddress())
        .distinct()
        .collect(toList());
    if (addressList.size() != permission.getKeysList().size()) {
      throw new ContractValidateException(
          "address should be distinct in permission " + permission.getType());
    }
    for (Key key : permission.getKeysList()) {
      if (!DecodeUtil.addressValid(key.getAddress().toByteArray())) {
        throw new ContractValidateException("key is not a validate address");
      }
      if (key.getWeight() <= 0) {
        throw new ContractValidateException("key's weight should be greater than 0");
      }
      try {
        weightSum = addExact(weightSum, key.getWeight());
      } catch (ArithmeticException e) {
        throw new ContractValidateException(e.getMessage());
      }
    }
    if (weightSum < permission.getThreshold()) {
      throw new ContractValidateException(
          "sum of all key's weight should not be less than threshold in permission " + permission
              .getType());
    }

  @Override
  public boolean validate() throws ContractValidateException {

    if (chainBaseManager == null) {
      throw new ContractValidateException(ActuatorConstant.STORE_NOT_EXIST);
    }

    if (this.any == null) {
      throw new ContractValidateException(ActuatorConstant.CONTRACT_NOT_EXIST);
    }

    AccountStore accountStore = chainBaseManager.getAccountStore();
    DynamicPropertiesStore dynamicStore = chainBaseManager.getDynamicPropertiesStore();

    if (dynamicStore.getAllowMultiSign() != 1) {
      throw new ContractValidateException("multi sign is not allowed, "
          + "need to be opened by the committee");
    }
    if (!this.any.is(AccountPermissionUpdateContract.class)) {
      throw new ContractValidateException(
          "contract type error,expected type [AccountPermissionUpdateContract],real type["
              + any.getClass() + "]");
    }
    final AccountPermissionUpdateContract accountPermissionUpdateContract;
    try {
      accountPermissionUpdateContract = any.unpack(AccountPermissionUpdateContract.class);
    } catch (InvalidProtocolBufferException e) {
      logger.debug(e.getMessage(), e);
      throw new ContractValidateException(e.getMessage());
    }
    byte[] ownerAddress = accountPermissionUpdateContract.getOwnerAddress().toByteArray();
    if (!DecodeUtil.addressValid(ownerAddress)) {
      throw new ContractValidateException("invalidate ownerAddress");
    }
    AccountCapsule accountCapsule = accountStore.get(ownerAddress);
    if (accountCapsule == null) {
      throw new ContractValidateException("ownerAddress account does not exist");
    }

    if (!accountPermissionUpdateContract.hasOwner()) {
      throw new ContractValidateException("owner permission is missed");
    }

    if (accountCapsule.getIsWitness()) {
      if (!accountPermissionUpdateContract.hasWitness()) {
        throw new ContractValidateException("witness permission is missed");
      }
    } else {
      if (accountPermissionUpdateContract.hasWitness()) {
        throw new ContractValidateException("account isn't witness can't set witness permission");
      }
    }

    if (accountPermissionUpdateContract.getActivesCount() == 0) {
      throw new ContractValidateException("active permission is missed");
    }
    if (accountPermissionUpdateContract.getActivesCount() > 8) {
      throw new ContractValidateException("active permission is too many");
    }

    Permission owner = accountPermissionUpdateContract.getOwner();
    Permission witness = accountPermissionUpdateContract.getWitness();
    List<Permission> actives = accountPermissionUpdateContract.getActivesList();

    if (owner.getType() != PermissionType.Owner) {
      throw new ContractValidateException("owner permission type is error");
    }
    checkPermission(owner);
    if (accountCapsule.getIsWitness()) {
      if (witness.getType() != PermissionType.Witness) {
        throw new ContractValidateException("witness permission type is error");
      }
      checkPermission(witness);
    }
    for (Permission permission : actives) {
      if (permission.getType() != PermissionType.Active) {
        throw new ContractValidateException("active permission type is error");
      }
      checkPermission(permission);
    }
    return true;
  }

  public void updatePermissions(Permission owner, Permission witness, List<Permission> actives) {
    Builder builder = this.account.toBuilder();

    owner = owner.toBuilder().setId(0).build();
    builder.setOwnerPermission(owner);
    if (witness != null && builder.getIsWitness()) {
      witness = witness.toBuilder().setId(1).build();
      builder.setWitnessPermission(witness);
    }

    builder.clearActivePermission();
    if (actives != null) {
      for (int i = 0; i < actives.size(); i++) {
        Permission permission = actives.get(i).toBuilder().setId(i + 2).build();
        builder.addActivePermission(permission);
      }
    }

    this.account = builder.build();
  }
