### Title
Single Failing `deposit_coins` in Distribution Loop Permanently Bricks Staking and Vesting Payouts — (`aptos-move/framework/aptos-framework/sources/staking_contract.move`, `vesting.move`)

---

### Summary

`staking_contract::distribute_internal` iterates over every recipient in the distribution pool and calls `aptos_account::deposit_coins` for each one inside a `while` loop with no error handling. If any single deposit aborts — because the recipient's `CoinStore` is frozen or the account has disabled direct coin transfers and is not registered for `AptosCoin` — the entire function reverts. Because `distribute_internal` is a mandatory step called from every critical staking and vesting path (`distribute`, `unlock_stake`, `request_commission`, `update_commission`, and transitively `vesting::distribute` and `vesting::vest`), a single bad recipient permanently bricks all fund flows for the affected staking contract and any vesting contract layered on top of it.

---

### Finding Description

**Root cause in `staking_contract::distribute_internal`** (lines 889–911):

```move
while (distribution_pool.shareholders_count() > 0) {
    let recipients = distribution_pool.shareholders();
    let recipient = recipients[0];
    let current_shares = distribution_pool.shares(recipient);
    let amount_to_distribute =
        distribution_pool.redeem_shares(recipient, current_shares);
    if (recipient == operator) {
        recipient = beneficiary_for_operator(operator);
    };
    aptos_account::deposit_coins(          // <-- aborts if recipient is bad
        recipient, coin::extract(&mut coins, amount_to_distribute)
    );
};
``` [1](#0-0) 

`aptos_account::deposit_coins` has two abort paths relevant here:

1. **Frozen `CoinStore`**: `coin::deposit` aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` if `global<CoinStore<AptosCoin>>(to).frozen` is true.
2. **Direct-transfer disabled + unregistered**: if the account exists, is not registered for `AptosCoin`, and has called `set_allow_direct_coin_transfers(false)`, the assertion at line 124–127 of `aptos_account.move` aborts. [2](#0-1) 

The spec file for `aptos_account` explicitly documents the frozen-store abort:
```
aborts_if if_exist_coin && global<coin::CoinStore<CoinType>>(to).frozen;
``` [3](#0-2) 

**Identical pattern in `vesting::distribute`** (lines 730–740):

```move
shareholders.for_each_ref(|shareholder| {
    ...
    let recipient_address = get_beneficiary(vesting_contract, shareholder);
    aptos_account::deposit_coins(recipient_address, share_of_coins);
});
``` [4](#0-3) 

`vesting::withdraw_stake` calls `staking_contract::distribute`, which calls `distribute_internal`, so the vesting layer is doubly exposed: [5](#0-4) 

**Call graph of blocked functions once `distribute_internal` reverts:**

```
staking_contract::distribute_internal  ← reverts permanently
  ↑ called by staking_contract::distribute        (public entry)
  ↑ called by staking_contract::unlock_stake      (called by vesting::unlock_stake)
  ↑ called by staking_contract::request_commission
  ↑ called by staking_contract::update_commission
  ↑ called by vesting::withdraw_stake → vesting::distribute (public entry)
  ↑ called by vesting::vest (public entry)
``` [6](#0-5) 

---

### Impact Explanation

Once `distribute_internal` is permanently wedged:

- **Staking contract**: `distribute`, `unlock_stake`, `request_commission`, and `update_commission` all revert. The staker can never withdraw unlocked APT; the operator can never collect commission. All APT in the stake pool is permanently frozen.
- **Vesting contract**: `vesting::distribute` and `vesting::vest` both call `withdraw_stake` → `staking_contract::distribute` → `distribute_internal`. They revert on every call. Shareholders can never receive vested APT or staking rewards. `terminate_vesting_contract` also calls `distribute` first, so even admin termination is blocked.

This matches the bounty's in-scope impact: **permanent freezing of APT staking balances and vesting balances**.

---

### Likelihood Explanation

Two realistic trigger paths exist:

**Path A (requires privileged freeze):** The Aptos framework holds `FreezeCapability<AptosCoin>`. If the framework freezes the APT `CoinStore` of any distribution recipient (staker, operator, or vesting beneficiary) — e.g., for regulatory compliance — `coin::deposit` aborts and the loop is permanently stuck.

**Path B (unprivileged):** The operator calls `set_beneficiary_for_operator(new_beneficiary)` where `new_beneficiary` is an address that (a) exists on-chain, (b) has not registered a `CoinStore<AptosCoin>`, and (c) has called `set_allow_direct_coin_transfers(false)`. All three of these are unprivileged operations. The `deposit_coins` assertion at line 124–127 then aborts every time `distribute_internal` runs. [7](#0-6) 

Path B is fully unprivileged: any operator can set their own beneficiary, and any account can disable direct transfers. The combination permanently bricks the staking contract for the staker.

---

### Recommendation

1. **Wrap each `deposit_coins` call in a try/skip pattern**: if a deposit fails, record the unclaimed amount in a per-recipient claimable balance rather than reverting the entire loop. This is the standard "pull-over-push" pattern.
2. **Separate distribution from withdrawal**: allow each recipient to independently claim their share via a dedicated `claim` entry function, so one bad recipient cannot block others.
3. **Validate beneficiary addresses at set-time**: in `set_beneficiary_for_operator` and `vesting::set_beneficiary`, assert that the target address can receive APT (registered and not frozen) before accepting the update.
4. **Add a fallback address**: if deposit to a recipient fails, redirect to a configurable fallback (e.g., the staker's withdrawal address) rather than aborting.

---

### Proof of Concept

1. Deploy a staking contract between staker `S` and operator `O`.
2. Operator `O` calls `set_beneficiary_for_operator(bad_addr)` where `bad_addr` is an account that has called `set_allow_direct_coin_transfers(false)` and has no `CoinStore<AptosCoin>`.
3. Wait for the lockup to expire so stake becomes inactive.
4. Call `staking_contract::distribute(S, O)`.
5. `distribute_internal` enters the while loop, reaches the operator's beneficiary `bad_addr`, calls `aptos_account::deposit_coins(bad_addr, ...)`, which hits the assertion at line 124–127 of `aptos_account.move` and aborts.
6. The entire transaction reverts. The coins remain locked in the stake pool.
7. Every subsequent call to `distribute`, `unlock_stake`, `request_commission`, or `update_commission` for this staking contract reverts identically.
8. If a vesting contract is layered on top, `vesting::distribute` and `vesting::vest` also revert permanently, freezing all shareholders' APT. [8](#0-7) [9](#0-8)

```text
    /// Distribute any withdrawable stake from the stake pool.
    public entry fun distribute(contract_address: address) acquires VestingContract {
        assert_active_vesting_contract(contract_address);

        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        let coins = withdraw_stake(vesting_contract, contract_address);
        let total_distribution_amount = coin::value(&coins);
        if (total_distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };

        // Distribute coins to all shareholders in the vesting contract.
        let grant_pool = &vesting_contract.grant_pool;
        let shareholders = &grant_pool.shareholders();
        shareholders.for_each_ref(|shareholder| {
            let shareholder = *shareholder;
            let shares = pool_u64::shares(grant_pool, shareholder);
            let amount = pool_u64::shares_to_amount_with_total_coins(grant_pool, shares, total_distribution_amount);
            let share_of_coins = coin::extract(&mut coins, amount);
            let recipient_address = get_beneficiary(vesting_contract, shareholder);
            aptos_account::deposit_coins(recipient_address, share_of_coins);
        });

        // Send any remaining "dust" (leftover due to rounding error) to the withdrawal address.
        if (coin::value(&coins) > 0) {
            aptos_account::deposit_coins(vesting_contract.withdrawal_address, coins);
        } else {
            coin::destroy_zero(coins);
        };

        emit(
            Distribute {
                admin: vesting_contract.admin,
                vesting_contract_address: contract_address,
                amount: total_distribution_amount,
            },
        );
    }
