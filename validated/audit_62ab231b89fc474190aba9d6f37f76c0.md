## Title
Graduated partial liquidation curve can push a position's LTV *above* its pre-liquidation level (and toward insolvency) instead of healing it — (File: `mainnet/contracts/market/v0-4-market.clar`)

### Summary
The `liquidate` function computes a graduated liquidation percentage and penalty from the position's current LTV via `calc-liquidation-params`/`calc-liq-factor`/`calc-liq-factor-bound`, intending "partial liquidation" to bring an unhealthy position back toward health without wiping it out, exactly as documented ("Allows targeted debt reduction, Minimizes user losses"). For positions whose LTV sits in the upper portion of the `LTV-LIQ-PARTIAL`→`LTV-LIQ-FULL` band, however, the liquidation-bonus-adjusted collateral seized outweighs the debt repaid enough that the position's LTV *increases* after the liquidation call, the same "spiral" defect described in the referenced report, but occurring in a single call instead of two, and able to push LTV past 100%.

### Finding Description
`calc-liquidation-params` computes, from `current-ltv`: [1](#0-0) 

- `liq-pct-scaled` (fraction `f` of debt to repay) via `calc-liq-factor`/`calc-liq-factor-exp`: [2](#0-1) 
- `liq-penalty` (bonus `p_pct` given to the liquidator), interpolated between `LIQ-PENALTY-MIN` and `LIQ-PENALTY-MAX` using the *same* liquidation fraction: [3](#0-2) 

These feed into `liquidate`, which caps the debt repaid at `max-debt-usd` and seizes collateral equal to `debt-repay * (1 + liq-penalty)`: [4](#0-3) [5](#0-4) 

Modeling the position as collateral value `C`, debt value `D`, `LTV0 = D/C`, liquidated debt fraction `f`, and bonus multiplier `p = 1 + liq-penalty`:

```
D' = D(1 - f)
C' = C - f*D*p
LTV' = D'/C' = LTV0*(1-f) / (1 - f*LTV0*p)
```

For any `f > 0`, `LTV' < LTV0` (i.e., the liquidation improves health) **if and only if** `LTV0 * p < 1`. This condition is independent of `f`, so it applies to both the linear curve (`LIQ-CURVE-EXP = 10000`) and any exponentiated curve.

Using the actual deployed egroup parameters (`LTV-LIQ-PARTIAL=8500`, `LTV-LIQ-FULL=9500`, `LIQ-PENALTY-MIN=500`, `LIQ-PENALTY-MAX=1000`): [6](#0-5) 

- At `LTV0 = 0.85` (just liquidatable): `penalty = 5%`, `LTV0*p = 0.8925 < 1` → position improves.
- At `LTV0 = 0.95` (edge of full-liq): `penalty = 10%`, `LTV0*p = 1.045 > 1` → position **worsens**.

Solving `LTV0*(1 + penalty(LTV0)) = 1` for the linear penalty schedule gives a crossover at `LTV0 ≈ 0.9211` (92.1%). For any `LTV0` between ~92.1% and 95%, calling `liquidate` (even for the "correct" curve-derived amount, or any smaller amount the liquidator chooses) makes the position's LTV *larger* than before the call — the opposite of the intended "minimize user losses" behavior. With the quadratic curve example (`LIQ-CURVE-EXP=20000`) the effect is even sharper: at `LTV0=0.945`, the calculation yields `LTV' ≈ 1.396` (139.6%), i.e. the single partial-liquidation call can drive the position from moderately unhealthy straight past 100% collateralization.

### Impact Explanation
A position pushed past `LTV-LIQ-FULL` (or past 100%) by its own "partial" liquidation immediately becomes fully liquidatable or insolvent. When collateral is fully exhausted, the market's bad-debt socialization path is triggered: [7](#0-6) [8](#0-7) 

Since the socialized deficit is funded by other depositors of the debt vault, this design flaw converts a routine partial liquidation into a mechanism that manufactures bad debt and forces losses onto other lenders — a form of unclaimed-yield/fund freezing/loss for the debt vault's depositors, i.e. temporary/permanent freezing of user funds via forced socialize-debt, consistent with the in-scope impact classes.

### Likelihood Explanation
Any position sitting in the upper part of the partial-liquidation band (LTV between roughly 92% and the `LTV-LIQ-FULL` threshold, exact crossover depending on `LIQ-PENALTY-MAX`/`LIQ-CURVE-EXP`) will exhibit this behavior on the very next ordinary, unprivileged `liquidate` call — no special conditions, flashloans, or privileged access are required, and no liquidator action is "wrong": they are simply following the protocol's own graduated formula. This is a mathematically deterministic consequence of the curve design, not a rare edge case, and price volatility routinely moves positions through this LTV band.

### Recommendation
Redesign the liquidation-percentage/penalty curve so that, for every point in the partial band, the resulting `LTV'` after liquidation is guaranteed to be ≤ `LTV0` (equivalently, ensure `f` is chosen such that `f ≥ 1 - 1/(LTV0*p)` rather than being driven solely by a distance-in-band ratio), or cap `liq-penalty` such that `LTV0 * (1 + liq-penalty) < 1` holds across the entire partial band — e.g., solve for the maximum liquidation bonus admissible at each LTV point instead of using an independent linear/exponential interpolation for penalty and liquidation fraction.

### Proof of Concept
Using egroup parameters `LTV-LIQ-PARTIAL=8500`, `LTV-LIQ-FULL=9500`, `LIQ-PENALTY-MIN=500`, `LIQ-PENALTY-MAX=1000`, `LIQ-CURVE-EXP=10000` (linear, no exponent adjustment needed to demonstrate the flaw):

1. Borrower position: `C` (collateral USD) and `D` (debt USD) such that `LTV0 = D/C = 0.94`.
2. `liq-pct-linear = (0.94-0.85)/(0.95-0.85) = 0.90` → 90% of debt liquidatable this call.
3. `liq-penalty = 0.05 + 0.90*(0.10-0.05) = 0.095` (9.5%).
4. Liquidator calls `liquidate` with `debt-amount` = full 90% of `D` (allowed, since capped at `max-debt-usd`), per `calc-liquidation-params`/`process-debt-asset`: [9](#0-8) 
5. Collateral seized = `0.9*D*1.095 = 0.9855*D`.
6. New debt `D' = 0.1*D`; new collateral `C' = D/0.94 - 0.9855D = 1.0638D - 0.9855D = 0.0783D`.
7. New `LTV' = 0.1D / 0.0783D ≈ 1.277` (127.7%) — the position is now deeply insolvent after a single "partial" liquidation intended to make it healthier, guaranteeing the next call (or the bad-debt path in this same call if collateral is insufficient) forces socialization of the shortfall onto the debt vault's other lenders.

  (ltv-liq-partial uint)
  (ltv-liq-full uint)
  (liq-penalty-min uint)
  (liq-penalty-max uint)
