### No vulnerability found for this question.

**Rationale:** The premise that extensions are granted only a "narrow relay" privilege is not supported by the contract's actual specification. The wallet contract's documented design explicitly states that extensions "have the same full power over the wallet-contract instance as the original signer does" [1](#0-0) , and `check_extension_enabled` is a straightforward set-membership check with no notion of scoped/narrow permissions by design [2](#0-1) .

There is no code path, data structure, or API that ever encodes a "narrow relay-only" extension — `AddExtension` only stores an `AccountId` in a `BTreeSet<AccountId>` [3](#0-2) [4](#0-3) , with no scope, capability list, or purpose tag attached. Once an extension is added, `w_execute_extension` grants it authority to submit *any* `Request` (internal ops and/or external promises) [5](#0-4) [6](#0-5) . This is exactly the documented and intended behavior — the signer who adds an extension is knowingly granting it *full co-equal control*, not a scoped relay right, as confirmed by the test in `crates/wallet/sdk/tests/test.rs` (`rotate`) where the temporary extension is explicitly asserted to be "able to execute requests on behalf of root" after the rotation [7](#0-6) .

There is no equality binding of "privilege granted == narrow intended relay purpose" anywhere in the code or spec to break — the actual binding is "privilege granted == full signer-equivalent control," which holds before and after the scenario described. Adding an extension is itself an action that requires the wallet owner's valid signature (via `w_execute_signed`) or an already-enabled extension's authorization [8](#0-7) ; an unprivileged attacker with no owner key cannot self-add as an extension. This is a documented trust model (README explicitly warns extensions have full power), not an authorization gap, and falls outside the in-scope impact categories (no unauthorized signature bypass, no fund movement without valid authorization — the owner's own signed action is what grants the extension full power, as intended).

    fn execute_signed(&mut self, msg: RequestMessage, proof: &str) -> Result<()> {
        if !self.0.is_signature_allowed() {
            return Err(Error::SignatureDisabled);
        }

        // TODO: change to the following when External Contract Calls land:
        // if !msg.pay_for_gas && env::is_external() {
        //     return Err(Error::UnauthorizedGasPayment);
        // }
        if msg.pay_for_gas {
            env::panic_str("`pay_for_gas` is not currently supported");
        }

        // check chain_id
        if msg.chain_id != env::chain_id() {
            return Err(Error::InvalidChainId);
        }

        // check signer_id
        if msg.signer_id != env::current_account_id() {
            return Err(Error::InvalidSignerId(msg.signer_id));
        }

        // commit the nonce
        self.0
            .nonces
            .commit(msg.nonce, msg.created_at, msg.timeout)?;

        // verify signature
        if !S::verify_request_msg(&self.0.public_key, &msg, proof) {
            return Err(Error::InvalidSignature);
        }

        let hash = msg.hash();
        WalletEvent::SignedRequest { hash }.emit();

        self.execute_request(msg.request, &Actor::SignedRequest(hash))
    }

    fn execute_extension(&mut self, request: Request) -> Result<()> {
        if env::attached_deposit().is_zero() {
            return Err(Error::InsufficientDeposit);
        }

        // check whether extension is enabled
        let extension_id = env::predecessor_account_id();
        self.check_extension_enabled(&extension_id)?;

        // maybe cleanup nonces from the storage as best-effort to make it
        // available for further applying wallet-ops below
        self.0.nonces.check_cleanup();

        self.execute_request(request, &Actor::Extension(extension_id.into()))
    }

    fn add_extension(&mut self, account_id: AccountId, actor: Actor<'_>) -> Result<()> {
        if !self.0.extensions.insert(account_id.clone()) {
            return Err(Error::ExtensionEnabled(account_id));
        }

        WalletEvent::ExtensionAdded {
            account_id: account_id.into(),
            by: actor,
        }
        .emit();

        Ok(())
    }
