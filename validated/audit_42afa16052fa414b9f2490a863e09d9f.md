### Title
Unauthenticated `RecvError` packets allow remote tunnel teardown via UDP source-address spoofing - ([File: outside.go])

### Summary
`header.RecvError` is the one nebula message type that is processed entirely outside of the Noise/AEAD-protected data plane: no certificate, handshake, or AEAD tag is required to have it accepted and acted upon. The only "authentication" applied is a check that the UDP source address of the packet matches the address nebula currently believes the peer is reachable at. Since UDP allows arbitrary source-address spoofing, this check is not a cryptographic guarantee, and an off-path/unauthenticated attacker who can forge packets with a spoofed source address can force a live, authenticated tunnel to be torn down — an unauthenticated header field (`RemoteIndex`) driving destructive state changes, structurally analogous to `payload_type` in the referenced report driving off-chain state without being bound to the signed/authenticated portion of the message.

### Finding Description
`readOutsidePackets` in [1](#0-0)  dispatches `header.RecvError` packets directly to `f.handleRecvError`, before any hostinfo lookup, AEAD decryption, or peer-certificate validation occurs — unlike every other message type, which requires an established `ConnectionState` and passes through `Decrypt`, whose associated data covers the full 16-byte header [2](#0-1) .

`handleRecvError` itself performs no cryptographic verification of the packet at all: [3](#0-2) 

The only defense is comparing the packet's source `addr` to `hostinfo.GetRemote()`. If they match, the tunnel is unconditionally torn down (`f.closeTunnel(hostinfo)`) and the pending handshake state is deleted. The `h.RemoteIndex` field used to look up the target hostinfo, and the packet's `Type`/fields in general, are attacker-supplied and carry no signature, HMAC, or AEAD tag tying them to the legitimate session — the log message "Someone spoofing recv_errors?" at line 565 shows the developers were aware spoofing is the only real threat model here, yet the mitigation is limited to a source-address string compare, which is not resistant to IP/UDP source spoofing.

This is the same bug class as the audit finding: a field that influences system behavior (there, an event `payload_type` read by off-chain systems; here, a `RemoteIndex`/source-address pair that triggers destructive local state mutation) is not bound into any cryptographic authentication mechanism, so any party who can put the "right" values on the wire — without holding a CA-signed certificate or having completed a handshake — can manipulate protected state.

### Impact Explanation
An attacker who can spoof a UDP packet's source address to match a victim's currently-known remote endpoint (trivial on networks without BCP38 egress filtering, or achievable by an attacker that can observe/infer the real remote's `ip:port`, e.g. via NAT-traversal or lighthouse queries) and guesses/observes a valid `RemoteIndex` can force `closeTunnel` and `handshakeManager.DeleteHostInfo` on a fully established, otherwise-authenticated tunnel. This is a remote state-poisoning / denial-of-service primitive reachable by an attacker holding no certificate and having never completed a handshake, since `RecvError` bypasses all AEAD/cert checks that protect every other packet type.

### Likelihood Explanation
Exploitability depends on (a) the operator's `acceptRecvErrorConfig`/`sendRecvErrorConfig` policy for the source address (gated via `ShouldRecvError`), and (b) the attacker's ability to spoof the legitimate peer's UDP source address and know/guess the correct `RemoteIndex`. On networks that do not filter spoofed source IPs (still common), and where the `RemoteIndex` can be inferred from prior observed traffic, this is a realistic off-path DoS vector; it is comparable in severity terms to the reference issue's "unfinished/incorrect state accepted due to unauthenticated field."

### Recommendation
Do not allow a completely unauthenticated packet type to mutate live tunnel/hostmap state. Either:
- Bind `RecvError` messages to the current session (e.g., require them to include an AEAD tag verifiable with the existing session key, similar to how relay messages are integrity protected via `VerifyRelay`), or
- Treat address match as advisory-only and require additional corroboration (e.g., only downgrade to "pending" and re-verify via a fresh handshake/liveness probe rather than immediately deleting hostinfo), removing the ability for a single spoofed UDP datagram to unilaterally tear down a tunnel.

### Proof of Concept
1. Establish a legitimate tunnel between host A and host B; A believes B's remote endpoint is `B_ip:B_port`, keyed by some `RemoteIndex` value R (learned by an attacker who observes prior handshake/traffic metadata, or via reconnection patterns).
2. From attacker-controlled infrastructure (or any host capable of source-IP spoofing on the path), craft a bare header-only UDP packet with `Type = header.RecvError`, `RemoteIndex = R`, and source address spoofed to `B_ip:B_port`, and send it to A's listening UDP port — no certificate, handshake, or key material is required, per [1](#0-0) .
3. A's `handleRecvError` finds the matching hostinfo via `QueryReverseIndex(R)`, sees the spoofed address matches `hostinfo.GetRemote()`, and calls `f.closeTunnel(hostinfo)` plus `handshakeManager.DeleteHostInfo(hostinfo)`, per [4](#0-3) , tearing down the legitimate, previously-authenticated tunnel without the attacker ever possessing a certificate or completing a handshake.

```go
func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
```
