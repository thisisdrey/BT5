### Title
Unverified public-key re-key in `Some(_)` branch of `validate_handshake` allows unauthenticated peer-identity takeover of a conversation slot - ([File: stackslib/src/net/chat.rs])

### Summary
`ConversationP2P::validate_handshake` only calls `message.verify_secp256k1(&handshake_data.node_public_key)` when `self.connection.get_public_key()` is `None`. Once a public key is already known for the conversation (`Some(_)` branch), the function performs no signature check at all against the new `node_public_key` (it only optionally checks the claimed address/port for outbound connections), so `update_from_handshake_data` installs whatever `node_public_key` the remote peer claims without any proof the message was signed by that key.

### Finding Description
The claimed equality "installed peer public key == the key that signed this handshake" holds only for the very first handshake (`None` branch), where `message.verify_secp256k1(&handshake_data.node_public_key)` is enforced: [1](#0-0) 

For every subsequent handshake on the same conversation slot (`Some(_)` branch), the only check performed is an address/port match, and it is gated on `self.stats.outbound`, meaning it doesn't even apply to inbound connections that a remote unprivileged attacker initiates: [2](#0-1) 

The remaining checks in `validate_handshake` (public-key format validity, expiry, and "not from myself") never verify the signature binds to `handshake_data.node_public_key`: [3](#0-2) 

`handle_handshake` calls `validate_handshake` and then unconditionally calls `update_from_handshake_data`, which takes `handshake_data.node_public_key` verbatim and calls `self.connection.set_public_key(Some(pubk.clone()))`, with no re-verification step in between: [4](#0-3) [5](#0-4) 

The `!authenticated && disable_inbound_handshakes` gate at the top of `handle_handshake` does not compensate: it can only ever prove the message was *not* signed by the *old* key (or is simply disabled), never that it *was* signed by the *new*, self-reported key: [6](#0-5) 

Exploit flow: an attacker opens an inbound P2P connection to the target node. They perform a first legitimate handshake, signed with private key A, so `self.connection.get_public_key()` becomes `Some(A)` (this is the normal, non-privileged code path — no secret or role needed). They then send a second `Handshake` message whose preamble signature is still produced with key A (or is even simply invalid/garbage), but whose `HandshakeData.node_public_key` field is set to an arbitrary key `B` (of valid secp256k1 format, with any acceptable `expire_block_height`) that the attacker does not control the private key for. Because the `Some(_)` branch of `validate_handshake` never calls `verify_secp256k1` against `B`, the message passes validation, and `update_from_handshake_data` installs `B` as the conversation's trusted public key — a cryptographic identity the attacker never proved possession of.

### Impact Explanation
The node's in-memory `ConversationP2P::connection` public key for that conversation slot — which is used throughout `chat.rs`/`p2p.rs` for peer identification, `to_neighbor_key()`, authenticated-message gating, and (for outbound conversations) written to `PeerDB` via `Neighbor::load_and_update`/`save_update` — can be set to a key the remote party does not control. This breaks the "installed pubkey == signer of the accepted handshake" invariant and lets an attacker claim an arbitrary peer identity (e.g., the pubkey hash of a trusted/allow-listed neighbor) for their own connection slot without holding that key, i.e., unauthenticated peer-identity takeover of a conversation slot. This is repeatable per connection/slot and requires only a TCP connection to the P2P port plus two crafted messages — matching the Critical "unauthenticated identity takeover" category in scope.

### Likelihood Explanation
No privileged role, secret, or special state is required: any remote party can open a P2P connection, complete an ordinary first handshake (learning `Some(pubkey)`), and then send one additional handshake with a spoofed `node_public_key`. Both steps are ordinary reachable P2P messages, cost is negligible (two signed messages), and the attack is repeatable against any conversation slot the attacker controls.

### Recommendation
In the `Some(_)` branch of `validate_handshake`, always call `message.verify_secp256k1(&handshake_data.node_public_key)` (in addition to the existing address check) before allowing `update_from_handshake_data` to overwrite the connection's public key, so a re-key handshake is only accepted when it is actually signed by the new key it claims to install.

### Proof of Concept
Add a test in `stackslib/src/net/chat.rs`'s test module modeled on `convo_handshake_badsignature`/the re-keying test near line 4890:
1. Create `convo_1`/`convo_2` with no known public keys, as in existing tests.
2. Perform a normal handshake from `local_peer_1` (key `A`) to `convo_2`, and assert `convo_2.connection.get_public_key() == Some(A)`.
3. Craft a second `Handshake` message with `HandshakeData.node_public_key` set to a fresh, unrelated key `B` (attacker does not sign with `B`'s private key — sign with `A`, or with garbage bytes), send it to `convo_2` via `convo_send_recv`, and call `convo_2.chat(...)`.
4. Assert that `convo_2.connection.get_public_key()` becomes `Some(B)` even though no message was ever signed by `B`'s private key — this demonstrates the missing `verify_secp256k1(&B)` check at `stackslib/src/net/chat.rs:1072-1091`, compared to the explicit check present in the `None` branch at lines 1058-1070.

    pub fn update_from_handshake_data(
        &mut self,
        preamble: &Preamble,
        handshake_data: &HandshakeData,
    ) -> Result<bool, net_error> {
        let pubk = handshake_data
            .node_public_key
            .to_public_key()
            .map_err(|e| net_error::DeserializeError(e.into()))?;

        self.peer_version = preamble.peer_version;
        self.peer_network_id = preamble.network_id;
        self.peer_services = handshake_data.services;
        self.peer_expire_block_height = handshake_data.expire_block_height;
        self.handshake_addrbytes = handshake_data.addrbytes.clone();
        self.handshake_port = handshake_data.port;
        self.data_url = handshake_data.data_url.clone();

        let mut updated = false;
        let cur_pubk_opt = self.connection.get_public_key();
        if let Some(cur_pubk) = cur_pubk_opt {
            if pubk != cur_pubk {
                debug!(
                    "{:?}: Upgrade key {:?} to {:?} expires {:?}",
                    &self,
                    &to_hex(&cur_pubk.to_bytes_compressed()),
                    &to_hex(&pubk.to_bytes_compressed()),
                    self.peer_expire_block_height
                );
                updated = true;
            }
        }

        self.connection.set_public_key(Some(pubk.clone()));

        Ok(updated)
    }
