The finding below is scoped to the C++ `ijar` zip reader that ships in the repo and is compiled as part of Bazel.

### Title
Out-of-bounds read parsing untrusted ZIP central directory entries in ijar - (File: third_party/ijar/zip.cc)

### Summary
`InputZipFile::ProcessCentralDirEntry` in `third_party/ijar/zip.cc` parses the ZIP central directory of an input file without any bounds checking, unlike its sibling `ProcessLocalFileEntry`, which explicitly calls `EnsureRemaining()` before every read. A crafted `file_name_length`, `extra_field_length`, `file_comment_length`, or ZIP64 extra-field `data_size` can advance the parsing cursor past the end of the mmap'd input buffer, causing subsequent `get_u2le`/`get_u4le`/`get_u8le`/`memcpy` reads to dereference out-of-bounds memory.

### Finding Description
`ProcessLocalFileEntry` guards every read with `EnsureRemaining(n, "state")`, which checks the remaining bytes in the mmap'd file before advancing the pointer [1](#0-0) .

By contrast, `ProcessCentralDirEntry` — which reads the signature, sizes, `file_name_length`, `extra_field_length`, `file_comment_length`, attribute/offset fields, and then the filename bytes and extra-field records — performs none of these checks: it blindly advances `p` by attacker-controlled length fields and `memcpy`s `file_name_length` bytes from `p` [2](#0-1) .

In particular, the ZIP64 extra-field loop is unbounded relative to the actual input buffer:
```
const u1 *extra_p = p;
p += extra_field_length;
while (extra_p != p) {
  const u2 header_id = get_u2le(extra_p);
  const u2 data_size = get_u2le(extra_p);
  const u1 *extra = extra_p;
  extra_p += data_size;
  ...
}
``` [3](#0-2) 

If `data_size` values don't sum exactly to `extra_field_length`, `extra_p` can run past `p` and the loop keeps calling `get_u2le`/`get_u8le` on `extra_p`, reading further and further outside the mapped file — an out-of-bounds read, structurally analogous to the openjpeg `pi.c` case where attacker-controlled header counts drive array/pointer traversal past the intended bounds. This method is invoked both while iterating entries (`ProcessNext` → `ProcessCentralDirEntry`) and while computing output size (`CalculateOutputLength`) [4](#0-3) [5](#0-4) .

### Impact Explanation
`ZipExtractor`/`InputZipFile` is the entry point for reading zip/jar files supplied to the `ijar`/`zip_main` command-line tools and internal callers such as `PartialZipExtractor` in `src/main/cpp/archive_utils.cc` [6](#0-5) . A hostile origin serving a crafted jar/zip (e.g. via `http_jar`/`java_import`-style remote dependency fetch) that is later processed by this reader can trigger reads past the mapped file, causing a crash (denial of availability for the build) or, depending on memory layout, leaking adjacent heap/mmap bytes into computed lengths — consistent with the CVSS 3.1 vector of the reference CVE (`C:N/I:N/A:H`, availability-impacting OOB read).

### Likelihood Explanation
`ProcessCentralDirEntry` is reachable purely from the bytes of an attacker-supplied zip/jar file — no privileged access is required, and the code path runs on every entry in the central directory. Because there is no analog of `EnsureRemaining` here (in contrast to `ProcessLocalFileEntry`, which was clearly hardened against this class of bug), any malformed length field is sufficient to trigger the issue, making it comparatively easy to hit non-deterministically (crash) but that overrun extent to a specific readable secret would depend on heap layout.

### Recommendation
Add the same `EnsureRemaining()`-style bounds checks used in `ProcessLocalFileEntry` to `ProcessCentralDirEntry`, validating `file_name_length`, `extra_field_length`, `file_comment_length`, and each extra-field `data_size` against the actual remaining central-directory/file bytes before advancing pointers or performing reads, and bound the `while (extra_p != p)` loop so it cannot run past `p`.

### Proof of Concept
A JUnit/C++ style reproduction (conceptually, since this is C++, a `gtest`/shell test under `src/test/shell` invoking `ijar`'s `unzip`/`zip_main` on a crafted archive) would:
1. Construct a minimal ZIP file with a valid End-Of-Central-Directory record but a central directory entry whose `extra_field_length` is non-zero and whose embedded extra-field `data_size` value does not sum to `extra_field_length` (e.g., declares `data_size = 0xFFFF` while only a few bytes remain in the file).
2. Invoke `devtools_ijar::ZipExtractor::Create()` / `ProcessAll()` (as done in `third_party/ijar/zip_main.cc`'s `extract()`) on this file.
3. Observe (under ASan/valgrind) an out-of-bounds read as `ProcessCentralDirEntry`'s extra-field loop walks `extra_p` past the mmap'd region, or a crash on unmapped memory access, whereas a well-formed file with matching lengths parses successfully. [7](#0-6)

bool InputZipFile::ProcessCentralDirEntry(const u1 *&p, u8 *compressed_size,
                                          u8 *uncompressed_size, char *filename,
                                          size_t filename_size, u4 *attr,
                                          u8 *offset) {
  u4 signature = get_u4le(p);

  if (signature != CENTRAL_FILE_HEADER_SIGNATURE) {
    if (signature != DIGITAL_SIGNATURE && signature != EOCD_SIGNATURE &&
        signature != ZIP64_EOCD_SIGNATURE) {
      error("invalid central file header signature: 0x%x\n", signature);
    }
    return false;
  }

  p += 16;  // skip to 'compressed size' field
  *compressed_size = get_u4le(p);
  *uncompressed_size = get_u4le(p);
  u2 file_name_length = get_u2le(p);
  u2 extra_field_length = get_u2le(p);
  u2 file_comment_length = get_u2le(p);
  p += 4;  // skip to external file attributes field
  *attr = get_u4le(p);
  *offset = get_u4le(p);
  {
    size_t len = (file_name_length < filename_size)
      ? file_name_length
      : (filename_size - 1);
    memcpy(reinterpret_cast<void*>(filename), p, len);
    filename[len] = 0;
  }
  p += file_name_length;
  const u1 *extra_p = p;
  p += extra_field_length;
  while (extra_p != p) {
    const u2 header_id = get_u2le(extra_p);
    const u2 data_size = get_u2le(extra_p);
    const u1 *extra = extra_p;
    extra_p += data_size;
    if (header_id == ZIP64_EXTRA_FIELD_TAG) {
      if (*uncompressed_size == U4_MAX) {
        *uncompressed_size = get_u8le(extra);
      }
      if (*compressed_size == U4_MAX) {
        *compressed_size = get_u8le(extra);
      }
      if (*offset == U4_MAX) {
        *offset = get_u8le(extra);
      }
    }
  }
  p += file_comment_length;
  return true;
}

u8 InputZipFile::CalculateOutputLength() {
  const u1* current = central_dir_;

  u8 compressed_size = 0;
  u8 uncompressed_size = 0;
  u8 skipped_compressed_size = 0;
  u4 attr;
  u8 offset;
  char filename[PATH_MAX];

  while (true) {
    u8 file_compressed, file_uncompressed;
    if (!ProcessCentralDirEntry(current,
                                &file_compressed, &file_uncompressed,
                                filename, PATH_MAX, &attr, &offset)) {
      break;
    }

    if (processor->Accept(filename, attr)) {
      compressed_size += (u8) file_compressed;
      uncompressed_size += (u8) file_uncompressed;
    } else {
      skipped_compressed_size += file_compressed;
    }
  }

  // The worst case is when the output is simply the input uncompressed. The
  // metadata in the zip file will stay the same, so the file will grow by the
  // difference between the compressed and uncompressed sizes.
  return (u8) input_file_->Length() - skipped_compressed_size
      + (uncompressed_size - compressed_size);
}

// Execute the extraction (or just listing if just v is provided)
int extract(char *zipfile, char *exdir, char **files, bool verbose,
            bool extract, bool flatten) {
  std::string cwd = get_cwd();
  if (cwd.empty()) {
    return -1;
  }

  char output_root[PATH_MAX + 1];
  if (exdir != NULL) {
    if (!concat_path(output_root, sizeof(output_root), cwd.c_str(), exdir)) {
      return -1;
    }
  } else if (cwd.length() >= sizeof(output_root)) {
    fprintf(stderr, "current working directory path too long");
    return -1;
  } else {
    memcpy(output_root, cwd.c_str(), cwd.length() + 1);
  }

  UnzipProcessor processor(output_root, files, verbose, extract, flatten);
  std::unique_ptr<ZipExtractor> extractor(ZipExtractor::Create(zipfile,
                                                               &processor));
  if (extractor == NULL) {
    fprintf(stderr, "Unable to open zip file %s: %s.\n", zipfile,
            strerror(errno));
    return -1;
  }

  if (extractor->ProcessAll() < 0) {
    fprintf(stderr, "%s.\n", extractor->GetError());
    return -1;
  }
  return 0;
}
