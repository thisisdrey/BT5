### Title
Priority-floor sigverify bypass via unparseable compute-budget packets - ([File: core/src/sigverify.rs])

### Summary
The scheduler-published priority floor (`apply_priority_floor_to_batch` in `core/src/sigverify.rs`) is meant to let sigverify workers cheaply drop low-value packets before spending CPU on `ed25519_verify_serial` once the leader banking buffer is saturated. However, any packet whose priority cannot be computed by `calculate_priority_from_bytes` (`core/src/transaction_priority.rs`) — e.g. because its compute-budget instructions fail sanitization — is unconditionally kept (`any_kept = true`) regardless of the floor, so it still undergoes full, expensive `ed25519_verify_serial` work.

### Finding Description
`SigVerifyWorkerPool::run_transaction_task` (`core/src/sigverify.rs:266-345`) runs dedup, then (if a nonzero floor is published, `state.priority_floor`) calls `apply_priority_floor_to_batch`, and only afterward runs `sigverify::ed25519_verify_serial` on whatever remains in the batch.

`apply_priority_floor_to_batch` (`core/src/sigverify.rs:413-440`) computes priority per packet via `calculate_priority_from_bytes(bank, data)`. It only discards a packet when `calculate_priority_from_bytes` returns `Some(priority) if priority <= floor`. In every other branch — including `None` — the packet is left in the batch (`any_kept = true`), explicitly documented as "Unparseable packets are kept and left for downstream rejection."

`calculate_priority_from_bytes` (`core/src/transaction_priority.rs:73-88`) returns `None` whenever `SanitizedTransactionView::try_new_sanitized` fails to parse, or `transaction_configuration()` fails. The latter happens whenever `ComputeBudgetInstructionDetails::try_from` / `sanitize_and_convert_to_compute_budget_limits` rejects the compute-budget instructions (e.g. duplicate `ComputeBudgetInstruction::set_compute_unit_price`/`set_compute_unit_limit` instructions), as shown by the `TransactionConfiguration`/`VersionedTransactionConfiguration` logic in `runtime-transaction/src/transaction_meta.rs:93-178`.

Crucially, none of these checks depend on signature validity. An attacker fully controls the message bytes and holds the signing keypair, so they can craft a legacy/v0 transaction containing two conflicting `ComputeBudgetInstruction` entries, sign it correctly (a cryptographically valid ed25519 signature over arbitrary attacker-chosen bytes costs the attacker only client-side compute), and send it to the leader's TPU. When the scheduler publishes a nonzero floor during saturation (`SchedulerController::update_scheduler_priority_floor`, `core/src/banking_stage/transaction_scheduler/scheduler_controller.rs:338-352`), this crafted packet's priority computation returns `None` in `apply_priority_floor_to_batch`, so it is never discarded and is passed straight into `ed25519_verify_serial`, consuming full server-side signature-verification CPU. The transaction will ultimately still fail later at `translate_to_runtime_view`/`try_handle_packet` (`core/src/banking_stage/transaction_scheduler/receive_and_buffer.rs:370-405`) with `PacketHandlingError::ComputeBudget`, but only after the expensive verification has already run.

### Impact Explanation
This defeats exactly the mitigation `apply_priority_floor_to_batch`/`SchedulerPriorityFloor` was added to provide: shedding cheap-to-produce, worthless-priority packets ahead of the expensive `ed25519_verify_serial` pass during the precise saturation window (`SATURATION_BUFFER_PCT = 99`) when the leader is already CPU-constrained. An unstaked, unprivileged remote sender can force full signature-verification CPU work per packet for a fee/cost that is effectively zero, degrading leader sigverify throughput below intended cost — matching "grossly underpriced pre-fee work" / QoS-evasion category described in scope.

### Likelihood Explanation
Fully feasible without any staked/privileged access: the attacker only needs (1) enough packet volume to saturate the banking buffer to ≥99% (already assumed precondition/attacker-achievable via cheap packet floods, same mechanism as scoped), and (2) trivially-crafted, self-signed transactions with duplicate compute-budget instructions. No special timing, no cluster state manipulation, and it's fully repeatable per packet as long as saturation persists.

### Recommendation
Make `apply_priority_floor_to_batch` fail-closed instead of fail-open for packets whose priority cannot be computed once a floor is active: e.g. treat `calculate_priority_from_bytes == None` (parse/compute-budget-sanitization failures) as priority `0` (or otherwise ≤ floor) for the purpose of the floor comparison, dropping them just like legitimate zero-priority packets, since they are already known to be rejected downstream and there is no benefit to spending sigverify CPU on them.

```rust
#[test]
fn floor_bypass_via_unparseable_compute_budget() {
    let (bank, mint) = test_bank_with_lamports_per_signature(5_000);

    // Craft a transaction with duplicate compute-budget instructions so
    // ComputeBudgetInstructionDetails::try_from fails sanitization, while
    // producing a fully valid ed25519 signature.
    let to = Pubkey::new_unique();
    let transfer = system_instruction::transfer(&mint.pubkey(), &to, 1);
    let dup_price_1 = ComputeBudgetInstruction::set_compute_unit_price(1);
    let dup_price_2 = ComputeBudgetInstruction::set_compute_unit_price(2); // duplicate -> sanitize error
    let message = Message::new(&[transfer, dup_price_1, dup_price_2], Some(&mint.pubkey()));
    let tx = Transaction::new(&[&mint], message, bank.last_blockhash());
    let bytes = bincode::serialize(&VersionedTransaction::from(tx)).unwrap();

    // Priority computation must fail (returns None) due to duplicate compute-budget ixs.
    assert!(calculate_priority_from_bytes(&bank, &bytes).is_none());

    // Build a PacketBatch containing this packet and run it through
    // apply_priority_floor_to_batch with a high floor (simulating saturation).
    let mut batch = make_packet_batch_from_bytes(&[bytes]); // test helper wrapping into PacketBatch
    let floor = u64::MAX; // any legitimate priced tx would be dropped at this floor
    let (dropped, all_below) = apply_priority_floor_to_batch(&mut batch, floor, &bank);

    // Assert the crafted packet was NOT dropped despite the floor being maximal,
    // proving it will proceed to full ed25519_verify_serial downstream.
    assert_eq!(dropped, 0);
    assert!(!all_below);
    assert!(!batch.iter().next().unwrap().meta().discard());
}
```

```rust
fn apply_priority_floor_to_batch(
    batch: &mut PacketBatch,
    floor: u64,
    bank: &Bank,
) -> (usize, bool) {
    let mut dropped: usize = 0;
    let mut any_kept = false;
    for mut packet in batch.iter_mut() {
        if packet.meta().discard() {
            continue;
        }
        let Some(data) = packet.data(..) else {
            // Zero-length or otherwise unreadable: leave to downstream
            // stages to reject.
            any_kept = true;
            continue;
        };
        // Unparseable packets are kept and left for downstream rejection.
        match calculate_priority_from_bytes(bank, data) {
            Some(priority) if priority <= floor => {
                packet.meta_mut().set_discard(true);
                dropped = dropped.saturating_add(1);
            }
            _ => any_kept = true,
        }
    }
    (dropped, !any_kept)
}
```

```rust
/// Evaluate raw packet bytes against the pf-floor, returning the computed
/// priority.
///
/// Returns `None` if the bytes don't parse as a valid transaction, in which
/// case the caller should leave the packet to downstream stages to reject.
pub(crate) fn calculate_priority_from_bytes(bank: &Bank, data: &[u8]) -> Option<u64> {
    let view = SanitizedTransactionView::try_new_sanitized(data, &sanitize_config()).ok()?;
    let runtime_tx = RuntimeTransaction::<SanitizedTransactionView<_>>::try_new(
        view,
        MessageHash::Compute,
        None,
    )
    .ok()?;
    let transaction_configuration = runtime_tx
        .transaction_configuration(&bank.feature_set)
        .ok()?;
    let (priority, _cost) =
        calculate_priority_and_cost(bank, &runtime_tx, &transaction_configuration);

    Some(priority)
}
```

```rust
    /// Update the scheduler priority floor.
    ///
    /// Semantics: when the retained scheduler buffer is nearly full, drop
    /// arrivals that are at-or-below the current queue-min priority, i.e. no
    /// better than what the bounded scheduler candidate set would evict.
    fn update_scheduler_priority_floor(&mut self, num_dropped_on_capacity: usize) {
        let buffer_size = self.container.buffer_size();
        let saturated = self
            .saturation_state
            .update(buffer_size, num_dropped_on_capacity);
        let priority_floor = if saturated {
            self.container
                .get_min_max_priority()
                .map_or(0, |(min, _)| min)
        } else {
            0
        };

        self.saturation_state.publish_floor(priority_floor);
    }
```
