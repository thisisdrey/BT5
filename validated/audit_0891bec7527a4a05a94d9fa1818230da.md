### Title
Unstaked attacker can exhaust the shared, pre-handshake `ClientConnectionTracker` permit pool by never completing the QUIC/TLS handshake, causing `incoming.refuse()` for legitimate (including staked) peers - (File: `streamer/src/nonblocking/quic.rs`)

### Summary
The QUIC accept loop reserves a `ClientConnectionTracker` permit for every incoming connection attempt **before** the TLS/QUIC handshake completes and **before** the peer's staked/unstaked identity is known, and only releases that permit when `setup_connection`'s `timeout(QUIC_CONNECTION_HANDSHAKE_TIMEOUT, connecting)` resolves. The two admission checks that run before the permit is taken (`overall_connection_rate_limiter` and per-IP `rate_limiter`) are non-consuming "peek" checks for unconfirmed peers, so an attacker who never finishes the handshake is not charged by either limiter and can keep re-acquiring/holding permits indefinitely.

### Finding Description
In the accept loop (`run_server`), for each `incoming` connection the server:
1. Peeks (does not consume) the global token bucket: `overall_connection_rate_limiter.current_tokens() == 0` [1](#0-0) 
2. Peeks (does not consume) the per-IP limiter: `rate_limiter.is_allowed(&incoming.remote_address().ip())` [2](#0-1) 
3. Acquires a `ClientConnectionTracker` slot bounded by `qos.max_concurrent_connections()`; on failure it calls `incoming.refuse()` [3](#0-2) 

`ClientConnectionTracker::new` is a simple atomic counter check (`stats.open_connections`), and the permit is only released on `Drop` [4](#0-3) .

The permit is held across `setup_connection`, which does `timeout(QUIC_CONNECTION_HANDSHAKE_TIMEOUT, connecting).await` where `QUIC_CONNECTION_HANDSHAKE_TIMEOUT = Duration::from_secs(2)` (the server-side constant, distinct from the client-side 60s constant in `quic-client`) [5](#0-4) [6](#0-5) . Only after the handshake succeeds does the code call `rate_limiter.register_connection` and `overall_connection_rate_limiter.consume_tokens`, which are the only calls that actually decrement either limiter [7](#0-6) . This is confirmed by `ConnectionRateLimiter::is_allowed`, which returns `true` for any IP that has no existing (i.e., previously *confirmed*) bucket entry, and only `register_connection` consumes tokens [8](#0-7) . The code comment explicitly documents this tradeoff: checks before IP is "control-asserted" (i.e., before handshake) are intentionally weak to avoid spoofing-based attacks between peers, relying only on the timeout + global "shed fast" policy [9](#0-8) .

Consequently, an attacker who opens QUIC connections and deliberately stalls the handshake (e.g., sends only an Initial packet and never advances the crypto handshake) is never actually rate-limited by either the global or per-IP token buckets — those only fire once tokens are fully depleted from *confirmed* connections, which never happens for stalled attempts. The only thing bounding stalled connections is the shared `max_concurrent_connections` pool, which is also used for legitimate staked and unstaked peers alike, since staked/unstaked classification (via `get_connection_stake`) happens only *after* a successful handshake, inside `setup_connection` [10](#0-9) . `SimpleQos::max_concurrent_connections` only reserves a fixed 25% headroom over `max_staked_connections` for legitimate in-flight handshakes [11](#0-10) , an amount trivially exceeded by a deliberate attacker.

By continuously cycling: open just over `max_concurrent_connections` stalled connections, hold each for up to 2 seconds (until the internal handshake timeout expires and the tracker is dropped), then immediately reopen from new ephemeral ports, an attacker can keep the shared pool saturated indefinitely, causing `ClientConnectionTracker::new` to fail and `incoming.refuse()` to fire for legitimate new connection attempts (staked or unstaked) at line 377.

### Impact Explanation
This is a network-wide-reachable DoS against a leader's TPU port: an unprivileged attacker can deny admission of new legitimate TPU/QUIC connections (including from staked validators forwarding transactions) for the duration of the attack, by exhausting the finite, peer-type-agnostic `ClientConnectionTracker` slot pool with handshakes that are never completed. This falls into the "unbounded resource consumption / node DoS via ingress" bounty category — the admission of new connections is not actually bounded fairly against attacker volume, contrary to the intended invariant.

### Likelihood Explanation
Feasible and repeatable with no privileges: the attacker only needs the ability to open UDP/QUIC connections to the TPU port and to withhold subsequent handshake packets, which is standard unprivileged network client behavior. The attack requires no staked keys, no leader/gossip control, and no server misconfiguration — it exploits the intrinsic design choice that pre-handshake admission checks are non-consuming and identity-agnostic. The attack is cheap: it needs only `~max_concurrent_connections` simultaneous stalled sockets, refreshed roughly every 2 seconds.

### Recommendation
Rate-limit or cost-charge stalled/incomplete handshake attempts as well, not only confirmed ones — e.g., consume (not just peek) global/per-IP tokens at the time a `ClientConnectionTracker` permit is granted (pre-handshake), refunding on graceful/verified completion if desired. Additionally, consider reserving separate, smaller pools for pending (unauthenticated) vs. established connections so that flooding pending-handshake slots cannot fully starve the admission of already-verified/staked traffic, and/or making the pending-handshake pool size scale down under sustained saturation (adaptive shedding) rather than being a fixed 25% headroom.

### Proof of Concept
Integration test plan (using existing test scaffolding in `streamer/src/nonblocking/quic.rs`'s `test` module and `testing_utilities::setup_quic_server` / `spawn_stake_weighted_qos_server`):
1. Start a QUIC server via `spawn_stake_weighted_qos_server` and capture `max_concurrent_connections` from `SpawnNonBlockingServerResult` (as already exposed in test code, e.g. `streamer/src/nonblocking/quic.rs:1596-1630`).
2. Spawn `max_concurrent_connections` raw UDP sockets, each sending a single crafted valid QUIC Initial packet to the server address and then sending no further packets (never completing the crypto handshake). Confirm via `stats.open_connections`/`stats.total_incoming_connection_attempts` that all attempts are admitted (tracker acquired) rather than refused.
3. Concurrently, attempt a legitimate `make_client_endpoint` connection (full valid handshake) and assert it is refused (`ConnectionError::ApplicationClosed`/`incoming.refuse()` observed via `stats.refused_connections_too_many_open_connections` incrementing) while the stalled connections are outstanding.
4. Assert that once `QUIC_CONNECTION_HANDSHAKE_TIMEOUT` (2s) elapses and slots free up momentarily, but that continuously re-issuing stalled Initial packets from fresh ports keeps `stats.refused_connections_too_many_open_connections` incrementing for new legitimate attempts over an extended window, demonstrating sustained denial rather than a one-off race.

    /// create ClientConnectionTracker and increment open connection count. Otherwise returns Err
    fn new(stats: Arc<StreamerStats>, max_concurrent_connections: usize) -> Result<Self, ()> {
        let open_connections = stats.open_connections.fetch_add(1, Ordering::Relaxed);

            debug!(
                "There are too many concurrent connections opened already: open: \
                 {open_connections}, max: {max_concurrent_connections}"
            );

    /// Check if the connection from the said `ip` is allowed.
    /// Here we assume that only IPs with actual confirmed connections are stored in it,
    /// since we should only modify server state once source IP is verified
    pub fn is_allowed(&self, ip: &IpAddr) -> bool {
        // Check if we have records in the rate limiter for the given IP address
        match self.limiter.current_tokens(ip) {
            Some(r) => r > 0, // we have a record, and rate is not exceeded
            None => true,     // if we have not seen IP, allow connection request
        }
    }

    pub fn register_connection(&self, ip: &IpAddr) -> bool {
        if self.limiter.consume_tokens(*ip, 1).is_ok() {
            debug!("Request from IP {ip:?} allowed");
            true // Request allowed
        } else {
            debug!("Request from IP {ip:?} blocked");
            false // Request blocked
        }
    }
