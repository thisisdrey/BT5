### Title
Unbounded tar extraction in `untar`/`CreateRepositoryFromSnapshot` allows disk/inode/CPU exhaustion DoS - ([File: internal/gitaly/service/repository/create_repository_from_snapshot.go])

### Summary
`CreateRepositoryFromSnapshot` streams an attacker/caller-supplied `HttpUrl` response body directly into `tar -C path -xvf -` with no size limit, entry-count limit, or timeout on the extraction itself. A malicious or compromised HTTP endpoint referenced by `in.GetHttpUrl()` can supply an arbitrarily large or arbitrarily long-lived tar stream (e.g., millions of zero-byte entries or a huge/sparse file) that `tar` will happily extract onto the storage shard, exhausting disk space, inodes, or CPU shared by all repositories on that Gitaly node.

### Finding Description
In `untar` [1](#0-0) , the RPC performs an HTTP GET against `in.GetHttpUrl()` and pipes the raw response body as stdin to `tar -C path -xvf -` via `command.New(ctx, s.logger, []string{"tar", "-C", path, "-xvf", "-"}, command.WithStdin(rsp.Body))`. There is no wrapping of `rsp.Body` in a `io.LimitReader`, no cap on the number of tar entries, and no application-level timeout/deadline distinct from the context's own cancellation. The only network-level protections are connection-level timeouts on the HTTP transport (`httpTransport` dial/TLS/response-header timeouts) [2](#0-1) , which do not bound the total size or duration of the response body once headers are received (a slow but continuously trickling body, or a very large/compressed body, is not stopped by `ResponseHeaderTimeout`).

The call site, `CreateRepositoryFromSnapshot`, only validates the target repository path via `s.locator.ValidateRepository` and wraps creation in `repoutil.Create`; it performs no validation of the archive size/content before or during extraction [3](#0-2) . The code even contains an explicit acknowledgment that the archive content is not hardened: "NOTE: The received archive is trusted *a lot*. Before pointing this RPC at endpoints not under our control, it should undergo a lot of hardening." [4](#0-3) . None of the standard Gitaly protections (`storage.ValidateRelativePath`, request size limits, `git.ValidateRevision`) apply here since this is a raw `tar` invocation over an HTTP body, not a git command with validated arguments.

### Impact Explanation
Given control of the `HttpUrl`/`ResolvedAddress` target, an attacker-controlled server can send a tar stream containing an unbounded number of entries or an extremely large/sparse payload. Because extraction runs unbounded, this can fill the Gitaly storage volume (disk exhaustion), exhaust the filesystem inode table (via many small/zero-byte files), or pin CPU/IO for an extended period — all of which are shared resources affecting every repository stored on that shard/storage, not just the target repository. This matches a storage-wide denial-of-service impact class.

### Likelihood Explanation
The finding is contingent on the stated precondition that the attacker can control or redirect the `HttpUrl` value used by `untar`. This RPC is typically invoked by GitLab Rails for internal repository-snapshot/import flows rather than being directly exposed with a caller-chosen arbitrary URL to end users; whether an unprivileged GitLab user can influence this field to point to a server they control depends on call sites outside this repository (e.g., Rails/Workhorse orchestration of imports or repository moves) which are not visible in this codebase. Within Gitaly itself, no additional authorization or URL allow-listing of `HttpUrl` exists beyond what's shown, so if the precondition holds, exploitation from a compromised/attacker-controlled snapshot endpoint is straightforward and repeatable — a single request triggers unbounded extraction with no retries required.

### Recommendation
- Wrap `rsp.Body` in an `io.LimitReader` with a hard maximum snapshot size, and fail with an internal error when exceeded.
- Enforce an application-level deadline for the whole `untar` operation using `context.WithTimeout`, independent of the HTTP transport timeouts.
- Consider streaming the tar entries in Go using `archive/tar` instead of shelling out to `tar`, so entry count, individual file size, and total extracted size can be checked incrementally and the extraction aborted early when limits are exceeded.
- Reconsider whether `HttpUrl` should ever be attacker-influenced; if so, restrict it to an allow-list of trusted internal hosts.

```go
func TestUntarUnboundedDoS(t *testing.T) {
    srv := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        tw := tar.NewWriter(w)
        for i := 0; ; i++ { // never stops (attacker-controlled server)
            hdr := &tar.Header{
                Name: fmt.Sprintf("file-%d", i),
                Mode: 0600,
                Size: 0,
            }
            if err := tw.WriteHeader(hdr); err != nil {
                return
            }
        }
    }))
    defer srv.Close()

    req := &gitalypb.CreateRepositoryFromSnapshotRequest{
        Repository: repo,
        HttpUrl:    srv.URL,
    }
    // Calling CreateRepositoryFromSnapshot will invoke untar, which pipes the
    // never-ending tar stream into `tar -xvf -`, consuming disk/inodes/CPU
    // without bound until the test/process is killed.
    _, err := client.CreateRepositoryFromSnapshot(ctx, req)
    // Expect: this call never completes / storage fills up — demonstrating
    // absence of any size or entry-count cap.
}
```
Expected: without a fix, the extraction runs indefinitely, consuming disk/inode resources on the shard; with a fix (size/entry limits and timeout), the RPC should fail fast with a bounded resource ceiling.

```go
func (s *server) untar(ctx context.Context, path string, in *gitalypb.CreateRepositoryFromSnapshotRequest) error {
	req, err := http.NewRequestWithContext(ctx, "GET", in.GetHttpUrl(), nil)
	if err != nil {
		return structerr.NewInvalidArgument("Bad HTTP URL: %w", err)
	}

	client := httpClient
	if resolvedAddress := in.GetResolvedAddress(); resolvedAddress != "" {
		client, err = newResolvedHTTPClient(in.GetHttpUrl(), resolvedAddress)
		if err != nil {
			return structerr.NewInvalidArgument("creating resolved HTTP client: %w", err)
		}
	}

	if in.GetHttpAuth() != "" {
		req.Header.Set("Authorization", in.GetHttpAuth())
	}

	rsp, err := client.Do(req)
	if err != nil {
		return structerr.NewInternal("HTTP request failed: %w", err)
	}
	defer rsp.Body.Close()

	if rsp.StatusCode < http.StatusOK || rsp.StatusCode >= http.StatusMultipleChoices {
		return structerr.NewInternal("HTTP server: %s", rsp.Status)
	}

	cmd, err := command.New(ctx, s.logger, []string{"tar", "-C", path, "-xvf", "-"}, command.WithStdin(rsp.Body))
	if err != nil {
		return err
	}

	return cmd.Wait()
```

```go
func (s *server) CreateRepositoryFromSnapshot(ctx context.Context, in *gitalypb.CreateRepositoryFromSnapshotRequest) (*gitalypb.CreateRepositoryFromSnapshotResponse, error) {
	repository := in.GetRepository()
	if err := s.locator.ValidateRepository(ctx, repository, storage.WithSkipRepositoryExistenceCheck()); err != nil {
		return nil, structerr.NewInvalidArgument("%w", err)
	}

	if err := repoutil.Create(ctx, s.logger, s.locator, s.gitCmdFactory, s.catfileCache, s.txManager, s.repositoryCounter, repository, func(repo *gitalypb.Repository) error {
		path, err := s.locator.GetRepoPath(ctx, repo, storage.WithRepositoryVerificationSkipped())
		if err != nil {
			return structerr.NewInternal("getting repo path: %w", err)
		}

		// The archive contains a partial git repository, missing a config file and
		// other important items. Initializing a new bare one and extracting the
		// archive on top of it ensures the created git repository has everything
		// it needs (especially, the config file and hooks directory).
		//
		// NOTE: The received archive is trusted *a lot*. Before pointing this RPC
		// at endpoints not under our control, it should undergo a lot of hardening.
		if err := s.untar(ctx, path, in); err != nil {
			return structerr.NewInternal("extracting snapshot: %w", err)
		}

		return nil
	}); err != nil {
		return nil, structerr.NewInternal("creating repository: %w", err)
	}
```
