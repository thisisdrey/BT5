After thorough analysis of the repository, I found a direct analog to the external overflow bug in the Aptos staking contract.

### Title
Intermediate u64 Overflow in `get_staking_contract_amounts_internal` Permanently Blocks Stake Withdrawal - (`File: aptos-move/framework/aptos-framework/sources/staking_contract.move`)

### Summary

`get_staking_contract_amounts_internal` computes commission via a bare u64 multiplication `accumulated_rewards * commission_percentage` before dividing by 100. When `accumulated_rewards` is large enough, this intermediate product overflows u64 and aborts the transaction. Because every stake-withdrawal path (`unlock_stake`, `request_commission`) calls this function, a staker whose pool crosses the overflow threshold is permanently unable to withdraw their funds.

### Finding Description

In `staking_contract.move`, the commission calculation is:

```move
let commission_amount =
    accumulated_rewards * staking_contract.commission_percentage / 100;
```

Both operands are `u64`. Move's arithmetic is checked and aborts on overflow. The overflow threshold is `MAX_U64 / commission_percentage`. For `commission_percentage = 100` (the maximum allowed), the threshold is `MAX_U64 / 100 ≈ 1.844 × 10¹⁷` octas (≈ 1.844 billion APT). For lower commission rates the threshold is proportionally higher.

The formal spec explicitly acknowledges this abort path:

```
aborts_if accumulated_rewards * staking_contract.commission_percentage > MAX_U64;
```

but no mitigation (u128 upcast, checked arithmetic, or input cap) is applied in the implementation.

Every user-facing withdrawal path calls `get_staking_contract_amounts_internal`:

- `unlock_stake` → `request_commission_internal` → `get_staking_contract_amounts_internal`
- `request_commission` → `request_commission_internal` → `get_staking_contract_amounts_internal`
- `vesting::unlock_rewards` → `staking_contract_amounts` → `get_staking_contract_amounts_internal`

Once the pool's accumulated rewards cross the threshold, all of these entry points abort, and the staker has no alternative path to recover their principal.

### Impact Explanation

A staker whose `accumulated_rewards * commission_percentage > MAX_U64` permanently loses the ability to call `unlock_stake` or `request_commission`. Their principal is locked in the stake pool with no recovery path, constituting permanent freezing of staking balances.

### Likelihood Explanation

The overflow threshold for `commission_percentage = 100` is ≈ 1.844 billion APT in accumulated rewards. Given the current total APT supply of ≈ 1 billion APT, this threshold is not reachable today. However, for lower commission rates the threshold is higher and even less reachable. The risk grows if APT supply expands significantly or if the staking contract is used with tokens of different denominations in future framework upgrades. The spec's own `aborts_if` clause confirms the condition is reachable in principle.

### Recommendation

Replace the bare u64 multiplication with a u128-promoted calculation, mirroring the pattern already used in `stake.move`'s `calculate_rewards_amount`:

```move
let commission_amount =
    (((accumulated_rewards as u128) * (staking_contract.commission_percentage as u128)
        / 100u128) as u64);
```

This eliminates the intermediate overflow for all values within the u64 range of `accumulated_rewards`.

### Proof of Concept

The overflow condition is formally documented in the spec schema `GetStakingContractAmountsAbortsIf`:

```
aborts_if accumulated_rewards * staking_contract.commission_percentage > MAX_U64;
```

Concrete trigger (commission_percentage = 100):
- `accumulated_rewards = 184_467_440_737_095_517` (just above `MAX_U64 / 100`)
- `accumulated_rewards * 100` overflows u64 → transaction aborts
- Final result `184_467_440_737_095_517` is a valid u64 value, so the overflow is purely intermediate [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3)

```text
    /// Calculate accumulated rewards and commissions since last update.
    fun get_staking_contract_amounts_internal(
        staking_contract: &StakingContract
    ): (u64, u64, u64) {
        // Pending_inactive is not included in the calculation because pending_inactive can only come from:
        // 1. Outgoing commissions. This means commission has already been extracted.
        // 2. Stake withdrawals from stakers. This also means commission has already been extracted as
        // request_commission_internal is called in unlock_stake
        let (active, _, pending_active, _) =
            stake::get_stake(staking_contract.pool_address);
        let total_active_stake = active + pending_active;
        let accumulated_rewards = total_active_stake - staking_contract.principal;
        let commission_amount =
            accumulated_rewards * staking_contract.commission_percentage / 100;

        (total_active_stake, accumulated_rewards, commission_amount)
    }
```
