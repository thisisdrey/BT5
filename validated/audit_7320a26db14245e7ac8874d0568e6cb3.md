### Title
Unauthenticated remote `/shutdown` endpoint terminates signer event receiver - (File: libsigner/src/events.rs)

### Summary
The `SignerEventReceiver::next_event` handler processes a bare `POST /shutdown` HTTP request by unconditionally setting `stop_signal` to `true` and returning `EventError::Terminated`, with no verification of the sender's identity, the node's `auth_token`/`auth_password`, or any other credential. Since the signer's event-receiver socket is configured to bind on `0.0.0.0` (per the reference config), any remote party able to reach that port can terminate the signer's event-processing loop with a single unauthenticated request.

### Finding Description
The broken equality: only the local trusted stacks-node process (the one configured via the matching `[[events_observer]] endpoint`) should be able to signal a shutdown of the event receiver, but the code allows *any* TCP client connecting to the bound HTTP listener to do so.

In `next_event()`, requests are dispatched purely by URL path with no auth check at all: [3](#0-2) 

Unlike the node's block-proposal/RPC endpoints that check an `auth_password`/`auth_token`, this HTTP server (`tiny_http`-based, bound via `bind()`) never inspects the `Authorization` header or any shared secret before acting on `/shutdown`. The other legitimate event paths (`/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block`) at least go through `process_event`, which deserializes JSON, but `/shutdown` performs a privileged state mutation (`stop_signal.store(true, Ordering::SeqCst)`) directly inline, before any content validation.

An attacker's exact message: a raw TCP connection to the signer's bound event-receiver address, sending
```
POST /shutdown HTTP/1.1
Host: <addr>
Connection: close
Content-Length: 0

```
This causes `is_stopped()` to return `true`, and `main_loop()` (in `libsigner/src/runloop.rs`, via `EventReceiver::main_loop`) breaks out of its loop on the next iteration, permanently ending the event-receiver thread for that signer process until manually restarted [4](#0-3) .

Existing guards (auth_token/auth_password matching between node and signer) apply only to the node-to-signer relationship configuration and to the node's RPC/block-proposal endpoints; they are never checked by `SignerEventReceiver` itself. The `endpoint` is documented/configured as `0.0.0.0:30000`, confirming it is meant to be reachable beyond localhost [2](#0-1) .

### Impact Explanation
A remote, unprivileged attacker who can reach the signer's event-receiver port can permanently stop that signer's event-processing loop with a single HTTP request, halting its ability to receive stackerdb chunks, block proposals, and burn-block events from the node. This is a Critical unauthenticated remote DoS: it takes a single crafted message and requires no credentials, no valid signer key, and no StackerDB slot ownership. Repeated against multiple signers it could degrade or stall Nakamoto block signing liveness for the affected signer set.

### Likelihood Explanation
The only precondition is network reachability to the configured `endpoint` port (default binds to `0.0.0.0`, i.e., all interfaces), which is explicitly what the sample production config recommends so the node can reach it — meaning if the port is exposed beyond localhost/firewalled internal network, it is exploitable from the internet. Attacker cost is a single TCP connection and one crafted POST request; no signing key, StackerDB slot, or RPC secret is needed. The action is trivially repeatable against any restarted signer instance.

### Recommendation
Require validation of the request's origin before honoring `/shutdown` (and ideally all POSTed events): check a shared secret/`auth_password` header matching the signer's configured secret, and/or restrict the shutdown-triggering mechanism to a local-only signal (e.g., have `SignerStopSignaler` use a loopback-only control channel or Unix socket instead of the same public HTTP port used for node events), rather than accepting an unauthenticated `POST /shutdown` on the externally-reachable event port.

### Proof of Concept
Rust test plan (extending `libsigner/src/tests/mod.rs` patterns, e.g. similar to `test_simple_signer`):
1. Construct a `SignerEventReceiver::new(false)`, spawn it via `Signer::spawn` bound to `127.0.0.1:<port>` (simulating the externally-reachable config), without ever calling `get_stop_signaler().send()`.
2. In a separate thread acting as the "attacker" (not the node, no auth header, no configured secret), open a raw `TcpStream::connect` to the bound address and write:
   ```
   POST /shutdown HTTP/1.1\r\nHost: 127.0.0.1:<port>\r\nConnection: close\r\nContent-Length: 0\r\n\r\n
   ```
3. Poll `event_receiver.is_stopped()` (or observe that `main_loop`'s thread join completes / no further events are forwarded even though the node keeps POSTing `/stackerdb_chunks`).
4. Assert `is_stopped() == true` and that a subsequent legitimate node POST to `/stackerdb_chunks` is never processed (channel receives nothing), proving the event loop was terminated by the unauthenticated request alone.

    fn main_loop(&mut self) {
        loop {
            if self.is_stopped() {

            let next_event = match self.next_event() {
                Ok(event) => event,
                Err(EventError::UnrecognizedEvent(..)) => {
                    // got an event that we don't care about (not a problem)
                    continue;
                }

                    // we're done
                    info!("Caught termination signal");
                    break;
                }
                Err(e) => {

                    continue;
                }
            };
            if !self.forward_event(next_event) {
                info!("Failed to forward event");
                break;
            }
        }
        info!("Event receiver main loop exit");
    }
