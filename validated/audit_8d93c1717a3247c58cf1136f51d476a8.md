### Title
Missing URL Scheme Validation Allows `ext::`/Argument-Injection via Remote URL Fields in `CreateRepositoryFromURL`, `FetchRemote`, `UpdateRemoteMirror`, and `FindRemoteRootRef` - ([File: internal/gitaly/service/repository/create_repository_from_url.go])

### Summary
Several Gitaly RPCs accept a caller-supplied remote URL string (`CreateRepositoryFromURLRequest.Url`, `FetchRemoteRequest.RemoteParams.Url`, `UpdateRemoteMirrorRequest.Remote.Url`, `FindRemoteRootRefRequest.RemoteUrl`) and pass it — after only an empty-string check — directly as a positional argument to `git clone`, `git fetch`, or `git remote show` via `remote.<name>.url` config or a CLI arg. There is no validation of the URL's scheme/format beyond emptiness, mirroring the reported bug class ("client accepts and forwards a user string without format validation, enabling injection in a downstream system").

### Finding Description
`validateCreateRepositoryFromURLRequest` only checks `req.GetUrl() == ""` and otherwise accepts any string: [1](#0-0) 

That URL is parsed with `url.Parse` (which does not reject non-standard/opaque schemes) and passed straight into `git clone`'s argument list: [2](#0-1) [3](#0-2) 

Similarly, `validateFetchRemoteRequest` only checks for blank/empty URL: [4](#0-3) 

and the URL is placed into git config as `remote.inmemory.url`: [5](#0-4) 

`FindRemoteRootRef` and `UpdateRemoteMirror` follow the identical pattern with no scheme restriction: [6](#0-5) [7](#0-6) 

Git supports the `ext::<command>` transport helper, which executes an arbitrary shell command as part of connecting to a "remote." None of these code paths set `protocol.ext.allow`/`GIT_ALLOW_PROTOCOL` to disable it, nor do they reject URLs that don't match `http(s)://`, `git://`, `ssh://`, or an SCP-like host:path form before handing the string to git. The codebase does have narrow protections against a related class of issue (DNS-rebinding via `GetURLAndResolveConfig`, and bundle-URI SSRF disabled in `cloneFromURLCommand`), but those are opt-in code paths only reached when `resolved_address` is set — they do not run a scheme allow-list check on the base URL itself, and skip entirely when `resolved_address` is empty.

### Impact Explanation
If any caller of these RPCs (e.g. an authenticated GitLab Rails/Sidekiq flow that lets a project owner configure a pull-mirror URL, an "import project by URL" feature, or Geo replication config) supplies a value like `ext::sh -c "id > /tmp/pwn"` instead of a normal git URL, and if git's `ext` transport helper is not otherwise disabled, Gitaly will invoke `git clone`/`git fetch`/`git remote show` with that value, resulting in arbitrary command execution in the Gitaly process/container. Even absent full RCE, unrestricted URL/scheme acceptance also permits SSRF-style requests to internal `http://`/`git://` endpoints, since the only mitigations (bundle-URI disablement, DNS-rebinding resolve) are conditional or narrow.

### Likelihood Explanation
Reachability requires that whatever caller sits above Gitaly (e.g. GitLab Rails) itself does not sufficiently validate the remote URL before issuing the RPC — this is analogous to the external report where the *client* (wallet-guard-snap) was the missing-validation layer. Because Gitaly's own RPC-level validation is limited to non-empty checks and the tests in the repo (`create_repository_from_url_test.go`) confirm that only "no URL provided" is exercised as invalid, likelihood of exploitation depends heavily on upstream input validation, which is outside this repository. This makes it a plausible but not independently provable RCE from Gitaly's perspective alone; it is a defense-in-depth gap rather than a confirmed end-to-end exploit within the provided code.

### Recommendation
Add an explicit allow-list validation of the remote URL scheme in `validateCreateRepositoryFromURLRequest`, `validateFetchRemoteRequest`, `UpdateRemoteMirror`, and `FindRemoteRootRef` — reject anything other than `http://`, `https://`, `git://`, `ssh://`, or a well-formed SCP-like `user@host:path`. Additionally, unconditionally set `-c protocol.ext.allow=never` (and consider `protocol.file.allow=never`) as a global git option on every command invocation that takes a user-controlled remote URL, not only when `resolved_address` is set, to close off the `ext::` transport helper regardless of upstream validation.

### Proof of Concept
1. Craft a `CreateRepositoryFromURLRequest` with `Url: "ext::sh -c 'touch /tmp/pwned'"` and a valid `Repository`.
2. Send it to Gitaly's `RepositoryService.CreateRepositoryFromURL`.
3. `validateCreateRepositoryFromURLRequest` passes (URL non-empty) [1](#0-0) .
4. `cloneFromURLCommand` builds `git clone --bare ext::sh -c 'touch /tmp/pwned' <targetPath>` and executes it via `s.gitCmdFactory.NewWithoutRepo` [3](#0-2) , resulting in command execution on the Gitaly host if the `ext` helper is enabled in the git build/config used by Gitaly (default git behavior does not disable it unless explicitly configured).

func buildCommandOpts(ctx context.Context, opts *localrepo.FetchOpts, req *gitalypb.FetchRemoteRequest) error {
	remoteURL := req.GetRemoteParams().GetUrl()
	var config []gitcmd.ConfigPair

	for _, refspec := range getRefspecs(req.GetRemoteParams().GetMirrorRefmaps()) {
		config = append(config, gitcmd.ConfigPair{
			Key: "remote.inmemory.fetch", Value: refspec,
		})
	}

	if resolvedAddress := req.GetRemoteParams().GetResolvedAddress(); resolvedAddress != "" {
		modifiedURL, resolveConfig, err := gitcmd.GetURLAndResolveConfig(remoteURL, resolvedAddress)
		if err != nil {
			return fmt.Errorf("couldn't get curloptResolve config: %w", err)
		}

		remoteURL = modifiedURL
		config = append(config, resolveConfig...)
	}

	config = append(config, gitcmd.ConfigPair{Key: "remote.inmemory.url", Value: remoteURL})

func (s *server) validateFetchRemoteRequest(ctx context.Context, req *gitalypb.FetchRemoteRequest) error {
	if err := s.locator.ValidateRepository(ctx, req.GetRepository()); err != nil {
		return structerr.NewInvalidArgument("%w", err)
	}

	if req.GetRemoteParams() == nil {
		return structerr.NewInvalidArgument("missing remote params")
	}

	if req.GetRemoteParams().GetUrl() == "" {
		return structerr.NewInvalidArgument("blank or empty remote URL")
	}

	return nil
}
