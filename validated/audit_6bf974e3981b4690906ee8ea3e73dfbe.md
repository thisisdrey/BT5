### Title
World-readable/writable `go env` config file can expose plaintext GOPROXY credentials - (File: src/cmd/go/internal/envcmd/env.go)

### Summary
`go env -w` persists key/value settings (including `GOPROXY`, which the go command explicitly supports as a URL with embedded `user:pass@host` Basic Auth credentials) into the per-user Go environment configuration file. The file is written with mode `0666` instead of a restrictive mode like `0600`, so on typical systems (umask 022) the resulting file ends up `0644` — readable by every local user, and even the requested mode is world-writable before umask is applied. This mirrors the Heketi CVE-2017-15104 pattern: a configuration file that can hold plaintext secrets is created with an overly permissive mode.

### Finding Description
Attacker input: a local, unprivileged user on a shared multi-user host.
Entry point: any invocation of `go env -w GOPROXY=https://user:pass@proxy.example.com` (or programmatic callers of `go env -w`) by the victim, which is a normal, documented workflow — `GOPROXY` credentials via URL userinfo are a supported mechanism (see `net/url.UserPassword` usage and Basic Auth handling in [1](#0-0) ).

- `runEnvW` in `src/cmd/go/internal/envcmd/env.go` accepts `KEY=VALUE` pairs and validates them via `checkEnvWrite`, which has no special validation/rejection for `GOPROXY` values (no case for `GOPROXY` in the switch), so a URL embedding a password is accepted unmodified: [2](#0-1) .
- `runEnvW` then calls `updateEnvFile(add, nil)`: [3](#0-2) .
- `updateEnvFile` writes the resulting KEY=VALUE lines (including the raw credential-bearing `GOPROXY` value) to the environment file using `os.WriteFile(file, data, 0666)`: [4](#0-3) .
- `os.WriteFile`'s documented semantics create the file "with permissions perm (before umask)" when it doesn't already exist: [5](#0-4) .
- `cfg.EnvFile()` resolves this file to `$XDG_CONFIG_HOME/go/env` (or platform equivalent) under the user's normal config directory — not a directory with restricted permissions by default: [6](#0-5) .

Failed check: there is no mode hardening (e.g., `0600`) analogous to what the standard library itself recommends elsewhere for user secrets, e.g. `os.WriteFile(configPath, config, 0600)` in the `os.UserConfigDir` example: [7](#0-6) .

Sink: the on-disk `go/env` file, containing the plaintext `GOPROXY=https://user:pass@host` line, created with mode `0666` (typically `0644` after umask) — readable by any local user/group, unlike the `0600`-mode pattern used elsewhere in the standard library for equivalent per-user secrets.

### Impact Explanation
Any other local, unprivileged user on the same host can read `~/.config/go/env` (or run `go env GOPROXY` as that user isn't even needed — direct file read suffices) and recover the victim's module-proxy Basic Auth credentials in plaintext, exactly analogous to the Heketi disclosure of plaintext passwords via a world-readable `heketi.json`. This is a Confidentiality impact (secret disclosure) that would fall under Go's PUBLIC track as a low-severity information-exposure hardening issue affecting a documented, supported feature (GOPROXY with embedded credentials, GOAUTH being a separate, safer alternative that exists precisely because of this risk).

### Likelihood Explanation
The victim workflow is entirely ordinary and documented: a developer runs `go env -w GOPROXY=https://user:pass@corp-proxy/` to persist proxy credentials, as suggested by numerous private-module-proxy setup guides that predate `GOAUTH`. No malicious input, TLS bypass, or code execution is required — the attacker only needs unprivileged local access to read a config file the go tool itself makes overly permissive.

### Recommendation
Change `updateEnvFile` in `src/cmd/go/internal/envcmd/env.go` to create the `go/env` file with mode `0600` on creation (matching the pattern already used by `os.UserConfigDir` examples and other per-user secret files), and consider tightening the mode of any pre-existing file that is more permissive than `0600` on write, plus documenting that `GOPROXY`/`GOAUTH` credentials should not be embedded via URL userinfo when this is not desired.

```go
// TestGoEnvWriteFilePermissions demonstrates that `go env -w GOPROXY=...`
// creates the go/env config file with an overly permissive mode (0666
// before umask), exposing any embedded credentials to other local users.
func TestGoEnvWriteFilePermissions(t *testing.T) {
	if runtime.GOOS == "windows" || runtime.GOOS == "plan9" {
		t.Skip("POSIX permission bits only")
	}

	dir := t.TempDir()
	envFile := filepath.Join(dir, "env")

	cmd := exec.Command("go", "env", "-w", "GOPROXY=https://alice:s3cr3t@proxy.example.com")
	cmd.Env = append(os.Environ(), "GOENV="+envFile)
	if out, err := cmd.CombinedOutput(); err != nil {
		t.Fatalf("go env -w failed: %v\n%s", err, out)
	}

	info, err := os.Stat(envFile)
	if err != nil {
		t.Fatalf("stat %s: %v", envFile, err)
	}

	mode := info.Mode().Perm()
	// A file holding a plaintext credential should not be group/world
	// readable or writable, e.g. it should be 0600.
	if mode&0077 != 0 {
		t.Errorf("go/env file %s has overly permissive mode %o (world/group accessible); credentials exposed", envFile, mode)
	}

	data, _ := os.ReadFile(envFile)
	t.Logf("go/env contents (mode %o):\n%s", mode, data)
}
```
Expected result on the affected (unfixed) code: the test fails because `mode&0077 != 0` (the file is created `0644`, i.e., world-readable), and the log output shows the plaintext `GOPROXY=https://alice:s3cr3t@proxy.example.com` line readable by any local user.

```go
func checkEnvWrite(key, val string) error {
	switch key {
	case "GOEXE",
		"GOGCCFLAGS",
		"GOHOSTARCH",
		"GOHOSTOS",
		"GOMOD",
		"GOROOT",
		"GOTELEMETRY",
		"GOTELEMETRYDIR",
		"GOTOOLDIR",
		"GOVERSION",
		"GOWORK":
		return fmt.Errorf("%s cannot be modified", key)
	case "GOENV", "GODEBUG":
		return fmt.Errorf("%s can only be set using the OS environment", key)
	}

	// To catch typos and the like, check that we know the variable.
	// If it's already in the env file, we assume it's known.
	if !cfg.CanGetenv(key) {
		return fmt.Errorf("unknown go command variable %s", key)
	}

	// Some variables can only have one of a few valid values. If set to an
	// invalid value, the next cmd/go invocation might fail immediately,
	// even 'go env -w' itself.
	switch key {
	case "GO111MODULE":
		switch val {
		case "", "auto", "on", "off":
		default:
			return fmt.Errorf("invalid %s value %q", key, val)
		}
	case "GOPATH":
		if strings.HasPrefix(val, "~") {
			return fmt.Errorf("GOPATH entry cannot start with shell metacharacter '~': %q", val)
		}
		if !filepath.IsAbs(val) && val != "" {
			return fmt.Errorf("GOPATH entry is relative; must be absolute path: %q", val)
		}
	case "GOMODCACHE":
		if !filepath.IsAbs(val) && val != "" {
			return fmt.Errorf("GOMODCACHE entry is relative; must be absolute path: %q", val)
		}
	case "CC", "CXX":
		if val == "" {
			break
		}
		args, err := quoted.Split(val)
		if err != nil {
			return fmt.Errorf("invalid %s: %v", key, err)
		}
		if len(args) == 0 {
			return fmt.Errorf("%s entry cannot contain only space", key)
		}
		if !filepath.IsAbs(args[0]) && args[0] != filepath.Base(args[0]) {
			return fmt.Errorf("%s entry is relative; must be absolute path: %q", key, args[0])
		}
	}
```

```go
// EnvFile returns the name of the Go environment configuration file,
// and reports whether the effective value differs from the default.
func EnvFile() (string, bool, error) {
	if file := os.Getenv("GOENV"); file != "" {
		if file == "off" {
			return "", false, fmt.Errorf("GOENV=off")
		}
		return file, true, nil
	}
	dir, err := os.UserConfigDir()
	if err != nil {
		return "", false, err
	}
	if dir == "" {
		return "", false, fmt.Errorf("missing user-config dir")
	}
	return filepath.Join(dir, "go/env"), false, nil
}
```
