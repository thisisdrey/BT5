### Title
Accumulated Staking Rewards Lost to Shareholders on Vesting Contract Termination — (`aptos-move/framework/aptos-framework/sources/vesting.move`)

---

### Summary

`terminate_vesting_contract` in `vesting.move` does not call `unlock_rewards` before terminating the contract. As a result, all accumulated staking rewards that are still sitting in the active stake pool are swept into the `unlock_stake(active_stake)` call and ultimately sent to the admin-controlled `withdrawal_address` via `admin_withdraw`, rather than being distributed to shareholders. Shareholders permanently lose their earned APT rewards.

---

### Finding Description

The normal reward-distribution lifecycle in the vesting module is:

1. `unlock_rewards` → moves accumulated rewards from active stake to `pending_inactive`
2. After lockup expires, `distribute` → withdraws inactive stake and pays shareholders proportionally

`vest()` correctly enforces this ordering:

```move
public entry fun vest(contract_address: address) acquires VestingContract {
    // Unlock all rewards first, if any.
    unlock_rewards(contract_address);   // ← always called first
    ...
    unlock_stake(vesting_contract, vested_amount);
}
``` [1](#0-0) 

`terminate_vesting_contract` breaks this invariant. It calls `distribute` (which only flushes already-inactive stake) but **never calls `unlock_rewards`**:

```move
public entry fun terminate_vesting_contract(admin: &signer, contract_address: address) {
    assert_active_vesting_contract(contract_address);

    // Distribute all withdrawable coins, which should have been from previous rewards withdrawal or vest.
    distribute(contract_address);   // ← only distributes already-inactive stake

    let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
    verify_admin(admin, vesting_contract);
    let (active_stake, _, pending_active_stake, _) =
        stake::get_stake(vesting_contract.staking.pool_address);
    // active_stake = original_grant + accumulated_rewards (both lumped together)

    vesting_contract.state = VESTING_POOL_TERMINATED;
    vesting_contract.remaining_grant = 0;
    unlock_stake(vesting_contract, active_stake);   // ← sweeps rewards + grant together
}
``` [2](#0-1) 

`active_stake` returned by `stake::get_stake` is the sum of the original grant principal **and** all accumulated staking rewards that have not yet been unlocked. Because `unlock_rewards` was never called, those rewards were never separated into `pending_inactive` for shareholders; they remain in `active_stake`.

`unlock_stake` internally calls `staking_contract::unlock_stake`, which moves the entire `active_stake` amount to `pending_inactive` under the vesting contract's own account. [3](#0-2) 

After termination the contract state is `VESTING_POOL_TERMINATED`. `distribute` requires `assert_active_vesting_contract`, so shareholders can no longer call it: [4](#0-3) 

The only remaining path is `admin_withdraw`, which sends everything to `withdrawal_address`:

```move
public entry fun admin_withdraw(admin: &signer, contract_address: address) {
    ...
    aptos_account::deposit_coins(vesting_contract.withdrawal_address, coins);
}
``` [5](#0-4) 

`total_accumulated_rewards` confirms that accumulated rewards are computed as `total_active_stake - remaining_grant - commission_amount`, i.e., they live inside `active_stake` until explicitly unlocked: [6](#0-5) 

---

### Impact Explanation

Shareholders permanently lose all accumulated staking rewards that had not been explicitly unlocked before the admin called `terminate_vesting_contract`. Those rewards are redirected to the admin-controlled `withdrawal_address`. For large vesting contracts (the test constant alone is 200 M APT), the magnitude of loss can be enormous. This is a direct, permanent loss of APT vesting balances belonging to shareholders.

---

### Likelihood Explanation

Any vesting contract admin who terminates a contract without first manually calling `unlock_rewards` triggers this bug. There is no on-chain guard, no warning, and no documentation in the function body prompting the admin to call `unlock_rewards` first. The comment in the function body says only "Distribute all withdrawable coins, which should have been from previous rewards withdrawal or vest" — implicitly assuming the caller already ran `unlock_rewards`, but this is not enforced. The likelihood is high because the omission is invisible to a well-intentioned admin.

---

### Recommendation

Add a call to `unlock_rewards` at the start of `terminate_vesting_contract`, mirroring the pattern used in `vest`:

```move
public entry fun terminate_vesting_contract(admin: &signer, contract_address: address)
    acquires VestingContract {
    assert_active_vesting_contract(contract_address);

    // Unlock accumulated rewards so shareholders receive them, not the withdrawal address.
    unlock_rewards(contract_address);

    // Distribute all withdrawable coins.
    distribute(contract_address);

    let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
    verify_admin(admin, vesting_contract);
    let (active_stake, _, pending_active_stake, _) =
        stake::get_stake(vesting_contract.staking.pool_address);
    assert!(pending_active_stake == 0, error::invalid_state(EPENDING_STAKE_FOUND));

    vesting_contract.state = VESTING_POOL_TERMINATED;
    vesting_contract.remaining_grant = 0;
    unlock_stake(vesting_contract, active_stake);
    ...
}
```

This ensures that by the time `active_stake` is read, it contains only the original grant principal (rewards have already been moved to `pending_inactive` for shareholders).

---

### Proof of Concept

Concrete state trace:

| Step | active_stake | pending_inactive | shareholder balance | withdrawal_address balance |
|------|-------------|-----------------|--------------------|-----------------------------|
| Initial grant | 200 M APT | 0 | 0 | 0 |
| After N epochs of staking rewards | 200 M + R APT | 0 | 0 | 0 |
| `terminate_vesting_contract` called (no `unlock_rewards`) | 0 | 200 M + R APT | 0 | 0 |
| Lockup expires, `admin_withdraw` called | 0 | 0 | 0 | **200 M + R APT** |

Shareholders receive **0** instead of **R APT** in rewards. The entire reward amount R is permanently redirected to `withdrawal_address`.

The existing test `test_vesting_contract` at line 1311–1320 shows `terminate_vesting_contract` followed by `admin_withdraw` receiving `with_rewards(total_active)` — which includes rewards — confirming the behavior is present in the current codebase: [7](#0-6)

        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        verify_admin(admin, vesting_contract);
        let coins = withdraw_stake(vesting_contract, contract_address);
        let amount = coin::value(&coins);
        if (amount == 0) {
            coin::destroy_zero(coins);
            return
        };
        aptos_account::deposit_coins(vesting_contract.withdrawal_address, coins);

        emit(
            AdminWithdraw {
                admin: vesting_contract.admin,
                vesting_contract_address: contract_address,
                amount,
            },
        );
    }
