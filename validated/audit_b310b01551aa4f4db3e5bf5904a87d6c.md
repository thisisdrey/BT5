### Title
Single Beneficiary Deposit Failure Permanently Blocks All Vesting Distributions — (`aptos-move/framework/aptos-framework/sources/vesting.move`)

### Summary

`vesting::distribute()` iterates over every shareholder and calls `aptos_account::deposit_coins` for each one inside a single atomic transaction. If any one deposit aborts, the entire distribution reverts, permanently preventing all other shareholders from receiving their vested APT until privileged admin intervention.

### Finding Description

`vesting::distribute()` withdraws all unlocked stake from the pool and then distributes it to every shareholder in a single loop: [1](#0-0) 

`aptos_account::deposit_coins` can abort in two ways:

1. The recipient account exists but is **not registered** for `AptosCoin`, and `can_receive_direct_coin_transfers(to)` returns `false` (i.e., the account has called `set_allow_direct_coin_transfers(account, false)`).
2. The recipient's `CoinStore<AptosCoin>` is **frozen**. [2](#0-1) 

The default beneficiary for a shareholder is the shareholder address itself (no explicit beneficiary set): [3](#0-2) 

The developers were aware of this risk and added a guard in `set_beneficiary` (admin path): [4](#0-3) 

However, this guard only applies when the admin **explicitly sets** a beneficiary. The original shareholder addresses stored in `grant_pool` at contract creation are **never validated** with `assert_account_is_registered_for_apt`. A shareholder whose address was created via `account::create_account` (without `register_apt`) and who subsequently calls `set_allow_direct_coin_transfers(self, false)` will cause every future `distribute()` call to abort, blocking all other shareholders.

The same unguarded loop pattern exists in `staking_contract::distribute_internal`, where the operator's beneficiary address is also not validated: [5](#0-4) 

### Impact Explanation

A single shareholder (or operator beneficiary) whose deposit aborts causes the entire `distribute()` transaction to revert. All unlocked APT is returned to the vesting contract's stake pool. No shareholder receives any distribution. This constitutes a **permanent freeze of vesting balances** until the admin intervenes by calling `set_beneficiary` to redirect the problematic shareholder to a valid address — which itself requires the admin to be available and responsive.

### Likelihood Explanation

- **Unprivileged trigger**: Any shareholder whose account is not registered for APT can call `set_allow_direct_coin_transfers(self, false)` to make their deposit abort. This is a standard, permissionless framework entry function.
- **No validation at creation**: `create_vesting_contract` does not call `assert_account_is_registered_for_apt` on shareholder addresses, leaving the gap the `set_beneficiary` guard was designed to close.
- **Griefing incentive**: A shareholder who disagrees with the vesting terms, or a malicious participant, can block all co-shareholders indefinitely.

### Recommendation

1. In `create_vesting_contract`, validate every shareholder address with `assert_account_is_registered_for_apt` before adding it to the grant pool, mirroring the guard already present in `set_beneficiary`.
2. Consider restructuring `distribute()` to use an internal accounting model (credit each shareholder's claimable balance) and let each shareholder withdraw independently, so a single failing deposit cannot block others — the exact pattern recommended in the original SetProtocol report.
3. Apply the same fix to `staking_contract::distribute_internal` for the operator beneficiary path.

### Proof of Concept

```
1. Admin calls create_vesting_contract with shareholders = [@alice, @bob].
   - @bob was created via account::create_account (no APT registration).
   - @bob calls set_allow_direct_coin_transfers(@bob, false).

2. Vesting period elapses; vest() is called successfully.

3. Anyone calls distribute(contract_address).
   - Loop reaches @bob: deposit_coins(@bob, share) aborts with
     EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS.
   - Entire transaction reverts.
   - @alice receives nothing.

4. Repeat indefinitely until admin calls set_beneficiary(@bob, <valid_addr>).
   If admin is a multisig or unavailable, @alice's vested APT is permanently frozen.
``` [6](#0-5) [2](#0-1) [7](#0-6)

    /// Distribute any withdrawable stake from the stake pool.
    public entry fun distribute(contract_address: address) acquires VestingContract {
        assert_active_vesting_contract(contract_address);

        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        let coins = withdraw_stake(vesting_contract, contract_address);
        let total_distribution_amount = coin::value(&coins);
        if (total_distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };

        // Distribute coins to all shareholders in the vesting contract.
        let grant_pool = &vesting_contract.grant_pool;
        let shareholders = &grant_pool.shareholders();
        shareholders.for_each_ref(|shareholder| {
            let shareholder = *shareholder;
            let shares = pool_u64::shares(grant_pool, shareholder);
            let amount = pool_u64::shares_to_amount_with_total_coins(grant_pool, shares, total_distribution_amount);
            let share_of_coins = coin::extract(&mut coins, amount);
            let recipient_address = get_beneficiary(vesting_contract, shareholder);
            aptos_account::deposit_coins(recipient_address, share_of_coins);
        });

        // Send any remaining "dust" (leftover due to rounding error) to the withdrawal address.
        if (coin::value(&coins) > 0) {
            aptos_account::deposit_coins(vesting_contract.withdrawal_address, coins);
        } else {
            coin::destroy_zero(coins);
        };

        emit(
            Distribute {
                admin: vesting_contract.admin,
                vesting_contract_address: contract_address,
                amount: total_distribution_amount,
            },
        );
    }

    fun get_beneficiary(contract: &VestingContract, shareholder: address): address {
        if (contract.beneficiaries.contains_key(&shareholder)) {
            *contract.beneficiaries.borrow(&shareholder)
        } else {
            shareholder
        }
    }
