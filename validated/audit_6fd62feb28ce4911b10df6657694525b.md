### Title
Unauthenticated stage-1 handshake packets force full Noise DH computation before certificate verification, enabling handshake-flood DoS - (File: handshake_manager.go, handshake/machine.go)

### Summary
The external report describes a DoS where an attacker floods a protocol's upkeep queue with cheap, unauthenticated "false offers" that never resolve, exhausting a bounded processing loop. The reachable analog in nebula is `HandshakeManager.HandleIncoming` / `beginHandshake`, which unconditionally runs a full Noise handshake (`machine.ProcessPacket`, including asymmetric Diffie-Hellman operations) for *every* inbound stage-1 packet (`h.MessageCounter == 1`, `h.RemoteIndex == 0`) before any certificate/CA validation occurs, and nebula has no anti-DoS cookie mechanism to gate this cost.

### Finding Description
`HandleIncoming` gates only on subtype and a zero `RemoteIndex`, then unconditionally calls `beginHandshake` for any first-stage packet: [1](#0-0) 

`beginHandshake` builds a new responder `Machine` and immediately calls `machine.ProcessPacket`, which performs the Noise `IX` handshake read (ephemeral key generation/DH, symmetric ratchet, and certificate reconstruction) — this is the expensive cryptographic work — and only *afterward* does certificate validation happen via the `verifier` callback invoked from within `ProcessPacket`: [2](#0-1) 

The `CertVerifier` (CA-pool check) is invoked as part of the noise machine's processing, not before it: [3](#0-2) 

Critically, the protocol's wire format has a `Cookie` field that was explicitly reserved for an anti-DoS mechanism but was never implemented in any released version: [4](#0-3) 

No rate limiter or per-source-IP throttle for inbound handshake stage-1 packets was found anywhere in the handshake path (`handshake_manager.go`) or the UDP receive path; the only gating checks are subtype and `RemoteIndex == 0`, which any attacker can satisfy trivially with a garbage or replayed packet body.

### Impact Explanation
An attacker without any CA-signed certificate can send an unlimited stream of spoofed/garbage UDP packets shaped as stage-1 handshake messages (`Type=Handshake`, `Subtype=HandshakeIXPSK0`, `MessageCounter=1`, `RemoteIndex=0`). Each such packet forces the target node to allocate a new `noise.HandshakeState`/`Machine` and perform real elliptic-curve Diffie-Hellman and certificate-parsing work before the packet is ultimately rejected (since it lacks a certificate the local CA pool trusts). This is a remote, pre-authentication CPU/allocation cost amplification: cheap for the attacker (UDP send), expensive for the victim (asymmetric crypto). Sustained flooding degrades the node's ability to service legitimate handshakes and traffic — a remote-crash/DoS-class impact reachable with no valid certificate.

### Likelihood Explanation
Likelihood is high: the attack requires only the ability to send arbitrary UDP packets to the node's listening port — no valid CA-signed certificate, no prior state, and no participation in the mesh is required. The only preconditions (`Subtype == HandshakeIXPSK0`, `MessageCounter == 1`, `RemoteIndex == 0`) are fixed, publicly-known wire-format constants and are trivial to satisfy in a forged packet, and (per the remote-allow-list check) can be bypassed simply by using any address permitted by `lighthouse.remote_allow_list` (which defaults to allowing unknown senders unless the operator has configured a restrictive allow-list).

### Recommendation
- Implement the previously-reserved anti-DoS cookie mechanism (or an equivalent stateless proof-of-work/return-routability check) so that a lightweight, stateless response is required before the responder commits to the costly Noise/DH computation, similar to WireGuard's cookie-reply mechanism.
- Add rate limiting (per source IP/subnet and/or globally) on stage-1 handshake initiation before invoking `beginHandshake`/`machine.ProcessPacket`.
- Consider deferring the expensive DH step until a cheap syntactic/format pre-check of the payload passes, to reduce the amount of forged-packet handling that reaches full crypto.

### Proof of Concept
Not independently reproduced in this session; the applicable code paths were traced statically:
1. Craft a UDP packet with a valid `header.H{Type: Handshake, Subtype: HandshakeIXPSK0, MessageCounter: 1, RemoteIndex: 0}` and arbitrary/garbage payload bytes.
2. Send a high volume of such packets from spoofed or throwaway source addresses to a nebula node's UDP listener.
3. Each packet reaches `HandleIncoming` → `beginHandshake` → `machine.ProcessPacket`, which performs Noise DH/crypto work per packet as shown in `handshake_manager.go:701-726` and `handshake/machine.go`, before any certificate is validated or trusted.
4. No cookie or rate-limit gate exists to reject these cheaply before the crypto cost is paid, as confirmed by the deprecated/never-implemented `Cookie` field in `handshake/handshake.proto:17-24`.

Note: I could not fully verify the exact per-message cost (number of DH operations) inside `noise.HandshakeState.ReadMessage` since the `flynn/noise` library internals are outside this repo's index, nor could I confirm the absence of a rate limiter with full certainty beyond grep coverage of the indexed files — a live PoC run and a review of the vendored `flynn/noise` dependency would be needed for full confirmation.

```go
func (hm *HandshakeManager) beginHandshake(via ViaSender, packet []byte, h *header.H) {
	f := hm.f
	cs := f.pki.getCertState()

	v := cs.DefaultVersion()
	if cs.GetCredential(v) == nil {
		f.l.Error("Unable to handshake with host because no certificate is available",
			"from", via, "certVersion", v)
		return
	}

	machine, err := handshake.NewMachine(
		v, cs.GetCredential,
		hm.certVerifier(), func() (uint32, error) { return generateIndex(f.l) },
		false, header.HandshakeIXPSK0,
	)
	if err != nil {
		f.l.Error("Failed to create handshake machine", "from", via, "error", err)
		return
	}

	response, result, err := machine.ProcessPacket(nil, packet)
	if err != nil {
		f.l.Error("Failed to process handshake packet", "from", via, "error", err)
		return
	}
```
