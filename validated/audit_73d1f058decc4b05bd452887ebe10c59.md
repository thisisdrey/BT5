### Title
Missing allowlist validation of client-supplied `GitConfigOptions` allows arbitrary Git config injection into `receive-pack`/`upload-pack` invocations - (File: internal/git/gitcmd/command_options.go)

### Summary
The external report describes `MarinateV2.sol` setters (`addApprovedMultiplierToken`, `setScale`, `setDepositLevel`) accepting new values without any semantic bounds/allowlist checks, only fixed after a partner added a targeted `require`. The analogous pattern in Gitaly is `gitcmd.ConvertConfigOptions` / `config.GitConfig.Validate()`, which accept arbitrary client-supplied Git config keys for `-c key=value` and only perform syntactic format checks (must contain a dot, no `=`, regex match) — there is no allowlist/denylist restricting *which* Git config namespaces an ordinary, authenticated push/fetch client may set.

### Finding Description
`GitConfigOptions` is a repeated string field accepted directly from RPC requests on `PostReceivePack`, `PostUploadPackWithSidechannel`, `InfoRefsUploadPack`/`InfoRefsReceivePack`, and the SSH equivalents [1](#0-0) . These are converted with `gitcmd.ConvertConfigOptions`, which merely splits on `=` without any restriction on the key namespace: [2](#0-1) .

The eventual validation performed in `GitConfig.Validate()` is purely syntactic (non-empty, no `=`, contains a dot, doesn't start/end with a dot, matches `configKeyRegex`) — it never restricts which config sections/keys (e.g. `uploadpack.*`, `receive.*`, `transfer.*`, `core.*`, `http.*`, `credential.*`) a request is permitted to set: [3](#0-2) [4](#0-3) . These values are then passed straight through to the `git receive-pack`/`git upload-pack` invocation via `-c`: [5](#0-4) [6](#0-5) [7](#0-6) .

The project's own CHANGELOG documents that this exact bug class ("injection of arbitrary config options") was previously exploited and had to be specifically patched for `http.*` options multiple times (13.0.12, 13.1.6, 13.2.2 era): [8](#0-7) [9](#0-8) [10](#0-9) . This confirms the historical pattern of ad-hoc, incomplete fixes rather than a systemic allowlist — mirroring the "resolved only partially / partner had to add a specific check" pattern in the analog report. Tests in this codebase further prove that `receive.MaxInputSize`, `uploadpack.hideRefs`, `transfer.hideRefs`, `uploadpack.allowAnySHA1InWant` are all currently accepted with no key-based restriction: [11](#0-10) [12](#0-11) [13](#0-12) .

Because there is no allowlist, any ordinary authenticated client performing a push or fetch can inject *any* syntactically valid Git config key, not just the intended small set of behavior-tuning options (`uploadpack.hideRefs`, `transfer.hideRefs`, etc.) that tests exercise. This is directly analogous to the "no upper/lower bound validation" bug class in the report — the setter (`ConvertConfigOptions`/`GitConfig.Validate`) accepts the new "value" (the config key/value pair) without checking it is within an acceptable domain before being used in a sensitive operation (spawning `git` with the value as `-c`).

### Impact Explanation
Unrestricted Git config injection from an untrusted RPC field into a spawned `git receive-pack`/`git upload-pack` process is a well-known high-impact primitive: it can be used to override safety-relevant settings such as pack size/object limits, protocol behavior, `uploadpack`/`transfer` ref-hiding rules (potential cross-repository/object visibility bypass or hidden-ref disclosure), or otherwise unexpected settings within a section not intended to be client-controllable. Because the constructed `-c` flags are passed to a real `git` subprocess, any config key Git honors for `receive-pack`/`upload-pack` operation could be affected, and the boundary of "safe" vs. "unsafe" keys is not enforced by Gitaly — only Git's own semantics limit exploitation, which is fragile and has already required repeated CVE-level patches for the `http.*` namespace.

### Likelihood Explanation
High likelihood of reachability: `GitConfigOptions` is a normal, top-level field on `PostReceivePackRequest`/`PostUploadPackWithSidechannelRequest`/`InfoRefsRequest`, reachable by any ordinary authenticated user performing a `git push`/`git fetch` through gitlab-shell/Workhorse to Gitaly, with no additional privilege required. The lack of an allowlist is directly visible in the current code path (`ConvertConfigOptions` → `GitConfig.Validate` → `-c`), and the changelog shows this exact injection surface has already caused security fixes for a subset of keys, indicating the general class remains only partially mitigated.

### Recommendation
Introduce an explicit allowlist of Git config keys/prefixes (or at minimum a denylist of known-dangerous sections such as `core.*`, `credential.*`, `http.*` beyond what's explicitly needed, `include.*`, `alias.*`, `uploadpack.packObjectsHook`, `core.hooksPath`) that `ConvertConfigOptions`/`GitConfig.Validate` enforces before any client-supplied `GitConfigOptions` are converted into `-c` arguments, rejecting any key outside the approved set with an `InvalidArgument` error, in `internal/git/gitcmd/command_options.go` and `internal/gitaly/config/config.go`.

### Proof of Concept
Given the current code, an authenticated client can attach an arbitrary syntactically-valid key/value pair to any `PostReceivePackRequest`/`PostUploadPackWithSidechannelRequest`/`InfoRefsRequest`:
```
rpcRequest := &gitalypb.PostUploadPackWithSidechannelRequest{
    Repository: repo,
    GitConfigOptions: []string{
        "core.<arbitrary>=<arbitrary>",   // not restricted to intended uploadpack./transfer. namespace
    },
}
```
This passes `ConvertConfigOptions` (`internal/git/gitcmd/command_options.go:118-131`) and `GitConfig.Validate()` (`internal/gitaly/config/config.go:436-470`) unchanged, and is appended directly as a `-c` flag to the spawned `git upload-pack`/`git receive-pack` process (`internal/gitaly/service/smarthttp/upload_pack.go:119`, `internal/gitaly/service/smarthttp/receive_pack.go:101-137`), demonstrating the code path accepts config keys outside the intended, documented set (`transfer.hideRefs`, `uploadpack.hideRefs`) used in the existing test suite [12](#0-11) .

// ConvertConfigOptions converts `<key>=<value>` config entries into `ConfigPairs`.
func ConvertConfigOptions(options []string) ([]ConfigPair, error) {
	configPairs := make([]ConfigPair, len(options))

	for i, option := range options {
		configPair := strings.SplitN(option, "=", 2)
		if len(configPair) != 2 {
			return nil, fmt.Errorf("cannot convert invalid config key: %q", option)
		}

		configPairs[i] = ConfigPair{Key: configPair[0], Value: configPair[1]}
	}

	return configPairs, nil
}

// Validate validates that the Git configuration conforms to a format that Git understands.
func (cfg GitConfig) Validate() error {
	// Even though redundant, this block checks for a few things up front to give better error
	// messages to the administrator in case any of the keys fails validation.
	if cfg.Key == "" {
		return cfgerror.NewValidationError(cfgerror.ErrNotSet, "key")
	}
	if strings.Contains(cfg.Key, "=") {
		return cfgerror.NewValidationError(
			fmt.Errorf(`key %q cannot contain "="`, cfg.Key),
			"key",
		)
	}
	if !strings.Contains(cfg.Key, ".") {
		return cfgerror.NewValidationError(
			fmt.Errorf("key %q must contain at least one section", cfg.Key),
			"key",
		)
	}
	if strings.HasPrefix(cfg.Key, ".") || strings.HasSuffix(cfg.Key, ".") {
		return cfgerror.NewValidationError(
			fmt.Errorf("key %q must not start or end with a dot", cfg.Key),
			"key",
		)
	}

	if !configKeyRegex.MatchString(cfg.Key) {
		return cfgerror.NewValidationError(
			fmt.Errorf("key %q failed regexp validation", cfg.Key),
			"key",
		)
	}

	return nil
}

func (s *server) validateUploadPackRequest(ctx context.Context, req *gitalypb.PostUploadPackWithSidechannelRequest) (string, []gitcmd.ConfigPair, error) {
	repository := req.GetRepository()
	if err := s.locator.ValidateRepository(ctx, repository); err != nil {
		return "", nil, err
	}
	repoPath, err := s.locator.GetRepoPath(ctx, repository)
	if err != nil {
		return "", nil, err
	}

	gitcmd.WarnIfTooManyBitmaps(ctx, s.logger, s.locator, repository.GetStorageName(), repoPath)

	config, err := gitcmd.ConvertConfigOptions(req.GetGitConfigOptions())
	if err != nil {
		return "", nil, err
	}

	return repoPath, config, nil
}

func (s *server) sshUploadPack(ctx context.Context, req *gitalypb.SSHUploadPackWithSidechannelRequest, stdin io.Reader, stdout, stderr io.Writer) (negotiation *stats.PackfileNegotiation, _ int, _ error) {
	repoProto := req.GetRepository()

	repo := s.localRepoFactory.Build(repoProto)
	repoPath, err := repo.Path(ctx)
	if err != nil {
		return nil, 0, err
	}

	gitcmd.WarnIfTooManyBitmaps(ctx, s.logger, s.locator, repoProto.GetStorageName(), repoPath)

	config, err := gitcmd.ConvertConfigOptions(req.GetGitConfigOptions())
	if err != nil {
		return nil, 0, err
	}

	var wg sync.WaitGroup
	pr, pw := io.Pipe()
	defer func() {
		pw.Close()
		wg.Wait()
	}()

	stdin = io.TeeReader(stdin, pw)

	wg.Add(1)
	go func() {
		defer func() {
			wg.Done()
			pr.Close()
		}()

		var opts []stats.ParsePackfileNegotiationOption
		if featureflag.LsRefsPipelineRefInstrumentation.IsEnabled(ctx) {
			opts = append(opts, stats.WithLsRefsPipelineRefPrefixes())
		}

		stats, errIgnore := stats.ParsePackfileNegotiation(pr, opts...)
		negotiation = &stats
		if errIgnore != nil {
			s.logger.WithError(errIgnore).DebugContext(ctx, "failed parsing packfile negotiation")
			return
		}
		stats.UpdateMetrics(s.packfileNegotiationMetrics, s.packfileNegotiationDeepenMetrics)
		stats.UpdateLsRefsPipelineRefLogFields(ctx)
		stats.UpdateLogFields(ctx)
	}()

	if s.bundleURIManager != nil {
		// Bundle generation is an optimization that is transparent to users.
		// If it fails, we log the error but continue with the regular upload-pack
		// operation without the bundle optimization.
		// If successful, a goroutine is spawned to generate the bundle, in which case
		// the bundle generation becomes independent of the RPC request.
		if err = s.bundleURIManager.GenerateWithStrategy(ctx, repo); err != nil {
			s.logger.WithError(err).Error("failed generating bundle")
		}
		config = append(config, s.bundleURIManager.UploadPackGitConfig(ctx, req.GetRepository())...)
	} else {
		config = append(config, bundleuri.CapabilitiesGitConfig(ctx, false)...)
	}

	objectHash, err := repo.ObjectHash(ctx)
	if err != nil {
		return nil, 0, fmt.Errorf("detecting object hash: %w", err)
	}

	commandOpts := []gitcmd.CmdOpt{
		gitcmd.WithGitProtocol(s.logger, req),
		gitcmd.WithConfig(config...),
		gitcmd.WithPackObjectsHookEnv(objectHash, repoProto, "ssh"),
	}
