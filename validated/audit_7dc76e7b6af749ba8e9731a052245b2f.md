### Title
Protocol fee bypass on NEP-245/IMT token diffs by splitting a transfer into unit (`|delta|<=1`) legs - (File: contracts/defuse/core/src/intents/token_diff.rs)

### Summary
`TokenDiff::token_fee` exempts any NEP-245 (`Imt`)/multi-token delta with `amount <= 1` from fees regardless of the configured `Pips` fee rate. Because this check is evaluated independently per `TokenDiff` intent on that intent's own raw `delta`, a signer can split a large multi-token transfer of `N` units into `N` separate signed `TokenDiff` intents each carrying `delta == -1` for the same `token_id`, causing `Self::token_fee` to hit the `Pips::ZERO` branch on every leg and completely eliminating the fee that a single `delta == -N` intent would have incurred.

### Finding Description
The binding that should hold is: `fee_owed(aggregate_delta = -N) == sum(fee_owed(unit_delta = -1) for i in 1..=N)`. The code breaks this binding.

In `contracts/defuse/core/src/intents/token_diff.rs`, `ExecutableIntent::execute_intent` computes the fee per intent: [1](#0-0) 

which calls `Self::token_fee`: [2](#0-1) 

For `TokenIdType::Nep245`/`Imt`, `token_fee` returns `Pips::ZERO` whenever `amount <= 1`, and only returns the configured `fee` when `amount > 1`. This is evaluated strictly on the raw `delta.unsigned_abs()` of a single `TokenDiff` intent, never on any cross-intent or cross-batch aggregate. `TokenDiff::supply_delta` applies the same per-leg logic used for closure computation: [3](#0-2) 

The existing unit test explicitly enumerates `(Nep245TokenId, 1)` and `(Nep245TokenId, -1)` as valid `#[values]` cases in `closure_delta`, confirming these leg sizes are legitimate, fee-exempt inputs to the same code path: [4](#0-3) 

Exploit: an unprivileged signer who wants to move `N` units of a NEP-245/IMT `token_id` submits `N` separate signed `TokenDiff` intents (or one `MultiPayload` containing `N` intents), each with `diff = {token_id: -1, ...offsetting token_out...}`, instead of a single intent with `diff = {token_id: -N, ...}`. Each intent independently calls `execute_intent`, and each call to `Self::token_fee(token_id, 1, fee)` falls into the `amount > 1` guard failure, returning `Pips::ZERO`, so `fee_ceil(1)` is `0` on every leg. The aggregate fee collected across the batch is `0`, whereas a single `delta = -N` intent (`N > 1`) would have charged `fee.fee_ceil(N) > 0`. No guard (`MultiPayload::verify`, nonce checks, `internal_apply_deltas`, or any cross-intent aggregation) recombines deltas across distinct `TokenDiff` intents before calling `token_fee`, so the divergence is not caught anywhere in `execute_intent`.

### Impact Explanation
This directly matches the Critical category "protocol fees bypassed ... over-collected": the fee collector receives strictly less than the protocol-configured `Pips` fee on any NEP-245/IMT swap or transfer that can be restructured into unit legs, for every signer and every such token, and is fully repeatable per batch with no bound other than the number of intents a signer is willing to sign/submit. The Verifier's internal balances remain net-zero (no funds are stolen from other users), but protocol fee revenue that should have been collected on the aggregate amount is entirely avoided — the specific harm the rules call out as Critical impact ("protocol fees bypassed").

### Likelihood Explanation
Any unprivileged signer with an NEP-245/IMT position can trivially perform this: no special role or victim key is needed, only the ability to sign multiple `TokenDiff` intents for their own balances (the same capability normal solvers/takers already use) and a `token_id` where the multi-token amounts can be freely divided into `1`-unit chunks. The only cost is transaction/intent overhead for `N` legs instead of `1`; there is no other precondition or race window. This is deterministic and 100% reproducible.

### Recommendation
Move fee determination from a per-`TokenDiff`-intent, per-leg basis to an amount-independent or aggregate-independent basis for NEP-245/IMT tokens (e.g., stop exempting fungible-style multi-token balances by raw `amount <= 1`, or key the exemption off whether the `token_id`'s registered supply/decimals indicate it behaves like an NFT rather than off the transient per-intent delta magnitude). Alternatively, aggregate deltas for the same `(signer, token_id)` pair across the whole batch before evaluating the `amount > 1` threshold.

### Proof of Concept
```rust
// contracts/defuse/core/src/intents/token_diff.rs (test module)
#[test]
fn fee_bypass_by_splitting_nep245_delta() {
    let token_id = TokenId::from(Nep245TokenId::new(
        "mt.near".parse::<AccountId>().unwrap(),
        "ft1".to_string(),
    ));
    let fee = Pips::ONE_PERCENT;

    // Single aggregate leg: delta = -100
    let fee_aggregate = TokenDiff::token_fee(&token_id, 100, fee).fee_ceil(100);
    assert!(fee_aggregate > 0);

    // 100 separate unit legs: delta = -1 each
    let mut fee_split_total: u128 = 0;
    for _ in 0..100 {
        let f = TokenDiff::token_fee(&token_id, 1, fee).fee_ceil(1);
        fee_split_total += f;
    }
    assert_eq!(fee_split_total, 0);

    // Binding broken: fee owed on aggregate transfer != fee actually collectible via split legs
    assert_ne!(fee_aggregate, fee_split_total);
}
```
This can be extended to a `near-workspaces` sandbox test executing one `TokenDiff` intent with `delta = -100` against `N = 100` separate `TokenDiff` intents each with `delta = -1` on the same `Nep245` `token_id`/fee, and comparing the emitted `fees_collected` totals from `TokenDiffEvent`.

    /// Returns total supply delta from token delta
    #[inline]
    fn supply_delta(token_id: &TokenId, delta: i128, fee: Pips) -> Option<i128> {
        if delta < 0 {
            // fee is taken only on negative deltas (i.e. token_in)
            delta.checked_mul_div_ceil(
                Self::token_fee(token_id, delta.unsigned_abs(), fee)
                    .invert()
                    .as_pips()
                    .into(),
                Pips::MAX.as_pips().into(),
            )
        } else {
            // token_out
            Some(delta)
        }
    }
