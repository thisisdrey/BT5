### Title
FetchRemote fails to disable `transfer.bundleURI`, enabling SSRF via attacker-controlled remote - ([File: internal/gitaly/service/repository/fetch_remote.go])

### Summary
`FetchRemote` performs a real `git-fetch` against a fully attacker-controlled `RemoteParams.Url` but, unlike `cloneFromURLCommand`'s deliberate SSRF mitigation, never sets `transfer.bundleURI=false`. A malicious remote server can advertise a `bundle.<name>.uri` during protocol v2 negotiation pointing at an internal address (e.g. `http://169.254.169.254/`), and Gitaly's git-fetch client will fetch it automatically.

### Finding Description
`FetchRemote` (`internal/gitaly/service/repository/fetch_remote.go:30-47`) calls `fetchRemoteAtomic`, which builds fetch options via `buildCommandOpts` (lines 260-304). That function sets `remote.inmemory.url` directly to `req.GetRemoteParams().GetUrl()` — a value fully controlled by the RPC caller (an unprivileged user can point this at their own attacker-controlled git server). It then calls `quarantineRepo.FetchRemote(ctx, "inmemory", opts)` (line 104), which executes `git fetch` (`internal/git/localrepo/remote.go:79-138`) against that URL.

The sibling `cloneFromURLCommand` explicitly disables the git-native bundle-uri client feature with a comment stating the exact rationale: *"Drop support for bundle URI when fetching from a remote repository. Since the URI can point to any server, including localhost, this is to prevent attack vectors that could abuse this mechanism"* (`internal/gitaly/service/repository/create_repository_from_url.go:72-75`), by passing `gitcmd.WithGlobalOption(gitcmd.ConfigPair{Key: "transfer.bundleURI", Value: "false"})`.

No equivalent config is applied in `buildCommandOpts` or anywhere in the `FetchOpts`/`Repo.FetchRemote` chain. Since bundle-uri is a client-side git feature that, when enabled/not explicitly disabled and the server advertises a `bundle-uri` capability during protocol v2 negotiation, causes the git client itself to issue an outbound HTTP request to the URI advertised by the (attacker-controlled) remote server — this is a genuine SSRF primitive reachable purely through the `FetchRemote` RPC, with no additional privilege required beyond controlling the remote URL, which the RPC always requires from the caller.

`UpdateRemoteMirror` was also checked but does not share this exposure: it never runs `git fetch`/`git clone` against `remote.GetUrl()`; it only performs `GetRemoteReferences` (ref listing) and `Push` (pushing local objects to the remote), neither of which triggers bundle-uri fetching.

### Impact Explanation
This is an SSRF vulnerability (matches GitLab bounty's SSRF impact class). An attacker with only the ability to create a repository and trigger `FetchRemote` (via mirroring, pull, or any GitLab Rails flow that maps to this RPC) against a remote of their choosing can direct Gitaly's git process to make outbound HTTP requests to internal/otherwise-unreachable addresses (e.g. cloud metadata endpoints), potentially disclosing sensitive metadata/credentials to the attacker via the bundle file content or triggering internal service interaction.

### Likelihood Explanation
Precondition is only that the attacker controls the remote server referenced by `RemoteParams.Url` in a `FetchRemote` call — achievable trivially by any unprivileged user who can configure/import a repository or repository mirror with an attacker-controlled URL and standard git protocol v2 support (advertising `bundle-uri` capability with a malicious URI). No special role, secret, or MITM is required, so this is highly likely to be exploitable and repeatable.

### Recommendation
Apply the same mitigation used in `cloneFromURLCommand`: in `buildCommandOpts` (`internal/gitaly/service/repository/fetch_remote.go`), append `gitcmd.WithGlobalOption(gitcmd.ConfigPair{Key: "transfer.bundleURI", Value: "false"})` to the options passed into `quarantineRepo.FetchRemote`, so any RPC that performs `git fetch` against a caller-supplied URL disables bundle-uri client behavior consistently.

func buildCommandOpts(ctx context.Context, opts *localrepo.FetchOpts, req *gitalypb.FetchRemoteRequest) error {
	remoteURL := req.GetRemoteParams().GetUrl()
	var config []gitcmd.ConfigPair

	for _, refspec := range getRefspecs(req.GetRemoteParams().GetMirrorRefmaps()) {
		config = append(config, gitcmd.ConfigPair{
			Key: "remote.inmemory.fetch", Value: refspec,
		})
	}

	if resolvedAddress := req.GetRemoteParams().GetResolvedAddress(); resolvedAddress != "" {
		modifiedURL, resolveConfig, err := gitcmd.GetURLAndResolveConfig(remoteURL, resolvedAddress)
		if err != nil {
			return fmt.Errorf("couldn't get curloptResolve config: %w", err)
		}

		remoteURL = modifiedURL
		config = append(config, resolveConfig...)
	}

	config = append(config, gitcmd.ConfigPair{Key: "remote.inmemory.url", Value: remoteURL})

	if featureflag.FetchRemoteProactiveAuth.IsEnabled(ctx) {
		if u, err := url.Parse(remoteURL); err == nil && u.User != nil {
			password, _ := u.User.Password()
			if u.User.Username() != "" && password != "" {
				config = append(config, gitcmd.ConfigPair{
					Key:   "http.proactiveAuth",
					Value: "basic",
				})
			}
		}
	}

	if authHeader := req.GetRemoteParams().GetHttpAuthorizationHeader(); authHeader != "" {
		config = append(config, gitcmd.ConfigPair{
			Key:   fmt.Sprintf("http.%s.extraHeader", req.GetRemoteParams().GetUrl()),
			Value: "Authorization: " + authHeader,
		})
	}

	opts.CommandOptions = append(opts.CommandOptions, gitcmd.WithConfigEnv(config...))

	return nil
}

func (repo *Repo) FetchRemote(ctx context.Context, remoteName string, opts FetchOpts) error {
	if err := validateNotBlank(remoteName, "remoteName"); err != nil {
		return err
	}

	var stderr bytes.Buffer
	if opts.Stderr == nil {
		opts.Stderr = &stderr
	}

	objectHash, err := repo.ObjectHash(ctx)
	if err != nil {
		return fmt.Errorf("detecting object hash: %w", err)
	}

	commandOptions := []gitcmd.CmdOpt{
		gitcmd.WithEnv(opts.Env...),
		gitcmd.WithStdout(opts.Stdout),
		gitcmd.WithStderr(opts.Stderr),
		gitcmd.WithConfig(gitcmd.ConfigPair{
			// Git is so kind to point out that we asked it to not show forced updates
			// by default, so we need to ask it not to do that.
			Key: "advice.fetchShowForcedUpdates", Value: "false",
		}),
		gitcmd.WithConfig(gitcmd.ConfigPair{
			// The patch series https://lore.kernel.org/git/20240910203835.2288291-1-bence@ferdinandy.com/
			// introduces new behaviour that automatically sets the local HEAD to the remote's HEAD during
			// a fetch. This happens when the mirror refspec is used to fetch into a bare repository, which
			// we use in operations like `FetchBundle`.
			//
			// Setting the remote's `followremotehead` config to "never" will disable the new behaviour. We
			// do this temporarily until we're sure the new behaviour doesn't have any consequences.
			Key: fmt.Sprintf("remote.%s.followremotehead", remoteName), Value: "never",
		}),
	}
	if opts.DisableTransactions {
		commandOptions = append(commandOptions, gitcmd.WithDisabledHooks())
	} else {
		commandOptions = append(commandOptions, gitcmd.WithRefTxHook(objectHash, repo))
	}
	commandOptions = append(commandOptions, opts.CommandOptions...)

	cmd, err := repo.Exec(ctx,
		gitcmd.Command{
			Name:  "fetch",
			Flags: opts.buildFlags(),
			Args:  []string{remoteName},
		},
		commandOptions...,
	)
	if err != nil {
		return err
	}

	if err := cmd.Wait(); err != nil {
		return FetchFailedError{errorWithStderr(err, stderr.Bytes())}
	}

	return nil
}
