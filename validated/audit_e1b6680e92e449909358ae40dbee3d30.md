### Title
Protocol fee bypass on NEP-245/IMT token diffs via unit-sized intent splitting - (File: `contracts/defuse/core/src/intents/token_diff.rs`)

### Summary
`TokenDiff::execute_intent` computes and collects the protocol fee independently for every single `TokenDiff` intent, using only that intent's own delta magnitude. `TokenDiff::token_fee` deliberately waives the fee (`Pips::ZERO`) whenever the token is `Nep245` or `Imt` and the delta magnitude is `<= 1`. Because a signer can pack an arbitrary number of `TokenDiff` intents into a single signed `DefuseIntents` payload, and each is fee-evaluated in isolation, an attacker can split what should be one fee-bearing swap of `N` units of a NEP-245/IMT-wrapped asset into `N` unit-sized `TokenDiff` intents, each individually qualifying for the `amount <= 1` fee exemption, and thereby pay **zero** protocol fee on the aggregate swap.

### Finding Description
The fee-collection logic lives in `TokenDiff::execute_intent`: [1](#0-0) 

For every negative delta (`token_in`) inside *that single intent's* `diff` map, the fee is `Self::token_fee(token_id, amount, protocol_fee).fee_ceil(amount)`, where `amount = delta.unsigned_abs()` — the magnitude within that one intent only.

`token_fee` explicitly zeroes the fee for `Nep245`/`Imt` tokens when the per-intent amount is `1` or less: [2](#0-1) 

Intents inside one signed payload are executed in a simple loop with no cross-intent fee aggregation: [3](#0-2) 

Because the engine settles the whole batch by checking that all token deltas across every executed intent net to zero (the global conservation invariant), a signer (or coordinated signer + counterparty) can achieve the exact same net economic transfer of `N` units of a `Nep245`/`Imt` asset by submitting `N` separate `TokenDiff` intents with `delta = ±1` instead of a single intent with `delta = ±N`. Each of the `N` unit intents independently satisfies `amount <= 1` and is charged `Pips::ZERO`, whereas the single, economically-equivalent `N`-unit intent would have been charged `protocol_fee` on the full amount.

This breaks the "fees owed versus fees collected" binding: the fee owed by the protocol's fee schedule for moving `N` units of a fee-bearing asset is `protocol_fee.fee_ceil(N)`, but the fee actually collected can be driven to `0` purely by re-encoding the same transfer as `N` unit-sized intents, all authorized by the signer's own signature(s), with no privileged role, no relayer, and no deployment misconfiguration involved.

### Impact Explanation
This is a direct fee-bypass on `Nep245`/`Imt`-typed token legs of `TokenDiff` swaps (e.g., MT-wrapped positions such as tokens deposited across nested Defuse/Verifier instances, per `contracts/defuse/src/contract/tokens/nep245/deposit.rs`). Any solver or trader routing volume through NEP-245/IMT-denominated legs can structure their intents as repeated unit-sized `TokenDiff`s to avoid protocol fees entirely on that leg, resulting in the fee collector permanently losing the fee revenue it should have received — this falls under the Critical impact category "fees bypassed or over-collected."

### Likelihood Explanation
The attack requires no special privileges — any account holder able to sign `DefuseIntents` payloads and call the public `execute_intents` entrypoint can do this. It only requires constructing more, smaller intents (all within normal usage) instead of one larger intent, and a counterparty (or self-matching structure) willing to net the deltas to zero. Given solvers/market-makers process significant recurring volume on NEP-245-denominated legs, this bypass is straightforward and repeatable, and profitable proportionally to the trade size and fee rate.

### Recommendation
Compute and apply the fee-exemption threshold (`amount <= 1`) based on the total position size held/transferred over the underlying token (or accumulate/aggregate deltas per `token_id` across all intents in the same signed payload / execution batch) rather than per individual `TokenDiff` intent. Alternatively, remove or tighten the `Nep245`/`Imt` `amount <= 1` fee exemption so it cannot be trivially satisfied by splitting a larger swap into many unit-sized intents, e.g., track cumulative negative deltas per `(signer, token_id)` within `Engine::execute_signed_intents` before applying the exemption.

### Proof of Concept
1. Attacker deposits/holds a `Nep245`-typed balance (e.g., wrapped FT balance from a nested Defuse contract) that would normally accrue `protocol_fee` on `TokenDiff` swaps.
2. Instead of signing one `DefuseIntents` payload with a single `TokenDiff` intent `{diff: {nep245_token: -100, token_out: +X}}` (which would charge `protocol_fee.fee_ceil(100)`), the attacker (optionally with solver counterparty legs) signs a payload whose `intents: Vec<Intent>` contains 100 separate `TokenDiff` intents, each `{diff: {nep245_token: -1, token_out: +x_i}}`.
3. Each of the 100 `TokenDiff::execute_intent` calls independently evaluates `Self::token_fee(nep245_token, 1, protocol_fee)`, which returns `Pips::ZERO` per `contracts/defuse/core/src/intents/token_diff.rs:206-217`, so `fee_ceil(1) == 0` every time.
4. `execute_signed_intents` sums all deltas globally via `Deltas`/`finalize()`; as long as the aggregate deltas across the whole batch (from the attacker's and counterparty's intents) net to zero, the transaction succeeds with the exact same net token movement as step 2's single intent, but with `0` total protocol fee collected instead of `protocol_fee.fee_ceil(100)`.
