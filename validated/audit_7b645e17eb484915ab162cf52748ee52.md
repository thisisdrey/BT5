### Title
Repository write-lock can be renewed indefinitely across arbitrary subtransactions without any bound, starving all other writers to the same repository - (File: internal/praefect/transactions/manager.go)

### Summary
Praefect's `WriteLockManager` serializes writes to a repository by acquiring a lock at `PREPARING_PHASE` and holding it until `COMMITTED_PHASE` [1](#0-0) . Each `PREPARED_PHASE` vote unconditionally calls `lock.Renew(ctx)`, pushing the lock's expiry 20 seconds into the future with no upper bound on how many times this can happen or how long the overall hold can last [2](#0-1) [3](#0-2) . A transaction can contain an unbounded number of `subtransaction`s, one per reference-transaction hook invocation `t.subtransactions = append(t.subtransactions, subtransaction)` [4](#0-3) , and each hook invocation that lands on `PREPARED_PHASE` triggers another renewal. As long as the client driving the push keeps the reference-transaction hook alive and never lets the process reach `COMMITTED_PHASE` (or an error), the lock is renewed forever and the repository is starved for all other writers, mirroring the "riskless trade" pattern where a cheap, unchecked renewal action defeats an expiry-gated mechanism.

### Finding Description
This is the closest reachable Gitaly analog to the "delay renewal defeats a closing gate" bug class from the report. The three structural ingredients from the original bug map directly:

1. **Renewal happens with no gating check.** `lockRepoForTransaction` renews the lock on every `PREPARED_PHASE` vote unconditionally — there's no check on how long the lock has already been held, how many times it has been renewed, or whether the underlying push is making forward progress [2](#0-1) .
2. **Release only happens at `COMMITTED_PHASE` or on error.** `unlockRepoForTransaction` only releases the lock when the phase is `COMMITTED_PHASE`, or when `PREPARING_PHASE`/`PREPARED_PHASE` returned an error [5](#0-4) . A client that keeps voting `PREPARED_PHASE` successfully never triggers a release.
3. **The renewal is cheap and repeatable by an ordinary pushing client.** A single logical push can involve many reference-transaction hook invocations, and the `transaction` type explicitly supports an unbounded sequence of `subtransaction`s, each of which can independently reach the `PREPARED_PHASE` step and call `Renew` [6](#0-5) . There is no cap in `RegisterTransaction`/`voteTransaction` on the number of subtransactions or on total lock hold time [7](#0-6) .

The `renew` SQL only checks that the caller still owns the lock row (`holder_txn_id = $2`); it does not check any absolute maximum lifetime for the lock [3](#0-2) . The design doc for this feature even documents the renewal as intentionally unconditional at `PREPARED_PHASE`, with only 20-second segments extended indefinitely as long as the transaction stays alive.

### Impact Explanation
If a client can keep a push's reference-transaction hook oscillating in/near the `PREPARED_PHASE` step (e.g., a slow or deliberately stalled client controlling pack transfer timing, or a client that triggers many incremental subtransactions per push) without ever completing to `COMMITTED_PHASE`, it holds the exclusive per-repository write lock indefinitely. Since `WriteLockManager.Lock` blocks all other transactions targeting the same `virtualStorage|relativePath` until the lock is released or its holder-owned row is deleted [8](#0-7) , this starves every other write (from any user) to that repository — a denial of service of the Praefect write path for that repository, analogous to the smart-contract exploit where cheap renewal indefinitely defeats an expiry-based enforcement gate.

### Likelihood Explanation
Exploitability depends on how much control an ordinary pushing client actually has over the number/pacing of reference-transaction hook phase transitions for a single push — this is driven by Git's internal hook invocation logic and by how many ref updates/subtransactions a single push produces, which I was not able to fully verify by reading `internal/gitaly/service/hook/reference_transaction.go` in enough depth (tool budget ran out before confirming whether client behavior alone, versus network/process stalls, can indefinitely postpone `COMMITTED_PHASE` transitions). This is a genuine gap in verification: it is plausible but unconfirmed that an unprivileged client can reliably keep re-triggering `PREPARED_PHASE` renewals without bound purely through push behavior (e.g., many refs, slow transfer, or repeated retries) rather than via a privileged/malicious Gitaly node.

### Recommendation
Bound the total lifetime of a repository write lock independent of how many times it is renewed, e.g., track an absolute lock-acquired timestamp and refuse to renew (or force-release and fail the transaction) past a maximum total hold duration. Additionally, consider capping the number of subtransactions/hook phase round-trips a single registered transaction may go through before it must either commit or be forcibly stopped, so that `PREPARED_PHASE` renewal cannot be used to hold the lock indefinitely.

### Proof of Concept
Not independently reproduced against a live Praefect cluster in this analysis; the existing test `TestRepositoryReferenceWriteLock/"renew extends lock and prevents acquisition by another txn"` already demonstrates the core renewal mechanic in isolation [9](#0-8) . Confirming full end-to-end exploitability (i.e., that an ordinary unprivileged push can trigger unbounded `PREPARED_PHASE` renewals without ever reaching `COMMITTED_PHASE`) requires further investigation of `internal/gitaly/service/hook/reference_transaction.go` and the coordinator's handling of multi-ref pushes, which could not be completed within the available tool budget.

func (mgr *Manager) RegisterTransaction(ctx context.Context, voters []Voter, threshold uint) (Transaction, CancelFunc, error) {
	mgr.lock.Lock()
	defer mgr.lock.Unlock()

	transactionID := atomic.AddUint64(&mgr.idSequence, 1)

	transaction, err := newTransaction(transactionID, voters, threshold)
	if err != nil {
		return nil, nil, err
	}

	if _, ok := mgr.transactions[transactionID]; ok {
		return nil, nil, errors.New("transaction exists already")
	}
	mgr.transactions[transactionID] = transaction

	mgr.logger.WithFields(log.Fields{
		"transaction.id":     transactionID,
		"transaction.voters": voters,
	}).DebugContext(ctx, "RegisterTransaction")

	mgr.counterMetric.WithLabelValues("registered").Add(float64(len(voters)))

	return transaction, func() error {
		return mgr.cancelTransaction(ctx, transaction)
	}, nil
}

func (mgr *Manager) cancelTransaction(ctx context.Context, transaction *transaction) error {
	mgr.lock.Lock()
	defer mgr.lock.Unlock()

	delete(mgr.transactions, transaction.ID())
	// Release while holding mgr.lock so a concurrent voteTransaction can't
	// re-acquire the repo lock between delete and cancel.
	mgr.releaseRepoLock(transaction.ID())
	transaction.cancel()
	mgr.subtransactionsMetric.Observe(float64(transaction.CountSubtransactions()))

	var committed uint64
	state, err := transaction.State()
	if err != nil {
		return err
	}

	for _, result := range state {
		if result == VoteCommitted {
			committed++
		}
	}

	mgr.logger.WithFields(log.Fields{
		"transaction.id":              transaction.ID(),
		"transaction.committed":       fmt.Sprintf("%d/%d", committed, len(state)),
		"transaction.subtransactions": transaction.CountSubtransactions(),
	}).InfoContext(ctx, "transaction completed")

	return nil
}

func (mgr *Manager) voteTransaction(ctx context.Context, transactionID uint64, storageName, repoRelativePath, node string,
	phase gitalypb.VoteTransactionRequest_Phase, vote voting.Vote,
) (returnedErr error) {
	mgr.lock.Lock()
	transaction, ok := mgr.transactions[transactionID]
	mgr.lock.Unlock()

	if !ok {
		return fmt.Errorf("%w: %d", ErrNotFound, transactionID)
	}

	err := mgr.lockRepoForTransaction(ctx, transactionID, storageName, repoRelativePath, phase)
	if err != nil {
		return fmt.Errorf("lock transaction %d: %w", transactionID, err)
	}
	defer func() {
		mgr.unlockRepoForTransaction(ctx, transactionID, returnedErr, phase)
	}()
	if err := transaction.vote(ctx, node, vote); err != nil {
		return err
	}

	return nil
}

func (mgr *Manager) lockRepoForTransaction(ctx context.Context, transactionID uint64, storageName, repoRelativePath string,
	phase gitalypb.VoteTransactionRequest_Phase,
) error {
	if featureflag.PraefectSerializedWrite.IsDisabled(ctx) {
		return nil
	}

	switch phase {
	case gitalypb.VoteTransactionRequest_PREPARING_PHASE:
		lock, err := mgr.repoWriteLockMgr.Lock(ctx, storageName, repoRelativePath, transactionID)
		if err != nil {
			return fmt.Errorf("try lock: %w", err)
		}
		mgr.repoLocks.Store(transactionID, lock)

	case gitalypb.VoteTransactionRequest_PREPARED_PHASE, gitalypb.VoteTransactionRequest_COMMITTED_PHASE:
		v, ok := mgr.repoLocks.Load(transactionID)
		if !ok {
			// No Preparing was cast for this transaction. This happens when Git itself drives
			// the reference-transaction hook on a Git build that doesn't emit "preparing"
			// (i.e. pre-2.54). Skip lock work; serialization is dormant for this path
			// until GIT_VERSION_PREV is bumped past 60d8c1e9.
			mgr.logger.WithFields(log.Fields{
				"transaction.id": transactionID,
				"phase":          phase.String(),
			}).DebugContext(ctx, "skipping lock check: no preparing phase recorded")
			return nil
		}
		lock := v.(datastore.RepoLock)
		if err := lock.Renew(ctx); err != nil {
			return err
		}
	}
	return nil
}

func (mgr *Manager) unlockRepoForTransaction(ctx context.Context, transactionID uint64, returnedErr error, phase gitalypb.VoteTransactionRequest_Phase) {
	if featureflag.PraefectSerializedWrite.IsDisabled(ctx) {
		return
	}

	// Decide whether this call releases the write lock. The lock spans all the
	// phases of one transaction and is only released when either the vote
	// failed (so callers can't advance to the next phase) or the committed
	// phase completes. Phases outside the reference transaction hook
	// lifecycle (e.g. SYNCHRONIZED_PHASE) never acquired a lock.
	var shouldUnlock bool
	switch phase {
	case gitalypb.VoteTransactionRequest_PREPARING_PHASE,
		gitalypb.VoteTransactionRequest_PREPARED_PHASE:
		shouldUnlock = returnedErr != nil
	case gitalypb.VoteTransactionRequest_COMMITTED_PHASE:
		shouldUnlock = true
	default:
		return
	}

	if !shouldUnlock {
		return
	}

	mgr.releaseRepoLockOnPhase(transactionID, phase.String())
}

// renew extends the expiry of the write lock held by txnID by another renewInterval.
// It returns an error if the lock is not currently held by txnID.
func (r *RepoReferenceWriteLockManager) renew(ctx context.Context, virtualStorage string, relativePath string, txnID uint64) error {
	query := `
UPDATE repository_reference_write_locks as locks
SET  expired_at = (NOW() + $3::interval)
WHERE locks.lock_id = $1 AND holder_txn_id = $2
RETURNING expired_at;
`
	lockID := repoLockID(virtualStorage, relativePath)
	start := time.Now()
	rows, err := r.qc.QueryContext(ctx, query, lockID, txnID, r.renewInterval)
	r.operationDuration.WithLabelValues(virtualStorage, "renew").Observe(time.Since(start).Seconds())
	if err != nil {
		return fmt.Errorf("renew repo reference write lock (executing query): %s, %w", lockID, err)
	}
	defer func() {
		if err := rows.Close(); err != nil {
			r.logger.WithError(err).Error("close rows")
		}
	}()
	if rows.Next() {
		return nil
	}
	if err := rows.Err(); err != nil {
		return fmt.Errorf("renew repo reference write lock (iterating rows): %s, %w", lockID, err)
	}
	return fmt.Errorf("renew repo reference write lock (no rows): %s", lockID)
}

// getOrCreateSubtransaction gets an ongoing subtransaction on which the given
// node hasn't yet voted on or creates a new one if the node has succeeded on
// all subtransactions. In case the node has failed on any of the
// subtransactions, an error will be returned.
func (t *transaction) getOrCreateSubtransaction(node string) (*subtransaction, error) {
	t.lock.Lock()
	defer t.lock.Unlock()

	switch t.state {
	case transactionOpen:
		// expected state, nothing to do
	case transactionCanceled:
		return nil, ErrTransactionCanceled
	case transactionStopped:
		return nil, ErrTransactionStopped
	default:
		return nil, errors.New("invalid transaction state")
	}

	// Check for pending subtransactions on the specified node.
	if subtransactions, err := t.getPendingNodeSubtransactions(node); err != nil {
		return nil, err
	} else if len(subtransactions) != 0 {
		// First pending subtransaction is the next in queue for processing.
		return subtransactions[0], nil
	}

	// If we arrive here, then we know that all the node has voted and
	// reached quorum on all subtransactions. We can thus create a new one.
	subtransaction, err := t.createSubtransaction()
	if err != nil {
		return nil, err
	}

	t.subtransactions = append(t.subtransactions, subtransaction)

	return subtransaction, nil
}
