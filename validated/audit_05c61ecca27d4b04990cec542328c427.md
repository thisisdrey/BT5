## Analog Found

### Title
Uncaught heap-array index overflow in `PrecompiledContracts.ValidateMultiSign.execute()` from unvalidated attacker-controlled offsets - (File: actuator/src/main/java/org/tron/core/vm/PrecompiledContracts.java)

### Summary
The iccDEV bug class is an out-of-bounds heap read caused by using an untrusted, unvalidated index/length taken from parsed data to walk an array (`ApplySequence`). The same pattern exists in java-tron's `ValidateMultiSign` TVM precompiled contract: attacker-controlled `DataWord` offsets and lengths taken directly from the smart-contract call's `rawData` are used to index into the `words[]` array and to slice the raw `data` buffer, with no bound check on the derived index before the array access, and — critically — this code executes **outside** any try/catch.

### Finding Description
`ValidateMultiSign.execute()` parses caller-controlled calldata into an array of 32-byte words and immediately indexes it without validating that the indices are in range: [1](#0-0) [2](#0-1) 

`words[1]`, `words[2]`, `words[3]` are dereferenced unconditionally, and `words[words[3].intValueSafe() / WORD_SIZE]` uses an attacker-supplied division result as an array index for the `sigArraySize` check. The helper functions it calls have the same weakness — they bounds-check only the starting `offset`, then read `len` from attacker data and loop past the array end: [3](#0-2) 

None of this — `DataWord.parseArray(rawData)`, the `words[1]/[2]/[3]` reads, the `sigArraySize` computation, or the `extractSigArray`/`extractBytesArray` calls — is inside the method's `try { ... } catch (Throwable t)` block, which only wraps the later signature-recovery loop starting at `AccountCapsule account = this.getDeposit().getAccount(address);`. A crafted `len` or offset therefore throws an uncaught `ArrayIndexOutOfBoundsException` (or similar) directly out of `execute()`.

This is a documented, acknowledged gap: a companion test for the sibling `ValidateMultiSign`/`BatchValidateSign` pair notes explicitly that before the `allowTvmOsaka` guard is activated, malformed/short calldata "reaches the legacy decoder" and "this precompile has no outer catch, so a too-short input raises inside the decoder; that is the documented pre-activation failure mode": [4](#0-3) 

Even when `VMConfig.allowTvmOsaka()` is active, the added `isValidAbiEncoding` guard only validates the overall byte-length shape of `rawData` (multiple of `WORD_SIZE`, tail consistent with `headerWords`/`itemWords`); it does not validate that the embedded offset/length fields extracted from the payload actually stay within the array/buffer bounds: [5](#0-4) 

Notably, the sibling `BatchValidateSign` precompile has the exact same offset/length parsing pattern but wraps it entirely in `execute() { try { return doExecute(data); } catch (Throwable t) { ... return safe default; } }`, which safely absorbs the same class of exception: [6](#0-5) 
`ValidateMultiSign` lacks this outer guard, making it the analog of `ApplySequence()`'s unguarded index usage.

### Impact Explanation
Any account can trigger this by issuing a `CALL`/`STATICCALL` (directly or via a deployed contract) to the `ValidateMultiSign` precompile address with a crafted, short or offset-manipulated payload. This reaches `PrecompiledContracts.getContractForAddress` dispatch in the TVM execution path from a normal broadcast transaction. The resulting uncaught exception surfaces from `execute()` into the TVM's precompiled-call handling; at minimum this is an unhandled-exception/DoS condition in transaction execution reachable by any unprivileged caller, matching the OOB-read/crash bug class of the reported CVE.

### Likelihood Explanation
High reachability: no special privileges are required, just a transaction/contract call to a known precompile address with attacker-chosen calldata. The vulnerable parsing code executes unconditionally before any signature/permission checks and before the method's own try/catch begins.

### Recommendation
Wrap the entire `ValidateMultiSign.execute()` body (from `DataWord.parseArray` through `extractSigArray`/`extractBytesArray`) in the same defensive `try { ... } catch (Throwable t) { return Pair.of(true, DATA_FALSE); }` pattern already used in `BatchValidateSign.execute()`, and additionally validate that every offset/length derived from `words[...]` stays within `words.length` and within `data.length` before use in `extractBytesArray`, `extractSigArray`, and the `sigArraySize`/`addrArraySize` lookups, mirroring `isValidAbiEncoding`'s intent but applied to the derived indices, not just total length.

### Proof of Concept
Construct a TVM `CALL` (e.g. from a simple Solidity contract or a raw transaction with `TriggerSmartContract`) to the `ValidateMultiSign` precompiled contract address with:
1. `rawData.length < 128` bytes (fewer than 4 words) — `words[3]` access in `sigArraySize`/offset computation throws `ArrayIndexOutOfBoundsException` before any try/catch is entered, matching the documented pre-activation failure mode in `ValidateMultiSignContractTest.testTip854PreActivationNoOp`.
2. Or, with `allowTvmOsaka` active and length-shape valid, set `words[3]` (the offset word) to a value whose `/WORD_SIZE` division points past `words.length`, or set the length word at that offset to a large value so the subsequent loop in `extractSigArray`/`extractBytesArray` reads `words[offset + i + 1]` past the end of the parsed array, or slices `data` past its bounds in `extractBytes`.

  private static byte[][] extractBytesArray(DataWord[] words, int offset, byte[] data) {
    if (offset > words.length - 1) {
      return new byte[0][];
    }
    int len = words[offset].intValueSafe();
    byte[][] bytesArray = new byte[len][];
    for (int i = 0; i < len; i++) {
      int bytesOffset = words[offset + i + 1].intValueSafe() / WORD_SIZE;
      int bytesLen = words[offset + bytesOffset + 1].intValueSafe();
      bytesArray[i] = extractBytes(data, (bytesOffset + offset + 2) * WORD_SIZE,
          bytesLen);
    }
    return bytesArray;
  }

  private static byte[][] extractSigArray(DataWord[] words, int offset, byte[] data) {
    if (offset > words.length - 1) {
      return new byte[0][];
    }
    int len = words[offset].intValueSafe();
    byte[][] bytesArray = new byte[len][];
    for (int i = 0; i < len; i++) {
      int bytesOffset = words[offset + i + 1].intValueSafe() / WORD_SIZE;
      bytesArray[i] = extractBytes(data, (bytesOffset + offset + 2) * WORD_SIZE,
          SIG_LENGTH);
    }
    return bytesArray;
  }

  private static byte[] extractBytes(byte[] data, int offset, int len) {
    return Arrays.copyOfRange(data, offset, offset + len);
  }

    if (data == null || data.length % WORD_SIZE != 0) {
      return false;
    }
