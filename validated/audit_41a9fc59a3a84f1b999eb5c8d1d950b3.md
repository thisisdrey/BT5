### Title
Push-over-Pull DOS in `vesting::distribute()` Blocks All Shareholders via `deposit_coins` Abort — (`File: aptos-move/framework/aptos-framework/sources/vesting.move`)

---

### Summary

`vesting::distribute()` iterates over every shareholder in a vesting contract and **pushes** `AptosCoin` to each beneficiary address via `aptos_account::deposit_coins`. If any single push aborts, the entire transaction reverts. A single shareholder (or their admin-assigned beneficiary) can permanently wedge the distribution loop by holding an account that has no `CoinStore<AptosCoin>` and has opted out of direct coin transfers, causing `deposit_coins` to abort with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS`. This permanently locks every other shareholder's vested and reward funds inside the contract.

---

### Finding Description

`vesting::distribute()` collects all withdrawable stake and then iterates over the full shareholder list in a single transaction:

```move
shareholders.for_each_ref(|shareholder| {
    let shareholder = *shareholder;
    ...
    let recipient_address = get_beneficiary(vesting_contract, shareholder);
    aptos_account::deposit_coins(recipient_address, share_of_coins); // ← aborts here
});
``` [1](#0-0) 

`aptos_account::deposit_coins` contains the following guard:

```move
if (!coin::is_account_registered<CoinType>(to)) {
    assert!(
        can_receive_direct_coin_transfers(to),
        error::permission_denied(EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS)
    );
    ...
};
``` [2](#0-1) 

`can_receive_direct_coin_transfers` returns `false` when the account has explicitly called `set_allow_direct_coin_transfers(false)`:

```move
public fun can_receive_direct_coin_transfers(account: address): bool {
    !exists<DirectTransferConfig>(account)
        || borrow_global<DirectTransferConfig>(account).allow_arbitrary_coin_transfers
}
``` [3](#0-2) 

`set_allow_direct_coin_transfers` is a public entry function callable by any account: [4](#0-3) 

The critical precondition is that `coin::is_account_registered<AptosCoin>(to)` must be `false`. After the APT fungible-asset migration, `aptos_account::create_account` calls `register_apt`, which creates a **primary fungible store** — not a `CoinStore<AptosCoin>`. Therefore any account created post-migration (or any account that never explicitly called `coin::register<AptosCoin>`) will have `is_account_registered<AptosCoin>` return `false`, making the `DirectTransferConfig` gate active.

The same structural flaw exists in `staking_contract::distribute_internal`, which uses an identical while-loop push pattern:

```move
while (distribution_pool.shareholders_count() > 0) {
    ...
    aptos_account::deposit_coins(
        recipient, coin::extract(&mut coins, amount_to_distribute)
    );
};
``` [5](#0-4) 

---

### Impact Explanation

- `distribute()` is the **only** mechanism by which vested tokens and staking rewards flow out of the vesting contract to shareholders.
- A single aborting `deposit_coins` call reverts the entire transaction, leaving the extracted `coins` value undelivered and the contract state unchanged.
- All other shareholders — who have done nothing wrong — are permanently unable to receive their vested APT or accumulated rewards.
- `terminate_vesting_contract` internally calls `distribute()` first, so even contract termination is blocked.
- Funds remain locked inside the vesting contract with no recovery path. [6](#0-5) 

---

### Likelihood Explanation

- Any shareholder whose beneficiary address was set to a post-migration account (no `CoinStore<AptosCoin>`) and who calls `set_allow_direct_coin_transfers(false)` triggers the DOS.
- `set_allow_direct_coin_transfers` is a public, unprivileged, zero-cost entry function.
- The admin can set beneficiaries, but shareholders can also be their own beneficiary (default). A malicious or griefing shareholder needs only two transactions: one to ensure no legacy coin store exists, one to opt out of direct transfers.
- The attack is permanent: once the distribution loop is wedged, no on-chain mechanism unblocks it without a framework upgrade.

---

### Recommendation

Replace the push pattern with a pull pattern:

1. **Record entitlements**: In `distribute()`, compute each shareholder's share and store it in a per-address claimable balance table inside the `VestingContract` resource instead of immediately transferring.
2. **Add a `claim(contract_address)` entry function**: Let each shareholder pull their own balance independently. A single shareholder's inability to receive coins does not affect others.
3. Apply the same fix to `staking_contract::distribute_internal`.

This mirrors the Pull-over-Push pattern recommended in the original Solidity report and eliminates the single-point-of-failure in the distribution loop.

---

### Proof of Concept

```
1. Admin creates a vesting contract with shareholders [Alice, Bob].
2. Bob creates a fresh account (post-FA-migration, no CoinStore<AptosCoin>).
3. Bob calls aptos_account::set_allow_direct_coin_transfers(false).
   → Bob's DirectTransferConfig.allow_arbitrary_coin_transfers = false.
4. Time passes; rewards accumulate; lockup expires.
5. Anyone calls vesting::distribute(contract_address).
6. The loop reaches Bob's entry:
     deposit_coins(bob_address, bob_share)
     → coin::is_account_registered<AptosCoin>(bob) == false  (no CoinStore)
     → can_receive_direct_coin_transfers(bob) == false        (opted out)
     → abort EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS
7. Entire transaction reverts.
8. Alice's share is never delivered. Alice's funds are permanently locked.
9. Every subsequent call to distribute() hits the same abort.
10. terminate_vesting_contract also fails (it calls distribute() internally).
``` [7](#0-6) [8](#0-7)

    /// Distribute any withdrawable stake from the stake pool.
    public entry fun distribute(contract_address: address) acquires VestingContract {
        assert_active_vesting_contract(contract_address);

        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        let coins = withdraw_stake(vesting_contract, contract_address);
        let total_distribution_amount = coin::value(&coins);
        if (total_distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };

        // Distribute coins to all shareholders in the vesting contract.
        let grant_pool = &vesting_contract.grant_pool;
        let shareholders = &grant_pool.shareholders();
        shareholders.for_each_ref(|shareholder| {
            let shareholder = *shareholder;
            let shares = pool_u64::shares(grant_pool, shareholder);
            let amount = pool_u64::shares_to_amount_with_total_coins(grant_pool, shares, total_distribution_amount);
            let share_of_coins = coin::extract(&mut coins, amount);
            let recipient_address = get_beneficiary(vesting_contract, shareholder);
            aptos_account::deposit_coins(recipient_address, share_of_coins);
        });

        // Send any remaining "dust" (leftover due to rounding error) to the withdrawal address.
        if (coin::value(&coins) > 0) {
            aptos_account::deposit_coins(vesting_contract.withdrawal_address, coins);
        } else {
            coin::destroy_zero(coins);
        };

        emit(
            Distribute {
                admin: vesting_contract.admin,
                vesting_contract_address: contract_address,
                amount: total_distribution_amount,
            },
        );
    }

    public entry fun set_allow_direct_coin_transfers(
        account: &signer, allow: bool
    ) acquires DirectTransferConfig {
        let addr = signer::address_of(account);
        if (exists<DirectTransferConfig>(addr)) {
            let direct_transfer_config = borrow_global_mut<DirectTransferConfig>(addr);
            // Short-circuit to avoid emitting an event if direct transfer config is not changing.
            if (direct_transfer_config.allow_arbitrary_coin_transfers == allow) { return };

            direct_transfer_config.allow_arbitrary_coin_transfers = allow;

            emit(
                DirectCoinTransferConfigUpdated {
                    account: addr,
                    new_allow_direct_transfers: allow
                }
            );
        } else {
            let direct_transfer_config = DirectTransferConfig {
                allow_arbitrary_coin_transfers: allow,
                update_coin_transfer_events: new_event_handle<
                    DirectCoinTransferConfigUpdatedEvent>(account)
            };
            emit(
                DirectCoinTransferConfigUpdated {
                    account: addr,
                    new_allow_direct_transfers: allow
                }
            );
            move_to(account, direct_transfer_config);
        };
    }
