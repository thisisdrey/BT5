### Title
Withdrawal lock check relies on a manipulable oracle quote — same-transaction price inflation unlocks collateral backing debt, leaving the pool insolvent - ([File: contracts/DepositToken.sol](contracts/DepositToken.sol))

### Summary
The readlink-race bug class is "a value is read to size a security decision, then acted on, while the value can differ from the state it was assumed to reflect" (TOCTOU on an external read). The strongest reachable analog in Metronome is `DepositToken.unlockedBalanceOf()`/`_revertIfLocked()`: the amount of msdTOKEN a debtor may withdraw is derived from the *current* oracle price of the collateral, and `withdraw()` performs no post-withdraw health check. An attacker who can move the collateral's USD quote within one transaction (e.g., vault-share collateral priced from a manipulable share price, or an AMM-priced underlying — same-transaction manipulation is in scope) can withdraw collateral that should remain locked against their debt, then unwind the price and strand the pool with bad debt.

### Finding Description
`withdraw()` gates solely on `_revertIfLocked`, which calls `unlockedBalanceOf()`:

```solidity
// contracts/DepositToken.sol L383-397
function unlockedBalanceOf(address account_) public view override returns (uint256 _unlockedBalance) {
    IPool _pool = pool;
    (, , uint256 _debtInUsd, , uint256 _issuableInUsd) = _pool.debtPositionOf(account_);
    if (_debtInUsd == 0) {
        return balanceOf[account_];
    }
    if (_issuableInUsd > 0) {
        _unlockedBalance = Math.min(
            balanceOf[account_],
            _pool.masterOracle().quoteUsdToToken(address(underlying), _issuableInUsd.wadDiv(collateralFactor))
        );
    }
}
``` [1](#0-0) 

Algebraically, for a single-collateral position with `A` deposit tokens, debt `D` (USD), collateral factor `CF`, and collateral price `P`:

```
unlocked = min(A, A - D / (CF · P))
```

The locked remainder equals `D / (CF · P)` tokens — i.e., exactly enough collateral, *at the price P observed during the check*, to back the debt. The protocol implicitly assumes `P` is stable between the check and subsequent settlement. It is not: `unlockedBalanceOf` re-queries `masterOracle().quoteUsdToToken` on every call, and `withdraw()` simply burns the shares and calls `treasury().pull(to_, _withdrawn)` with no re-verification of the position's health afterward. [2](#0-1) [3](#0-2) 

Attack path (all one transaction, unprivileged):

1. Deposit `A` units of a collateral whose oracle quote is manipulable in-transaction (e.g., a vault-share token whose price-per-share is derived from pool/strategy balances — donatable — or an underlying whose oracle route resolves via an on-chain AMM). `deposit()` measures the Treasury balance delta, so this is a normal deposit.
2. Issue synthetic debt up to the limit: `debtToken.issue(amount, attacker)` where `amount ≈ quoteUsdToToken(synth, issuableLimit)`. Position is healthy at true price.
3. Inflate the collateral's oracle quote to `P' >> P` (donation/flash-manipulated share price or AMM spot in the oracle path). Now `D / (CF · P')` collapses toward zero, so `unlockedBalanceOf(attacker) ≈ A`.
4. Call `depositToken.withdraw(A, attacker)`. `_revertIfLocked` passes because the *stale/manipulated* `P'` makes almost everything "unlocked"; `_withdraw` burns the msdTOKEN and `treasury().pull` pays out nearly all the underlying.
5. Unwind the price manipulation. The account still owes `D` but holds almost no collateral. Repayment of the flash capital comes from the withdrawn collateral; the debt is left as bad debt for the pool.

The invariant broken is solvency: locked collateral is supposed to guarantee `debtInUsd <= issuableLimitInUsd` at real prices, but the lock is evaluated against a price that no longer holds when the dust settles — the direct analog of `readlink` returning a path larger than the buffer sized by the earlier stat.

### Impact Explanation
Direct protocol insolvency / theft of user funds. The attacker extracts collateral belonging to the Treasury/other depositors while leaving an unrecoverable debt position. The pool's synthetic tokens are backed by Treasury collateral; once the withdrawn collateral exceeds what the remaining locked shares can cover at true prices, the position can never be fully liquidated (`maxLiquidable` only caps per-call seizure at `liquidate`, and `depositToken.seize` cannot recover what has already been paid out). Loss scales with `maxTotalSupply` of the deposit token and is bounded only by the attacker's ability to shift the oracle quote.

### Likelihood Explanation
Requires a listed collateral whose `masterOracle` quote is manipulable within a transaction. Metronome's documented collateral set includes vault-share tokens (Vesper `va*` pools and similar yield-bearing wrappers); share-price oracles sourced from on-chain `pricePerShare`/`totalValue` accounting are historically donatable, and any underlying routed through an AMM-derived price is manipulable via flash-loan-funded trades (explicitly allowed attacker tooling). For collaterals priced purely by push-oracles (e.g., Chainlink WETH/USD) the path fails, so likelihood depends on deployed oracle configuration. No privileged role, no governance action, and no malfunctioning third-party data feed is required — only same-transaction price movement, which the rules permit.

Note on verification limits: I confirmed `withdraw` has no post-check and that `_withdraw` sends real collateral via `treasury().pull`, but I could not fully read `MasterOracle`'s per-asset routing in the iterations available, so the concrete manipulability of a specific deployed collateral's quote should be confirmed against `contracts/*Oracle*.sol` and the deployed deployments config.

### Recommendation
- Do not let the unlock amount depend on a spot oracle read alone. After `treasury().pull` in `_withdraw`, or in `withdraw`/`withdrawFrom`/`flashWithdraw`, re-check `pool.debtPositionOf(account_)` and revert if unhealthy (mirroring the `PositionIsNotHealthy` end-check already used in `SmartFarmingManager.leverage`/`flashRepay`).
- Alternatively price collateral using a manipulation-resistant/TWAP or two-block delayed quote inside `unlockedBalanceOf`, or floor the locked amount using a conservative (min-of-sources) price.
- Keep the explicit check (`_revertIfLocked`) *and* the post-condition check; a post-only check would already close this hole because it evaluates debt vs. remaining collateral at whatever price the attacker set — so the post-check should also verify the position is healthy under the same oracle, i.e., it forces the attacker to hold the manipulated price *and* leave a healthy position at that manipulated price, removing the profit (remaining locked `D/(CF·P')` tokens at price `P'` exactly covers `D/CF` of debt — actually safe — but only if the check runs before state unwinds).

### Proof of Concept
Hardhat/foundry fork skeleton (requires identifying a deployed deposit token whose oracle is manipulable, e.g., a vaToken; `EVIL` below is any same-tx price mover):

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

import "forge-std/Test.sol";
import {IPool} from "../contracts/interfaces/IPool.sol";
import {IDepositToken} from "../contracts/interfaces/IDepositToken.sol";
import {IDebtToken} from "../contracts/interfaces/IDebtToken.sol";
import {IERC20} from "../contracts/dependencies/openzeppelin/token/ERC20/IERC20.sol";

contract WithdrawTOCTOU_PoC is Test {
    IPool pool = IPool(POOL_ADDR);            // deployed Pool proxy
    IDepositToken msdVault = IDepositToken(MSDTOKEN_ADDR);
    IDebtToken msUsdDebt = IDebtToken(MSUSD_DEBT_ADDR);
    IERC20 collateral = IERC20(address(msdVault.underlying()));

    function test_unlockByPriceInflation() public {
        address attacker = makeAddr("attacker");

        // 1. attacker deposits A units of collateral (acquired / flash-borrowed)
        uint256 A = 100 ether;
        deal(address(collateral), attacker, A);
        vm.startPrank(attacker);
        collateral.approve(address(msdVault), A);
        msdVault.deposit(A, attacker);

        // 2. borrow up to the issuable limit at the honest price
        (,,,,uint256 issuable) = pool.debtPositionOf(attacker);
        uint256 toIssue = pool.masterOracle().quoteUsdToToken(
            address(msUsdDebt.syntheticToken()), issuable);
        msUsdDebt.issue(toIssue, attacker);
        vm.stopPrank();

        // 3. same tx or via a helper contract: inflate collateral's oracle quote.
        //    For vault-share collateral: donate underlying to the vault so
        //    pricePerShare jumps; for AMM-priced collateral: flash-swap.
        _inflateCollateralOraclePrice();       // P' >> P

        // 4. withdraw almost everything — _revertIfLocked uses P'
        vm.prank(attacker);
        uint256 bal = msdVault.balanceOf(attacker);
        uint256 unlockedBefore = msdVault.unlockedBalanceOf(attacker);
        assertGt(unlockedBefore, bal * 9 / 10); // lock evaporated
        msdVault.withdraw(unlockedBefore, attacker);

        // 5. unwind price manipulation
        _restoreOraclePrice();

        // position is now deeply unhealthy and under-collateralized
        (bool healthy, uint256 depositUsd, uint256 debtUsd,,) =
            pool.debtPositionOf(attacker);
        assertFalse(healthy);
        assertLt(depositUsd * 1e18 / debtUsd, pool.maxLiquidable()); // unrecoverable bad debt
    }

    function _inflateCollateralOraclePrice() internal { /* donation / flash-swap per oracle route */ }
    function _restoreOraclePrice() internal { /* reverse the manipulation */ }
}
```

The PoC hinges on step 3's oracle route: confirm with `masterOracle.quoteTokenToUsd(underlying, ...)` that inflating the underlying's quote (or its share price) is feasible on the forked deployment; the Hardhat test harness already ships mock swappers/oracles (`test/SmartFarmingManager.test.ts` exercises `swapper.updateRate`) which demonstrates the intended one-block price-shift primitive.
