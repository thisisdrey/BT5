Audit Report

## Title
Burned relayer-tip funds recorded in `LostTips` are permanently unclaimable - (File: `bridges/snowbridge/pallets/system-v2/src/lib.rs`)

## Summary
`pallet-snowbridge-system-frontend::add_tip` irrevocably burns the user's real tip asset on AssetHub and forwards only the numeric amount via XCM to `pallet-snowbridge-system-v2::add_tip` on BridgeHub. If crediting the tip to the target queue pallet fails because the referenced nonce was already processed or is unknown, the amount is added to `LostTips<T>` instead of being refunded, and no extrinsic, hook, or governance call anywhere in the repository reads or drains `LostTips`, leaving burned value permanently locked in on-chain bookkeeping with no recovery path.

## Finding Description
On AssetHub, `add_tip` calls `swap_fee_asset_and_burn`, which either swaps the supplied asset to Ether via `swap_and_burn` or, if already Ether, calls `burn_for_teleport` directly — the user's real funds are destroyed/withdrawn immediately, before any BridgeHub-side validation occurs. The resulting `ether_gained` amount is packaged into an `EthereumSystemCall::AddTip { sender, message_id, amount }` and sent via unpaid `Transact` to BridgeHub. On BridgeHub, `pallet_snowbridge_system_v2::add_tip` calls `T::InboundQueue::add_tip(nonce, amount)` (for `MessageId::Inbound`) or the outbound equivalent. The inbound-queue's `AddTip` implementation checks `Nonce::<T>::get(nonce)` and returns `AddTipError::NonceConsumed` if the message was already processed via `process_message`, which sets `Nonce::<T>::set(nonce)` before paying out any tip. When `add_tip` on system-v2 receives this `Err`, it does not attempt to refund or re-route the value — it unconditionally accumulates it into `LostTips::<T>::mutate(&sender, ...)`. The storage doc comment explicitly states this only "supports implementing a recovery method in the future," confirming no such mechanism exists. The pallet's entire `#[pallet::call]` surface (`upgrade`, `set_operating_mode`, `register_token`, `add_tip`) contains no call that reads or clears `LostTips`, and no other code path in the repository references it outside this write site and tests.

## Impact Explanation
This is a direct, unprivileged permanent user-fund lock: real Ether-denominated value is burned on AssetHub as part of the tip flow, but if BridgeHub-side crediting fails for an easily reachable reason (timing race with independent message processing, or a stale/incorrect nonce), the value becomes permanently unrecoverable since no code path ever reads `LostTips` back into a payable state. This falls squarely within the "permanent user-fund or bridge-state lock" impact category for the Snowbridge bridge-reward flow.

## Likelihood Explanation
`add_tip` (AssetHub → BridgeHub, signed-origin only, no pending-nonce check) and `submit`/`process_message` (any relayer, for the same nonce) are two independent transactions submitted by unrelated, unprivileged actors. Any user who tips a message that gets processed concurrently or just before their tip lands, or who references a nonce that is already consumed or doesn't exist, will hit this path with no malicious behavior required from any party — purely from honest, uncoordinated activity, making this moderate-to-high likelihood in practice.

## Recommendation
Add a `claim_lost_tips`/`withdraw_lost_tips` extrinsic allowing the original `sender` recorded in `LostTips<T>` to redeem their balance, e.g. by teleporting/minting equivalent Ether back to their account on the origin chain via XCM. Alternatively, refactor the frontend `add_tip` to defer the burn/withdrawal until BridgeHub confirms successful crediting (e.g., via an XCM query-response pattern) rather than irrevocably burning funds before the destination side validates the nonce.

## Proof of Concept
1. User A calls `pallet_snowbridge_system_frontend::add_tip(message_id: Inbound(N), asset: Asset{Ether, amount})` on AssetHub; their asset is burned immediately in `swap_fee_asset_and_burn`.
2. Concurrently, a relayer submits `inbound-queue-v2::submit` for nonce `N`, which calls `Nonce::<T>::set(nonce)` marking it processed.
3. The XCM `Transact` carrying `EthereumSystemCall::AddTip { sender: A, message_id: Inbound(N), amount }` executes on BridgeHub, invoking `InboundQueue::add_tip(N, amount)`.
4. `InboundQueue::add_tip` returns `AddTipError::NonceConsumed` because `Nonce::<T>::get(N)` is now `true`.
5. `pallet_snowbridge_system_v2::add_tip` catches the `Err` and executes `LostTips::<T>::mutate(&sender, |lost_tip| *lost_tip = lost_tip.saturating_add(amount))`.
6. User A's burned Ether value now exists only as a number in `LostTips<T>` storage with no dispatchable in the pallet to move it back — permanently locked.

			origin: Location,
			fee_asset: Asset,
		) -> Result<u128, DispatchError> {
			let ether_location = T::EthereumLocation::get();
			let (fee_asset_location, fee_amount) = match fee_asset {
				Asset { id: AssetId(ref loc), fun: Fungible(amount) } => (loc, amount),
				_ => {
					tracing::debug!(target: LOG_TARGET, ?fee_asset, "error matching fee asset");
					return Err(Error::<T>::UnsupportedAsset.into());
				},
			};
			if fee_amount == 0 {
				return Ok(0);
			}

			let ether_gained = if *fee_asset_location != ether_location {
				Self::swap_and_burn(
					origin.clone(),
					fee_asset_location.clone(),
					ether_location,
					fee_amount,
				)
				.inspect_err(|&e| {
					tracing::debug!(target: LOG_TARGET, ?e, "error swapping asset");
				})?
			} else {
				burn_for_teleport::<T::AssetTransactor>(&origin, &fee_asset)
					.map_err(|_| Error::<T>::BurnError)?;
				fee_amount
			};
			Ok(ether_gained)
		}

	impl<T: Config> Pallet<T> {
		pub fn process_message(relayer: T::AccountId, message: Message) -> DispatchResult {
			// Verify that the message was submitted from the known Gateway contract
			ensure!(T::GatewayAddress::get() == message.gateway, Error::<T>::InvalidGateway);

			let (nonce, relayer_fee) = (message.nonce, message.relayer_fee);

			// Verify the message has not been processed
			ensure!(!Nonce::<T>::get(nonce), Error::<T>::InvalidNonce);

			// Mark message as received
			Nonce::<T>::set(nonce);

			let message_id = T::MessageProcessor::process_message(relayer.clone(), message)
				.map_err(|e| match e {
					MessageProcessorError::ProcessMessage(e) => e,
					MessageProcessorError::ConvertMessage(e) => Error::<T>::from(e).into(),
					MessageProcessorError::SendMessage(e) => Error::<T>::from(e).into(),
				})?;

			// Pay relayer reward
			let tip = Tips::<T>::take(nonce).unwrap_or_default();
			let total_tip = relayer_fee.saturating_add(tip);
			if total_tip > 0 {
				T::RewardPayment::register_reward(&relayer, T::DefaultRewardKind::get(), total_tip);
			}

			// Emit event with the message_id
			Self::deposit_event(Event::MessageReceived { nonce, message_id });

			Ok(())
		}
	}

	impl<T: Config> AddTip for Pallet<T> {
		fn add_tip(nonce: u64, amount: u128) -> Result<(), AddTipError> {
			ensure!(amount > 0, AddTipError::AmountZero);
			// If the nonce is already processed, return an error

			// Otherwise add the tip.

				*tip = Some(tip.unwrap_or_default().saturating_add(amount));
			});
			return Ok(());
		}
