### Title
`LinkRepositoryToObjectPool` allows linking a repository to itself as its own object pool, creating a self-referential Git alternates file - ([File: internal/gitaly/service/objectpool/link.go])

### Summary
`LinkRepositoryToObjectPool` never verifies that the `repository` field and the `object_pool.repository` field of the request refer to different repositories. This is directly analogous to the `transfer_share_and_rewards` bug where a missing "not equal to self" check let a caller apply a transfer operation onto itself, corrupting accounting invariants. Here, the missing check lets a caller "link" a repository's alternates file to point at itself, corrupting the repository's object-pool relationship instead of a reward balance.

### Finding Description
The RPC handler simply validates that `repository` is a valid repository and builds the pool object, but performs no comparison between the two repository identifiers: [1](#0-0) 

The core `Link` function then computes the relative alternates path between the "pool" and the "repo" using `getRelativeObjectPath`, and writes it into the repository's `objects/info/alternates` file: [2](#0-1) [3](#0-2) 

If a caller sets `object_pool.repository` equal to `repository` in the `LinkRepositoryToObjectPoolRequest`, `pool.Path(ctx)` and `repo.Path(ctx)` resolve to the identical filesystem path. `getRelativeObjectPath` then computes `filepath.Rel(repoPath/objects, repoPath)`, which is `".."`, and joins it with `"objects"`, producing `"../objects"` — a relative path that, when resolved from `repoPath/objects/info/alternates`, points right back at `repoPath/objects` itself. The repository ends up with an alternates file pointing at its own object directory. `linkedToRepository` (used to short-circuit on already-linked pools) does not special-case this self path either: [4](#0-3) 

There is no analog of the `sameRepo`/`storage.RepoPathEqual` guard that other RPCs in this codebase apply for legitimate same-repository handling (e.g. `FetchSourceBranch` explicitly detects and special-cases the same-repository case rather than blindly proceeding): [5](#0-4) 

No equivalent same-repository detection/rejection exists in the object-pool linking path.

### Impact Explanation
A self-referential `objects/info/alternates` entry corrupts the object-pool isolation invariant that Gitaly relies on: alternates are supposed to point from a "member" repository to a distinct pool repository so that object-graph traversal, GC, and consistency checks (`git-fsck`, repacking, quarantine migration) can reason about a bounded set of object stores. Making a repository an "alternate of itself" breaks that assumption for any repository-processing code path that walks alternates recursively (directly or via Git's own alternate-chain resolution), and it also causes `removeMemberBitmaps`/pool-bitmap accounting to behave incorrectly, since pool and repo paths are identical. This is a genuine corruption/DoS-class impact on an ordinary user-reachable RPC (`LinkRepositoryToObjectPoolRequest` can be issued for repositories/pools the caller controls, e.g. via GitLab's fork-management flows that call this RPC), analogous to the "self transfer" bug that corrupted share/reward accounting in the report by never rejecting `who == other`.

### Likelihood Explanation
The RPC is reachable by any caller able to issue `LinkRepositoryToObjectPoolRequest` with attacker-controlled `object_pool.repository` and `repository` fields (e.g., a user-driven fork/pool linking flow) — no special privilege is required beyond ordinary access to invoke object-pool RPCs on repositories/pools they already have access to. The check is a single missing equality comparison, so the likelihood of the specific corrupted-state code path being reached is high whenever such a request is crafted.

### Recommendation
In `LinkRepositoryToObjectPool` (internal/gitaly/service/objectpool/link.go), after resolving `repository` and the target pool's repository, reject the request (e.g., `InvalidArgument`) if `storage.RepoPathEqual(repository, pool.Repository())` (or equivalent comparison of resolved paths) is true, mirroring the same-repository detection pattern already used elsewhere in the codebase (see `internal/gitaly/service/repository/fetch.go`). Additionally, `internal/git/objectpool/link.go`'s `Link`/`getRelativeObjectPath`/`linkedToRepository` functions should defensively reject the case where `pool.Path(ctx) == repo.Path(ctx)`.

### Proof of Concept
1. Create repository `A`.
2. Issue `LinkRepositoryToObjectPoolRequest{ Repository: A, ObjectPool: { Repository: A } }`.
3. Observe that the RPC succeeds (no validation error) and that `A/objects/info/alternates` is written with content `../objects`, which resolves back to `A/objects` itself — a self-referential alternates entry, rather than a rejection of the malformed self-link request.

// Link will link the given repository to the object pool. This is done by writing the object pool's
// path relative to the repository into the repository's "alternates" file. This does not trigger
// deduplication, which is the responsibility of the caller.
func Link(ctx context.Context, pool, repo *localrepo.Repo, txManager transaction.Manager) (returnedErr error) {
	altPath, err := repo.InfoAlternatesPath(ctx)
	if err != nil {
		return err
	}

	expectedRelPath, err := getRelativeObjectPath(ctx, pool, repo)
	if err != nil {
		return err
	}

	linked, err := linkedToRepository(ctx, pool, repo)
	if err != nil {
		return err
	}

	if linked {
		// When the repository is already linked to the repository, cast a vote to ensure the
		// repository is consistent with the other replicas.
		if err := transaction.VoteOnContext(ctx, txManager, voting.VoteFromData([]byte("repository linked")), voting.Synchronized); err != nil {
			return fmt.Errorf("vote on linked repository: %w", err)
		}

		return nil
	}

func getRelativeObjectPath(ctx context.Context, pool, repo *localrepo.Repo) (string, error) {
	poolPath, err := pool.Path(ctx)
	if err != nil {
		return "", fmt.Errorf("getting object pool path: %w", err)
	}

	repoPath, err := repo.Path(ctx)
	if err != nil {
		return "", fmt.Errorf("getting repository path: %w", err)
	}

	relPath, err := filepath.Rel(filepath.Join(repoPath, "objects"), poolPath)
	if err != nil {
		return "", err
	}

	return filepath.Join(relPath, "objects"), nil
}

// linkedToRepository tests if a repository is linked to an object pool
func linkedToRepository(ctx context.Context, pool, repo *localrepo.Repo) (bool, error) {
	poolPath, err := pool.Path(ctx)
	if err != nil {
		return false, fmt.Errorf("getting object pool path: %w", err)
	}

	repoPath, err := repo.Path(ctx)
	if err != nil {
		return false, fmt.Errorf("getting repo path: %w", err)
	}

	altInfo, err := stats.AlternatesInfoForRepository(repoPath)
	if err != nil {
		return false, fmt.Errorf("getting alternates info: %w", err)
	}

	if !altInfo.Exists || len(altInfo.ObjectDirectories) == 0 {
		return false, nil
	}

	relPath := altInfo.ObjectDirectories[0]
	expectedRelPath, err := getRelativeObjectPath(ctx, pool, repo)
	if err != nil {
		return false, err
	}

	if relPath == expectedRelPath {
		return true, nil
	}

	if filepath.Clean(relPath) != filepath.Join(poolPath, "objects") {
		return false, fmt.Errorf("unexpected alternates content: %q", relPath)
	}

	return false, nil
}
