### Title
Adaptive Energy Limit can be gamed by manipulating the per-block average energy usage (`EnergyProcessor.updateTotalEnergyAverageUsage` / `updateAdaptiveTotalEnergyLimit`) - (File: `chainbase/src/main/java/org/tron/core/db/EnergyProcessor.java`)

### Summary
`Manager.processBlock` calls `EnergyProcessor.updateTotalEnergyAverageUsage()` and `updateAdaptiveTotalEnergyLimit()` after every block when adaptive energy is enabled [1](#0-0) . These functions compute a decayed running average of energy consumed per block (`totalEnergyAverageUsage`) and use it to expand or contract `totalEnergyCurrentLimit`, the shared pool from which every frozen-balance holder's per-account energy allowance (`calculateGlobalEnergyLimit`/`calculateGlobalEnergyLimitV2`) is derived [2](#0-1) . This mirrors the reported bug class: a global, shared reward/allowance parameter is derived from a short, attacker-influenceable rolling window of on-chain activity rather than from a robust, longer-horizon or volume-based signal, letting an unprivileged actor bias the metric with cheap transactions and then extract a disproportionate benefit in a single subsequent action.

### Finding Description
`blockEnergyUsage` is incremented by every energy-consuming smart-contract call within a block via `EnergyProcessor.useEnergy` [3](#0-2) , and it is reset to `0` at the start of each block by `Manager.processBlock` [4](#0-3) . Because any account that owns a smart contract, or simply calls one via `TriggerSmartContract`, can fully control how much energy it burns in a given block, an unprivileged transaction broadcaster can deterministically choose the value fed into the running average each block (e.g. keep it at or near `0`, or keep it just under `targetTotalEnergyLimit`).

`updateTotalEnergyAverageUsage` folds this attacker-controlled per-block value into a decayed average using the same `increase(...)` decay routine used for bandwidth/energy windows [5](#0-4) . `updateAdaptiveTotalEnergyLimit` then compares that average against `targetTotalEnergyLimit`: if the average stays below the target, `totalEnergyCurrentLimit` is expanded every maintenance cycle by `EXPAND_RATE_NUMERATOR/DENOMINATOR`, up to a cap of `totalEnergyLimit * adaptiveResourceLimitMultiplier` [6](#0-5) . An attacker can therefore:
1. Suppress network-wide energy usage they control (or simply avoid triggering contracts) so the average stays low, causing `totalEnergyCurrentLimit` to ratchet upward toward its multiplier-bound ceiling over successive maintenance windows — exactly the “trade a single wei repeatedly to zero the average” pattern from the report, adapted to “burn ~0 energy repeatedly to suppress the average.”
2. Once `totalEnergyCurrentLimit` is inflated, any account holding frozen balance for energy gets a proportionally larger free-energy allowance via `calculateGlobalEnergyLimit`/`calculateGlobalEnergyLimitV2`, since both are simple linear functions of `totalEnergyCurrentLimit` and `totalEnergyWeight` [7](#0-6) .
3. The attacker (or any large staker) can then execute energy-intensive contract calls that consume far more of the shared, TRX-price-subsidized “free energy” pool than the target design intended, at the expense of other stakers who now compete for an artificially inflated but soon-to-shrink resource, and at the expense of the network's intended energy-fee/anti-spam economics.

This is analogous to the reported `normalAverageFee` gaming: a protocol-critical average that gates a shared payout/allowance is computed from a short window of attacker-influenced samples, allowing the attacker to steer the derived resource toward a favorable extreme before harvesting it.

### Impact Explanation
Inflating `totalEnergyCurrentLimit` up to its multiplier ceiling lets large frozen-balance holders extract disproportionately more “free” energy allowance than the target design permits, effectively bypassing the intended fee/anti-congestion throttle that adaptive energy is meant to enforce. This can be leveraged to run unusually large volumes of energy-consuming computation without paying the TRX-denominated overage fee that would otherwise apply, degrading the economic assumptions the network relies on to price and rate-limit TVM execution, and creating an unfair advantage/resource-exhaustion vector against other participants sharing the same energy pool.

### Likelihood Explanation
Any account with an existing smart contract or a deployed contract used purely to burn arbitrary, attacker-chosen amounts of energy per block can influence `blockEnergyUsage`, and this requires no special privilege — just ordinary `TriggerSmartContract` transactions signed by any key. The manipulation is deterministic and repeatable across maintenance cycles, similar in mechanics (though not identical in specific formula) to the reported LP-dividend gaming technique, making this analog directly reachable from a single signed transaction stream.

### Recommendation
Base the adaptive-limit adjustment on a longer, harder-to-manipulate signal — e.g., a volume/usage measure aggregated over many maintenance cycles, or a metric that requires broad, costly participation across many independent accounts rather than a single actor's per-block energy usage — and/or cap the rate and magnitude at which `totalEnergyCurrentLimit` can expand relative to sustained, verified demand, rather than a single decayed rolling average driven by controllable per-block energy consumption.

### Proof of Concept
1. Deploy (or use) a contract whose function consumes a fixed, attacker-chosen amount of energy.
2. For several consecutive maintenance windows, call this contract so that `blockEnergyUsage` stays consistently below `targetTotalEnergyLimit` (e.g., near 0), driving `totalEnergyAverageUsage` down via `EnergyProcessor.updateTotalEnergyAverageUsage`.
3. Each maintenance cycle, `updateAdaptiveTotalEnergyLimit` expands `totalEnergyCurrentLimit` by `EXPAND_RATE_NUMERATOR/DENOMINATOR` since the average stays under target, converging toward `totalEnergyLimit * adaptiveResourceLimitMultiplier`.
4. Once expanded, use a large frozen-balance-backed account to invoke `calculateGlobalEnergyLimit`/`V2`-gated calls, consuming a share of the inflated `totalEnergyCurrentLimit` far beyond what the un-gamed target would have allowed, without incurring the intended TRX energy-overage fee.

  public void updateTotalEnergyAverageUsage() {
    long now = getHeadSlot();
    long blockEnergyUsage = dynamicPropertiesStore.getBlockEnergyUsage();
    long totalEnergyAverageUsage = dynamicPropertiesStore
        .getTotalEnergyAverageUsage();
    long totalEnergyAverageTime = dynamicPropertiesStore.getTotalEnergyAverageTime();

    long newPublicEnergyAverageUsage = increase(totalEnergyAverageUsage, blockEnergyUsage,
        totalEnergyAverageTime, now, averageWindowSize);

    dynamicPropertiesStore.saveTotalEnergyAverageUsage(newPublicEnergyAverageUsage);
    dynamicPropertiesStore.saveTotalEnergyAverageTime(now);
  }

  public void updateAdaptiveTotalEnergyLimit() {
    long totalEnergyAverageUsage = dynamicPropertiesStore
        .getTotalEnergyAverageUsage();
    long targetTotalEnergyLimit = dynamicPropertiesStore.getTotalEnergyTargetLimit();
    long totalEnergyCurrentLimit = dynamicPropertiesStore
        .getTotalEnergyCurrentLimit();
    long totalEnergyLimit = dynamicPropertiesStore.getTotalEnergyLimit();

    long result;
    if (totalEnergyAverageUsage > targetTotalEnergyLimit) {
      result = scaleByRate(totalEnergyCurrentLimit,
          AdaptiveResourceLimitConstants.CONTRACT_RATE_NUMERATOR,
          AdaptiveResourceLimitConstants.CONTRACT_RATE_DENOMINATOR);
    } else {
      result = scaleByRate(totalEnergyCurrentLimit,
          AdaptiveResourceLimitConstants.EXPAND_RATE_NUMERATOR,
          AdaptiveResourceLimitConstants.EXPAND_RATE_DENOMINATOR);
    }
    long upperBound = hardenCalculation()
        ? BigInteger.valueOf(totalEnergyLimit).multiply(BigInteger.valueOf(
            dynamicPropertiesStore.getAdaptiveResourceLimitMultiplier())).longValueExact()
        : totalEnergyLimit * dynamicPropertiesStore.getAdaptiveResourceLimitMultiplier();
    result = min(max(result, totalEnergyLimit, this.disableJavaLangMath()),
        upperBound, this.disableJavaLangMath());

    dynamicPropertiesStore.saveTotalEnergyCurrentLimit(result);
    logger.debug("Adjust totalEnergyCurrentLimit, old: {}, new: {}.",
        totalEnergyCurrentLimit, result);
  }

  public long calculateGlobalEnergyLimit(AccountCapsule accountCapsule) {
    long frozeBalance = accountCapsule.getAllFrozenBalanceForEnergy();
    if (dynamicPropertiesStore.supportUnfreezeDelay()) {
      return calculateGlobalEnergyLimitV2(frozeBalance);
    }
    if (frozeBalance < TRX_PRECISION) {
      return 0;
    }

    long totalEnergyLimit = dynamicPropertiesStore.getTotalEnergyCurrentLimit();
    long totalEnergyWeight = dynamicPropertiesStore.getTotalEnergyWeight();
    if (dynamicPropertiesStore.allowNewReward() && totalEnergyWeight <= 0) {
      return 0;
    } else {
      assert totalEnergyWeight > 0;
    }
    if (hardenCalculation()) {
      return calculateGlobalLimitV1(frozeBalance, totalEnergyLimit, totalEnergyWeight);
    }
    long energyWeight = frozeBalance / TRX_PRECISION;
    return (long) (energyWeight * ((double) totalEnergyLimit / totalEnergyWeight));
  }

  public long calculateGlobalEnergyLimitV2(long frozeBalance) {
    long totalEnergyLimit = dynamicPropertiesStore.getTotalEnergyCurrentLimit();
    long totalEnergyWeight = dynamicPropertiesStore.getTotalEnergyWeight();
    if (totalEnergyWeight == 0) {
      return 0;
    }
    if (hardenCalculation()) {
      return calculateGlobalLimitV2(frozeBalance, totalEnergyLimit, totalEnergyWeight);
    }
    double energyWeight = (double) frozeBalance / TRX_PRECISION;
    return (long) (energyWeight * ((double) totalEnergyLimit / totalEnergyWeight));
  }

  protected long increase(long lastUsage, long usage, long lastTime, long now, long windowSize) {
    long averageLastUsage;
    long averageUsage;
    if (hardenCalculation()) {
      BigInteger biPrecision = BigInteger.valueOf(precision);
      BigInteger biWindowSize = BigInteger.valueOf(windowSize);
      averageLastUsage = divideCeilExact(
          BigInteger.valueOf(lastUsage).multiply(biPrecision), biWindowSize);
      averageUsage = divideCeilExact(
          BigInteger.valueOf(usage).multiply(biPrecision), biWindowSize);
    } else {
      averageLastUsage = divideCeil(lastUsage * precision, windowSize);
      averageUsage = divideCeil(usage * precision, windowSize);
    }

    if (lastTime != now) {
      assert now > lastTime;
      if (lastTime + windowSize > now) {
        long delta = now - lastTime;
        double decay = (windowSize - delta) / (double) windowSize;
        averageLastUsage = round(averageLastUsage * decay,
            this.disableJavaLangMath());
      } else {
        averageLastUsage = 0;
      }
    }
    averageLastUsage += averageUsage;
    return getUsage(averageLastUsage, windowSize);
  }
