### Title
Slow/incomplete QUIC handshakes from a single unstaked IP evade per-IP `ConnectionRateLimiter` and exhaust the global `max_concurrent_connections` slot pool, starving legitimate connections - (File: streamer/src/nonblocking/quic.rs)

### Summary
`ConnectionRateLimiter::register_connection` is only invoked after a QUIC handshake succeeds, and `ConnectionRateLimiter::is_allowed` returns `true` for any IP with no recorded tokens. An attacker who deliberately never completes the handshake (trickling the ClientHello/Initial packets) never gets a rate-limiter record, so `is_allowed` permits unlimited repeated connection attempts from that IP forever, while each attempt still consumes a `ClientConnectionTracker` slot for up to `QUIC_CONNECTION_HANDSHAKE_TIMEOUT`.

### Finding Description
In `run_server` (`streamer/src/nonblocking/quic.rs:331-379`), an incoming connection is checked against the per-IP `ConnectionRateLimiter::is_allowed` [1](#0-0)  before a `ClientConnectionTracker` slot is reserved via `ClientConnectionTracker::new(stats.clone(), qos.max_concurrent_connections())` [2](#0-1) . This slot count is a single global counter (`stats.open_connections`), gated only by `qos.max_concurrent_connections()` (e.g. `SimpleQos::max_concurrent_connections` = `max_staked_connections * 5 / 4` [3](#0-2) , or the equivalent `(max_staked+max_unstaked)*5/4` in `SwQos`).

Crucially, `ConnectionRateLimiter::is_allowed` treats an unseen IP as always allowed (`None => true`) [4](#0-3) , and the corresponding `register_connection` call — which is the only thing that actually consumes a token for that IP — happens in `setup_connection` **only after** the QUIC handshake completes successfully within `QUIC_CONNECTION_HANDSHAKE_TIMEOUT` [5](#0-4) . If the handshake instead times out (attacker never finishes ClientHello/Handshake), `setup_connection` falls into the `else` branch and simply increments `connection_setup_timeout`; `register_connection` and `overall_connection_rate_limiter.consume_tokens` are never called [6](#0-5) . The `ClientConnectionTracker` slot is released only when it is dropped at end-of-task [7](#0-6) , so it is held for the full `QUIC_CONNECTION_HANDSHAKE_TIMEOUT` (2 seconds, `streamer/src/nonblocking/quic.rs:80`, not the 60s client-side constant used elsewhere in the codebase) [8](#0-7) .

The comment above this code block explicitly documents that IP-based enforcement is deliberately deferred until "a peer has asserted control over their ip address," relying instead on a fixed handshake timeout and a global slot cap to bound resource use [9](#0-8) . However, because neither `is_allowed` nor the global `overall_connection_rate_limiter` peek (`current_tokens() == 0`, non-consuming) [10](#0-9)  place any limit on the *rate* of repeated incomplete handshake attempts from the same IP, an attacker can continuously open new connections, let each linger just under 2 seconds, and repeat indefinitely — occupying up to `max_concurrent_connections` slots at any given time without ever being charged against `ConnectionRateLimiter` or entering `ConnectionTable`.

### Impact Explanation
Once the attacker saturates `stats.open_connections` up to `max_concurrent_connections`, `ClientConnectionTracker::new` fails for all further incoming connections (from any IP, staked or unstaked), which increments `refused_connections_too_many_open_connections` and calls `incoming.refuse()` [2](#0-1) . This is a QoS/availability evasion: a single unstaked, unprivileged attacker can deny legitimate TPU connection capacity to all other clients, including staked validators forwarding transactions, matching the "QoS evasion / resource-starvation" bounty category.

### Likelihood Explanation
Feasible with a single machine and a single source IP: no stake, no valid validator identity, and no cryptographic bypass are required — only the ability to open a QUIC connection to the public TPU port and withhold/trickle handshake bytes. The attack is repeatable indefinitely because the per-IP rate limiter is never charged for incomplete handshakes, and repeating connection attempts every <2s keeps the slot pool full. The `max_concurrent_connections` value is a fixed, moderate global cap (e.g. ~2500-6250 depending on config), achievable by a single attacker generating a modest sustained rate of new UDP/QUIC connection attempts.

### Recommendation
- Charge (or provisionally reserve) a per-IP rate-limiter token at the time a `ClientConnectionTracker` slot is granted (before handshake completion), releasing/refunding it on success, rather than only registering after a successful handshake.
- Consider consuming (not merely peeking) `overall_connection_rate_limiter` tokens at admission time for in-flight (not-yet-handshaken) connections as well.
- Additionally, consider tracking outstanding unfinished handshakes per-IP separately from `stats.open_connections`, and reject/limit further handshake attempts from an IP that already has an in-flight (unregistered) handshake outstanding.

### Proof of Concept
Integration test plan (in `streamer/src/nonblocking/quic.rs` test module, alongside existing `setup_quic_server`/`make_client_endpoint` helpers):
1. Configure `QuicStreamerConfig::default_for_tests()` with a small `max_concurrent_connections` (via small `max_staked_connections`/`max_unstaked_connections` in `SwQosConfig`) and `max_connections_per_ipaddr_per_min` set low (e.g. 2).
2. From one attacker "IP" (a single client `Endpoint`), open `max_concurrent_connections` raw UDP/QUIC connection attempts that send only the QUIC Initial packet and then stall (do not send subsequent Handshake CRYPTO frames) — e.g. use a custom `quinn::Endpoint` with client crypto that intentionally pauses before completing the TLS handshake, or a raw socket sending a valid Initial packet and no follow-up.
3. Assert via `stats.total_incoming_connection_attempts` and `stats.outstanding_incoming_connection_attempts` that all attempts were accepted (`ClientConnectionTracker::new` succeeded) and that `stats.connection_rate_limited_per_ipaddr` remains 0 (per-IP limiter never triggered).
4. Attempt a legitimate connection from a second IP/`make_client_endpoint` and assert it is refused: `stats.refused_connections_too_many_open_connections.load(Ordering::Relaxed) >= 1`.
5. Wait past `QUIC_CONNECTION_HANDSHAKE_TIMEOUT` and confirm `stats.connection_setup_timeout` increments for the attacker connections while `stats.total_new_connections` (and `ConnectionTable` size) remains 0 for them, proving the slots were held without ever registering.
