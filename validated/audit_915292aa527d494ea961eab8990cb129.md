### Title
StackerDB chunk signature omits contract identifier, enabling cross-StackerDB chunk replay - ([File: stackslib/src/net/stackerdb/db.rs, libstackerdb/src/libstackerdb.rs])

### Summary
`SlotMetadata::auth_digest()` hashes only `slot_id`, `slot_version`, and `data_hash` — it never binds the signature to the StackerDB's contract identifier. `StackerDBTx::try_replace_chunk` validates a submitted chunk purely by recovering the signer from this digest and checking it against the slot owner recorded for the target contract, so a signature produced for one StackerDB contract is equally valid for any other StackerDB contract in which the attacker's address happens to own the same slot ID.

### Finding Description
`SlotMetadata::auth_digest` in `libstackerdb/src/libstackerdb.rs` builds the signed digest as: [1](#0-0) 
No contract identifier, chain ID, or any DB-specific salt is included. `SlotMetadata::verify` and `StackerDBChunkData::verify` both call this same `auth_digest`, and signing (`SlotMetadata::sign`, `StackerDBChunkData::sign`) commits only to the same three fields: [2](#0-1) 

`StackerDBTx::try_replace_chunk` (in `stackslib/src/net/stackerdb/db.rs`) validates an incoming `StackerDBChunkData` by looking up the slot's expected signer for whichever contract the write is targeted at (via `get_slot_validation(contract_id, slot_id)`), then calls `slot_desc.verify(&slot_validation.signer)` on the submitted chunk metadata. Since the recovered public key hash depends solely on `(slot_id, slot_version, data_hash, sig)` and never on `contract_id`, a chunk legitimately signed for contract A's slot 0 will pass verification against contract B's slot 0 whenever the two contracts assign slot 0 to the same `StacksAddress`.

This is a genuine cross-context replay: the signer never intended to authorize a write into contract B's replicated state, but the digest gives the node no way to distinguish "signed for A" from "signed for B."

### Impact Explanation
An attacker who legitimately owns slot 0 (or any slot ID) in StackerDB contract A, and who also happens to be (or is configured as) the owner of the same slot ID in StackerDB contract B, can take a single signed chunk intended only for A and POST the identical bytes to B's `/v2/stackerdb/<B>/chunks` endpoint. The node will accept it as a valid, authenticated write into B's replicated data set — this is an unauthenticated/unauthorized write of forged data into StackerDB state, which then gets gossiped/relayed network-wide as legitimate slot content for contract B. This matches the Critical category ("unauthenticated/unauthorized write to state or StackerDB, network-wide propagation of forged data").

### Likelihood Explanation
The precondition — the same `StacksAddress` being assigned the same slot ID as a writer in two different StackerDB configs — is not attacker-controlled in general; it requires that two independently-configured StackerDBs assign identical signer addresses to identical slot indices. This can occur by coincidence (e.g., PoX signer sets reused across cycles/reward-set configuration, or a signer/operator legitimately holding a slot in multiple StackerDB replicas, such as the `.signers-0-0` and `.signers-1-0` contracts that are known to reuse the same signer set and slot numbering scheme across reward cycles). No secret or privileged role is required beyond already legitimately owning a slot somewhere. The attack is repeatable for every chunk the attacker signs, and the RPC POST endpoint is remotely reachable without authentication beyond the (contract-independent) signature check.

### Recommendation
Bind the signature to the StackerDB contract by including the `QualifiedContractIdentifier` (and ideally chain ID / a domain-separation tag) inside `auth_digest()`, e.g. hash `contract_id.to_string().as_bytes()` (or its serialized bytes) alongside `slot_id`, `slot_version`, and `data_hash`. This requires updating `SlotMetadata` to carry or receive the contract identifier during both signing and verification, and updating all callers of `sign`/`verify` (`StackerDBChunkData::sign`, `StackerDBChunkData::verify`, `StackerDBTx::try_replace_chunk`) to pass the target contract ID.

### Proof of Concept
1. Create two StackerDB configs (contract A `.testdb-a`, contract B `.testdb-b`) each with slot 0 assigned to the same `StacksAddress` derived from a test private key `pk`.
2. Build a `StackerDBChunkData { slot_id: 0, slot_version: 1, data: b"payload-for-A".to_vec(), .. }`, call `.sign(&pk)` — this signs `auth_digest()` which only covers `(0u32, 1u32, sha512_256(payload))`.
3. Call `StackerDBTx::try_replace_chunk` (or the equivalent `StackerDBs::put_chunk` used by the RPC handler) against contract A's DB — assert success (expected, legitimate use).
4. Take the *identical* signed `StackerDBChunkData` bytes and submit them via `try_replace_chunk` against contract B's DB (or POST to `/v2/stackerdb/<B-address>/testdb-b/chunks`).
5. Assert that `try_replace_chunk` for contract B *also* returns success and stores the chunk (`slot_desc.verify(&slot_validation.signer)` returns `Ok(true)` for contract B despite the signature never mentioning contract B) — demonstrating the cross-contract replay/forgery.

    fn auth_digest(&self) -> Sha512Trunc256Sum {
        let mut hasher = Sha512_256::new();
        hasher.update(self.slot_id.to_be_bytes());
        hasher.update(self.slot_version.to_be_bytes());
        hasher.update(self.data_hash.0);
        Sha512Trunc256Sum::from_hasher(hasher)
    }

    pub fn sign(&mut self, privkey: &StacksPrivateKey) -> Result<(), Error> {
        let auth_digest = self.auth_digest();
        let sig = privkey
            .sign(&auth_digest.0)
            .map_err(|se| Error::SigningError(se.to_string()))?;

        self.signature = sig;
        Ok(())
    }

    /// Verify that a given principal signed this chunk metadata.
    /// Note that the address version is ignored.
    pub fn verify(&self, principal: &StacksAddress) -> Result<bool, Error> {
        let sigh = self.auth_digest();
        let pubk = StacksPublicKey::recover_to_pubkey_without_validating_low_s(
            sigh.as_bytes(),
            &self.signature,
        )
        .map_err(|ve| Error::VerifyingError(ve.to_string()))?;

        let pubkh = Hash160::from_node_public_key(&pubk);
        Ok(pubkh == *principal.bytes())
    }
}
