### Title
Unauthenticated remote `/shutdown` HTTP request terminates the signer's event receiver - (File: libsigner/src/events.rs)

### Summary
`SignerEventReceiver::next_event` treats any HTTP `POST /shutdown` request received on the signer's public event-listener port as a valid shutdown command, with no secret, signature, or origin check. Any remote party able to reach that TCP port can terminate the signer's event ingestion loop with a single crafted request.

### Finding Description
`SignerEventReceiver::bind` opens an `HttpServer` on the address the node uses to POST signer events (`local_addr`), which is the same address `SignerStopSignaler::send` connects to when the runloop wants to shut the receiver down. [1](#0-0) 

In `next_event`, requests are dispatched purely by URL path and HTTP method, with `/status`, `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/shutdown`, and `/new_block` all handled the same way — no authentication token, shared secret, or peer/IP check is present anywhere in this function: [2](#0-1) 

The `/shutdown` branch specifically:
```rust
} else if request.url() == "/shutdown" {
    event_receiver.stop_signal.store(true, Ordering::SeqCst);
    Err(EventError::Terminated)
}
```
unconditionally sets `stop_signal` to `true` and returns `EventError::Terminated` for *any* POST to `/shutdown`, regardless of who sent it. [3](#0-2) 

`EventReceiver::main_loop` treats `Err(EventError::Terminated)` as a normal, expected exit condition and breaks the loop: [4](#0-3) 

The legitimate internal shutdown path, `SignerStopSignaler::send`, is implemented by literally hand-building the same HTTP request text and writing it over a plain `TcpStream::connect(self.local_addr)` — i.e., the "authentication" for shutdown is nothing more than knowing the URL path `/shutdown`, which is public knowledge from the source code: [5](#0-4) 

Any remote attacker who can open a TCP connection to the signer's bound event-listener port can send:
```
POST /shutdown HTTP/1.1
Host: <addr>
Connection: close
Content-Length: 5
Content-Type: text/plain

abcde
```
and this is functionally indistinguishable from the legitimate internal call, so the guard that exists (path match) provides no security value against a remote adversary — it only distinguishes shutdown-intent from other requests, not legitimate caller from attacker.

### Impact Explanation
A successful `/shutdown` POST permanently sets `stop_signal`, causing `is_stopped()` to return `true` forever thereafter (there is no reset path found in this file), and `main_loop` exits. This halts the signer's event ingestion: it stops receiving `/stackerdb_chunks`, `/new_burn_block`, `/proposal_response`, and `/new_block` events from the node, effectively taking the signer offline for consensus-relevant duties (block validation responses, DKG/signing message relay, etc.) until the process is restarted. Because a single small HTTP message triggers total, permanent halt, this matches the "Critical - remote crash/unauthenticated DoS from few messages" impact category. Repeatable per signer instance/port, and effective from a single unauthenticated connection.

### Likelihood Explanation
The only precondition is TCP reachability to the signer's configured event-receiver bind address/port (this is the endpoint operators configure the node to POST events to, e.g. `event_observer` target for the signer, exposed similarly to any locally/network-bound HTTP listener). No secret, peer key, StackerDB slot, or any privileged role is needed — this matches the "unprivileged attacker who can reach a node's ... port" threat model verbatim. Attacker cost is a single crafted TCP write; the exploit is trivially repeatable against any signer whose event port is reachable (this is an operational/deployment consideration outside this file, but the code itself contains zero authentication for this operation, so exposure is purely a function of network reachability, not code-level access control).

### Recommendation
Do not use a network-reachable HTTP endpoint as the shutdown mechanism, or if it must remain, require an unguessable per-run shared secret (e.g., a random token generated at `bind()` time, injected into `SignerStopSignaler` and validated in `next_event`'s `/shutdown` branch via constant-time comparison) or restrict `HttpServer::http(listener)` to loopback-only bind addresses and validate the request originates from `127.0.0.1`. Preferably, replace the TCP self-connect shutdown hack with a proper in-process mechanism (e.g., a channel/condvar polled between `recv()` timeouts) that does not expose a shutdown trigger on the network at all.

### Proof of Concept
```rust
use std::net::{TcpListener, TcpStream, SocketAddr};
use std::io::Write;
use libsigner::events::{EventReceiver, SignerEventReceiver};
use libsigner::EventError;

#[test]
fn test_unauthenticated_remote_shutdown() {
    let mut receiver: SignerEventReceiver<SomeMessageType> = SignerEventReceiver::new(false);
    let addr: SocketAddr = "127.0.0.1:0".parse().unwrap(); // use an ephemeral port bound explicitly reachable
    let bound = receiver.bind(addr).unwrap();

    // Simulate a remote unauthenticated attacker (fresh TCP connection, no secret)
    let mut stream = TcpStream::connect(bound).unwrap();
    let body = "x";
    let req = format!(
        "POST /shutdown HTTP/1.1\r\nHost: {}\r\nConnection: close\r\nContent-Length: {}\r\nContent-Type: text/plain\r\n\r\n{}",
        bound, body.len(), body
    );
    stream.write_all(req.as_bytes()).unwrap();

    // The receiver, with no way to distinguish attacker from legitimate signaler,
    // processes the request and terminates.
    let result = receiver.next_event();
    assert!(matches!(result, Err(EventError::Terminated)));
    assert!(receiver.is_stopped());
}
```
This demonstrates that a bare, unauthenticated TCP client reaching the bound event port can trigger `Err(EventError::Terminated)` and permanently flip `is_stopped()`, which would cause `main_loop` to exit on the next iteration.
