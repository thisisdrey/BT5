### Title
Unauthenticated remote shutdown of signer event receiver via `POST /shutdown` - (File: `libsigner/src/events.rs`)

### Summary
The signer's HTTP event-receiver endpoint accepts a bare `POST /shutdown` request with no authentication, secret, or origin check, and unconditionally sets the stop flag and terminates the receive loop. Any remote party able to open a TCP connection to the signer's event-receiver port can permanently halt the signer's event processing with a single crafted request.

### Finding Description
`SignerEventReceiver::next_event` dispatches purely on HTTP method + URL string equality, with no authentication of any kind: [1](#0-0) 

The method gate at line 430 only requires `POST`; there is no shared-secret header, bearer token, or peer-address allowlist check anywhere in this function. The URL branch `request.url() == "/shutdown"` at line 443 unconditionally does `event_receiver.stop_signal.store(true, Ordering::SeqCst)` and returns `Err(EventError::Terminated)`.

Back in `EventReceiver::main_loop`, `Err(EventError::Terminated)` is matched explicitly and breaks the loop, ending the receiver thread: [2](#0-1) 

The legitimate caller of this path, `SignerStopSignaler::send`, builds exactly this raw request (`"POST /shutdown HTTP/1.1\r\n..."`) and connects to `self.local_addr`, i.e. the same TCP endpoint the node's event dispatcher posts `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block` events to: [3](#0-2) 

There is nothing distinguishing this internal self-connect from an external attacker's raw socket: `tiny_http`'s `HttpServer::recv()` accepts any TCP client, and the handler only inspects method + URL string, not source IP, not any secret. Any attacker who can open a TCP connection to this port and send `POST /shutdown HTTP/1.1\r\nContent-Length: 0\r\n\r\n` satisfies the exact equality the dispatch relies on and reaches the same code path as the legitimate stop signaler.

### Impact Explanation
A single unauthenticated HTTP request permanently stops the signer's event-receiver thread. After this, the signer no longer receives `StackerDBChunksEvent` (block proposals, signer messages), `BlockValidateResponse`, `new_burn_block`, or `new_block` events from the node — effectively taking the signer offline for signing duties until the process/thread is manually restarted. This is a remote, unauthenticated, single-message DoS against a signer, matching the "Critical - remote crash/unauthenticated DoS from few messages" category.

### Likelihood Explanation
- No signer/node secret, peer key, or slot ownership is required — the attacker only needs raw TCP reachability to the event-receiver port.
- The exploit is a single HTTP request; no crafted binary payloads, no valid StackerDB signatures, no consensus state are needed.
- Repeatable indefinitely against any signer whose event-receiver port is reachable from the attacker (e.g., misconfigured to bind beyond loopback, or reachable within a shared network/segment).

### Recommendation
Require the event-receiver endpoint to authenticate `POST /shutdown` (and ideally all dispatcher-only endpoints) with a shared secret/token known only to the local node process, or restrict the listener to loopback only and verify the peer address of incoming connections equals the local dispatcher. At minimum, gate `/shutdown` behind the same-process/loopback-only guarantee rather than trusting URL string equality alone.
