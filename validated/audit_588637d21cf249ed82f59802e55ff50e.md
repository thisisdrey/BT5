### Title
Protocol fee bypass via single-unit NEP-245 `TokenDiff` leg fragmentation - (File: `contracts/defuse/core/src/intents/token_diff.rs`)

### Finding Description
The binding that must hold for the fee mechanism to be economically consistent is:

`Pips::fee_ceil(protocol_fee, N)` (fee on one leg with `|delta| == N`) `==` `Σ_{i=1..N} Pips::fee_ceil(protocol_fee, 1)` (fee on N legs each with `|delta| == 1`, same underlying NEP-245 token movement)

This does **not** hold, because `TokenDiff::token_fee` treats `Nep245`/`Imt` legs specially: [1](#0-0) 

For `TokenIdType::Nep245 | TokenIdType::Imt`, if `amount > 1` the normal `fee` is applied, but if `amount == 1` the function short-circuits and returns `Pips::ZERO`. This is invoked per-leg inside `TokenDiff::execute_intent`: [2](#0-1) 

The fee is computed purely from the `delta` of a *single leg of a single `TokenDiff` intent*, with no awareness of how many separate intents/legs move the same NEP-245 asset in aggregate. An unprivileged signer (optionally together with a second self-controlled/colluding account acting as counterparty) can therefore convert one `TokenDiff` with `delta = -N` on a NEP-245 "token-in" (which would pay `Pips::fee_ceil(protocol_fee, N) > 0`) into `N` separate `TokenDiff` intents, each with `delta = -1` on the same NEP-245 token id, matched against corresponding `+1` counter-legs elsewhere in the batch. Each of the `N` legs individually has `amount == 1`, hits the `Nep245 | Imt` fee-exempt branch, and returns `Pips::ZERO`, so `fee_ceil(0, 1) == 0` for every leg. The output side of the trade (the positive delta) never incurs a fee check at all (`if *delta < 0`), so it can be of any token type/amount.

All of this is fully reachable by an unprivileged signer through `execute_intents`/`MultiPayload`: each fragment is a normal, independently-signed `TokenDiff` intent, verified by `MultiPayload::verify`, nonce-checked normally, and the aggregate batch net-zero check (`TransferMatcher::finalize`) is satisfied purely by the deltas themselves (which do sum correctly), not by the fee amounts — so no existing guard (`verify_intent_nonce`, `MaybeLegacyNonces::commit`, `TransferMatcher::finalize`, `assert_one_yocto`, etc.) detects or prevents this, since none of them constrain fee arithmetic across multiple legs/intents.

### Impact Explanation
`fee_collector` receives strictly less than the amount it is owed for the exact same net token movement, i.e. protocol fees are bypassed — this matches the Critical "protocol fees bypassed" category directly. The blast radius covers any NEP-245/IMT-typed asset used as the "token-in" leg of a `TokenDiff` swap; the loss is proportional to trade size and is fully repeatable across accounts, tokens, and batches at will (any signer wishing to swap a NEP-245 asset can always fragment into unit legs to zero out the fee on that leg).

### Likelihood Explanation
The only preconditions are: `engine.state.fee() > Pips::ZERO`, the attacker (or attacker + a cooperating/self-controlled counterparty) holding the NEP-245 balance being swapped, and willingness to sign/submit more intents (more gas, no extra NEAR cost of substance). No privileged role, relayer key, or victim key is required — a normal, unprivileged signer can construct and submit the fragmented `MultiPayload` batch directly via `execute_intents`. This is straightforward to execute and fully repeatable.

### Recommendation
Compute the NEP-245/IMT fee-exemption based on the account's/asset's *aggregate* negative delta for a given token id across the whole intent-execution batch (i.e., defer the `amount > 1` decision to `TransferMatcher`/engine-level accumulation after all intents are applied, not per-individual-leg), or simply remove/tighten the `amount <= 1` fee exemption for `Nep245`/`Imt` token types so it only applies to true single-copy NFT-like tokens rather than any semi-fungible NEP-245 balance that can be fragmented into unit amounts.

### Proof of Concept
`cargo test` plan (in `contracts/defuse/core/src/intents/token_diff.rs` or an integration test under `tests/src/tests/defuse/intents/token_diff.rs`):
1. Set `protocol_fee = Pips::ONE_PERCENT` (or any `Pips > 0`).
2. Case A: build a single `TokenDiff` with `diff = { nep245_token: -100, out_token: +K }` matched by a counterparty leg; call `TokenDiff::execute_intent` (or run through `Engine::execute_signed_intents`) and assert `fees_collected.amount_for(nep245_token) == Pips::ONE_PERCENT.fee_ceil(100) > 0`.
3. Case B: build 100 separate `TokenDiff` intents, each `diff = { nep245_token: -1, out_token: +K/100 }`, matched by 100 corresponding counter-legs in the same batch; run through `Engine::execute_signed_intents` and sum `fees_collected` for `nep245_token` across all `TokenDiffEvent`s.
4. Assert Case B's total fee `== 0` while Case A's fee `> 0`, despite both moving the same net `100` units of the NEP-245 token — demonstrating the binding `Σ fee_ceil(split) == fee_ceil(unsplit)` is violated and `fee_collector`'s `internal_add_balance` credit differs between the two economically-equivalent executions.
