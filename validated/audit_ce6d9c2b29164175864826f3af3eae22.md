### Title
CancelAllUnfreezeV2Actuator re-freezes stake and re-adds voting power without settling pending vote rewards first - ([File: actuator/src/main/java/org/tron/core/actuator/CancelAllUnfreezeV2Actuator.java])

### Summary
`CancelAllUnfreezeV2Actuator.execute()` moves an account's pending `UnFreezeV2` entries back into `FrozenV2` balance (restoring bandwidth/energy/TRON_POWER weight) without first calling `MortgageService.withdrawReward()` / settling the account's outstanding vote reward, unlike every other stake-mutating actuator in the same package.

### Finding Description
Every actuator/processor that changes an account's frozen balance, TRON power or votes in java-tron settles pending vote rewards first by calling `mortgageService.withdrawReward(ownerAddress)` (or `VoteRewardUtil.withdrawReward` in the TVM native-contract equivalents) before mutating `AccountCapsule` state:
- `UnfreezeBalanceActuator.execute()` calls `mortgageService.withdrawReward(ownerAddress)` before unfreezing [1](#0-0) 
- `UnfreezeBalanceV2Actuator.execute()` does the same [2](#0-1) 
- `VoteWitnessActuator.countVoteAccount()` withdraws reward before clearing/re-adding votes [3](#0-2) 
- The equivalent TVM native processors (`UnfreezeBalanceV2Processor`, `VoteWitnessProcessor`) call `VoteRewardUtil.withdrawReward` first as well [4](#0-3) 

`CancelAllUnfreezeV2Actuator`, however, directly reads the account, iterates `unfrozenV2List`, restores frozen balance/weight via `updateFrozenInfoAndTotalResourceWeight`, and writes the account back — with no call to `mortgageService.withdrawReward` (or any reward-settlement routine) anywhere in `execute()`: [5](#0-4) 

This mirrors the Telcoin `removePlugin()` bug class: a state-changing operation on stake/voting power proceeds without first settling/crystallizing the account's currently-accrued reward allowance, which is computed off of the account's begin/end cycle bookkeeping in `DelegationStore` and driven by `MortgageService.withdrawReward()` / `computeReward()` [6](#0-5) .

### Impact Explanation
The vote-reward algorithm computes rewards for a cycle range `[beginCycle, endCycle)` using the account's *current* `getVotesList()` and the `getFrozenBalance`-derived `TronPower`, and updates `beginCycle`/`endCycle` bookkeeping only when `withdrawReward` runs. Because `CancelAllUnfreezeV2Actuator` restores frozen balance/TRON power directly without invoking `withdrawReward` first, the account's un-settled cycles are computed later using a state snapshot that no longer matches what was in effect during the unsettled cycles (frozen amount changed underneath the pending reward window). This can cause incorrect (under- or over-) reward crediting once `withdrawReward` is eventually invoked by another action, i.e., miscalculated/lost yield for the account — an unbacked or permanently-frozen reward, matching the "temporary unavailability of yield" impact category from the original report, but here rooted in TRON's own vote-reward accounting rather than a plugin removal.

### Likelihood Explanation
Any account holder can reach this path directly and unprivileged: `CancelAllUnfreezeV2Contract` is a standard broadcastable transaction type requiring only the account's own signature, gated only by the chain-level `supportAllowCancelAllUnfreezeV2()` feature flag (which is already enabled on mainnet). No special permissions are required, and the actuator is reachable through the standard transaction broadcast/Wallet path.

### Recommendation
Add a call to `mortgageService.withdrawReward(ownerAddress)` (and update votes/allowance bookkeeping consistently with the other unfreeze/vote actuators) at the start of `CancelAllUnfreezeV2Actuator.execute()`, before mutating `FrozenV2`/`UnfreezeV2` state, so that pending rewards are settled against the state that was in effect during the un-settled cycles, consistent with `UnfreezeBalanceActuator`, `UnfreezeBalanceV2Actuator`, and `VoteWitnessActuator`.

### Proof of Concept
1. Freeze balance via `FreezeBalanceV2Contract`, vote for a witness via `VoteWitnessContract` (tron power and votes recorded).
2. Let a cycle elapse (maintenance) so vote rewards accrue in `DelegationStore` per-cycle Vi tables, without withdrawing.
3. Unfreeze via `UnfreezeBalanceV2Contract` (creates `UnFreezeV2` entries, reducing frozen/TRON power weight) — note this call itself does settle reward correctly since it calls `withdrawReward` first.
4. Before the unfreeze expires, submit `CancelAllUnfreezeV2Contract` to restore the frozen balance. Because `CancelAllUnfreezeV2Actuator.execute()` never calls `withdrawReward`, the account's un-settled reward window (`beginCycle`..`endCycle`) is left pointing at a stale `beginCycle` while the underlying frozen/vote weight has just been restored — a subsequent `withdrawReward` call (e.g., triggered by a future vote or unfreeze) computes reward using `computeReward(beginCycle, endCycle, accountCapsule)` against the account's votes list captured only at that later time, not reflecting the intermediate frozen-balance state change introduced by the cancel-all-unfreeze operation, producing a reward calculation inconsistent with the actual voting power held during the unsettled cycles.

Note: I was not able to fully trace every downstream interaction between `CancelAllUnfreezeV2Actuator`'s vote-weight restoration and `VoteRewardUtil`/`MortgageService` reward computation across cycles within the available time; a background Devin session with full repository access and test execution would be needed to construct and run a deterministic unit test (similar to `VoteTest`/`CancelAllUnfreezeV2ActuatorTest`) to confirm the exact reward discrepancy magnitude.

  @Override
  public boolean execute(Object result) throws ContractExeException {
    TransactionResultCapsule ret = (TransactionResultCapsule) result;
    if (Objects.isNull(ret)) {
      throw new RuntimeException(ActuatorConstant.TX_RESULT_NULL);
    }
    long fee = calcFee();
    AccountStore accountStore = chainBaseManager.getAccountStore();
    DynamicPropertiesStore dynamicStore = chainBaseManager.getDynamicPropertiesStore();
    byte[] ownerAddress;
    try {
      ownerAddress = getOwnerAddress().toByteArray();
    } catch (InvalidProtocolBufferException e) {
      logger.debug(e.getMessage(), e);
      ret.setStatus(fee, code.FAILED);
      throw new ContractExeException(e.getMessage());
    }
    AccountCapsule ownerCapsule = accountStore.get(ownerAddress);
    List<UnFreezeV2> unfrozenV2List = ownerCapsule.getUnfrozenV2List();
    long now = dynamicStore.getLatestBlockHeaderTimestamp();
    AtomicLong atomicWithdrawExpireBalance = new AtomicLong(0L);
    /* The triple object is defined by resource type, with left representing the pair object
    corresponding to bandwidth, middle representing the pair object corresponding to energy, and
    right representing the pair object corresponding to tron power. The pair object for each
    resource type, left represents resource weight, and right represents the number of unfreeze
    resources for that resource type. */
    Triple<Pair<AtomicLong, AtomicLong>, Pair<AtomicLong, AtomicLong>, Pair<AtomicLong, AtomicLong>>
        triple = Triple.of(
        Pair.of(new AtomicLong(0L), new AtomicLong(0L)),
        Pair.of(new AtomicLong(0L), new AtomicLong(0L)),
        Pair.of(new AtomicLong(0L), new AtomicLong(0L)));
    for (UnFreezeV2 unFreezeV2 : unfrozenV2List) {
      updateAndCalculate(triple, ownerCapsule, now, atomicWithdrawExpireBalance, unFreezeV2);
    }
    ownerCapsule.clearUnfrozenV2();
    addTotalResourceWeight(dynamicStore, triple);

    long withdrawExpireBalance = atomicWithdrawExpireBalance.get();
    if (withdrawExpireBalance > 0) {
      ownerCapsule.setBalance(ownerCapsule.getBalance() + withdrawExpireBalance);
    }

    accountStore.put(ownerCapsule.createDbKey(), ownerCapsule);
    ret.setWithdrawExpireAmount(withdrawExpireBalance);
    Map<String, Long> cancelUnfreezeV2AmountMap = new HashMap<>();
    cancelUnfreezeV2AmountMap.put(BANDWIDTH.name(), triple.getLeft().getRight().get());
    cancelUnfreezeV2AmountMap.put(ENERGY.name(), triple.getMiddle().getRight().get());
    cancelUnfreezeV2AmountMap.put(TRON_POWER.name(), triple.getRight().getRight().get());
    ret.putAllCancelUnfreezeV2AmountMap(cancelUnfreezeV2AmountMap);
    ret.setStatus(fee, code.SUCESS);
    return true;
  }

  public void withdrawReward(byte[] address) {
    if (!dynamicPropertiesStore.allowChangeDelegation()) {
      return;
    }
    AccountCapsule accountCapsule = accountStore.get(address);
    long beginCycle = delegationStore.getBeginCycle(address);
    long endCycle = delegationStore.getEndCycle(address);
    long currentCycle = dynamicPropertiesStore.getCurrentCycleNumber();
    long reward = 0;
    if (beginCycle > currentCycle || accountCapsule == null) {
      return;
    }
    if (beginCycle == currentCycle) {
      AccountCapsule account = delegationStore.getAccountVote(beginCycle, address);
      if (account != null) {
        return;
      }
    }
    //withdraw the latest cycle reward
    if (beginCycle + 1 == endCycle && beginCycle < currentCycle) {
      AccountCapsule account = delegationStore.getAccountVote(beginCycle, address);
      if (account != null) {
        reward = computeReward(beginCycle, endCycle, account);
        adjustAllowance(address, reward);
        reward = 0;
        logger.info("Latest cycle reward {}, {}.", beginCycle, account.getVotesList());
      }
      beginCycle += 1;
    }
    //
    endCycle = currentCycle;
    if (CollectionUtils.isEmpty(accountCapsule.getVotesList())) {
      delegationStore.setBeginCycle(address, endCycle + 1);
      return;
    }
    if (beginCycle < endCycle) {
      reward += computeReward(beginCycle, endCycle, accountCapsule);
      adjustAllowance(address, reward);
    }
    delegationStore.setBeginCycle(address, endCycle);
    delegationStore.setEndCycle(address, endCycle + 1);
    delegationStore.setAccountVote(endCycle, address, accountCapsule);
    logger.info("Adjust {} allowance {}, now currentCycle {}, beginCycle {}, endCycle {}, "
            + "account vote {}.", Hex.toHexString(address), reward, currentCycle,
        beginCycle, endCycle, accountCapsule.getVotesList());
  }
