### Title
`RecurringAirdrop.claim()` can permanently prevent smart-contract recipients from collecting allocated MET rewards - (File: `contracts/utils/RecurringAirdrop.sol`)

### Summary
The deployed `MetAirdrop` contract inherits `RecurringAirdrop.claim()`, which derives both the Merkle leaf and the claim accounting key directly from `msg.sender`. [1](#0-0)  A smart contract included in the Merkle tree that lacks functionality to invoke `claim()` cannot authorize another account to claim on its behalf, leaving its allocated MET locked in the airdrop contract. [2](#0-1)  `MetAirdrop` is deployed on mainnet at `0x265714B10B9309a8A7A505DBFA6Cb6c39b842309`. [3](#0-2) 

### Finding Description
`claim()` constructs the expected leaf as `keccak256(abi.encodePacked(msg.sender, amount_))`, calculates the remaining allocation using `claimed[msg.sender]`, and transfers the reward only to `msg.sender`. [1](#0-0)  There is no `account` parameter, permit, delegation mechanism, or permissionless claim-to-recipient path. [4](#0-3) 

Although `Operator.execute()` can preserve the original caller for contracts using `SynthContext`, `RecurringAirdrop` does not inherit `SynthContext` and reads raw `msg.sender` directly. [5](#0-4) [6](#0-5)  Consequently, routing the call through `Operator` only changes the observed sender to the Operator contract and does not prove the intended recipient's leaf. [7](#0-6) 

Before the configured lock period expires, successful claims are delivered through `ESMET.lockFor(to_, ...)`; after expiration, MET is transferred directly to the same `msg.sender` recipient. [8](#0-7)  Neither path introduces a separate recipient field that would allow a third party to send the allocation to the entitled contract. [8](#0-7) 

### Impact Explanation
A contract recipient that cannot invoke `claim()` can never produce the required `msg.sender == recipient` condition, so its allocated rewards are permanently unclaimable and remain in `MetAirdrop`. [2](#0-1)  Examples include immutable contracts, contracts without arbitrary execution functionality, deployed smart accounts that cannot target this function, and other contract-controlled addresses included in a distribution. [9](#0-8) 

The broken invariant is liveness for allocated yield: the Merkle root commits tokens to an account, but the sole redemption path requires that account itself to initiate the transaction. [1](#0-0) 

### Likelihood Explanation
The likelihood depends on whether a non-forwarding smart contract is included as an airdrop account; EOA recipients are unaffected because they can directly submit the claim transaction. [1](#0-0)  No attacker action is required beyond demonstrating that third-party calls fail, and no privileged actor can resolve the issue through the public claim interface. [10](#0-9) 

The only administrative functions are updating the Merkle root and lock period; neither provides a rescue or recipient-directed claim mechanism. [11](#0-10) [12](#0-11) 

### Recommendation
Allow anyone to claim on behalf of a recipient while preserving payment to the committed recipient, for example:

```solidity
function claimFor(address account_, uint256 amount_, bytes32[] calldata proof_) external nonReentrant {
    if (merkleRoot == bytes32(0)) revert NothingToClaim();

    bytes32 leaf = keccak256(abi.encodePacked(account_, amount_));
    if (!MerkleProof.verify(proof_, merkleRoot, leaf)) revert InvalidProof();

    uint256 claimable = amount_ - claimed[account_];
    if (claimable == 0) revert NothingToClaim();

    claimed[account_] += claimable;
    _transferReward(account_, claimable);

    emit RewardClaimed(account_, claimable);
}
```

This change preserves the Merkle authorization model while separating the identity of the entitled account from the transaction initiator. [13](#0-12) 

### Proof of Concept
The following Foundry mainnet-fork test demonstrates that a contract recipient's valid allocation cannot be claimed by a third party and that no public recipient-directed path exists. [10](#0-9) 

```solidity
// SPDX-License-Identifier: MIT
pragma solidity 0.8.24;

import "forge-std/Test.sol";
import {MetAirdrop} from "../contracts/MetAirdrop.sol";
import {InvalidProof} from "../contracts/utils/RecurringAirdrop.sol";

contract PassiveRecipient {
    // Intentionally exposes no arbitrary call or airdrop-claim function.
}

contract MetAirdropContractRecipientPoC is Test {
    MetAirdrop internal airdrop;
    PassiveRecipient internal recipient;
    address internal attacker = makeAddr("attacker");

    function setUp() public {
        vm.createSelectFork(vm.envString("MAINNET_RPC_URL"));

        // The test contract deploys MetAirdrop and is therefore its governor.
        airdrop = new MetAirdrop();
        recipient = new PassiveRecipient();

        uint256 amount = 100 ether;
        bytes32[] memory proof = new bytes32[](0);
        bytes32 leaf = keccak256(abi.encodePacked(address(recipient), amount));

        airdrop.updateMerkleRoot(leaf, bytes32(uint256(1)));

        deal(address(airdrop.MET()), address(airdrop), amount);

        // Move beyond the lock window so a successful claim would transfer MET
        // directly rather than requiring the external esMET lock path.
        vm.warp(airdrop.updatedAt() + airdrop.lockPeriod() + 1);
    }

    function test_contractRecipientAllocationCannotBeClaimedByAnyoneElse() public {
        uint256 amount = 100 ether;
        bytes32[] memory proof = new bytes32[](0);

        // The caller's address is hashed into the leaf, so using the recipient's
        // valid allocation from another account fails Merkle verification.
        vm.prank(attacker);
        vm.expectRevert(InvalidProof.selector);
        airdrop.claim(amount, proof);

        assertEq(airdrop.claimed(address(recipient)), 0);
        assertEq(airdrop.MET().balanceOf(address(recipient)), 0);
        assertEq(airdrop.MET().balanceOf(address(airdrop)), amount);

        // PassiveRecipient has no function capable of invoking airdrop.claim(),
        // and MetAirdrop has no claimFor(account, ...) function. Its allocation
        // therefore remains frozen in the airdrop contract.
    }
}
```

     * @notice Claim reward
     * @dev Every tree leaf is a `[account, amount]` tuple, we assume that the `msg.sender` is the account
     * @param amount_ The amount to claim
     * @param proof_ The merkle tree proof for the given leaf
     */
    function claim(uint256 amount_, bytes32[] calldata proof_) external nonReentrant {
        if (merkleRoot == bytes32(0)) revert NothingToClaim();

        bytes32 _leaf = keccak256(abi.encodePacked(msg.sender, amount_));
        if (!MerkleProof.verify(proof_, merkleRoot, _leaf)) revert InvalidProof();

        uint256 _claimable = amount_ - claimed[msg.sender];
        if (_claimable == 0) revert NothingToClaim();

        claimed[msg.sender] += _claimable;

        _transferReward(msg.sender, _claimable);

        emit RewardClaimed(msg.sender, _claimable);
    }

     * @param to_ The claim account
     * @param amount_ The reward amount
     */
    function _transferReward(address to_, uint256 amount_) internal virtual {

    }
