## Finding

An unauthenticated attacker with network access to a `stacks-signer`'s event-listener HTTP port can permanently kill the signer's ability to receive events from the node by sending a single unauthenticated `POST /shutdown` request.

### Title
Unauthenticated remote shutdown of stacks-signer event receiver via `/shutdown` HTTP endpoint - (File: libsigner/src/events.rs)

### Summary
The `SignerEventReceiver` used by `stacks-signer` runs a plaintext HTTP server (bound, per sample configs, to `0.0.0.0:<port>`) that the Stacks node uses to push events (block proposals, burn blocks, StackerDB chunks) to the signer. None of the routes handled in `next_event`, including `/shutdown`, perform any authentication check before acting on the request. [1](#0-0) 

### Finding Description
`SignerEventReceiver::next_event` dispatches purely on URL path with no credential/token check:
- `/status` → replies `OK` (liveness, low-risk)
- `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block` → deserialize event payloads (at least these are later gated by StackerDB chunk signature checks downstream)
- `/shutdown` → sets `event_receiver.stop_signal.store(true, Ordering::SeqCst)` and returns `Err(EventError::Terminated)` [2](#0-1) 

The stop signal is consumed by `EventReceiver::main_loop`, which `break`s out of its loop as soon as `Err(EventError::Terminated)` is returned, permanently ending the event receiver's execution: [3](#0-2) 

This HTTP listener is bound directly with `HttpServer::http(listener)` and accepts any TCP connection to the configured address: [4](#0-3) 

`libsigner/src/http.rs`'s `decode_http_request`/`run_http_request` helpers confirm there is no `Authorization` header check anywhere in the transport code — no such check exists in this file at all.

Per the sample signer configuration, this listener binds to all interfaces by default (`endpoint = "0.0.0.0:30000"`), matching the deployment pattern described in `docs/signing.md`. The only authentication mechanism documented in this repo (`auth_token`/`auth_password`) secures the **node's** RPC endpoints (e.g. `/v3/block_proposal`), not the signer's own inbound event listener: [5](#0-4) 

There is no equivalent authentication check on the signer side for its inbound `/shutdown`, `/stackerdb_chunks`, `/new_burn_block`, `/new_block`, or `/proposal_response` handlers.

### Impact Explanation
The signer's event receiver is the sole channel by which the node feeds it block proposals, burn-block notifications, and StackerDB signer messages. A single unauthenticated `POST /shutdown` from any network-reachable host permanently terminates this receiver thread (`main_loop` `break`s and exits), silently cutting the signer off from all further events. Because Nakamoto block signing depends on signers responding to proposals delivered exclusively through this channel, this equates to an unauthenticated remote DoS against a signer's operation with a single crafted request — no volume/flooding needed. This matches the "Critical - remote crash/unauthenticated DoS from few messages" impact category.

### Likelihood Explanation
Trivial to exploit: it only requires network reachability to the signer's bind address/port (commonly `0.0.0.0:<port>` per the shipped sample config) and one raw HTTP POST with path `/shutdown`. No cryptographic material, node secret, or privileged role is required.

### Recommendation
Require the signer's `auth_password`/shared secret (the same value used to authenticate the node↔signer channel per `docs/signing.md`) on all inbound requests to `SignerEventReceiver`, especially `/shutdown`, before acting on them. Reject any request lacking a valid `Authorization` header matching the configured secret, mirroring the Bearer-auth gating pattern already used for `/v3/block_proposal` on the node side (`stackslib/src/net/api/postblock_proposal.rs`).

### Proof of Concept
1. Start a `stacks-signer` configured with `endpoint = "0.0.0.0:30000"` (as in the sample config).
2. From any host that can reach port 30000, send:
```
POST /shutdown HTTP/1.1
Host: <signer-ip>:30000
Connection: close
Content-Length: 0

```
3. Observe (per `libsigner/src/events.rs` lines 441-446 and 296-311) that the event receiver's `main_loop` logs "Caught termination signal" and exits — the signer stops receiving any further node events (block proposals, burn blocks, StackerDB chunks) without needing to know any secret or restart the process. [6](#0-5)

```rust
    fn next_event(&mut self) -> Result<SignerEvent<T>, EventError> {
        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)
            } else if request.url() == "/new_block" {
                process_event::<T, StacksBlockEvent>(request)
            } else {
                let url = request.url().to_string();
                debug!(
                    "[{:?}] next_event got request with unexpected url {}, return OK so other side doesn't keep sending this",
                    event_receiver.local_addr,
                    url
                );
                ack_dispatcher(request);
                Err(EventError::UnrecognizedEvent(url))
            }
        })?
    }
```
