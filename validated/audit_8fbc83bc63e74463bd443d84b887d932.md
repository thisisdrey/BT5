### Title
Unauthenticated remote shutdown of signer event receiver via `/shutdown` endpoint - (File: libsigner/src/events.rs)

### Summary
The `SignerEventReceiver::next_event` handler treats any POST to `/shutdown` as an authoritative stop signal with no verification that the sender is the local node or the `SignerStopSignaler`. Any remote peer able to open a TCP connection to the signer's bound event-receiver port can permanently terminate the signer's event-processing loop with a single crafted HTTP request.

### Finding Description
The intended invariant is that only the local node (via its event dispatcher) or the signer's own `SignerStopSignaler::send` (called internally on shutdown, `libsigner/src/events.rs:376-396`) should be able to stop the event receiver thread. Instead, `next_event` matches `request.url() == "/shutdown"` unconditionally at [1](#0-0) , calling `event_receiver.stop_signal.store(true, Ordering::SeqCst)` and returning `Err(EventError::Terminated)` for any POST, regardless of origin, source IP, or any credential. There is no check against `local_addr`, no shared secret, no TLS client cert, nothing — the equality "authenticated shutdown authority == any TCP sender" is broken because it's actually "any TCP sender == shutdown authority."

`main_loop` ( [2](#0-1) ) treats `EventError::Terminated` as a normal, successful termination ("we're done") and `break`s out of the loop entirely, ending the thread. Since `is_stopped()` (line 462-464) reads the same `stop_signal` `AtomicBool`, and it is now permanently `true`, the receiver can never restart itself — any subsequent legitimate StackerDB chunk/burn-block/block-validation-response event sent by the actual node is simply never read because the HTTP server socket is no longer being polled by the (now-dead) thread.

Existing guards that don't help: the endpoint only checks HTTP method (must be POST) and exact URL match — no signature check, no secret gate, no length cap relevant here since this isn't a data-carrying message needing validation. This is the signer's own locally-bound HTTP listener (distinct from the node's RPC secret-gated API), and nothing in `bind()` ( [3](#0-2) ) or elsewhere restricts inbound connections to loopback or authenticates the peer.

### Impact Explanation
A single POST request from any remote peer that can reach the signer's event-receiver TCP port permanently kills that signer's event-processing thread. After this, the signer stops receiving and processing all StackerDB chunks (block responses, state-machine updates, etc.), burn-block events, and block-validation responses from the node — effectively taking the signer offline for consensus participation until manually restarted. This is a Critical unauthenticated remote DoS achievable with one crafted message, matching the "remote crash/unauthenticated DoS from few messages" category.

### Likelihood Explanation
No privileged role, secret, or prior state is required — only network reachability to the signer's bound event-receiver port (typically configured and possibly exposed beyond loopback depending on deployment/binding address). The attack is a single, trivially repeatable POST request costing the attacker nothing.

### Recommendation
Gate the `/shutdown` path with an authentication check — e.g., restrict acceptance to loopback/local connections only (verify `request` peer address if `tiny_http` exposes it), or require a shared secret/token known only to the node and signer that must be included in the shutdown request and verified before honoring it.
