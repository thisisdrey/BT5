### Title
Unbounded Paths/Attributes lists in GetFileAttributes cause serial subprocess DoS - ([File: internal/gitaly/service/repository/file_attributes.go])

### Summary
`validateGetFileAttributesRequest` only checks that `Paths` and `Attributes` are non-empty, with no upper bound on their length. An attacker with only push/fetch access to their own repository can send a `GetFileAttributesRequest` with hundreds of thousands of `Paths`/`Attributes` entries, forcing the handler to invoke `checkAttrCmd.Check(path)` once per path in a serial loop, each of which performs a synchronous write/flush/read round-trip against the `git check-attr` subprocess.

### Finding Description
`GetFileAttributes` calls `validateGetFileAttributesRequest`, which enforces only `len(in.GetPaths()) == 0` and `len(in.GetAttributes()) == 0` checks with no maximum size guard. [1](#0-0) 

After validation, `gitattributes.CheckAttr` spawns a `git check-attr --stdin -z --source=<revision> <attributes...>` subprocess, passing every attacker-controlled attribute name directly as a command argument, and then the handler loops over every path, calling `checkAttrCmd.Check(path)` serially for each one. [2](#0-1) 

Each `Check(path)` call takes a mutex, writes the path to the subprocess's stdin, flushes, then blocks reading `c.count` (i.e., `len(attributes)`) null-delimited triples back from stdout before returning. [3](#0-2) 

This means total work is proportional to `len(Paths) × len(Attributes)`, executed synchronously within a single RPC handler invocation, with no per-request cap, timeout override, or streaming/pagination to bound the cost. A single crafted request (e.g., 100k paths × 100 attributes) can drive the check-attr subprocess and the handler goroutine into extended CPU/wall-clock consumption, and since paths/attributes are fairly small strings, a request well within typical gRPC message-size limits (e.g., a few MB) can encode very large N.

### Impact Explanation
This matches a DoS-of-RPC-handler class: an unauthenticated-in-content, low-privilege attacker (anyone who can push to and call RPCs against a repository they control) can consume disproportionate CPU and wall-clock time on the Gitaly node for a single RPC call. Because Gitaly is a shared multi-tenant service per storage, prolonged handler execution can degrade RPC availability for the storage shard hosting the attacker's repository, affecting other tenants sharing that storage/node.

### Likelihood Explanation
The precondition is minimal: any user with push/fetch access to a repository (including a repository they own/import) can call `GetFileAttributesRequest` with an arbitrarily large `Paths`/`Attributes` list, since `validateGetFileAttributesRequest` performs no upper-bound check on either list. The attack is trivially repeatable and requires no privileged role, no secret, and no misconfiguration.

### Recommendation
Add explicit upper bounds in `validateGetFileAttributesRequest` for `len(in.GetPaths())` and `len(in.GetAttributes())` (returning `InvalidArgument` when exceeded), and/or enforce a combined `Paths × Attributes` product limit before invoking `gitattributes.CheckAttr`. Consider also imposing a request-scoped timeout/context deadline independent of the general RPC timeout to bound subprocess I/O cost.

func validateGetFileAttributesRequest(ctx context.Context, locator storage.Locator, in *gitalypb.GetFileAttributesRequest) error {

		return err
	}

		return errors.New("revision is required")
	}

		return errors.New("file paths are required")
	}

	if len(in.GetAttributes()) == 0 {
		return errors.New("attributes are required")
	}

	return nil

func (c CheckAttrCmd) Check(path string) (Attributes, error) {
	if strings.Contains(path, "\000") {
		return nil, fmt.Errorf("path with NUL byte not allowed")
	}

	c.m.Lock()
	defer c.m.Unlock()

	if _, err := c.stdin.WriteString(path + "\000"); err != nil {
		return nil, fmt.Errorf("write path: %w", err)
	}
	if err := c.stdin.Flush(); err != nil {
		return nil, fmt.Errorf("flush: %w", err)
	}

	attrs := Attributes{}
	buf := make([]string, 0, 3)

	// Using git-check-attr(1) with -z will return data in the format:
	// <path> NUL <attribute> NUL <info> NUL ...
	for i := 0; i < c.count; {
		word, err := c.stdout.ReadBytes('\000')
		if err != nil {
			return nil, fmt.Errorf("read line: %w", err)
		}

		buf = append(buf, string(bytes.TrimSuffix(word, []byte{0})))

		if len(buf) < 3 {
			continue // Keep going until we have 3 words
		}

		if buf[0] != path {
			return nil, fmt.Errorf("wrong path name detected, expected %q, got %q", path, buf[0])
		}
		if buf[2] != Unspecified {
			attrs = append(attrs, Attribute{Name: buf[1], State: buf[2]})
		}

		i++
		buf = buf[:0]
	}

	return attrs, nil
}
