### Title
`flashWithdraw` bypasses the pool pause and locked-balance checks that guard `withdraw`/`withdrawFrom`, allowing collateral exit during emergency pause - ([File: contracts/DepositToken.sol](contracts/DepositToken.sol))

### Summary
Analogous to the jackson-databind `@JsonView` bypass — where a restriction was enforced on one deserialization branch but skipped on the "merging" branch — `DepositToken` enforces the lock check `_revertIfLocked` and `whenNotPaused` on the direct withdrawal paths, but the SmartFarmingManager "merging" path (`flashRepay` → `flashWithdraw` → `_withdraw`) performs neither check.

### Finding Description
The normal exit paths are gated:

- `deposit()` is `whenNotPaused` (`DepositToken.sol:214`), and `withdraw()` requires `whenNotPaused` implicitly via pause on pool operations plus explicitly calls `_revertIfLocked(_msgSender, amount_)` (`DepositToken.sol:406-412`).
- `withdrawFrom()` also calls `_revertIfLocked(from_, amount_)` (`DepositToken.sol:420-427`).

However, `flashWithdraw()` only has `onlyIfSmartFarmingManager` and delegates to `_withdraw`, which is `whenNotShutdown nonReentrant` — **not** `whenNotPaused`, and it never calls `_revertIfLocked` (`DepositToken.sol:245-250, 536-554`). The NatSpec even states "This function doesn't check if the amount is unlocked!".

`SmartFarmingManager.flashRepay()` — a public, unprivileged entry point — calls `depositToken_.flashWithdraw(_msgSender, withdrawAmount_)` guarded only by `whenNotShutdown` (`SmartFarmingManager.sol:98-122`).

An unprivileged attacker/user can therefore:

1. Call `SmartFarmingManager.flashRepay(synth, depositToken, withdrawAmount, minOut)` while the Pool is **paused** (not shutdown), or
2. Withdraw collateral that is `locked` because it backs open debt, as long as the final `debtPositionOf` health check passes — i.e., by repaying just enough debt via the swap, or withdrawing locked balance from a position whose `issuableInUsd` bookkeeping leaves headroom.

The `_revertIfLocked` check exists precisely to keep collateral locked while it backs debt; the pause exists to halt user exits during emergencies (oracle incident, insolvency response, exploit containment). Both are silently skipped on this branch.

### Impact Explanation
During an emergency pause (e.g., triggered to stop withdrawals while a bad oracle price or insolvency is handled), any user can still extract collateral through `flashRepay`, racing ahead of other depositors and draining Treasury-held underlying — first-mover theft of user funds / amplification of insolvency. Separately, the missing `_revertIfLocked` lets a borrower withdraw collateral that `unlockedBalanceOf` marks non-withdrawable, weakening the lock invariant that protects solvency; the post-tx health check only bounds this to "position remains healthy," not to "locked balance respected," which matters for underwater-threshold edge cases and dust-level positions under `debtFloorInUsd`.

### Likelihood Explanation
Reachable by any EOA via `Operator.execute` or a direct call to `SmartFarmingManager.flashRepay` with attacker-chosen `depositToken_`, `syntheticToken_`, and amounts. No privileged role needed. Requires either the pool to be paused (emergency scenario — exactly when the check matters) or a position with locked balance to partially unlock. Slippage and the final `PositionIsNotHealthy` check constrain but do not close the path.

### Recommendation
Apply the same guards on the flash path as on the direct path: add `whenNotPaused` to `flashWithdraw`/`_withdraw` (or to `SmartFarmingManager.flashRepay`), and either call `_revertIfLocked(account_, amount_)` inside `flashWithdraw` or explicitly document and bound the divergence — e.g., enforce that the withdrawn amount plus repaid debt keeps `unlockedBalanceOf` semantics by checking the pre-operation unlocked balance.

### Proof of Concept
Hardhat sketch (fork of a live deployment):

```ts
// 1. User deposits collateral, issues synth debt (position healthy).
await depositToken.deposit(amount, user.address);
await debtToken.issue(debt, user.address);

// 2. Governor pauses the pool (emergency).
await pool.connect(governor).pause(); // whenNotPaused now blocks withdraw()

// 3. Direct withdraw reverts:
await expect(depositToken.connect(user).withdraw(amount, user.address))
  .to.be.reverted; // paused

// 4. But flashRepay path is unguarded by whenNotPaused / _revertIfLocked:
//    withdraw collateral, swap -> synth, repay debt, health check passes.
await sfm.connect(user).flashRepay(
  syntheticToken.address,
  depositToken.address,
  withdrawAmount,
  minOut
);
// => succeeds: user exits collateral while pool is paused and/or while
//    balance was marked locked by unlockedBalanceOf().
```

Key lines: `DepositToken.sol:245-250` (`flashWithdraw`, no pause/lock check), `DepositToken.sol:536-540` (`_withdraw` is `whenNotShutdown` only), `DepositToken.sol:406-412` (`withdraw` checks `_revertIfLocked`), `SmartFarmingManager.sol:98-122` (`flashRepay` → `flashWithdraw` with only `whenNotShutdown`).
