### Title
Zero-fee oracle-priced synthetic swaps enable MEV reordering profit extraction - (File: contracts/Pool.sol)

### Summary
`Pool.swap` prices synthetic-to-synthetic swaps solely via `masterOracle().quote` and only deducts a fee when `feeProvider.swapFees(synthIn, synthOut)` returns a non-zero value. That mapping is directional and defaults to `0` for any unconfigured pair, so entire classes of synth pairs (e.g. anything other than the explicitly configured `msUSD <-> msETH` directions) can be swapped fee-free at the raw oracle price. An attacker who can observe/order oracle price updates relative to `swap` calls can round-trip a zero-fee pair across a price update and mint more synthetic value than they burned, diluting the collateral backing of the synth supply.

### Finding Description
`swap` burns `syntheticTokenIn_` and mints `syntheticTokenOut_` at the oracle conversion rate returned by `quoteSwapOut`, which calls `masterOracle().quote(synthIn, synthOut, amountIn)` directly. The only mitigation against oracle-latency arbitrage is `_fee = _amountOut.wadMul(_swapFee)`, and `_swapFee` comes from `feeProvider.swapFees(in, out)`, a `mapping(address => mapping(address => uint256))` that returns `0` for any pair/direction governance has not explicitly configured. Deploy scripts only set fees for a couple of directions (`msUSD => msETH` at 1%, `msETH => msUSD` at 0.35–0.45%); every other registered synthetic pair (msDOGE, msBTC, etc.) swaps at the raw oracle quote with zero fee in both directions. This mirrors the reported bug exactly: a no-fee, oracle-priced swap primitive where profit from a stale-but-valid price exceeds zero.

### Impact Explanation
Each zero-fee round trip across an oracle price movement mints net-new synthetic tokens for the attacker without any corresponding debt or collateral deposit. Since synthetic tokens are redeemable claims against pooled collateral (and can repay any user's debt), the attacker extracts real backing value, pushing the system toward undercollateralization — protocol insolvency. The attack is repeatable on every oracle update cycle, bounded only by the attacker's synth inventory (which can be amplified via `DebtToken.flashIssue`/leverage).

### Likelihood Explanation
Requires a public entry point (`Pool.swap` is permissionless, guarded only by `whenNotShutdown`, `nonReentrant`, and `isSwapActive`), two registered synthetic tokens on a pair with no configured fee, and the ability to reorder a `swap` against a valid oracle price update — standard MEV reordering, not incorrect oracle data. Modifiers and checks do not stop it: there is no minOut/slippage parameter, no freshness check, and no health check on the swapper. Exploitability depends on the deployed configuration leaving a pair at zero fee, which the deploy scripts demonstrate is the default state for all non-whitelisted pairs.

### Recommendation
Enforce a mandatory non-zero minimum swap fee (a `defaultSwapFee` floor) applied to every direction, and/or charge the fee on the input side so an unconfigured pair cannot trade at raw oracle parity. Alternatively, bound the oracle quote by a minimum received / slippage parameter supplied by the caller, or require a `quoteTimestamp`/freshness bound on `MasterOracle` quotes.

### Proof of Concept
1. Registered synths `msA` and `msB` have `feeProvider.swapFees(msA, msB) == 0` and `swapFees(msB, msA) == 0` (default for unconfigured pairs — see `FeeProviderStorageV2.swapFees` and the directional-default-zero tests in `test/FeeProvider.test.ts` and `test/foundry/FeeProvider.fuzz.t.sol`).
2. Attacker holds `X` of `msA` (or mints it via `DebtToken.flashIssue` inside one transaction).
3. A valid oracle price update raising `msA`'s USD price relative to `msB` is pending. Attacker orders `pool.swap(msA, msB, X)` **before** the update executes — no wait: order `swap(msB→msA)` before the update and `swap(msA→msB)` after, i.e. buy the appreciating synth at the stale price and sell back at the new price in the same block (or adjacent, controlling ordering).
4. Because both legs charge zero fee (`_swapFee == 0` path in `quoteSwapOut` / `quoteSwapIn`), the round trip returns strictly more `msA` than `X`, equal to `X * (newPrice/oldPrice - 1)`, minted out of thin air at `syntheticTokenOut_.mint(_msgSender, _amountOut)` (Pool.sol:668).
5. Repeat each oracle update cycle; extracted value dilutes collateral backing of all outstanding synths.

Reproducible in the existing Hardhat harness: the test `should swap synthetic tokens (swapFee == 0)` in `test/Pool.test.ts:1067` already demonstrates a fee-free oracle-priced swap on an unconfigured pair; a fork test only needs to interleave a price update between two opposing zero-fee swaps to show net minted profit.     function quoteSwapOut(
        ISyntheticToken syntheticTokenIn_,
        ISyntheticToken syntheticTokenOut_,
        uint256 amountIn_
    ) public view override returns (uint256 _amountOut, uint256 _fee) {
        _amountOut = _poolRegistry.masterOracle().quote(
            address(syntheticTokenIn_),
            address(syntheticTokenOut_),
            amountIn_
        );

        uint256 _swapFee = feeProvider.swapFees(address(syntheticTokenIn_), address(syntheticTokenOut_));

        if (_swapFee > 0) {
            _fee = _amountOut.wadMul(_swapFee);
            _amountOut -= _fee;
        }
    }

    function swap(
        ISyntheticToken syntheticTokenIn_,
        ISyntheticToken syntheticTokenOut_,
        uint256 amountIn_
    )
        external
        override
        whenNotShutdown
        nonReentrant
        onlyIfSyntheticTokenExists(syntheticTokenIn_)
        onlyIfSyntheticTokenExists(syntheticTokenOut_)
        returns (uint256 _amountOut, uint256 _fee)
    {
        address _msgSender = _msgSender();

        if (!isSwapActive) revert SwapFeatureIsInactive();
        if (amountIn_ == 0 || amountIn_ > syntheticTokenIn_.balanceOf(_msgSender)) revert AmountInIsInvalid();

        syntheticTokenIn_.burn(_msgSender, amountIn_);

        (_amountOut, _fee) = quoteSwapOut(syntheticTokenIn_, syntheticTokenOut_, amountIn_);

        if (_fee > 0) {
            syntheticTokenOut_.mint(_poolRegistry.feeCollector(), _fee);
        }

        syntheticTokenOut_.mint(_msgSender, _amountOut);

        emit SyntheticTokenSwapped(_msgSender, syntheticTokenIn_, syntheticTokenOut_, amountIn_, _amountOut, _fee);
    }
