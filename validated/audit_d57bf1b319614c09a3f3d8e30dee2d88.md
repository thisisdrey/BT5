### Title
Shareholder-Triggered DoS of `vesting::distribute` via `set_allow_direct_coin_transfers(false)` — (File: `aptos-move/framework/aptos-framework/sources/vesting.move`)

---

### Summary

`vesting::distribute` iterates over all shareholders and calls `aptos_account::deposit_coins` for each recipient inside a single transaction with no per-recipient error handling. A single shareholder can permanently block all distributions for every other shareholder by calling `set_allow_direct_coin_transfers(false)` while holding an account that lacks the legacy `CoinStore<AptosCoin>` (the default for new accounts post-FA migration). This is the direct Aptos analog of the external bug: a user manipulates their own account state to cause a protocol-level receive to abort, freezing funds for all other participants.

---

### Finding Description

**Root cause — `vesting::distribute` has no per-recipient fault isolation:** [1](#0-0) 

Every shareholder's payout is dispatched inside a single `for_each_ref` closure. If `aptos_account::deposit_coins` aborts for any one recipient, the entire transaction reverts, leaving all other shareholders unpaid and the coins locked in the pool.

**The abort path in `aptos_account::deposit_coins`:** [2](#0-1) 

When the recipient does **not** have a legacy `CoinStore<AptosCoin>` (i.e., `coin::is_account_registered<AptosCoin>` returns `false`) **and** `can_receive_direct_coin_transfers` returns `false`, the function aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` before ever reaching `coin::deposit`.

**New accounts default to FA-only, no legacy coin store:** [3](#0-2) 

`register_apt` only creates the primary fungible store; it does **not** call `coin::register<AptosCoin>`. The `new_accounts_default_to_fa_apt_store_enabled()` feature flag is permanently `true`. [4](#0-3) 

So any shareholder whose account was created after the FA migration has `coin::is_account_registered<AptosCoin>() == false`.

**`create_vesting_contract` does NOT validate shareholder APT registration:** [5](#0-4) 

`assert_account_is_registered_for_apt` is called only for `withdrawal_address`, not for each shareholder. Shareholders with FA-only accounts are accepted without restriction.

**The user-controlled state change (the "authority change" analog):** [6](#0-5) 

Any account holder can call `set_allow_direct_coin_transfers(false)` at any time, setting `allow_arbitrary_coin_transfers = false`. Combined with the absence of a legacy coin store, this makes `deposit_coins` abort deterministically.

**Same pattern in `staking_contract::distribute_internal`:** [7](#0-6) 

The staking contract distribution loop has the identical structural flaw.

---

### Impact Explanation

A single malicious (or griefing) shareholder can permanently freeze all APT distributions from a vesting contract. Every call to `vesting::distribute` or `vesting::distribute_many` will revert as long as the attacker keeps `allow_arbitrary_coin_transfers = false`. All other shareholders' vested APT remains locked in the contract with no recovery path, because there is no admin function to skip or remove a single shareholder from the distribution loop. This constitutes permanent freezing of user-controlled vesting balances.

---

### Likelihood Explanation

- Any shareholder with a post-FA-migration account (the default) is in the vulnerable state by default regarding the coin store.
- `set_allow_direct_coin_transfers` is a public entry function callable by any account holder at zero cost.
- The attack is reversible by the attacker (they can re-enable transfers), making it a persistent, on-demand DoS weapon rather than a one-time action.
- No privileged access is required beyond being a shareholder, which is set at contract creation by the admin.

---

### Recommendation

1. **Wrap each per-recipient deposit in a try/catch pattern** (or use a separate distribution queue) so that one recipient's failure does not block others.
2. **Validate at contract creation** that every shareholder has `coin::is_account_registered<AptosCoin>` true, or migrate the distribution path to use `primary_fungible_store::deposit` (FA path) which bypasses the `can_receive_direct_coin_transfers` gate.
3. **Add an admin escape hatch** to skip or re-route a stuck shareholder's distribution to the withdrawal address.

---

### Proof of Concept

1. Admin creates a vesting contract with two shareholders: `alice` (normal account) and `bob` (FA-only account, no legacy coin store).
2. `bob` calls `aptos_account::set_allow_direct_coin_transfers(false)`.
3. Time passes; vesting period elapses; `vest()` is called successfully.
4. Anyone calls `vesting::distribute(contract_address)`.
5. The loop reaches `bob`; `coin::is_account_registered<AptosCoin>(bob)` → `false`; `can_receive_direct_coin_transfers(bob)` → `false`; transaction aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS`.
6. `alice` receives nothing. The vested APT remains locked in the contract indefinitely.
7. `bob` can maintain this state at zero ongoing cost, permanently blocking all distributions.

    public entry fun set_allow_direct_coin_transfers(
        account: &signer, allow: bool
    ) acquires DirectTransferConfig {
        let addr = signer::address_of(account);
        if (exists<DirectTransferConfig>(addr)) {
            let direct_transfer_config = borrow_global_mut<DirectTransferConfig>(addr);
            // Short-circuit to avoid emitting an event if direct transfer config is not changing.
            if (direct_transfer_config.allow_arbitrary_coin_transfers == allow) { return };

            direct_transfer_config.allow_arbitrary_coin_transfers = allow;

            emit(
                DirectCoinTransferConfigUpdated {
                    account: addr,
                    new_allow_direct_transfers: allow
                }
            );
        } else {
            let direct_transfer_config = DirectTransferConfig {
                allow_arbitrary_coin_transfers: allow,
                update_coin_transfer_events: new_event_handle<
                    DirectCoinTransferConfigUpdatedEvent>(account)
            };
            emit(
                DirectCoinTransferConfigUpdated {
                    account: addr,
                    new_allow_direct_transfers: allow
                }
            );
            move_to(account, direct_transfer_config);
        };
