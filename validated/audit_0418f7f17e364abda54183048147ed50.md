### Title
Firewall rule revocation bypass via stale routine-local conntrack cache decoupled from `rulesVersion` - ([File: firewall.go])

### Summary
`Firewall.inConns` in `firewall.go` short-circuits and grants a packet permission if the flow's 5‑tuple is present in the caller's routine-local `ConntrackCache`, before it ever checks whether the underlying conntrack entry's `rulesVersion` still matches the firewall's current `rulesVersion`. The per-routine cache (`firewall/cache.go`) is invalidated purely on a wall-clock ticker (`firewall.conntrack.routine_cache_timeout`), which is completely independent of firewall reloads (SIGHUP). This is directly analogous to the reported `supportEMode` bug class: a permission (elevated collateral factor / firewall pass) that should be revoked when the underlying authorization changes (asset removed from E‑Mode / firewall rule removed) continues to be honored because the caching/accounting layer is not re-validated against the new authoritative state.

Because the local cache check happens *before* the `rulesVersion` comparison, and the local cache's own invalidation is driven by an independent time-based ticker rather than by `rulesVersion`, a flow that was permitted under an old ruleset continues to be treated as permitted for the remainder of the cache's tick window — even though the authoritative conntrack/rulesVersion mechanism was specifically built to prevent this. This mirrors the E‑Mode report's root cause: an authorization/attribute value (E‑Mode collateral factor / firewall permission) is cached at time of grant and is not re-derived from the current authoritative configuration when that configuration is intentionally narrowed.

### Impact Explanation
If an operator removes or tightens a firewall rule (e.g., revoking a group's access, removing a host from an "any" rule) via a live SIGHUP reload — the exact administrative action the `rulesVersion`/reload mechanism exists to enforce promptly — packets belonging to already-established flows can continue to traverse the firewall for up to the configured `routine_cache_timeout` window (recommended default 1s when `routines > 1`, but operator-configurable higher) purely because they hit the stale per-routine cache instead of the authoritative conntrack table. This is a firewall enforcement bypass: traffic that the operator has explicitly decided should now be dropped is instead allowed to pass, undermining the security boundary the firewall rules are meant to provide.

### Likelihood Explanation
This requires only a legitimate, already-flowing connection that predates a firewall rule change, and multiple tun/udp routines with the routine-local conntrack cache enabled (`routines > 1`, which is a fairly common performance configuration, or explicitly configured `firewall.conntrack.routine_cache_timeout`). No malicious certificate or unauthenticated attacker action is needed to trigger the bypass window; it is a straightforward operational sequence (active flow + firewall reload) rather than a crafted attack, making it moderately likely to occur in real deployments without indicating any observable protocol/handshake evidence, and undetectable to the operator who reasonably assumes the new rules take effect immediately as the `rulesVersion` design implies.

### Recommendation
Tie the routine-local `ConntrackCache` invalidation to the firewall's `rulesVersion` rather than (or in addition to) a wall-clock ticker, e.g., have `ConntrackCacheTicker.Get()`/`inConns` compare against the firewall's current `rulesVersion` and drop/reset cached entries whenever it changes, or simply skip the local-cache fast path whenever a reload has occurred since the entry was cached. Alternatively, remove the early-return local-cache check entirely for the first packet observed after a reload, always falling through to the authoritative `c.rulesVersion != f.rulesVersion` revalidation path in `inConns`.

### Proof of Concept
1. Configure Nebula with `routines: 2+` (or explicitly set `firewall.conntrack.routine_cache_timeout` to a non-zero value) so `NewConntrackCacheTicker` is active, as wired in `main.go`.
2. Establish an allowed flow between two hosts (e.g., rule allowing group `A` on UDP/443); the flow is recorded in both the routine-local `ConntrackCache` and the shared `Conntrack.Conns` with the current `rulesVersion`.
3. Operator issues SIGHUP after editing the firewall config to remove the rule allowing group `A` (or removes the host from an "any" rule); `reloadFirewall` builds a new `Firewall` with `rulesVersion = oldRulesVersion + 1`, per `interface.go:413`.
4. Continue sending packets for the same flow on the same routine before its local cache ticker fires (`cacheTick` unchanged): `inConns` returns `true` immediately from the local-cache hit at `firewall.go:507-509`, bypassing the `c.rulesVersion != f.rulesVersion` check at `firewall.go:527` that would otherwise re-run `table.match` and drop the flow.
5. Traffic for the revoked group continues to be forwarded until the local cache's next tick, demonstrating a temporary firewall bypass window not present when `routine_cache_timeout` is disabled/zero (confirmed by contrast against `TestFirewall_DropConntrackReload` in `firewall_test.go:667-729`, which only exercises the `nil`-localCache path and does correctly re-validate against `rulesVersion`).

// Get checks if the cache ticker has moved to the next version before returning
// the map. If it has moved, we reset the map.
func (c *ConntrackCacheTicker) Get() ConntrackCache {
	if c == nil {
		return nil
	}
	if tick := c.cacheTick.Load(); tick != c.cacheV {
		c.cacheV = tick
		if ll := len(c.cache); ll > 0 {
			if c.l.Enabled(context.Background(), slog.LevelDebug) {
				c.l.Debug("resetting conntrack cache", "len", ll)
			}
			c.cache = make(ConntrackCache, ll)
		}
	}

	return c.cache
}

func (f *Interface) reloadFirewall(c *config.C) {
	cs := f.pki.getCertState()
	curCert := cs.getCertificate(cert.Version2)
	if curCert == nil {
		curCert = cs.getCertificate(cert.Version1)
	}

	// The firewall builds its routableNetworks set from the certificate's UnsafeNetworks at construction.
	// Check to see if that set has changed, and if so, rebuild the firewall.
	certUnsafeChanged := curCert != nil && !slices.Equal(curCert.UnsafeNetworks(), f.firewall.unsafeNetworks)

	if !c.HasChanged("firewall") && !certUnsafeChanged {
		f.l.Debug("No firewall config change detected")
		return
	}

	fw, err := NewFirewallFromConfig(f.l, cs, c)
	if err != nil {
		f.l.Error("Error while creating firewall during reload", "error", err)
		return
	}

	oldFw := f.firewall
	conntrack := oldFw.Conntrack
	conntrack.Lock()
	defer conntrack.Unlock()

	fw.rulesVersion = oldFw.rulesVersion + 1
	// If rulesVersion is back to zero, we have wrapped all the way around. Be
	// safe and just reset conntrack in this case.
	if fw.rulesVersion == 0 {
		f.l.Warn("firewall rulesVersion has overflowed, resetting conntrack",
			"firewallHashes", fw.GetRuleHashes(),
			"oldFirewallHashes", oldFw.GetRuleHashes(),
			"rulesVersion", fw.rulesVersion,
		)
	} else {
		fw.Conntrack = conntrack
	}
