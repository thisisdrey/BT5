Audit Report

## Title
Child-bounty curator can self-award to the bounty's own keyless account, permanently stranding funds - (File: `substrate/frame/child-bounties/src/lib.rs`)

## Summary
`award_child_bounty` accepts a signer-supplied `beneficiary: AccountIdLookupOf<T>` with no validation against the child-bounty's own derived keyless account, `Self::child_bounty_account_id(parent_bounty_id, child_bounty_id)`. `claim_child_bounty` then unconditionally transfers the computed `payout` to that `beneficiary` and deletes the `ChildBounties` storage entry, so a self-referential beneficiary causes a self-transfer no-op that leaves the payout balance permanently orphaned with no code path to reclaim it.

## Finding Description
`award_child_bounty` only checks that the caller is the current child-bounty curator or the parent curator, and that the child bounty is `Active`, before recording the caller-chosen `beneficiary` into `ChildBountyStatus::PendingPayout`: [1](#0-0) 

`claim_child_bounty` computes `payout = balance.saturating_sub(curator_fee)` from the actual on-chain balance of `child_bounty_account_id(parent_bounty_id, child_bounty_id)`, pays the curator fee, then transfers `payout` to `beneficiary`, and unconditionally clears the storage entry via `*maybe_child_bounty = None`: [2](#0-1) 

Because `beneficiary` is never checked against `child_bounty_account_id(parent_bounty_id, child_bounty_id)` (or the parent bounty/treasury account), a curator can set `beneficiary` to that deterministic, publicly-derivable address. `T::Currency::transfer` from an account to itself is a no-op that returns `Ok`, so `claim_child_bounty` succeeds, the `Claimed` event fires, `ParentChildBounties` count decrements, `ChildBountyDescriptionsV1` is removed, and the `ChildBounties` entry is deleted — all bookkeeping that referenced the account's live balance is gone, but the `payout` amount remains sitting in `child_bounty_account_id`.

Unlike `pallet-bounties`, which added a permissionless `reclaim_bounty_funds` extrinsic (PR #11045) specifically to sweep funds stranded in a closed bounty's account back to the treasury: [3](#0-2) 

`pallet-child-bounties` has no equivalent call — confirmed by the absence of any `reclaim`-style extrinsic in `substrate/frame/child-bounties/src/lib.rs`, meaning once the `ChildBounties` entry is removed, no extrinsic in the pallet references or can withdraw from `child_bounty_account_id(parent_bounty_id, child_bounty_id)` again.

## Impact Explanation
This is a permanent lock of treasury-derived bounty funds (originating from the parent bounty, ultimately from the treasury), matching the "permanent user-fund or bridge-state lock" impact category. The stranded amount equals the child bounty's `value` minus `fee` and scales with however much value governance/the parent curator allocated to the child bounty.

## Likelihood Explanation
Exploiting this requires only that an account holding the child-bounty curator role (assigned via `propose_curator`/`accept_curator`, not necessarily a highly trusted or governance-controlled account) call `award_child_bounty` with `beneficiary` set to the deterministic, publicly computable `child_bounty_account_id(parent_bounty_id, child_bounty_id)`. No special privilege beyond holding curator status for that specific child bounty is needed, and any signed account can subsequently call `claim_child_bounty` to trigger the fund-stranding self-transfer.

## Recommendation
- **Short term:** In `award_child_bounty`, reject `beneficiary` values equal to `Self::child_bounty_account_id(parent_bounty_id, child_bounty_id)`, the parent bounty account, or the treasury/pallet account.
- **Long term:** Add a permissionless reclaim/sweep extrinsic to `pallet-child-bounties`, mirroring `pallet-bounties::reclaim_bounty_funds`, to recover balances stranded in closed child-bounty accounts.

## Proof of Concept
1. Governance creates and funds a parent bounty; a curator is accepted for it.
2. Parent curator calls `add_child_bounty` with some `value`; a curator is proposed and calls `accept_curator` for the child bounty, depositing `curator_deposit`. The derived account `child_bounty_account_id(parent_id, child_id)` now holds the child bounty's value.
3. The child-bounty curator computes `beneficiary = child_bounty_account_id(parent_id, child_id)` and calls `award_child_bounty(origin, parent_id, child_id, beneficiary)`, which succeeds since no check rejects a self-referential beneficiary.
4. After the payout delay, any signed account calls `claim_child_bounty(origin, parent_id, child_id)`.
5. `claim_child_bounty` pays the curator fee, transfers `payout` from `child_bounty_account` to itself (no-op), emits `Claimed`, and removes the `ChildBounties` entry — the `payout` balance remains in `child_bounty_account` with no remaining storage record or extrinsic path to retrieve it.

		pub fn award_child_bounty(
			origin: OriginFor<T>,
			#[pallet::compact] parent_bounty_id: BountyIndex,
			#[pallet::compact] child_bounty_id: BountyIndex,
			beneficiary: AccountIdLookupOf<T>,
		) -> DispatchResult {
			let signer = ensure_signed(origin)?;
			let beneficiary = T::Lookup::lookup(beneficiary)?;

			// Ensure parent bounty exists, and is active.
			let (parent_curator, _) = Self::ensure_bounty_active(parent_bounty_id)?;

			ChildBounties::<T>::try_mutate_exists(
				parent_bounty_id,
				child_bounty_id,
				|maybe_child_bounty| -> DispatchResult {
					let child_bounty =
						maybe_child_bounty.as_mut().ok_or(BountiesError::<T>::InvalidIndex)?;

					// Ensure child-bounty is in active state.
					if let ChildBountyStatus::Active { ref curator } = child_bounty.status {
						ensure!(
							signer == *curator || signer == parent_curator,
							BountiesError::<T>::RequireCurator,
						);
						// Move the child-bounty state to pending payout.
						child_bounty.status = ChildBountyStatus::PendingPayout {
							curator: signer,
							beneficiary: beneficiary.clone(),
							unlock_at: Self::treasury_block_number() +
								T::BountyDepositPayoutDelay::get(),
						};
						Ok(())
					} else {
						Err(BountiesError::<T>::UnexpectedStatus.into())
					}
				},
			)?;

		pub fn reclaim_bounty_funds(
			origin: OriginFor<T>,
			#[pallet::compact] bounty_id: BountyIndex,
		) -> DispatchResultWithPostInfo {
			ensure_signed(origin)?;

			// A live bounty still manages its account, so leave it untouched.
			ensure!(!Bounties::<T, I>::contains_key(bounty_id), Error::<T, I>::BountyStillActive);

			debug_assert!(
				T::ChildBountyManager::child_bounties_count(bounty_id) == 0,
				"child bounties should not exist for a closed bounty"
			);

			let bounty_account = Self::bounty_account_id(bounty_id);
			let treasury_account = Self::account_id();

			let transferred = T::TransferAllAssets::force_transfer_all_assets(
				&bounty_account,
				&treasury_account,
			)?;

			// Free only if something moved, otherwise paid to prevent griefing.
			if !transferred {
				return Ok(Pays::Yes.into());
			}

			Self::deposit_event(Event::<T, I>::BountyFundsReclaimed { bounty_id });

			Ok(Pays::No.into())
		}
