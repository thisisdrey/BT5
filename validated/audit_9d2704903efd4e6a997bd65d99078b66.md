The ALPINE-CVE-2024-56326 bug class is specific to Jinja2's `SandboxedEnvironment`, which is explicitly designed to allow execution of **untrusted templates** while restricting dangerous operations like `str.format`. The flaw was that a reference to a sandboxed-and-blocked method (`str.format`) could be smuggled through a custom filter, bypassing the sandbox's call-interception logic.

Go's standard library `text/template` and `html/template` packages have a fundamentally different security model: they explicitly assume **template authors are trusted** and only the data passed to `Execute` is untrusted. There is no "sandboxed environment" primitive in these packages that restricts which methods/functions a template can invoke — the documentation states this directly: [1](#0-0) [2](#0-1) 

`html/template`'s only protection is contextual **autoescaping of data values** embedded into HTML/JS/CSS/URL contexts [3](#0-2)  — this addresses injection of untrusted *data* into HTML output, not sandboxing of untrusted *template code* or restricting arbitrary method calls the way Jinja's sandbox does. Since Go's template engines never claim to safely execute untrusted template source (the attacker-controlled-template premise required by this CVE), there is no matching "sandbox escape via indirect method reference" primitive to analyze, and applying this bug class to Go's template packages would be a mismatched, hypothetical scenario rather than a proven root cause.

# Contexts

This package understands HTML, CSS, JavaScript, and URIs. It adds sanitizing
functions to each simple action pipeline, so given the excerpt

	<a href="/search?q={{.}}">{{.}}</a>

At parse time each {{.}} is overwritten to add escaping functions as necessary.
In this case it becomes

	<a href="/search?q={{. | urlescaper | attrescaper}}">{{. | htmlescaper}}</a>

where urlescaper, attrescaper, and htmlescaper are aliases for internal escaping
functions.
