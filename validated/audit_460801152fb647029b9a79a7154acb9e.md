### Title
Windows command-line argument escaping fails to neutralize embedded newlines, enabling cmd.exe command-line truncation/injection - ([File: src/syscall/exec_windows.go])

### Summary
`syscall.EscapeArg` / `appendEscapeArg` in `src/syscall/exec_windows.go` only treats `"`, `\`, space, and tab as characters that require quoting/escaping. A `\n` (or `\r`) embedded in an argument is left completely untouched and unquoted in the command line built for `CreateProcess`. This mirrors the `shescape` CVE-2022-31179 root cause: escaping logic for Windows/cmd.exe command lines fails to account for line-feed characters, which cmd.exe treats as a line terminator, letting an attacker truncate or hijack everything that follows in the command line.

### Finding Description
`os/exec.Cmd.Start` on Windows ultimately calls `syscall.StartProcess` (`src/syscall/exec_windows.go:307`), which builds the single flat command-line string passed to `CreateProcess`/`CreateProcessAsUser` via `makeCmdLine` (`src/syscall/exec_windows.go:104-115`), which in turn calls `appendEscapeArg` (`src/syscall/exec_windows.go:46-102`) for each argument. That function's decision to quote an argument is driven solely by the presence of `"`, `\`, `' '`, `'\t'` (`src/syscall/exec_windows.go:55-61`); a value containing only a `\n` character passes through unmodified and unquoted (`src/syscall/exec_windows.go:64-66`).

Because Windows `CreateProcess` receives the command line as a single opaque string, it is the invoked process — e.g. `cmd.exe` when a Go program does `exec.Command("cmd", "/C", untrustedArg)` — that re-parses the whole line. `cmd.exe` treats an embedded newline as ending the effective command, so any trailing developer-supplied arguments (flags, fixed sub-commands, restrictions appended after the untrusted value) are silently dropped, exactly the "attacker can omit all arguments following their input" primitive described in the shescape advisory. ### Impact Explanation
Any Go program on Windows that forwards attacker-controlled strings as an argument to `cmd.exe` (a common integration pattern for shelling out to batch commands, e.g. `exec.Command("cmd", "/C", "somecmd", userInput)`) can have trailing, developer-intended arguments truncated or effectively overridden by embedding a `\n` in `userInput`, because `EscapeArg`/`appendEscapeArg` never quotes or strips it. This can suppress safety flags or fixed suffix arguments meant to constrain the invoked command, a command-line-truncation/argument-injection primitive with security consequences comparable to the original advisory. This is a documented, long-standing behavior of Go's own escaping helper, not a newly introduced regression, so it would fall under Go's PUBLIC track for discussion of hardening `EscapeArg`, but it is not confirmed as an accepted Go Security team CVE (Go's `os/exec` package explicitly disclaims automatic shell invocation, and `EscapeArg` is documented purely as MSDN-style escaping, not as a security boundary against shell metacharacters).

### Likelihood Explanation
Reachable only when a Go application chooses to explicitly invoke `cmd.exe` (or another line-oriented interpreter) with untrusted data as one of the arguments — a realistic but not universal pattern (batch/script wrappers, CI tooling, etc. on Windows). The attacker only needs to control one argument value and does not need any special privileges beyond normal input to that workflow.

### Recommendation
Extend `appendEscapeArg` in `src/syscall/exec_windows.go` to also flag `\n`/`\r` (and other C0 control characters) as requiring quoting, or reject/strip them outright, and document explicitly in `os/exec` that `EscapeArg`/`CmdLine` do not provide shell-metacharacter safety for line-oriented consumers like `cmd.exe`, advising callers to strip newlines from any argument passed to a `cmd.exe`-invoking `exec.Command` call.

### Proof of Concept
```go
package syscall_test

import (
	"strings"
	"syscall"
	"testing"
)

func TestEscapeArgDoesNotNeutralizeNewline(t *testing.T) {
	payload := "safe-arg\nrestricted-suffix-args-are-now-dropped"
	got := syscall.EscapeArg(payload)

	// EscapeArg returns the string unchanged/unquoted because '\n'
	// is not among the characters that trigger quoting ('"', '\\', ' ', '\t').
	if got != payload {
		t.Fatalf("expected EscapeArg to leave newline-only payload unchanged, got %q", got)
	}
	if strings.Contains(got, `"`) {
		t.Fatalf("EscapeArg unexpectedly quoted the payload; newline handling may have been fixed")
	}
	// This demonstrates the embedded newline reaches CreateProcess's
	// command-line string unescaped, where cmd.exe will treat it as a
	// line terminator, truncating anything appended after it.
}
```

func EscapeArg(s string) string {
	if len(s) == 0 {
		return `""`
	}
	for i := 0; i < len(s); i++ {
		switch s[i] {
		case '"', '\\', ' ', '\t':
			// Some escaping required.
			b := make([]byte, 0, len(s)+2)
			b = appendEscapeArg(b, s)
			return string(b)
		}
	}
	return s
}

// makeCmdLine builds a command line out of args by escaping "special"
// characters and joining the arguments with spaces.
func makeCmdLine(args []string) string {
	var b []byte
	for _, v := range args {
		if len(b) > 0 {
			b = append(b, ' ')
		}
		b = appendEscapeArg(b, v)
	}
	return string(b)
}
