Audit Report

## Title
`add_external_asset` never initializes `AssetCeilingWeight`, permanently bricking minting for every newly approved external asset - (File: `substrate/frame/psm/src/lib.rs`)

## Summary
`AssetCeilingWeight` is a `ValueQuery` double map that defaults to `Permill::zero()` for any `(internal_asset, external_asset)` pair that has never been explicitly set, and a zero weight is defined by the pallet to mean minting is disabled for that external. `add_external_asset` inserts into `ExternalAssets` and bumps `PsmInfo::external_count`, but never writes an entry into `AssetCeilingWeight`, so every newly approved external asset has an implicit zero ceiling until an admin separately calls `set_asset_ceiling_weight`.

## Finding Description
`AssetCeilingWeight` is declared with `ValueQuery` and no custom default, so unset entries resolve to `Permill::zero()`: [1](#0-0) .

`max_asset_debt` reads this weight and passes it into `normalised_ceiling`, which explicitly returns `BalanceOf::<T>::zero()` when `weight == 0`: [2](#0-1) .

`add_external_asset` is the sole extrinsic used to approve a new external asset on a PSM instance; it validates decimals, inserts `ExternalAssetInfo` into `ExternalAssets`, and increments `info.external_count`, but at no point touches `AssetCeilingWeight` for the new pair: [3](#0-2) .

The only extrinsic that ever writes a non-zero value into `AssetCeilingWeight` is the separate, independent `set_asset_ceiling_weight` call: [4](#0-3) .

As a result, immediately after `add_external_asset` succeeds and before anyone calls `set_asset_ceiling_weight`, `max_asset_debt` for that pair evaluates to zero, and any `mint` call for that external asset will fail the `new_debt <= max_debt` check against `Error::ExceedsMaxPsmDebt`, regardless of how large `PsmInfo::max_debt` is. There is no fallback path in `max_asset_debt`, `normalised_ceiling`, or `add_external_asset`/`create_psm` that gives a freshly approved external any usable ceiling by default.

## Impact Explanation
This is a runtime bug that compromises the pallet's intended behavior: the PSM's core function — minting the internal asset against an approved external — is completely and silently disabled for every newly approved external asset until an operator performs an extra, easy-to-forget administrative step. The failure surfaces as `Error::ExceedsMaxPsmDebt`, which misleadingly suggests the debt ceiling has been reached rather than that ceiling-weight setup was never completed, making the root cause hard to diagnose operationally. This matches the "runtime bugs that compromise intended behavior" category of the accepted impact gate.

## Likelihood Explanation
High. No adversarial input is required — this triggers deterministically on the very first ordinary use of the documented `create_psm` → `add_external_asset` → `mint` workflow. Any runtime integrator or governance operator who is not specifically aware of the undocumented requirement to also call `set_asset_ceiling_weight` will hit this on every deployment, for every newly added external asset, with 100% reproducibility.

## Recommendation
Have `add_external_asset` initialize `AssetCeilingWeight` to a sane non-zero default (e.g., an equal share among all currently approved externals, recomputed at insertion time), or change `max_asset_debt`/`normalised_ceiling` so that an external with no explicit weight entry falls back to the full `PsmInfo::max_debt` rather than zero — analogous to how fee lookups use a `DefaultFee` `Get` implementation instead of relying on `ValueQuery`'s implicit zero. At minimum, add an integration test that calls `mint` immediately after `add_external_asset` without `set_asset_ceiling_weight`, which would catch this regression.

## Proof of Concept
1. `Root`/asset owner calls `create_psm(internal_asset, full_admin, emergency_admin, fee_destination, max_debt = 1_000_000, min_swap_amount = 1)`.
2. `full_admin` calls `add_external_asset(internal_asset, USDC)` — succeeds; `ExternalAssets` now contains `(internal_asset, USDC)`, but `AssetCeilingWeight::get(internal_asset, USDC)` is still `Permill::zero()` (never written), as shown at `substrate/frame/psm/src/lib.rs:1343-1354`.
3. A user calls `mint(internal_asset, USDC, external_amount = 1000, max_fee)`.
4. Inside `mint`, `Self::max_asset_debt(...)` calls `AssetCeilingWeight::get` → `0` → `normalised_ceiling` returns `0` (`substrate/frame/psm/src/lib.rs:1546-1548`) → `new_debt (>0) <= max_debt (0)` is `false` → the call reverts with `Error::ExceedsMaxPsmDebt`, despite `PsmInfo::max_debt` being `1_000_000`.
5. Minting for this external remains impossible for every user until `full_admin` separately calls `set_asset_ceiling_weight(internal_asset, USDC, weight)`.

		#[pallet::call_index(8)]
		#[pallet::weight(T::WeightInfo::set_asset_ceiling_weight())]
		pub fn set_asset_ceiling_weight(
			origin: OriginFor<T>,
			internal_asset: T::AssetId,
			external_asset: T::AssetId,
			weight: Permill,
		) -> DispatchResult {
			Self::ensure_psm_admin(origin, &internal_asset, |l| l.can_set_asset_ceiling())?;
			ensure!(
				ExternalAssets::<T>::contains_key(&internal_asset, &external_asset),
				Error::<T>::AssetNotApproved
			);
			// Reweighting renormalises every external's ceiling; an external left below its new
			// ceiling simply can't be minted until redemptions bring its debt back down.
			let old_value = AssetCeilingWeight::<T>::get(&internal_asset, &external_asset);
			AssetCeilingWeight::<T>::insert(&internal_asset, &external_asset, weight);
			Self::deposit_event(Event::AssetCeilingWeightUpdated {
				internal_asset,
				external_asset,
				old_value,
				new_value: weight,
			});
			Ok(())
		}

		#[pallet::call_index(9)]
		#[pallet::weight(T::WeightInfo::add_external_asset())]
		pub fn add_external_asset(
			origin: OriginFor<T>,
			internal_asset: T::AssetId,
			external_asset: T::AssetId,
		) -> DispatchResult {
			Self::ensure_psm_admin(origin, &internal_asset, |l| l.can_manage_assets())?;
			let mut info = Psm::<T>::get(&internal_asset).ok_or(Error::<T>::PsmNotFound)?;
			ensure!(
				!ExternalAssets::<T>::contains_key(&internal_asset, &external_asset),
				Error::<T>::AssetAlreadyApproved
			);
			ensure!(info.external_count < T::MaxExternals::get(), Error::<T>::TooManyAssets);
			ensure!(
				T::Fungibles::asset_exists(external_asset.clone()),
				Error::<T>::AssetDoesNotExist
			);

			let asset_decimals = T::Fungibles::decimals(external_asset.clone());
			ensure!(
				T::Fungibles::decimals(internal_asset.clone()) == info.internal_decimals,
				Error::<T>::DecimalsMismatch
			);
			ensure!(
				(asset_decimals.abs_diff(info.internal_decimals) as u32) <= MAX_DECIMALS_DIFF,
				Error::<T>::DecimalsRangeExceeded
			);

			ExternalAssets::<T>::insert(
				&internal_asset,
				&external_asset,
				ExternalAssetInfo {
					status: CircuitBreakerLevel::AllEnabled,
					decimals: asset_decimals,
				},
			);
			info.external_count = info.external_count.saturating_add(1);
			Psm::<T>::insert(&internal_asset, info);

			Self::deposit_event(Event::ExternalAssetAdded { internal_asset, external_asset });
			Ok(())
		}

		pub(crate) fn max_asset_debt(
			internal_asset: &T::AssetId,
			external_asset: &T::AssetId,
			info: &PsmInfo<T>,
		) -> BalanceOf<T> {
			let asset_weight = AssetCeilingWeight::<T>::get(internal_asset, external_asset);
			let total_weight = Self::total_ceiling_weight(internal_asset);
			Self::normalised_ceiling(asset_weight, total_weight, info.max_debt)
		}

		/// Sum of the configured ceiling weights across a PSM's approved externals.
		fn total_ceiling_weight(internal_asset: &T::AssetId) -> u32 {
			AssetCeilingWeight::<T>::iter_prefix(internal_asset)
				.map(|(_, w)| w.deconstruct())
				.fold(0u32, |acc, x| acc.saturating_add(x))
		}

		/// A single external's normalised debt ceiling: its share of the total weight applied
		/// to `max_debt`. Zero if the external (or the PSM as a whole) carries no weight.
		fn normalised_ceiling(
			asset_weight: Permill,
			total_weight: u32,
			max_debt: BalanceOf<T>,
		) -> BalanceOf<T> {
			let weight = asset_weight.deconstruct();
			if weight == 0 || total_weight == 0 {
				return BalanceOf::<T>::zero();
			}
			Perbill::from_rational(weight, total_weight).mul_floor(max_debt)
		}
