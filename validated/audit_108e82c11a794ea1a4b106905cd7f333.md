#No Vulnerability found for this question.

The premise misattributes the file scope (`net-utils/src/lib.rs`) to `entry::entry::hash_transactions`/`next_hash_with_signatures`, which actually live in `entry/src/entry.rs`, and the described attack chain doesn't hold up against the actual code:

1. **Signature-emptiness is already rejected at ingress.** `verify_packet` in `perf/src/sigverify.rs` explicitly checks `signatures.is_empty()` and marks the packet unverified/discarded before any transaction reaches banking or PoH: [1](#0-0) . This is invoked from `ed25519_verify_serial`, which discards any packet failing `verify_packet` [2](#0-1) , and this is called from `SigVerifyStage::run_transaction_task` after deduplication, prior to sending to banking [3](#0-2) . No race between dedup and sigverify is evidenced in the code — dedup runs first and only discards duplicates, it does not bypass or skip the subsequent `ed25519_verify_serial` call for the surviving packets.

2. **`hash_transactions`/`hash_signatures` are intentionally signature-only hashes for PoH mixing, not a substitute for verification.** As documented in the comment "a hash of a slice of transactions only needs to hash the signatures" [4](#0-3) , and separately, signature verification against the message is handled by `validate_and_hash_transactions`/`UnverifiedSignatures::verify()`, exercised by `test_validate_and_hash_transactions_and_signatures`, which shows that tampering with a signature (even zeroing it) is caught by `unverified_signatures.verify()` returning `TransactionError::SignatureFailure` [5](#0-4) .

3. **A zero-signature `VersionedTransaction` can never be constructed by an unprivileged remote packet reaching banking**, because `verify_packet` requires `signatures` non-empty before even attempting the ed25519 checks; a packet with zero signatures is discarded unconditionally, not merely "at risk of a race" [6](#0-5) .

4. **`PohRecorder::record`** takes the `transactions` vector as already-scheduled/verified by banking stage and only fails on bank-id/height mismatches; it does not re-verify signatures, but that's by design since verification happened upstream at sigverify and at bank-processing time [7](#0-6) .

No code path or race condition is identified in the repository that allows a zero-signature or hash-colliding-signature transaction to survive `verify_packet`'s explicit `signatures.is_empty()` check and reach `PohRecorder::record`. The question's claimed "sigverify/dedup race" is unsubstantiated speculation without a concrete reachable code path in this codebase.

fn verify_packet(packet: &mut PacketRefMut, reject_non_vote: bool, enable_tx_v1: bool) -> bool {
    // If this packet was already marked as discard, drop it
    if packet.meta().discard() {
        return false;
    }

    let Some(data) = packet.data(..) else {
        return false;
    };

    let (is_simple_vote_tx, verified) = {
        let Ok(view) = SanitizedTransactionView::try_new_sanitized(data, &sanitize_config()) else {
            return false;
        };

        if !enable_tx_v1 && matches!(view.version(), TransactionVersion::V1) {
            return false;
        }

        let is_simple_vote_tx = is_simple_vote_transaction_view(&view);
        if reject_non_vote && !is_simple_vote_tx {
            (is_simple_vote_tx, false)
        } else {
            let signatures = view.signatures();
            if signatures.is_empty() {
                (is_simple_vote_tx, false)
            } else {
                let message = view.message_data();
                let static_account_keys = view.static_account_keys();
                let verified = signatures
                    .iter()
                    .zip(static_account_keys.iter())
                    .all(|(signature, pubkey)| signature.verify(pubkey.as_ref(), message));
                (is_simple_vote_tx, verified)
            }
        }
    };

    if is_simple_vote_tx {
        packet.meta_mut().flags |= PacketFlags::SIMPLE_VOTE_TX;
    }

    verified
}

pub fn ed25519_verify_serial(batch: &mut PacketBatch, reject_non_vote: bool, enable_tx_v1: bool) {
    for mut packet in batch.iter_mut() {
        if !packet.meta().discard() && !verify_packet(&mut packet, reject_non_vote, enable_tx_v1) {
            packet.meta_mut().set_discard(true);
