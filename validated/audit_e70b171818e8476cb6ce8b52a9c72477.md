### Title
Unauthenticated `/shutdown` HTTP endpoint on `SignerEventReceiver` allows any remote TCP client to permanently halt the signer's event loop - (File: `libsigner/src/events.rs`)

### Summary
`SignerEventReceiver::next_event` handles the `/shutdown` URL path by unconditionally setting `stop_signal` to `true` and returning `EventError::Terminated`, without verifying that the request came from the local node process (the only intended caller, via `SignerStopSignaler::send`). Any TCP client that can reach the bound listener address can issue a single `POST /shutdown` request and permanently stop the signer's `main_loop`, since `EventReceiver::main_loop` unconditionally `break`s on `EventError::Terminated`.

### Finding Description
The intended invariant is: "the party allowed to halt event processing == the local node process," enforced only by convention (`SignerStopSignaler::send` at `libsigner/src/events.rs:376-396` is documented as "the caller" that triggers shutdown, and it connects back to `self.local_addr` to wake the HTTP server). However, the actual HTTP handler performs no verification of the request's origin, secret, or any authentication token: [1](#0-0) 

```rust
} else if request.url() == "/shutdown" {
    event_receiver.stop_signal.store(true, Ordering::SeqCst);
    Err(EventError::Terminated)
}
```

Any TCP peer that connects to the bound `HttpServer` (bound in `SignerEventReceiver::bind` at `libsigner/src/events.rs:404-408`) and sends a well-formed `POST /shutdown` HTTP request reaches this exact branch — there is no signature check, no shared secret, no source-IP allowlist, and no `Content-Length`/body validation gating this path (the body content is irrelevant; only the URL and method matter). Once `stop_signal` is set to `true`, `is_stopped()` (`libsigner/src/events.rs:462-464`) returns `true` for the lifetime of the process, and `EventReceiver::main_loop` (`libsigner/src/events.rs:284-312`) treats `Err(EventError::Terminated)` as a terminal condition and `break`s out of the loop permanently — there is no way to reset `stop_signal` back to `false`.

### Impact Explanation
A single unauthenticated HTTP POST permanently terminates the signer's event-receiving main loop, meaning the signer process stops receiving `stackerdb_chunks`, `proposal_response`, `new_burn_block`, and `new_block` events from the node. This effectively takes the signer offline for block validation/signing participation without crashing the process outright, but the practical effect is a full denial-of-service against a critical component in the signer/miner pipeline. This is repeatable against any signer whose event-listener endpoint is reachable, matching the "Critical - remote crash/unauthenticated DoS from few messages" category.

### Likelihood Explanation
The only precondition is network reachability to the address/port on which the signer's `SignerEventReceiver` is bound (configured via the signer's `event_server`/endpoint configuration). No secret, key, StackerDB slot ownership, or privileged role is required — this is a plain HTTP POST to a URL path. The attack costs a single TCP connection and a handful of bytes, and is trivially repeatable (idempotent — the loop cannot be un-stopped without a process restart).

### Recommendation
Add an authentication mechanism to the `/shutdown` path (and ideally all paths) on `SignerEventReceiver`'s HTTP server — e.g., restrict binding to loopback only, or require a shared secret/token known only to the local node process (similar to how other node-internal control channels are protected), and verify it before honoring the stop request.

### Proof of Concept
```rust
// libsigner/src/events.rs (or a new integration test)
use std::net::{TcpStream, SocketAddr};
use std::io::Write;
use std::thread;

#[test]
fn test_unauthenticated_shutdown_halts_event_loop() {
    let mut receiver: SignerEventReceiver<SomeMessageType> = SignerEventReceiver::new(false);
    let addr: SocketAddr = "127.0.0.1:0".parse().unwrap();
    let bound = receiver.bind(addr).unwrap();

    // Simulate an unrelated remote TCP client (not SignerStopSignaler)
    let mut stream = TcpStream::connect(bound).unwrap();
    let req = "POST /shutdown HTTP/1.1\r\nHost: x\r\nConnection: close\r\nContent-Length: 0\r\n\r\n";
    stream.write_all(req.as_bytes()).unwrap();

    // The receiver should now be permanently terminated
    let result = receiver.next_event();
    assert!(matches!(result, Err(EventError::Terminated)));
    assert!(receiver.is_stopped());
}
```
This demonstrates that an arbitrary TCP client — with no knowledge of any secret and no relationship to `SignerStopSignaler` — can permanently halt the event receiver's `main_loop` via a single crafted `/shutdown` POST, confirming the unauthenticated remote DoS.
