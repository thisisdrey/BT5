### Title
Borrow limit equals liquidation threshold — positions can be opened exactly at the liquidation boundary, enabling easy bad-debt creation - (File: contracts/Pool.sol)

### Summary
The JOJO report describes a system where the solvency check for opening a position and the solvency check for liquidation are the same inequality, so a trader can open a position sitting exactly on the liquidation boundary. Metronome has the identical structure: `DebtToken.issue` enforces `debt <= depositValue * collateralFactor` via `Pool.debtPositionOf`, and `Pool.liquidate` reuses the same `debtPositionOf`/`_issuableLimitInUsd` check to decide whether a position is liquidatable. There is no separate (stricter) issuance/initial-margin factor distinct from the liquidation factor — Metronome is actually a degenerate case where the "buffer" is only `1 - collateralFactor`, and the liquidation bonus itself pushes undercollateralization.

### Finding Description
Health is defined solely by `debtPositionOf`: a position is healthy iff `_debtInUsd <= _issuableLimitInUsd`, where `_issuableLimitInUsd = Σ depositValueUSD * collateralFactor` [1](#0-0) [2](#0-1) .

`DebtToken.issue` bounds issuance by exactly this same limit — `amount_ > quoteUsdToToken(_issuableInUsd)` reverts, meaning a user may mint up to `debtInUsd == issuableLimitInUsd`, i.e. `_issuableInUsd == 0` [3](#0-2) . The test suite confirms this is reachable state: `_mintableInUsdAfter == 0` and `_isHealthy == true` simultaneously [4](#0-3) .

`Pool.liquidate` gates liquidation on the identical predicate — `debtPositionOf` returns `_isHealthy` and `liquidate` reverts `PositionIsHealthy` only under that same boundary [5](#0-4) . No contract defines a `liquidationThreshold`, health-factor margin, or distinct borrow-vs-liquidation factor (grep for `healthFactor|liquidationThreshold` returns nothing). A position minted at the boundary flips to liquidatable on an arbitrarily small adverse price move.

Once unhealthy, `quoteLiquidateOut` seizes collateral worth `repaidDebt * (1 + liquidatorIncentive) + protocolFee` [6](#0-5) . When collateral value has fallen below debt value (`collateral:debt < 1`), the invariant `totalSeized <= balanceOf` forces `AmountIsTooHigh` reverts for full repayment and the liquidation can only cover a fraction of the debt [7](#0-6) ; the test suite confirms the account is left with ~0 collateral and `msEthDebtToken.balanceOf(alice) > 0` — residual debt permanently uncovered by collateral [8](#0-7) . There is no insurance fund or bad-debt socialization in the Pool; the residual `DebtToken` balance is unbacked synthetic supply held by `account_` and effectively by all synth holders.

### Impact Explanation
An attacker can deliberately open a maximally-leveraged position (`issue` to `_issuableInUsd == 0`), wait for or induce (via a same-block oracle-adjacent price move, or simply normal volatility) a small collateral price drop, and have the position go instantly underwater. After a further drop such that `depositValue < debtValue`, liquidation cannot restore solvency: the liquidator drains all collateral at a discount, and the remaining debt is unbacked — direct protocol insolvency (unbacked synthetic supply). Combined with `maxLiquidable` capping repayment per call [9](#0-8)  and `debtFloorInUsd` reverting repayments that leave dust debt [10](#0-9) , clearing the bad debt is additionally constrained. Because issuance sits exactly at the liquidation boundary, no safety margin exists — this is trivially reachable by any EOA with collateral, matching the "too easy to incur bad debt" class.

### Likelihood Explanation
High reachability: `DebtToken.issue` is a public, unprivileged entry point requiring only deposited collateral; `maxTotalSupply`, `debtFloorInUsd`, `whenNotShutdown`, and `nonReentrant` do not bound issuance below the liquidation boundary. The only mitigant is `collateralFactor < 1` giving a `(1/CF - 1)` price-drop distance to actual undercollateralization (e.g. ~20% at CF 0.83), but the position becomes *liquidatable* after an arbitrarily small move, and in fast markets a liquidator extracting `repaid * (1 + incentive + fee)` from a boundary position can itself push residual positions underwater. Exploitability depends on oracle price moves, which are outside attacker control except via normal market volatility or manipulation of an oracle source (allowed only same-transaction) — likelihood is moderate, bounded by how volatile the listed collaterals are.

### Recommendation
Introduce a distinct, stricter borrowing threshold: e.g. add `issuanceCollateralFactor < collateralFactor` (or a `minHealthFactor > 1` check) used by `DebtToken.issue`/`_issuableInUsd`, while keeping `liquidate`'s health definition unchanged. This restores the LTV/liquidation-threshold gap standard in lending protocols so positions cannot be opened on the liquidation boundary.

### Proof of Concept
Reproducible on the existing Hardhat suite (`test/Pool.test.ts` fixtures: MET collateral, `metCF` collateral factor, msETH/msDOGE debt tokens, mockable `masterOracle`):

```typescript
// alice deposits 6000 MET, issues max debt at boundary
await msdMET.connect(alice).deposit(parseEther('6000'), alice.address)
const {_issuableInUsd} = await pool.debtPositionOf(alice.address)
const maxIssuable = await masterOracle.quoteUsdToToken(msEth.address, _issuableInUsd)
await msEthDebtToken.connect(alice).issue(maxIssuable, alice.address)
// position sits exactly on liquidation boundary
expect((await pool.debtPositionOf(alice.address))._issuableInUsd).eq(0)

// arbitrarily small adverse move → liquidatable
await masterOracle.updatePrice(met.address, metPrice.mul(999).div(1000)) // -0.1%
expect((await pool.debtPositionOf(alice.address))._isHealthy).false

// deeper move → collateral < debt; full liquidation impossible
await masterOracle.updatePrice(met.address, toUSD('0.50'))
const maxRepay = await pool.quoteLiquidateMax(msEth.address, alice.address, msdMET.address)
await pool.connect(liquidator).liquidate(msEth.address, alice.address, maxRepay, msdMET.address)
// alice left with ~0 collateral and residual debt — unbacked bad debt remains on DebtToken
expect(await msEthDebtToken.balanceOf(alice.address)).gt(0)
expect(await msdMET.balanceOf(alice.address)).closeTo(0, 2000)
```

All steps use only public entry points (`DepositToken.deposit`, `DebtToken.issue`, `Pool.liquidate`) and an unprivileged account; the price updates use the test oracle the way deployed oracle updates would reflect real market moves.
