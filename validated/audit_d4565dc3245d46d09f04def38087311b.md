### Title
Stake-blind global connection admission gate lets unstaked churn starve staked TPU connections - (File: streamer/src/nonblocking/quic.rs)

### Summary
The global connection admission check performed by `ClientConnectionTracker::new` against `QosController::max_concurrent_connections()` happens before any peer-type classification, so it cannot distinguish staked from unstaked traffic. An unstaked attacker can combine persisted idle unstaked connections (up to `max_unstaked_connections`) with continuous handshake churn from many distinct IPs to consume the remaining 25% margin of the global counter, causing `refused_connections_too_many_open_connections` for legitimate staked peers before they ever reach the stake-aware pruning logic in `SwQos::try_add_connection`.

### Finding Description
In `run_server`, every accepted `Incoming` connection is gated purely by a global atomic counter, independent of stake: [1](#0-0) 
This call increments `stats.open_connections` and only fails if the global count is already at `qos.max_concurrent_connections()`: [2](#0-1) 
For `SwQos`, that limit is `(max_staked_connections + max_unstaked_connections) * 5 / 4`, i.e. a fixed 25% margin shared by both peer classes with no per-class reservation: [3](#0-2) 
Only after this stake-blind check passes does `setup_connection` classify the peer and call `qos.try_add_connection`, which is where staked-vs-unstaked table capacity and stake-based pruning (`prune_random`) are enforced: [4](#0-3) [5](#0-4) 

The unstaked branch bounds *persisted* connections at `max_unstaked_connections`, pruning to 90% capacity before insertion: [6](#0-5) 
so an attacker cannot indefinitely accumulate more than roughly `max_unstaked_connections` persisted unstaked entries in the table. However, the `ClientConnectionTracker` global counter is incremented at accept time, *before* the peer is classified and *before* `try_add_connection` runs — i.e., it also counts connections that are still mid-handshake or awaiting classification, not just those admitted into a table. Nothing reserves headroom in the 25% margin specifically for staked handshakes. By (a) filling and holding the unstaked table at capacity (~`max_unstaked_connections` idle connections, respecting per-IP caps of `max_connections_per_unstaked_peer` and the per-IP rate limiter) and (b) continuously initiating additional connection attempts from further distinct IPs that occupy the tracker slot during the handshake window (`QUIC_CONNECTION_HANDSHAKE_TIMEOUT`) before being classified/rejected, an attacker can push `stats.open_connections` up toward the shared cap. Since the check in `ClientConnectionTracker::new` is agnostic to stake, a legitimate staked peer's connection can be refused (`refused_connections_too_many_open_connections`) purely due to unstaked churn, without ever reaching the staked-preferential pruning logic (`prune_random`) that is supposed to protect staked peers from unstaked pressure.

The overall/per-IP connection rate limiters (`overall_connection_rate_limiter`, `ConnectionRateLimiter`) throttle the *rate* of new incoming connection attempts, but do not prevent an attacker with sufficiently many distinct IPs from maintaining a large number of connections concurrently in-flight/persisted, since each IP is independently bounded and the limiter windows are per-minute token buckets that refill.

### Impact Explanation
This is a QoS-evasion / denial-of-service against the TPU connection admission path: unstaked, unprivileged senders can deny staked senders the ability to open new TPU QUIC connections, which is exactly the invariant ("global connection capacity bounded regardless of packet volume and cannot be monopolized by unstaked churn") that the stake-based admission design is meant to guarantee. This falls under the QoS evasion / DoS bounty category for the TPU ingress path.

### Likelihood Explanation
Feasibility requires only unstaked network access and a large-but-plausible pool of distinct source IPs (to stay under the per-IP connection cap of `max_connections_per_unstaked_peer` = 8 and the per-IP rate limiter of 8/min while aggregating up to thousands of concurrent connections/handshakes). No stake, gossip participation, or validator control is needed — this matches the "unprivileged, unstaked client" threat model. The attack is repeatable and self-sustaining as long as the attacker maintains enough concurrent IPs/connections.

### Recommendation
Reserve headroom in the global `max_concurrent_connections()` bound explicitly for staked peers (e.g., track separate atomic counters for staked-in-progress vs. unstaked-in-progress connections, or perform peer/stake classification earlier — before incrementing the global counter — so unstaked connection attempts are checked against a strictly smaller quota than the shared staked+unstaked+margin pool). Alternatively, make the handshake-margin proportional and dedicated per class rather than a single shared pool consumable by either class.

### Proof of Concept
Integration test plan (in `streamer/src/nonblocking/swqos.rs` or `quic.rs` test modules), using `setup_quic_server` with `SwQosConfig { max_staked_connections: N, max_unstaked_connections: M, max_connections_per_unstaked_peer: K, .. }`:
1. Spin up the QUIC server with `SwQos`.
2. From `M` distinct fake-IP unstaked clients (or `M/K` IPs each opening `K` connections), open and hold idle connections (no stream writes) until the unstaked table is at capacity; assert `stats.open_connections` reaches `M`.
3. Concurrently, from additional distinct IPs, launch a stream of new unstaked connection attempts (each respecting per-IP rate limits) that complete the handshake but are intentionally slow/idle before classification, sized so that `open_connections` approaches `max_concurrent_connections()` (`(N+M)*5/4`).
4. From a staked client (assign stake via `staked_nodes`), attempt to connect.
5. Assert the staked connection is refused with `ConnectionError` and `stats.refused_connections_too_many_open_connections` increments, confirming `ClientConnectionTracker::new` rejected it before `SwQos::try_add_connection`/`prune_random` ever ran.
6. After idle/expired unstaked connections are pruned or torn down, assert a subsequent staked connection succeeds, confirming recovery.

Note: Full confirmation of exact numeric feasibility (how many concurrent mid-handshake attempts can realistically be sustained given `QUIC_CONNECTION_HANDSHAKE_TIMEOUT` and the overall token-bucket rate limiter capacity) requires runtime experimentation beyond static code reading; the constants (`QUIC_CONNECTION_HANDSHAKE_TIMEOUT`, overall rate limiter burst size) exist in `streamer/src/nonblocking/quic.rs` but their exact tuned values were not fully retrieved in this session, and should be checked in a Devin session for precise PoC parameters.

    /// Check the max_concurrent_connections limit and if it is within the limit
    /// create ClientConnectionTracker and increment open connection count. Otherwise returns Err
    fn new(stats: Arc<StreamerStats>, max_concurrent_connections: usize) -> Result<Self, ()> {
        let open_connections = stats.open_connections.fetch_add(1, Ordering::Relaxed);
        if open_connections >= max_concurrent_connections {
            stats.open_connections.fetch_sub(1, Ordering::Relaxed);
            debug!(
                "There are too many concurrent connections opened already: open: \
                 {open_connections}, max: {max_concurrent_connections}"
            );
            return Err(());
        }

        Ok(Self { stats })
    }
