## Finding: Spot-price fee-quoting in `pallet-asset-conversion-tx-payment` is manipulable within a single block

### Title
Unprotected spot-price AMM quote used for transaction fee payment enables self-manipulated fee underpayment - (File: `substrate/frame/transaction-payment/asset-conversion-tx-payment/src/payment.rs`)

### Summary
The external report's core broken invariant is: *a pricing calculation reads a pool's instantaneous reserves with no time-weighting, so any actor who can move funds into/out of the pool within the same atomic execution window can force a favorable price before the dependent logic consumes it.* The equivalent construct exists in `pallet-asset-conversion-tx-payment`'s `SwapAssetAdapter::withdraw_fee`, which converts a transaction's native fee into a user-chosen asset using `pallet-asset-conversion`'s instantaneous pool balances, with no TWAP or liquidity-floor protection.

### Finding Description
`SwapAssetAdapter::withdraw_fee` computes how much of a non-native `asset_id` a signed extrinsic must pay by calling: [1](#0-0) 

This delegates to `AssetConversion::quote_price_tokens_for_exact_tokens`, which reads the pool's *current* on-chain reserves via `get_reserves` and runs the constant-product formula (`get_amount_in`) directly against them, with no time-weighted average: [2](#0-1) [3](#0-2) 

The pallet's own doc comments even acknowledge the staleness risk without addressing manipulation: "Note that the price may have changed by the time the transaction is executed." This is the same missing invariant as `LP.sol#L87-L88`: a per-call live-balance read feeding directly into a value that has fund-moving consequences (here, how much of an asset gets consumed to pay a fee, or refunded post-dispatch via `correct_and_deposit_fee`).

Unlike EVM chains, Substrate has no atomic flash loans, but that primitive is unnecessary here: pool reserves persist as ordinary on-chain storage across extrinsics *within the same block*, and any account can submit multiple extrinsics in one block. An attacker holding both pool assets can:
1. In extrinsic 1, execute `AssetConversion::swap_exact_tokens_for_tokens` (or `add_liquidity`/`remove_liquidity`) to skew the `asset_id`/native reserve ratio drastically in their favor.
2. In extrinsic 2 (same block, same sender), submit any signed call using `ChargeAssetTxPayment` with `asset_id` set to the skewed asset; `withdraw_fee`'s `quote_price_tokens_for_exact_tokens` call reads the now-skewed reserves and charges a fee that can be made arbitrarily small relative to the real weight/length cost.
3. In extrinsic 3, reverse the swap to restore reserves, absorbing only the constant-product fee (`LPFee`) as cost, which is far smaller than the fee savings if the pool is thin.

Because `withdraw_fee` runs in `validate`/`prepare` (pre-dispatch) purely from current storage, and because block-authoring includes all of the attacker's extrinsics in one block without any external price oracle cross-check, none of the existing guards (`ProvidedMaximumNotSufficientForSwap`, `Preserve`/`Polite` reducible-balance checks, ED checks) address price *skew*, only liquidity sufficiency and account survivability.

### Impact Explanation
This directly matches the accepted impact class "public underpriced work that degrades block production": weight/length fees exist to price block space and deter spam; an attacker can make the effective on-chain cost of arbitrarily heavy extrinsics near-zero for any pool with thin liquidity, enabling free or near-free repeated block-space consumption funded by no one but themselves and the LPs of that pool (who absorb the arbitrage loss). No malicious validator, collator, governance actor, or off-chain infrastructure is required — a single unprivileged signed account performs the entire sequence.

### Likelihood Explanation
Any signer can create a pool and provide the minimal liquidity themselves via `create_pool`/`add_liquidity` (both permissionless), then target it with `ChargeAssetTxPayment { asset_id: Some(that_pool_asset) }`. There is no minimum-liquidity gate before a pool becomes usable for fee payment via `quote_price_tokens_for_exact_tokens`/`SwapAssetAdapter`, so the attack is available immediately after pool creation with no dependency on external market conditions.

### Recommendation
- Do not resolve `ChargeAssetTxPayment` fees against instantaneous pool reserves; require a minimum sustained liquidity/duration threshold before a pool is eligible as a fee-payment asset, or bound the maximum fee-asset amount fluctuation permitted per block.
- Consider deriving the conversion rate from a moving/time-weighted average of `get_reserves` snapshots (e.g., recorded once per block) rather than the live value read inside the same block as an attacker-controlled swap.
- Alternatively, disallow using a pool for `ChargeAssetTxPayment` unless its reserves have not been altered by the paying account (or accounts under its control) within the same block.

### Proof of Concept
1. Attacker calls `AssetConversion::create_pool(asset_A, Native)` and `add_liquidity` with minimal amounts (permissionless, no admin needed).
2. In block N, extrinsic 1 (attacker, `swap_exact_tokens_for_tokens`): dump a large amount of `asset_A` into the pool to crash `asset_A`'s price relative to Native.
3. Extrinsic 2 (attacker, any weight-heavy call) using `ChargeAssetTxPayment{ tip: 0, asset_id: Some(asset_A) }`: `withdraw_fee` → `SwapAssetAdapter::withdraw_fee` → `AssetConversion::quote_price_tokens_for_exact_tokens(asset_A, Native, fee_in_native, true)` returns a tiny `asset_fee` because the pool is now skewed, so the attacker pays almost nothing in `asset_A` for the real native-fee-equivalent weight consumed. See computation path at: [4](#0-3) 
4. Extrinsic 3 (attacker, `swap_exact_tokens_for_tokens` reverse direction): restore reserves, only losing the constant-product `LPFee` on the round trip, which is far less than the fee subsidy captured in step 3. [5](#0-4)

		pub fn get_amount_out(
			fee: Permill,
			amount_in: &T::Balance,
			reserve_in: &T::Balance,
			reserve_out: &T::Balance,
		) -> Result<T::Balance, Error<T>> {
			let amount_in = T::HigherPrecisionBalance::from(*amount_in);
			let reserve_in = T::HigherPrecisionBalance::from(*reserve_in);
			let reserve_out = T::HigherPrecisionBalance::from(*reserve_out);

			if reserve_in.is_zero() || reserve_out.is_zero() {
				return Err(Error::<T>::ZeroLiquidity);
			}

			let fee_complement = fee.left_from_one().deconstruct();
			let amount_in_with_fee = amount_in
				.checked_mul(&T::HigherPrecisionBalance::from(fee_complement))
				.ok_or(Error::<T>::Overflow)?;

			let numerator =
				amount_in_with_fee.checked_mul(&reserve_out).ok_or(Error::<T>::Overflow)?;

			let denominator = reserve_in
				.checked_mul(&T::HigherPrecisionBalance::from(Permill::ACCURACY))
				.ok_or(Error::<T>::Overflow)?
				.checked_add(&amount_in_with_fee)
				.ok_or(Error::<T>::Overflow)?;

			let result = numerator.checked_div(&denominator).ok_or(Error::<T>::Overflow)?;

			result.try_into().map_err(|_| Error::<T>::Overflow)
		}

		///
		/// If `include_fee` is true, the quote will include the liquidity provider fee.
		/// If the pool does not exist or has no liquidity, `None` is returned.
		/// Note that the price may have changed by the time the transaction is executed.
		/// (Use `amount_in_max` to control slippage.)
		/// Returns `Some(quoted_amount)` on success.
		pub fn quote_price_tokens_for_exact_tokens(
			asset1: T::AssetKind,
			asset2: T::AssetKind,
			amount: T::Balance,
			include_fee: bool,
		) -> Option<T::Balance> {
			// Swaps reject zero amounts, match that behavior.
			if amount.is_zero() {
				return None;
			}
			let pool_account = T::PoolLocator::pool_address(&asset1, &asset2).ok()?;

			let (balance1, balance2) = Self::get_reserves(asset1.clone(), asset2.clone()).ok()?;

			if balance1.is_zero() {
				return None;
			}

			// Swap withdrawals from pools use `keep_alive=true` (Preserve). Use the same
			// preservation level to determine the actual withdrawable amount.
			let max_output =
				T::Assets::reducible_balance(asset2.clone(), &pool_account, Preserve, Polite);
			if amount > max_output {
				return None;
			}

			if include_fee {
				let fee = Self::pool_fee_for(&asset1, &asset2).ok()?;
				Self::get_amount_in(fee, &amount, &balance1, &balance2).ok()
			} else {
				Self::quote(&amount, &balance2, &balance1).ok()
			}
		}
