### Title
Credential Disclosure via GOAUTH Error Logging on `git credential fill` / GOAUTH Command Failure - ([File: src/cmd/go/internal/auth/gitauth.go])

### Finding Description
When `GOAUTH=git <dir>` is configured, `runGitAuth` invokes `git credential fill` and, on non-zero exit, wraps the *raw combined stdout+stderr* of that command directly into an error via `fmt.Errorf("'git credential fill' failed (url=%s): %w\n%s", url, err, out)` [1](#0-0) . Because `out` is `cmd.CombinedOutput()` of the credential helper, it can contain `protocol=/host=/username=/password=` lines that some helpers echo/print even on a non-zero exit path (e.g. helper found credentials but failed a later step, or wrote partial data before erroring). This error is propagated unmodified up through `runGoAuth`, which stores it in `cmdErrs` and, if `cfg.BuildX` is set and no credential is ultimately loaded for the URL, prints every collected error verbatim with `log.Printf` [2](#0-1) [3](#0-2) . The same pattern exists for custom GOAUTH commands in `runAuthCommand`, which embeds `cmd.Stderr`/error text into `fmt.Errorf` without any redaction before it is likewise logged [4](#0-3) .

This is analogous to the Ansible CVE-2021-20191 primitive — sensitive credential material flowing into diagnostic/log output through an error/exception path that was not designed to redact secrets, even though the codebase elsewhere is careful to redact passwords (`net/url.Redacted`, `net/http` `stripPassword`) [5](#0-4) [6](#0-5) .

### Impact Explanation
If triggered, a user's Basic Auth username/password (or custom GOAUTH command's raw stderr, which may itself contain tokens) would be written to `go build -x`/`go get -x` log output, which is commonly captured in CI logs, terminal transcripts, or shared build logs — a credential-disclosure scenario matching CWE-532. However, this requires (a) `cfg.BuildX` (`-x` flag) to be enabled, and (b) the specific credential helper or authenticator command's failure-path output to include the secret, which is helper-implementation-dependent and not guaranteed by the go tool's own logic. This is a plausible but conditional/PRIVATE-track-level concern rather than a directly, unconditionally reproducible leak in stock configurations.

### Likelihood Explanation
Victim workflow: an ordinary developer sets `GOAUTH=git <dir>` (or a custom authenticator) and runs `go build -x`/`go get -x` against a module host requiring auth, while a locally configured credential helper returns a non-zero exit status after having already produced credential-shaped output. This depends on third-party credential-helper behavior, not solely on attacker input, and does not require any elevated privilege — it's a normal developer/CI workflow misconfiguration rather than an attacker-controlled trigger.

### Recommendation
Redact `out` before including it in error messages in `runGitAuth` (e.g., strip any `password=` line before formatting), and avoid echoing raw command stderr/output from `runAuthCommand` into errors that may be logged via `-x`. At minimum, document that `-x` output for GOAUTH commands may include sensitive helper output and should not be shared, and prefer emitting only human-readable diagnostic text (exit code, generic failure) rather than raw process output.

func TestGitAuthErrorLeaksCredential(t *testing.T) {
	// Simulated CombinedOutput() from a failing helper.
	fakeOut := []byte("protocol=https\nhost=example.com\nusername=bob\npassword=secr3t\n")
	err := &fakeExitError{}

	got := formatGitAuthError("https://example.com", err, fakeOut)

		t.Fatalf("credential leaked into error/log text: %q", got)
	}
}

// formatGitAuthError mirrors the vulnerable formatting in gitauth.go's
// runGitAuth error path (lines 49-51).
func formatGitAuthError(url string, err error, out []byte) string {
	return "'git credential fill' failed (url=" + url + "): " + err.Error() + "\n" + string(out)
}

type fakeExitError struct{}

func (e *fakeExitError) Error() string { return "exit status 1" }

var _ = bytes.NewReader // keep import used if trimmed later

// Redacted is like [URL.String] but replaces any password with "xxxxx".
// Only the password in u.User is redacted.
func (u *URL) Redacted() string {
	if u == nil {
		return ""
	}

	ru := *u
	if _, has := ru.User.Password(); has {
		ru.User = UserPassword(ru.User.Username(), "xxxxx")
	}
	return ru.String()
}

func stripPassword(u *url.URL) string {
	_, passSet := u.User.Password()
	if passSet {
		return strings.Replace(u.String(), u.User.String()+"@", u.User.Username()+":***@", 1)
	}
	return u.String()
}
