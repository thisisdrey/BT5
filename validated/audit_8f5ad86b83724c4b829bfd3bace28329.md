Audit Report

## Title
Incomplete `AliasOrigin` denylist in Snowbridge V2 outbound converter allows origin-spoofing of any non-AssetHub agent - (File: `bridges/snowbridge/primitives/outbound-queue/src/v2/converter/convert.rs`)

## Summary
`XcmConverter::convert()` extracts an `AliasOrigin(Location)` instruction directly from a user-supplied remote XCM program and, after only a single hard-coded exclusion check, converts it via `AgentIdOf::convert_location` into the `origin` field of the outbound `Message` delivered to the Ethereum Gateway [1](#0-0) . The guard `ensure!(AllowedAliasOrigin::contains(origin_location), InvalidOrigin)` is configured in the Bridge Hub Westend runtime as `EverythingBut<Equals<AssetHubLocation>>` [2](#0-1) , which blocks only the exact AssetHub location and permits any other `Location` value to be aliased into an agent id that becomes the message's authoritative origin.

## Finding Description
The XCM program processed by `XcmConverter::convert()` is the "remote program" passed as the inner `xcm` of an `ExportMessage` instruction handled by `EthereumBlobExporter::validate()` [3](#0-2) . This inner program is never locally executed by AssetHub's own XCM executor/barrier — it is only pattern-matched and converted into the Gateway `Message` format. Consequently, none of AssetHub's local `Aliasers`/`TrustedAliasers`/`AuthorizedAliasers` protections (which do gate `AliasOrigin` for locally-executed XCM, as seen in `bridge-hub-rococo`'s `TrustedAliasers` config [4](#0-3) ) ever apply to this embedded `AliasOrigin`. The only check is `AllowedAliasOrigin::contains(origin_location)` in `convert()`, which the Westend runtime instantiates as `EverythingBut<Equals<AssetHubLocation>>` — an exact-equality denylist for a single location, not an allowlist scoped to the caller's authenticated identity. `EthereumBlobExporter::validate()` does verify that the *outer* `universal_source` of the export call is AssetHub's own para ID [5](#0-4) , confirming that any unprivileged AssetHub signer can trigger this export path, but this check says nothing about what `Location` the embedded `AliasOrigin` instruction is allowed to claim. The negative test in the repository only exercises rejection of `Equals<AssetHubLocation>` and does not test rejection of any other parachain/location [6](#0-5) , confirming no broader validation exists or is tested.

## Impact Explanation
The `origin` field of the produced `Message` (derived via `AgentIdOf::convert_location`, which is a `HashedDescription`-based deterministic hash of the claimed `Location` [7](#0-6) ) determines which Ethereum-side agent contract is the authoritative "origin" for the message, including any embedded `Transact`/`Command::CallContract` [8](#0-7) . Because `AllowedAliasOrigin` only rejects the literal AssetHub location, an attacker can set `AliasOrigin` to any other parachain/location that has an existing Ethereum agent, causing the Gateway to treat the message as originating from that victim's agent. This matches the "unauthorized execution or origin escalation" impact category, since the corrupted value is the `origin` (effective identity/agent) field of the outbound `Message`.

## Likelihood Explanation
The exploit path requires only a signed AssetHub account submitting a standard extrinsic (`pallet_xcm::execute` / `transfer_assets_using_type_and_then` with a custom `remote_xcm`) — no privileged role, relayer, or validator behavior is needed. The check bypassed is a single, static equality comparison, trivially defeated by choosing any location other than `AssetHubLocation`.

## Recommendation
Replace the denylist `EverythingBut<Equals<AssetHubLocation>>` with an allowlist that ties `AliasOrigin` targets to the authenticated sending identity — e.g., only allow the origin to equal the actual `universal_source`/AssetHub-derived sub-location (or an explicitly-authorized descendant of it), analogous to the `TrustedAliasers`/`AuthorizedAliasers` model already used for local XCM execution.

## Proof of Concept
1. A victim parachain `V` (≠ AssetHub) has a pre-existing Ethereum agent contract with assets/allowances.
2. An unprivileged AssetHub signer calls `pallet_xcm::execute` with a `remote_xcm` program: `WithdrawAsset(fee) -> PayFees -> WithdrawAsset/ReserveAssetDeposited(assets) -> AliasOrigin(Location::new(1,[Parachain(V)])) -> DepositAsset{beneficiary: attacker} -> Transact{...} -> SetTopic`.
3. `EthereumBlobExporter::validate()` accepts the export since `universal_source` legitimately resolves to AssetHub [5](#0-4) .
4. `XcmConverter::convert()` accepts `AliasOrigin(V)` since `V != AssetHubLocation` passes `AllowedAliasOrigin::contains` [9](#0-8) , producing a `Message` whose `origin` is `V`'s agent id, letting the attacker's `Transact`/`CallContract` execute under `V`'s agent authority on Ethereum.

	fn validate(
		network: NetworkId,
		_channel: u32,
		universal_source: &mut Option<InteriorLocation>,
		destination: &mut Option<InteriorLocation>,
		message: &mut Option<Xcm<()>>,
	) -> SendResult<Self::Ticket> {
		tracing::debug!(target: TARGET, ?message, "message route through bridge.");

		let expected_network = EthereumNetwork::get();
		let universal_location = UniversalLocation::get();

		if network != expected_network {
			tracing::trace!(target: TARGET, ?network, "skipped due to unmatched bridge network.");
			return Err(SendError::NotApplicable);
		}

		// Cloning destination to avoid modifying the value so subsequent exporters can use it.
		let dest = destination.clone().ok_or(SendError::MissingArgument)?;
		if dest != Here {
			tracing::trace!(target: TARGET, destination=?dest, "skipped due to unmatched remote destination.");
			return Err(SendError::NotApplicable);
		}

		// Cloning universal_source to avoid modifying the value so subsequent exporters can use it.
		let (local_net, local_sub) = universal_source
			.clone()
			.ok_or_else(|| {
				tracing::error!(target: TARGET, "universal source not provided.");
				SendError::MissingArgument
			})?
			.split_global()
			.map_err(|()| {
				tracing::error!(target: TARGET, ?universal_source, "could not get global consensus.");
				SendError::NotApplicable
			})?;

		if Ok(local_net) != universal_location.global_consensus() {
			tracing::trace!(target: TARGET, relay_network=?local_net, "skipped due to unmatched relay network.");
			return Err(SendError::NotApplicable);
		}

		let para_id = match local_sub.as_slice() {
			[Parachain(para_id)] => *para_id,
			_ => {
				tracing::error!(target: TARGET, universal_source=?local_sub, "could not get parachain id.");
				return Err(SendError::NotApplicable);
			},
		};

		if ParaId::from(para_id) != AssetHubParaId::get() {
			tracing::error!(target: TARGET, ?para_id, "is not from asset hub.");
			return Err(SendError::NotApplicable);
		}

		let message = message.clone().ok_or_else(|| {
			tracing::error!(target: TARGET, "xcm message not provided.");
			SendError::MissingArgument
		})?;

		// Inspect `AliasOrigin` as V2 message. This exporter should only process Snowbridge V2
		// messages. We use the presence of an `AliasOrigin` instruction to distinguish between
		// Snowbridge V2 and Snowbridge V1 messages, since XCM V5 came after Snowbridge V1 and
		// so it's not supported in Snowbridge V1. Snowbridge V1 messages are processed by the
		// snowbridge-outbound-queue-primitives v1 exporter.
		let mut instructions = message.clone().0;

					_ => Ok(ControlFlow::Continue(())),
				};
			},
		);
		ensure!(result.is_err(), SendError::NotApplicable);

			XcmConverter::<ConvertAssetId, (), AllowedAliasOrigin>::new(&message, expected_network);
		let message = converter.convert().map_err(|err| {
			tracing::error!(target: TARGET, error=?err, "unroutable due to pattern matching.");
			SendError::Unroutable
		})?;

fn xcm_converter_convert_with_assethub_alias_origin_yields_invalid_origin() {

		fun: Fungible(1000),
