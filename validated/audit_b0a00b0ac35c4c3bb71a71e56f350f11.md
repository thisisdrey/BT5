### Title
Repo Contents Cache trusts a repository rule's self-declared `reproducible=True` claim with no verification, allowing a hostile repo rule to poison the cache for unrelated workspaces/builds - ([File: repo_metadata / repo contents cache mechanism, exercised in src/test/py/bazel/bzlmod/remote_repo_contents_cache_test.py, src/test/py/bazel/bzlmod/repo_contents_cache_test.py])

### Summary
`repository_ctx.repo_metadata(reproducible=True)` is a value returned entirely by the (often third‑party) implementation function of a repository rule. Bazel uses this single, self‑asserted boolean to decide whether the fetched repo's contents may be cached and served to *other* workspaces and builds via the repo contents cache / remote repo contents cache [1](#0-0) . There is no independent verification by Bazel that the rule's output is actually deterministic with respect to only the declared/recorded inputs (attrs, watched files, declared `environ`). This mirrors the report's bug class: a state‑changing/trust‑granting operation (`activateOperator`) that should require a privileged check but instead accepts an unauthenticated caller's say‑so.

### Finding Description
The recommended, documented contract for `reproducible=True` is: "if it were fetched another time with exactly the same input attributes, repo rule definition, watched files and environment variables, etc., then exactly the same output would be produced. This property needs to hold even if other untracked conditions change, such as information from the internet ... or output from running arbitrary executables" [2](#0-1) . Bazel does not check this invariant; it is purely advisory and self-reported by the `.bzl` code that implements the repository rule.

The impact of this trust is concretely observable in the test suite: once a repo rule returns `repo_metadata(reproducible=True)`, its fetched contents become cacheable and are subsequently *reused across `bazel clean --expunge`*, across independent workspaces on the same machine, and — with `--experimental_remote_repo_contents_cache` — across all machines sharing the remote cache/worker, without re-invoking the rule implementation at all [3](#0-2) [4](#0-3) . The cache key is derived only from "predeclared inputs" (rule attrs) and "recorded inputs" (watched files, declared `environ` variables) [5](#0-4) [6](#0-5)  — it does **not** include a hash of the actual fetched/produced bytes, and there is no re-verification step comparing a fresh fetch to the cached one.

Because a repository rule's implementation is ordinary Starlark that a project may load from an external, less‑trusted source (a `bazel_dep`/module, an `http_archive`, or a rule loaded from an untrusted branch that CI builds), an attacker who controls that `.bzl` code can:
1. Return `repo_metadata(reproducible=True)` unconditionally, while
2. Making the fetched repo contents actually depend on an **untracked** signal (e.g., a value read from the network with `ctx.download`/`ctx.execute` output not recorded via `watch()`/`environ`, current date, or a value affecting behavior only "sometimes" — e.g., only for certain CI machines or only the first N builds), and
3. Emitting attacker-controlled content once, which is then cached and silently served — without re-invoking the fetch — to all subsequent, unrelated builds that reference the same declared inputs, on the same machine (local repo contents cache) or across all consumers of a shared remote cache endpoint (remote repo contents cache).

This is analogous to the Solidity finding: a security‑relevant, cross‑tenant state transition (`activate` → global cacheability across future builds) is gated by nothing but the caller's own unauthenticated assertion, instead of an owner-controlled/verifiable check (e.g., a content digest comparison as Bazel does for `ctx.download(sha256=...)` [7](#0-6) ).

### Impact Explanation
A single dishonestly-reproducible repo rule invocation can inject attacker-chosen files into the external repository directory of every other build that shares the repo contents cache (same machine) or the remote repo contents cache (shared CI fleet), as long as the declared/recorded inputs match. Since these files become ordinary source artifacts under `$OUTPUT_BASE/external/<repo>` that are compiled/executed as part of the dependent build [8](#0-7) , this is a cache-poisoning primitive that can reach and corrupt other, unrelated builds — one of the explicitly in-scope impacts for this analysis.

### Likelihood Explanation
Any project can pull in repository-rule Starlark code from a `bazel_dep`, `http_archive`, or a shared `.bzl` file on a branch that CI builds without fully auditing it; the offending code just needs to call `repo_metadata(reproducible=True)`. No special privilege, credential, or MITM position is needed — the "attacker" is simply the author/publisher of that Starlark content, matching the required threat model (an outsider publishing content a victim's build consumes). The feature is on by default (repo contents cache) or opt-in (remote repo contents cache), both are current/documented Bazel functionality.

### Recommendation
Do not trust `reproducible=True` unconditionally for cross-workspace/cross-build caching. Options:
- Include a content digest of the actually-fetched repo tree in the cache key and/or periodically re-verify a sampled fraction of cache hits by re-running the rule and diffing output, similar to how downloads are pinned by `sha256`/`integrity`.
- Restrict remote/cross-workspace caching of `reproducible=True` repos to rules whose source is itself pinned/verified (e.g., only repos fetched via an integrity-checked `http_archive`/registry entry), rather than arbitrary local or transitively-loaded `.bzl` implementations.
- Surface a warning/audit log when a `reproducible=True` claim cannot be corroborated (e.g., the rule also performs unrecorded network/exec calls).

### Proof of Concept
The existing test files already demonstrate the trust boundary and its cross-workspace/cross-build reach; they can be adapted into a positive PoC by having the rule secretly branch on an *unrecorded* signal while still declaring `reproducible=True`, for example modeled on `testNoThrashingBetweenWorkspaces`: [3](#0-2) 
1. Workspace A fetches `my_repo` with a rule that reads an *unwatched* file/URL and writes attacker payload X into `BUILD`/source files, but returns `repo_metadata(reproducible=True)`.
2. Workspace B, with identical predeclared/recorded inputs but a different underlying "truth" for the unrecorded signal (which should have produced Y), builds `@my_repo//:...` and receives cached payload X from A instead of Y, without re-invoking the rule — exactly as shown by the "cached (even after expunging)" / "Fetch in B ... cached" assertions in the existing suite [9](#0-8) .

Note: I could not locate the underlying Java implementation classes (e.g., the equivalent of `RepoRecordedInputs`, `StarlarkRepositoryContext.repoMetadata`, or the `RemoteRepoContentsCacheImpl`/`LocalRepoContentsCache` cache-key computation) in the indexed codebase — searches for these symbols returned no Java matches, likely because the index size limits excluded those source files. If precise verification of the exact cache-key composition and whether any additional digesting exists is required, a Devin session with full repository access would be needed to inspect the Java sources directly (likely under `src/main/java/com/google/devtools/build/lib/bazel/repository/...` or `src/main/java/com/google/devtools/build/lib/rules/repository/...`).

```
Constructs an opaque object that can be returned from the repo rule's implementation function to provide metadata about its reproducibility.

### Parameters

| Parameter | Description |
| --- | --- |
| `reproducible` | [bool](../core/bool); default is `False`  States that this repo can be reproducibly refetched; that is, if it were fetched another time with exactly the same input attributes, repo rule definition, watched files and environment variables, etc., then exactly the same output would be produced. This property needs to hold even if other untracked conditions change, such as information from the internet, the path of the workspace root, output from running arbitrary executables, etc. If set to True, this allows the fetched repo contents to be cached across workspaces. Note that setting this to True does not guarantee caching in the repo contents cache; for example, local repo rules are never cached. |
```

```python
  def testNotCachedWhenPredeclaredInputsChange(self):
    self.ScratchFile(
        'MODULE.bazel',
        [
            'repo = use_repo_rule("//:repo.bzl", "repo")',
            'repo(name = "my_repo", data = 1)',
        ],
    )
    self.ScratchFile('BUILD.bazel')
    self.ScratchFile(
        'repo.bzl',
        [
            'def _repo_impl(rctx):',
            '  rctx.file("BUILD", "filegroup(name=\'haha\')")',
            '  print("JUST FETCHED")',
            '  return rctx.repo_metadata(reproducible=True)',
            'repo = repository_rule(_repo_impl, attrs={"data":attr.int()})',
        ],
    )

    repo_dir = self.RepoDir('my_repo')

    # First fetch: not cached
    _, _, stderr = self.RunBazel(['build', '@my_repo//:haha'])
    self.assertIn('JUST FETCHED', '\n'.join(stderr))
    self.assertTrue(os.path.exists(os.path.join(repo_dir, 'BUILD')))

    # Change predeclared inputs: not cached
    self.ScratchFile(
        'MODULE.bazel',
        [
            'repo = use_repo_rule("//:repo.bzl", "repo")',
            'repo(name = "my_repo", data = 2)',
        ],
    )
    _, _, stderr = self.RunBazel(['build', '@my_repo//:haha'])
    self.assertIn('JUST FETCHED', '\n'.join(stderr))
    self.assertTrue(os.path.exists(os.path.join(repo_dir, 'BUILD')))

    # Change back to previous predeclared inputs: cached (even after expunging)
    self.RunBazel(['clean', '--expunge'])
    self.ScratchFile(
        'MODULE.bazel',
        [
            'repo = use_repo_rule("//:repo.bzl", "repo")',
            'repo(name = "my_repo", data = 1)',
        ],
    )
    _, _, stderr = self.RunBazel(['build', '@my_repo//:haha'])
    self.assertNotIn('JUST FETCHED', '\n'.join(stderr))
    self.assertFalse(os.path.exists(os.path.join(repo_dir, 'BUILD')))
```

```python
  def testNoThrashingBetweenWorkspaces(self):
    module_bazel_lines = [
        'repo = use_repo_rule("//:repo.bzl", "repo")',
        'repo(name = "my_repo")',
    ]
    repo_bzl_lines = [
        'def _repo_impl(rctx):',
        '  rctx.file("BUILD", "filegroup(name=\'haha\')")',
        '  rctx.os.environ.get("LOLOL")',
        '  print("JUST FETCHED")',
        '  return rctx.repo_metadata(reproducible=True)',
        'repo = repository_rule(_repo_impl, environ = ["LOLOL"])',
    ]
    # Set up two workspaces with exactly the same repo definition (same
    # predeclared inputs)
    dir_a = self.ScratchDir('a')
    dir_b = self.ScratchDir('b')
    self.ScratchFile('a/MODULE.bazel', module_bazel_lines)
    self.ScratchFile('b/MODULE.bazel', module_bazel_lines)
    self.ScratchFile('a/BUILD.bazel')
    self.ScratchFile('b/BUILD.bazel')
    self.ScratchFile('a/repo.bzl', repo_bzl_lines)
    self.ScratchFile('b/repo.bzl', repo_bzl_lines)
    self.CopyFile(self.Path('.bazelrc'), 'a/.bazelrc')
    self.CopyFile(self.Path('.bazelrc'), 'b/.bazelrc')

    repo_dir_a = self.RepoDir('my_repo', cwd=dir_a)
    repo_dir_b = self.RepoDir('my_repo', cwd=dir_b)

    # First fetch in A: not cached
    _, _, stderr = self.RunBazel(
        ['build', '@my_repo//:haha'], cwd=dir_a, env_add={'LOLOL': 'lol'}
    )
    self.assertIn('JUST FETCHED', '\n'.join(stderr))
    self.assertTrue(os.path.exists(os.path.join(repo_dir_a, 'BUILD')))

    # Fetch in B (with same env variable): cached
    _, _, stderr = self.RunBazel(
        ['build', '@my_repo//:haha'], cwd=dir_b, env_add={'LOLOL': 'lol'}
    )
    self.assertNotIn('JUST FETCHED', '\n'.join(stderr))
    self.assertFalse(os.path.exists(os.path.join(repo_dir_b, 'BUILD')))

    # Change env variable: not cached
    _, _, stderr = self.RunBazel(
        ['build', '@my_repo//:haha'], cwd=dir_b, env_add={'LOLOL': 'rofl'}
    )
    self.assertIn('JUST FETCHED', '\n'.join(stderr))
    self.assertTrue(os.path.exists(os.path.join(repo_dir_b, 'BUILD')))

    # Building A again even after expunging: cached
    self.RunBazel(['clean', '--expunge'], cwd=dir_a)
    _, _, stderr = self.RunBazel(
        ['build', '@my_repo//:haha'], cwd=dir_a, env_add={'LOLOL': 'rofl'}
    )
    self.assertNotIn('JUST FETCHED', '\n'.join(stderr))
    self.assertFalse(os.path.exists(os.path.join(repo_dir_a, 'BUILD')))
```

```text
Once a repository is downloaded, the artifacts in it are treated as source
artifacts. This poses a problem because Bazel usually checks for up-to-dateness
of source artifacts by calling stat() on them, and these artifacts are also
invalidated when the definition of the repository they are in changes. Thus,
`FileStateValue`s for an artifact in an external repository need to depend on
their external repository. This is handled by `ExternalFilesHelper`.
```
