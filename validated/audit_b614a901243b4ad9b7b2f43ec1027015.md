### Title
Per-source-IP QUIC connection rate limiter trivially bypassed via IPv6 /64 address rotation - ([File: streamer/src/nonblocking/connection_rate_limiter.rs])

### Summary
`ConnectionRateLimiter` in `streamer/src/nonblocking/connection_rate_limiter.rs` keys its `KeyedRateLimiter` token buckets by exact `std::net::IpAddr`, and `run_server` in `streamer/src/nonblocking/quic.rs` applies this limiter per literal source `IpAddr` before/after handshake. An attacker who controls an IPv6 /64 (trivial for most residential/cloud allocations) can bind a new source address for every connection attempt, so each connection is seen as a "new IP" by `is_allowed`/`register_connection`, defeating `DEFAULT_MAX_CONNECTIONS_PER_IPADDR_PER_MINUTE` (and the connection-table `ConnectionTableKey::IP` per-peer caps that key off the same `IpAddr`).

### Finding Description
`run_server` performs two connection-admission gates before handing a connection to QoS: a single shared `overall_connection_rate_limiter` (`TokenBucket`, global to the endpoint) and a per-IP `rate_limiter: ConnectionRateLimiter` [1](#0-0) . `ConnectionRateLimiter::is_allowed`/`register_connection` operate on `KeyedRateLimiter<IpAddr>`, so any two distinct `IpAddr` values, even differing only in the low 64 bits, are treated as fully independent rate-limit buckets with their own quota of `DEFAULT_MAX_CONNECTIONS_PER_IPADDR_PER_MINUTE` (default 8) connections/minute plus 10x burst [2](#0-1) [3](#0-2) . Likewise `ConnectionTable`'s per-peer cap (`try_add_connection`) is keyed by `ConnectionTableKey::IP(ip)` derived from the exact remote `IpAddr` when no pubkey is presented [4](#0-3) [5](#0-4) . Since an unstaked QUIC client with no verified pubkey uses `ConnectionTableKey::IP`, an attacker rotating source addresses within an owned /64 prefix produces a new key for every connection, so neither the connection-rate limiter nor the per-peer connection-table cap accumulate against the attacker as a whole — only the single shared `overall_connection_rate_limiter` remains as a backstop.

This is a real QoS-fairness bypass: the per-IP limiter's entire purpose (bounding a single network endpoint's share of connection attempts) is defeated at negligible cost, since IPv6 /64 delegation is standard and gives 2^64 addresses. The attacker can consume the entire shared `overall_connection_rate_limiter` budget alone, effectively starving legitimate unstaked peers sharing the TPU port, and can also open many more concurrent unstaked connections against `DEFAULT_MAX_UNSTAKED_CONNECTIONS`/`DEFAULT_MAX_QUIC_CONNECTIONS_PER_UNSTAKED_PEER` than a single-peer cap intends, since each rotated address gets its own per-peer connection-table slot.

### Impact Explanation
Impact is scoped to QoS evasion / connection-table and rate-limiter fairness bypass for unstaked clients hitting the TPU QUIC port, not an unbounded global rate (the global `overall_connection_rate_limiter` still caps absolute throughput). The concrete scoped impact: a single unprivileged host can, at effectively zero cost, monopolize the shared connection admission budget and the unstaked connection-table capacity that are supposed to be fairly divided among many distinct source IPs, starving legitimate low-resource unstaked senders and degrading TPU ingress availability for others — this matches Agave's "TPU QoS bypass / resource starvation" bounty category.

### Likelihood Explanation
Highly likely/feasible: obtaining an IPv6 /64 is default behavior for most residential ISPs, VPS, and cloud providers; binding a new ephemeral source address per QUIC connection requires no special privilege, only `SO_REUSEADDR`-style socket binding to sequential addresses in the delegated prefix. No control over validator/gossip/staking is required — this is purely a client-side connection pattern from a single physical host with a routable /64.

### Recommendation
Rate-limit and connection-table-cap by network prefix as well as exact address: for IPv6 sources, derive the rate-limiter/connection-table key from the /64 (or configurable prefix length) network portion of the address instead of the full 128-bit `IpAddr`, e.g., mask the address before insertion into `ConnectionRateLimiter` and before constructing `ConnectionTableKey::IP`. Keep IPv4 keyed as today (or apply a coarser /24-style mask similarly). This preserves existing per-source semantics while closing the low-cost rotation bypass.

```rust
// streamer/src/nonblocking/connection_rate_limiter.rs (extend existing test module)
#[tokio::test]
async fn test_rate_limiter_ipv6_subnet_rotation_bypass() {
    use std::net::Ipv6Addr;
    let limiter = ConnectionRateLimiter::new(/*limit_per_minute=*/8, /*max_burst=*/80, 4);
    let base: u128 = Ipv6Addr::new(0x2001, 0xdb8, 0, 0, 0, 0, 0, 0).into();

    // Attacker owns a /64: rotate the low 64 bits for every connection.
    let mut accepted = 0;
    for i in 0..1000u128 {
        let addr = std::net::IpAddr::V6(Ipv6Addr::from(base | i));
        if limiter.register_connection(&addr) {
            accepted += 1;
        }
    }

    // Current behavior: every distinct address gets its own quota, so
    // essentially all 1000 connections are accepted despite the intended
    // 8/minute-per-source limit.
    assert!(
        accepted > 100,
        "expected current code to allow far more than the per-IP limit \
         via /64 rotation, got {accepted}"
    );

    // Desired fix behavior (should fail against unpatched code, pass after
    // subnet-aware keying is implemented):
    // assert!(accepted <= 80, "aggregate connections from one /64 should be \
    //     capped near the per-source burst limit, not scale with address count");
}
```

```rust
impl ConnectionRateLimiter {
    /// Create a new rate limiter per IpAddr. The rate is specified as the count per minute to allow for
    /// less frequent connections. Higher limit also allows higher bursts.
    /// num_shards controls how many shards are used in the underlying dashmap,
    /// should be set >= number of contending threads.
    pub fn new(limit_per_minute: u64, max_burst: u64, num_shards: usize) -> Self {
        Self {
            limiter: KeyedRateLimiter::new(
                CONNECTION_RATE_LIMITER_CLEANUP_SIZE_THRESHOLD,
                TokenBucket::new(limit_per_minute, max_burst, limit_per_minute as f64 / 60.0),
                num_shards,
            ),
        }
    }

    /// Check if the connection from the said `ip` is allowed.
    /// Here we assume that only IPs with actual confirmed connections are stored in it,
    /// since we should only modify server state once source IP is verified
    pub fn is_allowed(&self, ip: &IpAddr) -> bool {
        // Check if we have records in the rate limiter for the given IP address
        match self.limiter.current_tokens(ip) {
            Some(r) => r > 0, // we have a record, and rate is not exceeded
            None => true,     // if we have not seen IP, allow connection request
        }
    }

    pub fn register_connection(&self, ip: &IpAddr) -> bool {
        if self.limiter.consume_tokens(*ip, 1).is_ok() {
            debug!("Request from IP {ip:?} allowed");
            true // Request allowed
        } else {
            debug!("Request from IP {ip:?} blocked");
            false // Request blocked
        }
    }
```
