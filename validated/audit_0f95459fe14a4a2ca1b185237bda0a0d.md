### Title
Unauthenticated `/new_burn_block` HTTP endpoint lets a remote peer inject a forged `SignerEvent::NewBurnBlock` with attacker-chosen `consensus_hash`/`burn_header_hash` - (File: libsigner/src/events.rs)

### Summary
`SignerEventReceiver::next_event` dispatches any POST to `/new_burn_block` straight to `process_event::<T, BurnBlockEvent>`, which only JSON-deserializes the body and calls `TryFrom<BurnBlockEvent> for SignerEvent<T>` — there is no signature, MAC, or node-identity check anywhere in this file. Per the shipped sample config the signer's event-receiver HTTP server binds to `0.0.0.0:<port>`, so any remote host that can reach that port can feed the signer a fabricated burn-chain tip.

### Finding Description
`next_event()` routes the request purely by URL path [1](#0-0) , and `process_event` performs no authentication: it reads the body, ACKs the HTTP request, then deserializes attacker bytes directly into `BurnBlockEvent` and converts via `TryInto<SignerEvent<T>>` [2](#0-1) . The resulting `SignerEvent::NewBurnBlock` variant carries `burn_height`, `burn_header_hash`, `consensus_hash`, and `parent_burn_block_hash` fields copied verbatim from the JSON with no cryptographic tie to the burnchain [3](#0-2) . The `auth_token`/`auth_password` mechanism documented in the sample configs only authenticates the *signer's outbound calls to the node's RPC/block-proposal API* — it does not gate inbound POSTs to the signer's own event-receiver server [4](#0-3) . The sample signer config explicitly binds this receiver to all interfaces (`endpoint = "0.0.0.0:30000"`) [5](#0-4) , so it is reachable by any remote party, not just the paired stacks-node. Downstream, the signer's runloop consumes this event and unconditionally writes the attacker-controlled `burn_header_hash`/`consensus_hash`/`burn_height` into `signerdb.insert_burn_block(...)` and feeds them into `local_state_machine.bitcoin_block_arrival(...)`, driving the signer's notion of the current burnchain tip [6](#0-5) .

### Impact Explanation
A remote attacker who can reach the signer's event-receiver port can forge a `NewBurnBlock` event with an arbitrary `consensus_hash`/`burn_header_hash`/`burn_height`, causing the signer to persist bogus burn-block state and advance its local sortition/state machine as if a chain-tip update occurred that the actual burnchain never committed — effectively steering the signer off the true tip using forged data, repeatable per POST with no rate limiting in this code path.

### Likelihood Explanation
The only precondition is network reachability to the configured event-receiver bind address; per the project's own sample configuration this is bound to `0.0.0.0`, i.e., all interfaces, requiring no secret, no valid StackerDB slot, and no privileged role — an unprivileged remote attacker who can open a TCP connection can send the crafted POST directly.

### Recommendation
Require the event-receiver HTTP server to authenticate the source of `/new_burn_block` (and other) POSTs — e.g., enforce the same shared-secret/auth-token check used for node↔signer RPC on inbound event posts, bind the receiver to loopback/private interfaces by default, and/or verify the payload against the node's actual sortition DB state before trusting `consensus_hash`/`burn_header_hash` fields.

### Proof of Concept
```rust
// libsigner/src/tests/mod.rs style test
let ev = SignerEventReceiver::<SignerMessage>::new(false);
let (res_send, _res_recv) = channel();
let mut signer = Signer::new(SimpleRunLoop::new(1), ev, res_send);
let endpoint: SocketAddr = "0.0.0.0:30099".parse().unwrap();
let running_signer = signer.spawn(endpoint).unwrap();

// Attacker-controlled forged burn block payload
let forged = serde_json::json!({
    "burn_block_hash": "0x".to_string() + &"11".repeat(32),
    "burn_block_height": 999999,
    "consensus_hash": "0x".to_string() + &"22".repeat(20),
    "parent_burn_block_hash": "0x".to_string() + &"33".repeat(32),
    "burn_amount": 0,
    "reward_recipients": [],
    "reward_slot_holders": []
});
let body = forged.to_string();
let mut sock = TcpStream::connect(("127.0.0.1", 30099)).unwrap();
let req = format!(
    "POST /new_burn_block HTTP/1.1\r\nHost: 127.0.0.1:30099\r\nConnection: close\r\nContent-Type: application/json\r\nContent-Length: {}\r\n\r\n{}",
    body.len(), body
);
sock.write_all(req.as_bytes()).unwrap();

let accepted_events = running_signer.stop().unwrap();
// Assert the forged consensus_hash/burn_header_hash was accepted unverified
assert!(matches!(&accepted_events[0], SignerEvent::NewBurnBlock { consensus_hash, .. } if consensus_hash.to_hex() == "22".repeat(20)));
```
This demonstrates that an unauthenticated remote POST is accepted and converted into a `SignerEvent::NewBurnBlock` carrying attacker-chosen chain-tip fields with no verification against the actual burnchain state.

```rust
fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}
```
