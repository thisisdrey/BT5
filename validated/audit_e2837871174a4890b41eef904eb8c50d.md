Audit Report

## Title
`asset-rewards` pool becomes permanently unusable after expiry due to `last_update_block` exceeding `expiry_block`, causing arithmetic underflow that reverts `stake`/`unstake`/`harvest_rewards` forever - (File: `substrate/frame/asset-rewards/src/lib.rs`)

## Summary
`update_pool_rewards` unconditionally sets `PoolInfo::last_update_block` to the current block number with no cap at `expiry_block`, while `reward_per_token` computes `last_block_reward_applicable(expiry_block).ensure_sub(last_update_block)`. Once any legitimate post-expiry `stake`/`unstake`/`harvest_rewards` call bumps `last_update_block` past `expiry_block`, every subsequent interaction with the pool underflows and reverts, permanently locking stakers' funds and unclaimed rewards.

## Finding Description
`update_pool_rewards` (`substrate/frame/asset-rewards/src/lib.rs:775-784`) sets `new_pool_info.last_update_block = T::BlockNumberProvider::current_block_number()` unconditionally, without clamping to `pool_info.expiry_block`. `reward_per_token` (`lib.rs:786-810`) then computes `Self::last_block_reward_applicable(pool_info.expiry_block).ensure_sub(pool_info.last_update_block)`, and `last_block_reward_applicable` (`lib.rs:826-833`) returns `pool_expiry_block` once `now >= pool_expiry_block`. `ensure_sub` errors on underflow instead of saturating.

Both `unstake` (`lib.rs:513-560`) and `harvest_rewards` (`lib.rs:568-615`) explicitly allow calls after expiry via `ensure!(now > pool_info.expiry_block || caller == staker, BadOrigin)`, and all three public entrypoints (`stake`, `unstake`, `harvest_rewards`) call `update_pool_and_staker_rewards` → `reward_per_token` → `update_pool_rewards` at the start of their bodies. Once a post-expiry call with `total_tokens_staked != 0` succeeds and writes `last_update_block = now > expiry_block` to storage, the next call's `reward_per_token` computes `expiry_block.ensure_sub(last_update_block)` where `last_update_block > expiry_block`, underflowing and returning `Err(ArithmeticError::Underflow)`, which propagates through `?` and reverts the extrinsic. There is no code path that clamps or resets `last_update_block`, and `cleanup_pool` requires zero stakers, which can no longer be reached via `unstake`.

## Impact Explanation
This is a permanent user-fund lock: staked tokens (frozen via `AssetsFreezer`) and unclaimed reward tokens held in the pool account become permanently inaccessible once the corrupted `last_update_block` state is written, since `stake`, `unstake`, and `harvest_rewards` all deterministically revert afterward and `cleanup_pool` cannot be reached. This matches the permanent user-fund lock impact class.

## Likelihood Explanation
High and fully unprivileged: any staker performing a normal, explicitly-permitted post-expiry `unstake` or `harvest_rewards` call (intended usage once a pool's incentive period ends) with `total_tokens_staked` still nonzero triggers the state corruption; every subsequent call by any account on that pool then reverts deterministically with no recovery path.

## Recommendation
Cap `last_update_block` at `expiry_block` in `update_pool_rewards`, e.g. set it to `Self::last_block_reward_applicable(pool_info.expiry_block)` instead of the raw `current_block_number()`, or use saturating arithmetic in `reward_per_token` so `last_update_block` can never exceed `expiry_block` once elapsed.

## Proof of Concept
1. Create a pool with `expiry_block = E` and nonzero `reward_rate_per_block`; a staker stakes tokens before `E`.
2. At block `E+1`, the staker calls `unstake` for a partial amount (allowed since `now > expiry_block`). `reward_per_token` succeeds (`old_last_update_block <= E`), and `update_pool_rewards` writes `last_update_block = E+1` to `Pools` storage.
3. At any block `now2 >= E+1`, any account calls `unstake` or `harvest_rewards` on the pool. `reward_per_token` computes `last_block_reward_applicable(E) = E`, then `E.ensure_sub(E+1)` underflows, returning `Err(ArithmeticError::Underflow)`, reverting the call. All future calls on this pool revert identically, permanently locking remaining staked/reward funds.
