### Title
Unvalidated `git_object_directory`/`git_alternate_object_directories` request fields allow cross-repository object disclosure on read-only RPCs - (File: internal/git/gitcmd/command_factory.go)

### Summary
Any ordinary, authenticated Gitaly client can set the `git_object_directory` and `git_alternate_object_directories` fields on the `Repository` message of a read-only ("Accessor") RPC to a path-traversal value (e.g. `../../other-namespace/other-repo.git/objects`). The transaction/quarantine middleware explicitly treats non-empty values in these fields as "already quarantined by a trusted internal loop-back call" and skips both transaction management and validation, and the low-level Git command factory that actually builds the `GIT_OBJECT_DIRECTORY`/`GIT_ALTERNATE_OBJECT_DIRECTORIES` environment variables performs no validation that the resulting path stays inside the target repository or even the storage. This lets a caller redirect Git object lookups into a different repository's object store.

### Finding Description
The bug-class analog to the report is a value that is supposed to only be set by a trusted step in the pipeline (there: only the `onlyOwner`/protocol-controlled auction parameters; here: only the quarantine machinery acting on behalf of the internal Rails access-check loop-back) but is actually accepted "as-is" from a less-trusted actor and used later without re-validation, corrupting an operation's expected scope.

1. `beginTransactionForRepository` inspects the incoming request and, if `GetGitObjectDirectory()` or `GetGitAlternateObjectDirectories()` are non-empty, assumes the request "was already configured with a quarantine directory ... being looped back to Gitaly from Rails' authorization checks", and for Accessor RPCs it skips starting a transaction entirely, forwarding the raw, caller-supplied repository message straight to the RPC handler: [3](#0-2) . The comment in the code itself acknowledges: "This property is violated in tests which manually configure the object directory ... This allows for circumventing the transaction management ... We'll leave this unaddressed for now."
2. `configLocator.ValidateRepository`, which is the only repository-validation step invoked before the handler runs, never inspects `GitObjectDirectory`/`GitAlternateObjectDirectories` — it only validates `StorageName` and `RelativePath` [1](#0-0) .
3. When the RPC handler eventually executes a Git command, `ExecCommandFactory.newCommand` builds the object-directory environment directly from the raw request fields with no traversal check: `env = append(alternates.Env(repoPath, repo.GetGitObjectDirectory(), repo.GetGitAlternateObjectDirectories()), env...)` [4](#0-3) .
4. `alternates.Env` simply does `filepath.Join(repoPath, objectDirectory)` for each configured directory, with no bounds checking whatsoever: [5](#0-4) .
5. The only place that does validate these fields against traversal — `Repo.ObjectDirectoryPath()`, which checks the resolved path stays within the storage and matches either the repo's own directory or an expected quarantine-directory prefix — is a separate, narrowly-used accessor, not something invoked by the generic command-execution path above: [6](#0-5) .

Because Accessor RPCs (read-only) are explicitly exempted from the "mutator" rejection (`ErrQuarantineConfiguredOnMutator`) that exists specifically to prevent this trick on writes [7](#0-6) , any caller of a read RPC (e.g. `FindCommit`, `GetBlob`, `ListRefs`, `TreeEntry`) can supply `git_object_directory`/`git_alternate_object_directories` containing `../` segments to redirect Git's object search path into a sibling repository's `objects` directory on the same storage, without ever needing an internal-API secret. Test code confirms these fields are consumed verbatim to compute env vars and directly affect what objects a read RPC can see [8](#0-7) .

### Impact Explanation
This is a cross-repository object-access / information-disclosure primitive: an unprivileged, ordinary caller of any read-only RPC can point Git's object lookup at another repository's object store within the same storage by crafting the `git_object_directory`/`git_alternate_object_directories` fields, potentially exposing blobs, commits, or trees belonging to a repository the caller has no access to. It parallels the report's core problem — a value meant to be set only in a controlled/trusted context (there, contract parameters set only pre-transaction by governance; here, quarantine paths meant to be set only by the internal loop-back after access checks) is instead accepted from an untrusted step and used to affect the outcome of an in-flight operation, with no re-validation to enforce the original invariant.

### Likelihood Explanation
The precondition is simply calling a standard Accessor RPC (no special privilege) with an attacker-chosen `Repository.git_object_directory`/`git_alternate_object_directories` value; the developers' own comment in `middleware.go` documents that this bypass is a known, currently-unaddressed gap for the transaction/quarantine model. Whether this is exploitable end-to-end for actual cross-repository disclosure depends on gRPC/Praefect-layer request validation and on whatever authorization checks occur before hitting `ValidateRepository`/`newCommand`, which I could not fully trace within the available index; I could not find any additional validation of these two fields anywhere between the gRPC entrypoint and `newCommand`.

### Recommendation
Validate `GitObjectDirectory`/`GitAlternateObjectDirectories` the same way `Repo.ObjectDirectoryPath()` already does (bounded to the storage root and either the repository's own tree or an expected quarantine-directory prefix) at the point these fields are consumed in `ExecCommandFactory.newCommand`/`alternates.Env`, not only in the rarely-invoked `ObjectDirectoryPath()` helper. Additionally, reconsider the assumption in `beginTransactionForRepository` that any non-empty object-directory field implies a trusted loop-back call — this should be authenticated via context/metadata (e.g. only allowed when a snapshot-relative-path header from an internal call is present) rather than inferred from the request payload alone.

### Proof of Concept
Uncertain / not fully verifiable from the indexed code alone: I could not confirm within the available index whether an external, non-loop-back gRPC caller (as opposed to the internal Rails access-check loop-back, which does carry the `MetadataKeySnapshotRelativePath` header) can reach a handler with these fields set without that header, since `restoreSnapshotRelativePath`/`ErrQuarantineWithoutSnapshotRelativePath` in `middleware.go` seem to require that header for the non-transactional path to succeed [9](#0-8) . This metadata header is set by Gitaly internally, but it is unclear from the index whether it is itself protected from being forged by an ordinary external client. Confirming exploitability end-to-end (i.e., whether an ordinary unprivileged client can supply this header) would require deeper tracing of the gRPC entrypoint/metadata trust boundary than the current index coverage allows — a Devin session with full repository access could trace `MetadataKeySnapshotRelativePath` usage and Praefect's request proxying to confirm this.

	}

	// the relative path are unset.

		return structerr.NewInvalidArgument("%w", storage.ErrRepositoryNotSet)
	}

	if len(relativePath) == 0 {
		return structerr.NewInvalidArgument("%w", storage.ErrRepositoryPathNotSet)

		return nil
	}

	}

// ObjectDirectoryPath returns the full path of the object directory. The errors returned are gRPC
// errors with relevant error codes and should be passed back to gRPC without further decoration.
func (repo *Repo) ObjectDirectoryPath(ctx context.Context) (string, error) {
	repoPath, err := repo.Path(ctx)
	if err != nil {
		return "", err
	}

	objectDirectoryPath := repo.GetGitObjectDirectory()
	if objectDirectoryPath == "" {
		return "", structerr.NewInvalidArgument("object directory path is not set")
	}

	storagePath, err := repo.locator.GetStorageByName(ctx, repo.GetStorageName())
	if err != nil {
		return "", fmt.Errorf("get storage by name: %w", err)
	}

	// Ensure the path points somewhere in the storage.
	relativeObjectDirectoryPath, err := storage.ValidateRelativePath(storagePath, filepath.Join(repoPath, objectDirectoryPath))
	if err != nil {
		return "", structerr.NewInvalidArgument("validate relative path: %w", err)
	}

	parentDir := filepath.Base(filepath.Dir(relativeObjectDirectoryPath))
	baseDir := filepath.Base(relativeObjectDirectoryPath)
	isTransactionQuarantineDir := (baseDir == "quarantine") || ((parentDir == "quarantine") && strings.HasPrefix(baseDir, "tmp_objdir"))

	// Transactions quarantine a repository by pointing the object directory to a 'quarantine' named
	// directory in the transaction's temporary directory. If the base directory is `quarantine`,
	// Git push may apply an additional layer of quarantine such as `/quarantine/tmp_objdir-incoming-Gbc29N`
	// so we don't assert the `/quarantine` being the last element of the path. We thus also check for
	// whether the parent directory is in `quarantine` and whether the base directory has the expected
	// `tmp_objdir` suffix.
	if !isTransactionQuarantineDir {
		// We need to check whether the relative object directory as given by the repository is
		// a valid path. This may either be a path in the Git repository itself, where it may either
		// point to the main object directory storage or to an object quarantine directory as
		// created by git-receive-pack(1). Alternatively, if that is not the case, then it may be a
		// manual object quarantine directory located in the storage's temporary directory. These
		// have a repository-specific prefix which we must check in order to determine whether the
		// quarantine directory does in fact belong to the repo at hand.
		if _, origError := storage.ValidateRelativePath(repoPath, objectDirectoryPath); origError != nil {
			tempDir, err := repo.locator.TempDir(repo.GetStorageName())
			if err != nil {
				return "", structerr.NewInvalidArgument("getting storage's temporary directory: %w", err)
			}

			expectedQuarantinePrefix := filepath.Join(tempDir, storage.QuarantineDirectoryPrefix(repo))
			absoluteObjectDirectoryPath := filepath.Join(repoPath, objectDirectoryPath)

			// The relative path is outside of the repository
			if !strings.HasPrefix(absoluteObjectDirectoryPath, expectedQuarantinePrefix) {
				return "", structerr.NewInvalidArgument("not a valid relative path: %w", origError)
			}
		}
	}

// Env returns the alternate object directory environment variables.
func Env(repoPath, objectDirectory string, alternateObjectDirectories []string) []string {
	var env []string
	if objectDirectory != "" {
		env = append(env, fmt.Sprintf("GIT_OBJECT_DIRECTORY=%s", filepath.Join(repoPath, objectDirectory)))
	}

	if len(alternateObjectDirectories) > 0 {
		var dirsList []string

		for _, dir := range alternateObjectDirectories {
			dirsList = append(dirsList, filepath.Join(repoPath, dir))
		}

		env = append(env, fmt.Sprintf("GIT_ALTERNATE_OBJECT_DIRECTORIES=%s", strings.Join(dirsList, ":")))
	}

	return env
}
