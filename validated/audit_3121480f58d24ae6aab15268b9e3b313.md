### Title
Unauthenticated `RecvError` packets allow spoofed tunnel teardown (anonymous DoS) - (File: outside.go)

### Summary
`Interface.readOutsidePackets` dispatches `header.RecvError` packets to `handleRecvError` before any certificate-based authentication or AEAD decryption is performed [1](#0-0) . `handleRecvError` then tears down the tunnel (`closeTunnel` + `handshakeManager.DeleteHostInfo`) based solely on a plaintext `RemoteIndex` lookup and a UDP source-address comparison, with no cryptographic proof that the sender is the actual authenticated peer [2](#0-1) . This mirrors the `Phantasia Sports` bug class: an action that mutates/destroys protected state (a sell order / a tunnel) is accepted without verifying that the caller is the legitimate owner (the seller / the actual remote peer holding the certificate for that tunnel).

### Finding Description
In `readOutsidePackets`, before the packet is decrypted or matched against an established, cryptographically-verified `ConnectionState`, the header type is inspected and `RecvError` packets are routed directly to `f.handleRecvError(via.UdpAddr, h)`: [1](#0-0) 

`handleRecvError` looks up the hostinfo purely by the plaintext, wire-visible `RemoteIndex` field via `QueryReverseIndex`, and the only anti-spoofing control is a comparison of the packet's source `netip.AddrPort` against the hostinfo's currently known remote address: [3](#0-2) 

If that check passes (or if `hr.IsValid()` is false, e.g. before a remote address has been learned/confirmed), the function immediately calls `f.closeTunnel(hostinfo)` and `f.handshakeManager.DeleteHostInfo(hostinfo)`, unconditionally tearing down the tunnel: [4](#0-3) 

Unlike the `Message`, `LightHouse`, `Test`, and `CloseTunnel` message types — which are only processed *after* `hostinfo.ConnectionState.Decrypt` succeeds (i.e., after AEAD-authenticated proof the sender holds the peer's negotiated Noise keys) [5](#0-4)  — `RecvError` bypasses that authenticated pathway entirely. The `RemoteIndex` used to key the lookup travels in the cleartext header of every packet on the wire, so it is observable to any on-path/eavesdropping attacker, and the "spoof check" relies only on comparing the (easily spoofable) UDP source `IP:port`, not a certificate or MAC.

This is the direct analog of the reported `CancelNftSale`/`CancelEditionSale` bug: an action that destroys existing, legitimately-established state ("cancel my order" / "the tunnel I own is dead, teardown") is accepted from an unauthenticated party — the requester's *identity* is never cryptographically verified, only a coarse, forgeable attribute (the UDP source address) is checked.

### Impact Explanation
An attacker who can observe a victim's `RemoteIndex` (e.g., by sniffing traffic on a shared/wireless network segment, being on-path, or controlling infrastructure between the two peers) and who can spoof UDP packets with the source address of one of the two legitimate tunnel endpoints can force `closeTunnel` on the other endpoint, destroying the encrypted session state without any certificate/PKI validation. Repeated across all sessions this becomes a denial-of-service against the mesh: any node whose `RemoteIndex`/address pairing is known can have every one of its tunnels torn down on demand, exactly analogous to the "cancel all sell orders" DoS described in the report.

### Likelihood Explanation
The `RemoteIndex` is transmitted unencrypted in every packet, so it is trivially observable to anyone able to see traffic on the path (on-path attacker, compromised router/AP, malicious relay/lighthouse infrastructure member, or an attacker capable of IP spoofing where egress filtering is weak/absent — common on many networks and easily achieved between UDP peers without return-routability enforcement). No certificate, handshake completion, or possession of any Nebula key material is required to mount the attack, making this a low-effort, reliably reachable primitive by design (`listen.accept_recv_error` defaults to `"always"`) [6](#0-5) .

### Recommendation
Do not act on `RecvError` (or any pre-authentication signal) as sufficient grounds to tear down an established, authenticated tunnel. At minimum:
- Require some additional proof of authorization before closing a live tunnel in response to `RecvError` (e.g., only accept it while still in a pending/negotiating state, or require it to be authenticated similarly to `CloseTunnel`, which is only honored after AEAD decryption succeeds).
- Strengthen or replace the address-equality check with a scheme that cannot be satisfied merely by UDP source spoofing (e.g., rate-limit/require corroborating traffic loss signals locally rather than trusting a single unauthenticated remote packet).

### Proof of Concept
1. Establish two Nebula peers, A and B, with a live tunnel (matching the setup used in `TestCloseTunnelAuthenticated`) [7](#0-6) .
2. As a third party (attacker) able to observe or infer B's `RemoteIndex` for the A↔B tunnel and spoof UDP packets appearing to originate from A's current `CurrentRemote` address, craft a header with `Type = header.RecvError` and `RemoteIndex` set to B's index for that hostinfo, and send it to B.
3. `readOutsidePackets` routes it directly to `handleRecvError` prior to any decryption [8](#0-7) ; the address check passes because the spoofed source matches A's known remote, and B calls `closeTunnel`/`DeleteHostInfo`, destroying the tunnel state without any cryptographic verification of the sender [9](#0-8) .

func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
