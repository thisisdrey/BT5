### Title
Signer event-receiver HTTP endpoints accept unauthenticated POSTs, allowing any local/network caller to inject forged StackerDB/block-validation/burn-block events - (File: `libsigner/src/events.rs`)

### Summary
The `SignerEventReceiver::next_event` implementation dispatches any HTTP POST to `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, and `/new_block` straight into `process_event`, with no check of an authentication token or any other credential tied to the sender. `auth_token` is documented and configured on the node side (`connection_options.auth_token` in sample configs) as the mechanism meant to gate who may push events to a signer, but the receiver code that actually accepts these events never verifies it.

### Finding Description
`EventReceiver::next_event` in `libsigner/src/events.rs` reads the incoming HTTP request, checks only the URL path and HTTP method, and then unconditionally calls `process_event::<T, E>(request)` for the recognized endpoints: [1](#0-0) 

`process_event` reads the raw body, ACKs the request, and deserializes it directly into a `SignerEvent`: [2](#0-1) 

There is no header inspection, no shared-secret comparison, and no peer-identity check anywhere in this file or in `bind()`, which simply opens an `HttpServer` on the configured socket: [3](#0-2) 

Meanwhile, node-side sample configuration documents `auth_token` as the authentication mechanism protecting the `events_observer` → signer channel (`connection_options.auth_token` must match the signer's expected value), implying an authenticated relationship is expected: [4](#0-3) 

A `grep` across `libsigner/**` for `auth_token`/`Authorization` returns no matches at all — confirming the receiver-side code contains no logic to validate any credential, i.e., the "auth gate" that operators are led to configure via `auth_token` fails open on the signer's event-receiver side. This is the direct analog of the reported bug class: an equality/validation that is expected to exist (here: request-must-be-authenticated) is never actually enforced, and the path is remotely reachable and unprivileged for anyone who can reach the bound socket.

### Impact Explanation
Any party capable of sending a TCP connection to the signer's event-listener socket (the address configured under `[[events_observer]] endpoint`) can POST directly to `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, or `/new_block` and have it accepted as if it came from the trusted `stacks-node`. This lets an attacker:
- Inject a forged `StackerDBChunksEvent`, which is converted into `SignerEvent::MinerMessages`/`SignerEvent::SignerMessages` and fed straight into the signer's `run_one_pass` decision logic.
- Inject a forged `BlockValidateResponse`, `BurnBlockEvent`, or `StacksBlockEvent`, influencing the signer's view of the chain/burnchain state.

Given that signer decisions ultimately affect block signing/voting, an unauthenticated write into this channel is a serious integrity concern for any deployment where the bind address is not strictly firewalled to loopback-only, e.g. containerized/dockerized signer deployments where `0.0.0.0` binding is common, or misconfigured environments trusting `auth_token` to provide the isolation that the code doesn't implement. This matches the "unauthenticated/unauthorized write to state" and "forged data propagated / consumed by signer" impact class.

### Likelihood Explanation
Likelihood is moderate: exploitation requires the attacker to have network access to the signer's event-receiver bind address. In many recommended deployments this is `127.0.0.1`, which limits exposure to local processes. However, the code itself provides zero enforcement — it is entirely deployment/config dependent whether this is exploitable remotely, and the documented `auth_token` setting creates a false expectation of protection that the current `libsigner/src/events.rs` code does not implement. Any operator relying on `auth_token` alone (without additional network-layer firewalling) is effectively unprotected.

### Recommendation
- Implement authentication in `SignerEventReceiver::next_event` (or in the underlying `HttpServer` request handling) that validates an `Authorization`/token header against the configured `auth_token` before routing to `process_event`.
- Reject requests lacking a valid credential with an appropriate HTTP error status rather than silently ACKing/processing them.
- Ensure the `auth_token` value referenced in `stacks-signer/src/config.rs` and sample configs is actually wired through into the `libsigner` event-receiver bind/handling path, not left as a documentation-only convention enforced solely on the sender.

### Proof of Concept
1. Stand up a signer with `SignerEventReceiver::bind` listening on a reachable address (e.g., `0.0.0.0:30000` in a container/cloud deployment).
2. From any other host that can reach that port, craft an HTTP POST to `/stackerdb_chunks` with a JSON body matching `StackerDBChunksEvent`, containing an attacker-chosen `contract_id` (e.g., a `signers-X-Y` boot contract) and one or more `modified_slots` chunk entries (signature does not need to verify against the real signer set for it simply to be accepted by the HTTP layer and passed into `TryFrom<StackerDBChunksEvent> for SignerEvent<T>` — downstream signature checks in `try_from` filter individual chunks, but the network-level request itself required no credential check to reach that point).
3. Observe that the request is accepted (`ack_dispatcher` responds 200) and forwarded into the signer's event channel via `forward_event`, with no `Authorization`/`auth_token` verification anywhere in `libsigner/src/events.rs`, confirming the auth gate fails open at the transport layer regardless of downstream per-chunk signature checks.

```rust
    fn next_event(&mut self) -> Result<SignerEvent<T>, EventError> {
        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)
            } else if request.url() == "/new_block" {
                process_event::<T, StacksBlockEvent>(request)
            } else {
                let url = request.url().to_string();
                debug!(
                    "[{:?}] next_event got request with unexpected url {}, return OK so other side doesn't keep sending this",
                    event_receiver.local_addr,
                    url
                );
                ack_dispatcher(request);
                Err(EventError::UnrecognizedEvent(url))
            }
        })?
```

```rust
fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}
```
