### Title
A single reverting collateral or debt oracle blocks withdrawals from every other position token - ([File: contracts/Pool.sol])

### Summary
`DepositToken.withdraw()` always calls `Pool.debtPositionOf()` before burning and releasing collateral, even when the caller has no debt. [1](#0-0)  `debtPositionOf()` iterates over every deposit and debt token held by the account and performs an external oracle quote for each one. [2](#0-1)  If one supported asset’s oracle quote reverts, withdrawals of every other collateral held by that account revert as well. [3](#0-2) 

### Finding Description
`unlockedBalanceOf()` calls `debtPositionOf(account_)` unconditionally before determining the withdrawable balance. [4](#0-3)  `debtPositionOf()` calls `debtOf()` and `depositOf()`, which enumerate `debtTokensOfAccount` and `depositTokensOfAccount` and query `masterOracle` for every entry. [2](#0-1)  The subsequent `_withdraw()` call has no per-asset oracle fallback or exclusion mechanism, and the token must remain registered while its supply is non-zero. [5](#0-4) [6](#0-5) 

### Impact Explanation
A user holding collateral A and collateral B cannot withdraw A when B’s external price source reverts, because the withdrawal path prices B before permitting any withdrawal. [7](#0-6)  This can temporarily freeze collateral while an upstream feed, oracle adapter, or underlying asset integration is unavailable, and it can become effectively permanent if the integration cannot be restored and governance cannot migrate the oracle. [8](#0-7) 

### Likelihood Explanation
The path is reachable through ordinary public withdrawals and does not require a privileged actor to trigger once an external quote dependency becomes unavailable. [7](#0-6)  Withdrawals are intentionally allowed while the pool is paused, so the pause flags do not provide an emergency exit. [9](#0-8) 

### Recommendation
Avoid requiring a healthy quote for unrelated assets when the account has no debt, or add a bounded exclusion/fallback mechanism for unavailable assets. [4](#0-3)  In particular, return the full balance before calling `debtPositionOf()` when a debt-free path can be established without enumerating every oracle, and consider a governed asset exclusion that does not require the affected token’s supply to be zero. [10](#0-9) [6](#0-5) 

### Proof of Concept
A Foundry fork test can deposit two supported collaterals for the same account, make `masterOracle.quoteTokenToUsd` revert only for the second collateral, and then demonstrate that `withdraw()` for the first collateral also reverts. [10](#0-9) 

```solidity
function testPausedOracleBlocksOtherCollateralWithdrawal() external {
    // Existing fork fixtures:
    // - pool is registered in PoolRegistry
    // - collateralA and collateralB both have registered DepositTokens
    // - alice holds unlocked balances of both deposit tokens
    // - alice has no debt

    address collateralA = address(depositTokenA.underlying());
    address collateralB = address(depositTokenB.underlying());
    address oracle = address(pool.masterOracle());

    vm.mockCallRevert(
        oracle,
        abi.encodeWithSelector(
            IMasterOracle.quoteTokenToUsd.selector,
            collateralB,
            depositTokenB.balanceOf(alice)
        ),
        "ORACLE_PAUSED"
    );

    uint256 amount = depositTokenA.balanceOf(alice);

    vm.prank(alice);
    vm.expectRevert("ORACLE_PAUSED");
    depositTokenA.withdraw(amount, alice);
}
```
