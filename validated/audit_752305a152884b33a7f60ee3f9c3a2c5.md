### Title
Cross-StackerDB replay of validly-signed chunks due to signature not binding the contract identity - (File: `libstackerdb/src/libstackerdb.rs`)

### Summary
`SlotMetadata`'s signed digest (`auth_digest`) covers only `slot_id`, `slot_version`, and `data_hash` — it never binds the signature to the specific StackerDB contract (`QualifiedContractIdentifier`) the chunk was intended for. `StackerDBTx::try_replace_chunk` and `PeerNetwork::validate_received_chunk` authenticate a chunk purely by recovering the signer address from this digest and matching it against the configured slot owner for whichever contract the write request is aimed at. There is no check that the chunk was actually produced/authorized for *that* contract. <cite repo="Loderfordw/stacks-core--015" path="libstackerdb/src/libstackerdb.rs" start="159="/> [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
This is the network-layer analog of the reserve-protocol bug: an "equality" check that is too narrow to capture the full authorization context, allowing an attacker to feed data through a validation gate that was never intended for that destination. In the RToken bug, redemption checked collateralization/backing but not whether the specific backing token was the *legitimate* one for that redemption path; here, chunk storage checks "is this signed by *a* valid slot owner" but not "was this chunk signed *for this StackerDB*".

Concretely:
- `SlotMetadata::auth_digest` hashes `slot_id.to_be_bytes() || slot_version.to_be_bytes() || data_hash.0` only. [1](#0-0) 
- `SlotMetadata::verify` recovers the public key from that digest and only checks that the recovered `Hash160` equals the `principal` passed in by the caller — it has no knowledge of, or binding to, which StackerDB contract the caller believes it is validating for. [4](#0-3) 
- `StackerDBTx::try_replace_chunk` looks up `slot_validation.signer` from the specific `smart_contract` being written to, then calls `slot_desc.verify(&slot_validation.signer)`. It never confirms the signature commits to `smart_contract` itself. [5](#0-4) 
- `PeerNetwork::validate_received_chunk` follows the identical pattern for network-received chunks (both downloaded and pushed): it fetches `get_slot_signer(smart_contract_id, data.slot_id)` and calls `slot_metadata.verify(&addr)`, again with no contract binding in the signed material. [3](#0-2) 

Because the same signer key/address is routinely configured as a slot owner across *multiple concurrently-active* StackerDB contracts (e.g. the rotating `signers-0-xxx.clar` / `signers-1-xxx.clar` contracts used per reward cycle, where the same signer set is reused), a chunk that a signer legitimately signs and broadcasts for slot `N`, version `V` in contract `A` is *also* a valid, fully-authenticated chunk for slot `N`, version `V` in contract `B`, as long as the attacker can get that same `slot_id`/`slot_version`/`data` combination accepted as "new" in `B` (i.e. `slot_desc.slot_version > slot_validation.version` in `B`). Any unprivileged network observer who watches gossip (StackerDB chunk push/replication is by design broadcast to all replicas) can capture such a chunk and replay it — unmodified — into the sibling contract via `StackerDBPushChunkData` or by serving it during a sync round, without needing the signer's private key at all.

### Impact Explanation
This breaks the "authenticated vs. intended-destination" equality that StackerDB storage is supposed to enforce: unauthenticated/unauthorized write to a different StackerDB contract's state using another party's genuinely-signed, but misattributed, data. Depending on what data model consumers of that StackerDB assume (e.g., signer message contracts consumed by `stacks-signer`), this can inject forged-looking-but-technically-"valid" application data into the wrong contract's slot, and that data will then propagate network-wide via normal StackerDB replication (`make_StackerDBChunksInv_or_Nack` / sync), since downstream peers will also accept it under the same verification logic. This matches the "network-wide propagation of forged data" / "unauthenticated/unauthorized write to StackerDB" severity band.

### Likelihood Explanation
Requires no privileged access: an attacker only needs to observe a legitimately broadcast chunk from a signer (chunks are gossiped in the clear as part of normal StackerDB operation) and re-submit it (via `StackerDBPushChunk`) to a sibling contract where the same signer address happens to own the identically-numbered slot with a lower stored version. The precondition (same signer address active in slot `N` across sibling/rotating StackerDB contracts of the same signer-set epoch) is a normal, expected deployment configuration rather than an edge case, so likelihood is moderate-to-high wherever that configuration recurs.

### Recommendation
Include the target `QualifiedContractIdentifier` (and ideally the StackerDB's config/version epoch) in the signed digest, i.e. extend `SlotMetadata::auth_digest` to hash the contract identifier bytes alongside `slot_id`, `slot_version`, and `data_hash`, and thread the contract identifier into `sign`/`verify` calls. This forces every accepted chunk's signature to commit to the specific StackerDB it was authored for, closing the cross-contract replay path in `StackerDBTx::try_replace_chunk` and `PeerNetwork::validate_received_chunk`.

### Proof of Concept
1. Signer `S` is a configured slot owner for slot `0` in both StackerDB contract `A` (`signers-0-xxx`) and contract `B` (`signers-1-xxx`) for the same reward-cycle epoch (a normal configuration where the same signer set backs both rotating contracts).
2. `S` legitimately produces and signs `StackerDBChunkData { slot_id: 0, slot_version: 5, data, sig }` for contract `A`; this is broadcast over the P2P network as part of ordinary StackerDB replication.
3. Attacker (any peer) observes this chunk on the wire.
4. Attacker crafts a `StackerDBPushChunkData { contract_id: B, rc_consensus_hash, chunk_data: <same slot_id, slot_version, sig, data as captured> }` and sends it to a node that replicates `B`.
5. Because `B`'s stored version for slot `0` is `< 5`, and `slot_metadata.verify(&addr_for_slot_0_in_B)` succeeds (same `S`, same digest bytes — contract identity was never part of what was signed), `validate_received_chunk`/`try_replace_chunk` accept the chunk into `B`, even though `S` never signed anything for `B`.     /// Get the digest to sign that authenticates this chunk data and metadata
    fn auth_digest(&self) -> Sha512Trunc256Sum {
        let mut hasher = Sha512_256::new();
        hasher.update(self.slot_id.to_be_bytes());
        hasher.update(self.slot_version.to_be_bytes());
        hasher.update(self.data_hash.0);
        Sha512Trunc256Sum::from_hasher(hasher)
    }

    /// Verify that a given principal signed this chunk metadata.
    /// Note that the address version is ignored.
    pub fn verify(&self, principal: &StacksAddress) -> Result<bool, Error> {
        let sigh = self.auth_digest();
        let pubk = StacksPublicKey::recover_to_pubkey_without_validating_low_s(
            sigh.as_bytes(),
            &self.signature,
        )
        .map_err(|ve| Error::VerifyingError(ve.to_string()))?;

        let pubkh = Hash160::from_node_public_key(&pubk);
        Ok(pubkh == *principal.bytes())
    }

    /// Add or replace a chunk for a given reward cycle, if it is valid
    /// Otherwise, this errors out with Error::StaleChunk
    pub fn try_replace_chunk(
        &self,
        smart_contract: &QualifiedContractIdentifier,
        slot_desc: &SlotMetadata,
        chunk: &[u8],
    ) -> Result<(), net_error> {
        // Check per-replica chunk-size cap.
        if (chunk.len() as u64) > self.config.chunk_size {
            return Err(net_error::StackerDBChunkTooBig(chunk.len()));
        }

        let slot_validation = self
            .get_slot_validation(smart_contract, slot_desc.slot_id)?
            .ok_or(net_error::NoSuchSlot(
                smart_contract.clone(),
                slot_desc.slot_id,
            ))?;

        if !slot_desc.verify(&slot_validation.signer)? {
            return Err(net_error::BadSlotSigner(
                slot_validation.signer,
                slot_desc.slot_id,
            ));
        }
        if slot_desc.slot_version <= slot_validation.version {
            return Err(net_error::StaleChunk {
                supplied_version: slot_desc.slot_version,
                latest_version: slot_validation.version,
            });
        }
        if slot_desc.slot_version > self.config.max_writes {
            return Err(net_error::TooManySlotWrites {
                supplied_version: slot_desc.slot_version,
                latest_version: slot_validation.version,
                max_writes: self.config.max_writes,
            });
        }
        self.insert_chunk(smart_contract, slot_desc, chunk)
    }

    pub fn validate_received_chunk(
        &self,
        smart_contract_id: &QualifiedContractIdentifier,
        config: &StackerDBConfig,
        data: &StackerDBChunkData,
        expected_versions: &[u32],
    ) -> Result<bool, net_error> {
        // validate -- must not exceed this replica's configured chunk size.
        if (data.data.len() as u64) > config.chunk_size {
            info!(
                "Received StackerDBChunk for {} ID {}, which is oversized: {} bytes (max {} bytes)",
                smart_contract_id,
                data.slot_id,
                data.data.len(),
                config.chunk_size
            );
            return Ok(false);
        }

        // validate -- must be a valid chunk
        let Some(expected_version) = expected_versions.get(data.slot_id as usize) else {
            info!(
                "Received StackerDBChunk for {} ID {}, which is too big ({})",
                smart_contract_id,
                data.slot_id,
                expected_versions.len()
            );
            return Ok(false);
        };

        // validate -- must be signed by the expected author
        let addr = match self
            .stackerdbs
            .get_slot_signer(smart_contract_id, data.slot_id)?
        {
            Some(addr) => addr,
            None => {
                return Ok(false);
            }
        };

        let slot_metadata = data.get_slot_metadata();
        if !slot_metadata.verify(&addr)? {
            info!(
                "StackerDBChunk for {} ID {} is not signed by {}",
                smart_contract_id, data.slot_id, &addr
            );
            return Ok(false);
        }

        // validate -- must be the current or newer version
        if data.slot_version < *expected_version {
            info!(
                "Received StackerDBChunk for {} ID {} version {}, which is stale (expected {})",
                smart_contract_id, data.slot_id, data.slot_version, *expected_version
            );
            return Ok(false);
        }

        // validate -- must not exceed max writes
        if data.slot_version > config.max_writes {
            info!(
                "Write count exceeded for StackerDBChunk for {} ID {} version {} (max is {})",
                smart_contract_id, data.slot_id, data.slot_version, config.max_writes
            );
            return Ok(false);
        }

        Ok(true)
    }
