## Finding

### Title
Fixed-window stream throttle in QUIC streamer permits sustained rate-limit evasion via boundary bursting - (File: `streamer/src/nonblocking/stream_throttle.rs`)

### Summary
The QUIC stream throttling mechanism enforces `max_streams_per_throttling_interval` by comparing a stream counter to the value it had at the last full reset, rather than tracking streams against a continuous, sliding measure of load. Because the reset is a hard, periodic snapshot (like `updateWeights()` in the reported analog), a peer can time bursts around each reset boundary to sustain roughly double the intended per-connection stream rate indefinitely, without ever appearing to violate the limit in any single window.

### Finding Description
`ConnectionStreamCounter::reset_throttling_params_if_needed()` only resets `stream_count` to 0 when more than `STREAM_THROTTLING_INTERVAL` (100ms) has elapsed since `last_throttling_instant`: [1](#0-0) 

`throttle_stream()` then only checks the counter against the threshold relative to that last reset point: [2](#0-1) 

This is the same structural flaw as the reported `_isDepegged()` bug: the enforcement check measures deviation only from the last discrete "checkpoint" (`last_throttling_instant` / `stream_count`), not the true continuous rate of stream creation relative to a fixed benchmark. A peer that opens `max_streams_per_throttling_interval` streams just before a window boundary, then immediately opens another full batch just after the reset, can push close to `2x max_streams_per_throttling_interval` streams within a very short real-time span while each individual window "check" reports compliance. Because the reset zeroes the counter unconditionally rather than decaying/sliding, this bypass can be repeated at every 100ms boundary, producing a sustained ~2x rate-limit evasion, not just a single burst.

This function is invoked from `SwQos::on_new_stream()` for every accepted QUIC stream regardless of peer stake, so it is reachable by any unprivileged/unstaked or low-stake peer connecting to the TPU QUIC streamer: [3](#0-2) 

### Impact Explanation
This enables QoS evasion in the QUIC streamer: an unprivileged peer can consistently exceed the server's configured `max_streams_per_ms`/`STAKED`/`UNSTAKED` throttling budgets by exploiting the fixed-window boundary, increasing CPU/packet-processing load imposed on the validator beyond what the QoS design intends, without violating any single window's accounting.

### Likelihood Explanation
Exploitation only requires precise timing of stream creation relative to a 100ms wall-clock boundary, something a scripted/automated QUIC client can reliably achieve; no special stake or privileges are required, and the code path is on the hot ingestion path for every incoming transaction stream.

### Recommendation
Replace the hard reset-to-zero fixed window with a sliding window or token-bucket style accounting (as already used elsewhere in the codebase, e.g. `net_utils::token_bucket::TokenBucket`) so that the throttling decision reflects a continuously decaying measure of recent stream creation rather than resetting entirely at each interval boundary.

### Proof of Concept
1. Establish a QUIC connection as an unstaked (or low-stake) peer to the TPU QUIC port.
2. At time `t = 99ms` (just before a `STREAM_THROTTLING_INTERVAL` boundary since connection/last reset), open `max_streams_per_throttling_interval` unidirectional streams — `throttle_stream()` allows all of them since the counter starts at 0 for this window.
3. At time `t = 101ms`, `reset_throttling_params_if_needed()` resets `stream_count` to 0 because more than 100ms has elapsed. Immediately open another full batch of `max_streams_per_throttling_interval` streams.
4. Repeat every ~100ms window boundary: the peer sustains roughly double the intended stream rate indefinitely while both `throttle_stream()` checks individually report compliance.

    pub(crate) fn reset_throttling_params_if_needed(&self) -> tokio::time::Instant {
        let last_throttling_instant = *self.last_throttling_instant.read().unwrap();
        if tokio::time::Instant::now().duration_since(last_throttling_instant)
            > STREAM_THROTTLING_INTERVAL
        {
            let mut last_throttling_instant = self.last_throttling_instant.write().unwrap();
            // Recheck as some other thread might have done throttling since this thread tried to acquire the write lock.
            if tokio::time::Instant::now().duration_since(*last_throttling_instant)
                > STREAM_THROTTLING_INTERVAL
            {
                *last_throttling_instant = tokio::time::Instant::now();
                self.stream_count.store(0, Ordering::Relaxed);
            }
            *last_throttling_instant
        } else {
            last_throttling_instant
        }
    }
