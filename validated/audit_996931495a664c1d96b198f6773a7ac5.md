### Title
Nebula installs OS-level Windows Firewall (WDF) bypass filters and downgrades the network category by default, violating least privilege - ([File: overlay/tun_windows.go], [File: udp/udp_bypass_windows.go], [File: wfp/wfp_windows.go])

### Summary
On Windows, Nebula's tun device and UDP listener install WFP `PERMIT` filters that sit below (and override) Windows Defender Firewall (WDF), and the tun device is placed into the `private` network category — both enabled **by default**, without the operator opting in. This mirrors the reported class of bug (superfluous/overly-broad default permissions expanding the attack surface beyond what the component actually needs), except here the "permission" is a host firewall bypass rather than a snap manifest capability.

### Finding Description
`newTun` reads `tun.windows_bypass_wdf` with a default of `true` and `tun.network_category` with a default of `"private"`: [1](#0-0) 

When the adapter activates, if `bypassWDF` is set it calls `installInterfaceBypass`, which installs a WFP `PERMIT` filter scoped to the wintun interface LUID at `FWPM_LAYER_ALE_AUTH_RECV_ACCEPT_V4/V6`: [2](#0-1) 

The same pattern applies to the UDP listener: `NewListener` always wraps the connection with `wrapWithWDFBypass`, which — unless `listen.windows_bypass_wdf` is explicitly set to `false` — installs a `PERMIT` filter for the bound UDP port: [3](#0-2) [4](#0-3) 

Critically, these filters are installed with `FWPM_FILTER_FLAG_CLEAR_ACTION_RIGHT`, which the code explicitly documents as necessary because WDF's own block rules share the same sublayer weight and would otherwise be able to override the bypass — i.e., the bypass is engineered to win over any WDF block rule at the same priority: [5](#0-4) 

In addition, the tun adapter's network category is changed from whatever Windows assigned (usually `Public`, which is more restrictive) to `Private` by default, again requiring an explicit opt-out (`tun.network_category: unset`): [6](#0-5) 

This is acknowledged as a breaking, security-relevant behavior change in the changelog: [7](#0-6) 

Both mechanisms are installed unconditionally at startup for every Windows deployment, independent of any peer authentication, CA-signed certificate, or handshake state — an unauthenticated network attacker who can reach the host's UDP listener port or the wintun interface benefits from these default relaxations without needing any Nebula credential.

### Impact Explanation
The bypass filters are functionally equivalent to a firewall-enforcement bypass: they unconditionally override the host operating system's firewall (WDF) for the nebula adapter and listener port, and the private network category further relaxes the host firewall profile applied to the overlay. Operators who rely on WDF policy (endpoint security baselines, group policy firewall rules, EDR-managed rules) to restrict traffic to the nebula UDP port or adapter have that protection silently overridden the moment Nebula starts, by default, with no explicit administrator consent. Since Nebula's own userspace firewall (`firewall.go`) is the only remaining layer of defense at that point, any bug or misconfiguration in Nebula's firewall rules (or a `firewall.outbound_action`/`inbound_action` misconfiguration, or before certs/handshakes establish state) is no longer backstopped by the OS firewall as it would be for other Windows applications. This is a concrete firewall-bypass condition reachable by any network attacker who can send traffic to the exposed UDP port or interface, without holding a CA-signed certificate.

### Likelihood Explanation
High. No attacker action beyond default installation/operation of Nebula on Windows is required — the filters are installed automatically on every startup and every listener reload unless an administrator explicitly opts out via `tun.windows_bypass_wdf: false`, `listen.windows_bypass_wdf: false`, and `tun.network_category: unset`. Most operators upgrading will not be aware of this change unless they read the breaking-changes changelog entry.

### Recommendation
Apply the principle of least privilege: default `tun.windows_bypass_wdf` and `listen.windows_bypass_wdf` to `false`, and default `tun.network_category` to `unset`, requiring explicit administrator opt-in for any deployment that actually needs the WDF bypass or a relaxed network category. At minimum, emit a prominent one-time warning at startup when these bypasses are active so operators are aware their host firewall's rules for the nebula adapter/port are being overridden.

### Proof of Concept
1. Install Nebula on a Windows host with default configuration (no `tun.windows_bypass_wdf`, `listen.windows_bypass_wdf`, or `tun.network_category` set).
2. Configure a Windows Defender Firewall rule that blocks inbound UDP traffic to the Nebula listener port (or to the wintun adapter) — simulating an administrator's intended host-level restriction.
3. Start Nebula; observe log lines "Installed WFP filters bypassing Windows Defender Firewall on nebula interface" / "...on UDP listener port" as emitted by `installInterfaceBypass` and `wrapWithWDFBypass`.
4. Send UDP traffic from an external host to the listener port; observe that it reaches Nebula's userspace processing despite the WDF block rule, demonstrating the OS firewall is bypassed by default.

```go
// installInterfaceBypass installs a WFP PERMIT filter scoped to the wintun interface LUID so inbound traffic on the
// nebula adapter bypasses Windows Defender Firewall.
func installInterfaceBypass(l *slog.Logger, luid uint64) closer {
	s, err := wfp.PermitInterface(luid)
	if err != nil {
		l.Warn("Failed to install WFP bypass filters on nebula interface", "error", err)
		return nil
	}
	l.Info("Installed WFP filters bypassing Windows Defender Firewall on nebula interface")
	return s
}
```

```go
// parseNetworkCategory accepts the user-supplied tun.network_category. A
// second return of false means "leave the category alone".
func parseNetworkCategory(s string) (networkCategory, bool, error) {
	switch strings.ToLower(strings.TrimSpace(s)) {
	case "", "unset":
		return 0, false, nil
	case "public":
		return networkCategoryPublic, true, nil
	case "private":
		return networkCategoryPrivate, true, nil
	case "domain", "domainauthenticated":
		return networkCategoryDomainAuthenticated, true, nil
	}
	return 0, false, fmt.Errorf("unknown tun.network_category %q (expected public, private, domain, or unset)", s)
}
```
