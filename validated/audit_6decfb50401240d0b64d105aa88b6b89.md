### Title
`remove_account` leaves 8 account-scoped `TrieKey` variants (`ReceivedData`, `PostponedReceiptId`, `PendingDataCount`, `PostponedReceipt`, `PromiseYieldReceipt`, `PromiseYieldStatus`, `YieldIdToDataId`, `DataIdToYieldId`) un-erased, allowing state to survive `DeleteAccount` and be inherited by a same-name account recreation - (File: `core/store/src/utils/mod.rs`)

### Finding Description
`TrieKey::get_account_id()` marks 12 variants as account-scoped (returns `Some(account_id)`): `Account`, `ContractCode`, `AccessKey`, `GasKeyNonce`, `ReceivedData`, `PostponedReceiptId`, `PendingDataCount`, `PostponedReceipt`, `ContractData`, `PromiseYieldReceipt`, `PromiseYieldStatus`, `YieldIdToDataId`, `DataIdToYieldId` [1](#0-0) .

`remove_account` only removes `Account`, `ContractCode`, `AccessKey`/`GasKeyNonce` (via the access-key prefix iteration), and `ContractData` [2](#0-1) . It never scans or removes the `ReceivedData`, `PostponedReceiptId`, `PendingDataCount`, `PostponedReceipt`, `PromiseYieldReceipt`, `PromiseYieldStatus`, `YieldIdToDataId`, or `DataIdToYieldId` prefixes for the account, even though these carry the same account_id in their trie key encoding (as confirmed by their `get_account_id()` mapping and their key-serialization code that embeds `receiver_id`) [3](#0-2) .

`remove_account` is invoked from `action_delete_account`, which is reachable by an ordinary account owner submitting a `DeleteAccount` action (no privileged role required) [4](#0-3) , dispatched from the generic action-application switch [5](#0-4) .

Exploit flow: an attacker sends itself (or has in-flight) an action receipt with an unresolved input-data dependency, causing a `PostponedReceipt` + `PendingDataCount` + partial `ReceivedData` rows to be written under its own `account_id` while a companion piece of data is still outstanding. The attacker then deletes its account via `DeleteAccount`. `remove_account` clears the account/keys/code/contract-data but leaves the `PostponedReceipt`, `PendingDataCount`, and any `ReceivedData` rows for that account_id in the trie untouched. If a NEAR account name is later reused (accounts are permissionless to (re)create by name once free), the newly created account under the same name inherits this orphaned state: when the still-outstanding data input eventually arrives (or if `PendingDataCount` was already at/near zero), the postponed action receipt referencing the old account's actions can fire and execute against the new (differently-owned) account, or otherwise the trie retains dead data that a fresh account never explicitly wrote or authorized. Similarly, `PromiseYieldReceipt`/`PromiseYieldStatus`/`YieldIdToDataId`/`DataIdToYieldId` rows for yield/resume flows survive account deletion and can resolve against a recreated account of the same name.

None of the existing checks in `action_delete_account` (storage-usage cap, gas-key balance cap, `check_actor_permissions`) inspect or clean these 8 column ranges, so nothing currently stops this state leak.

### Impact Explanation
This is a violation of value/state conservation for account-scoped cleanup: the "writer set" (12 variants) is larger than the "cleaner set" (4 constructors) in `remove_account`. The scoped, concretely demonstrable impact is state keyed by a deleted account name persisting and being inherited by a name reuse — orphaned `PostponedReceipt`/`PendingDataCount`/`ReceivedData`/`PromiseYieldReceipt`/`PromiseYieldStatus`/`YieldIdToDataId`/`DataIdToYieldId`/`PostponedReceiptId` rows remain reachable under the same trie prefix after deletion. This falls in the "authorization escalation across accounts or promises" bounty category in the specific case where a postponed/yield receipt created by the pre-deletion account owner can later be resolved and executed against the differently-owned recreated account, and more generally is a state-hygiene/data-integrity defect (permanent unremovable trie growth tied to reused account names) that a full test-loop / unit reproduction can prove deterministically.

### Likelihood Explanation
No special privileges are needed — only a `CreateAccount`, a self-receipt with an unresolved data dependency (e.g. a yield/resume or cross-contract call with an `input_data_ids` entry that is never satisfied before deletion), and a `DeleteAccount` action, all of which an ordinary funded account can submit. The precondition of "account name gets reused" depends on someone (possibly the same attacker) recreating an account with the identical name, which is normal permissionless account creation in NEAR. The bug is deterministically reproducible via a `TrieUpdate`-only unit test with no dependency on validator/network timing.

### Recommendation
Extend `remove_account` in `core/store/src/utils/mod.rs` to also iterate and remove the raw-prefix ranges for `ReceivedData`, `PostponedReceiptId`, `PendingDataCount`, `PostponedReceipt`, `PromiseYieldReceipt`, `PromiseYieldStatus`, `YieldIdToDataId`, and `DataIdToYieldId` for the given `account_id`, mirroring the existing `ContractData`/access-key prefix-scan-and-remove pattern, so that the full set of `TrieKey` variants for which `get_account_id()` returns `Some` is torn down atomically with account deletion. Consider adding a debug-time invariant/test (e.g. in `core/store/src/utils/mod.rs`) that asserts, for every variant in `col::COLUMNS_WITH_ACCOUNT_ID_IN_KEY`, that after `remove_account` no residual keys with that account_id remain in the trie, to prevent regressions when new account-scoped `TrieKey` variants are added in the future.

### Proof of Concept
1. In `core/store/src/utils/mod.rs` tests (or a new test module), build a `TrieUpdate` via `TestTriesBuilder`.
2. For a fixed `account_id`, write one row of each of the 12 `col::COLUMNS_WITH_ACCOUNT_ID_IN_KEY` variants: `Account`, `ContractCode`, `AccessKey`, `ReceivedData`, `PostponedReceiptId` (equivalent path via `PostponedReceipt`/parsing), `PendingDataCount`, `PostponedReceipt`, `ContractData`, `PromiseYieldReceipt`, `PromiseYieldStatus`, `YieldIdToDataId`, `DataIdToYieldId` — using the existing helper setters (`set_account`, `set`, `set_received_data`, `set_postponed_receipt`, `set_promise_yield_receipt`, `set_promise_yield_status`, `set_yield_id_mapping`, and raw `set(state_update, TrieKey::PendingDataCount {...}, &count)`).
3. Call `remove_account(&mut state_update, &account_id)` and assert it returns `Ok`.
4. Using `state_update.trie().lock_for_iter()` and `state_update.locked_iter(...)` over the full account-id-scoped prefix (or over each of the 8 leaked prefixes via `trie_key_parsers`), collect `survivor_keys`.
5. Assert `survivor_keys.is_empty()`. The assertion fails, enumerating the 8 leaked variants: `ReceivedData`, `PostponedReceiptId`, `PendingDataCount`, `PostponedReceipt`, `PromiseYieldReceipt`, `PromiseYieldStatus`, `YieldIdToDataId`, `DataIdToYieldId`, proving the non-empty survivor set and the writer/cleaner set mismatch.

pub fn remove_account(
    state_update: &mut TrieUpdate,
    account_id: &AccountId,
) -> Result<RemoveAccountResult, StorageError> {
    state_update.remove(TrieKey::Account { account_id: account_id.clone() });
    state_update.remove(TrieKey::ContractCode { account_id: account_id.clone() });

    let mut gas_key_nonce_count: usize = 0;
    let mut gas_key_nonce_total_key_bytes: usize = 0;

    // Removing access keys and gas key nonces
    let lock = state_update.trie().lock_for_iter();
    let mut keys_to_remove: Vec<TrieKey> = Vec::new();
    for raw_key in state_update
        .locked_iter(&trie_key_parsers::get_raw_prefix_for_access_keys(account_id), &lock)?
    {
        let raw_key = raw_key?;
        let key_handle = trie_key_parsers::parse_key_handle_from_access_key_key(
            &raw_key, account_id,
        )
        .map_err(|_e| {
            StorageError::StorageInconsistentState(
                "Can't parse key handle from raw key for AccessKey".to_string(),
            )
        })?;
        let nonce_index =
            trie_key_parsers::parse_nonce_index_from_gas_key_key(&raw_key, account_id, &key_handle)
                .map_err(|_e| {
                    StorageError::StorageInconsistentState(
                        "Can't parse nonce index from raw key for AccessKey".to_string(),
                    )
                })?;
        if let Some(index) = nonce_index {
            gas_key_nonce_count += 1;
            gas_key_nonce_total_key_bytes += raw_key.len();
            keys_to_remove.push(TrieKey::gas_key_nonce(
                account_id.clone(),
                key_handle.clone(),
                index,
            ));
        } else {
            keys_to_remove.push(TrieKey::access_key(account_id.clone(), key_handle.clone()));
        }
    }
    drop(lock);

    for trie_key in keys_to_remove {
        state_update.remove(trie_key);
    }

    // Removing contract data
    let lock = state_update.trie().lock_for_iter();
    let data_keys = state_update
        .locked_iter(&trie_key_parsers::get_raw_prefix_for_contract_data(account_id, &[]), &lock)?
        .map(|raw_key| {
            trie_key_parsers::parse_data_key_from_contract_data_key(&raw_key?, account_id)
                .map_err(|_e| {
                    StorageError::StorageInconsistentState(
                        "Can't parse data key from raw key for ContractData".to_string(),
                    )
                })
                .map(Vec::from)
        })
        .collect::<Result<Vec<_>, _>>()?;
    drop(lock);

    for key in data_keys {
        state_update.remove(TrieKey::ContractData { account_id: account_id.clone(), key });
    }
    Ok(RemoveAccountResult { gas_key_nonce_count, gas_key_nonce_total_key_bytes })

pub(crate) fn action_delete_account(
    state_update: &mut TrieUpdate,
    account: &mut Option<Account>,
    actor_id: &mut AccountId,
    receipt: &Receipt,
    result: &mut ActionResult,
    account_id: &AccountId,
    delete_account: &DeleteAccountAction,
    config: &RuntimeConfig,
    current_protocol_version: ProtocolVersion,
) -> Result<(), StorageError> {
    let account_ref = account.as_ref().unwrap();
    let account_storage_usage = if ProtocolFeature::FixDeleteAccountGlobalContractStorageUsage
        .enabled(current_protocol_version)
    {
        let contract_storage = get_contract_storage_usage(state_update, account_id, account_ref)?;
        account_ref.storage_usage().saturating_sub(contract_storage)
    } else {
        // Legacy behavior: only subtracts local contract code, misses the
        // global contract identifier overhead.
        let account_storage_usage = account_ref.storage_usage();
        let code_len = get_code_len_or_default(
            state_update,
            account_id.clone(),
            account_ref.local_contract_hash().unwrap_or_default(),
        )?;
        debug_assert!(
            code_len == 0 || account_storage_usage > code_len,
            "account storage usage should be larger than code size. storage usage: {}, code size: {}",
            account_storage_usage,
            code_len
        );
        account_storage_usage.saturating_sub(code_len)
    };
    if account_storage_usage > Account::MAX_ACCOUNT_DELETION_STORAGE_USAGE {
        result.result =
            Err(ActionErrorKind::DeleteAccountWithLargeState { account_id: account_id.clone() }
                .into());
        return Ok(());
    }
    let gas_key_balance_to_burn = compute_gas_key_balance_sum(state_update, account_id)?;
    if gas_key_balance_to_burn > GasKeyInfo::MAX_BALANCE_TO_BURN {
        result.result = Err(ActionErrorKind::GasKeyBalanceTooHigh {
            account_id: account_id.clone(),
            public_key: None,
            balance: gas_key_balance_to_burn,
        }
        .into());
        return Ok(());
    }
    // We use current amount as a pay out to beneficiary.
    let account_balance = account_ref.amount();
    if account_balance > Balance::ZERO {
        result
            .new_receipts
            .push(Receipt::new_balance_refund(&delete_account.beneficiary_id, account_balance));
    }
    let remove_result = remove_account(state_update, account_id)?;
    result.tokens_burnt =
        result.tokens_burnt.checked_add(gas_key_balance_to_burn).ok_or_else(|| {
            StorageError::StorageInconsistentState("tokens_burnt overflow".to_string())
        })?;
    if remove_result.gas_key_nonce_count > 0 {
        let compute = storage_removes_compute(
            &config.wasm_config.ext_costs,
            remove_result.gas_key_nonce_count,
            remove_result.gas_key_nonce_total_key_bytes,
            AccessKey::NONCE_VALUE_LEN * remove_result.gas_key_nonce_count,
        );
        result.compute_usage = safe_add_compute(result.compute_usage, compute).map_err(|_| {
            StorageError::StorageInconsistentState("compute_usage overflow".to_string())
        })?;
    }
    *actor_id = receipt.predecessor_id().clone();
    *account = None;
    Ok(())
