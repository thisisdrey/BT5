### Title
StackerDB chunk signatures omit the contract identifier, enabling cross-contract replay of validly-signed chunks - ([File: libstackerdb/src/libstackerdb.rs])

### Summary
`SlotMetadata::auth_digest()` computes the digest that a StackerDB writer signs over `slot_id`, `slot_version`, and `data_hash` only — it never binds the signature to the specific `QualifiedContractIdentifier` (StackerDB smart contract) the chunk belongs to. Any chunk that was validly signed and stored/broadcast for one StackerDB contract can be replayed and accepted into any other StackerDB contract that happens to assign the same `slot_id` to the same signing address, as long as the attacker can reproduce (or simply resubmit) an already-observed `(slot_id, slot_version, data_hash, sig, data)` tuple. This mirrors the underlying GHSA-m6w8-fq7v-ph4m bug class: a security-relevant equality (“authenticated for X” vs. “what actually gets accepted/stored”) is broken because the encoding/commitment omits a field (there: the function selector; here: the contract identifier) that the consumer implicitly assumes is bound.

### Finding Description
`SlotMetadata::auth_digest` in [1](#0-0)  hashes only `slot_id`, `slot_version`, and `data_hash`:

```
hasher.update(self.slot_id.to_be_bytes());
hasher.update(self.slot_version.to_be_bytes());
hasher.update(self.data_hash.0);
```

`SlotMetadata::verify` [2](#0-1)  recovers the public key from this digest and only checks that the recovered `pubkh` equals the passed-in `principal` — the target StackerDB contract is never part of the signed material.

The verification call sites that gate acceptance of a chunk (`validate_received_chunk` in [3](#0-2) , and `try_replace_chunk`/`get_slot_signer` used by the HTTP POST handler [4](#0-3) ) look up the expected signer for `(smart_contract_id, slot_id)` via `get_slot_signer` [5](#0-4) , then call `slot_metadata.verify(&addr)`. Because the digest never included `smart_contract_id`, this check cannot distinguish "signed for contract A, slot 5" from "signed for contract B, slot 5" — it only confirms the address matches, which is looked up per-contract but is frequently the *same* signer address across multiple StackerDB contracts (e.g., the `.signers-0-<cycle>` / `.signers-1-<cycle>` contracts across reward cycles, whose slot ordering is derived directly from the on-chain signer set and commonly stays stable across adjacent cycles, as seen in `parse_slot_entry`/`eval_signer_slots` [6](#0-5) ).

A remote, unprivileged peer that has observed one validly-signed chunk (via gossip broadcast, or the public HTTP `GET /v2/stackerdb/.../chunks` endpoint) can resubmit that exact `StackerDBChunkData` — unmodified — against a *different* StackerDB contract path, as long as the target contract assigns the identical `slot_id` to the same signer address with a compatible expected version. `validate_received_chunk`/`try_replace_chunk` will accept it because the signature check only asserts pubkey-hash equality, not contract-scoped provenance; upon acceptance, `process_stacker_db_chunks` re-broadcasts the (replayed) chunk to peers [7](#0-6) , propagating cross-contract-replayed data as if it were freshly authenticated for that contract.

### Impact Explanation
This breaks the "authenticated for slot X in contract C" vs. "accepted/stored/broadcast in contract C'" equality. It allows a remote, unprivileged actor to cause a node to store and re-propagate data under a StackerDB smart-contract context the signer never intended to sign for — a form of forged-data propagation / unauthorized write relative to the correct contract scope, satisfying the Critical impact bucket ("network-wide propagation of forged data").

### Likelihood Explanation
No private key is required by the attacker; only an already-broadcast, validly-signed chunk needs to be observed (chunks are gossiped and independently queryable over HTTP). The precondition — the same signer address being assigned an identical `slot_id` in two distinct StackerDB contracts — is realistic given that signer-set slot assignment is derived deterministically from list order in `stackerdb-get-signer-slots`, and Nakamoto signer sets frequently persist unchanged (or with minor changes only affecting a subset of slots) across adjacent reward cycles/contracts.

### Recommendation
Bind the signed digest to the target StackerDB contract identifier (and any other context that should scope the signature) by including `smart_contract_id` (or a domain-separation tag derived from it) in `SlotMetadata::auth_digest`, and update all callers/tests that construct/verify `SlotMetadata` to pass and check the contract identifier as part of the signed payload. This is a wire/consensus-relevant format change and needs a version gate to avoid breaking existing signed chunks in flight.

### Proof of Concept
1. Signer `S` is assigned `slot_id = 5` in StackerDB contract `A` (e.g., `.signers-0-100`), and signs `StackerDBChunkData { slot_id: 5, slot_version: 3, data, sig }` for contract `A`; the chunk is broadcast/stored normally.
2. Attacker observes this chunk (via P2P `StackerDBPushChunk` broadcast or via `GET /v2/stackerdb/<A>/chunks/5`).
3. Signer `S` is also assigned `slot_id = 5` in contract `B` (e.g., `.signers-0-101`, or any other stackerdb contract sharing that assignment), currently at a version `<= 3`.
4. Attacker POSTs the identical `StackerDBChunkData` (same `slot_id`, `slot_version`, `sig`, `data`) to `/v2/stackerdb/<B>/.../chunks`. `try_replace_chunk` looks up the signer for `(B, 5)`, finds `S`, calls `slot_metadata.verify(S)` — which succeeds because the digest never referenced contract `A` vs. `B` — and the chunk is accepted and re-broadcast for contract `B`, even though `S` never authenticated this data for `B`.

    /// Get the principal who signs a particular slot in a particular stacker DB.
    /// Returns Ok(Some(addr)) if this slot exists in the DB
    /// Returns Ok(None) if the slot does not exist
    /// Returns Err(..) if the DB doesn't exist of some other DB error happens
    pub fn get_slot_signer(
        &self,
        smart_contract: &QualifiedContractIdentifier,
        slot_id: u32,
    ) -> Result<Option<StacksAddress>, net_error> {
        let stackerdb_id = self.get_stackerdb_id(smart_contract)?;
        let sql = "SELECT signer FROM chunks WHERE stackerdb_id = ?1 AND slot_id = ?2";
        let args = params![stackerdb_id, slot_id];
        query_row(&self.conn, sql, args).map_err(|e| e.into())
    }

    fn parse_slot_entry(
        entry: ClarityValue,
        contract_id: &QualifiedContractIdentifier,
    ) -> Result<(StacksAddress, u32), String> {
        let ClarityValue::Tuple(slot_data) = entry else {
            let reason = format!(
                "StackerDB fn `{contract_id}.{STACKERDB_SLOTS_FUNCTION}` returned non-tuple slot entry",
            );
            return Err(reason);
        };

        let Ok(ClarityValue::Principal(signer_principal)) = slot_data.get("signer") else {
            let reason = format!(
                "StackerDB fn `{contract_id}.{STACKERDB_SLOTS_FUNCTION}` returned tuple without `signer` entry of type `principal`",
            );
            return Err(reason);
        };

        let Ok(ClarityValue::UInt(num_slots)) = slot_data.get("num-slots") else {
            let reason = format!(
                "StackerDB fn `{contract_id}.{STACKERDB_SLOTS_FUNCTION}` returned tuple without `num-slots` entry of type `uint`",
            );
            return Err(reason);
        };

        let num_slots = u32::try_from(*num_slots)
            .map_err(|_| format!("Contract `{contract_id}` set too many slots for one signer (max = {STACKERDB_INV_MAX})"))?;
        if num_slots > STACKERDB_INV_MAX {
            return Err(format!("Contract `{contract_id}` set too many slots for one signer (max = {STACKERDB_INV_MAX})"));
        }

        let PrincipalData::Standard(standard_principal) = signer_principal else {
            return Err(format!(
                "StackerDB contract `{contract_id}` set a contract principal as a writer, which is not supported"
            ));
        };
        let addr = StacksAddress::from(standard_principal.clone());
        Ok((addr, num_slots))
    }
