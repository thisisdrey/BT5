### Title
Quarantine-name shortcut in `ObjectDirectoryPath` skips ownership verification, allowing cross-repository object-directory pointing via the client-controlled `git_object_directory` field - (File: internal/git/localrepo/paths.go)

### Summary
`Repo.ObjectDirectoryPath` is supposed to guarantee that a repository's `GitObjectDirectory` (a field fully controlled by the RPC caller through the `Repository` protobuf message) either points inside the repository itself or into a quarantine directory that was legitimately created for *that specific* repository. Instead of always performing the ownership check, the function takes a shortcut whenever the last path component is literally named `quarantine` (or `tmp_objdir*` under a `quarantine` parent), skipping the check entirely — mirroring the reported bug class where a security-critical amount/validation calculation is computed using an incomplete/"false" code path instead of the full one.

### Finding Description
`ObjectDirectoryPath` first validates that the requested object directory stays within the *storage* root: [1](#0-0) 

This only proves the path is somewhere under the shared storage root — which typically holds *every* repository on that Gitaly storage, not just the caller's own repository. The function then derives `baseDir`/`parentDir` from that path and, if the base directory is literally named `quarantine` (or matches the `tmp_objdir*` pattern under a `quarantine` parent), treats it as `isTransactionQuarantineDir` and completely skips the subsequent ownership check: [2](#0-1) 

The skipped block is precisely the logic that would otherwise verify the object directory either (a) is a genuine sub-path of the repository's own directory, or (b) is a manually created quarantine directory whose prefix matches `storage.QuarantineDirectoryPrefix(repo)` — a hash derived from *this* repository's relative path: [3](#0-2) 

Because the shortcut is triggered purely by the *name* of the final path component and not by any repository-specific token, a caller can set `GitObjectDirectory` on the `Repository` message to any path under the shared storage whose last component happens to be `quarantine` — including a quarantine/object directory that legitimately belongs to a *different* repository (e.g., another repository's in-flight push quarantine, or an alternates/object-pool quarantine directory) — and the check will pass without ever confirming it belongs to the repository being operated on.

This is the same bug class as the audited Solidity issue: a validation routine has two code paths (`_includeInterest` true/false; here, "verify ownership" vs. "skip because it's named `quarantine`"), and a caller ends up on the weaker path in a security-sensitive context, silently omitting a check that the rest of the codebase assumes is always enforced.

### Impact Explanation
`ObjectDirectoryPath` is a primitive used by object-directory operations such as `GetObjectDirectorySize`, which is directly reachable via the `RepositoryService.GetObjectDirectorySize` RPC and accepts the `Repository` message (including `git_object_directory`) straight from the caller: [4](#0-3) 

Any RPC path that resolves and then acts on the "object directory" for a caller-supplied `Repository` inherits this weakened validation. An attacker able to invoke such RPCs with a crafted `git_object_directory` value can make Gitaly resolve and operate on another repository's (or an unrelated directory's) object-directory tree merely by naming the final path segment `quarantine`, defeating the purpose of the ownership check and enabling cross-repository object-directory access/disclosure (e.g., leaking size/existence information about another repository's quarantine or object data) without ever passing the intended per-repository prefix verification.

### Likelihood Explanation
The `git_object_directory` / `git_alternate_object_directories` fields are part of every `Repository` message and are populated by legitimate internal flows (quarantine, custom hooks), but nothing in the gRPC surface prevents a client from setting them directly on any RPC that accepts a `Repository`. The exploit condition is simple (name the final path segment `quarantine`) and requires no race condition, timing, or privileged access — only knowledge of the storage layout (which the attacker's own repository's relative path already reveals part of). This makes the likelihood of triggering the weakened path moderate-to-high, though the practical impact is bounded by what other guardrails (e.g., `ValidateGitDirectory`, downstream `os.Stat`) still apply after the skipped check.

### Recommendation
Remove the "shortcut" that bypasses ownership verification based solely on the directory's name. The ownership check (matching either a true sub-path of `repoPath`, or the storage-temp-dir path prefixed with `storage.QuarantineDirectoryPrefix(repo)`) should always run, regardless of whether the final path component is called `quarantine`. If the `tmp_objdir-incoming-*` pattern needs special handling for transaction-created quarantine directories, that check should still be conditioned on the path also containing the repository-specific quarantine prefix (or being anchored under `repo.locator.TempDir(...)`), not merely on the literal string `quarantine` appearing as the last path segment.

### Proof of Concept
1. Attacker controls (or knows the relative path of) repository `A` and knows/derives the relative path (and thus predictable layout) of victim repository `B` on the same storage.
2. Attacker calls an RPC that accepts a `Repository` message and internally invokes `ObjectDirectoryPath` (e.g., `GetObjectDirectorySize`), passing `StorageName` for the shared storage and `GitObjectDirectory` set to a relative path that ends in `.../quarantine` but structurally resolves under repository `B`'s tree (for instance a leftover or concurrently-existing `quarantine` directory belonging to `B`'s in-flight push):
   - `storage.ValidateRelativePath(storagePath, filepath.Join(repoPath, objectDirectoryPath))` passes because the resulting path is still under the shared `storagePath`.
   - `baseDir == "quarantine"` is true, so `isTransactionQuarantineDir` short-circuits, and the block that would otherwise reject a directory not matching `A`'s own quarantine prefix (`storage.QuarantineDirectoryPrefix(repoA)`) never executes.
3. `ObjectDirectoryPath` returns the resolved path belonging to `B`'s quarantine directory as if it were `A`'s own object directory, and the calling RPC (e.g. `GetObjectDirectorySize`) reports information about `B`'s object directory to the attacker acting under repository `A`'s identity.

Note: I was not able to fully trace every downstream consumer of `ObjectDirectoryPath` within the indexing limits (only `GetObjectDirectorySize` was confirmed as a direct caller), so the complete blast radius (e.g., whether any git-command-spawning path also relies on this same check for `GIT_OBJECT_DIRECTORY` isolation) should be verified with a full checkout of the repository, as the codebase index used here may not include every call site.

// QuarantineDirectoryPrefix returns a prefix for use in the temporary directory. The prefix is
// based on the relative repository path and will stay stable for any given repository. This allows
// us to verify that a given quarantine object directory indeed belongs to the repository at hand.
// Ideally, this function would directly be located in the quarantine module, but this is not
// possible due to cyclic dependencies.
func QuarantineDirectoryPrefix(repo Repository) string {
	hash := [20]byte{}
	if repo != nil {
		hash = sha1.Sum([]byte(repo.GetRelativePath()))
	}
	return fmt.Sprintf("quarantine-%x-", hash[:8])
}

func (s *server) GetObjectDirectorySize(ctx context.Context, in *gitalypb.GetObjectDirectorySizeRequest) (*gitalypb.GetObjectDirectorySizeResponse, error) {
	repository := in.GetRepository()
	if err := s.locator.ValidateRepository(ctx, repository); err != nil {
		return nil, structerr.NewInvalidArgument("%w", err)
	}
	repo := s.localRepoFactory.Build(repository)

	path, err := repo.ObjectDirectoryPath(ctx)
	if err != nil {
		return nil, err
	}
	// path is the objects directory path, not repo's path
	sizeInBytes, err := dirSizeInBytes(path, snapshot.NewDefaultFilter(ctx))
	if err != nil {
		return nil, fmt.Errorf("calculating directory size: %w", err)
	}

	return &gitalypb.GetObjectDirectorySizeResponse{Size: sizeInBytes / 1024}, nil
}
