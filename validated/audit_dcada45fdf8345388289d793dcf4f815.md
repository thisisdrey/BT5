### Title
Protocol fee bypass on `Nep245`/`Nep171`/`Imt` `TokenDiff` legs by splitting a large negative delta into many `|delta| <= 1` intents - (File: contracts/defuse/core/src/intents/token_diff.rs)

### Summary
`TokenDiff::token_fee` deliberately returns `Pips::ZERO` for `TokenIdType::Nep245`/`Nep171`/`Imt` when the leg's absolute amount is `<= 1`, and this exemption is evaluated per `TokenDiff` intent leg rather than on the aggregate amount moved for a `TokenId` across a batch. An unprivileged signer can split a single intended `-1000` delta on a `Nep245` `TokenId` into 1000 separate `TokenDiff` intents (in one `DefuseIntents.intents` vec, signed once) each with `delta == -1` on the same `TokenId`, causing `Self::token_fee(token_id, 1, protocol_fee).fee_ceil(1)` to evaluate to `0` on every leg instead of the `Pips::fee_ceil(protocol_fee, 1000)` fee that would be charged for a single `-1000` leg.

### Finding Description
The broken binding: for a fixed `protocol_fee > 0` and a `Nep245` `TokenId` T, executing one `TokenDiff{diff:{T:-1000}}` should collect `fees_collected_total_for_T == Pips::fee_ceil(protocol_fee, 1000) > 0` into `fee_collector`. Executing 1000 `TokenDiff{diff:{T:-1}}` intents from the same signer (same or different payloads, same nonce cost) instead collects `fees_collected_total_for_T == 0`.

Root cause is in `TokenDiff::execute_intent` and `TokenDiff::token_fee`: [1](#0-0) [2](#0-1) 

For each `(token_id, delta)` pair inside a `TokenDiff`, the fee is computed independently as `Self::token_fee(token_id, delta.unsigned_abs(), protocol_fee).fee_ceil(amount)`. For `TokenIdType::Nep245`/`Nep171`/`Imt`, `token_fee` returns `Pips::ZERO` whenever `amount <= 1`. Because `DefuseIntents::execute_intent` simply iterates `Vec<Intent>` and calls `execute_intent` on each independently, an attacker can put 1000 `Intent::TokenDiff` entries — each a distinct `TokenDiff{diff:{T:-1}}` — inside one signed `DefuseIntents`/`MultiPayload` (single nonce, single signature): [3](#0-2) 

Each of the 1000 legs independently computes `fee = Pips::ZERO.fee_ceil(1) == 0`, so the total fee collected for token T is `0`, whereas the semantically equivalent single `-1000` leg would owe `Pips::fee_ceil(protocol_fee, 1000)`. The exemption comment ("do not take fees on NFTs and MTs with |delta| <= 1") is sound for true `Nep171` NFTs (which are always unit-amount), but `Nep245` (multi-token) legs support arbitrary fungible-like amounts, so the same per-leg `amount <= 1` threshold can be trivially defeated by decomposing the intended aggregate amount into unit legs.

The `TransferMatcher`/`finalize` invariant only checks that total deposits equal total withdrawals per `TokenId` across the whole batch — it does not distinguish between one aggregated `-1000` withdrawal and 1000 separate `-1` withdrawals, and it has no knowledge of "intended" fee amounts, so it does not catch or prevent this divergence: [4](#0-3) 

None of `MultiPayload::verify`, nonce/salt checks, or `#[pause]` guards address this because the attack is a valid, correctly-signed, correctly-nonced, balance-neutral batch; the only broken invariant is the fee total.

### Impact Explanation
The fee owed to `fee_collector` on a `Nep245` (and equally `Nep171`/`Imt`) token leg can be reduced to zero regardless of the notional amount moved, simply by restructuring one intended large-amount `TokenDiff` leg into many unit-amount `TokenDiff` intents targeting the same `TokenId`. This is a direct "protocol fees bypassed" impact (Critical category per the rules) — value that should have gone to `fee_collector` never does, on every trade routed through a `Nep245`/`Imt`-typed token (e.g. wrapped/derivative multi-token assets, LP-share-like MT tokens) where amounts greater than 1 are legitimately traded. It is fully repeatable across any signer, any counterparty, and any `Nep245`/`Imt` `TokenId`, and scales with batch size (attacker only pays extra NEAR gas for more intents in the same transaction, not additional signatures or nonces).

### Likelihood Explanation
- Requires only an unprivileged signer able to sign one `DefusePayload`/`MultiPayload` and a counterparty (could be the same actor via multiple controlled accounts, or an unwitting counterparty willing to trade a `Nep245`/`Imt` token) providing the matching reciprocal deposit for `TransferMatcher::finalize` to succeed.
- No special role, relayer key, or upgrade access needed.
- Cost is just gas for a larger intents vector; feasible with standard `execute_intents` calls.
- Fully repeatable per trade/batch involving `Nep245`/`Imt` tokens with `protocol_fee > 0`.

### Recommendation
Compute/enforce the fee-exemption threshold on the aggregate amount moved per `(signer, TokenId)` across the whole `DefuseIntents`/batch (or remove the `amount <= 1` exemption for `Nep245`/`Imt`, keeping it only for genuinely unit-only `Nep171` NFTs), rather than evaluating `token_fee` independently per `TokenDiff` leg.

### Proof of Concept
```rust
// cargo test -p defuse-core (or sandbox integration test)
// 1. Set protocol_fee = Pips::ONE_PERCENT (or any > 0), create a Nep245 TokenId `T`
//    backed by an MT contract, with attacker-controlled accounts `alice` (maker) and `bob` (taker).
// 2. Fund alice with 1000 units of T (and bob with enough of a counter token U to make batches balance).
//
// Case A (single leg):
//   alice signs DefuseIntents{ intents: vec![TokenDiff{ diff: {T: -1000, U: closure_delta(U, ...)} }] }
//   bob   signs the closing TokenDiff for U/T.
//   execute_intents([alice_payload, bob_payload]).
//   assert_eq!(fee_collector_balance_of(T), Pips::fee_ceil(protocol_fee, 1000)); // > 0
//
// Case B (split legs, same aggregate amount):
//   alice signs DefuseIntents{ intents: (0..1000).map(|_| TokenDiff{ diff: {T: -1} }).collect() }
//         plus the U-side closing leg computed the same way.
//   bob   signs the same closing TokenDiff for U/T.
//   execute_intents([alice_payload, bob_payload]).
//   assert_eq!(fee_collector_balance_of(T), 0); // FEES not equal to Case A -> bypass demonstrated
//
// The two `fee_collector_balance_of(T)` values diverge (Case A > 0, Case B == 0) despite both
// batches moving the same net -1000/+1000 amount of T for the same signer, proving
// fees_collected_total_for_T == Pips::fee_ceil(protocol_fee, 1000) is violated in Case B.
```

```rust
    // Finalizes all transfers, or returns unmatched deltas.
    // If unmatched deltas overflow, then Err(None) is returned.
    pub fn finalize(self) -> Result<Transfers, InvariantViolated> {
        let mut transfers = Transfers::default();
        let mut deltas = TokenDeltas::default();
        for (token_id, transfer_matcher) in self.0 {
            if let Err(unmatched) = transfer_matcher.finalize_into(&token_id, &mut transfers)
                && (unmatched == 0 || deltas.apply_delta(token_id, unmatched).is_none())
            {
                return Err(InvariantViolated::Overflow);
            }
        }
        if !deltas.is_empty() {
            return Err(InvariantViolated::UnmatchedDeltas {
                unmatched_deltas: deltas,
            });
        }
        Ok(transfers)
    }
}
```
