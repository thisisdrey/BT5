### Title
Global `open_connections` handshake-headroom ceiling is stake-agnostic, letting an unstaked attacker starve staked connection admission - (File: streamer/src/nonblocking/quic.rs)

### Summary
`ClientConnectionTracker::new` gates *all* incoming QUIC connections — staked or unstaked — against a single global counter (`stats.open_connections`) before peer stake/type is even known, using a ceiling of `(max_staked_connections + max_unstaked_connections) * 5 / 4`. [1](#0-0) [2](#0-1)  Because this gate runs before per-type table admission and before the per-IP rate limiter is ever populated for an unconfirmed IP, an unstaked attacker can flood half-open (never-completing) QUIC handshakes to consume the entire 25% headroom, causing legitimate staked connection attempts to be refused via `refused_connections_too_many_open_connections`.

### Finding Description
In the accept loop, the sequence for every incoming connection is: (1) global `overall_connection_rate_limiter` check, (2) per-IP `rate_limiter.is_allowed()` check, (3) `ClientConnectionTracker::new(stats, qos.max_concurrent_connections())`, and only *after* `accept()` succeeds and the handshake completes does `qos.try_add_connection()` determine stake/peer-type and admit into the staked/unstaked tables. [3](#0-2) [4](#0-3) 

The per-IP `is_allowed` check is a no-op for any IP that hasn't yet completed a handshake, since `register_connection` (the only call that consumes a token) is only invoked *after* the QUIC handshake finishes in `setup_connection`. [5](#0-4) [6](#0-5)  This means an attacker who deliberately never completes the handshake is never IP-throttled at all, and is bounded only by the global `overall_connection_rate_limiter` (burst 1000, sustained 2500/s). [7](#0-6) 

`ClientConnectionTracker::new` increments `open_connections` unconditionally at accept time and only decrements on `Drop` — i.e., when the connection is later dropped or the `QUIC_CONNECTION_HANDSHAKE_TIMEOUT` (2s) fires in `setup_connection`. [8](#0-7) [9](#0-8)  An attacker can therefore continuously open connections that stall in the Initial/Handshake state for up to 2 seconds, holding a `ClientConnectionTracker` slot the whole time without ever being classified as staked or unstaked. Since `max_concurrent_connections()` for `SwQos` is a single stake-agnostic ceiling `(max_staked_connections + max_unstaked_connections) * 5/4` — i.e., the entire 25% margin is shared and not partitioned/reserved per peer class — filling that margin with attacker half-handshakes pushes `open_connections` to the ceiling. Any further incoming connection, including one from a legitimately staked validator, is refused at the `ClientConnectionTracker::new` check itself (`refused_connections_too_many_open_connections`), before it ever reaches the staked-table pruning/eviction logic in `SwQos::try_add_connection` that would otherwise protect staked admission via `prune_random`. [10](#0-9)  The pruning-by-stake mechanism designed to protect staked connections only operates on the per-type `ConnectionTable`, which the attacker's half-open connections never enter — so it provides no protection against this earlier, stake-blind gate.

### Impact Explanation
This is a QUIC/TPU-port denial-of-service against staked-connection admission: an unprivileged unstaked remote client can transiently deny legitimate staked TPU connections (and thus transaction ingress) by monopolizing the handshake-headroom margin that was explicitly intended ("Allow 25% more connections than required to allow for handshake") to absorb connection setup overlap, not to be a first-come-first-served resource open to unauthenticated peers. This matches the "loss of availability / degraded performance of leader TPU ingestion via resource exhaustion" bounty category.

### Likelihood Explanation
Preconditions are minimal: the attacker only needs standard UDP/QUIC connectivity to a leader's public TPU port, no stake or keys. The overall connection rate limiter (burst 1000, 2500/s sustained) comfortably exceeds the size of the 25% margin for typical staked/unstaked connection limits, so the attack is trivially repeatable and sustainable by continuously re-triggering half-open connections before each one's 2-second timeout expires. No sigverify, dedup, or stake-based gate exists between accept() and the global `ClientConnectionTracker` check to prevent this.

### Recommendation
Reserve/partition the handshake headroom by peer class (e.g., track separate staked/unstaked in-flight counters, or require a minimal proof-of-ownership/retry token before consuming headroom slots), and/or make the per-IP rate limiter apply to unconfirmed connections (not only ones that already completed a handshake) so a single IP cannot cheaply flood the shared `open_connections` ceiling with connections it never intends to complete.

### Proof of Concept
Add a tokio integration test in `streamer/src/nonblocking/quic.rs` test module:
1. Spawn a `SwQos`-backed QUIC server via `spawn_stake_weighted_qos_server` with small `max_staked_connections`/`max_unstaked_connections` (e.g., 4/4, ceiling = 10).
2. From an unstaked test client, open `(max_staked_connections + max_unstaked_connections) * 5 / 4` raw QUIC connections that send only an Initial packet and then stall (no handshake completion), keeping them alive past accept but under `QUIC_CONNECTION_HANDSHAKE_TIMEOUT`.
3. Concurrently, from a separate staked keypair-backed client, attempt a normal connection.
4. Assert the staked connection attempt fails/times out and `stats.refused_connections_too_many_open_connections` is incremented, while `stats.connection_added_from_staked_peer` remains 0 — demonstrating the staked client is refused purely due to the stake-agnostic global ceiling being saturated by unstaked half-handshakes.

impl Drop for ClientConnectionTracker {
    /// When this is dropped, reduce the open connection count.
    fn drop(&mut self) {
        self.stats.open_connections.fetch_sub(1, Ordering::Relaxed);
    }
}

impl ClientConnectionTracker {
    /// Check the max_concurrent_connections limit and if it is within the limit
    /// create ClientConnectionTracker and increment open connection count. Otherwise returns Err
    fn new(stats: Arc<StreamerStats>, max_concurrent_connections: usize) -> Result<Self, ()> {
        let open_connections = stats.open_connections.fetch_add(1, Ordering::Relaxed);
        if open_connections >= max_concurrent_connections {
            stats.open_connections.fetch_sub(1, Ordering::Relaxed);
            debug!(
                "There are too many concurrent connections opened already: open: \
                 {open_connections}, max: {max_concurrent_connections}"
            );
            return Err(());
        }

        Ok(Self { stats })
    }

    /// Check if the connection from the said `ip` is allowed.
    /// Here we assume that only IPs with actual confirmed connections are stored in it,
    /// since we should only modify server state once source IP is verified
    pub fn is_allowed(&self, ip: &IpAddr) -> bool {
        // Check if we have records in the rate limiter for the given IP address
        match self.limiter.current_tokens(ip) {
            Some(r) => r > 0, // we have a record, and rate is not exceeded
            None => true,     // if we have not seen IP, allow connection request
        }
    }

    pub fn register_connection(&self, ip: &IpAddr) -> bool {
        if self.limiter.consume_tokens(*ip, 1).is_ok() {
            debug!("Request from IP {ip:?} allowed");
            true // Request allowed
        } else {
            debug!("Request from IP {ip:?} blocked");
            false // Request blocked
        }
    }
