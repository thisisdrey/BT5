### Title
Vesting and Staking Distribution Permanently Blocked by Recipient Opting Out of Direct Coin Transfers — (`aptos-move/framework/aptos-framework/sources/vesting.move`, `aptos-move/framework/aptos-framework/sources/staking_contract.move`)

---

### Summary

`vesting::distribute()` and `staking_contract::distribute_internal()` iterate over all shareholders and call `aptos_account::deposit_coins<AptosCoin>()` for each recipient inside a single atomic transaction. `deposit_coins` will **abort** if the recipient account exists, has not registered a legacy `CoinStore<AptosCoin>`, and has explicitly opted out of direct coin transfers via `set_allow_direct_coin_transfers(false)`. Because Move transactions are all-or-nothing, a single aborting recipient causes the entire distribution to revert, permanently blocking every other shareholder from receiving their vested or staked APT until the problematic recipient is resolved.

---

### Finding Description

**`aptos_account::deposit_coins<CoinType>`** (lines 111–131):

```move
public fun deposit_coins<CoinType>(
    to: address, coins: Coin<CoinType>
) acquires DirectTransferConfig {
    if (!account::exists_at(to)) {
        create_account(to);   // creates FA store only, NOT CoinStore<AptosCoin>
    };
    if (!coin::is_account_registered<CoinType>(to)) {
        assert!(
            can_receive_direct_coin_transfers(to),   // ← ABORTS here
            error::permission_denied(EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS)
        );
        coin::register<CoinType>(&create_signer(to));
    };
    coin::deposit<CoinType>(to, coins)
}
``` [1](#0-0) 

`create_account` calls `register_apt`, which only creates the **primary fungible store** for APT — it does **not** create a legacy `CoinStore<AptosCoin>`:

```move
public(friend) fun register_apt(account_signer: &signer) {
    ensure_primary_fungible_store_exists(signer::address_of(account_signer));
}
``` [2](#0-1) 

Therefore, any account created after the FA migration has no `CoinStore<AptosCoin>`, so `coin::is_account_registered<AptosCoin>(to)` returns `false`. If that account has also called `set_allow_direct_coin_transfers(false)`, `can_receive_direct_coin_transfers` returns `false` and the call aborts.

**`vesting::distribute()`** (lines 730–740) calls `deposit_coins` for every shareholder inside a single `for_each_ref` loop with no error isolation:

```move
shareholders.for_each_ref(|shareholder| {
    let shareholder = *shareholder;
    ...
    let recipient_address = get_beneficiary(vesting_contract, shareholder);
    aptos_account::deposit_coins(recipient_address, share_of_coins);
});
``` [3](#0-2) 

**`staking_contract::distribute_internal()`** (lines 888–911) has the same pattern in a `while` loop:

```move
while (distribution_pool.shareholders_count() > 0) {
    ...
    aptos_account::deposit_coins(
        recipient, coin::extract(&mut coins, amount_to_distribute)
    );
};
``` [4](#0-3) 

---

### Impact Explanation

Any shareholder or beneficiary in a vesting or staking contract who:
1. Has an account created post-FA-migration (no legacy `CoinStore<AptosCoin>`), **and**
2. Has called `set_allow_direct_coin_transfers(false)`

causes every call to `vesting::distribute()` or `staking_contract::distribute()` to abort. Because the entire transaction rolls back, **no shareholder receives any distribution** until the blocking condition is resolved. Vested APT and staking rewards remain locked in the stake pool indefinitely. In the vesting contract the admin can call `update_beneficiary` to work around this, but in the staking contract there is no equivalent escape hatch for the staker's own distribution slot.

---

### Likelihood Explanation

- Post-FA-migration, all newly created accounts lack a `CoinStore<AptosCoin>` by default, satisfying condition 1 automatically.
- `set_allow_direct_coin_transfers(false)` is an unprivileged, zero-cost entry function callable by any account holder.
- A single malicious or misconfigured shareholder in a multi-party vesting contract can trigger this at any time, with no special permissions.

---

### Recommendation

Replace the hard-aborting `aptos_account::deposit_coins` calls inside distribution loops with the fungible-asset path (`primary_fungible_store::deposit`), which does not gate on `DirectTransferConfig` and always succeeds for any existing account. Alternatively, introduce per-recipient error isolation (skip-and-accumulate dust) so that one failing recipient does not block the entire distribution batch.

---

### Proof of Concept

1. Deploy a vesting contract with shareholders Alice and Bob.
2. Bob creates a fresh account (post-FA-migration; no `CoinStore<AptosCoin>` exists).
3. Bob calls `aptos_account::set_allow_direct_coin_transfers(false)`.
4. Rewards accumulate; anyone calls `vesting::distribute(contract_address)`.
5. The loop reaches Bob's entry: `coin::is_account_registered<AptosCoin>(bob)` → `false`; `can_receive_direct_coin_transfers(bob)` → `false`; transaction aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS`.
6. Alice's distribution is also rolled back. Neither Alice nor Bob receives any APT. Repeated calls all abort identically. [5](#0-4) [6](#0-5) [7](#0-6)

    /// Distribute any withdrawable stake from the stake pool.
    public entry fun distribute(contract_address: address) acquires VestingContract {
        assert_active_vesting_contract(contract_address);

        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        let coins = withdraw_stake(vesting_contract, contract_address);
        let total_distribution_amount = coin::value(&coins);
        if (total_distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };

        // Distribute coins to all shareholders in the vesting contract.
        let grant_pool = &vesting_contract.grant_pool;
        let shareholders = &grant_pool.shareholders();
        shareholders.for_each_ref(|shareholder| {
            let shareholder = *shareholder;
            let shares = pool_u64::shares(grant_pool, shareholder);
            let amount = pool_u64::shares_to_amount_with_total_coins(grant_pool, shares, total_distribution_amount);
            let share_of_coins = coin::extract(&mut coins, amount);
            let recipient_address = get_beneficiary(vesting_contract, shareholder);
            aptos_account::deposit_coins(recipient_address, share_of_coins);
        });

        // Send any remaining "dust" (leftover due to rounding error) to the withdrawal address.
        if (coin::value(&coins) > 0) {
            aptos_account::deposit_coins(vesting_contract.withdrawal_address, coins);
        } else {
            coin::destroy_zero(coins);
        };

        emit(
            Distribute {
                admin: vesting_contract.admin,
                vesting_contract_address: contract_address,
                amount: total_distribution_amount,
            },
        );
    }
