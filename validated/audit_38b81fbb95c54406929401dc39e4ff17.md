## Finding

### Title
Active-Permission Delegate Can Escalate to Full Owner Permission via AccountPermissionUpdateContract - (File: actuator/src/main/java/org/tron/core/actuator/AccountPermissionUpdateActuator.java)

### Summary
`AccountPermissionUpdateContract` is a single, undifferentiated contract type that simultaneously carries the new `owner`, `witness`, and `active` permission sets. Authorization to submit this contract is granted purely via a bit in an `Active` permission's `operations` bitmap — the same coarse-grained mechanism used for any other contract type. Once an account owner grants an `Active` key this single bit (e.g., intending to let an automated/delegate key rotate its own active keys), that delegate key can submit a transaction that unconditionally overwrites the account's `Owner` permission, seizing full control of the account and locking out the legitimate owner. This mirrors the JumpServer analog: a narrowly-scoped permission bit is used to trigger a code path that performs an unconditioned "set" overwrite of a broader, higher-privilege authorization structure.

### Finding Description
Transaction signature/permission validation is generic and keyed off `permissionId` supplied in the contract itself, resolved against the signer's own `Permission` record and its `operations` bitmap: [1](#0-0) [2](#0-1) 

The only per-signature check for a non-owner (`permissionId != 0`) signer is that the permission type is `Active` and that the `operations` bitmap includes the bit for the contract type being submitted (`checkPermissionOperations`). There is no additional restriction preventing the `AccountPermissionUpdateContract` bit from being included in a custom `Active` permission's operations — the actuator's own field-level validation checks new operations bitmaps only against `AVAILABLE_CONTRACT_TYPE`, which does include the `AccountPermissionUpdateContract` bit (only `ClearABIContract`/`UpdateBrokerageContract` are excluded): [3](#0-2) 

By contrast, the *default* active permission created for new accounts intentionally excludes the `AccountPermissionUpdateContract` bit: [4](#0-3) 

showing the bit is treated as sensitive by default — but nothing in `AccountPermissionUpdateActuator.checkPermission()` prevents an owner (intentionally or by social engineering) from granting it to a custom `Active` permission: [5](#0-4) 

Once any signer is authorized to submit this contract type (regardless of whether they hold `Owner` or merely a scoped `Active` key), `execute()` unconditionally overwrites the account's `Owner` permission (and `Active`/`Witness` permissions) with whatever is supplied in the contract, with no check tying the signer's own permission level to which permission slot they are allowed to modify: [6](#0-5) [7](#0-6) 

`updatePermissions()` calls `builder.setOwnerPermission(owner)` unconditionally — there is no branch requiring that only a signer already holding the current `Owner` permission (permissionId == 0) can change the `Owner` permission.

### Impact Explanation
Any account owner who grants a subordinate/delegate `Active` key the `AccountPermissionUpdateContract` operation bit (a plausible configuration for automated key-rotation or convenience) unintentionally grants that delegate the ability to fully replace the account's `Owner` permission with attacker-controlled keys/threshold, permanently locking out the legitimate owner and taking full unauthorized control of the account (including its funds, since `Owner` permission also governs `AccountUpdateContract`, transfers via default operations, etc.). This is a concrete unauthorized-account-takeover / permanent-loss-of-control scenario reachable purely from a signed transaction.

### Likelihood Explanation
Exploitation requires the account owner to have first configured a custom `Active` permission that includes the `AccountPermissionUpdateContract` bit — this is not the default configuration, so the attack surface is limited to accounts using non-default, permissive multisig setups (a legitimate and documented multisig feature). Within that scope, exploitation is trivial: the delegate key simply signs one `AccountPermissionUpdateContract` transaction setting itself as sole `Owner`.

### Recommendation
Enforce that only a signer holding the current `Owner` permission (`permissionId == 0`, or a signature set satisfying the current owner threshold) can change the `Owner` (and `Witness`) permission fields; alternatively, split "modify active permissions" and "modify owner/witness permissions" into contract-type/operation-bit granularity so an `Active` delegate cannot escalate to `Owner`. At minimum, `AccountPermissionUpdateActuator.execute()`/`validate()` should reject any `AccountPermissionUpdateContract` transaction that changes the `Owner` permission unless it was signed under `permissionId == 0`.

### Proof of Concept
1. Account `A` sets up multisig via `AccountPermissionUpdateContract`, configuring an `Active` permission (key `D`) whose `operations` bitmap includes the `AccountPermissionUpdateContract` bit (permitted since `AVAILABLE_CONTRACT_TYPE` allows it) — e.g., intended to let `D` add/rotate other active keys.
2. Key `D` signs a new `AccountPermissionUpdateContract` transaction with `permission_id` set to `D`'s active permission id, supplying a new `owner` `Permission` containing only `D`'s address with `threshold = 1`, plus a required `actives` list.
3. `TransactionCapsule.validateSignature`/`checkPermission` passes because `D`'s active permission's operations bitmap includes the `AccountPermissionUpdateContract` bit.
4. `AccountPermissionUpdateActuator.execute()` calls `account.updatePermissions(newOwner, ..., ...)`, unconditionally overwriting `A`'s `Owner` permission to be solely controlled by `D`, completing the takeover.

  public static boolean validateSignature(Transaction transaction,
      byte[] hash, AccountStore accountStore, DynamicPropertiesStore dynamicPropertiesStore)
      throws PermissionException, SignatureException, SignatureFormatException {
    Transaction.Contract contract = transaction.getRawData().getContractList().get(0);
    int permissionId = contract.getPermissionId();
    byte[] owner = getOwner(contract);
    AccountCapsule account = accountStore.get(owner);
    Permission permission = null;
    if (account == null) {
      if (permissionId == 0) {
        permission = AccountCapsule.getDefaultPermission(ByteString.copyFrom(owner));
      }
      if (permissionId == 2) {
        permission = AccountCapsule
            .createDefaultActivePermission(ByteString.copyFrom(owner), dynamicPropertiesStore);
      }
    } else {
      permission = account.getPermissionById(permissionId);
    }
    if (permission == null) {
      throw new PermissionException("permission isn't exit");
    }
    checkPermission(permissionId, permission, contract);
    long weight = checkWeight(permission, transaction.getSignatureList(), hash, null);
    if (weight >= permission.getThreshold()) {
      return true;
    }
    return false;
  }

  private boolean checkPermission(Permission permission) throws ContractValidateException {
    DynamicPropertiesStore dynamicStore = chainBaseManager.getDynamicPropertiesStore();
    if (permission.getKeysCount() > dynamicStore.getTotalSignNum()) {
      throw new ContractValidateException("number of keys in permission should not be greater "
          + "than " + dynamicStore.getTotalSignNum());
    }
    if (permission.getKeysCount() == 0) {
      throw new ContractValidateException("key's count should be greater than 0");
    }
    if (permission.getType() == PermissionType.Witness && permission.getKeysCount() != 1) {
      throw new ContractValidateException("Witness permission's key count should be 1");
    }
    if (permission.getThreshold() <= 0) {
      throw new ContractValidateException("permission's threshold should be greater than 0");
    }
    String name = permission.getPermissionName();
    if (!StringUtils.isEmpty(name) && name.length() > 32) {
      throw new ContractValidateException("permission's name is too long");
    }
    //check owner name ?
    if (permission.getParentId() != 0) {
      throw new ContractValidateException("permission's parent should be owner");
    }

    long weightSum = 0;
    List<ByteString> addressList = permission.getKeysList()
        .stream()
        .map(x -> x.getAddress())
        .distinct()
        .collect(toList());
    if (addressList.size() != permission.getKeysList().size()) {
      throw new ContractValidateException(
          "address should be distinct in permission " + permission.getType());
    }
    for (Key key : permission.getKeysList()) {
      if (!DecodeUtil.addressValid(key.getAddress().toByteArray())) {
        throw new ContractValidateException("key is not a validate address");
      }
      if (key.getWeight() <= 0) {
        throw new ContractValidateException("key's weight should be greater than 0");
      }
      try {
        weightSum = addExact(weightSum, key.getWeight());
      } catch (ArithmeticException e) {
        throw new ContractValidateException(e.getMessage());
      }
    }
    if (weightSum < permission.getThreshold()) {
      throw new ContractValidateException(
          "sum of all key's weight should not be less than threshold in permission " + permission
              .getType());
    }

    ByteString operations = permission.getOperations();
    if (permission.getType() != PermissionType.Active) {
      if (!operations.isEmpty()) {
        throw new ContractValidateException(
            permission.getType() + " permission needn't operations");
      }
      return true;
    }
    //check operations
    if (operations.isEmpty() || operations.size() != 32) {
      throw new ContractValidateException("operations size must 32");
    }

    byte[] types1 = dynamicStore.getAvailableContractType();
    for (int i = 0; i < 256; i++) {
      boolean b = (operations.byteAt(i / 8) & (1 << (i % 8))) != 0;
      boolean t = ((types1[(i / 8)] & 0xff) & (1 << (i % 8))) != 0;
      if (b && !t) {
        throw new ContractValidateException(i + " isn't a validate ContractType");
      }
    }
    return true;
  }

  public void updatePermissions(Permission owner, Permission witness, List<Permission> actives) {
    Builder builder = this.account.toBuilder();

    owner = owner.toBuilder().setId(0).build();
    builder.setOwnerPermission(owner);
    if (witness != null && builder.getIsWitness()) {
      witness = witness.toBuilder().setId(1).build();
      builder.setWitnessPermission(witness);
    }

    builder.clearActivePermission();
    if (actives != null) {
      for (int i = 0; i < actives.size(); i++) {
        Permission permission = actives.get(i).toBuilder().setId(i + 2).build();
        builder.addActivePermission(permission);
      }
    }

    this.account = builder.build();
  }
