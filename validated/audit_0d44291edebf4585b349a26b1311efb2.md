Audit Report

## Title
Reward page is marked "claimed" before the funds are actually delivered, permanently burying nominator/validator rewards when the deposit to the payee fails - ([File: substrate/frame/staking-async/src/pallet/impls.rs])

## Summary
`do_payout_stakers_by_page` calls `Eras::<T>::set_rewards_as_claimed(era, &stash, page)` before attempting the actual reward transfer via `payout_from_provider` → `make_payout_from_provider`. If the underlying `T::Currency::transfer(&staker_rewards_pot, &payout_account, amount, Preservation::Expendable)` fails (e.g., depositing an amount below the Existential Deposit to a non-existent/killed payee account), the function silently logs an error and returns `None` with no rollback of the claimed flag, permanently burying that reward.

## Finding Description
In `substrate/frame/staking-async/src/pallet/impls.rs`, `Eras::<T>::set_rewards_as_claimed(era, &stash, page)` is executed at line 386, before `Eras::<T>::get_paged_exposure` is even called and well before any transfer is attempted. The comment "Input data seems good, no errors allowed after this point" immediately follows, confirming the code intentionally treats everything downstream as non-reverting/best-effort. [1](#0-0) 

The money movement happens later in `make_payout_from_provider`: it resolves the payee via `Self::payee(Stash(stash.clone()))` and `payout_account_for_dest`, then calls `T::Currency::transfer(&staker_rewards_pot, &payout_account, amount, Preservation::Expendable)`. On `Err`, it only logs via `log!(error, ...)` and returns `None` — no error propagation, no event, no retry mechanism, and no reversal of the claimed bit set earlier in `do_payout_stakers_by_page`. [2](#0-1) 

Because `Eras::<T>::is_rewards_claimed`/`get_next_claimable_page` gate the public `payout_stakers`/`payout_stakers_by_page` extrinsics, once the claimed flag is set for `(era, stash, page)` there is no path to retry that specific payout — the transfer failure is masked as a completed claim. [3](#0-2) [4](#0-3) 

## Impact Explanation
This is a real unbacked/permanent value-lock issue: the reward amount remains stuck in the era's `staker_rewards_pot` account, unreachable by the intended stash/nominator (claim slot burned) and not recoverable by anyone else. This aligns with the "permanent user-fund lock" and "balances ... must conserve value and settle exactly once to the rightful beneficiary" impact classes for `pallet-staking-async`, which is in-scope production runtime pallet code.

## Likelihood Explanation
The failure trigger is realistic and requires no privileged access: a nominator/validator with `RewardDestination::Account` pointing at a fresh or killed account, combined with a per-page reward share smaller than the chain's Existential Deposit — plausible for nominators with small stake shares on pages with many participants. Anyone can permissionlessly call `payout_stakers`/`payout_stakers_by_page` for any stash, triggering the bug without malicious intent, governance, or privileged capability, as long as the DAP transfer-based path (`use_dap_payout`) is active for the era. [5](#0-4) 

## Recommendation
Move `Eras::<T>::set_rewards_as_claimed` to occur only after `payout_from_provider`/`make_payout_from_provider` succeed (per validator/nominator, or per-page after confirming payability), or otherwise ensure the claim marking is transactional with the payout. Alternative mitigations: on transfer failure, fall back to crediting the stash's own account, or persist an "unpaid remainder" that can be reclaimed once the payee account becomes viable, and emit a distinguishable failure event rather than only a log line.

## Proof of Concept
1. Enable the DAP transfer-based payout path by setting `DisableMintingGuard::<T>::get()` to a past era.
2. Configure a nominator `N` with `RewardDestination::Account(fresh_account)` where `fresh_account` has never held a balance.
3. Arrange `N`'s exposure share on a given era/page to yield a reward below the chain's Existential Deposit (many nominators sharing a page, modest total payout).
4. Call `Staking::payout_stakers_by_page(origin, validator_stash, era, page)` from any account.
5. Trace execution: `Eras::<T>::set_rewards_as_claimed(era, &stash, page)` fires at line 386 before `payout_from_provider` runs; `make_payout_from_provider`'s `T::Currency::transfer` fails for the sub-ED deposit to `fresh_account`; the error is logged and `None` returned — no `Rewarded` event, no funds moved.
6. Call `payout_stakers_by_page` again for the same `(era, page)`: it now returns `Error::<T>::AlreadyClaimed` because `Eras::<T>::is_rewards_claimed` is already `true`, confirming the reward is permanently unclaimable and the funds remain stranded in `staker_rewards_pot`.

	fn payout_from_provider(
		era: EraIndex,
		stash: &T::AccountId,
		validator_payout: BalanceOf<T>,
		exposure: &crate::PagedExposure<T::AccountId, BalanceOf<T>>,
		overview_own: BalanceOf<T>,
		total_nominator_payout: BalanceOf<T>,
	) -> u32 {
		let mut nominator_payout_count: u32 = 0;

		if let Some((amount, dest)) = Self::make_payout_from_provider(era, stash, validator_payout)
		{
			Self::deposit_event(Event::<T>::Rewarded { stash: stash.clone(), dest, amount });
		}

		let total_nominator_stake = exposure.total().saturating_sub(overview_own);
		for nominator in exposure.others().iter() {
			let nominator_exposure_part =
				Perbill::from_rational(nominator.value, total_nominator_stake);
			let nominator_reward: BalanceOf<T> =
				nominator_exposure_part.mul_floor(total_nominator_payout);

			if let Some((amount, dest)) =
				Self::make_payout_from_provider(era, &nominator.who, nominator_reward)
			{
				nominator_payout_count.saturating_inc();
				Self::deposit_event(Event::<T>::Rewarded {
					stash: nominator.who.clone(),
					dest,
					amount,
				});
			}
		}

		nominator_payout_count
	}

	/// Make a payment to a staker from an era reward pot (transfer, not mint).
	fn make_payout_from_provider(
		era: EraIndex,
		stash: &T::AccountId,
		amount: BalanceOf<T>,
	) -> Option<(BalanceOf<T>, RewardDestination<T::AccountId>)> {
		if amount.is_zero() {
			return None;
		}

		let dest = match Self::payee(Stash(stash.clone())) {
			Some(d) => d,
			None => {
				Self::deposit_event(Event::<T>::Unexpected(UnexpectedKind::MissingPayee {
					era,
					stash: stash.clone(),
				}));
				return None;
			},
		};

		let payout_account = Self::payout_account_for_dest(stash, &dest)?;

		let staker_rewards_pot =
			T::RewardPots::pot_account(RewardPot::Era(era, RewardKind::StakerRewards));
		if let Err(e) = T::Currency::transfer(
			&staker_rewards_pot,
			&payout_account,
			amount,
			Preservation::Expendable,
		) {
			log!(
				error,
				"Failed to transfer reward from pot for era {:?}, stash {:?}: {:?}",
				era,
				stash,
				e
			);
			return None;
		}
