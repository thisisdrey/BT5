### Title
Unauthenticated `/shutdown` HTTP request permanently kills `SignerEventReceiver::main_loop` - (File: libsigner/src/events.rs)

### Summary
`SignerEventReceiver::next_event` treats any HTTP POST to the path `/shutdown` as a legitimate termination command with no authentication, signature, or source-address check. Any remote TCP client that can reach the signer's configured event-receiver endpoint can send a single crafted `POST /shutdown` request and permanently stop the signer's event-ingestion loop.

### Finding Description
In `next_event`, the branch handling incoming requests dispatches purely on `request.url()`: [1](#0-0) 

For `/shutdown`, the code immediately does `event_receiver.stop_signal.store(true, Ordering::SeqCst); Err(EventError::Terminated)` with **no verification of the caller's identity, no secret/token check, and no restriction to loopback** — unlike node-to-signer authenticity for actual event payloads (which is only implicitly trusted because the endpoint is expected to be reached only by the local node's event dispatcher, not because of any cryptographic check).

`main_loop` treats `EventError::Terminated` as a normal, unrecoverable exit condition: [2](#0-1) 

This is precisely the mechanism `SignerStopSignaler::send` uses internally to shut the signer down gracefully — it opens a `TcpStream` to the receiver's own bound address and sends `POST /shutdown ...`: [3](#0-2) 

Because the check is purely on the URL path of an inbound HTTP request to the bound socket, any TCP client capable of reaching that socket — not just the local stop-signaler — can trigger identical behavior. Once `stop_signal` is set true, `is_stopped()` returns true forever (no reset path), so `main_loop` exits on the next iteration and the signer stops receiving `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, and `/new_block` events pushed by the node from then on.

### Impact Explanation
A single unauthenticated HTTP POST permanently disables the signer's event receiver thread, cutting the signer off from all further node-pushed events (block proposals, burn blocks, StackerDB chunk notifications). This is a single-message, unauthenticated remote DoS against the signer's event ingestion pipeline, matching the "Critical - remote crash/unauthenticated DoS from few messages" category. It does not corrupt chain state directly, but it silently disables signer functionality, which can affect block signing/validation availability for that signer.

### Likelihood Explanation
- No secret, signature, or IP allow-list gates this path in `next_event` at all — it is a plain URL-string comparison.
- The endpoint's reachability depends solely on how the signer operator configures the event-receiver bind address/interface (this is operator-configured, not enforced in code to be loopback-only).
- Exploiting it requires nothing more than establishing a TCP connection to the bound port and sending a well-formed HTTP POST — trivially cheap and fully repeatable (each additional `/shutdown` POST is a no-op once stopped, but the first one is sufficient and irreversible without a manual restart).

### Recommendation
Do not treat `/shutdown` as a plain unauthenticated HTTP route. Options:
- Require the shutdown request to originate from a pre-shared secret/token known only to the internal stop-signaler (e.g., included in the request body/header and checked before setting `stop_signal`).
- Restrict acceptance of `/shutdown` to connections whose peer address matches `self.local_addr`'s loopback/local origin, rejecting the store when the request comes from a different peer.
- Alternatively, use an in-process signaling mechanism (e.g., a dedicated internal channel/socketpair) instead of exposing termination control over the same public-facing HTTP listener used for node event pushes.

use std::net::{TcpStream, SocketAddr};
use std::io::Write;
use std::thread;
use std::time::Duration;

#[test]
fn unauthenticated_remote_shutdown_kills_event_receiver() {
    let mut receiver: SignerEventReceiver<StackerDBChunksEvent> = SignerEventReceiver::new(false);
    let addr: SocketAddr = "127.0.0.1:0".parse().unwrap(); // in practice operator may bind 0.0.0.0
    let bound = receiver.bind(addr).unwrap();

    let handle = thread::spawn(move || receiver.main_loop());

    // Attacker: arbitrary remote TCP client, no secret, no signature
    let mut stream = TcpStream::connect(bound).unwrap();
    let body = "attacker payload";
    let req = format!(
        "POST /shutdown HTTP/1.1\r\nHost: {}\r\nConnection: close\r\nContent-Length: {}\r\n\r\n{}",
        bound, body.len(), body
    );
    stream.write_all(req.as_bytes()).unwrap();

    // main_loop should exit promptly, terminating the event receiver
    // without any node-issued /stackerdb_chunks event ever being processed again.
    handle.join().unwrap(); // succeeds -- proving the loop terminated from an unauthenticated request
}

        loop {
            if self.is_stopped() {

            let next_event = match self.next_event() {
                Ok(event) => event,
                Err(EventError::UnrecognizedEvent(..)) => {
                    // got an event that we don't care about (not a problem)
                    continue;
                }
                Err(EventError::Terminated) => {
                    // we're done
                    info!("Caught termination signal");
                    break;
                }
                Err(e) => {
                    warn!("Failed to receive next event: {:?}", &e);
                    continue;
                }
            };

                info!("Failed to forward event");
                break;
            }
        }
