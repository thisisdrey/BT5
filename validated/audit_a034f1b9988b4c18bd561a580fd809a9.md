Confirmed: `FindRemoteRootRefRequest` has no `timeout` field, unlike `FetchRemoteRequest` which has `Timeout` explicitly applied via `context.WithTimeout` in `FetchRemote`.### Title
FindRemoteRootRef lacks any bounded timeout for the outbound `git remote show` command, allowing indefinite hang and resource exhaustion - ([File: internal/gitaly/service/remote/find_remote_root_ref.go])

### Summary
`FindRemoteRootRef` executes `git remote show inmemory` against an attacker-controlled `RemoteUrl`, without ever applying a request-scoped or configurable timeout to the context passed to `repo.Exec`. Unlike `FetchRemote`, which explicitly applies `context.WithTimeout` based on `req.GetTimeout()`, `FindRemoteRootRefRequest` has no timeout field at all, so a slow/hanging remote endpoint can keep the underlying git process (and the goroutine reading its stdout) alive for as long as the client's own gRPC call remains open.

### Finding Description
`findRemoteRootRefCmd` builds a `git remote show inmemory` invocation using `request.GetRemoteUrl()` (with optional `ResolvedAddress`/auth header) purely via git config injection (`remote.inmemory.url`), then calls `repo.Exec(ctx, ...)` with the incoming RPC `ctx` unmodified: [1](#0-0) 

`findRemoteRootRef` then blocks reading from the command's stdout line by line via a `bufio.Scanner`, and finally calls `cmd.Wait()`: [2](#0-1) 

The public entrypoint `FindRemoteRootRef` validates only that `RemoteUrl` is non-empty and that the repository is valid — it does not create or bound any timeout: [3](#0-2) 

Contrast this with `FetchRemote`, which explicitly derives a bounded child context from `req.GetTimeout()` before doing any remote I/O: [4](#0-3) 

The `FindRemoteRootRefRequest` proto message has no equivalent `timeout` field — it only carries `repository`, `remote_url`, `http_authorization_header`, and `resolved_address`: [5](#0-4) 

Whereas `FetchRemoteRequest` explicitly defines a `timeout` field that is used for this purpose: [6](#0-5) 

The only thing that will eventually terminate the hung `git remote show` process is the calling gRPC client dropping the connection or an outer deadline set by the caller (e.g., GitLab Rails' Sidekiq/Rails HTTP client timeout) — but Gitaly itself enforces no bound. There is no Gitaly-side default RPC deadline interceptor found in `internal/gitaly/server/server.go`'s interceptor chain that would impose a ceiling here; deadlines are entirely at the discretion of whatever client calls this RPC.


An attacker who owns a project (and thus can invoke `RemoteService`/`FindRemoteRootRef`, e.g. via "import project by URL"/mirror configuration flows in GitLab) supplies a `RemoteUrl` pointing at a TCP listener that accepts the connection but never sends an HTTP response (slow-loris style) or a server that stalls mid-response. Each such call causes Gitaly to spawn a `git remote show` process and block indefinitely reading its output, holding a goroutine, file descriptors for the pipe, and the child process alive for the full duration.

### Impact Explanation
Repeated concurrent invocations of `FindRemoteRootRef` against slow/hanging endpoints let an unprivileged project owner accumulate an unbounded number of long-lived `git remote show` processes and associated goroutines/file descriptors on the Gitaly node, since there is no per-RPC timeout enforced in this code path (unlike `FetchRemote`). This matches a DoS/resource-exhaustion impact class: sustained load can exhaust process/FD limits and degrade or crash the Gitaly node for other tenants sharing the same node/storage.

### Likelihood Explanation
The only precondition is being an ordinary project owner/importer who can trigger the `FindRemoteRootRef` RPC (a normal accessor-level RPC in `RemoteService`, not requiring elevated privileges), and controlling the `RemoteUrl` value, which is exactly the case for mirror/import-by-URL flows in GitLab. The exploit is trivial and fully repeatable — no timing races, no privileged access, and no reliance on a bug in git or GitLab Rails; it purely exploits the absence of a bounded context/timeout in this specific Gitaly handler.

### Recommendation
Add an internal, non-attacker-controlled bounded timeout to `findRemoteRootRefCmd`/`FindRemoteRootRef` (e.g., wrap `ctx` with `context.WithTimeout` using a fixed or configurable server-side default, mirroring the pattern used for other outbound-remote RPCs such as `FetchRemote`), so that `git remote show` is forcibly killed if the remote does not respond within the bound, regardless of whether the calling client sets its own gRPC deadline.

### Proof of Concept
```go
func TestFindRemoteRootRef_HangingRemote(t *testing.T) {
    ctx := testhelper.Context(t)
    cfg, client := setupRemoteService(t, ctx)
    localRepo, _ := gittest.CreateRepository(t, ctx, cfg)

    // TCP listener that accepts connections but never responds.
    ln, err := net.Listen("tcp", "127.0.0.1:0")
    require.NoError(t, err)
    defer ln.Close()
    go func() {
        for {
            conn, err := ln.Accept()
            if err != nil {
                return
            }
            // Never write anything back; hold the connection open.
            _ = conn
        }
    }()

    start := time.Now()
    _, err = client.FindRemoteRootRef(ctx, &gitalypb.FindRemoteRootRefRequest{
        Repository: localRepo,
        RemoteUrl:  fmt.Sprintf("http://%s/", ln.Addr().String()),
    })
    elapsed := time.Since(start)

    // Expected: call should fail/timeout within a bounded window (e.g. tens of seconds)
    // enforced by Gitaly itself. Actual: without a caller-supplied gRPC deadline, the
    // call hangs indefinitely because no internal timeout bounds `git remote show`.
    require.Error(t, err)
    require.Less(t, elapsed, 30*time.Second, "FindRemoteRootRef should not hang indefinitely")
}
```
Running many such calls concurrently and observing `lsof`/process count for `git remote show` confirms unbounded growth over time, since each call's underlying process/goroutine is only released when the RPC context (set by the *caller*, not Gitaly) expires or is cancelled.

func (s *server) findRemoteRootRefCmd(ctx context.Context, request *gitalypb.FindRemoteRootRefRequest) (*command.Command, error) {
	remoteURL := request.GetRemoteUrl()
	var config []gitcmd.ConfigPair

	if resolvedAddress := request.GetResolvedAddress(); resolvedAddress != "" {
		modifiedURL, resolveConfig, err := gitcmd.GetURLAndResolveConfig(remoteURL, resolvedAddress)
		if err != nil {
			return nil, structerr.NewInvalidArgument("couldn't get curloptResolve config: %w", err)
		}

		remoteURL = modifiedURL
		config = append(config, resolveConfig...)
	}

	config = append(config, gitcmd.ConfigPair{Key: "remote.inmemory.url", Value: remoteURL})

	if authHeader := request.GetHttpAuthorizationHeader(); authHeader != "" {
		config = append(config, gitcmd.ConfigPair{
			Key:   fmt.Sprintf("http.%s.extraHeader", request.GetRemoteUrl()),
			Value: "Authorization: " + authHeader,
		})
	}

	repo := s.localRepoFactory.Build(request.GetRepository())

	return repo.Exec(ctx,
		gitcmd.Command{
			Name:   "remote",
			Action: "show",
			Args:   []string{"inmemory"},
		},
		gitcmd.WithDisabledHooks(),
		gitcmd.WithConfigEnv(config...),
		gitcmd.WithSetupStdout(),
	)
}

func (s *server) findRemoteRootRef(ctx context.Context, request *gitalypb.FindRemoteRootRefRequest) (string, error) {
	cmd, err := s.findRemoteRootRefCmd(ctx, request)
	if err != nil {
		return "", err
	}

	scanner := bufio.NewScanner(cmd)
	for scanner.Scan() {
		line := strings.TrimSpace(scanner.Text())

		if strings.HasPrefix(line, headPrefix) {
			rootRef := strings.TrimPrefix(line, headPrefix)
			if rootRef == "(unknown)" {
				return "", structerr.NewNotFound("no remote HEAD found")
			}
			return rootRef, nil
		}
	}

	if err := scanner.Err(); err != nil {
		return "", err
	}

	if err := cmd.Wait(); err != nil {
		return "", err
	}

	return "", structerr.NewNotFound("couldn't query the remote HEAD")
}

func (s *server) FindRemoteRootRef(ctx context.Context, in *gitalypb.FindRemoteRootRefRequest) (*gitalypb.FindRemoteRootRefResponse, error) {
	if in.GetRemoteUrl() == "" {
		return nil, structerr.NewInvalidArgument("missing remote URL")
	}
	if err := s.locator.ValidateRepository(ctx, in.GetRepository()); err != nil {
		return nil, structerr.NewInvalidArgument("%w", err)
	}

	ref, err := s.findRemoteRootRef(ctx, in)
	if err != nil {
		return nil, structerr.NewInternal("%w", err)
	}

	return &gitalypb.FindRemoteRootRefResponse{Ref: ref}, nil
}

  // Optional.
