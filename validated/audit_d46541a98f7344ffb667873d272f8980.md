### Title
Staker reward payouts are silently dropped and unrecoverable when the pot-to-staker transfer fails - (File: `substrate/frame/staking-async/src/pallet/impls.rs`)

### Summary
In `pallet-staking-async`, `payout_stakers` distributes an era's reward to a validator and its nominators by transferring balance out of a per-era reward pot account. The individual transfer to each staker (`make_payout_from_provider`) can fail (e.g. pot underfunded, existential-deposit edge cases), but that failure is only logged and swallowed — it never causes the enclosing `payout_stakers` dispatch to return an error. Because the extrinsic still returns `Ok(..)`, the page/era is treated as successfully paid, so the staker's share is permanently lost with no way to retry, exactly mirroring the audited bug's pattern of a broken sub-step ("swap only, no deposit into fToken") being swallowed while the outer flow proceeds as if it had succeeded.

### Finding Description
`payout_stakers`/`do_payout_stakers` computes `validator_staker_payout_for_page` and `reward_split.nominator_payout`, then calls `Self::payout_from_provider(...)` [1](#0-0) , which in turn calls `make_payout_from_provider` for the validator and every nominator [2](#0-1) .

`make_payout_from_provider` performs the actual settlement via `T::Currency::transfer` from the era's `staker_rewards_pot` to the payout account: [3](#0-2) 

If the transfer errors, the function only logs the error and returns `None` — it does not propagate a `DispatchError`, and the `Rewarded` event for that staker is simply never emitted. Meanwhile `payout_from_provider`/`payout_stakers` continue iterating the remaining nominators and, at the top level, `Ok(Some(weight).into())` is always returned for the dispatch [4](#0-3) . Because the call succeeds, the page is recorded as claimed (claimed-page bookkeeping is driven purely by a successful call to `payout_stakers`, not by whether every individual transfer inside it succeeded), so there is no mechanism to retry the failed payout for that staker/era/page afterward.

This is structurally identical to the audited Solidity bug: a conditional/failure branch inside a larger reward-processing routine is silently absorbed (there, via try/catch around the swap; here, via a logged-and-ignored `Err` from `Currency::transfer`), while the surrounding logic advances state (there, moving on to the next reward-processing step which then fails on zero fToken balance; here, marking the era page as paid) as though the sub-step had fully succeeded. In both cases the reward token/balance ends up permanently stranded — in the Solidity case in the underlying token in the pod contract, here in the untouched `staker_rewards_pot` for that era with no accounting path back to the staker.

### Impact Explanation
Any staker (validator or nominator) whose payout transfer fails for that page permanently and silently loses their reward for that era/page. Given the `Pivots` requirement that "payout state must only advance after ... settlement succeed[s] atomically," this violates the invariant that `payout_stakers` should only be considered complete once every entitled party has actually received funds. Because the extrinsic is publicly callable by anyone (it does not need to be the staker), this constitutes unbacked/lost value with no compensating control, and the era/page cannot be re-processed once marked claimed — a permanent fund-loss condition matching the "Impact" class of the seed report.

### Likelihood Explanation
Triggering the underlying transfer failure requires a specific pot/account balance condition (e.g., the `staker_rewards_pot` for an era running low due to rounding/edge distribution, or the destination account hitting an existential-deposit edge case under `Preservation::Expendable`). It is not attacker-controlled in the sense of an arbitrary unprivileged exploit, but it is a naturally reachable state (pot underfunding across many small per-nominator transfers, dust rounding, or `RewardDestination::Account` pointing at a reaped account) rather than requiring a malicious validator/relayer/admin, matching the "public underpriced/at-risk work" and "permanent fund lock" categories rather than the excluded "malicious peer/validator" categories.

### Recommendation
Do not allow `payout_stakers` (and the legacy mint path, which has the analogous swallow pattern in `make_payout_legacy` at the same file) to report success or advance claimed-page state when an individual settlement transfer fails. Either:
1. Propagate the transfer failure and abort the whole page's payout (rolling back to allow retry), or
2. Track and accumulate failed individual payouts into a persisted "unpaid" ledger entry per (era, stash) that can be retried/reclaimed later, instead of only emitting a best-effort log and an `Unexpected` event with no remediation path.

### Proof of Concept
1. Set up an era with a `staker_rewards_pot` account and multiple nominators sharing a validator's exposure.
2. Drain/underfund the `staker_rewards_pot` account (e.g. via dust rounding across many transfers, or by having its balance fall below the amount needed to complete `Preservation::Expendable` transfers for later nominators in the exposure list) so that a transfer partway through `payout_from_provider`'s loop over `exposure.others()` fails.
3. Call `payout_stakers(origin, validator_stash, era)` as any account.
4. Observe: the call returns `Ok(..)`, only some `Rewarded` events are emitted, the failed nominator receives nothing, and `Eras::<T>::get_next_claimable_page` no longer offers this page for reprocessing — the nominator's reward for that era/page is unrecoverable. This mirrors the underlying-token-stuck outcome of the audited report, where the outer flow reported success while the actual value transfer for a sub-case silently failed. [5](#0-4)

	/// Payout stakers from an era reward pot (transfer-based, no minting).
	fn payout_from_provider(
		era: EraIndex,
		stash: &T::AccountId,
		validator_payout: BalanceOf<T>,
		exposure: &crate::PagedExposure<T::AccountId, BalanceOf<T>>,
		overview_own: BalanceOf<T>,
		total_nominator_payout: BalanceOf<T>,
	) -> u32 {
		let mut nominator_payout_count: u32 = 0;

		if let Some((amount, dest)) = Self::make_payout_from_provider(era, stash, validator_payout)
		{
			Self::deposit_event(Event::<T>::Rewarded { stash: stash.clone(), dest, amount });
		}

		let total_nominator_stake = exposure.total().saturating_sub(overview_own);
		for nominator in exposure.others().iter() {
			let nominator_exposure_part =
				Perbill::from_rational(nominator.value, total_nominator_stake);
			let nominator_reward: BalanceOf<T> =
				nominator_exposure_part.mul_floor(total_nominator_payout);

			if let Some((amount, dest)) =
				Self::make_payout_from_provider(era, &nominator.who, nominator_reward)
			{
				nominator_payout_count.saturating_inc();
				Self::deposit_event(Event::<T>::Rewarded {
					stash: nominator.who.clone(),
					dest,
					amount,
				});
			}
		}

		nominator_payout_count
	}
