### Title
`ValidateMultiSign` precompile crashes on truncated ABI calldata when the TIP-854 guard is inactive — analog of CVE-2018-11095 (declared-length vs. actual-length mismatch) - (File: `actuator/src/main/java/org/tron/core/vm/PrecompiledContracts.java`)

### Summary
The CVE describes `libming`'s `decompileJUMP` trusting a header-declared size larger than the actual buffer, causing an out-of-bounds crash. The java-tron `ValidateMultiSign` precompiled contract has the same bug-class: it trusts attacker-supplied "array length" and "offset" header words taken from calldata without verifying they are consistent with the actual number of 32-byte words present, and unlike `BatchValidateSign`, it has no protective outer `try/catch`.

### Finding Description
`ValidateMultiSign.execute()` parses raw call data into fixed-size 32-byte `DataWord[] words = DataWord.parseArray(rawData)` [1](#0-0) , whose length is only `rawData.length / WORD_SIZE`. It then reads header words (`words[3]`) that encode an *offset* into this array, and uses `words[offset].intValueSafe()` as a declared array *length*, exactly mirroring the CVE pattern of "header says N items follow" without validating N against the buffer actually received: [2](#0-1) 

The strict bound check (`isValidAbiEncoding`) that would catch a mismatched length is only applied when `VMConfig.allowTvmOsaka()` is enabled: [3](#0-2) 

When that flag is not active (documented in the repository's own tests as "legacy behaviour"), a crafted `bytes32` header offset or an inflated `len` field feeds directly into `extractBytesArray` / `extractSigArray` / `extractBytes32Array`, which index `words[offset + i + 1]` with no bounds check against `words.length`: [4](#0-3) 

If the declared length/offset exceeds the actual number of parsed words, this throws an uncaught `ArrayIndexOutOfBoundsException`. Critically, `ValidateMultiSign.execute()` (unlike `BatchValidateSign.execute()`, which wraps its logic in `try { return doExecute(data); } catch (Throwable t) { ... }` [5](#0-4) ) has no such top-level guard, so the exception propagates out of `execute()` directly into `Program.callToPrecompiledAddress()`.

The project's own regression test explicitly documents this as a known, currently-unmitigated failure mode: [6](#0-5) 

and a companion test shows the intended post-fix behavior — that a proper TIP-854 fix must prevent any exception from escaping into the outer call frame: [7](#0-6) 

### Impact Explanation
`ValidateMultiSign` is invoked via a plain `CALL`/`STATICCALL` TVM opcode from any deployed smart contract to precompile address `0x...0a`, reachable by any unprivileged account that can deploy a contract and trigger it (or even directly if a contract forwards raw calldata). A single crafted transaction with malformed calldata (mismatched header offset/length vs. actual data size) can throw an unhandled `RuntimeException` from inside `PrecompiledContract.execute()`, which is not caught anywhere before returning to `Program.callToPrecompiledAddress` for this particular contract path, unlike its sibling `BatchValidateSign`. This can crash/halt transaction execution for the node processing it (denial of service on that node/validator), which is the direct analog of the "Segmentation fault and application crash" impact in CVE-2018-11095.

### Likelihood Explanation
Likelihood is high given the analog: no privileged role is required, the precompile is reachable from any contract call, and the vulnerable path is the *default* legacy path (active whenever `VMConfig.allowTvmOsaka()`/TIP-854 is not enabled). The test suite itself acknowledges this exact scenario throws pre-activation. I could not verify from the index whether `allowTvmOsaka` is enabled by default on mainnet at the current chain height — this determines whether the vulnerable "legacy" path is actually reachable in production today. If the flag is active network-wide, `isValidAbiEncoding` blocks this path; if inactive, the bug is live.

### Recommendation
Add a top-level `try/catch(Throwable)` around `ValidateMultiSign.execute()`'s body (mirroring `BatchValidateSign`'s pattern) that converts any unexpected exception into `Pair.of(true, DATA_FALSE)` regardless of `VMConfig.allowTvmOsaka()` state, and/or make the `isValidAbiEncoding` bound check unconditional rather than gated behind the TIP-854 feature flag, so malformed/truncated calldata can never reach unchecked array indexing in `extractBytesArray`/`extractSigArray`/`extractBytes32Array`.

### Proof of Concept
1. Craft calldata for `validatemultisign(address,uint256,bytes32,bytes[])` where the ABI-encoded dynamic array's declared length word implies more elements than the actual calldata length provides (e.g., truncate the trailing bytes after the header, similar to `ValidateMultiSignContractTest.testTip854RejectsMalformedCalldata`'s malformed buckets at lines 158-193, but executed with `VMConfig.allowTvmOsaka()` left at its default/inactive state).
2. Deploy a contract that performs a `CALL` to precompile address `0x0a` with this calldata, or submit it as a `TriggerSmartContract` transaction if a wrapper contract forwards raw calldata.
3. Observe `ValidateMultiSign.execute()` throwing `ArrayIndexOutOfBoundsException` from `extractBytesArray`/`extractSigArray` (lines 399-426), which is not caught by any surrounding handler in this precompile, unlike `BatchValidateSign`.

  public static DataWord[] parseArray(byte[] data) {
    int len = data.length / WORD_SIZE;
    DataWord[] words = new DataWord[len];
    for (int i = 0; i < len; i++) {
      byte[] bytes = Arrays.copyOfRange(data, i * WORD_SIZE, (i + 1) * WORD_SIZE);
      words[i] = new DataWord(bytes);
    }
    return words;
  }

  private static byte[][] extractBytes32Array(DataWord[] words, int offset) {
    int len = words[offset].intValueSafe();
    byte[][] bytes32Array = new byte[len][];
    for (int i = 0; i < len; i++) {
      bytes32Array[i] = words[offset + i + 1].getData();
    }
    return bytes32Array;
  }

  private static byte[][] extractBytesArray(DataWord[] words, int offset, byte[] data) {
    if (offset > words.length - 1) {
      return new byte[0][];
    }
    int len = words[offset].intValueSafe();
    byte[][] bytesArray = new byte[len][];
    for (int i = 0; i < len; i++) {
      int bytesOffset = words[offset + i + 1].intValueSafe() / WORD_SIZE;
      int bytesLen = words[offset + bytesOffset + 1].intValueSafe();
      bytesArray[i] = extractBytes(data, (bytesOffset + offset + 2) * WORD_SIZE,
          bytesLen);
    }
    return bytesArray;
  }

  private static byte[][] extractSigArray(DataWord[] words, int offset, byte[] data) {

      return new byte[0][];
    }

    }

  // batchValidateSign with malformed calldata must (a) push 0 onto the outer
  // stack, (b) leave the outer frame free of any propagated exception, and
  // (c) allow the outer frame to continue executing afterwards.
  @Test
  public void testTip854OuterFrameContainment() throws ContractValidateException {
    byte prePrefixByte = DecodeUtil.addressPreFixByte;
    DecodeUtil.addressPreFixByte = Constant.ADD_PRE_FIX_BYTE_MAINNET;
    VMConfig.initAllowTvmOsaka(1);
    try {
      for (PrecompiledContracts.PrecompiledContract contract :
          new PrecompiledContracts.PrecompiledContract[]{
              new PrecompiledContracts.ValidateMultiSign(),
              new PrecompiledContracts.BatchValidateSign()}) {
        invoke = new ProgramInvokeMockImpl();
        InternalTransaction interTrx = new InternalTransaction(
            Protocol.Transaction.getDefaultInstance(),
            InternalTransaction.TrxType.TRX_UNKNOWN_TYPE);
        program = new Program(new byte[0], new byte[0], invoke, interTrx);
        // inDataSize=0 ⇒ data=[] ⇒ fewer than H=5 head words ⇒ guard rejects.
        MessageCall messageCall = new MessageCall(
            Op.CALL, new DataWord(10000),
            DataWord.ZERO(), DataWord.ZERO(),
            DataWord.ZERO(), DataWord.ZERO(),
            DataWord.ZERO(), DataWord.ZERO(),
            DataWord.ZERO(), false);
        program.callToPrecompiledAddress(messageCall, contract);

        Assert.assertNull(contract.getClass().getSimpleName()
                + ": outer frame must not inherit an exception",
            program.getResult().getException());
        Assert.assertEquals(contract.getClass().getSimpleName() + ": inner CALL pushes 0",
            DataWord.ZERO(), program.getStack().pop());
        // Outer frame continues: another stack op works without throwing.
        program.stackPush(new DataWord(1));
        Assert.assertEquals(new DataWord(1), program.getStack().pop());
      }
    } finally {
      VMConfig.initAllowTvmOsaka(0);
      DecodeUtil.addressPreFixByte = prePrefixByte;
    }
