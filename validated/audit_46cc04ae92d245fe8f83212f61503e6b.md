## Title
Unauthenticated RPC endpoints leak internal DB/IO error details (Debug-formatted) to remote clients on server errors - (File: stackslib/src/net/api/gettenureblocks.rs)

### Summary
The `/v3/tenures/blocks/*` RPC endpoints convert internal `db_error` values into HTTP 500 responses by embedding the Rust `Debug` representation of the underlying error directly in the response body sent to the remote, unauthenticated caller.

### Finding Description
`ToHttpResponse for db_error::to_http_response` builds the HTTP 500 body via `format!("{error_msg}: {e:?}")` for every `db_error` variant other than `NotFoundError`/`BlockHeightOutOfRange`, then serves it verbatim as `HttpServerError`: [1](#0-0) 

`db_error` wraps low-level errors including `SqliteError(rusqlite::Error)` and `IOError(std::io::Error)`, whose `Debug` output can contain SQL statement/constraint text, SQLite internal state, and OS-level I/O failure details (e.g. file paths, `ENOENT`/permission errors): [2](#0-1) 

This helper is reused across all three "get tenure blocks" endpoints — by consensus hash, by burn block hash, and by burn block height — at every DB lookup site, e.g. `get_handle_from_ch`, `get_block_snapshot_by_consensus_hash`, and the tenure stream constructor: [3](#0-2) [4](#0-3) 

The `try_from_header_or_snapshot` and `next_block`/`generate_next_chunk` streaming paths similarly propagate `{e:?}` (and in some cases `ChainError`/chunk-generation errors) straight into the response body or chunk error text: [5](#0-4) [6](#0-5) 

These RPC endpoints (`/v3/tenures/blocks/:consensus_hash` and its byhash/byheight variants) require no authentication — any peer that can reach the node's HTTP RPC port can trigger them.

### Impact Explanation
On any internal DB fault (disk I/O error, SQLite corruption/locking error, or other `db_error`), the node returns the raw `Debug` string of the internal error to the remote caller in the HTTP body. This can disclose internal implementation details such as local filesystem paths, SQLite error internals, and other operational state that should not be exposed to untrusted remote parties — the same class of "Information leakage in Error Handler" (CWE-209) described in the referenced advisory. It does not directly grant write access or crash the node, so it sits at the lower end of information-disclosure impact rather than a critical primitive.

### Likelihood Explanation
No authentication or special privileges are needed — any error condition on the underlying sortition/chainstate DB during handling of these public RPC requests (e.g., disk pressure, lock contention, transient I/O failure) will trigger this code path and leak the formatted error text to the requester.

### Recommendation
Do not include `{:?}`-formatted internal error values in HTTP response bodies returned to remote clients. Log the detailed error server-side (as is already done via `error!`) and return a generic, non-identifying error message (or an opaque error code) to the client for all `db_error` variants other than the already-handled not-found cases.

### Proof of Concept
1. Cause any non-not-found `db_error` to occur while querying the sortition DB or chainstate DB backing `/v3/tenures/blocks/:consensus_hash` (e.g., simulate a locked/corrupted SQLite DB or an I/O failure on the DB file).
2. Send `GET /v3/tenures/blocks/<consensus_hash>` to the node's RPC interface as an unauthenticated remote client.
3. Observe the HTTP 500 response body contains the raw `Debug` output of the internal `db_error` (e.g., `SqliteError(...)` or `IOError(...)`), potentially including filesystem paths or SQL/SQLite internal detail, as constructed in `ToHttpResponse::to_http_response`.

impl ToHttpResponse for db_error {
    fn to_http_response(
        self,
        preamble: &HttpRequestPreamble,
        not_found_msg: String,
        error_msg: String,
    ) -> StacksHttpResponse {
        match self {
            db_error::NotFoundError | db_error::BlockHeightOutOfRange => {
                StacksHttpResponse::new_error(preamble, &HttpNotFound::new(not_found_msg))
            }
            e => {
                let msg = format!("{error_msg}: {e:?}");
                error!("{msg}");
                StacksHttpResponse::new_error(preamble, &HttpServerError::new(msg))
            }
        }
    }
}
