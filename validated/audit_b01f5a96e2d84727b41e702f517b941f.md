### Title
Repository-wide reference write lock uses unfair thundering-herd wakeup, allowing an unprivileged writer to starve other legitimate pushes indefinitely - ([File: internal/praefect/datastore/lock_manager.go])

### Summary
Praefect's `RepoReferenceWriteLockManager` serializes all write transactions to a repository behind a single PostgreSQL-backed lock keyed only by `virtualStorage|relativePath` — i.e. one lock per *repository*, not per reference. When the lock is contended, all waiters block on a shared notification channel and, upon release, are woken simultaneously to race for the lock via a non-FIFO `INSERT ... ON CONFLICT` UPSERT. This is directly analogous to the reported `Trader` frontrunning class: multiple parties compete for a single exclusive resource with no fairness/ordering guarantee, so a party who can generate more/cheaper concurrent attempts can reliably win the race and deny a legitimate single actor from ever completing.

### Finding Description
The lock is acquired at `PREPARING_PHASE` before any git-level ref lock is taken, and is scoped to the whole repository rather than the specific reference being updated: [1](#0-0) 

Contention handling is implemented as follows: any goroutine that fails to acquire the lock registers a notification channel and blocks; `Lock` loops, retrying the UPSERT after being woken: [2](#0-1) 

When the lock is released, **every** registered waiter for that lock is woken at once (`close(ch)` for all channels), with no ordering or fairness applied: [3](#0-2) 

All woken waiters then race to win the same `INSERT ... ON CONFLICT ... WHERE locks.expired_at < NOW() OR locks.holder_txn_id = $2` UPSERT; only one succeeds and the rest re-enter the queue: [4](#0-3) 

Because the lock is per-*repository* (not per-reference), a write to any ref in the repo contends with writes to *any other* ref in that same repo. Combined with the thundering-herd/no-fairness wakeup, a client that can issue many concurrent trivial writes (e.g. repeatedly creating/deleting an unrelated branch, or retrying its own write on every NOTIFY) has a statistically much higher chance of winning the UPSERT race on every release cycle than a single legitimate writer. The legitimate writer's request can be starved indefinitely (or until it hits its RPC timeout), exactly mirroring the reported bug class where an attacker observes contention for a shared resource and repeatedly re-enters the race to deny a legitimate counterpart from ever succeeding.

### Impact Explanation
This allows an ordinary user with write access to a repository (the same privilege level required to push at all — not a privileged operator) to deny other legitimate users' pushes/ref-updates to the *same repository*, even to completely unrelated branches, by flooding the repository-wide write-lock with cheap, repeated write transactions. This is a livelock/starvation Denial of Service on a normal git operation (push), consistent with "DoS of a handler" in the acceptance criteria. The severity is bounded by Praefect's write-lock TTL (20s) per held lock and by whatever RPC-level timeouts exist client-side, but a sustained attacker can keep re-winning the race across many release cycles, extending the denial for as long as they keep sending traffic.

### Likelihood Explanation
Likelihood is moderate: this requires (a) the serialized-writes feature to be enabled with `RepoReferenceWriteLockManager` configured (not the `NoopWriteLockManager`), and (b) the attacker to have push access to the same repository as the victim (a common scenario for shared repos with multiple contributors/CI). No cross-tenant or storage-escape capability is required — this is purely a fairness/starvation defect in the locking primitive that is reachable from an ordinary authenticated push.

### Recommendation
- Replace the thundering-herd wakeup with a FIFO/ticket-based wakeup: on release, wake only the oldest waiter (or hand the lock directly to it) instead of waking all waiters to race via UPSERT.
- Alternatively/additionally, scope the lock more granularly (e.g., per-reference or per set-of-referenced-refs within the transaction) instead of per-repository, so that unrelated ref updates do not contend with each other.
- Consider adding a maximum wait/backoff with increasing priority for long-waiting transactions, and/or per-client rate limiting on this lock table to prevent one client from generating unbounded contention.

### Proof of Concept
1. Enable serialized writes (`RepoReferenceWriteLockManager` backing `WriteLockManager`) for a virtual storage on Praefect.
2. Attacker (with ordinary push access to repository `R`) spins up N concurrent goroutines/processes that each continuously initiate a small write transaction against `R` (e.g., creating and immediately deleting a throwaway branch), driving `VoteTransaction` through `PREPARING_PHASE`→`COMMITTED_PHASE` in a tight loop.
3. Victim, with legitimate access to `R`, issues a single push to an unrelated branch, which also must acquire the same repository-scoped lock at `PREPARING_PHASE` (`internal/praefect/datastore/lock_manager.go:259-278`).
4. Because `Notified` wakes all waiters simultaneously (`lock_manager.go:101-112`) and the UPSERT race has no fairness guarantee (`lock_manager.go:304-356`), the attacker's many concurrent competitors statistically out-race the victim's single waiter on each release cycle, delaying/denying the victim's push until it times out.

// Notified signals all goroutines waiting on the released lock_id by closing their channels,
// then removes them from the waiters map.
func (d *lockReleaseDispatcher) Notified(n glsql.Notification) {
	lockID := LockID(n.Payload)
	d.mu.Lock()
	chs := d.waiters[lockID]
	delete(d.waiters, lockID)
	d.mu.Unlock()
	for _, ch := range chs {
		close(ch) // wake all waiters
	}
}

// Lock acquires the write lock for a given virtualStorage, relativePath and txnID,
// blocking until the lock is acquired or ctx is cancelled.
func (r *RepoReferenceWriteLockManager) Lock(ctx context.Context, virtualStorage, relativePath string, txnID uint64,
) (RepoLock, error) {
	for {
		res := r.tryLock(ctx, virtualStorage, relativePath, txnID)
		if res.Err != nil {
			return RepoLock{}, res.Err
		}
		if res.Acquired {
			return RepoLock{Unlock: res.Unlock, Renew: res.Renew}, nil
		}

		select {
		case <-ctx.Done():
			res.Deregister()
			return RepoLock{}, fmt.Errorf("wait for lock: %w", ctx.Err())
		case <-res.NotificationCh:
			// wait for the lock to release
		}
	}
}

func (r *RepoReferenceWriteLockManager) tryLock(ctx context.Context, virtualStorage, relativePath string, txnID uint64,
) tryLockResult {
	lockID := repoLockID(virtualStorage, relativePath)
	// Register for a lock release notification before attempting the INSERT, so
	// that no release event can be missed between a failed attempt and the caller
	// beginning to wait, thus eliminating the race window between contention detection
	// and notification.
	notificationCh, deregister := r.handler.RegisterForLockRelease(lockID)

	query := `
INSERT INTO repository_reference_write_locks as locks (lock_id, holder_txn_id, expired_at)
VALUES ($1, $2, NOW() + $3::interval)
ON CONFLICT (lock_id) DO UPDATE
  SET holder_txn_id = EXCLUDED.holder_txn_id,
      expired_at    = EXCLUDED.expired_at
WHERE locks.expired_at < NOW() OR locks.holder_txn_id = $2
RETURNING lock_id, holder_txn_id, expired_at;`

	start := time.Now()
	rows, err := r.qc.QueryContext(ctx, query, lockID, txnID, r.renewInterval)
	r.operationDuration.WithLabelValues(virtualStorage, "trylock").Observe(time.Since(start).Seconds())
	if err != nil {
		r.lockAcquiredTotal.WithLabelValues(virtualStorage, "error").Inc()
		deregister()
		return tryLockResult{
			Acquired: false,
			Err:      fmt.Errorf("acquire repo reference write lock: %s, %w", lockID, err),
		}
	}
	defer func() {
		if err := rows.Close(); err != nil {
			r.logger.WithError(err).Error("close rows")
		}
	}()
	if rows.Next() {
		_, alreadyHeld := r.lockAcquiredAt.LoadOrStore(lockID, time.Now())
		if !alreadyHeld {
			r.locksHeld.WithLabelValues(virtualStorage).Inc()
			r.lockAcquiredTotal.WithLabelValues(virtualStorage, "new_acquisition").Inc()
		}
		deregister()
		unlockFn := func() error {
			return r.unlock(virtualStorage, relativePath, txnID)
		}
		renewFn := func(renewCtx context.Context) error {
			return r.renew(renewCtx, virtualStorage, relativePath, txnID)
		}
		return tryLockResult{
			Acquired: true,
			Unlock:   unlockFn,
			Renew:    renewFn,
		}
	}
