### Title
Cache-key collision in `GetArchive` via unsafe field concatenation - ([File: internal/gitaly/service/repository/archive.go])

### Summary
`createArchiveCacheKey` builds the lookup key for Gitaly's shared, process-wide `streamcache.Cache` by writing three separate, variable-length, attacker-influenced fields directly into a SHA-256 hash with no length prefixes and no separator between fields (only within `pathspecs`/`args` is a comma used, which is itself ambiguous). This is the same "unsafe packing" bug class as `DKGResultVerification.verify`'s `abi.encodePacked(groupPubKey, misbehaved)`: two logically different requests can be crafted so that the concatenated bytes are identical, producing the same cache key and causing the streamcache to return a previously cached (i.e., wrong) archive stream for a different request.

### Finding Description
`createArchiveCacheKey` in `internal/gitaly/service/repository/archive.go` computes the cache key as: [1](#0-0) 

```go
func createArchiveCacheKey(gitLabProjectPath string, args []string, pathspecs []string) string {
	cacheKeyHash := sha256.New()
	cacheKeyHash.Write([]byte(gitLabProjectPath))
	cacheKeyHash.Write([]byte(strings.Join(args, ",")))
	cacheKeyHash.Write([]byte(strings.Join(pathspecs, ",")))
	return hex.EncodeToString(cacheKeyHash.Sum(nil))
}
```

There is no length-prefixing and no unambiguous delimiter between `gitLabProjectPath`, the joined `args`, and the joined `pathspecs`. All three inputs are influenced by the RPC caller:

- `gitLabProjectPath` comes from `repo.GetGlProjectPath()`, a field of the `Repository` message supplied in the request.
- `args` is built from `in.GetCommitId()` and, depending on `ElidePath`, the validated archive path.
- `pathspecs` is built from the validated archive path and the validated `exclude` entries (prefixed with `":(exclude)"`). [2](#0-1) [3](#0-2) 

Because `storage.ValidateRelativePath` only rejects path traversal, not commas or other characters, an attacker can shift bytes across the `args`/`pathspecs`/`gitLabProjectPath` boundaries (e.g. moving a comma from inside one field into the join separator of another) so that two semantically different requests produce byte-identical hash input and thus the same cache key.

Crucially, `s.archiveCache` (a `streamcache.Cache`) is a single, process-wide, in-memory index shared across **all** repositories and requests handled by that Gitaly node — the cache key is the *only* thing that scopes an entry to a particular repository/commit/path: [4](#0-3) 

`s.archiveCache.Fetch(ctx, cacheKey, ...)` therefore returns whichever stream was first stored under a colliding key, regardless of which repository/commit/path it actually corresponds to: [3](#0-2) 

Notably, Gitaly's own disk-cache keyer already recognizes and mitigates exactly this bug class elsewhere in the codebase via a `prefixLen` helper that length-prefixes each component before hashing: [5](#0-4) 

```go
// prefixLen reduces the risk of collisions due to different combinations of
// concatenated strings producing the same content.
// e.g. f+oobar and foo+bar concatenate to the same thing: foobar
func prefixLen(s string) []byte {
	return []byte(fmt.Sprintf("%08x%s", len(s), s))
}
```

`createArchiveCacheKey` was not given this same protection.

### Impact Explanation
A collision causes the streamcache to serve a cached archive generated for a different commit/path/exclude-set (and potentially a different `GlProjectPath`) instead of the archive actually requested. Because the cache is process-wide and unscoped to repository storage, this can lead to cross-repository/cross-project information disclosure of archive contents (source code, files) to an unauthorized caller, or cause a legitimate caller to silently receive stale/incorrect archive data for their repository.

### Likelihood Explanation
Exploitation requires the attacker (or a compromised/malicious client of the RPC) to be able to issue `GetArchive` requests with a crafted `Repository.GlProjectPath`, `CommitId`, `Path`, and `Exclude` values such that the concatenated byte streams collide, and to race the request so their crafted key overlaps with a live/recently created cache entry (the streamcache has a max-age eviction window). This is feasible for any client capable of sending `GetArchiveRequest` RPCs with attacker-controlled `path`/`exclude`/`Repository` fields, which is realistic for an ordinary authenticated Gitaly RPC caller.

### Recommendation
Length-prefix each component (mirroring `internal/cache/keyer.go`'s `prefixLen`) before writing it into the SHA-256 hash in `createArchiveCacheKey`, and apply the same treatment to each element of `args` and `pathspecs` individually rather than joining them with a plain comma. Consider also explicitly including the repository's canonical storage/relative path (not just `GlProjectPath`) in the key to further reduce ambiguity risk.

### Proof of Concept
Two `GetArchiveRequest`s constructed so that:
```
gitLabProjectPath_A + join(args_A, ",") + join(pathspecs_A, ",")
==
gitLabProjectPath_B + join(args_B, ",") + join(pathspecs_B, ",")
```
as raw byte strings, while `args_A/pathspecs_A` and `args_B/pathspecs_B` correspond to different commit IDs / paths / exclude lists (e.g. by moving a comma character across the `Path`/`Exclude` boundary, since `storage.ValidateRelativePath` permits commas in relative paths). The second request, sent shortly after the first while the entry is still in `s.archiveCache`'s in-memory index, receives the first request's cached archive stream instead of generating its own.

func (c *cache) getStream(key string, create func(io.Writer) error) (_ io.ReadCloser, _ *waiter, created bool, err error) {
	c.m.Lock()
	defer c.m.Unlock()

	if e := c.index[key]; e != nil {
		if r, err := e.pipe.OpenReader(); err == nil {
			return r, e.waiter, false, nil
		}

		// In this case err != nil. That is allowed to happen, for instance if
		// the *filestore cleanup goroutine deleted the file already. But let's
		// remove the key from the cache to save the next caller the effort of
		// trying to open this entry.
		c.delete(key)
	}

	r, e, err := c.newEntry(key, create)
	if err != nil {
		return nil, nil, false, err
	}

	c.index[key] = e
	c.setIndexSize()

	return r, e.waiter, true, nil
}
