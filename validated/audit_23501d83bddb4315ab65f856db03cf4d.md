### Title
Unsolicited `StackerDBHandshakeAccept`/`HandshakeAccept` allows silent public-key swap on an already-authenticated connection - (File: stackslib/src/net/chat.rs)

### Summary
`handle_handshake_accept` (chat.rs:1338-1391) calls `update_from_handshake_data` (chat.rs:1131-1167) unconditionally on any inbound `HandshakeAccept`/`StackerDBHandshakeAccept`, regardless of whether the message was solicited and regardless of whether `handshake_accept.handshake.node_public_key` matches the key already bound to the connection. The only check performed is a debug log comparing old vs. new key; there is no cryptographic re-proof requirement or solicitation check before `self.connection.set_public_key(Some(pubk.clone()))` executes.

### Finding Description
The claimed equality is confirmed by the code: in `update_from_handshake_data`, the current key `cur_pubk_opt = self.connection.get_public_key()` is compared to the new key `pubk` derived purely from the payload's `HandshakeData.node_public_key` field, and if they differ, `updated` is simply set to `true` and `self.connection.set_public_key(Some(pubk.clone()))` (chat.rs:1149-1164) is executed unconditionally — with no signature or ownership proof tying `pubk` to the specific `HandshakeAccept` message content. Inbound message authenticity is enforced only at the transport/preamble level against the connection's *currently bound* public key (i.e., the OLD key, already proven via the original `Handshake`); the *inner* `node_public_key` field of `HandshakeAcceptData.handshake` is untrusted, attacker-supplied payload data that is never itself proven by a signature from the claimed new key.

Consequently, an attacker who has completed one legitimate `Handshake` (binding key P1/P2 on both sides) can subsequently send an unsolicited `StackerDBHandshakeAccept` — a message type that, per protocol intent, should only be processed as a reply to the receiver's own prior outbound `Handshake` — with `handshake.node_public_key` set to an arbitrary P3. Because `handle_authenticated_control_message` dispatches to `handle_handshake_accept` without checking `connection.is_solicited(msg)` for this message type, and `handle_handshake_accept` unconditionally calls `update_from_handshake_data`, the connection's bound public key silently flips to P3 with zero cryptographic proof that the attacker (or anyone) possesses the private key for P3.

### Impact Explanation
The immediate, concretely provable effect is corruption of the conversation's identity-binding invariant: `self.connection`'s public key — which is supposed to represent a cryptographically-proven peer identity established via `Handshake` — is silently reassigned via a payload field with no signature proof over the new key. Note that `handle_handshake_accept` itself performs no PeerDB persistence (the `Neighbor::load_and_update`/`save_update` re-keying logic exists only in `handle_handshake`, not `handle_handshake_accept`), so this specific bug's confirmed blast radius is the in-memory `ConversationP2P` state of the victim's own connection, and since subsequent messages on that conversation will then be signature-checked against P3, the attacker (who does not hold P3's private key, if P3 is chosen to impersonate some other real peer) effectively breaks/DoSes their own established connection unless they generate their own fresh P3. I was not able to confirm during this investigation whether any downstream consumer (e.g. neighbor-walk logic in `neighbors/walk.rs`) subsequently treats this swapped key as if it were a proven identity and persists it to PeerDB or propagates it — that would be required to elevate this to a network-wide forged-data or unauthenticated-write finding, and I did not have remaining tool budget to fully trace that path.

### Likelihood Explanation
Preconditions are low-cost and fully attacker-controlled: any remote peer can complete one legitimate handshake (no privileged role required) and then send a single crafted `StackerDBHandshakeAccept`/`HandshakeAccept` message over the already-authenticated channel. No solicitation state or additional secret is required, since `handle_authenticated_control_message` does not gate this message type on `is_solicited`.

### Recommendation
In `handle_handshake_accept`, verify that the message was actually solicited (check `self.connection.is_solicited(message)` / that a matching outbound `Handshake` request with the corresponding sequence number is outstanding) before processing it at all. Additionally, in `update_from_handshake_data`, refuse to silently "upgrade" the bound public key from an Accept-path message unless the new key equals the previously verified key, or unless the message is a legitimate re-handshake (`Handshake`, not `HandshakeAccept`) that has independently been signature-verified against the new key itself.

### Proof of Concept
Net test plan (analogous to existing `chat.rs`/`net/tests` handshake tests using two in-memory `ConversationP2P` instances, `convo_1` and `convo_2`):
1. Complete a normal handshake between `convo_1` (local, key P1) and `convo_2` (remote, key P2) via `convo_1.handle_handshake`/`convo_2.handle_handshake` so `convo_1.connection.get_public_key() == Some(P2)`.
2. Construct a fresh `StacksMessage` from `convo_2` containing `StacksMessageType::StackerDBHandshakeAccept(HandshakeAcceptData { handshake: HandshakeData { node_public_key: P3_buffer, .. }, .. }, StackerDBHandshakeData{..})`, signed with P2's private key (the currently bound, legitimately-proven key), with a nonce/seq not tied to any outstanding request from `convo_1`.
3. Feed it to `convo_1.chat`/`handle_authenticated_control_message` as an inbound authenticated message.
4. Assert `convo_1.connection.get_public_key() == Some(P3)` afterward — demonstrating the key swap occurred with zero signature proof over P3, at the `self.connection.set_public_key(Some(pubk.clone()))` call site, `stackslib/src/net/chat.rs:1164`. [1](#0-0) [2](#0-1)

    pub fn update_from_handshake_data(
        &mut self,
        preamble: &Preamble,
        handshake_data: &HandshakeData,
    ) -> Result<bool, net_error> {
        let pubk = handshake_data
            .node_public_key
            .to_public_key()
            .map_err(|e| net_error::DeserializeError(e.into()))?;

        self.peer_version = preamble.peer_version;
        self.peer_network_id = preamble.network_id;
        self.peer_services = handshake_data.services;
        self.peer_expire_block_height = handshake_data.expire_block_height;
        self.handshake_addrbytes = handshake_data.addrbytes.clone();
        self.handshake_port = handshake_data.port;
        self.data_url = handshake_data.data_url.clone();

        let mut updated = false;
        let cur_pubk_opt = self.connection.get_public_key();
        if let Some(cur_pubk) = cur_pubk_opt {
            if pubk != cur_pubk {
                debug!(
                    "{:?}: Upgrade key {:?} to {:?} expires {:?}",
                    &self,
                    &to_hex(&cur_pubk.to_bytes_compressed()),
                    &to_hex(&pubk.to_bytes_compressed()),
                    self.peer_expire_block_height
                );
                updated = true;
            }
        }

        self.connection.set_public_key(Some(pubk.clone()));

        Ok(updated)
    }

    fn handle_handshake_accept(
        &mut self,
        burnchain_view: &BurnchainView,
        preamble: &Preamble,
        handshake_accept: &HandshakeAcceptData,
        stackerdb_accept: Option<&StackerDBHandshakeData>,
    ) -> Result<(), net_error> {
        self.update_from_handshake_data(preamble, &handshake_accept.handshake)?;
        self.peer_heartbeat =
            if handshake_accept.heartbeat_interval > (MAX_PEER_HEARTBEAT_INTERVAL as u32) {
                debug!(
                    "{:?}: heartbeat interval is too long; forcing default maximum",
                    self
                );
                MAX_PEER_HEARTBEAT_INTERVAL as u32
            } else {
                handshake_accept.heartbeat_interval
            };

        if let Some(stackerdb_accept) = stackerdb_accept {
            if stackerdb_accept.rc_consensus_hash == burnchain_view.rc_consensus_hash {
                // remote peer is in the same reward cycle as us.
                self.update_from_stacker_db_handshake_data(stackerdb_accept);
            } else {
                // remote peer's burnchain view has diverged, so assume no longer replicating (we
                // can't talk to it anyway).  This can happen once per burnchain block for a few
                // seconds as nodes begin processing the next Stacks blocks, but it's harmless -- at worst, it
                // just means that no stacker DB replication happens between this peer and
                // localhost during this time.
                self.clear_stacker_db_handshake_data();
            }
        } else {
            // no longer replicating
            self.clear_stacker_db_handshake_data();
        }

        self.stats.last_handshake_time = get_epoch_time_secs();

        debug!(
            "HandshakeAccept from {:?}: set public key to {:?} expiring at {:?} heartbeat {}s",
            &self,
            &to_hex(
                &handshake_accept
                    .handshake
                    .node_public_key
                    .to_public_key()
                    .unwrap()
                    .to_bytes_compressed()
            ),
            handshake_accept.handshake.expire_block_height,
            self.peer_heartbeat
        );
        Ok(())
    }
