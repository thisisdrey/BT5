### Title
Stale oracle quotes let users swap/mint synths at off-market prices, draining collateral backing - ([File: contracts/Pool.sol])

### Summary
`Pool.swap` prices synthetic-token exchanges exclusively through `masterOracle().quote()` with no reference to actual market prices and no slippage/deadline protection. Chainlink-style feeds only update on heartbeat or deviation-threshold crossings, so the oracle price can legitimately lag the true market price by up to ~1% while remaining "correct" per the feed. Because `FeeProvider.swapFees` is a per-pair mapping that defaults to `0` for any pair the governor has not explicitly configured, an unprivileged user can buy the underpriced synth (or the underpriced collateral asset) on the open market and atomically swap/mint against the stale oracle quote, extracting the spread at the expense of the pool's collateral backing. The same stale quote feeds `DebtToken.issue`, letting an attacker borrow synths against collateral whose oracle price is stale-high, creating bad debt once the feed updates.

### Finding Description
`Pool.swap` is public, `nonReentrant`, gated only by `isSwapActive` and synth-existence checks. It burns `syntheticTokenIn_` from the caller and mints `syntheticTokenOut_` according to `quoteSwapOut`, which calls `masterOracle().quote(syntheticTokenIn_, syntheticTokenOut_, amountIn_)` and deducts only `feeProvider.swapFees(in, out)` (Pool.sol:642-668, 508-525). `FeeProvider.swapFees` is a plain `mapping(address => mapping(address => uint256))`; it is `0` for every pair not explicitly configured (FeeProvider.sol:137-143), which the test suite confirms (`expect(feeProvider.swapFees(msETH, msDOGE)).eq(0)`).

Two reachable exploit paths:

1. **Synth-swap arbitrage.** When the market price of synthIn's underlying drops within the feed's deviation threshold so the oracle still reports the stale-high price, the attacker buys synthIn cheaply on an external venue (or mints it via their own collateralized debt position), calls `swap(synthIn, synthOut, amountIn)`, and receives `amountOut` minted at the stale oracle rate. The minted synthOut is a claim on the system's shared collateral; the extra value minted is not backed by anything, diluting all other debt holders.

2. **Overvalued-collateral issuance.** `DebtToken.issue`/collateralization checks value deposits through the same `masterOracle`. If collateral's oracle price is stale-high relative to market, the attacker deposits market-cheap collateral, issues synth debt up to the (overstated) collateral value, sells the synths, and abandons the position — once the feed updates the position is undercollateralized, i.e. protocol bad debt.

Neither path requires same-transaction oracle manipulation, privileged roles, or malformed input — only a naturally occurring stale price within the feed's deviation band, exactly the condition described in the reference report. `whenNotShutdown`, `nonReentrant`, `SynthContext` checks, and supply caps do not prevent it.

### Impact Explanation
Value minted through `swap` at a stale rate is unbacked: total synth liabilities exceed the USD value of locked collateral, degrading solvency and imposing losses on remaining collateral depositors/synth holders (bad debt after the oracle corrects and positions become unliquidatable-profitably). Repeatable on every heartbeat window the deviation persists.

### Likelihood Explanation
Requires a configured `isSwapActive` pool, a synth pair whose `swapFees` is below the feed's deviation threshold (fees default to 0), and a market move within the heartbeat that stays inside the deviation band — a routine occurrence for Chainlink feeds (e.g., ~0.5–1% deviations on major pairs). An attacker can monitor and act permissionlessly with flash-borrowed capital. Caveat: `IMasterOracle` is an external dependency (only a mock exists in-repo), so the concrete deviation parameters depend on the deployed oracle implementation; the finding holds for any heartbeat/deviation-based feed.

### Recommendation
- Enforce a non-zero minimum swap fee (or a global floor) covering the worst-case oracle deviation for each pair, rather than defaulting `swapFees` to 0.
- Add a staleness check (reject or price more conservatively when `updatedAt` is old) and/or bound quotes against a secondary price source.
- Charge a mint/issue fee sized to exceed the oracle deviation window on collateral, and add slippage/deadline parameters to `swap` so callers bind the execution price.

### Proof of Concept
```solidity
// Foundry fork sketch (mainnet), assuming msETH->msUSD pair has swapFee == 0
// and ETH/USD feed is stale-high by ~1% within its deviation threshold.
function test_staleOracleSwap() public {
    // ETH market price fell 0.9% below oracle's last reported price.
    // 1) Acquire msETH cheaply at market price (via own debt position or DEX).
    vm.startPrank(attacker);
    msdVaETH.deposit(collateralAtMarketPrice, attacker);   // collateral bought cheap
    msETHDebt.issue(amountToMintAtStaleOracleValue, attacker); // mint msETH

    // 2) Swap msETH -> msUSD at stale oracle rate, fee == 0
    uint256 inAmt = msETH.balanceOf(attacker);
    (uint256 quoted, ) = pool.quoteSwapOut(msETH, msUSD, inAmt);
    pool.swap(msETH, msUSD, inAmt);

    // 3) msUSD received exceeds market value of the msETH burned by ~0.9%.
    assertGt(msUSD.balanceOf(attacker), marketUsdValueOf(inAmt));
    // Attacker repays debt / sells msUSD; the excess minted synths are unbacked.
    vm.stopPrank();
}
```
The test analog confirms zero-fee swaps execute purely at oracle price (`Pool.test.ts` "should swap synthetic tokens (swapFee == 0)" expects `amountOut = amountInUsd / dogePrice` with no fee deduction).
