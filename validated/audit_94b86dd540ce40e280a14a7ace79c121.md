### Title
Protocol fee bypass on NEP-245/IMT `TokenDiff` intents via unit-splitting - (File: `contracts/defuse/core/src/intents/token_diff.rs`)

### Summary
`TokenDiff::token_fee` exempts NEP-245/IMT legs from fees only when the *per-intent* `amount` (the absolute delta of a single `TokenDiff` intent) is `<= 1`. Because fee assessment happens independently per `TokenDiff::execute_intent` call rather than on the net token flow of the whole `MultiPayload`/batch, a signer can convert one `-N` delta into `N` separate `-1` delta intents and pay zero fee instead of `protocol_fee.fee_ceil(N)`.

### Finding Description
The broken binding: for a NEP-245 token `T` moved with total negative delta `N` in a batch, `sum(fee_ceil for every executed negative delta of T)` should equal `protocol_fee.fee_ceil(N)` (the fee owed if the whole `-N` were expressed in one `TokenDiff`). Instead, when `N` unit deltas are submitted, the sum is `0`.

Code path: `TokenDiff::execute_intent` iterates `self.diff` and, for each negative delta, computes
```rust
let amount = delta.unsigned_abs();
let fee = Self::token_fee(token_id, amount, protocol_fee).fee_ceil(amount);
``` [1](#0-0) 

and `token_fee` waives the fee entirely for `Nep245`/`Imt` tokens whenever the local `amount <= 1`:
```rust
TokenIdType::Nep245 | TokenIdType::Imt if amount > 1 => {}
// do not take fees on NFTs and MTs with |delta| <= 1
TokenIdType::Nep171 | TokenIdType::Nep245 | TokenIdType::Imt => return Pips::ZERO,
``` [2](#0-1) 

This check is evaluated per `TokenDiff` intent, with no aggregation across multiple `TokenDiff` intents in the same `MultiPayload`, and no tracking of cumulative token flow for a signer/token pair across a batch. A signer holding an `mt.near` NEP-245 balance of `N` inside the Verifier can sign `N` separate `TokenDiff` intents (each with distinct nonces, valid signature, matched in the batch by corresponding positive legs elsewhere so the batch nets to zero as required by `TransferMatcher::finalize`), each with delta `-1` on the same `TokenId`. Each call to `token_fee` sees `amount == 1`, hits the waiver branch, and returns `Pips::ZERO`; `fees_collected` is never incremented for token `T`. The equivalent single intent with delta `-N` would have charged `protocol_fee.fee_ceil(N)` to `fee_collector` via `internal_add_balance` at the end of `execute_intent`. [3](#0-2) 

None of the existing guards (`MultiPayload::verify`, nonce/signature checks, `TransferMatcher::finalize`, `checked_*` arithmetic) address this because they only ensure signature validity and batch balance neutrality — they do not constrain how a signer partitions a given net flow into multiple signed `TokenDiff` intents.

### Impact Explanation
The `fee_collector` account is under-credited by exactly `protocol_fee.fee_ceil(N)` per exploited NEP-245/IMT flow, for every batch a signer chooses to construct this way, on any NEP-245/IMT token they can move (they don't even need to control issuance — they only need a Verifier balance to spend). This is repeatable per token, per batch, and by any account, so it results in systemic fee bypass on the entire NEP-245/IMT fee-collection mechanism, matching the "protocol fees bypassed" Critical category.

### Likelihood Explanation
The only precondition is holding a NEP-245/IMT balance inside the Verifier and constructing a `MultiPayload` with `N` unit-delta `TokenDiff` intents instead of one bulk intent — both are ordinary, unprivileged user actions requiring no special role, no signature forgery, and no additional cost beyond ordinary gas for `N` intents. This is trivially and consistently reproducible.

### Recommendation
Aggregate the fee-exemption check on the net per-token delta across the whole batch/signer scope rather than per-`TokenDiff`-intent, or remove the `amount <= 1` exemption entirely and always charge `fee_ceil` proportional to the actual amount moved, independent of how many intents the signer split the transfer into.

### Proof of Concept
`cargo test` in `contracts/defuse/core` (or a `near-workspaces` sandbox test under `tests/src/tests/defuse/intents/token_diff.rs`):
1. Set `protocol_fee = Pips::ONE_PERCENT` (or any `> Pips::ZERO`).
2. Case A: execute one `TokenDiff` intent with delta `-N` (`N > 1`) on a NEP-245 `TokenId`, matched by a corresponding positive delta elsewhere; assert `fees_collected` for that token equals `protocol_fee.fee_ceil(N)`.
3. Case B: execute `N` separate `TokenDiff` intents, each with delta `-1` on the same `TokenId` (each individually balanced by matching positive legs), inside one `MultiPayload`/`execute_intents` call; assert the sum of `fees_collected` for that token across all `N` intents equals `Pips::ZERO`.
4. Assert Case A's fee `!=` Case B's total fee (specifically `Case B total == 0 < Case A == protocol_fee.fee_ceil(N)`), demonstrating the fee bypass.
