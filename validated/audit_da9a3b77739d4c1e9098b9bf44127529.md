### Title
Truncation of the per-supply reward index permanently strands residual reward amounts - (File: contracts/RewardsDistributor.sol)

### Summary
`RewardsDistributor._calculateTokenIndex` converts elapsed rewards (`_deltaTimestamps * tokenSpeed`) into a per-token-supply index delta via `_tokensAccrued.wadDiv(_totalSupply)`. The fractional part of that division is discarded and never tracked anywhere. The sum of rewards credited to holders (`balanceOf.wadMul(deltaIndex)` per account) is therefore strictly less than `_deltaTimestamps * speed`, and the difference can never be claimed — an exact analog of the MultiRewards `leftover / rewardsDuration` truncation bug, where the residual is dropped instead of being carried into a `rewardResidual`-style accumulator.

### Finding Description
In `contracts/RewardsDistributor.sol:197-212`, each index update computes:

```solidity
uint256 _tokensAccrued = _deltaTimestamps * _speed;
uint256 _ratio = _totalSupply > 0 ? _tokensAccrued.wadDiv(_totalSupply) : 0;
_newIndex = (_supplyState.index + _ratio).toUint224();
```

`wadDiv` (WadRayMath.sol:39-41) rounds to the nearest wad and drops the remainder of `tokensAccrued * 1e18 / totalSupply`. Accounts are later credited via `_calculateTokenDelta` (lines 217-231): `token_.balanceOf(account_).wadMul(_deltaIndex)`. Because `_deltaIndex` is already truncated, `sum(balanceOf) * _deltaIndex < _tokensAccrued` whenever `tokensAccrued * WAD % totalSupply != 0`. There is no residual bookkeeping — the timestamp is advanced to `block.timestamp` on every update (lines 274-281), so the undistributed remainder is permanently orphaned in the contract rather than rolled into the next period.

`_updateTokenIndex` is invoked by the public, unguarded `updateBeforeMintOrBurn` (line 175) and `updateBeforeTransfer` (line 186), and implicitly by every `DepositToken`/`DebtToken` mint, burn, and transfer through the `updateRewardsBeforeMintOrBurn`/`updateRewardsBeforeTransfer` modifiers (DepositToken.sol:124-144, DebtToken.sol:114-121). Any EOA can therefore trigger the loss each block on every reward-tracked token.

### Impact Explanation
**Low.** The invariant `Σ credited rewards == elapsed * speed` breaks; the undistributed residual per update is bounded by roughly `totalSupply / 1e18` reward units — dust — but those rewards are permanently locked in `RewardsDistributor` since `_transferRewardIfEnoughTokens` only pays out recorded `tokensAccruedOf`. Additionally, `syncTokenSpeed` (lines 333-348) truncates `rewardRates * balance / totalSupply` when deriving `_speed` from the external Vesper pool, independently under-counting the emission rate, though that path is keeper-gated.

### Likelihood Explanation
**High.** The truncation occurs on virtually every index update — any deposit, withdraw, borrow, repay, transfer, liquidation, or public index poke — for every reward token, whenever `delta * speed * 1e18` is not exactly divisible by the token's `totalSupply`. Losses accumulate continuously across all tracked tokens.

### Recommendation
Track the residual explicitly, e.g. store a `rewardResidual[token_]` or a high-precision fractional index remainder, and fold `tokensAccrued - ratio * totalSupply / WAD` back into the next accrual so no emitted reward is dropped. Alternatively compute the index increment in a higher-precision denominator (e.g. accumulate `tokensAccrued` and divide lazily per-claim) so rounding never discards real amounts.

### Proof of Concept
Hardhat-style reproduction against `contracts/RewardsDistributor.sol`:

```ts
// Setup: rewardDistributor initialized, registered on pool,
// updateTokenSpeed(msdToken, speed = 1e18) called by governor.
// Alice holds 1 wei of a DepositToken with totalSupply = 3.

await msdToken.setTotalSupply(3);          // total supply = 3 wei
await msdToken.setBalance(alice, 1);

// Elapse exactly 1 second: tokensAccrued = 1e18
await time.increase(1);

// Anyone can trigger the index update:
await rewardsDistributor.connect(anyone).updateBeforeMintOrBurn(msdToken.address, alice.address);

// ratio = (1e18 * 1e18 + 1) / 3 = 333333333333333333 (wadDiv rounds)
// 3 * 333333333333333333 = 999999999999999999 < 1e18
// => 1 wei of reward (1e18 - 999999999999999999) is dropped permanently.

const accrued = await rewardsDistributor.tokensAccruedOf(alice.address);
// alice gets wadMul(1, ratio) = 0; the missing 1 wei is never claimable
// even though 1e18 was "emitted" during the elapsed second.
```

Generalized: for `totalSupply = S` and emission `A = delta * speed`, every update strands `A - floor(A * 1e18 / S) * S / 1e18` reward units with no recovery path, matching the MultiRewards residual-loss class.
