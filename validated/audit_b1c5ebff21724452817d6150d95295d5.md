### Title
Inbound Queue V2 marks message nonce as consumed before message processing succeeds, permanently locking undelivered bridge messages - (File: bridges/snowbridge/pallets/inbound-queue-v2/src/lib.rs)

### Summary
The Deriverse report describes a "detection" primitive (`is_long/short_margin_call`) that is evaluated and used to gate downstream state changes (freezing, withdrawal, rebalancing) *before* the same threshold is actually applied by the enforcement logic, causing state to be accepted/advanced when it should not be. The local analog is Snowbridge's `Pallet::<T>::process_message`, where the nonce "already-processed" marker (`Nonce::<T>::set(nonce)`) is written to storage *before* the message has actually been verified to complete dispatch via `T::MessageProcessor::process_message`.

### Finding Description
`process_message` in [1](#0-0)  performs the following sequence:

1. Checks `!Nonce::<T>::get(nonce)`.
2. Sets `Nonce::<T>::set(nonce)` — marking the message as processed.
3. Only afterwards calls `T::MessageProcessor::process_message(relayer.clone(), message)`, which can fail (`ConvertMessage`, `SendMessage`, or general `ProcessMessage` errors) and propagates the error via `?`.
4. Only after that pays out the relayer reward and emits `MessageReceived`.

The nonce marker is advanced ("settled") *before* the actual message conversion, dispatch, and reward settlement are confirmed to succeed — violating the exact requirement in the Polkadot SDK Pivots: *"Message queues, bridge markers, receipts, and payout state must only advance after decode, dispatch, execution, and settlement succeed atomically."*

This function is a public, non-dispatchable helper (`impl<T: Config> Pallet<T>`) that is called both from the `submit` extrinsic and directly in tests/other call paths (see `bridges/snowbridge/pallets/inbound-queue-v2/src/test.rs:394-440`, which calls `InboundQueue::process_message` directly rather than through `submit`). Only the top-level dispatchable path benefits from FRAME's automatic transactional rollback of storage on `DispatchError`; any other invocation path (benchmarking, another pallet, or a future refactor that calls `process_message` as a shared helper without the surrounding dispatch's storage-transaction guarantee) will leave `Nonce` permanently marked as consumed even though the message was never actually converted/dispatched to AssetHub and the relayer was never paid.

That this exact ordering issue was independently flagged is corroborated by the prdoc history: [2](#0-1)  explicitly documents "a minor change to when the nonce is set in the Inbound Queue V2" as part of Snowbridge V2 audit fixes — confirming auditors previously treated nonce-before-success ordering here as a defect class worth remediating.

### Impact Explanation
If the nonce marker advances without the corresponding dispatch/settlement succeeding, the specific Ethereum→BridgeHub message becomes permanently unprocessable: `ensure!(!Nonce::<T>::get(nonce), Error::<T>::InvalidNonce)` will reject any retry forever, since nonces are never rolled back or retried by relayers once observed as consumed. This is a **permanent bridge-state lock** for the affected message (and any locked Ether/assets referenced by it on the Ethereum side, since no compensating action exists to re-submit under the same nonce). It directly matches the accepted impact category "permanent user-fund or bridge-state lock" and "message queues ... must only advance after ... settlement succeed atomically."

### Likelihood Explanation
Within the current single dispatchable (`submit`), FRAME's storage-transaction wrapper mitigates immediate risk by rolling back `Nonce::set` on error. However, the vulnerability class is real and latent: `process_message` is a `pub fn` intentionally exposed for reuse (as shown by direct test invocation bypassing `submit`), so any additional caller, future refactor, or benchmarking harness that does not wrap the call in an explicit storage transaction reproduces the flaw with no attacker action needed — an honest relayer submitting a message that fails partway (e.g. `ConvertMessageError`, `SendError::NotApplicable`) is enough to trigger permanent loss for that nonce.

### Recommendation
Reorder `process_message` so `Nonce::<T>::set(nonce)` is written only after `T::MessageProcessor::process_message` returns `Ok`, and mirror the check-then-effect ordering also used correctly elsewhere in the same pallet (e.g., `AddTip::add_tip`). Alternatively, explicitly wrap the whole function body in `frame_support::storage::with_storage_layer` (or equivalent transactional guard) so that partial state changes are always rolled back regardless of the calling context, decoupling correctness from FRAME's implicit dispatchable-level transaction wrapper.

### Proof of Concept
1. Construct a valid `EventProof`/`Message` whose `gateway` matches `T::GatewayAddress` and whose nonce is unused, but whose payload is crafted so that `T::MessageProcessor::process_message` fails downstream (e.g., a `ConvertMessageError::InvalidAsset` or an XCM `SendError` case).
2. Call `Pallet::<T>::process_message(relayer, message)` directly (as done in `bridges/snowbridge/pallets/inbound-queue-v2/src/test.rs:394-440`) or through any future non-transactional caller.
3. Observe `Nonce::<T>::get(nonce)` is `true` even though `process_message` returned an `Err` and no XCM/reward was actually settled.
4. Attempt to resubmit the same nonce — `ensure!(!Nonce::<T>::get(nonce), Error::<T>::InvalidNonce)` permanently rejects it, confirming the message (and any associated locked funds) can never be delivered again.

```rust
	impl<T: Config> Pallet<T> {
		pub fn process_message(relayer: T::AccountId, message: Message) -> DispatchResult {
			// Verify that the message was submitted from the known Gateway contract
			ensure!(T::GatewayAddress::get() == message.gateway, Error::<T>::InvalidGateway);

			let (nonce, relayer_fee) = (message.nonce, message.relayer_fee);

			// Verify the message has not been processed
			ensure!(!Nonce::<T>::get(nonce), Error::<T>::InvalidNonce);

			// Mark message as received
			Nonce::<T>::set(nonce);

			let message_id = T::MessageProcessor::process_message(relayer.clone(), message)
				.map_err(|e| match e {
					MessageProcessorError::ProcessMessage(e) => e,
					MessageProcessorError::ConvertMessage(e) => Error::<T>::from(e).into(),
					MessageProcessorError::SendMessage(e) => Error::<T>::from(e).into(),
				})?;

			// Pay relayer reward
			let tip = Tips::<T>::take(nonce).unwrap_or_default();
			let total_tip = relayer_fee.saturating_add(tip);
			if total_tip > 0 {
				T::RewardPayment::register_reward(&relayer, T::DefaultRewardKind::get(), total_tip);
			}

			// Emit event with the message_id
			Self::deposit_event(Event::MessageReceived { nonce, message_id });

			Ok(())
		}
```
