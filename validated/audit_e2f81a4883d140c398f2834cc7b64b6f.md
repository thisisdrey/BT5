### Title
Users can split deposits into dust-sized calls to avoid deposit fees - ([File: contracts/DepositToken.sol](contracts/DepositToken.sol))

### Summary
`DepositToken.deposit()` calculates the deposit fee independently for every call through `quoteDepositOut()`. [1](#0-0)  The calculation uses `WadRayMath.wadMul()`, which rounds half-up and therefore returns zero whenever `amount * depositFee < 0.5e18`. [2](#0-1)  Because the only amount restriction is `amount_ != 0`, an unprivileged user can divide one deposit into many sufficiently small deposits and avoid the configured fee entirely. [3](#0-2) 

### Finding Description
`deposit()` transfers the full underlying amount to the treasury and then calls `quoteDepositOut(amount_)` to split the minted deposit-token supply between the depositor and the fee collector. [4](#0-3)  `quoteDepositOut()` computes `_fee = amount_.wadMul(_depositFee)` and gives the depositor the remaining `amount_ - _fee`. [5](#0-4) 

`wadMul()` returns `(a * b + HALF_WAD) / WAD`. [2](#0-1)  Consequently, for a configured fee `f`, every amount satisfying `amount < 0.5e18 / f` produces a zero fee. For example, at a 1% fee, deposits of 49 units or less produce no fee; at the maximum permitted 25% fee, a deposit of one unit still produces no fee. [6](#0-5) 

A normal deposit of `N` units is charged once, while `N` separate deposits of one unit each mint the full `N` deposit tokens to the user and zero deposit tokens to the fee collector whenever one unit is below the rounding threshold. [7](#0-6) 

### Impact Explanation
The protocol loses its configured deposit fee even though the depositor receives full deposit-token credit and the treasury receives the underlying collateral. [4](#0-3)  The missing fee is represented by deposit-token units that were never minted to `pool.feeCollector()`. [8](#0-7) 

This does not immediately create bad debt or insolvency because each individual deposit remains fully backed, but it permanently forfeits protocol revenue and breaks the intended proportional-fee accounting invariant. [5](#0-4) 

### Likelihood Explanation
Any EOA or contract holding the supported underlying can call `deposit()` repeatedly; no privileged role, timing condition, flash loan, oracle manipulation, or minimum deposit is required. [3](#0-2)  The attack is easiest for low-value token units and lower deposit fees, where more units fit below the zero-fee threshold. [2](#0-1)  The principal limitation is transaction gas: completely avoiding fees on economically large deposits may require many calls, but no code-level control prevents the technique. [3](#0-2) 

### Recommendation
Calculate deposit fees with explicit rounding in the protocol’s favor, such as `Math.mulDiv(amount_, depositFee, 1e18, Math.Rounding.Up)`. [5](#0-4)  Apply the same review to the analogous `issue` and `swap` fee calculations, which also use `wadMul()` for fee deductions. [9](#0-8) [10](#0-9)  Alternatively, enforce a minimum feeable amount, although ceiling-rounding better preserves proportional accounting without disabling dust deposits. [3](#0-2) 

### Proof of Concept
The following Foundry-style test demonstrates the invariant break for a configured 1% deposit fee: one deposit of 100 units pays one fee unit, while 100 one-unit deposits pay zero fees and still mint 100 user deposit tokens. [5](#0-4) 

```solidity
// SPDX-License-Identifier: MIT
pragma solidity 0.8.24;

import {Test} from "forge-std/Test.sol";
import {IERC20} from "../contracts/dependencies/openzeppelin/token/ERC20/IERC20.sol";
import {IDepositToken} from "../contracts/interfaces/IDepositToken.sol";
import {IFeeProvider} from "../contracts/interfaces/IFeeProvider.sol";

contract DepositFeeRoundingTest is Test {
    IDepositToken depositToken;
    IFeeProvider feeProvider;
    IERC20 underlying;
    address feeCollector;

    function testSplitDepositsAvoidFee() public {
        address alice = makeAddr("alice");

        // Deploy/fork setup:
        // - underlying = depositToken.underlying()
        // - feeProvider = depositToken.pool().feeProvider()
        // - feeCollector = depositToken.pool().feeCollector()
        // - configure feeProvider.depositFee() == 0.01e18
        // - give alice 200 underlying units and approve depositToken

        vm.startPrank(alice);
        underlying.approve(address(depositToken), type(uint256).max);

        uint256 userBefore = depositToken.balanceOf(alice);
        uint256 collectorBefore = depositToken.balanceOf(feeCollector);

        depositToken.deposit(100, alice);
        assertEq(depositToken.balanceOf(alice), userBefore + 99);
        assertEq(depositToken.balanceOf(feeCollector), collectorBefore + 1);

        userBefore = depositToken.balanceOf(alice);
        collectorBefore = depositToken.balanceOf(feeCollector);

        for (uint256 i; i < 100; ++i) {
            depositToken.deposit(1, alice);
        }

        assertEq(depositToken.balanceOf(alice), userBefore + 100);
        assertEq(depositToken.balanceOf(feeCollector), collectorBefore);

        vm.stopPrank();
    }
}
```

```text
    function quoteDepositOut(uint256 amount_) public view override returns (uint256 _amountToDeposit, uint256 _fee) {
        uint256 _depositFee = pool.feeProvider().depositFee();
        if (_depositFee == 0) {
            return (amount_, _fee);
        }

        _fee = amount_.wadMul(_depositFee);
        _amountToDeposit = amount_ - _fee;
```
