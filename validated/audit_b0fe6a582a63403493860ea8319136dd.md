### Title
Cross-contract StackerDB chunk-signature replay via contract-agnostic `auth_digest` - ([File: libstackerdb/src/libstackerdb.rs])

### Summary
`SlotMetadata::auth_digest` binds a chunk signature only to `(slot_id, slot_version, data_hash)` and never to the target StackerDB `contract_id`. Because multiple StackerDB contracts (e.g. `signers-0-1`, `signers-0-2`, `signers-0-3` for the same signer_set) are provisioned with the exact same signer-to-slot ordering by the `.signers` boot contract, a chunk validly signed by a slot owner for one contract is also a valid signature for the same slot in a sibling contract, letting anyone who observes it replay it cross-contract.

### Finding Description
`auth_digest` in `libstackerdb/src/libstackerdb.rs:160-166` computes `Sha512_256(slot_id || slot_version || data_hash)` with no `contract_id` component, and `SlotMetadata::verify`/`StackerDBChunkData::verify` (`libstackerdb/src/libstackerdb.rs:183-193`, `239-244`) only checks this digest against the claimed signer address — never against the contract the chunk is destined for.

Slot-to-signer assignment for the `.signers-{set}-{message_id}` contracts is derived from a single shared, ordered list per `signer_set` in `stackslib/src/chainstate/stacks/boot/signers.clar:40-43` (`stackerdb-get-signer-slots-page`), and every `signers-{set}-{message_id}` contract (`stackslib/src/chainstate/stacks/boot/signers-0-xxx.clar`, `signers-1-xxx.clar`) calls this same page for its slot ordering. The `MessageSlotID` enum (`libsigner/src/v0/messages.rs:68-78`, `BlockResponse=1`, `StateMachineUpdate=2`, `BlockPreCommit=3`) shows several such sibling contracts are simultaneously live for the same reward-cycle signer set — guaranteeing (not merely "plausibly") that the same signer address owns the same `slot_id` across `signers-0-1`, `signers-0-2`, and `signers-0-3` concurrently.

Both write paths trust the signature without checking the contract: `StackerDBTx::try_replace_chunk` (`stackslib/src/net/stackerdb/db.rs:398-438`) calls `slot_desc.verify(&slot_validation.signer)` with no reference to `smart_contract`, and `StackerDBSync::validate_received_chunk` (`stackslib/src/net/stackerdb/mod.rs:649-718`) likewise only checks `slot_metadata.verify(&addr)` against the per-contract signer lookup, again never mixing in `smart_contract_id`.

Attack: an unprivileged remote peer observes a legitimately signed `StackerDBChunkData{slot_id, slot_version, sig, data}` addressed to contract A (e.g. via the public `GET /v2/stackerdb/.../chunks/:slot_id` endpoint or via normal gossip), then sends the byte-identical payload to `POST /v2/stackerdb/:address/:contract_B/chunks` (`stackslib/src/net/api/poststackerdbchunk.rs:53-93`) naming sibling contract B, where the same address owns the same `slot_id`. `try_replace_chunk` accepts it as long as `slot_version` exceeds contract B's current stored version there — trivially true for any slot B hasn't yet received a write for, or that has a lower version. On acceptance the node automatically re-broadcasts it network-wide via `StacksMessageType::StackerDBPushChunk` (`stackslib/src/net/api/poststackerdbchunk.rs:315-324`), propagating the forged cross-contract chunk to all peers replicating contract B.

### Impact Explanation
This is an unauthenticated/unauthorized write into a StackerDB the signer never signed for, followed by network-wide propagation of forged data to every peer replicating that StackerDB — the node treats attacker-relayed bytes as an authentic write from the real slot owner for a context (contract B / message type) the owner never intended, since the signature says nothing about which contract it authorizes. This can also be used to grief the legitimate owner: the attacker can pre-empt contract B's slot with a high `slot_version`, causing the real owner's subsequent legitimate write to contract B to be rejected as `StaleChunk`.

### Likelihood Explanation
No privileged access is required: the attacker only needs to observe one publicly-readable, previously broadcast signed chunk (StackerDB reads require no authentication) and replay it to a sibling contract's public POST endpoint. The precondition (shared signer ordering across sibling `signers-{set}-{message_id}` contracts) is not a rare coincidence but the actual, always-true topology enforced by `signers.clar`. Cost is a single crafted HTTP POST; the attack is fully repeatable across every slot/message-type combination for the lifetime of a reward cycle.

### Recommendation
Include the target `contract_id` (or a stable identifier of it) in `SlotMetadata::auth_digest`, and thread the `smart_contract`/`contract_id` through `SlotMetadata::verify`/`StackerDBChunkData::verify` so that a signature is only valid for the specific StackerDB contract it was produced for. This requires a corresponding change to `StackerDBChunkData::sign`/`get_slot_metadata` call sites to pass the contract context, and is a wire-format-breaking change that needs versioning/migration.

### Proof of Concept
Rust test outline (extending `stackslib/src/net/stackerdb/tests/db.rs`):
1. Create two `StackerDBs` contracts `A` and `B` (e.g. `signers-0-1`-style and `signers-0-2`-style), each `reconfigure_stackerdb`'d with the identical `[(addr, 1)]` signer list at `slot_id = 0`, mirroring the shared-ordering guarantee from `signers.clar`.
2. Sign a `StackerDBChunkData { slot_id: 0, slot_version: 1, data: D }` with the slot owner's key, intended for contract `A`; call `tx.try_replace_chunk(&contract_A, &chunk.get_slot_metadata(), &chunk.data)` — assert `Ok(())`.
3. Without re-signing, call `tx.try_replace_chunk(&contract_B, &chunk.get_slot_metadata(), &chunk.data)` using the byte-identical `SlotMetadata`/signature.
4. Assert this call also returns `Ok(())` (accepted), demonstrating that `slot_desc.verify(&slot_validation.signer)` at `stackslib/src/net/stackerdb/db.rs:418` succeeds for contract `B` purely because `auth_digest` never included `contract_id` — proving the cross-contract replay is accepted rather than rejected with `BadSlotSigner`.     /// Get the digest to sign that authenticates this chunk data and metadata
    fn auth_digest(&self) -> Sha512Trunc256Sum {
        let mut hasher = Sha512_256::new();
        hasher.update(self.slot_id.to_be_bytes());
        hasher.update(self.slot_version.to_be_bytes());
        hasher.update(self.data_hash.0);
        Sha512Trunc256Sum::from_hasher(hasher)
    }

    /// Sign this slot metadata, committing to slot_id, slot_version, and
    /// data_hash.  Sets self.signature to the signature.
    /// Fails if the underlying crypto library fails
    pub fn sign(&mut self, privkey: &StacksPrivateKey) -> Result<(), Error> {
        let auth_digest = self.auth_digest();
        let sig = privkey
            .sign(&auth_digest.0)
            .map_err(|se| Error::SigningError(se.to_string()))?;

        self.signature = sig;
        Ok(())
    }

    /// Verify that a given principal signed this chunk metadata.
    /// Note that the address version is ignored.
    pub fn verify(&self, principal: &StacksAddress) -> Result<bool, Error> {
        let sigh = self.auth_digest();
        let pubk = StacksPublicKey::recover_to_pubkey_without_validating_low_s(
            sigh.as_bytes(),
            &self.signature,
        )
        .map_err(|ve| Error::VerifyingError(ve.to_string()))?;

        let pubkh = Hash160::from_node_public_key(&pubk);
        Ok(pubkh == *principal.bytes())
    }

    /// Add or replace a chunk for a given reward cycle, if it is valid
    /// Otherwise, this errors out with Error::StaleChunk
    pub fn try_replace_chunk(
        &self,
        smart_contract: &QualifiedContractIdentifier,
        slot_desc: &SlotMetadata,
        chunk: &[u8],
    ) -> Result<(), net_error> {
        // Check per-replica chunk-size cap.
        if (chunk.len() as u64) > self.config.chunk_size {
            return Err(net_error::StackerDBChunkTooBig(chunk.len()));
        }

        let slot_validation = self
            .get_slot_validation(smart_contract, slot_desc.slot_id)?
            .ok_or(net_error::NoSuchSlot(
                smart_contract.clone(),
                slot_desc.slot_id,
            ))?;

        if !slot_desc.verify(&slot_validation.signer)? {
            return Err(net_error::BadSlotSigner(
                slot_validation.signer,
                slot_desc.slot_id,
            ));
        }
        if slot_desc.slot_version <= slot_validation.version {
            return Err(net_error::StaleChunk {
                supplied_version: slot_desc.slot_version,
                latest_version: slot_validation.version,
            });
        }
        if slot_desc.slot_version > self.config.max_writes {
            return Err(net_error::TooManySlotWrites {
                supplied_version: slot_desc.slot_version,
                latest_version: slot_validation.version,
                max_writes: self.config.max_writes,
            });
        }
        self.insert_chunk(smart_contract, slot_desc, chunk)
    }
