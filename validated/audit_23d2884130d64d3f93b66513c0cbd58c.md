I found an important detail: `libsigner/src/events.rs` — the `SignerEventReceiver` HTTP server (used by `stacks-signer` to receive events like `/stackerdb_chunks`, `/proposal_response`, `/shutdown`) has **no authentication check whatsoever** on any of its endpoints.### Title
Unauthenticated `SignerEventReceiver` HTTP endpoint allows forged event injection and remote shutdown - (File: `libsigner/src/events.rs`)

### Summary
The `stacks-signer` process runs an HTTP event-receiver server (`SignerEventReceiver`) that the `stacks-node` is supposed to POST events to (`/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block`, `/shutdown`). This server performs **no authentication check** on any inbound request — it accepts and processes any POST body from any source that can reach the bound socket, and unconditionally honors `/shutdown`. This mirrors the Serena bug class: an unauthenticated, fixed-endpoint HTTP transport that both accepts arbitrary writes (forged event data fed directly into the signer's processing pipeline) and exposes an unauthenticated denial-of-service primitive.

### Finding Description
`SignerEventReceiver::next_event` in `libsigner/src/events.rs` dispatches purely on HTTP method/URL, with no credential check anywhere in the function: [1](#0-0) 

- `/status` → returns `OK` with no auth.
- `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block` → parsed via `process_event::<T, E>` directly from the raw request body, with no signature or token validation on the *transport* itself: [2](#0-1) 

- `/shutdown` → immediately sets the stop signal and terminates the receiver loop, with zero authentication: [3](#0-2) 

Nowhere in `bind`, `next_event`, or `process_event` is an `Authorization` header, token, or any other credential inspected. Compare this to the `auth_token`/`auth_password` documentation, which describes a token meant to secure "the communication channel between this node and a connected `stacks-signer` instance" — but that token is consumed only on the *node's outbound* side (e.g. `/v3/block_proposal`, `/v2/blocks?broadcast=1`); the signer's own receiver never checks it: [4](#0-3) [5](#0-4) 

The sample configuration binds this endpoint to `0.0.0.0:30000`, i.e., all interfaces, not just loopback: [6](#0-5) 

Once an attacker-forged `StackerDBChunksEvent` reaches `process_event`, it is converted via `TryFrom<StackerDBChunksEvent> for SignerEvent<T>`. Critically, this conversion only checks that a signature is *recoverable* (`chunk.recover_pk()`), not that it belongs to a legitimate, expected signer for that slot — that check exists only in the P2P/StackerDB code path (`validate_received_chunk` / `try_replace_chunk`), which this HTTP transport completely bypasses: [7](#0-6) 

Thus an attacker who can reach this port can (a) shut down the signer at will, and (b) inject fabricated events (self-signed StackerDB chunks, fake block-validation responses, fake burn-block/new-block events) directly into the signer's runloop input queue, entirely outside the node's normal StackerDB-signature-gated write path validated elsewhere (`stackslib/src/net/stackerdb/db.rs::try_replace_chunk`, `stackslib/src/net/stackerdb/mod.rs::validate_received_chunk`).

### Impact Explanation
- **Unauthenticated DoS**: any network-reachable client can call `POST /shutdown` and terminate the signer's event loop, taking the signer offline with a single unauthenticated request.
- **Unauthenticated forged-data injection**: the receiver accepts and forwards arbitrary attacker-crafted `StackerDBChunksEvent`/`BlockValidateResponse`/`BurnBlockEvent`/`StacksBlockEvent` payloads into the signer runloop's channel, bypassing the actual StackerDB owner-signature verification (`slot_desc.verify(&slot_validation.signer)`) that gates legitimate writes on the P2P path. This breaks the "authenticated vs. accepted-as-authentic" equality: data delivered over this transport is treated as if it originated from the trusted local node, without any proof of that origin.

This falls under "unauthenticated/unauthorized write to state" and "remote crash/unauthenticated DoS from few messages."

### Likelihood Explanation
High. No credentials, no prior interaction with the node, and no privileged position are required — only network reachability to the configured `endpoint` (which the sample config binds to `0.0.0.0`, i.e. all interfaces). A single crafted HTTP POST suffices for either the DoS or the forged-event injection.

### Recommendation
Add authentication to `SignerEventReceiver`'s HTTP handling (validate an `Authorization` header against the configured token/password before dispatching to `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block`, and especially `/shutdown`), and default `endpoint` binding to loopback rather than `0.0.0.0`.

### Proof of Concept
```
# No credentials required for any of the below:

# 1. Denial of service — kill the signer's event loop
curl -X POST http://<signer-endpoint>/shutdown

# 2. Forged data injection — craft an arbitrary self-signed StackerDBChunksEvent
#    (sign a fake chunk with any locally-generated key, then POST it)
curl -X POST http://<signer-endpoint>/stackerdb_chunks \
  -H "Content-Type: application/json" \
  -d '{"contract_id": "...", "modified_slots": [ ... attacker-signed chunk ... ]}'
```
Both requests are accepted and processed by `SignerEventReceiver::next_event` (`libsigner/src/events.rs:413-458`) with no authentication check anywhere in the call path.

*Note:* I could not fully trace whether every downstream consumer of `SignerEvent` (in `stacks-signer`'s runloop, out of the strict in-scope directories for this review) performs additional cross-validation before acting on injected events; the finding here is scoped to the transport-layer lack of authentication in `libsigner`, which is squarely in-scope.

        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)

                process_event::<T, BurnBlockEvent>(request)

fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}

    fn try_from(event: StackerDBChunksEvent) -> Result<Self, Self::Error> {
        let received_time = SystemTime::now();
        let signer_event = if event.contract_id.name.as_str() == MINERS_NAME

            let mut messages = vec![];

                match T::consensus_deserialize(&mut chunk.data.as_slice()) {
                    Ok(msg) => messages.push(msg),
                    Err(e) => {
                        debug!(
                            "Signer failed to deserialize miner chunk";
                            "slot_id" => chunk.slot_id,
                            "slot_version" => chunk.slot_version,
                            "data_len" => chunk.data.len(),
                            "error" => %e,
                        );
                    }
                }
            }
            SignerEvent::MinerMessages(messages)

                get_signers_db_signer_set_message_id(event.contract_id.name.as_str())
            else {
                return Err(EventError::UnrecognizedStackerDBContract(event.contract_id));
            };

            //
            // NOTE: the payload-type check below uses v0 `SignerMessageTypePrefix` semantics
            // (the mapping in `signer_message_payload_matches_lane` is fixed to v0). Future
            // signer-message versions must extend that mapping, or their chunks will not be
            // recognized here regardless of which `T` is in scope.
            let messages: Vec<_> = event

                            "payload_type_prefix" => type_byte,

                        return None;
                    }

                            "Skipping signer chunk: signature recovery failed";
                            "contract" => %event.contract_id,
                            "slot_id" => chunk.slot_id,
                        );
                        return None;

                    let Ok(message) = read_next::<T, _>(&mut &chunk.data[..]) else {

                            "contract" => %event.contract_id,
                            "slot_id" => chunk.slot_id,
                        );
                        return None;
                    };
                    Some((chunk.slot_id, pk, message))
