### Title
Transaction fees paid in a foreign asset are priced off manipulable spot AMM reserves, letting an attacker underpay for block resources - (File: `substrate/frame/transaction-payment/asset-conversion-tx-payment/src/payment.rs`)

### Summary
`pallet-asset-conversion-tx-payment`'s `SwapAssetAdapter::withdraw_fee` converts the native-denominated transaction fee into an amount of a user-chosen asset by calling `AssetConversion::quote_price_tokens_for_exact_tokens`, which reads the *live spot reserves* of a `pallet-asset-conversion` pool with no TWAP, minimum-liquidity floor, or manipulation resistance. Because pools are permissionlessly created and funded by any account (`create_pool`/`add_liquidity`), and because the price is fetched separately at `validate`/`prepare` time of each extrinsic rather than sourced from a robust oracle, a user can move the spot price of a shallow, self-owned pool in one extrinsic and then pay for a subsequent, resource-heavy extrinsic using that manipulated rate — systematically underpaying the resource cost the chain's fee mechanism is meant to enforce.

### Finding Description
`ChargeAssetTxPayment::validate` computes the native fee via `pallet_transaction_payment::Pallet::<T>::compute_fee` and then, if the signer selected a non-native `asset_id`, delegates pricing to `T::OnChargeAssetTransaction::withdraw_fee` [4](#0-3) . The canonical implementation, `SwapAssetAdapter`, quotes the required amount of the chosen asset using `S::quote_price_tokens_for_exact_tokens(asset_id, A::get(), fee, true)` [5](#0-4) , which in `pallet-asset-conversion` reduces to `get_amount_in` computed directly from `get_reserves` (the pool account's live token balances) [6](#0-5) .

The `QuotePrice` trait itself documents the weakness: "The quoted price is only guaranteed if no other swaps are made after the price is quoted and before the target swap (e.g., the swap is made immediately within the same transaction)" [7](#0-6) . No component in this path enforces that "same transaction" guarantee across extrinsics: `validate`/`prepare` for extrinsic N in a block reads whatever reserves exist at that point in state, which reflect any prior extrinsics (including ones from the same signer) already applied earlier in the same block.

Since `create_pool` and `add_liquidity` are permissionless [8](#0-7) , an attacker can create a pool between the native token and an arbitrary (even attacker-issued) asset with minimal liquidity, then in a single block: (1) swap heavily in one direction to skew the spot price, (2) submit a weight/length-heavy extrinsic with `ChargeAssetTxPayment` selecting that manipulated `asset_id`, paying a near-zero real amount, and (3) reverse the swap. The identical spot-price pattern (`SwapFirstAssetTrader` / `SingleAssetExchangeAdapter`) is also used for XCM execution and delivery fee payment [9](#0-8) [10](#0-9) , extending the same underpricing primitive to XCM message processing on Asset Hub and Penpal.

This is directly analogous to the Isomorph/Velodrome bug: pricing a resource (there, collateral; here, block-execution weight) using an unprotected spot AMM/peg value instead of a manipulation-resistant reference, letting an attacker exploit the gap between assumed and real value.

### Impact Explanation
An unprivileged account can pay drastically less than the intended fee for consuming block weight/length, since the "price" of the chosen asset relative to native currency is whatever the attacker set it to moments earlier in the same block via a permissionless swap on their own shallow pool. This is public underpriced work: validators/collators perform real computational work (weight) while receiving compensation computed from a manipulated exchange rate, degrading the economic security of block production and enabling spam at near-zero real cost — exactly the "public underpriced work that degrades block production" impact class.

### Likelihood Explanation
The attack requires no privileged role, no relayer, no validator collusion — only the ability to create/fund an AMM pool (permissionless) and submit multiple extrinsics in one block from the same account, both of which are ordinary user capabilities. The `QuotePrice` documentation itself acknowledges the price is only trustworthy "within the same transaction," confirming this is a known-but-unmitigated gap between extrinsics/blocks.

### Recommendation
Do not use raw, single-block spot pool reserves to price mandatory fee payments. Options: require a time-weighted average price (TWAP) or multi-block price observation for fee-asset conversion; enforce a minimum pool liquidity/depth relative to the fee amount before accepting an asset for fee payment; or bound how much the quoted rate is allowed to differ from a recent historical quote before rejecting the extrinsic in `can_withdraw_fee`/`withdraw_fee`.

### Proof of Concept
1. Attacker creates asset `X` and a `pallet-asset-conversion` pool `(Native, X)` with minimal liquidity via permissionless `create_pool`/`add_liquidity`.
2. In block `B`, attacker submits extrinsic 1: `swap_tokens_for_exact_tokens` (or `add_liquidity`/`remove_liquidity`) that skews the pool so `quote_price_tokens_for_exact_tokens(X, Native, fee, true)` returns a tiny amount of `X` for a given native `fee`.
3. Attacker submits extrinsic 2 in the same block: a heavy `RuntimeCall` wrapped with `ChargeAssetTxPayment::from(tip, Some(X))`. `validate`/`prepare` reads the now-skewed reserves and withdraws only the manipulated (tiny) amount of `X` per `substrate/frame/transaction-payment/asset-conversion-tx-payment/src/payment.rs:142-157`.
4. Attacker submits extrinsic 3 to reverse the initial swap, restoring the pool and recovering most of the value.
5. Net effect: extrinsic 2's real weight/length cost was paid for at a fraction of its intended value, confirmed by comparing `compute_fee` (native) against the actual value of `X` withdrawn.

	fn validate(
		&self,
		origin: <T::RuntimeCall as Dispatchable>::RuntimeOrigin,
		call: &T::RuntimeCall,
		info: &DispatchInfoOf<T::RuntimeCall>,
		len: usize,
		_self_implicit: Self::Implicit,
		_inherited_implication: &impl Encode,
		_source: TransactionSource,
	) -> ValidateResult<Self::Val, T::RuntimeCall> {
		let Some(who) = origin.as_system_origin_signer() else {
			return Ok((ValidTransaction::default(), Val::NoCharge, origin));
		};
		// Non-mutating call of `compute_fee` to calculate the fee used in the transaction priority.
		let fee = pallet_transaction_payment::Pallet::<T>::compute_fee(len as u32, info, self.tip);
		self.can_withdraw_fee(&who, call, info, fee)?;
		let priority = ChargeTransactionPayment::<T>::get_priority(info, len, self.tip, fee);
		let validity = ValidTransaction { priority, ..Default::default() };
		let val = Val::Charge { tip: self.tip, who: who.clone(), fee };
		Ok((validity, val, origin))
	}

	fn prepare(
		self,
		val: Self::Val,
		_origin: &<T::RuntimeCall as Dispatchable>::RuntimeOrigin,
		call: &T::RuntimeCall,
		info: &DispatchInfoOf<T::RuntimeCall>,
		_len: usize,
	) -> Result<Self::Pre, TransactionValidityError> {
		match val {
			Val::Charge { tip, who, fee } => {
				// Mutating call of `withdraw_fee` to actually charge for the transaction.
				let (_fee, initial_payment) = self.withdraw_fee(&who, call, info, fee)?;
				Ok(Pre::Charge { tip, who, initial_payment, weight: self.weight(call) })
			},
			Val::NoCharge => Ok(Pre::NoCharge { refund: self.weight(call) }),
		}
	}

		pub fn quote_price_tokens_for_exact_tokens(
			asset1: T::AssetKind,
			asset2: T::AssetKind,
			amount: T::Balance,
			include_fee: bool,
		) -> Option<T::Balance> {
			// Swaps reject zero amounts, match that behavior.
			if amount.is_zero() {
				return None;
			}
			let pool_account = T::PoolLocator::pool_address(&asset1, &asset2).ok()?;

			let (balance1, balance2) = Self::get_reserves(asset1.clone(), asset2.clone()).ok()?;

			if balance1.is_zero() {
				return None;
			}

			// Swap withdrawals from pools use `keep_alive=true` (Preserve). Use the same
			// preservation level to determine the actual withdrawable amount.
			let max_output =
				T::Assets::reducible_balance(asset2.clone(), &pool_account, Preserve, Polite);
			if amount > max_output {
				return None;
			}

			if include_fee {
				let fee = Self::pool_fee_for(&asset1, &asset2).ok()?;
				Self::get_amount_in(fee, &amount, &balance1, &balance2).ok()
			} else {
				Self::quote(&amount, &balance2, &balance1).ok()
			}
		}
