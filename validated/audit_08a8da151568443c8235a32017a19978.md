### Title
Unbounded length field in `ValidateMultiSign` precompile ABI decoding can trigger uncaught `OutOfMemoryError`/`ArrayIndexOutOfBoundsException` from attacker-controlled calldata - (File: `actuator/src/main/java/org/tron/core/vm/PrecompiledContracts.java`)

### Summary
`PrecompiledContracts.ValidateMultiSign.execute()` decodes attacker-controlled TVM call data into `DataWord[]` and immediately uses length/offset fields taken directly from that data to size and index arrays, *before* any exception-guarding `try/catch` is entered. This mirrors the CVE-2015-8270 bug class: an unauthenticated length field drives a buffer/array allocation and index computation with no upper-bound or in-range validation, which can crash the calling thread.

### Finding Description
`ValidateMultiSign.execute()` [1](#0-0)  parses `rawData` into words and, unless `VMConfig.allowTvmOsaka()` is active (which enforces `isValidAbiEncoding`, only checking overall length alignment, not embedded offsets/lengths), calls `extractBytesArray`/`extractSigArray` with an offset taken directly from `words[3]`.

`extractBytesArray` then reads a `len` value straight from attacker-controlled data and allocates an array of that size: [2](#0-1) 

Because `len = words[offset].intValueSafe()` is attacker-controlled and unbounded (only checked against `MAX_SIZE` *after* the array has already been allocated at line 1076), a crafted value near `Integer.MAX_VALUE` causes `new byte[len][]` to throw `OutOfMemoryError`, and crafted offsets can also produce `ArrayIndexOutOfBoundsException` in `words[offset + i + 1]` or `extractBytes`. Critically, this call happens at lines 1072-1074, entirely outside the `try { ... } catch (Throwable t)` block that only wraps the later signature-weight-computation loop (lines 1082-1117) [3](#0-2) . Any exception/error thrown during extraction is therefore uncaught by the precompile itself.

The repository's own test explicitly documents this as an acknowledged, un-hardened pre-activation code path: "this precompile has no outer catch, so a too-short input raises inside the decoder; that is the documented pre-activation failure mode the TIP explicitly preserves" [4](#0-3) . The mitigation (`isValidAbiEncoding`) that was added under TIP-854 only fires when `VMConfig.allowTvmOsaka()` is enabled and only validates the overall byte-length shape, not the actual offset/length fields used inside `extractBytesArray`/`extractSigArray`/`extractBytes32Array`.

### Impact Explanation
Any unprivileged account can invoke this precompile via a `TriggerSmartContract` transaction that issues a `CALL`/`STATICCALL` to the `ValidateMultiSign` precompiled address with crafted calldata. A malicious length field can cause the executing thread to throw `OutOfMemoryError` (attempted huge array allocation) or `ArrayIndexOutOfBoundsException`, uncaught within the precompile logic. Depending on how the outer TVM/`Program` exception handling wraps precompile calls, this can at minimum cause unexpected transaction processing failures, and in the `OutOfMemoryError` case risks broader JVM-level instability affecting the node process (a shared, unbounded-Error condition is not a normal recoverable `Exception`). This matches the CVE-2015-8270 bug class: an unauthenticated length field drives unsafe memory operations, leading to a crash / DoS condition.

### Likelihood Explanation
High from a reachability standpoint — no special privileges are required, only a standard `TriggerSmartContract` transaction targeting the fixed precompile address with attacker-chosen calldata. However, exploitability is gated by network activation flags (`VMConfig.allowTvmOsaka()`, `VMConfig.allowTvmSelfdestructRestriction()`); I could not verify from static code alone whether these TIPs are currently active on the target mainnet/testnet, which materially affects whether the guard (`isValidAbiEncoding`) is in effect. The test suite's explicit "pre-activation, no outer catch" comment indicates the maintainers are aware of and have chosen to preserve this failure mode for the deactivated-flag case.

### Recommendation
- Validate embedded offset and length fields (`words[3]`, and the `len` derived from `words[offset]`) against `MAX_SIZE` and against the bounds of `words.length`/`data.length` *before* allocating `bytesArray`/`bytes32Array`, independent of the `allowTvmOsaka` flag.
- Move the `extractBytesArray`/`extractSigArray`/`extractBytes32Array` invocations inside a `try/catch` in `ValidateMultiSign.execute()` (mirroring the pattern already used in `BatchValidateSign.execute()`, which wraps its entire `doExecute` call in `try { ... } catch (Throwable t) { return Pair.of(true, new byte[WORD_SIZE]); }`).
- Apply the same bounds validation unconditionally rather than gating it behind a feature-activation flag, so pre-activation calldata cannot reach unchecked array sizing.

### Proof of Concept
1. Construct calldata for a `CALL` to the `ValidateMultiSign` precompiled contract address such that:
   - `words[3]` (the offset word) resolves, after `/WORD_SIZE`, to an in-range index within the `words` array.
   - The word at that resolved index (used as `len` in `extractBytesArray`, line 403) is set to a very large value (e.g., `0x7FFFFFFF`).
2. Submit this as calldata in a `TriggerSmartContract` transaction on an account with any small amount of TRX/energy sufficient to invoke the call (energy formula `(data.length/32 - 5)/5 * 1500` is based on data length, not on the malicious embedded length).
3. Execution reaches `extractBytesArray(words, offset, rawData)` at line 1074 before the `try/catch` block, where `new byte[len][]` with `len = 0x7FFFFFFF` throws `OutOfMemoryError`, uncaught by `ValidateMultiSign.execute()`.

Note: I could not fully verify (within available tooling) how far up the `Program`/actuator call stack this uncaught `Throwable`/`Error` propagates, nor whether `VMConfig.allowTvmOsaka()`/`allowTvmSelfdestructRestriction()` are active on the deployed network — this affects whether the guard already mitigates the issue in the live environment.

  private static byte[][] extractBytesArray(DataWord[] words, int offset, byte[] data) {
    if (offset > words.length - 1) {
      return new byte[0][];
    }
    int len = words[offset].intValueSafe();
    byte[][] bytesArray = new byte[len][];
    for (int i = 0; i < len; i++) {
      int bytesOffset = words[offset + i + 1].intValueSafe() / WORD_SIZE;
      int bytesLen = words[offset + bytesOffset + 1].intValueSafe();
      bytesArray[i] = extractBytes(data, (bytesOffset + offset + 2) * WORD_SIZE,
          bytesLen);
    }
    return bytesArray;
  }

    public Pair<Boolean, byte[]> execute(byte[] rawData) {
      if (VMConfig.allowTvmOsaka()
          && !isValidAbiEncoding(rawData, ABI_HEADER_WORDS, ABI_ITEM_WORDS)) {
        return Pair.of(false, EMPTY_BYTE_ARRAY);
      }
      DataWord[] words = DataWord.parseArray(rawData);
      byte[] address = words[0].toTronAddress();

      byte[] data = words[2].getData();

      byte[] combine = ByteUtil.merge(address, ByteArray.fromInt(permissionId), data);
      byte[] hash = Sha256Hash.hash(CommonParameter
          .getInstance().isECKeyCryptoEngine(), combine);

      if (VMConfig.allowTvmSelfdestructRestriction()) {
        int sigArraySize = words[words[3].intValueSafe() / WORD_SIZE].intValueSafe();
        if (sigArraySize > MAX_SIZE) {
          return Pair.of(true, DATA_FALSE);
        }
      }
      byte[][] signatures = VMConfig.allowTvmSelfdestructRestriction() ?
          extractSigArray(words, words[3].intValueSafe() / WORD_SIZE, rawData) :
          extractBytesArray(words, words[3].intValueSafe() / WORD_SIZE, rawData);

      if (signatures.length == 0 || signatures.length > MAX_SIZE) {
        return Pair.of(true, DATA_FALSE);
      }

      AccountCapsule account = this.getDeposit().getAccount(address);
      if (account != null) {
        try {
          Permission permission = account.getPermissionById(permissionId);
          if (permission != null) {
            //calculate weight
            long totalWeight = 0L;
            List<byte[]> executedSignList = new ArrayList<>();
            for (byte[] sign : signatures) {
              byte[] recoveredAddr = recoverAddrBySign(sign, hash);

              sign = merge(recoveredAddr, sign);
              if (ByteArray.matrixContains(executedSignList, recoveredAddr)) {
                if (ByteArray.matrixContains(executedSignList, sign)) {
                  continue;
                }

              if (weight == 0) {

                return Pair.of(true, DATA_FALSE);

              executedSignList.add(sign);
              executedSignList.add(recoveredAddr);
            }

            if (totalWeight >= permission.getThreshold()) {
              return Pair.of(true, dataOne());
            }

        } catch (Throwable t) {
          if (t instanceof OutOfTimeException) {
            throw t;
          }
          logger.info("ValidateMultiSign error:{}", t.getMessage());
        }
