### Title
Linker archive symbol map parser trusts unvalidated entry count, causing out-of-bounds slice panic - ([File: src/cmd/link/internal/ld/ar.go])

### Summary
`readArmap` in the Go linker reads the entry count `c` directly from the archive symbol-map header (`/` or `/SYM64/` member) and uses it to slice and index the `contents` buffer without validating `c` against the buffer's actual length. A crafted host archive (`.a` file) with an oversized/overflowing entry count causes `contents[c*wordSize:]` or the subsequent `names[n]` walk to run out of the allocated buffer, panicking the linker (`cmd/link`) during a build that links against that archive. This mirrors the btrfs report's root cause: an on-disk count field is trusted to index a buffer sized independently of that count.

### Finding Description
`hostArchive` in [1](#0-0)  opens a host object archive (e.g. a `.a` static library referenced via cgo `#cgo LDFLAGS`/`-l` in a module) and, once it locates the `/`/`/SYM64/` armap member, calls `readArmap` to parse the symbol table: [2](#0-1) 

`contents` is allocated with `make([]byte, atolwhex(arhdr.size))`, i.e., sized from the archive member's own declared size field, and fully read via `io.ReadFull`. The count `c` (number of symbol entries) is then parsed from the first word(s) of that same buffer — also fully attacker-controlled — and used both to slice `names := contents[c*uint64(wordSize):]` and to drive a loop of `c` iterations that scans `names[n]` for a NUL terminator and repeatedly re-slices `contents = contents[wordSize:]`. There is no check that `c*wordSize <= len(contents)`, nor that enough name/offset bytes remain for `c` entries — the exact class of defect described in the btrfs report, where `num_entries` from an on-disk header is trusted to index a `pages[]` array sized independently by `i_size`. A crafted `c` (e.g., a very large value, or one that overflows `c*wordSize` in the `uint64` multiply and produces a deceptively small initial slice offset while the loop still runs `c` times) drives `names[n]` or the shrinking `contents[wordSize:]` operation past the buffer, hitting Go's slice-bounds-out-of-range panic in `readArmap`.

### Impact Explanation
Because Go's runtime enforces bounds checks, the direct consequence is a slice-bounds-out-of-range panic (denial of service) in the `go build`/`cmd/link` process rather than a raw OOB memory read/write as in the kernel case. This qualifies under Go's security policy for parser panics triggered by malicious input during the build/link pipeline (PUBLIC/low-severity track): the linker crashes while parsing a build-time archive supplied by a dependency/module rather than corrupting memory or executing arbitrary code.

### Likelihood Explanation
The victim workflow is `go build`/`go link` on a package that uses cgo and links a static archive (a common pattern for modules vendoring native libraries). An attacker who controls that `.a` file (e.g., a malicious module or a compromised vendored library) supplies a crafted armap header with an out-of-range entry count; no special privileges are required beyond the archive being consumed as ordinary build input, matching the "published module/archive... consumed by normal victim workflow" threat model.

### Recommendation
In `readArmap` (`src/cmd/link/internal/ld/ar.go`), validate `c` against the actual length of `contents` before slicing (`c*uint64(wordSize) <= uint64(len(contents))`, checking for multiplication overflow) and bound the name-scanning loop to remaining buffer length, failing with a clear "corrupt archive" error (as `Exitf`/error return) instead of panicking, analogous to how the btrfs fix rejects a free-space cache whose `num_entries`/`num_bitmaps` exceed the pages actually allocated.

// required objects. The general format is the same as a Go archive

	if ctxt.Debugvlog > 1 {
		ctxt.Logf("hostArchive(%s)\n", name)

		if os.IsNotExist(err) {
			// It's OK if we don't have a libgcc file at all.

			}
			return
		}
		Exitf("cannot open file %s: %v", name, err)
	}

	var magbuf [len(ARMAG)]byte
	if _, err := io.ReadFull(f, magbuf[:]); err != nil {
		Exitf("file %s too short", name)
	}

		Exitf("%s is not an archive file", name)
	}

	var arhdr ArHdr
	l := nextar(f, f.Offset(), &arhdr)

		Exitf("%s missing armap", name)

		armap = readArmap(name, f, arhdr)

func readArmap(filename string, f *bio.Reader, arhdr ArHdr) archiveMap {
	is64 := arhdr.name == "/SYM64/"
	wordSize := 4
	if is64 {
		wordSize = 8
	}

	contents := make([]byte, atolwhex(arhdr.size))
	if _, err := io.ReadFull(f, contents); err != nil {
		Exitf("short read from %s", filename)
	}

	var c uint64
	if is64 {
		c = binary.BigEndian.Uint64(contents)
	} else {
		c = uint64(binary.BigEndian.Uint32(contents))
	}
	contents = contents[wordSize:]

	ret := make(archiveMap)

	names := contents[c*uint64(wordSize):]
	for i := uint64(0); i < c; i++ {
		n := 0
		for names[n] != 0 {
			n++
		}
		name := string(names[:n])
		names = names[n+1:]

		// For Mach-O and PE/386 files we strip a leading
		// underscore from the symbol name.
		if buildcfg.GOOS == "darwin" || buildcfg.GOOS == "ios" || (buildcfg.GOOS == "windows" && buildcfg.GOARCH == "386") {
			if name[0] == '_' && len(name) > 1 {
				name = name[1:]
			}
		}

		var off uint64
		if is64 {
			off = binary.BigEndian.Uint64(contents)
		} else {
			off = uint64(binary.BigEndian.Uint32(contents))
		}
		contents = contents[wordSize:]

		ret[name] = off
	}

	return ret
}
