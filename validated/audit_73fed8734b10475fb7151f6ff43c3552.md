### Title
Unauthenticated forgery of `SignerEvent::MinerMessages` via unsigned `.miners` StackerDB chunks - ([File: libsigner/src/events.rs])

### Summary
`SignerEventReceiver::next_event` dispatches `POST /stackerdb_chunks` bodies to `process_event::<T, StackerDBChunksEvent>`, which calls `TryFrom<StackerDBChunksEvent>` for `SignerEvent<T>`. In the `MINERS_NAME` branch, chunk data is fed directly to `T::consensus_deserialize` and emitted as `SignerEvent::MinerMessages(messages)` with no call to `chunk.recover_pk()` or `chunk.verify()`, unlike the parallel `SIGNERS_NAME` branch which explicitly recovers/validates the signer's public key before accepting a chunk.

### Finding Description
The claimed equality — "every message in `SignerEvent::MinerMessages` == a message the current miner's key signed" — is broken by the code itself. In `libsigner/src/events.rs`:

```
549: let signer_event = if event.contract_id.name.as_str() == MINERS_NAME
550:     && event.contract_id.is_boot()
...
553:     for chunk in event.modified_slots {
554:         match T::consensus_deserialize(&mut chunk.data.as_slice()) {
555:             Ok(msg) => messages.push(msg),
...
567:     SignerEvent::MinerMessages(messages)
``` [1](#0-0) 

No `chunk.recover_pk()`/`chunk.verify()` call is made here, whereas the `SIGNERS_NAME` branch a few lines below explicitly does:
```
596: let Ok(pk) = chunk.recover_pk() else { ... }
``` [2](#0-1) 

The HTTP dispatch path leading here has no authentication whatsoever: `SignerEventReceiver::next_event` (`libsigner/src/events.rs:413-459`) routes `POST /stackerdb_chunks` straight to `process_event`, which reads the body, JSON-deserializes it into `StackerDBChunksEvent`, and calls `TryFrom` — with no header/secret/signature check anywhere in `libsigner` (`grep` for `auth_password`/`auth_token`/`Authorization` in `libsigner/` returns nothing). [3](#0-2) [4](#0-3) 

Sample configs show this listener bound to all interfaces, e.g. `sample/conf/signer/mainnet-signer-conf.toml` sets `endpoint = "0.0.0.0:30000"`, confirming remote reachability is an intended/supported deployment shape (the accompanying warning in `stacks-signer/src/lib.rs::SpawnedSigner::new` explicitly cautions about exposing this port to a non-local network). [5](#0-4) 

Attacker's exact message: open a TCP connection to the signer's bound event port and send:
```
POST /stackerdb_chunks HTTP/1.1
Content-Type: application/json
Content-Length: <n>

{"contract_id": {..boot .miners contract..}, "modified_slots": [{"slot_id":0,"slot_version":1,"sig":"00"*65-or-empty,"data": <bytes of a crafted SignerMessage::BlockProposal>}]}
```
This is exactly the shape exercised (with a *valid* signature) in the existing test `libsigner/src/tests/mod.rs::test_simple_signer` [6](#0-5)  — the only change needed to weaponize it is to skip `chunk.sign(&privk)` and populate `sig` with `MessageSignature::empty()`/garbage, since the `MINERS_NAME` branch never checks it.

### Impact Explanation
The signer runloop consumes `SignerEvent::MinerMessages(messages)` and treats every message therein as if it came from the legitimate, sortition-winning miner (it is documented as such: "A miner sent a message over `.miners`... `Vec<T>` will contain any signer messages made by the miner" [7](#0-6) ). An attacker who can merely open a TCP connection to the signer's event port can inject an arbitrary, unsigned `BlockProposal` (or any other `SignerMessage`) that the signer will process as genuine miner input — an unauthenticated write of forged data into the signer's decision-making input stream. This is a single-message, repeatable attack (matches: "unauthenticated/unauthorized write to state" — Critical).

### Likelihood Explanation
- Preconditions: the attacker needs only TCP reachability to the signer's `endpoint` (e.g. `0.0.0.0:30000` per sample config) — no RPC secret, signer key, or slot ownership required.
- Attacker cost: trivial — one crafted HTTP POST with a JSON body; no cryptographic work needed since `sig` is never checked on this branch.
- Repeatable indefinitely, for any number of forged messages.
- The only barrier is operational: whether operators bind the signer's event listener to loopback-only vs. a routable address. The repo's own sample config and code comments show this is a supported (if discouraged) deployment, and the vulnerability is a genuine code-level asymmetry (missing check that exists on the sibling branch), not merely a deployment misconfiguration.

### Recommendation
In the `MINERS_NAME` branch of `TryFrom<StackerDBChunksEvent> for SignerEvent<T>` (`libsigner/src/events.rs:549-567`), mirror the `SIGNERS_NAME` branch: call `chunk.recover_pk()` (or `chunk.verify()`) and validate the recovered public key corresponds to the currently-authorized miner (e.g. via the miner's registered StackerDB slot/election info) before accepting the chunk into `messages`. Reject/skip chunks that fail signature recovery or whose signer does not match the expected miner slot owner, exactly as is done for signer messages.

        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {

            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());

                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)

            }
        })?

fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}
