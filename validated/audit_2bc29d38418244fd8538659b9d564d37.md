### Title
Protected-branch/access-check bypass via `UpdateReferences` and `WriteRef` RPCs which mutate refs without invoking pre-receive/update hooks - (File: `internal/gitaly/service/ref/update_references.go`, `internal/gitaly/service/repository/write_ref.go`)

### Summary
The reported minievm issue is a class of "restriction only enforced at one entry point but bypassable through an alternate, lower-level path that achieves the same effect." In Gitaly, reference/permission gating (protected branches, force-push protection, custom `pre-receive`/`update` hooks) is enforced by running Git's `pre-receive`/`update` hooks, which post changes to Rails' `/internal/allowed` endpoint and execute admin-installed custom hooks, before any ref is mutated [1](#0-0) . This enforcement path is implemented via `updateref.UpdaterWithHooks`, which `OperationService` RPCs (e.g. `UserUpdateBranch`, `UserDeleteBranch`, `UserCommitFiles`) use to invoke `pre-receive`, migrate the quarantine directory, then `update`/`post-receive` [2](#0-1) .

However, Gitaly also exposes two other RPCs that mutate references directly through the low-level `updateref.New`/`Update`/`Commit` API and never call any hook manager at all: `RefService.UpdateReferences` [3](#0-2)  and `RepositoryService.WriteRef` [4](#0-3) . Neither of these code paths constructs a `gitcmd.NewHooksPayload`, invokes `hookManager.PreReceiveHook`, nor performs any external `/internal/allowed` access check or custom-hook execution — they simply validate the ref name/object IDs and call `updater.Commit()`.

### Finding Description
`updater.Update(...)`/`updater.Commit()` in both `UpdateReferences` and `WriteRef` write straight to `git update-ref` (or reftable) transactions with no `pre-receive`, `update`, or `post-receive` hook execution in between [5](#0-4) [6](#0-5) . This mirrors the minievm bug exactly: a high-level, gated path (`Create`/`Create2` calling `assertAllowedPublishers`, analogous to `UserUpdateBranch`/`UserDeleteBranch` calling `UpdaterWithHooks.UpdateReference` which triggers the Rails `/internal/allowed` check) coexists with a lower-level path that produces the same net effect (contract deployment / reference update) but skips the gating logic entirely (EVM opcode `CREATE` vs. `UpdateReferences`/`WriteRef`).

Since `UpdateReferences` and `WriteRef` are ordinary RPCs on the same gRPC service surface used for regular repository operations (not restricted to an internal-only service), any caller authorized to invoke gRPC methods against a repository (i.e., anyone who can reach Gitaly's RPC surface for that repository, the same trust boundary as `UserUpdateBranch`) can force-update or delete *any* reference — including protected branches or tags — without triggering the `pre-receive`/`update` hooks that GitLab relies on for protected-branch enforcement, force-push denial, and custom server hooks.

### Impact Explanation
An actor able to invoke `UpdateReferences`/`WriteRef` can silently rewrite protected branches, delete tags, or push disallowed history without the `/internal/allowed` Rails check or admin custom hooks ever running, completely bypassing GitLab's branch-protection and hook-based governance model. This is a direct analog of the reported "contract deployment restriction bypass": the intended gate (assertAllowedPublishers / pre-receive access checks) is only enforced on one code path while an alternate path exists in the same product surface to reach the same mutating capability.

### Likelihood Explanation
Both RPCs are always available on the standard `RefService`/`RepositoryService` interface, requiring no special configuration, feature flag, or privileged internal-only credential beyond ordinary Gitaly RPC access — the same access level required to call any other repository-mutating RPC such as `UserUpdateBranch`. No malicious peer, leaked token, or additional social-engineering step is required; a single crafted RPC call is sufficient.

### Recommendation
Route `UpdateReferences` and `WriteRef` through the same hook-invoking path (`updateref.UpdaterWithHooks`) used by `OperationService`, or explicitly document/restrict these RPCs so they cannot be used to bypass `pre-receive`/`update` hook enforcement (e.g., require an internal-only auth scope, or have Rails reject calls to these RPCs for user-facing ref mutations). At minimum, ensure any RPC capable of mutating references funnels through the same Rails `/internal/allowed` and custom-hook enforcement that `pre-receive`/`update` provide.

### Proof of Concept
1. As a client with standard Gitaly RPC access to a repository with a protected branch `refs/heads/main` and a custom `pre-receive` hook that rejects force-pushes to it.
2. Instead of calling `UserUpdateBranch` (which invokes `UpdaterWithHooks.UpdateReference` → `pre-receive` → Rails `/internal/allowed` → custom hooks, and would be rejected), call `RefService.UpdateReferences` with an `Update{ Reference: "refs/heads/main", OldObjectId: <current>, NewObjectId: <arbitrary-rewritten-history-oid> }` [7](#0-6) .
3. The RPC validates only ref format/object existence and commits the update directly via `updater.Commit()`, with no hook invocation, so the protected-branch/force-push restriction and any custom `pre-receive` logic are never evaluated — the branch is rewritten regardless of the intended restriction, exactly as the factory-contract path bypassed `assertAllowedPublishers` in the original report.

// UpdateReference updates a branch with a given commit ID using the Git hooks. If a quarantine
// directory is given, then the pre-receive, update and reference-transaction hook will be invoked
// with the quarantined repository as returned by the quarantine structure. If these hooks succeed,
// quarantined objects will be migrated and all subsequent hooks are executed via the unquarantined
// repository.
func (u *UpdaterWithHooks) UpdateReference(
	ctx context.Context,
	repoProto *gitalypb.Repository,
	user *gitalypb.User,
	quarantineDir *quarantine.Dir,
	reference git.ReferenceName,
	newrev, oldrev git.ObjectID,
	pushOptions ...string,
) error {
	var transaction *txinfo.Transaction
	if tx, err := txinfo.TransactionFromContext(ctx); err == nil {
		transaction = &tx
	} else if !errors.Is(err, txinfo.ErrTransactionNotFound) {
		return fmt.Errorf("getting transaction: %w", err)
	}

	repo := u.localrepo(repoProto)

	objectHash, err := repo.ObjectHash(ctx)
	if err != nil {
		return fmt.Errorf("detecting object hash: %w", err)
	}

	if reference == "" {
		return fmt.Errorf("reference cannot be empty")
	}
	if err := objectHash.ValidateHex(oldrev.String()); err != nil {
		return fmt.Errorf("validating old value: %w", err)
	}
	if err := objectHash.ValidateHex(newrev.String()); err != nil {
		return fmt.Errorf("validating new value: %w", err)
	}

	changes := fmt.Sprintf("%s %s %s\n", oldrev, newrev, reference)

	receiveHooksPayload := gitcmd.UserDetails{
		UserID:   user.GetGlId(),
		Username: user.GetGlUsername(),
		Protocol: "web",
	}

	// In case there's no quarantine directory, we simply take the normal unquarantined
	// repository as input for the hooks payload. Otherwise, we'll take the quarantined
	// repository, which carries information about the quarantined object directory. This is
	// then subsequently passed to Rails, which can use the quarantine directory to more
	// efficiently query which objects are new.
	quarantinedRepo := repoProto
	if quarantineDir != nil {
		quarantinedRepo = quarantineDir.QuarantinedRepo()
	}

	hooksPayload, err := gitcmd.NewHooksPayload(ctx, u.cfg, quarantinedRepo, objectHash, transaction, &receiveHooksPayload, gitcmd.ReceivePackHooks, featureflag.FromContext(ctx), storage.ExtractTransactionID(ctx)).Env()
	if err != nil {
		return fmt.Errorf("constructing hooks payload: %w", err)
	}

	var stdout, stderr bytes.Buffer
	if err := u.hookManager.PreReceiveHook(ctx, quarantinedRepo, pushOptions, []string{hooksPayload}, strings.NewReader(changes), &stdout, &stderr); err != nil {
		return fmt.Errorf("running pre-receive hooks: %w", wrapHookError(err, gitcmd.PreReceiveHook, stdout.String(), stderr.String()))
	}

func (s *server) writeRef(ctx context.Context, req *gitalypb.WriteRefRequest) error {
	repo := s.localRepoFactory.Build(req.GetRepository())

	if string(req.GetRef()) == "HEAD" {
		if err := repo.SetDefaultBranch(ctx, s.txManager, git.ReferenceName(req.GetRevision())); err != nil {
			return fmt.Errorf("setting default branch: %w", err)
		}

		return nil
	}

	return updateRef(ctx, repo, req)
}

func updateRef(ctx context.Context, repo *localrepo.Repo, req *gitalypb.WriteRefRequest) (returnedErr error) {
	objectHash, err := repo.ObjectHash(ctx)
	if err != nil {
		return fmt.Errorf("detecting object format: %w", err)
	}

	var newObjectID git.ObjectID
	if objectHash.IsZeroOID(git.ObjectID(req.GetRevision())) {
		// Passing the all-zeroes object ID as new value means that we should delete the
		// reference.
		newObjectID = objectHash.ZeroOID
	} else {
		// We need to resolve the new revision in order to make sure that we're actually
		// passing an object ID to git-update-ref(1), but more importantly this will also
		// ensure that the object ID we're updating to actually exists. Note that we also
		// verify that the object actually exists in the repository by adding "^{object}".
		var err error
		newObjectID, err = repo.ResolveRevision(ctx, git.Revision(req.GetRevision())+"^{object}")
		switch {
		case errors.Is(err, git.ErrReferenceNotFound):
			return structerr.NewNotFound("resolving new revision: %w", err).WithDetail(
				&gitalypb.ReferenceNotFoundError{
					ReferenceName: req.GetRevision(),
				},
			)
		case err != nil:
			return fmt.Errorf("resolving new revision: %w", err)
		}
	}

	var oldObjectID git.ObjectID
	if len(req.GetOldRevision()) > 0 {
		if objectHash.IsZeroOID(git.ObjectID(req.GetOldRevision())) {
			// Passing an all-zeroes object ID indicates that we should only update the
			// reference if it didn't previously exist.
			oldObjectID = objectHash.ZeroOID
		} else {
			var err error
			oldObjectID, err = repo.ResolveRevision(ctx, git.Revision(req.GetOldRevision())+"^{object}")
			switch {
			case errors.Is(err, git.ErrReferenceNotFound):
				return structerr.NewNotFound("resolving old revision: %w", err).WithDetail(
					&gitalypb.ReferenceNotFoundError{
						ReferenceName: req.GetOldRevision(),
					},
				)
			case err != nil:
				return fmt.Errorf("resolving old revision: %w", err)
			}
		}
	}

	u, err := updateref.New(ctx, repo)
	if err != nil {
		return fmt.Errorf("error when running creating new updater: %w", err)
	}
	defer func() {
		if err := u.Close(); err != nil && returnedErr == nil {
			returnedErr = fmt.Errorf("close updater: %w", err)
		}
	}()

	if err := u.Start(); err != nil {
		return fmt.Errorf("start reference transaction: %w", err)
	}

	if err := u.Update(git.ReferenceName(req.GetRef()), newObjectID, oldObjectID); err != nil {
		return fmt.Errorf("error when creating update-ref command: %w", err)
	}

	if err := u.Commit(); err != nil {
		var alreadyLockedErr updateref.AlreadyLockedError
		if errors.As(err, &alreadyLockedErr) {
			return structerr.NewAborted("reference is locked already").WithMetadata("reference", alreadyLockedErr.ReferenceName)
		}

		return fmt.Errorf("error when running update-ref command: %w", err)
	}

	return nil
}
