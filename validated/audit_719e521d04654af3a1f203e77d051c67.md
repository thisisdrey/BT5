`handleRecvError` in `outside.go` accepts unauthenticated `RecvError` packets from any source with no cert or handshake required, and uses only the sender's IP (not a nonce, cert, or cryptographic proof) to validate the request, then unconditionally tears down a live, valid, potentially higher-value tunnel.

### Title
Unauthenticated `RecvError` Packets Allow Remote Teardown of a Live, Valid Tunnel via Spoofable Source-Address Check - (File: outside.go)

### Summary
`readOutsidePackets` dispatches `header.RecvError` packets to `handleRecvError` before any certificate, handshake, or replay-window check is performed [1](#0-0) . `handleRecvError` looks up the hostinfo by the attacker-supplied `RemoteIndex` and then validates the sender only by comparing the raw UDP source address string to `hostinfo.GetRemote()` — a value that is itself learned from unauthenticated UDP traffic — before tearing down the tunnel and deleting the pending handshake state [2](#0-1) .

### Finding Description
This mirrors the reported bug class: a piece of live, currently-valid state (an established encrypted tunnel/`HostInfo`) is destroyed by a control message that is processed without confirming it reflects the current, legitimate state of the system. In the raffle report, an old configId/tier was trusted and blindly overwrote a newer valid voucher; here, an off-path attacker's forged `RecvError` packet is trusted (based only on a spoofable IP:port match) and blindly overwrites/destroys a currently valid, live tunnel state via `closeTunnel` + `handshakeManager.DeleteHostInfo`.

Key facts:
- `RemoteIndex` is a 32-bit value that is sent in cleartext on every packet, so an attacker who observes any traffic (or brute forces the space) knows valid indexes for a hostinfo [3](#0-2) .
- The only authentication check is `hr.IsValid() && hr != addr` — a bare comparison of source `netip.AddrPort`, which is trivially spoofable over UDP and is not itself protected by any nonce or AEAD tag [4](#0-3) .
- No certificate, replay window, or handshake proof gates this teardown path — it is reachable pre-authentication, matching the "no CA-signed certificate" reachability requirement.
- Once triggered, `f.closeTunnel(hostinfo)` followed by `f.handshakeManager.DeleteHostInfo(hostinfo)` destroys the live main-hostmap entry and pending handshake state [5](#0-4) .

### Impact Explanation
An attacker with no valid certificate can force a remote node to tear down any established (or handshaking) tunnel by UDP-spoofing a `RecvError` packet with the correct `RemoteIndex` and the victim's real peer address, causing repeated denial-of-service / forced re-handshakes — remote state poisoning of the hostmap that meets the "concrete... remote state poisoning" impact bar. Repeated abuse can prevent a tunnel from ever stabilizing, similar in spirit to the reported bug where a legitimate state was destroyed by an unauthenticated/late/out-of-context event.

### Likelihood Explanation
`RemoteIndex` values are observable in cleartext headers of every packet traversing the path (including by a passive on-path observer, or guessable via limited entropy scans off-path), and the source-address check is a plain UDP spoof, which is generally low-cost for an attacker who can spoof source IP/port (common on many networks, especially over UDP). This is gated by `acceptRecvErrorConfig.ShouldRecvError(addr)`, a config-controlled allow-list, so exploitability depends on deployment configuration, but where enabled, this is directly exploitable without a certificate.

### Recommendation
Do not use `RecvError`, an unauthenticated cleartext message, to unconditionally tear down live tunnel state. At minimum:
- Require some proof tied to the current session (e.g., an authenticated/encrypted acknowledgment carried inside the established tunnel, or a per-session cryptographic tag) before acting on a `RecvError`.
- If `RecvError` must remain a cleartext optimization, treat it only as a hint to trigger a re-handshake attempt rather than an unconditional `closeTunnel`/`DeleteHostInfo`, and rate-limit/verify against replay of previously seen `RecvError` packets.

### Proof of Concept
1. Attacker observes (or otherwise learns) a live tunnel's `RemoteIndex` and the legitimate peer's `UdpAddr` from any nebula packet on the wire (both are cleartext header fields).
2. Attacker crafts a UDP packet: `header.Encode(..., header.RecvError, 0, observedRemoteIndex, 0)` and spoofs the source address to match the victim's real peer `UdpAddr`, sending it to the victim node.
3. `readOutsidePackets` dispatches directly to `handleRecvError` without any cert/handshake validation.
4. `handleRecvError` finds the hostinfo via `QueryReverseIndex`, the spoofed source matches `hostinfo.GetRemote()`, and the check passes.
5. `f.closeTunnel(hostinfo)` and `f.handshakeManager.DeleteHostInfo(hostinfo)` execute, destroying the live, valid tunnel state — reproducible repeatedly for persistent DoS.

func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
