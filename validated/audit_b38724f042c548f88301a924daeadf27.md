Based on this investigation, Go's `net/url` package already fixed this exact class of bug and has active regression tests guarding it.

The Python CVE-2022-0391 concerns `urllib.parse.urlparse` failing to reject `\r`/`\n` in URL components, allowing CRLF injection when a crafted URL string is later used to construct requests/headers. The Go analog would be `net/url.Parse` accepting control characters (including `\r`, `\n`) in a URL string.

In this repository, `net/url.parse` explicitly guards against this via `stringContainsCTLByte`, which is checked at the very start of parsing [1](#0-0) , and rejects any ASCII byte `< ' '` or `0x7f` [2](#0-1) . This is proven by the dedicated regression test `TestRejectControlCharacters`, which specifically tests `\n` and `\r` injection payloads like `"http://foo.com/?foo\nbar"` and `"http\r://foo.com/"` and asserts they return `"net/url: invalid control character in URL"` [3](#0-2) .

Additionally, `net/http`'s request-writing path independently re-checks for CTL bytes in the assembled request URI via `stringContainsCTLByte(ruri)` before writing to the wire, returning `"net/http: can't write control character in Request.URL"` [4](#0-3) , with its own regression test using a `RawQuery` of `"new\nline"` [5](#0-4) .

This means the exact bug class described in the report (CRLF/control-character smuggling through URL parsing) is not reachable in Go's standard library `net/url`/`net/http` — it's actively rejected at two independent layers, with regression tests already covering the historical Go analog (`golang.org/issue/11208`, referenced directly in `url_test.go` line 1857) that this fix addresses.

// stringContainsCTLByte reports whether s contains any ASCII control character.
func stringContainsCTLByte(s string) bool {
	for i := 0; i < len(s); i++ {
		b := s[i]
		if b < ' ' || b == 0x7f {
			return true
		}
	}
	return false
}

func TestRejectControlCharacters(t *testing.T) {
	tests := []string{
		"http://foo.com/?foo\nbar",
		"http\r://foo.com/",
		"http://foo\x7f.com/",
	}
	for _, s := range tests {
		_, err := Parse(s)
		const wantSub = "net/url: invalid control character in URL"
		if got := fmt.Sprint(err); !strings.Contains(got, wantSub) {
			t.Errorf("Parse(%q) error = %q; want substring %q", s, got, wantSub)
		}
	}

	// But don't reject non-ASCII CTLs, at least for now:
	if _, err := Parse("http://foo.com/ctl\x80"); err != nil {
		t.Errorf("error parsing URL with non-ASCII control byte: %v", err)
	}

}
