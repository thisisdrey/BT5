### Title
Adversary can force a victim to accumulate unbounded `DelegatedResourceAccountIndex` entries, degrading query/actuator performance (Resource-Delegation DoS) - (File: `chainbase/src/main/java/org/tron/core/store/DelegatedResourceAccountIndexStore.java`)

### Summary
`DelegateResourceActuator` lets any account unilaterally delegate bandwidth/energy to an arbitrary `receiverAddress` without the receiver's consent, mirroring the ParaSpace pattern where a sender can unilaterally force state changes onto a passive receiver. Each delegation writes an index entry keyed by `V2_TO_PREFIX + receiver + sender` [1](#0-0) , and these entries are later reconstructed via an unbounded `prefixQuery` scan over all keys sharing the receiver's prefix in `getV2Index` [2](#0-1) .

### Finding Description
`DelegateResourceActuator.validate()`/`execute()` only checks the owner's own frozen balance and that the receiver is not a contract; it never requires receiver approval before crediting resource and writing an index record for the receiver [3](#0-2) . The underlying `delegateResource` helper (and the equivalent TVM-native `DelegateResourceProcessor`) always writes a `V2_TO_PREFIX+receiver+owner` index capsule for the receiver regardless of whether the receiver wants it [4](#0-3) .

Because each delegator gets its own key row (`V2_TO_PREFIX+receiver+sender`), an attacker who controls or generates many distinct sender addresses can trigger a large number of unique delegation index rows all associated with one victim. This is directly analogous to the ParaSpace bug: transferring/delegating something to a receiver silently mutates receiver-side state that the receiver never opted into, and that state subsequently increases the cost of operations that must process it.

`getV2Index(address)` reconstructs the full list of counterparties for that address by doing a raw LevelDB/RocksDB `prefixQuery` (range scan) over every key with that prefix, then sorts and streams the whole result set [5](#0-4) . This call is reachable from the public HTTP/gRPC/JSON-RPC surface: `GetDelegatedResourceAccountIndexV2` endpoints (`GetDelegatedResourceAccountIndexV2Servlet`, PBFT/Solidity variants, and `RpcApiService`) and `Wallet.java` all invoke this store method for an address supplied by an arbitrary caller, with no cap on how many entries a single account can accumulate.

### Impact Explanation
An unbounded number of small delegations (each only needs `>= 1 TRX`, see `DelegateResourceActuator.validate()` check `delegateBalance < TRX_PRECISION`) can be sent to a single victim address from many attacker-controlled sender accounts, inflating the number of rows under that victim's `V2_TO_PREFIX` key range. Every subsequent read of `GetDelegatedResourceAccountIndexV2` for that victim (a publicly reachable HTTP/gRPC/JSON-RPC query) forces the node to scan and sort the entire, attacker-inflated key range, increasing per-request I/O, CPU, and response size. If the count grows large enough, repeated requests for the same poisoned address can degrade node responsiveness for that query path — a resource-exhaustion condition on a node-served API, consistent with the "API the node can no longer serve" impact class. This is a lower-severity variant of the ParaSpace pattern (no funds are lost, no consensus break), so it is best assessed as a Medium finding.

### Likelihood Explanation
Likelihood is moderate: the delegate-resource operation is permissionless, cheap (>=1 TRX per delegation, refundable via `UnDelegateResourceContract` after the lock/expire period), and requires no cooperation from the victim, target address prediction, or special privileges — any signed transaction broadcaster can execute it repeatedly from freshly created addresses. The constraining factor is the cost of creating/funding many sender accounts and the per-transaction bandwidth/energy fee, which raises the cost of a large-scale attack but does not prevent it.

### Recommendation
- Bound the number of distinct delegation index entries maintained per receiver address (e.g., a hard cap, or require receiver opt-in/allow-list before an unsolicited delegation index entry is created).
- Replace `getV2Index`'s single unbounded `prefixQuery` with a paginated read path so an inflated key range cannot make one API call arbitrarily expensive, and expose pagination in the corresponding HTTP/gRPC/JSON-RPC handlers.
- Consider charging the account-creation-equivalent fee (or bandwidth cost proportional to index growth) for entries that force new state onto a third-party receiver, similar to the existing `getCreateNewAccountFeeInSystemContract` charged for `TransferAssetActuator`/`TransferActuator` when creating a receiver account, so that inflating another account's index has a real, scaling cost to the attacker.

### Proof of Concept
1. Attacker generates N distinct funded addresses `A_1..A_N`.
2. From each `A_i`, freeze at least 1 TRX for bandwidth or energy, then call `DelegateResourceContract` with `receiverAddress = Victim` and `balance = 1 TRX` [3](#0-2) .
3. Each call succeeds without any action from `Victim`, writing a new row keyed `V2_TO_PREFIX + Victim + A_i` via `delegateResource`/`DelegateResourceProcessor.delegateResource` [6](#0-5) .
4. Repeat for large N (cost bounded only by 1 TRX + tx fee per delegation, later reclaimable via `UnDelegateResourceContract`).
5. Any subsequent call to `GetDelegatedResourceAccountIndexV2` for `Victim` via HTTP/gRPC/JSON-RPC triggers `getV2Index`, which performs a `prefixQuery` scan and sort over all N rows [5](#0-4) , degrading response time/CPU/I-O for that query proportional to N, with no cap on N imposed anywhere in the write path.

      byte[] ownerAddress,
      byte[] receiverAddress,

    //modify DelegatedResourceStore

    long now = repo.getDynamicPropertiesStore().getLatestBlockHeaderTimestamp();
    byte[] fromKey = Bytes.concat(

        new DelegatedResourceAccountIndexCapsule(ByteString.copyFrom(receiverAddress));

    repo.updateDelegatedResourceAccountIndex(fromKey, toIndexCapsule);

    byte[] toKey = Bytes.concat(
        DelegatedResourceAccountIndexStore.getV2_TO_PREFIX(), receiverAddress, ownerAddress);
    DelegatedResourceAccountIndexCapsule fromIndexCapsule =
        new DelegatedResourceAccountIndexCapsule(ByteString.copyFrom(ownerAddress));

    repo.updateDelegatedResourceAccountIndex(toKey, fromIndexCapsule);

    //update Account for receiver
    AccountCapsule receiverCapsule = repo.getAccount(receiverAddress);
    if (isBandwidth) {
      receiverCapsule.addAcquiredDelegatedFrozenV2BalanceForBandwidth(delegateBalance);
    } else {
      receiverCapsule.addAcquiredDelegatedFrozenV2BalanceForEnergy(delegateBalance);
    }
    repo.updateDelegatedResource(key, delegatedResourceCapsule);
    repo.updateAccount(receiverCapsule.createDbKey(), receiverCapsule);

  public DelegatedResourceAccountIndexCapsule getV2Index(byte[] address) {
    return getWithPrefix(V2_FROM_PREFIX, V2_TO_PREFIX, address);
  }

  private DelegatedResourceAccountIndexCapsule getWithPrefix(byte[] fromPrefix, byte[] toPrefix, byte[] address) {
    DelegatedResourceAccountIndexCapsule tmpIndexCapsule =
        new DelegatedResourceAccountIndexCapsule(ByteString.copyFrom(address));

    byte[] key = Bytes.concat(fromPrefix, address);
    List<DelegatedResourceAccountIndexCapsule> tmpToList =
        new ArrayList<>(this.prefixQuery(key).values());
    tmpToList.sort(Comparator.comparing(DelegatedResourceAccountIndexCapsule::getTimestamp));
    List<ByteString> list = tmpToList.stream()
        .map(DelegatedResourceAccountIndexCapsule::getAccount).collect(Collectors.toList());
    tmpIndexCapsule.setAllToAccounts(list);

    key = Bytes.concat(toPrefix, address);
    List<DelegatedResourceAccountIndexCapsule> tmpFromList =
        new ArrayList<>(this.prefixQuery(key).values());
    tmpFromList.sort(Comparator.comparing(DelegatedResourceAccountIndexCapsule::getTimestamp));
    list = tmpFromList.stream().map(DelegatedResourceAccountIndexCapsule::getAccount).collect(
        Collectors.toList());
    tmpIndexCapsule.setAllFromAccounts(list);
    return tmpIndexCapsule;

  @Override
  public boolean execute(Object result) throws ContractExeException {
    TransactionResultCapsule ret = (TransactionResultCapsule) result;
    if (Objects.isNull(ret)) {
      throw new RuntimeException(ActuatorConstant.TX_RESULT_NULL);
    }

    long fee = calcFee();
    final DelegateResourceContract delegateResourceContract;
    AccountStore accountStore = chainBaseManager.getAccountStore();
    byte[] ownerAddress;
    try {
      delegateResourceContract = this.any.unpack(DelegateResourceContract.class);
      ownerAddress = getOwnerAddress().toByteArray();
    } catch (InvalidProtocolBufferException e) {
      logger.debug(e.getMessage(), e);
      ret.setStatus(fee, code.FAILED);
      throw new ContractExeException(e.getMessage());
    }

    AccountCapsule ownerCapsule = accountStore
        .get(delegateResourceContract.getOwnerAddress().toByteArray());
    DynamicPropertiesStore dynamicStore = chainBaseManager.getDynamicPropertiesStore();
    long delegateBalance = delegateResourceContract.getBalance();
    boolean lock = delegateResourceContract.getLock();
    long lockPeriod = getLockPeriod(dynamicStore.supportMaxDelegateLockPeriod(),
            delegateResourceContract);
    byte[] receiverAddress = delegateResourceContract.getReceiverAddress().toByteArray();

    // delegate resource to receiver
    switch (delegateResourceContract.getResource()) {
      case BANDWIDTH:
        delegateResource(ownerAddress, receiverAddress, true,
            delegateBalance, lock, lockPeriod);

        ownerCapsule.addDelegatedFrozenV2BalanceForBandwidth(delegateBalance);
        ownerCapsule.addFrozenBalanceForBandwidthV2(-delegateBalance);
        break;
      case ENERGY:
        delegateResource(ownerAddress, receiverAddress, false,
            delegateBalance, lock, lockPeriod);

        ownerCapsule.addDelegatedFrozenV2BalanceForEnergy(delegateBalance);
        ownerCapsule.addFrozenBalanceForEnergyV2(-delegateBalance);
        break;
      default:
        logger.debug("Resource Code Error.");
    }

    accountStore.put(ownerCapsule.createDbKey(), ownerCapsule);

    ret.setStatus(fee, code.SUCESS);

    return true;
