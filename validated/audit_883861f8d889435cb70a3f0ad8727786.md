### Title
Fee-free NEP-245/IMT `TokenDiff` splitting bypasses protocol fee on multi-unit MT transfers - ([File: contracts/defuse/core/src/intents/token_diff.rs])

### Summary
`TokenDiff::token_fee` explicitly waives fees on `TokenIdType::Nep245`/`Imt` deltas with `amount <= 1`, per-intent, not per-batch. Since a `MultiPayload`/`DefusePayload` can carry an arbitrary `Vec<Intent>` under one signature and one nonce, an unprivileged signer can split one N-unit `TokenDiff` (delta = -N) into N separate one-unit `TokenDiff` intents (each delta = -1) on the same `TokenId::Nep245`, causing `fee_ceil` to be evaluated at `amount == 1` for every leg and returning `Pips::ZERO` each time.

### Finding Description
The broken binding: `sum(fees_collected across batch) == protocol_fee.fee_ceil(N)` for an aggregate negative delta of N on token T, is violated.

In `contracts/defuse/core/src/intents/token_diff.rs`, `execute_intent` computes, per intent, per token: [1](#0-0) 
`fee = Self::token_fee(token_id, amount, protocol_fee).fee_ceil(amount)` where `amount = delta.unsigned_abs()`. `token_fee` is: [2](#0-1) 
For `TokenIdType::Nep245`/`Imt`, if `amount > 1` the configured fee is used, otherwise (`amount <= 1`) it returns `Pips::ZERO`. This check operates strictly on the `amount` of a single `TokenDiff.diff` entry, not on the aggregate delta the signer economically intends across the whole batch/payload.

`DefuseIntents` holds `Vec<Intent>` and `Intent::TokenDiff` is executed once per entry in a simple loop with no cross-intent, same-token aggregation for fee purposes: [3](#0-2) 
A single signed `DefusePayload`/`MultiPayload` carries one `nonce` for the whole `Vec<Intent>`, so nothing prevents packing N distinct `TokenDiff` intents, each `{ diff: { <same Nep245 TokenId>: -1 } }`, into one payload signed once.

Exploit: attacker holding balance N of a `TokenId::Nep245` MT signs one `MultiPayload` containing N `TokenDiff` intents, each with `diff = {token_id: -1}` (optionally paired with matching positive out-legs from a counterparty, or as part of an internal arbitrage-neutral diff set). Each `execute_intent` call computes `amount = 1`, hits the `TokenIdType::Nep245 ... amount <= 1 => Pips::ZERO` branch, and adds `fee = 0` to `fees_collected`. After the loop, total fee credited to `engine.state.fee_collector()` is 0, whereas a single `TokenDiff` with `delta = -N` on the same token would have computed `amount = N > 1`, used the real `protocol_fee`, and credited `protocol_fee.fee_ceil(N)` to the collector.

None of the listed guards address this: `MultiPayload::verify`/nonce checks only prevent replay/authorization forgery, not the fee-calculation granularity; `Amounts::add`/overflow checks are unaffected since the exploit fee is exactly zero, not overflowing; there is no cross-intent aggregation of same-token deltas before fee computation.

### Impact Explanation
Value leaving/not entering the Verifier's `fee_collector` balance that the protocol is owed is fully avoidable: any `Nep245`/`Imt` fungible-style MT balance of size N can settle a batch trade of magnitude N while the fee collector receives `0` instead of `protocol_fee.fee_ceil(N)`. This matches the explicitly listed Critical category "protocol fees bypassed." It is fully repeatable by any account, for any Nep245 token, any batch size N, at no cost beyond ordinary gas for extra intents in the same payload. Blast radius: entire protocol fee revenue on NEP-245/IMT-denominated `TokenDiff` trades, for the `fee_collector` specifically (does not touch other users' custodied balances directly — the net token diffs across the batch still sum to zero for principal amounts, only the fee leg is suppressed).

### Likelihood Explanation
Preconditions are minimal and fully within an unprivileged actor's control: hold (or arrange via counterparties) an MT balance of N units of any `TokenId::Nep245` token, have any nonzero protocol fee configured, and be able to construct and sign a `MultiPayload` with a `Vec<Intent>` of N single-unit `TokenDiff` entries instead of one N-unit entry — a purely client-side, cost-free choice (aside from marginal transaction size / gas for extra intents, explicitly out of scope). Fully repeatable across accounts, tokens, and batch sizes.

### Recommendation
Aggregate same-token negative deltas across the whole intent batch (or across the full `TokenDiff.diff` map is not enough — must be batch-wide) before deciding whether the `amount > 1` fee-exemption threshold applies, or remove the `amount <= 1` fee exemption for `Nep245`/`Imt` tokens and compute fees strictly per unit regardless of how deltas are split across intents in a payload.

### Proof of Concept
`cargo test` in `contracts/defuse/core` (or a `near-workspaces` sandbox test) that:
1. Sets up an `Engine`/`State` with a configured `protocol_fee = Pips::ONE_PERCENT` (or similar nonzero) and `fee_collector`.
2. Credits `signer` with `Nep245` balance N (e.g., N = 100) for `token_id`.
3. Path A: executes one `DefuseIntents { intents: vec![TokenDiff{ diff: {token_id: -100, <out_token>: +X} }] }` signed once; asserts `fee_collector` balance of `token_id` equals `protocol_fee.fee_ceil(100)`.
4. Path B: executes one `DefuseIntents { intents: vec![TokenDiff{diff:{token_id:-1, out:+x}}; 100] }` (100 unit-legs) signed once by the same account, with equivalent aggregate economics; asserts `fee_collector` balance of `token_id` equals `0`.
5. Assert Path A's collected fee ≠ Path B's collected fee (divergence), demonstrating `sum(fees_collected)` for Path B ≠ `protocol_fee.fee_ceil(N)`, confirming the fee-bypass.
