### Title
`ProxyOFT.sendFrom` hardcodes `_refundAddress` to `from_`, so LayerZero fee refunds are permanently lost when the sender is a contract that cannot receive native tokens — ([File: contracts/ProxyOFT.sol](https://github.com/ThankGodontt/metronome-synth-public--020/blob/main/contracts/ProxyOFT.sol))

### Summary
The user-friendly `sendFrom` in `ProxyOFT` forces the LayerZero `_refundAddress` to `payable(from_)`. Because `_debitFrom` enforces `_msgSender() == from_`, `from_` is always the caller. When a contract (e.g., a smart wallet or a protocol helper contract) calls `sendFrom` and overpays the estimated native fee, the LayerZero endpoint pushes the excess refund to that contract. If the contract has no payable `receive()`/`fallback()`, the refund call fails and the overpaid value is retained by the endpoint/relayer — identical to the reported bug class where overpaid messaging fees are never returned for contract destinations.

### Finding Description
`sendFrom` hardcodes the refund recipient:

```solidity
// contracts/ProxyOFT.sol:115-128
function sendFrom(address from_, uint16 dstChainId_, address to_, uint256 amount_) external payable {
    _send({
        _from: from_,
        _dstChainId: dstChainId_,
        _toAddress: abi.encodePacked(to_),
        _amount: amount_,
        _refundAddress: payable(from_),   // forced refund target
        ...
    });
}
```

`_send` passes the full `msg.value` as the native fee to `lzEndpoint.send{value: msg.value}(...)` (`OFTCoreUpgradeable._send` → `LzAppUpgradeable._lzSend`). The endpoint quotes the actual fee at execution time; any excess `msg.value` is refunded via a low-level call to `_refundAddress`. There is no user-supplied `refundAddress_` parameter and no excess-value refund inside `ProxyOFT`/`Operator` (`Operator.execute` also requires `msg.value == sum(call.value)`, forwarding everything).

Preconditions checked: `_debitFrom` requires `from_ == _msgSender()`, bridging active, destination supported — none of these prevent a contract caller. A smart contract account (e.g., a multisig wallet contract or an integration contract without a payable fallback) calling `sendFrom{value: estimatedFee}` is fully authorized, yet cannot receive the endpoint's refund.

### Impact Explanation
Any overpayment of the LayerZero native fee by a contract sender is irrecoverably captured by the endpoint/relayer. Since destination gas prices are unknown at send time, users must overpay to guarantee delivery; for contract senders the entire overshoot leaks value with no recourse. The affected funds are user funds lost on every cross-chain `sendFrom` issued by such contracts.

### Likelihood Explanation
Moderate. Contract wallets (Safe-style proxies, EIP-4337 accounts, integration contracts) are common senders, and some lack payable fallbacks or implement restricted `receive()` (the codebase itself demonstrates this pattern — `NativeTokenGateway.receive()` reverts for anyone except `nativeToken`). Overpayment is routine because `estimateSendFee` is only a quote at query time. Each occurrence leaks the delta, so the issue is highly repeatable though per-event amounts are modest.

### Recommendation
Add a `refundAddress_` (or refund-to-`to_`/EOA) parameter to the user-friendly `sendFrom`, or default the refund to the actual authenticated sender and document that contract callers must be able to receive native tokens. Alternatively, have `ProxyOFT` itself accept the refund and forward it to `from_` via `call`, or credit excess value back within the same transaction.

### Proof of Concept
```solidity
// SPDX-License-Identifier: MIT
pragma solidity 0.8.24;

import "forge-std/Test.sol";
import {ProxyOFT} from "../contracts/ProxyOFT.sol";

// Contract sender with no payable receive/fallback.
contract NoRefundSender {
    function bridge(ProxyOFT oft, uint16 dstChainId, address to, uint256 amount, uint256 fee) external {
        oft.sendFrom{value: fee}(address(this), dstChainId, to, amount);
    }
}

contract RefundLostTest is Test {
    ProxyOFT oft;          // deployed ProxyOFT (Optimism/Base fork)
    NoRefundSender sender; // cannot receive ETH
    address lzEndpoint;    // real LayerZero endpoint on the fork

    function test_refundLost() public {
        // 1. `sender` owns synthetic tokens and calls sendFrom with an overpaid fee.
        uint256 quotedFee = oft.estimateSendFee(dstChainId, to, amount);
        uint256 overpaid = quotedFee + 0.01 ether;

        uint256 endpointBalBefore = lzEndpoint.balance;

        // 2. Bridge via the contract sender. Refund target is hardcoded to `sender`.
        sender.bridge{value: overpaid}(oft, dstChainId, to, amount, overpaid);

        // 3. Endpoint attempts refund to `sender`; the call fails because
        //    `sender` has no payable receive. The 0.01 ether excess stays in
        //    the endpoint (claimable by the relayer).
        assertEq(address(sender).balance, 0);
        assertEq(lzEndpoint.balance - endpointBalBefore, 0.01 ether);
    }
}
```
On an Optimism/Base fork against the deployed `ProxyOFT`, the synthetic-token burn/mint path (`_debitFrom`/`_creditTo`) executes normally; only the endpoint's refund leg fails, leaving the overpayment stranded.
