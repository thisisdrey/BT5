### Title
Unauthenticated forged `MinerMessages` injection via `SignerEventReceiver`'s `/stackerdb_chunks` endpoint (.miners lane skips signature verification) - ([File: libsigner/src/events.rs])

### Summary
`TryFrom<StackerDBChunksEvent> for SignerEvent<T>` deserializes every `modified_slots` chunk for the `.miners` boot contract lane straight into `T::consensus_deserialize` with no call to `chunk.recover_pk()` or any signature/`verify()` check, unlike the sibling `.signers-*` lane a few lines below which explicitly calls `chunk.recover_pk()` before accepting a chunk. Since `SignerEventReceiver::bind` opens a plain `tiny_http` listener with no authentication on incoming POSTs, any TCP client that can reach that port can POST a forged `StackerDBChunksEvent` JSON body and have it accepted as `SignerEvent::MinerMessages(..)`.

### Finding Description
The claimed broken equality — "message forwarded to runloop == message signed by the `.miners` slot owner" — is in fact false in this code: [1](#0-0) 

for the `.miners` branch, `chunk.data` is deserialized directly with no signature check at all, whereas the `.signers-X-Y` branch a few lines later explicitly calls `chunk.recover_pk()` and rejects the chunk if recovery fails: [2](#0-1) 

The resulting `SignerEvent<T>` is produced by `process_event::<T, StackerDBChunksEvent>` from a raw HTTP request body with no further authentication: [3](#0-2) 

`SignerEventReceiver::bind` opens the listener with no auth/token gate on the socket itself: [4](#0-3) [5](#0-4) 

Critically, the signer binary's own startup code documents that this listener is meant only for a trusted local/subnet stacks node and explicitly warns that talking to it over an untrusted network is a security risk, but no code-level gate (auth header, source check, or per-chunk signature check for the `.miners` lane) enforces that expectation: [6](#0-5) 

`GlobalConfig.endpoint` (the bind address for this listener) is operator-configured and documented with an example of `"0.0.0.0:30000"` — i.e., it is explicitly expected to potentially be reachable beyond localhost, and the `auth_password` field only guards the outbound calls the signer makes to the node's RPC/block-validation endpoint, not inbound events on this listener: [7](#0-6) [8](#0-7) 

So: any remote party that can open a TCP connection to the configured `endpoint` can POST a crafted `StackerDBChunksEvent` JSON with `contract_id` set to the `.miners` boot contract and an arbitrary `data` field, and it will be accepted verbatim as a genuine miner-produced `SignerMessage` (e.g. `BlockProposal`), then forwarded to the signer's runloop via `forward_event`: [9](#0-8) 

### Impact Explanation
An attacker who can reach the signer's event-receiver port (which is explicitly documented/configured as potentially non-localhost) can inject arbitrary, unauthenticated `SignerEvent::MinerMessages` (`BlockProposal`/`BlockPushed`/`MockProposal`/`MockBlock`) into the signer's runloop, as if they came from the legitimate `.miners` slot owner — no signature check gates this lane at all, in contrast to the `.signers-*` lane which does verify `recover_pk()`. This is a forged-data injection into the signer's core decision-making input stream and is repeatable per HTTP request. This matches the Critical category: unauthenticated write to the signer's event/state stream with forged data purporting to originate from an authenticated miner slot.

### Likelihood Explanation
The only precondition is network reachability to the `SignerEventReceiver`'s bound `endpoint` (attacker cost: none beyond a raw HTTP POST, no keys, no StackerDB slot, no RPC secret needed for this listener). The code and docs show this endpoint's binding is operator-configured and can be set to a non-localhost address (documented default example `0.0.0.0:30000`); the code itself warns against exposing it externally, which corroborates that no other layer (auth header, IP allowlist, mTLS) protects this port at the code level. Whether this is "remotely reachable" in a given deployment is a network/firewall configuration matter, but nothing in the code enforces or defends against a reachable, unauthenticated caller — the `.miners` lane has zero cryptographic gate.

### Recommendation
Require the same authentication used for the `.signers-*` lane on the `.miners` lane: verify `chunk.recover_pk()` (or equivalent StackerDB chunk signature verification) against the known/expected `.miners` slot signer key before accepting the chunk data for deserialization in the `MINERS_NAME` branch of `TryFrom<StackerDBChunksEvent> for SignerEvent<T>`. Additionally, consider adding a shared-secret/HMAC or mTLS gate on the `SignerEventReceiver` HTTP listener itself, since it currently trusts any TCP client with no application-layer authentication at all.

### Proof of Concept
Rust unit test in `libsigner/src/events.rs` (or a new test module) demonstrating the missing check:
1. Construct a `chunk = StackerDBChunkData { slot_id: 0, slot_version: 1, sig: MessageSignature::empty(), data: <serialized SignerMessage::BlockProposal(..)> }` — i.e. an **unsigned/invalid** signature.
2. Construct `event = StackerDBChunksEvent { contract_id: boot_code_id(MINERS_NAME, is_mainnet), modified_slots: vec![chunk] }`.
3. Call `let signer_event: SignerEvent<SignerMessage> = event.try_into().unwrap();`
4. Assert `matches!(signer_event, SignerEvent::MinerMessages(msgs) if msgs.len() == 1)` — succeeds despite the empty/invalid signature, proving no signature check is performed, in contrast to an equivalent test against the `.signers-X-Y` lane (constructed the same way) which would fail because `chunk.recover_pk()` rejects it.
5. (End-to-end variant) Spin up `SignerEventReceiver::bind` on a local port, open a raw `TcpStream`, and send a crafted `POST /stackerdb_chunks HTTP/1.1` request with the same JSON body; assert that `next_event()` returns `Ok(SignerEvent::MinerMessages(..))` for a client with no StackerDB slot key and no prior interaction with the node.

    fn forward_event(&mut self, ev: SignerEvent<T>) -> bool {
        if self.out_channels.is_empty() {
            // nothing to do
            error!("No channels connected to event receiver");
            false
        } else if self.out_channels.len() == 1 {
            // avoid a clone
            if let Err(e) = self.out_channels[0].send(ev) {
                error!("Failed to send to signer runloop: {:?}", &e);
                return false;
            }
            true

            for (i, out_channel) in self.out_channels.iter().enumerate() {
                if let Err(e) = out_channel.send(ev.clone()) {
                    error!("Failed to send to signer runloop #{}: {:?}", i, &e);
                    return false;
                }
            }
            true
        }
    }

fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}
