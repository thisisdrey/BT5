### Title
Unauthenticated `RecvError` packets let a spoofing off-path attacker repeatedly force tunnel teardown (`handleRecvError`) - (File: outside.go)

### Summary
`RecvError` is one of only two packet types nebula processes before any cryptographic authentication (the other being `Handshake`), dispatched directly out of `readOutsidePackets` prior to `ConnectionState.Decrypt`. Its handler, `handleRecvError`, tears down an established tunnel based solely on a 4-byte `RemoteIndex` value and a UDP source-address match — neither of which requires possession of a CA-signed certificate. An attacker with no valid Nebula identity who can observe or guess the `RemoteIndex` (sent in the clear in every packet header) and spoof the victim's current remote UDP source address can force repeated, unauthenticated teardown of a legitimate tunnel between two authenticated peers, indefinitely, at any time — the same "anyone can repeatedly DOS a trusted, privileged action" pattern as the external report's `handleReallocation`/`renounceRole` abuse, just mapped onto Nebula's handshake/hostmap trust surface instead of a smart-contract role.

### Finding Description
`readOutsidePackets` parses the header and, before any AEAD decryption or certificate check, branches directly to unauthenticated handling for `header.Handshake` and `header.RecvError`: [1](#0-0) 

`handleRecvError` then:
1. Applies only a rate/allow-list gate (`acceptRecvErrorConfig.ShouldRecvError`), not a cryptographic one.
2. Looks up the hostinfo purely by the cleartext `RemoteIndex` field from the header via `QueryReverseIndex`.
3. Compares the packet's source `addr` against the hostinfo's currently known remote `hr`, and only refuses if they differ.
4. If they match, it unconditionally calls `f.closeTunnel(hostinfo)` and also deletes any pending hostinfo, tearing the tunnel down with no cryptographic proof that the sender is the actual peer. [2](#0-1) 

The `RemoteIndex` is a 32-bit value transmitted unencrypted in the header of every packet on the wire (`header.H.RemoteIndex`), so any entity that can observe traffic between the two legitimate peers (or simply guess across the 32-bit space) learns it without needing a CA-signed certificate: [3](#0-2) 

Combined with UDP source-address spoofing (trivial for an off-path/on-path attacker with no valid Nebula credential), this lets an unauthenticated party impersonate the legitimate remote well enough to satisfy the only check `handleRecvError` performs (`hr == addr`), and force `closeTunnel`/`DeleteHostInfo` repeatedly. This is analogous to the external report's core mechanic: an untrusted caller repeatedly triggers a state-destroying action on a privileged/trusted entity (there, revoking `SWAP_CALLER_ROLE` via `Executor`; here, tearing down an authenticated tunnel via a spoofable, unauthenticated `RecvError`), and the legitimate side has to re-establish (re-handshake) every time, exactly as the admin in the original report has to re-grant the role every time — and the attacker can simply repeat the action forever.

### Impact Explanation
An attacker with no CA-signed certificate can persistently and repeatedly force teardown of any tunnel whose current remote UDP endpoint and `RemoteIndex` they can observe or guess, denying service to legitimate, mutually-authenticated peers. Because the check is address-based rather than cryptographic, this can be repeated indefinitely (as in the source report), degrading availability of the mesh without ever needing to complete a valid handshake or hold a trusted certificate.

### Likelihood Explanation
Likelihood is moderate-to-high in adversarial network positions: UDP source-address spoofing is generally trivial, and the `RemoteIndex` is sent unencrypted on the wire in every message, so any attacker who can sniff traffic between two nebula nodes (e.g., a compromised intermediate network segment, or simply a passive observer of the tunnel's public UDP traffic) obtains everything the check requires. No CA-signed certificate or successful handshake is needed by the attacker.

### Recommendation
Do not tear down or otherwise mutate authenticated tunnel/hostmap state based on unauthenticated `RecvError` packets validated only by address+index matching. Either cryptographically bind `RecvError` to the session (e.g., require it be authenticated/encrypted under the existing session keys, similar to `CloseTunnel`'s handling after decryption) or treat address-matching `RecvError` as, at most, a hint that triggers a bounded, rate-limited re-probe/dead-tunnel check rather than an immediate unilateral teardown.

### Proof of Concept
1. Nodes `me` and `them` complete a legitimate handshake; `me` learns `them`'s `RemoteIndex` value is embedded in cleartext in every packet `them` sends `me` (and vice versa).
2. An off-path attacker who can observe this UDP traffic (or successfully guesses the 32-bit index) crafts a UDP datagram with `header.Type = RecvError`, `RemoteIndex` set to the observed index, and spoofed source address equal to `them`'s current UDP endpoint, and sends it to `me`.
3. `me.handleRecvError` finds the matching hostinfo via `QueryReverseIndex`, sees `hr == addr` (spoofed), and calls `f.closeTunnel(hostinfo)` plus `handshakeManager.DeleteHostInfo(hostinfo)` — tearing down the tunnel without any cryptographic proof of identity.
4. The attacker repeats this at will, indefinitely, each time `me` and `them` re-establish, exactly mirroring the "repeat renounceRole forever" DOS pattern from the source report.

```go
func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
```
