Based on my investigation, I found a real local analog to the LeXscrow bug class in the Polkadot SDK's crowdloan pallet.

### Title
Crowdloan `ensure_crowdloan_ended` guard can be bypassed by anyone donating dust to the fund's sovereign account - (File: `polkadot/runtime/common/src/crowdloan/mod.rs`)

### Summary
The LeXscrow report's root cause is a public state-gating check performed against the contract's *raw* token balance rather than tracked internal accounting, which lets any unprivileged party manipulate the gate by sending funds directly to the contract address. The Polkadot SDK crowdloan pallet contains the same broken-invariant pattern: `ensure_crowdloan_ended` gates the ability to withdraw/dissolve a crowdloan fund on the fund's sovereign account raw `free_balance`, which any unprivileged account can inflate via an ordinary balance transfer to a publicly-derivable address.

### Finding Description
`Pallet::<T>::ensure_crowdloan_ended` is used to decide whether a crowdloan fund's bid/lease is still "active": [1](#0-0) 

```rust
fn ensure_crowdloan_ended(...) -> sp_runtime::DispatchResult {
    ...
    // free balance must greater than or equal amount raised, otherwise funds are being used
    // and a bid or lease must be active.
    ensure!(
        CurrencyOf::<T>::free_balance(&fund_account) >= fund.raised,
        Error::<T>::BidOrLeaseActive
    );
    Ok(())
}
```

The check relies purely on the raw, externally observable `free_balance` of `fund_account` (`Pallet::<T>::fund_account_id(index)`), a deterministic sub-account derived from `T::PalletId` and the fund index: [2](#0-1) 

Because this is an ordinary `AccountId`, **any signed account** can compute it and top it up with an arbitrary transfer via `pallet_balances::transfer`/`transfer_keep_alive`, exactly the way any address can send dust ETH/tokens directly to a Solidity contract. The pallet has no way to distinguish "balance restored because the lease/bid ended and pallet-slots returned the deposit" from "balance artificially restored by a third-party donation." This is the same class of bug as the LeXscrow finding: a security-critical boolean gate is derived from a mutable, externally-writable raw balance instead of from pallet-tracked internal state (e.g., an explicit `LeaseActive`/`fund.raised` reconciliation independent of on-chain balance mutations by third parties).

### Impact Explanation
`ensure_crowdloan_ended`'s stated purpose is to prevent `withdraw`/`dissolve` while the fund's contributed capital is still committed as a parachain lease/bid deposit (i.e., `free_balance(fund_account) < fund.raised` because part of it was moved out to pay for the lease). If an attacker (or the fund's own depositor, front-running the intended flow) sends a top-up transfer to `fund_account` to restore its balance to `>= fund.raised` while the lease deposit is still actively held elsewhere (e.g. reserved for a slot in `pallet-slots`/Leases), the guard is satisfied even though the invariant it is meant to enforce (all committed funds have actually been returned) does not hold. This can let contributors reclaim/withdraw their contributions from the fund pot while the corresponding parachain lease deposit is still locked/active, breaking the "message queues/bridge markers/payout state advance only after settlement succeeds atomically" and "conserve value / settle exactly once" invariants called out in the task — i.e., duplicate or premature settlement of custodied funds.

### Likelihood Explanation
This requires no privileged actor: any account with a spare existential-deposit-sized amount of the native currency can compute `fund_account_id(index)` (a pure function of public `PalletId` and `fund_index`) and issue a plain `Balances::transfer_keep_alive` to it. No governance, validator, collator, or off-chain component is involved — it is a standard user-triggerable balance transfer against a public dispatchable's guard condition.

### Recommendation
Do not gate `withdraw`/`dissolve` on the raw `free_balance` of the fund's sovereign account. Instead, track the "in-use" state of the crowdloan's funds explicitly in pallet storage (e.g., a boolean/flag set/cleared by the pallet's own bid/lease-return logic, or a strict equality/accounting check reconciled only through pallet-internal transfers), so that third-party direct transfers to the sovereign account cannot influence whether the fund is considered "still active."

### Proof of Concept
1. Crowdloan `fund` is created and reaches `fund.raised = R`; the fund's sovereign account `fund_account_id(index)` wins a slot and its balance drops to `R' < R` because a lease deposit was reserved/moved elsewhere (as emulated by the test helper `set_winner`, which reserves `free_balance - ED` from the fund account).
2. Any unprivileged account computes `fund_account_id(index)` (deterministic, public derivation) and calls `Balances::transfer_keep_alive(fund_account_id(index), R - R')`.
3. `free_balance(&fund_account) >= fund.raised` in `ensure_crowdloan_ended` now evaluates `true`, even though the lease/bid deposit is still reserved/active.
4. `withdraw`/`dissolve` (which call `ensure_crowdloan_ended`) proceed, allowing contributors to be refunded from the topped-up pot while the actual lease deposit remains committed elsewhere, breaking the intended one-way settlement guarantee.

```rust
	/// This function checks all conditions which would qualify a crowdloan has ended.
	/// * If we have reached the `fund.end` block OR the first lease period the fund is trying to
	///   bid for has started already.
	/// * And, if the fund has enough free funds to refund full raised amount.
	fn ensure_crowdloan_ended(
		now: BlockNumberFor<T>,
		fund_account: &T::AccountId,
		fund: &FundInfo<T::AccountId, BalanceOf<T>, BlockNumberFor<T>, LeasePeriodOf<T>>,
	) -> sp_runtime::DispatchResult {
		// `fund.end` can represent the end of a failed crowdloan or the beginning of retirement
		// If the current lease period is past the first period they are trying to bid for, then
		// it is already too late to win the bid.
		let (current_lease_period, _) =
			T::Auctioneer::lease_period_index(now).ok_or(Error::<T>::NoLeasePeriod)?;
		ensure!(
			now >= fund.end || current_lease_period > fund.first_period,
			Error::<T>::FundNotEnded
		);
		// free balance must greater than or equal amount raised, otherwise funds are being used
		// and a bid or lease must be active.
		ensure!(
			CurrencyOf::<T>::free_balance(&fund_account) >= fund.raised,
			Error::<T>::BidOrLeaseActive
		);

		Ok(())
	}
```
