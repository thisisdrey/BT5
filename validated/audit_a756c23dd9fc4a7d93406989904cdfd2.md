### Title
Unauthenticated shutdown/control endpoints on the signer's `SignerEventReceiver` HTTP listener allow remote DoS - (File: `libsigner/src/events.rs`)

### Summary
The `stacks-signer` binary runs a small HTTP server (`SignerEventReceiver`) to receive events pushed from a Stacks node (`/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block`, `/shutdown`, `/status`). Unlike the node-side RPC endpoints that gate sensitive operations behind an `authorization` header compared against a shared secret (`auth_token`/`auth_password`), this receiver performs **no authentication whatsoever** on any of these routes.

### Finding Description
`SignerEventReceiver::next_event` dispatches purely on the HTTP method and URL path, with no credential check anywhere in the code path: [1](#0-0) 

Compare this to the equivalent node-side design pattern, where sensitive HTTP handlers explicitly gate on a shared `Authorization` header before doing anything else (e.g. `/v3/block_proposal` and `/v3/blocks/replay`): [2](#0-1) [3](#0-2) 

No such gate exists in `libsigner/src/http.rs`, which only parses raw HTTP (method/path/headers/body) and never inspects the `authorization` header — confirmed by the complete absence of any `authorization`/`auth_password` reference anywhere in the `libsigner` crate.

Critically, the `/shutdown` route requires zero payload validation and unconditionally flips the receiver's stop flag: [4](#0-3) 

The reference signer configuration explicitly documents that this listener is meant to bind on all interfaces (`0.0.0.0`), i.e. it is not restricted to loopback-only communication with the local node: [5](#0-4) 

The equality that should hold — "this HTTP request originated from *my paired stacks-node*" — is never checked; any remote unprivileged sender is treated identically to the legitimate node.

### Impact Explanation
A single unauthenticated `POST /shutdown` request causes `EventReceiver::next_event` to return `Err(EventError::Terminated)`, which is the designed mechanism to tear down the signer's event loop. This directly halts signer message processing (`/stackerdb_chunks`, block proposal responses, burn-block/tenure-change notifications), preventing the signer from participating in block validation/signing for as long as an attacker can repeat the request. This matches the in-scope "Critical - remote crash/unauthenticated DoS from few messages" category: one crafted HTTP request from an unprivileged remote party silently disables signer availability.

Additionally, `/stackerdb_chunks`, `/new_block`, `/new_burn_block`, and `/proposal_response` accept and forward arbitrary attacker-supplied JSON as if it came from the trusted node (downstream consumers like `SignerEvent::try_from` do apply StackerDB slot-signature checks for signer messages, so full state corruption there is bounded — but the `/shutdown` DoS is not bounded by any downstream check at all).

### Likelihood Explanation
Exploitation requires only network reachability to the signer's configured `endpoint` (the sample/reference config explicitly uses `0.0.0.0`, i.e., not loopback-restricted) and a single crafted HTTP POST — no credentials, keys, or node access needed. This is a trivial, low-cost, remote, unauthenticated action.

### Recommendation
Add a shared-secret (or mTLS) authentication check to `SignerEventReceiver`/`libsigner::http`, mirroring the node's `authorization` header pattern used for `/v3/block_proposal` and `/v3/blocks/replay`, and reject requests without a valid credential before acting on `/shutdown`, `/stackerdb_chunks`, `/new_block`, `/new_burn_block`, and `/proposal_response`. At minimum, gate `/shutdown` behind authentication, and strongly recommend/default this listener to bind to loopback only in documentation and config validation.

### Proof of Concept
1. Start a `stacks-signer` configured per the sample config with `endpoint = "0.0.0.0:30000"`.
2. From any remote host with network access to port 30000, send:
   ```
   POST /shutdown HTTP/1.1
   Host: <signer-ip>:30000
   Content-Length: 0

   ```
3. Observe (per `libsigner/src/events.rs:443-445`) that the receiver's `stop_signal` is set and the event loop terminates (`EventError::Terminated`), halting signer operation — achieved with zero authentication and a single request.

    /// Wait for the node to post something, and then return it.
    /// Errors are recoverable -- the caller should call this method again even if it returns an
    /// error.
    fn next_event(&mut self) -> Result<SignerEvent<T>, EventError> {
        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)
            } else if request.url() == "/new_block" {
                process_event::<T, StacksBlockEvent>(request)
            } else {
                let url = request.url().to_string();
                debug!(
                    "[{:?}] next_event got request with unexpected url {}, return OK so other side doesn't keep sending this",
                    event_receiver.local_addr,
                    url
                );
                ack_dispatcher(request);
                Err(EventError::UnrecognizedEvent(url))
            }
        })?
