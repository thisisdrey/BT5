### Title
Credential leakage via `FindRemoteRootRef` and other remote-URL RPCs not covered by `URLSanitizerHook`'s allowlist - ([File: internal/log/url_sanitizer.go])

### Summary
`URLSanitizerHook.Fire` only redacts credentialed URLs for gRPC methods explicitly registered via `AddPossibleGrpcMethod`, and only `UpdateRemoteMirror`, `FetchRemote`, and `CreateRepositoryFromURL` are registered in `configure()`. `FindRemoteRootRef` also accepts a `RemoteUrl` field and, on git command failure, propagates the raw git stderr (which can contain the embedded credential) directly into the gRPC response error, bypassing both the log-layer hook and any error-sanitization layer since `helper.SanitizeError`/`helper.SanitizeString` are never invoked anywhere in the codebase.

### Finding Description
`internal/gitaly/service/remote/find_remote_root_ref.go` builds a `git remote show inmemory` command using `request.GetRemoteUrl()` set via `remote.inmemory.url` git config [1](#0-0) . If the git subprocess fails (e.g., unreachable host, auth failure, malformed URL), `cmd.Wait()`'s error — which typically includes git's own diagnostic message containing the credentialed URL verbatim — is returned unmodified up the call stack [2](#0-1) , and then wrapped with `structerr.NewInternal("%w", err)` and returned directly to the RPC caller in `FindRemoteRootRef` [3](#0-2) . No call to `helper.SanitizeError`/`helper.SanitizeString` exists on this path, and in fact those functions have zero call sites in the entire non-test codebase [4](#0-3) , meaning `structerr`-wrapped errors are never scrubbed regardless of RPC.

Defense-in-depth at the logging layer also fails for this RPC: `URLSanitizerHook.Fire` only sanitizes `entry.Data["error"]`/`args`/`Message` when `entry.Data["grpc.method"]` is in `hook.possibleGrpcMethods` [5](#0-4) , and the allowlist configured at server startup omits `FindRemoteRootRef` [6](#0-5) . Consequently, any credentialed URL logged for `FindRemoteRootRef` (via `grpc.method`/`error` log fields) is written to Gitaly's structured logs unredacted, and the same credential is also returned to the RPC caller in the gRPC error text since `SanitizeError` is not applied anywhere before returning errors.

### Impact Explanation
Both Gitaly's persistent logs (potentially retained/forwarded to log aggregation, accessible to broader operational staff than the RPC caller) and the gRPC error response returned to the client can contain the raw credentialed URL. This matches GitLab's "credential/secret disclosure" bounty class, though scoped: it only affects RPCs with URL fields that are missing from the hardcoded allowlist, `FindRemoteRootRef` confirmed as one concrete example, and the root cause (`helper.SanitizeError`/`SanitizeString` unused) means the entire error-sanitization approach is allowlist-only.

### Likelihood Explanation
Feasibility is high for the log-based disclosure: the `URLSanitizerHook` allowlist is fixed at server startup and requires no privileged action to trigger — any caller of `FindRemoteRootRef` with a credentialed `RemoteUrl` that causes the underlying git command to fail (easy to arrange, e.g., unreachable host or bad credential) will have that URL logged unredacted. For the returned-gRPC-error disclosure, exploitability depends on whether GitLab Rails re-sanitizes or suppresses Gitaly-internal error text before surfacing it to end users — this is outside Gitaly's control and could not be fully verified from this repository alone. The underlying design flaw (allowlist-based sanitization with an unused generic `SanitizeError`/`SanitizeString` fallback) is fully reproducible and repeatable regardless of that caveat.

### Recommendation
Apply `helper.SanitizeError`/`helper.SanitizeString` to all error paths that may embed a git-remote-derived URL before returning them via `structerr` (in particular `find_remote_root_ref.go`), rather than relying solely on the logrus hook's allowlist. Additionally, register `FindRemoteRootRef` (and audit all RPCs with `RemoteUrl`/`Url` fields via `protoregistry`) in `URLSanitizerHook.AddPossibleGrpcMethod`, or switch to unconditional sanitization of any log field/error that may contain a URL rather than an opt-in per-method list.

```go
func (s *server) findRemoteRootRefCmd(ctx context.Context, request *gitalypb.FindRemoteRootRefRequest) (*command.Command, error) {
	remoteURL := request.GetRemoteUrl()
	var config []gitcmd.ConfigPair

	if resolvedAddress := request.GetResolvedAddress(); resolvedAddress != "" {
		modifiedURL, resolveConfig, err := gitcmd.GetURLAndResolveConfig(remoteURL, resolvedAddress)
		if err != nil {
			return nil, structerr.NewInvalidArgument("couldn't get curloptResolve config: %w", err)
		}

		remoteURL = modifiedURL
		config = append(config, resolveConfig...)
	}

	config = append(config, gitcmd.ConfigPair{Key: "remote.inmemory.url", Value: remoteURL})
```

```go
// SanitizeString will clean password and tokens from URLs, and replace them
// with [FILTERED].
func SanitizeString(str string) string {
	return hostPattern.ReplaceAllString(str, "$1[FILTERED]@$3$4")
}

// SanitizeError does the same thing as SanitizeString but for error types
func SanitizeError(err error) error {
	return errors.New(SanitizeString(err.Error()))
}
```

```go
func (hook *URLSanitizerHook) Fire(entry *logrus.Entry) error {
	mth, ok := entry.Data["grpc.method"]
	if !ok {
		return nil
	}

	mthStr, ok := mth.(string)
	if !ok || !hook.possibleGrpcMethods[mthStr] {
		return nil
	}

	if _, ok := entry.Data["args"]; ok {
		sanitizeSpawnLog(entry)
	} else if _, ok := entry.Data["error"]; ok {
		sanitizeErrorLog(entry)
	} else {
		entry.Message = sanitizeString(entry.Message)
	}

	return nil
}
```
