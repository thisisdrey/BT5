### Title
Credential Disclosure via Unsanitized Git Stderr Logging in `FindRemoteRootRef` - ([File: internal/gitaly/service/remote/find_remote_root_ref.go])

### Summary
Gitaly already has a purpose-built defense against the exact bug class described in the report — leaking credentials embedded in URLs into production logs. It uses a `URLSanitizerHook` that redacts user:password segments from log fields (`args`, `error`, message) for a specific allow-list of gRPC methods. [1](#0-0) 
That allow-list is configured in `configure()` in `internal/cli/gitaly/serve.go` and only covers `CreateRepositoryFromURL`, `FetchRemote`, and `UpdateRemoteMirror`: [2](#0-1) 

However, `FindRemoteRootRef` accepts a caller-supplied `remote_url` that can embed HTTP Basic credentials (`https://user:pass@host/repo.git`), exactly like `FetchRemote`/`CreateRepositoryFromURL`, but it is **not included** in the sanitizer's method list. [3](#0-2) 

### Finding Description
`findRemoteRootRefCmd` builds a `git remote show inmemory` command and injects the caller-supplied URL as `remote.inmemory.url` via `gitcmd.WithConfigEnv`, not as a literal argv element: [4](#0-3) 

When the underlying `git remote show` command fails (unreachable host, wrong credentials, TLS error, non-existent repository, etc.), Git itself writes the failure message to stderr, and that message typically **echoes back the full URL it was trying to reach — including embedded credentials** (e.g., `fatal: unable to access 'https://user:pass@host/repo.git/': Could not resolve host`).

Gitaly's `command.Command` captures this stderr into a bounded buffer and unconditionally logs it at `Warn`/`Error` level in `logProcessComplete()`: [5](#0-4) 

Gitaly's `URLSanitizerHook.Fire()` is a `logrus` hook that inspects the `grpc.method` field on each log entry and only redacts credentials if the method is in `possibleGrpcMethods`: [6](#0-5) 

Since `FindRemoteRootRef` is absent from the `AddPossibleGrpcMethod(...)` call in `serve.go`, `Fire()` returns `nil` without touching the message, so the stderr log line — containing the plaintext embedded credentials — is written to disk/log-aggregation exactly as-is. This mirrors the general-purpose `helper.SanitizeString`/`SanitizeError` helper used elsewhere for the same purpose but not applied here either: [7](#0-6) 

The existing test suite (`internal/log/url_sanitizer_test.go`) proves this class of leak is exactly what the hook is designed to prevent for the three registered methods, confirming the gap for `FindRemoteRootRef` is not intentional but an omission: [8](#0-7) 

### Impact Explanation
Any ordinary caller of the `RemoteService/FindRemoteRootRef` RPC (invoked by GitLab, e.g., during project-import/mirror configuration flows, or directly by anyone with access to the Gitaly gRPC endpoint) can supply a `remote_url` with embedded HTTP Basic credentials pointing at a remote that is guaranteed to fail (bad host, bad path, revoked auth). The resulting error is logged verbatim to Gitaly's structured logs, disclosing:
- Third-party or internal Git-hosting credentials supplied by the calling application/user.
- The internal remote endpoints/hostnames Gitaly is configured to reach.

Anyone with log read-access (log aggregator compromise, SIEM export, over-privileged read-only log viewer) can harvest these credentials and use them to access external or internal repositories directly — the same impact class as the referenced report's MongoDB URI leak.

### Likelihood Explanation
Likelihood is high for triggering the leak (any caller can force a git failure by pointing to an unreachable/invalid host), but the value of what leaks depends on whether the calling application (e.g., GitLab) actually passes credentials embedded in `remote_url` for this RPC versus using `http_authorization_header` (which is safely handled as a config value, not shown in stderr URL). Where embedded-credential URLs are used (common for legacy/self-managed import flows), a single failed root-ref query is sufficient to leak them into Gitaly's log stream.

### Recommendation
Add `"FindRemoteRootRef"` to the `URLSanitizerHook.AddPossibleGrpcMethod(...)` call in `internal/cli/gitaly/serve.go` alongside `CreateRepositoryFromURL`, `FetchRemote`, and `UpdateRemoteMirror`, and audit for any other RPCs (e.g., other remote-URL-accepting endpoints) missing from that allow-list. Alternatively, make the sanitizer opt-out (apply to all `grpc.method` values by default) rather than opt-in, so newly added RPCs that accept remote URLs are protected automatically.

### Proof of Concept
1. Call `RemoteService/FindRemoteRootRef` with `remote_url = "https://validuser:validpassword@nonexistent-host.invalid/repo.git"` against a test repository.
2. Git's `remote show inmemory` invocation fails to resolve the host and writes to stderr, e.g.:
   `fatal: unable to access 'https://validuser:validpassword@nonexistent-host.invalid/repo.git/': Could not resolve host: nonexistent-host.invalid`
3. Observe Gitaly's structured log output (level=error/warn) — the raw stderr line, including `validuser:validpassword`, is present verbatim, unlike the equivalent scenario for `FetchRemote`/`CreateRepositoryFromURL`/`UpdateRemoteMirror` where `URLSanitizerHook` would redact it to `[FILTERED]`.

// URLSanitizerHook stores which gRPC methods to perform sanitization for.
type URLSanitizerHook struct {
	// gRPC methods that are likely to have URLs to sanitize
	possibleGrpcMethods map[string]bool
}

// NewURLSanitizerHook returns a new logrus hook for sanitizing URLs.
func NewURLSanitizerHook() *URLSanitizerHook {
	return &URLSanitizerHook{possibleGrpcMethods: make(map[string]bool)}
}

// AddPossibleGrpcMethod adds method names that we should sanitize URLs from their logs.
func (hook *URLSanitizerHook) AddPossibleGrpcMethod(methods ...string) {
	for _, method := range methods {
		hook.possibleGrpcMethods[method] = true
	}
}

// Fire is called by logrus.
func (hook *URLSanitizerHook) Fire(entry *logrus.Entry) error {
	mth, ok := entry.Data["grpc.method"]
	if !ok {
		return nil
	}

	mthStr, ok := mth.(string)
	if !ok || !hook.possibleGrpcMethods[mthStr] {
		return nil
	}

	if _, ok := entry.Data["args"]; ok {
		sanitizeSpawnLog(entry)
	} else if _, ok := entry.Data["error"]; ok {
		sanitizeErrorLog(entry)
	} else {
		entry.Message = sanitizeString(entry.Message)
	}

	return nil
}

func (s *server) findRemoteRootRefCmd(ctx context.Context, request *gitalypb.FindRemoteRootRefRequest) (*command.Command, error) {
	remoteURL := request.GetRemoteUrl()
	var config []gitcmd.ConfigPair

	if resolvedAddress := request.GetResolvedAddress(); resolvedAddress != "" {
		modifiedURL, resolveConfig, err := gitcmd.GetURLAndResolveConfig(remoteURL, resolvedAddress)
		if err != nil {
			return nil, structerr.NewInvalidArgument("couldn't get curloptResolve config: %w", err)
		}

		remoteURL = modifiedURL
		config = append(config, resolveConfig...)
	}

	config = append(config, gitcmd.ConfigPair{Key: "remote.inmemory.url", Value: remoteURL})

	if authHeader := request.GetHttpAuthorizationHeader(); authHeader != "" {
		config = append(config, gitcmd.ConfigPair{
			Key:   fmt.Sprintf("http.%s.extraHeader", request.GetRemoteUrl()),
			Value: "Authorization: " + authHeader,
		})
	}

	repo := s.localRepoFactory.Build(request.GetRepository())

	return repo.Exec(ctx,
		gitcmd.Command{
			Name:   "remote",
			Action: "show",
			Args:   []string{"inmemory"},
		},
		gitcmd.WithDisabledHooks(),
		gitcmd.WithConfigEnv(config...),
		gitcmd.WithSetupStdout(),
	)
}

package helper

import (
	"errors"
	"regexp"
)

// Pattern taken from Regular Expressions Cookbook, slightly modified though
//
//	|Scheme                |User                         |Named/IPv4 host|IPv6+ host
var hostPattern = regexp.MustCompile(`(?i)([a-z][a-z0-9+\-.]*://)([a-z0-9\-._~%!$&'()*+,;=:]+@)([a-z0-9\-._~%]+|\[[a-z0-9\-._~%!$&'()*+,;=:]+\])`)

// SanitizeString will clean password and tokens from URLs, and replace them
// with [FILTERED].
func SanitizeString(str string) string {
	return hostPattern.ReplaceAllString(str, "$1[FILTERED]@$3$4")
}

// SanitizeError does the same thing as SanitizeString but for error types
func SanitizeError(err error) error {
	return errors.New(SanitizeString(err.Error()))
}
