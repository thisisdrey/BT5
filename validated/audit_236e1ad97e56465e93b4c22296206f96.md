### Title
Unauthenticated remote DoS via `/shutdown` endpoint on signer event receiver - (File: libsigner/src/events.rs)

### Summary
The `SignerEventReceiver::next_event` handler in `libsigner/src/events.rs` treats any HTTP `POST /shutdown` request as authoritative and immediately sets the stop flag, permanently terminating the signer's event-processing loop. There is no authentication, token, or origin check on this path, unlike the node's RPC `auth_token`/signer's `auth_password` pairing used elsewhere.

### Finding Description
`SignerStopSignaler::send` (the legitimate internal shutdown mechanism) constructs and sends a plain, unauthenticated HTTP request: `POST /shutdown HTTP/1.1` with an arbitrary body, over a plain `TcpStream::connect` to the receiver's bound address. [1](#0-0) 

`SignerEventReceiver::next_event` handles incoming requests by URL match. For `/shutdown`, it unconditionally stores `true` into `stop_signal` and returns `EventError::Terminated`, without checking any secret, header, or source: [2](#0-1) 

Note that every other branch (`/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block`, `/status`) is likewise reached with no authentication check inside this file — the entire event-receiver HTTP endpoint set is unauthenticated by design at this layer; it relies purely on network placement/firewalling. Once `stop_signal` is set, `main_loop` observes `is_stopped()` returning true and exits: [3](#0-2) 

This means any TCP client that can reach the bound port, replicating the exact same wire format used internally, can terminate the signer's event thread with a single crafted request — no signature, no `auth_password`, no shared secret is required or checked anywhere in this code path.

### Impact Explanation
A remote unauthenticated attacker who can reach the signer's event-listener port can permanently stop the `SignerEventReceiver`'s main loop with one HTTP request, halting delivery of `stackerdb_chunks`, `proposal_response`, `new_burn_block`, and `new_block` events to the signer's runloop. This effectively disables that signer instance's ability to participate in block signing until the process/thread is manually restarted, since `SpawnedSigner::join` documents that it "will hang forever if the event receiver stop signal was never sent/no error occurred" — implying no automatic recovery. This is a remote, single-message, unauthenticated DoS, matching the Critical category.

### Likelihood Explanation
The precondition is network reachability to the signer's event-receiver bind address. The codebase's own sample configuration for the signer binary explicitly sets `endpoint = "0.0.0.0:30000"` (not loopback-only) in `sample/conf/signer/mainnet-signer-conf.toml`, and `SpawnedSigner::new` in `stacks-signer/src/lib.rs` even logs a runtime warning about exposing the signer to non-local networks, indicating this is an anticipated/possible deployment topology rather than a purely theoretical one. [4](#0-3) [5](#0-4) 

The attack requires a single TCP connection and one crafted HTTP request, is trivially repeatable, and requires no credentials, keys, or privileged role — only network reachability to the bound port.

### Recommendation
Require an authenticated/shared-secret check (e.g., reuse the existing `auth_password`/`auth_token` mechanism already used between node and signer) before honoring `/shutdown` (and ideally the other POST endpoints) in `SignerEventReceiver::next_event`, or restrict/enforce loopback-only binding for the event receiver and document/enforce this at the config-validation layer rather than relying solely on a runtime warning log.
