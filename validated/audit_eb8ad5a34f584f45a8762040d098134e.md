### Title
`RewardsDistributor._calculateTokenDelta` credits `balance * INITIAL_INDEX` (≈1e18×) to any account whose `accountIndex` is still the 0 "unset" sentinel when `tokenStates.index == INITIAL_INDEX`, allowing the reward contract to be drained - ([File: contracts/RewardsDistributor.sol](contracts/RewardsDistributor.sol))

### Summary
Analogous to the mm_cid fixup bug, an account index of `0` is an "unset" sentinel that is only lazily written on the first `updateBefore*` call. The guard in `_calculateTokenDelta` floors a `0` account index to `INITIAL_INDEX` only when the global index has already advanced past `INITIAL_INDEX`; when `tokenStates[token].index == INITIAL_INDEX` exactly, the sentinel `0` is used as a real index and `_deltaIndex = INITIAL_INDEX - 0 = 1e18`, so the account accrues `balanceOf(account) * 1e18` reward units, which `claimRewards` then pays out (capped only by the distributor's token balance).

### Finding Description
`RewardsDistributor` tracks per-account reward checkpoints in `accountIndexOf`, where `0` means "never updated". The lazy-initialization fallback is in `_calculateTokenDelta`: [1](#0-0) 

```solidity
_tokenIndex = _tokenState.index;
uint256 _accountIndex = accountIndexOf[token_][account_];

if (_accountIndex == 0 && _tokenIndex > INITIAL_INDEX) {
    _accountIndex = INITIAL_INDEX;
}

uint256 _deltaIndex = _tokenIndex - _accountIndex;
_tokensDelta = token_.balanceOf(account_).wadMul(_deltaIndex);
```

The unset guard only fires when `_tokenIndex > INITIAL_INDEX`. When a token is first registered, `tokenStates[token_]` is set to `INITIAL_INDEX` (1e18) and the current timestamp: [2](#0-1) 

Within the same block (or any time `block.timestamp - tokenStates.timestamp == 0`), `_calculateTokenIndex` returns no new index, so `_updateTokenIndex` leaves `index == INITIAL_INDEX`: [3](#0-2) 

Then `_calculateTokenDelta` computes `_deltaIndex = 1e18 - 0 = 1e18`, and `_updateTokensAccruedOf` stores `tokensAccruedOf[account] += balanceOf(account).wadMul(1e18)` — i.e., `balance * 1e18` wei of reward entitlement: [4](#0-3) 

`claimRewards` is permissionless and pays `tokensAccruedOf[account]` up to the distributor's whole `rewardToken` balance: [5](#0-4) [6](#0-5) 

`updateBeforeMintOrBurn` and `updateBeforeTransfer` are externally callable by anyone and only require `tokenStates[token_].index > 0`, so the attacker can trigger the bad accrual themselves: [7](#0-6) 

### Impact Explanation
The attacker receives `tokensAccruedOf` equal to roughly `depositBalance * 1e18`, far above any legitimate accrual. `_transferRewardIfEnoughTokens` then transfers `min(accrued, contractBalance)`, i.e. the distributor's entire `rewardToken` balance — direct theft of all unclaimed yield belonging to every other depositor/borrower.

### Likelihood Explanation
Requirements:

1. Attacker holds a `DepositToken`/`DebtToken` balance while the token is not yet reward-registered, so `accountIndexOf[token][attacker] == 0`. Any holder before `updateTokenSpeed` qualifies — `updateBeforeMintOrBurn` skips accounts entirely when `index == 0`, leaving their account index unset while they hold balance.
2. Governor/keeper calls `updateTokenSpeed(token, speed > 0)`, initializing `tokenStates` to `INITIAL_INDEX`.
3. In the same block (mempool back-run of the governor transaction, or a bundled call on chains with fast follower timestamps), the attacker calls `updateBeforeMintOrBurn(token, attacker)` before any later-timestamp tick advances the index past `INITIAL_INDEX`.

After the first block passes with `speed > 0` and `totalSupply > 0`, the index exceeds `INITIAL_INDEX` and the window closes, so likelihood is moderate — it needs same-block front-running of the speed-setting transaction — but requires no privileged role and no price manipulation.

### Recommendation
In `_calculateTokenDelta`, floor the unset account index whenever `_accountIndex == 0 && _tokenIndex >= INITIAL_INDEX` (or, more robustly, `_accountIndex == 0 && _tokenIndex > 0`), so an "unset" sentinel is never used as a real baseline index. Equivalently, treat `_accountIndex == 0` as `_INITIAL_INDEX` unconditionally before computing `_deltaIndex`.

### Proof of Concept
Hardhat-style PoC following the repo's existing `test/RewardDistributor.test.ts` mocking pattern:

```ts
it('drains rewards for pre-registration holder with unset accountIndex', async () => {
  // 1) Alice deposits BEFORE the deposit token is reward-registered.
  //    updateBeforeMintOrBurn skips because tokenStates.index == 0,
  //    so accountIndexOf[token][alice] stays the 0 sentinel while balance > 0.
  msdTOKEN1.totalSupply.returns(parseEther('100'))
  msdTOKEN1.balanceOf.whenCalledWith(alice.address).returns(parseEther('100'))

  // 2) Governor registers the token: index = INITIAL_INDEX (1e18), timestamp = now.
  await rewardDistributor.updateTokenSpeed(msdTOKEN1.address, parseEther('1'))

  // 3) Same block: attacker back-runs updateTokenSpeed before time advances.
  await ethers.provider.send('evm_setAutomine', [false])
  await rewardDistributor.updateBeforeMintOrBurn(msdTOKEN1.address, alice.address)
  await ethers.provider.send('evm_mine', []) // same timestamp block
  await ethers.provider.send('evm_setAutomine', [true])

  // _tokenIndex == INITIAL_INDEX, _accountIndex == 0, guard skipped:
  // tokensDelta = 100e18 * 1e18 -> astronomical accrued amount
  const accrued = await rewardDistributor.tokensAccruedOf(alice.address)
  expect(accrued).to.be.gt(parseEther('100')) // sanity: >> real accrual of 0

  // 4) claimRewards pays out min(accrued, distributor balance) = entire reward pool.
  const distributorBalance = await vsp.balanceOf(rewardDistributor.address)
  await rewardDistributor['claimRewards(address)'](alice.address)
  expect(await vsp.balanceOf(alice.address)).to.eq(distributorBalance)
})
```

Key assertions: `accountIndexOf` is `0` at step 3, `tokenStates.index` is exactly `INITIAL_INDEX` (no timestamp delta), `_calculateTokenDelta` yields `balance * 1e18`, and `claimRewards` transfers the full reward-token balance to the attacker.
