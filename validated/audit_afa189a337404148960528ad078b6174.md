### Title
Unauthenticated HTTP event-injection endpoint on the signer's `SignerEventReceiver` allows forged StackerDB/block/burn-block events - (File: libsigner/src/events.rs)

### Summary
The `stacks-signer` binary listens on a plaintext HTTP socket (`SignerEventReceiver`) for event pushes that are supposed to come only from its paired `stacks-node`. That listener performs no authentication of any kind: any TCP client that can reach the configured `endpoint` (e.g. `0.0.0.0:30000` in the sample configs) can POST to `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block`, or `/shutdown` and have the payload accepted and forwarded into the signer's runloop as if it came from the legitimate node. This mirrors the MCP Inspector class of bug: a local/companion process trusts a proxy/companion channel with no auth, so any unauthenticated caller that can reach the port can drive privileged behavior.

### Finding Description
`SignerEventReceiver::bind` simply opens a `tiny_http::Server` on the configured address and `next_event` dispatches based solely on URL path, with zero credential/signature verification: [1](#0-0) 

Compare this to the deliberate authentication design elsewhere in the stack: the node-side block-proposal HTTP endpoint requires `[connection_options] auth_token` to match the signer's `auth_password`, as documented and configured explicitly: [2](#0-1) [3](#0-2) 

That `auth_token`/`auth_password` pairing only gates the **node's** RPC endpoint that the signer calls into (`postblock_proposal`); it does **not** protect the **signer's own** listening socket that receives push events from the node. A `grep` across `libsigner/**` for `Authorization`, `auth_password`, `bearer`, or any auth-check primitive returns zero matches, confirming there is no verification step in `events.rs` at all — the equality that should be enforced ("this event genuinely originated from my paired node") is never checked; the code implicitly treats "reached the listening port" as equivalent to "authenticated as the node," which is false for any signer bound to a non-loopback interface (the shipped sample configs bind to `0.0.0.0:30000`).

The test harness in `libsigner/src/tests/mod.rs` demonstrates the exact call shape an external attacker would use — a raw `TcpStream::connect` + manually-crafted HTTP POST with a JSON `StackerDBChunksEvent` body, accepted without any header or token: [4](#0-3) 

Because `StackerDBChunksEvent`/`BlockValidateResponse`/`BurnBlockEvent` are deserialized directly from the untrusted POST body and handed to the signer's runloop via `forward_event`, this is a store/act on unauthenticated input — the signer's internal state machine (block-proposal validation results, StackerDB chunk observations, burn-block view) can be fed forged data by anyone who can reach the port, without needing the node's key or the `auth_token`.

### Impact Explanation
An unauthenticated remote (or same-LAN) attacker who can reach the signer's event-listener port can inject forged `BlockValidateResponse` ("proposal_response"), forged `StackerDBChunksEvent`, and forged `BurnBlockEvent` messages directly into the signer process, bypassing the entire node→signer trust boundary and the `auth_token` protection that was clearly intended to guard this interaction. Depending on how the signer's runloop consumes these events, this can desynchronize the signer's view of chain state / block-validation results (e.g., making it believe a block was validated/invalidated when it wasn't) or feed it forged StackerDB chunk data, i.e. exactly the class of "forged gossip/data accepted without authentication" that the rules call out as Critical/High impact. It also fits the referenced CVE's pattern: a local/companion HTTP interface between two cooperating processes with no auth, letting any reachable caller drive one side's internal logic.

### Likelihood Explanation
Requires only network reachability to the signer's configured `endpoint`. The shipped sample configs (`sample/conf/signer/mainnet-signer-conf.toml`, mainnet/testnet signer node configs) bind this to `0.0.0.0:30000`, i.e., not loopback-only by default guidance, so any operator following the documented setup without an additional firewall/reverse-proxy is exposed. No key material, admin role, or the `auth_token` is needed — only a single crafted HTTP POST.

### Recommendation
Add an authentication check to `SignerEventReceiver`'s request handling (e.g., require and verify the same `auth_token`/`auth_password` shared secret already used for the node-side leg, via a header checked in `next_event` before dispatch), and/or default-bind the signer event listener to loopback with explicit opt-in and documentation warnings for non-loopback binding.

### Proof of Concept
1. Start a `stacks-signer` with a config where `endpoint = "0.0.0.0:30000"` (as in the shipped sample configs).
2. From a remote host, open a TCP connection to `<signer-ip>:30000` and send:
   ```
   POST /stackerdb_chunks HTTP/1.1
   Host: <signer-ip>:30000
   Connection: close
   Content-Type: application/json
   Content-Length: <len>

   {"contract_id": "...", "modified_slots": [<forged, arbitrarily signed chunk>]}
   ```
3. The signer's `SignerEventReceiver::next_event` accepts this with no credential check, deserializes it, and forwards it into the signer runloop (mirrors the test flow in `libsigner/src/tests/mod.rs` lines 120-146, which uses the identical unauthenticated request shape from a mock "node").

Note: I was not able to fully trace how the signer runloop consumes each forwarded `SignerEvent` variant downstream (that logic lives in `libsigner/src/runloop.rs` and the `stacks-signer` binary's coordinator/signer-decision code, which is out of scope per the rules), so the precise downstream state-corruption outcome per event type is not fully verified — the confirmed root cause is the missing authentication at the ingestion point itself.

impl<T: SignerEventTrait> EventReceiver<T> for SignerEventReceiver<T> {
    type ST = SignerStopSignaler;

    /// Start listening on the given socket address.
    /// Returns the address that was bound.
    /// Errors out if bind(2) fails
    fn bind(&mut self, listener: SocketAddr) -> Result<SocketAddr, EventError> {
        self.http_server = Some(HttpServer::http(listener).expect("failed to start HttpServer"));
        self.local_addr = Some(listener);
        Ok(listener)
    }

    /// Wait for the node to post something, and then return it.
    /// Errors are recoverable -- the caller should call this method again even if it returns an
    /// error.
    fn next_event(&mut self) -> Result<SignerEvent<T>, EventError> {
        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)
            } else if request.url() == "/new_block" {
                process_event::<T, StacksBlockEvent>(request)
            } else {
                let url = request.url().to_string();
                debug!(
                    "[{:?}] next_event got request with unexpected url {}, return OK so other side doesn't keep sending this",
                    event_receiver.local_addr,
                    url
                );
                ack_dispatcher(request);
                Err(EventError::UnrecognizedEvent(url))
            }
        })?
