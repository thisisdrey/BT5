## Title
Protocol fee on Nep245/Imt token movements can be fully evaded by splitting a `TokenDiff` delta into unit-sized (`|delta| = 1`) legs — ([File: contracts/defuse/core/src/intents/token_diff.rs])

### Summary
`TokenDiff::token_fee` waives the protocol fee entirely whenever the absolute delta on a `Nep245`/`Imt` token is `<= 1`, on the assumption that such tokens are indivisible NFT-like instances. Because `Nep245` (multi-token) balances are in practice arbitrary-amount, fungible-like quantities (as shown by MT balances of 70/160/270 units in the test suite), an unprivileged signer can restructure any MT trade into a sequence of unit (`delta = ±1`) `TokenDiff` intents to move the exact same net quantity while paying zero fee instead of `Pips::fee_ceil`.

### Finding Description
The binding that should hold is:

`fee_collected(total_movement M on token T) == Pips::fee_ceil(M, protocol_fee)` regardless of how the signer partitions `M` across `TokenDiff` intents within (or across) `execute_intents` batches.

The actual code computes fee per-intent, per-delta: [1](#0-0) 

```rust
pub fn token_fee(token_id: impl Into<TokenIdType>, amount: u128, fee: Pips) -> Pips {
    let token_id = token_id.into();
    match token_id {
        TokenIdType::Nep141 => {}
        TokenIdType::Nep245 | TokenIdType::Imt if amount > 1 => {}
        // do not take fees on NFTs and MTs with |delta| <= 1
        TokenIdType::Nep171 | TokenIdType::Nep245 | TokenIdType::Imt => return Pips::ZERO,
    }
    fee
}
```

This is invoked per negative delta inside `TokenDiff::execute_intent`: [2](#0-1) 

For `delta = -2` on a `Nep245` token, `amount = 2 > 1`, so the fee applies in full: `fee = fee_ceil(2, protocol_fee)`. If the same signer instead submits two `TokenDiff` intents each with `delta = -1` on the same token (matched by corresponding `+1` counter-deltas from a counterparty within the same batch, satisfying `TransferMatcher::finalize`'s net-zero invariant), each individual `token_fee` call sees `amount = 1`, hits the `<= 1` branch, and returns `Pips::ZERO` — so `fees_collected` is `0` for the entire batch despite moving the identical total quantity (2 units) of the identical token.

The root cause is that the `amount > 1` heuristic in `token_fee` conflates two distinct semantics of `Nep245`: NFT-like unique instances (where a `delta` is always exactly `±1` and can't be fractionally taxed) and fungible-like MT balances (which the codebase itself treats as arbitrary-quantity, e.g. balances of 70/160/270 shown in `tests/src/tests/defuse/tokens/nep245/mod.rs`). Nothing distinguishes these two uses at the `TokenId` level, so the exemption designed for indivisible NFTs also exempts arbitrarily large fungible MT trades restructured as a sequence of unit legs.

No existing guard prevents this: `TransferMatcher::finalize` only enforces that deltas across the batch net to zero per token, it does not aggregate or re-derive the "true" movement size for fee purposes; `Pips::fee_ceil` is a straightforward ceiling-rounding helper with no batch-awareness; there is no per-account/per-token minimum trade size or fee aggregation across intents in `execute_intents`.

### Impact Explanation
This directly reduces protocol revenue paid to `fee_collector` on `Nep245`/`Imt` swaps: any user (or colluding counterparties) trading multi-token balances of any magnitude can eliminate the entire protocol fee by decomposing the trade into `N` intents each moving `1` unit of the relevant token, instead of `1` intent moving `N` units. This matches the explicitly listed Critical impact category "protocol fees bypassed or over-collected". It is fully repeatable across any `Nep245`/`Imt` token, any account, and any batch, with no cap on the magnitude that can be evaded (evading fees on a movement of 1,000,000 units costs the same effort as splitting into 1,000,000 unit-legs, gas cost aside — which is explicitly out of scope per the rules).

### Likelihood Explanation
The attacker needs no special role — just the ability to sign `TokenDiff` intents and submit a `MultiPayload` batch via `execute_intents`/`simulate_intents`, which is available to any account with existing Verifier balances of a `Nep245`/`Imt` token. Splitting a trade into unit legs only requires a willing counterparty for the matching `+1` legs (which can be the same trade counterparty who already had to be present for a normal swap), so it is feasible for any P2P or solver-mediated `Nep245`/`Imt` swap. It is trivially repeatable.

### Recommendation
Compute the fee-exemption decision based on the true economic granularity of the token rather than per-intent `|delta|`. Concretely: track whether a `TokenId`'s `Nep245`/`Imt` instance is NFT-like (bounded to supply of 1, as already enforced for `Nep171` via `total_supply > 1` checks in `contracts/defuse/src/contract/tokens/mod.rs`) versus fungible, and only waive the fee for genuinely indivisible instances (max supply == 1), not merely because a single intent's delta happens to be 1. Alternatively, aggregate deltas per token across all `TokenDiff` intents in the batch before applying the `amount > 1` threshold, so splitting a movement across multiple intents cannot change the fee outcome.
