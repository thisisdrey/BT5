### Title
Relayer reward paid regardless of message execution outcome due to unchecked `DeliveryReceipt.success` flag - (File: bridges/snowbridge/pallets/outbound-queue-v2/src/lib.rs)

### Summary
`Pallet::process_delivery_receipt` decodes a `DeliveryReceipt` from a verified Ethereum transaction receipt/event log and pays the relayer (or a `reward_address` chosen by the relayer) the full `order.fee` for the corresponding `nonce`, without ever inspecting the `receipt.success` boolean that the event itself carries to indicate whether the outbound message actually executed successfully on the Ethereum `Gateway` contract.

### Finding Description
`DeliveryReceipt` is parsed from the `InboundMessageDispatched` Solidity event (`bool success` field) in [1](#0-0) , and the decode implementation copies `event.success` into the Rust struct at [2](#0-1) .

The extrinsic entrypoint `submit_delivery_receipt` verifies the header/message proof and decodes the receipt, then unconditionally forwards it to `process_delivery_receipt`: [3](#0-2) .

Inside `process_delivery_receipt`, the code checks the gateway address, resolves the `reward_account`, looks up the `PendingOrder` by `nonce`, and pays `order.fee` via `T::RewardPayment::register_reward` purely based on `order.fee > 0` — the decoded `receipt.success` value is never read: [4](#0-3) .

This is a direct analog of the "Unchecked Return Value" class from the external report: a status/success indicator returned from an external process (here, the Ethereum-side dispatch outcome carried inside a verified proof) is decoded but never checked before the dependent state-changing action (reward settlement) proceeds.

### Impact Explanation
Any relayer can submit a legitimate, cryptographically verified delivery-receipt proof for a message whose on-chain Ethereum execution reverted (`success = false`) and still collect the full relayer fee from `PendingOrders`, identical to a genuinely successful delivery. This decouples the reward-payout invariant from actual message settlement, allowing systematic collection of bridge relayer rewards for work that did not achieve its intended effect (message execution on Ethereum), which is a public underpriced-work / incorrect-payout condition on the Snowbridge outbound delivery flow.

### Likelihood Explanation
High: the path is a public, unprivileged extrinsic (`submit_delivery_receipt`) reachable by any signed account holding a valid proof of a real (but possibly failed) Ethereum transaction; no relayer allow-list, governance action, or malicious-peer assumption is required — an ordinary relayer only needs to relay a message that ends up reverting on the Ethereum Gateway (e.g., due to insufficient gas provisioning or an application-level revert) and then submit the resulting receipt.

### Recommendation
Branch on `receipt.success` in `process_delivery_receipt`: only call `T::RewardPayment::register_reward` when `receipt.success` is `true`; for `false`, either withhold/reduce the reward, apply a penalty, or route to a distinct handling path, while still removing the `PendingOrder` and emitting an event that reflects the failed outcome.

### Proof of Concept
1. A message is queued via `do_process_message`, creating a `PendingOrder { nonce, fee, .. }` [5](#0-4) .
2. The relayer relays the message to Ethereum; the Gateway contract's execution reverts (e.g. insufficient gas or a call that reverts), emitting `InboundMessageDispatched(nonce, topic, success=false, reward_address)`.
3. The relayer obtains a valid header/receipt proof for that (failed) event and calls `submit_delivery_receipt(origin, event)`.
4. `T::Verifier::verify` succeeds (the event is real), `DeliveryReceipt::try_from` decodes `success = false` into the struct, but `process_delivery_receipt` never reads that field and pays `order.fee` to `reward_account` exactly as it would for `success = true`.

```rust
		pub fn process_delivery_receipt(
			relayer: <T as frame_system::Config>::AccountId,
			receipt: DeliveryReceipt,
		) -> DispatchResult
		where
			<T as frame_system::Config>::AccountId: From<[u8; 32]>,
		{
			// Verify that the message was submitted from the known Gateway contract
			ensure!(T::GatewayAddress::get() == receipt.gateway, Error::<T>::InvalidGateway);

			let reward_account = if receipt.reward_address == [0u8; 32] {
				relayer
			} else {
				receipt.reward_address.into()
			};

			let nonce = receipt.nonce;

			let order = <PendingOrders<T>>::get(nonce).ok_or(Error::<T>::InvalidPendingNonce)?;

			if order.fee > 0 {
				// Pay relayer reward
				T::RewardPayment::register_reward(
					&reward_account,
					T::DefaultRewardKind::get(),
					order.fee,
				);
			}

			<PendingOrders<T>>::remove(nonce);

			Self::deposit_event(Event::MessageDelivered { nonce });

			Ok(())
		}
```
