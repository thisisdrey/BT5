### Title
Protocol fee bypass on NEP-245/IMT multi-token transfers by splitting a diff into unit-amount legs - ([File: contracts/defuse/core/src/intents/token_diff.rs])

### Summary
`TokenDiff::token_fee` computes the fee rate per individual `TokenDiff` intent using only that intent's own `|delta|`, exempting NEP-245/IMT (and NFT) legs whose amount is `<= 1` from any fee. Because fee computation is never aggregated across the multiple `TokenDiff` intents that a single `execute_intents` batch (or `TransferMatcher`) can combine, an attacker can split what would otherwise be a single fee-bearing multi-token transfer of size `N` into `N` unit-amount (`|delta| == 1`) `TokenDiff` intents and pay zero protocol fee on the whole transfer.

### Finding Description
The broken binding is:
`sum_{i=1..N} TokenDiff::token_fee(T, 1, fee).fee_ceil(1) == 0` (N separate unit legs)
vs.
`TokenDiff::token_fee(T, N, fee).fee_ceil(N) == fee.fee_ceil(N)` (one combined leg),
for `T` of `TokenIdType::Nep245`/`TokenIdType::Imt`, `fee > Pips::ZERO`.

In `ExecutableIntent for TokenDiff::execute_intent` [1](#0-0) , for every `(token_id, delta)` pair in `self.diff`, if `delta < 0` the fee is computed as `Self::token_fee(token_id, amount, protocol_fee).fee_ceil(amount)` where `amount = delta.unsigned_abs()` — strictly local to that single intent's own delta. `token_fee` itself gates the fee rate on `amount > 1` for `Nep245`/`Imt` types, returning `Pips::ZERO` otherwise: [2](#0-1) 

Nothing in `TokenDiff::execute_intent`, nor in the batch-level `TransferMatcher` that later reconciles all deltas across intents in the batch [3](#0-2) , aggregates deltas on the same `token_id` across multiple `TokenDiff` intents before deciding whether to apply the fee. The `TransferMatcher` only cares that deposits/withdrawals net to zero after fees have already been deducted per-intent; it performs no fee-relevant aggregation.

Exploit: the attacker holds `N` units of an NEP-245/IMT `token_id`. Instead of signing one `MultiPayload` with `TokenDiff{diff: {token_id: -N, ...}}` (which would charge `fee.fee_ceil(N)`), the attacker signs `N` separate `MultiPayload`s (distinct nonces), each with `TokenDiff{diff: {token_id: -1, other_token: +k}}`, and submits them together via `execute_intents`. Each leg is evaluated independently by `token_fee(token_id, 1, fee)`, which returns `Pips::ZERO` because `amount (1) > 1` is false, so `fee_ceil(1) == 0` for every leg. The counterparties (or the attacker's own self-matching legs) supply the offsetting positive deltas so the batch's `TransferMatcher::finalize` still balances to zero, but `fee_collector` never receives anything, whereas the same aggregate `-N` delta issued as one `TokenDiff` would have paid `fee.fee_ceil(N)`.

None of the existing guards prevent this: `MultiPayload::verify`, nonce checks, and `TransferMatcher::finalize`'s zero-sum invariant all pass normally — they only ensure balances net to zero and signatures/nonces are valid, not that the correct fee was charged. The design comment "do not take fees on NFTs and MTs with |delta| <= 1" assumes indivisible, always-unit-quantity assets; it does not account for a divisible NEP-245/IMT balance being deliberately fragmented into unit legs by its owner.

### Impact Explanation
`fee_collector`'s expected balance for token `T` falls short by `fee.fee_ceil(N)` per exploited batch, meaning protocol revenue is bypassed entirely on any NEP-245/IMT transfer that the signer chooses to fragment into unit legs. This is repeatable indefinitely, across any NEP-245/IMT token and any account, and scales with the size of the transfer being fragmented (larger `N` means bigger absolute fee loss), directly matching the "protocol fees bypassed" Critical impact category.

### Likelihood Explanation
The only precondition is holding a divisible NEP-245/IMT balance and a nonzero configured fee — both are ordinary states, not privileged. The attacker needs no special role: they just sign more, smaller `MultiPayload`s instead of one, at the cost of extra transaction/gas overhead and needing a counterparty (or self-matching multi-account setup) to keep the batch balanced. This is fully within the reach of any unprivileged signer and trivially repeatable.

### Recommendation
Compute and charge the NEP-245/IMT fee based on the aggregated negative delta per `token_id` across the whole intent/batch (e.g., accumulate per-token negative deltas via the `TransferMatcher` or a pre-pass over all `TokenDiff` intents in the batch before applying `token_fee`), rather than per single `TokenDiff` intent's own delta. Alternatively, remove the `amount > 1` exemption from `token_fee` for `Nep245`/`Imt` (keep the exemption only for genuinely indivisible `Nep171` NFTs), or track cumulative same-token-id negative deltas per signer/batch and only exempt intents when the true aggregate `|delta| <= 1`.

### Proof of Concept
Unit test (no sandbox needed) directly against `contracts/defuse/core/src/intents/token_diff.rs`:
```rust
#[test]
fn split_bypasses_mt_fee() {
    let token_id = TokenId::from(Nep245TokenId::new("mt.near".parse().unwrap(), "ft1".to_string()));
    let fee = Pips::ONE_PERCENT;
    let n: u128 = 10;

    // Combined single TokenDiff leg
    let combined_fee = TokenDiff::token_fee(&token_id, n, fee).fee_ceil(n);
    assert!(combined_fee > 0, "combined fee should be nonzero");

    // N split unit legs
    let split_fee: u128 = (0..n)
        .map(|_| TokenDiff::token_fee(&token_id, 1, fee).fee_ceil(1))
        .sum();
    assert_eq!(split_fee, 0);

    // Binding broken: sum of per-leg fees != fee on aggregate delta
    assert_ne!(split_fee, combined_fee);
}
```
For an end-to-end proof, a `near-workspaces` sandbox test can extend `tests/src/tests/defuse/intents/token_diff.rs`'s existing `swap_p2p`/`swap_many` harness: submit one `execute_intents` batch containing `N` signed `MultiPayload`s each with `TokenDiff{diff: {mt_token_id: -1, ft_token_id: +k}}` from the attacker matched against a counterparty's compensating `TokenDiff`, then assert `fee_collector`'s post-batch MT balance is `0` instead of the expected `fee.fee_ceil(N)`, as computed via `TokenDiff::closure_delta`/`token_fee` for the equivalent combined `-N` diff.

/// Accumulates internal deposits and withdrawals on different tokens
/// to match transfers using `.finalize()`
///
/// Transfers in `TokenDiff` intents are represented as deltas without receivers.
/// This struct accumulates tokens all transfers, and converts them from deltas, to
/// a set of transfers from one account to another.
/// Note that this doesn't touch account balances. The balances were already changed
/// in an earlier stage while executing the intent.
#[derive(Debug, Default)]
pub struct TransferMatcher(HashMap<TokenId, TokenTransferMatcher>);

impl TransferMatcher {
    #[inline]
    pub fn new() -> Self {
        Self(HashMap::new())
    }

    #[inline]
    pub fn deposit(&mut self, owner_id: AccountId, token_id: TokenId, amount: u128) -> bool {
        self.0.entry_or_default(token_id).deposit(owner_id, amount)
    }

    #[inline]
    pub fn withdraw(&mut self, owner_id: AccountId, token_id: TokenId, amount: u128) -> bool {
        self.0.entry_or_default(token_id).withdraw(owner_id, amount)
    }

    #[inline]
    pub fn add_delta(&mut self, owner_id: AccountId, token_id: TokenId, delta: i128) -> bool {
        self.0.entry_or_default(token_id).add_delta(owner_id, delta)
    }

    // Finalizes all transfers, or returns unmatched deltas.
    // If unmatched deltas overflow, then Err(None) is returned.
    pub fn finalize(self) -> Result<Transfers, InvariantViolated> {
        let mut transfers = Transfers::default();
        let mut deltas = TokenDeltas::default();
        for (token_id, transfer_matcher) in self.0 {
            if let Err(unmatched) = transfer_matcher.finalize_into(&token_id, &mut transfers)
                && (unmatched == 0 || deltas.apply_delta(token_id, unmatched).is_none())
            {
                return Err(InvariantViolated::Overflow);
            }
        }
        if !deltas.is_empty() {
            return Err(InvariantViolated::UnmatchedDeltas {
                unmatched_deltas: deltas,
            });
        }
        Ok(transfers)
    }
}
