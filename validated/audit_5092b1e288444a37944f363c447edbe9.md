### Title
Protocol fee bypass on `Nep245`/`Imt` `TokenDiff` intents via unit-delta batch splitting - ([File: contracts/defuse/core/src/intents/token_diff.rs])

### Summary
`TokenDiff::token_fee` waives the protocol fee whenever a `Nep245`/`Imt` token's per-intent negative delta magnitude is `<= 1`, and `TokenDiff::execute_intent` computes and collects fees independently for each `TokenDiff` intent with no aggregation across the batch. An unprivileged signer can therefore split any negative `Nep245`/`Imt` delta of size `N` into `N` separate `TokenDiff` intents each moving exactly `-1`, causing every individual fee computation to hit the `amount <= 1` exemption and yielding a total collected fee of `0` instead of `Pips::fee_ceil(fee, N)`.

### Finding Description
The broken binding: `fees_collected(T)` after processing a `MultiPayload` should equal `Pips::fee_ceil(fee, Σ|Δ_negative(T)|)` over all `TokenDiff` intents in the batch for token `T`. Instead, the code computes it per-intent: [1](#0-0) 

Each call to `execute_intent` allocates its own local `fees_collected: Amounts` and calls `Self::token_fee(token_id, amount, protocol_fee)` using only that single intent's `|delta|`: [2](#0-1) 

For `Nep245`/`Imt` tokens, `token_fee` returns `Pips::ZERO` whenever `amount <= 1`, and only applies the real `fee` when `amount > 1`. Because this threshold check is evaluated per intent (not on the aggregate signer delta for that token across the whole batch/payload), an attacker who needs to move `N` units of a `Nep245`/`Imt` token can sign `N` separate `TokenDiff` intents, each with `delta = -1` for that token (each offset by a matching `+1` elsewhere in the batch to satisfy `TransferMatcher::finalize`'s net-zero invariant), instead of one `TokenDiff` with `delta = -N`.

The dispatch path confirms there is no cross-intent aggregation: `Engine::execute_signed_intent` calls `intents.execute_intent` once per `MultiPayload`, and `DefuseIntents::execute_intent` simply iterates every `Intent` in that payload, calling each one's `execute_intent` independently: [3](#0-2) 

`Engine::finalize` (via `Deltas::finalize`/`TransferMatcher`) only checks that the *net* balance deltas across the batch settle to zero; it does not re-verify or recompute fee amounts against the total negative exposure per token. None of `MultiPayload::verify`, `has_public_key`, `verify_intent_nonce`, `commit_nonce`, or the finalize invariant check protects against this, because each intent has its own valid, distinct `intent_hash`/nonce and passes replay checks independently, and the fee exemption logic itself is the root cause, not a bypass of an existing guard.

Attacker's exact payload: a `MultiPayload` containing `N` signed `TokenDiff` intents, each with `diff = {T: -1, T_out: +k}` (or matched against counterparty intents), where `T` is a `Nep245`/`Imt` token. Each intent independently satisfies `amount(=1) <= 1`, so `token_fee` returns `Pips::ZERO` for every one of them, and the sum of `fees_collected` added to `fee_collector` across the whole batch is `0`, while the aggregate `Σ|Δ(T)|` moved is `N`.

### Impact Explanation
This is a protocol fee bypass on `fee_collector`, not fund theft from other users, but it directly under-collects the fee mandated by `engine.state.fee()` for `Nep245`/`Imt` token trades whose real economic size exceeds `1` unit. The bypass scales linearly with the number of `TokenDiff` intents included in a batch (bounded only by gas/payload size), so an attacker can route arbitrarily large `Nep245`/`Imt` volume through unit-sized intents and pay zero fee regardless of the configured `fee` rate. This matches the Critical category "protocol fees bypassed."

### Likelihood Explanation
No privileged role is required. The attacker only needs to be able to sign multiple `TokenDiff` intents (their own account, or coordinated with a counterparty/solver) whose deltas net to zero across the batch, which is standard usage of `TokenDiff` (see `solver_user_closure` / `swap_many` tests showing multi-intent `TokenDiff` batches are normal). Splitting a swap into unit-sized legs costs only extra signature/gas overhead, which is cheap relative to a fee percentage on any nontrivial `Nep245`/`Imt` transfer amount. This is fully repeatable across accounts, tokens, and batches.

### Recommendation
Compute the `Nep245`/`Imt` fee exemption based on the aggregate negative delta for a given `(signer_id, token_id)` across the entire `MultiPayload`/batch (or across the whole `DefuseIntents` execution), not on each `TokenDiff` intent's isolated delta. This could be done by accumulating negative deltas per token across all `TokenDiff` intents in `Engine`/`Deltas` before applying `token_fee`, or by moving fee assessment to `finalize()` where the net per-token exposure is already known.
