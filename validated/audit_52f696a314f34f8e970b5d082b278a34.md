### Title
Unauthenticated event-listener HTTP endpoint accepts forged node events, including chunks lacking a recovered signer key - ([File: libsigner/src/events.rs])

### Summary
The signer's `SignerEventReceiver` HTTP listener (`bind`/`next_event` in `libsigner/src/events.rs`) accepts `POST` requests on `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, and `/new_block` from any TCP client that can reach the bound socket, with no authentication check whatsoever. There is no `Authorization`/token verification anywhere in this file, unlike the node's `auth_token`, which only protects the *signer→node* RPC direction (block validation requests), not the *node→signer* event push direction.

### Finding Description
`SignerEventReceiver::bind` opens a plain `tiny_http` server on the configured `endpoint` [1](#0-0) , and `next_event` dispatches any POST to one of the known URLs straight into `process_event`, with no credential check [2](#0-1) . `process_event` simply reads the body, JSON-decodes it into the target event type, and converts it into a `SignerEvent`, which is then forwarded unconditionally to the signer's runloop channel [3](#0-2) . Sample deployment configs bind this listener on `0.0.0.0:30000` [4](#0-3) , and the docs describe the pairing purely via matching `endpoint`/`auth_token` strings for the *node's* RPC side, with no mention of any credential gating the *event push* side [5](#0-4) .

For `BlockValidateResponse` and `BurnBlockEvent`, the JSON payload is trusted directly with zero additional verification — `TryFrom<BlockValidateResponse>` and `TryFrom<BurnBlockEvent>` just wrap the fields into a `SignerEvent` [6](#0-5) . For `StackerDBChunksEvent` on the `.signers-*` contract, chunks are filtered only by whether a signature *recovers* to *some* public key (`chunk.recover_pk()`), not whether that key belongs to the actual registered signer set for that reward cycle/slot — that authorization check happens later, deeper in signer decision logic, which is out of scope here [7](#0-6) .

This breaks the intended trust boundary: the event listener is documented/designed to only ever receive pushes from the paired local `stacks-node`, but the transport enforces this by convention (matching bind address) rather than by any cryptographic or token-based check on the receiving side.

### Impact Explanation
An unauthenticated network peer that can reach the signer's event-listener port can inject forged `BlockValidateResponse` (`/proposal_response`) and `BurnBlockEvent` (`/new_burn_block`) events, and forged/garbage StackerDB chunk events, directly into the signer's event stream as if they came from the trusted node. Because `TryFrom<BlockValidateResponse>`/`TryFrom<BurnBlockEvent>` perform no signature or provenance check at all, this is a genuine unauthenticated write into the signer process's internal event queue — an auth bypass at the transport layer. Whether this rises to "Critical" (unauthorized write to state) or is contained depends on deployment topology (i.e., whether the port is reachable beyond `127.0.0.1`), but the code itself provides no defense-in-depth if it is exposed, and sample configs suggest binding on `0.0.0.0`.

### Likelihood Explanation
Likelihood depends heavily on operator configuration — if the signer's event endpoint is firewalled to loopback/localhost only, this is not remotely reachable. However, the shipped sample config explicitly sets `endpoint = "0.0.0.0:30000"` with no accompanying warning about restricting exposure, and there is no code-level authentication fallback to compensate for a misconfigured firewall, unlike the node-side RPC path which has `auth_token`.

### Recommendation
Add a shared-secret or token-based authentication check (mirroring the node's `auth_token`) to `SignerEventReceiver::next_event`/`process_event` in `libsigner/src/events.rs`, rejecting any POST request that lacks a valid credential before parsing/forwarding the body. This closes the gap regardless of network exposure and matches the symmetry already present for the node's RPC endpoint.

### Proof of Concept
1. Start a signer whose event listener binds `0.0.0.0:30000` (as in the shipped sample config).
2. From a separate, unauthenticated host that can reach port 30000, send:
```
POST /proposal_response HTTP/1.1
Host: <signer-ip>:30000
Content-Type: application/json
Content-Length: <len>

{ ... arbitrary BlockValidateResponse JSON ... }
```
3. `process_event::<T, BlockValidateResponse>` in `libsigner/src/events.rs` decodes this with no authentication and forwards it as `SignerEvent::BlockValidationResponse` to the signer runloop, exactly as if it had come from the paired node.

    /// Wait for the node to post something, and then return it.
    /// Errors are recoverable -- the caller should call this method again even if it returns an
    /// error.
    fn next_event(&mut self) -> Result<SignerEvent<T>, EventError> {
        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)
            } else if request.url() == "/new_block" {
                process_event::<T, StacksBlockEvent>(request)
            } else {
                let url = request.url().to_string();
                debug!(
                    "[{:?}] next_event got request with unexpected url {}, return OK so other side doesn't keep sending this",
                    event_receiver.local_addr,
                    url
                );
                ack_dispatcher(request);
                Err(EventError::UnrecognizedEvent(url))
            }
        })?

fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}

### 3. Verify Coordination

These settings **must** match between the node and signer configs:

| Signer Config   | Node Config                       | Must Match                    |
| --------------- | --------------------------------- | ----------------------------- |
| `auth_password` | `[connection_options] auth_token` | Exact string match            |
| `endpoint`      | `[[events_observer]] endpoint`    | Same host:port                |
| `node_host`     | `[node] rpc_bind`                 | Signer connects to node's RPC |
```
