### Title
Dust liquidations can front-run and invalidate maximum liquidation transactions - (File: `contracts/Pool.sol`)

### Summary
`Pool.quoteLiquidateMax()` calculates the largest repayable amount from the victim’s current debt balance and collateral balance. [1](#0-0)  An unprivileged user can front-run a maximum liquidation with a public dust liquidation, reducing the victim’s debt and collateral before the quoted maximum transaction executes. [2](#0-1) 

### Finding Description
When the liquidation limit is debt-bound, `quoteLiquidateMax()` returns approximately `debt * maxLiquidable`. [3](#0-2)  After an attacker repays even one unit of the victim’s debt, the stale amount divided by the reduced debt exceeds `maxLiquidable`, causing `liquidate()` to revert with `AmountGreaterThanMaxLiquidable`. [4](#0-3) 

When the maximum is collateral-bound, the attacker’s dust liquidation also seizes collateral through `depositToken_.seize()`. [5](#0-4)  The previously quoted amount can then require more collateral than remains and revert with `AmountIsTooHigh`. [6](#0-5) 

The attacker requires only synthetic-token balance, which can be obtained publicly by depositing collateral and issuing debt through `DebtToken.issue()` subject to normal collateral checks. [7](#0-6)  No privileged modifier restricts a liquidation to particular callers. [8](#0-7) 

### Impact Explanation
An attacker can repeatedly invalidate transactions that attempt to liquidate the maximum available amount. Because the attacker receives the configured liquidation incentive for each dust liquidation, the maneuver can be economically rational rather than purely griefing. [9](#0-8) 

The result is temporary denial of the protocol’s full-size liquidation path. Delayed liquidation during adverse price movement can leave collateral seized later at a worse protocol outcome and increase the probability of bad debt.

### Likelihood Explanation
The attack is reachable from any EOA that holds at least one repayable unit of the relevant synthetic token. It applies whenever another liquidator submits a transaction using a stale `quoteLiquidateMax()` result, which is the natural way to request the maximum liquidation. [1](#0-0) 

The existing guards do not prevent it: the victim must merely remain unhealthy, the attacker cannot be the victim, and a dust repayment is below `maxLiquidable`. [10](#0-9)  The dust repayment ordinarily avoids the debt-floor check because it leaves a large positive debt balance. [11](#0-10) 

### Recommendation
Allow a caller to request the current maximum liquidation atomically rather than requiring an exact stale quote. For example, support `type(uint256).max` as “liquidate the current maximum,” or calculate the current maximum inside `liquidate()` and clamp `amountToRepay_` to that value before applying the debt-floor and collateral checks.

A suitable pattern is:

```solidity
if (amountToRepay_ == type(uint256).max) {
    amountToRepay_ = quoteLiquidateMax(syntheticToken_, account_, depositToken_);
}
```

### Proof of Concept
A Hardhat regression test can be added beside the existing liquidation tests in `test/Pool.test.ts`; the test environment already exposes `pool`, `msEth`, `msEthDebtToken`, `msdMET`, `masterOracle`, `alice`, and `liquidator`. [12](#0-11) 

```ts
it('front-runs a max liquidation with a dust liquidation', async function () {
  // Make alice's position unhealthy while retaining enough collateral that
  // debt * maxLiquidable is the limiting quote.
  await masterOracle.updatePrice(met.address, newMetPrice)

  const maxLiquidable = await pool.maxLiquidable()
  const debtBefore = await msEthDebtToken.balanceOf(alice.address)
  const quotedMax = await pool.quoteLiquidateMax(
    msEth.address,
    alice.address,
    msdMET.address
  )

  // Ensure the selected scenario is debt-bound.
  expect(quotedMax).to.eq(debtBefore.mul(maxLiquidable).div(parseEther('1')))

  // Attacker/front-runner publicly performs a one-unit liquidation.
  await pool
    .connect(attacker)
    .liquidate(msEth.address, alice.address, 1, msdMET.address)

  // The transaction built from the pre-front-run quote is now invalid.
  await expect(
    pool
      .connect(liquidator)
      .liquidate(msEth.address, alice.address, quotedMax, msdMET.address)
  ).to.be.revertedWithCustomError(pool, 'AmountGreaterThanMaxLiquidable')
})
```

    function liquidate(
        ISyntheticToken syntheticToken_,
        address account_,
        uint256 amountToRepay_,
        IDepositToken depositToken_
    )
        external
        override
        whenNotShutdown
        nonReentrant
        onlyIfSyntheticTokenExists(syntheticToken_)
        onlyIfDepositTokenExists(depositToken_)
        returns (uint256 _totalSeized, uint256 _toLiquidator, uint256 _fee)
    {
        address _msgSender = _msgSender();

        if (amountToRepay_ == 0) revert AmountIsZero();
        if (_msgSender == account_) revert CanNotLiquidateOwnPosition();

        IDebtToken _debtToken = debtTokenOf[syntheticToken_];
        _debtToken.accrueInterest();

        (bool _isHealthy, , , , ) = debtPositionOf(account_);

        if (_isHealthy) {
            revert PositionIsHealthy();
        }

        uint256 _debtTokenBalance = _debtToken.balanceOf(account_);

        if (amountToRepay_.wadDiv(_debtTokenBalance) > maxLiquidable) {
            revert AmountGreaterThanMaxLiquidable();
        }

        if (debtFloorInUsd > 0) {
            uint256 _newDebtInUsd = masterOracle().quoteTokenToUsd(
                address(syntheticToken_),
                _debtTokenBalance - amountToRepay_
            );
            if (_newDebtInUsd > 0 && _newDebtInUsd < debtFloorInUsd) {
                revert RemainingDebtIsLowerThanTheFloor();

        if (_totalSeized > depositToken_.balanceOf(account_)) {
            revert AmountIsTooHigh();
        }

        syntheticToken_.burn(_msgSender, amountToRepay_);
        _debtToken.burn(account_, amountToRepay_);
        depositToken_.seize(account_, _msgSender, _toLiquidator);
