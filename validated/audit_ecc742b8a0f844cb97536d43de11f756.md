No valid analog exists in this repository for CVE-2016-3087.

The CVE concerns Apache Struts' REST plugin, where enabling Dynamic Method Invocation lets an unauthenticated attacker use OGNL expression syntax (the `!` operator) to invoke arbitrary methods on action classes reachable from the web tier, without any developer-side allowlisting — this results in unauthenticated RCE.

The closest structural analog in this Go standard-library repository is `net/rpc`, where the server dispatches method calls by name arriving over the wire. However, this does not share the same root-cause primitive:

- Methods are only reachable if the server explicitly calls `Register`/`RegisterName` [1](#0-0) , and `suitableMethods` filters the registered type's methods down to exported methods matching a strict signature (`(arg, *reply) error`) before they're placed in `s.method` [2](#0-1) .
- On the wire, `readRequestHeader` splits `Service.Method`, looks up the service in `server.serviceMap`, and then looks up the method strictly in the *pre-registered* `svc.method` map — an unknown method returns an explicit `"rpc: can't find method"` error rather than falling through to arbitrary reflection [3](#0-2) .
- The actual invocation, `function.Call(...)`, is only ever performed against a `methodType` obtained from that same vetted map [4](#0-3) .

This is fundamentally different from the Struts flaw: there is no expression language, no `!`-style operator syntax, and no way for an unauthenticated caller to reach a method that the application owner did not explicitly register and whose signature was not validated ahead of time. The behavior is intentional, by-design RPC dispatch, not a parsing/authorization bypass, and it's not reachable by an unprivileged party without the application author choosing to expose and register that exact method. The compiler/linker's `MethodByName` reachability analysis (`usemethod` in `walk/expr.go`, `deadcode` in `ld/deadcode.go`) is a build-time dead-code elimination mechanism, not a runtime authorization boundary reachable by attacker input, so it isn't a plausible analog either.
