## Title
Hardcoded `ADDRESS_REGISTRAR_ACCOUNT_ID` in the Wallet Contract causes caller deposits to be misappropriated instead of refunded on non-standard networks - (File: `runtime/near-wallet-contract/implementation/wallet-contract/src/lib.rs`)

### Summary
The ETH-implicit Wallet Contract embeds a compile-time-hardcoded address registrar account id (analogous to the hardcoded Uniswap router in the referenced report) and uses it to perform a cross-contract lookup before executing certain emulated Ethereum base-token transfers. When that hardcoded registrar account does not exist on the network the contract is deployed to (any chain other than the specific mainnet/testnet builds), the lookup promise fails, and the failure-handling branch silently drops the caller's attached deposit instead of refunding it — unlike the sibling callback `rlp_execute_callback`, which correctly refunds on failure.

### Finding Description
The registrar account id is baked into the contract binary at compile time: [1](#0-0) [2](#0-1) 

Different wasm binaries are pre-built per chain, and any chain that is not explicitly "mainnet" or "testnet" falls back to the `LOCALNET` build whose registrar id was baked in at build/test time and is not guaranteed to exist on a given deployment: [3](#0-2) [4](#0-3) 

When a relayer submits an `EOABaseTokenTransfer` that requires an address check (i.e. the target's derived address could plausibly correspond to a real named account), the contract creates a promise to `ADDRESS_REGISTRAR_ACCOUNT_ID.lookup(...)`, parsed directly from this hardcoded constant: [5](#0-4) 

The caller's attached deposit is tracked via `CallerDeposit` specifically so it can be refunded if the downstream cross-contract call fails: [6](#0-5) 

However, in `address_check_callback`, the `PromiseResult::Failed` branch (triggered when the registrar account does not exist / the call errors) returns an error response but never refunds `caller_deposit` — it is simply dropped: [7](#0-6) 

This is inconsistent with the general-purpose callback `rlp_execute_callback`, which does refund `caller_deposit` on a failed promise: [8](#0-7) 

Because the attached deposit for a `payable` method call is credited to the wallet contract's own account balance as soon as the function-call receipt executes, failing to issue a refund promise means that balance simply stays with the wallet (and is later spendable by the wallet's private-key owner), effectively transferring the relayer/caller's funds to the wallet owner without their consent.

### Impact Explanation
Any relayer/caller that attaches a NEAR deposit while calling `rlp_execute` for an `EOABaseTokenTransfer` requiring an address check will have that deposit permanently misappropriated (given to the wallet's owner instead of refunded) whenever the hardcoded registrar lookup fails — which is deterministic and reproducible on every ETH-implicit account deployed via the fallback `LOCALNET` wallet contract build on any chain lacking the baked-in registrar account. This is a concrete loss of caller funds (theft-by-omission of refund logic), directly caused by the non-configurable, hardcoded registrar address, mirroring the reported bug class of hardcoded addresses causing fund loss on non-standard networks.

### Likelihood Explanation
This is triggered by an ordinary, unprivileged caller (a relayer) simply invoking the documented `rlp_execute` entry point with any deposit attached for an eth-implicit-target base-token transfer; no special privileges are required, and the failure condition is guaranteed on any deployment of the `LOCALNET`/custom-chain wallet contract build where `address-map.near`-style hardcoded registrar id is absent, which is exactly the "non-standard network" scenario the original report describes.

### Recommendation
Refund `caller_deposit` in the `PromiseResult::Failed` arm of `address_check_callback`, mirroring the logic already present in `rlp_execute_callback`. Separately, avoid hardcoding the registrar account id at compile time; make it configurable per-deployment (e.g., part of contract state settable at initialization, similar in spirit to the report's recommendation of a constructor argument or admin-settable field) rather than embedding it via `include_str!`.

### Proof of Concept
1. Deploy the ETH-implicit Wallet Contract's `LOCALNET` build (per `wallet_contract_magic_bytes`/`eth_wallet_global_contract_hash` fallback) as the global contract for ETH-implicit accounts on a custom nearcore-based chain that does not have the baked-in `ADDRESS_REGISTRAR_ACCOUNT_ID` account deployed.
2. A relayer calls `rlp_execute` with an RLP transaction representing an `EOABaseTokenTransfer` to a target address requiring `address_check` (target address could plausibly be a named account), attaching a nonzero NEAR deposit to the `FunctionCall`.
3. Inside `inner_rlp_execute`, `address_registrar.lookup(...)` is scheduled against the nonexistent hardcoded account id; the receipt fails because the account does not exist.
4. `address_check_callback` receives `PromiseResult::Failed`, returns `ExecuteResponse { success: false, ... }`, and — per lines cited above — never issues a refund promise for `caller_deposit`.
5. The attached deposit remains part of the wallet (eth-implicit) account's balance, spendable only by the wallet's private-key owner, while the relayer who attached it receives nothing back.

/// A data type to keep track of the deposit given by an external caller.
/// This allows us to refund the caller's deposit if the cross-contract call fails.
#[derive(Debug, PartialEq, Eq, Clone, serde::Serialize, serde::Deserialize)]
pub struct CallerDeposit {
    pub account_id: AccountId,
    pub yocto_near: NonZeroU128,
}

impl CallerDeposit {
    pub fn new(context: &ExecutionContext) -> Option<Self> {
        // Only track for external (non-self) callers
        if context.current_account_id == context.predecessor_account_id {
            return None;
        }

        NonZeroU128::new(context.attached_deposit.as_yoctonear()).map(|yocto_near| Self {
            account_id: context.predecessor_account_id.clone(),
            yocto_near,
        })
    }
}
