The external Mantra bug is specific to a stableswap fee-quoting function (`query_reverse_simulation`) that omitted `extra_fees` from an inverse fee calculation used to derive an off-chain-facing quote, causing quoted and actual settlement amounts to diverge. Tare has no analogous formulaic "quote with fees" surface:

- The vault's `convertToShares`/`convertToAssets`/preview-style helpers use the exact same `assets * totalSupply / lastNav` (and inverse) formula as the actual `approveDeposit`/`approveRedemption` accounting paths, with no separate/partial fee model that could drift out of sync.
- `NavCalculator.getLoansValue` uses a single formula (`unreturnedInvestorPrincipal * bucketFactor + collectedCash`) consistently everywhere it's called; there's no second "reverse" or "preview" code path with a different, incomplete fee/discount composition.
- `LoansExchange` offer settlement uses a manually agreed lump-sum `price` with no on-chain fee formula at all — there's nothing computed like an in/out "simulation" that could omit a fee term. [1](#0-0) [2](#0-1) [3](#0-2) 

No reachable root cause matching the "quote omits a fee term used in a separate settlement formula" bug class was found in this repository.
