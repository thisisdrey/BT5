Audit Report

## Title
`pallet-psm::redeem` omits the live-decimals drift check present in `mint`, allowing conversions to run on a stale decimals snapshot - ([File: substrate/frame/psm/src/lib.rs])

## Summary
`pallet-psm`'s `mint` extrinsic validates that live on-chain decimals for both the internal and external asset still match the registration-time snapshot via `Self::ensure_decimals_match(...)` before performing any scaling arithmetic [1](#0-0) . `redeem`, which is documented by the same pallet's release notes as required to have this identical guard, instead reads the snapshot values `external.decimals` and `info.internal_decimals` directly with no drift check at all before driving `internal_to_external`/`external_to_internal` scaling and debt accounting [2](#0-1) .

## Finding Description
`ensure_decimals_match` compares `T::Fungibles::decimals(...)` for both assets against the stored snapshot and returns `Error::DecimalsMismatch` on divergence [3](#0-2) . `mint` calls it before any conversion math [4](#0-3) . `redeem` never calls this function; it pulls `ext_decimals`/`internal_decimals` straight from storage and proceeds to compute `external_out`, `effective_internal_net`, debt checks, transfers, and burns using those unchecked values [5](#0-4) .

The prdoc for this feature explicitly states the intended invariant: "Runtime drift guard: `mint`/`redeem` return `DecimalsMismatch` if live metadata diverges from the registration snapshot; that asset halts until governance intervenes" [6](#0-5) . The implementation satisfies this only for `mint`. Any asset owner can independently change `decimals` on their own asset via the permissionless (to them) `pallet_assets::set_metadata` extrinsic [7](#0-6) , creating exactly the drift condition the guard is meant to catch — but `redeem` will keep running scaling arithmetic on the stale snapshot regardless.

## Impact Explanation
`redeem` is a public, unprivileged, signed extrinsic that moves value out of the PSM reserve (`T::Fungibles::transfer` of `external_out`) and burns internal-asset supply (`T::Fungibles::burn_from` of `effective_internal_net`) based on a scaling factor derived from `ext_decimals`/`internal_decimals` [8](#0-7) . If the live decimals no longer match the snapshot, `internal_to_external`/`external_to_internal` (which scale by `10^|ext_decimals - internal_decimals|`) compute a payout/debt-reduction amount that no longer reflects real asset unit conversion [9](#0-8) , directly corrupting the amount paid to the user versus internal debt retired — a violation of the "conserve value and settle exactly once" asset-accounting invariant.

## Likelihood Explanation
Triggering this requires only that an external asset's decimals metadata drift after PSM registration, a normal and explicitly anticipated event per the pallet's own migration/registration design (`AssetDecimals` snapshot + drift guard). Any signed user can then call `redeem` on the affected pair with no privileged access beyond the routine ability of a registered asset's own owner to call the standard `set_metadata` extrinsic.

## Recommendation
Add `Self::ensure_decimals_match(&info, &internal_asset, &external_asset, &external)?` to `redeem` before computing `ext_decimals`/`internal_decimals`, mirroring `mint`, so redemption halts with `Error::DecimalsMismatch` under drift instead of continuing arithmetic on a stale snapshot. If the pallet intends redemptions to remain available under drift (as the function's own doc comment states: "Redemptions use the decimals snapshotted when the PSM/external pair was registered, allowing existing positions to unwind even if live metadata later changes" [10](#0-9) ), the prdoc's stated invariant should be corrected to reflect that only `mint` enforces the drift guard, since these two documentation sources are currently in direct conflict.

## Proof of Concept
1. Register an external asset (e.g. 18 decimals) with `pallet-psm`, snapshotting `external.decimals = 18`.
2. As the asset's registered owner, call `pallet_assets::set_metadata` to change its decimals (e.g. to 6) [7](#0-6) .
3. Call `Psm::mint(...)` for that asset — it fails with `Error::DecimalsMismatch` via `ensure_decimals_match` [1](#0-0) .
4. Call `Psm::redeem(...)` for the same asset — it succeeds despite the identical decimals divergence, since `redeem` never invokes `ensure_decimals_match` and scales with the stale snapshot values [11](#0-10) .

					let factor = Self::pow10(diff)?;

			}
		}

		/// Verify the live decimals for an external still match the snapshot taken at
		/// registration on this PSM, and that the internal asset's live decimals still
		/// match the snapshot stored in [`PsmInfo`].
		pub(crate) fn ensure_decimals_match(
			info: &PsmInfo<T>,
			internal_asset: &T::AssetId,
			external_asset: &T::AssetId,
			external: &ExternalAssetInfo,
		) -> Result<(u8, u8), DispatchError> {
			ensure!(
				T::Fungibles::decimals(external_asset.clone()) == external.decimals,
				Error::<T>::DecimalsMismatch
			);
			ensure!(
				T::Fungibles::decimals(internal_asset.clone()) == info.internal_decimals,
				Error::<T>::DecimalsMismatch
			);
			Ok((external.decimals, info.internal_decimals))
		}
