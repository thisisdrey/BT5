Audit Report

## Title
Permanently unclaimable relayer tips recorded in `LostTips` with no recovery mechanism - (File: `bridges/snowbridge/pallets/system-v2/src/lib.rs`)

## Summary
When a user pre-pays a relayer tip for an inbound/outbound Snowbridge message via `pallet_bridge_system_v2::add_tip`, and that tip loses the race against the relayer's `submit`/message-processing call for the same nonce, the already-debited tip amount is diverted into the `LostTips` storage map instead of the relayer reward. No dispatchable in the scoped pallets (`system-v2`, `system-frontend`, `inbound-queue-v2`, `outbound-queue-v2`) reads, refunds, or drains `LostTips`, so the value is permanently stranded on-chain.

## Finding Description
A user calls `pallet_bridge_system_frontend::add_tip`, which unconditionally swaps/burns the user's tip asset for ether before dispatching an XCM `Transact` to BridgeHub's `pallet_bridge_system_v2::add_tip` [5](#0-4) . On BridgeHub, `add_tip` calls `InboundQueue::add_tip`/`OutboundQueue::add_tip`; if this fails (e.g., because the nonce has already been consumed), the amount is moved into `LostTips::<T>` via `saturating_add` rather than applied to any reward [1](#0-0) .

The race condition is explicit: `pallet_snowbridge_inbound_queue_v2::AddTip::add_tip` returns `AddTipError::NonceConsumed` if `Nonce::<T>::get(nonce)` is already true [3](#0-2) , and `process_message` sets that nonce and atomically consumes any pending `Tips` entry as part of ordinary successful relaying [4](#0-3) . The `LostTips` doc comment itself concedes the gap: "Capturing the lost tips here supports implementing a recovery method in the future" [2](#0-1) . A repository-wide search confirms `LostTips` is referenced only in `system-v2/src/lib.rs` and test files — no extrinsic anywhere reads or drains it.

## Impact Explanation
This matches the "permanent user-fund or bridge-state lock" impact category: an ordinary, non-malicious user's already-debited ether-denominated tip becomes permanently unrecoverable through any on-chain mechanism, with the exact corrupted/stranded value being the `u128` entry keyed by `sender` in `LostTips::<T>`.

## Likelihood Explanation
High under normal operation. Tips are explicitly intended to be added to messages that are still pending relaying; any ordinary user boosting a fee for a message that a relayer processes in the same or an earlier block will trigger this loss. No adversarial timing, privileged access, or compromised party is required — only routine transaction-inclusion ordering.

## Recommendation
Add a signed extrinsic that allows the `sender` recorded in `LostTips` to withdraw their stranded balance, or redesign the flow so the tip is only debited from the user after confirming, atomically, that the corresponding nonce is unconsumed (e.g., a pessimistic reservation model that the user can unreserve if the tip fails to apply).

## Proof of Concept
1. User calls `pallet_bridge_system_frontend::add_tip(message_id, asset)`; the pallet swaps/burns the asset for ether and dispatches an XCM `Transact` targeting `pallet_bridge_system_v2::add_tip(sender, Inbound(nonce), amount)` on BridgeHub.
2. In the same or an earlier block, a relayer calls `submit` for the same `nonce`; `process_message` succeeds, sets `Nonce::<T>::set(nonce)`, and consumes/pays any tip present at that time (none yet).
3. The `add_tip` XCM arrives; `InboundQueue::add_tip` finds `Nonce::<T>::get(nonce) == true` and returns `AddTipError::NonceConsumed`.
4. `pallet_bridge_system_v2::add_tip` catches the error, moves `amount` into `LostTips::<T>::get(&sender)`, and emits `TipProcessed { success: false, .. }`.
5. No extrinsic exists in `system-v2`, `system-frontend`, `inbound-queue-v2`, or `outbound-queue-v2` to return this value to `sender`; it is permanently locked.

	impl<T: Config> Pallet<T> {
		pub fn process_message(relayer: T::AccountId, message: Message) -> DispatchResult {
			// Verify that the message was submitted from the known Gateway contract
			ensure!(T::GatewayAddress::get() == message.gateway, Error::<T>::InvalidGateway);

			let (nonce, relayer_fee) = (message.nonce, message.relayer_fee);

			// Verify the message has not been processed
			ensure!(!Nonce::<T>::get(nonce), Error::<T>::InvalidNonce);

			// Mark message as received
			Nonce::<T>::set(nonce);

			let message_id = T::MessageProcessor::process_message(relayer.clone(), message)
				.map_err(|e| match e {
					MessageProcessorError::ProcessMessage(e) => e,
					MessageProcessorError::ConvertMessage(e) => Error::<T>::from(e).into(),
					MessageProcessorError::SendMessage(e) => Error::<T>::from(e).into(),
				})?;

			// Pay relayer reward
			let tip = Tips::<T>::take(nonce).unwrap_or_default();
			let total_tip = relayer_fee.saturating_add(tip);
			if total_tip > 0 {
				T::RewardPayment::register_reward(&relayer, T::DefaultRewardKind::get(), total_tip);
			}

			// Emit event with the message_id
			Self::deposit_event(Event::MessageReceived { nonce, message_id });

			Ok(())
		}

		fn add_tip(nonce: u64, amount: u128) -> Result<(), AddTipError> {
			ensure!(amount > 0, AddTipError::AmountZero);
			// If the nonce is already processed, return an error
			ensure!(!Nonce::<T>::get(nonce.into()), AddTipError::NonceConsumed);
			// Otherwise add the tip.
