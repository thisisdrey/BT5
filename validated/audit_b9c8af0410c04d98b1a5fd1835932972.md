### Title
`FetchIntoObjectPool` fetches from an arbitrary caller-supplied `origin` repository into any object pool without verifying the origin is actually a linked member of that pool - ([File: internal/gitaly/service/objectpool/fetch_into_object_pool.go])

### Summary
`FetchIntoObjectPool` performs a privileged, resource-intensive git-fetch of *all references* (`+refs/*:refs/remotes/origin/*`) from a caller-supplied `origin` repository into a caller-supplied `object_pool` repository. The validation, `validateFetchIntoObjectPoolRequest`, only checks that both fields are non-nil and reside on the same storage — it never verifies that `origin` is actually a pool member linked to that specific `object_pool` (i.e. that `origin`'s alternates file points to this pool). This mirrors the "exercise" bug class: the handler operates on a caller-supplied secondary resource reference (`origin`) against a target resource (`object_pool`) without first confirming that the two are actually associated, allowing any caller who can reach this RPC to pull references/objects from an unrelated repository into a pool it does not own.

By contrast, `LinkRepositoryToObjectPool` at least records/validates the relationship via the alternates file mechanism, and `Disconnect`/`linkedToRepository` explicitly check that a repo's alternates point at the specific pool before treating it as a member. `FetchIntoObjectPool` skips this ownership/membership check entirely, so as long as `origin` and `object_pool` are on the same storage, an attacker with RPC access can name any two arbitrary repositories.

### Impact Explanation
An unprivileged caller able to invoke `FetchIntoObjectPool` (e.g. via a compromised/limited-scope token or a service that proxies this RPC per-repository) can specify any `origin` repository on the same storage as a target object pool they control (or vice versa), forcing Gitaly to fetch all of that origin repository's references — including private branches/tags not otherwise exposed — into the pool. Since dangling refs are preserved permanently (`refs/dangling/$OID`) per the design docs, and pool objects become reachable through any pool member via alternates, this can be used to smuggle private objects/refs from a victim repository into a repository the attacker controls (any repo linked to that pool), analogous to receiving another user's "profit" without authorization. It is also a resource-exhaustion vector: fetching arbitrarily large/unrelated repositories repeatedly triggers full repacking/housekeeping of the pool.

### Likelihood Explanation
`FetchIntoObjectPool` is a `MUTATOR` RPC reachable by any client with general Gitaly RPC access (the same trust boundary as ordinary push/fetch operations); it takes both `origin` and `object_pool` directly as request fields with no server-side derivation from an already-established pool membership, and the only guard is a same-storage check, so exploitation only requires knowing (or guessing) two repository paths that share a storage — a low bar in a Gitaly install serving many repositories per storage.

### Recommendation
Before performing the fetch, verify that `origin` is actually a linked member of `object_pool` (or is the pool's designated primary/original member), analogous to the check performed by `linkedToRepository` in `internal/git/objectpool/link.go`. For example, require that `origin`'s `objects/info/alternates` resolves to the target pool's object directory (or otherwise track/authorize pool membership) before invoking `FetchFromOrigin`, rather than relying solely on a same-storage-name comparison in `validateFetchIntoObjectPoolRequest`.

### Proof of Concept
1. Create object pool `P` from repository `A` (`CreateObjectPool`), and separately create an unrelated repository `V` (victim) on the same storage — `V` is never linked to `P`.
2. As an attacker who can call `FetchIntoObjectPool`, send:
```
FetchIntoObjectPoolRequest{
  Origin:      V,   // victim repo, not a member of P
  ObjectPool:  P,
}
```
3. `validateFetchIntoObjectPoolRequest` only checks `V.StorageName == P.Repository.StorageName`, which passes.
4. `FetchFromOrigin` executes `git fetch <V-path> +refs/*:refs/remotes/origin/*` into `P`'s repository, pulling all of `V`'s references/objects into the pool, even though `V` was never linked to `P` via `LinkRepositoryToObjectPool`.
5. Any repository already linked to `P` (via alternates) can now read `V`'s objects through the pool's dangling refs, without `V`'s owner ever consenting to be part of that pool.

func validateFetchIntoObjectPoolRequest(req *gitalypb.FetchIntoObjectPoolRequest) error {
	if req.GetOrigin() == nil {
		return errors.New("origin is empty")
	}

	if req.GetObjectPool() == nil {
		return errors.New("object pool is empty")
	}

	originRepository, poolRepository := req.GetOrigin(), req.GetObjectPool().GetRepository()

	if originRepository.GetStorageName() != poolRepository.GetStorageName() {
		return errors.New("origin has different storage than object pool")
	}

	return nil

// linkedToRepository tests if a repository is linked to an object pool
func linkedToRepository(ctx context.Context, pool, repo *localrepo.Repo) (bool, error) {
	poolPath, err := pool.Path(ctx)
	if err != nil {
		return false, fmt.Errorf("getting object pool path: %w", err)
	}

	repoPath, err := repo.Path(ctx)
	if err != nil {
		return false, fmt.Errorf("getting repo path: %w", err)
	}

	altInfo, err := stats.AlternatesInfoForRepository(repoPath)
	if err != nil {
		return false, fmt.Errorf("getting alternates info: %w", err)
	}

	if !altInfo.Exists || len(altInfo.ObjectDirectories) == 0 {
		return false, nil
	}

	relPath := altInfo.ObjectDirectories[0]
	expectedRelPath, err := getRelativeObjectPath(ctx, pool, repo)
	if err != nil {
		return false, err
	}

	if relPath == expectedRelPath {
		return true, nil
	}

	if filepath.Clean(relPath) != filepath.Join(poolPath, "objects") {
		return false, fmt.Errorf("unexpected alternates content: %q", relPath)
	}

	return false, nil
}

func (o *ObjectPool) FetchFromOrigin(ctx context.Context, origin *localrepo.Repo, newLocalRepo LocalRepoFactory) error {
	if !o.Exists(ctx) {
		return structerr.NewInvalidArgument("object pool does not exist")
	}

	originPath, err := origin.Path(ctx)
	if err != nil {
		return fmt.Errorf("computing origin repo's path: %w", err)
	}

	if err := o.housekeepingManager.CleanStaleData(ctx, o.Repo, housekeeping.DefaultStaleDataCleanup()); err != nil {
		return fmt.Errorf("cleaning stale data: %w", err)
	}

	if err := o.logStats(ctx, "before fetch"); err != nil {
		return fmt.Errorf("computing stats before fetch: %w", err)
	}
