### Title
Stale postponed/promise-yield receipt state not cleared by `remove_account` enables receipt hijacking on account-name reuse - (File: `core/store/src/utils/mod.rs`)

### Summary
`remove_account` (`core/store/src/utils/mod.rs:504-575`), invoked from `action_delete_account` (`runtime/runtime/src/actions.rs:314-391`), only removes `TrieKey::Account`, `ContractCode`, `AccessKey`/`GasKeyNonce`, and `ContractData`. It never removes `ReceivedData`, `PostponedReceiptId`, `PendingDataCount`, `PostponedReceipt`, `PromiseYieldReceipt`, `PromiseYieldStatus`, `YieldIdToDataId`, or `DataIdToYieldId` rows keyed by the deleted account's `receiver_id`. If any of these rows exist at deletion time, they persist in the trie after the account is gone, and `action_create_account` (`runtime/runtime/src/actions.rs:167-210`) permits recreating an account with the exact same name without checking for or clearing these leftovers.

### Finding Description
An account is deleted via `Action::DeleteAccount`, handled by `action_delete_account` (`runtime/runtime/src/actions.rs:314-391`), which only validates storage-usage size and gas-key burn limits before calling `remove_account(state_update, account_id)` (`core/store/src/utils/mod.rs:505`). That function's full cleanup logic (lines 509-573) is limited to `Account`, `ContractCode`, access keys/gas-key nonces (via prefix iteration), and `ContractData` (via prefix iteration). It performs no prefix scan and no removal for the receipt-lifecycle columns: `PostponedReceiptId`/`PendingDataCount`/`PostponedReceipt` (written by `process_action_receipt`, e.g. `runtime/runtime/src/lib.rs` around the postponed-receipt bookkeeping) or `PromiseYieldReceipt`/`PromiseYieldStatus`/`YieldIdToDataId`/`DataIdToYieldId` (written by `set_promise_yield_receipt`, `set_promise_yield_status`, `set_yield_id_mapping` — see `core/store/src/utils/mod.rs:120-347` and `runtime/runtime/src/ext.rs:353-441`).

If any account still has an outstanding postponed action receipt or promise-yield receipt (i.e., it is waiting on an `input_data_id`/yield resume) at the moment `DeleteAccount` executes, those rows remain in the trie, orphaned but keyed only by `receiver_id` + `receipt_id`/`data_id` — not by any account "generation" or existence check. `action_create_account` (`actions.rs:167-210`) lets anyone recreate a named account with the identical `account_id` afterward (subject to normal parent/registrar authorization), with a brand-new zero-balance `Account` object, but with no awareness of these stale rows.

Later, when the original triggering data/resume receipt for the stale `PostponedReceiptId`/`PromiseResume` arrives (`runtime/runtime/src/lib.rs:1415-1455` for the postponed path, `:1500-1563` for the promise-yield-resume path), the runtime resolves it purely by `account_id` + `receipt_id`/`data_id`, fetches the previously-stored `Receipt` via `get_postponed_receipt`/`get_promise_yield_receipt`, and executes its actions against whatever `Account` currently exists at that `account_id` — i.e., the newly recreated (and possibly funded) account — via `apply_action_receipt`. The actions embedded in that stale receipt were authored before deletion by the *original* predecessor and were never re-validated against the new account's owner/keys.

Existing checks that fail to prevent this:
- `action_delete_account` only checks `MAX_ACCOUNT_DELETION_STORAGE_USAGE` and gas-key balance, not outstanding postponed/yield state.
- `action_create_account`'s `check_account_existence`/`check_actor_permissions` (`actions.rs:787-855`, `739-785`) only check for `AccountAlreadyExists` on the *current* `Account` row, not for leftover receipt-lifecycle keys.
- The resolution paths in `lib.rs` (`process_receipt`, `apply_action_receipt`) have no "this account was deleted and recreated since this receipt was postponed" guard.

### Impact Explanation
This is a fund-theft/authorization-escalation primitive: an attacker can pre-stage a postponed action receipt (with arbitrary actions, e.g. `Transfer`/`FunctionCall`) targeting their own account while it still has an unresolved input-data dependency, delete that account (refunding themselves via `beneficiary_id`), wait for someone else to legitimately recreate and fund an account with the same name, then trigger delivery of the corresponding `Data`/`PromiseResume` receipt to force execution of the pre-staged actions against the new owner's funded account — without the new owner's authorization. This matches the "authorization escalation across accounts/promises" and "theft of user funds" bounty categories. At minimum it is a persistent state-bloat/orphaned-storage bug (rows never charged for and never reclaimed), but the receipt-hijack path is the more severe scoped impact matching this question's numeric-parity framing (`written != cleared` per `TrieKey` column for `receiver_id`).

### Likelihood Explanation
Preconditions are fully attacker-controlled and require no privileged role: create an account, issue a cross-contract call chain so a receipt targeting that account is postponed on an unresolved `input_data_id` (or issue `promise_yield_create`), then call `DeleteAccount` on the same account before the dependency resolves. The only extra requirement is that a third party (or the attacker under a different signer) later recreates an account with the identical name — feasible for any non-top-level name the attacker controls as parent, or for names that become available again. This is fully repeatable and costs only ordinary gas/storage fees.

### Recommendation
`remove_account` must, before or in addition to removing `Account`/`ContractCode`/`AccessKey`/`ContractData`, also prefix-scan and remove all rows for `ReceivedData`, `PostponedReceiptId`, `PendingDataCount`, `PostponedReceipt`, `PromiseYieldReceipt`, `PromiseYieldStatus`, `YieldIdToDataId`, and `DataIdToYieldId` keyed by the account being deleted, using `trie_key_parsers` prefix helpers analogous to `get_raw_prefix_for_access_keys`/`get_raw_prefix_for_contract_data`. Alternatively/additionally, `action_delete_account` should reject deletion (return an `ActionError`) if the account has any outstanding postponed or promise-yield receipts, mirroring the existing `DeleteAccountStaking`/`DeleteAccountWithLargeState` guard pattern.

/// Removes account, code and all access keys and gas keys associated to it.
pub fn remove_account(
    state_update: &mut TrieUpdate,
    account_id: &AccountId,
) -> Result<RemoveAccountResult, StorageError> {
    state_update.remove(TrieKey::Account { account_id: account_id.clone() });
    state_update.remove(TrieKey::ContractCode { account_id: account_id.clone() });

    let mut gas_key_nonce_count: usize = 0;
    let mut gas_key_nonce_total_key_bytes: usize = 0;

    // Removing access keys and gas key nonces
    let lock = state_update.trie().lock_for_iter();
    let mut keys_to_remove: Vec<TrieKey> = Vec::new();
    for raw_key in state_update
        .locked_iter(&trie_key_parsers::get_raw_prefix_for_access_keys(account_id), &lock)?
    {
        let raw_key = raw_key?;
        let key_handle = trie_key_parsers::parse_key_handle_from_access_key_key(
            &raw_key, account_id,
        )
        .map_err(|_e| {
            StorageError::StorageInconsistentState(
                "Can't parse key handle from raw key for AccessKey".to_string(),
            )
        })?;
        let nonce_index =
            trie_key_parsers::parse_nonce_index_from_gas_key_key(&raw_key, account_id, &key_handle)
                .map_err(|_e| {
                    StorageError::StorageInconsistentState(
                        "Can't parse nonce index from raw key for AccessKey".to_string(),
                    )
                })?;
        if let Some(index) = nonce_index {
            gas_key_nonce_count += 1;
            gas_key_nonce_total_key_bytes += raw_key.len();
            keys_to_remove.push(TrieKey::gas_key_nonce(
                account_id.clone(),
                key_handle.clone(),
                index,
            ));
        } else {
            keys_to_remove.push(TrieKey::access_key(account_id.clone(), key_handle.clone()));
        }
    }
    drop(lock);

    for trie_key in keys_to_remove {
        state_update.remove(trie_key);
    }

    // Removing contract data
    let lock = state_update.trie().lock_for_iter();
    let data_keys = state_update
        .locked_iter(&trie_key_parsers::get_raw_prefix_for_contract_data(account_id, &[]), &lock)?
        .map(|raw_key| {
            trie_key_parsers::parse_data_key_from_contract_data_key(&raw_key?, account_id)
                .map_err(|_e| {
                    StorageError::StorageInconsistentState(
                        "Can't parse data key from raw key for ContractData".to_string(),
                    )
                })
                .map(Vec::from)
        })
        .collect::<Result<Vec<_>, _>>()?;
    drop(lock);

    for key in data_keys {
        state_update.remove(TrieKey::ContractData { account_id: account_id.clone(), key });
    }
    Ok(RemoveAccountResult { gas_key_nonce_count, gas_key_nonce_total_key_bytes })
}

pub(crate) fn action_delete_account(
    state_update: &mut TrieUpdate,
    account: &mut Option<Account>,
    actor_id: &mut AccountId,
    receipt: &Receipt,
    result: &mut ActionResult,
    account_id: &AccountId,
    delete_account: &DeleteAccountAction,
    config: &RuntimeConfig,
    current_protocol_version: ProtocolVersion,
) -> Result<(), StorageError> {
    let account_ref = account.as_ref().unwrap();
    let account_storage_usage = if ProtocolFeature::FixDeleteAccountGlobalContractStorageUsage
        .enabled(current_protocol_version)
    {
        let contract_storage = get_contract_storage_usage(state_update, account_id, account_ref)?;
        account_ref.storage_usage().saturating_sub(contract_storage)
    } else {
        // Legacy behavior: only subtracts local contract code, misses the
        // global contract identifier overhead.
        let account_storage_usage = account_ref.storage_usage();
        let code_len = get_code_len_or_default(
            state_update,
            account_id.clone(),
            account_ref.local_contract_hash().unwrap_or_default(),
        )?;
        debug_assert!(
            code_len == 0 || account_storage_usage > code_len,
            "account storage usage should be larger than code size. storage usage: {}, code size: {}",
            account_storage_usage,
            code_len
        );
        account_storage_usage.saturating_sub(code_len)
    };
    if account_storage_usage > Account::MAX_ACCOUNT_DELETION_STORAGE_USAGE {
        result.result =
            Err(ActionErrorKind::DeleteAccountWithLargeState { account_id: account_id.clone() }
                .into());
        return Ok(());
    }
    let gas_key_balance_to_burn = compute_gas_key_balance_sum(state_update, account_id)?;
    if gas_key_balance_to_burn > GasKeyInfo::MAX_BALANCE_TO_BURN {
        result.result = Err(ActionErrorKind::GasKeyBalanceTooHigh {
            account_id: account_id.clone(),
            public_key: None,
            balance: gas_key_balance_to_burn,
        }
        .into());
        return Ok(());
    }
    // We use current amount as a pay out to beneficiary.
    let account_balance = account_ref.amount();
    if account_balance > Balance::ZERO {
        result
            .new_receipts
            .push(Receipt::new_balance_refund(&delete_account.beneficiary_id, account_balance));
    }
    let remove_result = remove_account(state_update, account_id)?;
    result.tokens_burnt =
        result.tokens_burnt.checked_add(gas_key_balance_to_burn).ok_or_else(|| {
            StorageError::StorageInconsistentState("tokens_burnt overflow".to_string())
        })?;
    if remove_result.gas_key_nonce_count > 0 {
        let compute = storage_removes_compute(
            &config.wasm_config.ext_costs,
            remove_result.gas_key_nonce_count,
            remove_result.gas_key_nonce_total_key_bytes,
            AccessKey::NONCE_VALUE_LEN * remove_result.gas_key_nonce_count,
        );
        result.compute_usage = safe_add_compute(result.compute_usage, compute).map_err(|_| {
            StorageError::StorageInconsistentState("compute_usage overflow".to_string())
        })?;
    }
    *actor_id = receipt.predecessor_id().clone();
    *account = None;
    Ok(())
}
