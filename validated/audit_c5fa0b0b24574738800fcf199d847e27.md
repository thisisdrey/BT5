## Analysis

The reported Solidity bug (`TempleGoldStaking._rewardPerToken`) has a direct structural analog in `pallet-asset-rewards`, which implements the same "reward-per-token accumulator" pattern (`reward_per_token_stored`, `last_update_block`, `reward_rate_per_block`). [1](#0-0) 

### Title
Reward accrual timestamp advances even when a pool has zero stakers, permanently forfeiting rewards accrued during that window - (File: `substrate/frame/asset-rewards/src/lib.rs`)

### Summary
`reward_per_token()` special-cases `total_tokens_staked == 0` by returning the stored (unchanged) `reward_per_token_stored` value, exactly like TempleGoldStaking's `_rewardPerToken` returning `rewardData.rewardPerTokenStored` when `totalSupply == 0`. However `update_pool_rewards()`, which is called on every stake/unstake/harvest/rate-change, unconditionally advances `last_update_block` to the current block regardless of whether `total_tokens_staked` was zero during the elapsed period: [2](#0-1) 

### Finding Description
`create_pool` initializes a pool with `total_tokens_staked: 0`, `reward_per_token_stored: 0`, `last_update_block: 0` and a `reward_rate_per_block > 0` and an `expiry_block`, while reward tokens accumulate to be claimable proportional to `reward_rate_per_block * blocks_elapsed`. Reward tokens can be pre-funded into the pool's pot account (either via `deposit_reward_tokens` or a direct transfer) at any time, including before any staker joins: [3](#0-2) 

If no staker calls `stake()` for `N` blocks after pool creation (or after the pool empties out to zero stakers and later regains a staker), `total_tokens_staked` is `0` throughout that window, so `reward_per_token()` correctly returns the stored value unchanged (no one over-earns). But when the first (or next) staker finally calls `stake()`, `update_pool_and_staker_rewards` → `update_pool_rewards` is invoked, and it unconditionally sets `last_update_block = current_block`: [4](#0-3) 

This silently "fast-forwards" the pool's clock past the entire zero-staker window. The `reward_rate_per_block * N` blocks worth of rewards that logically should have been withheld/returned to the admin are never credited to `reward_per_token_stored`, yet the reward tokens already sitting in the pool's pot account remain there. They can only ever be recovered via `cleanup_pool`, which requires the pool to have **zero** `PoolStakers` at cleanup time: [5](#0-4) 

As long as the pool retains at least one staker going forward (a very common, permissionless outcome once staking starts), that "skipped" reward-window's worth of tokens can never be claimed by any staker nor reclaimed by the admin — they are permanently stranded in the pool's pot account.

### Impact Explanation
This is a permanent-fund-lock in a runtime pallet reachable purely through the public, unprivileged `stake`/`deposit_reward_tokens`/`create_pool` extrinsics — no admin/governance/relayer misbehavior is required. Reward assets held in the pool's pot become unclaimable and unrecoverable dust that grows every time this "gap" occurs (pool creation-to-first-stake, or a pool going to zero stakers and someone re-staking later), matching the "permanent user-fund lock" impact category.

### Likelihood Explanation
Likelihood is moderate-to-high: any pool creator/admin routinely funds a pool via `deposit_reward_tokens` at or shortly after `create_pool`, and there is no guarantee the first `stake()` call happens in the very same block. Any delay — even a single block, and certainly any longer gap while the pool sits with zero stakers — reproduces the loss. This requires no adversarial coordination, just normal, permissionless usage.

### Recommendation
In `reward_per_token`, when `total_tokens_staked.is_zero()`, `update_pool_rewards` should not silently move `last_update_block` forward to "consume" reward-rate time that nobody earned. Either:
- Skip advancing `last_update_block` when `total_tokens_staked` is zero (so unearned block-rewards remain "pending" and are correctly attributed once staking resumes), or
- Track/refund the un-emitted `reward_rate_per_block * elapsed_blocks_at_zero_stake` back to the admin (mirroring the recommended TempleDAO fix of validating funds/stakers before allowing accrual), or
- Allow `cleanup_pool`-style recovery of stranded reward-window dust even when stakers exist, gated to the admin.

### Proof of Concept
1. Admin calls `create_pool` at block `1` with `reward_rate_per_block = 100` and `expiry_block = 1000`.
2. Admin calls `deposit_reward_tokens` to fund the pool's pot with `100_000` reward tokens.
3. No one stakes until block `101` (100 blocks pass with `total_tokens_staked == 0`).
4. Staker `A` calls `stake(pool_id, 100)` at block `101`. Internally: `reward_per_token()` returns `reward_per_token_stored = 0` (unchanged, correct so far), but `update_pool_rewards` sets `last_update_block = 101`, discarding the fact that blocks `1..101` produced no reward record.
5. From this point, rewards only start accruing to `A` from block `101` onward. The `100 * 100 = 10_000` reward tokens' worth of "block-rate" time between block `1` and `101` is never credited to `reward_per_token_stored` and never claimable by any staker.
6. As long as pool `pool_id` never returns to zero `PoolStakers` (e.g., `A` never fully unstakes, or new stakers keep joining), `cleanup_pool` can never be called, and that portion of the pre-funded reward tokens remains permanently stuck in `pool_info.account`.

		pub fn stake(origin: OriginFor<T>, pool_id: PoolId, amount: T::Balance) -> DispatchResult {
			let staker = ensure_signed(origin)?;

			// Always start by updating staker and pool rewards.
			let pool_info = Pools::<T>::get(pool_id).ok_or(Error::<T>::NonExistentPool)?;
			let staker_info = PoolStakers::<T>::get(pool_id, &staker).unwrap_or_default();
			let (mut pool_info, mut staker_info) =
				Self::update_pool_and_staker_rewards(&pool_info, &staker_info)?;

			T::AssetsFreezer::increase_frozen(
				pool_info.staked_asset_id.clone(),
				&FreezeReason::Staked.into(),
				&staker,
				amount,
			)?;

			// Update Pools.
			pool_info.total_tokens_staked.ensure_add_assign(amount)?;

			Pools::<T>::insert(pool_id, pool_info);

			// Update PoolStakers.
			staker_info.amount.ensure_add_assign(amount)?;
			PoolStakers::<T>::insert(pool_id, &staker, staker_info);

			// Emit event.
			Self::deposit_event(Event::Staked { staker, pool_id, amount });

			Ok(())
		}

		#[pallet::call_index(8)]
		pub fn cleanup_pool(origin: OriginFor<T>, pool_id: PoolId) -> DispatchResult {
			let who = ensure_signed(origin)?;

			let pool_info = Pools::<T>::get(pool_id).ok_or(Error::<T>::NonExistentPool)?;
			ensure!(pool_info.admin == who, BadOrigin);

			let stakers = PoolStakers::<T>::iter_key_prefix(pool_id).next();
			ensure!(stakers.is_none(), Error::<T>::NonEmptyPool);

			let pool_balance = T::Assets::reducible_balance(
				pool_info.reward_asset_id.clone(),
				&pool_info.account,
				Preservation::Expendable,
				Fortitude::Polite,
			);
			T::Assets::transfer(
				pool_info.reward_asset_id,
				&pool_info.account,
				&pool_info.admin,
				pool_balance,
				Preservation::Expendable,
			)?;

			if let Some((who, cost)) = PoolCost::<T>::take(pool_id) {
				T::Consideration::drop(cost, &who)?;
			}

			Pools::<T>::remove(pool_id);

			Self::deposit_event(Event::PoolCleanedUp { pool_id });

			Ok(())
		}

		/// Derives the current reward per token for this pool.
		pub(super) fn reward_per_token(
			pool_info: &PoolInfoFor<T>,
		) -> Result<T::Balance, DispatchError> {
			if pool_info.total_tokens_staked.is_zero() {
				return Ok(pool_info.reward_per_token_stored);
			}

			let rewardable_blocks_elapsed: u32 =
				match Self::last_block_reward_applicable(pool_info.expiry_block)
					.ensure_sub(pool_info.last_update_block)?
					.try_into()
				{
					Ok(b) => b,
					Err(_) => return Err(Error::<T>::BlockNumberConversionError.into()),
				};

			Ok(pool_info.reward_per_token_stored.ensure_add(
				pool_info
					.reward_rate_per_block
					.ensure_mul(rewardable_blocks_elapsed.into())?
					.ensure_mul(PRECISION_SCALING_FACTOR.into())?
					.ensure_div(pool_info.total_tokens_staked)?,
			)?)
		}
