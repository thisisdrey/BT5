### Title
Protocol fees on `Nep245`/`Imt` tokens can be bypassed by decomposing a large trade into many `amount == 1` `TokenDiff` intents - (File: contracts/defuse/core/src/intents/token_diff.rs)

### Summary
`TokenDiff::token_fee` exempts `Nep245`/`Imt` token deltas from fees only when the **per-intent** `amount` is `<= 1`, but this check is evaluated independently for every `TokenDiff` intent in a batch rather than on the aggregate economic value being traded. An attacker can split a large fungible-style `Nep245`/`Imt` trade into many `TokenDiff` intents, each with `delta == -1` on the same `token_id`, and collect zero protocol fee on the whole trade, whereas a single `TokenDiff` with the full amount would be fee-liable.

### Finding Description
The broken binding: for a given `token_id` and total traded `amount = A`, the intended fee should equal `protocol_fee.fee_ceil(A)` whenever `A > 1` for a fungible-behaving `Nep245`/`Imt` sub-token. Instead, the code computes the fee per-diff on the **local** `amount` of that single intent: [1](#0-0) 

and `execute_intent` invokes `token_fee` separately for every intent processed, using only that intent's own `delta`: [2](#0-1) 

Nowhere is the amount aggregated across the multiple `TokenDiff` intents that can be included in a single `MultiPayload`/execution batch before the `amount > 1` guard is evaluated. `TransferMatcher` (in `deltas.rs`) only nets deposits/withdrawals across the whole batch to compute final transfers and enforce the zero-sum invariant; it performs no fee aggregation or re-derivation: [3](#0-2) 

So an attacker (as the trade's `token_in` party) can submit `N` `TokenDiff` intents, each moving exactly `1` unit of the same valuable `Nep245`/`Imt` sub-token (`delta = -1`), matched in aggregate by a genuine counterparty's deltas so the batch still nets to zero. Each individual intent hits the `TokenIdType::Nep245 | TokenIdType::Imt if amount > 1 => {}` guard as false (since `amount == 1`), falls through to `return Pips::ZERO`, and the resulting `fees_collected` for that intent is `0`. Summed over the whole batch, the attacker pays `0` total fee on a trade of aggregate size `N`, versus `protocol_fee.fee_ceil(N)` had they submitted one `TokenDiff` with `delta = -N`.

None of the existing guards (`MultiPayload::verify`, nonce/salt checks, `TransferMatcher::finalize`'s zero-sum invariant) address this because they only validate signature/replay/balance-conservation properties, not fee correctness across multiple intents. The `amount > 1` check was intended as a "no fee on dust/single-unit NFT-like transfers" carve-out (mirroring `Nep171`'s always-zero fee), but because `Nep245`/`Imt` sub-tokens can represent large-value fungible balances, the same exemption is exploitable by structuring.

### Impact Explanation
The protocol's fee revenue is under-collected: the `fee_collector` account receives less than the fee schedule intends for the true economic size of the trade. This matches the explicitly listed Critical category "protocol fees bypassed or over-collected." No unauthorized balance movement or invariant violation occurs — the attacker's own funds and the counterparty's own funds move exactly as both parties authorized — but the DAO/protocol loses fee revenue on any `Nep245`/`Imt` fungible-style token trade, repeatable indefinitely by any account holding such balances, with no cap on the aggregate amount that can be moved fee-free (only bounded by how many `TokenDiff` intents can be encoded/executed in a payload/batch).

### Likelihood Explanation
Preconditions: the attacker only needs to hold a balance of a `Nep245`/`Imt` sub-token and find/collude with a counterparty willing to take the other side of the trade (which can be arranged since the attacker fully controls both signed intents in a self-consistent test, or coordinates with any counterparty in production). No privileged role, relayer key, or victim key is needed — this is purely a self-authorized structuring of the attacker's own intents. The only cost is the linear increase in number of intents (and therefore transaction/gas size) needed to decompose the trade into unit chunks, which is a usability/gas cost, not a blocker (gas/DoS concerns are explicitly out of scope for rejecting this finding's fee-bypass core issue). This is fully repeatable across accounts, tokens, and batches.

### Recommendation
Compute and validate the `Nep245`/`Imt` fee exemption against the aggregate traded amount per `token_id`, not the per-intent delta alone — e.g., accumulate amounts per `token_id` across the whole batch/execution context before applying the `amount > 1` threshold, or remove the dust exemption for `Nep245`/`Imt` entirely and instead exempt only intents whose token_id is provably non-fungible (e.g., encode NFT-like semantics explicitly rather than inferring it from `amount == 1`).

### Proof of Concept
Add a test in `contracts/defuse/core/src/intents/token_diff.rs` (or a `near-workspaces` sandbox test) that:
1. Creates two accounts, Alice (attacker, holds `N` units of a `Nep245` sub-token `mt.near:ft1`) and Bob (counterparty, holds `N` units of `ft.near` NEP-141).
2. Submits a **single** `TokenDiff` intent: Alice `{mt.near:ft1: -N, ft.near: +N}` and asserts `fees_collected` for `mt.near:ft1` equals `protocol_fee.fee_ceil(N) > 0` (baseline, non-exploited case).
3. Submits `N` separate `TokenDiff` intents, each: Alice `{mt.near:ft1: -1, ft.near: +1}`, matched against Bob's corresponding `{ft.near: -1, mt.near:ft1: +1}` diffs in the same batch/payload, and runs them through `Engine::execute` / `TransferMatcher::finalize`.
4. Assert that in step 3 the total `fees_collected` on `mt.near:ft1` summed across all `N` intents equals `0`, while the net transfer of `mt.near:ft1` from Alice to Bob is `N` — the same aggregate economic transfer as step 2 but with fee `0 < protocol_fee.fee_ceil(N)`, proving fee under-collection via structuring.

        let token_id = token_id.into();
        match token_id {

    // Finalizes all transfers, or returns unmatched deltas.
    // If unmatched deltas overflow, then Err(None) is returned.
    pub fn finalize(self) -> Result<Transfers, InvariantViolated> {
        let mut transfers = Transfers::default();
        let mut deltas = TokenDeltas::default();
        for (token_id, transfer_matcher) in self.0 {
            if let Err(unmatched) = transfer_matcher.finalize_into(&token_id, &mut transfers)
                && (unmatched == 0 || deltas.apply_delta(token_id, unmatched).is_none())
            {
                return Err(InvariantViolated::Overflow);
            }
        }
        if !deltas.is_empty() {
            return Err(InvariantViolated::UnmatchedDeltas {
                unmatched_deltas: deltas,
            });
        }
        Ok(transfers)
    }
