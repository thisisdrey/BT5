### Title
Debt interest is accrued before the rewards snapshot, so `RewardsDistributor` computes `tokensDelta` on the post-interest debt balance for the whole elapsed period - (File: contracts/DebtToken.sol)

### Summary
`DebtToken.accrueInterest()` grows `debtIndex`/`totalSupply_` before `updateRewardsBeforeMintOrBurn` runs inside `_mint()`/`_burn()`. `_updateTokensAccruedOf()` then multiplies the user's **interest-grown** `balanceOf` by the index delta covering the entire elapsed reward window, over-crediting borrow rewards for every `issue`, `mint`, `repay`, `repayAll`, and `burn` that follows an idle period.

### Finding Description
In `RewardsDistributor`, an account's reward delta is computed as `token_.balanceOf(account_).wadMul(deltaIndex)`, where `deltaIndex` covers `[tokenState.timestamp, block.timestamp]`. The invariant is that `balanceOf` is sampled at its pre-transition value, so rewards are credited only for balances actually held during the window.

In `DebtToken.issue()` (and `mint()`, `repay()`, `repayAll()`), `accrueInterest()` runs first and writes `lastTimestampAccrued = block.timestamp` plus the grown `debtIndex`. Only afterward does the `updateRewardsBeforeMintOrBurn` modifier inside `_mint()`/`_burn()` call `IRewardsDistributor.updateBeforeMintOrBurn`, which calls `_updateTokensAccruedOf`. At that point `balanceOf(account_)` returns `principal * newDebtIndex / oldDebtIndexOf` — i.e., the principal plus all interest just accrued for `[lastTimestampAccrued_old, now]`. The elapsed reward index delta therefore credits rewards on interest that did not exist during the accrual window.

This mirrors the reported pattern exactly: the time-dependent state (`debtIndex`/`lastTimestampAccrued`, analogous to `stakeBegin`) is updated before the reward computation reads balance state, so the reward uses a mutated divisor/base.

```solidity
// contracts/DebtToken.sol — repay() ordering
accrueInterest();                       // lastTimestampAccrued & debtIndex updated first
...
_burn(onBehalfOf_, _repaid);            // updateRewardsBeforeMintOrBurn reads grown balanceOf
```

### Impact Explanation
An attacker with an open debt position can let interest accumulate, then trigger `repay()`/`issue()` (or have SmartFarmingManager call `mint`/`flashIssue` flows) so their reward delta is computed on the inflated balance. Since token emission is a fixed `speed * deltaTime` pool distributed pro-rata via the index, each over-credited unit dilutes every other supplier's/borrower's `tokensAccruedOf`. This is theft of unclaimed yield from other users, repeatable on every interaction after idle periods; magnitude scales with `interestRate * idleTime * deltaIndex`.

### Likelihood Explanation
Reachable by any unprivileged user through the public `DebtToken.issue`, `repay`, `repayAll` (and via `SmartFarmingManager` for `mint`/`flashIssue`). No governor action, oracle manipulation, or privileged actor is required — only an existing debt position and elapsed time. The effect is small per call (bounded by accrued interest times the index delta), but it is systematic: every user interacting after an idle period is over-credited.

### Recommendation
Run the rewards snapshot before mutating the debt index. In `issue`, `mint`, `repay`, `repayAll`, and `burn`, invoke `RewardsDistributor.updateBeforeMintOrBurn` (or an equivalent `updateBeforeAccrual`) **before** `accrueInterest()`, so `_updateTokensAccruedOf` samples `balanceOf` at the pre-accrual index. Alternatively, have `_calculateTokenDelta` use the pre-accrual principal (`principalOf`) rather than the interest-inclusive `balanceOf`.

### Proof of Concept
```solidity
// Foundry — assumption: pool with a RewardsDistributor on a DebtToken, speed > 0
function testOverAccrualOnGrownBalance() public {
    // alice issues debt at t0; index updates with balance B
    debtToken.issue(amount, alice);

    // idle for T seconds — debtIndex grows by rate*T; reward index delta accumulates
    vm.warp(block.timestamp + 365 days);

    uint256 accruedBefore = rewardsDistributor.claimable(alice);

    // alice repays a dust amount; accrueInterest() runs BEFORE rewards snapshot
    uint256 grown = debtToken.balanceOf(alice);       // B * (1 + r*T)
    uint256 oldPrincipal = debtToken.principalOfView(alice); // B (pre-accrual view)

    debtToken.repay(alice, 1);

    uint256 deltaIndex = /* read tokenStates - accountIndex */;
    uint256 credited   = rewardsDistributor.tokensAccruedOf(alice) - accruedBefore;

    // credited == grown * deltaIndex  (uses post-interest balance)
    // correct   == oldPrincipal * deltaIndex
    assertGt(credited, oldPrincipal * deltaIndex / 1e18); // over-credit == r*T*B*deltaIndex
}
```
In a Hardhat equivalent, mock/real `DebtToken` with nonzero `interestRate`, fast-forward time, call `repay`, and compare `tokensAccruedOf` against `principal * deltaIndex` — the stored accrual exceeds the fair share by the accrued interest times the index delta.
