### No vulnerability found for this question.

The check in `verify_intent_nonce` is exactly the intended and correctly-implemented boundary: `if intent_deadline > deadline { return Err(DeadlineGreaterThanNonce) }` enforces `intent_deadline <= nonce.deadline`, matching the documented invariant that "the deadline for nonce may be greater than the deadline for intent" [1](#0-0) [2](#0-1) . This is not an off-by-one bug: the `>` operator correctly *allows* `intent_deadline == deadline` (equal is fine, since the invariant only forbids the intent deadline from exceeding the nonce deadline), and rejects only when it is strictly greater.

More importantly, the "double settlement" concern in the question is orthogonal to this comparison. Regardless of how the two deadlines relate, a nonce can only ever be committed once — `commit_nonce` is called unconditionally right after `verify_intent_nonce` succeeds and enforces one-time use via the underlying bitmap/nonce-tracking state [3](#0-2) . There is no code path where the same nonce bytes can be committed twice; the `deadline > nonce.deadline` check only gates whether a *given* signed payload is accepted at all, not whether the nonce can be reused. The existing test suite explicitly exercises this exact boundary (`"deadline is greater than nonce"` error using `Timestamp::MAX` vs. a nearer nonce deadline, and successful commit when `intent_deadline == nonce.deadline`) [4](#0-3) , confirming the boundary behaves as specified with a single, one-time settlement.

The separate `is_nonce_cleanable` check used by the garbage collector operates on a completely different concern (whether a *committed* nonce's underlying bitmap slot can be reclaimed for storage), not on settlement authorization, and does not interact with `verify_intent_nonce`'s comparison in any way that could enable double-processing [5](#0-4) .

    fn verify_intent_nonce(&self, nonce: Nonce, intent_deadline: Timestamp) -> Result<()> {
        let Some(nonce) = VersionedNonce::maybe_from(nonce) else {
            return Ok(());
        };

        match nonce {
            VersionedNonce::V1(SaltedNonce {
                salt,
                nonce: ExpirableNonce { deadline, .. },
            }) => {
                if !self.state.is_valid_salt(salt) {
                    return Err(DefuseError::InvalidSalt);
                }

                if intent_deadline > deadline {
                    return Err(DefuseError::DeadlineGreaterThanNonce);
                }

                if deadline < Timestamp::now() {
                    return Err(DefuseError::NonceExpired);
                }
            }
