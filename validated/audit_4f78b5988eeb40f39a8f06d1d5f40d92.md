### Title
Per-IP QUIC connection rate limiter can be bypassed via incomplete handshakes, allowing single-IP starvation of accept-loop capacity - (File: streamer/src/nonblocking/quic.rs)

### Summary
`ConnectionRateLimiter::is_allowed` and the global `overall_connection_rate_limiter.current_tokens() == 0` check in `run_server` are both non-mutating "peeks", while the actual token consumption (`register_connection` and `overall_connection_rate_limiter.consume_tokens`) happens only in `setup_connection` after the QUIC handshake successfully completes. An attacker who initiates a handshake but never lets it complete (aborts before `Connecting` resolves `Ok`) is never charged against either the per-IP or the global connection-rate token buckets, letting them occupy accept-loop/handshake slots up to the shared `max_concurrent_connections()` budget indefinitely.

### Finding Description
In `streamer/src/nonblocking/quic.rs::run_server` [1](#0-0) , the per-connection admission path is:
1. `overall_connection_rate_limiter.current_tokens() == 0` — a read-only peek, not a consume, so it does not reduce available tokens.
2. `rate_limiter.is_allowed(&ip)` — also documented as read-only in `ConnectionRateLimiter::is_allowed`: "we should only modify server state once source IP is verified" [2](#0-1) . If the IP has no bucket yet (`None`), it returns `true` unconditionally, and it never mutates the underlying `KeyedRateLimiter`.
3. `ClientConnectionTracker::new(..., qos.max_concurrent_connections())` — increments a **global** (not per-IP) `open_connections` counter bounded by `max_concurrent_connections()`, which for `SwQos`/`SimpleQos` is `(max_staked_connections + max_unstaked_connections) * 5/4` (default ≈ 5000) [3](#0-2) [4](#0-3) .
4. Only after `incoming.accept()` succeeds does `setup_connection` await the handshake with a bounded `tokio::time::timeout(QUIC_CONNECTION_HANDSHAKE_TIMEOUT, connecting)` where `QUIC_CONNECTION_HANDSHAKE_TIMEOUT = 2s` [5](#0-4) . **Only on `Ok(new_connection)`** does it call `rate_limiter.register_connection(&from.ip())` (which actually consumes a token) and `overall_connection_rate_limiter.consume_tokens(1)` [6](#0-5) .

Consequently, any connection attempt that never resolves to `Ok` (attacker sends the QUIC Initial then stops responding, or resets the connection before the handshake finishes, or the handshake times out) never touches either rate limiter's token state. Per-IP token consumption defined by `DEFAULT_MAX_CONNECTIONS_PER_IPADDR_PER_MINUTE = 8` (default) is thus never triggered for such attempts [7](#0-6) , and `is_allowed` keeps returning `true` for that IP forever since no bucket record was ever created (`current_tokens(ip) == None → true`).

The only real backstop is the shared `open_connections` cap enforced by `ClientConnectionTracker::new`, which is a global resource (staked + unstaked pool), not per-IP. A single attacking IP can therefore hold up to `max_concurrent_connections()` in-flight, never-completing handshakes (each bounded to 2s by the timeout, but continuously replaced with new attempts), starving that global slot pool and causing legitimate staked/unstaked peers to be rejected via `incoming.refuse()` and `stats.refused_connections_too_many_open_connections` [8](#0-7)  — even though the per-IP limiter was supposed to cap this attacker to 8 connections/minute.

### Impact Explanation
This is a QoS-evasion / unstaked-vs-legitimate-sender starvation issue: the per-IP connection rate limiter (`ConnectionRateLimiter`) can be trivially evaded by an unprivileged, unstaked remote client simply by never completing the QUIC handshake, letting a single source IP consume the shared handshake/`open_connections` budget (default ~5000 slots) that is meant to be shared fairly across all staked and unstaked peers. This matches the "unstaked QoS bypass/starvation" scope of the question and constitutes a legitimate DoS/QoS-evasion finding against the TPU QUIC ingress path in `streamer/src/nonblocking/quic.rs`.

### Likelihood Explanation
Fully feasible with a single unprivileged host: no stake, no gossip/peer control, and no more than normal UDP send capability from one IP are required. The attacker only needs to open a QUIC `Connecting` (send an Initial packet or a few handshake bytes) and then abandon it before the handshake completes; each attempt costs the attacker one send and ties up a server-side slot for up to `QUIC_CONNECTION_HANDSHAKE_TIMEOUT` (2s), which they can pipeline with many concurrent attempts (bounded only by the client's own socket/CPU) to keep the global slot pool saturated. This is straightforward to reproduce deterministically in a unit/integration test.

### Recommendation
Consume (or reserve) a per-IP token at admission time (before `incoming.accept()`), not only after a successful handshake, e.g. call a non-revocable "reserve" that decrements tokens at admission and only refunds them if the connection is later rejected for unrelated reasons (never on legitimate churn). Alternatively, track per-IP outstanding (in-flight, not-yet-handshaked) connection attempts separately from the global `open_connections` counter and cap them per-IP as well, so a single IP cannot exhaust the shared handshake budget by abandoning handshakes.

### Proof of Concept
Integration test plan against `setup_quic_server` (as used in `streamer/src/nonblocking/testing_utilities`):
```rust
#[tokio::test]
async fn test_incomplete_handshake_bypasses_per_ip_limiter() {
    let SpawnTestServerResult { server_address, stats, cancel, .. } = setup_quic_server(
        None,
        QuicStreamerConfig {
            max_connections_per_ipaddr_per_min: 8, // default
            ..QuicStreamerConfig::default_for_tests()
        },
        SwQosConfig::default(),
    );

    // Open and immediately drop many "connections" from the same source IP,
    // aborting before the handshake completes (e.g. by dropping the client
    // endpoint right after connect() is issued, before awaiting the Connecting future).
    for _ in 0..200 {
        let endpoint = make_client_endpoint(&server_address, None); // do not await connection
        drop(endpoint); // abort before handshake completes
    }

    tokio::time::sleep(Duration::from_secs(3)).await; // allow QUIC_CONNECTION_HANDSHAKE_TIMEOUT to elapse

    // Expected (if limiter worked correctly): only ~8 attempts should have been
    // admitted to accept()/handshake stage; connection_rate_limited_per_ipaddr
    // should reflect the remaining ~192 as rate-limited.
    assert!(
        stats.connection_rate_limited_per_ipaddr.load(Ordering::Relaxed) < 8,
        "per-IP limiter did not trigger despite 200 attempts from one IP: {}",
        stats.connection_rate_limited_per_ipaddr.load(Ordering::Relaxed)
    );
    // Actual (vulnerable) behavior: total_incoming_connection_attempts ~= 200,
    // outstanding_incoming_connection_attempts / open_connections briefly reflect
    // near-full occupancy, and connection_rate_limited_per_ipaddr stays near 0
    // because register_connection() was never invoked for any of the aborted attempts.
    cancel.cancel();
}
```
Expected failing assertion demonstrates that `connection_rate_limited_per_ipaddr` does not increment proportionally to actual attempts from the single IP, confirming the per-IP token bucket is never consumed for aborted handshakes.

    /// Check if the connection from the said `ip` is allowed.
    /// Here we assume that only IPs with actual confirmed connections are stored in it,
    /// since we should only modify server state once source IP is verified
    pub fn is_allowed(&self, ip: &IpAddr) -> bool {
        // Check if we have records in the rate limiter for the given IP address
        match self.limiter.current_tokens(ip) {
            Some(r) => r > 0, // we have a record, and rate is not exceeded
            None => true,     // if we have not seen IP, allow connection request
        }
    }
