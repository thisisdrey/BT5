### Title
Witness rewards accrued while its live vote count is zero are permanently lost in `DelegationStore.accumulateWitnessVi` / `MaintenanceManager.doMaintenance` - (File: `chainbase/src/main/java/org/tron/core/store/DelegationStore.java`, `consensus/src/main/java/org/tron/consensus/dpos/MaintenanceManager.java`)

### Summary
The DPoS reward-per-vote (`Vi`) accumulator only folds a witness's cycle reward into the claimable index when the witness's *live* vote count, read at maintenance time, is non-zero. Block/transaction-fee rewards are however accrued for the whole cycle independently of that live snapshot. If all voters unvote a witness within the same cycle after it has already earned rewards, the accrued reward is silently dropped instead of being carried forward, exactly the "rewards for the initial/uncounted period are lost" bug class described in the BathBuddy report, where a reward stream starts accruing before there is any eligible claimant.

### Finding Description
`MortgageService.payReward` credits a witness's per-cycle reward bucket every time it produces a block or collects transaction fees, independent of anyone's current vote count: [1](#0-0) 

At the end of the same cycle, `MaintenanceManager.doMaintenance()` converts each witness's newly accrued reward into the shared `Vi` accumulator (used by all voters to compute their claimable share) using the witness's *current, live* vote count, not the vote count that was in effect while the reward was being earned: [2](#0-1) 

`DelegationStore.accumulateWitnessVi` implements the actual folding logic. When `voteCount == 0`, the delta is never computed and the previous `Vi` is merely forwarded unchanged — the `reward` value that was already recorded via `addReward` for that cycle is never incorporated into `Vi`: [3](#0-2) 

Because `Vi` is the only mechanism by which `VoteRewardUtil.computeReward` / `MortgageService.computeReward` compute a voter's claimable share (via `endVi.subtract(beginVi)`), a reward that is never folded into `Vi` can never be withdrawn by anyone: [4](#0-3) 

The same drop-on-zero-vote pattern also exists in the pre-new-algorithm path: [5](#0-4) 

This mirrors the BathBuddy defect: a reward stream (`rewardRate`/here, per-cycle witness reward) starts accruing for a period, but if there is no "participant" recorded for that exact accounting checkpoint (BathBuddy: `totalSupply == 0`; java-tron: `voteCount == 0` at maintenance time), the reward for that period is permanently stranded and unclaimable by anyone.

### Impact Explanation
Any TRX that a witness earns for blocks it produces or fees it collects during a cycle in which its vote count reads as zero at the maintenance boundary is permanently and irrecoverably frozen inside the `delegation` store: it is recorded via `addReward` but the `Vi` accumulator (the only path to a claimable balance) never reflects it, and no future cycle re-processes that specific cycle's reward. This is a permanent freezing/loss of protocol-distributed funds, reachable without any privileged role.

### Likelihood Explanation
This is reachable purely through ordinary, unprivileged account actions: voting for a small/low-stake witness (`VoteWitnessContract`) so it becomes momentarily active, letting it produce at least one block or collect fees, and then withdrawing/cancelling the vote (e.g. via `UnfreezeBalanceV2Contract` triggering `updateVote`, or a subsequent `VoteWitnessContract` reducing votes to zero) before the cycle's `doMaintenance()` runs. Any voter, not just an attacker, could trigger this incidentally, and a witness operator/large voter could also do it deliberately to grief co-voters out of shared rewards for that cycle. No SR, committee, or node-operator privilege is required.

### Recommendation
Do not rely on the live vote count read at maintenance time to decide whether to fold a cycle's reward into `Vi`. Instead, use the vote count that was recorded for that cycle at cycle start (the same value used elsewhere as `getWitnessVote(cycle, address)`), and if it is genuinely zero, carry the un-distributable reward forward into the next cycle's reward pool for that witness (analogous to the recommendation in the BathBuddy report to only start/consume the reward stream once a participant exists) instead of discarding it.

### Proof of Concept
1. Voter A votes for witness W with a small stake, making W momentarily active for cycle N.
2. W produces a block / collects a transaction fee in cycle N; `MortgageService.payBlockReward`/`payTransactionFeeReward` → `payReward` → `delegationStore.addReward(N, W, value)` records a positive reward for `(N, W)`.
3. Before `doMaintenance()` executes for cycle N, Voter A fully unvotes/unfreezes, driving W's live `voteCount` to 0.
4. `doMaintenance()` runs: `delegationStore.accumulateWitnessVi(N, W, 0)` takes the "just forward pre vi" branch — the reward added in step 2 is never folded into `Vi(N, W)`.
5. No voter (past, present, or future) can ever claim that reward via `computeReward`, since `Vi` for cycle N never reflects it; the TRX credited in step 2 remains permanently stuck in the `delegation` store.

  private long computeReward(long cycle, List<Pair<byte[], Long>> votes) {
    long reward = 0;
    for (Pair<byte[], Long> vote : votes) {
      byte[] srAddress = vote.getKey();
      long totalReward = delegationStore.getReward(cycle, srAddress);
      if (totalReward <= 0) {
        continue;
      }
      long totalVote = delegationStore.getWitnessVote(cycle, srAddress);
      if (totalVote == DelegationStore.REMARK || totalVote == 0) {
        continue;
      }
      long userVote = vote.getValue();
      double voteRate = (double) userVote / totalVote;
      reward += voteRate * totalReward;
    }
    return reward;
  }

  public void accumulateWitnessVi(long cycle, byte[] address, long voteCount) {
    BigInteger preVi = getWitnessVi(cycle - 1, address);
    long reward = getReward(cycle, address);
    if (reward == 0 || voteCount == 0) { // Just forward pre vi
      if (!BigInteger.ZERO.equals(preVi)) { // Zero vi will not be record
        setWitnessVi(cycle, address, preVi);
      }
    } else { // Accumulate delta vi
      BigInteger deltaVi = BigInteger.valueOf(reward)
          .multiply(DECIMAL_OF_VI_REWARD)
          .divide(BigInteger.valueOf(voteCount));
      setWitnessVi(cycle, address, preVi.add(deltaVi));
    }
  }
