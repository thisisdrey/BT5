### Title
`vesting::distribute` Permanently Blocked by Single Shareholder's Undeliverable APT — (`aptos-move/framework/aptos-framework/sources/vesting.move`)

---

### Summary

`vesting::distribute` iterates over every shareholder in a single unbounded `for_each_ref` loop and calls `aptos_account::deposit_coins` for each one. If any single deposit aborts — because a shareholder's (or beneficiary's) `CoinStore<AptosCoin>` is frozen — the entire transaction reverts. No coins are distributed to any shareholder, and the function remains permanently stuck in that state. The Move prover team explicitly acknowledged this in `vesting.spec.move` with `// TODO: Can't handle abort in loop.` and disabled formal verification of the function.

---

### Finding Description

`vesting::distribute` is a `public entry fun` callable by anyone: [1](#0-0) 

The critical loop:

```move
shareholders.for_each_ref(|shareholder| {
    let shareholder = *shareholder;
    let shares = pool_u64::shares(grant_pool, shareholder);
    let amount = pool_u64::shares_to_amount_with_total_coins(...);
    let share_of_coins = coin::extract(&mut coins, amount);
    let recipient_address = get_beneficiary(vesting_contract, shareholder);
    aptos_account::deposit_coins(recipient_address, share_of_coins);  // ← can abort
});
```

`aptos_account::deposit_coins` has two abort paths: [2](#0-1) 

1. **Frozen `CoinStore`**: `coin::deposit` aborts if `coin_store.frozen == true`.
2. **Direct-transfer disabled**: If the recipient exists but is not registered for APT and has `allow_arbitrary_coin_transfers = false`, the `assert!` at line 124 aborts.

The formal spec confirms both abort conditions: [3](#0-2) 

The prover team explicitly disabled verification of `distribute` because of this loop-abort issue: [4](#0-3) 

The `set_beneficiary` guard (`assert_account_is_registered_for_apt`) only checks registration at the moment of assignment: [5](#0-4) 

It does **not** check whether the `CoinStore` is frozen, and it cannot prevent a CoinStore from being frozen *after* the beneficiary is set. Additionally, `reset_beneficiary` can remove a beneficiary and revert distribution to the shareholder's own address, which may itself have a frozen store: [6](#0-5) 

The same structural flaw is compounded by `distribute_many`, which calls `distribute` for multiple contracts in a second unbounded loop — a single failing contract blocks all subsequent ones: [7](#0-6) 

---

### Impact Explanation

If any one shareholder's (or beneficiary's) APT `CoinStore` is frozen, every call to `vesting::distribute` for that contract aborts. All other shareholders — who have done nothing wrong — are permanently denied their vested APT. The coins remain locked inside the vesting contract with no alternative distribution path. This constitutes **permanent freezing of vesting balances** for all shareholders in the affected contract.

---

### Likelihood Explanation

The Aptos framework holds a `FreezeCapability` for APT and can freeze any account's `CoinStore` (e.g., for regulatory/compliance reasons). Any such action against a single shareholder or beneficiary address permanently DoS's the entire vesting contract. The `reset_beneficiary` function provides an additional path: a beneficiary resetter (a role the admin can assign to any address) can remove a valid beneficiary, reverting distribution to a shareholder address that may subsequently be frozen. The structural vulnerability is acknowledged by the prover team and has no on-chain mitigation.

---

### Recommendation

Replace the all-or-nothing loop with a per-shareholder try/catch pattern, or add a `distribute(shareholder_address)` entry point that distributes to a single shareholder. This mirrors the fix suggested in the external report (`distribute(address[] memory _gauges)`). Concretely:

1. Add `public entry fun distribute_to_shareholder(contract_address: address, shareholder: address)` that distributes only to one shareholder at a time.
2. In the existing `distribute`, wrap each `aptos_account::deposit_coins` call so that a failure for one recipient does not revert the entire transaction (e.g., skip and emit a `DistributionFailed` event, or accumulate failed recipients for retry).
3. Extend the `set_beneficiary` guard to also assert the beneficiary's `CoinStore` is not frozen at assignment time (though this cannot prevent post-assignment freezing).

---

### Proof of Concept

```move
// 1. Attacker is a shareholder in a vesting contract.
// 2. Aptos framework freezes attacker's APT CoinStore (regulatory action).
// 3. Anyone calls vesting::distribute(contract_address).
//    → shareholders.for_each_ref iterates to attacker's address
//    → aptos_account::deposit_coins aborts: coin_store.frozen == true
//    → entire transaction reverts
//    → all other shareholders receive nothing
// 4. Every subsequent call to distribute also aborts.
//    → vesting balances of all shareholders are permanently frozen.

// Alternatively, without requiring a freeze:
// 1. Admin calls reset_beneficiary for shareholder S, removing their beneficiary.
// 2. S's own account was created via account::create_account (no APT registration).
// 3. S calls set_allow_direct_coin_transfers(false).
// 4. distribute() → deposit_coins(S, ...) → assert!(can_receive_direct_coin_transfers(S)) → ABORT
//    → all other shareholders permanently blocked.

    public entry fun distribute(contract_address: address) acquires VestingContract {
        assert_active_vesting_contract(contract_address);

        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        let coins = withdraw_stake(vesting_contract, contract_address);
        let total_distribution_amount = coin::value(&coins);
        if (total_distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };

        // Distribute coins to all shareholders in the vesting contract.
        let grant_pool = &vesting_contract.grant_pool;
        let shareholders = &grant_pool.shareholders();
        shareholders.for_each_ref(|shareholder| {
            let shareholder = *shareholder;
            let shares = pool_u64::shares(grant_pool, shareholder);
            let amount = pool_u64::shares_to_amount_with_total_coins(grant_pool, shares, total_distribution_amount);
            let share_of_coins = coin::extract(&mut coins, amount);
            let recipient_address = get_beneficiary(vesting_contract, shareholder);
            aptos_account::deposit_coins(recipient_address, share_of_coins);
        });

    public entry fun reset_beneficiary(
        account: &signer,
        contract_address: address,
        shareholder: address,
    ) acquires VestingAccountManagement, VestingContract {
        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        let addr = signer::address_of(account);
        assert!(
            addr == vesting_contract.admin ||
                addr == get_role_holder(contract_address, utf8(ROLE_BENEFICIARY_RESETTER)),
            error::permission_denied(EPERMISSION_DENIED),
        );

        let beneficiaries = &mut vesting_contract.beneficiaries;

            beneficiaries.remove(&shareholder);
