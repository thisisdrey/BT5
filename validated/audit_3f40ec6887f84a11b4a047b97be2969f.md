Audit Report

## Title
Reward pages are irrevocably marked "claimed" before the reward transfer succeeds, permanently burning stakers' rewards on transfer failure - ([File: substrate/frame/staking-async/src/pallet/impls.rs])

## Summary
In `do_payout_stakers_by_page`, `Eras::<T>::set_rewards_as_claimed(era, &stash, page)` is called at [1](#0-0)  before any actual transfer of value occurs, and the code explicitly documents that "no errors allowed after this point" at line 393. The subsequent transfer-based payout path, `make_payout_from_provider`, performs a real `T::Currency::transfer` from the era pot to the payee account and, on failure, only logs an error and returns `None`, silently dropping the reward with the page permanently marked claimed [2](#0-1) .

## Finding Description
`payout_stakers`/`payout_stakers_by_page` is a permissionless extrinsic that anyone can call for any stash. The claim-marking storage write happens unconditionally before settlement: [3](#0-2) . Since the DAP-payout mode was introduced (`prdoc/stable2606/pr_11616.prdoc`), payouts to `RewardDestination::Account` no longer mint tokens into the destination (which always succeeds and creates the account) but instead `transfer` real currency from a pre-funded era pot via `make_payout_from_provider`: [4](#0-3) . Unlike `mint_creating` used in the legacy path (`make_payout_legacy`, line 666), a `Currency::transfer` to a non-existent account below the existential deposit fails and returns `Err`. The same log-and-drop pattern with no retry exists for validator incentive transfers in `transfer_validator_incentive`: [5](#0-4) . Because `set_rewards_as_claimed` was already committed, `is_rewards_claimed` will return `true` for `(era, stash, page)` forever, so `Error::AlreadyClaimed` blocks any retry (line 381-384), and the era pot funds simply never reach the intended beneficiary.

Existing guards are insufficient: there is no pre-check that the destination account can actually receive the transfer (e.g., existence/ED check) before marking the page claimed, and the "Input data seems good, no errors allowed after this point" comment at line 393 confirms this is a deliberate design choice for individual payout failures within a batch, not a safety net.

This directly violates the required invariant that "payout state must only advance after ... settlement succeed[s] atomically" — the claimed-marker advances unconditionally, independent of whether the transfer that is supposed to deliver the reward actually succeeds.

## Impact Explanation
Any nominator or validator with `Payee` set to `RewardDestination::Account(dest_account)` pointing at an account with zero balance/no provider reference, whose per-page reward share is below `ExistentialDeposit`, permanently and irrecoverably loses that page's reward the moment anyone (not necessarily the stash owner) calls `payout_stakers`/`payout_stakers_by_page`. The era-pot funds are neither delivered to the beneficiary nor returned to any recoverable pool — this is a fund-loss/permanent-lock condition falling under "Balances ... must conserve value and settle exactly once to the rightful beneficiary and amount" and "payout state must only advance after ... settlement succeed[s] atomically."

## Likelihood Explanation
No privileged action, governance, or malicious infrastructure is required. A common, realistic configuration — a nominator directing rewards to a fresh cold-storage account with per-page reward below ED (easily arises for validators with many small nominators) — combined with the fact that `payout_stakers` is callable by anyone on behalf of any stash, makes this trivially and repeatably triggerable. This is confirmed by the codebase's own defensive test `defensive_panic_on_transfer_failure` in `substrate/frame/staking-async/src/tests/validator_incentive.rs` (lines 710-741), which demonstrates the transfer-failure path is a real, exercised code path (there it panics via `defensive!`, but the corresponding nominator/validator-staker path in `make_payout_from_provider` merely returns `None` and does not panic, silently dropping funds without rolling back the claim marker).

## Recommendation
Perform the transfer(s) first and only call `Eras::<T>::set_rewards_as_claimed` after the transfer (or full batch of transfers) succeeds, or make the claim-marking conditional/rollback-safe so a failed transfer does not permanently forfeit the reward. Alternatively, retain failed-transfer amounts in the era pot and expose a distinct, retryable "unclaimed reward" state (analogous to `UnclaimedRewardHandler`) instead of unconditionally and permanently marking the page as claimed regardless of transfer outcome.

## Proof of Concept
1. Configure a nominator's `Payee` as `RewardDestination::Account(fresh_account)` where `fresh_account` has zero balance and no existential deposit.
2. Ensure the nominator's computed page reward share for an era (in DAP/non-minting mode, i.e. after `DisableMintingGuard` is set) is less than `ExistentialDeposit`.
3. Call `payout_stakers_by_page(validator_stash, era, page)` (permissionless, callable by anyone).
4. Observe: `Eras::set_rewards_as_claimed` is set for `(era, stash, page)` at `substrate/frame/staking-async/src/pallet/impls.rs:386`; `make_payout_from_provider` for the nominator fails the `T::Currency::transfer` call (lines 602-616), logs the error, and returns `None` — no funds reach `fresh_account`.
5. Call the same extrinsic again for the same `(era, stash, page)` — it returns `Error::AlreadyClaimed` (lines 381-384), proving the reward is permanently and irrecoverably lost.

	/// Make a payment to a staker from an era reward pot (transfer, not mint).
	fn make_payout_from_provider(
		era: EraIndex,
		stash: &T::AccountId,
		amount: BalanceOf<T>,
	) -> Option<(BalanceOf<T>, RewardDestination<T::AccountId>)> {
		if amount.is_zero() {
			return None;
		}

		let dest = match Self::payee(Stash(stash.clone())) {
			Some(d) => d,
			None => {
				Self::deposit_event(Event::<T>::Unexpected(UnexpectedKind::MissingPayee {
					era,
					stash: stash.clone(),
				}));
				return None;
			},
		};

		let payout_account = Self::payout_account_for_dest(stash, &dest)?;

		let staker_rewards_pot =
			T::RewardPots::pot_account(RewardPot::Era(era, RewardKind::StakerRewards));
		if let Err(e) = T::Currency::transfer(
			&staker_rewards_pot,
			&payout_account,
			amount,
			Preservation::Expendable,
		) {
			log!(
				error,
				"Failed to transfer reward from pot for era {:?}, stash {:?}: {:?}",
				era,
				stash,
				e
			);
			return None;
		}
