## Finding

Analog located in the roaming/remote-address-trust logic that backs `lighthouse.remote_allow_list`, the nebula counterpart to Starklane's "whitelist" gate.

### Title
Replayed handshake makes `SetRemoteIfPreferred` roam a peer's remote UDP address without consulting `lighthouse.remote_allow_list` - (File: `hostmap.go`)

### Summary
`HostInfo.SetRemote` is the single place that trusts a UDP source address as the "current remote" for a peer, and every legitimate caller gates it behind `LightHouse.GetRemoteAllowList().AllowAll(...)` — except one: `SetRemoteIfPreferred`, invoked from the `ErrAlreadySeen` branch of handshake replay handling. That path unconditionally accepts the sender address of a *replayed* handshake packet as the new preferred remote, bypassing the allow-list check entirely.

### Finding Description
`HostInfo.SetRemote` records the UDP address to use for a peer and feeds it into the `RemoteList` cache via `LearnRemote`: [1](#0-0) 

Every call site that changes a peer's live remote address checks the allow list first:
- `beginHandshake` calls `hm.validatePeerCert`, which itself performs the `AllowAll` check before `HostInfo.SetRemote` is ever invoked: [2](#0-1) [3](#0-2) 
- `continueHandshake` explicitly checks `AllowAll` before processing the packet that leads to `SetRemote`: [4](#0-3) [5](#0-4) 
- `handleHostRoaming` explicitly checks `AllowAll` before roaming: [6](#0-5) 

But the fourth call site, `HostInfo.SetRemoteIfPreferred`, contains no such check at all: [7](#0-6) 

This function is invoked from `handleCheckAndCompleteError`'s `ErrAlreadySeen` branch — the code path taken when an incoming handshake stage-0 packet exactly matches a stage-0 packet already recorded for an existing `HostInfo` (i.e., a *replayed* handshake message): [8](#0-7) [9](#0-8) 

An e2e test already exercises this exact path and documents that it changes the tunnel's remote without any allow-list involvement: [10](#0-9) 

The asymmetry mirrors the external report's bug class precisely: three call sites treat "is this new remote address permitted" as a gate that must always be honored (the "whitelist enabled" check), while one — the replay/duplicate-handshake path — unconditionally trusts the attacker-influenced value (`via.UdpAddr`, the UDP source address of the packet, which is spoofable/replayable) and lets it become sticky state (`i.remote`, `lastRoamRemote`, and the `RemoteList` "learned" cache slot) that persists regardless of what `lighthouse.remote_allow_list` is configured to permit.

### Impact Explanation
An attacker who can capture a single legitimate handshake stage-0 packet exchanged between two nebula peers (e.g., via network sniffing/MITM position) and replay it — with a UDP source address of their choosing, since UDP has no source-address authentication at this layer — can cause the receiving node to roam ("prefer") its remote address for that peer to the attacker's address/port, provided that address falls inside the receiver's `preferred_ranges`. This happens even though `lighthouse.remote_allow_list` is configured and enforced everywhere else in the roaming logic, defeating the operator's intended address-trust restriction and poisoning the node's remote-address state for that tunnel (redirecting where subsequent UDP traffic for that vpn peer is sent). This is a remote-state-poisoning class impact reachable purely by replay, without possessing a CA-signed certificate.

### Likelihood Explanation
Requires only (a) the ability to observe/replay one valid handshake stage-0 packet between two already-paired peers, and (b) the ability to send a UDP packet with a chosen source address landing in one of the configured `preferred_ranges` — no cryptographic material or valid certificate is needed by the attacker themselves. This is a realistic on-path/off-path network attacker capability, especially since `preferred_ranges` commonly cover broad private/LAN ranges.

### Recommendation
Add the same `f.lightHouse.GetRemoteAllowList().AllowAll(hostinfo.vpnAddrs, via.UdpAddr.Addr())` gate inside `SetRemoteIfPreferred` (or immediately before it is invoked in `handleCheckAndCompleteError`'s `ErrAlreadySeen` branch), matching the check already performed at `continueHandshake`, `beginHandshake`/`validatePeerCert`, and `handleHostRoaming`, so that no code path can promote an attacker-supplied address to "current remote" without passing the configured allow list.

### Proof of Concept
1. Establish a normal tunnel between hosts A and B (as in `TestHandshakeAlreadySeenPreferredRemote`) and capture A's stage-0 handshake packet in flight to B. [11](#0-10) 
2. From an attacker-controlled address inside one of B's `preferred_ranges` (but excluded by a configured `lighthouse.remote_allow_list`), replay the exact captured stage-0 bytes to B.
3. B's `CheckAndComplete` matches the payload bytes against the existing `HostInfo` and returns `ErrAlreadySeen`; `handleCheckAndCompleteError` calls `existing.SetRemoteIfPreferred(f.hostMap, via)` with `via.UdpAddr` set to the attacker's address. [12](#0-11) 
4. Because `SetRemoteIfPreferred` never calls `AllowAll`, B accepts the attacker's address as the new preferred remote for A's `HostInfo`, redirecting future UDP sends for that tunnel — despite `remote_allow_list` being configured to deny it.

// SetRemoteIfPreferred returns true if the remote was changed. The lastRoam
// time on the HostInfo will also be updated.
func (i *HostInfo) SetRemoteIfPreferred(hm *HostMap, via ViaSender) bool {
	if via.IsRelayed {
		return false
	}

	currentRemote := i.GetRemote()
	if !currentRemote.IsValid() {
		i.SetRemote(via.UdpAddr)
		return true
	}

	// NOTE: We do this loop here instead of calling `isPreferred` in
	// remote_list.go so that we only have to loop over preferredRanges once.
	newIsPreferred := false
	for _, l := range hm.GetPreferredRanges() {
		// return early if we are already on a preferred remote
		if l.Contains(currentRemote.Addr()) {
			return false
		}

		if l.Contains(via.UdpAddr.Addr()) {
			newIsPreferred = true
		}
	}

	if newIsPreferred {
		// Consider this a roaming event
		i.lastRoam = time.Now()
		i.lastRoamRemote = currentRemote

		i.SetRemote(via.UdpAddr)

		return true
	}

	return false
}

func (f *Interface) handleHostRoaming(hostinfo *HostInfo, via ViaSender) {
	curRemote := hostinfo.GetRemote()
	if !via.IsRelayed && curRemote != via.UdpAddr {
		if !f.lightHouse.GetRemoteAllowList().AllowAll(hostinfo.vpnAddrs, via.UdpAddr.Addr()) {
			if f.l.Enabled(context.Background(), slog.LevelDebug) {
				hostinfo.logger(f.l).Debug("lighthouse.remote_allow_list denied roaming", "newAddr", via.UdpAddr)
			}
			return
		}

		if !hostinfo.lastRoam.IsZero() && via.UdpAddr == hostinfo.lastRoamRemote && time.Since(hostinfo.lastRoam) < RoamingSuppressSeconds*time.Second {
			if f.l.Enabled(context.Background(), slog.LevelDebug) {
				hostinfo.logger(f.l).Debug("Suppressing roam back to previous remote",
					"suppressSeconds", RoamingSuppressSeconds,
					"udpAddr", curRemote,
					"newAddr", via.UdpAddr,
				)
			}
			return
		}

		hostinfo.logger(f.l).Info("Host roamed to new udp ip/port.",
			"udpAddr", curRemote,
			"newAddr", via.UdpAddr,
		)
		hostinfo.lastRoam = time.Now()
		hostinfo.lastRoamRemote = curRemote
		hostinfo.SetRemote(via.UdpAddr)

func TestHandshakeAlreadySeenPreferredRemote(t *testing.T) {
	t.Parallel()
	// When a duplicate msg1 arrives via ErrAlreadySeen, verify the tunnel
	// remains functional and hostmap index count is stable.

	ca, _, caKey, _ := cert_test.NewTestCaCert(cert.Version1, cert.Curve_CURVE25519, time.Now(), time.Now().Add(10*time.Minute), nil, nil, []string{})
	myControl, myVpnIpNet, myUdpAddr, _ := newSimpleServer(cert.Version1, ca, caKey, "me", "10.128.0.1/24", nil)
	theirControl, theirVpnIpNet, theirUdpAddr, _ := newSimpleServer(cert.Version1, ca, caKey, "them", "10.128.0.2/24", nil)

	myControl.InjectLightHouseAddr(theirVpnIpNet[0].Addr(), theirUdpAddr)
	theirControl.InjectLightHouseAddr(myVpnIpNet[0].Addr(), myUdpAddr)

	myControl.Start()
	theirControl.Start()

	r := router.NewR(t, myControl, theirControl)
	defer r.RenderFlow()

	t.Log("Complete a normal handshake via the router")
	myControl.InjectTunPacket(BuildTunUDPPacket(theirVpnIpNet[0].Addr(), 80, myVpnIpNet[0].Addr(), 80, []byte("Hi")))
	r.RouteForAllUntilTxTun(theirControl)
	assertTunnel(t, myVpnIpNet[0].Addr(), theirVpnIpNet[0].Addr(), myControl, theirControl, r)

	t.Log("Record hostmap state")
	theirIndexes := len(theirControl.ListHostmapIndexes(false))
	hi := theirControl.GetHostInfoByVpnAddr(myVpnIpNet[0].Addr(), false)
	assert.NotNil(t, hi)
	originalRemote := hi.CurrentRemote

	t.Log("Re-trigger traffic to cause a new handshake attempt (ErrAlreadySeen)")
	myControl.InjectTunPacket(BuildTunUDPPacket(theirVpnIpNet[0].Addr(), 80, myVpnIpNet[0].Addr(), 80, []byte("roam")))
	r.RouteForAllUntilTxTun(theirControl)

	t.Log("Verify tunnel still works")
	assertTunnel(t, myVpnIpNet[0].Addr(), theirVpnIpNet[0].Addr(), myControl, theirControl, r)

	t.Log("Verify remote is still valid and index count is stable")
	hi2 := theirControl.GetHostInfoByVpnAddr(myVpnIpNet[0].Addr(), false)
	assert.NotNil(t, hi2)
	assert.Equal(t, originalRemote, hi2.CurrentRemote)
	assert.Equal(t, theirIndexes, len(theirControl.ListHostmapIndexes(false)),
		"no extra indexes should be created from ErrAlreadySeen")
