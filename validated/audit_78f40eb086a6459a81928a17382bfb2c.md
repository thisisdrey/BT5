### Title
Boundary-Exact `EnergyPriceHistory` Timestamp Lookup Can Report/Charge an Incorrect Historical Energy Price at a Tier Boundary - (File: `framework/src/main/java/org/tron/core/services/jsonrpc/JsonRpcApiUtil.java`)

### Summary
`JsonRpcApiUtil.parseEnergyFee` looks up the applicable energy price "tier" for a given `timestamp` by scanning a `time:price` history string and returning the first entry whose `time` is strictly less than the timestamp. This mirrors the reported `PriceTierVestingSale_2_0.getClaimableAmount` bug class: a tier boundary decision is made using a block-derived timestamp with a strict inequality, so a value that lands exactly on the tier boundary is resolved to the wrong (previous) tier.

### Finding Description
`parseEnergyFee` iterates the price history from the newest entry backward and returns the price of the first entry where `timestamp > time`: [1](#0-0) 

This is invoked with `block.getTimeStamp()` (an on-chain block timestamp) in `BlockEventGet.getEnergyPrice` used for transaction-log/receipt construction: [2](#0-1) 

and with an arbitrary caller-supplied `timestamp` in `Wallet.getEnergyFee(long timestamp)`: [3](#0-2) 

The strict `>` comparison means that a timestamp exactly equal to a price-change boundary (`time`) is excluded from that tier and falls through to the *previous* (older) price entry, producing an off-by-one-tier result at the exact boundary instant — the same class of defect the external report describes (block-time-driven tier lookup with an edge case at the exact transition moment).

### Impact Explanation
The reachable impact of this specific analog is limited: `parseEnergyFee`/`getEnergyPrice` feeds `effectiveGasPrice` in JSON-RPC transaction receipts/logs (`TransactionReceipt`, `TransactionLogTriggerCapsule`) — a reporting/informational value returned by the JSON-RPC query path, not the authoritative on-chain energy fee actually deducted from an account (that is governed directly by `DynamicPropertiesStore.getEnergyFee()`/proposal-controlled current value during actual execution). Because of this, the practical effect of hitting the boundary is an incorrect informational gas price reported via `eth_getTransactionReceipt`/log triggers for transactions whose block timestamp exactly equals a price-history change point, rather than a fund-theft or balance manipulation. This caps the severity below the "unauthorized fund movement / permanent freezing / chain halt" bar required by the validation rules for this scan.

### Likelihood Explanation
Any anonymous JSON-RPC client can query historical energy prices for a block whose timestamp coincides with a `time` boundary in `EnergyPriceHistory`, since block timestamps are deterministic and publicly known; hitting the exact boundary is a normal, non-adversarial occurrence (it requires no special privilege, just querying the specific block/timestamp), but the confirmed effect is confined to a reporting-only field.

### Recommendation
Change the comparison in `parseEnergyFee` from `timestamp > time` to `timestamp >= time` (or otherwise define/clarify tier inclusivity, e.g. treat `time` as inclusive of the new price) so that a timestamp exactly matching a price-change point resolves to the newly effective price tier, consistent with how the price update was intended to take effect at that instant.

### Proof of Concept
1. Configure/observe `DynamicPropertiesStore.getEnergyPriceHistory()` containing an entry such as `...,1000000:1000` (price 1000 sun/energy becomes effective at ms-timestamp `1000000`).
2. Produce or reference a block whose `getTimeStamp()` equals exactly `1000000`.
3. Call `BlockEventGet.getEnergyPrice(1000000)` (or JSON-RPC `eth_getTransactionReceipt` for a transaction in that block) — `parseEnergyFee` evaluates `1000000 > 1000000` as `false` and skips this entry, returning the *older* price entry preceding it instead of `1000`.
4. This demonstrates the boundary-exact tier miscalculation: the reported `effectiveGasPrice` for that block's transactions is one tier behind what the price schedule intended.

  public static long parseEnergyFee(long timestamp, String energyPriceHistory) {
    String[] priceList = energyPriceHistory.split(",");

    for (int i = priceList.length - 1; i >= 0; i--) {
      String[] priceArray = priceList[i].split(":");
      long time = Long.parseLong(priceArray[0]);
      long price = Long.parseLong(priceArray[1]);
      if (timestamp > time) {
        return price;
      }
    }

    return -1;
  }
