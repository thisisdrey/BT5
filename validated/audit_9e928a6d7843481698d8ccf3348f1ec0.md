### Title
`leverage` slippage check (`depositAmountMin_`) is applied before the deposit fee is deducted, so the user's final deposited collateral can be less than the minimum they specified - (File: contracts/SmartFarmingManager.sol)

### Summary
`SmartFarmingManager.leverage` lets the user pass `depositAmountMin_` documented as "The min final deposit amount (slippage)". The check at line 198 compares that minimum against `_depositAmount`, the gross collateral amount gathered before `DepositToken.deposit` is called. `DepositToken.deposit` then deducts `depositFee` via `quoteDepositOut`, so the amount actually credited to the user's position (`_deposited = _depositAmount - fee`) can be below `depositAmountMin_` while the transaction still succeeds. This is the same bug class as the Elfi finding: the min-out check is performed on the pre-fee amount instead of the post-fee amount actually delivered to the user.

### Finding Description
In `leverage`:

- Line 197: `_depositAmount = amountIn_ + _swap(...)` — gross collateral after the synth→collateral swap.
- Line 198: `if (_depositAmount < depositAmountMin_) revert LeverageSlippageTooHigh();` — slippage check on the gross amount.
- Line 203: `(_deposited, ) = depositToken_.deposit(_depositAmount, _msgSender);`

Inside `DepositToken.deposit` / `quoteWithdrawOut`-equivalent `quoteDepositOut` (`contracts/DepositToken.sol:294-302`), the fee is carved out:

```solidity
_fee = amount_.wadMul(_depositFee);
_amountToDeposit = amount_ - _fee;
```

and only `amount_ - _fee` (`_deposited`) is minted to `onBehalfOf_`, while `_fee` is minted to `feeCollector` (`DepositToken.sol:229-234`).

So when `depositFee > 0`, `depositAmountMin_` does not actually bound what lands in the user's collateral position. Example: user passes `depositAmountMin_ = 100` and `depositFee = 1%`; a path producing `_depositAmount = 100` passes the check but only `99` is minted to the user.

The sister function `flashRepay` does this correctly: its `swapAmountOutMin_` is checked against `_swapAmountOut` measured *after* `flashWithdraw` already deducted the withdraw fee (`SmartFarmingManager.sol:122-126`), showing the intended pattern is a post-fee check.

### Impact Explanation
The user's explicit minimum-received guarantee is violated: their position can be credited less collateral than `depositAmountMin_` without reverting, with the shortfall equal to `depositFee * _depositAmount` (bounded by `MAX_FEE` in `FeeProvider`). The post-`leverage` health check (`PositionIsNotHealthy`) does not prevent this — a position can remain healthy while receiving less collateral than the caller required, and the deficit is absorbed by the user, not the protocol. No attacker action is needed; any unprivileged caller of `leverage` on a deployment where `depositFee > 0` is affected.

### Likelihood Explanation
Requires `depositFee > 0` in `FeeProvider` on the deployment and users leveraging through `SmartFarmingManager.leverage` with a tight `depositAmountMin_`. Fees are quoteable off-chain, so the economic impact per call is bounded by the fee, but the slippage invariant itself is broken on every leverage call where the fee is non-zero.

### Recommendation
Apply the slippage check to the post-fee deposited amount, i.e. move it after `deposit`:

```solidity
// 3. swap synth for collateral
uint256 _depositAmount = amountIn_ + _swap(_swapper, syntheticToken_, _collateral, _issued, 0);

// 4. deposit collateral
_collateral.safeApprove(address(depositToken_), 0);
_collateral.safeApprove(address(depositToken_), _depositAmount);
(_deposited, ) = depositToken_.deposit(_depositAmount, _msgSender);
if (_deposited < depositAmountMin_) revert LeverageSlippageTooHigh();
```

Alternatively, check `quoteDepositOut(_depositAmount)._amountToDeposit >= depositAmountMin_` before depositing.

### Proof of Concept
Hardhat-style fork/unit test sketch (mirroring `test/SmartFarmingManager.test.ts` setup):

```ts
// given: depositFee > 0
await feeProvider.connect(governor).updateDepositFee(parseEther('0.01')) // 1%

// alice has collateral, pool has liquidity for the synth

const leverage = parseEther('1.5')

// compute expected gross deposit amount via quotes
const debt = await masterOracle.quote(collateral.address, synth.address,
  leverage.sub(parseEther('1')).mul(amountIn).div(parseEther('1')))
const swapped = /* quote synth->collateral for `debt` */
const gross = amountIn.add(swapped)

// user demands min = gross (zero tolerated slippage on the swap)
const tx = smartFarmingManager.connect(alice).leverage(
  ethers.constants.AddressZero, depositToken.address, synth.address,
  amountIn, leverage, gross /* depositAmountMin_ */)

// current code: succeeds even though net deposited is gross * 0.99 < gross
```

With the fix, the call reverts with `LeverageSlippageTooHigh` whenever `deposited < depositAmountMin_`.

Caveat: I did not fully verify whether `Pool.swap` exposes a user-supplied min-out checked pre-fee; the `leverage` path is the strongest confirmed surface for this bug class in this repo.
