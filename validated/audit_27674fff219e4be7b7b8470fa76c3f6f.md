### Title
Unauthenticated write of attacker-chosen content into AtlasDB via `AttachmentsDownloader::run` without hash-to-instance binding check - (File: stackslib/src/net/atlas/download.rs)

### Summary
`AttachmentsDownloader::run` inserts every `Attachment` returned by a peer for a `GetAttachment` request directly into `AtlasDB` via `insert_instantiated_attachment`, independent of whether `find_all_attachment_instances(&attachment.hash())` finds any matching on-chain-committed `AttachmentInstance`. A malicious peer can respond to any attachment fetch with arbitrary bytes unrelated to the on-chain `content_hash` that was actually requested, and that data will be persisted to the node's AtlasDB.

### Finding Description
The intended invariant of Atlas is that any `Attachment` stored in `AtlasDB` corresponds to some confirmed `AttachmentInstance.content_hash` committed on-chain via a BNS/Atlas contract-call. `AttachmentsBatchStateContext::extend_with_attachments` (stackslib/src/net/atlas/download.rs:530-558) takes an HTTP response from a peer, decodes it with `decode_atlas_get_attachment()`, and inserts `response.attachment` into `self.attachments` (a `HashSet<Attachment>`) with **no check that `response.attachment.hash() == request.content_hash`** — the `AttachmentRequest` that was sent (carrying the expected `content_hash`, see fields at download.rs:404-478) is discarded once the response arrives; only the URL/report is used to update peer reliability, and the attachment content itself is trusted verbatim.

Then in `AttachmentsDownloader::run`, when the state machine reaches `Done`:
```
stackslib/src/net/atlas/download.rs:153-169
AttachmentsBatchStateMachine::Done(ref mut context) => {
    for attachment in context.attachments.drain() {
        let attachments_instances = network
            .atlasdb
            .find_all_attachment_instances(&attachment.hash())
            .map_err(net_error::DBError)?;
        network
            .atlasdb
            .insert_instantiated_attachment(&attachment)
            .map_err(net_error::DBError)?;
        for attachment_instance in attachments_instances.into_iter() {
            resolved_attachments.push((attachment_instance, attachment.clone()));
        }
        context
            .attachments_batch
            .resolve_attachment(&attachment.hash())
    }
```
`insert_instantiated_attachment(&attachment)` is called unconditionally, regardless of whether `attachments_instances` (i.e., the set of confirmed `AttachmentInstance`s whose `content_hash` equals `attachment.hash()`) is empty. If it is empty, the attachment is still written to the DB, and simply no `resolved_attachments` entries are produced for it — the write happens anyway.

The attacker's exact message: run a peer that advertises (or is queried opportunistically via) an `AttachmentsInv`/`GetAttachment` HTTP exchange and, upon a `GetAttachment` request for content-hash `H` (from a legitimate, on-chain-recorded `AttachmentInstance`), respond with an HTTP 200 body encoding an arbitrary `Attachment` whose bytes hash to some unrelated value `H' != H`. `decode_atlas_get_attachment` only checks that the payload deserializes; it never compares the decoded attachment's hash to the request's `content_hash`. That forged attachment is then unconditionally written into `AtlasDB` by `insert_instantiated_attachment`, breaking the invariant `stored_attachment_hash == some_confirmed_AttachmentInstance.content_hash`.

Existing guards that do NOT stop this: HTTP length limits (`MAX_MESSAGE_LEN`/`MAX_PAYLOAD_LEN`) only bound message size, not content correctness; peer reliability scoring (`ReliabilityReport`) only affects future peer selection, not this write; `find_attachment`/`find_uninstantiated_attachment` checks in `check_attachment_instances` are used elsewhere (for instance resolution) but are not consulted at the point of insertion in `run`.

### Impact Explanation
A remote, unprivileged peer serving Atlas HTTP endpoints can cause arbitrary attacker-chosen byte content (bounded only by `attachments_max_size`, default 1 MiB) to be permanently written into a victim node's `AtlasDB` (`insert_instantiated_attachment`), with no corresponding on-chain `AttachmentInstance` binding that hash. This is a Critical-severity unauthenticated write of attacker-chosen content into persistent state without any on-chain commitment backing it, repeatable per attachment-request/response round-trip (the attacker can respond to many distinct requested hashes, or manufacture batches that get bogus attachments inserted). The forged rows sit in AtlasDB and can later be served to further nodes/clients if any Atlas RPC endpoint reads `find_attachment` by hash without independently re-validating the on-chain binding (out of scope to trace those endpoints here, but the write itself is the root vulnerability).

### Likelihood Explanation
Preconditions are minimal: the victim node must be running the Atlas downloader and have at least one outbound sync peer configured whose data URL resolves (an unprivileged remote peer merely needs to be selected as a data source, e.g., by being an outbound peer the node syncs with) — this requires no RPC secret, no privileged role, and no local access. The attacker only needs to run an HTTP server implementing the `GetAttachmentsInv`/`GetAttachment` protocol and respond with crafted bytes; this is fully remote and repeatable at will.

### Recommendation
In `AttachmentsDownloader::run` (and/or `extend_with_attachments`), before calling `insert_instantiated_attachment`, verify that `attachment.hash()` matches the `content_hash` of the originally-issued `AttachmentRequest` (available when the response is received) and/or require `find_all_attachment_instances(&attachment.hash())` to be non-empty before persisting the attachment; drop/penalize peers that return mismatched content instead of storing it.

### Proof of Concept
```rust
// stackslib/src/net/atlas/download.rs (test module)
#[test]
fn test_attachments_downloader_stores_unbound_attachment() {
    let mut atlasdb = AtlasDB::connect_memory().unwrap();
    // No AttachmentInstance in the db references this content at all.
    let forged = Attachment::new(b"attacker-controlled-bytes-unrelated-to-any-instance".to_vec());
    let forged_hash = forged.hash();

    // Simulate reaching AttachmentsBatchStateMachine::Done with the forged attachment
    // in context.attachments (as would happen after extend_with_attachments processes
    // a malicious peer's GetAttachment HTTP response with no hash validation).
    let mut context = AttachmentsBatchStateContext::new(
        AttachmentsBatch::new(),
        HashMap::new(),
        &ConnectionOptions::default(),
    );
    context.attachments.insert(forged.clone());

    for attachment in context.attachments.drain() {
        let instances = atlasdb.find_all_attachment_instances(&attachment.hash()).unwrap();
        assert!(instances.is_empty(), "no on-chain instance should reference this hash");
        atlasdb.insert_instantiated_attachment(&attachment).unwrap();
    }

    // Assert the forged, uncommitted attachment now exists in AtlasDB.
    let stored = atlasdb.find_attachment(&forged_hash).unwrap();
    assert!(stored.is_some(), "forged attachment with no on-chain binding was persisted");
}

    pub fn get_prioritized_attachments_requests(&self) -> BinaryHeap<AttachmentRequest> {
        let mut queue = BinaryHeap::new();
        let mut enqueued = HashSet::new();
        for ((contract_id, pages, _), peers_responses) in self.inventories.iter() {
            let missing_attachments = match self
                .attachments_batch
                .attachments_instances
                .get(contract_id)
            {
                None => continue,
                Some(missing_attachments) => missing_attachments,
            };
            // Note: we're getting missing_attachments (attachment_id: content_hash)
            for (attachment_index, content_hash) in missing_attachments.iter() {
                let page_index = attachment_index / AttachmentInstance::ATTACHMENTS_INV_PAGE_SIZE;
                // Since there's a limit in the number of pages that a node can request,
                // we can potentially have multiple inventory request at once.
                if !pages.contains(&page_index) {
                    continue;
                }

                if enqueued.contains(content_hash) {
                    debug!("Atlas: {} already enqueued", content_hash);
                    continue;
                }

                let mut sources = HashMap::new();
                let position_in_page =
                    attachment_index % AttachmentInstance::ATTACHMENTS_INV_PAGE_SIZE;

                for (peer_url, response) in peers_responses.iter() {
                    // Considering the response, look for the page with the index
                    // we're looking for.
                    let search_page = response.pages.iter().find(|page| page.index == page_index);

                    let has_attachment = search_page
                        .and_then(|search_page| {
                            search_page.inventory.get(position_in_page as usize)
                        })
                        .map(|result| *result == 1)
                        .unwrap_or(false);

                    if !has_attachment {
                        debug!(
                            "Atlas: peer does not have attachment ({}, {}) in its inventory {:?}",
                            page_index, position_in_page, response.pages
                        );
                        continue;
                    }

                    let report = self
                        .peers
                        .get(peer_url)
                        .expect("Atlas: unable to retrieve reliability report for peer");
                    sources.insert(peer_url.clone(), report.clone());
                }

                if sources.is_empty() {
                    warn!("Atlas: could not find a peer including attachment in its inventory");
                    continue;
                }

                // Success, we found at least one inventory including the attachment we're looking for.
                let request = AttachmentRequest {
                    sources,
                    content_hash: content_hash.clone(),
                    stacks_block_height: self.attachments_batch.stacks_block_height,
                    canonical_stacks_tip_height: self.attachments_batch.canonical_stacks_tip_height,
                };
                enqueued.insert(content_hash);
                queue.push(request);
            }
        }
        queue
    }

    pub fn extend_with_attachments(
        mut self,
        results: &mut BatchedRequestsResult<AttachmentRequest>,
    ) -> AttachmentsBatchStateContext {
        for (request, response) in results.succeeded.drain() {
            let report = self
                .peers
                .get_mut(request.get_url())
                .expect("Atlas: unable to retrieve reliability report for peer");

            let response = if let Some(r) = response {
                r
            } else {
                report.bump_failed_requests();
                continue;
            };

            if let Ok(response) = response.decode_atlas_get_attachment() {
                self.attachments.insert(response.attachment);
                report.bump_successful_requests();
            } else {
                report.bump_failed_requests();
            }
        }
        let mut events_ids = results.faulty_peers.keys().copied().collect::<Vec<usize>>();
        self.events_to_deregister.append(&mut events_ids);

        self
    }
