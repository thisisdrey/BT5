### Title
Unbounded concurrent FetchBundle calls with no default concurrency/size limits enable disk-exhaustion DoS - (File: internal/gitaly/service/repository/fetch_bundle.go)

### Summary
`FetchBundle` streams attacker-supplied bundle data to a per-call temporary file created via `tempdir.New` before invoking `git fetch` against it. Neither the RPC handler nor `createTempBundle` impose a limit on the number of concurrent invocations or the total size of the streamed bundle, and unlike `ReplicateRepository` there is no hard-coded default concurrency limiter for `FetchBundle`, so an unprivileged authenticated caller can invoke it many times in parallel, each unboundedly filling the storage's temp directory.

### Finding Description
`server.FetchBundle` reads the client stream via `streamio.NewReader` and calls `repo.FetchBundle(ctx, s.txManager, reader, opts)` [1](#0-0) . That in turn calls `repo.createTempBundle(ctx, reader)`, which allocates a new temp directory via `tempdir.New(ctx, repo.GetStorageName(), repo.logger, repo.locator)` and then does an unbounded `io.Copy(file, reader)` from the client stream into `repo.bundle` on disk [2](#0-1) . There is no cap on the number of bytes copied and no cap on the number of `FetchBundle` calls that may run concurrently for the same or different repositories.

Concurrency limiting in Gitaly is purely opt-in via the `[[concurrency]]` TOML configuration (`internal/gitaly/config/config.go`, `internal/grpc/middleware/limithandler/middleware.go`) [3](#0-2) . Only `ReplicateRepository` receives a built-in default limiter of `MaxConcurrency=1` when no operator configuration exists for it [4](#0-3) . `FetchBundle` has no such default, so on a stock/default Gitaly deployment (no `[[concurrency]]` entries added by the operator for this RPC) the `methodLimiters` map has no entry for it and `UnaryInterceptor`/`StreamInterceptor` bypass limiting entirely (`limiter == nil` → `return handler(...)`) [5](#0-4) .

An unprivileged user who can push/fetch/import/mirror a repository they control can drive `FetchBundle` (it is a client-streaming RPC, `rpc FetchBundle` in `proto/repository.proto`) with arbitrarily large or slow-trickling bundle payloads, and can open many such streams concurrently (e.g. against many forks/imports they own, or even the same repository if it's not otherwise serialized). Each stream allocates its own `tempdir.New`-backed temp directory and file, and the file grows without bound for as long as the client keeps sending `Data` chunks, since `io.Copy` has no size ceiling and the gRPC stream itself is not time- or size-bounded within this handler.

### Impact Explanation
This is a resource-exhaustion / denial-of-service vector: by opening N concurrent `FetchBundle` streams and slow-drip-feeding or bulk-feeding data, an attacker can consume disk space and I/O bandwidth on the shared storage backing many repositories on that Gitaly node, degrading or denying service for other tenants/repositories on the same storage. This matches the "resource exhaustion of a handler" impact class called out in the audit scope.

### Likelihood Explanation
Feasibility is high in principle: no special role is needed, only the ability to call `FetchBundle` (typically issued during repository import/mirroring flows, reachable by any user who can trigger such a fetch on a repo they own), and the vulnerability requires no non-default Gitaly configuration to exist — quite the opposite: the *absence* of an operator-configured `[[concurrency]]` entry for `FetchBundle` is what leaves it unprotected, and that absence is the default state. Repeatability is high — the attacker fully controls how many parallel streams to open and how much data to send per stream, bounded only by network/gRPC-layer limits (e.g., default gRPC keepalive/idle timeouts) which are not specific mitigations for this RPC.

However, this is a generic pattern shared by essentially every Gitaly RPC that streams client data to a temp file (`CreateRepositoryFromBundle`, `PostReceivePack`, etc.), and disk/IO exhaustion protection is treated in this codebase as an operator-configurable backpressure mechanism (`doc/backpressure.md`) rather than a per-RPC code bug — GitLab.com and self-managed operators are expected to configure `[[concurrency]]` limits for expensive RPCs. It is uncertain whether GitLab's bug bounty program treats "missing a bundled default `[[concurrency]]` entry for a specific RPC" as an in-scope Gitaly vulnerability versus an expected/known operational configuration responsibility, since the mitigation mechanism exists in-product but is not wired on by default for this RPC specifically (only for `ReplicateRepository`).

### Recommendation
- Add a conservative built-in default concurrency limiter for `FetchBundle` (similar to the `ReplicateRepository` special-case) so unconfigured deployments are not fully unprotected.
- Enforce a maximum bundle size in `createTempBundle`/`FetchBundle` (e.g., `io.LimitReader` or a byte-count check that aborts and cleans up once a configurable ceiling is exceeded).
- Consider serializing `FetchBundle` per destination repository via the existing per-repo concurrency-key mechanism (`LimitConcurrencyByRepo`) and document a recommended default in `doc/backpressure.md`.

    }
    wg.Wait()
    // Expected (vulnerable) behavior: storage temp directory usage grows
    // proportional to concurrency * bundle size with no server-side cap,
    // and no ResourceExhausted error is returned by default configuration.

func (repo *Repo) createTempBundle(ctx context.Context, reader io.Reader) (bundlPath string, cleanup func(), returnErr error) {
	tmpDir, cleanup, err := tempdir.New(ctx, repo.GetStorageName(), repo.logger, repo.locator)
	if err != nil {
		return "", nil, fmt.Errorf("create temp bundle: %w", err)
	}

	bundlePath := filepath.Join(tmpDir.Path(), "repo.bundle")

	file, err := os.Create(bundlePath)
	if err != nil {
		cleanup() // Clean up if we fail after creating the temp directory
		return "", nil, fmt.Errorf("create temp bundle: %w", err)
	}
	defer func() {
		if err := file.Close(); err != nil && returnErr == nil {
			returnErr = fmt.Errorf("create temp bundle: %w", err)
		}
	}()

	if _, err = io.Copy(file, reader); err != nil {
		cleanup() // Clean up if we fail after creating the temp directory
		return "", nil, fmt.Errorf("create temp bundle: %w", err)
	}

	return bundlePath, cleanup, nil

// UnaryInterceptor returns a Unary Interceptor
func (c *LimiterMiddleware) UnaryInterceptor() grpc.UnaryServerInterceptor {
	return func(ctx context.Context, req interface{}, info *grpc.UnaryServerInfo, handler grpc.UnaryHandler) (interface{}, error) {
		lockKey := c.getLockKey(ctx)
		if lockKey == "" {
			return handler(ctx, req)
		}

		// Check if request is authenticated
		limiter := c.methodLimiters[info.FullMethod]
		unauthLimiter, ok := c.methodLimitersUnauthenticated[info.FullMethod]
		if !auth.IsAuthenticated(ctx) && ok {
			limiter = unauthLimiter
		}

		if limiter == nil {
			// No concurrency limiting
			return handler(ctx, req)
		}

		return limiter.Limit(ctx, lockKey, func() (interface{}, error) {
			return handler(ctx, req)
		})
	}
}
