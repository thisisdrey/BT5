### Title
`ProxyOFT.sendFrom` forwards entire `msg.value` to the LayerZero endpoint with no fee validation or refund, permanently losing overpaid native fee - (File: contracts/ProxyOFT.sol)

### Summary
The user-friendly `sendFrom` function in `ProxyOFT` is `payable` and passes the caller's entire `msg.value` straight through to the LayerZero endpoint (`_send` → `_lzSend` → `lzEndpoint.send{value: msg.value}`). Like `pyth.updatePriceFeeds`, the LayerZero V1 messaging layer (`UltraLightNode`) only consumes the required oracle/relayer fee and does not return any excess ETH to the caller or the `refundAddress` on the source chain. The `_refundAddress` argument is only used for destination-chain gas and cannot recover a source-chain overpayment. Any ETH sent above the quoted `nativeFee` is locked in the LayerZero messaging contract.

### Finding Description
`ProxyOFT.sendFrom` (contracts/ProxyOFT.sol:115-128) builds `_adapterParams` itself, sets `_refundAddress = from_`, and calls the inherited `_send`. In `OFTCoreUpgradeable._send` (contracts/dependencies/@layerzerolabs/solidity-examples/contracts-upgradeable/token/oft/OFTCoreUpgradeable.sol:84-101), `_lzSend` is invoked with `msg.value` verbatim:

```solidity
_lzSend(_dstChainId, lzPayload, _refundAddress, _zroPaymentAddress, _adapterParams, msg.value);
```

There is no `estimateFees` check, no `require(msg.value == nativeFee)`, and no balance-delta refund anywhere along the path. A convenience `estimateSendFee` helper exists (contracts/ProxyOFT.sol:133-148) but the result is never enforced on-chain, so nothing prevents or compensates overpayment. Two loss scenarios mirror the Pyth report exactly:

- A user sends more ETH than `estimateSendFee` returned; the surplus is absorbed by the LayerZero endpoint/ULN and never returned.
- The LayerZero fee (oracle/relayer prices, configurable per chain) changes between the off-chain estimation and tx execution, so even a carefully computed `msg.value` can overshoot.

Other payable surfaces were checked and are not vulnerable: `Operator.execute` enforces `msg.value == _sumOfValues` (contracts/Operator.sol:54), and `NativeTokenGateway.deposit` converts all of `msg.value` into user collateral (contracts/NativeTokenGateway.sol:46-54).

### Impact Explanation
Any caller of `ProxyOFT.sendFrom` (EOA directly, or via `Operator.execute` bundling a bridge call) who supplies more native fee than required loses the difference permanently. The ETH is unrecoverable because the LayerZero V1 endpoint retains the excess; `_refundAddress` does not cover source-chain fee overpayment. This is a direct, irreversible loss of user funds reachable from an unprivileged public entry point, identical in impact to the Pyth overpayment bug.

### Likelihood Explanation
Medium. Users must bridge through `sendFrom` and fund `msg.value` manually or via a bundler/frontend estimate. Fee drift between quoting and inclusion, padded estimates supplied by UIs to avoid underpayment reverts, or the `Operator.execute` pattern (which happily forwards whatever per-call `value` is specified) all make overpayment plausible in normal operation. `sendFrom` is `nonReentrant`-free but harmless to call directly, and no modifier (`BridgingIsPaused` only gates `_debitFrom`, not fee handling) prevents the loss.

### Recommendation
Enforce the exact fee inside `sendFrom`, or refund the difference after `_lzSend`:

```diff
function sendFrom(address from_, uint16 dstChainId_, address to_, uint256 amount_) external payable {
+   (uint256 _nativeFee, ) = estimateSendFee(dstChainId_, abi.encodePacked(to_), amount_, false, _adapterParams());
+   require(msg.value == _nativeFee, "invalid-fee");
    _send({...});
}
```

Alternatively, compute the required fee, send only that to the endpoint, and `sendValue` the remainder back to `from_`.

### Proof of Concept
Fork test (Hardhat, mainnet) sketch:

```ts
// contracts under test: msETHProxyOFT / msUSDProxyOFT (deployed ProxyOFT)
const fee: BigNumber = await proxyOFT['estimateSendFee(uint16,address,uint256)'](
  DST_CHAIN_ID, alice.address, amount
)
const extra = parseEther('0.01')
const endpointBefore = await ethers.provider.getBalance(LZ_ENDPOINT)
const aliceBefore = await alice.getBalance()

await proxyOFT.connect(alice)['sendFrom(address,uint16,address,uint256)'](
  alice.address, DST_CHAIN_ID, bob.address, amount,
  { value: fee.add(extra) }
)

// Endpoint (or its ULN messaging library) keeps `extra`; no refund to alice or refundAddress
const endpointAfter = await ethers.provider.getBalance(LZ_ENDPOINT)
expect(endpointAfter.sub(endpointBefore)).to.eq(fee.add(extra))
// alice's balance decreased by fee + extra + gas, despite only `fee` being needed
```

Reproduction requires only a bridging-enabled deployment (e.g., `msETHProxyOFT`, dst chain `LZ_OP_CHAIN_ID`) and confirms excess `msg.value` is consumed without refund, matching the M-06 bug class.
