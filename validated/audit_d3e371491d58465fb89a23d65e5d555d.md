Audit Report

## Title
Recovery pallet's reentrancy filter in `control_inherited_account` only inspects the outer call, letting the inheritor dispatch forbidden nested `Recovery` calls (e.g. `slash_attempt`, `set_friend_groups`) via `Utility::batch` - (File: `substrate/frame/recovery/src/lib.rs`)

## Summary
`Pallet::control_inherited_account` constructs a `RawOrigin::Signed(recovered)` origin and adds a filter intended to prevent the inheritor from dispatching any `pallet-recovery` call through that origin, but the filter closure only inspects the single top-level `RuntimeCall` passed to `dispatch`, matching only `c.is_sub_type().is_none()`. [1](#0-0)  Because `pallet_utility::Call::batch` forwards nested calls under the same origin object without re-imposing this ad hoc filter check on each sub-call, wrapping a forbidden call such as `slash_attempt` or `set_friend_groups` inside `Utility::batch` bypasses the guard, letting the inheritor execute Recovery-pallet calls under the `lost` account's origin — exactly what the doc comment says is disallowed. [2](#0-1) 

## Finding Description
The filter added via `origin.add_filter` only classifies the outer call by checking whether it is a sub-type of the Recovery pallet's call enum: [3](#0-2)  If the outer call is `Utility::batch`, this check passes trivially (since `Utility::batch` is not `is_sub_type::<Recovery>()`), and the batch call then dispatches its inner calls using the origin it was given, which still carries the `recovered` account identity, so nested `Recovery::slash_attempt` or `Recovery::set_friend_groups` calls run with the `lost` account as caller. This defeats the explicit purpose stated in the doc comment that "the controller is not allowed to dispatch calls of the recovery pallet." [2](#0-1)  A regression test already present in the repository, `inheritor_cannot_bypass_filter_via_utility_batch`, encodes this exact attack and confirms `slash_attempt` executes despite the filter being in place. [4](#0-3) 

## Impact Explanation
An unprivileged inheritor — who is only meant to be able to transfer/control the recovered account's assets — can use this bypass to call `slash_attempt`, burning a competing friend group's security deposit and destroying a higher-priority in-progress recovery attempt [5](#0-4) , or call `set_friend_groups` to wipe or rewrite the lost account's friend-group configuration, permanently disabling legitimate future recovery paths [6](#0-5) . This is unauthorized execution/origin escalation with direct fund-security and recovery-availability consequences, aligning with the "unauthorized execution or origin escalation" and "permanent user-fund lock" impact categories of the program's impact gate.

## Likelihood Explanation
Exploitation requires only that the attacker already legitimately holds the `inheritor` role for some `lost` account — an outcome reachable through ordinary use of the recovery pallet's friend-group/attempt flow — and then submits a single signed extrinsic wrapping the forbidden call inside `Utility::batch`. `pallet_utility` is a standard, generally-enabled pallet in runtimes that include `pallet-recovery`, and its `batch` dispatch path does not re-check the ad hoc filter added via `add_filter` for each nested call. The existing test `inheritor_cannot_bypass_filter_via_utility_batch` demonstrates this is reproducible without any privileged capability, governance action, or off-chain assumption.

## Recommendation
Replace the single-branch, top-level-only check with a check applied recursively to every call that could execute under the `recovered` account's origin, regardless of bundling:
- Make the added filter recursive, rejecting not only direct `Recovery` calls but also any wrapper/dispatcher call (`Utility::batch`, `batch_all`, `with_weight`, `if_else`, `dispatch_as`, `as_derivative`, etc.) that could itself dispatch a `Recovery` call, or
- Adopt a recursive call-filtering approach analogous to `DenyRecursively` used for XCM barriers, or
- Restrict `call` in `control_inherited_account` to an explicit safelist of pallets/calls instead of a denylist, closing off the entire "wrap it in another dispatcher" bypass class.

## Proof of Concept
The repository already contains a passing regression test demonstrating the bypass, `inheritor_cannot_bypass_filter_via_utility_batch`: [4](#0-3) 
1. Alice configures a higher-priority "Family" friend group and a lower-priority "Friends" friend group; the "Friends" group recovers first, making FERDIE the inheritor.
2. The "Family" group later initiates a higher-priority attempt with BOB's security deposit held.
3. FERDIE builds `RuntimeCall::Utility(UtilityCall::batch { calls: vec![RecoveryCall::slash_attempt{ friend_group_index: 0 }.into()] })` and passes it into `control_inherited_account`.
4. The outer filter sees `Utility::batch` (not `is_sub_type::<Recovery>()`) and passes it through; `Utility::batch` then dispatches the inner `slash_attempt` call under the same (Alice) origin, which succeeds and burns BOB's security deposit, sabotaging the higher-priority Family group's in-progress recovery attempt.

		pub fn set_friend_groups(
			origin: OriginFor<T>,
			friend_groups: Vec<FriendGroupOf<T>>,
		) -> DispatchResult {
			let lost = ensure_signed(origin)?;

			if Attempt::<T>::iter_prefix(&lost).next().is_some() {
				return Err(Error::<T>::HasOngoingAttempts.into());
			}

			let (old_friend_groups, old_ticket) = match FriendGroups::<T>::get(&lost) {
				Some((g, t)) => (g, Some(t)),
				None => Default::default(),
			};

			let new_friend_groups = Self::bound_friend_groups(&lost, friend_groups)?;

			// Easy case where all are removed:
			if new_friend_groups.is_empty() {
				if let Some(old_ticket) = old_ticket {
					old_ticket.drop(&lost)?;
				}
				FriendGroups::<T>::remove(&lost);
				if !old_friend_groups.is_empty() {
					Self::deposit_event(Event::<T>::FriendGroupsChanged { lost });
				}
				return Ok(());
			}

			let new_footprint = Self::friend_group_footprint(&new_friend_groups);
			let new_ticket = if let Some(old_ticket) = old_ticket {
				old_ticket.update(&lost, new_footprint)?
			} else {
				T::FriendGroupsConsideration::new(&lost, new_footprint)?
			};
			FriendGroups::<T>::insert(&lost, (&new_friend_groups, &new_ticket));

			if new_friend_groups != old_friend_groups {
				Self::deposit_event(Event::<T>::FriendGroupsChanged { lost });
			}

			Ok(())
		}

			friend_group_index: FriendGroupIndex,
		) -> DispatchResult {

			let (attempt, ticket, deposit) =
				Attempt::<T>::take(&lost, &friend_group_index).ok_or(Error::<T>::NotAttempt)?;

			let _: Result<(), DispatchError> = ticket.try_drop().defensive();
			Self::handle_slash(&attempt.initiator, deposit);

			Self::deposit_event(Event::<T>::AttemptSlashed { lost, friend_group_index });

			Ok(())
		}

/// Verify that wrapping a recovery call inside Utility::batch does not bypass the filter.
#[test]
fn inheritor_cannot_bypass_filter_via_utility_batch() {
	new_test_ext().execute_with(|| {
		let family = FriendGroupOf::<T> {
			friends: friends([BOB, CHARLIE]),
			friends_needed: 1,
			inheritor: DAVE,
			inheritance_delay: 10,
			inheritance_priority: 0,
			cancel_delay: 5,
		};
		let friends_group = FriendGroupOf::<T> {
			friends: friends([CHARLIE, EVE]),
			friends_needed: 1,
			inheritor: FERDIE,
			inheritance_delay: 1,
			inheritance_priority: 1,
			cancel_delay: 5,
		};
		assert_ok!(Recovery::set_friend_groups(signed(ALICE), vec![family, friends_group]));

		// Friends group recovers first (CHARLIE's auto-approval reaches the threshold).
		assert_ok!(Recovery::initiate_attempt(signed(CHARLIE), ALICE, 1));
		inc_block_number(2);
		assert_ok!(Recovery::finish_attempt(signed(EVE), ALICE, 1));
		assert_eq!(Recovery::inheritor(ALICE), Some(FERDIE));

		// Family initiates higher-priority attempt
		assert_ok!(Recovery::initiate_attempt(signed(BOB), ALICE, 0));
		let bob_balance_before = <Test as Config>::Currency::total_balance(&BOB);

		// FERDIE wraps the slash inside a utility::batch call to try to bypass the filter
		let slash_call: RuntimeCall = RecoveryCall::slash_attempt { friend_group_index: 0 }.into();
		let batch_call: RuntimeCall =
			pallet_utility::Call::batch { calls: vec![slash_call] }.into();
		assert_ok!(Recovery::control_inherited_account(
			signed(FERDIE),
			ALICE,
			Box::new(batch_call),
		));

		// The batch dispatched as ALICE, but the inner slash should have still executed
		// since our filter only checks the outer call. Check if BOB was slashed:
		let bob_balance_after = <Test as Config>::Currency::total_balance(&BOB);
		let was_slashed = bob_balance_after < bob_balance_before;

		if was_slashed {
			panic!(
				"BYPASS: recovery call filter was circumvented via utility::batch! \
				 BOB lost {} from security deposit slash.",
				bob_balance_before - bob_balance_after
			);
		}
	});
}
