### Title
Operator Malicious Beneficiary Blocks `distribute_internal`, Permanently Locking Staker APT — (`File: aptos-move/framework/aptos-framework/sources/staking_contract.move`)

---

### Summary

`staking_contract::set_beneficiary_for_operator` accepts any address as the new beneficiary with zero validation. `distribute_internal` then calls `aptos_account::deposit_coins<AptosCoin>(beneficiary, ...)` for every recipient in the distribution pool. If the beneficiary address has disabled direct coin transfers and lacks a legacy `CoinStore<AptosCoin>`, `deposit_coins` aborts, reverting the entire distribution and permanently blocking the staker from withdrawing their unlocked APT.

---

### Finding Description

`staking_contract::set_beneficiary_for_operator` stores any caller-supplied address as the operator's commission beneficiary: [1](#0-0) 

No check is performed to verify that `new_beneficiary` is registered for APT or can receive direct coin transfers.

`distribute_internal` iterates over every recipient in the distribution pool and, when the recipient is the operator, redirects the payment to `beneficiary_for_operator(operator)`: [2](#0-1) 

The payment is made via `aptos_account::deposit_coins<AptosCoin>`: [3](#0-2) 

The abort path is:
1. Account exists at `to` (so `create_account` is skipped).
2. `coin::is_account_registered<AptosCoin>(to)` returns **false** — post-FA-migration accounts created via `aptos_account::create_account` only get a primary fungible store via `register_apt`; they do **not** get a legacy `CoinStore<AptosCoin>`. [4](#0-3) 

3. `can_receive_direct_coin_transfers(to)` returns **false** because the operator previously called `set_allow_direct_coin_transfers(false)` on the beneficiary account. [5](#0-4) 

4. The `assert!` at line 124–127 fires → `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` → entire transaction reverts.

The vesting module already recognized this exact risk and added an explicit guard in `vesting::set_beneficiary`: [6](#0-5) 

`staking_contract::set_beneficiary_for_operator` has no equivalent guard.

---

### Impact Explanation

`distribute_internal` is called from `distribute`, `request_commission`, `unlock_stake`, `switch_operator`, and `update_commision`. A DoS on `distribute_internal` means:

- The staker **cannot withdraw** any unlocked or pending-inactive APT from the stake pool.
- The staker **cannot switch operators** (the call internally forces a distribution).
- The staker **cannot request commission** (same reason).
- All APT that has already been unlocked and is sitting in the stake pool as `inactive` stake is inaccessible.

The staker's APT is effectively held hostage. The operator has no on-chain incentive to restore a valid beneficiary. The only recovery path is for the operator to voluntarily call `set_beneficiary_for_operator` again with a valid address — which a malicious operator will not do.

---

### Likelihood Explanation

- **Unprivileged trigger**: Any operator can call `set_beneficiary_for_operator` at any time; no governance or admin approval is required.
- **Setup cost**: The attacker needs one additional account with `set_allow_direct_coin_transfers(false)` set. This costs a single transaction.
- **Timing**: The operator can set the malicious beneficiary at any point — even after the staker has already called `unlock_stake` and is waiting for the lockup to expire, maximizing the damage.
- **Motivation**: A malicious operator (e.g., one being replaced via `switch_operator`) has a clear incentive to block the staker's withdrawal.

---

### Recommendation

Add the same guard that `vesting::set_beneficiary` uses:

```move
public entry fun set_beneficiary_for_operator(
    operator: &signer, new_beneficiary: address
) acquires BeneficiaryForOperator {
    assert!(
        features::operator_beneficiary_change_enabled(),
        std::error::invalid_state(EOPERATOR_BENEFICIARY_CHANGE_NOT_SUPPORTED)
    );
+   // Ensure the beneficiary can receive APT so distribute_internal cannot be DoS'd.
+   aptos_account::assert_account_is_registered_for_apt(new_beneficiary);
    ...
}
```

This mirrors the explicit protection in `vesting::set_beneficiary` at line 923. [7](#0-6) 

---

### Proof of Concept

```
1. Operator creates a fresh account B (e.g., via aptos_account::create_account(B)).
   - B gets a primary fungible store for APT but NO legacy CoinStore<AptosCoin>.

2. Operator calls set_allow_direct_coin_transfers(false) from account B.
   - B now has DirectTransferConfig { allow_arbitrary_coin_transfers: false }.

3. Operator calls staking_contract::set_beneficiary_for_operator(operator_signer, B).
   - No validation; B is stored as the operator's beneficiary.

4. Staker calls unlock_stake(...) and waits for the lockup to expire.

5. Anyone calls staking_contract::distribute(staker, operator).
   - distribute_internal is entered.
   - The distribution pool contains the operator's commission share.
   - recipient = beneficiary_for_operator(operator) = B.
   - aptos_account::deposit_coins<AptosCoin>(B, commission_coins) is called.
   - coin::is_account_registered<AptosCoin>(B) == false  (no legacy CoinStore).
   - can_receive_direct_coin_transfers(B) == false  (explicitly disabled).
   - assert! fires → EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS.
   - Transaction reverts. Staker receives nothing.

6. All subsequent calls to distribute, request_commission, unlock_stake,
   switch_operator for this staker/operator pair revert identically.
   Staker's unlocked APT is permanently inaccessible.
```

    public entry fun set_beneficiary_for_operator(
        operator: &signer, new_beneficiary: address
    ) acquires BeneficiaryForOperator {
        assert!(
            features::operator_beneficiary_change_enabled(),
            std::error::invalid_state(EOPERATOR_BENEFICIARY_CHANGE_NOT_SUPPORTED)
        );
        // The beneficiay address of an operator is stored under the operator's address.
        // So, the operator does not need to be validated with respect to a staking pool.
        let operator_addr = signer::address_of(operator);
        let old_beneficiary = beneficiary_for_operator(operator_addr);
        if (exists<BeneficiaryForOperator>(operator_addr)) {
            borrow_global_mut<BeneficiaryForOperator>(operator_addr).beneficiary_for_operator =
                new_beneficiary;
        } else {
            move_to(
                operator,
                BeneficiaryForOperator { beneficiary_for_operator: new_beneficiary }
            );
        };

        emit(
            SetBeneficiaryForOperator {
                operator: operator_addr,
                old_beneficiary,
                new_beneficiary
            }
        );
    }
