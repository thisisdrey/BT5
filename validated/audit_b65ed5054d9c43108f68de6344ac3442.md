### Title
Unauthenticated `RecvError` packet allows remote attacker to force-teardown arbitrary tunnels - (File: outside.go)

### Summary
`RecvError` is a plaintext, unauthenticated control message type. `Interface.handleRecvError` accepts this message before any handshake, certificate, or AEAD/MAC verification and uses only a weak, spoofable consistency check to decide whether to trust it, then unconditionally tears down the referenced tunnel.

### Finding Description
Like the Balancer flash-loan callback (`receiveFlashLoan`) which trusted `originalCallData` based solely on `msg.sender == _balancerVault` and never validated that the encoded action/borrower actually corresponded to a legitimate, self-initiated flash loan, Nebula's `RecvError` handler trusts unauthenticated wire data (the 32-bit `RemoteIndex` in the cleartext header) and only performs a soft, easily-spoofed sanity check before mutating security-relevant state (tunnel teardown).

In `readOutsidePackets`, `RecvError` is dispatched before any decryption or cert check: [1](#0-0) 

`handleRecvError` then looks up the hostinfo purely by the cleartext `RemoteIndex` field (which travels unencrypted in every packet header and is thus observable by anyone who can see traffic on the path, and is only a 32-bit value) and validates the sender only by comparing the observed UDP source address to the currently stored remote address: [2](#0-1) 

The check `hr.IsValid() && hr != addr` is the only "originalCallData" validation performed. There is no cryptographic authentication (no MAC, no signature, no proof of possession of the session keys) tying the `RecvError` message to the actual remote peer. It only rejects the packet if the hostinfo already has a *known* remote address that mismatches — an attacker who can spoof the UDP source `IP:port` (trivial over UDP with no return-routability check, or simply not yet having recorded `hr` when the field is still zero/roaming has just occurred) or who is on-path and can inject packets, can trigger `f.closeTunnel(hostinfo)` and `f.handshakeManager.DeleteHostInfo(hostinfo)` for a targeted `RemoteIndex`.

The default `acceptRecvErrorConfig` is defined via `recvErrorConfig` with `recvErrorAlways` as the zero value: [3](#0-2) 

This means, absent explicit hardening configuration, any packet type-tagged as `RecvError` reaching the socket is processed and can act on any guessed/observed `RemoteIndex`.

### Impact Explanation
An attacker with no CA-signed certificate and no established handshake can forge `RecvError` packets to remotely tear down active Nebula tunnels between two legitimate, authenticated peers (remote state poisoning / denial-of-service), forcing repeated re-handshakes and disrupting connectivity. This mirrors the C4 finding's core issue — a message whose payload/content is not validated against the true origin of the action being requested, enabling an unauthorized party to trigger sensitive state transitions (`_supplyBorrow`/`_repayAndWithdraw` in the original; `closeTunnel`/`DeleteHostInfo` here).

### Likelihood Explanation
Likelihood is limited by the need to either be on-path (able to spoof/observe UDP traffic between the two endpoints) or to guess a valid 32-bit `RemoteIndex` associated with an active tunnel; it is not exploitable by a purely off-path, blind remote attacker with certainty. However, `RemoteIndex` is transmitted in cleartext on every data packet, so any passive on-path observer (a very realistic threat model for UDP-based overlay networks traversing untrusted networks/NATs) can trivially harvest valid indexes and forge the teardown, without needing a CA-signed certificate.

### Recommendation
Do not act on `RecvError` content that is not cryptographically bound to an authenticated session:
- Require `RecvError` messages to carry a MAC/token derived from session key material known only to the two tunnel endpoints (e.g., HMAC over `RemoteIndex` using the session's sending key), or
- At minimum, tighten the existing spoofing check so it does not fail-open when `hr` is invalid/unset, and rate-limit/log repeated `RecvError` triggers per source before tearing down state, and
- Default `acceptRecvErrorConfig` to a stricter mode (e.g., `never`/`private`) rather than `always`.

### Proof of Concept
1. Establish two Nebula nodes `A` and `B` with a valid handshake/tunnel.
2. As an on-path attacker, capture one packet from `A`→`B` and read the cleartext `RemoteIndex` field from the header (no decryption needed).
3. Craft a `RecvError` header packet (`header.Encode(..., header.RecvError, 0, capturedIndex, 0)`) and send it to `B`, spoofing the source `IP:port` to match `A`'s current remote address (or send before `B` has ever recorded `hr` for that index, e.g., right after a roam).
4. `B.handleRecvError` finds the hostinfo via `QueryReverseIndex`, the `hr != addr` check passes (spoofed/matching or `hr` invalid), and `closeTunnel`/`DeleteHostInfo` are invoked, tearing down the legitimate tunnel — reproducing the "unauthenticated, unvalidated data drives privileged state change" pattern from the referenced report.

Note: I was unable to fully verify how `acceptRecvErrorConfig`/`sendRecvErrorConfig` are populated from the YAML config (default value wiring in the config loader) within the indexed context — the grep for `accept_recv_error`/`send_recv_error` config keys only matched `interface.go`, `outside.go`, and `CHANGELOG.md`, not a config-parsing file, so the effective default in a real deployment could not be conclusively confirmed from the available index. This may need direct verification in a full checkout.

```go
func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
```

```go
type recvErrorConfig uint8

const (
	recvErrorAlways recvErrorConfig = iota
	recvErrorNever
	recvErrorPrivate
)

func (s recvErrorConfig) ShouldRecvError(endpoint netip.AddrPort) bool {
	switch s {
	case recvErrorPrivate:
		return endpoint.Addr().IsPrivate()
	case recvErrorAlways:
		return true
	case recvErrorNever:
		return false
	default:
		panic(fmt.Errorf("invalid recvErrorConfig value: %d", s))
	}
}
```
