### Title
Unauthenticated remote DoS via `/shutdown` endpoint in `SignerEventReceiver` - (File: libsigner/src/events.rs)

### Summary
`SignerEventReceiver::next_event` handles `POST /shutdown` by unconditionally setting `stop_signal` to `true` and returning `EventError::Terminated`, with no check on the request's origin, credentials, or any shared secret. Any TCP peer that can reach the signer's event-receiver bind address can send this single crafted HTTP request to permanently halt the signer's event ingestion loop.

### Finding Description
The intended invariant is that only the local Stacks node (the legitimate event source) can request termination of the receiver, since termination is meant to be triggered internally via `SignerStopSignaler::send()` [1](#0-0) . However, the HTTP handler in `EventReceiver::next_event` dispatches purely on `request.url()` and `request.method()`, with the `/shutdown` branch performing no authentication whatsoever: [2](#0-1) 
Every other authenticated concept present in the system (StackerDB chunk signatures, slot ownership, etc.) is irrelevant here — this endpoint is served directly by the tiny_http-based `HttpServer` bound in `bind()` [3](#0-2) , which accepts any TCP connection and treats any well-formed HTTP POST to `/shutdown` as authoritative. There is no header, secret, or source-IP check anywhere in this file or in `HttpServer` construction that would distinguish the real node from an arbitrary attacker.

The exploit is trivial: an attacker sends
```
POST /shutdown HTTP/1.1\r\nHost: <addr>\r\nConnection: close\r\nContent-Length: <n>\r\nContent-Type: text/plain\r\n\r\n<body>
```
to the signer's bound event-receiver address. This is the exact same request format `SignerStopSignaler::send()` constructs for internal use [4](#0-3) , but any TCP peer can synthesize it. Once `stop_signal.store(true, Ordering::SeqCst)` executes, `next_event` returns `Err(EventError::Terminated)` on this and every subsequent call, causing `EventReceiver::main_loop` to break immediately [5](#0-4) . This permanently stops the signer's ingestion of `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, and `/new_block` events pushed by the node, silently disabling signer duties (block validation responses, signature broadcasting) without crashing the process or emitting an alarming error.

### Impact Explanation
A single unauthenticated POST permanently disables the signer's event-receiver thread, cutting the signer off from all node-pushed events (StackerDB chunks, burn blocks, new blocks, proposal responses). This is a remote, unauthenticated, single-message DoS against a signer node — matching the "Critical: remote crash/unauthenticated DoS from few messages" category. It is fully repeatable (nothing resets `stop_signal` once set) and requires no privileged role, secret, or prior state.

### Likelihood Explanation
The only precondition is TCP reachability to the signer's configured event-receiver bind address (`config.endpoint` in `stacks-signer`) [6](#0-5) . The codebase itself documents that this interface is expected to be reachable at least from the associated Stacks node and warns operators about exposure risk: "It's important to exercise caution if you are communicating with an external node... this could potentially expose sensitive data or functionalities to security risks if additional proper security checks are not integrated" [7](#0-6) . Any network path to that port (misconfigured binding to non-loopback, firewall misconfiguration, or a shared/subnet deployment as the warning itself alludes to) is sufficient; the attacker cost is a single raw HTTP POST.

### Recommendation
Require that `/shutdown` requests originate from the same process/node relationship — e.g., bind the event-receiver only to `127.0.0.1` by default and reject non-loopback shutdown requests at the TCP layer, and/or require a shared secret (e.g., a bearer token configured alongside the node's event-observer endpoint) that must be present and validated in the `/shutdown` request before setting `stop_signal`. At minimum, validate the peer's socket address against an allow-list of the configured node address before honoring `/shutdown`.

```rust
#[test]
fn test_unauthenticated_shutdown() {
    let mut ev = SignerEventReceiver::<SignerMessage>::new(false);
    let endpoint: SocketAddr = "127.0.0.1:32000".parse().unwrap();
    ev.bind(endpoint).unwrap();

    // Attacker: plain TCP peer, not the node, no secret
    let mut sock = TcpStream::connect(endpoint).unwrap();
    let body = "attacker shutdown".to_string();
    let req = format!(
        "POST /shutdown HTTP/1.1\r\nHost: {endpoint}\r\nConnection: close\r\nContent-Length: {}\r\nContent-Type: text/plain\r\n\r\n{}",
        body.len(), body
    );
    sock.write_all(req.as_bytes()).unwrap();
    sock.flush().unwrap();

    // Assert the receiver is terminated as a result of the unauthenticated request
    let res = ev.next_event();
    assert!(matches!(res, Err(EventError::Terminated)));
    assert!(ev.is_stopped());
}
```
