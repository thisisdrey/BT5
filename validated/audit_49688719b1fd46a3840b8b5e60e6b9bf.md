### Title
`vesting::withdraw_stake` uses `coin::balance` (CoinStore + FA store) but `coin::withdraw` only drains the FA primary store, permanently freezing vested APT - (`aptos-move/framework/aptos-framework/sources/vesting.move`)

---

### Summary

`vesting::withdraw_stake` reads the vesting contract account's total APT balance with `coin::balance<AptosCoin>`, which sums the legacy `CoinStore<AptosCoin>` balance **and** the FA primary-store balance. It then calls `coin::withdraw<AptosCoin>` with that total. After the coin-to-FA migration, `coin::withdraw` was rewritten to pull exclusively from the FA primary store via `primary_fungible_store::withdraw`. Any APT that remains in the old `CoinStore` is invisible to `coin::withdraw`, so the call aborts with `EINSUFFICIENT_BALANCE` whenever the two balances differ. This permanently wedges every public entry point that calls `withdraw_stake` — `distribute`, `admin_withdraw`, and (transitively) `terminate_vesting_contract` — freezing all vested APT inside the contract.

---

### Finding Description

**Root cause — wrong balance source**

`withdraw_stake` in `vesting.move`:

```move
fun withdraw_stake(vesting_contract: &VestingContract, contract_address: address): Coin<AptosCoin> {
    staking_contract::distribute(contract_address, vesting_contract.staking.operator);
    let withdrawn_coins = coin::balance<AptosCoin>(contract_address);   // ← CoinStore + FA store
    let contract_signer = &get_vesting_account_signer_internal(vesting_contract);
    coin::withdraw<AptosCoin>(contract_signer, withdrawn_coins)          // ← FA store only
}
``` [1](#0-0) 

`coin::balance<AptosCoin>` returns the **sum** of the legacy `CoinStore` balance and the FA primary-store balance:

```move
public fun balance<CoinType>(owner: address): u64 acquires CoinConversionMap, CoinStore {
    let paired_metadata = paired_metadata<CoinType>();
    coin_balance<CoinType>(owner)                          // CoinStore<AptosCoin>.coin.value
        + if (paired_metadata.is_some()) {
            primary_fungible_store::balance(owner, paired_metadata.extract())  // FA store
        } else { 0 }
}
``` [2](#0-1) 

After the migration, `coin::withdraw` was rewritten to pull **only** from the FA primary store:

```move
public fun withdraw<CoinType>(
    account: &signer, amount: u64
): Coin<CoinType> acquires CoinConversionMap, CoinInfo, PairedCoinType {
    let fa = primary_fungible_store::withdraw(
        account, ensure_paired_metadata<CoinType>(), amount
    );
    fungible_asset_to_coin(fa)
}
``` [3](#0-2) 

`primary_fungible_store::withdraw` calls `dispatchable_fungible_asset::withdraw`, which calls `fungible_asset::unchecked_withdraw` — touching only the FA store object, never the `CoinStore` resource. [4](#0-3) 

**How the CoinStore gets a non-zero balance**

Every vesting contract account is created with `coin::register<AptosCoin>`, which allocates a `CoinStore<AptosCoin>`. [5](#0-4) 

Before the coin-to-FA migration, `staking_contract::distribute_internal` called `aptos_account::deposit_coins` → `coin::deposit` → deposited into the `CoinStore`. After migration, `coin::deposit` was rewritten to route through `coin_to_fungible_asset` → `primary_fungible_store::deposit`, so new rewards land in the FA store. [6](#0-5) 

Any vesting contract that received staking rewards **before** the migration therefore holds:
- `CoinStore<AptosCoin>.coin.value = X` (pre-migration rewards)
- FA primary-store balance = `Y` (post-migration rewards)

`coin::balance` returns `X + Y`; `coin::withdraw(X + Y)` tries to pull `X + Y` from the FA store (which holds only `Y`) → `EINSUFFICIENT_BALANCE`.

**Affected entry points (all call `withdraw_stake`)**

| Entry function | Caller restriction |
|---|---|
| `distribute(contract_address)` | none — fully unprivileged |
| `admin_withdraw(admin, contract_address)` | admin signer |
| `terminate_vesting_contract(admin, contract_address)` | admin signer (calls `distribute` internally) | [7](#0-6) [8](#0-7) 

The `CoinStore` balance is permanently inaccessible: `coin::migrate_to_fungible_store` requires a signer for the vesting contract account, which is only obtainable through `get_vesting_account_signer_internal` — a private helper never called for migration purposes. [9](#0-8) 

---

### Impact Explanation

Any vesting contract account that accumulated APT in its `CoinStore` before the coin-to-FA migration will have `coin::balance > primary_fungible_store::balance`. Every subsequent call to `distribute()` aborts. Shareholders can never receive their vested APT; the coins in the `CoinStore` are permanently frozen inside the contract with no recovery path. This is a direct theft-equivalent (permanent freezing) of vesting balances, which is within the Aptos bounty scope.

---

### Likelihood Explanation

The Aptos coin-to-FA migration is a live mainnet event. Vesting contracts are long-lived (multi-year schedules). Any contract that was active and earning staking rewards before the migration has a non-zero `CoinStore` balance. The trigger (`distribute`) is a permissionless public entry function, so the failure is observable by any caller and cannot be worked around by the admin.

---

### Recommendation

Replace `coin::balance` with the FA-only balance in `withdraw_stake`, matching what `coin::withdraw` actually drains:

```move
fun withdraw_stake(vesting_contract: &VestingContract, contract_address: address): Coin<AptosCoin> {
    staking_contract::distribute(contract_address, vesting_contract.staking.operator);
    // Migrate any legacy CoinStore balance into the FA primary store first.
    let contract_signer = &get_vesting_account_signer_internal(vesting_contract);
    coin::migrate_to_fungible_store<AptosCoin>(contract_signer);
    // Now both old and new balances are in the FA store; coin::withdraw will see them all.
    let withdrawn_coins = primary_fungible_store::balance(
        contract_address,
        coin::ensure_paired_metadata<AptosCoin>()
    );
    coin::withdraw<AptosCoin>(contract_signer, withdrawn_coins)
}
```

Alternatively, call `coin::migrate_to_fungible_store<AptosCoin>` once during contract creation or at the start of `distribute` so the `CoinStore` is always empty before `coin::balance` is read.

---

### Proof of Concept

1. Create a vesting contract before the coin-to-FA migration. The contract account has `CoinStore<AptosCoin>` with balance `X > 0` from early staking rewards.
2. The migration activates. Subsequent staking rewards are deposited to the FA primary store; balance = `Y`.
3. Any account calls `vesting::distribute(contract_address)`.
4. `withdraw_stake` executes: `coin::balance` returns `X + Y`; `coin::withdraw(X + Y)` calls `primary_fungible_store::withdraw(contract_signer, apt_metadata, X + Y)`.
5. The FA store holds only `Y`; `unchecked_withdraw_with_no_events` asserts `store.balance >= X + Y` → false → aborts with `EINSUFFICIENT_BALANCE(0x10004)`.
6. `distribute` is permanently broken. Shareholders receive nothing. `X` APT is frozen in the `CoinStore` with no recovery path.
