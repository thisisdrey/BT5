### Title
`ReraiseETHCrowdfund`-style front-run state hijack via replayed handshake packet — `SetRemoteIfPreferred` accepts an attacker-controlled remote on `ErrAlreadySeen` - ([File: handshake_manager.go], [File: hostmap.go])

### Summary
`ReraiseETHCrowdfund.claim` let anyone attach pending state (voting power) to an *existing* asset by supplying attacker-controlled parameters that were not checked against the true owner/sender. Nebula has a structurally identical pattern in its handshake-replay path: `CheckAndComplete` in `handshake_manager.go` detects a duplicate stage-1 handshake purely by comparing raw packet bytes, with no binding to who actually sent it, and then `handleCheckAndCompleteError`'s `ErrAlreadySeen` branch calls `existing.SetRemoteIfPreferred(f.hostMap, via)` using the `via` (source address) of *whoever delivered the duplicate bytes*. An attacker who never completed a handshake and holds no CA-signed certificate of their own can capture one legitimate stage-1 packet and replay it from a spoofed source address to redirect where an already-established tunnel's traffic is sent — the same "attach my forged state to someone else's existing entry" primitive as the original finding, just applied to a hostinfo's remote address instead of a party card's voting power.

### Finding Description
`beginHandshake` builds a brand-new responder `Machine` for every inbound stage-1 packet and runs it through `machine.ProcessPacket`, then calls `CheckAndComplete`: [1](#0-0) 

The "already seen" detection is a pure byte comparison of the handshake payload against what's stored on the existing hostinfo — it does not check whether the *sender* of the duplicate is the same peer, since UDP source addresses are not cryptographically bound to anything at this layer: [2](#0-1) 

When that match fires, `handleCheckAndCompleteError` treats the duplicate as legitimate retransmission and immediately calls `SetRemoteIfPreferred` with the `via` of the packet that was just received — i.e., the replayer's address, not necessarily the real peer's: [3](#0-2) 

`SetRemoteIfPreferred` will overwrite the hostinfo's `remote` if the *new* source address falls in a preferred (e.g. local/LAN) CIDR while the *current* remote does not: [4](#0-3) 

Because a byte-identical stage-1 packet decrypts and cert-validates deterministically on a fresh `Machine` (the noise ephemeral key material and embedded certificate are unchanged), an attacker with no certificate of their own can simply capture one genuine stage-1 packet in flight and replay it with a forged/preferred-range source address to have the responder silently repoint the live tunnel's remote endpoint — exactly the "claim on someone else's behalf, no ownership check" pattern from the crowdfund bug, but here landing on `HostInfo.remote` (a "hostmap/lighthouse/relay address trust" primitive) rather than voting power.

### Impact Explanation
Successfully redirecting `HostInfo.remote` causes the responder to send subsequent encrypted tunnel traffic to the attacker-chosen address instead of the real peer, which is a form of remote state poisoning that can enable traffic redirection/interception or at minimum reliably sever the legitimate tunnel (denial of service) — without the attacker ever presenting a CA-signed certificate or completing an authenticated handshake themselves. This matches the accepted "remote state poisoning" / "traffic redirection" impact category.

### Likelihood Explanation
The attacker only needs to observe one stage-1 handshake packet on the wire/LAN (no decryption needed, it's the unencrypted first message) and be able to source-spoof or otherwise deliver it from an address inside the target's configured `preferred_ranges` (commonly private/LAN CIDRs, which are typically not filtered against spoofing on a local segment). No certificate, PSK, or successful handshake completion by the attacker is required — only a byte-for-byte replay, which the `bytes.Equal` check in `CheckAndComplete` explicitly does not disambiguate by sender.

### Recommendation
Bind the `ErrAlreadySeen` fast-path to the original packet's source context: only call `SetRemoteIfPreferred`/resend the cached stage-2 response when the replay arrives from the same transport path (or at least don't treat an arbitrary new source address for an old duplicate as a roam candidate). Alternatively, gate `SetRemoteIfPreferred` on this path so it never processes `via` from an unauthenticated duplicate-detection branch, mirroring the crowdfund fix's principle of requiring the actor performing the sensitive action to be the verified owner of the state being modified.

### Proof of Concept
1. Peer A initiates a handshake to Peer B over a non-preferred (e.g. public) address; B completes the responder side and stores `HandshakePacket[handshakePacketStage0]`.
2. Attacker C, without any nebula certificate, captures A's stage-1 packet bytes on the wire.
3. C replays the identical bytes to B but spoofs the UDP source address to one inside B's `preferred_ranges` (e.g. a LAN CIDR).
4. B's `beginHandshake` → `CheckAndComplete` finds a byte-identical duplicate (`ErrAlreadySeen`), calls `handleCheckAndCompleteError`, which calls `existing.SetRemoteIfPreferred(f.hostMap, via)` with C's spoofed address.
5. Since the spoofed address is in `preferred_ranges` and the current remote is not, `SetRemoteIfPreferred` overwrites `HostInfo.remote` to C's address; B now sends subsequent tunnel traffic there instead of to A. [5](#0-4) [6](#0-5)

// SetRemoteIfPreferred returns true if the remote was changed. The lastRoam
// time on the HostInfo will also be updated.
func (i *HostInfo) SetRemoteIfPreferred(hm *HostMap, via ViaSender) bool {
	if via.IsRelayed {
		return false
	}

	currentRemote := i.GetRemote()
	if !currentRemote.IsValid() {
		i.SetRemote(via.UdpAddr)
		return true
	}

	// NOTE: We do this loop here instead of calling `isPreferred` in
	// remote_list.go so that we only have to loop over preferredRanges once.
	newIsPreferred := false
	for _, l := range hm.GetPreferredRanges() {
		// return early if we are already on a preferred remote
		if l.Contains(currentRemote.Addr()) {
			return false
		}

		if l.Contains(via.UdpAddr.Addr()) {
			newIsPreferred = true
		}
	}

	if newIsPreferred {
		// Consider this a roaming event
		i.lastRoam = time.Now()
		i.lastRoamRemote = currentRemote

		i.SetRemote(via.UdpAddr)

		return true
	}

	return false
}
