### Title
Swap fee computed per-call with half-up rounding lets callers evade fees via dust-sized swaps - ([File: contracts/Pool.sol](contracts/Pool.sol))

### Summary
`Pool.swap` charges the swap fee on each individual call via `quoteSwapOut`, which computes `_fee = _amountOut.wadMul(_swapFee)` using half-up `wadMul` in `WadRayMath`. Because the fee is computed per operation rather than accrued and settled once, every call rounds independently, and for dust-sized outputs the fee rounds to `0`. An unprivileged user can split any large swap into many small swaps and pay materially less (or zero) protocol fee — the same per-fill fee-rounding bug class as the Dinari `BuyOrderIssuer`/`SellOrderProcessor` issue, where computing the percentage fee per fill instead of once at order close leaked protocol revenue.

### Finding Description
- `Pool.swap` burns `amountIn_` of the input synth and mints `_amountOut` of the output synth, minting `_fee` to `poolRegistry.feeCollector()` only `if (_fee > 0)` [1](#0-0) .
- `quoteSwapOut` computes the fee as `_fee = _amountOut.wadMul(_swapFee)` on the oracle-quoted output for that call only [2](#0-1) .
- `WadRayMath.wadMul` computes `(a * b + HALF_WAD) / WAD`, i.e., rounds half-up [3](#0-2) . Whenever `_amountOut * _swapFee < 0.5e18` the fee rounds to `0`. E.g., with a 0.25% fee (`_swapFee = 0.0025e18`), any `_amountOut < 200` wei yields `_fee == 0`; more generally, the per-call rounding error is up to ~0.5 wei in the caller's favor whenever the caller picks amounts where the product falls below the half-wad boundary.
- There is no minimum swap amount, no accumulated fee state, and no deferred settlement: the only guards are `whenNotShutdown`, `nonReentrant`, `isSwapActive`, and `amountIn_ > 0` [4](#0-3) . The rounding error therefore compounds linearly with the number of calls, exactly like the per-fill `collection = getPercentageFeeForOrder(receivedAmount)` accumulation in the Dinari report.
- The identical pattern exists in the other per-call fee quotes (`quoteSwapIn` line 487-491, `quoteLiquidateOut` line 464-466, `quoteIssueIn`/`quoteDeposit`/`quoteWithdraw` fee paths in `DebtToken.sol`/`DepositToken.sol`), all of which round once per user-initiated call [5](#0-4) .

### Impact Explanation
Every `swap` whose `_amountOut * swapFee` product falls below the half-up threshold pays zero fee, and mid-size swaps can be split so the aggregate fee is strictly less than the fee on the unsplit amount. Since `swap` is oracle-priced (input is burned, output minted at oracle rate), a caller iterating dust swaps converts synth↔synth at par value while systematically underpaying or fully evading the configured `swapFees`, leaking protocol revenue to the `feeCollector`. The loss is bounded by ~0.5 wei per call, so extraction requires many calls and is limited by gas costs — making this a real but low-magnitude revenue leak rather than direct theft, consistent with the Medium severity of the analogous Dinari finding.

### Likelihood Explanation
Reachable by any EOA holding a synth balance: call `Pool.swap(synthIn, synthOut, dustAmount)` repeatedly. No privileged role, oracle manipulation, or external dependency is needed; the only prerequisites are `isSwapActive == true` (default-initialized at line 180) and a non-zero `swapFee` for the pair. Whether profitable in practice depends on gas price vs. per-call rounding gain, so likelihood of meaningful loss is low on high-fee L1 but higher on L2 deployments (Optimism/Base/Swell deployments exist in `deployments/`).

### Recommendation
Compute fees so rounding cannot be gamed per call: enforce a minimum `amountIn_`/`amountOut` that guarantees `_fee >= 1` wei, or round the fee up (ceiling division in the wad mul) so any nonzero fee-bearing swap always contributes to the fee collector, or accrue fee obligations in a higher-precision accumulator and settle periodically, matching the Dinari recommendation of "calculate the fee once instead of at each fill".

### Proof of Concept
Hardhat/Foundry sketch against a deployed-pool fork:

```solidity
// Setup: swapFee(synthIn, synthOut) = 0.0025e18, oracle quotes 1:1 (same USD price)
uint256 dust = 199; // amountOut * fee < 0.5e18  =>  wadMul rounds to 0
for (uint256 i; i < N; ++i) {
    pool.swap(synthIn, synthOut, dust);   // _fee == 0 each call
}
// Compare: pool.swap(synthIn, synthOut, dust * N) would pay _fee > 0.
// Assert feeCollector received 0 over N dust swaps vs > 0 for one bulk swap.
```

Caveat: I could not fully verify `DepositToken`/`DebtToken` fee quote internals within available iterations, but the `Pool.swap`/`quoteSwapOut` path shown above is sufficient to stand the analog on its own.

    function quoteSwapOut(
        ISyntheticToken syntheticTokenIn_,
        ISyntheticToken syntheticTokenOut_,
        uint256 amountIn_
    ) public view override returns (uint256 _amountOut, uint256 _fee) {
        _amountOut = _poolRegistry.masterOracle().quote(
            address(syntheticTokenIn_),
            address(syntheticTokenOut_),
            amountIn_
        );

        uint256 _swapFee = feeProvider.swapFees(address(syntheticTokenIn_), address(syntheticTokenOut_));

        if (_swapFee > 0) {
            _fee = _amountOut.wadMul(_swapFee);
            _amountOut -= _fee;
        }
    }

        if (a == 0 || b == 0) {
