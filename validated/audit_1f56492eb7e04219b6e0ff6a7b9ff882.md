### Title
Unsynchronized `Interface.firewall` pointer swap during SIGHUP reload creates a data race allowing stale (looser) firewall rules to authorize packets after a rule tightening — (File: `interface.go`, `inside.go`, `outside.go`)

### Summary
`Interface.firewall` is a plain `*Firewall` field (not an `atomic.Pointer`, not guarded by a mutex on the read side) that is written by `reloadFirewall()` on the config-reload goroutine and concurrently read by every packet-processing goroutine (`listenIn`, `listenOut`, `handleOutsideMessagePacket`, `sendMessageNow`). This is the same class of bug as the reported ERC20 `approve()`/`transferFrom()` front‑run: a piece of "permission state" is overwritten in place while other execution contexts still observe/act on the value being replaced, and Go gives no atomicity guarantee for a plain pointer write racing with plain pointer reads across goroutines.

### Finding Description
`reloadFirewall()` builds a brand-new `*Firewall` (`fw`) from the reloaded config, transfers the conntrack table from the old firewall, and then does a bare assignment: [1](#0-0) 

```go
fw, err := NewFirewallFromConfig(f.l, cs, c)
...
oldFw := f.firewall
conntrack := oldFw.Conntrack
conntrack.Lock()
defer conntrack.Unlock()

fw.rulesVersion = oldFw.rulesVersion + 1
...
f.firewall = fw          // <-- plain, unsynchronized write

oldFw.Destroy()
```

This runs on the config-reload goroutine (triggered by SIGHUP/`ReloadConfig`), while the data-plane goroutines read `f.firewall` with no lock at all, both for outbound traffic and inbound traffic: [2](#0-1) [3](#0-2) [4](#0-3) 

`Interface.firewall` is declared as a bare pointer field with no `atomic.Pointer` wrapper, unlike other mutable fields in the same struct (`disconnectInvalid`, `closed`, `fatalErr`, etc., which are explicitly `atomic.*`): [5](#0-4) 

Because the write `f.firewall = fw` and the reads in `Drop()`-calling code are unsynchronized, this is a data race per the Go memory model: readers on other cores are not guaranteed to observe the new pointer promptly, and in principle (and definitely under `-race`) this is undefined behavior. In practice on most current architectures a pointer write may appear atomic, but the Go spec makes no such guarantee, and more importantly the *rules themselves* referenced through the new `Firewall` object (`InRules`, `OutRules`, `unsafeNetworks`, `routableNetworks`) can be read without a happens-before edge relative to `f.firewall`'s publication, so a reader goroutine could observe the new `firewall` pointer while other unsynchronized fields inside it are not yet fully visible, or continue using the old, more permissive `*Firewall` object well past the moment the operator believed the tightened ruleset was in effect.

This mirrors the analog vulnerability class precisely: the "allowance" (here, the currently effective firewall rule set/permission state) is being overwritten by one actor (config reload) while another actor's in-flight operation (a peer's packet being evaluated in `Drop()`) is concurrently reading the pre-overwrite state, so the old, more permissive rules can still be exercised by an external, unauthenticated network peer during the race window, exactly as Bob exploits the gap between Alice's two `approve()` calls.

### Impact Explanation
An operator tightening firewall rules via SIGHUP (e.g., removing a previously allowed group/CIDR/port to cut off a compromised or no-longer-trusted peer) has no guarantee that the tightened rule takes effect atomically with respect to the live packet-processing goroutines. During the reload race window, packets from the attacker can still be evaluated against `oldFw` (the stale, more permissive ruleset) because the currently executing `Drop()` call already captured the old firewall pointer before the swap, and — because there's no synchronization at all — worst case a torn/stale read of `f.firewall` could persist longer than expected on some platforms/compilers. The net effect is a remote-attacker-reachable firewall bypass window: traffic that the administrator intended to be blocked by the new rules can still be admitted and even get durably conntracked (`addConn`) under the old `rulesVersion`, at which point `inConns()`'s lazy re-validation logic is the only backstop that determines whether the connection survives future evaluation.

### Likelihood Explanation
Every SIGHUP/config reload that changes `firewall.*` triggers this path (`RegisterReloadCallback(f.reloadFirewall)`), and reloads happen routinely in production (config management, cert rotation via `pki.disconnect_invalid`, dynamic security tightening). Any peer that is already able to send traffic to the node (i.e., has a live or attempted tunnel) is a potential racer; no special privileges beyond normal network reachability are required to attempt to land packets in the narrow race window around a reload.

### Recommendation
Publish `f.firewall` with proper synchronization so that all readers get a happens-before-consistent view of the swap and of the `Firewall` object's fields:
- Change `Interface.firewall` to `atomic.Pointer[Firewall]` and use `Load()`/`Store()` for all reads/writes (`inside.go`, `outside.go`, `interface.go`), mirroring the pattern already used for `disconnectInvalid`, `closed`, and `fatalErr`.
- Ensure the new `*Firewall` object is fully constructed (including `Conntrack` assignment and `rulesVersion` bump) before it is published via `Store()`, so no reader can observe a partially-initialized firewall.
- Consider treating `oldFw.Conntrack` lock acquisition as the synchronization boundary that also protects the publish of `fw`, so that `Drop()` invocations that raced with the reload deterministically use one consistent rule set version rather than a torn pointer value.

### Proof of Concept
1. Start a Nebula node with a permissive `firewall.inbound` rule (e.g., allow group `any`).
2. Have an external, unauthenticated-by-cert-tightening peer establish a tunnel and begin sending a continuous stream of packets that match only the *current* permissive rule.
3. Concurrently trigger a config reload (SIGHUP or `config.ReloadConfig`) that removes/tightens the inbound rule so this peer's traffic should be dropped going forward (`reloadFirewall` → `f.firewall = fw`).
4. Because `f.firewall` is read without synchronization from `listenIn`/`listenOut`/`handleOutsideMessagePacket` (`inside.go:74`, `outside.go:502`) concurrently with the unguarded write in `interface.go:426`, some in-flight `Drop()` calls will execute against `oldFw` even after the swap is logically "complete" from the operator's perspective, and any packet processed in that window that matches the old rule set will be admitted and get `addConn`'d, extending the effective window of unauthorized access via the conntrack/`rulesVersion` reconciliation logic in `inConns()` (`firewall.go:505-578`).
5. Run the existing reload/firewall tests under `go test -race ./...`; the field access pattern for `f.firewall` should be flagged as a race by the Go race detector, confirming the lack of synchronization described above. [6](#0-5) [2](#0-1) [3](#0-2)

```go
func (f *Interface) reloadFirewall(c *config.C) {
	cs := f.pki.getCertState()
	curCert := cs.getCertificate(cert.Version2)
	if curCert == nil {
		curCert = cs.getCertificate(cert.Version1)
	}

	// The firewall builds its routableNetworks set from the certificate's UnsafeNetworks at construction.
	// Check to see if that set has changed, and if so, rebuild the firewall.
	certUnsafeChanged := curCert != nil && !slices.Equal(curCert.UnsafeNetworks(), f.firewall.unsafeNetworks)

	if !c.HasChanged("firewall") && !certUnsafeChanged {
		f.l.Debug("No firewall config change detected")
		return
	}

	fw, err := NewFirewallFromConfig(f.l, cs, c)
	if err != nil {
		f.l.Error("Error while creating firewall during reload", "error", err)
		return
	}

	oldFw := f.firewall
	conntrack := oldFw.Conntrack
	conntrack.Lock()
	defer conntrack.Unlock()

	fw.rulesVersion = oldFw.rulesVersion + 1
	// If rulesVersion is back to zero, we have wrapped all the way around. Be
	// safe and just reset conntrack in this case.
	if fw.rulesVersion == 0 {
		f.l.Warn("firewall rulesVersion has overflowed, resetting conntrack",
			"firewallHashes", fw.GetRuleHashes(),
			"oldFirewallHashes", oldFw.GetRuleHashes(),
			"rulesVersion", fw.rulesVersion,
		)
	} else {
		fw.Conntrack = conntrack
	}

	f.firewall = fw

	oldFw.Destroy()
```
