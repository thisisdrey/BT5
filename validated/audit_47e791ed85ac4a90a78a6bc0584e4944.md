### Title
Pool synthetic-token swaps do not enforce a caller-specified minimum output - (`contracts/Pool.sol`)

### Summary
`Pool.swap` allows a user to burn an exact amount of one synthetic token, but provides no `amountOutMin` or equivalent execution-price constraint for the synthetic token minted in return. The received amount is entirely determined by the oracle quote and swap fee at execution time, so the transaction can succeed even when the output is materially lower than the amount quoted when the user submitted it. [1](#0-0) [2](#0-1) 

### Finding Description
The public `Pool.swap` function accepts only `syntheticTokenIn_`, `syntheticTokenOut_`, and `amountIn_`. [3](#0-2) 

After burning the caller's input tokens, it calls `quoteSwapOut` and immediately mints whatever amount the current oracle and fee configuration return, without comparing that amount against a caller-supplied floor. [4](#0-3) 

`quoteSwapOut` calculates output from `masterOracle().quote(...)` and then subtracts the configured swap fee. [2](#0-1) 

Neither the interface nor the implementation exposes an `amountOutMin`, deadline, or other execution-time bound for this operation. [5](#0-4) [3](#0-2) 

### Impact Explanation
A swap user can receive less `syntheticTokenOut_` than expected if the oracle quote or fee result changes between transaction construction and execution. [6](#0-5) 

Because the input token is burned before the quote-derived output is minted, the protocol treats the transaction as successful regardless of how unfavorable the resulting conversion is to the user. [4](#0-3) 

This produces direct economic loss to the swap caller, with no way to bound the loss at execution time. [5](#0-4) 

### Likelihood Explanation
The vulnerable function is public whenever `isSwapActive` is enabled and requires no privileged role beyond holding a registered synthetic token. [7](#0-6) 

The only meaningful checks are nonzero input, sufficient balance, registered synthetic tokens, shutdown status, and reentrancy protection; none constrains the final amount received. [8](#0-7) 

The issue is exploitable through ordinary transaction ordering whenever the configured oracle quote changes before the user's transaction executes. [6](#0-5) [9](#0-8) 

### Recommendation
Add an `amountOutMin_` parameter to `Pool.swap` and `IPool.swap`, calculate the actual output as currently done, and revert if `_amountOut < amountOutMin_` before minting the output token. [6](#0-5) 

```solidity
function swap(
    ISyntheticToken syntheticTokenIn_,
    ISyntheticToken syntheticTokenOut_,
    uint256 amountIn_,
    uint256 amountOutMin_
) external returns (uint256 _amountOut, uint256 _fee) {
    // ...
    (_amountOut, _fee) = quoteSwapOut(
        syntheticTokenIn_,
        syntheticTokenOut_,
        amountIn_
    );
    if (_amountOut < amountOutMin_) revert SwapSlippageTooHigh();
    // ...
}
```

### Proof of Concept
The following Hardhat-style fork test demonstrates the unsafe flow: the user obtains a quote, the quote changes before execution, and `swap` still succeeds despite returning less output than expected.

```ts
it('executes a swap below the expected output', async function () {
  const amountIn = parseEther('1');

  // Initial conversion quote observed by the user.
  const { _amountOut: expectedOut } = await pool.quoteSwapOut(
    msETH.address,
    msUSD.address,
    amountIn
  );

  // Simulate a pending oracle update or market-state transition that lowers
  // the execution-time ETH/USD quote before the user's transaction is mined.
  await executeOracleOrSourcePriceUpdate();

  const inBefore = await msETH.balanceOf(alice.address);
  const outBefore = await msUSD.balanceOf(alice.address);

  const tx = await pool
    .connect(alice)
    .swap(msETH.address, msUSD.address, amountIn);

  const { _amountOut: actualOut } = await pool.quoteSwapOut(
    msETH.address,
    msUSD.address,
    amountIn
  );

  await expect(tx).to.emit(pool, 'SyntheticTokenSwapped');

  // The transaction succeeds even though the output is below the amount
  // the user expected when constructing the transaction.
  expect(actualOut).to.be.lt(expectedOut);
  expect(await msETH.balanceOf(alice.address)).to.eq(inBefore.sub(amountIn));
  expect(await msUSD.balanceOf(alice.address)).to.eq(outBefore.add(actualOut));
});
```

The absence of a minimum-output argument means no revert occurs after `quoteSwapOut` returns the reduced amount. [10](#0-9)
