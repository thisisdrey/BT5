### Title
Priority floor bypass via compute-budget-instruction parse failures forces full ed25519 verification on unpriced packets - ([File: core/src/sigverify.rs])

### Summary
`apply_priority_floor_to_batch` only discards a packet when `calculate_priority_from_bytes` successfully computes a priority `<= floor`; any packet for which that function returns `None` is unconditionally kept (`any_kept = true`) and the whole batch is forwarded to `ed25519_verify_serial`. Because `calculate_priority_from_bytes` requires stricter parsing (full compute-budget-instruction sanitization) than the raw signature-verification path (`verify_packet`), an attacker can craft packets that always fail priority computation yet still pass the cheaper parse check used before real ed25519 verification, permanently bypassing the priority floor.

### Finding Description
The priority floor is applied per-batch in `apply_priority_floor_to_batch`: [1](#0-0) 

For each non-discarded packet, `calculate_priority_from_bytes(bank, data)` is called. Only `Some(priority) if priority <= floor` results in a discard; any other outcome — including `None` — sets `any_kept = true` and leaves the packet un-discarded ("Unparseable packets are kept and left for downstream rejection").

`calculate_priority_from_bytes` requires three successive steps to succeed: `SanitizedTransactionView::try_new_sanitized`, `RuntimeTransaction::try_new`, and critically `.transaction_configuration(&bank.feature_set)`: [2](#0-1) 

`transaction_configuration()` performs full compute-budget instruction sanitization via `ComputeBudgetInstructionDetails::try_from`, which explicitly rejects duplicate compute-budget instructions (`SetComputeUnitLimit`, `SetComputeUnitPrice`, `RequestHeapFrame`, `SetLoadedAccountsDataSizeLimit`) with `TransactionError::DuplicateInstruction`: [3](#0-2) 

In contrast, the actual signature-verification routine used downstream, `verify_packet` (invoked by `ed25519_verify_serial`), only requires the raw `SanitizedTransactionView::try_new_sanitized` parse to succeed — it does not build a `RuntimeTransaction` and never runs compute-budget sanitization — before performing the real ed25519 cryptographic `signature.verify()` calls: [4](#0-3) [5](#0-4) 

Consequently, a transaction with a well-formed message/header/signature layout (so it parses as `SanitizedTransactionView`) but containing a duplicated compute-budget instruction (e.g., two `SetComputeUnitLimit` instructions) will:
1. Fail `calculate_priority_from_bytes` → returns `None`.
2. Be treated by `apply_priority_floor_to_batch` as "unparseable" and kept (`any_kept = true`, never marked discard).
3. Reach `ed25519_verify_serial` → `verify_packet`, where it passes the (cheaper) `SanitizedTransactionView` parse and undergoes full ed25519 signature verification, the expensive operation the floor is meant to gate.

This is invoked from the sigverify worker path that applies the scheduler-published floor before verification: [6](#0-5) 

### Impact Explanation
The priority floor mechanism exists specifically to bound pre-fee sigverify CPU work under scheduler saturation: once saturated, the scheduler publishes the queue-min priority so sigverify workers can cheaply drop below-floor packets before doing expensive ed25519 verification: [7](#0-6) 

An unprivileged remote attacker can craft an unbounded stream of cheap, distinct (to defeat dedup) packets containing a duplicate compute-budget instruction. Each such packet always evaluates to `None` in the floor check regardless of the published floor value, so it is never discarded pre-verification and always consumes a full ed25519 signature verification (the expensive per-packet cost the floor exists to bound). This is a QoS-evasion / grossly-underpriced-pre-fee-work condition: the intended invariant "sigverify work is bounded by fee-priced packets once saturated" is defeated for this crafted packet class, allowing a fee-less attacker to consume leader CPU at the same rate as legitimate paying traffic even while the scheduler is saturated and the floor is active.

### Likelihood Explanation
Fully reachable by an unstaked remote client opening a QUIC/UDP connection to the leader's public TPU port and sending arbitrary transaction packets — no staked/validator/gossip control required. Constructing a transaction with a valid message/signature-count/account-key layout but a duplicate compute-budget instruction requires no cryptographic secrets (a self-signed transfer transaction with two `SetComputeUnitLimit` instructions and a real keypair suffices to pass `SanitizedTransactionView` parsing). The existing deduper only blocks identical byte-for-byte repeats, easily defeated by varying blockhash/nonce per packet, so this is trivially repeatable at scale.

### Recommendation
Make the priority-floor packet classification consistent with (or at least as permissive as) the signature-verification pre-check: either (a) compute priority using only the same lightweight parse used by `verify_packet` (i.e., don't require full `transaction_configuration()`/compute-budget sanitization success to treat a packet as "priced"), treating compute-budget sanitization failures as priority `0` so they get floor-filtered like any other below-floor transaction, or (b) apply the same stricter sanitization check in `verify_packet`/`ed25519_verify_serial` before doing expensive signature checks so that packets rejected by `calculate_priority_from_bytes` are also cheaply rejected pre-verification, restoring the invariant that unparseable/unpriced packets never reach the costly ed25519 code path when a floor is active.

fn priority_floor_bypassed_by_duplicate_compute_budget_instruction() {
    // Build a bank with a nonzero floor scenario.
    let (bank, mint) = test_bank_with_lamports_per_signature(5_000);

    // Craft a transaction that parses fine as SanitizedTransactionView
    // (valid signatures/account keys) but has a DUPLICATE compute-budget
    // instruction, causing `transaction_configuration()` to fail.
    let to = Pubkey::new_unique();
    let transfer = system_instruction::transfer(&mint.pubkey(), &to, 1);
    let dup1 = ComputeBudgetInstruction::set_compute_unit_limit(1_000);
    let dup2 = ComputeBudgetInstruction::set_compute_unit_limit(2_000); // duplicate!
    let message = Message::new(&[transfer, dup1, dup2], Some(&mint.pubkey()));
    let tx = Transaction::new(&[&mint], message, bank.last_blockhash());
    let bytes = bincode::serialize(&VersionedTransaction::from(tx)).unwrap();

    // 1. calculate_priority_from_bytes must return None (bypasses pricing).
    assert!(calculate_priority_from_bytes(&bank, &bytes).is_none());

    // 2. Build a batch with only this "unparseable" packet plus one
    //    legitimately-priced below-floor packet, apply a high floor.
    let mut batch = /* construct PacketBatch containing `bytes` as one packet
                        + a normal low-priority transaction as a second packet */;
    let floor = u64::MAX; // everything priced should be dropped
    let (dropped, all_below) = apply_priority_floor_to_batch(&mut batch, floor, &bank);

    // Expected (buggy) behavior: the priced packet is dropped, but the
    // unpriced (duplicate-instruction) packet survives, so all_below is
    // false and the whole batch proceeds to full ed25519 verification,
    // defeating the floor for the crafted packet.
    assert_eq!(dropped, 1);
    assert!(!all_below, "malformed-but-verifiable packet defeats the floor");

    // 3. Confirm it is NOT marked discard, i.e. it will hit the real
    //    ed25519_verify_serial signature-verification cost.
    let crafted_packet = batch.iter().next().unwrap(); // the dup-CU-limit packet
    assert!(!crafted_packet.meta().discard());
}

fn apply_priority_floor_to_batch(
    batch: &mut PacketBatch,
    floor: u64,
    bank: &Bank,
) -> (usize, bool) {
    let mut dropped: usize = 0;
    let mut any_kept = false;
    for mut packet in batch.iter_mut() {
        if packet.meta().discard() {
            continue;
        }
        let Some(data) = packet.data(..) else {
            // Zero-length or otherwise unreadable: leave to downstream
            // stages to reject.
            any_kept = true;
            continue;
        };
        // Unparseable packets are kept and left for downstream rejection.
        match calculate_priority_from_bytes(bank, data) {
            Some(priority) if priority <= floor => {
                packet.meta_mut().set_discard(true);
                dropped = dropped.saturating_add(1);
            }
            _ => any_kept = true,
        }
    }
    (dropped, !any_kept)

fn verify_packet(packet: &mut PacketRefMut, reject_non_vote: bool, enable_tx_v1: bool) -> bool {
    // If this packet was already marked as discard, drop it
    if packet.meta().discard() {
        return false;
    }

    let Some(data) = packet.data(..) else {
        return false;
    };

    let (is_simple_vote_tx, verified) = {
        let Ok(view) = SanitizedTransactionView::try_new_sanitized(data, &sanitize_config()) else {
            return false;
        };

        if !enable_tx_v1 && matches!(view.version(), TransactionVersion::V1) {
            return false;
        }

        let is_simple_vote_tx = is_simple_vote_transaction_view(&view);
        if reject_non_vote && !is_simple_vote_tx {
            (is_simple_vote_tx, false)
        } else {
            let signatures = view.signatures();
            if signatures.is_empty() {
                (is_simple_vote_tx, false)
            } else {
                let message = view.message_data();
                let static_account_keys = view.static_account_keys();
                let verified = signatures
                    .iter()
                    .zip(static_account_keys.iter())
                    .all(|(signature, pubkey)| signature.verify(pubkey.as_ref(), message));
                (is_simple_vote_tx, verified)
            }
        }
    };

    if is_simple_vote_tx {
        packet.meta_mut().flags |= PacketFlags::SIMPLE_VOTE_TX;
    }

    verified
}

pub fn ed25519_verify_serial(batch: &mut PacketBatch, reject_non_vote: bool, enable_tx_v1: bool) {
    for mut packet in batch.iter_mut() {
        if !packet.meta().discard() && !verify_packet(&mut packet, reject_non_vote, enable_tx_v1) {
            packet.meta_mut().set_discard(true);
        }
    }

    /// Update the scheduler priority floor.
    ///
    /// Semantics: when the retained scheduler buffer is nearly full, drop
    /// arrivals that are at-or-below the current queue-min priority, i.e. no
    /// better than what the bounded scheduler candidate set would evict.
    fn update_scheduler_priority_floor(&mut self, num_dropped_on_capacity: usize) {
        let buffer_size = self.container.buffer_size();
        let saturated = self
            .saturation_state
            .update(buffer_size, num_dropped_on_capacity);
        let priority_floor = if saturated {
            self.container
                .get_min_max_priority()
                .map_or(0, |(min, _)| min)
        } else {
            0
        };

        self.saturation_state.publish_floor(priority_floor);
    }
