Audit Report

## Title
Rounding truncation lets `calculate_fee` return a zero remote fee for non-zero, validated pricing parameters, letting relayer-reward delivery costs go unpaid - ([File: bridges/snowbridge/pallets/outbound-queue/src/lib.rs])

## Summary
`PricingParameters::validate()` in `bridges/snowbridge/primitives/core/src/pricing.rs` only checks that raw governance-set fields are individually non-zero, but `Pallet::calculate_fee` in `bridges/snowbridge/pallets/outbound-queue/src/lib.rs` can still compute a derived `fee.remote == 0` due to integer-division truncation in `convert_from_ether_decimals`. This lets a user's message be enqueued via `SendMessage::validate`/`Pallet::validate` (`bridges/snowbridge/pallets/outbound-queue/src/send_message_impl.rs`) while paying zero for the remote component, even though `do_process_message` independently commits a non-zero wei `reward` to the `CommittedMessage` sent to Ethereum.

## Finding Description
`calculate_fee` computes `fee_per_gas * gas_used_at_most + reward` in wei, downcasts to `u128`, applies `multiplier`/`exchange_rate`, and finally calls `convert_from_ether_decimals`, which does `value.checked_div(10^(18 - T::Decimals))` [1](#0-0) . For a 10-decimal chain this divisor is `10^8`; if the scaled numerator is smaller than that, the division floors to zero. `PricingParameters::validate()` only checks that `exchange_rate`, `fee_per_gas`, `rewards.local`, `rewards.remote`, and `multiplier` are individually non-zero — it never inspects the value `calculate_fee` actually produces [2](#0-1) . This gap is directly confirmed by the pallet's own regression test, which sets `fee_per_gas=1`, `rewards.remote=1`, `exchange_rate=1/1`, `multiplier=1/1` (all individually non-zero, thus passing `validate()`) and asserts `fee.remote == 0` [3](#0-2) . That zero fee flows straight out of `Pallet::validate` (`SendMessage::validate`), which any unprivileged sender reaches through the `EthereumBlobExporter`/XCM `ExportMessage` path — `fee.total()` is what's ultimately charged via `take_fee` in the XCM executor [4](#0-3) . Meanwhile `do_process_message` derives the reward committed to Ethereum directly from the raw (non-truncated) `pricing_params.rewards.remote` in wei, independent of `fee.remote` [5](#0-4) . No code path re-validates the derived `fee.remote` against zero before enqueueing or before committing the reward, so the two values can diverge with `fee.remote == 0` while `reward > 0`.

## Impact Explanation
This matches the "public underpriced work that degrades block production or stalls bridge processing" impact category: any unprivileged user sending a message via the Snowbridge outbound path can have it accepted while paying only `fee.local`, with the ETH-side reward promised to relayers left uncovered by collected fees. This enables cheap/free spam of bridge messages under the affected pricing regime and creates a funding mismatch between collected local fees and committed remote rewards.

## Likelihood Explanation
Reachability is entirely dependent on which `PricingParameters` governance has set in production; the vulnerability is a deterministic rounding defect (not a race or timing issue) reachable by anyone whenever the parameters/gas combination puts the wei-scaled numerator below the decimal-conversion divisor. The pallet's own unit test demonstrates the exact triggering condition with concretely valid (non-zero) parameters, confirming the code path exists and is trivially triggerable given suitable parameters, though whether current live BridgeHub parameters are close to this threshold could not be verified from the repository alone.

## Recommendation
Add an explicit check on the computed `fee.remote` (not just raw inputs) inside `calculate_fee`, e.g. `ensure!(fee.remote > 0, ...)` whenever `params.rewards.remote > 0`, returning a `SendError`/rejecting the message so it cannot be enqueued with an uncovered reward. Additionally, derive/verify the wei `reward` field set in `do_process_message` consistently with the same conversion path used for `fee.remote`, and add a test enforcing `fee.remote > 0` whenever `PricingParameters::validate()` succeeds.

## Proof of Concept
The existing test `test_calculate_fees_with_valid_exchange_rate_but_remote_fee_calculated_as_zero` in `bridges/snowbridge/pallets/outbound-queue/src/test.rs` reproduces this with no code changes: setting `exchange_rate = 1/1`, `fee_per_gas = 1`, `rewards = {local: 1, remote: 1}`, `multiplier = 1/1` (all pass `PricingParameters::validate()`), calling `OutboundQueue::calculate_fee(250000, price_params)` yields `fee.local = 698000000` and `fee.remote = 0`, while `do_process_message` would still commit `reward = pricing_params.rewards.remote` (non-zero, in wei) to the outbound `CommittedMessage`.

		pub(crate) fn calculate_fee(
			gas_used_at_most: u64,
			params: PricingParameters<T::Balance>,
		) -> Fee<T::Balance> {
			// Remote fee in ether
			let fee = Self::calculate_remote_fee(
				gas_used_at_most,
				params.fee_per_gas,
				params.rewards.remote,
			);

			// downcast to u128
			let fee: u128 = fee.try_into().defensive_unwrap_or(u128::MAX);

			// multiply by multiplier and convert to local currency
			let fee = FixedU128::from_inner(fee)
				.saturating_mul(params.multiplier)
				.checked_div(&params.exchange_rate)
				.expect("exchange rate is not zero; qed")
				.into_inner();

			// adjust fixed point to match local currency
			let fee = Self::convert_from_ether_decimals(fee);

			Fee::from((Self::calculate_local_fee(), fee))
		}

		/// Calculate fee in remote currency for dispatching a message on Ethereum
		pub(crate) fn calculate_remote_fee(
			gas_used_at_most: u64,
			fee_per_gas: U256,
			reward: U256,
		) -> U256 {
			fee_per_gas.saturating_mul(gas_used_at_most.into()).saturating_add(reward)
		}

		/// The local component of the message processing fees in native currency
		pub(crate) fn calculate_local_fee() -> T::Balance {
			T::WeightToFee::weight_to_fee(
				&T::WeightInfo::do_process_message().saturating_add(T::WeightInfo::commit_single()),
			)
		}

		// 1 DOT has 10 digits of precision
		// 1 KSM has 12 digits of precision
		// 1 ETH has 18 digits of precision
		pub(crate) fn convert_from_ether_decimals(value: u128) -> T::Balance {
			let decimals = ETHER_DECIMALS.saturating_sub(T::Decimals::get()) as u32;
			let denom = 10u128.saturating_pow(decimals);
			value.checked_div(denom).expect("divisor is non-zero; qed").into()
		}

		}

			return Err(InvalidPricingParameters);

			return Err(InvalidPricingParameters);
		}

			return Err(InvalidPricingParameters);
		}
		if self.multiplier == FixedU128::zero() {
			return Err(InvalidPricingParameters);
		}
		Ok(())
	}

#[test]
fn test_calculate_fees_with_valid_exchange_rate_but_remote_fee_calculated_as_zero() {
	new_tester().execute_with(|| {
		let gas_used: u64 = 250000;
		let price_params: PricingParameters<<Test as Config>::Balance> = PricingParameters {
			exchange_rate: FixedU128::from_rational(1, 1),
			fee_per_gas: 1_u32.into(),
			rewards: Rewards { local: 1_u32.into(), remote: 1_u32.into() },
			multiplier: FixedU128::from_rational(1, 1),
		};
		let fee = OutboundQueue::calculate_fee(gas_used, price_params.clone());
		assert_eq!(fee.local, 698000000);
		// Though none zero pricing params the remote fee calculated here is invalid
		// which should be avoided
		assert_eq!(fee.remote, 0);
	});
}

	fn validate(
		message: &Message,
	) -> Result<(Self::Ticket, Fee<<Self as SendMessageFeeProvider>::Balance>), SendError> {
		// The inner payload should not be too large
		let payload = message.command.abi_encode();
		ensure!(
			payload.len() < T::MaxMessagePayloadSize::get() as usize,
			SendError::MessageTooLarge
		);

		// Ensure there is a registered channel we can transmit this message on
		ensure!(T::Channels::contains(&message.channel_id), SendError::InvalidChannel);

		// Generate a unique message id unless one is provided
		let message_id: H256 = message
			.id
			.unwrap_or_else(|| unique((message.channel_id, &message.command)).into());

		let gas_used_at_most = T::GasMeter::maximum_gas_used_at_most(&message.command);
		let fee = Self::calculate_fee(gas_used_at_most, T::PricingParameters::get());

		let queued_message: VersionedQueuedMessage = QueuedMessage {
			id: message_id,
			channel_id: message.channel_id,
			command: message.command.clone(),
		}
		.into();
		// The whole message should not be too large
		let encoded = queued_message.encode().try_into().map_err(|_| SendError::MessageTooLarge)?;

		let ticket = Ticket { message_id, channel_id: message.channel_id, message: encoded };

		Ok((ticket, fee))
	}
