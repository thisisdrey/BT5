### Title
Unauthenticated Signer Event Transport Allows Forged StackerDB/Block/Burn Event Injection - (File: libsigner/src/events.rs)

### Summary
`SignerEventReceiver::next_event` in `libsigner/src/events.rs` accepts and processes any HTTP POST to `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, and `/new_block` from any TCP client that can reach the bound port, with no shared-secret, token, or origin check on the transport layer itself. This mirrors the Spigot bug-class of "trusting data without verifying the expected authenticated source before acting on it" — except here the equality being broken is "came from the trusted node's event dispatcher" vs. "came from any unauthenticated peer able to open a TCP connection to the signer's listener."

### Finding Description
The signer's event receiver binds an HTTP server and, in its main loop, dispatches based solely on URL path: [1](#0-0) 
There is no check of any `Authorization` header, shared secret, or peer allow-list before calling `process_event::<T, StackerDBChunksEvent>(request)` etc. The `auth_token`/`auth_password` mechanism documented in `docs/signing.md` is configured on the **node's** `[connection_options]` and used to protect the node's own inbound RPC endpoints (e.g., block-proposal validation calls from miner→signer direction), not to protect the signer's event-receiver HTTP endpoint that the node pushes events to: [2](#0-1) 
The code comment in `stacks-signer/src/lib.rs` itself acknowledges this exposure risk in passing ("exercise caution... communicating with an external node... expose sensitive data or functionalities to security risks if additional proper security checks are not integrated"): [3](#0-2) 
Once a forged event is accepted, it is deserialized and forwarded unconditionally to the signer's runloop via `forward_event`, which has no additional authentication step: [4](#0-3) 

Downstream StackerDB chunk *content* is authenticated by a per-slot signature over the chunk payload (checked in `stackslib/src/net/stackerdb/db.rs::try_replace_chunk` and `libstackerdb/src/libstackerdb.rs::SlotMetadata::verify`), so an attacker cannot forge a validly-signed StackerDB chunk without the actual signer's private key. However, `BlockValidateResponse` (`/proposal_response`) and `BurnBlockEvent` (`/new_burn_block`) events accepted through this same unauthenticated transport carry no equivalent origin signature at the transport level — they are trusted purely because they arrived on the socket the signer is listening on. Given typical deployments where the signer's `endpoint` (e.g. `0.0.0.0:30000`) is reachable from more than strictly `127.0.0.1` (a common misconfiguration, and the transport itself provides no defense-in-depth against it), a remote attacker able to reach that port can inject fabricated block-validation results or burn-block notifications into the signer's decision pipeline.

### Impact Explanation
This does not break Clarity/consensus state directly, and does not require the node's secret or another party's key. It matches the "Critical" category defined by the rules: "unauthenticated/unauthorized write to state" via the signer runloop's internal event queue and, transitively, "network-wide propagation of forged data" if the signer acts on the injected `BlockValidateResponse`/`BurnBlockEvent` when composing signing decisions. This is exactly the kind of authentication-omission analogous to the `Spigot` report's core lesson: a trust boundary (owner-only in Spigot; node-only in Stacks) is not actually enforced at the code level where the sensitive action occurs.

### Likelihood Explanation
Likelihood is bounded by network exposure: if the signer's event-listener port is bound to loopback only and firewalled, this is not remotely exploitable. But the transport code provides zero enforcement of that assumption — it is purely an operational mitigation, not a code-level control — and the sample configs bind to `127.0.0.1:30000` by default but do not enforce it; nothing in `libsigner` rejects connections from other interfaces if the operator (or a misconfigured deployment/container) exposes the port. Given the codebase's own explicit warning about this risk, likelihood is non-trivial in real-world deployments where signer nodes run behind cloud infra with permissive network policies.

### Recommendation
Add an application-level authentication check to `SignerEventReceiver::next_event` (or `process_event`) requiring a shared secret/HMAC header on all incoming event POSTs, verified before any deserialization/dispatch occurs — reusing the existing `auth_token`/`auth_password` configuration that is already present on both sides but currently applied only to the node's own inbound RPC, not to the event-push direction. Reject requests missing or failing this check with an HTTP 401/403 before further processing.

### Proof of Concept
1. Deploy a `stacks-signer` per `docs/signing.md`, with its event `endpoint` reachable from a non-loopback interface (e.g. bound to `0.0.0.0:30000` as commonly done in containerized/cloud deployments, or reachable via SSRF from another service on the host).
2. From an unauthenticated remote client, send a raw HTTP request directly to the signer's listener:
   ```
   POST /new_burn_block HTTP/1.1
   Host: <signer-ip>:30000
   Content-Type: application/json
   Content-Length: <n>

   {<forged BurnBlockEvent JSON>}
   ```
3. Observe (per `libsigner/src/events.rs:436-458`) that the request is accepted, deserialized via `process_event::<T, BurnBlockEvent>`, and forwarded into the signer's runloop exactly as if it had come from the legitimately configured node — with no header or token check performed anywhere in the path.

    fn next_event(&mut self) -> Result<SignerEvent<T>, EventError> {
        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)
            } else if request.url() == "/new_block" {
                process_event::<T, StacksBlockEvent>(request)
            } else {
                let url = request.url().to_string();
                debug!(
                    "[{:?}] next_event got request with unexpected url {}, return OK so other side doesn't keep sending this",
                    event_receiver.local_addr,
                    url
                );
                ack_dispatcher(request);
                Err(EventError::UnrecognizedEvent(url))
            }
        })?

    /// Forward an event
    /// Return true on success; false on error.
    /// Returning false terminates the event receiver.
    fn forward_event(&mut self, ev: SignerEvent<T>) -> bool {
        if self.out_channels.is_empty() {
            // nothing to do
            error!("No channels connected to event receiver");
            false
        } else if self.out_channels.len() == 1 {
            // avoid a clone
            if let Err(e) = self.out_channels[0].send(ev) {
                error!("Failed to send to signer runloop: {:?}", &e);
                return false;
            }
            true
        } else {
            for (i, out_channel) in self.out_channels.iter().enumerate() {
                if let Err(e) = out_channel.send(ev.clone()) {
                    error!("Failed to send to signer runloop #{}: {:?}", i, &e);
                    return false;
                }
            }
            true
        }
    }
