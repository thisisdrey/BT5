### Title
`LinkRepositoryToObjectPool` writes the pool's alternates path into any target repository without verifying the repository is actually an authorized member/fork of that pool - ([File: internal/gitaly/service/objectpool/link.go])

### Summary
The bug class in the external report is: a mutating function checks only that an identifier is *valid* (`isValidDNft`) instead of checking that the caller/target is *authorized* (`isDNftOwner`), letting an unrelated actor mutate shared state tied to someone else's resource and thereby deny or corrupt legitimate use. `LinkRepositoryToObjectPool` in Gitaly has the analogous gap: it validates that the `repository` and `object_pool` fields each point to a *well-formed, existing* repository, but never validates that the two are actually supposed to be linked (e.g. that `repository` is a fork/descendant of the pool's origin). Any caller able to invoke this RPC with an attacker-chosen `(repository, object_pool)` pair can therefore graft one repository onto an arbitrary, unrelated object pool.

### Finding Description
`LinkRepositoryToObjectPool` performs two checks and nothing more: [1](#0-0) 

- `s.locator.ValidateRepository(ctx, repository)` only confirms the target repository path exists and is a valid git directory (`ValidateRepository`), analogous to `isValidDNft` in the report — it checks *existence*, not *ownership/relationship*. [2](#0-1) 
- `s.poolForRequest` → `objectpool.FromProto` only confirms the object pool path is a *valid pool repository* (right shape/location), again not that the caller or the `repository` field is entitled to be a member of it. [3](#0-2) [4](#0-3) 

The actual linking logic in `objectpool.Link` then unconditionally writes the pool's relative object path into the target repository's `objects/info/alternates` file (unless an alternates file already points elsewhere), and strips any existing bitmap files from the target member: [5](#0-4) 

There is no check anywhere in this call chain that `repository` was ever forked from, or is otherwise entitled to share objects with, the specified `object_pool`. This mirrors the DYAD finding precisely: the code validates *shape/validity* of both IDs but omits the *relationship/ownership* check that the operation's safety actually depends on — same class of "wrong/insufficient validation" bug, just applied to storage-path/alternates linkage instead of a DNft id.

### Impact Explanation
Linking a repository to an unrelated object pool has concrete integrity/availability consequences documented by Gitaly itself:
- The member repository will start reading objects transparently from the pool via alternates, and any subsequent `git repack`/`git gc` in the member will deduplicate against pool content, potentially discarding the member's own object storage layout in favor of pool objects (`doc/object_pools.md`).
- Existing bitmap files on the newly-linked member are deleted (`removeMemberBitmaps`), which is a real, immediate on-disk mutation performed on behalf of the "repository" party without their consent.
- Because deduplication and alternates lookups mean the member can now resolve pool objects that are otherwise unrelated to it, this creates a cross-repository object exposure path, and later `DisconnectGitAlternates`/repack operations against the wrongly-linked pair can fail their `git-fsck` consistency check, which — per the documented recovery path — re-adds the alternates link on failure, i.e. the corrupted linkage becomes sticky and hard to safely undo (`doc/object_pools.md`, `DisconnectGitAlternates` docs). [6](#0-5) 
- Because `Link` treats "already linked to a *different* pool" as a hard error (`unexpected alternates content`), an attacker who wins the race to link a victim repository to a bogus/attacker pool first can also permanently block the legitimate `LinkRepositoryToObjectPool` call for the real pool from ever succeeding for that repository — a direct DoS analog to the report's "attacker blocks legitimate withdraw/remove" scenario. [7](#0-6) 

### Likelihood Explanation
`LinkRepositoryToObjectPool` is invoked as part of the normal, user-triggered fork-creation flow (an ordinary user forking a repository causes GitLab to create an object pool and link both the source and fork to it), so the RPC is reachable through an ordinary "fork" action rather than an obscure admin-only path, as shown in the fork-creation test: [8](#0-7) 
Whether an external, unprivileged actor can supply an arbitrary `object_pool`/`repository` pair to this RPC depends entirely on what validation the calling layer (GitLab Rails) performs before invoking it — Gitaly itself performs none beyond existence/shape checks. I could not verify within this repository whether Rails enforces the fork/pool relationship before calling this RPC, since that logic lives outside Gitaly. This is the main source of uncertainty in assessing exploitability from an "ordinary user" surface as opposed to a privileged/internal caller.

### Recommendation
`LinkRepositoryToObjectPool` (and `objectpool.Link`) should verify that the target `repository` is actually a recognized member of (e.g., forked from) the specified `object_pool` before writing the alternates file — for example by checking recorded pool-membership metadata rather than trusting the caller-supplied pair, mirroring the report's fix of replacing the "is this ID well-formed" check with an "is this actor/entity actually authorized for this specific relationship" check.

### Proof of Concept
1. Attacker (or a compromised/duped caller of the Gitaly RPC surface) creates or has access to `victimRepo` (`storage/relative_path` known/guessable) and an attacker-controlled `attackerPool` object pool.
2. Attacker calls `LinkRepositoryToObjectPool(repository=victimRepo, object_pool=attackerPool)`.
3. `ValidateRepository` and `objectpool.FromProto` both succeed because both are valid, existing entities — no relationship check is performed: [1](#0-0) 
4. `objectpool.Link` writes `attackerPool`'s object path into `victimRepo/objects/info/alternates` and deletes `victimRepo`'s bitmap files: [9](#0-8) 
5. `victimRepo` is now silently dependent on `attackerPool` for object resolution; a subsequent legitimate `LinkRepositoryToObjectPool(victimRepo, legitimatePool)` call fails with `unexpected alternates content`, permanently breaking the intended pool relationship until manually repaired: [10](#0-9)

func (s *server) LinkRepositoryToObjectPool(ctx context.Context, req *gitalypb.LinkRepositoryToObjectPoolRequest) (*gitalypb.LinkRepositoryToObjectPoolResponse, error) {
	repository := req.GetRepository()
	if err := s.locator.ValidateRepository(ctx, repository); err != nil {
		return nil, structerr.NewInvalidArgument("%w", err)
	}

	pool, err := s.poolForRequest(ctx, req)
	if err != nil {
		return nil, err
	}

	repo := s.localRepoFactory.Build(repository)

	if err := pool.Link(ctx, repo); err != nil {
		return nil, structerr.NewInternal("%w", err)
	}

	return &gitalypb.LinkRepositoryToObjectPoolResponse{}, nil

// ValidateRepository validates whether the given path points to a valid Git repository. This
// function returns:
//
// - ErrRepositoryNotFound when the path cannot be found.
// - ErrRepositoryNotValid when the repository is not a valid Git repository.
// - An unspecified error when stat(3P)ing files fails due to other reasons.
func (l *configLocator) ValidateRepository(ctx context.Context, repo storage.Repository, opts ...storage.ValidateRepositoryOption) error {
	var cfg storage.ValidateRepositoryConfig
	for _, opt := range opts {
		opt(&cfg)
	}

	// Only checking for `nil` isn't sufficient as Protobuf messages may be non-nil, but still
	// either invalid or empty. Thus we also explicitly verify whether both the storage name and
	// the relative path are unset.
	if repo == nil || repo.GetStorageName() == "" && repo.GetRelativePath() == "" {
		return structerr.NewInvalidArgument("%w", storage.ErrRepositoryNotSet)
	}

	relativePath := repo.GetRelativePath()
	if len(relativePath) == 0 {
		return structerr.NewInvalidArgument("%w", storage.ErrRepositoryPathNotSet)
	}

// FromProto returns an object pool object from its Protobuf representation. This function verifies
// that the object pool exists and is a valid pool repository.
func FromProto(
	ctx context.Context,
	logger log.Logger,
	locator storage.Locator,
	gitCmdFactory gitcmd.CommandFactory,
	catfileCache catfile.Cache,
	txManager transaction.Manager,
	housekeepingManager housekeepingmgr.Manager,
	proto *gitalypb.ObjectPool,
) (*ObjectPool, error) {
	poolPath, err := locator.GetRepoPath(ctx, proto.GetRepository(), storage.WithRepositoryVerificationSkipped())
	if err != nil {
		return nil, err
	}

	if !storage.IsPoolRepository(proto.GetRepository()) {
		// When creating repositories in the ObjectPool service we will first create the
		// repository in a temporary directory. So we need to check whether the path we see
		// here is in such a temporary directory and let it pass.
		tempDir, err := locator.TempDir(proto.GetRepository().GetStorageName())
		if err != nil {
			return nil, fmt.Errorf("getting temporary storage directory: %w", err)
		}

		if !strings.HasPrefix(poolPath, tempDir) {
			return nil, ErrInvalidPoolDir
		}
	}

	pool := &ObjectPool{
		Repo:                localrepo.New(logger, locator, gitCmdFactory, catfileCache, proto.GetRepository()),
		logger:              logger,
		locator:             locator,
		gitCmdFactory:       gitCmdFactory,
		txManager:           txManager,
		housekeepingManager: housekeepingManager,
	}

	if !pool.IsValid(ctx) {
		return nil, ErrInvalidPoolRepository
	}

	return pool, nil
}

// Link will link the given repository to the object pool. This is done by writing the object pool's
// path relative to the repository into the repository's "alternates" file. This does not trigger
// deduplication, which is the responsibility of the caller.
func Link(ctx context.Context, pool, repo *localrepo.Repo, txManager transaction.Manager) (returnedErr error) {
	altPath, err := repo.InfoAlternatesPath(ctx)
	if err != nil {
		return err
	}

	expectedRelPath, err := getRelativeObjectPath(ctx, pool, repo)
	if err != nil {
		return err
	}

	linked, err := linkedToRepository(ctx, pool, repo)
	if err != nil {
		return err
	}

	if linked {
		// When the repository is already linked to the repository, cast a vote to ensure the
		// repository is consistent with the other replicas.
		if err := transaction.VoteOnContext(ctx, txManager, voting.VoteFromData([]byte("repository linked")), voting.Synchronized); err != nil {
			return fmt.Errorf("vote on linked repository: %w", err)
		}

		return nil
	}

	alternatesWriter, err := safe.NewLockingFileWriter(altPath)
	if err != nil {
		return fmt.Errorf("creating alternates writer: %w", err)
	}
	defer func() {
		if err := alternatesWriter.Close(); err != nil && returnedErr == nil {
			returnedErr = fmt.Errorf("closing alternates writer: %w", err)
		}
	}()

	if _, err := io.WriteString(alternatesWriter, expectedRelPath); err != nil {
		return fmt.Errorf("writing alternates: %w", err)
	}

	if err := transaction.CommitLockedFile(ctx, txManager, alternatesWriter); err != nil {
		return fmt.Errorf("committing alternates: %w", err)
	}

	if tx := storage.ExtractTransaction(ctx); tx != nil {
		alternatesRelativePath, err := filepath.Rel(tx.FS().Root(), altPath)
		if err != nil {
			return fmt.Errorf("rel alternates file: %w", err)
		}

		if err := tx.FS().RecordFile(alternatesRelativePath); err != nil {
			return fmt.Errorf("record alternates file")
		}
	}

	return removeMemberBitmaps(ctx, pool, repo)

// linkedToRepository tests if a repository is linked to an object pool
func linkedToRepository(ctx context.Context, pool, repo *localrepo.Repo) (bool, error) {
	poolPath, err := pool.Path(ctx)
	if err != nil {
		return false, fmt.Errorf("getting object pool path: %w", err)
	}

	repoPath, err := repo.Path(ctx)
	if err != nil {
		return false, fmt.Errorf("getting repo path: %w", err)
	}

	altInfo, err := stats.AlternatesInfoForRepository(repoPath)
	if err != nil {
		return false, fmt.Errorf("getting alternates info: %w", err)
	}

	if !altInfo.Exists || len(altInfo.ObjectDirectories) == 0 {
		return false, nil
	}

	relPath := altInfo.ObjectDirectories[0]
	expectedRelPath, err := getRelativeObjectPath(ctx, pool, repo)
	if err != nil {
		return false, err
	}

	if relPath == expectedRelPath {
		return true, nil
	}

	if filepath.Clean(relPath) != filepath.Join(poolPath, "objects") {
		return false, fmt.Errorf("unexpected alternates content: %q", relPath)
	}

	return false, nil
