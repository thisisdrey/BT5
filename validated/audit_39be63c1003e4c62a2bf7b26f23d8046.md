Confirmed: the `RemoteIndex` field in `header.H` is a plaintext, unauthenticated 32-bit field sent in every packet header [1](#0-0) , and `RecvError` packets are dispatched to `handleRecvError` before any certificate/handshake state or decryption is required [2](#0-1) . This matches the reachability constraints: no CA-signed certificate is needed to trigger it.

### Title
Unauthenticated `RecvError` packets allow remote teardown of established tunnels via source-address spoofing - (File: `outside.go`)

### Summary
Nebula's `RecvError` message type is processed without any cryptographic authentication. Anyone who can observe or brute-force a victim's `RemoteIndex` (sent in cleartext on every packet) and spoof the victim's current UDP source address can force `handleRecvError` to tear down an already-established, mutually-authenticated tunnel. This mirrors the referenced report's bug class: an unauthenticated third party invoking functionality that is supposed to be gated by a trusted relationship, breaking the victim's legitimate session state.

### Finding Description
`readOutsidePackets` parses the header and, before any hostinfo lookup, certificate verification, or decryption, dispatches `header.RecvError` packets directly to `f.handleRecvError`: [2](#0-1) 

`handleRecvError` looks up the hostinfo purely by the plaintext `RemoteIndex` field and only checks that the packet's source address matches the currently recorded remote address for that hostinfo — there is no MAC, signature, or handshake-derived authentication tying the `RecvError` packet to the peer's private key: [3](#0-2) 

If the source-address check passes (or is bypassed by IP spoofing / on-path interception, since UDP source addresses are not cryptographically bound), the function immediately calls `f.closeTunnel(hostinfo)` and `f.handshakeManager.DeleteHostInfo(hostinfo)`, unilaterally destroying a fully-authenticated tunnel. The `RemoteIndex` is not a secret — it is transmitted in cleartext in the header of every single packet on the wire, as shown by the header layout comment and `Encode`/`Parse` functions: [4](#0-3) [5](#0-4) 

By contrast, the functionally similar `CloseTunnel` message type was hardened to require successful decryption under the peer's established cipher state before being honored, as evidenced by the dedicated regression test `TestCloseTunnelAuthenticated`, which explicitly verifies that a bogus, unauthenticated `CloseTunnel` packet is rejected: [6](#0-5) . `RecvError` has no equivalent protection, and structurally cannot easily get one, since it is meant to be sent by hosts that have no valid session state for the sender.

### Impact Explanation
An attacker who can observe traffic (or intercept/spoof a single packet with the victim's `RemoteIndex` and current source `AddrPort`) can force termination of any active Nebula tunnel between two legitimate, certificate-authenticated peers. This is a remote denial-of-service against established connections: the victim's tunnel and pending handshake state are deleted (`f.closeTunnel` + `hm.DeleteHostInfo`), forcing renegotiation and disrupting connectivity — directly analogous to the referenced report where an unauthorized caller of `getReward` broke the Vault's own accounting/`claimRewards` flow for a victim who never authorized that call.

### Likelihood Explanation
`RemoteIndex` values are transmitted unencrypted in every packet's header, so any passive observer on the path (or a lighthouse-adjacent attacker, or someone who can send spoofed UDP with the correct 4-tuple) can harvest them cheaply. The `hr != addr` check is the only guard, and it depends solely on comparing UDP source address/port, which is not cryptographically authenticated at the RecvError layer. `sendRecvErrorConfig`/`acceptRecvErrorConfig` (`recvErrorAlways`/`recvErrorPrivate`/`recvErrorNever`) can reduce exposure but are not authentication mechanisms and default configurations may still accept these packets: [7](#0-6) 

### Recommendation
Do not allow `RecvError` to unilaterally tear down an existing, fully-established tunnel based solely on an unauthenticated index+source-address match. Options: (1) require a signed/MAC'd acknowledgment tied to the current handshake's key material before honoring `RecvError` for hosts with `ConnectionState != nil`; (2) rate-limit and require corroborating evidence (e.g., a subsequent failed decrypt, or invalidate only pending/handshake state rather than fully-established `ConnectionState`); (3) mirror the `CloseTunnel` hardening pattern (`TestCloseTunnelAuthenticated`) by requiring `RecvError` handling for already-established hosts to also be authenticated, falling back to the current permissive behavior only for truly unknown/no-hostinfo cases.

### Proof of Concept
1. Attacker passively observes (or otherwise learns) the `RemoteIndex` used by victim B when talking to victim A, and B's current UDP `AddrPort` (both visible in cleartext headers of ordinary traffic).
2. Attacker crafts a `header.H{Type: header.RecvError, RemoteIndex: <B's index as seen by A>}`, encodes it with `header.Encode`, and sends it to A's UDP listener spoofing the source address as B's current `AddrPort`.
3. A's `readOutsidePackets` dispatches directly to `handleRecvError` without decrypting or checking any certificate; the `hr != addr` check passes because the spoofed source matches B's recorded remote.
4. A calls `f.closeTunnel(hostinfo)` and `hm.DeleteHostInfo(hostinfo)`, tearing down the legitimate A↔B tunnel without either A or B having authorized it.

```go
func (h *H) Parse(b []byte) error {
	if len(b) < Len {
		return ErrHeaderTooShort
	}
	// get upper 4 bytes
	h.Version = uint8((b[0] >> 4) & 0x0f)
	// get lower 4 bytes
	h.Type = MessageType(b[0] & 0x0f)
	h.Subtype = MessageSubType(b[1])
	h.Reserved = binary.BigEndian.Uint16(b[2:4])
	h.RemoteIndex = binary.BigEndian.Uint32(b[4:8])
	h.MessageCounter = binary.BigEndian.Uint64(b[8:16])
	return nil
}
```

```go
func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
```

```go
func (s recvErrorConfig) ShouldRecvError(endpoint netip.AddrPort) bool {
	switch s {
	case recvErrorPrivate:
		return endpoint.Addr().IsPrivate()
	case recvErrorAlways:
		return true
	case recvErrorNever:
		return false
	default:
		panic(fmt.Errorf("invalid recvErrorConfig value: %d", s))
	}
}
```
