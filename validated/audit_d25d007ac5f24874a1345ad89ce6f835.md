#No Vulnerability found for this question.

The scaling in `compute_max_allowed_uni_streams_with_rtt` is bounded by design, not unbounded, and does not violate any documented invariant. [1](#0-0) [2](#0-1) 

The `rtt_millis` value is not an attacker-supplied field parsed from a packet; it comes from `connection.rtt()`, quinn's internal RTT estimator, and is explicitly clamped to `MAX_RTT_MS` (350 ms) before being passed into `compute_max_allowed_uni_streams_with_rtt`: [3](#0-2)  Inside the function itself, the RTT is clamped again to `[REFERENCE_RTT_MS, MAX_RTT_MS]` before scaling, so the maximum possible multiplier is `MAX_RTT_MS / REFERENCE_RTT_MS = 7x`, capping unstaked `max_uni_streams` at `QUIC_MAX_UNSTAKED_CONCURRENT_STREAMS * 7 = 896` per connection [4](#0-3) .

This bounded scaling is intentional BDP (bandwidth-delay-product) compensation, as documented in the code comments, and the test `test_max_allowed_uni_streams_with_rtt` confirms the expected bounded scaling behavior [5](#0-4) . Additionally, total unstaked connection/stream memory is already bounded independently by `max_unstaked_connections` and `max_connections_per_unstaked_peer` limits enforced in `try_add_connection`/`prune_unstaked_connections_and_add_new_connection`, with active pruning down to 90% capacity when the table fills [6](#0-5) . Since both the per-connection stream multiplier and the total connection count are hard-capped constants, there is no unbounded memory growth path reachable by an unstaked attacker reporting inflated RTT — the worst case is a fixed, small (7x) increase within an already capacity-limited system, which does not meet the bug bar of unbounded memory growth or invariant violation.

fn compute_max_allowed_uni_streams_with_rtt(
    rtt_millis: u32,
    peer_type: ConnectionPeerType,
    total_stake: u64,
) -> u32 {
    let streams = match peer_type {
        ConnectionPeerType::Staked(peer_stake) => {
            // No checked math for f64 type. So let's explicitly check for 0 here
            if total_stake == 0 || peer_stake > total_stake {
                warn!(
                    "Invalid stake values: peer_stake: {peer_stake:?}, total_stake: \
                     {total_stake:?}"
                );

                QUIC_MIN_STAKED_CONCURRENT_STREAMS
            } else {
                let delta = (QUIC_TOTAL_STAKED_CONCURRENT_STREAMS
                    - QUIC_MIN_STAKED_CONCURRENT_STREAMS) as f64;

                (((peer_stake as f64 / total_stake as f64) * delta) as u32
                    + QUIC_MIN_STAKED_CONCURRENT_STREAMS)
                    .clamp(
                        QUIC_MIN_STAKED_CONCURRENT_STREAMS,
                        QUIC_MAX_STAKED_CONCURRENT_STREAMS,
                    )
            }
        }
        ConnectionPeerType::Unstaked => QUIC_MAX_UNSTAKED_CONCURRENT_STREAMS,
    };
    // scale amount of streams based on RTT if RTT is larger than REFERENCE_RTT_MS
    // multiply first then divide to avoid rounding errors.
    (streams.saturating_mul(rtt_millis.clamp(REFERENCE_RTT_MS, MAX_RTT_MS))) / REFERENCE_RTT_MS
}

    fn prune_unstaked_connection_table(
        &self,
        unstaked_connection_table: &mut ConnectionTable<ConnectionStreamCounter>,
        max_unstaked_connections: usize,
        stats: Arc<StreamerStats>,
    ) {
        if unstaked_connection_table.total_size >= max_unstaked_connections {
            // Prune the connection table down to 90% capacity
            const PRUNE_TABLE_RATIO: f64 = 0.90;
            let max_connections = (PRUNE_TABLE_RATIO * (max_unstaked_connections as f64)) as usize;
            let num_pruned = unstaked_connection_table.prune_oldest(max_connections);
            stats
                .num_evictions_unstaked
                .fetch_add(num_pruned, Ordering::Relaxed);
        }
    }
