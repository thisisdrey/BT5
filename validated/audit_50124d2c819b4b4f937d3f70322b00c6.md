### Title
Depositors can frontrun `lending_pool_handle_bankruptcy` to dodge socialized losses - ([File: programs/marginfi/src/instructions/marginfi_group/handle_bankruptcy.rs])

### Summary
`lending_pool_handle_bankruptcy` performs a discrete, one-shot reduction of `Bank.asset_share_value` via `socialize_loss` when a bankrupt user's bad debt exceeds the insurance fund. This is functionally the same "discrete rebase-style step change" pattern flagged in the external report: any depositor who sees the bad-debt condition forming can withdraw before the socialization transaction lands, avoiding their pro-rata share of the loss and pushing it entirely onto slower depositors.

### Finding Description
When a bankrupt account's liabilities exceed the insurance fund's ability to cover them, `socialize_loss` is called and instantly rewrites `asset_share_value` for the whole bank: [1](#0-0) 

In the worst case (super-bankruptcy), `asset_share_value` is set to zero, wiping out all remaining depositors' holdings in one atomic step, exactly analogous to a large negative `rebaseSub`/`rebaseMul` in the referenced report: [2](#0-1) 

`lending_pool_handle_bankruptcy` is triggered either by `risk_admin`/`admin`, or — critically — permissionlessly by anyone when `PERMISSIONLESS_BAD_DEBT_SETTLEMENT_FLAG` is set on the bank: [3](#0-2) 

There is no window/delay/lock mechanism between the moment a user becomes eligible for bankruptcy (their liabilities are visible on-chain after liquidation) and the moment `handle_bankruptcy` actually executes and applies `socialize_loss`. Because interest accrual and share pricing are purely accounting-based with no withdrawal fee or timelock, an unprivileged depositor watching a bank approach bankruptcy (or watching for a pending `handle_bankruptcy`/liquidation transaction) can simply call the ordinary, permissionless `lending_account_withdraw` first, at the pre-loss `asset_share_value`, and exit before the haircut lands: [4](#0-3) 

This mirrors the report's exact bug class: a privileged/permissionless action produces a discrete, predictable step-change in the accounting rate (`asset_share_value`), and unprivileged users can race a normal withdrawal against it to shift the impact to other users.

### Impact Explanation
Depositors who successfully frontrun `handle_bankruptcy` fully avoid their share of socialized bad debt, while depositors who do not react in time absorb a disproportionately larger (up to 100%) share of the loss — including total wipeout in the super-bankruptcy case where `asset_share_value` is set to zero. This is a concrete unauthorized redistribution of loss/insolvency risk among unprivileged depositors, satisfying the "insolvency/bad debt" impact category.

### Likelihood Explanation
Likelihood is low-to-moderate: it requires an active bankruptcy condition to exist (documented as "rare," occurring only after failed liquidation, illiquid collateral, or a severe price shock), and it requires an alert actor to detect the pending bad debt/liquidation state and race a withdrawal before the (potentially admin-run) `handle_bankruptcy` transaction confirms. When `PERMISSIONLESS_BAD_DEBT_SETTLEMENT_FLAG` is set, any observer can also self-trigger `handle_bankruptcy` to bound the delay against slower depositors, but that does not change the fundamental race between "who withdraws first" and "who eats the loss."

### Recommendation
Consider one or more mitigations analogous to those suggested in the external report: (1) a short timelock/queue between when a bank is flagged eligible for bankruptcy and when `socialize_loss` can be applied, during which withdrawals from that specific bank are paused or fee-adjusted; (2) apply socialized losses retroactively/pro-rata to all depositors present at the time the bad debt was incurred (e.g., via a snapshot mechanism) rather than only to whoever remains at execution time; (3) add a small withdrawal fee/cooldown specifically for banks in a pre-bankruptcy state to reduce the incentive to race the socialization transaction.

### Proof of Concept
1. Bank B has depositors D1..Dn and a borrower who becomes liquidatable; liquidation fully drains the borrower's collateral, leaving bad debt (`total assets < total liabilities` for that position), matching `check_account_bankrupt` preconditions in `lending_pool_handle_bankruptcy`.
2. This state is visible on-chain (borrower's account has 0 assets, positive liability shares) before anyone calls `handle_bankruptcy`.
3. Depositor D1, monitoring the mempool/chain state (or simply monitoring bank health), submits `lending_account_withdraw` for their full position in bank B before `handle_bankruptcy`/`socialize_loss` executes, redeeming at the pre-loss `asset_share_value`.
4. `handle_bankruptcy` then executes `socialize_loss`, dividing the uncovered bad debt only among the shares still outstanding (`programs/marginfi/src/state/bank.rs:858-886`), meaning D2..Dn absorb what would have otherwise been partly borne by D1, and in the super-bankruptcy branch could see their `asset_share_value` reduced to zero entirely.

    /// Socialize a loss of `loss_amount` among depositors, the `total_deposit_shares` stays the
    /// same, but total value of deposits is reduced by `loss_amount`;
    ///
    /// In cases where assets < liabilities, the asset share value will be set to zero, but cannot
    /// go negative. Effectively, depositors forfeit their entire deposit AND all earned interest in
    /// this case.
    fn socialize_loss(&mut self, loss_amount: I80F48) -> MarginfiResult<bool> {
        let mut kill_bank = false;
        let total_asset_shares: I80F48 = self.total_asset_shares.into();
        let old_asset_share_value: I80F48 = self.asset_share_value.into();

        // Compute total "old" value of shares
        let total_value: I80F48 = total_asset_shares
            .checked_mul(old_asset_share_value)
            .ok_or_else(math_error!())?;

        // Subtract loss, clamping at zero (i.e. assets < liabilities, the bank is wiped out)
        if total_value <= loss_amount {
            self.asset_share_value = I80F48::ZERO.into();
            // This state is irrecoverable, the bank is dead.
            kill_bank = true;
        } else {
            // otherwise subtract then redistribute
            let new_share_value: I80F48 = (total_value - loss_amount)
                .checked_div(total_asset_shares)
                .ok_or_else(math_error!())?;
            self.asset_share_value = new_share_value.into();
            // Sanity check: should be unreachable.
            if new_share_value == I80F48::ZERO {
                kill_bank = true;
            }
        }

        Ok(kill_bank)
    }

* If bank's insurance fund > liabilities, then the insurance fund is used to repay the user's liability.
* If the bank's insurance fund is not sufficient, the remainder will be covered by taking liquidity
  out of the bank, reducing the asset share value. This socializes the loss to all remaining
  depositors.
* If the bank's insurance fund and liquidity are not sufficient (super-bankruptcy), the bank is
  killed. The asset share value is set to zero, wiping out all holdings for all other depositors.
  This state is irrecoverable, and the bank is permanently disabled.
