This is confirmed: `GetObjectDirectorySize` explicitly returns `0` for a quarantine directory before it is migrated into the main repository, as shown by the test at [1](#0-0) . This RPC and `RepositorySize` are the mechanisms GitLab uses during `pre-receive` (while objects are still quarantined) to evaluate a repository's on-disk footprint, per the object-quarantine design documented at [2](#0-1) . This maps to the reported bug class: a value used for an accept/reject decision is computed while excluding "pending" data (the quarantined push objects, analogous to the pending Uniswap fee) that will inevitably be merged into the accounted state right afterward, causing the check to understate the true resulting size.

### Title
GetObjectDirectorySize/RepositorySize undercount pending quarantined push objects, enabling repository-size-limit bypass - (File: internal/gitaly/service/repository/size.go)

### Summary
`GetObjectDirectorySize` and `RepositorySize` compute the on-disk size of a repository by walking its object directory on disk [3](#0-2) . When invoked with a quarantined repository (the object directory pointing at the quarantine tree used during `pre-receive`), the reported size is `0` regardless of how many bytes are staged in quarantine, because the walk only looks at the (empty) real object directory, not the quarantine directory that holds the incoming push's objects [4](#0-3) .

### Finding Description
During `git receive-pack`, all objects of an incoming push are first written into a per-push quarantine directory and only merged into the repository's real object directory after `pre-receive` succeeds, exactly as this repo's own documentation explains: object quarantine writes go to `objects/incoming-$RANDOM`, are only merged in if `pre-receive` passes, and the merge happens via `quarantine.Dir.Migrate` [5](#0-4) . GitLab's `pre-receive` handling explicitly gives Rails the quarantine object directory so that access checks made during this window can inspect what is being pushed [6](#0-5) . Any size-based check Rails performs at this point (e.g. via `RepositorySize`/`GetObjectDirectorySize`) is answered using only the pre-existing real object directory — the pending quarantined pack/loose objects are invisible to `dirSizeInBytes`, which walks a single path and does not consider `GitAlternateObjectDirectories`/quarantine content [3](#0-2) . Consequently, a repository-size evaluation performed while a large push is still quarantined will systematically undercount the amount of data about to be admitted, since that quarantined data is unconditionally migrated into the real directory immediately afterward if `pre-receive` passes [7](#0-6) .

### Impact Explanation
Any GitLab feature that relies on `RepositorySize`/`GetObjectDirectorySize` during `pre-receive` to decide whether to allow a push (e.g., a namespace/repository storage limit) would systematically see an undercounted value and could admit pushes that push the repository over its intended size limit, since the entire pending push payload is excluded from the reported figure until after quarantine merge. This is a DoS/resource-limit-bypass class issue: an ordinary authenticated pusher can inflate a repository's real on-disk size beyond any quota enforced at the `pre-receive` checkpoint, simply by pushing a large enough payload in one push (the check happens once, before merge, and the whole payload becomes part of the repo right after).

### Likelihood Explanation
Likelihood is high for any deployment that gates pushes based on Gitaly-reported size during `pre-receive`: no special privileges are needed, only the ability to push, and the quarantine window/merge sequencing is deterministic and always followed by `quarantine.Dir.Migrate` on success [8](#0-7) .

### Recommendation
When computing `RepositorySize`/`GetObjectDirectorySize` for a repository whose request carries a quarantine `GitObjectDirectory`/`GitAlternateObjectDirectories`, include the size of the quarantine directory (and any alternates) in the total, so the reported figure reflects what the repository size will be immediately after the pending quarantined objects are migrated in, rather than only the pre-push state.

### Proof of Concept
1. Start a push containing a very large packfile so that `git receive-pack` stages it fully in the quarantine directory `<storage>/tmp/quarantine-*` before `pre-receive` completes.
2. While the push is in the `pre-receive` phase, call `GetObjectDirectorySize` (as Rails would, using the quarantined repository) — observe it returns `0` per the behavior demonstrated at [9](#0-8) , even though gigabytes are staged in quarantine.
3. Any downstream size/quota gate keyed on this value passes the push.
4. `pre-receive` accepts (no other rejection reason), and `quarantine.Migrate` merges the full staged payload into the real object directory [5](#0-4) , at which point the repository's true, now-unbounded size is realized — after the quota checkpoint has already passed.

func (s *server) GetObjectDirectorySize(ctx context.Context, in *gitalypb.GetObjectDirectorySizeRequest) (*gitalypb.GetObjectDirectorySizeResponse, error) {
	repository := in.GetRepository()
	if err := s.locator.ValidateRepository(ctx, repository); err != nil {
		return nil, structerr.NewInvalidArgument("%w", err)
	}
	repo := s.localRepoFactory.Build(repository)

	path, err := repo.ObjectDirectoryPath(ctx)
	if err != nil {
		return nil, err
	}
	// path is the objects directory path, not repo's path
	sizeInBytes, err := dirSizeInBytes(path, snapshot.NewDefaultFilter(ctx))
	if err != nil {
		return nil, fmt.Errorf("calculating directory size: %w", err)
	}

	return &gitalypb.GetObjectDirectorySizeResponse{Size: sizeInBytes / 1024}, nil
}

// Migrate migrates all objects part of the quarantine directory into the repository and thus makes
// them generally available. This implementation follows the git.git's `tmp_objdir_migrate()`.
func (d *Dir) Migrate(ctx context.Context) error {
	repoPath, err := d.locator.GetRepoPath(ctx, d.repo, storage.WithRepositoryVerificationSkipped())
	if err != nil {
		return fmt.Errorf("migrating quarantine: %w", err)
	}

	objectDir := d.repo.GetGitObjectDirectory()
	if objectDir == "" {
		// Migrate the objects to the default object directory if the repository
		// didn't have an object directory explicitly configured.
		objectDir = "objects"
	}

	return migrate(ctx, d.dir.Path(), filepath.Join(repoPath, objectDir))
}
