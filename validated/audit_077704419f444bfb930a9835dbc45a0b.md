### Title
Unauthenticated gRPC DoS via null StreamObserver payload in GetPaginatedProposalList/GetPaginatedExchangeList - (File: framework/src/main/java/org/tron/core/services/RpcApiService.java)

### Summary
The gRPC `WalletApi.getPaginatedProposalList` and `getPaginatedExchangeList` handlers pass the return value of `Wallet.getPaginatedProposalList`/`getPaginatedExchangeList` straight into `responseObserver.onNext(...)` without a null check or exception handling, while the underlying `Wallet` methods are documented and implemented to return `null` for out-of-range `offset`/`limit` values that any anonymous gRPC client fully controls.

### Finding Description
`Wallet.getPaginatedProposalList(offset, limit)` returns `null` when `offset < 0`, `limit < 0`, or `offset >= latestProposalNum` [2](#0-1) . The analogous `getPaginatedExchangeList` has the same null-return path for equivalent boundary conditions [3](#0-2) .

The HTTP servlets that wrap these same `Wallet` calls correctly guard against a `null` reply, e.g. `GetPaginatedProposalListServlet.fillResponse` checks `if (reply != null)` before writing a JSON body [4](#0-3) , and `GetPaginatedExchangeListServlet` does the same [5](#0-4) .

But the gRPC service implementations in `RpcApiService` do not perform this null check, nor do they wrap the call in a `try/catch` the way neighboring handlers such as `getBandwidthPrices`, `getEnergyPrices`, and `getMemoFee` do [6](#0-5) . Protobuf-generated `StreamObserver` implementations reject `null` messages passed to `onNext`, throwing an unchecked `NullPointerException` from within the gRPC handler thread. Because the call is unguarded and not caught, this propagates as an unhandled exception in the gRPC request-processing path.

This is directly analogous to CVE-2019-14847: a low-privilege, unauthenticated client sends a normal-looking paginated query (dirsync in Samba; `GetPaginatedProposalList`/`GetPaginatedExchangeList` in java-tron) with parameters chosen to hit an edge case that the server-side code fails to validate before using the result, crashing/destabilizing the service process.

### Impact Explanation
Any anonymous gRPC client (full node's public `WalletApi` gRPC port, reachable without a signed transaction or any authorization) can trigger an unhandled `NullPointerException` in the node's gRPC service thread by sending an out-of-range `offset`/`limit` in a `PaginatedMessage` request. Depending on the gRPC server/thread pool's exception handling, this can terminate the handling stream abruptly and, if repeated, degrade or crash the API-serving capability of the node, denying `GetPaginatedProposalList`/`GetPaginatedExchangeList` service to legitimate callers. This matches the "API the node can no longer serve" acceptance criterion.

### Likelihood Explanation
High reachability and trivial trigger conditions: a single unauthenticated gRPC call with `offset` set beyond the current proposal/exchange count (or negative) is sufficient — no signed transaction, no special permissions, and no interaction with block production or consensus is required. The vulnerable code has existed unchanged relative to sibling methods that do implement guards, indicating an oversight rather than a defended edge case.

### Recommendation
In `RpcApiService.getPaginatedProposalList` and `getPaginatedExchangeList`, check the `Wallet` call result for `null` before calling `onNext`, and send an empty `ProposalList`/`ExchangeList` (or an explicit error via `onError`) instead, mirroring the null-safe pattern already used in the HTTP servlets. Wrap both handlers in a `try/catch` consistent with the neighboring `getBandwidthPrices`/`getEnergyPrices`/`getMemoFee` implementations so any unexpected exception is converted to `responseObserver.onError(...)` rather than propagating unhandled.

### Proof of Concept
1. Connect to the full node's gRPC `WalletApi` service without authentication.
2. Call `getPaginatedProposalList` with `PaginatedMessage{offset: -1, limit: 10}` (or `offset` set larger than the current `latestProposalNum`).
3. `Wallet.getPaginatedProposalList` returns `null` per its guard clause [7](#0-6) .
4. `RpcApiService` passes this `null` directly to `responseObserver.onNext(null)` [8](#0-7) , causing an unchecked `NullPointerException` in the gRPC handler with no surrounding try/catch to convert it to a graceful `onError`.
5. Repeat with `getPaginatedExchangeList` using the same offset/limit trick against the exchange list path [9](#0-8) .
