### Title
Unstaked peers can indefinitely evade connection eviction by refreshing `last_update` via cheap streams - ([File: streamer/src/nonblocking/quic.rs])

### Summary
The QUIC connection tables (`ConnectionTable`) evict connections using a least-recently-used policy keyed on a `last_update` timestamp. That timestamp is refreshed every time *any* stream on the connection finishes, including trivially small/cheap streams, with no minimum cost or validation tied to the refresh. An unprivileged (unstaked) client can keep opening and finishing minimal streams to continuously "touch" its connection's `last_update`, making it always appear as the most-recently-used entry and thereby permanently evading `prune_oldest` eviction, denying connection slots to other unstaked peers.

### Finding Description
`ConnectionEntry::last_update()` [1](#0-0)  feeds `prune_oldest`, which evicts the connection(s) with the smallest (oldest) `last_update` whenever the unstaked table exceeds its capacity: [2](#0-1) .

`last_update` is refreshed on every stream completion via `qos.on_stream_finished`, called unconditionally from `handle_connection` whenever `handle_chunks` reports `StreamState::Finished` — this includes tiny streams (e.g., single-byte payloads), not just legitimate, cost-bearing transaction submissions: [3](#0-2) . The refresh itself is implemented identically in both QoS backends: [4](#0-3)  and [5](#0-4) .

`prune_unstaked_connection_table` relies on `prune_oldest` (LRU by `last_update`) to make room for new unstaked connections once the unstaked table nears capacity: [6](#0-5) .

Because opening a uni-stream and sending even a single byte (well within per-stream/token-bucket throttling limits) counts as a "finished" stream and resets `last_update`, an unstaked attacker holding a connection can perpetually refresh it at negligible cost (bounded only by the per-connection stream-rate throttle in `on_new_stream`/`stream_counter`, not by any minimum useful work), keeping it permanently "young" from the eviction algorithm's perspective. This defeats the intended fairness mechanism that `prune_oldest`/`prune_unstaked_connection_table` implement to let idle/stale unstaked connections be recycled for new peers.

### Impact Explanation
This is a QoS/eviction-evasion bug: the connection turnover mechanism for the unstaked connection table is designed to bound resource usage and give a rotating set of unstaked peers a fair chance at connection slots. By trivially resetting the LRU timestamp with cheap streams, a small number of unstaked clients can occupy and retain connection slots indefinitely, denying other unstaked peers the ability to ever establish a connection to submit transactions through the QUIC streamer. This is analogous to the referenced report's core issue — a low/no-cost action being able to reset a timer that governs eviction/wait-period logic that other unprivileged users depend on.

### Likelihood Explanation
The attack requires no special privileges or stake — any unstaked client can open and finish minimal-size uni-streams at the maximum rate allowed by the unstaked token-bucket/throttle, well within normal usage patterns, so there's no rate-limiting mechanism that specifically distinguishes "connection keep-alive spam" from legitimate low-volume traffic.

### Recommendation
Do not treat every stream completion equally for LRU eviction purposes. Consider basing `last_update` refresh only on streams that produced a valid, forwarded packet (which already happens, since `on_stream_finished` is only called on `StreamState::Finished`, i.e., success) but additionally rate-limit how often a single connection's `last_update` can be refreshed for eviction purposes, or incorporate a secondary aging/round-robin factor into `prune_oldest`/`prune_unstaked_connection_table` (e.g., use connection creation/age or hybrid LRU+age instead of purely LRU) so that persistent "keep-alive via minimal traffic" connections cannot indefinitely evade eviction and starve new unstaked peers.

### Proof of Concept
1. An unstaked client establishes a connection to the QUIC TPU endpoint, filling the unstaked connection table near capacity (`prune_unstaked_connection_table` triggers around 90% capacity: [7](#0-6) ).
2. The attacker repeatedly opens a uni-stream, writes 1 byte, and finishes it (as shown in the test helper pattern) — each completion calls `qos.on_stream_finished`, refreshing `last_update`: [8](#0-7) .
3. Because `prune_oldest` always evicts based on the minimum `last_update` across connections: [9](#0-8) , the attacker's connection is never selected for eviction as long as it keeps refreshing faster than other connections age, while other unstaked peers attempting new connections get pruned/rejected once the table is full.

    pub(crate) fn prune_oldest(&mut self, max_size: usize) -> usize {
        let mut num_pruned = 0;
        let key = |(_, connections): &(_, &Vec<_>)| {
            connections.iter().map(ConnectionEntry::last_update).min()
        };
        while self.total_size.saturating_sub(num_pruned) > max_size {
            match self.table.values().enumerate().min_by_key(key) {
                None => break,
                Some((index, connections)) => {
                    num_pruned += connections.len();
                    self.table.swap_remove_index(index);
                }
            }
        }
        self.total_size = self.total_size.saturating_sub(num_pruned);
        num_pruned
    }

    fn prune_unstaked_connection_table(
        &self,
        unstaked_connection_table: &mut ConnectionTable<ConnectionStreamCounter>,
        max_unstaked_connections: usize,
        stats: Arc<StreamerStats>,
    ) {
        if unstaked_connection_table.total_size >= max_unstaked_connections {
            // Prune the connection table down to 90% capacity
            const PRUNE_TABLE_RATIO: f64 = 0.90;
            let max_connections = (PRUNE_TABLE_RATIO * (max_unstaked_connections as f64)) as usize;

            stats
                .num_evictions_unstaked
                .fetch_add(num_pruned, Ordering::Relaxed);
        }
    }
