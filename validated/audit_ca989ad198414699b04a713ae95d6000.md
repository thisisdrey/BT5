### Title
Missing StackerDB contract/context binding in chunk signature authorization allows cross-contract chunk replay - (File: `libstackerdb/src/libstackerdb.rs`)

### Summary
`SlotMetadata::auth_digest()` computes the signed digest for a StackerDB chunk from only `(slot_id, slot_version, data_hash)` and never binds the signature to the StackerDB contract (`QualifiedContractIdentifier`) the chunk is destined for. Because the Nakamoto signer set is expressed as the *same* ordered address list shared by every `signers-{0|1}-{message_id}` StackerDB contract for a signer set, the same `slot_id` maps to the same signer address across all of those contracts. A chunk validly signed by a signer for one contract (e.g. `signers-0-blockresponse`) is therefore also a validly-signed chunk for a *different* contract (e.g. `signers-0-transactions`) with the same `slot_id`, as long as the target contract's version/size checks are satisfied. This lets any unprivileged network participant harvest a legitimately broadcast, validly-signed chunk from one StackerDB and replay it as "authentic" data into a different StackerDB contract, mislabeling attacker-chosen (but pre-signed) bytes as a different message type.

**Consequence:** the tuple `(slot_id, signer_address)` is identical across every message-type StackerDB contract belonging to the same signer set for a given reward cycle. Since the chunk signature is only over `(slot_id, slot_version, data_hash)`, a signature produced for slot `k` in `signers-0-blockresponse` is bit-for-bit valid for slot `k` in `signers-0-transactions` (or any other `signers-0-*` contract) provided the target contract's version and size constraints happen to be satisfiable. This breaks the intended equality "signature authorizes a write to *this* StackerDB" vs. what is actually checked ("signature authorizes a write by *this signer* to *slot k*, contract-agnostic") — directly analogous to the reported Merkle bug, where the signed leaf omitted the reward-token identity, letting a proof meant for one context be reused in another.

### Impact Explanation
An unprivileged remote peer that observes (via the public StackerDB read/gossip protocol) any validly-signed chunk emitted by a signer can replay that exact `StackerDBChunkData` (same `slot_id`, `slot_version`, `sig`, `data`) as a `PostStackerDBChunk`/`StackerDBPushChunk` targeting a *different* StackerDB contract belonging to the same signer set, as long as:
- the target contract currently has a lower or equal slot version for that slot (any brand-new contract page/version window satisfies this trivially), and
- `slot_version <= max_writes` and chunk size fits the target's `chunk_size`.

The node's write path (`try_replace_chunk`) and gossip acceptance path (`validate_received_chunk`) will both accept this as a genuinely signer-authored chunk for the wrong contract, and the accepted chunk is then re-broadcast to peers as legitimate StackerDB state (`StackerDBChunkInv`/push gossip), i.e. forged/mismatched data is propagated network-wide as if it were canonical, mislabeled signer traffic for a different message type/contract. This matches the "network-wide propagation of forged data" / "unauthenticated/unauthorized write to a StackerDB" Critical impact bucket.

### Likelihood Explanation
High. No secret key material or privileged role is required — chunk data is intentionally public (StackerDB is a gossiped, eventually-consistent store), so any node can fetch a legitimately signed chunk and simply resubmit it verbatim to a sibling contract sharing the same slot-owner list. The only preconditions are naturally satisfied bookkeeping fields (`slot_version`, `max_writes`, `chunk_size`), which are either attacker-controllable indirectly (wait for the version window to line up) or already trivially satisfied for freshly-created contract pages.

### Recommendation
Bind the StackerDB contract identifier (and any other context the write is scoped to, e.g. reward cycle) into the signed digest in `SlotMetadata::auth_digest()`, mirroring the report's fix of including the token address in the Merkle leaf. Concretely, thread the `QualifiedContractIdentifier` (or an equivalent domain-separation tag) into `sign()`/`verify()` so that a signature for one StackerDB contract is provably not valid for another, and update all call sites (`try_replace_chunk`, `validate_received_chunk`, RPC chunk-post handler) accordingly. This requires a protocol/wire versioning change since it alters what bytes are signed.

### Proof of Concept
1. Two StackerDB contracts exist for the same signer set/reward cycle, e.g. `signers-0-blockresponse` and `signers-0-transactions`; both resolve `stackerdb-get-signer-slots` to the identical ordered address list (per `signers.clar`'s `stackerdb-signer-slots-0`).
2. Signer `S` (owner of slot `3` in both contracts) legitimately posts a chunk to `signers-0-blockresponse`: `slot_id=3, slot_version=7, data=<blockresponse bytes>`, signed via `StackerDBChunkData::sign`.
3. An unprivileged observer downloads this chunk (e.g. via `GetStackerDBChunk`/gossip) and repackages it unmodified as a `PostStackerDBChunk`/`StackerDBPushChunk` targeted at `signers-0-transactions`, keeping `slot_id=3, slot_version, sig, data` untouched.
4. On the receiving node, `try_replace_chunk`/`validate_received_chunk` looks up the slot-3 owner for `signers-0-transactions` (same address `S` as in `signers-0-blockresponse`), calls `slot_desc.verify(&owner)`, which recomputes `auth_digest()` over `(slot_id, slot_version, data_hash)` only — passes, because the digest never referenced the contract — and the write is accepted and gossiped to peers as authentic `signers-0-transactions` traffic, even though the payload is actually a `BlockResponse` message never authorized for that contract.

    /// Sign this slot metadata, committing to slot_id, slot_version, and
    /// data_hash.  Sets self.signature to the signature.
    /// Fails if the underlying crypto library fails
    pub fn sign(&mut self, privkey: &StacksPrivateKey) -> Result<(), Error> {
        let auth_digest = self.auth_digest();
        let sig = privkey
            .sign(&auth_digest.0)
            .map_err(|se| Error::SigningError(se.to_string()))?;

        self.signature = sig;
        Ok(())
    }

    /// Verify that a given principal signed this chunk metadata.
    /// Note that the address version is ignored.
    pub fn verify(&self, principal: &StacksAddress) -> Result<bool, Error> {
        let sigh = self.auth_digest();
        let pubk = StacksPublicKey::recover_to_pubkey_without_validating_low_s(
            sigh.as_bytes(),
            &self.signature,
        )
        .map_err(|ve| Error::VerifyingError(ve.to_string()))?;

        let pubkh = Hash160::from_node_public_key(&pubk);
        Ok(pubkh == *principal.bytes())
    }

fn signers_db_get_slots() {
    let stacker_1 = TestStacker::from_seed(&[3, 4]);
    let stacker_2 = TestStacker::from_seed(&[5, 6]);

    let (mut peer, test_signers, latest_block_id, _) = prepare_signers_test(
        function_name!(),
        vec![],
        &[stacker_1.clone(), stacker_2.clone()],
        None,

    let private_key = peer.config.private_key.clone();

    let mut expected_signers: Vec<_> =
        [&stacker_1.signer_private_key, &stacker_2.signer_private_key]
            .iter()
            .map(|sk| {
                let pk = Secp256k1PublicKey::from_private(sk);
                let pk_bytes = pk.to_bytes_compressed();
                let signer_addr = StacksAddress::p2pkh(false, &pk);
                let stackerdb_entry = TupleData::from_data(vec![
                    (
                        ClarityName::from_literal("signer"),
                        PrincipalData::from(signer_addr).into(),
                    ),
                    (ClarityName::from_literal("num-slots"), Value::UInt(1)),
                ])
                .unwrap();
                (pk_bytes, stackerdb_entry)
            })
            .collect();

    // should be sorted by the pk bytes
    expected_signers.sort_by_key(|x| x.0.clone());
    let expected_stackerdb_slots = Value::cons_list_unsanitized(
        expected_signers
            .into_iter()
            .map(|(_pk, entry)| Value::from(entry))
            .collect(),
    )
    .unwrap();

    for signer_set in 0..2 {
        for message_id in 0..SIGNER_SLOTS_PER_USER {
            let contract_name =
                ContractName::try_from(format!("signers-{}-{}", &signer_set, &message_id)).unwrap();
            let signers = readonly_call(
                &mut peer,
                &latest_block_id,
                contract_name.clone(),
                ClarityName::from_literal("stackerdb-get-signer-slots"),
                vec![],
            )
            .expect_result_ok()
            .unwrap();

            debug!("Check .{}", contract_name);
            if signer_set == 0 {
                assert_eq!(signers.expect_list().unwrap(), vec![]);
            } else {
                assert_eq!(signers, expected_stackerdb_slots);
            }
        }
    }
