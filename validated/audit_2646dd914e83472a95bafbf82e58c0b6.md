### Title
Unvalidated, unbounded `Attachment` content accepted from any download peer via `insert_instantiated_attachment` - ([File: stackslib/src/net/atlas/db.rs])

### Summary
The attachment-download path (`decode_atlas_get_attachment` → `extend_with_attachments` → `insert_instantiated_attachment`) accepts and permanently stores whatever bytes a remote peer returns for a `GET /v2/attachments/{hash}` request, without checking that the returned content's hash matches the queued `AttachmentInstance.content_hash`, and without applying `AtlasConfig.attachments_max_size`. This differs from the sibling ingestion path `should_keep_attachment` (used by `posttransaction.rs`), which does enforce both a whitelist and a size cap.

### Finding Description
`RPCGetAttachmentRequestHandler::decode_atlas_get_attachment` parses the HTTP response body straight into a `GetAttachmentResponse`/`Attachment` with no hash-equality check against the hash that was requested: [1](#0-0) 

`extend_with_attachments` then unconditionally inserts this attacker-supplied `Attachment` into `self.attachments` for every "succeeded" response, with no validation: [2](#0-1) 

In the `Done` state of the batch state machine, every drained attachment is looked up by its own (attacker-controlled) content hash and unconditionally persisted via `insert_instantiated_attachment`, regardless of whether any `AttachmentInstance` actually matches that hash: [3](#0-2) 

`insert_instantiated_attachment` itself performs a raw `INSERT OR REPLACE` with no size check and no requirement that the content correspond to any known `AttachmentInstance`: [4](#0-3) 

By contrast, the transaction-submission ingestion path enforces both a contract whitelist and `attachments_max_size`: [5](#0-4) 

Rows inserted with `was_instantiated = 1` are never garbage collected — only `was_instantiated = 0` (uninstantiated) rows are evicted by `evict_expired_uninstantiated_attachments` / `evict_k_oldest_uninstantiated_attachments`: [6](#0-5) 

Attack flow: once the node has queued an `AttachmentRequest` for some `content_hash` (from processing on-chain BNS operations), an attacker who is selected as a download peer for that request (any outbound peer that advertises the hash in its inventory) returns an `Attachment` whose `content` is large and unrelated to the requested hash. The node computes `attachment.hash()` from the returned bytes (not the originally requested hash), stores it unconditionally via `insert_instantiated_attachment`, and never associates or reconciles it with the actual `AttachmentInstance` that triggered the request. The stored row is permanent (no expiry path for `was_instantiated=1`), so this is a durable disk-growth primitive that can be repeated for every attachment instance the node has queued or will queue.

### Impact Explanation
This is a High-severity "attachment/BNS mismatch" condition: the node persistently stores attachment content that no on-chain name operation actually committed to, since the returned bytes are never checked against the specific `AttachmentInstance.content_hash` that generated the request — the lookup uses the hash of the attacker's own bytes. Repeated exploitation (across many queued instances) also produces unbounded, non-evicted storage growth in the `attachments` table, since the `attachments_max_size` cap that gates the contract-call path is not applied here.

### Likelihood Explanation
Preconditions: the target node must have queued an `AttachmentInstance` (e.g., from processing a BNS name-update/registration referencing an attachment) and select the attacker as one of its outbound sync/data peers for the download. This is achievable by any unprivileged peer that can gossip/serve attachment inventories and answer the resulting HTTP GET; no secret or privileged role is required. Repeatable per queued attachment instance and per peer connection.

### Recommendation
In `AttachmentsBatchStateContext::extend_with_attachments` (or in `decode_atlas_get_attachment`), verify that `attachment.hash() == request`'s expected `content_hash` before accepting the response, and reject/penalize peers that return mismatched content. Additionally, enforce `AtlasConfig.attachments_max_size` in `insert_instantiated_attachment` (or earlier, before storing) exactly as `should_keep_attachment` does, and add an eviction/expiry policy for `was_instantiated = 1` rows that fail hash reconciliation.

### Proof of Concept
Rust test in `stackslib::net::atlas::download`:
1. Construct an `AttachmentsBatchStateContext` with one `AttachmentInstance` whose `content_hash = H`.
2. Simulate a `BatchedRequestsResult<AttachmentRequest>` where the "succeeded" response for that request is a `StacksHttpResponse` JSON body encoding an `Attachment` with large content (e.g. several MB) whose actual hash `!= H`.
3. Call `extend_with_attachments` and drive the state machine to `Done`; assert the fabricated attachment is present in `context.attachments`.
4. Call `network.atlasdb.insert_instantiated_attachment(&attachment)` and assert it returns `Ok(())` even though `attachment.content.len() as u32 > atlas_config.attachments_max_size` and no `attachment_instances` row has `content_hash = attachment.hash()`.
5. Query `attachments` table directly and confirm the oversized, unmatched row persists with `was_instantiated = 1`, and that no eviction routine removes it.

    pub fn extend_with_attachments(
        mut self,
        results: &mut BatchedRequestsResult<AttachmentRequest>,
    ) -> AttachmentsBatchStateContext {
        for (request, response) in results.succeeded.drain() {
            let report = self
                .peers
                .get_mut(request.get_url())
                .expect("Atlas: unable to retrieve reliability report for peer");

            let response = if let Some(r) = response {
                r
            } else {
                report.bump_failed_requests();
                continue;
            };

            if let Ok(response) = response.decode_atlas_get_attachment() {
                self.attachments.insert(response.attachment);
                report.bump_successful_requests();
            } else {
                report.bump_failed_requests();
            }
        }
        let mut events_ids = results.faulty_peers.keys().copied().collect::<Vec<usize>>();
        self.events_to_deregister.append(&mut events_ids);

        self
    }

    pub fn should_keep_attachment(
        &self,
        contract_id: &QualifiedContractIdentifier,
        attachment: &Attachment,
    ) -> bool {
        if !self.atlas_config.contracts.contains(contract_id) {
            info!(
                "Atlas: will discard posted attachment - {} not in supported contracts",
                contract_id
            );
            return false;
        }
        if attachment.content.len() as u32 > self.atlas_config.attachments_max_size {
            info!("Atlas: will discard posted attachment - attachment too large");
            return false;
        }
        true
    }

    pub fn evict_k_oldest_uninstantiated_attachments(&mut self, k: u32) -> Result<(), db_error> {
        let tx = self.tx_begin()?;
        let res = tx.execute(
            "DELETE FROM attachments WHERE hash IN (SELECT hash FROM attachments WHERE was_instantiated = 0 ORDER BY created_at ASC LIMIT ?)",
            params![k],
        );
        res.map_err(db_error::SqliteError)?;
        tx.commit().map_err(db_error::SqliteError)?;
        Ok(())
    }

    pub fn evict_expired_uninstantiated_attachments(&mut self) -> Result<(), db_error> {
        let now = util::get_epoch_time_secs() as i64;
        let cut_off = now - self.atlas_config.uninstantiated_attachments_expire_after as i64;
        let tx = self.tx_begin()?;
        let res = tx.execute(
            "DELETE FROM attachments WHERE was_instantiated = 0 AND created_at < ?",
            params![cut_off],
        );
        res.map_err(db_error::SqliteError)?;
        tx.commit().map_err(db_error::SqliteError)?;
        Ok(())
    }

    pub fn insert_instantiated_attachment(
        &mut self,
        attachment: &Attachment,
    ) -> Result<(), db_error> {
        let now = util::get_epoch_time_secs() as i64;
        let tx = self.tx_begin()?;
        tx.execute(
            "INSERT OR REPLACE INTO attachments (hash, content, was_instantiated, created_at) VALUES (?, ?, 1, ?)",
            params![attachment.hash(), attachment.content, now],
        )?;
        tx.execute(
            "UPDATE attachment_instances SET is_available = 1 WHERE content_hash = ?1 AND status = ?2",
            params![attachment.hash(), AttachmentInstanceStatus::Checked],
        )?;
        tx.commit()?;
        Ok(())
    }
