### Title
Per-connection (not aggregate) unstaked stream throttle allows Sybil-via-IP-rotation to exceed the reserved unstaked TPS share and starve staked TPU capacity - ([File: streamer/src/nonblocking/stream_throttle.rs])

### Summary
`StakedStreamLoadEMA` derives a fixed, config-time budget for unstaked traffic (`max_unstaked_load_in_throttling_window = MAX_UNSTAKED_TPS * STREAM_THROTTLING_INTERVAL_MS / 1000`) and hands that exact same fixed quota to *every individual* unstaked connection, rather than dividing a global unstaked budget across connections the way it is done for staked peers. Because the unstaked cap is enforced per-`ConnectionStreamCounter` (per connection) with no shared/global counter, an attacker who opens many distinct unstaked connections (from many source IPs, up to `max_unstaked_connections`) can make the aggregate accepted unstaked stream rate scale linearly with connection count, vastly exceeding `EXPECTED_UNSTAKED_STREAMS_RATIO` of total TPU capacity.

### Finding Description
`StakedStreamLoadEMA::new` computes a single aggregate `max_staked_load_in_throttling_window` for staked peers, then splits it proportionally per staked connection (`stake / total_stake`) in `available_load_capacity_in_throttling_duration`, so the aggregate consumed by all staked connections is bounded by design regardless of how many staked connections exist: [1](#0-0) 

For unstaked peers, however, `available_load_capacity_in_throttling_duration` simply returns the constant `max_unstaked_load_in_throttling_window` for every connection — it is not divided by the number of unstaked connections: [2](#0-1) 

This per-connection value is enforced only against that connection's own `ConnectionStreamCounter` in `throttle_stream`, which resets and checks a purely local `stream_count`: [3](#0-2) 

`SwQos::on_new_stream` invokes `throttle_stream` per-connection with the quota from `max_streams_per_throttling_interval`, and `on_stream_accepted` only feeds the shared `StakedStreamLoadEMA` for *staked* traffic (`increment_load` only adds to `load_in_recent_interval` `if peer_type.is_staked()`), so unstaked volume never influences the shared EMA/throttling decision at all: [4](#0-3) [5](#0-4) 

The only structural limit on the number of concurrent unstaked connections is `max_unstaked_connections` (default 2000) enforced by `unstaked_connection_table`, and per-IP the cap is `max_connections_per_unstaked_peer` (default 8) plus `DEFAULT_MAX_CONNECTIONS_PER_IPADDR_PER_MINUTE`: [6](#0-5) [7](#0-6) 

Consequently, the theoretical aggregate unstaked throughput bound is `max_unstaked_connections * MAX_UNSTAKED_TPS` (e.g., `2000 * 200 = 400,000` streams/sec with defaults), which can approach or exceed `max_streams_per_ms * 1000` (default `500 * 1000 = 500,000`/s) — far above the intended `EXPECTED_UNSTAKED_STREAMS_RATIO` (20%) share. Since none of the existing throttles (per-connection counter, per-IP connection count, or the staked-load EMA) account for aggregate unstaked volume across distinct connections/IPs, an attacker rotating through enough distinct source IPs (Sybil at the IP level, no spoofing needed) can consume CPU/bandwidth/quinn-stream-processing resources on the leader's TPU port far beyond the "reserved" 20% design ratio, degrading real-world capacity available for staked traffic even though staked connections' *logical* quota computation is unaffected on paper.

### Impact Explanation
This is a QoS-evasion / denial-of-service class finding: the software's advertised isolation guarantee ("unstaked connections should only consume `EXPECTED_UNSTAKED_STREAMS_RATIO` of TPU capacity, leaving the rest for staked/leader traffic") is not actually enforced in aggregate — it is only enforced per single connection. A well-resourced Sybil attacker with many distinct IPs can consume shared physical/CPU/network resources on the leader's QUIC ingestion path disproportionate to the intended reservation, potentially degrading or starving legitimate staked transaction ingestion during that validator's leader slots.

### Likelihood Explanation
Feasibility requires the attacker to establish and sustain many concurrent unstaked QUIC connections from distinct source IP addresses (bounded by `max_unstaked_connections`, default 2000, and per-IP connection limits), each streaming near its individual `MAX_UNSTAKED_TPS` allowance during a `STREAM_THROTTLING_INTERVAL` window. This is more costly than a single-source attack (real distinct IPs are needed, not spoofed packets, since QUIC requires a completed handshake), but it does not require any stake, validator identity, or privileged access — only network-level IP diversity, which is realistically obtainable (cloud/VPS providers, botnets, IPv6 address space). The relevant knobs (`MAX_UNSTAKED_TPS`, `max_unstaked_connections`) are compile-time/config constants, not adaptively adjusted to the number of active unstaked connections.

### Recommendation
Track unstaked stream consumption in a shared/global counter (analogous to `StakedStreamLoadEMA`'s staked load tracking) and divide the unstaked budget (`max_unstaked_load_in_throttling_window`) across currently-active unstaked connections, or enforce it via a single shared token bucket/EMA counter across all unstaked connections rather than an independent per-connection counter. This ensures the aggregate unstaked throughput is actually bounded by `EXPECTED_UNSTAKED_STREAMS_RATIO * max_streams_per_ms` regardless of how many distinct unstaked connections/IPs are used.

async fn test_aggregate_unstaked_streams_exceed_reserved_ratio() {
    // Spawn a QUIC server with SwQos and default SwQosConfig
    // (max_streams_per_ms = 500, EXPECTED_UNSTAKED_STREAMS_RATIO = 0.20 => 100 streams/ms reserved for unstaked)
    let SpawnTestServerResult { stats, server_address, cancel, join_handle, .. } =
        setup_quic_server(None, QuicStreamerConfig::default_for_tests(), SwQosConfig::default());

    // Simulate Sybil via IP rotation: bind N client endpoints to distinct loopback
    // addresses (127.0.0.2..127.0.0.N) to get distinct ConnectionTableKey entries.
    const N_CONNECTIONS: usize = 50;
    let mut clients = Vec::new();
    for i in 0..N_CONNECTIONS {
        let local_ip = std::net::Ipv4Addr::new(127, 0, 0, (2 + i) as u8);
        let client = make_client_endpoint_with_local_ip(&server_address, local_ip).await;
        clients.push(client);
    }

    // Each connection sends near its individual per-connection cap
    // (MAX_UNSTAKED_TPS * STREAM_THROTTLING_INTERVAL_MS / 1000 streams per interval)
    // concurrently within one STREAM_THROTTLING_INTERVAL.
    let start = tokio::time::Instant::now();
    for client in &clients {
        for i in 0..20 { // per-connection cap at defaults
            let mut s = client.open_uni().await.unwrap();
            s.write_all(format!("{i}").as_bytes()).await.unwrap();
            s.finish().unwrap();
        }
    }

    tokio::time::sleep(STREAM_THROTTLING_INTERVAL).await;

    let accepted = stats.total_new_streams.load(Ordering::Relaxed)
        - stats.throttled_unstaked_streams.load(Ordering::Relaxed);

    // Expected reserved unstaked budget for one throttling interval:
    let expected_reserved = (EXPECTED_UNSTAKED_STREAMS_RATIO
        * (DEFAULT_MAX_STREAMS_PER_MS as f64)
        * (STREAM_THROTTLING_INTERVAL_MS as f64)) as u64;

    // FAILS on current implementation: accepted aggregate unstaked streams
    // greatly exceeds the intended reserved ratio because throttling is per-connection.
    assert!(
        accepted <= expected_reserved,
        "aggregate unstaked streams accepted ({accepted}) exceeded reserved budget ({expected_reserved})"
    );

    cancel.cancel();
    join_handle.await.unwrap();
}

    pub(crate) fn available_load_capacity_in_throttling_duration(
        &self,
        peer_type: ConnectionPeerType,
        total_stake: u64,
    ) -> u64 {
        match peer_type {
            ConnectionPeerType::Unstaked => self.max_unstaked_load_in_throttling_window,
            ConnectionPeerType::Staked(stake) => {
                if self.staked_throttling_enabled.load(Ordering::Relaxed) {
                    // 1 is added to `max_unstaked_load_in_throttling_window` to guarantee that staked
                    // clients get at least 1 more number of streams than unstaked connections.
                    self.max_staked_load_in_throttling_window
                        .saturating_mul(stake)
                        .checked_div(total_stake)
                        .unwrap_or(self.max_unstaked_load_in_throttling_window + 1)
                        .max(self.max_unstaked_load_in_throttling_window + 1)
                } else {
                    self.max_staked_load_in_throttling_window
                }
            }
        }
    }

pub(crate) async fn throttle_stream(
    stats: &StreamerStats,
    peer_type: ConnectionPeerType,
    remote_addr: std::net::SocketAddr,
    stream_counter: &Arc<ConnectionStreamCounter>,
    max_streams_per_throttling_interval: u64,
) {
    let throttle_interval_start = stream_counter.reset_throttling_params_if_needed();
    let streams_read_in_throttle_interval = stream_counter.stream_count.load(Ordering::Relaxed);
    if streams_read_in_throttle_interval >= max_streams_per_throttling_interval {
        // The peer is sending faster than we're willing to read. Sleep for what's
        // left of this read interval so the peer backs off.
        let throttle_duration =
            STREAM_THROTTLING_INTERVAL.saturating_sub(throttle_interval_start.elapsed());

        if !throttle_duration.is_zero() {
            debug!(
                "Throttling stream from {remote_addr:?}, peer type: {peer_type:?}, \
                 max_streams_per_interval: {max_streams_per_throttling_interval}, \
                 read_interval_streams: {streams_read_in_throttle_interval} throttle_duration: \
                 {throttle_duration:?}"
            );
            stats.throttled_streams.fetch_add(1, Ordering::Relaxed);
            match peer_type {
                ConnectionPeerType::Unstaked => {
                    stats
                        .throttled_unstaked_streams
                        .fetch_add(1, Ordering::Relaxed);
                }
                ConnectionPeerType::Staked(_) => {
                    stats
                        .throttled_staked_streams
                        .fetch_add(1, Ordering::Relaxed);
                }
            }
            sleep(throttle_duration).await;
        }
    }
}

    fn remove_connection(
        &self,
        conn_context: &SwQosConnectionContext,
        connection: Connection,
    ) -> impl Future<Output = usize> + Send {
        async move {
            let mut lock = if conn_context.in_staked_table {
                self.staked_connection_table.lock().await
            } else {
                self.unstaked_connection_table.lock().await
            };

            let stable_id = connection.stable_id();
            let remote_addr = conn_context.remote_address;

            let removed_count = lock.remove_connection(

                stable_id,
            );
            update_open_connections_stat(&self.stats, &lock);
            removed_count
        }
    }
