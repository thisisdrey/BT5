### Title
Signer event HTTP listener has no authentication of the sender — any TCP client can forge `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block` events - ([File: libsigner/src/events.rs])

### Summary
`SignerEventReceiver::next_event` routes incoming HTTP requests purely by `request.url()` and `request.method()`, with no shared secret, mTLS, or source-IP check verifying that the request actually originated from the configured Stacks node. Any TCP client that can reach the signer's bound `HttpServer` can POST forged JSON to the four dispatch routes and have it accepted, JSON-decoded, and forwarded into the signer's runloop as a trusted `SignerEvent`.

### Finding Description
The equality the design assumes — "source of event == the node the signer is configured to trust" — is never checked. `next_event` only inspects `request.url()`/`request.method()` before calling `process_event::<T, E>`: [1](#0-0) 

`process_event` reads the raw body, ACKs it, and directly `serde_json::from_slice`s it into the target event type, then converts it into a `SignerEvent<T>` with `try_into()` — no signature, token, or peer-identity check anywhere in this path: [2](#0-1) 

For `/stackerdb_chunks`, the `TryFrom<StackerDBChunksEvent>` conversion trusts the event's `contract_id` and `modified_slots` as given; for the `.miners` boot contract branch it deserializes chunk payloads with **no signature recovery at all** (unlike the `signers-X-Y` branch, which at least calls `chunk.recover_pk()` on the chunk's own embedded signature — itself attacker-suppliable since the whole JSON, including `chunk.data` and any signature bytes inside it, is attacker-controlled): [3](#0-2) 

Because this HTTP listener is a distinct process/port from the node's authenticated RPC (`auth_token`/`auth_password` only guards the node's own `/v2/block_proposal` endpoint, not the signer's event-intake port), and the shipped sample signer config explicitly binds it to `0.0.0.0:30000` (all interfaces) rather than loopback, the endpoint is remotely reachable with zero credentials: [4](#0-3) 

The existing unit test demonstrates the exact exploit primitive: a bare `TcpStream::connect` plus a hand-crafted `POST /stackerdb_chunks` HTTP request is sufficient to inject an event, with no authentication material sent: [5](#0-4) 

The project itself acknowledges this exact risk in a runtime warning rather than enforcing it in code: [6](#0-5) 

### Impact Explanation
An attacker who can reach the signer's bound event port can forge, for each of the four routes:
- `/proposal_response`: inject an arbitrary `BlockValidateResponse`, making the signer's runloop believe the real node validated (accepted or rejected) a block it never actually validated — i.e., unauthenticated write of forged "validation result" state into the signer, which can drive the signer to sign a block that was never genuinely checked.
- `/stackerdb_chunks`: inject fake miner/signer StackerDB chunk events, including unsigned miner-lane payloads (no `recover_pk` check on that branch), directly into the signer's event stream.
- `/new_burn_block` and `/new_block`: inject forged burn/Stacks block-height, hash, and transaction data, corrupting the signer's view of chain tip/state with data no canonical block or burn event actually committed.

This is repeatable per TCP connection with no rate limit tied to authentication, and matches the Critical category ("unauthenticated/unauthorized write to state ... auth bypass").

### Likelihood Explanation
No signer/node secret, peer key, or slot ownership is required — only network reachability to the bound `SocketAddr`. The shipped reference config binds the listener to `0.0.0.0`, and the code contains only an operational warning (not an enforced control) advising operators to keep this local. Any attacker who can route TCP to that port (e.g., misconfigured firewall, cloud security-group, or multi-host signer deployment) can exploit this trivially and repeatedly.

### Recommendation
Add an authentication gate in `SignerEventReceiver::next_event`/`process_event` before dispatch — e.g., require and verify a shared-secret header/token (mirroring the node's `auth_token`) or bind by default to loopback only and document/enforce it, and/or verify a per-request HMAC/signature from the node over the body before trusting `StackerDBChunksEvent`, `BlockValidateResponse`, burn/block events.

### Proof of Concept
Extend `libsigner/src/tests/mod.rs`'s pattern (`test_simple_signer`) into a standalone test that:
1. Spawns a `SignerEventReceiver` bound to `127.0.0.1:PORT` via `Signer::spawn`, with no client credentials configured anywhere.
2. From a plain `TcpStream::connect(endpoint)` (no auth headers), sends a hand-crafted `POST /proposal_response HTTP/1.1` request with a fabricated `BlockValidateResponse` JSON body.
3. Asserts the HTTP response is `200`, and asserts the consumer channel receives a `SignerEvent::BlockValidationResponse(...)` matching the forged payload — proving full ingestion with no verification, analogous to the existing `/stackerdb_chunks` test at [5](#0-4) .

    fn next_event(&mut self) -> Result<SignerEvent<T>, EventError> {
        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)
            } else if request.url() == "/new_block" {
                process_event::<T, StacksBlockEvent>(request)
            } else {
                let url = request.url().to_string();
                debug!(
                    "[{:?}] next_event got request with unexpected url {}, return OK so other side doesn't keep sending this",
                    event_receiver.local_addr,
                    url
                );
                ack_dispatcher(request);
                Err(EventError::UnrecognizedEvent(url))
            }
        })?

fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}
