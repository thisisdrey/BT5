### Title
StackerDB chunk signature omits the target smart-contract identity, enabling cross-StackerDB replay of validly-signed chunks - (File: libstackerdb/src/libstackerdb.rs)

### Summary
`SlotMetadata::auth_digest()` — the digest that authenticates every StackerDB chunk write — commits only to `slot_id`, `slot_version`, and `data_hash`. It never commits to the `smart_contract_id` (the specific StackerDB/contract instance) that the chunk was intended for. Because multiple StackerDB contracts (e.g. `.signers-0-<msgid>` and `.signers-1-<msgid>` for consecutive reward cycles, or other per-message-type replicas) reuse the same set of signer addresses/slot indices across contracts, a signature that is valid for one StackerDB contract instance can be replayed verbatim by any unprivileged remote party against a *different* StackerDB contract instance where the same signer address also owns the same `slot_id`, as long as the target slot's version counter is still below the replayed value.

### Finding Description
`SlotMetadata::sign`/`verify` compute the signed digest as:
```
hasher.update(self.slot_id.to_be_bytes());
hasher.update(self.slot_version.to_be_bytes());
hasher.update(self.data_hash.0);
``` [1](#0-0) 

`StackerDBChunkData::verify()`/`recover_pk()` reuse this same contract-agnostic digest via `get_slot_metadata()`: [2](#0-1) 

The contract binding is applied *only* out-of-band, by the caller looking up the expected signer for `(smart_contract_id, slot_id)` and then calling `slot_metadata.verify(&addr)`, e.g. in `StackerDBs::validate_received_chunk`:
```
let addr = match self.stackerdbs.get_slot_signer(smart_contract_id, data.slot_id)?
...
let slot_metadata = data.get_slot_metadata();
if !slot_metadata.verify(&addr)? { ... }
``` [3](#0-2) 

and the same pattern in the HTTP write path (`RPCPostStackerDBChunkRequestHandler::try_handle_request` → `tx.try_replace_chunk(&contract_identifier, &stackerdb_chunk.get_slot_metadata(), ...)`), which is a remote, unauthenticated (no HTTP-level auth — the "authentication" is entirely the chunk signature) write endpoint at `POST /v2/stackerdb/{address}/{contract}/chunks`: [4](#0-3) 

Because the digest contains no contract/DB identifier, the same `(slot_id, slot_version, sig, data)` tuple that a legitimate signer produced for contract A is a perfectly valid signed chunk for *any* other StackerDB contract B in which that signer owns `slot_id`, provided B's stored version at that slot is `< slot_version`. Successfully accepted chunks are unconditionally relayed to the whole network as validated push-chunk gossip:
```rust
if ack_resp.accepted {
    let push_chunk_data = StackerDBPushChunkData { contract_id: contract_identifier, ... };
    node.set_relay_message(StacksMessageType::StackerDBPushChunk(push_chunk_data));
}
``` [5](#0-4) 

This exactly mirrors the Crestal `M-2` bug class: a signature is created over a subset of the semantically relevant parameters (there, `tokenId`/`privateWorkerAddress`; here, the target contract identity), so an attacker who observes the signature in transit (StackerDB writes/pushes are gossiped in plaintext over the p2p network and are visible via the public HTTP write/read endpoints) can resubmit it with a different, attacker-chosen "extra parameter" — here, a different `contract_identifier` in the URL path — that was never part of what was actually signed.

Feasibility of finding a matching signer/slot across two different contract instances is concretely supported by the codebase: the two active `.signers-N-<msg_id>` StackerDB contracts for a signer set alternate strictly by `reward_cycle % 2`, and use the *same* signer-slot assignment list source (`stackerdb-get-signer-slots-page`) which is derived from the same underlying `.signers` cycle data: [6](#0-5) [7](#0-6) 
so the same signer address routinely occupies slot `k` in more than one contract instance at overlapping or successive points in time (e.g. across the two signer-set-parity contracts, or across the several `message_id` StackerDBs for the same signer), giving an attacker ample opportunity to find a `(slot_id)` collision for a targeted signer address.

### Impact Explanation
An unprivileged remote attacker who observes any validly-signed StackerDB chunk (via p2p gossip or by directly querying `GET /v2/stackerdb/.../chunks/{slot_id}`, since StackerDB reads are public) can replay it into a different StackerDB contract where the signing address also owns that slot, without the signer's cooperation or knowledge. This is an unauthorized write to a StackerDB replica (data attributed to a signer that the signer never actually wrote/signed for that specific contract), and the acceptance triggers network-wide propagation of this forged/mis-attributed chunk via `StackerDBPushChunk` relay. Depending on which contracts collide (e.g. successive reward-cycle `.signers` state-machine/vote contracts), this can let stale or cross-cycle signer messages be injected as "validly signed" current data in a different logical StackerDB, i.e., non-canonical/out-of-context data served and propagated as canonical for that DB. This matches the report's "High" bar: serving non-canonical state as canonical / propagating forged-context data network-wide, achieved purely from message volume already available on the wire — no secret key, no admin role required.

### Likelihood Explanation
Likelihood is bounded by needing the target signer to hold the same `slot_id` in two colliding StackerDB contracts and needing the target slot's stored version to be lower than the replayed chunk's version — both of which are realistic given the deterministic, parity-based `.signers-{0,1}-{message_id}` contract-slot assignment scheme, and given that slot versions reset/restart across reward cycles' contract instances. No secrets are needed; only observation of already-broadcast signed chunks and a normal unauthenticated POST to the target contract's chunk endpoint.

### Recommendation
Bind the signed digest to the specific StackerDB instance by including the `smart_contract_id` (or a stable numeric/opaque `stackerdb_id`) inside `SlotMetadata::auth_digest()`, so a chunk signature is cryptographically scoped to exactly the (contract, slot, version, data) tuple it was produced for, mirroring the general "sign all parameters that affect state" mitigation from the referenced report.

### Proof of Concept
1. Attacker observes (via p2p relay or `GET /v2/stackerdb/{addr}/{contractA}/chunks/{slot}`) a validly-signed chunk `(slot_id=k, slot_version=v, sig=S, data=D)` written by signer address `X` into StackerDB contract `A` (e.g. `.signers-0-<msgid>`).
2. Attacker checks that `X` also owns `slot_id=k` in a different StackerDB contract `B` for which the node is a replica (e.g. `.signers-1-<msgid>`, or the same message-id contract for a different reward cycle), and that `B`'s current stored version at slot `k` is `< v`.
3. Attacker issues `POST /v2/stackerdb/{X}/{contractB}/chunks` with the exact same JSON body `{slot_id: k, slot_version: v, sig: S, data: D}` observed in step 1.
4. `tx.try_replace_chunk` looks up the slot signer for `contractB`/`k` (which is `X`), calls `slot_metadata.verify(&addr)`, which succeeds because the digest never included the contract identifier — the write is accepted as `accepted: true`, stored, and relayed via `StackerDBPushChunk` to the network as legitimate data for contract `B`, despite `X` never having signed anything intended for `B`.

    /// Get the digest to sign that authenticates this chunk data and metadata
    fn auth_digest(&self) -> Sha512Trunc256Sum {
        let mut hasher = Sha512_256::new();
        hasher.update(self.slot_id.to_be_bytes());
        hasher.update(self.slot_version.to_be_bytes());
        hasher.update(self.data_hash.0);
        Sha512Trunc256Sum::from_hasher(hasher)
    }

    pub fn get_slot_metadata(&self) -> SlotMetadata {
        SlotMetadata {
            slot_id: self.slot_id,
            slot_version: self.slot_version,
            data_hash: self.data_hash(),
            signature: self.sig.clone(),
        }
    }

    /// Sign this given chunk data message with the given private key.
    /// Sets self.signature to the signature.
    /// Fails if the underlying signing library fails.
    pub fn sign(&mut self, privk: &StacksPrivateKey) -> Result<(), Error> {
        let mut md = self.get_slot_metadata();
        md.sign(privk)?;
        self.sig = md.signature;
        Ok(())
    }

    pub fn recover_pk(&self) -> Result<StacksPublicKey, Error> {
        let digest = self.get_slot_metadata().auth_digest();
        StacksPublicKey::recover_to_pubkey_without_validating_low_s(digest.as_bytes(), &self.sig)
            .map_err(|ve| Error::VerifyingError(ve.to_string()))
    }

    /// Verify that this chunk was signed by the given
    /// public key hash (`addr`).  Only fails if the underlying signing library fails.
    pub fn verify(&self, addr: &StacksAddress) -> Result<bool, Error> {
        let md = self.get_slot_metadata();
        md.verify(addr)
    }
