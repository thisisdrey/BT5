### Title
Unauthenticated pre-handshake connection flood bypasses per-IP/global rate limiters and exhausts the global `open_connections` counter, causing DoS of legitimate TPU clients - (File: `streamer/src/nonblocking/quic.rs`)

### Summary
`ClientConnectionTracker::new` gates ingress purely on a single global atomic counter (`stats.open_connections`) compared against `qos.max_concurrent_connections()`, and this counter is incremented for every `Incoming` connection *before* the QUIC handshake completes. Both the per-IP rate limiter (`ConnectionRateLimiter::is_allowed`) and the global rate limiter (`TokenBucket::current_tokens`) are advisory checks only — they never *consume* a token/record until after the handshake finishes in `setup_connection`, so an attacker who never completes the handshake is invisible to both limiters and can flood `open_connections` up to the cap, refusing all subsequent legitimate connections (staked or not) until `QUIC_CONNECTION_HANDSHAKE_TIMEOUT` expires.

### Finding Description
In `run_server` (`streamer/src/nonblocking/quic.rs:304-411`), for every accepted `Incoming` the following gates run in order:
1. `overall_connection_rate_limiter.current_tokens() == 0` — a read-only check, no tokens consumed here. [1](#0-0) 
2. `rate_limiter.is_allowed(&incoming.remote_address().ip())` — per-IP check. [2](#0-1) 
3. `ClientConnectionTracker::new(stats.clone(), qos.max_concurrent_connections())`, which does `stats.open_connections.fetch_add(1, …)` and only fails/refuses once the global counter reaches `max_concurrent_connections`. [3](#0-2) 

Crucially, both rate limiters are only ever *updated* (tokens consumed / IP registered) after the handshake completes, inside `setup_connection`: [4](#0-3) 

Looking at `ConnectionRateLimiter::is_allowed`, an IP that has never previously completed a handshake has no record in the limiter map, so `is_allowed` unconditionally returns `true` regardless of how many concurrent Incoming attempts are outstanding from that IP: [5](#0-4) 

Similarly `register_connection` (which actually consumes a token in `overall_connection_rate_limiter`/`rate_limiter`) is only called after `timeout(QUIC_CONNECTION_HANDSHAKE_TIMEOUT, connecting).await` resolves successfully: [6](#0-5) 

Thus an attacker that opens QUIC connections but deliberately stalls the TLS/QUIC handshake (e.g., sends the Initial packet then goes silent, or artificially delays subsequent flight) will:
- Pass the global rate limiter check (never consumes tokens, so `current_tokens()` stays at burst capacity).
- Pass the per-IP check (`is_allowed` returns `true` since the IP is never registered).
- Successfully call `ClientConnectionTracker::new`, incrementing `stats.open_connections`.
- Never reach `register_connection`/`consume_tokens`, and never get added into a `ConnectionTable` (staked/unstaked), since that only happens via `qos.try_add_connection` after the handshake succeeds inside `setup_connection`. [7](#0-6) 

By repeating this `max_concurrent_connections` times — where `max_concurrent_connections = (max_staked_connections + max_unstaked_connections) * 5 / 4` — the attacker saturates `stats.open_connections` before ever hitting the `ConnectionTable` per-peer limits. Once saturated, all subsequent `Incoming`s (from staked or unstaked, legitimate clients included) fail `ClientConnectionTracker::new` and are refused: [3](#0-2) [8](#0-7) 

The condition persists until each stalled connection's `timeout(QUIC_CONNECTION_HANDSHAKE_TIMEOUT, connecting)` fires and `ClientConnectionTracker`'s `Drop` decrements the counter: [9](#0-8) 

An attacker can then simply re-open new stalled connections just before the old ones time out, keeping the counter perpetually saturated with a comparatively small, steady stream of half-open connections — no completed handshakes, no stake, and no bypass of any per-peer `ConnectionTable` limit is required.

### Impact Explanation
This is a QoS/availability bypass: a single unstaked, unauthenticated attacker can deny all TPU/TPU-forward QUIC ingress (staked and unstaked alike) at a leader by keeping roughly `max_concurrent_connections` connections perpetually half-open, since the mechanism intended to bound resource use per-IP/globally (`ConnectionRateLimiter`, `TokenBucket`) is only enforced post-handshake and thus does not gate the resource (`open_connections`) that is actually being exhausted. This falls into the "bounded ingress buffers/counters regardless of packet volume" invariant violation and the QoS-evasion / DoS bounty category, since legitimate staked validators can be starved of leader TPU connectivity.

### Likelihood Explanation
Feasible with unprivileged access: the attacker only needs to be able to send QUIC Initial packets and control how quickly (or whether) it completes the cryptographic handshake — no special network position, no IP spoofing, and no stake required. The number of concurrent stalled connections needed equals `max_concurrent_connections`, a bounded value derived from validator CLI/config (`tpu_max_staked_connections`/`tpu_max_unstaked_connections`), which is realistically reachable by a single attacking host opening that many sockets. The attack is fully repeatable and can be sustained indefinitely by refreshing stalled connections just under `QUIC_CONNECTION_HANDSHAKE_TIMEOUT`.

### Recommendation
Enforce the per-IP and global rate limiters *before* incrementing `open_connections` (i.e., check-and-reserve semantics at `Incoming` time rather than deferring token consumption to post-handshake), or bound the number of pre-handshake ("outstanding") connections per-IP independently of the post-handshake `ConnectionTable`, so that a flood of stalled handshakes from one or few IPs cannot saturate the shared global counter that gates all clients. Consider tracking `outstanding_incoming_connection_attempts` (already counted) per-IP with its own cap, separate from `max_concurrent_connections`.

### Proof of Concept
Integration test plan (in `streamer/src/nonblocking/quic.rs` test module, using existing `setup_quic_server`/`make_client_endpoint` helpers):
```rust
#[tokio::test(flavor = "multi_thread")]
async fn test_stalled_handshakes_exhaust_open_connections_dos() {
    let SpawnTestServerResult { server_address, stats, cancel, join_handle, .. } =
        setup_quic_server(None, QuicStreamerConfig::default_for_tests(), SwQosConfig::default());

    // qos.max_concurrent_connections() == (max_staked + max_unstaked) * 5 / 4
    let max_concurrent = (SwQosConfig::default().max_staked_connections
        + SwQosConfig::default().max_unstaked_connections) * 5 / 4;

    // Open `max_concurrent` client endpoints that send the QUIC Initial packet
    // but never complete the handshake (e.g. client configured to stop responding
    // after Initial, or connect from an endpoint whose keys/cert cause the
    // handshake to stall indefinitely on the server side).
    let mut stalled = Vec::new();
    for _ in 0..max_concurrent {
        let endpoint = make_stalled_client_endpoint(&server_address).await; // sends Initial, never finishes
        stalled.push(endpoint);
    }

    // Give the server time to register all Incoming via ClientConnectionTracker::new.
    tokio::time::sleep(Duration::from_millis(200)).await;
    assert_eq!(stats.open_connections.load(Ordering::Relaxed), max_concurrent);

    // A legitimate, well-behaved client attempts to connect and should be refused.
    let legit_client = make_client_endpoint(&server_address, None).await;
    let result = legit_client_connect_and_expect_refused(&server_address).await;
    assert!(result.is_err());
    assert!(stats.refused_connections_too_many_open_connections.load(Ordering::Relaxed) > 0);

    // After QUIC_CONNECTION_HANDSHAKE_TIMEOUT, stalled trackers drop and counter resets.
    tokio::time::sleep(QUIC_CONNECTION_HANDSHAKE_TIMEOUT + Duration::from_millis(500)).await;
    assert_eq!(stats.open_connections.load(Ordering::Relaxed), 0);

    cancel.cancel();
    join_handle.await.unwrap();
}
```
Expected assertions: `stats.open_connections` reaches `max_concurrent_connections` from attacker-controlled stalled handshakes alone (none reach `ConnectionTable`), the legitimate client's connection is refused (`refused_connections_too_many_open_connections` increments), and normal service only resumes after `QUIC_CONNECTION_HANDSHAKE_TIMEOUT`.

    /// Here we assume that only IPs with actual confirmed connections are stored in it,

    pub fn is_allowed(&self, ip: &IpAddr) -> bool {
        // Check if we have records in the rate limiter for the given IP address
        match self.limiter.current_tokens(ip) {
            Some(r) => r > 0, // we have a record, and rate is not exceeded
            None => true,     // if we have not seen IP, allow connection request
