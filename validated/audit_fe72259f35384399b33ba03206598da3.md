### Title
Deterministic, project-ID-derived object-pool path allows pre-creation squatting of another repository's pool - ([File: internal/gitaly/storage/repository_path.go], [File: internal/gitaly/service/objectpool/create.go])

### Summary
`CreateObjectPool` accepts any client-supplied relative path that merely matches the "looks like a pool" naming convention, `@pools/<xx>/<yy>/<sha>.git` (Rails-style) — checked only via a regex format test — and Praefect's own internal replica path (`@cluster/pools/<xx>/<yy>/<repository-id>`) is derived deterministically from a public, sequential/guessable repository ID via `DerivePoolPath()`. Neither path incorporates any secret or ownership proof tying the physical location to the specific origin repository it will later be linked to. This mirrors the SuperchainTokenBridge bug: an entity's on-disk "address" is fully deterministic from public inputs, and the protocol trusts that address as a proxy for identity without verifying that whoever created something there is authorized to.

### Finding Description
Two path-derivation mechanisms decide where an object pool lives on disk, and both are purely deterministic functions of externally visible/guessable data:

- `storage.IsPoolRepository` / `IsRailsPoolRepository` only checks that a `RelativePath` matches the regex `@pools/([0-9a-f]{2})/([0-9a-f]{2})/([0-9a-f]{64})\.git` with the first four hex digits matching the folder prefix. [1](#0-0) 
- `storage.DerivePoolPath(repositoryID)` computes the on-disk pool path solely from the sequential integer repository ID via SHA256, and this ID is reserved beforehand by Praefect's router (`ReserveRepositoryID`) before the pool is actually created. [2](#0-1) [3](#0-2) 

`CreateObjectPool` only validates that the *format* of the requested pool relative path matches this convention — it never validates that the caller is authorized for, or has any special relationship to, that exact path, nor does it check that the path hasn't already been raced/pre-populated by another actor with unrelated content: [4](#0-3) 

The actual object-pool clone step (`objectpool.Create`) only checks that the target path doesn't already exist on disk before cloning into it — a simple `os.Stat` check with no ownership/content verification: [5](#0-4) 

Because the pool's identity (its file-system address) is fully computable in advance from public identifiers (a monotonically increasing repository ID, or a hex-encoded hash that is checked only for *shape*, not for *provenance*), an attacker who can create ordinary repositories via `CreateRepository`/`CreateRepositoryFromURL`/`CreateFork` (a normal user-permission RPC) can pre-populate the exact relative path that a to-be-created legitimate pool will occupy. `repoutil.Create`, used by both plain repository creation and object-pool creation, treats "path already exists" as the only race guard, and does not verify the identity of whoever created the pre-existing directory: [6](#0-5) [7](#0-6) 

Once linked via `objects/info/alternates` (`Link`/`getRelativeObjectPath`), the member repository's object lookups transparently traverse into whatever objects live at that deterministic path — Gitaly's alternates resolution simply walks the recorded directory: [8](#0-7) [9](#0-8) 

### Impact Explanation
If an attacker predicts (or races) the deterministic pool path for a repository they don't own — either the sequential Praefect-assigned `@cluster/pools/<id>` path (IDs are sequential and thus enumerable/guessable ahead of creation) or a Rails-style `@pools/<hash>.git` path whose format check has no ownership binding — they can:
1. Create a normal-looking repository at that exact path first (via a standard repository-creation RPC), causing legitimate `CreateObjectPool` for the real project to fail with "target path exists already" (denial of service against fork/object-pool housekeeping for that project), or
2. If timing allows the attacker's directory to instead be adopted as the pool and subsequently linked via alternates to the victim repository, the victim repository's Git operations begin resolving objects out of the attacker-controlled object directory, effectively smuggling attacker-chosen objects into the victim's reachable object graph — the same "any two addressable entities are treated as interchangeable" confusion described in the report, translated to Gitaly's content-addressed/path-addressed object storage.

This is High severity in spirit: cross-repository object exposure/injection and disk-path squatting are core storage-isolation guarantees Gitaly is expected to provide.

### Likelihood Explanation
Exploitability depends on timing/races and on how strictly Rails/Praefect gate direct `RelativePath` values before they reach Gitaly (this repo's index doesn't show gate-keeping beyond the regex/ID-derivation checks cited above). The repository-ID sequence used by `DerivePoolPath` is not secret, making prediction of the future pool path for a soon-to-be-created project straightforward for a determined actor with ordinary account access. The primary uncertainty is whether an intermediate layer (Rails or Praefect's coordinator/router) enforces additional authorization on `RelativePath` before invoking `CreateRepository`/`CreateObjectPool`, which is outside the indexed Gitaly code and could not be fully confirmed here.

### Recommendation
Do not rely purely on path-format/derivation to establish trust in an object pool's identity. `CreateObjectPool` and `Link` should verify a cryptographic or transactional binding between the origin repository and the pool directory (e.g., the pool must have been created for this exact origin as recorded by an authoritative source, not merely by matching a naming pattern), and repository/pool creation should fail-closed (with an explicit integrity/ownership error, not a generic "already exists") whenever the target path is occupied by content that wasn't produced by the expected `CreateObjectPool` flow for that origin.

### Proof of Concept
Conceptual PoC (cannot be fully executed against this index without live Praefect/Rails wiring):
1. Observe/predict the next sequential repository ID that Praefect's `ReserveRepositoryID` will hand out for a target project about to be forked or pooled (IDs are monotonic and low-entropy).
2. Compute `storage.DerivePoolPath(nextID)` (or a Rails-style `@pools/aa/bb/<64-hex>.git` path passing only the format regex).
3. Issue an ordinary `CreateRepository`/`CreateRepositoryFromURL` RPC targeting that exact `RelativePath` before the victim's `CreateObjectPool` runs.
4. Legitimate `CreateObjectPool` for the victim project now either fails (`target path exists already`, per `internal/git/objectpool/create.go:42-48`) causing denial of pooling/fork deduplication, or — depending on race ordering — the attacker's pre-existing directory becomes bound as the alternate object source for the victim repository once `Link` writes the alternates file, exposing/mixing the attacker's objects into the victim repository's object graph.

func IsRailsPoolRepository(repo Repository) bool {
	matches := railsPoolDirRegexp.FindStringSubmatch(repo.GetRelativePath())
	if matches == nil || !strings.HasPrefix(matches[3], matches[1]+matches[2]) {
		return false
	}

	return true
}

// IsPraefectPoolRepository returns whether the repository is a Praefect generated object pool repository.
func IsPraefectPoolRepository(repo Repository) bool {
	return praefectPoolDirRegexp.MatchString(repo.GetRelativePath())
}

// IsPoolRepository returns whether the repository is an object pool.
func IsPoolRepository(repo Repository) bool {
	return IsRailsPoolRepository(repo) || IsPraefectPoolRepository(repo)
}

// DeriveReplicaPath derives a repository's disk storage path from its repository ID. The repository ID
// is hashed with SHA256 and the first four hex digits of the hash are used as the two subdirectories to
// ensure even distribution into subdirectories. The format is @cluster/repositories/ab/cd/<repository-id>.
func DeriveReplicaPath(repositoryID int64) string {
	return deriveDiskPath(praefectRepositoryPathPrefix, repositoryID)
}

// DerivePoolPath derives an object pools's disk storage path from its repository ID. The repository ID
// is hashed with SHA256 and the first four hex digits of the hash are used as the two subdirectories to
// ensure even distribution into subdirectories. The format is @cluster/pools/ab/cd/<repository-id>. The pools
// have a different directory prefix from other repositories so Gitaly can identify them in OptimizeRepository
// and avoid pruning them.
func DerivePoolPath(repositoryID int64) string {
	return deriveDiskPath(praefectPoolPathPrefix, repositoryID)
}

func deriveDiskPath(prefixDir string, repositoryID int64) string {
	hasher := sha256.New()
	// String representation of the ID is used to make it easier to derive the replica paths with
	// external tools. The error is ignored as the hash.Hash interface is documented to never return
	// an error.
	hasher.Write([]byte(strconv.FormatInt(repositoryID, 10)))
	hash := hasher.Sum(nil)
	return filepath.Join(prefixDir, fmt.Sprintf("%x/%x/%d", hash[0:1], hash[1:2], repositoryID))

func getRelativeObjectPath(ctx context.Context, pool, repo *localrepo.Repo) (string, error) {
	poolPath, err := pool.Path(ctx)
	if err != nil {
		return "", fmt.Errorf("getting object pool path: %w", err)
	}

	repoPath, err := repo.Path(ctx)
	if err != nil {
		return "", fmt.Errorf("getting repository path: %w", err)
	}

	relPath, err := filepath.Rel(filepath.Join(repoPath, "objects"), poolPath)
	if err != nil {
		return "", err
	}

	return filepath.Join(relPath, "objects"), nil
}

func altObjectDirs(ctx context.Context, logger log.Logger, storagePrefix, objDir string, depth int) ([]string, error) {
	const maxAlternatesDepth = 5 // Taken from https://github.com/git/git/blob/v2.23.0/sha1-file.c#L575
	if depth > maxAlternatesDepth {
		logger.WithField("objdir", objDir).WarnContext(ctx, "ignoring deeply nested alternate object directory")
		return nil, nil
	}

	fi, err := os.Stat(objDir)
	if os.IsNotExist(err) {
		logger.WithField("objdir", objDir).WarnContext(ctx, "object directory not found")
		return nil, nil
	}
	if err != nil {
		return nil, err
	}
	if !fi.IsDir() {
		return nil, nil
	}

	dirs := []string{objDir}

	alternates, err := os.ReadFile(filepath.Join(objDir, "info", "alternates"))
	if os.IsNotExist(err) {
		return dirs, nil
	}
	if err != nil {
		return nil, err
	}

	for _, newDir := range strings.Split(string(alternates), "\n") {
		if len(newDir) == 0 || newDir[0] == '#' {
			continue
		}

		if !filepath.IsAbs(newDir) {
			newDir = filepath.Join(objDir, newDir)
		}

		if !strings.HasPrefix(newDir, storagePrefix) {
			return nil, alternateOutsideStorageError(newDir)
		}

		nestedDirs, err := altObjectDirs(ctx, logger, storagePrefix, newDir, depth+1)
		if err != nil {
			return nil, err
		}

		dirs = append(dirs, nestedDirs...)
	}

	return dirs, nil
}
