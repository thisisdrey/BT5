### Title
Panic inside `with_server`'s closure permanently disables `next_event()` by leaving `http_server` as `None` - (File: `libsigner/src/events.rs`)

### Summary
`SignerEventReceiver::with_server` takes the `HttpServer` out of `self.http_server` via `.take()` before invoking the caller-supplied closure, and only puts it back into `self.http_server` *after* the closure returns normally. If the closure panics, the stack unwinds past the restore line and `self.http_server` is permanently left as `None`, so every subsequent `next_event()` call returns `EventError::NotBound` for the rest of the process's life.

### Finding Description
`with_server` is implemented as: [1](#0-0) 

`self.http_server.take()` removes the `HttpServer` from the struct field first; the field is only repopulated by `self.http_server = Some(server);` on line 355, which executes strictly after `todo(...)` returns. There is no `catch_unwind`, no `Drop` guard, and no `finally`-style construct protecting that assignment. Any panic raised while executing `todo` unwinds through `with_server` without restoring `self.http_server`, and the local `server` variable (which still owns the live socket) is dropped during unwinding rather than being placed back into the struct.

`next_event()` calls `self.with_server(...)` with a closure that ultimately calls `request.recv()`, dispatches by URL, and for `/status` requests does: [2](#0-1) 

`request.respond(...).expect("response failed")` is a confirmed, unguarded panic site reachable directly from the closure passed to `with_server`. Any remote peer that connects to the bound HTTP port, sends a well-formed `GET /status` (or generates a `respond()` I/O failure some other way, e.g., resetting the connection or timing out before the response is flushed by `tiny_http`), can cause `respond()` to return an `Err`, which is turned into a panic via `.expect(...)`. That panic unwinds past `with_server`'s restore line, permanently leaving `self.http_server == None`.

I was not able to find an equivalent unconditional panic (`unwrap`/`expect`/unchecked arithmetic) inside the JSON deserialization/conversion chain for `StackerDBChunksEvent` or `StacksBlockEvent` as originally hypothesized in the prompt — `process_event`, the `TryFrom<StackerDBChunksEvent>` and `TryFrom<StacksBlockEvent>` impls, and `deserialize_raw_tx_hex` all route errors through `Result`/`map_err`/`Ok(...)?` rather than panicking: [3](#0-2) [4](#0-3) [5](#0-4) 
I could not further trace the `Deserialize` derive internals of `StackerDBChunksEvent`/`BurnBlockEvent` (defined in `blockstack_lib::chainstate::stacks::events`, outside this file) within the available tool budget, so I cannot confirm or rule out an arithmetic-overflow panic there. That specific sub-claim from the prompt is unverified.

What is confirmed is the general fault: **the take-then-restore-after-panic pattern in `with_server` has no panic safety**, and there is at least one concrete, remotely-triggerable panic path (`/status`'s `.expect("response failed")`) that exercises it without any malformed JSON at all.

### Impact Explanation
A single successful trigger (a `/status` GET whose response write fails, or a closure panic from any other future code path) permanently sets `self.http_server` to `None`. From that point on:
- `next_event()` always returns `Err(EventError::NotBound)`.
- The signer's HTTP event-receiver thread's `main_loop` will busy-loop logging warnings and never process another `/stackerdb_chunks`, `/new_block`, `/proposal_response`, `/new_burn_block`, or `/shutdown` event.
- This is a persistent, single-message DoS against the signer's event pipeline (the node can no longer deliver StackerDB chunks or block events to that signer), which matches the "Critical - remote crash/unauthenticated DoS from few messages" category, since it disables a remotely-reachable service permanently from one interaction.

### Likelihood Explanation
- The `/status` endpoint requires no authentication and is reachable by anyone who can reach the signer's event HTTP port.
- Triggering a `respond()` I/O error is not fully deterministic (it depends on `tiny_http`/OS socket behavior, e.g. an attacker closing/resetting the TCP connection right after sending the request but before the response is flushed), so exploitation reliability for this exact path is uncertain and may require several attempts.
- The broader structural flaw (no panic guard in `with_server`) is 100% certain from the code and would be triggered by any future panic introduced anywhere in the `next_event` closure, making the class of bug itself high-likelihood/low-effort to hit accidentally or intentionally, even though the specific JSON-overflow trigger asserted in the prompt is unconfirmed.

### Recommendation
Make `with_server` panic-safe: use a `Drop`-guard (or `std::panic::catch_unwind`) to guarantee `self.http_server` is restored (or the receiver is otherwise marked unusable and re-bindable) regardless of whether `todo` panics. Additionally, replace `request.respond(...).expect("response failed")` on the `/status` path with proper error handling (log and continue) so a client-side connection failure cannot panic the receiver thread at all.

### Proof of Concept

```rust
// libsigner/src/events.rs (test module)
#[test]
fn status_response_failure_disables_next_event_permanently() {
    let mut receiver: SignerEventReceiver<crate::v0::messages::SignerMessage> =
        SignerEventReceiver::new(false);
    let addr = receiver.bind("127.0.0.1:0".parse().unwrap()).unwrap();

    let handle = std::thread::spawn(move || {
        // Connect, send a GET /status request, then immediately close the
        // socket (RST) before the server can flush its response, causing
        // `request.respond(...)` to return Err and `.expect(...)` to panic
        // inside the `with_server` closure.
        use std::net::TcpStream;
        use std::io::Write;
        let mut stream = TcpStream::connect(addr).unwrap();
        stream.write_all(b"GET /status HTTP/1.1\r\nHost: x\r\nConnection: close\r\n\r\n").unwrap();
        stream.set_linger(Some(std::time::Duration::from_secs(0))).ok();
        drop(stream); // hard reset before response is sent
    });

    let result = std::panic::catch_unwind(std::panic::AssertUnwindSafe(|| {
        receiver.next_event()
    }));
    handle.join().unwrap();

    // If the panic occurred, http_server is now None and every future
    // call returns NotBound instead of recovering.
    assert!(result.is_err() || matches!(receiver.next_event(), Err(EventError::NotBound)));
    assert!(matches!(receiver.next_event(), Err(EventError::NotBound)));
}
```
Note: reliably forcing `respond()` to fail is timing/OS dependent; a more deterministic PoC would inject a custom `todo` closure directly via `with_server` (if made `pub(crate)`/testable) that panics unconditionally, then assert `self.http_server.is_none()` and that subsequent `next_event()` calls return `EventError::NotBound`.

```rust
    where
        F: FnOnce(&SignerEventReceiver<T>, &mut HttpServer, bool) -> R,
    {
        let mut server = if let Some(s) = self.http_server.take() {
            s
        } else {
            return Err(EventError::NotBound);
        };

        let res = todo(self, &mut server, self.is_mainnet);

        self.http_server = Some(server);
        Ok(res)
    }
```

```rust
fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}
```

```rust
impl<T: SignerEventTrait> TryFrom<StackerDBChunksEvent> for SignerEvent<T> {
    type Error = EventError;

    fn try_from(event: StackerDBChunksEvent) -> Result<Self, Self::Error> {
        let received_time = SystemTime::now();
        let signer_event = if event.contract_id.name.as_str() == MINERS_NAME
            && event.contract_id.is_boot()
        {
            let mut messages = vec![];
            for chunk in event.modified_slots {
                match T::consensus_deserialize(&mut chunk.data.as_slice()) {
                    Ok(msg) => messages.push(msg),
                    Err(e) => {
                        debug!(
                            "Signer failed to deserialize miner chunk";
                            "slot_id" => chunk.slot_id,
                            "slot_version" => chunk.slot_version,
                            "data_len" => chunk.data.len(),
                            "error" => %e,
                        );
                    }
                }
            }
            SignerEvent::MinerMessages(messages)
        } else if event.contract_id.name.starts_with(SIGNERS_NAME) && event.contract_id.is_boot() {
            let Some((signer_set, message_id)) =
                get_signers_db_signer_set_message_id(event.contract_id.name.as_str())
            else {
                return Err(EventError::UnrecognizedStackerDBContract(event.contract_id));
            };
            // signer-XXX-YYY boot contract
            //
            // NOTE: the payload-type check below uses v0 `SignerMessageTypePrefix` semantics
            // (the mapping in `signer_message_payload_matches_lane` is fixed to v0). Future
            // signer-message versions must extend that mapping, or their chunks will not be
            // recognized here regardless of which `T` is in scope.
            let messages: Vec<_> = event
                .modified_slots
                .iter()
                .filter_map(|chunk| {
                    // Accept only payloads whose type is valid for this contract's message id.
                    let &type_byte = chunk.data.first()?;
                    let payload_kind = SignerMessageTypePrefix::from_u8(type_byte)?;
                    if !signer_message_payload_matches_lane(payload_kind, message_id) {
                        warn!(
                            "Skipping signer chunk with unexpected payload type for contract";
                            "contract" => %event.contract_id,
                            "lane_message_id" => message_id,
                            "payload_type_prefix" => type_byte,
                        );
                        return None;
                    }
                    let Ok(pk) = chunk.recover_pk() else {
                        warn!(
                            "Skipping signer chunk: signature recovery failed";
                            "contract" => %event.contract_id,
                            "slot_id" => chunk.slot_id,
                        );
                        return None;
                    };
                    let Ok(message) = read_next::<T, _>(&mut &chunk.data[..]) else {
                        warn!(
                            "Skipping signer chunk: payload deserialization failed";
                            "contract" => %event.contract_id,
                            "slot_id" => chunk.slot_id,
                        );
                        return None;
                    };
                    Some((chunk.slot_id, pk, message))
                })
                .collect();
            SignerEvent::SignerMessages {
                signer_set,
                messages,
                received_time,
            }
        } else {
            return Err(EventError::UnrecognizedStackerDBContract(event.contract_id));
        };
        Ok(signer_event)
    }
}
```

```rust
fn deserialize_raw_tx_hex<'de, D: serde::Deserializer<'de>>(
    d: D,
) -> Result<Vec<StacksTransaction>, D::Error> {
    let tx_objs: Vec<NewBlockTransaction> = serde::Deserialize::deserialize(d)?;
    Ok(tx_objs

        .into_iter()

        .collect::<Vec<_>>())
```
