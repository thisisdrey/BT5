### Title
Sigverify's priority-floor check performs full transaction parsing and cost-model computation on every packet in a batch — including pre-signature-verification and even when the whole batch is ultimately dropped — enabling unauthenticated, underpriced CPU amplification ([File: core/src/sigverify.rs])

### Summary
`SigVerifyWorkerPool::run_transaction_task` invokes `apply_priority_floor_to_batch`, which iterates every non-discarded packet in a batch and calls `calculate_priority_from_bytes` on each one, fully sanitizing the transaction and running the cost model and fee calculation, before any Ed25519 signature verification occurs. An unstaked attacker can therefore force this parse-and-cost-model work on arbitrary packets (syntactically valid but with invalid signatures and sub-floor priority) with zero probability of ever paying a fee, and the loop performs this work for the entire batch even though the outcome is `all_below == true` and the batch is discarded wholesale.

### Finding Description
`apply_priority_floor_to_batch` loops over every packet in the batch and, for each non-discarded packet, calls `calculate_priority_from_bytes(bank, data)`, which performs `SanitizedTransactionView::try_new_sanitized`, `RuntimeTransaction::try_new`, and `calculate_priority_and_cost` (running `CostModel::calculate_cost_for_executed_transaction` and `solana_fee::calculate_fee_details`) [1](#0-0) [2](#0-1) . This happens in `run_transaction_task` *before* `sigverify::ed25519_verify_serial` is called [3](#0-2) , meaning the packet's signature has not yet been validated when this expensive parse-and-cost computation runs. There is no early exit: even when the batch will end up fully below-floor (`all_below == true`, the whole batch discarded and returned without being forwarded to banking or verified) [4](#0-3) , every packet in the batch is still individually parsed and priced by `calculate_priority_from_bytes` first. Only `discard()`-already-set packets are skipped [5](#0-4) , and packets that fail to parse (`data(..)` unreadable) are conservatively kept rather than cheaply rejected [6](#0-5) . An unstaked attacker who crafts syntactically well-formed transaction bytes (structurally valid message/instructions so `try_new_sanitized`/`try_new` succeed) with a fabricated low `compute_unit_price`/fee and an invalid or garbage signature can force this parse+cost-model work on every packet sent, at line rate, while never contributing a fee (the packet will be discarded here for being below floor, and would separately fail Ed25519 verification since it's unsigned/garbage-signed). Packet-level deduplication via `deduper::dedup_packets_and_count_discards` only catches exact/near-duplicate bytes [7](#0-6) , so trivial per-packet byte variation (e.g., varying a memo/nonce field) defeats it, and each variant still forces a full parse.

### Impact Explanation
This is scoped to sigverify worker threads: `SigVerifyWorkerPool::run_transaction_task` runs on dedicated `solSigVerify` worker threads that also perform actual signature verification and forwarding for legitimate transactions [8](#0-7) . Because `apply_priority_floor_to_batch` only activates when `SchedulerPriorityFloor` is non-zero — i.e., precisely when the banking-stage scheduler is already saturated/under load [9](#0-8)  — this adds attacker-controllable, pre-verification, pre-fee CPU cost exactly during periods of contention, degrading sigverify throughput for legitimate fee-paying transactions and matching the "grossly underpriced pre-fee work" bounty category (unauthenticated, unsigned input forcing meaningful CPU work with zero fee guarantee).

### Likelihood Explanation
Preconditions are attacker-controllable and unprivileged: an unstaked sender reaching the leader's TPU with a saturated scheduler (non-zero `SchedulerPriorityFloor`), which is a normal high-load condition rather than an operator misconfiguration. The attacker only needs to craft structurally valid (but unsigned/garbage-signature, sub-floor-fee) transaction bytes, which is trivial and requires no stake, keys, or special access. The attack is fully repeatable at line rate for as long as ingestion allows, since `calculate_priority_from_bytes` is called unconditionally for every un-discarded, undeduplicated packet regardless of eventual batch outcome.

### Recommendation
Reorder or short-circuit the floor check: cheaply sample or bound the per-batch floor-check cost (e.g., early-exit after observing that a sufficient prefix of packets are all below floor, or move the floor check to operate on already sig-verified/cheaper-to-extract priority hints rather than full `RuntimeTransaction`/cost-model construction), and/or perform a lightweight structural/signature presence check prior to invoking the full cost-model path so that unsigned or garbage-signature packets are discarded before expensive parsing.

### Proof of Concept
Add a benchmark/unit test in `core/src/sigverify.rs` (or a criterion bench) that:
1. Constructs a `PacketBatch` of N packets, all with valid message structure but `compute_unit_price = 0` (guaranteed sub-floor) and either no signature or a garbage signature.
2. Sets a non-zero `SchedulerPriorityFloor` and invokes `apply_priority_floor_to_batch` directly, measuring wall-clock time via `measure_us!` (mirroring `total_priority_floor_time_us` accounting already present at `core/src/sigverify.rs:305-311`).
3. Asserts that `priority_floor_time_us` scales linearly with `N` even though `all_below == true` for the whole batch (i.e., no early exit occurs), and compares this against a control batch where packets are pre-marked `discard()` (which should short-circuit at line 421-423 with near-zero cost), demonstrating the disparity between "cheap to discard" vs. "expensive to discard via floor" packets of equivalent attacker cost to produce.

fn apply_priority_floor_to_batch(
    batch: &mut PacketBatch,
    floor: u64,
    bank: &Bank,
) -> (usize, bool) {
    let mut dropped: usize = 0;
    let mut any_kept = false;
    for mut packet in batch.iter_mut() {
        if packet.meta().discard() {
            continue;
        }
        let Some(data) = packet.data(..) else {
            // Zero-length or otherwise unreadable: leave to downstream
            // stages to reject.
            any_kept = true;
            continue;
        };
        // Unparseable packets are kept and left for downstream rejection.
        match calculate_priority_from_bytes(bank, data) {
            Some(priority) if priority <= floor => {
                packet.meta_mut().set_discard(true);
                dropped = dropped.saturating_add(1);
            }
            _ => any_kept = true,
        }
    }

pub(crate) fn calculate_priority_from_bytes(bank: &Bank, data: &[u8]) -> Option<u64> {
    let view = SanitizedTransactionView::try_new_sanitized(data, &sanitize_config()).ok()?;
    let runtime_tx = RuntimeTransaction::<SanitizedTransactionView<_>>::try_new(
        view,
        MessageHash::Compute,
        None,
    )
    .ok()?;
    let transaction_configuration = runtime_tx
        .transaction_configuration(&bank.feature_set)
        .ok()?;
    let (priority, _cost) =
        calculate_priority_and_cost(bank, &runtime_tx, &transaction_configuration);

    Some(priority)
}
