## Title
Missing bounds checks in ijar's central directory extra-field parser cause out-of-bounds reads on attacker-supplied JAR/ZIP archives - (File: `third_party/ijar/zip.cc`)

### Summary
`InputZipFile::ProcessCentralDirEntry` in ijar (Bazel's interface-jar generator, used whenever a `.jar` — e.g. one fetched by `http_archive`/`http_jar`/`http_file`/Maven — is processed to build an interface jar) parses each Central Directory Header entry, including its variable-length "extra fields," with no bounds checking against the mapped file's end, unlike its sibling function `ProcessLocalFileEntry`, which explicitly calls `EnsureRemaining()` before every variable-length read.

### Finding Description
`ProcessCentralDirEntry` reads the fixed 46-byte CDH fields, the file name, and then walks the extra-field list purely via unchecked pointer arithmetic: [1](#0-0) 

Contrast this with `ProcessLocalFileEntry`, which calls `EnsureRemaining()` before reading the file name, extra field, and file data: [2](#0-1) 

In `ProcessCentralDirEntry`, `file_name_length`, `extra_field_length`, and `file_comment_length` are read directly from attacker-controlled bytes and are never validated against the remaining bytes in the mapped input file (`third_party/ijar/zip.cc:508-525`). The extra-field walking loop is especially unsafe: [3](#0-2) 
Here `data_size` (attacker-controlled, up to 65535) is added to `extra_p` with no check that `extra_p + data_size <= p` (the computed end of the extra-field region) or that it stays within the mapped file. If `header_id == ZIP64_EXTRA_FIELD_TAG`, `get_u8le(extra)` unconditionally reads 8 bytes from `extra`, again without checking that 8 bytes actually remain inside the extra-field region — a crafted 4-byte extra field header claiming the ZIP64 tag with insufficient payload triggers an 8-byte over-read. If `data_size` is crafted so `extra_p` overshoots `p` entirely, the `while (extra_p != p)` loop condition never re-triggers falsely-safe termination and continues walking forward past the mapped file boundary into adjacent heap memory, repeatedly calling `get_u2le`/`get_u8le` on unmapped/unrelated memory — a classic missing-bounds-check out-of-bounds read, directly analogous to the reported CVE-2019-9232 class (missing bounds check in size/offset-driven parsing leading to OOB read).

By contrast, the newer, structured header classes in `src/tools/singlejar/zip_headers.h` do perform bounds checks in `ExtraField::find()`: [4](#0-3) 
confirming that ijar's legacy `zip.cc` parser lacks the equivalent protection that singlejar's newer implementation has.

This function is reached via `InputZipFile::ProcessNext()` for every entry of an input JAR/ZIP that ijar processes: [5](#0-4) 

The input JAR is untrusted content an unprivileged attacker fully controls — e.g., bytes served from a compromised/malicious mirror behind an `http_archive`/`http_jar` rule, or a JAR checked into an untrusted branch that CI builds — and ijar's job is specifically to parse third-party JAR bytes into interface jars during the build.

### Impact Explanation
An attacker who can serve or place a malicious JAR that a Bazel build consumes (e.g., a dependency archive fetched via `http_jar`/`http_archive`, or a vendored precompiled JAR in a repo) can supply a CDH extra field with a crafted `data_size` and `ZIP64_EXTRA_FIELD_TAG` to cause `ProcessCentralDirEntry` to read heap memory beyond the mapped input file. This is a process memory-safety violation in the build tool that can manifest as a crash (though DoS/crash alone is out of scope) or, since the resulting mis-read `uncompressed_size`/`compressed_size`/`offset` values feed into subsequent buffer-length and offset computations (`ProcessNext`, `CalculateOutputLength`, `UncompressFile`), can lead to further out-of-bounds reads/writes during decompression and to malformed interface-jar output — a data-integrity issue in the untrusted-content-must-stay-data invariant during archive parsing.

### Likelihood Explanation
High for build environments that consume JARs from any less-trusted or attacker-influenced source (custom `http_jar`/`http_archive` for precompiled dependencies, vendored jars in a PR branch). ijar unconditionally runs `ProcessCentralDirEntry` on every CDH entry with no size sanity check before entering the extra-field loop, so any archive with a single crafted entry triggers the code path.

### Recommendation
Add explicit bounds checks in `ProcessCentralDirEntry` mirroring `EnsureRemaining()` used in `ProcessLocalFileEntry`: validate `file_name_length`, `extra_field_length`, and `file_comment_length` against the remaining bytes in the mapped file before advancing `p`, and validate each extra-field record (`header_id`/`data_size` pair plus payload) stays within `[extra_p_start, extra_p_start + extra_field_length)` before reading it, rejecting the archive with an error instead of reading past bounds — analogous to `ExtraField::find()` in `src/tools/singlejar/zip_headers.h`.

### Proof of Concept
A reproducible JUnit/`src/test/shell/bazel` proof would need to be authored by constructing a minimal ZIP whose single Central Directory Header entry declares an extra field with `header_id = 0x0001` (ZIP64 tag) and `data_size` set to a value both smaller than 24 bytes (to trigger the 8-byte-read overshoot in `get_u8le`) and separately set to a value that makes `extra_p` overshoot `p` (e.g., `extra_field_length = 4`, `data_size = 0xFFFF`), then invoking ijar's `InputZipFile::Open`/`ProcessNext` on that file and observing (under ASan) a heap-buffer-overflow read report in `ProcessCentralDirEntry`. I was not able to locate an existing test exercising this exact malformed-extra-field path in the indexed portion of the repo (only `input_jar_scan_entries_test.h`, which targets the newer, bounds-checked `singlejar` central-directory reader, not ijar's `zip.cc`) — a background Devin session with full repo/test access would be needed to author and run this PoC.

```text
bool InputZipFile::ProcessNext() {
  // Process the next entry in the central directory. Also make sure that the
  // content pointer is in sync.
  u8 compressed, uncompressed;
  u8 offset;
  if (!ProcessCentralDirEntry(central_dir_current_, &compressed, &uncompressed,
                              filename, PATH_MAX, &attr, &offset)) {
    return false;
  }

  // There might be an offset specified in the central directory that does
  // not match the file offset, so always update our pointer.
  p = zipdata_in_ + in_offset_ + offset;

  if (EnsureRemaining(4, "signature") < 0) {
    return false;
  }
  u4 signature = get_u4le(p);
  if (signature == LOCAL_FILE_HEADER_SIGNATURE) {
    if (ProcessLocalFileEntry(compressed, uncompressed) < 0) {
      return false;
    }
  } else {
    error("local file header signature for file %s not found\n", filename);
    return false;
  }

  return true;
}
```

```text
bool InputZipFile::ProcessCentralDirEntry(const u1 *&p, u8 *compressed_size,
                                          u8 *uncompressed_size, char *filename,
                                          size_t filename_size, u4 *attr,
                                          u8 *offset) {
  u4 signature = get_u4le(p);

  if (signature != CENTRAL_FILE_HEADER_SIGNATURE) {
    if (signature != DIGITAL_SIGNATURE && signature != EOCD_SIGNATURE &&
        signature != ZIP64_EOCD_SIGNATURE) {
      error("invalid central file header signature: 0x%x\n", signature);
    }
    return false;
  }

  p += 16;  // skip to 'compressed size' field
  *compressed_size = get_u4le(p);
  *uncompressed_size = get_u4le(p);
  u2 file_name_length = get_u2le(p);
  u2 extra_field_length = get_u2le(p);
  u2 file_comment_length = get_u2le(p);
  p += 4;  // skip to external file attributes field
  *attr = get_u4le(p);
  *offset = get_u4le(p);
  {
    size_t len = (file_name_length < filename_size)
      ? file_name_length
      : (filename_size - 1);
    memcpy(reinterpret_cast<void*>(filename), p, len);
    filename[len] = 0;
  }
  p += file_name_length;
  const u1 *extra_p = p;
  p += extra_field_length;
  while (extra_p != p) {
    const u2 header_id = get_u2le(extra_p);
    const u2 data_size = get_u2le(extra_p);
    const u1 *extra = extra_p;
    extra_p += data_size;
    if (header_id == ZIP64_EXTRA_FIELD_TAG) {
      if (*uncompressed_size == U4_MAX) {
        *uncompressed_size = get_u8le(extra);
      }
      if (*compressed_size == U4_MAX) {
        *compressed_size = get_u8le(extra);
      }
      if (*offset == U4_MAX) {
        *offset = get_u8le(extra);
      }
    }
  }
  p += file_comment_length;
  return true;
}
```

```text
  static const ExtraField* find(uint16_t tag, const uint8_t* start,
                                const uint8_t* end) {
    while (start < end) {

        break;

      auto extra_field = reinterpret_cast<const ExtraField*>(start);

        break;

      if (extra_field->is(tag)) {
        return extra_field;
      }
      start = ziph::byte_ptr(start) + extra_field->size();
```
