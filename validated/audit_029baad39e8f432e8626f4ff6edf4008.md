### Title
New debt and synthetic supply can be minted while the Pool is paused because `DebtToken.issue` only checks `whenNotShutdown` - ([File: contracts/DebtToken.sol](contracts/DebtToken.sol))

### Summary
Metronome's `Pauseable` has two escalation levels: `pause()` (governor only, sets `_paused`) and `shutdown()` (sets `_everythingStopped` and `_paused`). The docstring of `shutdown()` states it suspends "all features (issue, repay, deposit, withdraw, liquidate and swap)", while `pause()` is meant to suspend risk-increasing operations during an emergency. However, `DebtToken.issue` — the public entry point that locks a user's collateral position and mints new synthetic supply backed by fresh debt — is guarded only by `whenNotShutdown`, not `whenNotPaused`. While `Pool.paused()` is `true` (the emergency brake is pulled, e.g., due to a broken oracle quote or an active exploit), any unprivileged user can keep issuing synths against collateral priced by the very component the pause was meant to neutralize. This mirrors the SYMM-IO finding where `internalTransfer` bypassed `accountingPaused` to keep allocating collateral.

### Finding Description
`DepositToken.deposit` correctly uses `whenNotPaused` (via `Manageable.whenNotPaused`, which reads `pool.paused()`), so new collateral cannot enter during a pause:

```solidity
// contracts/DepositToken.sol:211-214
function deposit(
    uint256 amount_,
    address onBehalfOf_
) external override whenNotPaused nonReentrant onlyIfDepositTokenExists returns (uint256 _deposited, uint256 _fee) {
```

But the debt side is only shutdown-gated:

```solidity
// contracts/DebtToken.sol:235-271
function issue(
    uint256 amount_,
    address to_
)
    external
    override
    whenNotShutdown          // NOT whenNotPaused
    nonReentrant
    onlyIfSyntheticTokenExists
    returns (uint256 _issued, uint256 _fee)
{
    ...
    (, , , , uint256 _issuableInUsd) = _pool.debtPositionOf(_msgSender);
    IMasterOracle _masterOracle = _pool.masterOracle();
    if (amount_ > _masterOracle.quoteUsdToToken(address(_syntheticToken), _issuableInUsd)) {
        revert NotEnoughCollateral();
    }
    _mint(_pool, _masterOracle, _msgSender, amount_);
    ...
    _syntheticToken.mint(to_, _issued);
}
```

`whenNotShutdown` in `Pauseable.sol` only checks `everythingStopped()`; it does not check `paused()`. `Pauseable.pause()` sets only `_paused = true`, so `issue` stays fully callable. The same gap exists on `DebtToken.flashIssue`, `DebtToken.mint` (both reachable via `SmartFarmingManager.leverage` flash-loan flows) and `Pool.swap` (`whenNotShutdown` only), meaning a user can both mint synths and convert them during a pause. `DepositToken.transfer`/`transferFrom` also lack any pause check, letting collateral shares move to fresh accounts mid-pause.

The `whenNotShutdown`-only guard on repay/withdraw is defensible (exits should stay open), but `issue`/`flashIssue`/`mint` expand protocol obligations and synthetic supply — exactly the class of action a pause must halt.

### Impact Explanation
When the governor pauses the pool because of a suspected oracle mispricing, an accounting inconsistency, or an in-flight attack, the pause is ineffective at stopping the damage path: an attacker can continue to call `DebtToken.issue` (or `SmartFarmingManager.leverage` → `flashIssue`/`mint`) to mint synthetic tokens against collateral valued by the faulty oracle, then `Pool.swap` them into other synths and exit via bridge. This converts a stale/mispriced quote into real, withdrawable synthetic assets, directly draining value from the treasury-backed collateral pool and causing protocol insolvency — the same "funds keep flowing during an emergency stop" impact as the SYMM-IO report.

### Likelihood Explanation
- Fully unprivileged: `issue(amount, to)` only requires the caller to hold an existing deposit position with positive `issuableInUsd`, obtainable before the pause via a normal `DepositToken.deposit`.
- No privileged precondition: pause is governor-triggered and is precisely the state in which the bug matters; it requires no attacker control of oracles (the pause itself signals the defensive state — even a merely precautionary pause leaves the mint path open, letting attackers front-run a coming shutdown).
- Only needs `paused == true && everythingStopped == false`, the intended intermediate emergency state.

### Recommendation
Add `whenNotPaused` to the risk-expanding entry points, keeping exit functions (`repay`, `repayAll`, `withdraw`) on `whenNotShutdown` only:

```diff
// contracts/DebtToken.sol
- function issue(uint256 amount_, address to_) external override whenNotShutdown nonReentrant onlyIfSyntheticTokenExists ...
+ function issue(uint256 amount_, address to_) external override whenNotPaused nonReentrant onlyIfSyntheticTokenExists ...

- function flashIssue(address to_, uint256 amount_) external override onlyIfSmartFarmingManager whenNotShutdown ...
+ function flashIssue(address to_, uint256 amount_) external override onlyIfSmartFarmingManager whenNotPaused ...

- function mint(address to_, uint256 amount_) external override onlyIfSmartFarmingManager whenNotShutdown ...
+ function mint(address to_, uint256 amount_) external override onlyIfSmartFarmingManager whenNotPaused ...
```

Apply the same to `Pool.swap` if swaps are intended to halt on pause rather than only on shutdown, and document the intended semantics of `pause()` vs `shutdown()` explicitly in `Pauseable.sol`.

### Proof of Concept
Hardhat (fork of a deployed pool), against `test/` style fixtures:

```ts
// test/DebtToken.pause.t.sol-style Hardhat spec
it('mints new debt while pool is paused', async function () {
  // given: alice has deposited collateral, giving issuableInUsd > 0
  await met.connect(alice).approve(metDepositToken.address, MaxUint256)
  await metDepositToken.connect(alice).deposit(parseEther('10'), alice.address)

  // when: governor pauses the pool (not shutdown)
  await pool.connect(governor).pause()
  expect(await pool.paused()).eq(true)
  expect(await pool.everythingStopped()).eq(false)

  // then: deposits are blocked
  await expect(
    metDepositToken.connect(alice).deposit(parseEther('1'), alice.address)
  ).revertedWithCustomError(metDepositToken, 'IsPaused')

  // but: issuing new synthetic debt still succeeds
  const tx = debtToken.connect(alice).issue(parseEther('100'), alice.address)
  await expect(tx).emit(debtToken, 'SyntheticTokenIssued')
  expect(await syntheticToken.balanceOf(alice.address)).gt(0)
  expect(await debtToken.balanceOf(alice.address)).gt(0) // debt minted during pause
})
```

Uncertainty note: whether `pause()` is intended to block `issue`/`swap` depends on the protocol's intended pause semantics; `Pauseable.sol` documents `pause` as "suspend deposit feature," which may be a deliberate design choice. However, `shutdown()`'s own docstring lists "issue" among suspended features, and the `whenNotShutdown`-only guard leaves the supply-expanding path open during every non-shutdown emergency pause, which is inconsistent with the two-tier design's apparent intent. If the team confirms pause must halt issuance, this is a valid medium/high finding; if pause is strictly deposit-only by design, this reduces to a documentation/design concern.
