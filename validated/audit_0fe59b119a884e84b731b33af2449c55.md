### Title
Integer truncation in MVCC manifest chunk-offset parsing enables out-of-bounds slice panics (DoS) - ([File: internal/git/mvcc/manifest.go])

### Summary
`ParseManifest` in `internal/git/mvcc/manifest.go` decodes attacker/remote-storage-reachable manifest bytes without guarding against `uint64`→`int` truncation of file offsets, mirroring the reported class of bug (an unchecked-overflow arithmetic step producing a silently wrong value that is then used unsafely).

### Finding Description
`parseChunks` reads each TOC row's 8-byte big-endian offset and converts it directly to a native `int`: [1](#0-0) 

```go
chunkOffsetInFile := int(binary.BigEndian.Uint64(data[chunkOffset+4 : chunkOffset+tocChunkSize]))
...
nextChunkOffsetInFile := int(binary.BigEndian.Uint64(data[nextChunkStart+4 : nextChunkStart+tocChunkSize]))
```

On the 64-bit platforms Gitaly runs on, `int` is 64-bit, so any `uint64` value greater than `math.MaxInt64` (i.e., with the top bit set) converts to a **negative** `int` via two's-complement wraparound — exactly the kind of "value computed without accounting for overflow" flaw the external report describes for `mulDivUp`/`mulDivDown`. The subsequent bounds check:

```go
if chunkOffsetInFile > dataEnd || nextChunkOffsetInFile > dataEnd || nextChunkOffsetInFile < chunkOffsetInFile {
    return nil, fmt.Errorf(...)
}
chunkSize := nextChunkOffsetInFile - chunkOffsetInFile
```

is defeated: a crafted large `uint64` offset silently becomes a negative `int`, which is always `<= dataEnd`, so the guard passes. `chunkSize` is then computed from these corrupted values and used unchecked to slice `data` in the PATH/OBJS/REFS processing code that follows: [2](#0-1) 

Because `pathChunk.offset`/`size`, `objsChunk.offset`, and `refsChunk.offset` are derived from these unchecked ints, a manifest with a poisoned offset can drive `data[start:start+pw]` or `data[objsChunk.offset:objsChunk.offset+8]` calculations to out-of-range slice bounds, causing a runtime panic (`slice bounds out of range`), or corrupt the extracted `Paths`/`ObjPaths`/`RefPaths` values that are later joined into on-disk artifact paths.

This manifest data is not purely internally generated: `LocalCache.prepareManifestFile` and `putNewArtifacts` fetch and parse manifest bytes coming from `RemoteStorage`/object storage before any local file exists, and cache preparation runs for essentially every RPC against an MVCC-backend repository: [3](#0-2) [4](#0-3) 

### Impact Explanation
A malformed/malicious manifest (e.g. injected via a compromised or misbehaving remote storage backend, or a corrupted/attacker-influenced manifest hash pointer) can crash the Gitaly RPC handler thread processing any MVCC-backend repository operation via a Go panic on out-of-bounds slicing, which is a denial-of-service against normal push/fetch/read RPC handling for MVCC repositories. In the worst case, corrupted-but-panic-free offsets could also cause the parser to interpret unrelated manifest bytes as legitimate storage paths, misdirecting which reftable/pack artifacts are fetched.

### Likelihood Explanation
The MVCC backend is an experimental/new reference backend (`ReferenceBackendMVCC`) and manifest parsing here is invoked automatically on both read and write RPC paths whenever a repository uses this backend, so the code path is reachable without any special privileges once MVCC is enabled — only crafting of the manifest bytes is required (e.g. by whoever/whatever controls the configured `RemoteStorage`/object store).

### Recommendation
Validate that `chunkOffsetInFile` and `nextChunkOffsetInFile` fit within `int32`/`math.MaxInt32` (as already done in `ReadEWAH` for the packfile bitmap format) *before* casting from `uint64`, and reject any offset whose top bit is set or which exceeds `dataEnd` as a `uint64` comparison rather than an `int` comparison, e.g.:
```go
rawOffset := binary.BigEndian.Uint64(...)
if rawOffset > uint64(dataEnd) {
    return nil, fmt.Errorf("chunk offset out of bounds")
}
chunkOffsetInFile := int(rawOffset)
```
Perform all bounds comparisons in `uint64` space prior to converting to `int`.

### Proof of Concept
A crafted manifest body where a TOC row's 8-byte offset field is set to a value like `0xFFFFFFFFFFFFFFF0` (which becomes negative once cast to `int` on 64-bit Go) while `dataEnd` remains small will pass the `chunkOffsetInFile > dataEnd` check (since the value is negative), and subsequent slicing such as `data[start : start+pw]` in the PATH-chunk loop, or `data[objsChunk.offset : objsChunk.offset+8]` in the OBJS handling, will panic with "slice bounds out of range" when `ParseManifest` is invoked (e.g., via `LocalCache.prepareManifestFile`/`putNewArtifacts`, as covered by existing tests such as `TestParseManifest_HeaderValidations`/`TestParseManifest_duplicateChunks` in `internal/git/mvcc/manifest_test.go`, which already exercise `parseChunks` with attacker-controlled TOC bytes).

```go
// prepareManifestFile will read the manifest file defined by `hash` and return its parsed form.
// If the manifest file already exist on the local filesystem, the file is read from the filesystem.
// Else, the manifest file is fetched from ObjectStorage and then created on the local filesystem for future use.
func (m *LocalCache) prepareManifestFile(ctx context.Context, hash string) (manifest *Manifest, err error) {
	// Construct the manifest path
	manifestFilePath := filepath.Join(m.storagePath, m.repositoryID, mvccCacheDir, "manifests", hash)

	// Verify if it already exists on the local filesystem or not
	existLocally, err := fileExist(manifestFilePath)
	if err != nil {
		return nil, fmt.Errorf("check if file exists: %w", err)
	}

	if !existLocally {
		// If it does not exist, read content from ObjectStorage
		manifestReader, err := m.rs.ReadManifest(ctx, m.repositoryID, hash)
		if err != nil {
			return nil, fmt.Errorf("read manifest file: %w", err)
		}

		defer func() {
			closeErr := manifestReader.Close()
			err = errors.Join(err, closeErr)
		}()

		// Create the manifest file on the local file system atomically. This is a protection against
		// potential concurrent requests trying to create the same manifest file.
		if err = createFileAtomic(ctx, manifestFilePath, manifestReader); err != nil {
			return nil, fmt.Errorf("write manifest: %w", err)
		}
	}

	// Now that it exist on disk, let's open the file.
	manifestFile, err := os.Open(manifestFilePath)
	if err != nil {
		return nil, fmt.Errorf("opening manifest %s: %w", manifestFilePath, err)
	}

	// Read the content in memory. These files should not be that large.
	// The Manifest parsing logic needs the whole file at once to parse it.
	manifestContent := bytes.Buffer{}
	_, err = manifestContent.ReadFrom(manifestFile)
	if err != nil {
		return nil, fmt.Errorf("reading manifest: %w", err)
	}

	// Return the parsed manifest
	return ParseManifest(manifestContent.Bytes())
}
```
