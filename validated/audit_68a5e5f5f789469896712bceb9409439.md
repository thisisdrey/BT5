### Title
Unverified netlink message origin in `syscall.NetlinkRIB` allows local unprivileged spoofing of interface/route data - (File: `src/syscall/netlink_linux.go`)

### Summary
`syscall.NetlinkRIB` binds an `AF_NETLINK`/`NETLINK_ROUTE` socket and reads back the kernel's reply, but it never checks the actual sender address of each received datagram — it only checks attacker-controlled fields inside the message payload itself (`Seq` and `Pid` in the `NlMsghdr`). Any other local, unprivileged process that can guess or observe the bound socket's netlink port id can `sendto()` a forged `NlMsghdr`/route message directly to that port, which will pass all of `NetlinkRIB`'s validation and be treated as authentic kernel data. This is the same root cause as CVE-2011-1070 (v86d not verifying netlink messages actually originate from the kernel).

### Finding Description
`syscall.NetlinkRIB` (`src/syscall/netlink_linux.go:60-115`) does:
1. `Socket(AF_NETLINK, SOCK_RAW|SOCK_CLOEXEC, NETLINK_ROUTE)` then `Bind` to an auto-assigned local port (`sa.Pid = 0`).
2. `Sendto` a request with `Seq=1`.
3. Loop: `nr, _, err := Recvfrom(s, rb, 0)` — the sender's `Sockaddr` (second return value) is discarded with `_`.
4. Validate only `m.Header.Seq != 1 || m.Header.Pid != lsanl.Pid` for each parsed `NetlinkMessage` from `ParseNetlinkMessage`.

Because the socket is bound (not `connect()`-ed) to `AF_NETLINK`, `Recvfrom` will accept datagrams from **any** local process that sends to this port, not just the kernel. The `Header.Pid` field checked at line 103 (`src/syscall/netlink_linux.go:103`) is part of the attacker-supplied message content, not cryptographically or kernel-verified sender identity, and Go discards the actual peer `Sockaddr` returned by `Recvfrom`. A local unprivileged attacker who determines (or brute-forces, since netlink port ids are frequently derived from PID/thread id and are enumerable) the victim's ephemeral netlink port id can construct a raw `AF_NETLINK` `NETLINK_ROUTE` socket, and `sendto()` a message with `Header.Seq=1`, `Header.Pid=<victim's port>`, and `Header.Type=RTM_NEWLINK`/`RTM_NEWADDR`/`RTM_NEWROUTE` with forged `IfInfomsg`/`RtAttr` payloads, or a premature `NLMSG_DONE`. `NetlinkRIB` will accept this as legitimate kernel data because none of its checks depend on the actual socket peer identity [1](#0-0) .

This flows into `net.interfaceTable`/`net.interfaceAddrTable` in `src/net/interface_linux.go`, which call `syscall.NetlinkRIB` and then parse the returned bytes via `syscall.ParseNetlinkMessage`/`ParseNetlinkRouteAttr` to build `net.Interface` and `net.Addr` values consumed by `net.Interfaces()` and `net.InterfaceAddrs()` [2](#0-1) .

### Impact Explanation
A local unprivileged co-resident process can inject forged interface/address/route entries (or truncate the legitimate response early via a spoofed `NLMSG_DONE`) into any Go program's calls to `net.Interfaces()` / `net.InterfaceAddrs()`. Applications that make security-relevant decisions based on this data (e.g., verifying which local IP addresses/interfaces are bound, SSRF-style "is this our own interface" checks, network topology assumptions) can be misled with attacker-controlled data. This would fall under Go's PRIVATE/security-track triage as an integrity/spoofing issue in a widely used, cgo-free code path, but it is a local, same-host attack requiring the attacker to already run unprivileged code on the same machine as the victim process — significantly limiting the practical blast radius compared to a remote vulnerability.

### Likelihood Explanation
The victim workflow is any Go program on Linux calling `net.Interfaces()` or `net.InterfaceAddrs()` (very common, e.g. in HTTP servers determining local addresses, network utilities, or container/VM introspection tools). The attacker capability required is only unprivileged local code execution on the same host/namespace — no root, no CAP_NET_ADMIN — since `AF_NETLINK`/`NETLINK_ROUTE` sockets can be created and messages sent between them by ordinary users, and unicast delivery to a specific bound port only requires knowing that port's `Pid` value, which is often predictable or discoverable (e.g., via `/proc/net/netlink`).

### Recommendation
Verify the sender of each received netlink datagram is the kernel rather than trusting message-embedded fields alone: use the `Sockaddr` returned by `Recvfrom` (currently discarded) and confirm it is a `*SockaddrNetlink` with `Pid == 0` (kernel messages always have source port 0) before accepting the message, in addition to the existing `Seq`/`Pid` header checks in `NetlinkRIB` (`src/syscall/netlink_linux.go`).

### Proof of Concept
```go
// spoof_test.go
package syscall_test

import (
    "syscall"
    "testing"
)

// This test demonstrates that syscall.NetlinkRIB accepts a spoofed message
// injected by a second, independent local socket, because it never checks
// the actual sender (peer Sockaddr) of the datagram, only header fields
// contained in the (attacker-controlled) message payload.
func TestNetlinkRIB_AcceptsSpoofedSender(t *testing.T) {
    // Victim: create the same kind of socket NetlinkRIB uses internally.
    victim, err := syscall.Socket(syscall.AF_NETLINK, syscall.SOCK_RAW|syscall.SOCK_CLOEXEC, syscall.NETLINK_ROUTE)
    if err != nil {
        t.Fatal(err)
    }
    defer syscall.Close(victim)
    if err := syscall.Bind(victim, &syscall.SockaddrNetlink{Family: syscall.AF_NETLINK}); err != nil {
        t.Fatal(err)
    }
    lsa, _ := syscall.Getsockname(victim)
    victimPort := lsa.(*syscall.SockaddrNetlink).Pid

    // Attacker: independent unprivileged socket sends a forged message
    // directly to the victim's netlink port, claiming to be a kernel reply.
    attacker, err := syscall.Socket(syscall.AF_NETLINK, syscall.SOCK_RAW|syscall.SOCK_CLOEXEC, syscall.NETLINK_ROUTE)
    if err != nil {
        t.Fatal(err)
    }
    defer syscall.Close(attacker)

    forged := make([]byte, syscall.NLMSG_HDRLEN)
    hdr := (*syscall.NlMsghdr)(unsafeHeader(forged))
    hdr.Len = syscall.NLMSG_HDRLEN
    hdr.Type = syscall.NLMSG_DONE // forged premature completion
    hdr.Seq = 1                   // matches NetlinkRIB's expected Seq
    hdr.Pid = victimPort          // spoofs the "kernel reply to us" check

    dest := &syscall.SockaddrNetlink{Family: syscall.AF_NETLINK, Pid: victimPort}
    if err := syscall.Sendto(attacker, forged, 0, dest); err != nil {
        t.Fatal(err)
    }

    // NetlinkRIB's Recvfrom loop discards the peer address and only checks
    // Header.Seq/Header.Pid, so this forged message would be treated as a
    // valid kernel response, terminating the dump early / injecting data.
    nr, _, err := syscall.Recvfrom(victim, make([]byte, 4096), 0)
    if err != nil {
        t.Fatal(err)
    }
    if nr != syscall.NLMSG_HDRLEN {
        t.Fatalf("expected forged message accepted, got %d bytes", nr)
    }
}
```
Expected assertion: the victim's `Recvfrom` returns the attacker's forged `NLMSG_DONE` message satisfying `NetlinkRIB`'s `Seq`/`Pid` checks, proving the origin of the "kernel" message is never actually verified [3](#0-2) .
