### Title
StackerDB chunk signatures omit the target contract ID, enabling cross-lane chunk replay into a different signer StackerDB (`libstackerdb/src/libstackerdb.rs`)

### Summary
`SlotMetadata::auth_digest()` binds only `slot_id`, `slot_version`, and `data_hash` — it never binds the StackerDB's contract identity. For the Nakamoto signer set, all `signers-{set}-{message_id}` StackerDB replicas (`BlockResponse`, `StateMachineUpdate`, `BlockPreCommit`, …) reuse the *identical* signer→slot mapping for a given reward-cycle parity (`stackerdb-signer-slots-0`/`-1` in `signers.clar`), so the same address owns slot `N` in every one of those contracts simultaneously. Because the signature never commits to *which* contract/lane it was produced for, a chunk that a signer validly signed and broadcast for one lane can be captured and replayed by an unprivileged remote attacker into a different lane's slot, and it will pass all of `validate_received_chunk`'s checks.

### Finding Description
`SlotMetadata::auth_digest()` computes:
```
hasher.update(self.slot_id.to_be_bytes());
hasher.update(self.slot_version.to_be_bytes());
hasher.update(self.data_hash.0);
``` [1](#0-0) 

This digest is what gets signed (`SlotMetadata::sign`) and what is checked against the expected slot owner in `SlotMetadata::verify` [2](#0-1) . Notably no `QualifiedContractIdentifier` / StackerDB name is included anywhere in the signed material.

The server-side acceptance path, `StackerDBs::validate_received_chunk` in `stackslib/src/net/stackerdb/mod.rs`, only checks: chunk size vs `config.chunk_size`, that `expected_versions` has an entry for the slot, that `slot_metadata.verify(&addr)` succeeds against `self.stackerdbs.get_slot_signer(smart_contract_id, slot_id)`, that the version is not stale, and that it does not exceed `max_writes` [3](#0-2) . It never checks that the signed payload's declared type/lane matches `smart_contract_id`.

Because `signers.clar`'s `stackerdb-set-signer-slots` stores exactly one shared slot list per reward-cycle parity (`stackerdb-signer-slots-0`/`stackerdb-signer-slots-1`) [4](#0-3) , and every `signers-{set}-{message_id}` contract reads from that same shared page via `stackerdb-get-signer-slots-page` [5](#0-4) , this is confirmed by the test that asserts identical slot assignment across `signers-{0,1}-{message_id}` contracts [6](#0-5) , i.e. the same signer address owns slot `N` in `signers-1-1` (BlockResponse), `signers-1-2` (StateMachineUpdate), and `signers-1-3` (BlockPreCommit) at the same time.

An unprivileged remote observer who sees a legitimately-signed `StackerDBChunkData` broadcast for lane A (e.g. via the P2P `StackerDBPushChunk` message or the public `GET /v2/stackerdb/.../chunks/...` endpoint) can re-POST/re-push that identical `(slot_id, slot_version, sig, data)` tuple to a *different* signer lane B's contract (`PostChunk`/`StackerDBPushChunk` for `signers-1-2` instead of `signers-1-1`). Because `auth_digest` never included the contract identity, `slot_metadata.verify(&addr)` in the target contract's `validate_received_chunk` still succeeds (the recovered pubkey hash matches the same owner address, since both lanes share the identical slot owner), and — provided the version/size/max-writes checks are satisfied — the chunk is accepted and stored as though the signer had legitimately authored a message for that specific lane.

The only mitigating check today is downstream and lane-*specific*: `SignerEvent::try_from` in `libsigner/src/events.rs` inspects the first byte of the payload (`SignerMessageTypePrefix`) and drops it via `signer_message_payload_matches_lane` if the type doesn't match the target `message_id` [7](#0-6) . That filter only protects the specific `SignerEvent` consumer pipeline used by `stacks-signer`/`stackerdb_listener`; it does nothing to prevent the chunk from being accepted, stored, version-bumped, and relayed at the StackerDB storage/sync layer itself.

### Impact Explanation
This breaks the equality "a chunk stored in StackerDB replica/lane X was authenticated for lane X" — the signature only proves "signed by the slot owner for *some* slot/version/data-hash", not "signed for *this* StackerDB contract." Consequences reachable by a fully unprivileged remote party who merely replays a chunk they observed on the wire or fetched via the public HTTP StackerDB API:
- Unauthorized write into a StackerDB replica the attacker never obtained a valid signature for (the replayed chunk lands in a lane/contract that was never the intended target).
- Griefing/DoS on a legitimate signer's ability to write: the injected chunk bumps `slot_version` for that slot in the target lane, so the signer's *next legitimate* write to that lane can be rejected as stale (`net_error::StaleChunk`) until it catches up, effectively letting an unprivileged party interfere with a specific signer's participation in a specific message lane.
- The forged-context chunk is subject to normal StackerDB sync/gossip and can be relayed to other peers as a "validly signed" chunk for that lane (`handle_unsolicited_StackerDBPushChunk` path exercises the same `validate_received_chunk` logic, as covered by tests in `stackslib/src/net/tests/relay/nakamoto.rs`) [8](#0-7) , propagating the mismatched data network-wide.

This maps to the "unauthenticated/unauthorized write to state or StackerDB" and "network-wide propagation of forged data" Critical categories, since no secret key or admin role is needed — only observation/replay of already-public gossip traffic.

### Likelihood Explanation
High attack complexity is low: the attacker needs no cryptographic material, only to observe or fetch one legitimately signed chunk (StackerDB chunks and gossip are, by design, publicly readable/relayable) and resend it to a sibling contract that shares the same slot-owner mapping. This is a purely mechanical replay, requiring no private key, no admin role, and no consensus-internals manipulation.

### Recommendation
Bind the StackerDB contract identity (and ideally protocol/message version) into the signed digest, e.g. include the `QualifiedContractIdentifier` bytes (or a fixed identifier for the specific StackerDB) in `SlotMetadata::auth_digest()`, and thread that same contract id through `sign()`/`verify()`/`recover_pk()`. Alternatively, enforce the payload-type-vs-lane check (`signer_message_payload_matches_lane`) at the storage/validation layer (`validate_received_chunk`) rather than only in the downstream `SignerEvent` consumer, so mismatched chunks are rejected before being stored or relayed.

### Proof of Concept
1. Reward cycle `rc` is active; per `signers.clar`, the shared slot list `stackerdb-signer-slots-{rc%2}` assigns signer address `S` to slot `0` in every `signers-{rc%2}-{message_id}` contract (`BlockResponse=1`, `StateMachineUpdate=2`, `BlockPreCommit=3`).
2. Signer `S` legitimately signs and pushes a `StackerDBChunkData{slot_id:0, slot_version:v, data}` for contract `signers-{rc%2}-1` (BlockResponse). Signature = `sign(auth_digest(0, v, hash(data)))` under `S`'s key — this is broadcast over P2P `StackerDBPushChunk` and readable via `GET /v2/stackerdb/<signers-…-1 id>/0/<v>`.
3. An unprivileged attacker observes/fetches this exact `(slot_id=0, slot_version=v, sig, data)` tuple and re-submits it (via `StackerDBPushChunk` gossip or `POST /v2/stackerdb/<signers-…-2 id>/chunks`) to contract `signers-{rc%2}-2` (StateMachineUpdate) instead.
4. `validate_received_chunk` for `signers-{rc%2}-2` calls `get_slot_signer(signers-…-2, 0)` → returns `S` (same shared slot mapping), then `slot_metadata.verify(&S_addr)` succeeds because `auth_digest` never encoded which contract it was for. The chunk is accepted, stored under `signers-{rc%2}-2` slot 0, and its version counter is advanced — despite `S` never having signed anything for the `StateMachineUpdate` lane.

    /// Sign this slot metadata, committing to slot_id, slot_version, and
    /// data_hash.  Sets self.signature to the signature.
    /// Fails if the underlying crypto library fails
    pub fn sign(&mut self, privkey: &StacksPrivateKey) -> Result<(), Error> {
        let auth_digest = self.auth_digest();
        let sig = privkey
            .sign(&auth_digest.0)
            .map_err(|se| Error::SigningError(se.to_string()))?;

        self.signature = sig;
        Ok(())
    }

    /// Verify that a given principal signed this chunk metadata.
    /// Note that the address version is ignored.
    pub fn verify(&self, principal: &StacksAddress) -> Result<bool, Error> {
        let sigh = self.auth_digest();
        let pubk = StacksPublicKey::recover_to_pubkey_without_validating_low_s(
            sigh.as_bytes(),
            &self.signature,
        )
        .map_err(|ve| Error::VerifyingError(ve.to_string()))?;

        let pubkh = Hash160::from_node_public_key(&pubk);
        Ok(pubkh == *principal.bytes())
    }

        &self,
        smart_contract_id: &QualifiedContractIdentifier,
        config: &StackerDBConfig,
        data: &StackerDBChunkData,
        expected_versions: &[u32],
    ) -> Result<bool, net_error> {
        // validate -- must not exceed this replica's configured chunk size.
        if (data.data.len() as u64) > config.chunk_size {
            info!(
                "Received StackerDBChunk for {} ID {}, which is oversized: {} bytes (max {} bytes)",
                smart_contract_id,
                data.slot_id,
                data.data.len(),
                config.chunk_size
            );
            return Ok(false);
        }

        // validate -- must be a valid chunk
        let Some(expected_version) = expected_versions.get(data.slot_id as usize) else {
            info!(
                "Received StackerDBChunk for {} ID {}, which is too big ({})",
                smart_contract_id,
                data.slot_id,
                expected_versions.len()
            );
            return Ok(false);
        };

        // validate -- must be signed by the expected author
        let addr = match self
            .stackerdbs
            .get_slot_signer(smart_contract_id, data.slot_id)?
        {
            Some(addr) => addr,
            None => {
                return Ok(false);
            }
        };

        let slot_metadata = data.get_slot_metadata();
        if !slot_metadata.verify(&addr)? {
            info!(
                "StackerDBChunk for {} ID {} is not signed by {}",
                smart_contract_id, data.slot_id, &addr
            );
            return Ok(false);
        }

        if data.slot_version < *expected_version {
