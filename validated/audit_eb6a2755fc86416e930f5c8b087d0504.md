### Title
`CenterTargetPrice::adapt_price` can lock the Broker coretime sale price at zero forever when a sale sells out at price zero - ([File: substrate/frame/broker/src/adapt_price.rs])

### Summary
`pallet-broker`'s `CenterTargetPrice::adapt_price` (the default `AdaptPrice` implementation used to set the next coretime sale's `end_price`/`target_price`) only guards against the *computed* price rounding to zero, not against a `sellout_price` input that is already zero. This mirrors the reported bug class exactly: a one-sided bound check (only the "too high" / non-zero-after-multiplication path is patched) leaves a lower-bound gap that lets the derived value collapse to, and stay at, zero.

### Finding Description
`CenterTargetPrice::adapt_price` computes the next sale's `end_price` as 1/10th of the previous `sellout_price`: [1](#0-0) 

The known fix (documented in `prdoc/1.9.0/pr_3636.prdoc`, "Fix `Linear::adapt_price` behavior at zero") only handles the case where the *multiplication* `1/10 * sellout_price` rounds down to zero (e.g. `sellout_price` is small, like 1–9), by falling back to the raw `sellout_price` instead of the rounded-to-zero result: [2](#0-1) 

This guard does **not** cover the case where `sellout_price` itself is exactly `0`. If a core sells out at price `0` (a real value the code represents and even tests: see the `no_minimum_price_works_as_center_target_price` test case `(Some(0), 10)`), then `price = 1/10 * 0 = 0`, the "recovery" branch triggers (`price == Balance::zero()`), and it returns `sellout_price` — which is also `0`. The function then returns `AdaptedPrices { end_price: 0, target_price: 0 }`.

That `end_price`/`target_price` of `0` is fed straight back into `rotate_sale` as the next sale's `SaleInfoRecord::end_price` / `sellout_price`, and used as the renewal price stored in `PotentialRenewalRecord::price`: [3](#0-2) [4](#0-3) [5](#0-4) 

Because `adapt_price` is purely multiplicative (`price = f(previous_price)`), once `sellout_price` is `0`, every subsequent call reproduces `0 -> 0` forever — there is no additive/lower-bound floor to break out of the fixed point, exactly like the original report's `computePriceWithTick` collapsing to `0` from an unchecked lower bound.

The only defense against this is the *optional* wrapper `MinimumPrice<Balance, MinPrice>`, which clamps `end_price` up to `MinPrice::get()` — but this is an opt-in configuration choice by the runtime, not a guarantee inside `CenterTargetPrice` itself, and if a runtime configures `MinPrice = 0` (as the test `no_minimum_price_works_as_center_target_price` explicitly does with `ConstU64<0>`), the zero-lock is fully reproducible.

### Impact Explanation
If a coretime core genuinely sells for `0` (e.g., extremely low demand pushes the leadin-adjusted price down to `0` before any bid, or the sale simply has no participants at a bootstrapped low starting price), the sale price permanently locks at `0`. From that point, every future coretime core sale and every renewal derived from `PotentialRenewalRecord::price` would be prices at `0`, letting any account acquire coretime cores for free indefinitely. This is a public underpriced-work condition that degrades the economic security of coretime allocation on a production relay/parachain (Coretime chain) — cores that should be paid for in DOT/KSM become permanently free, causing unbacked loss of expected treasury/broker revenue with no recovery path, matching the "public underpriced work that degrades block production" and "theft or unbacked... unlock" impact classes.

### Likelihood Explanation
Likelihood is moderate: it requires the coretime sale to reach a state where `sellout_price` is exactly `0` for at least one rotation. This is plausible on low-demand or newly-launched coretime chains/testnets, or through the natural leadin/decay dynamics combined with a runtime that does not wrap `CenterTargetPrice` in `MinimumPrice` with a nonzero floor (the pallet exposes `CenterTargetPrice` as a directly usable, un-guarded `AdaptPrice` type, and the pallet's own test suite exercises `MinPrice = 0` as a valid, supported configuration). No privileged actor or malicious relayer/validator is needed — it's a pure function of public sale outcomes.

### Recommendation
- Short term: In `CenterTargetPrice::adapt_price`, treat an input `sellout_price == 0` the same as the rounding-to-zero case, e.g., substitute a hard-coded minimum non-zero unit (such as `Balance::one()`) instead of echoing back a zero `sellout_price`, so the multiplicative recurrence can never enter a permanent `0` state.
- Long term: Make `CenterTargetPrice`/`AdaptPrice` require a mandatory minimum price floor (fold `MinimumPrice`'s behavior into the base implementation, or make `AdaptPrice::adapt_price` bounds-checked with a non-optional lower bound), rather than relying on runtime integrators to remember to wrap it with `MinimumPrice` and to choose a nonzero `MinPrice`.

### Proof of Concept
Using the existing test harness in `substrate/frame/broker/src/adapt_price.rs`:
```rust
#[test]
fn price_locks_at_zero_when_sellout_price_is_zero() {
    let mut performance = SalePerformance::new(Some(0), 10);
    for _ in 0..5 {
        let prices = CenterTargetPrice::adapt_price(performance);
        assert_eq!(prices.end_price, 0);
        assert_eq!(prices.target_price, 0);
        performance.sellout_price = Some(prices.end_price); // 0
        performance.end_price = prices.end_price;
    }
    // end_price/target_price remain 0 for every subsequent rotation - permanent zero-price lock.
}
```
Chained with `rotate_sale` in `substrate/frame/broker/src/tick_impls.rs`, this zero `end_price`/`target_price` is written into `SaleInfoRecord` and `PotentialRenewalRecord::price`, meaning every subsequent sale and renewal is prices at zero DOT/KSM, unless the runtime happens to wrap the adapter in `MinimumPrice` with a nonzero floor.

		let Some(sellout_price) = performance.sellout_price else {
			return AdaptedPrices {
				end_price: performance.end_price,
				target_price: FixedU64::from(10).saturating_mul_int(performance.end_price),
			};
		};

		let price = FixedU64::from_rational(1, 10).saturating_mul_int(sellout_price);
		let price = if price == Balance::zero() {
			// We could not recover from a price equal 0 ever.
			sellout_price
		} else {
			price
		};

		AdaptedPrices { end_price: price, target_price: sellout_price }
	}
