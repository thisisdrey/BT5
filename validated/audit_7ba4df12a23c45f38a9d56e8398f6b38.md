**Analysis**: The premise that the compiled-artifact cache "diverges from trie state" is incorrect. The cache key used by `get_contract_cache_key` is not the `GlobalContractIdentifier::AccountId` — it's built from a `code_hash` that is *always freshly resolved from the current trie state* at call time, not cached across redeployments.

Specifically, `RuntimeContractIdentifier::resolve` (invoked per `FunctionCall` in `runtime/runtime/src/lib.rs`) calls `GlobalContractIdentifier::hash()`, which for an `AccountId` identifier performs `store.get_ref(&TrieKey::GlobalContractCode{...})?.value_hash()` — i.e., it reads the *current* trie value's hash, not a stale one. [1](#0-0) 

After a redeploy of contract B under the same `AccountId` identifier, the trie key `TrieKey::GlobalContractCode{identifier}` is overwritten with B's bytes via `state_update.set(trie_key, ...)` in `apply_distribution_current_shard`. [2](#0-1)  Any subsequent resolution of that identifier — on any node, since all nodes converge on the same state root — will compute `hash(B)`, producing `get_contract_cache_key(hash(B), ...)`, which is disjoint from the old `get_contract_cache_key(hash(A), ...)` entry. There is no mechanism by which a node would serve the stale `hash(A)` artifact for an account now mapped to B, because the cache key is a deterministic function of state content, not of the identifier alone.

Additionally, the pipelining layer includes explicit defense-in-depth against exactly this race within a single chunk: `PrepareTask::expected_hash` captures the code hash at submission time and discards a prepared artifact if it no longer matches at execution time [3](#0-2) , and `block_global_contracts` prevents pipelined preparation for any account depending on an `AccountId`/`CodeHash` global-contract identifier that was redeployed within the same chunk [4](#0-3) . This exact scenario (deploy contract A, deploy contract B under the same `AccountId`, verify B is what executes on all shards) is covered by an existing test, `test_global_contract_nonce_prevents_stale_overwrite`. [5](#0-4) 

Since the cache key is derived deterministically from the current trie state (which is identical across all correctly-functioning nodes at a given block), there is no path to state-root divergence or serving a stale compiled artifact for a redeployed `AccountId`-mode global contract.

impl GlobalContractAccessExt for GlobalContractIdentifier {
    fn hash(self, store: &TrieUpdate, access: AccessOptions) -> Result<CryptoHash, StorageError> {
        if let GlobalContractIdentifier::CodeHash(hash) = self {
            return Ok(hash);
        }
        let key = TrieKey::GlobalContractCode { identifier: self.into() };
        let value_ref =

                let TrieKey::GlobalContractCode { identifier } = key else { unreachable!() };
                StorageError::StorageInconsistentState(format!(
                    "Global contract identifier not found {:?}",
                    identifier
                ))
            })?;
        Ok(value_ref.value_hash())
    }
