### Title
Unauthenticated cross-tunnel state poisoning via spoofed `RecvError` index lookup - (File: outside.go)

### Summary
`handleRecvError` resolves the tunnel to tear down solely from the attacker-controlled `h.RemoteIndex` field of an unauthenticated, plaintext `RecvError` packet, then only checks that packet's *source UDP address* against the resolved host's cached remote address — never validating that the sender actually owns/authenticated that tunnel. This mirrors the reported bug class: the target "account" (here, a `HostInfo`/tunnel entry keyed by index) is selected from caller-supplied data rather than being derived/verified against the caller's own cryptographic identity, letting one (potentially cert-less) party affect another peer's state.

### Finding Description
`RecvError` is handled before any certificate or encryption check — it is processed directly in `readOutsidePackets` at [3](#0-2)  for `h.Type == header.RecvError`, bypassing the entire handshake/AEAD authentication path that protects `header.Message`/`header.LightHouse` traffic.

Inside `handleRecvError`, the only defense is:
1. `acceptRecvErrorConfig.ShouldRecvError(addr)` – a coarse policy gate based on the packet's *source address*, not identity.
2. `hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)` – looks up an existing tunnel purely by the attacker-supplied 32-bit index, with no derivation/binding check that this index actually belongs to the sender.
3. A best-effort UDP-address comparison (`hr != addr`) intended to catch spoofing — but this only compares against the *learned* remote UDP endpoint, which is itself just an unauthenticated `netip.AddrPort` value (roaming updates it opportunistically, see `handleHostRoaming`). An attacker who can send from (or spoof) the peer's known/roaming-eligible UDP source, or who guesses/observes a 32-bit `RemoteIndex` (transmitted in the clear on every packet, including relayed ones), can trigger `f.closeTunnel(hostinfo)` and `f.handshakeManager.DeleteHostInfo(hostinfo)` for a tunnel it does not own — tearing down another authority's established session and forcing renegotiation, with no possession of a CA-signed certificate or valid Noise session state required.

This is structurally identical to the Solana finding: the `AppendDataSandwichValidatorsBitmap` context trusted a caller-supplied PDA account reference instead of deriving it from `[SEED_PREFIX, multisig_authority.key(), epoch]` and checking the signer's authority; here, `handleRecvError` trusts a caller-supplied index/address pair to select and mutate another peer's tunnel state instead of requiring proof of possession of that tunnel's cryptographic material (AEAD-authenticated message).

### Impact Explanation
An attacker with no valid Nebula certificate can force termination of an arbitrary established tunnel between two legitimate, CA-signed peers by sending a single crafted, unauthenticated UDP packet, provided they can source-spoof UDP (trivial on many networks) or otherwise satisfy the loose address check, and know/guess the target's `RemoteIndex` (observable from any packet on that tunnel, e.g. via passive network observation or relay traffic). This is a remote state-poisoning / denial-of-service primitive against tunnels belonging to other, unrelated authorities — analogous in class (unauthorized cross-authority state modification via unvalidated reference) to the original finding, though the concrete impact here is availability/DoS rather than data corruption.

### Likelihood Explanation
Likelihood is moderated by: (1) `RecvError` handling is disabled unless `listen.send_recv_error`/accept config enables it (see `f.acceptRecvErrorConfig.ShouldRecvError`), and (2) it requires learning or spoofing a `RemoteIndex`+source address pair. However, `RemoteIndex` is transmitted unencrypted in every packet header (including on relays), and UDP source spoofing is feasible in many deployment topologies, so exploitation does not require any cryptographic material or CA trust.

### Recommendation
Do not act on `RecvError` based solely on `(RemoteIndex, source address)`. Require the `RecvError` handling path to bind to a value derived from the session's own cryptographic state (e.g., only accept it if it can be authenticated, or at minimum require it be delivered in-tunnel/AEAD-protected rather than as a bare, spoofable UDP datagram), and avoid relying on the opportunistically-updated `GetRemote()` address as the sole spoofing defense.

### Proof of Concept
1. Establish a legitimate tunnel between Peer A and Peer B; observe A's outgoing packets on the wire (or as a relay) to learn A's `RemoteIndex` value used for B (transmitted in cleartext header per [4](#0-3) ).
2. From an attacker-controlled host, craft a `header.RecvError` packet with `RemoteIndex` set to the observed value, and send it to A while spoofing the UDP source address to match B's known/expected endpoint (or before B has roamed, matching the stale endpoint check).
3. A's `handleRecvError` ( [2](#0-1) ) resolves the tunnel via `QueryReverseIndex(h.RemoteIndex)`, passes the loose address check, and calls `f.closeTunnel(hostinfo)` plus `f.handshakeManager.DeleteHostInfo(hostinfo)`, killing the A↔B tunnel without the attacker ever presenting a CA-signed certificate or completing a handshake.

```go
func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
```
