### Title
`NativeWithdraw` permanently burns a user's wNEAR balance with no refund path when the final native transfer fails - ([File: contracts/defuse/src/contract/tokens/nep141/native.rs])

### Summary
Unlike every other withdrawal path in the Defuse contract (`ft_withdraw`, `nft_withdraw`, `mt_withdraw`), `NativeWithdraw` has no resolve/refund callback. Once a user's wNEAR balance is debited and unwrapped to native NEAR, the final `Promise::new(receiver_id).transfer(amount)` step has no `.then()` resolver to detect failure and credit the user back. If that transfer fails for any reason, the debited value is neither delivered to the receiver nor refunded to the owner, permanently orphaning the funds inside the contract's own NEAR balance — the same class of defect as `Bank.sol`'s missing `receive()`, where value that leaves custody accounting has no path back into the ledger when the final leg of the transfer fails.

### Finding Description
`native_withdraw` first commits the debit against the owner's ledger balance and dispatches `near_withdraw` on wNEAR, then chains a callback into `do_native_withdraw`: [1](#0-0) 

`do_native_withdraw` only guards that `near_withdraw` itself succeeded, and then fires a bare `Promise::new(receiver_id).transfer(amount)` with no further `.then()` step to check the outcome or refund on failure: [2](#0-1) 

The intent's own doc comment acknowledges this: "the `wNEAR` will not be refunded in case of fail (e.g. `receiver_id` account does not exist)": [3](#0-2) 

Compare this with every other withdraw type, which all use a `_resolve_withdraw` callback that inspects the promise result and re-deposits (`self.deposit(...)`) any amount that failed to transfer, exactly modeling `debited == delivered + refunded`: [4](#0-3) 

The same resolve+refund pattern exists for NFTs and MTs: [5](#0-4) [6](#0-5) 

`NativeWithdraw` is structurally the odd one out: it is the only withdraw path in the contract where the custody binding "value debited == value delivered + value refunded" is not enforced by any code path. Because the ledger debit happens in an earlier, already-committed receipt (`self.withdraw(...)` in `native_withdraw`), a later failure in the detached promise chain (`near_withdraw` failing, or the final native `transfer` failing because `receiver_id` doesn't exist, was deleted, or transfer fails for any other on-chain reason) cannot roll back that debit. The NEAR that was unwrapped from wNEAR remains held by the Defuse contract's own account balance, disconnected from any user's ledger entry — a fund freeze from the affected user's perspective.

### Impact Explanation
This breaks the conservation invariant "debited == delivered + refunded" that is otherwise enforced for every other asset type in the contract (`ft_resolve_withdraw`, `nft_resolve_withdraw`, `mt_resolve_withdraw`). Any failure on the final native transfer leg (non-existent/deleted `receiver_id`, or transient NEAR delivery failure) results in funds that are irrecoverably stuck in the Defuse contract's own balance and unaccounted for on any user's ledger — matching the "funds permanently frozen" criterion.

### Likelihood Explanation
Likelihood is high for the ordinary failure mode: any user (or any script/integration constructing a `NativeWithdraw` intent) that supplies a `receiver_id` which does not exist as a named NEAR account will trigger exactly this loss, since NEAR native transfers to non-existent named accounts fail at the protocol level. No privileged role, DAO action, or victim key is required — a normal signer executing their own signed `NativeWithdraw` intent is sufficient to permanently lose the withdrawn amount, with no automatic recovery.

### Recommendation
Add a `native_resolve_withdraw`-style callback after the final `Promise::new(receiver_id).transfer(amount)`, symmetric to `ft_resolve_withdraw`/`nft_resolve_withdraw`/`mt_resolve_withdraw`, that checks the promise result and re-deposits (`self.deposit(...)`) the wNEAR-equivalent amount back to the owner if the native transfer failed, so that `debited == delivered + refunded` holds for `NativeWithdraw` just as it does for every other withdraw path.

### Proof of Concept
1. User signs and executes a `NativeWithdraw { receiver_id: "nonexistent-account.near", amount }` intent against their own wNEAR-backed Defuse balance.
2. `native_withdraw` debits `amount` from the owner's ledger and dispatches `near_withdraw` on wNEAR (`contracts/defuse/src/contract/intents/state.rs:212-237`).
3. `do_native_withdraw` unwraps the NEAR and calls `Promise::new("nonexistent-account.near").transfer(amount)` (`contracts/defuse/src/contract/tokens/nep141/native.rs:12-19`).
4. Because the named account does not exist, the native transfer receipt fails; the NEAR balance stays on the Defuse contract's own account.
5. No callback exists to detect this failure and re-credit the owner, so the owner's ledger balance remains debited with no corresponding on-chain delivery or refund — the funds are permanently lost to the user, contradicting the conservation binding enforced everywhere else in the contract.

#[near]
impl FungibleTokenWithdrawResolver for Contract {
    #[private]
    fn ft_resolve_withdraw(
        &mut self,
        token: AccountId,
        sender_id: AccountId,
        amount: U128,
        is_call: bool,
    ) -> U128 {
        let used = if is_call {
            // `ft_transfer_call` returns successfully transferred amount
            match promise_result_checked_json::<U128>(0) {
                Ok(Ok(used)) => used.0.min(amount.0),
                Ok(Err(_deserialize_err)) => 0,
                // do not refund on failed `ft_transfer_call` due to
                // NEP-141 vulnerability: `ft_resolve_transfer` fails to
                // read result of `ft_on_transfer` due to insufficient gas
                Err(_) => amount.0,
            }
        } else {
            // `ft_transfer` returns empty result on success
            if promise_result_checked_void(0).is_ok() {
                amount.0
            } else {
                0
            }
        };

        let refund = amount.0.saturating_sub(used);
        if refund > 0 {
            self.deposit(
                sender_id,
                [(Nep141TokenId::new(token).into(), refund)],
                Some(REFUND_MEMO),
            )
            .unwrap_or_else(|err| err.panic());
        }

        U128(used)
    }
}

#[near]
impl MultiTokenWithdrawResolver for Contract {
    #[private]
    fn mt_resolve_withdraw(
        &mut self,
        token: AccountId,
        sender_id: AccountId,
        token_ids: Vec<defuse_nep245::TokenId>,
        amounts: Vec<U128>,
        is_call: bool,
    ) -> Vec<U128> {
        require!(
            token_ids.len() == amounts.len() && !amounts.is_empty(),
            "invalid args"
        );

        let mut used = if is_call {
            // `mt_batch_transfer_call` returns successfully transferred amounts
            match promise_result_checked_json_with_len::<Vec<U128>>(0, amounts.len()) {
                Ok(Ok(used)) if used.len() == amounts.len() => used,
                Ok(_) => vec![U128(0); amounts.len()],
                // do not refund on failed `mt_batch_transfer_call` due to
                // NEP-141 vulnerability: `mt_resolve_transfer` fails to
                // read result of `mt_on_transfer` due to insufficient gas
                Err(_) => amounts.clone(),
            }
        } else {
            // `mt_batch_transfer` returns empty result on success
            if promise_result_checked_void(0).is_ok() {
                amounts.clone()
            } else {
                vec![U128(0); amounts.len()]
            }
        };

        self.deposit(
            sender_id,
            token_ids
                .into_iter()
                .zip(amounts)
                .zip(&mut used)
                .filter_map(|((token_id, amount), used)| {
                    // update min during iteration
                    used.0 = used.0.min(amount.0);
                    let refund = amount.0.saturating_sub(used.0);
                    if refund > 0 {
                        Some((Nep245TokenId::new(token.clone(), token_id).into(), refund))
                    } else {
                        None
                    }
                }),
            Some(REFUND_MEMO),
        )
        .unwrap_or_else(|err| err.panic());

        used
    }
}
