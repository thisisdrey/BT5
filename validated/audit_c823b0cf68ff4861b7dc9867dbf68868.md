### Title
LPs can front-run `liquidate()`'s bad-debt write-down by calling `redeem()` at the stale, inflated exchange rate - (File: `local-testing/contracts/vault/vault-stx.clar` / `vault-sbtc.clar` / `vault-ststx.clar` / `vault-usdc.clar` / `vault-usdh.clar` / `vault-ststxbtc.clar`, and `local-testing/contracts/market/market.clar`; mirrored in `mainnet/contracts/vault/v0-vault-*.clar` and `mainnet/contracts/market/v0-4-market.clar`)

### Summary
The referenced report describes depositors front-running a privileged "block" transaction to withdraw funds before a penalty (seizure) is applied to them. The analogous root cause exists in Zest's vault/market design: any liquidity provider can call the fully permissionless `redeem` function at any time, and the vault's exchange rate (`convert-to-assets-preview`) is computed from a `total-assets` figure that still includes bad, soon-to-be-written-off debt as if it were healthy interest-bearing debt. When a position with exhausted collateral gets `liquidate`d, `socialize-debt-asset` writes down `lindex`/`total-assets` to reflect the realized loss — but an LP who sees the liquidation (and its embedded price-feed update) land can front-run it with a same-block `redeem()` at the still-inflated rate, extracting a disproportionate share of the vault's real liquid cash and leaving the socialized loss entirely to the LPs who remain.

### Finding Description
`redeem` in every vault (e.g. `local-testing/contracts/vault/vault-stx.clar:797-831`) is a public, unauthenticated function callable by any LP holding zTokens: [1](#0-0) 

The redemption amount is derived from `convert-to-assets-preview`, which uses `total-assets-preview`: [2](#0-1) 

`total-assets` (and its preview variant) adds the *entire* outstanding debt-derived interest to the cash-on-hand `assets` variable, without distinguishing between healthy debt and debt owed by a position that is already undercollateralized/insolvent: [3](#0-2) 

Only when `liquidate()` fully exhausts a borrower's collateral does the market call `socialize-debt-asset`, which calls the vault's `socialize-debt`, writing `lindex` down proportionally to the realized loss in `total-assets`: [4](#0-3) [5](#0-4) 

Until that `liquidate`/`socialize-debt` call lands, every LP's share is priced as though the bad debt will be fully repaid — the exchange rate is stale/inflated. Because:
1. `liquidate()` requires an explicit price-feed update passed in as a parameter (`write-feeds price-feeds`) that is visible in the transaction/mempool before it is mined, and
2. `redeem()` has no cooldown, timelock, or block-based restriction (unlike `borrow`, which records `last-borrow-block` specifically to block same-block flash-loan liquidation, per `local-testing/contracts/market/market-vault.clar:442-450`),

an LP monitoring pending transactions can observe an impending `liquidate()` call that will trigger bad-debt socialization on a vault, and submit a higher-fee `redeem()` in the same or an earlier block. That `redeem()` executes at the old, unadjusted exchange rate, letting the front-running LP extract real, liquid `assets` (checked only by `(asserts! (>= current-assets inkind) ERR-INSUFFICIENT-ASSETS)`) proportional to the inflated share price, before `lindex`/`total-assets` is corrected downward for everyone else.

This mirrors the report's root cause precisely: a state-changing operation that imposes a loss on a set of principals (bad-debt write-down on all LPs) is not applied atomically/pre-emptively; the affected, unprivileged principals can permissionlessly react to a visible pending transaction and extract value before the loss lands on them, shifting it entirely onto remaining passive LPs.

### Impact Explanation
Bad debt in Zest's design is meant to be socialized pro-rata across all LPs of the vault holding that debt asset (per the `bad-debt-socialized` event and `lindex` write-down mechanism). By front-running the triggering `liquidate()` call with `redeem()`, an LP can withdraw at the stale, un-written-down rate, permanently and unfairly transferring their portion of the loss onto the remaining depositors of that vault. This is a form of theft of value belonging to other depositors (their principal/yield share is diminished beyond their fair pro-rata exposure) — falling under "theft of unclaimed yield" / temporary or permanent freezing of remaining depositors' funds, since the vault's real backing assets are drained disproportionately by the front-runner while `total-assets`/`lindex` for the remainder is only corrected after the fact.

### Likelihood Explanation
Medium-High. `liquidate()` is a fully public function, its calldata (including the price-feed update needed to make the position liquidatable/bad-debt-triggering) is visible pre-confirmation, and `redeem()` has no cooldown or block-delay protection analogous to the `last-borrow-block` check used elsewhere in the codebase for the symmetric flash-loan/liquidation-timing risk. Any LP (or a bot monitoring the mempool on behalf of LPs) can exploit this whenever a position is about to be liquidated with insufficient collateral to fully cover debt.

### Recommendation
- Short term: Introduce a mechanism analogous to the existing `last-borrow-block` same-block protection — e.g., snapshot/queue redemptions so that pending bad-debt socialization from an in-flight liquidation is applied before any `redeem()` in the same block is priced, or require a short delay/cooldown on `redeem()` after significant health-affecting events.
- Long term: Compute `total-assets`/exchange rate to discount debt on positions that are currently eligible for liquidation with insufficient collateral (i.e., mark expected bad debt down in real time / continuously, rather than only at the moment `socialize-debt` executes), removing the window where the exchange rate is knowably stale relative to an imminent write-down.

### Proof of Concept
1. Alice borrows heavily against thin collateral in vault-usdc's egroup; the oracle price for her collateral asset drops such that her position moves into `LTV-LIQ-FULL` territory with `coll-final == user-coll-balance` after seizure (i.e., collateral fully exhausted), guaranteeing `no-collateral-left` and hence `socialize-debt-asset` will run.
2. A liquidator broadcasts `liquidate(alice, collateral-ft, usdc-ft, debt-amount, min-collateral-expected, none, (some price-feeds))` — visible in the mempool along with the price update needed to make her liquidatable, per `local-testing/contracts/market/market.clar:1411-1454`.
3. Bob (an LP in `vault-usdc`) observes this pending transaction and immediately submits `redeem(shares, min-out, bob)` on `vault-usdc` with a higher fee, landing in the same or an earlier block, at the still-inflated `convert-to-assets-preview` rate computed from `total-assets` that still counts Alice's now-uncollectible interest as good debt (`local-testing/contracts/vault/vault-usdc.clar` `total-assets`/`redeem`).
4. The liquidation subsequently executes, `socialize-debt-asset`/`socialize-debt` writes `lindex` down to reflect the real loss (`local-testing/contracts/market/market.clar:901-925`, `local-testing/contracts/vault/vault-ststx.clar:948-988`).
5. Bob has extracted his redemption at the pre-write-down rate; the loss that should have been shared pro-rata across all `vault-usdc` LPs is now borne entirely by the LPs who did not redeem before step 3.

(define-public (socialize-debt (scaled-amount uint))
  (let ((scaled-principal (var-get principal-scaled))
        (borrowed (var-get total-borrowed))
        (idx (var-get index))
        (current-assets (var-get assets))
        (current-lindex (var-get lindex))
        (old-total-assets (total-assets))
        (debt-reduction (mul-div-down scaled-amount idx INDEX-PRECISION))
        (principal-reduction (if (> scaled-principal u0)
                                (mul-div-down scaled-amount borrowed scaled-principal)
                                u0))
        ;; Write down lindex proportionally to loss in total-assets
        (new-lindex (if (and (> old-total-assets u0) (> old-total-assets debt-reduction))
                       (mul-div-down current-lindex (- old-total-assets debt-reduction) old-total-assets)
                       u0)))

    (try! (check-caller-auth))
    (asserts! (> scaled-amount u0) ERR-AMOUNT-ZERO)

    (var-set lindex new-lindex)
    (var-set principal-scaled (if (> scaled-principal scaled-amount) (- scaled-principal scaled-amount) u0))
    (var-set total-borrowed (if (> borrowed principal-reduction) (- borrowed principal-reduction) u0))
    (var-set assets (if (> current-assets principal-reduction) (- current-assets principal-reduction) u0))

    (print {
      action: "socialize-debt",
      caller: contract-caller,
      data: {
        scaled-amount: scaled-amount,
        debt-reduction: debt-reduction,
        principal-reduction: principal-reduction,
        old-lindex: current-lindex,
        new-lindex: new-lindex,
        old-total-assets: old-total-assets,
        principal-scaled: (if (> scaled-principal scaled-amount) (- scaled-principal scaled-amount) u0),
        total-borrowed: (if (> borrowed principal-reduction) (- borrowed principal-reduction) u0),
        index: idx
      }
    })

    (ok true)))

(define-private (socialize-debt-asset
                (debt-entry { aid: uint, scaled: uint })
                (acc { borrower: principal, success: bool }))
  ;; Early return if previous socialization failed
  (if (not (get success acc))
      acc
      (let ((borrower (get borrower acc))
            (failed-status { borrower: borrower, success: false })
            (asset-id (get aid debt-entry))
            (scaled-debt (get scaled debt-entry)))

            ;; Socialize in vault - pass scaled directly to avoid rounding
            (unwrap! (vault-socialize-debt asset-id scaled-debt) failed-status)
            ;; Refresh cache with new indexes post-write-down (lindex decreased)
            (map-set index-cache
                     { timestamp: stacks-block-time, aid: asset-id }
                     (unwrap! (vault-accrue asset-id) failed-status))
            ;; Remove from obligation
            (unwrap! (contract-call? .market-vault
                                      debt-remove-scaled
                                      borrower
                                      scaled-debt
                                      asset-id) failed-status)
          acc)
        ))
