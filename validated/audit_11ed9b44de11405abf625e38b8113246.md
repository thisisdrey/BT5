### Title
Unauthenticated forged miner messages accepted via `/stackerdb_chunks` MINERS_NAME branch with no signature check - (File: libsigner/src/events.rs)

### Summary
`SignerEventReceiver::next_event` routes any POST to `/stackerdb_chunks` straight into `process_event::<T, StackerDBChunksEvent>` with no authentication, and `TryFrom<StackerDBChunksEvent> for SignerEvent<T>` deserializes every chunk in the `MINERS_NAME` branch with a bare `T::consensus_deserialize(&mut chunk.data.as_slice())`, never calling `chunk.recover_pk()` or any signature verification. This lets anyone who can open a TCP connection to the bound port inject arbitrary attacker-controlled messages (e.g. a forged `BlockProposal`) that are delivered as `SignerEvent::MinerMessages`, indistinguishable from a genuine `.miners` slot-signed message.

### Finding Description
The broken equality claimed is: *every entry in `SignerEvent::MinerMessages` == data taken from a chunk actually signed by the `.miners` StackerDB slot owner*. Tracing the code:

- `SignerEventReceiver::bind` opens a plain `tiny_http::Server` with no TLS and no auth mechanism [1](#0-0) .
- `next_event` dispatches any POST to `/stackerdb_chunks` to `process_event::<T, StackerDBChunksEvent>(request)` with no credential/secret check anywhere in the function [2](#0-1) .
- `process_event` just reads the body, JSON-deserializes it into `StackerDBChunksEvent`, and calls `.try_into()` [3](#0-2) .
- In `TryFrom<StackerDBChunksEvent>`, when `event.contract_id.name.as_str() == MINERS_NAME`, the code iterates `event.modified_slots` and does `T::consensus_deserialize(&mut chunk.data.as_slice())` directly, pushing the result into `messages`, which becomes `SignerEvent::MinerMessages(messages)` [4](#0-3) . No `chunk.recover_pk()`, no `StackerDBChunkData::verify()`, and no signer-set membership check occurs in this branch.
- By contrast, the sibling `SIGNERS_NAME` branch a few lines below explicitly calls `chunk.recover_pk()` and rejects the chunk on failure before accepting the message [5](#0-4) , showing the authors intended signature verification for StackerDB chunks but omitted it for the miner-message path.

Because the HTTP endpoint has no authentication and the JSON→`StackerDBChunksEvent`→chunk pipeline never checks `chunk.sig`/`chunk.recover_pk()` for the `.miners` contract, an attacker who can reach the bound socket can POST a crafted `StackerDBChunksEvent` JSON body with `contract_id.name = "miners"` and any `modified_slots[i].data` bytes that happen to consensus-deserialize as `T` (e.g. a `BlockProposal`), and it will be delivered to the signer runloop as `SignerEvent::MinerMessages`, exactly as if it came from the legitimate miner slot owner.

### Impact Explanation
This is unauthenticated injection of attacker-controlled data into the signer's message stream: a forged `BlockProposal` (or other miner message) is accepted and forwarded to the signer runloop as authentic miner data, with no cryptographic binding to the actual `.miners` slot key. This matches the "Critical: unauthenticated/unauthorized write to state, network-wide propagation of forged data" category, since the signer's decision/response logic downstream consumes `SignerEvent::MinerMessages` under the assumption it is authenticated. The attack is repeatable for every POST to `/stackerdb_chunks`.

### Likelihood Explanation
Precondition is only that the attacker can open a TCP connection to the address `SignerEventReceiver::bind` is listening on — no secret, no valid slot ownership, no privileged role is required, per the event receiver code shown, which has zero auth checks in `next_event`/`process_event`/the `TryFrom` implementation. Cost is a single crafted HTTP POST; the attack is trivially repeatable.

### Recommendation
In the `MINERS_NAME` branch of `TryFrom<StackerDBChunksEvent> for SignerEvent<T>`, call `chunk.recover_pk()` (or equivalent signature/`StackerDBChunkData::verify()` check) and verify the recovered public key corresponds to the authorized miner for that slot/reward-cycle before accepting `chunk.data` into `messages`, mirroring the verification already performed in the `SIGNERS_NAME` branch.

fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}
