Audit Report

## Title
Atomic Swap pallet permanently locks reserved funds on failed claim due to unconditional storage removal - (File: substrate/frame/atomic-swap/src/lib.rs)

## Summary
`claim_swap` computes whether `SwapAction::claim` actually succeeded but removes the `PendingSwaps` entry unconditionally regardless of that result. For `BalanceSwapAction`, `claim` can fail (return `false`) if `source`'s untagged reserved balance is insufficient at claim time, and once the entry is removed, `cancel_swap` — the only other path that can `unreserve` `source`'s funds — fails with `Error::NotExist` because it looks up the same now-deleted key, permanently stranding `source`'s reserved balance.

## Finding Description
`claim_swap` reads the pending swap, calls `swap.action.claim(&swap.source, &target)` to attempt settlement, and stores the boolean result in `succeeded`. For the `BalanceSwapAction` implementation, `claim` wraps `Currency::repatriate_reserved(source, target, self.value, BalanceStatus::Free)` and returns `.is_ok()`, which is `false` whenever `source`'s reserved balance is below `self.value` at the time of the call. `ReservableCurrency::reserve`/`unreserve` operate on a single, untagged per-account reserved-balance counter, so anything else reducing `source`'s reserved balance between `create_swap` and `claim_swap` (other pallets' reserve/unreserve activity, slashes, etc.) can trigger this failure path.

Regardless of `succeeded`'s value, `PendingSwaps::<T>::remove(target.clone(), hashed_proof)` executes unconditionally immediately afterward, and only the `SwapClaimed { success: succeeded }` event communicates the failure. Because the swap record keyed by `(target, hashed_proof)` is destroyed, `cancel_swap`'s lookup `PendingSwaps::<T>::get(&target, hashed_proof)` returns `None` and the call reverts with `Error::NotExist` before reaching `swap.action.cancel(&swap.source)` (which would call `C::unreserve`). The reservation created earlier in `create_swap` via `action.reserve(&source)` thus has no remaining dispatchable code path to be released.

## Impact Explanation
This is a permanent, unrecoverable lock of user funds (the reserved balance of `source` corresponding to the deleted `PendingSwaps<T>` entry for `(target, hashed_proof)`), triggerable entirely through the pallet's own public, unprivileged extrinsics with no governance, validator, or admin involvement — matching the "permanent user-fund ... lock" criterion of the impact gate, since settlement state (`PendingSwaps` removal) advances even though the underlying settlement action did not succeed.

## Likelihood Explanation
The trigger condition — `source`'s generic reserved balance dropping below `value` by claim time — is reachable in any production runtime where the same `Currency`/reserve pool is shared across pallets (the pallet uses the legacy untagged `ReservableCurrency`), or can be deliberately engineered by `source` to grief a counterparty. It requires no special timing, validator cooperation, or privileged access; any signed account pair using `create_swap`/`claim_swap`/`cancel_swap` can encounter or induce it.

## Recommendation
In `claim_swap`, only remove the `PendingSwaps` entry when `succeeded` is `true`. On failure, either leave the entry intact so `source` can later `cancel_swap` after `end_block` (or `target` can retry the claim), or explicitly `unreserve`/refund `source`'s remaining stake as part of the same failed-claim path before removing the entry, ensuring no dispatchable value can become permanently stranded.

## Proof of Concept
1. `A` (source) calls `create_swap(target = B, hashed_proof = H, action = BalanceSwapAction::new(V), duration = D)`, reserving `V` via `action.reserve(&A)`.
2. Before `B` claims, `A`'s reserved balance drops below `V` through any independent operation touching the shared reserve pool.
3. `B` calls `claim_swap(proof, action)` with the correct pre-image of `H`; `swap.action.claim(&A, &B)` fails (`repatriate_reserved` errors), so `succeeded = false`.
4. `PendingSwaps::<T>::remove(B, H)` still executes; `Event::SwapClaimed { success: false }` is emitted.
5. `A` later calls `cancel_swap(target = B, hashed_proof = H)` after `end_block`; lookup returns `None`, call reverts with `Error::NotExist`, and `action.cancel(&A)` never runs.
6. `A`'s remaining reserved balance stays reserved indefinitely with no pallet call able to release it.
