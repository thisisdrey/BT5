### Title
Early-return via `?` in `GetTenureStartBlock` arm skips `self.idle = true`, permanently desyncing `NakamotoTenureDownloader::idle` from the actual (no-longer-inflight) `NeighborRPC` state - (File: stackslib/src/net/download/nakamoto/tenure_downloader.rs)

### Summary
`NakamotoTenureDownloader::handle_next_download_response` sets `self.idle = true` only after the `match` block completes normally, but the `GetTenureStartBlock` (and `GetTenureEndBlock`/`GetTenureBlocks`) arms use the `?` operator on `response.decode_nakamoto_block()`, which returns early from the whole function on decode failure. A remote peer chosen as a download source can trivially trigger this by replying to the tenure-start-block GET request with a body that fails to decode as a `NakamotoBlock`, permanently leaving `self.idle == false` even though the corresponding `NeighborRPC` entry for `self.naddr` has already been drained/removed by `collect_replies`.

### Finding Description
The invariant the state machine relies on is: `self.idle == true` iff `NeighborRPC` has no in-flight request for `self.naddr`. `send_next_download_request` sets `self.idle = false` right after calling `neighbor_rpc.send_request(...)` [1](#0-0) . The response is expected to flip `idle` back to `true` once handled, via the final statement of `handle_next_download_response`:

```rust
let handle_result = match &self.state {
    NakamotoTenureDownloadState::GetTenureStartBlock(block_id, start_request_time) => {
        ...
        let block = response.decode_nakamoto_block().inspect_err(|e| {
            warn!("Failed to decode response for a Nakamoto block: {e:?}")
        })?;
        self.try_accept_tenure_start_block(block)?;
        Ok(None)
    }
    ...
};
self.idle = true;
handle_result
``` [2](#0-1) 

Because `?` propagates the `Err` out of `handle_next_download_response` itself (not just out of the match arm), a decode failure causes the function to return before line 802 executes, so `self.idle` is never reset to `true`.

Meanwhile, `NeighborRPC::collect_replies` drains the corresponding entry out of its internal `state` map once a response is retrieved from the wire, regardless of whether that response later fails to parse: `for (naddr, (event_id, mut request_opt)) in self.state.drain() { ... ret.push((naddr, response)); }` [3](#0-2) . After this drain, `has_inflight(&self.naddr)` returns `false` [4](#0-3) , while `self.idle` on the `NakamotoTenureDownloader` is stuck at `false`. The equality `idle == !has_inflight` is broken permanently for this instance.

The attacker's exact message: any peer picked as `self.naddr` for a `NakamotoTenureDownloader` in the `GetTenureStartBlock(block_id, ..)` state can respond to the corresponding `GET /v3/blocks/{block_id}` (or equivalent nakamoto-block route) request with a 200 (or otherwise HTTP-valid) response whose body is not a well-formed `NakamotoBlock`. `StacksHttpResponse::decode_nakamoto_block()` will return `Err`, which is exactly what `inspect_err` logs and `?` propagates. No signature, no secret, and no privileged role is required — only that this node selected the peer as a tenure download source, which happens as part of normal, unauthenticated tenure-download peer selection (matched by any `naddr` a node picked via inventory gossip).

### Impact Explanation
Once `self.idle` is stuck `false` for a given `NakamotoTenureDownloader`, any downstream logic that only issues a new request or reaps/retries the state machine when `idle == true` (e.g., driving `send_next_download_request` again from `tenure_downloader_set.rs`/`download_state_machine.rs`) will treat this machine as having a request perpetually in flight, even though `NeighborRPC` shows no in-flight entry. This stalls further progress on downloading that tenure (`tenure_id_consensus_hash`) from that state machine, matching a "single-message unauthenticated DoS" against this specific piece of tenure-download state: a single malformed HTTP response permanently wedges the corresponding downloader instance. This matches the audit's Critical category of "remote crash/unauthenticated DoS from few messages" — here specifically causing a permanent stall of the tenure-download state machine rather than a rebuildable state, since `idle` is never restored and no code path in this file resets it. Impact is scoped to this per-tenure downloader instance (not proven here to corrupt other tenures/machines or crash the whole node), and no data is forged, written, or served as canonical.

### Likelihood Explanation
Preconditions are minimal: the attacker only needs to be selected as a tenure-download peer (`naddr`) by the victim node, which happens through normal, unauthenticated P2P handshake and inventory-driven peer selection — no RPC secret, no StackerDB slot key, no privileged role. Attacker cost is a single malformed HTTP response to a `GetTenureStartBlock` request. The bug is deterministic and repeatable for every state machine instance targeting that peer.

### Recommendation
Move `self.idle = true;` so it is set unconditionally before returning from `handle_next_download_response`, e.g., by computing `handle_result` without early-returning via `?` inside the match (convert to explicit `match ... { Ok(v) => v, Err(e) => { self.idle = true; return Err(e); } }`), or set `self.idle = true` at every error path (each `inspect_err`/`?` site) so `idle` is always resynchronized with `NeighborRPC`'s actual in-flight status regardless of decode success/failure.

### Proof of Concept
Add a unit test in `stackslib/src/net/download/nakamoto/tenure_downloader.rs` (or `stackslib/src/net/tests/download/nakamoto.rs`):
1. Construct a `NakamotoTenureDownloader` via `NakamotoTenureDownloader::new(...)` — this sets `state = GetTenureStartBlock(tenure_start_block_id, ts)` and `idle = false`.
2. Simulate having sent a request (optional, since `idle` starts `false` by construction already, matching post-`send_next_download_request` state).
3. Build a `StacksHttpResponse` whose body is not a valid `NakamotoBlock` (e.g., an HTTP 200 response with an empty or garbage byte body, or a well-formed HTTP response wrapping an unrelated payload) so that `response.decode_nakamoto_block()` returns `Err`.
4. Call `downloader.handle_next_download_response(response)`.
5. Assert the call returns `Err(..)`.
6. Assert `downloader.idle == false` (bug: should have been reset to reflect no in-flight request), while independently confirming (or noting) that a `NeighborRPC` instance would no longer contain an in-flight entry for this `naddr` after `collect_replies` drained it — demonstrating the state divergence.

    pub fn collect_replies(
        &mut self,
        network: &mut PeerNetwork,
    ) -> Vec<(NeighborAddress, StacksHttpResponse)> {
        let mut inflight = HashMap::new();
        let mut dead = vec![];
        let mut ret = vec![];
        for (naddr, (event_id, mut request_opt)) in self.state.drain() {
            let response =
                match NeighborRPC::poll_next_reply(network, &naddr, event_id, &mut request_opt) {
                    Ok(Some(response)) => response,
                    Ok(None) => {
                        // keep trying
                        debug!("Still waiting for next reply from {naddr}");
                        inflight.insert(naddr, (event_id, request_opt));
                        continue;
                    }
                    Err(NetError::WaitingForDNS) => {
                        // keep trying
                        debug!("Could not yet poll next reply from {naddr}: waiting for DNS",);
                        inflight.insert(naddr, (event_id, request_opt));
                        continue;
                    }
                    Err(NetError::InProgress) => {
                        // keep trying
                        debug!(
                        "Could not yet poll next reply from {naddr}: request already in progress",
                    );
                        inflight.insert(naddr, (event_id, request_opt));
                        continue;
                    }
                    Err(e) => {
                        // declare this neighbor as dead by default
                        debug!("Failed to poll next reply from {naddr}: {e}");
                        dead.push((
                            naddr,
                            DropReason::DeadConnection(format!("Failed to poll next reply: {e}")),
                        ));
                        continue;
                    }
                };

            ret.push((naddr, response));
        }
        for (naddr, reason) in dead.into_iter() {
            self.add_dead(network, &naddr, reason, DropSource::NeighborRPC);
        }
        self.state.extend(inflight);
        ret
    }
```
