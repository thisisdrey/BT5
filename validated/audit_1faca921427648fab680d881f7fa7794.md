### Title
Front-Running Repository Creation via Predictable Replica Paths Causes Denial-of-Service on Fork/Import RPCs - ([File: internal/gitaly/storage/repository_path.go])

### Summary
Gitaly derives a repository's on-disk relative path deterministically from its sequential repository ID via `DeriveReplicaPath`/`deriveDiskPath`, and both Gitaly's `repoutil.Create` and Praefect's `ReserveRepositoryID` treat "does this path/ID already exist" as a simple existence check that the first caller wins. Because the path is predictable from a sequential integer, an unprivileged caller who can trigger any repository-creating RPC (`CreateRepository`, `CreateFork`, `CreateRepositoryFromURL`, `CreateObjectPool`, etc., e.g. via GitLab's fork/import flows) can pre-create a repository at the relative path that will be assigned to the next legitimate repository, permanently blocking that legitimate creation with an `AlreadyExists` error — the same "front-run a predictable identifier to grief a legitimate future action" pattern as the CredibleAccountModule `enableSessionKey` bug.

### Finding Description
`DeriveReplicaPath` computes the on-disk path purely as a hash of the sequential repository ID, with no random or secret component:

<cite repo="Loderfordw/gitaly--007" path="internal/gitaly/storage/repository_path.go" start="45="50" end="68" /> [1](#0-0) 

Repository creation in `repoutil.Create` only guards against a *concurrent* creation happening in the tiny window between two on-disk stats; it does not protect against an attacker having created the target path arbitrarily far in advance: [2](#0-1) [3](#0-2) 

At the Praefect layer, the same "first writer wins" semantics apply to ID reservation, which is documented and tested as returning `ErrRepositoryAlreadyExists` to whichever caller loses the race for a given `virtualStorage`/`relativePath`: [4](#0-3) [5](#0-4) 

All of these creating RPCs are reachable through ordinary user-triggered actions (forking a project, importing a repository by URL, etc.), and Praefect explicitly lists them as `repositoryCreatingRPCs`: [6](#0-5) 

Because the target `relativePath`/replica path is a deterministic function of a predictable, sequential repository ID, an attacker can precompute the path that will be assigned to the next repository (their own upcoming fork, or another user's project about to be created/imported) and race to create a dummy repository or file at that exact path before the legitimate flow completes. The legitimate creation then fails at the pre-lock/post-lock `os.Stat` check with `AlreadyExists`, exactly mirroring the impact of the reference bug: the legitimate actor is permanently prevented from claiming a resource whose identifier could be predicted in advance by an unrelated party.

### Impact Explanation
This is a denial-of-service vector against repository provisioning: any user able to invoke a repository-creating RPC repeatedly (directly, or indirectly through the GitLab fork/import API which forwards to Gitaly) can squat on upcoming, predictable replica paths and cause legitimate `CreateRepository`/`CreateFork`/`CreateRepositoryFromURL`/`CreateObjectPool`/`ReplicateRepository` calls to fail with `AlreadyExists`. Unlike the original SCW bug where the effect was blocking one specific session key, here the effect is blocking creation of a specific project/fork's repository, which can disrupt onboarding, imports, or forking workflows for other tenants sharing the same Gitaly/Praefect deployment.

### Likelihood Explanation
Exploitation only requires knowledge of the (small, sequential) space of upcoming repository IDs and the ability to issue repository-creating RPCs — both are realistic in a multi-tenant GitLab/Gitaly deployment where repository IDs are sequential and project creation/import/fork endpoints are exposed to ordinary authenticated users. No special privilege beyond normal write access to create a repository somewhere is needed to pre-create a colliding path.

### Recommendation
Do not rely purely on "path does not yet exist" as proof of legitimate ownership of a to-be-created repository. Introduce an authoritative reservation step tied to the actual owning entity (e.g., reserve the repository ID/relative path transactionally in the metadata store before any filesystem path is derived or exposed, and reject/replace externally pre-created directories at reserved paths rather than treating pre-existence as authoritative) so that racing to create a predictable path cannot pre-empt the rightful owner's reservation.

### Proof of Concept
1. Observe (or infer from prior successful creations) the next sequential repository ID that Praefect/Gitaly will assign, e.g. via `storage.DeriveReplicaPath(nextID)`.
2. Before the legitimate user's fork/import completes, call `CreateRepository`/`CreateRepositoryFromURL` directly with `RelativePath` set to that derived path (as `create_repository_test.go`'s `preexistingRepo` cases demonstrate is possible today).
3. When the legitimate fork/import flow later attempts to create its repository at the now-colliding replica path, `repoutil.Create`'s pre-lock/post-lock stat finds the path occupied and returns `structerr.NewAlreadyExists("repository exists already")`, permanently failing the legitimate operation as shown in `internal/gitaly/service/repository/create_repository_test.go` and `internal/gitaly/service/repository/create_fork_test.go`'s "target exists" test cases.

```go
// DeriveReplicaPath derives a repository's disk storage path from its repository ID. The repository ID
// is hashed with SHA256 and the first four hex digits of the hash are used as the two subdirectories to
// ensure even distribution into subdirectories. The format is @cluster/repositories/ab/cd/<repository-id>.
func DeriveReplicaPath(repositoryID int64) string {
	return deriveDiskPath(praefectRepositoryPathPrefix, repositoryID)
}

// DerivePoolPath derives an object pools's disk storage path from its repository ID. The repository ID
// is hashed with SHA256 and the first four hex digits of the hash are used as the two subdirectories to
// ensure even distribution into subdirectories. The format is @cluster/pools/ab/cd/<repository-id>. The pools
// have a different directory prefix from other repositories so Gitaly can identify them in OptimizeRepository
// and avoid pruning them.
func DerivePoolPath(repositoryID int64) string {
	return deriveDiskPath(praefectPoolPathPrefix, repositoryID)
}

func deriveDiskPath(prefixDir string, repositoryID int64) string {
	hasher := sha256.New()
	// String representation of the ID is used to make it easier to derive the replica paths with
	// external tools. The error is ignored as the hash.Hash interface is documented to never return
	// an error.
	hasher.Write([]byte(strconv.FormatInt(repositoryID, 10)))
	hash := hasher.Sum(nil)
	return filepath.Join(prefixDir, fmt.Sprintf("%x/%x/%d", hash[0:1], hash[1:2], repositoryID))
```
