Audit Report

## Title
`SwapFirstAssetTrader::refund_weight` performs an unprotected AMM swap (no `amount_out_min`) when converting unused XCM execution fee back to the original fee asset - ([File: cumulus/primitives/utility/src/lib.rs])

## Summary
`SwapFirstAssetTrader::buy_weight` bounds its `pallet-asset-conversion` swap by requesting an exact `amount_out` via `SwapCredit::swap_tokens_for_exact_tokens`, but `refund_weight` calls `SwapCredit::swap_exact_tokens_for_tokens(vec![Target::get(), refund_swap_asset], refund, None)` with `amount_out_min = None`, disabling the slippage floor entirely. This asymmetry means the fee-refund leg of an otherwise-protected fee-swap flow settles at whatever price the public AMM pool offers at execution time, with no minimum-output guard.

## Finding Description
`buy_weight` swaps the user's asset into `Target` using an exact-output swap bounded by the computed `fee`, so the user cannot be charged more than intended. [1](#0-0) 

`refund_weight` computes the unused portion of `total_fee` and swaps it back into the asset the user originally paid with, but passes `None` as `amount_out_min`: [2](#0-1) 

In `pallet_asset_conversion`, the minimum-output check (`ProvidedMinimumNotSufficientForSwap`) is only evaluated when `amount_out_min` is `Some(_)`; passing `None` skips this check entirely. [3](#0-2)  This code path is used in production runtime configs — `asset-hub-rococo`, `asset-hub-westend`, `penpal`, and `staking-async` all wire up `SwapFirstAssetTrader` as part of their `WeightTrader`.

## Impact Explanation
The AMM pools backing this swap are public and unprivileged: any account can shift reserves via ordinary swap/add-liquidity/remove-liquidity extrinsics. Because the refund leg has no floor, an attacker who moves the `Target -> refund_swap_asset` price unfavorably immediately before this refund executes (and reverses afterward) captures the difference as a sandwich against the pool's liquidity providers, at the user's/LP's expense. This is a genuine missing invariant (cost/value correctness on a public, permissionless AMM interaction embedded in the XCM fee path), though the magnitude per occurrence is bounded by the small "unused execution weight" refund amount, and no chain-halting, fund-locking, or origin-escalation consequence results from it.

## Likelihood Explanation
Triggering `refund_weight` requires only an ordinary XCM message that overpays execution weight while paying fees in a non-`Target` asset — a common pattern on Asset Hub/Penpal — and pool manipulation requires only unprivileged swap/liquidity extrinsics against the same public pool, executable in the same or adjacent block. No relayer, collator, or governance/admin privilege is needed.

## Recommendation
Compute a bounded `amount_out_min` for the refund swap using `SwapCredit::quote_price_exact_tokens_for_tokens` (mirroring `buy_weight`/`quote_weight`'s use of `QuotePrice`) with an acceptable slippage tolerance, and skip the refund (return `None`, keeping funds in `total_fee`) if the quote cannot be met, instead of calling `swap_exact_tokens_for_tokens` with `None`.

## Proof of Concept
1. Configure a runtime with `SwapFirstAssetTrader` as `WeightTrader` and a `pallet-asset-conversion` pool for `(Target, refund_swap_asset)`, as done in `asset-hub-rococo`/`asset-hub-westend`/`penpal` xcm_config.
2. An attacker submits a swap/liquidity extrinsic that worsens the `Target -> refund_swap_asset` price.
3. In the same/adjacent block, a user's XCM message pays fees in `refund_swap_asset` with weight overestimation, triggering `buy_weight` then `refund_weight`.
4. `refund_weight`'s `SwapCredit::swap_exact_tokens_for_tokens(..., None)` executes at the manipulated rate; the attacker reverses their trade to capture the extracted value. Contrast with `pallet_asset_conversion::swap_exact_tokens_for_tokens`'s public dispatchable, which always enforces `amount_out_min` per the `swap_should_not_work_if_too_much_slippage` test in `substrate/frame/asset-conversion/src/tests.rs` (lines 1565-1613), confirming only the `refund_weight` internal call path lacks this guard.
