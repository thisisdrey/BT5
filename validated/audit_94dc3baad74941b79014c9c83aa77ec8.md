### Title
Unbounded per-word buffering in CheckAttrCmd.Check enables memory-exhaustion DoS via crafted .gitattributes - (File: internal/git/gitattributes/check_attr.go)

### Summary
`CheckAttrCmd.Check` reads each NUL-delimited word from `git-check-attr -z` output with `bufio.Reader.ReadBytes('\000')` and imposes no size limit on any single word. Because the third word ("info"/value) is exactly the raw attribute value text taken from a `.gitattributes` file the attacker fully controls, an attacker can commit a `.gitattributes` entry with a multi-megabyte attribute value and force Gitaly to buffer that entire value in memory on every `GetFileAttributes` (or linguist) call.

### Finding Description
`gitattributes.CheckAttr` (`internal/git/gitattributes/check_attr.go:30-60`) spawns `git check-attr --stdin -z --source=<rev> <names...>` and wraps its stdout in a `bufio.Reader`. `Check(path)` (`check_attr.go:63-107`) then loops, calling `c.stdout.ReadBytes('\000')` to pull three NUL-separated words per attribute (`path`, `attribute`, `info`) — `check_attr.go:83-104`. There is no cap on the length of any word before the next NUL byte, so `ReadBytes` will keep growing its internal buffer until it finds a NUL.

The `info` field emitted by `git-check-attr` for a "set to value" attribute (`pattern attr=value`) is exactly the literal value string from `.gitattributes`, with no length restriction enforced by git or by Gitaly. An attacker who owns/forks a repository can push a `.gitattributes` file such as:
```
*.txt linguist-language=AAAA...(several MB of 'A')...
```
This is entirely attacker-controlled repository content, requiring no privileged access — just push access to their own repo, matching the threat model (unprivileged GitLab user, push/fork/import).

When any code path calls `CheckAttrCmd.Check` for a path matched by that pattern — e.g. the `GetFileAttributes` RPC handler (`internal/gitaly/service/repository/file_attributes.go:14-42`) or the linguist stats path via `fileInstance` (`internal/gitaly/linguist/file_instance.go:33-43`, used by `CommitLanguages`) — the subprocess emits the oversized value word, and `ReadBytes` buffers the whole thing into a Go string/byte slice before the loop can proceed. `validateGetFileAttributesRequest` (`file_attributes.go:44-62`) only checks that `Paths`/`Attributes`/`Revision` are non-empty; it does not bound the number of paths or attributes requested, so a single RPC call can request many paths, each triggering a fresh multi-MB (or larger) allocation.

No existing safeguard (`storage.ValidateRelativePath`, revision validation, request limits) bounds `.gitattributes` content size or the per-word read size in this parsing loop.

### Impact Explanation
This allows an unprivileged attacker to cause elevated, attacker-amplified memory allocation in the Gitaly process handling `GetFileAttributes`/linguist-consuming RPCs, proportional to the size of attribute values they can embed in `.gitattributes` and to the number of paths/attributes requested per call. Repeated or concurrent calls can drive Gitaly toward memory exhaustion, degrading or crashing the service for other users on the same node — a resource-exhaustion/DoS impact on a Gitaly RPC handler.

### Likelihood Explanation
Exploitation only requires normal push access to a repository the attacker owns and the ability to invoke a standard RPC (`GetFileAttributes`, or any GitLab feature exercising linguist language detection). No special role, secret, or non-default configuration is needed, and the primitive is straightforward and repeatable (push once, call the RPC as many times/paths as desired).

### Recommendation
Bound the size of each word read by `ReadBytes` in `CheckAttrCmd.Check`, e.g. by using `io.LimitReader` per read or a `bufio.Reader` sized/limited operation that returns an error once a configurable maximum (e.g. a few KB, matching realistic attribute value lengths) is exceeded, and treat oversized words as a check-attr protocol error. Additionally, consider bounding the number of `Paths`/`Attributes` accepted per `GetFileAttributesRequest`.

### Proof of Concept
1. In a repository the attacker controls, commit `.gitattributes`:
   ```
   *.txt linguist-language=AAAA... (e.g. 50MB of 'A') ...
   ```
   and a file `foo.txt`.
2. Call `GetFileAttributes` RPC with `Revision` = that commit, `Paths = ["foo.txt", ...repeated N times...]`, `Attributes = ["linguist-language"]`.
3. Observe that each `Check("foo.txt")` call causes `bufio.Reader.ReadBytes('\000')` (`check_attr.go:84`) to allocate a buffer on the order of the 50MB value; with N repeated paths in one request, memory usage scales as N × 50MB in a single RPC invocation, measurable via Go's memory profiler (`pprof`) during the call. func (s *server) GetFileAttributes(ctx context.Context, in *gitalypb.GetFileAttributesRequest) (*gitalypb.GetFileAttributesResponse, error) {
	if err := validateGetFileAttributesRequest(ctx, s.locator, in); err != nil {
		return nil, structerr.NewInvalidArgument("%w", err)
	}

	repo := s.localRepoFactory.Build(in.GetRepository())

	checkAttrCmd, finishAttr, err := gitattributes.CheckAttr(ctx, repo, git.Revision(in.GetRevision()), in.GetAttributes())
	if err != nil {
		return nil, structerr.New("check attr: %w", err)
	}

	defer finishAttr()

	var attrValues []*gitalypb.GetFileAttributesResponse_AttributeInfo

	for _, path := range in.GetPaths() {
		attrs, err := checkAttrCmd.Check(path)
		if err != nil {
			return nil, structerr.New("check attr: %w", err)
		}

		for _, attr := range attrs {
			attrValues = append(attrValues, &gitalypb.GetFileAttributesResponse_AttributeInfo{Path: path, Attribute: attr.Name, Value: attr.State})
		}
	}

	return &gitalypb.GetFileAttributesResponse{AttributeInfos: attrValues}, nil
}

func validateGetFileAttributesRequest(ctx context.Context, locator storage.Locator, in *gitalypb.GetFileAttributesRequest) error {
	if err := locator.ValidateRepository(ctx, in.GetRepository()); err != nil {
		return err
	}

	if len(in.GetRevision()) == 0 {
		return errors.New("revision is required")
	}

	if len(in.GetPaths()) == 0 {
		return errors.New("file paths are required")
	}

	if len(in.GetAttributes()) == 0 {
		return errors.New("attributes are required")
	}

	return nil
}
