### Title
Unauthenticated remote injection of forged `SignerEvent`s via `/stackerdb_chunks` HTTP POST - (File: libsigner/src/events.rs)

### Summary
`SignerEventReceiver::next_event` dispatches any POST to `/stackerdb_chunks` straight into `process_event::<T, StackerDBChunksEvent>`, which JSON-decodes the body and converts it via `TryFrom<StackerDBChunksEvent> for SignerEvent<T>` with no check on the identity of the HTTP client. The reference config binds this listener to `0.0.0.0`, so any network peer that can reach the port can forge events, and for the `.miners` contract branch there is no per-chunk signature verification at all before the payload is forwarded to the runloop.

### Finding Description
`next_event` routes based solely on URL path and HTTP method, with no authentication check on the sender: [1](#0-0) 

`process_event` reads the raw body, JSON-decodes it into `StackerDBChunksEvent`, and immediately converts it into a `SignerEvent`: [2](#0-1) 

Crucially, `TryFrom<StackerDBChunksEvent> for SignerEvent<T>` branches on `contract_id`. For the `.signers-X-Y` boot contracts, each chunk's origin is verified via `chunk.recover_pk()` before the message is admitted: [3](#0-2) 

But for the `.miners` boot contract branch, chunk payloads are deserialized directly with `T::consensus_deserialize` and pushed into `SignerEvent::MinerMessages` with **no signature/pubkey recovery check at all**: [4](#0-3) 

An attacker who can reach the bound address can craft a JSON `StackerDBChunksEvent` body with `contract_id.name == "miners"` and `contract_id.is_boot() == true`, and arbitrary `modified_slots` chunk data that deserializes as a valid `T` (e.g., a `BlockProposal` or other miner-lane `SignerMessage`). This bypasses the intended guarantee that `MinerMessages` only ever reflects data the node itself relayed from an authenticated StackerDB slot write (which is normally signature-checked by the StackerDB replication logic before the node's event-observer dispatch, not re-verified here). The endpoint itself performs no check that the connection originates from the local node's event-observer subsystem (no loopback check, no shared secret/auth header check) — the only "authentication" that exists anywhere in this pipeline is the per-chunk `recover_pk()` call, which is applied to the `.signers-*` lane but omitted for `.miners`.

The reference deployment config confirms this port is meant to be reachable beyond loopback: [5](#0-4) 

### Impact Explanation
A remote, unprivileged attacker who can reach the signer's event-receiver port can inject a fabricated `SignerEvent::MinerMessages(Vec<T>)` into the signer runloop's input queue via `forward_event`, with zero cryptographic verification tying the message to any real miner or StackerDB write. This is a critical unauthenticated-injection vulnerability: fabricated "miner" signer-protocol messages (e.g., forged block proposals) can be delivered directly into the signer's decision pipeline, and the attack is trivially repeatable per TCP connection/POST.

### Likelihood Explanation
The only precondition is network reachability to the bound event-receiver address, which per the shipped reference config (`endpoint = "0.0.0.0:30000"`) is not loopback-restricted by default. No secret, peer key, or StackerDB slot ownership is required — the attacker needs only to open a TCP connection and issue a well-formed HTTP POST with a crafted JSON body and a boot `.miners` contract id. This requires no privileged role and is fully remote.

### Recommendation
Add an authentication/authorization gate to the signer's event HTTP server (e.g., require a shared-secret header/token configured on both node and signer, and/or bind by default to loopback and document the trust boundary), and independently verify the authenticity of `.miners`-lane StackerDB chunks (e.g., verify the chunk was actually written by a legitimate miner's key, mirroring the `recover_pk()` check already used for the `.signers-*` lane) before constructing `SignerEvent::MinerMessages`.

### Proof of Concept
```rust
// libsigner/src/events.rs (test module) or a new integration test
use std::io::Write;
use std::net::TcpStream;
use std::sync::mpsc::channel;

#[test]
fn unauthenticated_forged_miner_event_is_forwarded() {
    let mut receiver: SignerEventReceiver<SomeT> = SignerEventReceiver::new(false);
    let addr = receiver.bind("127.0.0.1:0".parse().unwrap()).unwrap();
    let (tx, rx) = channel();
    receiver.add_consumer(tx);

    std::thread::spawn(move || receiver.main_loop());

    // Forge a StackerDBChunksEvent JSON body naming the boot .miners contract,
    // simulating a non-privileged remote sender (no auth header, no secret).
    let body = serde_json::json!({
        "contract_id": "SP000000000000000000002Q6VF78.miners",
        "modified_slots": [ /* crafted chunk with attacker-controlled data */ ]
    }).to_string();

    let mut stream = TcpStream::connect(addr).unwrap();
    let req = format!(
        "POST /stackerdb_chunks HTTP/1.1\r\nHost: {addr}\r\nContent-Length: {}\r\nContent-Type: application/json\r\nConnection: close\r\n\r\n{}",
        body.len(), body
    );
    stream.write_all(req.as_bytes()).unwrap();

    // Assert the forged event reaches the runloop consumer with no auth check.
    let ev = rx.recv_timeout(std::time::Duration::from_secs(2)).unwrap();
    assert!(matches!(ev, SignerEvent::MinerMessages(_)));
}
```
This test opens a plain TCP connection (no credentials) to the bound `SignerEventReceiver`, posts a forged `/stackerdb_chunks` body, and asserts the resulting `SignerEvent::MinerMessages` is delivered via `forward_event` at [6](#0-5)  — demonstrating unauthenticated injection into the signer runloop's queue.

    fn forward_event(&mut self, ev: SignerEvent<T>) -> bool {
        if self.out_channels.is_empty() {
            // nothing to do
            error!("No channels connected to event receiver");
            false
        } else if self.out_channels.len() == 1 {
            // avoid a clone
            if let Err(e) = self.out_channels[0].send(ev) {
                error!("Failed to send to signer runloop: {:?}", &e);
                return false;
            }
            true
        } else {
            for (i, out_channel) in self.out_channels.iter().enumerate() {
                if let Err(e) = out_channel.send(ev.clone()) {
                    error!("Failed to send to signer runloop #{}: {:?}", i, &e);
                    return false;
                }
            }
            true
        }
    }
