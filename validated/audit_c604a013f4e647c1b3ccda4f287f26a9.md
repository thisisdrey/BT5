**Tracing the invariant failure:**

If a `CompiledModule` is crafted with:
- `variant_field_instantiations = Some([VariantFieldInstantiation { handle: 0, ... }])` (non-empty)
- `variant_field_handles = None`

Then `verify_impl` calls `check_table(Some([inst]), check_variant_field_instantiation)`, which iterates and calls `check_variant_field_instantiation(inst)`. That function calls `check_bounds_impl_opt(&None, inst.handle)`, which immediately returns `Ok(())` — the handle index is never validated against any pool. The module passes the bounds checker.

**Is this reachable from an unprivileged entrypoint?**

Yes. Module publishing via a `publish_package` transaction is an unprivileged entrypoint. The binary format allows `variant_field_handles` and `variant_field_instantiations` to be independent optional tables, so a crafted binary can have one without the other. The bounds checker is the authoritative gate for this invariant.

**What is the confirmed impact?**

The bounds checker's invariant — *every `VariantFieldInstantiation` must reference a valid `VariantFieldHandle`* — is broken. A malformed module passes `BoundsChecker::verify_module` and can be committed to chain state. This is a confirmed unauthorized state transition via broken bytecode verification, which is explicitly in scope.

The secondary impact (validator crash when the VM executes `MutBorrowVariantFieldGeneric`/`ImmBorrowVariantFieldGeneric` against a `None` handle table) depends on whether the VM executor has its own guard — that code path was not reachable in this search — but the bounds checker is the designed guard and it fails.

### Title
Bounds checker silently accepts `VariantFieldInstantiation` referencing absent `variant_field_handles` table, allowing malformed module publication — (`third_party/move/move-binary-format/src/check_bounds.rs`)

### Summary
`BoundsChecker::check_variant_field_instantiation` delegates handle validation to `check_bounds_impl_opt`, which returns `Ok(())` when the `variant_field_handles` pool is `None`. A crafted `CompiledModule` with a non-empty `variant_field_instantiations` table and no `variant_field_handles` table passes `verify_module` without error, violating the invariant that every instantiation must reference a valid handle.

### Finding Description
`check_bounds_impl_opt` is defined as:

```rust
fn check_bounds_impl_opt<T, I>(pool: &Option<&[T]>, idx: I) -> PartialVMResult<()> {
    pool.map_or(Ok(()), |p| check_bounds_impl(p, idx))
}
```

When `pool` is `None`, it returns `Ok(())` unconditionally. `check_variant_field_instantiation` passes `self.view.variant_field_handles()` — which is `Option<&[VariantFieldHandle]>` and can be `None` — as the pool. If the module has no `variant_field_handles` table, the `inst.handle` field is never bounds-checked. The `check_table` wrapper only skips iteration when the *instantiations* table itself is `None`; it does not guard against the *referenced* table being absent.

### Impact Explanation
A malformed module that violates the bytecode format invariant is accepted by the verifier and committed to chain state (unauthorized state transition via broken bytecode verification). If the VM executor subsequently attempts to resolve `variant_field_handles[inst.handle]` against a `None` table without its own guard, this additionally causes a validator abort/crash on any node that processes a transaction calling into the malformed module, constituting a chain availability failure.

### Likelihood Explanation
Module publishing is an unprivileged operation. The binary format permits independent optional tables. Crafting the malformed module requires only knowledge of the binary format serialization, which is public. No privileged keys or validator access are needed.

### Recommendation
`check_variant_field_instantiation` (and the analogous `check_field_instantiation`) should explicitly reject the case where the referenced handle pool is `None` but the instantiation entry exists:

```rust
fn check_variant_field_instantiation(
    &self,
    inst: &VariantFieldInstantiation,
) -> PartialVMResult<()> {
    let handles = self.view.variant_field_handles().ok_or_else(|| {
        verification_error(
            StatusCode::INDEX_OUT_OF_BOUNDS,
            IndexKind::VariantFieldHandle,
            inst.handle.into_index() as TableIndex,
        )
    })?;
    check_bounds_impl(handles, inst.handle)?;
    check_bounds_impl(self.view.signatures(), inst.type_parameters)
}
```

Alternatively, `check_bounds_impl_opt` should be replaced at this call site with a version that errors when the pool is absent.

### Proof of Concept
Build a `CompiledModule` with:
- A valid module handle and self-handle
- One `variant_field_instantiation` entry: `VariantFieldInstantiation { handle: VariantFieldHandleIndex(0), type_parameters: SignatureIndex(0) }`
- `variant_field_handles` table: absent (`None`)
- A valid empty signature at index 0

Call `BoundsChecker::verify_module(&module)` and assert the result is `Err(...)`. Under the current code it returns `Ok(())`, confirming the invariant is broken.
