### Title
Unauthenticated `/new_block`, `/stackerdb_chunks`, `/proposal_response` event injection into signer runloop - (File: libsigner/src/events.rs)

### Summary
`SignerEventReceiver::next_event` dispatches any POST to `/stackerdb_chunks`, `/proposal_response`, or `/new_block` straight into `process_event::<T,E>`, which only performs `serde_json::from_slice` and `E::try_into::<SignerEvent<T>>()` with zero authentication of the sender. Any TCP peer that can open a connection to the bound event-receiver socket and send a well-formed HTTP POST can therefore inject a forged `SignerEvent::NewBlock`, `SignerEvent::BlockValidationResponse`, or `SignerEvent::MinerMessages`/`SignerEvent::SignerMessages` (via a crafted `StackerDBChunksEvent`) that is forwarded to the signer runloop as if it came from the configured node.

### Finding Description
`next_event` (libsigner/src/events.rs:413-459) routes on `request.url()` and calls `process_event::<T, E>(request)` for the three event types with no check of the request's origin, no shared-secret/token header, and no TLS/mTLS. `process_event` (lines 519-542) reads the raw body, JSON-decodes it into `E`, and converts it via `TryInto<SignerEvent<T>>` — this conversion happens purely on the parsed payload, before (and without) any verification that the payload came from the node's event dispatcher.

For `/new_block`, `StacksBlockEvent`'s fields (`index_block_hash`, `consensus_hash`, `block_hash`, `block_height`, `transactions`) are taken from attacker JSON verbatim and mapped 1:1 into `SignerEvent::NewBlock` (lines 690-720) — no signature, no PoW, no consensus check tying these values to any chain state. For `/proposal_response`, `BlockValidateResponse` is deserialized from JSON and wrapped directly into `SignerEvent::BlockValidationResponse` (lines 627-635) with no validation that the enclosed decision was actually produced by the node's block-validation logic. For `/stackerdb_chunks`, chunk contents inside `StackerDBChunksEvent.modified_slots` are checked for a recoverable public key (`chunk.recover_pk()`) only in the signer-contract branch (lines 596-603), but the miner-contract branch (`MINERS_NAME`) blindly deserializes chunk bytes with no key/signature check at all (lines 549-566), and the top-level `StackerDBChunksEvent` itself (contract id, slot ids, slot data) is attacker-controlled JSON with no proof the chunks were actually fetched from the real StackerDB replica set.

Because none of `next_event`, `with_server`, or `process_event` check the remote peer's IP/identity or require a shared secret/header that only the configured node would know, the equality "every `SignerEvent` surfaced to the runloop == an event the configured node emitted" is broken: it should read "every `SignerEvent` surfaced to the runloop == a well-formed JSON body POSTed by *any* TCP client that reached this port."

### Impact Explanation
An attacker who can reach the signer's event-receiver port can inject arbitrary `NewBlock`, `BlockValidationResponse`, or stacker-DB-derived miner/signer messages into the signer's runloop, causing the signer to act on forged chain/tenure/validation state (e.g., treating an attacker-fabricated block or block-validation verdict as authentic input to its signing decisions). This is unauthenticated write of forged state into the signer process — matching the "unauthenticated/unauthorized write to state" / "network-wide propagation of forged data" severity category, since a signer that acts on forged `NewBlock`/`BlockValidationResponse` data can produce signatures/votes that propagate to the wire and to other signers/miners. The attack is trivially repeatable per TCP connection with no rate limiting evident in this code path.

### Likelihood Explanation
The only precondition is TCP reachability to the bound event-receiver address/port and the target signer must have subscribed the corresponding endpoints. `SignerEventReceiver::bind` (line 404) uses `HttpServer::http(listener)` with whatever socket address is configured — I could not fully verify from the indexed portion of `stacks-signer/src/config.rs`/`lib.rs` whether the default deployment binds this to `127.0.0.1` (which would require local access, taking it out of the stated unprivileged-remote threat model) or to a routable address. If the operator configures/exposes this endpoint on a non-loopback interface (which the code does not prevent), the attack requires no credentials, no privileged role, and no prior state — just an HTTP POST, making likelihood high in that configuration. If it is loopback-only by default, exploitation requires local access and falls outside this audit's scope, but the code itself performs no authentication regardless of bind address, i.e., the vulnerability is in the code, and exposure depends purely on deployment/network configuration rather than any protection in `libsigner/src/events.rs`.

### Recommendation
Add authentication for events at the transport/application layer: require a pre-shared secret/HMAC header (verified in `next_event`/`process_event` before deserialization) that only the configured node knows, and/or bind the event-receiver listener to loopback only and document/enforce that it must never be exposed on a routable interface. Additionally, verify chunk signatures for the miner-contract branch in `TryFrom<StackerDBChunksEvent>` (currently only the signer-contract branch calls `chunk.recover_pk()`), and cross-check `NewBlock`/`BlockValidationResponse` payload fields against locally-known chain state before acting on them.

use std::net::{TcpStream, SocketAddr};

#[test]
fn forged_new_block_is_accepted_without_auth() {
    let mut receiver: SignerEventReceiver<SomeSignerMessageType> = SignerEventReceiver::new(false);
    let addr: SocketAddr = "127.0.0.1:0".parse().unwrap();
    let bound = receiver.bind(addr).unwrap();

    // Attacker: independent TCP client, no credentials, no shared secret
    let body = r#"{
        "index_block_hash": "0xAA..AA",
        "consensus_hash": "0xBB..BB",
        "block_hash": "0xCC..CC",
        "block_height": 999999,
        "transactions": []
    }"#;
    let req = format!(
        "POST /new_block HTTP/1.1\r\nHost: {bound}\r\nContent-Length: {}\r\nContent-Type: application/json\r\nConnection: close\r\n\r\n{}",
        body.len(), body
    );
    let mut stream = TcpStream::connect(bound).unwrap();
    stream.write_all(req.as_bytes()).unwrap();

    // Assert the receiver accepts and forwards the forged event with no auth check
    let event = receiver.next_event().unwrap();
    assert!(matches!(event, SignerEvent::NewBlock { block_height: 999999, .. }));
}

    fn next_event(&mut self) -> Result<SignerEvent<T>, EventError> {
        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)
            } else if request.url() == "/new_block" {
                process_event::<T, StacksBlockEvent>(request)
            } else {
                let url = request.url().to_string();
                debug!(
                    "[{:?}] next_event got request with unexpected url {}, return OK so other side doesn't keep sending this",
                    event_receiver.local_addr,
                    url
                );
                ack_dispatcher(request);
                Err(EventError::UnrecognizedEvent(url))
            }
        })?
    }

fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}
