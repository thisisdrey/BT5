### Title
Unauthenticated `POST /shutdown` permanently halts the signer's event receiver - (File: libsigner/src/events.rs)

### Summary
`SignerEventReceiver::next_event` routes HTTP requests solely by matching `request.url()` against fixed path strings, with no authentication, origin check, or secret verification on any branch. The `"/shutdown"` branch sets `stop_signal` to `true` and returns `EventError::Terminated` on any POST to that path, which `main_loop` treats as a clean exit, so a single unauthenticated POST from any TCP peer able to reach the bound event port permanently disables the signer's event stream.

### Finding Description
In `SignerEventReceiver::next_event` (`libsigner/src/events.rs:413-459`), the dispatcher only checks `request.method()` and `request.url()`:
```
} else if request.url() == "/shutdown" {
    event_receiver.stop_signal.store(true, Ordering::SeqCst);
    Err(EventError::Terminated)
}
``` [1](#0-0) 
There is no check of a shared secret, HMAC, source IP allow-list, or any other credential — the same trivial string comparison used for legitimate paths like `/stackerdb_chunks` is used for the destructive shutdown action. `is_stopped()` simply loads that same `AtomicBool` (`libsigner/src/events.rs:462-464`), and `main_loop` treats `Err(EventError::Terminated)` as a normal termination and calls `break` (`libsigner/src/events.rs:296-300`), exiting the loop for good — there is no re-arm path.

The intended trigger for this branch is `SignerStopSignaler::send`, which is invoked only by the local process holding the `Arc<AtomicBool>` and constructs the exact same POST request over a loopback-style connection (`libsigner/src/events.rs:376-396`). Because the HTTP handler cannot distinguish this legitimate local caller from any other TCP client, the equality "`stop_signal` set == shutdown authorized by the local node operator" does not hold: any bytes matching `POST /shutdown` trigger the same effect regardless of sender identity.

Sample deployment configs bind this receiver to all interfaces (e.g. `endpoint = "0.0.0.0:30000"` in `sample/conf/signer/mainnet-signer-conf.toml:39` and referenced from `docs/signing.md:45`), so the exposure is not merely theoretical for deployments following the provided sample config; the port is reachable by any TCP peer that can route to the signer host.

### Impact Explanation
Any remote party able to open a TCP connection to the signer's event-receiver port can send a single crafted HTTP POST to `/shutdown` and cause `main_loop` to exit permanently, silently disabling the signer's participation in block validation/signing (it stops receiving `stackerdb_chunks`, `proposal_response`, `new_burn_block`, and `new_block` events from the node). This is a repeatable, single-message, unauthenticated denial of service against a signer, matching the "Critical - remote crash/unauthenticated DoS from few messages" category.

### Likelihood Explanation
No secret, signature, or session state is required — only network reachability to the bound event port and the ability to send one raw HTTP POST. If the operator binds the listener to a non-loopback address (as shown in the repo's own sample configuration), this is trivially exploitable by any unprivileged network peer, with no dependency on holding a slot, key, or admin role.

### Recommendation
Require an authentication check before honoring `/shutdown` (and ideally all other event paths) — e.g., verify a shared secret/HMAC or restrict acceptance to loopback connections only, or bind the stop-signaler's request over a dedicated internal channel/socket instead of a public HTTP path that mirrors external event traffic.

}
