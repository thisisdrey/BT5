### Title
Cross-repository transaction hijacking via unauthenticated `transaction_id` in `RefTransaction.StopTransaction` - (File: internal/praefect/service/transaction/server.go)

### Summary
The bug class described in the report is a coarse-grained authorization check: `cancelSignature` verifies only that the caller is *authorized for the account* rather than that the caller *owns the specific nonce*, letting any co-authorized actor cancel another user's resource. The same class of flaw exists in Praefect's `RefTransaction` service: `StopTransaction` verifies nothing about the caller's ownership of the specific `transaction_id` it is asked to stop — it accepts any sequentially-guessable ID and stops that transaction regardless of which repository or push it belongs to.

### Finding Description
`StopTransaction` in `internal/praefect/service/transaction/server.go` forwards directly to `Manager.StopTransaction(ctx, in.GetTransactionId())` [1](#0-0)  — the `repository` field of `StopTransactionRequest` is never consulted to verify that the caller's transaction actually belongs to the repository/push it claims to be acting on. `Manager.StopTransaction` looks up the transaction purely by numeric ID in a shared map and stops it unconditionally if found, with no ownership or per-repository check tying the ID back to the caller: [2](#0-1) .

Transaction IDs are not per-caller secrets; they are simple sequentially incrementing counters shared across the entire Praefect process for all repositories and all users: `transactionID := atomic.AddUint64(&mgr.idSequence, 1)` [3](#0-2) .

Every ordinary push causes Gitaly to hand the Git hook process a `HooksPayload` that embeds this transaction ID plus the internal-socket auth token needed to reach the `RefTransaction` gRPC service: `TransactionID storage.TransactionID`, `InternalSocketToken string` [4](#0-3) . A user who can trigger any push (and therefore obtain a valid internal token bound to their own transaction) can enumerate the small, predictable ID space (next/previous integers) and call `StopTransaction` with a different repository's/user's transaction ID. Since the RPC never validates that the ID belongs to the caller's repository, it will happily stop someone else's concurrent transaction — exactly the pattern in the report where a check scoped to "authorized" (here: "holds a valid internal token") replaces a check scoped to "owns this specific resource" (here: "this transaction ID for this repository").

### Impact Explanation
Calling `StopTransaction` on a foreign transaction ID forces that unrelated, concurrent push to receive `VoteTransactionResponse_STOP`, causing it to fail. This is a cross-tenant denial-of-service: an attacker with the ability to trigger their own push against any repository on a shared Gitaly Cluster/Praefect installation can disrupt other users' concurrent pushes to unrelated repositories by guessing nearby sequential transaction IDs, with no rate limit or ownership check blocking the abuse.

### Likelihood Explanation
Likelihood is limited by timing (an attacker needs another transaction to be in-flight at a guessable ID near their own) but is otherwise trivial to exploit: transaction IDs are small monotonically increasing integers, so an attacker can simply try `myID-1`, `myID+1`, etc., or repeatedly issue pushes to sample many IDs to find one currently in `PREPARING`/`PREPARED` state and stop it. On a busy shared cluster with concurrent pushes, valid targets will regularly be adjacent to the attacker's own ID.

### Recommendation
Bind the ownership check to the resource, not merely to "is an authenticated internal caller": require that `StopTransaction` (and `VoteTransaction`) verify that the given `transaction_id` was registered for the `repository` presented in the request (and ideally that the caller is one of the transaction's registered voters/nodes), rejecting the call otherwise. Alternatively, make transaction IDs unguessable (e.g., random UUIDs) so a token issued for one push cannot be leveraged to name another push's transaction, closing the coarse-authorization gap described in the analog report.

### Proof of Concept
1. `Manager.RegisterTransaction` allocates sequential IDs via `atomic.AddUint64(&mgr.idSequence, 1)` [3](#0-2) , so pushing to repo A yields transaction ID `N`, and a concurrent push to repo B (by any other user) yields `N+1` or `N-1`.
2. The attacker's own push causes Gitaly to invoke a hook with a `HooksPayload` containing a valid `InternalSocketToken` for the `RefTransaction` gRPC service [4](#0-3) .
3. Using that token, the attacker's hook process calls `RefTransactionClient.StopTransaction` with `TransactionId: N+1` and an arbitrary/incorrect `Repository` (which is ignored) [1](#0-0) .
4. `Manager.StopTransaction` finds transaction `N+1` in the shared map and stops it unconditionally [5](#0-4) , causing the victim's unrelated, concurrent push transaction to fail with `VoteTransactionResponse_STOP`, exactly as demonstrated for the legitimate use case in `TestStopTransaction`'s "stopping a single voter" subtest [6](#0-5) .

func (s *Server) StopTransaction(ctx context.Context, in *gitalypb.StopTransactionRequest) (*gitalypb.StopTransactionResponse, error) {
	if err := s.txMgr.StopTransaction(ctx, in.GetTransactionId()); err != nil {
		switch {
		case errors.Is(err, transactions.ErrNotFound):
			return nil, structerr.NewNotFound("%w", err)
		case errors.Is(err, transactions.ErrTransactionCanceled):
			return nil, structerr.NewCanceled("%w", err)
		case errors.Is(err, transactions.ErrTransactionStopped):
			return &gitalypb.StopTransactionResponse{}, nil
		default:
			return nil, structerr.NewInternal("%w", err)
		}
	}

func (mgr *Manager) RegisterTransaction(ctx context.Context, voters []Voter, threshold uint) (Transaction, CancelFunc, error) {
	mgr.lock.Lock()
	defer mgr.lock.Unlock()

	transactionID := atomic.AddUint64(&mgr.idSequence, 1)

	transaction, err := newTransaction(transactionID, voters, threshold)
	if err != nil {
		return nil, nil, err
	}

	if _, ok := mgr.transactions[transactionID]; ok {
		return nil, nil, errors.New("transaction exists already")
	}
	mgr.transactions[transactionID] = transaction

// StopTransaction will gracefully stop a transaction.
func (mgr *Manager) StopTransaction(ctx context.Context, transactionID uint64) error {
	mgr.lock.Lock()
	transaction, ok := mgr.transactions[transactionID]
	if ok {
		// Release while holding mgr.lock so a concurrent voteTransaction
		// can't acquire a fresh repo lock between this release and stop.
		mgr.releaseRepoLock(transactionID)
	}
	mgr.lock.Unlock()

	if !ok {
		return fmt.Errorf("%w: %d", ErrNotFound, transactionID)
	}
	if err := transaction.stop(); err != nil {
		return err
	}

	mgr.logger.WithFields(log.Fields{
		"transaction.id": transactionID,
	}).DebugContext(ctx, "VoteTransaction: transaction stopped")
	mgr.counterMetric.WithLabelValues("stopped").Inc()

	return nil
}
