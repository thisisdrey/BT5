### Title
Protocol fee bypassed on NEP-245/NEP-171/IMT trades via unit-splitting `TokenDiff` intents in one `MultiPayload` - (File: `contracts/defuse/core/src/intents/token_diff.rs`)

### Summary
`TokenDiff::token_fee` exempts NFT/MT/IMT legs from the protocol fee only when the **per-intent** delta magnitude is `<= 1`. Because `DefuseIntents::intents` is a `Vec<Intent>` allowing arbitrarily many `TokenDiff` entries inside a single signed payload, and each `TokenDiff::execute_intent` computes and collects its fee independently over its own `self.diff` map, an attacker can split what is economically a single large NEP-245/NEP-171/IMT trade into N separate `TokenDiff` intents each moving exactly `amount == 1` of the same token, driving the aggregate collected fee to zero while `TransferMatcher::finalize` still nets and executes the full real transfer.

### Finding Description
Binding claimed: fee credited to `fee_collector` for token `X` moved by `signer` within one execution == `protocol_fee` applied to the **aggregate** `|Σ negative deltas|` on `X` by that `signer` in the call. Actual code enforces fee per individual `TokenDiff` intent entry, not per-`(signer, token)` aggregate: [1](#0-0) 

and the exemption itself: [2](#0-1) 

`token_fee` returns `Pips::ZERO` whenever `amount <= 1` for `Nep171`/`Nep245`/`Imt` token types, with no memory of how many other `TokenDiff` intents in the same `DefuseIntents`/`MultiPayload` (or same `execute_signed_intents` batch) already moved units of the very same `TokenId`.

`DefuseIntents` allows an arbitrary `Vec<Intent>` under a single signature/nonce: [3](#0-2) 

and each intent is executed and its fee computed independently: [4](#0-3) 

All balance deltas from every `TokenDiff` across the whole payload/batch are accumulated in a single `TransferMatcher` and only netted into real transfers once, at `finalize()`, after every intent's (zero) fee has already been collected: [5](#0-4) [6](#0-5) 

Exploit: Alice (signer A) wants to sell `N` units of `Nep245TokenId("mt.near", "nft1")` to Bob (signer B) for `N * price` of a NEP-141 token. Instead of one `TokenDiff{ diff: {mt: -N, ft: +N*price} }` (which would trigger `token_fee` with `amount = N > 1` and charge `protocol_fee`), Alice signs one `MultiPayload` containing `N` separate `TokenDiff` intents, each `{ mt: -1, ft: +price }`. Bob signs a matching `MultiPayload` with `N` `TokenDiff` intents `{ mt: +1, ft: -price }`. Every individual intent hits `amount == 1`, so `Self::token_fee(mt_token_id, 1, protocol_fee) == Pips::ZERO` for every single one of the N legs — `fees_collected` for the `mt` token is `0` in total, while `TransferMatcher::finalize` still nets and executes the full `N`-unit transfer of `mt` from Alice to Bob. No existing guard (`MultiPayload::verify`, nonce checks, `TransferMatcher::finalize`'s zero-sum invariant, `Pips::fee_ceil`) references the number of intents or the cumulative moved amount per token within a call — they only ensure signature/nonce validity and that deltas net to zero, not that fee scales with aggregate volume.

### Impact Explanation
This is a systematic protocol-fee bypass on any NEP-245 (or NEP-171/IMT) leg of a trade: the protocol collects `0` fee instead of `protocol_fee * aggregate_amount`, regardless of how large the real underlying transfer is. This directly matches the Critical category "protocol fees bypassed." It is fully repeatable by any unprivileged user for any account pair and any NFT/MT/IMT token, with the bypassed amount scaling to whatever `N` legs the attacker signs (bounded only by gas/payload size, not by protocol design). The `fee_collector` account under-receives revenue on every such trade; no other user funds are frozen or stolen, but protocol revenue is systematically under-collected.

### Likelihood Explanation
No special privileges are required: any two accounts (or even the same signer coordinating both sides via two of their own accounts) with Verifier balances can construct and sign `MultiPayload`s with N `TokenDiff` intents, then call `execute_intents`. The only "cost" is the larger payload/transaction size and gas, which is easily paid for any economically-meaningful trade — the incentive to bypass fees on high-value NFT/MT trades far outweighs the marginal gas overhead of splitting into unit-sized intents. This requires no relayer key, no DAO role, and no signature forgery — it uses the standard, documented intent format.

### Recommendation
Change `TokenDiff::token_fee`'s exemption logic (and its callers `supply_delta`/`closure_supply_delta`) to be based on the aggregate amount moved per `(signer, token_id)` across the entire `DefuseIntents`/execution batch (e.g., accumulate per-token totals before applying the `amount <= 1` exemption, or move fee computation to `TransferMatcher::finalize` using the final matched transfer amounts rather than per-intent deltas), so that splitting a trade into many unit legs cannot reduce the aggregate fee owed.

### Proof of Concept
`cargo test` in `contracts/defuse/core` (or an integration test using `near-workspaces`):
1. Set `protocol_fee = Pips::ONE_PERCENT`.
2. Sign one `MultiPayload` for Alice containing `N = 100` `TokenDiff` intents, each `{ diff: { nep245_token_id: -1, ft_token_id: +price } }`.
3. Sign one `MultiPayload` for Bob containing `N = 100` `TokenDiff` intents, each `{ diff: { nep245_token_id: +1, ft_token_id: -price } }`.
4. Call `execute_signed_intents([alice_payload, bob_payload])` (or `execute_intents`).
5. Assert LHS: total `fees_collected` credited to `fee_collector` for `nep245_token_id` equals `0` (actual behavior).
6. Assert RHS: `Pips::ONE_PERCENT.fee_ceil(100)` (expected fee if computed on the aggregate `100`-unit move) is nonzero.
7. Assert the two values diverge, proving the binding `fee_collected == protocol_fee(aggregate_amount)` is violated, while confirming via `Transfers`/balance checks that the full `100`-unit `nep245_token_id` transfer from Alice to Bob was still executed.

    // Finalizes all transfers, or returns unmatched deltas.
    // If unmatched deltas overflow, then Err(None) is returned.
    pub fn finalize(self) -> Result<Transfers, InvariantViolated> {
        let mut transfers = Transfers::default();
        let mut deltas = TokenDeltas::default();
        for (token_id, transfer_matcher) in self.0 {
            if let Err(unmatched) = transfer_matcher.finalize_into(&token_id, &mut transfers)
                && (unmatched == 0 || deltas.apply_delta(token_id, unmatched).is_none())
            {
                return Err(InvariantViolated::Overflow);
            }
        }
        if !deltas.is_empty() {
            return Err(InvariantViolated::UnmatchedDeltas {
                unmatched_deltas: deltas,
            });
        }
        Ok(transfers)
    }
}
