### Title
Global (non-per-IP) `ClientConnectionTracker` slot exhaustion via never-completing QUIC handshakes enables single-IP ingress DoS on TPU - ([File: streamer/src/nonblocking/quic.rs])

### Summary
`ClientConnectionTracker::new` enforces `qos.max_concurrent_connections()` as a single global counter (`stats.open_connections`), checked and incremented before any handshake completes and before any per-source rate limiting is actually applied. Because the per-IP/global `ConnectionRateLimiter`/`overall_connection_rate_limiter` only *consume* tokens on a **successfully completed** handshake, an attacker who never sends the QUIC Handshake packet after Initial can hold a tracker slot for up to `QUIC_CONNECTION_HANDSHAKE_TIMEOUT` (2s) at negligible cost, and by rotating ephemeral source ports on one IP, can perpetually keep all `max_concurrent_connections()` slots occupied, causing `incoming.refuse()` for every other client, staked or not.

### Finding Description
In `run_server` (`streamer/src/nonblocking/quic.rs:331-379`), the accept path performs, in order:
1. `overall_connection_rate_limiter.current_tokens() == 0` — a **read-only** check (no token consumption) [1](#0-0) 
2. `rate_limiter.is_allowed(&incoming.remote_address().ip())` — also **read-only**, and per `ConnectionRateLimiter::is_allowed`'s own doc comment, "we assume that only IPs with actual confirmed connections are stored in it" [2](#0-1) 
3. `ClientConnectionTracker::new(stats.clone(), qos.max_concurrent_connections())` — increments a single global `AtomicU64` (`stats.open_connections`) and fails only once that global count reaches `max_concurrent_connections()` [3](#0-2) 

Only after `incoming.accept()` succeeds does `setup_connection` await the handshake with a 2-second timeout (`QUIC_CONNECTION_HANDSHAKE_TIMEOUT`) [4](#0-3) . Actual rate-limiter token consumption (`rate_limiter.register_connection(&from.ip())` and `overall_connection_rate_limiter.consume_tokens(1)`) happens **only after the handshake succeeds** [5](#0-4) .

This means: nothing in the accept path meters or caps *pending, incomplete* handshakes per source IP. An attacker sends an Initial packet from a fresh ephemeral source port, which passes both rate-limiter checks (no tokens ever consumed for this IP since no handshake has completed) and successfully acquires a `ClientConnectionTracker` slot, consuming 1 of the finite `max_concurrent_connections()` global budget for close to 2 seconds even with zero further packets sent. By continuously issuing new Initial packets from a rotating pool of source ports (trivially available - tens of thousands of ephemeral ports on one NIC/IP), the attacker can keep the entire global slot budget permanently saturated, so that `ClientConnectionTracker::new` returns `Err(())` for every other incoming connection attempt (staked or unstaked), which get `incoming.refuse()`'d in `run_server` [6](#0-5) . This directly violates the invariant that connection-related limits are enforced per source and cannot be evaded by connection churn — here the only real limit is global, and the per-source limiters are deliberately deferred until identity/ownership of the IP is "confirmed" via a completed handshake, which the attack never allows to happen.

### Impact Explanation
This is a low-cost, unprivileged network-level denial of service against the TPU QUIC ingress: a single attacking IP can starve the entire cluster of stake-weighted and unstaked clients from ever acquiring a `ClientConnectionTracker` slot, meaning no new QUIC connections (and thus no new transactions from any client, including staked validators/forwarders) can be accepted for the duration of the attack. This matches the Agave bounty category of ingress/DoS resource-exhaustion against the validator's transaction-processing path — it can render a leader effectively unable to accept new transaction connections while the flood continues, without requiring any stake, valid packets, or completed handshakes.

### Likelihood Explanation
Highly feasible: requires only an unprivileged remote client capable of sending raw UDP/QUIC Initial packets to the public TPU QUIC port, and enough OS ephemeral source ports (default range gives tens of thousands, easily reusable in a rolling window) to sustain `max_concurrent_connections()` in-flight attempts. Since `max_concurrent_connections()` is `(max_staked_connections + max_unstaked_connections) * 5 / 4` (see `SwQos::max_concurrent_connections`, `streamer/src/nonblocking/swqos.rs:518-522`), the attacker only needs to sustain roughly `max_concurrent_connections() / QUIC_CONNECTION_HANDSHAKE_TIMEOUT` new Initial-only attempts per second — a modest and easily sustained packet rate for a single host. No IP spoofing, valid TLS material, or stake is required.

### Recommendation
Enforce a per-source-IP cap on *pending* (pre-handshake) tracker slots, not just a global cap, before allowing `ClientConnectionTracker::new` to succeed — e.g., track outstanding (accepted-but-not-handshake-completed) connection attempts per IP alongside `stats.outstanding_incoming_connection_attempts`, and refuse/ignore further Initial packets from an IP that already holds N pending slots. Alternatively, consume a rate-limiter token optimistically at accept time (before handshake completion) and refund it on success, so that repeated non-completing handshake attempts from one IP are throttled the same way completed-handshake floods are.

### Proof of Concept
Integration test plan (extends existing `setup_quic_server` test harness in `streamer/src/nonblocking/quic.rs` tests):
1. Configure `SwQosConfig` with a small `max_staked_connections + max_unstaked_connections` (e.g., total budget of 4, so `max_concurrent_connections()` == 5).
2. Spawn N ≈ `max_concurrent_connections()` raw UDP sockets bound to distinct ephemeral ports on `127.0.0.1`, each sending a single QUIC Initial packet to the server's QUIC endpoint and then going silent (never sending Handshake), verifying via `stats.open_connections` that all slots are occupied.
3. Concurrently, attempt to establish a legitimate client connection via `make_client_endpoint` and measure how long `connection.await`/`incoming.accept()` on the server takes to succeed.
4. Every ~1.9s (just under `QUIC_CONNECTION_HANDSHAKE_TIMEOUT`), replace each attacker socket with a new one bound to a new ephemeral port, repeating the Initial-only send.
5. Assert that the legitimate client's connection attempt is refused (`stats.refused_connections_too_many_open_connections` increments) or is denied for a duration far exceeding a bounded/expected acceptance latency, demonstrating unbounded starvation as long as the attacker sustains the churn — i.e., there is no time bound after which the legitimate client is guaranteed a slot while a single attacking IP is churning.

impl ClientConnectionTracker {
    /// Check the max_concurrent_connections limit and if it is within the limit
    /// create ClientConnectionTracker and increment open connection count. Otherwise returns Err
    fn new(stats: Arc<StreamerStats>, max_concurrent_connections: usize) -> Result<Self, ()> {
        let open_connections = stats.open_connections.fetch_add(1, Ordering::Relaxed);
        if open_connections >= max_concurrent_connections {
            stats.open_connections.fetch_sub(1, Ordering::Relaxed);
            debug!(
                "There are too many concurrent connections opened already: open: \
                 {open_connections}, max: {max_concurrent_connections}"
            );
            return Err(());
        }

        Ok(Self { stats })
    }
