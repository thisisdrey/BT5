### Title
Cross-StackerDB replay of a signed chunk due to missing contract binding in `SlotMetadata::auth_digest` - ([File: stackslib/src/net/api/poststackerdbchunk.rs])

### Summary
`RPCPostStackerDBChunkRequestHandler::try_handle_request` derives `contract_identifier` purely from the URL path and passes it to `tx.try_replace_chunk`, which validates the chunk's signature via `SlotMetadata::verify`. The signed digest (`SlotMetadata::auth_digest`) is computed only from `slot_id`, `slot_version`, and `data_hash` — it never includes the `contract_identifier` — so a signature produced for one StackerDB contract's slot is equally valid for any other StackerDB contract where the same key is registered as the signer of the same `slot_id`.

### Finding Description
The write path is: `poststackerdbchunk.rs` extracts `contract_identifier` from the URL (`get_contract_address`), begins a transaction for that contract with `stackerdbs_tx_begin`, and calls `tx.try_replace_chunk(&contract_identifier, &stackerdb_chunk.get_slot_metadata(), &stackerdb_chunk.data)` [1](#0-0) .

`try_replace_chunk` looks up `slot_validation` (which includes the expected signer address) *per contract* via `get_slot_validation(smart_contract, slot_id)`, then checks `slot_desc.verify(&slot_validation.signer)` [2](#0-1) . This lookup is contract-scoped, but the thing actually being cryptographically verified — `SlotMetadata::auth_digest()` — is not: it hashes only `slot_id`, `slot_version`, and `data_hash` [3](#0-2) , with no contract identifier or StackerDB-instance-specific domain separator included in the signed bytes.

Consequently, if the same signer key is registered as slot `N`'s owner in two independently-configured StackerDB contracts (contract A and contract B), a chunk `(slot_id=N, slot_version=V, sig, data)` signed once for contract A satisfies `verify()` against contract B's registered signer for slot N as well, because the signature check only compares the recovered pubkey hash to the expected signer address for the contract passed in — it does not confirm the signature was computed with contract B's identity data in scope. The attacker's exact message is simply re-POSTing (or replaying via P2P push, since `handle_unsolicited_StackerDBPushChunk`/`process_stacker_db_chunks` use the same `get_slot_metadata()`/`verify` scheme [4](#0-3) [5](#0-4) ) the same bytes against a different `contract_identifier` path/contract, resulting in acceptance rather than a `BadSlotSigner`/`NoSuchSlot` rejection.

### Impact Explanation
If exploited, an attacker can write attacker-chosen data into a slot of a StackerDB instance whose slot-owner set they were never authorized to write to directly — matching the "unauthorized write to state or StackerDB" Critical category. The success of this write is contingent, however, on an operational precondition described below: it does not work against an arbitrary victim StackerDB, only against ones where the attacker's own key happens to also be registered as the owner of the same `slot_id` index.

### Likelihood Explanation
This requires: (1) the attacker holds a valid signed chunk from a StackerDB instance they legitimately own a slot in, and (2) the same public key hash is registered as the owner of the identical `slot_id` in a second, differently-configured StackerDB contract. Slot assignments come from each contract's `stackerdb-get-signer-slots` Clarity function [6](#0-5) , and in the signer-set architecture, multiple StackerDB contracts (e.g., different message-type replicas for the same reward cycle) are commonly configured with the same signer ordering, making identical `slot_id ↔ signer` mappings across contracts plausible in practice rather than purely theoretical. The attacker needs no privileged role — only ability to POST to the RPC endpoint or push a P2P StackerDB chunk message — and the attack is trivially repeatable (replay the same signed bytes to any contract satisfying the slot-alignment precondition).

### Recommendation
Bind the signed digest to the specific StackerDB instance by including the `contract_identifier` (and ideally a reward-cycle or config version) inside `SlotMetadata::auth_digest()` (and correspondingly in `StackerDBChunkData::sign`/`verify`/`recover_pk`), so that a chunk signed for one contract cannot validate against another contract's slot-owner set, even when the underlying signer key coincides.

### Proof of Concept
Rust test outline (extends `libstackerdb/src/tests/mod.rs` / `stackslib/src/net/stackerdb/tests/db.rs` patterns):
1. Create two `StackerDBs` contracts, `sc_a` and `sc_b`, each with the same signer key `pk` registered as the owner of `slot_id = 0`, via `tx.create_stackerdb(&sc_a, &[(addr,1)])` and `tx.create_stackerdb(&sc_b, &[(addr,1)])`.
2. Build `chunk_data = StackerDBChunkData::new(0, 1, data)`, call `chunk_data.sign(&pk)`.
3. Call `tx.try_replace_chunk(&sc_a, &chunk_data.get_slot_metadata(), &chunk_data.data)` — expect `Ok(())`.
4. Call `tx.try_replace_chunk(&sc_b, &chunk_data.get_slot_metadata(), &chunk_data.data)` using the *same* signed `chunk_data` — current code returns `Ok(())` (accepted) instead of the expected `BadSlotSigner`/rejection, demonstrating the cross-contract replay at `stackslib/src/net/stackerdb/db.rs:418` (`slot_desc.verify(&slot_validation.signer)`), because `SlotMetadata::auth_digest` at `libstackerdb/src/libstackerdb.rs:160-166` never includes `sc_a`/`sc_b` in the signed bytes.

    fn auth_digest(&self) -> Sha512Trunc256Sum {
        let mut hasher = Sha512_256::new();
        hasher.update(self.slot_id.to_be_bytes());
        hasher.update(self.slot_version.to_be_bytes());
        hasher.update(self.data_hash.0);
        Sha512Trunc256Sum::from_hasher(hasher)
    }

    fn eval_signer_slots(
        chainstate: &mut StacksChainState,
        burn_dbconn: &dyn BurnStateDB,
        contract_id: &QualifiedContractIdentifier,
        tip: &StacksBlockId,
    ) -> Result<Vec<(StacksAddress, u32)>, NetError> {
        let value = chainstate.eval_read_only(
            burn_dbconn,
            tip,
            contract_id,
            &format!("({STACKERDB_SLOTS_FUNCTION})"),
        )?;

        let result = value.expect_result()?;
        let slot_list = match result {
            Err(err_val) => {
                let err_code = err_val.expect_u128()?;
                let reason = format!(
                    "Contract {} failed to run `stackerdb-get-signer-slots`: error u{}",
                    contract_id, &err_code
                );
                warn!("{}", &reason);
                return Err(NetError::InvalidStackerDBContract(
                    contract_id.clone(),
                    reason,
                ));
            }
            Ok(ok_val) => ok_val.expect_list()?,
        };

        let mut total_num_slots = 0u32;
        let mut ret = vec![];
        for slot_value in slot_list.into_iter() {
            let (addr, num_slots) =
                Self::parse_slot_entry(slot_value, contract_id).map_err(|e| {
                    warn!("Failed to parse StackerDB slot entry: {}", &e);
                    NetError::InvalidStackerDBContract(contract_id.clone(), e)
                })?;

            if num_slots > STACKERDB_INV_MAX {
                let reason = format!(
                    "Contract {} stipulated more than maximum number of slots for one signer ({})",
                    contract_id, STACKERDB_INV_MAX
                );
                warn!("{}", &reason);
                return Err(NetError::InvalidStackerDBContract(
                    contract_id.clone(),
                    reason,
                ));
            }

            total_num_slots =
                total_num_slots
                    .checked_add(num_slots)
                    .ok_or(NetError::OverflowError(format!(
                        "Contract {} stipulates more than u32::MAX slots",
                        &contract_id
                    )))?;

            if total_num_slots > STACKERDB_INV_MAX {
                let reason = format!(
                    "Contract {contract_id} stipulated more than the maximum number of slots"
                );
                warn!("{reason}");
                return Err(NetError::InvalidStackerDBContract(
                    contract_id.clone(),
                    reason,
                ));
            }

            ret.push((addr, num_slots));
        }
        Ok(ret)
    }
