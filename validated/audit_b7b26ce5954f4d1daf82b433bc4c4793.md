## Finding: SSRF-style analog — peer-supplied `data_url` drives outbound HTTP connections without the private-IP filter that other code paths apply

### Summary
The Postiz/Next.js report is a classic SSRF: attacker-supplied URL data causes the server to make outbound requests to attacker-chosen (potentially internal) hosts. The closest structural analog in this repo's networking code is that a remote, unauthenticated-at-handshake-time peer supplies its own `data_url` (an arbitrary host:port) during the P2P handshake, and this value is later used verbatim by the node to open outbound HTTP connections — for block/microblock downloads and generic StackerDB/RPC requests — via `PeerNetwork::connect_or_send_http_request` / `HttpPeer::connect_http`. Critically, the mempool-sync code path explicitly filters out private-range addresses before connecting: [1](#0-0) 

But the block/microblock downloader (`stackslib/src/net/download/epoch2x.rs`) and the generic neighbor-RPC sender (`stackslib/src/net/neighbors/rpc.rs`) contain **no equivalent `is_in_private_range`/`private_neighbors` check** before calling `connect_or_send_http_request`/`connect_http` with the peer-supplied `data_url`'s resolved address: [2](#0-1) [3](#0-2) [4](#0-3) 

### Finding Description
The `data_url` a peer advertises comes straight from its P2P `HandshakeData`, echoed from `HandshakeData::from_local_peer`, and is stored as `convo.data_url` on the receiving node: [5](#0-4) 

Downstream consumers resolve this URL (via `PeerHost::try_from_url` / DNS resolution in `chat.rs`'s block-URL DNS logic) and then open a TCP+HTTP connection to the resolved socket address: [6](#0-5) [7](#0-6) 

The mempool-sync state machine explicitly recognized this risk and added a guard: it refuses to connect to a resolved address in the private IP range unless `private_neighbors` is enabled in the node's connection options: [1](#0-0) 

However, the block/microblock downloader's `begin_request` (used to fetch anchored blocks/microblocks by data URL from `BlockRequestKey`) and `NeighborRPC::send_request` (used generically to make HTTP requests to connected/authenticated peers, e.g. for StackerDB or other RPC calls) invoke `connect_or_send_http_request`/`connect_http` directly on the resolved `SocketAddr` with no such filter: [2](#0-1) [8](#0-7) 

`connect_http` itself performs no address-class validation either — it simply calls `NetworkState::connect(&addr, ...)`: [9](#0-8) 

This breaks the equality the codebase itself establishes elsewhere: "outbound connections initiated on behalf of a remote peer's advertised URL must be filtered against private/internal address ranges unless explicitly allowed." Mempool sync enforces this; block download and generic neighbor RPC do not, so a malicious peer can steer the node into connecting to `127.0.0.1`, link-local/internal addresses, or other internal services by simply advertising them as its own `data_url` during handshake.

### Impact Explanation
A remote, unprivileged peer (no special key or role required — any peer that completes a handshake) can set an attacker-controlled `data_url`. When the victim node later attempts to download a block/microblock from that peer, or issue a generic neighbor-RPC HTTP request, it will connect to whatever host:port the attacker specified, without the private-range check applied elsewhere in the same codebase. This can be used to probe/interact with internal services reachable from the node's network position (bounded compute/read-endpoint style impact — "steering a node off the tip via false inventory" is a related but distinct effect; here, the more precise impact is unauthenticated outbound requests to arbitrary internal addresses, i.e., a network-reachability/SSRF-class issue reachable purely by any P2P peer completing a handshake and advertising a malicious `data_url`).

### Likelihood Explanation
Handshakes are exchanged with any connecting peer as part of normal P2P operation; setting an arbitrary `data_url` value requires no authentication beyond completing a handshake, and both the block downloader and generic neighbor-RPC path are exercised routinely during normal chain sync and StackerDB operations. The existence of the private-range guard in `mempool_sync_send_query` demonstrates the maintainers considered and mitigated this exact vector for one call path, but the fix was not applied uniformly across all call sites that consume peer-supplied `data_url`s.

### Recommendation
Apply the same `private_neighbors`/`is_in_private_range` check used in `stackslib/src/net/mempool/mod.rs` (lines 488-498) uniformly at the point where any peer-supplied `data_url` is resolved to a `SocketAddr` and about to be connected to — specifically in `stackslib/src/net/download/epoch2x.rs::begin_request` and `stackslib/src/net/neighbors/rpc.rs::send_request` (and ideally centrally inside `HttpPeer::connect_http` / `PeerNetwork::connect_or_send_http_request` so all callers get the protection automatically), unless the node has explicitly opted into `private_neighbors`.

### Proof of Concept
1. Start a victim Stacks node with default connection options (`private_neighbors = false`).
2. Have a malicious peer complete a P2P handshake advertising `data_url = http://127.0.0.1:<internal-port>/` (or another internal/link-local address) in its `HandshakeData`.
3. Trigger the victim to request a block/microblock it believes this peer has (e.g., by advertising a matching block inventory), causing `PeerNetwork::begin_request` in `stackslib/src/net/download/epoch2x.rs` to resolve and connect to the attacker-chosen address via `connect_or_send_http_request`.
4. Observe the victim node opening an outbound HTTP connection to the internal address, unlike the mempool-sync path, which would have rejected the same private-range address per `stackslib/src/net/mempool/mod.rs:488-498`.

    pub fn connect_or_send_http_request(
        &mut self,
        data_url: UrlString,
        addr: SocketAddr,
        request: StacksHttpRequest,
    ) -> Result<usize, NetError> {
        PeerNetwork::with_network_state(self, |ref mut network, ref mut network_state| {
            PeerNetwork::with_http(network, |ref mut network, ref mut http| {
                match http.connect_http(
                    network_state,
                    network,
                    data_url.clone(),
                    addr,
                    Some(request.clone()),
                ) {
                    Ok(event_id) => Ok(event_id),
                    Err(NetError::AlreadyConnected(event_id, _)) => {
                        if let (Some(ref mut convo), Some(ref mut socket)) =
                            http.get_conversation_and_socket(event_id)
                        {
                            convo.send_request(request)?;
                            HttpPeer::saturate_http_socket(socket, convo)?;
                            Ok(event_id)
                        } else {
                            debug!("HTTP failed to connect to {data_url}, {addr:?}");
                            Err(NetError::PeerNotConnected(format!(
                                "HTTP failed to connect to {data_url}, {addr:?}",
                            )))
                        }
                    }
                    Err(e) => Err(e),
                }
            })
        })
    }

    pub fn from_local_peer(local_peer: &LocalPeer) -> HandshakeData {
        let (addrbytes, port) = match local_peer.public_ip_address {
            Some((ref public_addrbytes, ref port)) => (public_addrbytes.clone(), *port),
            None => (local_peer.addrbytes.clone(), local_peer.port),
        };

        // transmit the empty string if our data URL compels us to bind to the anynet address
        let data_url = if local_peer.data_url.has_routable_host() {
            local_peer.data_url.clone()
        } else if let Some(data_port) = local_peer.data_url.get_port() {
            // deduce from public IP
            UrlString::try_from(format!("http://{}", addrbytes.to_socketaddr(data_port))).unwrap()
        } else {
            // unroutable, so don't bother
            UrlString::try_from("").unwrap()
        };

        HandshakeData {
            addrbytes,
            port,
            services: local_peer.services,
            node_public_key: StacksPublicKeyBuffer::from_public_key(
                &Secp256k1PublicKey::from_private(&local_peer.private_key),
            ),
            expire_block_height: local_peer.private_key_expire,
            data_url,
        }
    }
