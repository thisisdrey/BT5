### Title
Single Shareholder Opt-Out Permanently Wedges `vesting::distribute` for All Shareholders — (`aptos-move/framework/aptos-framework/sources/vesting.move`)

---

### Summary

`vesting::distribute` iterates over every shareholder in a vesting contract and calls `aptos_account::deposit_coins` for each one inside a `for_each_ref` closure with no error isolation. Move has no try-catch; any abort inside the closure aborts the entire transaction. A single shareholder whose address is not registered for `AptosCoin` and who has called `set_allow_direct_coin_transfers(false)` causes `deposit_coins` to abort with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS`, permanently wedging `distribute` — and by extension `terminate_vesting_contract` — for every other shareholder in the same contract.

---

### Finding Description

**Root cause — `distribute` in `vesting.move`:**

```move
shareholders.for_each_ref(|shareholder| {
    let shareholder = *shareholder;
    let shares = pool_u64::shares(grant_pool, shareholder);
    let amount = pool_u64::shares_to_amount_with_total_coins(...);
    let share_of_coins = coin::extract(&mut coins, amount);
    let recipient_address = get_beneficiary(vesting_contract, shareholder);
    aptos_account::deposit_coins(recipient_address, share_of_coins);  // ← can abort
});
``` [1](#0-0) 

**Abort path in `deposit_coins`:**

```move

``` [2](#0-1) 

`can_receive_direct_coin_transfers` returns `false` when the account has explicitly called `set_allow_direct_coin_transfers(false)`:

```move
public fun can_receive_direct_coin_transfers(account: address): bool acquires DirectTransferConfig {
    !exists<DirectTransferConfig>(account)
        || borrow_global<DirectTransferConfig>(account).allow_arbitrary_coin_transfers
}
``` [3](#0-2) 

**Unprivileged trigger sequence:**

1. A vesting contract is created with shareholder address `S` (e.g., a resource account or any account created without registering for `AptosCoin`).
2. The controller of `S` calls `aptos_account::set_allow_direct_coin_transfers(false)` — a standard, unprivileged `public entry fun`.
3. `S` is not registered for `AptosCoin` (possible for resource accounts or accounts created via lower-level `account::create_account`).
4. Any call to `vesting::distribute(contract_address)` now aborts at the `deposit_coins` call for `S`, rolling back the entire transaction.

**Cascading breakage — `terminate_vesting_contract` also fails:**

```move
public entry fun terminate_vesting_contract(admin: &signer, contract_address: address) ... {
    assert_active_vesting_contract(contract_address);
    distribute(contract_address);   // ← always aborts if S is bad
    ...
}
``` [4](#0-3) 

Because `terminate_vesting_contract` calls `distribute` unconditionally, the admin can never terminate the contract either. The only escape hatch is for the admin to call `update_beneficiary` to redirect `S`'s share to a valid address before calling `distribute` again — but there is no mechanism to remove a shareholder, and if the admin is unresponsive or the governance process is slow, all other shareholders' vested APT is frozen indefinitely.

---

### Impact Explanation

- Every shareholder's withdrawable APT in the affected vesting contract is frozen for as long as `distribute` aborts.
- `terminate_vesting_contract` is also blocked, preventing the admin from reclaiming funds.
- `vest_many` and `distribute_many` propagate the same abort to any batch that includes the affected contract address. [5](#0-4) [6](#0-5) 

The formal spec for `distribute` explicitly marks the loop unverifiable due to potential aborts:

```
spec distribute(contract_address: address) {
    // TODO: Can't handle abort in loop.
    pragma verify = false;
``` [7](#0-6) 

---

### Likelihood Explanation

`set_allow_direct_coin_transfers` is a standard, documented, unprivileged entry function available to any account holder. Resource accounts — which are commonly used as shareholders in programmatic vesting setups — are not automatically registered for `AptosCoin`. A single shareholder acting in bad faith (or even accidentally, by opting out of direct transfers before registering for APT) can trigger this condition. There is no on-chain guard preventing it.

---

### Recommendation

1. **Wrap each `deposit_coins` call in an isolated error boundary.** Move does not have try-catch, but the pattern can be approximated by checking all preconditions before extracting coins, or by using a "push vs. pull" distribution model where each shareholder claims their own share independently.
2. **Replace the push-distribution loop with a pull model:** record each shareholder's claimable balance in a table and let each shareholder call a separate `claim` entry function. This eliminates the single-point-of-failure entirely.
3. **Add a `remove_shareholder` or `skip_shareholder` governance function** so the admin can excise a permanently broken address without having to redirect via `update_beneficiary`.

---

### Proof of Concept

```
1. Admin creates vesting contract with shareholders [Alice, MaliciousResourceAccount].
2. MaliciousResourceAccount controller calls:
       aptos_account::set_allow_direct_coin_transfers(false)
   (MaliciousResourceAccount was never registered for AptosCoin.)
3. Time passes; stake unlocks; anyone calls:
       vesting::distribute(contract_address)
4. Loop reaches MaliciousResourceAccount:
       deposit_coins<AptosCoin>(MaliciousResourceAccount, share)
       → coin::is_account_registered<AptosCoin>(MaliciousResourceAccount) == false
       → can_receive_direct_coin_transfers(MaliciousResourceAccount) == false
       → ABORT: EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS
5. Entire transaction rolls back. Alice's APT remains locked in the stake pool.
6. Admin calls terminate_vesting_contract → also aborts at step 4.
7. Alice's vested APT is frozen until admin calls update_beneficiary for MaliciousResourceAccount.

    /// Distribute any withdrawable stake from the stake pool.
    public entry fun distribute(contract_address: address) acquires VestingContract {
        assert_active_vesting_contract(contract_address);

        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        let coins = withdraw_stake(vesting_contract, contract_address);
        let total_distribution_amount = coin::value(&coins);
        if (total_distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };

        // Distribute coins to all shareholders in the vesting contract.
        let grant_pool = &vesting_contract.grant_pool;
        let shareholders = &grant_pool.shareholders();
        shareholders.for_each_ref(|shareholder| {
            let shareholder = *shareholder;
            let shares = pool_u64::shares(grant_pool, shareholder);
            let amount = pool_u64::shares_to_amount_with_total_coins(grant_pool, shares, total_distribution_amount);
            let share_of_coins = coin::extract(&mut coins, amount);
            let recipient_address = get_beneficiary(vesting_contract, shareholder);
            aptos_account::deposit_coins(recipient_address, share_of_coins);
        });

        // Send any remaining "dust" (leftover due to rounding error) to the withdrawal address.
        if (coin::value(&coins) > 0) {
            aptos_account::deposit_coins(vesting_contract.withdrawal_address, coins);
        } else {
            coin::destroy_zero(coins);
        };

        emit(
            Distribute {
                admin: vesting_contract.admin,
                vesting_contract_address: contract_address,
                amount: total_distribution_amount,
            },
        );
    }

    public entry fun terminate_vesting_contract(admin: &signer, contract_address: address) acquires VestingContract {
        assert_active_vesting_contract(contract_address);

        // Distribute all withdrawable coins, which should have been from previous rewards withdrawal or vest.
        distribute(contract_address);

        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        verify_admin(admin, vesting_contract);
        let (active_stake, _, pending_active_stake, _) = stake::get_stake(vesting_contract.staking.pool_address);
        assert!(pending_active_stake == 0, error::invalid_state(EPENDING_STAKE_FOUND));

        // Unlock all remaining active stake.
        vesting_contract.state = VESTING_POOL_TERMINATED;
        vesting_contract.remaining_grant = 0;
        unlock_stake(vesting_contract, active_stake);

        emit(
            Terminate {
                admin: vesting_contract.admin,
                vesting_contract_address: contract_address,
            },
        );
    }

    /// Set whether `account` can receive direct transfers of coins that they have not explicitly registered to receive.
    public entry fun set_allow_direct_coin_transfers(
        account: &signer, allow: bool
    ) acquires DirectTransferConfig {
        let addr = signer::address_of(account);
        if (exists<DirectTransferConfig>(addr)) {
            let direct_transfer_config = borrow_global_mut<DirectTransferConfig>(addr);
            // Short-circuit to avoid emitting an event if direct transfer config is not changing.
            if (direct_transfer_config.allow_arbitrary_coin_transfers == allow) { return };

            direct_transfer_config.allow_arbitrary_coin_transfers = allow;

            emit(
                DirectCoinTransferConfigUpdated {
                    account: addr,
                    new_allow_direct_transfers: allow
                }
            );
        } else {
            let direct_transfer_config = DirectTransferConfig {
                allow_arbitrary_coin_transfers: allow,
                update_coin_transfer_events: new_event_handle<
                    DirectCoinTransferConfigUpdatedEvent>(account)
            };
            emit(
                DirectCoinTransferConfigUpdated {
                    account: addr,
                    new_allow_direct_transfers: allow
                }
            );
            move_to(account, direct_transfer_config);
        };
    }

    #[view]
    /// Return true if `account` can receive direct transfers of coins that they have not explicitly registered to
