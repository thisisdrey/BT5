### Title
Missing address validation in `FreezeBalanceProcessor` allows TVM `FREEZE` opcode to delegate resources to unvalidated/zero addresses - (File: actuator/src/main/java/org/tron/core/vm/nativecontract/FreezeBalanceProcessor.java)

### Summary
`FreezeBalanceProcessor.validate()`, which backs the TVM `FREEZE` opcode (`0xd5`), never calls `DecodeUtil.addressValid()` on either `ownerAddress` or `receiverAddress` before using them, unlike every other sibling processor (`FreezeBalanceV2Processor`, `DelegateResourceProcessor`, `UnDelegateResourceProcessor`) and unlike the analogous system-contract actuator (`FreezeBalanceActuator`), which all explicitly validate addresses with `DecodeUtil.addressValid`.

### Finding Description
The `FREEZE` opcode is dispatched to `OperationActions.freezeAction()` [1](#0-0) , which pops `receiverAddress` directly off the EVM stack and calls `Program.freeze()` [2](#0-1) . That method converts the raw stack word to a TRON address via `receiverAddress.toTronAddress()` and passes it straight into `FreezeBalanceParam`, which is handed to `FreezeBalanceProcessor.validate()` and `.execute()`.

`FreezeBalanceProcessor.validate()` only checks that the frozen balance is positive/within bounds, resource type is valid, and (if `ownerAddress != receiverAddress`) that the receiver isn't a `Contract` account — it never calls `DecodeUtil.addressValid()` on `ownerAddress` or `receiverAddress` [3](#0-2) . If the receiver account doesn't exist, it is silently auto-created via `repo.createNormalAccount(receiverAddress)` [4](#0-3) , and `execute()` unconditionally delegates the resource weight to that address [5](#0-4) .

This is inconsistent with the equivalent V2 path (`FreezeBalanceV2Processor.validate()`), which explicitly checks `DecodeUtil.addressValid(ownerAddress)` [6](#0-5) , and with `DelegateResourceProcessor`/`UnDelegateResourceProcessor`, which validate both owner and receiver addresses [7](#0-6) [8](#0-7) . The system-contract counterpart `FreezeBalanceActuator.validate()` also validates the receiver address explicitly [9](#0-8) .

### Impact Explanation
Because `receiverAddress` in `Program.freeze()` is always derived from a `DataWord.toTronAddress()` conversion, the format/length of the produced address is always structurally consistent with a valid TRON address (correct byte length and prefix are enforced by `toTronAddress()`), so this does not enable a wholly out-of-range address. However, the missing `DecodeUtil.addressValid` check means the well-known chain-specific "reserved"/zero-payload address (address bytes that decode to the all-zero 20-byte payload) is never rejected, unlike every other resource-delegation code path in the codebase. A contract can call `FREEZE` (0xd5) targeting this reserved address, causing the resource weight (bandwidth/energy delegation credit) to be silently attributed to an account that no legitimate user controls, effectively wasting/burning that portion of "acquired delegated" resource capacity for the receiver-side accounting, with no way for the contract owner to reclaim the delegated bookkeeping benefit through normal `UNFREEZE`/undelegate flows aimed at a real counterpart. This is a resource-accounting/consistency defect rather than a direct TRX theft, since the frozen TRX principal itself stays locked under the owner's own balance in the `FreezeBalanceCapsule`, and can eventually be unfrozen back to the owner.

### Likelihood Explanation
The `FREEZE` opcode is reachable from any smart contract call once the `allowTvmFreeze` proposal is active on the network, making the path directly triggerable via a single `TriggerSmartContract` transaction from any unprivileged caller. No special privileges are required — any contract that implements a wrapper for `target.freeze(amount, resource)` can pass an attacker-controlled `receiverAddress` including the zero/reserved payload, since the actuator's protobuf-facing sibling correctly rejects invalid formats but this internal TVM-native path does not perform the same check.

### Recommendation
Add `DecodeUtil.addressValid(ownerAddress)` and `DecodeUtil.addressValid(receiverAddress)` checks at the top of `FreezeBalanceProcessor.validate()`, mirroring the checks already present in `FreezeBalanceV2Processor.validate()`, `DelegateResourceProcessor.validate()`, and `UnDelegateResourceProcessor.validate()`, and reject reserved/zero-payload addresses before auto-creating an account or delegating resource weight to them.

### Proof of Concept
Not independently executed against a live/dev node due to tooling constraints (this analysis is based purely on static code review of the referenced files). Conceptually:
1. Deploy a contract exposing a function that calls the TVM opcode equivalent of `target.freeze(amount, resourceType)` with `target` set to the reserved/zero-payload TRON address (prefix byte + 20 zero bytes).
2. Ensure `allowTvmFreeze` is enabled (as in the existing `FreezeTest.java` test suite, which already exercises this opcode with `manager.getDynamicPropertiesStore().saveAllowTvmConstantinople(1)`-style flags [10](#0-9) ).
3. Trigger the contract via a normal `TriggerSmartContract` transaction with sufficient balance.
4. Observe that `FreezeBalanceProcessor.validate()` does not reject the zero/reserved receiver address, unlike the analogous `FreezeBalanceActuator`/`DelegateResourceProcessor` paths, and that `execute()` proceeds to delegate resource weight to that unusable account.

  public static void freezeAction(Program program) {
    // after allow vote, check static
    if (VMConfig.allowTvmVote() && program.isStaticCall()) {
      throw new Program.StaticCallModificationException();
    }
    // 0 as bandwidth, 1 as energy
    DataWord resourceType = program.stackPop();
    DataWord frozenBalance = program.stackPop();
    DataWord receiverAddress = program.stackPop();

    if (VMConfig.allowTvmFreezeV2()) {
      // after v2 activated, we just push zero to stack and do nothing
      program.stackPush(DataWord.ZERO());
    } else {
      boolean result = program.freeze(receiverAddress, frozenBalance, resourceType );
      program.stackPush(result ? DataWord.ONE() : DataWord.ZERO());
    }
    program.step();
  }

  public void validate(FreezeBalanceParam param, Repository repo) throws ContractValidateException {
    if (repo == null) {
      throw new ContractValidateException(STORE_NOT_EXIST);
    }

    // validate arg @frozenBalance
    byte[] ownerAddress = param.getOwnerAddress();
    AccountCapsule ownerCapsule = repo.getAccount(ownerAddress);
    long frozenBalance = param.getFrozenBalance();
    if (frozenBalance <= 0) {
      throw new ContractValidateException("FrozenBalance must be positive");
    } else if (frozenBalance < TRX_PRECISION) {
      throw new ContractValidateException("FrozenBalance must be greater than or equal to 1 TRX");
    } else if (frozenBalance > ownerCapsule.getBalance()) {
      throw new ContractValidateException("FrozenBalance must be less than or equal to accountBalance");
    }

    // validate frozen count of owner account
    int frozenCount = ownerCapsule.getFrozenCount();
    if (frozenCount != 0 && frozenCount != 1) {
      throw new ContractValidateException("FrozenCount must be 0 or 1");
    }

    // validate arg @resourceType
    switch (param.getResourceType()) {
      case BANDWIDTH:
      case ENERGY:
        break;
      default:
        throw new ContractValidateException(
            "Unknown ResourceCode, valid ResourceCode[BANDWIDTH、ENERGY]");
    }

    // validate for delegating resource
    byte[] receiverAddress = param.getReceiverAddress();
    if (!FastByteComparisons.isEqual(ownerAddress, receiverAddress)) {
      param.setDelegating(true);

      // check if receiver account exists. if not, then create a new account
      AccountCapsule receiverCapsule = repo.getAccount(receiverAddress);
      if (receiverCapsule == null) {
        receiverCapsule = repo.createNormalAccount(receiverAddress);
      }

      // forbid delegating resource to contract account
      if (receiverCapsule.getType() == Protocol.AccountType.Contract) {
        throw new ContractValidateException(
            "Do not allow delegate resources to contract addresses");
      }
    }
