Found FindRemoteRepository and FindRemoteRootRef RPCs which accept attacker-controlled `remote`/`remote_url` fields (including embedded credentials) but are **not** in `possibleGrpcMethods` allowlist in `internal/cli/gitaly/serve.go`, confirming the reported gap.

### Title
Incomplete gRPC method allowlist in `URLSanitizerHook` leaks credentialed URLs for `FindRemoteRepository`/`FindRemoteRootRef` - (File: internal/log/url_sanitizer.go)

### Summary
`URLSanitizerHook.Fire` only sanitizes log fields for gRPC methods explicitly registered via `AddPossibleGrpcMethod`, which in `internal/cli/gitaly/serve.go` is hardcoded to `CreateRepositoryFromURL`, `FetchRemote`, and `UpdateRemoteMirror` only. `RemoteService.FindRemoteRepository` and `RemoteService.FindRemoteRootRef` both accept an attacker-supplied URL field (`remote` / `remote_url`) that can embed HTTP Basic credentials (`https://user:pass@host/...`), yet neither method is in the allowlist, so any error or spawn-args log entry produced while processing these RPCs bypasses the `sanitizeString` regex and can log the raw credentialed URL.

### Finding Description
`hostPattern`/`sanitizeString` in `internal/log/url_sanitizer.go` strips `user:pass@` from log fields, but `Fire` gates this entirely on `hook.possibleGrpcMethods[mthStr]` [1](#0-0) . The allowlist is populated only with three RPC names in `configure()` [2](#0-1) .

`FindRemoteRepositoryRequest.remote` and `FindRemoteRootRefRequest.remote_url` are both attacker-controlled URL strings that can embed credentials (`proto/remote.proto` lines 103-146) — same shape as the already-sanitized `UpdateRemoteMirrorRequest.Remote.url` and `FetchRemoteRequest.RemoteParams.Url` [3](#0-2) . These RPCs pass the raw URL into `git-ls-remote`/similar git invocations, and any resulting error (e.g. connection failure, auth failure, malformed URL) is logged with the "args" or "error" fields containing the original unsanitized URL — because their method names are absent from `possibleGrpcMethods`, `Fire` returns early without redacting.

By contrast, `CreateFork` does not accept a URL field at all (`CreateForkRequest` has only `repository`, `source_repository`, `revision` [4](#0-3) ) — so the audit prompt's premise regarding `CreateFork`'s `resolved_address` is inaccurate; `resolved_address` belongs to `Remote`/`FetchRemoteRequest`/`UpdateRemoteMirrorRequest`, which are already covered. Likewise, bundle-URI signed URLs (`bundleuri.GenerationManager.SignedURL`) are server-generated from Gitaly's own storage configuration, not attacker-controlled input, so they are not a credential-leak vector [5](#0-4) .

### Impact Explanation
Credentials embedded in a URL supplied to `FindRemoteRepository`/`FindRemoteRootRef` can appear unredacted in Gitaly's structured logs (spawn args or error text) whenever these RPCs error out (e.g., unreachable host, bad SSH key, auth failure). This matches GitLab's "sensitive data exposure via logs" impact class — anyone with read access to Gitaly logs (log aggregation, Sentry via error forwarding, etc.) could recover credentials that the calling user believed were only used transiently to reach a remote Git server.

### Likelihood Explanation
Any unprivileged GitLab user who can trigger a repository import/mirror-status check that maps to `FindRemoteRepository` or `FindRemoteRootRef` (both accessible via the "check remote repository" / "detect default branch" flows used during project import/mirror setup) can supply a credentialed URL and force an error path, reliably producing the unsanitized log line. No special role or configuration is required beyond default Gitaly logging.

### Recommendation
Add `FindRemoteRepository` and `FindRemoteRootRef` (and any other future RPC accepting a `url`/`remote_url`/`remote` field) to the `AddPossibleGrpcMethod` call in `internal/cli/gitaly/serve.go`. Longer term, replace the static allowlist with a mechanism derived from `protoregistry` metadata (e.g., a proto field option marking URL-bearing fields) so newly added RPCs are automatically covered instead of relying on manual registration.

### Proof of Concept
```go
// internal/log/url_sanitizer_test.go (extend existing tests)
func TestURLSanitizerHook_MissingAllowlistEntry(t *testing.T) {
    hook := log.NewURLSanitizerHook()
    hook.AddPossibleGrpcMethod("CreateRepositoryFromURL", "FetchRemote", "UpdateRemoteMirror")
    // FindRemoteRepository / FindRemoteRootRef are NOT registered.

    entry := &logrus.Entry{
        Data: logrus.Fields{
            "grpc.method": "FindRemoteRepository",
            "error":       errors.New("dial https://user:secret@evil.example/repo.git: connection refused"),
        },
    }
    require.NoError(t, hook.Fire(entry))
    // BUG: credential is NOT redacted because the method isn't allowlisted.
    require.Contains(t, entry.Data["error"].(error).Error(), "user:secret@")
}
```
RPC-level repro: call `RemoteService.FindRemoteRepository` with `remote: "https://user:secret@invalid-host.invalid/repo.git"` and `storage_name` set; the resulting log entry for the failed `git-ls-remote` invocation contains the raw `user:secret@` credential, unlike an equivalent failure from `FetchRemote` with the same credentialed URL, which is sanitized.

func (hook *URLSanitizerHook) Fire(entry *logrus.Entry) error {
	mth, ok := entry.Data["grpc.method"]
	if !ok {
		return nil
	}

	mthStr, ok := mth.(string)
	if !ok || !hook.possibleGrpcMethods[mthStr] {
		return nil
	}

	if _, ok := entry.Data["args"]; ok {
		sanitizeSpawnLog(entry)
	} else if _, ok := entry.Data["error"]; ok {
		sanitizeErrorLog(entry)
	} else {
		entry.Message = sanitizeString(entry.Message)
	}

	return nil
}

  // remote_url specifies the remote repository URL which should be fetched from.

  reserved "http_host";

// SignedURL returns a public URL to give anyone access to download the bundle from.
func (g *GenerationManager) SignedURL(ctx context.Context, repo storage.Repository) (string, error) {
	relativePath := bundleRelativePath(ctx, repo, defaultBundle)

	repoProto, ok := repo.(*gitalypb.Repository)
	if !ok {
		return "", fmt.Errorf("unexpected repository type %t", repo)
	}

	if tx := storage.ExtractTransaction(ctx); tx != nil {
		origRepo := tx.OriginalRepository(repoProto)
		relativePath = bundleRelativePath(ctx, origRepo, defaultBundle)
	}

	return g.sink.signedURL(ctx, relativePath)
}
