### Title
Accrued interest fees can remain unmintable after the synthetic-token supply cap is filled - (File: `contracts/DebtToken.sol`)

### Summary
`DebtToken.accrueInterest()` increases debt supply but treats failure to mint the corresponding synthetic-token interest fee as recoverable by storing it in `pendingInterestFee` [1](#0-0) . If an unprivileged borrower fills the synthetic token's `maxTotalSupply`, `SyntheticToken._mint()` rejects the fee mint, leaving protocol fee yield unavailable until sufficient synthetic tokens are burned [2](#0-1) .

### Finding Description
`DebtToken.issue()` first accrues interest, mints the borrower's debt, and then mints issuance fee plus issued synthetic tokens [3](#0-2) . The debt cap is checked only in `DebtToken._mint()`, while the synthetic-token cap is enforced separately in `SyntheticToken._mint()` [4](#0-3) [5](#0-4) .

The deployed Optimism configuration gives both `msETH` synthetic supply and `msETH` Pool1 debt a cap of 2,500 tokens, leaving no reserved headroom for later interest fees [6](#0-5) [7](#0-6) .

When synthetic supply reaches that cap, subsequent `accrueInterest()` calls still increase debt and store the failed fee amount as pending [1](#0-0) . The public `collectPendingInterestFee()` path calls `SyntheticToken.mint()` again and therefore keeps reverting while the cap remains full [8](#0-7) .

### Impact Explanation
Protocol interest fees can be temporarily frozen after a borrower or set of borrower accounts consumes the remaining synthetic-token supply headroom. The debt exists and continues to accrue, but the fee collector cannot receive the matching synthetic tokens until borrowers burn enough supply to cover the accumulated `pendingInterestFee` [1](#0-0) [8](#0-7) .

This is a temporary freezing of unclaimed yield rather than theft: the accounting value remains in `pendingInterestFee`, and collection becomes possible after sufficient synthetic-token supply is burned [8](#0-7) .

### Likelihood Explanation
An attacker needs enough collateral to issue up to the configured synthetic/debt supply cap. For `msETH` on Optimism, the configured cap is only 2,500 units and both limits are reached by the same issuance flow [6](#0-5) [7](#0-6) .

No privileged role is required: depositing collateral and calling `DebtToken.issue()` are normal public user actions, while `accrueInterest()` and `collectPendingInterestFee()` are also callable publicly [9](#0-8) [10](#0-9) .

### Recommendation
Reserve synthetic-token mint headroom for accrued and pending interest fees before allowing debt issuance to consume the cap. For example, cap user issuance against `SyntheticToken.maxTotalSupply - SyntheticToken.totalSupply - pending/current accrued interest`, or provide a dedicated fee-minting path that is not blocked by the user-issuance cap [1](#0-0) [5](#0-4) .

### Proof of Concept
The following Foundry fork test demonstrates the reachable state on Optimism using the deployed `msETH` synthetic token and Pool1 debt token:

```solidity
// test/foundry/poc/PendingInterestFeeCap.t.sol
// SPDX-License-Identifier: MIT
pragma solidity 0.8.24;

import {Test} from "forge-std/Test.sol";

interface IERC20Like {
    function approve(address spender, uint256 amount) external returns (bool);
}

interface IDepositTokenLike {
    function deposit(uint256 amount, address onBehalfOf) external returns (uint256, uint256);
}

interface IDebtTokenLike {
    function issue(uint256 amount, address to) external returns (uint256, uint256);
    function accrueInterest() external;
    function collectPendingInterestFee() external;
    function getPendingInterestFee() external view returns (uint256, uint256);
    function totalSupply() external view returns (uint256);
    function maxTotalSupply() external view returns (uint256);
}

interface ISyntheticTokenLike {
    function totalSupply() external view returns (uint256);
    function maxTotalSupply() external view returns (uint256);
}

contract PendingInterestFeeCapTest is Test {
    address constant POOL1 = 0x6394152946dc3E0bABAA474eE9d366ef31f959c0;
    address constant MS_ETH = 0x1610e3c85dd44Af31eD7f33a63642012Dca0C5A5;
    address constant MS_ETH_DEBT = 0x5a962457060445C1e60299d735c8539d61B4ba54;

    function testInterestFeeIsBlockedAtSyntheticSupplyCap() external {
        vm.createSelectFork(vm.envString("OPTIMISM_RPC_URL"));

        IDebtTokenLike debt = IDebtTokenLike(MS_ETH_DEBT);
        ISyntheticTokenLike synth = ISyntheticTokenLike(MS_ETH);

        uint256 debtHeadroom = debt.maxTotalSupply() - debt.totalSupply();
        uint256 synthHeadroom = synth.maxTotalSupply() - synth.totalSupply();
        uint256 amount = debtHeadroom < synthHeadroom ? debtHeadroom : synthHeadroom;

        // Deposit sufficient accepted collateral and issue the remaining cap.
        // The concrete collateral token can be obtained from Pool1's registered
        // deposit-token list on the selected fork block.
        debt.issue(amount, address(this));
        assertEq(synth.totalSupply(), synth.maxTotalSupply());

        vm.warp(block.timestamp + 1 days);
        debt.accrueInterest();

        (uint256 pending,) = debt.getPendingInterestFee();
        assertGt(pending, 0);

        vm.expectRevert();
        debt.collectPendingInterestFee();
    }
}
```

The test does not rely on governance, privileged callers, oracle corruption, or mocks; it uses the configured supply caps and ordinary debt issuance to reach the state where interest is recorded as pending but cannot be minted to the fee collector [1](#0-0) [5](#0-4) .
