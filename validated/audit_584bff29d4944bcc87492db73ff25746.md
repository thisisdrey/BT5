### Title
`Pool.swap` executes oracle-priced synthetic swaps without user slippage control - (File: contracts/Pool.sol)

### Summary
`Pool.swap` lets users burn one synthetic token and mint another at a price determined entirely by `masterOracle().quote` at execution time. There is no `amountOutMin` / `minAmountOut` parameter, so a swap submitted in the mempool can execute at a worse rate than the user saw when signing. The same pattern affects `quoteSwapIn`-style flows and any oracle-priced mint path. This is the same bug class as the Rio LRT deposit issue: the received quantity floats with the price feed until the transaction is mined.

### Finding Description
The swap flow in `Pool.sol` burns the caller's `syntheticTokenIn_` first, then computes `_amountOut` via `quoteSwapOut`, which internally calls `IMasterOracle.quote(syntheticTokenIn_, syntheticTokenOut_, amountIn_)` [1](#0-0) . The quote resolves `priceIn/priceOut` through the configured token oracles (Chainlink/Pyth pull feeds on deployed chains) [2](#0-1) . Because the function signature is `swap(syntheticTokenIn_, syntheticTokenOut_, amountIn_)` with no bound on the output [3](#0-2) , the caller has no way to revert if the oracle price moved adversely while the transaction was pending.

The same is true on the deposit/withdraw side: `DepositToken.deposit`/`withdraw` mint/burn deposit-token shares whose USD value is oracle-derived, but those are 1:1 in underlying units, so `Pool.swap` is the strongest analog.

### Impact Explanation
A user's `swap` transaction can be executed after an unfavorable oracle update (e.g., a Pyth `updatePriceFeeds` pushed in the same block by anyone, or a Chainlink round update landing first), delivering less `syntheticTokenOut_` than the fair rate at submission time. The protocol itself remains solvent — value is burned and minted at the same oracle rate — but the user suffers an unbounded, unprotectable price loss on the swap leg, exactly matching the "less tokens received, no slippage" impact in the source report. Since the burn happens before the quote, the user cannot even back out at a stale price.

### Likelihood Explanation
Oracle prices move between mempool submission and inclusion routinely on mainnet/Base/Optimism, and pull-oracle updates are permissionless (the test suite itself shows an EOA calling `pyth.updatePriceFeeds` inside an `Operator.execute` batch) [4](#0-3) . Any swap pending across such an update settles at the new price. No privileged role is needed to cause the price change, and no existing guard (`isSwapActive`, `nonReentrant`, `whenNotShutdown`) bounds the output.

### Recommendation
Add a `minAmountOut_` parameter to `swap` (and optionally a symmetric `maxAmountIn_` exact-out variant), and revert when `quoteSwapOut` yields less than the user-specified bound:

```solidity
function swap(
    ISyntheticToken syntheticTokenIn_,
    ISyntheticToken syntheticTokenOut_,
    uint256 amountIn_,
    uint256 minAmountOut_
) ... {
    ...
    (_amountOut, _fee) = quoteSwapOut(syntheticTokenIn_, syntheticTokenOut_, amountIn_);
    if (_amountOut < minAmountOut_) revert SlippageTooHigh();
    ...
}
```

### Proof of Concept
Foundry fork test sketch (Base/mainnet deployment, where `isSwapActive` is enabled):

```solidity
function testSwapNoSlippage() public {
    IPool pool = IPool(POOL_ADDRESS);          // deployed Pool
    IERC20 msUSD = IERC20(MSUSD_ADDRESS);
    ISyntheticToken msETH = ISyntheticToken(MSETH_ADDRESS);

    // Victim holds msUSD, signs swap expecting ~oracle rate R0
    uint256 amountIn = 1_000e18;
    deal(address(msUSD), victim, amountIn);
    (uint256 expectedOut,) = pool.quoteSwapOut(msUSD, msETH, amountIn);

    // Before victim's tx lands, a permissionless Pyth/Chainlink update
    // raises msUSD price (or lowers msETH price) by 5%
    vm.prank(anyone);
    pyth.updatePriceFeeds(freshUpdateData);     // price moved -5% for the pair

    // Victim's swap executes with no minAmountOut check
    vm.prank(victim);
    (uint256 amountOut,) = pool.swap(msUSD, msETH, amountIn);

    // Burned at old expectation, minted at new worse price; no revert path
    assertLt(amountOut, expectedOut * 95 / 100); // ~5% loss, fully unbounded
}
```

The transaction succeeds despite delivering materially less than `quoteSwapOut` showed at signing time, because `swap` has no output bound [5](#0-4) .

```text
        ISyntheticToken syntheticTokenIn_,
        ISyntheticToken syntheticTokenOut_,
        uint256 amountIn_
    ) public view override returns (uint256 _amountOut, uint256 _fee) {
        _amountOut = _poolRegistry.masterOracle().quote(
            address(syntheticTokenIn_),
            address(syntheticTokenOut_),
            amountIn_
        );

        uint256 _swapFee = feeProvider.swapFees(address(syntheticTokenIn_), address(syntheticTokenOut_));

        if (_swapFee > 0) {
            _fee = _amountOut.wadMul(_swapFee);
            _amountOut -= _fee;
        }
    }
```

```text
    function swap(
        ISyntheticToken syntheticTokenIn_,
        ISyntheticToken syntheticTokenOut_,
        uint256 amountIn_
    )
        external
        override
        whenNotShutdown
        nonReentrant
        onlyIfSyntheticTokenExists(syntheticTokenIn_)
        onlyIfSyntheticTokenExists(syntheticTokenOut_)
        returns (uint256 _amountOut, uint256 _fee)
    {
        address _msgSender = _msgSender();

        if (!isSwapActive) revert SwapFeatureIsInactive();
        if (amountIn_ == 0 || amountIn_ > syntheticTokenIn_.balanceOf(_msgSender)) revert AmountInIsInvalid();

        syntheticTokenIn_.burn(_msgSender, amountIn_);

        (_amountOut, _fee) = quoteSwapOut(syntheticTokenIn_, syntheticTokenOut_, amountIn_);

        if (_fee > 0) {
            syntheticTokenOut_.mint(_poolRegistry.feeCollector(), _fee);
        }

        syntheticTokenOut_.mint(_msgSender, _amountOut);

        emit SyntheticTokenSwapped(_msgSender, syntheticTokenIn_, syntheticTokenOut_, amountIn_, _amountOut, _fee);
    }
```
