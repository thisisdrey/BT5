### Title
Risk engine health checks use stale (un-accrued) interest for a position's other bank debts, allowing borrowing/withdrawal past true insolvency threshold - ([File: programs/marginfi/src/state/marginfi_account.rs])

### Summary
Marginfi's `lending_account_borrow` and `lending_account_withdraw` instructions call `bank.accrue_interest(...)` only for the single bank being acted on, then immediately run the risk-engine health check (`check_account_init_health` → `get_health_components`) over **all** of the account's active balances. For every bank other than the one just touched, `get_health_components` reads `bank.liability_share_value`/`bank.asset_share_value` directly from the loaded `Bank` account without accruing interest first. If a user's multi-bank position has a debt in a bank that has gone a long time without any transaction (and thus without an `accrue_interest` call), that debt's true, currently-owed value is understated in the health check, exactly mirroring the BlueBerryBank H-4 bug class: only one debt token's interest is refreshed while the liquidatability/health decision is based on all debt tokens.

### Finding Description
`lending_account_borrow` accrues interest for only the acted-upon bank before the health check: [1](#0-0) 

then runs `check_account_init_health`: [2](#0-1) 

Likewise, `lending_account_withdraw` accrues interest only for the withdrawn bank: [3](#0-2) 

The health check itself, `get_health_components`, iterates over every active balance in the account and loads each referenced `Bank` (via `AccountLoader`), computing liability/asset values directly from the bank's stored share values with no call to `accrue_interest` for those other banks: [4](#0-3) 

The actual liability value comes from `bank.get_liability_amount(balance.liability_shares)`, i.e. `shares * self.liability_share_value`, which is only updated when that specific bank's `accrue_interest` runs: [5](#0-4) [6](#0-5) 

Interest accrual is otherwise only triggered per-bank, either by user transactions against that specific bank or by the permissionless `lending_pool_accrue_bank_interest` instruction: [7](#0-6) 

Because interest for banks not directly touched in the current instruction is not refreshed before the health/risk decision, an account holding debt across multiple banks can pass `check_account_init_health` using an understated total liability, even though its true (interest-inclusive) debt would make it unhealthy or already liquidatable.

### Impact Explanation
An attacker can deliberately structure a position with debt in an illiquid/rarely-touched bank (whose `liability_share_value` has gone stale) alongside activity in a frequently-used bank. Each time they interact with the active bank (e.g., repeated `lending_account_borrow` or `lending_account_withdraw` calls), the risk engine underestimates the stale bank's debt, letting them borrow/withdraw more than their real (interest-inclusive) collateralization allows. Once the stale bank's interest is eventually accrued (by anyone, or by a subsequent transaction against it), the account's true debt jumps and it may be under-collateralized beyond what a liquidation can recover, producing bad debt that must be socialized among lenders via the bankruptcy path. This is an insolvency/bad-debt impact reachable by any unprivileged user with a multi-bank position.

### Likelihood Explanation
Likelihood is moderate: it requires an account to have at least two active debt/asset balances across banks with materially different accrual cadences, and for the attacker to time transactions to exploit the gap. Isolated or low-traffic banks (which the README itself acknowledges "compound just a few times per week") make the staleness window realistic, and no privileged access or oracle manipulation is needed — only ordinary user instructions (`lending_account_borrow`, `lending_account_withdraw`) available to any account holder.

### Recommendation
Before running `check_account_init_health` (or any risk-engine health/liquidation decision), accrue interest on every bank referenced by the account's active balances, not just the bank being acted upon in the current instruction — mirroring the Sherlock/BlueBerry recommendation to accrue interest on every debt token of a position at the start of the risk-affecting execution path.

### Proof of Concept
1. User opens a marginfi account with a deposit in Bank C (active/liquid).
2. User borrows from Bank A, an isolated/low-traffic bank, at t0. `liability_share_value` for Bank A is set at t0.
3. Time passes (e.g. weeks) without anyone interacting with Bank A, so its `liability_share_value` is never refreshed, while its true interest-owed keeps growing.
4. User repeatedly calls `lending_account_borrow` against Bank B (a different, actively used bank). Each call accrues interest only for Bank B (`programs/marginfi/src/instructions/marginfi_account/borrow.rs:76-81`), then `check_account_init_health` computes total liabilities using Bank A's stale `liability_share_value` (`programs/marginfi/src/state/marginfi_account.rs:662-738`, `programs/marginfi/src/state/bank.rs:231-235`).
5. Because Bank A's real debt is understated, the health check passes and the user is allowed to borrow more from Bank B than their true collateralization supports.
6. When Bank A's interest is finally accrued (by any permissionless `lending_pool_accrue_bank_interest` call or a subsequent Bank A transaction), the account's real liabilities exceed its assets, producing bad debt that must be resolved through `lending_pool_handle_bankruptcy`, socializing losses to Bank A's/Bank B's depositors.

pub fn lending_pool_accrue_bank_interest(
    ctx: Context<LendingPoolAccrueBankInterest>,
) -> MarginfiResult {
    let clock = Clock::get()?;
    let mut bank = ctx.accounts.bank.load_mut()?;
    let group = &ctx.accounts.group.load()?;

    bank.accrue_interest(
        clock.unix_timestamp,
        group,
        #[cfg(not(feature = "client"))]
        ctx.accounts.bank.key(),
    )?;

    // TODO see if we can recycle some things like the InterestRateCalc from accrue to save some CU
    bank.update_bank_cache(group)?;

    Ok(())
}
