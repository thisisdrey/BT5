## Title
Protocol fee bypass on NEP-245/NEP-171 token transfers via unit-leg batching in `TokenDiff::execute_intent` / `TokenDiff::token_fee` - (`contracts/defuse/core/src/intents/token_diff.rs`)

### Summary
`TokenDiff::token_fee` waives protocol fees on any `Nep245`/`Nep171`/`Imt` leg whose `amount <= 1`, and `TokenDiff::execute_intent` computes/collects this fee strictly per-intent, per-token-id, with no aggregation across a `MultiPayload` batch. An unprivileged signer can therefore split a single N-unit MT/NFT transfer into N separately-signed, unit-amount `TokenDiff` intents in one batch and pay zero total protocol fee, whereas the economically identical single N-unit intent would owe `Pips::fee_ceil(N, protocol_fee)`.

### Finding Description
The broken binding: for a batch that moves a net `N` units of the same `Nep245` `token_id` out of a signer's account, the expected invariant is
`sum(fees credited to fee_collector for token T across the batch) == Pips::fee_ceil(N, protocol_fee)`
(this is what a single `TokenDiff{diff:{T:-N}}` intent produces via `Self::token_fee(token_id, amount, protocol_fee).fee_ceil(amount)` at [1](#0-0) ).

`TokenDiff::token_fee` explicitly zeroes the fee for `Nep245`/`Nep171`/`Imt` tokens whenever the per-intent `amount <= 1`: [2](#0-1) 

Because this check is evaluated once per `TokenDiff::execute_intent` call using only that intent's own `delta` (not any batch-wide aggregate), a signer can submit `N` separately-signed `MultiPayload` entries, each containing a `TokenDiff{diff:{token_id: -1}, ...}` on the same `Nep245`/`Nep171` `token_id`, with distinct nonces. Each call independently computes `fee = token_fee(token_id, 1, protocol_fee).fee_ceil(1) = 0`, so `fees_collected` stays empty and `internal_add_balance` to `fee_collector` is skipped every time ( [3](#0-2) ).

For the batch to actually settle (not revert), the withdrawn units must be matched by equal deposits recorded in the global `TransferMatcher` across all intents in the same `execute_signed_intents` call ( [4](#0-3) , finalized in [5](#0-4) ). This is trivially satisfiable: the attacker (or a counterparty, who may be the attacker's own second account, or any genuine trading partner) signs N matching `+1` legs for the same `token_id`, so `TokenTransferMatcher::finalize_into` pairs them into a plain transfer of `N` total units from signer to counterparty ( [6](#0-5) ) — no invariant violation occurs, and the whole batch settles.

None of the standard guards (`MultiPayload::verify`, `has_public_key`, `verify_intent_nonce`, nonce commit, invariant/`TransferMatcher::finalize`) address this because they only guarantee authenticity of each signed intent and zero-sum balance conservation across the batch; they say nothing about fee aggregation across multiple legs of the same logical trade. The fee computation itself is the root cause: it is per-intent-per-token, and the `amount <= 1` exemption (intended for genuine single-NFT transfers) is defeated by trivially chunking a larger MT/NFT quantity into repeated 1-unit legs, each independently signed by the attacker's own key.

### Impact Explanation
The `fee_collector` under-collects protocol fees on any `Nep245` (multi-token/semi-fungible) or `Nep171` transfer/swap whose size can be represented as repeated unit legs. A single N-unit `TokenDiff` would owe `Pips::fee_ceil(N, protocol_fee)`; N chunked unit-leg intents owe `0`. This is repeatable without limit across accounts, tokens, and batches — any principal amount of an MT-type asset can be moved fee-free by an attacker willing to sign N intents instead of 1. This matches the Critical category "protocol fees bypassed," since value that should be credited to `fee_collector` never is, while the underlying asset still moves between accounts.

### Likelihood Explanation
Preconditions are minimal and fully within an unprivileged actor's control: `protocol_fee > 0`, a `fee_collector` configured, and the attacker holding `N` units of some `Nep245`/`Nep171` `token_id`. The attacker only needs to sign `N` `TokenDiff` intents with their own key (trivial, no forged signatures, no role) and, if a genuine transfer/swap is wanted, a counterparty (which can be another self-owned account) signing matching legs. Cost scales with the number of intents/gas for a larger batch (out of scope per rules to penalize), but the bypass itself is deterministic and fully reproducible for any `N`.

### Recommendation
Aggregate the fee-exemption threshold across the whole batch/signer rather than per individual `TokenDiff` intent — e.g., accumulate net per-`token_id` negative deltas across all intents from the same signer (or globally) in the `Engine`/`TransferMatcher` before applying the `amount <= 1` exemption in `TokenDiff::token_fee`, or restrict this exemption to token types/IDs whose max supply is provably 1 (true NFTs) rather than to a raw per-call `amount` threshold applied to semi-fungible `Nep245` tokens.

    // Finalizes all transfers, or returns unmatched deltas.
    // If unmatched deltas overflow, then Err(None) is returned.
    pub fn finalize(self) -> Result<Transfers, InvariantViolated> {
        let mut transfers = Transfers::default();
        let mut deltas = TokenDeltas::default();
        for (token_id, transfer_matcher) in self.0 {
            if let Err(unmatched) = transfer_matcher.finalize_into(&token_id, &mut transfers)
                && (unmatched == 0 || deltas.apply_delta(token_id, unmatched).is_none())
            {
                return Err(InvariantViolated::Overflow);
            }
        }
        if !deltas.is_empty() {
            return Err(InvariantViolated::UnmatchedDeltas {
                unmatched_deltas: deltas,
            });
        }
        Ok(transfers)
    }

    pub fn finalize_into(self, token_id: &TokenId, transfers: &mut Transfers) -> Result<(), i128> {
        // sort deposits and withdrawals in descending order
        let [mut deposits, mut withdrawals] = [self.deposits, self.withdrawals].map(|amounts| {
            let mut amounts: Vec<_> = amounts.into_iter().collect();
            amounts.sort_unstable_by_key(|(_, amount)| Reverse(*amount));
            amounts.into_iter()
        });

        // take first sender and receiver
        let (mut deposit, mut withdraw) = (deposits.next(), withdrawals.next());

        // as long as there is both: sender and receiver
        while let Some(((sender, send), (receiver, receive))) =
            withdraw.as_mut().zip(deposit.as_mut())
        {
            // get min amount and transfer
            let transfer = (*send).min(*receive);
            transfers
                .transfer(sender.clone(), receiver.clone(), token_id.clone(), transfer)
                // no error can happen since we add only one transfer for each
                // combination of (sender, receiver, token_id)
                .unwrap_or_else(|| unreachable!());

            // subtract amount from sender and receiver
            *send = send.saturating_sub(transfer);
            *receive = receive.saturating_sub(transfer);

            if *send == 0 {
                // select next sender
                withdraw = withdrawals.next();
            }
            if *receive == 0 {
                // select next receiver
                deposit = deposits.next();
            }
        }

        // only sender(s) left
        if let Some((_, send)) = withdraw {
            return Err(withdrawals
                .try_fold(send, |total, (_, s)| total.checked_add(s))
                .and_then(|total| i128::try_from(total).ok())
                .and_then(i128::checked_neg)
                .unwrap_or_default());
        }
        // only receiver(s) left
        if let Some((_, receive)) = deposit {
            return Err(deposits
                .try_fold(receive, |total, (_, r)| total.checked_add(r))
                .and_then(|total| i128::try_from(total).ok())
                .unwrap_or_default());
        }

        Ok(())
    }
