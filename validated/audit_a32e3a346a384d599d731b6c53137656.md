### Title
Unstaked peers can inflate `max_uni_streams` up to 7x fair-share cap via QUIC RTT/ACK-delay gaming - ([File: streamer/src/nonblocking/swqos.rs])

### Summary
`compute_max_allowed_uni_streams_with_rtt` scales the per-connection concurrent unidirectional stream limit linearly by the connection's observed RTT, up to `MAX_RTT_MS` (350ms), without any authentication of that RTT value. Because QUIC RTT is measured server-side purely from the timing of client ACKs, an unstaked (or minimally-staked) attacker fully controls this input and can inflate the granted `max_uni_streams` from the intended `QUIC_MAX_UNSTAKED_CONCURRENT_STREAMS` (128) up to `128 * 350 / 50 = 896` streams — a 7x fair-share bypass.

### Finding Description
In `cache_new_connection`, the leader reads `connection.rtt()` from `quinn` and clamps it to `MAX_RTT_MS` before computing the stream allowance: [1](#0-0) 

`compute_max_allowed_uni_streams_with_rtt` then multiplies the base per-tier stream count (`QUIC_MAX_UNSTAKED_CONCURRENT_STREAMS` for unstaked peers) by `rtt_millis.clamp(REFERENCE_RTT_MS, MAX_RTT_MS) / REFERENCE_RTT_MS`: [2](#0-1) 

`REFERENCE_RTT_MS` is 50ms and `MAX_RTT_MS` is 350ms: [3](#0-2) 

`connection.rtt()` (from the `quinn` library) is derived purely from the elapsed time between an ACK-eliciting packet sent by the leader and the corresponding ACK frame received back from the peer. Since the attacker is the QUIC client, they fully control when they send ACK frames back to the leader; deliberately delaying ACKs (or routing through an artificially-delayed proxy path) directly inflates the server-observed RTT for that connection, with no server-side sanity check, challenge, or independent verification of the RTT value. The result is fed straight into `set_max_concurrent_uni_streams`, so the leader grants the attacker up to `896` concurrent unidirectional streams instead of the intended `128` for an unstaked peer — a 7x excess over the documented "fair share" ceiling (`QUIC_MAX_UNSTAKED_CONCURRENT_STREAMS`). The existing test `test_max_allowed_uni_streams_with_rtt` even demonstrates the scaling behavior explicitly (1.5x at 75ms RTT), confirming the mechanism is unguarded against adversarial RTT inflation up to the 350ms cap.

### Impact Explanation
A single unstaked/minimal-stake attacker can hold up to ~7x more concurrently open unidirectional streams than the tier is designed to allow, each of which consumes leader-side per-stream receive-buffer/flow-control state and scheduling resources. Combined with `max_connections_per_unstaked_peer` allowing multiple such connections per peer, this lets one low-cost attacker capture a disproportionate share of the unstaked connection pool's stream capacity, starving other legitimate unstaked senders sharing the same unstaked connection/stream budget — a QoS evasion of the stake-weighted QoS design (`SwQos`) that is explicitly intended to bound per-peer resource consumption by stake tier.

### Likelihood Explanation
Fully feasible for any unprivileged remote client: no stake, no validator/gossip control, and no cryptographic bypass is required — only control over one's own ACK timing or use of a delaying network path, both trivially available to any attacker. The behavior is deterministic and repeatable on every new connection.

### Recommendation
Decouple the BDP stream-scaling factor from a raw, attacker-observable/attacker-influenceable RTT sample. Options: cap the RTT-based multiplier much lower for the unstaked tier (or disable BDP scaling entirely for `ConnectionPeerType::Unstaked`, since unstaked peers have no reputational cost for gaming it), smooth/verify the RTT sample using multiple independent measurements with outlier rejection, or bound the *total* additional streams-of-scaling granted per unstaked peer regardless of `rtt_millis` to a hard ceiling independent of the RTT-derived multiplier.

### Proof of Concept

```rust
// streamer/src/nonblocking/swqos.rs (test module)
#[test]
fn test_unstaked_rtt_gaming_exceeds_fair_share() {
    // Attacker-controlled RTT at the clamp ceiling (achievable by delaying ACKs)
    let gamed = compute_max_allowed_uni_streams_with_rtt(
        MAX_RTT_MS, // 350ms, attacker-inflated
        ConnectionPeerType::Unstaked,
        10_000,
    );
    // Intended fair-share ceiling for an unstaked peer
    assert!(
        gamed > QUIC_MAX_UNSTAKED_CONCURRENT_STREAMS,
        "expected RTT gaming to exceed fair-share cap, got {gamed} vs cap {QUIC_MAX_UNSTAKED_CONCURRENT_STREAMS}"
    );
    // Demonstrates ~7x amplification: 128 * 350 / 50 = 896
    assert_eq!(gamed, QUIC_MAX_UNSTAKED_CONCURRENT_STREAMS * (MAX_RTT_MS / REFERENCE_RTT_MS));
}
```
Integration-level PoC: spin up a `quinn` client against the streamer's QUIC endpoint, artificially delay outgoing ACK frames (or insert a proxy adding fixed latency) to push `connection.rtt()` toward 350ms, then call `connection.open_uni()` in a loop and assert that more than `QUIC_MAX_UNSTAKED_CONCURRENT_STREAMS` streams can be opened concurrently before `max_concurrent_uni_streams` blocks further opens.

```rust
fn compute_max_allowed_uni_streams_with_rtt(
    rtt_millis: u32,
    peer_type: ConnectionPeerType,
    total_stake: u64,
) -> u32 {
    let streams = match peer_type {
        ConnectionPeerType::Staked(peer_stake) => {
            // No checked math for f64 type. So let's explicitly check for 0 here
            if total_stake == 0 || peer_stake > total_stake {
                warn!(
                    "Invalid stake values: peer_stake: {peer_stake:?}, total_stake: \
                     {total_stake:?}"
                );

                QUIC_MIN_STAKED_CONCURRENT_STREAMS
            } else {
                let delta = (QUIC_TOTAL_STAKED_CONCURRENT_STREAMS
                    - QUIC_MIN_STAKED_CONCURRENT_STREAMS) as f64;

                (((peer_stake as f64 / total_stake as f64) * delta) as u32
                    + QUIC_MIN_STAKED_CONCURRENT_STREAMS)
                    .clamp(
                        QUIC_MIN_STAKED_CONCURRENT_STREAMS,
                        QUIC_MAX_STAKED_CONCURRENT_STREAMS,
                    )
            }
        }
        ConnectionPeerType::Unstaked => QUIC_MAX_UNSTAKED_CONCURRENT_STREAMS,
    };
    // scale amount of streams based on RTT if RTT is larger than REFERENCE_RTT_MS
    // multiply first then divide to avoid rounding errors.
    (streams.saturating_mul(rtt_millis.clamp(REFERENCE_RTT_MS, MAX_RTT_MS))) / REFERENCE_RTT_MS
}
```
