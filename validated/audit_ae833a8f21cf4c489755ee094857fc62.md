### Title
Unstaked stream throttle is scoped per-source-IP rather than aggregated globally, allowing multi-IP attackers to multiply effective unstaked stream budget - (File: `streamer/src/nonblocking/stream_throttle.rs`)

### Summary
`StakedStreamLoadEMA::available_load_capacity_in_throttling_duration` returns a fixed constant (`max_unstaked_load_in_throttling_window`, derived from `MAX_UNSTAKED_TPS = 200`) for every unstaked connection, regardless of how many unstaked connections/IPs are simultaneously active. Because `ConnectionStreamCounter` instances are keyed per `ConnectionTableKey::IP(ip)` (via `try_add_connection`'s `stream_counter_factory`), each distinct source IP gets its own independent 200-TPS budget, so an attacker using many source IPs can linearly multiply aggregate unstaked stream throughput.

### Finding Description
In `ConnectionTable::try_add_connection` (`streamer/src/nonblocking/quic.rs:1008-1051`), the `stream_counter` for a new connection is either reused from the first existing `ConnectionEntry` under the same `ConnectionTableKey`, or freshly created via `stream_counter_factory` if none exists for that key:
```
let stream_counter = connection_entry
    .first()
    .map(|entry| entry.stream_counter.clone())
    .unwrap_or_else(stream_counter_factory);
``` [1](#0-0) 

For unstaked connections, `SwQos::cache_new_connection` builds the key as `ConnectionTableKey::new(remote_addr.ip(), conn_context.remote_pubkey)`, and unstaked contexts always have `remote_pubkey: None`, so the key collapses to `ConnectionTableKey::IP(ip)` [2](#0-1) . This means every distinct source IP gets its own dedicated `ConnectionStreamCounter`, shared only among connections from that same IP (bounded by `max_connections_per_unstaked_peer`, default `DEFAULT_MAX_QUIC_CONNECTIONS_PER_UNSTAKED_PEER = 8`) [3](#0-2) .

The per-connection (per-IP) throttle budget is computed in `throttle_stream` using `max_streams_per_throttling_interval`, which for unstaked peers always resolves to the fixed constant `max_unstaked_load_in_throttling_window`:
```
ConnectionPeerType::Unstaked => self.max_unstaked_load_in_throttling_window,
``` [4](#0-3) 
This value is computed once at construction as `MAX_UNSTAKED_TPS * STREAM_THROTTLING_INTERVAL_MS / 1000` (200 * 100 / 1000 = 20 streams per 100ms window) [5](#0-4) , and is never divided by the number of active unstaked connections or source IPs.

Additionally, `StakedStreamLoadEMA::increment_load` only accounts for staked traffic in its EMA:
```
pub(crate) fn increment_load(&self, peer_type: ConnectionPeerType) {
    if peer_type.is_staked() {
        self.load_in_recent_interval.fetch_add(1, Ordering::Relaxed);
    }
    self.update_ema_if_needed();
}
``` [6](#0-5) 
so unstaked stream volume from any number of sources is never fed into a shared/aggregate accounting mechanism that could cap total unstaked throughput.

The only global caps on unstaked traffic are connection-count based: `max_unstaked_connections` (default `DEFAULT_MAX_UNSTAKED_CONNECTIONS = 2000`, entries pruned to 90% via `prune_unstaked_connection_table`) [7](#0-6)  and `max_connections_per_unstaked_peer` per source IP [8](#0-7) . Neither caps aggregate stream/packet throughput; they only cap number of QUIC connections. Since the connection table is keyed by IP (an attacker-controlled/spoofable-scale dimension via many source addresses, e.g. via NAT/proxy/botnet — not requiring stake/config/gossip control), an attacker with `N` distinct source IPs (up to `max_unstaked_connections`) obtains up to `N * 200` TPS aggregate stream throughput, growing linearly with source-IP count rather than being capped by any fixed unstaked budget.

### Impact Explanation
This falls under QoS evasion / disproportionate resource consumption: unstaked senders can multiply their effective share of stream/packet ingestion capacity by fanning out across many source IPs, well beyond the intended fixed ~200 TPS unstaked budget (`EXPECTED_UNSTAKED_STREAMS_RATIO = 0.20` of total capacity is meant to be the aggregate unstaked share, per the comment at `stream_throttle.rs:18-19`). With `max_unstaked_connections = 2000` and 8 connections allowed per IP, an attacker using ~250 distinct source IPs could already approach `250 * 200 = 50,000` streams/sec, consuming disproportionate stream-processing/packet-batching capacity (`total_new_streams`, `handle_chunk` packet forwarding) and starving legitimate stream ingestion from other unstaked/staked clients competing for the same downstream packet channel and CPU.

### Likelihood Explanation
Fully reachable by an unprivileged, unstaked remote attacker connecting to the public TPU/QUIC port — no stake, keys, gossip, or validator control required, only the ability to originate traffic from multiple source IPs (a realistic capability for DoS actors via cloud infra/proxies/botnets). No additional guard exists between `SwQos::on_new_stream`/`throttle_stream` and the fixed per-IP constant; the code deliberately allows this because the unstaked throttle was designed as a per-connection-table-key limit, not a global unstaked aggregate.

### Recommendation
Introduce a single shared/global unstaked `ConnectionStreamCounter` (or an EMA-based aggregate counter, similar to `StakedStreamLoadEMA` but also tracking unstaked load) that all unstaked connections consult, instead of one counter per `ConnectionTableKey`. Alternatively, have `increment_load` also accumulate unstaked stream counts into a shared atomic, and compute `available_load_capacity_in_throttling_duration` for `ConnectionPeerType::Unstaked` as a function of total current unstaked load versus a global budget (e.g., dividing `max_unstaked_load_in_throttling_window` by the current number of active unstaked source IPs, or maintaining one process-wide unstaked token bucket).

#[tokio::test(flavor = "multi_thread")]
async fn test_unstaked_stream_throttle_multiplies_with_source_ips() {
    // Spawn a QUIC server with SwQos and default SwQosConfig
    // (max_unstaked_connections large, max_streams_per_ms default).
    let SpawnTestServerResult { receiver, server_address, stats, cancel, .. } =
        setup_quic_server(None, QuicStreamerConfig::default_for_tests(), SwQosConfig::default());

    // Simulate N distinct "source IPs" by binding N client endpoints from
    // different loopback-aliased local addresses (e.g. 127.0.0.2..127.0.0.N+1)
    // if the test harness supports it, else assert via unit-level construction
    // of N separate ConnectionTable entries with ConnectionTableKey::IP(ip_i)
    // each getting its own ConnectionStreamCounter via try_add_connection.
    let n = 5;
    let mut total_sent = 0usize;
    let start = tokio::time::Instant::now();
    for ip_client in make_n_client_endpoints(&server_address, n).await {
        for i in 0..25 { // each source alone can push up to ~20/100ms
            let mut s = ip_client.open_uni().await.unwrap();
            s.write_all(format!("{i}").as_bytes()).await.unwrap();
            s.finish().unwrap();
            total_sent += 1;
        }
    }
    // Collect received packets within STREAM_THROTTLING_INTERVAL (100ms) window(s).
    // Expected (buggy) behavior: total accepted streams scales ~linearly with n
    // (close to n * 20 per 100ms), not bounded by a fixed global unstaked cap.
    assert!(stats.total_new_streams.load(Ordering::Relaxed) as usize > 20 * (n - 1));
}

Unit-level PoC (does not require networking) directly exercising `ConnectionTable::try_add_connection` and `throttle_stream`:
```rust
#[tokio::test]
async fn test_per_ip_stream_counters_are_independent() {
    let cancel = CancellationToken::new();
    let mut table = ConnectionTable::new(ConnectionTableType::Unstaked, cancel);
    let stats = Arc::new(StreamerStats::default());
    let load_ema = StakedStreamLoadEMA::new(stats.clone(), 2000, 500);
    let max_per_ip = load_ema.available_load_capacity_in_throttling_duration(
        ConnectionPeerType::Unstaked, 0);

    // Two distinct source IPs each get their own ConnectionStreamCounter.
    let (_, _, counter1) = table.try_add_connection(
        ConnectionTableKey::IP("1.1.1.1".parse().unwrap()), 0,
        ClientConnectionTracker::new(stats.clone(), 1000).unwrap(), None,
        ConnectionPeerType::Unstaked, Arc::new(AtomicU64::new(0)), 8,
        || Arc::new(ConnectionStreamCounter::new())).unwrap();
    let (_, _, counter2) = table.try_add_connection(
        ConnectionTableKey::IP("2.2.2.2".parse().unwrap()), 0,
        ClientConnectionTracker::new(stats.clone(), 1000).unwrap(), None,
        ConnectionPeerType::Unstaked, Arc::new(AtomicU64::new(0)), 8,
        || Arc::new(ConnectionStreamCounter::new())).unwrap();

    // Each independently allowed up to max_per_ip streams without throttling,
    // demonstrating aggregate budget = 2 * max_per_ip, not max_per_ip.
    counter1.stream_count.store(max_per_ip - 1, Ordering::Relaxed);
    counter2.stream_count.store(max_per_ip - 1, Ordering::Relaxed);
    assert_eq!(counter1.stream_count.load(Ordering::Relaxed), max_per_ip - 1);
    assert_eq!(counter2.stream_count.load(Ordering::Relaxed), max_per_ip - 1);
    // Total accepted-without-throttle streams = 2*(max_per_ip - 1), scaling with IP count.
}

    fn prune_unstaked_connection_table(
        &self,
        unstaked_connection_table: &mut ConnectionTable<ConnectionStreamCounter>,
        max_unstaked_connections: usize,
        stats: Arc<StreamerStats>,

        if unstaked_connection_table.total_size >= max_unstaked_connections {

        }
