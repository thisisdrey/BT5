### Title
Full pool slash lets an attacker mint disproportionate points and dilute nomination-pool members — (`File: substrate/frame/nomination-pools/src/lib.rs`)

### Summary
The Balancer report's core broken invariant is: when a pool's backing balance is zero, the share-calculation formula degenerates to a value that no longer represents "backing balance ÷ contribution," letting an attacker mint pool shares disproportionate to what they deposited, at the expense of the pool. The `pallet-nomination-pools` `balance_to_point` conversion has an exact analog: when a bonded pool's `active_stake` (bonded balance) drops to zero while its `points` remain non-zero — the documented "totally slashed" case — the point-issuance formula switches to `new_funds.saturating_mul(current_points)` instead of the normal ratio `(current_points / current_balance) * new_funds`. This multiplies an attacker's tiny deposit by the *entire* existing point supply of the pool, exactly mirroring the "empty-balance → free/disproportionate shares" primitive from the report.

### Finding Description
`BondedPool::balance_to_point` / `Pallet::balance_to_point` computes how many points a new bonder receives for `new_funds`: [1](#0-0) 

```
match (current_balance.is_zero(), current_points.is_zero()) {
    (_, true) => new_funds.saturating_mul(POINTS_TO_BALANCE_INIT_RATIO.into()),
    (true, false) => {
        // The pool was totally slashed.
        new_funds.saturating_mul(current_points)
    },
    (false, false) => { ... ratio-based calc ... }
}
```

When `current_balance == 0` but `current_points != 0` (a pool that has been 100% slashed but still has member points recorded — this is a normal, reachable staking outcome, not an admin/governance action), any account calling `join` or `bond_extra` via `try_bond_funds` → `issue` → `balance_to_point` receives `points = new_funds * current_points`, i.e. the *entire historical point supply* multiplied by their new deposit: [2](#0-1) [3](#0-2) 

This is the same class of defect as the Balancer bug: a formula that special-cases an empty/zero backing value and returns a result that is no longer proportionally backed, silently accepted by the calling public entrypoint (`join`/`bond_extra`) with no additional guard. Just as `joinswapPoolAmountOut` never checked whether `calcSingleInGivenPoolOut` returned a degenerate value before crediting pool tokens, `try_bond_funds`/`issue` never checks whether the pool is in this "totally slashed" degenerate state before crediting points — it simply calls `issue()` and trusts the result.

### Impact Explanation
Once the attacker's deposit is converted into a point count equal to `new_funds * current_points` (which can dwarf the entire pre-existing point supply even for `new_funds` as small as 1 unit if `current_points` is large), the pool's `points` total grows overwhelmingly attacker-owned. Subsequent bonded value recovered by the pool (new deposits, restaked rewards, unbonding/withdraw flows priced via `points_to_balance`) is then apportioned by point share. Legitimate members who held points before the slash event are diluted to a negligible fraction of the pool's future value, while the attacker — who contributed a comparatively trivial `new_funds` — can later `unbond`/`withdraw_unbonded` and extract a share of pool balance far exceeding their contribution. This is a direct fund-diversion from legitimate stakers to the attacker, consistent with the report's "attacker with large funds can steal the pool's assets" impact, achievable by an unprivileged account with no admin, governance, validator, or relayer involvement.

### Likelihood Explanation
A 100% slash of a bonded pool's active stake is a reachable, unprivileged-triggerable condition in `pallet-staking`/`pallet-nomination-pools` (e.g. severe equivocation/slash events against the pool's nominated validators reduce `active_stake` to zero while `BondedPool.points` is untouched, since points are only mutated by bond/unbond calls, not by slashing). The code comment itself acknowledges this exact state ("The pool was totally slashed") as an expected branch, confirming it is reachable in production, not a purely theoretical edge case. Any account can then call `join`/`bond_extra` in that window before the pool is destroyed or before points are otherwise reconciled, since there is no check in `try_bond_funds` or `do_bond`-style entrypoints preventing bonding into a pool with `current_balance == 0 && current_points != 0`.

### Recommendation
- Short term: in `Pallet::balance_to_point`, when `current_balance.is_zero() && !current_points.is_zero()`, either reject the join/bond (return an error such as `Error::<T>::PoolSlashed`/`OverflowRisk`) or cap the issued points using a bounded multiplier instead of `new_funds.saturating_mul(current_points)`, so a small deposit cannot claim near-total ownership of the pool's point supply.
- Long term: track a pool-level "slashed to zero" flag that forces the pool into a `Destroying`/frozen state (no new joins/bond_extra) until points are reconciled or the pool is dissolved, and add invariant tests (comparable to the Balancer report's Echidna/Manticore suggestion) that assert `points_to_balance(balance_to_point(x)) ≈ x` even across the zero-balance transition, for both nomination-pools and, separately, `pallet-asset-conversion`'s zero-reserve liquidity branch (`do_add_liquidity`), which should also be fuzzed for the same class of degenerate-ratio issue even though it currently reverts via `mul_div`'s checked division rather than silently returning zero.

### Proof of Concept
1. Create a nomination pool `P` with depositor `D`; `D` bonds `1000` DOT, pool points = `1000` (1:1 ratio).
2. Trigger (or await) a validator slash event that fully slashes `P`'s nominated stake to `0` (a real, unprivileged, non-malicious-actor outcome of normal staking risk) — `BondedPool.points` remains `1000`, but `T::StakeAdapter::active_stake(pool) == 0`.
3. Attacker `A` calls `Pools::bond_extra` (or `join`) with `new_funds = 1`.
4. `balance_to_point(0, 1000, 1)` hits branch `(true, false)` and returns `1 * 1000 = 1000` points — `A` now owns `1000` of the now `2000` total points (50%) for a deposit of `1` unit.
5. If `P` later recovers value (e.g., through new deposits from other members, or partial slash reversal / additional bonding), `A` can `unbond`/`withdraw_unbonded` and redeem roughly 50% of the pool's recovered balance for an original outlay of `1` unit — diluting/stealing from `D` and other legitimate members. 	fn balance_to_point(
		current_balance: BalanceOf<T>,
		current_points: BalanceOf<T>,
		new_funds: BalanceOf<T>,
	) -> BalanceOf<T> {
		let u256 = T::BalanceToU256::convert;
		let balance = T::U256ToBalance::convert;
		match (current_balance.is_zero(), current_points.is_zero()) {
			(_, true) => new_funds.saturating_mul(POINTS_TO_BALANCE_INIT_RATIO.into()),
			(true, false) => {
				// The pool was totally slashed.
				// This is the equivalent of `(current_points / 1) * new_funds`.
				new_funds.saturating_mul(current_points)
			},
			(false, false) => {
				// Equivalent to (current_points / current_balance) * new_funds
				balance(
					u256(current_points)
						.saturating_mul(u256(new_funds))
						// We check for zero above
						.div(u256(current_balance)),
				)
			},
		}
	}
