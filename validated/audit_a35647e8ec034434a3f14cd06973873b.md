A few notes on what the codebase actually shows:

- **Download integrity is enforced**: `sha256`/`integrity` mismatches on `http_archive`/`ctx.download` are tested to hard-fail the build (`Checksum was ... but wanted ...`), including via the repository cache and the remote downloader path. [1](#0-0) [2](#0-1) 
- **The repository cache is keyed by checksum** (`content_addressable/sha256/<hash>/file`), so an attacker who doesn't know the pinned hash cannot poison the cache with different content and have it accepted, and the on-disk layout is designed around that invariant. [3](#0-2) 
- **Archive extraction containment is checked at the C++ zipper level** (`third_party/ijar`): entries are rejected if the normalized output path would land outside the extraction root, and there's an explicit path-traversal regression test. [4](#0-3) [5](#0-4) 
- **`strip_prefix`/`add_prefix` escape attempts are explicitly guarded** in `git.bzl` (`fail("strip_prefix at ... escaped the checkout directory")`, `fail("add_prefix ... escaped the base directory ...")`). [6](#0-5) 
- **Symlinks from fetched content are subject to explicit checks** (`test_bad_symlinks`, `test_symlink_outside_still_checked`), and vendoring/caching logic rewrites or validates symlink targets rather than trusting them blindly. [7](#0-6)

def _checkout_path(ctx):
    """
    Returns the path where the git repository will be checked out.

    The path returned will be the repository directory. If `add_prefix` is set,
    the additional prefix subdirectory path is appended to the repository
    directory. If the directory escapes the "root" repository, eg. an uplevel
    reference '..', the method will fail.

    if ctx.attr.add_prefix:
