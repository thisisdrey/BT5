### Title
StackerDB chunk signatures are not bound to a contract, enabling cross-contract replay of authenticated writes - ([File: libstackerdb/src/libstackerdb.rs])

### Summary
`SlotMetadata::auth_digest()` — the digest a signer's private key actually authenticates over — commits only to `slot_id`, `slot_version`, and `data_hash`. It never binds the signature to the specific StackerDB smart contract (`QualifiedContractIdentifier`) the chunk is destined for. `StackerDBTx::try_replace_chunk` and `PeerNetwork::validate_received_chunk` both look up the expected signer *by contract + slot_id* and then call `SlotMetadata::verify()`, but `verify()` only checks that the signature recovers to the expected address — it has no way to know (and does not check) that the signer intended the chunk for *this* contract. This is structurally the same "authenticated-vs-used-for" equality break as the Taiko bug: a value that is authorized/committed for one purpose (block proposer as `msg.sender`) is silently substituted/reused for a different purpose (`_meta.coinbase`) without an equality check tying it back to the authenticated actor's real intent.

### Finding Description
- The signed digest is built purely from slot bookkeeping fields, never from the contract identifier: `libstackerdb/src/libstackerdb.rs:159-166` (`auth_digest`) and the `sign`/`verify` methods at `libstackerdb/src/libstackerdb.rs:171-193`.
- `StackerDBTx::try_replace_chunk` fetches the `slot_validation.signer` for `(smart_contract, slot_desc.slot_id)` and calls `slot_desc.verify(&slot_validation.signer)` — nothing in this check involves `smart_contract` beyond the slot lookup: `stackslib/src/net/stackerdb/db.rs:400-437`.
- The P2P path is identical: `PeerNetwork::validate_received_chunk` resolves `addr = get_slot_signer(smart_contract_id, data.slot_id)` and then calls `slot_metadata.verify(&addr)`, again with no binding to `smart_contract_id` in the actual cryptographic check: `stackslib/src/net/stackerdb/mod.rs:679-697`.
- Because many StackerDB contracts assign slots by the same deterministic signer-set ordering (e.g. the paired `.signers-0-*` / `.signers-1-*` contracts for a reward cycle), it is common for the same principal to own the same `slot_id` across multiple distinct StackerDB replicas.

Consequence: if principal `P` legitimately signs and publishes a chunk `(slot_id=k, slot_version=v, data)` for contract `A` (where `P` owns slot `k` in `A`), and `P` also owns slot `k` in a different contract `B` (with a slot version in `B` that is currently lower than `v` and within `max_writes`), any third party who merely observes that chunk on the wire — no private key needed — can resubmit the *exact same bytes* to `B`'s `/v2/stackerdb/.../chunks` endpoint. `try_replace_chunk` for `B` will pass the `BadSlotSigner` check (`verify()` succeeds because the digest/signature never referenced `A` or `B`), pass the version/`max_writes` checks, and store attacker-relayed data for contract `B` as if `P` had authored it there.

### Impact Explanation
This breaks the intended equality "signature authenticates author *for the contract slot it was intended for*" and allows unauthenticated write of forged/cross-context data into a StackerDB slot, which is then propagated further via `handle_unsolicited_StackerDBPushChunk` / `StackerDBPushChunk` relay (`stackslib/src/net/stackerdb/mod.rs:742-861`) to the rest of the network as if it were the legitimate, freshly-authored payload for that contract. Depending on how the data in slot `k` is interpreted by consumers of that particular StackerDB contract (e.g. signer messages, miner messages), this can inject stale/foreign-context data as canonical current data for a different contract — an unauthorized/forged write and network-wide propagation of forged data.

### Likelihood Explanation
Exploitability requires: (1) a legitimate chunk observed on the wire (trivial — StackerDB chunks are broadcast/gossiped and are fetchable via the read API), and (2) the same principal owning the identical `slot_id` in two different StackerDB contracts with the target contract's stored version lower than the replayed version. Given the deterministic, index-based slot assignment scheme used for paired signer-set contracts within stacks-core, this precondition is plausible in real deployments, making this a realistic, low-cost (no key material needed) analog rather than a purely theoretical one.

### Recommendation
Include the target `QualifiedContractIdentifier` (and ideally a chain/network identifier) in `SlotMetadata::auth_digest()` so a signature cannot be replayed across different StackerDB contracts. This requires updating `sign`/`verify` call sites to pass the contract identifier and bump the wire-format/version if necessary.

### Proof of Concept
1. Set up two StackerDB contracts, `A` and `B`, where principal `P` is assigned `slot_id = 0` in both (achievable via the standard reward-cycle signer slot allocation, e.g. `.signers-0-N` / `.signers-1-N`).
2. `P` signs and POSTs a legitimate chunk to `A`: `StackerDBChunkData{slot_id:0, slot_version:5, sig, data}` — accepted by `try_replace_chunk` per `stackslib/src/net/stackerdb/db.rs:400-437`.
3. An observer captures this exact `StackerDBChunkData` (sig + data are unchanged) and POSTs it unmodified to `B`'s `/v2/stackerdb/<B-address>/<B-contract>/chunks` endpoint, where `B`'s stored version for slot 0 is `< 5` and `5 <= max_writes`.
4. `RPCPostStackerDBChunkRequestHandler::try_handle_request` (`stackslib/src/net/api/poststackerdbchunk.rs:163-268`) calls `tx.try_replace_chunk(&B, &chunk.get_slot_metadata(), &chunk.data)`; `slot_desc.verify(&slot_validation.signer)` succeeds because the digest never referenced contract `A` vs `B`, so the chunk is stored in `B` and relayed via `StackerDBPushChunk`, even though `P` never signed anything intending it for `B`.     /// Get the digest to sign that authenticates this chunk data and metadata
    fn auth_digest(&self) -> Sha512Trunc256Sum {
        let mut hasher = Sha512_256::new();
        hasher.update(self.slot_id.to_be_bytes());
        hasher.update(self.slot_version.to_be_bytes());
        hasher.update(self.data_hash.0);
        Sha512Trunc256Sum::from_hasher(hasher)
    }

    /// Sign this slot metadata, committing to slot_id, slot_version, and
    /// data_hash.  Sets self.signature to the signature.
    /// Fails if the underlying crypto library fails
    pub fn sign(&mut self, privkey: &StacksPrivateKey) -> Result<(), Error> {
        let auth_digest = self.auth_digest();
        let sig = privkey
            .sign(&auth_digest.0)
            .map_err(|se| Error::SigningError(se.to_string()))?;

        self.signature = sig;
        Ok(())
    }

    /// Verify that a given principal signed this chunk metadata.
    /// Note that the address version is ignored.
    pub fn verify(&self, principal: &StacksAddress) -> Result<bool, Error> {
        let sigh = self.auth_digest();
        let pubk = StacksPublicKey::recover_to_pubkey_without_validating_low_s(
            sigh.as_bytes(),
            &self.signature,
        )
        .map_err(|ve| Error::VerifyingError(ve.to_string()))?;

        let pubkh = Hash160::from_node_public_key(&pubk);
        Ok(pubkh == *principal.bytes())
    }
