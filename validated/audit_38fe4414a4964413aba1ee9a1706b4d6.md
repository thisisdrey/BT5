No vulnerability found for this question.

**Rationale (brief):** The report's bug class (predictable, sender/nonce-dependent contract address enabling front-run/back-run theft via reorg, mitigated by baking the deployer/owner/salt into a `create2` address) has no live analog in this nearcore tree:

- NEAR-implicit and ETH-implicit account IDs are derived purely from a public key the *future owner* controls (`derive_near_implicit_account_id`, `derive_eth_implicit_account_id`, [1](#0-0) ), so an attacker without the matching private key cannot "squat" and control the account, unlike a `create`-derived Vault address controlled by a deployer's nonce.
- Deterministic accounts (NEP-616) already implement exactly the recommended fix pattern: the account id is `'0s' + keccak256(borsh(state_init))`, i.e. a full-content-addressed salt (code + data), enforced by `validate_deterministic_state_init` checking `derived_id == receiver_id` ( [2](#0-1) ) and by `deploy_deterministic_account` only initializing an `uninit` account once ( [3](#0-2) ).
- The one closely analogous bug that did exist — a delegated-action (meta-tx) receiver-id mismatch that could let a `DeterministicStateInitAction` be smuggled to squat/redirect a different deterministic account than the outer transaction's receiver — was already identified and fixed via the `FixDelegatedDeterministicStateInit` protocol feature, with regression tests explicitly reproducing the pre-fix exploit and confirming the post-fix rejection ( [4](#0-3) , [5](#0-4) ). This is already remediated in-protocol, not an open finding.

No unpatched, reachable analog satisfying the required impact (theft/freezing of funds, replay, authorization escalation, state-root divergence) was found.

    action: &DeterministicStateInitAction,

    let storage_usage_config = &apply_state.config.fees.storage_usage_config;
    let account = match maybe_account {
        Some(account) => account,
        None => {

            // `nonexist` -> `uninit` account state transition
            // Create with zero balance now and check later how much of the
            // provided deposit is needed.

            maybe_account.insert(new_account)

            state_update,
            account,
            account_id,
            &action.state_init,
            result,

    env.deploy_global_contract(GlobalContractDeployMode::AccountId);

    let (_state_init_a, det_account_a) = env.new_deterministic_account_with_data(small());
    let (state_init_b, det_account_b) = env.new_deterministic_account_with_data(big());
    assert_ne!(det_account_a, det_account_b);

    // Deploy det_account_b and add a full-access key so it can act as meta_tx_sender.
    let user_signer = create_user_test_signer(&env.user_account());
    let storage_balance = env.balance_for_storage(state_init_b.clone());
    let deploy_tx = SignedTransaction::deterministic_state_init(
        env.next_nonce(),
        env.user_account(),
        det_account_b.clone(),
        &user_signer,
        env.get_tx_block_hash(),
        state_init_b.clone(),
        storage_balance,
    );
    env.run_tx(deploy_tx);

        &borsh::to_vec(&meta_tx_sender_signer.public_key()).unwrap(),
    );
    let add_key_args = serde_json::json!([
        { "batch_create": { "account_id": det_account_b.as_str() }, "id": 0 },
        {
            "action_add_key_with_full_access": {
                "promise_index": 0,
                "public_key": pk_base64,
                "nonce": 0
            },
            "id": 0,
            "return": true
        }
    ]);
    let add_key_tx = SignedTransaction::call(
        env.next_nonce(),
        env.user_account(),
        det_account_b.clone(),

        "call_promise".to_owned(),
        serde_json::to_vec(&add_key_args).unwrap(),
        Gas::from_teragas(300),
        env.get_tx_block_hash(),

    // In no protocol version can this ever be allowed to be executed successfully.
    let relayer = env.independent_account();

        deposit: Balance::ZERO,

    let delegate_nonce = env.next_nonce_for(&det_account_b);
    let delegate_action = DelegateAction {
        sender_id: det_account_b.clone(),
        receiver_id: det_account_a,
        actions: vec![NonDelegateAction::try_from(inner_action).unwrap()],
        nonce: delegate_nonce,
        max_block_height: 1_000_000,
        public_key: meta_tx_sender_signer.public_key(),
    };

        env.next_nonce(),
        relayer,
        det_account_b,
        &relayer_signer,
        vec![Action::Delegate(Box::new(signed_delegate_action))],
        env.get_tx_block_hash(),
    );
    env.try_execute_tx(tx)
}
