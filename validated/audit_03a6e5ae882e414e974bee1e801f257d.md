Unauthenticated `RecvError` packets let any network attacker unconditionally tear down active tunnels - (File: `outside.go`)

### Summary
The external report describes Tribe Turbo's `gib()` function: a privileged action that removes funds from a safe with no runtime conditions, guarded only by an off-chain, unenforced promise ("it will be behind a timelock"). The nebula analog is `handleRecvError` in `outside.go`, which performs the consequential, one-shot, irreversible action of destroying an established tunnel's state, gated only by a plaintext, unauthenticated protocol message and a weak address-equality check — not by any cryptographic proof tied to the peer's certificate.

### Finding Description
`RecvError` (`header.RecvError`) is dispatched in `readOutsidePackets` before any certificate, handshake, or AEAD verification is performed: [1](#0-0) 
```
case header.RecvError:
    f.handleRecvError(via.UdpAddr, h)
    return
```
`handleRecvError` then unconditionally destroys tunnel state as long as (a) the acceptRecvErrorConfig allows it for the given address class, (b) a `RemoteIndex` in the packet header matches a live hostinfo, and (c) the reported source `netip.AddrPort` happens to equal the hostinfo's currently recorded remote address: [2](#0-1) 
```
func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		...
		return
	}
	...
	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		...
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?", ...)
		return
	}

	f.closeTunnel(hostinfo)
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
```
None of these checks require the sender to hold a CA-signed certificate, complete a handshake, or produce any AEAD-authenticated proof of identity. `RemoteIndex` is a 32-bit value transmitted in cleartext on every prior packet and is therefore observable to any attacker who can see traffic (or who can brute-force/guess it, since it's only 32 bits). The `addr == hr` check is a UDP source-address comparison, which is spoofable on many network paths and, even when not spoofed, is satisfied automatically by an on-path or off-path attacker who has observed the real remote's `AddrPort` from earlier traffic. Once these two weak conditions are met, `closeTunnel`/`DeleteHostInfo` execute unconditionally — exactly the "privileged action with no limiting condition" pattern the report flags, except here the "privilege" is granted by a spoofable network property instead of governance/timelock.

This is consistent with the project's own history: CHANGELOG documents that recv_error handling has been a recurring source of security concern (spoofing false positives fixed in 1.5.0, and recv_error responses disabled outside the allowable counter window in 1.9.7), confirming this code path is a known-sensitive, previously-patched area rather than a purely theoretical concern. ### Impact Explanation
An attacker with no valid Nebula certificate — merely capable of sending UDP packets that reach the target's listen port, or of spoofing a source address that matches a legitimate remote's `AddrPort` — can force the target to tear down (`closeTunnel` + `DeleteHostInfo`) any live tunnel whose `RemoteIndex` they can observe or guess. This is a remote, unauthenticated denial-of-service against established tunnels: repeatedly issued, it can prevent two Nebula nodes from maintaining a stable tunnel, disrupting availability of the overlay network. It does not, by itself, decrypt traffic or forge data, but it is a concrete, unconditional state-poisoning/DoS primitive exercised by an unauthenticated party, directly paralleling the "privileged action, no condition" root cause in the report.

### Likelihood Explanation
Likelihood is limited by two factors that make this weaker than a full bypass: (1) the attacker must know or guess a live `RemoteIndex` (32-bit, sent in cleartext on the wire, so trivially known to any passive/off-path observer of existing traffic, and only moderately hard to blind-guess); and (2) the attacker's claimed source `AddrPort` must equal the value nebula currently has recorded as the peer's remote — satisfied automatically by any on-path attacker or anyone who has observed the peer's traffic and can spoof UDP source address/port (routine on unauthenticated UDP transport). `acceptRecvErrorConfig` (`send_recv_error`/accept equivalent) can reduce exposure but is opt-in/config-dependent, not a structural cryptographic control, matching the sponsor's original "it's mitigated by an external control, not by the code" pattern criticized in the report.

### Recommendation
Do not act on `RecvError` unless the packet can be tied to a cryptographically-authenticated source. Concretely: require `RecvError` handling to occur only over an already-authenticated relationship (e.g., require it be authenticated with the peer's current session key/AEAD tag, or ignore it entirely and rely solely on internal liveness/timeout detection), rather than trusting a bare `RemoteIndex` + UDP source-address match. At minimum, treat `RecvError` as advisory (e.g., trigger a re-handshake attempt) rather than as authorization to unilaterally destroy tunnel state.

### Proof of Concept
1. Attacker passively observes (or is on-path for) UDP traffic between nodes A and B, learning B's `RemoteIndex` value used by A (visible in the cleartext Nebula header of every packet) and B's current `netip.AddrPort`.
2. Attacker crafts a `header.RecvError` packet with that `RemoteIndex` and sends it to A, spoofing the source address/port to equal B's currently recorded remote (or simply sends from a vantage point that satisfies the equality if on-path).
3. `readOutsidePackets` routes it directly to `handleRecvError` with no handshake or AEAD check.
4. `QueryReverseIndex` finds A's live hostinfo for B; `hr == addr` passes; `closeTunnel(hostinfo)` and `DeleteHostInfo` execute, destroying the tunnel unconditionally — with the attacker never having presented a certificate or completed authentication.

func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
