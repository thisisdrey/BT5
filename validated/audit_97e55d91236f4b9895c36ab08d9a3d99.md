### Title
Debt floor + maxLiquidable bound conflict makes positions permanently unliquidatable via attacker-funded `repay` - ([File: contracts/Pool.sol])

### Summary
CVE-2020-23313 is a hard assertion on an internal counter that crashes the engine once pushed past a boundary — a reachable "impossible state" DoS. The Metronome analog is a pair of bounds checks in `Pool.liquidate` and `DebtToken.repay`/`_mint` that are individually sound but jointly unsatisfiable: once a position's remaining debt in USD lands in the interval `(0, debtFloorInUsd / (1 - maxLiquidable) ... ]` effectively below `debtFloorInUsd * debt` boundary conditions, every liquidation attempt reverts — `amountToRepay_.wadDiv(_debtTokenBalance) > maxLiquidable` reverts `AmountGreaterThanMaxLiquidable` for full repayment, while any partial repayment that leaves a non-zero remainder below `debtFloorInUsd` reverts `RemainingDebtIsLowerThanTheFloor`. An unprivileged attacker can push any victim into this state via `DebtToken.repay(onBehalfOf_ = victim, ...)`, permanently disabling liquidation of that position.

### Finding Description
`Pool.liquidate` enforces two bounds on `amountToRepay_` against the account's total debt `_debtTokenBalance`:
1. Upper bound: `amountToRepay_ / _debtTokenBalance <= maxLiquidable` (line 567). If `maxLiquidable < 100%`, the full debt can never be repaid in one call.
2. Lower bound on the remainder: if `debtFloorInUsd > 0`, then `_debtTokenBalance - amountToRepay_` must be either `0` or quote to `>= debtFloorInUsd` (lines 571-579).

These compose into a dead zone. When the account's total debt `_debtTokenBalance` satisfies `debtUsd(_debtTokenBalance) <= debtFloorInUsd`, then:
- repaying the whole debt is forbidden because `amountToRepay_ / _debtTokenBalance = 1 > maxLiquidable` (any `maxLiquidable < 1e18`),
- repaying any smaller amount leaves `0 < remainingDebtUsd < debtFloorInUsd` → `RemainingDebtIsLowerThanTheFloor`.

Every call to `liquidate` on such an account reverts unconditionally. Normally a user cannot reach this state themselves because `_mint` enforces `DebtLowerThanTheFloor` (line 583-588) and `repay` enforces `RemainingDebtIsLowerThanTheFloor` (line 442-451). However, `DebtToken.repay` accepts an arbitrary `onBehalfOf_` account — the payer `_msgSender` funds the repayment, not the debtor. An attacker can therefore repay a victim's debt down to exactly the floor boundary (`remaining debt USD == debtFloorInUsd`, which passes the floor check since the check is strict `<`), creating a position that no liquidator can ever touch.

### Impact Explanation
Once a victim's debt sits at or below the floor with `maxLiquidable < 100%`, the position is permanently unliquidatable. If the position is or becomes unhealthy (collateral price decline, or interest accrual pushing debt above collateral value), the protocol cannot recover it through `liquidate`, `NativeTokenGateway`, or `SmartFarmingManager.flashRepay` (whose final health check would also fail for the liquidator). The result is permanently frozen bad debt that accrues interest indefinitely — protocol insolvency and permanent freezing of the locked collateral's liquidation path. This is reachable by any EOA holding the synthetic token; no privileged role, oracle manipulation, or governance action is required beyond a configured `debtFloorInUsd > 0` and `maxLiquidable < 1e18` (both are live parameters on deployed pools).

### Likelihood Explanation
- `debtFloorInUsd` and `maxLiquidable` are governor-set but are ordinary deployed configuration values; the bug is the protocol's own invariant conflict, not a parameter-choice criticism.
- The attacker only needs to buy or mint the synthetic asset and call `repay(victim, amount)`. The cost is bounded by `victimDebt - debtFloorInUsd` worth of synth; the attacker can target the smallest debts in the system or freshly-created near-floor positions to minimize cost.
- The dead-zone logic follows directly from the arithmetic of the two checks — no race, no privileged cooperation.

### Recommendation
- In `Pool.liquidate`, allow full repayment (`amountToRepay_ == _debtTokenBalance`) to bypass the `maxLiquidable` cap when the position is liquidatable, or add an explicit escape: if `debtUsd(remaining) < debtFloorInUsd`, force/permit full repayment rather than reverting.
- Alternatively, treat `remaining < floor` as "wipe to zero" (forgive dust or seize proportionally), matching the `repayAll` semantics in `DebtToken` which already bypasses the floor by repaying the entire balance.
- Also consider rejecting `repay` calls that would leave the victim in the dead zone, since `repay` is attacker-fundable via `onBehalfOf_`.

### Proof of Concept
Hardhat sketch (fork/local network with a deployed `Pool`, `DebtToken`, `FeeProvider`/`Pool` configured with `debtFloorInUsd > 0` and `maxLiquidable < 1e18`):

```ts
// Setup: victim has a position with debt D, debtFloorInUsd = F, maxLiquidable = 0.5e18.
// Attacker (any EOA holding synth) repays victim down to exactly the floor:
const victimDebt = await msEthDebtToken.balanceOf(victim.address);
const floorInSynth = await masterOracle.quoteUsdToToken(msEth.address, debtFloorInUsd);
await msEth.connect(attacker).approve(msEthDebtToken.address, MaxUint256);
// repay victim's debt so remaining == floor (passes the strict < check)
await msEthDebtToken.connect(attacker).repay(victim.address, victimDebt.sub(floorInSynth));

// Make position unhealthy (price drop, or interest accrual over time):
await masterOracle.updatePrice(collateral.address, lowerPrice);
expect((await pool.debtPositionOf(victim.address))._isHealthy).false;

// Any liquidation attempt reverts:
//  - full repay:
await expect(pool.liquidate(msEth.address, victim.address, floorInSynth, msdMET.address))
  .revertedWithCustomError(pool, 'AmountGreaterThanMaxLiquidable');
//  - partial repay:
await expect(pool.liquidate(msEth.address, victim.address, floorInSynth.div(2), msdMET.address))
  .revertedWithCustomError(pool, 'RemainingDebtIsLowerThanTheFloor');
// Position is permanently unliquidatable -> bad debt accrues forever.
```

Key code paths: `Pool.liquidate` max-liquidable and floor checks ( [1](#0-0) ), `DebtToken.repay` allowing third-party `onBehalfOf_` funded by the payer ( [2](#0-1) ), and the `_mint` floor check that prevents users — but not attacker-funded repayers — from entering the dead zone directly ( [3](#0-2) ).

        address onBehalfOf_,
        uint256 amount_
    )
        external
        override
        whenNotShutdown
        nonReentrant
        onlyIfSyntheticTokenExists
        returns (uint256 _repaid, uint256 _fee)
    {
        if (amount_ == 0) revert AmountIsZero();

        accrueInterest();

        address _msgSender = _msgSender();
        IPool _pool = pool;
        ISyntheticToken _syntheticToken = syntheticToken;

        (_repaid, _fee) = quoteRepayOut(amount_);
        if (_fee > 0) {
            _syntheticToken.seize(_msgSender, _pool.feeCollector(), _fee);
        }

        uint256 _debtFloorInUsd = _pool.debtFloorInUsd();
        if (_debtFloorInUsd > 0) {
            uint256 _newDebtInUsd = _pool.masterOracle().quoteTokenToUsd(
                address(_syntheticToken),
                balanceOf(onBehalfOf_) - _repaid
            );
            if (_newDebtInUsd > 0 && _newDebtInUsd < _debtFloorInUsd) {
                revert RemainingDebtIsLowerThanTheFloor();
            }
        }

        _syntheticToken.burn(_msgSender, _repaid);
        _burn(onBehalfOf_, _repaid);

        emit DebtRepaid(_msgSender, onBehalfOf_, amount_, _repaid, _fee);
    }
