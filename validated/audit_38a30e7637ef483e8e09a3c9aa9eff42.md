### Title
Signer's HTTP event-listener accepts unauthenticated pushed events (`StackerDBChunksEvent`, `BlockValidateResponse`, `BurnBlockEvent`, `StacksBlockEvent`) from any TCP client - (File: `libsigner/src/events.rs`)

### Summary
`SignerEventReceiver::next_event` (`libsigner/src/events.rs`) is the sole gate between the network socket the signer listens on and the signer's decision-making runloop. It routes any HTTP POST to `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block`, or `/shutdown` straight into event construction and forwarding, with **no verification that the request actually originated from the paired, trusted `stacks-node`**. This is the same trust-boundary failure as the flashloan report: a component built to be driven only by one specific, trusted caller instead accepts the triggering call from anyone who can reach the socket.

### Finding Description
The signer process binds an HTTP server (`endpoint`, e.g. `0.0.0.0:30000` per `sample/conf/signer/mainnet-signer-conf.toml`) that the paired `stacks-node`'s event-observer is supposed to be the exclusive caller of. Looking at `bind`/`next_event`: [1](#0-0) 

`next_event` only inspects `request.url()` and `request.method()` to decide which typed event to construct (`process_event::<T, StackerDBChunksEvent>`, `BlockValidateResponse`, `BurnBlockEvent`, `StacksBlockEvent`) and then hands the result straight to `forward_event`, which pushes it into the channel consumed by the signer's runloop: [2](#0-1) 

Nothing in this path — nor in the low-level HTTP decoder `decode_http_request` in `libsigner/src/http.rs` — checks a shared secret, token, or peer identity before the event is accepted and forwarded: [3](#0-2) 

By contrast, the *node-side* RPC surface that the signer calls out to (block-proposal endpoint) is explicitly protected by a shared `auth_token`/`auth_password`, as documented in the sample configs: [4](#0-3) [5](#0-4) 

That `auth_token`/`auth_password` protects the direction "signer → node", but the direction "node → signer" (the event push endpoint implemented in `libsigner/src/events.rs`) has no equivalent check at the transport layer. Any TCP peer that can reach the bound `endpoint` (which the sample configs default to `0.0.0.0:30000`, i.e. all interfaces) can POST a forged `StackerDBChunksEvent`, `BlockValidateResponse`, `BurnBlockEvent`, or `StacksBlockEvent` and have it treated exactly as if the legitimate node had sent it — this is precisely the "the callback trusts the caller instead of the intended trusted party" pattern in the reference report, mapped onto the "auth-gate that fails open" bug class from the rules.

Downstream, `TryFrom<StackerDBChunksEvent> for SignerEvent<T>` does re-derive signer identity from the chunk's own embedded signature (`chunk.recover_pk()` / signer-message validation), so forged StackerDB chunk contents are still filtered by signature there: [6](#0-5) 

However, `SignerEvent::BlockValidationResponse`, `SignerEvent::NewBurnBlock`, and `SignerEvent::NewBlock` carry **no equivalent signer-key authentication inside the payload itself** — they are trusted purely because they arrived on this HTTP endpoint. An attacker who can reach the endpoint can inject a forged `BlockValidateResponse` or `NewBurnBlock`/`NewBlock` event that the signer's runloop will process as if the connected `stacks-node` produced it.

### Impact Explanation
This lets a remote, unauthenticated party feed forged control-plane events directly into a signer process's decision pipeline over the network (if the operator's `endpoint` is reachable beyond localhost, which the shipped sample config for mainnet explicitly sets to `0.0.0.0:30000`). Per the rules, this maps to "unauthenticated/unauthorized write to state" of the signer's internal event stream and can steer it away from validated data. I cannot fully trace inside the excluded signer-decision-logic module how far a forged `BlockValidationResponse`/`NewBurnBlock` propagates (that internal logic is explicitly out of scope for this analysis), so I am not asserting a downstream consensus-level break — only that the entry point itself performs no authentication, which is the direct analog to the reported bug class.

### Likelihood Explanation
Exploitability depends entirely on network exposure of the signer's `endpoint`. The reference/sample configuration binds it to `0.0.0.0`, and nothing in `libsigner/src/events.rs` or `libsigner/src/http.rs` enforces localhost-only or authenticated access at the code level — the security boundary is left entirely to deployment-level firewalling, which is not a code guarantee. Given the shipped defaults, this is a real, low-effort remote reachability issue whenever an operator does not manually restrict access to the port.

### Recommendation
Require the same shared-secret/token mechanism used for the node→signer RPC direction (`auth_token`/`auth_password`) to also gate the signer's own event-receiving HTTP endpoint in `SignerEventReceiver::next_event` (e.g., verify a header/token on every POST before calling `process_event`), and/or bind the receiver to loopback by default, rejecting non-local connections unless explicitly authenticated.

### Proof of Concept
1. Start a `stacks-signer` configured per `sample/conf/signer/mainnet-signer-conf.toml` (`endpoint = "0.0.0.0:30000"`).
2. From a separate, unrelated host, `POST` a crafted JSON body matching `BurnBlockEvent` (or `BlockValidateResponse`) to `http://<signer-ip>:30000/new_burn_block` (or `/proposal_response`), mirroring the request format used in `libsigner/src/tests/mod.rs`'s `test_simple_signer`: [7](#0-6) 
3. Because `next_event` (`libsigner/src/events.rs:413-459`) performs no authentication check on the incoming HTTP request, the forged event is accepted, parsed, and forwarded to the signer runloop via `forward_event`, indistinguishable from a legitimate push by the trusted `stacks-node`.

    /// Wait for the node to post something, and then return it.
    /// Errors are recoverable -- the caller should call this method again even if it returns an
    /// error.
    fn next_event(&mut self) -> Result<SignerEvent<T>, EventError> {
        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)
            } else if request.url() == "/new_block" {
                process_event::<T, StacksBlockEvent>(request)
            } else {
                let url = request.url().to_string();
                debug!(
                    "[{:?}] next_event got request with unexpected url {}, return OK so other side doesn't keep sending this",
                    event_receiver.local_addr,
                    url
                );
                ack_dispatcher(request);
                Err(EventError::UnrecognizedEvent(url))
            }
        })?
    }

    /// Forward an event
    /// Return true on success; false on error.
    /// Returning false terminates the event receiver.
    fn forward_event(&mut self, ev: SignerEvent<T>) -> bool {
        if self.out_channels.is_empty() {
            // nothing to do
            error!("No channels connected to event receiver");
            false
        } else if self.out_channels.len() == 1 {
            // avoid a clone
            if let Err(e) = self.out_channels[0].send(ev) {
                error!("Failed to send to signer runloop: {:?}", &e);
                return false;
            }
            true
        } else {
            for (i, out_channel) in self.out_channels.iter().enumerate() {
                if let Err(e) = out_channel.send(ev.clone()) {
                    error!("Failed to send to signer runloop #{}: {:?}", i, &e);
                    return false;
                }
            }
            true
        }
    }

pub fn decode_http_request(payload: &[u8]) -> Result<SignerHttpRequest, EventError> {
    // realistically, there won't be more than 32 headers
    let mut headers_buf = [httparse::EMPTY_HEADER; MAX_HTTP_HEADERS];
    let mut req = httparse::Request::new(&mut headers_buf);
    let (verb, path, headers, body_offset) =
        if let Ok(httparse::Status::Complete(body_offset)) = req.parse(payload) {
            // version must be valid
            match req
                .version
                .ok_or(EventError::MalformedRequest("No HTTP version".to_string()))?
            {
                0 => {}
                1 => {}
                _ => {
                    return Err(EventError::MalformedRequest(
                        "Invalid HTTP version".to_string(),
                    ));
                }
            };

            let verb = req
                .method
                .ok_or(EventError::MalformedRequest("No HTTP method".to_string()))?
                .to_string();
            let path = req
                .path
                .ok_or(EventError::MalformedRequest("No HTTP path".to_string()))?
                .to_string();

            let mut headers: HashMap<String, String> = HashMap::new();
            for i in 0..req.headers.len() {
                let value = String::from_utf8(req.headers[i].value.to_vec()).map_err(|_e| {
                    EventError::MalformedRequest("Invalid HTTP header value: not utf-8".to_string())
                })?;
                if !value.is_ascii() {
                    return Err(EventError::MalformedRequest(
                        "Invalid HTTP request: header value is not ASCII-US".to_string(),
                    ));
                }
                if value.len() > MAX_HTTP_HEADER_LEN {
                    return Err(EventError::MalformedRequest(
                        "Invalid HTTP request: header value is too big".to_string(),
                    ));
                }

                let key = req.headers[i].name.to_string().to_lowercase();
                if headers.get(&key).is_some() {
                    return Err(EventError::MalformedRequest(format!(
                        "Invalid HTTP request: duplicate header \"{key}\""
                    )));
                }
                headers.insert(key, value);
            }
            (verb, path, headers, body_offset)
        } else {
            return Err(EventError::Deserialize(
                "Failed to decode HTTP headers".to_string(),
            ));
        };

    Ok(SignerHttpRequest::new(verb, path, headers, body_offset))
}
