#No Vulnerability found for this question.

**Analysis:** The described "asymmetry" is standard, deterministic gas metering behavior, not a security bug. In `set_impl` [1](#0-0) , `pay_base(write_register_base)` and `pay_per(write_register_byte, data_len)` are charged before `check_set_register` [2](#0-1)  can fail on the `max_number_registers` boundary — this is the well-known and explicitly documented pattern throughout the entire host-function interface: gas is charged for work performed up to the point of failure (`base` cost, memory reads, etc. are all charged before their respective checks can abort execution), and this is true for essentially every fallible host call in `logic.rs`, not unique to registers.

This is fully deterministic: every validator executes the identical WASM contract with the identical gas counter logic, so every node computes exactly the same burnt gas for the failing call and exactly the same burnt gas for any retry. There is no cross-node divergence — the "asymmetry" is a property of the (documented, protocol-frozen) function behavior, not an implementation-dependent one, since gas accounting is pure/deterministic state threaded through `GasCounter`. A contract paying gas twice for two separate host calls (one failing, one succeeding) is expected economics of gas metering, not a double-charge exploit; the attacker only spends their own attached gas and cannot cause loss or freezing of funds belonging to anyone else, cannot cause state-root divergence, and cannot halt a shard.

The referenced code comment itself states this behavior is "now part of the protocol" by design [3](#0-2) , meaning it is an accepted, consensus-safe quirk rather than an exploitable divergence. This finding does not meet the required bar of concrete loss/freezing of funds, consensus divergence, or shard halt, and is rejected as a speculative resource-hygiene / non-reachable-impact claim per the rules.

    fn set_impl<T>(
        &mut self,
        gas_counter: &mut GasCounter,
        config: &LimitConfig,
        register_id: u64,
        data: T,
        charge_bytes_gas: bool,
    ) -> Result<()>
    where
        T: Into<Rc<[u8]>> + AsRef<[u8]>,
    {
        let data_len =
            u64::try_from(data.as_ref().len()).map_err(|_| HostError::MemoryAccessViolation)?;
        gas_counter.pay_base(write_register_base)?;
        if charge_bytes_gas {
            gas_counter.pay_per(write_register_byte, data_len)?;
        }
        let entry = self.check_set_register(config, register_id, data_len)?;
        let data = data.into();
        match entry {
            Entry::Occupied(mut entry) => {
                entry.insert(data);
            }
            Entry::Vacant(entry) => {
                entry.insert(data);
            }
        };
        Ok(())
    }

        &'a mut self,
        config: &LimitConfig,
        register_id: u64,
        data_len: u64,

        if data_len > config.max_register_size {
            return Err(HostError::MemoryAccessViolation.into());

        // the protocol so we can’t change it.
