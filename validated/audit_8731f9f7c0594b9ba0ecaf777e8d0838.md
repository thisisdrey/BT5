### Title
Protocol fee bypass on NEP-245/IMT `TokenDiff` intents via 1-unit delta quantization - ([File: contracts/defuse/core/src/intents/token_diff.rs])

### Summary
`TokenDiff::execute_intent` computes the fee for a negative delta on a per-intent basis using `Self::token_fee(token_id, amount, protocol_fee)`, where for `Nep245`/`Imt` tokens the fee is forced to `Pips::ZERO` whenever the intent's own `|delta| <= 1`. Because the `Verifier` (via `TransferMatcher`) only checks that, per token, total withdrawals equal total deposits across the whole batch — it performs no batch-level fee re-aggregation — an unprivileged signer can split a large NEP-245/IMT trade into many unit-sized `TokenDiff` intents to make every single fee computation resolve to zero while the aggregate transferred amount is unchanged.

### Finding Description
The intended binding is:
`fee_collector_balance_after_batch - fee_collector_balance_before_batch == Pips::fee_ceil(fee, total_negative_delta_of_T_in_batch)`

In `TokenDiff::execute_intent` [1](#0-0) , for each `(token_id, delta)` pair *within a single intent*, if `delta < 0` the fee is computed as:
```
let amount = delta.unsigned_abs();
let fee = Self::token_fee(token_id, amount, protocol_fee).fee_ceil(amount);
```
`token_fee` explicitly zeroes the fee for `Nep245`/`Imt` tokens when `amount <= 1`: [2](#0-1) 

This `amount` is scoped to the *individual intent's own delta*, not to the cumulative negative delta of that token across the `MultiPayload` batch. The batch-level custody check lives entirely in `TransferMatcher`, which only nets deposits vs. withdrawals per `(token_id, owner_id)` to produce `Transfers` or an `InvariantViolated::UnmatchedDeltas` error — it has no notion of "fee owed" and performs no aggregation of the per-intent fee computations: [3](#0-2) [4](#0-3) 

Each withdrawal (full `|delta|`) and each deposit (fee to `fee_collector`, remainder to counterparty) are recorded via `internal_sub_balance`/`internal_add_balance`, which forward straight into `TransferMatcher::withdraw`/`deposit`: [5](#0-4) 

Because `execute_signed_intents` processes each `MultiPayload`/`Intent`/`TokenDiff` independently with `intents.execute_intent(&signer_id, self, hash)` [6](#0-5) , and the batch-level check `self.state.finalize()` only validates that deposits and withdrawals net out per token [7](#0-6) , splitting one large `TokenDiff` (delta = -Q) into Q intents each with delta = -1 leaves the `TransferMatcher` invariant fully satisfied (total withdrawn still equals total deposited to the counterparty) while every one of the Q per-intent fee computations evaluates to `Pips::ZERO`, so `fees_collected` is empty and `fee_collector` never receives any deposit for that token.

Attack payload: attacker (with a second self-controlled account acting as counterparty, or any willing counterparty) signs Q `TokenDiff` intents in one `MultiPayload`/`execute_intents` batch, each with `diff = {T: -1, U: +k}` for a NEP-245/IMT token `T`, where the matching counterparty intents supply `{T: +1, U: -k}`. The aggregate effect equals a single swap of `Q` units of `T`, but because `amount == 1` in every individual intent, `token_fee` returns `Pips::ZERO` every time, so no fee is ever collected, versus `Pips::fee_ceil(fee, Q)` that a single-intent trade of the same aggregate size would owe.

None of the existing guards (`MultiPayload::verify`, nonce/salt checks, `TransferMatcher::finalize`) address this because they check signature/replay validity and token-supply/custody balance, not fee correctness; the invariant `TransferMatcher` enforces is agnostic to how much fee "should" have been taken.

### Impact Explanation
This is a systemic protocol fee bypass on the entire NEP-245/IMT product line: any swap involving an NEP-245 or IMT-typed asset can be fully de-feed by quantizing the trade into unit legs, at the cost of extra intents in the same batch (no extra signatures, no extra gas-limited operations beyond intent count). `fee_collector` permanently under-collects relative to the specified `fee` rate for all such trades, which the rules explicitly classify as Critical ("protocol fees bypassed or over-collected"). The bypass is repeatable per token, per batch, and across all accounts and NEP-245/IMT tokens without bound.

### Likelihood Explanation
The attacker needs only: a NEP-245/IMT balance (their own), a counterparty willing to take the other leg of the trade (which can be a second account the same attacker controls, since no privileged role is required), and the ability to submit `MultiPayload` batches with many `TokenDiff` intents, all of which are available to any unprivileged signer as defined by the attacker profile. The only cost is a larger batch (more intents to sign/submit), which is linear in the quantization granularity and has no gas-limit-related exclusions relevant here since the finding itself is not about resource exhaustion but about the fee-bypass outcome. This is fully feasible and repeatable.

### Recommendation
Compute and apply the NEP-245/IMT fee threshold (`amount > 1`) against the cumulative negative delta for a given `TokenId` across the entire batch (or at minimum across the entire signer's aggregated diff), rather than per individual `TokenDiff` intent's own local delta. This requires either an aggregation pass before/at `finalize()` that recomputes fees from total negative deltas per token, or restructuring `token_fee` to be evaluated against `TransferMatcher`-level aggregated withdrawal amounts instead of per-intent amounts.

    pub fn finalize(self) -> Result<Transfers, InvariantViolated> {
        let mut transfers = Transfers::default();
        let mut deltas = TokenDeltas::default();
        for (token_id, transfer_matcher) in self.0 {
            if let Err(unmatched) = transfer_matcher.finalize_into(&token_id, &mut transfers)
                && (unmatched == 0 || deltas.apply_delta(token_id, unmatched).is_none())
            {
                return Err(InvariantViolated::Overflow);
            }

        if !deltas.is_empty() {
            return Err(InvariantViolated::UnmatchedDeltas {
                unmatched_deltas: deltas,
            });
        }

    }

    // If returned delta is zero, then overflow happened
    pub fn finalize_into(self, token_id: &TokenId, transfers: &mut Transfers) -> Result<(), i128> {
        // sort deposits and withdrawals in descending order
        let [mut deposits, mut withdrawals] = [self.deposits, self.withdrawals].map(|amounts| {
            let mut amounts: Vec<_> = amounts.into_iter().collect();
            amounts.sort_unstable_by_key(|(_, amount)| Reverse(*amount));
            amounts.into_iter()
        });

        // take first sender and receiver
        let (mut deposit, mut withdraw) = (deposits.next(), withdrawals.next());

        // as long as there is both: sender and receiver
        while let Some(((sender, send), (receiver, receive))) =
            withdraw.as_mut().zip(deposit.as_mut())
        {
            // get min amount and transfer
            let transfer = (*send).min(*receive);
            transfers
                .transfer(sender.clone(), receiver.clone(), token_id.clone(), transfer)
                // no error can happen since we add only one transfer for each
                // combination of (sender, receiver, token_id)
                .unwrap_or_else(|| unreachable!());

            // subtract amount from sender and receiver
            *send = send.saturating_sub(transfer);
            *receive = receive.saturating_sub(transfer);

            if *send == 0 {
                // select next sender
                withdraw = withdrawals.next();
            }
            if *receive == 0 {
                // select next receiver
                deposit = deposits.next();
            }
        }

        // only sender(s) left
        if let Some((_, send)) = withdraw {
            return Err(withdrawals
                .try_fold(send, |total, (_, s)| total.checked_add(s))
                .and_then(|total| i128::try_from(total).ok())
                .and_then(i128::checked_neg)
                .unwrap_or_default());
        }
        // only receiver(s) left
        if let Some((_, receive)) = deposit {
            return Err(deposits
                .try_fold(receive, |total, (_, r)| total.checked_add(r))
                .and_then(|total| i128::try_from(total).ok())
                .unwrap_or_default());
        }

        Ok(())
    }
