### Title
Incomplete `on_withdraw` notification in `do_withdraw_unbonded` leaves nomination-pools' `TotalValueLocked` permanently stale when the ledger is killed - (File: `substrate/frame/staking/src/pallet/impls.rs`, `substrate/frame/staking-async/src/pallet/impls.rs`)

### Summary
`TotalValueLocked` in `pallet-nomination-pools` is a cached, derived aggregate of a pool's staked balance, kept in sync purely through the `OnStakingUpdate::on_withdraw` hook fired from `pallet-staking`'s `do_withdraw_unbonded`. The hook is invoked with `value = old_total - new_total`, computed only from the balance removed by `consolidate_unlocked` (matured unlocking chunks). When the same call also triggers `kill_stash` because the remaining `active` balance falls below the existential deposit, that remaining balance is silently destroyed (ledger deleted, lock removed) without ever being included in the `on_withdraw` notification. The cached `TotalValueLocked` therefore never accounts for that residual amount and remains stale after the withdrawal — the same broken-invariant pattern as the reported `perp_withdraw`/`change_edge_px` bug: a state-mutating withdrawal path exits without propagating the balance change to the dependent cached value.

### Finding Description
`do_withdraw_unbonded` (both `substrate/frame/staking/src/pallet/impls.rs:193-233` and the staking-async analog `substrate/frame/staking-async/src/pallet/impls.rs:259-317`) works as follows: [1](#0-0) 

1. `old_total` is captured before `consolidate_unlocked`.
2. `ledger.consolidate_unlocked(current_era)` removes only matured `unlocking` chunks and reduces `total` accordingly; `new_total` is the post-consolidation total (which, if `unlocking` is now empty, equals `ledger.active`).
3. If `unlocking` is empty and `active < ExistentialDeposit` (dust) or zero, `Self::kill_stash(...)` is called, which fully deletes the ledger and removes the stash's stake lock via `StakingLedger::kill`: [2](#0-1) 

4. The `on_withdraw` notification fires unconditionally based on `new_total < old_total`, using `value = old_total - new_total` — i.e., only the portion consumed by `consolidate_unlocked`:

```
if new_total < old_total {
    let value = old_total.defensive_saturating_sub(new_total);
    Self::deposit_event(Event::<T>::Withdrawn { stash, amount: value });
    T::EventListeners::on_withdraw(controller, value);
}
```

The dust `active` amount that is wiped out by `kill_stash` (i.e., the delta from `new_total` down to `0`) is never passed into `on_withdraw`. `pallet-nomination-pools` relies exclusively on this hook (introduced by the fix documented in `prdoc/1.8.0/pr_3052.prdoc`, implemented at `substrate/frame/nomination-pools/src/lib.rs`) to decrement `TotalValueLocked`: [3](#0-2) 

Because `TotalValueLocked` is a bare `StorageValue` with no independent reconciliation against the actual staking ledger once the ledger is deleted, the missing decrement for the dust portion is permanent — there is no later call that can "catch up" the difference, since the underlying ledger no longer exists to be compared against. This mirrors exactly the reported bug class: a withdrawal-type call path mutates the true underlying balance (the stash's stake, `info.funds` analog) but fails to propagate that mutation into the cached/derived value used by downstream consumers (`TotalValueLocked`, the `edge_px`/liquidation-tree analog).

### Impact Explanation
`TotalValueLocked` is a user- and protocol-facing accounting invariant documented as an upper bound: "This might be lower but never higher than the sum of `total_balance` of all `PoolMembers`" (`substrate/frame/nomination-pools/src/lib.rs:1745-1750`). A stale, inflated `TotalValueLocked` breaks this invariant and any pallet or off-chain logic (fee calculations, pool health checks, weighting decisions, or future features gating on TVL) that treats `TotalValueLocked` as ground truth for the pool's actually-staked funds will operate on an incorrect value. In aggregate over many pools/unbonding cycles that end in dust-triggered `kill_stash`, the drift is systemic rather than a one-off rounding error, since it accrues every time a bonded pool account (or any staker) is killed with a non-zero pre-kill `active` remainder that was previously counted in TVL.

### Likelihood Explanation
This path executes on the ordinary user-facing `withdraw_unbonded` extrinsic, requires no privileged origin, and is reachable any time a nominator/pool account unbonds an amount that brings its active balance below the existential deposit while no unlocking chunks remain pending — a common real-world pattern (e.g., a member fully unbonding from a pool such that the pool-bonded-account or member's underlying stash ends up dusted). No malicious peer, validator, or governance action is required; it is a deterministic consequence of the accounting arithmetic in `do_withdraw_unbonded`.

### Recommendation
In `do_withdraw_unbonded`, when `kill_stash` is invoked, the notification value passed to `on_withdraw` (and the `Withdrawn` event) should account for the *entire* remaining `total` being removed, not just the delta consumed by `consolidate_unlocked`. Concretely, compute the notified withdrawal amount as `old_total - 0` (i.e., the full pre-withdrawal total) whenever the kill branch is taken, instead of `old_total - new_total`, ensuring `on_withdraw` (and therefore `TotalValueLocked`) is decremented by the complete amount actually released/unlocked in that call.

### Proof of Concept
1. Create a nomination pool and bond a member such that the pool's bonded stash ends up with `active` balance exactly at, or reducible to below, `ExistentialDeposit` after a full unbond (e.g., pool bonded account has `active = ED - 1` post-unbond, with zero remaining `unlocking` chunks after era advancement).
2. Record `TotalValueLocked::<T>::get()` before calling `withdraw_unbonded`.
3. Call `Staking::withdraw_unbonded` (or the pool's `withdraw_unbonded`/`pool_withdraw_unbonded` which internally calls into `do_withdraw_unbonded`) once the unlocking chunk has matured and `active` is below ED with no unlocking chunks left.
4. Observe: `kill_stash` executes, deleting the ledger and clearing the lock for the full `new_total` (equal to the residual `active` dust), but the `Withdrawn` event/`on_withdraw` call only reports `old_total - new_total` (the consolidated chunk amount), omitting the dust `new_total` itself.
5. Compare `TotalValueLocked::<T>::get()` after the call: it will be higher than the pool's actual remaining staked balance (which is now zero, since the stash was killed), by exactly the size of the unreported dust — reproducing the "stale cached derived value after withdraw" condition described in the external report.

	pub(super) fn do_withdraw_unbonded(
		controller: &T::AccountId,
		num_slashing_spans: u32,
	) -> Result<Weight, DispatchError> {
		let mut ledger = Self::ledger(Controller(controller.clone()))?;
		let (stash, old_total) = (ledger.stash.clone(), ledger.total);
		if let Some(current_era) = CurrentEra::<T>::get() {
			ledger = ledger.consolidate_unlocked(current_era)
		}
		let new_total = ledger.total;

		let ed = asset::existential_deposit::<T>();
		let used_weight =
			if ledger.unlocking.is_empty() && (ledger.active < ed || ledger.active.is_zero()) {
				// This account must have called `unbond()` with some value that caused the active
				// portion to fall below existential deposit + will have no more unlocking chunks
				// left. We can now safely remove all staking-related information.
				Self::kill_stash(&ledger.stash, num_slashing_spans)?;

				T::WeightInfo::withdraw_unbonded_kill(num_slashing_spans)
			} else {
				// This was the consequence of a partial unbond. just update the ledger and move on.
				ledger.update()?;

				// This is only an update, so we use less overall weight.
				T::WeightInfo::withdraw_unbonded_update(num_slashing_spans)
			};

		// `old_total` should never be less than the new total because
		// `consolidate_unlocked` strictly subtracts balance.
		if new_total < old_total {
			// Already checked that this won't overflow by entry condition.
			let value = old_total.defensive_saturating_sub(new_total);
			Self::deposit_event(Event::<T>::Withdrawn { stash, amount: value });

			// notify listeners.
			T::EventListeners::on_withdraw(controller, value);
		}

		Ok(used_weight)
	}

	/// Clears all data related to a staking ledger and its bond in both [`Ledger`] and [`Bonded`]
	/// storage items and updates the stash staking lock.
	pub(crate) fn kill(stash: &T::AccountId) -> DispatchResult {
		let controller = <Bonded<T>>::get(stash).ok_or(Error::<T>::NotStash)?;

		<Ledger<T>>::get(&controller).ok_or(Error::<T>::NotController).map(|ledger| {
			Ledger::<T>::remove(controller);
			<Bonded<T>>::remove(&stash);
			<Payee<T>>::remove(&stash);

			// kill virtual staker if it exists.
			if <VirtualStakers<T>>::take(&ledger.stash).is_none() {
				// if not virtual staker, clear locks.
				asset::kill_stake::<T>(&ledger.stash)?;
			}

			Ok(())
		})?
	}
