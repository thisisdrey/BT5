### Title
Stale per-batch conntrack cache lets already-established flows bypass firewall rule-reload revalidation - (File: `firewall/cache.go`, `firewall.go`)

### Summary
Nebula's firewall implements a fast-path "conntrack" cache used to avoid the full firewall rule evaluation on every packet in a flow. When rules are reloaded (SIGHUP), the authoritative conntrack table is *not* dropped — instead, entries are revalidated lazily by comparing `c.rulesVersion` against the current `f.rulesVersion` the next time `inConns` is called [1](#0-0) . This lazy revalidation is the correct mechanism when it runs. However, `inConns` first consults a per-goroutine `localCache` (`firewall.ConntrackCache`) and returns `true` immediately on a hit, **before** ever touching `conntrack.Conns[fp]` or checking `c.rulesVersion` against the current rule version [2](#0-1) .

### Finding Description
The `localCache` is populated once a flow passes the full `inConns` logic, and it is only invalidated on a time-based ticker (`ConntrackCacheTicker`), completely independent of firewall rule reloads [3](#0-2) . This mirrors the InitCapital bug class precisely: an administrator performs an action meant to immediately restrict a previously-allowed operation (pausing `collateralize`/rule reload), but a secondary, unaccounted data path (direct LP-token donation / the per-batch `localCache`) continues to grant the previously-authorized state without re-checking the updated authoritative source of truth.

Concretely:
- `f.rulesVersion` is bumped when firewall rules are reloaded, and `FirewallConntrack.Conns` entries are meant to be re-validated against the new ruleset the next time they are consulted (`inConns`, lines 527-560) [4](#0-3) .
- But `inConns` checks `localCache` first and returns `true` without ever loading `conntrack.Conns[fp]`, so the `rulesVersion` comparison and re-match against `f.InRules`/`f.OutRules` is skipped entirely for cached hits [5](#0-4) .
- The `ConntrackCache` reset is driven solely by `ConntrackCacheTicker`'s time-based `cacheTick`, with no hook into rule reload / `rulesVersion` changes [6](#0-5) .

As a result, for the duration of the cache tick interval, packets belonging to a flow that was already cached continue to be forwarded even though the operator just pushed a rule change intended to immediately close that flow — the enforcement decision is effectively stuck on stale internal state instead of being re-derived from the authoritative (just-updated) rule set, exactly as the report describes wLp collateral being computed from a balance that bypasses the intended internal-accounting gate.

### Impact Explanation
An operator relying on `nebula-cert`/config reload to immediately cut off a previously allowed flow (e.g., after detecting misuse, revoking access via new firewall rules) may have that expectation violated: traffic on already-cached tuples keeps flowing until the local cache ticks over, independent of the new `rulesVersion`. This is a firewall-enforcement bypass of admin-directed policy changes — the same "pause is bypassable" class of bug flagged as Medium severity in the source report, since the impact is limited to a window of continued (should-be-blocked) traffic rather than full compromise.

### Likelihood Explanation
This path is reachable by any already-established peer that keeps sending on a matching 4-tuple through the normal in/out packet path (`inside.go`/`outside.go` call `Drop` with a non-nil `localCache` on the hot path) — no malicious peer/cert forgery is required, and the condition (rule reload while flows are cached) is a routine operational action (SIGHUP/config reload), making this readily triggerable in normal operation.

### Recommendation
Tie `ConntrackCache` invalidation to `rulesVersion` changes (not just a time ticker), or have `inConns` validate `rulesVersion` before/instead of trusting a `localCache` hit, so that a rule reload immediately and deterministically revalidates all tracked flows rather than relying on a stale per-batch cache.

### Proof of Concept
1. Establish a firewall rule allowing UDP flow `A`; send traffic so the flow gets recorded in `Conntrack.Conns` and, within the same packet-processing batch/routine, in `localCache` (`firewall.ConntrackCache`).
2. Reload nebula config with a rule set that would now reject flow `A` (bumping `f.rulesVersion`).
3. Continue sending packets for flow `A` within the same cache-tick window (`net.conntrack_cache_timeout`): `inConns` hits `localCache[fp]` and returns `true` immediately (`firewall.go` lines 505-511), so `Drop` never calls `table.match` against the new rules and never checks `c.rulesVersion != f.rulesVersion` — the packet is allowed despite the new, more restrictive ruleset, until the ticker resets the cache.

func (f *Firewall) inConns(fp firewall.Packet, h *HostInfo, caPool *cert.CAPool, localCache firewall.ConntrackCache) bool {
	if localCache != nil {
		if _, ok := localCache[fp]; ok {
			return true
		}
	}
	conntrack := f.Conntrack
	conntrack.Lock()

	// Purge every time we test
	ep, has := conntrack.TimerWheel.Purge()
	if has {
		f.evict(ep)
	}

	c, ok := conntrack.Conns[fp]

	if !ok {
		conntrack.Unlock()
		return false
	}

	if c.rulesVersion != f.rulesVersion {
		// This conntrack entry was for an older rule set, validate
		// it still passes with the current rule set
		table := f.OutRules
		if c.incoming {
			table = f.InRules
		}

		// We now know which firewall table to check against
		if !table.match(fp, c.incoming, h.ConnectionState.peerCert, caPool) {
			if f.l.Enabled(context.Background(), slog.LevelDebug) {
				h.logger(f.l).Debug("dropping old conntrack entry, does not match new ruleset",
					"fwPacket", fp,
					"incoming", c.incoming,
					"rulesVersion", f.rulesVersion,
					"oldRulesVersion", c.rulesVersion,
				)
			}
			delete(conntrack.Conns, fp)
			conntrack.Unlock()
			return false
		}

		if f.l.Enabled(context.Background(), slog.LevelDebug) {
			h.logger(f.l).Debug("keeping old conntrack entry, does match new ruleset",
				"fwPacket", fp,
				"incoming", c.incoming,
				"rulesVersion", f.rulesVersion,
				"oldRulesVersion", c.rulesVersion,
			)
		}

		c.rulesVersion = f.rulesVersion
	}

func (c *ConntrackCacheTicker) tick(ctx context.Context, d time.Duration) {
	t := time.NewTicker(d)
	defer t.Stop()
	for {
		select {
		case <-ctx.Done():
			return
		case <-t.C:
			c.cacheTick.Add(1)
		}
	}
}

// Get checks if the cache ticker has moved to the next version before returning
// the map. If it has moved, we reset the map.
func (c *ConntrackCacheTicker) Get() ConntrackCache {
	if c == nil {
		return nil
	}
	if tick := c.cacheTick.Load(); tick != c.cacheV {
		c.cacheV = tick
		if ll := len(c.cache); ll > 0 {
			if c.l.Enabled(context.Background(), slog.LevelDebug) {
				c.l.Debug("resetting conntrack cache", "len", ll)
			}
			c.cache = make(ConntrackCache, ll)
		}
	}

	return c.cache
}
