Based on my investigation, I found a concrete instance of the asymmetric-validation pattern described in the report, reachable from an unprivileged RPC caller.

### Title
Unvalidated `GitAlternateObjectDirectories`/`GitObjectDirectory` request fields allow arbitrary object-directory injection into Git subprocess environment - ([File: internal/git/gitcmd/command_factory.go])

### Summary
Gitaly validates `GitObjectDirectory` when a repository's object directory path is resolved for direct filesystem access via `Repo.ObjectDirectoryPath()`, which enforces that the path stays within the storage root or matches an expected quarantine prefix [1](#0-0) . However, the exact same client-supplied `Repository.GitObjectDirectory` / `Repository.GitAlternateObjectDirectories` fields are consumed by `alternates.Env()` and injected as `GIT_OBJECT_DIRECTORY` / `GIT_ALTERNATE_OBJECT_DIRECTORIES` environment variables for every Git subprocess spawned via `ExecCommandFactory.newCommand()`, with no equivalent boundary check [2](#0-1) [3](#0-2) .

### Finding Description
The invariant that should hold symmetrically is: any object-directory-related path taken from a `gitalypb.Repository` message must be confined to the storage root (or a legitimate quarantine directory). This is enforced in one place — `ObjectDirectoryPath()` — via `storage.ValidateRelativePath` and a quarantine-prefix check [4](#0-3) , and again for reading `objects/info/alternates` file contents via `alternateOutsideStorageError` checks in `internal/git/dirs.go` [5](#0-4) .

But `alternates.Env()`, which is the function that actually builds the environment passed to every `git` subprocess (`newCommand`), performs no such validation — it simply does `filepath.Join(repoPath, dir)` for every alternate directory and joins them into `GIT_ALTERNATE_OBJECT_DIRECTORIES` [6](#0-5) . Because `filepath.Join` cleans `..` sequences, a value such as `"../../../../etc"` or an absolute path resolves outside of the repository/storage root, and the resulting env var is handed directly to git.

The `Repository.GitObjectDirectory` / `GitAlternateObjectDirectories` proto fields are explicitly designed to be client-settable — Rails re-sends these fields on RPC calls made during pre-receive access checks (documented in `doc/object_quarantine.md`) [7](#0-6) , and test coverage confirms ordinary Accessor RPCs (e.g., `FindCommits`, `CommitIsAncestor`) accept these fields directly on the request's `Repository` message and route them straight to git execution [8](#0-7) . The `storagemgr` transaction middleware explicitly acknowledges that these fields can be set arbitrarily and is only concerned with transaction boundary integrity, not path-escape safety, noting: *"This property is violated in tests which manually configure the object directory... This allows for circumventing the transaction management... We'll leave this unaddressed for now"* [9](#0-8) .

### Impact Explanation
If reachable on a mutator-free RPC that doesn't route through the transaction manager's `ObjectDirectoryPath`-based checks, an attacker-controlled `GitAlternateObjectDirectories` value can point `git` subprocesses at arbitrary filesystem directories outside the storage root. Since `GIT_ALTERNATE_OBJECT_DIRECTORIES` is a search path Git uses to resolve object lookups, this allows disclosure of objects (blobs, trees, commits) from files on disk that happen to look like valid loose objects/packfiles anywhere the Gitaly process can read — a cross-repository / arbitrary-filesystem object access, matching the "Accept only concrete... cross-repository object access" category in scope.

### Likelihood Explanation
The `Repository.GitObjectDirectory`/`GitAlternateObjectDirectories` fields are ordinary proto fields on every `Repository` message used across nearly all RPCs, and are demonstrably settable directly on the request by callers (as shown in test setups). The `ObjectDirectoryPath()` guard only applies to code paths that explicitly call it (e.g., snapshot creation, some direct filesystem paths); it is not applied as a universal input-sanitization step before `alternates.Env()` is invoked in `newCommand()`, meaning any RPC that reaches `ExecCommandFactory.New()` with a repo carrying attacker-supplied object-directory fields bypasses that check.

### Recommendation
Apply the same boundary validation used in `ObjectDirectoryPath()` (via `storage.ValidateRelativePath` plus the quarantine-prefix exception) inside `alternates.Env()` (or immediately before it is called in `newCommand()`), rejecting any `GitObjectDirectory`/`GitAlternateObjectDirectories` value that resolves outside the storage root or a legitimate quarantine directory, for every code path that constructs Git subprocess environments — not just the paths that happen to call `ObjectDirectoryPath()` directly.

### Proof of Concept
1. As an ordinary caller, issue an RPC (e.g., `FindCommits`, `CommitIsAncestor`, or similar Accessor RPC) whose request carries a `Repository` message with `git_alternate_object_directories` set to a path such as `"../../../../etc"` or an absolute path outside the storage root.
2. The request flows to `ExecCommandFactory.newCommand()`, which calls `alternates.Env(repoPath, repo.GetGitObjectDirectory(), repo.GetGitAlternateObjectDirectories())` [2](#0-1) .
3. `alternates.Env()` joins the value with `repoPath` via `filepath.Join`, producing a path outside the intended repository/storage tree, and sets it as `GIT_ALTERNATE_OBJECT_DIRECTORIES` for the spawned `git` process [6](#0-5) .
4. Git will search that directory for loose objects/packfiles when resolving the requested OID, potentially returning data outside the caller's own repository.

**Caveat**: I was unable to fully trace whether `middleware.go`'s transaction gating (which restricts Mutator RPCs with quarantine fields set) or some other upstream validation blocks this specific vector for all RPC types in this codebase version — the code comment at `internal/gitaly/storage/storagemgr/middleware.go:278-282` explicitly says this gap is "left unaddressed," but I could not exhaustively verify every RPC's calling path within the available iterations. A background agent with full test-execution access should verify end-to-end reachability via a live RPC call before treating this as fully confirmed.

// ObjectDirectoryPath returns the full path of the object directory. The errors returned are gRPC
// errors with relevant error codes and should be passed back to gRPC without further decoration.
func (repo *Repo) ObjectDirectoryPath(ctx context.Context) (string, error) {
	repoPath, err := repo.Path(ctx)
	if err != nil {
		return "", err
	}

	objectDirectoryPath := repo.GetGitObjectDirectory()
	if objectDirectoryPath == "" {
		return "", structerr.NewInvalidArgument("object directory path is not set")
	}

	storagePath, err := repo.locator.GetStorageByName(ctx, repo.GetStorageName())
	if err != nil {
		return "", fmt.Errorf("get storage by name: %w", err)
	}

	// Ensure the path points somewhere in the storage.
	relativeObjectDirectoryPath, err := storage.ValidateRelativePath(storagePath, filepath.Join(repoPath, objectDirectoryPath))
	if err != nil {
		return "", structerr.NewInvalidArgument("validate relative path: %w", err)
	}

	parentDir := filepath.Base(filepath.Dir(relativeObjectDirectoryPath))
	baseDir := filepath.Base(relativeObjectDirectoryPath)
	isTransactionQuarantineDir := (baseDir == "quarantine") || ((parentDir == "quarantine") && strings.HasPrefix(baseDir, "tmp_objdir"))

	// Transactions quarantine a repository by pointing the object directory to a 'quarantine' named
	// directory in the transaction's temporary directory. If the base directory is `quarantine`,
	// Git push may apply an additional layer of quarantine such as `/quarantine/tmp_objdir-incoming-Gbc29N`
	// so we don't assert the `/quarantine` being the last element of the path. We thus also check for
	// whether the parent directory is in `quarantine` and whether the base directory has the expected
	// `tmp_objdir` suffix.
	if !isTransactionQuarantineDir {
		// We need to check whether the relative object directory as given by the repository is
		// a valid path. This may either be a path in the Git repository itself, where it may either
		// point to the main object directory storage or to an object quarantine directory as
		// created by git-receive-pack(1). Alternatively, if that is not the case, then it may be a
		// manual object quarantine directory located in the storage's temporary directory. These
		// have a repository-specific prefix which we must check in order to determine whether the
		// quarantine directory does in fact belong to the repo at hand.
		if _, origError := storage.ValidateRelativePath(repoPath, objectDirectoryPath); origError != nil {
			tempDir, err := repo.locator.TempDir(repo.GetStorageName())
			if err != nil {
				return "", structerr.NewInvalidArgument("getting storage's temporary directory: %w", err)
			}

			expectedQuarantinePrefix := filepath.Join(tempDir, storage.QuarantineDirectoryPrefix(repo))
			absoluteObjectDirectoryPath := filepath.Join(repoPath, objectDirectoryPath)

			// The relative path is outside of the repository
			if !strings.HasPrefix(absoluteObjectDirectoryPath, expectedQuarantinePrefix) {
				return "", structerr.NewInvalidArgument("not a valid relative path: %w", origError)
			}
		}

// Env returns the alternate object directory environment variables.
func Env(repoPath, objectDirectory string, alternateObjectDirectories []string) []string {
	var env []string
	if objectDirectory != "" {
		env = append(env, fmt.Sprintf("GIT_OBJECT_DIRECTORY=%s", filepath.Join(repoPath, objectDirectory)))
	}

	if len(alternateObjectDirectories) > 0 {
		var dirsList []string

		for _, dir := range alternateObjectDirectories {
			dirsList = append(dirsList, filepath.Join(repoPath, dir))
		}

		env = append(env, fmt.Sprintf("GIT_ALTERNATE_OBJECT_DIRECTORIES=%s", strings.Join(dirsList, ":")))
	}

	return env
}
