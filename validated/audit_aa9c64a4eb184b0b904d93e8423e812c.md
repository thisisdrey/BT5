Based on the report’s bug class — an unauthenticated actor invoking a state‑mutating function with no cryptographic tie to the legitimate party, causing denial of service — the closest reachable analog in this nebula fork is the `RecvError` handling path in `outside.go`, which tears down an active tunnel based on an **unauthenticated, unencrypted** UDP packet.

### Title
Unauthenticated `RecvError` packet allows remote tunnel teardown / DoS - ([File: outside.go])

### Summary
`header.RecvError` packets are processed by `readOutsidePackets` in the "Unencrypted packets" branch, before any Noise handshake authentication or AEAD decryption is performed: [1](#0-0) 

They are routed straight to `handleRecvError`, which looks up the hostinfo purely by the attacker-supplied `h.RemoteIndex` and — if the hostinfo has no remote set yet, or the packet's source address happens to match the currently known remote — closes the tunnel and deletes the pending handshake state, with no certificate, MAC, or handshake proof required: [2](#0-1) 

### Finding Description
Unlike `header.Message`/`header.LightHouse`/`header.Test` traffic, which is only acted on after `ConnectionState.Decrypt` or `VerifyRelay` succeed (i.e., after AEAD authentication tied to the handshake-derived keys), `header.RecvError` is handled unconditionally for any UDP datagram whose header parses and whose type is `RecvError`: [3](#0-2) 

The only gate is `acceptRecvErrorConfig.ShouldRecvError(addr)`, which is a coarse IP‑range policy (`always`/`never`/`private`), not an authentication check: [4](#0-3) [5](#0-4) 

The only defense inside `handleRecvError` itself is comparing the packet's source `netip.AddrPort` to the hostinfo's currently stored remote (`hr`), and even that check is skipped entirely when `hr` is not yet valid (e.g., a freshly established or still-roaming tunnel): [6](#0-5) 

This mirrors the reported bug class directly: a state-mutating operation (`approve()` resetting an allowance; here, `handleRecvError` tearing down a tunnel and deleting handshake state) is reachable by an unauthenticated party and can be invoked to disrupt a legitimate operation in progress, exactly as `approve(0)` front-running blocks deposit/mint.

### Impact Explanation
An attacker who can send a spoofed UDP packet with the type `RecvError` and a guessed/observed `RemoteIndex` can force `f.closeTunnel(hostinfo)` and `f.handshakeManager.DeleteHostInfo(hostinfo)` to run for a victim tunnel, tearing down an established or in-progress Nebula tunnel without ever presenting a valid certificate or completing a handshake. Because UDP source addresses are trivially spoofable on many network paths, and the address check is bypassable whenever `hr` is not yet set (pre-roam, freshly handshaken hostinfo), this is a remote, unauthenticated denial-of-service primitive against Nebula tunnels — directly matching the "no CA-signed certificate" reachability constraint and the "remote crash/DoS impact" acceptance criteria.

### Likelihood Explanation
`RemoteIndex` is a 32-bit randomly generated value (see `generateIndex` in `handshake_manager.go`), so blind guessing is impractical, but an attacker positioned to observe traffic (on-path, or with access to any legitimate packet exchanged with the victim) can read the index directly off any Nebula packet header and then spoof a `RecvError` from an arbitrary source, since the "matching remote" check is the only barrier and it is skippable when `hr` is invalid. The project's own changelog acknowledges this exact tradeoff was already a known "Security" concern (`listen.send_recv_error`/`listen.accept_recv_error`, default `always`), confirming this is a genuine, previously-recognized weakness that remains exploitable by default.

### Recommendation
Do not act on `RecvError` packets that are not cryptographically tied to the tunnel they claim to affect. Options:
- Require `RecvError` packets to carry a MAC/tag derived from the tunnel's established keys (or a short authenticated cookie exchanged during handshake) rather than trusting the bare header + source-address heuristic.
- Tighten the existing address check so a missing/invalid `hr` never bypasses the check — instead, fall back to requiring the packet to originate from an address consistent with the hostinfo's `remotes` list, not simply "match or hr is unset."
- Rate-limit/log repeated `RecvError`-driven teardowns per hostinfo to reduce the blast radius of spoofed traffic even if perfect authentication is infeasible for this control message.

### Proof of Concept
1. Attacker observes (or otherwise learns) the 32-bit `RemoteIndex` used between victim A and B, e.g., by capturing any Nebula packet exchanged between them (the index is sent in cleartext in every header).
2. Attacker crafts a UDP packet with `header.RecvError` type and that `RemoteIndex`, sets the source address to spoof B's address (or sends at a moment when A's `hr` for that hostinfo is not yet set, e.g., right after roam/reconnect).
3. A's `readOutsidePackets` dispatches straight to `handleRecvError` without any decryption/authentication: [3](#0-2) 
4. `handleRecvError` finds the hostinfo via `QueryReverseIndex`, passes the (bypassable) address check, and calls `f.closeTunnel(hostinfo)` plus `hm.DeleteHostInfo(hostinfo)`, terminating the legitimate tunnel: [7](#0-6) 
5. Repeating this at will lets the attacker perpetually deny tunnel establishment/maintenance between A and B — a denial of service reachable with no certificate and no completed handshake.

```go
func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
```

```go
type recvErrorConfig uint8

const (
	recvErrorAlways recvErrorConfig = iota
	recvErrorNever
	recvErrorPrivate
)

func (s recvErrorConfig) ShouldRecvError(endpoint netip.AddrPort) bool {
	switch s {
	case recvErrorPrivate:
		return endpoint.Addr().IsPrivate()
	case recvErrorAlways:
		return true
	case recvErrorNever:
		return false
	default:
		panic(fmt.Errorf("invalid recvErrorConfig value: %d", s))
	}
}
```

```go
func (f *Interface) reloadAcceptRecvError(c *config.C) {
	if c.InitialLoad() || c.HasChanged("listen.accept_recv_error") {
		stringValue := c.GetString("listen.accept_recv_error", "always")

		switch stringValue {
		case "always":
			f.acceptRecvErrorConfig = recvErrorAlways
		case "never":
			f.acceptRecvErrorConfig = recvErrorNever
		case "private":
			f.acceptRecvErrorConfig = recvErrorPrivate
		default:
			if c.GetBool("listen.accept_recv_error", true) {
				f.acceptRecvErrorConfig = recvErrorAlways
			} else {
				f.acceptRecvErrorConfig = recvErrorNever
			}
		}

		f.l.Info("Loaded accept_recv_error config", "acceptRecvError", f.acceptRecvErrorConfig.String())
	}
}
```
