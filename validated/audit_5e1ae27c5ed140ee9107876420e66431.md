### Title
Blocklisted/invalid peer certificates continue to pass traffic through already-established conntrack entries until the next connection-manager sweep - ([File: firewall.go])

### Summary
The reported bug pattern ("pausing/blocklisting only affects future actions, not previously-accepted state") has a direct analog in Nebula's firewall conntrack revalidation logic combined with the periodic (not per-packet) certificate blocklist check in the connection manager.

### Finding Description
Nebula's `Firewall.Drop` first checks the conntrack table via `inConns` before ever consulting the firewall rule table or the CA pool's certificate blocklist for that packet 4-tuple: [1](#0-0) 

Inside `inConns`, an existing conntrack entry is only re-validated against the firewall rule table when the firewall's `rulesVersion` counter has changed (i.e., after a firewall config reload) — it is never re-checked against the CA pool / certificate blocklist: [2](#0-1) 

Certificate blocklisting is handled entirely separately, via `CAPool.BlocklistFingerprint`/`IsBlocklisted`: [3](#0-2) 

The only place a blocklisted (or otherwise invalid) peer certificate causes a tunnel teardown is `connectionManager.isInvalidCertificate`, which explicitly always disconnects on `cert.ErrBlockListed`: [4](#0-3) 

However, this check is not invoked on every packet — it runs on the connection manager's periodic sweep/tick cycle (the same mechanism that also evaluates inactivity and traffic decisions), as seen in the surrounding `makeTrafficDecision`/`isInactive` logic: [5](#0-4) 

This mirrors the `NFTFloorOracle` bug precisely: `setPause`/blocklisting an asset (here, blocklisting a certificate fingerprint) does not retroactively invalidate the already-"cached" trust decision (here, the conntrack entry that let packets bypass the CA pool check). Traffic on that tunnel is only cut off once the connection manager gets around to its next sweep and calls `isInvalidCertificate` — an interval-bound window, not immediate revocation, during which packets from a peer whose certificate has just been blocklisted keep flowing through the already-established conntrack entries.

### Impact Explanation
An operator who discovers a compromised or malicious peer and blocklists its certificate fingerprint expects traffic from that peer to be dropped immediately. Instead, any already-open flow (TCP/UDP 4-tuple) recorded in conntrack keeps being allowed by `inConns` without any certificate check, because conntrack revalidation is keyed only to firewall `rulesVersion`, not to CA pool/blocklist state. The tunnel itself is eventually torn down by the connection manager, but only on its periodic check cycle, not synchronously with the blocklist action, meaning malicious traffic continues to be routed to the overlay/tun interface for a window after the administrative intent to block it.

### Likelihood Explanation
This is a deterministic, unauthenticated-adjacent effect of normal blocklist operation: it requires no exploitation on the attacker's part beyond having an already-established conntrack entry (e.g., an existing legitimate-looking flow that later needs to be blocked). Any admin action to blocklist a fingerprint while a tunnel is active will trigger this window, making the likelihood high whenever `pki.blocklist` is used against an active connection.

### Recommendation
Have firewall conntrack revalidation also account for certificate/blocklist state changes, not just `rulesVersion`. For example, bump `rulesVersion` (or add a separate `caPoolVersion`) whenever the CA pool blocklist changes, and check the certificate/blocklist status of the corresponding `HostInfo.ConnectionState.peerCert` inside `inConns` before allowing a cached flow through, in addition to the periodic teardown in `connectionManager.isInvalidCertificate`.

### Proof of Concept
1. Establish a tunnel and firewall rule allowing traffic between hosts A and B; send a packet so `Firewall.addConn` records a conntrack entry for the flow (see `firewall_test.go` `TestFirewall_DropConntrackReload` for the harness pattern): [6](#0-5) 
2. While the tunnel is open, call `caPool.BlocklistFingerprint(<B's fingerprint>)` — this does not touch `Firewall.rulesVersion`.
3. Send another packet on the same 4-tuple; `Firewall.Drop` → `inConns` finds the existing entry with matching `rulesVersion` and allows it (line 460-462, 527-560) without ever consulting `caPool.IsBlocklisted`.
4. The packet is only stopped once `connectionManager.isInvalidCertificate` runs on its next cycle and tears down the tunnel (`connection_manager.go` lines 470-499) — demonstrating the window where the blocklist affects future certificate re-verification but not the already-flowing traffic.

```go
func (f *Firewall) inConns(fp firewall.Packet, h *HostInfo, caPool *cert.CAPool, localCache firewall.ConntrackCache) bool {
	if localCache != nil {
		if _, ok := localCache[fp]; ok {
			return true
		}
	}
	conntrack := f.Conntrack
	conntrack.Lock()

	// Purge every time we test
	ep, has := conntrack.TimerWheel.Purge()
	if has {
		f.evict(ep)
	}

	c, ok := conntrack.Conns[fp]

	if !ok {
		conntrack.Unlock()
		return false
	}

	if c.rulesVersion != f.rulesVersion {
		// This conntrack entry was for an older rule set, validate
		// it still passes with the current rule set
		table := f.OutRules
		if c.incoming {
			table = f.InRules
		}

		// We now know which firewall table to check against
		if !table.match(fp, c.incoming, h.ConnectionState.peerCert, caPool) {
			if f.l.Enabled(context.Background(), slog.LevelDebug) {
				h.logger(f.l).Debug("dropping old conntrack entry, does not match new ruleset",
					"fwPacket", fp,
					"incoming", c.incoming,
					"rulesVersion", f.rulesVersion,
					"oldRulesVersion", c.rulesVersion,
				)
			}
			delete(conntrack.Conns, fp)
			conntrack.Unlock()
			return false
		}

		if f.l.Enabled(context.Background(), slog.LevelDebug) {
			h.logger(f.l).Debug("keeping old conntrack entry, does match new ruleset",
				"fwPacket", fp,
				"incoming", c.incoming,
				"rulesVersion", f.rulesVersion,
				"oldRulesVersion", c.rulesVersion,
			)
		}

		c.rulesVersion = f.rulesVersion
	}
```

```go
// BlocklistFingerprint adds a cert fingerprint to the blocklist
func (ncp *CAPool) BlocklistFingerprint(f string) {
	ncp.certBlocklist[f] = struct{}{}
}

// ResetCertBlocklist removes all previously blocklisted cert fingerprints
func (ncp *CAPool) ResetCertBlocklist() {
	ncp.certBlocklist = make(map[string]struct{})
}

// IsBlocklisted tests the provided fingerprint against the pools blocklist.
// Returns true if the fingerprint is blocked.
func (ncp *CAPool) IsBlocklisted(fingerprint string) bool {
	if _, ok := ncp.certBlocklist[fingerprint]; ok {
		return true
	}

	return false
}
```

```go
func (cm *connectionManager) isInactive(hostinfo *HostInfo, now time.Time) (time.Duration, bool) {
	if cm.dropInactive.Load() == false {
		// We aren't configured to drop inactive tunnels
		return 0, false
	}

	inactiveDuration := now.Sub(hostinfo.lastUsed)
	if inactiveDuration < cm.getInactivityTimeout() {
		// It's not considered inactive
		return inactiveDuration, false
	}

	// The tunnel is inactive
	return inactiveDuration, true
}
```

```go
// isInvalidCertificate decides if we should destroy a tunnel.
// returns true if pki.disconnect_invalid is true and the certificate is no longer valid.
// Blocklisted certificates will skip the pki.disconnect_invalid check and return true.
func (cm *connectionManager) isInvalidCertificate(now time.Time, hostinfo *HostInfo) bool {
	remoteCert := hostinfo.GetCert()
	if remoteCert == nil {
		return false //don't tear down tunnels for handshakes in progress
	}

	caPool := cm.intf.pki.GetCAPool()
	err := caPool.VerifyCachedCertificate(now, remoteCert)
	if err == nil {
		return false //cert is still valid! yay!
	} else if err == cert.ErrBlockListed { //avoiding errors.Is for speed
		// Block listed certificates should always be disconnected
		hostinfo.logger(cm.l).Info("Remote certificate is blocked, tearing down the tunnel",
			"error", err,
			"fingerprint", remoteCert.Fingerprint,
		)
		return true
	} else if cm.intf.disconnectInvalid.Load() {
		hostinfo.logger(cm.l).Info("Remote certificate is no longer valid, tearing down the tunnel",
			"error", err,
			"fingerprint", remoteCert.Fingerprint,
		)
		return true
	} else {
		//if we reach here, the cert is no longer valid, but we're configured to keep tunnels from now-invalid certs open
		return false
	}
```
