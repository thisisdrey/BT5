### Title
Firewall `rulesVersion` is not bumped on CA pool/blocklist reload, allowing already-established conntrack entries to bypass revalidation against a newly revoked or blocklisted certificate - (File: `pki.go`, `interface.go`, `firewall.go`)

### Summary
`RdpxV2Core`'s bug class is: a synchronization step (`sync`) that re-validates stored state is only invoked on some state-changing code paths, not all, so downstream security decisions (`lowerDepeg`/`upperDepeg`) can act on stale data. Nebula has a structurally identical gap: the firewall's `rulesVersion` counter — the mechanism used to force re-validation of already-accepted (conntracked) flows — is only bumped when the `firewall` config block or the local certificate's unsafe networks change. It is never bumped when the CA pool or `pki.blocklist` is reloaded, even though CA pool state is exactly what firewall rule matching uses to authorize a peer.

### Finding Description
`PKI.reloadCAPool` in [1](#0-0)  reloads and atomically swaps the `cert.CAPool`, including newly added fingerprints from `pki.blocklist` [2](#0-1) . This reload runs from its own independent `RegisterReloadCallback` registered in `NewPKIFromConfig` [3](#0-2) , completely decoupled from the `Interface`'s firewall reload callback.

The `Interface.reloadFirewall` callback, which is the only place that bumps `Firewall.rulesVersion`, only triggers a rebuild when `c.HasChanged("firewall")` or when the local certificate's `UnsafeNetworks()` changed: [4](#0-3) . It never checks whether the CA pool or blocklist changed.

`rulesVersion` is the sole signal used by `Firewall.inConns` to decide whether an already-tracked flow needs to be re-validated against the (now current) `caPool` and rule table: [5](#0-4) 
If `c.rulesVersion == f.rulesVersion`, the conntrack hit is accepted immediately — `table.match(fp, c.incoming, h.ConnectionState.peerCert, caPool)` is skipped entirely, meaning the (possibly stale) `caPool` reference is never even consulted for that packet.

Because `rulesVersion` is not incremented on a CA/blocklist reload, every conntrack entry established before the reload keeps its old `rulesVersion`, which still equals `f.rulesVersion` (unchanged), so `inConns` treats the flow as still valid and skips re-checking it against the CA pool that now has the peer's issuing CA blocklisted or removed.

### Impact Explanation
An operator who blocklists a compromised/rotated CA fingerprint via `pki.blocklist` (or removes a CA from `pki.ca`) and hot-reloads config expects that peer's traffic to be rejected going forward. Because the firewall's conntrack fast path is keyed only on `rulesVersion` and that version is not tied to CA state, already-established tunnels from the now-untrusted issuer keep flowing without being re-evaluated against `table.match`/`caPool` until the conntrack entry naturally expires (`TCPTimeout`, up to Linux's 5-day max) or until it is refreshed by traffic (which resets `Expires` on every hit, effectively extending it indefinitely). This is a concrete firewall bypass / stale-trust-state poisoning: revocation intent is silently ignored for existing sessions.

### Likelihood Explanation
This requires no CA-signed certificate from the attacker and no cooperation from a malicious peer — it is purely a server-side trust-management defect. Any deployment that relies on `pki.blocklist` or CA rotation to cut off a compromised peer while keeping existing tunnels alive is affected. The condition is deterministic: any CA/blocklist reload without a matching firewall-config change reproduces it every time.

### Recommendation
In `reloadFirewall` (`interface.go`), also detect CA pool/blocklist changes (e.g., compare `c.HasChanged("pki.ca")` / `c.HasChanged("pki.blocklist")`, or compare fingerprint sets between the old and new `cert.CAPool`) and bump `rulesVersion` (or force a full conntrack flush) whenever the CA pool changes, mirroring the existing `certUnsafeChanged` check.

### Proof of Concept
1. Start nebula with a CA pool containing CA `X`, and a firewall rule allowing traffic from certs issued by `X`.
2. Peer `P`, whose certificate was issued by CA `X`, establishes a tunnel and passes traffic; a conntrack entry is created via `addConn` with `rulesVersion = f.rulesVersion` (e.g. `0`) [6](#0-5) .
3. Operator reloads config, adding CA `X`'s fingerprint to `pki.blocklist` (no change to the `firewall` block). `PKI.reloadCAPool` swaps in a new `CAPool` with `X` blocklisted [1](#0-0) .
4. `reloadFirewall` runs, but `c.HasChanged("firewall")` is `false` and `certUnsafeChanged` is `false`, so it returns early without bumping `f.rulesVersion` [7](#0-6) .
5. Peer `P` continues sending packets on the existing flow. `Firewall.Drop` → `inConns` finds `c.rulesVersion == f.rulesVersion`, skips `table.match` (and thus any check against the blocklisted CA), refreshes `c.Expires`, and returns `true` (allowed) [8](#0-7) .
6. Traffic from the now-blocklisted CA's peer continues to be forwarded indefinitely as long as it keeps the conntrack entry alive.

```go
func (f *Interface) reloadFirewall(c *config.C) {
	cs := f.pki.getCertState()
	curCert := cs.getCertificate(cert.Version2)
	if curCert == nil {
		curCert = cs.getCertificate(cert.Version1)
	}

	// The firewall builds its routableNetworks set from the certificate's UnsafeNetworks at construction.
	// Check to see if that set has changed, and if so, rebuild the firewall.
	certUnsafeChanged := curCert != nil && !slices.Equal(curCert.UnsafeNetworks(), f.firewall.unsafeNetworks)

	if !c.HasChanged("firewall") && !certUnsafeChanged {
		f.l.Debug("No firewall config change detected")
		return
	}
```

```go
func (f *Firewall) inConns(fp firewall.Packet, h *HostInfo, caPool *cert.CAPool, localCache firewall.ConntrackCache) bool {
	if localCache != nil {
		if _, ok := localCache[fp]; ok {
			return true
		}
	}
	conntrack := f.Conntrack
	conntrack.Lock()

	// Purge every time we test
	ep, has := conntrack.TimerWheel.Purge()
	if has {
		f.evict(ep)
	}

	c, ok := conntrack.Conns[fp]

	if !ok {
		conntrack.Unlock()
		return false
	}

	if c.rulesVersion != f.rulesVersion {
		// This conntrack entry was for an older rule set, validate
		// it still passes with the current rule set
		table := f.OutRules
		if c.incoming {
			table = f.InRules
		}

		// We now know which firewall table to check against
		if !table.match(fp, c.incoming, h.ConnectionState.peerCert, caPool) {
			if f.l.Enabled(context.Background(), slog.LevelDebug) {
				h.logger(f.l).Debug("dropping old conntrack entry, does not match new ruleset",
					"fwPacket", fp,
					"incoming", c.incoming,
					"rulesVersion", f.rulesVersion,
					"oldRulesVersion", c.rulesVersion,
				)
			}
			delete(conntrack.Conns, fp)
			conntrack.Unlock()
			return false
		}

		if f.l.Enabled(context.Background(), slog.LevelDebug) {
			h.logger(f.l).Debug("keeping old conntrack entry, does match new ruleset",
				"fwPacket", fp,
				"incoming", c.incoming,
				"rulesVersion", f.rulesVersion,
				"oldRulesVersion", c.rulesVersion,
			)
		}

		c.rulesVersion = f.rulesVersion
	}

	switch fp.Protocol {
	case firewall.ProtoTCP:
		c.Expires = time.Now().Add(f.TCPTimeout)
	case firewall.ProtoUDP:
		c.Expires = time.Now().Add(f.UDPTimeout)
	default:
		c.Expires = time.Now().Add(f.DefaultTimeout)
	}

	conntrack.Unlock()
```

```go
func (f *Firewall) addConn(fp firewall.Packet, incoming bool) {
	var timeout time.Duration
	c := &conn{}

	switch fp.Protocol {
	case firewall.ProtoTCP:
		timeout = f.TCPTimeout
	case firewall.ProtoUDP:
		timeout = f.UDPTimeout
	default:
		timeout = f.DefaultTimeout
	}

	conntrack := f.Conntrack
	conntrack.Lock()
	if _, ok := conntrack.Conns[fp]; !ok {
		conntrack.TimerWheel.Advance(time.Now())
		conntrack.TimerWheel.Add(fp, timeout)
	}

	// Record which rulesVersion allowed this connection, so we can retest after
	// firewall reload
	c.incoming = incoming
	c.rulesVersion = f.rulesVersion
	c.Expires = time.Now().Add(timeout)
	conntrack.Conns[fp] = c
	conntrack.Unlock()
}
```
