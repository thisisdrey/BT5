### Title
Stale StackerDB slots/chunks from a superseded configuration are never wiped and continue to be served to remote peers as canonical when a StackerDB's signer set legitimately becomes empty - (File: stackslib/src/net/stackerdb/mod.rs)

### Summary
`PeerNetwork::create_or_reconfigure_stackerdbs` decides whether to call `reconfigure_stackerdb` (which drops/rekeys slots for changed signers and shrinks the slot table) using an equality test between the freshly-evaluated `StackerDBConfig` and the previously-cached one. When the newly evaluated config differs from the cached one *and* has an empty signer list, the reconfigure step is unconditionally skipped. This is intended to protect against a transient smart-contract evaluation failure (which falls back to `StackerDBConfig::noop()`, itself an empty-signers config) from wiping a legitimate, populated StackerDB. But the exact same code path also fires when the contract *legitimately* reports zero signers for that reward-cycle/contract. In that case the on-disk `chunks` table for that StackerDB is never resized or cleared, so old slot data belonging to previously-authorized (now unauthorized/removed) signers remains resident and keeps being served to the network indefinitely.

### Finding Description
`create_or_reconfigure_stackerdbs` computes `new_config` for each tracked StackerDB contract and only calls `self.reconfigure_stackerdb(...)` under this condition: [1](#0-0) 

```
if !existing_contract_ids.contains(&stackerdb_contract_id) {
    ... create_stackerdb ...
} else if (new_config != stackerdb_config && !new_config.signers.is_empty())
    || (new_config == stackerdb_config
        && new_config.signers.len()
            != self.get_slot_versions(&stackerdb_contract_id)?.len())
{
    // only reconfigure if the config has changed
    ...
    self.reconfigure_stackerdb(&stackerdb_contract_id, &new_config)
}
```

`reconfigure_stackerdb` is the only routine that shrinks the `chunks` table and rekeys/wipes slots whose owning signer changed: [2](#0-1) 

If it is not called, the previously stored `chunks` rows (with their old signer, data, signature and version) remain untouched in the database forever, regardless of what the current contract-derived configuration says.

The problematic branch is `new_config != stackerdb_config && !new_config.signers.is_empty()`: reconfiguration is skipped whenever the *new* config has an empty signer list, whether that emptiness is due to (a) a transient contract-evaluation error that fell back to `StackerDBConfig::noop()` (the scenario the surrounding comment explains) or (b) the contract legitimately reporting zero signers for this StackerDB at this point in time, e.g. `stackerdb-get-signer-slots` returning an empty list for a boot contract such as `.signers-N-M`: [3](#0-2) 

The code has no way to distinguish these two cases, so it fails open for both: the config is updated in `new_stackerdb_configs` (reporting zero slots going forward), but the underlying chunk table used to answer network requests is left exactly as it was under the old signer set.

Crucially, the network-facing read path that answers unauthenticated `StackerDBGetChunkInv`/`StackerDBPushChunk` requests reads directly from the on-disk chunk table, not from the in-memory `StackerDBConfig`: [4](#0-3) 

and `StackerDBGetChunk` similarly serves whatever chunk is stored on disk for a slot ID/version: [5](#0-4) 

So any remote, unauthenticated peer that queries this node for the StackerDB's inventory or chunk content will keep receiving the stale, superseded slot data (and its old signer's slot count / versions) even though the current authoritative configuration says there should be no such data. This breaks the intended equality between "served state" and "canonical, contract-derived state" — the exact bug class highlighted in the analog report, where deleting/superseding a registration without properly tearing down the associated state leaves stale data permanently reachable.

### Impact Explanation
This is a High-impact issue: it causes a node to serve non-canonical StackerDB state (stale slot data, belonging to signers no longer authorized under the current contract-derived configuration) as if it were canonical, to any peer that requests `StackerDBGetChunkInv` or `StackerDBGetChunk` for the affected contract. Because `reconfigure_stackerdb`/`shrink_stackerdb` never run while the contract-reported signer set stays empty, this stale-serving condition can persist indefinitely (not just for one refresh cycle), and it propagates via the normal StackerDB replication/broadcast machinery in `process_stacker_db_chunks`, meaning other nodes may also sync and re-store this stale data, further entrenching the inconsistency in the network's StackerDB replica set.

### Likelihood Explanation
The condition is reached whenever `StackerDBConfig::from_smart_contract` legitimately returns zero signers for a tracked contract (a state fully controllable by the contract's own logic, e.g. `.signers-N-M` reporting no signers for a given page/cycle) while the node still holds populated slots from a prior configuration. This requires no privileged access or admin role — it is a normal consequence of contract-driven configuration changes combined with the network's default periodic `refresh_stacker_db_configs` call, and the resulting stale data is exposed via ordinary, unauthenticated P2P StackerDB read requests.

### Recommendation
Distinguish "config evaluation failed, fell back to noop()" from "contract legitimately reports zero signers" so that stale chunk data is properly cleared in the latter case. For example, propagate an explicit `Option<StackerDBConfig>`/error flag from the evaluation step instead of unconditionally substituting `StackerDBConfig::noop()`, and only skip `reconfigure_stackerdb` when the evaluation genuinely failed. When the contract legitimately reports zero signers, still call `reconfigure_stackerdb` (or an explicit `clear_stackerdb_slots`) so that `get_slot_versions`/`get_chunk` no longer serve stale, superseded slot data.

### Proof of Concept
1. Register a StackerDB-backed contract that initially reports N signers via `stackerdb-get-signer-slots`; let the node populate `chunks` with data for those N slots (as in `create_or_reconfigure_stackerdbs` → `create_stackerdb`).
2. Update the contract (or its backing state) so it now legitimately returns an empty signer list for this StackerDB.
3. On the next call to `refresh_stacker_db_configs`/`create_or_reconfigure_stackerdbs`, observe that `new_config.signers.is_empty()` is `true`, so the `else if` branch's first disjunct is `false` (because of the `!new_config.signers.is_empty()` guard), and the second disjunct is also `false` unless `new_config == stackerdb_config` (which will not hold here since the config changed) — so `reconfigure_stackerdb` is never invoked and the old `chunks` rows remain in the DB with their original slot count/signers.
4. As an unauthenticated remote peer, send a `StackerDBGetChunkInv` for this contract; observe the node replies via `make_StackerDBChunksInv_or_Nack` → `stackerdbs.get_slot_versions(contract_id)` with the stale, non-empty slot-version vector, and `StackerDBGetChunk` requests for those slot IDs still return the old chunk content — despite the current authoritative configuration reporting zero signers/slots.

    /// Update a database's storage slots, e.g. from new configuration state in its smart contract.
    /// Chunk data for slots that no longer exist will be dropped.
    /// Newly-created slots will be instantiated with empty data.
    /// If the address for a slot changes, then its data will be dropped.
    pub fn reconfigure_stackerdb(
        &self,
        smart_contract: &QualifiedContractIdentifier,
        slots: &[(StacksAddress, u32)],
    ) -> Result<(), net_error> {
        let stackerdb_id = self.get_stackerdb_id(smart_contract)?;
        let mut total_slots_read = 0u32;
        for (principal, slot_count) in slots.iter() {
            total_slots_read =
                total_slots_read
                    .checked_add(*slot_count)
                    .ok_or(net_error::OverflowError(
                        "Slot count exceeeds u32::MAX".to_string(),
                    ))?;
            let slots_before_principal = total_slots_read - slot_count;
            for cur_principal_slot in 0..*slot_count {
                let slot_id = slots_before_principal + cur_principal_slot;
                if let Some(existing_validation) =
                    self.get_slot_validation(smart_contract, slot_id)?
                {
                    // this slot already exists.
                    if existing_validation.signer == *principal {
                        // no change
                        continue;
                    }
                }

                debug!("Reset slot {} of {}", slot_id, smart_contract);

                // new slot, or existing slot with a different signer
                let qry = "INSERT OR REPLACE INTO chunks (stackerdb_id,signer,slot_id,version,write_time,data,data_hash,signature) VALUES (?1,?2,?3,?4,?5,?6,?7,?8)";
                let mut stmt = self.sql_tx.prepare(qry)?;
                let args = params![
                    stackerdb_id,
                    principal.to_string(),
                    slot_id,
                    NO_VERSION,
                    0,
                    vec![],
                    Sha512Trunc256Sum([0u8; 32]),
                    MessageSignature::empty(),
                ];

                stmt.execute(args)?;
            }
        }
        debug!("Shrink {} to {} slots", smart_contract, total_slots_read);
        self.shrink_stackerdb(stackerdb_id, total_slots_read)?;
        Ok(())
    }

    /// Handle an inbound StackerDBGetChunk request.
    /// Generates a StackerDBChunk response from the target database table, if we have it.
    /// Generates a NACK if we don't have this DB, or if the request's consensus hash or version
    /// are stale or invalid.
    fn make_stacker_db_getchunk_response(
        network: &PeerNetwork,
        getchunk: &StackerDBGetChunkData,
    ) -> StacksMessageType {
        let local_peer = network.get_local_peer();
        let burnchain_view = network.get_chain_view();
        let stacker_dbs = network.get_stackerdbs();

        if burnchain_view.rc_consensus_hash != getchunk.rc_consensus_hash {
            debug!(
                "{local_peer:?}: NACK StackerDBGetChunk; {} != {}",
                &burnchain_view.rc_consensus_hash, &getchunk.rc_consensus_hash
            );
            return StacksMessageType::Nack(NackData::new(NackErrorCodes::StaleView));
        }

        let chunk = match stacker_dbs.get_chunk(
            &getchunk.contract_id,
            getchunk.slot_id,
            getchunk.slot_version,
        ) {
            Ok(Some(chunk)) => chunk,
            Ok(None) => {
                // TODO: this is racey
                if let Ok(Some(actual_version)) =
                    stacker_dbs.get_slot_version(&getchunk.contract_id, getchunk.slot_id)
                {
                    // request for a stale chunk
                    debug!("{local_peer:?}: NACK StackerDBGetChunk; version mismatch for requested slot {}.{} for {}. Expected {actual_version}", getchunk.slot_id, getchunk.slot_version, &getchunk.contract_id);
                    if actual_version > getchunk.slot_version {
                        return StacksMessageType::Nack(NackData::new(
                            NackErrorCodes::StaleVersion,
                        ));
                    } else {
                        return StacksMessageType::Nack(NackData::new(
                            NackErrorCodes::FutureVersion,
                        ));
                    }
                }
                // if we hit a DB error, just treat it as if the DB doesn't exist
                debug!(
                    "{local_peer:?}: NACK StackerDBGetChunk; unloadable slot {}.{} for {}",
                    getchunk.slot_id, getchunk.slot_version, &getchunk.contract_id
                );
                return StacksMessageType::Nack(NackData::new(NackErrorCodes::NoSuchDB));
            }
            Err(e) => {
                debug!(
                    "{local_peer:?}: failed to get chunk for slot {}.{} for {}: {e:?}",
                    getchunk.slot_id, getchunk.slot_version, &getchunk.contract_id
                );

                // most likely indicates that this DB doesn't exist
                return StacksMessageType::Nack(NackData::new(NackErrorCodes::NoSuchDB));
            }
        };

        StacksMessageType::StackerDBChunk(chunk)
    }
