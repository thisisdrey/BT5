### Title
Missing `X-Content-Type-Options: nosniff` on StackerDB chunk-serving endpoint allows content-sniffing/MHTML-style reflected content execution - ([File: stackslib/src/net/api/getstackerdbchunk.rs])

### Summary
The unauthenticated `GET /v2/stackerdb/{principal}/{contract}/{slot_id}[/{slot_version}]` endpoint returns arbitrary, attacker-influenced byte blobs with `Content-Type: application/octet-stream` and no `X-Content-Type-Options: nosniff` header anywhere in the HTTP response stack, while every response also unconditionally sets `Access-Control-Allow-Origin: *`. This mirrors the bug class in CVE-2017-7678 (Apache Spark UI): untrusted data submitted to the server is later served back verbatim to a browser client, and in the absence of anti-sniffing protections a legacy/MIME-sniffing user agent can be tricked into rendering/executing it.

### Finding Description
`RPCGetStackerDBChunkRequestHandler::try_handle_request` loads the raw chunk bytes for a slot and returns them as-is with `HttpContentType::Bytes` and `security: []` (no auth required to read): [1](#0-0) 

The StackerDB chunk contract explicitly imposes no structure on the stored bytes — "The chunks themselves are ordered byte sequences with no mandatory internal structure": [2](#0-1) 

Any principal registered by a StackerDB-controlling contract as a slot signer can write arbitrary bytes to their own slot using their own key (`try_replace_chunk` only verifies the signature and version, not the *content*), and this content is later served to any unauthenticated remote client who requests it via the GET endpoint. Every HTTP response written by the node (including this one) is emitted by `HttpResponsePreamble::consensus_serialize`, which sets `Server`, `Date`, `Access-Control-Allow-Origin: *`, `Access-Control-Allow-Headers`, `Access-Control-Allow-Methods`, `Content-Type`, and `Content-Length`/`Transfer-Encoding` — but never `X-Content-Type-Options: nosniff`: [3](#0-2) 

A search across the entire repository confirms `X-Content-Type-Options`/`nosniff` is never emitted anywhere in the node's HTTP layer. Combined with the wildcard CORS header, this reproduces the exact structural weakness behind GHSA-r34r-f84j-5x4x: content that originates from a (possibly low-trust) writer is reflected back to arbitrary browsers with no defense against legacy MIME/content sniffing (the underlying mechanism CVE-2017-7678 exploited via MHTML in Windows browsers).

### Impact Explanation
This does not achieve the "Critical" bar (no auth bypass, no unauthorized state write, no forged-data propagation across the P2P network — StackerDB chunk *storage* is properly signature-gated as shown by `validate_received_chunk`/`try_replace_chunk`/`BadSlotSigner`). At best this is a client-side (browser) content-sniffing exposure affecting whichever human operator's browser is pointed at the URL serving a hostile StackerDB slot's content; it does not compromise node integrity, availability, or any other party's funds/keys, and modern browsers already treat `application/octet-stream` conservatively. This falls short of the "High" bar defined by the rules (serving non-canonical state as canonical, steering off tip, bounded compute DoS) and is closer to a best-practice / defense-in-depth gap than an exploitable Critical/High issue in this codebase's threat model.

### Likelihood Explanation
Low. Exploitation requires (a) an entity able to write into some StackerDB slot (a registered signer using their own key — not an arbitrary attacker, and not requiring another party's secret), (b) that content reaching a legacy/content-sniffing browser (modern browsers largely ignore MHTML-style sniffing for `application/octet-stream`), and (c) a victim being lured to visit the specific chunk URL.

### Recommendation
Add `X-Content-Type-Options: nosniff` (and consider `Content-Disposition: attachment`) to all binary/`application/octet-stream` HTTP responses emitted by `HttpResponsePreamble::consensus_serialize`, particularly for the StackerDB chunk-serving endpoints in `getstackerdbchunk.rs`, to eliminate any residual browser content-sniffing risk for reflected/stored third-party content.

### Proof of Concept
1. Register/obtain a StackerDB slot as a legitimate signer for some StackerDB-controlled contract.
2. Sign and POST a chunk whose bytes are a polyglot payload (e.g., crafted to be misinterpreted by a legacy sniffing browser) via `POST /v2/stackerdb/{principal}/{contract}/chunks`.
3. Share the link `GET /v2/stackerdb/{principal}/{contract}/{slot_id}` with a victim.
4. Observe the response is served with `Content-Type: application/octet-stream`, `Access-Control-Allow-Origin: *`, and no `X-Content-Type-Options` header — leaving MIME-sniffing browsers free to reinterpret it.

impl StacksMessageCodec for HttpResponsePreamble {
    fn consensus_serialize<W: Write>(&self, fd: &mut W) -> Result<(), CodecError> {
        fd.write_all("HTTP/1.1 ".as_bytes())
            .map_err(CodecError::WriteError)?;
        fd.write_all(format!("{} {}\r\n", self.status_code, self.reason).as_bytes())
            .map_err(CodecError::WriteError)?;

        if !self.headers.contains_key("server") {
            fd.write_all("Server: stacks/2.0\r\n".as_bytes())
                .map_err(CodecError::WriteError)?;
        }

        if !self.headers.contains_key("date") {
            fd.write_all("Date: ".as_bytes())
                .map_err(CodecError::WriteError)?;
            fd.write_all(rfc7231_now()?.as_bytes())
                .map_err(CodecError::WriteError)?;
            fd.write_all("\r\n".as_bytes())
                .map_err(CodecError::WriteError)?;
        }

        if !self.headers.contains_key("access-control-allow-origin") {
            fd.write_all("Access-Control-Allow-Origin: *\r\n".as_bytes())
                .map_err(CodecError::WriteError)?;
        }

        if !self.headers.contains_key("access-control-allow-headers") {
            fd.write_all("Access-Control-Allow-Headers: origin, content-type\r\n".as_bytes())
                .map_err(CodecError::WriteError)?;
        }

        if !self.headers.contains_key("access-control-allow-methods") {
            fd.write_all("Access-Control-Allow-Methods: POST, GET, OPTIONS\r\n".as_bytes())
                .map_err(CodecError::WriteError)?;
        }

        // content type (reserved header)
        fd.write_all("Content-Type: ".as_bytes())
            .map_err(CodecError::WriteError)?;
        fd.write_all(self.content_type.to_string().as_bytes())
            .map_err(CodecError::WriteError)?;
        fd.write_all("\r\n".as_bytes())
            .map_err(CodecError::WriteError)?;
