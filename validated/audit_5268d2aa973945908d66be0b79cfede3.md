### Title
Unbounded/unauthenticated blocking read of the event-receiver's HTTP body causes single-thread DoS - (File: `libsigner/src/events.rs`)

### Summary
`process_event::<T, E>` reads the entire HTTP body via `request.as_reader().read_to_string(&mut body)` with no maximum-size check and no read timeout, unlike the client-side `decode_http_body`/`decode_http_request` path in `libsigner/src/http.rs`, which bounds chunked bodies to `MAX_MESSAGE_LEN`. Because `SignerEventReceiver::next_event()` is called synchronously and exclusively from the single-threaded `main_loop()`, a peer that opens a TCP connection, sends a `POST /stackerdb_chunks` request with a huge `Content-Length` header, and then stalls or trickles bytes can keep `read_to_string` blocked indefinitely, freezing the entire event-receiver thread.

### Finding Description
`process_event` in `libsigner/src/events.rs` (lines 519-542) does:
```
let mut body = String::new();
if let Err(e) = request.as_reader().read_to_string(&mut body) { ... }
```
`request.as_reader()` (from `tiny_http`) returns a reader that will keep pulling bytes off the socket until it has consumed exactly `Content-Length` bytes (or the connection errors/EOFs). There is no cap comparable to `MAX_MESSAGE_LEN` (used only in the client-facing `decode_http_body` in `libsigner/src/http.rs`, lines 196-217, which is never invoked from the server-side `events.rs` path) and no socket read-timeout is configured anywhere in `events.rs` or on the `tiny_http::Server` returned by `HttpServer::http(listener)` in `bind()` (line 405).

Because `next_event()` (lines 413-459) is invoked in a tight loop from `EventReceiver::main_loop()` (lines 284-312) with no concurrency, a caller who supplies a large `Content-Length` (e.g. `4294967295`) but sends only a handful of bytes and then pauses (or trickles data slower than the peer's patience) will cause `read_to_string` to block on that single connection. While blocked, the event-receiver thread cannot call `http_server.recv()` again, so it cannot process any other legitimate event (block proposals, burn blocks, StackerDB chunks) arriving from the node. This starves the signer's entire event pipeline with a single lingering connection and a small number of bytes.

Memory allocation itself is not unbounded in the way the question frames it—`read_to_string` grows its buffer only in proportion to bytes actually received, so a stalled sender does not force a large allocation—but the indefinite-block condition is real and matches the "single-message... DoS against the signer's event thread (blocking `next_event()` indefinitely...)" framing in the question.

Existing guards that would normally prevent this (`MAX_MESSAGE_LEN`/per-field caps, an auth-gate, or a request-size limit) are not present on this server-side code path; those caps exist only in the client-side response decoder in `http.rs`, which `events.rs` does not use.

### Impact Explanation
A single unauthenticated TCP connection with a crafted `Content-Length` header and a slow/incomplete body can hang the signer's event-receiver thread indefinitely, preventing the signer from processing any further StackerDB chunks, block proposals, or burn-block notifications from the node it listens to. This is a single-message, unauthenticated availability impact against the signer process, consistent with the "Critical - remote crash/unauthenticated DoS from few messages" category, since one connection suffices and no authentication/secret is required to reach `process_event`.

### Likelihood Explanation
- No authentication or secret check exists before `process_event` reads the body — reaching `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, or `/new_block` on the receiver only requires being able to open a TCP connection to the bound listener address.
- Whether this is remotely reachable by a truly unprivileged network attacker depends on the deployment's `endpoint` configuration for the signer's event-observer bind address; if bound to a loopback-only address as is typical, only local processes (e.g., a colocated node) can reach it, which would fall outside the "no local access" attacker model. I was unable to confirm from `stacks-signer/src/config.rs` whether operators are constrained to bind this only to loopback or whether non-loopback bindings are a supported/common configuration — this affects whether the attacker precondition ("remote party who can connect") is actually met.
- Assuming the port is reachable (per the question's framing), attacker cost is minimal: one connection and a few bytes, and the condition is repeatable per connection.

### Recommendation
Enforce a maximum content length before reading the body (reject/close if `Content-Length` header exceeds a bound analogous to `MAX_MESSAGE_LEN` or `BLOCK_RESPONSE_DATA_MAX_SIZE`), and set an explicit read/write timeout on the accepted socket (or drive `next_event()`/body reads off the main loop thread, or via a background thread pool with per-connection timeouts) so a stalled peer cannot block the whole receiver. Reading the body with `Read::take(limit)` plus a bounded-time read loop (or moving to an async/threaded HTTP handling model) would close this gap.

### Proof of Concept
Rust test plan (in `libsigner::events` test module or an integration test):
1. Construct a `SignerEventReceiver<T>` and call `bind()` on `127.0.0.1:0`, spawn `main_loop()` (or directly call `next_event()`) in a thread.
2. From a separate thread, open a raw `TcpStream` to the bound address and write:
   `POST /stackerdb_chunks HTTP/1.1\r\nHost: x\r\nContent-Length: 4294967295\r\n\r\n` followed by only a few bytes (e.g., `{}`), then simply stop writing (do not close the socket).
3. On the main thread, assert that `next_event()` returns within a bounded timeout (e.g., using `std::sync::mpsc` with `recv_timeout(Duration::from_secs(5))` around the call, or running it in a joined thread with a timeout join). The assertion should be: the call does **not** return within the timeout, demonstrating the block, versus the expected behavior of a bounded-size/timeout rejection (e.g., `EventError::MalformedRequest` for an oversized or slow body) that a fixed version should produce.         loop {
            if self.is_stopped() {

                Ok(event) => event,
                Err(EventError::UnrecognizedEvent(..)) => {
                    // got an event that we don't care about (not a problem)
                    continue;
                }
                Err(EventError::Terminated) => {
                    // we're done
                    info!("Caught termination signal");
                    break;
                }
                Err(e) => {
                    warn!("Failed to receive next event: {:?}", &e);
                    continue;
                }
            };
            if !self.forward_event(next_event) {
                info!("Failed to forward event");
                break;
            }
        }
        info!("Event receiver main loop exit");
    }

    /// Errors are recoverable -- the caller should call this method again even if it returns an
    /// error.
    fn next_event(&mut self) -> Result<SignerEvent<T>, EventError> {
        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)
            } else if request.url() == "/new_block" {
                process_event::<T, StacksBlockEvent>(request)
            } else {
                let url = request.url().to_string();
                debug!(
                    "[{:?}] next_event got request with unexpected url {}, return OK so other side doesn't keep sending this",
                    event_receiver.local_addr,
                    url
                );
                ack_dispatcher(request);
                Err(EventError::UnrecognizedEvent(url))
            }
        })?
    }

fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}

/// Decode an HTTP body, given the headers.
pub fn decode_http_body(headers: &HashMap<String, String>, mut buf: &[u8]) -> io::Result<Vec<u8>> {
    let chunked = if let Some(val) = headers.get("transfer-encoding") {
        val == "chunked"
    } else {
        false
    };

    let body = if chunked {
        // chunked encoding
        let ptr = &mut buf;
        let mut fd = HttpChunkedTransferReader::from_reader(ptr, MAX_MESSAGE_LEN.into());
        let mut decoded_body = vec![];
        fd.read_to_end(&mut decoded_body)?;
        decoded_body
    } else {
        // body is just as-is
        buf.to_vec()
    };

    Ok(body)
}
