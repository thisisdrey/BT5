### Title
Per-connection stream throttling is not aggregated per source IP, allowing unstaked TPS amplification via concurrent connections - ([File: streamer/src/nonblocking/stream_throttle.rs])

### Summary
The per-connection stream throttle (`throttle_stream`, `ConnectionStreamCounter`) enforces `max_streams_per_throttling_interval` independently for each `Connection`/`ConnectionStreamCounter` instance, and this budget (`available_load_capacity_in_throttling_duration` for `ConnectionPeerType::Unstaked`) is a fixed constant derived from `MAX_UNSTAKED_TPS` that does not scale down with the number of concurrent connections held by the same source IP. Since an unstaked peer may hold up to `max_connections_per_unstaked_peer` (default `DEFAULT_MAX_QUIC_CONNECTIONS_PER_UNSTAKED_PEER = 8`) concurrent connections, aggregate throughput from a single attacker IP can reach up to 8x the intended `MAX_UNSTAKED_TPS`.

### Finding Description
`ConnectionStreamCounter` tracks `stream_count` and `last_throttling_instant` per connection object, created fresh for each new connection via `cache_new_connection`'s `|| Arc::new(ConnectionStreamCounter::new())` closure [1](#0-0) . `throttle_stream` only reads/resets that single connection's counter and sleeps if `streams_read_in_throttle_interval >= max_streams_per_throttling_interval` [2](#0-1) .

The budget itself, `max_streams_per_throttling_interval`, is computed via `StakedStreamLoadEMA::available_load_capacity_in_throttling_duration`, which for `ConnectionPeerType::Unstaked` simply returns the constant `max_unstaked_load_in_throttling_window = MAX_UNSTAKED_TPS * STREAM_THROTTLING_INTERVAL_MS / 1000` [3](#0-2) [4](#0-3) . Crucially, `increment_load` (called from `on_stream_accepted`) only feeds the EMA / load accounting when `peer_type.is_staked()` is true [5](#0-4) ; unstaked stream activity is never aggregated into any global or per-source-IP counter that would reduce the budget for sibling connections from the same IP.

Meanwhile, connection admission is only capped per-peer at `max_connections_per_unstaked_peer` (default 8, `DEFAULT_MAX_QUIC_CONNECTIONS_PER_UNSTAKED_PEER`) [6](#0-5) , enforced independently of the stream-level throttle in `cache_new_connection`'s `try_add_connection` call [7](#0-6) . There is no coupling between "how many connections this IP currently holds" and "what per-connection stream budget each of those connections gets." Consequently, an attacker opening N ≤ 8 concurrent connections from one IP gets N independent `ConnectionStreamCounter`s, each allowed `MAX_UNSTAKED_TPS * STREAM_THROTTLING_INTERVAL_MS/1000` streams per 100ms window, for an aggregate throughput of up to `N × MAX_UNSTAKED_TPS` — up to 8× the intended per-source unstaked cap — without needing to "reset" anything via churn (churn is not even required; simple concurrency suffices, though churn could refresh counters if connections are recycled).

### Impact Explanation
This allows an unstaked/unprivileged remote attacker to bypass the intended unstaked-TPS ceiling (`MAX_UNSTAKED_TPS = 200`) and inject up to `max_connections_per_unstaked_peer × MAX_UNSTAKED_TPS` (≈1600 with defaults) transactions/sec worth of streams into a leader's TPU ingress from a single IP, consuming disproportionate leader CPU/ingress/sigverify capacity relative to staked traffic — a QoS/rate-limit evasion falling under "resource exhaustion / QoS bypass" bounty categories rather than a consensus-safety bug.

### Likelihood Explanation
Feasible for any unprivileged client: it only requires opening up to `DEFAULT_MAX_QUIC_CONNECTIONS_PER_UNSTAKED_PEER` (8) concurrent QUIC connections to the TPU port from one IP and sending streams as fast as allowed on each — no stake, keys, or special config needed. This is straightforward to reproduce deterministically and is fully within the "unstaked remote client to TPU" threat model described in scope.

### Recommendation
Aggregate unstaked (and ideally staked) stream throughput per source (e.g., per IP or `ConnectionTableKey`) rather than per individual `ConnectionStreamCounter`, e.g., by sharing one throttling counter/token bucket across all connections keyed by the same `ConnectionTableKey`, or by feeding unstaked stream counts into `StakedStreamLoadEMA`/a per-IP EMA so that `available_load_capacity_in_throttling_duration` divides the fixed unstaked budget across the peer's currently-open connections.

### Proof of Concept
Extend the existing `test_throttling_check_no_packet_drop`-style integration test in `streamer/src/nonblocking/quic.rs` to open `DEFAULT_MAX_QUIC_CONNECTIONS_PER_UNSTAKED_PEER` concurrent client connections from the same local address to one `setup_quic_server` instance, have each connection open uni-streams as fast as possible for `STREAM_THROTTLING_INTERVAL`, and assert:
```
// pseudo-code
let mut total_txs = 0;
for _ in 0..DEFAULT_MAX_QUIC_CONNECTIONS_PER_UNSTAKED_PEER {
    let conn = make_client_endpoint(&server_address, None).await;
    connections.push(conn);
}
// concurrently send max_streams_per_throttling_interval streams on each connection
// wait STREAM_THROTTLING_INTERVAL, then count packets received by `receiver`
assert!(total_txs_received <= MAX_UNSTAKED_TPS * STREAM_THROTTLING_INTERVAL_MS / 1000,
    "aggregate unstaked throughput from one IP exceeded per-IP TPS cap: {total_txs_received}");
```
Expected (buggy) result: `total_txs_received` scales linearly with the number of concurrent connections (up to 8×), violating the intended per-IP `MAX_UNSTAKED_TPS` bound.

    pub(crate) fn available_load_capacity_in_throttling_duration(
        &self,
        peer_type: ConnectionPeerType,
        total_stake: u64,
    ) -> u64 {
        match peer_type {
            ConnectionPeerType::Unstaked => self.max_unstaked_load_in_throttling_window,
            ConnectionPeerType::Staked(stake) => {
                if self.staked_throttling_enabled.load(Ordering::Relaxed) {
                    // 1 is added to `max_unstaked_load_in_throttling_window` to guarantee that staked
                    // clients get at least 1 more number of streams than unstaked connections.
                    self.max_staked_load_in_throttling_window
                        .saturating_mul(stake)
                        .checked_div(total_stake)
                        .unwrap_or(self.max_unstaked_load_in_throttling_window + 1)
                        .max(self.max_unstaked_load_in_throttling_window + 1)
                } else {
                    self.max_staked_load_in_throttling_window
                }
            }
        }
    }

pub(crate) async fn throttle_stream(
    stats: &StreamerStats,
    peer_type: ConnectionPeerType,
    remote_addr: std::net::SocketAddr,
    stream_counter: &Arc<ConnectionStreamCounter>,
    max_streams_per_throttling_interval: u64,
) {
    let throttle_interval_start = stream_counter.reset_throttling_params_if_needed();
    let streams_read_in_throttle_interval = stream_counter.stream_count.load(Ordering::Relaxed);
    if streams_read_in_throttle_interval >= max_streams_per_throttling_interval {
        // The peer is sending faster than we're willing to read. Sleep for what's
        // left of this read interval so the peer backs off.
        let throttle_duration =
            STREAM_THROTTLING_INTERVAL.saturating_sub(throttle_interval_start.elapsed());

        if !throttle_duration.is_zero() {
            debug!(
                "Throttling stream from {remote_addr:?}, peer type: {peer_type:?}, \
                 max_streams_per_interval: {max_streams_per_throttling_interval}, \
                 read_interval_streams: {streams_read_in_throttle_interval} throttle_duration: \
                 {throttle_duration:?}"
            );
            stats.throttled_streams.fetch_add(1, Ordering::Relaxed);
            match peer_type {
                ConnectionPeerType::Unstaked => {
                    stats
                        .throttled_unstaked_streams
                        .fetch_add(1, Ordering::Relaxed);
                }
                ConnectionPeerType::Staked(_) => {
                    stats
                        .throttled_staked_streams
                        .fetch_add(1, Ordering::Relaxed);
                }
            }
            sleep(throttle_duration).await;
        }
    }
