### Title
Unauthenticated Handshake Flood Causes Unbounded Cryptographic Work — No Rate Limiting on Stage-1 Handshake Processing - ([File: handshake_manager.go])

### Summary
The external report flags the absence of rate limiting on a sensitive HTTP endpoint that performs per-request expensive server-side work, allowing resource exhaustion via unauthenticated request flooding. The closest reachable analog in this codebase is the incoming Nebula handshake path: any UDP peer, without holding a CA-signed certificate, can send arbitrary stage-1 (`msg1`) handshake packets and force the responder to perform a full Noise handshake computation (ephemeral key generation, X25519 DH, state machine allocation) for every packet, with no per-source rate limiting on this operation.

### Finding Description
`HandshakeManager.HandleIncoming` in `handshake_manager.go` dispatches any packet with `h.MessageCounter == 1` (a fresh stage-1 message) directly to `beginHandshake`, gated only by the `lighthouse.remote_allow_list` IP allow-list check [1](#0-0) . That allow list is a coarse subnet-based filter, not a rate limiter, and by default (`AllowAll`) permits any source address.

`beginHandshake` then unconditionally constructs a brand-new `handshake.Machine` and calls `machine.ProcessPacket`, which performs a Noise `ReadMessage` — i.e., an ephemeral/static Diffie-Hellman computation — *before* any certificate is verified [2](#0-1) . The certificate validation (`validateCert`, invoking the CA pool verifier) only happens inside `processPayload`, which runs *after* `ReadMessage` has already completed the DH computation [3](#0-2) [4](#0-3) .

Because this path has no rate limiting, concurrency cap, or per-source cost accounting, an attacker holding no valid CA-signed certificate can repeatedly send freshly-forged stage-1 packets (any `RemoteIndex == 0`, arbitrary Noise ephemeral key bytes) to force the target to keep allocating `Machine` objects and running expensive asymmetric crypto operations on every single packet. There is no mechanism analogous to a per-IP token bucket, half-open handshake cap, or SYN-cookie-style stateless challenge to make the responder do cheap work before committing to the DH computation.

### Impact Explanation
Each forged stage-1 packet forces genuine CPU-bound asymmetric cryptography (X25519 DH) and heap allocation (`handshake.Machine`, `HostInfo`) on the responder before any authentication occurs. A flood of such packets — trivially scriptable and requiring no valid certificate — can exhaust CPU and drive up processing latency for legitimate handshakes and data-plane traffic, degrading or denying service on the affected Nebula node. This mirrors the reported bug class (unauthenticated endpoint with no rate limiting enabling resource exhaustion/DoS), but here the "endpoint" is the UDP handshake responder rather than an HTTP route, and the cost per request is cryptographic rather than a database/API lookup.

### Likelihood Explanation
Likelihood is **Medium**. The attack requires no credentials, no valid certificate, and no prior state — only the ability to send UDP packets to the node's listen port, which any of Nebula's exposed endpoints (esp. lighthouses, which must be reachable by all nodes) inherently allow. The main mitigating factor is that `beginHandshake` does not persist state for these bogus responders long-term (failed cert validation causes early return without registering a pending index at line 728-738 comment path or from `handleCheckAndCompleteError`), so the primary cost is transient CPU/allocation per packet rather than durable memory growth — but that is exactly the resource-exhaustion vector described in the source report.

### Recommendation
- Introduce per-source-IP rate limiting (token bucket) on stage-1/`msg1` handshake packets in `HandshakeManager.HandleIncoming`, dropping excess packets before invoking `beginHandshake`.
- Consider a lightweight, stateless pre-check (e.g., a cookie/puzzle mechanism) that must be satisfied before the responder performs the DH computation, similar to WireGuard's cookie reply mechanism, so unauthenticated senders cannot force expensive asymmetric crypto per packet.
- Bound the number of concurrently in-flight (unauthenticated) handshake attempts per source address/subnet.

### Proof of Concept
1. Attacker (no CA-issued certificate) crafts a UDP packet with a valid Nebula header: `Type=Handshake`, `Subtype=HandshakeIXPSK0`, `MessageCounter=1`, `RemoteIndex=0`, followed by arbitrary/garbage Noise payload bytes of sufficient length to pass `len(packet) < header.Len` check.
2. Sends this packet repeatedly (varying source port/spoofed content) to the target's UDP listen port.
3. Each packet reaches `HandshakeManager.HandleIncoming` → `beginHandshake` → `handshake.NewMachine` + `machine.ProcessPacket` → `hs.ReadMessage`, performing a full DH computation and Machine allocation regardless of whether the payload/cert later fails validation.
4. Since no rate limiter exists on this path, sustained flooding consumes CPU cycles proportional to the attacker's send rate, degrading handshake and data-plane performance for legitimate peers — the same resource-exhaustion/DoS class described in the source report, mapped onto the unauthenticated Nebula handshake responder path.

func (hm *HandshakeManager) HandleIncoming(via ViaSender, packet []byte, h *header.H) {
	// Gate on known handshake subtypes. Unknown subtypes (or future ones we
	// don't yet support) are dropped here rather than silently routed through
	// the IX path. Add a case when introducing a new pattern.
	switch h.Subtype {
	case header.HandshakeIXPSK0:
		// supported
	default:
		hm.l.Debug("dropping handshake with unsupported subtype",
			"from", via, "subtype", h.Subtype)
		return
	}

	// First remote allow list check before we know the vpnIp
	if !via.IsRelayed {
		if !hm.lightHouse.GetRemoteAllowList().AllowUnknownVpnAddr(via.UdpAddr.Addr()) {
			hm.l.Debug("lighthouse.remote_allow_list denied incoming handshake", "from", via)
			return
		}
	}

	// First message of a new handshake. The wire format requires RemoteIndex
	// to be zero here (the initiator has no responder index to fill in yet),
	// and generateIndex never allocates 0, so any non-zero RemoteIndex on a
	// stage-1 packet is malformed or someone probing for an index collision.
	// Drop without paying the cost of running noise on a pending Machine.
	if h.MessageCounter == 1 {
		if h.RemoteIndex != 0 {
			hm.l.Debug("dropping stage-1 handshake with non-zero RemoteIndex",
				"from", via, "remoteIndex", h.RemoteIndex)
			return
		}
		hm.beginHandshake(via, packet, h)
		return

func (hm *HandshakeManager) beginHandshake(via ViaSender, packet []byte, h *header.H) {
	f := hm.f
	cs := f.pki.getCertState()

	v := cs.DefaultVersion()
	if cs.GetCredential(v) == nil {
		f.l.Error("Unable to handshake with host because no certificate is available",
			"from", via, "certVersion", v)
		return
	}

	machine, err := handshake.NewMachine(
		v, cs.GetCredential,
		hm.certVerifier(), func() (uint32, error) { return generateIndex(f.l) },
		false, header.HandshakeIXPSK0,
	)
	if err != nil {
		f.l.Error("Failed to create handshake machine", "from", via, "error", err)
		return
	}

	response, result, err := machine.ProcessPacket(nil, packet)
	if err != nil {
		f.l.Error("Failed to process handshake packet", "from", via, "error", err)
		return
	}

func (m *Machine) ProcessPacket(out, packet []byte) ([]byte, *Result, error) {
	if m.failed {
		return nil, nil, ErrMachineFailed
	}
	if len(packet) < header.Len {
		return nil, nil, ErrPacketTooShort
	}
	// Reject packets whose subtype doesn't match the one this Machine was
	// built for. A pending handshake that suddenly receives a different
	// subtype on its index is either a stray packet that matched by chance
	// or a peer protocol violation; drop it without failing the Machine so
	// the legitimate retransmit can still complete.
	if header.MessageSubType(packet[1]) != m.subtype {
		return nil, nil, ErrSubtypeMismatch
	}
	if m.result.Initiator && m.hs.MessageIndex() == 0 {
		m.failed = true
		return nil, nil, ErrInitiateNotCalled
	}

	// The (eKey, dKey) ordering here is correct for IX, where the initiator
	// completes the handshake by reading the responder's stage-2 message.
	// noise returns (cs1, cs2) where cs1 is the initiator->responder cipher.
	// For 3-message patterns where a responder finishes by reading the final
	// message, this ordering would be wrong; revisit when XX/pqIX lands.
	msg, eKey, dKey, err := m.hs.ReadMessage(nil, packet[header.Len:])
	if err != nil {
		// Noise ReadMessage failed. The noise library checkpoints and rolls back
		// on failure, so the Machine is still alive. The caller can retry with
		// a different packet.
		return nil, nil, fmt.Errorf("noise ReadMessage: %w", err)
	}

	// From here on, noise state has advanced. Any error is fatal.
	flags := m.peerMsgFlags()

	if err := m.processPayload(msg, flags); err != nil {
		return nil, nil, err
	}

func (m *Machine) validateCert(payload Payload) error {
	cred := m.getCred(m.myVersion)
	if cred == nil {
		m.failed = true
		return fmt.Errorf("%w: %v", ErrNoCredential, m.myVersion)
	}
	rc, err := cert.Recombine(
		cert.Version(payload.CertVersion),
		payload.Cert,
		m.hs.PeerStatic(),
		cred.Cert.Curve(),
	)
	if err != nil {
		m.failed = true
		return fmt.Errorf("recombine cert: %w", err)
	}

	if !bytes.Equal(rc.PublicKey(), m.hs.PeerStatic()) {
		m.failed = true
		return ErrPublicKeyMismatch
	}

	// Version negotiation, if the peer sent a different version and we have it, switch
	if rc.Version() != m.myVersion {
		if m.getCred(rc.Version()) != nil {
			m.myVersion = rc.Version()
		}
	}

	verified, err := m.verifier(rc)
	if err != nil {
		m.failed = true
		return fmt.Errorf("verify cert: %w", err)
	}

	m.result.RemoteCert = verified
	m.remoteCertSet = true
	return nil
