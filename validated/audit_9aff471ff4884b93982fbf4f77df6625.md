## Finding

### Title
Protocol fee is silently bypassed for any `Nep245`/`Imt` token traded in single-unit (`|delta| <= 1`) `TokenDiff` chunks - (File: `contracts/defuse/core/src/intents/token_diff.rs`)

### Summary
`TokenDiff::token_fee()` unconditionally returns `Pips::ZERO` for `Nep245` and `Imt` token types whenever the transferred amount is `<= 1`, on the assumption that a delta of magnitude 1 always represents an "NFT-like" negligible transfer. This assumption is false for `Nep245`/`Imt` tokens, which can represent arbitrarily valuable, coarsely-denominated fungible balances (e.g. cross-`defuse` wrapped tokens, or self-minted `Imt` tokens). Any unprivileged user can therefore move unlimited nominal value through `TokenDiff` intents while paying zero protocol fee, simply by keeping every negative delta at magnitude exactly 1.

### Finding Description
In `TokenDiff::execute_intent`, the fee actually collected for a signer's `TokenDiff` is: [1](#0-0) 

which delegates to `TokenDiff::token_fee`: [2](#0-1) 

The match statement charges the configured `fee` for `Nep141` unconditionally, and for `Nep245`/`Imt` **only** if `amount > 1`; for `amount <= 1` on `Nep171`, `Nep245`, or `Imt` it returns `Pips::ZERO`. This logic is written for the `Nep171` (true single-copy NFT) case, where `amount` is always exactly `1` and genuinely represents one indivisible item — fee exemption there is sound.

However `Nep245` and `Imt` are **not** restricted to NFT-like semantics:
- `Nep245TokenId` is explicitly used to represent fungible balances wrapped from other contracts/other `defuse` instances (see cross-`defuse` wrapping tests using `Nep245TokenId::new(other_defuse_id, ft_id.to_string())`), where "amount" tracks raw units of an arbitrary underlying fungible token with its own (possibly very coarse) decimals.
- `Imt` tokens are minted permissionlessly by any signer via `ImtMint`, with the minter fully controlling the `token_id` namespace and the raw `u128` amount minted/moved — there is no decimals or per-unit-value constraint enforced on-chain: [3](#0-2) 

Because `amount` is a raw integer with no enforced relationship to real economic value, a single unit of a `Nep245`-wrapped or `Imt` token can represent arbitrarily large value. Any `TokenDiff` whose negative delta (`token_in`) is on such a token with `|delta| == 1` is charged `Pips::ZERO` fee by `supply_delta`/`token_fee`, regardless of the value actually moved: [4](#0-3) 

### Impact Explanation
This breaks the "fees owed versus fees collected" invariant: the protocol fee that should be assessed on the value of a `token_in` leg is unconditionally zeroed out based only on the *raw integer magnitude* of the delta, not the actual value transferred. An unprivileged user (no DAO/Role/relayer needed) can:
1. Use (or wrap) any coarsely-denominated, high-per-unit-value asset as a `Nep245` token id (e.g. a token wrapped from another `defuse` instance, or minted via `ImtMint`), and
2. Structure both legs of a `TokenDiff` settlement so every negative delta on that token is exactly `1`,

to move arbitrarily large nominal value through `execute_intents` while the protocol collects `0` fee on that leg — versus the correct behavior of charging `protocol_fee * amount`. This is an unauthorized reduction of protocol revenue that matches the listed Critical impact "fees bypassed."

### Likelihood Explanation
Reaching this path requires no special privileges: any account can sign a `TokenDiff` intent and any account can create/hold `Nep245`-wrapped or self-minted `Imt` balances (via the permissionless `ImtMint` intent). The only requirement is that the counterparty side of the trade also transacts in `Nep245`/`Imt` units of magnitude `≤1`, which is trivially achievable for two cooperating (or self-controlled) accounts, or for a solver quoting in such units. This makes the bypass practically reachable without gas-limit issues, since it does not require splitting a trade into many transactions — a single pair of `TokenDiff` intents each with a `|delta| == 1` `Nep245`/`Imt` leg suffices.

### Recommendation
Do not exempt `Nep245`/`Imt` tokens from fees based purely on raw magnitude `<= 1`. Fee exemption for "NFT-like" transfers should be limited to `Nep171` (which is the only type guaranteed to be single-copy/non-fungible). For `Nep245`/`Imt`, charge the protocol fee unconditionally (same as `Nep141`), or introduce an explicit, contract-enforced notion of "non-fungible multi-token" (e.g. a supply cap of 1 per `token_id`) before granting a fee exemption to those types.

### Proof of Concept
1. Attacker mints an `Imt` token (or uses a `Nep245`-wrapped representation of a coarse, high-value asset) to themselves via `ImtMint`, e.g. `amount = 1` under `imt:<attacker>:<token_id>`, or wraps a low-decimal NEP141 token as `nep245:<other_defuse>:<underlying_token>`.
2. Attacker (or an attacker-controlled second account / cooperating counterparty) signs two `TokenDiff` intents whose only negative deltas are `-1` on that `Nep245`/`Imt` token id, exchanging it for the desired value on the positive-delta side.
3. Submit both signed payloads together via `execute_intents`. In `TokenDiff::execute_intent`, `Self::token_fee(token_id, 1, protocol_fee)` returns `Pips::ZERO` for both legs (per `token_diff.rs` lines 206-216), so `fees_collected` is empty and no balance is added to `fee_collector` — despite the settlement having moved the full value of the underlying wrapped/minted asset.
4. Compare against an equivalent trade denominated in a `Nep141` token id of the same underlying value: `token_fee` would return the full configured `fee`, and `fees_collected` would be non-empty, proving the fee was bypassed solely due to the `Nep245`/`Imt` + `amount<=1` exemption.

    #[inline]
    fn supply_delta(token_id: &TokenId, delta: i128, fee: Pips) -> Option<i128> {
        if delta < 0 {
            // fee is taken only on negative deltas (i.e. token_in)
            delta.checked_mul_div_ceil(
                Self::token_fee(token_id, delta.unsigned_abs(), fee)
                    .invert()
                    .as_pips()
                    .into(),
                Pips::MAX.as_pips().into(),
            )
        } else {
            // token_out
            Some(delta)
        }
    }
