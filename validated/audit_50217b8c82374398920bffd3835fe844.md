### Title
Unauthenticated remote DoS via `POST /shutdown` on the signer event-receiver socket - (File: libsigner/src/events.rs)

### Summary
`SignerEventReceiver::next_event` dispatches any HTTP POST to `/shutdown` by unconditionally setting `stop_signal` to `true` and returning `EventError::Terminated`, with no check that the caller is the internal `SignerStopSignaler` rather than an arbitrary remote client. Any party who can reach the event-receiver port (the same port that receives `/new_block`, `/new_burn_block`, etc. from the node) can silence the signer's entire event stream with a single crafted request.

### Finding Description
The intended invariant is that `is_stopped() == true` should only be reachable via `SignerStopSignaler::send`, which is meant to be called only by the signer process itself (e.g. on shutdown) [1](#0-0) . However, the dispatch logic in `next_event` treats the URL path `/shutdown` as sufficient authorization: it matches on `request.url() == "/shutdown"` and immediately calls `event_receiver.stop_signal.store(true, Ordering::SeqCst)` followed by `Err(EventError::Terminated)`, with no signature, secret, or peer-identity check tying the request to the legitimate internal caller [2](#0-1) .

The exact call sequence is: `EventReceiver::main_loop` calls `self.next_event()` [3](#0-2) , which calls `http_server.recv()` to block for the next HTTP request and then matches on `request.url()` [4](#0-3) . Any TCP client that can connect to the bound `HttpServer` (bound via `SignerEventReceiver::bind`) and send `POST /shutdown HTTP/1.1 ...` with any body reaches the `/shutdown` branch exactly the same way the legitimate `SignerStopSignaler::send` does — the wire format constructed in `send()` (`"POST /shutdown HTTP/1.1\r\nHost: ...\r\nContent-Length: ...\r\n\r\n{body}"`) is not distinguished from any other client's identically-shaped request. Once `stop_signal` is set, `is_stopped()` returns `true` on the next loop iteration and `main_loop` breaks [3](#0-2) , permanently terminating the signer's event-receiver thread (it is not designed to restart itself).

No existing guard prevents this: there is no shared secret, no source-IP allowlist, no mTLS, and no comparison of the request against anything tied to the `SignerStopSignaler` instance that legitimately calls `send()`.

### Impact Explanation
A single unauthenticated `POST /shutdown` request permanently stops the `SignerEventReceiver::main_loop`, which is the mechanism by which the signer receives `/new_block`, `/new_burn_block`, `/stackerdb_chunks`, and `/proposal_response` events from the node's event dispatcher. Once stopped, the signer stops observing block proposals, burn blocks, and StackerDB messages, effectively blinding it without crashing the whole process — a stealthy, repeatable, single-message DoS against the signer's liveness that requires no privileges, matching the "Critical — remote crash/unauthenticated DoS from few messages" category.

### Likelihood Explanation
The only precondition is TCP reachability to the signer's bound event-receiver socket, which per the question's stated precondition is the same reachability the node's own event dispatcher uses to POST `/new_block` etc. No secret, key, or role is needed — the attacker only needs to craft one HTTP POST. The attack is trivially repeatable (each request can be sent again after any restart) and costs a single TCP connection and a few bytes.

### Recommendation
Do not treat `/shutdown` as a network-reachable HTTP endpoint. Use an in-process/loopback-only mechanism to signal termination (e.g., a local unix socket, a purely in-memory channel/condvar shared between `SignerStopSignaler` and `SignerEventReceiver`, or gating the HTTP `/shutdown` route behind a per-process random secret token generated at bind time and known only to the `SignerStopSignaler` instance). At minimum, restrict acceptance of `/shutdown` to requests originating from `127.0.0.1`/the local host when the listener is not itself loopback-bound, and require a token comparison before calling `stop_signal.store(true, ...)`.

```rust
#[test]
fn unauthenticated_shutdown_stops_event_receiver() {
    use std::net::{SocketAddr, TcpStream};
    use std::io::Write;
    use std::thread;

    let mut receiver: SignerEventReceiver<StacksTransaction /* or any T */> =
        SignerEventReceiver::new(false);
    let addr: SocketAddr = "127.0.0.1:0".parse().unwrap();
    let bound_addr = receiver.bind(addr).unwrap();

    // Run main_loop in a separate thread, exactly like the real signer does.
    let handle = thread::spawn(move || {
        receiver.main_loop(); // should only return once stop_signal is set
    });

    // Attacker: no SignerStopSignaler used at all -- raw socket, arbitrary body.
    let mut stream = TcpStream::connect(bound_addr).unwrap();
    let body = "arbitrary attacker body";
    let req = format!(
        "POST /shutdown HTTP/1.1\r\nHost: {}\r\nConnection: close\r\nContent-Length: {}\r\nContent-Type: text/plain\r\n\r\n{}",
        bound_addr, body.len(), body
    );
    stream.write_all(req.as_bytes()).unwrap();

    // Assert the main_loop thread exits solely from this unauthenticated request,
    // proving no origin/secret check gates the /shutdown path in next_event.
    handle.join().expect("main_loop should have terminated due to unauthenticated /shutdown");
}
```
