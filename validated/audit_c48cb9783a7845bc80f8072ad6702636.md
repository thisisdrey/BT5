### Title
Unbounded reference enumeration and deletion in a single transaction causes DoS - (File: internal/gitaly/service/ref/delete_refs.go)

### Summary
The `DeleteRefs` RPC accepts an `except_with_prefix` field that, unlike other reference-listing RPCs (e.g. `ListRefs`, which is paginated), triggers an **unbounded** enumeration of every reference in the repository and stages *all* non-excluded refs for deletion in a single `git update-ref` transaction, with no upper bound on count. [1](#0-0) 

### Finding Description
`refsToRemove` calls `repo.GetReferences(ctx)` to load the complete set of references and appends every one that doesn't match an excluded prefix into `refs`, with no cap on the resulting slice size. [2](#0-1) 

`DeleteRefs` then iterates over this unbounded list twice — once to validate each name and once to call `updater.Delete(ref)` plus feed each ref into a `voting.NewVoteHash()` — before calling `Prepare()` and `Commit()`, which lock and rewrite references via a single `git update-ref --stdin` process. [3](#0-2) 

This mirrors the reported bug class: an unbounded loop over a caller-influenceable collection (whitelisted tokens in the Moloch report; references in Gitaly) performed synchronously inside a single mutating operation, with no chunking, streaming, or count limit. Unlike `ListRefs`/`FindRefsByOID`/`ListBranchNamesContainingCommit`, which expose explicit `limit`/pagination parameters, `DeleteRefs`'s `except_with_prefix` code path has none. [4](#0-3) 

An ordinary authenticated Gitaly client (e.g. via `UpdateReferences`, which itself has no bound on the number of refs it can create across repeated calls) can first grow a repository to contain a very large number of loose/packed references, then issue a single `DeleteRefs` call with `except_with_prefix` set to an unmatched prefix. This forces Gitaly to enumerate, hash, and stage all of them for deletion within one RPC invocation, while holding reference locks (`Prepare()`/`Commit()`) for the full duration.

### Impact Explanation
A single unary RPC call can force Gitaly to perform O(N) work (ref enumeration, `update-ref` stdin writes, vote-hash computation, and reference locking) where N is attacker-grown and effectively unbounded. This can produce long-running requests that consume CPU/memory and hold reference locks for extended periods, degrading or blocking concurrent operations against the same repository (a DoS of the `DeleteRefs` handler and, transitively, of other reference operations on that repository) — the closest concrete, reachable analog to the reported "unbounded loop / resource exhaustion" bug class permitted by the validation rules.

### Likelihood Explanation
Reaching this requires only standard, unprivileged Gitaly RPC access already available to any client permitted to call `RefService` (the same trust level used for ordinary pushes/branch management): creating many references via existing RPCs, then calling `DeleteRefs` with `except_with_prefix`. No special privilege, leaked token, or malicious peer is required, and the `refs` field variant of the same RPC is at least partially bounded by gRPC message size, but the `except_with_prefix` variant is not bounded at all.

### Recommendation
- Enforce a maximum reference count (or require pagination/batching) for the `except_with_prefix` deletion path in `refsToRemove`, mirroring the `limit` pattern already used by `ListRefs`/`FindRefsByOID`. [5](#0-4) 
- Alternatively, reject `DeleteRefs` requests using `except_with_prefix` when the resulting deletion set exceeds a configured threshold, returning an `InvalidArgument`/`ResourceExhausted` error instructing the caller to narrow the prefix or batch the operation.
- Consider chunking large deletions into multiple smaller `update-ref` transactions to bound per-call lock hold time.

### Proof of Concept
1. As an ordinary authenticated client, repeatedly call `UpdateReferences` to create a very large number of references (e.g. hundreds of thousands of `refs/keep-around/*` or similar) in a target repository. [6](#0-5) 
2. Call `DeleteRefs` with `except_with_prefix: ["refs/heads/nonexistent-prefix"]`, which excludes nothing and therefore selects all created references for deletion. [7](#0-6) 
3. Observe that the single RPC call must enumerate, hash, and stage every reference for deletion, holding reference locks for the whole operation, degrading Gitaly's responsiveness for that repository until the call completes.

func (s *server) refsToRemove(ctx context.Context, repo *localrepo.Repo, req *gitalypb.DeleteRefsRequest) ([]git.ReferenceName, error) {
	if len(req.GetRefs()) > 0 {
		refs := make([]git.ReferenceName, len(req.GetRefs()))
		for i, ref := range req.GetRefs() {
			refs[i] = git.ReferenceName(ref)
		}
		return refs, nil
	}

	prefixes := make([]string, len(req.GetExceptWithPrefix()))
	for i, prefix := range req.GetExceptWithPrefix() {
		prefixes[i] = string(prefix)
	}

	existingRefs, err := repo.GetReferences(ctx)
	if err != nil {
		return nil, err
	}

	var refs []git.ReferenceName
	for _, existingRef := range existingRefs {
		if hasAnyPrefix(existingRef.Name.String(), prefixes) {
			continue
		}

		refs = append(refs, existingRef.Name)
	}

	return refs, nil
}

message DeleteRefsRequest{
  // repository is the repository that reference is deleted from.
  Repository repository = 1 [(target_repository)=true];
  // except_with_prefix is the prefix used to determine which references to exclude from being deleted.
  // This field can not be set in combination with the refs field. If the refs field is not set, except_with_prefix
  // must contain at least one prefix as deleting all references in not allowed.
  repeated bytes except_with_prefix = 2; // protolint:disable:this REPEATED_FIELD_NAMES_PLURALIZED
  // refs is the list of references to be deleted. This field can not be set in combination with except_with_prefix
  // and cannot be empty if except_with_prefix is also empty.
  repeated bytes refs = 3;
}

func (s *server) UpdateReferences(server gitalypb.RefService_UpdateReferencesServer) error {
	ctx := server.Context()

	request, err := server.Recv()
	if err != nil {
		return fmt.Errorf("receiving initial request: %w", err)
	}

	if err := s.locator.ValidateRepository(ctx, request.GetRepository()); err != nil {
		return err
	}
	repo := s.localRepoFactory.Build(request.GetRepository())

	objectHash, err := repo.ObjectHash(ctx)
	if err != nil {
		return fmt.Errorf("detecting object hash: %w", err)
	}

	// Unset the repository so that we can more easily verify inside of the loop that all incoming requests
	// ain't got a repository set anymore.
	request.Repository = nil

		return fmt.Errorf("creating updater: %w", err)
