### Title
Arbitrary-repository alternates linkage bypasses pool restriction during partition assignment - ([File: internal/gitaly/storage/storagemgr/partition_assigner.go])

### Summary
`getAlternatePartitionID` reads a repository's `objects/info/alternates` file and, after path validation, merges that repository's partition with whatever relative path the alternate resolves to, without checking that the target is an actual object pool (`storage.IsPoolRepository`). However, exploiting this requires the attacker to control the *content* of `objects/info/alternates` for a repository under their control, and I could not confirm any unprivileged, Gitaly-reachable RPC path that lets an attacker write arbitrary content into that specific file — the only code path that writes it (`Link` in `internal/git/objectpool/link.go`) computes the path itself from the pool repository rather than accepting attacker-controlled content, and it is normally invoked with an already-validated pool relative path (`objectpool` gRPC service, gated by GitLab Rails' internal object-pool management).

### Finding Description
`getAlternatePartitionID` at [1](#0-0)  only rejects a self-referencing alternate (`alternateRelativePath == relativePath`) and a chained alternate (`recursiveCall`), but never checks `storage.IsPoolRepository` on the resolved target. This is confirmed by the existing test `TestPartitionAssigner_alternates`, which explicitly demonstrates a non-pool-named repository (`"pool"`, which does not match `railsPoolDirRegexp`/`praefectPoolDirRegexp`) successfully being merged into the same partition as `"member"` via an alternates entry `"../../pool/objects"` [2](#0-1) . The relative-path validation (`storage.ValidateRelativePath`) only prevents escaping the storage root, not pointing to an arbitrary sibling repository.

However, this function is not attacker-input-reachable in the way the question assumes. The alternates file is not attacker-writable content coming through Git push objects, pack processing, or fetch/import RPCs — Git object data (blobs/trees/commits) is stored under `objects/<sha>` or in packfiles, not as the plain `objects/info/alternates` text file, and Gitaly's push/receive-pack handling does not write attacker pack content into that file. The only in-repo code that legitimately writes `objects/info/alternates` is `Link` in `internal/git/objectpool/link.go`, which computes the alternates content itself from the object pool's own repository path (`getRelativeObjectPath`), it is not derived from any attacker-supplied string [3](#0-2) . The `Link`/`LinkRepositoryToObjectPool` RPC is invoked with a pool repository resolved by GitLab Rails (which is responsible for choosing/creating legitimate object pools per fork network) — an unprivileged user does not directly control which relative path is treated as the "pool" in that call. I was not able to find an RPC that lets an attacker specify literal alternates file content or a client-chosen "pool" path that Gitaly will then treat as authoritative without going through the fork/pool creation flow that GitLab Rails controls.

I also could not confirm within the available index whether other repository-creation paths (e.g., `CreateRepositoryFromSnapshot`, which extracts an attacker/administrator-supplied tar archive via `s.untar` directly into the new repository directory [4](#0-3) ) are reachable by an unprivileged, non-admin GitLab user in the current architecture — this RPC is documented as trusting the archive "a lot" and is normally used only for internal Gitaly-to-Gitaly repository moves, not for a general user-facing import flow, and its access is gated by GitLab Rails/internal auth rather than exposed directly to end users.

### Impact Explanation
If an attacker *could* control alternates file content (unconfirmed reachability), the missing `IsPoolRepository` check would let them merge their repository's partition with an arbitrary sibling repository's partition, potentially exposing that repository's objects (cross-tenant object leakage) once the transaction manager treats them as co-located. This would match a cross-tenant data disclosure impact class if a write path existed.

### Likelihood Explanation
Low/unconfirmed. The precondition — "attacker can write/modify their own repository's `objects/info/alternates` file content" — is not demonstrated to be reachable via any unprivileged GitLab RPC in this codebase. The only writer of that file (`Link`) derives content from the trusted pool path, not from attacker input, and pool linkage is orchestrated by GitLab Rails, not by an arbitrary end user. Without a concrete, unprivileged write primitive into `objects/info/alternates`, the described attack chain (craft alternates → call `Begin`) is not currently exploitable given the traced code.

### Recommendation
Even absent a confirmed write primitive, defense-in-depth is warranted: `getAlternatePartitionID` should validate that `alternateRelativePath` satisfies `storage.IsPoolRepository` before merging partitions, rejecting alternates that point to non-pool repositories, matching the invariant already assumed elsewhere (e.g., `internal/git/objectpool/pool.go`'s `FromRepo`, which validates the resolved object pool repository via `locator.ValidateRepository`).

### Proof of Concept
Not provided — reachability of attacker-controlled alternates file content via an unprivileged GitLab RPC could not be established from the available code, so a concrete RPC-level PoC cannot be constructed. The unit-level behavior (non-pool target accepted) is demonstrated in the existing test at [2](#0-1) , but this alone does not establish attacker reachability.

func (pa *partitionAssigner) getAlternatePartitionID(ctx context.Context, relativePath string, recursiveCall bool, partitionHint storage.PartitionID) (storage.PartitionID, error) {
	alternate, err := gitstorage.ReadAlternatesFile(filepath.Join(pa.storagePath, relativePath))
	if err != nil {
		return 0, fmt.Errorf("read alternates file: %w", err)
	}

	if recursiveCall {
		// recursive being true indicates we've arrived here through another repository's alternate.
		// Repositories in Gitaly should only have a single alternate that points to the repository's
		// pool. Chains of alternates are unexpected and could go arbitrarily long, so fail the operation.
		return 0, storage.ErrAlternateHasAlternate
	}

	// The relative path should point somewhere within the same storage.
	alternateRelativePath, err := storage.ValidateRelativePath(
		pa.storagePath,
		// Take the relative path to the repository, not 'repository/objects'.
		filepath.Dir(
			// The path in alternates file points to the object directory of the alternate
			// repository. The path is relative to the repository's own object directory.
			filepath.Join(relativePath, "objects", alternate),
		),
	)
	if err != nil {
		return 0, fmt.Errorf("validate relative path: %w", err)
	}

	if alternateRelativePath == relativePath {
		// The alternate must not point to the repository itself. Not only is it non-sensical
		// but it would also cause a dead lock as the repository is locked during this call
		// already.
		return 0, storage.ErrAlternatePointsToSelf
	}

func Link(ctx context.Context, pool, repo *localrepo.Repo, txManager transaction.Manager) (returnedErr error) {
	altPath, err := repo.InfoAlternatesPath(ctx)
	if err != nil {
		return err
	}

	expectedRelPath, err := getRelativeObjectPath(ctx, pool, repo)
	if err != nil {
		return err
	}

	linked, err := linkedToRepository(ctx, pool, repo)
	if err != nil {
		return err
	}

	if linked {
		// When the repository is already linked to the repository, cast a vote to ensure the
		// repository is consistent with the other replicas.
		if err := transaction.VoteOnContext(ctx, txManager, voting.VoteFromData([]byte("repository linked")), voting.Synchronized); err != nil {
			return fmt.Errorf("vote on linked repository: %w", err)
		}

		return nil
	}

	alternatesWriter, err := safe.NewLockingFileWriter(altPath)
	if err != nil {
		return fmt.Errorf("creating alternates writer: %w", err)
	}
	defer func() {
		if err := alternatesWriter.Close(); err != nil && returnedErr == nil {
			returnedErr = fmt.Errorf("closing alternates writer: %w", err)
		}
	}()

	if _, err := io.WriteString(alternatesWriter, expectedRelPath); err != nil {
		return fmt.Errorf("writing alternates: %w", err)
	}

func (s *server) untar(ctx context.Context, path string, in *gitalypb.CreateRepositoryFromSnapshotRequest) error {
	req, err := http.NewRequestWithContext(ctx, "GET", in.GetHttpUrl(), nil)
	if err != nil {
		return structerr.NewInvalidArgument("Bad HTTP URL: %w", err)
	}

	client := httpClient
	if resolvedAddress := in.GetResolvedAddress(); resolvedAddress != "" {
		client, err = newResolvedHTTPClient(in.GetHttpUrl(), resolvedAddress)
		if err != nil {
			return structerr.NewInvalidArgument("creating resolved HTTP client: %w", err)
		}
	}

	if in.GetHttpAuth() != "" {
		req.Header.Set("Authorization", in.GetHttpAuth())
	}

	rsp, err := client.Do(req)
	if err != nil {
		return structerr.NewInternal("HTTP request failed: %w", err)
	}
	defer rsp.Body.Close()

	if rsp.StatusCode < http.StatusOK || rsp.StatusCode >= http.StatusMultipleChoices {
		return structerr.NewInternal("HTTP server: %s", rsp.Status)
	}

	cmd, err := command.New(ctx, s.logger, []string{"tar", "-C", path, "-xvf", "-"}, command.WithStdin(rsp.Body))
	if err != nil {
		return err
	}

	return cmd.Wait()
}
