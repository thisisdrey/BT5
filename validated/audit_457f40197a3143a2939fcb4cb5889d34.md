### Title
Attachment content hash never verified against the requested `content_hash`, permanently stalling BNS resolution while poisoning the attachments store - ([File: stackslib/src/net/atlas/download.rs])

### Summary
`AttachmentsBatchStateContext::extend_with_attachments` accepts any HTTP-200 attachment body from a peer without checking that its `Hash160` matches the `AttachmentRequest.content_hash` that was actually requested. The subsequent `Done` branch in `AttachmentsDownloader::run` then indexes and resolves using `attachment.hash()` — the hash of the *served bytes* — instead of the original missing `content_hash`, so a malicious peer can serve unrelated bytes to poison the atlas DB while leaving the real, requested attachment forever unresolved.

### Finding Description
`get_prioritized_attachments_requests` builds an `AttachmentRequest{ content_hash, .. }` for each attachment instance that is missing content, keyed by the on-chain-committed `AttachmentInstance.content_hash` [1](#0-0) . When the HTTP response comes back, `extend_with_attachments` decodes it and inserts the resulting `Attachment` into `self.attachments` — a `HashSet<Attachment>` — with **no comparison at all** between the decoded attachment's hash and `request.content_hash`: [2](#0-1) 

Then, in `AttachmentsDownloader::run`'s `Done(ref mut context)` arm, every attachment is looked up and resolved strictly by `attachment.hash()` (i.e., `Hash160` of the bytes the peer actually sent), never by the `content_hash` that was originally requested: [3](#0-2) 

Because `Hash160` is preimage-resistant but not checked at all here, a malicious peer answering an `AttachmentRequest` for `content_hash = H` can return arbitrary bytes `B` with `Hash160(B) = H' ≠ H`. The code:
1. Calls `find_all_attachment_instances(&H')`, which returns no matching confirmed `AttachmentInstance` (since no committed name operation references `H'`) — so `resolved_attachments` stays empty for this item and it is never surfaced to BNS name-resolution logic.
2. Calls `insert_instantiated_attachment(&B)`, permanently storing the junk bytes under `H'` in the atlas DB.
3. Calls `context.attachments_batch.resolve_attachment(&H')` — resolving the wrong key. The true missing entry keyed by `H` in `attachments_batch.attachments_instances` is untouched, so `has_fully_succeed()` stays `false` forever for that entry [4](#0-3) .

No other guard in this path (DNS resolution, HTTP status check, `report.bump_successful_requests()`) verifies content integrity — the 404 check only screens out explicit not-found responses [5](#0-4) , and nothing downstream re-checks the hash.

### Impact Explanation
The batch is repeatedly re-queued and retried against the same or other peers up to `max_attachment_retry_count`, after which it is dropped [4](#0-3) ; either way, the real attachment content committed by a confirmed name operation is never resolved, so BNS name resolution for that record never completes (indefinite pending state). Simultaneously, every malicious response permanently inserts unrelated bytes into the atlas attachments table via `insert_instantiated_attachment`, growing storage with junk that is never linked to any instance. This is a state-integrity/availability issue matching the "attachment/BNS mismatch" High-severity category — no crash or unauthorized write to consensus state, but the node serves/stores wrong attachment state and never converges to the canonical one.

### Likelihood Explanation
Any unprivileged remote peer that is selected as a source (appears in `context.peers`/is an outbound sync peer with a data URL) and is asked for a given `content_hash` can trivially trigger this by returning an HTTP 200 response with arbitrary body content instead of 404. No secret, signature, or privileged role is needed — this is exactly the "attacker connects to P2P/RPC and returns crafted bytes" threat model. It is fully repeatable per attachment request and requires no special timing or node state beyond the attachment already being tracked as missing.

### Recommendation
In `AttachmentsBatchStateContext::extend_with_attachments`, verify `response.attachment.hash() == request.content_hash` before inserting into `self.attachments`; treat a mismatch as a failed request (`report.bump_failed_requests()`), not a success. Additionally/alternatively, in the `Done` branch of `AttachmentsDownloader::run`, use the original `request.content_hash` (not `attachment.hash()`) as the key for `find_all_attachment_instances`, `insert_instantiated_attachment`, and `resolve_attachment`, and reject/skip attachments whose content hash doesn't match what was requested.

### Proof of Concept
Rust net test plan (`stackslib/src/net/atlas/tests.rs`):
1. Set up an `AttachmentsBatch` with one `AttachmentInstance` whose `content_hash = H` (derived from real content the "network" considers canonical/committed).
2. Drive the `AttachmentsBatchStateMachine` through `Initialized -> DNSLookup -> DownloadingAttachmentsInv -> DownloadingAttachment`, mocking a peer HTTP server that, for the `GetAttachment` request for `H`, returns HTTP 200 with an unrelated payload `B` (`Hash160(B) = H' != H`).
3. Call `try_proceed` to reach `Done`, then run the equivalent of `AttachmentsDownloader::run`'s `Done` handling.
4. Assert `context.attachments_batch.has_fully_succeed() == false` after the cycle despite reaching `Done`.
5. Query `atlasdb` directly: assert a row exists in the `attachments` table with hash `H'` (via `find_attachment`/`insert_instantiated_attachment` side effect) while no row in `attachment_instances` references `H'`, and the original instance for `H` remains unresolved (`find_all_attachment_instances(&H)` still returns the instance as pending).

    pub fn get_prioritized_attachments_requests(&self) -> BinaryHeap<AttachmentRequest> {
        let mut queue = BinaryHeap::new();
        let mut enqueued = HashSet::new();
        for ((contract_id, pages, _), peers_responses) in self.inventories.iter() {
            let missing_attachments = match self
                .attachments_batch
                .attachments_instances
                .get(contract_id)
            {
                None => continue,
                Some(missing_attachments) => missing_attachments,
            };
            // Note: we're getting missing_attachments (attachment_id: content_hash)
            for (attachment_index, content_hash) in missing_attachments.iter() {
                let page_index = attachment_index / AttachmentInstance::ATTACHMENTS_INV_PAGE_SIZE;
                // Since there's a limit in the number of pages that a node can request,
                // we can potentially have multiple inventory request at once.
                if !pages.contains(&page_index) {
                    continue;
                }

                if enqueued.contains(content_hash) {
                    debug!("Atlas: {} already enqueued", content_hash);
                    continue;
                }

                let mut sources = HashMap::new();
                let position_in_page =
                    attachment_index % AttachmentInstance::ATTACHMENTS_INV_PAGE_SIZE;

                for (peer_url, response) in peers_responses.iter() {
                    // Considering the response, look for the page with the index
                    // we're looking for.
                    let search_page = response.pages.iter().find(|page| page.index == page_index);

                    let has_attachment = search_page
                        .and_then(|search_page| {
                            search_page.inventory.get(position_in_page as usize)
                        })
                        .map(|result| *result == 1)
                        .unwrap_or(false);

                    if !has_attachment {
                        debug!(
                            "Atlas: peer does not have attachment ({}, {}) in its inventory {:?}",
                            page_index, position_in_page, response.pages
                        );
                        continue;
                    }

                    let report = self
                        .peers
                        .get(peer_url)
                        .expect("Atlas: unable to retrieve reliability report for peer");
                    sources.insert(peer_url.clone(), report.clone());
                }

                if sources.is_empty() {
                    warn!("Atlas: could not find a peer including attachment in its inventory");
                    continue;
                }

                // Success, we found at least one inventory including the attachment we're looking for.
                let request = AttachmentRequest {
                    sources,
                    content_hash: content_hash.clone(),
                    stacks_block_height: self.attachments_batch.stacks_block_height,
                    canonical_stacks_tip_height: self.attachments_batch.canonical_stacks_tip_height,
                };
                enqueued.insert(content_hash);
                queue.push(request);
            }

    pub fn extend_with_attachments(
        mut self,
        results: &mut BatchedRequestsResult<AttachmentRequest>,
    ) -> AttachmentsBatchStateContext {
        for (request, response) in results.succeeded.drain() {
            let report = self
                .peers
                .get_mut(request.get_url())
                .expect("Atlas: unable to retrieve reliability report for peer");

            let response = if let Some(r) = response {
                r
            } else {
                report.bump_failed_requests();
                continue;
            };

            if let Ok(response) = response.decode_atlas_get_attachment() {
                self.attachments.insert(response.attachment);
                report.bump_successful_requests();
            } else {
                report.bump_failed_requests();
            }
        }
        let mut events_ids = results.faulty_peers.keys().copied().collect::<Vec<usize>>();
        self.events_to_deregister.append(&mut events_ids);

        self
    }
