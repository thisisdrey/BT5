### Title
Protocol fee bypass on `Nep245`/`Imt` token transfers via 1-unit `TokenDiff` splitting - (File: contracts/defuse/core/src/intents/token_diff.rs)

### Summary
`TokenDiff::token_fee` exempts any `Nep245`/`Imt` delta with `amount <= 1` from protocol fees, and this check is evaluated independently per `TokenDiff::execute_intent` call rather than on the aggregated net position of a token across a batch. Two colluding (or attacker-controlled) accounts can move an arbitrary quantity of a multi-token asset by splitting it into many unit-sized `TokenDiff` intents inside a single signed `MultiPayload`, paying zero fee, whereas the equivalent single-intent transfer would incur `Pips::fee_ceil(net_amount) > 0`.

### Finding Description
The broken binding is:
`fee_collected_across_batch(T) == protocol_fee.fee_ceil(net_negative_delta(T))`, aggregated over the whole batch.

In practice it is evaluated per-intent instead: [1](#0-0) 

The fee amount for negative deltas is computed via `Self::token_fee(token_id, amount, protocol_fee).fee_ceil(amount)`, where `token_fee` explicitly zeroes out fees on `Nep245`/`Imt` tokens whenever the per-intent `amount <= 1`: [2](#0-1) 

Within a single `TokenDiff` intent, the `diff: BTreeMap<TokenId, i128>` prevents splitting the same token into multiple entries. However, `DefuseIntents::intents` is a `Vec<Intent>`, so a single signer (or multiple signers) can submit many separate `TokenDiff` intents in one `MultiPayload`, each moving exactly 1 unit of the same `Nep245TokenId`. `Engine::execute_signed_intent` calls `intents.execute_intent` once per signed payload, and each `TokenDiff` intent independently snapshots `protocol_fee` and accumulates its own `fees_collected`, which is added to the fee collector immediately — there is no batch-level aggregation of `fees_collected` by token: [3](#0-2) 

The only cross-intent invariant enforced is that total deposits/withdrawals per token across the whole batch net to zero (via `TransferMatcher::finalize`); it does not check or aggregate fee accounting: [4](#0-3) 

Exploit flow: attacker controls two Verifier accounts A and B (or colludes with a second account). A holds `N` units of an `Nep245` token `T` (`N > 1`, `protocol_fee > 0`). A signs `N` separate `TokenDiff` intents each with `diff = {T: -1}`; B signs `N` separate `TokenDiff` intents each with `diff = {T: +1}`. All `2N` intents are submitted together as a `Vec<MultiPayload>` to `execute_intents`. Each negative-delta intent has `amount = 1`, so `token_fee` returns `Pips::ZERO`, and `fee_ceil(1) * 0 = 0` for every one of the `N` withdrawal intents. `TransferMatcher::finalize` matches A's withdrawals against B's deposits (net zero per token), so the batch passes the invariant check and the intents settle. Total fee collected across the batch is `0`, whereas a single `TokenDiff{T: -N}` intent would have paid `protocol_fee.fee_ceil(N) > 0`.

No existing guard prevents this: `MultiPayload::verify`, `has_public_key`, `verify_intent_nonce`, and `TransferMatcher::finalize` all check signature validity, nonce validity, and balance conservation — none of them re-aggregate or re-derive fees from the net per-token delta across intents.

### Impact Explanation
This is a protocol fee bypass: any pair of colluding/attacker-controlled accounts can transfer arbitrary amounts of `Nep245`/`Imt` multi-token assets through the Verifier while paying zero protocol fee, by splitting the transfer into unit-sized `TokenDiff` intents in one transaction. This directly matches the Critical impact category "protocol fees bypassed or over-collected." It is fully repeatable across any `Nep245`/`Imt` `TokenId` and any account pair, and scales linearly with the number of split intents (bounded only by gas, which is out of scope for rejection here but limits the practical `N` per transaction).

### Likelihood Explanation
Preconditions are minimal and fully within an unprivileged attacker's reach: two self-controlled accounts, a deposited/held balance of any `Nep245` token, and `protocol_fee > 0` (a typical deployment configuration). No role, relayer key, or DAO action is needed. The attacker only needs to construct and sign `2N` small `TokenDiff` intents (cheap to generate offline) and submit them in one `execute_intents` call.

### Recommendation
Aggregate the fee-relevant amount per `TokenId` across all `TokenDiff` intents in the batch (or across all intents for a given signer/token) before applying the `amount <= 1` fee exemption in `TokenDiff::token_fee`, e.g. by computing fees during `TransferMatcher::finalize` on the net matched/unmatched deltas per token rather than per individual intent's per-token delta.

### Proof of Concept
`cargo test` (near-workspaces sandbox, extending `tests/src/tests/defuse/intents/token_diff.rs`):
1. Deploy Verifier, create two users A and B, deposit `N = 100` units of an `Nep245` token `T` (e.g. wrap an owned MT contract) to A's Verifier balance, `protocol_fee = Pips::ONE_PERCENT`.
2. Batch 1: build a `MultiPayload` with 100 `TokenDiff` intents signed by A (`diff = {T: -1}` each) and 100 signed by B (`diff = {T: +1}` each); call `execute_intents`. Assert `mt_balance_of(fee_collector, T) == 0` and A's balance decreased by 100, B's increased by 100.
3. Batch 2 (control): reset balances, build a single `TokenDiff` intent per side with `diff = {T: -100}` (A) and `{T: +100}` (B, adjusted via `TokenDiff::closure_delta` for the fee); call `execute_intents`. Assert `mt_balance_of(fee_collector, T) == protocol_fee.fee_ceil(100) > 0`.
4. Assert the two fee_collector balances differ (`0` vs `> 0`), proving the same net token movement yields different collected fees depending on how the diff is split across intents.

    fn execute_signed_intent(&mut self, signed: MultiPayload) -> Result<()> {
        // verify signed payload and get public key
        let public_key = signed.verify().ok_or(DefuseError::InvalidSignature)?;

        // calculate intent hash
        let hash = signed.hash();

        // extract NEP-413 payload
        let DefusePayload::<DefuseIntents> {
            signer_id,
            verifying_contract,
            deadline,
            nonce,
            message: intents,
        } = signed.extract_defuse_payload()?;

        // check recipient
        if verifying_contract != *self.state.verifying_contract() {
            return Err(DefuseError::WrongVerifyingContract);
        }

        self.inspector.on_deadline(deadline);

        // make sure message is still valid
        if deadline < Timestamp::now() {
            return Err(DefuseError::DeadlineExpired);
        }

        // make sure the account has this public key
        if !self.state.has_public_key(&signer_id, &public_key) {
            return Err(DefuseError::PublicKeyNotExist(signer_id, public_key));
        }

        // commit nonce
        self.verify_intent_nonce(nonce, deadline)?;
        self.state.commit_nonce(signer_id.clone(), nonce)?;

        intents.execute_intent(&signer_id, self, hash)?;
        self.inspector.on_intent_executed(&signer_id, hash, nonce);

        Ok(())
    }

    // Finalizes all transfers, or returns unmatched deltas.
    // If unmatched deltas overflow, then Err(None) is returned.
    pub fn finalize(self) -> Result<Transfers, InvariantViolated> {
        let mut transfers = Transfers::default();
        let mut deltas = TokenDeltas::default();
        for (token_id, transfer_matcher) in self.0 {
            if let Err(unmatched) = transfer_matcher.finalize_into(&token_id, &mut transfers)
                && (unmatched == 0 || deltas.apply_delta(token_id, unmatched).is_none())
            {
                return Err(InvariantViolated::Overflow);
            }
        }
        if !deltas.is_empty() {
            return Err(InvariantViolated::UnmatchedDeltas {
                unmatched_deltas: deltas,
            });
        }
        Ok(transfers)
    }
