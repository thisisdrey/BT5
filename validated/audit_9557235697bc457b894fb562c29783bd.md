Audit Report

## Title
User-controlled `gas` field in `Command::CallContract` is trusted without a minimum bound, enabling guaranteed-fail destination execution for Snowbridge outbound messages - (File: `bridges/snowbridge/primitives/outbound-queue/src/v2/message.rs`)

## Summary
`ConstantGasMeter::maximum_dispatch_gas_used_at_most` computes a fixed, protocol-chosen gas figure for every `Command` variant except `Command::CallContract`, where the gas value is passed through verbatim from the caller-supplied field with no floor enforced [1](#0-0) . This value is decoded from an XCM `Transact` payload during outbound message conversion and flows unmodified into `OutboundCommandWrapper.gas` and the committed `CommandWrapper.gas` that Ethereum's Gateway uses to bound forwarded gas [2](#0-1) [3](#0-2) .

## Finding Description
`Command::CallContract { target, calldata, gas, value }` carries a `gas: u64` field defined directly in the primitive type [4](#0-3) . Unlike every other command variant, which is assigned a fixed protocol constant (`SetOperatingMode`: 40_000, `Upgrade`: 50_000 + initializer cost, `UnlockNativeToken`: 200_000, `RegisterForeignToken`: 1_200_000, `MintForeignToken`: 100_000), `CallContract`'s gas is taken verbatim as `*gas_limit` with zero validation [1](#0-0) .

The `gas` field originates from an XCM `Transact` instruction decoded via `ContractCall::decode_all` inside `XcmConverter::convert`, and the decoded `gas` is placed directly into `Command::CallContract` with no lower bound check [2](#0-1) . This converted message is committed by `do_process_message` in the outbound-queue-v2 pallet, which computes `gas: T::GasMeter::maximum_dispatch_gas_used_at_most(&command)` and stores the value unchanged into `Messages` and the ABI-encoded `MessageLeaves` merkle commitment [5](#0-4) . No code in this path enforces a floor on `gas`.

However, verifying full unprivileged exploitability required checking who can set the `AliasOrigin` used to authorize this XCM path. The converter enforces `ensure!(AllowedAliasOrigin::contains(origin_location), InvalidOrigin)` before accepting the message [6](#0-5) , and the `EthereumBlobExporter` additionally restricts this whole V2 export path to messages originating from AssetHub (`para_id != AssetHubParaId::get()` is rejected) [7](#0-6) . The concrete `AllowedAliasOrigin` type binding used in the live runtime (i.e., which specific `Location`s AssetHub permits to alias, and thus which users can reach `CallContract` with an arbitrary `gas`) could not be located in the indexed codebase — no runtime configuration setting `type AllowedAliasOrigin = ...` was found via search. This is the same gap noted in the original claim: the missing-minimum-gas defect in `ConstantGasMeter`/`do_process_message` itself is verified and real, but whether an ordinary unprivileged user (versus a governance-gated or otherwise-restricted alias origin) can supply the `gas` value on the live BridgeHub/AssetHub runtime wiring remains unverified from the index.

## Impact Explanation
The underlying code defect — `Command::CallContract`'s `gas` being trusted without a protocol-enforced minimum, in contrast to every other command's hardcoded gas constant — is confirmed in `ConstantGasMeter::maximum_dispatch_gas_used_at_most` [8](#0-7) . If reachable by an unprivileged alias origin, this allows a caller to under-fund the gas committed for a cross-chain call, causing the forwarded Ethereum execution to guaranteed-revert while the commitment/settlement machinery on the Substrate side proceeds normally (nonce increment, merkle commitment) regardless of whether the destination call can possibly succeed [9](#0-8) . This repository does not contain the Ethereum Gateway Solidity contract, so the delivery-receipt/relayer-reward mechanics referenced in the original claim (i.e., whether the Gateway marks delivery as settled independent of forwarded-call success) could not be verified from this index; that part of the impact narrative rests on the external LayerZero-analogy reasoning rather than on code inspected here. As stated in the original claim itself, this is a per-nonce message that fails, not a "permanently blocking channel" state — so even if fully verified, the severity would be bounded to guaranteed-fail dispatch/fee mischarging for a single message, not a systemic bridge lockup.

## Likelihood Explanation
Likelihood cannot be confirmed as High for unprivileged exploitation. The `gas` value is unconditionally accepted by `ConstantGasMeter` and `do_process_message` with no minimum-floor check — that part is code-certain. But reaching this code path requires passing `AllowedAliasOrigin::contains(origin_location)` in the XCM converter and originating from AssetHub via the `EthereumBlobExporter`, and the concrete production binding of `AllowedAliasOrigin` (i.e., whether it permits arbitrary end-user accounts to alias, or only privileged/system origins) was not found in the indexed runtime configuration. Without that binding, it is not possible to confirm this is reachable by an "unprivileged external attacker using public extrinsics" as required by the impact gate, rather than by a privileged or restricted origin.

## Recommendation
Enforce a protocol-defined minimum gas floor for `Command::CallContract` inside `ConstantGasMeter::maximum_dispatch_gas_used_at_most` (e.g., reject or clamp `gas` below a `MIN_CALL_CONTRACT_GAS` constant), mirroring the fixed minimums already used for other commands, and validate this either in the XCM converter (`convert.rs`) before the command is constructed or in `do_process_message` before commitment. Additionally, the exact production `AllowedAliasOrigin` binding should be reviewed to confirm what class of origin can set `gas` for `CallContract`, since severity/likelihood scoring materially depends on it.

## Proof of Concept
1. Construct an XCM message containing `AliasOrigin(origin)` where `origin` passes the deployed `AllowedAliasOrigin` filter, followed by a `Transact` instruction encoding `ContractCall::V1 { target, calldata, gas: 1, value }`.
2. Route this XCM through `EthereumBlobExporter::validate`/`deliver` (AssetHub → BridgeHub path) as shown in `bridges/snowbridge/primitives/outbound-queue/src/v2/converter/mod.rs`.
3. Observe that `XcmConverter::convert` accepts `gas: 1` unchanged into `Command::CallContract` [10](#0-9) , and that `do_process_message` commits `gas: 1` into `MessageLeaves` via `ConstantGasMeter::maximum_dispatch_gas_used_at_most` [3](#0-2)  with no error raised.
4. This confirms the missing-floor defect exists in-repo; confirming full unprivileged reachability requires locating and inspecting the concrete `AllowedAliasOrigin` type used in the deployed AssetHub/BridgeHub runtime, which was not found in this index.

impl GasMeter for ConstantGasMeter {
	fn maximum_dispatch_gas_used_at_most(command: &Command) -> u64 {
		match command {
			Command::SetOperatingMode { .. } => 40_000,
			Command::Upgrade { initializer, .. } => {
				// total maximum gas must also include the gas used for updating the proxy before
				// the the initializer is called.
				50_000 + initializer.maximum_required_gas
			},
			Command::UnlockNativeToken { .. } => 200_000,
			Command::RegisterForeignToken { .. } => 1_200_000,
			Command::MintForeignToken { .. } => 100_000,
			Command::CallContract { gas: gas_limit, .. } => *gas_limit,
		}
