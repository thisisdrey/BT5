### Title
Missing content-hash verification on Atlas attachment responses allows a malicious peer to poison `resolve_attachment`, permanently starving BNS name resolution for the requested hash - (File: `stackslib/src/net/atlas/download.rs`)

### Summary
`AttachmentsBatchStateContext::extend_with_attachments` accepts any `GetAttachmentResponse` a peer returns for an `AttachmentRequest` without checking that the returned attachment's content actually hashes to the requested `content_hash`. The `AttachmentsDownloader::run` loop then resolves the batch using `attachment.hash()` (computed from the attacker-supplied bytes) instead of the originally-requested hash, so the entry for the legitimately committed content hash is never marked resolved.

### Finding Description
The claimed equality is: `Hash160::from_data(returned_bytes) == requested content_hash H`. This is never checked anywhere in the path.

1. `AttachmentsBatchStateContext::get_prioritized_attachments_requests` builds an `AttachmentRequest { content_hash: H, sources, .. }` for a missing, on-chain-confirmed `AttachmentInstance` [1](#0-0) .
2. The request is sent to a peer and the raw HTTP response is decoded purely as JSON via `decode_atlas_get_attachment`, with no comparison to `H` at all: [2](#0-1) .
3. `extend_with_attachments` takes whatever `Attachment` was decoded and inserts it into `self.attachments: HashSet<Attachment>` — again, no check that `attachment.hash() == request.content_hash`: [3](#0-2) .
4. In `AttachmentsDownloader::run`, when the state machine reaches `Done`, every attachment collected is looked up and resolved using its **own** computed hash, not the hash that was originally requested: [4](#0-3) . Specifically `context.attachments_batch.resolve_attachment(&attachment.hash())` uses `H2 = attachment.hash()`, which can be anything the attacker chooses by controlling the response bytes.

Because `H2 != H`, `AttachmentsBatch`'s tracked entry for `H` (inside `attachments_instances`, populated by `track_attachment`) is never removed, so `has_fully_succeed()` stays false for that batch and `bump_retry_count()` fires on every cycle until `max_attachment_retry_count` is exhausted, at which point the whole batch (including the legitimately-missing attachment for `H`) is simply dropped rather than resolved. This directly matches the "attachment/BNS mismatch" High-impact category: the content committed on-chain for that BNS name is never served, even though a canonical `AttachmentInstance` exists for it.

Additionally, note that `insert_instantiated_attachment(&attachment)` is called unconditionally for whatever content the attacker returned, before any instance lookup succeeds/fails — meaning arbitrary attacker-chosen bytes are written into the Atlas DB's instantiated-attachment table regardless of whether any instance actually references that hash [5](#0-4) .

No existing guard (signature check, length cap, or hash check) currently prevents this: the response is only rejected on HTTP-level failure (`status_code == 404`, JSON decode failure), not on content/hash mismatch [6](#0-5) .

### Impact Explanation
An unprivileged remote peer (anyone who can be selected as a data-URL source for a node's attachment download, which requires no authentication — just running a reachable HTTP endpoint that gets included in `sources`) can respond to a `GET /v2/attachments/<H>` proxy-style request with arbitrary bytes. This:
- Prevents the requesting node from ever resolving `H` to its true, on-chain-committed content within that batch/retry cycle, so BNS name resolution against that node for that attachment stays perpetually "missing" until the batch is exhausted and dropped.
- Causes unauthenticated writes of attacker-chosen data into the node's Atlas DB "instantiated attachments" table, unconditionally, regardless of whether the data corresponds to any known committed instance.
This is repeatable on every retry cycle by continuing to answer the same content_hash request with mismatched bytes, and affects any client relying on that node to resolve BNS names/subdomains via zonefiles/attachments.

### Likelihood Explanation
The attacker only needs to be selectable as an attachment-inventory-reporting peer/data source (an ordinary outbound sync peer with a reachable data URL) — no RPC secret, no privileged role, no StackerDB slot ownership required, and no compromise of any existing peer. The attacker cost is a single crafted HTTP response per request; it's fully repeatable across retry cycles.

### Recommendation
In `AttachmentsBatchStateContext::extend_with_attachments` (and/or in `AttachmentsDownloader::run` before resolving), verify `Hash160::from_data(&response.attachment.content) == request.content_hash` before inserting the attachment into `self.attachments`. Reject/penalize (bump_failed_requests, mark faulty) any peer whose response hash does not match the requested `content_hash`, and only call `resolve_attachment` using the originally requested hash after this check passes. Additionally, guard `insert_instantiated_attachment` so it is only invoked for attachments matching a known/requested hash.

### Proof of Concept
Rust test plan in `stackslib::net::atlas::download` tests:
1. Construct an `AttachmentsBatch` with `track_attachment` for a known `AttachmentInstance` with `content_hash = H`.
2. Build an `AttachmentsBatchStateContext` and simulate `extend_with_attachments` being fed a `BatchedRequestsResult` whose `succeeded` map contains the `AttachmentRequest{content_hash: H, ..}` paired with a crafted `StacksHttpResponse` whose JSON body is `GetAttachmentResponse { attachment: Attachment { content: b"malicious bytes" } }` (hashing to `H2 != H`).
3. Run the equivalent of the `Done` branch of `AttachmentsDownloader::run` (or directly call `resolve_attachment(&attachment.hash())` as done there).
4. Assert `context.attachments_batch.has_fully_succeed() == false` and that the entry for `H` remains present in `attachments_instances`.
5. Repeat across simulated retries and assert `bump_retry_count()`/`retry_count` increments each time without ever resolving `H`, up to `max_attachment_retry_count`, demonstrating the batch is dropped without ever having served the correct content for `H`.

    pub fn get_prioritized_attachments_requests(&self) -> BinaryHeap<AttachmentRequest> {
        let mut queue = BinaryHeap::new();
        let mut enqueued = HashSet::new();
        for ((contract_id, pages, _), peers_responses) in self.inventories.iter() {
            let missing_attachments = match self
                .attachments_batch
                .attachments_instances
                .get(contract_id)
            {
                None => continue,
                Some(missing_attachments) => missing_attachments,
            };
            // Note: we're getting missing_attachments (attachment_id: content_hash)
            for (attachment_index, content_hash) in missing_attachments.iter() {
                let page_index = attachment_index / AttachmentInstance::ATTACHMENTS_INV_PAGE_SIZE;
                // Since there's a limit in the number of pages that a node can request,
                // we can potentially have multiple inventory request at once.
                if !pages.contains(&page_index) {
                    continue;
                }

                if enqueued.contains(content_hash) {
                    debug!("Atlas: {} already enqueued", content_hash);
                    continue;
                }

                let mut sources = HashMap::new();
                let position_in_page =
                    attachment_index % AttachmentInstance::ATTACHMENTS_INV_PAGE_SIZE;

                for (peer_url, response) in peers_responses.iter() {
                    // Considering the response, look for the page with the index
                    // we're looking for.
                    let search_page = response.pages.iter().find(|page| page.index == page_index);

                    let has_attachment = search_page
                        .and_then(|search_page| {
                            search_page.inventory.get(position_in_page as usize)
                        })
                        .map(|result| *result == 1)
                        .unwrap_or(false);

                    if !has_attachment {
                        debug!(
                            "Atlas: peer does not have attachment ({}, {}) in its inventory {:?}",
                            page_index, position_in_page, response.pages
                        );
                        continue;
                    }

                    let report = self
                        .peers
                        .get(peer_url)
                        .expect("Atlas: unable to retrieve reliability report for peer");
                    sources.insert(peer_url.clone(), report.clone());
                }

                if sources.is_empty() {
                    warn!("Atlas: could not find a peer including attachment in its inventory");
                    continue;
                }

                // Success, we found at least one inventory including the attachment we're looking for.
                let request = AttachmentRequest {
                    sources,
                    content_hash: content_hash.clone(),
                    stacks_block_height: self.attachments_batch.stacks_block_height,
                    canonical_stacks_tip_height: self.attachments_batch.canonical_stacks_tip_height,
                };
                enqueued.insert(content_hash);
                queue.push(request);
            }

    pub fn extend_with_attachments(
        mut self,
        results: &mut BatchedRequestsResult<AttachmentRequest>,
    ) -> AttachmentsBatchStateContext {
        for (request, response) in results.succeeded.drain() {
            let report = self
                .peers
                .get_mut(request.get_url())
                .expect("Atlas: unable to retrieve reliability report for peer");

            let response = if let Some(r) = response {
                r
            } else {
                report.bump_failed_requests();
                continue;
            };

            if let Ok(response) = response.decode_atlas_get_attachment() {
                self.attachments.insert(response.attachment);
                report.bump_successful_requests();
            } else {
                report.bump_failed_requests();
            }
        }
        let mut events_ids = results.faulty_peers.keys().copied().collect::<Vec<usize>>();
        self.events_to_deregister.append(&mut events_ids);

        self
    }

impl StacksHttpResponse {
    pub fn decode_atlas_get_attachment(self) -> Result<GetAttachmentResponse, NetError> {
        let contents = self.get_http_payload_ok()?;
        let contents_json: serde_json::Value = contents.try_into()?;
        let resp: GetAttachmentResponse = serde_json::from_value(contents_json)
