## Title
StackerDB `write_freq` rate limit is never enforced at write/relay time, letting an authorized slot writer flood the network with chunk updates - ([File: stackslib/src/net/stackerdb/db.rs])

## Summary
`StackerDBConfig.write_freq` is documented and used as the mechanism that caps how often a given StackerDB slot may be rewritten, but the actual chunk-admission path (`try_replace_chunk`/`insert_chunk`) never checks it, and the unsolicited chunk-push path explicitly skips the check "because bandwidth throttling handles it." This mirrors the `tracer` bug class: a periodic/rate-gated invariant that downstream logic relies on ("this slot was written at most once per `write_freq`") is only enforced as an advisory, client-side heuristic rather than at the authoritative point where state is committed.

## Finding Description
`StackerDBTx::try_replace_chunk` is the sole gate that decides whether a chunk write is accepted into the DB. It only checks chunk size, slot-signer signature validity, monotonic version ("stale chunk"), and `max_writes`: [1](#0-0) 

There is no `write_freq`/timestamp gate here at all, even though `write_time` is recorded on every insert: [2](#0-1) 

The only place `write_freq` is consulted is in the *fetch scheduling* heuristic used when a node decides which chunks it wants to *download* from peers - it skips requesting a chunk it believes was "written too recently," purely to avoid needless traffic: [3](#0-2) 

For the unsolicited-push path (which is the one an untrusted-but-authorized remote signer actually uses to publish updates), the code explicitly documents that write frequency is *not* checked, on the assumption that per-connection bandwidth throttling in `ConversationP2P` is a sufficient substitute: [4](#0-3) 

`validate_received_chunk`, which gates both the push path and the download path, likewise only checks size, expected version, signer signature, and `max_writes` - never `write_freq`: [5](#0-4) 

And the bandwidth throttle it relies on is a coarse bytes/sec cap unrelated to write cadence, not a per-chunk or per-slot rate limiter: [6](#0-5) 

So the equality that other logic implicitly assumes - "a slot's version increases at most once per `write_freq` seconds, network-wide" - is broken: any node holding a valid slot-signer private key (a normal, unprivileged StackerDB participant, not an admin or someone else's key) can push new chunk versions as fast as `max_writes` and small per-message sizes allow, well under the coarse bytes/sec cap. Each push causes: (a) a full signature verification and DB write on every receiving replica via `try_replace_chunk`, and (b) re-broadcast/relay of the chunk to that replica's own outbound peers via the push-chunk sync machinery (`make_chunk_push_schedule`/`pushchunks_begin`), fanning out across the network: [7](#0-6) [8](#0-7) 

This is directly analogous to the `tracer` insurance bug: a control meant to gate a periodic state-changing action ("once per hour" / "once per `write_freq`") is only actually enforced by a local, bypassable heuristic rather than by the code path that actually commits/serves the state, so the invariant other logic depends on for staleness/consistency assumptions does not hold under adversarial (but authorized-key) use.

## Impact Explanation
This does not require any secret beyond a legitimately-provisioned slot signer key, and produces amplified, network-wide compute/storage/bandwidth load: every receiving node must run signature verification and a DB write per chunk version, then relay it onward to its own peers, all at a cadence the `write_freq` config was specifically designed to prevent. This matches the "bounded compute DoS on a read endpoint" / amplification class called out as acceptable High-severity impact, since it is triggered remotely by a small number of unprivileged (from the node's perspective) messages and propagates the effect to other nodes.

## Likelihood Explanation
Likely, once a party controls a valid StackerDB slot key (a routine, unprivileged role for many StackerDB-backed contracts, e.g. signer message slots) - no other party's key or node secret is needed, and the mechanism intended to prevent this (`write_freq`) is dead code on the acceptance path.

## Recommendation
Enforce `config.write_freq` against the stored `write_time` inside `StackerDBTx::try_replace_chunk` (or equivalently in `validate_received_chunk`) before accepting/committing a new chunk version, for both the push and pull paths, instead of relying solely on the advisory fetch-scheduling heuristic and the unrelated bytes/sec bandwidth throttle.

## Proof of Concept
1. Become the registered signer for a StackerDB slot with `write_freq = N` seconds and `max_writes = M`.
2. Repeatedly call `PeerNetwork::handle_unsolicited_StackerDBPushChunk` (i.e., send `StackerDBPushChunk` messages) with strictly increasing `slot_version`, staying under `max_writes` and under `max_stackerdb_push_bandwidth` bytes/sec, but far more frequently than once every `N` seconds.
3. Observe in `StackerDBTx::try_replace_chunk` (`stackslib/src/net/stackerdb/db.rs:400-438`) that each push is accepted and stored regardless of `write_freq`, and that each accepted chunk gets re-scheduled for push to further neighbors via `make_chunk_push_schedule`/`pushchunks_begin` in `stackslib/src/net/stackerdb/sync.rs`, confirming the intended per-slot write cadence is not enforced anywhere on the acceptance/relay path.

    pub fn try_replace_chunk(
        &self,
        smart_contract: &QualifiedContractIdentifier,
        slot_desc: &SlotMetadata,
        chunk: &[u8],
    ) -> Result<(), net_error> {
        // Check per-replica chunk-size cap.
        if (chunk.len() as u64) > self.config.chunk_size {
            return Err(net_error::StackerDBChunkTooBig(chunk.len()));
        }

        let slot_validation = self
            .get_slot_validation(smart_contract, slot_desc.slot_id)?
            .ok_or(net_error::NoSuchSlot(
                smart_contract.clone(),
                slot_desc.slot_id,
            ))?;

        if !slot_desc.verify(&slot_validation.signer)? {
            return Err(net_error::BadSlotSigner(
                slot_validation.signer,
                slot_desc.slot_id,
            ));
        }
        if slot_desc.slot_version <= slot_validation.version {
            return Err(net_error::StaleChunk {
                supplied_version: slot_desc.slot_version,
                latest_version: slot_validation.version,
            });
        }
        if slot_desc.slot_version > self.config.max_writes {
            return Err(net_error::TooManySlotWrites {
                supplied_version: slot_desc.slot_version,
                latest_version: slot_validation.version,
                max_writes: self.config.max_writes,
            });
        }
        self.insert_chunk(smart_contract, slot_desc, chunk)
    }

    pub fn validate_received_chunk(
        &self,
        smart_contract_id: &QualifiedContractIdentifier,
        config: &StackerDBConfig,
        data: &StackerDBChunkData,
        expected_versions: &[u32],
    ) -> Result<bool, net_error> {
        // validate -- must not exceed this replica's configured chunk size.
        if (data.data.len() as u64) > config.chunk_size {
            info!(
                "Received StackerDBChunk for {} ID {}, which is oversized: {} bytes (max {} bytes)",
                smart_contract_id,
                data.slot_id,
                data.data.len(),
                config.chunk_size
            );
            return Ok(false);
        }

        // validate -- must be a valid chunk
        let Some(expected_version) = expected_versions.get(data.slot_id as usize) else {
            info!(
                "Received StackerDBChunk for {} ID {}, which is too big ({})",
                smart_contract_id,
                data.slot_id,
                expected_versions.len()
            );
            return Ok(false);
        };

        // validate -- must be signed by the expected author
        let addr = match self
            .stackerdbs
            .get_slot_signer(smart_contract_id, data.slot_id)?
        {
            Some(addr) => addr,
            None => {
                return Ok(false);
            }
        };

        let slot_metadata = data.get_slot_metadata();
        if !slot_metadata.verify(&addr)? {
            info!(
                "StackerDBChunk for {} ID {} is not signed by {}",
                smart_contract_id, data.slot_id, &addr
            );
            return Ok(false);
        }

        // validate -- must be the current or newer version
        if data.slot_version < *expected_version {
            info!(
                "Received StackerDBChunk for {} ID {} version {}, which is stale (expected {})",
                smart_contract_id, data.slot_id, data.slot_version, *expected_version
            );
            return Ok(false);
        }

        // validate -- must not exceed max writes
        if data.slot_version > config.max_writes {
            info!(
                "Write count exceeded for StackerDBChunk for {} ID {} version {} (max is {})",
                smart_contract_id, data.slot_id, data.slot_version, config.max_writes
            );
            return Ok(false);
        }

        Ok(true)
    }
