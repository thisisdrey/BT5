### Title
Missing new-authority validation in `transfer_to_new_account`/`transfer_to_new_account_pda` allows permanent, unrecoverable loss of margin account control - ([File: programs/marginfi/src/instructions/marginfi_account/transfer_account.rs])

### Summary
The account-authority migration instructions `transfer_to_new_account` and `transfer_to_new_account_pda` accept a caller-supplied `new_authority` account that is completely unvalidated (not checked against `Pubkey::default()`, not required to be a signer, not checked to be a valid/controllable key), and the migration is a single, irreversible step. This mirrors the reported bug class: a single-step ownership/authority transfer function with no target-address sanity check, where mistakenly or maliciously supplying an uncontrolled/invalid address permanently locks the account and all its collateral/borrow positions.

### Finding Description
`TransferToNewAccount` and `TransferToNewAccountPda` declare `new_authority` as an `UncheckedAccount` explicitly annotated with `WARN: New authority is completely unchecked`. [1](#0-0) [2](#0-1) 

The handler `transfer_to_new_account` performs fee checks, flashloan/receivership/order-execution checks, and a re-migration guard, but never validates `ctx.accounts.new_authority.key()` before assigning it as the new account's `authority` via `initialize_migrated_account`, and it unconditionally disables the old account (`ACCOUNT_DISABLED`) and zeroes its `lending_account`, making the migration irreversible. [3](#0-2) [4](#0-3) 

Notably, the CLI helper `marginfi_account_transfer` in `p0-cli` does add a defensive check against `Pubkey::default()` before submitting the instruction, confirming the team recognizes the zero-address risk — but this check exists only client-side, not in the on-chain program. [5](#0-4) 

The project's own test suite explicitly documents this as intentional/known behavior rather than a bug: "Here the user moves authority to some new wallet. WARN: User picks the new authority with no restrictions!" [6](#0-5) 

This is directly analogous to the referenced report's `PNG.sol::setMinter` / `Airdrop.sol::setOwner` pattern: a single-step authority transfer with insufficient validation of the destination address, as opposed to the two-step (propose/accept) pattern recommended as the fix.

### Impact Explanation
Because `old_account` is permanently disabled (`ACCOUNT_DISABLED`, `lending_account` zeroed) and migration cannot be repeated (`AccountAlreadyMigrated` check), if `new_authority` is set to `Pubkey::default()`, a burn address, or any key the user does not control, all deposit/borrow positions transferred to the new account become permanently inaccessible — no privileged path exists to reclaim or reverse this, since `authority` on `MarginfiAccount` is the sole gate for standard user operations. This is a permanent lock/freeze of user funds, matching the accepted impact classes.

### Likelihood Explanation
This is triggerable by any unprivileged account authority (the account owner itself) with no admin/group privilege required — it is a standard user-facing instruction (`transfer_to_new_account`, `transfer_to_new_account_pda`) exposed in `lib.rs`. [7](#0-6) 
It requires either user error (fat-fingering an address, as is common in wallet/CLI flows) or a malicious front-end/dApp integration tricking a user into signing a transfer to an attacker/burn address. Given that the CLI itself defends against the zero-address case (line 1179 of `account.rs`), the team is aware this scenario is realistic enough to guard against — just not consistently at the protocol layer.

### Recommendation
Add on-chain validation in `transfer_to_new_account`/`transfer_to_new_account_pda` rejecting `new_authority == Pubkey::default()` at minimum, and consider requiring `new_authority` to co-sign the transfer (or implement a two-step accept/claim flow similar to the Timelock two-step pattern referenced in the analog report) so that the destination address is proven controllable before the old account is irreversibly disabled.

### Proof of Concept
1. User (or a malicious dApp) calls `transfer_to_new_account` with `new_authority = Pubkey::default()` (or any address the user does not control), `old_marginfi_account` = a live account with active deposits/borrows. [8](#0-7) 
2. The instruction succeeds because no check exists on `new_authority`'s validity; `new_account.authority` is set to the unvalidated key and `old_account` is disabled with its `lending_account` zeroed. [9](#0-8) 
3. Re-running the transfer on `old_marginfi_account` fails with `AccountAlreadyMigrated`, and the funds in `new_marginfi_account` are now permanently controlled by an authority nobody holds the private key for. [10](#0-9)

fn initialize_migrated_account(
    new_account: &mut MarginfiAccount,
    old_account: &MarginfiAccount,
    new_authority: Pubkey,
    current_timestamp: u64,
    old_account_key: Pubkey,
) {
    new_account.initialize(old_account.group, new_authority, current_timestamp);
    new_account.lending_account = old_account.lending_account;
    new_account.emissions_destination_account = old_account.emissions_destination_account;
    new_account.account_flags = old_account.account_flags;
    new_account.migrated_from = old_account_key;
    new_account.indexer_flags = old_account.indexer_flags;
    new_account.sync_indexer_flags();
}

fn finalize_migrated_old_account(
    old_account: &mut MarginfiAccount,
    new_account_key: Pubkey,
    current_timestamp: u64,
) {
    old_account.migrated_to = new_account_key;
    old_account.last_update = current_timestamp;
    old_account.lending_account = LendingAccount::zeroed();
    old_account.set_flag(ACCOUNT_DISABLED, true);
    old_account.sync_indexer_flags();
}

pub fn transfer_to_new_account(ctx: Context<TransferToNewAccount>) -> MarginfiResult {
    // Validate the global fee wallet and claim a nominal fee
    let group = ctx.accounts.group.load()?;
    check_eq!(
        ctx.accounts.global_fee_wallet.key(),
        group.fee_state_cache.global_fee_wallet,
        MarginfiError::InvalidFeeAta
    );
    anchor_lang::system_program::transfer(ctx.accounts.transfer_fee(), ACCOUNT_TRANSFER_FEE)?;

    let mut old_account = ctx.accounts.old_marginfi_account.load_mut()?;

    check!(
        !old_account.get_flag(ACCOUNT_IN_FLASHLOAN),
        MarginfiError::AccountInFlashloan
    );

    check!(
        !old_account.get_flag(ACCOUNT_IN_RECEIVERSHIP),
        MarginfiError::ForbiddenIx
    );

    check!(
        !old_account.get_flag(ACCOUNT_IN_ORDER_EXECUTION),
        MarginfiError::ForbiddenIx
    );

    check!(
        old_account.active_orders == 0,
        MarginfiError::IllegalAction,
        "Close all active orders before transfer"
    );

    // Prevent multiple migrations from the same account
    check_eq!(
        old_account.migrated_to,
        Pubkey::default(),
        MarginfiError::AccountAlreadyMigrated
    );

    let mut new_account = ctx.accounts.new_marginfi_account.load_init()?;
    let current_timestamp = Clock::get()?.unix_timestamp as u64;
    initialize_migrated_account(
        &mut new_account,
        &old_account,
        ctx.accounts.new_authority.key(),
        current_timestamp,
        ctx.accounts.old_marginfi_account.key(),
    );

    finalize_migrated_old_account(
        &mut old_account,
        ctx.accounts.new_marginfi_account.key(),
        current_timestamp,
    );

    emit!(MarginfiAccountTransferToNewAccount {
        header: AccountEventHeader {
            signer: Some(ctx.accounts.authority.key()),
            marginfi_account: ctx.accounts.new_marginfi_account.key(),
            marginfi_account_authority: ctx.accounts.new_authority.key(),
            marginfi_group: ctx.accounts.group.key(),
        },
        old_account: ctx.accounts.old_marginfi_account.key(),
        old_account_authority: ctx.accounts.authority.key(),
        new_account_authority: ctx.accounts.new_authority.key(),
    });

    Ok(())
}
