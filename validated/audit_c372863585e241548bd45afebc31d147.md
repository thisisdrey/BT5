### Title
Push-Payment Distribution Loop Permanently Freezes All Shareholder Funds When Any Single Recipient Blocks Coin Deposits — (`aptos-move/framework/aptos-framework/sources/vesting.move`, `staking_contract.move`)

---

### Summary

`vesting::distribute` and `staking_contract::distribute_internal` iterate over all shareholders/recipients and call `aptos_account::deposit_coins` for each one inside a single atomic transaction. `deposit_coins` aborts if the recipient has not registered for `AptosCoin` (e.g., FA-only account post-migration) **and** has called `set_allow_direct_coin_transfers(false)`. Because Move transactions are atomic, a single aborting deposit reverts the entire distribution, permanently blocking every other shareholder from receiving their vested tokens or staking rewards.

---

### Finding Description

`vesting::distribute` withdraws all unlocked stake and then pushes coins to every shareholder in a `for_each_ref` loop:

```move
shareholders.for_each_ref(|shareholder| {
    ...
    let recipient_address = get_beneficiary(vesting_contract, shareholder);
    aptos_account::deposit_coins(recipient_address, share_of_coins);  // can abort
});
``` [1](#0-0) 

`staking_contract::distribute_internal` does the same for every entry in the distribution pool:

```move
while (distribution_pool.shareholders_count() > 0) {
    ...
    aptos_account::deposit_coins(
        recipient, coin::extract(&mut coins, amount_to_distribute)
    );
``` [2](#0-1) 

`aptos_account::deposit_coins` contains the following guard:

```move
if (!coin::is_account_registered<CoinType>(to)) {
    assert!(
        can_receive_direct_coin_transfers(to),
        error::permission_denied(EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS)
    );
    coin::register<CoinType>(&create_signer(to));
};
coin::deposit<CoinType>(to, coins)
``` [3](#0-2) 

`coin::is_account_registered<AptosCoin>` checks for the existence of a legacy `CoinStore<AptosCoin>`. Post-FA-migration, accounts created via `create_account` receive an APT Primary Fungible Store but **no** `CoinStore<AptosCoin>`, so `is_account_registered` returns `false` for them. The spec confirms this abort path:

```
aborts_if if_exist_coin && global<coin::CoinStore<CoinType>>(to).frozen;
include RegistCoinAbortsIf<CoinType>;   // includes can_receive_direct_coin_transfers check
``` [4](#0-3) 

`can_receive_direct_coin_transfers` returns `false` when the account has explicitly called `set_allow_direct_coin_transfers(false)`:

```move
public fun can_receive_direct_coin_transfers(account: address): bool acquires DirectTransferConfig {
    !exists<DirectTransferConfig>(account)
        || borrow_global<DirectTransferConfig>(account).allow_arbitrary_coin_transfers
}
``` [5](#0-4) 

`set_allow_direct_coin_transfers` is an unprivileged public entry function callable by any account holder: [6](#0-5) 

**Attack path:**
1. Attacker is a shareholder (or admin sets attacker as a beneficiary) in a vesting contract or staking contract.
2. Attacker's account is FA-only (no legacy `CoinStore<AptosCoin>`), which is the default for accounts created after the FA migration.
3. Attacker calls `set_allow_direct_coin_transfers(false)`.
4. Any call to `vesting::distribute` or `staking_contract::distribute` now aborts at the attacker's `deposit_coins` call.
5. Because the transaction is atomic, **all** coins extracted from the stake pool are rolled back, and **no** shareholder receives anything.
6. The distribution is permanently wedged: every future call to `distribute` hits the same abort.

The same abort can also be triggered by a frozen APT Primary Fungible Store (checked inside `coin::deposit` → `primary_fungible_store::deposit` → `fungible_asset::deposit_sanity_check`): [7](#0-6) 

---

### Impact Explanation

- **Permanent freezing of vesting balances**: All shareholders in a `VestingContract` are blocked from ever receiving vested tokens or rewards. The coins remain locked in the vesting pool's stake account with no recovery path, since `terminate_vesting_contract` also calls `distribute` internally. [8](#0-7) 

- **Permanent freezing of staking balances**: The staker cannot withdraw unlocked stake and the operator cannot collect commission. `distribute` is the only exit path for unlocked funds. [9](#0-8) 

---

### Likelihood Explanation

- `set_allow_direct_coin_transfers` is a free, unprivileged, single-transaction call available to any account.
- Post-FA-migration, new accounts do not have a legacy `CoinStore<AptosCoin>`, making the abort condition the default state for any shareholder who opts out.
- A malicious shareholder, or an admin who sets a malicious beneficiary address, can trigger this with zero cost and no special privileges.
- The `distribute` and `distribute_many` entry points are callable by anyone (no access control), so the attacker does not even need to be the one calling distribute. [10](#0-9) 

---

### Recommendation

Replace the push-payment loop with a pull-payment pattern:

1. **Accumulate per-recipient balances** in a `SimpleMap<address, u64>` inside the contract state instead of immediately pushing coins.
2. Add a separate `claim(contract_address)` entry function that lets each shareholder pull their own allocation. A single failed claim does not affect others.
3. Alternatively, wrap each `deposit_coins` call in a guard: if the deposit would fail (recipient has disabled direct transfers or store is frozen), escrow the coins under the recipient's address in the contract and emit an event, then continue the loop.

For the frozen-store case, use `aptos_account::deposit_fungible_assets` (which routes through the FA path and bypasses the legacy `CoinStore` frozen check for APT) or use `fungible_asset::unchecked_deposit` with the APT `TransferRef` to bypass the frozen flag, consistent with how `fungible_transfer_only` already handles APT: [11](#0-10)

### Proof of Concept

```move
// Pseudocode demonstrating the wedge in vesting::distribute

// Setup: vesting contract with two shareholders: @alice and @bob
// @bob is an FA-only account (no CoinStore<AptosCoin>) and calls:
//   aptos_account::set_allow_direct_coin_transfers(&bob_signer, false);

// After lockup expires, anyone calls:
//   vesting::distribute(contract_address);
//
// Execution trace:
//   withdraw_stake(...)  -> coins = 1000 APT
//   deposit_coins(@alice, 500)  -> succeeds (alice has CoinStore or allows transfers)
//   deposit_coins(@bob,   500)  -> ABORTS: bob has no CoinStore<AptosCoin> AND
//                                   allow_arbitrary_coin_transfers == false
//                                   => error::permission_denied(EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS)
//
// Entire transaction reverts. Alice receives 0. Bob receives 0.
// coins are rolled back into the stake pool.
// Every subsequent call to distribute() hits the same abort.
// Alice's vested tokens are permanently frozen.
```
