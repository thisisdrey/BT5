### Title
Cross-repository quarantine directory access via unanchored prefix match in `ObjectDirectoryPath` - (File: internal/git/localrepo/paths.go)

### Summary
`Repo.ObjectDirectoryPath` validates a caller-supplied `GitObjectDirectory` field by checking whether the resolved absolute path starts with an "expected quarantine prefix" built from the repository's own quarantine-directory prefix. The check uses `strings.HasPrefix` on the raw path string without ensuring a path-separator boundary follows the prefix, so a manually-crafted quarantine path belonging to a *different* repository (whose quarantine prefix happens to share the same string prefix) can satisfy the check.

### Finding Description
`ObjectDirectoryPath` in [1](#0-0)  handles the case where the repository-supplied `GitObjectDirectory` is not a plain sub-path of the repo (i.e. it's meant to be a manual/legacy object-quarantine directory located in the storage's temp dir). It computes:

```go
expectedQuarantinePrefix := filepath.Join(tempDir, storage.QuarantineDirectoryPrefix(repo))
absoluteObjectDirectoryPath := filepath.Join(repoPath, objectDirectoryPath)
if !strings.HasPrefix(absoluteObjectDirectoryPath, expectedQuarantinePrefix) {
    return "", structerr.NewInvalidArgument("not a valid relative path: %w", origError)
}
```

This is intended to restrict a repository to only being able to reference quarantine directories that belong to it (i.e. directories named `<tempDir>/<repo-specific-prefix>-<random>`). However, `strings.HasPrefix` performs a pure string-prefix comparison, not a path-boundary-aware comparison. If `storage.QuarantineDirectoryPrefix(repo)` for repository A is a string prefix of the quarantine-prefix generated for repository B (e.g. prefixes derived from relative path hashes/identifiers that are not disambiguated by a trailing separator, or where one repo's prefix is literally a prefix substring of another, such as `"proj-1"` vs `"proj-11"`), then repository A's crafted `GitObjectDirectory` value can resolve to a temp directory that actually belongs to repository B's in-flight quarantine (created via `quarantine.New`, [2](#0-1) ) and pass the check.

The `GitObjectDirectory`/`GitAlternateObjectDirectories` fields on the `gitalypb.Repository` message are attacker-influenceable inputs reaching this code path from ordinary RPC calls that accept a `Repository` message with those fields populated (e.g. requests carrying quarantine information forwarded from GitLab Rails during hook callbacks, as documented in [3](#0-2) ). Since the validation is the sole gate preventing an attacker-supplied object-directory value from pointing outside of the repository's own object storage, an unanchored-prefix bypass would let a request for repository A configure Git to read/write objects into another repository B's active quarantine directory while still targeting repository A logically.

### Impact Explanation
If exploitable, this breaks the isolation the quarantine mechanism is meant to provide: it could let an unprivileged caller with access to one repository (A) reach or influence Git object data staged for a concurrent push/fetch quarantine of another repository (B) — a cross-repository object access / quarantine-isolation violation, matching the "quarantine gating" and "cross-repository object access" categories called out as in-scope. This could result in object leakage between repositories or corruption of another tenant's in-flight push.

### Likelihood Explanation
Exploitability depends entirely on whether `storage.QuarantineDirectoryPrefix` produces prefixes that can collide as a string-prefix of one another for different repositories (I was not able to inspect the body of `storage.QuarantineDirectoryPrefix` in `internal/gitaly/storage/locator.go` before running out of investigation budget — its definition location was found via grep but its implementation was not retrieved). If the prefix format embeds a fixed-length hash or otherwise guarantees a separator immediately after the repo-specific component, the bypass is not possible. Given this open verification gap, likelihood is assessed as uncertain/moderate rather than confirmed.

### Recommendation
Replace the raw `strings.HasPrefix` check with a boundary-aware comparison, e.g. verify that `absoluteObjectDirectoryPath` equals `expectedQuarantinePrefix` or has `expectedQuarantinePrefix + string(os.PathSeparator)` as a prefix, and additionally confirm `QuarantineDirectoryPrefix` values cannot be a prefix of one another across different repositories (e.g. by anchoring on `filepath.Rel` + explicit segment comparison rather than string prefix matching), consistent with how `storage.ValidateRelativePath` is used elsewhere in this same file.

### Proof of Concept
Not able to construct a concrete, verified PoC within the available investigation budget because the exact output format of `storage.QuarantineDirectoryPrefix` (in `internal/gitaly/storage/locator.go`) could not be retrieved before the session ended. A full PoC would require confirming whether two distinct repositories' relative paths can be crafted so that one's derived quarantine prefix is a literal string-prefix of the other's, then issuing an RPC for repository A with `GitObjectDirectory` set to a path under repository B's active quarantine temp directory sharing that prefix, and observing whether `ObjectDirectoryPath` accepts it.

func New(ctx context.Context, repo *gitalypb.Repository, logger log.Logger, locator storage.Locator) (*Dir, func(), error) {
	repoPath, err := locator.GetRepoPath(ctx, repo, storage.WithRepositoryVerificationSkipped())
	if err != nil {
		return nil, nil, structerr.NewInternal("getting repo path: %w", err)
	}

	quarantineDir, cleanup, err := tempdir.NewWithPrefix(ctx, repo.GetStorageName(),
		storage.QuarantineDirectoryPrefix(repo), logger, locator)
	if err != nil {
		return nil, nil, fmt.Errorf("creating quarantine: %w", err)
	}

	quarantinedRepo, err := Apply(repoPath, repo, quarantineDir.Path())
	if err != nil {
		cleanup() // Clean up if we fail after creating the temp directory
		return nil, nil, err
	}

	return &Dir{
		repo:            repo,
		quarantinedRepo: quarantinedRepo,
		locator:         locator,
		dir:             quarantineDir,
	}, cleanup, nil
}
