### Title
Per-intent MT/NFT dust-fee exemption in `TokenDiff::token_fee` lets a signer bypass protocol fees by splitting one large `TokenDiff` into N unit-sized `TokenDiff` intents in a single `MultiPayload` - (File: `contracts/defuse/core/src/intents/token_diff.rs`)

### Summary
`TokenDiff::execute_intent` computes and collects protocol fees independently for each `TokenDiff` intent, using `token_fee(token_id, |delta|, protocol_fee)` where `amount` is the magnitude of *that single intent's* delta, not the aggregate delta for the token across the batch. Because `token_fee` returns `Pips::ZERO` for `Nep245`/`Imt` (and `Nep171`) whenever `amount <= 1`, an unprivileged signer can decompose a single `TokenDiff{token_id: -N}` into N separate `TokenDiff{token_id: -1}` intents inside one signed `MultiPayload`, causing the total fee credited to `fee_collector` to be `0` instead of `Pips::fee_ceil(protocol_fee, N)`.

### Finding Description
The broken binding: `sum(fees_collected for token T across all TokenDiff intents in the batch) == Pips::fee_ceil(protocol_fee, sum(|negative deltas of T| across the batch))`. This holds when the whole negative delta for `T` is expressed in a single `TokenDiff` intent, but breaks when the same aggregate negative delta is split across multiple `TokenDiff` intents.

Code path:
- `DefuseIntents::execute_intent` iterates `Vec<Intent>` and executes each `Intent` (including multiple `TokenDiff`s) independently under a single nonce commit: [1](#0-0) .
- `Engine::execute_signed_intent` verifies the signature and commits the nonce exactly once per `MultiPayload`, then dispatches the entire `intents` vector: [2](#0-1) .
- `TokenDiff::execute_intent` applies the delta to the signer's balance and computes the fee per intent from that intent's own `amount = delta.unsigned_abs()`: [3](#0-2) .
- `TokenDiff::token_fee` returns `Pips::ZERO` for `Nep245`/`Imt` tokens when `amount <= 1`: [4](#0-3) .

Root cause: the "no fee on dust NFT/MT legs" exemption is evaluated on a per-`TokenDiff`-intent basis, not on the aggregate signer delta for the token across the whole `MultiPayload`/batch. Since a signer can place arbitrarily many `TokenDiff` intents in one `Vec<Intent>` under one signature/nonce, and the `TransferMatcher` used in `finalize()` matches deltas across the whole engine execution by token/account regardless of how many intents contributed them (`add_delta` accumulates per-account, per-token) [5](#0-4) , splitting a large MT/NFT leg into N unit legs is fully equivalent from the counterparty/settlement perspective, but each unit leg is separately exempted from the fee.

Attacker's exact payload: sign one `MultiPayload` with `DefuseIntents.intents` containing N `TokenDiff` entries, each `{diff: {token_id: -1, x_token: +m_i}}` for the same `Nep245TokenId`, where the sum of `m_i` equals what a single legal `TokenDiff{token_id: -N, x_token: +M}` would yield, matched against a counterparty's (or the attacker's own second account's) opposing legs. No signature, nonce, deadline, salt, or lock check catches this because each leg is a syntactically valid, independent `TokenDiff` and the guards (`MultiPayload::verify`, `verify_intent_nonce`, `commit_nonce`) only govern signature/nonce validity, not per-token fee aggregation across intents.

### Impact Explanation
`fee_collector` is under-credited for every MT/NFT/IMT leg an attacker chooses to split, at zero additional signer cost beyond gas for extra intent entries (bounded and attacker-controlled, not unbounded). This matches the listed Critical category "protocol fees bypassed": value that should flow to `fee_collector` never arrives, while the signer's net debit and the trade's economic outcome are unchanged from the non-split case. This is repeatable for any account and any `Nep245`/`Imt` token id with `amount > 1`, on every trade, as long as `protocol_fee > 0`.

### Likelihood Explanation
Preconditions are modest and fully attacker-controlled: hold `N` units of a `Nep245`/`Imt` token inside the Verifier, have `protocol_fee > 0` (a normal deployed configuration), and be able to construct/sign one `MultiPayload` with N `TokenDiff` entries plus a matching counterparty (or attacker's second account) to satisfy the batch's zero-sum invariant. No role, relayer key, or victim key is needed. This is highly feasible and repeatable across all trades involving MT/NFT/IMT tokens.

### Recommendation
Compute the dust-fee exemption on the aggregate negative delta per `(signer, token_id)` across the entire batch (all `TokenDiff` intents within `execute_signed_intents`/`Engine`), not per individual `TokenDiff` intent — e.g., accumulate per-token negative deltas for the signer across the whole payload set before deciding whether `amount <= 1`, or require that the exemption is not the emergent output of independently signed legs but an intrinsic property of the final aggregate transfer computed by `TransferMatcher::finalize`.

### Proof of Concept
`cargo test` plan (near-workspaces sandbox, in `tests/src/tests/defuse/intents/token_diff.rs`):
1. Deploy `Defuse` with `protocol_fee = Pips::ONE_PERCENT` (or any `Pips > 0`), a `Nep245` MT contract, and two users (`seller`, `buyer`).
2. Deposit `N` (e.g. `N = 10`) units of `mt_token_id` to `seller`'s Verifier balance, and sufficient `ft_token_id` balance to `buyer`.
3. Case A (baseline): `seller` signs one `MultiPayload` with a single `TokenDiff{mt_token_id: -N, ft_token_id: +M}`; `buyer` signs the matching `TokenDiff{mt_token_id: +N, ft_token_id: -M}`. Execute via `execute_intents`. Assert `fee_collector`'s `mt_token_id` balance increases by `Pips::fee_ceil(protocol_fee, N)` (nonzero, since `N > 1`).
4. Case B (exploit): `seller` signs one `MultiPayload` whose `DefuseIntents.intents` contains N separate `TokenDiff{mt_token_id: -1, ft_token_id: +M/N}` entries; `buyer` signs the same aggregate matching `TokenDiff{mt_token_id: +N, ft_token_id: -M}` (or N matching `+1` legs). Execute via `execute_intents`.
5. Assert: `fee_collector`'s `mt_token_id` balance increase in Case B is `0`, while `seller`'s net `mt_token_id` debit (`-N`) and `buyer`'s net credit are identical to Case A — demonstrating the binding `sum(fees_collected) == Pips::fee_ceil(protocol_fee, N)` holds in Case A but fails (`0 != fee_ceil(...)`) in Case B.

    fn execute_signed_intent(&mut self, signed: MultiPayload) -> Result<()> {
        // verify signed payload and get public key
        let public_key = signed.verify().ok_or(DefuseError::InvalidSignature)?;

        // calculate intent hash
        let hash = signed.hash();

        // extract NEP-413 payload
        let DefusePayload::<DefuseIntents> {
            signer_id,
            verifying_contract,
            deadline,
            nonce,
            message: intents,
        } = signed.extract_defuse_payload()?;

        // check recipient
        if verifying_contract != *self.state.verifying_contract() {
            return Err(DefuseError::WrongVerifyingContract);
        }

        self.inspector.on_deadline(deadline);

        // make sure message is still valid
        if deadline < Timestamp::now() {
            return Err(DefuseError::DeadlineExpired);
        }

        // make sure the account has this public key
        if !self.state.has_public_key(&signer_id, &public_key) {
            return Err(DefuseError::PublicKeyNotExist(signer_id, public_key));
        }

        // commit nonce
        self.verify_intent_nonce(nonce, deadline)?;
        self.state.commit_nonce(signer_id.clone(), nonce)?;

        intents.execute_intent(&signer_id, self, hash)?;
        self.inspector.on_intent_executed(&signer_id, hash, nonce);

        Ok(())
    }

    #[inline]
    pub fn add_delta(&mut self, owner_id: AccountId, token_id: TokenId, delta: i128) -> bool {
        self.0.entry_or_default(token_id).add_delta(owner_id, delta)
    }

    // Finalizes all transfers, or returns unmatched deltas.
    // If unmatched deltas overflow, then Err(None) is returned.
    pub fn finalize(self) -> Result<Transfers, InvariantViolated> {
        let mut transfers = Transfers::default();
        let mut deltas = TokenDeltas::default();
        for (token_id, transfer_matcher) in self.0 {
            if let Err(unmatched) = transfer_matcher.finalize_into(&token_id, &mut transfers)
                && (unmatched == 0 || deltas.apply_delta(token_id, unmatched).is_none())
            {
                return Err(InvariantViolated::Overflow);
            }
        }
        if !deltas.is_empty() {
            return Err(InvariantViolated::UnmatchedDeltas {
                unmatched_deltas: deltas,
            });
        }
        Ok(transfers)
    }
}
