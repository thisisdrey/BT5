### Title
Firewall conntrack timeout reconfiguration is not propagated to the preserved `TimerWheel`, allowing stale connections to bypass firewall re-validation past their configured timeout - (File: `firewall.go`, `interface.go`, `timeout.go`)

### Summary
When Nebula's firewall is reloaded (e.g. via SIGHUP), `reloadFirewall` builds a brand-new `Firewall` object with newly configured `TCPTimeout`/`UDPTimeout`/`DefaultTimeout` values, but deliberately keeps the *old* `Conntrack` (and therefore the old `TimerWheel`) alive across the reload to preserve existing connection state [1](#0-0) . The `TimerWheel`'s `tickDuration` and `wheelDuration` are fixed at construction time from the timeout values that were in effect *before* the reload [2](#0-1) , and are never recalculated when the firewall's timeout configuration changes. This is structurally the same bug class as the reported "changes to vesting period is not handled" issue: a duration value baked into derived state (the `fullyVestedAt` timestamp / here the wheel's tick and wheel duration) becomes stale relative to a runtime-configurable period (the `vestingPeriod` / here `TCPTimeout`, `UDPTimeout`, `DefaultTimeout`), and the code path that uses the new period value doesn't validate consistency against the frozen derived state.

### Finding Description
`NewFirewallFromConfig` reads the current `firewall.conntrack.*` timeouts from config and calls `NewFirewall`, which sizes the `TimerWheel`'s `tickDuration` (= min of the three timeouts) and `wheelDuration` (= max of the three timeouts) purely from the timeout values passed in at that moment [3](#0-2) [4](#0-3) .

On reload, `reloadFirewall` creates this new `Firewall` (with new `TCPTimeout`/`UDPTimeout`/`DefaultTimeout` fields and a new, differently-sized `TimerWheel`), but then explicitly overwrites the new `TimerWheel` with the old one from `oldFw.Conntrack` in order to preserve in-flight connections: [1](#0-0) 

After this, `fw.TCPTimeout`/`fw.UDPTimeout`/`fw.DefaultTimeout` reflect the *new* configuration, but `fw.Conntrack.TimerWheel.tickDuration`/`wheelDuration` still reflect the *old* configuration — there is no re-derivation of the wheel's timing parameters, analogous to `_stakeInfo.fullyVestedAt` never being recomputed when `vestingPeriod` changes.

New and refreshed connections use the up-to-date timeout fields to compute the real expiry (`c.Expires`), but schedule the eviction check in the stale wheel via `findWheel`, which silently clamps the actual timeout to the wheel's old `tickDuration`/`wheelDuration` bounds: [5](#0-4) [6](#0-5) 

If the admin reduces the conntrack timeouts on reload (e.g. shortens `firewall.conntrack.udp_timeout` from a large old max down to a very small value), the new, correct (short) `c.Expires` is computed and stored, but the actual eviction re-check via `TimerWheel.Purge()`/`evict()` is only triggered when the *stale, larger* wheel tick fires — because the entry was inserted into a wheel whose `tickDuration`/`wheelDuration` still correspond to the pre-reload (larger) timeout configuration: [7](#0-6) 

Until that stale, delayed wheel tick fires, the conntrack entry remains present in `conntrack.Conns` and continues to be matched and permitted by `inConns`, even though its intended (newly configured, shorter) timeout has already elapsed: [8](#0-7) 

This means a firewall reload that is meant to tighten conntrack timeouts does not take effect for already-established flows until the stale wheel period elapses — the conntrack table continues authorizing traffic based on the old, longer timeout window despite the administrator's newly configured shorter one.

### Impact Explanation
This is a firewall enforcement bypass in the temporal sense: traffic that should be re-evaluated/dropped once the newly configured (shorter) conntrack timeout has elapsed continues to be passed through the firewall as an established "allowed" flow, because the stale `TimerWheel` retained from before the reload does not fire its eviction check until much later. An attacker who already has an open flow through the firewall at the time of the reload effectively gets an unintended grace period beyond the administrator's newly configured timeout, extending the window during which their traffic is treated as a matched conntrack entry rather than being re-subjected to full rule evaluation.

### Likelihood Explanation
This triggers deterministically whenever an operator reduces `firewall.conntrack.tcp_timeout`, `udp_timeout`, or `default_timeout` via a config reload (SIGHUP) while existing conntrack entries are present — a routine operational action, not requiring any certificate or privileged access from the attacker's side. The attacker only needs an already-established flow through the firewall at reload time, which is a normal, reachable, no-CA-cert-required condition.

### Recommendation
When `reloadFirewall` builds the new `Firewall` and decides to keep the existing `Conntrack` for continuity, it should also rebuild/replace the `TimerWheel` (or resize it) using the newly configured timeout bounds, re-inserting existing entries with correctly recalculated remaining durations — mirroring how the vesting-rate fix recommends clamping/recomputing derived state whenever the underlying period changes, rather than trusting a stale value baked in before the reconfiguration.

### Proof of Concept
1. Start Nebula with `firewall.conntrack.udp_timeout: 3m` (or similarly large default) and establish a UDP flow so a conntrack entry is added: `addConn` inserts it into `TimerWheel` sized with `tickDuration`/`wheelDuration` derived from the initial (large) timeouts (`firewall.go` `NewFirewall`).
2. Send a SIGHUP after editing the config to set `firewall.conntrack.udp_timeout: 1s`. `reloadFirewall` builds a new `Firewall` with `UDPTimeout = 1s`, but reuses `oldFw.Conntrack` (old `TimerWheel`, still sized for the old ~3-minute bounds) (`interface.go` `reloadFirewall`).
3. Continue sending packets on the existing flow: `inConns`/`addConn` update `c.Expires = time.Now().Add(1s)` using the new short timeout, but the wheel slot scheduled for eviction re-check was set using the old, much larger `tickDuration`/`wheelDuration` (clamped in `findWheel`).
4. Stop sending packets after `c.Expires` (1s) has passed. The conntrack entry should now be considered expired, but because the `TimerWheel`'s stale schedule does not purge that slot for a much longer period, the entry remains in `conntrack.Conns` and continues to match in `inConns`, allowing reply/return traffic through the firewall well beyond the newly configured 1-second timeout.

// findWheel find the next position in the wheel for the provided timeout given the current tick
func (tw *TimerWheel[T]) findWheel(timeout time.Duration) (i int) {
	if timeout < tw.tickDuration {
		// Can't track anything below the set resolution
		timeout = tw.tickDuration
	} else if timeout > tw.wheelDuration {
		// We aren't handling timeouts greater than the wheels duration
		timeout = tw.wheelDuration
	}

	// Find the next highest, rounding up
	tick := int(((timeout - 1) / tw.tickDuration) + 1)

	// Add another tick since the current tick may almost be over then map it to the wheel from our
	// current position
	tick += tw.current + 1
	if tick >= tw.wheelLen {
		tick -= tw.wheelLen
	}

	return tick
}

func (f *Firewall) inConns(fp firewall.Packet, h *HostInfo, caPool *cert.CAPool, localCache firewall.ConntrackCache) bool {
	if localCache != nil {
		if _, ok := localCache[fp]; ok {
			return true
		}
	}
	conntrack := f.Conntrack
	conntrack.Lock()

	// Purge every time we test
	ep, has := conntrack.TimerWheel.Purge()
	if has {
		f.evict(ep)
	}

	c, ok := conntrack.Conns[fp]

	if !ok {
		conntrack.Unlock()
		return false
	}

	if c.rulesVersion != f.rulesVersion {
		// This conntrack entry was for an older rule set, validate
		// it still passes with the current rule set
		table := f.OutRules
		if c.incoming {
			table = f.InRules
		}

		// We now know which firewall table to check against
		if !table.match(fp, c.incoming, h.ConnectionState.peerCert, caPool) {
			if f.l.Enabled(context.Background(), slog.LevelDebug) {
				h.logger(f.l).Debug("dropping old conntrack entry, does not match new ruleset",
					"fwPacket", fp,
					"incoming", c.incoming,
					"rulesVersion", f.rulesVersion,
					"oldRulesVersion", c.rulesVersion,
				)
			}
			delete(conntrack.Conns, fp)
			conntrack.Unlock()
			return false
		}

		if f.l.Enabled(context.Background(), slog.LevelDebug) {
			h.logger(f.l).Debug("keeping old conntrack entry, does match new ruleset",
				"fwPacket", fp,
				"incoming", c.incoming,
				"rulesVersion", f.rulesVersion,
				"oldRulesVersion", c.rulesVersion,
			)
		}

		c.rulesVersion = f.rulesVersion
	}

	switch fp.Protocol {
	case firewall.ProtoTCP:
		c.Expires = time.Now().Add(f.TCPTimeout)
	case firewall.ProtoUDP:
		c.Expires = time.Now().Add(f.UDPTimeout)
	default:
		c.Expires = time.Now().Add(f.DefaultTimeout)
	}

	conntrack.Unlock()

	if localCache != nil {
		localCache[fp] = struct{}{}
	}

	return true
}

func (f *Firewall) addConn(fp firewall.Packet, incoming bool) {
	var timeout time.Duration
	c := &conn{}

	switch fp.Protocol {
	case firewall.ProtoTCP:
		timeout = f.TCPTimeout
	case firewall.ProtoUDP:
		timeout = f.UDPTimeout
	default:
		timeout = f.DefaultTimeout
	}

	conntrack := f.Conntrack
	conntrack.Lock()
	if _, ok := conntrack.Conns[fp]; !ok {
		conntrack.TimerWheel.Advance(time.Now())
		conntrack.TimerWheel.Add(fp, timeout)
	}

	// Record which rulesVersion allowed this connection, so we can retest after
	// firewall reload
	c.incoming = incoming
	c.rulesVersion = f.rulesVersion
	c.Expires = time.Now().Add(timeout)
	conntrack.Conns[fp] = c
	conntrack.Unlock()
}

// Evict checks if a conntrack entry has expired, if so it is removed, if not it is re-added to the wheel
// Caller must own the connMutex lock!
func (f *Firewall) evict(p firewall.Packet) {
	// Are we still tracking this conn?
	conntrack := f.Conntrack
	t, ok := conntrack.Conns[p]
	if !ok {
		return
	}

	newT := t.Expires.Sub(time.Now())

	// Timeout is in the future, re-add the timer
	if newT > 0 {
		conntrack.TimerWheel.Advance(time.Now())
		conntrack.TimerWheel.Add(p, newT)
		return
	}

	// This conn is done
	delete(conntrack.Conns, p)
}
