### Title
Deposit and withdraw fees can be fully avoided via rounding down in `quoteDepositOut`/`quoteWithdrawOut` - (File: contracts/DepositToken.sol)

### Summary
`DepositToken` computes protocol fees as `amount_.wadMul(fee)` and transfers only `amount - fee` worth of value. `wadMul` rounds half-up to the nearest wei, so for any `amount_ < HALF_WAD / fee` the computed fee is exactly `0`, and for many larger amounts the fee is rounded in the caller's favor. An unprivileged user can split deposits and withdrawals into small chunks and pay zero protocol fee, the same bug class as the Yieldy `instantUnstake` finding.

### Finding Description
In `DepositToken.sol`:

- `quoteDepositOut`: `_fee = amount_.wadMul(_depositFee); _amountToDeposit = amount_ - _fee;` — the user is credited `amount_ - fee`.
- `quoteWithdrawOut`: `_fee = amount_.wadMul(_withdrawFee); _amountToWithdraw = amount_ - _fee;` — the user receives `amount_ - fee`.
- `_withdraw` burns `_withdrawn` and transfers `_fee` msdTOKEN to `feeCollector`; when `_fee == 0` nothing is collected.
- `deposit` mints `_deposited` to the user and `_fee` to `feeCollector`; when `_fee == 0` nothing is collected.

`WadRayMath.wadMul` returns `(a * b + HALF_WAD) / WAD` (`contracts/lib/WadRayMath.sol:25-31`). Therefore `_fee == 0` whenever `amount_ * fee < 0.5e18`. With a 0.25% fee (`2.5e15`), any `amount_ <= 199` wei is fee-free; with a 0.1% fee, any `amount_ <= 499` wei. Both `deposit` and `withdraw` are public, `whenNotPaused`/`whenNotShutdown` entry points with no minimum-amount check besides `amount_ == 0`.

Concretely an attacker can:
1. Call `deposit(amount_, attacker)` repeatedly with `amount_` below the rounding threshold — zero deposit fee paid.
2. Call `withdraw(amount_, attacker)` repeatedly to pull the collateral back out — zero withdraw fee paid.

Since the deposit itself can also be chunked to avoid the entry fee, the entire round trip bypasses `FeeProvider` fees. The same pattern exists in `Pool.quoteSwapOut` (`_fee = _amountOut.wadMul(_swapFee); _amountOut -= _fee;`) and `quoteLiquidateOut`, so swaps and small liquidations have the identical rounding-to-zero property.

### Impact Explanation
Protocol deposit/withdraw (and swap) fees are silently set to zero for small amounts, letting any user fully avoid fees by looping transfers. On low-cost chains this drains expected fee revenue to `feeCollector`; economically the protocol charges nothing where a fee is configured. Per Metronome's own code this is a direct loss of protocol yield/fees, matching the impact accepted in the original Yieldy finding.

### Likelihood Explanation
Likelihood is high where fees are configured and gas is cheap: the threshold is `0.5e18 / fee` wei of the deposit token. For an 18-decimal collateral this is dust-sized, but for low-decimals underlying (e.g., 6–8 decimals wrapped assets) the threshold is a non-trivial fraction of a unit, and even for 18-decimal tokens the attack remains profitable on L2s since `deposit`/`withdraw` are single cheap calls. No privileged role, oracle manipulation, or timing is required — only repeated public calls.

### Recommendation
Compute the net amount so that the fee component rounds up, not the user-facing amount. Mirror the Uniswap-style mitigation, e.g.:

```solidity
_amountToWithdraw = amount_.wadMul(1e18 - _withdrawFee); // rounds net down => fee effectively rounds up
_fee = amount_ - _amountToWithdraw;
```

Apply the same fix in `quoteDepositOut`, `quoteSwapIn`/`quoteSwapOut`, and `quoteLiquidateOut`. Optionally also enforce a minimum `amount_` in `deposit`/`withdraw`/`swap`.

### Proof of Concept
Foundry-style test (against a deployed pool where `feeProvider.withdrawFee() = 0.0025e18`):

```solidity
// attacker holds msdVaUSDC; withdrawFee = 0.25%
uint256 amount = 199; // amount * fee = 199 * 0.0025e18 < 0.5e18

for (uint256 i; i < N; ++i) {
    (uint256 withdrawn, uint256 fee) = msdToken.withdraw(amount, attacker);
    assertEq(fee, 0);        // wadMul rounds to 0
    assertEq(withdrawn, 199);// full amount returned
}
// total withdrawn == 199*N with zero fee paid to feeCollector
```

Contrast: a single `withdraw(199 * N, attacker)` would pay `wadMul(199*N, fee) > 0`. The split-loop strictly avoids the configured fee. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) [5](#0-4)
