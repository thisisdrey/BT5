### Title
Protocol fees on `Nep245`/`Imt` `TokenDiff` intents can be bypassed entirely by splitting a large negative delta into many unit (`|delta| == 1`) intents - (`contracts/defuse/core/src/intents/token_diff.rs`)

### Summary
`TokenDiff::execute_intent` computes and collects the protocol fee independently for each signed `TokenDiff` intent, using only that intent's own per-token delta magnitude, with no aggregation across the intents in a batch or across a signer's history. Because `TokenDiff::token_fee` exempts `Nep245`/`Imt` tokens from fees whenever the per-intent amount is `<= 1`, a signer can split a single `-1000` delta on such a token into 1000 separately signed `TokenDiff` intents each with `delta == -1`, causing the fee for that token to be evaluated as `Pips::ZERO` 1000 times instead of once as `fee_ceil(1000)`.

### Finding Description
The broken binding: for a signer's batch, the fee credited to `fee_collector` for token `T` should equal `Pips::fee_ceil(protocol_fee, aggregate_negative_delta_of_T)`. Instead, the implementation computes, per `TokenDiff` intent `i`:

```
fees_collected[T] = Σ_i  TokenDiff::token_fee(T, |delta_i|, fee).fee_ceil(|delta_i|)
``` [1](#0-0) 

`token_fee` returns `Pips::ZERO` for `Nep245`/`Imt` tokens whenever `amount <= 1`: [2](#0-1) 

This per-intent, per-amount check is never reconciled against the total amount moved by the signer across the batch. `Engine::execute_signed_intents` simply iterates every `MultiPayload` in the batch and executes each signed intent independently, without any cross-intent or cross-payload fee accounting: [3](#0-2) 

Exploit: an unprivileged signer holding an `Nep245` (NEP-245 multi-token, which supports arbitrary/fungible supply, not only NFT-like 1/1 items) balance of 1000 units of token `T` wants to spend all 1000 units. Instead of signing one `TokenDiff{diff: {T: -1000, out: +X}}` (which would legitimately incur `fee_ceil(1000)`), the signer signs 1000 separate `MultiPayload`s, each a `TokenDiff{diff: {T: -1, out: +x_i}}` with distinct nonces, and submits all 1000 in a single `execute_intents(signed)` call. For each of these, `amount = 1`, so `token_fee` returns `Pips::ZERO`, and `fee_ceil(1)` for that call is `0`. Aggregate fee collected on `T` across the whole batch is `0`, whereas a single unsplit intent would have incurred `Pips::fee_ceil(fee, 1000) > 0` (for any nonzero `fee`). The `+x_i` outgoing legs must still balance against a counterparty in the same batch (via `TransferMatcher::finalize`), but that is orthogonal to fee computation on the signer's negative-delta side and does not prevent the split.

None of the existing guards prevent this: `execute_intent`'s `delta == 0` rejection only stops zero-delta griefing, not `|delta| == 1` splitting [4](#0-3) ; nonce/signature verification, `has_public_key`, and `verify_intent_nonce` only ensure each payload is authentically the signer's own and used once, they impose no cap on how many distinct nonces/payloads one signer can bundle into one `execute_intents` call [5](#0-4) ; `TransferMatcher::finalize` only verifies net-zero balance across the batch, not fee correctness [6](#0-5) .

### Impact Explanation
Fees that should be credited to `fee_collector` for `Nep245`/`Imt` token trades are reduced to zero regardless of the true traded volume, as long as the signer (and any cooperating counterparty) is willing to sign and submit many small unit-delta intents in one transaction. This is a direct, repeatable protocol-fee bypass (Critical: "protocol fees bypassed") affecting any deployer/holder of an NEP-245 multi-token used as a fungible-like asset within the Verifier. It scales linearly with the number of split intents an attacker is willing to construct and sign, and it works for any nonzero configured fee.

### Likelihood Explanation
The attacker needs only: (1) a balance of an `Nep245` token inside the Verifier (self-controlled, since anyone can deploy their own MT contract and deposit into their own Defuse account), (2) their own signing key, and (3) the ability to construct N `MultiPayload`s with distinct nonces (trivial, entirely client-side) and submit them together via `execute_intents`. No privileged role, relayer key, or victim key is required. The only cost is proportional gas/tx size for signing and submitting more, smaller intents (explicitly out of scope to weigh as a deterrent per audit rules), making this fully attacker-controlled and repeatable across tokens, accounts, and batches.

### Recommendation
Compute and enforce the `Nep245`/`Imt` fee exemption based on the aggregate absolute negative delta per `(signer, token)` across the entire signed batch (or better, disallow the `amount <= 1` fee exemption from being satisfied by cumulative small transfers within one `execute_intents` call), mirroring the aggregation logic already implemented client-side in `TokenDiff::closure_deltas`/`supply_delta` (contracts/defuse/core/src/intents/token_diff.rs:139-183), instead of evaluating `token_fee` independently per intent.

### Proof of Concept
`cargo test` plan (near-workspaces sandbox, e.g. in `tests/src/tests/defuse/intents/token_diff.rs`):
1. Deploy an NEP-245 multi-token contract; deposit 1000 units of token `T` into attacker's Defuse account; set a nonzero protocol `fee` (e.g. `Pips::ONE_PERCENT`).
2. Baseline: sign a single `TokenDiff{diff: {T: -1000, out_token: +closure}}` payload, execute it, and assert `fees_collected[T] == Pips::fee_ceil(fee, 1000)` (from the emitted `TokenDiffEvent`/fee_collector balance) — non-zero.
3. Exploit: reset state, sign 1000 separate `TokenDiff{diff: {T: -1, out_token: +x_i}}` payloads (distinct nonces) from the same attacker, balanced against a counterparty in the same batch; call `execute_intents` once with all 1000 signed payloads plus the counterparty payload(s).
4. Assert the fee_collector's balance increase for `T` after step 3 is `0`, while `Pips::fee_ceil(fee, 1000) > 0`, demonstrating `fees_collected == 0 != Pips::fee_ceil(fee, 1000)` — confirming the aggregate binding is violated.

        mut self,
        signed: impl IntoIterator<Item = MultiPayload>,
    ) -> Result<Transfers> {
        for signed in signed {
            self.execute_signed_intent(signed)?;
        }
        self.finalize()
    }

    fn execute_signed_intent(&mut self, signed: MultiPayload) -> Result<()> {
        // verify signed payload and get public key
        let public_key = signed.verify().ok_or(DefuseError::InvalidSignature)?;

        // calculate intent hash
        let hash = signed.hash();

        // extract NEP-413 payload
        let DefusePayload::<DefuseIntents> {
            signer_id,
            verifying_contract,
            deadline,
            nonce,
            message: intents,
        } = signed.extract_defuse_payload()?;

        // check recipient
        if verifying_contract != *self.state.verifying_contract() {
            return Err(DefuseError::WrongVerifyingContract);
        }

        self.inspector.on_deadline(deadline);

        // make sure message is still valid
        if deadline < Timestamp::now() {
            return Err(DefuseError::DeadlineExpired);
        }

        // make sure the account has this public key
        if !self.state.has_public_key(&signer_id, &public_key) {
            return Err(DefuseError::PublicKeyNotExist(signer_id, public_key));
        }

        // commit nonce
        self.verify_intent_nonce(nonce, deadline)?;
        self.state.commit_nonce(signer_id.clone(), nonce)?;

        intents.execute_intent(&signer_id, self, hash)?;
        self.inspector.on_intent_executed(&signer_id, hash, nonce);

        Ok(())
    }

    // Finalizes all transfers, or returns unmatched deltas.
    // If unmatched deltas overflow, then Err(None) is returned.
    pub fn finalize(self) -> Result<Transfers, InvariantViolated> {
        let mut transfers = Transfers::default();
        let mut deltas = TokenDeltas::default();
        for (token_id, transfer_matcher) in self.0 {
            if let Err(unmatched) = transfer_matcher.finalize_into(&token_id, &mut transfers)
                && (unmatched == 0 || deltas.apply_delta(token_id, unmatched).is_none())
            {
                return Err(InvariantViolated::Overflow);
            }
        }
        if !deltas.is_empty() {
            return Err(InvariantViolated::UnmatchedDeltas {
                unmatched_deltas: deltas,
            });
        }
        Ok(transfers)
    }
