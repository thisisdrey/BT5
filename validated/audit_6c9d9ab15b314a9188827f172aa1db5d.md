Found `RepositoryImpl.calculateGlobalEnergyLimit` reachable from a plain contract-call transaction via the TVM energy-accounting path, with an unguarded integer/long division that can crash the node.

### Title
Unhandled division-by-zero in `RepositoryImpl.calculateGlobalEnergyLimit` when `totalEnergyWeight` is 0 - (File: actuator/src/main/java/org/tron/core/vm/repository/RepositoryImpl.java)

### Summary
`RepositoryImpl.calculateGlobalEnergyLimit(AccountCapsule)` divides by `totalEnergyWeight` without a zero-guard, unlike its sibling implementations in `EnergyProcessor` (`chainbase/src/main/java/org/tron/core/db/EnergyProcessor.java`) which explicitly check `totalEnergyWeight <= 0` before dividing. If `totalEnergyWeight` is 0 or negative and hardened resource calculation (`VMConfig.allowHardenResourceCalculation()`) is enabled, `BigInteger.divide(BigInteger.ZERO)` throws an unhandled `ArithmeticException`, which propagates out of energy accounting called from ordinary contract execution.

### Finding Description
`RepositoryImpl.calculateGlobalEnergyLimit`: [1](#0-0) 

```java
public long calculateGlobalEnergyLimit(AccountCapsule accountCapsule) {
    long frozeBalance = accountCapsule.getAllFrozenBalanceForEnergy();
    if (frozeBalance < TRX_PRECISION) {
      return 0;
    }
    long energyWeight = frozeBalance / TRX_PRECISION;
    long totalEnergyLimit = getDynamicPropertiesStore().getTotalEnergyCurrentLimit();
    long totalEnergyWeight = getDynamicPropertiesStore().getTotalEnergyWeight();

    assert totalEnergyWeight > 0;

    if (hardenResourceCalculation()) {
      return BigInteger.valueOf(energyWeight)
          .multiply(BigInteger.valueOf(totalEnergyLimit))
          .divide(BigInteger.valueOf(totalEnergyWeight))
          .longValueExact();
    }
    return (long) (energyWeight * ((double) totalEnergyLimit / totalEnergyWeight));
}
```

The only protection against `totalEnergyWeight == 0` is a Java `assert` statement, which is compiled out and disabled by default (`-ea` is not passed at runtime in production JVMs), so it provides no real protection. Contrast this with the two nearly identical, safety-hardened sibling implementations that were already fixed in this codebase: [2](#0-1) [3](#0-2) 

Both `EnergyProcessor.calculateGlobalEnergyLimit` and `BandwidthProcessor.calculateGlobalNetLimit` contain the explicit guard `if (dynamicPropertiesStore.allowNewReward() && totalEnergyWeight <= 0) { return 0; }` / `if (totalNetWeight == 0) { return 0; }`, showing this exact division-by-zero class was identified and remediated for the account-resource-consumption paths, but the `RepositoryImpl` copy used by the VM/TVM `Repository` interface (reachable from smart-contract execution, e.g. via `ENERGY_LIMIT`/opcode-triggered energy checks and `ContractState.getAccountEnergyUsage`/`calculateGlobalEnergyLimit`) was not updated with the same guard.

`totalEnergyWeight` is a chain-wide dynamic property (`DynamicPropertiesStore.getTotalEnergyWeight()`), decremented as accounts unfreeze energy-frozen balance. It is technically possible to reach 0 (e.g. right after a large-scale unfreeze, or on freshly bootstrapped test/private networks before any energy is frozen), and this call path is exercised on every energy-consuming contract call through the `Repository`/`ContractState` abstraction.

### Impact Explanation
An unhandled `ArithmeticException` thrown deep inside the TVM energy-accounting code, invoked during ordinary contract execution/energy metering, would propagate as an uncaught runtime exception if not caught by the surrounding actuator, potentially aborting block processing/transaction execution unexpectedly and causing a node crash or, in the worst case, non-deterministic transaction execution results between nodes if error handling differs, risking a chain split.

### Likelihood Explanation
The precondition (`totalEnergyWeight == 0`) is a valid, currently-untested chain state combined with `allowHardenResourceCalculation()` being enabled (a feature switch already present and toggled in tests via `VMConfig.initAllowHardenResourceCalculation(1)`), and can be triggered simply by any account making a normal contract call while that global state holds — no special privilege is required to trigger the call path itself.

### Recommendation
Add the same zero/negative guard used in `EnergyProcessor.calculateGlobalEnergyLimit` and `BandwidthProcessor.calculateGlobalNetLimit` to `RepositoryImpl.calculateGlobalEnergyLimit`, replacing the disabled `assert totalEnergyWeight > 0;` with an explicit `if (totalEnergyWeight <= 0) { return 0; }` before the `hardenResourceCalculation()` branch.

### Proof of Concept
1. On a network (e.g. private/test net) where `totalEnergyWeight` becomes 0 (all energy-frozen balances withdrawn) and `allowHardenResourceCalculation` is enabled via `VMConfig`.
2. Any account with `frozeBalance >= TRX_PRECISION` (from `AccountCapsule.getAllFrozenBalanceForEnergy()`) issues a normal `TriggerSmartContract` transaction that reaches energy accounting via `Repository`/`ContractState.calculateGlobalEnergyLimit`.
3. `RepositoryImpl.calculateGlobalEnergyLimit` executes `BigInteger.valueOf(totalEnergyLimit).divide(BigInteger.valueOf(0))`, throwing an unhandled `ArithmeticException` that is not caught by the intended validate/execute exception paths for this specific call, as confirmed by the existing hardened-path tests in `framework/src/test/java/org/tron/core/vm/repository/RepositoryImplHardenTest.java` which demonstrate `ArithmeticException` being thrown by this class of computation under hardening.

  public long calculateGlobalEnergyLimit(AccountCapsule accountCapsule) {
    long frozeBalance = accountCapsule.getAllFrozenBalanceForEnergy();
    if (dynamicPropertiesStore.supportUnfreezeDelay()) {
      return calculateGlobalEnergyLimitV2(frozeBalance);
    }
    if (frozeBalance < TRX_PRECISION) {
      return 0;
    }

    long totalEnergyLimit = dynamicPropertiesStore.getTotalEnergyCurrentLimit();
    long totalEnergyWeight = dynamicPropertiesStore.getTotalEnergyWeight();
    if (dynamicPropertiesStore.allowNewReward() && totalEnergyWeight <= 0) {
      return 0;
    } else {
      assert totalEnergyWeight > 0;
    }
    if (hardenCalculation()) {
      return calculateGlobalLimitV1(frozeBalance, totalEnergyLimit, totalEnergyWeight);
    }
    long energyWeight = frozeBalance / TRX_PRECISION;
    return (long) (energyWeight * ((double) totalEnergyLimit / totalEnergyWeight));
  }
