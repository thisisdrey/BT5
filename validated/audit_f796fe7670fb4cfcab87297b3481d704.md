### Title
Archive Extraction Path Traversal via untrusted tar in `CreateRepositoryFromSnapshot` - ([File: internal/gitaly/service/repository/create_repository_from_snapshot.go])

### Summary
`server.untar` streams the body fetched from the attacker-controlled `HttpUrl` (optionally with attacker-controlled `HttpAuth` header) directly into an external `tar -C path -xvf -` process with no validation of archive entry names. A malicious tar containing `../` traversal segments or symlink entries can cause files to be written outside the newly-created repository directory, anywhere the Gitaly process has write access under the storage root (including other repositories' `hooks/` directories).

### Finding Description
`CreateRepositoryFromSnapshot` calls `repoutil.Create` to initialize a new bare repository at `path`, then invokes `s.untar(ctx, path, in)` [1](#0-0) . Inside `untar`, the response body of an HTTP GET to `in.GetHttpUrl()` (with an optional attacker-supplied `Authorization` header from `in.GetHttpAuth()`) is piped as stdin into the shell command `tar -C path -xvf -` [2](#0-1) .

There is no inspection of the archive's entries: no allowlist of relative paths, no rejection of `../` segments, no rejection of symlink/hardlink entries, and no post-extraction verification that written files remain under `path`. The code comment explicitly acknowledges this: "the received archive is trusted *a lot*... Before pointing this RPC at endpoints not under our control, it should undergo a lot of hardening." [3](#0-2) .

None of the standard Gitaly path-confinement mechanisms (`storage.ValidateRelativePath`, locator path joining) apply here, because the confinement is delegated entirely to the external `tar` binary's own path handling, and GNU `tar` extracts relative paths containing `../` as given (it only strips leading `/` for absolute-path member names by default) — it does not clamp extraction to the `-C` directory for relative traversal sequences. An attacker who controls `HttpUrl` (e.g. via GitLab's "import project by URL"-style flow feeding into this RPC, or any SSRF-reachable/attacker-hosted endpoint) can therefore craft a tar with entries such as `../../<victim-repo>.git/hooks/pre-receive` to write/overwrite an executable hook in a sibling repository, or write to arbitrary paths under the storage root that the Gitaly process user can reach.

### Impact Explanation
This enables cross-repository file write, including writing a git hook (`pre-receive`, `post-receive`, etc.) into another repository, which grants arbitrary code execution in the context of that repository's future push/receive operations — this is a hook/quarantine-bypass style compromise and storage-path escape, matching the "storage-path escape" / "hook bypass leading to RCE" impact classes.

### Likelihood Explanation
The attacker only needs the ability to trigger `CreateRepositoryFromSnapshot` for a repository they own, supplying an `HttpUrl` they control (their own server or an SSRF-reachable target) and serving a crafted tar file. No admin privileges, stolen secrets, or non-default configuration are required — only that this RPC path is reachable from a user-initiated flow (e.g., project import). Given that, the exploit is deterministic and repeatable.

### Recommendation
Do not shell out to the system `tar` binary on untrusted input. Extract the archive in-process (e.g., Go's `archive/tar`) while: rejecting any entry whose cleaned relative path escapes `path` (reject `..` after `filepath.Clean`/`filepath.Rel` check), rejecting symlink/hardlink entries or resolving and validating their targets stay within `path`, and enforcing size/entry-count limits. Alternatively, restrict `HttpUrl` to a strict allowlist of trusted internal snapshot endpoints and drop `HttpAuth`/`HttpUrl` as free-form user input.

```go
func TestCreateRepositoryFromSnapshot_pathTraversal(t *testing.T) {
    // Serve a malicious tar containing a traversal entry.
    var buf bytes.Buffer
    tw := tar.NewWriter(&buf)
    payload := []byte("#!/bin/sh\ntouch /tmp/pwned\n")
    require.NoError(t, tw.WriteHeader(&tar.Header{
        Name: "../../victim.git/hooks/pre-receive",
        Mode: 0o755,
        Size: int64(len(payload)),
    }))
    _, err := tw.Write(payload)
    require.NoError(t, err)
    require.NoError(t, tw.Close())

    srv := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        w.Write(buf.Bytes())
    }))
    defer srv.Close()

    // ... call CreateRepositoryFromSnapshot with HttpUrl: srv.URL
    // Assert: /storage-root/victim.git/hooks/pre-receive now exists and is executable,
    // even though "victim.git" is not the repository being created.
}
```

```go
func (s *server) untar(ctx context.Context, path string, in *gitalypb.CreateRepositoryFromSnapshotRequest) error {
	req, err := http.NewRequestWithContext(ctx, "GET", in.GetHttpUrl(), nil)
	if err != nil {
		return structerr.NewInvalidArgument("Bad HTTP URL: %w", err)
	}

	client := httpClient
	if resolvedAddress := in.GetResolvedAddress(); resolvedAddress != "" {
		client, err = newResolvedHTTPClient(in.GetHttpUrl(), resolvedAddress)
		if err != nil {
			return structerr.NewInvalidArgument("creating resolved HTTP client: %w", err)
		}
	}

	if in.GetHttpAuth() != "" {
		req.Header.Set("Authorization", in.GetHttpAuth())
	}

	rsp, err := client.Do(req)
	if err != nil {
		return structerr.NewInternal("HTTP request failed: %w", err)
	}
	defer rsp.Body.Close()

	if rsp.StatusCode < http.StatusOK || rsp.StatusCode >= http.StatusMultipleChoices {
		return structerr.NewInternal("HTTP server: %s", rsp.Status)
	}

	cmd, err := command.New(ctx, s.logger, []string{"tar", "-C", path, "-xvf", "-"}, command.WithStdin(rsp.Body))
	if err != nil {
		return err
	}

	return cmd.Wait()
```
