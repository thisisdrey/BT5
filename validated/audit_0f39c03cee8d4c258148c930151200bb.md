### Title
Unguarded `getContract(0)` access in `TransactionCapsule.validateSignature` before contract-count validation - (File: `chainbase/src/main/java/org/tron/core/capsule/TransactionCapsule.java`)

### Summary
`TransactionCapsule.validateSignature()` dereferences the first transaction contract via `getContract(0)` *before* any check that the `contract` list is non-empty, mirroring the CVE-2016-2782 root cause: a code path accesses a structure/element it assumes exists without verifying that assumption first, causing an unhandled fault when the structure is absent.

### Finding Description
`validateSignature()` immediately does: [1](#0-0) 
which calls `this.getInstance().getRawData().getContract(0)` with no prior `getContractCount() > 0` guard. The count check only exists inside the sibling helper `validatePubSignature()`, which is invoked *after* this unguarded access: [2](#0-1) 
If `getContractCount()` is `0`, line 702's `getContract(0)` throws `IndexOutOfBoundsException` before the intended `ValidateSignatureException("miss sig or contract")` can ever be raised. Other call sites in the same codebase (`TransactionUtil.getTransactionSignWeight`, `Wallet.getTransactionApprovedList`) explicitly guard with `getContractCount() == 0` before calling `getContract(0)`, showing the convention this method fails to follow.

This method is invoked from `Manager.ValidateSignTask.call()`: [3](#0-2) 
which only catches `ValidateSignatureException`. An `IndexOutOfBoundsException` raised inside `validateSignature()` is not a `ValidateSignatureException`, so it is not handled by this catch block and propagates as an unexpected `RuntimeException` out of the signature-validation task for a transaction submitted with an empty `contract` list.

### Impact Explanation
A transaction crafted with zero entries in `raw_data.contract` (a structurally valid but semantically empty protobuf transaction) reaching multi-threaded signature validation triggers an uncaught `IndexOutOfBoundsException` instead of the intended, safely-handled `ValidateSignatureException`. This is the same bug class as CVE-2016-2782: a missing precondition check before touching an optional/absent element, leading to an unhandled runtime fault in a security-critical validation routine reachable by any unprivileged transaction broadcaster.

### Likelihood Explanation
Any unprivileged client can submit a transaction (e.g., via gRPC/HTTP broadcast) with a `raw_data` containing an empty `contract` list; this requires no special privileges, signatures, or preconditions besides the malformed transaction reaching the signature-validation stage.

### Recommendation
Add an explicit `getContractCount() == 0` (or `!= 1`) check at the very top of `validateSignature()`, before calling `getContract(0)`, mirroring the guard already present in `validatePubSignature()`, `TransactionUtil.getTransactionSignWeight()`, and `Wallet.getTransactionApprovedList()`, and throw `ValidateSignatureException` consistently instead of allowing an unchecked exception to propagate.

### Proof of Concept
1. Construct a `Transaction` whose `raw_data` has an empty `contract` repeated field (no `Contract` entries) but a non-empty or empty `signature` list.
2. Wrap it in a `TransactionCapsule` and invoke `validateSignature(accountStore, dynamicPropertiesStore)` directly, or submit it through the broadcast path that schedules a `Manager.ValidateSignTask` for it.
3. Observe that execution throws `IndexOutOfBoundsException` at `this.getInstance().getRawData().getContract(0)` (line 702) instead of the expected `ValidateSignatureException("miss sig or contract")`, since that guard is only reached inside `validatePubSignature()`, which is never invoked before the crash.   public boolean validateSignature(AccountStore accountStore,
      DynamicPropertiesStore dynamicPropertiesStore) throws ValidateSignatureException {
    if (!isVerified) {
      //Do not support multi contracts in one transaction
      Transaction.Contract contract = this.getInstance().getRawData().getContract(0);
      if (contract.getType() != ContractType.ShieldedTransferContract) {
        validatePubSignature(accountStore, dynamicPropertiesStore);
      } else {  //ShieldedTransfer
        byte[] owner = getOwnerAddress();
        if (!ArrayUtils.isEmpty(owner)) { //transfer from transparent address
          validatePubSignature(accountStore, dynamicPropertiesStore);
        } else { //transfer from shielded address
          if (this.transaction.getSignatureCount() > 0) {
            throw new ValidateSignatureException("there should be no signatures signed by "
                    + "transparent address when transfer from shielded address");
          }
        }
      }
      isVerified = true;
    }
    return true;
  }

  private static class ValidateSignTask implements Callable<Boolean> {

    private TransactionCapsule trx;
    private CountDownLatch countDownLatch;
    private ChainBaseManager manager;

    ValidateSignTask(TransactionCapsule trx, CountDownLatch countDownLatch,
        ChainBaseManager manager) {
      this.trx = trx;
      this.countDownLatch = countDownLatch;
      this.manager = manager;
    }

    @Override
    public Boolean call() throws ValidateSignatureException {
      try {
        trx.validateSignature(manager.getAccountStore(), manager.getDynamicPropertiesStore());
      } catch (ValidateSignatureException e) {
        throw e;
      } finally {
        countDownLatch.countDown();
      }
      return true;
    }
  }
