### Title
Unbounded number of concurrent pending handshakes allows transient memory amplification via distinct unestablished destinations - ([File: handshake_manager.go], [File: inside.go])

### Summary
`consumeInsidePacket` → `getOrHandshakeConsiderRouting` → `HandshakeManager.GetOrHandshake` → `StartHandshake` creates one `HandshakeHostInfo` entry per distinct destination VPN address with no cap on the total number of concurrently pending entries in `hm.vpnIps`. Each such entry can buffer up to `maxCachedPackets` (100) full MTU-sized packets via `hh.cachePacket`, so while the per-hostinfo cache is bounded, the aggregate memory across many simultaneously pending, never-established destinations is not.

### Finding Description
`HandshakeManager.StartHandshake` unconditionally inserts a new `*HandshakeHostInfo` into `hm.vpnIps[vpnAddr]` for every new, distinct destination address seen, with no limit on map size: [1](#0-0) 

`GetOrHandshake` calls `StartHandshake` whenever the destination is not already in the main hostmap, and the caller-supplied `cacheCallback` (from `inside.go`) immediately calls `hh.cachePacket`, which stores up to `maxCachedPackets = 100` copies of the outgoing packet per `HandshakeHostInfo`: [2](#0-1) [3](#0-2) [4](#0-3) 

While `maxCachedPackets` bounds memory *per* pending-handshake entry, there is no corresponding cap on the *number* of entries that can exist in `hm.vpnIps` at once. Each entry stays alive until `DefaultHandshakeRetries` (10) attempts time out (`handleOutbound` in `handshake_manager.go:207-236`, deleting the entry once `hh.counter >= hm.config.retries`), which — given `DefaultHandshakeTryInterval` and linear backoff — keeps an entry alive for multiple seconds. If a burst of packets addressed to many distinct, never-established destinations is originated within that window (e.g., via routed/unsafe-network traffic reaching this node's TUN, or ECMP gateway fallout in `getOrHandshakeConsiderRouting`), the number of live `HandshakeHostInfo` entries — and their associated packet caches (up to 100 × MTU bytes each) — grows proportionally to the number of distinct destinations, unconstrained by any global limit.

### Impact Explanation
This is a transient, bounded-duration memory amplification: total worst-case memory is roughly `(distinct destinations reached within the handshake retry window) × 100 × MTU`. With a sufficiently high rate of distinct-destination traffic sustained across the retry window, this can materially inflate heap usage and add GC/allocation pressure on the node processing packets for all peers, matching a resource-exhaustion / availability-degradation impact category. It is not an unbounded/permanent leak (entries are eventually reaped by the timeout path), which limits severity relative to a true unbounded cache.

### Likelihood Explanation
Exploitability depends entirely on the stated precondition — the node originating or routing packets to many distinct, non-existent VPN addresses within its configured networks (e.g., via `unsafe_routes`/gateway routing reachable from a downstream, unprivileged network segment). Given that precondition, triggering it requires only ordinary, unauthenticated data-plane traffic; no certificate or handshake completion is needed. Without that routing precondition (i.e., a normal, non-routing Nebula node whose TUN only carries locally-originated traffic under the node operator's control), this is not remotely triggerable by an unprivileged network attacker.

### Recommendation
Add a global cap on the number of concurrent pending entries in `HandshakeManager.vpnIps` (and/or a total cached-packet byte budget across all pending handshakes), rejecting/evicting oldest-first once the limit is reached, similar to the existing per-hostinfo `maxCachedPackets` bound.

### Proof of Concept
Unit test in `handshake_manager_test.go` (or new test file):
1. Construct a `HandshakeManager` with a fake `mainHostMap`/`lightHouse` as done in existing tests.
2. Call `GetOrHandshake` with N (e.g., 100,000) distinct, never-resolving `netip.Addr` values, each with a `cacheCallback` that calls `hh.cachePacket` with an MTU-sized packet.
3. Assert `len(hm.vpnIps)` and total buffered packet bytes across all `HandshakeHostInfo.packetStore` entries stay below a defined global bound; expect the test to fail against current code since no such bound exists (map grows to N entries, up to 100×N cached packets total before any timeout fires).

func (hh *HandshakeHostInfo) cachePacket(l *slog.Logger, t header.MessageType, st header.MessageSubType, packet []byte, f packetCallback, m *cachedPacketMetrics) {
	if len(hh.packetStore) < maxCachedPackets {
		tempPacket := make([]byte, len(packet))
		copy(tempPacket, packet)

		hh.packetStore = append(hh.packetStore, &cachedPacket{t, st, f, tempPacket})
		if l.Enabled(context.Background(), slog.LevelDebug) {
			hh.hostinfo.logger(l).Debug("Packet store",
				"length", len(hh.packetStore),
				"stored", true,
			)
		}

		m.dropped.Inc(1)

			hh.hostinfo.logger(l).Debug("Packet store",
				"length", len(hh.packetStore),
				"stored", false,
			)
		}
	}
}

// GetOrHandshake will try to find a hostinfo with a fully formed tunnel or start a new handshake if one is not present
// The 2nd argument will be true if the hostinfo is ready to transmit traffic
func (hm *HandshakeManager) GetOrHandshake(vpnIp netip.Addr, cacheCb func(*HandshakeHostInfo)) (*HostInfo, bool) {
	hm.mainHostMap.RLock()
	h, ok := hm.mainHostMap.Hosts[vpnIp]
	hm.mainHostMap.RUnlock()

	if ok {
		// Do not attempt promotion if you are a lighthouse
		if !hm.lightHouse.amLighthouse {
			h.TryPromoteBest(hm.mainHostMap.GetPreferredRanges(), hm.f)
		}
		return h, true
	}

	return hm.StartHandshake(vpnIp, cacheCb), false
}

func (hm *HandshakeManager) StartHandshake(vpnAddr netip.Addr, cacheCb func(*HandshakeHostInfo)) *HostInfo {
	hm.Lock()

	if hh, ok := hm.vpnIps[vpnAddr]; ok {
		// We are already trying to handshake with this vpn ip
		if cacheCb != nil {
			cacheCb(hh)
		}
		hm.Unlock()
		return hh.hostinfo
	}

	hostinfo := &HostInfo{
		vpnAddrs:        []netip.Addr{vpnAddr},
		HandshakePacket: make(map[uint8][]byte, 0),
		relayState: RelayState{
			relays:         nil,
			relayForByAddr: map[netip.Addr]*Relay{},
			relayForByIdx:  map[uint32]*Relay{},
		},
	}

	hh := &HandshakeHostInfo{
		hostinfo:  hostinfo,
		startTime: time.Now(),
	}
	hm.vpnIps[vpnAddr] = hh
	hm.metricInitiated.Inc(1)
	hm.OutboundHandshakeTimer.Add(vpnAddr, hm.config.tryInterval)

	if cacheCb != nil {
		cacheCb(hh)
	}
