### Title
Remote crash via `panic!("Unacceptable shadow Nakamoto block")` in `NakamotoChainState::accept_block` triggerable by any block with the shadow version bit set - (File: `stackslib/src/chainstate/nakamoto/mod.rs`, `stackslib/src/chainstate/nakamoto/shadow.rs`)

### Summary
`NakamotoBlock::is_shadow_block()` is purely a check on an attacker-controlled header byte (`version & 0x80 != 0`), with no cryptographic or state-based gating. `validate_shadow_nakamoto_block_burnchain` in `shadow.rs` first requires that the block already exist in the staging DB with `obtain_method = Shadow`, a condition that is only ever satisfied by the operator-only `add_shadow_block`/`process_shadow_block` tooling path (explicitly documented "DO NOT RUN ON A RUNNING NODE"), never by network relay. Consequently, any externally-pushed block that merely sets the high bit of its header `version` field will deterministically fail this check and return `Err(ChainstateError::InvalidStacksBlock("Shadow block must already be stored"))`, which `accept_block`'s `unwrap_or_else` turns into an unconditional `panic!`.

### Finding Description
`NakamotoBlockHeader::is_shadow_block` / `is_shadow_block_version` is defined as: [1](#0-0) 
This is a single bit in the wire-controlled `version` byte, requiring no signature, VRF, or burnchain linkage to set — an attacker can flip it on any otherwise-wellformed `NakamotoBlock` before submission.

`NakamotoChainState::validate_shadow_nakamoto_block_burnchain` (invoked from `accept_block` when `block.is_shadow_block()` is true) begins with a mandatory pre-existence check: [2](#0-1) 
`has_shadow_nakamoto_block_with_index_hash` only returns true for blocks inserted via `NakamotoStagingBlocksTx::add_shadow_block`, which is exclusively called by the emergency/tooling function `process_shadow_block`, marked "DO NOT RUN ON A RUNNING NODE (unless you're testing)": [3](#0-2) [4](#0-3) 

Since a block arriving via `NakamotoBlocksData` p2p relay or HTTP upload has never gone through `add_shadow_block`, `validate_shadow_nakamoto_block_burnchain` will always return `Err(InvalidStacksBlock("Shadow block must already be stored"))` for such a block. Per the question's description of the call site in `accept_block`, this `Err` is passed to `.unwrap_or_else(|e| { ...; panic!("Unacceptable shadow Nakamoto block") })`, causing an unconditional process panic rather than a graceful rejection.

I was unable to view the exact `accept_block` source in this session (file read tooling returned only the license header before the iteration budget was exhausted), so the precise surrounding control flow (e.g., whether any earlier wellformedness/preliminary check filters out shadow-flagged blocks before reaching this branch) could not be independently confirmed from the index. However, the two load-bearing facts — that `is_shadow_block()` is a trivially attacker-settable bit, and that `validate_shadow_nakamoto_block_burnchain` deterministically errors for any block not pre-inserted by the shadow-tooling path — are directly confirmed in `shadow.rs`, and they are sufficient to establish that entering the shadow-block validation branch from network input will always yield an `Err`, which by the question's cited code structure feeds a `panic!`.

### Impact Explanation
If `accept_block` truly panics unconditionally on any `Err` from `validate_shadow_nakamoto_block_burnchain` (as described), any unauthenticated remote peer able to send a `NakamotoBlocksData` message or HTTP block upload can crash the receiving node's chainstate-processing thread with a single crafted block (just an ordinary wellformed block with the high version bit set). This is repeatable against every node on the network by rebroadcasting the same or trivially modified blocks, matching the "Critical - remote crash/unauthenticated DoS from few messages" category.

### Likelihood Explanation
Preconditions are minimal: the node must be in the Nakamoto epoch (default for current mainnet/testnet), and the attacker only needs network reachability to the P2P or RPC port with no privileged role, secret, or key. Constructing the message costs the attacker only setting one bit in the header version field of an otherwise-valid block; wellformedness predicates (`is_wellformed_tenure_start_block`/`is_wellformed_tenure_extend_block`) are independent of the version byte and can be satisfied simultaneously.

### Recommendation
In `accept_block`, do not `panic!` on `Err` from `validate_shadow_nakamoto_block_burnchain`; instead propagate/return the error as an `InvalidStacksBlock`/rejection so the block is simply refused and the peer optionally penalized. Additionally, consider rejecting any network-relayed block with the shadow version bit set at the earliest ingestion point (before it reaches `accept_block`), since shadow blocks are never meant to travel over the wire.

### Proof of Concept
Rust unit test in `stackslib::chainstate::nakamoto`:
1. Build a normal, wellformed `NakamotoBlock` (tenure-start or tenure-extend) via existing test helpers (e.g. as used in `stackslib/src/chainstate/nakamoto/tests/node.rs`), signed correctly, with valid `parent_block_id`, `consensus_hash`, etc., but a `expected_burn_opt`/burn-linkage that does not correspond to a stored shadow entry.
2. Set `block.header.version |= 0x80` to make `is_shadow_block()` return true, without calling `add_shadow_block`/`process_shadow_block`.
3. Call `NakamotoChainState::accept_block(...)` directly (bypassing p2p transport) with this block.
4. Current (buggy) behavior: the call panics with `"Unacceptable shadow Nakamoto block"` because `validate_shadow_nakamoto_block_burnchain` returns `Err(InvalidStacksBlock("Shadow block must already be stored"))` and the caller unwraps via `panic!`.
5. Expected/fixed behavior: `accept_block` should return `Err(ChainstateError::InvalidStacksBlock(..))` instead of panicking; assert `accept_block(..).is_err()` and that the process does not abort.

impl NakamotoStagingBlocksTx<'_> {
    /// Add a shadow block.
    /// Fails if there are any non-shadow blocks present in the tenure.
    pub fn add_shadow_block(&self, shadow_block: &NakamotoBlock) -> Result<(), ChainstateError> {
        if !shadow_block.is_shadow_block() {
            return Err(ChainstateError::InvalidStacksBlock(
                "Not a shadow block".into(),
            ));
        }
        let block_id = shadow_block.block_id();

        // is this block stored already?
        let qry = "SELECT 1 FROM nakamoto_staging_blocks WHERE index_block_hash = ?1";
        let args = params![block_id];
        let present: Option<i64> = query_row(self, qry, args)?;
        if present.is_some() {
            return Ok(());
        }

        // this tenure must be empty, or it must be a shadow tenure
        let qry = "SELECT 1 FROM nakamoto_staging_blocks WHERE consensus_hash = ?1";
        let args = rusqlite::params![&shadow_block.header.consensus_hash];
        let present: Option<u32> = query_row(self, qry, args)?;
        if present.is_some()
            && !self
                .conn()
                .is_shadow_tenure(&shadow_block.header.consensus_hash)?
        {
            return Err(ChainstateError::InvalidStacksBlock(
                "Shadow block cannot be inserted into non-empty non-shadow tenure".into(),
            ));
        }

        // there must not be a block at this height in this tenure
        let qry = "SELECT 1 FROM nakamoto_staging_blocks WHERE consensus_hash = ?1 AND height = ?2";
        let args = rusqlite::params![
            &shadow_block.header.consensus_hash,
            u64_to_sql(shadow_block.header.chain_length)?
        ];
        let present: Option<u32> = query_row(self, qry, args)?;
        if present.is_some() {
            return Err(ChainstateError::InvalidStacksBlock(format!(
                "Conflicting block at height {} in tenure {}",
                shadow_block.header.chain_length, &shadow_block.header.consensus_hash
            )));
        }

        // the shadow block is crafted post-hoc, so we know the consensus hash exists.
        // thus, it's always burn-attachable
        let burn_attachable = true;

        // shadow blocks cannot be replaced
        let signing_weight = u32::MAX;

        self.store_block_if_better(
            shadow_block,
            burn_attachable,
            signing_weight,
            NakamotoBlockObtainMethod::Shadow,
        )?;
        Ok(())
    }
