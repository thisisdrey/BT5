The go-ethereum codebase correctly implements ECDSA malleability protection where it matters for consensus:

- `crypto.ValidateSignatureValues` explicitly rejects `s` values above `secp256k1halfN` when `homestead` is `true`, per the documented EIP-2 rule [1](#0-0) .
- Transaction signatures (`core/types/transaction_signing.go`) and EIP-7702 `SetCodeAuthorization.Authority()` both call `ValidateSignatureValues(..., true)`, i.e. with the homestead malleability check enabled [2](#0-1) .
- The `ECRECOVER` precompile intentionally calls `crypto.ValidateSignatureValues(v, r, s, false)` (homestead=false), but this is spec-correct: the Yellow Paper / EIP-2 restriction on `s` only applies to transaction signatures, not to the `ECRECOVER` precompile, which is documented in the code comment "tighter sig s values input homestead only apply to tx sigs" [3](#0-2) .
- `crypto.VerifySignature` (used for non-consensus verification, e.g. p2p/BLS-adjacent paths) also explicitly rejects malleable signatures via `s.IsOverHalfOrder()` [4](#0-3) .

None of these paths break a consensus equality: the `ECRECOVER` precompile's acceptance of full-range `s` is the specified mainnet behavior (it always was, and is tested against known vectors), not a deviation introduced by an outdated/malleable ECDSA library as in the OpenZeppelin advisory. The reported OpenZeppelin issue concerns Solidity contract-level `ECDSA.recover` with single-byte signature format ambiguity, which has no counterpart divergence in go-ethereum's core/consensus code.

```go
// ValidateSignatureValues verifies whether the signature values are valid with
// the given chain rules. The v value is assumed to be either 0 or 1.
func ValidateSignatureValues(v byte, r, s *big.Int, homestead bool) bool {
	if r.Cmp(common.Big1) < 0 || s.Cmp(common.Big1) < 0 {
		return false
	}
	// reject upper range of s values (ECDSA malleability)
	// see discussion in secp256k1/libsecp256k1/include/secp256k1.h
	if homestead && s.Cmp(secp256k1halfN) > 0 {
		return false
	}
	// Frontier: allow s to be in full N range
	return r.Cmp(secp256k1N) < 0 && s.Cmp(secp256k1N) < 0 && (v == 0 || v == 1)
}
```
