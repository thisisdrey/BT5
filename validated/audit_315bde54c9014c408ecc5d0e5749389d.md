### Title
Unbounded Delegation Index Scan Enables Query-Based DoS on Full Node - (File: chainbase/src/main/java/org/tron/core/store/DelegatedResourceAccountIndexStore.java)

### Summary
Any account can grow the on-chain `DelegatedResourceAccountIndexStore` entry for its address without bound by issuing many cheap `DelegateResourceContract` transactions to distinct receiver addresses. The public, unauthenticated `GetDelegatedResourceAccountIndex`/`GetDelegatedResourceAccountIndexV2` HTTP/gRPC endpoints then perform an unbounded prefix scan and in-memory sort over that attacker-controlled data set on every call, mirroring the "unbounded loop in a callable path" bug class described in the Forta `redeem()` report.

### Finding Description
`DelegateResourceActuator.validate()` only enforces a minimum delegate amount of 1 TRX and available frozen balance; it places no limit on how many distinct receiver addresses one account can delegate to, nor how large `DelegatedResourceAccountIndexStore` may grow for a single address: [1](#0-0) 

Each successful delegation permanently registers the pair via `delegate()`/`delegateV2()`: [2](#0-1) 

When the index is later queried (for the "to"/"from" list of an address), `getWithPrefix()` performs an unbounded `prefixQuery` DB scan, materializes every matching row into a `List`, and sorts the entire list by timestamp on every single call — with no pagination, cap, or size limit: [3](#0-2) 

This method is reachable directly from unauthenticated, anonymous API clients through both the HTTP and gRPC query surfaces: [4](#0-3) [5](#0-4) [6](#0-5) 

Since an attacker can build up a large number of distinct simultaneous delegations from one owner address for the cost of locking modest amounts of TRX (each delegate call only requires `>= 1 TRX` and remains under the attacker's control, later reclaimable via `UnDelegateResourceContract`), the size of the list scanned/sorted by `getWithPrefix()` is effectively attacker-controlled and unbounded, unlike the bounded, validated vote lists used elsewhere in the codebase (e.g. `MAX_VOTE_NUMBER` enforced in `VoteWitnessActuator.validate()` at [7](#0-6) ).

### Impact Explanation
Repeated queries against an address with a large, attacker-inflated delegation index cause the full node's HTTP/gRPC handler thread to perform unbounded DB scanning and O(n log n) in-memory sorting synchronously per request. Because the endpoint is public and unauthenticated and can be invoked repeatedly and concurrently, this can be used to degrade or exhaust CPU/memory resources of full nodes serving these APIs, denying legitimate API service to other users — directly matching the accepted impact category of "an API the node can no longer serve."

### Likelihood Explanation
The attack requires only signing many `DelegateResourceContract` transactions from a single controlled account to many distinct (self-generated) receiver addresses, each satisfying the trivial `delegateBalance >= 1 TRX` check; the locked TRX is not spent and can be reused/reclaimed later. No special privilege, witness/committee role, or protocol bug beyond the missing bound is needed, making this practically reachable by any ordinary funded account.

### Recommendation
Cap the number of distinct delegation relationships (`toAccounts`/`fromAccounts`) an address may accumulate in `DelegatedResourceAccountIndexStore`, or paginate/limit `getWithPrefix()`'s scan and avoid full in-memory sort on unbounded result sets. Alternatively, enforce a maximum index size in `DelegateResourceActuator.validate()`/`DelegateResourceProcessor.validate()`, analogous to `MAX_VOTE_NUMBER` used for votes.

### Proof of Concept
1. Fund one account with enough TRX to freeze and generate `N` (e.g. 50,000) unique receiver addresses.
2. For each receiver, freeze the minimum required balance and submit a `DelegateResourceContract` transaction delegating `1 TRX` (`lock=false`) to that receiver, without undelegating — this appends an entry into the owner's `toAccounts` list and each receiver's `fromAccounts` list via `DelegatedResourceAccountIndexStore.delegateV2()`.
3. Call `GET /wallet/getdelegatedresourceaccountindexv2` (or the gRPC `GetDelegatedResourceAccountIndexV2`) with the owner's address repeatedly and concurrently.
4. Observe that each call triggers an unbounded `prefixQuery` scan and sort over the tens of thousands of entries in `DelegatedResourceAccountIndexStore.getWithPrefix()`, consuming disproportionate CPU/memory on the serving full node relative to the trivial cost of building the state.

  public DelegatedResourceAccountIndexCapsule getV2Index(byte[] address) {
    return getWithPrefix(V2_FROM_PREFIX, V2_TO_PREFIX, address);

  private DelegatedResourceAccountIndexCapsule getWithPrefix(byte[] fromPrefix, byte[] toPrefix, byte[] address) {
    DelegatedResourceAccountIndexCapsule tmpIndexCapsule =
        new DelegatedResourceAccountIndexCapsule(ByteString.copyFrom(address));

    byte[] key = Bytes.concat(fromPrefix, address);
    List<DelegatedResourceAccountIndexCapsule> tmpToList =
        new ArrayList<>(this.prefixQuery(key).values());
    tmpToList.sort(Comparator.comparing(DelegatedResourceAccountIndexCapsule::getTimestamp));
    List<ByteString> list = tmpToList.stream()
        .map(DelegatedResourceAccountIndexCapsule::getAccount).collect(Collectors.toList());
    tmpIndexCapsule.setAllToAccounts(list);

    key = Bytes.concat(toPrefix, address);
    List<DelegatedResourceAccountIndexCapsule> tmpFromList =
        new ArrayList<>(this.prefixQuery(key).values());
    tmpFromList.sort(Comparator.comparing(DelegatedResourceAccountIndexCapsule::getTimestamp));
    list = tmpFromList.stream().map(DelegatedResourceAccountIndexCapsule::getAccount).collect(
        Collectors.toList());
    tmpIndexCapsule.setAllFromAccounts(list);
    return tmpIndexCapsule;
  }

  public DelegatedResourceAccountIndex getDelegatedResourceAccountIndex(ByteString address) {
    if (address == null || address.size() != DecodeUtil.ADDRESS_SIZE / 2) {
      return DelegatedResourceAccountIndex.getDefaultInstance();
    }
    DelegatedResourceAccountIndexCapsule accountIndexCapsule =
        chainBaseManager.getDelegatedResourceAccountIndexStore().getIndex(address.toByteArray());
    if (accountIndexCapsule != null) {
      return accountIndexCapsule.getInstance();
    } else {
      return DelegatedResourceAccountIndex.getDefaultInstance();
    }
  }
