### Title
Malformed `_toAddress` in `ProxyOFT.sendFrom` permanently bricks the inbound LayerZero channel until governor intervention - (File: contracts/dependencies/@layerzerolabs/solidity-examples/contracts-upgradeable/token/oft/composable/ComposableOFTCoreUpgradeable.sol)

### Summary
`ProxyOFT` inherits the raw LayerZero `sendFrom(address,uint16,bytes,uint,...)` entry point, which forwards an attacker-controlled `bytes _toAddress` of arbitrary length into the cross-chain payload. On the destination chain, `_sendAck` calls `toAddressBytes.toAddress(0)`, which reverts when `_toAddress.length < 20`. The failed message is stored on the LayerZero endpoint and, because inbound nonces are delivered in order, blocks every subsequent message from that source chain/remote pair. `retryMessage` re-executes the same malformed payload and reverts forever, so the channel can only be recovered via the owner-only `forceResumeReceive`. An attacker can permanently (until privileged recovery) freeze bridging for all users on a route at the cost of a dust amount of their own synthetic tokens — a direct analog of CVE-2018-14851's "crafted input → out-of-bounds read → application crash / DoS" bug class.

### Finding Description
- Source side: `OFTCoreUpgradeable.sendFrom` calls `_send(_from, _dstChainId, _toAddress, ...)` with no validation that `_toAddress.length == 20`; the payload is `abi.encode(PT_SEND, _toAddress, amount)`. [1](#0-0) 
- `ProxyOFT._debitFrom` only checks sender, bridging-active flag, and supported chain — it burns the attacker's tokens and ignores `toAddress_` entirely. [2](#0-1) 
- `ProxyOFT`'s user-friendly `sendFrom(from,dst,to,amount)` packs a 20-byte address, but the raw `bytes` overload inherited from `IOFTCoreUpgradeable` remains public and unrestricted. [3](#0-2) 
- Destination side: `_sendAck` decodes the payload and executes `toAddressBytes.toAddress(0)`, which enforces `_bytes.length >= _start + 20` in `BytesLib` and reverts on a short `toAddress` (the "out-of-bounds read" analog). `_creditTo` is never reached, so no mint occurs. [4](#0-3) 
- The revert propagates out of `nonblockingLzReceive`, the endpoint stores the payload as failed, and ordered delivery blocks all later nonces on that `(srcChainId, srcAddress)` channel. `retryMessage` requires the identical payload hash and re-executes the same reverting decode — it can never clear. [5](#0-4) 
- The only recovery is `LzApp.forceResumeReceive`/`retryPayload`, gated by `onlyOwner`, and `ProxyOFT.owner()` resolves to the pool-registry governor — i.e., a privileged action an unprivileged attacker can force. [6](#0-5) 

### Impact Explanation
Permanent (until governor intervention) freezing of a bridge route: all subsequent `PT_SEND` messages from the affected source chain through that trusted remote are blocked, so every user's bridged synthetic tokens in transit behind the poisoned nonce are frozen. The attacker's cost is a dust amount of the synthetic token plus LZ fee. This matches the accepted "temporary/permanent freezing of funds / liveness break" impact class.

### Likelihood Explanation
Fully unprivileged: any EOA calls `sendFrom(from, dstChainId, malformedToAddress, dustAmount, ...)` on a deployed `ProxyOFT` where `isBridgingActive()` and `isDestinationChainSupported()` hold. No oracle manipulation, privileged role, or malicious endpoint required — the crafted payload is produced by the protocol's own `abi.encode` from attacker-supplied bytes.

### Recommendation
Validate `_toAddress.length == 20` (EVM destination) on the source chain before building the payload — override `sendFrom`/`_send` in `ProxyOFT` to enforce it — and/or bounds-check `toAddress` in `_sendAck` so a malformed message reverts before the debit/ordering path is poisoned, or route decoding errors to a non-blocking handler.

```text
    function retryMessage(uint16 _srcChainId, bytes calldata _srcAddress, uint64 _nonce, bytes calldata _payload) public payable virtual {
        // assert there is message to retry
        bytes32 payloadHash = failedMessages[_srcChainId][_srcAddress][_nonce];
        require(payloadHash != bytes32(0), "NonblockingLzApp: no stored message");
        require(keccak256(_payload) == payloadHash, "NonblockingLzApp: invalid payload");
        // clear the stored message
        failedMessages[_srcChainId][_srcAddress][_nonce] = bytes32(0);
        // execute the message. revert if it fails again
        _nonblockingLzReceive(_srcChainId, _srcAddress, _nonce, _payload);
        emit RetryMessageSuccess(_srcChainId, _srcAddress, _nonce, payloadHash);
```
