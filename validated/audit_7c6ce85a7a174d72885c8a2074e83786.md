### Title
Shared global `overall_connection_rate_limiter` in `setup_connection`/`run_server` allows IP-diversity Sybil exhaustion to deny all TPU connection admission - (File: streamer/src/nonblocking/quic.rs)

### Summary
The QUIC ingress path in `run_server` and `setup_connection` enforces connection admission through two independent gates: a per-IP `ConnectionRateLimiter` and a single shared `overall_connection_rate_limiter` (a `TokenBucket` sized `MAX_CONNECTION_BURST`/`TOTAL_CONNECTIONS_PER_SECOND`). Because the shared bucket has no per-source reservation or fairness accounting, an attacker who can present many distinct source IPs (e.g. via IPv6 rotation) can keep each IP under its individual limit while collectively draining the shared bucket, causing every other client — staked or unstaked — to be denied admission.

### Finding Description
In `run_server`, each new `incoming` connection is checked first against the shared bucket (`overall_connection_rate_limiter.current_tokens() == 0`) and then against `rate_limiter.is_allowed(&ip)` (per-IP) before the QUIC handshake is accepted [1](#0-0) . After the handshake completes, `setup_connection` performs the authoritative consumption: `rate_limiter.register_connection(&from.ip())` (per-IP) followed unconditionally by `overall_connection_rate_limiter.consume_tokens(1)` [2](#0-1) . The bucket is created once per server with `MAX_CONNECTION_BURST = 1000` and `TOTAL_CONNECTIONS_PER_SECOND = 2500.0` [3](#0-2)  and shared via `Arc` across all connections regardless of source IP or stake [4](#0-3) , [5](#0-4) .

Per-IP limiting is implemented via `ConnectionRateLimiter::is_allowed`/`register_connection`, which only track state once an IP has actually completed a connection ("we should only modify server state once source IP is verified") [6](#0-5) . Each never-before-seen IP is treated as fully allowed (`None => true`), so an attacker rotating through distinct IPs never trips the per-IP gate, yet every successful handshake still consumes one token from the single shared bucket. Because `TokenBucket::consume_tokens` is a plain atomic decrement with no per-key/per-subnet fairness (see `net-utils/src/token_bucket.rs`), there is no mechanism preventing one set of source addresses from starving the bucket that gates admission for all other addresses, including staked/legitimate unstaked peers.

The code comment in `run_server` explicitly documents the layered strategy — "protect against connection attempt bursts with a global rate-limiter" and "rate-limit abusive peers by (control-asserted) ip" — but confirms no reservation exists to guarantee admission bandwidth to previously-unseen legitimate sources [7](#0-6) . No QUIC Retry/address-validation challenge is used to make IP diversity costly before the shared token is consumed.

### Impact Explanation
An attacker with access to many distinct source addresses (trivial via an IPv6 /64 or larger delegation) can continuously issue new-IP connection attempts at a rate exceeding `TOTAL_CONNECTIONS_PER_SECOND` (2500/s, burst 1000), each individually compliant with the per-IP quota (`DEFAULT_MAX_CONNECTIONS_PER_IPADDR_PER_MINUTE = 8` per IP [8](#0-7) ), and thereby keep `overall_connection_rate_limiter` at zero tokens indefinitely. Once exhausted, `run_server` calls `incoming.ignore()` for every subsequent connection attempt from any source, including legitimate staked validators and RPC/wallet clients [9](#0-8) . This is a total TPU connection-admission denial-of-service, matching the "grossly underpriced pre-fee work" / availability DoS bounty category since the attacker spends only cheap IP rotation and packet volume to deny all clients access to the leader's TPU port.

### Likelihood Explanation
Preconditions are minimal: no stake, no gossip participation, and only the ability to open UDP/QUIC connections from many distinct source IPs to a public TPU port — squarely within the unprivileged remote attacker model. IPv6 address rotation within a single owned prefix makes generating thousands of distinct source addresses essentially free and requires no coordination with other clients. The sustained rate needed (~2500 handshakes/sec) is achievable by a single moderately-resourced attacker, making this readily repeatable for the duration of the attack.

### Recommendation
Do not gate all admission behind a single undifferentiated shared bucket. Options: (1) reserve a guaranteed minimum admission quota/lane for previously-unseen or low-frequency source IPs (e.g. split the overall budget between a "burst" pool and a "guaranteed new-IP" pool); (2) weight or prioritize staked-identity handshakes ahead of the shared bucket check so stake-weighted traffic is not starved by unstaked Sybil IPs; (3) require QUIC Retry (address-validation token) before consuming a global admission token, raising the cost of IP rotation; (4) key part of the global rate limit by subnet (e.g. /48 or /56) rather than a single process-wide bucket, so IP rotation within a small number of prefixes cannot exhaust admission for the rest of the internet.

### Proof of Concept
Integration/fuzz test plan (extending `streamer/src/nonblocking/quic.rs` test module and `net-utils/src/token_bucket.rs` test patterns):
```rust
#[tokio::test]
async fn test_ip_diversity_exhausts_overall_rate_limiter() {
    // Use TokenBucket::new(MAX_CONNECTION_BURST, MAX_CONNECTION_BURST, TOTAL_CONNECTIONS_PER_SECOND)
    let overall = Arc::new(TokenBucket::new(1000, 1000, 2500.0));
    let per_ip = Arc::new(ConnectionRateLimiter::new(8, 80, 4));

    // Simulate N distinct attacker IPs, each issuing exactly 1 connection
    // (well under its own per-IP quota of 8/min).
    let n_attacker_ips = 1500; // > MAX_CONNECTION_BURST
    for i in 0..n_attacker_ips {
        let ip = IpAddr::V4(Ipv4Addr::new(10, (i >> 16) as u8, (i >> 8) as u8, i as u8));
        assert!(per_ip.is_allowed(&ip), "attacker IP {i} should pass per-IP check");
        assert!(per_ip.register_connection(&ip), "attacker IP {i} should register fine");
        let _ = overall.consume_tokens(1); // mirrors setup_connection
    }

    // A legitimate, previously-unseen IP now attempts to connect.
    let legit_ip = IpAddr::V4(Ipv4Addr::new(192, 168, 1, 1));
    assert!(per_ip.is_allowed(&legit_ip), "legit IP passes its own per-IP gate");
    // But the shared bucket is drained, so admission is denied regardless of stake/legitimacy:
    assert_eq!(overall.current_tokens(), 0);
    assert!(overall.consume_tokens(1).is_err(),
        "legitimate client denied admission solely due to shared-bucket exhaustion by IP-diverse attacker");
}
```
Expected result: the assertion demonstrates that despite every attacker IP individually complying with `ConnectionRateLimiter`, the shared `overall_connection_rate_limiter` reaches zero tokens and denies the legitimate, previously-unseen IP — reproducing the `run_server`/`setup_connection` code path (`current_tokens() == 0` → `incoming.ignore()`, or `consume_tokens(1).is_err()` → connection closed with `CONNECTION_CLOSE_CODE_DISALLOWED`).

    /// Check if the connection from the said `ip` is allowed.
    /// Here we assume that only IPs with actual confirmed connections are stored in it,
    /// since we should only modify server state once source IP is verified
    pub fn is_allowed(&self, ip: &IpAddr) -> bool {
        // Check if we have records in the rate limiter for the given IP address
        match self.limiter.current_tokens(ip) {
            Some(r) => r > 0, // we have a record, and rate is not exceeded
            None => true,     // if we have not seen IP, allow connection request
        }
    }

    pub fn register_connection(&self, ip: &IpAddr) -> bool {
        if self.limiter.consume_tokens(*ip, 1).is_ok() {
            debug!("Request from IP {ip:?} allowed");
            true // Request allowed
        } else {
            debug!("Request from IP {ip:?} blocked");
            false // Request blocked
        }
    }
