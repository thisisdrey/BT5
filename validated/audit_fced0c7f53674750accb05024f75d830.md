### Title
WFP UDP-port PERMIT filter bypasses Windows Defender Firewall on *all* interfaces, not just the intended listener interface - ([File: wfp/wfp_windows.go])

### Summary
`addUDPPortFilter` (used by `PermitUDPPort`) builds a WFP filter that only matches `fwpmConditionIPProtocol` and `fwpmConditionIPLocalPort`, with no `fwpmConditionIPLocalInterface` condition, even though the code already defines and uses `fwpmConditionIPLocalInterface` in the sibling `addInterfaceFilter`/`PermitInterface` path. Because the filter carries `fwpmFilterFlagClearActionRight` and is installed in a sublayer weighted `0xFFFF` above WDF's sublayer, it unconditionally overrides any WDF block rule for that UDP port on every network interface on the host, not just the interface nebula is meant to listen on.

### Finding Description
When `listen.windows_bypass_wdf` is true, `bypassConn.ReloadConfig` calls `wfp.PermitUDPPort(addr.Port())` [1](#0-0) , which calls `addUDPPortFilter` for both the V4 and V6 `FWPM_LAYER_ALE_AUTH_RECV_ACCEPT` layers [2](#0-1) .

`addUDPPortFilter` constructs exactly two conditions - IP protocol == UDP and IP local port == the listener port - and no interface condition at all [3](#0-2) . The resulting `fwpmFilter0` sets `flags: fwpmFilterFlagClearActionRight` and `weight: 15` inside a sublayer registered with `weight: 0xFFFF`, which is explicitly documented to arbitrate above WDF's default sublayer and to prevent lower-priority WDF filters from overriding the permit [4](#0-3) . The package doc comment for `PermitUDPPort` itself states the consequence: "Inbound UDP to that port on any interface bypasses Windows Defender Firewall" [5](#0-4) .

The codebase already contains an interface-scoped alternative, `PermitInterface`/`addInterfaceFilter`, which adds a `fwpmConditionIPLocalInterface` condition keyed to a specific adapter LUID [6](#0-5) , proving that interface-scoping is a solved and available mechanism in this file - but the actual Windows WDF-bypass wiring in `udp_bypass_windows.go` only ever calls the interface-agnostic `PermitUDPPort` [7](#0-6) .

Consequently, an unprivileged attacker present on any other NIC of the multi-homed host (e.g. a public Wi-Fi adapter, a guest LAN, a directly attached untrusted segment) that the administrator intended to keep isolated from the nebula listener via a WDF block rule can simply send UDP datagrams to the nebula listen port; the WFP PERMIT filter installed by `PermitUDPPort` has no interface predicate, so it matches and overrides the WDF block on every interface, letting the packets reach the nebula UDP socket and enter handshake processing.

### Impact Explanation
This defeats the administrator's WDF-based interface isolation for the nebula UDP port network-wide on the host: any interface, including ones explicitly firewalled off by the admin, becomes reachable to the nebula listener once `windows.bypass_wdf` is enabled. This matches a firewall-bypass class impact - unintended network exposure of the VPN listener socket to traffic sources the operator believed were blocked.

### Likelihood Explanation
This triggers deterministically and automatically whenever `listen.windows_bypass_wdf` is true (which is the default, `true`, per `c.GetBool("listen.windows_bypass_wdf", true)` [8](#0-7) ) on any amd64/arm64 Windows build. No attacker interaction is required to enable the exposure; any host with multiple NICs where one is intended to be isolated by WDF is affected as soon as the config reloads.

### Recommendation
Scope the UDP-port permit filter to the specific interface(s) nebula is actually bound to (analogous to `addInterfaceFilter`) by adding a `fwpmConditionIPLocalInterface` condition alongside the protocol/port conditions in `addUDPPortFilter`, or by combining `PermitInterface` and `PermitUDPPort` semantics (protocol AND port AND local interface LUID) so the PERMIT only applies to the intended listening interface(s) rather than every NIC on the host.

### Proof of Concept
Integration test plan:
1. On a Windows test VM, create two virtual adapters: `Adapter-A` (intended nebula listen interface) and `Adapter-B` (to be isolated via a WDF outbound/inbound block rule for the nebula UDP port).
2. Configure a WDF rule blocking inbound UDP to the nebula port specifically scoped to `Adapter-B`.
3. Start nebula with `listen.windows_bypass_wdf: true`, bound so its socket answers on `0.0.0.0:<port>`.
4. From a host attached to `Adapter-B` only (simulating the unprivileged attacker on the untrusted NIC), send a UDP datagram to `<hostIP-on-Adapter-B>:<port>`.
5. Assert: without the fix, the packet reaches the nebula listener (observable via nebula's handshake/packet-received logging or a raw socket capture on the loopback path) despite the WDF block rule on `Adapter-B`.
6. After applying the fix (adding `fwpmConditionIPLocalInterface` scoped to `Adapter-A`'s LUID in `addUDPPortFilter`), repeat step 4 and assert the packet is dropped by WDF and never reaches the nebula listener.

func PermitUDPPort(port uint16) (*Session, error) {
	s, sublayerKey, err := newSession()
	if err != nil {
		return nil, err
	}

	if err := addUDPPortFilter(s.engine, sublayerKey, fwpmLayerAleAuthRecvAcceptV4, port); err != nil {
		s.Close()
		return nil, fmt.Errorf("add v4 filter: %w", err)
	}
	if err := addUDPPortFilter(s.engine, sublayerKey, fwpmLayerAleAuthRecvAcceptV6, port); err != nil {
		s.Close()
		return nil, fmt.Errorf("add v6 filter: %w", err)
	}
	return s, nil
}

// FWP_UINT8 and FWP_UINT16 are <= 32 bits so they live inline in the FWP_VALUE0 union.
func addUDPPortFilter(engine uintptr, sublayerKey, layer windows.GUID, port uint16) error {
	name, _ := windows.UTF16PtrFromString("Nebula allow UDP port inbound")
	desc, _ := windows.UTF16PtrFromString("Permits inbound UDP to a nebula listener port")

	conds := [2]fwpmFilterCondition0{
		{
			fieldKey:  fwpmConditionIPProtocol,
			matchType: fwpMatchEqual,
			conditionValue: fwpValue0{
				type_: fwpUint8,
				value: uintptr(ipprotoUDP),
			},
		},
		{
			fieldKey:  fwpmConditionIPLocalPort,
			matchType: fwpMatchEqual,
			conditionValue: fwpValue0{
				type_: fwpUint16,
				value: uintptr(port),
			},
		},
	}

	filter := fwpmFilter0{
		displayData:         fwpmDisplayData0{name: name, description: desc},
		flags:               fwpmFilterFlagClearActionRight,
		layerKey:            layer,
		subLayerKey:         sublayerKey,
		weight:              fwpValue0{type_: fwpUint8, value: uintptr(15)},
