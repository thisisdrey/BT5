### Title
Front-running micro-`repay` permanently invalidates pending full-size `liquidate` calls via assertion revert — (File: contracts/Pool.sol)

### Summary
CVE-2019-6471 is a race condition in which discarding a packet that became malformed mid-processing hits a `REQUIRE` assertion and kills the process (availability loss). The Metronome analog is a race between `DebtToken.repay` and `Pool.liquidate`: `repay(onBehalfOf_, amount_)` is permissionless and lets any third party reduce a victim's debt balance [1](#0-0) . A liquidation transaction constructed against the pre-race debt then hits a hard revert inside `liquidate`, so it is always discarded when mined after the repay.

### Finding Description
`Pool.liquidate` snapshots the debt balance after `accrueInterest()` and enforces `amountToRepay_.wadDiv(_debtTokenBalance) <= maxLiquidable` [2](#0-1) . `DebtToken.repay` burns the caller's synth and calls `_burn(onBehalfOf_, _repaid)`, lowering `principalOf[onBehalfOf_]` for an arbitrary account [3](#0-2) [4](#0-3) . An attacker who observes a `liquidate` tx that repays 100% (or any fraction `> maxLiquidable` of the post-repay balance) of a victim's debt can front-run with `repay(victim, 1 wei of synth)`. When the liquidator's tx executes, `amountToRepay_ > _debtTokenBalance` makes `wadDiv > 1e18 >= maxLiquidable`, so it reverts with `AmountGreaterThanMaxLiquidable`; alternatively, if `debtFloorInUsd > 0`, the subtraction/remaining-debt check at [5](#0-4)  reverts. Neither `whenNotShutdown`, `nonReentrant`, the SynthContext sender checks, nor pause flags prevent this — `repay` is a public entry point callable by any EOA (also via `Operator.execute`) and `liquidate` even works while paused [6](#0-5) . The attack is repeatable every block: each resubmission can be invalidated by another dust repay (or by the interest accrual itself, which grows `balanceOf` between quote and execution — the same race exists without any attacker when using a stale `quoteLiquidateMax` amount).

### Impact Explanation
Liquidation liveness (the "process stays up" analog of the CVE) is broken: a targeted unhealthy position can indefinitely evade liquidation for the cost of a few wei of synthetic token plus gas per block, letting bad debt accrue interest and pushing the pool toward insolvency. Even without an attacker, full-repay liquidations built from `quoteLiquidateMax`/`balanceOf` quotes race with `accrueInterest()` state changes and are discarded on assertion, forcing liquidators to leave buffer or retry repeatedly. Impact class: temporary freezing of the liquidation function for the targeted account / liveness.

### Likelihood Explanation
Requires only an unprivileged account holding (or flash-borrowing via `flashIssue`) a dust amount of the synthetic token, plus mempool visibility to front-run. Cost per griefed block is ~1 wei of debt repayment (which even benefits the victim marginally) plus gas. The preconditions (`maxLiquidable < 100%` or `debtFloorInUsd > 0`) are normal deployed configurations.

### Recommendation
In `Pool.liquidate`, cap `amountToRepay_` to `_debtTokenBalance` (and to the `maxLiquidable` fraction) instead of reverting, or accept a `minAmountToRepay_`/`slippage` parameter so a slightly smaller repayment still succeeds. Alternatively, restrict `DebtToken.repay`'s `onBehalfOf_` to `msg.sender` or add a minimum repay amount to make dust griefing uneconomical.

### Proof of Concept
Hardhat/fork sketch (mirroring `test/Pool.test.ts` liquidation setup [7](#0-6) ):

```ts
// alice has unhealthy position: deposited msdMET, minted 1 msETH, MET price dropped
const debtBefore = await msEthDebtToken.balanceOf(alice.address) // full debt

// attacker holds a few wei of msETH (or obtains via flashIssue)
// front-run: pay down 1 wei of alice's debt
await msEthDebtToken.connect(attacker).repay(alice.address, 1)

// liquidator's pending tx: repay the previously-quoted full debt
await expect(
  pool.connect(liquidator).liquidate(msEth.address, alice.address, debtBefore, msdMET.address)
).revertedWithCustomError(pool, 'AmountGreaterThanMaxLiquidable')
// or Panic(0x11) / RemainingDebtIsLowerThanTheFloor depending on config
```

Variant without attacker: call `quoteLiquidateMax`, advance one block so `accrueInterest` grows the balance, then `liquidate` with the quoted amount reverts — showing the race between quote-time state and execution-time assertion is inherent.
