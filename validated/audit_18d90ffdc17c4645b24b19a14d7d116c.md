### Title
Unauthenticated Signer event-receiver HTTP endpoint accepts forged StackerDB/proposal/burn-block events - (File: libsigner/src/events.rs)

### Summary
`SignerEventReceiver::next_event` (`libsigner/src/events.rs`) is the HTTP server that the `stacks-signer` binds to receive event-observer callbacks (`/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block`) from its local node. Unlike the node's `/v3/block_proposal` RPC endpoint, which requires an `authorization` header matching a shared `auth_token`/`auth_password` [1](#0-0) , the signer's event receiver performs **no authentication check whatsoever** on incoming POSTs before deserializing and acting on them [2](#0-1) . The sender side (`stacks-node`'s event dispatcher) also never attaches an auth header to these callbacks [3](#0-2) . This is the same class of bug as the reported "ProfitNotifier doesn't validate new numerators" issue: a value/input (here, "is this event authentic/from my own node") that is validated in one code path (the block-proposal RPC endpoint) is missing validation in a structurally similar path (the signer's event-observer intake), fails open, and the omission is not obvious from a local read of the affected function.

### Finding Description
The intended dataflow is: `stacks-node` internally validates a `StackerDBChunkData` (signature, slot ownership, version) via `PeerNetwork::validate_received_chunk`/`StackerDBTx::try_replace_chunk` [4](#0-3) [5](#0-4) , and only *then* fires an HTTP callback to the configured `events_observer` endpoint carrying a `StackerDBChunksEvent`. The signer trusts that anything arriving on this endpoint has already gone through that node-side gate.

However, `SignerEventReceiver::next_event` accepts any HTTP POST to `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, or `/new_block` and deserializes the body directly into the corresponding event type with no origin check, no shared secret, and no signature over the transport itself [2](#0-1) . Sample configuration for this endpoint documents binding it on `0.0.0.0` [6](#0-5) , and the docs explicitly warn that exposing this endpoint to non-local/external hosts is a security risk without additional controls [7](#0-6) , confirming the endpoint is not assumed to be unreachable by design.

Once a forged `StackerDBChunksEvent` is accepted, `TryFrom<StackerDBChunksEvent> for SignerEvent<T>` only checks that the chunk's signature is *recoverable* to *some* public key (`chunk.recover_pk()`), and that the payload's type-prefix byte matches the expected "lane" for the target boot contract — it never checks that the recovered key belongs to the actual registered signer for that StackerDB slot [8](#0-7) . That slot-owner check only happens inside the node's own StackerDB write path (`validate_received_chunk`, `try_replace_chunk`) [9](#0-8) [10](#0-9) , which the forged HTTP callback completely bypasses. This is exactly the "authenticated vs. stored" equality break called out in the rules: signer messages that reach `SignerEvent::SignerMessages` are supposed to be equal to messages that passed StackerDB slot-signer verification, but a forged event never went through that gate.

### Impact Explanation
An attacker who can reach the signer's event-observer HTTP listener (any deployment following the documented sample config that binds non-locally, or any attacker positioned to reach the loopback-bound port, e.g. via SSRF from another local service) can POST a self-signed, arbitrary `StackerDBChunksEvent`/`BlockValidateResponse`/`BurnBlockEvent`/`StacksBlockEvent` body. This is accepted as if it came from the trusted local node and is forwarded into the signer's runloop as legitimate `SignerEvent::SignerMessages`/`MinerMessages`, i.e., an unauthenticated write into the signer's decision-making input stream — matching the Critical bucket "unauthenticated/unauthorized write to state" and "network-wide propagation of forged data" (a compromised or exposed signer polluting the signer set's view with forged messages).

### Likelihood Explanation
Likelihood is High for any deployment that follows the shipped sample configuration, since `sample/conf/mainnet-signer.toml` binds the observer endpoint on `0.0.0.0` and the only mitigation mentioned in code is an operator warning printed at signer startup [7](#0-6)  rather than an enforced control. No cryptographic material, node secret, or privileged role is required to exploit — it's a plain HTTP POST to a documented endpoint/path set.

### Recommendation
**Short term:** Add authentication to `SignerEventReceiver::next_event` (e.g., require and verify a shared-secret header analogous to the node's `authorization` check used for `/v3/block_proposal`), and have the node's event dispatcher (`stacks-node/src/event_dispatcher`) attach that same secret on every callback it sends to `events_observer` endpoints. Reject requests without a valid token before deserializing the body.

**Long term:** Do not rely solely on network-level trust for endpoints that feed signer/consensus-relevant data; enforce it in code. Additionally, harden `TryFrom<StackerDBChunksEvent> for SignerEvent<T>` to re-verify that a chunk's recovered signer key matches the registered slot owner for the target contract before trusting its payload, so the event-observer path fails closed even if the transport-layer auth is misconfigured.

### Proof of Concept
1. Deploy a `stacks-signer` using the shipped `sample/conf/signer/mainnet-signer-conf.toml` with `endpoint = "0.0.0.0:30000"` per the sample node config [6](#0-5) .
2. From any host that can reach `30000/tcp` on the signer, construct a `StackerDBChunksEvent` JSON body for the `.signers-0-...` boot contract, with a `StackerDBChunkData` whose `sig` field is a signature (from an attacker-controlled key) over the chunk metadata, and whose `data` begins with a valid `SignerMessageTypePrefix` byte for that lane.
3. POST this JSON to `http://<signer-host>:30000/stackerdb_chunks` with `Content-Type: application/json`.
4. `SignerEventReceiver::next_event` routes it to `process_event::<T, StackerDBChunksEvent>` with no auth check [11](#0-10) ; `TryFrom<StackerDBChunksEvent>` recovers a public key from the attacker's own signature (always succeeds for a well-formed signature) and, since the type-prefix matches the lane, emits `SignerEvent::SignerMessages` containing the forged message [12](#0-11) , without ever checking that the recovered key is a real registered signer for that slot — this check exists only inside the node's own StackerDB write path, which this HTTP POST never touched.

        self.with_server(|event_receiver, http_server, _is_mainnet| {

            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)
            } else if request.url() == "/new_block" {
                process_event::<T, StacksBlockEvent>(request)
            } else {
                let url = request.url().to_string();

                    url
