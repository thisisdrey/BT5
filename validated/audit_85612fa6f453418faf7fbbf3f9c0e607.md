### Title
Disabled-API access-control bypass in `HttpApiAccessFilter.isDisabled` allows reading data the operator has explicitly blocked - (File: `framework/src/main/java/org/tron/core/services/filter/HttpApiAccessFilter.java`)

### Summary
`node.disabledApi` lets an operator explicitly turn off specific HTTP wallet APIs (e.g. `getaccount`, `getnowblock`) that they consider unsafe to expose publicly. [1](#0-0)  Enforcement for HTTP is done in `HttpApiAccessFilter.isDisabled`, which normalizes the request path and then blindly indexes the **third path segment** (`endpoint.split("/")[2]`) to decide whether the requested endpoint name is on the disabled list. [2](#0-1)  Because dot-segment normalization can shift the servlet name away from index `2` (e.g. extra path segments that partially collapse under `..`), the filter can fail to recognize the disabled endpoint even though the request still resolves to that servlet, letting an unauthenticated client read data the node operator intended to block. This is analogous in bug-class (unauthenticated HTTP request bypassing an access restriction to reach a subset of otherwise-restricted server data) to CVE-2026-73872 in Helidon's Imperative Web Server.

### Finding Description
The filter is wired for all `/wallet/*`, `/net/listnodes`, `/monitor/getstatsinfo`, and `/monitor/getnodeinfo` paths ahead of the actual servlets. [3](#0-2)  Its `isDisabled` check is:
```java
endpoint = URI.create(endpoint).normalize().toString();
List<String> disabledApiList = CommonParameter.getInstance().getDisabledApiList();
if (!disabledApiList.isEmpty()) {
  disabled = disabledApiList.contains(endpoint.split("/")[2].toLowerCase(Locale.ROOT));
}
```
This assumes that after normalization the disabled API name is always the element at index `2` of the split path (e.g. `["", "wallet", "getnowblock"]`). The project's own test suite demonstrates that this assumption breaks: for a disabled API `getnowblock`, the path `"/wallet/a/../b/../getnowblock"` normalizes fully to `/wallet/getnowblock` and is correctly blocked, but `"/wallet/a/b/../getnowblock"` normalizes only partially to `/wallet/a/getnowblock` (because `URI.normalize()` removes just one preceding segment per `..`), moving the real endpoint name to index `3` instead of `2` — and the filter's own unit test explicitly asserts this case is **not** flagged as disabled. [4](#0-3)  The gRPC equivalent (`RpcApiAccessInterceptor`) has the analogous flaw with a similar fixed-index `split("/")[1]` lookup, though gRPC method names are not attacker-shaped the same way. [5](#0-4) 

Any wallet HTTP endpoint an operator disables (e.g. `getaccount`, `getnowblock`, `listwitnesses`, `getnodeinfo`) is a candidate: the same servlet handlers (`GetAccountServlet`, `GetBlockByNumServlet`, `GetNodeInfoServlet`, etc.) remain registered and reachable by the underlying Jetty dispatcher; only this filter is supposed to gate them once disabled via config. [6](#0-5) 

### Impact Explanation
If exploitable end-to-end (i.e., if the crafted path with residual `..` segments still resolves through the servlet container's URL-to-servlet mapping to the intended servlet while `getServletPath()`/`getContextPath()` still returns the un-collapsed path fed into `isDisabled`), an unauthenticated remote client could retrieve account data, node/block/witness/exchange information, etc. from an endpoint the node operator explicitly disabled to reduce information exposure — matching the "unauthorized read access to a subset of accessible data" classification of CVE-2026-73872. This is Confidentiality-only, no funds theft or RCE, consistent with a Medium severity finding.

### Likelihood Explanation
Likelihood depends on whether the servlet container (Jetty, via `ServletContextHandler`) itself canonicalizes/collapses `..`/`.` segments in the raw request path before dispatch and before `getServletPath()` is read. Modern Jetty versions typically perform URI compliance normalization at the connector level, which could either (a) reject ambiguous paths outright, (b) fully canonicalize them before the filter sees them (defeating the bypass), or (c) pass through partially-resolved paths depending on `UriCompliance` mode configured. I was not able to fully confirm the exact Jetty version/`UriCompliance` configuration used by `HttpService`/`FullNodeHttpApiService` within the available index, so I cannot conclusively prove that a real network request (as opposed to the direct reflection-based unit test) reaches the vulnerable code path with an un-normalized/partially-normalized `getServletPath()`. This is a meaningful gap in the proof; the code-level flaw (fixed-index path parsing after only partial normalization) is real and demonstrated by the project's own test, but full remote exploitability could not be verified from the indexed sources alone.

### Recommendation
Replace the fixed-index parsing in `HttpApiAccessFilter.isDisabled` (and the analogous logic in `RpcApiAccessInterceptor`) with a check based on the last path segment after full normalization (or an explicit servlet-name lookup / allow-list from the actual registered `ServletHolder` mapping) rather than assuming the disabled API name always sits at index `2`. Additionally, verify/enforce a strict `UriCompliance` mode on the Jetty connector so that requests containing residual or ambiguous `.`/`..` segments are rejected (400) rather than dispatched with partially-normalized paths.

### Proof of Concept
Using the project's own filter test as a template (`HttpApiAccessFilterTest.testIsDisabled`), with `getnowblock` configured as disabled: requesting the same underlying servlet via `GET /wallet/a/b/../getnowblock` internally normalizes to `/wallet/a/getnowblock`, shifting `getnowblock` from index `2` to index `3` in the split path, causing `isDisabled` to return `false` and allow the request through — as directly asserted by the existing unit test. [7](#0-6)  Full remote reproduction requires confirming that an actual HTTP client can cause Jetty to dispatch such a request to the `getnowblock` servlet while presenting this same un/partially-normalized path via `getServletPath()`, which was not verifiable from the available codebase index.

    boolean disabled = false;

      if (!disabledApiList.isEmpty()) {

      }

      logger.warn("check isDisabled except, endpoint={}, {}", endpoint, e.getMessage());
    }
