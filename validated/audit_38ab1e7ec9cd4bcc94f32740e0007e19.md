### Title
Unauthenticated, unrate-limited stage-1 handshake processing enables remote CPU-exhaustion DoS - (File: handshake_manager.go)

### Summary
`HandshakeManager.HandleIncoming` accepts any UDP packet with `h.Type == header.Handshake` and, for every packet with `MessageCounter == 1` and `RemoteIndex == 0`, unconditionally calls `beginHandshake`, which performs a full Noise `ReadMessage`/DH computation and (optionally) a `WriteMessage` response, before any certificate is validated. There is no per-source or global rate limit on how many stage-1 handshakes a given attacker (or spoofed source) can trigger, mirroring the audited bug class of "no rate limiting on a semi-trusted/cheap-to-reach entry point that performs expensive/valuable work."

### Finding Description
`HandleIncoming` gates on subtype and on the `remote_allow_list` (`AllowUnknownVpnAddr`), then immediately dispatches to `beginHandshake` for any packet claiming to be message 1: [1](#0-0) 

`beginHandshake` builds a fresh `handshake.Machine` and calls `machine.ProcessPacket`, which performs an X25519 Diffie-Hellman/Noise `ReadMessage` operation (asymmetric crypto) and, if the pattern requires it, immediately serializes and sends a response via `WriteMessage` — all of this happens *before* `validatePeerCert` runs, i.e., before any certificate/CA verification of the sender: [2](#0-1) [3](#0-2) 

Nothing in this path tracks or limits how many times a given source address (or `via`) can trigger `beginHandshake` within a time window; the only gate is the remote allow list (which, by default configuration, allows any address, and even when configured, allows entire CIDR ranges of untrusted/unauthenticated senders). The `HandshakeManager.config` struct only holds retry/backoff parameters for the *outbound* side (`tryInterval`, `retries`, `triggerBuffer`), with no analogous inbound rate limiter: [4](#0-3) 

Compare this to the data-plane replay protection (`Bits`/`ConnectionState.Decrypt`), which only runs *after* a handshake is completed and a `ConnectionState` exists — there is no equivalent cost-control mechanism prior to that point for stage-1 packets: [5](#0-4) 

This is analogous to the Arrakis M-2 bug class: a cheap, repeatable call into an expensive operation (`rebalance` there; here, Noise DH computation and certificate reconstruction/verification) with no rate limiting, allowing a caller who doesn't need to hold any privileged credential (an unauthenticated UDP sender — no CA-signed cert required to reach this code) to force unbounded resource consumption on the target.

### Impact Explanation
An attacker with no valid Nebula certificate can flood a node (or a lighthouse, which is reachable by design from many peers) with crafted UDP packets of `header.Handshake` type, subtype `HandshakeIXPSK0`, `MessageCounter == 1`, `RemoteIndex == 0`. Each such packet forces the victim to allocate a new `handshake.Machine`, perform a Noise handshake state DH computation, and potentially build/send a response packet — all before certificate verification rejects the packet. Because there is no limit on the number of concurrent/sequential stage-1 attempts an unauthenticated source can generate, this allows a remote, unauthenticated actor to exhaust CPU and induce a denial of service on legitimate handshake processing, which is a "remote crash/DoS" class impact per the task's acceptance criteria.

### Likelihood Explanation
Likelihood is high in typical deployments: the `remote_allow_list` defaults to allowing all sources unless explicitly restricted, so most Nebula deployments are reachable via UDP by hosts with no prior authentication. Constructing a syntactically valid stage-1 packet (header + Noise ephemeral key) requires no possession of a CA-signed certificate — only a well-formed message-1 payload, which is public protocol structure. The attack requires no cryptographic secret and can be launched from any IP address that reaches the UDP listener (including spoofed source since UDP is used and the underlying transport is not authenticated at this stage).

### Recommendation
Introduce inbound rate limiting on stage-1 handshake processing, keyed by source address (`via.UdpAddr.Addr()`), analogous to a token-bucket or a limit on outstanding pending-handshake `Machine` instances per source/CIDR. Reject or drop excess stage-1 attempts before allocating a `handshake.Machine` or invoking `ProcessPacket`. Consider also bounding the total number of pending (`hm.indexes`/`hm.vpnIps`) handshake entries system-wide to cap memory/CPU exposure, similar to the existing `TODO: need conntrack max tracked connections handling` noted for the firewall's conntrack table.

### Proof of Concept
Not independently executable in this review (no runtime/network access), but the code path is deterministic and reachable as follows:
1. Attacker crafts a UDP packet with `header.Type = Handshake`, `Subtype = HandshakeIXPSK0`, `MessageCounter = 1`, `RemoteIndex = 0`, and a syntactically valid (but arbitrary) Noise ephemeral-key payload.
2. Send this packet repeatedly (varying nonces/ephemeral keys to avoid `ErrAlreadySeen` dedup) from any source address permitted by `remote_allow_list` (default: any).
3. Each packet reaches `HandleIncoming` → `beginHandshake` → `machine.ProcessPacket`, forcing a DH computation and Machine allocation on the victim, with no rate limit rejecting the flood before this expensive work occurs.
4. Repeating at high volume drives CPU/memory consumption on the target node, degrading or denying legitimate handshake processing — consistent with the `e2e/handshake_manager_test.go` tests (`TestHandshakeUnknownMessageCounter`, `TestHandshakeRemoteAllowList`) which confirm the exact set of gates (subtype, allow-list) but do not exercise or enforce any volumetric/rate limit on stage-1 processing: [6](#0-5) [7](#0-6)

func (hm *HandshakeManager) HandleIncoming(via ViaSender, packet []byte, h *header.H) {
	// Gate on known handshake subtypes. Unknown subtypes (or future ones we
	// don't yet support) are dropped here rather than silently routed through
	// the IX path. Add a case when introducing a new pattern.
	switch h.Subtype {
	case header.HandshakeIXPSK0:
		// supported
	default:
		hm.l.Debug("dropping handshake with unsupported subtype",
			"from", via, "subtype", h.Subtype)
		return
	}

	// First remote allow list check before we know the vpnIp
	if !via.IsRelayed {
		if !hm.lightHouse.GetRemoteAllowList().AllowUnknownVpnAddr(via.UdpAddr.Addr()) {
			hm.l.Debug("lighthouse.remote_allow_list denied incoming handshake", "from", via)
			return
		}
	}

	// First message of a new handshake. The wire format requires RemoteIndex
	// to be zero here (the initiator has no responder index to fill in yet),
	// and generateIndex never allocates 0, so any non-zero RemoteIndex on a
	// stage-1 packet is malformed or someone probing for an index collision.
	// Drop without paying the cost of running noise on a pending Machine.
	if h.MessageCounter == 1 {
		if h.RemoteIndex != 0 {
			hm.l.Debug("dropping stage-1 handshake with non-zero RemoteIndex",
				"from", via, "remoteIndex", h.RemoteIndex)
			return
		}
		hm.beginHandshake(via, packet, h)
		return
	}

func (hm *HandshakeManager) beginHandshake(via ViaSender, packet []byte, h *header.H) {
	f := hm.f
	cs := f.pki.getCertState()

	v := cs.DefaultVersion()
	if cs.GetCredential(v) == nil {
		f.l.Error("Unable to handshake with host because no certificate is available",
			"from", via, "certVersion", v)
		return
	}

	machine, err := handshake.NewMachine(
		v, cs.GetCredential,
		hm.certVerifier(), func() (uint32, error) { return generateIndex(f.l) },
		false, header.HandshakeIXPSK0,
	)
	if err != nil {
		f.l.Error("Failed to create handshake machine", "from", via, "error", err)
		return
	}

	response, result, err := machine.ProcessPacket(nil, packet)
	if err != nil {
		f.l.Error("Failed to process handshake packet", "from", via, "error", err)
		return
	}

	if result == nil {
		// Multi-message pattern: the responder Machine would need to be
		// registered in hm.indexes so a future inbound packet finds it via
		// continueHandshake. The current manager doesn't do that yet, so
		// fail loudly rather than silently dropping the in-flight handshake.
		// TODO: support multi-message responder flows (XX, pqIX, etc.).
		// See also the IX-shaped cipher key assignment in handshake.Machine.
		f.l.Error("multi-message handshake responder is not supported",
			"from", via, "error", handshake.ErrMultiMessageUnsupported)
		return
	}

	remoteCert := result.RemoteCert
	if remoteCert == nil {
		f.l.Error("Handshake did not produce a peer certificate", "from", via)
		return
	}

	// Validate peer identity
	vpnAddrs, anyVpnAddrsInCommon, ok := hm.validatePeerCert(via, remoteCert)
	if !ok {
		return
	}

func (m *Machine) ProcessPacket(out, packet []byte) ([]byte, *Result, error) {
	if m.failed {
		return nil, nil, ErrMachineFailed
	}
	if len(packet) < header.Len {
		return nil, nil, ErrPacketTooShort
	}
	// Reject packets whose subtype doesn't match the one this Machine was
	// built for. A pending handshake that suddenly receives a different
	// subtype on its index is either a stray packet that matched by chance
	// or a peer protocol violation; drop it without failing the Machine so
	// the legitimate retransmit can still complete.
	if header.MessageSubType(packet[1]) != m.subtype {
		return nil, nil, ErrSubtypeMismatch
	}
	if m.result.Initiator && m.hs.MessageIndex() == 0 {
		m.failed = true
		return nil, nil, ErrInitiateNotCalled
	}

	// The (eKey, dKey) ordering here is correct for IX, where the initiator
	// completes the handshake by reading the responder's stage-2 message.
	// noise returns (cs1, cs2) where cs1 is the initiator->responder cipher.
	// For 3-message patterns where a responder finishes by reading the final
	// message, this ordering would be wrong; revisit when XX/pqIX lands.
	msg, eKey, dKey, err := m.hs.ReadMessage(nil, packet[header.Len:])
	if err != nil {
		// Noise ReadMessage failed. The noise library checkpoints and rolls back
		// on failure, so the Machine is still alive. The caller can retry with
		// a different packet.
		return nil, nil, fmt.Errorf("noise ReadMessage: %w", err)
	}

func (cs *ConnectionState) Decrypt(l *slog.Logger, messageCounter uint64, out []byte, packet []byte, nb []byte) ([]byte, error) {
	var err error
	cs.decryptLock.Lock()
	result := cs.window.Check(l, messageCounter)
	cs.decryptLock.Unlock()
	if !result {
		return nil, ErrAlreadySeen
	}

	out, err = cs.dKey.DecryptDanger(out, packet[:header.Len], packet[header.Len:], messageCounter, nb)
	if err != nil {
		return nil, err
	}

	cs.decryptLock.Lock()
	result = cs.window.Update(l, messageCounter)
	cs.decryptLock.Unlock()
	if !result {
		return nil, ErrAlreadySeen
	}
	return out, nil
}

func TestHandshakeUnknownMessageCounter(t *testing.T) {
	t.Parallel()
	// A handshake packet with an unexpected message counter should be silently
	// dropped with no side effects and no UDP response.

	ca, _, caKey, _ := cert_test.NewTestCaCert(cert.Version1, cert.Curve_CURVE25519, time.Now(), time.Now().Add(10*time.Minute), nil, nil, []string{})
	myControl, _, myUdpAddr, _ := newSimpleServer(cert.Version1, ca, caKey, "me", "10.128.0.1/24", nil)
	theirControl, theirVpnIpNet, theirUdpAddr, _ := newSimpleServer(cert.Version1, ca, caKey, "them", "10.128.0.2/24", nil)

	myControl.InjectLightHouseAddr(theirVpnIpNet[0].Addr(), theirUdpAddr)

	myControl.Start()
	theirControl.Start()

	t.Log("Inject handshake with MessageCounter=3")
	myControl.InjectUDPPacket(makeHandshakePacket(theirUdpAddr, myUdpAddr, header.HandshakeIXPSK0, 0, 3))

	t.Log("Inject handshake with MessageCounter=99")
	myControl.InjectUDPPacket(makeHandshakePacket(theirUdpAddr, myUdpAddr, header.HandshakeIXPSK0, 0, 99))

	t.Log("Verify no tunnels or pending handshakes")
	assert.Empty(t, myControl.ListHostmapHosts(false))
	assert.Empty(t, myControl.ListHostmapHosts(true))

	t.Log("Verify no UDP response was sent")
	time.Sleep(100 * time.Millisecond)
	assert.Nil(t, myControl.GetFromUDP(false))

	myControl.Stop()
	theirControl.Stop()
}

func TestHandshakeRemoteAllowList(t *testing.T) {
	t.Parallel()
	// Verify that a handshake from a blocked underlay IP is dropped with no
	// response and no state changes. Then verify the same packet from an
	// allowed IP succeeds.

	ca, _, caKey, _ := cert_test.NewTestCaCert(cert.Version1, cert.Curve_CURVE25519, time.Now(), time.Now().Add(10*time.Minute), nil, nil, []string{})
	myControl, myVpnIpNet, myUdpAddr, _ := newSimpleServer(cert.Version1, ca, caKey, "me", "10.128.0.1/24", m{
		"lighthouse": m{
			"remote_allow_list": m{
				"10.0.0.0/8": true,
				"0.0.0.0/0":  false,
			},
		},
	})
	theirControl, theirVpnIpNet, theirUdpAddr, _ := newSimpleServer(cert.Version1, ca, caKey, "them", "10.128.0.2/24", nil)

	myControl.InjectLightHouseAddr(theirVpnIpNet[0].Addr(), theirUdpAddr)
	theirControl.InjectLightHouseAddr(myVpnIpNet[0].Addr(), myUdpAddr)

	myControl.Start()
	theirControl.Start()

	r := router.NewR(t, myControl, theirControl)
	defer r.RenderFlow()

	t.Log("Trigger handshake from them")
	theirControl.InjectTunPacket(BuildTunUDPPacket(myVpnIpNet[0].Addr(), 80, theirVpnIpNet[0].Addr(), 80, []byte("Hi")))
	msg1 := theirControl.GetFromUDP(true)

	t.Log("Rewrite the source to a blocked IP and inject")
	blockedMsg := msg1.Copy()
	blockedMsg.From = netip.MustParseAddrPort("192.168.1.1:4242")
	myControl.InjectUDPPacket(blockedMsg)

	t.Log("Verify no tunnel, no pending, no response from blocked source")
	time.Sleep(100 * time.Millisecond)
	assert.Empty(t, myControl.ListHostmapHosts(false))
	assert.Empty(t, myControl.ListHostmapHosts(true))
	assert.Nil(t, myControl.GetFromUDP(false), "should not respond to blocked source")

	t.Log("Now inject the real packet from the allowed source")
	myControl.InjectUDPPacket(msg1)

	t.Log("Verify handshake completes from allowed source")
	resp := myControl.GetFromUDP(true)
	assert.NotNil(t, resp)
	theirControl.InjectUDPPacket(resp)
	theirControl.WaitForType(1, 0, myControl)

	t.Log("Drain cached packet and verify tunnel works")
	cachedPacket := myControl.GetFromTun(true)
	assertUdpPacket(t, []byte("Hi"), cachedPacket, theirVpnIpNet[0].Addr(), myVpnIpNet[0].Addr(), 80, 80)
	assertTunnel(t, myVpnIpNet[0].Addr(), theirVpnIpNet[0].Addr(), myControl, theirControl, r)

	myControl.Stop()
	theirControl.Stop()
}
