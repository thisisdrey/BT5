### Title
`GetArchive` cache key omits the actual repository identity, enabling cross-repository archive content disclosure - (File: internal/gitaly/service/repository/archive.go)

### Summary
`MultiMerkleDistributor.claim()` bound a leaf proof only to `index/account/amount`, omitting `questID`/`period`, so a proof valid for one quest/period could be replayed against another. The same missing-identity-binding pattern exists in Gitaly's `GetArchive` RPC: the disk-backed archive `streamcache.Cache` is keyed by `createArchiveCacheKey(gitLabProjectPath, args, pathspecs)` in `internal/gitaly/service/repository/archive.go:290-296`, which never includes the repository's `StorageName`/`RelativePath` — the values that actually identify which on-disk repository the content was generated from.

### Finding Description
`GetArchive` builds its cache key purely from three request-controlled/derived values: [1](#0-0) [2](#0-1) 

`gitLabProjectPath` comes from `repo.GetGlProjectPath()`, which is simply a field on the client-supplied `gitalypb.Repository` message: [3](#0-2) 

Unlike `StorageName`/`RelativePath`, `GlProjectPath` is metadata passed through from the caller (GitLab Rails/Workhorse) and is not verified by `ValidateRepository`/`GetRepoPath` against the actual on-disk repository being addressed — it plays no role in path resolution, only informational purposes such as LFS smudging. The RPC itself does validate `StorageName`/`RelativePath` for the repository it operates on: [4](#0-3) 

...but that validated identity is never mixed into the cache key. The shared `streamcache.Cache.Fetch` looks up entries purely by string `key`, with no secondary check against the repository that originated the request: [5](#0-4) 

Since `args` is built from `in.GetCommitId()` (a plain SHA/ref string, not scoped to a repository) and `pathspecs` from a path/exclude list, two different repositories that happen to reference the same commit OID and same file path, while sharing (or being made to share) the same `GlProjectPath` value, will resolve to the same cache key. Because `GlProjectPath` is not tied to storage/relative path by any server-side check, a caller of `GetArchive` — such as GitLab Rails invoking on behalf of an ordinary user who fetches/imports/forks another accessible repository sharing a commit history (e.g. a fork of a public project, both objects reachable via alternates/object pool sharing the same OIDs) — can cause an archive generated for repository A to be served for repository B, or vice versa, as long as the three cache-key inputs collide.

### Impact Explanation
A successful collision returns file contents belonging to a repository other than the one that was actually requested and authorized for the current caller, i.e., cross-repository content disclosure. This is a confidentiality violation similar in class to the merkle-tree bug's cross-context "wrong rewards claimed" — here it's "wrong repository's archive returned" because the identity actually verified per-request (storage+relative path) is decoupled from the key actually used for retrieval/caching.

### Likelihood Explanation
Exploitation requires: (1) the attacker's session/project to reach `GetArchive` with a controllable/collidable `GlProjectPath` metadata value, and (2) a commit-OID + pathspec collision between the victim and attacker repositories (most easily achieved between a project and its own fork/pool-linked repository, which commonly share object IDs via Gitaly's object-pool/alternates mechanism). This narrows real-world likelihood, matching the "low likelihood, high impact" medium-risk classification of the original report, since it depends on shared history between repositories and correctly-timed cache population, but requires no privileged access, malicious peer, or leaked token — only ordinary repository access (e.g., fork relationship) that Gitaly must otherwise strictly isolate via storage path/relative path scoping.

### Recommendation
Include the validated repository identity (e.g., `StorageName` + `RelativePath`, or the resolved absolute repo path) in `createArchiveCacheKey` instead of, or in addition to, the caller-supplied `GlProjectPath`, mirroring the merkle-tree fix of binding the proof to the full identifying context (`questID`, `period`) rather than trusting an externally supplied identifier alone.

### Proof of Concept
1. Two repositories, `repo-A` (`storage/relpath-a`) and `repo-B` (`storage/relpath-b`), share commit `deadbeef...` (e.g., `repo-B` is a fork/pool member of `repo-A`) and both requests set the same `GlProjectPath` value in the `Repository` message (either through natural equal project-path metadata forwarded by Rails, or a directly crafted RPC when Gitaly is reached without strict Rails mediation).
2. Caller issues `GetArchive` against `repo-A` for `commitId=deadbeef`, `path="."`, format `TAR`. Response is cached under `sha256(GlProjectPath || "deadbeef" || "." )`.
3. Caller (with access only to `repo-B`) issues `GetArchive` against `repo-B` with the same `commitId=deadbeef`, `path="."`, format `TAR`, and the same `GlProjectPath`.
4. `createArchiveCacheKey` produces the identical key as step 2 (since `StorageName`/`RelativePath` are never part of the key), so `streamcache.Cache.Fetch` returns the cached archive built from `repo-A`'s working tree/refs (potentially including files that differ between the two repositories despite the shared commit, e.g. paths outside the shared history or private additions), rather than regenerating from `repo-B`.

func createArchiveCacheKey(gitLabProjectPath string, args []string, pathspecs []string) string {
	cacheKeyHash := sha256.New()
	cacheKeyHash.Write([]byte(gitLabProjectPath))
	cacheKeyHash.Write([]byte(strings.Join(args, ",")))
	cacheKeyHash.Write([]byte(strings.Join(pathspecs, ",")))
	return hex.EncodeToString(cacheKeyHash.Sum(nil))
}

func (c *cache) Fetch(ctx context.Context, key string, dst io.Writer, create func(io.Writer) error) (written int64, created bool, err error) {
	var (
		rc io.ReadCloser
		wt *waiter
	)
	rc, wt, created, err = c.getStream(key, create)
	if err != nil {
		return written, created, err
	}
	defer rc.Close()

	written, err = io.Copy(dst, rc)
	if err != nil {
		return written, created, err
	}

	err = wt.Wait(ctx)
	return written, created, err
}
