Based on my research, I found a legitimate analog to the CVE-2022-43551 bug class in java-tron. The core pattern is: a security check uses a **pre-canonicalization value** for one purpose (deduplication) while the **canonical/normalized value** (the actual signer identity) is used for weight/authorization — allowing a bypass through non-canonical representations that resolve to the same underlying entity, exactly like the curl bug used the pre-IDN hostname for the HSTS cache write while the post-IDN hostname was used for the actual connection.

### Title
Multisig duplicate-signer check keyed on raw (malleable) signature bytes instead of canonical recovered address inflates approval weight - (File: `chainbase/src/main/java/org/tron/core/capsule/TransactionCapsule.java`)

### Summary
`TransactionCapsule.checkWeight()` computes each signer's weight for a multisig `Permission` by recovering `address` from each submitted signature, but the "signed twice" duplicate-detection dictionary (`addMap`) is keyed on the **raw base64 signature string**, not on the canonical `address`, unless `ForkController.instance().pass(Parameter.ForkBlockVersionEnum.VERSION_4_7_1)` is true. [1](#0-0) 

### Finding Description
The dedup key normally should be the canonical signer identity (the recovered `address`), because a single ECDSA key can produce multiple distinct, independently-valid signature byte strings for the same message hash (canonical vs. non-canonical `s`, or any equivalent malleated encoding accepted by the underlying verifier). When the fork gate is not active, the code instead uses `base64 = TransactionCapsule.getBase64FromByteString(sig)` (i.e., the pre-normalization raw signature bytes) as the map key: [2](#0-1)  — this is structurally identical to the curl bug, where the un-normalized hostname was written to the HSTS cache while the normalized hostname was used for the actual connection/security decision. Here, the un-normalized signature bytes are used for the "already counted" check, while the normalized/canonical `address` (derived via `SignUtils.signatureToAddress`) is what actually maps to weight via `getWeight(permission, address)`. If an attacker (or a single legitimate co-signer) supplies two syntactically different but validly-recoverable signatures for the same underlying key, both pass the `weight == 0` check and both get added under distinct raw-signature keys, so `currentWeight` counts the same key's weight twice instead of once.

The post-fork branch fixes this properly by re-keying on `encode58Check(address)` — the canonical identity — showing the project maintainers previously recognized address-based (not raw-bytes-based) dedup as the correct approach. [3](#0-2) 

This function is reached from every path that validates a signed multisig transaction's weight, including `TransactionCapsule.validateSignature` (called from `validatePubSignature`, invoked for every broadcast transaction), `TransactionUtil.getTransactionSignWeight`, `Wallet.getTransactionApprovedList`, and `TransactionCapsule.addSign`. [4](#0-3) [5](#0-4) 

### Impact Explanation
If the fork gate is not active for the block being processed (which matters for backward-compatible historical block replay/re-validation and for any deployment/private chain where this specific proposal has not been activated), a signer holding a single active key with weight `W` could get counted with effective weight `2W` (or more, bounded by `MAX_SIZE`/`totalSignNum`) by submitting multiple distinct signature encodings, potentially satisfying a multisig `threshold` without the required number of independent co-signers. This is a broken-access-control primitive for TRON's account permission (multisig) system — an unauthorized account operation (funds transfer, permission change, etc.) could be executed with fewer real approvers than the permission's threshold requires.

### Likelihood Explanation
The vulnerable code path is only reachable when `ForkController.instance().pass(VERSION_4_7_1)` returns `false`. On networks where this specific hard fork has already been activated (the typical state for long-running mainnets/testnets), the address-keyed branch is used and the issue is not exploitable in present-day operation. The residual risk applies to: private/consortium java-tron networks that have not yet activated this proposal, and any historical-block re-validation/replay logic that intentionally exercises pre-fork rules. It also requires the ability to construct a second syntactically-different-but-valid signature for the same key/hash, which depends on the underlying `SignUtils`/`ECKey` signature verification accepting non-canonical `s` values or other malleated encodings.

### Recommendation
Always key the `addMap` duplicate-check by the canonical recovered `address` (as already done post-fork), regardless of fork-activation status, or explicitly reject any signature whose `s` value is not in canonical low-form before recovery — closing the malleability gap at the source rather than only at the dedup step.

### Proof of Concept
1. Set up an account with an `Active` permission requiring `threshold = 2` with two keys, or (for the strongest case) a single key with `weight >= threshold` under a chain state where `ForkController.instance().pass(VERSION_4_7_1)` is `false`.
2. Sign the transaction hash once with the private key to get signature `sig1`.
3. Derive a second, syntactically different but independently-valid signature `sig2` for the same `(privateKey, hash)` pair by manipulating the signature encoding so that `SignUtils.signatureToAddress` still recovers the same `address`, but `getBase64FromByteString(sig2) != getBase64FromByteString(sig1)`.
4. Submit a transaction with `signatures = [sig1, sig2]`.
5. In `checkWeight`, both pass `weight == 0` checks and are added to `addMap` under two different `base64` keys (since the fork gate is inactive), so `currentWeight = 2 * weight` even though only one distinct key/signer actually signed. [6](#0-5) 
6. If `2 * weight >= permission.getThreshold()`, the transaction is treated as validly authorized despite lacking the required number of distinct approving keys.

  public static long checkWeight(Permission permission, List<ByteString> sigs, byte[] hash,
      List<ByteString> approveList)
      throws SignatureException, PermissionException, SignatureFormatException {
    long currentWeight = 0;
    if (sigs.size() > permission.getKeysCount()) {
      throw new PermissionException(
          "Signature count is " + (sigs.size()) + " more than key counts of permission : "
              + permission.getKeysCount());
    }
    HashMap addMap = new HashMap();
    for (ByteString sig : sigs) {
      if (sig.size() < 65) {
        throw new SignatureFormatException(
            "Signature size is " + sig.size());
      }
      String base64 = TransactionCapsule.getBase64FromByteString(sig);
      byte[] address = SignUtils
          .signatureToAddress(hash, base64, CommonParameter.getInstance().isECKeyCryptoEngine());
      long weight = getWeight(permission, address);
      if (weight == 0) {
        throw new PermissionException(
            ByteArray.toHexString(hash) + " is signed by " + encode58Check(address)
                + " but it is not contained of permission.");
      }
      if (ForkController.instance().pass(Parameter.ForkBlockVersionEnum.VERSION_4_7_1)) {
        base64 = encode58Check(address);
      }
      if (addMap.containsKey(base64)) {
        throw new PermissionException(encode58Check(address) + " has signed twice!");
      }
      addMap.put(base64, weight);
      if (approveList != null) {
        approveList.add(ByteString.copyFrom(address)); //out put approve list.
      }
      currentWeight += weight;
    }
    return currentWeight;

  public static boolean validateSignature(Transaction transaction,
      byte[] hash, AccountStore accountStore, DynamicPropertiesStore dynamicPropertiesStore)
      throws PermissionException, SignatureException, SignatureFormatException {
    Transaction.Contract contract = transaction.getRawData().getContractList().get(0);
    int permissionId = contract.getPermissionId();
    byte[] owner = getOwner(contract);
    AccountCapsule account = accountStore.get(owner);
    Permission permission = null;
    if (account == null) {
      if (permissionId == 0) {
        permission = AccountCapsule.getDefaultPermission(ByteString.copyFrom(owner));
      }
      if (permissionId == 2) {
        permission = AccountCapsule
            .createDefaultActivePermission(ByteString.copyFrom(owner), dynamicPropertiesStore);
      }
    } else {
      permission = account.getPermissionById(permissionId);
    }
    if (permission == null) {
      throw new PermissionException("permission isn't exit");
    }
    checkPermission(permissionId, permission, contract);
    long weight = checkWeight(permission, transaction.getSignatureList(), hash, null);
    if (weight >= permission.getThreshold()) {
      return true;
    }
    return false;
  }
