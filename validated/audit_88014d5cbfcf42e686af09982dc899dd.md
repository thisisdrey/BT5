Audit Report

## Title
Ethereum-side relayer reward silently truncates to zero for cheap commands, letting anyone submit real bridge-committed messages while underpaying the reward component of `Fee` - (File: `bridges/snowbridge/pallets/outbound-queue/src/lib.rs`)

## Summary
`calculate_fee` in `bridges/snowbridge/pallets/outbound-queue/src/lib.rs` computes the ETH-side relayer reward via `checked_div` by the ETH/DOT `exchange_rate` followed by integer truncation in `convert_from_ether_decimals`, and this can legitimately floor to zero even when every individual `PricingParameters` field is validated non-zero by `PricingParameters::validate`. [1](#0-0) [2](#0-1)  Neither `validate()` in `send_message_impl.rs` nor `PricingParameters::validate()` checks that the resulting `Fee` is non-zero, so an unprivileged caller can get real commands committed into `Messages`/`MessageLeaves` while the relayer reward embedded in `CommittedMessage.reward` is zero. [3](#0-2) [4](#0-3) 

## Finding Description
The test suite already demonstrates the exact zero-truncation path with fully "valid" non-zero pricing parameters (`exchange_rate = 1/1`, `fee_per_gas = 1`, `rewards = {local:1, remote:1}`, `multiplier = 1/1`, `gas_used = 250000`), producing `fee.remote == 0`, and the test's own comment acknowledges this is an "invalid" outcome that "should be avoided." [5](#0-4)  The computed `Fee` flows unmodified from `calculate_fee` into `SendMessage::validate`, which is invoked by every outbound message submission path, including ordinary user XCM transfers exported by `EthereumBlobExporter::validate`, which converts the fee to an `Asset` for local payment and forwards the ticket. [6](#0-5)  `deliver()` then unconditionally enqueues the message regardless of the fee amount computed upstream. [7](#0-6)  `do_process_message` subsequently reads `pricing_params.rewards.remote` directly (not the post-truncation `Fee` value) to populate `CommittedMessage.reward`, and commits the message into the Merkle tree without any re-validation that the fee actually charged is non-zero. [8](#0-7) 

## Impact Explanation
This matches the accepted "public underpriced work that degrades block production or stalls bridge processing" category: any ordinary account submitting XCM transfers to Ethereum with `gas_used_at_most` landing in a truncation-vulnerable band can get commands committed into `CommittedMessage` with `reward = 0` embedded, since `calculate_fee`'s output is never floor-guarded to be non-zero. [9](#0-8) 

## Likelihood Explanation
No privileged role is required — only ordinary permissionless message submission with a `gas_used_at_most` value that lands in the exact truncation band, and the existing unit test proves this reachable with realistic, individually non-zero `PricingParameters`. [5](#0-4) 

## Recommendation
Add an explicit invariant check in `calculate_fee` (or immediately after it) asserting the computed `fee.remote != 0` whenever `PricingParameters.rewards.remote` and `fee_per_gas` are non-zero, rejecting the message via `SendError` otherwise. Alternatively, use `Rounding::Up` for the `checked_div`/decimal-truncation steps in `calculate_fee` and `convert_from_ether_decimals` so a nonzero pre-truncation value can never collapse to zero.

## Proof of Concept
The existing test `test_calculate_fees_with_valid_exchange_rate_but_remote_fee_calculated_as_zero` in `bridges/snowbridge/pallets/outbound-queue/src/test.rs` reproduces the issue directly: with `exchange_rate = 1/1`, `fee_per_gas = 1`, `rewards = {local:1, remote:1}`, `multiplier = 1/1`, `gas_used = 250000`, `OutboundQueue::calculate_fee` returns `fee.remote == 0`. [5](#0-4)  A message submitted under these conditions via `EthereumBlobExporter::validate` → `SendMessage::validate` → `deliver` → `do_process_message` is accepted, enqueued, and merkle-committed with `reward = 0` recorded in `CommittedMessage`. [10](#0-9)

		pub(crate) fn calculate_fee(
			gas_used_at_most: u64,
			params: PricingParameters<T::Balance>,
		) -> Fee<T::Balance> {
			// Remote fee in ether
			let fee = Self::calculate_remote_fee(
				gas_used_at_most,
				params.fee_per_gas,
				params.rewards.remote,
			);

			// downcast to u128
			let fee: u128 = fee.try_into().defensive_unwrap_or(u128::MAX);

			// multiply by multiplier and convert to local currency
			let fee = FixedU128::from_inner(fee)
				.saturating_mul(params.multiplier)
				.checked_div(&params.exchange_rate)
				.expect("exchange rate is not zero; qed")
				.into_inner();

			// adjust fixed point to match local currency
			let fee = Self::convert_from_ether_decimals(fee);

			Fee::from((Self::calculate_local_fee(), fee))
		}

	pub fn validate(&self) -> Result<(), InvalidPricingParameters> {
		if self.exchange_rate == FixedU128::zero() {
			return Err(InvalidPricingParameters);
		}
		if self.fee_per_gas == U256::zero() {
			return Err(InvalidPricingParameters);
		}
		if self.rewards.local.is_zero() {
			return Err(InvalidPricingParameters);
		}
		if self.rewards.remote.is_zero() {
			return Err(InvalidPricingParameters);
		}
		if self.multiplier == FixedU128::zero() {
			return Err(InvalidPricingParameters);
		}
		Ok(())
	}

	fn validate(
		message: &Message,
	) -> Result<(Self::Ticket, Fee<<Self as SendMessageFeeProvider>::Balance>), SendError> {
		// The inner payload should not be too large
		let payload = message.command.abi_encode();
		ensure!(
			payload.len() < T::MaxMessagePayloadSize::get() as usize,
			SendError::MessageTooLarge
		);

		// Ensure there is a registered channel we can transmit this message on
		ensure!(T::Channels::contains(&message.channel_id), SendError::InvalidChannel);

		// Generate a unique message id unless one is provided
		let message_id: H256 = message
			.id
			.unwrap_or_else(|| unique((message.channel_id, &message.command)).into());

		let gas_used_at_most = T::GasMeter::maximum_gas_used_at_most(&message.command);
		let fee = Self::calculate_fee(gas_used_at_most, T::PricingParameters::get());

		let queued_message: VersionedQueuedMessage = QueuedMessage {
			id: message_id,
			channel_id: message.channel_id,
			command: message.command.clone(),
		}
		.into();
		// The whole message should not be too large
		let encoded = queued_message.encode().try_into().map_err(|_| SendError::MessageTooLarge)?;

		let ticket = Ticket { message_id, channel_id: message.channel_id, message: encoded };

		Ok((ticket, fee))
	}

fn test_calculate_fees_with_valid_exchange_rate_but_remote_fee_calculated_as_zero() {
	new_tester().execute_with(|| {
		let gas_used: u64 = 250000;
		let price_params: PricingParameters<<Test as Config>::Balance> = PricingParameters {
			exchange_rate: FixedU128::from_rational(1, 1),
			fee_per_gas: 1_u32.into(),
			rewards: Rewards { local: 1_u32.into(), remote: 1_u32.into() },
			multiplier: FixedU128::from_rational(1, 1),
		};
		let fee = OutboundQueue::calculate_fee(gas_used, price_params.clone());
		assert_eq!(fee.local, 698000000);
		// Though none zero pricing params the remote fee calculated here is invalid
		// which should be avoided
		assert_eq!(fee.remote, 0);
	});
}
