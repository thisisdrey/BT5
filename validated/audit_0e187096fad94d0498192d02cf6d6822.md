### Title
Unvalidated attachment content hash allows uncommitted data to be persisted into AtlasDB - (File: stackslib/src/net/atlas/download.rs)

### Summary
`AttachmentsBatchStateContext::extend_with_attachments` inserts a peer-supplied `Attachment` into the `attachments` set without verifying that `Hash160::from_data(&attachment.content)` equals the `content_hash` of the `AttachmentRequest` that was sent. The subsequent `AttachmentsDownloader::run` unconditionally persists every attachment in that set via `atlasdb.insert_instantiated_attachment(&attachment)`, regardless of whether it matches any known/requested content hash.

### Finding Description
`extend_with_attachments` (stackslib/src/net/atlas/download.rs:530-558) iterates `results.succeeded`, decodes the HTTP response via `response.decode_atlas_get_attachment()`, and does `self.attachments.insert(response.attachment)` with no check comparing `response.attachment.hash()` to `request.content_hash`. The `request` (which carries the original `content_hash`) is discarded once decoding succeeds — it's only used to look up the `report`/peer for reliability bookkeeping. In `AttachmentsDownloader::run`, the `Done` branch (lines 153-169) drains `context.attachments` and for each one:
1. calls `find_all_attachment_instances(&attachment.hash())` to find matching pending instances (keyed on the attacker-controlled hash of Y, not X)
2. unconditionally calls `network.atlasdb.insert_instantiated_attachment(&attachment)` — persisting Y under `Hash160::from_data(&Y)` in the AtlasDB `attachments` table, with no gating on whether this matches any legitimate `AttachmentInstance.content_hash` from a confirmed BNS transaction.

An attacker who is selected as `get_most_reliable_source()` for a given `AttachmentRequest{content_hash: X}` (reachable by being an outbound sync peer inventoried with the bit set in the requested page — an unprivileged peer role since Atlas inventory requests don't require any secret) can respond on `GET /v2/attachments/X` with an `Attachment{content: Y}` where `Y`'s hash ≠ X. This response is accepted, decoded, and inserted into `self.attachments` with no equality check.

### Impact Explanation
This causes uncommitted data (Y) to be stored persistently in the node's AtlasDB `attachments` table under key `Hash160::from_data(&Y)`, a hash no on-chain BNS name-update transaction ever committed to. This matches the "attachment/BNS mismatch" High-impact category: the node's local storage now contains attachment content that was never validated against any canonical on-chain commitment, and it is repeatable per attachment request, allowing an attacker (as the chosen download source) to pollute the AtlasDB with arbitrary uncommitted blobs on every request they win. ### Likelihood Explanation
Preconditions: the node must be actively resolving a BNS attachment instance with `content_hash == X`, have the attacker as an outbound sync peer advertising the attachment in its inventory (so it's chosen as a "reliable source" for the `AttachmentRequest`), and respond to the resulting `GET /v2/attachments/X` request. No privileged role, secret, or key is required to be an outbound peer/HTTP responder for public attachment content — this is a normal unauthenticated read endpoint. Attacker cost is a single crafted HTTP response, and the attack is repeatable for every attachment request routed to the malicious peer.

### Recommendation
In `extend_with_attachments`, before inserting into `self.attachments`, verify `response.attachment.hash() == request.content_hash`; on mismatch, treat it as a failed request (`report.bump_failed_requests()`) and optionally flag/deregister the peer, mirroring the existing `decode_atlas_get_attachment()` failure branch.

    pub fn extend_with_attachments(
        mut self,
        results: &mut BatchedRequestsResult<AttachmentRequest>,
    ) -> AttachmentsBatchStateContext {
        for (request, response) in results.succeeded.drain() {
            let report = self
                .peers
                .get_mut(request.get_url())
                .expect("Atlas: unable to retrieve reliability report for peer");

            let response = if let Some(r) = response {
                r
            } else {
                report.bump_failed_requests();
                continue;
            };

            if let Ok(response) = response.decode_atlas_get_attachment() {
                self.attachments.insert(response.attachment);
                report.bump_successful_requests();
            } else {
                report.bump_failed_requests();
            }
        }
        let mut events_ids = results.faulty_peers.keys().copied().collect::<Vec<usize>>();
        self.events_to_deregister.append(&mut events_ids);

        self
    }
