### Title
Operator-Controlled Beneficiary Can Permanently DoS Staker's `unlock_stake` and `switch_operator` via Undeliverable Commission Payment — (`File: aptos-move/framework/aptos-framework/sources/staking_contract.move`)

---

### Summary

`unlock_stake` and `switch_operator` in `staking_contract.move` call `distribute_internal` atomically before completing the staker's requested operation. `distribute_internal` calls `aptos_account::deposit_coins` for every distribution recipient. That function aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` when the recipient has no `CoinStore<AptosCoin>` and has set `allow_arbitrary_coin_transfers = false`. A malicious operator can set a beneficiary address that satisfies both conditions, causing every subsequent `unlock_stake` and `switch_operator` call to revert permanently, locking the staker's APT with no recovery path.

---

### Finding Description

`unlock_stake` forces a distribution of any already-inactive stake before recording the staker's new withdrawal:

```move
// Force distribution of any already inactive stake.
distribute_internal(staker_address, operator, staking_contract);
``` [1](#0-0) 

`distribute_internal` iterates over every shareholder in the distribution pool and calls:

```move
aptos_account::deposit_coins(
    recipient, coin::extract(&mut coins, amount_to_distribute)
);
``` [2](#0-1) 

When the recipient is the operator, the actual target is redirected to the operator's registered beneficiary:

```move
if (recipient == operator) {
    recipient = beneficiary_for_operator(operator);
};
``` [3](#0-2) 

`aptos_account::deposit_coins` contains the following guard:

```move
if (!coin::is_account_registered<CoinType>(to)) {
    assert!(
        can_receive_direct_coin_transfers(to),
        error::permission_denied(EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS)
    );
    coin::register<CoinType>(&create_signer(to));
};
``` [4](#0-3) 

`can_receive_direct_coin_transfers` returns `false` when the account has explicitly called `set_allow_direct_coin_transfers(false)`:

```move
public fun can_receive_direct_coin_transfers(account: address): bool acquires DirectTransferConfig {
    !exists<DirectTransferConfig>(account)
        || borrow_global<DirectTransferConfig>(account).allow_arbitrary_coin_transfers
``` [5](#0-4) 

Any operator can call `set_beneficiary_for_operator` to redirect commission to an arbitrary address:

```move
public entry fun set_beneficiary_for_operator(
    operator: &signer, new_beneficiary: address
) acquires BeneficiaryForOperator {
``` [6](#0-5) 

The same `distribute_internal` call also appears inside `switch_operator`, which is the staker's only escape route:

```move
let (_, staking_contract) = staking_contracts.remove(&old_operator);
// Force distribution of any already inactive stake.
distribute_internal(staker_address, old_operator, &mut staking_contract);
``` [7](#0-6) 

**Concrete trigger sequence:**

1. Operator creates or controls address `B`.
2. `B` calls `set_allow_direct_coin_transfers(false)` and does **not** register `CoinStore<AptosCoin>` (achievable in the FA-migration era where accounts may use FA-only stores, or by creating the account through a path that skips `register_apt`).
3. Operator calls `set_beneficiary_for_operator(B)`.
4. Any subsequent call to `unlock_stake` or `switch_operator` by the staker reaches `distribute_internal`, which attempts `deposit_coins(B, commission)`, hits the `assert!(can_receive_direct_coin_transfers(B), ...)` guard, and aborts.
5. The transaction reverts. The staker's principal remains locked in the stake pool with no callable exit path.

---

### Impact Explanation

The staker's APT staking balance is permanently frozen. `unlock_stake` is the only mechanism to begin withdrawing stake; `switch_operator` is the only mechanism to change operators without unstaking. Both are blocked by the same `distribute_internal` call. There is no privileged recovery function available to the staker. The staker's funds are effectively stolen through permanent inaccessibility.

This matches the "permanent freezing of staking balances" category in the Aptos allowed impact gate.

---

### Likelihood Explanation

- The operator is a user-chosen but otherwise unprivileged party; no framework admin capability is required.
- `set_beneficiary_for_operator` is an unrestricted entry function callable by any operator at any time.
- `set_allow_direct_coin_transfers(false)` is a standard user-facing entry function.
- A malicious operator has a clear financial motive: prevent the staker from withdrawing and moving stake to a competing validator.
- No on-chain monitoring or staker-side defense can prevent the operator from changing the beneficiary after the staking contract is established.

---

### Recommendation

Decouple commission distribution from the staker's withdrawal and operator-switch paths. Two concrete options:

1. **Lazy distribution:** Remove the `distribute_internal` call from `unlock_stake` and `switch_operator`. Let distributions accumulate and be claimed separately (as the standalone `distribute` entry function already allows). This mirrors the fix applied in the referenced BNB report.

2. **Graceful skip on delivery failure:** Wrap each `deposit_coins` call in `distribute_internal` in a try-catch pattern (or check deliverability before attempting), and if delivery fails, hold the undeliverable amount in a claimable escrow rather than aborting the entire transaction.

Additionally, `set_beneficiary_for_operator` should validate that the new beneficiary address is capable of receiving `AptosCoin` before accepting the change.

---

### Proof of Concept

```
// Step 1 – operator prepares an undeliverable beneficiary address B
// (B has no CoinStore<AptosCoin> and has opted out of direct transfers)
aptos_account::set_allow_direct_coin_transfers(&b_signer, false);
// Do NOT call coin::register<AptosCoin>(&b_signer)

// Step 2 – operator poisons the beneficiary
staking_contract::set_beneficiary_for_operator(&operator_signer, @B);

// Step 3 – staker attempts to unlock stake (any amount > 0)
// This calls distribute_internal -> deposit_coins(@B, commission)
// deposit_coins aborts: EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS
staking_contract::unlock_stake(&staker_signer, @operator, amount);
// ^ always aborts from this point forward

// Step 4 – staker attempts to escape via switch_operator
// switch_operator also calls distribute_internal with the same operator
staking_contract::switch_operator(&staker_signer, @operator, @new_operator, 10);
// ^ also always aborts

// Result: staker's APT is permanently locked in the stake pool.
```
