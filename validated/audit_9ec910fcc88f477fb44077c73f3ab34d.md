### Title
Users can be liquidated while `Pool.paused()` blocks collateral deposits, preventing position defense - (File: contracts/Pool.sol)

### Summary
`Pool.pause()` disables `DepositToken.deposit()` (via `whenNotPaused`), but `Pool.liquidate()` is only gated by `whenNotShutdown`. A user whose position becomes unhealthy while the pool is paused cannot add collateral to restore health, yet any liquidator can still seize their collateral.

### Finding Description
Metronome's `Pauseable` design gives `paused` and `everythingStopped` different scopes: `pause()` is documented to "suspend deposit feature" while `shutdown()` suspends "issue, repay, deposit, withdraw, liquidate and swap" [1](#0-0) . `docs/emergency-flags.md` confirms: `DepositToken.deposit()` is disabled by `Pool.paused()`, while `Pool.liquidate()` is only disabled by `Pool.everythingStopped()` [2](#0-1) . `Pool.liquidate` carries `whenNotShutdown` but no `whenNotPaused` [3](#0-2) , and the test suite explicitly verifies liquidation succeeds while paused ("should not revert if paused") [4](#0-3) . Meanwhile `DepositToken.deposit` reverts with `IsPaused` when the pool is paused [5](#0-4) . A holder of collateral tokens whose position crosses the collateral-factor threshold during a pause cannot top up their position; a liquidator needs only synth balance and calls `liquidate(syntheticToken_, account_, amountToRepay_, depositToken_)`, which passes the health check, burns the liquidator's synth, and seizes collateral plus liquidation fee [6](#0-5) .

### Impact Explanation
Users holding idle collateral (but insufficient synth balance to call `repay`) suffer forced seizures of collateral plus liquidation fees during a pause — liquidations that would have been avoided had deposits remained open. This is temporary inability to manage a position combined with direct loss of collateral to third-party liquidators.

### Likelihood Explanation
Pausing is an intended emergency response, likely invoked precisely during market stress — the same conditions that push positions below the collateral factor. The liquidator is fully unprivileged; only the pause itself requires the governor. Likelihood is bounded by how often pools are paused, hence Medium rather than High.

### Recommendation
Either block `liquidate` under `whenNotPaused`, or (preferably, matching the report's recommendation) keep deposits enabled while paused — i.e., remove `whenNotPaused` from `DepositToken.deposit` or introduce a separate `depositPaused` flag — so users can always add collateral to defend their positions.

### Proof of Concept
Fork test (Hardhat, extending `test/Pool.test.ts`):

```ts
// given: alice has an unhealthy position (met price dropped)
await masterOracle.updatePrice(met.address, toUSD('0.95'))
const { _isHealthy } = await pool.debtPositionOf(alice.address)
expect(_isHealthy).false

// when: governor pauses the pool (deposit-only pause, not shutdown)
await pool.pause()

// then: alice cannot deposit more collateral to defend the position
await met.connect(alice).approve(metDepositToken.address, MaxUint256)
await expect(
  metDepositToken.connect(alice).deposit(parseEther('100'), alice.address)
).revertedWithCustomError(metDepositToken, 'IsPaused')

// but: an unprivileged liquidator can still seize alice's collateral
const amountToRepay = await pool.quoteLiquidateMax(msEth.address, alice.address, msdMET.address)
await expect(
  pool.connect(liquidator).liquidate(msEth.address, alice.address, amountToRepay, msdMET.address)
).emit(pool, 'PositionLiquidated')
```

    function pause() external virtual whenNotPaused onlyGovernor {
        _paused = true;

        _paused = true;

**maxTotalSupply**: Supply cap. This cap impacts `issue` and `leverage` features. It doesn't impact `swap`.

**maxTotalSupply**: Supply cap. This cap impacts `deposit` feature.

**isActive**: If `false` deposit receipt mint is disabled. It will impact `deposit` feature. The `withdraw` continues working.
