### Title
Old-model TRON_POWER frozen balance is dropped and `TotalTronPowerWeight` left un-decremented on contract self-destruct - ([File: actuator/src/main/java/org/tron/core/vm/program/Program.java])

### Summary
When a smart contract account self-destructs (`SUICIDE`/`SUICIDE2`) while it has an old-model (`FreezeBalanceContract`, i.e. Freeze V1) frozen balance, `Program.java` migrates the frozen BANDWIDTH and ENERGY balances to the inheritor and correspondingly decrements `TotalNetWeight`/`TotalEnergyWeight`. However, unlike those two resource types, the old-model TRON_POWER frozen balance is never transferred, refunded, or subtracted from `TotalTronPowerWeight`. This is the same bug class as the reported issue: one supply/resource type ("Protocol Owned Treasury Ohm"/TRON_POWER) lacks the setter/adjustment logic that its sibling resource types have.

### Finding Description
`FreezeBalanceActuator` (old model) explicitly supports freezing TRX for `TRON_POWER` and increments `TotalTronPowerWeight` accordingly: [1](#0-0) 

When a contract self-destructs, `Program.suicide`/`suicide2` call `transferDelegatedResourceToInheritor` for the old (V1) freeze model: [2](#0-1) 

That method only handles BANDWIDTH and ENERGY frozen balances — it reads them, moves them to the inheritor's spendable balance, and decrements the corresponding total weights — but contains no branch at all for TRON_POWER: [3](#0-2) 

`clearOwnerFreeze`, called right after (only under `allowTvmSelfdestructRestriction`), also only clears bandwidth/energy freeze fields, leaving the TRON_POWER frozen field on the (soon to be deleted) account untouched: [4](#0-3) 

Additionally, the pre-suicide guard `freezeV1Check` (used by `canSuicide2`) checks only BANDWIDTH and ENERGY frozen/expire state and delegated balances — it never checks whether the account still has a nonzero old-model TRON_POWER frozen balance, so self-destruct is not blocked in that case: [5](#0-4) 

By contrast, the newer Freeze V2 model's equivalent transfer routine, `transferFrozenV2BalanceToInheritor`, correctly handles all three resource types including TRON_POWER when migrating frozen balances to the inheritor: [6](#0-5) 

This asymmetry mirrors the reported analog exactly: BANDWIDTH and ENERGY (like "protocolOwnedBorrowableOhm" and other tracked supply types) receive full setter/adjustment treatment on this code path, while TRON_POWER (like "protocolOwnedTreasuryOhm") is silently omitted.

### Impact Explanation
When the account is deleted (`getResult().addDeleteAccount(...)` / `markSelfDestruct`), its underlying `AccountCapsule` row — including the old-model TRON_POWER frozen amount — is removed from the account store without that value ever being added back to any account's spendable balance or to the inheritor, and without `TotalTronPowerWeight` being decremented via `repo.addTotalTronPowerWeight(...)`. This causes:
1. Permanent freezing/loss of the TRX that was frozen for TRON_POWER (nobody can ever unfreeze it, since the owning account no longer exists and the value was never routed anywhere).
2. A permanently unbacked/incorrect `TotalTronPowerWeight` global counter — it keeps counting weight for TRX that no longer corresponds to any live account's frozen balance, corrupting a chain-wide accounting value used for resource distribution.

This is reachable purely through a standard user-broadcast contract deployment + a `SUICIDE` opcode invocation, no privileged role required, and results in concrete permanent freezing of funds plus a corrupted global accounting value — squarely within the "permanent freezing of funds / unbacked balance" impact bucket.

### Likelihood Explanation
Requires: (1) `allowTvmFreeze` (old model) feature enabled, (2) `supportAllowNewResourceModel` enabled so `TRON_POWER` is an allowed resource for old-model freeze, and (3) a contract account that froze TRX for TRON_POWER via `FreezeBalanceContract`, then executes `SUICIDE`/`SUICIDE2`. All of these are legitimate, permissionless actions available to any deployer/caller once these chain parameters are on (as they are expected to be in a mature/parameterized network), making this reliably triggerable, not a contrived edge case.

### Recommendation
In `transferDelegatedResourceToInheritor` (and in `clearOwnerFreeze`), add the same handling used for BANDWIDTH/ENERGY to TRON_POWER: read `ownerCapsule.getTronPowerFrozenBalance()`, add it to the amount transferred to the inheritor's balance, decrement `TotalTronPowerWeight` via `repo.addTotalTronPowerWeight(...)`, and clear the owner's TRON_POWER frozen field. Also update `freezeV1Check` to reject self-destruct (or otherwise force-settle) when the account still has an unexpired old-model TRON_POWER frozen balance, mirroring the BANDWIDTH/ENERGY checks.

### Proof of Concept
1. Enable `allowTvmFreeze` and `supportAllowNewResourceModel` (both are configurable via proposal/committee parameters and, once active for the network, are usable by any account).
2. Deploy a contract account and, using a `FreezeBalanceContract` transaction with `resource = TRON_POWER`, freeze TRX from the contract account (as in `FreezeBalanceActuator`, case `TRON_POWER`), which increases `TotalTronPowerWeight`: [1](#0-0) 
3. Trigger the contract's `SUICIDE`/`SUICIDE2` opcode. `Program.suicide`/`suicide2` invoke `transferDelegatedResourceToInheritor`, which only migrates BANDWIDTH/ENERGY frozen balances and weights: [7](#0-6) 
4. Observe that after the transaction: the contract account row is deleted; the inheritor's balance increase excludes the TRON_POWER frozen amount; and `DynamicPropertiesStore.getTotalTronPowerWeight()` (unlike `TotalNetWeight`/`TotalEnergyWeight`) is unchanged, i.e., still counts the now-nonexistent account's frozen TRON_POWER weight — the frozen TRX is permanently unaccounted for and unrecoverable.

  private void transferDelegatedResourceToInheritor(byte[] ownerAddr, byte[] inheritorAddr, Repository repo) {

    // delegated resource from sender to owner, just abandon
    // in order to making that sender can unfreeze their balance in future
    // nothing will be deleted

    // delegated resource from owner to receiver
    // there cannot be any resource when suicide

    AccountCapsule ownerCapsule = repo.getAccount(ownerAddr);

    // transfer owner`s frozen balance for bandwidth to inheritor
    long frozenBalanceForBandwidthOfOwner = 0;
    // check if frozen for bandwidth exists
    if (ownerCapsule.getFrozenCount() != 0) {
      frozenBalanceForBandwidthOfOwner = ownerCapsule.getFrozenList().get(0).getFrozenBalance();
    }
    repo.addTotalNetWeight(-frozenBalanceForBandwidthOfOwner / TRX_PRECISION);

    long frozenBalanceForEnergyOfOwner =
        ownerCapsule.getAccountResource().getFrozenBalanceForEnergy().getFrozenBalance();
    repo.addTotalEnergyWeight(-frozenBalanceForEnergyOfOwner / TRX_PRECISION);

    // transfer all kinds of frozen balance to BlackHole
    repo.addBalance(inheritorAddr, frozenBalanceForBandwidthOfOwner + frozenBalanceForEnergyOfOwner);

    if (VMConfig.allowTvmSelfdestructRestriction()) {
      clearOwnerFreeze(ownerCapsule);
      repo.updateAccount(ownerAddr, ownerCapsule);
    }
  }

  private long transferFrozenV2BalanceToInheritor(byte[] ownerAddr, byte[] inheritorAddr, Repository repo) {
    AccountCapsule ownerCapsule = repo.getAccount(ownerAddr);
    AccountCapsule inheritorCapsule = repo.getAccount(inheritorAddr);
    long now = repo.getHeadSlot();

    // transfer frozen resource
    ownerCapsule.getFrozenV2List().stream()
        .filter(freezeV2 -> freezeV2.getAmount() > 0)
        .forEach(
            freezeV2 -> {
              switch (freezeV2.getType()) {
                case BANDWIDTH:
                  inheritorCapsule.addFrozenBalanceForBandwidthV2(freezeV2.getAmount());
                  break;
                case ENERGY:
                  inheritorCapsule.addFrozenBalanceForEnergyV2(freezeV2.getAmount());
                  break;
                case TRON_POWER:
                  inheritorCapsule.addFrozenForTronPowerV2(freezeV2.getAmount());
                  break;
              }
            });

  private boolean freezeV1Check(AccountCapsule accountCapsule) {
    if (!VMConfig.allowTvmFreeze()) {
      return true;
    }

    // check freeze
    long now = getContractState().getDynamicPropertiesStore().getLatestBlockHeaderTimestamp();
    // bandwidth
    if (accountCapsule.getFrozenCount() > 0
        && accountCapsule.getFrozenList().stream()
        .anyMatch(frozen -> frozen.getExpireTime() > now)) {
      return false;
    }
    // energy
    Protocol.Account.Frozen frozenEnergy =
        accountCapsule.getAccountResource().getFrozenBalanceForEnergy();
    if (frozenEnergy.getFrozenBalance() > 0 && frozenEnergy.getExpireTime() > now) {
      return false;
    }

    // check delegate
    return accountCapsule.getDelegatedFrozenBalanceForBandwidth() == 0
        && accountCapsule.getDelegatedFrozenBalanceForEnergy() == 0;
  }
