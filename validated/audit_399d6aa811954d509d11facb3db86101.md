### Title
Prefix-only quarantine-directory check allows `GitObjectDirectory` to escape the intended quarantine path - (File: internal/git/localrepo/paths.go)

### Summary
`Repo.ObjectDirectoryPath` (used whenever Gitaly resolves the effective object directory for a repository, including quarantined pushes) validates a client/RPC-supplied `GitObjectDirectory` value with `storage.ValidateRelativePath`, but when that first validation fails it falls back to a bare `strings.HasPrefix` string comparison against the expected quarantine directory instead of a boundary-safe path check. This is the same class of bug as the reported issue: a value is checked once, but the actual value used afterwards is not re-validated with the same rigor, so the "final" path used can diverge from what was verified — analogous to slippage being checked before fee deduction changes the real value paid out.

### Finding Description
`ObjectDirectoryPath` in [1](#0-0)  first tries `storage.ValidateRelativePath(storagePath, filepath.Join(repoPath, objectDirectoryPath))`. If that check fails (i.e., the object directory is not inside the repo's own object tree, which is expected for quarantine directories created outside the repo), the code falls into a secondary branch that computes an `expectedQuarantinePrefix` and does:

```go
absoluteObjectDirectoryPath := filepath.Join(repoPath, objectDirectoryPath)
if !strings.HasPrefix(absoluteObjectDirectoryPath, expectedQuarantinePrefix) {
    return "", structerr.NewInvalidArgument("not a valid relative path: %w", origError)
}
``` [2](#0-1) 

`strings.HasPrefix` is a raw string comparison, not a path-boundary-aware check. Any `objectDirectoryPath` whose joined absolute path *textually* begins with `expectedQuarantinePrefix` passes, even if the full string continues into an unrelated sibling directory (e.g. `expectedQuarantinePrefix + "-evil/../../../etc"` or `expectedQuarantinePrefix + "somethingelse"`), because `HasPrefix` has no separator-boundary requirement. Once this second check passes, `fullPath := filepath.Join(repoPath, objectDirectoryPath)` is computed again from the *original, unvalidated-by-boundary* `objectDirectoryPath` and returned as the trusted object directory for the repository — this path is subsequently wired into `GIT_OBJECT_DIRECTORY`/`GIT_ALTERNATE_OBJECT_DIRECTORIES` for spawned Git subprocesses (per the quarantine mechanism described in [3](#0-2) ), meaning arbitrary filesystem locations sharing the string prefix could be treated as the repository's authoritative object directory.

This is the analog of the reported bug: the check (`HasPrefix`) is performed on a computed value, but the value actually used later (`fullPath`, rebuilt from the same unbounded `objectDirectoryPath`) is not re-derived from the validated/clamped result the way `ValidateRelativePath` does (which returns a `filepath.Rel`-clamped, canonicalized value). The check and the used value are not tied together with the same invariant, exactly like the slippage check being evaluated on `price` while the money actually transferred is `price - fees`.

`GitObjectDirectory`/`GitAlternateObjectDirectories` are attacker-influenceable fields on the `Repository` proto (set during git push quarantine flows and propagated through Rails' internal API back into Gitaly RPC calls, as documented in [4](#0-3) ), making this reachable from an ordinary push-driven code path rather than requiring a privileged actor.

### Impact Explanation
If the prefix-only check can be satisfied by a value that still escapes the intended quarantine root (e.g., a sibling directory with a matching string prefix, since real quarantine dirs from `git-receive-pack` have no separator between the prefix and the `-incoming-XXXX`/`tmp_objdir-` suffix, the code intentionally omits the separator requirement), a crafted `GitObjectDirectory` could point Git object resolution at a directory outside the transaction's true quarantine scope. This could allow cross-repository or cross-tenant object visibility/injection during hook execution (pre-receive/access-check RPCs see objects from the wrong quarantine), a storage escape via the object search path, and violates the intended isolation the quarantine mechanism guarantees (see [5](#0-4) ).

### Likelihood Explanation
Moderate. The relevant fields are exercised on every push (`git-receive-pack`) and are set programmatically by Gitaly/quarantine helpers under normal conditions [6](#0-5) , but the same `Repository.GitObjectDirectory` field is also accepted directly from gRPC `Repository` messages passed through internal API calls, giving an ordinary authenticated push/hook flow a path to influence the value. Exploitation requires crafting a directory name that both matches the expected prefix textually and contains a meaningful traversal/target beyond it, which is a non-trivial but concrete constraint (not purely theoretical, since existing tests in `paths_test.go` already probe several traversal permutations around this exact code path [7](#0-6) , none of which cover a same-prefix/sibling-escape case).

### Recommendation
Replace the `strings.HasPrefix(absoluteObjectDirectoryPath, expectedQuarantinePrefix)` check with a boundary-safe comparison equivalent to `storage.ValidateRelativePath`, e.g. verify that `absoluteObjectDirectoryPath` equals `expectedQuarantinePrefix` or has `expectedQuarantinePrefix + os.PathSeparator` as a prefix, and additionally re-derive `fullPath` from the validated/cleaned relative path rather than re-joining the raw, client-supplied `objectDirectoryPath`.

### Proof of Concept
1. An ordinary push triggers Gitaly's quarantine flow, which sets `Repository.GitObjectDirectory` on the RPC message used for subsequent hook/access-check calls.
2. Craft/replay an RPC request (e.g., via the internal API round-trip described in `doc/object_quarantine.md`) with `GitObjectDirectory` set to a value whose absolute-path form is `expectedQuarantinePrefix` followed immediately (no separator) by attacker-chosen text that ultimately resolves outside the true quarantine directory once joined and used by Git (e.g., `<prefix>-outside/../../../elsewhere`).
3. `ObjectDirectoryPath` computes `expectedQuarantinePrefix` from `storage.QuarantineDirectoryPrefix(repo)` and checks only `strings.HasPrefix`, which the crafted value satisfies.
4. `fullPath` is rebuilt via `filepath.Join(repoPath, objectDirectoryPath)` from the same unbounded string and returned as trusted; Git subprocesses spawned afterward use this path as the object directory, potentially exposing or accepting objects from outside the intended quarantine scope.

// ObjectDirectoryPath returns the full path of the object directory. The errors returned are gRPC
// errors with relevant error codes and should be passed back to gRPC without further decoration.
func (repo *Repo) ObjectDirectoryPath(ctx context.Context) (string, error) {
	repoPath, err := repo.Path(ctx)
	if err != nil {
		return "", err
	}

	objectDirectoryPath := repo.GetGitObjectDirectory()
	if objectDirectoryPath == "" {
		return "", structerr.NewInvalidArgument("object directory path is not set")
	}

	storagePath, err := repo.locator.GetStorageByName(ctx, repo.GetStorageName())
	if err != nil {
		return "", fmt.Errorf("get storage by name: %w", err)
	}

	// Ensure the path points somewhere in the storage.
	relativeObjectDirectoryPath, err := storage.ValidateRelativePath(storagePath, filepath.Join(repoPath, objectDirectoryPath))
	if err != nil {
		return "", structerr.NewInvalidArgument("validate relative path: %w", err)
	}

	parentDir := filepath.Base(filepath.Dir(relativeObjectDirectoryPath))
	baseDir := filepath.Base(relativeObjectDirectoryPath)
	isTransactionQuarantineDir := (baseDir == "quarantine") || ((parentDir == "quarantine") && strings.HasPrefix(baseDir, "tmp_objdir"))

	// Transactions quarantine a repository by pointing the object directory to a 'quarantine' named
	// directory in the transaction's temporary directory. If the base directory is `quarantine`,
	// Git push may apply an additional layer of quarantine such as `/quarantine/tmp_objdir-incoming-Gbc29N`
	// so we don't assert the `/quarantine` being the last element of the path. We thus also check for
	// whether the parent directory is in `quarantine` and whether the base directory has the expected
	// `tmp_objdir` suffix.
	if !isTransactionQuarantineDir {
		// We need to check whether the relative object directory as given by the repository is
		// a valid path. This may either be a path in the Git repository itself, where it may either
		// point to the main object directory storage or to an object quarantine directory as
		// created by git-receive-pack(1). Alternatively, if that is not the case, then it may be a
		// manual object quarantine directory located in the storage's temporary directory. These
		// have a repository-specific prefix which we must check in order to determine whether the
		// quarantine directory does in fact belong to the repo at hand.
		if _, origError := storage.ValidateRelativePath(repoPath, objectDirectoryPath); origError != nil {
			tempDir, err := repo.locator.TempDir(repo.GetStorageName())
			if err != nil {
				return "", structerr.NewInvalidArgument("getting storage's temporary directory: %w", err)
			}

			expectedQuarantinePrefix := filepath.Join(tempDir, storage.QuarantineDirectoryPrefix(repo))
			absoluteObjectDirectoryPath := filepath.Join(repoPath, objectDirectoryPath)

			// The relative path is outside of the repository
			if !strings.HasPrefix(absoluteObjectDirectoryPath, expectedQuarantinePrefix) {
				return "", structerr.NewInvalidArgument("not a valid relative path: %w", origError)
			}
		}
	}

	fullPath := filepath.Join(repoPath, objectDirectoryPath)
	if _, err := os.Stat(fullPath); os.IsNotExist(err) {
		return "", structerr.NewNotFound("object directory does not exist: %q", fullPath)
	}

	return fullPath, nil
}
