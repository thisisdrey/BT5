### Title
Out-of-Bounds Slice Access When Parsing Attacker-Supplied Reftable Blocks During Repository Snapshot Import - (File: internal/git/reftable/reftable.go)

### Summary
`CreateRepositoryFromSnapshot` and the equivalent `ReplicateRepository`/`createFromSnapshot` flow extract an entire TAR archive (fetched over HTTP, or streamed from a peer via `GetSnapshot`) directly on top of a newly initialized repository, including whatever files reside under the `reftable/` directory [1](#0-0) [2](#0-1) . The code comment explicitly acknowledges the trust problem: *"the received archive is trusted a lot"* [3](#0-2) . Once such a repository is created, any subsequent RPC that reads references from the reftable backend (`ParseTable`/`GetReferences`) parses attacker-controlled `.ref` files with essentially no bounds checking of length/offset fields taken directly from the file — the same bug class as the reported `SparseMerkleProof.verifyProof` missing length check that leads to out-of-bounds array access.

### Finding Description
The reftable block parser computes byte offsets and lengths purely from data embedded in the file and indexes `src` (a `[]byte` holding the entire table) without validating that the computed indices stay within `len(src)`:

- `extractBlockLen` reads `src[blockStart+1 : blockStart+4]` with no check that `blockStart+4 <= len(src)` [4](#0-3) .
- `getVarInt` only bounds-checks against a caller-supplied `blockEnd`, but the very first read `src[start]` inside the function (before any check) can already be out of range if `start` was miscomputed elsewhere [5](#0-4) .
- `getRefsFromBlock` computes `suffixLength`/`hashSize` from the file and slices `src[idx:idx+suffixLength]` and `src[idx:idx+uint(hashSize)]` with no check that `idx+suffixLength` or `idx+hashSize` is `<= len(src)` [6](#0-5) .
- `parseRefBlock` computes `b.RestartStart = blockStart + currentBS - 2 - 3*uint(b.RestartCount)`, where `currentBS` comes from `extractBlockLen` (attacker controlled) and `RestartCount` is read from `src[blockStart+currentBS-2:]` — if `currentBS` is small or zero, `blockStart+currentBS-2` can underflow (uint arithmetic) or point outside `src`, causing an out-of-bounds `binary.Read`/slice panic [7](#0-6) .

This exactly mirrors the reported vulnerability class: the code trusts a length/offset field taken from untrusted input and indexes into a slice without first validating that the length matches the expected/available bounds (in the original report, `TREE_DEPTH` vs. `_rawProof.length`; here, computed block offsets vs. `len(src)`).

### Impact Explanation
A Go slice index/subslice operation whose bounds exceed the underlying array causes a runtime panic (`slice bounds out of range` / `index out of range`). Because these functions are invoked while reading references from a reftable-backed repository (e.g., `GetReferences`, called from ref-listing code paths built on `internal/gitaly/storage/storagemgr/partition/reftable.go`), a repository created from a maliciously crafted snapshot can cause any subsequent RPC that reads its refs to panic. Depending on whether the gRPC panic-recovery middleware (`internal/grpc/middleware/panichandler`) intercepts the panic, this results in a failed RPC (per-request DoS) or, in code paths not wrapped by the panic handler (e.g., background/maintenance goroutines that read refs), it could crash the `gitaly` process, denying service to all repositories served by that node.

### Likelihood Explanation
`CreateRepositoryFromSnapshot` is a `MUTATOR` RPC that takes an attacker-influenced `http_url`/`resolved_address` and fetches an arbitrary TAR stream over HTTP [8](#0-7) ; nothing validates the contents of files placed under `reftable/` before they are later parsed. Likelihood is moderate: it requires the operator to trigger `CreateRepositoryFromSnapshot`/`ReplicateRepository` against a source under attacker influence (a scenario the code authors themselves flag as insufficiently hardened), but no privileged access, leaked token, or MITM is required — a caller with access to this RPC and control over the snapshot content is sufficient, which fits the "ordinary user's ... import" trigger category.

### Recommendation
Add explicit bounds checks before every slice operation in `internal/git/reftable/reftable.go` that depends on file-derived offsets/lengths:
- In `extractBlockLen`, verify `blockStart+4 <= len(src)` before indexing.
- In `getVarInt`, verify `start < len(src)` (in addition to `blockEnd`) before reading `src[start]`.
- In `getRefsFromBlock`, after computing `prefixLength`, `suffixLength`, and `hashSize`, verify `idx+suffixLength <= len(src)` and `idx+hashSize <= len(src)` (and `prefixLength <= len(prefix)`) before slicing, returning a parse error otherwise.
- In `parseRefBlock`, validate that `currentBS >= 2+3*uint(b.RestartCount)` and that `blockStart+currentBS <= len(src)`/`blockEnd` before computing `RestartStart`, to prevent unsigned-integer underflow and out-of-range reads.
Treat any such violation as a corrupt/malicious table and return an error instead of panicking, consistent with how `internal/git/mvcc/manifest.go` validates chunk offsets against `len(data)` before use [9](#0-8) .

### Proof of Concept
1. Create a source repository using the reftable backend, obtain a legitimate snapshot via `GetSnapshot`/tar export.
2. Modify the `reftable/*.ref` file inside the tar so that a ref block declares a `suffixLength` or `hashSize`-derived offset that extends beyond the end of the block/file (e.g., set the varint-encoded suffix length far larger than the remaining bytes in the block), or set the block's length byte(s) read by `extractBlockLen` to a very small value so that `parseRefBlock`'s `RestartStart` computation underflows.
3. Serve this modified tar from an HTTP endpoint and call `CreateRepositoryFromSnapshot` with `http_url` pointing at it (or supply it as the source in `ReplicateRepository`).
4. Once the repository is created, invoke any RPC that reads references from the reftable table (e.g., `ListRefs`/internal reftable read path calling `Table.GetReferences`) — parsing the crafted block triggers a Go slice-bounds panic in `getRefsFromBlock`/`parseRefBlock`, consistent with the missing-length-validation bug class described in the source report.

func (s *server) extractSnapshot(ctx context.Context, source, target *gitalypb.Repository) error {
	repoClient, err := s.newRepoClient(ctx, source.GetStorageName())
	if err != nil {
		return fmt.Errorf("new client: %w", err)
	}

	stream, err := repoClient.GetSnapshot(ctx, &gitalypb.GetSnapshotRequest{Repository: source})
	if err != nil {
		return fmt.Errorf("get snapshot: %w", err)
	}

	// We need to catch a possible 'invalid repository' error from GetSnapshot. On an empty read,
	// we read the first message from the stream here to get access to the possible 'invalid repository' error.
	firstBytes, err := stream.Recv()
	if err != nil {
		switch {
		case structerr.GRPCCode(err) == codes.NotFound && strings.Contains(err.Error(), "GetRepoPath: not a git repository:"):
			// The error condition exists for backwards compatibility purposes, only,
			// and can be removed in the next release.
			return ErrInvalidSourceRepository
		case structerr.GRPCCode(err) == codes.NotFound && strings.Contains(err.Error(), storage.ErrRepositoryNotFound.Error()):
			return ErrInvalidSourceRepository
		case structerr.GRPCCode(err) == codes.FailedPrecondition && strings.Contains(err.Error(), storage.ErrRepositoryNotValid.Error()):
			return ErrInvalidSourceRepository
		default:
			return fmt.Errorf("first snapshot read: %w", err)
		}
	}

	snapshotReader := io.MultiReader(
		bytes.NewReader(firstBytes.GetData()),
		streamio.NewReader(func() ([]byte, error) {
			resp, err := stream.Recv()
			return resp.GetData(), err
		}),
	)

	targetPath, err := s.locator.GetRepoPath(ctx, target, storage.WithRepositoryVerificationSkipped())
	if err != nil {
		return fmt.Errorf("target path: %w", err)
	}

	// Extract tar using Go's tar package
	if err := s.extractTarToDirectory(ctx, snapshotReader, targetPath); err != nil {
		return fmt.Errorf("extract tar: %w", err)
	}

	return nil
}

func (t *Table) getVarInt(src []byte, start uint, blockEnd uint) (uint, uint, error) {
	var val uint

	val = uint(src[start]) & 0x7f

	for (uint(src[start]) & 0x80) > 0 {
		start++
		if start > blockEnd {
			return 0, 0, fmt.Errorf("exceeded block length")
		}

		val = ((val + 1) << 7) | (uint(src[start]) & 0x7f)
	}

	return start + 1, val, nil
}

func (t *Table) parseRefBlock(src []byte, headerOffset, blockStart, blockEnd uint) ([]git.Reference, error) {
	currentBS := t.extractBlockLen(src, blockStart+headerOffset)

	fullBlockSize := t.blockSize
	if fullBlockSize == 0 {
		fullBlockSize = currentBS
	} else if currentBS < fullBlockSize && currentBS < (blockEnd-blockStart) && src[blockStart+currentBS] != 0 {
		fullBlockSize = currentBS
	}

	b := &block{
		BlockStart:    blockStart + headerOffset,
		FullBlockSize: fullBlockSize,
	}

	if err := binary.Read(bytes.NewBuffer(src[blockStart+currentBS-2:]), binary.BigEndian, &b.RestartCount); err != nil {
		return nil, fmt.Errorf("reading restart count: %w", err)
	}

	b.RestartStart = blockStart + currentBS - 2 - 3*uint(b.RestartCount)

	return t.getRefsFromBlock(src, b)
