### No vulnerability found for this question.

**Analysis:** The `token_fee` exemption is evaluated independently for each `(token_id, delta)` pair inside the `for` loop in `TokenDiff::execute_intent`, not once globally for the whole diff. [1](#0-0)  For each token in the diff with a negative delta, the fee is `Self::token_fee(token_id, amount, protocol_fee).fee_ceil(amount)`, where `token_id` and `amount` are that specific token's own id and its own delta magnitude. [2](#0-1) 

`token_fee` itself matches on the `TokenIdType` derived from the passed-in `token_id`: the zero-fee exemption only triggers for `Nep171`/`Nep245`/`Imt` types when that token's own `amount <= 1`. `Nep141` (FT) tokens always fall through to the full `fee`, regardless of what other tokens/deltas exist in the same `TokenDiff`. [3](#0-2) 

So batching a `Nep245TokenId` delta of `-1` (which is exempt on its own leg) together with a large FT delta of `-N` in the same `TokenDiff` has no effect on the FT leg's fee calculation — the loop computes `token_fee` and `fee_ceil` separately per token, keyed strictly by that token's own `TokenIdType` and its own `amount`. The FT leg's fee is `protocol_fee.fee_ceil(N)` exactly, unaffected by the presence of the NFT leg, matching `test_ft_diffs`/`swap_many`/`swap_p2p` style tests that verify per-token fee closures independently. [4](#0-3) 

There is no cross-token state shared in `token_fee` or in the fee-collection loop that could let the NFT leg's exemption "leak" into the FT leg's fee computation, so the claimed binding violation (fee owed on the FT leg ≠ fee collected) does not occur.

    pub fn token_fee(token_id: impl Into<TokenIdType>, amount: u128, fee: Pips) -> Pips {
        let token_id = token_id.into();
        match token_id {
            TokenIdType::Nep141 => {}
            TokenIdType::Nep245 | TokenIdType::Imt if amount > 1 => {}
            // do not take fees on NFTs and MTs with |delta| <= 1
            TokenIdType::Nep171 | TokenIdType::Nep245 | TokenIdType::Imt => return Pips::ZERO,
        }
        fee
    }
