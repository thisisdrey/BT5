### Title
Bad-debt `socialize-debt` write-down mixes accrued interest into the loss amount used to devalue LP shares (`lindex`) - (File: `mainnet/contracts/vault/v0-vault-sbtc.clar` and sibling vaults)

### Summary
The reported LoopFi bug (`CDPVault::liquidatePositionBadDebt`) computed `loss = totalDebt (principal + accruedInterest) − repayAmount` instead of `loss = principal − repayAmount`, incorrectly treating unrealized interest as a realized loss and over-burning protocol reserves. The Zest vault contracts contain a structurally identical mixing of principal and accrued-interest amounts inside `socialize-debt`, where the index-based write-down of the LP share value (`lindex`) is driven by the *full* interest-inclusive debt amount while the actual asset ledger (`assets`/`total-borrowed`) is only reduced by the *principal* portion.

### Finding Description
`socialize-debt` is called from every market's bad-debt path (`socialize-debt-asset` in `market.clar`/`v0-4-market.clar`, invoked from `liquidate` when a position has no collateral left) [1](#0-0) . Inside the vault, it computes:

```
(debt-reduction (mul-div-down scaled-amount idx INDEX-PRECISION))
(principal-reduction (if (> scaled-principal u0)
                        (mul-div-down scaled-amount borrowed scaled-principal)
                        u0))
(new-lindex (if (and (> old-total-assets u0) (> old-total-assets debt-reduction))
               (mul-div-down current-lindex (- old-total-assets debt-reduction) old-total-assets)
               u0))
``` [2](#0-1) 

`debt-reduction` is computed from `idx` (the current borrow index), i.e. it is the *full* outstanding amount including any interest that has accrued on the scaled principal since the last accrual — mirroring `calcTotalDebt() = debt.debt + debt.accruedInterest` in the C4 report. `principal-reduction`, by contrast, is only the pro-rata share of `total-borrowed` (the original principal), analogous to `debtData.debt` in the LoopFi code. The write-down of `lindex` — the index used to price LP shares against `old-total-assets` — is scaled by the full `debt-reduction`/`old-total-assets` ratio, while the only quantity actually deducted from the ledger (`assets`, `total-borrowed`) is the smaller `principal-reduction` [3](#0-2) .

This is the exact analog of the reported bug: the interest portion of the written-off debt (which the vault never actually held as real assets — it is future/unrealized yield) is folded into the amount used to compute the loss/write-down ratio applied against real `old-total-assets`, over-penalizing the LP share price (`lindex`) beyond the true principal loss. As in the LoopFi finding, this understates realized profit/overstates loss and causes LP depositors to absorb a write-down larger than the actual principal shortfall, since a chunk of the "loss" being socialized was interest that was never collected into `assets` in the first place.

The bug path is reachable by any unprivileged caller: bad-debt socialization is triggered automatically inside the permissionless `liquidate` entry point whenever the borrower's remaining collateral hits zero [4](#0-3) , with no special caller checks other than the general liquidation preconditions.

### Impact Explanation
`lindex` governs the exchange rate between vault shares and underlying assets for all depositors (`total-assets`/withdraw/redeem accounting). Over-writing it down using an interest-inclusive amount permanently understates the redeemable value of every LP share in the pool beyond the actual principal loss, i.e. depositors as a whole lose more real value than the bad debt actually cost the protocol. This is a permanent, protocol-wide mispricing of vault shares triggered on every bad-debt liquidation, which falls under "protocol insolvency" / permanent loss of user (depositor) funds at rest.

### Likelihood Explanation
Bad-debt socialization is a normal, expected path whenever a borrower's position is fully liquidated with zero remaining collateral and unpaid debt — no special privileges or economic setup are required beyond a naturally occurring undercollateralized position, so the flawed write-down triggers routinely under standard liquidation conditions across all six vaults (`v0-vault-sbtc`, `v0-vault-ststx`, `v0-vault-ststxbtc`, `v0-vault-stx`, `v0-vault-usdc`, `v0-vault-usdh`).

### Recommendation
Separate the interest and principal components in `socialize-debt`: compute the write-down ratio applied to `lindex` using only `principal-reduction` (the actual asset loss), not `debt-reduction` (which includes accrued-but-unrealized interest). Track/forgive the interest portion (`debt-reduction - principal-reduction`) as forgone future yield rather than realized loss against `old-total-assets`.

### Proof of Concept
1. Borrower accrues debt such that `scaled-principal` corresponds to principal `P` but current index `idx` inflates the scaled debt to `P + I` (interest `I`) — i.e., `debt-reduction = P + I` while `total-borrowed` (real principal ledger) still only reflects `P`.
2. Borrower's collateral is fully seized in `liquidate`, triggering `socialize-debt-asset` → `vault-socialize-debt` with `scaled-amount` equal to the borrower's full scaled debt [5](#0-4) .
3. In `socialize-debt`, `debt-reduction = P + I` is used to shrink `lindex` proportionally to `old-total-assets`, while only `principal-reduction ≈ P` is deducted from `assets`/`total-borrowed` [6](#0-5) .
4. Every LP share's redeemable value (via `lindex`) is now devalued by the ratio `(P+I)/old-total-assets` instead of the correct `P/old-total-assets`, permanently under-crediting all depositors by the interest amount `I` that was never actually part of `old-total-assets` to begin with.

(define-public (socialize-debt (scaled-amount uint))
  (let ((scaled-principal (var-get principal-scaled))
        (borrowed (var-get total-borrowed))
        (idx (var-get index))
        (current-assets (var-get assets))
        (current-lindex (var-get lindex))
        (old-total-assets (total-assets))
        (debt-reduction (mul-div-down scaled-amount idx INDEX-PRECISION))
        (principal-reduction (if (> scaled-principal u0)
                                (mul-div-down scaled-amount borrowed scaled-principal)
                                u0))
        ;; Write down lindex proportionally to loss in total-assets
        (new-lindex (if (and (> old-total-assets u0) (> old-total-assets debt-reduction))
                       (mul-div-down current-lindex (- old-total-assets debt-reduction) old-total-assets)
                       u0)))

    (try! (check-caller-auth))
    (asserts! (> scaled-amount u0) ERR-AMOUNT-ZERO)

    (var-set lindex new-lindex)
    (var-set principal-scaled (if (> scaled-principal scaled-amount) (- scaled-principal scaled-amount) u0))
    (var-set total-borrowed (if (> borrowed principal-reduction) (- borrowed principal-reduction) u0))
    (var-set assets (if (> current-assets principal-reduction) (- current-assets principal-reduction) u0))
