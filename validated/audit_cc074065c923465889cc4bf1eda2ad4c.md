### Title
Downgraded low-stake peers retain pubkey-keyed connection-table entries, bypassing the per-IP unstaked connection cap - ([File: streamer/src/nonblocking/swqos.rs])

### Finding Description
`SwQos::build_connection_context` (streamer/src/nonblocking/swqos.rs:302-342) computes `stake_ratio = stake / total_stake` and, when `stake_ratio < min_stake_ratio`, sets `peer_type = ConnectionPeerType::Unstaked` while leaving `remote_pubkey: Some(pubkey)` unchanged (lines 318-339). The connection is then routed into `try_add_connection`'s `ConnectionPeerType::Unstaked` branch (lines 415-438), which calls `prune_unstaked_connections_and_add_new_connection` against the single shared `self.unstaked_connection_table`, bounded globally by `self.config.max_unstaked_connections`.

Inside `cache_new_connection` (lines 205-219), the per-peer cap (`max_connections_per_unstaked_peer`) is enforced via `ConnectionTable::try_add_connection` keyed by `ConnectionTableKey::new(remote_addr.ip(), conn_context.remote_pubkey)` (line 211). For a genuinely unstaked client (no cert stake match), `get_connection_stake` returns `None`, so `remote_pubkey` is `None`, and the table key collapses to IP-only — meaning all connections from that IP share one per-peer bucket and are capped by `max_connections_per_unstaked_peer`. For a downgraded low-stake staked peer, `remote_pubkey` remains `Some(pubkey)`, so the key is `(ip, Some(pubkey))`. A single IP presenting many distinct low-stake pubkeys therefore obtains a distinct per-peer bucket for each pubkey, each independently allowed up to `max_connections_per_unstaked_peer` connections, rather than being limited to one IP-wide bucket like a genuinely unstaked client. All of these entries still draw from and count toward the same shared `unstaked_connection_table`/`max_unstaked_connections` global capacity, so a small number of IPs rotating through many low-stake keys can consume a share of the shared unstaked pool proportional to the number of distinct pubkeys used, rather than being capped to one IP's fair share (`max_connections_per_unstaked_peer`) as a genuinely-unstaked peer is.

I was not able to inspect the full body of `ConnectionTable::try_add_connection`/`ConnectionTableKey` in `streamer/src/nonblocking/quic.rs` within the available tool budget to confirm the exact per-key counting semantics; the analysis above is based on the call signature, key construction at swqos.rs:211/481, and the field naming (`max_connections_per_peer`). This should be independently verified by reading `streamer/src/nonblocking/quic.rs`'s `ConnectionTable` implementation before treating this as fully confirmed.

### Impact Explanation
If confirmed, this allows an attacker who controls several low-stake identities (stake below `min_stake_ratio`, obtainable via ordinary permissionless stake delegation) but only a few source IPs to consume a disproportionate fraction of the shared unstaked connection/stream QoS budget, at the expense of genuinely unstaked clients sharing the same pool, up to the global `max_unstaked_connections`/`QUIC_MAX_UNSTAKED_CONCURRENT_STREAMS` bound. This is a QoS-evasion / fair-share bypass rather than a total budget increase, since the shared table's global cap is unaffected.

### Likelihood Explanation
Exploitation requires the attacker to hold multiple on-chain low-stake identities (each below the `min_stake_ratio` heuristic) reachable from a small set of IPs, and to open concurrent QUIC connections presenting each identity's certificate. Obtaining minimal delegated stake is a low-cost, permissionless action, making this feasible for a motivated attacker, though it is not a zero-cost pure network-only attack like a fully unstaked flood.

### Recommendation
When downgrading a low-stake staked peer to `ConnectionPeerType::Unstaked` in `build_connection_context`, also clear `remote_pubkey` to `None` (or otherwise key downgraded connections by IP only) so that the per-peer connection cap for the unstaked table is enforced per source IP rather than per pubkey, matching the treatment of genuinely unstaked clients.

### Proof of Concept
Integration test plan in `streamer/src/nonblocking/swqos.rs` test module:
1. Configure `SwQosConfig::default_for_tests()` (`max_connections_per_unstaked_peer = 1`) and a `StakedNodes` map with `total_stake` large and N distinct pubkeys each with stake such that `stake/total_stake < min_stake_ratio`.
2. Simulate N connections from the same source IP, each presenting one of the N distinct low-stake pubkeys, calling `build_connection_context` then `try_add_connection`.
3. Assert all N connections are accepted into `unstaked_connection_table` (i.e., `unstaked_connection_table.total_size == N`), exceeding what a single genuinely-unstaked IP (pubkey `None`) would be allowed (`max_connections_per_unstaked_peer == 1`).
4. Contrast with a control case: N connections from the same IP with `remote_pubkey = None` (genuinely unstaked), asserting only 1 is accepted, confirming the discrepancy in enforced per-IP capacity.
