### Title
QUIC/SWQoS Connection Stake Snapshot Is Frozen At Handshake Time, Never Re-Evaluated For The Life Of The Connection - (File: streamer/src/nonblocking/swqos.rs)

### Summary
The external report describes a "spot value at settlement time" bug: a reward is computed once, using whatever value happens to be true at that instant, and that fixed value is then applied to a duration over which the underlying value actually fluctuated, letting a user lock in a favorable rate that no longer reflects reality. The closest reachable analog in the unprivileged QUIC/UDP streamer path is Agave's stake-weighted QoS (`SwQos`), which derives a peer's stake/`total_stake` exactly once when the QUIC connection is opened, via `build_connection_context` → `get_connection_stake`, and then uses that frozen snapshot for the entire lifetime of the connection to size stream and throughput allowances.

### Finding Description
`get_connection_stake` reads the current `StakedNodes` map once and returns `(pubkey, stake, total_stake)`: [1](#0-0) 

`SwQos::build_connection_context` calls this exactly once, at connection establishment, and bakes the result into `SwQosConnectionContext { peer_type, total_stake, ... }`: [2](#0-1) 

That same, never-refreshed context is subsequently used for the entire life of the connection to compute:
- The maximum concurrent unidirectional streams allowed (`compute_max_allowed_uni_streams_with_rtt`, driven by `peer_stake / total_stake`): [3](#0-2) 
- The per-interval stream throttling capacity (`max_streams_per_throttling_interval`, driven by `conn_context.total_stake`): [4](#0-3) 

`ConnectionContext`/`QosController` expose no hook to refresh a peer's stake mid-connection — `build_connection_context` is only invoked once per connection (grep confirms a single call site each in `simple_qos.rs`, `swqos.rs`, and `quic.rs`), and the trait itself documents building the context as a one-time step tied to connection creation: [5](#0-4) 

This mirrors the reported bug class exactly: a value that legitimately changes over time (stake, analogous to token price) is sampled once ("spot") and then used to compute an entitlement (stream/throughput allowance, analogous to `aSugar` reward) that is applied uniformly across a duration (the connection's lifetime) during which the true value may have drifted arbitrarily.

### Impact Explanation
Because `total_stake` and `peer_stake` are pinned at handshake time, a connection opened at a favorable moment (e.g., when the node's own delegated stake is momentarily inflated, or when cluster `total_stake` is momentarily low right after an epoch boundary recomputation) retains that inflated `ConnectionPeerType::Staked(stake)` classification and the correspondingly large `max_uni_streams`/`throttle capacity` for as long as the QUIC connection stays open — independent of subsequent stake changes (undelegation, slashing-equivalent stake decrease, or epoch-driven `total_stake` growth that should shrink this peer's fair share). This lets a peer sustain an unfairly large share of TPU/TPU-forward QUIC bandwidth relative to its real, current stake — i.e., QoS evasion — without needing repeated attacks, only a single well-timed handshake and connection persistence.

### Likelihood Explanation
Moderate. Exploiting it requires a peer to control the timing of its own stake and the moment its QUIC connection is (re-)established relative to `StakedNodes` updates, and to keep the connection alive afterward. `StakedNodes` is refreshed periodically by `staked_nodes_updater_service` (not on every packet), so a window exists between refreshes where a peer's advertised stake can diverge from the entitlement locked into an already-established connection. This is fully triggerable by any unprivileged network peer (no special validator role required) and does not depend on mocked-only conditions.

### Recommendation
Periodically re-derive `SwQosConnectionContext`/`ConnectionPeerType` for long-lived connections (e.g., on a timer or on each new stream) rather than caching stake permanently for the connection's lifetime, so that `compute_max_allowed_uni_streams_with_rtt` and `max_streams_per_throttling_interval` always reflect the current `StakedNodes` snapshot instead of a stale value captured at handshake time.

### Proof of Concept
Conceptual: 1) A peer's stake is at value S1 (favorable ratio) when it opens a QUIC connection to the TPU/TPU-forward endpoint, triggering `build_connection_context`/`get_connection_stake`, which locks in `peer_stake=S1, total_stake=T1` into `SwQosConnectionContext`. 2) The peer's real stake subsequently drops to S2 « S1 (or cluster `total_stake` grows to T2 » T1) on the next `StakedNodes` refresh. 3) The peer keeps the same QUIC connection open (no forced re-handshake), so `compute_max_allowed_uni_streams_with_rtt` and `max_streams_per_throttling_interval` continue to compute allowances from the stale `S1/T1` ratio, giving the peer a stream/throughput quota disproportionate to its now-current stake for the remaining connection lifetime.

pub fn get_connection_stake(
    connection: &Connection,
    staked_nodes: &RwLock<StakedNodes>,
) -> Option<(Pubkey, u64, u64)> {
    let pubkey = get_remote_pubkey(connection)?;
    debug!("Peer public key is {pubkey:?}");
    let staked_nodes = staked_nodes.read().unwrap();
    Some((
        pubkey,
        staked_nodes.get_node_stake(&pubkey)?,
        staked_nodes.total_stake(),
    ))
}

fn compute_max_allowed_uni_streams_with_rtt(
    rtt_millis: u32,
    peer_type: ConnectionPeerType,
    total_stake: u64,
) -> u32 {
    let streams = match peer_type {
        ConnectionPeerType::Staked(peer_stake) => {
            // No checked math for f64 type. So let's explicitly check for 0 here
            if total_stake == 0 || peer_stake > total_stake {
                warn!(
                    "Invalid stake values: peer_stake: {peer_stake:?}, total_stake: \
                     {total_stake:?}"
                );

                QUIC_MIN_STAKED_CONCURRENT_STREAMS
            } else {
                let delta = (QUIC_TOTAL_STAKED_CONCURRENT_STREAMS
                    - QUIC_MIN_STAKED_CONCURRENT_STREAMS) as f64;

                (((peer_stake as f64 / total_stake as f64) * delta) as u32
                    + QUIC_MIN_STAKED_CONCURRENT_STREAMS)
                    .clamp(
                        QUIC_MIN_STAKED_CONCURRENT_STREAMS,
                        QUIC_MAX_STAKED_CONCURRENT_STREAMS,
                    )
            }
        }
        ConnectionPeerType::Unstaked => QUIC_MAX_UNSTAKED_CONCURRENT_STREAMS,
    };
    // scale amount of streams based on RTT if RTT is larger than REFERENCE_RTT_MS
    // multiply first then divide to avoid rounding errors.
    (streams.saturating_mul(rtt_millis.clamp(REFERENCE_RTT_MS, MAX_RTT_MS))) / REFERENCE_RTT_MS
}

impl QosController<SwQosConnectionContext> for SwQos {
    fn build_connection_context(&self, connection: &Connection) -> SwQosConnectionContext {
        let remote_address = connection.remote_address();
        get_connection_stake(connection, &self.staked_nodes).map_or(
            SwQosConnectionContext {
                peer_type: ConnectionPeerType::Unstaked,
                total_stake: 0,
                remote_pubkey: None,
                in_staked_table: false,
                remote_address,
                stream_counter: None,
                last_update: Arc::new(AtomicU64::new(timing::timestamp())),
            },
            |(pubkey, stake, total_stake)| {
                // The heuristic is that the stake should be large enough to have 1 stream pass through within one throttle
                // interval during which we allow max (MAX_STREAMS_PER_MS * STREAM_THROTTLING_INTERVAL_MS) streams.

                let peer_type = {
                    let max_streams_per_ms = self.staked_stream_load_ema.max_streams_per_ms();
                    let min_stake_ratio =
                        1_f64 / (max_streams_per_ms * STREAM_THROTTLING_INTERVAL_MS) as f64;
                    let stake_ratio = stake as f64 / total_stake as f64;
                    if stake_ratio < min_stake_ratio {
                        // If it is a staked connection with ultra low stake ratio, treat it as unstaked.
                        ConnectionPeerType::Unstaked
                    } else {
                        ConnectionPeerType::Staked(stake)
                    }
                };

                SwQosConnectionContext {
                    peer_type,
                    total_stake,
                    remote_pubkey: Some(pubkey),
                    in_staked_table: false,
                    remote_address,
                    last_update: Arc::new(AtomicU64::new(timing::timestamp())),
                    stream_counter: None,
                }
            },
        )
    }
