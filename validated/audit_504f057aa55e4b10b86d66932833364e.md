### Title
Liquidating an insolvent position exhausts collateral while leaving unbacked debt - (File: contracts/Pool.sol)

### Summary
`Pool.liquidate()` lets an unprivileged liquidator seize nearly all collateral from an underwater account while burning only the portion of debt that the seized collateral can repay. The account can consequently retain positive `DebtToken` debt with approximately zero collateral, while the originally minted synthetic asset remains outstanding, creating unpriced protocol bad debt.

### Finding Description
`quoteLiquidateMax()` computes the repayable debt as the lesser of the collateral-convertible amount and `debt * maxLiquidable`. For an insolvent position, the collateral-convertible amount is necessarily below the outstanding debt. [1](#0-0) [2](#0-1) 

`liquidate()` accepts that partial repayment, burns only `amountToRepay_` of both the synthetic asset and debt, and transfers `_toLiquidator` plus the optional protocol fee from the borrower’s deposit-token balance. [3](#0-2) [4](#0-3) 

The only collateral bound is the account’s deposit-token balance; the function does not require remaining collateral to cover remaining debt and has no bad-debt reserve, deficit accrual, write-off, or socialization step. [5](#0-4) [6](#0-5) 

This is reachable even when `maxLiquidable` is 100%, because `quoteLiquidateMax()` still clamps repayment to the value purchasable from the borrower’s collateral. The default configuration is more restrictive at 50%, which leaves additional debt behind. [2](#0-1) [7](#0-6) 

### Impact Explanation
After the liquidation, `debtPositionOf()` can report positive debt and approximately zero deposits because debt and collateral are independently summed across the account’s token lists. [8](#0-7) [9](#0-8) 

The residual debt corresponds to synthetic supply that was minted but not burned during liquidation, so aggregate synthetic liabilities are no longer backed by the liquidated borrower’s collateral. The loss is ultimately borne by synthetic holders or other protocol participants rather than being explicitly reserved or resolved.

The repository’s own test scenario demonstrates this end state: after an underwater liquidation, the deposit balance is approximately zero while `msEthDebtToken.balanceOf(alice)` remains positive and Alice’s minted `msETH` remains outstanding. [10](#0-9) 

### Likelihood Explanation
An ordinary collateral-price decline can make a borrower’s debt exceed the account’s collateral value. Once `_isHealthy` is false, any EOA holding the required synthetic token can call the public `liquidate()` function. [11](#0-10) [12](#0-11) 

No privileged role, invalid oracle data, or attacker-controlled collateral is required; the liquidator merely supplies a listed synthetic token, borrower, repayment amount, and listed deposit token.

### Recommendation
Add explicit underwater-liquidation handling:

- When collateral is exhausted and debt remains, calculate and record the uncovered amount as protocol bad debt.
- Cover the deficit from an insurance fund or reserve where available.
- If reserves are insufficient, socialize the loss through an explicit accounting mechanism rather than leaving an economically uncollectible account debt.
- Ensure liquidation against the final available collateral is not blocked by `debtFloorInUsd`; permit the residual position to be closed or written off while recording the deficit.
- Add invariant tests asserting that after all collateral is seized, either remaining debt is zero or an equal explicit bad-debt liability exists.

### Proof of Concept
The following Hardhat test uses the existing `Pool.test.ts` fixture and production `Pool.liquidate()` path:

```ts
it('leaves unbacked debt after liquidating an insolvent account', async function () {
  // Fixture state:
  // Alice: 6,000 MET collateral and 1 msETH debt.
  // MET initially = $4; msETH = $4,000.
  await feeProvider.updateProtocolLiquidationFee(0);

  // Simulate a legitimate market decline: collateral is now worth $3,000,
  // while debt remains $4,000.
  await masterOracle.updatePrice(met.address, toUSD('0.50'));

  // Move the minted synthetic asset to an unrelated holder to show that the
  // circulating supply is no longer backed by Alice's collateral.
  await msEth.connect(alice).transfer(bob.address, userMintAmount);

  const collateralBefore = await msdMET.balanceOf(alice.address);
  const debtBefore = await msEthDebtToken.balanceOf(alice.address);

  const amountToRepay = await pool.quoteLiquidateMax(
    msEth.address,
    alice.address,
    msdMET.address
  );

  expect(amountToRepay).lt(debtBefore);

  await pool
    .connect(liquidator)
    .liquidate(msEth.address, alice.address, amountToRepay, msdMET.address);

  const collateralAfter = await msdMET.balanceOf(alice.address);
  const debtAfter = await msEthDebtToken.balanceOf(alice.address);
  const position = await pool.debtPositionOf(alice.address);

  // Approximately all collateral was seized.
  expect(collateralAfter).lt(collateralBefore);
  expect(collateralAfter).closeTo(0, 2_000);

  // Uncollectible debt remains without an explicit bad-debt record.
  expect(debtAfter).gt(0);
  expect(position._depositInUsd).closeTo(0, toUSD('0.01'));
  expect(position._debtInUsd).gt(0);
  expect(position._isHealthy).false;

  // The synthetic asset minted against the failed position remains circulating.
  expect(await msEth.balanceOf(bob.address)).eq(userMintAmount);
});
```
