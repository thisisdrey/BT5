### Title
Null Pointer Dereference in `Util.getVisiblePost()` / `Util.getContractType()` via crafted HTTP request body ("null" literal) - (File: `framework/src/main/java/org/tron/core/services/http/Util.java`)

### Summary
`Util.getVisiblePost(String input)` and `Util.getContractType(String input)` in `framework/src/main/java/org/tron/core/services/http/Util.java` call `JSON.parseObject(input)` and then immediately dereference the result with `jsonObject.containsKey(...)` without checking for `null`. This mirrors the iccDEV bug class: a parser (`CIccProfileXml::ParseBasic()` / here `JSON.parseObject`) that can legitimately return `null` on certain inputs, and a caller that unconditionally dereferences the parse result, causing an NPE.

### Finding Description
`JSON.parseObject` in `common/src/main/java/org/tron/json/JSON.java` explicitly returns `null` when the input text is the literal string `"null"` (case-sensitive, lowercase) via `isNullLiteral()`: [1](#0-0) 

`Util.getVisiblePost` guards on `StringUtil.isNotBlank(input)` — which is true for the literal string `"null"` since it's non-blank — then calls `JSON.parseObject(input)` and immediately calls `jsonObject.containsKey(VISIBLE)` with no null check: [2](#0-1) 

The sibling method `Util.getContractType` has the identical pattern — it doesn't even check for blank input before parsing and dereferencing: [3](#0-2) 

Both methods are reachable from many HTTP wallet servlets that accept a raw POST body from an anonymous API client, e.g. `TriggerSmartContractServlet.doPost`, `TransferServlet`, `TransferAssetServlet`, `ProposalCreateServlet`, `MarketSellAssetServlet`, `SetAccountIdServlet`, `VoteWitnessAccountServlet`, `WithdrawBalanceServlet`, etc., all of which call `Util.getVisiblePost(contract)` or similar on the unparsed request body before/while constructing the transaction: [4](#0-3) 

Sending a POST body consisting of exactly the text `null` (not JSON `null` as part of an object, but the raw body itself) to any of these endpoints triggers `JSON.parseObject("null")` → returns `null` → `jsonObject.containsKey(VISIBLE)` throws `NullPointerException`.

### Impact Explanation
This directly parallels the referenced CVE-2026-21506 class (parser returns null on certain valid/near-valid input, caller dereferences without a null check → crash). In this codebase, however, every servlet `doPost`/`doGet` calling this path wraps the call in a `try { ... } catch (Exception e) { Util.processError(e, response); }` block, so the resulting `NullPointerException` is caught per request and only manifests as an HTTP error response, not a JVM crash or full node halt.

### Likelihood Explanation
Trivially reachable: any anonymous HTTP API client can send a single POST request with body `null` to numerous wallet endpoints to trigger the NPE. However, because every caller in the HTTP layer catches generic `Exception`, the practical effect is limited to a malformed/misleading error response for that single request rather than a lasting denial of service against the node or any other client. No amplification, state corruption, or persistent unavailability is demonstrated.

### Recommendation
Add an explicit null check after `JSON.parseObject(input)` in both `Util.getVisiblePost` and `Util.getContractType`, returning the default value (`false` / `null`) when the parsed result is `null`, consistent with how other helpers in the same file already guard (`getRequestValue`/`checkGetParam` at lines 590-599 do check `jsonObject != null`).

### Proof of Concept
1. Send `POST /wallet/triggersmartcontract` (or `/wallet/createtransaction`, `/wallet/transferasset`, etc.) with request body exactly: `null`
2. Inside `TriggerSmartContractServlet.doPost`, `Util.getVisiblePost("null")` is invoked; `StringUtil.isNotBlank("null")` is `true`, `JSON.parseObject("null")` returns `null` per `isNullLiteral`, and `jsonObject.containsKey(VISIBLE)` throws `NullPointerException`.
3. The exception is caught by the servlet's generic `catch (Exception e)` and reported as an `OTHER_ERROR` response rather than crashing the process — confirming the bug exists but its impact is confined to a single malformed request/response cycle, not a node-wide denial of service.   /**
   * Returns {@code true} when {@code text} is null, blank, or a
   * lowercase {@code "null"} literal.
   */
  static boolean isNullLiteral(String text) {
    if (text == null) {
      return true;
    }
    String trimmed = text.trim();
    return trimmed.isEmpty() || "null".equals(trimmed);
  }

  public static JSONObject parseObject(String text) {
    if (isNullLiteral(text)) {
      return null;
    }
    try {
      JsonNode node = MAPPER.readTree(text);
      if (node == null || node.isNull()) {
        return null;
      }
      if (!node.isObject()) {
        throw new JSONException("can not cast to JSONObject.");
      }
      return new JSONObject((ObjectNode) node);
    } catch (JSONException e) {
      throw e;
    } catch (Exception e) {
      throw new JSONException(e.getMessage(), e);
    }
  }

        visible = Boolean.parseBoolean(jsonObject.getString(VISIBLE));
