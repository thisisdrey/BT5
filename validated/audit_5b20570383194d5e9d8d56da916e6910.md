The Mellow report concerns an application-level vault contract's withdrawal-fee/LP-share accounting, where a batch of withdrawal requests is priced against a `totalSupply`/`totalValue` snapshot taken once at the start of `calculateStack()` rather than updated incrementally as each request is processed, letting later requests in the same batch fail to capture fee-driven share appreciation and letting a sandwiching depositor capture it instead [1](#0-0) .

Geth's analogous mainnet mechanism is EIP-4895 withdrawal processing in `Finalize`, which simply credits each validator's specified `Amount` (in gwei, converted to wei) directly to its balance via `state.AddBalance`, with no derived share price, no snapshot of total supply/value, and no per-recipient proportional calculation that could grow stale across a batch [2](#0-1) . The same direct-credit pattern is used in the block-generation/test tooling and t8n execution path [3](#0-2) . Each withdrawal amount is fixed by the consensus layer ahead of time and is not a function of any pooled totalSupply/totalValue that other withdrawals in the same block could dilute or inflate, so there is no equivalent "stale snapshot reused across a batch of value-bearing operations" bug class reachable in the in-scope execution-layer code (`core/**`, `consensus/**`, `beacon/engine/**`, `eth/catalyst/**`, `miner/**`). Without a pooled/share-price abstraction being updated incrementally, there is no equality this pattern could break (no ETH created/moved without authorization, no state root divergence, no gas/receipt mismatch).

// Finalize implements consensus.Engine and processes withdrawals on top.
func (beacon *Beacon) Finalize(chain consensus.ChainHeaderReader, header *types.Header, state vm.StateDB, body *types.Body, blockAccessIndex uint32, bal *bal.ConstructionBlockAccessList) {
	if !beacon.IsPoSHeader(header) {
		beacon.ethone.Finalize(chain, header, state, body, blockAccessIndex, bal)
		return
	}
	// Withdrawals processing.
	for _, w := range body.Withdrawals {
		// Convert amount from gwei to wei.
		amount := new(uint256.Int).SetUint64(w.Amount)
		amount = amount.Mul(amount, uint256.NewInt(params.GWei))
		prev := state.AddBalance(w.Address, amount, tracing.BalanceIncreaseWithdrawal)

		// Populate the block-level accessList if Amsterdam is enabled
		if chain.Config().IsAmsterdam(header.Number, header.Time) {
			if w.Amount == 0 {
				// Zero amount withdrawal, account is accessed potential
				// without state changes.
				bal.AccountRead(w.Address)
			} else {
				// Non-zero amount withdrawal, account is accessed with
				// a balance change.
				bal.BalanceChange(blockAccessIndex, w.Address, new(uint256.Int).Add(&prev, amount))
			}
		}
	}
	// No block reward which is issued by consensus layer instead.
