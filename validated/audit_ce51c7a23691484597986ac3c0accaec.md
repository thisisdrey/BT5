### Title
Attacker-controlled MessageRelay packet length causes negative-length slice panic in VerifyRelay - ([File: connection_state.go])

### Summary
`nebula.(*ConnectionState).VerifyRelay` computes `signedPayload := packet[:len(packet)-cs.dKey.Overhead()]` without first checking that `len(packet) >= cs.dKey.Overhead()`. The function's own comment ("packet must be length-checked by the caller") shows the length check is not performed inside the function, and the relay dispatch path in `outside.go` passes the post-header remainder of an attacker-supplied UDP datagram directly into this function.

### Finding Description
`VerifyRelay` is reached when an inbound UDP datagram parses as `header.MessageRelay` and its `RemoteIndex` matches an existing relayed `HostInfo`/`ConnectionState` on the receiving node [1](#0-0) . Inside the function, `signedPayload` and `signatureValue` are derived by slicing `packet` using `cs.dKey.Overhead()` (the AEAD tag size, e.g. 16 bytes for the configured cipher) with no prior bound check:
```go
signedPayload := packet[:len(packet)-cs.dKey.Overhead()]
signatureValue := packet[len(packet)-cs.dKey.Overhead():]
``` [2](#0-1) 

If the attacker sends a `MessageRelay` packet whose payload (the portion after the fixed wire header) is shorter than `cs.dKey.Overhead()`, `len(packet)-cs.dKey.Overhead()` is negative, and Go's slice expression `packet[:negative]` panics with "slice bounds out of range" before any AEAD/authentication check runs. The AEAD decrypt/verify call that would otherwise reject a forged/short payload (`cs.dKey.DecryptDanger`) never executes because the panic happens earlier, so no existing cryptographic check protects this path. The replay-window check (`cs.window.Check`) that runs first only validates the message counter, not the packet length, so it does not prevent the crash. Because `RemoteIndex` values are carried in cleartext in the Nebula wire header, an attacker who can observe (or otherwise obtain) a valid `RemoteIndex` for an active relay session — without holding any certificate, key, or host access — can address a spoofed short `MessageRelay` datagram at the target and trigger this panic.

### Impact Explanation
A panic during UDP packet processing crashes the interface's read goroutine (and, absent a recover wrapper around this exact call path, the process), taking down packet forwarding for every peer connected through the affected relay hostinfo — a remote, unauthenticated denial-of-service/crash triggered purely by packet length, matching Nebula's "remote crash/wedge" bounty impact category.

### Likelihood Explanation
Exploitation only requires knowledge of a valid `RemoteIndex` for an existing relayed connection (obtainable via passive observation of the cleartext header field on the wire) and the ability to send a single spoofed UDP datagram of length less than `header.Len + cs.dKey.Overhead()` to the target's UDP port. No certificate, handshake completion, or privileged access is needed, making this readily repeatable once a valid index is known.

### Recommendation
Add an explicit length check at the top of `VerifyRelay` (and anywhere else `packet` length is used for AEAD-overhead-based slicing) that returns an error such as `ErrPacketTooShort` when `len(packet) < cs.dKey.Overhead()`, before performing any slicing arithmetic.

### Proof of Concept
Add a fuzz/unit test in `connection_state_test.go`:
```go
func TestVerifyRelay_ShortPacket(t *testing.T) {
    cs := &ConnectionState{ /* initialize dKey with real cipher, window */ }
    for n := 0; n < cs.dKey.Overhead(); n++ {
        packet := make([]byte, n)
        err := cs.VerifyRelay(logger, 1, packet, nil)
        require.Error(t, err) // must not panic
    }
}
```
Run with `-fuzz` over packet lengths `0..Overhead()-1` and assert the call returns a graceful error rather than panicking; currently it panics with "slice bounds out of range" for any packet shorter than `Overhead()`.

// VerifyRelay verifies AEAD protected (but not encrypted) relay frames. packet must be length-checked by the caller.
func (cs *ConnectionState) VerifyRelay(l *slog.Logger, messageCounter uint64, packet []byte, nb []byte) error {
	cs.decryptLock.Lock()
	result := cs.window.Check(l, messageCounter)
	cs.decryptLock.Unlock()
	if !result {
		return ErrAlreadySeen
	}

	signedPayload := packet[:len(packet)-cs.dKey.Overhead()]
	signatureValue := packet[len(packet)-cs.dKey.Overhead():]
	_, err := cs.dKey.DecryptDanger(nil, signedPayload, signatureValue, messageCounter, nb)
	if err != nil {
		return err
	}
```
