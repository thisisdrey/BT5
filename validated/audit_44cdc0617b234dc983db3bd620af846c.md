### Title
Unauthenticated `POST /shutdown` on signer event-listener causes remote DoS of the signer's event loop - (File: libsigner/src/events.rs)

### Summary
`SignerEventReceiver`'s HTTP loop treats any request whose URL equals `/shutdown` as a termination signal, with no secret, token, or origin check tying the request to the internal `SignerStopSignaler`. Any remote party able to reach the bound event-listener socket can send a bare `POST /shutdown HTTP/1.1` and force the receiver to return `EventError::Terminated`, killing the signer's event-processing loop.

### Finding Description
`SignerStopSignaler::send` (in `libsigner/src/events.rs`) is the internal mechanism used to unblock a `HttpServer::recv()` call that would otherwise block forever: it stores a stop flag and then issues an HTTP request to `/shutdown` against the server's own `local_addr`, purely to wake up the blocking call. The receive loop (`next_event`) checks `request.url() == "/shutdown"` and, on match, responds and returns `EventError::Terminated`, unwinding the signer's event loop — this check uses only the URL string, not any shared secret, HMAC, or loopback-only enforcement [1](#0-0) .

Because the match is on URL content alone, the mechanism cannot distinguish "wake-up call issued by our own `SignerStopSignaler`" from "arbitrary POST from any TCP peer that can reach the listening socket." The signer's event-listener endpoint is configured to accept pushed events from the stacks-node's event dispatcher and, per the question's stated attacker model, is reachable by a remote unprivileged party. That party needs no RPC secret, no StackerDB slot, and no peer key — a single `POST /shutdown HTTP/1.1\r\nHost: x\r\nContent-Length: 0\r\n\r\n` sent to the bound address suffices to trip the same code path.

### Impact Explanation
A single crafted request terminates the signer's `next_event` loop, stopping ingestion of block proposals, burn-block events, and StackerDB chunk events pushed from the node. This is a remote, unauthenticated crash/DoS achievable with one message and is trivially repeatable (an attacker can send it again every time the process/loop is restarted), matching the "Critical - remote crash/unauthenticated DoS from few messages" category. It does not corrupt chain state directly, but it silently disables a signer's participation in block validation/voting, which can affect availability of signature threshold in the network if repeated against multiple signers.

### Likelihood Explanation
- No secret, peer identity, or StackerDB slot is required — only network reachability to the bound event-listener address.
- Cost is a single small HTTP POST.
- Repeatable indefinitely as long as the port is reachable.
- The only variable is whether the operator has bound/firewalled the listener to loopback-only; the question's threat model explicitly stipulates the attacker "can reach the signer's bound event-listener address," making this reachable.

### Recommendation
Do not use a URL-only unauthenticated trigger for internal wake-up. Options:
- Bind the internal signaling connection to a loopback-only socket, and have the event-listener itself reject any `/shutdown` request that did not originate from `127.0.0.1`/the local process.
- Require a locally-generated random per-run token (shared only in-process between `SignerStopSignaler` and `SignerEventReceiver`) included in the `/shutdown` request, checked before terminating.
- Replace the HTTP self-poke with an OS-level mechanism (e.g., a pipe/eventfd or a `mio`/`tokio` wakeup) that isn't exposed on the network-facing listener at all.

### Proof of Concept
Rust-style `net` test plan:
1. Start a `SignerEventReceiver` bound to `127.0.0.1:0`, capture the bound port.
2. From a separate `TcpStream`, connect to that port and write raw bytes:
   `b"POST /shutdown HTTP/1.1\r\nHost: x\r\nContent-Length: 0\r\n\r\n"`.
3. Call `next_event()` on the receiver from the test thread and assert it returns `Err(EventError::Terminated)` even though `SignerStopSignaler::send` was never invoked and the internal stop flag was never set by the receiver's owner.
4. Confirms termination is triggered purely by URL match on attacker-controlled input, not by any authenticated internal signal.
