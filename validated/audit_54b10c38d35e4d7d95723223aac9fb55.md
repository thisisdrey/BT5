### Title
Archive cache key omits format/prefix/LFS-inclusion, causing cross-request cache poisoning in GetArchive - (File: internal/gitaly/service/repository/archive.go)

### Summary
`GetArchive`'s cache key is derived only from the GitLab project path, the `git archive` positional args (commit ID/path), and pathspecs, while the archive `format`, `--prefix` value, and whether LFS blobs are smudged (`IncludeLfsBlobs`) are excluded from the key even though they change the byte content that gets cached and streamed back to the client.

### Finding Description
`GetArchive` builds a cache key with `createArchiveCacheKey(repo.GetGlProjectPath(), args, pathspecs)` and looks it up in `s.archiveCache`, a raw `streamcache.Cache` that serves byte-for-byte whatever was stored under a matching key with no further validation of the parameters used to produce it. [3](#0-2) 

The key-building function only hashes the project path, `args`, and `pathspecs`: [4](#0-3) 

But the actual command/content generated is also controlled by `p.format` (`--format` flag), `p.in.GetPrefix()` (`--prefix` flag), and `p.in.GetIncludeLfsBlobs()`, which toggles smudge filtering that replaces LFS pointer files with real blob content fetched from GitLab: [5](#0-4) [6](#0-5) 

Because none of `format`, `prefix`, or `IncludeLfsBlobs` participate in the cache key, two different `GetArchiveRequest`s that only differ in these fields but share the same repository/commit/path/exclude set will collide on the same cache key. The `streamcache.Cache.Fetch`/`getStream` implementation treats any existing index entry for that key as an unconditional hit and streams its previously-written bytes to the new caller without re-checking what parameters generated it. [7](#0-6) 

### Impact Explanation
An ordinary, unprivileged caller of `GetArchive` (any client permitted to read a repository) can trigger this collision. The most severe consequence is with `IncludeLfsBlobs`: if one request populates the cache with `IncludeLfsBlobs=true` (embedding real LFS blob contents fetched via the GitLab smudge filter) for a given commit/path/exclude combination, a subsequent request for the same commit/path/exclude but with a different `Format`/`Prefix`/`IncludeLfsBlobs` value will get served the first request's cached bytes mislabeled as its own format/prefix, effectively cross-wiring archive contents between requests (e.g., a ZIP-format-requesting or LFS-pointer-only-requesting caller instead receives a cached TAR/real-LFS-blob payload from a different request). This is a concrete cache-key/argument-omission bug enabling content confusion and potential disclosure of LFS blob content to a request context that did not ask for smudging, directly analogous to the reported bug class (a verification/identity hash omitting fields that materially affect the executed action's outcome).

### Likelihood Explanation
Triggering this requires no special privilege beyond ordinary repository read access already needed to call `GetArchive`, and only requires sending two requests for the same repository/commit/path with differing `format`/`prefix`/`include_lfs_blobs` fields in close succession (within the cache's `MaxAge`/`MinOccurrences` window) — an easily reachable condition from a normal client or even concurrent legitimate traffic.

### Recommendation
Include `p.format`, `p.in.GetPrefix()`, and `p.in.GetIncludeLfsBlobs()` (and any other flag affecting content, e.g. `compressArgs`) in `createArchiveCacheKey`'s hash input, using length-prefixed or otherwise unambiguous encoding for each component (the current comma-joining of `args`/`pathspecs` is itself ambiguous and susceptible to delimiter-collision between differently-structured argument lists).

### Proof of Concept
1. Client A calls `GetArchive` for `Repository=R`, `CommitId=C`, `Format=TAR`, `IncludeLfsBlobs=true` — the response is cached under key `H(glProjectPath, args=[C], pathspecs=[path])`, containing a TAR with real LFS blob contents smudged in.
2. Client B, shortly after (within cache TTL), calls `GetArchive` for the same `Repository=R`, `CommitId=C`, but `Format=ZIP`, `IncludeLfsBlobs=false` — `args`/`pathspecs` are identical to step 1, so the same cache key `H(...)` is computed.
3. `s.archiveCache.Fetch` finds the existing entry for that key and streams back Client A's TAR bytes (including smudged LFS content) to Client B, even though Client B requested ZIP without LFS smudging — demonstrating cross-request content confusion caused by the incomplete cache key.

func (c *cache) Fetch(ctx context.Context, key string, dst io.Writer, create func(io.Writer) error) (written int64, created bool, err error) {
	var (
		rc io.ReadCloser
		wt *waiter
	)
	rc, wt, created, err = c.getStream(key, create)
	if err != nil {
		return written, created, err
	}
	defer rc.Close()

	written, err = io.Copy(dst, rc)
	if err != nil {
		return written, created, err
	}

	err = wt.Wait(ctx)
	return written, created, err
}

func (c *cache) getStream(key string, create func(io.Writer) error) (_ io.ReadCloser, _ *waiter, created bool, err error) {
	c.m.Lock()
	defer c.m.Unlock()

	if e := c.index[key]; e != nil {
		if r, err := e.pipe.OpenReader(); err == nil {
			return r, e.waiter, false, nil
		}

		// In this case err != nil. That is allowed to happen, for instance if
		// the *filestore cleanup goroutine deleted the file already. But let's
		// remove the key from the cache to save the next caller the effort of
		// trying to open this entry.
		c.delete(key)
	}

	r, e, err := c.newEntry(key, create)
	if err != nil {
		return nil, nil, false, err
	}

	c.index[key] = e
	c.setIndexSize()

	return r, e.waiter, true, nil
}

func (s *server) handleArchive(ctx context.Context, p archiveParams) error {

		// git archive [options] <commit ID>:<path> -- [exclude*]
		args = []string{p.in.GetCommitId() + ":" + p.archivePath}

		// git archive [options] <commit ID> -- [exclude*]
		args = []string{p.in.GetCommitId()}
	}

	for _, exclude := range p.exclude {
		pathspecs = append(pathspecs, ":(exclude)"+exclude)
	}

	var env []string
	var gitConfig []gitcmd.ConfigPair

	if p.in.GetIncludeLfsBlobs() {
		smudgeCfg := smudge.Config{
			GlRepository: p.in.GetRepository().GetGlRepository(),
			Gitlab:       s.cfg.Gitlab,
			TLS:          s.cfg.TLS,
			DriverType:   smudge.DriverTypeProcess,
		}

		smudgeEnv, err := smudgeCfg.Environment()
		if err != nil {
			return fmt.Errorf("setting up smudge environment: %w", err)
		}

		smudgeGitConfig, err := smudgeCfg.GitConfiguration(s.cfg)
		if err != nil {
			return fmt.Errorf("setting up smudge gitconfig: %w", err)

			smudgeEnv,

		gitConfig = append(gitConfig, smudgeGitConfig)
	}

	repo := s.localRepoFactory.Build(p.in.GetRepository())

	cacheKey := createArchiveCacheKey(repo.GetGlProjectPath(), args, pathspecs)
	_, _, err := s.archiveCache.Fetch(ctx, cacheKey, p.writer, func(writer io.Writer) error {

			Flags:       []gitcmd.Option{gitcmd.ValueFlag{Name: "--format", Value: p.format}, gitcmd.ValueFlag{Name: "--prefix", Value: p.in.GetPrefix() + "/"}},
			Args:        args,
			PostSepArgs: pathspecs,
		}, gitcmd.WithEnv(env...), gitcmd.WithConfig(gitConfig...), gitcmd.WithSetupStdout())
		if err != nil {
			return err

				return err
			}
		} else if _, err = io.Copy(writer, archiveCommand); err != nil {
			return err
		}

		return archiveCommand.Wait()
	})

// createArchiveCacheKey creates a cache key using the GitLab project's path, the `git archive`
// command arguments and the pathspecs. The goal is to create a key that is unique not only
// across repository, but also across the content of each archive within the same repository.
func createArchiveCacheKey(gitLabProjectPath string, args []string, pathspecs []string) string {
	cacheKeyHash := sha256.New()
	cacheKeyHash.Write([]byte(gitLabProjectPath))
	cacheKeyHash.Write([]byte(strings.Join(args, ",")))
	cacheKeyHash.Write([]byte(strings.Join(pathspecs, ",")))
	return hex.EncodeToString(cacheKeyHash.Sum(nil))
}
