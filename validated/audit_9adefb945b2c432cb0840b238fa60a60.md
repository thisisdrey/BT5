### Title
Attacker-controlled `RemoteIp` field lets a single cheap fetch flood exhaust the shared per-IP pack-objects concurrency/queue slot, denying service to other legitimate clients behind the same IP - (File: internal/gitaly/service/hook/pack_objects.go)

### Summary
The `PackObjectsHookWithSidechannel` RPC path keys its concurrency/queue limiter by the value of the `RemoteIp` field taken directly from the incoming request message rather than by a value that is bound to per-caller identity/authorization. Because many unrelated Git users can share the same limiting key (e.g. everyone behind the same NAT/proxy address, or an attacker who can influence what `RemoteIp` is populated with), a single low-cost stream of `git fetch`/`clone` requests can fill up the small, fixed-size per-key queue, causing legitimate users' `PackObjectsHookWithSidechannel` requests that hash to the same key to be rejected with `ResourceExhausted`. This mirrors the referenced bug class: a shared, low-cost-to-consume quota that any unprivileged caller can trivially exhaust to deny service to other users of that same quota bucket.

### Finding Description
`packObjectsHook` derives the limiting key for the pack-objects concurrency limiter from `req.GetRemoteIp()`: [1](#0-0) 

This key is then used to call `runPackObjectsLimited`, which enforces the shared concurrency/queue limits: [2](#0-1) 

The limiter itself (`ConcurrencyLimiter.Limit` / `keyedConcurrencyLimiter.acquire`) enforces a fixed, small `MaxQueueSize`/`MaxConcurrency` per key; once the per-key queue token pool is exhausted, all further callers using that same key are rejected immediately with `ErrMaxQueueSize`, regardless of which repository or GitLab user they represent: [3](#0-2) [4](#0-3) 

The configured limits are intentionally small and static/adaptive but bounded (`packObjects` limiter setup): [5](#0-4) 

Because the key is derived purely from the `RemoteIp` string carried in the RPC payload (best-effort parsed, with only loopback addresses excluded), any set of ordinary, unprivileged clients that happen to share (or can be made to share) the same `RemoteIp` value fall into the same bucket of concurrency/queue tokens. A cheap, repeated `git fetch`/`clone` (or, if reachable directly, repeated `PackObjectsHookWithSidechannelRequest` calls with a fixed `RemoteIp`) is all that is required to keep the queue for that key permanently saturated, since the queue size is a small fixed number (analogous to `MAX_LOAN_PER_BLOCK` in the referenced report) shared across every caller mapped to that key.

### Impact Explanation
Once the per-key queue is full, every subsequent legitimate fetch/clone from a different user that resolves to the same limiting key is rejected with a structured `ResourceExhausted`/`LimitError` response instead of being served, denying access to Git data for those legitimate users. This is a DoS of a resource-limited RPC handler triggered purely by ordinary fetch/clone traffic that an unprivileged user fully controls (repeat requests are cheap — no large payload or expensive git operation is required to occupy a queue slot, only to occupy the queue admission window).

### Likelihood Explanation
This requires only the ability to send repeated ordinary `git fetch`/`clone` requests (or crafted `PackObjectsHookWithSidechannelRequest` calls carrying a `RemoteIp` value shared with the target) — actions available to any unprivileged Git client. No additional privilege, token leak, or malicious-peer setup is needed. The bounded queue/concurrency size (`PackObjectsLimiting.MaxConcurrency`/`MaxQueueSize`, defaulting to small static or narrow adaptive ranges) makes exhaustion cheap and repeatable per block/window, matching the "minimal cost, repeatable per interval" pattern in the referenced report.

### Recommendation
1. Do not rely solely on the client-supplied/derived `RemoteIp` string as the sole limiting key shared across independent users; combine it with a stronger per-caller identity (e.g., authenticated user/token identity) so that unrelated legitimate users are not co-located in the same limited bucket purely by IP coincidence.
2. Bound how much of the shared per-key queue capacity a single caller identity can consume (analogous to "limit maximum consumption per caller per window" in the referenced remediation).
3. Consider making queue/concurrency limits adaptive per observed abuse pattern (already partially supported via `Adaptive` settings) and add metrics/alerting on sustained per-key `ErrMaxQueueSize` rejection bursts so operators can detect this pattern.

### Proof of Concept
1. Identify (or arrange) a `RemoteIp` value shared with a victim population (e.g., requests traversing a common NAT gateway or corporate proxy address that Gitaly records as `RemoteIp`).
2. Repeatedly issue ordinary `git fetch`/`clone` operations (or, where reachable, `PackObjectsHookWithSidechannelRequest` calls) using that `RemoteIp`, each just cheap enough to occupy a queue slot in `runPackObjectsLimited` at `internal/gitaly/service/hook/pack_objects.go:176-212`.
3. Once `PackObjectsLimiting.MaxQueueSize` for that key is reached (`internal/limiter/concurrency_limiter.go:62-70`), any further requests from legitimate users sharing that `RemoteIp` value are rejected immediately with `ErrMaxQueueSize` (`internal/limiter/concurrency_limiter.go:219-224`), denying them service until the attacker's queued/in-flight requests complete — which the attacker can then repeat indefinitely.

// acquire tries to acquire the semaphore. It may fail if the admission queue is full or if the max
// queue-time ticker ticks before acquiring a concurrency token.
func (sem *keyedConcurrencyLimiter) acquire(ctx context.Context, limitingKey string) (returnedErr error) {
	if sem.queueTokens != nil {
		// Try to acquire the queueing token. The queueing token is used to control how many
		// callers may wait for the concurrency token at the same time. If there are no more
		// queueing tokens then this indicates that the queue is full and we thus return an
		// error immediately.
		if err := sem.queueTokens.TryAcquire(); err != nil {
			return err
		}
		// We have acquired a queueing token, so we need to release it if acquiring
		// the concurrency token fails. If we succeed to acquire the concurrency
		// token though then we retain the queueing token until the caller signals
		// that the concurrency-limited function has finished. As a consequence the
		// queue token is returned together with the concurrency token.
		//
		// A simpler model would be to just have `maxQueueLength` many queueing
		// tokens. But this would add concurrency-limiting when acquiring the queue
		// token itself, which is not what we want to do. Instead, we want to admit
		// as many callers into the queue as the queue length permits plus the
		// number of available concurrency tokens allows.
		defer func() {
			if returnedErr != nil {
				sem.queueTokens.Release()
			}
		}()
	}

func (c *ConcurrencyLimiter) Limit(ctx context.Context, limitingKey string, f LimitedFunc) (interface{}, error) {
	span, ctx := tracing.StartSpanIfHasParent(
		ctx,
		"limiter.ConcurrencyLimiter.Limit",
		[]attribute.KeyValue{
			attribute.String("key", limitingKey),
		},
	)
	defer span.End()

	if c.currentLimit() <= 0 {
		return f()
	}

	sem := c.getConcurrencyLimit(limitingKey)
	defer c.putConcurrencyLimit(limitingKey)

	start := time.Now()

	if err := sem.acquire(ctx, limitingKey); err != nil {
		queueTime := time.Since(start)
		switch {
		case errors.Is(err, ErrMaxQueueSize):
			c.monitor.Dropped(ctx, limitingKey, sem.queueLength(), sem.inProgress(), queueTime, "max_size")
			return nil, structerr.NewResourceExhausted("%w", ErrMaxQueueSize).WithDetail(&gitalypb.LimitError{
				ErrorMessage: err.Error(),
				RetryAfter:   durationpb.New(0),
			})
		case errors.Is(err, ErrMaxQueueTime):
			c.monitor.Dropped(ctx, limitingKey, sem.queueLength(), sem.inProgress(), queueTime, "max_time")
			return nil, structerr.NewResourceExhausted("%w", ErrMaxQueueTime).WithDetail(&gitalypb.LimitError{
				ErrorMessage: err.Error(),
				RetryAfter:   durationpb.New(0),
			})
		default:
			c.monitor.Dropped(ctx, limitingKey, sem.queueLength(), sem.inProgress(), queueTime, "other")
			return nil, fmt.Errorf("unexpected error when dequeueing request: %w", err)
		}
	}
