### Title
Signer event-receiver HTTP transport accepts unauthenticated POSTs for block-validation/StackerDB/burn-block events - (File: libsigner/src/events.rs)

### Summary
`SignerEventReceiver::next_event` (the signer-side HTTP listener that the Stacks node's event-observer POSTs to) dispatches `/stackerdb_chunks`, `/proposal_response`, and `/new_burn_block` requests straight into `process_event` with no authentication check whatsoever, even though the project's own documentation states that `auth_token` (node) / `auth_password` (signer) "must match" to secure this channel.

### Finding Description
The signer's event transport is implemented in `libsigner/src/events.rs`. `EventReceiver::main_loop` repeatedly calls `next_event`, which dispatches based solely on the URL path: [1](#0-0) 

There is no check of any `Authorization` header, bearer token, or shared secret anywhere in this file — a `grep` for `auth_token`/`Authorization`/`check_auth` across `libsigner/**` returns zero matches. The only gate is the URL string (`/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/status`, `/shutdown`), and the body is simply JSON-deserialized in `process_event`: [2](#0-1) 

By contrast, `docs/signing.md` explicitly documents `auth_token`/`auth_password` as a security control that "must match" between node and signer configs, and the sample configs (`mainnet-miner-conf.toml`, `testnet-miner-conf.toml`) present `[connection_options] auth_token` as guarding "Authentication for signer communication": [3](#0-2) [4](#0-3) 

That token is in fact consumed elsewhere in the codebase (`stackslib/src/net/api/postblock_proposal.rs`, `stackslib/src/net/connection.rs`) for the *node's* `/v3/block_proposal` RPC endpoint, but it is never referenced by, or plumbed into, the signer's own event-receiver transport in `libsigner`. This breaks the intended equality "only the paired node with the shared secret can push events to this signer" — the actual code accepts data from *any* peer that can reach the bound TCP port, regardless of whether it presents any credential.

The most impactful of the three unauthenticated endpoints is `/proposal_response`, which feeds a `BlockValidateResponse` directly into the signer's decision pipeline (via `SignerEvent`), and `/stackerdb_chunks`, which feeds a `StackerDBChunksEvent` (containing `StackerDBChunkData`, i.e. attacker-supplied `modified_slots`) into the same pipeline. I was not able to fully trace, within the tool budget available, whether every downstream consumer of `StackerDBChunksEvent`/`BlockValidateResponse` re-validates chunk signatures or block-validation provenance before acting on it (e.g. `stacks-signer/src/v0` message handling) — that would need to be confirmed by a background agent with fuller repository access. What is concrete and directly verified is that the transport layer itself performs no authentication before forwarding this attacker-reachable data into the signer runloop.

### Impact Explanation
If the signer's event-receiver bind address is reachable over the network (the sample configs show `endpoint = "127.0.0.1:30000"`, but nothing in the code enforces a loopback-only bind, and operators following the "must match" auth guidance would reasonably assume the `auth_token`/`auth_password` pairing is what protects this port from spoofed traffic), a remote, unauthenticated attacker can POST arbitrary `StackerDBChunksEvent` / `BlockValidateResponse` / `BurnBlockEvent` payloads directly to the signer, without ever touching the real Stacks node. This is an auth-gate that fails open on the transport that is supposed to be secured by a shared secret, and it directly reaches the signer's core decision loop (block approval, StackerDB chunk observation). Depending on what downstream code trusts unconditionally, this can range from injecting misleading/forged data into the signer's local state to influencing block-signing decisions — hence Critical-tier impact per the stated criteria ("unauthenticated/unauthorized write to state," "network-wide propagation of forged data").

### Likelihood Explanation
High for any deployment where the signer's `bind_addr` is reachable from outside strict loopback (a common misconfiguration given the documented reliance on the shared-secret pairing rather than network isolation), since exploitation requires nothing more than an HTTP POST with a well-formed JSON body to a known, documented path (`/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`).

### Recommendation
Add authentication (e.g., a bearer-token/HMAC check against the configured `auth_password`) inside `SignerEventReceiver::next_event` in `libsigner/src/events.rs` before dispatching to `process_event`, so the documented `auth_token`/`auth_password` contract is actually enforced by the transport code rather than existing only in configuration/documentation.

### Proof of Concept
Given a running signer with `SignerEventReceiver` bound to `HOST:PORT`, an attacker with network access can send:
```
POST /proposal_response HTTP/1.1
Host: HOST:PORT
Content-Type: application/json
Content-Length: <n>

{ ...forged BlockValidateResponse JSON... }
```
As shown in `libsigner/src/events.rs:437-447`, this reaches `process_event::<T, BlockValidateResponse>(request)` with no prior authentication check, identical to the legitimate node's own request path, since `next_event` performs no credential verification of any kind.

    fn next_event(&mut self) -> Result<SignerEvent<T>, EventError> {
        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)
            } else if request.url() == "/new_block" {
                process_event::<T, StacksBlockEvent>(request)
            } else {
                let url = request.url().to_string();
                debug!(
                    "[{:?}] next_event got request with unexpected url {}, return OK so other side doesn't keep sending this",
                    event_receiver.local_addr,
                    url
                );
                ack_dispatcher(request);
                Err(EventError::UnrecognizedEvent(url))
            }
        })?

fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}
