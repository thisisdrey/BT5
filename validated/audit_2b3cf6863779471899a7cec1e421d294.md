### Title
PeerDB neighbor records are keyed by self-reported (unverified) `HandshakeData.addrbytes/port` on first-time handshakes, allowing IP/port spoofing and cache poisoning - (File: `stackslib/src/net/chat.rs`, `stackslib/src/net/neighbors/db.rs`, `stackslib/src/net/neighbors/walk.rs`)

### Summary
`PeerDB` write paths triggered by a completed handshake key the stored `(addr, pubkey)` pair on the self-reported `HandshakeData.addrbytes`/`port` fields, not on the actual verified socket address of the connection. On the very first handshake of a fresh outbound connection (the common case when the neighbor-walk logic dials a "neighbor of a neighbor" it has never talked to before), `validate_handshake` only verifies the message signature and never checks that the claimed address matches the socket the connection was made to, so a remote peer using its own real key can claim to be located at an arbitrary victim IP/port and have that mapping written into the local node's `PeerDB`.

### Finding Description
`ConversationP2P::validate_handshake` (`stackslib/src/net/chat.rs:1047-1127`) has two branches depending on whether a public key is already known for the connection:
- `None` branch (first handshake ever on this connection) only calls `message.verify_secp256k1(&handshake_data.node_public_key)` — it never compares `handshake_data.addrbytes`/`port` to the actual TCP peer address [1](#0-0) .
- `Some(_)` branch (re-key) does check `self.peer_addrbytes`/`self.peer_port` against the claimed address, but only for outbound connections that already have a known key [2](#0-1) .

The neighbor-walk logic (`GetHandshakesBegin`/`GetHandshakesFinish`) dials newly-discovered "neighbors of a neighbor" addresses it has never connected to before — precisely the case where `get_public_key()` is `None` and no address check occurs. When the reply comes back, `handle_neighbor_handshake_accept` forwards the handshake data straight into `NeighborWalkDB::add_or_schedule_replace_neighbor` without any cross-check against the address that was actually dialed [3](#0-2) . That function calls `Neighbor::load_and_update`, which computes the PeerDB key via `NeighborKey::from_handshake(peer_version, network_id, handshake_data)` — i.e., using the self-reported `addrbytes`/`port`, not the dialed socket address — and then persists it with `neighbor_from_handshake.save(...)` (`PeerDB::try_insert_peer`) [4](#0-3) [5](#0-4) .

Because the attacker signs the entire `HandshakeData` (including the forged `addrbytes`/`port`) with its own real private key, the signature check passes trivially — the equality the audit asks about, `peerdb_entry.pubkey == verified_handshake_pubkey`, technically holds (the pubkey field is correctly the attacker's own verified key), but the **address** half of the key is never verified to correspond to a handshake actually completed from that address. The result is a `PeerDB` row `(victim_ip, victim_port) -> attacker_pubkey` created without ever contacting the victim.

Note that the sibling "pingback" code path (inbound-peer routability confirmation) *does* defend against this: `pingback_handshakes_try_finish` calls `check_handshake_pubkey_hash`, comparing the responder's key against the hash recorded from the original, actually-verified inbound connection, and rejects mismatches [6](#0-5) . The `GetHandshakesBegin`/`neighbor_handshakes_try_finish` path lacks any equivalent check.

This poisoned record is then served to other peers via `handle_getneighbors`, which selects rows from `PeerDB::get_fresh_random_neighbors` and returns them as `NeighborsData` [7](#0-6) , propagating the forged `(victim address, attacker pubkey)` association to the wider network.

### Impact Explanation
An unauthenticated remote peer can cause a node to write a false `(IP, port) -> public key` binding into its `PeerDB` for an address it does not control, without ever contacting that address. This is an unauthenticated write to node state, and because that state is served back out through `GetNeighbors`/`NeighborsData`, it enables network-wide propagation of forged neighbor data (nodes crawling this poisoned entry will attempt to dial the victim's address expecting the attacker's key, causing failed/misdirected walks, wasted connection attempts against the victim, and reputational/routing confusion in the frontier). This matches the "unauthenticated/unauthorized write to state" and "network-wide propagation of forged data" Critical categories.

### Likelihood Explanation
Preconditions are minimal: the attacker just needs to be reachable as a candidate "neighbor of a neighbor" for some already-connected honest peer (trivial — any peer that completes a normal handshake with any well-connected node will eventually be listed in that node's `GetNeighbors` replies) and respond to the resulting fresh outbound handshake with a forged `addrbytes`/`port`. No secrets, no privileged role, and no local access are required — the attacker only runs its own P2P peer and speaks the wire protocol. The attack is repeatable per neighbor-walk cycle and can target arbitrary victim addresses.

### Recommendation
For the initial (no-prior-key) handshake case in `validate_handshake`, and in the `GetHandshakesBegin`/`neighbor_handshakes_try_finish`/`add_or_schedule_replace_neighbor` path, require that the self-reported `addrbytes`/`port` match the actual dialed/peer socket address (mirroring the check already done in the re-key branch and in `check_handshake_pubkey_hash` for pingbacks) before using that address as the `PeerDB` key, unless the reported address is the any-network placeholder (in which case fall back to the confirmed socket address rather than trusting an arbitrary claimed address).

### Proof of Concept
Add a test in `stackslib/src/net/neighbors/walk.rs` (or a new integration test) that:
1. Sets up an honest node `N` and an attacker node `A` with `A`'s real keypair.
2. Registers `A` as a "neighbor of a neighbor" of `N` (i.e., seed `N`'s frontier so `GetHandshakesBegin` dials `A`'s real socket address).
3. Has `A`'s handshake-accept handler return `HandshakeAcceptData` whose `handshake.addrbytes`/`port` are set to a victim IP/port that `A` never actually listens on, while `handshake.node_public_key` is `A`'s real key, correctly signed.
4. Drives `N`'s walk state machine through `neighbor_handshakes_begin`/`neighbor_handshakes_try_finish`.
5. Asserts that `PeerDB::get_peer(N.peerdb_conn(), network_id, victim_addrbytes, victim_port)` returns `Some(neighbor)` with `neighbor.public_key == A`'s pubkey — demonstrating that `N`'s `PeerDB` now contains a forged `(victim_addr) -> A_pubkey` record despite never having handshaken with the victim's address, contradicting the required invariant that `peerdb_entry.pubkey` correspond to a handshake actually completed from the keyed address.

    fn handle_getneighbors(
        &mut self,
        network: &PeerNetwork,
        preamble: &Preamble,

        monitoring::increment_msg_counter("p2p_get_neighbors".to_string());

        // get neighbors at random as long as they're fresh, and as long as they're compatible with
        // the current system epoch.

        // the time being, the remote peer has no way of asking for a particular subset.
        let mut neighbors = PeerDB::get_fresh_random_neighbors(
            peer_dbconn,
            self.network_id,
            epoch.network_epoch,
            self.peer_version,
            get_epoch_time_secs().saturating_sub(self.connection.options.max_neighbor_age),
            MAX_NEIGHBORS_DATA_LEN,
            chain_view.burn_block_height,
            false,
            thread_rng().gen(),
        )
        .map_err(net_error::DBError)?;

        if cfg!(test) && self.connection.options.disable_chat_neighbors {
            // never report neighbors if this is disabled by a test
            debug!(
                "{:?}: Neighbor crawl is disabled; reporting 0 neighbors",
                &local_peer
            );
            neighbors.clear();
        }

        let neighbor_addrs: Vec<NeighborAddress> = neighbors
            .iter()
            .map(NeighborAddress::from_neighbor)
            .collect();

        debug!(
            "{:?}: handle GetNeighbors from {:?}. Reply with {} neighbors",
            &local_peer,
            &self,
            neighbor_addrs.len()
        );

        let payload = StacksMessageType::Neighbors(NeighborsData {
            neighbors: neighbor_addrs,
        });
        let reply = self.sign_reply(chain_view, &local_peer.private_key, payload, preamble.seq)?;
        let reply_handle = self
            .relay_signed_message(reply)
            .inspect_err(|_e| debug!("Outbox to {self:?} is full; cannot reply to GetNeighbors"))?;

        Ok(reply_handle)
    }

    /// Does a given handshakedata represent an expected public key hash?
    fn check_handshake_pubkey_hash(
        nk: &NeighborKey,
        data: &HandshakeAcceptData,
        naddr: &NeighborAddress,
    ) -> bool {
        let neighbor_pubkey_hash =
            Hash160::from_node_public_key_buffer(&data.handshake.node_public_key);
        if neighbor_pubkey_hash != naddr.public_key_hash {
            debug!(
                "Neighbor {:?} had an unexpected pubkey hash: expected {:?} != {:?}",
                nk, &naddr.public_key_hash, &neighbor_pubkey_hash
            );
            return false;
        }

        true
    }

    /// Finish up connecting to newly-discovered inbound peers
    pub fn pingback_handshakes_try_finish(
        &mut self,
        network: &mut PeerNetwork,
    ) -> Result<bool, net_error> {
        assert!(self.state == NeighborWalkState::PingbackHandshakesFinish);

        // see if we got any replies
        for (naddr, message) in self.comms.collect_replies(network).into_iter() {
            // if we got back a HandshakeAccept, and it's on the same chain as us, we're good!
            let (data, db_data) = match message.payload {
                StacksMessageType::HandshakeAccept(ref data) => {
                    debug!("{:?}: received HandshakeAccept from peer {:?}; now known to be routable from us", network.get_local_peer(), &message.to_neighbor_key(&data.handshake.addrbytes, data.handshake.port));
                    (data, None)
                }
                StacksMessageType::StackerDBHandshakeAccept(ref data, ref db_data) => {
                    debug!("{:?}: received StackerDBHandshakeAccept from peer {:?}; now known to be routable from us", network.get_local_peer(), &message.to_neighbor_key(&data.handshake.addrbytes, data.handshake.port));
                    (data, Some(db_data))
                }
                _ => {
                    let nkey = naddr.to_neighbor_key(network);
                    debug!(
                        "{:?}: Neighbor {:?} replied {:?} instead of pingback handshake",
                        network.get_local_peer(),
                        &nkey,
                        &message.get_message_name()
                    );
                    continue;
                }
            };

            let peer_nk = message.to_neighbor_key(&data.handshake.addrbytes, data.handshake.port);
            if !Self::check_handshake_pubkey_hash(&peer_nk, data, &naddr) {
                continue;
            }

            self.neighbor_db.add_or_schedule_replace_neighbor(
                network,
                &message.preamble,
                &data.handshake,
                db_data,
                &mut self.neighbor_replacements,
            )?;
        }

        let tx = network.peerdb_tx_begin()?;

            Neighbor::load_and_update(&tx, preamble.peer_version, preamble.network_id, handshake)?;

        if was_present {

                "{}: already know about neighbor {:?}",

        if added {
            // neighbor was new, and we had space to add it.
            tx.commit()?;
