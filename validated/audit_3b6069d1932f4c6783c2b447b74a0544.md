### Title
`CommitIsAncestor` RPC collapses all `git-merge-base --is-ancestor` failures into a false "not ancestor" result instead of surfacing real errors - (File: internal/gitaly/service/commit/isancestor.go)

### Summary
This is the gitaly analog of the ERC20 return-value-checking bug class: instead of discriminating between the different ways an external operation can signal a definitive result versus a genuine failure, the `commitIsAncestorName` handler collapses every possible outcome of `git-merge-base --is-ancestor` into a boolean by checking only `cmd.Wait() == nil`. Any non-zero exit — whether it means "not an ancestor" (exit 1) or a hard failure such as an invalid/missing object, corrupted repository state, or a killed/crashed process (exit 128 or higher, signals, etc.) — is silently reported as `Value: false` with `err == nil`, exactly analogous to treating a reverted/failed ERC20 transfer as a successful "false" return rather than surfacing the failure.

### Finding Description
`CommitIsAncestor` is a public, unprivileged-reachable gitaly RPC (`op_type: ACCESSOR`) that takes attacker/user-influenced `AncestorId`/`ChildId` strings and executes `git merge-base --is-ancestor <ancestor> <child>`: [1](#0-0) 

`git merge-base --is-ancestor` can exit with:
- `0` — the first commit is an ancestor of the second (true)
- `1` — the first commit is *not* an ancestor (false)
- other codes (typically `128`) — invalid/unresolvable revision, corrupted object, or other fatal git errors

The handler only distinguishes success (`nil` error) from failure, mapping *every* failure to `false` with no error: [2](#0-1) 

Contrast this with the sibling implementation `Repo.IsAncestor` in `internal/git/localrepo/commit.go`, which explicitly discriminates exit code `1` (genuine "not ancestor") from other exit statuses (which are surfaced as errors, including a dedicated `InvalidCommitError`): [3](#0-2) 

The gRPC-facing `commitIsAncestorName` does not apply this same discrimination, so a caller supplying a malformed, non-existent, or otherwise unresolvable `ancestor_id`/`child_id`, or any transient git failure (e.g., resource exhaustion, packfile corruption, or command timeout/kill), is indistinguishable at the RPC boundary from a legitimate, confirmed "not an ancestor" answer.

### Impact Explanation
Callers of `CommitIsAncestor` (e.g., GitLab Rails for force-push protection, fast-forward-only merge checks, protected-branch history-rewrite detection) rely on a boolean ancestry verdict to make authorization/safety decisions. Because the handler always returns a confident `false` on any non-zero exit rather than an error, a caller cannot tell "confirmed not ancestor" apart from "the check itself failed/errored." Any code path that treats a non-error `false` response as an authoritative negative answer (rather than retrying or failing closed) can be misled into approving destructive operations (e.g., a force push / history rewrite) under the belief that ancestry was definitively disproven, when in fact the underlying git invocation errored out (e.g., due to a crafted invalid revision string or an intermittent git failure) and never actually determined ancestry. This is a decision-logic integrity bug at a security-relevant boundary (branch protection / history-rewrite gating), reachable by any client that can call this ACCESSOR RPC with attacker-controlled commit identifiers.

### Likelihood Explanation
The RPC is reachable by any authenticated gitaly client without special privilege (it is a plain `ACCESSOR`), and the two input fields (`ancestor_id`, `child_id`) are free-form strings passed directly as `git merge-base` arguments, so a wide range of invalid/edge-case values (non-existent OIDs, malformed strings, revisions pointing at missing/corrupted objects) are trivially reachable and will drive git into its non-`0`/non-`1` exit paths. Exploitability of the downstream impact depends on how the consuming caller (e.g., GitLab Rails) interprets a `false, nil` response, which is outside this repository, so likelihood of the impact escalating into an actual authorization bypass depends on external logic that could not be fully verified here.

### Recommendation
Mirror the discrimination already implemented in `internal/git/localrepo/commit.go`'s `IsAncestor`: in `commitIsAncestorName`, use `command.ExitStatus` to check specifically for exit code `1` and return `(false, nil)` only in that case; for any other exit status (or non-`exec.ExitError` failure), return `(false, err)` so the gRPC handler surfaces an `Internal`/appropriate error instead of a false "confirmed not ancestor" result. Additionally consider mapping invalid/missing revision errors to a distinct error type (as `InvalidCommitError` already does) so callers can distinguish "bad input" from "definitively not an ancestor."

### Proof of Concept
1. Call `CommitIsAncestor` with `AncestorId` set to a syntactically valid-looking but non-existent object ID (or any string causing `git merge-base --is-ancestor` to fail with exit code `128`, e.g. `"fatal: Not a valid object name"`). [2](#0-1) 
2. Observe that the RPC returns `CommitIsAncestorResponse{Value: false}` with `err == nil`, identical to the response for a genuinely confirmed non-ancestor pair (as covered by the "not an ancestor" test case). [4](#0-3) 
3. A caller cannot distinguish this failure case from a legitimate "not an ancestor" verdict, since no error is propagated—unlike `Repo.IsAncestor`, which would return a distinguishable error (`InvalidCommitError` or a generic error) for the same input. [5](#0-4)

func (s *server) commitIsAncestorName(ctx context.Context, repo gitcmd.RepositoryExecutor, ancestorID, childID string) (bool, error) {
	s.logger.WithFields(log.Fields{
		"ancestorSha": ancestorID,
		"childSha":    childID,
	}).DebugContext(ctx, "commitIsAncestor")

	cmd, err := repo.Exec(ctx, gitcmd.Command{
		Name:  "merge-base",
		Flags: []gitcmd.Option{gitcmd.Flag{Name: "--is-ancestor"}}, Args: []string{ancestorID, childID},
	})
	if err != nil {
		return false, structerr.NewInternal("%w", err)
	}

	return cmd.Wait() == nil, nil

func (repo *Repo) IsAncestor(ctx context.Context, parent, child git.Revision) (bool, error) {
	const notValidCommitName = "fatal: Not a valid commit name"

	stderr := &bytes.Buffer{}
	if err := repo.ExecAndWait(ctx,
		gitcmd.Command{
			Name:  "merge-base",
			Flags: []gitcmd.Option{gitcmd.Flag{Name: "--is-ancestor"}},
			Args:  []string{parent.String(), child.String()},
		},
		gitcmd.WithStderr(stderr),
	); err != nil {
		status, ok := command.ExitStatus(err)
		if ok && status == 1 {
			return false, nil
		} else if ok && strings.HasPrefix(stderr.String(), notValidCommitName) {
			commitOID := strings.TrimSpace(strings.TrimPrefix(stderr.String(), notValidCommitName))
			return false, InvalidCommitError(commitOID)
		}

		return false, fmt.Errorf("determine ancestry: %w, stderr: %q", err, stderr)
	}

	return true, nil
}
