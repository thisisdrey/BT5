Audit Report

## Title
`Pallet::unbond` computes unbonding balance from stale point/balance ratio without applying pending slash - (File: substrate/frame/nomination-pools/src/lib.rs)

## Summary
The `unbond` extrinsic [1](#0-0)  computes `unbonding_balance` via `bonded_pool.dissolve(unbonding_points)` using the pool's currently recorded `points`/`active_stake` ratio, without first calling `do_apply_slash` to absorb any pending slash on the pool's stake account. In contrast, `withdraw_unbonded` explicitly calls `Self::do_apply_slash(&member_account, None, false)` before computing the amount to release [2](#0-1) .

## Finding Description
`member_pending_slash` shows that a pool's ratio depends on `T::StakeAdapter::pending_slash(pool_account)` and the discrepancy between `member_delegation_balance` and `pool_member.total_balance()` [3](#0-2) . Because a slash is applied lazily to `pending_slash` on the pool's stake account but the `BondedPool.points`↔balance ratio is only corrected via `do_apply_slash`, calling `unbond` while a slash is pending (i.e., recorded but not yet applied) lets a member dissolve points using a stale, pre-slash ratio. `withdraw_unbonded`'s code comment itself acknowledges this is only an expected—not guaranteed—precondition ("pool slashes must have been already applied via permissionless `Call::apply_slash`") [4](#0-3) , and the defensive re-sync exists precisely to close that gap for `withdraw_unbonded`, but the equivalent call is absent from `unbond`.

## Impact Explanation
This allows an unbonding member to lock in a favorable pre-slash points/balance exchange rate into the `UnbondPool`, shifting the slash's economic burden onto members who remain in the pool or unbond after `apply_slash` corrects the ratio — a violation of exact value conservation/settlement for pooled staking funds, matching the "theft or unbacked mint/unlock" and value-conservation impact categories for `pallet-nomination-pools`.

## Likelihood Explanation
Exploitation requires no privilege: any pool member holding points can call the public `unbond` extrinsic at the moment a slash has been reported against the pool's stake account but before `apply_slash`/`withdraw_unbonded` has been (permissionlessly) invoked for that pool — a normal, unprivileged, and repeatable transient runtime state.

## Recommendation
Add a call to `Self::do_apply_slash(&member_account, None, false)` (tolerating `Error::<T>::NothingToSlash`) at the start of `unbond`, before `bonded_pool.dissolve` and `T::StakeAdapter::unbond` are invoked, mirroring the defensive synchronization already present in `withdraw_unbonded`.

## Proof of Concept
1. Pool uses `DelegateStake` strategy; member Alice holds `points` worth balance `X`.
2. An offence is reported against the pool's stash, setting `T::StakeAdapter::pending_slash(pool)` non-zero, prior to any `apply_slash` call.
3. Alice calls `unbond`; `bonded_pool.dissolve(unbonding_points)` at [5](#0-4)  computes `unbonding_balance` from the pre-slash ratio, extracting more than her fair post-slash share.
4. When `apply_slash` eventually runs for remaining members, Alice's already-departed `unbonding_balance` is unaffected, so remaining members absorb a disproportionate share of the slash.

		#[pallet::weight(T::WeightInfo::unbond())]
		pub fn unbond(
			origin: OriginFor<T>,
			member_account: AccountIdLookupOf<T>,
			#[pallet::compact] unbonding_points: BalanceOf<T>,
		) -> DispatchResult {
			let who = ensure_signed(origin)?;
			let member_account = T::Lookup::lookup(member_account)?;
			// ensure member is not in an un-migrated state.
			ensure!(
				!Self::api_member_needs_delegate_migration(member_account.clone()),
				Error::<T>::NotMigrated
			);

			let (mut member, mut bonded_pool, mut reward_pool) =
				Self::get_member_with_pools(&member_account)?;

			bonded_pool.ok_to_unbond_with(&who, &member_account, &member, unbonding_points)?;

			// Claim the the payout prior to unbonding. Once the user is unbonding their points no
			// longer exist in the bonded pool and thus they can no longer claim their payouts. It
			// is not strictly necessary to claim the rewards, but we do it here for UX.
			reward_pool.update_records(
				bonded_pool.id,
				bonded_pool.points,
				bonded_pool.commission.current(),
			)?;
			Self::do_reward_payout(
				&member_account,
				&mut member,
				&mut bonded_pool,
				&mut reward_pool,
			)?;

			let active_era = T::StakeAdapter::current_era();
			let unbond_era = T::StakeAdapter::bonding_duration().saturating_add(active_era);

			// Unbond in the actual underlying nominator.
			let unbonding_balance = bonded_pool.dissolve(unbonding_points);
			T::StakeAdapter::unbond(Pool::from(bonded_pool.bonded_account()), unbonding_balance)?;

	/// Pending slash for a member.
	///
	/// Takes the pool_member object corresponding to the `member_account`.
	fn member_pending_slash(
		member_account: Member<T::AccountId>,
		pool_member: PoolMember<T>,
	) -> Result<BalanceOf<T>, DispatchError> {
		// only executed in tests: ensure the member account is correct.
		debug_assert!(
			PoolMembers::<T>::get(member_account.clone().get()).expect("member must exist") ==
				pool_member
		);

		let pool_account = Pallet::<T>::generate_bonded_account(pool_member.pool_id);
		// if the pool doesn't have any pending slash, it implies the member also does not have any
		// pending slash.
		if T::StakeAdapter::pending_slash(Pool::from(pool_account.clone())).is_zero() {
			return Ok(Zero::zero());
		}

		// this is their actual held balance that may or may not have been slashed.
		let actual_balance = T::StakeAdapter::member_delegation_balance(member_account)
			// no delegation implies the member delegation is not migrated yet to `DelegateStake`.
			.ok_or(Error::<T>::NotMigrated)?;

		// this is their balance in the pool
		let expected_balance = pool_member.total_balance();

		// return the amount to be slashed.
		Ok(actual_balance.saturating_sub(expected_balance))
	}
