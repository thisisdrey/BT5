Audit Report

## Title
Snowbridge relayer-tip flow permanently burns user funds with no recovery path when the remote `add_tip` fails - (File: `bridges/snowbridge/pallets/system-frontend/src/lib.rs`)

## Summary
`pallet-snowbridge-system-frontend::add_tip` irrevocably burns the caller's converted-to-Ether asset on the local chain before the corresponding remote `EthereumSystem::add_tip` call on BridgeHub is guaranteed to succeed. If the remote call fails because the message nonce was already consumed (a normal, non-malicious race with honest relayer processing), the burned value is only recorded into `LostTips` — a storage map with no extrinsic anywhere in the codebase to claim or refund it.

## Finding Description
`add_tip` calls `swap_fee_asset_and_burn`, which unconditionally converts and burns the caller's asset via `burn_for_teleport` before any confirmation of remote success: [1](#0-0) [2](#0-1) 

The resulting `ether_gained` is packaged into an `EthereumSystemCall::AddTip` and dispatched via unpaid, fire-and-forget XCM `Transact` to BridgeHub, with no callback for failure: [3](#0-2) 

On BridgeHub, `InboundQueue::add_tip` (implementing the `AddTip` trait) explicitly rejects the tip if the nonce has already been consumed by ordinary, permissionless message processing: [4](#0-3)  This nonce-consumption check races directly against `process_message`, which sets `Nonce::<T>::set(nonce)` as soon as any relayer submits the message: [5](#0-4) 

`system-v2::add_tip` catches this failure and only records it into `LostTips`, emitting `TipProcessed{success: false}` but returning `Ok(())` — never reverting or refunding: [6](#0-5) 

`LostTips` is explicitly documented as merely a placeholder pending a future (nonexistent) recovery mechanism: [7](#0-6)  No extrinsic in `system-v2` or `system-frontend` reads or clears `LostTips`. The `AddTipError` enum confirms `NonceConsumed`, `UnknownMessage`, and `AmountZero` are all expected, reachable failure modes, not exceptional/malicious conditions: [8](#0-7) 

The burn on AssetHub and the tip-attach on BridgeHub are two separate, non-atomic operations connected only by a best-effort unpaid XCM message, so any timing where an honest relayer processes the referenced message before the `Transact` executes results in permanently destroyed value with no compensating credit anywhere in the system.

## Impact Explanation
This matches the allowed impact category "permanent user-fund or bridge-state lock": real asset value is burned on the source chain (AssetHub) with no compensating mint, no relayer reward credit, and no extrinsic to reclaim the amount recorded in `LostTips`. This is a genuine value-conservation break — the accounting violates the requirement that message queues, bridge markers, and payout state must only advance after the operation succeeds atomically; here, the burn happens unconditionally before success is known.

## Likelihood Explanation
No malicious actor, governance action, or privileged capability is required — only an ordinary, unprivileged user calling the public `add_tip` extrinsic on a message that is concurrently or subsequently processed by any honest relayer via the equally public, permissionless `submit`/`process_message` path. Given that message processing races with tipping are a routine and expected part of bridge operation (the code even names `NonceConsumed` as an anticipated `AddTipError` variant), this is a realistic and repeatable occurrence, not a contrived edge case.

## Recommendation
Make the tip burn conditional and reversible: either hold/reserve the tip asset on the frontend chain until BridgeHub confirms successful tip attachment (two-phase commit), or add a claim/refund extrinsic on `system-v2`/`system-frontend` that lets the `sender` recorded in `LostTips` reclaim (mint back) the lost amount, using the existing XCM/`PaymentProcedure` infrastructure already used for relayer rewards.

## Proof of Concept
1. Alice calls `EthereumSystemFrontend::add_tip(message_id=Inbound(N), asset=(DOT, X))` on AssetHub; `swap_fee_asset_and_burn` swaps and burns Alice's `X` DOT irrevocably (`system-frontend/src/lib.rs:372-404`).
2. Before the XCM `Transact` executes on BridgeHub, an honest relayer submits inbound message nonce `N` via `InboundQueue::submit`, causing `process_message` to set `Nonce::<T>::set(N)` (`inbound-queue-v2/src/lib.rs:214-245`).
3. The delayed `Transact` executes `EthereumSystemCall::AddTip{sender: Alice, message_id: Inbound(N), amount}` on BridgeHub; `InboundQueue::add_tip` returns `Err(AddTipError::NonceConsumed)` because `Nonce::<T>::get(N)` is true (`inbound-queue-v2/src/lib.rs:248-258`).
4. `system-v2::add_tip` records `LostTips::<T>::mutate(&Alice, ...)`, emits `TipProcessed{success: false}`, and returns `Ok(())` (`system-v2/src/lib.rs:266-270`).
5. Alice's burned DOT/Ether is permanently gone — never credited to any relayer reward and unrecoverable, since no extrinsic reads or clears `LostTips`.

		fn swap_fee_asset_and_burn(
			origin: Location,
			fee_asset: Asset,
		) -> Result<u128, DispatchError> {
			let ether_location = T::EthereumLocation::get();
			let (fee_asset_location, fee_amount) = match fee_asset {
				Asset { id: AssetId(ref loc), fun: Fungible(amount) } => (loc, amount),
				_ => {
					tracing::debug!(target: LOG_TARGET, ?fee_asset, "error matching fee asset");
					return Err(Error::<T>::UnsupportedAsset.into());
				},
			};
			if fee_amount == 0 {
				return Ok(0);
			}

			let ether_gained = if *fee_asset_location != ether_location {
				Self::swap_and_burn(
					origin.clone(),
					fee_asset_location.clone(),
					ether_location,
					fee_amount,
				)
				.inspect_err(|&e| {
					tracing::debug!(target: LOG_TARGET, ?e, "error swapping asset");
				})?
			} else {
				burn_for_teleport::<T::AssetTransactor>(&origin, &fee_asset)
					.map_err(|_| Error::<T>::BurnError)?;
				fee_amount
			};
			Ok(ether_gained)
		}

	impl<T: Config> Pallet<T> {
		pub fn process_message(relayer: T::AccountId, message: Message) -> DispatchResult {
			// Verify that the message was submitted from the known Gateway contract
			ensure!(T::GatewayAddress::get() == message.gateway, Error::<T>::InvalidGateway);

			let (nonce, relayer_fee) = (message.nonce, message.relayer_fee);

			// Verify the message has not been processed
			ensure!(!Nonce::<T>::get(nonce), Error::<T>::InvalidNonce);

			// Mark message as received
			Nonce::<T>::set(nonce);

			let message_id = T::MessageProcessor::process_message(relayer.clone(), message)
				.map_err(|e| match e {
					MessageProcessorError::ProcessMessage(e) => e,
					MessageProcessorError::ConvertMessage(e) => Error::<T>::from(e).into(),
					MessageProcessorError::SendMessage(e) => Error::<T>::from(e).into(),
				})?;

			// Pay relayer reward
			let tip = Tips::<T>::take(nonce).unwrap_or_default();
			let total_tip = relayer_fee.saturating_add(tip);
			if total_tip > 0 {
				T::RewardPayment::register_reward(&relayer, T::DefaultRewardKind::get(), total_tip);
			}

			// Emit event with the message_id
			Self::deposit_event(Event::MessageReceived { nonce, message_id });

			Ok(())
		}

	impl<T: Config> AddTip for Pallet<T> {
		fn add_tip(nonce: u64, amount: u128) -> Result<(), AddTipError> {
			ensure!(amount > 0, AddTipError::AmountZero);
			// If the nonce is already processed, return an error
			ensure!(!Nonce::<T>::get(nonce.into()), AddTipError::NonceConsumed);
			// Otherwise add the tip.
			Tips::<T>::mutate(nonce, |tip| {
				*tip = Some(tip.unwrap_or_default().saturating_add(amount));
			});
			return Ok(());
		}
	}

		#[pallet::call_index(3)]
		#[pallet::weight(<T as pallet::Config>::WeightInfo::add_tip())]
		pub fn add_tip(
			origin: OriginFor<T>,
			sender: AccountIdOf<T>,
			message_id: MessageId,
			amount: u128,
		) -> DispatchResult {
			T::FrontendOrigin::ensure_origin(origin)?;

			let result = match message_id {
				Inbound(nonce) => <T as pallet::Config>::InboundQueue::add_tip(nonce, amount),
				Outbound(nonce) => <T as pallet::Config>::OutboundQueue::add_tip(nonce, amount),
			};

			if let Err(ref e) = result {
				tracing::debug!(target: LOG_TARGET, ?e, ?message_id, ?amount, "error adding tip");
				LostTips::<T>::mutate(&sender, |lost_tip| {
					*lost_tip = lost_tip.saturating_add(amount);
				});
			}

			Self::deposit_event(Event::<T>::TipProcessed {
				sender,
				message_id,
				amount,
				success: result.is_ok(),
			});

			Ok(())
		}
