### Title
Unbounded delegation index scan in `DelegatedResourceAccountIndexStore.getWithPrefix` leads to CPU/DoS in `Wallet.getDelegatedResourceAccountIndex(V2)` and `FreezeBalanceActuator`/`DelegateResourceActuator` - (File: chainbase/src/main/java/org/tron/core/store/DelegatedResourceAccountIndexStore.java)

### Summary
`DelegatedResourceAccountIndexStore.getWithPrefix` performs an unbounded `prefixQuery` over the whole `DelegatedResourceAccountIndex`/`DelegatedResourceAccountIndexV2` column family for a given address, materializes every matching entry into an `ArrayList`, and sorts the entire list, with no limit on how many delegation relationships an attacker can create for a single address.

### Finding Description
`getWithPrefix` (called from `getIndex`/`getV2Index`) scans all keys under the `FROM_PREFIX`/`TO_PREFIX` (or `V2_FROM_PREFIX`/`V2_TO_PREFIX`) for an address and loads them all into memory before sorting: [1](#0-0) 

Each entry in this prefix range is created by `delegate()`/`delegateV2()`, invoked from `FreezeBalanceActuator.delegateResource` whenever a user freezes/delegates bandwidth or energy to a receiver: [2](#0-1) 

An unprivileged account can broadcast many `FreezeBalanceContract` (or `DelegateResourceContract`) transactions, each delegating the protocol minimum (1 TRX) to a distinct freshly-generated receiver address, creating an unbounded number of `from->to` and `to->from` index entries keyed by the attacker's own address. There is no cap in `FreezeBalanceActuator.validate()` on the number of distinct receivers an account can delegate to over time, only a cap of one/zero *self*-frozen entries: [3](#0-2) 

The legacy `convert()` path also iterates the entire old-format `toList`/`fromList` for an address and re-inserts each entry one at a time when the optimization flag is enabled, which is invoked synchronously during `delegateResource` execution (i.e., inside actuator/transaction execution, not just query serving): [4](#0-3) 

Both `getIndex`/`getV2Index` are exposed directly to any anonymous API client through the gRPC and HTTP/JSON-RPC wallet APIs: [5](#0-4) [6](#0-5) [7](#0-6) 

This is structurally the same bug class as `BountyCore.getLockedFunds`: a store-level function loops/collects over an attacker-growable list with no size bound, and that function is reachable both from a public read API and from transaction execution.

### Impact Explanation
An attacker only needs enough TRX to satisfy the 1-TRX-per-delegation minimum to inflate the from/to index for their own address to an arbitrary size. Every subsequent call to `getDelegatedResourceAccountIndex`/`getDelegatedResourceAccountIndexV2` for that address (callable by any unauthenticated API client) forces the node to scan and sort the full prefix range, consuming CPU/memory proportional to the number of delegations the attacker created. Because `convert()`/`getWithPrefix` are also invoked as part of normal `FreezeBalanceActuator`/`DelegateResourceActuator` execution, this can also slow down or degrade actuator execution during block application for transactions touching that account, extending the resource-exhaustion impact beyond just the read API into transaction processing.

### Likelihood Explanation
Any single funded account can trigger this without special privileges — only the ability to broadcast standard `FreezeBalanceContract`/`DelegateResourceContract` transactions to many distinct receiver addresses, each requiring only the protocol minimum of 1 TRX. No SR/witness/committee/peer role is required, satisfying the "unprivileged transaction broadcaster" and "HTTP/gRPC query path" reachability criteria.

### Recommendation
Bound the number of distinct delegation relationships (`from`/`to` entries) an account can accumulate, or replace the full-prefix scan-and-sort in `getWithPrefix` with a paginated/limited query, and avoid full-list materialization in `convert()`. Consider deprecating/rate-limiting the unbounded `getDelegatedResourceAccountIndex(V2)` query paths, or requiring pagination parameters similar to `GetPaginatedNowWitnessList`.

### Proof of Concept
1. Attacker generates N new receiver addresses.
2. Attacker submits N `FreezeBalanceContract` transactions from a single owner address, each delegating the minimum 1 TRX of BANDWIDTH/ENERGY to a distinct receiver (`FreezeBalanceActuator.delegateResource`), populating N `from->to`/`to->from` entries in `DelegatedResourceAccountIndexStore`.
3. Attacker (or anyone) repeatedly calls the public `getdelegatedresourceaccountindexv2` HTTP/gRPC endpoint for the owner address, forcing `getWithPrefix` to scan and sort all N entries on every call, consuming node CPU/memory proportional to N with no upper bound.

  private DelegatedResourceAccountIndexCapsule getWithPrefix(byte[] fromPrefix, byte[] toPrefix, byte[] address) {
    DelegatedResourceAccountIndexCapsule tmpIndexCapsule =
        new DelegatedResourceAccountIndexCapsule(ByteString.copyFrom(address));

    byte[] key = Bytes.concat(fromPrefix, address);
    List<DelegatedResourceAccountIndexCapsule> tmpToList =
        new ArrayList<>(this.prefixQuery(key).values());
    tmpToList.sort(Comparator.comparing(DelegatedResourceAccountIndexCapsule::getTimestamp));
    List<ByteString> list = tmpToList.stream()
        .map(DelegatedResourceAccountIndexCapsule::getAccount).collect(Collectors.toList());
    tmpIndexCapsule.setAllToAccounts(list);

    key = Bytes.concat(toPrefix, address);
    List<DelegatedResourceAccountIndexCapsule> tmpFromList =
        new ArrayList<>(this.prefixQuery(key).values());
    tmpFromList.sort(Comparator.comparing(DelegatedResourceAccountIndexCapsule::getTimestamp));
    list = tmpFromList.stream().map(DelegatedResourceAccountIndexCapsule::getAccount).collect(
        Collectors.toList());
    tmpIndexCapsule.setAllFromAccounts(list);
    return tmpIndexCapsule;
  }

  public DelegatedResourceAccountIndex getDelegatedResourceAccountIndex(ByteString address) {
    if (address == null || address.size() != DecodeUtil.ADDRESS_SIZE / 2) {
      return DelegatedResourceAccountIndex.getDefaultInstance();
    }
    DelegatedResourceAccountIndexCapsule accountIndexCapsule =
        chainBaseManager.getDelegatedResourceAccountIndexStore().getIndex(address.toByteArray());
    if (accountIndexCapsule != null) {
      return accountIndexCapsule.getInstance();
    } else {
      return DelegatedResourceAccountIndex.getDefaultInstance();
    }
  }
