Confirmed: `LinkRepositoryToObjectPool` performs no check that `repository != pool.Repository` before calling `pool.Link()`, and `Link()` itself never compares the two repository identities. [1](#0-0) 

### Title
Self-linking a repository to its own object pool creates a self-referential alternate and permanently DoSes the repository - (File: `internal/git/objectpool/link.go`)

### Summary
`LinkRepositoryToObjectPool` and the underlying `objectpool.Link()` never verify that the target `repository` differs from the `object_pool`'s own repository. Just as the reported `PanopticPool` refund logic assumes the two parties in a transfer are distinct and silently becomes a no-op/self-transfer when `account == msg.sender`, Gitaly's alternates-linking logic assumes `pool` and `repo` are distinct repositories and produces a broken self-referential state when they coincide.

### Finding Description
`LinkRepositoryToObjectPool` builds `pool` from `req.GetObjectPool()` and `repo` from `req.GetRepository()` independently and validates only that the repository exists — never that `repo.RelativePath != pool.RelativePath` (or storage) — before calling `pool.Link(ctx, repo)`: [1](#0-0) 

Inside `objectpool.Link()`, when `pool` and `repo` resolve to the same on-disk repository:

- `getRelativeObjectPath` computes the alternate path relative to the repo's own `objects` directory. When `poolPath == repoPath`, `filepath.Rel(repoPath/objects, poolPath)` yields `".."`, so the alternate entry written is `"../objects"`, which resolves back to the repository's own `objects` directory — i.e. the alternates file references itself: [2](#0-1) 
- The code then unconditionally writes this alternate into the repository's own `objects/info/alternates` file via `safe.NewLockingFileWriter`/`transaction.CommitLockedFile`, with no self-reference guard analogous to the one Gitaly already applies elsewhere: [3](#0-2) 
- `removeMemberBitmaps(ctx, pool, repo)` is then invoked with `pool == repo`, so it looks up "member" bitmaps and pool bitmaps in the *same* directory and deletes them, destroying the repository/pool's own bitmap: [4](#0-3) 

Gitaly is fully aware that self-referential alternates are invalid and dangerous — it explicitly detects and rejects them in the partition assignment path: `alternateRelativePath == relativePath` returns `storage.ErrAlternatePointsToSelf` [5](#0-4) . However, that guard only runs later, during transaction/partition setup — it does not prevent `objectpool.Link()` from writing the corrupt alternates file in the first place, and it doesn't run for non-transactional (Rugged/legacy) storage configurations at all. This is exactly the "assumes source and destination are distinct parties" failure pattern from the reported bug: the safety mechanism (partition self-alternate check, or the absent check in `Link`) is not applied at the point where the corrupting write happens.

### Impact Explanation
Once the self-referential alternates file is written:
1. On transactional storage, the repository becomes permanently unable to start write transactions: every future `Begin` call re-reads the alternates file via `getAlternatePartitionID` and fails with `storage.ErrAlternatePointsToSelf`, which is returned all the way up through `assignPartitionID`/`getPartitionIDRecursive` — a persistent denial of service for that repository until manually repaired. [6](#0-5) 
2. The repository's packfile bitmap is deleted as a side effect of `removeMemberBitmaps` treating the repo as its own "member," degrading performance for reads/clones that rely on bitmaps.
3. Any RPC/tooling that walks alternates for object listing (`internal/git/dirs.go`) will recurse up to `maxAlternatesDepth` before giving up, wasting resources on every such call. [7](#0-6) 

### Likelihood Explanation
`LinkRepositoryToObjectPool` is a `MUTATOR` RPC whose `Repository` and `ObjectPool` fields are supplied independently by the caller (documented as "the responsibility of the caller" to use correctly, with "no safety checks in place" per the sibling `DeleteObjectPool` doc comment, indicating this trust model is by design for this service) [8](#0-7) . Any code path that constructs this RPC (e.g., a forking/import workflow) with the object pool's own repository mistakenly passed as the "member" repository — whether via a bug in the caller, a race during fork setup, or a crafted RPC field — reaches this code with no rejection at the Gitaly layer.

### Recommendation
Add an explicit, early self-reference check in `objectpool.Link()` (and ideally at the `LinkRepositoryToObjectPool` RPC boundary), analogous to the existing `storage.ErrAlternatePointsToSelf` check in `partition_assigner.go`: compare `pool.GetStorageName()`/`pool.GetRelativePath()` against `repo.GetStorageName()`/`repo.GetRelativePath()` and reject the request with `InvalidArgument` before touching the alternates file or bitmaps.

### Proof of Concept
1. Create an object pool `P` from some source repository via `CreateObjectPool`.
2. Call `LinkRepositoryToObjectPool` with `ObjectPool = P` and `Repository = P.Repository` (the pool's own repository) — no validation rejects this combination. [1](#0-0) 
3. Inspect `P`'s `objects/info/alternates` file — it will contain `"../objects"`, a path resolving back to `P`'s own object directory. [2](#0-1) 
4. Attempt any write RPC against `P` on a transactional storage — `Begin` fails with `storage.ErrAlternatePointsToSelf` sourced from `getAlternatePartitionID`, permanently blocking writes until the alternates file is manually cleaned up. [9](#0-8)

func removeMemberBitmaps(ctx context.Context, pool *localrepo.Repo, repo *localrepo.Repo) error {
	poolPath, err := pool.Path(ctx)
	if err != nil {
		return err
	}

	poolBitmaps, err := getBitmaps(poolPath)
	if err != nil {
		return err
	}
	if len(poolBitmaps) == 0 {
		return nil
	}

	repoPath, err := repo.Path(ctx)
	if err != nil {
		return err
	}

	memberBitmaps, err := getBitmaps(repoPath)
	if err != nil {
		return err
	}
	if len(memberBitmaps) == 0 {
		return nil
	}

	for _, bitmap := range memberBitmaps {
		if err := os.Remove(bitmap); err != nil && !os.IsNotExist(err) {
			return err
		}
	}

	return nil
}

func getRelativeObjectPath(ctx context.Context, pool, repo *localrepo.Repo) (string, error) {
	poolPath, err := pool.Path(ctx)
	if err != nil {
		return "", fmt.Errorf("getting object pool path: %w", err)
	}

	repoPath, err := repo.Path(ctx)
	if err != nil {
		return "", fmt.Errorf("getting repository path: %w", err)
	}

	relPath, err := filepath.Rel(filepath.Join(repoPath, "objects"), poolPath)
	if err != nil {
		return "", err
	}

	return filepath.Join(relPath, "objects"), nil
}

func (pa *partitionAssigner) assignPartitionID(ctx context.Context, relativePath string, recursiveCall bool, partitionHint storage.PartitionID) (storage.PartitionID, error) {
	// Check if the repository has an alternate. If so, it needs to go into the same
	// partition with it.
	ptnID, err := pa.getAlternatePartitionID(ctx, relativePath, recursiveCall, partitionHint)
	if err != nil {
		if !errors.Is(err, gitstorage.ErrNoAlternate) {
			return 0, fmt.Errorf("get alternate partition ID: %w", err)
		}

		ptnID = partitionHint
		if ptnID == invalidPartitionID {
			// The repository has no alternate. Unpooled repositories go into their own partitions.
			// Allocate a new partition ID for this repository.
			ptnID, err = pa.allocatePartitionID()
			if err != nil {
				return 0, fmt.Errorf("acquire partition id: %w", err)
			}
		}
	}

	if err := pa.partitionAssignmentTable.setPartitionID(relativePath, ptnID); err != nil {
		return 0, fmt.Errorf("set partition: %w", err)
	}

	return ptnID, nil
}

func (pa *partitionAssigner) getAlternatePartitionID(ctx context.Context, relativePath string, recursiveCall bool, partitionHint storage.PartitionID) (storage.PartitionID, error) {
	alternate, err := gitstorage.ReadAlternatesFile(filepath.Join(pa.storagePath, relativePath))
	if err != nil {
		return 0, fmt.Errorf("read alternates file: %w", err)
	}

	if recursiveCall {
		// recursive being true indicates we've arrived here through another repository's alternate.
		// Repositories in Gitaly should only have a single alternate that points to the repository's
		// pool. Chains of alternates are unexpected and could go arbitrarily long, so fail the operation.
		return 0, storage.ErrAlternateHasAlternate
	}

	// The relative path should point somewhere within the same storage.
	alternateRelativePath, err := storage.ValidateRelativePath(
		pa.storagePath,
		// Take the relative path to the repository, not 'repository/objects'.
		filepath.Dir(
			// The path in alternates file points to the object directory of the alternate
			// repository. The path is relative to the repository's own object directory.
			filepath.Join(relativePath, "objects", alternate),
		),
	)
	if err != nil {
		return 0, fmt.Errorf("validate relative path: %w", err)
	}

	if alternateRelativePath == relativePath {
		// The alternate must not point to the repository itself. Not only is it non-sensical
		// but it would also cause a dead lock as the repository is locked during this call
		// already.
		return 0, storage.ErrAlternatePointsToSelf
	}
