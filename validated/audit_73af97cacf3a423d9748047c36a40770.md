### Title
`is_simple_vote_transaction_view` in sigverify only checks transaction *shape*, not actual vote-instruction validity, allowing spoofed "vote" packets to receive vote-lane QoS treatment - ([File: perf/src/sigverify.rs])

### Summary
The Babylon bug stems from a validator accepting a Bitcoin transaction with a special, unchecked property (coinbase, unspendable for 100 blocks) as an ordinary staking transaction, letting an attacker evade the slashing invariant because the code never verifies the "is this actually a normal spendable tx" property before granting it staking status. The Agave analog is in `perf/src/sigverify.rs`, where `is_simple_vote_transaction_view` grants a packet the special `SIMPLE_VOTE_TX` classification purely by structural shape—program id, instruction count, signature count, message version—without ever decoding the instruction data to confirm it is actually a valid vote instruction.

### Finding Description
In `verify_packet`, every incoming packet is classified via `is_simple_vote_transaction_view` [1](#0-0) . That classifier only checks: ≤2 signatures, legacy message version, exactly one instruction, and that the instruction's `program_id` equals `solana_sdk_ids::vote::id()` [2](#0-1) . It never deserializes the instruction data to confirm it is a real `VoteInstruction` (e.g. `TowerSync`/`UpdateVoteState`).

Contrast this with the stricter check used elsewhere in the codebase, `is_valid_vote_only_transaction` in `vote/src/vote_parser.rs`, which additionally calls `limited_deserialize::<VoteInstruction>` and requires `ix.is_single_vote_state_update()` before treating the transaction as a genuine vote [3](#0-2) .

Because `verify_packet` only uses the weaker shape-based check, any unprivileged sender can craft a single-instruction, ≤2-signature, legacy-message transaction whose sole instruction targets the vote program but carries arbitrary/garbage instruction data (not a real vote). Sigverify will still set `PacketFlags::SIMPLE_VOTE_TX` on it [4](#0-3) . That flag is a load-bearing classification consumed throughout the pipeline to route/treat the packet differently from ordinary transactions:
- `core/src/banking_stage/tpu_to_pack.rs` translates the flag into `tpu_message_flags::IS_SIMPLE_VOTE` for the external scheduler [5](#0-4) .
- `core/src/forwarding_stage.rs` and `core/src/banking_stage/vote_storage.rs` / `latest_validator_vote_packet.rs` reference `SIMPLE_VOTE_TX` to decide vote-specific handling (dedicated vote storage/dedup keyed by voter, separate from the general fee-market transaction flow).

This mirrors the Babylon bug class exactly: a component that grants a transaction a special status/exemption (there: "valid staking tx" bypassing coinbase-immaturity concerns; here: "vote transaction" bypassing normal non-vote treatment) does so based on an incomplete check, letting the attacker's crafted input take on the special status without actually possessing the substantive property that justifies it.

### Impact Explanation
Votes are treated specially for QoS/prioritization purposes—they get their own ingestion channels (`tpu_vote`, `gossip_vote`) and dedicated dedup/storage (`VoteStorage`, `LatestValidatorVote`) separate from the general non-vote transaction flow subject to normal fee-market and priority-fee accounting (`prioritization_fee_cache.rs`, `cost-model/src/transaction_cost.rs` both branch on `is_simple_vote_transaction`). An attacker who can get garbage-vote-shaped packets classified as `SIMPLE_VOTE_TX` can inject them into the vote-specific lane, potentially consuming vote-lane capacity/bandwidth or bank-level "vote" accounting without needing a legitimate vote authority, i.e., a QoS evasion of the intended separation between vote traffic (privileged low-latency lane) and ordinary paid transaction traffic.

### Likelihood Explanation
This is reachable by any unprivileged client over the normal TPU/QUIC ingestion path: constructing a legacy, single-instruction, ≤2-signature transaction addressed to the vote program with non-vote instruction data requires no special stake, keys, or leader role—only a valid signature over arbitrary bytes and any keypair as signer. No mocking or privileged access is needed to reach `verify_packet`.

### Recommendation
Align `is_simple_vote_transaction_view` in `perf/src/sigverify.rs` with the stricter validation already implemented in `vote/src/vote_parser.rs::is_valid_vote_only_transaction`: deserialize the instruction data with `limited_deserialize::<VoteInstruction>` and require `is_single_vote_state_update()` (or equivalent) before setting `PacketFlags::SIMPLE_VOTE_TX`, so the vote-lane classification is granted only to transactions that are structurally *and* semantically valid votes.

### Proof of Concept
1. Build a `VersionedTransaction` with a legacy message, one signature, and a single instruction whose `program_id_index` points at `solana_sdk_ids::vote::id()`, but with instruction `data` set to arbitrary bytes that do not deserialize into a valid `VoteInstruction`.
2. Send the packet through the standard TPU ingestion path so it reaches `ed25519_verify`/`verify_packet` in `perf/src/sigverify.rs`.
3. Observe that `is_simple_vote_transaction_view` returns `true` (since it never inspects instruction data), causing `packet.meta_mut().flags |= PacketFlags::SIMPLE_VOTE_TX` to be set, and the packet to be subsequently routed/accounted through the vote-specific banking-stage/forwarding-stage paths despite not being a real vote. fn verify_packet(packet: &mut PacketRefMut, reject_non_vote: bool, enable_tx_v1: bool) -> bool {
    // If this packet was already marked as discard, drop it
    if packet.meta().discard() {
        return false;
    }

    let Some(data) = packet.data(..) else {
        return false;
    };

    let (is_simple_vote_tx, verified) = {
        let Ok(view) = SanitizedTransactionView::try_new_sanitized(data, &sanitize_config()) else {
            return false;
        };

        if !enable_tx_v1 && matches!(view.version(), TransactionVersion::V1) {
            return false;
        }

        let is_simple_vote_tx = is_simple_vote_transaction_view(&view);
        if reject_non_vote && !is_simple_vote_tx {
            (is_simple_vote_tx, false)
        } else {
            let signatures = view.signatures();
            if signatures.is_empty() {
                (is_simple_vote_tx, false)
            } else {
                let message = view.message_data();
                let static_account_keys = view.static_account_keys();
                let verified = signatures
                    .iter()
                    .zip(static_account_keys.iter())
                    .all(|(signature, pubkey)| signature.verify(pubkey.as_ref(), message));
                (is_simple_vote_tx, verified)
            }
        }
    };

    if is_simple_vote_tx {
        packet.meta_mut().flags |= PacketFlags::SIMPLE_VOTE_TX;
    }

    verified
}

fn is_simple_vote_transaction_view<D: TransactionData>(view: &SanitizedTransactionView<D>) -> bool {
    // vote could have 1 or 2 sigs; zero sig has already been excluded by sanitization.
    if view.num_signatures() > 2 {
        return false;
    }

    // simple vote should only be legacy message
    if !matches!(view.version(), TransactionVersion::Legacy) {
        return false;
    }

    // skip if has more than 1 instruction
    if view.num_instructions() != 1 {
        return false;
    }

    let mut instructions = view.instructions_iter();
    let Some(instruction) = instructions.next() else {
        return false;
    };
    if instructions.next().is_some() {
        return false;
    }

    let program_id_index = usize::from(instruction.program_id_index);
    let Some(program_id) = view.static_account_keys().get(program_id_index) else {
        return false;
    };

    *program_id == solana_sdk_ids::vote::id()
}

/// Check if a transaction is a valid vote-only transaction.
/// A valid vote-only transaction must:
/// 1. Have exactly one instruction
/// 2. That instruction must be to the vote program
/// 3. That instruction must be a single vote state update (UpdateVoteState, TowerSync, etc.)
pub fn is_valid_vote_only_transaction(tx: &impl SVMTransaction) -> bool {
    let mut instructions = tx.program_instructions_iter();

    let Some((program_id, instruction)) = instructions.next() else {
        return false;
    };

    if instructions.next().is_some() {
        return false;
    }

    if !solana_sdk_ids::vote::check_id(program_id) {
        return false;
    }

    limited_deserialize::<VoteInstruction>(instruction.data, solana_packet::PACKET_DATA_SIZE as u64)
        .map(|ix| ix.is_single_vote_state_update())
        .unwrap_or(false)
}

fn flags_from_meta(flags: PacketFlags) -> u8 {
    let mut tpu_message_flags = 0;

    if flags.contains(PacketFlags::SIMPLE_VOTE_TX) {
        tpu_message_flags |= tpu_message_flags::IS_SIMPLE_VOTE;
    }
    if flags.contains(PacketFlags::FORWARDED) {
        tpu_message_flags |= tpu_message_flags::FORWARDED;
    }
    if flags.contains(PacketFlags::FROM_STAKED_NODE) {
        tpu_message_flags |= tpu_message_flags::FROM_STAKED_NODE;
    }

    tpu_message_flags
}
