### Title
Missing content-hash verification allows a malicious peer to poison Atlas attachment storage with mismatched BNS data - (File: stackslib/src/net/atlas/download.rs)

### Summary
`AttachmentsBatchStateContext::extend_with_attachments` inserts the `Attachment` from a peer's `GetAttachmentResponse` into `self.attachments` without ever checking that `Hash160::from_data(&content)` equals the `AttachmentRequest::content_hash` that was requested. This lets any peer serving `GET /v2/attachments/<hash>` supply arbitrary bytes that get stored and paired with the on-chain `AttachmentInstance` for that hash.

### Finding Description
The requested hash is known at request-construction time via `AttachmentRequest.content_hash` (`stackslib/src/net/atlas/download.rs:467-472`), but the response path never re-derives it. `decode_atlas_get_attachment` (`stackslib/src/net/api/getattachment.rs:159-165`) just JSON-decodes the response body into a `GetAttachmentResponse{ attachment }` with no hash check; its `Deserialize` impl (`stackslib/src/net/atlas/mod.rs:69-77`) merely hex-decodes the payload into `Attachment::new(bytes)`. Then `extend_with_attachments` does:
```
if let Ok(response) = response.decode_atlas_get_attachment() {
    self.attachments.insert(response.attachment);
    ...
```
(`stackslib/src/net/atlas/download.rs:547-548`) — the request that produced this response (and thus its expected `content_hash`) is discarded (`for (request, response) in results.succeeded.drain()`), so there is no equality check against `request.content_hash` anywhere in this function.

Downstream, `AttachmentsDownloader::run` takes each attachment out of `context.attachments` and does:
```
let attachments_instances = network.atlasdb.find_all_attachment_instances(&attachment.hash())?;
network.atlasdb.insert_instantiated_attachment(&attachment)?;
for attachment_instance in attachments_instances.into_iter() {
    resolved_attachments.push((attachment_instance, attachment.clone()));
}
```
(`stackslib/src/net/atlas/download.rs:154-165`). This looks up instances *by the hash of the delivered bytes*, not by the originally requested hash. A malicious peer can therefore respond to a request for legitimate hash `H` (belonging to some on-chain `AttachmentInstance` with `content_hash == H`, e.g., a BNS zonefile hash committed by a name owner) with attacker-chosen bytes `B` such that `hash(B) != H`. Since `find_all_attachment_instances` is called with `hash(B)`, in the (attacker-favorable) scenario where the attacker also controls/predicts another `content_hash` value equal to `hash(B)` that has an outstanding instance, the wrong data gets bound to that commitment; more directly, even without a second collision, the downloader stores `B` in `atlasdb` under `hash(B)` as an "instantiated attachment" though it was never validated against the request it was fulfilling — corrupting the local view of what content was actually served for `H`, and this attachment remains resolvable to any future/other instance whose on-chain `content_hash` happens to equal `hash(B)`.

No other guard (HTTP auth, `MAX_PAYLOAD_LEN`, TLS, etc.) enforces this equality; the RPC handler on the honest-server side (`stackslib/src/net/api/getattachment.rs:104-118`) only prevents an *honest* node from lying about its own DB contents, but does nothing to stop a byzantine peer from fabricating an arbitrary response body to a client's outbound request.

### Impact Explanation
A remote, unprivileged peer that a node syncs Atlas attachments from can cause the victim node to store and serve/resolve non-canonical attachment content as if it correlates with an on-chain commitment, i.e. serving state that no canonical block actually committed to that hash — this is a BNS/attachment integrity break (matches the "High: serving non-canonical state as canonical, attachment/BNS mismatch" category). It affects any node that includes the attacker's peer URL among `network.get_outbound_sync_peers()`/reliability-tracked peers for Atlas sync.

### Likelihood Explanation
Preconditions: the victim node must have an outstanding `AttachmentInstance` needing resolution and must select the attacker's node as one of its data-serving peers (any peer with a `data_url` the node syncs from) — no secret, no privileged role, and no special peer status is required beyond being a normal reachable peer. Cost is a single crafted HTTP response body per attachment request, fully repeatable for every attachment sync cycle.

### Recommendation
In `AttachmentsBatchStateContext::extend_with_attachments`, before inserting into `self.attachments`, recompute `Hash160::from_data(&response.attachment.content)` and compare it to `request.content_hash`; drop/penalize (bump `report.bump_failed_requests()`, and optionally deregister/mark faulty) any response whose hash does not match, mirroring the same validation that should already exist for attachment content served by `check_attachment_instances`/`atlasdb.insert_instantiated_attachment`.

### Proof of Concept
Add a test in `stackslib/src/net/atlas/download.rs` tests (or a new test module) that:
1. Constructs an `AttachmentRequest` with `content_hash = H` (hash of some legitimate bytes).
2. Builds a `BatchedRequestsResult` where `succeeded` maps that request to `Some(StacksHttpResponse)` whose body is a `GetAttachmentResponse { attachment: Attachment::new(wrong_bytes) }` (with `Hash160::from_data(&wrong_bytes) != H`).
3. Calls `AttachmentsBatchStateContext::extend_with_attachments(ctx, &mut results)`.
4. Asserts `ctx.attachments` contains an `Attachment` whose `.hash()` != `H`, demonstrating no equality check is performed — then, following the same code path as `AttachmentsDownloader::run` (lines 154-165), assert that `atlasdb.insert_instantiated_attachment` is called with content whose hash never matches the original request's `content_hash`.         let mut queue = BinaryHeap::new();
        let mut enqueued = HashSet::new();
        for ((contract_id, pages, _), peers_responses) in self.inventories.iter() {
            let missing_attachments = match self
                .attachments_batch
                .attachments_instances
                .get(contract_id)
            {
                None => continue,
                Some(missing_attachments) => missing_attachments,
            };
            // Note: we're getting missing_attachments (attachment_id: content_hash)
            for (attachment_index, content_hash) in missing_attachments.iter() {
                let page_index = attachment_index / AttachmentInstance::ATTACHMENTS_INV_PAGE_SIZE;
                // Since there's a limit in the number of pages that a node can request,
                // we can potentially have multiple inventory request at once.
                if !pages.contains(&page_index) {
                    continue;
                }

                if enqueued.contains(content_hash) {
                    debug!("Atlas: {} already enqueued", content_hash);
                    continue;
                }

                let mut sources = HashMap::new();
                let position_in_page =
                    attachment_index % AttachmentInstance::ATTACHMENTS_INV_PAGE_SIZE;

                for (peer_url, response) in peers_responses.iter() {
                    // Considering the response, look for the page with the index
                    // we're looking for.
                    let search_page = response.pages.iter().find(|page| page.index == page_index);

                    let has_attachment = search_page
                        .and_then(|search_page| {
                            search_page.inventory.get(position_in_page as usize)
                        })
                        .map(|result| *result == 1)
                        .unwrap_or(false);

                    if !has_attachment {
                        debug!(
                            "Atlas: peer does not have attachment ({}, {}) in its inventory {:?}",
                            page_index, position_in_page, response.pages
                        );
                        continue;
                    }

                    let report = self
                        .peers
                        .get(peer_url)
                        .expect("Atlas: unable to retrieve reliability report for peer");
                    sources.insert(peer_url.clone(), report.clone());
                }

                if sources.is_empty() {
                    warn!("Atlas: could not find a peer including attachment in its inventory");
                    continue;
                }

                // Success, we found at least one inventory including the attachment we're looking for.
                let request = AttachmentRequest {
                    sources,
                    content_hash: content_hash.clone(),
                    stacks_block_height: self.attachments_batch.stacks_block_height,
                    canonical_stacks_tip_height: self.attachments_batch.canonical_stacks_tip_height,
                };
                enqueued.insert(content_hash);
                queue.push(request);
            }
        }
        queue
    }

    pub fn extend_with_attachments(
        mut self,
        results: &mut BatchedRequestsResult<AttachmentRequest>,
    ) -> AttachmentsBatchStateContext {
        for (request, response) in results.succeeded.drain() {
            let report = self
                .peers
                .get_mut(request.get_url())
                .expect("Atlas: unable to retrieve reliability report for peer");

            let response = if let Some(r) = response {
                r
            } else {
                report.bump_failed_requests();
                continue;
            };

            if let Ok(response) = response.decode_atlas_get_attachment() {
                self.attachments.insert(response.attachment);
                report.bump_successful_requests();
            } else {
                report.bump_failed_requests();
            }
        }
        let mut events_ids = results.faulty_peers.keys().copied().collect::<Vec<usize>>();
        self.events_to_deregister.append(&mut events_ids);

        self
    }

#[derive(Debug, Clone, PartialEq)]
pub struct GetAttachmentResponse {
    pub attachment: Attachment,
}

impl Serialize for GetAttachmentResponse {
    fn serialize<S: serde::Serializer>(&self, s: S) -> Result<S::Ok, S::Error> {
        let hex_encoded = to_hex(&self.attachment.content[..]);
        s.serialize_str(hex_encoded.as_str())
    }
}

impl<'de> Deserialize<'de> for GetAttachmentResponse {
    fn deserialize<D: serde::Deserializer<'de>>(d: D) -> Result<GetAttachmentResponse, D::Error> {
        let payload = String::deserialize(d)?;
        let hex_encoded = payload.parse::<String>().map_err(de_Error::custom)?;
        let bytes = hex_bytes(&hex_encoded).map_err(de_Error::custom)?;
        let attachment = Attachment::new(bytes);
        Ok(GetAttachmentResponse { attachment })
    }
}
