### Title
No grace period after `open()`/`unpause()` allows instant liquidation of positions frozen during shutdown - ([File: contracts/utils/Pauseable.sol](contracts/utils/Pauseable.sol))

### Summary
Metronome's `Pool.shutdown()` (inherited from `Pauseable`) freezes all user exit and top-up paths (`deposit`, `withdraw`, `repay`, `repayAll`, `issue`, `swap`, `liquidate`). While the pool is shut down, positions keep accruing interest and collateral prices keep moving, so a previously healthy account can drift below the liquidation threshold with no ability to react. When the governor calls `open()`, all functions — including `Pool.liquidate()` — are re-enabled atomically in the same block, and there is no grace period. An unprivileged liquidator can front-run the victim's first `repay`/`deposit` transaction in the block where the pool reopens and seize their collateral.

### Finding Description
`Pauseable.shutdown()` sets `_everythingStopped = true` and `_paused = true`, disabling every user-facing recovery path [1](#0-0) . Per `docs/emergency-flags.md`, `everythingStopped` disables `issue`, `leverage`, `repay`, `repayAll`, `liquidate`, `swap`, and `DepositToken.withdraw`, while `paused` additionally blocks `deposit` [2](#0-1) . `open()` simply clears the flag with no timelock or liquidation grace window [3](#0-2) . `Pool.liquidate()` is `whenNotShutdown` and has no "recently reopened" check — it is callable by anyone the instant `open()` lands [4](#0-3) .

Concrete sequence:
1. Governor/guardian calls `Pool.shutdown()` in an emergency.
2. During shutdown, interest accrues on `DebtToken` balances and/or the collateral's oracle price drops. Alice's position becomes unhealthy, but `repay`, `repayAll`, `deposit`, `withdraw`, and `swap` all revert for her.
3. Governor calls `open()`. In the same or next block, an attacker back-runs `open()` (or front-runs Alice's `repayAll`) with `pool.liquidate(synth, alice, amountToRepay, depositToken)`, repaying her debt with synth and seizing her `DepositToken` collateral plus the liquidation bonus.

Even the weaker `pause()` state has a related asymmetry: `deposit` (the only way to top up collateral) is blocked while `liquidate` remains live (test `should not revert if paused` in `test/Pool.test.ts` confirms liquidations proceed while paused) [5](#0-4) . A user who does not already hold the synthetic asset cannot add collateral during a pause and must hope `swap` liquidity suffices to deleverage — the shutdown case is the clean version where *all* exits are blocked.

### Impact Explanation
Direct loss of user collateral. Users whose positions turned liquidatable during a shutdown window lose their collateral to liquidators with zero opportunity to cure, contradicting the expectation that a user can always exit or top up before being liquidated. The liquidation bonus plus fee is seized via `depositToken_.seize()` [6](#0-5) .

### Likelihood Explanation
Requires a shutdown/pause event to coincide with adverse price movement — an uncommon but realistic scenario, since shutdowns are most likely invoked precisely during volatile emergencies. Once it occurs, the front-running itself is trivial for any unprivileged EOA holding or flash-sourcing the synthetic asset; no privileged role is needed for the attack transaction itself.

### Recommendation
Record `block.timestamp` in `open()`/`unpause()` and enforce a grace period (e.g., revert in `Pool.liquidate()` while `block.timestamp < reopenedAt + GRACE_PERIOD`), during which users can `repay`/`deposit`/`withdraw` but cannot be liquidated.

### Proof of Concept
Hardhat, extending the existing `Pool.test.ts` fixture:

```ts
it('liquidator front-runs user right after open() with no grace period', async function () {
  // alice has a healthy position (existing fixture)
  await pool.shutdown(); // guardian/governor emergency action

  // while shutdown: price drops, alice cannot repay/deposit/withdraw
  await masterOracle.updatePrice(met.address, toUSD('0.80'));
  await expect(msEthDebtToken.connect(alice).repayAll(alice.address))
    .to.be.revertedWithCustomError(msEthDebtToken, 'IsShutdown');
  await expect(msdMET.connect(alice).deposit(parseEther('1'), alice.address))
    .to.be.reverted;
  const { _isHealthy } = await pool.debtPositionOf(alice.address);
  expect(_isHealthy).to.be.false;

  // governor reopens; liquidator acts in the very next tx
  await pool.open();
  const amountToRepay = await msEthDebtToken.balanceOf(alice.address);
  await pool.connect(liquidator)
    .liquidate(msEth.address, alice.address, amountToRepay, msdMET.address);

  // alice's collateral was seized before she could react
  expect(await msdMET.balanceOf(alice.address)).to.eq(0);
});
```

Note: this is an edge-case-but-valid analog — the privileged `open()`/`shutdown()` calls set the stage, but the value extraction is performed by an unprivileged liquidator front-running in a public mempool.
