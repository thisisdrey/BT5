Audit Report

## Title
Missing `AssetConversion` entry in `ProxyType::NonTransfer` filter permits value transfer by a "non-transfer" proxy - (File: `cumulus/parachains/runtimes/assets/asset-hub-westend/src/lib.rs`)

## Summary
`ProxyType::NonTransfer::filter` is implemented as a negated `matches!` over an explicit block-list of value-moving `RuntimeCall` variants. `pallet_asset_conversion` swap calls, which accept an arbitrary `send_to` beneficiary and move the proxied account's tokens to it, are absent from this list, so they fall through the `!matches!(...)` and are treated as permitted under `NonTransfer`.

## Finding Description
`InstanceFilter::filter` for `ProxyType::NonTransfer` returns `true` (allowed) for any `RuntimeCall` variant not explicitly enumerated in the block-list at lines 834-849. `RuntimeCall::AssetConversion(..)` is not present in that enumeration, meaning swap calls such as `swap_exact_tokens_for_tokens` and `swap_tokens_for_exact_tokens` — both of which take a `send_to: AccountId` parameter that can be set to any account, distinct from the origin — pass the filter and are dispatchable through `pallet_proxy::proxy` under a `NonTransfer` delegation. Since the block-list approach requires exhaustive manual maintenance against every value-moving pallet, and `pallet_asset_conversion` moves value out of the proxied account's `Balances`/`Assets` holdings to an arbitrary destination, this is a genuine gap in the exclusion list.

## Impact Explanation
A delegate holding only a `NonTransfer` proxy over a victim account can invoke `AssetConversion::swap_exact_tokens_for_tokens` via `pallet_proxy::proxy`, swapping the victim's balance/assets and redirecting the output to an account the delegate controls. This matches the accepted impact category of unauthorized execution/origin escalation via a public wrapper (`proxy`) leading to fund loss to an unintended beneficiary.

## Likelihood Explanation
Medium-to-High. The only precondition is holding a `NonTransfer` proxy — a common, "safe" delegation type that does not require any privileged role — and `pallet_asset_conversion` and `pallet_proxy` are both standard public entry points wired into `asset-hub-westend-runtime`.

## Recommendation
Add `RuntimeCall::AssetConversion(..)` to the `ProxyType::NonTransfer` exclusion list in `cumulus/parachains/runtimes/assets/asset-hub-westend/src/lib.rs`, matching the treatment already given to `Balances`, `Assets`, `Nfts`, etc. Consider a test asserting every value-moving `RuntimeCall` variant is explicitly classified to prevent future regressions.

## Proof of Concept
1. Account `A` grants `pallet_proxy::add_proxy(delegate = B, proxy_type = ProxyType::NonTransfer)`.
2. `B` calls `pallet_proxy::proxy(real = A, call = RuntimeCall::AssetConversion(pallet_asset_conversion::Call::swap_exact_tokens_for_tokens { path: [DOT, USDT], amount_in: ALL_OF_A_BALANCE, amount_out_min: 0, send_to: B, keep_alive: false }))`.
3. `InstanceFilter::filter` evaluates `ProxyType::NonTransfer` against this call; since `AssetConversion` is absent from the block-list at lines 834-849, `!matches!(...)` returns `true` and the call dispatches with `A`'s origin.
4. `A`'s DOT balance is swapped and the USDT output is sent to `B`, confirming value leaves `A`'s account despite `B` holding only a `NonTransfer` proxy.
