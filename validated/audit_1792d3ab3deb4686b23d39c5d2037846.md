Based on my research, the closest analog in this Go standard-library tree is the `go env -w` config-file writer, which persists potentially credential-bearing values (like a `GOPROXY` URL with embedded HTTP Basic-Auth userinfo) to a world-writable file.

### Title
`go env -w` persists GOPROXY Basic-Auth credentials to a world-writable env file - (File: src/cmd/go/internal/envcmd/env.go)

### Summary
`go env -w GOPROXY=https://user:pass@proxy.example.com` (a documented way to authenticate to a module proxy) causes the go command to write the literal URL — including the embedded username/password — into the per-user Go environment configuration file. That file is created with mode `0666` (before umask), so on a multi-user POSIX host it is normally world-readable/writable under default `umask 022`, exposing the proxy credentials to any local user, mirroring the nextflow `seqera-auth.config` world-readable token issue.

### Finding Description
A user runs `go env -w GOPROXY=<url-with-userinfo>` (or any other GOAUTH-adjacent secret-bearing var) as part of ordinary configuration of a private module proxy. This flows into `runEnvW` → `updateEnvFile` in [1](#0-0) , which calls `updateEnvFile(add, nil)`. That function serializes all KEY=VALUE lines (including the just-added `GOPROXY=https://user:pass@host`) and writes them with: [2](#0-1) 
`os.WriteFile(file, data, 0666)` (with a fallback also using `0666` after `MkdirAll(dir, 0777)`). Unlike the nextflow patch, which now applies `0600`, this Go code path never restricts the file's permissions — it relies solely on the umask, exactly the failure mode described in the advisory. `proxyList()` in `src/cmd/go/internal/modfetch/proxy.go` later reads this GOPROXY value verbatim and `net/url` parses the userinfo credentials out of it via `parseAuthority` [3](#0-2) , confirming the go toolchain treats embedded userinfo in GOPROXY as real Basic-Auth credentials.

### Impact Explanation
On a shared/multi-user host (HPC login node, shared workstation, CI runner shared among teams), any local user who can read `$XDG_CONFIG_HOME/go/env` (or platform equivalent, as reported by `os.UserConfigDir`) obtains the victim's module-proxy Basic-Auth credentials, enabling impersonation against that proxy — a confidentiality/cross-user secret disclosure, matching CWE-276/732 in the referenced advisory. This is a `PUBLIC` track kind of hardening issue: real secret disclosure via a permissive default file mode, not a hypothetical misuse.

### Likelihood Explanation
The victim workflow (`go env -w GOPROXY=...` with embedded credentials) is an ordinary, documented way to configure a private Go module proxy, requiring no privileged or malicious server. The attacker only needs unprivileged local access to the same multi-user machine and default umask — no code execution or elevated privilege needed to read the resulting `0666` file.

### Recommendation
Change `updateEnvFile` to write the go/env config file (and create its directory) with restrictive permissions, e.g. `os.WriteFile(file, data, 0600)` and `os.MkdirAll(filepath.Dir(file), 0700)`, and consider re-tightening permissions on every `go env -w` invocation for any pre-existing world-readable file, similar to the nextflow fix.

### Proof of Concept
```go
package envcmd_test

import (
    "os"
    "path/filepath"
    "testing"
)

// Simulates updateEnvFile's write call in src/cmd/go/internal/envcmd/env.go:775
func TestGoEnvFileWorldReadable(t *testing.T) {
    dir := t.TempDir()
    file := filepath.Join(dir, "env")
    data := []byte("GOPROXY=https://user:secret@proxy.example.com\n")

    if err := os.WriteFile(file, data, 0666); err != nil {
        t.Fatal(err)
    }

    info, err := os.Stat(file)
    if err != nil {
        t.Fatal(err)
    }

    // Under default umask 022, resulting mode is 0644 (world-readable).
    if info.Mode().Perm()&0044 != 0 {
        t.Fatalf("go/env config file is group/world-readable (mode %v); "+
            "embedded GOPROXY credentials are exposed to other local users", info.Mode().Perm())
    }
}
```
Expected: the assertion fails on a default `umask 022` system, demonstrating that credentials embedded in `GOPROXY` persisted via `go env -w` end up in a group/world-readable file.
