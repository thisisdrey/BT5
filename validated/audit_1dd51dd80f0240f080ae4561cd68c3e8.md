### Title
Vesting `distribute` Permanently Freezes All Shareholders' APT When Any Shareholder Opts Out of Direct Coin Transfers — (`aptos-move/framework/aptos-framework/sources/vesting.move`)

---

### Summary

`vesting::distribute` iterates over every shareholder and calls `aptos_account::deposit_coins<AptosCoin>` for each one. `deposit_coins` aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` if the recipient account has not registered a `CoinStore<AptosCoin>` **and** has called `set_allow_direct_coin_transfers(false)`. Because Move's transaction semantics roll back all state on abort, a single shareholder who opts out of direct coin transfers causes every call to `distribute` to revert — permanently blocking APT distribution to **all** shareholders until an admin manually re-routes that shareholder's beneficiary. The same root cause exists in `staking_contract::distribute_internal`.

---

### Finding Description

`vesting::distribute` is a permissionless `public entry fun` that anyone can call. Its core loop is:

```move
shareholders.for_each_ref(|shareholder| {
    let shareholder = *shareholder;
    let shares = pool_u64::shares(grant_pool, shareholder);
    let amount = pool_u64::shares_to_amount_with_total_coins(...);
    let share_of_coins = coin::extract(&mut coins, amount);
    let recipient_address = get_beneficiary(vesting_contract, shareholder);
    aptos_account::deposit_coins(recipient_address, share_of_coins);  // ← can abort
});
``` [1](#0-0) 

`aptos_account::deposit_coins` contains:

```move
if (!coin::is_account_registered<CoinType>(to)) {
    assert!(
        can_receive_direct_coin_transfers(to),
        error::permission_denied(EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS)
    );
    coin::register<CoinType>(&create_signer(to));
};
``` [2](#0-1) 

`can_receive_direct_coin_transfers` returns `false` when the account has explicitly called `set_allow_direct_coin_transfers(false)`:

```move
public fun can_receive_direct_coin_transfers(account: address): bool acquires DirectTransferConfig {
    !exists<DirectTransferConfig>(account)
        || borrow_global<DirectTransferConfig>(account).allow_arbitrary_coin_transfers
}
``` [3](#0-2) 

Accounts created via the current `aptos_account::create_account` only receive a primary fungible store (via `register_apt` → `ensure_primary_fungible_store_exists`), **not** a `CoinStore<AptosCoin>`. So `coin::is_account_registered<AptosCoin>` returns `false` for them. [4](#0-3) 

**Attack path:**
1. Shareholder `S` is enrolled in a vesting contract (or is set as a beneficiary).
2. `S` calls `set_allow_direct_coin_transfers(false)` — a permissionless `public entry fun`.
3. `S`'s account has no `CoinStore<AptosCoin>` (new FA-based account).
4. Any caller invokes `vesting::distribute(contract_address)`.
5. When the loop reaches `S`, `deposit_coins<AptosCoin>(S, ...)` aborts.
6. The entire transaction reverts; no APT is distributed to anyone.
7. Every future call to `distribute` hits the same abort — all shareholders are frozen.

The same pattern exists in `staking_contract::distribute_internal` at lines 899–901 and 915, where `deposit_coins` is called for each distribution recipient and for the staker's dust remainder. [5](#0-4) 

Additionally, `terminate_vesting_contract` calls `distribute` as its first step, so the admin cannot even terminate the contract while the freeze is active: [6](#0-5) 

---

### Impact Explanation

All vested and reward APT locked in the vesting contract becomes permanently undistributable to every shareholder. The coins are not destroyed — they remain in the vesting contract's account — but no shareholder can receive them. `terminate_vesting_contract` is also blocked because it calls `distribute` internally. This constitutes permanent freezing of vesting balances, which is an in-scope impact.

---

### Likelihood Explanation

The trigger is a single unprivileged transaction (`set_allow_direct_coin_transfers(false)`) callable by any shareholder or beneficiary. Vesting contracts can have up to 30 shareholders (`MAXIMUM_SHAREHOLDERS = 30`), so the attack surface is wide. A malicious or negligent shareholder, or one who simply opts out of direct transfers for privacy reasons, can inadvertently or deliberately freeze the entire contract. The admin can mitigate by calling `set_beneficiary` to redirect the problematic shareholder's share to a cooperative address, but this requires admin responsiveness and knowledge of the issue.

---

### Recommendation

Replace the bare `aptos_account::deposit_coins` calls in `vesting::distribute` and `staking_contract::distribute_internal` with a pattern that does not abort on recipient opt-out. Options:

1. **Skip and accumulate**: If `deposit_coins` would fail (check `can_receive_direct_coin_transfers` and `coin::is_account_registered` before calling), hold the coins in a per-shareholder claimable balance instead of pushing them.
2. **Use `coin::force_deposit`**: The framework already has `coin::force_deposit` which bypasses the frozen-store check; a similar bypass for the direct-transfer opt-out should be added for the vesting/staking distribution path, since these are not arbitrary third-party transfers but contractually owed funds.
3. **Require registration at enrollment**: Assert at `create_vesting_contract` time that each shareholder/beneficiary address is registered for `AptosCoin` and has not opted out.

---

### Proof of Concept

```
1. Deploy a vesting contract with shareholders [Alice, Bob].
2. Bob calls: aptos_account::set_allow_direct_coin_transfers(false)
   (Bob's account was created with the FA system, so no CoinStore<AptosCoin>)
3. After the lockup period, anyone calls: vesting::distribute(contract_address)
4. The loop reaches Bob → deposit_coins<AptosCoin>(Bob, ...) aborts with
   EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS (error code 0x50003)
5. Transaction reverts. Alice receives nothing.
6. Repeat step 3 indefinitely — always aborts at Bob.
7. Admin calls terminate_vesting_contract → also aborts (calls distribute internally).
8. All APT in the vesting contract is frozen.
``` [7](#0-6) [8](#0-7)

    /// Distribute any withdrawable stake from the stake pool.
    public entry fun distribute(contract_address: address) acquires VestingContract {
        assert_active_vesting_contract(contract_address);

        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        let coins = withdraw_stake(vesting_contract, contract_address);
        let total_distribution_amount = coin::value(&coins);
        if (total_distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };

        // Distribute coins to all shareholders in the vesting contract.
        let grant_pool = &vesting_contract.grant_pool;
        let shareholders = &grant_pool.shareholders();
        shareholders.for_each_ref(|shareholder| {
            let shareholder = *shareholder;
            let shares = pool_u64::shares(grant_pool, shareholder);
            let amount = pool_u64::shares_to_amount_with_total_coins(grant_pool, shares, total_distribution_amount);
            let share_of_coins = coin::extract(&mut coins, amount);
            let recipient_address = get_beneficiary(vesting_contract, shareholder);
            aptos_account::deposit_coins(recipient_address, share_of_coins);
        });

        // Send any remaining "dust" (leftover due to rounding error) to the withdrawal address.
        if (coin::value(&coins) > 0) {
            aptos_account::deposit_coins(vesting_contract.withdrawal_address, coins);
        } else {
            coin::destroy_zero(coins);
        };

        emit(
            Distribute {
                admin: vesting_contract.admin,
                vesting_contract_address: contract_address,
                amount: total_distribution_amount,
            },
        );
    }
