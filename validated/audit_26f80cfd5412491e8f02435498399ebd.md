### Title
`Pool.liquidate` reverts on underwater accounts with no collateral, leaving bad debt permanently unliquidatable - (File: contracts/Pool.sol)

### Summary
`Pool.liquidate` requires the liquidator's seizure amount (`_totalSeized`) to be bounded by the account's `DepositToken` balance and there is no bad-debt clearing path. Once an unhealthy account's collateral balance reaches zero (fully seized or never deposited) while debt remains, every subsequent `liquidate` call reverts with `AmountIsTooHigh`, and `quoteLiquidateMax` returns `0`. Residual debt becomes permanent protocol insolvency with no mechanism to socialize or write it off.

### Finding Description
In `Pool.liquidate`, the health check uses `debtPositionOf`, which computes `_issuableLimitInUsd` solely from `depositOf` (the USD value of the account's `DepositToken` balances). An account with debt but zero collateral is still correctly flagged unhealthy, so the `PositionIsHealthy` revert does not block liquidation. However, the seized amount is computed as `quoteLiquidateOut(...)` for the repaid synth amount, and the function then enforces `if (_totalSeized > depositToken_.balanceOf(account_)) revert AmountIsTooHigh()`. For a zero-collateral account any `amountToRepay_ > 0` produces `_totalSeized > 0` and reverts, and `amountToRepay_ == 0` reverts `AmountIsZero`. The helper `quoteLiquidateMax` confirms the dead end: it quotes `quoteLiquidateIn` with `totalToSeize_ = depositToken_.balanceOf(account_) = 0`, yielding `_amountToRepay = 0`, so the max liquidable amount is `0`. There is no `handleBadDebt`-style fallback anywhere in `Pool.sol`, `DebtToken.sol`, or `DepositToken.sol`.

This mirrors the referenced JOJO issue: the bad-debt code path is unreachable by construction — in JOJO because `_isSafe` can never be false with zero open positions, here because the only liquidation path is gated on seizing collateral that does not exist.

### Impact Explanation
Bad debt (debt token supply not backed by collateral) can never be removed through `liquidate`. The `DebtToken` balance and its USD debt keep accruing interest forever, the synthetic token remains redeemable against the pool's shared collateral via `swap`, and the shortfall is silently socialized across all other depositors. This is direct, permanent protocol insolvency with no privileged or unprivileged recovery path.

### Likelihood Explanation
Requires a position to become deeply underwater — collateral USD value falling below debt — which occurs during sharp collateral price crashes or high accrued interest. Liquidators are economically incentivized to seize whatever collateral exists (test `Pool.test.ts` "collateral:debt < 1" shows seizure of essentially the full balance), after which the residual debt is permanently stuck. No attacker action is needed to create it, though an attacker can deliberately leave dust collateral so the deposit set still contains the token while the revert persists.

### Recommendation
Add an explicit bad-debt path: when `depositOf` (or the relevant `depositToken_` balance) is insufficient, allow `liquidate` to repay debt without seizure (`_totalSeized == 0` short-circuit), or implement debt socialization/write-off via treasury or a cover mechanism. Alternatively, emit a `BadDebt` event and let governance burn the residual `DebtToken` balance.

```typescript
// Hardhat fork test sketch (metronome-synth-public--021)
// Setup: alice deposits MET, issues msETH; MET price crashes so debt > collateral.
await msdMET.connect(alice).deposit(parseEther('1000'), alice.address);
await msEthDebtToken.connect(alice).issue(parseEther('1'), alice.address);
await masterOracle.updatePrice(met.address, toUSD('0.50')); // collateral < debt

// 1) Liquidator seizes essentially all collateral
const max = await pool.quoteLiquidateMax(msEth.address, alice.address, msdMET.address);
await pool.connect(liquidator).liquidate(msEth.address, alice.address, max, msdMET.address);

// 2) Alice still has residual debt but ~0 collateral
expect(await msEthDebtToken.balanceOf(alice.address)).gt(0);
expect(await msdMET.balanceOf(alice.address)).eq(0); // or dust

// 3) Bad debt is now unreachable
expect(await pool.quoteLiquidateMax(msEth.address, alice.address, msdMET.address)).eq(0);
await expect(
  pool.connect(liquidator).liquidate(msEth.address, alice.address, 1, msdMET.address)
).to.be.revertedWithCustomError(pool, 'AmountIsTooHigh');
```
