### Title
Missing verification that hook-RPC caller matches an actual in-flight Git operation allows env/quarantine-path forgery in `PreReceiveHook`/`UpdateHook`/`ReferenceTransactionHook` - (File: `internal/gitaly/service/hook/pre_receive.go`, `internal/gitaly/hook/prereceive.go`)

### Summary
The `CredibleAccountModule` bug is a missing check that the caller actually installed/initialized the hook before letting it act on session-key state supplied via `msg.sender`/`msgData`. The reachable Gitaly analog is in the `HookService` RPCs (`PreReceiveHook`, `UpdateHook`, `PostReceiveHook`, `ReferenceTransactionHook`). These RPC handlers only validate that the target `Repository` field is a legitimate repository path (`locator.ValidateRepository`) — they never verify that the caller is the specific `gitaly-hooks` subprocess Gitaly itself spawned for a genuine `git-receive-pack` invocation, nor that the `EnvironmentVariables`-embedded `GITALY_HOOKS_PAYLOAD` (containing `TransactionID`, `UserDetails`, and quarantine `GitObjectDirectory`/`GitAlternateObjectDirectories`) corresponds to a transaction actually owned by that call.

### Finding Description
`PreReceiveHook` extracts the entire trust payload from a caller-supplied field: [1](#0-0) 
which is handed to `GitLabHookManager.PreReceiveHook`, and immediately decoded via `gitcmd.HooksPayloadFromEnv(env)`: [2](#0-1) 

The only server-side validation performed before this is `locator.ValidateRepository(ctx, in.GetRepository())`: [3](#0-2) 
There is no check binding the `TransactionID`/`UserDetails`/quarantine directories inside the caller-supplied environment payload to an actual transaction that the calling context legitimately owns — the same class of gap as the report's missing "is this caller the one that initialized the hook" check. `ReferenceTransactionHook` and `UpdateHook` have the identical pattern (repository-only validation, then trusting the embedded payload): [4](#0-3) [5](#0-4) 

Within the manager, the pre-receive path further trusts `GIT_OBJECT_DIRECTORY`/`GIT_ALTERNATE_OBJECT_DIRECTORIES` values taken directly from the caller-supplied `env` and converts them to relative paths using only `filepath.Rel`, with no containment check that the resulting relative path stays inside the repository: [6](#0-5) [7](#0-6) 
Because `filepath.Rel` will happily produce paths containing `../` sequences when the two inputs are unrelated absolute paths, and this relative path is set as `repo.GitObjectDirectory` and forwarded to the Rails `/internal/allowed` API and later used to instruct Git to add an alternate object directory search path, a caller who can invoke `PreReceiveHook` directly (bypassing the legitimate `git-receive-pack` → `gitaly-hooks` → quarantine flow described in `doc/object_quarantine.md`) can supply arbitrary `GIT_OBJECT_DIRECTORY`/`GIT_ALTERNATE_OBJECT_DIRECTORIES` values, causing Gitaly to treat an attacker-chosen directory as a valid alternate object store for the target repository and to report it to Rails as the quarantine location for that push. This mirrors the reported bug class: "any caller, not just the entity that legitimately established the [hook] context, can drive state that should only be reachable by the initializer."

### Impact Explanation
An attacker able to reach the `HookService` RPCs directly (the same network/auth boundary used by the `gitaly-hooks` binary and, in Praefect-fronted deployments, by any node holding the shared Gitaly auth token) can:
- Forge a `TransactionID` to interact with another user's/repository's in-flight write transaction (`ReferenceTransactionHook`, `PostReceiveHook` both do `m.txRegistry.Get(payload.TransactionID)` based purely on the attacker-controlled payload), potentially recording bogus initial reference values, voting on someone else's transaction, or triggering `stopTransaction` for unrelated pushes.
- Supply forged `GitObjectDirectory`/`GitAlternateObjectDirectories` values that get relativized without a repo-root containment check and then passed to the Rails `Allowed()` API and Git subprocesses as an alternate object directory, causing Gitaly to expose objects from, or graft config pointing to, a directory outside the intended repository — a cross-repository/storage-escape condition.
- Bypass the actual access-control flow (custom hooks, Rails `/internal/allowed` check tied to a real push) since the RPC can be invoked standalone with crafted `EnvironmentVariables`, independent of whether `git-receive-pack` is actually running.

This is a Medium-severity finding: it requires the caller to already be able to reach the internal `HookService` (an authenticated Gitaly client), but once that bar is met, no additional binding checks prevent forging hook context for arbitrary repositories/transactions.

### Likelihood Explanation
Reachability depends on whether the `HookService` socket/RPCs are exposed only to the loopback `gitaly-hooks` subprocess (via `InternalSocket`/`InternalSocketToken`) or are also reachable through Gitaly's normal gRPC listener protected by the shared Gitaly auth token (`cfg.Auth.GetToken()`), which is the same token used by `gitaly-hooks`, Praefect nodes, and other trusted-but-not-fully-isolated callers. Because `NewHooksPayload` reuses `cfg.Auth.GetToken()` as `InternalSocketToken` rather than a per-invocation random secret bound to the specific transaction/repository, any holder of that shared token can construct a valid payload for an arbitrary repository or transaction ID — this is a "crafted RPC field" path rather than a privileged-actor-only path, satisfying the validation bar. Exact exposure of the socket (whether it's strictly loopback-only) could not be fully confirmed within the indexed files; this should be verified against `internal/gitaly/server` socket/listener setup, which was not available in the current search results.

### Recommendation
Bind the hook-RPC context to a verifiable, per-request secret/transaction record rather than trusting caller-supplied environment variables wholesale:
- Validate that `payload.TransactionID` (and `payload.Repo`) correspond to a transaction that was actually created by the current Gitaly node for a specific repository/user before honoring reference-transaction/pre-receive/update calls, rejecting requests that reference an unknown or mismatched transaction/repository pairing.
- When computing relative quarantine object directories in `getRelativeObjectDirs`, validate the resulting relative path stays within the repository (reject paths containing `..` or absolute prefixes escaping `repoPathReal`) rather than accepting whatever `filepath.Rel` produces.
- Ensure the `HookService` is only reachable via the loopback internal socket authenticated with a per-run random token, not the same static shared secret used elsewhere, so that possessing generic Gitaly RPC access is insufficient to forge hook payloads for other repositories/transactions.

### Proof of Concept
1. Obtain valid Gitaly gRPC credentials (the shared `Auth.Token` used generally for internal RPCs, as reused in `HooksPayload.InternalSocketToken`). [8](#0-7) 
2. Craft a `PreReceiveHookRequest` for a target repository with `EnvironmentVariables` containing a `GITALY_HOOKS_PAYLOAD` whose `Repo.GitObjectDirectory`/`GitAlternateObjectDirectories` point at an attacker-controlled path, and/or a `TransactionID` belonging to another user's in-flight push.
3. Call `HookService.PreReceiveHook` directly (bypassing `git-receive-pack`/`gitaly-hooks`); the handler only checks `locator.ValidateRepository` on the target repo and otherwise trusts the payload: [9](#0-8) 
4. Observe that `preReceiveHook` relativizes and installs the attacker-chosen object directories via `getRelativeObjectDirs` without containment validation, and forwards them to Rails' `Allowed()` API as if they were the legitimate quarantine directory for this push: [10](#0-9)

func getRelativeObjectDirs(repoPath, gitObjectDir, gitAlternateObjectDirs string) (string, []string, error) {
	repoPathReal, err := filepath.EvalSymlinks(repoPath)
	if err != nil {
		return "", nil, err
	}

	gitObjDirRel, err := filepath.Rel(repoPathReal, gitObjectDir)
	if err != nil {
		return "", nil, err
	}

	var gitAltObjDirsRel []string

	for _, gitAltObjDirAbs := range strings.Split(gitAlternateObjectDirs, ":") {
		gitAltObjDirRel, err := filepath.Rel(repoPathReal, gitAltObjDirAbs)
		if err != nil {
			return "", nil, err
		}

		gitAltObjDirsRel = append(gitAltObjDirsRel, gitAltObjDirRel)
	}

	return gitObjDirRel, gitAltObjDirsRel, nil

func (m *GitLabHookManager) preReceiveHook(ctx context.Context, payload gitcmd.HooksPayload, repo *gitalypb.Repository, pushOptions, envs []string, changes []byte, stdout, stderr io.Writer) error {
	repoPath, err := m.locator.GetRepoPath(ctx, repo)
	if err != nil {
		return structerr.NewInternal("getting repo path: %w", err)
	}

	if gitObjDir, gitAltObjDirs := env.ExtractValue(envs, "GIT_OBJECT_DIRECTORY"), env.ExtractValue(envs, "GIT_ALTERNATE_OBJECT_DIRECTORIES"); gitObjDir != "" && gitAltObjDirs != "" {
		gitObjectDirRel, gitAltObjectDirRel, err := getRelativeObjectDirs(repoPath, gitObjDir, gitAltObjDirs)
		if err != nil {
			return structerr.NewInternal("getting relative git object directories: %w", err)
		}

		repo.GitObjectDirectory = gitObjectDirRel
		repo.GitAlternateObjectDirectories = gitAltObjectDirRel
	}

	if len(changes) == 0 {
		return structerr.NewInternal("hook got no reference updates")
	}

	if repo.GetGlRepository() == "" {
		return structerr.NewInternal("repository not set")
	}
	if payload.UserDetails == nil {
		return structerr.NewInternal("payload has no receive hooks info")
	}
	if payload.UserDetails.UserID == "" {
		return structerr.NewInternal("user ID not set")
	}
	if payload.UserDetails.Protocol == "" {
		return structerr.NewInternal("protocol not set")
	}

	params := gitlab.AllowedParams{
		RepoPath:                      repoPath,
		RelativePath:                  repo.GetRelativePath(),
		GitObjectDirectory:            repo.GetGitObjectDirectory(),
		GitAlternateObjectDirectories: repo.GetGitAlternateObjectDirectories(),
		GLRepository:                  repo.GetGlRepository(),
		GLID:                          payload.UserDetails.UserID,
		GLProtocol:                    payload.UserDetails.Protocol,
		Changes:                       string(changes),
		PushOptions:                   pushOptions,
		ClientContext:                 payload.GitalyClientContext,
	}
