### Title
Unauthenticated `/shutdown` HTTP POST permanently terminates the signer's event-receiver thread - (File: `libsigner/src/events.rs`)

### Summary
`SignerEventReceiver::next_event` handles any incoming request to the path `/shutdown` by unconditionally setting `stop_signal` to `true` and returning `Err(EventError::Terminated)`, with no verification of the sender's identity, source address, or any secret/signature. Any remote party able to open a TCP connection to the signer's bound event port can send a bare `POST /shutdown` request and permanently halt the signer's event-receiving thread.

### Finding Description
In `libsigner/src/events.rs`, `next_event()` dispatches on `request.url()` inside the closure passed to `with_server`: [1](#0-0) 

There is no check comparing the request's source `SocketAddr`, no signature/HMAC verification, no shared-secret header check — nothing that distinguishes a legitimate "same node that started the signer" caller (which normally triggers this path internally via `SignerStopSignaler::send` at `libsigner/src/events.rs:376-395`) from an arbitrary external TCP client. The `tiny_http`-based `HttpServer` created in `bind()` listens on the configured `bind_addr` [2](#0-1)  and, per `Signer::spawn` in `libsigner/src/runloop.rs`, that address is whatever operators configure for the signer to receive node event POSTs [3](#0-2) . If that address is reachable from the network (not restricted to loopback via firewall/config), any remote unprivileged party can connect and send:

```
POST /shutdown HTTP/1.1\r\nHost: <addr>\r\nConnection: close\r\nContent-Length: 0\r\n\r\n
```

This causes `stop_signal.store(true, Ordering::SeqCst)` and `Err(EventError::Terminated)` to propagate out of `next_event()`, which (via `EventReceiver::main_loop`, not shown here but referenced by the event thread in `runloop.rs:229-236`) ends the event-receiving thread. Once terminated, the signer can no longer receive `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, or `/new_block` POSTs from the node, silencing the signer's participation in signing rounds until manually restarted.

### Impact Explanation
A single unauthenticated HTTP POST permanently disables the signer's ability to receive further events from its paired node — including StackerDB chunk events used for signer coordination — until the operator restarts the signer process. This is a remote, unauthenticated, single-message DoS against the signer's event-receiving thread, matching the "Critical – remote crash/unauthenticated DoS from few messages" category. The attack is trivially repeatable against a fresh signer instance and requires no knowledge of any secret, key, or node-specific state — just the fixed, well-known path `/shutdown`.

### Likelihood Explanation
The only precondition is TCP reachability to the signer's bound event port. If an operator binds the signer's event-receiver to a non-loopback interface (e.g., to allow a co-located but separately hosted node to POST events, or misconfigures the bind address), the port is reachable by any unprivileged remote party per the threat model. The attacker needs no credentials, no valid StackerDB slot, and no signature — a bare raw socket write of a fixed HTTP request suffices. This is a code-level authentication gap, not a volumetric/DDoS issue, since exactly one crafted message with no valid credential causes the halt.

### Recommendation
Do not accept unauthenticated shutdown requests from the network. Options: bind the event-receiver strictly to loopback and rely on `SignerStopSignaler::send` using loopback-only connections; or add an explicit shared-secret/local-only check (e.g., verify `request.remote_addr()` is loopback, or require a token known only to the node/runloop) before honoring `/shutdown`, rejecting all other callers with a 4xx response instead of halting the receiver.
