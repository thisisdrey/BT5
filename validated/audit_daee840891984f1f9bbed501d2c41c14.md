### Title
Attacker-controlled `GitObjectDirectory`/`GitAlternateObjectDirectories` fields bypass storage confinement in `FetchRemote` via unvalidated alternates - ([File: internal/gitaly/service/repository/fetch_remote.go])

### Summary
`validateFetchRemoteRequest` only validates `req.GetRepository().RelativePath` through `s.locator.ValidateRepository`, but never validates the `GitObjectDirectory`/`GitAlternateObjectDirectories` fields of the incoming `Repository` message. These attacker-supplied fields flow unfiltered through `quarantine.Apply` into the quarantined repository object and are ultimately used by `alternates.Env`, which performs zero path-confinement checks before joining them onto the repository path and exporting them as `GIT_OBJECT_DIRECTORY`/`GIT_ALTERNATE_OBJECT_DIRECTORIES` for the spawned `git fetch` process.

### Finding Description
`validateFetchRemoteRequest` at [1](#0-0)  only checks `RelativePath`/`StorageName` via `s.locator.ValidateRepository`, and never inspects `GitObjectDirectory` or `GitAlternateObjectDirectories`.

`fetchRemoteAtomic` then calls `quarantine.New(ctx, req.GetRepository(), ...)` [2](#0-1) , which internally calls `locator.GetRepoPath(ctx, repo, storage.WithRepositoryVerificationSkipped())` [3](#0-2)  — this only skips the "is-a-valid-git-directory" check, `ValidateRelativePath` for `RelativePath` still runs inside `ValidateRepository` [4](#0-3) , so `RelativePath` escape is not the issue.

The real gap is in `quarantine.Apply`, which builds the quarantined repo's alternates list directly from the attacker-supplied fields without any validation: [5](#0-4) 
`objectDir` is `repo.GetGitObjectDirectory()` (attacker controlled, defaults to `"objects"` only if empty), and `alternateObjectDirs` is seeded with that plus the entire attacker-supplied `repo.GetGitAlternateObjectDirectories()` slice — none of it goes through `storage.ValidateRelativePath` or the confinement logic that exists elsewhere (e.g. `localrepo.Repo.ObjectDirectoryPath`, which explicitly calls `storage.ValidateRelativePath` and rejects paths outside the repo/quarantine prefix, see [6](#0-5) ).

This resulting `quarantinedRepo` proto is used to build the `localrepo.Repo` that executes `git fetch` [7](#0-6) . When the command is spawned, `ExecCommandFactory.newCommand` calls `alternates.Env(repoPath, repo.GetGitObjectDirectory(), repo.GetGitAlternateObjectDirectories())` [8](#0-7) . `alternates.Env` performs **no path confinement whatsoever** — it simply does `filepath.Join(repoPath, dir)` for each entry and emits `GIT_OBJECT_DIRECTORY`/`GIT_ALTERNATE_OBJECT_DIRECTORIES`: [9](#0-8) 

Because `filepath.Join` normalizes `..` segments, an attacker-supplied `GitAlternateObjectDirectories` entry such as `"../../../../"` resolves outside the repository (and potentially outside the storage root entirely), and git will treat that directory as a valid alternate object store for the duration of the `git fetch`/subsequent `git cat-file`/`git-update-ref` operations invoked on the quarantined repo.

### Impact Explanation
This allows an unprivileged user who controls the `FetchRemoteRequest.Repository` message (in particular `GitObjectDirectory`/`GitAlternateObjectDirectories`) to make Gitaly's `git` subprocess read objects from an arbitrary directory outside the confined repository/storage root, as long as that directory is readable by the Gitaly process user and structured as a Git object store (or even a loose-object directory). This is a cross-repository/arbitrary-path object access primitive — objects from other repositories (or any readable directory on the Gitaly host) can be resolved as if they belonged to the attacker's own repository, matching the "storage-path escape / cross-repository object access" impact class.

### Likelihood Explanation
The attacker only needs the ability to shape the `Repository` message fields sent to `FetchRemote` (an RPC field-level precondition explicitly allowed by this audit's threat model). No admin role, no leaked secret, and no separate bug in git/Rails is required — the missing validation is entirely within Gitaly's `validateFetchRemoteRequest`/`quarantine.Apply`/`alternates.Env` code path. The exploit is deterministic and repeatable for any repository the attacker can target with a `FetchRemote` call.

### Recommendation
- Validate `GitObjectDirectory` and `GitAlternateObjectDirectories` in `validateFetchRemoteRequest` (and generally wherever a `Repository` message is accepted) using the same confinement logic as `localrepo.Repo.ObjectDirectoryPath` (i.e., `storage.ValidateRelativePath` against the repository/storage root, with the existing quarantine-prefix carve-out).
- Alternatively/additionally, make `alternates.Env` itself reject or clamp any `objectDirectory`/`alternateObjectDirectories` entries that escape `repoPath`'s root before exporting them as environment variables, since it is the last common chokepoint used by every git invocation.

```go
func TestFetchRemote_alternatesEscape(t *testing.T) {
    ctx := testhelper.Context(t)
    cfg, client := setupRepositoryService(t)

    repo, _ := gittest.CreateRepository(t, ctx, cfg)

    // Attacker crafts a Repository with a valid RelativePath, but sets
    // GitAlternateObjectDirectories to a path that escapes the repository root.
    repo.GitAlternateObjectDirectories = []string{"../../../../"}

    _, err := client.FetchRemote(ctx, &gitalypb.FetchRemoteRequest{
        Repository: repo,
        RemoteParams: &gitalypb.RemoteRepository{Url: "https://example.com/some.git"},
    })
    // Expect: no InvalidArgument is raised for GitAlternateObjectDirectories,
    // proving the field is never validated (contrast with GetObjectDirectorySize's
    // "relative path escapes root directory" InvalidArgument for the same field).
    require.NotContains(t, err.Error(), "relative path escapes root directory")
}
```
This mirrors the existing test `TestGetObjectDirectorySize_quarantine`/"quarantined repo with different relative path" pattern [10](#0-9) , which shows that `GetObjectDirectorySize` *does* enforce confinement via `ObjectDirectoryPath`, while `FetchRemote`'s `validateFetchRemoteRequest` and `alternates.Env` path do not.

```go
// ObjectDirectoryPath returns the full path of the object directory. The errors returned are gRPC
// errors with relevant error codes and should be passed back to gRPC without further decoration.
func (repo *Repo) ObjectDirectoryPath(ctx context.Context) (string, error) {
	repoPath, err := repo.Path(ctx)
	if err != nil {
		return "", err
	}

	objectDirectoryPath := repo.GetGitObjectDirectory()
	if objectDirectoryPath == "" {
		return "", structerr.NewInvalidArgument("object directory path is not set")
	}

	storagePath, err := repo.locator.GetStorageByName(ctx, repo.GetStorageName())
	if err != nil {
		return "", fmt.Errorf("get storage by name: %w", err)
	}

	// Ensure the path points somewhere in the storage.
	relativeObjectDirectoryPath, err := storage.ValidateRelativePath(storagePath, filepath.Join(repoPath, objectDirectoryPath))
	if err != nil {
		return "", structerr.NewInvalidArgument("validate relative path: %w", err)
	}

	parentDir := filepath.Base(filepath.Dir(relativeObjectDirectoryPath))
	baseDir := filepath.Base(relativeObjectDirectoryPath)
	isTransactionQuarantineDir := (baseDir == "quarantine") || ((parentDir == "quarantine") && strings.HasPrefix(baseDir, "tmp_objdir"))

	// Transactions quarantine a repository by pointing the object directory to a 'quarantine' named
	// directory in the transaction's temporary directory. If the base directory is `quarantine`,
	// Git push may apply an additional layer of quarantine such as `/quarantine/tmp_objdir-incoming-Gbc29N`
	// so we don't assert the `/quarantine` being the last element of the path. We thus also check for
	// whether the parent directory is in `quarantine` and whether the base directory has the expected
	// `tmp_objdir` suffix.
	if !isTransactionQuarantineDir {
		// We need to check whether the relative object directory as given by the repository is
		// a valid path. This may either be a path in the Git repository itself, where it may either
		// point to the main object directory storage or to an object quarantine directory as
		// created by git-receive-pack(1). Alternatively, if that is not the case, then it may be a
		// manual object quarantine directory located in the storage's temporary directory. These
		// have a repository-specific prefix which we must check in order to determine whether the
		// quarantine directory does in fact belong to the repo at hand.
		if _, origError := storage.ValidateRelativePath(repoPath, objectDirectoryPath); origError != nil {
			tempDir, err := repo.locator.TempDir(repo.GetStorageName())
			if err != nil {
				return "", structerr.NewInvalidArgument("getting storage's temporary directory: %w", err)
			}

			expectedQuarantinePrefix := filepath.Join(tempDir, storage.QuarantineDirectoryPrefix(repo))
			absoluteObjectDirectoryPath := filepath.Join(repoPath, objectDirectoryPath)

			// The relative path is outside of the repository
			if !strings.HasPrefix(absoluteObjectDirectoryPath, expectedQuarantinePrefix) {
				return "", structerr.NewInvalidArgument("not a valid relative path: %w", origError)
			}
		}
	}

	fullPath := filepath.Join(repoPath, objectDirectoryPath)
	if _, err := os.Stat(fullPath); os.IsNotExist(err) {
		return "", structerr.NewNotFound("object directory does not exist: %q", fullPath)
	}

	return fullPath, nil
}
```

```go
// Env returns the alternate object directory environment variables.
func Env(repoPath, objectDirectory string, alternateObjectDirectories []string) []string {
	var env []string
	if objectDirectory != "" {
		env = append(env, fmt.Sprintf("GIT_OBJECT_DIRECTORY=%s", filepath.Join(repoPath, objectDirectory)))
	}

	if len(alternateObjectDirectories) > 0 {
		var dirsList []string

		for _, dir := range alternateObjectDirectories {
			dirsList = append(dirsList, filepath.Join(repoPath, dir))
		}

		env = append(env, fmt.Sprintf("GIT_ALTERNATE_OBJECT_DIRECTORIES=%s", strings.Join(dirsList, ":")))
	}

	return env
}
```
