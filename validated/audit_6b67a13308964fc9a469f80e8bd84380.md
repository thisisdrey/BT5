This confirms the exploit path: `execute_signed_intents` iterates over the batch of `MultiPayload` and calls `execute_signed_intent` for each independently, with fee state (`fees_collected`) scoped to a single `TokenDiff::execute_intent` call and never aggregated across the batch or across separate signed intents.### Title
Fee bypass via unit-splitting of NEP-245/IMT `TokenDiff` legs across a batch - ([File: contracts/defuse/core/src/intents/token_diff.rs])

### Summary
`TokenDiff::token_fee` waives fees for `TokenIdType::Nep245`/`TokenIdType::Imt` whenever the per-leg `amount <= 1`, but this exemption is evaluated independently for every single `TokenDiff::execute_intent` invocation, not per account/token across the whole batch. An attacker can split any large NEP-245 sub-token transfer into `K` unit-sized (`delta = -1`) `TokenDiff` intents — either as multiple entries in one `DefuseIntents.intents` list or as multiple signed `MultiPayload`s in one `execute_intents` call — and pay zero fee on the full aggregate volume, whereas expressing the same net effect as a single `delta = -K` leg would pay `fee_ceil(protocol_fee, K)`.

### Finding Description
The claimed binding: `fee_collector_credit(T, batch) == Pips::fee_ceil(protocol_fee, sum_of_negative_deltas_of_T_in_batch)`. Tracing the code shows this does not hold.

- `TokenDiff::execute_intent` (contracts/defuse/core/src/intents/token_diff.rs:41-104) resets `fees_collected` to `Amounts::default()` on every call, and for each `(token_id, delta)` in `self.diff` computes `fee = Self::token_fee(token_id, amount, protocol_fee).fee_ceil(amount)` using only the amount local to that single leg [1](#0-0) .
- `token_fee` explicitly zeroes the fee for `TokenIdType::Nep245`/`TokenIdType::Imt` when `amount <= 1`: `TokenIdType::Nep245 | TokenIdType::Imt if amount > 1 => {}` else `return Pips::ZERO` [2](#0-1) .
- Batch execution never re-aggregates deltas across intents for fee purposes: `DefuseIntents::execute_intent` simply loops `for intent in self.intents { intent.execute_intent(...)?; }` [3](#0-2) , and `Engine::execute_signed_intents` loops over the whole `MultiPayload` batch calling `execute_signed_intent` independently per payload, with the only cross-cutting check being the final zero-sum invariant in `finalize()`, which enforces balance conservation but has no notion of fee accumulation [4](#0-3) .

Attacker's payload: sign either (a) one `DefusePayload` whose `DefuseIntents.intents` contains `K` `TokenDiff { diff: {token_id: -1, other_token: +x} }` entries, or (b) `K` separately signed `MultiPayload`s each with one such `TokenDiff`, and submit them together to `execute_intents`. Each leg independently satisfies `amount == 1`, so `token_fee` returns `Pips::ZERO` every time, and the fee_collector receives `0` total for token `T` regardless of `K`, while the signer's aggregate transferred volume of `T` is `K`.

None of the existing guards prevent this: `MultiPayload::verify`, nonce/salt checks, and `has_public_key` only authenticate/authorize the signer and intents — they say nothing about fee aggregation. The zero-sum invariant checked in `finalize()` only ensures net token balances match across the whole batch (deltas sum to zero including fees paid), it does not constrain how the exempted-fee unit legs are structured, so a batch built entirely of unit legs still balances to zero with zero fee taken.

### Impact Explanation
This directly matches the "protocol fees bypassed" Critical impact category. Fees intended for the `fee_collector` on NEP-245/IMT token-in legs can be entirely avoided for any volume by decomposing the transfer into unit-sized legs within a single batch, at no extra cost to the attacker beyond gas for additional intents/signatures they already control. This applies to any NEP-245/IMT token the attacker can source in bulk (including attacker-deployed MT contracts used as wrapped-fungible assets), and is repeatable indefinitely across accounts, tokens, and batches; the fee_collector systematically under-collects revenue proportional to the volume routed this way.

### Likelihood Explanation
Preconditions are trivial for an unprivileged actor: hold (or mint, via a self-deployed MT contract) `K` units of a NEP-245 token, and sign `K` (or one multi-intent) `TokenDiff` payloads with own key(s). No special role, relayer key, or victim key is needed. The only cost is proportional additional gas/signing overhead for splitting into unit legs, which is cheap relative to the fee saved for any nontrivial protocol fee rate and volume. This is fully reproducible with a local `cargo test`/sandbox setup with an arbitrary chosen `K`.

### Recommendation
Aggregate the amount used for the `TokenIdType::Nep245`/`Imt` "amount <= 1" fee-exemption check across all `TokenDiff` legs for the same `token_id` and `signer_id` within the entire `execute_signed_intents` batch (or at minimum within one `DefusePayload`'s intents), rather than per single-leg invocation, before deciding whether to waive the fee. Alternatively, remove the per-leg `amount <= 1` special case for `Nep245`/`Imt` and always charge fees on negative deltas for these token types (relying instead on `fee_ceil` rounding, or a minimum-fee floor), closing the unit-splitting loophole.

fn fee_bypass_via_unit_split_nep245() {
    let fee = Pips::ONE_PERCENT; // nonzero protocol fee
    let token_id = TokenId::from(Nep245TokenId::new(
        "mt.near".parse::<AccountId>().unwrap(),
        "sub1".to_string(),
    ));

    // Case A: K = 100 separate unit legs (delta = -1 each)
    let mut fees_collected_split = Amounts::default();
    for _ in 0..100 {
        let fee_leg = TokenDiff::token_fee(&token_id, 1, fee).fee_ceil(1);
        fees_collected_split.add(token_id.clone(), fee_leg).unwrap();
    }
    assert_eq!(fees_collected_split.amount_for(&token_id), 0);

    // Case B: single leg with delta = -100
    let fee_single = TokenDiff::token_fee(&token_id, 100, fee).fee_ceil(100);
    assert!(fee_single > 0);

    // Binding violated: aggregate fee for same token/volume differs based on batching
    assert_ne!(fees_collected_split.amount_for(&token_id), fee_single);
}

    pub fn execute_signed_intents(
        mut self,
        signed: impl IntoIterator<Item = MultiPayload>,
    ) -> Result<Transfers> {
        for signed in signed {
            self.execute_signed_intent(signed)?;
        }
        self.finalize()
    }

    fn execute_signed_intent(&mut self, signed: MultiPayload) -> Result<()> {
        // verify signed payload and get public key
        let public_key = signed.verify().ok_or(DefuseError::InvalidSignature)?;

        // calculate intent hash
        let hash = signed.hash();

        // extract NEP-413 payload
        let DefusePayload::<DefuseIntents> {
            signer_id,
            verifying_contract,
            deadline,
            nonce,
            message: intents,
        } = signed.extract_defuse_payload()?;

        // check recipient
        if verifying_contract != *self.state.verifying_contract() {
            return Err(DefuseError::WrongVerifyingContract);
        }

        self.inspector.on_deadline(deadline);

        // make sure message is still valid
        if deadline < Timestamp::now() {
            return Err(DefuseError::DeadlineExpired);
        }

        // make sure the account has this public key
        if !self.state.has_public_key(&signer_id, &public_key) {
            return Err(DefuseError::PublicKeyNotExist(signer_id, public_key));
        }

        // commit nonce
        self.verify_intent_nonce(nonce, deadline)?;
        self.state.commit_nonce(signer_id.clone(), nonce)?;

        intents.execute_intent(&signer_id, self, hash)?;
        self.inspector.on_intent_executed(&signer_id, hash, nonce);

        Ok(())
    }

    #[inline]
    fn verify_intent_nonce(&self, nonce: Nonce, intent_deadline: Timestamp) -> Result<()> {
        let Some(nonce) = VersionedNonce::maybe_from(nonce) else {
            return Ok(());
        };

        match nonce {
            VersionedNonce::V1(SaltedNonce {
                salt,
                nonce: ExpirableNonce { deadline, .. },
            }) => {
                if !self.state.is_valid_salt(salt) {
                    return Err(DefuseError::InvalidSalt);
                }

                if intent_deadline > deadline {
                    return Err(DefuseError::DeadlineGreaterThanNonce);
                }

                if deadline < Timestamp::now() {
                    return Err(DefuseError::NonceExpired);
                }
            }
        }

        Ok(())
    }

    #[inline]
    fn finalize(self) -> Result<Transfers> {
        self.state
            .finalize()
            .map_err(DefuseError::InvariantViolated)
    }
