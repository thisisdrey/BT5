### Title
Protocol fee bypass on NEP-245/IMT `TokenDiff` transfers by splitting a quantity into multiple `amount==1` legs - (File: `contracts/defuse/core/src/intents/token_diff.rs`)

### Summary
`TokenDiff::token_fee` charges a fee on NEP-245 (`Nep245`) and IMT (`Imt`) token deltas only when the per-intent `amount > 1`, exempting `amount == 1` entirely. Because this threshold is evaluated per `TokenDiff` intent (not on the signer's aggregate net position across the batch), a signer can split any quantity `N` of an NEP-245/IMT token into `N` separate signed `TokenDiff` intents each with `delta == -1`, paying zero fee in total instead of `fee_ceil(N, protocol_fee)` that a single `delta == -N` intent would incur.

### Finding Description
The broken binding, stated explicitly:
- Expected: `total_fee_collected(token T) == Pips::fee_ceil(protocol_fee, sum_of_negative_deltas_of(T))` for any signer moving `T` out through the Verifier in one settlement.
- Actual: for `TokenIdType::Nep245`/`TokenIdType::Imt`, `token_fee` is computed independently per `TokenDiff` intent as [1](#0-0) 
i.e. `Pips::ZERO` whenever that single intent's `amount <= 1`, and `protocol_fee` (then `fee_ceil`'d) only when that single intent's `amount > 1`.

Code path: in `TokenDiff::execute_intent`, for each `(token_id, delta)` pair in the intent's own `diff` map, the fee is computed from that pair's `amount = delta.unsigned_abs()` alone: [2](#0-1) 
This is called once per `TokenDiff` intent object, and a signer can submit multiple `TokenDiff` intents (in a single `DefuseIntents` message, in multiple `MultiPayload`s, or via multiple signer accounts they control) inside one `execute_intents` batch, each carrying `delta = -1` for the same `token_id`. Each such intent independently hits the `Nep245 | Imt` exemption arm (`amount == 1` -> `Pips::ZERO`), so total fees collected sum to `0`.

Root cause: fee-exemption thresholding is scoped to a single intent's delta magnitude rather than to the signer's aggregate negative delta for that token across the whole settled batch, and nothing (`MultiPayload::verify`, `verify_intent_nonce`, `MaybeLegacyNonces::commit`, `TransferMatcher::finalize`) aggregates or re-checks fee amounts across intents — `finalize()` in `contracts/defuse/core/src/engine/state/deltas.rs` only enforces that net token deltas across the whole batch settle to zero via `TransferMatcher`; it performs no fee re-derivation. [3](#0-2) 

Attacker's payload: two (or `N`) signed `TokenDiff` intents, each `diff = {token_T: -1, token_out: +k}` (or split across counterparty legs to net to zero via `TransferMatcher`), instead of one intent `diff = {token_T: -2, token_out: +2k}`. All are ordinary `execute_intents`/`MultiPayload` calls available to any unprivileged signer with a valid nonce and their own key — no role, relayer key, or DAO access is required. [4](#0-3) 

Why guards don't help: signature verification, nonce checks, and the `Deltas`/`TransferMatcher` invariant only ensure balances move consistently and no double-signature/double-nonce reuse occurs — none of them look at whether fee was correctly assessed on the aggregate signer-side outflow of a token; fee accounting is strictly local to each `TokenDiff::execute_intent` call.

### Impact Explanation
The `fee_collector` account under-collects protocol fees on any NEP-245 (multi-token, which frequently represents fungible-quantity balances of wrapped assets) or IMT transfer whose quantity is split into unit legs, while the signer's net token movement is identical to an un-split transfer. This matches the explicitly listed Critical category "protocol fees bypassed or over-collected." The bypass is fully repeatable: for a transfer of size `N` units, an attacker pays zero fee (vs. `fee_ceil(N, protocol_fee)`) simply by using `N` intents instead of one, for any `N >= 1` and any account/token pair of type `Nep245`/`Imt`. Blast radius is protocol-wide fee revenue for all NEP-245/IMT flows, not limited to a single account.

### Likelihood Explanation
Preconditions: `protocol_fee > 0`, signer holds `>= 2` units of an NEP-245/IMT token they wish to move, and a counterparty (which the attacker can also control, since nothing requires distinct parties) providing the matching opposite deltas so `TransferMatcher::finalize` nets to zero. Attacker cost is trivial — constructing and signing one extra intent per unit split is free apart from transaction/gas cost, and no special privilege, relayer key, or role is needed; this is fully reachable by any ordinary user calling `execute_intents`. It is repeatable indefinitely across accounts, tokens, and batches.

### Recommendation
Compute the NEP-245/IMT fee exemption on the signer's aggregate negative delta per token across the entire settled batch (or per `DefuseIntents` message) rather than per individual `TokenDiff` intent, e.g. accumulate `amount` per `(signer_id, token_id)` before evaluating the `amount > 1` threshold in `TokenDiff::token_fee`, or remove per-intent granularity from the fee-exemption decision entirely and require exemption only when the token's true unit quantity (e.g., an actual NFT-style unique id, always amount 1) is transferred, not an arbitrary application-chosen split.

    // If unmatched deltas overflow, then Err(None) is returned.
    pub fn finalize(self) -> Result<Transfers, InvariantViolated> {
        let mut transfers = Transfers::default();
        let mut deltas = TokenDeltas::default();
        for (token_id, transfer_matcher) in self.0 {
            if let Err(unmatched) = transfer_matcher.finalize_into(&token_id, &mut transfers)
                && (unmatched == 0 || deltas.apply_delta(token_id, unmatched).is_none())
            {
                return Err(InvariantViolated::Overflow);
            }
        }
        if !deltas.is_empty() {
            return Err(InvariantViolated::UnmatchedDeltas {
                unmatched_deltas: deltas,
            });
        }
        Ok(transfers)
    }
