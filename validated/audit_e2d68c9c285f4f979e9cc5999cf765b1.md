### Title
Stale PromiseYield state (`PromiseYieldReceipt`/`PromiseYieldStatus`/`YieldIdToDataId`/`DataIdToYieldId`) survives `DeleteAccount` and is later replayed as a forged self-call against whoever recreates the account name - ([File: core/store/src/utils/mod.rs])

### Summary
`remove_account` (`core/store/src/utils/mod.rs:504-575`) only removes `Account`, `ContractCode`, `AccessKey`/`GasKeyNonce`, and `ContractData` rows, but never touches `PromiseYieldReceipt`, `PromiseYieldStatus`, `YieldIdToDataId`, or `DataIdToYieldId`. These are all keyed purely by the `AccountId` string, so a pending yield created before an account is deleted stays live in state and is later delivered — as an authenticated self-call (`predecessor_id == receiver_id == account_id`) with attacker-chosen `method_name`/`arguments` — to whatever new owner recreates that account name.

### Finding Description
When a contract calls `promise_yield_create`/`promise_yield_create_with_id`, the runtime writes:
- `PromiseYieldStatus{receiver_id, data_id}` and `PromiseYieldReceipt{receiver_id, data_id}` (`runtime/runtime/src/ext.rs:353-369`, `core/store/src/utils/mod.rs:200-212`),
- optionally `YieldIdToDataId`/`DataIdToYieldId` (`core/store/src/utils/mod.rs:281-297`),
- a global, shard-scoped `PromiseYieldTimeout{index}` entry via `enqueue_promise_yield_timeout` (`core/store/src/utils/mod.rs:182-198`, called from `runtime/runtime/src/function_call.rs:161-169`).

The parked receipt created by `create_promise_yield_receipt` sets `receiver_id = current_account_id` (i.e. the calling account itself), and the wrapping `Receipt` built in `function_call.rs:187-189` sets `predecessor_id = account_id`. So the parked action receipt is inherently a **self-call**: `predecessor_id == receiver_id == account_id`.

`action_delete_account` (`runtime/runtime/src/actions.rs:314-390`) performs no check for outstanding yields and calls `remove_account` (`core/store/src/utils/mod.rs:504-575`), which removes only `Account`/`ContractCode`/`AccessKey`/`GasKeyNonce`/`ContractData`. The four PromiseYield-related trie key families are never enumerated or removed there.

The global `PromiseYieldTimeout` queue is shard-scoped, not account-scoped, and its consumer `resolve_promise_yield_timeouts` (`runtime/runtime/src/lib.rs:3009-3104`) only checks `contains_key(PromiseYieldReceipt{receiver_id, data_id})` (line 3051) — with no check that the account still exists, let alone that it's still owned by the same key-holder. If the key is present (which it still is, since `remove_account` never cleared it), the runtime synthesizes a `PromiseResume` receipt with `predecessor_id = receiver_id = queue_entry.account_id` and forwards/buffers it.

When that `PromiseResume` receipt is later applied, `process_receipt` (`runtime/runtime/src/lib.rs:1500-1562`) looks up `get_promise_yield_receipt(state_update, account_id, data_id)` — again purely by name, with no linkage to any account "generation" — finds the still-present stored yield receipt, and executes it via `apply_action_receipt`. The executed actions are exactly the `method_name`/`arguments` the *original* (now-deleted) account owner chose when calling `promise_yield_create`, run against whatever contract now occupies that account name, with `predecessor_id == current_account_id` (a self-call).

Attack flow:
1. Attacker's contract on account `A` calls `promise_yield_create_with_id(method_name, arguments, ...)`, writing `PromiseYieldReceipt`, `PromiseYieldStatus`, `YieldIdToDataId`, `DataIdToYieldId` for `A`, and enqueuing a `PromiseYieldTimeout` entry.
2. Attacker submits `DeleteAccount` for `A` before the timeout fires. `action_delete_account` → `remove_account` clears `Account`/`ContractCode`/`AccessKey`/`ContractData` but leaves all four PromiseYield trie key families intact.
3. Account name `A` becomes available; at some later point a different, unrelated party creates a new account named `A` and deploys their own contract (e.g. one that gates privileged/internal logic behind `predecessor_account_id() == current_account_id()`, a common self-call trust pattern).
4. The pre-existing `PromiseYieldTimeout` entry for `A` eventually fires in `resolve_promise_yield_timeouts`, finds `PromiseYieldReceipt{A, data_id}` still present, and emits/executes a self-call into the new owner's contract using the attacker's chosen `method_name`/`arguments` — actions the new account owner never authorized.

No existing check (signature, nonce, access-key, `check_account_existence`, storage staking) intervenes, because the entire path is driven by trie keys that are never re-validated against account identity/existence.

### Impact Explanation
This is an authorization-escalation primitive across account identities on the same shard: a party who no longer owns account `A` can plant a forged, self-authenticated action receipt that fires later against a completely different party that later claims the name `A`, with attacker-controlled method name and argument bytes. Depending on what privileged self-call surface the new contract exposes (common in callback/resolve patterns that trust `predecessor == current_account_id`), this can be leveraged for state corruption, spurious balance/callback resolution, or other logic bypass in the new owner's contract — falling under "authorization escalation across accounts or promises."

### Likelihood Explanation
Preconditions are cheap and fully attacker-controlled up to step 3: deploying a wasm contract, calling `promise_yield_create_with_id`, and issuing `DeleteAccount` are ordinary unprivileged transactions. The remaining precondition — that some other party later reuses the exact deleted account name and deploys a contract with a matching privileged self-call method/signature — is opportunistic rather than guaranteed for arbitrary victims, but the attacker can pick account names anticipated to be desirable/recycled (e.g., short names) and select `method_name` values matching common self-call callback conventions to raise the hit probability. The underlying code defect (stale, unscoped PromiseYield state surviving `DeleteAccount`) is fully deterministic and reproducible on every run.

### Recommendation
`remove_account` should enumerate and remove any pending `PromiseYieldReceipt`/`PromiseYieldStatus`/`YieldIdToDataId`/`DataIdToYieldId` rows for the account being deleted (mirroring how it already enumerates `AccessKey`/`ContractData` via prefix iteration), and/or `resolve_promise_yield_timeouts`/`process_receipt` should verify the account still exists (and ideally that it's the "same" account instance, e.g. by fencing account state with a generation/nonce) before treating a stored `PromiseYieldReceipt` as valid to execute.

// Enqueues given timeout to the PromiseYield timeout queue
pub fn enqueue_promise_yield_timeout(
    state_update: &mut TrieUpdate,
    promise_yield_indices: &mut PromiseYieldIndices,
    account_id: AccountId,
    data_id: CryptoHash,
    expires_at: BlockHeight,
) {
    set(
        state_update,
        TrieKey::PromiseYieldTimeout { index: promise_yield_indices.next_available_index },
        &PromiseYieldTimeout { account_id, data_id, expires_at },
    );
    promise_yield_indices.next_available_index = promise_yield_indices
        .next_available_index
        .checked_add(1)
        .expect("Next available index for PromiseYield timeout queue exceeded the integer limit");
}

pub fn set_promise_yield_receipt(state_update: &mut TrieUpdate, receipt: &Receipt) {
    match receipt.versioned_receipt() {
        VersionedReceiptEnum::PromiseYield(action_receipt) => {
            assert!(action_receipt.input_data_ids().len() == 1);
            let key = TrieKey::PromiseYieldReceipt {
                receiver_id: receipt.receiver_id().clone(),
                data_id: action_receipt.input_data_ids()[0],
            };
            set(state_update, key, receipt);
        }
        _ => unreachable!("Expected PromiseYield receipt"),
    }
}

/// Removes account, code and all access keys and gas keys associated to it.
pub fn remove_account(
    state_update: &mut TrieUpdate,
    account_id: &AccountId,
) -> Result<RemoveAccountResult, StorageError> {
    state_update.remove(TrieKey::Account { account_id: account_id.clone() });
    state_update.remove(TrieKey::ContractCode { account_id: account_id.clone() });

    let mut gas_key_nonce_count: usize = 0;
    let mut gas_key_nonce_total_key_bytes: usize = 0;

    // Removing access keys and gas key nonces
    let lock = state_update.trie().lock_for_iter();
    let mut keys_to_remove: Vec<TrieKey> = Vec::new();
    for raw_key in state_update
        .locked_iter(&trie_key_parsers::get_raw_prefix_for_access_keys(account_id), &lock)?
    {
        let raw_key = raw_key?;
        let key_handle = trie_key_parsers::parse_key_handle_from_access_key_key(
            &raw_key, account_id,
        )
        .map_err(|_e| {
            StorageError::StorageInconsistentState(
                "Can't parse key handle from raw key for AccessKey".to_string(),
            )
        })?;
        let nonce_index =
            trie_key_parsers::parse_nonce_index_from_gas_key_key(&raw_key, account_id, &key_handle)
                .map_err(|_e| {
                    StorageError::StorageInconsistentState(
                        "Can't parse nonce index from raw key for AccessKey".to_string(),
                    )
                })?;
        if let Some(index) = nonce_index {
            gas_key_nonce_count += 1;
            gas_key_nonce_total_key_bytes += raw_key.len();
            keys_to_remove.push(TrieKey::gas_key_nonce(
                account_id.clone(),
                key_handle.clone(),
                index,
            ));
        } else {
            keys_to_remove.push(TrieKey::access_key(account_id.clone(), key_handle.clone()));
        }
    }
    drop(lock);

    for trie_key in keys_to_remove {
        state_update.remove(trie_key);
    }

    // Removing contract data
    let lock = state_update.trie().lock_for_iter();
    let data_keys = state_update
        .locked_iter(&trie_key_parsers::get_raw_prefix_for_contract_data(account_id, &[]), &lock)?
        .map(|raw_key| {
            trie_key_parsers::parse_data_key_from_contract_data_key(&raw_key?, account_id)
                .map_err(|_e| {
                    StorageError::StorageInconsistentState(
                        "Can't parse data key from raw key for ContractData".to_string(),
                    )
                })
                .map(Vec::from)
        })
        .collect::<Result<Vec<_>, _>>()?;
    drop(lock);

    for key in data_keys {
        state_update.remove(TrieKey::ContractData { account_id: account_id.clone(), key });
    }
    Ok(RemoveAccountResult { gas_key_nonce_count, gas_key_nonce_total_key_bytes })
}

fn resolve_promise_yield_timeouts(
    processing_state: &mut ApplyProcessingReceiptState,
    receipt_sink: &mut ReceiptSink,
    compute_limit: u64,
) -> Result<ResolvePromiseYieldTimeoutsResult, RuntimeError> {
    let mut state_update = &mut processing_state.state_update;
    let total = &mut processing_state.total;
    let apply_state = &processing_state.apply_state;

    let mut promise_yield_indices: PromiseYieldIndices =
        get(state_update, &TrieKey::PromiseYieldIndices)?.unwrap_or_default();
    let initial_promise_yield_indices = promise_yield_indices.clone();
    let mut new_receipt_index: usize = 0;

    let mut processed_yield_timeouts = vec![];
    let yield_processing_start = std::time::Instant::now();
    while promise_yield_indices.first_index < promise_yield_indices.next_available_index {
        if total.compute >= compute_limit || state_update.trie.check_proof_size_limit_exceed() {
            break;
        }

        let queue_entry_key =
            TrieKey::PromiseYieldTimeout { index: promise_yield_indices.first_index };

        let queue_entry =
            get::<PromiseYieldTimeout>(state_update, &queue_entry_key)?.ok_or_else(|| {
                StorageError::StorageInconsistentState(format!(
                    "PromiseYield timeout queue entry #{} should be in the state",
                    promise_yield_indices.first_index
                ))
            })?;

        // Queue entries are ordered by expires_at
        if queue_entry.expires_at > apply_state.block_height {
            break;
        }

        // Check if the yielded promise still needs to be resolved
        let promise_yield_key = TrieKey::PromiseYieldReceipt {
            receiver_id: queue_entry.account_id.clone(),
            data_id: queue_entry.data_id,
        };
        if state_update.contains_key(&promise_yield_key, AccessOptions::DEFAULT)? {
            let new_receipt_id = create_receipt_id_from_receipt_id(
                &queue_entry.data_id,
                apply_state.block_height,
                new_receipt_index,
            );
            new_receipt_index += 1;

            // Create a PromiseResume receipt to resolve the timed-out yield.
            let resume_receipt = Receipt::V0(ReceiptV0 {
                predecessor_id: queue_entry.account_id.clone(),
                receiver_id: queue_entry.account_id.clone(),
                receipt_id: new_receipt_id,
                receipt: ReceiptEnum::PromiseResume(DataReceipt {
                    data_id: queue_entry.data_id,
                    data: None,
                }),
            });

            // Record a ReceiptToTx entry for the new resume receipt. The parent is the
            // yield receipt that is being timed out.
            if processing_state.apply_state.save_receipt_to_tx {
                let yield_receipt: Receipt = get_pure(state_update, &promise_yield_key)?
                    .expect("promise yield receipt should exist since contains_key was true");
                processing_state.receipt_to_tx.push((
                    new_receipt_id,
                    ReceiptToTxInfo::V1(ReceiptToTxInfoV1 {
                        origin: ReceiptOrigin::FromReceipt(ReceiptOriginReceipt {
                            parent_receipt_id: *yield_receipt.receipt_id(),
                            parent_predecessor_id: yield_receipt.predecessor_id().clone(),
                        }),
                        receiver_account_id: queue_entry.account_id.clone(),
                        shard_id: processing_state.apply_state.shard_id,
                    }),
                ));
            }

            // The receipt is destined for the local shard and will be placed in the outgoing
            // receipts buffer. It is possible that there is already an outgoing receipt resolving
            // this yield if `yield_resume` was invoked by some receipt which was processed in
            // the current chunk. The ordering will be maintained because the receipts are
            // destined for the same shard; the timeout will be processed second and discarded.
            receipt_sink.forward_or_buffer_receipt(
                resume_receipt,
                apply_state,
                &mut state_update,
            )?;
