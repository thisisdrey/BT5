Audit Report

## Title
`claim_rewards_to` permanently clears Snowbridge relayer rewards on local XCM delivery success, without confirming remote `DepositAsset` settlement on AssetHub - (File: bridges/snowbridge/primitives/core/src/reward.rs)

## Summary
`pallet_bridge_relayers::do_claim_rewards` removes the caller's reward from `RelayerRewards` and emits `RewardPaid` as soon as `T::PaymentProcedure::pay_reward` returns `Ok`, but for `BridgeReward::Snowbridge` that `Ok` only means the `DepositAsset` XCM was accepted into BridgeHub's outbound queue toward AssetHub via `XcmSender::deliver`, not that the remote deposit actually succeeded. Because the relayer supplies the destination `Location` beneficiary directly through the unprivileged `claim_rewards_to` extrinsic and no validation is performed against AssetHub's account-derivation rules, an incorrectly-encoded `Location` causes BridgeHub to irreversibly settle (clear storage + emit `RewardPaid`) while the actual remote deposit is lost or unclaimed on AssetHub.

## Finding Description
`do_claim_rewards` takes the reward balance out of storage via `try_mutate_exists`, calls `PaymentProcedure::pay_reward`, and on `Ok` immediately deposits `RewardPaid` with no rollback path and no further confirmation step: [1](#0-0) 

`claim_rewards_to` is a public, unprivileged, signed extrinsic that forwards an arbitrary caller-supplied `BeneficiaryOf<T, I>` straight into `do_claim_rewards`: [2](#0-1) 

For Snowbridge rewards, this beneficiary flows through `BridgeRewardPayer::pay_reward`, which only checks the `VersionedLocation` decodes to a `Location` — it performs no check that the location resolves to an account the relayer controls via AssetHub's signed-origin converter: [3](#0-2) 

`PayAccountOnLocation::pay_reward` then builds a fire-and-forget `UnpaidExecution`/`DepositAsset` XCM using that unvalidated `beneficiary`, and returns `Ok(())` as soon as `XcmSender::deliver` succeeds — i.e., once the message is merely accepted for delivery, with no on-chain confirmation of the remote `DepositAsset` outcome: [4](#0-3) 

This violates the settlement invariant that payout state must only advance after execution/settlement actually succeeds — here `RelayerRewards` is cleared and `RewardPaid` is emitted based solely on local queue-acceptance, not on remote-side deposit success. The existing test suite acknowledges the malformed-beneficiary case only fails locally when there is no HRMP channel configured in the mock environment; it does not demonstrate any validation against AssetHub's actual account-resolution semantics: [5](#0-4) 

The integration test `claim_rewards_works` confirms the intended good path (a correctly-encoded `AccountId32 { network: None }` junction resolves and deposits on AssetHub), but there is no corresponding mechanism preventing an incorrectly-encoded beneficiary from being accepted and settled on BridgeHub while failing/trapping on AssetHub: [6](#0-5) 

## Impact Explanation
This is a permanent, unbacked loss of relayer reward funds with no recovery path once `RelayerRewards` is cleared and `RewardPaid` is emitted, matching the "permanent user-fund or bridge-state lock" category and the settlement-atomicity pivot ("payout state must only advance after ... settlement succeed atomically"). It is reachable purely through the public, unprivileged `claim_rewards_to` extrinsic with a self-supplied malformed `Location`, requiring no malicious peer, validator, or privileged access.

## Likelihood Explanation
The likelihood is non-trivial in practice: constructing a correct `VersionedLocation` beneficiary requires exact `NetworkId`/junction encoding matching what AssetHub's signed-origin converter recognizes. There is no on-chain guard validating this before BridgeHub commits the settlement, so any relayer/tooling that gets this encoding wrong loses their reward irreversibly, and the bug is deterministically repeatable for any malformed input.

## Recommendation
Do not clear `RelayerRewards` (or emit `RewardPaid`) until remote settlement on AssetHub is confirmed, e.g., via an XCM query/callback pattern, or validate that `Location` decodes to a well-formed `AccountId32`/`AccountKey20` junction matching AssetHub's expected signed-origin encoding before accepting it in `claim_rewards_to`/`PayAccountOnLocation::pay_reward`.

## Proof of Concept
1. Relayer accrues a `BridgeReward::Snowbridge` reward via `register_reward` on BridgeHub, as shown in `claim_rewards_works`.
2. Relayer calls `claim_rewards_to(BridgeReward::Snowbridge, BridgeRewardBeneficiaries::AssetHubLocation(location))` with a `Location` whose `AccountId32.network`/junction structure does not match what AssetHub's signed-origin converter would derive for an account the relayer controls.
3. `PayAccountOnLocation::pay_reward` builds and delivers the `DepositAsset` XCM to AssetHub; `XcmSender::deliver` succeeds, so `do_claim_rewards` clears `RelayerRewards` and emits `RewardPaid` on BridgeHub.
4. On AssetHub, `DepositAsset` executes against a location the relayer cannot present a matching signed origin for, or traps the assets.
5. The relayer's reward is permanently gone: `RelayerRewards` cannot be restored on BridgeHub, and the deposited/trapped value on AssetHub is unreachable by the relayer.

		fn do_claim_rewards(
			relayer: T::AccountId,
			reward_kind: T::Reward,
			beneficiary: BeneficiaryOf<T, I>,
		) -> DispatchResult {
			RelayerRewards::<T, I>::try_mutate_exists(
				&relayer,
				reward_kind,
				|maybe_reward| -> DispatchResult {
					let reward_balance =
						maybe_reward.take().ok_or(Error::<T, I>::NoRewardForRelayer)?;
					T::PaymentProcedure::pay_reward(
						&relayer,
						reward_kind,
						reward_balance,
						beneficiary.clone(),
					)
					.map_err(|e| {
						tracing::error!(
							target: LOG_TARGET,
							error=?e,
							?relayer,
							?reward_kind,
							?reward_balance,
							?beneficiary,
							"Failed to pay rewards"
						);
						Error::<T, I>::FailedToPayReward
					})?;

					Self::deposit_event(Event::<T, I>::RewardPaid {
						relayer: relayer.clone(),
						reward_kind,
						reward_balance,
						beneficiary,
					});
					Ok(())
				},
			)

	fn pay_reward(
		relayer: &Relayer,
		_: (),
		reward: RewardBalance,
		beneficiary: Self::Beneficiary,
	) -> Result<(), Self::Error> {
		let ethereum_location = Location::new(2, [GlobalConsensus(EthereumNetwork::get())]);
		let assets: Asset = (ethereum_location.clone(), reward.into()).into();

		let xcm: Xcm<()> = alloc::vec![
			UnpaidExecution { weight_limit: Unlimited, check_origin: None },
			DescendOrigin(InboundQueueLocation::get().into()),
			UniversalOrigin(GlobalConsensus(EthereumNetwork::get())),
			ReserveAssetDeposited(assets.into()),
			DepositAsset { assets: AllCounted(1).into(), beneficiary },
		]
		.into();

		let (ticket, fee) =
			validate_send::<XcmSender>(AssetHubLocation::get(), xcm).map_err(|_| XcmSendFailure)?;
		XcmExecutor::charge_fees(relayer.clone(), fee).map_err(|_| ChargeFeesFailure)?;
		XcmSender::deliver(ticket).map_err(|_| XcmSendFailure)?;

		Ok(())
	}

#[test]
fn claim_rewards_works() {
	let assethub_location = BridgeHubWestend::sibling_location_of(AssetHubWestend::para_id());
	let assethub_sovereign = BridgeHubWestend::sovereign_account_id_of(assethub_location);

	let relayer_account = BridgeHubWestendSender::get();
	let reward_address = AssetHubWestendReceiver::get();

	BridgeHubWestend::fund_accounts(vec![
		(assethub_sovereign.clone(), INITIAL_FUND),
		(relayer_account.clone(), INITIAL_FUND),
	]);
	set_up_eth_and_dot_pool();

	BridgeHubWestend::execute_with(|| {
		type RuntimeEvent = <BridgeHubWestend as Chain>::RuntimeEvent;
		type RuntimeOrigin = <BridgeHubWestend as Chain>::RuntimeOrigin;
		let reward_amount = ETHER_MIN_BALANCE * 2; // Reward should be more than Ether min balance

		type BridgeRelayers = <BridgeHubWestend as BridgeHubWestendPallet>::BridgeRelayers;
		BridgeRelayers::register_reward(
			(&relayer_account.clone()).into(),
			BridgeReward::Snowbridge,
			reward_amount,
		);

		// Check that the reward was registered.
		assert_expected_events!(
			BridgeHubWestend,
			vec![
				RuntimeEvent::BridgeRelayers(pallet_bridge_relayers::Event::RewardRegistered { relayer, reward_kind, reward_balance }) => {
					relayer: *relayer == relayer_account,
					reward_kind: *reward_kind == BridgeReward::Snowbridge,
					reward_balance: *reward_balance == reward_amount,
				},
			]
		);

		let relayer_location = Location::new(
			0,
			[Junction::AccountId32 { id: reward_address.clone().into(), network: None }],
		);
		let reward_beneficiary =
			BridgeRewardBeneficiaries::AssetHubLocation(VersionedLocation::V5(relayer_location));
		let result = BridgeRelayers::claim_rewards_to(
			RuntimeOrigin::signed(relayer_account.clone()),
			BridgeReward::Snowbridge,
			reward_beneficiary.clone(),
		);
		assert_ok!(result);

		assert_expected_events!(
			BridgeHubWestend,
			vec![
				// Check that the pay reward event was emitted on BH
				RuntimeEvent::BridgeRelayers(pallet_bridge_relayers::Event::RewardPaid { relayer, reward_kind, reward_balance, beneficiary }) => {
					relayer: *relayer == relayer_account,
					reward_kind: *reward_kind == BridgeReward::Snowbridge,
					reward_balance: *reward_balance == reward_amount,
					beneficiary: *beneficiary == reward_beneficiary,
				},
			]
		);
	});

	AssetHubWestend::execute_with(|| {
		type RuntimeEvent = <AssetHubWestend as Chain>::RuntimeEvent;
		assert_expected_events!(
			AssetHubWestend,
			vec![
				// Check that the reward was paid on AH
				RuntimeEvent::ForeignAssets(pallet_assets::Event::Deposited { asset_id, who: owner, .. }) => {
					asset_id: *asset_id == eth_location(),
					owner: *owner == reward_address.clone().into(),
				},
			]
		);
	})
}
