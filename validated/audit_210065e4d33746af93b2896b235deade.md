The CVE describes a heap-based buffer overflow in FFmpeg's C `filter_frame` function for the bitplane noise video filter, caused by missing bounds validation on frame dimensions/strides in native C code. The closest analog in this repository is the Go standard library's PNG filter/decoder pipeline (`src/image/png/reader.go`, `src/image/png/paeth.go`, `src/image/png/writer.go`), which applies per-row filters (`ftUp`, `ftSub`, `ftAverage`, `ftPaeth`) to pixel byte slices.

Unlike the FFmpeg C code, Go's implementation is memory-safe by construction and explicitly guards against the failure mode this CVE hinges on:

- `parseIHDR` rejects non-positive dimensions and checks for `nPixels64` / 8-bytes-per-pixel overflow before any allocation. [1](#0-0) 
- `readImagePass` computes `rowSize` via `int64` arithmetic and explicitly rejects overflow before allocating `cr`/`pr`, so the filter loops (`ftSub`, `ftUp`, `ftAverage`, `ftPaeth` → `filterPaeth`) always operate within correctly sized, Go-bounds-checked slices. [2](#0-1) [3](#0-2) 
- `filterPaeth` itself only indexes within `len(cdat)`/`len(pdat)`, which the Go runtime bounds-checks regardless. [4](#0-3) 
- The encoder side (`writeImage`/`filter`) similarly sizes `cr`/`pr` buffers from validated bounds before running the same class of filter arithmetic. [5](#0-4) 

There is regression test coverage (`TestDimensionOverflow`) specifically for the dimension/overflow classes that would be needed to trigger an analogous out-of-bounds write, confirming this is already a defended, previously-audited path rather than a live, reachable vulnerability. [6](#0-5) 

Since even attacker-controlled, malformed PNG dimensions/strides cannot produce an out-of-bounds heap write in this Go path (Go's runtime bounds-checks slice access and the decoder pre-validates dimension arithmetic before allocation), there is no reachable analog to the FFmpeg heap buffer overflow in this codebase's production paths.

func filterPaeth(cdat, pdat []byte, bytesPerPixel int) {
	var a, b, c, pa, pb, pc int
	for i := 0; i < bytesPerPixel; i++ {
		a, c = 0, 0
		for j := i; j < len(cdat); j += bytesPerPixel {
			b = int(pdat[j])
			pa = b - c
			pb = a - c
			pc = abs(pa + pb)
			pa = abs(pa)
			pb = abs(pb)
			if pa <= pb && pa <= pc {
				// No-op.
			} else if pb <= pc {
				a = b
			} else {
				a = c
			}
			a += int(cdat[j])
			a &= 0xff
			cdat[j] = uint8(a)
			c = b
		}
	}
}
