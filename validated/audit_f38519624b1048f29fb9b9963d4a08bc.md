### Title
Custom-hooks tar extraction allows unrestricted symlinks, enabling divergent replica vote hashes and quorum/DoS - (File: internal/gitaly/repoutil/custom_hooks.go)

### Summary
`SetCustomHooks` extracts the attacker-supplied hooks tarball with the external `tar -xf` binary in `ExtractHooks`, with no post-extraction validation of symlink targets (unlike `extractTarToDirectory` in `internal/gitaly/service/repository/replicate.go`, which explicitly rejects absolute and directory-escaping symlinks). `newDirectoryVote` then walks the extracted tree and calls `os.Open` on every non-directory `DirEntry`, including symlinks, which transparently follows the link to wherever it resolves on the local filesystem. Because vote hashes are computed independently per Gitaly node from locally resolved file content, a symlink whose target differs (or exists/doesn't exist) per-node produces divergent per-replica vote hashes from byte-identical tar input.

### Finding Description
`ExtractHooks` (`internal/gitaly/repoutil/custom_hooks.go:55-95`) shells out to `tar -xf - -C path --strip-components 0 custom_hooks` with no `--no-same-owner`, no post-extraction symlink checks, and no rejection of `tar.TypeSymlink` entries — contrasted with the hardened, hand-rolled tar extractor in `extractTarToDirectory` (`internal/gitaly/service/repository/replicate.go:314-406`), which validates that symlink targets are relative and stay within `targetDir`. A crafted tar can therefore place an arbitrary symlink (e.g. `custom_hooks/hook -> /etc/hostname`, a per-node file, or a dangling target) into `tempHooksPath`.

`newDirectoryVote` (`internal/gitaly/repoutil/custom_hooks.go:257-304`) walks that path with `filepath.WalkDir`. The `entry.IsDir()` check at line 283 is based on the raw directory-entry type (symlinks are never reported as directories by `WalkDir`, regardless of what they point to), so a symlink entry always falls through to `os.Open(path)` at line 287, which follows the link and reads whatever it resolves to on that node's local disk. Since `SetCustomHooks` is invoked independently and per-node on each Gitaly replica behind Praefect (the same tar bytes replicated to each backend), the resolved target's presence/content can legitimately differ across machines (host-specific files, differing local state, dangling links present/absent due to timing, etc.), producing different vote hashes at the `Prepared`/`Committed` phases (`voteCustomHooks`, lines 195 and 240) even though the RPC input was identical.

Existing hardening for path traversal into the tar target directory does exist elsewhere in the codebase (`replicate.go`), confirming this is a real gap specific to `custom_hooks.go`'s use of the external `tar` binary without equivalent link validation.

### Impact Explanation
This is a denial-of-service class issue against the transactional voting layer: a Praefect-fronted `SetCustomHooks` call can be made to produce inconsistent per-node votes purely from repository-owner-controlled tar content, without any privileged access. Divergent votes cause the transaction to fail to reach quorum, stalling the `SetCustomHooks` RPC / reference update flow for that repository. This matches the "DoS of an RPC handler" impact class called out in the rules, scoped to voting/transaction integrity rather than data corruption (since a failed vote aborts rather than partially commits) — but it can be leveraged repeatedly by an attacker to reliably disrupt hook updates for their own repository, and by extension it demonstrates a real correctness gap in vote hashing (walking through symlinks) that undermines the "vote reflects committed file content" invariant.

### Likelihood Explanation
Preconditions are minimal and match the allowed threat model: an unprivileged repository owner can call `SetCustomHooks` (via GitLab Rails / RPC) against their own repository on a Praefect-fronted, multi-node Gitaly cluster, supplying an arbitrary tar as the hooks payload. No admin privileges, secrets, or peer compromise are required. Constructing a tar with a `TypeSymlink` entry under `custom_hooks/` is trivial with the standard `archive/tar` package or GNU `tar --hard-dereference`-free defaults. The exploit is fully repeatable, since the attacker fully controls the tar bytes sent to every replica.

### Recommendation
In `ExtractHooks`/`SetCustomHooks`, either switch extraction to a hardened Go-based tar extractor that rejects (or resolves-and-validates) symlink entries the way `extractTarToDirectory` already does in `replicate.go`, or add an explicit post-extraction walk that uses `os.Lstat`/`fs.DirEntry.Type()&fs.ModeSymlink` to reject any symlink under `tempHooksPath` before voting. In `newDirectoryVote`, use `os.Lstat`/`d.Type()` to detect symlinks explicitly and either reject them outright or hash the raw link target string (via `os.Readlink`) instead of calling `os.Open`, so the vote never depends on resolving arbitrary filesystem state outside the extracted tree.

func ExtractHooks(ctx context.Context, logger log.Logger, reader io.Reader, path string, stripPrefix bool) error {
	// GNU tar does not accept an empty file as a valid tar archive and produces
	// an error. Since an empty hooks tar is symbolic of a repository having no
	// hooks, the reader is peeked to check if there is any data present.
	buf := bufio.NewReader(reader)
	if _, err := buf.Peek(1); errors.Is(err, io.EOF) {
		return nil
	}

	stripComponents := "0"
	if stripPrefix {
		stripComponents = "1"
	}

	cmdArgs := []string{"-xf", "-", "-C", path, "--strip-components", stripComponents, CustomHooksDir}

	var stderrBuilder strings.Builder
	cmd, err := command.New(ctx, logger, append([]string{"tar"}, cmdArgs...),
		command.WithStdin(buf),
		command.WithStderr(&stderrBuilder))
	if err != nil {
		return fmt.Errorf("executing tar command: %w", err)
	}

	if err := cmd.Wait(); err != nil {
		stderr := stderrBuilder.String()

		// GNU and BSD tar versions have differing errors when attempting to
		// extract specified members from a valid tar archive. If the tar
		// archive is valid the errors for GNU and BSD tar should have the
		// same prefix, which can be checked to validate whether the expected
		// content is present in the archive for extraction.
		if strings.HasPrefix(stderr, "tar: custom_hooks: Not found in archive") {
			return nil
		}

		return structerr.New("waiting for tar command completion: %w", err).WithMetadata("stderr", stderr)
	}

	return nil
}

func newDirectoryVote(basePath string) (*voting.VoteHash, error) {
	voteHash := voting.NewVoteHash()

	if err := filepath.WalkDir(basePath, func(path string, entry fs.DirEntry, err error) error {
		if err != nil {
			return err
		}

		relPath, err := filepath.Rel(basePath, path)
		if err != nil {
			return fmt.Errorf("getting relative path: %w", err)
		}

		// Write file relative path to hash.
		_, _ = voteHash.Write([]byte(relPath))

		info, err := entry.Info()
		if err != nil {
			return fmt.Errorf("getting file info: %w", err)
		}

		// Write file permissions to hash.
		permBytes := make([]byte, 4)
		binary.BigEndian.PutUint32(permBytes, uint32(info.Mode()))
		_, _ = voteHash.Write(permBytes)

		if entry.IsDir() {
			return nil
		}

		file, err := os.Open(path)
		if err != nil {
			return fmt.Errorf("opening file: %w", err)
		}
		defer file.Close()

		// Copy file data to hash.
		if _, err = io.Copy(voteHash, file); err != nil {
			return fmt.Errorf("copying file to hash: %w", err)
		}

		return nil
	}); err != nil {
		return nil, fmt.Errorf("walking directory: %w", err)
	}

	return &voteHash, nil
}
