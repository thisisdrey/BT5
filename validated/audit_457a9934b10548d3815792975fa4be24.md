### Title
Token Object Address Collision via Unseparated `::` Delimiter in `create_token_seed` - (File: `aptos-move/framework/aptos-token-objects/sources/token.move`)

### Summary

`create_token_seed` constructs a named-object seed by concatenating `collection_name || "::" || token_name`. Because neither collection names nor token names are restricted from containing the literal string `::`, two distinct `(collection, name)` pairs can produce an identical byte sequence, mapping to the same on-chain object address. This is the direct Aptos analog of the aragonOne/Fundraising `apmNamehash` collision: two logically distinct identifiers share the same derived key.

### Finding Description

`create_token_seed` is defined as:

```move
public fun create_token_seed(collection: &String, name: &String): vector<u8> {
    assert!(name.length() <= MAX_TOKEN_NAME_LENGTH, error::out_of_range(ETOKEN_NAME_TOO_LONG));
    let seed = *collection.bytes();
    seed.append(b"::");
    seed.append(*name.bytes());
    seed
}
``` [1](#0-0) 

The only validation is a length check on `name`; no character-set restriction prevents `::` from appearing in either argument. The resulting seed is passed directly to `object::create_object_address`:

```move
public fun create_token_address(creator: &address, collection: &String, name: &String): address {
    object::create_object_address(creator, create_token_seed(collection, name))
}
``` [2](#0-1) 

Concrete collision example (same creator address):

| collection | name | seed bytes |
|---|---|---|
| `"A::B"` | `"C"` | `A::B::C` |
| `"A"` | `"B::C"` | `A::B::C` |

Both produce `sha3_256(creator_bcs || "A::B::C" || 0xFE)` — the identical object address.

The same flaw propagates into `create_token_name_with_seed`, which appends a third user-controlled string to the already-ambiguous seed:

```move
public fun create_token_name_with_seed(collection: &String, name: &String, seed: &String): vector<u8> {
    assert!(seed.length() <= MAX_TOKEN_SEED_LENGTH, error::out_of_range(ESEED_TOO_LONG));
    let seeds = create_token_seed(collection, name);
    seeds.append(*seed.bytes());
    seeds
}
``` [3](#0-2) 

Collection names are validated only for length (128 bytes), with no character restrictions: [4](#0-3) 

### Impact Explanation

When a creator has already minted token `("A::B", "C")`, the object at address `sha3_256(creator || "A::B::C" || 0xFE)` already exists. Any subsequent call to `create_named_token(creator, "A", ..., "B::C", ...)` will abort with `OBJECT_EXISTS` (error `0x80001`), permanently preventing that token from ever being created at its canonical address. Because `create_token_address` is a `public` view function used by off-chain indexers and dApps to pre-compute token addresses, the collision also causes address-lookup confusion: two distinct `(collection, name)` identities resolve to the same on-chain object, mirroring the original `apmNamehash` collision where a single registry entry could not simultaneously represent both contracts.

For protocols that build fungible assets on top of named tokens (as in `managed_fungible_token.move`, which derives the `Metadata` object address via `create_token_seed`), a collision permanently blocks the expected fungible-asset metadata address from being created, freezing the fungible asset's on-chain lifecycle. [5](#0-4) 

### Likelihood Explanation

Any creator who uses `::` in a collection name or token name — which is permitted by the framework — can trigger this collision inadvertently. The `::` character is a natural choice for namespacing (e.g., `"MyProject::Series1"`). The collision is deterministic and permanent once the first token is minted.

### Recommendation

Apply domain separation by length-prefixing each component before concatenation, or by restricting `::` from appearing in collection and token names. For example:

```move
public fun create_token_seed(collection: &String, name: &String): vector<u8> {
    assert!(name.length() <= MAX_TOKEN_NAME_LENGTH, error::out_of_range(ETOKEN_NAME_TOO_LONG));
    // Length-prefix each component to prevent cross-component collisions
    let seed = bcs::to_bytes(&collection.length());
    seed.append(*collection.bytes());
    seed.append(bcs::to_bytes(&name.length()));
    seed.append(*name.bytes());
    seed
}
```

Alternatively, validate that neither `collection` nor `name` contains the byte sequence `::` before constructing the seed.

### Proof of Concept

```move
// Both calls produce the same token address for the same creator.
let addr1 = token::create_token_address(
    &@creator,
    &string::utf8(b"A::B"),   // collection name contains "::"
    &string::utf8(b"C"),
);
let addr2 = token::create_token_address(
    &@creator,
    &string::utf8(b"A"),
    &string::utf8(b"B::C"),   // token name contains "::"
);
assert!(addr1 == addr2, 0);   // passes — identical addresses

// Creating the first token succeeds:
token::create_named_token(creator, utf8(b"A::B"), ..., utf8(b"C"), ...);

// Creating the second token permanently fails with OBJECT_EXISTS (0x80001):
token::create_named_token(creator, utf8(b"A"), ..., utf8(b"B::C"), ...);
// abort 0x80001 at aptos_framework::object
