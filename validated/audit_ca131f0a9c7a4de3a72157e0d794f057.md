### Title
Frequent public `accrue()` calls cause per-call interest deltas to round `reserve-inc`/`treasury-lp` to zero, permanently denying the DAO treasury its protocol fee - (File: `mainnet/contracts/vault/v0-vault-usdc.clar` and identical logic in `v0-vault-stx.clar`, `v0-vault-sbtc.clar`, `v0-vault-ststx.clar`, `v0-vault-ststxbtc.clar`, `v0-vault-usdh.clar`)

### Summary
The external report describes a case where a caller can supply a token amount that is technically above a minimum threshold, but small enough that a downstream reward-distribution formula (`(_amountToken * precisionDelta * 1e18) / gnsBalance`) rounds to zero, silently discarding rewards that should have gone to stakers. The Zest vault `accrue()` function contains the same rounding-to-zero pattern with no minimum threshold at all: any caller who invokes the public `accrue()` function frequently (once per block) keeps each interest increment small enough that the treasury's reserve-factor cut (`reserve-inc`, and the derived `treasury-lp` mint) rounds down to zero on every call, permanently denying the DAO treasury its protocol fee while suppliers still receive their full yield via the `lindex` update.

### Finding Description
In every vault's `accrue()` function, the protocol reserve fee is computed and minted as follows: [1](#0-0) 

Specifically:
- `debt-delta` is the newly accrued interest on debt since `last-update`, computed from the change in `idx`/`next` applied to `scaled-principal`.
- `reserve-inc` is `debt-delta * fee-reserve / BPS` — the protocol's cut of that interest.
- `treasury-lp` converts `reserve-inc` into vault shares minted to `.dao-treasury`, using integer division (`mul-div-down`).

`accrue()` is a public function with no permission gate (`try! (check-caller-auth)` is only required for `system-borrow`/`system-repay`, not for `accrue`), and it is also invoked automatically by every `deposit`/`redeem`/`system-borrow` call. Any principal can call `accrue()` directly, as often as once per Stacks block. Because `next-index()` only advances based on elapsed time since `last-update` [2](#0-1) , calling `accrue()` every block minimizes the `time-delta` used in each computation, which minimizes `debt-delta`, which in turn minimizes `reserve-inc`. When `fee-reserve` is a modest percentage (e.g., 10%, BPS-scaled) and `debt-delta` for a single short block interval is small relative to `BPS`, `mul-div-down(debt-delta, fee-reserve, BPS)` rounds down to `u0` on that call. Since `treasury-lp` is only minted `(if (> reserve-inc u0) ... u0)`, no treasury shares are minted for that period even though real interest genuinely accrued (and is fully captured by `index`/`lindex` for borrowers/suppliers). Because `last-update` is advanced to the current block regardless [3](#0-2) , that specific slice of interest can never be recovered by a subsequent larger-interval `accrue()` call — the increment is permanently lost to the treasury.

This mirrors the external report's root cause exactly: a threshold-free (or too-low-threshold) rounding division in a reward/fee-distribution formula that a caller can repeatedly trigger with small enough deltas to zero out the intended recipient's share, while the rest of the accounting (borrower debt, supplier yield) proceeds normally.

### Impact Explanation
This does not threaten user principal or borrower/supplier accounting (those are tracked via `index`/`lindex`, which still update correctly). It results in permanent, unrecoverable loss of the DAO treasury's reserve-factor fee income — a protocol-level unclaimed-yield stream — because each accrue interval's rounded-to-zero reserve amount is discarded rather than deferred or accumulated. Repeated automated calling (trivial to script, e.g., once every block by a bot) can suppress essentially all treasury fee accrual over the vault's lifetime. This lands in the in-scope High-impact category: "permanent freezing" (more precisely, permanent loss) "of unclaimed yield" belonging to the DAO treasury.

### Likelihood Explanation
`accrue()` is a fully public, unauthenticated function with no fee or rate-limit for calling it, and any principal (or their own deployed contract) can call it as fast as once per Stacks block indefinitely at negligible cost. The rounding condition (`reserve-inc` computed from a single block's worth of interest rounding to `u0`) is realistic for vaults with modest utilization/rates or lower-decimal underlying assets, especially early after deployment or during low-activity periods. No privileged access or DAO compromise is required.

### Recommendation
Accumulate the fractional/rounded-down remainder of `reserve-inc` (or `debt-delta`) across calls instead of discarding it when `treasury-lp` rounds to zero, e.g., maintain a `pending-reserve` accumulator that carries over unminted reserve amounts to the next `accrue()` call, or defer minting to be based on cumulative debt-delta since the last successful treasury mint rather than per-call deltas.

### Proof of Concept
1. Deploy/observe a vault (e.g., `v0-vault-usdc`) with `fee-reserve` set to a typical value (e.g., 1000 = 10% in BPS) and normal utilization/interest rate.
2. From any account, call `accrue()` once per Stacks block (script a bot to do so) instead of allowing it to be called at longer, natural intervals.
3. Each call computes `debt-delta` for only ~1 block's worth of interest; verify via `get-index`/print events that `reserve-inc` and hence `treasury-lp` are `u0` on each call (no `ft-mint? zft treasury-lp .dao-treasury` invoked), while `index`/`lindex` still advance normally.
4. Compare against a control scenario where `accrue()` is called only occasionally (e.g., once per day): observe non-zero `treasury-lp` mints accumulating to `.dao-treasury`.
5. Confirm that in the frequent-calling scenario, `.dao-treasury`'s zft balance never grows despite real interest accruing to `index`, demonstrating permanent loss of the treasury's fee share.

(define-public (accrue)
  (let ((states (var-get pause-states))
        (idx (var-get index))
        (lidx (var-get lindex)))
      (if (get accrue states)
          ;; PAUSED: Pass-through without reverting
          (ok { index: idx, lindex: lidx })
          ;; NOT PAUSED: Normal accrual logic
          (let ((next (next-index))
                (nliq (next-liquidity-index))
                (scaled-principal (var-get principal-scaled))
                (old-debt (mul-div-down scaled-principal idx INDEX-PRECISION))
                (new-debt (mul-div-down scaled-principal next INDEX-PRECISION))
                (debt-delta (if (> new-debt old-debt) (- new-debt old-debt) u0))
                (reserve-inc (mul-div-down debt-delta (var-get fee-reserve) BPS))
                (treasury-lp (if (> reserve-inc u0) (mul-div-down reserve-inc (total-supply) (- (total-assets-preview) reserve-inc)) u0)))
            (if (not (is-eq idx next))
                (var-set index next)
                false)
            (if (not (is-eq lidx nliq))
                (var-set lindex nliq)
                false)
            (if (> treasury-lp u0)
                (try! (ft-mint? zft treasury-lp .dao-treasury))
                false)
            (if (or (not (is-eq idx next)) (not (is-eq lidx nliq)))
                (var-set last-update stacks-block-time)
                false)
            (ok { index: next, lindex: nliq })))))
