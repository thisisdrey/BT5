### Title
Missing bulk complexity metering for `VariantFieldInstantiation` (and `StructVariantInstantiation`) tables allows complexity-check bypass, enabling unbounded bytecode-verifier work during module publish — (`third_party/move/move-binary-format/src/check_complexity.rs`)

### Summary
`check_module_complexity` bulk-meters `FunctionInstantiation`, `StructDefInstantiation`, and `FieldInstantiation` tables unconditionally, but has no equivalent bulk pass for the `VariantFieldInstantiation` or `StructVariantInstantiation` tables introduced with the enum/variant feature. Those entries are only metered when referenced by bytecode instructions. The bytecode verifier, however, processes every entry in both tables unconditionally. An attacker can publish a module whose `VariantFieldInstantiation` table is padded with up to 65535 entries (all unreferenced by any function body) pointing to a moderately complex signature, pass the complexity gate, and force O(N × T) verifier work — where N ≤ 65535 and T is the number of type nodes in the referenced signature.

### Finding Description
In `check_module_complexity` the call sequence is:

```
meter.meter_signatures()              // charges each unique signature once
meter.meter_function_instantiations() // multiplier for FunctionInstantiation
meter.meter_struct_def_instantiations()// multiplier for StructDefInstantiation
meter.meter_field_instantiations()    // multiplier for FieldInstantiation
// ← NO meter_variant_field_instantiations()
// ← NO meter_struct_variant_instantiations()
meter.meter_function_defs()           // only reaches variant entries via bytecode
```

`meter_variant_field_instantiation` (singular) exists and is correct, but it is only invoked from `meter_code` when a `ImmBorrowVariantFieldGeneric`/`MutBorrowVariantFieldGeneric` instruction is encountered. A table entry that is never referenced by any instruction is never charged.

The bytecode verifier (`verify_module_impl` in `signature_v2.rs`) calls `verify_variant_field_instantiations_contextless()` unconditionally, which iterates every entry. The per-entry function `verify_variant_field_instantiation_contextless` caches by `VariantFieldInstantiationIndex`; 65535 distinct entries all pointing to the same signature are 65535 distinct cache keys, so `verify_struct_type_params` is invoked 65535 times. The inner `ty_results` cache reduces per-type cost to O(1) after the first entry, but the outer loop still runs T iterations per entry, giving total verifier work O(N × T).

### Impact Explanation
An unprivileged account submits a package-publish transaction containing a `CompiledModule` with 65535 `VariantFieldInstantiation` entries, none referenced by any function body, all pointing to a signature with T type nodes. The module passes `check_module_complexity` (only the signature cost T × 8 is charged, which is well within the budget). Every validator that processes the publish transaction then runs the bytecode verifier, performing O(65535 × T) work. With T = 30,000 this is ~2 billion loop iterations per validator per publish. Repeated submissions (each publish is a separate transaction) can sustain the load. The impact is material validator slowdown during module publish, degrading block processing throughput.

### Likelihood Explanation
The entrypoint is a standard, permissionless package-publish transaction. No privileged keys, governance, or validator access are required. The binary can be crafted programmatically. The only cost to the attacker is gas for the publish transaction; the complexity check does not reject the module, so gas is consumed normally.

### Recommendation
Add a bulk metering pass for both missing tables in `check_module_complexity`, mirroring the existing `meter_field_instantiations` pattern:

```rust
// after meter_field_instantiations():
meter.meter_variant_field_instantiations()?;
meter.meter_struct_variant_instantiations()?;
```

Implement `meter_variant_field_instantiations` to iterate `self.resolver.variant_field_instantiations()` and call `self.meter_variant_field_instantiation(idx)` for each entry, and similarly for `meter_struct_variant_instantiations`. This restores the invariant that every complexity-contributing binary structure is charged against the budget regardless of bytecode references.
