Unauthenticated event-injection into `SignerEventReceiver`'s HTTP listener bypasses the Stacks node entirely - (File: `libsigner/src/events.rs`)

### Summary
`SignerEventReceiver::next_event()` binds a plain HTTP server (`tiny_http`) that the `stacks-node` is expected to `POST` events to (`/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block`), which are then fed straight into the signer's runloop channel. The handler performs zero authentication or origin verification on these requests — it only checks the HTTP verb (`POST`) and URL path before deserializing and forwarding the body as a trusted event.

Compare this to the request-parsing helper `decode_http_request` in the same crate, which decodes headers but is never used here to check for any shared secret / `Authorization` header: [2](#0-1) 

`process_event` simply reads the body and deserializes it into the expected type without validating provenance: [3](#0-2) 

The documented deployment model relies on a shared secret (`auth_password` / `[connection_options] auth_token`) — but that secret is only checked by the **node's** block-proposal RPC endpoint (`postblock_proposal.rs`) for requests coming *from* the signer. There is no analogous check on the **signer's own listener**, which the operator is told to bind on `0.0.0.0` in the sample configs: [4](#0-3) [5](#0-4) 

This breaks the intended equality "event received on this socket originated from the trusted, co-located stacks-node" vs. "event received from any remote unauthenticated client." Any host that can reach the configured `endpoint:port` can craft a raw HTTP POST to `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, or `/new_block` and have it processed identically to a genuine node-originated event — including `StackerDBChunksEvent` payloads whose individual chunk signatures are validated by the *node* before it normally emits this event (see `poststackerdbchunk.rs` / `libstackerdb.rs` verification path), but that validation is entirely skipped when the attacker talks to the signer's listener directly instead of going through the node.

This is the direct analog of the Jenkins CSRF class of bug: a state-changing endpoint that accepts unauthenticated/unverified requests and performs a privileged action (here, injecting data into a security-critical signer decision pipeline) as if it came from a trusted actor.

### Impact Explanation
An unauthenticated remote attacker who can reach the signer's bound event port can inject forged `StackerDBChunksEvent`, `BlockValidateResponse`, `BurnBlockEvent`, or `StacksBlockEvent` messages directly into the signer runloop, bypassing all of the node-side signature/validation checks that normally gate this data (e.g., StackerDB chunk owner-signature verification in `libstackerdb::SlotMetadata::verify`). This is an unauthorized write into signer-internal state via forged data injection — matching the Critical/High impact bar for "unauthenticated/unauthorized write to state" and "network-wide propagation of forged data" once the (out-of-scope) signer decision logic consumes this unverified input.

### Likelihood Explanation
Exploitation requires only network reachability to the event-receiver port — no credentials, no node secret, no privileged role. The sample configs explicitly instruct operators to bind this listener on `0.0.0.0`, increasing real-world exposure, and the handler contains no header/secret check whatsoever to gate access.

### Recommendation
Require the signer's event-receiver endpoint to validate a shared secret (e.g., the same `auth_password`/`auth_token` already used elsewhere) via an `Authorization` header (or equivalent) on every POST in `SignerEventReceiver::next_event`, rejecting any request that lacks a valid credential before deserializing and forwarding the body, in `libsigner/src/events.rs`.

        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {

                    url

fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}
