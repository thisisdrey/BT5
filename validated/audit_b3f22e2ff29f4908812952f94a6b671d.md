### Title
Off-by-one boundary check in `was_recent_validator` lets recently-slashable validators unlock stake one era early via `unbond()` - (File: substrate/frame/staking-async/src/pallet/mod.rs)

### Summary
`Pallet::unbond()` in `pallet-staking-async` decides whether a stash must wait the full `BondingDuration` (recent-validator protection) or the shorter `nominator_bonding_duration` by comparing `active_era.saturating_sub(last_era) < T::BondingDuration::get()`. This strict `<` comparison is the same class of boundary error as the Knox `_getNextFriday()` bug: at the exact boundary (`active_era - last_era == BondingDuration`), the check flips to "not recent" one era earlier than the protection window the code's own documentation describes, letting a former validator claim the shorter unbonding period instead of the intended full `BondingDuration`.

### Finding Description
`LastValidatorEra` tracks the last era in which a stash was included in an era's exposure/snapshot, specifically to force former validators to wait the full `BondingDuration` before withdrawing, "even if they've switched to nominator role", preventing them from "using the shorter nominator unbonding duration to withdraw funds before being slashed": [1](#0-0) 

The `unbond()` extrinsic computes this protection using: [2](#0-1) 

`was_recent_validator` is `true` only while `active_era - last_era < BondingDuration`. The moment `active_era - last_era` reaches exactly `BondingDuration`, the comparison becomes `false` and the account is treated as an ordinary nominator, receiving `nominator_bonding_duration()` (a strictly shorter duration than `BondingDuration`) instead of the full protection window. This is precisely the class of bug described in the report: a boundary subtraction (`friday8am - timestamp < 4 days`) that should include an additional offset (`+8 hours`) but does not, causing the "next" (safe) value to be silently swapped for the "current" (shorter/unsafe) one exactly at the boundary.

Additionally, `LastValidatorEra` can legitimately be `active_era + 1` once the next era's election has been stored but not yet activated (confirmed by the dedicated regression test and PR doc): [3](#0-2) [4](#0-3) 

This shows the `LastValidatorEra` value is deliberately allowed to sit right at these boundary values, making the exact-boundary case (`active_era - last_era == BondingDuration`) a realistic, reachable state rather than a theoretical corner case — an unprivileged staker only needs to time their `unbond()` call for the era in which this equality holds.

### Impact Explanation
The full `BondingDuration` wait is the protocol's slashing-safety margin: it exists so that offences committed while the account was an active validator have time to be reported, deferred (`SlashDeferDuration`), and applied before the stash can withdraw funds and disappear from the slashable pool. By resolving the boundary check one era too early, a former validator can obtain the shorter nominator unbonding schedule and unlock/withdraw stake before the intended protection window elapses, undermining the exact security property the storage item and code comment claim to guarantee (evading slashing consequences on withdrawn funds). This directly matches "theft or unbacked... unlock" and "runtime bug that compromises intended behavior" under the accepted impact classes — the corrupted value is the boolean `was_recent_validator`, which becomes incorrectly `false` one era earlier than the invariant the code documents.

### Likelihood Explanation
No privileged actor, governance action, or malicious peer/validator/relayer is required. Any staker who was a validator and switches to nominating (or simply stops validating) can trigger this by calling the public, unprivileged `unbond()` extrinsic in the exact era where `active_era - LastValidatorEra == BondingDuration`. This is a deterministic, attacker-controlled timing condition based only on public chain state (`ActiveEra`, `LastValidatorEra`), making it straightforward to reach.

### Recommendation
Change the boundary comparison to be inclusive of the full `BondingDuration` window, i.e. use `<=` instead of `<` (or equivalently compare `active_era.saturating_sub(last_era) < T::BondingDuration::get() + 1` / require `active_era >= last_era.saturating_add(T::BondingDuration::get())` before treating the stash as no longer a "recent validator"), mirroring the recommended fix pattern of widening the boundary check rather than narrowing it:

```diff
- let was_recent_validator = LastValidatorEra::<T>::get(&stash)
-     .map(|last_era| active_era.saturating_sub(last_era) < T::BondingDuration::get())
-     .unwrap_or(false);
+ let was_recent_validator = LastValidatorEra::<T>::get(&stash)
+     .map(|last_era| active_era.saturating_sub(last_era) <= T::BondingDuration::get())
+     .unwrap_or(false);
```

### Proof of Concept
1. Account `S` validates and is exposed in era `E` (`LastValidatorEra::<T>::get(S) == Some(E)`, per `substrate/frame/staking-async/src/pallet/impls.rs` exposure-snapshot flow and `tests/try_state.rs` boundary behavior).
2. `S` chills / stops validating, becomes (or stays) a nominator.
3. Chain progresses until `active_era == E + BondingDuration` exactly.
4. `S` calls `Staking::unbond(origin, value)`. In `pallet/mod.rs`, `active_era.saturating_sub(last_era) == BondingDuration`, so `BondingDuration < BondingDuration` is `false`, `was_recent_validator = false`.
5. `unbond_duration` is set to `nominator_bonding_duration()` (shorter than `BondingDuration`), and the unlock chunk's era is `active_era + nominator_bonding_duration` rather than `active_era + BondingDuration`.
6. `S` can call `withdraw_unbonded()` `BondingDuration - nominator_bonding_duration` eras earlier than the protection window intends, one era sooner than the documented "must wait full BondingDuration" guarantee at the precise boundary state confirmed reachable in `tests/try_state.rs`.

#[test]
fn last_validator_era_can_be_one_greater_than_active_era() {
	// When the election for the next era has finished but the era is not yet active,
	// `LastValidatorEra` is set to `active_era + 1`.
	ExtBuilder::default().try_state(false).build_and_execute(|| {
		Session::roll_until_active_era(1);
		let era = active_era();

		// Before election, `LastValidatorEra` equals the active era.
		for (validator, _) in ErasStakersOverview::<T>::iter_prefix(era) {
			assert_eq!(LastValidatorEra::<T>::get(&validator), Some(era));
		}

		// Roll session by session until the election for the next era has been stored, i.e.
		// `ErasStakersOverview` for the next era is populated.
		while ErasStakersOverview::<T>::iter_prefix(era + 1).next().is_none() {
			Session::roll_to_next_session();
		}

		// Election for era 2 is stored but era 2 is not yet active.
		assert_eq!(active_era(), 1);
		assert_eq!(current_era(), 2);

		// After election, `LastValidatorEra` is now 1 greater than active era.
		for (validator, _) in ErasStakersOverview::<T>::iter_prefix(era) {
			assert_eq!(LastValidatorEra::<T>::get(&validator), Some(era + 1));
		}
	});
