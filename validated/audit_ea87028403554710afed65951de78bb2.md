## Title
TVM native-contract unfreeze/withdraw opcodes bypass the committee `UnfreezeDelay` feature-gate enforced by the corresponding actuators - (File: `actuator/src/main/java/org/tron/core/vm/nativecontract/UnfreezeBalanceV2Processor.java` and `actuator/src/main/java/org/tron/core/vm/nativecontract/WithdrawExpireUnfreezeProcessor.java`)

### Summary
In java-tron, the `UnfreezeDelay`/`UnfreezeBalanceV2` feature (the "new staking" unfreeze/withdraw mechanism) is a committee-controlled feature switch, exactly like the `pause()` gate in the Telcoin report. Ordinary transactions go through `UnfreezeBalanceV2Actuator` and `WithdrawExpireUnfreezeActuator`, whose `validate()` methods explicitly refuse to run unless `dynamicStore.supportUnfreezeDelay()` is true: [1](#0-0) [2](#0-1) 

But the same fund-moving logic is also reachable from a smart contract via TVM opcodes (`unfreezeBalanceV2` / `withdrawExpireUnfreeze`, wired through `Program.java`, e.g. `Program.withdrawExpireUnfreeze()`), which delegate to `UnfreezeBalanceV2Processor` and `WithdrawExpireUnfreezeProcessor`. Neither processor's `validate()` checks `supportUnfreezeDelay()`: [3](#0-2) [4](#0-3) [5](#0-4) 

### Finding Description
`supportUnfreezeDelay()` is the on-chain "pause/enable" flag for the whole `UnfreezeBalanceV2`/`WithdrawExpireUnfreeze` fund-movement feature, controlled by committee proposal (`unfreezeDelayDays`), analogous to the `whenNotPaused` guard in the Telcoin `StakingModule`. Both actuator-level `validate()` methods correctly gate the feature behind this flag, refusing execution when the committee has not enabled it. However, the TVM-reachable processors that implement the identical state transitions (moving funds from the frozen/unfrozen pool back into `AccountCapsule.balance`) omit this check entirely. Any deployed contract can invoke these native-contract opcodes from a normal `TriggerSmartContract` transaction, bypassing the feature gate that the direct actuator path enforces.

### Impact Explanation
If `supportUnfreezeDelay()`/`unfreezeDelayDays` has not been enabled by the committee (default `0`, i.e., feature "paused"), a contract can still call the TVM `unfreezeBalanceV2`/`withdrawExpireUnfreeze` precompiled opcodes to perform unfreeze/withdraw operations that credit `AccountCapsule.balance`, executing fund-movement logic the protocol has deliberately disabled network-wide. This is a state-transition/feature-gate bypass reachable from an ordinary contract-call transaction, directly matching the report's bug class ("privileged/critical function omits the same access-control/state check enforced elsewhere, enabling fund movement while the corresponding path is supposed to be blocked").

### Likelihood Explanation
Any account can deploy a contract and issue a `TriggerSmartContract` transaction invoking the corresponding TVM opcode; no special role is required beyond normal contract deployment/invocation, which is well within the scope of an unprivileged transaction broadcaster.

### Recommendation
Add the same `dynamicStore.supportUnfreezeDelay()` check to `UnfreezeBalanceV2Processor.validate()` and `WithdrawExpireUnfreezeProcessor.validate()` (and any other TVM native-contract processors implementing committee-gated features) so that the TVM opcode paths cannot bypass the feature switch enforced in the corresponding actuators.

### Proof of Concept
1. Deploy a contract that invokes the `unfreezeBalanceV2`/`withdrawExpireUnfreeze` TVM precompile via `Program.withdrawExpireUnfreeze()` / the analogous unfreeze opcode.
2. On a network where the committee has not enabled `unfreezeDelayDays` (`supportUnfreezeDelay()` is false), submitting a normal `UnfreezeBalanceV2Contract`/`WithdrawExpireUnfreezeContract` transaction via `UnfreezeBalanceV2Actuator`/`WithdrawExpireUnfreezeActuator` is rejected with "Not support UnfreezeV2 transaction, need to be opened by the committee".
3. Invoking the same operation through the contract's TVM opcode path succeeds because `UnfreezeBalanceV2Processor.validate()`/`WithdrawExpireUnfreezeProcessor.validate()` never checks `supportUnfreezeDelay()`, allowing the fund transition to execute despite the feature being disabled.

Note: I could not fully trace the exact opcode dispatch table entries in `OperationRegistry.java`/`OperationActions.java` that route to these processors within the available indexed content, so the precise opcode names/gas costs are not independently verified beyond the `Program.java` call sites cited above; a full Devin session with repo access would be needed to confirm the opcode wiring end-to-end.

  public void validate(WithdrawExpireUnfreezeParam param, Repository repo) throws ContractValidateException {
    if (repo == null) {
      throw new ContractValidateException(STORE_NOT_EXIST);
    }

    byte[] ownerAddress = param.getOwnerAddress();
    DynamicPropertiesStore dynamicStore = repo.getDynamicPropertiesStore();
    if (!DecodeUtil.addressValid(ownerAddress)) {
      throw new ContractValidateException("Invalid address");
    }
    AccountCapsule accountCapsule = repo.getAccount(ownerAddress);
    if (Objects.isNull(accountCapsule)) {
      String readableOwnerAddress = StringUtil.createReadableString(ownerAddress);
      throw new ContractValidateException(ACCOUNT_EXCEPTION_STR
          + readableOwnerAddress + NOT_EXIST_STR);
    }

    long now = dynamicStore.getLatestBlockHeaderTimestamp();
    List<Protocol.Account.UnFreezeV2> unfrozenV2List = accountCapsule.getInstance()
        .getUnfrozenV2List();
    long totalWithdrawUnfreeze = getTotalWithdrawUnfreeze(unfrozenV2List, now);
    if (totalWithdrawUnfreeze < 0) {
      throw new ContractValidateException("no unFreeze balance to withdraw ");
    }
    try {
      LongMath.checkedAdd(accountCapsule.getBalance(), totalWithdrawUnfreeze);
    } catch (ArithmeticException e) {
      logger.debug(e.getMessage(), e);
      throw new ContractValidateException(e.getMessage());
    }

    if (accountCapsule.hasInvalidDelegatedV2()) {
      MUtil.checkCPUTimeForInvalidDelegatedV2Balance();
    }
  }

  public long withdrawExpireUnfreeze() {
    Repository repository = getContractState().newRepositoryChild();
    byte[] owner = getContextAddress();

    increaseNonce();
    InternalTransaction internalTx = addInternalTx(null, owner, owner, 0, null,
        "withdrawExpireUnfreeze", nonce, null);

    try {
      WithdrawExpireUnfreezeParam param = new WithdrawExpireUnfreezeParam();
      param.setOwnerAddress(owner);

      WithdrawExpireUnfreezeProcessor processor = new WithdrawExpireUnfreezeProcessor();
      processor.validate(param, repository);
      long expireUnfreezeBalance = processor.execute(param, repository);
      repository.commit();
      if (internalTx != null) {
        internalTx.setValue(expireUnfreezeBalance);
      }
      return expireUnfreezeBalance;
    } catch (ContractValidateException e) {
      logger.warn("TVM WithdrawExpireUnfreeze: validate failure. Reason: {}", e.getMessage());
    } catch (ContractExeException e) {
      logger.warn("TVM WithdrawExpireUnfreeze: execute failure. Reason: {}", e.getMessage());
    }
    if (internalTx != null) {
      internalTx.reject();
    }
    return 0;
  }
