### Title
Attacker-controlled remote URL with `ext::` scheme bypasses protocol allowlist and is forwarded unmodified to `git-fetch(1)` - ([File: internal/git/gitcmd/command_resolve.go])

### Summary
`GetURLAndResolveConfig` only special-cases `http(s)://`, `git://`, and `ssh://` prefixes; any other string (including `ext::...` or other arbitrary scp-like/`ext::`-style values) falls through to `getURLAndResolveConfigForSCP`, which does no scheme validation and simply forwards the string. `buildCommandOpts` in `fetch_remote.go` places this value verbatim into `remote.inmemory.url` and invokes `git-fetch(1)` against it, with no allowlist rejecting the `ext::` (or other remote-helper) scheme anywhere in Gitaly.

### Finding Description
`FetchRemote`'s `validateFetchRemoteRequest` (internal/gitaly/service/repository/fetch_remote.go:306-320) only checks that `RemoteParams.Url` is non-empty — it performs no scheme/protocol allowlisting. `buildCommandOpts` (fetch_remote.go:260-304) takes `req.GetRemoteParams().GetUrl()` and, if `ResolvedAddress` is set, passes it to `gitcmd.GetURLAndResolveConfig` (internal/git/gitcmd/command_resolve.go:27-49). That function's `switch` only recognizes `http://`, `https://`, `git://`, `ssh://` prefixes explicitly; every other value — including `ext::sh -c ...` — falls into the `default` branch calling `getURLAndResolveConfigForSCP` (command_resolve.go:62-79), which merely does a `SplitN(remoteURL, ":", 2)` string manipulation and returns a modified string without validating that the “host” portion is a real host and not a git remote-helper invocation like `ext::`. The (possibly rewritten) URL is then set as `remote.inmemory.url` config (fetch_remote.go:280) and used directly by `quarantineRepo.FetchRemote(ctx, "inmemory", opts)` → `git fetch inmemory` (internal/git/localrepo/remote.go:79-128).

However, whether this results in code execution depends on Git's own protocol allowlist, not Gitaly's. Since Git 2.12.0, remote helpers invoked via the `<scheme>::` transport syntax (e.g., `ext::`, `fd::`) are disabled by default unless explicitly enabled via `protocol.ext.allow` (default: `user`, requiring explicit opt-in) or the `GIT_ALLOW_PROTOCOL` environment variable. I found no evidence in this codebase that Gitaly sets `GIT_ALLOW_PROTOCOL`, `protocol.ext.allow=always`, or any config that would enable the `ext` transport for spawned git processes — no matches were found for `GIT_ALLOW_PROTOCOL`, `protocol.ext.allow`, or `curl.allow` in production code. Because Git's own built-in protocol allowlist defaults to blocking `ext::` (returning "fatal: transport 'ext' not allowed"), the mere absence of scheme validation in `GetURLAndResolveConfig`/`getURLAndResolveConfigForSCP` does not, by itself, translate into command execution under default Git/Gitaly configuration — it requires Git's default protection to have been separately weakened, which is out of scope per the audit rules ("reject anything requiring ... non-default configuration ... or a bug in git itself rather than in Gitaly").

Additionally, this same input class is reachable without `ResolvedAddress` at all (`resolvedAddress` is optional in `buildCommandOpts`), so `GetURLAndResolveConfig`/`getURLAndResolveConfigForSCP` is not even a mandatory gate — the raw attacker URL flows to `remote.inmemory.url` regardless, whether or not this function is invoked. That confirms the missing validation is a genuine gap in Gitaly's own input handling (no scheme allowlist exists anywhere on this attacker-controlled path), but the described end-to-end "code execution via `ext::`" impact relies on Git's separate, independent, default-enabled protection remaining intact.

### Impact Explanation
If Git's own remote-helper protocol restriction were ever bypassed or misconfigured (not evidenced in this repo), the missing scheme validation in `GetURLAndResolveConfig`/`getURLAndResolveConfigForSCP` and `validateFetchRemoteRequest` would allow arbitrary command execution via `ext::` or similar remote helpers, since the resulting URL flows unmodified into `git fetch`. As it stands, given Git's default protocol allowlist rejects `ext::`, this does not yield remote code execution under default configuration.

### Likelihood Explanation
Low under default configuration: the attacker (an unprivileged GitLab user configuring a mirror/fetch URL for their own project) can freely control `RemoteParams.Url` and `ResolvedAddress`, and Gitaly performs no scheme validation of its own. But default Git behavior (`protocol.ext.allow` defaulting to disabled for fetch, requiring explicit `user`/`always` opt-in or `GIT_ALLOW_PROTOCOL`) blocks the `ext::` transport before any command execution occurs, so exploitation requires a non-default Git/Gitaly configuration that is outside this audit's scope.

### Recommendation
Add an explicit allowlist of accepted URL schemes (`http://`, `https://`, `git://`, `ssh://`, and bare scp-like `host:path`) in `validateFetchRemoteRequest` (or in `GetURLAndResolveConfig`) that rejects any URL containing `::` transport syntax (e.g., `ext::`, `fd::`, or any string matching Git's remote-helper transport pattern `^[A-Za-z0-9_+-]+::`) before it reaches `git-fetch(1)`/`git-clone(1)`. Defense-in-depth: also explicitly set `GIT_ALLOW_PROTOCOL`/`protocol.*.allow=never` (except the needed ones) on git subprocess invocations spawned from RPC-supplied URLs, rather than relying solely on Git's own defaults.

func GetURLAndResolveConfig(remoteURL string, resolvedAddress string) (string, []ConfigPair, error) {
	if remoteURL == "" {
		return "", nil, fmt.Errorf("URL is empty")
	}

	if resolvedAddress == "" {
		return "", nil, fmt.Errorf("resolved address is empty")
	}

	resolvedIP := net.ParseIP(resolvedAddress)
	if resolvedIP == nil {
		return "", nil, fmt.Errorf("resolved address has invalid IPv4/IPv6 address")
	}

	switch {
	case strings.HasPrefix(remoteURL, "http://"), strings.HasPrefix(remoteURL, "https://"), strings.HasPrefix(remoteURL, "git://"):
		return getURLAndResolveConfigForURL(remoteURL, resolvedAddress)
	case strings.HasPrefix(remoteURL, "ssh://"):
		return getURLAndResolveConfigForSSH(remoteURL, resolvedAddress)
	default:
		return getURLAndResolveConfigForSCP(remoteURL, resolvedAddress)
	}
}

func getURLAndResolveConfigForSCP(remoteURL, resolvedAddress string) (string, []ConfigPair, error) {
	hostAndPath := strings.SplitN(remoteURL, ":", 2)
	if len(hostAndPath) != 2 {
		return "", nil, fmt.Errorf("invalid protocol/URL encountered: %s", remoteURL)
	}

	if strings.Contains(hostAndPath[0], "/") {
		return "", nil, fmt.Errorf("SSH URLs with '/' before colon are unsupported")
	}

	var userPrefix string

	if userAndHost := strings.SplitAfterN(remoteURL, "@", 2); len(userAndHost) > 1 {
		userPrefix = userAndHost[0]
	}

	return fmt.Sprintf("%s%s:%s", userPrefix, resolvedAddress, hostAndPath[1]), nil, nil
}

func buildCommandOpts(ctx context.Context, opts *localrepo.FetchOpts, req *gitalypb.FetchRemoteRequest) error {
	remoteURL := req.GetRemoteParams().GetUrl()
	var config []gitcmd.ConfigPair

	for _, refspec := range getRefspecs(req.GetRemoteParams().GetMirrorRefmaps()) {
		config = append(config, gitcmd.ConfigPair{
			Key: "remote.inmemory.fetch", Value: refspec,
		})
	}

	if resolvedAddress := req.GetRemoteParams().GetResolvedAddress(); resolvedAddress != "" {
		modifiedURL, resolveConfig, err := gitcmd.GetURLAndResolveConfig(remoteURL, resolvedAddress)
		if err != nil {
			return fmt.Errorf("couldn't get curloptResolve config: %w", err)
		}

		remoteURL = modifiedURL
		config = append(config, resolveConfig...)
	}

	config = append(config, gitcmd.ConfigPair{Key: "remote.inmemory.url", Value: remoteURL})

	if featureflag.FetchRemoteProactiveAuth.IsEnabled(ctx) {
		if u, err := url.Parse(remoteURL); err == nil && u.User != nil {
			password, _ := u.User.Password()
			if u.User.Username() != "" && password != "" {
				config = append(config, gitcmd.ConfigPair{
					Key:   "http.proactiveAuth",
					Value: "basic",
				})
			}
		}
	}

	if authHeader := req.GetRemoteParams().GetHttpAuthorizationHeader(); authHeader != "" {
		config = append(config, gitcmd.ConfigPair{
			Key:   fmt.Sprintf("http.%s.extraHeader", req.GetRemoteParams().GetUrl()),
			Value: "Authorization: " + authHeader,
		})
	}

	opts.CommandOptions = append(opts.CommandOptions, gitcmd.WithConfigEnv(config...))

	return nil
}

func (s *server) validateFetchRemoteRequest(ctx context.Context, req *gitalypb.FetchRemoteRequest) error {
	if err := s.locator.ValidateRepository(ctx, req.GetRepository()); err != nil {
		return structerr.NewInvalidArgument("%w", err)
	}

	if req.GetRemoteParams() == nil {
		return structerr.NewInvalidArgument("missing remote params")
	}

	if req.GetRemoteParams().GetUrl() == "" {
		return structerr.NewInvalidArgument("blank or empty remote URL")
	}

	return nil
}

func (repo *Repo) FetchRemote(ctx context.Context, remoteName string, opts FetchOpts) error {
	if err := validateNotBlank(remoteName, "remoteName"); err != nil {
		return err
	}

	var stderr bytes.Buffer
	if opts.Stderr == nil {
		opts.Stderr = &stderr
	}

	objectHash, err := repo.ObjectHash(ctx)
	if err != nil {
		return fmt.Errorf("detecting object hash: %w", err)
	}

	commandOptions := []gitcmd.CmdOpt{
		gitcmd.WithEnv(opts.Env...),
		gitcmd.WithStdout(opts.Stdout),
		gitcmd.WithStderr(opts.Stderr),
		gitcmd.WithConfig(gitcmd.ConfigPair{
			// Git is so kind to point out that we asked it to not show forced updates
			// by default, so we need to ask it not to do that.
			Key: "advice.fetchShowForcedUpdates", Value: "false",
		}),
		gitcmd.WithConfig(gitcmd.ConfigPair{
			// The patch series https://lore.kernel.org/git/20240910203835.2288291-1-bence@ferdinandy.com/
			// introduces new behaviour that automatically sets the local HEAD to the remote's HEAD during
			// a fetch. This happens when the mirror refspec is used to fetch into a bare repository, which
			// we use in operations like `FetchBundle`.
			//
			// Setting the remote's `followremotehead` config to "never" will disable the new behaviour. We
			// do this temporarily until we're sure the new behaviour doesn't have any consequences.
			Key: fmt.Sprintf("remote.%s.followremotehead", remoteName), Value: "never",
		}),
	}
	if opts.DisableTransactions {
		commandOptions = append(commandOptions, gitcmd.WithDisabledHooks())
	} else {
		commandOptions = append(commandOptions, gitcmd.WithRefTxHook(objectHash, repo))
	}
	commandOptions = append(commandOptions, opts.CommandOptions...)

	cmd, err := repo.Exec(ctx,
		gitcmd.Command{
			Name:  "fetch",
			Flags: opts.buildFlags(),
			Args:  []string{remoteName},
		},
		commandOptions...,
	)
