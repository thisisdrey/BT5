### Title
Precompiled Contracts Use Shared Mutable Singleton State, Enabling Cross-Transaction Pollution of Repository/Result/Timeout Context - ([File: actuator/src/main/java/org/tron/core/vm/PrecompiledContracts.java])

### Summary
`PrecompiledContracts` instantiates each precompile (`ecRecover`, `sha256`, `batchValidateSign`, `validateMultiSign`, `modExp`, etc.) exactly once as a `private static final` singleton field [1](#0-0) . Every CALL/STATICCALL/DELEGATECALL opcode targeting a precompile address resolves to the same shared object via `getContractForAddress` [2](#0-1) . Before invoking `execute()`, `Program.callToPrecompiledAddress` mutates that shared instance's fields — `setRepository(deposit)`, `setResult(this.result)`, `setCallerAddress(...)`, `setConstantCall(...)`, `setVmShouldEndInUs(...)` — then reads them back during execution [3](#0-2) . This is the same bug class as the OperationStorage report: a component meant to be "temporary, per-execution context" is instead a long-lived shared object with no per-call isolation and no access control ensuring it starts clean.

### Finding Description
`PrecompiledContract` subclasses hold instance fields (repository/deposit, caller address, `ProgramResult`, constant-call flag, CPU deadline) that are set imperatively right before `execute()` is called [4](#0-3) , and `execute()` itself reads `this.getDeposit()`/`this.isConstantCall()`/`this.getVmShouldEndInUs()` while doing signature-recovery work, e.g. in `ValidateMultiSign.execute` [5](#0-4)  and `BatchValidateSign.execute`/`doExecute` [6](#0-5) . `BatchValidateSign` additionally offloads work to a shared static `ExecutorService` and blocks on `countDownLatch.await(getCPUTimeLeftInNanoSecond())`, where `getCPUTimeLeftInNanoSecond()` derives from the mutable `vmShouldEndInUs` field on the singleton [7](#0-6) .

Because these fields are ordinary (non-thread-local, non-synchronized) instance fields on a `static final` singleton, any two invocations of the same precompile that execute concurrently on the node (e.g. one path processing a broadcast transaction while another thread services a `triggerConstantContract`/query call that reaches the same precompile address) can race on `setRepository`/`setResult`/`setCallerAddress`/`setVmShouldEndInUs` and read a value written by the other context. This mirrors exactly the DeFi Saver `OperationStorage` flaw: a "temporary per-operation" store that lacks isolation and can be polluted by an unrelated concurrent execution, so a later `push`/read (here, the precompile's read of `deposit`, `result`, or the CPU deadline) can observe attacker- or otherwise-unrelated-execution-controlled state instead of its own.

The presence of `getOptimizedContractForConstant`, which reflectively constructs a *fresh* instance of a precompile via its no-arg constructor [8](#0-7) , indicates the codebase is already aware that per-call isolation is required for some paths, but the default `getContractForAddress` lookup used by `Program.callToPrecompiledAddress` still returns the shared singleton for ordinary calls.

### Impact Explanation
If concurrent executions race on the shared precompile instance:
- `setRepository(deposit)`/`getDeposit()` mismatch can cause a `ValidateMultiSign`/`BatchValidateSign` call in one transaction context to read account/permission data from a *different* transaction's `Repository`, corrupting multisig validation results (accepting/rejecting signatures against the wrong account state).
- `setResult(this.result)` pollution can cause cross-transaction bleed of `ProgramResult` state (log/trigger/exception bookkeeping attributed to the wrong transaction).
- `setVmShouldEndInUs` pollution changes the CPU-time deadline `BatchValidateSign`'s thread-pool wait relies on, which can either cause spurious `notEnoughTime` failures for unrelated transactions or bypass the intended CPU-time enforcement, undermining the node's execution-time/energy metering guarantees.

This can manifest as incorrect authorization decisions (multisig bypass/rejection against wrong state) or CPU/time-limit enforcement bypass triggerable by an unprivileged party issuing ordinary transactions/queries that hit precompile addresses `0x9`/`0xa` — within the report's allowed impact categories (unauthorized account operation, energy/CPU metering bypass).

### Likelihood Explanation
Exploitability depends on whether the node actually executes multiple invocations of the same precompile concurrently in practice (e.g., overlapping `triggerConstantContract` query threads and block-processing threads, or any multi-threaded transaction execution path). I was not able to fully confirm within the available tool budget whether java-tron's transaction/block processing is strictly single-threaded end-to-end for all call paths that reach `Program.callToPrecompiledAddress`, or whether concurrent query execution paths can overlap with it — this needs direct verification of the threading model around `Manager`/`Wallet` constant-call execution versus `VMActuator`/block application. Given that `getOptimizedContractForConstant` exists specifically to hand out fresh instances (implying awareness of this exact class of hazard for at least the constant-call path), the underlying design flaw (shared mutable singleton precompile state) is confirmed in code, but full triggering likelihood is uncertain without confirming concurrent call sites.

### Recommendation
- Do not store per-call context (`repository`/deposit, `result`, `callerAddress`, `constantCall`, `vmShouldEndInUs`) as instance fields on shared `static final` precompile singletons.
- Pass this context as explicit method parameters to `execute(...)`, or construct/isolate a fresh precompile instance per invocation (as `getOptimizedContractForConstant` already does for some cases) uniformly for every call path, not just constant calls.
- Audit all threads that can concurrently reach `PrecompiledContracts.getContractForAddress` (block application vs. constant-call/query API) to confirm whether races are actually reachable today, and add synchronization or per-call isolation regardless as defense in depth.

### Proof of Concept
Conceptual PoC (requires confirming concurrent reachability, which I could not fully verify):
1. Thread A executes a broadcast transaction whose contract calls `BatchValidateSign`/`ValidateMultiSign` (precompile address `0x9`/`0xa`), which internally calls `contract.setRepository(depositA)` then blocks on the internal `ExecutorService` while validating signatures.
2. Concurrently, Thread B (e.g., a `triggerConstantContract` API request from an anonymous client) also invokes the same precompile instance, calling `contract.setRepository(depositB)`/`setVmShouldEndInUs(deadlineB)` on the same singleton object before Thread A's `execute()` finishes reading those fields.
3. Thread A's in-flight `execute()` may then observe `depositB`/`deadlineB` instead of its own, corrupting its signature/account validation result or CPU-time enforcement. [9](#0-8)

  public static class BatchValidateSign extends PrecompiledContract {

    private static final ExecutorService workers;
    private static final String workersName = "validate-sign-contract";
    private static final int ENGERYPERSIGN = 1500;
    private static final int MAX_SIZE = 16;
    private static final int ABI_HEADER_WORDS = 5;
    private static final int ABI_ITEM_WORDS = 6;

    static {
      workers = ExecutorServiceManager.newFixedThreadPool(workersName,
          Runtime.getRuntime().availableProcessors() / 2 + 1);
    }

    @Override
    public long getEnergyForData(byte[] data) {
      long cnt = (data.length / WORD_SIZE - 5) / 6;
      // one sign 1500, half of ecrecover
      return cnt * ENGERYPERSIGN;
    }

    @Override
    public Pair<Boolean, byte[]> execute(byte[] data) {
      try {
        return doExecute(data);
      } catch (Throwable t) {
        if (t instanceof InterruptedException){
          Thread.currentThread().interrupt();
        }
        return Pair.of(true, new byte[WORD_SIZE]);
      }
    }

    private Pair<Boolean, byte[]> doExecute(byte[] data)
        throws InterruptedException, ExecutionException {
      if (VMConfig.allowTvmOsaka()
          && !isValidAbiEncoding(data, ABI_HEADER_WORDS, ABI_ITEM_WORDS)) {
        return Pair.of(false, EMPTY_BYTE_ARRAY);
      }
      DataWord[] words = DataWord.parseArray(data);
      byte[] hash = words[0].getData();

      if (VMConfig.allowTvmSelfdestructRestriction()) {
        int sigArraySize = words[words[1].intValueSafe() / WORD_SIZE].intValueSafe();
        int addrArraySize = words[words[2].intValueSafe() / WORD_SIZE].intValueSafe();
        if (sigArraySize > MAX_SIZE || addrArraySize > MAX_SIZE) {
          return Pair.of(true, DATA_FALSE);
        }
      }

      byte[][] signatures = VMConfig.allowTvmSelfdestructRestriction() ?
          extractSigArray(words, words[1].intValueSafe() / WORD_SIZE, data) :
          extractBytesArray(words, words[1].intValueSafe() / WORD_SIZE, data);
      byte[][] addresses = extractBytes32Array(
          words, words[2].intValueSafe() / WORD_SIZE);
      int cnt = signatures.length;
      if (cnt == 0 || cnt > MAX_SIZE || signatures.length != addresses.length) {
        return Pair.of(true, DATA_FALSE);
      }
      byte[] res = new byte[WORD_SIZE];
      if (isConstantCall()) {
        //for constant call not use thread pool to avoid potential effect
        for (int i = 0; i < cnt; i++) {
          if (DataWord
              .equalAddressByteArray(addresses[i], recoverAddrBySign(signatures[i], hash))) {
            res[i] = 1;
          }
        }
      } else {
        // add check
        CountDownLatch countDownLatch = new CountDownLatch(cnt);
        List<Future<RecoverAddrResult>> futures = new ArrayList<>(cnt);

        for (int i = 0; i < cnt; i++) {
          Future<RecoverAddrResult> future = workers
              .submit(new RecoverAddrTask(countDownLatch, hash, signatures[i], i));
          futures.add(future);
        }
        boolean withNoTimeout = countDownLatch
            .await(getCPUTimeLeftInNanoSecond(), TimeUnit.NANOSECONDS);

        if (!withNoTimeout) {
          logger.info("BatchValidateSign timeout");
          throw Program.Exception.notEnoughTime("call BatchValidateSign precompile method");
        }

        for (Future<RecoverAddrResult> future : futures) {
          RecoverAddrResult result = future.get();
          int index = result.nonce;
          if (DataWord.equalAddressByteArray(result.addr, addresses[index])) {
            res[index] = 1;
          }
        }
      }
      return Pair.of(true, res);
    }
