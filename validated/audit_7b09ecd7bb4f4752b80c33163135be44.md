### Title
Permissionless PDA-account squatting lets an attacker occupy a victim's deterministic MarginfiAccount PDA slot before the victim can claim it - ([File: programs/marginfi/src/instructions/marginfi_account/transfer_account.rs])

### Summary
The reported InstaDApp bug is a front-running griefing attack where an attacker races a `build()+setOwner(X)` call ahead of the legitimate `setOwner(X)` transaction so that the deterministic wallet address for `X` is already taken, permanently blocking `X` from ever registering that specific wallet. marginfi-v2 has an analogous deterministic-address-squatting surface in its PDA-based account system: `MarginfiAccount` addresses for the `_pda` instructions are derived purely from `(group, authority, account_index, third_party_id)` [1](#0-0) , and the "authority"/"new_authority" whose pubkey is baked into the seed is not required to co-sign every instruction that creates such an account.

### Finding Description
`marginfi_account_initialize_pda` does require the `authority` field to be a `Signer`, so an attacker cannot squat a PDA for `authority = victim` directly through that entrypoint [2](#0-1) .

However, `transfer_to_new_account` (and by symmetry `transfer_to_new_account_pda`) explicitly marks the recipient authority as unchecked and not required to sign: [3](#0-2) 

`transfer_to_new_account_pda` derives the `new_marginfi_account` PDA from `(group, new_authority, account_index, third_party_id)` and calls `initialize_migrated_account(..., ctx.accounts.new_authority.key(), ...)` to set the new account's `authority` field, using an `init` constraint on the PDA seeds [4](#0-3) . Because `new_authority` is only ever read as a pubkey (never required to sign), any attacker who owns a throwaway `MarginfiAccount` (trivially creatable, permissionless, cost of one rent-exempt account) can call `transfer_to_new_account_pda` and set `new_authority = <victim_pubkey>` together with a chosen `account_index`/`third_party_id`. This permanently occupies the PDA at that exact seed tuple with an anchor `init` constraint, so any later attempt by the victim (or an integrator acting on the victim's behalf) to create their own PDA account at that same `(account_index, third_party_id)` via `marginfi_account_initialize_pda` or `transfer_to_new_account_pda` will fail because the account already exists — mirroring the "proxy already exists → revert" griefing pattern from the InstaDApp report.

### Impact Explanation
This is an unauthorized state change: an attacker can force-create a `MarginfiAccount` whose `authority` field is set to an arbitrary victim pubkey without that victim ever signing anything, and can permanently deny that victim the ability to initialize a PDA account at a specific, predictable `account_index`/`third_party_id` (e.g., the commonly-used default index `0`, which the docs and CLI/test-fixtures treat as the conventional first account) [5](#0-4) . This can disrupt third-party integrators that rely on deterministically deriving a specific PDA index for a given user, and creates attacker-controlled "phantom" accounts nominally owned by victims (with `migrated_from` pointing at attacker-controlled junk accounts), polluting account state. It does not directly enable theft of already-deposited funds because the victim's real assets live in a separate, un-squattable account, and the victim retains the full `u16` index space to pick an alternate slot — so it is a griefing/permanent-lock-of-one-slot issue rather than a full account takeover or insolvency bug.

### Likelihood Explanation
Exploitation only requires: (1) creating one throwaway `MarginfiAccount` (cheap, permissionless), and (2) calling `transfer_to_new_account_pda` with `new_authority` set to the target victim pubkey and a guessed/likely `account_index` (0 is the conventional default per the integrator guide) before the victim does. No signature from the victim is needed, and the attack can be scripted to pre-emptively squat index 0/other common indices for many known addresses at low cost, similar in spirit to the original front-running described in the report (though here it does not require literal mempool front-running — an attacker can proactively squat indices for any address ahead of time).

### Recommendation
Require the `new_authority` in `transfer_to_new_account` / `transfer_to_new_account_pda` to be a co-signer (or introduce a two-step "propose/accept" flow analogous to the report's suggested `acceptOwnershipTransfer()` pattern) so that a new PDA-based account can only be created under a given authority with that authority's active consent, closing the same class of address-squatting griefing described in the external report.

### Proof of Concept
1. Attacker creates `attacker_old_account` via `marginfi_account_initialize` (or `_pda`), a normal, cheap, permissionless call.
2. Attacker computes `victim_pda = MarginfiAccount::derive_pda(group, victim_pubkey, account_index=0, third_party_id=None, program_id)` exactly as the victim/integrator would [1](#0-0) .
3. Attacker calls `transfer_to_new_account_pda` with `old_marginfi_account = attacker_old_account`, `authority = attacker` (signs), `new_authority = victim_pubkey` (does NOT sign, per `UncheckedAccount`), `account_index = 0`, `third_party_id = None`, and `new_marginfi_account = victim_pda`.
4. The `init` constraint succeeds because the PDA didn't previously exist; `victim_pda.authority` is now set to `victim_pubkey` even though the victim never signed [4](#0-3) .
5. When the victim later tries `marginfi_account_initialize_pda(account_index=0)` (or any transfer targeting that same index), the `init` constraint fails because `victim_pda` is already initialized — this can be verified against the existing "duplicate/already in use" test pattern used for the same PDA-init code path [6](#0-5) .

pub fn transfer_to_new_account_pda(
    ctx: Context<TransferToNewAccountPda>,
    account_index: u16,
    third_party_id: Option<u16>,
) -> MarginfiResult {
    // Validate the global fee wallet and claim a nominal fee
    let group = ctx.accounts.group.load()?;
    check_eq!(
        ctx.accounts.global_fee_wallet.key(),
        group.fee_state_cache.global_fee_wallet,
        MarginfiError::InvalidFeeAta
    );
    anchor_lang::system_program::transfer(ctx.accounts.transfer_fee(), ACCOUNT_TRANSFER_FEE)?;

    let mut old_account = ctx.accounts.old_marginfi_account.load_mut()?;

    check!(
        !old_account.get_flag(ACCOUNT_IN_FLASHLOAN),
        MarginfiError::AccountInFlashloan
    );

    check!(
        !old_account.get_flag(ACCOUNT_IN_RECEIVERSHIP),
        MarginfiError::ForbiddenIx
    );

    check!(
        !old_account.get_flag(ACCOUNT_IN_ORDER_EXECUTION),
        MarginfiError::ForbiddenIx
    );

    check!(
        old_account.active_orders == 0,
        MarginfiError::IllegalAction,
        "Close all active orders before transfer"
    );

    // Prevent multiple migrations from the same account
    check_eq!(
        old_account.migrated_to,
        Pubkey::default(),
        MarginfiError::AccountAlreadyMigrated
    );

    // Validate third-party id restriction if provided
    if let Some(id) = third_party_id {
        if !is_allowed_cpi_for_third_party_id(&ctx.accounts.instructions_sysvar, id)? {
            return err!(MarginfiError::Unauthorized);
        }
    }

    let mut new_account = ctx.accounts.new_marginfi_account.load_init()?;
    let current_timestamp = Clock::get()?.unix_timestamp as u64;
    initialize_migrated_account(
        &mut new_account,
        &old_account,
        ctx.accounts.new_authority.key(),
        current_timestamp,
        ctx.accounts.old_marginfi_account.key(),
    );
    new_account.account_index = account_index;
    new_account.third_party_index = third_party_id.unwrap_or(0);
    new_account.bump = ctx.bumps.new_marginfi_account;

#[tokio::test]
async fn marginfi_account_create_pda_duplicate_fails() -> anyhow::Result<()> {
    let test_f = TestFixture::new(None).await;

    let authority = test_f.payer();
    let account_index = 0;
    let third_party_id = None;

    // Derive PDA for the marginfi account
    let (marginfi_account_pda, _bump) = MarginfiAccount::derive_pda(
        &test_f.marginfi_group.key,
        &authority,
        account_index,
        third_party_id,
        &marginfi::ID,
    );

    let accounts = marginfi::accounts::MarginfiAccountInitializePda {
        marginfi_group: test_f.marginfi_group.key,
        marginfi_account: marginfi_account_pda,
        authority: authority,
        fee_payer: authority,
        instructions_sysvar: solana_instructions_sysvar::id(),
        system_program: system_program::id(),
    };

    let init_marginfi_account_pda_ix = Instruction {
        program_id: marginfi::ID,
        accounts: accounts.to_account_metas(Some(true)),
        data: marginfi::instruction::MarginfiAccountInitializePda {
            account_index,
            third_party_id,
        }
        .data(),
    };

    // First transaction should succeed
    let tx1 = Transaction::new_signed_with_payer(
        &[init_marginfi_account_pda_ix.clone()],
        Some(&test_f.payer()),
        &[&test_f.payer_keypair()],
        test_f.get_latest_blockhash().await,
    );

    let res1 = test_f
        .context
        .borrow_mut()
        .banks_client
        .process_transaction(tx1)
        .await;

    assert!(res1.is_ok());

    // Second transaction with same parameters should fail
    let tx2 = Transaction::new_signed_with_payer(
        &[init_marginfi_account_pda_ix],
        Some(&test_f.payer()),
        &[&test_f.payer_keypair()],
        test_f.get_latest_blockhash().await,
    );

    let res2 = test_f
        .context
        .borrow_mut()
        .banks_client
        .process_transaction(tx2)
        .await;

    assert!(res2.is_err(), "Duplicate account creation should fail");

    Ok(())
}
