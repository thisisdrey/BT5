### Title
Per-bank pause does not stop permissionless interest accrual, unlike the global protocol pause - ([File: programs/marginfi/src/instructions/marginfi_group/accrue_bank_interest.rs])

### Summary
`marginfi-v2` supports two independent "emergency stop" mechanisms: a group-wide `panic_pause` and a per-bank `operational_state = Paused` set via `configure_bank`. The per-bank `Paused` state is documented to halt *all* user operations on that bank — deposit, borrow, withdraw, repay, and liquidation — exactly the "emergency: halt all activity while investigating an issue" use case described in `guides/ADMIN/BANK_STATE.md` [1](#0-0) . However, the permissionless `lending_pool_accrue_bank_interest` instruction only checks the group-level `is_protocol_paused()` flag; it never validates the bank's own `operational_state` via `validate_bank_state`, so interest keeps compounding on a per-bank-paused market even though users cannot repay or be liquidated on it.

### Finding Description
The `LendingPoolAccrueBankInterest` accounts struct gates the permissionless interest-accrual crank solely on the group-wide pause flag: [2](#0-1) 

Contrast this with the other user-facing instructions (`borrow`, `repay`, `withdraw`, `liquidate`), which all call `validate_bank_state(&bank, InstructionKind::…)` before proceeding, e.g. in `repay`: [3](#0-2) 

`validate_bank_state` is what actually enforces the per-bank `Paused`/`ReduceOnly`/`KilledByBankruptcy` semantics documented in the summary table (Paused blocks deposit/borrow/withdraw/repay/liquidate for that specific bank): [4](#0-3) [5](#0-4) 

`lending_pool_accrue_bank_interest` never calls `validate_bank_state`, so it does not check `bank.config.operational_state` at all — only `group.is_protocol_paused()`. `Bank::accrue_interest` itself is purely time-based and has no concept of the bank's operational state: [6](#0-5) 

The repo's own regression tests only verify that the **group-wide** panic pause blocks this crank (`accrue_bank_interest_blocked_during_pause`) — there is no equivalent test asserting that a **per-bank** `Paused` state blocks it: [7](#0-6) 

This is a direct analog of the referenced GMX M-19 bug: order/decrease-position ability can be administratively disabled, but the fee/funding engine (here, `accrue_interest`'s `time_delta`-based compounding) is unaware of the pause and keeps running, penalizing users who are locked out of remediating their position.

### Impact Explanation
When a group admin sets an individual bank's `operational_state` to `Paused` (the documented emergency-halt mechanism), borrowers on that bank cannot repay and cannot be liquidated (both blocked by `BankPaused`/`BankReduceOnly` errors from `validate_bank_state`). Any third party can still permissionlessly call `lending_pool_accrue_bank_interest` on that same bank, since it is gated only by the *group*-level pause flag. This lets liability share value keep climbing for the entire duration of the per-bank pause. When the admin later restores the bank to `Operational`, borrowers face inflated debt they had no ability to service or prevent during the pause, which can push previously-healthy positions into liquidation territory or worsen accounts that end up requiring `handle_bankruptcy`/bad-debt settlement — an unauthorized increase in liability state contributing to unfair liquidation and potential bad debt, through no fault of the borrower.

### Likelihood Explanation
Likelihood is moderate: it requires an admin action (pausing an individual bank) that the protocol explicitly documents as an available/expected emergency tool, combined with the passage of time before the bank is un-paused. No attacker privilege is needed to trigger the accrual itself — `lending_pool_accrue_bank_interest` is permissionless and can be called by anyone (or simply left to a keeper/crank) while the bank sits in the `Paused` state.

### Recommendation
Add a `validate_bank_state` (or equivalent operational-state) check to `LendingPoolAccrueBankInterest`/`lending_pool_accrue_bank_interest`, so that interest accrual is halted whenever the bank's own `operational_state` is `Paused` (and reconsidered for `KilledByBankruptcy`), consistent with how `borrow`, `repay`, `withdraw`, and `liquidate` already gate on this field. Alternatively, freeze `last_update` at the moment a bank enters `Paused` and resume the clock only when it returns to `Operational`/`ReduceOnly`, so the pause window contributes no interest.

### Proof of Concept
1. Admin sets `usdc_bank.config.operational_state = Paused` via `configure_bank` (documented emergency use case).
2. A borrower with an outstanding USDC liability on that bank cannot call `repay` (`BankPaused`) and cannot be liquidated (`BankPaused` blocks the withdraw/repay legs of liquidation), per `validate_bank_state`.
3. Anyone calls `lending_pool_accrue_bank_interest(usdc_bank)`; because its `Accounts` struct only checks `!group.is_protocol_paused()`, and the group is not group-wide paused, the call succeeds and `Bank::accrue_interest` advances `last_update`/`liability_share_value` based on elapsed time exactly as if the bank were `Operational`.
4. This can be repeated for the entire duration the bank remains `Paused`.
5. When the admin sets the bank back to `Operational`, the borrower's debt has grown with no opportunity to repay or otherwise avoid it during the pause, and may now be liquidatable purely due to interest accrued while remediation was administratively blocked.

```rust
pub fn validate_bank_state(bank: &Bank, kind: InstructionKind) -> MarginfiResult {
    if bank.config.operational_state == BankOperationalState::KilledByBankruptcy {
        return err!(MarginfiError::BankKilledByBankruptcy);
    }
    // Bank exists but has not completed one-time setup (e.g. JupLend seed deposit). Block every
    // operation until init runs.
    if bank.config.operational_state == BankOperationalState::Uninitialized {
        return err!(MarginfiError::BankUninitialized);
    }

    match kind {
        InstructionKind::FailsInReduceState if bank.config.operational_state.is_reduce_only() => {
            return err!(MarginfiError::BankReduceOnly);
        }

        InstructionKind::FailsInPausedState
            if bank.config.operational_state == BankOperationalState::Paused =>
        {
            return err!(MarginfiError::BankPaused);
        }

        InstructionKind::FailsIfPausedOrReduceState
            if matches!(
                bank.config.operational_state,
                BankOperationalState::Paused
                    | BankOperationalState::ReduceOnly
                    | BankOperationalState::ReduceOnlyWithBorrowingPower
            ) =>
        {
            return match bank.config.operational_state {
                BankOperationalState::Paused => {
                    err!(MarginfiError::BankPaused)
                }
                state if state.is_reduce_only() => {
                    err!(MarginfiError::BankReduceOnly)
                }
                _ => unreachable!(),
            };
        }
        _ => {}
    }

    Ok(())
}
```

```rust
/// Permissionless `lending_pool_accrue_bank_interest` is rejected while the protocol is paused.
#[tokio::test]
async fn accrue_bank_interest_blocked_during_pause() -> anyhow::Result<()> {
    let test_f = TestFixture::new(Some(TestSettings::all_banks_payer_not_admin())).await;

    let usdc_bank = test_f.get_bank(&BankMint::Usdc);

    // Sanity check: accrue works while unpaused.
    test_f.marginfi_group.try_accrue_interest(usdc_bank).await?;

    // Pause and propagate so the group cache reflects the paused state.
    test_f.marginfi_group.try_panic_pause().await?;
    test_f.marginfi_group.try_propagate_fee_state().await?;

    let marginfi_group = test_f.marginfi_group.load().await;
    assert!(marginfi_group.panic_state_cache.is_paused_flag());

    // While paused, the permissionless crank must be rejected.
    let result = test_f.marginfi_group.try_accrue_interest(usdc_bank).await;

    assert_custom_error!(result.unwrap_err(), MarginfiError::ProtocolPaused);

    Ok(())
}
```
