### Title
Unstaked attacker can reset the per-connection QUIC stream-rate budget by reconnecting from the same IP, bypassing `STREAM_THROTTLING_INTERVAL` throttling - ([File: streamer/src/nonblocking/quic.rs])

### Summary
`ConnectionTable::try_add_connection` only reuses an existing `stream_counter` when a live `ConnectionEntry` for the same `ConnectionTableKey` is still present in the table; once the last connection under a key is removed, `remove_connection` deletes the map entry entirely (`e.swap_remove_entry()`), so the very next connection from that key calls the `stream_counter_factory` closure and gets a brand-new `Arc<ConnectionStreamCounter>` with `stream_count = 0` and `last_throttling_instant = now`. An unstaked, unauthenticated peer is keyed purely by IP (`ConnectionTableKey::IP`), so closing and reopening a QUIC connection from the same IP with a new ephemeral port resets the stream-rate budget used by `throttle_stream`.

### Finding Description
For unstaked/unauthenticated peers, `ConnectionTableKey::new(ip, remote_pubkey)` resolves to `ConnectionTableKey::IP(ip)` because `remote_pubkey` is `None` [1](#0-0) . `try_add_connection` looks up `self.table.entry(key)`, and only reuses the existing `stream_counter` if there is already at least one `ConnectionEntry` for that key; otherwise it invokes the caller-supplied `stream_counter_factory`, which in `SwQos::cache_new_connection` constructs a fresh `Arc::new(ConnectionStreamCounter::new())`: [2](#0-1) [3](#0-2) 

`ConnectionStreamCounter::new()` initializes `stream_count = 0` and `last_throttling_instant = now` [4](#0-3) .

When a connection is closed, `remove_connection` filters the entry vector for that key and, if it becomes empty, removes the key from the `IndexMap` entirely: [5](#0-4) 

Consequently, if the attacker's IP has exactly one active connection and it is closed, the table entry for that IP is deleted. The next connection attempt from the same IP (new ephemeral source port, same key) finds `connection_entry.first()` to be `None` and creates a brand-new counter via the factory closure, resetting both `stream_count` and `last_throttling_instant`.

`throttle_stream` enforces the budget purely off this per-key counter state: it compares `stream_count` against `max_streams_per_throttling_interval` within a rolling `STREAM_THROTTLING_INTERVAL` (100ms) window computed from `last_throttling_instant` [6](#0-5) . There is no persistent, IP-scoped memory of consumed budget across the connection's lifetime — the throttle state lives entirely in the `ConnectionStreamCounter` Arc held by the `ConnectionEntry`, which is dropped with the connection.

The only mitigating control is `ConnectionRateLimiter`, a per-IP token bucket gating new connection registrations (`limit_per_minute`, `max_burst`) [7](#0-6) . This limits *how often* an IP may establish new connections, but it operates on a per-minute budget with burst allowance, independent of and much coarser-grained than the 100ms `STREAM_THROTTLING_INTERVAL`; within its allowed burst, the attacker can still execute several full reconnect-and-reset cycles before this limiter engages, and once past the burst, is only throttled to whatever `limit_per_minute` connections/minute are configured — still bypassing the intended sustained-throughput budget derived from `max_streams_per_throttling_interval` per 100ms window, since each reconnect resets the counter to zero completely independent of how long the attacker was previously connected.

### Impact Explanation
An unstaked source can exceed its intended sustained stream/tx rate share (`available_load_capacity_in_throttling_duration` for `ConnectionPeerType::Unstaked`, driven by `MAX_UNSTAKED_TPS` / `STREAM_THROTTLING_INTERVAL_MS`) by repeatedly reconnecting rather than being capped at that steady-state rate. This is a QoS/fairness bypass — the intended per-source stream budget can be reset arbitrarily often, letting the attacker consume more than its fair share of unstaked capacity and starve other unstaked (or, indirectly, staked) peers competing for the shared stream-processing budget. This matches the "QoS bypass/starvation" category referenced in the question; it is not a memory-safety, consensus, or verification-bypass bug, so its bounty classification would be a lower-severity availability/fairness issue rather than a critical one.

### Likelihood Explanation
Preconditions are fully attacker-controlled and require no privilege: an unstaked remote client only needs to (1) open a QUIC connection to the public TPU port, (2) send bursts of streams up to the throttling budget, (3) close the connection, and (4) reconnect with a new ephemeral port before `STREAM_THROTTLING_INTERVAL_MS` (100ms) elapses, while staying within `max_connections_per_unstaked_peer` (trivially true since only one connection is open at a time). The only friction is the per-IP `ConnectionRateLimiter`, which caps connection *establishment* rate per minute/burst but is a coarser, independent budget that does not scale down to the 100ms throttling window, so short bursts of reconnects are not fully prevented by it. This makes the exploit readily repeatable, bounded mainly by QUIC handshake latency and the configured connection-rate-limiter burst.

### Recommendation
Persist and rate-limit the stream-throttling state per source IP independently of individual connection lifetime — e.g., store `ConnectionStreamCounter` (or equivalent quota state) in a separate, longer-lived map keyed by IP (with its own TTL/pruning) rather than deriving it solely from the currently-live `ConnectionEntry` list in `ConnectionTable`. Alternatively, when the last connection for a key is removed, retain the `stream_counter` (and its `last_throttling_instant`) for a grace period at least as long as `STREAM_THROTTLING_INTERVAL`, and only allow the factory to create a fresh counter after that grace period elapses, so reconnects within the throttling window inherit the prior counter's accumulated budget.

### Proof of Concept
Integration test plan (extending existing `test_throttling_check_no_packet_drop`-style tests in `streamer/src/nonblocking/quic.rs` / `swqos.rs`):
1. Spin up a QUIC test server with `SwQos` and a known unstaked `max_streams_per_throttling_interval` (e.g. from `available_load_capacity_in_throttling_duration(Unstaked, ...)`).
2. From a single client IP, open a connection, send exactly the budget's worth of streams within one `STREAM_THROTTLING_INTERVAL`, and confirm the next stream is throttled (as in `test_throttling_check_no_packet_drop`).
3. Immediately close the connection (drop `client_connection`), then reconnect a new `quinn::Connection` from the same IP (different ephemeral port) before `STREAM_THROTTLING_INTERVAL_MS` has elapsed since the first burst started.
4. Send another full budget's worth of streams on the new connection immediately.
5. Assert that the second burst is *not* throttled (i.e., `stats.throttled_unstaked_streams` does not increase for the second burst), proving the counter was reset.
6. Repeat the reconnect-cycle N times within a fixed wall-clock window and measure total streams delivered; assert that the effective streams/sec exceeds `max_streams_per_throttling_interval / (STREAM_THROTTLING_INTERVAL_MS/1000)`, demonstrating the sustained-rate cap is bypassed.

    // Returns number of connections that were removed
    pub(crate) fn remove_connection(
        &mut self,
        key: ConnectionTableKey,
        port: u16,
        stable_id: usize,
    ) -> usize {
        if let Entry::Occupied(mut e) = self.table.entry(key) {
            let e_ref = e.get_mut();
            let old_size = e_ref.len();

            e_ref.retain(|connection_entry| {
                // Retain the connection entry if the port is different, or if the connection's
                // stable_id doesn't match the provided stable_id.
                // (Some unit tests do not fill in a valid connection in the table. To support that,
                // if the connection is none, the stable_id check is ignored. i.e. if the port matches,
                // the connection gets removed)
                connection_entry.port != port
                    || connection_entry
                        .connection
                        .as_ref()
                        .and_then(|connection| (connection.stable_id() != stable_id).then_some(0))
                        .is_some()
            });
            let new_size = e_ref.len();
            if e_ref.is_empty() {
                e.swap_remove_entry();
            }
            let connections_removed = old_size.saturating_sub(new_size);
            self.total_size = self.total_size.saturating_sub(connections_removed);
            connections_removed
        } else {
            0
        }
    }

pub(crate) async fn throttle_stream(
    stats: &StreamerStats,
    peer_type: ConnectionPeerType,
    remote_addr: std::net::SocketAddr,
    stream_counter: &Arc<ConnectionStreamCounter>,
    max_streams_per_throttling_interval: u64,
) {
    let throttle_interval_start = stream_counter.reset_throttling_params_if_needed();
    let streams_read_in_throttle_interval = stream_counter.stream_count.load(Ordering::Relaxed);
    if streams_read_in_throttle_interval >= max_streams_per_throttling_interval {
        // The peer is sending faster than we're willing to read. Sleep for what's
        // left of this read interval so the peer backs off.
        let throttle_duration =
            STREAM_THROTTLING_INTERVAL.saturating_sub(throttle_interval_start.elapsed());

        if !throttle_duration.is_zero() {
            debug!(
                "Throttling stream from {remote_addr:?}, peer type: {peer_type:?}, \
                 max_streams_per_interval: {max_streams_per_throttling_interval}, \
                 read_interval_streams: {streams_read_in_throttle_interval} throttle_duration: \
                 {throttle_duration:?}"
            );
            stats.throttled_streams.fetch_add(1, Ordering::Relaxed);
            match peer_type {
                ConnectionPeerType::Unstaked => {
                    stats
                        .throttled_unstaked_streams
                        .fetch_add(1, Ordering::Relaxed);
                }
                ConnectionPeerType::Staked(_) => {
                    stats
                        .throttled_staked_streams
                        .fetch_add(1, Ordering::Relaxed);
                }
            }
            sleep(throttle_duration).await;
        }
    }
}

impl ConnectionRateLimiter {
    /// Create a new rate limiter per IpAddr. The rate is specified as the count per minute to allow for
    /// less frequent connections. Higher limit also allows higher bursts.
    /// num_shards controls how many shards are used in the underlying dashmap,
    /// should be set >= number of contending threads.
    pub fn new(limit_per_minute: u64, max_burst: u64, num_shards: usize) -> Self {
        Self {
            limiter: KeyedRateLimiter::new(
                CONNECTION_RATE_LIMITER_CLEANUP_SIZE_THRESHOLD,
                TokenBucket::new(limit_per_minute, max_burst, limit_per_minute as f64 / 60.0),
                num_shards,
            ),
        }
    }

    /// Check if the connection from the said `ip` is allowed.
    /// Here we assume that only IPs with actual confirmed connections are stored in it,
    /// since we should only modify server state once source IP is verified
    pub fn is_allowed(&self, ip: &IpAddr) -> bool {
        // Check if we have records in the rate limiter for the given IP address
        match self.limiter.current_tokens(ip) {
            Some(r) => r > 0, // we have a record, and rate is not exceeded
            None => true,     // if we have not seen IP, allow connection request
        }
    }

    pub fn register_connection(&self, ip: &IpAddr) -> bool {
        if self.limiter.consume_tokens(*ip, 1).is_ok() {
            debug!("Request from IP {ip:?} allowed");
            true // Request allowed
        } else {
            debug!("Request from IP {ip:?} blocked");
            false // Request blocked
        }
    }
