## Title
Unauthenticated event-injection into stacks-signer's `SignerEventReceiver` HTTP listener — ([File: libsigner/src/events.rs])

### Summary
`SignerEventReceiver`, the HTTP server that the signer binds to receive events pushed by a Stacks node (`/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block`), never validates any authentication credential on incoming requests, even though the documented deployment model claims a shared secret (`auth_token` / `auth_password`) authenticates this channel.

### Finding Description
The signer's event listener is implemented in `SignerEventReceiver::next_event` [1](#0-0) . It dispatches purely on URL path (`/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block`, `/status`, `/shutdown`) and hands the request straight to `process_event`, which just reads the body and JSON-deserializes it into a `SignerEvent`: [2](#0-1) 

There is no check anywhere in `libsigner/src/events.rs` of an `Authorization` header, a shared secret, or the request's origin — confirmed by the absence of any `auth_token`/`auth_password`/`authorization` reference in `libsigner/`. Compare this to `docs/signing.md`, which documents that `auth_password` (signer config) and `[connection_options] auth_token` (node config) "must match" and states this is how the node/signer coordination is secured [3](#0-2) . The signer binds this listener on a configurable, potentially non-loopback endpoint (e.g., sample configs show `endpoint = "0.0.0.0:30000"` in `docs/signing.md`), and `stacks-signer/src/lib.rs` explicitly warns operators about exposure risk when communicating with external nodes [4](#0-3) , implying this endpoint is expected to be network-reachable in some deployments, yet no server-side authentication is implemented to back that warning up.

The equality broken here is: "event asserted to originate from the paired, trusted Stacks node" vs. "event actually accepted from any TCP client that can reach the listening socket." Any remote, unprivileged actor who can reach the signer's bound port can POST a forged `StackerDBChunksEvent`, `BlockValidateResponse`, `BurnBlockEvent`, or `StacksBlockEvent` payload and have it accepted and forwarded into the signer's runloop (`forward_event` → `main_loop`) exactly as if the paired node had sent it [5](#0-4) , [6](#0-5) .

### Impact Explanation
Injected/forged events feed directly into the signer's decision-making runloop as trusted node-originated input. While the signer's downstream cryptographic decision logic is out of scope for this analog, the transport-layer gap itself means the signer cannot distinguish node-originated stackerdb/block/burn-block events from attacker-crafted ones whenever the listener is reachable — undermining the entire documented "shared secret" trust model for this channel. This matches the "unauthenticated/unauthorized write to state" and "auth bypass" impact classes for a component that explicitly claims to be gated by a shared token.

### Likelihood Explanation
Exploitability depends entirely on network exposure: if the signer's endpoint is bound to a non-loopback address (which the sample configs and warning text anticipate as a real operational scenario), the endpoint accepts unauthenticated POSTs from any reachable client with no additional preconditions (no key, no valid signature, no session) — reachable with a single crafted HTTP request.

### Recommendation
Implement the documented `auth_token`/`auth_password` check inside `SignerEventReceiver` (e.g., verify an `Authorization` header against the configured secret in `next_event`/`process_event`) before accepting `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, and `/new_block` payloads, rejecting unauthenticated requests with 401, consistent with how `postblock_proposal.rs` and `blocksimulate.rs` gate their endpoints in `stackslib`.

### Proof of Concept
1. Configure a signer with `endpoint = "0.0.0.0:30000"` per the sample config.
2. From a separate, unprivileged host, send:
```
POST /stackerdb_chunks HTTP/1.1
Host: <signer-ip>:30000
Content-Type: application/json
Content-Length: <n>

{...forged StackerDBChunksEvent JSON...}
```
3. No `Authorization` header or token is required; `process_event` in `libsigner/src/events.rs` deserializes and forwards the event to the signer runloop as if it came from the legitimate node.

**Uncertainty note:** I could not verify (due to index limits) whether an authentication check might be implemented in a caller/wrapper outside `libsigner/` (e.g., inside `stacks-signer`) that filters requests before they reach `SignerEventReceiver`. My searches for `auth_token`/`auth_password`/`authorization` in `libsigner/` and in `stackslib/src/event_dispatcher.rs` returned no matches, suggesting no such check exists on either the client-dispatch or receiver side, but I recommend starting a full Devin session to grep the entire `stacks-signer` crate and confirm no auth middleware wraps this listener before treating this as fully confirmed.

    fn next_event(&mut self) -> Result<SignerEvent<T>, EventError> {
        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)
            } else if request.url() == "/new_block" {
                process_event::<T, StacksBlockEvent>(request)
            } else {
                let url = request.url().to_string();
                debug!(
                    "[{:?}] next_event got request with unexpected url {}, return OK so other side doesn't keep sending this",
                    event_receiver.local_addr,
                    url
                );
                ack_dispatcher(request);
                Err(EventError::UnrecognizedEvent(url))
            }
        })?

    /// Forward an event
    /// Return true on success; false on error.
    /// Returning false terminates the event receiver.
    fn forward_event(&mut self, ev: SignerEvent<T>) -> bool {
        if self.out_channels.is_empty() {
            // nothing to do
            error!("No channels connected to event receiver");
            false
        } else if self.out_channels.len() == 1 {
            // avoid a clone
            if let Err(e) = self.out_channels[0].send(ev) {
                error!("Failed to send to signer runloop: {:?}", &e);
                return false;
            }
            true
        } else {
            for (i, out_channel) in self.out_channels.iter().enumerate() {
                if let Err(e) = out_channel.send(ev.clone()) {
                    error!("Failed to send to signer runloop #{}: {:?}", i, &e);
                    return false;
                }
            }
            true
        }
    }

fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}

    fn main_loop<EVST: EventStopSignaler>(
        &mut self,
        event_recv: Receiver<SignerEvent<T>>,
        result_send: Sender<R>,
        mut event_stop_signaler: EVST,
    ) -> Option<R> {
        info!("Signer runloop begin");
        loop {
            let poll_timeout = self.get_event_timeout();
            let next_event_opt = match event_recv.recv_timeout(poll_timeout) {
                Ok(event) => Some(event),
                Err(RecvTimeoutError::Timeout) => None,
                Err(RecvTimeoutError::Disconnected) => {
                    info!("Event receiver disconnected");
                    return None;
                }
            };
            if let Some(final_state) = self.run_one_pass(next_event_opt, &result_send) {
                info!("Runloop exit; signaling event-receiver to stop");
                event_stop_signaler.send();
                return Some(final_state);
            }
        }
    }
