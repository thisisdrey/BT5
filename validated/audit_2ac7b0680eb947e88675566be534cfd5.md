### Title
Global QUIC connection-count gate (`ClientConnectionTracker::new`) is checked and enforced *before* per-table QoS eviction runs, letting idle unstaked connections exhaust `max_concurrent_connections()` headroom and starve new legitimate connections - (File: streamer/src/nonblocking/quic.rs)

### Summary
`ClientConnectionTracker::new` enforces a single global atomic counter (`stats.open_connections`) against `qos.max_concurrent_connections()` at accept time, strictly before the connection is handed to `QosController::try_add_connection`, which is the only place per-table pruning/eviction (`prune_oldest`, `prune_random`, `prune_unstaked_connection_table`) is invoked. An unstaked attacker that opens and holds many idle QUIC connections (never sending a stream) from a spread of distinct source IPs can occupy slots in the global counter without those connections ever being evicted, because eviction logic only runs when a *new* connection reaches `try_add_connection` for the same table — it is never triggered for other connections sitting in the global counter that never leave a per-IP/table cap.

### Finding Description
The accept loop performs, in order: per-IP rate limiting, overall rate limiting, then `ClientConnectionTracker::new(stats.clone(), qos.max_concurrent_connections())` [1](#0-0) . This call only compares a single global atomic (`stats.open_connections`) to `max_concurrent_connections()` and does not consult, nor trigger, any per-peer or per-table pruning logic [2](#0-1) . If the check fails, the connection is refused and `refused_connections_too_many_open_connections` is incremented [1](#0-0) .

The actual QoS-aware eviction (stake-based `prune_random` for staked connections, LRU-based `prune_oldest` via `prune_unstaked_connection_table` for unstaked connections) only executes inside `QosController::try_add_connection`, which is called later in `setup_connection` after handshake completion [3](#0-2) [4](#0-3) . Critically, this eviction is scoped to the table being inserted into for the *current* connection attempt — a connection whose slot in the global `open_connections` counter is occupied by an idle, already-admitted low-priority unstaked connection is never revisited or reaped just because a *different* new connection is trying to come in; eviction only fires when the same table's `try_add_connection` path is itself invoked. But `try_add_connection` is never even reached for the new connection if `ClientConnectionTracker::new` already failed the global gate, so idle attacker connections sitting comfortably under `max_unstaked_connections` (and therefore never subject to `prune_unstaked_connection_table`'s 90%-capacity trim) can persist indefinitely and consume global headroom that is shared across both staked and unstaked pools.

Because `ClientConnectionTracker` is only dropped (decrementing `open_connections`) when its owning `ConnectionEntry` is dropped — i.e., on table-level eviction, explicit close, or idle-timeout closure by the transport, none of which is triggered by the global-counter check itself — an attacker distributed across many source IPs (to stay under per-IP rate limits) can accumulate up to `max_concurrent_connections()` idle-but-admitted connections. New legitimate connections then fail the global check in `ClientConnectionTracker::new` and are refused via `refused_connections_too_many_open_connections`, without any chance for the existing per-table QoS eviction to run and free space, since that logic is gated behind a step (`try_add_connection`) the new connection never reaches.

### Impact Explanation
This is a QoS-evasion / bounded-ingress-buffer violation: legitimate TPU QUIC connection attempts (including from staked nodes, since the check is peer-type-agnostic) are refused purely due to global connection-count exhaustion by unprivileged, unstaked, idle connections, even though per-table stake-aware/LRU eviction exists specifically to prevent this outcome but is architecturally unreachable in this scenario. This matches the "QoS evasion" bounty category referenced in the prompt.

### Likelihood Explanation
Preconditions: attacker needs enough distinct source IPs to stay under per-IP (`rate_limiter`) and overall (`overall_connection_rate_limiter`) connection-attempt rate limits while establishing a slow, steady population of idle connections up to `max_unstaked_connections`/`max_concurrent_connections()` headroom. This is feasible for a modestly resourced attacker (cloud IP ranges, low-rate connection establishment) and is repeatable indefinitely as long as the idle connections are kept alive (e.g. via QUIC keep-alives) without ever opening a stream, since no stream-idle timeout applies to a connection with zero streams.

### Recommendation
Decouple or reorder the checks so that the global `max_concurrent_connections()` admission gate itself triggers (or is preceded by) table-level pruning of low-priority/idle connections — e.g., attempt `prune_oldest`/`prune_random` against the unstaked/staked tables when the global counter is saturated, before refusing the new connection in `ClientConnectionTracker::new`/the accept loop. Alternatively, enforce a hard idle-connection timeout (no streams opened within N seconds) that forcibly closes and evicts connections independent of the peer-scoped table logic.

impl ClientConnectionTracker {
    /// Check the max_concurrent_connections limit and if it is within the limit
    /// create ClientConnectionTracker and increment open connection count. Otherwise returns Err
    fn new(stats: Arc<StreamerStats>, max_concurrent_connections: usize) -> Result<Self, ()> {
        let open_connections = stats.open_connections.fetch_add(1, Ordering::Relaxed);
        if open_connections >= max_concurrent_connections {
            stats.open_connections.fetch_sub(1, Ordering::Relaxed);
            debug!(
                "There are too many concurrent connections opened already: open: \
                 {open_connections}, max: {max_concurrent_connections}"
            );
            return Err(());
        }

        Ok(Self { stats })
    }
}

    fn prune_unstaked_connection_table(

        unstaked_connection_table: &mut ConnectionTable<ConnectionStreamCounter>,
        max_unstaked_connections: usize,

        if unstaked_connection_table.total_size >= max_unstaked_connections {
