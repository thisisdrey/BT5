Audit Report

## Title
Staking-async marks reward pages as claimed before verifying the transfer succeeded, permanently losing rewards on transfer failure - (File: `substrate/frame/staking-async/src/pallet/impls.rs`)

## Summary
`Pallet::do_payout_stakers_by_page` calls `Eras::<T>::set_rewards_as_claimed(era, &stash, page)` before any reward transfer is attempted, and the downstream `payout_from_provider` → `make_payout_from_provider` path swallows `Currency::transfer` failures by logging and returning `None` instead of propagating a `DispatchError`. Since the claim flag is already persisted and the extrinsic still returns `Ok(...)`, a failed transfer (e.g. an ED-related failure for a small prorated nominator reward sent to a fresh account) results in silent, permanent, unretriable loss of that staker's reward for the era/page.

## Finding Description
In `do_payout_stakers_by_page`, the claim check and claim-setting occur immediately, well before the payout computation and transfer: [1](#0-0) 

The dispatch then proceeds to compute the payout split and invoke either the transfer-based or legacy mint-based payout path: [2](#0-1) 

`payout_from_provider` iterates the validator and every nominator in the page, calling `make_payout_from_provider` for each and only reacting to a `Some` result (emitting `Rewarded` / incrementing the payout counter); a `None` is silently skipped with no error surfaced: [3](#0-2) 

`make_payout_from_provider` performs the actual `T::Currency::transfer` from the era's `StakerRewards` pot to the payee. On error (e.g., destination account absent and reward below `ExistentialDeposit`, or the pot's reducible balance insufficient) it only logs and returns `None`, never propagating the error: [4](#0-3) 

Because `set_rewards_as_claimed` was already persisted for the whole page before any transfer was attempted, any retry of `payout_stakers`/`payout_stakers_by_page` for that era/page is rejected by the same `is_rewards_claimed` guard used at line 381-384, with no other code path to reconcile or re-drive the missed payout. This confirms the claimed sequence: settlement state (claim flag) advances despite the underlying value-moving operation (transfer) not succeeding, violating the requirement that payout state should only advance after settlement succeeds.

This is distinct from the legacy mint-based path (`payout_legacy_mint`, using `T::Reward::on_unbalanced`), which mints value and therefore cannot fail in the same way; the transfer-based `payout_from_provider` path introduced for staking-async is the one exposed to this failure mode.

## Impact Explanation
Any nominator or validator whose prorated reward transfer fails for a given era/page loses that reward permanently: the page's claim flag is already set, so no subsequent call to `payout_stakers_by_page` can re-attempt payment for that stash/era/page (`Error::AlreadyClaimed`), and there is no separate storage item tracking the shortfall for later reconciliation. This is a direct violation of the "rewards must conserve value and settle exactly once to the rightful beneficiary" invariant — here the reward is silently dropped, settling zero times instead of once, with the extrinsic returning `Ok(...)` to the caller with no on-chain signal of the failure.

## Likelihood Explanation
The bug is reachable through the ordinary, permissionless `payout_stakers`/`payout_stakers_by_page` extrinsics, callable by any signed account for any validator/era/page — no privileged access or malicious actor is required. The triggering condition (a nominator's prorated reward below `ExistentialDeposit` when the destination `RewardDestination::Account` has no existing balance, which is realistic for validators with many small nominators up to `MaxExposurePageSize`) is a naturally occurring scenario rather than a contrived edge case, making the issue a persistent, repeatable risk in normal reward-payout activity rather than a one-off.

## Recommendation
Defer persisting `set_rewards_as_claimed` until after all transfers in `payout_from_provider` have been attempted and their outcomes are known. Either make the whole page's payout atomic (roll back the claim flag, and ideally the whole page, if any transfer fails so it can be retried), or introduce a durable, retryable record (dedicated storage/event) of per-account failed payouts that keeps the page claimable/reconcilable for the affected stash, rather than marking the entire page permanently claimed while transfers silently fail inside `make_payout_from_provider`.

## Proof of Concept
1. Configure a validator `V` with nominators such that at least one nominator `N`'s prorated `nominator_reward` for a page is below `ExistentialDeposit`, with `N`'s reward-destination account (`RewardDestination::Account`) not yet holding any balance.
2. Fund the era's `StakerRewards` pot normally.
3. Call `Staking::payout_stakers_by_page(origin, V, era, page)`; observe `Eras::<T>::set_rewards_as_claimed(era, &V, page)` executes at `impls.rs:386` and the extrinsic returns `Ok(...)`.
4. Inside `payout_from_provider`/`make_payout_from_provider`, the `T::Currency::transfer` to `N` fails (ED-related), is only logged (`impls.rs:602-616`), and `Rewarded` is not emitted for `N`; the call returns without error.
5. Re-invoke `payout_stakers_by_page(origin, V, era, page)`; it returns `Error::<T>::AlreadyClaimed`, confirming `N`'s reward is permanently lost with no retry path.

	/// Payout stakers from an era reward pot (transfer-based, no minting).
	fn payout_from_provider(
		era: EraIndex,
		stash: &T::AccountId,
		validator_payout: BalanceOf<T>,
		exposure: &crate::PagedExposure<T::AccountId, BalanceOf<T>>,
		overview_own: BalanceOf<T>,
		total_nominator_payout: BalanceOf<T>,
	) -> u32 {
		let mut nominator_payout_count: u32 = 0;

		if let Some((amount, dest)) = Self::make_payout_from_provider(era, stash, validator_payout)
		{
			Self::deposit_event(Event::<T>::Rewarded { stash: stash.clone(), dest, amount });
		}

		let total_nominator_stake = exposure.total().saturating_sub(overview_own);
		for nominator in exposure.others().iter() {
			let nominator_exposure_part =
				Perbill::from_rational(nominator.value, total_nominator_stake);
			let nominator_reward: BalanceOf<T> =
				nominator_exposure_part.mul_floor(total_nominator_payout);

			if let Some((amount, dest)) =
				Self::make_payout_from_provider(era, &nominator.who, nominator_reward)
			{
				nominator_payout_count.saturating_inc();
				Self::deposit_event(Event::<T>::Rewarded {
					stash: nominator.who.clone(),
					dest,
					amount,
				});
			}
		}

		nominator_payout_count
	}

	/// Make a payment to a staker from an era reward pot (transfer, not mint).
	fn make_payout_from_provider(
		era: EraIndex,
		stash: &T::AccountId,
		amount: BalanceOf<T>,
	) -> Option<(BalanceOf<T>, RewardDestination<T::AccountId>)> {
		if amount.is_zero() {
			return None;
		}

		let dest = match Self::payee(Stash(stash.clone())) {
			Some(d) => d,
			None => {
				Self::deposit_event(Event::<T>::Unexpected(UnexpectedKind::MissingPayee {
					era,
					stash: stash.clone(),
				}));
				return None;
			},
		};

		let payout_account = Self::payout_account_for_dest(stash, &dest)?;

		let staker_rewards_pot =
			T::RewardPots::pot_account(RewardPot::Era(era, RewardKind::StakerRewards));
		if let Err(e) = T::Currency::transfer(
			&staker_rewards_pot,
			&payout_account,
			amount,
			Preservation::Expendable,
		) {
			log!(
				error,
				"Failed to transfer reward from pot for era {:?}, stash {:?}: {:?}",
				era,
				stash,
				e
			);
			return None;
		}
