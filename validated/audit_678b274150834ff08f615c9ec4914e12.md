### Title
Stake-derived QoS permission is fixed at connection accept-time and never re-validated or revoked for the life of the connection - (File: streamer/src/nonblocking/swqos.rs)

### Summary
The stake-weighted QoS (`SwQos`) and simple QoS (`SimpleQos`) controllers determine a connection's `peer_type`/`total_stake` "approval" exactly once, in `build_connection_context()`, at connection accept-time. That `ConnectionContext` (`SwQosConnectionContext` / `SimpleQosConnectionContext`) is then cached and reused for the entire lifetime of the QUIC connection to decide concurrent-stream limits, per-peer connection limits, and stream-throttling budgets. There is no mechanism to re-check or revoke this stake-derived permission if the peer's underlying stake changes (decreases, is unstaked, or drops to zero) while the connection remains open. This mirrors the Visor `approveTransferERC721()` pattern: a permission is granted once and is never revoked/re-validated later, so it continues to be exploitable after the condition that justified it is gone.

### Finding Description
`get_connection_stake()` reads the current `StakedNodes` snapshot to determine a peer's stake, and this call happens only inside `build_connection_context()`, which itself is only invoked once when a new incoming connection is accepted [1](#0-0) . The resulting `peer_type` and `total_stake` fields are stored in `SwQosConnectionContext`/`SimpleQosConnectionContext`, which are `Clone` value structs carried alongside the connection for its whole life [2](#0-1) [3](#0-2) .

Every later QoS decision for that connection re-uses these cached, stale values instead of re-deriving them from the live `staked_nodes` table:
- `on_new_stream()` computes `max_streams_per_throttling_interval` purely from `context.peer_type` / `context.total_stake` [4](#0-3) [5](#0-4) .
- `cache_new_connection()` sets `max_concurrent_uni_streams` and per-peer connection limits from the same cached `peer_type` [6](#0-5) .

Meanwhile, the actual source of truth (`StakedNodes`) is refreshed independently on a background timer every `STAKE_REFRESH_CYCLE` (5 seconds) by `StakedNodesUpdaterService` [7](#0-6) , and `get_connection_stake()` itself always reads the live table [8](#0-7) . This means the check-then-use pattern is only performed once (at connect time); no code path repeats `get_connection_stake()` for an already-established connection to demote it back to `Unstaked` treatment. The only revocation mechanism present is the `SimpleQosBanlist`, which is an explicit, separate ban/eviction feature and only handles the "banned pubkey" case, not the "stake dropped to zero/decreased" case — there is no analogous eviction hook tied to stake decreases for `SwQos`, and even the ban path only exists in the `SimpleQos` controller.

Because QUIC connections use a 30-second idle timeout with keep-alives (`QUIC_MAX_TIMEOUT`) [9](#0-8) , a peer can keep a connection alive indefinitely by sending periodic traffic, and it will continue to receive whatever `peer_type`/`total_stake`-derived treatment it was granted at the original handshake — regardless of subsequent stake changes.

### Impact Explanation
An attacker who briefly holds (or is delegated) a large stake, opens a QUIC TPU connection while staked, and then has that stake reduced/removed (deactivated, undelegated, or naturally decayed) can keep the already-approved connection alive via keep-alives and continue enjoying the elevated staked-tier QoS treatment — higher `max_concurrent_uni_streams`, higher `max_connections_per_staked_peer`, and a larger `max_streams_per_throttling_interval` share of the stream-throttling budget — that unstaked or lower-staked peers are not entitled to. This is a QoS evasion: the validator's stake-weighted admission control, whose entire purpose is to prioritize genuinely staked traffic and rate-limit everyone else, can be permanently bypassed for the life of one long-lived connection, letting an effectively-unstaked/low-stake sender consume disproportionate stream/connection quota that should have been reserved for currently-staked validators. This degrades TPU packet ingestion fairness and can be used to starve legitimately staked senders of stream capacity.

### Likelihood Explanation
This requires only unprivileged network access (any peer able to open a QUIC connection to the TPU port) and no validator/operator role — a normal user with a keypair that briefly has stake can trigger it. It is straightforward to reproduce deterministically: establish a connection while staked, then have the stake change (e.g., wait for an epoch stake update, or manipulate a delegated stake account), and observe that the connection's admitted `peer_type`/limits are unchanged because `build_connection_context()` is never called again for an existing connection. The main constraint is that acquiring stake to exploit this has some cost, but the exploit does not require sustained stake — only stake at the moment of connection establishment — after which the elevated treatment persists for as long as the connection is kept alive.

### Recommendation
Periodically re-validate a connection's `peer_type`/stake against the live `staked_nodes` table (e.g., on each `on_new_stream`/`on_stream_finished` callback, or via a background sweep similar to the existing `SimpleQosBanlist` evictor) and demote/evict connections whose backing stake has dropped, rather than caching the stake-derived permission for the entire connection lifetime. Extend the eviction mechanism used for banned pubkeys in `SimpleQos` to also cover stake-decrease/zero-stake cases, and add an equivalent mechanism for `SwQos`, so that admitted staked-tier treatment is revoked (not merely granted once) when the underlying justification disappears.

### Proof of Concept
1. Client `C` acquires stake `S` sufficient to pass the `min_stake_ratio` check in `SwQos::build_connection_context()` [10](#0-9) .
2. `C` opens a QUIC connection to the validator's TPU; `try_add_connection()` admits it into the staked connection table and grants elevated `max_concurrent_uni_streams`/throttling budget based on `conn_context.peer_type = Staked(S)` [11](#0-10) .
3. `C`'s stake `S` is subsequently undelegated/deactivated so that `StakedNodesUpdaterService` refreshes `staked_nodes` to reflect zero/near-zero stake for `C`'s pubkey within the next `STAKE_REFRESH_CYCLE` (5s) [7](#0-6) .
4. `C` keeps the original QUIC connection alive using QUIC keep-alives/idle traffic (under the 30s `QUIC_MAX_TIMEOUT`) without reconnecting.
5. `C` continues to open new streams on the same connection; `on_new_stream()` still uses the original cached `SwQosConnectionContext.peer_type = Staked(S)` and `total_stake` to compute `max_streams_per_throttling_interval`, granting `C` the same elevated stream budget as before, even though `C` is now effectively unstaked [4](#0-3) .
6. No code path re-invokes `get_connection_stake()`/`build_connection_context()` for this already-open connection, so the elevated permission is never revoked for the connection's remaining lifetime.

impl QosController<SwQosConnectionContext> for SwQos {
    fn build_connection_context(&self, connection: &Connection) -> SwQosConnectionContext {
        let remote_address = connection.remote_address();
        get_connection_stake(connection, &self.staked_nodes).map_or(
            SwQosConnectionContext {
                peer_type: ConnectionPeerType::Unstaked,
                total_stake: 0,
                remote_pubkey: None,
                in_staked_table: false,
                remote_address,
                stream_counter: None,
                last_update: Arc::new(AtomicU64::new(timing::timestamp())),
            },
            |(pubkey, stake, total_stake)| {
                // The heuristic is that the stake should be large enough to have 1 stream pass through within one throttle
                // interval during which we allow max (MAX_STREAMS_PER_MS * STREAM_THROTTLING_INTERVAL_MS) streams.

                let peer_type = {
                    let max_streams_per_ms = self.staked_stream_load_ema.max_streams_per_ms();
                    let min_stake_ratio =
                        1_f64 / (max_streams_per_ms * STREAM_THROTTLING_INTERVAL_MS) as f64;
                    let stake_ratio = stake as f64 / total_stake as f64;
                    if stake_ratio < min_stake_ratio {
                        // If it is a staked connection with ultra low stake ratio, treat it as unstaked.
                        ConnectionPeerType::Unstaked
                    } else {
                        ConnectionPeerType::Staked(stake)
                    }
                };

                SwQosConnectionContext {
                    peer_type,
                    total_stake,
                    remote_pubkey: Some(pubkey),
                    in_staked_table: false,
                    remote_address,
                    last_update: Arc::new(AtomicU64::new(timing::timestamp())),
                    stream_counter: None,
                }
            },
        )
    }

pub struct StakedNodesUpdaterService {

impl StakedNodesUpdaterService {
    pub fn new(
        exit: Arc<AtomicBool>,
        bank_forks: Arc<RwLock<BankForks>>,
        staked_nodes: Arc<RwLock<StakedNodes>>,
        staked_nodes_overrides: Arc<RwLock<HashMap<Pubkey, u64>>>,

        let thread_hdl = Builder::new()
            .name("solStakedNodeUd".to_string())
            .spawn(move || {
                while !exit.load(Ordering::Relaxed) {
                    let stakes = {
                        let root_bank = bank_forks.read().unwrap().root_bank();
                        root_bank.current_epoch_staked_nodes()
                    };
                    let overrides = staked_nodes_overrides.read().unwrap().clone();
                    *staked_nodes.write().unwrap() = StakedNodes::new(stakes, overrides);
                    std::thread::sleep(STAKE_REFRESH_CYCLE);
                }
            })
            .unwrap();
