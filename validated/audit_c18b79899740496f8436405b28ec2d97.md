### Title
`go` command logs plaintext Git credentials to console when GOAUTH=git fails under `-x` - ([File: src/cmd/go/internal/auth/gitauth.go])

### Summary
`runGitAuth` in `src/cmd/go/internal/auth/gitauth.go` wraps the raw, unredacted stdout/stderr of `git credential fill` (`out`) directly into the returned error whenever the command exits non‑zero or the response fails to parse into a matching URL prefix. `runGoAuth` in `src/cmd/go/internal/auth/auth.go` collects these errors and, when `cfg.BuildX` (`go build/get -x`) is set, prints them verbatim via `log.Printf` to the console. Because `git credential fill` output includes a `password=<secret>` line, any failure in that flow (malformed helper response, mismatched URL prefix, or non-zero exit) results in the plaintext password being written to the terminal/log.

### Finding Description
Attacker/trigger path: a module-fetching victim runs `go get -x` (or any subcommand with `-x`) with `GOAUTH=git <dir>` configured and requests a module hosted at a private HTTPS URL for which a git credential helper is configured. Entry point: `AddCredentials` (`src/cmd/go/internal/auth/auth.go:32`) → `runGoAuth` (`auth.go:53`) → `runGitAuth` (`gitauth.go:33`). Inside `runGitAuth`:
- `cmd.CombinedOutput()` captures git credential helper output containing `password=<secret>` (`gitauth.go:48`).
- On non-zero exit: `return "", nil, fmt.Errorf("'git credential fill' failed (url=%s): %w\n%s", url, err, out)` embeds the raw `out` (with the password line) into the error (`gitauth.go:50`).
- Even on success, if `parseGitAuth` fails to reconstruct a prefix or the parsed prefix isn't a prefix of the requested `url` (e.g., a credential helper returning an unexpected/malformed response), the error path is taken without printing `out`, but the mismatch-prefix case at `gitauth.go:57-59` also doesn't include `out`; the primary sink is the non-zero-exit branch at line 50.

That error flows back to `runGoAuth`, which appends it to `cmdErrs` (`auth.go:112`) and, gated only by `cfg.BuildX && url != ""` and lack of a cached credential (`auth.go:131-138`), calls `log.Printf("GOAUTH encountered errors for %s:", url)` followed by `log.Printf("  %v", err)` for each error — printing the embedded password to standard error. The check that fails to redact is the absence of any scrubbing of `out` before it's folded into the error string; unlike `net/url.URL.Redacted()` (`src/net/url/url.go:886`) and `http.Client`'s `stripPassword` (`src/net/http/client.go:1058`), which the Go stdlib uses elsewhere specifically to avoid this class of leak, `gitauth.go` has no equivalent redaction for the git-credential-helper transcript.

### Impact Explanation
This discloses a git-hosting credential in plaintext to the console/build log, which is a secret-disclosure issue matching the CVE-2026-25813 bug class (sensitive data written to logs unredacted). Exposure is conditioned on `-x`/build tracing and a git-credential-helper failure or malformed response, which limits but does not eliminate real-world exposure (build logs from CI systems using `-x` for debugging are a plausible victim workflow). This would likely be assessed on Go's **PUBLIC** track as a low-severity info-disclosure hardening issue rather than urgent, since it requires opt-in `-x` tracing plus a failing/misconfigured credential helper.

### Likelihood Explanation
Victim workflow: a developer or CI pipeline using `GOAUTH=git <dir>` for private module fetching, invoking `go get -x` or another `-x`-traced `go` command for debugging, where the credential helper occasionally errors (wrong protocol, expired session, mistyped `url=` line) or returns a URL that doesn't prefix-match the request. No attacker control of the server is required — this is triggered by the victim's own legitimate credential-helper interaction failing, and the leaked data lands wherever `-x` output is captured (terminal scrollback, CI logs, bug reports).

### Recommendation
Before embedding `out` into the error in `runGitAuth` (`gitauth.go:50`), redact any `password=` line (e.g., replace the value with `password=xxxxx` similar to `url.URL.Redacted()`), or omit `out` from the error entirely and instead return a generic message, logging only non-sensitive diagnostic fields (protocol/host/username) if needed for debugging.
