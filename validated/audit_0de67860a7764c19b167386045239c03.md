Based on my investigation, I found the strongest concrete analog in `beginHandshake`/`CheckAndComplete`, where an attacker with **no CA-signed certificate** can trigger real state effects before any certificate validation occurs.

### Title
Unauthenticated attacker can trigger costly Noise handshake processing and cert verification with a forged/garbage stage-1 packet before any CA validation, at zero cost to themselves - (File: handshake_manager.go)

### Summary
`HandshakeManager.HandleIncoming` routes any inbound UDP packet whose header parses as a stage-1 handshake (`h.MessageCounter == 1`, `h.RemoteIndex == 0`) directly into `beginHandshake`, which constructs a new responder `handshake.Machine` and calls `machine.ProcessPacket` *before* any certificate belonging to the sender has been validated against the CA pool. [1](#0-0) 

### Finding Description
The only pre-checks applied to an unauthenticated stage-1 packet are the handshake subtype gate and the `remote_allow_list.AllowUnknownVpnAddr` check (an IP allow-list, not identity-based) before `beginHandshake` is invoked. `beginHandshake` then runs the full Noise `ProcessPacket` (DH operations, decryption, and only afterward the embedded certificate is checked against the CA pool via `hm.certVerifier()` / `CAPool.VerifyCertificate`). [2](#0-1) [3](#0-2) [4](#0-3) 

Because no proof-of-possession of a valid CA-signed certificate is required to reach this expensive cryptographic path, an attacker outside the mesh (holding no certificate at all) can send a stream of crafted stage-1 packets and force every listening node to perform Diffie-Hellman and AEAD decrypt operations on each one. This is directly analogous to the reported `Vepoch.sol` pattern: a party with no legitimate stake in the system (no CA cert, no deposit) can cheaply force expensive/undesirable state changes on the target that specifically harm the *service quality experienced by legitimate peers*, at a cost asymmetry (attacker pays only bandwidth+minimal CPU; victim pays real handshake CPU, and — since responder-side pending state is index-scoped rather than IP-scoped, see `allocateIndex`/`CheckAndComplete` — resources are consumed generically rather than being isolated per legitimate sender). [5](#0-4) [6](#0-5) 

### Impact Explanation
A remote crash/resource-exhaustion impact is plausible: sustained bogus stage-1 traffic forces CPU-bound Noise processing and CA-pool signature verification (`VerifyCertificate`/`CheckSignature`) on every node exposed to the internet, degrading handshake responsiveness for legitimate peers — the direct networking analog of "reducing other users' rewards without any penalty to the attacker," since real peers experience delayed/failed handshakes while the attacker incurs only the cost of sending small UDP packets.

### Likelihood Explanation
Likelihood is moderate: this requires no CA-signed certificate, no prior trust relationship, and no privileged network position — only the ability to send UDP packets to a node's listen port, which is the baseline threat model for any internet-facing Nebula lighthouse or node. However, the actual asymmetry is bounded by Noise's cheap early rejection of malformed DH material and by the fact that a full computationally expensive cert-signature check only occurs once a syntactically valid Noise message decrypts, which limits amplification compared to, e.g., unauthenticated ASN.1 parsing bugs.

### Recommendation
Consider adding a cheap, pre-Noise proof-of-work-like or rate-limiting gate keyed by source address before invoking `beginHandshake`/`machine.ProcessPacket`, and/or cap concurrent pending (unauthenticated) handshake `Machine` allocations per source address so an unauthenticated flood cannot consume unbounded CPU/index-allocation resources intended for legitimate peers.

### Proof of Concept
1. From a host with no CA-issued certificate, craft a UDP packet with a valid Nebula header (`header.Handshake`, `header.HandshakeIXPSK0` subtype, `MessageCounter == 1`, `RemoteIndex == 0`) and arbitrary/garbage Noise payload bytes sized to pass initial parsing.
2. Send a continuous stream of such packets to a target node's listen port.
3. Observe that each packet reaches `beginHandshake` → `machine.ProcessPacket`, consuming CPU for DH/AEAD attempts and (for packets that pass Noise framing) triggering `certVerifier()`/`CAPool.VerifyCertificate` calls, all prior to any check that the sender holds a certificate signed by the network's actual CA. [7](#0-6)

Note: This analog is speculative extrapolation from a smart-contract reward-griefing report onto an unrelated Go networking codebase, and I want to be direct about that. The `Vepoch.sol` report describes a very specific economic griefing pattern (front-run a reward-distribution call, deposit, then withdraw without penalty) that has no structural equivalent in Nebula — there is no "reward pool," "deposit," or "forfeit" concept here. The finding above is the closest reachable-by-unauthenticated-attacker pattern I could substantiate with actual code (pre-CA-validation costly work), but it is a much weaker and more generic "unauthenticated resource consumption" finding, not a direct analog of the reported economic exploit. I'd treat this with skepticism rather than as a confirmed, high-confidence vulnerability.

func (hm *HandshakeManager) CheckAndComplete(hostinfo *HostInfo, handshakePacket uint8, f *Interface) (*HostInfo, error) {
	hm.mainHostMap.Lock()
	defer hm.mainHostMap.Unlock()
	hm.Lock()
	defer hm.Unlock()

	// Check if we already have a tunnel with this vpn ip
	existingHostInfo, found := hm.mainHostMap.Hosts[hostinfo.vpnAddrs[0]]
	if found && existingHostInfo != nil {
		// Is it just a delayed handshake packet? Check every hostinfo we hold for this address.
		for _, testHostInfo := range hm.mainHostMap.unlockedGetHostList(hostinfo.vpnAddrs[0]) {
			if bytes.Equal(hostinfo.HandshakePacket[handshakePacket], testHostInfo.HandshakePacket[handshakePacket]) {
				return testHostInfo, ErrAlreadySeen
			}
		}

		// Is this a newer handshake?
		if existingHostInfo.lastHandshakeTime >= hostinfo.lastHandshakeTime && !existingHostInfo.ConnectionState.initiator {
			return existingHostInfo, ErrExistingHostInfo
		}

		existingHostInfo.logger(hm.l).Info("Taking new handshake")
	}

	existingIndex, found := hm.mainHostMap.Indexes[hostinfo.localIndexId]
	if found {
		// We have a collision, but for a different hostinfo
		return existingIndex, ErrLocalIndexCollision
	}

	existingPendingIndex, found := hm.indexes[hostinfo.localIndexId]
	if found && existingPendingIndex.hostinfo != hostinfo {
		// We have a collision, but for a different hostinfo
		return existingPendingIndex.hostinfo, ErrLocalIndexCollision
	}

	existingRemoteIndex, found := hm.mainHostMap.RemoteIndexes[hostinfo.remoteIndexId]
	if found && existingRemoteIndex != nil && existingRemoteIndex.vpnAddrs[0] != hostinfo.vpnAddrs[0] {
		// We have a collision, but this can happen since we can't control
		// the remote ID. Just log about the situation as a note.
		hostinfo.logger(hm.l).Info("New host shadows existing host remoteIndex",
			"collision", existingRemoteIndex.vpnAddrs,
		)
	}

	hm.mainHostMap.unlockedAddHostInfo(hostinfo, f)
	return existingHostInfo, nil
}

func (hm *HandshakeManager) allocateIndex(hh *HandshakeHostInfo) (uint32, error) {
	hm.mainHostMap.RLock()
	defer hm.mainHostMap.RUnlock()
	hm.Lock()
	defer hm.Unlock()

	for range 32 {
		index, err := generateIndex(hm.l)
		if err != nil {
			return 0, err
		}

		_, inPending := hm.indexes[index]
		_, inMain := hm.mainHostMap.Indexes[index]

		if !inMain && !inPending {
			hh.hostinfo.localIndexId = index
			hm.indexes[index] = hh
			return index, nil
		}
	}

	return 0, errors.New("failed to generate unique localIndexId")
}

func (hm *HandshakeManager) beginHandshake(via ViaSender, packet []byte, h *header.H) {
	f := hm.f
	cs := f.pki.getCertState()

	v := cs.DefaultVersion()
	if cs.GetCredential(v) == nil {
		f.l.Error("Unable to handshake with host because no certificate is available",
			"from", via, "certVersion", v)
		return
	}

	machine, err := handshake.NewMachine(
		v, cs.GetCredential,
		hm.certVerifier(), func() (uint32, error) { return generateIndex(f.l) },
		false, header.HandshakeIXPSK0,
	)
	if err != nil {
		f.l.Error("Failed to create handshake machine", "from", via, "error", err)
		return
	}

	response, result, err := machine.ProcessPacket(nil, packet)
	if err != nil {
		f.l.Error("Failed to process handshake packet", "from", via, "error", err)
		return
	}

func (hm *HandshakeManager) certVerifier() handshake.CertVerifier {
	return func(c cert.Certificate) (*cert.CachedCertificate, error) {
		return hm.f.pki.GetCAPool().VerifyCertificate(time.Now(), c)
	}
