### Title
Incomplete signature deduplication in `ValidateMultiSign` precompile allows a single key's weight to be counted multiple times, bypassing multi-sig thresholds - (File: `actuator/src/main/java/org/tron/core/vm/PrecompiledContracts.java`)

### Summary
The `ValidateMultiSign` TVM precompiled contract (address `0x...0a`) verifies a set of signatures against an account `Permission` and sums up the weight of each recovered signer to compare against the permission threshold. The deduplication logic only rejects a signature if the *exact byte-identical* signature for an already-seen address is resubmitted; if the same address recovers from a second, differently-encoded but still valid signature over the same hash, its weight is added again. This lets a caller satisfy a multi-signature threshold using fewer distinct authorized keys than the permission actually requires.

### Finding Description
`ValidateMultiSign.execute()` [1](#0-0)  iterates over caller-supplied signatures, recovers an address for each via `recoverAddrBySign`, and accumulates `totalWeight` from `TransactionCapsule.getWeight(permission, recoveredAddr)`. The dedup check is:

```java
byte[] recoveredAddr = recoverAddrBySign(sign, hash);
sign = merge(recoveredAddr, sign);
if (ByteArray.matrixContains(executedSignList, recoveredAddr)) {
  if (ByteArray.matrixContains(executedSignList, sign)) {
    continue;
  }
  MUtil.checkCPUTime();
}
long weight = TransactionCapsule.getWeight(permission, recoveredAddr);
...
totalWeight += weight;
executedSignList.add(sign);
executedSignList.add(recoveredAddr);
``` [2](#0-1) 

The only case that is skipped (`continue`) is when the *combined* `address+rawSignatureBytes` blob has been seen verbatim before. If `recoveredAddr` has already been counted but this particular signature's raw bytes differ (e.g., produced via ECDSA signature malleability by flipping `s` to `n-s`, or any other encoding that still recovers to the same public key/address for the given `hash`), the code falls through and adds `weight` to `totalWeight` again for the same address. There is no check keyed purely on `recoveredAddr` to prevent re-counting.

This differs from the intended semantic implied by the comment/limit logic (`MAX_SIZE` cap on the number of *distinct* signers) — the actuator never actually enforces "one signature per address," only "one exact signature blob per address."

### Impact Explanation
An account can configure an `Active` permission requiring multiple distinct authorized keys to reach a signing threshold (e.g., a 2-of-3 multisig wallet or contract-controlled treasury). Via this precompile, a smart contract could accept a `data` blob containing two (or more) signatures that all recover to the *same single* authorized address, but are byte-for-byte different (malleated). Because the loop only dedupes on the literal signature bytes rather than the recovered address, `totalWeight` will exceed the account's threshold using only one real private key, and the contract will treat the multi-sig check as passed (`dataOne()`) [3](#0-2) . Any TVM contract that gates an unauthorized account operation (fund transfer, permission update, withdrawal approval) on `ValidateMultiSign` returning success can be tricked into approving an operation that should have required cooperation of multiple key holders, resulting in unauthorized account operation / theft of funds — directly mirroring the Aztec Connect incident's "incomplete proof/verification logic" root cause (checks that look complete but fail to bind uniqueness to the right identity, allowing an attacker to satisfy verification with less than the intended cryptographic material).

### Likelihood Explanation
The precompile is reachable by any TVM contract deployer/caller — no privileged role is required, matching the "unprivileged transaction broadcaster / contract deployer" reachability requirement. Exploitation additionally requires the ability to produce two distinct, valid signature encodings that recover to the same address for a given hash (classical ECDSA malleability via `s -> n-s`, or alternate DER/compact encodings depending on how `recoverAddrBySign` parses `v/r/s`). Whether the underlying `ECKey`/`SignUtils` signature-recovery path enforces canonical low-`s` values could not be fully confirmed from the code explored, so exploitability specifically hinges on that verification detail; this is a caveat on likelihood that should be validated against `crypto/src/main/java/org/tron/common/crypto/ECKey.java` and `SignUtils.java`. If canonical-`s` is not enforced at the recovery step used inside this precompile, the bug is directly and trivially exploitable by any contract caller.

### Recommendation
Change the dedup key from `address+rawSignatureBytes` to `address` alone: once an address's weight has been added to `totalWeight`, skip all further signatures that recover to that same address, regardless of the specific signature bytes supplied. This restores the intended one-signature-per-signer semantics for the multisig threshold check.

### Proof of Concept
Conceptual PoC (requires confirming malleable/duplicate valid encodings recover to the same address in the local `recoverAddrBySign`/ECKey implementation):
1. Configure an account with an `Active` permission requiring 2 distinct keys (threshold = sum of two keys' weights) among 3 authorized addresses.
2. Sign the `hash` (built from `address|permissionId|data`, see `PrecompiledContracts.java:1062-1064`) with only key A, producing signature `sigA`.
3. Derive a second, differently-encoded but still-valid signature `sigA'` from the same key A over the same `hash` (e.g., malleated `s' = n - s`, or a re-encoded `v` variant), such that `recoverAddrBySign(sigA', hash)` still equals address A.
4. Call `ValidateMultiSign(address, permissionId, data, [sigA, sigA'])`.
5. Observe that `totalWeight` accumulates key A's weight twice (since `sigA != sigA'` as raw bytes, the inner `matrixContains(executedSignList, sign)` check fails and weight is re-added), reaching the 2-key threshold using a single real private key, and the call returns `dataOne()` (success).   public static class ValidateMultiSign extends PrecompiledContract {

    private static final int ENGERYPERSIGN = 1500;
    private static final int MAX_SIZE = 5;
    private static final int ABI_HEADER_WORDS = 5;
    private static final int ABI_ITEM_WORDS = 5;


    @Override
    public long getEnergyForData(byte[] data) {
      long cnt = (data.length / WORD_SIZE - 5) / 5;
      // one sign 1500, half of ecrecover
      return cnt * ENGERYPERSIGN;
    }

    @Override
    public Pair<Boolean, byte[]> execute(byte[] rawData) {
      if (VMConfig.allowTvmOsaka()
          && !isValidAbiEncoding(rawData, ABI_HEADER_WORDS, ABI_ITEM_WORDS)) {
        return Pair.of(false, EMPTY_BYTE_ARRAY);
      }
      DataWord[] words = DataWord.parseArray(rawData);
      byte[] address = words[0].toTronAddress();
      int permissionId = words[1].intValueSafe();
      byte[] data = words[2].getData();

      byte[] combine = ByteUtil.merge(address, ByteArray.fromInt(permissionId), data);
      byte[] hash = Sha256Hash.hash(CommonParameter
          .getInstance().isECKeyCryptoEngine(), combine);

      if (VMConfig.allowTvmSelfdestructRestriction()) {
        int sigArraySize = words[words[3].intValueSafe() / WORD_SIZE].intValueSafe();
        if (sigArraySize > MAX_SIZE) {
          return Pair.of(true, DATA_FALSE);
        }
      }
      byte[][] signatures = VMConfig.allowTvmSelfdestructRestriction() ?
          extractSigArray(words, words[3].intValueSafe() / WORD_SIZE, rawData) :
          extractBytesArray(words, words[3].intValueSafe() / WORD_SIZE, rawData);

      if (signatures.length == 0 || signatures.length > MAX_SIZE) {
        return Pair.of(true, DATA_FALSE);
      }

      AccountCapsule account = this.getDeposit().getAccount(address);
      if (account != null) {
        try {
          Permission permission = account.getPermissionById(permissionId);
          if (permission != null) {
            //calculate weight
            long totalWeight = 0L;
            List<byte[]> executedSignList = new ArrayList<>();
            for (byte[] sign : signatures) {
              byte[] recoveredAddr = recoverAddrBySign(sign, hash);

              sign = merge(recoveredAddr, sign);
              if (ByteArray.matrixContains(executedSignList, recoveredAddr)) {
                if (ByteArray.matrixContains(executedSignList, sign)) {
                  continue;
                }
                MUtil.checkCPUTime();
              }
              long weight = TransactionCapsule.getWeight(permission, recoveredAddr);
              if (weight == 0) {
                //incorrect sign
                return Pair.of(true, DATA_FALSE);
              }
              totalWeight += weight;
              executedSignList.add(sign);
              executedSignList.add(recoveredAddr);
            }

            if (totalWeight >= permission.getThreshold()) {
              return Pair.of(true, dataOne());
            }
          }
        } catch (Throwable t) {
          if (t instanceof OutOfTimeException) {
            throw t;
          }
          logger.info("ValidateMultiSign error:{}", t.getMessage());
        }
      }
      return Pair.of(true, DATA_FALSE);
    }
