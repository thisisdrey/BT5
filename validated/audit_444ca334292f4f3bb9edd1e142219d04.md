### Title
Unstaked-peer connection cap bypass via QUIC client key rotation - (streamer/src/nonblocking/quic.rs)

### Summary
`ConnectionTableKey::new` keys the unstaked connection table by the client's self-reported TLS identity pubkey whenever one is present, rather than by source IP, and `get_remote_pubkey` supplies that pubkey for any QUIC client regardless of stake. An unstaked attacker who rotates ephemeral Ed25519 keypairs per connection therefore creates a fresh `ConnectionTableKey::Pubkey` entry each time, so `max_connections_per_unstaked_peer` (enforced per-key in `ConnectionTable::try_add_connection`) never throttles the attacker's own connections from a single IP.

### Finding Description
`ConnectionTableKey::new` maps `(ip, maybe_pubkey)` to `ConnectionTableKey::Pubkey(pubkey)` whenever a pubkey is available, falling back to `ConnectionTableKey::IP(ip)` only when no pubkey exists: [1](#0-0) . Both `SwQos::cache_new_connection` and `SimpleQos::cache_new_connection` build this key from `conn_context.remote_pubkey`, which originates from the QUIC/TLS client certificate and is populated independent of stake status: [2](#0-1) [3](#0-2) .

`ConnectionTable::try_add_connection` enforces `max_connections_per_peer` only against the `Vec<ConnectionEntry>` bucket associated with that single key: [4](#0-3) . Since an attacker can generate an arbitrary number of distinct Ed25519 keypairs for the QUIC TLS handshake (no stake needed to present a pubkey), each new connection lands in its own bucket in `unstaked_connection_table`, so the per-peer cap (`max_connections_per_unstaked_peer`) never limits connections from the same physical attacker IP.

The only remaining backstop is the global table size, which is bounded by `prune_oldest`, evicting the bucket with the globally oldest `last_update` regardless of which key owns it: [5](#0-4) . This means once the table fills, pruning can evict legitimate staked or unstaked clients' connections just as easily as the attacker's own (freshly created, non-idle) entries, giving the attacker an effective way to churn and starve the table of capacity for others.

### Impact Explanation
This is a QoS/connection-limit evasion: the invariant "unstaked connection limits enforced per source and cannot be evaded by spoofed identity" is violated because the per-peer cap is keyed by an attacker-controlled TLS pubkey rather than IP. A single attacker can occupy an arbitrary share of `unstaked_connection_table` slots up to `max_unstaked_connections`, causing repeated `prune_oldest` evictions of other clients' connections and denying legitimate unstaked senders TPU connection capacity.

### Likelihood Explanation
Fully feasible with no privileges: generating fresh Ed25519 keypairs for QUIC client TLS identities is free and requires no stake, gossip presence, or validator control. The attacker simply opens N QUIC connections from one IP, each with a new keypair, which is exactly the call sequence described (`connect N times with N distinct ephemeral keys`).

### Recommendation
Enforce the unstaked per-peer connection cap by source IP in addition to (or instead of) pubkey, e.g., use `ConnectionTableKey::IP` for unstaked connections unconditionally, or track a combined `(ip)`-level counter alongside the pubkey-keyed table so `max_connections_per_unstaked_peer` cannot be bypassed by rotating the TLS identity key.

### Proof of Concept
Extend `test_prune_table_with_unique_pubkeys` (in `streamer/src/nonblocking/quic.rs` test module) as follows:
```rust
#[test]
fn test_unstaked_peer_cap_bypass_via_pubkey_rotation() {
    let cancel = CancellationToken::new();
    let mut table = ConnectionTable::new(ConnectionTableType::Unstaked, cancel);
    let ip = IpAddr::V4(Ipv4Addr::new(1, 1, 1, 1));
    let max_connections_per_unstaked_peer = 1;
    let stats = Arc::new(StreamerStats::default());

    // Attacker rotates keys: each call uses a distinct Pubkey but the same IP.
    for i in 0..20 {
        let key = ConnectionTableKey::new(ip, Some(Pubkey::new_unique()));
        let added = table.try_add_connection(
            key,
            /*port:*/ 0,
            ClientConnectionTracker::new(stats.clone(), 1000).unwrap(),
            None,
            ConnectionPeerType::Unstaked,
            Arc::new(AtomicU64::new(i)),
            max_connections_per_unstaked_peer,
            || Arc::new(NullStreamerCounter {}),
        );
        assert!(added.is_some(), "connection {i} should succeed despite per-peer cap of 1");
    }

    // BUG: total_size grows unbounded from a single IP even though
    // max_connections_per_unstaked_peer == 1.
    assert_eq!(table.total_size, 20);
}
```
Expected (buggy) result: all 20 connections succeed and `total_size` reaches 20 from one IP, despite `max_connections_per_unstaked_peer = 1`, demonstrating the cap is evaded by key rotation.

    pub(crate) fn prune_oldest(&mut self, max_size: usize) -> usize {
        let mut num_pruned = 0;
        let key = |(_, connections): &(_, &Vec<_>)| {
            connections.iter().map(ConnectionEntry::last_update).min()
        };
        while self.total_size.saturating_sub(num_pruned) > max_size {
            match self.table.values().enumerate().min_by_key(key) {
                None => break,
                Some((index, connections)) => {
                    num_pruned += connections.len();
                    self.table.swap_remove_index(index);
                }
            }
        }
        self.total_size = self.total_size.saturating_sub(num_pruned);
        num_pruned
    }
