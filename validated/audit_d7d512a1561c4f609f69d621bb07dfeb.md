### Title
Unauthenticated `RecvError` message allows spoofed teardown of established tunnels - (File: outside.go)

### Summary
Nebula's outer packet dispatcher processes `header.RecvError` messages before any cryptographic authentication (no handshake, no MAC/AEAD check, no certificate involved), and the only defense against forgery is a comparison of the packet's source `UDPAddr` against the tunnel's currently known remote address — a value that is trivially spoofable over UDP. This lets an attacker who holds no CA-signed certificate and is not a party to the tunnel force termination of another peer's authenticated session, analogous to the tbtc report where a missing access-control check let an unauthorized caller trigger a trusted state-changing action (`DepositLog` events) that other components relied on as authoritative.

### Finding Description
In `readOutsidePackets`, the header type/subtype are parsed from the wire before any peer authentication occurs, and `header.RecvError` is special-cased to be handled immediately, prior to any hostinfo/connection-state lookup or decrypt step: [1](#0-0) 

`handleRecvError` performs only two checks: a local rate/allow policy (`ShouldRecvError`) and a comparison between the sender's reported UDP address and the `HostInfo`'s currently known remote address; if they don't match it merely logs "Someone spoofing recv_errors?" and drops — otherwise it unconditionally tears the tunnel down: [2](#0-1) 

The `RemoteIndex` used to look up the target `HostInfo` (`QueryReverseIndex`) is carried in cleartext in every packet header (`header.H.RemoteIndex`, parsed in `H.Parse`), so it is observable to any network-position attacker without needing to complete a handshake or present a certificate: [3](#0-2) 

There is no cryptographic binding (no signature, no AEAD tag, no session key) tying the `RecvError` packet to the claimed sender — unlike every other message type, which is only processed after `ConnectionState.Decrypt` succeeds: [4](#0-3) 

This mirrors the tbtc bug class: a privileged, state-changing operation (`DepositLog.logSomething` in tbtc; `closeTunnel` in Nebula) is reachable by any caller because the only "access control" is a checkable-but-forgeable attribute (`approvedToLog` returning `true` unconditionally in tbtc; a spoofable UDP source-address check in Nebula), rather than genuine cryptographic authentication.

### Impact Explanation
An attacker with no CA-signed certificate and no participation in the mesh can send a single spoofed UDP packet (source address set to the real peer's IP:port, `header.RecvError` type, target `RemoteIndex` learned by passive observation of any traffic between the two peers) to force `f.closeTunnel(hostinfo)` on the victim node, tearing down an established, fully-authenticated Noise tunnel between two legitimate peers, and also causing `hm.DeleteHostInfo` to purge the pending handshake state. This is remote state poisoning of the hostmap and denial of service against a specific tunnel, without requiring any valid identity.

### Likelihood Explanation
Exploitability depends on the attacker's ability to spoof the source UDP address of a legitimate peer and to observe or guess the current `RemoteIndex` for the target tunnel, both of which are achievable for an on-path or same-broadcast-domain/network attacker (or anywhere lacking egress/ingress anti-spoofing filtering) — a much weaker bar than possessing a CA-signed certificate. The check `hr.IsValid() && hr != addr` is only a heuristic best-effort filter, not cryptographic verification, so it does not prevent the described spoofing.

### Recommendation
Do not action tunnel teardown, or any other trusted state change, based on an unauthenticated message. At minimum, require `RecvError` handling to be gated by proof of possession of the relevant session (e.g., require it to be sent under the encrypted/authenticated `Message` channel, or require an AEAD/MAC computed with a value derived from the session keys) rather than relying solely on comparing the observed UDP source address to the stored remote address.

### Proof of Concept
1. Two nebula peers A and B complete a handshake and establish a tunnel; A's `HostInfo` for B records `RemoteIndex = X` and `hr = B_ip:B_port`.
2. Attacker (holding no nebula certificate) passively observes any UDP traffic between A and B (or otherwise learns `X`), then crafts a UDP datagram with header `Type=header.RecvError`, `RemoteIndex=X`, and spoofs the IP source/port to `B_ip:B_port`, sending it to A's underlay address.
3. `readOutsidePackets` on A dispatches this immediately to `f.handleRecvError` without any decryption/authentication step.
4. `handleRecvError` finds `hostinfo` via `QueryReverseIndex(X)`, sees the spoofed source address matches the recorded remote, and calls `f.closeTunnel(hostinfo)`, tearing down A's tunnel to B despite the attacker never having proven possession of any certificate or session key.

func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}

// Parse is a helper function to parses given bytes into new Header struct
func (h *H) Parse(b []byte) error {
	if len(b) < Len {
		return ErrHeaderTooShort
	}
	// get upper 4 bytes
	h.Version = uint8((b[0] >> 4) & 0x0f)
	// get lower 4 bytes
	h.Type = MessageType(b[0] & 0x0f)
	h.Subtype = MessageSubType(b[1])
	h.Reserved = binary.BigEndian.Uint16(b[2:4])
	h.RemoteIndex = binary.BigEndian.Uint32(b[4:8])
	h.MessageCounter = binary.BigEndian.Uint64(b[8:16])
	return nil
}
