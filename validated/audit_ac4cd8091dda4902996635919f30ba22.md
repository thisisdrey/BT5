### Title
Unauthenticated `/stackerdb_chunks` POST to `SignerEventReceiver`'s HTTP listener lets any remote peer inject forged `SignerEvent::MinerMessages`/`SignerMessages` - (libsigner/src/events.rs)

### Summary
`SignerEventReceiver::bind()` opens a plain `tiny_http::HttpServer` (by default on `0.0.0.0:<port>` per the sample configs), and `next_event()` dispatches any POST to `/stackerdb_chunks` straight into `process_event`/`TryFrom<StackerDBChunksEvent>` with no check of the connecting peer's identity, IP, or any shared secret. For the miner (`MINERS_NAME`) boot contract branch, chunk payloads are deserialized directly with `T::consensus_deserialize` and forwarded as `SignerEvent::MinerMessages` with **zero signature verification of any kind**, breaking the invariant that the runloop only acts on events the locally configured stacks-node actually observed.

### Finding Description
`SignerEventReceiver::bind()` at [1](#0-0)  simply calls `HttpServer::http(listener)` with whatever `SocketAddr` was configured — the sample signer config ships with `endpoint = "0.0.0.0:30000"` [2](#0-1) , i.e. reachable from any remote host unless separately firewalled.

`next_event()` accepts any connection's request and, for `/stackerdb_chunks`, calls `process_event::<T, StackerDBChunksEvent>(request)` unconditionally — there is no check of source IP, no `Authorization` header check, no shared-secret/token comparison anywhere in this function: [3](#0-2) .

`process_event` reads the raw HTTP body and deserializes it as JSON into `StackerDBChunksEvent`, then converts it via `TryFrom` into a `SignerEvent<T>` — again with no authentication of the sender: [4](#0-3) .

The `TryFrom<StackerDBChunksEvent>` implementation has two branches. For the miner boot contract (`MINERS_NAME`), each `chunk.data` is deserialized directly into `T` with **no signature/`recover_pk` check at all**, and pushed into `SignerEvent::MinerMessages`: [5](#0-4) . This is the exact equality break the question describes: nothing ties the JSON body received over this raw TCP connection to any chunk that was actually written to StackerDB by a legitimate miner, or to any authenticity proof from the configured stacks-node event-observer. The `SignerMessages` branch (for `signers-X-Y` contracts) at least calls `chunk.recover_pk()` [6](#0-5) , but the miner-message path has none.

The `main_loop()` then unconditionally calls `forward_event()` on whatever `next_event()` returns, pushing it straight to the signer runloop's channel [7](#0-6) , so a forged `MinerMessages` event is delivered to the runloop indistinguishably from a genuine one.

Notably, this exact risk is called out by the maintainers at signer startup: `SpawnedSigner::new` logs a runtime warning that the signer is designed for a "local or subnet network" and that talking to an "external node" "could potentially expose sensitive data or functionalities to security risks if additional proper security checks are not integrated" [8](#0-7) . That warning is about the node the signer connects out to, but it corroborates that this listener has no built-in authentication for inbound connections either — the code confirms there is none.

### Impact Explanation
An attacker who can reach the signer's event-listener port (bound on `0.0.0.0` per shipped sample config) can, with a single crafted HTTP POST to `/stackerdb_chunks`, inject an arbitrary `SignerEvent::MinerMessages(Vec<T>)` into the signer's runloop with no signature check whatsoever on the miner-message path. This is unauthenticated write into the signer's in-memory event stream/state that the runloop treats as if it came from the node's StackerDB observer. The action is fully repeatable per message (each new TCP connection + POST yields another forged event), matching the "Critical – unauthenticated/unauthorized write to state" category from the rubric, scoped strictly to the event-ingestion path in this file (not the downstream decision logic, which is out of scope).

### Likelihood Explanation
No privileged role, secret, or peer identity is required — only network reachability to the bound `endpoint` (which defaults to `0.0.0.0:30000` in the shipped sample configs) [2](#0-1) . The listener performs no TLS, no auth header, no IP allow-list check anywhere in `next_event`/`process_event`. Cost per exploit attempt is a single raw TCP connection and a hand-built JSON body; it is fully repeatable.

### Recommendation
Add an authentication gate to `SignerEventReceiver::next_event()`/`bind()`: require a shared secret (e.g. reuse `auth_token`/`auth_password` already present in the node/signer configs) verified via a header on every incoming request, and/or bind by default to `127.0.0.1` with an explicit opt-in flag to bind to a non-loopback address. Reject any request lacking the correct token before it reaches `process_event`.

### Proof of Concept
```rust
// libsigner/src/events.rs (or a new integration test)
use std::net::{SocketAddr, TcpStream};
use std::io::Write;
use std::sync::mpsc::channel;

#[test]
fn unauthenticated_stackerdb_chunks_injection() {
    let mut receiver: SignerEventReceiver<SignerMessage> = SignerEventReceiver::new(false);
    let addr: SocketAddr = "127.0.0.1:31337".parse().unwrap();
    receiver.bind(addr).unwrap();

    // Attacker: unrelated client, never proves it is the configured node.
    let body = serde_json::to_string(&forged_stackerdb_chunks_event()).unwrap();
    let req = format!(
        "POST /stackerdb_chunks HTTP/1.1\r\nHost: {addr}\r\nConnection: close\r\nContent-Type: application/json\r\nContent-Length: {}\r\n\r\n{}",
        body.len(), body
    );
    let mut sock = TcpStream::connect(addr).unwrap();
    sock.write_all(req.as_bytes()).unwrap();

    // Assert: server accepts and produces a SignerEvent despite no auth.
    let event = receiver.next_event().unwrap();
    assert!(matches!(event, SignerEvent::MinerMessages(_)));
}
```
The assertion succeeds because `next_event()` ( [3](#0-2) ) and `process_event` ( [4](#0-3) ) never verify the caller's identity before returning `Ok(SignerEvent::MinerMessages(..))`.

fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}
