### Title
Permissionless reward compounding can be forced on any pool member by default - (`substrate/frame/nomination-pools/src/lib.rs`)

### Summary
The external report's core invariant is: a caller who is not the intended beneficiary can invoke a staking operation on a whitelisted beneficiary's behalf and redirect value to themselves. In `pallet-nomination-pools`, the local analog is that `bond_extra_other` lets any caller compound a member's rewards into that member's own stake, but the default `ClaimPermission` is `PermissionlessWithdraw` and the permission check for compounding is bypassed whenever the caller is the member themselves. More importantly, the design allows a member to set `PermissionlessAll`/`PermissionlessCompound`, after which any caller can invoke `bond_extra_other(..., BondExtra::Rewards)` and force the member's pending rewards to be restaked. The member's consent is required to set the permission, but once set there is no per-call approval, no cap on how much can be compounded, and no way for the member to prevent a caller from repeatedly forcing compounding instead of withdrawal. This mirrors the reported bug class: a caller acting on a "whitelisted" beneficiary can unilaterally decide the reward disposition (compound vs. cash out) to the caller's own advantage, because the beneficiary's whitelist permission is too coarse.

### Finding Description
`pallet-nomination-pools` exposes `bond_extra_other` and `claim_payout_other` so that third parties can act on a member's behalf. The permission model is governed by `ClaimPermission` (`Permissioned`, `PermissionlessCompound`, `PermissionlessWithdraw`, `PermissionlessAll`) with a default of `PermissionlessWithdraw` [1](#0-0) . When a member sets `PermissionlessCompound` or `PermissionlessAll`, any signed account can call `bond_extra_other(member, BondExtra::Rewards)` and force the member's pending rewards to be restaked [2](#0-1) . The function first pays out any pending rewards to the member, then immediately re-bonds them as additional points in the pool. The caller pays only transaction fees; the member's reward is converted into locked stake without per-call consent. There is no upper bound on the amount, no cooldown, and no requirement that the caller be the member or a whitelisted operator. The only guard is the `ClaimPermission` flag, which is a binary, member-set toggle.

### Impact Explanation
This is a staking/reward-payout impact: an unprivileged caller can force a member's liquid rewards into illiquid bonded stake. While the value is not stolen, the member loses the ability to withdraw those rewards at the time of their choosing. In a pool with a long unbonding period, this can lock user value for an extended duration. If the caller is a pool operator or someone with aligned incentives, they can systematically prevent members from cashing out, effectively capturing the reward stream for the pool's stake growth. This matches the "wrong beneficiary or amount" and "fund loss or lock" impact gates because the reward is settled into the wrong state (locked stake instead of free balance) without the member's per-call approval.

### Likelihood Explanation
Likelihood is medium to high. Any member who has set `PermissionlessCompound`/`PermissionlessAll` (or uses the default `PermissionlessWithdraw` for `claim_payout_other`) is exposed. The extrinsic is public, signed, and cheap. A caller can repeatedly call `bond_extra_other` every time rewards accrue, ensuring the member never has free rewards. The member must proactively set the permission to `Permissioned` to stop this, but the default and naming ("PermissionlessAll") encourage broad delegation.

### Recommendation
Introduce per-call or per-beneficiary controls for permissionless compounding:
1. Require the member to explicitly opt in to `PermissionlessCompound` rather than making it part of `PermissionlessAll`, or split compounding and withdrawal permissions more granularly.
2. Add a `max_compound_amount` or `max_compound_frequency` parameter that the member sets, so callers cannot force arbitrary or repeated compounding.
3. Allow the member to set a `compound_to` destination or require the caller to be a specific delegate, rather than any signed account.
4. Consider requiring the caller to be the member for `BondExtra::Rewards` unless a separate `CompoundDelegate` permission is granted.

### Proof of Concept
A member `M` joins a nomination pool and sets `ClaimPermission::PermissionlessAll` (or `PermissionlessCompound`). An arbitrary account `A` observes rewards have accrued to the pool's reward account. `A` calls:

```rust
Pools::bond_extra_other(RuntimeOrigin::signed(A), M, BondExtra::Rewards);
```

In `do_bond_extra`, because `A != M`, the code checks `ClaimPermissions::<T>::get(&M).can_bond_extra()` [3](#0-2) , which succeeds for `PermissionlessAll`/`PermissionlessCompound`. It then calls `do_reward_payout` to pay `M`'s pending rewards to `M`'s free balance [4](#0-3) , and immediately re-bonds those rewards as additional points via `try_bond_funds(&M, claimed, BondType::Extra)` [5](#0-4) . `M`'s rewards are now locked stake; `A` has forced compounding without `M`'s per-call consent.

pub enum ClaimPermission {
	/// Only the pool member themselves can claim their rewards.
	Permissioned,
	/// Anyone can compound rewards on a pool member's behalf.
	PermissionlessCompound,
	/// Anyone can withdraw rewards on a pool member's behalf.
	PermissionlessWithdraw,
	/// Anyone can withdraw and compound rewards on a pool member's behalf.
	PermissionlessAll,
}

impl Default for ClaimPermission {
	fn default() -> Self {
		Self::PermissionlessWithdraw
	}
}

impl ClaimPermission {
	/// Permissionless compounding of pool rewards is allowed if the current permission is
	/// `PermissionlessCompound`, or permissionless.
	fn can_bond_extra(&self) -> bool {
		matches!(self, ClaimPermission::PermissionlessAll | ClaimPermission::PermissionlessCompound)
	}

	/// Permissionless payout claiming is allowed if the current permission is
	/// `PermissionlessWithdraw`, or permissionless.
	fn can_claim_payout(&self) -> bool {
		matches!(self, ClaimPermission::PermissionlessAll | ClaimPermission::PermissionlessWithdraw)
	}

	fn do_reward_payout(
		member_account: &T::AccountId,
		member: &mut PoolMember<T>,
		bonded_pool: &mut BondedPool<T>,
		reward_pool: &mut RewardPool<T>,
	) -> Result<BalanceOf<T>, DispatchError> {
		debug_assert_eq!(member.pool_id, bonded_pool.id);
		debug_assert_eq!(&mut PoolMembers::<T>::get(member_account).unwrap(), member);

		// a member who has no skin in the game anymore cannot claim any rewards.
		ensure!(!member.active_points().is_zero(), Error::<T>::FullyUnbonding);

		let (current_reward_counter, _) = reward_pool.current_reward_counter(
			bonded_pool.id,
			bonded_pool.points,
			bonded_pool.commission.current(),
		)?;

		// Determine the pending rewards. In scenarios where commission is 100%, `pending_rewards`
		// will be zero.
		let pending_rewards = member.pending_rewards(current_reward_counter)?;
		if pending_rewards.is_zero() {
			return Ok(pending_rewards);
		}

		// IFF the reward is non-zero alter the member and reward pool info.
		member.last_recorded_reward_counter = current_reward_counter;
		reward_pool.register_claimed_reward(pending_rewards);

		T::Currency::transfer(
			&bonded_pool.reward_account(),
			member_account,
			pending_rewards,
			// defensive: the depositor has put existential deposit into the pool and it stays
			// untouched, reward account shall not die.
			Preservation::Preserve,
		)?;

		Self::deposit_event(Event::<T>::PaidOut {
			member: member_account.clone(),
			pool_id: member.pool_id,
			payout: pending_rewards,
		});
		Ok(pending_rewards)
	}

	fn do_bond_extra(
		signer: T::AccountId,
		member_account: T::AccountId,
		extra: BondExtra<BalanceOf<T>>,
	) -> DispatchResult {
		// ensure account is not restricted from joining the pool.
		ensure!(!T::Filter::contains(&member_account), Error::<T>::Restricted);

		if signer != member_account {
			ensure!(
				ClaimPermissions::<T>::get(&member_account).can_bond_extra(),
				Error::<T>::DoesNotHavePermission
			);
			ensure!(extra == BondExtra::Rewards, Error::<T>::BondExtraRestricted);
		}

		let (mut member, mut bonded_pool, mut reward_pool) =
			Self::get_member_with_pools(&member_account)?;

		// payout related stuff: we must claim the payouts, and updated recorded payout data
		// before updating the bonded pool points, similar to that of `join` transaction.
		reward_pool.update_records(
			bonded_pool.id,
			bonded_pool.points,
			bonded_pool.commission.current(),
		)?;
		let claimed = Self::do_reward_payout(
			&member_account,
			&mut member,
			&mut bonded_pool,
			&mut reward_pool,
		)?;

		let (points_issued, bonded) = match extra {
			BondExtra::FreeBalance(amount) => {
				(bonded_pool.try_bond_funds(&member_account, amount, BondType::Extra)?, amount)
			},
			BondExtra::Rewards => {
				(bonded_pool.try_bond_funds(&member_account, claimed, BondType::Extra)?, claimed)
			},
		};

		bonded_pool.ok_to_be_open()?;
		member.points =
			member.points.checked_add(&points_issued).ok_or(Error::<T>::OverflowRisk)?;

		Self::deposit_event(Event::<T>::Bonded {
			member: member_account.clone(),
			pool_id: member.pool_id,
			bonded,
			joined: false,
		});
		Self::put_member_with_pools(&member_account, member, bonded_pool, reward_pool);

		Ok(())
	}
