### Title
Firewall conntrack fast-path bypasses certificate blocklist revalidation, allowing continued traffic on blocklisted tunnels - (File: firewall.go)

### Summary
Nebula's firewall maintains a conntrack table (`f.Conntrack.Conns`) that allows already-approved flows to bypass full rule matching on subsequent packets. This fast path, `Firewall.inConns`, only re-validates a flow against the firewall rule table when the firewall's `rulesVersion` has changed (e.g., after a SIGHUP config reload); it never checks whether the remote peer's certificate has since been placed on the CA pool's blocklist. Detection and teardown of blocklisted-certificate tunnels is instead delegated entirely to the asynchronous `connectionManager` tick (`isInvalidCertificate`), which runs on a timer (`timers.connection_alive_interval`, default 5s). This mirrors the reported bug class: a security-relevant, mutable trust state (blocklist status) is not re-checked at the point actual traffic decisions are made, allowing an unpredictable/attacker-favorable window where stale trust decisions keep being honored.

### Finding Description
The fast path `inConns` in [1](#0-0)  looks up the packet 5-tuple in the conntrack map and returns "allowed" immediately if found and `c.rulesVersion == f.rulesVersion`. It does not consult `caPool.IsBlocklisted` or otherwise re-verify the certificate that originally authorized the flow. Certificate/blocklist verification is instead centralized in `connectionManager.isInvalidCertificate`, which calls `caPool.VerifyCachedCertificate` and tears down the tunnel with `closeTunnel` if `cert.ErrBlockListed` is returned [2](#0-1) . This check is only invoked from the periodic `makeTrafficDecision` tick [3](#0-2) , driven by `cm.trafficTimer` on an interval configured by `timers.connection_alive_interval` (default 5 seconds) [4](#0-3) .

Consequently, once an operator blocklists a remote's certificate fingerprint (via `pki.blocklist` or an SSH command), packets that match an already-established conntrack entry for that host continue to be forwarded by `Firewall.Drop` → `inConns` for up to one `checkInterval`, because the fast path performs no blocklist check and the periodic teardown has not yet run. The `Drop` entry point itself only performs full rule matching (which does incorporate `caPool` for CA-name based rules) via `table.match` when there is no existing conntrack hit [5](#0-4) ; once a flow is conntrack'd, that path is skipped for the life of the entry.

### Impact Explanation
This is a firewall-bypass analog: newly-blocklisted (compromised/revoked) peers are not immediately cut off — encrypted traffic keeps flowing through their existing tunnel and conntrack'd 5-tuples until the connection-manager's next tick fires and the tunnel is torn down. If an attacker has compromised a host's certificate and the operator reacts by blocklisting the fingerprint expecting immediate enforcement, the compromised peer can continue to send/receive packets matching existing conntrack state for up to the configured `checkInterval` (default 5s, but operator-configurable to larger values), undermining the intended "always disconnect blocklisted hosts" guarantee referenced in the CHANGELOG fix for issue #858 [6](#0-5) . The severity is bounded by the check interval and does not defeat blocklisting entirely, but it is a real gap between "operator declares peer untrusted" and actual traffic enforcement.

### Likelihood Explanation
This triggers deterministically any time an already-tunneled peer's certificate fingerprint is blocklisted while conntrack entries exist for that host — a common operational response to a detected compromise. No attacker action is required beyond having an established, conntrack'd tunnel prior to being blocklisted, and normal bidirectional traffic naturally keeps entries fresh via `addConn`'s TTL refresh in `inConns` [7](#0-6) , extending the exposure window.

### Recommendation
In `Firewall.inConns`, additionally verify the current blocklist status of `h.ConnectionState.peerCert` (e.g., via `caPool.IsBlocklisted` on the cached fingerprint) on every fast-path hit, not only when `rulesVersion` differs, and evict/deny the conntrack entry immediately if the certificate is blocklisted. Alternatively, have blocklist updates bump `f.rulesVersion` (or a dedicated blocklist-version counter checked in `inConns`) so that the existing rulesVersion-triggered revalidation path in `inConns` is forced to run and pick up the new blocklist decision immediately rather than waiting for the next `connectionManager` tick.

### Proof of Concept
1. Establish a tunnel between host A and host B and pass traffic so a conntrack entry exists in `A`'s `Firewall.Conntrack.Conns` for `B`'s flow (via `Firewall.Drop` → `addConn`, [8](#0-7) ).
2. On host A, blocklist B's certificate fingerprint at runtime (e.g., SSH `reload`/config change adding to `pki.blocklist`, populated into the CA pool via `loadCAPoolFromConfig` [9](#0-8) ). Note this does not bump `f.rulesVersion`.
3. Immediately after blocklisting (before the next `connectionManager` tick, i.e., within `timers.connection_alive_interval`), continue sending packets on the same conntrack'd 5-tuple from B.
4. Observe that `Firewall.Drop` on host A returns `nil` (allowed) via `inConns`'s fast path because `c.rulesVersion == f.rulesVersion` still holds and no blocklist check occurs, even though `caPool.VerifyCachedCertificate` would return `cert.ErrBlockListed` if invoked. Traffic keeps flowing until `connectionManager.isInvalidCertificate` runs on its next tick and issues `closeTunnel`.

func (f *Firewall) inConns(fp firewall.Packet, h *HostInfo, caPool *cert.CAPool, localCache firewall.ConntrackCache) bool {
	if localCache != nil {
		if _, ok := localCache[fp]; ok {
			return true
		}
	}
	conntrack := f.Conntrack
	conntrack.Lock()

	// Purge every time we test
	ep, has := conntrack.TimerWheel.Purge()
	if has {
		f.evict(ep)
	}

	c, ok := conntrack.Conns[fp]

	if !ok {
		conntrack.Unlock()
		return false
	}

	if c.rulesVersion != f.rulesVersion {
		// This conntrack entry was for an older rule set, validate
		// it still passes with the current rule set
		table := f.OutRules
		if c.incoming {
			table = f.InRules
		}

		// We now know which firewall table to check against
		if !table.match(fp, c.incoming, h.ConnectionState.peerCert, caPool) {
			if f.l.Enabled(context.Background(), slog.LevelDebug) {
				h.logger(f.l).Debug("dropping old conntrack entry, does not match new ruleset",
					"fwPacket", fp,
					"incoming", c.incoming,
					"rulesVersion", f.rulesVersion,
					"oldRulesVersion", c.rulesVersion,
				)
			}
			delete(conntrack.Conns, fp)
			conntrack.Unlock()
			return false
		}

		if f.l.Enabled(context.Background(), slog.LevelDebug) {
			h.logger(f.l).Debug("keeping old conntrack entry, does match new ruleset",
				"fwPacket", fp,
				"incoming", c.incoming,
				"rulesVersion", f.rulesVersion,
				"oldRulesVersion", c.rulesVersion,
			)
		}

		c.rulesVersion = f.rulesVersion
	}

func (f *Firewall) addConn(fp firewall.Packet, incoming bool) {
	var timeout time.Duration
	c := &conn{}

	switch fp.Protocol {
	case firewall.ProtoTCP:
		timeout = f.TCPTimeout
	case firewall.ProtoUDP:
		timeout = f.UDPTimeout
	default:
		timeout = f.DefaultTimeout
	}

	conntrack := f.Conntrack
	conntrack.Lock()
	if _, ok := conntrack.Conns[fp]; !ok {
		conntrack.TimerWheel.Advance(time.Now())
		conntrack.TimerWheel.Add(fp, timeout)
	}

	// Record which rulesVersion allowed this connection, so we can retest after
	// firewall reload
	c.incoming = incoming
	c.rulesVersion = f.rulesVersion
	c.Expires = time.Now().Add(timeout)
	conntrack.Conns[fp] = c
	conntrack.Unlock()
}

// isInvalidCertificate decides if we should destroy a tunnel.
// returns true if pki.disconnect_invalid is true and the certificate is no longer valid.
// Blocklisted certificates will skip the pki.disconnect_invalid check and return true.
func (cm *connectionManager) isInvalidCertificate(now time.Time, hostinfo *HostInfo) bool {
	remoteCert := hostinfo.GetCert()
	if remoteCert == nil {
		return false //don't tear down tunnels for handshakes in progress
	}

	caPool := cm.intf.pki.GetCAPool()
	err := caPool.VerifyCachedCertificate(now, remoteCert)
	if err == nil {
		return false //cert is still valid! yay!
	} else if err == cert.ErrBlockListed { //avoiding errors.Is for speed
		// Block listed certificates should always be disconnected
		hostinfo.logger(cm.l).Info("Remote certificate is blocked, tearing down the tunnel",
			"error", err,
			"fingerprint", remoteCert.Fingerprint,
		)
		return true
	} else if cm.intf.disconnectInvalid.Load() {
		hostinfo.logger(cm.l).Info("Remote certificate is no longer valid, tearing down the tunnel",
			"error", err,
			"fingerprint", remoteCert.Fingerprint,
		)
		return true
	} else {
		//if we reach here, the cert is no longer valid, but we're configured to keep tunnels from now-invalid certs open
		return false
	}
