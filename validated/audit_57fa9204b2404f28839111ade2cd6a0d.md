### Title
CreateRepositoryFromURL accepts `file://` and other local-filesystem git URLs, enabling local repository/file disclosure - (File: internal/gitaly/service/repository/create_repository_from_url.go)

### Summary
`validateCreateRepositoryFromURLRequest` only rejects an empty `Url` and performs no scheme/host allowlisting, and `cloneFromURLCommand` passes the URL verbatim to `git clone` without disabling local transports. Since `git-clone` natively supports `file://` (and bare local paths), a user who can trigger `CreateRepositoryFromURL` (e.g. via project import) can make the Gitaly host clone from any path on its own local filesystem, including other repositories' `.git` directories stored on disk, into a repository the attacker fully controls.

### Finding Description
`validateCreateRepositoryFromURLRequest` at [1](#0-0)  only calls `locator.ValidateRepository` on the *destination* repository and checks `req.GetUrl() == ""`; it never inspects the URL's scheme. `cloneFromURLCommand` at [2](#0-1)  parses the URL with `net/url`, optionally strips credentials, optionally applies `curlopt-resolve` rewriting for DNS-pinning, then unconditionally passes it as an argument to `git clone --bare/--mirror <url> <path>` via `s.gitCmdFactory.NewWithoutRepo`. The only defensive measure present is disabling `transfer.bundleURI` to block a previously-fixed bundle-URI SSRF vector (see CHANGELOG entry for MR gitlab-org/gitaly!8843/security fix), but there is no equivalent guard against `file://` transport, unauthenticated local paths, or `ext::`-style helper invocation. `net/url.Parse` and `git` itself will happily process `file:///some/path` or a bare filesystem path, and git-clone treats it as a local repository path, not as a data stream fetch — so this does not disclose arbitrary file contents byte-for-byte, but it does let the client clone *any git repository reachable on the Gitaly host filesystem*, including other tenants' repositories under the same storage root (which are normally protected by `storage.ValidateRelativePath`/locator confinement on the destination side only, not on the source side of this RPC).

### Impact Explanation
This matches the "cross-repository object access" / "storage-path confinement bypass" impact class: an unprivileged user who can trigger a project import can create a new repository under their control seeded from the full object/ref history of an arbitrary local repository path on the Gitaly node (e.g., another user's private repository if its on-disk relative path can be guessed or enumerated), rather than being limited to the intended remote fetch. It does not directly yield arbitrary file read of non-git files, since `git clone` requires a valid git repository at the source path, but it breaks the confinement invariant that Gitaly's storage layout should not be reachable through arbitrary "remote" import URLs.

### Likelihood Explanation
Precondition matches an unprivileged user capability directly (project import flow invoking `CreateRepositoryFromURL` with a fully attacker-controlled `Url` field). No special role, secret, or non-default configuration is required — the code path is reachable with default configuration since no scheme filtering exists in Gitaly itself. The main uncertainty is what validation happens upstream in GitLab Rails (`Gitlab::UrlBlocker`) before this RPC is invoked; that component is not part of this repository and could not be verified here, so whether this Gitaly-level gap is actually exploitable end-to-end depends on Rails-side filtering, which per the rules of this audit should not be assumed to compensate for a missing Gitaly-side check.

### Recommendation
Add scheme validation in `validateCreateRepositoryFromURLRequest` to reject any URL whose scheme is not one of an explicit allowlist (e.g. `http`, `https`, `git`, `ssh`), and reject bare filesystem paths and `file://`/`ext::` transports outright, in addition to the existing bundle-URI restriction. This should happen inside `internal/gitaly/service/repository/create_repository_from_url.go` and be enforced regardless of what filtering exists at the GitLab Rails layer, since Gitaly is directly reachable as its own RPC surface.

func (s *server) cloneFromURLCommand(
	ctx context.Context,
	repoURL, resolvedAddress, repositoryFullPath, authorizationToken string, mirror bool,
	opts ...gitcmd.CmdOpt,
) (*command.Command, error) {
	cloneFlags := []gitcmd.Option{
		gitcmd.Flag{Name: "--quiet"},
	}

	if mirror {
		cloneFlags = append(cloneFlags, gitcmd.Flag{Name: "--mirror"})
	} else {
		cloneFlags = append(cloneFlags, gitcmd.Flag{Name: "--bare"})
	}

	u, err := url.Parse(repoURL)
	if err != nil {
		return nil, structerr.NewInternal("%w", err)
	}

	var config []gitcmd.ConfigPair
	if u.User != nil {
		password, hasPassword := u.User.Password()

		var creds string
		if hasPassword {
			creds = u.User.Username() + ":" + password
		} else {
			creds = u.User.Username()
		}

		u.User = nil
		authHeader := fmt.Sprintf("Authorization: Basic %s", base64.StdEncoding.EncodeToString([]byte(creds)))
		config = append(config, gitcmd.ConfigPair{Key: "http.extraHeader", Value: authHeader})
	} else if len(authorizationToken) > 0 {
		authHeader := fmt.Sprintf("Authorization: %s", authorizationToken)
		config = append(config, gitcmd.ConfigPair{Key: "http.extraHeader", Value: authHeader})
	}

	urlString := u.String()

	if resolvedAddress != "" {
		modifiedURL, resolveConfig, err := gitcmd.GetURLAndResolveConfig(u.String(), resolvedAddress)
		if err != nil {
			return nil, structerr.NewInvalidArgument("couldn't get curloptResolve config: %w", err)
		}

		urlString = modifiedURL
		config = append(config, resolveConfig...)
	}

	// Drop support for bundle URI when fetching from a remote repository.
	// Since the URI can point to any server, including localhost, this is to
	// prevent attack vectors that could abuse this mechanism.
	opts = append(opts, gitcmd.WithGlobalOption(gitcmd.ConfigPair{Key: "transfer.bundleURI", Value: "false"}))

	return s.gitCmdFactory.NewWithoutRepo(ctx,
		gitcmd.Command{
			Name:  "clone",
			Flags: cloneFlags,
			Args:  []string{urlString, repositoryFullPath},
		},
		append(opts, gitcmd.WithConfigEnv(config...))...,
	)
}

func validateCreateRepositoryFromURLRequest(ctx context.Context, locator storage.Locator, req *gitalypb.CreateRepositoryFromURLRequest) error {
	if err := locator.ValidateRepository(ctx, req.GetRepository(), storage.WithSkipRepositoryExistenceCheck()); err != nil {
		return err
	}

	if req.GetUrl() == "" {
		return fmt.Errorf("empty Url")
	}

	return nil
