## Title
Just-in-time deposit before `lending_pool_emissions_deposit` lets an attacker skim a disproportionate share of third-party-funded emissions - (File: `programs/marginfi/src/instructions/marginfi_group/configure_bank.rs`)

### Summary
The `liquidity_lockbox` report describes an attacker who deposits a large position right before an LP-reward event and withdraws immediately after, capturing rewards they never economically earned. Marginfi has a structurally identical unprivileged path through the permissionless `lending_pool_emissions_deposit` instruction, which pro-rata distributes a same-mint reward top-up to *whoever currently holds `total_asset_shares`* at the moment the instruction executes — with no lock-up, vesting, or minimum holding period.

### Finding Description
`lending_pool_emissions_deposit` lets any signer permissionlessly transfer tokens into a bank's `liquidity_vault` and immediately re-price `asset_share_value` for every existing depositor, proportional to their current share of `total_asset_shares`: [1](#0-0) [2](#0-1) 

Crucially, the reward apportionment is a single atomic recalculation based on `total_asset_shares` at call time — there is no snapshot of "shares held for N slots" or exclusion of shares created moments earlier in the same or a preceding transaction. A user can:

1. Deposit a large amount into the bank via `lending_account_deposit` (ordinary, unprivileged instruction) immediately before a legitimate `lending_pool_emissions_deposit` call lands (this call is routinely and intentionally funded by a third party — a project/rewards program — as documented and tested, e.g. `try_emissions_deposit`).
2. Let the emissions deposit transaction execute; `bank.asset_share_value` increases for *all* current holders of `total_asset_shares`, including the attacker's just-added shares, per [3](#0-2) .
3. Immediately withdraw via `lending_account_withdraw` (`withdraw_all: true`), as shown by the standard withdraw flow: interest accrual, share lookup, and transfer with no cool-down check on the flags/timing of the position: [4](#0-3) 

This mirrors the report's core flaw — reward distribution keyed purely on instantaneous position size, with `withdraw()` having "no restrictions or checks that prevent immediate withdrawal after a deposit and pays all accrued... rewards to the caller." Marginfi's `ACCOUNT_IN_FLASHLOAN` documentation confirms deposit-then-withdraw-in-one-tx is an explicitly supported pattern (health checks deferred to end of tx), reinforcing that nothing structurally prevents rapid deposit/withdraw cycling around a reward event: [5](#0-4) 

### Impact Explanation
An attacker who times a large deposit immediately ahead of a third-party-funded `lending_pool_emissions_deposit`, then withdraws immediately after, captures a share of the emissions proportional to their transient share of the pool — value that was intended by the funder to reward genuine, time-weighted depositors. This is a real value transfer: the emissions funder's tokens end up disproportionately routed to a depositor with zero time-at-risk, diluting the rewards actually earned by long-term depositors. Repeatable whenever an emissions top-up is anticipated (the instruction and its funding source are publicly visible/permissionless), this can be cycled to systematically skim reward programs.

### Likelihood Explanation
Requires only ordinary unprivileged instructions (`lending_account_deposit`, `lending_pool_emissions_deposit` observation, `lending_account_withdraw`) with no special permissions, and depositing large capital is achievable via a flashloan (marginfi natively supports flashloans in the same manner referenced by the report) or simply idle liquidity. The only timing requirement is landing a deposit before a known/anticipated emissions-deposit transaction, which is feasible given the instruction is permissionless and its use is documented/expected (e.g., as a reward program mechanism).

### Recommendation
- Snapshot eligible shares for an emissions distribution prior to the funding transaction (e.g., require shares to have existed for at least N slots, or use a merkle/eligibility snapshot rather than live `total_asset_shares`).
- Alternatively, charge a withdrawal fee or minimum holding period on the depositor's newly created shares before they can participate in `asset_share_value` increases contributed by `lending_pool_emissions_deposit`.
- Consider restricting `lending_pool_emissions_deposit` to distribute pro-rata only to balances that existed as of the start of the same transaction/prior block, closing the JIT-deposit window.

### Proof of Concept
1. Attacker observes/anticipates a `lending_pool_emissions_deposit` call funded by a third party (project rewards) on Bank X.
2. Attacker calls `lending_account_deposit` with a large sum, making their shares dominate `bank.total_asset_shares`.
3. The pending `lending_pool_emissions_deposit(amount)` executes, per [2](#0-1) , raising `bank.asset_share_value` for the whole pool including the attacker's fresh deposit.
4. Attacker immediately calls `lending_account_withdraw(withdraw_all: true)` per [6](#0-5) , redeeming their shares at the inflated `asset_share_value` and pocketing a disproportionate slice of the emissions funder's contribution relative to the seconds they were actually deposited.
5. Repeat around future emissions top-ups.

```rust
/// Permissionlessly deposit same-mint emissions directly into the bank liquidity vault,
/// increasing depositor value through asset share value.
pub fn lending_pool_emissions_deposit(
    ctx: Context<LendingPoolEmissionsDeposit>,
    amount: u64,
) -> MarginfiResult {
    if amount == 0 {
        return Ok(());
    }

    let clock = Clock::get()?;
    let mut bank = ctx.accounts.bank.load_mut()?;
    let group = ctx.accounts.group.load()?;

    utils::validate_bank_state(&bank, utils::InstructionKind::FailsIfPausedOrReduceState)?;

    // Reject mints with non-zero transfer fees or active transfer hooks.
    let mint_ai = ctx.accounts.mint.to_account_info();
    check!(
        !utils::nonzero_fee(mint_ai.clone(), clock.epoch)?,
        MarginfiError::InvalidTransfer
    );
    check!(
        !utils::has_transfer_hook(mint_ai)?,
        MarginfiError::InvalidTransfer
    );

    let total_asset_shares = I80F48::from(bank.total_asset_shares);
    check!(
        total_asset_shares > I80F48::ZERO,
        MarginfiError::EmissionsUpdateError
    );

    bank.accrue_interest(
        clock.unix_timestamp,
        &group,
        #[cfg(not(feature = "client"))]
        ctx.accounts.bank.key(),
    )?;
```

```rust
pub fn lending_account_withdraw<'info>(
    mut ctx: Context<'info, LendingAccountWithdraw<'info>>,
    amount: u64,
    withdraw_all: Option<bool>,
) -> MarginfiResult {
    let LendingAccountWithdraw {
        marginfi_account: marginfi_account_loader,
        destination_token_account,
        liquidity_vault: bank_liquidity_vault,
        token_program,
        bank_liquidity_vault_authority,
        bank: bank_loader,
        group: marginfi_group_loader,
        ..
    } = ctx.accounts;
    let clock = Clock::get()?;

    let withdraw_all = withdraw_all.unwrap_or(false);
    let mut marginfi_account = marginfi_account_loader.load_mut()?;
    let group = marginfi_group_loader.load()?;

    {
        let maybe_bank_mint = {
            let bank = bank_loader.load()?;
            utils::maybe_take_bank_mint(&mut ctx.remaining_accounts, &bank, token_program.key)?
        };

        let in_receivership_or_order_execution =
            marginfi_account.get_flag(ACCOUNT_IN_RECEIVERSHIP | ACCOUNT_IN_ORDER_EXECUTION);
        let mut bank = bank_loader.load_mut()?;
        validate_bank_state(&bank, InstructionKind::FailsInPausedState)?;

        // Fetch oracle price for rate limiting and deleverage tracking
        // When group rate limiter is enabled, oracle is required
        let group_rate_limit_enabled = group.rate_limiter.is_enabled();
        let price = if in_receivership_or_order_execution || group_rate_limit_enabled {
            let price = fetch_asset_price_for_bank_low_bias(
                &bank_loader.key(),
                &bank,
                &clock,
                ctx.remaining_accounts,
            )?;

            // Validate price is non-zero during liquidation/deleverage to prevent exploits
            if in_receivership_or_order_execution {
                check!(price > I80F48::ZERO, MarginfiError::ZeroAssetPrice);
            }

            price
        } else {
            I80F48::ZERO
        };

        bank.accrue_interest(
            clock.unix_timestamp,
            &group,
            #[cfg(not(feature = "client"))]
            bank_loader.key(),
        )?;
```
