## Analysis

The Malt report's core broken invariant: a **permissioned, infrequently-updated price value** feeds a fee/incentive calculation that is used by an **unprivileged, public entrypoint**, and the gap between "stale stored price" and "real market price" can be exploited by ordinary users because no code path forces a refresh before the value is consumed.

The closest local analog is in the Snowbridge outbound-queue pallet, where the ETH/DOT `exchange_rate` and `fee_per_gas` used to price every outbound bridge message are stored in a single `PricingParameters` value that governance is expected to refresh "every few weeks" via a root-only extrinsic, while the public `send`/`validate` path charges every user based on whatever stale value happens to be in storage at that moment.

### Title
Outbound bridge message fees are priced from a governance-refreshed, non-live `PricingParameters` value, letting any user submit underpriced bridge messages that stall relayer processing - (File: bridges/snowbridge/pallets/outbound-queue/src/lib.rs)

### Summary
`Pallet::calculate_fee` (and thus `validate()` in `send_message_impl.rs`) derives the fee charged to a caller sending a Snowbridge outbound message entirely from `T::PricingParameters::get()`, a single governance-set storage value covering `exchange_rate`, `fee_per_gas`, `multiplier`, and `rewards`. The module docs explicitly state this value is manually refreshed "every few weeks" via `set_pricing_parameters`, not derived from a live oracle. There is no on-chain mechanism forcing this value to reflect current Ethereum gas price or ETH/DOT rate at the time any given message is queued.

### Finding Description
`Pallet::calculate_fee` at [1](#0-0)  computes the local+remote fee for a message using `params: PricingParameters<T::Balance>` pulled from configuration/storage, and this is invoked from `SendMessage::validate` at [2](#0-1) , which any unprivileged XCM sender reaches indirectly through the exporter. The pricing value itself is only mutated by `set_pricing_parameters`, a root-only extrinsic in the system pallet, documented as an "interim measure" refreshed periodically by governance: [3](#0-2) . The committed message that gets queued for relayers embeds `max_fee_per_gas` and `reward` taken straight from that same stale snapshot at `do_process_message`: [4](#0-3) .

There is no validation anywhere in `validate()`, `deliver()`, or `do_process_message()` that the stored `fee_per_gas`/`exchange_rate` are still consistent with real-world Ethereum gas prices or ETH/DOT rates at message-submission time — the only guard is `MaxMessagesPerBlock` limiting per-block throughput, not price staleness: [5](#0-4) . This mirrors the Malt bug class precisely: a value meant to track external market conditions is updated by an external/privileged actor on a slow cadence, while a public, unprivileged entrypoint keeps consuming it as if it were live.

### Impact Explanation
Once real Ethereum gas prices rise materially above the stored `fee_per_gas` (a routine market event, not requiring any malicious actor), any ordinary user can continue calling the public message-send path and get messages committed and merkle-rooted on Bridge Hub while paying/embedding fees calculated from the outdated, underpriced parameters. Relayers, who are only reimbursed `Min(GasPrice, Message.MaxFeePerGas) * GasUsed + Reward`, have no rational incentive to submit these underpriced messages to Ethereum once real gas cost exceeds `max_fee_per_gas + reward`. Messages accumulate as committed leaves/merkle roots with no relayer picking them up, i.e. "public underpriced work that degrades block production or stalls bridge processing" — an explicitly in-scope impact.

### Likelihood Explanation
This requires no malicious peer, validator, collator, relayer, or governance actor — it is triggered purely by ordinary ETH gas-price/DOT-rate market movement between the periodic (manual, "every few weeks") governance refreshes, combined with any normal user continuing to call the public send path during that stale window. This is a naturally recurring condition rather than an edge case, making likelihood moderate-to-high over any sufficiently volatile period.

### Recommendation
Bind message fee calculation to a live or frequently-refreshed source (e.g., short-TTL oracle with automatic in-block staleness checks), or add a staleness guard in `calculate_fee`/`validate()` that rejects/derates message submission if `PricingParameters` has not been updated within an acceptable freshness window, forcing an update before further messages are accepted, analogous to what the Malt judges recommended (auto-update or cumulative feed with anti-staleness bound) rather than relying purely on manual governance cadence.

### Proof of Concept
1. At time T0, governance sets `PricingParameters { fee_per_gas: gwei(20), exchange_rate: 1/400, ... }` via `set_pricing_parameters` (as in [6](#0-5) ).
2. Real Ethereum gas price rises to, say, 5x the stored `fee_per_gas` due to network congestion — no on-chain check detects or blocks this drift.
3. An unprivileged user repeatedly calls the public bridge-send path (e.g., `pallet_xcm::execute`/`send` routed to `SnowbridgeExporter`), which calls `SendMessage::validate` → `calculate_fee` using the stale `PricingParameters`, paying only the old, now-underpriced fee: [7](#0-6) .
4. Each message is accepted, queued, and committed into the merkle root by `do_process_message`/`commit` regardless of whether the embedded `max_fee_per_gas`/`reward` are sufficient for the current market: [8](#0-7) .
5. Relayers decline to submit these underpriced commitments to Ethereum since reimbursement is capped at the stale `max_fee_per_gas`, so the backlog of committed-but-undelivered messages grows until governance manually updates pricing parameters — degrading/stalling bridge message delivery throughput with no privileged or malicious actor involved.

		/// Process a message delivered by the MessageQueue pallet
		pub(crate) fn do_process_message(
			_: ProcessMessageOriginOf<T>,
			mut message: &[u8],
		) -> Result<bool, ProcessMessageError> {
			use ProcessMessageError::*;

			// Yield if the maximum number of messages has been processed this block.
			// This ensures that the weight of `on_finalize` has a known maximum bound.
			ensure!(
				MessageLeaves::<T>::decode_len().unwrap_or(0) <
					T::MaxMessagesPerBlock::get() as usize,
				Yield
			);

			// Decode bytes into versioned message
			let versioned_queued_message: VersionedQueuedMessage =
				VersionedQueuedMessage::decode(&mut message).map_err(|_| Corrupt)?;

			// Convert versioned message into latest supported message version
			let queued_message: QueuedMessage =
				versioned_queued_message.try_into().map_err(|_| Unsupported)?;

			// Obtain next nonce
			let nonce = <Nonce<T>>::try_mutate(
				queued_message.channel_id,
				|nonce| -> Result<u64, ProcessMessageError> {
					*nonce = nonce.checked_add(1).ok_or(Unsupported)?;
					Ok(*nonce)
				},
			)?;

			let pricing_params = T::PricingParameters::get();
			let command = queued_message.command.index();
			let params = queued_message.command.abi_encode();
			let max_dispatch_gas =
				T::GasMeter::maximum_dispatch_gas_used_at_most(&queued_message.command);
			let reward = pricing_params.rewards.remote;

			// Construct the final committed message
			let message = CommittedMessage {
				channel_id: queued_message.channel_id,
				nonce,
				command,
				params,
				max_dispatch_gas,
				max_fee_per_gas: pricing_params
					.fee_per_gas
					.try_into()
					.defensive_unwrap_or(u128::MAX),
				reward: reward.try_into().defensive_unwrap_or(u128::MAX),
				id: queued_message.id,
			};

			// ABI-encode and hash the prepared message
			let message_abi_encoded = ethabi::encode(&[message.clone().into()]);
			let message_abi_encoded_hash = <T as Config>::Hashing::hash(&message_abi_encoded);

			Messages::<T>::append(Box::new(message));
			MessageLeaves::<T>::append(message_abi_encoded_hash);

			Self::deposit_event(Event::MessageAccepted { id: queued_message.id, nonce });

			Ok(true)
		}

		pub(crate) fn calculate_fee(
			gas_used_at_most: u64,
			params: PricingParameters<T::Balance>,
		) -> Fee<T::Balance> {
			// Remote fee in ether
			let fee = Self::calculate_remote_fee(
				gas_used_at_most,
				params.fee_per_gas,
				params.rewards.remote,
			);

			// downcast to u128
			let fee: u128 = fee.try_into().defensive_unwrap_or(u128::MAX);

			// multiply by multiplier and convert to local currency
			let fee = FixedU128::from_inner(fee)
				.saturating_mul(params.multiplier)
				.checked_div(&params.exchange_rate)
				.expect("exchange rate is not zero; qed")
				.into_inner();

			// adjust fixed point to match local currency
			let fee = Self::convert_from_ether_decimals(fee);

			Fee::from((Self::calculate_local_fee(), fee))
		}

	fn validate(
		message: &Message,
	) -> Result<(Self::Ticket, Fee<<Self as SendMessageFeeProvider>::Balance>), SendError> {
		// The inner payload should not be too large
		let payload = message.command.abi_encode();
		ensure!(
			payload.len() < T::MaxMessagePayloadSize::get() as usize,
			SendError::MessageTooLarge
		);

		// Ensure there is a registered channel we can transmit this message on
		ensure!(T::Channels::contains(&message.channel_id), SendError::InvalidChannel);

		// Generate a unique message id unless one is provided
		let message_id: H256 = message
			.id
			.unwrap_or_else(|| unique((message.channel_id, &message.command)).into());

		let gas_used_at_most = T::GasMeter::maximum_gas_used_at_most(&message.command);
		let fee = Self::calculate_fee(gas_used_at_most, T::PricingParameters::get());

		let queued_message: VersionedQueuedMessage = QueuedMessage {
			id: message_id,
			channel_id: message.channel_id,
			command: message.command.clone(),
		}
		.into();
		// The whole message should not be too large
		let encoded = queued_message.encode().try_into().map_err(|_| SendError::MessageTooLarge)?;

		let ticket = Ticket { message_id, channel_id: message.channel_id, message: encoded };

		Ok((ticket, fee))
	}

		/// Set pricing parameters on both sides of the bridge
		///
		/// Fee required: No
		///
		/// - `origin`: Must be root
		#[pallet::call_index(2)]
		#[pallet::weight((T::WeightInfo::set_pricing_parameters(), DispatchClass::Operational))]
		pub fn set_pricing_parameters(
			origin: OriginFor<T>,
			params: PricingParametersOf<T>,
		) -> DispatchResult {
			ensure_root(origin)?;
			params.validate().map_err(|_| Error::<T>::InvalidPricingParameters)?;
			PricingParameters::<T>::put(params.clone());

			let command = Command::SetPricingParameters {
				exchange_rate: params.exchange_rate.into(),
				delivery_cost: T::InboundDeliveryCost::get().saturated_into::<u128>(),
				multiplier: params.multiplier.into(),
			};
			Self::send(PRIMARY_GOVERNANCE_CHANNEL, command, PaysFee::<T>::No)?;

			Self::deposit_event(Event::PricingParametersChanged { params });
			Ok(())
		}
