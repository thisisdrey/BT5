### Title
Stale, asset-owner-controlled decimals snapshot corrupts PSM swap conversion rate - (`substrate/frame/psm/src/lib.rs`)

### Summary
The external report's core broken invariant is: a contract lets an untrusted caller supply/influence a `decimals` value used in value-critical math, instead of always reading it live from the canonical token. The local analog is `pallet-psm` (Peg Stability Module), which snapshots an external asset's `decimals` into `ExternalAssets` storage at `add_external_asset` time and documents that it is only re-validated against a `PsmInfo` snapshot as a *precondition of listing*, not on every swap. [1](#0-0)  Because ERC20/`pallet-assets`-style metadata (`decimals`) is mutable by the asset's own owner via `set_metadata`/`do_set_metadata` at any later time, the PSM's cached decimals value can silently diverge from the token's true, live decimals after listing. [2](#0-1) [3](#0-2) 

### Finding Description
`add_external_asset` reads the external asset's decimals at listing time and stores it as a fixed value in `ExternalAssets`, as confirmed by the test that shows `stored.decimals == 8` immediately after listing a token whose metadata reports 8 decimals. [4](#0-3)  The pallet's core conversion helper, `external_to_internal`, takes `ext_decimals` and `internal_decimals` as plain parameters and scales the swap amount by `10^(|diff|)` — it does not itself query `T::Fungibles::decimals()` live; it trusts whatever decimals value is handed to it by the caller. [5](#0-4) 

The pallet's own documentation states the live-decimals check ("the external's live decimals must still match the snapshot in `PsmInfo`") is one of the preconditions listed specifically for the `add_external_asset` operation, not for the recurring `mint`/`redeem` swap path. [1](#0-0)  This mirrors the audited Treasury bug exactly: a decimals figure that should always be fetched fresh from the token (`usdt.decimals()`) is instead captured once and reused, and the entity that controls that figure (the asset owner, via `Assets::set_metadata`) is not the entity trusted with PSM governance. [6](#0-5) 

Since `pallet-assets`' `set_metadata` only requires the asset to be `Live` and the caller to be the asset's `owner` — an ordinary, unprivileged account with respect to the PSM instance — the owner of any externally-approved token can unilaterally change `decimals` after the PSM has listed it, without any interaction with or authorization from the PSM's governance/admin roles. [7](#0-6) 

### Impact Explanation
If `mint`/`redeem` continue to use the stale, snapshotted decimals instead of re-deriving them live for every swap, then after an asset owner changes their token's decimals (e.g., from 6 to 18, or 18 to 6), the PSM's `external_to_internal`/`internal_to_external` scaling factor becomes wrong by a power of 10 relative to the token's actual on-chain unit size. [5](#0-4)  This breaks the pallet's fundamental 1:1 peg invariant documented at the top of the module ("A PSM strengthens its internal asset's peg... Reserve: External asset balance... PSM Debt: Total internal asset minted... backed 1:1 by external assets") and lets an attacker who owns (or controls) an approved external token mint internal stablecoin far in excess of what they deposited, or drain the PSM reserve on redemption — a direct theft/unbacked-mint impact against the "conserve value" pivot required by the impact gate. [8](#0-7) 

### Likelihood Explanation
The precondition for exploitation is narrow but realistic and does not require any privileged actor beyond the ordinary owner-role of the external token itself (which is explicitly a normal, non-governance account per `pallet-assets`), so it is not excluded by the "privileged governance or admin abuse" exclusion — the PSM's own admin/governance never authorizes the decimals change; only the token's owner does, and the PSM has no visibility into or control over that action after listing. [7](#0-6)  Likelihood depends on confirming that `mint`/`redeem` actually reuse the stored/snapshotted decimals rather than re-fetching live decimals on each call; I was not able to view the exact `mint`/`redeem` call sites for `external_to_internal` before running out of tool budget, so this should be verified directly against those dispatchables in `substrate/frame/psm/src/lib.rs` before treating this as fully confirmed.

### Recommendation
Remove any decimals caching/snapshot used for swap-time math in `pallet-psm`; instead, have `mint`/`redeem` (and any other value-critical path using `external_to_internal`/`internal_to_external`) always call `T::Fungibles::decimals(asset_id)` live at execution time, exactly mirroring the external report's recommendation to call `usdt.decimals()` directly rather than trusting a caller- or listing-time-supplied value. If a cached value is kept for UX/read-only purposes, it must never be used for balance-affecting conversion; only the live value should feed `external_to_internal`.

### Proof of Concept
1. Governance calls `add_external_asset(internal_asset, usdt_asset_id)` while `usdt_asset_id` has `decimals = 6`; the snapshot `ExternalAssets` entry stores `decimals = 6`. [4](#0-3) 
2. Governance sets a non-zero `AssetCeilingWeight` so minting is enabled, per the PSM setup flow. [9](#0-8) 
3. The USDT asset owner (an unprivileged account w.r.t. the PSM) calls `Assets::set_metadata(usdt_asset_id, ..., decimals = 18)`, which succeeds because they are the asset's `owner` and the asset is `Live`. [10](#0-9) 
4. If `mint`/`redeem` still use the PSM's stale `ext_decimals = 6` snapshot inside `external_to_internal` rather than the live `18`, the scaling factor is off by `10^12`, letting the attacker mint a grossly inflated amount of internal stablecoin for a small USDT deposit (or drain the reserve on redeem), corrupting the PSM's `internal_asset` debt accounting. [5](#0-4) 

Confirming step 4 requires reading the exact `mint`/`redeem` dispatchable bodies in `substrate/frame/psm/src/lib.rs` to verify whether they pass the stored snapshot or a freshly-fetched decimals value into `external_to_internal` — this was not directly observed in the available context and should be checked before treating the finding as fully proven.

	/// Do set metadata
	pub(super) fn do_set_metadata(
		id: T::AssetId,
		from: &T::AccountId,
		name: Vec<u8>,
		symbol: Vec<u8>,
		decimals: u8,
	) -> DispatchResult {
		let bounded_name: BoundedVec<u8, T::StringLimit> =
			name.clone().try_into().map_err(|_| Error::<T, I>::BadMetadata)?;
		let bounded_symbol: BoundedVec<u8, T::StringLimit> =
			symbol.clone().try_into().map_err(|_| Error::<T, I>::BadMetadata)?;

		let d = Asset::<T, I>::get(&id).ok_or(Error::<T, I>::Unknown)?;
		ensure!(d.status == AssetStatus::Live, Error::<T, I>::AssetNotLive);
		ensure!(from == &d.owner, Error::<T, I>::NoPermission);

		Metadata::<T, I>::try_mutate_exists(id.clone(), |metadata| {
			ensure!(metadata.as_ref().map_or(true, |m| !m.is_frozen), Error::<T, I>::NoPermission);

			let old_deposit = metadata.take().map_or(Zero::zero(), |m| m.deposit);
			let new_deposit = Self::calc_metadata_deposit(&name, &symbol);

			if new_deposit > old_deposit {
				T::Currency::reserve(from, new_deposit - old_deposit)?;
			} else {
				T::Currency::unreserve(from, old_deposit - new_deposit);
			}

			*metadata = Some(AssetMetadata {
				deposit: new_deposit,
				name: bounded_name,
				symbol: bounded_symbol,
				decimals,
				is_frozen: false,
			});

//! ## Overview
//!
//! A PSM strengthens its internal asset's peg by providing arbitrage opportunities:
//! - When the internal asset trades **above** $1: Users swap external assets for the internal asset
//!   and sell for profit.
//! - When the internal asset trades **below** $1: Users buy cheap internal asset and swap for
//!   external assets.
//!
//! This creates a price corridor bounded by the minting and redemption fees.
//!
//! ### Key Concepts
//!
//! * **PSM instance**: A configured Peg Stability Module, keyed by its internal asset id and
//!   described by [`PsmInfo`]. Each instance has its own reserve account derived from
//!   `blake2_256((PalletId::TYPE_ID, PalletId, internal_asset).encode())`.
//! * **Minting**: Deposit external asset → receive internal asset (minus fee).
//! * **Redemption**: Burn internal asset → receive external asset (minus fee).
//! * **Reserve**: External asset balance held by a PSM's reserve account (derived, not stored).
//! * **PSM Debt**: Total internal asset minted through a PSM, backed 1:1 by external assets in that
//!   PSM's reserve.
//! * **Circuit Breaker**: Per-external emergency control to disable minting or all swaps.

		/// Convert an amount denominated in external-asset units into internal units.
		///
		/// Scales by `10^(ext_decimals - internal_decimals)` — multiplies up when internal has more
		/// decimals, floor-divides when it has fewer. Returns [`Error::ConversionOverflow`] if
		/// the scaling factor or the product does not fit in the balance type.
		pub(crate) fn external_to_internal(
			amount: BalanceOf<T>,
			ext_decimals: u8,
			internal_decimals: u8,
		) -> Result<BalanceOf<T>, Error<T>> {
			use core::cmp::Ordering::*;
			match ext_decimals.cmp(&internal_decimals) {
				Equal => Ok(amount),
				Less => {
					let diff = (internal_decimals - ext_decimals) as u32;
					let factor = Self::pow10(diff)?;
					amount.checked_mul(&factor).ok_or(Error::<T>::ConversionOverflow)
				},
				Greater => {
					let diff = (ext_decimals - internal_decimals) as u32;
					let factor = Self::pow10(diff)?;
					Ok(amount.checked_div(&factor).unwrap_or_else(BalanceOf::<T>::zero))
				},
			}
		}
