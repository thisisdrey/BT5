### Title
Cross-StackerDB chunk signature replay due to missing contract-identifier binding in `SlotMetadata::auth_digest` - (File: `libstackerdb/src/libstackerdb.rs`)

### Summary
`SlotMetadata::auth_digest` (and thus every chunk signature verified in `try_replace_chunk` and `validate_received_chunk`) is computed only from `slot_id`, `slot_version`, and `data_hash` [1](#0-0) . The signature never binds to the `QualifiedContractIdentifier` (the specific StackerDB replica) it was created for. Any signer registered with the same slot ID in more than one StackerDB contract can therefore have a chunk they legitimately signed for contract A silently accepted and stored under contract B, because the storage/verification path only checks `slot_desc.verify(&slot_validation.signer)` against the locally-loaded signer for that contract, never that the message was actually meant for that contract [2](#0-1) .

### Finding Description
This is the same class of bug as the external report: the Gnosis Safe deployment used a `create2` salt that failed to uniquely bind the deployment to "this rollup", allowing a colliding/front-run deployment from an unrelated context to interfere with the target. Here, the StackerDB chunk-authentication scheme fails to uniquely bind a signature to "this StackerDB contract", allowing a chunk that is valid (and was broadcast) for one StackerDB replica to be replayed as valid for a different StackerDB replica that happens to reuse the same signer key at the same slot index.

Concretely:
- `SlotMetadata::sign`/`verify` operate over `auth_digest()`, which hashes only `slot_id`, `slot_version`, and `data_hash` [3](#0-2) .
- Both the push-side gossip validator `PeerNetwork::validate_received_chunk` [4](#0-3)  and the storage layer `StackerDBTx::try_replace_chunk` [2](#0-1)  and the HTTP write path `poststackerdbchunk.rs` all resolve the *contract-local* signer address for the slot and check `slot_desc.verify(&signer)`, but the digest being verified says nothing about which contract it belongs to.
- StackerDB signer/slot assignment is driven per-contract by smart contracts (e.g. `.signers-0-XXX`, `.signers-1-XXX`, custom app StackerDB contracts) [5](#0-4) , and it is entirely plausible/likely for the same principal (a stacker/signer address) to be assigned the same slot index across multiple distinct StackerDB replicas over time or concurrently (e.g. across the `stackerdb-signer-slots-0`/`-1` pages, or across an app's separate StackerDB contracts for the same operator) [6](#0-5) .

Because nothing in the signed payload distinguishes contract A from contract B, an unprivileged network participant who observes a legitimately signed, broadcast chunk (chunks are gossiped in the clear over the P2P StackerDB sync/push protocol) can resubmit that exact `StackerDBChunkData` to a *different* StackerDB replica that shares the signer/slot mapping, as long as the target replica's currently stored version for that slot is lower than the replayed version. The replayed write will pass every check — size, signer-verify, staleness, max-writes — and get accepted, stored, and re-broadcast by the receiving node [7](#0-6) .

### Impact Explanation
This breaks the equality the protocol is supposed to enforce: "this signature authenticates writes to *this specific* StackerDB contract's slot," when in fact it only authenticates "some slot with this ID and version, in some StackerDB." An attacker with no privileged key can inject cross-context, forged-appearing data into an unrelated StackerDB replica and have it propagate network-wide via the normal chunk-broadcast path, matching the Critical-tier "unauthenticated/unauthorized write to state or StackerDB" and "network-wide propagation of forged data" categories.

### Likelihood Explanation
Exploitation requires only: (1) observing one legitimately-broadcast chunk (trivial — StackerDB chunks are public gossip data), and (2) a target StackerDB contract that happens to assign the same signer principal to the same slot index as the source contract, with a currently-stored version lower than the replayed chunk's version. Because slot assignment is entirely contract-controlled and there is no cross-contract domain separation anywhere in the signing/verification code, this condition is a matter of configuration/coincidence rather than a cryptographic barrier — the flaw is structural, not probabilistic.

### Recommendation
Bind the signed digest to the target StackerDB context, e.g. include the `QualifiedContractIdentifier` (and ideally the reward cycle / configuration version) as an additional field hashed into `SlotMetadata::auth_digest`, and update `sign`/`verify` call sites (`SlotMetadata`, `StackerDBChunkData`) accordingly so a signature can never be replayed across different StackerDB contracts.

### Proof of Concept
1. Attacker observes a valid `StackerDBChunkData` (`slot_id=k`, `slot_version=v`, `sig`, `data`) broadcast for contract `A`, where `A`'s slot `k` is owned by signer `S`.
2. Attacker identifies (or waits for) a second StackerDB contract `B` in which slot `k` is also owned by the same signer `S`, and whose currently stored version for slot `k` is `< v`.
3. Attacker submits the identical `StackerDBChunkData` to a node serving `B` (via `POST /v2/stackerdb/.../chunks` or via P2P `StackerDBPushChunk`).
4. `try_replace_chunk`/`validate_received_chunk` for `B` load `B`'s signer for slot `k` (which is `S`), verify `slot_desc.verify(&S)` — which succeeds because the digest never referenced contract `A` or `B` — pass the staleness/max-writes checks, and accept and re-broadcast the chunk under contract `B`.     /// Get the digest to sign that authenticates this chunk data and metadata
    fn auth_digest(&self) -> Sha512Trunc256Sum {
        let mut hasher = Sha512_256::new();
        hasher.update(self.slot_id.to_be_bytes());
        hasher.update(self.slot_version.to_be_bytes());
        hasher.update(self.data_hash.0);
        Sha512Trunc256Sum::from_hasher(hasher)
    }

    /// Sign this slot metadata, committing to slot_id, slot_version, and
    /// data_hash.  Sets self.signature to the signature.
    /// Fails if the underlying crypto library fails
    pub fn sign(&mut self, privkey: &StacksPrivateKey) -> Result<(), Error> {
        let auth_digest = self.auth_digest();
        let sig = privkey
            .sign(&auth_digest.0)
            .map_err(|se| Error::SigningError(se.to_string()))?;

        self.signature = sig;
        Ok(())
    }

    /// Verify that a given principal signed this chunk metadata.
    /// Note that the address version is ignored.
    pub fn verify(&self, principal: &StacksAddress) -> Result<bool, Error> {
        let sigh = self.auth_digest();
        let pubk = StacksPublicKey::recover_to_pubkey_without_validating_low_s(
            sigh.as_bytes(),
            &self.signature,
        )
        .map_err(|ve| Error::VerifyingError(ve.to_string()))?;

        let pubkh = Hash160::from_node_public_key(&pubk);
        Ok(pubkh == *principal.bytes())
    }

    /// Add or replace a chunk for a given reward cycle, if it is valid
    /// Otherwise, this errors out with Error::StaleChunk
    pub fn try_replace_chunk(
        &self,
        smart_contract: &QualifiedContractIdentifier,
        slot_desc: &SlotMetadata,
        chunk: &[u8],
    ) -> Result<(), net_error> {
        // Check per-replica chunk-size cap.
        if (chunk.len() as u64) > self.config.chunk_size {
            return Err(net_error::StackerDBChunkTooBig(chunk.len()));
        }

        let slot_validation = self
            .get_slot_validation(smart_contract, slot_desc.slot_id)?
            .ok_or(net_error::NoSuchSlot(
                smart_contract.clone(),
                slot_desc.slot_id,
            ))?;

        if !slot_desc.verify(&slot_validation.signer)? {
            return Err(net_error::BadSlotSigner(
                slot_validation.signer,
                slot_desc.slot_id,
            ));
        }
        if slot_desc.slot_version <= slot_validation.version {
            return Err(net_error::StaleChunk {
                supplied_version: slot_desc.slot_version,
                latest_version: slot_validation.version,
            });
        }
        if slot_desc.slot_version > self.config.max_writes {
            return Err(net_error::TooManySlotWrites {
                supplied_version: slot_desc.slot_version,
                latest_version: slot_validation.version,
                max_writes: self.config.max_writes,
            });
        }
        self.insert_chunk(smart_contract, slot_desc, chunk)
    }

    pub fn validate_received_chunk(
        &self,
        smart_contract_id: &QualifiedContractIdentifier,
        config: &StackerDBConfig,
        data: &StackerDBChunkData,
        expected_versions: &[u32],
    ) -> Result<bool, net_error> {
        // validate -- must not exceed this replica's configured chunk size.
        if (data.data.len() as u64) > config.chunk_size {
            info!(
                "Received StackerDBChunk for {} ID {}, which is oversized: {} bytes (max {} bytes)",
                smart_contract_id,
                data.slot_id,
                data.data.len(),
                config.chunk_size
            );
            return Ok(false);
        }

        // validate -- must be a valid chunk
        let Some(expected_version) = expected_versions.get(data.slot_id as usize) else {
            info!(
                "Received StackerDBChunk for {} ID {}, which is too big ({})",
                smart_contract_id,
                data.slot_id,
                expected_versions.len()
            );
            return Ok(false);
        };

        // validate -- must be signed by the expected author
        let addr = match self
            .stackerdbs
            .get_slot_signer(smart_contract_id, data.slot_id)?
        {
            Some(addr) => addr,
            None => {
                return Ok(false);
            }
        };

        let slot_metadata = data.get_slot_metadata();
        if !slot_metadata.verify(&addr)? {
            info!(
                "StackerDBChunk for {} ID {} is not signed by {}",
                smart_contract_id, data.slot_id, &addr
            );
            return Ok(false);
        }

        // validate -- must be the current or newer version
        if data.slot_version < *expected_version {
            info!(
                "Received StackerDBChunk for {} ID {} version {}, which is stale (expected {})",
                smart_contract_id, data.slot_id, data.slot_version, *expected_version
            );
            return Ok(false);
        }

        // validate -- must not exceed max writes
        if data.slot_version > config.max_writes {
            info!(
                "Write count exceeded for StackerDBChunk for {} ID {} version {} (max is {})",
                smart_contract_id, data.slot_id, data.slot_version, config.max_writes
            );
            return Ok(false);
        }

        Ok(true)
    }
