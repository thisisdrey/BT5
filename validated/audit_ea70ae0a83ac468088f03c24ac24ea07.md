### Title
Integer overflow in reftable ref-block varint parsing causes out-of-bounds slice panic - ([File: internal/git/reftable/reftable.go])

### Summary
`internal/git/reftable/reftable.go`'s `getRefsFromBlock` parses reftable ref-block records using `getVarInt` to decode attacker-influenced `prefixLength`, `suffixLength`, and symref `size` values, then uses them directly in slice expressions (`prefix[:prefixLength]`, `src[idx:idx+suffixLength]`, `src[idx:idx+size]`) without checking for integer overflow of the addition, mirroring the Vyper `slice()` bug where `start+length` can overflow and bypass the bounds `assert`.

### Finding Description
`getVarInt` decodes a base-128 varint with no cap on magnitude: [1](#0-0) 
Because `val` is a native Go `uint`, repeated continuation bytes make `val = ((val + 1) << 7) | ...` wrap silently (Go integer overflow is well-defined but unchecked) — there is no upper bound comparison against the block/table size, only a check that parsing doesn't run past `blockEnd`. This lets a crafted reftable produce an arbitrarily large `prefixLength`/`suffixLength`/`size`.

Those values then flow straight into slice arithmetic in `getRefsFromBlock`: [2](#0-1) [3](#0-2) 
`idx + suffixLength` (or `idx + size`) is computed exactly like the Vyper report's `start + length`: an unchecked, overflow-prone addition feeding a slice bound. If `suffixLength`/`size` is large enough that `idx + suffixLength` wraps around the 64-bit `uint` space, the resulting high-bound can become smaller than `idx` (or otherwise inconsistent with the real buffer length `len(src)`), which Go's runtime slice-bounds-check will reject with a panic (`slice bounds out of range`), or, in cases where the wrapped value still satisfies `low <= high <= cap(src)`, produce a bogus record read that is silently accepted as valid ref data.

`getRefsFromBlock` is reached via `Table.GetReferences` → `parseRefBlock`: [4](#0-3) [5](#0-4) 
`GetReferences`/`ParseTable` are used in `internal/gitaly/service/ref/list_refs_test.go`, `internal/backup/repository.go`, and `internal/gitaly/service/repository/replicate.go` — i.e. reftable files are parsed whenever Gitaly reads refs from a repository's `reftable` backend, including on repository replication and backup, both of which process reftable files that ultimately originate from a client's push/fetch traffic or replicated repository state (an ordinary, unprivileged actor controls repository content via normal Git operations, and Git writes ref updates it receives into these reftable files).

### Impact Explanation
An attacker able to get a crafted reftable persisted into a repository (via ordinary push/ref-update flows or a repository that gets replicated/backed up) can trigger an out-of-bounds slice panic when Gitaly later parses the table with `GetReferences`, crashing the RPC handler goroutine (denial of service for `ListRefs`, replication, or backup operations on that repository). This matches "DoS of a handler," one of the accepted analog categories.

### Likelihood Explanation
Reftable-backed repositories are read by common RPCs (`ListRefs`), by replication, and by backup, so any repository containing a maliciously-crafted reftable file will be parsed by these code paths without additional privilege. The bug requires a crafted `.ref` table file already present on disk, which is a realistic scenario for a compromised/malicious replica or synthetically constructed repository ingested via replication/import.

### Recommendation
Bound-check varint decoding in `getVarInt` against a sane maximum (e.g. `math.MaxUint32` or remaining block size) and reject values that would overflow, and replace all `idx + length`-style slice arithmetic in `getRefsFromBlock`/`parseRefBlock` with overflow-safe checks (e.g. verify `length <= blockEnd - idx` before computing `idx + length`) before using the sums as slice bounds, returning a parse error rather than allowing wraparound.

### Proof of Concept
1. Construct a reftable ref block whose varint-encoded `suffixLength` field is composed of a long chain of continuation bytes (`0x80`-prefixed) such that, per `getVarInt`'s `val = ((val+1)<<7) | ...` recurrence, the accumulated `uint` value overflows/wraps near `2^64`.
2. Place this crafted block as a `.ref` file for a repository (e.g. by pushing ref updates that Git's reftable backend materializes, or by delivering the crafted table through replication).
3. Trigger `ListRefs`, `Backup`, or replication on that repository so Gitaly calls `Table.GetReferences` → `parseRefBlock` → `getRefsFromBlock`.
4. Observe that `idx + suffixLength` in `refname := prefix[:prefixLength] + string(src[idx:idx+suffixLength])` produces an out-of-range slice expression, panicking the handling goroutine.

Note: I was unable to fully trace every reftable ingestion path (e.g., how exactly a client-supplied push results in on-disk reftable content, since Git itself — not Gitaly — writes reftables); confirming the precise remote-trigger chain end-to-end would benefit from a live Devin session with repository/test execution access.

func (t *Table) getVarInt(src []byte, start uint, blockEnd uint) (uint, uint, error) {
	var val uint

	val = uint(src[start]) & 0x7f

	for (uint(src[start]) & 0x80) > 0 {
		start++
		if start > blockEnd {
			return 0, 0, fmt.Errorf("exceeded block length")
		}

		val = ((val + 1) << 7) | (uint(src[start]) & 0x7f)
	}

	return start + 1, val, nil
}

// all the reference updates.
func (t *Table) parseRefBlock(src []byte, headerOffset, blockStart, blockEnd uint) ([]git.Reference, error) {
	currentBS := t.extractBlockLen(src, blockStart+headerOffset)

	fullBlockSize := t.blockSize
	if fullBlockSize == 0 {
		fullBlockSize = currentBS
	} else if currentBS < fullBlockSize && currentBS < (blockEnd-blockStart) && src[blockStart+currentBS] != 0 {
		fullBlockSize = currentBS
	}

	b := &block{
		BlockStart:    blockStart + headerOffset,
		FullBlockSize: fullBlockSize,
	}

	if err := binary.Read(bytes.NewBuffer(src[blockStart+currentBS-2:]), binary.BigEndian, &b.RestartCount); err != nil {
		return nil, fmt.Errorf("reading restart count: %w", err)
	}

	b.RestartStart = blockStart + currentBS - 2 - 3*uint(b.RestartCount)

	return t.getRefsFromBlock(src, b)
}

// GetReferences returns all references from the table.
func (t *Table) GetReferences() ([]git.Reference, error) {
	headerOffset := uint(t.footer.Version.HeaderSize())
	offset := uint(0)
	var allRefs []git.Reference

	if _, err := t.src.Seek(0, io.SeekStart); err != nil {
		return nil, fmt.Errorf("seek start: %w", err)
	}

	src, err := io.ReadAll(t.src)
	if err != nil {
		return nil, fmt.Errorf("read all: %w", err)
	}

	for offset < t.footerOffset {
		blockStart, blockEnd := t.getBlockRange(offset, t.blockSize)
		if blockStart == 0 && blockEnd == 0 {
			break
		}

		// If we run out of ref blocks, we can stop the iteration.
		if src[blockStart+headerOffset] != 'r' {
			return allRefs, nil
		}

		references, err := t.parseRefBlock(src, headerOffset, blockStart, blockEnd)
		if err != nil {
			return nil, fmt.Errorf("parsing block: %w", err)
		}

		if len(references) == 0 {
			break
		}

		allRefs = append(allRefs, references...)

		offset = blockEnd
	}

	return allRefs, nil
}
