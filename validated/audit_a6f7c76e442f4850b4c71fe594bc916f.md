## Analog Found

### Title
Unbounded, attacker-growable `VotesStore` iteration causes DoS of `Wallet.getPaginatedNowWitnessList` and of block-time maintenance processing - (File: `framework/src/main/java/org/tron/core/Wallet.java`, `consensus/src/main/java/org/tron/consensus/dpos/MaintenanceManager.java`)

### Summary
`VoteWitnessActuator` lets any funded account create a permanent (until next maintenance) entry in `VotesStore`, and casting a vote costs zero fee. `Wallet.countVote(VotesStore)` and `MaintenanceManager.countVote(VotesStore)` both iterate the **entire** `VotesStore` with no bound, once per public API call (`getPaginatedNowWitnessList`) and once per maintenance cycle (`doMaintenance`, executed synchronously during block application). Because the store's size is fully attacker-controlled and never capped, this is the same "unbounded loop length DoS" bug class as the referenced Canto finding, but reachable through a free, unprivileged transaction, and impacting both a public query API and core block-application logic.

### Finding Description
- `VoteWitnessActuator.calcFee()` returns `0` [1](#0-0) , and `execute()` unconditionally calls `countVoteAccount`, which creates/updates one `VotesCapsule` entry keyed by the voter's address in `VotesStore` [2](#0-1) .
- `validate()` only requires that the voter's own `tronPower` (frozen balance) covers the votes cast; it places no limit on the total number of distinct voting accounts network-wide [3](#0-2) . Any number of sybil accounts can each freeze a minimal amount (temporarily locked, not burned) and cast a free vote, each adding a new entry to `VotesStore`.
- `Wallet.countVote(VotesStore)`, used by the public `getPaginatedNowWitnessList` RPC/HTTP endpoint, iterates every entry of `VotesStore` on **every single call**: `Iterator<Entry<byte[], VotesCapsule>> dbIterator = votesStore.iterator(); while (dbIterator.hasNext()) { ... }` [4](#0-3) . This has no pagination or size cap, unlike the surrounding witness-list pagination logic.
- `MaintenanceManager.countVote(VotesStore)` performs the same unbounded full-table scan (plus a delete per entry) but runs **inside block application**, invoked automatically from `doMaintenance()` every maintenance cycle [5](#0-4) , itself called from `applyBlock` when the maintenance time is reached [6](#0-5) .
- There is no mechanism to cap, batch, or incrementally process `VotesStore`; entries only get cleared as a side effect of the very same unbounded loop in `doMaintenance()`, so between maintenance cycles the store can grow arbitrarily from attacker-submitted, essentially free vote transactions.

### Impact Explanation
Because casting a vote costs 0 TRX in fees, and only requires a small, temporary stake (not burned, refundable via unfreeze) per sybil account, an attacker can grow `VotesStore` to an arbitrarily large size within a single maintenance epoch at very low real cost — cheaper than the analogous Canto scenario, which required significant, un-recoverable liquidity. The consequences are twofold:
1. `Wallet.getPaginatedNowWitnessList` is a publicly reachable query endpoint; every call becomes O(n) in the number of sybil-inflated `VotesStore` entries, letting any anonymous API client degrade or effectively deny this API to legitimate users by driving n up and then hammering the endpoint.
2. `MaintenanceManager.doMaintenance()` runs synchronously as part of block application every maintenance cycle. A sufficiently large `VotesStore` increases the time spent inside block processing, risking missed block-production slots or a stalled node during maintenance — a chain-availability risk analogous to (and more severe than) the referenced admin-only `setPeriodSize` DoS, since here the affected code path is triggered automatically for every node on every maintenance boundary rather than by an admin-only, rarely-invoked call.

### Likelihood Explanation
The attack requires only ordinary, unprivileged transactions (`FreezeBalanceContract`/`FreezeBalanceV2Contract` plus `VoteWitnessContract`) that anyone with minimal TRX can broadcast; the vote itself is free (`calcFee() == 0`), and the frozen stake is recoverable after the unfreeze period, so capital is only temporarily locked, not spent. No special privileges (SR, witness, committee) are required, matching the permitted "unprivileged transaction broadcaster" threat model.

### Recommendation
- Cap the number of distinct entries `VotesStore` can accumulate per epoch, or require a non-zero fee for `VoteWitnessContract` proportional to vote count, to make sybil growth economically costly.
- Make `Wallet.countVote` and `MaintenanceManager.countVote` bounded/paginated (e.g., process in fixed-size batches across multiple calls/blocks) rather than a single unbounded full-table scan, mirroring the incremental approach already used elsewhere (e.g., market order pagination with `MARKET_COUNT_LIMIT_MAX`).
- Consider processing `doMaintenance()`'s vote tally incrementally across several blocks if `VotesStore` size exceeds a safety threshold, so a single maintenance boundary cannot stall block application.

### Proof of Concept
1. Create N funded accounts (only enough TRX for account activation + minimal freeze, e.g. 1 TRX each).
2. From each account, submit `FreezeBalanceV2Contract` freezing 1 TRX, then `VoteWitnessContract` voting 1 vote for any existing witness. The vote transaction costs 0 fee per `VoteWitnessActuator.calcFee()` [1](#0-0) .
3. Repeat for N in the millions within one maintenance epoch (~6 hours); each vote adds/updates a distinct key in `VotesStore` via `countVoteAccount` [2](#0-1) .
4. Repeatedly call the `getPaginatedNowWitnessList` API/RPC; observe response latency scale linearly with N due to the full `VotesStore` scan in `Wallet.countVote` [4](#0-3) .
5. When the maintenance boundary is crossed, observe `MaintenanceManager.doMaintenance()`'s `countVote` performing the same O(N) scan-and-delete synchronously inside block application [5](#0-4) , delaying that block's processing proportionally to N.

    AccountStore accountStore = chainBaseManager.getAccountStore();
    VotesStore votesStore = chainBaseManager.getVotesStore();
    MortgageService mortgageService = chainBaseManager.getMortgageService();
    byte[] ownerAddress = voteContract.getOwnerAddress().toByteArray();

    VotesCapsule votesCapsule;

    //
    mortgageService.withdrawReward(ownerAddress);

    AccountCapsule accountCapsule = accountStore.get(ownerAddress);

    DynamicPropertiesStore dynamicStore = chainBaseManager.getDynamicPropertiesStore();
    if (dynamicStore.supportAllowNewResourceModel()
        && accountCapsule.oldTronPowerIsNotInitialized()) {
      accountCapsule.initializeOldTronPower();
    }

    if (!votesStore.has(ownerAddress)) {
      votesCapsule = new VotesCapsule(voteContract.getOwnerAddress(),
          accountCapsule.getVotesList());
    } else {
      votesCapsule = votesStore.get(ownerAddress);
    }

    accountCapsule.clearVotes();
    votesCapsule.clearNewVotes();

    voteContract.getVotesList().forEach(vote -> {
      logger.debug("countVoteAccount, address[{}]",
          ByteArray.toHexString(vote.getVoteAddress().toByteArray()));

      votesCapsule.addNewVotes(vote.getVoteAddress(), vote.getVoteCount());
      accountCapsule.addVotes(vote.getVoteAddress(), vote.getVoteCount());
    });

    accountStore.put(accountCapsule.createDbKey(), accountCapsule);
    votesStore.put(ownerAddress, votesCapsule);
  }

  private Map<ByteString, Long> countVote(VotesStore votesStore) {
    // Initialize a result map to store vote changes for each witness
    Map<ByteString, Long> countWitness = Maps.newHashMap();

    // VotesStore is a key-value store, where the key is the address of the voter
    Iterator<Entry<byte[], VotesCapsule>> dbIterator = votesStore.iterator();

    while (dbIterator.hasNext()) {
      Entry<byte[], VotesCapsule> next = dbIterator.next();
      VotesCapsule votes = next.getValue();

      /**
       * VotesCapsule contains two lists:
       * - Old votes: Last votes from the previous epoch, updated in maintenance period
       * - New votes: Latest votes in current epoch, updated after each vote transaction
       */
      votes.getOldVotes().forEach(vote -> {
        ByteString voteAddress = vote.getVoteAddress();
        long voteCount = vote.getVoteCount();
        countWitness.put(voteAddress,
            countWitness.getOrDefault(voteAddress, 0L) - voteCount);
      });
      votes.getNewVotes().forEach(vote -> {
        ByteString voteAddress = vote.getVoteAddress();
        long voteCount = vote.getVoteCount();
        countWitness.put(voteAddress,
            countWitness.getOrDefault(voteAddress, 0L) + voteCount);
      });
    }
    return countWitness;

  private Map<ByteString, Long> countVote(VotesStore votesStore) {
    final Map<ByteString, Long> countWitness = Maps.newHashMap();
    Iterator<Entry<byte[], VotesCapsule>> dbIterator = votesStore.iterator();
    long sizeCount = 0;
    while (dbIterator.hasNext()) {
      Entry<byte[], VotesCapsule> next = dbIterator.next();
      VotesCapsule votes = next.getValue();
      votes.getOldVotes().forEach(vote -> {
        ByteString voteAddress = vote.getVoteAddress();
        long voteCount = vote.getVoteCount();
        if (countWitness.containsKey(voteAddress)) {
          countWitness.put(voteAddress, countWitness.get(voteAddress) - voteCount);
        } else {
          countWitness.put(voteAddress, -voteCount);
        }
      });
      votes.getNewVotes().forEach(vote -> {
        ByteString voteAddress = vote.getVoteAddress();
        long voteCount = vote.getVoteCount();
        if (countWitness.containsKey(voteAddress)) {
          countWitness.put(voteAddress, countWitness.get(voteAddress) + voteCount);
        } else {
          countWitness.put(voteAddress, voteCount);
        }
      });
      sizeCount++;
      votesStore.delete(next.getKey());
    }
    logger.info("There is {} new votes in this epoch", sizeCount);
    return countWitness;
  }
