### Title
Missing Authorization Enforcement of `node.disabledApi` on JSON-RPC Endpoints - (File: `framework/src/main/java/org/tron/core/services/jsonrpc/FullNodeJsonRpcHttpService.java`)

### Summary
java-tron lets an operator restrict sensitive read APIs (account data, blocks, transactions) via `node.disabledApi`, enforced by `HttpApiAccessFilter` for HTTP and `RpcApiAccessInterceptor` for gRPC/PBFT. This enforcement is never wired into the JSON-RPC (Ethereum-compatible) HTTP server, so any address/account/transaction/block query an operator intends to shut off remains fully queryable via the equivalent `eth_*` JSON-RPC method — mirroring the GitLab CVE-2025-6171 pattern where an access restriction on one API surface (repository access) did not propagate to a functionally equivalent alternate API surface (packages API).

### Finding Description
`node.disabledApi` is documented as a general-purpose way "to disable an API endpoint that you do not want to expose publicly" [3](#0-2) , and the reference config explicitly states the mechanism "works for http, rpc and pbft, not jsonrpc" [4](#0-3) .

The enforcement is implemented by two components:
- `HttpApiAccessFilter.isDisabled`, wired via `FullNodeHttpApiService.addFilter` onto `/wallet/*`, `/net/listnodes`, `/monitor/getstatsinfo`, `/monitor/getnodeinfo` [5](#0-4) 
- `RpcApiAccessInterceptor.isDisabled`, wired as a gRPC server interceptor [6](#0-5) 

`FullNodeJsonRpcHttpService`, which serves the Ethereum-compatible `eth_*` methods through `TronJsonRpcImpl` (e.g. `getTrxBalance`, `getTransactionByHash`, `ethGetBlockByNumber`, `getABIOfSmartContract`), only installs `HttpInterceptor` in `addFilter` and never installs `HttpApiAccessFilter` [7](#0-6) . The same gap applies to `JsonRpcOnSolidityServlet`/`JsonRpcOnPBFTServlet`, since `RpcApiAccessInterceptor` is a gRPC interceptor and JSON-RPC does not go through gRPC. Because both `TronJsonRpcImpl` (`eth_getBalance` → `getTrxBalance`, `eth_getTransactionByHash` → `getTransactionByHash`, `eth_getBlockByNumber`/`eth_getBlockByHash`) and the corresponding disabled HTTP servlets (`GetAccountServlet` for `getaccount`, `GetTransactionByIdServlet` for `gettransactionbyid`, `GetBlockByNumServlet`/`GetNowBlockServlet`) read from the same `Wallet` data layer, any address, account balance, transaction, or block information an operator disables via `node.disabledApi` is still fully retrievable through the equivalent JSON-RPC method with zero authorization gate. [8](#0-7) 

### Impact Explanation
This is an information-exposure / missing-authorization bug: an operator who has explicitly restricted an API surface for privacy, compliance, or DoS-mitigation reasons believes the data is inaccessible, but any anonymous JSON-RPC client can still retrieve it through an equivalent Ethereum-style method. This matches the analog scope (anonymous API client reaching the query path into Wallet/TronJsonRpcImpl) and the CVE bug class (an access-control setting on one endpoint not honored on an alternate endpoint serving equivalent data). Severity is Medium: it is confined to read-only data disclosure and does not itself enable fund theft, RCE, or consensus impact, but it is a real, concretely reachable violation of an intended access-control boundary that a node operator relies on.

### Likelihood Explanation
High likelihood of reachability: JSON-RPC is enabled via a simple config flag (`node.jsonrpc.httpFullNodeEnable`) that many production nodes turn on for Ethereum-tooling compatibility [9](#0-8) , and no authentication or permission is required to call `eth_getBalance`/`eth_getTransactionByHash`/`eth_getBlockByNumber` — this is a pure unauthenticated HTTP JSON-RPC request path.

### Recommendation
Wire `HttpApiAccessFilter` (or an equivalent disabled-API check that maps `eth_*` method names to their `node.disabledApi` equivalents) into `FullNodeJsonRpcHttpService.addFilter`, `JsonRpcOnSolidityServlet`, and `JsonRpcOnPBFTServlet` so the same operator-configured restriction applies consistently across HTTP, gRPC, and JSON-RPC surfaces.

### Proof of Concept
1. Configure `node.disabledApi = ["getaccount"]` and confirm `GET /wallet/getaccount?address=...` returns `{"Error":"this API is unavailable due to config"}` as validated by the existing test `HttpApiAccessFilterTest.testHttpFilter` [10](#0-9) .
2. Enable `node.jsonrpc.httpFullNodeEnable = true`.
3. Send a JSON-RPC request `{"method":"eth_getBalance","params":["<address>","latest"]}` to `/jsonrpc` on the same node — the request succeeds and returns the account balance despite `getaccount` being in `disabledApi`, because `FullNodeJsonRpcHttpService` never applies `HttpApiAccessFilter` [7](#0-6) .

  private boolean isDisabled(String endpoint) {
    boolean disabled = false;

    try {
      endpoint = URI.create(endpoint).normalize().toString();
      List<String> disabledApiList = CommonParameter.getInstance().getDisabledApiList();
      if (!disabledApiList.isEmpty()) {
        disabled = disabledApiList.contains(endpoint.split("/")[2].toLowerCase(Locale.ROOT));
      }
    } catch (Exception e) {
      logger.warn("check isDisabled except, endpoint={}, {}", endpoint, e.getMessage());
    }

    return disabled;
  }

  @Override
  public <ReqT, RespT> Listener<ReqT> interceptCall(ServerCall<ReqT, RespT> call,
      Metadata headers,
      ServerCallHandler<ReqT, RespT> next) {

    String endpoint = call.getMethodDescriptor().getFullMethodName();

    try {
      if (isDisabled(endpoint)) {
        call.close(Status.UNAVAILABLE
            .withDescription("this API is unavailable due to config"), headers);
        return new ServerCall.Listener<ReqT>() {};

      } else {
        return next.startCall(call, headers);
      }
    } catch (Exception e) {
      logger.error("check rpc api access Error: {}", e.getMessage());
      return next.startCall(call, headers);
    }
  }

  @Override
  public TransactionResult getTransactionByHash(String txId) throws JsonRpcInvalidParamsException {
    ByteString transactionId = ByteString.copyFrom(hashToByteArray(txId));

    TransactionInfo transactionInfo = wallet.getTransactionInfoById(transactionId);
    if (transactionInfo == null) {
      TransactionCapsule transactionCapsule = wallet.getTransactionCapsuleById(transactionId);
      if (transactionCapsule == null) {
        return null;
      }

      BlockCapsule blockCapsule = wallet.getBlockCapsuleByNum(transactionCapsule.getBlockNum());
      if (blockCapsule == null) {
        return new TransactionResult(transactionCapsule.getInstance(), wallet);
      } else {
        int transactionIndex = getTransactionIndex(
            ByteArray.toHexString(transactionCapsule.getTransactionId().getBytes()),
            blockCapsule.getInstance().getTransactionsList());

        if (transactionIndex == -1) {
          return null;
        }

        long energyUsageTotal = 0;
        return new TransactionResult(blockCapsule, transactionIndex,
            transactionCapsule.getInstance(), energyUsageTotal,
            wallet.getEnergyFee(blockCapsule.getTimeStamp()), wallet);
      }
    } else {
      Block block = wallet.getBlockByNum(transactionInfo.getBlockNumber());
      if (block == null) {
        return null;
      }

      return formatTransactionResult(transactionInfo, block);
    }
  }
