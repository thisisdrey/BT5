## Finding

### Title
StackerDB Chunk Signatures Omit the Target Contract Identifier, Enabling Cross-Contract Chunk Replay - (File: `libstackerdb/src/libstackerdb.rs`)

### Summary
`SlotMetadata::auth_digest()` computes the digest that a signer signs over `(slot_id, slot_version, data_hash)` only — it never includes the target `smart_contract_id` (StackerDB instance). Because the `.signers-{set}-{message_id}` boot contracts all derive their `(signer, slot_id)` layout from the same underlying `signers` contract list (keyed only by signer-set page, not by `message_id`), every signer occupies the *same* `slot_id` across all sibling message-lane contracts for a signer set. A chunk legitimately signed and published for one contract (e.g. the `BlockResponse` lane) is therefore also a validly-signed chunk for any other sibling contract at the same slot, and can be replayed there.

### Finding Description
The signature commitment is built here: [1](#0-0) 

and verified against only the recorded per-slot signer address for whatever contract is being checked, with no binding to which contract the signature was meant for: [2](#0-1) 

The slot-to-signer assignment for every `.signers-{set}-{message_id}` contract is derived from a single shared list in the `.signers` boot contract, keyed only by signer-set page (`u0`/`u1`), independent of `message_id`: [3](#0-2) [4](#0-3) 

This is confirmed by the test that iterates all `message_id` sub-contracts for a signer set and shows they all return the identical `(signer, num-slots)` ordering: [5](#0-4) 

The chunk-acceptance path — reachable both via the raw p2p unsolicited-push handler and the `POST /v2/stackerdb/.../chunks` RPC — validates only size, expected slot signer, freshness, and write-count; it never checks that the signature/data was intended for `smart_contract_id`: [6](#0-5) 

The unsolicited push handler tests demonstrate the only checks enforced are "signature well-formed" and "signer matches the expected slot signer" — never contract binding: [7](#0-6) 

Because the same signer key owns the same `slot_id` in every sibling `signers-{set}-*` contract, a chunk `(slot_id, slot_version, sig, data)` that was legitimately signed and published to contract A satisfies `SlotMetadata::verify()` against the recorded slot signer of contract B as well, since `get_slot_signer` for the same slot index resolves to the identical address in both: [8](#0-7) 

An attacker (any connected, unprivileged p2p peer) can capture a chunk broadcast for one lane (e.g. `BlockResponse`, message id 1) and push it — unmodified — as an unsolicited chunk for a sibling lane contract (e.g. `BlockPreCommit`, message id 7) at the same slot, provided the target contract's expected slot version is not higher. `validate_received_chunk` will accept and store it because signer, size, freshness, and write-count checks all pass; the contract binding is never checked.

### Impact Explanation
This is an unauthenticated/unauthorized write to StackerDB state: data that a signer never intended for a given StackerDB instance is written into that instance's replica and then gossiped/propagated to the rest of the network as authentic content for that contract (per the "store-and-forward" replication semantics documented in `stackslib/src/net/stackerdb/mod.rs`). This satisfies the rule's "Critical" bucket — "unauthenticated/unauthorized write to state or StackerDB, network-wide propagation of forged data" — since replayed, misattributed data for a signer/slot can corrupt or desynchronize what other nodes believe is that signer's current message in a completely different message lane, degrading signer coordination and consensus-adjacent StackerDB integrity, without requiring any secret key or privileged role.

### Likelihood Explanation
Exploitation requires no special access: the attacker only needs to observe a normal, legitimately signed chunk broadcast on the p2p network (chunks are gossiped publicly to all StackerDB replicas) and re-push it, unmodified, to a sibling contract at the identical slot index. The slot-index equivalence across sibling `signers-{set}-*` contracts is a direct, deterministic byproduct of how the `.signers` boot contract assigns slots (page keyed only by signer-set, not message id), so this is not probabilistic — it is guaranteed for every signer set.

### Recommendation
Include the target `smart_contract_id` (or a domain separator that binds signature validity to it) in `SlotMetadata::auth_digest()`, mirroring the report's own recommendation of binding signed data to a unique instance identifier (EIP-712-style domain separation). This ensures a valid signature for one StackerDB contract cannot be replayed as valid input to another.

### Proof of Concept
1. Signer S is assigned `slot_id = k` in both `signers-0-1` (`BlockResponse`) and `signers-0-7` (`BlockPreCommit`) contracts for reward cycle R (guaranteed by shared slot-list derivation in `signers.clar`).
2. S signs and publishes a `StackerDBChunkData { slot_id: k, slot_version: v, sig, data }` to `signers-0-1` via normal signer operation; the chunk is gossiped across the network per `mod.rs` documentation.
3. Attacker observes this chunk on the wire and re-packages it (unmodified) as a `StackerDBPushChunkData { contract_id: signers-0-7, chunk_data: <same chunk> }`, sending it unsolicited to any peer via `handle_unsolicited_StackerDBPushChunk`, or via the `POST /v2/stackerdb/{signers-0-7}/chunks` RPC.
4. `validate_received_chunk`/`try_replace_chunk` for `signers-0-7` calls `get_slot_signer` for slot `k`, resolving to the same address as S (per step 1); `slot_metadata.verify(&addr)` succeeds because the digest never bound the contract; size/version/write-count checks pass identically.
5. The chunk is accepted, stored under `signers-0-7`, and re-broadcast as authentic `BlockPreCommit`-lane content, even though S never signed anything for that contract.

```rust
    fn auth_digest(&self) -> Sha512Trunc256Sum {
        let mut hasher = Sha512_256::new();
        hasher.update(self.slot_id.to_be_bytes());
        hasher.update(self.slot_version.to_be_bytes());
        hasher.update(self.data_hash.0);
        Sha512Trunc256Sum::from_hasher(hasher)
    }
```

```rust
    /// Note that the address version is ignored.
    pub fn verify(&self, principal: &StacksAddress) -> Result<bool, Error> {
        let sigh = self.auth_digest();
        let pubk = StacksPublicKey::recover_to_pubkey_without_validating_low_s(
            sigh.as_bytes(),
            &self.signature,
        )
        .map_err(|ve| Error::VerifyingError(ve.to_string()))?;

        let pubkh = Hash160::from_node_public_key(&pubk);
        Ok(pubkh == *principal.bytes())
    }
```

```rust
    pub fn validate_received_chunk(
        &self,
        smart_contract_id: &QualifiedContractIdentifier,
        config: &StackerDBConfig,
        data: &StackerDBChunkData,
        expected_versions: &[u32],
    ) -> Result<bool, net_error> {
        // validate -- must not exceed this replica's configured chunk size.
        if (data.data.len() as u64) > config.chunk_size {
            info!(
                "Received StackerDBChunk for {} ID {}, which is oversized: {} bytes (max {} bytes)",
                smart_contract_id,
                data.slot_id,
                data.data.len(),
                config.chunk_size
            );
            return Ok(false);
        }

        // validate -- must be a valid chunk
        let Some(expected_version) = expected_versions.get(data.slot_id as usize) else {
            info!(
                "Received StackerDBChunk for {} ID {}, which is too big ({})",
                smart_contract_id,
                data.slot_id,
                expected_versions.len()
            );
            return Ok(false);
        };

        // validate -- must be signed by the expected author
        let addr = match self
            .stackerdbs
            .get_slot_signer(smart_contract_id, data.slot_id)?
        {
            Some(addr) => addr,
            None => {
                return Ok(false);
            }
        };

        let slot_metadata = data.get_slot_metadata();
        if !slot_metadata.verify(&addr)? {
            info!(
                "StackerDBChunk for {} ID {} is not signed by {}",
                smart_contract_id, data.slot_id, &addr
            );
            return Ok(false);
        }

        // validate -- must be the current or newer version
        if data.slot_version < *expected_version {
            info!(
                "Received StackerDBChunk for {} ID {} version {}, which is stale (expected {})",
                smart_contract_id, data.slot_id, data.slot_version, *expected_version
            );
            return Ok(false);
        }

        // validate -- must not exceed max writes
        if data.slot_version > config.max_writes {
            info!(
                "Write count exceeded for StackerDBChunk for {} ID {} version {} (max is {})",
                smart_contract_id, data.slot_id, data.slot_version, config.max_writes
            );
            return Ok(false);
        }

        Ok(true)
    }
```

```rust
    /// Get the principal who signs a particular slot in a particular stacker DB.
    /// Returns Ok(Some(addr)) if this slot exists in the DB
    /// Returns Ok(None) if the slot does not exist
    /// Returns Err(..) if the DB doesn't exist of some other DB error happens
    pub fn get_slot_signer(
        &self,
        smart_contract: &QualifiedContractIdentifier,
        slot_id: u32,
    ) -> Result<Option<StacksAddress>, net_error> {
        let stackerdb_id = self.get_stackerdb_id(smart_contract)?;
        let sql = "SELECT signer FROM chunks WHERE stackerdb_id = ?1 AND slot_id = ?2";
        let args = params![stackerdb_id, slot_id];
        query_row(&self.conn, sql, args).map_err(|e| e.into())
    }
```
