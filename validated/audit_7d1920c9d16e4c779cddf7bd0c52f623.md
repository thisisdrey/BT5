### Title
`native_withdraw` debits wNEAR but has no resolver/refund path if `near_withdraw` or the final NEAR transfer fails - ([File: contracts/defuse/src/contract/tokens/nep141/native.rs])

### Summary
Unlike `ft_withdraw`, `nft_withdraw`, and `mt_withdraw` (all of which attach a `*_resolve_withdraw` callback that checks the outer transfer's promise result and refunds the sub-balance if the transfer failed), `native_withdraw` in `contracts/defuse/src/contract/intents/state.rs` detaches its promise chain right after `do_native_withdraw` with no resolver. If `near_withdraw` fails or the final `Promise::new(receiver_id).transfer(amount)` in `do_native_withdraw` fails/loses funds, the wNEAR already subtracted from the account's Defuse ledger is never restored.

### Finding Description
The invariant that should hold is: `internal_sub_balance(wNEAR, account) == NEAR delivered to receiver_id OR internal_add_balance(wNEAR, account) (refund)`.

Tracing `native_withdraw` in [1](#0-0) : it first calls `self.withdraw(...)`, which subtracts the wNEAR balance from `owner_id`'s ledger, then fires `near_withdraw` followed by `.then(do_native_withdraw)`, and finally `.detach()`s the whole chain with **no further callback**.

`do_native_withdraw` in [2](#0-1)  does `require!(promise_result_checked_void(0).is_ok(), "near_withdraw failed")` — if the preceding `near_withdraw` XCC failed, this callback panics, and there is no subsequent step to detect that panic and re-credit the account. Even if `near_withdraw` succeeds, the trailing `Promise::new(withdraw.receiver_id).transfer(withdraw.amount)` is the terminal promise in the detached chain: there is no resolve step to confirm the NEAR transfer succeeded, and no refund is issued if it fails (e.g., `receiver_id` is a non-existent/invalid account, causing the transfer receipt to fail).

This is in stark contrast to the sibling withdraw flows, which all implement refund-on-failure resolvers:
- `ft_resolve_withdraw` refunds `amount - used` back to `sender_id` when `ft_transfer`/`ft_transfer_call` fails [3](#0-2) 
- `nft_resolve_withdraw` refunds the NFT back on failure [4](#0-3) 
- `mt_resolve_withdraw` refunds unused amounts back on failure [5](#0-4) 

`native_withdraw` has no equivalent `native_resolve_withdraw`, so any failure downstream of the debit (either the `near_withdraw` unwrap call itself failing, or the terminal native `transfer` to `receiver_id` failing) results in the ledger's wNEAR debit being permanent while the NEAR never reaches the named receiver and is never returned to the signer's Defuse balance.

### Impact Explanation
The account that called `native_withdraw` (an account with `auth_by_predecessor_id` enabled, or via a signed `NativeWithdraw` intent through `execute_intents`) permanently loses the withdrawn wNEAR amount: it is subtracted from their Defuse balance, and if the unwrap or final transfer fails, no NEAR reaches them and no wNEAR is refunded. This matches the "Critical - user funds permanently frozen (unrecoverable without a privileged action)" category, since only a DAO/`UnrestrictedWithdrawer`/similar privileged role could manually compensate the affected account. The bug is deterministic and repeatable for any account/amount whenever the withdraw's `receiver_id` cannot accept a plain NEAR transfer (e.g., malformed/non-existent account) or when `near_withdraw` on the wNEAR contract fails for any reason.

### Likelihood Explanation
No special privileges are needed — any account with `auth_by_predecessor_id` enabled (the default for accounts, per `is_auth_by_predecessor_id_enabled` in [6](#0-5) ) can trigger `native_withdraw` directly by choosing a `receiver_id` that will fail to receive a NEAR transfer, or the failure can occur non-maliciously whenever `near_withdraw` reverts. The precondition is simply having a wNEAR balance to withdraw and control over the `receiver_id`/`amount` parameters of the `NativeWithdraw` intent, both fully attacker-controlled. This is repeatable across accounts and amounts with no cost beyond the withdrawn amount itself.

### Recommendation
Add a `native_resolve_withdraw`-style `#[private]` callback attached after `do_native_withdraw` (mirroring `ft_resolve_withdraw`/`nft_resolve_withdraw`/`mt_resolve_withdraw`) that inspects the promise result of the final `transfer` (and of the `near_withdraw`/`do_native_withdraw` chain) and calls `self.deposit(...)` to refund the wNEAR back to the original owner when the transfer did not succeed, instead of `.detach()`ing the chain with no resolution.

### Proof of Concept
`cargo test` plan (near-workspaces sandbox, no mainnet):
1. Deploy the defuse contract, wNEAR contract, and register a user account `alice` with wNEAR balance `X` in Defuse (via `mint`/deposit flow).
2. Have `alice` call `native_withdraw` (or execute a signed `NativeWithdraw` intent) with `receiver_id` set to a syntactically valid but non-existent account (e.g. `"doesnotexist.test.near"`) and `amount = X`.
3. Assert before: `defuse.balance_of(alice, wnear_token_id) == X`.
4. After the promise chain resolves (transfer receipt fails since receiver doesn't exist), assert:
   - `defuse.balance_of(alice, wnear_token_id) == 0` (debited, confirming loss).
   - The receiver account balance did not increase (NEAR never delivered).
   - No `deposit`/refund event was emitted crediting `alice` back.
5. This demonstrates `wNEAR debited != NEAR delivered to receiver OR refunded`, proving the invariant is broken with no privileged-action recovery path.

    #[private]
    fn ft_resolve_withdraw(
        &mut self,
        token: AccountId,
        sender_id: AccountId,
        amount: U128,
        is_call: bool,
    ) -> U128 {
        let used = if is_call {
            // `ft_transfer_call` returns successfully transferred amount
            match promise_result_checked_json::<U128>(0) {
                Ok(Ok(used)) => used.0.min(amount.0),
                Ok(Err(_deserialize_err)) => 0,
                // do not refund on failed `ft_transfer_call` due to
                // NEP-141 vulnerability: `ft_resolve_transfer` fails to
                // read result of `ft_on_transfer` due to insufficient gas
                Err(_) => amount.0,
            }
        } else {
            // `ft_transfer` returns empty result on success
            if promise_result_checked_void(0).is_ok() {
                amount.0
            } else {
                0
            }
        };

        let refund = amount.0.saturating_sub(used);
        if refund > 0 {
            self.deposit(
                sender_id,
                [(Nep141TokenId::new(token).into(), refund)],
                Some(REFUND_MEMO),
            )
            .unwrap_or_else(|err| err.panic());
        }

        U128(used)
    }

    #[private]
    fn mt_resolve_withdraw(
        &mut self,
        token: AccountId,
        sender_id: AccountId,
        token_ids: Vec<defuse_nep245::TokenId>,
        amounts: Vec<U128>,
        is_call: bool,
    ) -> Vec<U128> {
        require!(
            token_ids.len() == amounts.len() && !amounts.is_empty(),
            "invalid args"
        );

        let mut used = if is_call {
            // `mt_batch_transfer_call` returns successfully transferred amounts
            match promise_result_checked_json_with_len::<Vec<U128>>(0, amounts.len()) {
                Ok(Ok(used)) if used.len() == amounts.len() => used,
                Ok(_) => vec![U128(0); amounts.len()],
                // do not refund on failed `mt_batch_transfer_call` due to
                // NEP-141 vulnerability: `mt_resolve_transfer` fails to
                // read result of `mt_on_transfer` due to insufficient gas
                Err(_) => amounts.clone(),
            }
        } else {
            // `mt_batch_transfer` returns empty result on success
            if promise_result_checked_void(0).is_ok() {
                amounts.clone()
            } else {
                vec![U128(0); amounts.len()]
            }
        };

        self.deposit(
            sender_id,
            token_ids
                .into_iter()
                .zip(amounts)
                .zip(&mut used)
                .filter_map(|((token_id, amount), used)| {
                    // update min during iteration
                    used.0 = used.0.min(amount.0);
                    let refund = amount.0.saturating_sub(used.0);
                    if refund > 0 {
                        Some((Nep245TokenId::new(token.clone(), token_id).into(), refund))
                    } else {
                        None
                    }
                }),
            Some(REFUND_MEMO),
        )
        .unwrap_or_else(|err| err.panic());

        used
    }
}
