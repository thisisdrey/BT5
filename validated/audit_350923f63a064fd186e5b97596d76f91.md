### Title
Missing bundle-URI SSRF mitigation in `FetchRemote`/`UpdateRemoteMirror`/`FindRemoteRootRef` allows client-controlled `git-bundle-uri` requests - (File: internal/gitaly/service/repository/fetch_remote.go)

### Summary
The bug class in the external report is a security check that was added to one operation but omitted from a sibling operation performing the same underlying action, allowing the protection to be bypassed. Gitaly shows the same pattern: an SSRF mitigation ("disable bundle URIs when fetching from a remote URL") was added only to `CreateRepositoryFromURL`, but the equivalent remote-fetching RPCs `FetchRemote`, `UpdateRemoteMirror`, and `FindRemoteRootRef` — which also connect to a caller-supplied remote URL — do not set the same mitigation.

### Finding Description
In `internal/gitaly/service/repository/create_repository_from_url.go`, the `cloneFromURLCommand` function explicitly disables the Git `bundle-uri` feature before invoking `git clone` against a user-controlled URL: [1](#0-0) 
This was added specifically as an SSRF mitigation, as documented in the changelog: "repoFromURL: Disable bundle URIs when cloning from URL to prevent SSRF" [2](#0-1) . The rationale is that the bundle-uri feature causes the Git client (Gitaly, acting as a client toward the untrusted remote) to follow a server-advertised URI to fetch a bundle from an arbitrary location, including internal/localhost addresses — i.e., a second-order SSRF vector triggered by data returned from the remote itself.

However, other RPCs that make Gitaly act as a Git client against a caller-supplied remote URL do not apply this same `transfer.bundleURI=false` mitigation:
- `FetchRemote`'s `buildCommandOpts`, which builds the git configuration used for `git fetch` against `req.GetRemoteParams().GetUrl()`, has no bundle-uri disabling: [3](#0-2) 
- `UpdateRemoteMirror`'s remote-config construction, used for `GetRemoteReferences`/`Push` against `remote.GetUrl()`, likewise has no such config: [4](#0-3) 
- `FindRemoteRootRef`'s `findRemoteRootRefCmd`, which runs `git remote show` against `request.GetRemoteUrl()`, also has no such config: [5](#0-4) 

A repository-scoped grep confirms `transfer.bundleURI`/bundle-URI disabling logic is referenced only in `create_repository_from_url.go` among these remote-fetching code paths, and nowhere in `fetch_remote.go`, `update_remote_mirror.go`, or `find_remote_root_ref.go`.

### Impact Explanation
`FetchRemote`, `UpdateRemoteMirror`, and `FindRemoteRootRef` are all reachable via ordinary gRPC calls with a caller-supplied `RemoteUrl`/`Remote.Url` field (used for repository mirroring/pull-mirror workflows). Because these paths do not disable `transfer.bundleURI`, a malicious or compromised remote endpoint that Gitaly is instructed to fetch/mirror from can respond during Git's protocol negotiation with a bundle-uri advertisement pointing at an arbitrary internal address (e.g., cloud metadata endpoints, internal services, or `file://` paths where reachable). Git's client-side bundle-uri implementation will then have the Gitaly host fetch/dereference that URI, resulting in server-side request forgery originating from the Gitaly node, potentially exposing internal network services or leaking metadata/credentials.

### Likelihood Explanation
This is reachable directly from an unprivileged/ordinary caller (e.g., a project owner configuring a pull mirror or invoking `FetchRemote`/`UpdateRemoteMirror`/`FindRemoteRootRef` with an attacker-controlled `RemoteUrl`) — no privileged actor, leaked-token, or MITM is required; the "malicious remote" is exactly the third-party server the caller instructs Gitaly to contact, which is the normal, expected input surface of these RPCs. Given that GitLab's own security team already treated the equivalent gap in `CreateRepositoryFromURL` as an SSRF vulnerability worth a dedicated fix, the same code pattern in these three sibling RPCs is a concrete, high-likelihood analog.

### Recommendation
Apply the same mitigation used in `create_repository_from_url.go` to the other remote-fetching code paths: pass `gitcmd.ConfigPair{Key: "transfer.bundleURI", Value: "false"}` (or the equivalent `gitcmd.WithGlobalOption`) when constructing the git command/config for:
- `buildCommandOpts` in `internal/gitaly/service/repository/fetch_remote.go`
- the remote config construction in `internal/gitaly/service/remote/update_remote_mirror.go`
- `findRemoteRootRefCmd` in `internal/gitaly/service/remote/find_remote_root_ref.go`

Alternatively, centralize this SSRF-hardening configuration into a shared helper (e.g., extend `gitcmd.GetURLAndResolveConfig` or a new `gitcmd.WithSSRFHardening()` option) that all remote-URL-consuming call sites use, preventing this same gap from being reintroduced for future RPCs.

### Proof of Concept
1. Configure a pull mirror or directly call `FetchRemote` (or `UpdateRemoteMirror`/`FindRemoteRootRef`) with `RemoteParams.Url` (or `Remote.Url`/`RemoteUrl`) pointing to an attacker-controlled Git HTTP server.
2. The attacker's server, during the smart-HTTP `info/refs` / capability negotiation, advertises a `bundle-uri` value pointing at an internal address (e.g., `http://169.254.169.254/latest/meta-data/` or an internal-only service).
3. Because `transfer.bundleURI` is not disabled in `buildCommandOpts`/`updateRemoteMirror`/`findRemoteRootRefCmd`, the Git client process spawned by Gitaly will follow the bundle-uri advertisement and issue a request to the attacker-specified internal address from the Gitaly host — as it is not disabled the way it is in `cloneFromURLCommand`: [1](#0-0) 
4. This confirms the SSRF mitigation applied to `CreateRepositoryFromURL` is absent from the analogous `FetchRemote`, `UpdateRemoteMirror`, and `FindRemoteRootRef` code paths.

func buildCommandOpts(ctx context.Context, opts *localrepo.FetchOpts, req *gitalypb.FetchRemoteRequest) error {
	remoteURL := req.GetRemoteParams().GetUrl()
	var config []gitcmd.ConfigPair

	for _, refspec := range getRefspecs(req.GetRemoteParams().GetMirrorRefmaps()) {
		config = append(config, gitcmd.ConfigPair{
			Key: "remote.inmemory.fetch", Value: refspec,
		})
	}

	if resolvedAddress := req.GetRemoteParams().GetResolvedAddress(); resolvedAddress != "" {
		modifiedURL, resolveConfig, err := gitcmd.GetURLAndResolveConfig(remoteURL, resolvedAddress)
		if err != nil {
			return fmt.Errorf("couldn't get curloptResolve config: %w", err)
		}

		remoteURL = modifiedURL
		config = append(config, resolveConfig...)
	}

	config = append(config, gitcmd.ConfigPair{Key: "remote.inmemory.url", Value: remoteURL})

	if featureflag.FetchRemoteProactiveAuth.IsEnabled(ctx) {
		if u, err := url.Parse(remoteURL); err == nil && u.User != nil {
			password, _ := u.User.Password()
			if u.User.Username() != "" && password != "" {
				config = append(config, gitcmd.ConfigPair{
					Key:   "http.proactiveAuth",
					Value: "basic",
				})
			}
		}
	}

	if authHeader := req.GetRemoteParams().GetHttpAuthorizationHeader(); authHeader != "" {
		config = append(config, gitcmd.ConfigPair{
			Key:   fmt.Sprintf("http.%s.extraHeader", req.GetRemoteParams().GetUrl()),
			Value: "Authorization: " + authHeader,
		})
	}

	opts.CommandOptions = append(opts.CommandOptions, gitcmd.WithConfigEnv(config...))

	return nil
}

func (s *server) findRemoteRootRefCmd(ctx context.Context, request *gitalypb.FindRemoteRootRefRequest) (*command.Command, error) {
	remoteURL := request.GetRemoteUrl()
	var config []gitcmd.ConfigPair

	if resolvedAddress := request.GetResolvedAddress(); resolvedAddress != "" {
		modifiedURL, resolveConfig, err := gitcmd.GetURLAndResolveConfig(remoteURL, resolvedAddress)
		if err != nil {
			return nil, structerr.NewInvalidArgument("couldn't get curloptResolve config: %w", err)
		}

		remoteURL = modifiedURL
		config = append(config, resolveConfig...)
	}

	config = append(config, gitcmd.ConfigPair{Key: "remote.inmemory.url", Value: remoteURL})

	if authHeader := request.GetHttpAuthorizationHeader(); authHeader != "" {
		config = append(config, gitcmd.ConfigPair{
			Key:   fmt.Sprintf("http.%s.extraHeader", request.GetRemoteUrl()),
			Value: "Authorization: " + authHeader,
		})
	}

	repo := s.localRepoFactory.Build(request.GetRepository())

	return repo.Exec(ctx,
		gitcmd.Command{
			Name:   "remote",
			Action: "show",
			Args:   []string{"inmemory"},
		},
		gitcmd.WithDisabledHooks(),
		gitcmd.WithConfigEnv(config...),
		gitcmd.WithSetupStdout(),
	)
