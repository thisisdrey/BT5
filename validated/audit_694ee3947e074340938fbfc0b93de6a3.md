Based on my investigation, the `libsigner` `SignerEventReceiver` HTTP transport has a genuine unauthenticated-endpoint gap analogous to the OpenClaw finding.

### Title
Unauthenticated write to the Signer's local event-listener endpoints allows forged StackerDB/block/burn events - (File: libsigner/src/events.rs)

### Summary
`SignerEventReceiver::next_event` dispatches incoming HTTP POSTs by URL path (`/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block`, `/shutdown`) but performs no authentication check anywhere in the receive path, unlike the node-side `/v3/block_proposal` and `/v2/blocks?broadcast=1` endpoints, which are gated by `auth_token`/`Authorization` header checks.

### Finding Description
`SignerEventReceiver::bind` opens a plain `tiny_http` server on the configured `endpoint` address [1](#0-0) , and `next_event` routes every request purely by URL, with zero credential/header validation before calling `process_event` or triggering shutdown [2](#0-1) . `process_event` only checks that the body deserializes into the expected JSON type; it does not verify the sender's identity [3](#0-2) . This contrasts with the node's own HTTP RPC surface, where equivalent sensitive endpoints require a matching `auth_token` (e.g. `postblock_proposal` and `postblock_v3` return 401 without a correct `Authorization` header) [4](#0-3) [5](#0-4) . The `auth_token`/`connection_options.auth_token` mechanism documented for securing the node↔signer channel [6](#0-5)  and the operational docs pairing `auth_token`/`auth_password` between node and signer [7](#0-6)  is never consulted or enforced on the signer's *receiving* side — it only guards what the node requires when the signer calls *into* the node, not what the signer accepts when the node (or anyone else) calls *into* it.

### Impact Explanation
Any process capable of reaching the signer's bound endpoint (documented examples bind to `0.0.0.0:30000`, not exclusively loopback, per sample/doc configs) [8](#0-7)  can POST directly to `/new_burn_block`, `/proposal_response`, `/new_block`, or `/shutdown` and have the payload accepted and forwarded to the signer runloop as if it originated from the trusted node — or terminate the event receiver outright via a forged `/shutdown` [9](#0-8) . This is an authentication-gate that fails open on the transport boundary, matching the reported bug class (unauthenticated endpoint alongside authenticated siblings) and reaching an unauthorized write/injection into the signer's event stream and a remote unauthenticated DoS vector (forged shutdown).

### Likelihood Explanation
Exploitation only requires network reachability to the bound port and knowledge of the fixed, undocumented-as-secret URL paths (`/shutdown`, `/new_burn_block`, etc.), which are visible directly in this source file. No cryptographic material, node secret, or privileged role is needed to reach and interact with the endpoint itself.

### Recommendation
Require the same `auth_token`/`Authorization` mechanism used elsewhere in the node↔signer channel to be validated inside `SignerEventReceiver::next_event` before dispatching to `process_event` or acting on `/shutdown`, and bind the listener to loopback by default unless explicitly overridden.

### Proof of Concept
1. Configure a signer with `endpoint = "0.0.0.0:30000"` as shown in sample configs.
2. From a separate host/process, `curl -X POST http://<signer-host>:30000/shutdown` — the receiver sets its stop signal and terminates without any credential check [9](#0-8) .
3. Alternatively, POST a crafted JSON body to `/new_burn_block` or `/proposal_response`; it is deserialized and forwarded to the signer runloop with no verification that it came from the paired node [3](#0-2) .

Note: I could not fully verify from the indexed files whether any authentication is enforced at a layer outside `libsigner` (e.g., in `stacks-node/src/event_dispatcher.rs`, which is out of scope for this repo-context restriction) — that file was outside the in-scope path set specified in the rules, so I did not use it as supporting or refuting evidence. If a Devin session with full repo access is desired to confirm whether any wrapping authentication exists for this listener in practice, that would need to be checked outside the current index limits.

```rust
    fn next_event(&mut self) -> Result<SignerEvent<T>, EventError> {
        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)
            } else if request.url() == "/new_block" {
                process_event::<T, StacksBlockEvent>(request)
            } else {
                let url = request.url().to_string();
                debug!(
                    "[{:?}] next_event got request with unexpected url {}, return OK so other side doesn't keep sending this",
                    event_receiver.local_addr,
                    url
                );
                ack_dispatcher(request);
                Err(EventError::UnrecognizedEvent(url))
            }
        })?
    }
```

```rust
fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}
```
