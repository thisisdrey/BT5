### Title
`Pool.liquidate()` cannot clear residual debt once collateral is exhausted, leaving permanently unbacked synthetic supply — a "last synth holder loses" bad-debt scenario - (contracts/Pool.sol)

### Summary
`Pool.liquidate()` seizes collateral only up to the account's `depositToken_` balance and reverts otherwise (`AmountIsTooHigh`). When a position is deeply underwater (debt > collateral value), the maximum repayable amount is capped by the collateral that can be seized (`quoteLiquidateMax` uses `depositToken_.balanceOf(account_)` as the bound), so after a full liquidation the account retains residual debt with ~zero collateral. Nothing ever writes off or covers this residual debt, and `debtFloorInUsd` can even revert partial repayments that would leave a below-floor remainder. The corresponding synthetic tokens stay in circulation with no collateral backing — protocol insolvency that is socialized across all holders of the synthetic asset.

### Finding Description
- `liquidate()` reverts if `_totalSeized > depositToken_.balanceOf(account_)`, bounding repayment to what the remaining collateral covers (Pool.sol:581-585).
- `quoteLiquidateMax` explicitly computes the cap as `min(collateral-covered repay, debt * maxLiquidable)` (Pool.sol:429-439).
- After collateral is fully seized, the leftover debt accrues interest forever (`accrueInterest`), but there is no incentive to repay it since there is nothing left to seize — there is no `liquidateClean`/bad-debt write-off equivalent anywhere in the contracts (no cover/socialize/write-off mechanism exists).
- Additionally, `debtFloorInUsd` reverts partial repayments leaving 0 < remaining < floor (Pool.sol:571-579), while full repayment reverts via `AmountIsTooHigh` — making small residual debts impossible to remove even for a willing liquidator.

### Impact Explanation
Every synthetic token in circulation is nominally backed by collateralized debt positions. Once an account's collateral is seized and residual debt remains, a portion of `syntheticToken.totalSupply()` is backed by nothing. Since synthetic holders cannot redeem collateral directly, the loss is socialized: early sellers exit at oracle/AMM price while later holders absorb the depeg — the same "first to exit wins, last holder absorbs the loss" dynamic as the reference finding. This is direct protocol insolvency.

### Likelihood Explanation
Requires a sharp collateral price drop pushing positions below 1:1 collateralization (the test suite itself exercises this branch at `newMetPrice = $0.50`). No privileged action needed — liquidations are permissionless. The `debtFloorInUsd` interaction makes residual debt guaranteed on deployed configurations where the floor is set. The absence of any backstop/write-off means accumulation is monotonic over time.

### Recommendation
Add a bad-debt mechanism: allow a permissionless "clean" liquidation that writes off residual debt when an account's collateral reaches zero (or near-zero), burning the debt-token balance so it stops accruing interest, and/or socialize the shortfall explicitly (e.g., a cover pool or haircut) rather than leaving phantom backing. Exempt write-off liquidations from `debtFloorInUsd` and `AmountGreaterThanMaxLiquidable` checks.

### Proof of Concept
Reproducible with the existing Hardhat setup mirroring `test/Pool.test.ts:773-819`:

```ts
// Position: alice deposits MET, issues msETH; MET price drops to $0.50
// so debtInUsd > depositInUsd (underwater).
await masterOracle.updatePrice(met.address, toUSD('0.50'))

// Liquidator repays the max allowed by collateral
const amountToRepay = await pool.quoteLiquidateMax(msEth.address, alice.address, msdMET.address)
await pool.connect(liquidator).liquidate(msEth.address, alice.address, amountToRepay, msdMET.address)

// After liquidation:
expect(await msdMET.balanceOf(alice.address)).closeTo(0, dust)   // collateral ~gone
expect(await msEthDebtToken.balanceOf(alice.address)).gt(0)      // residual debt remains

// 1) Further liquidation is impossible/unprofitable:
//    - repaying full remaining debt reverts AmountIsTooHigh (no collateral left to seize)
//    - any repayable amount leaves dust collateral with no liquidator incentive
// 2) If remaining debt < debtFloorInUsd, even a willing liquidator hits
//    RemainingDebtIsLowerThanTheFloor for any partial repayment.
// 3) The burned amountToRepay < original issued amount, so msETH supply now
//    exceeds the debt/collateral backing it — unbacked supply accrues indefinitely
//    via accrueInterest() while every msETH holder bears the eventual depeg.
```

Key code: `liquidate` bound check at `contracts/Pool.sol:583-585`, collateral cap in `quoteLiquidateMax` at `contracts/Pool.sol:429-439`, floor revert at `contracts/Pool.sol:571-579`.
