### Title
`AccountPermissionUpdateContract` performs an irreversible one-step owner-permission replacement with no acceptance/proof-of-key-control from the new keys, permanently bricking accounts on a single mistaken transaction - (File: actuator/src/main/java/org/tron/core/actuator/AccountPermissionUpdateActuator.java)

### Summary
`AccountPermissionUpdateActuator.execute()` overwrites an account's `Owner` (and `Active`/`Witness`) `Permission` in a single transaction via `AccountCapsule.updatePermissions()`, with no two-step "propose then accept" flow and no requirement that the newly designated keys co-sign to prove key possession, mirroring the `changeDAO()` one-step admin-transfer bug class.

### Finding Description
`AccountPermissionUpdateActuator.execute()` unconditionally applies the new permission set supplied in the contract: [1](#0-0) 

This call to `account.updatePermissions(...)` fully replaces the stored `ownerPermission` (and optionally `witnessPermission`/`activePermission`) with the contract's `owner`/`witness`/`actives` fields, with no staging, pending-state, or acceptance step: [2](#0-1) 

`validate()` checks that the *submitted* keys/threshold/weights are structurally sane (`checkPermission`), but never verifies that the account actually controls the private keys for the new `Owner` permission's addresses — it only checks address format validity: [3](#0-2) 

Crucially, the transaction authorizing this change is validated against the account's *current* (old) permission only — via `TransactionCapsule.validateSignature()`/`checkWeight()` — not against the new permission being installed: [4](#0-3) 

Once this executes, every future transaction from that account — including any further `AccountPermissionUpdateContract` to fix a mistake — must satisfy the *new* `Owner` permission's threshold, per `checkWeight`/`getWeight`: [5](#0-4) 

If the submitted `Owner` permission references an address/key the sender does not actually hold the private key for (typo, wrong key, lost key), there is no way to recover: the account can never again produce a valid signature satisfying the new owner threshold, exactly the "incorrect address used, and future administrative access is prevented" scenario described for `changeDAO()`.

### Impact Explanation
This results in permanent, irreversible loss of administrative control over the account and permanent freezing of all TRX/TRC10/TRC20 assets and resources (bandwidth/energy delegation, voting rights, etc.) held by that account, since no subsequent transaction — including any corrective permission update — can ever be authorized again. This matches the "permanent freezing of funds" acceptance criterion.

### Likelihood Explanation
Any account holder with multisig enabled (`AllowMultiSign`) can trigger this with a single mistaken transaction, requiring no privileged role, malicious peer, or unusual state — only a well-formed `AccountPermissionUpdateContract` that references an address whose key is unavailable to the sender. This is a low-effort, high-consequence self-inflicted (or social-engineering-induced, e.g. a compromised UI substituting an attacker address as one of the new owner keys) failure mode with no built-in safety net, directly analogous to the `changeDAO()` finding.

### Recommendation
Introduce a two-step permission-update process: the current owner permission proposes the new permission set in one transaction, and the process only takes effect after a second transaction signed by (a sufficient threshold of) the *newly proposed* keys explicitly accepts/confirms control, optionally combined with a timelock before the new permission becomes active, matching the recommendation from the referenced Vader `changeDAO()` finding.

### Proof of Concept
1. Account `A` has `AllowMultiSign` enabled and controls its current `Owner` permission key `k_old`.
2. `A` broadcasts an `AccountPermissionUpdateContract` for its own `owner_address`, setting the new `Owner` permission's key list to an address `k_typo` for which no private key is ever obtained (fat-fingered or maliciously substituted address), signed with `k_old` per current permission — validated only against the old permission by `TransactionCapsule.validateSignature()`.
3. `AccountPermissionUpdateActuator.execute()` commits the change via `AccountCapsule.updatePermissions()`.
4. All subsequent transactions from `A`, including further `AccountPermissionUpdateContract`s meant to fix the mistake, must satisfy the new `Owner` permission's threshold against `k_typo`, which nobody can sign; `A`'s funds and permissions are now permanently frozen.

  public void updatePermissions(Permission owner, Permission witness, List<Permission> actives) {
    Builder builder = this.account.toBuilder();

    owner = owner.toBuilder().setId(0).build();
    builder.setOwnerPermission(owner);
    if (witness != null && builder.getIsWitness()) {
      witness = witness.toBuilder().setId(1).build();
      builder.setWitnessPermission(witness);
    }

    builder.clearActivePermission();
    if (actives != null) {
      for (int i = 0; i < actives.size(); i++) {
        Permission permission = actives.get(i).toBuilder().setId(i + 2).build();
        builder.addActivePermission(permission);
      }
    }

    this.account = builder.build();
  }

  public static long checkWeight(Permission permission, List<ByteString> sigs, byte[] hash,
      List<ByteString> approveList)
      throws SignatureException, PermissionException, SignatureFormatException {
    long currentWeight = 0;
    if (sigs.size() > permission.getKeysCount()) {
      throw new PermissionException(
          "Signature count is " + (sigs.size()) + " more than key counts of permission : "
              + permission.getKeysCount());
    }
    HashMap addMap = new HashMap();
    for (ByteString sig : sigs) {
      if (sig.size() < 65) {
        throw new SignatureFormatException(
            "Signature size is " + sig.size());
      }
      String base64 = TransactionCapsule.getBase64FromByteString(sig);
      byte[] address = SignUtils
          .signatureToAddress(hash, base64, CommonParameter.getInstance().isECKeyCryptoEngine());
      long weight = getWeight(permission, address);
      if (weight == 0) {
        throw new PermissionException(
            ByteArray.toHexString(hash) + " is signed by " + encode58Check(address)
                + " but it is not contained of permission.");
      }
      if (ForkController.instance().pass(Parameter.ForkBlockVersionEnum.VERSION_4_7_1)) {
        base64 = encode58Check(address);
      }
      if (addMap.containsKey(base64)) {
        throw new PermissionException(encode58Check(address) + " has signed twice!");
      }
      addMap.put(base64, weight);
      if (approveList != null) {
        approveList.add(ByteString.copyFrom(address)); //out put approve list.
      }
      currentWeight += weight;
    }
    return currentWeight;
  }

  public static boolean validateSignature(Transaction transaction,
      byte[] hash, AccountStore accountStore, DynamicPropertiesStore dynamicPropertiesStore)
      throws PermissionException, SignatureException, SignatureFormatException {
    Transaction.Contract contract = transaction.getRawData().getContractList().get(0);
    int permissionId = contract.getPermissionId();
    byte[] owner = getOwner(contract);
    AccountCapsule account = accountStore.get(owner);
    Permission permission = null;
    if (account == null) {
      if (permissionId == 0) {
        permission = AccountCapsule.getDefaultPermission(ByteString.copyFrom(owner));
      }
      if (permissionId == 2) {
        permission = AccountCapsule
            .createDefaultActivePermission(ByteString.copyFrom(owner), dynamicPropertiesStore);
      }
    } else {
      permission = account.getPermissionById(permissionId);
    }
    if (permission == null) {
      throw new PermissionException("permission isn't exit");
    }
    checkPermission(permissionId, permission, contract);
    long weight = checkWeight(permission, transaction.getSignatureList(), hash, null);
    if (weight >= permission.getThreshold()) {
      return true;
    }
    return false;
  }
