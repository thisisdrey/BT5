### Title
Per-source QUIC rate limiting is keyed by exact `IpAddr`, allowing an attacker with an IPv6 /64 to bypass per-IP fairness limits and monopolize the shared unstaked connection budget - ([File: streamer/src/nonblocking/connection_rate_limiter.rs], [File: streamer/src/nonblocking/quic.rs])

### Summary
`ConnectionRateLimiter` and `ConnectionTable`/`ConnectionTableKey::IP` both key exclusively on the exact source `IpAddr`, with no subnet-aware (e.g. /64) aggregation. A single attacker who owns an IPv6 /64 (trivial with most residential/cloud allocations) can rotate through many distinct addresses to bypass `DEFAULT_MAX_CONNECTIONS_PER_IPADDR_PER_MINUTE` and the per-peer connection cap, effectively claiming an unfair share of the shared unstaked connection budget rather than being limited to the single-source share the mechanism was designed to enforce.

### Finding Description
`ConnectionRateLimiter::is_allowed`/`register_connection` use a `KeyedRateLimiter<IpAddr>` and check tokens per exact `IpAddr` key [1](#0-0) . In `run_server`, this per-IP limiter is applied after a global `overall_connection_rate_limiter` check, on `incoming.remote_address().ip()` [2](#0-1) , and `register_connection` is invoked again post-handshake in `setup_connection` [3](#0-2) . Similarly, `ConnectionTable::try_add_connection` is keyed by `ConnectionTableKey::IP(ip)` (exact address) when no pubkey/stake is asserted, capping only per-exact-address concurrent connections, in both `SwQos::cache_new_connection` and `SimpleQos::cache_new_connection` [4](#0-3) [5](#0-4) .

Because these are keyed by exact `IpAddr` and not by /64 prefix, an attacker rotating through N distinct source addresses within a single owned /64 gets N independent token buckets and N independent per-peer connection-table slots, each starting fresh. This defeats the intended invariant that a single network source is bounded to `DEFAULT_MAX_CONNECTIONS_PER_IPADDR_PER_MINUTE` connections/min and `max_connections_per_unstaked_peer` concurrent connections.

However, this bypass is **not unbounded** as the question asserts. Two global backstops remain in place regardless of source-address diversity:
- `overall_connection_rate_limiter`, a single global `TokenBucket` gating all incoming QUIC handshake attempts before the per-IP check is even reached [6](#0-5) [7](#0-6) , and again enforced per-connection in `setup_connection` [8](#0-7) .
- The unstaked connection table has a global capacity (`max_unstaked_connections`, default `DEFAULT_MAX_UNSTAKED_CONNECTIONS = 2000`) enforced via `prune_random`/`prune_oldest` eviction rather than per-IP [9](#0-8) [10](#0-9) .

So the actual, scoped impact of the /64 rotation is: the attacker can monopolize essentially the entire shared global unstaked-connection/handshake-rate budget that was supposed to be fairly divided among many independent unstaked peers, causing connection-table churn (via `prune_random` eviction of legitimate unstaked entries) and starving other unstaked clients of TPU connection slots — not an unbounded resource-exhaustion DoS on its own, since the global caps still bound total table size and total QUIC handshake throughput.

### Impact Explanation
This is a QoS evasion issue: per-source fairness invariants (`max_connections_per_ipaddr_per_min`, `max_connections_per_unstaked_peer`) intended to bound any single network source can be trivially defeated by IPv6 address rotation within an owned /64, letting one attacker consume the full shared `max_unstaked_connections` budget and the full `overall_connection_rate_limiter` throughput, at the expense of other legitimate unstaked clients whose connections get pruned by `prune_random`/`prune_oldest`. This falls into the "QoS evasion" bounty category referenced in the audit rules, scoped to connection-table starvation of other unstaked peers rather than unbounded memory growth or node crash, since global caps (`overall_connection_rate_limiter`, `max_unstaked_connections`) still bound the absolute worst case.

### Likelihood Explanation
Highly feasible: attacker only needs a routed IPv6 /64 (common in residential and virtually all cloud/VPS IPv6 allocations) and standard socket binding to sequential addresses in that prefix — no staking, gossip participation, or validator control required. Each new address resets the per-IP `TokenBucket` and connection-table slot state, so the attack is fully repeatable and requires no special timing beyond opening connections from different local source addresses.

### Recommendation
Make `ConnectionRateLimiter` and `ConnectionTableKey::IP` subnet-aware for IPv6 sources — key rate limiting and per-peer connection caps by a normalized /64 (or configurable) prefix instead of (or in addition to) the exact `IpAddr`, so that address rotation within an owned prefix cannot multiply the effective per-source limit budget.

### Proof of Concept
Integration test plan (extends existing `test_rate_limiting`-style tests in `streamer/src/nonblocking/quic.rs`):
```rust
#[tokio::test(flavor = "multi_thread")]
async fn test_ipv6_subnet_rotation_bypasses_per_ip_limit() {
    // Set max_connections_per_ipaddr_per_min = 1 (as in test_rate_limiting)
    let SpawnTestServerResult { server_address, stats, .. } = setup_quic_server(
        None,
        QuicStreamerConfig { max_connections_per_ipaddr_per_min: 1, ..QuicStreamerConfig::default_for_tests() },
        SwQosConfig { max_connections_per_unstaked_peer: 100, ..Default::default() },
    );

    // Open connections from many distinct IPv6 addresses within a single /64
    let base: u128 = 0x2001_0db8_0000_0001_0000_0000_0000_0000;
    let mut accepted = 0;
    for i in 0..64u128 {
        let ip = Ipv6Addr::from(base + i);
        let addr = SocketAddr::new(IpAddr::V6(ip), 0);
        if make_client_endpoint_from(addr, &server_address).await.is_ok() {
            accepted += 1;
        }
    }

    // Expected (documenting the bypass): each distinct address gets its own
    // rate-limiter bucket, so far more than 1 connection/min succeeds despite
    // max_connections_per_ipaddr_per_min == 1.
    assert!(
        accepted > 1,
        "per-IP limit of 1/min was bypassed via /64 address rotation: accepted={accepted}"
    );
    // and total accepted is bounded only by the global max_unstaked_connections /
    // overall_connection_rate_limiter, not the per-IP policy:
    assert!(stats.connection_rate_limited_per_ipaddr.load(Ordering::Relaxed) == 0);
}
```
Expected result confirms `connection_rate_limited_per_ipaddr` stays at 0 while dozens of connections succeed from a single /64, demonstrating that the per-source QoS invariant is evaded even though the total is still capped by the shared global `max_unstaked_connections`/`overall_connection_rate_limiter` budget.

```rust
/// Limits the rate of connections per IP address.
pub struct ConnectionRateLimiter {
    limiter: KeyedRateLimiter<IpAddr>,
}

/// The threshold of the size of the connection rate limiter map. When
/// the map size is above this, we will trigger a cleanup of older
/// entries used by past requests.
const CONNECTION_RATE_LIMITER_CLEANUP_SIZE_THRESHOLD: usize = 100_000;

impl ConnectionRateLimiter {
    /// Create a new rate limiter per IpAddr. The rate is specified as the count per minute to allow for
    /// less frequent connections. Higher limit also allows higher bursts.
    /// num_shards controls how many shards are used in the underlying dashmap,
    /// should be set >= number of contending threads.
    pub fn new(limit_per_minute: u64, max_burst: u64, num_shards: usize) -> Self {
        Self {
            limiter: KeyedRateLimiter::new(
                CONNECTION_RATE_LIMITER_CLEANUP_SIZE_THRESHOLD,
                TokenBucket::new(limit_per_minute, max_burst, limit_per_minute as f64 / 60.0),
                num_shards,
            ),
        }
    }

    /// Check if the connection from the said `ip` is allowed.
    /// Here we assume that only IPs with actual confirmed connections are stored in it,
    /// since we should only modify server state once source IP is verified
    pub fn is_allowed(&self, ip: &IpAddr) -> bool {
        // Check if we have records in the rate limiter for the given IP address
        match self.limiter.current_tokens(ip) {
            Some(r) => r > 0, // we have a record, and rate is not exceeded
            None => true,     // if we have not seen IP, allow connection request
        }
    }

    pub fn register_connection(&self, ip: &IpAddr) -> bool {
        if self.limiter.consume_tokens(*ip, 1).is_ok() {
            debug!("Request from IP {ip:?} allowed");
            true // Request allowed
        } else {
            debug!("Request from IP {ip:?} blocked");
            false // Request blocked
        }
    }
```

```rust
    // Randomly selects sample_size many connections, evicts the one with the
    // lowest stake, and returns the number of pruned connections.
    // If the stakes of all the sampled connections are higher than the
    // threshold_stake, rejects the pruning attempt, and returns 0.
    pub(crate) fn prune_random(&mut self, sample_size: usize, threshold_stake: u64) -> usize {
        let num_pruned = std::iter::once(self.table.len())
            .filter(|&size| size > 0)
            .flat_map(|size| {
                let mut rng = rng();
                repeat_with(move || rng.random_range(0..size))
            })
            .map(|index| {
                let connection = self.table[index].first();
                let stake = connection.map(|connection: &ConnectionEntry<S>| connection.stake());
                (index, stake)
            })
            .take(sample_size)
            .min_by_key(|&(_, stake)| stake)
            .filter(|&(_, stake)| stake < Some(threshold_stake))
            .and_then(|(index, _)| self.table.swap_remove_index(index))
            .map(|(_, connections)| connections.len())
            .unwrap_or_default();
        self.total_size = self.total_size.saturating_sub(num_pruned);
        num_pruned
    }
```
