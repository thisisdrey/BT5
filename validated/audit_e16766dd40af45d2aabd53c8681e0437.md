### Title
Unclaimed emissions are permanently zeroed when a Balance is closed - ([File: programs/marginfi/src/state/marginfi_account.rs])

### Summary
When a user fully repays a liability or fully withdraws an asset (or explicitly calls `lending_account_close_balance`), the `Balance` slot is reset via `BalanceImpl::close()`, which overwrites the entire struct — including `emissions_outstanding` — with `Balance::empty_deactivated()`. Neither `close_balance()` nor `repay_all()` checks that `emissions_outstanding` is zero, nor do they sweep/settle it anywhere before wiping it. This mirrors the reported Alchemix bug class: unclaimed reward accounting attached to a position is destroyed when that position is closed/burned without first being claimed.

### Finding Description
`Balance::close()` unconditionally overwrites the balance with a zeroed struct: [1](#0-0) [2](#0-1) 

This is invoked from two accounting paths that any account authority can trigger without any special privilege:
- `close_balance()`, used by the `lending_account_close_balance` instruction, only validates that liability/asset amounts are zero — it never checks `emissions_outstanding`: [3](#0-2) 
- `repay_all()`, used when a user repays with `repay=true` (the flow the integrator docs explicitly call "the only way to close a Balance"), calls `balance.close()` right after validating the liability, again without touching `emissions_outstanding`: [4](#0-3) 

Notably, the error enum already defines a dedicated guard for exactly this scenario — `CannotCloseOutstandingEmissions` — but it is never referenced by any `check!()` in the instruction/state code; it only appears in its own definition and in a TS test-utility string: [5](#0-4) 

The `lending_account_close_balance` instruction itself performs no emissions-related validation before delegating to `close_balance()`: [6](#0-5) 

By contrast, when authority is migrated via `transfer_to_new_account`/`transfer_to_new_account_pda`, `emissions_outstanding` per-balance IS correctly carried over to the new account (verified in tests), which confirms the field is meant to persist and be claimable until settled — but `close_balance`/`repay_all` do not preserve or settle it, they simply erase it. [7](#0-6) 

### Impact Explanation
This is a permanent freezing/loss-of-yield bug: any accrued but not-yet-claimed emissions attributed to a `Balance` are irrecoverably destroyed the moment the position is fully repaid/withdrawn and closed (either explicitly via `lending_account_close_balance` or implicitly via full-repay). The dedicated `CannotCloseOutstandingEmissions` error code strongly indicates this check was intended but is not enforced in the current code path, making this a genuine unaddressed regression rather than a documented, accepted design tradeoff.

### Likelihood Explanation
Likelihood is moderate: it requires (a) a bank with an active/past emissions campaign that has accrued `emissions_outstanding` on the user's `Balance`, and (b) the user fully repaying (`repay=true`) or withdrawing (`withdraw_all=true`)/calling `close_balance` before claiming those emissions. Given emissions/claim flows are separate, ordinary user instructions (repay-all, withdraw-all, close-balance) with no special coordination required, this is straightforward to trigger unintentionally by a normal unprivileged user managing their own position.

### Recommendation
Before allowing `close_balance()`/`repay_all()` to zero out a `Balance`, either:
1. Reject the close if `balance.emissions_outstanding` is non-zero (re-enable/wire up `MarginfiError::CannotCloseOutstandingEmissions`), forcing the user to claim emissions first, or
2. Automatically sweep `emissions_outstanding` to the account's emissions-claim state (or a claimable holding balance) before zeroing the `Balance`, so closing a position never destroys already-accrued rewards.

### Proof of Concept
Not independently executed against the live program (read-only analysis); the codebase inspection shows the reachable path directly:
1. Deposit/borrow on a bank with an active emissions campaign so that `balance.emissions_outstanding` accrues a non-zero value (see `programs/marginfi/src/instructions/marginfi_account/emissions.rs` for accrual logic).
2. Fully repay the liability with `repay=true` (`lending_account_repay`) — this calls `repay_all()`, which calls `balance.close()`.
3. Read back the account's `Balance` for that bank and observe `emissions_outstanding == 0`, with no emissions having been claimed or transferred anywhere — confirming permanent loss.
Alternatively, step 2 can be replaced by first withdrawing the full asset balance and then calling `lending_account_close_balance`, which reaches `close_balance()` with the same result.

Note: I could not fully verify the current status/reachability of the emissions campaign mechanism itself in this build (patch notes indicate significant emissions-system wind-down in `patch-note-drafts/patch-notes-0.1.9.md`, e.g. removal of `lending_pool_reclaim_emissions_vault`/`lending_account_clear_emissions`), so it's possible some emissions campaigns are now legacy-only; however, the `emissions_outstanding` field, its accrual mechanism (`emissions.rs`), and the destructive `close()`/`repay_all()` paths are all still present and unguarded in the current code, so the underlying accounting bug remains valid wherever `emissions_outstanding` can be non-zero at close time.

pub fn lending_account_close_balance(ctx: Context<LendingAccountCloseBalance>) -> MarginfiResult {
    let LendingAccountCloseBalance {
        marginfi_account,
        bank: bank_loader,
        group: marginfi_group_loader,
        ..
    } = ctx.accounts;

    let mut marginfi_account = marginfi_account.load_mut()?;
    let mut bank = bank_loader.load_mut()?;

    check!(
        !marginfi_account.get_flag(ACCOUNT_DISABLED),
        MarginfiError::AccountDisabled
    );

    let group = &*marginfi_group_loader.load()?;
    bank.accrue_interest(
        Clock::get()?.unix_timestamp,
        group,
        #[cfg(not(feature = "client"))]
        bank_loader.key(),
    )?;

    bank.update_bank_cache(group)?;

    let in_receivership = marginfi_account.get_flag(ACCOUNT_IN_RECEIVERSHIP);
    let lending_account: &mut marginfi_type_crate::types::LendingAccount =
        &mut marginfi_account.lending_account;
    let mut bank_account =
        BankAccountWrapper::find(&bank_loader.key(), &mut bank, lending_account)?;

    bank_account.close_balance(in_receivership)?;
    lending_account.sort_balances();
    marginfi_account.sync_indexer_flags();
    marginfi_account.last_update = Clock::get()?.unix_timestamp as u64;

    Ok(())
}
