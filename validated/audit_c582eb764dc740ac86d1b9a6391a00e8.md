### Title
Unbounded/mismatched-width varint parsing in reftable block decoder can panic Gitaly on crafted reference data - (File: internal/git/reftable/reftable.go)

### Summary
The Cosmos SDK advisory (ASA-2024-010) describes a bit-length mismatch between `sdk.Int` and `sdk.Dec` that let out-of-range values slip past validation and later cause a panic during arithmetic in an unrelated numeric domain. The closest reachable analog in this codebase is Gitaly's own binary reftable block parser in `internal/git/reftable/reftable.go`, which decodes attacker/peer-influenced varints and lengths with no width or bounds validation against the actual block/slice sizes, and then uses the resulting values directly as slice indices and lengths.

### Finding Description
`Table.getVarInt` decodes a git reftable varint by shifting an unsigned `uint` with no cap on the number of continuation bytes or resulting magnitude: [1](#0-0) 

The only bound enforced is that the *byte position* `start` does not exceed `blockEnd`; the *decoded value* `val` itself is never checked against the size of the block or the source slice. This value is then used, unchecked, as a length to slice into the raw block bytes in `getRefsFromBlock`: [2](#0-1) 
and again for the symref-length case: [3](#0-2) 

Similarly, `extractBlockLen` and `parseRefBlock` compute the restart-table position by subtracting an attacker-influenced count from an offset with no lower-bound check, which can underflow the unsigned `uint` arithmetic and produce a huge value used to slice into `src`: [4](#0-3) 

This mirrors the advisory's bug class: numeric width/validation of one representation (the varint's logical value, or the restart-count-derived offset) is never reconciled with the bit-width/bounds of the buffer it indexes into (`src []byte`), which is exactly the "mismatched bit-length validation" pattern that leads to a panic rather than a controlled error.

### Impact Explanation
Because Go slicing panics on out-of-range indices (`index out of range` or `slice bounds out of range`) rather than returning an error, a single crafted reftable block reaching `Table.GetReferences()` can crash the Gitaly worker goroutine handling that RPC. Table parsing is invoked from `internal/gitaly/storage/storagemgr/partition/reftable.go`'s `stageTables`/`getLatestReftableName` path (transaction resequencing during commits) and from repository replication (`internal/gitaly/service/repository/replicate.go`) and snapshot-based repo creation, where the reftable directory is populated by the tar-extraction of a `GetSnapshot` stream sourced from another node's repository state — i.e., data whose byte-level shape is only as trustworthy as whatever wrote it to disk, not solely git's own writer. A malformed/corrupted or maliciously constructed reftable block (e.g. delivered via replication of a repository whose reftable files were tampered with, or via any code path that reads a table an attacker can influence) causes an unrecovered panic in the parsing goroutine, resulting in denial of service of that RPC handler (and, depending on panic-recovery middleware, potentially the whole process).

### Likelihood Explanation
Likelihood is moderate: reftable files are normally produced by Git itself, so triggering this from an ordinary `git push` is not straightforward. However, reftable parsing is exercised in transaction/WAL resequencing (`stageTables`) during ordinary reference-update transactions, and in replication/snapshot restoration flows that copy raw files between Gitaly nodes without independent structural validation of the reftable's internal varint/length fields. Any code path that allows reading a table file whose bytes were not produced by a fully-trusted `git reftable` writer (partial writes, tampered snapshot data, or corrupted disk state) can reach `getVarInt`/`getRefsFromBlock` with unvalidated lengths.

### Recommendation
- In `getVarInt`, bound the decoded `val` (and number of continuation bytes) against a sane maximum (e.g., block size or a fixed shift limit) and return an error rather than allowing unbounded growth.
- In `getRefsFromBlock` and `parseRefBlock`, validate `prefixLength`, `suffixLength`, and `size` against `len(src)`/`b.RestartStart`/`b.FullBlockSize` before slicing, returning a structured error on overflow instead of panicking.
- In `parseRefBlock`, check that `blockStart+currentBS-2-3*uint(b.RestartCount)` does not underflow before computing `RestartStart`.
- Wrap `Table.GetReferences()` (and its callers in the storage manager / replication code) with panic recovery converting to a structured error, consistent with how other malformed-input parsers in this codebase (e.g. `internal/git/mvcc/manifest.go`, `internal/git/packfile/bitmap.go`) explicitly bound-check every offset/length before use.

### Proof of Concept
1. Construct a minimal valid reftable header/footer (version 1 or 2) with a single ref block.
2. Within the ref block, craft a `prefixLength`/`suffixLength` varint pair whose decoded `suffixLength` value, once shifted (`(val+1)<<7`) several times, produces a length far larger than the remaining bytes in the block, or craft a byte pattern that makes `RestartCount` large enough that `blockStart+currentBS-2-3*uint(b.RestartCount)` underflows to a huge `uint`.
3. Feed this table file into any Gitaly code path that calls `reftable.ParseTable` + `GetReferences` on it (e.g. as part of `stageTables` during a reference-update transaction, or via a replicated snapshot containing this crafted `reftable/*.ref` file).
4. Observe that `src[idx:idx+suffixLength]` (or `src[blockStart+currentBS-2:]`) panics with a slice-bounds-out-of-range error, crashing the handling goroutine — demonstrating the DoS analog to the advisory's mismatched-bit-length panic condition.

// getVarInt parses a variable int and increases the index.
func (t *Table) getVarInt(src []byte, start uint, blockEnd uint) (uint, uint, error) {
	var val uint

	val = uint(src[start]) & 0x7f

	for (uint(src[start]) & 0x80) > 0 {
		start++
		if start > blockEnd {
			return 0, 0, fmt.Errorf("exceeded block length")
		}

		val = ((val + 1) << 7) | (uint(src[start]) & 0x7f)
	}

	return start + 1, val, nil
}

// parseRefBlock parses a block and if it is a ref block, provides
// all the reference updates.
func (t *Table) parseRefBlock(src []byte, headerOffset, blockStart, blockEnd uint) ([]git.Reference, error) {
	currentBS := t.extractBlockLen(src, blockStart+headerOffset)

	fullBlockSize := t.blockSize
	if fullBlockSize == 0 {
		fullBlockSize = currentBS
	} else if currentBS < fullBlockSize && currentBS < (blockEnd-blockStart) && src[blockStart+currentBS] != 0 {
		fullBlockSize = currentBS
	}

	b := &block{
		BlockStart:    blockStart + headerOffset,
		FullBlockSize: fullBlockSize,
	}

	if err := binary.Read(bytes.NewBuffer(src[blockStart+currentBS-2:]), binary.BigEndian, &b.RestartCount); err != nil {
		return nil, fmt.Errorf("reading restart count: %w", err)
	}

	b.RestartStart = blockStart + currentBS - 2 - 3*uint(b.RestartCount)

	return t.getRefsFromBlock(src, b)
