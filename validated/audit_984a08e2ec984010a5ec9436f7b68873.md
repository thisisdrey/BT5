### Title
Firewall rule-reload bypass via stale per-routine conntrack cache — ([File: firewall.go])

### Summary
The Fuji report's bug class ("state consulted for authorization decisions must be refreshed before it is read, or callers silently use a stale value") maps onto Nebula's firewall conntrack fast-path. `Firewall.inConns` allows a packet immediately if it is present in a per-routine `localCache`, without ever comparing the cached flow's rule version to the firewall's current `rulesVersion`. Only the slower, non-cached path (`conntrack.Conns[fp]`) performs that revalidation.

### Finding Description
`Firewall.Drop` calls `f.inConns(fp, h, caPool, localCache)` to short-circuit the full rule match if the flow is already established [1](#0-0) . Inside `inConns`, the very first check is against the caller-supplied `localCache`, and if the tuple is present it returns `true` immediately — no `rulesVersion` comparison occurs on this path: [2](#0-1) 

Only when the tuple is *not* in `localCache` does the code fall through to `conntrack.Conns[fp]`, where the entry's `rulesVersion` is compared to `f.rulesVersion` and revalidated against the *current* rule table if the firewall was reloaded [3](#0-2) . This revalidation logic — the exact mechanism designed to prevent stale-rule authorization — is what `localCache` bypasses.

`localCache` is a `firewall.ConntrackCache` (`map[Packet]struct{}`) obtained from a `ConntrackCacheTicker` that is reset only on a fixed wall-clock tick, completely decoupled from `Firewall.rulesVersion`: [4](#0-3)  The ticker interval is controlled by `firewall.conntrack.routine_cache_timeout`, defaulting to 1 second when running with multiple routines: [5](#0-4) 

Meanwhile, `reloadFirewall` swaps in a new `Firewall` object and bumps `rulesVersion` on every config/cert change (e.g. a SIGHUP with a tightened firewall policy), specifically so `inConns`'s conntrack-entry revalidation catches already-established flows that should now be blocked: [6](#0-5)  That revalidation is exactly the code path `localCache` skips.

The same `localCache` is threaded through both the inbound and outbound packet paths (`handleOutsideMessagePacket` / `consumeInsidePacket`), so both directions of traffic are affected: [7](#0-6) [8](#0-7) 

### Impact Explanation
For up to `routine_cache_timeout` (default 1s with multiple routines, but operator-configurable to an arbitrary duration) after a firewall reload narrows or removes a rule, any flow a peer had established under the old rule set continues to be admitted on that routine, ignoring the new (more restrictive) policy — a firewall bypass. This is a remote-state-poisoning/enforcement-bypass class issue: the enforcement decision is made against data that was never refreshed to reflect the update, exactly analogous to the Fuji report's "operation reads a value that a required update step didn't refresh yet."

### Likelihood Explanation
Likelihood is moderate-to-low: it requires (1) an existing flow between two nebula peers, and (2) a firewall config/cert change (SIGHUP or a certificate-driven `unsafe_networks` change) that would deny that flow going forward, occurring while `firewall.conntrack.routine_cache_timeout` is non-zero (on by default whenever `routines > 1`). In that window, a peer can keep the previously allowed flow open (or race to reuse the 5-tuple) and continue sending traffic that should have been dropped.

### Recommendation
- Short term: have `inConns` check the cached tuple against `f.rulesVersion` even on the `localCache` hit path (e.g., store/compare a version stamp per cached tuple, or simply skip the `localCache` fast path whenever `oldFw.rulesVersion != fw.rulesVersion` has changed since the cache was built), or invalidate/clear `ConntrackCacheTicker`'s cache synchronously whenever `reloadFirewall` swaps in a new firewall/rulesVersion instead of relying solely on the independent time-based tick.
- Long term: redesign the fast-path cache so it cannot diverge from `rulesVersion` by construction — e.g., key the cache by `(Packet, rulesVersion)` or tie cache invalidation directly to the firewall-reload event rather than a wall-clock ticker, mirroring the report's recommendation to prevent developers/operators from being able to "forget" to invalidate cached authorization state.

### Proof of Concept
1. Start two nebula nodes with `routines > 1` (or `firewall.conntrack.routine_cache_timeout` set) and a permissive inbound rule (e.g., allow UDP port 90 from `any`).
2. Establish a flow between them so a conntrack entry (and the per-routine `localCache` entry) is created for `(local, remote, 90/udp)`, as in the existing `TestFirewall_DropConntrackReload` unit test scaffold [9](#0-8) .
3. On the receiving node, reload the firewall config (SIGHUP) with a new rule set that no longer allows port 90 (bump `rulesVersion`), as exercised in `TestReloadFirewall_CertUnsafeNetworksChanged`/`reloadFirewall` [6](#0-5) .
4. Within the `routine_cache_timeout` window, send another packet on the same 5-tuple on the same routine. Because `inConns` checks `localCache` before comparing `rulesVersion`, `Drop` returns `nil` (packet allowed) even though the newly loaded rule table would reject it — unlike the non-cached path, which correctly returns `ErrNoMatchingRule` for the analogous scenario without `localCache` populated, as shown by `TestFirewall_DropConntrackReload`'s final assertion [10](#0-9) .

Note on confidence: I was unable to locate the exact call site that constructs/passes the `ConntrackCacheTicker`-backed `localCache` into the packet-processing loop (`GetConntrackCache`/`cacheTicker` symbols were not found by search), so the precise per-routine wiring between `ConntrackCacheTimeout` and each `Drop` call could not be fully traced with the available tools. The core divergence — `inConns`'s `localCache` short-circuit bypassing the `rulesVersion` check that the non-cached path performs — is directly confirmed in `firewall.go`.

// Get checks if the cache ticker has moved to the next version before returning
// the map. If it has moved, we reset the map.
func (c *ConntrackCacheTicker) Get() ConntrackCache {
	if c == nil {
		return nil
	}
	if tick := c.cacheTick.Load(); tick != c.cacheV {
		c.cacheV = tick
		if ll := len(c.cache); ll > 0 {
			if c.l.Enabled(context.Background(), slog.LevelDebug) {
				c.l.Debug("resetting conntrack cache", "len", ll)
			}
			c.cache = make(ConntrackCache, ll)
		}
	}

	return c.cache
}

func (f *Interface) consumeInsidePacket(packet []byte, fwPacket *firewall.Packet, nb, out []byte, q int, localCache firewall.ConntrackCache) {
	err := newPacket(packet, false, fwPacket)
	if err != nil {
		if f.l.Enabled(context.Background(), slog.LevelDebug) {
			f.l.Debug("Error while validating outbound packet",
				"packet", packet,
				"error", err,
			)
		}
		return
	}

	// Ignore local broadcast packets
	if f.dropLocalBroadcast {
		if f.myBroadcastAddrsTable.Contains(fwPacket.RemoteAddr) {
			return
		}
	}

	if f.myVpnAddrsTable.Contains(fwPacket.RemoteAddr) {
		// Immediately forward packets from self to self.
		// This should only happen on Darwin-based and FreeBSD hosts, which
		// routes packets from the Nebula addr to the Nebula addr through the Nebula
		// TUN device.
		if immediatelyForwardToSelf {
			_, err := f.readers[q].Write(packet)
			if err != nil {
				f.l.Error("Failed to forward to tun", "error", err)
			}
		}
		// Otherwise, drop. On linux, we should never see these packets - Linux
		// routes packets from the nebula addr to the nebula addr through the loopback device.
		return
	}

	// Ignore multicast packets
	if f.dropMulticast && fwPacket.RemoteAddr.IsMulticast() {
		return
	}

	hostinfo, ready := f.getOrHandshakeConsiderRouting(fwPacket, func(hh *HandshakeHostInfo) {
		hh.cachePacket(f.l, header.Message, 0, packet, f.sendMessageNow, f.cachedPacketMetrics)
	})

	if hostinfo == nil {
		f.rejectInside(packet, out, q)
		if f.l.Enabled(context.Background(), slog.LevelDebug) {
			f.l.Debug("dropping outbound packet, vpnAddr not in our vpn networks or in unsafe networks",
				"vpnAddr", fwPacket.RemoteAddr,
				"fwPacket", fwPacket,
			)
		}
		return
	}

	if !ready {
		return
	}

	dropReason := f.firewall.Drop(*fwPacket, false, hostinfo, f.pki.GetCAPool(), localCache)
	if dropReason == nil {
		f.sendNoMetrics(header.Message, 0, hostinfo.ConnectionState, hostinfo, netip.AddrPort{}, packet, nb, out, q)

	} else {
		f.rejectInside(packet, out, q)
		if f.l.Enabled(context.Background(), slog.LevelDebug) {
			hostinfo.logger(f.l).Debug("dropping outbound packet",
				"fwPacket", fwPacket,
				"reason", dropReason,
			)
		}
	}
}
