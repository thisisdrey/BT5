### Title
`early_resolution_vote_threshold` Inflated by Non-Voting APT Supply — (`aptos-move/framework/aptos-framework/sources/aptos_governance.move`)

### Summary

`create_proposal_v2_impl` sets the early-resolution threshold to `coin::supply<AptosCoin>() / 2 + 1`. `coin::supply<AptosCoin>()` counts every APT in existence — including APT held in regular accounts, APT in the `inactive` state of a stake pool, and APT that has never been staked — none of which carries any governance voting power. The actual maximum achievable vote count is bounded by the subset of staked APT whose lockup extends past the proposal's expiration. When that subset is materially smaller than half the total supply, early resolution can never be triggered regardless of how many eligible stakers participate.

### Finding Description

In `create_proposal_v2_impl`:

```move
let total_voting_token_supply = coin::supply<AptosCoin>();
let early_resolution_vote_threshold = option::none<u128>();
if (total_voting_token_supply.is_some()) {
    let total_supply = *total_voting_token_supply.borrow();
    // 50% + 1 to avoid rounding errors.
    early_resolution_vote_threshold = option::some(total_supply / 2 + 1);
};
``` [1](#0-0) 

`coin::supply<AptosCoin>()` returns the aggregate of every APT token tracked by `CoinInfo<AptosCoin>` plus the paired fungible-asset supply: [2](#0-1) 

This total includes:
- APT held in ordinary accounts (zero governance voting power)
- APT in the `inactive` bucket of a `StakePool` (already unlocked, zero voting power)
- APT in stake pools whose lockup expires before the proposal does (ineligible to vote)

Governance voting power is derived exclusively from `get_voting_power(stake_pool)`, which sums only `active + pending_active + pending_inactive` for pools whose lockup extends past the proposal expiration: [3](#0-2) 

The code comment itself acknowledges the mismatch but frames it as minor inflation/deflation noise: [4](#0-3) 

In reality the gap is structural: a large fraction of total APT supply is permanently non-voting (held on exchanges, in cold wallets, or in `inactive` stake), making the discrepancy far larger than epoch-level inflation.

The `can_be_resolved_early` check in `voting.move` compares accumulated `yes_votes` or `no_votes` against this inflated threshold: [5](#0-4) 

### Impact Explanation

When the sum of all eligible staked APT (with sufficient lockup) is less than `coin::supply<AptosCoin>() / 2 + 1`, early resolution is permanently unreachable even if every eligible staker votes unanimously. Emergency governance actions that depend on the early-resolution path — intended to allow the network to react quickly to critical bugs or attacks — are silently disabled. Proposals must always wait for the full `voting_duration_secs` to elapse, removing the safety valve the mechanism was designed to provide.

Note: the `min_vote_threshold` used for normal (post-expiry) resolution is a fixed absolute value set at governance initialization and is not derived from total supply, so ordinary proposals can still pass after the voting period. The impact is confined to the early-resolution path.

### Likelihood Explanation

On Aptos mainnet a significant fraction of total APT supply is not staked (held on exchanges, in cold wallets, or in `inactive` pools). The early-resolution threshold is therefore structurally higher than the maximum achievable vote count from eligible stakers, making the condition permanently or near-permanently unachievable without any attacker action — it is a passive design flaw triggered by normal network usage.

### Recommendation

Replace `coin::supply<AptosCoin>()` with the sum of `total_voting_power` across all active and pending-inactive validators (i.e., the actual maximum achievable vote count), or use a fixed governance-configured absolute threshold that is known to be reachable. If a supply-based percentage is desired, it should be computed over staked APT only, not total circulating supply.

### Proof of Concept

1. At proposal creation time, `coin::supply<AptosCoin>()` returns, say, 1 000 000 000 APT.
2. `early_resolution_vote_threshold` is set to 500 000 001 APT.
3. Total staked APT with lockup extending past the proposal expiration is 400 000 000 APT.
4. Even if all 400 000 000 APT votes `yes`, `yes_votes (400 000 000) < early_resolution_threshold (500 000 001)`.
5. `can_be_resolved_early` returns `false`; the proposal cannot be resolved early regardless of unanimous support.
6. The network must wait the full `voting_duration_secs` before the proposal can be resolved through the normal path. [6](#0-5) [7](#0-6)

    /// Returns the amount of coin in existence.
    public fun supply<CoinType>(): Option<u128> acquires CoinInfo, CoinConversionMap {
        let coin_supply = coin_supply<CoinType>();
        let metadata = paired_metadata<CoinType>();
        if (metadata.is_some()) {
            let fungible_asset_supply =
                fungible_asset::supply(metadata.extract());
            if (coin_supply.is_some()) {
                let supply = coin_supply.borrow_mut();
                *supply += fungible_asset_supply.destroy_some();
            };
        };
        coin_supply
    }
