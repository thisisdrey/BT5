### Title
Rewards accrued for a witness with zero votes in a cycle are permanently lost, never converted into claimable `Vi` - ([File: chainbase/src/main/java/org/tron/core/store/DelegationStore.java])

### Summary
`DelegationStore.accumulateWitnessVi` is the java-tron analog of Synthetix-style `rewardPerToken()` accumulation in `VirtualStakingRewards`. Just as the reported Solidity bug skips reward accrual when `_totalSupply == 0`, `accumulateWitnessVi` skips accrual whenever a witness's `voteCount` for the cycle is `0`, permanently losing the reward that was already credited into the per-cycle reward pot via `payReward`.

### Finding Description
Each cycle, `MaintenanceManager.doMaintenance()` calls, for every witness: [1](#0-0) 
which invokes `DelegationStore.accumulateWitnessVi(cycle, address, voteCount)`: [2](#0-1) 

Meanwhile, block/transaction-fee rewards are unconditionally accrued into the same cycle's reward bucket via `MortgageService.payReward` → `delegationStore.addReward(cycle, witnessAddress, value)`, independent of whether the witness had any recorded votes for that cycle: [3](#0-2) 

When `accumulateWitnessVi` runs for that cycle and finds `voteCount == 0` (e.g., a witness produced blocks and earned reward in a cycle where nobody currently holds votes for it, or votes have not yet been snapshotted/updated for that cycle), it takes the "just forward pre Vi" branch and does **not** fold the accumulated `reward` into `deltaVi`:
```java
if (reward == 0 || voteCount == 0) { // Just forward pre vi
  ...
} else { // Accumulate delta vi
```
The reward value stored via `addReward` for that cycle is simply discarded from the Vi-based reward stream — it is never redistributed to any voter, and there is no sweep/rollover mechanism to recover it in later cycles. This mirrors exactly the reported `VirtualStakingRewards` flaw where rewards accrued while `_totalSupply == 0` are dropped from `rewardPerTokenStored` and become permanently stuck.

The legacy (`useNewRewardAlgorithm` == false) path has the analogous behavior in `MortgageService.computeReward(cycle, votes)`, which also skips a cycle's reward entirely when `totalVote == REMARK || totalVote == 0`: [4](#0-3) 

### Impact Explanation
TRX minted/allocated as block rewards and transaction-fee rewards for a witness in a cycle where that witness's on-chain vote snapshot is zero become permanently unclaimable by any account — they are not credited to the witness's brokerage allowance (that portion is handled separately) and not converted into `Vi`, so no voter can ever withdraw them via `withdrawReward`/`queryReward`. This is a permanent freezing/loss-of-funds condition affecting the reward pool, reachable purely through normal DPoS operation (a witness losing all votes for one cycle while still being scheduled to produce a block, or being paid standby rewards) — no privileged or malicious actor is required.

### Likelihood Explanation
This requires a witness to have `voteCount == 0` for a given cycle snapshot (`getWitnessVote`/`witness.getVoteCount()` at the time `accumulateWitnessVi` runs) while reward was still added for that cycle (block/tx-fee reward, or standby-witness pay). This can occur naturally, e.g., a witness that is briefly active/paid but has all voters unvote within the same cycle boundary, or during the standby-witness payout to witnesses whose vote count is nonzero but individually rounds edge cases; the exact triggering window depends on cycle/vote timing and would need to be confirmed via a live network trace, since I could not fully verify all code paths that populate `witness.getVoteCount()` vs. `delegationStore.getWitnessVote(cycle, ...)` used elsewhere.

### Recommendation
When `voteCount == 0` but `reward > 0` in `accumulateWitnessVi`, do not discard `reward`; instead roll it forward (e.g., carry it into the next cycle's reward bucket for the same witness via `addReward(cycle+1, address, reward)`), or ensure `payReward`/`payStandbyWitness` never register a reward for a cycle where the witness's committed vote count is zero. Add a corresponding fix to the legacy `computeReward(cycle, votes)` path in `MortgageService`.

### Proof of Concept
Not independently reproducible from static analysis alone — the report is an analog derived from code-flow inspection of `DelegationStore.accumulateWitnessVi` and `MortgageService.payReward`/`computeReward`; a live/testnet simulation would be needed to trigger the exact `voteCount == 0` + nonzero `reward` condition for a specific cycle and confirm the reward is unrecoverable.

  public void accumulateWitnessVi(long cycle, byte[] address, long voteCount) {
    BigInteger preVi = getWitnessVi(cycle - 1, address);
    long reward = getReward(cycle, address);
    if (reward == 0 || voteCount == 0) { // Just forward pre vi
      if (!BigInteger.ZERO.equals(preVi)) { // Zero vi will not be record
        setWitnessVi(cycle, address, preVi);
      }
    } else { // Accumulate delta vi
      BigInteger deltaVi = BigInteger.valueOf(reward)
          .multiply(DECIMAL_OF_VI_REWARD)
          .divide(BigInteger.valueOf(voteCount));
      setWitnessVi(cycle, address, preVi.add(deltaVi));
    }
  }
```

    long cycle = dynamicPropertiesStore.getCurrentCycleNumber();
    int brokerage = delegationStore.getBrokerage(cycle, witnessAddress);
    double brokerageRate = (double) brokerage / 100;
    long brokerageAmount = (long) (brokerageRate * value);
    value -= brokerageAmount;
    delegationStore.addReward(cycle, witnessAddress, value);
    adjustAllowance(witnessAddress, brokerageAmount);
  }

  private long computeReward(long cycle, List<Pair<byte[], Long>> votes) {
    long reward = 0;
    for (Pair<byte[], Long> vote : votes) {
      byte[] srAddress = vote.getKey();
      long totalReward = delegationStore.getReward(cycle, srAddress);
      if (totalReward <= 0) {
        continue;
      }
      long totalVote = delegationStore.getWitnessVote(cycle, srAddress);
      if (totalVote == DelegationStore.REMARK || totalVote == 0) {
        continue;
      }
      long userVote = vote.getValue();
      double voteRate = (double) userVote / totalVote;
      reward += voteRate * totalReward;
    }
    return reward;
  }
```
