### Title
Debt interest under-accrues because `SECONDS_PER_YEAR` uses 365.25 days - (File: contracts/DebtToken.sol)

### Summary
`DebtToken` defines `SECONDS_PER_YEAR` as `365.25 days` even though `interestRate` is documented as an APR; this makes `interestRatePerSecond()` divide the annual rate by `31,557,600` seconds instead of `31,536,000`. [1](#0-0) [2](#0-1) 

### Finding Description
`_calculateInterestAccrual()` multiplies `interestRatePerSecond()` by the elapsed time, while `interestRatePerSecond()` returns `interestRate / SECONDS_PER_YEAR`. [3](#0-2) [4](#0-3) 

The oversized denominator causes every nonzero configured APR to be converted into a per-second rate approximately `0.0684%` too small. [1](#0-0) 

An unprivileged borrower reaches this calculation through `DebtToken.issue()`, which accrues interest before creating debt, or through `repay()` and `repayAll()`, which accrue interest before repayment. [5](#0-4) [6](#0-5) [7](#0-6) 

### Impact Explanation
Borrowers systematically repay less interest than the configured APR specifies, while the protocol fee collector receives correspondingly less minted synthetic interest during `accrueInterest()`. [8](#0-7) 

For a principal `P` and configured APR `R`, a 365-day interval accrues approximately `P * R * 365 / 365.25` instead of `P * R`, producing a loss of `P * R * 0.25 / 365.25` in accrued debt and fee revenue. [9](#0-8) 

### Likelihood Explanation
The error is deterministic whenever a nonzero interest rate is configured because `accrueInterest()` is public and is also invoked automatically by public borrowing and repayment entry points. [10](#0-9) [5](#0-4) 

No privileged actor, oracle manipulation, reentrancy, or special timing is needed beyond normal debt issuance and elapsed time. [11](#0-10) 

### Recommendation
Replace `365.25 days` with the intended annualization constant of exactly `365 days` or `31_536_000` seconds, so that configured APR values map correctly to per-second rates. [1](#0-0) 

```solidity
uint256 public constant SECONDS_PER_YEAR = 365 days;
```

### Proof of Concept
This Foundry test can be added to `DebtTokenInvariant_Test`, which already deploys `underlying`, `depositToken`, `syntheticToken`, and `debtToken`. [12](#0-11) 

```solidity
function test_interestUnderAccruesDueToLeapYearDenominator() external {
    debtToken.updateInterestRate(1e18); // configured as 100% APR

    address user = address(0xA77ACC);
    uint256 depositAmount = 1_000e18;
    uint256 principal = 100e18;

    vm.startPrank(user);
    underlying.mint(user, depositAmount);
    underlying.approve(address(depositToken), depositAmount);
    depositToken.deposit(depositAmount, user);
    debtToken.issue(principal, user);

    vm.warp(block.timestamp + 365 days);
    debtToken.accrueInterest();
    vm.stopPrank();

    uint256 expectedCorrectDebt = principal * 2; // 100% APR over 365 days

    uint256 wrongPerSecondRate = 1e18 / 31_557_600; // 365.25 days
    uint256 wrongRateToAccrue = wrongPerSecondRate * 31_536_000;
    uint256 expectedActualDebt = principal + (wrongRateToAccrue * principal) / 1e18;

    assertLt(debtToken.balanceOf(user), expectedCorrectDebt);
    assertApproxEqAbs(debtToken.balanceOf(user), expectedActualDebt, 1e12);
}
```

At a configured 100% APR, the borrower’s debt after 365 days is approximately `199.93155` tokens rather than `200` tokens, proving that the borrower receives an unintended discount and the protocol under-accrues fee revenue. [9](#0-8)
