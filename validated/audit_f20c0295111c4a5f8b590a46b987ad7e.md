### Title
Postponed self-receipt from a deleted account survives `remove_account` and hijacks a re-created account of the same name - ([File: core/store/src/utils/mod.rs / runtime/runtime/src/actions.rs])

### Summary
`remove_account` (`core/store/src/utils/mod.rs:504-575`) removes `Account`, `ContractCode`, `AccessKey`/gas-key rows, and `ContractData`, but never removes `TrieKey::PostponedReceipt`, `TrieKey::PendingDataCount`, or `TrieKey::PostponedReceiptId` entries keyed under the deleted `receiver_id`. Because `check_actor_permissions` (`runtime/runtime/src/actions.rs:739-784`) authorizes purely by comparing `AccountId` strings (`actor_id != account_id`), a self-targeted postponed `ActionReceipt` created before deletion (`predecessor_id == receiver_id == A`) will still pass authorization once delivered against a brand-new account that happens to have been re-created under the same name `A`.

### Finding Description
An attacker controlling account `A` can, from a `FunctionCall` executed by `A`, call `promise_create`/`promise_then` targeting itself (`receiver_id = A`) with a data dependency (an unresolved `input_data_id`), producing an `ActionReceipt` with `predecessor_id = A`, `receiver_id = A`, and a queued privileged action such as `AddKey(FullAccess, attacker_key)`. Because the dependency is unmet, `process_action_receipt` (`runtime/runtime/src/lib.rs:1593-1655`) stores this as a **postponed receipt**: `TrieKey::PendingDataCount{receiver_id: A, receipt_id}` and `TrieKey::PostponedReceipt{receiver_id: A, receipt_id}`, plus a `TrieKey::PostponedReceiptId{receiver_id: A, data_id}` link (set in `lib.rs:1614-1622`).

The attacker then submits `DeleteAccount(beneficiary=A)` from `A`. `action_delete_account` (`runtime/runtime/src/actions.rs:314-390`) calls `remove_account` (`core/store/src/utils/mod.rs:504-575`), which only iterates and removes `Account`, `ContractCode`, access/gas keys, and `ContractData` — it has no knowledge of, and never scans for, `PostponedReceipt`/`PendingDataCount`/`PostponedReceiptId` rows. These three rows, all keyed by `receiver_id = A`, survive account deletion untouched in the trie.

Once account `A`'s name becomes available, an unrelated party `B` can call `CreateAccount` for the name `A` (as a top-level account it must go through the registrar, or as a sub-account any predecessor can create its own sub-account with that label; either way a distinct, unrelated new account object is created at the same `AccountId` string). `B` may then deploy a contract and start using `A` normally.

When the dependency-resolving `DataReceipt` eventually arrives (attacker can trigger this arbitrarily, e.g., by having the callee finish its call), `process_receipt` (`runtime/runtime/src/lib.rs:1386-1455`) finds the `PostponedReceiptId` link, decrements `PendingDataCount` to zero, fetches the stored `ready_receipt` via `get_postponed_receipt`, and calls `apply_action_receipt` on it. Inside `apply_action_receipt` (`runtime/runtime/src/lib.rs:773-951`), `actor_id` is initialized to `receipt.predecessor_id().clone()` (line 855), which is the string `"A"`, and `account_id` is `receipt.receiver_id()`, also `"A"` — now referring to `B`'s freshly created account. `check_actor_permissions` (`actions.rs:739-784`) only checks `actor_id != account_id` as strings; since both are `"A"`, the check trivially passes for `AddKey`/`DeployContract`/`DeleteKey`, and the queued privileged action executes against the new owner's account, granting the attacker's key full access (or replacing code) on an account it does not own.

This defeats the intended authorization invariant that a promise/receipt should only carry privileges its creator held over the *current* incarnation of the account — the check has no notion of account "generation" and the storage cleanup on deletion is incomplete, letting a stale postponed receipt outlive the account it was scoped to.

### Impact Explanation
This is an authorization-escalation / account-hijack bug: an attacker who once owned account name `A` can later inject a `FullAccess` key (or deploy a contract) onto whatever unrelated account subsequently reuses the name `A`, without holding any key or relationship to that new account. This falls under "authorization escalation across accounts / account hijack of a re-created name," a critical-severity finding per the stated scope, since it directly permits theft/control of a re-created account's funds and access.

### Likelihood Explanation
Preconditions are all within a normal unprivileged user's capability: create/own an account, deploy a trivial contract that issues a self-targeted `promise_then`, delete the account, and wait for someone (anyone) to re-create an account with that exact name — which for sub-accounts is entirely within the attacker's own control (e.g., `attacker` deletes `victim.attacker`, but note the direct exploit requires a *third party* to recreate the same name; more realistically an attacker who controls a namespace can pre-arrange or wait for reuse of desirable short/top-level names, or use their own registrar-created sub-account and later re-issue `CreateAccount` for the same sub-account themselves to selfishly re-add a key that outlives an intended "reset"). The cost is a few actions' worth of gas; the postponed state persists indefinitely in the trie since nothing garbage-collects it independent of account lifetime. Repeatable per account name.

### Recommendation
Make `remove_account` (or `action_delete_account`) also scan and remove any `TrieKey::PostponedReceipt`, `TrieKey::PendingDataCount`, and `TrieKey::PostponedReceiptId` entries scoped to the account being deleted (mirroring the existing access-key/contract-data iteration pattern), before or as part of account removal. Alternatively/additionally, bind promise authorization to something more durable than the bare `AccountId` string — e.g., reject delivering a postponed/pending action receipt whose receiver account was deleted and recreated in the interim, or fail `DeleteAccount` while pending postponed receipts exist for that receiver.

### Proof of Concept

1. Create account `A` and deploy a contract capable of `promise_create` + `promise_then` targeting itself with a pending data dependency, where the callback action list includes `AddKey(FullAccess, attacker_key)`.

/// Removes account, code and all access keys and gas keys associated to it.
pub fn remove_account(
    state_update: &mut TrieUpdate,
    account_id: &AccountId,
) -> Result<RemoveAccountResult, StorageError> {
    state_update.remove(TrieKey::Account { account_id: account_id.clone() });
    state_update.remove(TrieKey::ContractCode { account_id: account_id.clone() });

    let mut gas_key_nonce_count: usize = 0;
    let mut gas_key_nonce_total_key_bytes: usize = 0;

    // Removing access keys and gas key nonces
    let lock = state_update.trie().lock_for_iter();
    let mut keys_to_remove: Vec<TrieKey> = Vec::new();
    for raw_key in state_update
        .locked_iter(&trie_key_parsers::get_raw_prefix_for_access_keys(account_id), &lock)?
    {
        let raw_key = raw_key?;
        let key_handle = trie_key_parsers::parse_key_handle_from_access_key_key(
            &raw_key, account_id,
        )
        .map_err(|_e| {
            StorageError::StorageInconsistentState(
                "Can't parse key handle from raw key for AccessKey".to_string(),
            )
        })?;
        let nonce_index =
            trie_key_parsers::parse_nonce_index_from_gas_key_key(&raw_key, account_id, &key_handle)
                .map_err(|_e| {
                    StorageError::StorageInconsistentState(
                        "Can't parse nonce index from raw key for AccessKey".to_string(),
                    )
                })?;
        if let Some(index) = nonce_index {
            gas_key_nonce_count += 1;
            gas_key_nonce_total_key_bytes += raw_key.len();
            keys_to_remove.push(TrieKey::gas_key_nonce(
                account_id.clone(),
                key_handle.clone(),
                index,
            ));
        } else {
            keys_to_remove.push(TrieKey::access_key(account_id.clone(), key_handle.clone()));
        }
    }
    drop(lock);

    for trie_key in keys_to_remove {
        state_update.remove(trie_key);
    }

    // Removing contract data
    let lock = state_update.trie().lock_for_iter();
    let data_keys = state_update
        .locked_iter(&trie_key_parsers::get_raw_prefix_for_contract_data(account_id, &[]), &lock)?
        .map(|raw_key| {
            trie_key_parsers::parse_data_key_from_contract_data_key(&raw_key?, account_id)
                .map_err(|_e| {
                    StorageError::StorageInconsistentState(
                        "Can't parse data key from raw key for ContractData".to_string(),
                    )
                })
                .map(Vec::from)
        })
        .collect::<Result<Vec<_>, _>>()?;
    drop(lock);

    for key in data_keys {
        state_update.remove(TrieKey::ContractData { account_id: account_id.clone(), key });
    }
    Ok(RemoveAccountResult { gas_key_nonce_count, gas_key_nonce_total_key_bytes })
}

pub(crate) fn action_delete_account(
    state_update: &mut TrieUpdate,
    account: &mut Option<Account>,
    actor_id: &mut AccountId,
    receipt: &Receipt,
    result: &mut ActionResult,
    account_id: &AccountId,
    delete_account: &DeleteAccountAction,
    config: &RuntimeConfig,
    current_protocol_version: ProtocolVersion,
) -> Result<(), StorageError> {
    let account_ref = account.as_ref().unwrap();
    let account_storage_usage = if ProtocolFeature::FixDeleteAccountGlobalContractStorageUsage
        .enabled(current_protocol_version)
    {
        let contract_storage = get_contract_storage_usage(state_update, account_id, account_ref)?;
        account_ref.storage_usage().saturating_sub(contract_storage)
    } else {
        // Legacy behavior: only subtracts local contract code, misses the
        // global contract identifier overhead.
        let account_storage_usage = account_ref.storage_usage();
        let code_len = get_code_len_or_default(
            state_update,
            account_id.clone(),
            account_ref.local_contract_hash().unwrap_or_default(),
        )?;
        debug_assert!(
            code_len == 0 || account_storage_usage > code_len,
            "account storage usage should be larger than code size. storage usage: {}, code size: {}",
            account_storage_usage,
            code_len
        );
        account_storage_usage.saturating_sub(code_len)
    };
    if account_storage_usage > Account::MAX_ACCOUNT_DELETION_STORAGE_USAGE {
        result.result =
            Err(ActionErrorKind::DeleteAccountWithLargeState { account_id: account_id.clone() }
                .into());
        return Ok(());
    }
    let gas_key_balance_to_burn = compute_gas_key_balance_sum(state_update, account_id)?;
    if gas_key_balance_to_burn > GasKeyInfo::MAX_BALANCE_TO_BURN {
        result.result = Err(ActionErrorKind::GasKeyBalanceTooHigh {
            account_id: account_id.clone(),
            public_key: None,
            balance: gas_key_balance_to_burn,
        }
        .into());
        return Ok(());
    }
    // We use current amount as a pay out to beneficiary.
    let account_balance = account_ref.amount();
    if account_balance > Balance::ZERO {
        result
            .new_receipts
            .push(Receipt::new_balance_refund(&delete_account.beneficiary_id, account_balance));
    }
    let remove_result = remove_account(state_update, account_id)?;
    result.tokens_burnt =
        result.tokens_burnt.checked_add(gas_key_balance_to_burn).ok_or_else(|| {
            StorageError::StorageInconsistentState("tokens_burnt overflow".to_string())
        })?;
    if remove_result.gas_key_nonce_count > 0 {
        let compute = storage_removes_compute(
            &config.wasm_config.ext_costs,
            remove_result.gas_key_nonce_count,
            remove_result.gas_key_nonce_total_key_bytes,
            AccessKey::NONCE_VALUE_LEN * remove_result.gas_key_nonce_count,
        );
        result.compute_usage = safe_add_compute(result.compute_usage, compute).map_err(|_| {
            StorageError::StorageInconsistentState("compute_usage overflow".to_string())
        })?;
    }
    *actor_id = receipt.predecessor_id().clone();
    *account = None;
    Ok(())
}

pub(crate) fn check_actor_permissions(
    action: &Action,
    account: &Option<Account>,
    actor_id: &AccountId,
    account_id: &AccountId,
) -> Result<(), ActionError> {
    match action {
        Action::DeployContract(_)
        | Action::Stake(_)
        | Action::AddKey(_)
        | Action::DeleteKey(_)
        | Action::DeployGlobalContract(_)
        | Action::UseGlobalContract(_)
        | Action::WithdrawFromGasKey(_) => {
            if actor_id != account_id {
                return Err(ActionErrorKind::ActorNoPermission {
                    account_id: account_id.clone(),
                    actor_id: actor_id.clone(),
                }
                .into());
            }
        }
        Action::DeleteAccount(_) => {
            if actor_id != account_id {
                return Err(ActionErrorKind::ActorNoPermission {
                    account_id: account_id.clone(),
                    actor_id: actor_id.clone(),
                }
                .into());
            }
            let account = account.as_ref().unwrap();
            if !account.locked().is_zero() {
                return Err(ActionErrorKind::DeleteAccountStaking {
                    account_id: account_id.clone(),
                }
                .into());
            }
        }
        Action::CreateAccount(_)
        | Action::FunctionCall(_)
        | Action::Transfer(_)
        | Action::TransferToGasKey(_) => (),
        Action::Delegate(_) | Action::DelegateV2(_) => (),
        Action::DeterministicStateInit(_) => (),
    };
    Ok(())

    /// were already received before and saved in the state.
    /// And if we have all input data, then we can immediately execute the receipt.
    /// If not, then we will postpone this receipt for later.
    fn process_action_receipt(
        &self,
        receipt: &Receipt,
        receipt_sink: &mut ReceiptSink,
        instant_receipts: &mut VecDeque<Receipt>,
        validator_proposals: &mut Vec<ValidatorStake>,
        state_update: &mut TrieUpdate,
        apply_state: &ApplyState,
        epoch_info_provider: &dyn EpochInfoProvider,
        pipeline_manager: &ReceiptPreparationPipeline,
        stats: &mut ChunkApplyStatsV1,
        account_id: &AccountId,
        action_receipt: VersionedActionReceipt<'_>,
        receipt_to_tx: &mut Vec<(CryptoHash, ReceiptToTxInfo)>,
    ) -> Result<Option<ExecutionOutcomeWithId>, RuntimeError> {
        let mut pending_data_count: u32 = 0;
        for data_id in action_receipt.input_data_ids() {
            if !has_received_data(state_update, account_id, *data_id)? {
                pending_data_count += 1;
                // The data for a given data_id is not available, so we save a link to this
                // receipt_id for the pending data_id into the state.
                set(
                    state_update,
                    TrieKey::PostponedReceiptId {
                        receiver_id: account_id.clone(),
                        data_id: *data_id,
                    },
                    receipt.receipt_id(),
                )
            }
        }

        if pending_data_count == 0 {
            // All input data is available. Executing the receipt. It will cleanup
            // input data from the state.
            return self
                .apply_action_receipt(
                    state_update,
                    apply_state,
                    pipeline_manager,
                    receipt,
                    receipt_sink,
                    instant_receipts,
                    validator_proposals,
                    stats,
                    epoch_info_provider,
                    receipt_to_tx,
                )
                .map(Some);
        } else {

            // Save the counter for the number of pending input data items into the state.
