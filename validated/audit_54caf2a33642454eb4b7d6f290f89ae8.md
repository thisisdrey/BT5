## Binding Claimed

The question implicitly claims: `fee_owed(batch, T) == protocol_fee.fee_ceil(|net_negative_delta_T|)` for the whole batch executed via one `execute_intents` call, i.e. fees should be computed on the *aggregate* net negative delta on a token across the batch, not per individual signed `TokenDiff`.

## What the code actually does

`TokenDiff::execute_intent` computes and collects the fee **independently for each `TokenDiff` intent**, based only on that intent's own declared `delta`: [1](#0-0) 

The critical detail is `TokenDiff::token_fee`, which explicitly zeroes the fee for NFTs/MTs/IMTs when the per-intent `amount <= 1`: [2](#0-1) 

`execute_signed_intents` / `execute_signed_intent` in the engine iterate over each `MultiPayload` and each `Intent` inside it and dispatch to `execute_intent` independently, with no batch-level aggregation of deltas for fee purposes — deltas are only aggregated for the balance/invariant check in `Deltas`/`finalize`, not for fee computation: [3](#0-2) [4](#0-3) 

## Evaluating the equality

- Single `TokenDiff` with `delta = -2` on a `Nep245` token: `amount = 2 > 1`, so `token_fee` returns the real `protocol_fee`, and `fee_ceil(2)` is generally non-zero for any non-zero fee rate.
- Two `TokenDiff` intents (in the same or different signed payloads, same batch) each with `delta = -1` on the same `Nep245` token: for each, `amount = 1`, so `token_fee` returns `Pips::ZERO` (per the explicit "do not take fees on NFTs and MTs with `|delta| <= 1`" rule), so `fee_ceil(1) = 0` in each call. `fees_collected.add(token_id, 0)` happens twice, contributing nothing.

Both sides of the equality do **not** match: the batch that nets to `-2` collects strictly less fee (down to zero) than a single `-2` intent, purely because of how the trade was fragmented into intents. This is a real, demonstrable divergence, not a theoretical one — it directly follows from the amount-based per-intent threshold in `token_fee`, which is checked per call, not against any batch-level aggregate.

No existing guard (nonce/signature verification, `MaybeLegacyNonces::commit`, `SaltRegistry::is_valid`, `assert_one_yocto`, `#[pause]`, access-control checks) touches fee computation at all — they only gate authenticity/replay of the signed payload, not the amount used for fee calculation.

### Title
Fee revenue bypassed by fragmenting a `Nep245`/IMT trade into multiple unit-delta `TokenDiff` intents in a single `execute_intents` batch - (File: `contracts/defuse/core/src/intents/token_diff.rs`)

### Summary
`TokenDiff::execute_intent` computes and collects protocol fees per individual signed `TokenDiff` intent, using `TokenDiff::token_fee`, which returns `Pips::ZERO` for `Nep245`/`Nep171`/`Imt` tokens whenever the *single intent's* `|delta| <= 1`. A signer can split a large semi-fungible-token trade (e.g. `delta = -2`) into multiple intents each with `delta = -1`, driving the fee for that entire economic trade to zero, whereas executing it as one intent would incur a non-zero fee.

### Finding Description
The broken binding: `fee_owed(batch, T)` should reflect the batch's real net negative delta on `T`, but instead `fee_owed(batch, T) = Σ_i token_fee(T, |delta_i|, protocol_fee).fee_ceil(|delta_i|)` computed independently per `TokenDiff` intent `i`. Since `token_fee` special-cases `Nep245`/`Nep171`/`Imt` tokens to `Pips::ZERO` whenever a single intent's `amount <= 1` (`contracts/defuse/core/src/intents/token_diff.rs:206-217`), an attacker who owns ≥2 units of a `Nep245` token can sign two separate `TokenDiff` intents (in one or two `MultiPayload`s, submitted together in one `execute_intents` call) each moving `delta = -1` of that token, instead of one intent moving `delta = -2`. Each call to `execute_intent` (`contracts/defuse/core/src/intents/token_diff.rs:41-104`) independently calls `internal_apply_deltas` and computes `fee_ceil` on its own `amount = 1`, yielding `fee = 0` both times, versus a non-zero fee if issued as a single `delta = -2` intent. `execute_signed_intents`/`execute_signed_intent` (`contracts/defuse/core/src/engine/mod.rs:32-83`) provide no aggregation of deltas across intents for fee purposes — only nonce/signature/deadline checks are done there, none of which affect fee computation.

### Impact Explanation
The `fee_collector` receives strictly less (down to zero) protocol fee than it would for an economically equivalent single-intent trade of the same net size, for any `Nep245`/`Nep171`/`Imt` token whose transferred quantity is fragmented into unit (`|delta|<=1`) chunks. This matches the Critical category "protocol fees bypassed or over-collected." The blast radius is scoped to semi-fungible/NFT-style tokens (`Nep245`/`Imt`; `Nep171` NFTs are inherently unit-sized so not meaningfully affected) and is repeatable by any signer, for any quantity, by splitting into as many unit-delta intents as needed — an attacker moving `N` units pays zero fee instead of `fee_ceil(N)` by submitting `N` intents of `delta=-1` each.

### Likelihood Explanation
Preconditions are minimal: the attacker needs no special role, just their own signing key and a balance of `N >= 2` units of a `Nep245`/`Imt` token they wish to move. Cost is only the extra intents/signatures within a single `execute_intents` transaction (gas cost), which is straightforward and fully within the attacker's control. This is trivially and repeatably exploitable by any unprivileged signer against any `Nep245`/`Imt` token traded through `TokenDiff`.

### Recommendation
Compute the fee-eligibility threshold (`|delta| <= 1` exemption for `Nep245`/`Imt`) against the aggregated net delta per token across the whole batch (all `TokenDiff` intents executed within one `execute_signed_intents` call for the same signer/token), not per individual intent — e.g., accumulate per-token net deltas in the `Engine`/`Deltas` layer before applying `token_fee`, or require that the per-unit fee exemption only apply when the token's underlying `TokenIdType` truly represents a single indivisible unit (i.e., disallow amount-based fragmentation of `Nep245`/`Imt` for fee purposes).

### Proof of Concept
`cargo test` in `contracts/defuse/core` (or `tests/src/tests/defuse/intents/token_diff.rs` using `near-workspaces` sandbox):
1. Set a non-zero `protocol_fee` (e.g. `Pips::ONE_PERCENT`).
2. Fund a signer with `>=2` units of a `Nep245` token.
3. Case A: sign and execute one `TokenDiff` intent with `diff = {nep245_token: -2, some_out_token: +X}` via `execute_intents`; read `fees_collected` from the emitted `TokenDiffEvent` (or the fee_collector's resulting balance for `nep245_token`).
4. Case B: sign and execute two `TokenDiff` intents (separate nonces/payloads) each with `diff = {nep245_token: -1, some_out_token: +X/2}`, batched together in a single `execute_intents([...])` call; read the resulting fee_collector balance for `nep245_token`.
5. Assert `fee_collector_balance_case_A(nep245_token) > 0` and `fee_collector_balance_case_B(nep245_token) == 0`, despite both cases moving the same net `-2` of `nep245_token` for the signer.

    fn execute_signed_intent(&mut self, signed: MultiPayload) -> Result<()> {
        // verify signed payload and get public key
        let public_key = signed.verify().ok_or(DefuseError::InvalidSignature)?;

        // calculate intent hash
        let hash = signed.hash();

        // extract NEP-413 payload
        let DefusePayload::<DefuseIntents> {
            signer_id,
            verifying_contract,
            deadline,
            nonce,
            message: intents,
        } = signed.extract_defuse_payload()?;

        // check recipient
        if verifying_contract != *self.state.verifying_contract() {
            return Err(DefuseError::WrongVerifyingContract);
        }

        self.inspector.on_deadline(deadline);

        // make sure message is still valid
        if deadline < Timestamp::now() {
            return Err(DefuseError::DeadlineExpired);
        }

        // make sure the account has this public key
        if !self.state.has_public_key(&signer_id, &public_key) {
            return Err(DefuseError::PublicKeyNotExist(signer_id, public_key));
        }

        // commit nonce
        self.verify_intent_nonce(nonce, deadline)?;
        self.state.commit_nonce(signer_id.clone(), nonce)?;

        intents.execute_intent(&signer_id, self, hash)?;
        self.inspector.on_intent_executed(&signer_id, hash, nonce);

        Ok(())
    }
