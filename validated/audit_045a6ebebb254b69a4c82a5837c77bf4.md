### Title
Unbounded heap over-read while parsing ZIP central-directory entries - (File: `third_party/ijar/zip.cc`)

### Summary
`InputZipFile::ProcessCentralDirEntry` in Bazel's own ZIP reader (used by the `ijar`/`zipper`/singlejar toolchain, and by `repository_ctx.extract`/`download_and_extract` code paths that go through the ijar-based zip decompressor) parses length-prefixed fields (`file_name_length`, `extra_field_length`, ZIP64 extra-field `data_size`) directly out of a memory-mapped input file **without any `EnsureRemaining`-style bounds check**, unlike its sibling `ProcessLocalFileEntry`, which does call `EnsureRemaining` before every variable-length read. [1](#0-0) 

### Finding Description
`ProcessCentralDirEntry` reads the signature, sizes, filename length, extra-field length, comment length, attribute and offset fields directly via `get_u4le`/`get_u2le` with no check that these bytes are still inside the mapped file (contrast with `ProcessLocalFileEntry`, which guards every field with `EnsureRemaining`). [2](#0-1) 

Worse, the loop that walks ZIP64 "extra field" records advances `extra_p` by an attacker-controlled `data_size` read from the file itself, with the loop condition `while (extra_p != p)`. If `data_size` is crafted so that `extra_p` steps past `p`, the pointer never becomes equal to `p` again and the loop continues reading `header_id`/`data_size` from ever-increasing (out-of-mapping) addresses, an unbounded out-of-bounds read. [3](#0-2) 

The comment above the function explicitly states the (false) assumption this relies on: "the central directory is always followed by another data structure that has a signature, so parsing it this way is safe" — this assumption only holds for well-formed archives, not attacker-crafted ones. [4](#0-3) 

Because `input_file_` is backed by an `mmap`'d region [5](#0-4) , reading past its bounds is a real invalid-memory-access condition (segfault or leaked adjacent heap/page bytes into `filename`/output), directly analogous to the sentencepiece CWE-119 issue: a length-prefixed record parser trusting attacker-supplied lengths without validating them against the buffer size.

### Impact Explanation
If reached with attacker-controlled bytes, this can crash the Bazel/ijar process (denial of service) or, depending on memory layout, copy adjacent heap bytes into the `filename` buffer or into the generated output artifact (an information-disclosure primitive). It is a genuine memory-safety bug in Bazel's own native ZIP-parsing code.

### Recommendation
If a Devin agent with full repo/tool access confirms `zip.cc`'s `ProcessCentralDirEntry` is reachable from `http_archive`/`download_and_extract`/`repository_ctx.extract` on unpinned or attacker-controlled ZIP content, the fix is to add `EnsureRemaining` bounds checks before every central-directory field read (mirroring `ProcessLocalFileEntry`), and to bound the ZIP64 extra-field walk so `data_size` can never advance `extra_p` past `p` or past the mapped file's end.

// Of course, in the latter case, the size output variables are not changed.
// Note that the central directory is always followed by another data structure

                                          u8 *uncompressed_size, char *filename,
                                          size_t filename_size, u4 *attr,
                                          u8 *offset) {

  if (signature != CENTRAL_FILE_HEADER_SIGNATURE) {
    if (signature != DIGITAL_SIGNATURE && signature != EOCD_SIGNATURE &&
        signature != ZIP64_EOCD_SIGNATURE) {
      error("invalid central file header signature: 0x%x\n", signature);
    }
    return false;
  }

  p += 16;  // skip to 'compressed size' field
  *compressed_size = get_u4le(p);
  *uncompressed_size = get_u4le(p);
  u2 file_name_length = get_u2le(p);
  u2 extra_field_length = get_u2le(p);
  u2 file_comment_length = get_u2le(p);
  p += 4;  // skip to external file attributes field
  *attr = get_u4le(p);
  *offset = get_u4le(p);
  {
    size_t len = (file_name_length < filename_size)
      ? file_name_length
      : (filename_size - 1);
    memcpy(reinterpret_cast<void*>(filename), p, len);
    filename[len] = 0;
  }
  p += file_name_length;
  const u1 *extra_p = p;
  p += extra_field_length;

    const u2 header_id = get_u2le(extra_p);
    const u2 data_size = get_u2le(extra_p);
    const u1 *extra = extra_p;
    extra_p += data_size;
    if (header_id == ZIP64_EXTRA_FIELD_TAG) {
      if (*uncompressed_size == U4_MAX) {
        *uncompressed_size = get_u8le(extra);
      }
      if (*compressed_size == U4_MAX) {
        *compressed_size = get_u8le(extra);
      }
      if (*offset == U4_MAX) {
        *offset = get_u8le(extra);
      }
    }
  }
