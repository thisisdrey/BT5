## Analog Found: Unauthenticated `RecvError` message allows unrestricted tunnel teardown

The governance bug is "any party can force-cancel a resource regardless of state, with only a weak identity check that can be trivially satisfied." The strongest reachable analog in Nebula is the handling of the unencrypted `RecvError` control packet, which lets an attacker who can spoof a UDP source address force-teardown ("cancel") an already-Established, fully authenticated tunnel — with no cryptographic authentication of the message itself and no restriction based on tunnel state.

### Root cause

`RecvError` packets are dispatched in the "Unencrypted packets" branch of `readOutsidePackets`, before any AEAD decryption or handshake state is consulted: [1](#0-0) 

They are handled by `handleRecvError`, whose only "authentication" is comparing the claimed source `netip.AddrPort` against the hostinfo's last known remote address — a value that is neither secret nor cryptographically bound to the packet: [2](#0-1) 

Key points:
- `h.RemoteIndex` is looked up via `f.hostMap.QueryReverseIndex(h.RemoteIndex)` [3](#0-2) . This index is the `localIndexId` that this host assigned during the handshake and which is transmitted in plaintext in the header of every packet it sends to the peer, so it is trivially observable by anyone who can see any traffic on the tunnel (or who can brute force the 32-bit space).
- The only gate against forgery is `hr.IsValid() && hr != addr` [4](#0-3) , i.e., a UDP source-address match. UDP source addresses are attacker-controlled/spoofable and are not authenticated by any MAC, nonce, or handshake state — unlike every other packet type, which must pass `header.Version`, `IsValidSubType`, and AEAD decryption via `ConnectionState.Decrypt`/`VerifyRelay` before being actioned (see the same file, lines 43–132: `outside.go:43-132`).
- Once the address "matches," the tunnel is torn down unconditionally via `f.closeTunnel(hostinfo)` and also removed from the pending handshake manager — there is no check on the tunnel's current state (`Established`, `Disestablished`, mid-rehandshake, etc.), directly analogous to `Governance::cancel` allowing cancellation in any non-`Executed` state with only a weak proposer/threshold check that is easy to satisfy.

### Impact

An attacker who can spoof a UDP packet with the victim's peer address as the source (classic off-path UDP spoofing, or any on-path attacker) and who has observed or guessed the 32-bit `RemoteIndex` can force any Nebula node to tear down an established, mutually authenticated tunnel at will — a remote, unauthenticated denial-of-service / connection-state-poisoning primitive that requires no valid certificate and no participation in the Noise handshake at all.

### Recommendation

Do not let an unauthenticated, unencrypted message type unilaterally destroy authenticated tunnel state. At minimum:
- Require `RecvError` to be authenticated (e.g., HMAC/AEAD-protected using the tunnel's derived key, or accepted only when it can be tied to a legitimate handshake artifact) rather than relying solely on a spoofable source-address comparison.
- Rate-limit / require corroborating evidence (e.g., a subsequent failed retransmit) before tearing down an `Established` tunnel in response to a `RecvError`. [2](#0-1) [1](#0-0)

```go
func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
```
