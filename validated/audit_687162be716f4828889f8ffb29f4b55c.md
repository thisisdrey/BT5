### Title
Object-directory quarantine ownership check bypassed for any path ending in `quarantine`/`tmp_objdir-*` - ([File: internal/git/localrepo/paths.go])

### Summary
`Repo.ObjectDirectoryPath` is supposed to guarantee that a client-supplied `GitObjectDirectory` either lives inside the repository itself or is a temporary quarantine directory that has been proven to belong to *that* repository (via a per-repository hash prefix). A heuristic shortcut based purely on the last one or two path components ("is this named `quarantine`?") skips that ownership proof entirely, so any storage-internal directory whose name happens to match the heuristic is accepted without verifying it belongs to the calling repository.

### Finding Description
`ObjectDirectoryPath` first restricts the joined path to the storage root with `storage.ValidateRelativePath(storagePath, ...)` [1](#0-0)  — this only prevents escaping the storage root, not cross-repository access.

It then computes `isTransactionQuarantineDir` purely from the base name of the resulting relative path (`quarantine`, or a parent named `quarantine` with a `tmp_objdir` prefix) and, when true, skips the block that verifies the path either resides under the repository itself or under a quarantine directory whose name is derived from `storage.QuarantineDirectoryPrefix(repo)` (a SHA1 of the repo's own relative path): [2](#0-1) 

The `QuarantineDirectoryPrefix` doc comment states its purpose explicitly: "This allows us to verify that a given quarantine object directory indeed belongs to the repository at hand." [3](#0-2)  The `isTransactionQuarantineDir` branch bypasses exactly this ownership proof whenever the path's tail matches the naming heuristic, regardless of which repository, partition, or transaction actually owns that directory.

`GitObjectDirectory` is a field on the `Repository` message that is part of ordinary RPC requests (used by Rails/hooks looping back into Gitaly during access checks), so it is attacker-influenceable input reaching this code path on essentially every accessor RPC that resolves an object directory.

### Impact Explanation
If an attacker can predict or otherwise obtain the relative path of another live transaction's/partition's temporary quarantine directory elsewhere under the same storage root, they can set `GitObjectDirectory` to that path. Because the heuristic bypasses the identity check, `ObjectDirectoryPath` will happily resolve and later be used to configure `GIT_OBJECT_DIRECTORY`/`GIT_ALTERNATE_OBJECT_DIRECTORIES` for git subprocesses, exposing objects from another repository's or another user's in-flight (possibly not-yet-authorized, or rejected) push to the requester — a cross-repository object access/disclosure of not-yet-committed data.

### Likelihood Explanation
Exploitability depends on whether the concrete quarantine/transaction directory names are guessable or enumerable in the storage layout (the search into `internal/gitaly/storage/storagemgr/partition_manager.go` and `transaction_manager.go` to determine exact directory naming/predictability was not completed before this analysis ended). The root-cause bypass in `paths.go` is confirmed by code, but I could not fully verify how predictable the target directory names are, so likelihood is uncertain and should be validated by tracing `PartitionsDir`/`tempdir.NewWithPrefix` naming conventions.

### Recommendation
Remove the `isTransactionQuarantineDir` shortcut, or restrict it so it only exempts paths that are also confirmed to be children of the repository's own partition/transaction temp directory (not merely matching a name heuristic anywhere in the storage tree). The exemption should still perform an ownership/ prefix check analogous to `QuarantineDirectoryPrefix`, scoped to the correct transaction rather than to a fixed literal name.

### Proof of Concept
Not fully constructible without confirming the exact on-disk naming/predictability of transaction quarantine directories (see Likelihood Explanation); the code-level bypass itself is demonstrated by the branch at [4](#0-3) , which unconditionally skips the ownership-prefix check whenever `baseDir == "quarantine"` or the `tmp_objdir` heuristic matches.

// QuarantineDirectoryPrefix returns a prefix for use in the temporary directory. The prefix is
// based on the relative repository path and will stay stable for any given repository. This allows
// us to verify that a given quarantine object directory indeed belongs to the repository at hand.
// Ideally, this function would directly be located in the quarantine module, but this is not
// possible due to cyclic dependencies.
func QuarantineDirectoryPrefix(repo Repository) string {
	hash := [20]byte{}
	if repo != nil {
		hash = sha1.Sum([]byte(repo.GetRelativePath()))
	}
	return fmt.Sprintf("quarantine-%x-", hash[:8])
