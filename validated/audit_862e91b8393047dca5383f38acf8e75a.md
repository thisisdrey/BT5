## Analog Vulnerability Found

### Title
Bank interest rate/config changes are applied retroactively over unaccrued time, causing depositors to permanently lose already-earned interest - (File: `programs/marginfi/src/instructions/marginfi_group/configure_bank.rs`, `programs/marginfi/src/instructions/marginfi_group/configure_bank_lite.rs`)

### Summary
The external report describes a bug where `GaugeController.emergencyShutdown()` changes a gauge's state (`isActive = false`) without first calling the revenue-distribution function that would settle/credit its already-accumulated rewards, so those rewards are permanently lost. The marginfi-v2 analog is in the bank configuration path: `lending_pool_configure_bank` and `lending_pool_configure_bank_interest_only` mutate `bank.config.interest_rate_config` (and other rate-affecting fields) directly via `bank.configure()` / `bank.config.interest_rate_config.update()` **without first calling `bank.accrue_interest()`**. Because `accrue_interest` always computes interest for the *entire* elapsed `time_delta` using whatever `interest_rate_config` is stored **at the time it finally runs**, any config change made between the last accrual and the next user interaction is applied retroactively over the full unaccrued period, permanently erasing (or distorting) interest that depositors had already earned under the old rate — the same "accrued value is lost because settlement is skipped before a state change" root cause as the reported gauge bug.

### Finding Description
`Bank::accrue_interest` computes `time_delta` as the seconds since `self.last_update` and then builds an `ir_calc` from `self.config.interest_rate_config` as it exists *right now*, applying that rate over the *entire* `time_delta`: [1](#0-0) [2](#0-1) 

Other instructions that touch a bank's balances (`lending_account_repay`, `lending_account_borrow`, `lending_pool_accrue_bank_interest`, `lending_pool_emissions_deposit`) all correctly call `bank.accrue_interest(...)` *before* mutating anything else, so the old rate is settled first: [3](#0-2) [4](#0-3) [5](#0-4) 

However, `lending_pool_configure_bank` (the admin's general bank-configuration entrypoint) calls `bank.configure(&bank_config)` directly, with no preceding `accrue_interest` call: [6](#0-5) 

And `bank.configure()` overwrites `interest_rate_config` and other risk parameters in place: [7](#0-6) 

Likewise, `lending_pool_configure_bank_interest_only` (callable by `delegate_curve_admin`) updates `interest_rate_config` directly with no prior accrual: [8](#0-7) 

Since `last_update` is only advanced inside `accrue_interest` (and `update_bank_cache`), any interest that accrued under the *old* rate config between the last accrual and the config change is never settled at the old rate. It is silently absorbed into the next `accrue_interest` call and computed using the *new* config over the full elapsed `time_delta` — exactly mirroring the gauge report's pattern of "change state → then settle → settlement uses the state as it now exists, not as it existed when the value accrued."

### Impact Explanation
If the interest rate curve is lowered (e.g., a risk parameter reduction, a benign rebalancing, or an admin key compromise) at a time when a bank has unaccrued interest built up under a higher rate, depositors permanently lose that portion of interest — it is retroactively recomputed at the lower rate for the whole idle period. Conversely, if the rate is raised, borrowers are retroactively charged the higher rate for time when the lower rate should have applied, i.e. an unauthorized increase in their liability. Both directions are concrete, unauthorized reallocations of value between depositors/borrowers and the protocol/other counterparties, with no user action required — a `core accounting` defect within the bank's central `asset_share_value`/`liability_share_value` bookkeeping.

### Likelihood Explanation
Interest accrues "when any transaction that changes funds occurs" and is documented to go stale otherwise: "banks without much activity may have stale numbers until someone interacts with them" (per project docs). This means low-activity banks (which are common — e.g. new banks, or in the interim between busy periods) routinely carry unaccrued interest for meaningful stretches. Any routine `lending_pool_configure_bank` or `lending_pool_configure_bank_interest_only` call during such a window — a normal, expected admin/`delegate_curve_admin` operation, not requiring anything exotic — triggers the retroactive-rate bug. [9](#0-8) 

### Recommendation
Call `bank.accrue_interest(clock.unix_timestamp, &group, ...)` and `bank.update_bank_cache(&group)` at the start of `lending_pool_configure_bank` and `lending_pool_configure_bank_interest_only` (and any other admin instruction that mutates `interest_rate_config`, `asset_weight_*`, `liability_weight_*`, or `operational_state`), before applying the new config, so any interest accrued under the old parameters is settled into `asset_share_value`/`liability_share_value` prior to the parameter change taking effect.

### Proof of Concept
1. Bank has active deposits (lender L) and borrows (borrower B), accruing interest at rate `R1` under `interest_rate_config` C1.
2. No one interacts with the bank for a period `T` (a realistic idle window per the docs) — `last_update` stays fixed, interest is unaccrued.
3. `delegate_curve_admin` calls `lending_pool_configure_bank_interest_only` to update `interest_rate_config` to C2 with a much lower `lending_rate_apr` (a routine, non-malicious risk-parameter update): [8](#0-7)  — this returns immediately without ever calling `accrue_interest`.
4. Any subsequent user action (e.g. L withdraws, or the permissionless `lending_pool_accrue_bank_interest` is called) invokes `bank.accrue_interest`, which computes `time_delta = now - last_update` (covering the full idle period `T`, including the time under C1) and applies it using the *current* config C2: [10](#0-9) .
5. L's `asset_share_value` increase for period `T` reflects C2's lower rate instead of C1's higher rate — the interest L had already earned under C1 for that period is permanently lost, with no instruction path to recover it.

    fn accrue_interest(
        &mut self,
        current_timestamp: i64,
        group: &MarginfiGroup,
        #[cfg(not(feature = "client"))] bank: Pubkey,
    ) -> MarginfiResult<()> {
        #[cfg(all(not(feature = "client"), feature = "debug"))]
        sol_log_compute_units();

        let time_delta: u64 = (current_timestamp - self.last_update).try_into().unwrap();
        if time_delta == 0 {
            return Ok(());
        }

        let total_assets = self.get_asset_amount(self.total_asset_shares.into())?;
        let total_liabilities = self.get_liability_amount(self.total_liability_shares.into())?;

        self.last_update = current_timestamp;

        if (total_assets == I80F48::ZERO) || (total_liabilities == I80F48::ZERO) {
            #[cfg(not(feature = "client"))]
            emit!(LendingPoolBankAccrueInterestEvent {
                header: GroupEventHeader {
                    marginfi_group: self.group,
                    signer: None
                },
                bank,
                mint: self.mint,
                delta: time_delta,
                fees_collected: 0.,
                insurance_collected: 0.,
            });

            return Ok(());
        }
        let ir_calc = self
            .config
            .interest_rate_config
            .create_interest_rate_calculator(group);

        let InterestRateStateChanges {
            new_asset_share_value: asset_share_value,
            new_liability_share_value: liability_share_value,
            insurance_fees_collected,
            group_fees_collected,
            protocol_fees_collected,
        } = calc_interest_rate_accrual_state_changes(
            time_delta,
            total_assets,
            total_liabilities,
            &ir_calc,
            self.asset_share_value.into(),
            self.liability_share_value.into(),
        )?;

pub fn lending_pool_configure_bank(
    ctx: Context<LendingPoolConfigureBank>,
    bank_config: BankConfigOpt,
) -> MarginfiResult {
    let mut bank = ctx.accounts.bank.load_mut()?;

    // If settings are frozen, you can only update the deposit and borrow limits, everything else is ignored.
    if bank.get_flag(FREEZE_SETTINGS) {
        bank.configure_unfrozen_fields_only(&bank_config)?;

        msg!("WARN: Only deposit+borrow limits updated. Other settings IGNORED for frozen banks!");

        emit!(LendingPoolBankConfigureFrozenEvent {
            header: GroupEventHeader {
                marginfi_group: ctx.accounts.group.key(),
                signer: Some(*ctx.accounts.admin.key)
            },
            bank: ctx.accounts.bank.key(),
            mint: bank.mint,
            deposit_limit: bank.config.deposit_limit,
            borrow_limit: bank.config.borrow_limit,
        });
    } else {
        // Settings are not frozen, everything updates
        bank.configure(&bank_config)?;
        msg!("Bank configured!");

        let group = ctx.accounts.group.load()?;
        bank.emode.validate_entries_with_liability_weights(
            &bank.config,
            group.emode_max_init_leverage,
            group.emode_max_maint_leverage,
        )?;

        emit!(LendingPoolBankConfigureEvent {
            header: GroupEventHeader {
                marginfi_group: ctx.accounts.group.key(),
                signer: Some(*ctx.accounts.admin.key)
            },
            bank: ctx.accounts.bank.key(),
            mint: bank.mint,
            config: bank_config,
        });
    }

    Ok(())
}

pub fn lending_pool_configure_bank_interest_only(
    ctx: Context<LendingPoolConfigureBankInterestOnly>,
    interest_rate_config: InterestRateConfigOpt,
) -> MarginfiResult {
    let mut bank = ctx.accounts.bank.load_mut()?;
    msg!(
        "Configuring bank: {:?} mint: {:?}",
        ctx.accounts.bank.key(),
        bank.mint
    );

    // If settings are frozen, interest rates can't update.
    if bank.get_flag(FREEZE_SETTINGS) {
        msg!("WARN: Bank settings frozen, did nothing.");
    } else {
        bank.config
            .interest_rate_config
            .update(&interest_rate_config);
        bank.config.interest_rate_config.validate()?;
        msg!("Bank configured!");
    }

    Ok(())
}
