### Title
Unauthenticated `RecvError` packets allow off-path spoofed teardown of a victim's tunnel, permanently blocking reconnection at near-zero attacker cost - (File: outside.go)

### Summary
Nebula's `RecvError` control message is processed entirely outside the AEAD/authentication path: it is handled in the "Unencrypted packets" branch of `readOutsidePackets`, before any certificate, handshake, or per-packet decryption/authentication is performed. The only defense against forgery is a plaintext source-address comparison against the hostinfo's currently known remote, which is not a cryptographic check and is trivially defeated by UDP source-address spoofing. This lets an attacker who possesses no CA-signed certificate and is not a party to the tunnel forcibly tear down another user's live, authenticated tunnel and delete its pending-handshake state, repeatable indefinitely for the cost of one crafted 12-byte UDP packet per attempt.

### Finding Description
`readOutsidePackets` dispatches `header.RecvError` packets to `handleRecvError` immediately after header parsing, with no involvement of `ConnectionState`, no AEAD tag, and no certificate check: [1](#0-0) 

`handleRecvError` then looks up the target purely from the plaintext `h.RemoteIndex` field (which travels in cleartext in every packet header of an established tunnel, and is thus observable by anyone who can see any packet on that flow, or who can brute-force/guess it), and its only anti-spoofing measure is comparing the UDP *source address* of the incoming packet to the address currently on file for that hostinfo: [2](#0-1) 

If the attacker crafts a UDP packet with a spoofed source `netip.AddrPort` equal to the victim peer's real remote address (a classic, well-known weakness of UDP, requiring no cryptographic material or CA-signed certificate at all) and the correct `RemoteIndex`, this check passes and the code unconditionally calls:

```go
f.closeTunnel(hostinfo)
f.handshakeManager.DeleteHostInfo(hostinfo)
```

`closeTunnel` removes the hostinfo from the main hostmap and clears lighthouse state if it was the last tunnel for that peer: [3](#0-2) 

This mirrors the root cause pattern in the reference report: a state-mutating action that is supposed to require the actual party's consent/ownership (here: only the genuine remote peer should be able to trigger teardown of its own tunnel) is instead gated by a check that can be satisfied by *anyone* impersonating the required identity at negligible cost (spoofed source address vs. the report's `isOToken`-authorized indirection that let anyone specify an arbitrary "account"). In both cases the actual authorization boundary (true ownership/identity of the acting party) is not cryptographically enforced on the state-mutating path, even though a stricter, cert-authenticated path exists elsewhere in the same system for legitimate operations.

### Impact Explanation
An attacker with no CA-signed certificate, who can spoof UDP source addresses (routinely possible on networks without egress/ingress filtering, and is a documented UDP-protocol weakness independent of any Nebula-specific control) and who can observe or guess a 32-bit `RemoteIndex`, can force teardown of an arbitrary victim's active, fully-authenticated tunnel. Because this requires no handshake and no valid certificate, the attacker can repeat it indefinitely against a target as soon as reconnection completes (each reconnection assigns a new index, but the attacker can re-observe it from any subsequent packet on the wire, or continue to brute force), producing a sustained denial of service that keeps the victim's tunnel perpetually torn down — the mesh-networking analog of "permanently locking" a victim's state at near-zero cost to the attacker. The `f.l.Info("Someone spoofing recv_errors?", ...)` log line shows the developers were aware spoofing was a risk here, but the mitigation (address equality) is not cryptographic and does not stop UDP source spoofing.

### Likelihood Explanation
Likelihood is bounded by two prerequisites: (1) ability to spoof the source UDP address of the genuine remote peer, which is feasible on many network paths and does not require holding a CA-signed cert or being a mesh member; and (2) knowledge of the 32-bit `RemoteIndex`, which is sent in cleartext in every packet of the flow and is therefore recoverable by anyone who can observe a single packet of the target flow (on-path attacker, or a former peer who retains old traffic captures), reducing this to a moderate-difficulty, high-impact remote DoS rather than a purely theoretical one. `f.acceptRecvErrorConfig` defaults to `recvErrorAlways`, so the check is enabled by default unless an operator has explicitly restricted it via `listen.accept_recv_error`.

### Recommendation
Do not allow an unauthenticated, cleartext control packet to tear down an established tunnel based solely on a spoofable source-address comparison. Options:
- Require `RecvError` handling to additionally validate a value derived from the current session's AEAD state (e.g., require the sender to prove possession of the peer's decryption key, or embed an authenticated tag over the error using the existing tunnel keys) before acting on it.
- At minimum, rate-limit and require multiple consistent observations, or bind acceptance to only endpoints already validated as roamed-to via the existing HMAC/lighthouse-verified roaming path, rather than a raw plaintext address match.
- Consider deprecating unauthenticated `RecvError`-triggered teardown entirely in favor of the connection manager's own liveness/timeout detection (`tunnels.drop_inactive`), which already exists and is authenticated.

### Proof of Concept
1. Establish (or observe) a live Nebula tunnel between `Victim-A` and `Victim-B`; capture one packet on the wire to learn `RemoteIndex` (visible in the plaintext header of every packet) and `Victim-B`'s real UDP `AddrPort`.
2. As `Attacker` (no CA-issued certificate, not a member of the mesh), craft a 12-byte header-only UDP datagram:
```go
b := header.Encode(make([]byte, header.Len), header.Version, header.RecvError, 0, capturedRemoteIndex, 0)
```
3. Send `b` to `Victim-A`'s UDP listener with the source address spoofed to `Victim-B`'s real `AddrPort` (e.g. via a raw socket on a network without BCP38 egress filtering, or via a MITM position on the path).
4. On `Victim-A`, `handleRecvError` finds the hostinfo via `QueryReverseIndex(capturedRemoteIndex)`, the spoofed source address matches `hostinfo.GetRemote()`, and `f.closeTunnel(hostinfo)` plus `f.handshakeManager.DeleteHostInfo(hostinfo)` execute, tearing down the tunnel without either legitimate party requesting it.
5. Repeat whenever `Victim-A` re-establishes a tunnel (re-observing the new index from cleartext headers) to keep the tunnel perpetually disrupted. [4](#0-3)

// closeTunnel closes a tunnel locally, it does not send a closeTunnel packet to the remote
func (f *Interface) closeTunnel(hostInfo *HostInfo) {
	final := f.hostMap.DeleteHostInfo(hostInfo)
	if final {
		// We no longer have any tunnels with this vpn addr, clear learned lighthouse state to lower memory usage
		f.lightHouse.DeleteVpnAddrs(hostInfo.vpnAddrs)
	}
}

func (f *Interface) sendRecvError(endpoint netip.AddrPort, index uint32) {
	f.messageMetrics.Tx(header.RecvError, 0, 1)

	b := header.Encode(make([]byte, header.Len), header.Version, header.RecvError, 0, index, 0)
	_ = f.outside.WriteTo(b, endpoint)
	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error sent",
			"index", index,
			"udpAddr", endpoint,
		)
	}
}

func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
