### Title
Unauthenticated remote shutdown of the stacks-signer event receiver via `/shutdown` HTTP POST - (File: `libsigner/src/events.rs`)

### Summary
The `stacks-signer` binary runs an HTTP server (`SignerEventReceiver`) that is meant to receive events only from its paired `stacks-node`. This listener performs **no authentication** of incoming requests. Any request whose URL path is `/shutdown` immediately sets the receiver's stop signal and terminates the event-receiving thread, regardless of who sent it. Since the sample/documented configuration binds this listener to `0.0.0.0` (all interfaces), any unauthenticated remote party that can reach the configured port can permanently disable the signer's ability to receive further node events with a single HTTP request.

### Finding Description
`SignerEventReceiver::next_event` dispatches on the raw HTTP method/URL of an inbound request with no credential check whatsoever: [1](#0-0) 

Notably the `/shutdown` branch: [2](#0-1) 

sets `event_receiver.stop_signal.store(true, Ordering::SeqCst)` and returns `Err(EventError::Terminated)`. `main_loop()` checks `is_stopped()` at the top of every iteration and also breaks immediately on `EventError::Terminated`: [3](#0-2) 

There is no comparison against any shared secret, HMAC, or `Authorization` header anywhere in this file. Contrast this with the *other* direction of the node/signer channel — the signer authenticates itself to the node's RPC endpoint using an `auth_password`/`AUTHORIZATION` header (`stacks-signer/src/client/stacks_client.rs`), and the node's own RPC (`postblock_proposal.rs`) checks a matching `auth_token`. But the `[connection_options] auth_token` configured on the node side is never attached to the outbound POSTs the node makes to the signer's event endpoint: [4](#0-3) [5](#0-4) 

So the signer's inbound listener has no authentication mechanism at all, and the documented deployment topology explicitly recommends binding it to all interfaces: [6](#0-5) 

This breaks the intended equality "only the paired node may control the signer's event channel" — in reality, any TCP peer that can reach the bound port is treated as the trusted node.

### Impact Explanation
A remote, unprivileged attacker who can reach a signer's event-receiver port needs only to send `POST /shutdown` (or any bytes tinyhttp accepts as an HTTP POST to that path). This immediately and irrecoverably terminates the receiver thread (`main_loop exit`), after which the signer stops receiving `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, and `/new_block` events from its node. The signer effectively goes dark until manually restarted — a remote, unauthenticated denial of service achievable with a single HTTP request, matching the "Critical - remote crash/unauthenticated DoS from few messages" bar.

### Likelihood Explanation
The listener's bind address is operator-configured, and the maintained sample configuration explicitly sets it to `0.0.0.0:30000`, i.e., reachable from any network the host is exposed to. No credentials, keys, or special network position are required — only knowledge/discovery of the port. This is a low-effort, high-confidence attack against any signer deployment following the documented configuration.

### Recommendation
Require and verify a shared secret (e.g., an `Authorization` header matching the node's configured `auth_token`) on every request handled by `SignerEventReceiver::next_event`, and reject unauthenticated requests before acting on control paths like `/shutdown`. At minimum, gate the `/shutdown` handler behind this check, and document/default the listener to bind to `127.0.0.1` unless authentication is enabled.

### Proof of Concept
Against a signer whose `endpoint` is reachable (e.g. `0.0.0.0:30000` per the sample config):
```
curl -X POST http://<signer-host>:30000/shutdown
```
This single unauthenticated request causes `SignerEventReceiver::next_event` to hit the `/shutdown` branch in [7](#0-6) , setting `stop_signal` and returning `EventError::Terminated`, which `main_loop` treats as a termination condition and exits, per [8](#0-7) .

    /// Main loop for the receiver.
    /// Typically, this is started in a separate thread.
    fn main_loop(&mut self) {
        loop {
            if self.is_stopped() {
                info!("Event receiver stopped");
                break;
            }
            let next_event = match self.next_event() {
                Ok(event) => event,
                Err(EventError::UnrecognizedEvent(..)) => {
                    // got an event that we don't care about (not a problem)
                    continue;
                }
                Err(EventError::Terminated) => {
                    // we're done
                    info!("Caught termination signal");
                    break;
                }
                Err(e) => {
                    warn!("Failed to receive next event: {:?}", &e);
                    continue;
                }
            };
            if !self.forward_event(next_event) {
                info!("Failed to forward event");
                break;
            }
        }
        info!("Event receiver main loop exit");
    }

    fn next_event(&mut self) -> Result<SignerEvent<T>, EventError> {
        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)
            } else if request.url() == "/new_block" {
                process_event::<T, StacksBlockEvent>(request)
            } else {
                let url = request.url().to_string();
                debug!(
                    "[{:?}] next_event got request with unexpected url {}, return OK so other side doesn't keep sending this",
                    event_receiver.local_addr,
                    url
                );
                ack_dispatcher(request);
                Err(EventError::UnrecognizedEvent(url))
            }
        })?
