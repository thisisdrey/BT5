### Title
Object pool authenticity determined by self-consistency of the caller-supplied path instead of an authoritative pool registry, enabling cross-repository object disclosure via `DisconnectGitAlternates`/`FetchIntoObjectPool` - (File: internal/git/objectpool/pool.go, internal/git/objectpool/disconnect.go)

### Summary
Analogous to the reported vault-authenticity bug — where a "vault" is trusted because it merely *reports itself* as pointing to a valid `LiquidStakingManager` rather than being checked against an authoritative registry of real vaults — Gitaly's object-pool machinery trusts a repository's *self-reported* `objects/info/alternates` content (or a caller-supplied `ObjectPool` path) as long as it is structurally well-formed and points at *some* valid git directory. It never confirms against an authoritative source (the pool actually created via `CreateObjectPool`, or ownership/lineage of the pool) that the target is genuinely *this* repository's object pool.

### Finding Description
`objectpool.FromRepo` (`internal/git/objectpool/pool.go:123-171`) derives the "pool" a repository is linked to purely from the repository's own `objects/info/alternates` file: [1](#0-0) 
The only "authenticity" check performed is `locator.ValidateRepository`, i.e. does a git repository exist at that path — not whether it is a genuine, previously-created object pool. `ObjectPool.IsValid` similarly only checks: [2](#0-1) 

`objectpool.FromProto` (used by `LinkRepositoryToObjectPool`, `FetchIntoObjectPool`, `DeleteObjectPool`) is only slightly stronger — it checks `storage.IsPoolRepository`, which is a **pure regex/naming-convention check on the caller-supplied relative path** (`@pools/xx/yy/<hash>.git` or the Praefect `@cluster/pools/...` pattern): [3](#0-2) [4](#0-3) 
This is a self-consistency/format check on the untrusted input, not a lookup against an authoritative pool registry (there is no verification that this exact path was ever produced by `CreateObjectPool` for a specific origin, nor that the calling repository is entitled to use it).

Critically, `objectpool.Disconnect` (`internal/git/objectpool/disconnect.go:36-134`), invoked by the unprivileged, repository-owner-reachable `DisconnectGitAlternates` RPC, goes even further: it never calls `IsPoolRepository`/`FromProto`/`FromRepo` authenticity checks at all. It simply reads whatever `objects/info/alternates` currently says: [5](#0-4) 
then, once it verifies the target is *some* directory on disk, iterates and hard-links every object file found there into the calling repository: [6](#0-5) 
The only gate that exists is "is `altObjectDir` a directory" — there is no check that this directory is a registered pool, nor that the repository is actually entitled to consume its contents.

### Impact Explanation
If a repository's `objects/info/alternates` file can be made to reference *any* other repository's object directory on the same storage (rather than a legitimate, registered object pool), `Disconnect`/`FetchIntoObjectPool`-style flows will happily hard-link (i.e., copy in) all of that target's objects into the attacker-controlled repository — a cross-repository object disclosure. This mirrors the reported bug class exactly: authenticity is established by asking the attacker-influenced input to vouch for itself (does it look like a pool path / does *a* repository exist there) rather than checking it against ground truth (was this pool actually created for me, by `CreateObjectPool`, and am I a legitimate member of it).

### Likelihood Explanation
I could not fully confirm, within the scope of this repo's index, an unprivileged/ordinary-user code path that lets an attacker directly overwrite their own repository's `objects/info/alternates` file with an arbitrary absolute/relative path pointing at another repository's object directory (the normal `Link` path always computes this value itself from an already-checked pool). Repository-import/snapshot paths (`CreateRepositoryFromSnapshot`, `ReplicateRepository`'s custom tar extractor in `internal/gitaly/service/repository/replicate.go`) do let a repository owner supply arbitrary file contents for their *own* new repository, which is a plausible vector to plant such a file, but I was not able to trace, with concrete file/line evidence, that this specific file survives untouched into a state where `Disconnect`/`FromRepo` would later be triggered by an ordinary caller against an alternates target outside the intended pool. This gap should be verified with further investigation (e.g., tracing whether `repoutil.Create`/`CreateRepositoryFromSnapshot` allow files under `objects/info/` to pass through unmodified, and whether `DisconnectGitAlternates`/`FetchIntoObjectPool` can then be invoked on that repository by its owner without any additional server-side sanity check other than the ones cited above).

### Recommendation
- Do not derive "this repository's pool" purely from self-reported alternates content or a naming-convention regex on caller-supplied paths. Validate the `ObjectPool`/`FromRepo` target against an authoritative source of truth — e.g., require a lookup in the pool metadata table (`PoolStore`, as used in `ScanPoolMetadata`) or an explicit repository-ID/pool-ID relationship recorded at `CreateObjectPool`/`LinkRepositoryToObjectPool` time, similar to the recommended fix of taking a `LiquidStakingManager` address list rather than trusting a caller-supplied vault's self-report.
- In `objectpool.Disconnect`, add an explicit check that `altObjectDir`'s owning repository satisfies `storage.IsPoolRepository` (or the stronger registry check above) before treating it as a legitimate pool to hard-link objects from.
- Audit all code paths that can write to `objects/info/alternates` (repository creation from snapshot/bundle/replication) to ensure such files are stripped, regenerated, or validated rather than passed through verbatim.

### Proof of Concept
Not independently reproduced against a running Gitaly instance; the analysis is based on static code review of the cited functions. A concrete PoC would require: (1) confirming a code path that lets an ordinary user plant an attacker-chosen `objects/info/alternates` file in a repository they own that survives repository creation, and (2) invoking `DisconnectGitAlternates` (or `FetchIntoObjectPool`) against that repository to demonstrate objects from an unrelated victim repository being copied into the attacker's repository.

// FromProto returns an object pool object from its Protobuf representation. This function verifies
// that the object pool exists and is a valid pool repository.
func FromProto(
	ctx context.Context,
	logger log.Logger,
	locator storage.Locator,
	gitCmdFactory gitcmd.CommandFactory,
	catfileCache catfile.Cache,
	txManager transaction.Manager,
	housekeepingManager housekeepingmgr.Manager,
	proto *gitalypb.ObjectPool,
) (*ObjectPool, error) {
	poolPath, err := locator.GetRepoPath(ctx, proto.GetRepository(), storage.WithRepositoryVerificationSkipped())
	if err != nil {
		return nil, err
	}

	if !storage.IsPoolRepository(proto.GetRepository()) {
		// When creating repositories in the ObjectPool service we will first create the
		// repository in a temporary directory. So we need to check whether the path we see
		// here is in such a temporary directory and let it pass.
		tempDir, err := locator.TempDir(proto.GetRepository().GetStorageName())
		if err != nil {
			return nil, fmt.Errorf("getting temporary storage directory: %w", err)
		}

		if !strings.HasPrefix(poolPath, tempDir) {
			return nil, ErrInvalidPoolDir
		}
	}

// IsRailsPoolRepository returns whether the repository is a pool repository generated by Rails.
func IsRailsPoolRepository(repo Repository) bool {
	matches := railsPoolDirRegexp.FindStringSubmatch(repo.GetRelativePath())
	if matches == nil || !strings.HasPrefix(matches[3], matches[1]+matches[2]) {
		return false
	}

	return true
}

// IsPraefectPoolRepository returns whether the repository is a Praefect generated object pool repository.
func IsPraefectPoolRepository(repo Repository) bool {
	return praefectPoolDirRegexp.MatchString(repo.GetRelativePath())
}

// IsPoolRepository returns whether the repository is an object pool.
func IsPoolRepository(repo Repository) bool {
	return IsRailsPoolRepository(repo) || IsPraefectPoolRepository(repo)
}

func Disconnect(ctx context.Context, f storage.FS, repo *localrepo.Repo, logger log.Logger, txManager transaction.Manager) error {
	repoPath, err := repo.Path(ctx)
	if err != nil {
		return err
	}

	altInfo, err := stats.AlternatesInfoForRepository(repoPath)
	if err != nil {
		return err
	}

	// If the repository does not have an alternates file or if alternate file does not contain
	// object directories, there is not an object pool repository to disconnect from and no need to
	// continue.
	if !altInfo.Exists || len(altInfo.ObjectDirectories) == 0 {
		// When a repository is not linked to any alternates, ensure the repository is consistent
		// with other replicas.
		if err := transaction.VoteOnContext(ctx, txManager, voting.VoteFromData([]byte("no alternates")), voting.Synchronized); err != nil {
			return fmt.Errorf("vote on missing alternates: %w", err)
		}

		return nil
	}
