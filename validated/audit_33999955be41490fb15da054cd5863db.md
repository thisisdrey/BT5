### Title
Unbounded array size / out-of-bounds heap allocation in `ValidateMultiSign` precompile ABI decoding causes uncaught runtime exception (DoS) - (File: actuator/src/main/java/org/tron/core/vm/PrecompiledContracts.java)

### Summary
The `ValidateMultiSign` TVM precompiled contract decodes an attacker-controlled ABI blob into `DataWord[]` and derives array lengths and offsets directly from that untrusted data before allocating arrays and copying bytes, similar in root cause to Exiv2's `printIFDStructure` trusting attacker-supplied offset/count fields when building in-memory structures, leading to out-of-bounds heap access.

### Finding Description
`ValidateMultiSign.execute` parses the raw call data into `DataWord[] words` and then calls `extractSigArray`/`extractBytesArray` with an `offset` and `data` derived from `words[3].intValueSafe()` [1](#0-0) . Inside `extractBytesArray`/`extractSigArray`, the array length `len` and per-item `bytesOffset`/`bytesLen` are read straight from `words[...]` (attacker-controlled) and used to allocate `new byte[len][]` and to compute a byte offset passed to `extractBytes`, which does `Arrays.copyOfRange(data, offset, offset + len)` with no bounds validation against `data.length` [2](#0-1) . Attacker-chosen `offset`/`len` values can be negative, overflow, or exceed `data.length`, which trigger `NegativeArraySizeException`, `ArrayIndexOutOfBoundsException`, or `IllegalArgumentException` inside `Arrays.copyOfRange`. The bounds/format check `isValidAbiEncoding` is only invoked when `VMConfig.allowTvmOsaka()` is enabled, and the `MAX_SIZE` check on `sigArraySize` is only applied when `VMConfig.allowTvmSelfdestructRestriction()` is enabled [3](#0-2) ; when these hard-fork/config gates are not active (or on chains where they are disabled), no validation of the header fields (`words[3]`, or the per-item offsets `words[offset+i+1]`) exists before the array is sized and copied, so the exception occurs deep inside the precompile's `execute` before the encompassing `try { ... } catch (Throwable t)` block even executes — the `try` block that catches `Throwable` starts only around the signature-recovery loop (`account.getPermissionById` onward), not around the earlier `DataWord.parseArray`/`extractSigArray`/`extractBytesArray` calls [4](#0-3) .

### Impact Explanation
Any account can trigger `ValidateMultiSign` by invoking a Solidity contract that calls the precompile at its fixed address, or directly via a crafted TVM call, with fully attacker-controlled `rawData`. Because the length/offset fields feeding `extractBytesArray`/`extractSigArray`/`extractBytes` are unvalidated before array allocation and copy, a malicious transaction can throw an uncaught `RuntimeException` (e.g., `NegativeArraySizeException`) from within precompile execution. Depending on how the outer TVM interpreter/`Program` handles exceptions thrown out of `PrecompiledContract.execute`, this can propagate as an unexpected runtime error during transaction execution across all full nodes processing the same block, which is a denial-of-service class impact (node crash/consensus-processing failure) analogous to the CVE's "crafted input leads to remote denial of service."

### Likelihood Explanation
Reachable by any unprivileged account with a single transaction that calls a contract invoking the `ValidateMultiSign` precompile with crafted `rawData`; no special permissions, staking, or witness/SR role required. However, whether the resulting exception ultimately crashes the node, halts consensus, or is safely caught/mapped to a reverted-transaction result somewhere in the TVM call plumbing (`Program`/`OperationActions`) could not be conclusively verified from the retrieved code — the exact exception-handling wrapper around `PrecompiledContract.execute()` invocation in `Program.java`/`OperationActions.java` was not fully inspected due to tool-call limits.

### Recommendation
Validate all length/offset/count fields decoded from precompile input (`words[3]`, per-item offsets in `extractBytesArray`/`extractSigArray`, and lengths passed to `extractBytes`) against `0 <= value <= data.length` (and consistent with `words.length`) before performing any array allocation or `Arrays.copyOfRange` call, independent of the `allowTvmOsaka`/`allowTvmSelfdestructRestriction` feature flags. Wrap the full `ValidateMultiSign.execute` body (including ABI parsing) in bounds-checked logic or a top-level `catch (Throwable)` that returns `DATA_FALSE` rather than propagating raw parsing exceptions.

### Proof of Concept
Craft `rawData` for a call to the `ValidateMultiSign` precompile where:
- `words[3]` (used as `words[3].intValueSafe() / WORD_SIZE`) points to a header word whose `intValueSafe()` (`len`) is a large negative or huge positive value, or
- the header at that offset yields a `bytesOffset`/`bytesLen` such that `(bytesOffset + offset + 2) * WORD_SIZE` in `extractBytes` exceeds `data.length` or is negative.

Send this as calldata via a contract call (`TriggerSmartContract`) that dispatches to the precompile address; `extractSigArray`/`extractBytesArray`/`extractBytes` at [2](#0-1)  will throw `NegativeArraySizeException`/`ArrayIndexOutOfBoundsException` before the enclosing `try/catch(Throwable)` in `execute()` at [4](#0-3)  can intercept it (since that try block only wraps the code starting at `account.getPermissionById`, not the earlier extraction calls).

  private static byte[][] extractBytesArray(DataWord[] words, int offset, byte[] data) {
    if (offset > words.length - 1) {
      return new byte[0][];
    }
    int len = words[offset].intValueSafe();
    byte[][] bytesArray = new byte[len][];
    for (int i = 0; i < len; i++) {
      int bytesOffset = words[offset + i + 1].intValueSafe() / WORD_SIZE;
      int bytesLen = words[offset + bytesOffset + 1].intValueSafe();
      bytesArray[i] = extractBytes(data, (bytesOffset + offset + 2) * WORD_SIZE,
          bytesLen);
    }
    return bytesArray;
  }

  private static byte[][] extractSigArray(DataWord[] words, int offset, byte[] data) {
    if (offset > words.length - 1) {
      return new byte[0][];
    }
    int len = words[offset].intValueSafe();
    byte[][] bytesArray = new byte[len][];
    for (int i = 0; i < len; i++) {
      int bytesOffset = words[offset + i + 1].intValueSafe() / WORD_SIZE;
      bytesArray[i] = extractBytes(data, (bytesOffset + offset + 2) * WORD_SIZE,
          SIG_LENGTH);
    }
    return bytesArray;
  }

  private static byte[] extractBytes(byte[] data, int offset, int len) {
    return Arrays.copyOfRange(data, offset, offset + len);
  }
