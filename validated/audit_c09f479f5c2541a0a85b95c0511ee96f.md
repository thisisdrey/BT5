### Title
`storage.IsPoolRepository` uses an unanchored regex, letting a crafted `relative_path` with a `..`-prefixed traversal segment pass the pool-dir check while resolving to a repository location outside the `@pools/xx/yy/` subtree - (File: internal/gitaly/storage/repository_path.go, internal/gitaly/service/objectpool/create.go, internal/git/objectpool/pool.go)

### Summary
`railsPoolDirRegexp` in `internal/gitaly/storage/repository_path.go` is anchored only with a trailing `$`, not a leading `^`, so `IsPoolRepository`/`IsRailsPoolRepository` return true for any string that merely *ends* with a valid `@pools/xx/yy/<64-hex>.git` suffix, regardless of what precedes it. `CreateObjectPool` (`internal/gitaly/service/objectpool/create.go`) and `objectpool.FromProto` (`internal/git/objectpool/pool.go`) validate the pool-dir shape using this check on the raw, attacker-supplied `relative_path` before the path is cleaned/joined by `storage.ValidateRelativePath`/`locator.GetRepoPath`. This lets an attacker prepend arbitrary traversal components (e.g. `foo/../../other/@pools/aa/bb/<hash>.git`) that pass `IsPoolRepository` but resolve, after `filepath.Join`/`Clean`, to a location entirely outside the intended `@pools/aa/bb/` two-level subtree (while still remaining inside the storage root, so `ErrRelativePathEscapesRoot` is not triggered).

### Finding Description
- `railsPoolDirRegexp = regexp.MustCompile(`@pools/([0-9a-f]{2})/([0-9a-f]{2})/([0-9a-f]{64})\.git$`)` [1](#0-0)  has no `^` anchor, so `FindStringSubmatch` matches on any suffix of the input string, not the whole string.
- `IsRailsPoolRepository`/`IsPoolRepository` only check that suffix match plus the hash-prefix relationship (`matches[3]` starts with `matches[1]+matches[2]`); they never verify that the string starts with `@pools/...` [2](#0-1) .
- `CreateObjectPool` calls `storage.IsPoolRepository(poolRepo)` directly on the attacker-controlled `ObjectPool.Repository.RelativePath` from the request, before any path cleaning occurs, and rejects only if that check fails [3](#0-2) .
- `objectpool.FromProto` similarly evaluates `storage.IsPoolRepository(proto.GetRepository())` against the raw proto field, separately from `poolPath` which is obtained via `locator.GetRepoPath` (which internally performs the join/clean/escape validation) [4](#0-3) . The value that is checked for "is this a pool path" and the value that is actually used to resolve the on-disk directory diverge.
- `storage.ValidateRelativePath` only guarantees the resolved path stays under `rootDir`; it does not guarantee the resolved path stays under `@pools/xx/yy/` [5](#0-4) .
- The existing negative tests in `create_test.go` (`"path must be lowercase"`, `"subdirectories must match first four pool digits"`, `"pool path traversal fails"`) only test simple malformed suffixes or a trailing `/..`, none of which exercise a *prefixed* traversal segment placed before a syntactically-valid pool suffix [6](#0-5) , so this bypass is not covered.

As a result, an attacker can submit `CreateObjectPoolRequest{ObjectPool:{Repository:{relative_path: "somedir/../../otherdir/@pools/aa/bb/aabb<60 more hex chars>.git"}}}`. `IsPoolRepository` matches the trailing `@pools/aa/bb/aabb....git` portion and returns true, satisfying the check in `create.go`. The repository is then actually created (via `repoutil.Create` → `objectpool.Create` → path resolution through the locator) at the *cleaned* relative path, which after `filepath.Join`/`Clean` collapses the `..` segments and lands at `otherdir/@pools/aa/bb/aabb....git` — a location that is not under the canonical `@pools/aa/bb/` two-level tree that the pool-pruning/GC-exemption logic in `OptimizeRepository` expects (per the comment on `DerivePoolPath`, pools are placed in a distinctive prefix specifically so Gitaly can identify and skip pruning them) [7](#0-6) .

### Impact Explanation
This does not escape the storage root (`ErrRelativePathEscapesRoot` still guards that), but it does bypass the intended structural constraint that pool repositories must reside strictly under `@pools/<2-hex>/<2-hex>/`. Depending on downstream directory-existence handling in `repoutil.Create`, this can be used to place an attacker-controlled "pool" repository at an unexpected relative path within the shared storage, potentially colliding with paths used by unrelated repositories (hashed/legacy storage relative paths can be predictable from project IDs), and it undermines an internal invariant (pool GC exemption relies on the fixed `@pools` prefix) relied on elsewhere in the codebase. This falls under storage-path constraint bypass / potential cross-repository interference within the shared storage.

### Likelihood Explanation
Any unprivileged user able to invoke `CreateObjectPool` (which fork/import workflows exercise) can trigger this; no special role, secret, or non-default configuration is required — only crafting the `relative_path` field of the RPC request. It is fully repeatable.

### Recommendation
Anchor `railsPoolDirRegexp` at both ends (`^@pools/...$`) and validate `IsPoolRepository` against the *cleaned* relative path (post `storage.ValidateRelativePath`) rather than the raw, attacker-supplied string, in both `internal/gitaly/service/objectpool/create.go` and `internal/git/objectpool/pool.go`.

### Proof of Concept
```go
func TestIsPoolRepository_UnanchoredRegexBypass(t *testing.T) {
    hash := strings.Repeat("a", 64) // starts with "aa" matching subdir prefix
    repo := &gitalypb.Repository{
        RelativePath: "legituser/../../otherdir/@pools/aa/aa/" + hash + ".git",
    }
    require.True(t, storage.IsPoolRepository(repo)) // passes despite traversal prefix
}
```
Corresponding gRPC PoC:
```
CreateObjectPoolRequest{
  Origin: <valid repo>,
  ObjectPool: {Repository: {
    StorageName: "default",
    RelativePath: "legituser/../../otherdir/@pools/aa/aa/aaaa...(64 hex).git",
  }},
}
```
Expected (buggy) behavior: request passes the `errInvalidPoolDir` check in `create.go` and proceeds to repository creation, resulting in a pool repository materialized outside the `@pools/xx/yy/` subtree once the relative path is cleaned by the locator.

func IsRailsPoolRepository(repo Repository) bool {
	matches := railsPoolDirRegexp.FindStringSubmatch(repo.GetRelativePath())
	if matches == nil || !strings.HasPrefix(matches[3], matches[1]+matches[2]) {
		return false
	}

	return true
}

// IsPraefectPoolRepository returns whether the repository is a Praefect generated object pool repository.
func IsPraefectPoolRepository(repo Repository) bool {
	return praefectPoolDirRegexp.MatchString(repo.GetRelativePath())
}

// IsPoolRepository returns whether the repository is an object pool.
func IsPoolRepository(repo Repository) bool {
	return IsRailsPoolRepository(repo) || IsPraefectPoolRepository(repo)
}

func ValidateRelativePath(rootDir, relativePath string) (string, error) {
	absPath := filepath.Join(rootDir, relativePath)
	if rootDir != absPath && !strings.HasPrefix(absPath, rootDir+string(os.PathSeparator)) {
		return "", ErrRelativePathEscapesRoot
	}

	return filepath.Rel(rootDir, absPath)
}
