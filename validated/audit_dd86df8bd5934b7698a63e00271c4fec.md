### Title
Interest keeps compounding during `shutdown` while repay/liquidate are blocked, exposing borrowers to instant liquidation on `open()` — ([File: contracts/DebtToken.sol](contracts/DebtToken.sol))

### Summary
`Pool`/`PoolRegistry` `shutdown()` blocks `repay`, `repayAll`, `liquidate`, `swap`, `issue`, and `withdraw` via the `whenNotShutdown` modifier (`Pauseable.sol:50-53`, `113-117`). However, `DebtToken._calculateInterestAccrual()` computes accrued interest purely from `block.timestamp - lastTimestampAccrued` (`DebtToken.sol:559-564`) and never accounts for the shutdown window. When the governor calls `open()`, all interest that compounded while users were forcibly prevented from repaying materializes at once in `balanceOf()`/`debtPositionOf()`, and any account can be permissionlessly liquidated the same block. No pause/shutdown timestamp is stored anywhere to offset accrual — identical bug class to the BendDAO `InterestLogic::_updateBorrowIndex` finding.

### Finding Description
- `shutdown()` sets `_everythingStopped = true` (governor or guardian), blocking every exit path: `DebtToken.repay`/`repayAll` are gated by `whenNotShutdown` (`DebtToken.sol:424`, `470`), and `Pool.liquidate`/`swap`/`issue` are likewise disabled per `docs/emergency-flags.md:39`.
- `DebtToken.accrueInterest()` and the view `balanceOf()` both rely on `_calculateInterestAccrual()`, which uses `interestRatePerSecond() * (block.timestamp - lastTimestampAccrued)` (`DebtToken.sol:560`) — there is no subtraction of the shutdown duration, and `lastTimestampAccrued` is only bumped on the next accrual (`DebtToken.sol:167`), which cannot happen during shutdown since no state-changing entry point runs.
- On `open()` (`Pauseable.sol:97-100`), the first `accrueInterest()` credits the entire shutdown interval. Any borrower whose health was marginal pre-shutdown — or degraded by collateral/synth price moves during shutdown — becomes liquidatable immediately, with zero opportunity to repay.

### Impact Explanation
Loss of user collateral through forced liquidation: interest accrues during a window where repayment is contractually impossible, then liquidations execute the moment the pool reopens. An unprivileged liquidator can call `Pool.liquidate` in the same transaction/block as `open()` (or immediately after), front-running users' repay transactions. Severity mirrors the judged Medium: shutdown is intended for emergencies, but duration is arbitrary and the unfair accrual is fully preventable at contract level.

### Likelihood Explanation
Requires a shutdown event (emergency-only, admin-triggered), so frequency is low; but the harm is deterministic once it occurs — every borrower accrues unpayable interest, and thin-margin positions are guaranteed to cross liquidation bounds. No attacker privilege or oracle manipulation is needed; liquidation is permissionless.

### Recommendation
Record the shutdown timestamp in `Pauseable` (or per-DebtToken) and either (a) on `open()`, advance `lastTimestampAccrued` by the shutdown duration before any accrual, or (b) subtract the shutdown interval inside `_calculateInterestAccrual()`. Alternatively, keep `repay`/`repayAll` enabled during shutdown so users can always deleverage.

### Proof of Concept
Reproducible in the existing Hardhat suite (`test/DebtToken.test.ts` already demonstrates `poolMock.shutdown()` reverting `repayAll` with `IsShutdown`, lines 549-558):

```ts
// user1 has a debt position near the liquidation boundary
await msUSDDebt.connect(user1).issue(amount, user1.address)

// guardian/governor emergency shutdown
await poolMock.shutdown()
await expect(msUSDDebt.connect(user1).repayAll(user1.address))
  .to.be.revertedWithCustomError(msUSDDebt, 'IsShutdown')
await expect(pool.connect(lq).liquidate(...)).to.be.reverted // liquidate also blocked

// interest silently compounds during shutdown
await time.increase(time.duration.days(30))
const debtDuring = await msUSDDebt.balanceOf(user1.address) // grew despite frozen market

// reopen -> same-block liquidation front-runs user's repay
await poolMock.connect(governor).open()
await msUSDDebt.accrueInterest() // credits full 30-day interval
const {_debtInUsd} = await pool.debtPositionOf(user1.address)
// health factor now < 1; unprivileged liquidator seizes collateral
await pool.connect(attacker).liquidate(msdMET.address, user1.address, msUSDDebt.address, ...)
expect(await msUSDDebt.balanceOf(user1.address)).to.eq(0) // position wiped
```

Key code paths: `Pauseable.sol:113-117` (shutdown), `DebtToken.sol:424,470` (`whenNotShutdown` on repay paths), `DebtToken.sol:551-566` (accrual ignores shutdown window), `Pauseable.sol:97-100` (reopen with no timestamp adjustment).
