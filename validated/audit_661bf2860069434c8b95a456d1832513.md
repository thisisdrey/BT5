### Title
Unbounded attacker-controlled length used for array allocation in `ValidateMultiSign`/`BatchValidateSign` precompile helpers - ([File: actuator/src/main/java/org/tron/core/vm/PrecompiledContracts.java])

### Summary
The libssh2 CVE is rooted in taking an attacker-controlled 32-bit count from protocol input and using it directly to size an allocation without an upper-bound check, letting a remote peer force an oversized/overflowed allocation. The same pattern exists in java-tron's TVM precompile helpers `extractBytesArray` / `extractSigArray` / `extractBytes32Array`, which take a length word straight out of attacker-supplied call data (`words[offset].intValueSafe()`) and immediately allocate `new byte[len][]` before any upper-bound (`MAX_SIZE`) check is guaranteed to run.

### Finding Description
`extractBytesArray`, `extractSigArray`, and `extractBytes32Array` read a count field directly from the caller-controlled ABI-encoded input and use it to allocate a two-dimensional array with no validation: [1](#0-0) 

`intValueSafe()` on `DataWord` returns `Integer.MAX_VALUE` for any value that doesn't fit safely in 4 bytes, meaning an attacker can force `len` to be `Integer.MAX_VALUE` merely by placing a large 32-byte word at the expected array-length position in calldata: [2](#0-1) 

These helpers are invoked from `ValidateMultiSign.execute` (precompile address `0x...a`) and `BatchValidateSign.execute` (precompile address `0x...9`), both reachable by any contract via `CALL`/`STATICCALL` from an unprivileged, unsigned-permission caller: [3](#0-2) [4](#0-3) 

Critically, the `MAX_SIZE` bound check is only performed when the `VMConfig.allowTvmSelfdestructRestriction()` feature flag is active, and even then it is checked using a *different* code path (`extractSigArray`) than the unguarded legacy path (`extractBytesArray`), which is exercised whenever that flag is off: [5](#0-4) 

In `ValidateMultiSign.execute`, the call to `extractBytesArray`/`extractSigArray` (and the resulting huge allocation or `ArrayIndexOutOfBoundsException` from wildly out-of-range `bytesOffset`/`bytesLen` values) happens *outside* any try/catch block in that method — only the inner permission-weight loop is wrapped in `try { ... } catch (Throwable t)`. Any exception or `OutOfMemoryError` thrown while parsing the array therefore propagates unguarded out of `ValidateMultiSign.execute`.

### Impact Explanation
An attacker deploys or calls a contract that invokes the `validatemultisign`/`batchvalidatesign` precompile with a crafted length word (e.g., `0x7fffffff`) at the position used as the array-count offset. This forces an attempt to allocate a reference array with up to `Integer.MAX_VALUE` elements (potentially several GB on 64-bit JVMs), or drives `extractBytesArray`'s inner-loop offset arithmetic (`bytesOffset`, `bytesLen`) with attacker-chosen huge values that can throw unhandled `ArrayIndexOutOfBoundsException`/`NegativeArraySizeException`/`OutOfMemoryError`. Since `ValidateMultiSign.execute` does not wrap this call in a broad catch, the exception/error propagates out of the precompile into the VM execution path for that transaction. Depending on how the outer VM/transaction-processing layer handles such throwables, this can degrade or crash the node's block/transaction processing (denial of service), which matches the "node crash or halt" / "API the node can no longer serve" impact class for this scan.

### Likelihood Explanation
The precompile is reachable by any account via a single ordinary smart-contract call (`CALL`/`STATICCALL` to address `0x...a`), requiring no special privileges, no valid account/permission, and no cooperation from other parties — an anonymous contract deployer/caller can trigger it directly, matching the "unprivileged transaction broadcaster/contract deployer" reachability bar from the scan rules. The bound check (`MAX_SIZE`) exists but is gated behind the `allowTvmSelfdestructRestriction` flag and, even when active, the check is duplicated separately from the actual extraction call rather than being enforced unconditionally inside `extractBytesArray` itself, leaving the legacy unguarded path (`extractBytesArray`) reachable whenever the flag is not enabled.

### Recommendation
Enforce the `MAX_SIZE` bound unconditionally and *inside* `extractBytesArray`/`extractSigArray`/`extractBytes32Array` themselves before any allocation, regardless of `VMConfig.allowTvmSelfdestructRestriction()`. Reject calls where `words[offset].intValueSafe()` exceeds a small sane bound (e.g., `MAX_SIZE`) or where computed offsets exceed `words.length`/`data.length`, returning `DATA_FALSE` instead of allocating or indexing. Wrap the entire body of `ValidateMultiSign.execute` (not just the inner permission loop) in a catch-all that safely returns `DATA_FALSE` for any `Throwable`, consistent with `BatchValidateSign.execute`'s outer try/catch.

### Proof of Concept
1. Deploy a contract that performs a `CALL` (or `STATICCALL`) to the `ValidateMultiSign` precompile address with ABI-encoded input matching `validatemultisign(address,uint256,bytes32,bytes[])`, but with the array-length word for `bytes[]` set to a maliciously large value (e.g. `0x00000000000000000000000000000000000000000000000000000007ffffff` or `0xffffffff...` such that `intValueSafe()` returns `Integer.MAX_VALUE`), while `VMConfig.allowTvmSelfdestructRestriction()` is disabled (legacy path).
2. This calldata reaches `ValidateMultiSign.execute`, which calls `extractBytesArray(words, ..., rawData)` before any size guard, per lines 1072–1074 of `PrecompiledContracts.java`.
3. `extractBytesArray` allocates `new byte[len][]` with `len == Integer.MAX_VALUE`, immediately triggering `OutOfMemoryError`, or (with a smaller but still out-of-range value) drives `bytesOffset`/`bytesLen` computed from attacker words to out-of-bounds `Arrays.copyOfRange` calls that throw unhandled runtime exceptions.
4. Because this occurs outside the `try/catch(Throwable)` block in `ValidateMultiSign.execute`, the exception/error is not contained, and propagates to the node's VM execution layer for every transaction that includes this call — repeatable at will by any broadcaster to degrade node availability. [6](#0-5)

  private static byte[][] extractBytes32Array(DataWord[] words, int offset) {
    int len = words[offset].intValueSafe();
    byte[][] bytes32Array = new byte[len][];
    for (int i = 0; i < len; i++) {
      bytes32Array[i] = words[offset + i + 1].getData();
    }
    return bytes32Array;
  }

  private static byte[][] extractBytesArray(DataWord[] words, int offset, byte[] data) {
    if (offset > words.length - 1) {
      return new byte[0][];
    }
    int len = words[offset].intValueSafe();
    byte[][] bytesArray = new byte[len][];
    for (int i = 0; i < len; i++) {
      int bytesOffset = words[offset + i + 1].intValueSafe() / WORD_SIZE;
      int bytesLen = words[offset + bytesOffset + 1].intValueSafe();
      bytesArray[i] = extractBytes(data, (bytesOffset + offset + 2) * WORD_SIZE,
          bytesLen);
    }
    return bytesArray;
  }

    private static final int ENGERYPERSIGN = 1500;
    private static final int MAX_SIZE = 5;
    private static final int ABI_HEADER_WORDS = 5;
    private static final int ABI_ITEM_WORDS = 5;


    @Override
    public long getEnergyForData(byte[] data) {
      long cnt = (data.length / WORD_SIZE - 5) / 5;
      // one sign 1500, half of ecrecover
      return cnt * ENGERYPERSIGN;
    }

    @Override
    public Pair<Boolean, byte[]> execute(byte[] rawData) {
      if (VMConfig.allowTvmOsaka()
          && !isValidAbiEncoding(rawData, ABI_HEADER_WORDS, ABI_ITEM_WORDS)) {
        return Pair.of(false, EMPTY_BYTE_ARRAY);
      }
      DataWord[] words = DataWord.parseArray(rawData);
      byte[] address = words[0].toTronAddress();
      int permissionId = words[1].intValueSafe();
      byte[] data = words[2].getData();

      byte[] combine = ByteUtil.merge(address, ByteArray.fromInt(permissionId), data);
      byte[] hash = Sha256Hash.hash(CommonParameter
          .getInstance().isECKeyCryptoEngine(), combine);

      if (VMConfig.allowTvmSelfdestructRestriction()) {
        int sigArraySize = words[words[3].intValueSafe() / WORD_SIZE].intValueSafe();
        if (sigArraySize > MAX_SIZE) {
          return Pair.of(true, DATA_FALSE);
        }
      }
      byte[][] signatures = VMConfig.allowTvmSelfdestructRestriction() ?
          extractSigArray(words, words[3].intValueSafe() / WORD_SIZE, rawData) :
          extractBytesArray(words, words[3].intValueSafe() / WORD_SIZE, rawData);

      if (signatures.length == 0 || signatures.length > MAX_SIZE) {
        return Pair.of(true, DATA_FALSE);
      }

      AccountCapsule account = this.getDeposit().getAccount(address);
      if (account != null) {
        try {
          Permission permission = account.getPermissionById(permissionId);
          if (permission != null) {
            //calculate weight
            long totalWeight = 0L;
            List<byte[]> executedSignList = new ArrayList<>();
            for (byte[] sign : signatures) {
              byte[] recoveredAddr = recoverAddrBySign(sign, hash);

              sign = merge(recoveredAddr, sign);
              if (ByteArray.matrixContains(executedSignList, recoveredAddr)) {
                if (ByteArray.matrixContains(executedSignList, sign)) {
                  continue;
                }
                MUtil.checkCPUTime();
              }
              long weight = TransactionCapsule.getWeight(permission, recoveredAddr);
              if (weight == 0) {
                //incorrect sign
                return Pair.of(true, DATA_FALSE);
              }
              totalWeight += weight;
              executedSignList.add(sign);
              executedSignList.add(recoveredAddr);
            }

            if (totalWeight >= permission.getThreshold()) {
              return Pair.of(true, dataOne());
            }
          }
        } catch (Throwable t) {
          if (t instanceof OutOfTimeException) {
            throw t;
          }
          logger.info("ValidateMultiSign error:{}", t.getMessage());
        }
      }
      return Pair.of(true, DATA_FALSE);
    }
  }
