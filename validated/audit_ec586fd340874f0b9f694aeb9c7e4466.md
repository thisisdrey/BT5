### Title
TXT-record certificate disclosure via UDP source-IP spoofing bypassing `isSelfNebulaOrLocalhost` gate - ([File: dns_server.go])

### Summary
The DNS TXT handler in `dnsServer.parseQuery` gates certificate disclosure solely on `isSelfNebulaOrLocalhost(w.RemoteAddr().String())`, which trusts the UDP packet's reported source IP address with no cryptographic verification. Because the listener binds to whatever address `lighthouse.dns.host` names (including a plain wildcard/public-facing address, e.g. the default empty host resolving to `:53`), an unprivileged remote attacker can forge the UDP source address to match a value in `cs.myVpnAddrsTable` or loopback, satisfy the gate, and have `QueryCert` return any peer's certificate JSON from `d.hostMap` with zero cryptographic authentication.

### Finding Description
`parseQuery` only permits TXT (certificate) lookups when `d.isSelfNebulaOrLocalhost(w.RemoteAddr().String())` returns true: [1](#0-0) 

`isSelfNebulaOrLocalhost` derives its trust decision purely from the address string reported for the incoming packet — either `IsLoopback()` or membership in `cs.myVpnAddrsTable` (the lighthouse's own known overlay peer addresses) — with no signature, handshake, or session-key check involved: [2](#0-1) 

The DNS responder is a plain connectionless UDP `dns.Server` (`Net: "udp"`) bound to an admin-configured address built from `lighthouse.dns.host`/`lighthouse.dns.port`, which defaults to an empty host (wildcard bind) rather than being restricted to loopback or the nebula tun device: [3](#0-2) [4](#0-3) 

Because standard UDP sockets provide no verification of the sender's claimed source address, and the miekg/dns UDP server surfaces exactly that unverified address as `w.RemoteAddr()`, an attacker who can reach the bound UDP port and forge (spoof) a source IP equal to loopback or to any address the lighthouse considers "its own VPN address" satisfies `isSelfNebulaOrLocalhost` without possessing any nebula certificate, key, or completed handshake. Once past that gate, `QueryCert` performs no additional authentication: it parses the attacker-controlled query name into an `netip.Addr`, looks it up directly in `d.hostMap.QueryVpnAddr(ip)`, and serializes and returns the matching peer's certificate: [5](#0-4) 

This is confirmed by the existing test showing `QueryCert` returns cert bytes for any address recognized by the hostmap/PKI state with no additional identity check on the caller: [6](#0-5) 

### Impact Explanation
An unauthenticated, unprivileged network attacker who can reach the lighthouse's DNS UDP port can enumerate and retrieve the full X.509/Nebula certificate (name, VPN addresses, groups, public key, validity window) of any peer currently or recently in the lighthouse's `hostMap`, by spoofing a UDP source address rather than presenting a CA-signed certificate. This is a certificate/topology disclosure that leaks overlay identity and public-key material an attacker could use to fingerprint the network topology and target subsequent handshake or impersonation attempts against real peers, matching the scoped impact in the question.

### Likelihood Explanation
Exploitability depends entirely on network-level conditions outside nebula's control: the attacker must be able to (a) reach the UDP port the DNS responder is bound to, and (b) successfully spoof a UDP source address that either matches loopback or one of the lighthouse's known VPN addresses without being dropped by ingress/anti-spoofing filtering somewhere on the path. If the lighthouse binds the responder to a publicly reachable interface (the default empty `lighthouse.dns.host` binds a wildcard address rather than restricting to loopback or the nebula tun interface) and the network path does not enforce source-address validation (BCP38/uRPF), this is directly reachable and repeatable by a purely unprivileged remote attacker with no certificate, key, or prior handshake — exactly the "spoofed source addresses" capability the rules explicitly treat as in-scope attacker input.

### Recommendation
Do not derive the TXT-query trust decision from the unauthenticated UDP source address. At minimum: (1) require `lighthouse.dns.host` to be restricted to loopback or an address that is only reachable via the nebula tun device, and refuse to serve TXT records at all when the responder is bound to a non-loopback/non-overlay address; (2) prefer binding the DNS responder to the nebula tun interface exclusively for TXT/cert-disclosure queries so that only already-authenticated, already-handshaked overlay traffic can reach `QueryCert`; (3) as defense in depth, require an explicit shared secret or nebula-native authenticated channel (e.g., serve cert lookups only over an established nebula tunnel API rather than plain UDP DNS) rather than trusting `net.Addr` values from a connectionless transport.

### Proof of Concept
Unit/integration test plan:
1. Build a `dnsServer` with `hostMap` populated with a `HostInfo` for a victim's `netip.Addr` (using existing helpers like `newTestPKI`/`cert_test.NewTestCert`), and a `pki`/`certState` whose `myVpnAddrsTable` contains the lighthouse's own address (not the victim's).
2. Construct a `dns.ResponseWriter` stub (as `stubDNSWriter` already does) whose `RemoteAddr()` returns a forged `*net.UDPAddr` with an `IP` value copied from `cs.myVpnAddrsTable` (or `127.0.0.1`), simulating a spoofed UDP source address rather than a genuine self/loopback origin.
3. Call `ds.parseQuery(m, spoofedWriter)` with a TXT question for the victim's VPN address.
4. Assert `isSelfNebulaOrLocalhost` returns `true` purely from the forged string, and that `m.Answer` contains the victim's certificate JSON returned by `QueryCert`, demonstrating that certificate disclosure succeeds without the caller ever presenting a CA-signed certificate or completing a nebula handshake — i.e., the only "authentication" is a client-supplied source-address string.

func (d *dnsServer) QueryCert(data string) string {
	if len(data) < 2 {
		return ""
	}
	ip, err := netip.ParseAddr(data[:len(data)-1])
	if err != nil {
		return ""
	}

	// The hostmap only ever contains peers we have handshaked with, so it never carries an entry for ourselves.
	// Answer self lookups straight from the local cert state.
	if cs := d.certState(); cs != nil && cs.myVpnAddrsTable != nil && cs.myVpnAddrsTable.Contains(ip) {
		c := cs.GetDefaultCertificate()
		if c == nil {
			return ""
		}
		b, err := c.MarshalJSON()
		if err != nil {
			return ""
		}
		return string(b)
	}

	hostinfo := d.hostMap.QueryVpnAddr(ip)
	if hostinfo == nil {
		return ""
	}

	q := hostinfo.GetCert()
	if q == nil {
		return ""
	}

	b, err := q.Certificate.MarshalJSON()
	if err != nil {
		return ""
	}
	return string(b)
}

func (d *dnsServer) isSelfNebulaOrLocalhost(addr string) bool {
	a, _, _ := net.SplitHostPort(addr)
	b, err := netip.ParseAddr(a)
	if err != nil {
		return false
	}

	if b.IsLoopback() {
		return true
	}

	cs := d.certState()
	if cs == nil || cs.myVpnAddrsTable == nil {
		return false
	}
	//if we found it in this table, it's good
	return cs.myVpnAddrsTable.Contains(b)
}
