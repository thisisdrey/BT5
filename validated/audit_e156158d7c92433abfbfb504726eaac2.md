### Title
Unauthenticated remote shutdown of signer event receiver via `POST /shutdown` - ([File: libsigner/src/events.rs])

### Summary
The `/shutdown` branch in `SignerEventReceiver::next_event` sets the shared `stop_signal` and returns `EventError::Terminated` based purely on the HTTP request URL path, with no authentication, shared secret, or loopback-only enforcement. Any remote party who can reach the signer's event-listener port can send this exact request and permanently halt the signer's event `main_loop`.

### Finding Description
`SignerStopSignaler::send` (the intended, trusted, in-process caller) signals shutdown by opening a `TcpStream` to `self.local_addr` and sending a raw, unauthenticated `POST /shutdown` HTTP request with an arbitrary body: [1](#0-0) 

The receiving side, `SignerEventReceiver::next_event`, dispatches purely on `request.url()`. When the path equals `/shutdown`, it unconditionally stores `true` into the shared `stop_signal` atomic and returns `Err(EventError::Terminated)`, without checking the request's source address, any header, token, or body content: [2](#0-1) 

Since the socket is opened via `HttpServer::http(listener)` in `bind()` on the configured `SocketAddr` (which per the signer's config can be a non-loopback address), any TCP client capable of reaching that address/port can replicate the exact bytes `SignerStopSignaler::send` sends and trigger the same effect: [3](#0-2) 

`main_loop` treats `Err(EventError::Terminated)` as the signal to break out permanently: [4](#0-3) 

There is no signature, secret, or peer-identity check anywhere on this path — the "equality" the code should be enforcing (only the node's own `SignerStopSignaler` may cause a stop) is reduced to nothing more than matching a public, well-known URL string.

### Impact Explanation
Once `stop_signal` is set to `true`, `is_stopped()` returns `true` forever (there's no reset path), and every subsequent `main_loop` iteration exits at the `is_stopped()` check. The signer permanently stops receiving StackerDB chunks, burn-block events, and new-block events, i.e., a complete, permanent denial of service against that signer's event pipeline from a single crafted TCP message. This matches the "Critical - remote crash/unauthenticated DoS from few messages" category.

### Likelihood Explanation
The only precondition is TCP reachability to the port the signer's `SignerEventReceiver::bind` listens on (this is the same event-observer endpoint the node's event dispatcher posts to, and per the signer's configuration this can be bound to a non-loopback interface). The attacker needs no secret, no valid peer key, and no prior interaction — a single unauthenticated HTTP POST suffices, and it is trivially repeatable/idempotent against restarts.

### Recommendation
Restrict the `/shutdown` endpoint so it cannot be triggered by arbitrary remote clients: bind the event-receiver socket to loopback only (or otherwise ensure it isn't exposed) and/or require the stop request to carry a locally-generated, unpredictable shared secret/token known only to `SignerStopSignaler` (e.g., established at `bind()`/`get_stop_signaler()` time and checked in the `/shutdown` branch before flipping `stop_signal`). Alternatively, use an in-process channel/self-pipe instead of a network request for intra-process shutdown signaling, eliminating the network-reachable shutdown path entirely.

### Proof of Concept
```rust
// libsigner/src/events.rs (test module) or a new integration test
use std::io::Write;
use std::net::TcpStream;
use crate::events::{EventReceiver, SignerEventReceiver};
use crate::v0::messages::SignerMessage; // example T

#[test]
fn remote_party_can_trigger_shutdown() {
    let mut receiver: SignerEventReceiver<SignerMessage> = SignerEventReceiver::new(false);
    let addr = receiver.bind("127.0.0.1:0".parse().unwrap()).unwrap();

    // Attacker: independent TcpStream, NOT via SignerStopSignaler
    let body = "attacker controlled body";
    let req = format!(
        "POST /shutdown HTTP/1.1\r\nHost: {}\r\nConnection: close\r\nContent-Length: {}\r\n\r\n{}",
        addr, body.len(), body
    );
    let mut stream = TcpStream::connect(addr).unwrap();
    stream.write_all(req.as_bytes()).unwrap();

    // The malicious request is processed by next_event()
    let result = receiver.next_event();
    assert!(matches!(result, Err(crate::EventError::Terminated)));
    assert!(receiver.is_stopped()); // permanently true, no legitimate caller involved
}
```
This confirms any remote TCP client — not just the node's own `SignerStopSignaler` — can permanently halt the signer's event loop with a single crafted message.
