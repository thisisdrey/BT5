### Title
Missing cross-storage validation in `LinkRepositoryToObjectPool` allows linking a repository to an object pool on a different storage - ([File: internal/gitaly/service/objectpool/link.go])

### Summary
`LinkRepositoryToObjectPool` never checks that the target repository and the object pool reside on the same storage before writing the pool's path into the repository's `objects/info/alternates` file. The sibling RPC `FetchIntoObjectPool` explicitly enforces this invariant via `validateFetchIntoObjectPoolRequest`, but that same guard is absent from `LinkRepositoryToObjectPool`, so the "safe" linking path lacks a check that an analogous method in the same package intentionally enforces.

### Finding Description
`LinkRepositoryToObjectPool` validates only that the repository argument is well-formed and resolves the pool via `poolForRequest`/`objectpool.FromProto`, then immediately calls `pool.Link(ctx, repo)`: [1](#0-0) 

Contrast this with `FetchIntoObjectPool`, which validates the request with an explicit storage-equality check before doing any work: [2](#0-1) 

The underlying `Link` function in `internal/git/objectpool/link.go` computes the relative alternates path purely via `filepath.Rel` between the two repository paths, with no storage-boundary check of its own: [3](#0-2) [4](#0-3) 

`objectpool.FromProto`, used to resolve the pool object in `poolForRequest`, only validates that the pool path is a valid pool repository within its own storage — it does not compare the pool's storage to the target repository's storage: [5](#0-4) [6](#0-5) 

Because Gitaly storages are configured as independent root directories, `filepath.Rel(repoObjectsDir, poolObjectsDir)` between paths in two different storages can still produce a syntactically valid relative path (e.g., `../../../other-storage-root/.../objects`), which gets written verbatim into the repository's alternates file. This is analogous to the reported bug class: a "guarded" operation (`FetchIntoObjectPool`, which enforces same-storage) and an "unguarded" twin (`LinkRepositoryToObjectPool`) that performs a structurally identical, security-relevant action but omits the check the other path considers mandatory.

### Impact Explanation
If reachable with mismatched storages, this would let an ordinary caller of `LinkRepositoryToObjectPool` (a Rails-driven RPC used during fork/object-pool setup) point a repository's `objects/info/alternates` at an object directory living on a completely different storage root. Git treats alternates as a search path for objects, so this can expose objects across storages/tenants (cross-repository object disclosure) and corrupt the pool/member relationship that Gitaly's replication, partitioning, and housekeeping logic assumes always share one storage (as enforced elsewhere, e.g. in `beginTransactionForRepository`'s `ErrRepositoriesInDifferentStorages` check and Praefect's coordinator check for `FetchIntoObjectPool`). [7](#0-6) [8](#0-7) 

### Likelihood Explanation
Likelihood is **uncertain/low-to-moderate** given what is verifiable from the index alone. On a WAL/transaction-enabled Gitaly deployment, the transaction middleware's partitioning logic (`beginTransactionForRepository`) rejects requests whose additional repository is on a different storage before the handler even runs, which would likely block this path in that configuration. It is unclear from the available code whether that middleware check applies uniformly to `LinkRepositoryToObjectPool` in all deployment modes (non-WAL/non-transactional Gitaly, or direct calls that bypass the coordinator), and I could not fully trace whether `LinkRepositoryToObjectPool` is registered as a method with an "additional repository" hint that triggers this middleware guard. This uncertainty should be resolved before treating the finding as confirmed exploitable.

### Recommendation
Add the same storage-equality check used in `validateFetchIntoObjectPoolRequest` to `LinkRepositoryToObjectPool` (and ideally centralize it, e.g. in `poolForRequest` or `objectpool.FromProto`) so that the pool and target repository are required to share `GetStorageName()` before `pool.Link` is invoked, regardless of whether transaction middleware also happens to enforce this in some configurations.

### Proof of Concept
Not independently reproduced from the index; this is based on static code comparison between `LinkRepositoryToObjectPool` (internal/gitaly/service/objectpool/link.go) and `FetchIntoObjectPool`'s explicit same-storage guard (internal/gitaly/service/objectpool/fetch_into_object_pool.go:102-118), plus the fact that `Link`/`FromProto`/`poolForRequest` perform no equivalent check. Full confirmation would require exercising `LinkRepositoryToObjectPool` with a `Repository` and `ObjectPool` on two different configured storages in a running Gitaly instance (with and without WAL/transactions enabled) to determine whether the request is rejected earlier by transaction-routing middleware or actually reaches `pool.Link`.

func (s *server) LinkRepositoryToObjectPool(ctx context.Context, req *gitalypb.LinkRepositoryToObjectPoolRequest) (*gitalypb.LinkRepositoryToObjectPoolResponse, error) {
	repository := req.GetRepository()
	if err := s.locator.ValidateRepository(ctx, repository); err != nil {
		return nil, structerr.NewInvalidArgument("%w", err)
	}

	pool, err := s.poolForRequest(ctx, req)
	if err != nil {
		return nil, err
	}

	repo := s.localRepoFactory.Build(repository)

	if err := pool.Link(ctx, repo); err != nil {
		return nil, structerr.NewInternal("%w", err)
	}

	return &gitalypb.LinkRepositoryToObjectPoolResponse{}, nil
}

func validateFetchIntoObjectPoolRequest(req *gitalypb.FetchIntoObjectPoolRequest) error {
	if req.GetOrigin() == nil {
		return errors.New("origin is empty")
	}

	if req.GetObjectPool() == nil {
		return errors.New("object pool is empty")
	}

	originRepository, poolRepository := req.GetOrigin(), req.GetObjectPool().GetRepository()

	if originRepository.GetStorageName() != poolRepository.GetStorageName() {
		return errors.New("origin has different storage than object pool")
	}

	return nil
}

func getRelativeObjectPath(ctx context.Context, pool, repo *localrepo.Repo) (string, error) {
	poolPath, err := pool.Path(ctx)
	if err != nil {
		return "", fmt.Errorf("getting object pool path: %w", err)
	}

	repoPath, err := repo.Path(ctx)
	if err != nil {
		return "", fmt.Errorf("getting repository path: %w", err)
	}

	relPath, err := filepath.Rel(filepath.Join(repoPath, "objects"), poolPath)
	if err != nil {
		return "", err
	}

	return filepath.Join(relPath, "objects"), nil
}

func FromProto(
	ctx context.Context,
	logger log.Logger,
	locator storage.Locator,
	gitCmdFactory gitcmd.CommandFactory,
	catfileCache catfile.Cache,
	txManager transaction.Manager,
	housekeepingManager housekeepingmgr.Manager,
	proto *gitalypb.ObjectPool,
) (*ObjectPool, error) {
	poolPath, err := locator.GetRepoPath(ctx, proto.GetRepository(), storage.WithRepositoryVerificationSkipped())
	if err != nil {
		return nil, err
	}

	if !storage.IsPoolRepository(proto.GetRepository()) {
		// When creating repositories in the ObjectPool service we will first create the
		// repository in a temporary directory. So we need to check whether the path we see
		// here is in such a temporary directory and let it pass.
		tempDir, err := locator.TempDir(proto.GetRepository().GetStorageName())
		if err != nil {
			return nil, fmt.Errorf("getting temporary storage directory: %w", err)
		}

		if !strings.HasPrefix(poolPath, tempDir) {
			return nil, ErrInvalidPoolDir
		}
	}

	pool := &ObjectPool{
		Repo:                localrepo.New(logger, locator, gitCmdFactory, catfileCache, proto.GetRepository()),
		logger:              logger,
		locator:             locator,
		gitCmdFactory:       gitCmdFactory,
		txManager:           txManager,
		housekeepingManager: housekeepingManager,
	}

	if !pool.IsValid(ctx) {
		return nil, ErrInvalidPoolRepository
	}

	return pool, nil
}

func (s *server) poolForRequest(ctx context.Context, req PoolRequest) (*objectpool.ObjectPool, error) {
	pool, err := objectpool.FromProto(ctx, s.logger, s.locator, s.gitCmdFactory, s.catfileCache, s.txManager, s.housekeepingManager, req.GetObjectPool())
	if err != nil {
		if errors.Is(err, objectpool.ErrInvalidPoolDir) {
			return nil, errInvalidPoolDir
		}

		if errors.Is(err, objectpool.ErrInvalidPoolRepository) {
			return nil, structerr.NewFailedPrecondition("%w", err)
		}

		return nil, structerr.NewInternal("%w", err)
	}

	return pool, nil
}
