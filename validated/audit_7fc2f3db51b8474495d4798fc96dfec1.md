### Title
Missing reward sync before frozen-balance/TRON Power restoration in `CancelAllUnfreezeV2Actuator` allows unfair reward accrual - ([File: actuator/src/main/java/org/tron/core/actuator/CancelAllUnfreezeV2Actuator.java])

### Summary
`CancelAllUnfreezeV2Actuator.execute()` restores an account's frozen balance (bandwidth, energy, and TRON Power) from its pending-unfreeze list without first syncing the account's pending vote/witness rewards via `MortgageService.withdrawReward()`, unlike every other actuator in java-tron that mutates frozen balance / TRON Power.

### Finding Description
Every other actuator that changes an account's frozen balance / TRON Power calls `mortgageService.withdrawReward(ownerAddress)` as the *first* state-mutating step, exactly in order to sync/settle the account's pending reward bookkeeping (`beginCycle`/`endCycle` in `DelegationStore`, and the `accountVote` snapshot) before the weight-affecting change is applied:

- `UnfreezeBalanceActuator.execute()` calls `mortgageService.withdrawReward(ownerAddress)` immediately before touching `accountCapsule`/frozen balance: [1](#0-0) 

- `UnfreezeBalanceV2Actuator.execute()` does the same, calling `withdrawReward` before `unfreezeExpire`, `updateTotalResourceWeight`, and `updateVote`: [2](#0-1) 

However, `CancelAllUnfreezeV2Actuator.execute()` directly restores frozen balances/TRON Power weight (via `updateAndCalculate` → `updateFrozenInfoAndTotalResourceWeight`, which calls `addFrozenBalanceForBandwidthV2` / `addFrozenBalanceForEnergyV2` / `addFrozenForTronPowerV2`) and updates the global total resource weights, **without ever calling `mortgageService.withdrawReward()`**: [3](#0-2) [4](#0-3) 

This mirrors the H-33 root cause exactly: an operation that changes the account's stake-weighted state proceeds without first settling/syncing the reward accounting that depends on that state. In `MortgageService.withdrawReward()`, the "sync" step performs two important things before any subsequent reward computation: (1) it snapshots the account's current vote list into `delegationStore.setAccountVote(endCycle, address, accountCapsule)`, and (2) it advances `beginCycle`/`endCycle` bookkeeping so that a later `computeReward(beginCycle, endCycle, accountCapsule)` call is scoped to the correct cycle window using per-witness `Vi` deltas: [5](#0-4) [6](#0-5) 

Because `CancelAllUnfreezeV2` skips this sync step entirely, the cycle bookkeeping is not closed out at the point where the account's stake weight changes. When the account's reward is finally settled by a later action (`WithdrawBalanceActuator`, `UnfreezeBalanceV2Actuator`, or `VoteWitnessActuator`, all of which call `withdrawReward`), `computeReward` will apply the account's *current* vote count uniformly across the entire unsettled `beginCycle`→`endCycle` span, even though the account's TRON Power/stake was different (lower, since balance was still pending unfreeze) for part of that span before `CancelAllUnfreezeV2` silently restored it.

### Impact Explanation
This causes incorrect ("unfair") reward accrual for the affected account and, since witness/voter reward math is a shared pool (`delegationStore.addReward`/`getReward` per cycle, per witness), it can also affect the reward computed for other voters of the same witness, because reward share is computed as `userVote/totalVote * totalReward`. A user can strategically call `CancelAllUnfreezeV2` to restore stake weight right before triggering `withdrawReward`, inflating the reward attributed to cycles during which their real voting weight was lower. This is a fund-accounting correctness bug directly reachable by any account holder via a standard, unprivileged `CancelAllUnfreezeV2Contract` transaction — Medium/High severity per the same class of finding as H-33 (unbacked/incorrect reward accrual, "unfair accrual of rewards").

### Likelihood Explanation
High reachability: any account with a pending V2 unfreeze list can broadcast a `CancelAllUnfreezeV2Contract` transaction (validated only by `dynamicStore.supportAllowCancelAllUnfreezeV2()` and having a non-empty unfreeze list — see `validate()`), requiring no special privilege, and combine it with any subsequent reward-withdrawing action. [7](#0-6) 

### Recommendation
Add `mortgageService.withdrawReward(ownerAddress)` as the first operation in `CancelAllUnfreezeV2Actuator.execute()`, before any frozen-balance/TRON Power restoration, mirroring `UnfreezeBalanceActuator` and `UnfreezeBalanceV2Actuator`, so that pending rewards are settled against the account's stake weight prior to the change.

### Proof of Concept
1. Account `A` freezes TRX (V2) and votes for witness `W`.
2. `A` calls `UnfreezeBalanceV2` for some amount, reducing `A`'s frozen balance/TRON Power (and this correctly calls `withdrawReward` first, settling rewards up to the current cycle).
3. Several cycles pass while `A`'s unfreeze request is pending (lower TRON Power / effectively reduced weight relative to what `A` had before), accruing witness rewards for `W` in `DelegationStore` each cycle.
4. `A` calls `CancelAllUnfreezeV2` to cancel the still-pending unfreeze request and restore the original frozen balance / TRON Power — this executes `updateFrozenInfoAndTotalResourceWeight` and updates account balance/weight directly, with **no** call to `mortgageService.withdrawReward()`.
5. `A` then calls `WithdrawBalance` (or any action that triggers `withdrawReward`). `MortgageService.computeReward()` computes reward for the entire unsettled `beginCycle`→`endCycle` window using `A`'s *current* (now fully restored) vote count against the accumulated `Vi` deltas, rather than the actually-reduced weight that existed during the intermediate cycles — resulting in a reward larger than `A` should be entitled to for that period, at the expense of the shared reward pool for witness `W`'s other voters.

    byte[] ownerAddress;

      ownerAddress = getOwnerAddress().toByteArray();

      logger.debug(e.getMessage(), e);

      throw new ContractExeException(e.getMessage());

    AtomicLong atomicWithdrawExpireBalance = new AtomicLong(0L);

    right representing the pair object corresponding to tron power. The pair object for each

    resources for that resource type. */

        triple = Triple.of(

        Pair.of(new AtomicLong(0L), new AtomicLong(0L)));

    addTotalResourceWeight(dynamicStore, triple);

    cancelUnfreezeV2AmountMap.put(BANDWIDTH.name(), triple.getLeft().getRight().get());

    cancelUnfreezeV2AmountMap.put(TRON_POWER.name(), triple.getRight().getRight().get());
    ret.putAllCancelUnfreezeV2AmountMap(cancelUnfreezeV2AmountMap);
    ret.setStatus(fee, code.SUCESS);

  public void withdrawReward(byte[] address) {
    if (!dynamicPropertiesStore.allowChangeDelegation()) {
      return;
    }
    AccountCapsule accountCapsule = accountStore.get(address);
    long beginCycle = delegationStore.getBeginCycle(address);
    long endCycle = delegationStore.getEndCycle(address);
    long currentCycle = dynamicPropertiesStore.getCurrentCycleNumber();
    long reward = 0;
    if (beginCycle > currentCycle || accountCapsule == null) {
      return;
    }
    if (beginCycle == currentCycle) {
      AccountCapsule account = delegationStore.getAccountVote(beginCycle, address);
      if (account != null) {
        return;
      }
    }
    //withdraw the latest cycle reward
    if (beginCycle + 1 == endCycle && beginCycle < currentCycle) {
      AccountCapsule account = delegationStore.getAccountVote(beginCycle, address);
      if (account != null) {
        reward = computeReward(beginCycle, endCycle, account);
        adjustAllowance(address, reward);
        reward = 0;
        logger.info("Latest cycle reward {}, {}.", beginCycle, account.getVotesList());
      }
      beginCycle += 1;
    }
    //
    endCycle = currentCycle;
    if (CollectionUtils.isEmpty(accountCapsule.getVotesList())) {
      delegationStore.setBeginCycle(address, endCycle + 1);
      return;
    }
    if (beginCycle < endCycle) {
      reward += computeReward(beginCycle, endCycle, accountCapsule);
      adjustAllowance(address, reward);
    }
    delegationStore.setBeginCycle(address, endCycle);
    delegationStore.setEndCycle(address, endCycle + 1);
    delegationStore.setAccountVote(endCycle, address, accountCapsule);
    logger.info("Adjust {} allowance {}, now currentCycle {}, beginCycle {}, endCycle {}, "
            + "account vote {}.", Hex.toHexString(address), reward, currentCycle,
        beginCycle, endCycle, accountCapsule.getVotesList());
  }

  private long computeReward(long beginCycle, long endCycle, AccountCapsule accountCapsule) {
    if (beginCycle >= endCycle) {
      return 0;
    }

    long reward = 0;
    long newAlgorithmCycle = dynamicPropertiesStore.getNewRewardAlgorithmEffectiveCycle();
    List<Pair<byte[], Long>> srAddresses = accountCapsule.getVotesList().stream()
        .map(vote -> new Pair<>(vote.getVoteAddress().toByteArray(), vote.getVoteCount()))
        .collect(Collectors.toList());
    if (beginCycle < newAlgorithmCycle) {
      long oldEndCycle = min(endCycle, newAlgorithmCycle,
          dynamicPropertiesStore.disableJavaLangMath());
      reward = getOldReward(beginCycle, oldEndCycle, srAddresses);
      beginCycle = oldEndCycle;
    }
    if (beginCycle < endCycle) {
      for (Pair<byte[], Long>  vote : srAddresses) {
        byte[] srAddress = vote.getKey();
        BigInteger beginVi = delegationStore.getWitnessVi(beginCycle - 1, srAddress);
        BigInteger endVi = delegationStore.getWitnessVi(endCycle - 1, srAddress);
        BigInteger deltaVi = endVi.subtract(beginVi);
        if (deltaVi.signum() <= 0) {
          continue;
        }
        long userVote = vote.getValue();
        reward += deltaVi.multiply(BigInteger.valueOf(userVote))
            .divide(DelegationStore.DECIMAL_OF_VI_REWARD).longValue();
      }
    }
    return reward;
  }
