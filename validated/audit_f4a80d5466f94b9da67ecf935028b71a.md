### Title
Unauthenticated `RecvError` packet with spoofed source address triggers forced tunnel teardown (DoS) - ([File: outside.go])

### Summary
`Interface.handleRecvError` tears down a live tunnel (`f.closeTunnel(hostinfo)` and `f.handshakeManager.DeleteHostInfo(hostinfo)`) based solely on an unauthenticated `header.RecvError` packet whose only "authentication" is that the claimed source `netip.AddrPort` matches the hostinfo's currently known remote address. Since UDP source addresses are trivially spoofable and the check does not rely on any cryptographic proof (e.g. MAC, sequence number, or session key), an attacker who knows/guesses a victim's live `RemoteIndex` and can spoof packets with source address equal to the real peer's remote endpoint can force session teardown.

### Finding Description
The reachable path is: attacker-sent UDP packet with `h.Type == header.RecvError` -> `readOutsidePackets` dispatches directly to `f.handleRecvError(via.UdpAddr, h)` [1](#0-0)  -> `handleRecvError` looks up the hostinfo via `f.hostMap.QueryReverseIndex(h.RemoteIndex)`, checks only that `hr.IsValid() && hr != addr` (i.e., the spoofable source address matches the currently known remote), and then unconditionally calls `f.closeTunnel(hostinfo)` and `f.handshakeManager.DeleteHostInfo(hostinfo)` [2](#0-1) . There is no cryptographic verification of the `RecvError` packet body — the header carries only the plaintext `RemoteIndex`, with no MAC or handshake-derived authentication tag. `closeTunnel` immediately deletes hostmap state via `f.hostMap.DeleteHostInfo(hostInfo)` [3](#0-2) . This matches the "outside packet type=RecvError -> handleRecvError -> hostMap.QueryReverseIndex -> compare hr==addr -> closeTunnel/DeleteHostInfo" call chain in the question. Additionally, note the RecvError code is gated by `f.acceptRecvErrorConfig.ShouldRecvError(addr)` [4](#0-3) , which is a rate/acceptance policy but not a cryptographic authentication check, so it does not prevent spoofing once the attacker's rate is within policy.

### Impact Explanation
Once triggered, the tunnel's hostinfo entry is deleted from both the main hostmap and the pending handshake manager, forcing the two legitimate peers to re-run a full Noise handshake before traffic can resume. This is a remote, unauthenticated denial-of-service against an active tunnel: repeated spoofed `RecvError` packets can indefinitely prevent two nodes from maintaining a stable session, and each forced re-handshake resets the AEAD nonce/counter state for a fresh session (new `ConnectionState`), so no counter is reused across sessions — but availability is still degraded/exploitable as DoS.

### Likelihood Explanation
The exploit requires the attacker to know a live `RemoteIndex` for a target tunnel and to be able to spoof UDP packets appearing to originate from the real remote endpoint address of that tunnel (source-address spoofing over UDP is generally feasible on unauthenticated/less-restrictive networks, though it can be mitigated by network-level ingress/anti-spoofing filtering, which is outside Nebula's control). `RemoteIndex` values are 32-bit and not secret—they can potentially be observed on-path or guessed/brute-forced in some deployments, but doing so blindly over the internet has non-trivial cost (brute force across the whole 32-bit space per victim, absent additional information leakage). This is a known, previously-discussed design trade-off in Nebula (the `RecvError` optimization message), and its acceptance is configurable via `accept_recv_error`/`send_recv_error` settings, which can be disabled to fully eliminate this attack surface.

### Recommendation
Do not allow an unauthenticated packet to mutate hostmap/session state. Options: (1) disable/deprecate `RecvError` handling by default, requiring an explicit opt-in with a warning about its trust model; (2) require the `RecvError` packet to be authenticated (e.g., encrypted/MAC'd with the session key or a truncated AEAD tag over the header) so only a peer possessing session key material can trigger teardown; (3) at minimum, treat `RecvError` as an advisory-only signal (e.g., trigger a lightweight re-handshake probe/handshake retry) rather than immediate `DeleteHostInfo`/`closeTunnel`, requiring corroborating evidence (e.g., subsequent decrypt failures) before destructive state mutation.

### Proof of Concept
Unit/integration test plan:
1. Establish a real tunnel between two `Interface` instances (or mock hostinfo with `ConnectionState` and `GetRemote()` set to a known `netip.AddrPort`).
2. From a separate, unauthenticated sender, craft a `header.H` with `Type = header.RecvError` and `RemoteIndex` set to the victim's known/leaked `RemoteIndex`, encode it with `header.Encode`.
3. Call `f.readOutsidePackets` (or directly `f.handleRecvError`) with `via.UdpAddr` set to the spoofed address equal to `hostinfo.GetRemote()` (simulating IP spoofing) but without any valid session key or MAC.
4. Assert: `f.hostMap.QueryIndex`/`QueryReverseIndex` no longer returns the hostinfo (tunnel destroyed), and `f.handshakeManager.DeleteHostInfo` was invoked — demonstrating unauthenticated state mutation.
5. Follow up with a legitimate handshake from the real peer and confirm a new `ConnectionState`/nonce counters are established (no counter reuse across the new session), but note the intervening service disruption (dropped in-flight packets, handshake re-negotiation delay) as the DoS impact.

	if final {

func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
