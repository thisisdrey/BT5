### Title
Protocol fee bypass on `Nep245`/`Imt` tokens by splitting `TokenDiff` into unit-delta intents - (File: `contracts/defuse/core/src/intents/token_diff.rs`)

### Summary
`TokenDiff::token_fee` waives the protocol fee whenever the per-intent `amount` (i.e. `delta.unsigned_abs()` of a single `TokenDiff`) is `<= 1` for `Nep245`/`Imt` token types. Because `DefuseIntents::execute_intent` executes each `Intent::TokenDiff` in `self.intents` independently and fees are computed per intent rather than on the net delta of the whole batch, an unprivileged signer can split one N-unit negative delta on a fungible `Nep245`/`Imt` token into N separate `TokenDiff` intents of `delta = -1` each, inside a single signed `DefuseIntents` payload, and pay zero fee instead of `protocol_fee.fee_ceil(N)`.

### Finding Description
The binding broken: `sum(fees_collected[token_X])` over the batch should equal `protocol_fee.fee_ceil(N)` for a net `-N` delta on token `X`, but with the split payload it equals `0`.

Code path:
- `Engine::execute_signed_intent` extracts `DefuseIntents` and calls `intents.execute_intent(&signer_id, self, hash)` [1](#0-0) .
- `DefuseIntents::execute_intent` loops over `self.intents` and calls `intent.execute_intent(...)` for each entry independently, with no aggregation across intents [2](#0-1) .
- `TokenDiff::execute_intent` computes `fee = Self::token_fee(token_id, amount, protocol_fee).fee_ceil(amount)` per negative delta *within that single intent* [3](#0-2) .
- `TokenDiff::token_fee` explicitly returns `Pips::ZERO` for `Nep245`/`Imt` types when `amount <= 1` (`amount > 1` guard) [4](#0-3) .

Root cause: the fee-waiver threshold ("do not take fees on NFTs and MTs with `|delta| <= 1`") is evaluated per `TokenDiff` intent, not on the net delta for a token across an entire signed message/batch. `Nep245TokenId` is used not only for genuine NFTs but also to represent wrapped fungible-like balances (e.g. `nep141:ft1.test.near` wrapped as an MT with balances such as 100/200/300 units, as seen in `tests/src/tests/defuse/tokens/nep245/mod.rs`), so the `amount<=1` fee-free carve-out is not restricted to true one-off NFT items.

Exploit: the signer holds `N` units of Nep245/Imt token `X` in `token_balances`. They sign one `MultiPayload` containing a single `DefuseIntents` whose `intents: Vec<Intent>` holds `N` separate `TokenDiff` entries, each `{ diff: { X: -1 } }` (each `TokenDiff` value is itself a `BTreeMap`, so a single `TokenDiff` cannot repeat a key, but nothing prevents repeating the same `token_id` across distinct `TokenDiff` intents in the same message). Each intent independently calls `token_fee(X, 1, fee)` → `Pips::ZERO`, so `fees_collected` is empty for every one of the N intents, and `engine.state.fee_collector()` receives `0` in total for this token, versus `protocol_fee.fee_ceil(N)` had it been submitted as one `TokenDiff` with `delta = -N`.

None of the existing guards (`MultiPayload::verify`, nonce/salt checks, `assert_one_yocto`, invariant checking in `Deltas::finalize`) prevent this: the balance invariant (sum of deltas nets to zero across the whole intent set) is unaffected by fee computation, and per-intent fee logic is evaluated independent of any other intent in the batch.

### Impact Explanation
This is a protocol fee bypass: value that should be credited to `fee_collector` is not, for any `Nep245`/`Imt`-typed token that a signer trades in bulk. The attacker/trader keeps the fee that should have gone to the protocol on every trade involving such tokens, repeatable indefinitely across any account and any Nep245/Imt token, and scales linearly with `N` (the split count), matching the "protocol fees bypassed" Critical category. No third party's funds are stolen and no signature/authorization is bypassed — the signer only avoids paying a fee on their own outgoing balance — but the fee_collector is systematically underpaid relative to specified protocol economics.

### Likelihood Explanation
Preconditions are minimal: the attacker only needs (a) a Nep245/Imt token balance of `N` units in Defuse, (b) the ability to construct and sign one `DefuseIntents` message with `N` `TokenDiff` intents instead of one, and (c) a matching counterparty delta (or `Transfer`) to satisfy the zero-sum invariant, exactly as required for any ordinary `TokenDiff` trade. This costs nothing extra beyond a slightly larger payload/gas, is fully attacker-controlled, and is repeatable on every trade of this token type.

### Recommendation
Compute `Nep245`/`Imt` fee waiver based on the net delta per `token_id` aggregated over the whole `DefuseIntents`/batch (or restrict the `amount<=1` fee-free carve-out to intents representing genuinely non-fungible items, e.g. by tracking per-token supply/fungibility rather than per-intent delta magnitude), so that splitting one delta into many unit-delta `TokenDiff` intents cannot change the total fee owed.

### Proof of Concept
`cargo test` (near-workspaces sandbox), analogous to `tests/src/tests/defuse/intents/token_diff.rs`:
1. Deploy Defuse with non-zero `fee` (e.g. `Pips::ONE_PERCENT`). Deposit an MT (`Nep245TokenId`) token `X` with `N = 100` units to `user`, and a counterparty `solver` with a matching token to trade against, so the batch nets to zero.
2. Case A: sign a single `DefuseIntents` with one `TokenDiff { diff: { X: -100, Y: <closure> } }`. Execute; assert `fee_collector` balance for `X` equals `fee.fee_ceil(100)` (`> 0`).
3. Case B: sign a single `DefuseIntents` with 100 `TokenDiff` intents, each `{ diff: { X: -1, Y: <closure_i> } }` (matched leg-by-leg by the counterparty so the batch still nets to zero). Execute; assert `fee_collector` balance for `X` equals `0`.
4. Assert Case A's fee `!=` Case B's fee (both computed on the same net `-100` delta of `X`), proving the binding `sum(fees_collected) == protocol_fee.fee_ceil(N)` is violated for the split payload.
