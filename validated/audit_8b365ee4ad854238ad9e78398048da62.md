### Title
`Pool.liquidate` abandons underwater positions with residual debt and zero collateral, leaving unbacked synthetic supply that becomes a permanent, unsocialized shortfall — (File: contracts/Pool.sol)

### Summary
When a position is liquidated while its collateral value is below its debt (collateral:debt < 1), `Pool.liquidate` caps the seizure at the account's entire `DepositToken` balance via `quoteLiquidateMax` / the `AmountIsTooHigh` check, but burns only the debt corresponding to the seized collateral. The leftover `DebtToken` balance remains against an account with ~0 collateral and no incentive for anyone — the owner included — to repay it. The corresponding `SyntheticToken` supply stays in circulation unbacked, breaking the protocol's core solvency invariant (every synth is backed by collateral), so the loss is silently absorbed by the last synth holders / swap counterparties rather than socialized.

### Finding Description
In `Pool.liquidate`, the liquidator repays `amountToRepay_` of a synthetic token and seizes oracle-priced collateral plus incentive/fee via `quoteLiquidateOut`. Two bounds constrain it:

- `amountToRepay_.wadDiv(_debtTokenBalance) > maxLiquidable` reverts (`AmountGreaterThanMaxLiquidable`).
- `if (_totalSeized > depositToken_.balanceOf(account_)) revert AmountIsTooHigh()` — the seizure is strictly bounded by the account's deposit token balance. [1](#0-0) 

`quoteLiquidateMax` explicitly helps the liquidator take the full collateral by computing the repay amount from `depositToken_.balanceOf(account_)` when the position is underwater: [2](#0-1) 

The project's own tests confirm the end state: after a max liquidation of an underwater position, `depositToken` balance is ~0, `debtToken.balanceOf(account) > 0`, and `_isHealthy` stays false — the account is abandoned bad debt (test asserts `expect(await msEthDebtToken.balanceOf(alice.address)).gt(0)` with deposit ≈ 0). [3](#0-2) 

Unlike Perennial, where negative collateral is tracked, Metronome simply stops at 0 collateral with positive debt. There is no insurance fund call, no bad-debt write-off, and no socialization hook: `seize` only transfers existing shares, `DebtToken.burn` only destroys debt equal to the repayment, and `SyntheticToken.burn` only burns the liquidator's synths. The residual debt corresponds to synths already sold/swapped to third parties — those tokens have no collateral backing them.

### Impact Explanation
Protocol insolvency. Every unit of residual `DebtToken` balance on an emptied account represents `SyntheticToken` supply backed by nothing. The deficit is not booked or socialized, so the protocol's aggregate collateral value is permanently less than the aggregate value of outstanding synths. Users holding the affected synth (acquired via `Pool.swap` or external markets) hold claims that cannot be honored — the last holders absorb the full shortfall. Any sufficiently large underwater event (fast collateral crash, same-transaction oracle/AMM manipulation of a vault-share collateral price before liquidation, or gap liquidation) creates this unbacked supply, and rational actors will race to dump the affected synth, replicating the bank-run dynamic of the reference report.

### Likelihood Explanation
An unprivileged attacker can manufacture bad debt: deposit a volatile collateral (including vault-share collateral priced by `MasterOracle`), mint max issuable synth, drive the collateral price down via AMM trades on the oracle's underlying pool in the same transaction, then let (or perform) a `liquidate` call that seizes all collateral and leaves unpaid debt — while the attacker already swapped the minted synth for other synths. Even without manipulation, ordinary price volatility between oracle updates produces underwater positions, since liquidation depends on a keeper acting before collateral < debt*(1+incentive). No privileged role, governance parameter, or trusted party failure is required; `whenNotShutdown`, `nonReentrant`, and the `AmountIsTooHigh` bound are exactly what guarantees the debt remainder.

### Recommendation
Add an explicit bad-debt path: when `liquidate` would seize the account's entire deposit balance, allow a "full liquidation" that burns all collateral and writes off the residual debt — e.g., burn the remainder `DebtToken` balance and either (a) socialize it by reducing claims on the affected synth (haircut/negative rebase or protocol-level debt pool absorbed across all depositors of that collateral), or (b) fund it from an insurance/treasury buffer (`Treasury`/`feeCollector` accumulated `_fee`). At minimum, surface the shortfall: track `badDebt` per synthetic token and expose it so `swap`/oracle-facing solvency checks and integrators can account for unbacked supply. Setting `maxLiquidable = 1e18`, conservative collateral factors, and `debtFloorInUsd` reduce — but do not eliminate — the occurrence.

### Proof of Concept
Reproducible in the existing Hardhat suite (`test/Pool.test.ts`), extending the "collateral:debt < 1" describe block:

```ts
it('leaves unbacked synth supply after underwater liquidation (bad debt)', async function () {
  // given: alice deposited MET and minted msETH; MET price dropped to $0.50
  // (beforeEach already does masterOracle.updatePrice(met.address, toUSD('0.50')))
  const depositBefore = await msdMET.balanceOf(alice.address)
  const debtBefore = await msEthDebtToken.balanceOf(alice.address)

  // when: liquidator repays the max possible (seizes ~all collateral)
  const amountToRepay = await pool.quoteLiquidateMax(msEth.address, alice.address, msdMET.address)
  await pool.connect(liquidator).liquidate(msEth.address, alice.address, amountToRepay, msdMET.address)

  // then: account abandoned with ~0 collateral but positive debt
  expect(await msdMET.balanceOf(alice.address)).closeTo(BigNumber.from('0'), 6000)
  const residualDebt = await msEthDebtToken.balanceOf(alice.address)
  expect(residualDebt).gt(0)

  // residualDebt worth of msETH remains in circulation with no collateral backing.
  // No function exists to burn/socialize it; syntheticToken.totalSupply > backed supply.
  const unbacked = await masterOracle.quoteTokenToUsd(msEth.address, residualDebt)
  expect(unbacked).gt(0)
})
```

On a mainnet fork, the same flow applies: attacker deposits collateral, mints to the issuance limit, waits for (or induces) a price drop below the liquidation threshold plus incentive, calls `liquidate` with `quoteLiquidateMax`, and the protocol is left permanently short.
