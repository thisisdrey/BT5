### Title
Malformed `.ARM.attributes` ELF section causes unrecovered index-out-of-range panic in the Go linker - ([File: src/cmd/link/internal/loadelf/ldelf.go])

### Summary
`parseArmAttributes` in `src/cmd/link/internal/loadelf/ldelf.go` parses the `.ARM.attributes` build-attributes section of an ELF object file being linked, mirroring the exact bug class in CVE-2017-9044 (binutils `print_symbol_for_build_attribute` crashing on a crafted ELF build-attributes section). The Go function performs multiple unchecked length/offset computations on attacker-controlled section bytes, so a crafted ARM object file (`.o`/`.syso`) fed to `go build`/the linker triggers an out-of-bounds slice panic instead of a graceful `FormatError`.

### Finding Description
Attacker input is a crafted ELF relocatable object file (e.g., a `.syso` file or a cgo/archive-supplied `.o`) containing a `SHT_ARM_ATTRIBUTES`/`.ARM.attributes` section with corrupted lengths. This file flows into `cmd/link`'s `loadelf.Load` [1](#0-0) , which calls `parseArmAttributes(e, sect.base[:sect.size])` on the raw section bytes.

Inside `parseArmAttributes`, several fields read directly from attacker data are used as slice bounds without validating they fit within the remaining buffer:
- `sectionlength := e.Uint32(data)` then `sectiondata := data[4:sectionlength]` and `data = data[sectionlength:]` — no check that `sectionlength >= 4` or `sectionlength <= len(data)`.
- Inside the sub-section loop, `subsectionsize := e.Uint32(sectiondata[sz:])` then `subsectiondata := sectiondata[sz+4 : subsectionsize]` and `sectiondata = sectiondata[subsectionsize:]` — again no bounds validation. [2](#0-1) 

Any of these can panic with "slice bounds out of range" when `sectionlength`/`subsectionsize` is smaller than the consumed header size or larger than the remaining buffer — the same invalid-read/crash primitive as the binutils CVE, just manifesting as a Go runtime panic in the linker rather than a SEGV in `readelf`.

### Impact Explanation
This causes the Go toolchain (`go build`/`cmd/link`) to crash with an unrecovered panic when linking a package that supplies a malicious ARM object file (a `.syso` file checked into a module, or an object referenced via cgo/archive linking). This is a build-time denial of service for any developer who builds such a module for `GOARCH=arm`. Under Go's security triage this class of "malicious input parser panic causing DoS during build/link of untrusted source" is a plausible **PUBLIC** track candidate — it doesn't grant code execution or ASLR/`go build`-runs-malicious-code violations (the build itself isn't executing attacker code, just crashing on a malformed file), matching Go's stated policy that a panic on malformed input can qualify.

### Likelihood Explanation
Victim workflow: `go build`/`go get` + build for `GOARCH=arm` of a module containing (or importing a package that contains) a `.syso` file or externally-linked `.o`/`.a` with a corrupted `.ARM.attributes` section. Attacker capability required is only the ability to publish an ordinary Go module/package with a crafted binary blob — no privileged position needed, matching the report's "ordinary/published module consumed by a normal victim workflow" premise.

### Recommendation
Add explicit bounds checks before every slice operation in `parseArmAttributes`: validate `len(data) >= 4` before reading `sectionlength`, validate `4 <= sectionlength <= len(data)` before slicing `sectiondata`/`data`, and validate `sz+4 <= len(sectiondata)` and `sz+4 <= subsectionsize <= len(sectiondata)` before slicing `subsectiondata`/advancing `sectiondata`. Return a descriptive `error` (as the function already does for other malformed cases) instead of allowing a runtime panic, consistent with how `src/debug/elf/file.go` validates section/segment sizes (`FormatError`) elsewhere in the standard library.

### Proof of Concept
Because `parseArmAttributes` is in an internal package (`cmd/link/internal/loadelf`), the most direct external repro is via the linker itself, but a minimal internal unit test demonstrates the panic directly:

```go
package loadelf

import "encoding/binary"
import "testing"

func TestParseArmAttributes_MalformedSectionLength_Panics(t *testing.T) {
	defer func() {
		if r := recover(); r == nil {
			t.Fatal("expected panic/slice-bounds-out-of-range due to unchecked sectionlength, got none")
		}
	}()

	// 'A' marker, then a bogus 4-byte little-endian section length (1)
	// that is smaller than the 4 bytes just consumed, forcing
	// data[4:sectionlength] to slice with a negative/invalid range.
	data := []byte{'A', 0x01, 0x00, 0x00, 0x00}

	_, _, _ = parseArmAttributes(binary.LittleEndian, data)
}
```

Expected result: with the current code, `sectiondata := data[4:sectionlength]` (here `data[4:1]`) triggers `panic: runtime error: slice bounds out of range [4:1]`, confirming the unchecked-length primitive analogous to CVE-2017-9044's crafted-ELF build-attribute crash. After the fix, `parseArmAttributes` should return a non-nil `error` instead of panicking. [3](#0-2)

func parseArmAttributes(e binary.ByteOrder, data []byte) (found bool, ehdrFlags uint32, err error) {
	found = false
	if data[0] != 'A' {
		return false, 0, fmt.Errorf(".ARM.attributes has unexpected format %c\n", data[0])
	}
	data = data[1:]
	for len(data) != 0 {
		sectionlength := e.Uint32(data)
		sectiondata := data[4:sectionlength]
		data = data[sectionlength:]

		nulIndex := bytes.IndexByte(sectiondata, 0)
		if nulIndex < 0 {
			return false, 0, fmt.Errorf("corrupt .ARM.attributes (section name not NUL-terminated)\n")
		}
		name := string(sectiondata[:nulIndex])
		sectiondata = sectiondata[nulIndex+1:]

		if name != "aeabi" {
			continue
		}
		for len(sectiondata) != 0 {
			subsectiontag, sz := binary.Uvarint(sectiondata)
			subsectionsize := e.Uint32(sectiondata[sz:])
			subsectiondata := sectiondata[sz+4 : subsectionsize]
			sectiondata = sectiondata[subsectionsize:]

			if subsectiontag != TagFile {
				continue
			}
			attrList := elfAttributeList{data: subsectiondata}
			for !attrList.done() {
				attr := attrList.armAttr()
				if attr.tag == TagABIVFPArgs && attr.ival == 1 {
					found = true
					ehdrFlags = 0x5000402 // has entry point, Version5 EABI, hard-float ABI
				}
			}
			if attrList.err != nil {
				return false, 0, fmt.Errorf("could not parse .ARM.attributes\n")
			}
		}
	}
	return found, ehdrFlags, nil
}
