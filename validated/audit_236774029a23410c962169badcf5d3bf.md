### Title
`vesting::distribute()` Iterates All Shareholders in a Loop; Any Single Beneficiary Blocking Deposit Reverts the Entire Distribution — (`File: aptos-move/framework/aptos-framework/sources/vesting.move`)

---

### Summary

`vesting::distribute()` distributes unlocked APT to every shareholder in a single atomic loop. It calls `aptos_account::deposit_coins<AptosCoin>` for each recipient. If any one recipient's deposit aborts — which any shareholder/beneficiary can arrange unprivileged by opting out of direct coin transfers after migrating away from the legacy `CoinStore` — the entire transaction reverts and **no shareholder receives their vested APT**.

---

### Finding Description

`vesting::distribute()` withdraws all unlocked stake and then iterates over every shareholder in the vesting pool:

```move
shareholders.for_each_ref(|shareholder| {
    let shareholder = *shareholder;
    let shares = pool_u64::shares(grant_pool, shareholder);
    let amount = pool_u64::shares_to_amount_with_total_coins(...);
    let share_of_coins = coin::extract(&mut coins, amount);
    let recipient_address = get_beneficiary(vesting_contract, shareholder);
    aptos_account::deposit_coins(recipient_address, share_of_coins);  // ← can abort
});
```

`aptos_account::deposit_coins<AptosCoin>` contains the following guard:

```move
if (!coin::is_account_registered<CoinType>(to)) {
    assert!(
        can_receive_direct_coin_transfers(to),
        error::permission_denied(EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS)
    );
    coin::register<CoinType>(&create_signer(to));
};
coin::deposit<CoinType>(to, coins)
```

`coin::is_account_registered<AptosCoin>` checks for the existence of a `CoinStore<AptosCoin>` resource. Post-FA migration, `aptos_account::create_account` only creates a primary fungible store (via `register_apt` → `ensure_primary_fungible_store_exists`), **not** a `CoinStore`. Therefore, for any account created after the FA migration, `is_account_registered<AptosCoin>` returns `false`.

Any account can call `aptos_account::set_allow_direct_coin_transfers(false)` — an unprivileged entry function — to set `allow_arbitrary_coin_transfers = false`. When `deposit_coins` is subsequently called for that address, `can_receive_direct_coin_transfers` returns `false` and the function aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS`.

Because the entire shareholder loop is inside a single atomic transaction, this abort reverts the whole `distribute()` call. The coins extracted from the stake pool are never delivered to any shareholder.

Additionally, `coin::deposit<CoinType>` itself aborts if the recipient's `CoinStore` is frozen (`aborts_if coin_store.frozen`), providing a second abort path if the `CoinStore` exists but is frozen.

`terminate_vesting_contract` also calls `distribute()` internally, so a blocked `distribute()` also prevents contract termination.

---

### Impact Explanation

All shareholders in the vesting contract are blocked from receiving their vested APT. The coins remain locked in the staking pool and cannot be distributed until the blocking condition is resolved. Since `terminate_vesting_contract` calls `distribute()` internally, the admin also cannot terminate the contract. This constitutes a material freeze of vesting balances for all non-blocking shareholders.

---

### Likelihood Explanation

Any shareholder or beneficiary can trigger this with two unprivileged transactions:
1. Migrate APT to fungible store (removing the `CoinStore<AptosCoin>`)
2. Call `set_allow_direct_coin_transfers(false)`

Post-FA migration, newly created accounts already lack a `CoinStore`, so only step 2 is needed. A malicious or uncooperative shareholder can block all other shareholders' distributions indefinitely. The admin can work around it by reassigning the blocking shareholder's beneficiary, but this requires admin responsiveness and does not prevent the initial DoS.

---

### Recommendation

1. Wrap each individual `deposit_coins` call in a try-catch pattern (or use a skip-on-failure approach) so that a single failing deposit does not revert the entire distribution.
2. Alternatively, accumulate unclaimed distributions in a per-shareholder claimable balance that each shareholder withdraws individually, eliminating the shared-loop failure mode entirely.
3. At minimum, add a separate `distribute_to(contract_address, shareholder_address)` entry function that distributes to a single shareholder, allowing other shareholders to receive their funds even when one is blocked.

---

### Proof of Concept

1. Admin creates a vesting contract with shareholders A and B.
2. Shareholder B (or their beneficiary) calls `aptos_account::set_allow_direct_coin_transfers(false)`. If their account was created post-FA migration (no `CoinStore<AptosCoin>`), no further action is needed.
3. Time passes; stake earns rewards; `vest()` is called.
4. Anyone calls `vesting::distribute(contract_address)`.
5. The loop reaches shareholder B's `deposit_coins` call, which aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS`.
6. The entire transaction reverts. Shareholder A receives nothing.
7. Shareholder A cannot call `distribute()` themselves — it will always revert as long as B's blocking condition holds.

    public entry fun set_allow_direct_coin_transfers(
        account: &signer, allow: bool
    ) acquires DirectTransferConfig {
        let addr = signer::address_of(account);
        if (exists<DirectTransferConfig>(addr)) {
            let direct_transfer_config = borrow_global_mut<DirectTransferConfig>(addr);
            // Short-circuit to avoid emitting an event if direct transfer config is not changing.
            if (direct_transfer_config.allow_arbitrary_coin_transfers == allow) { return };

            direct_transfer_config.allow_arbitrary_coin_transfers = allow;

            emit(
                DirectCoinTransferConfigUpdated {
                    account: addr,
                    new_allow_direct_transfers: allow
                }
            );
        } else {
            let direct_transfer_config = DirectTransferConfig {
                allow_arbitrary_coin_transfers: allow,
                update_coin_transfer_events: new_event_handle<
                    DirectCoinTransferConfigUpdatedEvent>(account)
            };
            emit(
                DirectCoinTransferConfigUpdated {
                    account: addr,
                    new_allow_direct_transfers: allow
                }
            );
            move_to(account, direct_transfer_config);
        };
    }
