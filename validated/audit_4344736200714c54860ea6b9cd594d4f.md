### Title
Attacker-controlled `data_url` from an unauthenticated/self-signed Handshake enables SSRF against internal network targets - (File: stackslib/src/net/chat.rs)

### Summary
`ConversationHttp`/`ConversationP2P::update_from_handshake_data` stores the `data_url` field from a peer-supplied `HandshakeData` message verbatim, with no restriction against private/loopback/link-local hosts, unlike the analogous `addrbytes` handling elsewhere in the same walk logic. This URL is later used verbatim to construct and send outbound HTTP requests (e.g., Atlas attachment/attachment-inventory downloads), giving a remote peer control over the destination of the node's outbound HTTP traffic — a classic SSRF pattern, structurally analogous to the Tlon extension flaw (user-controlled base URL used to build an outbound request with no SSRF guard).

### Finding Description
When a `Handshake` message is received, `handle_handshake` calls `update_from_handshake_data`, which unconditionally overwrites the conversation's `data_url` with the value taken from the untrusted `HandshakeData`: [1](#0-0) 

`validate_handshake` only checks the signature/public key, expiry, and (for outbound convos with an existing pubkey) that `addrbytes`/`port` match — it never inspects or restricts `data_url`: [2](#0-1) 

The `HandshakeData` wire format enforces only that the port is non-zero and that the URL string passes `UrlString`'s regex/length checks and `parse_to_block_url()` (valid `http`/`https` scheme, no query/fragment/userinfo). `parse_to_block_url()` explicitly accepts loopback/private IP literals such as `http://127.0.0.1:1234/...`, as shown in the project's own unit test: [3](#0-2) [4](#0-3) 

`UrlString::has_routable_host()` only rejects `0.0.0.0`/`::` — it does not treat RFC1918/loopback ranges as unroutable: [5](#0-4) 

Contrast this with the peer-address handling in the neighbor-walk state machine, which explicitly guards against a peer supplying a private IP address for `addrbytes`: [6](#0-5) 

and with the StackerDB smart-contract-supplied `hint-replicas`, which explicitly filters out private-range addresses before they can be used as replica targets: [7](#0-6) 

No equivalent filter exists for the p2p handshake `data_url`. Once stored, `data_url` is resolved to an IP (directly, if it's a literal IP, via `try_decode_data_url_ipaddr`, bypassing DNS) and is exposed through `PeerNetwork::get_data_url`/`get_outbound_sync_peers`, which is precisely what the Atlas attachment downloader uses to pick peer URLs and issue outbound HTTP GET requests (`/v2/attachments/inv`, `/v2/attachments/<hash>`): [8](#0-7) [9](#0-8) [10](#0-9) 

The request is then actually dispatched to the resolved socket address via `connect_or_send_http_request`, which connects directly to whatever `SocketAddr` was resolved for the attacker-chosen host/IP: [11](#0-10) [12](#0-11) 

Because `validate_handshake` performs no address/host check on `data_url` for either inbound or outbound conversations, and because a handshake can be sent by any peer that can open a p2p connection (no StackerDB/mining/admin privilege is required, only a valid, non-expired self-consistent key signature over the message it itself supplies), a remote, unprivileged peer can steer the node's own Atlas attachment/inventory download requests to arbitrary internal hosts and ports (e.g., loopback services, internal RPC ports, or metadata endpoints reachable from the node's network namespace).

### Impact Explanation
This breaks the "served-URL-must-be-attacker's-own-node vs.-arbitrary-internal-target" boundary: the node is induced into making outbound HTTP requests to a location entirely dictated by an untrusted counterparty. This matches the "Critical" tier's "unauthenticated ... network-wide propagation of forged data" bucket's sibling risk, and functionally maps to the CWE-918 SSRF class from the reference report — an unprivileged remote actor can cause the target node to issue crafted HTTP GET requests toward internal/loopback addresses, which can be used to probe internal services, hit unauthenticated internal RPC endpoints, or interact with metadata services in cloud deployments. It does not itself corrupt consensus-relevant state, but it is a direct violation of the "served/committed" trust boundary for outbound network actions initiated on behalf of the operator, triggered purely by unauthenticated protocol data.

### Likelihood Explanation
High. The attack requires only establishing a normal p2p handshake (inbound or outbound) with the target node and controlling the `data_url` field, both of which are entirely attacker-controlled and require no elevated privilege, valid StackerDB slot, or block-producing role. `data_url` only needs to pass `UrlString`'s syntactic checks, which explicitly permit loopback/private literal IPs. The Atlas subsystem periodically enumerates `get_outbound_sync_peers()`/`get_data_url()` for its download machinery, so exploitation does not require any additional attacker action beyond waiting for the node's normal attachment-sync cycle.

### Recommendation
Add an SSRF guard analogous to the one already used for StackerDB `hint-replicas` and neighbor-walk `addrbytes`: reject or ignore `data_url` values whose resolved host is in a private/loopback/link-local/multicast range (and ideally re-validate at DNS-resolution time to avoid DNS-rebinding to different destinations after the initial check), unless an explicit opt-in configuration flag is set (mirroring `channels.tlon.allowPrivateNetwork` in the referenced fix). This check should occur in `validate_handshake`/`update_from_handshake_data` in `stackslib/src/net/chat.rs`, and ideally also be enforced at the point `data_url` is resolved to an IP in `try_decode_data_url_ipaddr`/DNS lookup completion.

### Proof of Concept
1. Stand up a malicious Stacks node/peer with a valid keypair.
2. Perform a normal p2p handshake against the target node, but in the `HandshakeData` payload set `data_url` to `http://127.0.0.1:<internal-port>/` (or another private/loopback address reachable from the target node's network namespace) — this passes `parse_to_block_url()` validation since scheme/host/format are all otherwise well-formed.
3. The target's `update_from_handshake_data` stores this URL as the neighbor's `data_url` without any private-range check.
4. Ensure the malicious peer's `PeerAddress` is treated as a candidate for `get_outbound_sync_peers()` (e.g., via an Atlas-eligible connection) so that its `data_url` participates in `AttachmentsDownloader::run`'s peer selection.
5. Observe the target node issue outbound HTTP GET requests to the attacker-chosen internal `data_url` (e.g., `/v2/attachments/inv?...`) as part of its normal Atlas sync cycle, confirming SSRF against the attacker-specified internal target.

    fn validate_handshake(
        &mut self,
        local_peer: &LocalPeer,
        chain_view: &BurnchainView,
        message: &mut StacksMessage,
    ) -> Result<(), net_error> {
        let handshake_data = match message.payload {
            StacksMessageType::Handshake(ref mut data) => data.clone(),
            _ => panic!("Message is not a handshake"),
        };

        match self.connection.get_public_key() {
            None => {
                // if we don't yet have a public key for this node, verify the message.
                // if it's improperly signed, it's probably a poorly-timed re-key request (but either way the message should be rejected)
                message
                    .verify_secp256k1(&handshake_data.node_public_key)
                    .map_err(|_e| {
                        debug!(
                            "{:?}: invalid handshake: not signed with given public key",
                            &self
                        );
                        net_error::InvalidMessage
                    })?;
            }
            Some(_) => {
                // for outbound connections, the self-reported address must match socket address if we already have a public key.
                // (not the case for inbound connections, since the peer socket address we see may
                // not be the same as the address the remote peer thinks it has).
                // The only exception to this is if the remote peer does not yet know its own
                // public IP address, in which case, its handshake addrbytes will be the
                // any-network bind address (0.0.0.0 or ::)
                if self.stats.outbound
                    && (!handshake_data.addrbytes.is_anynet()
                        && (self.peer_addrbytes != handshake_data.addrbytes
                            || self.peer_port != handshake_data.port))
                {
                    // wrong peer address
                    debug!(
                        "{:?}: invalid handshake -- wrong addr/port ({:?}:{:?})",
                        &self, &handshake_data.addrbytes, handshake_data.port
                    );
                    return Err(net_error::InvalidHandshake);
                }
            }
        };

        let their_public_key_res = handshake_data.node_public_key.to_public_key();
        match their_public_key_res {
            Ok(_) => {}
            Err(_e) => {
                // bad public key
                debug!("{:?}: invalid handshake -- invalid public key", &self);
                return Err(net_error::InvalidMessage);
            }
        };

        if handshake_data.expire_block_height <= chain_view.burn_block_height {
            // already stale
            debug!(
                "{:?}: invalid handshake -- stale public key (expired at {})",
                &self, handshake_data.expire_block_height
            );
            return Err(net_error::InvalidHandshake);
        }

        // the handshake cannot come from us
        if handshake_data.node_public_key
            == StacksPublicKeyBuffer::from_public_key(&Secp256k1PublicKey::from_private(
                &local_peer.private_key,
            ))
        {
            debug!(
                "{:?}: invalid handshake -- got a handshake from myself",
                &self
            );
            return Err(net_error::InvalidHandshake);
        }

        Ok(())
    }

    pub fn has_routable_host(&self) -> bool {
        let url = match url::Url::parse(&self.to_string()) {
            Ok(x) => x,
            Err(_) => {
                // should be unreachable
                return false;
            }
        };
        match url.host_str() {
            Some(host_str) => {
                if host_str == "0.0.0.0" || host_str == "[::]" || host_str == "::" {
                    return false;
                } else {
                    return true;
                }
            }
            None => {
                return false;
            }
        }
    }

impl StacksMessageCodec for HandshakeData {
    fn consensus_serialize<W: Write>(&self, fd: &mut W) -> Result<(), codec_error> {
        write_next(fd, &self.addrbytes)?;
        write_next(fd, &self.port)?;
        write_next(fd, &self.services)?;
        write_next(fd, &self.node_public_key)?;
        write_next(fd, &self.expire_block_height)?;
        write_next(fd, &self.data_url)?;
        Ok(())
    }

    fn consensus_deserialize<R: Read>(fd: &mut R) -> Result<HandshakeData, codec_error> {
        let addrbytes: PeerAddress = read_next(fd)?;
        let port: u16 = read_next(fd)?;
        if port == 0 {
            return Err(codec_error::DeserializeError(
                "Invalid handshake data: port is 0".to_string(),
            ));
        }

        let services: u16 = read_next(fd)?;
        let node_public_key: StacksPublicKeyBuffer = read_next(fd)?;
        let expire_block_height: u64 = read_next(fd)?;
        let data_url: UrlString = read_next(fd)?;
        Ok(HandshakeData {
            addrbytes,
            port,
            services,
            node_public_key,
            expire_block_height,
            data_url,
        })
    }
}

    ) -> Result<usize, NetError> {
        PeerNetwork::with_network_state(self, |ref mut network, ref mut network_state| {
            PeerNetwork::with_http(network, |ref mut network, ref mut http| {
                match http.connect_http(
                    network_state,
                    network,
                    data_url.clone(),
                    addr,
                    Some(request.clone()),
                ) {
                    Ok(event_id) => Ok(event_id),
                    Err(NetError::AlreadyConnected(event_id, _)) => {
                        if let (Some(ref mut convo), Some(ref mut socket)) =

                            Ok(event_id)

                            Err(NetError::PeerNotConnected(format!(
                                "HTTP failed to connect to {data_url}, {addr:?}",
                            )))
                        }
                    }
                    Err(e) => Err(e),
                }
            })
        })
