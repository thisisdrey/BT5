### Title
Inconsistent EIP-3607 origin enforcement lets a contract's fallback account bypass `pallet-revive` access-control invariant via `remove_code`/`unmap_account` - (File: `substrate/frame/revive/src/lib.rs`)

### Summary
Every other publicly-dispatchable extrinsic in `pallet-revive` that accepts a `Signed` origin calls `Self::ensure_non_contract_if_signed(&origin)` before doing anything else, enforcing the invariant that a contract address (or precompile) can never act as `tx.origin` (EIP-3607). Two dispatchables in the same `#[pallet::call]` block, `remove_code` (call_index 5) and `unmap_account` (call_index 8), omit this check entirely. This mirrors the `OmoAgent.sol` report's core defect: a set of functions is supposed to share one uniform access-control gate, but the gate is applied inconsistently across the sibling entry points, leaving some of them reachable through a path the rest of the module was designed to block.

### Finding Description
`ensure_non_contract_if_signed` is the pallet's single source of truth for the "signed origin must not resolve to a contract/precompile address" invariant: [1](#0-0) 

It is consistently invoked as the very first step of `call`, `instantiate`, `instantiate_with_code`, `eth_instantiate_with_code`, `eth_call`, `eth_substrate_call`, `upload_code`, `map_account`, `batch_map_accounts`, and `dispatch_as_fallback_account`: [2](#0-1) [3](#0-2) [4](#0-3) [5](#0-4) 

But `remove_code`, which is a privileged operation that mutates code refcounts and refunds a deposit, only does `ensure_signed`: [6](#0-5) 

and `unmap_account`, which releases an address-mapping deposit and removes the mapping, likewise only does `ensure_signed`: [7](#0-6) 

The existing regression test `eip3607_reject_tx_from_contract_or_precompile` in `substrate/frame/revive/src/tests/pvm.rs` explicitly enumerates the dispatchables that must reject a fallback-account origin derived from a contract/precompile address (`call`, `eth_call`, `instantiate`, `eth_instantiate_with_code`, `instantiate_with_code`, `upload_code`, `map_account`, `dispatch_as_fallback_account`, `eth_substrate_call`) — `remove_code` and `unmap_account` are conspicuously absent from that coverage, confirming the gap was never enforced or tested: [8](#0-7) 

The pallet's history shows this invariant has been actively hardened and generalized over time (e.g. PR making EIP-3607 apply only to dispatchables, and PR aligning `eth_substrate_call`'s check with the others), indicating the maintainers treat "every signed dispatchable must call `ensure_non_contract_if_signed`" as a hard, chain-wide rule — yet two call sites in the same file were left out of that rule: [9](#0-8) [10](#0-9) 

### Impact Explanation
`ensure_non_contract_if_signed` exists precisely to stop a signed origin whose mapped `H160` address coincides with a contract/precompile from being treated as a legitimate transaction initiator, since Ethereum-style semantics (and this pallet's own EIP-3607 test suite) assume contracts cannot originate transactions. `remove_code` and `unmap_account` are state-mutating (deposit refund / refcount decrement / mapping removal) and are reachable by exactly the same class of origin the rest of the pallet defends against. Because the check is applied file-wide as a uniform invariant, a caller that is blocked from `call`, `map_account`, `upload_code`, etc. by this guard is *not* blocked from `remove_code` or `unmap_account`, allowing an origin that the pallet's design intends to be non-privileged/blocked to still mutate deposit and mapping state through this asymmetric surface.

### Likelihood Explanation
This is directly triggerable by any account without needing a validator, relayer, governance, or admin role — it only requires constructing a normal signed extrinsic against `remove_code` or `unmap_account` using an origin the pallet elsewhere refuses. It requires no malicious peer/node assumption and no privileged actor, matching the review's "unprivileged attacker, public entry point" criteria. The exact conditions under which an attacker can obtain a signed `AccountId` whose mapped address collides with a contract/precompile (via the fallback-account derivation mechanism exercised in `eip3607_reject_tx_from_contract_or_precompile`) were not fully re-derived in this pass, so likelihood should be validated against `AddressMapper`'s mapping/fallback-derivation logic (`substrate/frame/revive/src/address.rs`) before treating this as fully weaponized; what is certain from the code is that the access-control gate is inconsistently applied across sibling dispatchables in the same module.

### Recommendation
Add `Self::ensure_non_contract_if_signed(&origin)` as the first statement in both `remove_code` and `unmap_account`, mirroring every other signed dispatchable in the `#[pallet::call]` block, and extend the `eip3607_reject_tx_from_contract_or_precompile` test to cover both functions so the invariant is enforced uniformly and regression-tested.

### Proof of Concept
1. Derive/obtain a signed `AccountId` `origin` whose `AddressMapper::to_address(&origin)` resolves to an address recognized as a contract or precompile (same technique used by `eip3607_reject_tx_from_contract_or_precompile` via `to_fallback_account_id`, tested in `substrate/frame/revive/src/tests/pvm.rs:5182-5252`).
2. Call `Pallet::<Test>::call(origin.clone(), ...)`, `map_account(origin.clone())`, or `upload_code(origin.clone(), ...)` — all correctly return `DispatchError::BadOrigin` due to `ensure_non_contract_if_signed`.
3. Call `Pallet::<Test>::remove_code(origin.clone(), code_hash)` or `Pallet::<Test>::unmap_account(origin.clone())` with the same origin — these succeed (subject only to `ensure_signed` and the underlying storage checks), demonstrating that the same origin blocked everywhere else in the pallet is not blocked here. 	/// Ensure that the origin is neither a pre-compile nor a contract.
	///
	/// This enforces EIP-3607.
	fn ensure_non_contract_if_signed(origin: &OriginFor<T>) -> DispatchResult {
		if DebugSettings::bypass_eip_3607::<T>() {
			return Ok(());
		}
		let Some(address) = origin
			.as_system_ref()
			.and_then(|o| o.as_signed())
			.map(<T::AddressMapper as AddressMapper<T>>::to_address)
		else {
			return Ok(());
		};
		if exec::is_precompile::<T, ContractBlob<T>>(&address) ||
			<AccountInfo<T>>::is_contract(&address)
		{
			log::debug!(
				target: crate::LOG_TARGET,
				"EIP-3607: reject tx as pre-compile or account exist at {address:?}",
			);
			Err(DispatchError::BadOrigin)
		} else {
			Ok(())
		}
	}

#[test]
fn eip3607_reject_tx_from_contract_or_precompile() {
	let (binary, _code_hash) = compile_module("dummy").unwrap();

	ExtBuilder::default().existential_deposit(200).build().execute_with(|| {
		let _ = <Test as Config>::Currency::set_balance(&ALICE, 1_000_000);

		// the origins from which we try to call a dispatchable
		let Contract { addr: contract_addr, .. } =
			builder::bare_instantiate(Code::Upload(binary)).build_and_unwrap_contract();
		assert!(<AccountInfo<Test>>::is_contract(&contract_addr));
		let blake2_addr = H160::from_low_u64_be(9);
		let system_addr = H160::from_low_u64_be(0x900);
		let addresses = [contract_addr, blake2_addr, system_addr];

		// used to test `dispatch_as_fallback_account`
		let call = Box::new(RuntimeCall::Balances(pallet_balances::Call::transfer_all {
			dest: EVE,
			keep_alive: false,
		}));

		for address in addresses.iter() {
			let origin = <Test as Config>::AddressMapper::to_fallback_account_id(address);

			let result =
				builder::call(BOB_ADDR).origin(RuntimeOrigin::signed(origin.clone())).build();
			assert_err!(result, DispatchError::BadOrigin);

			let result = builder::eth_call(BOB_ADDR)
				.origin(Origin::EthTransaction(origin.clone()).into())
				.build();
			assert_err!(result, DispatchError::BadOrigin);

			let result = builder::instantiate(Default::default())
				.origin(RuntimeOrigin::signed(origin.clone()))
				.build();
			assert_err!(result, DispatchError::BadOrigin);

			let result = builder::eth_instantiate_with_code(Default::default())
				.origin(Origin::EthTransaction(origin.clone()).into())
				.build();
			assert_err!(result, DispatchError::BadOrigin);

			let result = builder::instantiate_with_code(Default::default())
				.origin(RuntimeOrigin::signed(origin.clone()))
				.build();
			assert_err!(result, DispatchError::BadOrigin);

			let result = <Pallet<Test>>::upload_code(
				RuntimeOrigin::signed(origin.clone()),
				Default::default(),
				<BalanceOf<Test>>::MAX,

			let result = <Pallet<Test>>::dispatch_as_fallback_account(

    The EIP states that contract addresses cannot be the origin of a transaction. However, we are enforcing this rule for all contract execution (i.e all public function on the pallet). This is a problem for code that uses `pallet_revive` and explicitly wants to allow this.

    This PR now only enforces this check for dispatchables so that all the `bare_*` functions are unaffected.
