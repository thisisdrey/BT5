Audit Report

## Title
Relayer reward paid regardless of on-chain execution outcome (`success` field ignored in `process_delivery_receipt`) - (File: `bridges/snowbridge/pallets/outbound-queue-v2/src/lib.rs`)

## Summary
`DeliveryReceipt::try_from` decodes the Ethereum `InboundMessageDispatched(nonce, topic, bool success, reward_address)` event and correctly extracts the `success` boolean flag indicating whether the message actually executed successfully on the Ethereum Gateway contract. However, `Pallet::process_delivery_receipt`, invoked by the public `submit_delivery_receipt` extrinsic, never reads or branches on `receipt.success` before paying the relayer reward and removing the pending order.

## Finding Description
The public extrinsic `submit_delivery_receipt` verifies the Merkle/log proof via `T::Verifier::verify`, decodes the log into a `DeliveryReceipt` (which includes `success: bool`), and immediately calls `Self::process_delivery_receipt(relayer, receipt)`: [1](#0-0) 

Inside `process_delivery_receipt`, the only checks performed are that the gateway address matches (`T::GatewayAddress::get() == receipt.gateway`) and that a `PendingOrder` exists for `receipt.nonce`. If `order.fee > 0`, the relayer reward is unconditionally registered via `T::RewardPayment::register_reward`, and the pending order is removed — with `receipt.success` never inspected: [2](#0-1) 

The `DeliveryReceipt` struct itself carries the `success` field decoded directly from the Ethereum event, confirming the information is available but simply unused: [3](#0-2) 

This breaks the invariant that payout/settlement state must only advance after execution actually succeeds — here, decode-and-proof-verify of a genuine log is treated as sufficient for reward settlement even when the log itself states `success = false`.

## Impact Explanation
Any unprivileged relayer can submit a genuine, correctly proven Ethereum event log for a message whose `InboundMessageDispatched` event reports `success: false` (e.g., due to a revert or gas exhaustion in the downstream Gateway contract dispatch) and still receive the full `order.fee` reward as though delivery succeeded. This is an unbacked payout from the bridge reward pot — value is paid for work that did not complete — matching the "theft or unbacked mint" / "duplicate settlement or payout" impact class for bridge-state/reward correctness.

## Likelihood Explanation
No malicious peer, validator, or admin action is required. Any relayer running the normal relaying flow can trigger this merely by submitting a legitimate failure event that already exists on Ethereum (execution failures are a normal, expected occurrence, e.g., gas exhaustion or revert in the Gateway's dispatch call). Since `success` is already decoded and present in the struct but simply unchecked at the payout site, this is a straightforward missing-branch defect rather than a complex exploit chain, making it readily and repeatably triggerable in ordinary operation.

## Recommendation
In `process_delivery_receipt`, branch on `receipt.success`: only call `T::RewardPayment::register_reward` when `receipt.success == true`. When `success == false`, still resolve/remove the `PendingOrder` (or mark it failed) but skip the reward payment, and emit a distinct event (e.g., `MessageDeliveryFailed`) so downstream systems can react appropriately (retries, refunds, etc.).

## Proof of Concept
Using `bridges/snowbridge/pallets/outbound-queue-v2/src/test.rs`'s existing harness pattern (as in `poc_m1`): insert a `PendingOrder { nonce, fee: 1_000_000, .. }` into `PendingOrders`, construct a `DeliveryReceipt` with `success: false` for that `nonce`, and call `Pallet::<Test>::process_delivery_receipt(relayer, receipt)` (or `OutboundQueue::submit_delivery_receipt` with a mocked event/proof decoding to that receipt). Assert the call returns `Ok(())`, the relayer's reward balance increases by `order.fee`, and `PendingOrders::<Test>::get(nonce)` becomes `None` — demonstrating the reward is paid and the order is settled despite `success == false`.

		/// Process a delivery receipt from a relayer, to allocate the relayer reward.
		pub fn process_delivery_receipt(
			relayer: <T as frame_system::Config>::AccountId,
			receipt: DeliveryReceipt,
		) -> DispatchResult
		where
			<T as frame_system::Config>::AccountId: From<[u8; 32]>,
		{
			// Verify that the message was submitted from the known Gateway contract
			ensure!(T::GatewayAddress::get() == receipt.gateway, Error::<T>::InvalidGateway);

			let reward_account = if receipt.reward_address == [0u8; 32] {
				relayer
			} else {
				receipt.reward_address.into()
			};

			let nonce = receipt.nonce;

			let order = <PendingOrders<T>>::get(nonce).ok_or(Error::<T>::InvalidPendingNonce)?;

			if order.fee > 0 {
				// Pay relayer reward
				T::RewardPayment::register_reward(
					&reward_account,
					T::DefaultRewardKind::get(),
					order.fee,
				);
			}

			<PendingOrders<T>>::remove(nonce);

			Self::deposit_event(Event::MessageDelivered { nonce });

			Ok(())
		}

/// Delivery receipt
#[derive(Clone, Debug)]
pub struct DeliveryReceipt {
	/// The address of the outbound queue on Ethereum that emitted this message as an event log
	pub gateway: H160,
	/// The nonce of the dispatched message
	pub nonce: u64,
	/// Message topic
	pub topic: H256,
	/// Delivery status
	pub success: bool,
	/// The reward address
	pub reward_address: [u8; 32],
}

#[derive(Copy, Clone, Encode, Decode, Eq, PartialEq, Debug, TypeInfo)]
pub enum DeliveryReceiptDecodeError {
	DecodeLogFailed,
	DecodeAccountFailed,
}

impl TryFrom<&Log> for DeliveryReceipt {
	type Error = DeliveryReceiptDecodeError;

	fn try_from(log: &Log) -> Result<Self, Self::Error> {
		let topics: Vec<B256> = log.topics.iter().map(|x| B256::from_slice(x.as_ref())).collect();

		let event = InboundMessageDispatched::decode_raw_log_validate(topics, &log.data)
			.map_err(|_| DeliveryReceiptDecodeError::DecodeLogFailed)?;

		Ok(Self {
			gateway: log.address,
			nonce: event.nonce,
			topic: H256::from_slice(event.topic.as_ref()),
			success: event.success,
			reward_address: event.reward_address.0,
		})
	}
