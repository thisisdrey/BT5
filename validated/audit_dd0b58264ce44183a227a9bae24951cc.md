## Analysis

The Sherlock finding is about `NFTCollection.sol`'s ownership-transfer function accepting a new owner address without checking it against `address(0)`, so a user error can permanently brick owner-gated functionality until a valid owner is set again.

The closest reachable analog in java-tron is `AccountPermissionUpdateActuator`, which lets **any account owner** (an unprivileged, self-signed transaction, `AccountPermissionUpdateContract`) rewrite the account's `Owner`, `Witness`, and `Active` permissions, including reassigning the set of key addresses that control the account going forward.

### Root cause

In `checkPermission()`, each `Key`'s address is validated only through `DecodeUtil.addressValid()`: [1](#0-0) 

`DecodeUtil.addressValid()` only checks the byte-array length and the network prefix byte — it never checks whether the remaining 20 bytes are non-zero, i.e. it accepts a syntactically well-formed but semantically "null" address (prefix byte + 20 zero bytes) exactly like a Solidity `address(0)`: [2](#0-1) 

Beyond format validity, `validate()` never checks that the new `Owner` permission's key set contains an address anyone can actually control (e.g. an address whose private key exists), nor does it verify the new keys correspond to a real/reachable account: [3](#0-2) 

`execute()` then unconditionally overwrites the account's permissions with whatever passed `validate()`: [4](#0-3) 

### Title
Missing validation that new Owner/Active permission key addresses are non-degenerate ("zero-like") in `AccountPermissionUpdateContract` can permanently lock account control - (File: `actuator/src/main/java/org/tron/core/actuator/AccountPermissionUpdateActuator.java`)

### Summary
`AccountPermissionUpdateActuator.checkPermission()` validates permission key addresses only with `DecodeUtil.addressValid()`, which merely checks address length (21 bytes) and the chain's address prefix byte. It performs no check that the address is an address anyone can actually sign for (e.g. rejecting the degenerate prefix+zero-bytes address), mirroring the reported Solidity pattern of missing "new owner is not `address(0)`" validation.

### Finding Description
Any account holder can submit an `AccountPermissionUpdateContract` to replace their `Owner`, `Witness`, or `Active` permission key sets. `checkPermission()` enforces key count limits, positive weights, distinct addresses, and threshold ≤ weight-sum, but the only per-key address check is `DecodeUtil.addressValid(key.getAddress().toByteArray())`, which is purely a format check (length + prefix byte) and accepts a degenerate address such as prefix-byte + 20 zero bytes. `validate()` never cross-checks that the resulting Owner permission is satisfiable by a key an actual user controls. `execute()` then commits the new permission set via `account.updatePermissions(...)` unconditionally once `validate()` passes.

### Impact Explanation
If a user (through a mistake, a buggy wallet/tool, or a malicious multisig co-signer during a threshold update) sets the Owner permission's controlling key(s) to such a degenerate address with enough weight to meet the threshold, the account permanently loses the ability to sign further `AccountPermissionUpdateContract` transactions with a legitimate key, since no private key exists for the format-only address. This is the same "protocol will misbehave till the valid owner address is assigned" impact called out in the source report, except here it is irreversible because there is no admin/owner overwrite path once Owner permission is bricked — a form of permanent loss of account control equivalent to permanent freezing of funds gated behind that permission.

### Likelihood Explanation
Reachable by any unprivileged, single signed transaction (`AccountPermissionUpdateContract`) from the account owner without any special privilege, matching the "unprivileged transaction broadcaster" reachability bar. Likelihood of triggering is tied to user/tooling error (as in the original report) or a malicious co-signer manipulating a legitimately-permissioned multisig update, rather than a purely external attacker forging someone else's permissions (the actuator still requires the transaction be signed under the account's current permission rules).

### Recommendation
In `checkPermission()`, reject key addresses that are the all-zero-body address (prefix + 20 zero bytes) or otherwise clearly non-derivable from any key pair, in addition to the existing `DecodeUtil.addressValid()` format check, mirroring `newOwner != address(0)` checks recommended for the Solidity analog.

### Proof of Concept
1. Attacker/owner crafts an `AccountPermissionUpdateContract` for `OWNER_ADDRESS` where the `Owner` permission's `Key` list contains only `Key{address = <prefix-byte + 20 zero bytes>, weight = threshold}`.
2. `AccountPermissionUpdateActuator.validate()` calls `checkPermission(owner)`, which passes: `DecodeUtil.addressValid()` returns `true` for this well-formed but unowned address (see `DecodeUtil.java` lines 15-33), weight > 0, and weight-sum ≥ threshold.
3. `execute()` calls `account.updatePermissions(...)`, replacing the Owner permission irreversibly (`AccountPermissionUpdateActuator.java` lines 44-52).
4. The account can no longer produce a valid Owner-level signature for any future `AccountPermissionUpdateContract`, permanently freezing its ability to update its own permission structure.

  @Override
  public boolean validate() throws ContractValidateException {

    if (chainBaseManager == null) {
      throw new ContractValidateException(ActuatorConstant.STORE_NOT_EXIST);
    }

    if (this.any == null) {
      throw new ContractValidateException(ActuatorConstant.CONTRACT_NOT_EXIST);
    }

    AccountStore accountStore = chainBaseManager.getAccountStore();
    DynamicPropertiesStore dynamicStore = chainBaseManager.getDynamicPropertiesStore();

    if (dynamicStore.getAllowMultiSign() != 1) {
      throw new ContractValidateException("multi sign is not allowed, "
          + "need to be opened by the committee");
    }
    if (!this.any.is(AccountPermissionUpdateContract.class)) {
      throw new ContractValidateException(
          "contract type error,expected type [AccountPermissionUpdateContract],real type["
              + any.getClass() + "]");
    }
    final AccountPermissionUpdateContract accountPermissionUpdateContract;
    try {
      accountPermissionUpdateContract = any.unpack(AccountPermissionUpdateContract.class);
    } catch (InvalidProtocolBufferException e) {
      logger.debug(e.getMessage(), e);
      throw new ContractValidateException(e.getMessage());
    }
    byte[] ownerAddress = accountPermissionUpdateContract.getOwnerAddress().toByteArray();
    if (!DecodeUtil.addressValid(ownerAddress)) {
      throw new ContractValidateException("invalidate ownerAddress");
    }
    AccountCapsule accountCapsule = accountStore.get(ownerAddress);
    if (accountCapsule == null) {
      throw new ContractValidateException("ownerAddress account does not exist");
    }

    if (!accountPermissionUpdateContract.hasOwner()) {
      throw new ContractValidateException("owner permission is missed");
    }

    if (accountCapsule.getIsWitness()) {
      if (!accountPermissionUpdateContract.hasWitness()) {
        throw new ContractValidateException("witness permission is missed");
      }
    } else {
      if (accountPermissionUpdateContract.hasWitness()) {
        throw new ContractValidateException("account isn't witness can't set witness permission");
      }
    }

    if (accountPermissionUpdateContract.getActivesCount() == 0) {
      throw new ContractValidateException("active permission is missed");
    }
    if (accountPermissionUpdateContract.getActivesCount() > 8) {
      throw new ContractValidateException("active permission is too many");
    }

    Permission owner = accountPermissionUpdateContract.getOwner();
    Permission witness = accountPermissionUpdateContract.getWitness();
    List<Permission> actives = accountPermissionUpdateContract.getActivesList();

    if (owner.getType() != PermissionType.Owner) {
      throw new ContractValidateException("owner permission type is error");
    }
    checkPermission(owner);
    if (accountCapsule.getIsWitness()) {
      if (witness.getType() != PermissionType.Witness) {
        throw new ContractValidateException("witness permission type is error");
      }
      checkPermission(witness);
    }
    for (Permission permission : actives) {
      if (permission.getType() != PermissionType.Active) {
        throw new ContractValidateException("active permission type is error");
      }
      checkPermission(permission);
    }
    return true;

  public static boolean addressValid(byte[] address) {
    if (ArrayUtils.isEmpty(address)) {
      logger.warn("Warning: Address is empty !!");
      return false;
    }
    if (address.length != ADDRESS_SIZE / 2) {
      logger.warn(
          "Warning: Address length need " + ADDRESS_SIZE + " but " + address.length
              + " !!");
      return false;
    }

    if (address[0] != addressPreFixByte) {
      logger.warn("Warning: Address need prefix with " + addressPreFixByte + " but "
          + address[0] + " !!");
      return false;
    }
    return true;
  }
