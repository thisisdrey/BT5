This is a real code-level finding, though its practical impact is bounded by an independent per-connection stream-rate throttle (`throttle_stream`/`StakedStreamLoadEMA::available_load_capacity_in_throttling_duration`), which caps unstaked TPS at `MAX_UNSTAKED_TPS` (200) regardless of `max_uni_streams`. Still, the concurrent-stream cap itself can be inflated well beyond the documented/intended `QUIC_MAX_UNSTAKED_CONCURRENT_STREAMS` limit purely by the attacker's own connection behavior.

### Title
Unstaked peers can inflate `max_concurrent_uni_streams` beyond `QUIC_MAX_UNSTAKED_CONCURRENT_STREAMS` via self-induced RTT growth - (File: streamer/src/nonblocking/swqos.rs)

### Summary
`compute_max_allowed_uni_streams_with_rtt` applies BDP-based RTT scaling uniformly to all peer types, including `ConnectionPeerType::Unstaked`, so the resulting concurrent-uni-stream limit for an unstaked connection can reach up to `QUIC_MAX_UNSTAKED_CONCURRENT_STREAMS * (MAX_RTT_MS / REFERENCE_RTT_MS)` = `128 * 7` = `896`, instead of being capped at the documented maximum of `128`. Because `connection.rtt()` reflects the attacker's own observed round-trip time, an unstaked client can deliberately delay its ACKs (or otherwise inflate perceived latency) to push `rtt_millis` toward `MAX_RTT_MS` and thereby obtain a `max_uni_streams` grant up to ~7x the intended unstaked cap.

### Finding Description
In `streamer/src/nonblocking/swqos.rs`:
- `QUIC_MAX_UNSTAKED_CONCURRENT_STREAMS` is documented as an empirically-tuned hard maximum (`streamer/src/nonblocking/swqos.rs:36-39`).
- `compute_max_allowed_uni_streams_with_rtt` (`streamer/src/nonblocking/swqos.rs:147-179`) computes a base `streams` value per `peer_type` (fixed `128` for `Unstaked`), then unconditionally rescales it: `(streams.saturating_mul(rtt_millis.clamp(REFERENCE_RTT_MS, MAX_RTT_MS))) / REFERENCE_RTT_MS` (`streamer/src/nonblocking/swqos.rs:178`). This scaling is applied regardless of peer type — there is no branch that skips/clamps it for `Unstaked`.
- `cache_new_connection` (`streamer/src/nonblocking/swqos.rs:196-202`) feeds `connection.rtt()` (the quinn-measured RTT, driven by the client's own ACK timing) directly into this function and then calls `connection.set_max_concurrent_uni_streams(max_uni_streams)` (`streamer/src/nonblocking/swqos.rs:224`).
- The existing unit test `test_max_allowed_uni_streams_with_rtt` (`streamer/src/nonblocking/swqos.rs:560-580`) explicitly documents and asserts this scaling for `ConnectionPeerType::Unstaked`, confirming it is reachable/intended by the current code, but it is inconsistent with the semantics of the constant name and its doc comment.

An unstaked attacker fully controls the timing of its own QUIC ACKs and can therefore inflate the RTT quinn measures for the connection (up to the `MAX_RTT_MS`=350ms clamp), causing the server to grant `max_uni_streams` far above `QUIC_MAX_UNSTAKED_CONCURRENT_STREAMS`.

### Impact Explanation
This is a QoS-evasion issue rather than a sigverify/dedup bypass: transactions submitted on the extra streams still go through the normal sigverify/dedup pipeline — the finding does not let garbage packets skip verification. The concrete impact is that an unstaked peer can hold up to ~7x more concurrent QUIC streams open than the intended cap allows, increasing per-connection buffering/resource usage (receive windows, stream state) on the leader beyond the documented safe maximum, weakening the intended stake-based QoS differentiation between staked and unstaked traffic. Overall throughput is still bounded by the independent `throttle_stream`/`MAX_UNSTAKED_TPS`(=200) rate limiter in `streamer/src/nonblocking/stream_throttle.rs:17,167-173`, which caps unstaked TPS irrespective of concurrent stream count, so this does not translate into unbounded transaction throughput, but it does allow more simultaneous open/half-open streams (memory/state overhead) than the constant's name and comment promise.

### Likelihood Explanation
High feasibility for triggering the elevated cap: an unstaked attacker only needs to delay its own ACKs (e.g., via added local network delay, a slow proxy, or client-side ACK pacing) to raise the RTT quinn measures for the connection — no cooperation from the validator or other privileged access is required. This is fully within the stated attacker model (unstaked remote client, controls its own network delay).

### Recommendation
In `compute_max_allowed_uni_streams_with_rtt` (`streamer/src/nonblocking/swqos.rs:147-179`), skip or clamp the RTT-based BDP scaling for `ConnectionPeerType::Unstaked`, e.g. only apply the `rtt_millis` multiplier branch for `Staked` peers, or clamp the final result to `QUIC_MAX_UNSTAKED_CONCURRENT_STREAMS` for unstaked connections before returning.

### Proof of Concept
Add/extend a unit test in `streamer/src/nonblocking/swqos.rs` asserting the invariant:

```rust
fn compute_max_allowed_uni_streams_with_rtt(
    rtt_millis: u32,
    peer_type: ConnectionPeerType,
    total_stake: u64,
) -> u32 {
    let streams = match peer_type {
        ConnectionPeerType::Staked(peer_stake) => {
            // No checked math for f64 type. So let's explicitly check for 0 here
            if total_stake == 0 || peer_stake > total_stake {
                warn!(
                    "Invalid stake values: peer_stake: {peer_stake:?}, total_stake: \
                     {total_stake:?}"
                );

                QUIC_MIN_STAKED_CONCURRENT_STREAMS
            } else {
                let delta = (QUIC_TOTAL_STAKED_CONCURRENT_STREAMS
                    - QUIC_MIN_STAKED_CONCURRENT_STREAMS) as f64;

                (((peer_stake as f64 / total_stake as f64) * delta) as u32
                    + QUIC_MIN_STAKED_CONCURRENT_STREAMS)
                    .clamp(
                        QUIC_MIN_STAKED_CONCURRENT_STREAMS,
                        QUIC_MAX_STAKED_CONCURRENT_STREAMS,
                    )
            }
        }
        ConnectionPeerType::Unstaked => QUIC_MAX_UNSTAKED_CONCURRENT_STREAMS,
    };
    // scale amount of streams based on RTT if RTT is larger than REFERENCE_RTT_MS
    // multiply first then divide to avoid rounding errors.
    (streams.saturating_mul(rtt_millis.clamp(REFERENCE_RTT_MS, MAX_RTT_MS))) / REFERENCE_RTT_MS
}
```

```rust
    pub(crate) fn available_load_capacity_in_throttling_duration(
        &self,
        peer_type: ConnectionPeerType,
        total_stake: u64,
    ) -> u64 {
        match peer_type {
            ConnectionPeerType::Unstaked => self.max_unstaked_load_in_throttling_window,
            ConnectionPeerType::Staked(stake) => {
                if self.staked_throttling_enabled.load(Ordering::Relaxed) {
                    // 1 is added to `max_unstaked_load_in_throttling_window` to guarantee that staked
                    // clients get at least 1 more number of streams than unstaked connections.
                    self.max_staked_load_in_throttling_window
                        .saturating_mul(stake)
                        .checked_div(total_stake)
                        .unwrap_or(self.max_unstaked_load_in_throttling_window + 1)
                        .max(self.max_unstaked_load_in_throttling_window + 1)
                } else {
                    self.max_staked_load_in_throttling_window
                }
            }
        }
```
