## Valid Analog Found

### Title
Single-step account permission update allows permanent account bricking via `AccountPermissionUpdateContract` - (File: `actuator/src/main/java/org/tron/core/actuator/AccountPermissionUpdateActuator.java`)

### Summary
`AccountPermissionUpdateActuator` lets any account owner overwrite the account's `Owner`, `Witness`, and `Active` permissions in a single atomic step, with no "pending" or two-step confirmation mechanism. If the new `Owner` permission's key set is misconfigured (wrong address, unreachable/typo'd key, or a threshold/weight combination that can never be satisfied by any held private key), the account's owner authority is permanently and irrecoverably lost, since owner permission is the only permission capable of re-issuing another `AccountPermissionUpdateContract` to fix itself.

### Finding Description
`AccountPermissionUpdateActuator.execute()` unconditionally applies the new permission set to the target account as soon as the surrounding transaction is validated and broadcast: [1](#0-0) 

The `validate()` method and its helper `checkPermission()` only perform structural sanity checks — key count limits, address format validity (`DecodeUtil.addressValid`), threshold > 0, weight sum ≥ threshold, distinct addresses, and operations bitmap validity: [2](#0-1) [3](#0-2) 

None of these checks verify that the account owner actually controls the private key(s) corresponding to the new `Owner` permission's key addresses — that is structurally impossible to verify on-chain, but it also means there is no protective mechanism (e.g. requiring the new owner to "claim" the role in a follow-up transaction) to catch a mistaken address. Once `account.updatePermissions(...)` is executed and the `AccountCapsule` is persisted, the previous owner permission is gone; the only entity that can ever again submit a valid `AccountPermissionUpdateContract` for this account is whoever holds keys satisfying the *new* `Owner` permission's threshold, per `TransactionCapsule.validateSignature` / `checkWeight`: [4](#0-3) [5](#0-4) 

This is a direct analog of the reported single-step ownership transfer risk: the whole class of admin-controlled contracts in java-tron (`WitnessUpdateActuator`, asset issuer actuators, exchange actuators, resource freeze/delegate actuators, etc.) is gated by the `Owner`/`Active` permission structure on the `AccountCapsule`. Bricking the `Owner` permission via a bad `AccountPermissionUpdateContract` bricks control over every subsequent owner-gated actuator for that account (asset issuance withdrawals, exchange management, witness administration, frozen/delegated resource management), since: [6](#0-5) 
all such actuators rely on the same owner-address-based signature/permission validation path in `Manager.processTransaction` → `TransactionCapsule.validateSignature`: [7](#0-6) 

### Impact Explanation
High. A single incorrect `AccountPermissionUpdateContract` (bad `Owner` permission key address, or a threshold unreachable by any real signer) permanently locks out the account owner from ever again authorizing owner-gated operations for that account: further permission updates, witness administration, asset-issuer administration, frozen/delegated TRX and resources, and all owner-only actuators become permanently frozen/unusable. Funds held under that account (TRX balance, TRC10 tokens, frozen/delegated resources) become effectively unmovable via owner-permission paths — a form of permanent asset freezing.

### Likelihood Explanation
Low. It requires the account owner to submit a malformed `AccountPermissionUpdateContract` (wrong key address, or a key/threshold combination with no satisfiable weight from held keys). This is a self-inflicted operational error rather than an attacker-triggered exploit, consistent with the referenced report's likelihood rating, but the resulting state is unrecoverable on-chain.

### Recommendation
Introduce a two-step confirmation for `Owner`-permission changes in `AccountPermissionUpdateContract`/`AccountPermissionUpdateActuator`: stage the proposed new `Owner` permission, and require a subsequent transaction — signed by a key satisfying the *proposed* new owner permission — to "accept"/finalize the change before it takes effect, leaving the previous `Owner` permission in force in the interim. Alternatively, add an on-chain simulated/emulated signature-capability probe (e.g. requiring a signed acknowledgment structure from the new keys' addresses within the same or a follow-up transaction) so an unreachable owner key cannot be committed irreversibly.

### Proof of Concept
1. Account `A` (owner permission threshold=1, key=`A`) submits an `AccountPermissionUpdateContract` setting `owner.keys = [{address: X, weight: 1}]` where `X` is a typo'd/unowned address, signed validly by `A`'s current owner key (satisfies current threshold in `checkPermission`/`validate()`).
2. `AccountPermissionUpdateActuator.execute()` calls `account.updatePermissions(...)` and persists it — see `actuator/src/main/java/org/tron/core/actuator/AccountPermissionUpdateActuator.java` lines 47-52.
3. Any subsequent transaction from account `A` requiring owner-permission signature (including another `AccountPermissionUpdateContract` to fix the mistake) is validated against the new `Owner` permission via `TransactionCapsule.validateSignature`/`checkWeight` (`chainbase/src/main/java/org/tron/core/capsule/TransactionCapsule.java` lines 468-496, 233-270); since nobody controls `X`'s private key, no signature can ever reach the threshold.
4. Account `A` is permanently locked out of all owner-gated operations, and any TRX/TRC10/frozen resources requiring owner authorization become permanently frozen.

  private boolean checkPermission(Permission permission) throws ContractValidateException {
    DynamicPropertiesStore dynamicStore = chainBaseManager.getDynamicPropertiesStore();
    if (permission.getKeysCount() > dynamicStore.getTotalSignNum()) {
      throw new ContractValidateException("number of keys in permission should not be greater "
          + "than " + dynamicStore.getTotalSignNum());
    }
    if (permission.getKeysCount() == 0) {
      throw new ContractValidateException("key's count should be greater than 0");
    }
    if (permission.getType() == PermissionType.Witness && permission.getKeysCount() != 1) {
      throw new ContractValidateException("Witness permission's key count should be 1");
    }
    if (permission.getThreshold() <= 0) {
      throw new ContractValidateException("permission's threshold should be greater than 0");
    }
    String name = permission.getPermissionName();
    if (!StringUtils.isEmpty(name) && name.length() > 32) {
      throw new ContractValidateException("permission's name is too long");
    }
    //check owner name ?
    if (permission.getParentId() != 0) {
      throw new ContractValidateException("permission's parent should be owner");
    }

    long weightSum = 0;
    List<ByteString> addressList = permission.getKeysList()
        .stream()
        .map(x -> x.getAddress())
        .distinct()
        .collect(toList());
    if (addressList.size() != permission.getKeysList().size()) {
      throw new ContractValidateException(
          "address should be distinct in permission " + permission.getType());
    }
    for (Key key : permission.getKeysList()) {
      if (!DecodeUtil.addressValid(key.getAddress().toByteArray())) {
        throw new ContractValidateException("key is not a validate address");
      }
      if (key.getWeight() <= 0) {
        throw new ContractValidateException("key's weight should be greater than 0");
      }
      try {
        weightSum = addExact(weightSum, key.getWeight());
      } catch (ArithmeticException e) {
        throw new ContractValidateException(e.getMessage());
      }
    }
    if (weightSum < permission.getThreshold()) {
      throw new ContractValidateException(
          "sum of all key's weight should not be less than threshold in permission " + permission
              .getType());
    }

  public static long checkWeight(Permission permission, List<ByteString> sigs, byte[] hash,
      List<ByteString> approveList)
      throws SignatureException, PermissionException, SignatureFormatException {
    long currentWeight = 0;
    if (sigs.size() > permission.getKeysCount()) {
      throw new PermissionException(
          "Signature count is " + (sigs.size()) + " more than key counts of permission : "
              + permission.getKeysCount());
    }
    HashMap addMap = new HashMap();
    for (ByteString sig : sigs) {
      if (sig.size() < 65) {
        throw new SignatureFormatException(
            "Signature size is " + sig.size());
      }
      String base64 = TransactionCapsule.getBase64FromByteString(sig);
      byte[] address = SignUtils
          .signatureToAddress(hash, base64, CommonParameter.getInstance().isECKeyCryptoEngine());
      long weight = getWeight(permission, address);
      if (weight == 0) {
        throw new PermissionException(
            ByteArray.toHexString(hash) + " is signed by " + encode58Check(address)
                + " but it is not contained of permission.");
      }
      if (ForkController.instance().pass(Parameter.ForkBlockVersionEnum.VERSION_4_7_1)) {
        base64 = encode58Check(address);
      }
      if (addMap.containsKey(base64)) {
        throw new PermissionException(encode58Check(address) + " has signed twice!");
      }
      addMap.put(base64, weight);
      if (approveList != null) {
        approveList.add(ByteString.copyFrom(address)); //out put approve list.
      }
      currentWeight += weight;
    }
    return currentWeight;
  }

  public static boolean validateSignature(Transaction transaction,
      byte[] hash, AccountStore accountStore, DynamicPropertiesStore dynamicPropertiesStore)
      throws PermissionException, SignatureException, SignatureFormatException {
    Transaction.Contract contract = transaction.getRawData().getContractList().get(0);
    int permissionId = contract.getPermissionId();
    byte[] owner = getOwner(contract);
    AccountCapsule account = accountStore.get(owner);
    Permission permission = null;
    if (account == null) {
      if (permissionId == 0) {
        permission = AccountCapsule.getDefaultPermission(ByteString.copyFrom(owner));
      }
      if (permissionId == 2) {
        permission = AccountCapsule
            .createDefaultActivePermission(ByteString.copyFrom(owner), dynamicPropertiesStore);
      }
    } else {
      permission = account.getPermissionById(permissionId);
    }
    if (permission == null) {
      throw new PermissionException("permission isn't exit");
    }
    checkPermission(permissionId, permission, contract);
    long weight = checkWeight(permission, transaction.getSignatureList(), hash, null);
    if (weight >= permission.getThreshold()) {
      return true;
    }
    return false;
  }
