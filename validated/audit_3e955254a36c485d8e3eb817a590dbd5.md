### Title
Unbounded/duplicate `groups` field in certificate ASN.1 parsing enables pre-authentication CPU griefing - (File: cert/cert_v2.go)

### Summary
`unmarshalDetails` in `cert/cert_v2.go` parses the `groups` field of an attacker-supplied handshake certificate into an unbounded, unsorted, unchecked `[]string` slice, with no limit on entry count and no duplicate detection — unlike `networks`/`unsafeNetworks`, which are sorted and passed through `findDuplicatePrefix`. This parsing occurs in `Machine.validateCert` (`handshake/machine.go`) prior to any CA signature verification, making it reachable by any peer able to send a single handshake stage-2/final packet, without holding a CA-signed certificate.

### Finding Description
`cert/cert_v2.go:641-745` (`unmarshalDetails`) reads the `TagDetailsGroups` ASN.1 element and appends each UTF8String entry into `groups` with only a length/empty check per entry — no bound on the number of groups and no duplicate check: [1](#0-0) 

Compare this to the networks handling in the same function, which is bounded implicitly by certificate size but, more importantly, whose *duplicate* detection is deferred to `validate()`: [2](#0-1) 

`validate()` explicitly sorts and dedupes `networks` and `unsafeNetworks` via `findDuplicatePrefix` (an O(n log n) sort + O(n) linear scan), but performs **no equivalent sort/dedupe/limit check on `groups`** at all: [3](#0-2) [4](#0-3) 

This unbounded, un-deduplicated `groups` slice later feeds `CachedCertificate.InvertedGroups` (built in `CAPool.VerifyCertificate`) and is walked linearly against firewall rule groups in `FirewallRule.match` (`firewall.go:858-874`), and also walked in `checkCAConstraints` (`cert/ca_pool.go:298-306`) via `slices.Contains(signerGroups, g)` for every entry — an O(n·m) linear search per verification. The critical point, however, is that the unbounded parsing itself (`unmarshalDetails`) happens in `Machine.validateCert` (`handshake/machine.go:342-380`) via `cert.Recombine` **before** `m.verifier(rc)` is invoked: [5](#0-4) 

Because the ASN.1 `cryptobyte` reader in `unmarshalDetails` only bounds each individual group's presence in the certificate byte buffer (limited by `MaxCertificateSize`), an attacker can craft a self-signed (unverified) certificate whose `groups` list is packed with tens of thousands of small duplicate group strings, all fitting within `MaxCertificateSize`, and send it as the certificate payload in a single handshake message to a completely unauthenticated peer. This is directly analogous to the `AllowedMethodsEnforcer`/`AllowedTargetsEnforcer` bug: attacker-controlled duplicate list entries that increase downstream linear-scan cost, with no uniqueness enforcement at parse time.

### Impact Explanation
An attacker (or unauthenticated peer with an arbitrary self-signed static-key certificate, no CA signature required) can force the responder to allocate and process a large, duplicate-laden `groups` slice during `validateCert`, before signature verification fails and the handshake is aborted. Repeated stage packets (each handshake attempt is otherwise cheap and unauthenticated at this stage) amplify CPU cost on the victim relative to attacker effort, and if the cert did pass verification (e.g. a legitimately signed cert with a griefing groups list, mirroring the original report's threat model of an "authorized redeemer" causing gas griefing), the downstream firewall/`CheckCAConstraints` linear scans become expensive per packet/handshake evaluation. This is a CPU-based denial-of-service degradation, not a memory-safety or authentication bypass.

### Likelihood Explanation
Reaching `unmarshalDetails` requires only sending a single crafted handshake packet with a `Cert` payload; it does not require possessing a CA-signed certificate, matching the reachability constraint. Exploitation is straightforward (bytes with many small group strings, well under `MaxCertificateSize`), but the actual damage is bounded by per-message cert size limits and the fact that failed-signature certs are rejected right after this parsing step, limiting sustained amplification to repeated single-packet sends rather than persistent connection state.

### Recommendation
Add the same treatment applied to `networks`/`unsafeNetworks` to `groups`: enforce a maximum group count and/or maximum total groups length during `unmarshalDetails`, and add a duplicate-detection pass (e.g., sort + `slices.Compact` or a set-based check) in `certificateV2.validate()` analogous to `findDuplicatePrefix`, rejecting certificates with duplicate or excessive group entries before any further processing.

### Proof of Concept
Not independently executed; based on static analysis of `cert/cert_v2.go` (`unmarshalDetails`, `validate`) and `handshake/machine.go` (`validateCert`) showing that `groups` parsing/validation occurs pre-signature-check and lacks the duplicate/size guard present for `networks`/`unsafeNetworks`. A concrete PoC would construct a `certificateV2` with `groups` containing N duplicate short strings (e.g., 10,000× `"g"`), marshal it via `MarshalForHandshakes`, and drive it through `Machine.ProcessPacket` with an unrelated/self-generated peer static key to observe parse time and allocation scale with N despite ultimate verification failure.

func (c *certificateV2) validate() error {
	// Empty names are allowed

	if len(c.publicKey) == 0 {
		return ErrInvalidPublicKey
	}

	if !c.details.isCA && len(c.details.networks) == 0 {
		return NewErrInvalidCertificateProperties("non-CA certificate must contain at least 1 network")
	}

	hasV4Networks := false
	hasV6Networks := false
	for _, network := range c.details.networks {
		if !network.IsValid() || !network.Addr().IsValid() {
			return NewErrInvalidCertificateProperties("invalid network: %s", network)
		}

		if network.Addr().IsUnspecified() {
			return NewErrInvalidCertificateProperties("non-CA certificates must not use the zero address as a network: %s", network)
		}

		if network.Addr().Zone() != "" {
			return NewErrInvalidCertificateProperties("networks may not contain zones: %s", network)
		}

		if network.Addr().Is4In6() {
			return NewErrInvalidCertificateProperties("4in6 networks are not allowed: %s", network)
		}

		hasV4Networks = hasV4Networks || network.Addr().Is4()
		hasV6Networks = hasV6Networks || network.Addr().Is6()
	}

	slices.SortFunc(c.details.networks, comparePrefix)
	err := findDuplicatePrefix(c.details.networks)
	if err != nil {
		return err
	}

	for _, network := range c.details.unsafeNetworks {
		if !network.IsValid() || !network.Addr().IsValid() {
			return NewErrInvalidCertificateProperties("invalid unsafe network: %s", network)
		}

		if network.Addr().Zone() != "" {
			return NewErrInvalidCertificateProperties("unsafe networks may not contain zones: %s", network)
		}

		if !c.details.isCA {
			if network.Addr().Is6() {
				if !hasV6Networks {
					return NewErrInvalidCertificateProperties("IPv6 unsafe networks require an IPv6 address assignment: %s", network)
				}
			} else if network.Addr().Is4() {
				if !hasV4Networks {
					return NewErrInvalidCertificateProperties("IPv4 unsafe networks require an IPv4 address assignment: %s", network)
				}
			}
		}
	}

	slices.SortFunc(c.details.unsafeNetworks, comparePrefix)
	err = findDuplicatePrefix(c.details.unsafeNetworks)
	if err != nil {
		return err
	}

	return nil
}

// findDuplicatePrefix returns an error if there is a duplicate prefix in the pre-sorted input slice sortedPrefixes
func findDuplicatePrefix(sortedPrefixes []netip.Prefix) error {
	if len(sortedPrefixes) < 2 {
		return nil
	}
	for i := 1; i < len(sortedPrefixes); i++ {
		if comparePrefix(sortedPrefixes[i], sortedPrefixes[i-1]) == 0 {
			return NewErrInvalidCertificateProperties("duplicate network detected: %v", sortedPrefixes[i])
		}
	}
	return nil
}
