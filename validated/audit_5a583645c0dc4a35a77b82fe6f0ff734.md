### Title
Unvalidated `GitObjectDirectory`/`GitAlternateObjectDirectories` fields allow arbitrary object-directory injection into every Git subprocess - (File: internal/git/gitcmd/command_factory.go)

### Summary
The `Repository` protobuf message exposes two attacker-settable fields, `git_object_directory` and `git_alternate_object_directories`, which are meant to carry Gitaly-internal quarantine paths so that a proposed object store can be inspected before it is merged into a repository [1](#0-0) . Just like the Sablier report where a caller-supplied `permit2` address was blindly trusted instead of being checked against an allowlist, `ExecCommandFactory.newCommand` takes these two fields straight off the incoming `Repository` message and turns them into `GIT_OBJECT_DIRECTORY`/`GIT_ALTERNATE_OBJECT_DIRECTORIES` environment variables for every Git subprocess it spawns, without any path-containment check at that call site.

### Finding Description
When a Git command is built for a specific repository, the command factory does: [2](#0-1) 
`repo.GetGitObjectDirectory()` and `repo.GetGitAlternateObjectDirectories()` are passed unchecked into `alternates.Env`, which simply joins them onto the repository path and exports them as environment variables: [3](#0-2) 

There is a separate, stricter validation routine, `Repo.ObjectDirectoryPath`, which checks that `GitObjectDirectory` stays within the storage root and either resolves inside the repository or matches an expected quarantine-directory prefix [4](#0-3) . However, that validation is only invoked by a narrow set of call sites (e.g. `GetObjectDirectorySize`), not by the generic command-execution path in `command_factory.go` that every RPC funnels through to actually run `git`. Critically, `GitAlternateObjectDirectories` is *never* passed through `ObjectDirectoryPath`-style validation at all — only `GitObjectDirectory` has any dedicated checker, and even that checker is bypassed for the actual git-process invocation.

Because `Repository` is embedded in the vast majority of Gitaly RPC requests, any caller with access to an RPC that carries a `Repository` message can populate `git_object_directory` / `git_alternate_object_directories` with a path such as `../../../other-repo/objects` or an absolute path elsewhere on disk. When that repository is subsequently used to run a Git command, Git will honor those environment variables for both object lookup and write targeting.

### Impact Explanation
This is a concrete case of cross-repository object access and storage-root escape: an ordinary caller can point a "trusted" internal knob (originally intended only for the pre-receive/quarantine mechanism) to any path on the filesystem via a crafted RPC field, causing Git commands to read objects from, or write loose objects into, directories outside the intended repository/storage boundary. This can be used to leak the presence/content of another repository's objects or, depending on operation, to pollute another repository/pool's object store, undermining Gitaly's storage-path isolation and pool trust boundaries.

### Likelihood Explanation
This does not require any special privilege beyond invoking a standard Gitaly RPC that includes a `Repository` message with attacker-controllable `GitObjectDirectory`/`GitAlternateObjectDirectories` fields — exactly the "envoy with access to the target" pattern in the analog report, since a normal RPC caller has no reason to expect these two internal-use fields to be honored without validation on the primary command-execution path.

### Recommendation
Validate `GitObjectDirectory` and `GitAlternateObjectDirectories` at the single choke point where they are converted into environment variables (`internal/git/gitcmd/command_factory.go`'s `newCommand`), reusing the same containment/quarantine-prefix checks implemented in `Repo.ObjectDirectoryPath`, and apply equivalent validation to every entry of `GitAlternateObjectDirectories` rather than relying on scattered, RPC-specific validation.

### Proof of Concept
1. Call any Gitaly RPC that accepts a `gitalypb.Repository` for an existing, accessible repository.
2. Set `git_object_directory` to a relative path that escapes the repository, e.g. `../../victim-repo/objects`, and/or set `git_alternate_object_directories` to `["../../victim-repo/objects"]`.
3. Trigger a Git operation on that repository (e.g. one that writes or reads loose objects).
4. Because `command_factory.go` builds `GIT_OBJECT_DIRECTORY`/`GIT_ALTERNATE_OBJECT_DIRECTORIES` directly from these fields without calling the storage-boundary validation used elsewhere, Git operates against the victim repository's object directory instead of the intended one, evidenced by objects appearing in / being read from the victim path.

Note: I could not exhaustively confirm from the indexed code whether every externally reachable RPC strips or overwrites these two fields before dispatch (some server-side code paths may reset them for security, e.g. quarantine setup, but this was not visible for all RPC handlers in the indexed subset). A Devin session with full repository access would be needed to enumerate all RPC handlers that pass a client-supplied `Repository` message straight into `newCommand` to confirm end-to-end reachability.

// Env returns the alternate object directory environment variables.
func Env(repoPath, objectDirectory string, alternateObjectDirectories []string) []string {
	var env []string
	if objectDirectory != "" {
		env = append(env, fmt.Sprintf("GIT_OBJECT_DIRECTORY=%s", filepath.Join(repoPath, objectDirectory)))
	}

	if len(alternateObjectDirectories) > 0 {
		var dirsList []string

		for _, dir := range alternateObjectDirectories {
			dirsList = append(dirsList, filepath.Join(repoPath, dir))
		}

		env = append(env, fmt.Sprintf("GIT_ALTERNATE_OBJECT_DIRECTORIES=%s", strings.Join(dirsList, ":")))
	}

	return env
}

// ObjectDirectoryPath returns the full path of the object directory. The errors returned are gRPC
// errors with relevant error codes and should be passed back to gRPC without further decoration.
func (repo *Repo) ObjectDirectoryPath(ctx context.Context) (string, error) {
	repoPath, err := repo.Path(ctx)
	if err != nil {
		return "", err
	}

	objectDirectoryPath := repo.GetGitObjectDirectory()
	if objectDirectoryPath == "" {
		return "", structerr.NewInvalidArgument("object directory path is not set")
	}

	storagePath, err := repo.locator.GetStorageByName(ctx, repo.GetStorageName())
	if err != nil {
		return "", fmt.Errorf("get storage by name: %w", err)
	}

	// Ensure the path points somewhere in the storage.
	relativeObjectDirectoryPath, err := storage.ValidateRelativePath(storagePath, filepath.Join(repoPath, objectDirectoryPath))
	if err != nil {
		return "", structerr.NewInvalidArgument("validate relative path: %w", err)
	}

	parentDir := filepath.Base(filepath.Dir(relativeObjectDirectoryPath))
	baseDir := filepath.Base(relativeObjectDirectoryPath)
	isTransactionQuarantineDir := (baseDir == "quarantine") || ((parentDir == "quarantine") && strings.HasPrefix(baseDir, "tmp_objdir"))

	// Transactions quarantine a repository by pointing the object directory to a 'quarantine' named
	// directory in the transaction's temporary directory. If the base directory is `quarantine`,
	// Git push may apply an additional layer of quarantine such as `/quarantine/tmp_objdir-incoming-Gbc29N`
	// so we don't assert the `/quarantine` being the last element of the path. We thus also check for
	// whether the parent directory is in `quarantine` and whether the base directory has the expected
	// `tmp_objdir` suffix.
	if !isTransactionQuarantineDir {
		// We need to check whether the relative object directory as given by the repository is
		// a valid path. This may either be a path in the Git repository itself, where it may either
		// point to the main object directory storage or to an object quarantine directory as
		// created by git-receive-pack(1). Alternatively, if that is not the case, then it may be a
		// manual object quarantine directory located in the storage's temporary directory. These
		// have a repository-specific prefix which we must check in order to determine whether the
		// quarantine directory does in fact belong to the repo at hand.
		if _, origError := storage.ValidateRelativePath(repoPath, objectDirectoryPath); origError != nil {
			tempDir, err := repo.locator.TempDir(repo.GetStorageName())
			if err != nil {
				return "", structerr.NewInvalidArgument("getting storage's temporary directory: %w", err)
			}

			expectedQuarantinePrefix := filepath.Join(tempDir, storage.QuarantineDirectoryPrefix(repo))
			absoluteObjectDirectoryPath := filepath.Join(repoPath, objectDirectoryPath)

			// The relative path is outside of the repository
			if !strings.HasPrefix(absoluteObjectDirectoryPath, expectedQuarantinePrefix) {
				return "", structerr.NewInvalidArgument("not a valid relative path: %w", origError)
			}
		}
	}

	fullPath := filepath.Join(repoPath, objectDirectoryPath)
	if _, err := os.Stat(fullPath); os.IsNotExist(err) {
		return "", structerr.NewNotFound("object directory does not exist: %q", fullPath)
	}

	return fullPath, nil
}
