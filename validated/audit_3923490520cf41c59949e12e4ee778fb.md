### Title
Unauthenticated `/shutdown` HTTP endpoint allows any remote peer to terminate the signer's event receiver - (File: `libsigner/src/events.rs`)

### Summary
The `SignerEventReceiver::next_event` handler treats any HTTP POST to `/shutdown` as authoritative and immediately sets the shared `stop_signal` atomic to `true`, returning `EventError::Terminated`. This causes `EventReceiver::main_loop` to break and permanently stop consuming further StackerDB/burn-block/block events, with no verification that the request originated from the signer's own local `SignerStopSignaler`.

### Finding Description
`SignerStopSignaler::send()` is intended to be the only legitimate caller that stops the receiver: it stores `true` into `stop_signal` and sends a crafted `POST /shutdown` request to the receiver's own bound address purely to wake up the blocking `http_server.recv()` call. [1](#0-0)  However, the actual state transition is not gated on the sender being this internal signaler — it is performed unconditionally inside the request-handling closure of `next_event`, purely based on matching the URL string `/shutdown`: [2](#0-1) 

There is no signature, secret, source-address check, or any authentication applied to this branch (contrast with `/status`, `/stackerdb_chunks`, `/proposal_response`, etc., which also have no such checks but only *forward* data rather than terminate the loop). Since `EventReceiver::main_loop` treats `EventError::Terminated` as an unconditional break condition: [3](#0-2) 

any TCP client that can reach the signer's bound event-receiver socket (`config.endpoint`, listened on via `bind()` in `Signer::spawn`) can send the identical raw HTTP request `POST /shutdown HTTP/1.1\r\nHost: x\r\nContent-Length: 0\r\n\r\n` and achieve the exact same effect as the legitimate internal stop signal — permanently halting event processing for that signer process. The `stacks-signer/src/lib.rs` startup code even emits a runtime warning acknowledging that exposing this endpoint to a non-local/external node "could potentially expose sensitive data or functionalities to security risks," confirming this is a recognized, unmitigated exposure. [4](#0-3) 

### Impact Explanation
Any unauthenticated remote client reaching the signer's event-receiver port can send a single crafted HTTP POST to permanently stop that signer instance from processing further StackerDB chunks, burn-block events, new-block events, and block-validation responses, effectively disabling the signer's participation in signing rounds. This is a single-message, repeatable, remotely triggerable denial of service against a specific signer node, matching the "Critical – remote crash/unauthenticated DoS from few messages" impact category.

### Likelihood Explanation
The only precondition is network reachability to the signer's bound listening address/port for its event receiver, which is the address configured in `GlobalConfig::endpoint` and passed to `Signer::spawn`/`bind()`. No secret, peer key, or StackerDB slot ownership is needed — the handler performs no authentication whatsoever on the `/shutdown` path, unlike protected paths in the node's RPC/P2P surface. Attacker cost is a single raw HTTP POST; the action is trivially repeatable against any signer whose event port is reachable beyond localhost/trusted network.

### Recommendation
Do not expose a global unauthenticated `/shutdown` control-plane action on the same public HTTP listener that receives node events. Options: (1) restrict the listener to loopback-only binding by default and document/enforce it, (2) require a locally-generated shared secret/token in the shutdown request that is only known to the in-process `SignerStopSignaler` (e.g., an HMAC or random nonce generated at `bind()` time and compared in the `/shutdown` handler), or (3) use a separate control channel (e.g., a local Unix socket or in-process channel) for stop signaling instead of routing it through the same TCP listener that accepts remote events.

### Proof of Concept
```rust
// libsigner/src/tests or a standalone integration test
use std::net::{TcpStream, SocketAddr};
use std::io::Write;
use std::sync::mpsc::channel;
use libsigner::{EventReceiver, SignerEventReceiver};

#[test]
fn unauthenticated_shutdown_dos() {
    let mut receiver: SignerEventReceiver<SomeSignerMessageType> = SignerEventReceiver::new(false);
    let addr: SocketAddr = "127.0.0.1:0".parse().unwrap();
    let bound = receiver.bind(addr).unwrap();
    let (tx, _rx) = channel();
    receiver.add_consumer(tx);

    // spawn main_loop in a thread
    let handle = std::thread::spawn(move || receiver.main_loop());

    // Attacker: raw unauthenticated request, no legitimate SignerStopSignaler used
    let mut stream = TcpStream::connect(bound).unwrap();
    let req = "POST /shutdown HTTP/1.1\r\nHost: x\r\nContent-Length: 0\r\n\r\n";
    stream.write_all(req.as_bytes()).unwrap();

    // main_loop should exit due to attacker-triggered Terminated error
    handle.join().unwrap();
    // Assertion: main_loop returned/exited even though no legitimate
    // SignerStopSignaler::send() was ever invoked, proving unauthenticated DoS.
}
```

                Ok(event) => event,

                    // got an event that we don't care about (not a problem)
                    continue;
                }

                    // we're done
                    info!("Caught termination signal");
                    break;

                }
            };

                info!("Failed to forward event");
                break;
            }
        }
