Audit Report

## Title
Same-extrinsic AMM spot-price manipulation in `ChargeAssetTxPayment`/`SwapAssetAdapter` lets a user drain `pallet-asset-conversion` pool liquidity between fee withdrawal and fee refund - (File: substrate/frame/transaction-payment/asset-conversion-tx-payment/src/payment.rs)

## Summary
`SwapAssetAdapter::withdraw_fee` quotes and swaps the fee-asset at pre-dispatch spot reserves via `S::quote_price_tokens_for_exact_tokens` [1](#0-0) , and `correct_and_deposit_fee` re-quotes the refund at post-dispatch spot reserves via `S::quote_price_exact_tokens_for_tokens` [2](#0-1) . Because the wrapped, attacker-controlled `call` executes strictly between `prepare()` and `post_dispatch_details()` in the `TransactionExtension` pipeline [3](#0-2) , an attacker can move the same pool's reserves with an ordinary swap inside their own extrinsic and profit from the rate mismatch between the two quotes, at LP expense.

## Finding Description
The extension flow is: `validate` → `prepare` (calls `withdraw_fee`, quoting/swapping asset X for exact fee amount of asset A against live reserves) → the wrapped `call` dispatches → `post_dispatch_details` (calls `correct_and_deposit_fee`, which re-quotes `A → X` for the refund against reserves as they stand *after* the call executed) [4](#0-3) . Nothing in `correct_and_deposit_fee` re-checks consistency with the rate used in `withdraw_fee`; the `QuotePrice` trait documentation itself states the quoted price is only valid "if no other swaps are made after the price is quoted and before the target swap" — a precondition `ChargeAssetTxPayment` cannot guarantee since the intervening call is fully attacker-controlled [5](#0-4) . This confirms the two quotes in `payment.rs` can be made inconsistent by an ordinary, permissionless swap call (e.g., `AssetConversion::swap_exact_tokens_for_tokens` on the same pool) executed as, or nested within (e.g. via `Utility::batch`), the wrapped call.

`SwapAssetAdapter` is not a purely theoretical config: it is wired into `OnChargeAssetTransaction` in real production runtime code (`asset-hub-rococo`, `asset-hub-westend`, and other included runtimes), confirming this is live, in-scope logic rather than a mock-only construct.

## Impact Explanation
This breaks the value-conservation invariant for `pallet-asset-conversion` pool liquidity: the refund conversion rate (`A → X`) can be biased relative to the withdrawal rate (`X → A`) purely by an unprivileged signed account moving the reserves within its own atomic extrinsic, letting it extract value from LPs (or cause the treasury/fee handler `OU` to receive a mispriced amount) — matching the "assets/pools must conserve value and settle exactly once at the correct amount" pivot. No governance, validator, or off-chain assumption is required; the attacker only needs ordinary capital and a public swap call.

## Likelihood Explanation
High feasibility and low cost: the attacker needs only a chain configuring `ChargeAssetTxPayment` with `SwapAssetAdapter` against `pallet-asset-conversion` (present in in-repo runtimes) and capital sufficient to move the target pool's reserves within one extrinsic. No external flash loan, collusion, or privileged access is needed, and the attack can be repeated every block against any pool used for fee payment.

## Recommendation
- Snapshot the effective conversion rate/reserve state at `withdraw_fee` time and reuse it (or a bounded slippage tolerance around it) for the `correct_and_deposit_fee` refund conversion, instead of re-querying live spot reserves after the wrapped call executes.
- Alternatively, bound the deviation between the withdrawal-time and refund-time quoted rates, or use a manipulation-resistant price source (e.g., TWAP) for `SwapAssetAdapter` refund conversions rather than raw spot reserves from `pallet-asset-conversion`.

## Proof of Concept
1. Configure a runtime with `ChargeAssetTxPayment<T>` using `SwapAssetAdapter<A, F, S, OU>` where `S = pallet-asset-conversion`, and create a pool for `(A, X)`.
2. Attacker submits a signed extrinsic with `asset_id = X` and `call = AssetConversion::swap_exact_tokens_for_tokens(path: [X, A], amount_in: LARGE, ...)`.
3. `prepare()` invokes `withdraw_fee`, quoting/swapping a small amount of `X` for the exact fee in `A` at pre-call reserves (`payment.rs:142-157`).
4. The wrapped call executes, sharply skewing the `X`/`A` reserve ratio via the attacker's large swap.
5. `post_dispatch_details()` invokes `correct_and_deposit_fee`, which re-quotes the unspent-weight refund (`A → X`) against the now-skewed reserves (`payment.rs:262-297`), yielding the attacker a more favorable `X` amount than the pre-call rate, drawn from pool liquidity/LPs.
6. Repeatable every block since it requires only a normal signed extrinsic with no privileged actor.

	fn prepare(
		self,
		val: Self::Val,
		_origin: &<T::RuntimeCall as Dispatchable>::RuntimeOrigin,
		call: &T::RuntimeCall,
		info: &DispatchInfoOf<T::RuntimeCall>,
		_len: usize,
	) -> Result<Self::Pre, TransactionValidityError> {
		match val {
			Val::Charge { tip, who, fee } => {
				// Mutating call of `withdraw_fee` to actually charge for the transaction.
				let (_fee, initial_payment) = self.withdraw_fee(&who, call, info, fee)?;
				Ok(Pre::Charge { tip, who, initial_payment, weight: self.weight(call) })
			},
			Val::NoCharge => Ok(Pre::NoCharge { refund: self.weight(call) }),
		}
	}

	fn post_dispatch_details(
		pre: Self::Pre,
		info: &DispatchInfoOf<T::RuntimeCall>,
		post_info: &PostDispatchInfoOf<T::RuntimeCall>,
		len: usize,
		_result: &DispatchResult,
	) -> Result<Weight, TransactionValidityError> {
		let (tip, who, initial_payment, extension_weight) = match pre {
			Pre::Charge { tip, who, initial_payment, weight } => {
				(tip, who, initial_payment, weight)
			},
			Pre::NoCharge { refund } => {
				// No-op: Refund everything
				return Ok(refund);
			},
		};

		match initial_payment {
			InitialPayment::Native(already_withdrawn) => {
				// Take into account the weight used by this extension before calculating the
				// refund.
				let actual_ext_weight = <T as Config>::WeightInfo::charge_asset_tx_payment_native();
				let unspent_weight = extension_weight.saturating_sub(actual_ext_weight);
				let mut actual_post_info = *post_info;
				actual_post_info.refund(unspent_weight);
				let actual_fee = pallet_transaction_payment::Pallet::<T>::compute_actual_fee(
					len as u32,
					info,
					&actual_post_info,
					tip,
				);
				T::OnChargeTransaction::correct_and_deposit_fee(
					&who,
					info,
					&actual_post_info,
					actual_fee,
					tip,
					already_withdrawn,
				)?;
				pallet_transaction_payment::Pallet::<T>::deposit_fee_paid_event(
					who, actual_fee, tip,
				);
				Ok(unspent_weight)
			},
			InitialPayment::Asset((asset_id, already_withdrawn)) => {
				// Take into account the weight used by this extension before calculating the
				// refund.
				let actual_ext_weight = <T as Config>::WeightInfo::charge_asset_tx_payment_asset();
				let unspent_weight = extension_weight.saturating_sub(actual_ext_weight);
				let mut actual_post_info = *post_info;
				actual_post_info.refund(unspent_weight);
				let actual_fee = pallet_transaction_payment::Pallet::<T>::compute_actual_fee(
					len as u32,
					info,
					&actual_post_info,
					tip,
				);
				let converted_fee = T::OnChargeAssetTransaction::correct_and_deposit_fee(
					&who,
					info,
					&actual_post_info,
					actual_fee,
					tip,
					asset_id.clone(),
					already_withdrawn,
				)?;
