### Title
CreateRepositoryFromSnapshot performs unauthenticated-URL SSRF with credential forwarding and unvalidated tar extraction - (File: internal/gitaly/service/repository/create_repository_from_snapshot.go)

### Summary
The `CreateRepositoryFromSnapshot` RPC lets any caller holding a valid Gitaly auth token supply an arbitrary `HttpUrl`/`HttpAuth`/`ResolvedAddress` that Gitaly's server will fetch server-side and pipe directly into an unguarded `tar -xvf -` extraction, with no protections against archive-extraction escape that exist elsewhere in the same codebase.

### Finding Description
`s.untar` builds an HTTP GET request using an attacker-supplied URL taken directly from the request (`in.GetHttpUrl()`), optionally attaches an attacker-influenced address override (`in.GetResolvedAddress()`) to bypass DNS, and forwards an attacker-controlled `Authorization` header value (`in.GetHttpAuth()`) verbatim to that URL: [1](#0-0) 

The HTTP response body is piped straight into the system `tar` binary without any of the extraction-escape validation (symlink/hardlink target checks, absolute-path rejection, path-prefix confinement) that the sibling snapshot-extraction code path implements elsewhere in the repository: [2](#0-1) 

Compare this to `extractTarToDirectory` in `replicate.go`, which is the properly hardened analog used for `GetSnapshot`-based replication and explicitly checks for path/symlink/hardlink escape: [3](#0-2) 

The code even carries an explicit acknowledgment that the archive content is "trusted a lot" and needs hardening before being pointed at untrusted endpoints: [4](#0-3) 

This RPC is reachable by any client with a valid (possibly limited-scope) Gitaly auth token — e.g., during a GitLab project import/fork flow — without any additional per-URL authorization or allow-listing.

### Impact Explanation
- **SSRF**: An ordinary caller can direct the Gitaly server to make outbound HTTP requests to arbitrary internal/external hosts (`in.GetHttpUrl()`), potentially reaching internal metadata services or other internal-only endpoints.
- **Credential disclosure**: `in.GetHttpAuth()` is placed verbatim into the `Authorization` header of the outbound request. Because the destination URL is attacker-controlled, this can be used to redirect any credential the caller places in that field to an attacker-controlled endpoint, or, in the reverse scenario, disclose the way credentials are echoed to arbitrary hosts.
- **Archive extraction escape / storage escape**: The tar stream fetched from the (attacker-influenced) URL is extracted with the raw `tar` binary without the symlink/hardlink/absolute-path containment logic present in the codebase's other tar-extraction implementation, risking writes outside the intended repository directory depending on the `tar` binary/version behavior on the host.

### Likelihood Explanation
Requires only a valid Gitaly auth token (the same token used for all normal repository RPCs) — no special/administrative privilege is needed beyond what's needed to call any mutator RPC. This RPC is part of the normal repository-creation/import code path (`repoutil.Create` → `untar`), matching the "ordinary user... import" reachability criterion.

### Recommendation
- Restrict/allow-list destinations reachable via `HttpUrl` (e.g., only Gitaly-internal service addresses set by the server itself, never fully attacker-controlled).
- Do not forward attacker-supplied `Authorization` header content to an attacker-chosen host; if it must be supported, bind it to a validated, server-controlled endpoint only.
- Replace the raw `tar -xvf -` invocation with the same hardened Go-based extraction routine (`extractTarToDirectory`/`extractFile`) used in `replicate.go`, including absolute-path, symlink, and hardlink escape checks.

### Proof of Concept
1. Obtain a valid Gitaly auth token (standard token used for all RPCs).
2. Call `CreateRepositoryFromSnapshot` with:
   - `HttpUrl` pointing to an attacker-controlled HTTP server (or an internal service address).
   - `HttpAuth` set to a sensitive value.
3. Gitaly's server issues the HTTP GET to the attacker URL, forwarding the `HttpAuth` header (SSRF + credential exfiltration).
4. The attacker server responds with a crafted tar stream containing symlink/hardlink or path-escaping entries; because `untar` uses raw `tar -xvf -` with no path-confinement logic, files can be written outside the intended repository directory (archive extraction escape), unlike the hardened extraction path used elsewhere in Gitaly.

// extractTarToDirectory extracts a tar archive to the specified directory using Go's tar package
func (s *server) extractTarToDirectory(ctx context.Context, reader io.Reader, targetDir string) error {
	targetDir = filepath.Clean(targetDir)
	tarReader := tar.NewReader(reader)

	for {
		select {
		case <-ctx.Done():
			return ctx.Err()
		default:
		}

		header, err := tarReader.Next()
		if err == io.EOF {
			break // End of archive
		}
		if err != nil {
			return fmt.Errorf("reading tar header: %w", err)
		}

		targetPath := filepath.Join(targetDir, header.Name)

		if !strings.HasPrefix(targetPath, targetDir+string(os.PathSeparator)) &&
			targetPath != targetDir {
			return fmt.Errorf("invalid file path in tar: %s", header.Name)
		}

		switch header.Typeflag {
		case tar.TypeDir:
			if err := os.MkdirAll(targetPath, os.FileMode(header.Mode)); err != nil {
				return fmt.Errorf("creating directory %s: %w", targetPath, err)
			}

		case tar.TypeReg:
			if err := s.extractFile(ctx, tarReader, targetPath, header); err != nil {
				return fmt.Errorf("extracting file %s: %w", targetPath, err)
			}

		case tar.TypeSymlink:
			if filepath.IsAbs(header.Linkname) {
				return fmt.Errorf("absolute symlink not allowed: %s -> %s", header.Name, header.Linkname)
			}

			// Resolve the relative symlink target from the symlink's parent directory
			// and verify it stays within the extraction boundary, consistent with the
			// hard link validation below.
			resolvedTarget := filepath.Join(filepath.Dir(targetPath), header.Linkname)
			if !strings.HasPrefix(resolvedTarget, targetDir+string(os.PathSeparator)) &&
				resolvedTarget != targetDir {
				return fmt.Errorf("symlink target escapes extraction directory: %s -> %s", header.Name, header.Linkname)
			}
