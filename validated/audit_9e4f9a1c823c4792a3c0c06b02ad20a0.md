Now I have the full picture of `remove_value_of_size` in `core/store/src/trie/trie_storage.rs`. [1](#0-0) 

`remove_value_of_size` and `add_value_of_size` are purely internal bookkeeping helpers on `TrieCacheInner` — they just adjust `self.total_size` (a `u64` counter approximating the shard cache's memory footprint) by `entry_size(len) = len as u64 + PER_ENTRY_OVERHEAD`. This function never reads, compares, inlines, or dereferences any trie value; it doesn't touch `FlatStateValue::Ref`/`Inlined` variants at all. It's called from `put` and `pop` on eviction/insertion of cache entries to keep `total_size` in sync with what's actually cached, purely for enforcing the `total_size_limit` bound on the LRU shard cache [2](#0-1) .

The premise of the question — that this function is where "one path reads the inlined value and another the referenced one" — doesn't match the code. The actual inline-vs-reference decision logic lives in `FlatStateValue::on_disk`/`should_inline` in `core/primitives/src/state.rs` (threshold `INLINE_DISK_VALUE_THRESHOLD` = 4000 bytes) and in `Trie::get_optimized_ref` / `deref_optimized` in `core/store/src/trie/mod.rs`, which is documented to keep gas accounting and semantics identical regardless of which path serves the read, including a `debug_assert` that flat-storage and on-disk trie walks agree when recording is enabled. [3](#0-2) [4](#0-3) 

`remove_value_of_size` has no size-threshold branching, no inline/reference distinction, and no relation to extension-node length or key structure — it's just `total_size -= len + 100`. There is no code path here where inlined and referenced values could diverge, because this function doesn't compare or produce values at all — it merely tracks aggregate byte counts for cache eviction. An attacker's `storage_write`/`storage_remove`/`storage_read` calls can affect what gets cached and evicted (via `TrieCache::update_cache`, `put`, `pop`), but no combination of value sizes or key shapes can make this size-accounting function return or expose divergent value content, since it doesn't return or store a value at all — only a byte count is mutated.

    pub(crate) fn put(&mut self, key: CryptoHash, value: Arc<[u8]>) {
        while self.total_size > self.total_size_limit || self.cache.len() == self.cache.cap().get()
        {
            // First, try to evict value using the key from deletions queue.
            match self.deletions.pop() {
                Some(key) => match self.cache.pop(&key) {
                    Some(value) => {
                        self.metrics.shard_cache_pop_hits.inc();
                        self.remove_value_of_size(value.len());
                        continue;
                    }
                    None => {
                        self.metrics.shard_cache_pop_misses.inc();
                    }
                },
                None => {}
            }

            // Second, pop LRU value.
            self.metrics.shard_cache_pop_lru.inc();
            let (_, value) =
                self.cache.pop_lru().expect("Cannot fail because total size capacity is > 0");
            self.remove_value_of_size(value.len());
        }

        // Add value to the cache.
        self.add_value_of_size(value.len());
        match self.cache.push(key, value) {
            Some((evicted_key, evicted_value)) => {
                log_assert!(
                    key == evicted_key,
                    "LRU cache with shard_id = {}, is_view = {} can't be full before inserting key {}",
                    self.shard_id,
                    self.is_view,
                    key
                );
                self.remove_value_of_size(evicted_value.len());
            }
            None => {}
        };
    }

    /// Account consumed memory for a new entry in the cache.
    pub(crate) fn add_value_of_size(&mut self, len: usize) {
        self.total_size += Self::entry_size(len);
    }

    /// Remove consumed memory for an entry in the cache.
    pub(crate) fn remove_value_of_size(&mut self, len: usize) {
        self.total_size -= Self::entry_size(len);
    }

    /// Approximate memory consumption of LRU cache.
    pub fn current_total_size(&self) -> u64 {
        self.total_size
    }

    fn entry_size(len: usize) -> u64 {
