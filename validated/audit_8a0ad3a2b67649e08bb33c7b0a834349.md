### Title
Recovery pallet's `control_inherited_account` filter checks only the outer call, letting a malicious inheritor bypass restrictions via `Utility::batch` - (File: substrate/frame/recovery/src/lib.rs)

### Summary
`pallet_recovery`'s inheritance flow lets an `inheritor` account execute an arbitrary call as the recovered account through `control_inherited_account` [1](#0-0) . The pallet restricts which calls an inheritor can issue directly against the recovered account (e.g. it must not be able to `slash_attempt` a higher-priority friend group's pending recovery, and must not be able to wipe out `set_friend_groups`) — this is the exact analog of `GovernorAlpha.veto()` only inspecting the top-level proposal action targets. Just as a malicious proposer could add an action pointing at governance itself to make a proposal unvetoable, a malicious inheritor can wrap the forbidden inner call (`slash_attempt`, `set_friend_groups`) inside `pallet_utility::Call::batch` so that the surface-level filter only ever sees `Utility::batch { .. }` and never recurses into the nested call it is supposed to block.

### Finding Description
The regression tests in the repository directly demonstrate the intended invariant and its bypass:

- `inheritor_can_slash_higher_priority_attempts_and_remove_friend_groups` asserts that a lower-priority inheritor (FERDIE) must not be able to directly call `control_inherited_account` with `slash_attempt { friend_group_index: 0 }` or `set_friend_groups { friend_groups: vec![] }` to destroy a higher-priority family group's pending recovery attempt or wipe the friend-group configuration [2](#0-1) .
- `inheritor_cannot_bypass_filter_via_utility_batch` shows the same attacker (FERDIE) wrapping the identical `slash_attempt` call inside `pallet_utility::Call::batch { calls: vec![slash_call] }` and dispatching it through `control_inherited_account`. The comment in the test explicitly states: *"the batch dispatched as ALICE, but the inner slash should have still executed since our filter only checks the outer call"* [3](#0-2) .

This mirrors the `GovernorAlpha` veto bug precisely: the guard is a shallow, single-level match on the outer call variant (`RuntimeCall::Recovery(Call::slash_attempt {..})` vs. anything else), rather than a check that recurses through call-wrapping pallets such as `Utility::batch`/`batch_all`/`force_batch` (or `Proxy`/`Multisig`) before applying the restriction. Once the forbidden call is nested one level deeper, the filter's `match` falls through to the permissive branch and the inner call is dispatched with the recovered account's origin (`control_inherited_account` sets the origin to the recovered account before dispatching the boxed call), so `slash_attempt`/`set_friend_groups` executes with full effect.

### Impact Explanation
If this filter gap is real in the shipped pallet (the tests are written specifically to catch it, with `panic!("VULNERABILITY: ...")` / `panic!("BYPASS: ...")` messages), a minority/low-priority inheritor can:
- Force-slash a higher-priority friend group's security deposit, causing an honest initiator (BOB) to lose funds unbacked by any wrongdoing, and
- Destroy the `friend_groups` configuration for the lost account, permanently removing higher-priority recovery paths and effectively locking out the rightful inheritor.

Both outcomes are unbacked fund loss / permanent state lock caused entirely by an unprivileged account (the assigned inheritor of a lower-priority group), matching the "theft or unbacked... permanent user-fund... lock" impact class.

### Likelihood Explanation
The path requires no malicious peer, validator, collator, or governance actor — only a normal inheritor account of a friend group set up by the account owner, using the public `Utility::batch` wrapper, which is present in essentially every runtime that includes `pallet_recovery`. The wrapping technique (batch-wrap to dodge a shallow call-type filter) is trivial and requires no special timing or race condition.

### Recommendation
Make the restriction in `control_inherited_account` recurse into calls that can carry a nested `RuntimeCall` (at minimum `pallet_utility::{batch, batch_all, force_batch, as_derivative}`, and ideally any call implementing `GetDispatchInfo`/`IsSubType` wrapping) before permitting dispatch, or add an origin-level `CallFilter`/`add_filter` (similar to how `pallet_proxy` and `pallet_utility::batch_all` add filters to prevent nested `batch_all`) that is enforced for every call actually executed, not just the outermost one submitted by the inheritor.

### Proof of Concept
See `substrate/frame/recovery/src/tests.rs`:
- `inheritor_can_slash_higher_priority_attempts_and_remove_friend_groups` (lines 1354-1421) proves the direct call is correctly blocked.
- `inheritor_cannot_bypass_filter_via_utility_batch` (lines 1424-1477) proves the same call, wrapped in `Utility::batch`, is dispatched and executes the slash, bypassing the filter. [4](#0-3)

#[test]
fn inheritor_cannot_bypass_filter_via_utility_batch() {
	new_test_ext().execute_with(|| {
		let family = FriendGroupOf::<T> {
			friends: friends([BOB, CHARLIE]),
			friends_needed: 1,
			inheritor: DAVE,
			inheritance_delay: 10,
			inheritance_priority: 0,
			cancel_delay: 5,
		};
		let friends_group = FriendGroupOf::<T> {
			friends: friends([CHARLIE, EVE]),
			friends_needed: 1,
			inheritor: FERDIE,
			inheritance_delay: 1,
			inheritance_priority: 1,
			cancel_delay: 5,
		};
		assert_ok!(Recovery::set_friend_groups(signed(ALICE), vec![family, friends_group]));

		// Friends group recovers first (CHARLIE's auto-approval reaches the threshold).
		assert_ok!(Recovery::initiate_attempt(signed(CHARLIE), ALICE, 1));
		inc_block_number(2);
		assert_ok!(Recovery::finish_attempt(signed(EVE), ALICE, 1));
		assert_eq!(Recovery::inheritor(ALICE), Some(FERDIE));

		// Family initiates higher-priority attempt
		assert_ok!(Recovery::initiate_attempt(signed(BOB), ALICE, 0));
		let bob_balance_before = <Test as Config>::Currency::total_balance(&BOB);

		// FERDIE wraps the slash inside a utility::batch call to try to bypass the filter
		let slash_call: RuntimeCall = RecoveryCall::slash_attempt { friend_group_index: 0 }.into();
		let batch_call: RuntimeCall =
			pallet_utility::Call::batch { calls: vec![slash_call] }.into();
		assert_ok!(Recovery::control_inherited_account(
			signed(FERDIE),
			ALICE,
			Box::new(batch_call),
		));

		// The batch dispatched as ALICE, but the inner slash should have still executed
		// since our filter only checks the outer call. Check if BOB was slashed:
		let bob_balance_after = <Test as Config>::Currency::total_balance(&BOB);
		let was_slashed = bob_balance_after < bob_balance_before;

		if was_slashed {
			panic!(
				"BYPASS: recovery call filter was circumvented via utility::batch! \
				 BOB lost {} from security deposit slash.",
				bob_balance_before - bob_balance_after
			);
		}
	});
