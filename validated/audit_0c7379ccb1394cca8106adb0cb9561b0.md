### Title
Unchecked Return Value of `reduceAssetAmountV2` in `MarketSellAssetActuator.transferBalanceOrToken` - (File: actuator/src/main/java/org/tron/core/actuator/MarketSellAssetActuator.java)

### Summary
`MarketSellAssetActuator.transferBalanceOrToken` calls `AccountCapsule.reduceAssetAmountV2(...)` to debit the seller's TRC10 token balance when placing a sell order, but discards the boolean return value that indicates whether the deduction actually succeeded.

### Finding Description
`reduceAssetAmountV2` is designed to be a guarded, checked balance-mutation primitive: it only performs the subtraction and returns `true` if `amount > 0 && currentAmount != null && amount <= currentAmount`; otherwise it returns `false` and leaves the account's asset map untouched [1](#0-0) . Callers are expected to check this boolean, exactly as `TransferAssetActuator.execute` and `Commons.adjustAssetBalanceV2` do, both of which throw an exception when the call returns `false` [2](#0-1) [4](#0-3) .

`MarketSellAssetActuator.transferBalanceOrToken`, however, invokes `reduceAssetAmountV2` and ignores its result [3](#0-2) . This method is called unconditionally from `execute()` immediately before the order is created and persisted to `orderStore`/`marketAccountStore` [5](#0-4) . If the deduction silently fails (returns `false` without throwing), the order is still created and can later be matched or filled via `matchOrder`/`addTrxOrToken`, crediting the counterparty with tokens the seller never actually gave up.

### Impact Explanation
If `reduceAssetAmountV2` returns `false` while execution continues unchecked, the seller keeps their original token balance yet a matching order is created and — once matched — the buyer receives tokens via `addTrxOrToken`, and the seller may also receive the buyer's TRX/tokens. This produces an unbacked token/TRX credit and asset duplication, i.e., theft of funds or creation of unbacked balance in the token/TRX market, which is a fund-integrity issue in a broadcastable-transaction path (`MarketSellAssetContract`).

### Likelihood Explanation
`validate()` performs `assetBalanceEnoughV2` and other checks before `execute()` runs [6](#0-5) , which reduces the chance of `reduceAssetAmountV2` failing under normal conditions. Whether a state exists where `validate()` passes but `reduceAssetAmountV2` still returns `false` (e.g., due to state drift between the two calls, asset-ID/name inconsistency under `AllowSameTokenName` transitions, or a TOCTOU window) requires further scrutiny of the exact interaction between `assetBalanceEnoughV2` and `reduceAssetAmountV2`'s internal branching on `AllowSameTokenName`.

### Recommendation
Check the boolean return value of `reduceAssetAmountV2` in `transferBalanceOrToken` and throw a `ContractExeException` (mirroring the pattern in `TransferAssetActuator`) if it returns `false`, aborting order creation instead of silently proceeding.

### Proof of Concept
Not directly demonstrable without confirming a validate/execute state mismatch; the finding is based on static code-path analysis showing the unchecked call, matching the exact bug class described in the external report (unchecked boolean return of a balance-transfer function).

  public boolean reduceAssetAmountV2(byte[] key, long amount,
                                     DynamicPropertiesStore dynamicPropertiesStore, AssetIssueStore assetIssueStore) {
    importAsset(key);
    //key is token name
    boolean disableJavaLangMath = dynamicPropertiesStore.disableJavaLangMath();
    if (dynamicPropertiesStore.getAllowSameTokenName() == 0) {
      Map<String, Long> assetMap = this.account.getAssetMap();
      AssetIssueCapsule assetIssueCapsule = assetIssueStore.get(key);
      String tokenID = assetIssueCapsule.getId();
      String nameKey = ByteArray.toStr(key);
      Long currentAmount = assetMap.get(nameKey);
      if (amount > 0 && null != currentAmount && amount <= currentAmount) {
        this.account = this.account.toBuilder()
                .putAsset(nameKey, subtractExact(currentAmount, amount, disableJavaLangMath))
                .putAssetV2(tokenID, subtractExact(currentAmount, amount, disableJavaLangMath))
                .build();
        return true;
      }
    }
    //key is token id
    if (dynamicPropertiesStore.getAllowSameTokenName() == 1) {
      String tokenID = ByteArray.toStr(key);
      Map<String, Long> assetMapV2 = this.account.getAssetV2Map();
      Long currentAmount = assetMapV2.get(tokenID);
      if (amount > 0 && null != currentAmount && amount <= currentAmount) {
        this.account = this.account.toBuilder()
                .putAssetV2(tokenID, subtractExact(currentAmount, amount, disableJavaLangMath))
                .build();
        return true;
      }
    }

    return false;
  }
