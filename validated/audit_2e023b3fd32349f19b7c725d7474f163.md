### Title
`Pool.swap` charges swap fees for same-token synthetic swaps - (contracts/Pool.sol)

### Summary

`Pool.swap` does not reject calls where `syntheticTokenIn_ == syntheticTokenOut_`. A user can therefore burn a registered synthetic token and receive the same asset back after the configured swap fee is deducted. When `PoolRegistry.feeProvider.swapFees()` returns a non-zero fee for that pair, the user loses funds to the fee collector even though no economic exchange occurred.

### Finding Description

The public `swap` function only checks that both synthetic tokens are registered through `onlyIfSyntheticTokenExists`, that swapping is active, and that `amountIn_` is non-zero and within the caller’s balance. [1](#0-0) 

For an identity swap, `quoteSwapOut` queries the oracle for the same input and output asset and then deducts the configured swap fee from the quoted output. [2](#0-1) 

The caller’s full `amountIn_` is burned, the fee portion is minted to the pool’s fee collector, and only the remaining `_amountOut` is minted back to the caller. [3](#0-2) 

Metronome already recognizes this bug class elsewhere: `SmartFarmingManager._swap` explicitly bypasses external swapper calls when `tokenIn_ == tokenOut_` and returns the input unchanged. [4](#0-3) 

### Impact Explanation

A user calling `Pool.swap(syntheticToken, syntheticToken, amount)` unnecessarily pays the protocol swap fee and receives less of the same asset than was supplied. The loss is proportional to `amount` and `swapFees(syntheticToken, syntheticToken)`, and is transferred to the configured fee collector as synthetic-token supply. This is direct loss of user funds caused by a no-op conversion path.

### Likelihood Explanation

The function is permissionless and does not require privileged state, oracle manipulation, a malicious endpoint, flash loans, or attacker contracts. It can be reached accidentally by a malformed UI request, aggregator route, or direct contract call whenever the pool’s configured fee for the synthetic pair is non-zero. There is no `syntheticTokenIn_ != syntheticTokenOut_` precondition to prevent the transaction from succeeding.

### Recommendation

Add an explicit same-asset guard to `Pool.swap`:

```solidity
if (syntheticTokenIn_ == syntheticTokenOut_) revert IdenticalSyntheticTokens();
```

Alternatively, return `amountIn_` unchanged without burning and reminting, although rejecting the call is safer because it avoids silently accepting economically meaningless operations.

### Proof of Concept

The following Foundry fork test demonstrates the issue using the deployed Ethereum pool and a registered synthetic token. The route configuration associates this synthetic token with the pool. [5](#0-4) 

```solidity
// test/foundry/PoolSameTokenSwap.t.sol
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

import {Test} from "forge-std/Test.sol";

interface IERC20Like {
    function balanceOf(address) external view returns (uint256);
}

interface IPoolLike {
    function swap(
        address syntheticTokenIn_,
        address syntheticTokenOut_,
        uint256 amountIn_
    ) external returns (uint256 amountOut, uint256 fee);
}

contract PoolSameTokenSwapTest is Test {
    // Ethereum deployment from docs/routes.json.
    IPoolLike internal constant POOL =
        IPoolLike(0x3364f53cB866762Aef66DeEF2a6b1a17C1F17f46);

    // Registered msUSD synthetic token used by the documented route.
    address internal constant SYNTH =
        0xab5eB14c09D416F0aC63661E57EDB7AEcDb9BEfA;

    function testSameSyntheticSwapPaysFee() public {
        vm.createSelectFork(vm.envString("MAINNET_RPC_URL"));

        address user = makeAddr("user");
        uint256 amountIn = 1_000e18;

        deal(SYNTH, user, amountIn);

        uint256 before = IERC20Like(SYNTH).balanceOf(user);

        vm.prank(user);
        (uint256 amountOut, uint256 fee) =
            POOL.swap(SYNTH, SYNTH, amountIn);

        uint256 afterBalance = IERC20Like(SYNTH).balanceOf(user);

        assertEq(before - afterBalance, fee);
        assertEq(amountOut + fee, amountIn);
        assertGt(fee, 0);
        assertLt(amountOut, amountIn);
    }
}
```

Run with:

```bash
forge test --match-test testSameSyntheticSwapPaysFee -vvvv
```
