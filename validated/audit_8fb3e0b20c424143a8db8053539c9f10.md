## Title
QoS-tier bypass via connection-lifetime-cached stake in QUIC streamer - ([File: streamer/src/nonblocking/swqos.rs])

### Summary
`SwQos::build_connection_context` and `SimpleQos::build_connection_context` snapshot a peer's stake once, at QUIC connection establishment, via `get_connection_stake` [1](#0-0) . This snapshot (`ConnectionPeerType::Staked(stake)` / `total_stake`) is cached inside the `ConnectionContext` (`SwQosConnectionContext`/`SimpleQosConnectionContext`) and is never refreshed for the lifetime of the connection [2](#0-1) [3](#0-2) . This is structurally the same "verify once, trust forever" pattern flagged in the Wormhole report: a privileged classification is computed against mutable global state at admission time, then relied upon for all subsequent decisions without re-checking that state, even though the underlying state (stake) can and does change (unstaking, delegation changes, epoch boundary).

### Finding Description
On connection setup, `get_connection_stake` reads the current `StakedNodes` snapshot to determine the peer's stake and total stake [1](#0-0) . `SwQos::build_connection_context` uses this one-time reading to decide `peer_type` (`Staked(stake)` vs `Unstaked`) and stores `total_stake` in the connection context [4](#0-3) . That cached `peer_type`/`total_stake` then drives:
- `compute_max_allowed_uni_streams_with_rtt`, which sets `max_concurrent_uni_streams` for the QUIC connection based on the peer's proportional stake [5](#0-4) [6](#0-5) .
- `max_streams_per_throttling_interval`, which determines how many streams (transactions) per throttling window the connection is allowed via `StakedStreamLoadEMA::available_load_capacity_in_throttling_duration` [7](#0-6) [8](#0-7) .
- Priority to survive pruning: `ConnectionEntry::stake()` returns the peer type captured at connection-add time, and `prune_random` uses that stale value to decide which connections to evict when the staked table is full [9](#0-8) [10](#0-9) .

Nowhere in the connection's lifetime (which can span many epochs, since QUIC connections aren't force-closed on stake changes) is the stake re-verified against the live `StakedNodes` state. This mirrors the TemporalGovernor bug pattern: a state-dependent authorization check is performed once, and a decision made much later (here: every subsequent stream/packet admission and throttling decision, potentially over an unbounded connection lifetime) relies on that stale check instead of re-verifying against current state.

### Impact Explanation
A node that holds a large stake can open a QUIC connection, receive the high-stake QoS classification (larger `max_concurrent_uni_streams`, larger throttling allowance, resistance to `prune_random` eviction), and then have its stake reduced to zero (fully unstaked/deactivated) while keeping the connection open. The validator continues to grant it the original stake-weighted QoS tier indefinitely, i.e., an actor that is no longer an unprivileged staked participant retains privileged-tier packet-admission priority over genuinely staked or unstaked senders — a QoS evasion analogous to the "verification bypass by state change between check and use" described in the Wormhole finding. This can let a delisted/unstaked sender continue crowding out legitimate low-stake or unstaked senders' transaction throughput on the TPU ingest path.

### Likelihood Explanation
This requires only unprivileged actions reachable by any network peer: open a QUIC connection while staked (or with a validator identity that currently has stake), and keep the connection alive after the stake is reduced/removed. No special validator/operator role is required to trigger it — only ordinary participation in staking and TPU QUIC connectivity, which is within the "unprivileged-user" scope of the QUIC/UDP streamer component. The main constraint is how long connections normally live and whether periodic connection churn (idle timeouts, `prune_random`, `prune_oldest`) forces reconnection soon enough to bound the exposure window; the code as inspected does not perform any active re-verification tied to stake changes, so the staleness window is bounded only by connection lifetime/idle-timeout behavior, not by any explicit re-check.

### Recommendation
Periodically re-resolve `get_connection_stake` for open connections (e.g., on the `staked_nodes` update path or as part of the periodic connection-table maintenance already present for pruning/banning) and update the cached `peer_type`/`total_stake` in the connection context and `ConnectionEntry`, or close/downgrade connections whose backing stake has dropped below the threshold used at admission. At minimum, re-validate stake before granting further stream-throttling allowance rather than trusting the value captured at `build_connection_context` for the connection's full lifetime.

### Proof of Concept
1. Validator A holds sufficient stake to be classified `ConnectionPeerType::Staked(stake)` by `get_connection_stake` [1](#0-0) .
2. A opens a QUIC connection to the target node; `SwQos::build_connection_context`/`try_add_connection` computes and caches `total_stake`/`peer_type` and sets `max_concurrent_uni_streams` and stream-throttling allowance accordingly [11](#0-10) [12](#0-11) .
3. A's delegated stake is later withdrawn/deactivated (a normal, permissionless staking operation), so a fresh `get_connection_stake` lookup would now return `Unstaked`/zero.
4. A keeps the original connection open (no forced reconnection tied to stake changes exists in this code path).
5. All subsequent streams on that connection continue to be throttled/admitted using the original (now-stale) high-stake `SwQosConnectionContext`/`ConnectionEntry` values, granting A continued high-QoS treatment it is no longer entitled to.

    // Randomly selects sample_size many connections, evicts the one with the
    // lowest stake, and returns the number of pruned connections.
    // If the stakes of all the sampled connections are higher than the
    // threshold_stake, rejects the pruning attempt, and returns 0.
    pub(crate) fn prune_random(&mut self, sample_size: usize, threshold_stake: u64) -> usize {
        let num_pruned = std::iter::once(self.table.len())
            .filter(|&size| size > 0)
            .flat_map(|size| {
                let mut rng = rng();
                repeat_with(move || rng.random_range(0..size))
            })
            .map(|index| {
                let connection = self.table[index].first();
                let stake = connection.map(|connection: &ConnectionEntry<S>| connection.stake());
                (index, stake)
            })
            .take(sample_size)
            .min_by_key(|&(_, stake)| stake)
            .filter(|&(_, stake)| stake < Some(threshold_stake))
            .and_then(|(index, _)| self.table.swap_remove_index(index))
            .map(|(_, connections)| connections.len())
            .unwrap_or_default();
        self.total_size = self.total_size.saturating_sub(num_pruned);
        num_pruned
    }

fn compute_max_allowed_uni_streams_with_rtt(
    rtt_millis: u32,
    peer_type: ConnectionPeerType,
    total_stake: u64,
) -> u32 {
    let streams = match peer_type {
        ConnectionPeerType::Staked(peer_stake) => {
            // No checked math for f64 type. So let's explicitly check for 0 here
            if total_stake == 0 || peer_stake > total_stake {
                warn!(
                    "Invalid stake values: peer_stake: {peer_stake:?}, total_stake: \
                     {total_stake:?}"
                );

                QUIC_MIN_STAKED_CONCURRENT_STREAMS
            } else {
                let delta = (QUIC_TOTAL_STAKED_CONCURRENT_STREAMS
                    - QUIC_MIN_STAKED_CONCURRENT_STREAMS) as f64;

                (((peer_stake as f64 / total_stake as f64) * delta) as u32
                    + QUIC_MIN_STAKED_CONCURRENT_STREAMS)
                    .clamp(
                        QUIC_MIN_STAKED_CONCURRENT_STREAMS,
                        QUIC_MAX_STAKED_CONCURRENT_STREAMS,
                    )
            }
        }
        ConnectionPeerType::Unstaked => QUIC_MAX_UNSTAKED_CONCURRENT_STREAMS,
    };
    // scale amount of streams based on RTT if RTT is larger than REFERENCE_RTT_MS
    // multiply first then divide to avoid rounding errors.
    (streams.saturating_mul(rtt_millis.clamp(REFERENCE_RTT_MS, MAX_RTT_MS))) / REFERENCE_RTT_MS
}

impl QosController<SwQosConnectionContext> for SwQos {
    fn build_connection_context(&self, connection: &Connection) -> SwQosConnectionContext {
        let remote_address = connection.remote_address();
        get_connection_stake(connection, &self.staked_nodes).map_or(
            SwQosConnectionContext {
                peer_type: ConnectionPeerType::Unstaked,
                total_stake: 0,
                remote_pubkey: None,
                in_staked_table: false,
                remote_address,
                stream_counter: None,
                last_update: Arc::new(AtomicU64::new(timing::timestamp())),
            },
            |(pubkey, stake, total_stake)| {
                // The heuristic is that the stake should be large enough to have 1 stream pass through within one throttle
                // interval during which we allow max (MAX_STREAMS_PER_MS * STREAM_THROTTLING_INTERVAL_MS) streams.

                let peer_type = {
                    let max_streams_per_ms = self.staked_stream_load_ema.max_streams_per_ms();
                    let min_stake_ratio =
                        1_f64 / (max_streams_per_ms * STREAM_THROTTLING_INTERVAL_MS) as f64;
                    let stake_ratio = stake as f64 / total_stake as f64;
                    if stake_ratio < min_stake_ratio {
                        // If it is a staked connection with ultra low stake ratio, treat it as unstaked.
                        ConnectionPeerType::Unstaked
                    } else {
                        ConnectionPeerType::Staked(stake)
                    }
                };

                SwQosConnectionContext {
                    peer_type,
                    total_stake,
                    remote_pubkey: Some(pubkey),
                    in_staked_table: false,
                    remote_address,
                    last_update: Arc::new(AtomicU64::new(timing::timestamp())),
                    stream_counter: None,
                }
            },
        )
    }

    pub(crate) fn available_load_capacity_in_throttling_duration(
        &self,
        peer_type: ConnectionPeerType,
        total_stake: u64,
    ) -> u64 {
        match peer_type {
            ConnectionPeerType::Unstaked => self.max_unstaked_load_in_throttling_window,
            ConnectionPeerType::Staked(stake) => {
                if self.staked_throttling_enabled.load(Ordering::Relaxed) {
                    // 1 is added to `max_unstaked_load_in_throttling_window` to guarantee that staked
                    // clients get at least 1 more number of streams than unstaked connections.
                    self.max_staked_load_in_throttling_window
                        .saturating_mul(stake)
                        .checked_div(total_stake)
                        .unwrap_or(self.max_unstaked_load_in_throttling_window + 1)
                        .max(self.max_unstaked_load_in_throttling_window + 1)
                } else {
                    self.max_staked_load_in_throttling_window
                }
            }
        }
    }
