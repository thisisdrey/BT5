The code is clear enough to render a verdict. Let me verify one key detail about whether `create_token` is accessible post-transfer.

### Title
Original Collection Creator Bypasses Post-Transfer Minting Authorization via `create_token` — (`aptos-move/framework/aptos-token-objects/sources/token.move`)

---

### Summary

After transferring a collection created with `create_fixed_collection_as_owner`, the original creator retains the ability to mint tokens into that collection by calling `token::create_token` (or `create_numbered_token_object`, `create_named_token_object`, `create_named_token_from_seed`). These functions route through `create_common_with_collection`, which checks the static `Collection.creator` field — a field that is set at creation time and **never updated on transfer**. The `_as_owner` variants correctly check `collection.owner()`, but the original non-owner variants remain callable and bypass the post-transfer ownership invariant.

---

### Finding Description

`create_fixed_collection_as_owner` (and `create_unlimited_collection_as_owner`) explicitly enable ungated transfer of the collection object and document that "This transfers ownership and minting permissions to the new address." [1](#0-0) 

When the collection is transferred, the object's owner changes, but `Collection.creator` is a plain `address` field stored in the `Collection` resource and is never mutated: [2](#0-1) [3](#0-2) 

`create_common_with_collection` enforces only the stale creator check: [4](#0-3) 

While `create_common_with_collection_as_owner` correctly enforces the live owner check: [5](#0-4) 

The public entry points `create_token`, `create_numbered_token_object`, `create_named_token_object`, and `create_named_token_from_seed` all route through `create_common_with_collection`: [6](#0-5) 

These functions are `public fun` — callable from any transaction. The original creator can invoke them at any time after transfer, and the `Collection.creator == signer` assertion will always pass because `Collection.creator` is immutable.

---

### Impact Explanation

- **Unauthorized minting**: The original creator can mint token objects into a collection they sold/transferred, violating the new owner's exclusive minting rights.
- **Fixed-supply exhaustion**: For a `create_fixed_collection_as_owner` collection, the original creator can exhaust the remaining supply slots, permanently preventing the new owner from minting any further tokens.
- **Economic harm**: The new owner acquired the collection expecting exclusive minting control. The original creator can dilute or exhaust the collection without the new owner's consent.

This constitutes unauthorized minting of token objects — a direct asset impact on the new owner's on-chain property.

---

### Likelihood Explanation

The attack requires only that:
1. A collection was created with `create_fixed_collection_as_owner` or `create_unlimited_collection_as_owner` (the `collection_owner` feature flag is enabled on mainnet).
2. The collection was transferred to a new owner.
3. The original creator submits a transaction calling `token::create_token` with their own signer and the collection object.

All three conditions are normal, expected usage patterns. No privileged keys, governance access, or validator control are required.

---

### Recommendation

`create_common_with_collection` should be updated to additionally check whether the collection has ungated transfer enabled (i.e., was created as an owner-transferable collection). If so, it should enforce `collection.owner() == signer::address_of(creator)` instead of (or in addition to) the static `Collection.creator` check. Alternatively, the `create_token`, `create_numbered_token_object`, `create_named_token_object`, and `create_named_token_from_seed` functions should abort if the collection is an owner-transferable collection and the caller is not the current owner.

---

### Proof of Concept

```move
#[test(creator = @0x123, buyer = @0x456, aptos_framework = @aptos_framework)]
fun poc_original_creator_mints_after_transfer(
    creator: &signer, buyer: &signer, aptos_framework: &signer
) {
    features::change_feature_flags_for_testing(
        aptos_framework,
        vector[features::get_collection_owner_feature()],
        vector[]
    );

    // Step 1: Creator creates a transferable fixed collection
    let constructor_ref = collection::create_fixed_collection_as_owner(
        creator,
        string::utf8(b"desc"), 10,
        string::utf8(b"MyCollection"),
        option::none(),
        string::utf8(b"uri"),
    );
    let collection = object::object_from_constructor_ref<collection::Collection>(&constructor_ref);

    // Step 2: Creator transfers collection to buyer
    object::transfer(creator, collection, signer::address_of(buyer));
    assert!(collection.owner() == signer::address_of(buyer), 0);

    // Step 3: Original creator mints via create_token (uses Collection.creator check, not owner)
    // This should fail but SUCCEEDS — creator is no longer the owner
    token::create_token(
        creator, collection,
        string::utf8(b"desc"),
        string::utf8(b"UnauthorizedToken"),
        option::none(),
        string::utf8(b"uri"),
    );
    // Unauthorized token minted into buyer's collection
}
```
