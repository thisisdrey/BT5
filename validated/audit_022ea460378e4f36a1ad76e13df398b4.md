### Title
Nep245/Imt `TokenDiff` fee evasion via unit-splitting across multiple signed intents - (File: contracts/defuse/core/src/intents/token_diff.rs)

### Summary
`TokenDiff::token_fee` decides whether to charge the protocol fee purely from the `amount` declared *inside a single `TokenDiff` intent*, and explicitly returns `Pips::ZERO` whenever a Nep245/Imt token_in delta has `amount <= 1`. Because fee assessment is never aggregated across the intents in a batch or across a signer's total position, an attacker can decompose one large Nep245/Imt trade into N separately signed unit-delta `TokenDiff` intents and pay zero protocol fee on a trade that would otherwise be charged `fee_ceil(N)` if submitted as a single intent.

### Finding Description
Binding claimed to hold: for a Nep245 token `T` with total negative delta `-N` (`N>1`) moved by a signer, `Σ_{i=1}^{N} Pips::fee_ceil(1)` (fee charged when split into N unit intents) `==` `Pips::fee_ceil(N)` (fee charged for one unsplit intent). This binding is **false** in the code.

Root cause, in `contracts/defuse/core/src/intents/token_diff.rs`:
```
pub fn token_fee(token_id: impl Into<TokenIdType>, amount: u128, fee: Pips) -> Pips {
    let token_id = token_id.into();
    match token_id {
        TokenIdType::Nep141 => {}
        TokenIdType::Nep245 | TokenIdType::Imt if amount > 1 => {}
        // do not take fees on NFTs and MTs with |delta| <= 1
        TokenIdType::Nep171 | TokenIdType::Nep245 | TokenIdType::Imt => return Pips::ZERO,
    }
    fee
}

The engine's `Deltas`/`TransferMatcher` layer, which enforces the batch-wide zero-sum invariant, operates purely on raw per-token amounts and never revisits or recomputes fees; fees are baked in before the deltas even reach the matcher: [3](#0-2) [4](#0-3) 

Exploit flow: two accounts controlled by the same attacker, A and B, both hold Nep245 balances of token `T` (fungible-style multi-token, amount not limited to 1) and token `U`. Instead of signing one `TokenDiff` per account (`A: {T:-N, U:+M}`, `B: {T:+N, U:-M}`), which would each trigger `fee_ceil(N)`/`fee_ceil(M)` on the negative sides (since `amount>1`), the attacker signs N separate `TokenDiff` payloads per account, each with `delta == ±1` on `T` and `±(M/N)` on `U`. Each individual call to `token_fee` sees `amount<=1` and returns `Pips::ZERO`, so `fee_ceil` is `0` for every one of the N intents. The batch is submitted in one `execute_intents([payload_1..payload_2N])` call; the `TransferMatcher` still nets the deltas to zero across the whole batch (the invariant check does not care about intent granularity), so the batch succeeds while `fee_collector` receives nothing.

`simulate_intents`'s `StateOutput.fee` simply echoes the globally configured `Pips` rate via `self.fee()` — it is not a computed effective/aggregate fee for the batch, so it is not literally "wrong," but it also gives no signal that the effective collected fee for this batch is zero; it therefore cannot be relied upon by a counterparty to infer real fee collection for a split-intent batch. [5](#0-4) [6](#0-5) 

None of the existing guards (`MultiPayload::verify`, nonce/salt checks, `TransferMatcher::finalize` invariant, `#[pause]`) address this, because they only ensure signatures/nonces are valid and the batch nets to zero — they do not constrain intent granularity or aggregate per-token fee assessment across intents.

### Impact Explanation
`fee_collector`'s balance for `fees_collected` on Nep245/Imt token trades is permanently under-collected whenever a trade is decomposed into unit-delta intents, matching the explicit Critical category "protocol fees bypassed." The loss is proportional to `fee_ceil(N)` for whatever volume `N` the attacker chooses to route through unit-sized diffs, and is fully repeatable across any Nep245/Imt token and any number of trades — there is no cap other than gas/signing cost of N payloads in one transaction. The attacker's gain is the fee they would otherwise have paid; no victim funds are stolen (this is not "value leaving the Verifier that the signer never authorized" in the sense of theft), but the protocol's designed fee revenue is bypassed at will by any unprivileged signer trading (or self-trading across two of their own accounts) Nep245/Imt tokens.

### Likelihood Explanation
Preconditions are minimal: the attacker needs only Nep245/Imt token balances inside Defuse (obtainable by anyone via normal deposit) and the ability to sign and submit multiple `TokenDiff` payloads in a single `execute_intents` call, which is exactly the unprivileged capability granted to any caller. No special role, relayer key, or victim key is required — the two counter-parties can be two accounts the same attacker controls. Cost scales only with the number of intents N (signing + gas), which is well within normal transaction limits for moderate N (tens to low hundreds), so this is practical and repeatable, not merely theoretical.

### Recommendation
Compute the Nep245/Imt fee exemption based on the aggregate per-signer, per-token negative delta accumulated across the whole batch (or across the account's actual token supply/holding semantics), not on the per-intent declared `amount`. Alternatively, remove the `amount <= 1` special case for Nep245/Imt and instead determine fee-exemption from token metadata (e.g., an explicit "non-fungible" flag on the sub-token id) rather than from the transient delta size of a single intent, so that splitting a delta across multiple intents cannot change the total fee owed.

    pub fn finalize(self) -> Result<Transfers, InvariantViolated> {
        let mut transfers = Transfers::default();
        let mut deltas = TokenDeltas::default();
        for (token_id, transfer_matcher) in self.0 {
            if let Err(unmatched) = transfer_matcher.finalize_into(&token_id, &mut transfers)
                && (unmatched == 0 || deltas.apply_delta(token_id, unmatched).is_none())
            {
                return Err(InvariantViolated::Overflow);
            }
        }
        if !deltas.is_empty() {
            return Err(InvariantViolated::UnmatchedDeltas {
                unmatched_deltas: deltas,
            });
        }
