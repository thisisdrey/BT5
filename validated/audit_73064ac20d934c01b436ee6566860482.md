Audit Report

## Title
Reward-per-token accumulator in `pallet-asset-rewards` can overflow `T::Balance` when `total_tokens_staked` is dust, permanently freezing staked tokens - (File: `substrate/frame/asset-rewards/src/lib.rs`)

## Summary
`Pallet::<T>::reward_per_token` computes `reward_per_token_stored + reward_rate_per_block * blocks_elapsed * PRECISION_SCALING_FACTOR / total_tokens_staked` using `ensure_mul`/`ensure_add`/`ensure_div`, which return `Err` on overflow rather than saturating. [1](#0-0)  Because `total_tokens_staked` is fully attacker/staker-controllable via ordinary `unstake` calls and can be driven to a small dust value, and because the numerator grows unboundedly with elapsed blocks, this division can overflow `T::Balance`, causing `reward_per_token` to error out permanently for that pool.

## Finding Description
`reward_per_token` only special-cases an exactly-zero `total_tokens_staked` [2](#0-1) ; any nonzero dust amount goes through the full division. `PRECISION_SCALING_FACTOR` is a fixed constant (4096) that further inflates the numerator [3](#0-2) . `update_pool_and_staker_rewards` calls `reward_per_token` and propagates its error via `?` [4](#0-3) . All three user-facing extrinsics that mutate staker state call this function first: `stake` [5](#0-4) , `unstake` [6](#0-5) , and `harvest_rewards` [7](#0-6) . If the underlying `reward_per_token` errors, the whole extrinsic aborts atomically (no partial state change, but also no successful unfreeze), leaving the staker's tokens frozen via `T::AssetsFreezer` indefinitely, since the accumulator (`reward_per_token_stored`) is monotonically non-decreasing and the error condition only worsens as more blocks pass — there is no code path that resets or caps it, nor any minimum-stake floor guarding the division.

## Impact Explanation
Once triggered for a pool, no staker can `unstake`, `harvest_rewards`, or new stakers `stake` into that pool — this matches the "permanent user-fund … lock" impact category, since staked tokens remain frozen under `FreezeReason::Staked` with no recovery path in the current code (confirmed: no minimum-stake threshold, no accumulator reset/checkpoint logic exists in `reward_per_token`).

## Likelihood Explanation
Exploitability is gated by `T::Balance` typically being `u128` in production runtimes, so triggering the overflow requires an extreme configuration: a pool created with a very large `reward_rate_per_block` (set at `create_pool` time, gated by `CreatePoolOrigin`) combined with the pool being drained to near-zero `total_tokens_staked` by ordinary unprivileged staker `unstake` actions, and either a long elapsed-block window or aggressive draining. This is a narrower, harder-to-trigger condition than a `uint104`-bound analog, but the structural flaw (unbounded accumulator growth divided by a caller-influenced, un-floored total stake) is real and unmitigated in the reviewed code, with no privileged action required beyond legitimate pool parameter choices at creation.

## Recommendation
- Enforce a minimum non-dust `total_tokens_staked` threshold below which `reward_per_token` short-circuits to the last stored value instead of dividing.
- Bound or rate-limit `reward_rate_per_block` relative to a realistic minimum `total_tokens_staked`, or periodically checkpoint/reset the accumulator to prevent unbounded growth.
- Add regression tests exercising a pool drained to minimal stake with a high reward rate over many blocks to confirm `stake`/`unstake`/`harvest_rewards` do not become permanently unusable.

## Proof of Concept
1. `create_pool` with a very large `reward_rate_per_block` relative to `T::Balance::MAX`.
2. Staker calls `stake` with a small amount so `total_tokens_staked` is minimal (dust).
3. Advance many blocks (via `BlockNumberProvider`).
4. Call `unstake` or `harvest_rewards`: `reward_per_token` computes `reward_rate_per_block.ensure_mul(blocks_elapsed).ensure_mul(4096).ensure_div(total_tokens_staked)`, which overflows `T::Balance` and returns `Err`, aborting the extrinsic and leaving the staker's tokens frozen for that pool indefinitely.

		/// Derives the current reward per token for this pool.
		pub(super) fn reward_per_token(
			pool_info: &PoolInfoFor<T>,
		) -> Result<T::Balance, DispatchError> {
			if pool_info.total_tokens_staked.is_zero() {
				return Ok(pool_info.reward_per_token_stored);
			}

			let rewardable_blocks_elapsed: u32 =
				match Self::last_block_reward_applicable(pool_info.expiry_block)
					.ensure_sub(pool_info.last_update_block)?
					.try_into()
				{
					Ok(b) => b,
					Err(_) => return Err(Error::<T>::BlockNumberConversionError.into()),
				};

			Ok(pool_info.reward_per_token_stored.ensure_add(
				pool_info
					.reward_rate_per_block
					.ensure_mul(rewardable_blocks_elapsed.into())?
					.ensure_mul(PRECISION_SCALING_FACTOR.into())?
					.ensure_div(pool_info.total_tokens_staked)?,
			)?)
		}
