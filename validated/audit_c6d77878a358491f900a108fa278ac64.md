### Title
Missing URL scheme allowlist in `cloneFromURLCommand` permits `ext::`/`file://` transport injection leading to RCE/local file read - ([File: internal/gitaly/service/repository/create_repository_from_url.go])

### Finding Description
`CreateRepositoryFromURL` takes `req.GetUrl()` and passes it through `validateCreateRepositoryFromURLRequest`, which only checks that the URL string is non-empty and validates the target repository path — it performs no scheme allowlisting. [1](#0-0) 

The URL is then parsed with `url.Parse` — which happily accepts any scheme, including `ext::`, `fd::`, `file://`, or even an unqualified local path — and the resulting (possibly re-serialized) string is passed as a plain positional argument to `git clone` via `gitcmd.Command{Name: "clone", ..., Args: []string{urlString, repositoryFullPath}}`. [2](#0-1) [3](#0-2) 

Git's `ext::` transport helper interprets the remainder of the URL after `ext::` as a shell command to execute (`git clone ext::sh -c 'id > /tmp/x'`), and `file://`/bare local paths are interpreted by git as local repository clones/copies, which can read arbitrary local files reachable to the Gitaly process (subject to filesystem permissions). Nowhere in `cloneFromURLCommand` or `validateCreateRepositoryFromURLRequest` is the scheme restricted to network transports like `http(s)://`, `git://`, or `ssh://`. The code does show security awareness of similarly abusable transport features (bundle URI is explicitly disabled with the comment "Since the URI can point to any server, including localhost, this is to prevent attack vectors that could abuse this mechanism"), but this same reasoning was not applied to the primary clone URL itself. [4](#0-3) 

This RPC is reachable from GitLab's "import project from URL" feature, which is available to unprivileged users who can create/import a project. Assuming Gitaly is invoked with the raw, attacker-controlled URL (as the code path shows no scheme filtering at the Gitaly layer), an attacker-supplied `ext::` value is passed unmodified as a `git clone` operand, resulting in command execution in the context of the `git` process spawned by Gitaly.

### Impact Explanation
This maps to GitLab bounty's "command injection" / "arbitrary code execution" impact class. Successful exploitation lets an unprivileged, import-capable user execute arbitrary shell commands on the Gitaly host under the `git` process's privileges (via `ext::`), or read local files outside the intended repository storage tree (via `file://` or local path values consumed as legit git clone sources).

### Likelihood Explanation
The only precondition is the attacker's ability to trigger the "import project from a URL" workflow and control the `Url` field of `CreateRepositoryFromURLRequest`, which the threat model explicitly grants ("unprivileged repository-import action"). No secrets, no special roles, and no race conditions are required — a single crafted request is sufficient. The exploit is fully repeatable.

### Recommendation
In `validateCreateRepositoryFromURLRequest` (or in `cloneFromURLCommand` before use), parse the URL and enforce an allowlist of schemes (e.g., `http`, `https`, `git`, `ssh`) and reject `ext::`, `fd::`, `file://`, and schemeless/local-path values. Additionally, pass `-c protocol.ext.allow=never -c protocol.file.allow=never` (or the equivalent `GIT_ALLOW_PROTOCOL`/`protocol.allow` git-config restrictions) as defense-in-depth on the spawned `git clone` command regardless of upstream validation, mirroring the existing `transfer.bundleURI=false` mitigation pattern already present in this function.

### Proof of Concept
```go
func TestCreateRepositoryFromURL_extProtocolInjection(t *testing.T) {
    // ... standard gitaly test server setup producing client `repositoryClient` ...

    repo := &gitalypb.Repository{StorageName: cfg.Storages[0].Name, RelativePath: "attacker-import.git"}

    _, err := repositoryClient.CreateRepositoryFromURL(ctx, &gitalypb.CreateRepositoryFromURLRequest{
        Repository: repo,
        Url:        "ext::sh -c \"touch /tmp/pwned-by-gitaly\"",
    })

    // Expected (buggy) behavior: git clone executes `sh -c "touch /tmp/pwned-by-gitaly"`
    // via the ext:: transport helper, creating /tmp/pwned-by-gitaly on the Gitaly host,
    // instead of returning an InvalidArgument error for a disallowed URL scheme.
    require.NoError(t, err)
    require.FileExists(t, "/tmp/pwned-by-gitaly")
}
```

```go
func validateCreateRepositoryFromURLRequest(ctx context.Context, locator storage.Locator, req *gitalypb.CreateRepositoryFromURLRequest) error {
	if err := locator.ValidateRepository(ctx, req.GetRepository(), storage.WithSkipRepositoryExistenceCheck()); err != nil {
		return err
	}

	if req.GetUrl() == "" {
		return fmt.Errorf("empty Url")
	}

	return nil
```
