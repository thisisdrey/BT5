The Lixir Finance report describes an application-level Solidity bug: a broken EIP-2612 `permit` signature check that let an attacker reuse a fixed/dummy signature to gain approval over unrelated token holders (i.e., failure to bind the signature to a specific owner/nonce/deadline, or accepting a constant recovered signer). To find a genuine Go-stdlib analog, I examined the closest production signature-verification paths:

- `crypto/ecdsa.Verify` / `VerifyASN1` and the legacy/FIPS verify paths explicitly reject non-positive, out-of-range, and zero `r`/`s` values before doing the scalar math, and this is covered by dedicated tests (`TestZeroSignature`, `TestNegativeSignature`, `TestRPlusNSignature`, etc.). [1](#0-0) [2](#0-1) 
- The FIPS ECDSA `verifyGeneric` implementation independently rejects zero `r`/`s`. [3](#0-2) 
- `crypto/ed25519.VerifyWithOptions`/`verifyWithDom` enforce fixed signature length, canonical `S` encoding, and a full recomputation binding the signature to the specific public key and message (no dummy-signature bypass possible). [4](#0-3) 
- `crypto/x509.checkSignature`, which is the production caller that dispatches to these verifiers for certificate/CSR/CRL signature checks, does not skip or weaken any of these checks — it always calls the underlying `Verify`/`VerifyASN1`/`VerifyPKCS1v15` and treats any error/`false` as verification failure. [5](#0-4) 

None of these Go paths exhibit the Lixir-Finance-class flaw (accepting a fixed/reused signature independent of the actual signer/message/nonce). Each verifier cryptographically binds the signature to the specific hash and public key, and rejects degenerate (zero, negative, out-of-range, wrong-length) signature components — the exact classes of "broken permit signature" bypass described in the report. I found no unfixed, reachable analog in production Go code matching this bug class.

func verifyWithDom(pub *PublicKey, message, sig []byte, domPrefix, context string) error {
	if l := len(sig); l != signatureSize {
		return errors.New("ed25519: bad signature length: " + strconv.Itoa(l))
	}

	if sig[63]&224 != 0 {
		return errors.New("ed25519: invalid signature")
	}

	kh := sha512.New()
	if domPrefix != domPrefixPure {
		kh.Write([]byte(domPrefix))
		kh.Write([]byte{byte(len(context))})
		kh.Write([]byte(context))
	}
	kh.Write(sig[:32])
	kh.Write(pub.aBytes[:])
	kh.Write(message)
	hramDigest := make([]byte, 0, sha512Size)
	hramDigest = kh.Sum(hramDigest)
	k, err := edwards25519.NewScalar().SetUniformBytes(hramDigest)
	if err != nil {
		panic("ed25519: internal error: setting scalar failed")
	}

	S, err := edwards25519.NewScalar().SetCanonicalBytes(sig[32:])
	if err != nil {
		return errors.New("ed25519: invalid signature")
	}

	// [S]B = R + [k]A --> [k](-A) + [S]B = R
	minusA := (&edwards25519.Point{}).Negate(&pub.a)
	R := (&edwards25519.Point{}).VarTimeDoubleScalarBaseMult(k, minusA, S)

	if !bytes.Equal(sig[:32], R.Bytes()) {
		return errors.New("ed25519: invalid signature")
	}
	return nil
