### Title
Blind SSRF via unrestricted peer-advertised `data_url` used for outbound Stacks HTTP requests - (File: `stackslib/src/net/p2p.rs`, `stackslib/src/net/httpcore.rs`, `stackslib/src/net/chat.rs`)

### Summary
Any remote, unauthenticated-then-handshaking peer can advertise an arbitrary `data_url` (host:port) as its HTTP endpoint. The node accepts this value, resolves it to a `SocketAddr` with no restriction on loopback/link-local/private ranges, and then automatically issues real Stacks-protocol HTTP requests (mempool sync, attachment inventory, block/StackerDB fetches) to that address — a blind SSRF matching the CWE-918 class in the referenced `webfinger.js` advisory: an externally supplied "address" is used to build/target an outbound request with no host-class validation.

### Finding Description
When a peer's `HandshakeData`/`HandshakeAcceptData` is processed, the peer's self-reported HTTP endpoint is stored as `data_url` on the conversation object [1](#0-0) . This `data_url` is later resolved via `PeerNetwork::try_get_url_ip`, which special-cases the domain literal `"localhost"` (mapping it to `127.0.0.1`) but performs **no filtering at all** on numeric IP hosts — any IPv4/IPv6 literal (loopback, RFC1918/private, link-local `169.254.0.0/16`, etc.) is accepted verbatim and turned into a connect target: [2](#0-1) 

The same unrestricted resolution path is used for the general async DNS-based lookup in `ConversationP2P::try_decode_data_url_ipaddr` / DNS queue logic [3](#0-2) , and in the block/attachment downloader's `dns_lookups_begin` [4](#0-3) . Once a `SocketAddr` is obtained, several independent subsystems open real TCP+HTTP connections to it without any additional host-class check:

- `PeerNetwork::connect_or_send_http_request` → `HttpPeer::connect_http` → `NetworkState::connect` [5](#0-4) [6](#0-5) .
- Mempool sync (`mempool_sync_send_query`) builds and sends a real HTTP POST to the resolved address [7](#0-6) .
- The attachment/block downloader's `begin_request` connects to every resolved socket address for a peer-supplied URL [8](#0-7) .
- Authenticated-peer RPC (`neighbors::rpc::send_request`/`get_peer_host`) likewise trusts `convo.data_url` unconditionally [9](#0-8) .

I searched the in-scope `stackslib/src/net/**` tree for any private/loopback/reserved-address filtering (`is_private`, `is_loopback`, deny-lists, etc.) and found none applicable to outbound P2P HTTP targets — the only "private"/"reserved" hits in the module are unrelated (HTTP cache-control headers). This confirms the equality that should hold — "the address we connect to is the peer's externally reachable service" — is not enforced; the trust boundary between "attacker-supplied string" and "resolvable network target" is broken exactly as in the `webfinger.js` report, just without the additional path-injection component (the request path here is fixed by the node's own code, only host:port is attacker-controlled).

### Impact Explanation
Any peer participating in the P2P network (no special privilege beyond completing a handshake, which any remote party can do) can force a victim node to originate outbound HTTP connections to arbitrary internal/loopback/link-local addresses reachable from the victim's host or LAN (e.g., `127.0.0.1:<port>`, RFC1918 addresses, `169.254.169.254` cloud-metadata endpoints). This is a classic blind SSRF: the victim node acts as a proxy that can be steered to probe or interact with services that are not otherwise reachable from the public network. Because multiple independent subsystems (mempool sync, attachment/block downloader, neighbor RPC) reuse this same unchecked resolution path, the blast radius spans several core networking components, not a single isolated feature.

### Likelihood Explanation
High likelihood of exploitability: it requires only a normal, unauthenticated P2P handshake (any node can initiate one) and setting the peer's own `data_url` handshake field to a chosen host:port — no elevated privileges, no signature forgery, and no race condition. The complete absence of any private/loopback address filtering in the resolution path (`try_get_url_ip`, DNS resolution in `chat.rs`/`epoch2x.rs`) makes this trivially reachable by design rather than by chance.

### Recommendation
Add an explicit deny-list/allow-list check immediately after resolving a peer-supplied `data_url` to a `SocketAddr` (in `PeerNetwork::try_get_url_ip`, the DNS-resolution completion paths in `chat.rs`/`epoch2x.rs`, and before any `connect_http`/`TcpStream::connect` call), rejecting loopback, link-local, and (optionally, configurable for private test networks) RFC1918 private ranges unless explicitly whitelisted by node operators.

### Proof of Concept
1. Stand up a target internal service on the victim node's host or LAN, e.g. `python3 -m http.server 8000` bound to `127.0.0.1` or a private LAN IP.
2. As a remote peer, complete a normal P2P handshake with the victim node and set the `HandshakeData.data_url` field to `http://127.0.0.1:8000` (or any private/link-local address reachable from the victim).
3. Trigger any workflow that causes the victim to contact the peer's advertised HTTP endpoint — e.g. wait for mempool sync (`mempool_sync_send_query`) or an attachment-inventory/block-download cycle for that peer.
4. Observe (via the internal service's own logs) that the victim node's outbound HTTP request (with a Stacks-protocol path such as `/v2/mempool/...` or `/v2/attachments/inv?...`) is delivered to the internal/loopback address — confirming the SSRF, since no code path rejects non-public target addresses derived from `data_url`.

    pub fn connect_or_send_http_request(
        &mut self,
        data_url: UrlString,
        addr: SocketAddr,
        request: StacksHttpRequest,
    ) -> Result<usize, NetError> {
        PeerNetwork::with_network_state(self, |ref mut network, ref mut network_state| {
            PeerNetwork::with_http(network, |ref mut network, ref mut http| {
                match http.connect_http(
                    network_state,
                    network,
                    data_url.clone(),
                    addr,
                    Some(request.clone()),
                ) {
                    Ok(event_id) => Ok(event_id),
                    Err(NetError::AlreadyConnected(event_id, _)) => {
                        if let (Some(ref mut convo), Some(ref mut socket)) =
                            http.get_conversation_and_socket(event_id)
                        {
                            convo.send_request(request)?;
                            HttpPeer::saturate_http_socket(socket, convo)?;
                            Ok(event_id)
                        } else {
                            debug!("HTTP failed to connect to {data_url}, {addr:?}");
                            Err(NetError::PeerNotConnected(format!(
                                "HTTP failed to connect to {data_url}, {addr:?}",
                            )))
                        }
                    }
                    Err(e) => Err(e),
                }
            })
        })
    }

    pub fn connect_http(
        &mut self,
        network_state: &mut NetworkState,
        network: &PeerNetwork,
        data_url: UrlString,
        addr: SocketAddr,
        request: Option<StacksHttpRequest>,
    ) -> Result<usize, net_error> {
        if let Some(event_id) = self.find_free_conversation(&data_url) {
            let http_nk = NeighborKey {
                peer_version: network.burnchain.peer_version,
                network_id: network.local_peer.network_id,
                addrbytes: PeerAddress::from_socketaddr(&addr),
                port: addr.port(),
            };
            return Err(net_error::AlreadyConnected(event_id, http_nk));
        }

        let sock = NetworkState::connect(
            &addr,
            network.connection_opts.socket_send_buffer_size,
            network.connection_opts.socket_recv_buffer_size,
        )?;
        let hint_event_id = network_state.next_event_id()?;
        let next_event_id =
            network_state.register(self.http_server_handle, hint_event_id, &sock)?;

        self.connecting.insert(
            next_event_id,
            (sock, Some(data_url), request, get_epoch_time_secs()),
        );
        Ok(next_event_id)
    }
