Based on the evidence gathered, I found a concrete local analog in the `bags-list`/`staking-async` interaction, documented in the repository's own changelog.

### Title
Chilled stakers retain a stale score/position in `pallet-bags-list`, mirroring the "poke bypass" bug class - (File: `substrate/frame/bags-list/src/lib.rs`)

### Summary
The external report's core broken invariant is: a periodic "poke" mechanism is supposed to re-sync a position's weight/eligibility with its live source of truth, but a code path that shares logic with a normal state-changing action (vote) can leave a stale, favorable value permanently un-recomputed once the reference data becomes invalid (disabled). The same broken invariant exists between `pallet-staking-async`'s chill logic and `pallet-bags-list`'s `rebag`/`on_remove` mechanism.

### Finding Description
In `pallet-bags-list`, `rebag_internal` is the function that re-syncs an account's list position with its live score from `T::ScoreProvider` [1](#0-0) . This function underlies both the permissionless `rebag` extrinsic and the `on_idle` auto-rebag loop [2](#0-1) , i.e., it is the "poke" primitive for the voter list, exactly analogous to `Voter._vote()` being reused as VotingEscrow's poke primitive.

The repository's own prdoc for `pallet-staking-async` documents that this poke path was broken: previously, `staking` always issued `T::VoterList::on_remove` when an account called `chill`, guaranteeing removal from the bags-list. Additionally, an older `rebag` implementation only adjusted the score of *existing* nodes and could not add or remove nodes. A later change added a `Lock` capability to block bags-list mutation during the election snapshot phase and, to compensate, `rebag` was rewritten to also add/remove nodes — which reintroduced the gap: a chilled staker (who is no longer a validator or nominator and should have no score) can retain a spot in the bags-list with a stale, non-zero score, "preventing other legit nominators/validators from taking their place" [3](#0-2) .

This is structurally identical to the VotingEscrow bug: an account performs an ordinary state-changing action (chill / vote-for-a-soon-disabled-vault) whose effect on the shared list/vault is supposed to be reflected by the generic "sync" operation (`rebag` / poke), but a change elsewhere in the system (Lock during snapshot / killBribeVault) causes that generic sync operation to no longer correctly evict or zero out the stale entry, so the account keeps an undue slot/weight it should have lost.

### Impact Explanation
Retaining an undeserved slot in the bags-list means the account can continue to occupy an approximate-score bucket used by the election system for candidate/voter selection, displacing legitimately active nominators or validators from being considered, and skewing the semi-sorted linked list used to bound iteration costs for the multi-block election provider. This degrades correct election outcomes on a live chain, matching the "runtime bugs that compromise intended behavior" impact category.

### Likelihood Explanation
Medium/Low: exploitation requires a chill call combined with the bags-list being in the `Lock`ed state (i.e., during an election snapshot window) so that the compensating add/remove path in `rebag` is exercised incorrectly, per the prdoc's own root-cause description [4](#0-3) . No privileged/governance action is required — only the timing coincidence of a normal chill during a locked snapshot window, unlike the original external report which required a governance proposal to land at just the right time.

### Recommendation
Ensure `chill`/any transition that makes an account ineligible (`T::ScoreProvider::score` returning `None`) is unconditionally reflected by removing the account from the bags-list, regardless of `Lock` state — either by queuing the removal in `PendingRebag` (as already done for insertions during `Lock`, see `on_insert`) [5](#0-4)  or by making `on_remove` bypass the lock the same way removal-on-chill historically did, so a chilled account can never retain a stale score/slot.

### Proof of Concept
1. Staker `S` is an active nominator with a nonzero score/slot in `pallet-bags-list`.
2. The election snapshot phase begins; `Lock::<T,I>::put(())` is set, so `ensure_unlocked()` starts failing [6](#0-5) .
3. `S` calls `chill` in `pallet-staking-async`; because the list is locked, the removal that `on_remove`/`rebag_internal` would normally perform for a now-scoreless account does not take effect immediately (per the documented root cause in `pr_9926.prdoc`).
4. `S` retains their bags-list node/slot with a stale nonzero score through the remainder of the locked snapshot window, occupying a position that should belong to an active nominator/validator, exactly mirroring Alice's vote on a soon-to-be-disabled vault preserving her stale, undecaying voting weight.

	fn rebag_internal(account: &T::AccountId) -> Result<Option<(T::Score, T::Score)>, Error<T, I>> {
		// Ensure the pallet is not locked
		Self::ensure_unlocked().map_err(|_| Error::<T, I>::Locked)?;

		PendingRebag::<T, I>::remove(account);

		// Check if the account exists and retrieve its current score
		let existed = ListNodes::<T, I>::contains_key(account);
		let maybe_score = T::ScoreProvider::score(account);

		match (existed, maybe_score) {
			(true, Some(current_score)) => {
				// The account exists and has a valid score, so try to rebag
				log!(debug, "Attempting to rebag node {:?}", account);
				Pallet::<T, I>::do_rebag(account, current_score)
					.map_err::<Error<T, I>, _>(Into::into)
			},
			(false, Some(current_score)) => {
				// The account doesn't exist, but it has a valid score - insert it
				log!(debug, "Inserting node {:?} with score {:?}", account, current_score);
				List::<T, I>::insert(account.clone(), current_score)
					.map_err::<Error<T, I>, _>(Into::into)?;
				Ok(None)
			},
			(true, None) => {
				// The account exists but no longer has a valid score, so remove it
				log!(debug, "Removing node {:?}", account);
				List::<T, I>::remove(account).map_err::<Error<T, I>, _>(Into::into)?;
				Ok(None)
			},
			(false, None) => {
				// The account doesn't exist and has no valid score - do nothing
				Err(Error::<T, I>::List(ListError::NodeNotFound))
			},
		}
	}
