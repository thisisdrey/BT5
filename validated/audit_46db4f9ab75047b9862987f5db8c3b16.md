### Title
Protocol fee on `Nep245`/`Imt` `TokenDiff` legs can be bypassed by splitting an aggregate delta into unit (`|delta| == 1`) legs across multiple intents in one signed payload - (`contracts/defuse/core/src/intents/token_diff.rs`)

### Summary
`TokenDiff::token_fee` exempts `Nep245`/`Imt` legs from any fee when the per-intent `amount <= 1`. Because fees are computed independently for each `TokenDiff` intent rather than on the aggregate delta of a token across a batch, an attacker can split one large `Nep245` outgoing delta into many single-unit `TokenDiff` intents inside the same signed `MultiPayload`, each paying zero fee, while an equivalent single `TokenDiff` with the same aggregate `|delta|` would pay `protocol_fee.fee_ceil(amount)`.

### Finding Description
The binding that should hold is:

`sum_over_batch(fee_collected for token T)` == `protocol_fee.fee_ceil(aggregate_negative_delta_of_T)`

but the actual code computes fee independently per `TokenDiff` intent execution: [1](#0-0) 

using: [2](#0-1) 

The guard `TokenIdType::Nep245 | TokenIdType::Imt if amount > 1 => {}` only lets the fee apply when the *single intent's* `amount > 1`; otherwise it falls through to `return Pips::ZERO`. Since `TokenDiff::diff` is a `BTreeMap<TokenId, i128>` (one entry per token per intent), an attacker cannot express two `-1` legs for the same token inside a single `TokenDiff`; but nothing prevents submitting N separate `TokenDiff` intents (each with `delta == -1` on the same `Nep245` token, and any matching counter-leg to keep the intent non-empty) inside one signed `MultiPayload`/intents batch. `execute_intents` invokes `TokenDiff::execute_intent` once per intent, and each call independently computes `token_fee(token_id, 1, protocol_fee) == Pips::ZERO`, so `fee_ceil(1) == 0` for every leg. Summed across N legs, `fees_collected == 0` for token T, even though the aggregate outgoing amount is N and a single `TokenDiff` with `delta == -N` would have paid `protocol_fee.fee_ceil(N) > 0`.

No existing guard (`verify_intent_nonce`, `MaybeLegacyNonces::commit`, `TransferMatcher::finalize`, etc.) aggregates deltas across intents for fee purposes; nonce/replay checks are unrelated to per-token fee accounting, and `internal_add_balance(fee_collector, fees_collected)` only adds whatever `fees_collected` map yields, which is zero here.

### Impact Explanation
The `fee_collector` is under-paid: it should receive `protocol_fee.fee_ceil(N)` for a net `Nep245`/`Imt` outflow of size `N` from the signer, but receives `0` when the same outflow is split into N unit legs. The counterparty on the other side of the swap effectively receives the full 1:1 exchange at zero protocol cost. This is repeatable by any unprivileged signer, on any `Nep245`/`Imt` token they hold, for any batch size, and scales linearly with N (the larger the split, the more fee is bypassed), matching the Critical category "protocol fees bypassed."

### Likelihood Explanation
Preconditions are minimal and fully within an unprivileged signer's control: they need sufficient `Nep245` balance to cover the aggregate outgoing amount (which they already need for the equivalent single-leg trade), a nonzero `fee_collector` `Pips` configuration (already assumed by the audit scope), and the ability to construct a `MultiPayload` with N `TokenDiff` intents instead of one — a purely client-side payload construction change with no additional cost besides slightly larger transaction size. This is trivially reproducible and repeatable.

### Recommendation
Aggregate the fee computation for `Nep245`/`Imt` tokens by the token's net amount across all intents in the batch (or, at minimum, base the `amount > 1` fee-exemption threshold on the total transferred amount per token across the transaction rather than per individual intent leg), so that splitting a delta into unit legs cannot change the total fee owed for a given aggregate outgoing amount.

### Proof of Concept
Add a `cargo test` in `contracts/defuse/core/src/intents/token_diff.rs` (or an engine-level integration test) that:
1. Sets `protocol_fee = Pips::ONE_PERCENT` (or any nonzero `Pips`).
2. Executes a single `TokenDiff` with `delta = -100` on a `Nep245` token (plus an offsetting positive leg on another token) via `TokenDiff::execute_intent`, and records `fees_collected` for the `Nep245` token — expect `fees_collected > 0` (`== protocol_fee.fee_ceil(100)`).
3. Executes 100 separate `TokenDiff` intents, each with `delta = -1` on the same `Nep245` token (each paired with its own offsetting positive leg), via 100 calls to `TokenDiff::execute_intent` within the same engine/batch, and sums `fees_collected` for that token across all 100 calls — expect the sum to equal `0`.
4. Assert `fees_collected_single_leg != fees_collected_split_legs_sum` (specifically, `fees_collected_split_legs_sum == 0 < fees_collected_single_leg`), demonstrating the binding violation.
