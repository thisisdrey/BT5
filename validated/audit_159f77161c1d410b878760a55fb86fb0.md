### Title
Unauthenticated `/shutdown` and event endpoints on the signer's `SignerEventReceiver` HTTP listener allow any reachable client to halt signer event processing - (File: libsigner/src/events.rs)

### Summary
`SignerEventReceiver`, the HTTP server the `stacks-signer` binds to receive push events from its associated Stacks node (`/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block`, `/shutdown`), performs no authentication whatsoever on incoming requests. Any client that can reach the bound socket can send a single unauthenticated `POST /shutdown` and immediately terminate the receiver's main loop, which requires the signer process to be restarted to resume participating in block signing.

### Finding Description
`SignerEventReceiver::next_event` dispatches on the URL path with no credential check of any kind: [1](#0-0) . Notably the `/shutdown` branch immediately flips the stop flag and returns `Terminated`, which stops `main_loop` on the next iteration: [2](#0-1)  and [3](#0-2) .

This directly parallels the CWE-306 "missing authentication for a critical function" class in the rclone advisory: rclone's `rcd --rc-serve` listener processed unauthenticated requests that reached privileged code paths (backend init / command execution) because auth was optional and off by default. Here, the signer's event HTTP listener (`bind()` opens a plain `HttpServer::http(listener)` with no auth middleware: [4](#0-3) ) accepts a privileged control command (`/shutdown`) from any client that can reach the socket, with zero authentication gate — there is no equivalent of `--rc-user`/`--rc-pass` for this listener at all. Unlike the node's RPC endpoints (`postblock_v3`, `postblock_proposal`, `blockreplay`, etc.), which all enforce a shared-secret `authorization` header comparison before acting ( [5](#0-4) ), the signer's own event-ingestion HTTP server has no such gate on any of its routes, including the process-control `/shutdown` route.

The `endpoint` config for the signer is frequently documented/configured as `127.0.0.1:30000` in sample configs ( [6](#0-5) ), but nothing in `stacks-signer` or `libsigner` enforces loopback-only binding or checks the origin of connections — an operator who binds the signer's endpoint to a routable interface (e.g., to run the signer on a separate host from the node, a documented/expected topology) exposes this unauthenticated shutdown primitive to the network. The `SpawnedSigner` code even carries an explicit warning about this exact risk without providing any code-level mitigation: [7](#0-6) .

### Impact Explanation
Any unauthenticated client that can reach the signer's event port can issue a single `POST /shutdown` HTTP request to permanently stop that signer's event receiver loop, cutting off its ability to receive `stackerdb_chunks`, `proposal_response`, and `burn_block` events from its node until the operator manually restarts the process. Because signer nodes are relied upon for Nakamoto block signing consensus, disabling event ingestion for even a single signer degrades its ability to participate in signing rounds — and if reachable across multiple signers (e.g., a common misconfiguration or shared network segment), this is a low-cost, single-request DoS primitive against block-signing availability. This matches the "Critical - remote crash/unauthenticated DoS from few messages" bar.

### Likelihood Explanation
Exploitation requires only network reachability to the configured `endpoint` and a single crafted HTTP POST — no cryptographic material, node secret, or privileged role is needed. The main mitigating factor is that sample configs bind to `127.0.0.1`, but this is a convention, not an enforced control, and the codebase itself acknowledges (via the warning in `stacks-signer/src/lib.rs`) that operators sometimes expose this endpoint beyond localhost.

### Recommendation
Require the signer's `SignerEventReceiver` to authenticate incoming requests (e.g., verify the same `auth_token`/`Authorization` header scheme already used for the node's RC/RPC endpoints in `stackslib/src/net/api/*`) before acting on any endpoint, and in particular before honoring `/shutdown`. Alternatively/additionally, enforce loopback-only binding by default and require an explicit opt-in plus mandatory auth token when binding to a non-loopback address.

### Proof of Concept
Against a signer whose `endpoint` is reachable (e.g., `0.0.0.0:30000` or any routable interface):
```
POST /shutdown HTTP/1.1
Host: <signer-host>:30000
Content-Length: 0

```
This single unauthenticated request causes `SignerEventReceiver::next_event` to set the stop signal and return `EventError::Terminated`, terminating the event receiver's `main_loop` ( [2](#0-1) ), matching the exact mechanism the codebase's own `SignerStopSignaler::send` uses internally to shut the receiver down ( [8](#0-7) ) — except performed by an unauthenticated remote party instead of the local process.

    fn main_loop(&mut self) {
        loop {
            if self.is_stopped() {
                info!("Event receiver stopped");
                break;
            }
            let next_event = match self.next_event() {
                Ok(event) => event,
                Err(EventError::UnrecognizedEvent(..)) => {
                    // got an event that we don't care about (not a problem)
                    continue;
                }
                Err(EventError::Terminated) => {
                    // we're done
                    info!("Caught termination signal");
                    break;
                }
                Err(e) => {
                    warn!("Failed to receive next event: {:?}", &e);
                    continue;
                }
            };
            if !self.forward_event(next_event) {
                info!("Failed to forward event");
                break;
            }
        }
        info!("Event receiver main loop exit");
    }

    fn next_event(&mut self) -> Result<SignerEvent<T>, EventError> {
        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)
            } else if request.url() == "/new_block" {
                process_event::<T, StacksBlockEvent>(request)
            } else {
                let url = request.url().to_string();
                debug!(
                    "[{:?}] next_event got request with unexpected url {}, return OK so other side doesn't keep sending this",
                    event_receiver.local_addr,
                    url
                );
                ack_dispatcher(request);
                Err(EventError::UnrecognizedEvent(url))
            }
        })?
