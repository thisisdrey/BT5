### Title
Protocol fees bypassed on NEP-245/IMT `TokenDiff` intents via unit-splitting - ([File: contracts/defuse/core/src/intents/token_diff.rs])

### Summary
`TokenDiff::token_fee` waives protocol fees whenever the per-intent `|delta|` for a NEP-245/IMT token is `<= 1`, and `TokenDiff::execute_intent` computes and collects fees strictly per-intent, with no aggregation across the multiple `TokenDiff` intents that can appear in a single `MultiPayload` batch (or across separate `execute_intents` calls). A signer can therefore replace one `TokenDiff` intent moving `N` units of a NEP-245/IMT token_in with `N` separate `TokenDiff` intents each moving `1` unit, driving the collected fee to `0` regardless of `N` or `protocol_fee`.

### Finding Description
The binding that should hold is:
`sum(fees_collected over the N unit-legs) == Pips::fee_ceil(protocol_fee, N)` for an equivalent single `TokenDiff` with `delta = -N` on the same NEP-245/IMT `token_id`.

In `TokenDiff::execute_intent` (contracts/defuse/core/src/intents/token_diff.rs:59-78), for each `(token_id, delta)` in the intent's own diff map:
```rust
if *delta < 0 {
    let amount = delta.unsigned_abs();
    let fee = Self::token_fee(token_id, amount, protocol_fee).fee_ceil(amount);
    fees_collected.add(token_id.clone(), fee)...
}
```
`amount` is scoped to *this single intent's* delta, and `Self::token_fee` (contracts/defuse/core/src/intents/token_diff.rs:206-216) explicitly zeroes the fee for `Nep245`/`Imt` types when `amount <= 1`:
```rust
TokenIdType::Nep245 | TokenIdType::Imt if amount > 1 => {}
TokenIdType::Nep171 | TokenIdType::Nep245 | TokenIdType::Imt => return Pips::ZERO,
fee
```
Since `Intent::execute_intent` (contracts/defuse/core/src/intents/mod.rs:115-145) dispatches each `TokenDiff` in the batch independently, and each call to `TokenDiff::execute_intent` starts its own local `fees_collected` with no shared state or memory of prior intents from the same signer/token in the batch (or across separate transactions), there is nothing that aggregates the `amount` used for the `> 1` check across multiple intents.

Exploit: an attacker holding `N` units of a NEP-245/IMT `token_id` signs `N` distinct `TokenDiff` intents (each with `diff = {token_id: -1, token_out: +k}`), matched in the same `MultiPayload` by counterparty intent(s) supplying the offsetting `+N`/`-N*k` legs (a real counterparty or the attacker's own second account, since NEP-245/IMT `token_in` fee-liability only depends on the negative-delta side). Each of the `N` legs independently hits `amount == 1`, so `token_fee` returns `Pips::ZERO` for every leg, and the total `fees_collected` deposited to `fee_collector` is `0`. The equivalent single `TokenDiff{ token_id: -N, token_out: +N*k }` would compute `amount = N > 1`, use the real `protocol_fee`, and collect `Pips::fee_ceil(protocol_fee, N) > 0`.

No existing guard prevents this: `MultiPayload::verify`, nonce/salt checks, and the `TransferMatcher`/invariant only enforce that the batch's net token deltas sum to zero across all signers — they do not constrain how a single signer's total per-token exposure is chunked across intents, and fee computation has no cross-intent or cross-transaction memory. The `amount <= 1` exemption is intended for atomic NFT-like items (comment: "do not take fees on NFTs and MTs with |delta| <= 1"), but nothing stops a signer from artificially chunking a bulk semi-fungible NEP-245/IMT transfer into unit-sized legs to invoke that exemption `N` times.

### Impact Explanation
Value that should have flowed to `fee_collector` (via `internal_add_balance` in contracts/defuse/core/src/intents/token_diff.rs:96-101) never leaves the trading signer's balance. This is a direct, repeatable protocol-fee bypass on any NEP-245/IMT token with `protocol_fee > 0`: the loss scales linearly with `N` and is bounded only by how many `TokenDiff` intents can be batched/sent (no cap tied to fee evasion specifically). This matches the Critical category "protocol fees bypassed... on an aggregate amount that would have been fee-liable as one delta." It is repeatable across any account, any NEP-245/IMT token, and any batch/session — the attacker (or a colluding pair of accounts) can always avoid MT/IMT fees entirely by never issuing a `TokenDiff` leg with `|delta| > 1` for that token.

### Likelihood Explanation
Preconditions are minimal and fully attacker-controlled: own or acquire `N` units of a NEP-245/IMT token registered in the Verifier, and have `protocol_fee > 0` configured (a normal production setting). No privileged role, relayer key, or victim key is needed — the attacker only needs to sign `N` ordinary `TokenDiff` intents (or coordinate with a willing counterparty/second account) and submit them via `execute_intents`/`simulate_intents`. This is cheap and fully repeatable; the only cost is the marginal gas/transaction size of issuing `N` legs instead of one.

### Recommendation
Compute the `amount > 1` NEP-245/IMT fee-exemption check against the aggregate `|delta|` for a given `(signer_id, token_id)` across the whole intent batch (and ideally guard against splitting across separate calls, e.g. by removing the size-based exemption for fungible-quantity MT/IMT balances and reserving it only for genuinely atomic, always-quantity-1 token ids), rather than per individual `TokenDiff` intent.

### Proof of Concept
`cargo test` in `contracts/defuse/core` (or a `near-workspaces` sandbox test alongside `tests/src/tests/defuse/intents/token_diff.rs`):
1. Set `protocol_fee = Pips::ONE_PERCENT` (or any `> 0`), pick a `Nep245`/`Imt` `token_id`, `N = 100`.
2. Case A ("single diff"): execute one `TokenDiff{ diff: {token_id: -100, token_out: +100k} }` (with a matching counterparty leg providing `+100`/`-100k`) via `execute_intents`; assert `fee_collector` balance for `token_id` equals `Pips::ONE_PERCENT.fee_ceil(100)` (`> 0`).
3. Case B ("split diff"): reset state, execute 100 separate `TokenDiff{ diff: {token_id: -1, token_out: +k} }` intents in one `MultiPayload` batch (matched by counterparty legs summing to `+100`/`-100k`) via `execute_intents`; assert `fee_collector` balance for `token_id` equals `0`.
4. Assert `Case_A_fee != Case_B_fee` (specifically `Case_B_fee == 0 < Case_A_fee`), demonstrating `sum(fees_collected across N legs) != Pips::fee_ceil(protocol_fee, N)`. [1](#0-0) [2](#0-1) [3](#0-2)

impl ExecutableIntent for TokenDiff {
    fn execute_intent<S, I>(
        self,
        signer_id: &AccountIdRef,
        engine: &mut Engine<S, I>,
        intent_hash: [u8; 32],
    ) -> Result<()>
    where
        S: State,
        I: Inspector,
    {
        if self.diff.is_empty() {
            return Err(DefuseError::InvalidIntent);
        }

        let protocol_fee = engine.state.fee();
        let mut fees_collected: Amounts = Amounts::default();

        for (token_id, delta) in &self.diff {
            if *delta == 0 {
                return Err(DefuseError::InvalidIntent);
            }

            // add delta to signer's account
            engine
                .state
                .internal_apply_deltas(signer_id, [(token_id.clone(), *delta)])?;

            // take fees only from negative deltas (i.e. token_in)
            if *delta < 0 {
                let amount = delta.unsigned_abs();
                let fee = Self::token_fee(token_id, amount, protocol_fee).fee_ceil(amount);

                // collect fee
                fees_collected
                    .add(token_id.clone(), fee)
                    .ok_or(DefuseError::BalanceOverflow)?;
            }
        }

        engine.inspector.on_event(DefuseEvent::TokenDiff(
            [MaybeIntentEvent::new_intent(
                AccountEvent::new(
                    signer_id,
                    TokenDiffEvent {
                        diff: Cow::Borrowed(&self),
                        fees_collected: fees_collected.clone(),
                    },
                ),
                intent_hash,
            )]
            .as_slice()
            .into(),
        ));

        // deposit fees to collector
        if !fees_collected.is_empty() {
            engine
                .state
                .internal_add_balance(engine.state.fee_collector().into_owned(), fees_collected)?;
        }

        Ok(())
    }

impl ExecutableIntent for Intent {
    fn execute_intent<S, I>(
        self,
        signer_id: &AccountIdRef,
        engine: &mut Engine<S, I>,
        intent_hash: [u8; 32],
    ) -> Result<()>
    where
        S: State,
        I: Inspector,
    {
        match self {
            Self::AddPublicKey(intent) => intent.execute_intent(signer_id, engine, intent_hash),
            Self::RemovePublicKey(intent) => intent.execute_intent(signer_id, engine, intent_hash),
            Self::Transfer(intent) => intent.execute_intent(signer_id, engine, intent_hash),
            Self::FtWithdraw(intent) => intent.execute_intent(signer_id, engine, intent_hash),
            Self::NftWithdraw(intent) => intent.execute_intent(signer_id, engine, intent_hash),
            Self::MtWithdraw(intent) => intent.execute_intent(signer_id, engine, intent_hash),
            Self::NativeWithdraw(intent) => intent.execute_intent(signer_id, engine, intent_hash),
            Self::StorageDeposit(intent) => intent.execute_intent(signer_id, engine, intent_hash),
            Self::TokenDiff(intent) => intent.execute_intent(signer_id, engine, intent_hash),
            Self::SetAuthByPredecessorId(intent) => {
                intent.execute_intent(signer_id, engine, intent_hash)
            }
            Self::AuthCall(intent) => intent.execute_intent(signer_id, engine, intent_hash),
            #[cfg(feature = "imt")]
            Self::ImtMint(intent) => intent.execute_intent(signer_id, engine, intent_hash),
            #[cfg(feature = "imt")]
            Self::ImtBurn(intent) => intent.execute_intent(signer_id, engine, intent_hash),
        }
    }
