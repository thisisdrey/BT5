## Title
Permanent handshake DOS via unconditional, non-disableable Root CA expiration check in `CAPool.verify` — ([File: `cert/ca_pool.go`])

### Summary
Nebula's certificate-verification path unconditionally rejects any peer certificate once the signing root CA certificate's `NotAfter` time has elapsed, with **no configuration knob to disable or bypass this check for new handshakes**. This mirrors the referenced GasThrottle finding: a single, hard-coded gating condition (there, an external gas-price oracle; here, the root CA's expiration timestamp) that, once it trips, permanently blocks the protected operation (there, swaps; here, all new tunnel handshakes) network-wide, with no governance-controlled way to turn the check off.

### Finding Description
`CAPool.verify` performs the trust-chain check for every certificate presented during a handshake: [1](#0-0) 

```go
func (ncp *CAPool) verify(c Certificate, now time.Time, certFp string, signerFp string) (*CachedCertificate, error) {
	...
	signer, err := ncp.GetCAForCert(c)
	...
	if signer.Certificate.Expired(now) {
		return nil, ErrRootExpired
	}
	if c.Expired(now) {
		return nil, ErrExpired
	}
	...
}
```

This is invoked by `VerifyCertificate`, which is exactly the function the handshake manager wires up as the `CertVerifier` for **every new handshake**: [2](#0-1) 

There is no config setting analogous to `pki.disconnect_invalid` that applies to this path. `pki.disconnect_invalid` only governs whether an *already-established* tunnel is torn down once its peer's cert becomes invalid — it has no effect on new handshake verification: [3](#0-2) 

Once every CA in the pool has expired, `loadCAPoolFromConfig` will even refuse to start the process at all: [4](#0-3) 

But short of that total-failure case, if the currently-loaded root CA certificate simply passes its `NotAfter` time while the process keeps running (e.g., an operator misses a scheduled CA rotation, or forgets to `SIGHUP`-reload a renewed CA before the old one lapses), `ncp.verify` starts returning `ErrRootExpired` for **every** peer certificate signed by that CA — for every new handshake attempt across the mesh — and there is no configuration flag or admin command to suppress this and keep accepting handshakes signed by the (now formally expired) CA while a fix is rolled out.

### Impact Explanation
Once the loaded root CA certificate's validity window elapses, all new handshake attempts across the entire mesh permanently fail with `ErrRootExpired` (`cert/errors.go` line 10), because `certVerifier()` (used by every handshake) calls straight into the same unconditional check. Existing tunnels may survive if `pki.disconnect_invalid` is left at its default `false`... but any node that restarts, roams, or needs to re-handshake (e.g. after a route change, `recv_error`, or process restart) can never reconnect until an operator manually redistributes a renewed CA bundle to every host in the network. This is a network-wide denial of service with no built-in recovery or override mechanism — directly analogous to GasThrottle's "no way to remove after deployment" DOS, except the trigger is CA expiry rather than a corrupted oracle value.

### Likelihood Explanation
This does not require compromising cryptography — it only requires the operationally common scenario of CA-renewal lapsing (misconfiguration, missed rotation window, or clock skew pushing `now` past `NotAfter`). Because there is no config toggle to bypass root-expiry checking on the handshake path (unlike the tear-down path, which is governed by `pki.disconnect_invalid`), any lapse turns into an unrecoverable, fleet-wide handshake outage rather than a soft/gradual degradation.

### Recommendation
Add a governance-controlled override (e.g. extend `pki.disconnect_invalid`, or introduce a dedicated `pki.allow_expired_root` style flag) that lets an operator explicitly choose to keep accepting handshakes signed by an expired-but-not-blocklisted root CA while a renewal is rolled out, mirroring the C4 recommendation to let governance "turn off" the hard gate rather than have it be an unconditional, unrecoverable failure mode.

### Proof of Concept
1. Generate a CA cert with a short `NotAfter`, and issue host certs signed by it (`NewTestCaCert`/`NewTestCert` as used in `cert/ca_pool_test.go`).
2. Load the CA into a running Nebula mesh via `pki.ca` and start multiple nodes.
3. Advance time (or wait) past the CA's `NotAfter`.
4. Observe that `TestCertificateV1_VerifyP256` / `TestCertificateV2_VerifyP256`-style calls to `caPool.VerifyCertificate(time.Now(), c)` now return `"root certificate is expired"` (`ErrRootExpired`) for every certificate signed by that CA: [5](#0-4) 
5. Confirm any node that must re-handshake (restart, roam, `SIGHUP` reload without a fresh CA) can no longer establish a tunnel to any peer, and that no config setting exists to suppress `ErrRootExpired` on the handshake path — only `pki.disconnect_invalid`, which governs teardown of already-established tunnels, not new handshake acceptance (`connection_manager.go` lines 470-500).

func (ncp *CAPool) verify(c Certificate, now time.Time, certFp string, signerFp string) (*CachedCertificate, error) {
	if ncp.IsBlocklisted(certFp) {
		return nil, ErrBlockListed
	}

	signer, err := ncp.GetCAForCert(c)
	if err != nil {
		return nil, err
	}

	if signer.Certificate.Curve() != c.Curve() {
		return nil, ErrCurveMismatch
	}

	if signer.Certificate.Expired(now) {
		return nil, ErrRootExpired
	}

	if c.Expired(now) {
		return nil, ErrExpired
	}

// isInvalidCertificate decides if we should destroy a tunnel.
// returns true if pki.disconnect_invalid is true and the certificate is no longer valid.
// Blocklisted certificates will skip the pki.disconnect_invalid check and return true.
func (cm *connectionManager) isInvalidCertificate(now time.Time, hostinfo *HostInfo) bool {
	remoteCert := hostinfo.GetCert()
	if remoteCert == nil {
		return false //don't tear down tunnels for handshakes in progress
	}

	caPool := cm.intf.pki.GetCAPool()
	err := caPool.VerifyCachedCertificate(now, remoteCert)
	if err == nil {
		return false //cert is still valid! yay!
	} else if err == cert.ErrBlockListed { //avoiding errors.Is for speed
		// Block listed certificates should always be disconnected
		hostinfo.logger(cm.l).Info("Remote certificate is blocked, tearing down the tunnel",
			"error", err,
			"fingerprint", remoteCert.Fingerprint,
		)
		return true
	} else if cm.intf.disconnectInvalid.Load() {
		hostinfo.logger(cm.l).Info("Remote certificate is no longer valid, tearing down the tunnel",
			"error", err,
			"fingerprint", remoteCert.Fingerprint,
		)
		return true
	} else {
		//if we reach here, the cert is no longer valid, but we're configured to keep tunnels from now-invalid certs open
		return false
	}
}
