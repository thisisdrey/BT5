## Title
Unchecked-null `AccountCapsule` dereference in `VoteWitnessProcessor.execute()` allows an attacker to crash TVM execution via the native vote-witness precompile — (File: `actuator/src/main/java/org/tron/core/vm/nativecontract/VoteWitnessProcessor.java`)

### Summary
`VoteWitnessProcessor.execute()` fetches the voter's `AccountCapsule` from the repository and immediately dereferences it (via `accountCapsule.getVotesList()`, `accountCapsule.clearVotes()`, `accountCapsule.getTronPower()` / `getAllTronPower()`) with no null check, mirroring the class of bug described in CVE-2024-26648 (`edp_setup_replay()` dereferencing a pointer before its NULL check). `validate()` in the same processor never verifies that the voter account exists, so a caller can reach `execute()` with a non-existent account and trigger a `NullPointerException`.

### Finding Description
`VoteWitnessProcessor` is the native-contract implementation used by the TVM vote-witness precompile path (analogous to `VoteWitnessActuator` but invoked from Solidity contract execution through `VoteWitnessParam`/`Program.java`). [1](#0-0) 

`validate()` only checks that `repo` is non-null and that the vote count does not exceed `MAX_VOTE_NUMBER`. It never checks whether the account at `param.getVoterAddress()` exists in the repository: [1](#0-0) 

`execute()` then fetches the account and dereferences it immediately, with no null guard, unlike every actuator-level `validate()` method in the codebase (e.g. `VoteWitnessActuator`, `TransferActuator`, `FreezeBalanceV2Actuator`) which all explicitly check `accountCapsule == null` before use: [2](#0-1) 

Compare this to the pattern consistently enforced elsewhere, such as `VoteWitnessActuator.countVoteAccount()`: [3](#0-2) 

Note that even `VoteWitnessActuator.countVoteAccount()` itself fetches `accountCapsule` and dereferences `accountCapsule.oldTronPowerIsNotInitialized()` / `accountCapsule.getVotesList()` without a null check at line 163–173, relying entirely on `validate()` having already confirmed the owner account exists. `VoteWitnessProcessor`, by contrast, has no equivalent existence check in its own `validate()`, meaning the safety invariant that protects the actuator path is not enforced for the native/TVM code path.

### Impact Explanation
If `param.getVoterAddress()` can refer to an account that does not yet exist in the repository (e.g., because the TVM-reachable native-contract path does not go through the same account-creation/validation guarantees as normal transaction actuators), `repo.getAccount(ownerAddress)` returns `null`, and the subsequent `accountCapsule.getVotesList()` / `accountCapsule.clearVotes()` calls throw an unguarded `NullPointerException`. Because this code executes inside block/transaction processing (VM execution during `Manager` block application), an uncaught NPE here can abort transaction processing unexpectedly and is a node-crash / node-halt class issue reachable from a TVM contract call.

### Likelihood Explanation
Reachability depends on whether the TVM vote-witness native contract can be invoked with a voter address that has no corresponding `AccountCapsule` in the repository at execution time (e.g., through delegatecall/callcode context confusion, or invocation before the calling contract's own account has been created in the current execution branch). This condition could not be fully confirmed within the scope of this review — the call sites in `Program.java` and `VoteWitnessParam.java` construct the parameter object, but verifying whether an account-existence guarantee is enforced upstream before `VoteWitnessProcessor.execute()` is invoked requires deeper tracing of `Program.java`'s native-contract dispatch, which was not completed.

### Recommendation
Add an explicit null check for `repo.getAccount(param.getVoterAddress())` in `VoteWitnessProcessor.validate()` (or immediately in `execute()`), throwing a `ContractValidateException`/`ContractExeException` before any account field is dereferenced — matching the defensive pattern already used throughout `org.tron.core.actuator.*` classes.

### Proof of Concept
Not fully constructible without confirming the exact upstream call path that supplies `VoteWitnessParam.voterAddress`. Conceptually: invoke the TVM native vote-witness precompile/opcode passing an address that has no `AccountCapsule` record in the current repository state (e.g., a fresh, never-funded address used as `msg.sender` context in a delegate/library call), then observe `execute()` throw `NullPointerException` at `accountCapsule.getVotesList()`.
