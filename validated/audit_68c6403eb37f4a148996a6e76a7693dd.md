### Title
stSTXbtc/zstSTXbtc collateral priced as raw STX with no exchange-rate callcode, causing systematic mispricing of a wrapped yield-bearing asset - (File: mainnet/contracts/proposals/mainnet/v0-init.clar / mainnet/contracts/market/v0-4-market.clar)

### Summary
`stSTXbtc` is registered in the asset registry with the plain STX/USD Pyth feed and `callcode: none`, meaning its on-chain collateral value is computed as exactly the STX price with no adjustment for its own token exchange rate. This mirrors the wstETH incompatibility described in the referenced report: a wrapped/rebasing derivative asset is priced using a single-asset oracle for its underlying, with no mechanism to reflect the wrapper's accrued value, even though the protocol's own oracle system already implements exactly such a mechanism (`CALLCODE-STSTX`) for the sibling asset `stSTX`.

### Finding Description
The oracle-callcode design in `market.clar` demonstrates the protocol is aware that wrapped/staking derivatives need an exchange-rate transformation layered on top of the base feed — this is precisely how `stSTX` is priced (`CALLCODE-STSTX` → `resolve-ststx` → `call-ststx-ratio`). However, `stSTXbtc`, itself a derivative built on stSTX (per its constant name and vault structure), is registered with `callcode: none` against the raw `STX-FEED-ID`, so `price-resolve` returns the bare STX/USD price for it with no correcting transform. `zstSTXbtc` then applies `CALLCODE-ZSTSTXBTC` → `resolve-ztoken`, which multiplies that already-unadjusted base price by the vault's liquidity index only — it never composes in an stSTXbtc-specific exchange ratio the way `CALLCODE-ZSTSTX` composes `resolve-ststx` before `resolve-ztoken`.

### Impact Explanation
This is a Medium-class analog of the report: the collateral valuation for `stSTXbtc`/`zstSTXbtc` is structurally decoupled from the token's real economic value, causing persistent over- or under-collateralization of positions using it. Since `zstSTXbtc` backs debt egroups (STX, sBTC, stSTX, USDC, USDh borrowing), a persistent mispricing either freezes legitimate borrowing capacity (temporary freezing of funds if undervalued) or allows positions to remain "healthy" while actually undercollateralized (protocol insolvency risk if overvalued), depending on how far stSTXbtc's real exchange rate has drifted from raw STX.

### Likelihood Explanation
This triggers automatically and continuously for every health check, borrow, and liquidation call that touches `stSTXbtc`/`zstSTXbtc` collateral via `get-assets`/`price-multi-resolve` — no attacker action is required, only the natural accrual of value in the underlying staking/yield mechanism, which is guaranteed to occur over time exactly as it does for `stSTX`.

### Recommendation
Apply an explicit exchange-rate callcode for `stSTXbtc` analogous to `CALLCODE-STSTX`/`CALLCODE-ZSTSTX`, sourcing the stSTXbtc:STX (or stSTXbtc:stSTX) ratio from its authoritative on-chain rate, before layering the vault liquidity-index transform for `zstSTXbtc`.

### Proof of Concept
1. Observe `stSTXbtc` registered with `{ type: TYPE-PYTH, ident: STX-FEED-ID, callcode: none }` in `v0-init.clar` line 132-133.
2. Trace `price-resolve` in `v0-4-market.clar`: for this asset, `resolve-callcode` receives `callcode: none` and returns the raw STX price unmodified (line 349-350: `(unwrap! callcode (ok p))`).
3. Compare to `stSTX`'s registration (line 108-109), which applies `CALLCODE-STSTX` to compose the staking ratio — showing the protocol has, but did not use, the correcting mechanism for `stSTXbtc`.
4. As `stSTXbtc`'s real value diverges from raw STX over time, every collateral valuation for accounts holding `stSTXbtc`/`zstSTXbtc` (via `get-assets`/`sum-collateral-usd`-equivalent logic in market.clar) uses the stale/incorrect 1:1 STX price, mispricing health factors for all such positions.

(define-private (resolve-ztoken (p uint) (aid uint))
  (let ((cached (unwrap! (get-cached-indexes aid) ERR-ORACLE-CALLCODE))
        (cached-lindex (get lindex cached))
        (scaled (* p cached-lindex)))
    (ok (div-down scaled INDEX-PRECISION))))

(define-private (resolve-callcode (p uint) (callcode (optional (buff 1))))
  (let ((cc (unwrap! callcode (ok p))))
    (if (is-eq cc CALLCODE-STSTX) (resolve-ststx p)
    (if (is-eq cc CALLCODE-ZSTX) (resolve-ztoken p STX)
    (if (is-eq cc CALLCODE-ZSBTC) (resolve-ztoken p sBTC)
    (if (is-eq cc CALLCODE-ZSTSTX) (resolve-ztoken (try! (resolve-ststx p)) stSTX)
    (if (is-eq cc CALLCODE-ZUSDC) (resolve-ztoken p USDC)
    (if (is-eq cc CALLCODE-ZUSDH) (resolve-ztoken p USDH)
    (if (is-eq cc CALLCODE-ZSTSTXBTC) (resolve-ztoken p stSTXbtc)
    ERR-ORACLE-CALLCODE)))))))))
