## Title
No slippage protection when swapping refunded weight fees back to the original asset - (File: `cumulus/primitives/utility/src/lib.rs`)

## Summary
`SwapFirstAssetTrader::refund_weight` swaps the unused portion of `total_fee` (held in `Target` asset) back into the user's original payment asset by calling `SwapCredit::swap_exact_tokens_for_tokens` with `amount_out_min` hardcoded to `None`, meaning the refund conversion has no protection against adverse price movement in the underlying AMM pool. This is inconsistent with the codebase's own established pattern (`SwapAssetAdapter::correct_and_deposit_fee`), which quotes an expected amount first and enforces it as `Some(refund_asset_amount)`.

## Finding Description
`SwapFirstAssetTrader::buy_weight` swaps the user's payment asset into `Target` via `SwapCredit::swap_tokens_for_exact_tokens`, accumulating the result into `self.total_fee` [1](#0-0) .

`refund_weight` later extracts the unused portion of `total_fee` and swaps it back to `refund_swap_asset` via `SwapCredit::swap_exact_tokens_for_tokens(vec![Target::get(), refund_swap_asset], refund, None)` — passing `None` as `amount_out_min` [2](#0-1) .

The `Swap` trait's `swap_exact_tokens_for_tokens` signature explicitly supports an `amount_out_min: Option<Self::Balance>` parameter for this purpose [3](#0-2) . `pallet-asset-conversion`'s implementation, `do_swap_exact_credit_tokens_for_tokens`, only enforces the `ProvidedMinimumNotSufficientForSwap` check when `amount_out_min` is `Some`; with `None` the check is a no-op (`amount_out_min.map_or(true, |a| amount_out >= a)`), so whatever `amount_out` the AMM curve produces at execution time is accepted [4](#0-3) .

By contrast, `quote_weight` in the same trader impl does call `QuotePrice::quote_price_tokens_for_exact_tokens` to compute the required input before the trader charges the user [5](#0-4) , and `SwapAssetAdapter::correct_and_deposit_fee` in the tx-payment pallet explicitly quotes `refund_asset_amount` via `quote_price_exact_tokens_for_tokens` and passes `Some(refund_asset_amount)` into the analogous refund swap [6](#0-5) . `refund_weight` deviates from this established pattern by skipping the quote step entirely.

I confirmed `SwapFirstAssetTrader` is not merely a library primitive but is actually wired into production runtime XCM configurations, including `asset-hub-rococo`, `asset-hub-westend`, the `penpal` testing parachain, and `substrate/frame/staking-async/runtimes/parachain`, each referencing it in their `xcm_config.rs`.

## Impact Explanation
Because the refund leg executes with no floor on output, any AMM price movement between the `buy_weight` swap and the `refund_weight` swap — including price impact from other swaps against the same `Target`/`refund_swap_asset` pool within the same block — passes through unchecked. This causes the XCM message sender to receive less value back than they are entitled to, silently, with no error raised (the swap succeeds with a suboptimal `amount_out`). This is a value-conservation / correct-payout violation: the refund amount credited back to the message sender's holding is not bound to the fair/quoted value, and the specific corrupted value is the `refund` `Credit` amount returned by `SwapCredit::swap_exact_tokens_for_tokens` at `cumulus/primitives/utility/src/lib.rs:540-544`.

## Likelihood Explanation
`SwapFirstAssetTrader` is live in shipped parachain runtime configurations backed by `pallet-asset-conversion` pools. The refund path executes for essentially any XCM message that overestimates weight and pays fees in a non-`Target` asset. No privileged actor is required — ordinary AMM trading activity from unrelated, unprivileged users against the shared pool (including the trader's own preceding `buy_weight` swap) is sufficient to move the price unfavorably before `refund_weight` executes.

## Recommendation
Before executing the refund swap, quote an expected output via `QuotePrice::quote_price_exact_tokens_for_tokens(Target::get(), refund_swap_asset, refund_amount, true)`, and pass `Some(expected_amount)` (optionally tolerance-adjusted) as `amount_out_min` to `swap_exact_tokens_for_tokens`, mirroring `SwapAssetAdapter::correct_and_deposit_fee`. If the quote fails or the swap cannot meet the minimum, fall back to not refunding rather than accepting an unbounded-slippage swap.

## Proof of Concept
1. Configure a runtime with `SwapFirstAssetTrader<Target, AssetConversion, ...>` in the `WeightTrader`, backed by a live `pallet-asset-conversion` pool for `Target`/`AssetX` (as done in `asset-hub-rococo`/`asset-hub-westend`/`penpal`).
2. Send an XCM message paying fees in `AssetX` with an overestimated weight, so `buy_weight` swaps `AssetX -> Target` via `swap_tokens_for_exact_tokens`, accumulating `total_fee`, and a nontrivial refund becomes due.
3. In the same block, submit other swaps against the `Target`/`AssetX` pool to move reserves so the `Target -> AssetX` rate becomes unfavorable.
4. Observe `refund_weight` invoke `SwapCredit::swap_exact_tokens_for_tokens(vec![Target::get(), refund_swap_asset], refund, None)` at `cumulus/primitives/utility/src/lib.rs:540-544` — the swap succeeds and returns a reduced `refund` amount with no error, since `amount_out_min` was never enforced, shortchanging the refund recipient.
