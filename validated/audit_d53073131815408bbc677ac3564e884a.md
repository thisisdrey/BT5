### Title
Idle-triggered decay of `StakedStreamLoadEMA` allows low-stake QUIC clients to bypass stake-weighted stream throttling - (File: streamer/src/nonblocking/stream_throttle.rs)

### Summary
`StakedStreamLoadEMA` computes a single, connection-table-wide exponential moving average of staked stream load and uses it to decide whether stake-proportional throttling should be enabled. The EMA is only advanced lazily, on stream events, and any gap between events longer than `STREAM_LOAD_EMA_INTERVAL_MS` (5ms) is "caught up" by repeatedly applying the decay function with zero load, driving the EMA toward zero. Once the EMA (and therefore `staked_throttling_enabled`) collapses to zero/false during a quiet period, the very next burst of streams from any staked connection — regardless of how little stake it holds — is granted the full un-throttled `max_staked_load_in_throttling_window` instead of its stake-proportional share, letting a minimally-staked peer consume disproportionate QUIC stream capacity on the TPU.

### Finding Description
`StakedStreamLoadEMA::update_ema` decays the EMA once per 5ms bin, and when it hasn't been called in a while, replays the decay for every missed bin with a load of `0`, driving `current_load_ema` toward `0`: [1](#0-0) 

The decayed value directly gates a global boolean, `staked_throttling_enabled`, using a fixed threshold: [2](#0-1) 

This update only runs opportunistically, invoked from `increment_load` (fired when a new stream is accepted), and from `on_stream_error`/`on_stream_closed`: [3](#0-2) [4](#0-3) 

`staked_throttling_enabled` is a single, shared flag for *all* staked connections in the `SwQos` controller (not per-connection or per-stake), and it directly determines the throttle window available to a connection: [5](#0-4) 

That capacity is consumed by `on_new_stream`, which computes the max streams allowed for the *current* throttling interval using whatever the EMA/flag currently holds, before the stream itself is counted via `on_stream_accepted`/`increment_load`: [6](#0-5) 

Because there is no time-invariant floor on how much a single missed-interval gap can shrink `current_load_ema`, and no minimum sample size or dwell time required before flipping `staked_throttling_enabled` back off, any quiet period on the TPU/TPU-forwards QUIC port (natural lulls between leader slots, low-traffic windows, or a period where an adversary simply withholds traffic) causes the load estimate to collapse toward zero. The next connection to send streams — even one with a trivially small stake just above the `min_stake_ratio` cutoff used to classify it as `Staked` rather than `Unstaked` — is then evaluated with `staked_throttling_enabled == false` and receives `max_staked_load_in_throttling_window` (the full staked budget) rather than its proportional share (`max_staked_load_in_throttling_window * stake / total_stake`) computed in `available_load_capacity_in_throttling_duration`.

This mirrors the reported `AggregateStablePrice2.price_w()` bug class: a time-decayed weighting factor (`alpha` in the report, `current_load_ema`/`staked_throttling_enabled` here) that is only updated on interested-party-triggered calls, whose value can be driven to an extreme by elapsed idle time, after which a single subsequent observation/burst gets outsized influence on a security-relevant decision (TVL there; QUIC QoS admission here).

### Impact Explanation
The stake-weighted throttle is the mechanism intended to make QUIC stream admission proportional to stake so that low-stake or unstaked peers cannot consume more than their fair share of the leader's transaction-ingestion capacity (a core anti-DoS/QoS control on the TPU path). Bypassing it by exploiting an idle-triggered EMA collapse lets a peer with a tiny stake temporarily submit up to the full staked stream budget in a 100ms throttling window instead of its proportional slice, i.e. grossly underpriced (in stake terms) consumption of validator pre-fee ingestion capacity — a QoS evasion on the unprivileged QUIC/UDP streamer ingestion path.

### Likelihood Explanation
Exploitation only requires being a staked (even minimally staked) QUIC client able to open streams, and either waiting for a naturally quiet period (idle windows between bursts of leader traffic are common) or triggering one relative to their own connection's throttling checks — no special validator/operator role, no forged data, and no dependence on other clients' cooperation. It's a purely time-based race against the lazily-driven EMA state.

### Recommendation
Bound how much a single call to `update_ema`/`update_ema_if needed` can decay `current_load_ema` regardless of elapsed idle time, or force periodic (timer-driven, not stream-event-driven) EMA updates so the estimate can't collapse to near-zero purely because no stream event happened to trigger a recompute. Additionally, consider requiring a minimum recent observation count before disabling `staked_throttling_enabled`, and/or applying throttling decisions per-connection stake rather than gating the whole staked population off a single global flag.

### Proof of Concept
1. Observe/wait for a period where no staked QUIC stream activity occurs on the target validator's TPU/TPU-forwards port for more than `STREAM_LOAD_EMA_INTERVAL_COUNT * STREAM_LOAD_EMA_INTERVAL_MS` (~200ms) — e.g., a lull between leader slots.
2. During this idle period, any subsequent call to `update_ema_if_needed` (triggered by connection setup, `on_stream_error`, or `on_stream_closed`) replays enough zero-load intervals via `update_ema`'s `num_extra_updates` loop that `current_load_ema` drops below `staked_throttling_on_load_threshold`, setting `staked_throttling_enabled = false`.
3. As soon as this happens, connect as a staked peer with minimal stake (just above the `min_stake_ratio` cutoff so it is classified `ConnectionPeerType::Staked` rather than `Unstaked`) and immediately open a burst of QUIC streams.
4. `on_new_stream` computes `max_streams_per_throttling_interval` via `available_load_capacity_in_throttling_duration`, which — because `staked_throttling_enabled` is `false` — returns the full `max_staked_load_in_throttling_window` rather than the attacker's stake-proportional share, letting the low-stake connection consume the entire staked stream budget for that throttling interval.

    fn update_ema(&self, time_since_last_update_ms: u128) {
        // if time_since_last_update_ms > STREAM_LOAD_EMA_INTERVAL_MS, there might be intervals where ema was not updated.
        // count how many updates (1 + missed intervals) are needed.
        let num_extra_updates =
            time_since_last_update_ms.saturating_sub(1) / u128::from(STREAM_LOAD_EMA_INTERVAL_MS);

        let load_in_recent_interval =
            u128::from(self.load_in_recent_interval.swap(0, Ordering::Relaxed));

        let mut updated_load_ema = Self::ema_function(
            u128::from(self.current_load_ema.load(Ordering::Relaxed)),
            load_in_recent_interval,
        );

        for _ in 0..num_extra_updates {
            updated_load_ema = Self::ema_function(updated_load_ema, 0);
            if updated_load_ema == 0 {
                break;
            }
        }

        let Ok(updated_load_ema) = u64::try_from(updated_load_ema) else {
            error!("Failed to convert EMA {updated_load_ema} to a u64. Not updating the load EMA");
            self.stats
                .stream_load_ema_overflow
                .fetch_add(1, Ordering::Relaxed);
            return;
        };

    pub(crate) fn update_ema_if_needed(&self) {
        const EMA_DURATION: Duration = Duration::from_millis(STREAM_LOAD_EMA_INTERVAL_MS);
        // Read lock enables multiple connection handlers to run in parallel if interval is not expired
        if Instant::now().duration_since(*self.last_update.read().unwrap()) >= EMA_DURATION {
            let mut last_update_w = self.last_update.write().unwrap();
            // Recheck as some other thread might have updated the ema since this thread tried to acquire the write lock.
            let since_last_update = Instant::now().duration_since(*last_update_w);
            if since_last_update >= EMA_DURATION {
                *last_update_w = Instant::now();
                self.update_ema(since_last_update.as_millis());
            }
        }
    }

    pub(crate) fn increment_load(&self, peer_type: ConnectionPeerType) {
        if peer_type.is_staked() {
            self.load_in_recent_interval.fetch_add(1, Ordering::Relaxed);
        }
        self.update_ema_if_needed();
    }

    pub(crate) fn available_load_capacity_in_throttling_duration(
        &self,
        peer_type: ConnectionPeerType,
        total_stake: u64,
    ) -> u64 {
        match peer_type {
            ConnectionPeerType::Unstaked => self.max_unstaked_load_in_throttling_window,
            ConnectionPeerType::Staked(stake) => {
                if self.staked_throttling_enabled.load(Ordering::Relaxed) {
                    // 1 is added to `max_unstaked_load_in_throttling_window` to guarantee that staked
                    // clients get at least 1 more number of streams than unstaked connections.
                    self.max_staked_load_in_throttling_window
                        .saturating_mul(stake)
                        .checked_div(total_stake)
                        .unwrap_or(self.max_unstaked_load_in_throttling_window + 1)
                        .max(self.max_unstaked_load_in_throttling_window + 1)
                } else {
                    self.max_staked_load_in_throttling_window
                }
            }
        }
    }
