### Title
Unrestricted `new_authority` in `transfer_to_new_account`/`transfer_to_new_account_pda` allows permanent lock of account funds - ([File: programs/marginfi/src/instructions/marginfi_account/transfer_account.rs])

### Summary
`transfer_to_new_account` and `transfer_to_new_account_pda` let the current authority migrate a `MarginfiAccount` (with its entire `lending_account` balances) to a brand-new account whose authority is set to an arbitrary `new_authority` pubkey, with zero validation that this address is capable of signing/controlling the new account. This mirrors the `OgvStaking.stake(amount, duration, to)` bug class, where funds can be attributed to an address that can never operate on them.

### Finding Description
Both instructions accept `new_authority` as a fully `UncheckedAccount`, explicitly documented as `WARN: New authority is completely unchecked`: [1](#0-0) [2](#0-1) 

The instruction body copies the old account's entire `lending_account` (all deposit/borrow balances) into the new account and sets the new account's `authority` to `new_authority.key()` without requiring `new_authority` to be a signer, without checking it is not the zero/default pubkey, and without any capability check (e.g., that it's not a PDA with no corresponding signer, or a program-owned account that cannot invoke marginfi instructions): [3](#0-2) [4](#0-3) 

Once migration completes, the old account is permanently disabled (`ACCOUNT_DISABLED`) and its `lending_account` is zeroed out, so there is no way to reverse the transfer: [5](#0-4) [6](#0-5) 

The corresponding test file itself acknowledges this design choice as risky: "Here the user moves authority to some new wallet. WARN: User picks the new authority with no restrictions!" [7](#0-6) 

Just as in the `OgvStaking.stake` bug, a user who mistypes an address, uses a PDA they don't control the seeds/signer for, or specifies a program-owned/uncontrollable account as `new_authority`, permanently and irreversibly loses access to all funds held in the migrated `MarginfiAccount` (deposits, collateral, and any open positions), because the old account is disabled and the new account's authority cannot be changed back by anyone.

### Impact Explanation
This can lead to permanent loss/freeze of user funds: all deposited collateral and lending-account balances migrated to the new account become inaccessible if `new_authority` cannot sign transactions for that account (e.g., wrong address, PDA without corresponding program logic to operate marginfi instructions, or a burn/black-hole address). There is no recovery instruction that lets a bricked account revert or reassign authority, since `migrated_to`/`ACCOUNT_DISABLED` on the old account and `migrated_from` on the new account are set unconditionally and irreversibly.

### Likelihood Explanation
Likelihood is moderate: the flow requires the account's own authority (a user) to actively call the migration instruction and supply an incorrect/uncontrollable `new_authority`. This can happen from a client-side bug, a copy-paste error, a malicious frontend, or by a user attempting to migrate to a PDA-based account layout (as supported by `transfer_to_new_account_pda`) using an authority key they mistakenly believe they control. Because the instruction offers no confirmation (e.g., no requirement that `new_authority` co-sign, or an initial no-op sanity round-trip), a single mistaken call causes an unrecoverable loss.

### Recommendation
Require `new_authority` to be a `Signer` (or otherwise prove control, e.g., a two-step transfer where the new authority must accept/claim the migrated account in a follow-up instruction) before finalizing the migration and disabling the old account. Alternatively, add a claim/rollback mechanism analogous to `stakeFor` + `onlyGovernor`/receiver-must-operate pattern recommended in the referenced report: keep the old account usable/reversible until the new authority actively signs a "claim" transaction confirming they can operate the new account.

### Proof of Concept
1. User A owns `old_marginfi_account` with deposited collateral (e.g., USDC) as shown by `try_bank_deposit_with_authority` in the transfer test setup: [8](#0-7) 
2. User A calls `transfer_to_new_account`/`transfer_to_new_account_pda`, supplying `new_authority` = an address they do not actually control (e.g., a randomly generated pubkey, or a PDA of an unrelated program), per the account struct: [9](#0-8) 
3. The instruction succeeds: it disables `old_marginfi_account` (`ACCOUNT_DISABLED`, `lending_account` zeroed, `migrated_to` set) and creates `new_marginfi_account` with `authority = new_authority` and the copied `lending_account` balances: [10](#0-9) 
4. Because `new_authority` never signed and cannot produce a signature for any future marginfi instruction (withdraw, borrow-repay, close), the funds now held in `new_marginfi_account` are permanently unreachable — a direct “loss of staked funds” analog to the `OgvStaking` bug class.

fn initialize_migrated_account(
    new_account: &mut MarginfiAccount,
    old_account: &MarginfiAccount,
    new_authority: Pubkey,
    current_timestamp: u64,
    old_account_key: Pubkey,
) {
    new_account.initialize(old_account.group, new_authority, current_timestamp);
    new_account.lending_account = old_account.lending_account;
    new_account.emissions_destination_account = old_account.emissions_destination_account;
    new_account.account_flags = old_account.account_flags;
    new_account.migrated_from = old_account_key;
    new_account.indexer_flags = old_account.indexer_flags;
    new_account.sync_indexer_flags();
}

fn finalize_migrated_old_account(
    old_account: &mut MarginfiAccount,
    new_account_key: Pubkey,
    current_timestamp: u64,
) {
    old_account.migrated_to = new_account_key;
    old_account.last_update = current_timestamp;
    old_account.lending_account = LendingAccount::zeroed();
    old_account.set_flag(ACCOUNT_DISABLED, true);
    old_account.sync_indexer_flags();
}

#[derive(Accounts)]
pub struct TransferToNewAccount<'info> {
    #[account(
        constraint = (
            !group.load()?.is_protocol_paused()
        ) @ MarginfiError::ProtocolPaused
    )]
    pub group: AccountLoader<'info, MarginfiGroup>,

    #[account(
        mut,
        has_one = group @ MarginfiError::InvalidGroup,
        constraint = {
            let a = old_marginfi_account.load()?;
            account_not_frozen_for_authority(&a, authority.key())
        } @ MarginfiError::AccountFrozen,
        constraint = {
            let a = old_marginfi_account.load()?;
            let g = group.load()?;
            is_signer_authorized(&a, g.admin, authority.key(), false, false)
        } @ MarginfiError::Unauthorized
    )]
    pub old_marginfi_account: AccountLoader<'info, MarginfiAccount>,

    #[account(
        init,
        payer = fee_payer,
        space = 8 + std::mem::size_of::<MarginfiAccount>()
    )]
    pub new_marginfi_account: AccountLoader<'info, MarginfiAccount>,

    pub authority: Signer<'info>,

    #[account(mut)]
    pub fee_payer: Signer<'info>,

    /// CHECK: WARN: New authority is completely unchecked
    pub new_authority: UncheckedAccount<'info>,

    /// CHECK: Validated against group fee state cache
    #[account(mut)]
    pub global_fee_wallet: UncheckedAccount<'info>,

    pub system_program: Program<'info, System>,
}
