### Title
Unauthenticated HTTP event-ingestion endpoint in `SignerEventReceiver` allows forged StackerDB/block/burn events to be injected as if from the trusted node - (File: `libsigner/src/events.rs`)

### Summary
`SignerEventReceiver::next_event`, the HTTP listener that a signer process binds to receive `StackerDBChunksEvent`, `BlockValidateResponse`, `BurnBlockEvent`, and `StacksBlockEvent` payloads from the node's event-observer, performs no authentication check on inbound POST requests before parsing and forwarding them into the signer runloop.

### Finding Description
`SignerEventReceiver::next_event` dispatches any HTTP POST to `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, or `/new_block` straight into `process_event`, which reads the body, JSON-decodes it, and converts it into a `SignerEvent` that is forwarded to the signer runloop via `forward_event`. [1](#0-0) [2](#0-1) 

There is no check of any bearer token, shared secret, or `Authorization` header anywhere in `libsigner`'s event-receiver code path — a search of `libsigner/**` for `auth_token`/`Authorization` returned no matches, even though the shipped node configuration documents an `auth_token` that is supposed to gate "Authentication for signer communication": [3](#0-2) 

The only concession to trust boundaries is a code comment in `SpawnedSigner::new` warning operators that exposing this endpoint to anything other than a local/trusted node "could potentially expose sensitive data or functionalities to security risks if additional proper security checks are not integrated": [4](#0-3) 

This is the direct structural analog of the report's bug class: an equality that should gate a write/state update ("this event genuinely came from my authenticated node") is never checked, so the gate fails open for any TCP client that can reach the listening port. Once through the door, a crafted `StackerDBChunksEvent` for a `signers-X-Y` contract is converted into `SignerEvent::SignerMessages` by extracting `chunk.recover_pk()` from an attacker-controlled signature (any keypair recovers successfully) and an attacker-controlled `chunk.data` payload: [5](#0-4) 

### Impact Explanation
If a signer's event-receiver socket is reachable by anyone other than the paired node (a misconfiguration the code itself explicitly warns is easy to make, and for which the shipped sample config's `auth_token` gives operators the false impression that authentication is enforced), a remote unauthenticated party can inject forged `StackerDBChunksEvent`/`BlockValidateResponse`/`BurnBlockEvent`/`StacksBlockEvent` messages directly into the signer's decision pipeline, impersonating the node. This is an unauthenticated write into signer state via a transport layer that is explicitly in-scope (`libsigner` transport files), independent of the signer's downstream decision logic (which is out of scope here).

### Likelihood Explanation
Requires the signer's event-receiver TCP endpoint to be reachable by an untrusted network party — a configuration explicitly acknowledged as a real-world risk in the code's own warning message, and made more likely by the sample config presenting `auth_token` as though it provides protection when no corresponding check exists in `libsigner`.

### Recommendation
Add authentication to `SignerEventReceiver` (e.g., validate a shared-secret/bearer header on every request, or bind by default to loopback only and reject external client IPs) before processing any event body, and either implement enforcement of the documented `auth_token` or remove it from sample configs if it is not implemented anywhere in the codebase.

### Proof of Concept
Any TCP client that can reach the signer's listening address (see the wire-format test itself) can replicate a forged event: [6](#0-5) 
—an attacker sends the same raw `POST /stackerdb_chunks HTTP/1.1 ... {json}` request with a self-crafted `StackerDBChunksEvent`/signature, and it is accepted and forwarded identically to a legitimate node's event, because no authentication check exists in `next_event`/`process_event` to distinguish the two.

**Caveat on confidence:** I could not fully verify whether `auth_token` is enforced somewhere outside `libsigner` (e.g., in `stackslib`'s HTTP client that posts events to the observer, which I was not able to fully trace within the tool-call budget), so it's possible the token is checked via a mechanism I did not locate. This should be confirmed before treating the finding as fully proven.

    fn next_event(&mut self) -> Result<SignerEvent<T>, EventError> {
        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)
            } else if request.url() == "/new_block" {
                process_event::<T, StacksBlockEvent>(request)
            } else {
                let url = request.url().to_string();
                debug!(
                    "[{:?}] next_event got request with unexpected url {}, return OK so other side doesn't keep sending this",
                    event_receiver.local_addr,
                    url
                );
                ack_dispatcher(request);
                Err(EventError::UnrecognizedEvent(url))
            }
        })?
    }

fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}
