### Title
Shared global `overall_connection_rate_limiter` TokenBucket in QUIC accept loop can be exhausted by unstaked IP churn, denying TPU access to staked peers - ([File: streamer/src/nonblocking/quic.rs])

### Summary
The QUIC server maintains a single, connection-type-agnostic `overall_connection_rate_limiter` (`TokenBucket`, capacity `MAX_CONNECTION_BURST = 1000`, refill `TOTAL_CONNECTIONS_PER_SECOND = 2500`) that is checked/consumed for *every* incoming connection before stake is known. An attacker controlling many distinct source IPs (each individually staying under `DEFAULT_MAX_CONNECTIONS_PER_IPADDR_PER_MINUTE = 8` per-IP limit) can collectively open connections fast enough to keep this shared bucket empty, causing legitimate staked peers' connections to also be rejected via `connection_rate_limited_across_all`.

### Finding Description
In `run_server` (`streamer/src/nonblocking/quic.rs:270-281`), a single `TokenBucket` is created and shared across all connections regardless of source IP or stake: [1](#0-0) 

This bucket is checked twice, both before stake/peer type is known:
1. In the accept loop, before even accepting the QUIC handshake: `overall_connection_rate_limiter.current_tokens() == 0` → `incoming.ignore()`. [2](#0-1) 
2. In `setup_connection`, after the handshake completes but *before* `qos.build_connection_context` determines whether the peer is staked: `overall_connection_rate_limiter.consume_tokens(1).is_err()` → connection closed with `CONNECTION_CLOSE_CODE_DISALLOWED`. [3](#0-2) 

Only the per-IP `ConnectionRateLimiter` (`rate_limiter.is_allowed` / `rate_limiter.register_connection`) is keyed by IP; the global bucket has no per-key or per-stake partitioning at all — it is a flat, cluster-wide-constant-rate resource shared indiscriminately by every incoming connection, staked or not. Since stake is only knowable *after* a successful handshake (via `qos.build_connection_context`), the global limiter check at line 495 happens strictly before any staked/unstaked distinction is applied, so there is no mechanism protecting staked-peer connection attempts from being starved by unstaked traffic consuming the shared token supply. An attacker using rotating source IPs (e.g., cheap VPS/VPN/cloud egress pools or IPv6 address space) can each individually respect the per-IP limit of `DEFAULT_MAX_CONNECTIONS_PER_IPADDR_PER_MINUTE = 8` connections/min yet in aggregate exceed `TOTAL_CONNECTIONS_PER_SECOND = 2500`/s sustained rate and drain the `MAX_CONNECTION_BURST = 1000` burst capacity, keeping `current_tokens() == 0` continuously.

### Impact Explanation
This causes denial of TPU ingress specifically to legitimate staked validators/forwarders attempting new QUIC connections during the attack window, since their connection attempts are rejected at the same shared-bucket checkpoint as unstaked attackers (`connection_rate_limited_across_all` stat increments regardless of peer stake). This falls under a network-level DoS against consensus-critical transaction ingress (TPU), a legitimate Agave bounty category (denial of service against validator networking), though it is a resource-starvation/availability issue rather than a memory-safety, consensus, or fund-safety bug.

### Likelihood Explanation
Feasibility depends entirely on the attacker's ability to source enough *distinct* IP addresses to generate combined new-connection throughput exceeding ~2500/s sustained (with allowance to briefly burst 1000). This is achievable with commodity infrastructure (cloud auto-scaling egress, IPv6 /64 blocks giving effectively unlimited distinct source addresses, or botnets), and requires no validator/staked/gossip privileges — purely unauthenticated UDP/QUIC connection attempts to the public TPU port, consistent with the stated attacker model. The comment in the code (`streamer/src/nonblocking/quic.rs:332-340`) acknowledges the *design intent* of the global limiter (guard against pre-handshake IP-spoofing bursts) but does not address the fact that the limiter remains shared and un-partitioned even post-handshake when stake is already resolvable, making the tradeoff broader than necessary.

### Recommendation
Partition or reserve capacity in the global rate limiter so staked-peer connection attempts are not starved by unstaked churn — e.g., maintain separate token buckets (or reserved token quotas) for staked vs. unstaked traffic post-handshake, or exempt/priority-fast-path staked-identity connections (verified via `get_remote_pubkey` / `qos.build_connection_context`) from the shared `overall_connection_rate_limiter` check once stake is known, similar to how `SimpleQos`/`SwQos` already separates `max_staked_connections` from `max_unstaked_connections`.

### Proof of Concept
Integration test plan (extending `streamer/src/nonblocking/quic.rs` test harness or `tpu-client-next/tests/connection_workers_scheduler_test.rs`):
```rust
#[tokio::test]
async fn test_global_rate_limiter_starves_staked_peer() {
    // Spawn QUIC server with default QuicStreamerConfig (MAX_CONNECTION_BURST=1000,
    // TOTAL_CONNECTIONS_PER_SECOND=2500) and StakedNodes containing a known staked keypair.
    let staked_identity = Keypair::new();
    let staked_nodes = StakedNodes::new(
        Arc::new(HashMap::from([(staked_identity.pubkey(), 1_000_000)])),
        HashMap::default(),
    );
    let SpawnTestServerResult { server_address, stats, cancel, .. } =
        setup_quic_server(Some(staked_nodes), QuicStreamerConfig::default_for_tests(), SwQosConfig::default());

    // Simulate N unstaked attackers from N distinct source IPs (e.g. bound to
    // 127.0.0.<i> loopback range or via a mock UDP transport), each opening
    // <= DEFAULT_MAX_CONNECTIONS_PER_IPADDR_PER_MINUTE connections concurrently,
    // aggregate connection attempts > MAX_CONNECTION_BURST + TOTAL_CONNECTIONS_PER_SECOND.
    let mut attacker_handles = vec![];
    for ip_index in 0..2000 {
        attacker_handles.push(tokio::spawn(spawn_unstaked_connection_from_ip(server_address, ip_index)));
    }
    futures::future::join_all(attacker_handles).await;

    // Assert the shared bucket is drained.
    assert_eq!(stats.overall_connection_rate_limiter_current_tokens(), 0); // exposed via test hook

    // Now attempt a staked-peer connection.
    let staked_conn_result = make_client_endpoint_with_identity(&server_address, Some(staked_identity)).await;

    // Vulnerable behavior: staked_conn_result fails / stats.connection_rate_limited_across_all > 0
    // for a peer whose identity is staked.
    assert!(
        staked_conn_result.is_ok(),
        "staked peer connection should not be rejected due to unstaked-only churn on shared global limiter"
    );
}
```
Expected result on current code: the staked connection attempt fails/is closed with `CONNECTION_CLOSE_CODE_DISALLOWED` and `stats.connection_rate_limited_across_all` increments, demonstrating that legitimate staked TPU ingress can be starved purely by unstaked IP churn against the shared `overall_connection_rate_limiter`.
