### Title
Unauthenticated NullPointerException in TVM Native Vote Processor Crashes Node - ([File: actuator/src/main/java/org/tron/core/vm/nativecontract/VoteWitnessProcessor.java])

### Summary
`VoteWitnessProcessor.validate()`/`execute()` — the TVM "native contract" implementation of vote-witness that is invoked from bytecode execution in `Program.java` — never checks whether the voter's `AccountCapsule` actually exists in the account store before dereferencing it. This mirrors the reported bug class exactly: one code path (`snap/src/utils/fetchAddress.ts` in the report, here `VoteWitnessActuator.validate()`) defensively checks for `null`/non-existence, while a second, parallel code path that performs the *same logical operation* (`snap/src/utils/toggleHelper.ts` in the report, here `VoteWitnessProcessor.execute()`) omits the check and dereferences the result directly.

### Finding Description
`VoteWitnessActuator` (the normal transaction-based vote actuator) explicitly validates account existence before use: [1](#0-0) 

However, the TVM-native equivalent, `VoteWitnessProcessor`, which is reachable when a smart contract invokes the vote-witness native/precompiled path from `Program.java`, performs no such check: [2](#0-1) 

`validate()` only checks that `repo` is non-null and that the vote count doesn't exceed `MAX_VOTE_NUMBER` — it never checks that the voter account (`param.getVoterAddress()`) exists. `execute()` then calls `repo.getAccount(ownerAddress)` and immediately dereferences the result via `accountCapsule.getVotesList()` and `accountCapsule.clearVotes()` without a null check: [3](#0-2) 

`Repository.getAccount()`/`RepositoryImpl` can legitimately return `null` if the address has no corresponding entry in `AccountStore` (e.g. an address that has never received TRX/been touched, similar to how `snap_manageState.get` legitimately returns `null` before `addAddress()` first runs). Other native-contract processors in the same package explicitly guard against `accountCapsule == null` (see `VoteRewardUtil.withdrawReward`/`queryReward`, which check `if (accountCapsule == null) return`), confirming that `null` is an expected, reachable state for this store and that the omission in `VoteWitnessProcessor` is inconsistent, unguarded logic rather than an intentional invariant.

### Impact Explanation
A `NullPointerException` thrown deep inside TVM execution during block application is an uncaught runtime exception outside the normal `ContractExeException`/`ContractValidateException` handling that the actuator/TVM dispatch expects for reverts. Depending on how the exception propagates through `Program.callToAddress`/native-contract dispatch, this can escape the expected catch blocks used for graceful contract-call failure and destabilize transaction processing/block application in `Manager`, causing a node crash or halt when validating or re-executing a block containing such a call — this is a broadcastable-transaction-triggered denial-of-service against any node that processes the transaction/block (including all full nodes syncing the chain), which the rules explicitly list as an acceptable impact ("node crash or halt").

### Likelihood Explanation
Reaching this path only requires deploying/calling a smart contract that invokes the native vote-witness operation with a voter address that has no `AccountCapsule` (e.g. a freshly-derived/never-funded address used as `msg.sender`/`tx.origin` in a `DELEGATECALL` context, or a self-destructed account address reused before an account record exists). This is achievable by any unprivileged contract deployer/caller with a single crafted transaction, with no privileged access or malicious-validator assumption required.

### Recommendation
Add the same existence check used in `VoteWitnessActuator.validate()` to `VoteWitnessProcessor.validate()` (or `execute()`), e.g.:
```java
AccountCapsule accountCapsule = repo.getAccount(param.getVoterAddress());
if (accountCapsule == null) {
  throw new ContractValidateException(ACCOUNT_EXCEPTION_STR + ... + NOT_EXIST_STR);
}
```
and reuse that already-fetched capsule in `execute()` instead of re-fetching and assuming non-null. More generally, audit all `Repository.getAccount()`/store `.get()` call sites in `org.tron.core.vm.nativecontract` for the same missing-null-check pattern, since several sibling processors (e.g. `VoteRewardUtil`) already demonstrate the correct guarded pattern.

### Proof of Concept
1. Deploy a smart contract that, via the TVM "vote" native-contract path (through `Program.java`'s dispatch to `VoteWitnessProcessor`), calls vote-witness logic using an address that has never been recorded in `AccountStore` (e.g. derive a fresh address inside the contract call context that has received no TRX and has no account entry).
2. Trigger the contract call from any account with sufficient energy to reach the native vote dispatch.
3. `VoteWitnessProcessor.execute()` calls `repo.getAccount(ownerAddress)`, which returns `null`; the subsequent `accountCapsule.getVotesList()` call throws `NullPointerException`, which is not one of the checked exceptions (`ContractExeException`/`ContractValidateException`) the surrounding TVM call-dispatch code is designed to catch, risking abnormal termination of transaction/block processing on any node that executes this transaction.

Note: I was unable to fully trace the exact call site(s) in `Program.java` that invoke `VoteWitnessProcessor` (grep matched 3 occurrences in `Program.java` in one search pass but a follow-up scoped search returned no matches, likely due to an indexing/search inconsistency), so the precise opcode/dispatch trigger conditions in `Program.java` could not be independently confirmed within the available tool calls. A Devin session with full repository access would be needed to pin down the exact TVM invocation path and confirm exception propagation behavior end-to-end.

    if (repo == null) {
      throw new ContractValidateException(STORE_NOT_EXIST);
    }

    if (param.getVotes().size() > MAX_VOTE_NUMBER) {
      throw new ContractValidateException(
          "VoteNumber more than maxVoteNumber " + MAX_VOTE_NUMBER);
    }
  }

  public void execute(VoteWitnessParam param, Repository repo) throws ContractExeException {
    byte[] ownerAddress = param.getVoterAddress();
    VoteRewardUtil.withdrawReward(ownerAddress, repo);

    AccountCapsule accountCapsule = repo.getAccount(ownerAddress);

    VotesCapsule votesCapsule = repo.getVotes(ownerAddress);
    if (votesCapsule == null) {
      votesCapsule = new VotesCapsule(ByteString.copyFrom(ownerAddress),
          accountCapsule.getVotesList());
    }

    accountCapsule.clearVotes();
