### Title
`ScanPoolMetadata` aborts the entire storage walk on a single repository's alternates read failure - ([File: internal/gitaly/service/internalgitaly/scan_pool_metadata.go])

### Summary
`ScanPoolMetadata` walks every repository in a storage and, for each one, reads its `objects/info/alternates` file to determine pool membership. If that per-repository read fails for any single repository, the error is propagated instead of being handled locally, and Go's `filepath.WalkDir` aborts the *entire* walk. This means one problematic repository silently prevents pool-metadata discovery for every other, unrelated repository in the same storage — mirroring the reported bug class where a single failing external call inside a per-item loop disables functionality for all other, unrelated items.

### Finding Description
`processPoolMemberFunc` is invoked once per repository found by `walk.FindRepositories`. On failure to read a repository's alternates info it returns a hard error rather than skipping the repository: [1](#0-0) 

This callback is passed straight into `filepath.WalkDir` via `walk.FindRepositories`: [2](#0-1) 

Per `filepath.WalkDir` semantics, any error returned by the walk function other than `fs.SkipDir`/`fs.SkipAll` immediately terminates the walk and is bubbled up. `ScanPoolMetadata` then converts it to an `Internal` error and ends the stream: [3](#0-2) 

`AlternatesInfoForRepository` itself performs two separate filesystem accesses — an open/read of the alternates file followed by a separate `os.Stat` on the same path — either of which can fail transiently (e.g. a TOCTOU race where the file is renamed/removed between the two calls, or a permission/mount hiccup): [4](#0-3) 

Such a race is not far-fetched: legitimate, unprivileged repository operations rewrite or remove the alternates file via a backup-and-rename dance, e.g. object pool disconnection (`Disconnect`), which any repository/fork owner can trigger: [5](#0-4) 

If a `ScanPoolMetadata` pass is running concurrently on the same storage while this rename happens on some other repository, `os.Stat` on the transiently-renamed alternates file can fail, and the entire walk for the storage — potentially covering thousands of unrelated repositories/forks — stops and returns an internal error instead of the expected stream of pool relationships.

Notably, the codebase demonstrates awareness of exactly this hazard elsewhere and handles it correctly: `RepositoryCounter.countRepositories` explicitly logs and returns `nil` (continue) rather than propagating the error from a similar per-repository operation during the same kind of storage-wide walk: [6](#0-5) 

`ScanPoolMetadata`'s `processPoolMemberFunc` does not follow this pattern for the `AlternatesInfoForRepository` error path.

### Impact Explanation
`ScanPoolMetadata` is the mechanism used to (re)discover repository-to-object-pool relationships across an entire storage, feeding the pool metadata store that downstream housekeeping/consistency logic (object pool disconnect safety checks, `RepositoryInfo` pool-size aggregation, `FetchIntoObjectPool`, replication of object pool state) relies on. A single repository whose alternates file transiently fails to be read aborts metadata discovery for *every other* repository still to be walked in that storage (walk order is lexicographic, so anything sorting after the failing path is skipped for that run). This is a availability/DoS impact scoped to a maintenance handler rather than to a live push/fetch path, so it does not itself corrupt data, but it can leave the pool metadata store permanently stale for a large fraction of repositories in a storage, which is the direct analog of the original report's "one bad item disables the loop-based mechanism for all others."

### Likelihood Explanation
Likelihood is moderate-to-low: it requires a narrow timing race (or a transient filesystem/permission error) coinciding with a `ScanPoolMetadata` pass touching the same repository. Object pool disconnection is a normal, unprivileged operation (e.g. triggered when a fork is detached from its pool), so the precondition is reachable without any special privileges — it does not require a leaked token, malicious peer, or MITM. However, it is inherently racy and not deterministically reproducible on demand by an attacker.

### Recommendation
In `processPoolMemberFunc`, do not return a hard error when `stats.AlternatesInfoForRepository` fails for a single repository; instead log the failure (as `RepositoryCounter.countRepositories` does) and return `nil` to allow the walk to continue with the remaining repositories. More generally, review all consumers of `walk.FindRepositories` to ensure a per-repository failure cannot abort the walk for unrelated repositories, matching the pattern already used in `internal/gitaly/storage/counter/counter.go`.

### Proof of Concept
1. On a Gitaly storage, create two repositories `A` and `B`, both linked to an object pool via `objects/info/alternates`.
2. Start a `ScanPoolMetadata` stream for that storage (this is what happens periodically/administratively to rebuild pool metadata).
3. Concurrently, invoke the normal `DisconnectGitAlternates` flow on repository `A` (an ordinary, unprivileged operation any fork owner can perform), which backs up and removes/renames `A`'s alternates file mid-walk (see `internal/git/objectpool/disconnect.go`'s `newBackupFile`/rename sequence).
4. If the walk visits `A` at the moment its alternates file is being renamed away, `os.Stat` inside `AlternatesInfoForRepository` fails, `processPoolMemberFunc` returns a non-nil error, `filepath.WalkDir` aborts, and the `ScanPoolMetadata` RPC terminates with an `Internal` error — repository `B` (and any other repository ordered after `A`) is never reported even though it is perfectly healthy and linked to a pool.

func (s *server) ScanPoolMetadata(req *gitalypb.ScanPoolMetadataRequest, stream gitalypb.InternalGitaly_ScanPoolMetadataServer) error {
	ctx := stream.Context()
	storageName := req.GetStorageName()

	storagePath, err := s.locator.GetStorageByName(ctx, storageName)
	if err != nil {
		return structerr.NewInvalidArgument("get storage: %w", err)
	}

	processPoolMember := processPoolMemberFunc(ctx, storagePath, storageName, s.poolStore, s.logger, stream)

	if err := walk.FindRepositories(ctx, s.locator, storageName, processPoolMember); err != nil {
		return structerr.NewInternal("%w", err)
	}

	return nil
}

// AlternatesInfoForRepository reads the alternates file and returns information on it. This
// function does not return an error in case the alternates file doesn't exist. Existence can be
// checked via the `Exists` field of the returned `AlternatesInfo` structure.
func AlternatesInfoForRepository(repoPath string) (AlternatesInfo, error) {
	alternatePaths, err := ReadAlternatesFile(repoPath)
	if err != nil {
		if errors.Is(err, fs.ErrNotExist) {
			return AlternatesInfo{Exists: false}, nil
		}

		return AlternatesInfo{}, fmt.Errorf("read alternates file: %w", err)
	}

	stat, err := os.Stat(AlternatesFilePath(repoPath))
	if err != nil {
		return AlternatesInfo{}, fmt.Errorf("stat: %w", err)
	}

	return AlternatesInfo{
		Exists:            true,
		ObjectDirectories: alternatePaths,
		LastModified:      stat.ModTime(),
		repoPath:          repoPath,
	}, nil
}
