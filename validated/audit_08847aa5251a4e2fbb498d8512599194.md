### Title
Unstaked attacker can exhaust QUIC `ClientConnectionTracker` slots via never-completing handshakes, bypassing rate limiters that only decrement on successful handshakes - (File: streamer/src/nonblocking/quic.rs)

### Summary
The connection-admission gate in `run_server` checks the overall and per-IP rate limiters with non-consuming "peek" reads (`current_tokens() == 0` and `is_allowed`) that are only decremented later, in `setup_connection`, and only if the QUIC handshake actually succeeds. An attacker who sends valid QUIC Initial packets but never completes the handshake never triggers `register_connection`/`consume_tokens`, so these limiters never engage against it, while each such attempt still consumes a `ClientConnectionTracker` slot (bounded only by `qos.max_concurrent_connections()`) for up to `QUIC_CONNECTION_HANDSHAKE_TIMEOUT` (2 seconds).

### Finding Description
In `streamer/src/nonblocking/quic.rs::run_server` [1](#0-0) , for every accepted `Incoming` the code:
1. Peeks `overall_connection_rate_limiter.current_tokens() == 0` — a non-consuming check.
2. Peeks `rate_limiter.is_allowed(&ip)` — also non-consuming; for an IP never seen before it always returns `true` [2](#0-1) .
3. Calls `ClientConnectionTracker::new(stats.clone(), qos.max_concurrent_connections())`, which increments `stats.open_connections` and fails only once the global slot count reaches `max_concurrent_connections` [3](#0-2) . If it fails, `refused_connections_too_many_open_connections` is incremented and the connection is refused.
4. If a slot is obtained, `setup_connection` is spawned, which calls `timeout(QUIC_CONNECTION_HANDSHAKE_TIMEOUT, connecting).await` — bounding the slot's occupancy to `QUIC_CONNECTION_HANDSHAKE_TIMEOUT = Duration::from_secs(2)` [4](#0-3) [5](#0-4) .
5. Only **after** the handshake succeeds does the code call `rate_limiter.register_connection(&from.ip())` (which actually consumes a token from the per-IP bucket) and `overall_connection_rate_limiter.consume_tokens(1)` (which actually consumes from the global bucket) [6](#0-5) .

Because steps 1–2 never consume tokens, and the only token-consuming operations (step 5) require a successfully completed handshake, an attacker who deliberately never completes the QUIC handshake (e.g., sends a valid Initial packet then goes silent, or drops/malforms subsequent flight packets) never depletes either rate limiter. Such an attacker therefore is not throttled by `connection_rate_limited_per_ipaddr` or `connection_rate_limited_across_all` at all — those stats only fire against attackers who *do* complete handshakes. The only backstop is the global `ClientConnectionTracker` slot count (`max_concurrent_connections`) and the 2-second handshake timeout, which are shared by all peers, staked and unstaked, well-behaved and malicious alike, with no per-IP fairness enforced against half-open attempts.

QUIC Initial packets are trivial and cheap to construct without any server secret or completed round trip (initial protection keys are derived from public, version-specific constants and the client-chosen Destination Connection ID per the QUIC spec), so quinn's `Endpoint::accept()` will happily yield an `Incoming` for essentially any well-formed Initial datagram, letting the attacker "spend" one UDP packet to occupy a full tracker slot for up to 2 seconds. Repeating this continuously (from one IP or a rotating set) lets the attacker keep the global `open_connections` counter pinned at `max_concurrent_connections`, causing `refused_connections_too_many_open_connections` to trigger for legitimate unstaked and even staked clients attempting real connections, since the tracker slot check in step 3 is unconditional and independent of stake — it happens before per-type (staked/unstaked) `ConnectionTable` admission logic ever runs.

### Impact Explanation
This is a QoS-evasion / connection-starvation issue: an unprivileged, unstaked attacker can consume the entire global connection-tracker budget with cheap half-open QUIC handshakes, causing legitimate senders (including staked validators) to be refused via `refused_connections_too_many_open_connections`, starving them of TPU capacity. This matches the "unstaked client can bypass or unfairly capture connection/QoS limits and starve legitimate senders of TPU capacity" bounty category referenced in the prompt.

### Likelihood Explanation
Feasible for any unprivileged remote UDP client with no stake and no gossip/config access — it only requires the ability to send raw UDP/QUIC Initial packets to the public TPU QUIC port and refrain from completing the handshake, which is well within the stated attacker capability (arbitrary packets/streams to the TPU port). The attack is trivially repeatable: each attempt costs the attacker one packet and at most 2 seconds of "connection lifetime," while the defender's rate limiters (per-IP and global) never engage against non-completing handshakes, so the attacker's "share" of the connection pool is not bounded by `max_connections_per_ipaddr_per_min` as intended — it is bounded only by how fast the attacker can source new half-open attempts (single IP is sufficient since the tracker slot limit is global, not per-IP).

### Recommendation
Consume from (or at least provisionally reserve against) the per-IP and overall rate limiters at admission time (before/while allocating a `ClientConnectionTracker` slot) rather than only after a successful handshake, so that peers who never complete the handshake still count against their rate budget. Alternatively/additionally, reserve a portion of `max_concurrent_connections` slots specifically for staked/known peers, or apply a per-IP cap on *outstanding* (pre-handshake) `ClientConnectionTracker` slots so a single IP cannot occupy an unbounded fraction of the global pool with half-open connections.

### Proof of Concept
Integration test plan (extending the existing test harness in `streamer/src/nonblocking/quic.rs`, using `setup_quic_server`/`make_client_endpoint` helpers already present in the test module):

1. Spawn the QUIC server via `setup_quic_server` with a small `max_concurrent_connections` (e.g., 4) via `SwQosConfig`/`SimpleQosConfig`.
2. From a single attacker source, repeatedly open raw UDP sockets and send a crafted, spec-valid QUIC Initial datagram to the server's TPU QUIC port using quinn's client `Endpoint::connect` but drop/never respond to server flight packets (e.g., by immediately closing the underlying UDP socket after sending the Initial, or using a custom transport that only writes the first datagram) — repeat this `max_concurrent_connections + N` times within a window smaller than `QUIC_CONNECTION_HANDSHAKE_TIMEOUT` (2s).
3. Concurrently, have a legitimate client attempt `make_client_endpoint(&server_address, None).await` and complete a normal handshake.
4. Assert:
   - `stats.open_connections` reaches `max_concurrent_connections` due to the attacker's half-open attempts.
   - `stats.refused_connections_too_many_open_connections` increments for the legitimate client's attempt (i.e., it is refused) while the attacker's half-open connections are still pending.
   - `stats.connection_rate_limited_per_ipaddr` and `stats.connection_rate_limited_across_all` remain at 0 for the attacker's traffic throughout, demonstrating the rate limiters never engaged against the attacker despite it having sent far more than `max_connections_per_ipaddr_per_min` connection attempts.
   - After `QUIC_CONNECTION_HANDSHAKE_TIMEOUT` elapses, `stats.connection_setup_timeout` increments and slots free up, then legitimate client succeeds — showing the window of starvation is repeatable indefinitely by the attacker simply repeating the flood every ~2 seconds.

impl ClientConnectionTracker {
    /// Check the max_concurrent_connections limit and if it is within the limit
    /// create ClientConnectionTracker and increment open connection count. Otherwise returns Err
    fn new(stats: Arc<StreamerStats>, max_concurrent_connections: usize) -> Result<Self, ()> {
        let open_connections = stats.open_connections.fetch_add(1, Ordering::Relaxed);
        if open_connections >= max_concurrent_connections {
            stats.open_connections.fetch_sub(1, Ordering::Relaxed);
            debug!(
                "There are too many concurrent connections opened already: open: \
                 {open_connections}, max: {max_concurrent_connections}"
            );
            return Err(());
        }

        Ok(Self { stats })
    }
}
