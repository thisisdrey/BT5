### Title
Unauthenticated forgery of `SignerEvent::NewBurnBlock` via unauthenticated `/new_burn_block` endpoint - ([File: libsigner/src/events.rs])

### Summary
`SignerEventReceiver::next_event` dispatches any POST to `/new_burn_block` straight into `process_event::<T, BurnBlockEvent>` with no source authentication, and `TryFrom<BurnBlockEvent> for SignerEvent<T>` copies `burn_block_height`, `burn_block_hash`, `consensus_hash`, and `parent_burn_block_hash` verbatim into `SignerEvent::NewBurnBlock`. Any remote party who can reach the signer's bound HTTP listener can therefore inject an arbitrary, attacker-chosen burn-block view into the signer's event stream.

### Finding Description
The broken equality is: `SignerEvent::NewBurnBlock` delivered to the signer runloop should equal the burn block actually observed/committed by the paired stacks-node's event dispatcher, but the transport never enforces this. In `next_event` (`libsigner/src/events.rs:413-459`), the only routing logic is on `request.url()` and `request.method()`; there is no check of an API/shared secret, no peer allowlist, no TLS client cert, nothing tying the request to the legitimate node [1](#0-0) . `process_event` reads the raw JSON body and deserializes it directly into `E` (here `BurnBlockEvent`), then calls `.try_into()` [2](#0-1) . `TryFrom<BurnBlockEvent> for SignerEvent<T>` then blindly copies every field from the deserialized JSON into the emitted `SignerEvent::NewBurnBlock` variant with no cross-check against any locally observed chain state [3](#0-2) . Since `HttpServer::http(listener)` (tiny_http) accepts connections from any source that can reach the bound socket, and the event receiver performs no authentication of the caller, a remote unprivileged party who can open a TCP connection to the signer's event-receiver port can POST a crafted `BurnBlockEvent` JSON body and have it accepted verbatim as a genuine node-observed burn block.

### Impact Explanation
An attacker can forge the signer's view of the burnchain tip — arbitrary `burn_block_height`, `burn_header_hash`, `consensus_hash`, and `parent_burn_block_hash` — and inject it directly into the signer runloop's event channel, repeatable on demand for every message sent. This is an unauthenticated write into the signer's internal decision-input state, matching the "unauthenticated/unauthorized write to state" Critical category, since nothing in the transport layer validates that the payload originated from the node the signer is paired with.

### Likelihood Explanation
The only precondition is TCP reachability to the signer's event-receiver bind address/port; no secret, peer identity, StackerDB slot ownership, or privileged role is required. If that port is bound to a non-loopback/publicly reachable interface (which is a deployment/config choice, not enforced by this code), any remote party satisfying the stated unprivileged-attacker model can exploit it with a single crafted HTTP POST, and can repeat it arbitrarily.

### Recommendation
Add authentication to the `SignerEventReceiver` HTTP server (e.g., a shared bearer token/HMAC header configured between the node's event dispatcher and the signer, validated in `next_event` before dispatch), and/or bind the listener to loopback-only by default with an explicit opt-in for remote binding; reject requests lacking a valid credential before calling `process_event`.

```rust
// libsigner/src/events.rs (test module) or a new integration test
use std::net::{TcpStream, SocketAddr};
use std::io::Write;
use libsigner::{SignerEventReceiver, EventReceiver, SignerEvent};

#[test]
fn forge_new_burn_block_unauthenticated() {
    let mut receiver = SignerEventReceiver::<crate::v0::messages::SignerMessage>::new(false);
    let addr: SocketAddr = "127.0.0.1:0".parse().unwrap();
    let bound = receiver.bind(addr).unwrap();

    // Attacker-controlled JSON body, no auth header, no relation to node state
    let body = serde_json::json!({
        "burn_block_hash": "0x11".repeat(1).to_string(), // crafted hex hash
        "burn_block_height": 999999,
        "consensus_hash": "0x22".repeat(1).to_string(),
        "parent_burn_block_hash": "0x33".repeat(1).to_string(),
        "burn_amount": 0,
        "reward_recipients": [],
        "reward_slot_holders": [],
        "burn_block_index": 0
    }).to_string();

    let mut stream = TcpStream::connect(bound).unwrap();
    let req = format!(
        "POST /new_burn_block HTTP/1.1\r\nHost: {}\r\nContent-Length: {}\r\nContent-Type: application/json\r\nConnection: close\r\n\r\n{}",
        bound, body.len(), body
    );
    stream.write_all(req.as_bytes()).unwrap();

    let ev = receiver.next_event().unwrap();
    match ev {
        SignerEvent::NewBurnBlock { burn_height, .. } => assert_eq!(burn_height, 999999),
        _ => panic!("unexpected event"),
    }
}
```
This connects as an arbitrary unauthenticated client (no header, no secret) and demonstrates the attacker-supplied `burn_height`/hashes flow unchecked into `SignerEvent::NewBurnBlock`, confirming the transport performs no verification against the real node's observed state at `libsigner/src/events.rs:637-649` and `:413-459`.

```rust
fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}
```
