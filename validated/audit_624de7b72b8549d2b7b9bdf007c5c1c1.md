### Title
Structural fee bypass on Nep245/Imt token diffs via 1-unit leg splitting - (File: `contracts/defuse/core/src/intents/token_diff.rs`)

### Summary
`TokenDiff::token_fee` decides whether to apply the protocol fee based solely on the `amount` of a *single* `TokenDiff` intent's delta for a Nep245/Imt token, requiring `amount > 1` to charge a fee. Because this check is evaluated per-intent and never aggregated across intents in the same batch/signer/token, an attacker can split any transfer of N units of the same Nep245/Imt id into N intents of `amount = 1` each, causing `token_fee` to return `Pips::ZERO` every time and fully bypassing the fee that a single combined intent would have paid.

### Finding Description
The claimed binding is:
`fee.fee_ceil(2) == fee.fee_ceil(1) + fee.fee_ceil(1)` for the same signer/token/fee-rate.

Tracing `TokenDiff::execute_intent` [1](#0-0) , for each `(token_id, delta)` pair in a single intent's diff, if `delta < 0` the fee is computed as `Self::token_fee(token_id, amount, protocol_fee).fee_ceil(amount)` where `amount = delta.unsigned_abs()`. `token_fee` implements the guard in question: [2](#0-1) 

For `fee = Pips::ONE_PERCENT` (10,000 pips out of `Pips::MAX = 1,000,000`):
- Single intent, `amount = 2`: guard `amount > 1` is true → `token_fee` returns `ONE_PERCENT`; `fee_ceil(2) = ceil(2 * 10000 / 1000000) = 1`.
- Two intents, each `amount = 1`: guard `amount > 1` is false → `token_fee` returns `Pips::ZERO`; `fee_ceil(1) = 0` for each, total `0`.

So `1 != 0` — the equality is broken. This is not limited to the amount=2 boundary: because the check operates per single-intent delta magnitude, any transfer of N Nep245/Imt units can be split into N intents of `amount=1`, always yielding zero fee (`token_fee` returns `Pips::ZERO`, computed via `fee_ceil` on `crates/primitives/fees/src/lib.rs` lines 116-121).

Root cause: fee eligibility is decided using the local magnitude of a single `TokenDiff.diff` entry rather than the net economic transfer that ultimately gets settled via `TransferMatcher::finalize` [3](#0-2) . The matcher aggregates deposits/withdrawals across all intents in the batch into net transfers between accounts [4](#0-3) , but by the time matching happens, the fee has already been computed and collected per-intent in `execute_intent`, with no reference to the aggregate. `Engine::execute_signed_intents` simply iterates each signed payload and executes its intents independently [5](#0-4) , with no cross-intent or cross-batch fee aggregation.

Attacker payload: sign one `MultiPayload` (or two) each containing a `TokenDiff` intent with `diff = {Nep245TokenId(mt.near, id): -1}`, matched by a counterparty transaction that credits the equivalent `+1` per leg (or a self-consistent set of intents netting to zero via `TransferMatcher`). None of `verify`, `has_public_key`, `verify_intent_nonce`, nonce commit, or `checked_*` arithmetic guards check per-token aggregate amounts across intents — they only validate signature/nonce/deadline validity, which splitting into multiple correctly-signed nonces trivially satisfies.

### Impact Explanation
Protocol fees on Nep245/Imt (multi-token) transfers are under-collected/bypassed entirely whenever a party structures a transfer as multiple `amount=1` legs instead of one combined delta. The fee collector (`engine.state.fee_collector()`) receives strictly less than intended for the exact same net token movement, matching the "protocol fees bypassed or over-collected" Critical impact category. This is repeatable indefinitely, for any Nep245/Imt token id, by any unprivileged signer, across any number of units, at zero additional attacker cost beyond additional NEAR gas for the extra intents/nonces.

### Likelihood Explanation
Preconditions are minimal: the attacker only needs to hold ≥1 unit of a Nep245/Imt-typed token per leg and craft two or more legitimately-signed `TokenDiff` intents instead of one. No privileged role, relayer key, or victim key is required. This is trivially and cheaply repeatable (the only cost is marginal extra gas for issuing more/smaller intents), making it highly likely to be exploited by any economically rational trader wanting to avoid the MT fee.

### Recommendation
Aggregate fee-eligible amounts per `(signer, token_id)` across the whole batch (or across the fully netted transfer produced by `TransferMatcher::finalize`) before applying the `amount > 1` threshold for Nep245/Imt, rather than evaluating it per individual `TokenDiff` intent delta. Alternatively, remove the `amount > 1` exemption for Nep245/Imt entirely (charge fee on any nonzero negative delta) if the intent behind the exemption was only meant to spare true "NFT-like" single-unit MT transfers, and instead identify NFT-like MT ids by their token metadata/supply rather than by the size of a single intent's delta.

use crate::{fees::Pips, token_id::nep245::Nep245TokenId, token_id::TokenId};

#[test]
fn fee_bypass_via_leg_splitting_nep245() {
    let token_id: TokenId =
        Nep245TokenId::new("mt.near".parse().unwrap(), "id1".to_string()).into();
    let fee = Pips::ONE_PERCENT;

    // Combined single intent: amount = 2
    let combined_fee = TokenDiff::token_fee(&token_id, 2, fee).fee_ceil(2);

    // Split into two intents: amount = 1 each
    let split_fee_leg1 = TokenDiff::token_fee(&token_id, 1, fee).fee_ceil(1);
    let split_fee_leg2 = TokenDiff::token_fee(&token_id, 1, fee).fee_ceil(1);
    let split_fee_total = split_fee_leg1 + split_fee_leg2;

    assert_eq!(combined_fee, 1);
    assert_eq!(split_fee_total, 0);
    assert_ne!(
        combined_fee, split_fee_total,
        "fee for identical net transfer differs depending on leg-splitting: {combined_fee} vs {split_fee_total}"
    );
}

    // If unmatched deltas overflow, then Err(None) is returned.
    pub fn finalize(self) -> Result<Transfers, InvariantViolated> {
        let mut transfers = Transfers::default();
        let mut deltas = TokenDeltas::default();
        for (token_id, transfer_matcher) in self.0 {
            if let Err(unmatched) = transfer_matcher.finalize_into(&token_id, &mut transfers)
                && (unmatched == 0 || deltas.apply_delta(token_id, unmatched).is_none())
            {
                return Err(InvariantViolated::Overflow);
            }
        }
        if !deltas.is_empty() {
            return Err(InvariantViolated::UnmatchedDeltas {
                unmatched_deltas: deltas,
            });
        }
        Ok(transfers)
    }
}

    pub fn finalize_into(self, token_id: &TokenId, transfers: &mut Transfers) -> Result<(), i128> {
        // sort deposits and withdrawals in descending order
        let [mut deposits, mut withdrawals] = [self.deposits, self.withdrawals].map(|amounts| {
            let mut amounts: Vec<_> = amounts.into_iter().collect();
            amounts.sort_unstable_by_key(|(_, amount)| Reverse(*amount));
            amounts.into_iter()
        });

        // take first sender and receiver
        let (mut deposit, mut withdraw) = (deposits.next(), withdrawals.next());

        // as long as there is both: sender and receiver
        while let Some(((sender, send), (receiver, receive))) =
            withdraw.as_mut().zip(deposit.as_mut())
        {
            // get min amount and transfer
            let transfer = (*send).min(*receive);
            transfers
                .transfer(sender.clone(), receiver.clone(), token_id.clone(), transfer)
                // no error can happen since we add only one transfer for each
                // combination of (sender, receiver, token_id)
                .unwrap_or_else(|| unreachable!());

            // subtract amount from sender and receiver
            *send = send.saturating_sub(transfer);
            *receive = receive.saturating_sub(transfer);

            if *send == 0 {
                // select next sender
                withdraw = withdrawals.next();
            }
            if *receive == 0 {
                // select next receiver
                deposit = deposits.next();
            }
        }

        // only sender(s) left
        if let Some((_, send)) = withdraw {
            return Err(withdrawals
                .try_fold(send, |total, (_, s)| total.checked_add(s))
                .and_then(|total| i128::try_from(total).ok())
                .and_then(i128::checked_neg)
                .unwrap_or_default());
        }
        // only receiver(s) left
        if let Some((_, receive)) = deposit {
            return Err(deposits
                .try_fold(receive, |total, (_, r)| total.checked_add(r))
                .and_then(|total| i128::try_from(total).ok())
                .unwrap_or_default());
        }

        Ok(())
    }
