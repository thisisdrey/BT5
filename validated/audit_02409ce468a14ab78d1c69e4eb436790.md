### Title
Unsanitized `tar -C -xvf -` extraction in CreateRepositoryFromSnapshot allows path traversal/symlink escape and SSRF via ResolvedAddress - (File: internal/gitaly/service/repository/create_repository_from_snapshot.go)

### Summary
`CreateRepositoryFromSnapshot` fetches an attacker-controlled `HttpUrl` and pipes the raw response body directly into the system `tar -C path -xvf -` command with no entry-name or symlink sanitization, unlike the hardened `extractTarToDirectory` used in `replicate.go`. Additionally, `newResolvedHTTPClient` accepts an arbitrary `ResolvedAddress` and dials it directly, allowing DNS-bypassing connections to internal-only addresses.

### Finding Description
In `s.untar` [1](#0-0) , the HTTP response body (`rsp.Body`) from `in.GetHttpUrl()` is passed as stdin directly to the external `tar` binary with `-C path -xvf -`, with no validation of the archive entries beforehand. Contrast this with `internal/gitaly/service/repository/replicate.go`'s `extractTarToDirectory`, which explicitly checks that each `targetPath := filepath.Join(targetDir, header.Name)` stays within `targetDir`, and separately validates symlink/hardlink targets before creating them [2](#0-1) [3](#0-2) . `create_repository_from_snapshot.go` has no equivalent check; system `tar` by default will follow `../` path components and symlinks written into the archive, permitting writes outside the target repository directory (e.g., into a sibling repository's `hooks/`).

The code itself documents this as an accepted, known risk: "NOTE: The received archive is trusted *a lot*. Before pointing this RPC at endpoints not under our control, it should undergo a lot of hardening." [4](#0-3) 

Separately, `newResolvedHTTPClient` takes `in.GetResolvedAddress()`, validates only that it parses as an IP (`net.ParseIP`), and dials that address+port directly, bypassing DNS resolution of the host in `HttpUrl` [5](#0-4) . There is no check that this IP is not a loopback/link-local/RFC1918 address, so an attacker who controls this field can direct Gitaly's HTTP client at internal-only network endpoints while presenting an arbitrary hostname/scheme in `HttpUrl`.

### Impact Explanation
If reachable by an unprivileged attacker, this allows planting or overwriting arbitrary files outside the target repository path (path traversal / archive extraction escape), including overwriting Git hooks (`hooks/pre-receive`, etc.) of unrelated repositories on the same storage — a path to remote code execution on the Gitaly host. The `ResolvedAddress` design additionally lets an attacker force outbound Gitaly HTTP requests to internal-only network addresses (SSRF), potentially reaching internal services or metadata endpoints reachable only from the Gitaly host.

### Likelihood Explanation
This depends heavily on whether `CreateRepositoryFromSnapshot` is actually reachable by an unprivileged, ordinary GitLab user in the current product configuration. Both the in-code warning ("trusted *a lot*... before pointing this RPC at endpoints not under our control") and the design of `ResolvedAddress` (intended for GitLab Rails to pre-resolve a validated, DNS-rebinding-safe address before calling Gitaly) strongly indicate that this RPC's `HttpUrl`/`ResolvedAddress` inputs are meant to be constrained/validated by a trusted caller (GitLab Rails' internal Import/Export or snapshot-transfer flow) rather than fed directly with attacker-chosen arbitrary values. I could not confirm within this repository (Gitaly only) what authorization/gating GitLab Rails applies before invoking this RPC with attacker-influenced `HttpUrl`/`ResolvedAddress`, since that logic lives outside Gitaly. Given the explicit code comment acknowledging the archive is "trusted a lot" and that hardening is a known future TODO for use with untrusted endpoints, this looks like a recognized, already-documented risk rather than a novel bypass of an existing Gitaly-side control, and the actual exploitability hinges entirely on Rails-side gating that is out of scope for this repo.

### Recommendation
- Replace the raw `tar -C path -xvf -` command in `create_repository_from_snapshot.go` with the same hardened extraction routine used in `replicate.go` (`extractTarToDirectory`/`extractFile`), enforcing path-containment and symlink/hardlink target validation.
- In `newResolvedHTTPClient`, reject `ResolvedAddress` values that are loopback, link-local, or private/internal ranges unless explicitly allowed by configuration, or otherwise ensure only GitLab Rails' pre-vetted address is ever passed through with corresponding trust boundaries documented and enforced.

### Proof of Concept
Not independently reproducible from the Gitaly repo alone: the vulnerable code path is fully present in `create_repository_from_snapshot.go` (raw `tar` invocation, no entry sanitization) as shown above, but confirming actual attacker reachability (whether an unprivileged GitLab user can supply an arbitrary `HttpUrl`/`ResolvedAddress` to this RPC) requires the GitLab Rails call site, which is outside this repository's scope. A conceptual PoC:

func (s *server) untar(ctx context.Context, path string, in *gitalypb.CreateRepositoryFromSnapshotRequest) error {
	req, err := http.NewRequestWithContext(ctx, "GET", in.GetHttpUrl(), nil)
	if err != nil {
		return structerr.NewInvalidArgument("Bad HTTP URL: %w", err)
	}

	client := httpClient
	if resolvedAddress := in.GetResolvedAddress(); resolvedAddress != "" {
		client, err = newResolvedHTTPClient(in.GetHttpUrl(), resolvedAddress)
		if err != nil {
			return structerr.NewInvalidArgument("creating resolved HTTP client: %w", err)
		}
	}

	if in.GetHttpAuth() != "" {
		req.Header.Set("Authorization", in.GetHttpAuth())
	}

	rsp, err := client.Do(req)
	if err != nil {
		return structerr.NewInternal("HTTP request failed: %w", err)
	}
	defer rsp.Body.Close()

	if rsp.StatusCode < http.StatusOK || rsp.StatusCode >= http.StatusMultipleChoices {
		return structerr.NewInternal("HTTP server: %s", rsp.Status)
	}

	cmd, err := command.New(ctx, s.logger, []string{"tar", "-C", path, "-xvf", "-"}, command.WithStdin(rsp.Body))
	if err != nil {
		return err
	}

	return cmd.Wait()
