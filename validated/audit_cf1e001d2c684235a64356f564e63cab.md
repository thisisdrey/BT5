### Title
Object-directory quarantine check accepts any path ending in "quarantine", allowing storage-path escape via a crafted `git_object_directory` field - (File: internal/git/localrepo/paths.go)

### Summary
`Repo.ObjectDirectoryPath()` is supposed to restrict the client-controllable `GitObjectDirectory`/`GitAlternateObjectDirectories` fields of the `Repository` message to either (a) a path inside the repository, or (b) a legitimate transaction/quarantine temp directory prefixed with the repository's own quarantine prefix. The guard that decides whether to skip that containment check is satisfied by any relative path whose *base name* is literally `"quarantine"`, regardless of how many `..` traversal segments precede it or whether the parent directory matches the expected quarantine prefix. This mirrors the External Report's root cause pattern: a public/attacker-reachable input path lacks the access-control/validation that the surrounding code assumes exists, letting an ordinary caller flip protocol-level state (here, the effective object directory used for git operations) outside the intended boundary.

### Finding Description
`ObjectDirectoryPath` first tries `storage.ValidateRelativePath` to confirm the object directory is inside the repo; if that fails it falls back to checking whether the path is a "transaction quarantine directory": [1](#0-0) 

```go
parentDir := filepath.Base(filepath.Dir(relativeObjectDirectoryPath))
baseDir := filepath.Base(relativeObjectDirectoryPath)
isTransactionQuarantineDir := (baseDir == "quarantine") || ((parentDir == "quarantine") && strings.HasPrefix(baseDir, "tmp_objdir"))
...
if !isTransactionQuarantineDir {
    // enforcement block that checks the path is within the repo or within
    // the storage's quarantine temp dir prefix
}
```

The first disjunct, `baseDir == "quarantine"`, does not require any relationship to `repo.locator.TempDir()` or `storage.QuarantineDirectoryPrefix(repo)` at all — it only checks the final path component's literal name. Consequently, any `GitObjectDirectory` value such as `../../../../some/arbitrary/path/quarantine` sets `isTransactionQuarantineDir = true` and the entire containment check at lines 53-75 (`storage.ValidateRelativePath` plus the `expectedQuarantinePrefix` check) is skipped: [2](#0-1) 

Only an existence check (`os.Stat`) is performed afterward — no boundary/prefix validation — so if a directory literally named `quarantine` exists anywhere reachable via the traversal (e.g., an unrelated repository's own quarantine directory, or any directory an admin/other tenant created ending in that name), Gitaly will accept it as the effective object directory for that RPC.

This escape hatch is reachable by an ordinary caller because the `GitObjectDirectory`/`GitAlternateObjectDirectories` fields of the `Repository` proto are part of the public request message (`proto/shared.proto`), and Gitaly's transaction middleware explicitly allows **Accessor** RPCs to carry pre-populated object-directory fields without starting a fresh, sandboxed transaction — this path is only blocked for **Mutator** RPCs: [3](#0-2) 

The comment at lines 278-281 explicitly acknowledges that "this property is violated" when object directories are manually configured, i.e., the invariant that these fields are always legitimately Gitaly/Rails-issued is not actually enforced end-to-end for accessor traffic.

### Impact Explanation
If exploitable end-to-end, this allows an ordinary caller of any read-only ("Accessor") RPC that resolves the target repository's object directory (e.g., object lookups, `Fsck`, ref/commit accessors) to redirect Gitaly's git object search path to a directory outside the intended repository/quarantine sandbox, provided a directory literally named `quarantine` exists at the traversed location. This is a cross-repository/filesystem object-access class issue: it can leak objects from another tenant's quarantine directory (which by design contains not-yet-authorized, potentially private push contents) or otherwise defeat the isolation the quarantine mechanism is meant to provide, similar in spirit to the External Report's "unauthorized state change reachable by anyone" pattern — here the "state" is the effective object-directory search path used for a git operation.

### Likelihood Explanation
Likelihood is moderate and not fully proven: the vulnerable branch is trivially reachable by construction of the `GitObjectDirectory` string (a single string field on a public proto message, with no character-set restriction shown here), and the guard is bypassed by any string ending in `/quarantine`. What is **not verified from static review alone** is (a) which specific Accessor RPC handlers pass client-supplied `GitObjectDirectory` straight into `ObjectDirectoryPath` without an additional locator-level check earlier in the call chain, and (b) whether a target `quarantine`-named directory is realistically discoverable/creatable by an unprivileged caller in a shared Gitaly deployment. Confirming full exploitability would require tracing a concrete accessor RPC end-to-end (or running it) in a live Gitaly instance, which is outside the scope of static code search.

### Recommendation
Tighten `isTransactionQuarantineDir` so that the first disjunct also requires the resolved absolute path to have the expected `storage.QuarantineDirectoryPrefix(repo)` prefix (i.e., merge both branches under the same prefix check instead of allowing a bare basename match to short-circuit validation). Additionally, consider rejecting client-supplied `GitObjectDirectory`/`GitAlternateObjectDirectories` fields for Accessor RPCs unless a signed/opaque quarantine handle (rather than a raw path string) issued by Gitaly itself is presented, closing the gap acknowledged in `middleware.go`.

### Proof of Concept
Not independently executed against a running Gitaly instance; based on static analysis of `internal/git/localrepo/paths.go` lines 43-53 and 61-83, the following would need to be validated live:
1. Ensure a directory named `quarantine` exists at a path reachable via traversal from a target repository (e.g., another repository's own transaction quarantine temp dir, which is created under the storage's temp dir per `quarantine.go`/`locator.go`).
2. Issue an Accessor RPC (per `middleware.go` lines 283-289, quarantine-configured Accessor requests are allowed through without a fresh transaction) whose `Repository.git_object_directory` is set to a relative path such as `../../../<storage-temp-dir-relative-path>/quarantine`.
3. Observe that `ObjectDirectoryPath` returns this foreign directory instead of erroring, because `baseDir == "quarantine"` satisfies `isTransactionQuarantineDir` and skips the `storage.ValidateRelativePath`/`expectedQuarantinePrefix` enforcement.
