### No vulnerability found for this question.

Analysis: Tracing `do_mt_withdraw` at [1](#0-0)  confirms that `ext_mt_core::ext_on(p)` chains `mt_batch_transfer`/`mt_batch_transfer_call` onto the `storage_deposit` promise `p` via a standard NEAR `.then()`-style dependency, which fires regardless of whether `p` succeeded or panicked — and `mt_resolve_withdraw` at [2](#0-1)  only inspects `promise_result_checked_void(0)`/`promise_result_checked_json_with_len(0, …)`, i.e., the result of the immediately-preceding `mt_batch_transfer(_call)`, and only ever re-credits `Nep245TokenId` amounts, never the wNEAR `storage_deposit` leg debited earlier in `internal_mt_withdraw` at [3](#0-2) . So the technical premise about the promise chain and missing wNEAR re-credit is accurate.

However, this cannot be weaponized against a victim: `MtWithdraw` is a signed intent authorized only by the account whose balance is debited, and the malicious `attacker_mt` token contract is chosen by that same signer. The described attack requires the attacker to sign the withdraw themselves, against their own wNEAR balance, targeting their own deployed contract — meaning the only party who loses funds is the attacker, and there is no path for an unprivileged attacker to force this outcome onto another signer's balance without that signer's own signature over the same malicious payload. `mt_force_withdraw` could bypass the signature requirement, but it is gated by `access_control_any(roles(Role::DAO, Role::UnrestrictedWithdrawer))` at [4](#0-3) , which is explicitly out of scope for an unprivileged attacker per the rules.

Since the only demonstrable effect is the signer destroying their own wNEAR with no compensating credit and no attacker profit or third-party victim, this is self-inflicted griefing, which is explicitly listed as out-of-scope ("griefing with no attacker profit").

                .with_static_gas(STORAGE_DEPOSIT_GAS)
                // do not distribute remaining gas here
                .with_unused_gas_weight(0)
                .storage_deposit(Some(withdraw.receiver_id.clone()), None)
        } else {
            Promise::new(withdraw.token)
        };

        let p = ext_mt_core::ext_on(p)
            .with_attached_deposit(NearToken::from_yoctonear(1))
            .with_static_gas(min_gas)
            // distribute remaining gas here
            .with_unused_gas_weight(1);

                withdraw.token_ids,
                amounts,
                None,
                withdraw.memo,
                msg,

                withdraw.receiver_id,
                withdraw.token_ids,
                amounts,
                None,
                withdraw.memo,
            )
        }

#[near]
impl MultiTokenWithdrawResolver for Contract {
    #[private]
    fn mt_resolve_withdraw(
        &mut self,
        token: AccountId,
        sender_id: AccountId,
        token_ids: Vec<defuse_nep245::TokenId>,
        amounts: Vec<U128>,
        is_call: bool,
    ) -> Vec<U128> {
        require!(
            token_ids.len() == amounts.len() && !amounts.is_empty(),
            "invalid args"
        );

        let mut used = if is_call {
            // `mt_batch_transfer_call` returns successfully transferred amounts
            match promise_result_checked_json_with_len::<Vec<U128>>(0, amounts.len()) {
                Ok(Ok(used)) if used.len() == amounts.len() => used,
                Ok(_) => vec![U128(0); amounts.len()],
                // do not refund on failed `mt_batch_transfer_call` due to
                // NEP-141 vulnerability: `mt_resolve_transfer` fails to
                // read result of `mt_on_transfer` due to insufficient gas
                Err(_) => amounts.clone(),
            }
        } else {
            // `mt_batch_transfer` returns empty result on success
            if promise_result_checked_void(0).is_ok() {
                amounts.clone()
            } else {
                vec![U128(0); amounts.len()]
            }
        };

        self.deposit(
            sender_id,
            token_ids
                .into_iter()
                .zip(amounts)
                .zip(&mut used)
                .filter_map(|((token_id, amount), used)| {
                    // update min during iteration
                    used.0 = used.0.min(amount.0);
                    let refund = amount.0.saturating_sub(used.0);
                    if refund > 0 {
                        Some((Nep245TokenId::new(token.clone(), token_id).into(), refund))
                    } else {
                        None
                    }
                }),
            Some(REFUND_MEMO),
        )
        .unwrap_or_else(|err| err.panic());

        used
    }
