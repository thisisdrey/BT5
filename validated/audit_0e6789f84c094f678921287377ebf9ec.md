### Title
Unbounded reftable block parsing causes index-out-of-range panic on malformed/corrupted `.ref` table files - ([File: internal/git/reftable/reftable.go])

### Summary
`internal/git/reftable/reftable.go` parses git reftable-format ref-storage files (`.ref` files under a repository's `reftable/` directory) using raw, unchecked slice indexing. Several of the low-level parsing helpers — `extractBlockLen`, `getVarInt`, `getRefsFromBlock`, and `parseRefBlock` — index into the file's byte buffer using offsets/lengths that are derived directly from the file contents, without verifying the offsets stay within the buffer bounds. Malformed or corrupted table data can therefore trigger a Go runtime panic (`slice bounds out of range`), which is functionally the same defect class as the reported `PlonkVerifier::verify_gnark_proof` issue: unchecked parsing of untrusted/attacker-influenced binary input leads to a crash of the handling code path instead of a graceful error.

### Finding Description
`Table.getVarInt` reads `src[start]` and advances `start` based on the continuation bit of each byte, only checking that `start <= blockEnd`, but `blockEnd` (`b.RestartStart` or `b.FullBlockSize`) is itself computed from unchecked, attacker-influenceable fields in the file: [1](#0-0) 

`getRefsFromBlock` uses the resulting `prefixLength`/`suffixLength`/`hashSize` values to slice `src[idx:idx+suffixLength]` and `src[idx : idx+uint(hashSize)]` directly, with no bounds validation against `len(src)`: [2](#0-1) 

`parseRefBlock` computes `b.RestartStart = blockStart + currentBS - 2 - 3*uint(b.RestartCount)` from `currentBS` (`extractBlockLen`) and `b.RestartCount` (parsed straight from file bytes), which can underflow (since these are unsigned `uint` values) or exceed the true block size, and then feeds these unchecked values into `getRefsFromBlock`: [3](#0-2) 

`extractBlockLen` itself does an unchecked slice read `src[blockStart+1 : blockStart+4]`: [4](#0-3) 

`GetReferences()` drives this parsing loop over the entire on-disk table contents: [5](#0-4) 

Unlike the header/footer parsing in the same file, which validates magic bytes, version, hash ID, and checksum before trusting any derived offsets (`parseHeader`, `parseFooter`), the per-block ref parsing path performs essentially no bounds validation before indexing. [6](#0-5) 

The reftable format is one of the two supported Git reference-storage backends (`git.ReferenceBackendReftables`), and `Table.GetReferences()`/`ParseTable()` is exercised whenever Gitaly reads or resequences a repository's reftable data — e.g. in `internal/gitaly/storage/storagemgr/partition/reftable.go`'s `stageTables()`/`getLatestReftableName()`, which run as part of the write-ahead-log transaction pipeline for repositories using the reftables backend: [7](#0-6) 

Because reftable files are ordinary files on disk inside a repository's data directory (`<repo>/reftable/*.ref`), any code path that writes or replicates repository content that is not purely `git`-generated — e.g. repository creation/import from an uploaded bundle, replication/backup restoration, or any other path that materializes raw repository files supplied outside of `git`'s own reftable writer — could deposit a corrupted or adversarially crafted `.ref` file that is later read by `ParseTable`/`GetReferences`. Even absent a fully attacker-controlled write path, ordinary file corruption (partial writes, disk truncation, concurrent access) can independently trigger the same panics, since none of the length/offset fields derived from file bytes are bounds-checked against the actual buffer size.

### Impact Explanation
A panic inside these parsing routines that is not recovered before propagating to a goroutine boundary will crash the whole `gitaly` process, taking down all in-flight requests for every repository the storage node serves — the same "process termination" impact called out in the reference report. Gitaly's gRPC layer does install `panichandler.UnaryPanicHandler`/`StreamPanicHandler` as the outermost interceptors to convert panics that occur directly inside RPC handler goroutines into `Internal` errors: [8](#0-7) 
However, this recovery only protects the specific goroutine on which the interceptor's `defer` runs; a panic that occurs on a different goroutine spawned during the RPC (or during background transaction-manager/WAL processing such as `stageTables()`) is not guarded by this interceptor and can crash the entire process. Repeated read attempts against a corrupted or crafted reftable file thus provide a persistent denial-of-service vector against the storage node, matching the "repeated attacks" / "process termination" scenario in the source report.

### Likelihood Explanation
Likelihood is moderate: the most straightforward trigger is any form of repository data corruption (partial disk writes, concurrent unsynchronized modification of reftable files, or a bug elsewhere in the reftable writer) rather than a fully external "malformed input" path, since the reftable format is normally written by `git` itself. However, any repository-provisioning code path in Gitaly/Praefect that materializes raw filesystem content into a repository (e.g. via replication, backup restore, or bundle-based repository creation) without re-validating the format of any embedded reftable files would give an unprivileged actor a way to plant a crafted `.ref` file, after which any subsequent read of references (`ListRefs`, WAL/transaction processing) would trigger the panic. I was unable to fully verify from the indexed files whether such a raw-file-copy repository provisioning path exists that lets a normal user push/import content that lands directly as `reftable/*.ref` files without being written by `git`'s own reftable code — this would need to be confirmed with a full checkout of the repository-creation/import and replication code paths.

### Recommendation
1. Add explicit bounds checks in `extractBlockLen`, `getVarInt`, `getRefsFromBlock`, and `parseRefBlock` before every slice operation, returning an error (e.g. "corrupt reftable block") instead of indexing unchecked offsets.
2. Validate that `RestartStart`, `FullBlockSize`, and every computed `idx` value are within `[0, len(src))` (and within the current block's bounds) before use, and specifically guard the subtraction `blockStart + currentBS - 2 - 3*uint(b.RestartCount)` against unsigned underflow.
3. Wrap the top-level reftable parsing entry points (`ParseTable`, `GetReferences`, `stageTables`) with `recover()` at the goroutine boundary so a malformed table degrades to a structured error rather than crashing the process, mirroring the protection already provided by `panichandler` for gRPC handler goroutines.
4. Add fuzz tests for `Table.GetReferences`/`parseRefBlock`/`getRefsFromBlock` (there is already a fuzz harness pattern for catfile parsing in `internal/git/catfile/object_info_reader_fuzz.go` that can be used as a template) to catch out-of-bounds accesses on crafted reftable files.
5. Audit any repository-provisioning path (bundle-based creation, replication/backup restore) that writes files directly into a repository's `reftable/` directory to ensure such files are always re-validated (or regenerated via `git`) rather than trusted as-is.

### Proof of Concept
Not independently reproduced against a live Gitaly instance because the code index does not expose the full repository-creation/import code paths needed to confirm an end-to-end attacker-controlled write of a crafted `.ref` file. The root-cause mechanism can, however, be demonstrated directly against the parser: a `reftable/*.ref` file whose ref-block bytes encode a `RestartCount` or varint length such that `b.RestartStart`/`idx` exceeds `len(src)` (or causes the unsigned subtraction in `parseRefBlock` to underflow) will cause `Table.GetReferences()` to panic with `runtime error: slice bounds out of range` when it reaches the corresponding `src[idx:idx+...]` expression in `getRefsFromBlock`, as shown in the cited code. The existing test `TestParseTable_validation` in `internal/git/reftable/reftable_test.go` already patches header/footer fields to test validation of *those* structures; the same file-patching technique, applied to the ref-block bytes rather than the header/footer, is the concrete PoC vector for this bug.

// parseHeader parses the header of a reftable. reader should be at the beginning
// of the header.
func parseHeader(reader io.Reader, hdr *header) error {
	if err := binary.Read(reader, binary.BigEndian, &hdr.headerV1); err != nil {
		return fmt.Errorf("reading header: %w", err)
	}

	if hdr.Magic != magic {
		return fmt.Errorf("unexpected magic bytes: %q", hdr.Magic)
	}

	if !(hdr.Version == 1 || hdr.Version == 2) {
		return fmt.Errorf("unsupported version: %d", hdr.Version)
	}

	if hdr.Version == 2 {
		if err := binary.Read(reader, binary.BigEndian, &hdr.HashID); err != nil {
			return fmt.Errorf("read hash id: %w", err)
		}

		if !(hdr.HashID == hashIDSHA1 || hdr.HashID == hashIDSHA256) {
			return fmt.Errorf("unsupported hash id: %q", hdr.HashID)
		}
	}

	return nil
}

// parseFooter parses the footer of a reftable. reader should be at the beginning
// of the footer.
func parseFooter(reader io.Reader, f *footer) error {
	footerBytes, err := io.ReadAll(reader)
	if err != nil {
		return fmt.Errorf("read all: %w", err)
	}

	footerReader := bytes.NewReader(footerBytes)
	if err := parseHeader(footerReader, &f.header); err != nil {
		return fmt.Errorf("parse header: %w", err)
	}

	if err := binary.Read(footerReader, binary.BigEndian, &f.footerEnd); err != nil {
		return fmt.Errorf("parse remainder: %w", err)
	}

	if crc32.ChecksumIEEE(footerBytes[:len(footerBytes)-binary.Size(f.CRC32)]) != f.CRC32 {
		return errors.New("checksum mismatch")
	}

	return nil
}

// getVarInt parses a variable int and increases the index.
func (t *Table) getVarInt(src []byte, start uint, blockEnd uint) (uint, uint, error) {
	var val uint

	val = uint(src[start]) & 0x7f

	for (uint(src[start]) & 0x80) > 0 {
		start++
		if start > blockEnd {
			return 0, 0, fmt.Errorf("exceeded block length")
		}

		val = ((val + 1) << 7) | (uint(src[start]) & 0x7f)
	}

	return start + 1, val, nil
}

// parseRefBlock parses a block and if it is a ref block, provides
// all the reference updates.
func (t *Table) parseRefBlock(src []byte, headerOffset, blockStart, blockEnd uint) ([]git.Reference, error) {
	currentBS := t.extractBlockLen(src, blockStart+headerOffset)

	fullBlockSize := t.blockSize
	if fullBlockSize == 0 {
		fullBlockSize = currentBS
	} else if currentBS < fullBlockSize && currentBS < (blockEnd-blockStart) && src[blockStart+currentBS] != 0 {
		fullBlockSize = currentBS
	}

	b := &block{
		BlockStart:    blockStart + headerOffset,
		FullBlockSize: fullBlockSize,
	}

	if err := binary.Read(bytes.NewBuffer(src[blockStart+currentBS-2:]), binary.BigEndian, &b.RestartCount); err != nil {
		return nil, fmt.Errorf("reading restart count: %w", err)
	}

	b.RestartStart = blockStart + currentBS - 2 - 3*uint(b.RestartCount)

	return t.getRefsFromBlock(src, b)
}

// GetReferences returns all references from the table.
func (t *Table) GetReferences() ([]git.Reference, error) {
	headerOffset := uint(t.footer.Version.HeaderSize())
	offset := uint(0)
	var allRefs []git.Reference

	if _, err := t.src.Seek(0, io.SeekStart); err != nil {
		return nil, fmt.Errorf("seek start: %w", err)
	}

	src, err := io.ReadAll(t.src)
	if err != nil {
		return nil, fmt.Errorf("read all: %w", err)
	}

	for offset < t.footerOffset {
		blockStart, blockEnd := t.getBlockRange(offset, t.blockSize)
		if blockStart == 0 && blockEnd == 0 {
			break
		}

		// If we run out of ref blocks, we can stop the iteration.
		if src[blockStart+headerOffset] != 'r' {
			return allRefs, nil
		}

		references, err := t.parseRefBlock(src, headerOffset, blockStart, blockEnd)
		if err != nil {
			return nil, fmt.Errorf("parsing block: %w", err)
		}

		if len(references) == 0 {
			break
		}

		allRefs = append(allRefs, references...)

		offset = blockEnd
	}

	return allRefs, nil
}

func handleCrash(logger log.Logger, grpcMethodName string, handler PanicHandler) {
	if r := recover(); r != nil {
		logger.WithFields(log.Fields{
			"error":     r,
			"method":    grpcMethodName,
			"backtrace": string(debug.Stack()),
		}).Error("grpc panic")

		handler(grpcMethodName, r)

		for _, fn := range additionalHandlers {
			fn(grpcMethodName, r)
		}
	}
}
