### Title
Missing URL-scheme sanitization in `go/doc/comment` HTML link rendering allows `javascript:` URI injection - ([File: src/go/doc/comment/html.go])

### Summary
`go/doc/comment` parses Go documentation comments (which may contain author-controlled Markdown-like `[text](url)` links) into a `Link` node and renders it to HTML in `(*htmlPrinter).text`. The renderer only HTML-entity-escapes the URL string via `escape()`; unlike `html/template`'s `urlFilter`/`isSafeURL`, it never validates the URL scheme, so a `javascript:` (or other dangerous-scheme) URL is emitted verbatim into the `href` attribute of the generated `<a>` tag.

### Finding Description
Attacker input: a Go source file's doc comment containing a Markdown-style link such as `[Click](javascript:alert(document.cookie))`. This is parsed by `go/doc/comment` into a `*Link{URL: "javascript:alert(document.cookie)", Text: [...]}` node (`src/go/doc/comment/parse.go`, `type Link struct`). When rendering to HTML, `(*Printer).HTML` calls `(*htmlPrinter).block` → `(*htmlPrinter).text`, which for a `*Link` does:
```go
out.WriteString(`<a href="`)
p.escape(out, t.URL)
out.WriteString(`">`)
``` [1](#0-0) 

`escape()` only replaces `< & " ' >` with HTML entities [2](#0-1)  — it does **not** check or filter the URL scheme. This is the exact analog of the reported bug class: content is parsed into a hyperlink (the "marked.parse" step) and then only syntax-escaped rather than scheme-sanitized (the "DOMPurify" step), so `javascript:` URIs survive into the rendered `href`.

Contrast with the sibling package `html/template`, which explicitly implements `isSafeURL`/`urlFilter` to strip any URL whose scheme is not `http`, `https`, or `mailto` [3](#0-2) . `go/doc/comment`'s own HTML printer has no equivalent check, so `<a href="javascript:...">` reaches the sink directly.

This HTML output is consumed by tools that render package documentation to end users in browsers — `go doc -html`, `godoc`, and (most importantly) `pkg.go.dev`, which renders `Doc.HTML` output for arbitrary published modules to any visitor viewing that package's documentation page.

### Impact Explanation
An attacker who publishes a Go module (an ordinary, unprivileged action — no special credentials or trust required) can embed a `javascript:` link in an exported identifier's doc comment. Any user (including maintainers, downstream consumers, or documentation-site visitors) who views the rendered documentation and clicks the link will execute attacker-controlled JavaScript in the viewing origin — a Stored XSS via a public/normal-workflow entry point. This matches the CWE-79 / GHSA-cqp4-qqvg-3787 primitive precisely: parse-then-insufficiently-sanitize ordering for markdown-generated links. Given `go/doc/comment` is standard library code consumed by widely used tooling (pkg.go.dev, godoc), if exploitable in a currently deployed renderer this would be a PUBLIC-track security issue for the Go project (not urgent RCE, but genuine stored XSS/session-token-theft-class impact depending on the consuming site's CSP/session model).

### Likelihood Explanation
Victim workflow: any developer or user browsing package documentation (e.g., via `pkg.go.dev`, `go doc -html`, or `godoc`) for a package that contains a malicious doc comment. Attacker capability: merely publishing a Go module with such a comment — no compromise of infrastructure, no privileged account, matching the "unprivileged, ordinary published module consumed by normal victim workflow" threat model required.

### Recommendation
Add scheme validation to `(*htmlPrinter).text`'s `*Link` and `*DocLink` cases (or to `escape`/a new helper) mirroring `html/template`'s `isSafeURL`, allowing only `http`, `https`, `mailto` (and relative URLs), and rejecting/defanging all other schemes (e.g., replacing with `#` or omitting the `href`) before writing `t.URL`/`url` into the `href` attribute.

### Proof of Concept
```go
package comment_test

import (
	"go/doc/comment"
	"strings"
	"testing"
)

func TestLinkJavascriptSchemeNotFiltered(t *testing.T) {
	var p comment.Parser
	doc := p.Parse("[Click](javascript:alert(document.cookie))\n")

	var pr comment.Printer
	out := string(pr.HTML(doc))

	// EXPECTED (secure behavior): the javascript: scheme should be stripped/filtered,
	// e.g. href="#ZgotmplZ" or scheme removed, similar to html/template's urlFilter.
	if strings.Contains(out, `href="javascript:`) {
		t.Fatalf("unsafe javascript: URL scheme was not sanitized, got: %s", out)
	}
}
```
Running this test against the current `go/doc/comment` implementation is expected to **fail** (i.e., `out` contains `href="javascript:alert(document.cookie)"`), demonstrating that no scheme filtering occurs, in contrast to `html/template`'s `isSafeURL` behavior.

func (p *htmlPrinter) escape(out *bytes.Buffer, s string) {
	start := 0
	for i := 0; i < len(s); i++ {
		switch s[i] {
		case '<':
			out.WriteString(s[start:i])
			out.WriteString("&lt;")
			start = i + 1
		case '&':
			out.WriteString(s[start:i])
			out.WriteString("&amp;")
			start = i + 1
		case '"':
			out.WriteString(s[start:i])
			out.WriteString("&quot;")
			start = i + 1
		case '\'':
			out.WriteString(s[start:i])
			out.WriteString("&apos;")
			start = i + 1
		case '>':
			out.WriteString(s[start:i])
			out.WriteString("&gt;")
			start = i + 1
		}
	}
	out.WriteString(s[start:])
}

func urlFilter(args ...any) string {
	s, t := stringify(args...)
	if t == contentTypeURL {
		return s
	}
	if !isSafeURL(s) {
		return "#" + filterFailsafe
	}
	return s
}

// isSafeURL is true if s is a relative URL or if URL has a protocol in
// (http, https, mailto).
func isSafeURL(s string) bool {
	if protocol, _, ok := strings.Cut(s, ":"); ok && !strings.Contains(protocol, "/") {
		if !strings.EqualFold(protocol, "http") && !strings.EqualFold(protocol, "https") && !strings.EqualFold(protocol, "mailto") {
			return false
		}
	}
	return true
}
