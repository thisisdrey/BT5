### Title
Unstaked stream-rate cap (`MAX_UNSTAKED_TPS`) is enforced per-connection, not globally, letting a many-IP botnet multiply aggregate unstaked stream throughput - (File: streamer/src/nonblocking/stream_throttle.rs)

### Summary
`StakedStreamLoadEMA::available_load_capacity_in_throttling_duration` returns the same fixed `max_unstaked_load_in_throttling_window` (derived from the constant `MAX_UNSTAKED_TPS = 200`) for every unstaked connection, and `throttle_stream` only tracks/limits streams per individual `ConnectionStreamCounter` (i.e., per connection). Because the budget is not divided across concurrently open unstaked connections, an attacker who opens many separate unstaked QUIC connections (from a botnet of IPs, each individually staying under `DEFAULT_MAX_CONNECTIONS_PER_IPADDR_PER_MINUTE`/per-connection limits) can multiply the intended ~200 TPS unstaked budget by the number of concurrently admitted unstaked connections.

### Finding Description
`MAX_UNSTAKED_TPS: u64 = 200` is documented as the aggregate rate allowed for unstaked traffic, and `EXPECTED_UNSTAKED_STREAMS_RATIO` is used to carve out a fixed 20% slice of `max_streams_per_ms` from the staked budget on the assumption that unstaked traffic is bounded to this reserved slice [1](#0-0) . However, the actual per-request enforcement point, `available_load_capacity_in_throttling_duration`, hands back the *entire* `max_unstaked_load_in_throttling_window` value to every unstaked connection independently, with no division by the number of currently open unstaked connections: [2](#0-1) 

`throttle_stream` and `ConnectionStreamCounter` operate purely on a per-connection basis — `stream_count` resets and accrues independently for each connection's own `ConnectionStreamCounter`, and the sleep-based backoff only throttles that one connection once its own local counter crosses `max_streams_per_throttling_interval`: [3](#0-2) 

There is no shared, global atomic counter across all unstaked connections that enforces the aggregate 200 TPS design intent; the constant is applied as a per-connection ceiling. As a result, admitting N concurrent unstaked connections lets the aggregate unstaked stream/packet rate scale to roughly `N × MAX_UNSTAKED_TPS`, bounded only by whatever `max_unstaked_connections` admission limit and per-IP connection caps are configured — not by the 20%-of-budget design assumption baked into `StakedStreamLoadEMA::new`.

### Impact Explanation
This causes packetization, sigverify, dedup, and batching CPU work driven by unstaked traffic to scale with attacker-controlled connection count rather than with the fee-weighted/stake-weighted budget the throttle was designed to enforce, matching the "grossly underpriced pre-fee work" / QoS-evasion bounty category referenced in the prompt. Since unstaked transactions pay the same base fee regardless of volume admitted, a botnet that fans out across many low-stake/no-stake IPs can force the leader to spend far more CPU on sigverify/dedup/batching than the fees collected would justify, degrading the leader below its intended cost model.

### Likelihood Explanation
Exploitability requires only unprivileged network access: opening many separate QUIC connections from many IPs to the TPU port, each individually complying with existing per-IP and per-connection stream limits. No stake, keys, or validator control is needed. The only limiting factor is the fixed `max_unstaked_connections` admission cap in the connection table, but as long as that cap is materially larger than 1 (which it must be to serve any legitimate unstaked traffic), the aggregate unstaked throughput scales linearly with admitted connection count rather than staying pinned to the single fixed `MAX_UNSTAKED_TPS` budget the code's naming and the `EXPECTED_UNSTAKED_STREAMS_RATIO` calculation assume it represents.

Note: I was not able to fully trace the exact call site(s) of `throttle_stream`/`available_load_capacity_in_throttling_duration` inside `nonblocking/quic.rs` (to confirm whether this is the live production QoS path versus the newer `simple_qos.rs`/`swqos.rs` abstractions), nor retrieve the exact configured value of `DEFAULT_MAX_UNSTAKED_CONNECTIONS` in this checkout, due to tool-call limits. This affects precise quantification of the achievable multiplier but not the core per-connection-vs-global enforcement gap identified above.

### Recommendation
Replace the per-connection unstaked cap with a shared, globally-tracked token bucket/counter across all unstaked connections (similar in spirit to the staked EMA load tracking), so that `available_load_capacity_in_throttling_duration` for `ConnectionPeerType::Unstaked` divides the fixed `MAX_UNSTAKED_TPS` budget among currently active unstaked connections, or enforces it via a single shared atomic counter rather than one counter per connection.

### Proof of Concept
Integration test plan (extending `streamer/src/nonblocking/stream_throttle.rs` test module):
1. Construct `StakedStreamLoadEMA` with `DEFAULT_MAX_UNSTAKED_CONNECTIONS` and `DEFAULT_MAX_STREAMS_PER_MS`.
2. Spawn `N` separate `ConnectionStreamCounter` instances representing `N` concurrent unstaked connections (N < `max_unstaked_connections`).
3. For each counter, call `available_load_capacity_in_throttling_duration(ConnectionPeerType::Unstaked, total_stake)` and drive `throttle_stream` to consume up to that returned capacity within one `STREAM_THROTTLING_INTERVAL`.
4. Assert that `sum_over_all_counters(streams_admitted_per_interval)` exceeds `max_unstaked_load_in_throttling_window` (the single-connection budget derived from `MAX_UNSTAKED_TPS`) by a factor proportional to `N`, demonstrating the aggregate unstaked throughput is not capped at the intended global 200 TPS once more than one unstaked connection is active.

    pub(crate) fn available_load_capacity_in_throttling_duration(
        &self,
        peer_type: ConnectionPeerType,
        total_stake: u64,
    ) -> u64 {
        match peer_type {
            ConnectionPeerType::Unstaked => self.max_unstaked_load_in_throttling_window,
            ConnectionPeerType::Staked(stake) => {
                if self.staked_throttling_enabled.load(Ordering::Relaxed) {
                    // 1 is added to `max_unstaked_load_in_throttling_window` to guarantee that staked
                    // clients get at least 1 more number of streams than unstaked connections.
                    self.max_staked_load_in_throttling_window
                        .saturating_mul(stake)
                        .checked_div(total_stake)
                        .unwrap_or(self.max_unstaked_load_in_throttling_window + 1)
                        .max(self.max_unstaked_load_in_throttling_window + 1)
                } else {
                    self.max_staked_load_in_throttling_window
                }
            }
        }
    }

pub(crate) async fn throttle_stream(
    stats: &StreamerStats,
    peer_type: ConnectionPeerType,
    remote_addr: std::net::SocketAddr,
    stream_counter: &Arc<ConnectionStreamCounter>,
    max_streams_per_throttling_interval: u64,
) {
    let throttle_interval_start = stream_counter.reset_throttling_params_if_needed();
    let streams_read_in_throttle_interval = stream_counter.stream_count.load(Ordering::Relaxed);
    if streams_read_in_throttle_interval >= max_streams_per_throttling_interval {
        // The peer is sending faster than we're willing to read. Sleep for what's
        // left of this read interval so the peer backs off.
        let throttle_duration =
            STREAM_THROTTLING_INTERVAL.saturating_sub(throttle_interval_start.elapsed());

        if !throttle_duration.is_zero() {
            debug!(
                "Throttling stream from {remote_addr:?}, peer type: {peer_type:?}, \
                 max_streams_per_interval: {max_streams_per_throttling_interval}, \
                 read_interval_streams: {streams_read_in_throttle_interval} throttle_duration: \
                 {throttle_duration:?}"
            );
            stats.throttled_streams.fetch_add(1, Ordering::Relaxed);
            match peer_type {
                ConnectionPeerType::Unstaked => {
                    stats
                        .throttled_unstaked_streams
                        .fetch_add(1, Ordering::Relaxed);
                }
                ConnectionPeerType::Staked(_) => {
                    stats
                        .throttled_staked_streams
                        .fetch_add(1, Ordering::Relaxed);
                }
            }
            sleep(throttle_duration).await;
        }
    }
}
