### Title
Public pull-oracle price updates can be sandwiched via `Pool.swap` for risk-free profit at the protocol's expense - (File: contracts/Pool.sol)

### Summary
Metronome prices all synthetic-to-synthetic conversions in `Pool.swap` directly through `PoolRegistry.masterOracle` (`IMasterOracle.quote`), burning the input synthetic and minting the output synthetic at oracle value minus a swap fee. The deployed configuration uses pull oracles (Pyth `updatePriceFeeds`, RedStone `pullPriceProvider.updatePrice`) whose updates are ordinary, permissionless on-chain transactions visible in the mempool — the E2E tests themselves bundle `pyth.updatePriceFeeds(...)` together with protocol calls through `Operator.execute`. An unprivileged searcher can therefore observe a pending price update, buy the appreciating synthetic at the stale price, let the update land, and sell back at the new price, extracting value whenever the price delta exceeds twice the swap fee.

### Finding Description
`Pool.swap` (and `DebtToken.issue`/`repay` paths that price debt in USD via `masterOracle`) reads prices at call time with no staleness protection beyond the oracle's own freshness window — a still-fresh price remains valid right up to the next update. The update transaction (`Pyth.updatePriceFeeds` / `PullPriceProvider.updatePrice`) is callable by any EOA and reveals the signed new price in its calldata before execution. Attack flow:

1. Searcher sees a pending `updatePriceFeeds`/`updatePrice` tx raising the price of synthetic A relative to synthetic B.
2. Frontrun: `Pool.swap(B → A, amountIn)` at the old price (flash-borrow B or mint via `DebtToken.issue` against deposited collateral).
3. Let the oracle update tx execute (or include it in the bundle — anyone may push it; `Operator.execute` explicitly supports batching `updatePrice` + pool calls, as demonstrated in `test/Operator.test.ts` and `test/E2E.mainnet.test.ts`).
4. Backrun: `Pool.swap(A → B)` at the new price.

The round trip returns `amountIn * (pNew/pOld) * (1-fee)^2`; any update where `pNew/pOld > 1/(1-fee)^2` yields profit. Because synthetics are minted rather than drawn from inventory, the created surplus is a claim on pooled collateral, so attacker profit translates into protocol insolvency / dilution of honest synthetic holders. `Pauseable`, `isSwapActive`, `SynthContext`, and the transient reentrancy guard do not prevent this — all calls are normal public entry points, and the deployed mainnet/hemi setups keep pull oracles that revert with `price-too-behind`/`price-expired` only when *stale*, not when a fresh update is imminent.

### Impact Explanation
Direct extraction of protocol value: the attacker mints synthetic claims worth more than what they paid, redeemable against borrower collateral via swaps and liquidations, producing bad debt for the pool. Scales with capital (flash-loanable) and with update infrequency — exactly the class described in the report.

### Likelihood Explanation
Requires an oracle update whose delta exceeds ~2× swap fee in a single push. For volatile crypto feeds this occurs on large moves; for near-peg feeds (msUSD vs stablecoins) it rarely does. Execution is trivially reachable by any mempool searcher since updates are permissionless and bundleable via `Operator.execute`. Medium likelihood, bounded by fee parameters.

### Recommendation
Enforce a per-block price-consistent nonce or commit the update atomically inside the same transaction that consumes the price (the `Operator.execute` pattern), or add a deviation bound/`cooldown` between oracle updates and swap/issue calls. Prefer push-style feeds with tight heartbeats, or require swaps to use the minimum of the previous and current price on updates that move the price upward (and vice versa) to remove the sandwich edge.

### Proof of Concept
Reproducible on a mainnet fork (mirroring `test/E2E.mainnet.test.ts` "when pull oracle prices are outdated"):

```ts
// 1. Fetch Pyth update that moves msETH up vs msUSD
const priceUpdate = await pythAPI.getPriceFeedsUpdateData([ETH_FEED]);
const fee = await pyth.getUpdateFee(priceUpdate);

// 2. Attacker tx 1 (frontrun): buy msETH with msUSD at stale price
await pool.swap(msUSD.address, msETH.address, amountIn); // priced via masterOracle.quote at old price

// 3. Oracle update lands (permissionless, attacker can include it in their own bundle)
await pyth.updatePriceFeeds(priceUpdate, { value: fee });

// 4. Attacker tx 2 (backrun): sell msETH back at new price
await pool.swap(msETH.address, msUSD.address, amountOut);
// profit = amountOutUsd * (1-fee)^2 - amountInUsd > 0 whenever price delta > ~2*swapFee
```

Invariant broken: solvency — synthetic supply/value created exceeds value deposited, transferable against pooled collateral.
