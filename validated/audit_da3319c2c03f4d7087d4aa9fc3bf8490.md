### Title
Reward funds become permanently locked when a witness's total vote count drops to zero for a cycle in which it still earned a reward - ([File: chainbase/src/main/java/org/tron/core/store/DelegationStore.java])

### Summary
`DelegationStore.accumulateWitnessVi` (and its duplicate in `RewardViCalService.accumulateWitnessVi`) skips accumulating the delta-VI (reward index) for a cycle whenever the witness's recorded vote count for that cycle is `0`, even if a non-zero reward was already credited to that witness for the same cycle. Because voter reward withdrawal is computed exclusively from the VI delta, any reward accrued in a "zero-vote" cycle is silently dropped and can never be claimed by anyone, permanently freezing those funds inside the contract's internal reward accounting. This mirrors the reported `updateGlobalExchangeRate` bug where `totalGlobalShares == 0` causes reward to be lost rather than redistributed or carried forward.

### Finding Description
`payReward` in `MortgageService` credits a witness's per-cycle reward pool independent of the witness's current vote count: [1](#0-0) 

At maintenance/cycle rollover, `MaintenanceManager.doMaintenance()` calls `delegationStore.accumulateWitnessVi(curCycle, witness.createDbKey(), witness.getVoteCount())` for every witness using the reward and vote data recorded for that cycle: [2](#0-1) 

The vote count used for the *next* cycle is snapshotted from the witness's current `getVoteCount()` only at the end of the current maintenance cycle: [3](#0-2) 

In `DelegationStore.accumulateWitnessVi`, when the reward for a cycle is non-zero but the recorded `voteCount` for that same cycle is zero, the method takes the "just forward pre vi" branch — it does **not** fold the reward into the VI, and the reward is never reflected in any voter's redeemable balance: [4](#0-3) 

The identical logic (and identical bug) exists in `RewardViCalService.accumulateWitnessVi`, used for cycles processed under the legacy/backfill reward algorithm path: [5](#0-4) 

Voter reward computation (`MortgageService.computeReward` for the new algorithm) strictly relies on `endVi - beginVi` (the VI delta) multiplied by the user's vote count; it has no fallback to redistribute reward that was recorded via `addReward` but never folded into VI: [6](#0-5) 

A witness's recorded vote count for a cycle can legitimately fall to zero even though it still produced blocks and earned reward during that cycle — e.g., all voters withdrawing/reallocating their votes away from that witness between maintenance windows while the witness remains in the active/standby set for the remainder of the cycle (vote-count changes take effect at the *next* maintenance boundary, while block/standby rewards accrue continuously during the cycle). When this occurs, `delegationStore.addReward(cycle, witnessAddress, value)` (called on every block produced by that witness, or via `payStandbyWitness`) keeps growing the stored reward for that cycle, but `accumulateWitnessVi` for that cycle sees `voteCount == 0` and discards the accumulation, permanently orphaning that reward — no voter's VI ever accounts for it, and it can never be withdrawn via `withdrawReward`/`queryReward`.

### Impact Explanation
Funds credited via `payReward` (block rewards, transaction fee rewards, standby witness pay) for a cycle in which the witness's snapshotted vote count is zero become permanently unclaimable by any account, since the accounting mechanism (VI delta) that governs all voter withdrawals silently discards them. This is a permanent freezing/loss-of-funds condition reachable through normal, unprivileged blockchain operation (voting/unvoting via `VoteWitnessContract`, which any account can broadcast) combined with ordinary block production reward distribution — no malicious or privileged actor is required.

### Likelihood Explanation
This requires only that a witness produce blocks (or be in the standby-pay list) during a cycle while its recorded vote total for that cycle is zero — achievable by any voter(s) fully unvoting a witness near a maintenance boundary while the witness is still active/standby for the remainder of the cycle. This is reachable purely through standard `VoteWitnessContract` transactions from unprivileged accounts, so likelihood of occurrence in production over time is realistic, though it depends on specific vote-timing conditions rather than being trivially triggerable in a single transaction.

### Recommendation
When `accumulateWitnessVi`/`accumulateWitnessVi` in `RewardViCalService` encounters `reward > 0` but `voteCount == 0` for a cycle, do not silently drop the reward. Instead, either: (1) carry the un-distributable reward forward to the next cycle's reward pool for that witness (added to `getReward(cycle+1, address)` before computing that cycle's VI), or (2) redirect it to the witness's own claimable allowance, or (3) prevent a witness's per-cycle reward from being recorded when the witness has zero snapshotted votes for that cycle. Any of these preserve conservation of value instead of permanently deleting it from the accounting.

### Proof of Concept
1. Witness `W` is active/standby and has non-zero votes at the start of cycle `N`; `W` produces blocks during cycle `N`, causing repeated `delegationStore.addReward(N, W, value)` calls via `MortgageService.payReward`.
2. Before the maintenance boundary that finalizes cycle `N`'s vote snapshot, all voters broadcast `VoteWitnessContract` transactions withdrawing every vote from `W` (fully unvoting), so that when `MaintenanceManager.doMaintenance()` runs `delegationStore.setWitnessVote(nextCycle, W, witness.getVoteCount())`, the recorded vote count used at cycle `N` is `0` (or the relevant vote snapshot for cycle N ends up 0 due to the timing of `getWitnessVote`).
3. At the maintenance rollover computing cycle `N`'s VI, `accumulateWitnessVi(N, W, 0)` is invoked; since `voteCount == 0`, the branch that folds `reward` into VI is skipped, even though `getReward(N, W) > 0`.
4. No voter's `beginVi`/`endVi` delta for `W` across cycle `N` ever reflects this reward (`MortgageService.computeReward` uses only VI deltas), so the reward recorded in `delegationStore` for `(N, W)` is permanently unreachable by `withdrawReward` or `queryReward` for any account, freezing those funds indefinitely.

  private long computeReward(long beginCycle, long endCycle, AccountCapsule accountCapsule) {
    if (beginCycle >= endCycle) {
      return 0;
    }

    long reward = 0;
    long newAlgorithmCycle = dynamicPropertiesStore.getNewRewardAlgorithmEffectiveCycle();
    List<Pair<byte[], Long>> srAddresses = accountCapsule.getVotesList().stream()
        .map(vote -> new Pair<>(vote.getVoteAddress().toByteArray(), vote.getVoteCount()))
        .collect(Collectors.toList());
    if (beginCycle < newAlgorithmCycle) {
      long oldEndCycle = min(endCycle, newAlgorithmCycle,
          dynamicPropertiesStore.disableJavaLangMath());
      reward = getOldReward(beginCycle, oldEndCycle, srAddresses);
      beginCycle = oldEndCycle;
    }
    if (beginCycle < endCycle) {
      for (Pair<byte[], Long>  vote : srAddresses) {
        byte[] srAddress = vote.getKey();
        BigInteger beginVi = delegationStore.getWitnessVi(beginCycle - 1, srAddress);
        BigInteger endVi = delegationStore.getWitnessVi(endCycle - 1, srAddress);
        BigInteger deltaVi = endVi.subtract(beginVi);
        if (deltaVi.signum() <= 0) {
          continue;
        }
        long userVote = vote.getValue();
        reward += deltaVi.multiply(BigInteger.valueOf(userVote))
            .divide(DelegationStore.DECIMAL_OF_VI_REWARD).longValue();
      }
    }
    return reward;
  }

  public void accumulateWitnessVi(long cycle, byte[] address, long voteCount) {
    BigInteger preVi = getWitnessVi(cycle - 1, address);
    long reward = getReward(cycle, address);
    if (reward == 0 || voteCount == 0) { // Just forward pre vi
      if (!BigInteger.ZERO.equals(preVi)) { // Zero vi will not be record
        setWitnessVi(cycle, address, preVi);
      }
    } else { // Accumulate delta vi
      BigInteger deltaVi = BigInteger.valueOf(reward)
          .multiply(DECIMAL_OF_VI_REWARD)
          .divide(BigInteger.valueOf(voteCount));
      setWitnessVi(cycle, address, preVi.add(deltaVi));
    }
  }
