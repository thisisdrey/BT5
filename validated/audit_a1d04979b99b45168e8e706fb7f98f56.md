### Title
Unchecked underflow of `totalSupply_` in `DebtToken._burn` when interest is unaccrued — permanent freeze of debt market (File: contracts/DebtToken.sol)

### Summary
`DebtToken._burn` performs `totalSupply_ -= amount_` inside an `unchecked` block. The guard only checks `balanceOf(account_) >= amount_`, but `balanceOf` includes virtually-accrued interest while `totalSupply_` is only updated when `accrueInterest()` runs. The external `burn(address,uint256)` entry point (callable by `Pool` during liquidation) does **not** call `accrueInterest()` first, so a burn amount that includes pending interest can exceed the stale `totalSupply_`, silently wrapping it to ~2^256 and permanently freezing the entire debt market.

### Finding Description
The bug class is integer wraparound on a stale counter, analogous to the L2CAP integer wraparound (untrusted length/index arithmetic wrapping a size field).

Relevant code:

```solidity
// contracts/DebtToken.sol
function burn(address from_, uint256 amount_) external override onlyPool {
    _burn(from_, amount_);   // <-- no accrueInterest()
}
```

```solidity
function _burn(address account_, uint256 amount_) private updateRewardsBeforeMintOrBurn(account_) {
    if (account_ == address(0)) revert BurnFromNullAddress();
    uint256 _accountBalance = balanceOf(account_);      // includes pending interest
    if (_accountBalance < amount_) revert BurnAmountExceedsBalance();
    unchecked {
        principalOf[account_] = _accountBalance - amount_;
        debtIndexOf[account_] = debtIndex;
        totalSupply_ -= amount_;                        // <-- wraps if amount_ > stale totalSupply_
    }
    ...
}
```

`balanceOf` computes `principal * currentIndex / accountIndex` where `currentIndex` reflects interest accrued since `lastTimestampAccrued`, whereas `totalSupply_` only grows inside `accrueInterest()`. When `burn` is invoked from `Pool.liquidate` without a preceding `accrueInterest()` on that `DebtToken`, `amount_` can legitimately satisfy `amount_ <= balanceOf(account_)` while `amount_ > totalSupply_`. Because the subtraction is `unchecked`, `totalSupply_` wraps to a value near `2^256` instead of reverting.

### Impact Explanation
Once `totalSupply_` wraps:

- Every subsequent `_mint` hits `if (totalSupply_ > maxTotalSupply) revert SurpassMaxDebtSupply()` — all new debt issuance is bricked.
- `accrueInterest()` executes `totalSupply_ += _interestAmountAccrued` in checked arithmetic, which overflows and reverts. Since `issue`, `repay`, `repayAll`, `mint`, `flashIssue` all call `accrueInterest()` first, the entire debt-token market becomes unusable.
- `totalSupply()` and any downstream view (`debtPositionOf` consumers, liquidations, withdraw/health checks that read debt supply) revert, permanently freezing collateral withdrawals, repayments, and liquidations for all users of that synthetic market — protocol-wide DoS / permanent freezing of funds, reachable by an unprivileged liquidator.

### Likelihood Explanation
Preconditions: pending interest exists (i.e., `block.timestamp > lastTimestampAccrued`, guaranteed for any liquidation occurring in a later block than the last debt operation), and the burned amount exceeds stale `totalSupply_`. The latter is reachable when the liquidated account represents (close to) all outstanding principal — e.g., a sole debtor or dominant debtor whose `balanceOf` (principal + accrued interest) exceeds total principal supply — and the liquidation repays an amount larger than `totalSupply_`. For a dominant debtor, `balanceOf ≈ principal + interest > totalSupply_ = Σ principals`, so a sufficiently large liquidation (or full liquidation allowed below `debtFloorInUsd`) triggers the wrap. Only an unprivileged liquidator calling `Pool.liquidate` is required; no privileged role. Residual uncertainty: whether `Pool.liquidate` (or an earlier call in the same transaction) already calls `accrueInterest()` on this debt token, which would refresh `totalSupply_` and prevent the underflow — this could not be fully confirmed from the indexed code and should be verified in the PoC.

### Recommendation
- Remove the `unchecked` block around `totalSupply_ -= amount_` (keep `unchecked` only where provably safe), or
- Call `accrueInterest()` at the top of `burn()` (matching `issue`/`repay`/`mint`), so `totalSupply_` is consistent with interest-inclusive `balanceOf`, and/or
- Compute `totalSupply_ -= amount_` against an explicitly accrued supply and assert `totalSupply_ >= amount_`.

### Proof of Concept
Foundry fork test sketch:

```solidity
// SPDX-License-Identifier: MIT
pragma solidity 0.8.24;

import "forge-std/Test.sol";
import {DebtToken} from "../contracts/DebtToken.sol";
import {IPool} from "../contracts/interfaces/IPool.sol";

contract DebtTokenSupplyWrap is Test {
    DebtToken debtToken;   // deployed msUSD debt token (fork)
    IPool pool;
    address alice = address(0xA11CE); // sole/large debtor
    address liquidator = address(0xB0B);

    function test_supplyUnderflowViaLiquidation() public {
        // 1. alice deposits collateral and issues max debt (she is ~100% of supply)
        // 2. vm.warp(block.timestamp + 365 days) to accrue interest
        //    now: balanceOf(alice) = P * (1+r) > totalSupply_ = P
        vm.warp(block.timestamp + 365 days);

        // 3. drop collateral price (fork: move pool / set oracle state) so alice is liquidatable,
        //    or use a synthetic whose price rose; liquidator repays ~full debt
        uint256 repayAmt = debtToken.balanceOf(alice); // includes interest
        uint256 supplyBefore = debtToken.totalSupply_();
        assertGt(repayAmt, supplyBefore);              // burn amount > stale supply

        // 4. liquidate path calls debtToken.burn(alice, repayAmt) WITHOUT accrueInterest
        vm.prank(address(pool));
        debtToken.burn(alice, repayAmt);

        // 5. totalSupply_ wrapped to ~2^256
        assertGt(debtToken.totalSupply_(), type(uint256).max / 2);

        // 6. everything is bricked
        vm.expectRevert(); // accrueInterest overflows / SurpassMaxDebtSupply
        debtToken.accrueInterest();
    }
}
```

Invariants broken: `totalSupply_ == Σ principal + accrued interest` (supply solvency), and liveness of the entire debt market (repay/issue/liquidate all permanently revert), causing permanent freezing of user collateral and debt positions.
