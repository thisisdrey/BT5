Based on my investigation, I found the analogous issue: certificate signing (`checkCAConstraints`) validates `NotBefore`/`NotAfter` using full-precision `time.Time` values, but the wire encoding truncates those same values to Unix-second granularity — and truncation is a floor operation, not a round-to-nearest. This is the "not exact inverses" pattern.

### Title
CA constraint checks validate full-precision timestamps while the signed wire format truncates to seconds, allowing sub-second constraint bypass - (File: cert/sign.go, cert/cert_v1.go, cert/cert_v2.go)

### Summary
`TBSCertificate.SignWith` validates `t.NotBefore`/`t.NotAfter` against the signer's constraints via `checkCAConstraints` using the caller-supplied, full-precision `time.Time` values [1](#0-0) . Once validated, the certificate is serialized for signing using only Unix-second precision (`.Unix()`), discarding sub-second precision, both for v1 (protobuf `int64` seconds) [2](#0-1)  and v2 (ASN.1 `AddASN1Int64WithTag(d.notBefore.Unix()...)`) [3](#0-2) . On the wire and at verification time, the certificate is reconstructed with `time.Unix(notBefore, 0)` / `time.Unix(notAfter, 0)` [4](#0-3) , which floors any sub-second component. The constraint check that gates `NotAfter`/`NotBefore` against the signer's own bounds (`checkCAConstraints`) is thus performed on values that are never exactly what ends up signed and later re-verified [5](#0-4) .

### Finding Description
The validation-vs-serialization mismatch is exactly the "allocate ≠ remove" rounding-direction bug pattern from the external report, applied to certificate temporal bounds instead of token reserves:
- `checkCAConstraints(signer, notBefore, notAfter, ...)` compares the leaf's requested `NotAfter` against `signer.NotAfter()` and requires `!notAfter.After(signer.NotAfter())` [5](#0-4) .
- The leaf's `NotAfter` passed to this check is the raw, full-precision `time.Time` supplied to `TBSCertificate.Sign`/`SignWith` [6](#0-5) .
- After signing, the cert's actual (wire-encoded, and re-parsed) `NotAfter` is `time.Unix(t.NotAfter.Unix(), 0)` — always truncated downward (floored) to the nearest whole second [3](#0-2) [4](#0-3) .
- Because truncation is a floor, the *effective, signed* `NotAfter` is always `<=` the value that was checked, and the *effective, signed* `NotBefore` is always `<=` the value that was checked. This means the constraint check and the actual enforced value are not exact inverses of one another: the check happens on one representation, and the value actually burned into the signature and later checked by `CAPool.verify`/`Expired` is a different (truncated) representation [7](#0-6) [8](#0-7) .

### Impact Explanation
For `NotAfter`, flooring can only shrink validity (move it earlier), so this direction is not exploitable for extending validity beyond the CA's bound. However, for `NotBefore`, the same floor operation applied by the code comments in the test helpers (`cert/helper_test.go`, `cert_test/cert.go`) explicitly acknowledge this is a real, non-test hazard ("a leaf signed with default times can never expire after its CA on a rounding race") — indicating the authors are aware the CA/leaf NotBefore/NotAfter comparison can be affected by sub-second truncation and mitigate it only in test helpers by pre-rounding `time.Now()` to the second before use, not in the production `Sign`/`SignWith` path [9](#0-8) . In production, an operator or automated cert-issuance pipeline that calls `TBSCertificate.Sign` with sub-second-precision `time.Time` values (e.g., `time.Now()` without rounding) has no such guard, so the constraint check performed at signing time is not the same value that ends up enforced at verification time (`Expired`, `checkCAConstraints` re-evaluated on the reconstructed certificate during future re-signs/renewals). This is a correctness/robustness bug rather than a directly attacker-triggerable authentication bypass, since exploitation of the discrepancy in the constrained direction (i.e., producing an actually-longer-lived cert than the CA allows) is not possible—flooring only shortens intervals.

### Likelihood Explanation
Low. The issue is real and demonstrable (analogous to the allocate/remove non-inverse rounding bug), but it can only make certificate validity windows *narrower* than requested, never *wider* than the CA's constraint. There is no reachable path here for an attacker without a CA-signed certificate to leverage this into an authentication bypass, certificate verification bypass, traffic forgery, or firewall bypass — it does not create a scenario where a certificate becomes valid outside the signer's permitted window.

### Recommendation
Round or truncate `NotBefore`/`NotAfter` to the same second-level precision used for wire serialization *before* running `checkCAConstraints`, so the value validated matches the value actually signed and later re-verified (mirroring the guard already applied ad hoc in test helpers). Long term, add a property/fuzz test (as recommended in the original report) asserting that a certificate's `NotBefore()`/`NotAfter()` after a full Sign→Marshal→Unmarshal round trip always equals the value that was checked against CA constraints at sign time.

### Proof of Concept
Not applicable as a remote exploit — the discrepancy only narrows validity windows, so no concrete remote authentication bypass, decryption, forgery, replay, or firewall-bypass PoC can be constructed from this rounding mismatch alone.

func (t *TBSCertificate) Sign(signer Certificate, curve Curve, key []byte) (Certificate, error) {
	switch t.Curve {
	case Curve_CURVE25519:
		pk := ed25519.PrivateKey(key)
		sp := func(certBytes []byte) ([]byte, error) {
			sig := ed25519.Sign(pk, certBytes)
			return sig, nil
		}
		return t.SignWith(signer, curve, sp)
	case Curve_P256:
		pk, err := ecdsa.ParseRawPrivateKey(elliptic.P256(), key)
		if err != nil {
			return nil, err
		}
		sp := func(certBytes []byte) ([]byte, error) {
			// We need to hash first for ECDSA
			// - https://pkg.go.dev/crypto/ecdsa#SignASN1
			hashed := sha256.Sum256(certBytes)
			return ecdsa.SignASN1(rand.Reader, pk, hashed[:])
		}
		return t.SignWith(signer, curve, sp)
	default:
		return nil, fmt.Errorf("invalid curve: %s", t.Curve)
	}
}

// checkCAConstraints is a very generic function allowing both Certificates and TBSCertificates to be tested.
func checkCAConstraints(signer Certificate, notBefore, notAfter time.Time, groups []string, networks, unsafeNetworks []netip.Prefix) error {
	// Make sure this cert isn't valid after the root
	if notAfter.After(signer.NotAfter()) {
		return fmt.Errorf("certificate expires after signing certificate")
	}

	// Make sure this cert wasn't valid before the root
	if notBefore.Before(signer.NotBefore()) {
		return fmt.Errorf("certificate is valid before the signing certificate")
	}
