### Title
Protocol fees bypassed on `defuse_nep245::TokenId` by splitting a large transfer into unit `TokenDiff` legs - ([File: contracts/defuse/core/src/intents/token_diff.rs])

### Summary
`TokenDiff::execute_intent` computes `fees_collected[token]` per-intent via `Self::token_fee(token_id, amount, protocol_fee).fee_ceil(amount)`, and `token_fee` returns `Pips::ZERO` for `TokenIdType::Nep245`/`Imt` whenever the leg's `amount <= 1`. Because fee assessment is done independently per intent (per `TokenDiff::execute_intent` call inside `Engine::execute_signed_intent`), an attacker can move an arbitrarily large NEP-245 balance while paying zero protocol fee by splitting the negative (`token_in`) side into N legs of `delta == -1` across N intents in one signed payload, whereas one intent with `delta == -N` on the same token would pay `protocol_fee.fee_ceil(N) > 0`.

### Finding Description
The intended binding is: `fees_collected[token_id] == protocol_fee.fee_ceil(total_amount_moved_of(token_id))` for the economic amount a signer moves out of their balance on `token_id` within a settlement. The code instead computes, independently for every intent:
```
let fee = Self::token_fee(token_id, amount, protocol_fee).fee_ceil(amount);
``` [1](#0-0) 
and `token_fee` zeroes the rate whenever the *per-intent* leg amount is `<= 1` for `Nep245`/`Imt`:
```
TokenIdType::Nep245 | TokenIdType::Imt if amount > 1 => {}
TokenIdType::Nep171 | TokenIdType::Nep245 | TokenIdType::Imt => return Pips::ZERO,
``` [2](#0-1) 

Because `Engine::execute_signed_intent` iterates over each `MultiPayload`'s intents and calls `intents.execute_intent(...)` once per signed payload without ever aggregating same-`TokenId` legs across different `TokenDiff` intents before computing fees, and `TransferMatcher`/`Deltas::finalize` only nets balances across the whole batch to settle transfers (never re-evaluates fee based on the aggregate), the exemption `amount <= 1` is trivially defeated by splitting one large leg into many unit legs. [3](#0-2) [4](#0-3) 

**Attacker payload**: One signed `DefusePayload` from account A containing N `TokenDiff` intents, each `diff = {token_X (Nep245): -1}` (`fee = token_fee(token_X, 1, protocol_fee).fee_ceil(1) == 0` for every leg since `amount <= 1`). A counterpart payload (e.g. attacker's second account B, or a cooperating solver) supplies the matching positive side, e.g. one `TokenDiff{diff: {token_X: N}}` — the fee-check `if *delta < 0` in `execute_intent` never taxes the positive/deposit side regardless of magnitude, so B's leg is fee-free by design (that is intended: fee is only on token_in). Submitted together via `execute_intents`/`simulate_intents` in one `MultiPayload` batch, `TransferMatcher::finalize` nets A's N withdrawals of 1 against B's single deposit of N, producing a legitimate `Transfer(A → B, token_X, N)` while `fees_collected` for `token_X` stays `0` for the whole batch. [5](#0-4) 

Existing guards do not stop this: `MultiPayload::verify`, `has_public_key`, `verify_intent_nonce`, and `commit_nonce` all check signature/authorization/replay validity, not fee correctness; `TransferMatcher::finalize` only asserts the balance-delta invariant (unmatched deltas must be zero), which is satisfied here since balances net out — it has no visibility into, nor any check on, `fees_collected`. There is no code path that aggregates identical `TokenId` deltas across multiple `TokenDiff` intents (even from the same signer, same payload) prior to fee computation.

### Impact Explanation
The fee_collector's `internal_add_balance` under `engine.state.fee_collector()` receives `0` tokens for a NEP-245 transfer of arbitrary size `N`, instead of `protocol_fee.fee_ceil(N)`, whenever the attacker structures the negative leg as N one-unit `TokenDiff` intents rather than a single `delta = -N` intent. [6](#0-5) 
This matches the Critical category "protocol fees bypassed" — value that should flow to the `fee_collector` never leaves the trading accounts. The attack is fully repeatable: any account trading any `Nep245`/`Imt` token pays this by simply restructuring their intents into unit legs (cost is only extra intents in the same or an additional signed payload, no extra NEAR fees beyond gas for more intents processed in the same transaction). It applies to every NEP-245/IMT token in the Verifier, so blast radius is protocol-wide fee revenue on multi-token swaps, not limited to one token or one account.

### Likelihood Explanation
Preconditions are minimal and fully within an unprivileged actor's control: the attacker needs (a) a `Nep245`/`Imt` token balance inside the Verifier to sell, (b) any counterparty willing to take the other side of the trade at the same price (can be the attacker's own second account, requiring no cooperation from anyone else), and (c) the ability to sign a `DefusePayload` with N `TokenDiff` intents (trivially constructible client-side, no special role required). It works exactly the same in `execute_intents` and `simulate_intents` (so the exploit can be pre-validated risk-free before broadcasting). This is straightforward and cheap — the only "cost" is issuing more intents than a single aggregated one, which is minor and repeatable indefinitely across accounts, tokens and batches.

### Recommendation
Compute the NEP-245/IMT fee exemption based on the aggregate `token_in` amount per `TokenId` across the whole intents batch (or at minimum per signer), not per individual `TokenDiff` intent leg. Concretely, sum all negative deltas for a given `TokenId` across every `TokenDiff` intent executed within `Engine::execute_signed_intents` before evaluating `token_fee`'s `amount <= 1` exemption, or remove the amount-based exemption entirely and replace it with an explicit flag on the `TokenId`/token metadata that distinguishes genuinely non-fungible sub-tokens (always `amount == 1` by definition) from fungible NEP-245 sub-tokens that can be split.

### Proof of Concept
```
cargo test (near-workspaces sandbox), new test in tests/src/tests/defuse/intents/token_diff.rs:

1. Deploy a NEP-245 (multi-token) contract, deposit N=1000 units of sub-token "ft1" into user A's Verifier balance, set protocol_fee = Pips::ONE_PERCENT.
2. Case "aggregated": sign one TokenDiff{diff: {mt_token: -1000}} from A, matched by TokenDiff{diff: {mt_token: 1000}} from B (with A/B having appropriate opposite tokens or a two-leg swap). Execute via execute_intents. Assert fee_collector's mt_balance_of(mt_token) == protocol_fee.fee_ceil(1000) > 0.
3. Case "split": sign ONE payload from A containing 1000 TokenDiff intents, each {diff: {mt_token: -1}}, plus one TokenDiff{diff: {mt_token: 1000}} from B. Execute the same batch via execute_intents.
4. Assert: A's mt_token balance decreased by 1000, B's increased by 1000 (transfer happened identically to case 2), but fee_collector's mt_balance_of(mt_token) == 0, proving fees_collected diverges from case 2's `protocol_fee.fee_ceil(1000)` for the same net economic transfer — breaking fees_collected[token] == Pips::fee_ceil(protocol_fee, total_amount_moved).
```

    fn execute_signed_intent(&mut self, signed: MultiPayload) -> Result<()> {
        // verify signed payload and get public key
        let public_key = signed.verify().ok_or(DefuseError::InvalidSignature)?;

        // calculate intent hash
        let hash = signed.hash();

        // extract NEP-413 payload
        let DefusePayload::<DefuseIntents> {
            signer_id,
            verifying_contract,
            deadline,
            nonce,
            message: intents,
        } = signed.extract_defuse_payload()?;

        // check recipient
        if verifying_contract != *self.state.verifying_contract() {
            return Err(DefuseError::WrongVerifyingContract);
        }

        self.inspector.on_deadline(deadline);

        // make sure message is still valid
        if deadline < Timestamp::now() {
            return Err(DefuseError::DeadlineExpired);
        }

        // make sure the account has this public key
        if !self.state.has_public_key(&signer_id, &public_key) {
            return Err(DefuseError::PublicKeyNotExist(signer_id, public_key));
        }

        // commit nonce
        self.verify_intent_nonce(nonce, deadline)?;
        self.state.commit_nonce(signer_id.clone(), nonce)?;

        intents.execute_intent(&signer_id, self, hash)?;
        self.inspector.on_intent_executed(&signer_id, hash, nonce);

        Ok(())
    }

    pub fn finalize(self) -> Result<Transfers, InvariantViolated> {
        let mut transfers = Transfers::default();
        let mut deltas = TokenDeltas::default();
        for (token_id, transfer_matcher) in self.0 {
            if let Err(unmatched) = transfer_matcher.finalize_into(&token_id, &mut transfers)
                && (unmatched == 0 || deltas.apply_delta(token_id, unmatched).is_none())
            {
                return Err(InvariantViolated::Overflow);
            }

        if !deltas.is_empty() {
            return Err(InvariantViolated::UnmatchedDeltas {
                unmatched_deltas: deltas,
            });
        }

    }

    pub fn finalize_into(self, token_id: &TokenId, transfers: &mut Transfers) -> Result<(), i128> {
        // sort deposits and withdrawals in descending order
        let [mut deposits, mut withdrawals] = [self.deposits, self.withdrawals].map(|amounts| {
            let mut amounts: Vec<_> = amounts.into_iter().collect();
            amounts.sort_unstable_by_key(|(_, amount)| Reverse(*amount));
            amounts.into_iter()
        });

        // take first sender and receiver
        let (mut deposit, mut withdraw) = (deposits.next(), withdrawals.next());

        // as long as there is both: sender and receiver
        while let Some(((sender, send), (receiver, receive))) =
            withdraw.as_mut().zip(deposit.as_mut())
        {
            // get min amount and transfer
            let transfer = (*send).min(*receive);
            transfers
                .transfer(sender.clone(), receiver.clone(), token_id.clone(), transfer)
                // no error can happen since we add only one transfer for each
                // combination of (sender, receiver, token_id)
                .unwrap_or_else(|| unreachable!());

            // subtract amount from sender and receiver
            *send = send.saturating_sub(transfer);
            *receive = receive.saturating_sub(transfer);

            if *send == 0 {
                // select next sender
                withdraw = withdrawals.next();
            }
            if *receive == 0 {
                // select next receiver
                deposit = deposits.next();
            }
        }

        // only sender(s) left
        if let Some((_, send)) = withdraw {
            return Err(withdrawals
                .try_fold(send, |total, (_, s)| total.checked_add(s))
                .and_then(|total| i128::try_from(total).ok())
                .and_then(i128::checked_neg)
                .unwrap_or_default());
        }
        // only receiver(s) left
        if let Some((_, receive)) = deposit {
            return Err(deposits
                .try_fold(receive, |total, (_, r)| total.checked_add(r))
                .and_then(|total| i128::try_from(total).ok())
                .unwrap_or_default());
        }

        Ok(())
    }
