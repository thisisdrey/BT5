### Title
Unauthenticated `RecvError` packets allow remote attackers to force-terminate tunnels and poison HandshakeManager state - (File: outside.go)

### Summary
The external report describes an unauthenticated, unprivileged actor (`popDebtFromQueue()`) that can mutate shared protocol state before a legitimate operation (`auctionSurplus()`) checks that state, causing the legitimate operation to fail/be denied — a front-running state-poisoning DoS. The reachable analog in this Nebula build is `handleRecvError`, which processes the `header.RecvError` message type before any cryptographic authentication of the sender and mutates the host's connection/handshake state (tears down the tunnel and deletes pending handshake bookkeeping) based only on a weak IP-match check.

### Finding Description
Inbound UDP packets are dispatched by type in `readOutsidePackets` before any decryption or certificate verification occurs: [1](#0-0) 

`header.RecvError` is handled immediately by `f.handleRecvError(via.UdpAddr, h)` with zero cryptographic authentication — the packet carries only a `RemoteIndex` (a 32-bit value that is visible in cleartext on every packet header sent by the target, so it can be learned by an on-path/eavesdropping attacker or simply guessed since it's attacker-observable) and no key or signature: [2](#0-1) 

Inside `handleRecvError`, the only gating check before mutating shared state is whether the packet's claimed sender address matches the currently known remote address for that hostinfo (`hr.IsValid() && hr != addr`). If it matches — or if the tunnel currently has no confirmed remote (`hr.IsValid()` is false, e.g., a freshly established or roaming tunnel) — the code proceeds to:

- `f.closeTunnel(hostinfo)` — tearing down the active tunnel state, and
- `f.handshakeManager.DeleteHostInfo(hostinfo)` — removing the corresponding entry from the `HandshakeManager`'s pending index maps (`hm.indexes`) via `unlockedDeleteHostInfo`: [3](#0-2) 

This is structurally analogous to `popDebtFromQueue()` in the GEB report: a caller with no special privilege or valid credential (no CA-signed certificate is validated anywhere in this code path) can invoke a function that mutates the shared queue/index state (`hm.indexes`, `hm.mainHostMap.Indexes`) that a legitimate protocol operation (`continueHandshake`'s `hm.queryIndex(h.RemoteIndex)` lookup, or the data-plane tunnel itself) depends on. Just as popping a debt block out from under `auctionSurplus()`'s precondition check forces that check to fail, sending a spoofed `RecvError` deletes the hostinfo/index entry out from under an in-progress handshake or a live tunnel, forcing subsequent legitimate packets (continuation handshake messages, or data-plane traffic) to be dropped as orphaned/unknown, exactly as seen in the "orphan" drop paths of `HandleIncoming`: [4](#0-3) 

### Impact Explanation
An attacker who can source (or spoof) a single UDP packet matching a target's current remote endpoint and RemoteIndex can remotely force-close an established tunnel and purge its pending-handshake bookkeeping, without ever presenting a valid certificate. This is remote state poisoning / denial of service: it can repeatedly disrupt tunnel establishment or force costly re-handshakes network-wide, particularly damaging for lighthouse or frequently-used tunnels. The project's own CHANGELOG documents this class of exposure as a recognized security concern (`send_recv_error`/`accept_recv_error` config knobs exist specifically to mitigate spoofing/probing risk), but the default (`recvErrorAlways`) accepts RecvError from any address: [5](#0-4) 

### Likelihood Explanation
Exploitability depends on: (1) knowledge of the target's `RemoteIndex` for the tunnel (observable from any packet exchanged on that tunnel, i.e., trivial for an on-path attacker, and only moderately hard for a pure off-path attacker), and (2) the ability to source a UDP packet whose apparent address matches `hostinfo.GetRemote()` (or exploiting the window where `GetRemote()` is not yet valid, e.g., during roaming/relay setup). Because UDP allows straightforward source-address spoofing on networks without egress filtering, and because the check is purely address-based rather than cryptographic, this is realistically reachable by a network-adjacent or spoofing-capable attacker with no CA-signed certificate.

### Recommendation
Do not let an unauthenticated `RecvError` packet alone trigger destructive state mutation (`closeTunnel` + `DeleteHostInfo`). At minimum:
- Require some proof of tunnel knowledge beyond the cleartext `RemoteIndex` and source-IP match (e.g., rate-limit and require a matching outstanding *sent* packet/challenge, or authenticate `RecvError` using a keyed check derived from the tunnel's established keys once a tunnel is up).
- Default `listen.accept_recv_error` to a safer mode (e.g., `never` or `private`) rather than `always`, or require corroborating evidence (like consecutive send failures) before acting on a `RecvError`.
- Ensure the fix also covers the case in `handleRecvError` where `hr.IsValid()` is false, which currently bypasses the address check entirely.

### Proof of Concept
1. Attacker observes (or otherwise learns) a live Nebula tunnel between host A and host B, capturing any packet to learn A's `RemoteIndex` value used by B (visible in the cleartext header) and B's current UDP endpoint for A.
2. Attacker crafts a `header.RecvError` packet with `RemoteIndex` set to the observed index and sends it to A's listening UDP port, spoofing the source address to match B's known endpoint (or timing the injection during a window where A has not yet confirmed B's remote, i.e., `hr.IsValid() == false`).
3. `readOutsidePackets` on A dispatches the packet type `header.RecvError` to `handleRecvError` with no decryption/certificate check.
4. The address check in `handleRecvError` passes (matches B's known endpoint, or is skipped because `hr` is not yet valid), so A calls `f.closeTunnel(hostinfo)` and `f.handshakeManager.DeleteHostInfo(hostinfo)`, destroying the tunnel state.
5. Legitimate subsequent packets from B are now treated as orphaned (no matching index), forcing a full re-handshake and network disruption — repeatable at will by the attacker.

func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}

func (hm *HandshakeManager) DeleteHostInfo(hostinfo *HostInfo) {
	hm.Lock()
	defer hm.Unlock()
	hm.unlockedDeleteHostInfo(hostinfo)
}

func (hm *HandshakeManager) unlockedDeleteHostInfo(hostinfo *HostInfo) {
	for _, addr := range hostinfo.vpnAddrs {
		if cur, ok := hm.vpnIps[addr]; ok && cur.hostinfo == hostinfo {
			delete(hm.vpnIps, addr)
		}
	}

	if len(hm.vpnIps) == 0 {
		hm.vpnIps = map[netip.Addr]*HandshakeHostInfo{}
	}

	delete(hm.indexes, hostinfo.localIndexId)
	if len(hm.indexes) == 0 {
		hm.indexes = map[uint32]*HandshakeHostInfo{}
	}

	if hm.l.Enabled(context.Background(), slog.LevelDebug) {
		hm.l.Debug("Pending hostmap hostInfo deleted",
			"hostMap", m{"mapTotalSize": len(hm.vpnIps),
				"vpnAddrs": hostinfo.vpnAddrs, "indexNumber": hostinfo.localIndexId, "remoteIndexNumber": hostinfo.remoteIndexId},
		)
	}
}

type recvErrorConfig uint8

const (
	recvErrorAlways recvErrorConfig = iota
	recvErrorNever
	recvErrorPrivate
)

func (s recvErrorConfig) ShouldRecvError(endpoint netip.AddrPort) bool {
	switch s {
	case recvErrorPrivate:
		return endpoint.Addr().IsPrivate()
	case recvErrorAlways:
		return true
	case recvErrorNever:
		return false
	default:
		panic(fmt.Errorf("invalid recvErrorConfig value: %d", s))
	}
}

func (s recvErrorConfig) String() string {
	switch s {
	case recvErrorAlways:
		return "always"
	case recvErrorNever:
		return "never"
	case recvErrorPrivate:
		return "private"
	default:
		return fmt.Sprintf("invalid(%d)", s)
	}
}
