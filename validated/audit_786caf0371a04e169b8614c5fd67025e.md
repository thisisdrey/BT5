### Title
DepositToken redeems collateral 1:1 from Treasury with no loss socialization — first withdrawers are paid in full, later withdrawers' funds are frozen/lost - (File: contracts/DepositToken.sol)

### Summary
`DepositToken` mints `msdTOKEN` 1:1 against collateral held in `Treasury` and burns it 1:1 on withdrawal via `Treasury.pull`. There is no exchange-rate or loss-socialization mechanism: each withdrawal transfers the full nominal token amount. If the Treasury's underlying collateral balance ever falls below `totalSupply` (e.g., the collateral is a yield-bearing/rebasing vault-share token that suffers a permanent loss at the token level, as in the reported SUSD-vault class), the deficit is borne entirely by whoever withdraws last — early withdrawers exit at par while late withdrawers' `pull` reverts on insufficient Treasury balance, permanently freezing their funds.

### Finding Description
- `DepositToken.deposit` measures the Treasury balance delta and mints shares 1:1 (minus fee): `amount_ = _underlying.balanceOf(_treasury) - _balanceBefore` then `_mint(onBehalfOf_, _deposited)` [1](#0-0) 
- `DepositToken._withdraw` burns shares and pulls the full nominal amount: `(_withdrawn, _fee) = quoteWithdrawOut(amount_); _burn(account_, _withdrawn); _pool.treasury().pull(to_, _withdrawn)` [2](#0-1) 
- `Treasury.pull` performs a plain `safeTransfer(to_, amount_)` of the underlying — it reverts if the Treasury's token balance is insufficient, so a shortfall is silently assigned to the last withdrawers [3](#0-2) 
- No pro-rata redemption (`shares * treasuryBalance / totalSupply`) exists anywhere in the withdraw path, and Metronome explicitly supports vault-share collateral (e.g., `VaUSDC`, `VaWSTETH`, `VaETH` deposit tokens; `VesperGateway.withdraw` redeems `vToken`s whose `withdraw` itself can return less underlying than requested after a Vesper pool loss) [4](#0-3) 

### Impact Explanation
Direct loss / permanent freezing of user funds with unfair distribution: identical to the reported bug class. Once the collateral token's backing drops below `DepositToken.totalSupply` (permanent loss in the external vault or a downward rebase of the collateral token), the first users to call `withdraw`/`VesperGateway.withdraw` receive 100% of their nominal collateral; when `treasuryBalance < amount_` the `safeTransfer` in `pull` reverts, so remaining `msdTOKEN` holders can never exit — a first-come-first-served bank-run dynamic instead of pro-rata loss sharing.

### Likelihood Explanation
Requires an underlying loss event rather than pure attacker action, matching the reported class. The precondition is realistic: Metronome whitelists external yield-vault shares as collateral, and those vaults can report losses. Any unprivileged user can then race to withdraw and receive full value, concentrating 100% of the loss on non-first movers. No modifier (`whenNotShutdown`, `nonReentrant`, `_revertIfLocked`) mitigates this — the failure is a raw ERC20 balance shortfall in `Treasury.pull`.

### Recommendation
Make `msdTOKEN` a pro-rata claim on the Treasury's collateral balance instead of a 1:1 wrapper: on withdrawal compute `underlyingOut = amount_ * treasuryBalance / totalSupply` (or track an explicit exchange rate updated on loss events), so losses are socialized across all holders. Alternatively, for vault-share collateral, resolve redemption via the external vault's share-to-asset conversion and distribute any withdrawal shortfall proportionally.

### Proof of Concept
Hardhat/Foundry fork sketch:
1. Deploy/fork `Pool` + `Treasury` + a `DepositToken` whose `underlying` is a mock vault-share token (or a rebasing ERC20) that can reduce the Treasury's balance (simulating a vault loss, e.g., `burn` a portion of Treasury holdings or a negative rebase).
2. Users A and B each deposit 100 tokens → each holds 100 msdTOKEN; Treasury holds 200.
3. Trigger the external loss: Treasury balance drops to 150 while `totalSupply` remains 200.
4. A calls `depositToken.withdraw(100e18, A)` → `Treasury.pull` transfers 100 (full amount, no loss).
5. B calls `depositToken.withdraw(100e18, B)` → `Treasury.pull` `safeTransfer` reverts (balance 50 < 100). B's 50-token residual claim is permanently frozen and B absorbs the entire 50-token loss.

This reproduces the exact invariant break: redemption is 1:1 in nominal terms while backing is impaired, so losses are not fairly redistributed.
