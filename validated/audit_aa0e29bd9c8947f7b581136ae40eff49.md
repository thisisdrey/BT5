### Title
Stake-based QUIC QoS classification is frozen at connection-open time, letting a peer keep elevated stream/connection privileges after their stake is withdrawn - (File: `streamer/src/nonblocking/swqos.rs`)

### Summary
The Mento report describes a class of bug where a derived privilege (veMENTO voting power) is computed once from an underlying entitlement (locked MENTO) and is never re-validated after that entitlement is removed via an admin stop/start cycle, letting the user keep the privilege after withdrawing their stake. The closest concrete, unprivileged-user-reachable analog in Agave's in-scope surfaces (QUIC/UDP streamer QoS) is `SwQos`/`SimpleQos`'s handling of `total_stake`/`peer_type`: these are computed exactly once when a QUIC connection is opened and are never refreshed for the lifetime of that connection, even though the underlying stake (the "entitlement") can change (e.g. go to zero) at any later point while the connection stays open.

### Finding Description
`SwQos::build_connection_context` looks up the connecting peer's stake via `get_connection_stake(connection, &self.staked_nodes)` and bakes the result into an immutable `SwQosConnectionContext` (`peer_type`, `total_stake`) at connection-establishment time. [1](#0-0) 

This context is then used for the entire life of the connection to:
- decide `max_connections_per_peer` and which connection table (`staked_connection_table` vs `unstaked_connection_table`) the connection lives in, and to prune competing connections via `prune_random(..., stake)` using the cached stake value, in `cache_new_connection`/`try_add_connection`. [2](#0-1) [3](#0-2) 
- compute `max_uni_streams` for the connection via `compute_max_allowed_uni_streams_with_rtt(rtt_millis, conn_context.peer_type(), conn_context.total_stake)`, again from the cached snapshot. [4](#0-3) 
- gate per-stream throttling via `max_streams_per_throttling_interval`, which forwards `conn_context.peer_type` and `conn_context.total_stake` straight into `StakedStreamLoadEMA::available_load_capacity_in_throttling_duration`, which grants staked peers a share of `max_staked_load_in_throttling_window` proportional to the *cached* stake. [5](#0-4) [6](#0-5) 

At the `ConnectionTable` level, the per-entry `stake()` used for eviction comparisons (`prune_random`) is likewise the `peer_type` value frozen when the entry was created, not something re-derived from the live stake map. [7](#0-6) [8](#0-7) 

There is no code path that re-invokes `build_connection_context`/`get_connection_stake` for an already-open connection when the shared `staked_nodes: Arc<RwLock<StakedNodes>>` is updated (e.g. on an epoch boundary or after the peer un-delegates/withdraws their stake). The only place `ConnectionEntry` last-update/idle time is checked is for idle-based pruning, which is unrelated to stake re-validation.

This mirrors the reported bug's root cause exactly: an entitlement (locked balance / stake) changes, but a derived, already-materialized privilege (veMENTO voting power / QUIC QoS class, connection-table membership, prune-resistance, and per-connection stream quota) is not recomputed and continues to be honored until some unrelated event (there: `start()` is called; here: the connection is eventually closed/pruned for unrelated reasons).

### Impact Explanation
An attacker can temporarily acquire (or borrow/rent) a large stake, open one or more QUIC connections to a validator's TPU while staked (getting placed in the high-priority `staked_connection_table`, being granted a large `max_uni_streams` value, a high per-connection quota via `StakedStreamLoadEMA`, and prune-resistance against random eviction), then immediately reduce or remove that stake. The already-open connections retain their favorable QoS classification and are not re-evaluated, so the attacker keeps consuming disproportionate `staked` streaming capacity and connection-table slots (at the expense of genuinely staked peers, whose new connections may be evicted or rate-limited more aggressively due to the frozen-stake attacker occupying `staked_connection_table` capacity) for as long as the connections remain alive. This is a QoS-evasion issue: SWQoS resource allocation is supposed to be proportional to current stake, but is effectively "sticky" to a point-in-time stake snapshot.

### Likelihood Explanation
Reachable by any unprivileged network peer capable of transiently acquiring stake (or having stake reduced) and maintaining a long-lived QUIC connection; no validator/operator role is required, matching the "unprivileged-user analog" constraint for QUIC/UDP streamer QoS. The precondition (stake changing after connection establishment, e.g. via de-delegation, unstaking, or natural epoch-boundary stake changes) is common in normal cluster operation, making exploitation opportunistic rather than requiring rare conditions.

### Recommendation
Periodically re-validate (or re-fetch) the connection's stake against the live `staked_nodes` map — e.g., on each new stream, on `staked_nodes` epoch refresh, or on a timer — and demote/re-tier the connection's `peer_type`/`total_stake` (and, if necessary, migrate it between `staked_connection_table` and `unstaked_connection_table`, or close it) when the peer's current stake no longer supports its cached classification, instead of trusting the value captured once at connection-open time for the connection's entire lifetime.

### Proof of Concept
1. Node `A` obtains sufficient stake to be classified `ConnectionPeerType::Staked(stake)` by `get_connection_stake`.
2. `A` opens a QUIC connection to a validator's TPU; `SwQos::build_connection_context`/`cache_new_connection` place it in `staked_connection_table` with a `max_uni_streams` and per-interval stream budget computed from `stake` at that instant. [2](#0-1) 
3. `A`'s stake is reduced to (near) zero (de-delegate/deactivate/transfer out) immediately after the connection handshake completes.
4. `A` keeps the connection open (sending occasional traffic to avoid idle-based pruning) and continues sending streams at the rate permitted by the now-stale, high `total_stake`/`peer_type` cached in `SwQosConnectionContext`, since `on_new_stream`/`max_streams_per_throttling_interval` never re-derive these values from the current `staked_nodes` state. [9](#0-8) 
5. Because `ConnectionTable::stake()` used by `prune_random` also reflects the stale, originally-cached stake, `A`'s connection resists eviction as if it still held its original stake, even though it no longer does. [8](#0-7)

fn compute_max_allowed_uni_streams_with_rtt(
    rtt_millis: u32,
    peer_type: ConnectionPeerType,
    total_stake: u64,
) -> u32 {
    let streams = match peer_type {
        ConnectionPeerType::Staked(peer_stake) => {
            // No checked math for f64 type. So let's explicitly check for 0 here
            if total_stake == 0 || peer_stake > total_stake {
                warn!(
                    "Invalid stake values: peer_stake: {peer_stake:?}, total_stake: \
                     {total_stake:?}"
                );

                QUIC_MIN_STAKED_CONCURRENT_STREAMS
            } else {
                let delta = (QUIC_TOTAL_STAKED_CONCURRENT_STREAMS
                    - QUIC_MIN_STAKED_CONCURRENT_STREAMS) as f64;

                (((peer_stake as f64 / total_stake as f64) * delta) as u32
                    + QUIC_MIN_STAKED_CONCURRENT_STREAMS)
                    .clamp(
                        QUIC_MIN_STAKED_CONCURRENT_STREAMS,
                        QUIC_MAX_STAKED_CONCURRENT_STREAMS,
                    )
            }
        }
        ConnectionPeerType::Unstaked => QUIC_MAX_UNSTAKED_CONCURRENT_STREAMS,
    };
    // scale amount of streams based on RTT if RTT is larger than REFERENCE_RTT_MS
    // multiply first then divide to avoid rounding errors.
    (streams.saturating_mul(rtt_millis.clamp(REFERENCE_RTT_MS, MAX_RTT_MS))) / REFERENCE_RTT_MS
}

    fn cache_new_connection(
        &self,
        client_connection_tracker: ClientConnectionTracker,
        connection: &Connection,
        mut connection_table_l: MutexGuard<ConnectionTable<ConnectionStreamCounter>>,
        conn_context: &SwQosConnectionContext,

            CancellationToken,

        // get current RTT and limit it to MAX_RTT_MS right away
        let rtt_millis = connection.rtt().as_millis().min(MAX_RTT_MS as u128) as u32;
        let max_uni_streams = VarInt::from_u32(compute_max_allowed_uni_streams_with_rtt(

        let max_connections_per_peer = match conn_context.peer_type() {
            ConnectionPeerType::Unstaked => self.config.max_connections_per_unstaked_peer,

                remote_addr.port(),

                conn_context.peer_type(),
                conn_context.last_update.clone(),
                max_connections_per_peer,
                || Arc::new(ConnectionStreamCounter::new()),

            drop(connection_table_l);

            connection.set_max_concurrent_uni_streams(max_uni_streams);
            debug!(

                conn_context.total_stake,

                remote_addr,
            );
            Ok((last_update, cancel_connection, stream_counter))
        } else {

    fn build_connection_context(&self, connection: &Connection) -> SwQosConnectionContext {
        let remote_address = connection.remote_address();
        get_connection_stake(connection, &self.staked_nodes).map_or(
            SwQosConnectionContext {
                peer_type: ConnectionPeerType::Unstaked,
                total_stake: 0,
                remote_pubkey: None,
                in_staked_table: false,
                remote_address,
                stream_counter: None,
                last_update: Arc::new(AtomicU64::new(timing::timestamp())),
            },
            |(pubkey, stake, total_stake)| {
                // The heuristic is that the stake should be large enough to have 1 stream pass through within one throttle
                // interval during which we allow max (MAX_STREAMS_PER_MS * STREAM_THROTTLING_INTERVAL_MS) streams.

                let peer_type = {
                    let max_streams_per_ms = self.staked_stream_load_ema.max_streams_per_ms();
                    let min_stake_ratio =
                        1_f64 / (max_streams_per_ms * STREAM_THROTTLING_INTERVAL_MS) as f64;
                    let stake_ratio = stake as f64 / total_stake as f64;
                    if stake_ratio < min_stake_ratio {
                        // If it is a staked connection with ultra low stake ratio, treat it as unstaked.
                        ConnectionPeerType::Unstaked
                    } else {
                        ConnectionPeerType::Staked(stake)
                    }
                };

                SwQosConnectionContext {
                    peer_type,
                    total_stake,
                    remote_pubkey: Some(pubkey),
                    in_staked_table: false,
                    remote_address,
                    last_update: Arc::new(AtomicU64::new(timing::timestamp())),
                    stream_counter: None,
                }
            },
        )
    }

        match peer_type {

                        .max(self.max_unstaked_load_in_throttling_window + 1)
                } else {
                    self.max_staked_load_in_throttling_window
                }
            }

    // Randomly selects sample_size many connections, evicts the one with the
    // lowest stake, and returns the number of pruned connections.
    // If the stakes of all the sampled connections are higher than the
    // threshold_stake, rejects the pruning attempt, and returns 0.
    pub(crate) fn prune_random(&mut self, sample_size: usize, threshold_stake: u64) -> usize {
        let num_pruned = std::iter::once(self.table.len())
            .filter(|&size| size > 0)
            .flat_map(|size| {
                let mut rng = rng();
                repeat_with(move || rng.random_range(0..size))
            })
            .map(|index| {
                let connection = self.table[index].first();
                let stake = connection.map(|connection: &ConnectionEntry<S>| connection.stake());
                (index, stake)
            })
            .take(sample_size)
            .min_by_key(|&(_, stake)| stake)
            .filter(|&(_, stake)| stake < Some(threshold_stake))
            .and_then(|(index, _)| self.table.swap_remove_index(index))
            .map(|(_, connections)| connections.len())
            .unwrap_or_default();
        self.total_size = self.total_size.saturating_sub(num_pruned);
        num_pruned
    }
