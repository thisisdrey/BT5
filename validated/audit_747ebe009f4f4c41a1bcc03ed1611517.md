### Title
Positions with debt between `debtFloorInUsd` and `2 * debtFloorInUsd` can never be liquidated, guaranteeing protocol bad debt - ([File: contracts/Pool.sol])

### Summary
`Pool.liquidate` enforces two conflicting invariants: a per-call `maxLiquidable` cap (50% of the account's debt-token balance) and a `debtFloorInUsd` rule that forbids leaving residual debt below the floor (unless fully repaid). For any account whose total debt in a synthetic token is in the range `(debtFloorInUsd, 2 * debtFloorInUsd)`, every allowed repayment amount reverts, so the position is permanently un-liquidatable. Like the Asterisk CVE (a remote authenticated user crashing the service with a crafted message), an unprivileged user can deterministically force a core protocol function to revert on every call.

### Finding Description
In `Pool.liquidate`, the repay amount is capped by `maxLiquidable` (initialized to `0.5e18` = 50%): [1](#0-0) 

```solidity
if (amountToRepay_.wadDiv(_debtTokenBalance) > maxLiquidable) {
    revert AmountGreaterThanMaxLiquidable();
}
if (debtFloorInUsd > 0) {
    uint256 _newDebtInUsd = masterOracle().quoteTokenToUsd(
        address(syntheticToken_), _debtTokenBalance - amountToRepay_);
    if (_newDebtInUsd > 0 && _newDebtInUsd < debtFloorInUsd) {
        revert RemainingDebtIsLowerThanTheFloor();
    }
}
``` [2](#0-1) 

Consider an account whose debt `D` (in USD) satisfies `debtFloorInUsd < D < 2 * debtFloorInUsd`:

- **Partial repay** `amountToRepay_ <= 0.5 * D` leaves remaining debt `>= 0.5 * D > 0`, and since `D < 2*floor`, remaining debt `< floor` → reverts `RemainingDebtIsLowerThanTheFloor`.
- **Full repay** `amountToRepay_ = D` gives ratio `wadDiv = 1e18 > maxLiquidable` → reverts `AmountGreaterThanMaxLiquidable`.

Every possible `amountToRepay_` reverts. The same floor check in `DebtToken.repay` means no one can cheaply "fix" the account either (any repay leaving sub-floor debt reverts, and a full repay is a pure donation): [3](#0-2) 

Reachability for an unprivileged attacker: open a normal position via `DepositToken.deposit` + `DebtToken.issue` sized so the debt lands in the dead band (issuing debt `>= floor` is permitted), then either let interest accrual/collateral price drift make it unhealthy, or intentionally become liquidatable. Once `debtPositionOf(account_)` returns `_isHealthy == false`, every `liquidate` call reverts. This is not governance-dependent: `maxLiquidable = 50%` is the deployment default and `debtFloorInUsd > 0` is an ordinary production configuration.

### Impact Explanation
Protocol insolvency: the unhealthy position's collateral cannot be seized, so while the synthetic debt remains outstanding the collateral backing it continues to decay (price moves or further interest accrual) with no recourse. Liquidation liveness — the core solvency invariant — is broken for an entire contiguous band of debt sizes that normal users can freely create.

### Likelihood Explanation
High whenever `debtFloorInUsd > 0` is configured. The vulnerable band `(floor, 2*floor)` is wide (e.g., floor = $100 → any debt in $100–$200). Any user can mint debt inside it, and positions can also drift into it naturally via interest accrual on the debt or synthetic-token price appreciation. No privileged role, oracle manipulation, or exotic tooling is needed.

### Recommendation
Apply `maxLiquidable` and the debt floor conjunctively rather than letting them conflict: e.g., in `liquidate`, allow a full repay whenever a partial repay would push the residual below the floor (`if remaining < floor: require amountToRepay_ == _debtTokenBalance` and exempt full-repay from the `maxLiquidable` cap), or relax `maxLiquidable` to `min(maxLiquidable, needed to reach floor or zero)`. Add a test covering `debtFloorInUsd < debt < 2 * debtFloorInUsd`.

### Proof of Concept
Hardhat sketch (mirroring `test/Pool.test.ts` liquidation setup):

```ts
// Setup: pool with maxLiquidable = 50%, debtFloorInUsd = $100
await pool.updateDebtFloor(parseEther('100'));
await pool.updateMaxLiquidable(parseEther('0.5'));

// Alice deposits MET collateral and issues msUSD debt worth ~$150 (in the dead band)
await met.connect(alice).approve(msdMET.address, MAX);
await msdMET.connect(alice).deposit(alice.address, collateralFor150Usd);
await msUsdDebtToken.connect(alice).issue(parseEther('150'), alice.address); // debt = $150

// Price moves so position becomes unhealthy
await masterOracle.updatePrice(met.address, lowerPrice);
expect((await pool.debtPositionOf(alice.address))._isHealthy).false;

// Partial repay (e.g. 50%) -> residual $75 < floor
await expect(
  pool.connect(liq).liquidate(msUsd.address, alice.address, parseEther('75'), msdMET.address)
).revertedWithCustomError(pool, 'RemainingDebtIsLowerThanTheFloor');

// Full repay -> ratio 1e18 > maxLiquidable
await expect(
  pool.connect(liq).liquidate(msUsd.address, alice.address, parseEther('150'), msdMET.address)
).revertedWithCustomError(pool, 'AmountGreaterThanMaxLiquidable');

// No amountToRepay in (0, debt] succeeds: position is un-liquidatable
```
