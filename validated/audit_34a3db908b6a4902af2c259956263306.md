### Title
Unbounded tar extraction and double directory walk in `SetCustomHooks` enables repository-scoped DoS via hooks-lock starvation - ([File: internal/gitaly/repoutil/custom_hooks.go])

### Summary
`SetCustomHooks` extracts an attacker-supplied, size-unbounded tar stream via a spawned `tar` process and then walks the extracted tree twice with `filepath.WalkDir` (once for the "prepared" vote, once for the "committed" vote) while holding the repository's custom-hooks lock (`safe.NewLockingDirectory`) for the whole operation. Because there is no entry-count, path-depth, or total-size limit enforced before or during extraction, a user with write access to any repository can submit a tar with a very large number of entries (or deeply nested paths) to make the handler consume excessive CPU/memory/time while the hooks lock is held, blocking other legitimate hook updates on that repository.

### Finding Description
The RPC entry point `(s *server) SetCustomHooks` reads the `SetCustomHooksRequest` stream directly into `repoutil.SetCustomHooks` without any size or entry-count validation: [1](#0-0) .

Inside `SetCustomHooks`, the hooks lock is acquired before any bound is placed on the incoming data: [2](#0-1) .

`ExtractHooks` then pipes the raw reader straight into a spawned `tar -xf -` process with no `--max` limits on file count or path length: [3](#0-2) .

After extraction, `newDirectoryVote` performs a full `filepath.WalkDir` over the extracted tree — opening and hashing every file — and this function is called twice per `SetCustomHooks` invocation: once on the temporary extraction path (`tempHooksPath`) before the move, and once again on the final repository path (`repoHooksPath`) after the move: [4](#0-3) [5](#0-4) [6](#0-5) .

None of `ValidateRepository`, `locator.GetRepoPath`, or the tar extraction logic impose an upper bound on the number of tar entries, nesting depth, or total extracted size, so the CPU/IO cost of both the `tar` subprocess and the double `WalkDir` scales linearly (or worse, due to per-entry filesystem syscalls) with attacker-controlled input, all while `hooksLock` is held for the repository, which is a shared resource for any other `SetCustomHooks`/`RestoreCustomHooks` call on the same repository.

### Impact Explanation
The impact is scoped to the targeted repository: a single request with e.g. 10^6 tiny `custom_hooks/` entries would force the `tar` subprocess and two full-tree walks (with per-file `os.Open`/`io.Copy` calls) to process a huge number of filesystem operations, extending the time `hooksLock` is held and consuming CPU/memory/file-descriptor resources on the Gitaly node. This matches the "DoS of an RPC handler" impact class; if issued concurrently from multiple repositories/requests, it can also contribute to worker/goroutine exhaustion on the node, though this is not unique to hooks — it is proportional resource use similar to any large streamed write.

### Likelihood Explanation
Any authenticated user with push/write access to a repository they control can invoke `SetCustomHooks`/`RestoreCustomHooks` and stream an arbitrarily large tar, since there is no message/entry/size ceiling enforced in `ExtractHooks` or `SetCustomHooks` before extraction and locking. This requires no special role and is trivially repeatable, but it is also not qualitatively different from other legitimate large writes a repository owner can already perform on their own repository (e.g., pushing huge packs), so the marginal severity depends on how disproportionate the resource cost is relative to accepted request sizes elsewhere in Gitaly.

### Recommendation
Enforce limits before/while extracting: cap the maximum number of tar entries, maximum total extracted size, and maximum path depth/length for `custom_hooks` tarballs (e.g., pre-scan the tar header stream or pass `tar` flags/wrapper limits), and consider bounding `filepath.WalkDir` traversal (entry count and depth) in `newDirectoryVote`, returning a client error when limits are exceeded instead of performing unbounded work while holding `hooksLock`.

    var buf bytes.Buffer

    for i := 0; i < 1_000_000; i++ {
        name := fmt.Sprintf("custom_hooks/f%d", i)
        require.NoError(t, tw.WriteHeader(&tar.Header{Name: name, Size: 0, Mode: 0o755}))
    }
    require.NoError(t, tw.Close())

    start := time.Now()
    err := SetCustomHooks(ctx, logger, locator, txManager, &buf, repo)
    elapsed := time.Since(start)
    require.NoError(t, err)
    // Assert this stays within an expected bound, e.g. elapsed < 1s and memory usage bounded;
    // currently no such assertion is enforceable because no limit is implemented.

func (s *server) SetCustomHooks(stream gitalypb.RepositoryService_SetCustomHooksServer) error {
	ctx := stream.Context()

	firstRequest, err := stream.Recv()
	if err != nil {
		return structerr.NewInternal("getting first request: %w", err)
	}

	repo := firstRequest.GetRepository()
	if err := s.locator.ValidateRepository(ctx, repo); err != nil {
		return structerr.NewInvalidArgument("%w", err)
	}

	reader := streamio.NewReader(func() ([]byte, error) {
		if firstRequest != nil {
			data := firstRequest.GetData()
			firstRequest = nil
			return data, nil
		}

		request, err := stream.Recv()
		return request.GetData(), err
	})

	if err := repoutil.SetCustomHooks(ctx, s.logger, s.locator, s.txManager, reader, repo); err != nil {
		return structerr.NewInternal("setting custom hooks: %w", err)
	}

	return stream.SendAndClose(&gitalypb.SetCustomHooksResponse{})

func ExtractHooks(ctx context.Context, logger log.Logger, reader io.Reader, path string, stripPrefix bool) error {
	// GNU tar does not accept an empty file as a valid tar archive and produces
	// an error. Since an empty hooks tar is symbolic of a repository having no
	// hooks, the reader is peeked to check if there is any data present.
	buf := bufio.NewReader(reader)
	if _, err := buf.Peek(1); errors.Is(err, io.EOF) {
		return nil
	}

	stripComponents := "0"
	if stripPrefix {
		stripComponents = "1"
	}

	cmdArgs := []string{"-xf", "-", "-C", path, "--strip-components", stripComponents, CustomHooksDir}

	var stderrBuilder strings.Builder
	cmd, err := command.New(ctx, logger, append([]string{"tar"}, cmdArgs...),
		command.WithStdin(buf),
		command.WithStderr(&stderrBuilder))
	if err != nil {
		return fmt.Errorf("executing tar command: %w", err)
	}

	if err := cmd.Wait(); err != nil {
		stderr := stderrBuilder.String()

		// GNU and BSD tar versions have differing errors when attempting to
		// extract specified members from a valid tar archive. If the tar
		// archive is valid the errors for GNU and BSD tar should have the
		// same prefix, which can be checked to validate whether the expected
		// content is present in the archive for extraction.
		if strings.HasPrefix(stderr, "tar: custom_hooks: Not found in archive") {
			return nil
		}

		return structerr.New("waiting for tar command completion: %w", err).WithMetadata("stderr", stderr)
	}

	return nil
}

func newDirectoryVote(basePath string) (*voting.VoteHash, error) {
	voteHash := voting.NewVoteHash()

	if err := filepath.WalkDir(basePath, func(path string, entry fs.DirEntry, err error) error {
		if err != nil {
			return err
		}

		relPath, err := filepath.Rel(basePath, path)
		if err != nil {
			return fmt.Errorf("getting relative path: %w", err)
		}

		// Write file relative path to hash.
		_, _ = voteHash.Write([]byte(relPath))

		info, err := entry.Info()
		if err != nil {
			return fmt.Errorf("getting file info: %w", err)
		}

		// Write file permissions to hash.
		permBytes := make([]byte, 4)
		binary.BigEndian.PutUint32(permBytes, uint32(info.Mode()))
		_, _ = voteHash.Write(permBytes)

		if entry.IsDir() {
			return nil
		}

		file, err := os.Open(path)
		if err != nil {
			return fmt.Errorf("opening file: %w", err)
		}
		defer file.Close()

		// Copy file data to hash.
		if _, err = io.Copy(voteHash, file); err != nil {
			return fmt.Errorf("copying file to hash: %w", err)
		}

		return nil
	}); err != nil {
		return nil, fmt.Errorf("walking directory: %w", err)
	}

	return &voteHash, nil
}
