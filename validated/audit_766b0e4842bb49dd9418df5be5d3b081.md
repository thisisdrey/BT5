### Title
StackerDB slot signatures do not bind to the contract/StackerDB instance, enabling cross-contract chunk replay - (File: `libstackerdb/src/libstackerdb.rs`)

### Summary
`SlotMetadata::sign`/`verify` (used by every StackerDB chunk write path) compute the signed digest over only `slot_id`, `slot_version`, and `data_hash` — it never includes the target `QualifiedContractIdentifier` (the specific StackerDB instance/contract). This is the same class of bug as the Trader `LimitOrder` issue: a signature that authorizes an action in one context (a market / a StackerDB contract) carries no binding to that context, so it can be replayed in a different context where the equality check that *should* tie the signature to its intended contract is missing.

### Finding Description

and `sign`/`verify` operate purely over that digest: [2](#0-1) 

Every place that accepts a chunk — `StackerDBTx::try_replace_chunk` (local write path) and `PeerNetwork::validate_received_chunk` (network push/pull path) — validates the signature only against `(slot_id, slot_version, data_hash)` plus a separately-looked-up expected signer address for *that* `smart_contract_id`; the contract identifier itself is never mixed into the signed material: [3](#0-2) [4](#0-3) 

This means the *equality* that should be enforced — "this signature was produced by this signer **for this specific StackerDB contract**" — is never checked; only "this signature recovers to an address that happens to be the configured signer for slot `slot_id` in contract `smart_contract_id`" is checked. If the same private key/address is registered as the owner of slot `N` in two different StackerDB contracts (which does happen: e.g. the same reward-cycle/signer-set participants own the same slot numbering across multiple `signer-<cycle>-<set>` and `signer-<cycle>-<set>-...` boot contracts for different message "lanes", as referenced in the lane-matching logic in `libsigner/src/events.rs`), a chunk signed for contract A (specific slot_id/version/data_hash) is a byte-for-byte valid signature for the identically-numbered slot in contract B, provided the attacker can also make the `slot_version`/`data_hash` match (or simply captures/replays a genuine chunk originally destined for contract A into contract B while both are still awaiting that version/data).

Note: `handle_unsolicited_StackerDBPushChunk` does look up the `StackerDBConfig` keyed by `chunk_data.contract_id` and calls `get_slot_signer(smart_contract_id, slot_id)` (contract-scoped lookup), so the *address* check is contract-scoped — but the underlying cryptographic proof (the signature itself) does not depend on which contract it is checked against, only on `(slot_id, slot_version, data_hash)`. Any relayer/attacker holding a valid `(slot_id, slot_version, data_hash, sig)` tuple originally produced for contract A can present the identical tuple to a node's endpoint for contract B; it will be accepted there if the signing address also owns that slot in B.

### Impact Explanation
This breaks the intended data-authenticity guarantee of StackerDB: an operator or attacker who has observed a chunk signed for one StackerDB contract can forward that same signed chunk into a different StackerDB contract that shares slot ownership (e.g. across the multiple `signer-<cycle>-<set>` "lane" contracts used for different `SignerMessageTypePrefix` categories, as seen in `libsigner/src/events.rs`'s lane-matching logic), causing a node to store attacker-forwarded data as if it were freshly and independently authorized for that contract. Depending on which lane/contract this lands in, this is unauthorized-write-adjacent: data intended for one message category (e.g. `BlockPreCommit`) could satisfy the slot/version/hash requirements of another category's slot if `data_hash` happens to coincide, or more realistically an attacker with network position can indefinitely re-broadcast/relay a legitimately-signed chunk into a sibling contract it was never meant for, propagating it as authentic StackerDB state network-wide. This matches the "unauthenticated/unauthorized write to state" / "network-wide propagation of forged data" impact class, since the receiving contract has no cryptographic assurance the signer ever intended the data for *that* contract.

### Likelihood Explanation
Exploitation requires: (1) the same signer address to be configured as slot owner in two or more StackerDB contracts with the same `slot_id` (a real, existing occurrence given the multi-lane signer contract design referenced by `get_signers_db_signer_set_message_id`/lane matching), and (2) either colliding `data_hash`/`slot_version` or simple capture-and-replay of an observed chunk into the sibling contract before/around when it's independently expected there. This is a moderate-likelihood, remote, unauthenticated (no node secret or admin role needed) network-relay condition — the attacker only needs to observe a legitimately broadcast/gossiped `StackerDBChunkData`/`StackerDBPushChunkData` message and resend it, unmodified, to a peer configured for a different but slot-compatible StackerDB contract.

### Recommendation
Bind the signed digest to the target contract as well: include `smart_contract_id` (or a stable, canonical serialization of it) inside `SlotMetadata::auth_digest()` before hashing, e.g.:
```
hasher.update(contract_id.serialize_to_vec());
hasher.update(self.slot_id.to_be_bytes());
hasher.update(self.slot_version.to_be_bytes());
hasher.update(self.data_hash.0);
```
and propagate the contract identifier through `sign`/`verify`/`recover_pk` in `StackerDBChunkData` and `SlotMetadata`, updating all call sites (`try_replace_chunk`, `validate_received_chunk`, `validate_downloaded_chunk`, RPC POST-chunk handlers, and the miner/signer chunk-signing helpers in `stacks-node`) to pass the contract ID into the digest computation. This closes the cross-contract replay gap analogous to adding the `order.targetTracer == market` check in the referenced report.

### Proof of Concept
Conceptual PoC (cannot be executed here, but derivable from the code paths cited above):
1. Configure two StackerDB contracts, A and B, both listing address `S` as the signer for `slot_id = 0`.
2. Signer `S` legitimately signs and pushes chunk `(slot_id=0, slot_version=1, data)` to contract A via `StackerDBChunkData::sign` (`libstackerdb/src/libstackerdb.rs:226-231`).
3. Attacker observes this `StackerDBPushChunkData` (or `StackerDBChunkData`) on the wire and resubmits the identical `(slot_id, slot_version, sig, data)` payload but targeting contract B's endpoint/contract_id.
4. `PeerNetwork::validate_received_chunk` (`stackslib/src/net/stackerdb/mod.rs:649-718`) looks up `get_slot_signer(B, 0)` → `S`, then calls `slot_metadata.verify(&S)`, which succeeds because the digest never encoded which contract it was for — the chunk is accepted into contract B's slot 0 even though `S` never signed anything for B specifically.     /// Get the digest to sign that authenticates this chunk data and metadata
    fn auth_digest(&self) -> Sha512Trunc256Sum {
        let mut hasher = Sha512_256::new();
        hasher.update(self.slot_id.to_be_bytes());
        hasher.update(self.slot_version.to_be_bytes());
        hasher.update(self.data_hash.0);
        Sha512Trunc256Sum::from_hasher(hasher)
    }

    /// Sign this slot metadata, committing to slot_id, slot_version, and
    /// data_hash.  Sets self.signature to the signature.
    /// Fails if the underlying crypto library fails
    pub fn sign(&mut self, privkey: &StacksPrivateKey) -> Result<(), Error> {
        let auth_digest = self.auth_digest();
        let sig = privkey
            .sign(&auth_digest.0)
            .map_err(|se| Error::SigningError(se.to_string()))?;

        self.signature = sig;
        Ok(())
    }

    /// Verify that a given principal signed this chunk metadata.
    /// Note that the address version is ignored.
    pub fn verify(&self, principal: &StacksAddress) -> Result<bool, Error> {
        let sigh = self.auth_digest();
        let pubk = StacksPublicKey::recover_to_pubkey_without_validating_low_s(
            sigh.as_bytes(),
            &self.signature,
        )
        .map_err(|ve| Error::VerifyingError(ve.to_string()))?;

        let pubkh = Hash160::from_node_public_key(&pubk);
        Ok(pubkh == *principal.bytes())
    }

    /// Add or replace a chunk for a given reward cycle, if it is valid
    /// Otherwise, this errors out with Error::StaleChunk
    pub fn try_replace_chunk(
        &self,
        smart_contract: &QualifiedContractIdentifier,
        slot_desc: &SlotMetadata,
        chunk: &[u8],
    ) -> Result<(), net_error> {
        // Check per-replica chunk-size cap.
        if (chunk.len() as u64) > self.config.chunk_size {
            return Err(net_error::StackerDBChunkTooBig(chunk.len()));
        }

        let slot_validation = self
            .get_slot_validation(smart_contract, slot_desc.slot_id)?
            .ok_or(net_error::NoSuchSlot(
                smart_contract.clone(),
                slot_desc.slot_id,
            ))?;

        if !slot_desc.verify(&slot_validation.signer)? {
            return Err(net_error::BadSlotSigner(
                slot_validation.signer,
                slot_desc.slot_id,
            ));
        }
        if slot_desc.slot_version <= slot_validation.version {
            return Err(net_error::StaleChunk {
                supplied_version: slot_desc.slot_version,
                latest_version: slot_validation.version,
            });
        }
        if slot_desc.slot_version > self.config.max_writes {
            return Err(net_error::TooManySlotWrites {
                supplied_version: slot_desc.slot_version,
                latest_version: slot_validation.version,
                max_writes: self.config.max_writes,
            });
        }
        self.insert_chunk(smart_contract, slot_desc, chunk)
    }
}

    pub fn validate_received_chunk(
        &self,
        smart_contract_id: &QualifiedContractIdentifier,
        config: &StackerDBConfig,
        data: &StackerDBChunkData,
        expected_versions: &[u32],
    ) -> Result<bool, net_error> {
        // validate -- must not exceed this replica's configured chunk size.
        if (data.data.len() as u64) > config.chunk_size {
            info!(
                "Received StackerDBChunk for {} ID {}, which is oversized: {} bytes (max {} bytes)",
                smart_contract_id,
                data.slot_id,
                data.data.len(),
                config.chunk_size
            );
            return Ok(false);
        }

        // validate -- must be a valid chunk
        let Some(expected_version) = expected_versions.get(data.slot_id as usize) else {
            info!(
                "Received StackerDBChunk for {} ID {}, which is too big ({})",
                smart_contract_id,
                data.slot_id,
                expected_versions.len()
            );
            return Ok(false);
        };

        // validate -- must be signed by the expected author
        let addr = match self
            .stackerdbs
            .get_slot_signer(smart_contract_id, data.slot_id)?
        {
            Some(addr) => addr,
            None => {
                return Ok(false);
            }
        };

        let slot_metadata = data.get_slot_metadata();
        if !slot_metadata.verify(&addr)? {
            info!(
                "StackerDBChunk for {} ID {} is not signed by {}",
                smart_contract_id, data.slot_id, &addr
            );
            return Ok(false);
        }

        // validate -- must be the current or newer version
        if data.slot_version < *expected_version {
            info!(
                "Received StackerDBChunk for {} ID {} version {}, which is stale (expected {})",
                smart_contract_id, data.slot_id, data.slot_version, *expected_version
            );
            return Ok(false);
        }

        // validate -- must not exceed max writes
        if data.slot_version > config.max_writes {
            info!(
                "Write count exceeded for StackerDBChunk for {} ID {} version {} (max is {})",
                smart_contract_id, data.slot_id, data.slot_version, config.max_writes
            );
            return Ok(false);
        }

        Ok(true)
    }
