### Title
Unstaked attacker can fill/evict the bounded TPU-vote channel with garbage "vote-shaped" transactions by exploiting `is_simple_vote_transaction_view`'s structural-only heuristic - (File: perf/src/sigverify.rs)

### Summary
`verify_packet()` classifies a packet as `SIMPLE_VOTE_TX` purely from message *shape* (legacy version, ≤2 sigs, exactly one instruction whose `program_id_index` resolves to `solana_sdk_ids::vote::id()`) via `is_simple_vote_transaction_view`, independent of whether the instruction data actually decodes to a valid `VoteInstruction`. Because the cryptographic check in the same function only verifies that the attacker-supplied signatures match attacker-supplied pubkeys over the message (`signature.verify(pubkey.as_ref(), message)`), an unstaked attacker can self-sign a "vote-shaped" transaction with garbage instruction data, have it pass sigverify, and have it routed into the small, bounded vote channel.

### Finding Description
`verify_packet` (perf/src/sigverify.rs:20-63) computes `is_simple_vote_tx` from `is_simple_vote_transaction_view` (lines 76-106), which only checks:
- `num_signatures() <= 2`
- `TransactionVersion::Legacy`
- exactly 1 instruction
- that instruction's `program_id_index` resolves to `vote::id()`

It never inspects the instruction data. The signature check (lines 43-54) verifies signatures against the *static account keys embedded in the same attacker-controlled message* — i.e., it proves the attacker owns the keys they put in the message, not that the transaction is a genuine vote. [1](#0-0) [2](#0-1) 

This is corroborated by the existing test `test_is_simple_vote_transaction`, which explicitly constructs a legacy single-instruction vote-program transaction with garbage data (`tx.message.instructions[0].data = vec![1, 2, 3]`) and asserts `is_simple_vote_transaction_view` still returns `true`. [3](#0-2) 

Routing into the vote channel vs non-vote channel is primarily determined by which QUIC/UDP socket the packet arrived on, not by the flag: the TPU-vote QUIC port is served by `spawn_simple_qos_server` (not the stake-weighted `spawn_stake_weighted_qos_server` used for the regular TPU port), meaning an unstaked/unprivileged client can connect directly. [4](#0-3) 

Packets from that vote socket are dispatched with `reject_non_vote = true` in the sigverify worker pool: `Self::run_transaction_task(batch, true, ..., true, true, ..., &channels.tpu_vote_state)`. [5](#0-4) 

Inside `verify_packet`, when `reject_non_vote` is true, the only gate applied is the structural `is_simple_vote_tx` heuristic — `if reject_non_vote && !is_simple_vote_tx { (is_simple_vote_tx, false) }` — so a crafted vote-shaped-but-fake transaction with a self-signed valid signature sails through this gate and is marked `verified = true`. [6](#0-5) 

The verified batch is then forwarded to `tpu_vote_sender`, which feeds the bounded vote channel sized `VOTE_CHANNEL_CAPACITY = 1024 * 8`, versus `NON_VOTE_CHANNEL_CAPACITY = 1024 * 16` for regular transactions. [7](#0-6) 

That channel is an `EvictingSender`, which on overflow evicts the *oldest* queued message to make room for the newer one rather than blocking or rejecting the new send: [8](#0-7) 

Only much later, in `LatestValidatorVote::new_from_view` (core/src/banking_stage/latest_validator_vote_packet.rs), is the instruction data actually deserialized as a `VoteInstruction` and rejected if it doesn't parse or lacks an authorized-voter signature. [9](#0-8)  By that point the packet has already consumed a slot in the small, bounded, evicting vote channel and CPU cycles in the dedicated vote sigverify/worker path — resources that are disproportionately scarce compared to the non-vote channel.

### Impact Explanation
An unstaked remote client can flood the TPU-vote QUIC port with self-signed, structurally-vote-shaped-but-semantically-invalid transactions. Because these pass the `reject_non_vote` structural gate and real signature check (attacker signs their own garbage), they occupy space in the smaller, `EvictingSender`-backed `VOTE_CHANNEL_CAPACITY` (8192) channel, potentially evicting genuine, stake-relevant validator vote packets before they reach `VoteWorker`/`VoteStorage` for consensus-critical processing. This is a vote-channel capacity DoS: it degrades the leader's ability to timely process real votes under load, distinct from — and cheaper to mount than — flooding the much larger non-vote channel, since it requires no real vote-program semantics, only message shape and a trivial keypair-owned signature.

### Likelihood Explanation
Fully reachable by an unstaked/unprivileged remote client: it only requires opening a QUIC connection to the leader's public TPU-vote port (served via `spawn_simple_qos_server`, no stake-weighting gate) and sending crafted packets. Constructing the exploit payload is straightforward — a legacy `Transaction` with one instruction whose `program_id` is `solana_sdk_ids::vote::id()`, up to 2 signers, and arbitrary instruction `data`, self-signed with freshly generated keypairs. This requires no leaked keys, no staked identity, and no validator misconfiguration — it is repeatable at will and scriptable into a sustained flood.

### Recommendation
Do not treat structural shape alone as sufficient for routing/priority decisions on the reduced-capacity vote channel. Either:
1. In `is_simple_vote_transaction_view` (or a variant used specifically for the `reject_non_vote` gate on the TPU-vote ingress path), additionally attempt a lightweight `limited_deserialize::<VoteInstruction>` of the instruction data and require it to decode into a recognized vote instruction variant before accepting the packet into the vote channel; reject otherwise (discard) at `verify_packet` time rather than deferring rejection to `LatestValidatorVote::new_from_view`.
2. Alternatively/additionally, apply per-source-IP or per-connection rate limiting / QoS on the TPU-vote QUIC port comparable to the stake-weighted approach used for the regular TPU port, so unstaked senders cannot cheaply saturate the vote channel.

```rust
#[test]
fn test_fake_vote_shaped_packet_passes_reject_non_vote_gate() {
    use solana_message::Message;
    use solana_transaction::Transaction;
    use solana_keypair::Keypair;
    use solana_signer::Signer;
    use solana_hash::Hash;
    use solana_message::compiled_instruction::CompiledInstruction;

    let attacker = Keypair::new();
    // Legacy message, single instruction targeting the vote program,
    // with garbage (non-VoteInstruction) data.
    let message = Message::new_with_compiled_instructions(
        1,
        0,
        vec![attacker.pubkey(), solana_sdk_ids::vote::id()],
        Hash::default(),
        vec![CompiledInstruction::new(1, &[0xDE, 0xAD, 0xBE, 0xEF], vec![0])],
    );
    let mut tx = Transaction::new_unsigned(message);
    tx.sign(&[&attacker], Hash::default());

    let mut packet = BytesPacket::from_data(tx).unwrap();

    // Simulate the tpu-vote ingress path: reject_non_vote = true.
    let verified = verify_packet(&mut packet.as_mut(), /*reject_non_vote=*/ true, false);

    // Expect the fix: garbage vote-shaped data with no real VoteInstruction should be
    // rejected here (discarded before the vote channel), not merely later in banking stage.
    assert!(!verified, "garbage vote-shaped tx should not survive reject_non_vote sigverify gate");
    assert!(
        !packet.meta().is_simple_vote_tx(),
        "packet should not be classified SIMPLE_VOTE_TX without a decodable VoteInstruction"
    );
}
```
Current (pre-fix) behavior: `verified == true` and `packet.meta().is_simple_vote_tx() == true`, demonstrating the packet would be forwarded into `tpu_vote_sender` / `VOTE_CHANNEL_CAPACITY`, confirming the bypass described above.

```rust
fn is_simple_vote_transaction_view<D: TransactionData>(view: &SanitizedTransactionView<D>) -> bool {
    // vote could have 1 or 2 sigs; zero sig has already been excluded by sanitization.
    if view.num_signatures() > 2 {
        return false;
    }

    // simple vote should only be legacy message
    if !matches!(view.version(), TransactionVersion::Legacy) {
        return false;
    }

    // skip if has more than 1 instruction
    if view.num_instructions() != 1 {
        return false;
    }

    let mut instructions = view.instructions_iter();
    let Some(instruction) = instructions.next() else {
        return false;
    };
    if instructions.next().is_some() {
        return false;
    }

    let program_id_index = usize::from(instruction.program_id_index);
    let Some(program_id) = view.static_account_keys().get(program_id_index) else {
        return false;
    };

    *program_id == solana_sdk_ids::vote::id()
}
```

```rust
    fn try_send(&self, msg: T) -> std::result::Result<(), TrySendError<T>> {
        let Err(e) = self.sender.try_send(msg) else {
            return Ok(());
        };

        match e {
            // Prefer newer messages over older messages.
            TrySendError::Full(msg) => match self.receiver.try_recv() {
                Ok(older) => {
                    // Attempt to requeue the newer message.
                    // NB: if multiple senders are used, and another sender is faster than us to send() after we've popped `older`,
                    // our try_send() will fail with Full(msg), in which case we drop the new message.
                    self.sender.try_send(msg)?;
                    // Propagate the error _with the older message_.
                    Err(TrySendError::Full(older))
                }
                // Unlikely race condition -- it was just indicated that the channel is full.
                // Attempt to requeue the message.
                Err(TryRecvError::Empty) => self.sender.try_send(msg),
                // Unreachable in practice since we maintain a reference to both the sender and receiver.
                Err(TryRecvError::Disconnected) => unreachable!(),
            },
            // Unreachable in practice since we maintain a reference to both the sender and receiver.
            TrySendError::Disconnected(_) => unreachable!(),
        }
    }
```
