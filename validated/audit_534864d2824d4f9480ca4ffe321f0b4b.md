### Title
Unvalidated cache-freshness/completeness check when resolving MVCC manifest pointer allows stale-read and cross-request torn-state access - (File: internal/git/mvcc/cache.go)

### Summary
The Chainlink report's root cause is that a data feed's "latest" value (`latestRoundData()`) is consumed without verifying it is fresh/complete (no round-completeness or staleness check), so a stale value silently drives a downstream computation. Gitaly's MVCC read/write cache (`internal/git/mvcc/cache.go`, `internal/git/mvcc/storage_local.go`) has the same structural gap: the "latest manifest pointer" (the analog of the price feed's round data) is read once via `ReadManifestPointer`/`ReadManifest` and trusted as authoritative for the rest of the RPC, with no check that the returned pointer is itself fresh, that the manifest it names is complete relative to concurrent commits, or that a subsequently-referenced manifest file still exists on disk once used.

### Finding Description
In `LocalCache.prepare` (`internal/git/mvcc/cache.go:272-320`), when `hash == latestManifestPointer` the code calls: [1](#0-0) 
and immediately trusts the returned `rawPointer` as the canonical state to build `m.baseHash`/`m.baseManifest` and to warm reftable artifacts, exactly analogous to the report's pattern of consuming `latestRoundData()` without validating `answeredInRound`/`timestamp`.

`LocalStorage.ReadManifestPointer` (`internal/git/mvcc/storage_local.go:53-63`) simply does an `os.ReadFile` of the pointer file and trims a newline — there is no round/version/staleness metadata at all, no modification-time check, and no verification that the pointer file's content corresponds to a manifest that is still present on disk: [2](#0-1) 

Contrast this with `LocalStorage.Commit` (`internal/git/mvcc/storage_local.go:107-144`), which *does* perform a compare-and-swap by re-reading the pointer under a lock and rejecting the write if `current != baseHash`: [3](#0-2) 
This shows the codebase's own authors recognize that the pointer can race, yet the read path (`prepare`) that resolves the "latest" pointer for read-only accessor RPCs performs no equivalent staleness/consistency check — it is a bare, one-shot read that is fed straight into `GIT_MVCC_MANIFEST`/`GIT_MVCC_MANIFEST_PATH` environment variables that steer which Git artifacts (reftables, objects) subsequent git subprocesses will read (`internal/git/mvcc/cache.go:296-317`).

Additionally, `LocalCache.putNewArtifacts` at commit time re-opens the manifest by filename (`internal/git/mvcc/cache.go:433-476`) purely from local disk without re-validating the checksum encoded at manifest-parse time was still current for the actual base used to diff artifacts — the diffing logic (`baseSet` vs `newManifest.Paths`) assumes `m.baseManifest`, captured at `prepare()` time, is still an accurate reflection of the repository state that was used to compute `newHash`, with no re-validation against the environment at commit time beyond the CAS on the pointer file itself.

Although `ParseManifest` does validate a trailing SHA-256 checksum, path bounds, and known constants (`internal/git/mvcc/manifest.go:141-229`) — which is stronger integrity checking than the original Chainlink code — this only proves the manifest *file* is internally well-formed. It does not prove the *pointer* returned by `ReadManifestPointer` is fresh (i.e., not superseded by a newer commit that raced with this read), nor does it protect readers from being handed manifest content whose referenced reftables have since been garbage-collected between `ReadManifestPointer` and the artifact-warming step in `prepareArtifacts` (`internal/git/mvcc/cache.go:372-431`).

### Impact Explanation
An accessor RPC (read-only, e.g. ref resolution, upload-pack) that calls `Prepare`/`WaitUntilReady` can observe an inconsistent or superseded manifest pointer without any signal that a fresher pointer exists, analogous to the Oracle bug's "wrong `quoteAmount`" — here it manifests as returning results based on a torn or outdated repository snapshot to the calling gRPC client (potentially GitLab Rails or another Gitaly RPC) without any error, since there is no completeness/staleness check comparable to `answeredInRound >= roundID`. Because the MVCC backend is explicitly documented as experimental ("vibe coding" per `doc/mvcc_rpc_flow.md`) and only reachable when `ReferenceBackendMVCC` is used, the practical blast radius is currently limited, but the code path is reachable from ordinary read RPCs against MVCC-backed repositories without any privileged actor involved.

### Likelihood Explanation
Likelihood is moderate-to-low: the race window between `ReadManifestPointer` and completion of `prepareArtifacts`/`WaitUntilReady` is narrow but is explicitly a known, accepted race in Gitaly's other similar mechanism (the disk-cache design doc explicitly documents an analogous lockless race and calls it acceptable), so the MVCC pointer-read path inherits the same class of risk without inheriting that mechanism's mitigating short-TTL "latest" tracking with in-flight lease files (`doc/design_diskcache.md:63-96`). Triggering it requires only ordinary concurrent read/write traffic against an MVCC repository, not a privileged actor.

### Recommendation
Add explicit freshness/consistency validation when resolving the "latest" manifest pointer analogous to the recommended Chainlink fix (validate round completeness/staleness before trusting the value):
- Record a monotonically increasing sequence number or timestamp alongside the manifest pointer in `LocalStorage.ReadManifestPointer`, and reject/re-fetch if the artifacts referenced by the resolved manifest are found to be missing during `prepareArtifacts`, rather than silently treating a missing local file as "not yet fetched."
- Re-validate that `m.baseManifest` used for diffing in `putNewArtifacts` still corresponds to the state the pointer named at commit time, in addition to the existing CAS on the pointer file.
- Surface a distinguishable error (e.g., `ErrManifestPointerStale`) so that callers, similar to the Oracle fix's explicit `require` statements, can detect and retry rather than silently operating on a torn view.

### Proof of Concept
Not independently verified with a live race reproduction (this analysis is based on static code review of `internal/git/mvcc/cache.go`, `internal/git/mvcc/storage_local.go`, and `internal/git/mvcc/manifest.go`; the MVCC backend is guarded by `gittest.SkipWithoutMVCCGit(t)` in tests, indicating it requires a special Git build and is not enabled by default, which limits confidence in exploitability at index-review time). Conceptually:
1. Client A begins an accessor RPC; `Prepare()` calls `ReadManifestPointer` and observes pointer `H1`.
2. Concurrently, Client B's mutator RPC calls `Commit()`, which garbage-collects/replaces artifacts referenced only by `H1` once `H2` is durable (outside the code shown, but implied by the artifact-diffing model in `putNewArtifacts`).
3. Client A's `prepareArtifacts` for `H1`'s reftables can race against this transition; because there is no staleness check equivalent to the recommended `answeredInRound >= roundID`, Client A has no way to detect it is operating on a manifest pointer that is no longer the "canonical" one, and will proceed to build `GIT_MVCC_MANIFEST=H1` for git subprocesses regardless. func (m *LocalCache) prepare(ctx context.Context, hash string) (err error) {
```go
	// An empty hash means to fetch the latest pointer.
	if hash == latestManifestPointer {
		// Read the manifest pointer from the RemoteStorage
		rawPointer, err := m.rs.ReadManifestPointer(ctx, m.repositoryID)
		if err != nil {
			return fmt.Errorf("read manifest pointer: %w", err)
		}
		hash = rawPointer
	}

	manifest, err := m.prepareManifestFile(ctx, hash)
	if err != nil {
		return fmt.Errorf("prepare manifest file: %w", err)
	}

	// Warm the cache. We only care about reftables for now. Objects will
	// be taken care of at a later stage.
	err = m.prepareArtifacts(ctx, manifest.RefPaths())
	if err != nil {
		return fmt.Errorf("prepare artifacts: %w", err)
	}
```

```go
func (l *LocalStorage) ReadManifestPointer(_ context.Context, repositoryID string) (string, error) {
	pointerPath := filepath.Join(l.storageRoot, repositoryID, mvccCacheDir, manifestPointer)
	raw, err := os.ReadFile(pointerPath)
	if err != nil {
		return "", err
	}
	return strings.TrimSuffix(string(raw), "\n"), nil
}
```
