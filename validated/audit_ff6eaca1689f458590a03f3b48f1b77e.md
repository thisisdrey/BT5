### Title
Netrc "default" credentials are attached to every URL host without validation - ([File: tools/build_defs/repo/utils.bzl])

### Summary
The reported issue is a classic "missing zero-value check" bug: `InitializableOwnable.initOwner` accepts any address including the zero address as `_OWNER_` without validating it, silently creating an unusable/degenerate trust anchor. The structural analog in bazel is in `use_netrc` in [1](#0-0) , where the netrc "default" machine entry — stored under the empty-string sentinel key `""` — is used as a fallback credential source for **any** host that doesn't have an explicit `machine` entry, without validating that the host is one the credentials were meant for.

### Finding Description
`parse_netrc` intentionally maps the netrc `default` directive to the empty string key, since `""` "can never be a valid hostname": [2](#0-1) . Then in `use_netrc`, for every URL in the `urls` list, the host is extracted and looked up in the netrc dict; if not found, the code falls through to the default entry unconditionally: [3](#0-2) 
```
host = schemerest[1].split("/")[0].split(":")[0]
if host in netrc:
    authforhost = netrc[host]
elif "" in netrc:
    authforhost = netrc[""]
else:
    continue
```
There is no allow-list, scope check, or restriction tying the "default" credential entry to a specific host or origin — it is attached to *every* URL passed in, regardless of which host it targets. This is analogous to the zero-address bug: a special sentinel value (`""`/"default") is treated as valid for all recipients instead of being rejected or scoped.

`get_auth` (called from `http_archive`, `http_file`, `http_jar`) drives this: it resolves the netrc (either explicit `ctx.attr.netrc`, `NETRC` env var, or the user's `~/.netrc`) and calls `use_netrc(netrc, ctx.attr.urls, auth_patterns)` over the *entire* URL list configured for the repository rule [4](#0-3) . `http_archive`/`http_file` support multiple mirror URLs, and Bzlmod registries can supply additional `mirror_urls` (documented in `bazel_registry.json`/`source.json`) [5](#0-4) . Since `use_netrc` computes an `auth` dict keyed per-URL and attaches the same default login/password/token to every URL host that lacks a specific netrc entry, credentials intended as a generic/default fallback (e.g., for a corporate proxy or private mirror) get sent as `Authorization` headers to *any other host* named in the URL list — including a hostile mirror URL that an attacker controls (e.g. via an attacker-published/tampered registry `bazel_registry.json` mirror list, or a malicious secondary URL in a shared `urls = [...]` list).

### Impact Explanation
If a victim has a netrc "default" entry (a common pattern for blanket authentication, e.g. a corporate artifact proxy), and a repository rule or Bzlmod-resolved URL list includes an additional attacker-controlled or attacker-influenced mirror host, that host will receive the same default `Authorization` credentials without any host-scoping check. This is effectively credential exfiltration to an attacker-controlled host, matching the "credential exfiltration" acceptance criterion for this analysis. The blast radius depends on the sensitivity of the default netrc credential, but the design flaw — a global sentinel credential entry applied without host-scoping validation — is present regardless.

### Likelihood Explanation
Likelihood is moderate: it requires (a) a user/CI environment with a netrc "default" entry configured, and (b) a URL list that includes a host controlled or served by an attacker (achievable via a malicious mirror URL added to `bazel_registry.json`'s `mirrors` array served by an untrusted or compromised registry, or via a repo rule with a mixed `urls` list where one entry is attacker-supplied). The `.netrc` "default" directive is a real and documented feature exercised in bazel's own tests [6](#0-5) , so the mechanism is not hypothetical, but reliance on a "default" netrc entry combined with untrusted mirrors is a narrower precondition than a fully generic MITM scenario.

### Recommendation
Do not fall back to the empty-string "default" netrc entry for arbitrary hosts without additional validation. At minimum:
- Warn (or require explicit opt-in) when a "default" netrc entry's credentials would be attached to a host not explicitly listed in the netrc file.
- Consider scoping the default entry's use to only the primary/first URL of `url`/`urls`, not to every mirror host resolved from external, potentially attacker-influenced sources (like Bzlmod registry `mirrors`).
- Emit a clear diagnostic identifying which host received the "default" credentials, similar to the existing password-missing warning at [7](#0-6) .

### Proof of Concept
Not independently reproduced in this analysis (no execution environment available for a JUnit/shell integration test). A `src/test/shell/bazel/starlark_repository_test.sh`-style test could be constructed by: (1) creating a `.netrc` with only a `default` machine block (no per-host password), (2) invoking `http_archive`/`http_file` with `urls = ["https://trusted.example/x", "https://attacker.example/x"]`, and (3) asserting that the resulting `auth` dict computed by `use_netrc` contains an `Authorization`/basic-auth entry for `attacker.example`, matching the test scaffolding already present in [8](#0-7) .

**Uncertainty note:** I was not able to fully trace how the native Java HTTP downloader (`HttpDownloader`/`HttpConnector`) consumes this `auth` dict to confirm there's no additional host-matching guard applied downstream of `use_netrc` before the `Authorization` header is actually sent — the index did not surface a `NetrcParser`/native netrc-credentials Java class for cross-verification. If such a downstream check exists and re-validates the host against the netrc entry before sending, it would mitigate this finding; based on available evidence, the Starlark-level `use_netrc` logic itself performs no such validation.

```text
def use_netrc(netrc, urls, patterns):
    """Compute an auth dict from a parsed netrc file and a list of URLs.

    Args:
      netrc: a netrc file already parsed to a dict, e.g., as obtained from
        read_netrc
      urls: a list of URLs.
      patterns: optional dict of url to authorization patterns

    Returns:
      dict suitable as auth argument for ctx.download; more precisely, the dict
      will map all URLs where the netrc file provides login and password to a
      dict containing the corresponding login, password and optional authorization pattern,
      as well as the mapping of "type" to "basic" or "pattern".
    """
    auth = {}
    for url in urls:
        schemerest = url.split("://", 1)
        if len(schemerest) < 2:
            continue
        if not (schemerest[0] in ["http", "https"]):
            # For other protocols, bazel currently does not support
            # authentication. So ignore them.
            continue
        host = schemerest[1].split("/")[0].split(":")[0]
        if host in netrc:
            authforhost = netrc[host]
        elif "" in netrc:
            authforhost = netrc[""]
        else:
            continue
```
