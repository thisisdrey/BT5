### Title
`RewardsDistributor._calculateTokenDelta` treats an uninitialized `accountIndexOf` (0) as a real index instead of `INITIAL_INDEX`, crediting the account its full token balance as rewards - ([File: contracts/RewardsDistributor.sol](contracts/RewardsDistributor.sol))

### Summary
The Rust advisory concerns reading uninitialized memory; the Solidity analog is reading an uninitialized storage mapping (`accountIndexOf`) and treating its default `0` as a meaningful reward index. `RewardsDistributor` uses `INITIAL_INDEX = 1e18` as the baseline index, but the "uninitialized account" fallback in `_calculateTokenDelta` only triggers when `_tokenIndex > INITIAL_INDEX`. When the global token index is still exactly `INITIAL_INDEX`, an account whose `accountIndexOf` was never written gets `_deltaIndex = INITIAL_INDEX - 0 = 1e18`, so `_tokensDelta = balance.wadMul(1e18) = balance` — i.e., rewards equal to its entire DepositToken/DebtToken balance are accrued and become claimable.

### Finding Description
- `_calculateTokenDelta` reads `accountIndexOf[token_][account_]` (defaults to `0` for any account that was never checkpointed) and only substitutes `INITIAL_INDEX` when `_tokenIndex > INITIAL_INDEX` [1](#0-0) .
- When a reward token is first activated, `_updateTokenSpeed` stores `TokenState({index: INITIAL_INDEX, timestamp: block.timestamp})` — the index equals `INITIAL_INDEX`, not above it [2](#0-1) .
- While the stored index remains `INITIAL_INDEX` (same block as activation, or later blocks where `speed * Δt` is too small for `wadDiv` to yield a non-zero ratio), `_updateTokenIndex` leaves `tokenStates[token_].index == INITIAL_INDEX` [3](#0-2) .
- `claimRewards` and the publicly callable `updateBeforeMintOrBurn` both proceed whenever `tokenStates[token_].index > 0` (true for `INITIAL_INDEX`) and then call `_updateTokensAccruedOf`, which writes the inflated `tokensAccruedOf` [4](#0-3) [5](#0-4) .
- `_transferRewardIfEnoughTokens` then pays out `tokensAccruedOf[account_]` from the distributor's reward-token balance [6](#0-5) .

### Impact Explanation
An attacker with any DepositToken or DebtToken balance receives `tokensAccruedOf = balance` (in the reward token's 1e18-scaled terms the delta index is 1e18, so `wadMul` returns the balance itself). They can drain the RewardsDistributor's entire reward-token balance — stealing yield owed to all other depositors/borrowers — by simply holding a balance larger than the contract's reward reserves. This is theft of unclaimed yield / reward funds.

### Likelihood Explanation
- The vulnerable window opens every time `updateTokenSpeed(s)` activates a new reward token, which is routine governance operation — no malicious admin needed.
- In the same block/timestamp as activation, `deltaTimestamps == 0` so the index can never advance past `INITIAL_INDEX`; an attacker can front-run or immediately follow the activation with `updateBeforeMintOrBurn(depositToken, attacker)` (callable by anyone) or `claimRewards(attacker, [token])`.
- The window can also persist across many blocks: `_newIndex` only grows if `_tokensAccrued.wadDiv(_totalSupply) > 0`; with a small `speed` or large supply, `INITIAL_INDEX` persists while only the timestamp advances.
- Attacker needs only an existing deposit/debt balance (obtainable via normal `DepositToken.mint`/deposit or a flash-funded position in the same transaction via `Operator.execute`), satisfying the unprivileged-attacker model. No modifier (`nonReentrant`, `onlyIfDistributorExists`, pause flags) blocks the path.

### Recommendation
In `_calculateTokenDelta`, treat a zero `accountIndexOf` as `INITIAL_INDEX` unconditionally (or as the current `_tokenIndex` if lower), e.g. `if (_accountIndex == 0) _accountIndex = _tokenIndex > INITIAL_INDEX ? INITIAL_INDEX : _tokenIndex;`. This removes the boundary case where `_tokenIndex == INITIAL_INDEX` produces a `1e18` delta for uninitialized accounts.

### Proof of Concept
```solidity
// Hardhat fork test sketch
// 1. Attacker deposits underlying into a DepositToken so balanceOf(attacker) = B.
await depositToken.connect(attacker).deposit(amount); // or via Pool deposit

// 2. Governor activates a reward speed for that DepositToken (normal op).
await rewardsDistributor.connect(governor).updateTokenSpeed(depositToken.address, speed);
//    -> tokenStates[depositToken].index == INITIAL_INDEX, timestamp == now

// 3. Same block (or while accrued ratio rounds to 0):
//    attackerIndex == 0 and tokenIndex == INITIAL_INDEX -> fallback skipped.
await rewardsDistributor.connect(anyone).updateBeforeMintOrBurn(depositToken.address, attacker.address);

// 4. tokensAccruedOf[attacker] == B (wadMul(delta=1e18) returns balance).
expect(await rewardsDistributor.tokensAccruedOf(attacker.address)).to.eq(B);

// 5. Claim drains the distributor's reward-token balance.
await rewardsDistributor.connect(attacker).claimRewards(attacker.address, [depositToken.address]);
expect(await rewardToken.balanceOf(attacker.address)).to.be.gt(0); // = min(B, contract balance)
```
