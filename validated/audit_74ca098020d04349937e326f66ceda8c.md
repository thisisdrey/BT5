### Title
Gossip vote signature verification result is discarded, allowing unverified/invalid-signature votes to reach `GossipVerifiedVoteBatch` - ([File: core/src/sigverify.rs])

### Summary
`SigVerifyWorkerPool::run_gossip_task` calls `sigverify::ed25519_verify_serial(&mut work.batch, true, false)` purely for its side effect of marking packets, but never inspects the returned discard count, never checks `packet.meta().discard()` on the resulting batch, and unconditionally forwards the (possibly still-invalid) batch to `verified_vote_sender` as a `GossipVerifiedVoteBatch`. This differs from the sibling `run_transaction_task` path, which explicitly checks `num_valid_packets == 0` and filters/returns before sending downstream.

### Finding Description
In `core/src/sigverify.rs`, `run_gossip_task` is: [1](#0-0) 

Compare this with `run_transaction_task`, which after calling `ed25519_verify_serial` explicitly counts valid packets and bails out if none are valid before sending to the banking stage: [2](#0-1) 

`run_gossip_task` has no equivalent check. `ed25519_verify_serial` operates in place on `PacketBatch`, setting each packet's `meta().discard()` bit for packets that fail verification, but does not remove or otherwise flag them at the batch level in a way that is enforced by the caller. Since `run_gossip_task` ignores the discard bits and sends `work.batch` straight into `GossipVerifiedVoteBatch` via `verified_vote_sender.send(...)`, any packet with an invalid/corrupted signature that entered via `GossipSigVerifier::send_votes_to_worker_pool` → `GossipVerifyTask` will still be forwarded to whatever consumes `GossipVerifiedVoteBatch` (the gossip vote path feeding `cluster_info_vote_listener`), with only the `discard` metadata (unchecked by the caller) indicating an issue.

### Impact Explanation
This is a signature verification bypass in the gossip vote ingestion pipeline: an invalid-signature "vote" transaction can reach downstream vote-processing logic tagged with `GossipVerifiedVoteBatch`, which its name and position in the pipeline (post-sigverify-worker) imply is signature-verified. This falls into the "verification bypass" bounty category. However, the actual severity depends on whether the downstream consumer (`cluster_info_vote_listener.rs`) itself re-checks `meta().discard()` before trusting the packet's parsed vote content — I was unable to fully confirm this in the available index within the tool-call budget, so the ultimate reachability of unverified data into consensus-affecting logic (e.g., optimistic confirmation, vote tracking) is not fully verified from this trace alone; it rests specifically on the gap identified in `run_gossip_task`.

### Likelihood Explanation
Precondition per the prompt requires attacker ability to inject a vote-shaped `Transaction` into the gossip verify worker queue via `GossipSigVerifier::send_votes_to_worker_pool`. That function is reachable from the gossip vote ingestion path (`crds`/gossip push/pull vote handling) which processes votes gossiped by any cluster peer, including low-stake or the sender itself claiming a vote-shaped payload; the queue itself does no signature pre-check before enqueueing — verification is deferred entirely to `run_gossip_task`. Given the missing check is unconditional and deterministic, exploitation is fully repeatable with a single crafted transaction with a corrupted `Ed25519` signature.

### Recommendation
In `run_gossip_task`, after calling `ed25519_verify_serial`, check `sigverify::count_valid_packets` (or iterate `work.batch.iter()` and check `packet.meta().discard()`), and only forward to `verified_vote_sender` if the packet is verified; otherwise drop it (mirroring the `num_valid_packets == 0` early return used in `run_transaction_task`).

    fn run_gossip_task(
        mut work: GossipVerifyTask,
        verified_vote_sender: &Sender<GossipVerifiedVoteBatch>,
    ) -> bool {
        // Gossip votes are legacy Transaction values, not tx-v1 packets.
        sigverify::ed25519_verify_serial(&mut work.batch, true, false);

        if let Err(err) = verified_vote_sender.send(GossipVerifiedVoteBatch {
            transaction: work.transaction,
            packet_batch: work.batch,

            debug!("gossip sigverify response send failed: {err:?}");

        true
    }
