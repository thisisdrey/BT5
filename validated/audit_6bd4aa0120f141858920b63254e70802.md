### Title
Object directory path validation is bypassed for any path whose base directory is literally named `quarantine`/`tmp_objdir-*`, allowing cross-repository object-directory access via `GitObjectDirectory` - ([File: internal/git/localrepo/paths.go])

### Summary
`Repo.ObjectDirectoryPath` is supposed to prove that a client-supplied `GitObjectDirectory` (an attacker/Rails-controllable field of the `Repository` proto, propagated through the object-quarantine flow described in `doc/object_quarantine.md`) both (a) stays inside the storage root and (b) actually belongs to the calling repository (either as a subdirectory of the repo or as a quarantine directory whose prefix matches that specific repo). Instead of enforcing (b) with the same rigor for every code path, the function substitutes a name-based heuristic (`baseDir == "quarantine"` or `parentDir == "quarantine" && strings.HasPrefix(baseDir, "tmp_objdir")`) for the real ownership check, and when that heuristic matches it skips the per-repository prefix validation entirely. This is analogous to the ERC4626 bug where the code used the wrong variable (`amount` instead of `shares`) to perform a security-relevant action — here the code uses the wrong *signal* (directory name heuristic) instead of the correctly-scoped variable (the repo-specific quarantine prefix) to decide whether an object directory belongs to the caller's repository.

### Finding Description
`ObjectDirectoryPath` in [1](#0-0)  first validates that `filepath.Join(repoPath, objectDirectoryPath)` is within the storage root via `storage.ValidateRelativePath(storagePath, ...)`. That check only proves the path is *somewhere* under the storage — not that it belongs to the target repository. The function then derives `parentDir`/`baseDir` from the resulting relative path and computes: [2](#0-1) 

If `isTransactionQuarantineDir` is true, the block that would otherwise perform the actual ownership check is skipped: [3](#0-2) 

That skipped block is the only place that ties the quarantine directory to *this specific repository*, via `expectedQuarantinePrefix := filepath.Join(tempDir, storage.QuarantineDirectoryPrefix(repo))` (which incorporates the repo's own relative path, see [4](#0-3) -scoped `QuarantineDirectoryPrefix`). When `isTransactionQuarantineDir` short-circuits this check, the only remaining guarantee is that the path is (1) inside the storage root and (2) its final path component happens to be named `quarantine`, or its parent is named `quarantine` and the leaf starts with `tmp_objdir`. Nothing ties the directory to the caller's own repository or to a legitimate quarantine actually created for this request.

`GitObjectDirectory`/`GitAlternateObjectDirectories` are exactly the fields that Rails echoes back to Gitaly during the object-quarantine handshake documented in [5](#0-4) , and the existing regression tests explicitly acknowledge that this value is attacker/Rails-supplied and must be checked against the calling repo, e.g. the "different relative path" test that intentionally swaps two repositories' quarantine directories and expects a rejection: [6](#0-5) 

That test only covers the case where neither swapped path ends in a name matching the `isTransactionQuarantineDir` heuristic (both are real quarantine dirs created by `quarantine.New`, whose base directory is a random tempdir name, not literally `quarantine`). It does not cover the case where a caller supplies a `GitObjectDirectory` value crafted so that its base directory literally equals `quarantine` (or `<something>/quarantine/tmp_objdir-XXXX`) but points at a directory belonging to a different repository or an arbitrary location under the storage root (e.g. another repo's `tx-state/quarantine` directory, matching the pattern exercised in the "repository quarantined by transaction manager" test at [7](#0-6) , but pointed at a foreign repository's transaction quarantine path instead of the caller's own).

### Impact Explanation
`ObjectDirectoryPath` gates access for the `GetObjectDirectorySize` RPC [8](#0-7) , which is used by Rails as part of push-size/quota accounting during the pre-receive access-check flow. A malicious or compromised caller of this RPC (Rails proxies client-controlled quarantine metadata straight through) could point `GitObjectDirectory` at a directory belonging to a completely different repository's quarantine/transaction state, as long as its terminal path segment is named `quarantine` (or matches the `tmp_objdir` pattern). Because the repo-specific-prefix check is skipped, Gitaly will happily walk and sum the size of that foreign directory and report it back as if it were the caller's own quarantine size. This breaks the intended repo-scoping invariant of quarantine-directory access and enables cross-repository disk-content disclosure (directory sizes, and by extension confirmation of the existence/size of another repository's in-flight push objects) — the same class of "check one thing, but act on an unrelated, less-verified quantity" flaw as the ERC4626 report, applied to storage-path/argument validation instead of asset accounting.

### Likelihood Explanation
Reachability is high in principle: `GitObjectDirectory` and `GitAlternateObjectDirectories` are populated end-to-end from data Rails passes back from the client-visible pre-receive hook payload, and `GetObjectDirectorySize` is specifically designed to be invoked with such attacker/Rails-influenced quarantine paths (as shown by the dedicated `TestGetObjectDirectorySize_quarantine` suite). However, exploitation requires the caller to be able to supply a `GitObjectDirectory` value whose base directory literally is `quarantine`/`tmp_objdir-*` while resolving (after `storage.ValidateRelativePath` against the *storage* root, not the repo) to a directory outside the caller's own repository/temp-dir prefix — for example another repository's `tx-state/quarantine` transaction directory. Whether an ordinary, unprivileged Gitaly client (as opposed to Rails/Praefect, which are treated as trusted intermediaries) can supply this field directly, or whether it is exclusively derived/rewritten server-side before reaching this function, could not be fully confirmed from the indexed code; this determines whether the primitive is exploitable end-to-end from an "ordinary user" RPC or only from a compromised/trusted Rails leg. Given the explicit test coverage acknowledging the security intent of this exact check, this is assessed as a real weakness in the defense-in-depth logic, but likelihood of a fully unprivileged exploitation path is uncertain without confirming the callers permitted to set `GitObjectDirectory` freely.

### Recommendation
Do not treat "path ends in a directory named `quarantine`/`tmp_objdir-*`" as sufficient proof of ownership. Always additionally verify that the resolved path is contained under `filepath.Join(tempDir, storage.QuarantineDirectoryPrefix(repo))` (the repo-specific prefix) — i.e., merge the `isTransactionQuarantineDir` fast-path into, rather than as a bypass of, the ownership-prefix check at [9](#0-8) . Concretely, replace the heuristic short-circuit with a check that the relative object directory path either (a) is under the repo's own `repoPath`, or (b) has the `expectedQuarantinePrefix` for *this* repo, computed unconditionally rather than only in the `!isTransactionQuarantineDir` branch.

### Proof of Concept
Conceptual PoC (not run against a live instance, derived from existing test scaffolding):
1. Set up two repositories, `repoA` (attacker-controlled) and `repoB` (victim), in the same storage.
2. Trigger a transaction-manager quarantine for `repoB` so a directory such as `<storage>/tx-state/quarantine` (or similarly named) is created and contains objects — mirroring the setup in [7](#0-6) .
3. As the caller for `repoA`, issue a `GetObjectDirectorySize` request with `Repository.RelativePath` set to `repoA`'s relative path but `GitObjectDirectory` crafted as a relative path from `repoA` to `repoB`'s `tx-state/quarantine` directory (e.g. `../../repoB/tx-state/quarantine`), and `GitAlternateObjectDirectories: ["objects"]`.
4. Because the final path component is exactly `quarantine`, `isTransactionQuarantineDir` becomes true in `ObjectDirectoryPath`, and the block that would check the path against `repoA`'s own `expectedQuarantinePrefix` is skipped. Only the storage-root containment check (`storage.ValidateRelativePath(storagePath, ...)`) applies, which `repoB`'s quarantine path still satisfies since it is under the same storage.
5. The RPC returns the size of `repoB`'s quarantine directory to the caller of `repoA`, demonstrating cross-repository quarantine-directory access instead of the intended same-repository-only scoping enforced by `expectedQuarantinePrefix`.

// ObjectDirectoryPath returns the full path of the object directory. The errors returned are gRPC
// errors with relevant error codes and should be passed back to gRPC without further decoration.
func (repo *Repo) ObjectDirectoryPath(ctx context.Context) (string, error) {
	repoPath, err := repo.Path(ctx)
	if err != nil {
		return "", err
	}

	objectDirectoryPath := repo.GetGitObjectDirectory()
	if objectDirectoryPath == "" {
		return "", structerr.NewInvalidArgument("object directory path is not set")
	}

	storagePath, err := repo.locator.GetStorageByName(ctx, repo.GetStorageName())
	if err != nil {
		return "", fmt.Errorf("get storage by name: %w", err)
	}

	// Ensure the path points somewhere in the storage.
	relativeObjectDirectoryPath, err := storage.ValidateRelativePath(storagePath, filepath.Join(repoPath, objectDirectoryPath))
	if err != nil {
		return "", structerr.NewInvalidArgument("validate relative path: %w", err)
	}

	parentDir := filepath.Base(filepath.Dir(relativeObjectDirectoryPath))
	baseDir := filepath.Base(relativeObjectDirectoryPath)
	isTransactionQuarantineDir := (baseDir == "quarantine") || ((parentDir == "quarantine") && strings.HasPrefix(baseDir, "tmp_objdir"))

	// Transactions quarantine a repository by pointing the object directory to a 'quarantine' named
	// directory in the transaction's temporary directory. If the base directory is `quarantine`,
	// Git push may apply an additional layer of quarantine such as `/quarantine/tmp_objdir-incoming-Gbc29N`
	// so we don't assert the `/quarantine` being the last element of the path. We thus also check for
	// whether the parent directory is in `quarantine` and whether the base directory has the expected
	// `tmp_objdir` suffix.

func (s *server) GetObjectDirectorySize(ctx context.Context, in *gitalypb.GetObjectDirectorySizeRequest) (*gitalypb.GetObjectDirectorySizeResponse, error) {
	repository := in.GetRepository()
	if err := s.locator.ValidateRepository(ctx, repository); err != nil {
		return nil, structerr.NewInvalidArgument("%w", err)
	}
	repo := s.localRepoFactory.Build(repository)

	path, err := repo.ObjectDirectoryPath(ctx)
	if err != nil {
		return nil, err
	}
	// path is the objects directory path, not repo's path
	sizeInBytes, err := dirSizeInBytes(path, snapshot.NewDefaultFilter(ctx))
	if err != nil {
		return nil, fmt.Errorf("calculating directory size: %w", err)
	}

	return &gitalypb.GetObjectDirectorySizeResponse{Size: sizeInBytes / 1024}, nil
}
