### Title
Delayed OFT mint can exhaust the destination bridge cap and freeze user funds - ([File: contracts/ProxyOFT.sol](contracts/ProxyOFT.sol))

### Summary
`ProxyOFT._debitFrom` burns the sender’s synthetic tokens on the source chain before the destination message is delivered. [1](#0-0)   
The corresponding destination mint is evaluated only when the delayed LayerZero message executes, and `SyntheticToken._mint` can then revert if intervening inbound transfers consumed `maxBridgedInSupply`. [2](#0-1) [3](#0-2)   
The failed message is retained for retry, but the source-chain tokens remain burned and no destination tokens are minted until the net bridged-in supply later falls below the cap. [4](#0-3) [5](#0-4) 

### Finding Description
A user calls `ProxyOFT.sendFrom`, which sends a `PT_SEND` payload after `_debitFrom` has already burned the specified balance. [6](#0-5) [7](#0-6)   
The source-side checks validate only that the caller owns the tokens, global bridging is active, and the destination route is supported; they do not reserve capacity under the destination’s `maxBridgedInSupply`. [1](#0-0)   
When the destination eventually receives the message, `_sendAck` calls `_creditTo`, which calls `SyntheticToken.mint`. [8](#0-7) [2](#0-1)   
For a mint initiated by `ProxyOFT`, `_mint` increments `totalBridgedIn` and reverts whenever `bridgedInSupply()` would exceed `maxBridgedInSupply`. [3](#0-2)   
Because `bridgedInSupply` is the live net value `totalBridgedIn - totalBridgedOut`, unrelated inbound bridge messages delivered between initiation and execution can make a previously admissible transfer invalid. [9](#0-8)   
`NonblockingLzAppUpgradeable._blockingLzReceive` catches that revert and stores only the payload hash, leaving the source burn final but the destination credit absent. [4](#0-3)   
`retryMessage` deletes the stored hash before re-executing the same message, so a retry while the cap is still saturated reverts and records the message again through the outer LayerZero receive path only if invoked there; direct repeated public retries must restore the stored hash or be routed through `lzReceive` to preserve the same retry state. [5](#0-4) 

### Impact Explanation
The victim experiences a temporary freezing of funds: the token balance is burned on the source chain, while no corresponding balance exists on the destination chain. [10](#0-9)   
The tokens cannot be returned through an automatic refund path because `_send` has no failure-compensation logic and the payload hash merely permits future execution of the same mint. [7](#0-6) [5](#0-4)   
Recovery requires enough bridged-out volume on the destination chain to lower `bridgedInSupply`, or a later configuration change raising `maxBridgedInSupply`; neither action is under the victim’s direct control after the source tokens are burned. [11](#0-10) [12](#0-11) 

### Likelihood Explanation
Any unprivileged user holding or acquiring the synthetic asset on a supported source chain can consume the destination’s remaining inbound bridge capacity by calling `sendFrom` before a delayed victim message executes. [1](#0-0) [6](#0-5)   
The attack is most practical when `maxBridgedInSupply - bridgedInSupply()` is small relative to the victim’s transfer or when ordinary bridge congestion can close the remaining headroom during LayerZero delivery. [11](#0-10)   
No malicious LayerZero endpoint is required because normal asynchronous ordering can deliver the attacker’s earlier message before the victim’s later message. [4](#0-3) 

### Recommendation
Reserve destination-side bridge capacity at debit time, include a source-side refund for failed credits, or add a recovery path that credits the user without treating the failed transfer as new net inbound supply after an authenticated timeout. [10](#0-9)   
At minimum, expose the destination headroom in quoting/UI and provide a canonical retry path that preserves `failedMessages` until the destination mint succeeds. [11](#0-10) [5](#0-4) 

### Proof of Concept
The following Foundry fork-test outline demonstrates the state transition using the deployed source and destination `ProxyOFT`/`SyntheticToken` contracts and their normal LayerZero endpoints.

```solidity
// test/foundry/poc/DelayedOftCap.t.sol
function testDelayedBridgeInvalidatedByInboundCap() public {
    uint256 victimAmount = 1 ether;

    uint256 dstFork = vm.createFork(DST_RPC);
    uint256 srcFork = vm.createFork(SRC_RPC);

    // Destination: determine remaining inbound headroom.
    vm.selectFork(dstFork);
    SyntheticToken dstSynth = SyntheticToken(DST_SYNTH);
    ProxyOFT dstOft = ProxyOFT(DST_OFT);
    uint256 headroom =
        dstSynth.maxBridgedInSupply() - dstSynth.bridgedInSupply();
    vm.assume(headroom >= victimAmount);

    // Source: attacker first sends enough tokens to consume all headroom.
    // Victim then sends victimAmount while headroom still appears sufficient.
    vm.selectFork(srcFork);
    SyntheticToken srcSynth = SyntheticToken(SRC_SYNTH);
    ProxyOFT srcOft = ProxyOFT(SRC_OFT);

    deal(address(srcSynth), attacker, headroom);
    deal(address(srcSynth), victim, victimAmount);

    vm.prank(attacker);
    srcOft.sendFrom{value: attackFee}(
        attacker,
        DST_LZ_ID,
        attacker,
        headroom
    );

    vm.prank(victim);
    srcOft.sendFrom{value: victimFee}(
        victim,
        DST_LZ_ID,
        victim,
        victimAmount
    );

    // Victim's source funds are already burned.
    assertEq(srcSynth.balanceOf(victim), 0);

    // Deliver the earlier attacker packet first through the normal endpoint.
    vm.selectFork(dstFork);
    deliverLzPacket(attackerPacket);
    assertEq(dstSynth.bridgedInSupply(), headroom);

    // Deliver the delayed victim packet. The credit reverts and is cached.
    uint256 victimDstBefore = dstSynth.balanceOf(victim);
    deliverLzPacket(victimPacket);

    assertEq(dstSynth.balanceOf(victim), victimDstBefore);
    assertEq(
        dstOft.failedMessages(
            SRC_LZ_ID,
            abi.encodePacked(SRC_OFT),
            victimNonce
        ),
        keccak256(victimPayload)
    );

    // While the inbound cap remains saturated, the same mint cannot execute.
    vm.expectRevert(SurpassMaxBridgingSupply.selector);
    deliverLzPacketAgain(victimPacket);

    // Funds remain burned on source and absent on destination until
    // bridgedOutSupply rises enough or the cap is increased.
}
```

The critical assertion is that the source `_debitFrom` has already burned `victimAmount`, while the destination `_creditTo` reverts solely because `totalBridgedIn` changed after the source transaction was initiated. [10](#0-9) [3](#0-2)

    function retryMessage(uint16 _srcChainId, bytes calldata _srcAddress, uint64 _nonce, bytes calldata _payload) public payable virtual {
        // assert there is message to retry
        bytes32 payloadHash = failedMessages[_srcChainId][_srcAddress][_nonce];
        require(payloadHash != bytes32(0), "NonblockingLzApp: no stored message");
        require(keccak256(_payload) == payloadHash, "NonblockingLzApp: invalid payload");
        // clear the stored message
        failedMessages[_srcChainId][_srcAddress][_nonce] = bytes32(0);
        // execute the message. revert if it fails again
        _nonblockingLzReceive(_srcChainId, _srcAddress, _nonce, _payload);
        emit RetryMessageSuccess(_srcChainId, _srcAddress, _nonce, payloadHash);
