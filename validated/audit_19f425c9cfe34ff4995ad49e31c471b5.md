### Title
StackerDB chunk signatures are not bound to the target smart contract, allowing cross-StackerDB replay of validly-signed chunks - (File: `libstackerdb/src/libstackerdb.rs`)

### Summary
`SlotMetadata::auth_digest()` computes the signed digest for a StackerDB chunk from only `slot_id`, `slot_version`, and `data_hash` — it never includes the target smart-contract identifier (the StackerDB "site"). Because multiple StackerDB contracts share identical `(signer → slot_id)` assignments (e.g. all `.signers-<N>-<message_id>` contracts for a given signer set use the same slot ordering), a chunk validly signed by a signer for one StackerDB contract can be replayed verbatim into a different StackerDB contract that the same signer also owns the same `slot_id` in. This is the direct analog of the `rails_multisite` flaw, where a secret/signature was not scoped per "site," allowing cross-site reuse.

### Finding Description
`SlotMetadata::auth_digest()` [1](#0-0)  only commits to `slot_id`, `slot_version`, and `data_hash`. The verification routine `SlotMetadata::verify()` recovers the public key from this same digest and compares its hash to the expected `principal` [2](#0-1) . Nowhere in the signed material is the `smart_contract_id` (the StackerDB the chunk is destined for) included.

On the receive path, `StackerDBSync::validate_received_chunk` looks up the expected signer address *for the given `smart_contract_id` and `slot_id`* via `get_slot_signer`, then calls `slot_metadata.verify(&addr)` [3](#0-2) . Since the digest is contract-agnostic, this check only confirms "some principal who owns this slot_id in *this* DB produced this signature" — it does not confirm the signature was produced *for this DB*.

Critically, the on-chain `.signers` boot contract assigns the *same* `(signer, num-slots)` ordering across every `.signers-<cycle_mod>-<message_id>` StackerDB contract for a given signer set: `stackerdb-get-signer-slots-page` returns identical `stackerdb-signer-slots-0`/`-1` lists for all "page"/message-id contracts [4](#0-3) , and this is asserted by the test that iterates `signer_set in 0..2` and `message_id in 0..SIGNER_SLOTS_PER_USER`, confirming every message-id contract returns the exact same signer/slot list [5](#0-4) . This means the same signer occupies the *same numeric slot_id* across all of its StackerDB contracts within a signer set.

Consequently, if that signer ever produces a chunk with a given `(slot_id, slot_version, data)` for contract A, the exact wire tuple `(slot_id, slot_version, signature, data)` — trivially observable by any peer since StackerDB chunks are broadcast unencrypted over gossip and served via the public HTTP `POST /stackerdb_chunks` / `PostStackerDBChunk` endpoints — will also pass `verify()` for contract B, provided B's stored version for that slot is lower and the chunk fits B's `chunk_size`/`max_writes` config. `try_replace_chunk` and `validate_received_chunk` perform no contract-binding check beyond looking up "who owns slot X in this DB," so the replayed chunk is accepted and stored/relayed as if it were legitimately authored for contract B.

### Impact Explanation
An unprivileged network observer who captures any legitimately-signed StackerDB chunk (freely obtainable, since these are broadcast/publicly served) can replay it into a *different* StackerDB namespace owned by the same signer, causing the node to store and further gossip data as canonical content of a StackerDB contract it was never intended for. Downstream consumers (e.g. `stacks-signer`, `StackerDBListener`) that key their message-type parsing off of which contract/slot the chunk arrived on [6](#0-5)  would then process attacker-selected, out-of-context bytes as if authentically produced for that context — a "non-canonical data served/stored as canonical" condition, and unauthenticated cross-context write propagated network-wide via normal StackerDB replication/broadcast.

### Likelihood Explanation
Exploitation requires no key material and no privileged role — only observing one legitimately-broadcast chunk (which is inherent to the protocol) and resubmitting it (via HTTP `POST /stackerdb_chunks` or p2p `StackerDBPushChunk`) targeting a sibling contract where the same signer holds the same `slot_id`. This condition is structurally guaranteed today by the `.signers` contract's identical slot assignment across message-id contracts, making the precondition (`same slot_id owned by same signer in ≥2 contracts`) always true in the current signer StackerDB deployment.

### Recommendation
Bind the signed digest to the target StackerDB context by including the `smart_contract_id` (and ideally chain/network identifiers) inside `SlotMetadata::auth_digest()`, so a chunk signature is only valid for the specific StackerDB it was created for. This requires a coordinated wire/protocol version bump since it changes what byte string signers must sign.

### Proof of Concept
1. Signer `S` owns `slot_id = 3` in both `.signers-0-0` and `.signers-0-1` (per the identical slot-list assignment shown by `signers_db_get_slots`).
2. `S` legitimately signs and publishes chunk `(slot_id=3, slot_version=5, sig, data)` to `.signers-0-0`.
3. Attacker observes this chunk (via public StackerDB HTTP/gossip) and re-submits the identical `(slot_id=3, slot_version=5, sig, data)` tuple, but targets `.signers-0-1` instead, provided `.signers-0-1`'s current stored version for slot 3 is `< 5`.
4. `validate_received_chunk`/`try_replace_chunk` for `.signers-0-1` looks up slot 3's owner (`S`), calls `slot_metadata.verify(&S)`, which succeeds because `auth_digest()` never referenced which contract this was signed for — the chunk is accepted and stored under `.signers-0-1`, then relayed to the node's peers as canonical data for that contract.     /// Get the digest to sign that authenticates this chunk data and metadata
    fn auth_digest(&self) -> Sha512Trunc256Sum {
        let mut hasher = Sha512_256::new();
        hasher.update(self.slot_id.to_be_bytes());
        hasher.update(self.slot_version.to_be_bytes());
        hasher.update(self.data_hash.0);
        Sha512Trunc256Sum::from_hasher(hasher)
    }

    /// Sign this slot metadata, committing to slot_id, slot_version, and
    /// data_hash.  Sets self.signature to the signature.
    /// Fails if the underlying crypto library fails
    pub fn sign(&mut self, privkey: &StacksPrivateKey) -> Result<(), Error> {
        let auth_digest = self.auth_digest();
        let sig = privkey
            .sign(&auth_digest.0)
            .map_err(|se| Error::SigningError(se.to_string()))?;

        self.signature = sig;
        Ok(())
    }

    /// Verify that a given principal signed this chunk metadata.
    /// Note that the address version is ignored.
    pub fn verify(&self, principal: &StacksAddress) -> Result<bool, Error> {
        let sigh = self.auth_digest();
        let pubk = StacksPublicKey::recover_to_pubkey_without_validating_low_s(
            sigh.as_bytes(),
            &self.signature,
        )
        .map_err(|ve| Error::VerifyingError(ve.to_string()))?;

        let pubkh = Hash160::from_node_public_key(&pubk);
        Ok(pubkh == *principal.bytes())
    }

    pub fn validate_received_chunk(
        &self,
        smart_contract_id: &QualifiedContractIdentifier,
        config: &StackerDBConfig,
        data: &StackerDBChunkData,
        expected_versions: &[u32],
    ) -> Result<bool, net_error> {
        // validate -- must not exceed this replica's configured chunk size.
        if (data.data.len() as u64) > config.chunk_size {
            info!(
                "Received StackerDBChunk for {} ID {}, which is oversized: {} bytes (max {} bytes)",
                smart_contract_id,
                data.slot_id,
                data.data.len(),
                config.chunk_size
            );
            return Ok(false);
        }

        // validate -- must be a valid chunk
        let Some(expected_version) = expected_versions.get(data.slot_id as usize) else {
            info!(
                "Received StackerDBChunk for {} ID {}, which is too big ({})",
                smart_contract_id,
                data.slot_id,
                expected_versions.len()
            );
            return Ok(false);
        };

        // validate -- must be signed by the expected author
        let addr = match self
            .stackerdbs
            .get_slot_signer(smart_contract_id, data.slot_id)?
        {
            Some(addr) => addr,
            None => {
                return Ok(false);
            }
        };

        let slot_metadata = data.get_slot_metadata();
        if !slot_metadata.verify(&addr)? {
            info!(
                "StackerDBChunk for {} ID {} is not signed by {}",
                smart_contract_id, data.slot_id, &addr
            );
            return Ok(false);
        }
