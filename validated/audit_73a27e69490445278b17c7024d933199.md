### Title
Path Traversal in `LoansNFT` Metadata URI - ([File: contracts/LoansNFT.sol])

### Summary
The `LoansNFT` contract allows an administrator to set a base URI for token metadata without any validation or sanitization of the input string. This allows a malicious or compromised admin to point the token metadata to arbitrary filesystem paths or external URLs, potentially leading to path traversal or information disclosure when processed by off-chain indexers and metadata services.

### Finding Description
In `LoansNFT.sol`, the `setBaseURI` function [1](#0-0)  updates the private variable `_loansBaseURI`. This variable is subsequently used in the `tokenURI` function (inherited from OpenZeppelin's `ERC721`) via the `_baseURI` internal override [2](#0-1) .

The function lacks any validation to ensure the `newBaseURI` follows a safe scheme (e.g., `https://` or `ipfs://`) or is restricted to a specific domain. An attacker can provide a string like `file:///etc/passwd?` or `../../secret/path/`, which, when concatenated with the `tokenId`, could trick off-chain systems into attempting to read local files or traverse directory structures on the metadata server.

### Impact Explanation
While the direct impact on the blockchain state is minimal, this vulnerability breaks the integrity of the loan representation.
1.  **Information Disclosure**: Off-chain metadata engines (marketplaces, explorers, or the Tare frontend) that fetch this URI might be vulnerable to Server-Side Request Forgery (SSRF) or local file inclusion if they do not properly sanitize the resulting URI.
2.  **Unauthorized State Transition**: By pointing metadata to a malicious server, an attacker can manipulate the perceived "terms" or "identity" of a loan NFT in external UIs, potentially tricking buyers on the `LoansExchange` [3](#0-2) .
3.  **Protocol Reputation**: The ability to inject arbitrary paths into the canonical URI of a loan asset allows for defacement and loss of trust in the protocol's asset representation.

### Likelihood Explanation
The likelihood is rated as **Medium**. Although it requires `ADMIN_ROLE` [4](#0-3) , the Tare security model acknowledges that a compromised admin can cause material harm [5](#0-4) . The external report specifically highlights that the "client has commented that the function should be able to read any file... and it is not the responsibility of the code," which is a dangerous assumption for protocol-wide metadata.

### Recommendation
Implement input validation in `setBaseURI` to ensure the URI starts with an approved prefix (e.g., `https://api.tare.io/metadata/`) and does not contain traversal sequences like `..`.

```solidity
function setBaseURI(string calldata newBaseURI) external {
    require(IGuardianAccessControl(LOANS_CONTRACT).hasRole(ADMIN_ROLE, msg.sender), Unauthorized());
    // Example validation
    bytes memory uriBytes = bytes(newBaseURI);
    require(uriBytes.length >= 8 && 
            uriBytes[0] == 'h' && uriBytes[1] == 't' && uriBytes[2] == 't' && uriBytes[3] == 'p' && 
            uriBytes[4] == 's' && uriBytes[5] == ':' && uriBytes[6] == '/' && uriBytes[7] == '/', 
            "Invalid URI scheme");
    
    _loansBaseURI = newBaseURI;
    emit BaseURIUpdated(newBaseURI);
}
```

### Proof of Concept
1.  Attacker gains `ADMIN_ROLE` on the `Loans` contract.
2.  Attacker calls `LoansNFT.setBaseURI("file:///etc/shadow\0")`.
3.  The `tokenURI(1)` function now returns `file:///etc/shadow\01`.
4.  A vulnerable off-chain metadata parser fetches this URI and attempts to read the host's sensitive files, leaking them to the attacker via the metadata response.
