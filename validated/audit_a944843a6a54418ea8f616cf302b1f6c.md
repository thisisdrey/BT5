### Title
Firewall conntrack cache reuses stale certificate-based authorization after a peer rehandshake without re-validating against the new certificate - (File: `firewall.go`)

### Summary
Nebula's firewall fast-paths already-seen flows through a conntrack cache keyed only by the packet 4-tuple (local/remote address+port+protocol), not by the peer's certificate identity. Once a flow is admitted, subsequent packets on the same 4-tuple are re-authorized only if the *local* firewall ruleset version has changed — never if the remote peer's certificate itself changes (e.g., via a rehandshake that drops a required group, changes CA, or otherwise alters the identity that originally justified the rule match). This mirrors the analog bug class: a previously-granted authorization/config is reused for packets from what is now effectively a different "owner" (certificate) without re-checking it still applies.

### Finding Description
`Firewall.Drop` fast-paths packets that already have a conntrack entry via `inConns`: [1](#0-0) 

Inside `inConns`, a cached entry is only re-validated against the firewall table (which is what actually checks `h.ConnectionState.peerCert` groups/CA/host) when `c.rulesVersion != f.rulesVersion`: [2](#0-1) 

If the local ruleset version has *not* changed, the code simply refreshes the conntrack expiry and returns `true` without any cert re-check: [3](#0-2) 

`rulesVersion` is a property of the local `Firewall` object, bumped only on config/cert-unsafe-network reload (`reloadFirewall`): [4](#0-3) 

It is not tied to the remote peer's certificate content at all. When a tunnel rehandshakes (certificate renewal, group change, downgrade, etc.), the peer's `ConnectionState.peerCert` is replaced in place on the same `HostInfo`/tunnel: [5](#0-4) 

but the conntrack table (`Firewall.Conntrack`), which is keyed purely by the 4-tuple `firewall.Packet{LocalAddr, RemoteAddr, LocalPort, RemotePort, Protocol}`, is untouched and continues to authorize the flow using the pre-rehandshake decision: [6](#0-5) [7](#0-6) 

So, exactly like the `AutoRange` finding where `positionConfigs[tokenId]` set by a prior owner is used by `execute()` without checking it against the current owner, an established conntrack entry — effectively "config" that says "this 4-tuple was authorized under a specific certificate's groups/CA" — keeps being honored for the lifetime of the connection track entry (`TCPTimeout`/`UDPTimeout`/`DefaultTimeout`, up to 5 days for TCP by default) regardless of the fact that the remote's certificate backing that authorization has since changed, as long as the local rule *text* hasn't also been reloaded.

### Impact Explanation
This allows a peer whose certificate no longer satisfies a configured firewall rule (e.g., it lost a `group` membership required by an inbound/outbound rule, or its issuing CA/`ca_name`/`ca_sha` changed) to keep sending/receiving traffic on an already-established flow for as long as the conntrack entry survives, because the fast path in `inConns` never re-evaluates `h.ConnectionState.peerCert` unless the administrator also reloads/changes the firewall config at the same moment. This is a firewall-enforcement bypass: traffic that should be dropped under the currently effective certificate-based policy is allowed to continue flowing.

### Likelihood Explanation
This is reachable by any already-connected, non-CA-signed-certificate peer that can trigger a rehandshake with a new certificate (certificate rotation is a normal, expected occurrence in Nebula, and rehandshakes on cert change are an intentional built-in feature). No special privileges beyond an existing tunnel are required, and no local config change or restart is needed to trigger the exposure window — only that the operator's firewall config text stays the same across the rehandshake, which is the common case.

### Recommendation
Tie conntrack validity to the certificate/authorization state that produced it, not only to `Firewall.rulesVersion`. For example, store a fingerprint/version of the peer certificate (or a monotonically increasing per-`HostInfo` cert-generation counter) in the `conn` struct alongside `rulesVersion`, and force re-validation in `inConns` whenever either the firewall ruleset OR the peer's certificate has changed since the entry was created — mirroring the existing `c.rulesVersion != f.rulesVersion` re-check path.

### Proof of Concept
1. Establish a tunnel between `A` (has a rule requiring group `admin`) and `B`, where `B`'s certificate includes group `admin`. Send traffic so a conntrack entry is created for a given 4-tuple, authorized by the `table.match` check inside `Drop`.
2. Rotate `B`'s certificate (e.g. via SIGHUP-triggered PKI reload) to a new certificate that no longer includes group `admin`, without changing `A`'s firewall config text at all (so `A.firewall.rulesVersion` stays constant, as in `reloadFirewall`, which only bumps `rulesVersion` on firewall-config or unsafe-network changes).
3. `B` rehandshakes with `A`; `A`'s `HostInfo.ConnectionState.peerCert` is replaced with the new, non-`admin` certificate per `continueHandshake`.
4. `B` continues sending packets on the same already-conntracked 4-tuple. `A.firewall.Drop` → `inConns` finds `c.rulesVersion == f.rulesVersion` and simply extends the expiry, never re-invoking `table.match` against the new certificate — traffic that should now be dropped (no `admin` group) continues to be allowed until the conntrack entry naturally expires (up to the configured `TCPTimeout`/`UDPTimeout`/`DefaultTimeout`).

func (f *Firewall) inConns(fp firewall.Packet, h *HostInfo, caPool *cert.CAPool, localCache firewall.ConntrackCache) bool {
	if localCache != nil {
		if _, ok := localCache[fp]; ok {
			return true
		}
	}
	conntrack := f.Conntrack
	conntrack.Lock()

	// Purge every time we test
	ep, has := conntrack.TimerWheel.Purge()
	if has {
		f.evict(ep)
	}

	c, ok := conntrack.Conns[fp]

	if !ok {
		conntrack.Unlock()
		return false
	}

	if c.rulesVersion != f.rulesVersion {
		// This conntrack entry was for an older rule set, validate
		// it still passes with the current rule set
		table := f.OutRules
		if c.incoming {
			table = f.InRules
		}

		// We now know which firewall table to check against
		if !table.match(fp, c.incoming, h.ConnectionState.peerCert, caPool) {
			if f.l.Enabled(context.Background(), slog.LevelDebug) {
				h.logger(f.l).Debug("dropping old conntrack entry, does not match new ruleset",
					"fwPacket", fp,
					"incoming", c.incoming,
					"rulesVersion", f.rulesVersion,
					"oldRulesVersion", c.rulesVersion,
				)
			}
			delete(conntrack.Conns, fp)
			conntrack.Unlock()
			return false
		}

		if f.l.Enabled(context.Background(), slog.LevelDebug) {
			h.logger(f.l).Debug("keeping old conntrack entry, does match new ruleset",
				"fwPacket", fp,
				"incoming", c.incoming,
				"rulesVersion", f.rulesVersion,
				"oldRulesVersion", c.rulesVersion,
			)
		}

		c.rulesVersion = f.rulesVersion
	}

func (f *Firewall) addConn(fp firewall.Packet, incoming bool) {
	var timeout time.Duration
	c := &conn{}

	switch fp.Protocol {
	case firewall.ProtoTCP:
		timeout = f.TCPTimeout
	case firewall.ProtoUDP:
		timeout = f.UDPTimeout
	default:
		timeout = f.DefaultTimeout
	}

	conntrack := f.Conntrack
	conntrack.Lock()
	if _, ok := conntrack.Conns[fp]; !ok {
		conntrack.TimerWheel.Advance(time.Now())
		conntrack.TimerWheel.Add(fp, timeout)
	}

	// Record which rulesVersion allowed this connection, so we can retest after
	// firewall reload
	c.incoming = incoming
	c.rulesVersion = f.rulesVersion
	c.Expires = time.Now().Add(timeout)
	conntrack.Conns[fp] = c
	conntrack.Unlock()
}

func (f *Interface) reloadFirewall(c *config.C) {
	cs := f.pki.getCertState()
	curCert := cs.getCertificate(cert.Version2)
	if curCert == nil {
		curCert = cs.getCertificate(cert.Version1)
	}

	// The firewall builds its routableNetworks set from the certificate's UnsafeNetworks at construction.
	// Check to see if that set has changed, and if so, rebuild the firewall.
	certUnsafeChanged := curCert != nil && !slices.Equal(curCert.UnsafeNetworks(), f.firewall.unsafeNetworks)

	if !c.HasChanged("firewall") && !certUnsafeChanged {
		f.l.Debug("No firewall config change detected")
		return
	}

	fw, err := NewFirewallFromConfig(f.l, cs, c)
	if err != nil {
		f.l.Error("Error while creating firewall during reload", "error", err)
		return
	}

	oldFw := f.firewall
	conntrack := oldFw.Conntrack
	conntrack.Lock()
	defer conntrack.Unlock()

	fw.rulesVersion = oldFw.rulesVersion + 1
	// If rulesVersion is back to zero, we have wrapped all the way around. Be
	// safe and just reset conntrack in this case.
	if fw.rulesVersion == 0 {
		f.l.Warn("firewall rulesVersion has overflowed, resetting conntrack",
			"firewallHashes", fw.GetRuleHashes(),
			"oldFirewallHashes", oldFw.GetRuleHashes(),
			"rulesVersion", fw.rulesVersion,
		)
	} else {
		fw.Conntrack = conntrack
	}
