### Title
Reward truncation via double-precision division in `MortgageService.computeReward` causes permanent loss of voter rewards - (File: `chainbase/src/main/java/org/tron/core/service/MortgageService.java`)

### Summary
`MortgageService.computeReward(long cycle, List<Pair<byte[], Long>> votes)` (the legacy per-cycle reward algorithm) computes a voter's share of a Super Representative's cycle reward using floating-point division (`double voteRate = (double) userVote / totalVote; reward += voteRate * totalReward;`) instead of exact integer/BigInteger arithmetic [1](#0-0) . This is the same root-cause pattern as the reported Illuminate `Redeemer.sol#authRedeem` bug: a proportional-share calculation that can truncate to a smaller value than the mathematically correct one, and even truncate entirely to zero for small stakers, with no minimum-output check.

### Finding Description
Any account holder can trigger this code path by broadcasting a `WithdrawBalanceContract` transaction. `WithdrawBalanceActuator.execute` calls `mortgageService.withdrawReward(ownerAddress)` unconditionally for any signed, unprivileged transaction [2](#0-1) . Inside `withdrawReward`, once a cycle's reward is computed for an account, the routine advances `beginCycle`/`endCycle` bookkeeping and records `accountVote` for that cycle, permanently marking that cycle as "settled" for the address [3](#0-2) .

The reward for old cycles (before `newRewardAlgorithmEffectiveCycle`) is computed via `getOldReward`, which calls the double-based `computeReward(cycle, votes)` once per cycle in the range [4](#0-3) . For a witness with `totalReward` and `totalVote`, and a voter with `userVote`, the code computes `voteRate = userVote / totalVote` as a `double`, then multiplies by `totalReward` and truncates via implicit cast to `long`. When `userVote` is small relative to `totalVote` (e.g. `userVote / totalVote < 1/totalReward`), the multiplication rounds down to `0`, so the voter's entire entitled reward for that cycle is silently dropped to zero.

Because the settlement is once-per-cycle and irreversible (the cycle's `accountVote` snapshot is stored and `beginCycle` moves past it), the truncated amount is never retried or reconciled — it is permanently lost, exactly mirroring the `Redeemer.sol` finding where `redeemed` truncates to 0 after the principal token is already burned.

### Impact Explanation
Unlike the newer reward algorithm (`computeReward(long beginCycle, long endCycle, AccountCapsule)`), which uses `BigInteger`-based `Vi` delta math to avoid precision loss [5](#0-4) , the legacy per-cycle path retains double-precision arithmetic. Any voter whose relative stake is small enough for a given cycle's reward pool permanently forfeits that cycle's reward with no recourse — a concrete "permanent freezing/loss of funds" for the affected account, reachable purely by a normal user calling `WithdrawBalanceContract` (or indirectly via `queryReward`/other flows that hit `computeReward`).

### Likelihood Explanation
This path is reachable by any unprivileged account that has voted and calls the standard `WithdrawBalanceContract` — no special privilege is required. The truncation condition (`userVote/totalVote` small relative to `1/totalReward`) is common for smaller voters on witnesses with large `totalVote`/`totalReward`, making this readily triggerable in practice for legacy cycles (i.e., any cycle prior to `newRewardAlgorithmEffectiveCycle`, which remains part of permanent chain history for older reward periods and is still exercised by `getOldReward` for any un-migrated cycle range).

### Recommendation
Replace the double-based proportional computation in `computeReward(long cycle, List<Pair<byte[], Long>> votes)` with exact integer arithmetic (e.g., `BigInteger` multiply-then-divide: `totalReward * userVote / totalVote`), consistent with the approach already used in the newer Vi-based `computeReward` and in `VoteRewardUtil.computeReward` [6](#0-5) , to avoid floating-point truncation of voter rewards to zero.

### Proof of Concept
1. Witness `W` accumulates `totalReward = R` in cycle `C` with `totalVote = V` (via `payReward`/`delegationStore.addReward`).
2. Voter `A` has `userVote = u` in cycle `C`, where `u` is small enough that `(double) u / V * R < 1` (e.g., `u=1`, `V=1_000_000`, `R=500_000`, giving `voteRate*R = 0.5` truncated to `0`).
3. Voter `A` submits a `WithdrawBalanceContract` transaction, which is dispatched to `WithdrawBalanceActuator.execute` → `mortgageService.withdrawReward(A)` [2](#0-1) .
4. `withdrawReward` calls `computeReward(beginCycle, endCycle, accountCapsule)` → `getOldReward` → `computeReward(cycle, votes)` for cycle `C`, yielding `reward += 0` for voter `A`'s share of `W`'s reward [7](#0-6) .
5. `beginCycle`/`endCycle` for `A` are advanced past cycle `C`, permanently finalizing the (zero) reward for that cycle [8](#0-7) ; voter `A`'s legitimately earned reward for cycle `C` is permanently lost.

  private long computeReward(long cycle, List<Pair<byte[], Long>> votes) {
    long reward = 0;
    for (Pair<byte[], Long> vote : votes) {
      byte[] srAddress = vote.getKey();
      long totalReward = delegationStore.getReward(cycle, srAddress);
      if (totalReward <= 0) {
        continue;
      }
      long totalVote = delegationStore.getWitnessVote(cycle, srAddress);
      if (totalVote == DelegationStore.REMARK || totalVote == 0) {
        continue;
      }
      long userVote = vote.getValue();
      double voteRate = (double) userVote / totalVote;
      reward += voteRate * totalReward;
    }
    return reward;
  }

  private static long computeReward(long beginCycle, long endCycle,
                                    AccountCapsule accountCapsule, Repository repository) {
    if (beginCycle >= endCycle) {
      return 0;
    }

    long reward = 0;
    for (Protocol.Vote vote : accountCapsule.getVotesList()) {
      byte[] srAddress = vote.getVoteAddress().toByteArray();
      BigInteger beginVi = repository.getDelegationStore().getWitnessVi(beginCycle - 1, srAddress);
      BigInteger endVi = repository.getDelegationStore().getWitnessVi(endCycle - 1, srAddress);
      BigInteger deltaVi = endVi.subtract(beginVi);
      if (deltaVi.signum() <= 0) {
        continue;
      }
      long userVote = vote.getVoteCount();
      reward += deltaVi.multiply(BigInteger.valueOf(userVote))
          .divide(DelegationStore.DECIMAL_OF_VI_REWARD).longValue();
    }
    return reward;
  }
