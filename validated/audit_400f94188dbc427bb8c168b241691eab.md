Confirmed critical fact: `decode_atlas_get_attachment` in `stackslib/src/net/api/getattachment.rs:159-165` deserializes the peer's HTTP response into a `GetAttachmentResponse` (raw bytes) with **no validation that `Hash160::from_data(&content) == request.content_hash`**. This is called from `extend_with_attachments` in `stackslib/src/net/atlas/download.rs:547-552`, which blindly inserts `response.attachment` into the `HashSet<Attachment>` keyed on `content` bytes, without ever checking the response against the `AttachmentRequest.content_hash` that solicited it.

### Title
Unvalidated attachment content allows a malicious peer to poison the Atlas store with data unbound to any on-chain commitment - (File: `stackslib/src/net/atlas/download.rs`)

### Summary
`AttachmentsBatchStateContext::extend_with_attachments` accepts any bytes returned by a peer for a `GET /v2/attachments/<hash>` request and stores them in the node's Atlas DB without ever re-hashing the payload and comparing it to the requested `content_hash`. A single malicious source peer answering an outstanding `AttachmentRequest` can inject an attachment blob that is persisted and treated as validated, unrelated to the on-chain commitment that triggered the fetch.

### Finding Description
The broken invariant is: `attachment.hash() == request.content_hash` is assumed but never checked. In `download.rs:547-552`:
```
if let Ok(response) = response.decode_atlas_get_attachment() {
    self.attachments.insert(response.attachment);
    report.bump_successful_requests();
}
```
`decode_atlas_get_attachment` (`stackslib/src/net/api/getattachment.rs:159-165`) only parses JSON/hex into `GetAttachmentResponse { attachment }` — no hash check against the URL path's hash (`/v2/attachments/<hash>`) that was requested. The result is inserted into a `HashSet<Attachment>` keyed by `content` (`mod.rs:147-165`, deriving `Hash`/`Eq` on `content`), so any distinct byte string a peer returns is independently accepted.

In `AttachmentsDownloader::run` (`download.rs:153-169`), every attachment drained from this set is persisted via `insert_instantiated_attachment` and paired to on-chain `AttachmentInstance`s solely by `find_all_attachment_instances(&attachment.hash())`. Since `attachment.hash()` is computed from the (possibly forged) content itself, a forged attachment simply doesn't match any instance and sits in the DB as an "instantiated" but unpaired attachment — while the batch resolution at `context.attachments_batch.resolve_attachment(&attachment.hash())` (`download.rs:168`) only resolves the hash that was actually returned. If the honest peer's correct response for `H` is also received in the same batch cycle (a separate request/response, keyed independently in the `HashSet`), `H` still gets resolved correctly; the forged blob is simply additional garbage stored under its own hash.

The attack works only if there's a distinct outstanding request whose result is attacker-controlled: `AttachmentsBatchStateContext::get_prioritized_attachments_requests` (`download.rs:404-478`) builds one `AttachmentRequest` per `content_hash`, listing **all** peers (`sources`) that advertise the attachment in their inventory as candidate sources — but `BatchedRequestsState::try_proceed` (`download.rs:819-943`) pops `Requestable` values from a `BinaryHeap<AttachmentRequest>` and issues **one** HTTP GET per `AttachmentRequest` via `PeerNetwork::begin_request`, i.e., to one URL (`request.get_url()`), not one per source. I did not find code that fans a single `content_hash` out to multiple sources in parallel within one batch pass; retries occur only across `try_proceed` batch-level retries (`bump_retry_count`), which re-issue against the (possibly re-picked) best-reliability peer, not against two peers simultaneously for the same request object. So the "two-source, same-cycle" mechanic asserted in the question is not directly substantiated by the code I could inspect — a single malicious peer chosen for the retry, or as the request's source, can already inject bad content given the missing hash check, but I could not confirm the specific "two concurrent responses accepted for the same content_hash in one Done cycle" pathway (e.g., how `sources: HashMap<UrlString, ReliabilityReport>` per-`AttachmentRequest` maps to actual HTTP calls being issued to more than one URL) without reading `Requestable`/`begin_request`/`AttachmentRequest::get_url` implementations, which I was unable to load within the iteration budget.

### Impact Explanation
A malicious peer that is (or becomes, via retry) the source for a given `content_hash` can have its returned bytes persisted into `AtlasDB` as a validated `Attachment` with no verification that `Hash160::from_data(content) == content_hash`. This matches "serving non-canonical state as canonical / attachment-BNS mismatch" (High) only insofar as the forged content itself gets stored keyed by its own (self-consistent) hash — it does not, based on what I could verify, cause the legitimately requested hash `H` to be resolved with wrong content, nor does it permanently block `H` from resolving (a later honest response for `H` in a subsequent retry cycle would still resolve it correctly under `resolve_attachment`). The scoped impact ("both halves simultaneously" — `H` unresolved forever AND `bytes_Y` stored) requires the specific concurrent dual-source race described in the question, which I could not confirm in the code available to me.

### Likelihood Explanation
Unclear/unconfirmed. Requires: (1) attacker peer to be selected as the source responder for a `content_hash` corresponding to a real, unresolved BNS `AttachmentInstance`; (2) the specific concurrency the question describes (two sources both getting their responses accepted within the same `Done` cycle for the same request) which I could not verify is architecturally possible given the one-`get_url`-per-`AttachmentRequest` request model observed in `BatchedRequestsState`.

### Recommendation
Regardless of the exact concurrency mechanics, `extend_with_attachments` should validate `Hash160::from_data(&response.attachment.content) == request.content_hash` before inserting into `self.attachments`, and discard/blacklist the peer on mismatch. This closes the root cause (missing hash verification) independent of whether the dual-source race is exploitable.

### Proof of Concept
Not fully constructible with confidence: I could verify the missing hash check in `extend_with_attachments`/`decode_atlas_get_attachment`, but could not verify (due to not inspecting `Requestable::get_url`, `AttachmentRequest`'s `Hash`/`Eq`/`Ord` impls, and `PeerNetwork::begin_request`) whether the exact "two peers, same content_hash, same batch-Done cycle" race in the question is reachable, versus only a sequential single-source-per-retry substitution. A Devin session with full repo access should inspect `stackslib/src/net/atlas/download.rs` lines 1000-1321 (the `AttachmentRequest` `Hash`/`Ord`/`Requestable` impls) and `PeerNetwork::begin_request` to confirm whether one or multiple HTTP requests can be in-flight for the same `content_hash` within a single `BatchedRequestsState` pass before finalizing this into a concrete PoC.

#### Verdict
Given the missing hash-verification is real but the specific dual-source race and "permanently unresolved + garbage stored" combined impact could not be confirmed from available code, I cannot fully validate the High-severity claim as stated. The narrower, confirmed bug (no hash check on attachment responses, allowing storage of self-consistent-but-uncommitted attachment blobs from a single malicious source peer) is real but its independently-assessed impact (storing an attachment nobody asked for, under its own hash, with no effect on resolving the legitimately committed hash) does not clearly meet the "High" bar as scoped (BNS mismatch / non-canonical state served as canonical) without further confirmation of the race.                 .attachments_instances

                Some(missing_attachments) => missing_attachments,
            };
            // Note: we're getting missing_attachments (attachment_id: content_hash)
            for (attachment_index, content_hash) in missing_attachments.iter() {
                let page_index = attachment_index / AttachmentInstance::ATTACHMENTS_INV_PAGE_SIZE;
                // Since there's a limit in the number of pages that a node can request,
                // we can potentially have multiple inventory request at once.
                if !pages.contains(&page_index) {
                    continue;
                }

                if enqueued.contains(content_hash) {
                    debug!("Atlas: {} already enqueued", content_hash);
                    continue;
                }

                let mut sources = HashMap::new();
                let position_in_page =
                    attachment_index % AttachmentInstance::ATTACHMENTS_INV_PAGE_SIZE;

                for (peer_url, response) in peers_responses.iter() {
                    // Considering the response, look for the page with the index
                    // we're looking for.
                    let search_page = response.pages.iter().find(|page| page.index == page_index);

                    let has_attachment = search_page
                        .and_then(|search_page| {
                            search_page.inventory.get(position_in_page as usize)
                        })
                        .map(|result| *result == 1)
                        .unwrap_or(false);

                    if !has_attachment {
                        debug!(
                            "Atlas: peer does not have attachment ({}, {}) in its inventory {:?}",
                            page_index, position_in_page, response.pages
                        );
                        continue;
                    }

                    let report = self
                        .peers
                        .get(peer_url)
                        .expect("Atlas: unable to retrieve reliability report for peer");
                    sources.insert(peer_url.clone(), report.clone());
                }

                if sources.is_empty() {
                    warn!("Atlas: could not find a peer including attachment in its inventory");
                    continue;
                }

                // Success, we found at least one inventory including the attachment we're looking for.
                let request = AttachmentRequest {
                    sources,
                    content_hash: content_hash.clone(),
                    stacks_block_height: self.attachments_batch.stacks_block_height,
                    canonical_stacks_tip_height: self.attachments_batch.canonical_stacks_tip_height,
                };
                enqueued.insert(content_hash);
                queue.push(request);
            }
        }
        queue

impl<T: Ord + Requestable + fmt::Display + std::hash::Hash> BatchedRequestsState<T> {
    fn try_proceed(
        fsm: BatchedRequestsState<T>,
        dns_lookups: &HashMap<UrlString, Option<Vec<SocketAddr>>>,
        network: &mut PeerNetwork,
        connection_options: &ConnectionOptions,
    ) -> BatchedRequestsState<T> {
        let mut fsm = fsm;

        match fsm {
            BatchedRequestsState::BeginRequests(ref mut queue, ref mut results) => {
                let mut queue = match queue.take() {
                    Some(queue) => queue,
                    None => unreachable!(),
                };
                let mut results = match results.take() {
                    Some(results) => results,
                    None => BatchedRequestsResult::new(HashMap::new()),
                };

                // We want to limit the number of requests in flight,
                // so we will be batching our requests.
                for _ in 0..connection_options.max_inflight_attachments {
                    if let Some(requestable) = queue.pop() {
                        let mut requestables = VecDeque::new();
                        requestables.push_back(requestable);
                        let res =
                            PeerNetwork::begin_request(network, dns_lookups, &mut requestables);
                        if let Some((request, event_id)) = res {
                            results.remaining.insert(event_id, request);
                        }
                    }
                }

                BatchedRequestsState::PollRequests(Some(queue), Some(results))
            }
            BatchedRequestsState::PollRequests(ref mut queue, ref mut results) => {
                let mut pending_requests = HashMap::new();

                let state = match results {
                    Some(state) => state,
                    None => unreachable!(),
                };
                debug!(
                    "Atlas: will poll {} remaining requests",
                    state.remaining.len()
                );

                PeerNetwork::with_http(network, |_, ref mut http| {
                    for (event_id, request) in state.remaining.drain() {
                        match http.get_conversation(event_id) {
                            None => {
                                if http.is_connecting(event_id) {
                                    debug!(
                                        "Atlas: Request {} (event_id: {}) is still connecting",
                                        request, event_id
                                    );
                                    pending_requests.insert(event_id, request);
                                } else {
                                    debug!(
                                        "Atlas: Request {} (event_id: {}) failed to connect. Temporarily blocking URL",
                                        request,
                                        event_id
                                    );
                                    let peer_url = request.get_url().clone();
                                    state.faulty_peers.insert(event_id, peer_url);
                                }
                            }
                            Some(ref mut convo) => {
                                match convo.try_get_response() {
                                    None => {
                                        // still waiting
                                        debug!(
                                            "Atlas: Request {} (event_id: {}) is still waiting for a response",
                                            request,
                                            event_id
                                        );
                                        pending_requests.insert(event_id, request);
                                        continue;
                                    }
                                    Some(response) => {
                                        let peer_url = request.get_url().clone();
                                        if response.preamble().status_code == 404 {
                                            state.faulty_peers.insert(event_id, peer_url);
                                            continue;
                                        }
                                        debug!(
                                            "Atlas: Request {} (event_id: {}) received HTTP 200",
                                            request, event_id
                                        );
                                        state.succeeded.insert(request, Some(response));
                                    }
                                }
                            }
                        }
                    }
                });

                if !pending_requests.is_empty() {
                    // We need to keep polling
                    for (event_id, request) in pending_requests.drain() {
                        state.remaining.insert(event_id, request);
                    }
                    return fsm;
                }
                debug!(
                    "Atlas: Processed request batch ({} success, {} faults)",
                    state.succeeded.len(),
                    state.faulty_peers.len()
                );

                // Requests completed!
                // any requests left to perform?
                let queue = match queue.take() {
                    Some(queue) => queue,
                    None => unreachable!(),
                };
                match queue.len() {
                    0 => BatchedRequestsState::Done(results.take().unwrap()),
                    _ => BatchedRequestsState::BeginRequests(Some(queue), results.take()),
                }
            }
            BatchedRequestsState::Done(_) => unreachable!(),
        }
    }

#[derive(Debug, Clone, Serialize, Deserialize, Eq, PartialEq, Hash)]
/// Attachments are the content associated with an AttachmentInstance
pub struct Attachment {
    pub content: Vec<u8>,
}

impl Attachment {
    pub fn new(content: Vec<u8>) -> Attachment {
        Attachment { content }
    }

    pub fn hash(&self) -> Hash160 {
        Hash160::from_data(&self.content)
    }

    pub fn empty() -> Attachment {
        Attachment { content: vec![] }
    }
}
