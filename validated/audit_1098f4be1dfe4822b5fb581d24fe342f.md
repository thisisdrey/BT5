### Title
Attacker can exploit oracle deviation-threshold staleness to mint undercollateralized synths and leave bad debt - (File: `contracts/DebtToken.sol`)

### Summary
`DebtToken.issue` and `Pool.debtPositionOf` value collateral and debt entirely at `MasterOracle` (Chainlink-backed) prices. Because Chainlink feeds only update once deviation exceeds a threshold (e.g. 0.5% for ETH/USD), the oracle can be stale relative to the real market price. An unprivileged attacker can deposit collateral whose real price has already moved, issue synthetic debt against the stale (overvalued) collateral price, sell the minted synths externally, and leave a position that becomes undercollateralized the moment the oracle updates — creating protocol bad debt. This is the same oracle-latency arbitrage class as the reference report, mapped onto Metronome's mint/health-check surface rather than a deposit/withdraw LP surface.

### Finding Description
Metronome computes how much debt an account can carry in `Pool.debtPositionOf`/`depositOf`, which sums `masterOracle().quoteTokenToUsd(underlying, depositToken.balanceOf(account)) * collateralFactor` for each deposit token [1](#0-0) . `DebtToken.issue` then enforces only `amount_ <= quoteUsdToToken(syntheticToken, _issuableInUsd)` and mints both debt and synth [2](#0-1) .

The analogous sequence:

1. Collateral asset (e.g. WETH) real price falls, but by less than the Chainlink deviation threshold, so `latestAnswer` still returns the stale, higher price.
2. Attacker buys the collateral cheaply on a DEX (flash-loanable) and calls `DepositToken.deposit` — credited at stale USD value via `depositOf`.
3. Attacker calls `DebtToken.issue` for the full `_issuableInUsd` — allowed, because the stale oracle overstates collateral value.
4. Attacker sells the minted msAssets on an external market at real prices.
5. The oracle updates (or the attacker pushes the update once deviation is reached). `debtPositionOf` now shows `_debtInUsd > _issuableLimitInUsd`; the position is liquidatable but `Pool.liquidate` caps seizure at `depositToken_.balanceOf(account_)` (`AmountIsTooHigh` check) [3](#0-2) , so the shortfall between repaid value and seized collateral is socialized as bad debt.

The same staleness applies in `Pool.swap`, which prices synth-for-synth purely via `masterOracle().quote` with no reserve [4](#0-3) , letting the attacker also rotate minted debt into whichever synth is most mispriced before exiting — though swap itself cannot drain a reserve since it just re-denominates debt.

No guard stops this: `issue` is unprivileged (`onlyIfSyntheticTokenExists`, `whenNotShutdown`, `nonReentrant` only), there is no same-block/freshness check, and the health check in `SmartFarmingManager.leverage`/`flashRepay` uses the same stale `debtPositionOf` [5](#0-4) .

### Impact Explanation
Protocol insolvency: each cycle converts the gap between stale oracle valuation and real collateral value into unbacked synth supply. The loss per position is bounded by the deviation threshold times position size, but the attack is repeatable and scalable with flash-borrowed capital, so aggregate bad debt grows with available liquidity. Liquidators cannot recover the shortfall because seized collateral is capped at the account's deposit balance.

### Likelihood Explanation
Requires a real price move near/above the Chainlink deviation threshold plus profitable exit liquidity for the minted synth (a DEX pool or `Pool.swap` into a better-priced synth). These conditions recur during normal volatility; the attacker needs no privileges and can execute deposit → issue → external sell in a single transaction.

### Recommendation
- Enforce oracle freshness/staleness checks (e.g. reject `issue`, `swap`, and collateral deposits when `updatedAt` is older than a threshold, or use a tighter deviation-sensitive feed like a TWAP median) in `MasterOracle`.
- Add a safety buffer on `issue` (e.g. haircut issuable limit when oracle data is older than N seconds).
- Charge a fee on `issue`/withdraw sized above typical deviation thresholds, mirroring the reference report's recommendation, so single-block oracle-latency arbitrage is unprofitable.

### Proof of Concept
Reproducible in the existing Hardhat suite (`test/Pool.test.ts` already uses `masterOracle.updatePrice` to simulate feed moves):

```ts
// fork/fork-simulated flow, analogous to test/Pool.test.ts liquidation setup
// 1. alice = attacker; oracle still reports stale high ETH price
await weth.connect(attacker).approve(wethDepositToken.address, MaxUint256)
await wethDepositToken.connect(attacker).deposit(ethAmount, attacker.address)

// 2. stale oracle overstates collateral -> oversized issuable limit
const { _issuableInUsd } = await pool.debtPositionOf(attacker.address)
const amountToIssue = await masterOracle.quoteUsdToToken(msEth.address, _issuableInUsd)
await msEthDebtToken.connect(attacker).issue(amountToIssue, attacker.address)

// 3. attacker sells msEth externally (SwapperMock/DEX) at real market price

// 4. oracle updates to the real (lower) collateral price
await masterOracle.updatePrice(weth.address, realLowerPrice)

// 5. position is unhealthy; liquidation seizes all collateral but debt remains
const { _isHealthy, _depositInUsd, _debtInUsd } = await pool.debtPositionOf(attacker.address)
expect(_isHealthy).to.be.false
expect(_debtInUsd).to.be.gt(_depositInUsd) // bad debt
```

The invariant that breaks is solvency: debt issued is bounded only by stale oracle valuation of collateral, and `liquidate` cannot seize more than exists.
