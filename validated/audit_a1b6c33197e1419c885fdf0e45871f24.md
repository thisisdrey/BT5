### Title
SSRF-analog: Atlas attachment downloader connects to peer-supplied `data_url` without any private/internal IP filtering - (File: `stackslib/src/net/atlas/download.rs`)

### Summary
Every other outbound-request path in the p2p networking code that resolves and connects to a data URL supplied by a remote peer enforces a private/loopback IP check (`PeerAddress::is_in_private_range()`), gated by the `private_neighbors` connection option, before issuing the request. The Atlas `AttachmentsDownloader` — which resolves `data_url` values taken from `HandshakeData.data_url` of arbitrary remote peers and issues HTTP GET requests to fetch attachment inventories/attachments — performs no such check anywhere in its DNS-resolution or request-dispatch logic.

### Finding Description
When a remote node completes a p2p handshake, it supplies a free-form `data_url` string in `HandshakeData` that is copied verbatim into the local conversation state with no validation that it corresponds to the peer's actual observed IP: [1](#0-0) 

This `data_url` is later used by the Atlas subsystem to build the peer set for attachment inventory sync: [2](#0-1) 

The batched DNS-resolution logic resolves the hostname/IP portion of that URL and only validates the URL *scheme* (via `UrlString::parse_to_block_url`, which just enforces `http`/`https`, no query/fragment/credentials) — it never checks whether the resolved address is private, loopback, or a link-local metadata address: [3](#0-2) 

Once resolved, the request is dispatched via `PeerNetwork::begin_request` / `connect_or_send_http_request`, which simply connects to whatever socket address resulted from resolution: [4](#0-3) 

Contrast this with the mempool sync path, which resolves the same kind of peer-supplied `data_url` but explicitly rejects private-range addresses unless the operator has opted in via `private_neighbors`: [5](#0-4) 

A `grep` across `stackslib/src/net/**` for `is_in_private_range`/`private_neighbors` shows this guard is applied in `mempool/mod.rs`, `stackerdb/sync.rs`, `stackerdb/config.rs`, `neighbors/walk.rs`, `neighbors/db.rs`, `connection.rs`, `db.rs`, `p2p.rs`, and `api/liststackerdbreplicas.rs` — but it is **absent from `net/atlas/download.rs`**, the one module whose entire purpose is to fetch content (attachment inventories and attachment bodies) from URLs sourced from remote, potentially-hostile peers.

This breaks the invariant the rest of the networking code enforces: "an outbound HTTP request to a peer-supplied data URL must not target a private/internal/loopback address unless explicitly allowed." In Atlas, that invariant simply does not exist.

### Impact Explanation
Any remote peer that can complete a handshake (an unprivileged, unauthenticated operation from the node's perspective — it requires no special role, key, or configuration) can set its advertised `data_url` to an internal address such as `http://127.0.0.1:<port>/`, an RFC1918 address reachable from the victim's network, or a cloud metadata endpoint. When the victim's Atlas downloader batch runs, it will:
1. Resolve that URL and connect to the attacker-chosen internal/private address.
2. Issue a real GET request for `/v2/attachments/inv` or `/v2/attachments/{hash}`.
3. Parse whatever JSON-shaped response comes back as `GetAttachmentsInvResponse`/`GetAttachmentResponse` and merge it into in-memory reliability/inventory state, and (if the content hash matches an expected content hash) even insert the returned bytes into the persistent `AtlasDB` as a validated `Attachment`.

This gives an external, unprivileged party a request-forgery primitive from the node's process: it can be used to probe internal/private network reachability (open vs. closed port behavior differs, as in the reference report), and — for services returning JSON — to read internal endpoints and feed their responses into the node's own memory/DB state, since Atlas response parsing accepts arbitrary JSON matching the response schema, not attacker-arbitrary content only from the network.

### Likelihood Explanation
Likelihood is high: `AttachmentsDownloader::run` is a routine part of the p2p event loop for any Atlas/BNS-enabled node, and any successfully-handshaked outbound sync peer is eligible to have its `data_url` used as an inventory/attachment source — no additional privilege, signature, or admin role is required beyond completing an ordinary peer handshake.

### Recommendation
Apply the same `PeerAddress::is_in_private_range()` (gated by `connection_options.private_neighbors`) check used in `mempool/mod.rs` and `stackerdb/sync.rs` to the resolved socket addresses produced by `BatchedDNSLookupsState` / `AttachmentsBatchStateContext::get_peers_urls` in `stackslib/src/net/atlas/download.rs`, before any `AttachmentsInventoryRequest`/`AttachmentRequest` is dispatched. Reject or skip peers whose resolved `data_url` address falls in a private/loopback/link-local range unless the operator has explicitly enabled `private_neighbors`.

### Proof of Concept
1. Stand up a malicious Stacks peer that completes a normal handshake with the victim node but sets `HandshakeData.data_url` to `http://127.0.0.1:<internal-service-port>/` (or a link-local/RFC1918 address reachable from the victim host).
2. Ensure the victim believes it has outbound sync peers with Atlas/StackerDB services enabled so `AttachmentsDownloader::run` selects this peer's URL (`network.get_data_url(&peer)` in `stackslib/src/net/atlas/download.rs:117`).
3. Trigger an Atlas attachment sync (e.g., by advertising an `AttachmentInstance` referencing an unknown content hash so a batch is queued).
4. Observe that the victim's node resolves `127.0.0.1:<port>` via `BatchedDNSLookupsState` and issues a `GET /v2/attachments/inv...` request to that internal endpoint — confirmable via network capture or an internal test HTTP listener that logs the incoming request, analogous to the PoC in the referenced advisory.

                        continue;
                    }
                    let url = match url_str.parse_to_block_url() {
                        Ok(url) => url,
                        Err(e) => {
                            warn!("Atlas: Unsupported URL {:?}, {}", url_str, e);
                            state.errors.insert(url_str, e.into());
                            continue;
                        }
                    };
                    let port = match url.port_or_known_default() {
                        Some(p) => p,
                        None => {
                            warn!("Atlas: Unsupported URL {:?}: unknown port", &url);
                            continue;
                        }
                    };
                    match url.host() {
                        Some(url::Host::Domain(domain)) => {
                            let res = dns_client.queue_lookup(
                                domain,
                                port,
                                get_epoch_time_ms() + connection_options.dns_timeout,
                            );
                            match res {
                                Ok(_) => {
                                    state.dns_lookups.insert(url_str.clone(), None);
                                    state.parsed_urls.insert(
                                        url_str,
                                        DNSRequest::new(domain.to_string(), port, 0),
                                    );
                                }
                                Err(e) => {
                                    state.errors.insert(url_str.clone(), e);
                                }
                            }
                        }

                            state.dns_lookups.insert(
                                url_str,
                                Some(vec![SocketAddr::new(IpAddr::V4(addr), port)]),
                            );
                        }

                            state.dns_lookups.insert(
                                url_str,

    pub fn connect_or_send_http_request(
        &mut self,
        data_url: UrlString,
        addr: SocketAddr,
        request: StacksHttpRequest,
    ) -> Result<usize, NetError> {
        PeerNetwork::with_network_state(self, |ref mut network, ref mut network_state| {
            PeerNetwork::with_http(network, |ref mut network, ref mut http| {
                match http.connect_http(
                    network_state,
                    network,
                    data_url.clone(),
                    addr,
                    Some(request.clone()),
                ) {
                    Ok(event_id) => Ok(event_id),
                    Err(NetError::AlreadyConnected(event_id, _)) => {
                        if let (Some(ref mut convo), Some(ref mut socket)) =
                            http.get_conversation_and_socket(event_id)
                        {
                            convo.send_request(request)?;
                            HttpPeer::saturate_http_socket(socket, convo)?;
                            Ok(event_id)
                        } else {
                            debug!("HTTP failed to connect to {data_url}, {addr:?}");
                            Err(NetError::PeerNotConnected(format!(
                                "HTTP failed to connect to {data_url}, {addr:?}",
                            )))
                        }
                    }
                    Err(e) => Err(e),
                }
            })
        })
    }
