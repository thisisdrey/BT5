Audit Report

## Title
`pallet-psm::redeem` skips the live-decimals guard that `mint` enforces, letting a decimals-metadata change drain the PSM reserve - (File: `substrate/frame/psm/src/lib.rs`)

## Summary
`redeem()` reads `ext_decimals = external.decimals` and `internal_decimals = info.internal_decimals` directly from the registration-time snapshot and feeds them into `internal_to_external`/`external_to_internal` without ever calling `Self::ensure_decimals_match`, unlike `mint()`, which explicitly re-validates live decimals before converting [1](#0-0)  vs. [2](#0-1) . This asymmetry means a post-deposit change to the external asset's live decimals (performed by that asset's own `pallet-assets` metadata admin, independent of PSM governance) is caught on the deposit side but silently trusted on the withdrawal side.

## Finding Description
`ensure_decimals_match` compares `T::Fungibles::decimals(external_asset)` and `T::Fungibles::decimals(internal_asset)` against the stored snapshots and fails with `Error::DecimalsMismatch` on drift [3](#0-2) , and `mint()` calls this before computing `external_to_internal`/`internal_to_external` [4](#0-3) , confirmed by the test `mint_halts_when_asset_decimals_drift`. `redeem()`, by contrast, takes `ext_decimals`/`internal_decimals` straight from storage snapshots and calls `internal_to_external`/`external_to_internal` on them without any live check [5](#0-4) . `internal_to_external` and `external_to_internal` purely scale by `10^|ext_decimals-internal_decimals|`, so if `external.decimals` (snapshot) diverges from the asset's live decimals, the scaling factor used at redeem time no longer reflects the real per-unit value of the external asset, and `T::Fungibles::transfer` pays out of `psm_account` at the stale, incorrect rate. This directly matches the report's claimed exploit path: an attacker mints normally while decimals are correctly aligned (accruing legitimate debt, passing `ensure_decimals_match`), then the external asset's own metadata admin changes its live decimals, and the attacker calls `redeem`, which has no equivalent guard and computes `external_out` using the stale snapshot, extracting far more (or less) real value from the shared reserve than was actually deposited.

The code's own doc-comment states this asymmetry is intentional ("Redemptions use the decimals snapshotted... allowing existing positions to unwind even if live metadata later changes"), which the report correctly identifies as the design flaw, since "unwinding at snapshot rate" without bounding it to pre-drift debt or freezing the pair allows exploitation of any future decimals change, not just wind-down of pre-existing debt.

## Impact Explanation
This allows an external, permissionless actor (any account with metadata-admin rights on the specific `external_asset` in `pallet-assets`, which is a role independent of the PSM's own `full_admin`/`emergency_admin`) to distort the redeem-side exchange rate and drain `T::Fungibles::balance(external_asset, psm_account)` — the shared reserve potentially backing multiple depositors of the same `internal_asset`. This is an unbacked/incorrect settlement of value between `internal_asset` and `external_asset` and a direct drain of protocol reserves, matching the "theft or unbacked mint/unlock" and "runtime bugs that compromise intended behavior" categories in the impact gate.

## Likelihood Explanation
The attack requires no privileged PSM governance action, no validator/relayer collusion, and no compromised keys — only that the specific `external_asset`'s own decimals-metadata role (its `pallet-assets` owner) is held by an account distinct from and not gated by the PSM's `full_admin`. This is realistic for permissionlessly created assets approved on a PSM, and the sequence (mint at correct rate → external decimals change → redeem at stale rate) is fully attacker-controlled and repeatable once decimals have drifted, with `mint()`'s guard blocking new debt accrual at the wrong rate but not blocking exploitation of already-accrued debt via `redeem()`.

## Recommendation
Call `Self::ensure_decimals_match(&info, &internal_asset, &external_asset, &external)?` inside `redeem()` before computing `internal_to_external`/`external_to_internal`, exactly mirroring `mint()`, and return `Error::DecimalsMismatch` on drift. If unwinding pre-existing debt at the historical snapshot rate is a desired feature, it should be implemented as a separate, explicitly-gated path that freezes the pair from further minting and is strictly bounded to the debt that existed prior to the drift being detected, rather than silently applying stale rates to all future redemptions.

## Proof of Concept
1. PSM governance approves `external_asset = FOO` (live decimals = 6) on `internal_asset = hUSD` (6 decimals); `ExternalAssetInfo::decimals` snapshots 6.
2. Attacker calls `mint(hUSD, FOO, 1_000_000, ..)`; `ensure_decimals_match` passes (6==6), deposits 1,000,000 raw FOO into `psm_account`, receives ~1,000,000 raw hUSD, and `PsmDebt[(hUSD,FOO)]` increases accordingly [6](#0-5) .
3. FOO's `pallet-assets` metadata admin (unrelated to PSM governance) calls `set_metadata` changing FOO's decimals from 6 to 0.
4. Attacker calls `redeem(hUSD, FOO, 1_000_000, ..)`; since `redeem()` never calls `ensure_decimals_match`, it uses the stale snapshot (`ext_decimals=6`) to compute `external_out`, transferring raw FOO units from `psm_account` that are now worth ~10^6× more real value than what was deposited [7](#0-6) [8](#0-7) , draining the reserve while `PsmDebt` is decremented as though a normal, value-preserving redemption occurred.

```rust
		/// Verify the live decimals for an external still match the snapshot taken at
		/// registration on this PSM, and that the internal asset's live decimals still
		/// match the snapshot stored in [`PsmInfo`].
		pub(crate) fn ensure_decimals_match(
			info: &PsmInfo<T>,
			internal_asset: &T::AssetId,
			external_asset: &T::AssetId,
			external: &ExternalAssetInfo,
		) -> Result<(u8, u8), DispatchError> {
			ensure!(
				T::Fungibles::decimals(external_asset.clone()) == external.decimals,
				Error::<T>::DecimalsMismatch
			);
			ensure!(
				T::Fungibles::decimals(internal_asset.clone()) == info.internal_decimals,
				Error::<T>::DecimalsMismatch
			);
			Ok((external.decimals, info.internal_decimals))
		}
```
