This is used for repository moving/replication between Gitaly nodes (e.g., Geo, storage-move import flows), where `HttpUrl` points to a `GetSnapshot`-served tar archive of a repository. The RPC extracts an attacker/peer-influenced tar stream directly into the target repository directory with a raw `tar -C path -xvf -` call, and the code explicitly documents that the archive content is fully trusted without validation of individual archive entries (paths, symlinks, device files, permissions), which is the same bug class as the report: fully attacker/peer-controlled data (there, `initializer` bytes; here, tar member paths/types) is passed unchecked into a security-sensitive operation whose outcome depends entirely on trusting that untrusted input structurally conforms to an expected format.

### Title
Unvalidated tar extraction in `CreateRepositoryFromSnapshot` allows archive-controlled filesystem writes outside the target repository - (File: internal/gitaly/service/repository/create_repository_from_snapshot.go)

### Summary
`CreateRepositoryFromSnapshot` fetches an attacker/peer-influenced tar stream from `in.GetHttpUrl()` and pipes it straight into `tar -C <repoPath> -xvf -` with no inspection of the archive's member names, types, or link targets before or after extraction.

### Finding Description
The RPC handler `CreateRepositoryFromSnapshot` in [1](#0-0)  creates a fresh repository directory via `repoutil.Create` and then calls `s.untar` to populate it. `untar` performs an HTTP GET against a caller-supplied `HttpUrl` (optionally with a caller-supplied `Authorization` header and DNS-rebinding-resistant `ResolvedAddress`) and streams the HTTP response body directly into an invocation of the external `tar` binary: [2](#0-1) .

The code contains an explicit acknowledgment of the risk: "The received archive is trusted *a lot*. Before pointing this RPC at endpoints not under our control, it should undergo a lot of hardening" [3](#0-2) . No allow-list, path-canonicalization, symlink-rejection, or member-type filtering is applied to the archive contents before or after `tar` runs; the process relies entirely on the archive being well-behaved and structurally trusted, exactly like the analog report's reliance on the `initializer` calldata being trusted to only call `initialize`.

Because the target path passed to `tar -C` is the freshly created repository directory (obtained from `s.locator.GetRepoPath`, see [4](#0-3) ), any archive entry containing path traversal segments (`../`), an absolute path, a symlink, hardlink, device, or FIFO member is passed through to `tar` unfiltered. Whether this leads to file writes escaping the repository directory depends only on the behavior of the specific `tar` binary invoked on the host — the Gitaly code itself performs zero validation, so protection (if any) is incidental rather than intentional.

### Impact Explanation
A malicious or compromised source of the snapshot archive (e.g., a rogue/compromised peer Gitaly node serving `GetSnapshot`, or any actor able to influence the URL/response reachable via `ResolvedAddress`/`HttpUrl` in a storage-move or replication workflow) can supply a crafted tar stream containing traversal paths or symlink entries. Depending on the `tar` implementation's own protections, this can result in files being written outside the newly created repository directory on the Gitaly server's filesystem — a cross-repository/storage escape and potential remote code or config injection (e.g., overwriting `hooks/`, `config`, or files outside the storage root entirely). This matches the "archive or bundle extraction" and "cross-repository object access" acceptable-analog categories.

### Likelihood Explanation
The RPC is invoked as part of repository replication/migration flows where the request's `HttpUrl`/`ResolvedAddress`/`HttpAuth` fields determine which endpoint's response bytes get extracted verbatim. Any node or actor able to influence the served tar content (a malicious peer, a compromised internal endpoint, or an SSRF-style redirection of the fetch target) can trigger extraction of a hostile archive without any content validation in Gitaly itself, making exploitation likely wherever this RPC is reachable with an untrusted or semi-trusted `HttpUrl`.

### Recommendation
Do not pipe the fetched tar stream directly into the external `tar` binary without validation. Parse the archive in Go using `archive/tar`, reject or normalize any entry whose name is absolute or contains `..` segments that would resolve outside the target directory, and reject non-regular-file/non-directory entry types (symlinks, hardlinks, device nodes, FIFOs) unless explicitly required. Only after validating every entry should the contents be written to disk, mirroring the report's recommendation to strictly validate/constrain untrusted structured input rather than trusting it to conform to an expected shape.

### Proof of Concept
1. Stand up an HTTP server that serves a tar stream containing a member named `../../../../tmp/evil` (or a symlink member pointing outside the target directory).
2. Call `CreateRepositoryFromSnapshot` with `HttpUrl` pointing at that server (using `ResolvedAddress` to bypass DNS-based restrictions if needed, as demonstrated in the existing test `TestCreateRepositoryFromSnapshot_resolvedAddressSuccess` [5](#0-4) ).
3. Observe that `s.untar` extracts the archive via `tar -C <repoPath> -xvf -` [6](#0-5)  with no path/type validation performed by Gitaly, and check whether the crafted entry lands outside `repoPath`.

func (s *server) untar(ctx context.Context, path string, in *gitalypb.CreateRepositoryFromSnapshotRequest) error {
	req, err := http.NewRequestWithContext(ctx, "GET", in.GetHttpUrl(), nil)
	if err != nil {
		return structerr.NewInvalidArgument("Bad HTTP URL: %w", err)
	}

	client := httpClient
	if resolvedAddress := in.GetResolvedAddress(); resolvedAddress != "" {
		client, err = newResolvedHTTPClient(in.GetHttpUrl(), resolvedAddress)
		if err != nil {
			return structerr.NewInvalidArgument("creating resolved HTTP client: %w", err)
		}
	}

	if in.GetHttpAuth() != "" {
		req.Header.Set("Authorization", in.GetHttpAuth())
	}

	rsp, err := client.Do(req)
	if err != nil {
		return structerr.NewInternal("HTTP request failed: %w", err)
	}
	defer rsp.Body.Close()

	if rsp.StatusCode < http.StatusOK || rsp.StatusCode >= http.StatusMultipleChoices {
		return structerr.NewInternal("HTTP server: %s", rsp.Status)
	}

	cmd, err := command.New(ctx, s.logger, []string{"tar", "-C", path, "-xvf", "-"}, command.WithStdin(rsp.Body))
	if err != nil {
		return err
	}

	return cmd.Wait()
}

func (s *server) CreateRepositoryFromSnapshot(ctx context.Context, in *gitalypb.CreateRepositoryFromSnapshotRequest) (*gitalypb.CreateRepositoryFromSnapshotResponse, error) {
	repository := in.GetRepository()
	if err := s.locator.ValidateRepository(ctx, repository, storage.WithSkipRepositoryExistenceCheck()); err != nil {
		return nil, structerr.NewInvalidArgument("%w", err)
	}

	if err := repoutil.Create(ctx, s.logger, s.locator, s.gitCmdFactory, s.catfileCache, s.txManager, s.repositoryCounter, repository, func(repo *gitalypb.Repository) error {
		path, err := s.locator.GetRepoPath(ctx, repo, storage.WithRepositoryVerificationSkipped())
		if err != nil {
			return structerr.NewInternal("getting repo path: %w", err)
		}

		// The archive contains a partial git repository, missing a config file and
		// other important items. Initializing a new bare one and extracting the
		// archive on top of it ensures the created git repository has everything
		// it needs (especially, the config file and hooks directory).
		//
		// NOTE: The received archive is trusted *a lot*. Before pointing this RPC
		// at endpoints not under our control, it should undergo a lot of hardening.
		if err := s.untar(ctx, path, in); err != nil {
			return structerr.NewInternal("extracting snapshot: %w", err)
		}

		return nil
	}); err != nil {
		return nil, structerr.NewInternal("creating repository: %w", err)
	}
