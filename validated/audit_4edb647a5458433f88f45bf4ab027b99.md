### Title
`ProxyOFT.sendFrom` burns before validating the destination recipient, making failed cross-chain mints unrecoverable - ([File: contracts/ProxyOFT.sol](contracts/ProxyOFT.sol))

### Summary
`ProxyOFT` exposes both the raw LayerZero `sendFrom(address,uint16,bytes,uint256,...)` path and a convenience `sendFrom(address,uint16,address,uint256)` overload, but neither validates the destination recipient before `_debitFrom` burns the synthetic token. [1](#0-0) [2](#0-1) [3](#0-2)  A zero or malformed destination makes the destination-side `_sendAck/_creditTo` mint revert while the source-chain burn is already final. [4](#0-3) [5](#0-4) 

### Finding Description
`OFTCoreUpgradeable.sendFrom` is public and forwards caller-controlled `_toAddress` bytes into `_send`. [6](#0-5)  `_send` calls `_debitFrom` before transmitting, and Metronome’s `_debitFrom` only checks sender ownership, bridging activity, and destination-chain support; it ignores `toAddress_` and calls `syntheticToken.burn(from_, amount_)`. [3](#0-2) [2](#0-1)  The overload `sendFrom(address,uint16,address,uint256)` also accepts `to_ == address(0)` and merely packs it into `abi.encodePacked(to_)`. [1](#0-0)  On receive, `_sendAck` decodes the bytes to an address and `_creditTo` mints to it; `SyntheticToken._mint` reverts on `account_ == address(0)` with `MintToTheZeroAddress`. [4](#0-3) [7](#0-6) 

### Impact Explanation
The broken invariant is bridge conservation: source supply is burned in `_debitFrom`, but no corresponding destination mint can complete when the destination recipient is invalid. [8](#0-7) [9](#0-8)  `NonblockingLzAppUpgradeable` catches the failed receive and stores only `keccak256(_payload)`, and `retryMessage` requires the identical payload hash before re-executing, so the recipient cannot be corrected during recovery. [10](#0-9) [11](#0-10)  The result is permanent loss of the bridged synthetic amount for an unprivileged caller that supplies `address(0)` through the convenience overload or malformed bytes through the raw OFT interface. [1](#0-0) [6](#0-5) 

### Likelihood Explanation
The path is permissionless and requires no governor, keeper, malicious endpoint, or trusted remote; it only needs an EOA to call `sendFrom` with a bad recipient while bridging is active and the destination chain is supported. [2](#0-1) [1](#0-0)  The likelihood is limited by the fact that the caller primarily burns their own position rather than taking another user’s funds, but the failed-message retry cannot repair the recipient and therefore preserves the loss permanently. [11](#0-10) 

### Recommendation
Reject invalid recipients before debit: in `ProxyOFT.sendFrom(address,uint16,address,uint256)` revert on `to_ == address(0)`, and in the raw bytes `sendFrom`/`_send` path require `_toAddress.length == 20` and `toAddress_.toAddress(0) != address(0)` before `_debitFrom`. [1](#0-0) [3](#0-2)  Prefer validating inside `_debitFrom` so every future entry point that reaches `_send` performs the same check before `syntheticToken.burn`. [2](#0-1) 

### Proof of Concept
```ts
// Hardhat sketch: source ProxyOFT burns, destination ProxyOFT stores an unrecoverable failure.
// Setup: PoolRegistry mock returns isBridgingActive=true and isDestinationChainSupported(dst)=true;
// SyntheticToken mints alice msUSD; alice owns balance; source/destination ProxyOFT point to a mock endpoint.

const amount = parseEther('100')

// 1) Convenience overload accepts address(0): no recipient check before burn.
await expect(
  oftSrc.connect(alice)['sendFrom(address,uint16,address,uint256)'](
    alice.address,
    dstChainId,
    ethers.constants.AddressZero,
    amount,
    {value: nativeFee}
  )
).to.emit(synth, 'Transfer').withArgs(alice.address, ethers.constants.AddressZero, amount)

// Source invariant already broken: alice burned and totalBridgedOut increased.
expect(await synth.balanceOf(alice.address)).to.eq(before.sub(amount))
expect(await synth.totalBridgedOut()).to.eq(bridgedOutBefore.add(amount))

// 2) Mock endpoint delivers PT_SEND payload to destination; _sendAck decodes to=0 and
// SyntheticToken._mint reverts MintToTheZeroAddress, so NonblockingLzApp stores failedMessages.
await endpoint.deliverTo(oftDst.address) // invokes lzReceive -> nonblockingLzReceive -> _sendAck
expect(await oftDst.failedMessages(srcChainId, srcBytes, nonce)).to.not.eq(ethers.constants.HashZero)
expect(await synthDst.balanceOf(ethers.constants.AddressZero)).to.eq(0)

// 3) Recovery cannot fix recipient: retryMessage requires identical payload and reverts again.
await expect(
  oftDst.retryMessage(srcChainId, srcBytes, nonce, samePayload)
).to.be.reverted // MintToTheZeroAddress / stored payload cannot be edited
```

The same source-side burn occurs for the raw `sendFrom(address,uint16,bytes,uint256,...)` overload with malformed `_toAddress` because `_debitFrom` is reached before any destination-decoding failure. [3](#0-2) [4](#0-3)

```text
    function retryMessage(uint16 _srcChainId, bytes calldata _srcAddress, uint64 _nonce, bytes calldata _payload) public payable virtual {
        // assert there is message to retry
        bytes32 payloadHash = failedMessages[_srcChainId][_srcAddress][_nonce];
        require(payloadHash != bytes32(0), "NonblockingLzApp: no stored message");
        require(keccak256(_payload) == payloadHash, "NonblockingLzApp: invalid payload");
        // clear the stored message
        failedMessages[_srcChainId][_srcAddress][_nonce] = bytes32(0);
        // execute the message. revert if it fails again
        _nonblockingLzReceive(_srcChainId, _srcAddress, _nonce, _payload);
        emit RetryMessageSuccess(_srcChainId, _srcAddress, _nonce, payloadHash);
```
