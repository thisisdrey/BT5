### Title
Untrusted snapshot/tar extraction can plant a malformed `objects/info/alternates` file that permanently violates Gitaly's single-alternate invariant, bricking the repository - ([File: internal/gitaly/service/repository/create_repository_from_snapshot.go])

### Summary
`Link()` in `internal/git/objectpool/link.go` is the only sanctioned way Gitaly writes a repository's `objects/info/alternates` file, and it enforces (via `linkedToRepository` and atomic, voted writes) that a repository is linked to at most one alternate object directory. Multiple other subsystems assume this invariant holds unconditionally and have no recovery path if it is violated — mirroring the Hats Protocol bug where `enabledModuleCount` was assumed to track the true module count but could be silently bypassed by another code path, permanently breaking the gate's before/after comparison.

`CreateRepositoryFromSnapshot` and `ReplicateRepository`'s `createFromSnapshot`/`extractSnapshot` bypass `Link()` entirely: they extract a raw tar stream (fetched over HTTP from a caller-supplied URL, or streamed from a "source" Gitaly node) directly onto the new repository's filesystem tree, file-for-file, with only path-traversal checks — not content validation. [1](#0-0) [2](#0-1) 

### Finding Description
Gitaly's documented and enforced object-pool invariant is: "A repository should only ever be linked to a single alternate object directory." [3](#0-2) 

This invariant is normally guaranteed only by `Link()`, which checks whether the repository is already linked and writes a single relative path into `objects/info/alternates` under a lock/vote. [4](#0-3) 

However, `CreateRepositoryFromSnapshot.untar` shells out to `tar -C <path> -xvf -`, extracting an HTTP-fetched archive verbatim into the freshly created bare repository, and the code comment itself acknowledges the archive is "trusted *a lot*" with no hardening in place. [5](#0-4) 

Similarly, `ReplicateRepository`'s snapshot path extracts an arbitrary tar stream from a remote Gitaly node file-by-file (only guarding against path traversal via `filepath` prefix checks — not file content), which would also let a crafted `objects/info/alternates` land unchecked. [6](#0-5) 

Because these code paths write files directly rather than going through `Link()`, an attacker who controls the archive contents (the HTTP endpoint for `CreateRepositoryFromSnapshot`, or a malicious/compromised source repository for `ReplicateRepository`) can embed an `objects/info/alternates` file containing:
- multiple alternate lines, or
- a self-referencing alternate, or
- a chained alternate (an alternate that itself has an alternate).

Once such a repository exists, every subsystem that assumes the single-alternate invariant fails hard and permanently:
- `gitstorage.ReadAlternatesFile` returns `ErrMultipleAlternates` for >1 alternate line, with the comment "Repositories shouldn't have more than one alternate given they should only be linked to a single pool at most." [7](#0-6) 
- `partitionAssigner.getAlternatePartitionID`, used to assign/resolve the WAL partition for the repository, fails outright with `storage.ErrAlternateHasAlternate` if the alternate chain is more than one level deep, or `storage.ErrAlternatePointsToSelf` if the alternate points back at the repository itself. [8](#0-7) 
- `objectpool.Disconnect`, the only mechanism that can remove an alternate link, refuses to run and returns a bare, unrecoverable error if more than one alternate object directory is present. [3](#0-2) 

There is no RPC in the codebase (analogous to a hypothetical `removeModules`) that repairs or truncates a malformed `objects/info/alternates` file once it exists — the only sanctioned writer (`Link`) refuses to overwrite existing alternates content it doesn't recognize, and `Disconnect` bails out instead of fixing multi-line files.

### Impact Explanation
This exactly parallels the Hats Protocol root cause: a security invariant ("at most one/tracked module" vs. "at most one alternate") is enforced only along one blessed code path, while another reachable path (untrusted tar extraction) can silently violate it. Once violated, every downstream check that assumes the invariant (partition assignment, pool disconnect/housekeeping) fails permanently rather than gracefully, with no built-in repair mechanism — a durable denial of service against the affected repository (transactions/partition assignment failing, and object-pool housekeeping/disconnect being permanently blocked).

### Likelihood Explanation
`CreateRepositoryFromSnapshot` is a `MUTATOR` RPC that fetches content from a `HttpUrl` supplied in the request; whoever controls that URL (or a compromised/malicious intermediary) fully controls the extracted file tree, including `objects/info/alternates`. [9](#0-8) 
The RPC's own documentation and code comments already flag it as fetching "trusted *a lot*" content without hardening, which supports that this is a recognized weak boundary rather than a hypothetical one. [10](#0-9) 

I was not able to fully confirm within the available context whether `getAlternatePartitionID` is re-evaluated on every subsequent transaction against the repository or only cached after first assignment; documentation suggests partition assignment happens "when a transaction is began against a repository for the first time," which would still make the first (and creation-time) transaction fail, but I could not verify from the indexed code whether failures at this stage are retried indefinitely on every future access (fully bricking) or fail only once. This is a gap that should be verified by a background agent with full repository access. [11](#0-10) 

### Recommendation
- Validate and sanitize `objects/info/alternates` content (and any other repository-config-like files) after tar/snapshot extraction in `CreateRepositoryFromSnapshot` and `ReplicateRepository`'s snapshot path, rejecting or stripping archives that contain more than one alternate line, self-referencing alternates, or alternate chains, before the repository is considered created.
- Route any alternates present in an extracted snapshot through the same validation used by `Link()` rather than writing them verbatim to disk.
- Add an explicit repair/administrative path (analogous to the Hats fix's suggested `removeModules`) that can safely truncate or reset a malformed multi-line `objects/info/alternates` file so a repository is not permanently stuck once the invariant is violated.

### Proof of Concept
1. Prepare a directory that will be tarred, containing a minimal bare-repo-like layout, but with `objects/info/alternates` containing two lines, e.g.:
   ```
   ../../pool-a/objects
   ../../pool-b/objects
   ```
2. Serve this tar over HTTP (as the test helpers in `create_repository_from_snapshot_test.go` do) and call `CreateRepositoryFromSnapshot` with `HttpUrl` pointing at it. [12](#0-11) 
3. The repository is created successfully because `untar` copies files unconditionally. [13](#0-12) 
4. Subsequent transaction/partition assignment against this repository calls `getAlternatePartitionID`, which reads the alternates file; since it now contains multiple entries, downstream consumers (`gitstorage.ReadAlternatesFile`) return `ErrMultipleAlternates`, and any attempt to run `objectpool.Disconnect` on it permanently fails with `"multiple alternate object directories"` with no code path to remediate it. [14](#0-13) [15](#0-14)

```go
func (s *server) untar(ctx context.Context, path string, in *gitalypb.CreateRepositoryFromSnapshotRequest) error {
	req, err := http.NewRequestWithContext(ctx, "GET", in.GetHttpUrl(), nil)
	if err != nil {
		return structerr.NewInvalidArgument("Bad HTTP URL: %w", err)
	}

	client := httpClient
	if resolvedAddress := in.GetResolvedAddress(); resolvedAddress != "" {
		client, err = newResolvedHTTPClient(in.GetHttpUrl(), resolvedAddress)
		if err != nil {
			return structerr.NewInvalidArgument("creating resolved HTTP client: %w", err)
		}
	}

	if in.GetHttpAuth() != "" {
		req.Header.Set("Authorization", in.GetHttpAuth())
	}

	rsp, err := client.Do(req)
	if err != nil {
		return structerr.NewInternal("HTTP request failed: %w", err)
	}
	defer rsp.Body.Close()

	if rsp.StatusCode < http.StatusOK || rsp.StatusCode >= http.StatusMultipleChoices {
		return structerr.NewInternal("HTTP server: %s", rsp.Status)
	}

	cmd, err := command.New(ctx, s.logger, []string{"tar", "-C", path, "-xvf", "-"}, command.WithStdin(rsp.Body))
	if err != nil {
		return err
	}

	return cmd.Wait()
}
```

```go
func (s *server) extractSnapshot(ctx context.Context, source, target *gitalypb.Repository) error {
	repoClient, err := s.newRepoClient(ctx, source.GetStorageName())
	if err != nil {
		return fmt.Errorf("new client: %w", err)
	}

	stream, err := repoClient.GetSnapshot(ctx, &gitalypb.GetSnapshotRequest{Repository: source})
	if err != nil {
		return fmt.Errorf("get snapshot: %w", err)
	}

	// We need to catch a possible 'invalid repository' error from GetSnapshot. On an empty read,
	// we read the first message from the stream here to get access to the possible 'invalid repository' error.
	firstBytes, err := stream.Recv()
	if err != nil {
		switch {
		case structerr.GRPCCode(err) == codes.NotFound && strings.Contains(err.Error(), "GetRepoPath: not a git repository:"):
			// The error condition exists for backwards compatibility purposes, only,
			// and can be removed in the next release.
			return ErrInvalidSourceRepository
		case structerr.GRPCCode(err) == codes.NotFound && strings.Contains(err.Error(), storage.ErrRepositoryNotFound.Error()):
			return ErrInvalidSourceRepository
		case structerr.GRPCCode(err) == codes.FailedPrecondition && strings.Contains(err.Error(), storage.ErrRepositoryNotValid.Error()):
			return ErrInvalidSourceRepository
		default:
			return fmt.Errorf("first snapshot read: %w", err)
		}
	}

	snapshotReader := io.MultiReader(
		bytes.NewReader(firstBytes.GetData()),
		streamio.NewReader(func() ([]byte, error) {
			resp, err := stream.Recv()
			return resp.GetData(), err
		}),
	)

	targetPath, err := s.locator.GetRepoPath(ctx, target, storage.WithRepositoryVerificationSkipped())
	if err != nil {
		return fmt.Errorf("target path: %w", err)
	}

	// Extract tar using Go's tar package
	if err := s.extractTarToDirectory(ctx, snapshotReader, targetPath); err != nil {
		return fmt.Errorf("extract tar: %w", err)
	}

	return nil
}
```

```go
func (pa *partitionAssigner) getAlternatePartitionID(ctx context.Context, relativePath string, recursiveCall bool, partitionHint storage.PartitionID) (storage.PartitionID, error) {
	alternate, err := gitstorage.ReadAlternatesFile(filepath.Join(pa.storagePath, relativePath))
	if err != nil {
		return 0, fmt.Errorf("read alternates file: %w", err)
	}

	if recursiveCall {
		// recursive being true indicates we've arrived here through another repository's alternate.
		// Repositories in Gitaly should only have a single alternate that points to the repository's
		// pool. Chains of alternates are unexpected and could go arbitrarily long, so fail the operation.
		return 0, storage.ErrAlternateHasAlternate
	}

	// The relative path should point somewhere within the same storage.
	alternateRelativePath, err := storage.ValidateRelativePath(
		pa.storagePath,
		// Take the relative path to the repository, not 'repository/objects'.
		filepath.Dir(
			// The path in alternates file points to the object directory of the alternate
			// repository. The path is relative to the repository's own object directory.
			filepath.Join(relativePath, "objects", alternate),
		),
	)
	if err != nil {
		return 0, fmt.Errorf("validate relative path: %w", err)
	}

	if alternateRelativePath == relativePath {
		// The alternate must not point to the repository itself. Not only is it non-sensical
		// but it would also cause a dead lock as the repository is locked during this call
		// already.
		return 0, storage.ErrAlternatePointsToSelf
	}

	// Recursively get the alternate's partition ID or assign it one. This time
	// we set recursive to true to fail the operation if the alternate itself has an
	// alternate configured.
	ptnID, err := pa.getPartitionIDRecursive(ctx, alternateRelativePath, true, partitionHint, false)
	if err != nil {
		return 0, fmt.Errorf("get partition ID: %w", err)
	}

	return ptnID, nil
}
```
