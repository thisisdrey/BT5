## No vulnerability found for this question.

**Reasoning:** The question's premise is incorrect. In `Nonces<T>` (backing `MaybeLegacyNonces::legacy`), a `Nonce` is `type Nonce = U256` (a `[u8; 32]`), and `NoncePrefix = U248` (`[u8; 31]`). The bit lookup in `BitMap256::get_bit`/`set_bit` destructures the nonce as: [1](#0-0) 

```rust
let [word_pos @ .., bit_pos] = n;   // word_pos: 31 bytes, bit_pos: last byte
```

This split is **exhaustive** over all 32 bytes of the nonce: 31 bytes go to `word_pos` (the map key / `NoncePrefix`) and the 32nd byte goes to `bit_pos`, which is then further decomposed into `byte = bit_pos/8` (indexing into the 32-byte stored bitmap value) and `mask = 1 << (bit_pos % 8)` (indexing the specific bit within that byte). Since `bit_pos` ranges over the full `u8` domain (0–255) and the stored bitmap value has exactly 256 bits, there is a perfect bijection between `bit_pos` and bit-address within the map entry — no two distinct `bit_pos` values alias to the same bit, and no two distinct `word_pos` values alias to the same map key.

Consequently, `(NoncePrefix, bit_pos)` together reconstruct the *entire* 32-byte nonce with no residual bytes left uncovered. Two nonces that share the same `NoncePrefix` and the same last byte (`bit_pos`) are, by construction, the *same* nonce — there is no "collision" scenario where distinct nonce values map to the same bit address while differing in bytes outside the prefix/bit_pos split, because no such uncovered bytes exist.

This is confirmed by the existing property tests in `contracts/defuse/src/contract/accounts/account/nonces.rs`, e.g. `commit_existing_legacy_nonce` and `check_used_nonces`, which commit a set of legacy nonces and then assert that only those exact nonces are reported as used via `MaybeLegacyNonces::is_used`/`commit`, with no false positives observed across randomized nonce sets: [2](#0-1) [3](#0-2) 

The `MaybeLegacyNonces::commit` logic itself only rejects when `legacy.is_used(nonce)` is true for the *exact* nonce being committed: [4](#0-3) 

Since `is_used` cannot return a false positive for a different logical nonce (the prefix+bit_pos split has no ambiguity), the described false-positive replay-block scenario is not reachable. No fund-freezing bug exists here.

    pub fn get_bit(&self, n: U256) -> bool {
        let [word_pos @ .., bit_pos] = n;
        let Some(bitmap) = self.0.get(&word_pos) else {
            return false;
        };
        let byte = bitmap[usize::from(bit_pos / 8)];
        let byte_mask = 1 << (bit_pos % 8);
        byte & byte_mask != 0
    }

    pub fn commit(&mut self, nonce: Nonce) -> Result<()> {
        // Check legacy maps for used nonce
        if self
            .legacy
            .as_ref()
            .is_some_and(|legacy| legacy.is_used(nonce))
        {
            return Err(DefuseError::NonceUsed);
        }

        // New nonces can be committed only to the new map
        self.nonces.commit(nonce)
    }
