### Title
Unauthenticated `RecvError` packets can tear down in-progress/established tunnels before remote-address verification is possible - ([File: outside.go])

### Summary
`handleRecvError` in `outside.go` processes `header.RecvError` packets — a plaintext, unauthenticated, unencrypted control message type handled before any Noise handshake or certificate verification occurs — and unconditionally tears down the referenced tunnel (`closeTunnel` + `DeleteHostInfo`) unless it can prove the sender is spoofing. That anti-spoofing check is only performed when the target `hostinfo` already has a valid recorded remote address; for hostinfo objects whose remote address is not yet set (the common state for a pending/initiating handshake), the check is skipped entirely, letting anyone who observes or guesses a 32-bit index abort the handshake or session at will.

### Finding Description
`readOutsidePackets` dispatches `header.RecvError` packets straight to `f.handleRecvError` immediately after header parsing, with no decryption, no cert check, and no handshake state required: [1](#0-0) 

`handleRecvError` looks up the hostinfo by the attacker-supplied `h.RemoteIndex` and only refuses to act if the hostinfo already has a *valid* recorded remote UDP address that does not match the sender: [2](#0-1) 

The critical gap is the conditional `if hr.IsValid() && hr != addr`. If `hr` (the hostinfo's currently known remote) is *not yet valid* — which is the normal state for an initiator's `HostInfo` while a handshake is still pending, since `SetRemote` is only called once a handshake response is processed in `continueHandshake`/`beginHandshake` — the "someone spoofing recv_errors?" guard never triggers, and the tunnel/handshake is torn down unconditionally: `f.closeTunnel(hostinfo)` followed by `f.handshakeManager.DeleteHostInfo(hostinfo)`.

`RemoteIndex` (the "local index" a peer allocates for its side of the handshake/tunnel) is not a secret: it is transmitted in cleartext in every packet header sent by that host, including the very first plaintext handshake packet. This means the value needed to forge a `RecvError` packet is directly observable by any network-adjacent unauthenticated party, or brute-forceable given only 32 bits of entropy and no rate limiting on this code path. By default, `acceptRecvErrorConfig.ShouldRecvError` (configured via `listen.send_recv_error`) accepts these packets from all senders.

This is a close structural analog to the reported bug class: a state-mutating operation is exposed to an unauthenticated/untrusted actor with insufficient validation of whether the triggering condition is genuine, and the operation can be invoked repeatedly against many targets to force wasted, repeated state resets (repeated handshake aborts/restarts) — exactly the "guaranteed-to-fail-yet-repeatedly-triggered reset" pattern described in the report, but manifesting here as unauthenticated remote-state poisoning/DoS rather than gas waste.

### Impact Explanation
An attacker with no valid Nebula certificate and no established tunnel can:
- Repeatedly abort in-flight handshakes for arbitrary peers by sending forged `RecvError` packets referencing observed/guessed local indexes, forcing perpetual handshake restarts and preventing legitimate tunnels from ever completing (remote state poisoning / availability impact).
- Because the check is skipped only in the pre-remote-set window, this is a genuine unauthenticated bypass of the anti-spoofing protection that the code clearly intends to provide (`"Someone spoofing recv_errors?"` log message demonstrates the intended invariant).

### Likelihood Explanation
Likelihood is moderate-to-high: the packet type requires no cryptographic material, no valid certificate, and no completed handshake. The only "secret" needed is the 32-bit index, which is sent in cleartext by the target host itself in ordinary handshake traffic, making it trivially observable to a network-adjacent attacker and guessable by brute force (2^32 space, no rate limiting present in this path) to an off-path attacker with UDP send access to the victim's listen port.

### Recommendation
Do not rely solely on `hr.IsValid()` to decide whether to validate the sender address. Either (a) refuse to act on `RecvError` for hostinfo whose remote is not yet confirmed (treat "unknown remote" as untrusted, not as "no check needed"), or (b) require the `RecvError` to additionally prove knowledge of session-derived material (e.g., only accept it after the handshake has produced keys, and authenticate/MAC the RecvError content), and add source-based rate limiting for this unauthenticated control path.

### Proof of Concept
1. Node A (initiator) begins a handshake with Node B, sending a stage-0 handshake packet. The plaintext header of that packet embeds A's local index (`RemoteIndex` in packets B will observe corresponds to A's local index).
2. Attacker M, without any Nebula certificate, observes (or brute-forces) that index and crafts a `header.RecvError` packet with `RemoteIndex` set to A's index, spoofing any source UDP address, and sends it to A's listen port.
3. On A, `readOutsidePackets` routes it to `handleRecvError` before any decryption/authentication: [3](#0-2) 
4. `QueryReverseIndex` finds A's pending `HostInfo` for the handshake with B. Since A's `hostinfo.GetRemote()` has not yet been set (A hasn't yet confirmed which of B's candidate remotes is live), `hr.IsValid()` is false, and the spoofing check is bypassed: [4](#0-3) 
5. `f.closeTunnel(hostinfo)` and `f.handshakeManager.DeleteHostInfo(hostinfo)` execute, aborting the handshake attempt. Repeating this for every new handshake attempt permanently prevents A from establishing a tunnel to B, at negligible attacker cost and with no certificate or CA trust required.

func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
