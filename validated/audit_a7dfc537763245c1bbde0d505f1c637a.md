### Title
Stale per-connection stake snapshot causes incorrect QUIC QoS classification for the life of a connection - ([File: streamer/src/nonblocking/swqos.rs])

### Summary
`SwQos::build_connection_context` looks up a peer's stake once, at connection-establishment time, via `get_connection_stake(connection, &self.staked_nodes)` [1](#0-0) . The resulting `peer_type` and `total_stake` are cached inside `SwQosConnectionContext` and reused for every subsequent stream on that connection — including the stream-throttling and concurrency limit decisions in `on_new_stream`/`max_streams_per_throttling_interval` and `cache_new_connection`'s `compute_max_allowed_uni_streams_with_rtt` call — without ever being refreshed from the live `staked_nodes` map for the remainder of the connection's lifetime [2](#0-1) [3](#0-2) .

### Finding Description
This mirrors the reported bug class exactly: an economically/QoS-significant decision (here, tier classification and stream/bandwidth entitlement instead of DeFi fee direction) is made from a value cached at one point in time (`zkusdAmounts[_token]` in the report; `SwQosConnectionContext.total_stake`/`peer_type` here) and never updated to reflect the authoritative, live source of truth (the token price feed there; the `staked_nodes` `RwLock<StakedNodes>` map here). The live map is only refreshed cluster-wide by `StakedNodesUpdaterService` on a `STAKE_REFRESH_CYCLE` of 5 seconds using the root bank's `current_epoch_staked_nodes()` [4](#0-3) , but that refresh only affects the shared map — it does not touch already-open connections, because `SwQos` never re-derives `peer_type`/`total_stake` for an existing `SwQosConnectionContext` after `build_connection_context` runs once at connection accept time.

As a result, a peer that is staked (or highly staked) at connection-open time is permanently classified as `ConnectionPeerType::Staked(stake)` with the original `total_stake` for as long as the QUIC connection stays open, even if the underlying stake later drops to zero (unstake, deactivation, slashing-equivalent stake removal) or drastically changes relative to total network stake. Because `compute_max_allowed_uni_streams_with_rtt` and `max_streams_per_throttling_interval` (via `StakedStreamLoadEMA::available_load_capacity_in_throttling_duration`) both key off this stale `peer_type`/`total_stake`, the peer keeps receiving the elevated stream/uni-stream concurrency and throttling allowance appropriate to its old stake rather than its current (possibly zero) stake.

### Impact Explanation
This is a QoS-evasion analog to the reported "outdated cached value causes wrong economic direction" bug: an unprivileged QUIC client can retain preferential, stake-weighted transaction-forwarding bandwidth on the TPU/QUIC streamer indefinitely by simply keeping a single connection alive after unstaking, bypassing the SWQoS mechanism's intent of granting bandwidth proportional to *current* stake. Because streaming/bandwidth allowance is the resource being mis-priced (analogous to the mispriced fee in the report), this degrades the fairness/anti-DoS guarantees SWQoS is designed to provide, and could be leveraged to keep sending high-volume unstaked traffic at staked-tier throughput by holding the connection open across a stake-loss event.

### Likelihood Explanation
Reachable by any ordinary (unprivileged) client that can open a QUIC connection to the TPU streamer — no validator/operator privilege is required. The only precondition is that the peer be staked (even minimally, above `min_stake_ratio`) at connection-open time and subsequently lose/reduce stake while keeping the connection alive; connections can remain open indefinitely absent idle-timeout/pruning, and pruning in `prune_unstaked_connection_table`/`prune_random` operates on connection count pressure, not on stake staleness, so a connection is not proactively re-evaluated when the underlying stake changes.

### Recommendation
Periodically re-resolve `peer_type`/`total_stake` for already-open connections (e.g., on each `on_new_stream` call, or via a background sweep keyed off `StakedNodesUpdaterService`'s refresh cycle) rather than caching it once in `SwQosConnectionContext` for the connection's full lifetime, so that stream-throttling and concurrency decisions reflect the peer's current stake rather than a point-in-time snapshot.

### Proof of Concept
1. A validator/peer with nonzero stake opens a QUIC connection to a node's TPU streamer; `SwQos::build_connection_context` classifies it `ConnectionPeerType::Staked(stake)` with `total_stake` captured from `staked_nodes` at that instant [1](#0-0) .
2. The peer's stake subsequently drops to zero (deactivated/unstaked) in a later epoch; `StakedNodesUpdaterService` updates the shared `staked_nodes` map within 5 seconds [4](#0-3) , but the peer keeps its original QUIC connection open.
3. Every subsequent stream on that connection still uses the cached `SwQosConnectionContext.peer_type`/`total_stake` in `on_new_stream` → `max_streams_per_throttling_interval` → `StakedStreamLoadEMA::available_load_capacity_in_throttling_duration`, and the connection's `max_uni_streams` was already fixed at accept-time by `compute_max_allowed_uni_streams_with_rtt` in `cache_new_connection` [5](#0-4) , granting staked-tier throughput to a now-unstaked peer for the connection's remaining lifetime.

fn compute_max_allowed_uni_streams_with_rtt(
    rtt_millis: u32,
    peer_type: ConnectionPeerType,
    total_stake: u64,
) -> u32 {
    let streams = match peer_type {
        ConnectionPeerType::Staked(peer_stake) => {
            // No checked math for f64 type. So let's explicitly check for 0 here
            if total_stake == 0 || peer_stake > total_stake {
                warn!(
                    "Invalid stake values: peer_stake: {peer_stake:?}, total_stake: \
                     {total_stake:?}"
                );

                QUIC_MIN_STAKED_CONCURRENT_STREAMS
            } else {
                let delta = (QUIC_TOTAL_STAKED_CONCURRENT_STREAMS
                    - QUIC_MIN_STAKED_CONCURRENT_STREAMS) as f64;

                (((peer_stake as f64 / total_stake as f64) * delta) as u32
                    + QUIC_MIN_STAKED_CONCURRENT_STREAMS)
                    .clamp(
                        QUIC_MIN_STAKED_CONCURRENT_STREAMS,
                        QUIC_MAX_STAKED_CONCURRENT_STREAMS,
                    )
            }
        }
        ConnectionPeerType::Unstaked => QUIC_MAX_UNSTAKED_CONCURRENT_STREAMS,
    };
    // scale amount of streams based on RTT if RTT is larger than REFERENCE_RTT_MS
    // multiply first then divide to avoid rounding errors.
    (streams.saturating_mul(rtt_millis.clamp(REFERENCE_RTT_MS, MAX_RTT_MS))) / REFERENCE_RTT_MS
}

impl SwQos {
    fn cache_new_connection(
        &self,
        client_connection_tracker: ClientConnectionTracker,
        connection: &Connection,
        mut connection_table_l: MutexGuard<ConnectionTable<ConnectionStreamCounter>>,
        conn_context: &SwQosConnectionContext,
    ) -> Result<
        (
            Arc<AtomicU64>,
            CancellationToken,
            Arc<ConnectionStreamCounter>,
        ),
        ConnectionHandlerError,
    > {
        // get current RTT and limit it to MAX_RTT_MS right away
        let rtt_millis = connection.rtt().as_millis().min(MAX_RTT_MS as u128) as u32;
        let max_uni_streams = VarInt::from_u32(compute_max_allowed_uni_streams_with_rtt(
            rtt_millis,
            conn_context.peer_type(),
            conn_context.total_stake,
        ));
        let remote_addr = conn_context.remote_address;

        let max_connections_per_peer = match conn_context.peer_type() {
            ConnectionPeerType::Unstaked => self.config.max_connections_per_unstaked_peer,
            ConnectionPeerType::Staked(_) => self.config.max_connections_per_staked_peer,
        };
        if let Some((last_update, cancel_connection, stream_counter)) = connection_table_l
            .try_add_connection(
                ConnectionTableKey::new(remote_addr.ip(), conn_context.remote_pubkey),
                remote_addr.port(),
                client_connection_tracker,
                Some(connection.clone()),
                conn_context.peer_type(),
                conn_context.last_update.clone(),
                max_connections_per_peer,
                || Arc::new(ConnectionStreamCounter::new()),
            )
        {
            update_open_connections_stat(&self.stats, &connection_table_l);
            drop(connection_table_l);

            connection.set_max_concurrent_uni_streams(max_uni_streams);
            debug!(
                "Peer type {:?}, total stake {}, max streams {} from peer {}",
                conn_context.peer_type(),
                conn_context.total_stake,
                max_uni_streams.into_inner(),
                remote_addr,
            );
            Ok((last_update, cancel_connection, stream_counter))
        } else {
            self.stats
                .connection_add_failed
                .fetch_add(1, Ordering::Relaxed);
            Err(ConnectionHandlerError::ConnectionAddError)
        }
    }

pub struct StakedNodesUpdaterService {

impl StakedNodesUpdaterService {
    pub fn new(
        exit: Arc<AtomicBool>,

        staked_nodes: Arc<RwLock<StakedNodes>>,

        let thread_hdl = Builder::new()
            .name("solStakedNodeUd".to_string())
            .spawn(move || {
                while !exit.load(Ordering::Relaxed) {
                    let stakes = {
                        let root_bank = bank_forks.read().unwrap().root_bank();
                        root_bank.current_epoch_staked_nodes()
                    };
                    let overrides = staked_nodes_overrides.read().unwrap().clone();
                    *staked_nodes.write().unwrap() = StakedNodes::new(stakes, overrides);
                    std::thread::sleep(STAKE_REFRESH_CYCLE);
