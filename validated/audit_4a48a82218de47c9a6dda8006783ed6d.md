### Title
Unauthenticated `/shutdown` POST terminates the signer's event receiver - ([File: libsigner/src/events.rs])

### Summary
The `SignerEventReceiver::next_event` handler in `libsigner/src/events.rs` matches the request URL against `/shutdown` and, upon a match, unconditionally sets `stop_signal` to `true` and returns `Err(EventError::Terminated)`, with no check of any credential, secret, or peer identity. Any TCP client that can reach the signer's configured event-receiver endpoint (the address configured for the node-to-signer event feed) can send a single `POST /shutdown` and permanently halt the signer's event-processing loop.

### Finding Description
The claimed equality/fault: the party permitted to POST `/shutdown` must be the locally-configured Stacks node that the signer trusts (the only legitimate caller of this endpoint, as evidenced by `SignerStopSignaler::send()` at [1](#0-0)  constructing this exact POST to self-wake the receiver). No such check exists: the branch that handles this URL only inspects the string path, never any header, token, or source-identity: [2](#0-1) 

This is reached directly from `next_event()`, which is called every iteration of `EventReceiver::main_loop`: [3](#0-2) 

Exploit flow: an attacker opens a raw TCP connection to the signer's bound event-receiver socket (`SignerEventReceiver::bind`, [4](#0-3) ) and sends a minimal, well-formed HTTP/1.1 POST to `/shutdown` (no body needed, any `Content-Length` accepted, no auth header required — matching exactly what `SignerStopSignaler::send()` itself sends). `next_event()` matches `request.url() == "/shutdown"`, sets `stop_signal.store(true, Ordering::SeqCst)`, and returns `Err(EventError::Terminated)`. `main_loop` then hits the `Err(EventError::Terminated)` arm and `break`s, permanently exiting the event-receiver thread. No existing guard — no `MAX_MESSAGE_LEN`, signature check, or auth gate — is present on this code path since the HTTP server (`tiny_http`-based `HttpServer`) has no authentication layer at all in this file, and the other endpoints (`/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block`) similarly lack authentication but at least require a well-formed, deserializable payload; `/shutdown` requires nothing.

### Impact Explanation
A single unauthenticated POST permanently terminates the signer's event-receiver thread, which is the sole channel by which the signer node learns of `StackerDBChunksEvent`, block-validation responses, new burn blocks, and new Stacks blocks. Once terminated, the signer stops receiving/relaying nakamoto block-signing events, effectively removing that signer from the signing set until manually restarted — a remote, unauthenticated denial of service achievable with one crafted HTTP request, and trivially repeatable against any signer whose endpoint address is network-reachable. This matches the "Critical - remote crash/unauthenticated DoS from few messages" category.

### Likelihood Explanation
Preconditions: the attacker only needs network connectivity to the signer's configured event-receiver bind address/port (the interface/port operators configure for the node to POST events to the signer, per `stacks-signer/src/config.rs`). No node-runner secret, peer key, or StackerDB slot ownership is needed — the vulnerable check exists purely on URL string matching with zero credential verification. If operators bind this listener to a non-loopback interface (common in multi-host or containerized signer/node deployments) or the interface is otherwise reachable (e.g., via SSRF from another service, or a misconfigured firewall), the attack is a single low-cost HTTP POST, trivially repeatable.

### Recommendation
Add authentication to the `/shutdown` endpoint (and ideally the entire event-receiver HTTP surface): require a shared secret/HMAC or mTLS between the stacks-node and the signer's event receiver, verified before honoring `/shutdown` (and before processing any other event). At minimum, restrict `bind()` to loopback by default and document/enforce that this listener must never be exposed to untrusted networks, and add a constant-time credential check inside the `/shutdown` branch in `libsigner/src/events.rs` before calling `stop_signal.store(true, ...)`.

### Proof of Concept
```rust
// libsigner/tests/shutdown_dos.rs (test plan)
use std::io::Write;
use std::net::TcpStream;
use std::sync::mpsc::channel;
use libsigner::{EventReceiver, SignerEventReceiver, SignerEvent};

#[test]
fn unauthenticated_shutdown_terminates_receiver() {
    let mut receiver: SignerEventReceiver<SignerEvent<()>> = SignerEventReceiver::new(false);
    let addr = "127.0.0.1:0".parse().unwrap();
    let bound_addr = receiver.bind(addr).unwrap();
    let (tx, _rx) = channel();
    receiver.add_consumer(tx);

    // spawn main_loop in background thread
    let handle = std::thread::spawn(move || {
        receiver.main_loop();
    });

    // "Attacker" with no credentials sends raw POST /shutdown
    let mut stream = TcpStream::connect(bound_addr).unwrap();
    let req = "POST /shutdown HTTP/1.1\r\nHost: x\r\nConnection: close\r\nContent-Length: 0\r\n\r\n";
    stream.write_all(req.as_bytes()).unwrap();

    // Assert: main_loop thread exits promptly (event receiver stopped)
    // without any credential ever being presented.
    handle.join().expect("main_loop should exit due to unauthenticated /shutdown");
}
```
Expected/observed result: the background thread running `main_loop()` exits after the single unauthenticated request, confirming `is_stopped()` becomes true via [2](#0-1)  and `main_loop` breaks at [5](#0-4) , with no credential ever checked.

    fn main_loop(&mut self) {

                Ok(event) => event,

                    // got an event that we don't care about (not a problem)
                    continue;
                }

                    // we're done
                    info!("Caught termination signal");
                    break;

                    continue;
                }
            };

                info!("Failed to forward event");
                break;
            }
        }
