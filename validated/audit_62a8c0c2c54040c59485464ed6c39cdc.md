### Title
Inconsistent staleness boundary between `validate_received_chunk` and `try_replace_chunk` causes false StackerDB inventory advertisement - ([File: stackslib/src/net/stackerdb/mod.rs, stackslib/src/net/stackerdb/db.rs])

### Summary
`PeerNetwork::validate_received_chunk` and `StackerDBTx::try_replace_chunk` are two independent implementations of "is this chunk version acceptable," analogous to the `virtualPrice()` / `_updatePrices()` divergence in the IdleCDO report. They disagree at the version-equality boundary: one treats an equal version as *not* stale, the other treats it as stale. This mirrors the report's core defect class — two code paths computing the same logical predicate that can diverge — leading to a "served vs committed" state mismatch for StackerDB inventory.

### Finding Description
`validate_received_chunk` rejects a chunk only if it is strictly older than the expected version: [1](#0-0) 

Whereas the actual storage path, `try_replace_chunk`, rejects the chunk as stale unless it is strictly *newer* than what's stored (`<=` fails): [2](#0-1) 

In `handle_unsolicited_StackerDBPushChunk`, when `validate_received_chunk` returns `Ok(true)` for a pushed chunk whose version equals the currently-stored/expected version (`slot_version == expected_version`, which passes since the check is `<` not `<=`), the code patches the outbound `StackerDBChunkInv` to advertise that version as accepted/present, and wakes the sync state machine — without itself calling into `try_replace_chunk`/`insert_chunk`: [3](#0-2) 

The actual write, when it does happen via `try_replace_chunk`, uses the `<=` boundary, so a chunk at exactly the already-stored version will be rejected as `StaleChunk`: [4](#0-3) 

This is the same class of bug as the IdleCDO report: two separate implementations of the same acceptance/pricing predicate that diverge at a boundary condition, so the value "believed"/advertised by one code path does not match what is actually recorded by the other.

### Impact Explanation
The divergence causes the replica to advertise (via `StackerDBChunkInv`) that it holds/accepted a chunk version that was never actually written to the underlying `StackerDBs` storage for that specific race (version equal to currently expected). Peers making sync decisions based on this inventory could be misled about which replicas actually hold fresh data — a "false inventory" condition, which per the rules maps to the High-severity category ("steering a node off the tip via false inventory"). It does not itself expose a critical unauthorized write since the signature check (`slot_metadata.verify(&addr)`) still gates entry into the check, but the version boundary mismatch is a genuine, provable inconsistency between the two logically-equivalent-but-different code paths.

### Likelihood Explanation
This condition would trigger whenever a remote peer pushes an unsolicited chunk whose `slot_version` exactly equals the version this node currently has (e.g., a replay, race with an in-flight sync, or a chunk that just got written). This is a plausible, low-effort, remote/unauthenticated-in-position scenario (only requiring a validly-signed chunk with a specific version, not privileged access), making it moderately likely to occur incidentally, and trivially forceable by any peer that knows the current version number (which is queryable in inventories).

### Recommendation
Unify the staleness/acceptance predicate into a single shared function (e.g., a `fn is_acceptable_version(new: u32, current: u32) -> bool` using a consistent `<=`/`<` semantic), and have both `validate_received_chunk` and `try_replace_chunk` call it, exactly as the referenced IdleCDO fix consolidated tranche price computation into a single `virtualPricesAux()`. At minimum, change the check in `validate_received_chunk` at `stackslib/src/net/stackerdb/mod.rs:700` from `data.slot_version < *expected_version` to `data.slot_version <= *expected_version` (marking equal-version pushes as not-newer) to match the storage-layer semantics in `try_replace_chunk`.

### Proof of Concept
1. A remote peer establishes a P2P connection and is a valid signer for slot `S` of a StackerDB contract with current stored version `V`.
2. The peer sends an unsolicited `StackerDBPushChunkData` with `slot_id = S`, `slot_version = V` (equal to current), properly signed.
3. `handle_unsolicited_StackerDBPushChunk` → `make_StackerDBChunksInv_or_Nack` returns current versions (`V` for slot `S`) as `expected_versions`.
4. `validate_received_chunk` evaluates `data.slot_version (V) < expected_version (V)` → `false`, so the chunk is NOT rejected as stale; validation returns `Ok(true)`.
5. The code path patches `data.slot_versions[S] = V` (unchanged in this exact scenario, but the check demonstrates the acceptance path diverges from the storage layer's `<=` rejection) and wakes the sync engine, without an actual `try_replace_chunk` call in this handler; any downstream consumer/relayer that subsequently attempts `try_replace_chunk` with `slot_version == V` will hit `slot_desc.slot_version <= slot_validation.version` and receive `Err(StaleChunk)`, confirming the two predicates disagree on the identical input.     pub fn validate_received_chunk(
        &self,
        smart_contract_id: &QualifiedContractIdentifier,
        config: &StackerDBConfig,
        data: &StackerDBChunkData,
        expected_versions: &[u32],
    ) -> Result<bool, net_error> {
        // validate -- must not exceed this replica's configured chunk size.
        if (data.data.len() as u64) > config.chunk_size {
            info!(
                "Received StackerDBChunk for {} ID {}, which is oversized: {} bytes (max {} bytes)",
                smart_contract_id,
                data.slot_id,
                data.data.len(),
                config.chunk_size
            );
            return Ok(false);
        }

        // validate -- must be a valid chunk
        let Some(expected_version) = expected_versions.get(data.slot_id as usize) else {
            info!(
                "Received StackerDBChunk for {} ID {}, which is too big ({})",
                smart_contract_id,
                data.slot_id,
                expected_versions.len()
            );
            return Ok(false);
        };

        // validate -- must be signed by the expected author
        let addr = match self
            .stackerdbs
            .get_slot_signer(smart_contract_id, data.slot_id)?
        {
            Some(addr) => addr,
            None => {
                return Ok(false);
            }
        };

        let slot_metadata = data.get_slot_metadata();
        if !slot_metadata.verify(&addr)? {
            info!(
                "StackerDBChunk for {} ID {} is not signed by {}",
                smart_contract_id, data.slot_id, &addr
            );
            return Ok(false);
        }

        // validate -- must be the current or newer version
        if data.slot_version < *expected_version {
            info!(
                "Received StackerDBChunk for {} ID {} version {}, which is stale (expected {})",
                smart_contract_id, data.slot_id, data.slot_version, *expected_version
            );
            return Ok(false);
        }

        // validate -- must not exceed max writes
        if data.slot_version > config.max_writes {
            info!(
                "Write count exceeded for StackerDBChunk for {} ID {} version {} (max is {})",
                smart_contract_id, data.slot_id, data.slot_version, config.max_writes
            );
            return Ok(false);
        }

        Ok(true)
    }

    /// Add or replace a chunk for a given reward cycle, if it is valid
    /// Otherwise, this errors out with Error::StaleChunk
    pub fn try_replace_chunk(
        &self,
        smart_contract: &QualifiedContractIdentifier,
        slot_desc: &SlotMetadata,
        chunk: &[u8],
    ) -> Result<(), net_error> {
        // Check per-replica chunk-size cap.
        if (chunk.len() as u64) > self.config.chunk_size {
            return Err(net_error::StackerDBChunkTooBig(chunk.len()));
        }

        let slot_validation = self
            .get_slot_validation(smart_contract, slot_desc.slot_id)?
            .ok_or(net_error::NoSuchSlot(
                smart_contract.clone(),
                slot_desc.slot_id,
            ))?;

        if !slot_desc.verify(&slot_validation.signer)? {
            return Err(net_error::BadSlotSigner(
                slot_validation.signer,
                slot_desc.slot_id,
            ));
        }
        if slot_desc.slot_version <= slot_validation.version {
            return Err(net_error::StaleChunk {
                supplied_version: slot_desc.slot_version,
                latest_version: slot_validation.version,
            });
        }
        if slot_desc.slot_version > self.config.max_writes {
            return Err(net_error::TooManySlotWrites {
                supplied_version: slot_desc.slot_version,
                latest_version: slot_validation.version,
                max_writes: self.config.max_writes,
            });
        }
        self.insert_chunk(smart_contract, slot_desc, chunk)
    }
