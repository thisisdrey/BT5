## Analysis

The core theme of the referenced report is that a security control meant to block requests to internal/local addresses can be defeated because the *string parsed to determine the target host* diverges from the *string actually used to connect*. Gitaly has a directly analogous mechanism: `GetURLAndResolveConfig` in [1](#0-0)  exists specifically to pin `git`'s connection to a pre-validated (by GitLab Rails) `resolved_address`, defeating DNS-rebinding/SSRF where an attacker's hostname resolves to a private IP only at connection time. This is invoked from `FetchRemote` (pull mirrors), `UpdateRemoteMirror` (push mirrors), `CreateRepositoryFromURL` (project import) and `FindRemoteRootRef` — all reachable via ordinary user-controlled `remote_url`/`resolved_address` fields, as documented in [2](#0-1)  and used in [3](#0-2)  and [4](#0-3) .

The SCP-style branch, `getURLAndResolveConfigForSCP`, uses two independent and inconsistent heuristics to rewrite the URL — splitting on the first `:` to find `host:path`, but splitting separately on the first `@` to find `user@` — and then blindly recombines them assuming `hostAndPath[0]` is exactly `[user@]host`: [5](#0-4) 

If the untrusted `remoteURL`'s path segment (everything after the first `:`) contains an `@` while there is no explicit `user@` before the host, `strings.SplitAfterN(remoteURL, "@", 2)` matches that later `@` instead, so `userPrefix` absorbs the **original, un-vetted hostname** verbatim, and the resolved (vetted) IP is spliced into the wrong position — inside the path — having no effect on which host `git` actually contacts.

## Title
DNS-rebinding/SSRF protection bypass via inconsistent URL-token splitting in SCP-style remote URL rewriting - (File: internal/git/gitcmd/command_resolve.go)

## Summary
`GetURLAndResolveConfig` is Gitaly's enforcement point for pinning outbound Git network operations (fetch, push-mirror, pull-mirror, `CreateRepositoryFromURL` import) to a `resolved_address` that GitLab Rails validated is not a local/private IP. For SCP-style URLs (`[user@]host:path`, the default form used for most SSH remotes such as `git@host:group/repo.git`), the rewriting function `getURLAndResolveConfigForSCP` derives the host boundary using a naive first-`:`-and-first-`@` split. A crafted URL whose path segment contains an `@` character causes the function to misidentify the host token, leaving the original untrusted hostname embedded in the rewritten command-line argument passed to `git`, while the validated resolved IP address is spliced into an inert position.

## Finding Description
Callers such as `FetchRemote`, `UpdateRemoteMirror`, and `CreateRepositoryFromURL` accept a `remote.url` and a separately-validated `remote.resolved_address` from the caller (GitLab Rails), which performs SSRF filtering by resolving the hostname and rejecting local/reserved ranges before invoking Gitaly. Because DNS resolution done in Rails is not guaranteed to still be valid by the time `git` connects (TOCTOU/DNS rebinding), Gitaly is expected to force `git` to use the *already-validated* IP rather than re-resolving the attacker-supplied hostname, via `GetURLAndResolveConfig`.

For SCP-style syntax, this pinning is done by literally rewriting the URL string in [5](#0-4) . The function:
1. Splits `remoteURL` on the first `:` to get `hostAndPath`.
2. Independently splits the *whole* `remoteURL` on the first `@` to compute `userPrefix`.
3. Reassembles as `userPrefix + resolvedAddress + ":" + hostAndPath[1]`, assuming `hostAndPath[0]` is exactly `userPrefix + host`.

This assumption breaks when the path (`hostAndPath[1]`) itself contains an `@` and there is no user segment before the host: the first `@` found is inside the path, so `userPrefix` swallows the original host plus part of the path verbatim, and the resolved IP is placed inside the path rather than replacing the host. The resulting string handed to `git clone`/`git fetch` still contains the original, unvalidated hostname where `git`'s own URL parser will find it, so `git` performs its own DNS resolution of the attacker-controlled hostname — completely bypassing the anti-DNS-rebinding purpose of the function.

## Impact Explanation
Since Gitaly's IP-pinning is the last line of defense against DNS rebinding for push mirrors, pull mirrors, and URL-based project imports, a bypass here allows a user who controls a mirror/import URL (an ordinary, non-privileged action in GitLab) to make the Gitaly node perform an outbound Git operation (fetch or push) against an internal/private address of the attacker's choosing, at the exact moment `git` resolves the hostname — a classic SSRF via DNS-rebinding, potentially exposing internal services, cloud metadata endpoints, or triggering credential/header disclosure via `http.extraHeader`/SSH key material configured for that remote.

## Likelihood Explanation
Reachable from unprivileged, standard GitLab actions: configuring a pull mirror (`FetchRemote`), a push mirror (`UpdateRemoteMirror`), or importing a repository by URL (`CreateRepositoryFromURL`), all of which accept attacker-controlled SCP-style SSH URLs — a very common transport form for Git remotes. No elevated privileges, leaked tokens, or MITM position are required; the only requirement is the ability to specify a repository URL, and the ability to control (or point) the crafted host component.

## Recommendation
Rewrite `getURLAndResolveConfigForSCP` to derive the host boundary using a single, git-compatible parsing pass (mirroring `git`'s own SCP-like URL grammar: locate the user boundary as the last `@` occurring before the first `/`, then split the remainder on the first `:`), instead of two independent, order-dependent `SplitN` calls on the raw string. Add regression tests covering paths containing `@` characters, multiple `@` occurrences, and no explicit user segment.

## Proof of Concept
Given `remoteURL = "127.0.0.1:22/x@y.git"` and `resolvedAddress = "203.0.113.5"` (a validated public IP substituted by Rails for an originally-resolved-to-private hostname):
- `hostAndPath := strings.SplitN(remoteURL, ":", 2)` → `["127.0.0.1", "22/x@y.git"]`
- `userAndHost := strings.SplitAfterN(remoteURL, "@", 2)` → `["127.0.0.1:22/x@", "y.git"]` (the only `@` is inside the path) → `userPrefix = "127.0.0.1:22/x@"`
- Result: `fmt.Sprintf("%s%s:%s", userPrefix, resolvedAddress, hostAndPath[1])` → `"127.0.0.1:22/x@203.0.113.5:22/x@y.git"`

The original host `127.0.0.1` remains present verbatim in the command-line argument that is subsequently passed to `git clone`/`git fetch` in `Args: []string{urlString, repositoryFullPath}` [6](#0-5) , so `git` will resolve and connect to the original, attacker-controlled hostname rather than the vetted `resolved_address`, defeating the anti-DNS-rebinding purpose of the mechanism.

func GetURLAndResolveConfig(remoteURL string, resolvedAddress string) (string, []ConfigPair, error) {
	if remoteURL == "" {
		return "", nil, fmt.Errorf("URL is empty")
	}

	if resolvedAddress == "" {
		return "", nil, fmt.Errorf("resolved address is empty")
	}

	resolvedIP := net.ParseIP(resolvedAddress)
	if resolvedIP == nil {
		return "", nil, fmt.Errorf("resolved address has invalid IPv4/IPv6 address")
	}

	switch {
	case strings.HasPrefix(remoteURL, "http://"), strings.HasPrefix(remoteURL, "https://"), strings.HasPrefix(remoteURL, "git://"):
		return getURLAndResolveConfigForURL(remoteURL, resolvedAddress)
	case strings.HasPrefix(remoteURL, "ssh://"):
		return getURLAndResolveConfigForSSH(remoteURL, resolvedAddress)
	default:
		return getURLAndResolveConfigForSCP(remoteURL, resolvedAddress)
	}
}

func getURLAndResolveConfigForSCP(remoteURL, resolvedAddress string) (string, []ConfigPair, error) {
	hostAndPath := strings.SplitN(remoteURL, ":", 2)
	if len(hostAndPath) != 2 {
		return "", nil, fmt.Errorf("invalid protocol/URL encountered: %s", remoteURL)
	}

	if strings.Contains(hostAndPath[0], "/") {
		return "", nil, fmt.Errorf("SSH URLs with '/' before colon are unsupported")
	}

	var userPrefix string

	if userAndHost := strings.SplitAfterN(remoteURL, "@", 2); len(userAndHost) > 1 {
		userPrefix = userAndHost[0]
	}

	return fmt.Sprintf("%s%s:%s", userPrefix, resolvedAddress, hostAndPath[1]), nil, nil
}
