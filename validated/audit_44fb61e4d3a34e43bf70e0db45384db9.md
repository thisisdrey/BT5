Audit Report

## Title
`System` precompile's `terminate`/`ownCodeHash` derive identity from `env.caller()` without a delegatecall guard - (File: `substrate/frame/revive/src/precompiles/builtin/system.rs`)

## Summary
The `System` builtin precompile (fixed address `0x900`) implements `terminate(beneficiary)` and `ownCodeHash()` by reading `env.caller()`/invoking `env.terminate_caller()` directly, without ever checking `env.is_delegate_call()`. Every sibling precompile that consumes caller identity for privileged operations (ERC20, asset-conversion, XCM, vesting) was explicitly hardened in PR #11715 with a `PrecompileDelegateDenied` guard precisely because `env.caller()` resolves to the original external caller during `DELEGATECALL`, not the delegating contract — `System::call` was left out of that fix.

## Finding Description
`System::call` matches on `ISystemCalls::terminate` and `ISystemCalls::ownCodeHash` and unconditionally reads `env.caller()` / calls `env.terminate_caller(&h160)` [1](#0-0) . No arm in the whole `match` on `input` checks `env.is_delegate_call()` anywhere in the function [2](#0-1) . As documented for the underlying `caller()` host function, in a nested-call context the identity returned is "the address of the contract" that invoked the current frame — and, per the delegatecall semantics fixed in PR #11715, under `DELEGATECALL` this identity is inherited from the *original* caller of the delegating frame rather than the delegating contract itself [3](#0-2) . Sibling precompiles that touch caller identity for state-changing operations (ERC20 [4](#0-3) , XCM [5](#0-4) , vesting [6](#0-5) ) all guard with `ensure!(!env.is_delegate_call(), ...PrecompileDelegateDenied)`, and this pattern was introduced project-wide via PR #11715 explicitly to close this exact hazard [7](#0-6) . `System::call` was not updated with this guard, so `terminate` and `ownCodeHash` remain exposed to the same class of misidentification when invoked via `DELEGATECALL`.

## Impact Explanation
`terminate` self-destructs the calling contract's code/storage and redirects its remaining balance to `beneficiary`, and `ownCodeHash` returns a code hash keyed off the resolved caller's mapped address. If a contract is induced to `DELEGATECALL` into `0x900` (e.g. via a shared "system library" pattern), the precompile resolves identity from the delegatecall-propagated caller rather than rejecting the call, unlike every other precompile that was patched for this exact scenario. This directly matches the accepted impact categories of unauthorized execution/origin escalation and unbacked/unintended fund redirection through `terminate`'s beneficiary transfer.

## Likelihood Explanation
No privileged actor is required — any ordinary contract-composition pattern (proxy, shared library, or contract that trusts and delegatecalls to an address it does not fully control) reaching `0x900` triggers the flawed identity resolution. Since PR #11715 patched every other precompile for exactly this reachable, attacker-triggerable condition and left `System` unpatched, the gap is a straightforward, directly exploitable oversight rather than a defense-in-depth or purely theoretical concern.

## Recommendation
Add the same guard used elsewhere, at minimum before the `terminate` and `ownCodeHash` arms in `System::call`:
```rust
frame_support::ensure!(
    !env.is_delegate_call(),
    crate::Error::<T>::PrecompileDelegateDenied,
);
```
consistent with the ERC20, asset-conversion, XCM, and vesting precompiles.

## Proof of Concept
1. Deploy `Victim`, a contract that `DELEGATECALL`s to `0x900` encoding `terminate(beneficiary)` (mirroring shared "system library" usage patterns).
2. Have an attacker-influenced code path reach this delegatecall (e.g., via a shared/upgradeable library address resolving to `0x900`, or the attacker's own frame delegatecalling into `System`).
3. Inside `System::call`, `env.terminate_caller(&h160)` executes using the delegatecall-propagated caller identity without any `is_delegate_call()` rejection, unlike the guarded sibling precompiles [8](#0-7) .
4. `terminate_caller` deletes code/storage and transfers the resolved account's balance to the attacker-supplied `beneficiary`, demonstrating unauthorized state mutation tied to a misidentified caller.

fn ensure_mutable<T: Config>(env: &impl Ext<T = T>) -> Result<(), Error> {
	if env.is_read_only() {
		return Err(pallet_revive::Error::<T>::StateChangeDenied.into());
