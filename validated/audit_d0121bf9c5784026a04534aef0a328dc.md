### Title
Unauthenticated `RecvError` packets allow remote tunnel teardown before the remote address is roamed/pinned - ([File: outside.go])

### Summary
`header.RecvError` is processed as a fully unauthenticated, unencrypted control message, before any decryption or certificate validation occurs. The one address check that exists to prevent spoofed teardown is skipped entirely whenever the target hostinfo's remote address is not yet "valid" (e.g., a pending/roaming hostinfo). In that state, `handleRecvError` unconditionally calls `f.closeTunnel(hostinfo)` and deletes the pending handshake state, without ever verifying the sender presented a CA-signed certificate or held any cryptographic material tied to the tunnel.

### Finding Description
`readOutsidePackets` dispatches `header.RecvError` before any certificate or encryption check: [1](#0-0) 

`handleRecvError` looks up the hostinfo by reverse index and only rejects the packet if the hostinfo already has a *valid* pinned remote address that differs from the sender: [2](#0-1) 

```go
hr := hostinfo.GetRemote()
if hr.IsValid() && hr != addr {
    f.l.Info("Someone spoofing recv_errors?", ...)
    return
}

f.closeTunnel(hostinfo)
f.handshakeManager.DeleteHostInfo(hostinfo)
```

If `hr.IsValid()` is `false` — which is the case for a hostinfo whose remote hasn't been pinned yet (e.g. during handshake, or a roamed/racing tunnel before `handleHostRoaming` sets it) — the address-equality check is bypassed entirely, and *any* UDP packet of type `RecvError` carrying the matching `RemoteIndex` causes the tunnel/handshake state to be torn down. No AEAD tag, no certificate, no CA-pool verification is involved anywhere in this path, unlike every other message type which requires `ConnectionState.Decrypt` (itself gated behind a completed, cert-verified handshake).

This mirrors the reported bug class: a state-mutating "privileged" operation (`_collectManagementFee`/tunnel teardown) that can be invoked repeatedly by an unauthorized party, cumulatively degrading legitimate participants' state, and can be timed adversarially ("front-run") right before a victim's legitimate traffic — here, an attacker who can predict/replay/observe `h.RemoteIndex` can preemptively tear down a tunnel the instant it enters a state where `hr.IsValid()` is false, with no certificate-based authentication gate at all.

### Impact Explanation
An attacker with no CA-signed certificate can force closure of tunnels/handshakes for arbitrary victims whenever their `HostInfo.remote` has not yet been pinned (freshly started handshakes, or hosts that haven't roamed yet), simply by sending a bare `RecvError` packet with a known/guessed `RemoteIndex`. This is a remote state-poisoning / denial-of-service vector reachable by an unauthenticated peer, directly analogous to the reported bug where a privileged, repeatable, insufficiently-gated action degrades existing participants without their consent or knowledge.

### Likelihood Explanation
Exploitation requires the attacker to know a victim's `RemoteIndex` (a random 32-bit value) and to catch the hostinfo in the window before its remote address is pinned as "valid." This is realistic for on-path or racing adversaries (e.g., during initial handshake churn, relay re-establishment, or roaming), which the codebase's own tests (`TestRelayHandshakeOverDisestablishedEntry`, `TestReestablishRelays`) show are common transient states. `ShouldRecvError` throttling (`sendRecvErrorConfig`/`acceptRecvErrorConfig`) limits volume but does not add any cryptographic authentication to the message itself.

### Recommendation
Require the same authentication guarantees for `RecvError` as other post-handshake messages: either (a) never act on a `RecvError` when the hostinfo's remote is not yet pinned/valid, or (b) require the message to be authenticated (e.g., an AEAD-protected control message using an established `ConnectionState`) rather than trusting bare `RemoteIndex` + source-address equality, which is spoofable and skipped in the unset case.

### Proof of Concept
1. Have a victim (`them`) begin a handshake or roam so that `HostInfo.remote` transiently reports `IsValid() == false` (e.g. via `hh := hm.StartHandshake(...)` before `handleHostRoaming` pins a remote, as exercised in `e2e/handshake_manager_test.go`).
2. As an attacker with no certificate, craft a raw UDP packet: `header.Encode(buf, header.Version, header.RecvError, 0, <victim's known localIndexId>, 0)` and send it to the victim's listening UDP port from any source address.
3. `readOutsidePackets` routes it straight to `handleRecvError` (outside.go:81-83) without any decrypt/cert check.
4. Because `hr.IsValid()` is false, the spoofing check at outside.go:564 is skipped, and `f.closeTunnel(hostinfo)` plus `hm.DeleteHostInfo(hostinfo)` execute unconditionally, tearing down the victim's tunnel/pending handshake state with zero authentication.

```go
func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
```
