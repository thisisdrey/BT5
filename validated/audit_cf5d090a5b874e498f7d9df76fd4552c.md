### Title
Unauthenticated event listener lets any remote host inject forged block-validation, burn-block, and StackerDB-chunk events into the signer process - ([File: libsigner/src/events.rs])

### Summary
The `stacks-signer`'s event receiver (`SignerEventReceiver`, `libsigner/src/events.rs`) is a plain `tiny_http` server that accepts POST requests on `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block`, and `/shutdown` from any TCP peer that can reach the configured `endpoint` — with no authentication check whatsoever. This is the analog of the reported bug class: the node-side `auth_token`/`auth_password` mechanism documented for this channel (`docs/signing.md:33-47`, `stackslib/src/config/mod.rs:3802-3816`) is never enforced on the receiving side, so the "shared secret" protecting this channel simply doesn't gate anything — an auth-gate that fails open (in this case, is entirely absent).

### Finding Description
`stacks-node`'s `[connection_options] auth_token` is documented as the mechanism that "secures the communication channel between this node and a connected `stacks-signer` instance" [1](#0-0) , and the signer-side `auth_password` is described as needing to exactly match it [2](#0-1) . However, that token is only used for the *outbound* RPC endpoints on the node (`/v3/block_proposal`, `/v3/blocks?broadcast=1`, `/v3/blocks/replay`, `/v3/blocks/simulate`, `/v3/transactions/simulate`), each of which does compare `auth_header != password` [3](#0-2) .

The signer's own listening HTTP server, `SignerEventReceiver`, which receives events pushed by the node's event-observer mechanism, performs no such check at all. `next_event()` simply reads the request and dispatches purely by URL path, with zero header/credential validation: [4](#0-3) 

`process_event` reads the raw body, deserializes it straight into a `StackerDBChunksEvent`, `BlockValidateResponse`, `BurnBlockEvent`, or `StacksBlockEvent`, and converts it into a `SignerEvent`, which is then forwarded unconditionally into the signer's runloop channel: [5](#0-4) 

Sample configs show this endpoint bound to a wildcard address (`endpoint = "0.0.0.0:30000"`), making it reachable over the network rather than just loopback: [6](#0-5) 

This breaks the intended equality "message accepted by signer" == "message actually sent by the trusted, authenticated node." Any of the four POST endpoints can be hit directly by an unauthenticated third party:
- `/new_burn_block` and `/new_block` bodies are trusted with no cryptographic binding to the real chain state.
- `/proposal_response` (`BlockValidateResponse`) is trusted with no signature — an attacker can forge a "valid" validation result for an arbitrary block.
- `/stackerdb_chunks` chunks still require a valid signature from a registered signer key to be *acted on downstream* (`stacks-node/src/nakamoto_node/stackerdb_listener.rs:342-383`), so forged-signature chunks are filtered later, but delivery/injection into the runloop itself is unauthenticated, and correctly-signed-but-replayed/rerouted chunks that never actually traversed the real node/StackerDB can still be fed in directly.

### Impact Explanation
This is an unauthenticated write into the signer's internal event stream — matching the "Critical: unauthenticated/unauthorized write to state ... auth bypass" bucket. An attacker who can reach the signer's bound TCP port (frequently a public/wildcard address per the sample configs) can inject fabricated `NewBurnBlock`, `NewBlock`, and `BlockValidationResponse` events without presenting any credential, entirely bypassing the `auth_token`/`auth_password` mechanism that the documentation and node-side code claim protects this channel. Since these events feed directly into the signer's decision-making runloop, this is a serious integrity break of the trust boundary between node and signer, even though I cannot assess (out of scope) how specifically the signer's business logic (`run_one_pass`) would react to each forged event type.

### Likelihood Explanation
Exploitation requires only network reachability to the signer's event port and a raw HTTP POST — no key material, no prior session, no privileged role. The only prerequisite is that the operator's deployment exposes this port beyond localhost, which the shipped sample configs (`endpoint = "0.0.0.0:30000"`) explicitly enable and document as the expected topology for signer coordination.

### Recommendation
Enforce the same `auth_token`/shared-secret check on the signer's `SignerEventReceiver` that already exists on the node's outbound RPC handlers: require and validate an `Authorization` header (matching `auth_password`) before dispatching to `process_event` in `libsigner/src/events.rs`, rejecting unauthenticated requests with 401 before any body is parsed. Document that the endpoint should be bound to a loopback/firewalled address as defense-in-depth, but treat that as a mitigation, not a substitute for authentication at the transport layer.

### Proof of Concept
1. Deploy a `stacks-signer` per `docs/signing.md`, with `endpoint = "0.0.0.0:30000"` as shown in the sample configs.
2. From a remote host with no credentials, send:
```
POST /proposal_response HTTP/1.1
Host: <signer-ip>:30000
Content-Type: application/json
Content-Length: <n>

{ ...forged BlockValidateResponse JSON... }
```
3. Observe in `libsigner/src/events.rs::next_event` that the request is dispatched to `process_event::<T, BlockValidateResponse>(request)` with no authentication check, and the resulting `SignerEvent::BlockValidationResponse` is forwarded into the signer runloop via `forward_event` — identical in effect to a legitimate response from the trusted node.

    fn next_event(&mut self) -> Result<SignerEvent<T>, EventError> {
        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)
            } else if request.url() == "/new_block" {
                process_event::<T, StacksBlockEvent>(request)
            } else {
                let url = request.url().to_string();
                debug!(
                    "[{:?}] next_event got request with unexpected url {}, return OK so other side doesn't keep sending this",
                    event_receiver.local_addr,
                    url
                );
                ack_dispatcher(request);
                Err(EventError::UnrecognizedEvent(url))
            }
        })?

```rust
fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}
```
