### Title
Unpartitioned pre-handshake connection headroom pool lets unstaked flood block staked TPU handshakes - ([File: streamer/src/nonblocking/quic.rs])

### Summary
`ClientConnectionTracker::new` gates every incoming QUIC connection attempt against a single shared counter (`qos.max_concurrent_connections()`), before the peer's stake status is known. Because this headroom pool is not partitioned by peer type, and the `overall_connection_rate_limiter` only performs a non-consuming `current_tokens() == 0` check at accept time (tokens are only actually consumed after a full handshake succeeds), an unprivileged attacker can flood half-open QUIC connection attempts from a single IP to exhaust the pool and cause legitimate staked handshakes to be refused.

### Finding Description
In `run_server` (`streamer/src/nonblocking/quic.rs:304-411`), for every accepted `Incoming`, the server:
1. Checks `overall_connection_rate_limiter.current_tokens() == 0` [1](#0-0)  — this only *reads* the bucket; tokens are not consumed here. Consumption only happens later, in `setup_connection`, after the QUIC handshake fully succeeds [2](#0-1) . An attacker who never completes the handshake never triggers this consumption, so this "global rate limiter" provides no real throttling against incomplete/half-open attempts.
2. Checks per-IP `rate_limiter.is_allowed(ip)` [3](#0-2) , but `register_connection` (the actual token consumption for that limiter) is also only called post-handshake-success in `setup_connection` [4](#0-3) . An IP with no completed-connection history is always allowed (`None => true`) in `ConnectionRateLimiter::is_allowed` [5](#0-4) .
3. Calls `ClientConnectionTracker::new(stats, qos.max_concurrent_connections())`, which increments a single global `stats.open_connections` atomic and rejects only when that counter reaches `max_concurrent_connections` [6](#0-5) . For `SwQos`, this limit is `(max_staked_connections + max_unstaked_connections) * 5 / 4` [7](#0-6) , a single number with no reservation for staked-vs-unstaked in-flight handshakes.

At this point in the code, peer type (staked/unstaked) is not yet known — that is only resolved after the handshake completes and `qos.build_connection_context` / `get_connection_stake` run [8](#0-7) . The tracker slot is held for up to `QUIC_CONNECTION_HANDSHAKE_TIMEOUT` (2 seconds) via the `timeout(...)` wrapping the `Connecting` future in `setup_connection` [9](#0-8) [10](#0-9) , and if the handshake succeeds, the tracker is moved into the `ConnectionEntry` and held until the connection is pruned/dropped from the `ConnectionTable` [11](#0-10) .

Exploit flow: an attacker from a single real (non-spoofed) IP opens many concurrent QUIC connections (distinct connection IDs/ports) and stalls the handshake (sends Initial, never completes TLS). Each stalled attempt: passes the rate-limiter checks (neither is actually consuming tokens for incomplete attempts) and successfully allocates a `ClientConnectionTracker` slot, incrementing `open_connections` toward `max_concurrent_connections`. Once `open_connections >= max_concurrent_connections`, *any* subsequent `Incoming` (including from a staked node) fails `ClientConnectionTracker::new` and is refused via `incoming.refuse()`, incrementing `stats.refused_connections_too_many_open_connections` [12](#0-11) , before the server ever knows the new peer is staked.

### Impact Explanation
While the flood is sustained, legitimate staked senders cannot even begin a QUIC handshake to the leader's TPU — their `Incoming` is refused at the pre-handshake gate regardless of stake. This is a temporary denial of TPU ingress availability to staked/legitimate senders, achievable by a single unprivileged, unstaked remote attacker with no special network position (no IP spoofing required). This falls under the availability/DoS category for the TPU ingress path.

### Likelihood Explanation
Feasible and repeatable: no privileged role, staked identity, or gossip control is required — only the ability to open many concurrent QUIC connections to the public TPU port and withhold handshake completion. The only real friction is generating enough concurrent half-open attempts to exceed `max_concurrent_connections` (e.g., 5000 for SwQos defaults: `(2000+2000)*5/4`), which is well within reach of a single moderately-provisioned attacker host given neither of the two "rate limiters" actually throttles incomplete-handshake attempts.

### Recommendation
- Make `overall_connection_rate_limiter` actually consume a token at accept time (before spawning `setup_connection`), not just check `current_tokens() == 0`, so incomplete/half-open attempts are genuinely throttled.
- Partition the pre-handshake headroom so unstaked in-flight attempts cannot consume slots reserved for potential staked handshakes — e.g., track separate pending-connection counters/limits for staked-headroom vs unstaked-headroom (reserving at least `max_staked_connections` worth of headroom that unstaked pending attempts cannot exhaust), falling back to the shared/unstaked pool only after those reservations are respected.
- Consider reducing `QUIC_CONNECTION_HANDSHAKE_TIMEOUT` exposure by rate-limiting per-IP *attempt* rate (not just completed connections) in `run_server` before `ClientConnectionTracker::new` is invoked.

### Proof of Concept
Integration test plan (in `streamer/src/nonblocking/quic.rs` test module or a new integration test alongside `tpu-client-next/tests/connection_workers_scheduler_test.rs`):
```rust
#[tokio::test]
async fn test_unstaked_flood_starves_staked_handshake() {
    // Configure SwQos with small pools to make the attack cheap in test:
    // max_staked_connections = 4, max_unstaked_connections = 4
    // => max_concurrent_connections = (4+4)*5/4 = 10
    let SpawnTestServerResult { server_address, stats, cancel, .. } = setup_quic_server(
        None,
        QuicStreamerConfig::default_for_tests(),
        SwQosConfig {
            max_staked_connections: 4,
            max_unstaked_connections: 4,
            ..Default::default()
        },
    );

    // Attacker: open >= max_concurrent_connections QUIC connections from one
    // client endpoint (multiple `connect()` calls) and never drive them past
    // Initial (e.g. spawn connect() futures but don't await completion,
    // or drop the handshake future after sending Initial).
    let flood_attempts: Vec<_> = (0..12)
        .map(|_| make_stalled_client_connection(&server_address)) // does not complete handshake
        .collect();

    // Give the flood time to occupy the headroom pool but stay within
    // QUIC_CONNECTION_HANDSHAKE_TIMEOUT (2s).
    tokio::time::sleep(Duration::from_millis(200)).await;

    // Legitimate staked client attempts to connect concurrently.
    let staked_keypair = Keypair::new();
    let staked_connect = tokio::time::timeout(
        Duration::from_secs(2), // QUIC_CONNECTION_HANDSHAKE_TIMEOUT
        make_client_endpoint(&server_address, Some(staked_keypair)),
    ).await;

    // Expect failure/refusal while flood holds the shared headroom pool.
    assert!(staked_connect.is_err() || stats.refused_connections_too_many_open_connections.load(Ordering::Relaxed) > 0,
        "expected staked handshake to be refused due to shared unpartitioned headroom pool");

    drop(flood_attempts);
    cancel.cancel();
}
```
Expected assertion: `stats.refused_connections_too_many_open_connections` increases and/or the staked client's connection attempt does not succeed within `QUIC_CONNECTION_HANDSHAKE_TIMEOUT` while the unstaked flood is active, demonstrating that unstaked half-open attempts can starve staked handshake capacity from the shared pool.

impl ClientConnectionTracker {
    /// Check the max_concurrent_connections limit and if it is within the limit
    /// create ClientConnectionTracker and increment open connection count. Otherwise returns Err
    fn new(stats: Arc<StreamerStats>, max_concurrent_connections: usize) -> Result<Self, ()> {
        let open_connections = stats.open_connections.fetch_add(1, Ordering::Relaxed);
        if open_connections >= max_concurrent_connections {
            stats.open_connections.fetch_sub(1, Ordering::Relaxed);
            debug!(
                "There are too many concurrent connections opened already: open: \
                 {open_connections}, max: {max_concurrent_connections}"
            );
            return Err(());
        }

        Ok(Self { stats })
    }
}
