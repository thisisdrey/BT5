## Analysis

**Binding claimed to be broken:**
`fees_collected[T]` (across a `MultiPayload` batch) `== Pips::fee_ceil(protocol_fee, Σ negative deltas of T for signer S across the batch)`

**What the code actually computes:** `fees_collected[T]` is accumulated independently **per `TokenDiff` intent**, and the fee-exemption test `amount > 1` in `TokenDiff::token_fee` is evaluated against `delta.unsigned_abs()` of **that single intent's delta**, not the signer's aggregate negative delta for `T` across all intents in the batch.
```rust
pub fn token_fee(token_id: impl Into<TokenIdType>, amount: u128, fee: Pips) -> Pips {
    let token_id = token_id.into();
    match token_id {
        TokenIdType::Nep141 => {}
        TokenIdType::Nep245 | TokenIdType::Imt if amount > 1 => {}
        // do not take fees on NFTs and MTs with |delta| <= 1
        TokenIdType::Nep171 | TokenIdType::Nep245 | TokenIdType::Imt => return Pips::ZERO,
    }
    fee
}
```

Each `TokenDiff` intent is executed independently via `Engine::execute_signed_intent`, one per `MultiPayload` entry, with its own nonce commit; there is no per-signer/per-token fee aggregation across intents in the batch. [3](#0-2) 

The **only** cross-intent invariant enforced for the whole batch is `TransferMatcher::finalize`, which checks that net deltas per token sum to zero (conservation of value transferred), not that fees were computed on the aggregated per-signer negative delta. [4](#0-3) 

**Exploit:** A signer can fragment a Nep245 (or Imt) "token-in" leg of quantity `N` into `N` separate `TokenDiff` intents, each with `delta = -1` for the same `token_id`, all signed by the same `signer_id`, packaged in one `MultiPayload` alongside whatever counter-leg(s) balance the batch (from a counterparty or another signed intent providing the offsetting `+N`). Each of the `N` intents independently evaluates `token_fee(token_id, 1, protocol_fee)` → `Pips::ZERO` (the `amount > 1` guard fails), so `fees_collected` for that token is `0` for every leg, summing to `0` total — instead of `fee_ceil(protocol_fee, N)` that would apply if expressed as one intent with `delta = -N`. No existing guard (`MultiPayload::verify`, nonce checks, `TransferMatcher::finalize`) checks or prevents this, because none of them look at cumulative per-signer/per-token deltas for fee purposes — `finalize` only checks net-zero conservation across the whole batch, which is unaffected by how the fee-exempt legs are split.

This only affects Nep245/Imt-typed tokens (the `amount <= 1` exemption doesn't exist for Nep141), but for any Nep245/Imt token with quantity semantics (e.g., a semi-fungible/quantity token where large trade sizes are meaningful), this lets an attacker completely bypass `protocol_fee` on that leg by unit-fragmenting it, which matches the "protocol fees bypassed" Critical impact category.

### Title
Fee-exempt Nep245/Imt `|delta|<=1` check is evaluated per-`TokenDiff`-intent, not per-signer-per-token across the batch, allowing fee bypass by unit-fragmentation - (File: contracts/defuse/core/src/intents/token_diff.rs)

### Summary
`TokenDiff::execute_intent` computes and exempts fees using only the current intent's own delta magnitude (`amount = delta.unsigned_abs()`), rather than the signer's total negative delta of that `token_id` across the whole `MultiPayload`. For Nep245/Imt tokens, `TokenDiff::token_fee` returns `Pips::ZERO` whenever a single intent's delta magnitude is `<= 1`, so a signer can split a large negative delta into many `delta = -1` legs across multiple self-signed `TokenDiff` intents in one batch and pay zero fee in total, instead of `fee_ceil(protocol_fee, N)`.

### Finding Description
The broken binding: `fees_collected[T]` should equal `Pips::fee_ceil(protocol_fee, Σ negative deltas of T for signer across the batch)`, but the code computes it per intent (`contracts/defuse/core/src/intents/token_diff.rs:59-78`), and the Nep245/Imt fee exemption (`token_fee`, lines 206-216) checks `amount > 1` against only that intent's delta. `Engine::execute_signed_intent` (`contracts/defuse/core/src/engine/mod.rs:32-83`) processes each `MultiPayload` entry — and thus each intent — independently, committing separate nonces, with no cross-intent, per-signer/per-token fee aggregation. The only batch-wide check is `TransferMatcher::finalize` (`contracts/defuse/core/src/engine/state/deltas.rs:265-283`), which enforces conservation of value (net-zero deltas per token) but is indifferent to how fees were computed on the legs that produced those deltas.

Attacker payload: a `MultiPayload` containing `N` `TokenDiff` intents, all signed by the same attacker `signer_id` (each with a unique nonce), each with `diff = {token_id_Nep245: -1, ...}`, plus a counter-leg (from a counterparty or a matching offsetting intent) supplying the `+N` needed to satisfy `TransferMatcher::finalize`. Each of the `N` intents independently calls `token_fee(token_id, 1, protocol_fee)` → `Pips::ZERO`, so `fee_ceil(protocol_fee, 1) == 0` every time, and total `fees_collected` for `token_id` across the batch is `0`.

### Impact Explanation
Protocol fees on Nep245 (and Imt, if enabled) "token-in" legs can be bypassed entirely regardless of the aggregate volume traded, by fragmenting one logical trade into unit legs across multiple same-signer `TokenDiff` intents in a single batch. This is `fee_collector` under-collection scalable to any traded amount of a Nep245/Imt token, repeatable on every batch and by any account, matching the Critical "protocol fees bypassed" category.

### Likelihood Explanation
Requires only standard, unprivileged capabilities: signing multiple `TokenDiff` intents with distinct nonces and packaging them plus a counter-leg into one `MultiPayload` submitted via `execute_intents`. No special role, relayer key, or DAO action needed. The only extra requirement is a counterparty (or a second self-controlled leg) to supply the offsetting `+N` to satisfy the batch-wide zero-sum invariant, which is trivial in any real swap scenario.

### Recommendation
Aggregate negative deltas per `(signer_id, token_id)` across the entire `MultiPayload`/execution context before applying the Nep245/Imt `amount <= 1` fee exemption, e.g., by computing fees in `Engine::finalize` from the accumulated `TransferMatcher`/`Deltas` state rather than inside each `TokenDiff::execute_intent` call, or by tracking a running per-signer-per-token negative-delta total across intents in the batch when deciding whether the `amount > 1` fee threshold applies.

### Proof of Concept
`cargo test` (workspace sandbox) plan:
1. Deploy Defuse Verifier with `protocol_fee > 0` and an Nep245-type token with a real MT contract.
2. Fund attacker account A with `2` units of the Nep245 token, and a counterparty B with the offsetting token to receive.
3. Sign two `TokenDiff` intents from A in one `MultiPayload`, each `diff = {nep245_token: -1, other_token: +k}` (unique nonces), plus B's matching `TokenDiff` to balance the batch (`+2` of nep245_token, `-2k` of other_token).
4. Call `execute_intents` with this `MultiPayload`.
5. Assert `fee_collector`'s `mt_balance_of(nep245_token)` increased by `0`, while `Pips::fee_ceil(protocol_fee, 2)` (the amount that would be collected had this been a single `TokenDiff` with `delta = -2`) is `> 0` — demonstrating `fees_collected[nep245_token] == 0 != fee_ceil(protocol_fee, 2)`.

```rust
    fn execute_signed_intent(&mut self, signed: MultiPayload) -> Result<()> {
        // verify signed payload and get public key
        let public_key = signed.verify().ok_or(DefuseError::InvalidSignature)?;

        // calculate intent hash
        let hash = signed.hash();

        // extract NEP-413 payload
        let DefusePayload::<DefuseIntents> {
            signer_id,
            verifying_contract,
            deadline,
            nonce,
            message: intents,
        } = signed.extract_defuse_payload()?;

        // check recipient
        if verifying_contract != *self.state.verifying_contract() {
            return Err(DefuseError::WrongVerifyingContract);
        }

        self.inspector.on_deadline(deadline);

        // make sure message is still valid
        if deadline < Timestamp::now() {
            return Err(DefuseError::DeadlineExpired);
        }

        // make sure the account has this public key
        if !self.state.has_public_key(&signer_id, &public_key) {
            return Err(DefuseError::PublicKeyNotExist(signer_id, public_key));
        }

        // commit nonce
        self.verify_intent_nonce(nonce, deadline)?;
        self.state.commit_nonce(signer_id.clone(), nonce)?;

        intents.execute_intent(&signer_id, self, hash)?;
        self.inspector.on_intent_executed(&signer_id, hash, nonce);

        Ok(())
    }
```

```rust
    // Finalizes all transfers, or returns unmatched deltas.
    // If unmatched deltas overflow, then Err(None) is returned.
    pub fn finalize(self) -> Result<Transfers, InvariantViolated> {
        let mut transfers = Transfers::default();
        let mut deltas = TokenDeltas::default();
        for (token_id, transfer_matcher) in self.0 {
            if let Err(unmatched) = transfer_matcher.finalize_into(&token_id, &mut transfers)
                && (unmatched == 0 || deltas.apply_delta(token_id, unmatched).is_none())
            {
                return Err(InvariantViolated::Overflow);
            }
        }
        if !deltas.is_empty() {
            return Err(InvariantViolated::UnmatchedDeltas {
                unmatched_deltas: deltas,
            });
        }
        Ok(transfers)
    }
```
