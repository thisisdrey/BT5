### Title
DebtToken interest-inflated `balanceOf` inflates per-account reward delta, overpaying early claimers and draining `RewardsDistributor` - (File: contracts/RewardsDistributor.sol)

### Summary
`RewardsDistributor._calculateTokenDelta` computes an account's accrued rewards as `token_.balanceOf(account_).wadMul(_deltaIndex)`, applying the index delta accumulated over the whole elapsed period to the *current* balance [1](#0-0) . For `DebtToken`, `balanceOf` is not a static share: it returns `principalOf[account_] * debtIndex / debtIndexOf[account_]`, which grows continuously as interest accrues [2](#0-1) . That growth happens silently inside `accrueInterest`/`_calculateInterestAccrual` without calling `updateBeforeMintOrBurn`, so the rewards distributor never sees the balance change [3](#0-2) . This is the same bug class as the reference finding: a per-share rate is multiplied by a quantity that includes an un-accounted correction (accrued interest), rather than by the time-consistent share that the index delta was actually earned against.

### Finding Description
The global reward index is computed as `accruedTokens.wadDiv(totalSupply)` added to `tokenStates[token_].index` [4](#0-3) . The index delta `(_tokenIndex - _accountIndex)` therefore represents rewards earned *per unit of supply* over the period. The correct payout for an account is `(time-weighted balance) * deltaIndex`. Instead, the code pays `balanceOf_now * deltaIndex`. For `DebtToken`, `balanceOf_now` embeds the interest factor `debtIndex_now / debtIndexOf[account_]`, so every holder's claimable amount is scaled up by that factor. Since all holders' balances grow by the same factor, the sum of all `_tokensDelta` equals `totalSupply_now * deltaIndex`, which exceeds the `tokensAccrued = deltaTimestamp * speed` that the index was supposed to distribute. The accounting identity `sum(user deltas) == accrued emissions` is broken.

Concrete attack path (all unprivileged):
1. Governor previously set a nonzero `tokenSpeed` for a `DebtToken` (the test suite configures exactly this: speeds on both `msdTOKEN` and `debtToken` [5](#0-4) ).
2. Attacker calls `DebtToken.issue(amount, attacker)` to take on debt, which mints via `_mint` (hooks fire normally) [6](#0-5) .
3. Time passes. `accrueInterest` increases `debtIndex` and `totalSupply_`, so `balanceOf(attacker)` grows, but no reward hook runs.
4. Attacker calls `claimRewards(attacker, [debtToken])`; `_updateTokensAccruedOf` credits `balanceOf_now * deltaIndex` — strictly more than `balance_then * deltaIndex` — and `_transferRewardIfEnoughTokens` pays it out [7](#0-6) .
5. The overpayment is bounded only by the contract's reward-token balance; other users' later claims find `amount > balance` and silently get nothing because `_transferRewardIfEnoughTokens` skips the transfer and leaves `tokensAccruedOf` set but unpaid [8](#0-7) .

No guard prevents this: `updateBeforeMintOrBurn` is permissionless but settles with the same inflated `balanceOf`, `claimRewards` is `nonReentrant` but the path is non-reentrant anyway, and no pause/shutdown flag applies to claims.

### Impact Explanation
Direct theft of unclaimed yield: an attacker holding `DebtToken` receives rewards proportional to `balance * (1 + interest accrued since last index update)` instead of `balance`, i.e. is paid emissions as if they had held the *grown* balance for the entire period. Because total payouts exceed total emissions, the distributor's reward-token balance is drained early, permanently freezing the accrued-but-unpaid `tokensAccruedOf` of all other deposit/debt holders across every reward token.

### Likelihood Explanation
Requires only that rewards are configured for a `DebtToken` with a nonzero `interestRate` — both are normal deployed configuration (interest-bearing debt is core protocol behavior, and tests configure speeds on debt tokens). Any user can reach it via `issue` → wait → `claimRewards`; the inflation factor grows monotonically with time between index updates. The magnitude equals roughly `speed * deltaT * (interestAccrued/totalSupply)`, so for high-APR debt tokens the overpayment is material and continuous, not a one-off.

### Recommendation
Do not use a lazily-rebased `balanceOf` as the multiplier for index deltas. Options:
- In `_calculateTokenDelta`, use the reward-accounting principal (`principalOf`) for `DebtToken` rather than interest-adjusted `balanceOf`, or
- Have `DebtToken.accrueInterest` notify registered rewards distributors (e.g. an `updateBeforeBalanceChange` hook) so each account's index is settled before the implicit balance growth, or
- Exclude `DebtToken`s from reward speeds since the index-based design assumes non-rebasing balances.

### Proof of Concept
Hardhat sketch (mirroring `test/RewardDistributor.test.ts` setup):

```ts
// setup: real DebtToken (or mock where balanceOf grows with interest factor)
await rewardDistributor.updateTokenSpeed(debtToken.address, parseEther('1'))

// attacker "mints" debt: rewards hook settles at index = INITIAL_INDEX
await rewardDistributor.updateBeforeMintOrBurn(debtToken.address, attacker.address)

// balance at mint time: 100; later balanceOf returns 110 (10% interest accrued)
debtToken.totalSupply.returns(parseEther('100'))
debtToken.balanceOf.whenCalledWith(attacker.address).returns(parseEther('100'))

// no rewards accrued yet at index settle; now advance time AND grow balance
await increaseTimeOfNextBlock(10)
debtToken.balanceOf.whenCalledWith(attacker.address).returns(parseEther('110'))
// NOTE: with a real DebtToken this is achieved by interestRate > 0 + accrueInterest()

await rewardDistributor['claimRewards(address)'](attacker.address)

// Fair reward = 100 * (10 speed-seconds / 100 supply) = 10 tokens
// Actual payout = 110 * deltaIndex = 11 tokens -> 10% theft of emission
expect(await rewardToken.balanceOf(attacker.address)).to.eq(parseEther('11')) // should be 10
```

With a second holder, repeat and observe `tokensAccruedOf` of the later claimer exceeding the remaining reward balance, so their claim is silently skipped by `_transferRewardIfEnoughTokens` — proving both overpayment and freezing of others' yield.
