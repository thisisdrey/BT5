### Title
Module content is extracted to disk and made visible to concurrent readers before its checksum is verified - ([File: src/cmd/go/internal/modfetch/fetch.go])

### Summary
`Fetcher.Download` extracts a downloaded module zip to its final on-disk cache directory via `f.download(ctx, mod)` (which calls `unzip`) and only afterwards calls `f.checkMod(ctx, mod)` to verify the checksum against `go.sum`/the checksum database. Because `unzip` removes the `.partial` marker (making `DownloadDir` report the directory as "complete") before the checksum check runs, there is a window where unverified, potentially malicious module content is fully materialized and externally observable on disk before validation happens - the same "update-before-validate" ordering flaw as the MagicLP TWAP report, where state is committed before the check that is supposed to gate its use.

### Finding Description
Attacker input: a module proxy/VCS source (consumed by an ordinary `go build`/`go get`/`go mod download` workflow) serves a zip whose content does not match the expected `go.sum` hash (e.g. a MITM'd or compromised proxy, or a race with a legitimate re-tag).

Entry point: `Fetcher.Download` [1](#0-0) .

Flow:
1. `Download` calls `f.download(ctx, mod)` at line 53, which calls `unzip(ctx, mod, zipfile)`.
2. `unzip` writes a `.partial` marker, extracts the zip via `modzip.Unzip(dir, mod, zipfile)`, then **removes the `.partial` file** at line 187 - at this point `DownloadDir` (used by *other, independent* callers such as `modload/build.go`, `modload/load.go`, `fips140.go`, `modcmd/verify.go`) will report the directory as fully populated and usable [2](#0-1) .
3. Only after `f.download` returns does `Download` call `f.checkMod(ctx, mod)` (line 57) to verify the checksum, which calls `checkModSum` → `checkSumDB`/`haveModSumLocked`, and calls `base.Fatalf` on mismatch [3](#0-2) .

Failed check: the checksum verification (`checkMod`/`checkModSum`) is the gate that is supposed to prevent use of unverified module content, but it runs *after* the content is already committed to disk and discoverable as "complete" by any other code path that calls `DownloadDir` directly (bypassing `Fetcher.Download`'s wrapper entirely).

Sink: any concurrent `go` invocation (or another package in the same process, e.g. `modload.PackageModuleInfo`/build code that resolves package directories through `DownloadDir`) that queries the module cache for the same module version during that window can read and use the unverified, potentially corrupted source files for compilation before the verifying goroutine calls `base.Fatalf` and aborts.

### Impact Explanation
This weakens the module-checksum integrity guarantee that `go.sum`/GOSUMDB is designed to provide: a build could compile against module source that fails checksum verification, i.e. content that does not match what `go.sum` or the checksum database attests to. This is analogous to a supply-chain integrity bypass. Because it requires a very specific timing window (a concurrent process/goroutine reading the same not-yet-verified module directory) and Go's own module lock protocol (`lockVersion`) mediates most of the writing/extraction path, this is a narrow race rather than a deterministic bypass. I could not fully verify from the available files whether any of the observed direct `DownloadDir` callers (`modload/load.go`, `modload/build.go`) are actually invoked concurrently with an in-flight `Fetcher.Download` for the *same* module/version in a real `go build` workflow, or whether higher-level module-graph logic serializes all such access behind `Fetcher.Download`. This uncertainty means I cannot confirm reachability strongly enough to call it a proven, exploitable bug in this codebase as it stands — it is a plausible ordering weakness matching the report's root-cause pattern, not a confirmed exploit.

### Likelihood Explanation
Victim workflow: any ordinary `go build`/`go get`/`go mod download` invocation with `GOFLAGS=-mod=mod` or similar, fetching a new module version from an attacker-influenced proxy/mirror. Attacker capability required: control over (or a MITM position on) the module source/proxy serving a zip that doesn't match `go.sum`, i.e., no privileged access to the victim's machine — consistent with the "unauthenticated content served to an ordinary workflow" threat model. Exploiting the race additionally requires triggering a second, concurrent module-resolution path for the same module version during the narrow window between `unzip`'s partial-file removal and `checkMod`'s `base.Fatalf`, which I was not able to confirm as reachable within the scope of files reviewed.

### Recommendation
Perform (or at least start) checksum verification of the module content before removing the `.partial` marker / before the extracted directory is considered "complete" by `DownloadDir`, mirroring the `_twapUpdate()`-before-reserve-change fix in the original report: verify first, commit (remove `.partial`) second. Concretely, move `f.checkMod(ctx, mod)` (or an equivalent zip-hash check) to run against the extracted content (or the zip) *before* `unzip` deletes `partialPath`, so no other caller of `DownloadDir` can observe the directory as valid prior to successful verification.

func (f *Fetcher) Download(ctx context.Context, mod module.Version) (dir string, err error) {
	if gover.IsToolchain(mod.Path) {
		return "", ErrToolchain
	}
	if err := checkCacheDir(ctx); err != nil {
		base.Fatal(err)
	}

	// The par.Cache here avoids duplicate work.
	return f.downloadCache.Do(mod, func() (string, error) {
		dir, err := f.download(ctx, mod)
		if err != nil {
			return "", err
		}
		f.checkMod(ctx, mod)

		// If go.mod exists (not an old legacy module), check version is not too new.
		if data, err := os.ReadFile(filepath.Join(dir, "go.mod")); err == nil {
			goVersion := gover.GoModLookup(data, "go")
			if gover.Compare(goVersion, gover.Local()) > 0 {
				return "", &gover.TooNewError{What: mod.String(), GoVersion: goVersion}
			}
		} else if !errors.Is(err, fs.ErrNotExist) {
			return "", err
		}

		return dir, nil
	})

	// Extract the module zip directory at its final location.
	//
	// To prevent other processes from reading the directory if we crash,
	// create a .partial file before extracting the directory, and delete
	// the .partial file afterward (all while holding the lock).
	//
	// Before Go 1.16, we extracted to a temporary directory with a random name
	// then renamed it into place with os.Rename. On Windows, this failed with
	// ERROR_ACCESS_DENIED when another process (usually an anti-virus scanner)
	// opened files in the temporary directory.
	//
	// Go 1.14.2 and higher respect .partial files. Older versions may use
	// partially extracted directories. 'go mod verify' can detect this,
	// and 'go clean -modcache' can fix it.
	if err := os.MkdirAll(parentDir, 0o777); err != nil {
		return "", err
	}
	if err := os.WriteFile(partialPath, nil, 0o666); err != nil {
		return "", err
	}
	if err := modzip.Unzip(dir, mod, zipfile); err != nil {
		fmt.Fprintf(os.Stderr, "-> %s\n", err)
		if rmErr := RemoveAll(dir); rmErr == nil {
			os.Remove(partialPath)
		}
		return "", err
	}
	if err := os.Remove(partialPath); err != nil {
		return "", err
	}

	if !cfg.ModCacheRW {
		makeDirsReadOnly(dir)
	}
	return dir, nil
}

// checkMod checks the given module's checksum and Go version.
func (f *Fetcher) checkMod(ctx context.Context, mod module.Version) {
	// Do the file I/O before acquiring the go.sum lock.
	ziphash, err := CachePath(ctx, mod, "ziphash")
	if err != nil {
		base.Fatalf("verifying %v", module.VersionError(mod, err))
	}
	data, err := lockedfile.Read(ziphash)
	if err != nil {
		base.Fatalf("verifying %v", module.VersionError(mod, err))
	}
	data = bytes.TrimSpace(data)
	if !isValidSum(data) {
		// Recreate ziphash file from zip file and use that to check the mod sum.
		zip, err := CachePath(ctx, mod, "zip")
		if err != nil {
			base.Fatalf("verifying %v", module.VersionError(mod, err))
		}
		err = hashZip(f, mod, zip, ziphash)
		if err != nil {
			base.Fatalf("verifying %v", module.VersionError(mod, err))
		}
		return
	}
	h := string(data)
	if !strings.HasPrefix(h, "h1:") {
		base.Fatalf("verifying %v", module.VersionError(mod, fmt.Errorf("unexpected ziphash: %q", h)))
	}

	if err := checkModSum(f, mod, h); err != nil {
		base.Fatalf("%s", err)
	}
}
