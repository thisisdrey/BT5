### Title
Excess `msg.value` is forwarded to the LayerZero endpoint and lost when bridging via `ProxyOFT.sendFrom` - (File: contracts/dependencies/@layerzerolabs/solidity-examples/token/oft/OFTCore.sol, contracts/dependencies/@layerzerolabs/solidity-examples/lzApp/LzApp.sol, contracts/ProxyOFT.sol)

### Summary
All bridge `sendFrom` entry points on `ProxyOFT` pass the *entire* `msg.value` to `lzEndpoint.send{value: _nativeFee}` without checking it against the actually required LayerZero fee and without returning any excess. Any ETH sent above the quoted fee is consumed by the endpoint/messaging library and never refunded to the sender.

### Finding Description
`ProxyOFT.sendFrom(from_, dstChainId_, to_, amount_)` and the inherited `OFTCoreUpgradeable.sendFrom(...)` both funnel into `OFTCore._send`, which calls:

```solidity
_lzSend(_dstChainId, lzPayload, _refundAddress, _zroPaymentAddress, _adapterParams, msg.value);
```
`contracts/dependencies/@layerzerolabs/solidity-examples/token/oft/OFTCore.sol:86`

`_lzSend` then forwards that whole amount:

```solidity
lzEndpoint.send{value: _nativeFee}(
    _dstChainId, trustedRemote, _payload,
    _refundAddress, _zroPaymentAddress, _adapterParams
);
```
`contracts/dependencies/@layerzerolabs/solidity-examples/lzApp/LzApp.sol:75-82`

There is no check like `msg.value == requiredFee` and no balance-delta refund back to `_refundAddress` after the call. In LayerZero v1, the endpoint/messaging library charges the quoted `nativeFee` but the UA contract itself never verifies or recovers the surplus, so the surplus stays with the endpoint/treasury — the `_refundAddress` parameter is only used by the messaging layer for its own accounting, not for returning the user-paid excess.

This is exactly the bug class in the external report: the correctness check is effectively `msg.value >= fee`, so overpayment passes silently and is lost.

### Impact Explanation
A user who overpays `msg.value` in `sendFrom` (stale fee quote, mis-estimated `lzBaseGasLimit` pricing, or simply a typo) permanently loses the excess ETH. The invariant broken is fee-payment conservation: value in excess of the bridge fee leaves the user's control with no corresponding credit.

### Likelihood Explanation
Low — it requires a user mistake (over-quoting the native fee). No attacker is needed to trigger it, and it cannot be exploited to steal from other users; it is a self-inflicted loss of funds, matching the reported severity profile (high impact, low likelihood).

Note: `Operator.execute` does **not** have this flaw — it enforces `msg.value == _sumOfValues` (`contracts/Operator.sol:54`), and `NativeTokenGateway.deposit` wraps the full `msg.value` into the user's collateral, so the excess is not lost there either. `ProxyOFT`/`OFTCore` is the only production surface with a payable check that accepts and consumes unbounded excess.

### Recommendation
Quote the fee and enforce exact payment (preferred), mirroring `Operator.execute`:

```solidity
uint256 fee = lzEndpoint.estimateFees(...); // or use estimateSendFee
require(msg.value <= fee, "excess-fee"); // or == fee
```

Alternatively, capture `address(this).balance` before and after `lzEndpoint.send` and `Address.sendValue(_refundAddress, excess)` — this is more flexible but riskier (reentrancy); enforce `nonReentrant` if chosen.

### Proof of Concept
Hardhat fork sketch (real LZ endpoint on a supported chain):

```solidity
// Fork mainnet, use deployed ProxyOFT and real lzEndpoint
uint256 fee = proxyOFT.estimateSendFee(dstChainId, alice, amount);

// Alice sends fee + 1 ether excess
uint256 balBefore = alice.balance;
proxyOFT.sendFrom{value: fee + 1 ether}(alice, dstChainId, alice, amount);

// Alice's balance decreased by fee + 1 ether; ProxyOFT retains nothing,
// endpoint received the full msg.value, excess is unrecoverable
assertEq(alice.balance, balBefore - fee - 1 ether);
assertEq(address(proxyOFT).balance, 0); // excess is gone, not held for refund
```

A Foundry equivalent: `vm.deal(alice, fee + 1 ether)`, call `sendFrom`, assert `alice.balance` dropped by the full `msg.value` and that no refund path returns the delta.
