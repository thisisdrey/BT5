### Title
Max-debt positions are liquidatable immediately because issuance limit and liquidation threshold use the same `collateralFactor` - (File: contracts/Pool.sol)

### Summary
Metronome uses a single per-collateral `collateralFactor` for both (a) the maximum amount of debt a user can issue in `DebtToken.issue()` and (b) the health boundary checked in `Pool.liquidate()`. There is no liquidation threshold below the max borrow limit. A user who mints the maximal synth amount sits exactly at the boundary (`_isHealthy = _debtInUsd <= _issuableLimitInUsd`), and becomes liquidatable on the very next interest accrual tick or the smallest price move, with no window to add collateral or repay. An unprivileged liquidator can seize collateral plus `liquidatorIncentive` and `protocolFee` in the same/next block.

### Finding Description
`DebtToken.issue()` lets a borrower mint up to `quoteUsdToToken(syntheticToken, _issuableInUsd)`, where `_issuableInUsd` is derived from `_issuableLimitInUsd = Σ depositInUsd * collateralFactor` (`DebtToken.sol:254-260`, `Pool.sol:274-288`).

`Pool.liquidate()` only requires `debtPositionOf(account_)._isHealthy == false`, i.e. `_debtInUsd > _issuableLimitInUsd` (`Pool.sol:559-563`, `Pool.sol:262-265`). It is the exact same `_issuableLimitInUsd` used at issuance — there is no separate, more conservative liquidation factor.

Additionally, `DebtToken._calculateInterestAccrual()` grows `debtIndex` every second when `interestRate > 0` (`DebtToken.sol:551-566`), so a position minted at exactly the limit is pushed over the boundary by interest alone, without any price movement. The liquidator then repays `amountToRepay` and seizes `amountToRepay * (1 + liquidatorIncentive)` plus the protocol fee via `quoteLiquidateOut`/`depositToken_.seize` (`Pool.sol:451-472`, `Pool.sol:587-593`).

### Impact Explanation
A user taking maximal debt loses collateral valued above the repaid debt (liquidator incentive + protocol fee) almost immediately, with no opportunity to cure the position. This is direct transfer of user collateral value to MEV liquidators and the fee collector. In volatile conditions it also produces cascading liquidations that can push collateral value below debt, creating bad debt for the protocol.

### Likelihood Explanation
Deterministic: any borrower who mints the maximum issuable amount (a common leverage pattern, e.g. via `SmartFarmingManager.leverage`) crosses the liquidation boundary on the next interest accrual or minor oracle update. Liquidation requires no privileged role — any EOA holding or flash-minting the synthetic token can call `Pool.liquidate()`. `maxLiquidable`, `debtFloorInUsd`, `whenNotShutdown`, and `nonReentrant` do not prevent it.

### Recommendation
Introduce a distinct liquidation threshold per collateral (e.g. `liquidationFactor > collateralFactor` applied in `debtPositionOf` for the healthy check only), so that the max borrowable amount is strictly below the point at which liquidation begins, mirroring Aave's Max LTV vs. Liquidation Threshold separation. Alternatively keep a pool-level `liquidationMargin` subtracted from `_issuableLimitInUsd` in the health check.

### Proof of Concept
```solidity
// Hardhat/Foundry fork-style PoC
// 1. Attacker/victim deposits collateral
msdMET.connect(alice).deposit(depositAmount, alice.address);

// 2. Mint the maximal debt allowed by collateralFactor
(, , , , uint256 issuableInUsd) = pool.debtPositionOf(alice.address);
uint256 maxMsEth = masterOracle.quoteUsdToToken(address(msEth), issuableInUsd);
msEthDebtToken.connect(alice).issue(maxMsEth, alice.address);

// _isHealthy == true here: _debtInUsd <= _issuableLimitInUsd (equality)
(bool healthy,,,,) = pool.debtPositionOf(alice.address);
assert(healthy);

// 3. Advance time so interest accrues (no price change needed)
vm.warp(block.timestamp + 1);
msEthDebtToken.accrueInterest(); // debtIndex increases

// 4. Position is now unhealthy and liquidatable in the same threshold
(bool healthyNow,,,,) = pool.debtPositionOf(alice.address);
assert(!healthyNow);

// 5. Unprivileged liquidator seizes collateral + incentive
uint256 repay = pool.quoteLiquidateMax(msEth, alice.address, msdMET);
pool.connect(liquidator).liquidate(msEth, alice.address, repay, msdMET);
// liquidator received > repay value in collateral; alice had no window to cure
```
