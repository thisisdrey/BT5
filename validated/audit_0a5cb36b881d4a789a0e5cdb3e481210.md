### Title
FindRemoteRepository/FindRemoteRootRef credentialed URLs are not sanitized in Gitaly logs due to missing entries in `possibleGrpcMethods` allowlist - ([File: internal/log/url_sanitizer.go])

### Summary
`URLSanitizerHook.Fire` only redacts credentials embedded in URLs (`user:pass@host`) for log entries whose `grpc.method` is in the opt-in `possibleGrpcMethods` map, which is populated in `internal/cli/gitaly/serve.go` with only `CreateRepositoryFromURL`, `FetchRemote`, and `UpdateRemoteMirror`. `RemoteService.FindRemoteRepository` and `RemoteService.FindRemoteRootRef` both accept attacker-controlled, credential-bearing remote URLs (`FindRemoteRepositoryRequest.remote`, `FindRemoteRootRefRequest.remote_url`) but are absent from this allowlist, so any log entry logged under these methods' `grpc.method` context (command spawn "args" logs, command completion "args" logs, or wrapped error logs) will retain raw credentials.

### Finding Description
`internal/log/url_sanitizer.go` `Fire()` gates all sanitization behind `hook.possibleGrpcMethods[mthStr]` (line 40): [1](#0-0) . The registration is done once at startup in `configure()`: [2](#0-1) 

Two remote-URL-accepting RPCs are missing from this list:

- `FindRemoteRepository` takes `req.GetRemote()` directly as a git URL and spawns `git ls-remote <remote> HEAD` via `s.gitCmdFactory.NewWithoutRepo`: [3](#0-2) 
- `FindRemoteRootRef` takes `request.GetRemoteUrl()` and injects it into git config (`remote.inmemory.url`) before running `git remote show inmemory`: [4](#0-3) 

Every spawned git subprocess is logged with the "args" field both at spawn time and at completion, tagged with `grpc.method` from context via `methodFromContext`: [5](#0-4)  and [6](#0-5) . Because `FindRemoteRepository`/`FindRemoteRootRef` are not registered in `possibleGrpcMethods`, `Fire()` returns early (`ok` is false at line 40) and `sanitizeSpawnLog`/`sanitizeErrorLog` are never invoked, so the URL argument — potentially of the form `https://user:secret@attacker-controlled-or-victim-host/repo` — is written to Gitaly's structured logs unredacted.

This is a real gap: the same class of RPC (`UpdateRemoteMirror`, which also embeds `url`) is explicitly protected, confirming the design intent is to redact all remote-URL RPCs, but two sibling RPCs with an identical URL-in-args pattern were never added to the allowlist.

### Impact Explanation
Any unprivileged GitLab user able to trigger `FindRemoteRepository` (e.g. via "Import project from URL" existence checks) or `FindRemoteRootRef` (mirror/import root-ref detection) with a credentialed URL can cause the credential to be persisted in Gitaly's DEBUG/WARN/ERROR-level logs (spawn/completion "args", or stderr excerpts) without redaction. Given Gitaly logs are typically shipped to centralized log aggregation (e.g. via Fluentd/ELK in GitLab omnibus/production setups) that many operational/support roles can query, this constitutes a credential-disclosure vulnerability matching GitLab's "Information Disclosure — sensitive data exposure via logs" bounty class. Impact is scoped to whatever credentials the attacker embeds in the URL they submit (their own or a victim's, if they can convince Gitaly to fetch a URL containing someone else's credentials, e.g. via SSRF-adjacent import flows) plus any HTTP auth headers passed alongside (`http_authorization_header`), since the URL/host embedding is the only thing the regex targets.

### Likelihood Explanation
No special privileges are required: the RPCs are reachable through standard GitLab project import/mirror-check flows available to regular authenticated users, and args logging occurs at DEBUG level unconditionally at spawn time, and at WARN/ERROR level whenever the git subprocess writes to stderr or exits non-zero (highly likely for a bogus/malformed credentialed URL, which the attacker fully controls to force an error). This is deterministic and repeatable via a single RPC call with any log level ≥ debug.

### Recommendation
Add `FindRemoteRepository` and `FindRemoteRootRef` (and audit for any other RPC handler that passes an unvalidated URL to `git` as an argument or config value) to the `AddPossibleGrpcMethod` call in `internal/cli/gitaly/serve.go`. Better, invert the design: sanitize URLs in `args`/`error` log fields by default for all gRPC methods (deny-list approach or pattern-based detection) instead of relying on a manually maintained allowlist, since the pattern already exists in `hostPattern`/`sanitizeString` and false positives are low-risk while false negatives leak secrets.

### Proof of Concept
```go
// internal/log/url_sanitizer_test.go (extension)
func TestURLSanitizerHook_MissingMethodLeaksCredentials(t *testing.T) {
	hook := NewURLSanitizerHook()
	hook.AddPossibleGrpcMethod("CreateRepositoryFromURL", "FetchRemote", "UpdateRemoteMirror")

	entry := &logrus.Entry{
		Data: logrus.Fields{
			"grpc.method": "FindRemoteRepository", // not registered
			"args":        []string{"ls-remote", "https://user:supersecret@example.com/repo.git", "HEAD"},
		},
	}

	require.NoError(t, hook.Fire(entry))

	args := entry.Data["args"].([]string)
	// FAILS the security invariant: credential remains present because
	// FindRemoteRepository is absent from possibleGrpcMethods.
	require.Contains(t, args[1], "supersecret")
}
```
RPC-level reproduction: call `RemoteService.FindRemoteRepository` with `remote: "https://user:supersecret@invalid.invalid/x"`; the resulting `git ls-remote` subprocess fails, and the spawn/completion log entries tagged `grpc.method=FindRemoteRepository` contain the credentialed URL in the `args` field, unlike an equivalent `UpdateRemoteMirror` call with a credentialed `url` field, which is redacted to `[FILTERED]@example.com`.

func (hook *URLSanitizerHook) Fire(entry *logrus.Entry) error {
	mth, ok := entry.Data["grpc.method"]
	if !ok {
		return nil
	}

	mthStr, ok := mth.(string)
	if !ok || !hook.possibleGrpcMethods[mthStr] {
		return nil
	}

	if _, ok := entry.Data["args"]; ok {
		sanitizeSpawnLog(entry)
	} else if _, ok := entry.Data["error"]; ok {
		sanitizeErrorLog(entry)
	} else {
		entry.Message = sanitizeString(entry.Message)
	}

	return nil

func (s *server) FindRemoteRepository(ctx context.Context, req *gitalypb.FindRemoteRepositoryRequest) (*gitalypb.FindRemoteRepositoryResponse, error) {
	if req.GetRemote() == "" {
		return nil, structerr.NewInvalidArgument("empty remote can't be checked.")
	}

	var output bytes.Buffer
	cmd, err := s.gitCmdFactory.NewWithoutRepo(ctx,
		gitcmd.Command{
			Name: "ls-remote",
			Args: []string{
				req.GetRemote(),
				"HEAD",
			},
		},
		gitcmd.WithStdout(&output),
	)
	if err != nil {
		return nil, structerr.NewInternal("error executing git command: %w", err)
	}

func (s *server) findRemoteRootRefCmd(ctx context.Context, request *gitalypb.FindRemoteRootRefRequest) (*command.Command, error) {
	remoteURL := request.GetRemoteUrl()
	var config []gitcmd.ConfigPair

	if resolvedAddress := request.GetResolvedAddress(); resolvedAddress != "" {
		modifiedURL, resolveConfig, err := gitcmd.GetURLAndResolveConfig(remoteURL, resolvedAddress)
		if err != nil {
			return nil, structerr.NewInvalidArgument("couldn't get curloptResolve config: %w", err)
		}

		remoteURL = modifiedURL
		config = append(config, resolveConfig...)
	}

	config = append(config, gitcmd.ConfigPair{Key: "remote.inmemory.url", Value: remoteURL})

	if authHeader := request.GetHttpAuthorizationHeader(); authHeader != "" {
		config = append(config, gitcmd.ConfigPair{
			Key:   fmt.Sprintf("http.%s.extraHeader", request.GetRemoteUrl()),
			Value: "Authorization: " + authHeader,
		})
	}

	repo := s.localRepoFactory.Build(request.GetRepository())

	return repo.Exec(ctx,
		gitcmd.Command{
			Name:   "remote",
			Action: "show",
			Args:   []string{"inmemory"},
		},
		gitcmd.WithDisabledHooks(),
		gitcmd.WithConfigEnv(config...),
		gitcmd.WithSetupStdout(),
	)
}
