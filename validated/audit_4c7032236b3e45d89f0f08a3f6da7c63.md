### Title
Signer Event Receiver Accepts Unauthenticated POST Requests, Allowing Injection of Forged Node Events - (File: libsigner/src/events.rs)

### Summary
`SignerEventReceiver` (the HTTP transport that the `stacks-signer` process uses to receive events from its paired node) performs no authentication check on incoming requests. Although the configuration model documents an `auth_token`/`auth_password` pair intended to authenticate the node-to-signer channel, the receiver's request-handling code never inspects any `Authorization` header or shared-secret value before dispatching a request body into the signer's event pipeline.

### Finding Description
`SignerEventReceiver::next_event` in `libsigner/src/events.rs` dispatches incoming HTTP POSTs purely by URL path (`/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block`), with no check of caller identity: [1](#0-0) 

`process_event` then reads the raw body and deserializes it directly into a `StackerDBChunksEvent`/`BlockValidateResponse`/`BurnBlockEvent`, again with no authentication gate: [2](#0-1) 

A repo-wide search of `libsigner/**` confirms there is no `Authorization` header check, no `auth_token`/`auth_password` comparison, and no bearer-token logic anywhere in the transport code (`grep` for `Authorization|auth_token|check_request_authorization` in `libsigner/**` returned zero matches). Yet the project's own operational documentation states that the `auth_password` (signer side) and `auth_token` (node side, `[connection_options] auth_token`) "must match" as part of "Authentication for signer communication": [3](#0-2) 

This is a classic "authenticated vs. stored" equality break: the system's design/documentation asserts that node→signer traffic is authenticated by a shared secret, but the actual transport implementation (`SignerEventReceiver`) fails open — it never verifies the secret, so the gate that is supposed to authenticate the sender does not exist in code. Any host that can reach the signer's bound listener (`bind()` opens a plain `HttpServer` on the configured `endpoint`, e.g. `0.0.0.0:30000` per the sample config) can POST directly to these paths and have its payload accepted as if it came from the trusted, paired stacks-node.

### Impact Explanation
This is an unauthenticated write into the signer's internal event/message pipeline from any network-reachable attacker (no node private key, no operator/admin role required to reach the listener — only network reachability to the configured endpoint, which per the sample config is bound to `0.0.0.0`). Forged `StackerDBChunksEvent` (miner/signer StackerDB pushes), forged `BlockValidateResponse` (block validation results), and forged `BurnBlockEvent` messages can all be injected directly into `SignerRunLoop` processing without ever having been legitimately observed by the paired node. This matches the "unauthenticated/unauthorized write to state" Critical category: it breaks the intended trust boundary between the node and the signer transport layer, independent of whatever downstream signature checks individual signer messages may later apply (the signer-decision logic itself is out of scope for this analog, but the transport-level fail-open auth gate is squarely in the `libsigner` transport surface).

### Likelihood Explanation
Likelihood is high for any deployment where the signer's event-receiver endpoint is reachable from outside a trusted network boundary (e.g., bound to a non-loopback address, as the shipped sample configs do — `endpoint = "127.0.0.1:30000"` in the docs, but operator-configurable to any bind address). No cryptographic material, private keys, or race conditions are needed — a single crafted HTTP POST suffices, and the code path is unconditionally reachable prior to any authentication.

### Recommendation
Implement and enforce shared-secret (or mTLS) authentication in `SignerEventReceiver::next_event` before parsing or dispatching the request body — reject requests whose `Authorization` header (or equivalent) does not match the configured `auth_token`/`auth_password`. This should occur before `process_event` reads/deserializes the body, matching the intent already documented in `docs/signing.md`.

### Proof of Concept
1. Deploy a `stacks-signer` with `endpoint = "0.0.0.0:30000"` (or any address reachable by the attacker), per `sample/conf/testnet-miner-conf.toml`'s `[[events_observer]]` block.
2. From an unrelated, unauthenticated host, send:
```
POST /stackerdb_chunks HTTP/1.1
Host: <signer-ip>:30000
Content-Type: application/json
Content-Length: <n>

{"contract_id": "...", "modified_slots": [ ... attacker-crafted chunk ... ]}
```
3. Observe that `SignerEventReceiver` accepts and forwards this into the signer runloop (`SignerEvent::forward_event`) exactly as it would a legitimate event pushed by the paired node — no header or secret is checked anywhere in `next_event`/`process_event` (as shown above), confirmed by the absence of any `Authorization`/`auth_token` reference in the `libsigner` crate.

    fn next_event(&mut self) -> Result<SignerEvent<T>, EventError> {
        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)
            } else if request.url() == "/new_block" {
                process_event::<T, StacksBlockEvent>(request)
            } else {
                let url = request.url().to_string();
                debug!(
                    "[{:?}] next_event got request with unexpected url {}, return OK so other side doesn't keep sending this",
                    event_receiver.local_addr,
                    url
                );
                ack_dispatcher(request);
                Err(EventError::UnrecognizedEvent(url))
            }
        })?

fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}
```

### 2. Configure the Signer

Use [`mainnet-signer-conf.toml`](../sample/conf/signer/mainnet-signer-conf.toml) as a starting point.
Key settings:

```toml
stacks_private_key = "<YOUR_SIGNER_PRIVATE_KEY_HEX>"
node_host = "127.0.0.1:20443"
endpoint = "0.0.0.0:30000"
network = "mainnet"
auth_password = "your-secret-token"
db_path = "/var/lib/stacks-signer/signerdb.sqlite"
```

### 3. Verify Coordination

These settings **must** match between the node and signer configs:

| Signer Config   | Node Config                       | Must Match                    |
| --------------- | --------------------------------- | ----------------------------- |
| `auth_password` | `[connection_options] auth_token` | Exact string match            |
| `endpoint`      | `[[events_observer]] endpoint`    | Same host:port                |
| `node_host`     | `[node] rpc_bind`                 | Signer connects to node's RPC |
```
