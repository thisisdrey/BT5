### Title
Bazel's `git_repository` re-enables local-filesystem submodule cloning (`protocol.file.allow=always`), allowing an attacker-published repository to exfiltrate arbitrary host files - ([File: tools/build_defs/repo/git_worker.bzl])

### Summary
`git_repository`/`new_git_repository` shell out to the system `git` binary to clone and, optionally, recursively initialize submodules. When submodules are enabled, Bazel unconditionally passes `-c protocol.file.allow=always` to `git submodule update`, which disables the upstream Git hardening (default `protocol.file.allow=user`) that was added specifically to stop a malicious repository from using a submodule `url=` entry pointing at a local filesystem path to read arbitrary files off the machine performing the clone (the class of bug fixed by Git as CVE-2022-39253). Because the `.gitmodules` file — including every submodule `url` — is content supplied entirely by whoever publishes/controls the fetched Git ref, an unprivileged attacker who publishes (or maintains a branch that CI tracks without a commit pin) the dependency can embed a submodule URL such as `../../../../etc` or an absolute local path, and Bazel's explicit override makes Git perform a same-host "clone" of that path into the external repository tree.

### Finding Description
`update_submodules` in `git_worker.bzl` builds the submodule-update commands with a forced local-protocol allowance: [1](#0-0) 

```
def update_submodules(ctx, git_repo, recursive = False):
    if recursive:
        # "protocol.file.allow=always" allows the submodule command clone from a local directory.
        # It's necessary for Git 2.38.1 and assoicated backport versions.
        # See https://github.com/bazelbuild/bazel/issues/17040
        _git_maybe_shallow(ctx, git_repo, "-c", "protocol.file.allow=always", "submodule", "update", "--init", "--recursive", "--checkout", "--force")
    else:
        _git_maybe_shallow(ctx, git_repo, "-c", "protocol.file.allow=always", "submodule", "update", "--init", "--checkout", "--force")
```

This code path is reached whenever `git_repository(init_submodules = True, ...)` or `recursive_init_submodules = True` is used — both are ordinary, documented, commonly used attributes: [2](#0-1) 

The actual `.gitmodules` content (which defines each submodule's `url`) comes from the fetched remote repository's tree, i.e. it is data supplied by whatever party controls the content at `ctx.attr.remote` for the fetched ref (`commit`, `tag`, or `branch`): [3](#0-2) 

Upstream Git changed the default of `protocol.file.allow` from `always` to `user` in 2.38.1 precisely to stop this class of attack, because a submodule `url` pointing at a local path (absolute, or relative such as `../../../secret`) makes `git submodule update` perform a same-machine "clone" that copies arbitrary readable files/directories on the build host into the checked-out submodule directory. Bazel's `git_worker.bzl` explicitly reverts that protection for every submodule-enabled `git_repository` fetch, with no scheme/path validation of submodule URLs anywhere in the file.

### Impact Explanation
If a `git_repository`/`git_override` dependency (a) is tracked by `branch` (no `commit` pin — an untrusted branch a victim's CI continuously re-fetches) or (b) is simply an externally-authored repository whose maintainer/publisher is the attacker (a normal "third-party dependency" trust boundary, not root-repo Starlark), and `init_submodules`/`recursive_init_submodules` is enabled, the attacker can ship a `.gitmodules` entry with a `file://` or path-only `url` that resolves to sensitive local files/directories on the machine running the Bazel fetch (e.g. `~/.ssh`, CI credential files mounted into the workspace, `/etc`, the repository cache, or other parts of the output base reachable by path traversal). Git will read that local content and place it into the external repository's working tree, from where it becomes visible to subsequent build actions (globs, `genrule`s, packaging steps, or simply committed/uploaded build outputs), constituting a containment/read violation and potential credential/file exfiltration.

### Likelihood Explanation
Recursive/`init_submodules` git dependencies are common in real Bazel projects, and Git's own default (`protocol.file.allow=user`) exists precisely because this attack pattern is realistic and was assigned a CVE. Bazel deliberately disables that default for every such fetch, with the override applying regardless of whether the fetched content is fully trusted, branch-tracked, or a widely-used open source dependency whose upstream host or account could be compromised. No additional attacker capability beyond publishing repository content is required.

### Recommendation
Do not unconditionally force `protocol.file.allow=always`. Restrict the override (if still needed for `bazelbuild/bazel#17040`) to same-repository local submodules that resolve within the checkout directory, or validate/reject submodule URLs that use `file://`/local paths (or other command-executing transports such as `ext::`) before invoking `git submodule update`, restoring Git's upstream hardening by default and only relaxing it when the resolved submodule path is verified to stay inside the fetched repository's own directory tree.

### Proof of Concept
1. Attacker publishes (or is granted push access to a tracked branch of) a Git repository `evil-dep` containing a `.gitmodules` file:
   ```
   [submodule "leak"]
       path = leak
       url = ../../../../../../etc
   ```
2. Victim's `MODULE.bazel`/`WORKSPACE` declares:
   ```python
   git_repository(
       name = "evil_dep",
       remote = "https://example.com/attacker/evil-dep.git",
       branch = "main",
       recursive_init_submodules = True,
   )
   ```
3. During `bazel build`, `git_repo()` → `_update()` → `update_submodules()` runs:
   ```
   git -c core.fsmonitor=false -c protocol.file.allow=always submodule update --init --recursive --checkout --force
   ```
   because `protocol.file.allow` is forced to `always`, Git performs a local clone of `/etc` (relative to the submodule's location on disk) into `external/evil_dep/leak`, making host files available inside the Bazel external repository tree — reproducible as a `src/test/shell/bazel` shell integration test that sets up a local git server repo with a submodule pointing at a sibling directory outside the repo and asserts that with a stock/patched Git (`protocol.file.allow` default `user`) the fetch fails, but with Bazel's current `git_worker.bzl` it succeeds and copies the out-of-tree content.

```text
def git_repo(ctx, directory):
    """ Fetches data from git repository and checks out file tree.

    Called by git_repository rule.

    Args:
        ctx: Context of the calling rules, for reading the attributes.
        Please refer to the git_repository rule for the description.
        directory: Directory where to check out the file tree.
    Returns:
        The struct with the following fields:
        commit: Actual HEAD commit of the checked out data.
        shallow_since: Actual date and time of the HEAD commit of the checked out data.
    """
    if ctx.attr.shallow_since:
        if ctx.attr.tag:
            fail("shallow_since not allowed if a tag is specified; --depth=1 will be used for tags")
        if ctx.attr.branch:
            fail("shallow_since not allowed if a branch is specified; --depth=1 will be used for branches")

    # Use shallow-since if given
    if ctx.attr.shallow_since:
        shallow = "--shallow-since=%s" % ctx.attr.shallow_since
    else:
        shallow = "--depth=1"

    reset_ref = ""
    fetch_ref = ""
    if ctx.attr.commit:
        reset_ref = ctx.attr.commit
        fetch_ref = ctx.attr.commit
    elif ctx.attr.tag:
        reset_ref = "tags/" + ctx.attr.tag
        fetch_ref = "tags/" + ctx.attr.tag + ":tags/" + ctx.attr.tag
    elif ctx.attr.branch:
        reset_ref = "origin/" + ctx.attr.branch
        fetch_ref = ctx.attr.branch + ":origin/" + ctx.attr.branch
    else:
        reset_ref = "origin/HEAD"
        fetch_ref = "HEAD:refs/remotes/origin/HEAD"

    git_repo = _GitRepoInfo(
        directory = ctx.path(directory),
        shallow = shallow,
        reset_ref = reset_ref,
        fetch_ref = fetch_ref,
        remote = str(ctx.attr.remote),
        init_submodules = ctx.attr.init_submodules,
        recursive_init_submodules = ctx.attr.recursive_init_submodules,
    )
```
