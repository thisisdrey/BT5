### Title
API access-block security filter fails open on any parsing exception, allowing operator-disabled endpoints to be reached - ([File: framework/src/main/java/org/tron/core/services/filter/HttpApiAccessFilter.java])

### Summary
`HttpApiAccessFilter.isDisabled()` and its gRPC counterpart `RpcApiAccessInterceptor.isDisabled()` implement the node's `disabledApiList` security policy — an operator-configured deny-list intended to make specific HTTP/JSON-RPC/gRPC endpoints unreachable (e.g. sensitive wallet APIs). Both methods wrap the deny-list lookup in a `try { ... } catch (Exception e) { log; }` that leaves the local `disabled` variable at its pre-initialized value of `false` whenever any exception occurs while computing or matching the endpoint. This is structurally the same bug class as GHSA-29w2-fq35-v728: when the data/logic used to enforce a configured security policy fails, the code fails open instead of failing closed, and the per-request enforcement is silently skipped. [1](#0-0) 

### Finding Description
`HttpApiAccessFilter.doFilter()` computes the request `endpoint` from `contextPath + servletPath` and calls `isDisabled(endpoint)` to decide whether to reject the request with HTTP 404 before it reaches the actual `Wallet`/JSON-RPC handler. [2](#0-1) 

Inside `isDisabled()`, the deny-list match itself (`URI.create(endpoint).normalize()`, then `endpoint.split("/")[2]`) is wrapped in a try/catch that swallows any exception and simply logs a warning, returning the default `disabled = false`: [1](#0-0) 

The gRPC path (`RpcApiAccessInterceptor.isDisabled()`) has the identical pattern, using `endpoint.split("/")[1]`, with the outer `interceptCall` also catching any exception and calling `next.startCall(...)` (i.e., proceeding with the call) rather than blocking it: [3](#0-2) 

The existing unit test already demonstrates that a crafted path with an unexpected number of segments after normalization (`/wallet/a/b/../getnowblock`) causes the match to fail and the request to be treated as *not* disabled, even though the resolved logical endpoint is `getnowblock`: [4](#0-3) 

This is the exact analog of the reported CWE-455 issue: a security-policy enforcement path (the operator's `disabledApiList`, configured in `reference.conf`/`config.conf` and consumed via `CommonParameter.getInstance().getDisabledApiList()`) is designed to gate/deny access to specific APIs, but any failure in evaluating that policy (malformed/ambiguous path, unexpected segment count, URI normalization edge case) causes the check to default to "allow" rather than "deny," silently bypassing the intended access restriction for the lifetime of that request (and, more importantly, for any input shaped the same way — a systemic bypass class, not a one-off).

### Impact Explanation
An operator who disables a sensitive API endpoint (for example a wallet-management or account-query endpoint listed in `disabledApiList`) expects that endpoint to be completely unreachable — this is the node's only path-level access control for such endpoints since there is no other authentication layer on the HTTP/gRPC API. If the endpoint-matching logic throws (e.g., due to path segment count deviating from the exact index the code expects, `[2]` for HTTP or `[1]` for gRPC), the filter fails open and forwards the request to the real handler, defeating the operator's security policy. Depending on which APIs are disabled in a given deployment (this can include APIs the operator considers unsafe to expose, such as broadcast/administrative endpoints), this can expose functionality the operator explicitly intended to firewall off, an "API the node can no longer serve" being incorrectly served.

### Likelihood Explanation
The request path/endpoint string is fully attacker-controlled (any client can send arbitrary HTTP paths or gRPC method calls), while the matching logic makes fixed assumptions about the number of `/`-separated segments after `URI.create(...).normalize()`. The project's own test (`HttpApiAccessFilterTest.testIsDisabled`) confirms that some legitimately-resolving paths (e.g. containing `..` segments) already produce a different segment count than expected, causing a match miss even without an exception — and any input causing an actual exception in `URI.create`/`split` indexing degrades further into the fail-open catch block. No special privileges are required; this is reachable by any anonymous API client, matching the CVE's "AC:H/PR:N/UI:R" reachability profile via crafted requests rather than by a startup-time data-load failure.

### Recommendation
Change both `isDisabled()` implementations to fail closed: if the endpoint cannot be parsed/matched against the deny list due to an exception, treat the request as disabled (or otherwise reject/require exact match) rather than defaulting `disabled = false`. Additionally, avoid brittle fixed-index `split("/")[n]` matching; instead robustly extract the intended API name (e.g., via the servlet path element or a canonicalized/normalized single-segment comparison) so that legitimately different path shapes for the same disabled endpoint cannot bypass the filter.

### Proof of Concept
Given `disabledApiList = ["getnowblock"]` configured on a running node:
1. A request to `/wallet/getnowblock` is correctly blocked (matches `HttpApiAccessFilterTest.testIsDisabled`, line 136-138).
2. A request to `/wallet/a/b/../getnowblock` — which a servlet container/URI normalizer resolves to the same logical `getnowblock` endpoint — is *not* blocked (`Assert.assertFalse(f)` at line 144-146), because `endpoint.split("/")[2]` picks up `"a"` instead of `"getnowblock"` after normalization, silently bypassing the operator's disabled-API policy and forwarding the request to the live handler.   @Override
  public void doFilter(ServletRequest request, ServletResponse response, FilterChain chain) {
    try {
      if (request instanceof HttpServletRequest) {
        String contextPath = ((HttpServletRequest) request).getContextPath();
        String endpoint = contextPath + ((HttpServletRequest) request).getServletPath();
        HttpServletResponse resp = (HttpServletResponse) response;

        if (isDisabled(endpoint)) {
          resp.setStatus(HttpServletResponse.SC_NOT_FOUND);
          resp.setContentType("application/json; charset=utf-8");
          JSONObject jsonObject = new JSONObject();
          jsonObject.put("Error", "this API is unavailable due to config");
          resp.getWriter().println(jsonObject.toJSONString());
          return;
        }

        CharResponseWrapper responseWrapper = new CharResponseWrapper(resp);
        chain.doFilter(request, responseWrapper);

      } else {
        chain.doFilter(request, response);
      }

    } catch (Exception e) {
      logger.error("http api access filter exception: {}", e.getMessage());
    }
  }

  private boolean isDisabled(String endpoint) {
    boolean disabled = false;

    try {
      endpoint = URI.create(endpoint).normalize().toString();
      List<String> disabledApiList = CommonParameter.getInstance().getDisabledApiList();
      if (!disabledApiList.isEmpty()) {
        disabled = disabledApiList.contains(endpoint.split("/")[2].toLowerCase(Locale.ROOT));
      }
    } catch (Exception e) {
      logger.warn("check isDisabled except, endpoint={}, {}", endpoint, e.getMessage());
    }

    return disabled;
  }

  @Override
  public <ReqT, RespT> Listener<ReqT> interceptCall(ServerCall<ReqT, RespT> call,
      Metadata headers,
      ServerCallHandler<ReqT, RespT> next) {

    String endpoint = call.getMethodDescriptor().getFullMethodName();

    try {
      if (isDisabled(endpoint)) {
        call.close(Status.UNAVAILABLE
            .withDescription("this API is unavailable due to config"), headers);
        return new ServerCall.Listener<ReqT>() {};

      } else {
        return next.startCall(call, headers);
      }
    } catch (Exception e) {
      logger.error("check rpc api access Error: {}", e.getMessage());
      return next.startCall(call, headers);
    }
  }

  private boolean isDisabled(String endpoint) {
    boolean disabled = false;

    try {
      List<String> disabledApiList = CommonParameter.getInstance().getDisabledApiList();
      if (!disabledApiList.isEmpty()) {
        disabled = disabledApiList.contains(endpoint.split("/")[1].toLowerCase(Locale.ROOT));
      }
    } catch (Exception e) {
      logger.error("check isDisabled except, endpoint={}, error is {}", endpoint, e.getMessage());
    }

    return disabled;
  }
