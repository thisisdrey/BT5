### Title
Signer Event HTTP Listener Accepts Unauthenticated POST Requests, Allowing Forged Node Events to Reach the Signer Runloop - ([File: libsigner/src/events.rs])

### Summary
The `SignerEventReceiver` in `libsigner` — the HTTP listener a `stacks-signer` process runs to receive events pushed by its configured `stacks-node` (block proposals, StackerDB chunk events, burn-block events) — accepts and dispatches any POST request on its bound socket with no check of an `Authorization`/`auth_token` header. Any host that can reach the configured listen address can inject forged events directly into the signer's processing pipeline, bypassing the node entirely.

### Finding Description
`SignerEventReceiver::next_event` in `libsigner/src/events.rs` binds an HTTP server and, on every incoming request, dispatches purely by URL path (`/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block`, `/status`, `/shutdown`) directly to `process_event::<T, _>(request)`, with no verification of any shared secret or `Authorization` header before decoding and forwarding the body: [1](#0-0) 

A `grep` for `Authorization`/`auth_token`/`check_auth` inside this file returns no matches, confirming there is no authentication gate on this inbound channel. This stands in contrast to the documented security model, where `auth_token`/`auth_password` is described as securing "the communication channel between this node and a connected `stacks-signer` instance": [2](#0-1) 

Sample deployment configs explicitly instruct binding this listener on all interfaces (`endpoint = "0.0.0.0:30000"`), which is the deployment topology the docs recommend: [3](#0-2) 

The `forward_event` method then unconditionally pushes whatever was decoded into the signer runloop's channel with no re-validation of its origin: [4](#0-3) 

This mirrors the report's bug class: an untrusted, attacker-controlled input (there, an image URL; here, an HTTP POST body) is consumed and acted upon without validating that it actually originated from the trusted, expected party (there, no filetype/origin validation before firing a GET; here, no `Authorization`/`auth_token` check before accepting the event as authentic node-originated data). The equality broken is: "event received on this socket came from the configured, trusted `stacks-node`" vs. "event received on this socket came from any host that can reach the port," and the code silently assumes the former without checking it.

### Impact Explanation
An attacker who can reach the signer's event-listener port can submit fabricated `StackerDBChunksEvent`, `BlockValidateResponse`, `BurnBlockEvent`, or `StacksBlockEvent` payloads directly to the signer process, impersonating the node. Because `process_event`/`forward_event` place these directly onto the channel consumed by the signer's runloop with no source authentication, this is an unauthenticated write of attacker-controlled data into the signer's event stream — a channel that is documented as being protected by a shared secret but is not actually checked in this transport code. This can desynchronize or corrupt a signer's view of node state (fed burn-block/StackerDB/proposal-response events it never actually received from its node), which is a precursor to signer misbehavior, even though the signer's downstream decision logic itself is out of scope for this report.

### Likelihood Explanation
Likelihood is moderate-to-high for deployments following the provided sample configuration, which explicitly recommends binding the listener on `0.0.0.0`. No credentials, node secret keys, or privileged roles are required — only network reachability to the configured port — satisfying the "remote, unprivileged" requirement.

### Recommendation
Require and verify an `Authorization` header (matching the documented `auth_token`/`auth_password` shared secret) on every incoming request in `SignerEventReceiver::next_event` before dispatching to `process_event`, rejecting unauthenticated requests with an HTTP error rather than processing them.

### Proof of Concept
1. Configure/observe a signer per the sample config, whose event listener binds `0.0.0.0:30000` as documented in `sample/conf/signer/mainnet-signer-conf.toml`.
2. From a remote host with network access to port 30000, send a raw HTTP POST to `/stackerdb_chunks` with an arbitrary, self-crafted JSON body deserializable as `StackerDBChunksEvent` (no `Authorization` header required, mirroring the test harness pattern at `libsigner/src/tests/mod.rs:120-143`, but from an unauthenticated third party rather than the real node).
3. Observe that `SignerEventReceiver::next_event` (`libsigner/src/events.rs:413-458`) accepts the request purely based on the URL path, decodes it, and `forward_event` pushes it onto the signer runloop's channel — with no rejection due to missing authentication.

    fn next_event(&mut self) -> Result<SignerEvent<T>, EventError> {
        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)
            } else if request.url() == "/new_block" {
                process_event::<T, StacksBlockEvent>(request)
            } else {
                let url = request.url().to_string();
                debug!(
                    "[{:?}] next_event got request with unexpected url {}, return OK so other side doesn't keep sending this",
                    event_receiver.local_addr,
                    url
                );
                ack_dispatcher(request);
                Err(EventError::UnrecognizedEvent(url))
            }
        })?

    /// Forward an event
    /// Return true on success; false on error.
    /// Returning false terminates the event receiver.
    fn forward_event(&mut self, ev: SignerEvent<T>) -> bool {
        if self.out_channels.is_empty() {
            // nothing to do
            error!("No channels connected to event receiver");
            false
        } else if self.out_channels.len() == 1 {
            // avoid a clone
            if let Err(e) = self.out_channels[0].send(ev) {
                error!("Failed to send to signer runloop: {:?}", &e);
                return false;
            }
            true
        } else {
            for (i, out_channel) in self.out_channels.iter().enumerate() {
                if let Err(e) = out_channel.send(ev.clone()) {
                    error!("Failed to send to signer runloop #{}: {:?}", i, &e);
                    return false;
                }
            }
            true
        }
    }
