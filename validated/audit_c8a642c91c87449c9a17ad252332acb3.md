Audit Report

## Title
Fee-refund quote (`quote_price_exact_tokens_for_tokens`) recomputed post-dispatch on a pool the extrinsic itself can move, causing silent, unrecoverable overpayment when the refund swap can no longer be quoted - (File: `substrate/frame/transaction-payment/asset-conversion-tx-payment/src/payment.rs`)

## Summary
`SwapAssetAdapter::withdraw_fee` locks in `asset_fee` via a pre-dispatch quote (`quote_price_tokens_for_exact_tokens`) at [1](#0-0) , then `correct_and_deposit_fee` re-quotes the same pool post-dispatch via `quote_price_exact_tokens_for_tokens` and silently treats a failed quote (`None`) as zero refund rather than an error, forfeiting the entire withheld fee to `OU` at [2](#0-1) . Because the dispatched call executes between these two quotes and can freely trade against the same public AMM pool, a user (or interleaved extrinsic) can move reserves such that the refund quote returns `None`, causing the payer to lose the full withheld amount instead of the correct partial refund.

## Finding Description
`withdraw_fee` withdraws `asset_fee` of the non-native asset based on a pre-dispatch quote of the pool state [3](#0-2) . After the dispatched call runs — with full access to the same public `pallet-asset-conversion` pool, e.g. via `swap_exact_tokens_for_tokens` or `remove_liquidity` — `correct_and_deposit_fee` computes `refund_amount = fee_paid - corrected_fee` and re-quotes the pool with `quote_price_exact_tokens_for_tokens(A::get(), asset_id, refund_amount, true)` [4](#0-3) . `quote_price_exact_tokens_for_tokens`'s underlying implementation returns `None` whenever the pool reserve is zero or the swap output exceeds the pool's reducible balance [5](#0-4) . When the quote fails, the code takes `.unwrap_or(Zero::zero())` and then, because `refund_asset_amount.is_zero()`, enters the "cannot swap back" branch that hands the entire `fee_paid` to `OU::on_unbalanceds` with **no refund at all** to the payer [6](#0-5) . This is exactly the same code path described in the claim, present verbatim in this repository.

## Impact Explanation
This breaks the "conserve value and settle exactly once to the rightful beneficiary and amount" invariant for fee accounting: an unprivileged signed user is charged based on a pre-dispatch AMM quote and, after their own dispatched call moves the same pool's reserves, receives zero refund instead of the correct amount — an unbacked, silent transfer of value from the payer to the fee destination `OU`. `SwapAssetAdapter` is a first-class, publicly configurable FRAME component (not test-only), so any runtime enabling asset-conversion-based fee payment is affected.

## Likelihood Explanation
No privileged actor or off-chain assumption is required. A normal signed account paying fees in a non-native asset, whose single extrinsic dispatches a call trading against the exact fee-conversion pool (public `AssetConversion::swap_exact_tokens_for_tokens` / `remove_liquidity`), can trigger the zero-refund branch, and it can also occur naturally with thin liquidity and any other extrinsic in the same block shifting reserves between the two quotes.

## Recommendation
Do not silently drop the refund on a failed post-dispatch quote in `correct_and_deposit_fee`. Options: fail the transaction (revert) rather than default to zero when the swap-back can't be quoted; queue/retry the refund as a debt; or bound the refund using the same pool-state snapshot taken at withdrawal time instead of re-quoting a state the extrinsic itself can move.

## Proof of Concept
1. Configure a runtime with `pallet_asset_conversion_tx_payment::SwapAssetAdapter` as `OnChargeAssetTransaction`; create a thin-liquidity pool between native asset `A` and asset `X`.
2. Submit an extrinsic paying fees in `X` (`ChargeAssetTxPayment::from(tip, Some(X))`) whose dispatched call is `AssetConversion::swap_exact_tokens_for_tokens([X, A], ...)` or `remove_liquidity` that drains the `A`/`X` pool.
3. `withdraw_fee` quotes and withdraws `asset_fee` of `X` pre-call [1](#0-0) .
4. The dispatched call drains the pool reserves.
5. `correct_and_deposit_fee` calls `quote_price_exact_tokens_for_tokens(A, X, refund_amount, true)`, which returns `None` due to depleted reserves, so `refund_asset_amount` becomes `0` and the entire `fee_paid` is forfeited to `OU` with zero refund to the payer [7](#0-6) .

				asset_id.clone(),

				fee,
				Precision::Exact,
				Preservation::Preserve,
				Fortitude::Polite,
			)
			.map_err(|_| InvalidTransaction::Payment)?;

			return Ok((fee_credit, fee));
		}

		// Quote the amount of the `asset_id` needed to pay the fee in the asset `A`.
		let asset_fee =
			S::quote_price_tokens_for_exact_tokens(asset_id.clone(), A::get(), fee, true)
				.filter(|asset_fee| !asset_fee.is_zero())
				.ok_or(InvalidTransaction::Payment)?;

		// Withdraw the `asset_id` credit for the swap.
		let asset_fee_credit = F::withdraw(
			asset_id.clone(),
			who,
			asset_fee,
			Precision::Exact,
			Preservation::Preserve,
			Fortitude::Polite,
		)
		.map_err(|_| InvalidTransaction::Payment)?;

		let (fee_credit, change) = match S::swap_tokens_for_exact_tokens(
			vec![asset_id, A::get()],

			Err((credit_in, _)) => {

				let _ = F::resolve(who, credit_in).defensive_proof("Should resolve the credit");
				return Err(InvalidTransaction::Payment.into());
			},
		};

		// Since the exact price for `fee` has been quoted, the change should be zero.
		ensure!(change.peek().is_zero(), InvalidTransaction::Payment);

		Ok((fee_credit, asset_fee))
	}
