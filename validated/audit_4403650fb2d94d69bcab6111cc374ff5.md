### Title
Cross-repository object disclosure via attacker-controlled `GitObjectDirectory`/`GitAlternateObjectDirectories` on quarantine-based mutator RPCs (e.g. `UserUpdateSubmodule`) - ([File: internal/gitaly/service/operations/submodules.go], [internal/git/quarantine/quarantine.go], [internal/gitaly/storage/storagemgr/middleware.go])

### Summary
`UserUpdateSubmodule` calls `s.quarantinedRepo(ctx, req.GetRepository())`, which forwards the caller-supplied `gitalypb.Repository` message — including any attacker-populated `GitObjectDirectory`/`GitAlternateObjectDirectories` — straight into `quarantine.New`/`quarantine.Apply`. `Apply` folds these attacker-controlled values into the quarantined repo's alternates list without validating or stripping them, and `alternates.Env` turns them into `GIT_OBJECT_DIRECTORY`/`GIT_ALTERNATE_OBJECT_DIRECTORIES` via a plain `filepath.Join` that does not prevent `..` traversal. The only defense against this is the transaction middleware's `ErrQuarantineConfiguredOnMutator` check, but that check is only wired up when Gitaly's WAL/transactions feature is enabled, which the code and docs describe as an opt-in, experimental, non-default feature.

### Finding Description
`UserUpdateSubmodule` (`internal/gitaly/service/operations/submodules.go:28`) does:
```go
quarantineDir, quarantineRepo, cleanup, err := s.quarantinedRepo(ctx, req.GetRepository())
``` [1](#0-0) 

`quarantinedRepo` (`internal/gitaly/service/operations/server.go:50-58`) simply calls `quarantine.New(ctx, repo, ...)` with the raw request repository and builds a `localrepo.Repo` from the result: [2](#0-1) 

`quarantine.New`/`Apply` (`internal/git/quarantine/quarantine.go:37-88`) does not reject or clear a pre-existing `GitObjectDirectory`/`GitAlternateObjectDirectories` on the incoming repo. Instead it *uses* the existing `GetGitObjectDirectory()` as the base object dir (defaulting to `"objects"` only if empty) and *appends* the caller-supplied `GetGitAlternateObjectDirectories()` to the new alternates list: [3](#0-2) 

These alternates are later turned into git environment variables by `alternates.Env`, which does a raw `filepath.Join(repoPath, dir)` with no traversal check: [4](#0-3) 

The only place in the codebase that rejects a mutator request carrying a pre-populated `GitObjectDirectory`/`GitAlternateObjectDirectories` is the transaction middleware's `beginTransactionForRepository`, which explicitly checks for this and returns `ErrQuarantineConfiguredOnMutator` for `OpMutator` RPCs: [5](#0-4) 

Critically, this middleware is only installed when `cfg.Transactions.Enabled` is true (`internal/cli/gitaly/serve.go:462-464`), which the project's own docs describe as "an experimental feature... not production ready yet": [6](#0-5) 

When transactions/WAL are not enabled (the historical/legacy code path, and not a state requiring "non-default" hardening — quite the opposite, it is the currently-shipped default absent explicit opt-in), `UserUpdateSubmodule` and other quarantine-based mutators receive the raw request with no interception, and `quarantinedRepo`/`quarantine.Apply` will happily incorporate attacker-supplied `GitAlternateObjectDirectories` into the alternates used for `ReadTree`, `ResolveRevision`, and `WriteCommit`. If an attacker sets `GitAlternateObjectDirectories` to a path-traversal relative string (e.g. `"../../<victim-storage-relative-path>/objects"`) pointing at another repository's object store on the same storage, the alternates mechanism gives the attacker's quarantined `localrepo.Repo` visibility into the victim's objects, letting `ResolveRevision`/`ReadTree` dereference victim-only OIDs and `WriteCommit` bake them into the attacker's new commit (e.g. as a submodule tree entry), which then gets written into the attacker's own repository and can be fetched back out.

### Impact Explanation
This is a cross-repository object disclosure primitive: with knowledge (or a guess, e.g. from GitLab's deterministic hashed-storage paths) of a victim repository's relative path on the same Gitaly storage, an unprivileged fork owner can smuggle a `GitAlternateObjectDirectories` entry into a mutator RPC that Gitaly interprets as trusted quarantine configuration. This can expose the content of blobs/trees/commits from repositories the attacker has no access to, matching GitLab's "unauthorized access to private repository data" bounty impact class. The severity depends on the ability to enumerate/guess victim relative paths, and is limited by the fact WAL/transactions is intended to close this hole once GA.

### Likelihood Explanation
- Preconditions: Gitaly deployed with transactions/WAL disabled (the non-experimental/legacy configuration), and the attacker must know or be able to guess the victim's storage-relative path.
- Attacker capability: fully within scope — any user who owns a repository can freely set `GitObjectDirectory`/`GitAlternateObjectDirectories` on their own `Repository` proto field in a `UserUpdateSubmoduleRequest` (or other quarantine-based mutator such as `UserCommitFiles`, `UserMergeBranch`, etc., all of which call the same `quarantinedRepo` pattern).
- Repeatability: deterministic and repeatable — no race conditions or timing dependency.
- The main uncertainty is whether GitLab Rails' hashed-storage relative paths are practically guessable for a given target project without prior access, and whether `s.locator.ValidateRepository` performs any traversal-sanitization on the `GitObjectDirectory`/`GitAlternateObjectDirectories` fields specifically (this could not be conclusively confirmed from the available index; that function was not found in the searchable code index).

### Recommendation
Do not trust attacker-supplied `GitObjectDirectory`/`GitAlternateObjectDirectories` on requests destined for mutator RPCs regardless of whether WAL/transactions are enabled. Either:
1. Move the `ErrQuarantineConfiguredOnMutator`-style rejection into a check that always runs (not gated behind the experimental transaction middleware), e.g. in `storage.Locator.ValidateRepository` or directly in `quarantinedRepo`/`quarantine.New`, rejecting any repository message with a pre-set `GitObjectDirectory`/`GitAlternateObjectDirectories` on mutator RPCs; and
2. Validate that any accepted `GitObjectDirectory`/`GitAlternateObjectDirectories` values resolve (after `filepath.Join` and `Clean`) to paths within the repository's own storage-relative subtree, rejecting any traversal outside of it.

func TestUserUpdateSubmodule_CrossRepoAlternateInjection(t *testing.T) {

	// attacker-owned repo
	repoProto, repoPath := gittest.CreateRepository(t, ctx, cfg, gittest.CreateRepositoryConfig{})
	// victim repo containing a secret blob, elsewhere on the same storage
	victimProto, victimPath := gittest.CreateRepository(t, ctx, cfg, gittest.CreateRepositoryConfig{})
	secretOID := gittest.WriteBlob(t, cfg, victimPath, []byte("victim secret"))

	// craft relative path from attacker repo to victim's objects dir
	rel, err := filepath.Rel(repoPath, filepath.Join(victimPath, "objects"))
	require.NoError(t, err)

	// set up attacker repo w/ submodule scaffolding, master branch, etc. (omitted for brevity)
	repoProto.GitAlternateObjectDirectories = []string{rel} // attacker-controlled field

	_, err = client.UserUpdateSubmodule(ctx, &gitalypb.UserUpdateSubmoduleRequest{
		Repository:    repoProto,
		User:          gittest.TestUser,
		CommitSha:     secretOID.String(), // reference to victim-only object
		Branch:        []byte("master"),
		Submodule:     []byte("sub"),
		CommitMessage: []byte("steal"),
	})

	// Expected (secure) behavior: err should be ErrQuarantineConfiguredOnMutator-equivalent,
	// or ResolveRevision should fail to find secretOID.
	// Actual (vulnerable) behavior without WAL: request succeeds, secretOID gets referenced
	// into attacker's tree/commit and becomes fetchable from the attacker's repo.

// Apply applies the quarantine on the repository. This is done by setting the quarantineDirectory
// as the repository's object directory, and configuring the repository's object directory as an alternate.
func Apply(repoPath string, repo *gitalypb.Repository, quarantineDir string) (*gitalypb.Repository, error) {
	relativePath, err := filepath.Rel(repoPath, quarantineDir)
	if err != nil {
		return nil, fmt.Errorf("creating quarantine: %w", err)
	}

	// All paths are relative to the repository root.
	objectDir := repo.GetGitObjectDirectory()
	if objectDir == "" {
		// Set the default object directory as an alternate if the repository didn't
		// have the object directory overwritten yet.
		objectDir = "objects"
	}

	alternateObjectDirs := make([]string, 0, len(repo.GetGitAlternateObjectDirectories())+1)
	alternateObjectDirs = append(alternateObjectDirs, objectDir)
	alternateObjectDirs = append(alternateObjectDirs, repo.GetGitAlternateObjectDirectories()...)

	quarantinedRepo := proto.Clone(repo).(*gitalypb.Repository)
	quarantinedRepo.GitObjectDirectory = relativePath
	quarantinedRepo.GitAlternateObjectDirectories = alternateObjectDirs

	return quarantinedRepo, nil
}

// Env returns the alternate object directory environment variables.
func Env(repoPath, objectDirectory string, alternateObjectDirectories []string) []string {
	var env []string
	if objectDirectory != "" {
		env = append(env, fmt.Sprintf("GIT_OBJECT_DIRECTORY=%s", filepath.Join(repoPath, objectDirectory)))
	}

	if len(alternateObjectDirectories) > 0 {
		var dirsList []string

		for _, dir := range alternateObjectDirectories {
			dirsList = append(dirsList, filepath.Join(repoPath, dir))
		}

		env = append(env, fmt.Sprintf("GIT_ALTERNATE_OBJECT_DIRECTORIES=%s", strings.Join(dirsList, ":")))
	}

	return env
}
