### Title
Unsolicited/unlinked attachments accepted via `POST /v2/transactions` can evict legitimately-referenced pending attachments - ([File: stackslib/src/net/atlas/db.rs])

### Summary
`AtlasDB::insert_uninstantiated_attachment` inserts attacker-supplied attachment bytes into the `attachments` table keyed only by `attachment.hash()`, with no check that the hash matches any `content_hash` in a confirmed on-chain `AttachmentInstance`. This is reachable via the unauthenticated `POST /v2/transactions` RPC endpoint, and the eviction policy (`evict_k_oldest_uninstantiated_attachments`) removes rows purely by insertion age, so flooding this endpoint with junk attachments can cause legitimately pending (contract-committed) attachments to be evicted from local storage.

### Finding Description
The reachable path is: `RPCPostTransactionRequestHandler::try_parse_request` decodes a JSON body containing `tx` and `attachment` [1](#0-0) . In `try_handle_request`, after the transaction is accepted into the mempool, if the transaction is a `ContractCall` and `should_keep_attachment(contract_id, attachment)` returns true, the raw attacker-supplied `Attachment` is passed straight to `network.get_atlasdb_mut().insert_uninstantiated_attachment(attachment)` [2](#0-1) .

Inside `insert_uninstantiated_attachment`, the code computes `attachment.hash()` from the attacker-controlled bytes and inserts it directly with `was_instantiated = 0`, with no lookup against `attachment_instances.content_hash` to confirm any committed name/contract operation actually references that hash [3](#0-2) . Before inserting, if `count_uninstantiated_attachments() >= max_uninstantiated_attachments`, it evicts `1 + uninstantiated_attachments - max_uninstantiated_attachments` rows via `evict_k_oldest_uninstantiated_attachments`, which deletes strictly by `created_at ASC` among `was_instantiated = 0` rows — with no validity or reference check [4](#0-3) .

The only gate is `should_keep_attachment`, whose implementation was not located in this investigation; based on the call pattern it plausibly checks the contract is a tracked Atlas contract and enforces a size limit, but it cannot verify a specific `content_hash` binding since at POST time there is no guarantee an on-chain `AttachmentInstance` for that content has even been mined yet (that is, in fact, the entire purpose of the "uninstantiated" staging table — to hold attachments in advance of/independently of instance confirmation). This means the equality "stored_attachment.hash() == some committed AttachmentInstance.content_hash" is never enforced at insert time, matching the question's claim.

### Impact Explanation
An attacker who can reach the node's RPC port can submit `ContractCall` transactions to any Atlas-tracked contract with a distinct fabricated attachment payload in each request. Once accepted to the mempool, `insert_uninstantiated_attachment` stores it, and once `max_uninstantiated_attachments` is reached, further attacker inserts trigger eviction of the oldest `was_instantiated = 0` rows — which may be legitimate attachments awaiting confirmation from real, previously-processed name/contract operations. This is a High-severity finding per the given severity rubric ("attachment/BNS mismatch"/storage-integrity issue tied to a consensus commitment): the node's uninstantiated-attachment cache can be polluted and legitimate pending state evicted, undermining reliable serving/relay of attachments actually referenced by chain state.

### Likelihood Explanation
Precondition: the attacker needs to submit valid, mempool-acceptable `ContractCall` transactions (i.e., pay a fee, use a valid nonce, and target a contract tracked by `AtlasConfig.contracts`) targeting the node's `/v2/transactions` RPC endpoint — no admin secret or peer key is required, matching the "unprivileged remote attacker" threat model. Each attack unit costs a distinct valid transaction (nonce/fee), which bounds throughput compared to a free flood but does not require any privileged capability, and is fully repeatable as long as the attacker can keep submitting valid transactions.

### Recommendation
Before inserting into the `attachments` table via `insert_uninstantiated_attachment`, require that `attachment.hash()` match at least one existing row in `attachment_instances.content_hash` (i.e., only cache attachments that are actually referenced by a known, already-queued/confirmed `AttachmentInstance`), or otherwise bound/rate-limit uninstantiated attachment ingestion per-source. Additionally, consider making `evict_k_oldest_uninstantiated_attachments` prefer evicting attachments with no corresponding row in `attachment_instances` before evicting ones that are actually referenced.

### Proof of Concept
Rust test in `stackslib::net::atlas::db` (or `tests.rs`, following existing patterns there):
1. Construct `AtlasDB::connect_memory` with a small `max_uninstantiated_attachments` (e.g. 2).
2. Call `insert_attachment_instance`/`queue_attachment_instance` (legitimate path) to register one `AttachmentInstance` whose `content_hash` equals `legit_attachment.hash()`, then call `insert_uninstantiated_attachment(&legit_attachment)`.
3. Call `insert_uninstantiated_attachment` repeatedly with `max_uninstantiated_attachments` distinct attacker-crafted `Attachment` values that have no corresponding `AttachmentInstance` row.
4. Assert that `find_uninstantiated_attachment(&legit_attachment.hash())` returns `None` (i.e., it was evicted) while the attacker's junk entries remain, confirming `evict_k_oldest_uninstantiated_attachments` evicted by age only, not validity.

    fn parse_posttransaction_json(
        body: &[u8],
    ) -> Result<(StacksTransaction, Option<Attachment>), Error> {
        let body: PostTransactionRequestBody = serde_json::from_slice(body)
            .map_err(|_e| Error::DecodeError("Failed to parse body".into()))?;

        let tx = {
            let tx_bytes = hex_bytes(&body.tx)
                .map_err(|_e| Error::DecodeError("Failed to parse tx".into()))?;
            StacksTransaction::consensus_deserialize(&mut &tx_bytes[..]).map_err(|e| {
                if let CodecError::DeserializeError(msg) = e {
                    Error::DecodeError(format!("Failed to deserialize posted transaction: {}", msg))
                } else {
                    e.into()
                }
            })
        }?;

        let attachment = match body.attachment {
            None => None,
            Some(ref attachment_content) => {
                let content = hex_bytes(attachment_content)
                    .map_err(|_e| Error::DecodeError("Failed to parse attachment".into()))?;
                Some(Attachment::new(content))
            }
        };

        Ok((tx, attachment))
    }

    pub fn insert_uninstantiated_attachment(
        &mut self,
        attachment: &Attachment,
    ) -> Result<(), db_error> {
        // Insert the new attachment
        let uninstantiated_attachments = self.count_uninstantiated_attachments()?;
        if uninstantiated_attachments >= self.atlas_config.max_uninstantiated_attachments {
            let to_delete =
                1 + uninstantiated_attachments - self.atlas_config.max_uninstantiated_attachments;
            self.evict_k_oldest_uninstantiated_attachments(to_delete)?;
        }

        let tx = self.tx_begin()?;
        let now = util::get_epoch_time_secs() as i64;
        let res = tx.execute(
            "INSERT OR REPLACE INTO attachments (hash, content, was_instantiated, created_at) VALUES (?, ?, 0, ?)",
            params![
                attachment.hash(),
                attachment.content,
                now,
            ],
        );
        res.map_err(db_error::SqliteError)?;
        tx.commit().map_err(db_error::SqliteError)?;
        Ok(())
    }

    pub fn evict_k_oldest_uninstantiated_attachments(&mut self, k: u32) -> Result<(), db_error> {
        let tx = self.tx_begin()?;
        let res = tx.execute(
            "DELETE FROM attachments WHERE hash IN (SELECT hash FROM attachments WHERE was_instantiated = 0 ORDER BY created_at ASC LIMIT ?)",
            params![k],
        );
        res.map_err(db_error::SqliteError)?;
        tx.commit().map_err(db_error::SqliteError)?;
        Ok(())
    }
