### Title
Any contract invoked via `Operator.execute` can impersonate the caller and move their unlocked deposit tokens - ([File: contracts/Operator.sol](contracts/Operator.sol))

### Summary
`Operator.execute` stores the EOA caller in transient storage and then performs arbitrary external calls to attacker-influenceable `target` contracts. While such a target executes, `msg.sender == Operator`, so `SynthContext._msgSender()` resolves to the victim's address for every protocol contract call the target makes. A malicious target therefore has full impersonation rights over the victim for the duration of the call — the on-chain equivalent of a cross-origin request executed "on behalf of the user" with no origin validation.

### Finding Description
- `Operator.execute` iterates `calls_` and invokes `call.target.functionCallWithValue(...)` after `setMsgSender` has written the EOA `msg.sender` into `MSG_SENDER_STORAGE`. [1](#0-0) 
- `SynthContext._msgSender()` returns `operator.getActualMsgSender()` whenever `msg.sender == operator`, i.e. during the entire nested call tree of `execute`. [2](#0-1) 
- Protocol contracts (`Pool`, `DepositToken`, `DebtToken`, `SyntheticToken`, `VesperGateway`, `SmartFarmingManager`, `NativeTokenGateway`) all authorize via `SynthContext._msgSender()` (36–62 usages each per grep). A `target` contract called inside a batch can therefore call e.g. `depositToken.transfer(attacker, amount)` or `pool.withdraw(...)` and the protocol treats the victim as the sender. Only `DepositToken._revertIfLocked` limits the theft to the victim's *unlocked* balance — which is still the directly withdrawable collateral.
- There is no validation of `calls_[i].target`: the Operator is a generic multicall that forwards identity to arbitrary code. Unlike a plain EOA transaction (where an external contract sees `msg.sender = victim` but gains no rights), here the called contract inherits the victim's authenticated identity across the entire protocol surface.

Attack path: attacker gets the victim to include one attacker-controlled `target` in an `Operator.execute` batch (phishing front-end, malicious zap/route aggregator, or any third-party contract the victim batch-calls — the same user-interaction requirement as the reference CORS bug, CVSS UI:R). Inside the call, the target calls `DepositToken.transfer(attacker, victim.unlockedBalanceOf(victim))`, drains transferable synthetic tokens via `SyntheticToken.transfer`, or initiates `Pool.withdraw`/`DebtToken` actions as the victim.

### Impact Explanation
Direct theft of user funds: all unlocked `DepositToken` collateral and transferable `SyntheticToken` balances of any user who ever routes a batch through a malicious/compromised target contract can be stolen in one transaction. The identity invariant (only the account owner can move their position) is broken for the duration of the call.

### Likelihood Explanation
Requires the victim to include an attacker-controlled target in an `execute` batch — analogous to the UI:R phishing precondition of the CORS advisory. `nonReentrant` prevents reentering `execute` itself but does not restrict what the called target does with the inherited identity; transient storage is correctly cleared only after the batch finishes. No governance, keeper, or privileged role is needed on the attacker's side.

### Recommendation
Validate `calls_[i].target` against an allowlist of protocol contracts (Pool, gateways, SmartFarmingManager, tokens), or record per-call the intended `target` in transient storage and let `getActualMsgSender()`/consumers verify the current caller chain. Alternatively, have `SynthContext._msgSender()` only trust the Operator when the immediate calling contract is a registered protocol contract (e.g. check the caller against `poolRegistry.isPoolRegistered` / known token list) rather than trusting any code reachable during the batch.

### Proof of Concept
Foundry fork sketch:

```solidity
contract EvilTarget {
    function drain(IDepositToken dt, address attacker) external {
        // msg.sender == Operator; SynthContext resolves _msgSender() to the victim
        uint256 bal = dt.unlockedBalanceOf(dt.pool(). /* victim via Operator.getActualMsgSender */ );
        dt.transfer(attacker, dt.balanceOf(IOperator(msg.sender).getActualMsgSender()));
    }
}

function testImpersonation() public {
    // victim deposits collateral, then batch-calls a benign action + EvilTarget
    IOperator.Call[] memory calls = new IOperator.Call[](1);
    calls[0] = IOperator.Call({
        target: address(evil),
        value: 0,
        callData: abi.encodeCall(EvilTarget.drain, (depositToken, attacker))
    });
    vm.prank(victim);
    operator.execute(calls);

    assertEq(depositToken.balanceOf(victim), 0);
    assertGt(depositToken.balanceOf(attacker), 0);
}
```

Reproduces on mainnet-fork deployment `0xc06D6347915f6B5e9dBB53Fe17B988b99DbaD360` (deployments/mainnet/Operator.json) against any registered pool's `DepositToken`.
