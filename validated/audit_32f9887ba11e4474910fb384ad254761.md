Based on the codebase evidence, I found a solid local analog to the Alchemix `VotingEscrow` "fill the delegate slots" DoS: `pallet-nomination-pools`' fixed, count-based `MaxPoolMembersPerPool` cap can be exhausted by unprivileged sybil accounts, permanently blocking legitimate users from joining that pool — exactly the same "bounded-count exhaustion, independent of value" pattern as the reported `MAX_DELEGATES` bug.

### Title
Unprivileged sybil accounts can permanently fill a Nomination Pool's `MaxPoolMembersPerPool` slot cap, denying legitimate users the ability to join - (File: `substrate/frame/nomination-pools/src/lib.rs`)

### Summary
`pallet-nomination-pools::join` is a fully permissionless, publicly callable extrinsic that increments a per-pool member counter bounded by a fixed cap, `MaxPoolMembersPerPool`. Unlike stake-sorted lists (e.g. staking's nominator reward cutoff), pool membership admission is purely a *count* check with no value/priority ordering, so anyone can occupy every remaining slot with many low-value accounts, exactly mirroring the reported `MAX_DELEGATES` bug where an attacker fills a bounded destination list regardless of economic value, permanently DoS-ing the target.

### Finding Description
`join` is dispatched by any signed account and targets an arbitrary `pool_id`: [1](#0-0) 

Before bonding funds, it calls `bonded_pool.try_inc_members()`, which enforces only two thresholds — the *count* of members in the target pool and the global member count — with no floor based on stake weighting or an economically meaningful minimum bond size at the protocol level: [2](#0-1) 

The cap itself is a plain `StorageValue<u32>` set via governance/admin (`set_configs`), and by default (see genesis config) `MinJoinBond` can be `0`: [3](#0-2) [4](#0-3) 

The pallet's own test suite demonstrates the exact failure mode: once `MaxPoolMembersPerPool` is reached, all further `join` calls to that pool unconditionally fail with `Error::<Runtime>::MaxPoolMembers`, with no mechanism (priority queue, stake-weighted eviction, minimum-value threshold) that would let a legitimate, higher-value joiner displace low-value sybils: [5](#0-4) 

This is structurally identical to the Alchemix `VotingEscrow` bug: `require(dstTokensOld.length + 1 <= MAX_DELEGATES, ...)` is a pure slot-count guard with no value ordering, so an attacker can pre-fill the bounded list on the target with worthless entries and permanently block legitimate users from being admitted to that same target.

### Impact Explanation
An attacker can, at the cost of only `MinJoinBond` (potentially `0`) plus the existential deposit per sybil account, permanently occupy all `MaxPoolMembersPerPool` slots of any specific nomination pool (including the default/most prominent pools), preventing any further legitimate user from joining that pool via `Pallet::join`. This is a pure griefing/denial-of-service vector against ordinary users of a core staking-participation pathway, with no profit motive required from the attacker, consistent with the "Griefing" impact category described in the source report.

### Likelihood Explanation
The attack requires only the ability to sign transactions from many accounts and fund each with `MinJoinBond` (which may be `0` per default genesis config) plus the account's existential deposit — no privileged origin, validator, collator, or admin action is needed. `join` is a normal, permissionless, publicly documented extrinsic, and the vulnerability is directly exercised by the pallet's own `join_max_member_limits_are_respected` test, confirming the DoS condition is a first-class, reachable code path rather than a theoretical edge case.

### Recommendation
Introduce either (a) a non-zero, protocol-enforced minimum `MinJoinBond` floor that cannot be configured to `0` for pools intended to be publicly joinable, and/or (b) stake-weighted/priority-based admission (or eviction of lowest-stake members) when a pool is at `MaxPoolMembersPerPool`, so that a legitimate higher-value joiner can always displace low-value sybil members, analogous to how `pallet-staking`'s reward-eligible nominator list is sorted by stake rather than by raw slot occupancy.

### Proof of Concept
1. Target a pool `P` with `MaxPoolMembersPerPool = 32` (default) and `MinJoinBond = 0`.
2. From 29 distinct sybil accounts (each funded only with the existential deposit), call `NominationPools::join(origin_i, 0, P)` for `i in 1..=29` until `bonded_pool.member_counter == MaxPoolMembersPerPool`.
3. A legitimate user then calls `NominationPools::join(origin_victim, large_amount, P)`.
4. The call fails with `Error::<T>::MaxPoolMembers` (as verified by the existing `join_max_member_limits_are_respected` test at `substrate/frame/nomination-pools/src/tests.rs:979-1036`), permanently denying the legitimate user access to pool `P` until an admin manually intervenes (kicking members requires the pool to be set to `Blocked`/`Destroying` and administrator action).

	/// Increment the member counter. Ensures that the pool and system member limits are
	/// respected.
	fn try_inc_members(&mut self) -> Result<(), DispatchError> {
		ensure!(
			MaxPoolMembersPerPool::<T>::get()
				.map_or(true, |max_per_pool| self.member_counter < max_per_pool),
			Error::<T>::MaxPoolMembers
		);
		ensure!(
			MaxPoolMembers::<T>::get().map_or(true, |max| PoolMembers::<T>::count() < max),
			Error::<T>::MaxPoolMembers
		);
		self.member_counter = self.member_counter.checked_add(1).ok_or(Error::<T>::OverflowRisk)?;
		Ok(())

		pub fn join(
			origin: OriginFor<T>,
			#[pallet::compact] amount: BalanceOf<T>,
			pool_id: PoolId,
		) -> DispatchResult {
			let who = ensure_signed(origin)?;
			// ensure pool is not in an un-migrated state.
			ensure!(!Self::api_pool_needs_delegate_migration(pool_id), Error::<T>::NotMigrated);

			// ensure account is not restricted from joining the pool.
			ensure!(!T::Filter::contains(&who), Error::<T>::Restricted);

			ensure!(amount >= MinJoinBond::<T>::get(), Error::<T>::MinimumBondNotMet);
			// If a member already exists that means they already belong to a pool
			ensure!(!PoolMembers::<T>::contains_key(&who), Error::<T>::AccountBelongsToOtherPool);

			let mut bonded_pool = BondedPool::<T>::get(pool_id).ok_or(Error::<T>::PoolNotFound)?;
			bonded_pool.ok_to_join()?;

			let mut reward_pool = RewardPools::<T>::get(pool_id)
				.defensive_ok_or::<Error<T>>(DefensiveError::RewardPoolNotFound.into())?;
			// IMPORTANT: reward pool records must be updated with the old points.
			reward_pool.update_records(
				pool_id,
				bonded_pool.points,
				bonded_pool.commission.current(),
			)?;

			bonded_pool.try_inc_members()?;
			let points_issued = bonded_pool.try_bond_funds(&who, amount, BondType::Extra)?;

	#[test]
	fn join_max_member_limits_are_respected() {
		ExtBuilder::default().build_and_execute(|| {
			// Given
			assert_eq!(MaxPoolMembersPerPool::<Runtime>::get(), Some(3));
			for i in 1..3 {
				let account = i + 100;
				Currency::set_balance(&account, 100 + Currency::minimum_balance());

				assert_ok!(Pools::join(RuntimeOrigin::signed(account), 100, 1));
			}

			Currency::set_balance(&103, 100 + Currency::minimum_balance());

			// Then
			assert_eq!(
				pool_events_since_last_call(),
				vec![
					Event::Created { depositor: 10, pool_id: 1 },
					Event::Bonded { member: 10, pool_id: 1, bonded: 10, joined: true },
					Event::MetadataUpdated { pool_id: 1, caller: 900 },
					Event::Bonded { member: 101, pool_id: 1, bonded: 100, joined: true },
					Event::Bonded { member: 102, pool_id: 1, bonded: 100, joined: true }
				]
			);

			assert_noop!(
				Pools::join(RuntimeOrigin::signed(103), 100, 1),
				Error::<Runtime>::MaxPoolMembers
			);
