### Title
Deny-list bypass for disabled JSON HTTP API endpoints via inconsistent path canonicalization in `HttpApiAccessFilter` - (File: `framework/src/main/java/org/tron/core/services/filter/HttpApiAccessFilter.java`)

### Summary
`HttpApiAccessFilter.isDisabled()` is the sole enforcement point for the operator-configured `node.http.disabledApi` deny-list, which node operators use to turn off specific JSON HTTP API endpoints (e.g. `getnowblock`, `getaccount`, or any other `/wallet`, `/walletsolidity`, `/walletpbft` endpoint) without disabling the whole HTTP service. The filter derives the "endpoint name" it checks against the deny-list by calling `URI.create(endpoint).normalize()` and then naively splitting the resulting string on `"/"` and taking index `[2]`, lower-casing it. This is a different, weaker canonicalization than what the underlying Jetty `ServletHandler` uses to actually dispatch the request to the target servlet. Any path representation that Jetty still routes to the disabled servlet but that this ad-hoc parser fails to recognize (extra `/` segments, encoded slashes, trailing segments, or a parse that throws and is silently swallowed) results in `disabled` staying `false`, and the request reaches the "disabled" servlet anyway.

### Finding Description
The filter’s only check is: [1](#0-0) 

```
endpoint = URI.create(endpoint).normalize().toString();
List<String> disabledApiList = CommonParameter.getInstance().getDisabledApiList();
if (!disabledApiList.isEmpty()) {
  disabled = disabledApiList.contains(endpoint.split("/")[2].toLowerCase(Locale.ROOT));
}
```
and the whole computation is wrapped in a broad `try { ... } catch (Exception e) { logger.warn(...); }` that leaves `disabled = false` on any exception [2](#0-1) .

`URI.normalize()` only resolves `.`/`..` segments; it does **not** collapse repeated slashes, does not decode/re-encode percent-escapes consistently with the servlet container, and does not treat encoded or duplicated separators the way Jetty's `ServletHandler` path matching does when actually routing the request to the concrete servlet (e.g. `GetNowBlockServlet` mapped at `/wallet/getnowblock`). Because the filter (`doFilter`) runs *before* dispatch and independently re-derives the "logical endpoint," any divergence between its parsing and Jetty's routing/normalization is a path-canonicalization mismatch of exactly the class described in the reference report: the access-control check is evaluated on one path representation while the resource is served under an equivalent-but-differently-represented path.

Concretely:
- `endpoint.split("/")[2]` assumes exactly the `"/<walletRoot>/<api>"` shape. A request such as `/wallet//getnowblock` (duplicate slash — untouched by `URI.normalize()`, which does not collapse repeated slashes) splits into `["", "wallet", "", "getnowblock"]`; index `[2]` is the empty string `""`, which never matches any entry in `disabledApiList`, so `isDisabled` returns `false` even though `getnowblock` is deny-listed. Whether Jetty still dispatches `//getnowblock` to the same servlet depends on Jetty's own path normalization, which for `ServletHandler` mappings commonly does treat/collapses such variants as the same resource — meaning the filter can be tricked into evaluating the wrong segment while the container still serves the real, denied endpoint.
- Any other malformed variant that causes `endpoint.split("/")` to have fewer than 3 elements (e.g. a doubly-encoded or otherwise unexpected `contextPath+servletPath` combination) throws `ArrayIndexOutOfBoundsException`, which is caught by the blanket `catch (Exception e)` in `doFilter`/`isDisabled`, again defaulting to "not disabled" and letting the request through to `chain.doFilter(...)`.

This mirrors the CVE's root cause pattern precisely: "fail to canonicalize paths before evaluating access rules... alternate path representations that match no rule but resolve to the same [resource], gaining unauthorized access."

The existing test suite only validates the `..`-traversal normalization case and does not cover duplicate slashes, encoded slashes, or malformed-segment exception paths: [3](#0-2) .

### Impact Explanation
`node.http.disabledApi` is an operator-facing security control used to shut off specific HTTP JSON-RPC-style endpoints on a full node, solidity node, or PBFT node (e.g. to reduce attack surface or hide functionality an operator considers unsafe to expose, such as certain query or account-listing endpoints) while keeping the rest of the HTTP API reachable. An unauthenticated/any HTTP client reachable to the node's JSON API port can bypass this administrator-defined deny-list and continue to invoke the "disabled" endpoint by sending a request with a path representation (duplicate slash, malformed segment) that the container still routes to the target servlet but that `HttpApiAccessFilter.isDisabled()` fails to recognize as the denied name. This defeats an explicit administrative access-control decision — matching the High-severity classification of the analogous CVE (access-rule bypass exposing content the administrator explicitly restricted) — although the concrete data/functionality exposed depends on which endpoints an operator has chosen to disable.

### Likelihood Explanation
The affected code path (`HttpApiAccessFilter.doFilter`) is applied to every incoming HTTP request on any exposed `FullNodeHttpApiService`, `SolidityNodeHttpApiService`, `HttpApiOnPBFTService`, or `HttpApiOnSolidityService` instance [4](#0-3) , requiring only that `node.http.disabledApi` be non-empty (a realistic, documented operator configuration) and no authentication — any anonymous API client can attempt the bypass with a single crafted GET/POST request. The mismatch between `URI.normalize()`'s limited scope (only `.`/`..`) and the naive fixed-index `split("/")[2]` parsing is a straightforward, low-complexity condition to trigger.

### Recommendation
- Canonicalize the request path using the same logic the servlet container/dispatcher uses before matching against `disabledApiList`, rather than a custom `URI.normalize()` + fixed-index split.
- Collapse repeated slashes and decode the path consistently (once) prior to segment extraction; do not rely on positional indexing (`[2]`) — instead extract and validate the API name robustly, defaulting to "disabled/deny" (fail-closed) rather than "allowed" when parsing fails or the shape is unexpected.
- Change the `catch (Exception e)` fallback in `isDisabled`/`doFilter` from fail-open (`disabled = false`) to fail-closed for malformed/unparseable paths.
- Add regression tests covering duplicate slashes, percent-encoded slashes, and malformed segments in addition to the existing `..`-traversal case.

### Proof of Concept
1. Configure a node with `node.http.disabledApi = ["getnowblock"]` (deny-listed via `Args`/`CommonParameter.getDisabledApiList()`), as exercised in `HttpApiAccessFilterTest.testHttpFilter` [5](#0-4) .
2. A normal request to `GET /wallet/getnowblock` is correctly blocked with `{"Error":"this API is unavailable due to config"}`.
3. Send `GET /wallet//getnowblock` (duplicate slash) or another path variant that `endpoint.split("/")[2]` cannot resolve to `"getnowblock"` (e.g., causing an `ArrayIndexOutOfBoundsException` that is swallowed by the surrounding `try/catch`), while the underlying Jetty `ServletHandler` mapping still dispatches the request to `GetNowBlockServlet`.
4. Because `isDisabled()` returns `false` for this alternate representation, `HttpApiAccessFilter.doFilter` calls `chain.doFilter(request, responseWrapper)` [6](#0-5) , and the response returns the actual `getnowblock` data, bypassing the administrator's deny rule.

*Note: I was not able to inspect Jetty's exact `ServletHandler` path-mapping/normalization behavior in this codebase (no `addServlet`/`ServletHolder` registration code was found in the indexed portion of `FullNodeHttpApiService.java`), so whether every listed variant is dispatched identically by Jetty could not be fully confirmed from the available index; verifying the precise dispatch normalization Jetty applies for the target servlet path mapping would require a live test or fuller file contents than the index provided.*

  @Override
  public void doFilter(ServletRequest request, ServletResponse response, FilterChain chain) {
    try {
      if (request instanceof HttpServletRequest) {
        String contextPath = ((HttpServletRequest) request).getContextPath();
        String endpoint = contextPath + ((HttpServletRequest) request).getServletPath();
        HttpServletResponse resp = (HttpServletResponse) response;

        if (isDisabled(endpoint)) {
          resp.setStatus(HttpServletResponse.SC_NOT_FOUND);
          resp.setContentType("application/json; charset=utf-8");
          JSONObject jsonObject = new JSONObject();
          jsonObject.put("Error", "this API is unavailable due to config");
          resp.getWriter().println(jsonObject.toJSONString());
          return;
        }

        CharResponseWrapper responseWrapper = new CharResponseWrapper(resp);
        chain.doFilter(request, responseWrapper);

      } else {
        chain.doFilter(request, response);
      }

    } catch (Exception e) {
      logger.error("http api access filter exception: {}", e.getMessage());
    }
  }

  private boolean isDisabled(String endpoint) {
    boolean disabled = false;

    try {
      endpoint = URI.create(endpoint).normalize().toString();
      List<String> disabledApiList = CommonParameter.getInstance().getDisabledApiList();
      if (!disabledApiList.isEmpty()) {
        disabled = disabledApiList.contains(endpoint.split("/")[2].toLowerCase(Locale.ROOT));
      }
    } catch (Exception e) {
      logger.warn("check isDisabled except, endpoint={}, {}", endpoint, e.getMessage());
    }

    return disabled;
  }
