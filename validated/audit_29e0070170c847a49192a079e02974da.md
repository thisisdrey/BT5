### Title
Stale `TombStone.original_owner` Enables Unauthorized Object Reclaim After Transfer — (`aptos-move/framework/aptos-framework/sources/object.move`)

---

### Summary

`object::burn` records the caller's address in a `TombStone` resource stored at the object's address. `object::transfer_raw` (and its inner helper `transfer_raw_inner`) updates `ObjectCore.owner` but **never clears the `TombStone`**. If the object is subsequently transferred to a new owner via `transfer_raw`, and that new owner sends the object to `BURN_ADDRESS`, the original burner can call `object::unburn` and reclaim the object — even though they no longer own it. This is the direct Move analog of the Witch M-03 "second grab overwrites original owner" bug.

---

### Finding Description

`burn` adds a `TombStone { original_owner }` to the object without moving the object itself: [1](#0-0) 

`transfer_raw_inner`, called by every ungated transfer path (`transfer`, `transfer_call`, `transfer_raw`), only mutates `ObjectCore.owner` — it never touches `TombStone`: [2](#0-1) 

By contrast, `transfer_with_ref` explicitly removes the `TombStone` before transferring: [3](#0-2) 

`unburn` has two branches. The BURN_ADDRESS branch trusts `TombStone.original_owner` unconditionally and transfers the object back to that address: [4](#0-3) 

Because `transfer_raw` never clears the `TombStone`, `TombStone.original_owner` can be stale — pointing to a previous owner who has already transferred the object away — and the BURN_ADDRESS branch will still honour it.

---

### Impact Explanation

An attacker (Alice) can permanently reclaim a token object she previously sold or transferred to a victim (Bob), as long as Bob sends the object to `BURN_ADDRESS` via `transfer_raw`. This constitutes **unauthorized reassignment of a token object** (NFT, fungible-asset store, or any `key` resource object), which is within the Aptos bounty scope.

---

### Likelihood Explanation

- All three functions (`burn`, `transfer_raw`/`transfer_call`, `unburn`) are `public entry` — no privileged capability is required.
- `allow_ungated_transfer` defaults to `true` for most objects, making `transfer_raw` to `BURN_ADDRESS` freely callable.
- The scenario arises naturally when a seller soft-burns an NFT before listing it (a common pattern to hide it from indexers), then transfers it to a buyer. If the buyer later tries to permanently destroy the object, they cannot call `burn` again (`EOBJECT_ALREADY_BURNT` aborts), so their only path is `transfer_raw(bob, obj, BURN_ADDRESS)` — exactly the condition Alice needs.

---

### Recommendation

`transfer_raw_inner` should clear any existing `TombStone` before updating `ObjectCore.owner`, mirroring the guard already present in `transfer_with_ref`:

```move
inline fun transfer_raw_inner(object: address, to: address) {
    // Clear stale soft-burn marker so the previous burner cannot reclaim
    // the object via unburn after ownership has changed.
    if (exists<TombStone>(object)) {
        let TombStone { original_owner: _ } = move_from<TombStone>(object);
    };
    let object_core = borrow_global_mut<ObjectCore>(object);
    if (object_core.owner != to) {
        event::emit(Transfer { object, from: object_core.owner, to });
        object_core.owner = to;
    };
}
```

Alternatively, the BURN_ADDRESS branch of `unburn` should verify that `TombStone.original_owner` is still the current owner (i.e., the object was never transferred after burning), and abort otherwise.

---

### Proof of Concept

```
Step 1 — Alice burns her NFT object (soft burn, object stays with Alice):
  object::burn(alice_signer, nft_object)
  → TombStone { original_owner: @alice } stored at nft_addr
  → ObjectCore.owner == @alice  (unchanged)

Step 2 — Alice transfers the NFT to Bob via transfer_raw (TombStone NOT cleared):
  object::transfer_raw(alice_signer, nft_addr, @bob)
  → ObjectCore.owner == @bob
  → TombStone { original_owner: @alice }  ← STALE

Step 3 — Bob tries to permanently destroy the NFT:
  object::burn(bob_signer, nft_object)
  → ABORTS with EOBJECT_ALREADY_BURNT (TombStone already exists)
  Bob falls back to:
  object::transfer_raw(bob_signer, nft_addr, BURN_ADDRESS)
  → ObjectCore.owner == BURN_ADDRESS
  → TombStone { original_owner: @alice }  ← still stale

Step 4 — Alice reclaims the NFT she no longer owns:
  object::unburn(alice_signer, nft_object)
  → object_core.owner == BURN_ADDRESS  → enters BURN_ADDRESS branch
  → original_owner_addr == @alice == signer::address_of(alice_signer)  ✓
  → transfer_raw_inner(nft_addr, @alice)
  → ObjectCore.owner == @alice  ← Alice has stolen the NFT from Bob
```

The corrupted value is `TombStone.original_owner` at `nft_addr`: it records `@alice` even after `ObjectCore.owner` has been updated to `@bob` and then to `BURN_ADDRESS`. The `unburn` BURN_ADDRESS branch reads this stale field and unconditionally transfers the object back to Alice, bypassing Bob's legitimate ownership. [5](#0-4) [1](#0-0) [2](#0-1) [6](#0-5)

    public entry fun unburn<T: key>(
        original_owner: &signer,
        object: Object<T>,
    ) {
        let object_addr = object.inner;
        assert!(exists<TombStone>(object_addr), error::invalid_argument(EOBJECT_NOT_BURNT));

        // The new owner of the object can always unburn it, but if it's the burn address, we go to the old functionality
        let object_core = borrow_global<ObjectCore>(object_addr);
        if (object_core.owner == signer::address_of(original_owner)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(object_addr);
        } else if (object_core.owner == BURN_ADDRESS) {
            // The old functionality
            let TombStone { original_owner: original_owner_addr } = move_from<TombStone>(object_addr);
            assert!(
                original_owner_addr == signer::address_of(original_owner),
                error::permission_denied(ENOT_OBJECT_OWNER)
            );
            transfer_raw_inner(object_addr, original_owner_addr);
        } else {
            abort error::permission_denied(ENOT_OBJECT_OWNER);
        };
    }
