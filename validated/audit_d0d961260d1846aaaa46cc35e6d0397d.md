### Title
Credential Disclosure via Unsanitized Git Error Logs in `FindRemoteRootRef` RPC - ([File: internal/cli/gitaly/serve.go])

### Summary
The `FindRemoteRootRef` RPC accepts a caller-supplied `remote_url` that may embed HTTP basic-auth credentials (e.g. `https://user:pass@host/repo.git`). Gitaly injects this URL into a `git remote show` invocation via config, and if the invocation fails or produces stderr, the raw stderr text (which Git often includes the URL, credentials and all) is written to Gitaly's logs. Gitaly does have a `URLSanitizerHook` designed to redact such credentials from logs, but it only activates for an explicit whitelist of gRPC method names, and `FindRemoteRootRef` is not on that list.

### Finding Description
`FindRemoteRootRef` builds the remote URL directly from the request and passes it into the repository's git invocation: [1](#0-0) 

Every git subprocess spawned by Gitaly is logged through `internal/command`, and any stderr output the subprocess produces is logged as the log message via `entry.WarnContext`/`entry.ErrorContext`: [2](#0-1) 

Gitaly's log pipeline includes a `URLSanitizerHook` whose `Fire` method only redacts credentials embedded in URLs when the current gRPC method is in an explicit allow-list (`possibleGrpcMethods`): [3](#0-2) 

That allow-list is populated once, at server startup, in `configure()`, and only contains three methods: `CreateRepositoryFromURL`, `FetchRemote`, and `UpdateRemoteMirror`. `FindRemoteRootRef` — which also accepts a raw, potentially credential-bearing URL from the caller — is not registered: [4](#0-3) 

The existing test suite for the sanitizer confirms the exact bug class this protects against — git stderr messages such as `fatal: Authentication failed for 'https://foo_the_user:hUntEr1@gitlab.com/foo/bar'` being redacted to `[FILTERED]` — but only for registered methods: [5](#0-4) 

Because `FindRemoteRootRef` is absent from the registered method list, any git error text produced while contacting a caller-supplied remote (e.g. authentication failures, "repository not found", DNS/connection errors that echo the URL) is written to Gitaly's server logs with the embedded credentials intact.

### Impact Explanation
An ordinary API caller who invokes `FindRemoteRootRef` with a `remote_url` containing embedded basic-auth credentials (a legitimate use case, e.g. verifying the default branch of a private third-party/fork source before import) will have those credentials appear verbatim in Gitaly's server-side logs whenever the underlying git command errors and writes the URL to stderr. Anyone with access to Gitaly's logs (log aggregation systems, container/host log storage, log shipping backends) can recover those third-party credentials, matching the credential-disclosure impact described in the referenced report, just via a different, unprotected RPC path.

### Likelihood Explanation
Reaching this path requires nothing more than calling the `FindRemoteRootRef` RPC with a URL that embeds credentials and points at a remote that will produce an error (e.g., wrong credentials, unreachable host, private repo without proper access) — all conditions fully controllable by the calling client. No privileged access, MITM, or dependency compromise is needed; it is triggered directly through a normal RPC field.

### Recommendation
Register `FindRemoteRootRef` with the `URLSanitizerHook` in `internal/cli/gitaly/serve.go` (`urlSanitizer.AddPossibleGrpcMethod(...)`), alongside `CreateRepositoryFromURL`, `FetchRemote`, and `UpdateRemoteMirror`. More robustly, audit all RPCs that accept a raw remote URL and default the sanitizer to apply broadly (e.g., sanitize any logged string/error by pattern regardless of method) rather than relying on a hand-maintained allow-list, since new URL-accepting RPCs can silently bypass protection.

### Proof of Concept
1. Call `FindRemoteRootRef` with `repository` set to an existing repo and `remote_url` = `https://validuser:secretpassword@example.com/nonexistent/repo.git`.
2. The `git remote show inmemory` subprocess fails to reach/authenticate against the fake remote and git writes an error to stderr containing the full URL (e.g. `fatal: unable to access 'https://validuser:secretpassword@example.com/...'`).
3. `logProcessComplete` logs this stderr text via `entry.WarnContext`/`ErrorContext` [6](#0-5) .
4. Because the `grpc.method` field is `FindRemoteRootRef`, which is absent from `possibleGrpcMethods`, `URLSanitizerHook.Fire` returns immediately without redaction [7](#0-6) , and the credentials `validuser:secretpassword` are written in plaintext to Gitaly's log output.

func (s *server) findRemoteRootRefCmd(ctx context.Context, request *gitalypb.FindRemoteRootRefRequest) (*command.Command, error) {
	remoteURL := request.GetRemoteUrl()
	var config []gitcmd.ConfigPair

	if resolvedAddress := request.GetResolvedAddress(); resolvedAddress != "" {
		modifiedURL, resolveConfig, err := gitcmd.GetURLAndResolveConfig(remoteURL, resolvedAddress)
		if err != nil {
			return nil, structerr.NewInvalidArgument("couldn't get curloptResolve config: %w", err)
		}

		remoteURL = modifiedURL
		config = append(config, resolveConfig...)
	}

	config = append(config, gitcmd.ConfigPair{Key: "remote.inmemory.url", Value: remoteURL})

	if authHeader := request.GetHttpAuthorizationHeader(); authHeader != "" {
		config = append(config, gitcmd.ConfigPair{
			Key:   fmt.Sprintf("http.%s.extraHeader", request.GetRemoteUrl()),
			Value: "Authorization: " + authHeader,
		})
	}

	repo := s.localRepoFactory.Build(request.GetRepository())

	return repo.Exec(ctx,
		gitcmd.Command{
			Name:   "remote",
			Action: "show",
			Args:   []string{"inmemory"},
		},
		gitcmd.WithDisabledHooks(),
		gitcmd.WithConfigEnv(config...),
		gitcmd.WithSetupStdout(),
	)

// URLSanitizerHook stores which gRPC methods to perform sanitization for.
type URLSanitizerHook struct {
	// gRPC methods that are likely to have URLs to sanitize
	possibleGrpcMethods map[string]bool
}

// NewURLSanitizerHook returns a new logrus hook for sanitizing URLs.
func NewURLSanitizerHook() *URLSanitizerHook {
	return &URLSanitizerHook{possibleGrpcMethods: make(map[string]bool)}
}

// AddPossibleGrpcMethod adds method names that we should sanitize URLs from their logs.
func (hook *URLSanitizerHook) AddPossibleGrpcMethod(methods ...string) {
	for _, method := range methods {
		hook.possibleGrpcMethods[method] = true
	}
}

// Fire is called by logrus.
func (hook *URLSanitizerHook) Fire(entry *logrus.Entry) error {
	mth, ok := entry.Data["grpc.method"]
	if !ok {
		return nil
	}

	mthStr, ok := mth.(string)
	if !ok || !hook.possibleGrpcMethods[mthStr] {
		return nil
	}

	if _, ok := entry.Data["args"]; ok {
		sanitizeSpawnLog(entry)
	} else if _, ok := entry.Data["error"]; ok {
		sanitizeErrorLog(entry)
	} else {
		entry.Message = sanitizeString(entry.Message)
	}

	return nil
}
