### Title
Unauthenticated `/shutdown` endpoint permanently halts signer event ingestion - ([File: libsigner/src/events.rs])

### Summary
`SignerEventReceiver::next_event` in `libsigner/src/events.rs` handles `POST /shutdown` by unconditionally setting `stop_signal` to `true` and returning `EventError::Terminated`, with no authentication, secret, or signature check on the sender. Any TCP client able to reach the bound event-receiver address can send this single unauthenticated request to permanently stop the signer's event loop.

### Finding Description
In `next_event` (`libsigner/src/events.rs` L437-448), the URL dispatch branch for `/shutdown` is:
```
} else if request.url() == "/shutdown" {
    event_receiver.stop_signal.store(true, Ordering::SeqCst);
    Err(EventError::Terminated)
}
``` [1](#0-0) 
There is no comparison against a secret, no signature verification, and no check on the request body or origin — unlike the legitimate `SignerStopSignaler::send()` caller, which happens to be the only intended sender but is not cryptographically distinguished from any other TCP client that can reach the port [2](#0-1) . `main_loop` (`libsigner/src/events.rs` L284-312) checks `is_stopped()` at the top of every iteration and also treats `Err(EventError::Terminated)` from `next_event()` as a signal to `break`, exiting the loop permanently [3](#0-2) . I confirmed via a repo-wide search that `libsigner/src/events.rs` contains no `Authorization`, `auth_token`, `secret`, or similar header check anywhere in the HTTP handling code, so this endpoint's admission is a straight URL-string match, equal for any sender.

### Impact Explanation
Any client able to open a TCP connection to the event-receiver's bound address and issue `POST /shutdown HTTP/1.1` with any body causes the signer's event-ingestion thread to terminate for good. Once `main_loop` breaks, the process no longer receives StackerDB chunk events, block-validation responses, or burn-block events from the node, effectively taking the signer offline until manually restarted. This is a single-message, repeatable DoS against the signer component, matching the "remote crash/unauthenticated DoS from few messages" Critical category to the extent the socket is reachable.

### Likelihood Explanation
Exploitability depends entirely on network reachability of the event-receiver bind address. In default node/signer configurations this endpoint is typically configured for local/loopback communication between the node and its co-located signer process, which would require local access (out of scope per the rules, which reject local/physical-access assumptions). If an operator binds the event-receiver to a non-loopback interface (a misconfiguration explicitly acknowledged in the question), then any unprivileged remote party can trivially trigger this with a single crafted HTTP POST, at negligible cost, and repeat it at will. No signer/peer/tip state is required — only network reachability to the port.

### Recommendation
Add authentication to the `/shutdown` endpoint (and ideally to all POST endpoints in `SignerEventReceiver`), e.g., a shared secret or token verified via a header/body field known only to the local node process, or restrict acceptance of `/shutdown` requests to loopback-originated connections regardless of configured bind address. At minimum, document and enforce that the event-receiver bind address must never be exposed on a non-loopback interface, and consider requiring a random per-run token exchanged out-of-band between the node and its signer instead of an unauthenticated URL match.

### Proof of Concept
```rust
// In libsigner/src/tests/mod.rs style, analogous to test_status_endpoint
#[test]
fn test_unauthenticated_shutdown() {
    let ev = SignerEventReceiver::<SignerMessage>::new(false);
    let (res_send, _res_recv) = channel();
    let mut signer = Signer::new(SimpleRunLoop::new(5), ev, res_send);
    let endpoint: SocketAddr = "127.0.0.1:32000".parse().unwrap();
    let running_signer = signer.spawn(endpoint).unwrap();

    // Attacker-controlled socket, no secret/auth provided
    let mut sock = TcpStream::connect(endpoint).unwrap();
    let body = "attacker payload";
    let req = format!(
        "POST /shutdown HTTP/1.1\r\nHost: {endpoint}\r\nConnection: close\r\nContent-Length: {}\r\n\r\n{}",
        body.len(), body
    );
    sock.write_all(req.as_bytes()).unwrap();
    sock.flush().unwrap();

    // main_loop should observe Err(EventError::Terminated) and break with no auth check
    let _ = running_signer.join(); // event thread exits; signer effectively dead
}
```
