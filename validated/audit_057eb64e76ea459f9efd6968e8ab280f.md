## Analog Vulnerability Analysis

### Title
Server-Side Request Forgery via unrestricted HTTP fetch in `CreateRepositoryFromSnapshot` - (File: `internal/gitaly/service/repository/create_repository_from_snapshot.go`)

### Summary
The external Redpanda report's root issue is that a backend service accepts and blindly trusts network-reachable input without restricting which hosts/services it may talk to, exposing internal infrastructure to attacker-directed requests. The closest concrete analog in Gitaly is the `CreateRepositoryFromSnapshot` RPC, which takes an attacker/caller-supplied `HttpUrl` field and performs an unauthenticated-scope HTTP `GET` against it from the Gitaly host itself, with no allowlist or private-network restriction unless the optional `ResolvedAddress` pinning is supplied by the same untrusted caller.

### Finding Description
`CreateRepositoryFromSnapshot` accepts a `CreateRepositoryFromSnapshotRequest` containing `HttpUrl`, `HttpAuth`, and an optional `ResolvedAddress`. The handler's `untar` function issues `client.Do(req)` directly against the caller-provided URL: [1](#0-0) 

If the caller does not supply `ResolvedAddress`, the plain `httpClient` (which merely follows `http.ProxyFromEnvironment` and disables redirects) is used with zero restriction on destination host — meaning the Gitaly process, which may run inside a private network segment with access to internal services (metadata endpoints, admin APIs, other internal broker/queue services analogous to Redpanda), can be forced to issue arbitrary outbound HTTP requests: [2](#0-1) 

The `ResolvedAddress`/`http.curloptResolve` mechanism used elsewhere (e.g. `FindRemoteRootRef`) exists specifically to mitigate DNS-rebinding but is opt-in and does not enforce that the resolved address is non-private; it only validates that it parses as an IP: [3](#0-2) 

The code even documents its own trust assumption without enforcing it: "the received archive is trusted *a lot* ... Before pointing this RPC at endpoints not under our control, it should undergo a lot of hardening," yet no hardening (host allowlisting, blocking RFC1918/loopback/link-local ranges, egress restriction) is implemented in the handler: [4](#0-3) 

The response body is piped directly into `tar -C path -xvf -` without validating that the response is actually a snapshot archive, compounding the risk of extraction of attacker-controlled/internal-service content into the newly created repository directory: [5](#0-4) 

This mirrors the Redpanda finding's underlying bug class: a service is architected such that it will reach out to (or expose itself to) arbitrary network endpoints supplied by another party, without ACL-style restriction to only the necessary/expected internal or external hosts.

### Impact Explanation
An attacker who can influence the `HttpUrl` value in a `CreateRepositoryFromSnapshotRequest` (e.g. via a repository import/fork/snapshot-bootstrap flow that surfaces this field, or a compromised/lower-trust component that proxies this RPC) can force Gitaly to make server-side HTTP requests to arbitrary hosts and ports reachable from the Gitaly network, including internal-only services, cloud metadata endpoints, or loopback-bound admin interfaces. Combined with the `HttpAuth` header being attacker-supplied and forwarded, and the response being unpacked with `tar`, this can lead to internal network reconnaissance/SSRF, potential credential/metadata disclosure, and extraction of attacker-influenced archive content into a live repository path.

### Likelihood Explanation
The RPC is a first-class gRPC endpoint (`RepositoryService.CreateRepositoryFromSnapshot`) reachable by any client authorized to call Gitaly's `RepositoryService` (e.g. Praefect-proxied cluster bootstrap/replication flows). Because `ResolvedAddress` is optional and not validated against private ranges even when present, no additional privilege beyond issuing this RPC is required to reach the vulnerable code path — matching the "ordinary...crafted RPC field" reachability bar.

### Recommendation
- **Short term**: Restrict the HTTP client used in `untar` to disallow requests to private/loopback/link-local address ranges (RFC1918, ::1, 169.254.0.0/16, etc.) unless explicitly configured as trusted; validate `ResolvedAddress` against the same denylist even when caller-supplied.
- **Long term**: Require this RPC to be restricted to trusted, allowlisted snapshot endpoints only (e.g. configured per-deployment sources), and avoid piping arbitrary remote HTTP responses directly into `tar` without content validation.

### Proof of Concept
1. Issue `CreateRepositoryFromSnapshot` with `HttpUrl` pointing to an internal-only address (e.g. `http://169.254.169.254/latest/meta-data/` or an internal admin service reachable from the Gitaly host) and no `ResolvedAddress`.
2. Gitaly's `untar` performs `client.Do(req)` against that internal URL with `HttpAuth` header if provided, and pipes the response body into `tar -xvf -`, demonstrating outbound SSRF and potential disclosure/extraction of internal service data. [6](#0-5)

```go
func (s *server) untar(ctx context.Context, path string, in *gitalypb.CreateRepositoryFromSnapshotRequest) error {
	req, err := http.NewRequestWithContext(ctx, "GET", in.GetHttpUrl(), nil)
	if err != nil {
		return structerr.NewInvalidArgument("Bad HTTP URL: %w", err)
	}

	client := httpClient
	if resolvedAddress := in.GetResolvedAddress(); resolvedAddress != "" {
		client, err = newResolvedHTTPClient(in.GetHttpUrl(), resolvedAddress)
		if err != nil {
			return structerr.NewInvalidArgument("creating resolved HTTP client: %w", err)
		}
	}

	if in.GetHttpAuth() != "" {
		req.Header.Set("Authorization", in.GetHttpAuth())
	}

	rsp, err := client.Do(req)
	if err != nil {
		return structerr.NewInternal("HTTP request failed: %w", err)
	}
	defer rsp.Body.Close()

	if rsp.StatusCode < http.StatusOK || rsp.StatusCode >= http.StatusMultipleChoices {
		return structerr.NewInternal("HTTP server: %s", rsp.Status)
	}

	cmd, err := command.New(ctx, s.logger, []string{"tar", "-C", path, "-xvf", "-"}, command.WithStdin(rsp.Body))
	if err != nil {
		return err
	}

	return cmd.Wait()
```

```go
func (s *server) CreateRepositoryFromSnapshot(ctx context.Context, in *gitalypb.CreateRepositoryFromSnapshotRequest) (*gitalypb.CreateRepositoryFromSnapshotResponse, error) {
	repository := in.GetRepository()
	if err := s.locator.ValidateRepository(ctx, repository, storage.WithSkipRepositoryExistenceCheck()); err != nil {
		return nil, structerr.NewInvalidArgument("%w", err)
	}

	if err := repoutil.Create(ctx, s.logger, s.locator, s.gitCmdFactory, s.catfileCache, s.txManager, s.repositoryCounter, repository, func(repo *gitalypb.Repository) error {
		path, err := s.locator.GetRepoPath(ctx, repo, storage.WithRepositoryVerificationSkipped())
		if err != nil {
			return structerr.NewInternal("getting repo path: %w", err)
		}

		// The archive contains a partial git repository, missing a config file and
		// other important items. Initializing a new bare one and extracting the
		// archive on top of it ensures the created git repository has everything
		// it needs (especially, the config file and hooks directory).
		//
		// NOTE: The received archive is trusted *a lot*. Before pointing this RPC
		// at endpoints not under our control, it should undergo a lot of hardening.
		if err := s.untar(ctx, path, in); err != nil {
			return structerr.NewInternal("extracting snapshot: %w", err)
		}

		return nil
	}); err != nil {
		return nil, structerr.NewInternal("creating repository: %w", err)
	}
```
