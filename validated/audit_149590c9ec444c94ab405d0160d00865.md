### Title
Unrestricted archive extraction in `CreateRepositoryFromSnapshot` allows tar-based path traversal / storage escape - ([File: internal/gitaly/service/repository/create_repository_from_snapshot.go])

### Summary
`RepositoryService.CreateRepositoryFromSnapshot` downloads an attacker/caller-controlled HTTP resource and pipes its body directly into `tar -C <repoPath> -xvf -` with no validation of the archive's member paths, similar in spirit to the referenced finding's theme of a critical operation lacking a necessary guard (there, an access-control guard; here, a content/path-validation guard on an operation that writes into the filesystem under Gitaly's control).

### Finding Description
The RPC handler `CreateRepositoryFromSnapshot` validates only the *target* repository path via `s.locator.ValidateRepository` [1](#0-0) , then calls `s.untar`, which fetches the archive from `in.GetHttpUrl()` and streams the HTTP response body straight into `tar -C path -xvf -` [2](#0-1) . There is no inspection of the tar member names before or during extraction — no rejection of entries containing `..`, absolute paths, or symlinks that point outside `path`. The code even documents this as an explicit trust gap:

> "NOTE: The received archive is trusted *a lot*. Before pointing this RPC at endpoints not under our control, it should undergo a lot of hardening." [3](#0-2) 

This differs from other Gitaly code paths that carefully constrain paths within a storage root, e.g. `ObjectDirectoryPath` uses `storage.ValidateRelativePath` and explicit prefix checks before trusting a path derived from RPC input [4](#0-3) . `CreateRepositoryFromSnapshot` has no analogous validation for archive contents, so if the HTTP source (identified by the caller-supplied `HttpUrl`/`ResolvedAddress`/`HttpAuth` fields) returns a crafted tar containing `../../../` paths or symlinked entries, GNU `tar` extraction can write or overwrite files outside the newly created repository directory, anywhere the Gitaly process has filesystem permission to write, including other repositories' storage on the same node.

### Impact Explanation
An attacker who can influence the tar content served at the `http_url` passed to this RPC (e.g., because they control an internal or attacker-reachable HTTP endpoint that Gitaly is pointed at, or via a compromised/misconfigured migration source) can escape the intended repository directory and write arbitrary files to the storage filesystem — potentially corrupting or overwriting other repositories' objects/hooks/config, or planting files elsewhere on disk that Gitaly can read (e.g., custom hook scripts in other repos), leading to cross-repository object/data corruption or code execution via injected hooks. This matches the "archive/bundle extraction escape" and "remote URL handling" categories called out as in-scope.

### Likelihood Explanation
The RPC is a first-class, non-deprecated `RepositoryService` mutator RPC reachable through the standard gRPC surface (confirmed via `_RepositoryService_...` generated handlers and `proto/repository.proto` definitions) [5](#0-4) . Its precondition is only that the caller can invoke the RPC with a chosen `HttpUrl`/`HttpAuth`/`ResolvedAddress` — there is no restriction that the URL must point to a trusted, Gitaly-generated snapshot, and the extraction path itself performs no content sanitization. The in-code comment confirms the maintainers are aware this RPC is unsafe against untrusted archive sources, which raises the likelihood that this remains an exploitable gap in deployments where the HTTP endpoint is not fully trusted or is reachable by lower-privileged callers (e.g. multi-tenant setups, SSRF-adjacent scenarios via `ResolvedAddress`).

### Recommendation
- Enumerate tar entries (via something like the existing `internal/archive` tar-entry helpers referenced in tests) before/while extracting, and reject any entry whose resolved path is not strictly contained within the destination repository path (reject `..`, absolute paths, and symlink/hardlink entries pointing outside the target directory), mirroring the `storage.ValidateRelativePath` pattern used elsewhere in the codebase.
- Extract with hardened tar options (e.g., disallow absolute paths, disable following of `..`, and forbid device/symlink entries) or perform extraction in Go using a controlled tar reader instead of shelling out to `tar`, validating each header's `Name` against the target directory before writing.
- Restrict/document that `HttpUrl` must resolve to explicitly trusted, operator-approved sources (and enforce this at the RPC boundary), since the current code merely warns about the risk without enforcing it.

### Proof of Concept
1. Stand up an HTTP server serving a tar archive containing an entry named `../../victim-repo/hooks/pre-receive` with executable attacker script content (or `../../../etc/some-writable-path`).
2. Call `CreateRepositoryFromSnapshot` with `HttpUrl` pointing at that server, `Repository` set to any new repository path within a storage.
3. Observe that `tar -C <path> -xvf -` extracts the entry following the `../` traversal in the header, writing the file outside the newly created repository directory (e.g., overwriting `hooks/pre-receive` in an existing repository if paths align), since the handler applies no path containment check before invoking `tar` [6](#0-5) .

func (s *server) untar(ctx context.Context, path string, in *gitalypb.CreateRepositoryFromSnapshotRequest) error {
	req, err := http.NewRequestWithContext(ctx, "GET", in.GetHttpUrl(), nil)
	if err != nil {
		return structerr.NewInvalidArgument("Bad HTTP URL: %w", err)
	}

	client := httpClient
	if resolvedAddress := in.GetResolvedAddress(); resolvedAddress != "" {
		client, err = newResolvedHTTPClient(in.GetHttpUrl(), resolvedAddress)
		if err != nil {
			return structerr.NewInvalidArgument("creating resolved HTTP client: %w", err)
		}
	}

	if in.GetHttpAuth() != "" {
		req.Header.Set("Authorization", in.GetHttpAuth())
	}

	rsp, err := client.Do(req)
	if err != nil {
		return structerr.NewInternal("HTTP request failed: %w", err)
	}
	defer rsp.Body.Close()

	if rsp.StatusCode < http.StatusOK || rsp.StatusCode >= http.StatusMultipleChoices {
		return structerr.NewInternal("HTTP server: %s", rsp.Status)
	}

	cmd, err := command.New(ctx, s.logger, []string{"tar", "-C", path, "-xvf", "-"}, command.WithStdin(rsp.Body))
	if err != nil {
		return err
	}

	return cmd.Wait()
}
