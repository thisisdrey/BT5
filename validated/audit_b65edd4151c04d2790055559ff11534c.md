### Title
StackerDB chunk signature omits contract identity, enabling cross-contract signed-chunk replay - (File: `libstackerdb/src/libstackerdb.rs`)

### Summary
`SlotMetadata::auth_digest()` computes the signed digest from only `slot_id`, `slot_version`, and `data_hash` [1](#0-0) . It omits the StackerDB's smart-contract identity (`contract_id`) and any reward-cycle/consensus-context binding (`rc_consensus_hash`). Authorization to write a slot is decided purely by looking up which `StacksAddress` owns `slot_id` in the *target* contract's config via `get_slot_signer(smart_contract_id, slot_id)` and checking that this address recovers from the signature [2](#0-1) . Because the signed digest itself never commits to which contract (or which epoch) the chunk was intended for, a validly-signed `StackerDBChunkData` message observed on the network (StackerDB traffic is broadcast in the clear, e.g. via `StackerDBPushChunk`/`StackerDBChunk`) can be replayed verbatim into any other StackerDB instance where the same signer address happens to be assigned the same `slot_id`, as long as the replayed `slot_version` satisfies the local staleness/`max_writes` checks.

### Finding Description
`StackerDBChunkData::sign`/`verify` delegate to `SlotMetadata::sign`/`verify`, which hash and sign only `(slot_id, slot_version, data_hash)` [3](#0-2) . The struct itself carries no `contract_id` field [4](#0-3) , and `contract_id` is only supplied out-of-band by the surrounding message (`StackerDBGetChunkData`, `StackerDBPushChunkData`) or HTTP path (`/v2/stackerdb/{contract}/{slot}/chunks`), never mixed into the digest that is actually signed. `validate_received_chunk`, which is used both for pull-based sync (`validate_downloaded_chunk`) and for unsolicited pushes (`handle_unsolicited_StackerDBPushChunk`), resolves the authorized signer strictly from the *target* `smart_contract_id`'s configuration and then checks the signature against that address — it does not verify that the signature was produced with that specific contract (or epoch) in mind [5](#0-4) . This is exactly the "id/commitment omits critical binding data" pattern from the reference report: there, the diamond-cut proposal hash skipped `_init`/`_calldata`; here, the chunk's authentication digest skips the contract/context binding, so the same signed bytes are valid proof-of-authorship for more than the one context the signer intended.

### Impact Explanation
If the same signer address is configured as the owner of the same `slot_id` in two different StackerDB smart contracts (a realistic situation for Nakamoto signer-set contracts across consecutive reward cycles, e.g. `signers-N-0` / `signers-(N+1)-0`, where slot assignment by index often persists across cycles for the same signer), an unprivileged network observer can capture a legitimately signed chunk from one context and re-inject it (via the same unauthenticated HTTP POST endpoint or via P2P `StackerDBPushChunk`) into the other context. Because `try_replace_chunk`/`validate_received_chunk` only check `slot_id`, `slot_version` bounds, and the recovered signer address — never the contract the signature was meant for — the replayed chunk is accepted as an authentic, current write, letting stale or out-of-context signer data be served as canonical current state for that StackerDB. This matches "unauthenticated/unauthorized write to state" and "serving non-canonical state as canonical" impact classes without requiring any private key or admin role.

### Likelihood Explanation
Requires only: (1) observing StackerDB traffic, which is unauthenticated and broadcast/servable to any peer or RPC client, and (2) a signer address being assigned the same `slot_id` in more than one StackerDB contract instance (plausible across reward-cycle rollovers with stable signer ordering). No cryptographic secret or privileged role is needed by the attacker — only replay of previously-seen valid bytes.

### Recommendation
Include the target `contract_id` (and ideally an epoch/consensus-hash binding such as `rc_consensus_hash`) inside `SlotMetadata::auth_digest()` so a chunk signature cryptographically commits to exactly which StackerDB instance and context it authorizes, mirroring the recommended fix of adding the omitted fields (`_init`/`_calldata`) into the hashed commitment in the referenced report.

### Proof of Concept
1. Configure two StackerDB contracts, `contract_a` and `contract_b`, both assigning `slot_id = 0` to address `A` (owned by key `pk`).
2. Signer with `pk` signs and pushes `StackerDBChunkData { slot_id: 0, slot_version: 5, data, sig }` to `contract_a`; this traffic is visible on the wire (e.g., via `StackerDBPushChunk`).
3. An attacker without `pk` copies the identical `StackerDBChunkData` bytes and POSTs/pushes them against `contract_b`'s StackerDB (same `slot_id`, same or higher `slot_version` relative to `contract_b`'s current state).
4. `validate_received_chunk` resolves `get_slot_signer(contract_b, 0) == A`, recovers `A` from `sig` via `SlotMetadata::verify`, and — since the digest never encoded `contract_a` vs `contract_b` — accepts the chunk as an authentic write to `contract_b`, even though the signer never signed anything for `contract_b`.     /// Get the digest to sign that authenticates this chunk data and metadata
    fn auth_digest(&self) -> Sha512Trunc256Sum {
        let mut hasher = Sha512_256::new();
        hasher.update(self.slot_id.to_be_bytes());
        hasher.update(self.slot_version.to_be_bytes());
        hasher.update(self.data_hash.0);
        Sha512Trunc256Sum::from_hasher(hasher)
    }

    /// Sign this slot metadata, committing to slot_id, slot_version, and
    /// data_hash.  Sets self.signature to the signature.
    /// Fails if the underlying crypto library fails
    pub fn sign(&mut self, privkey: &StacksPrivateKey) -> Result<(), Error> {
        let auth_digest = self.auth_digest();
        let sig = privkey
            .sign(&auth_digest.0)
            .map_err(|se| Error::SigningError(se.to_string()))?;

        self.signature = sig;
        Ok(())
    }

    /// Verify that a given principal signed this chunk metadata.
    /// Note that the address version is ignored.
    pub fn verify(&self, principal: &StacksAddress) -> Result<bool, Error> {
        let sigh = self.auth_digest();
        let pubk = StacksPublicKey::recover_to_pubkey_without_validating_low_s(
            sigh.as_bytes(),
            &self.signature,
        )
        .map_err(|ve| Error::VerifyingError(ve.to_string()))?;

        let pubkh = Hash160::from_node_public_key(&pubk);
        Ok(pubkh == *principal.bytes())
    }

        config: &StackerDBConfig,

    ) -> Result<bool, net_error> {
        // validate -- must not exceed this replica's configured chunk size.
        if (data.data.len() as u64) > config.chunk_size {
            info!(
                "Received StackerDBChunk for {} ID {}, which is oversized: {} bytes (max {} bytes)",
                smart_contract_id,
                data.slot_id,
                data.data.len(),
                config.chunk_size
            );
            return Ok(false);
        }

        // validate -- must be a valid chunk
        let Some(expected_version) = expected_versions.get(data.slot_id as usize) else {
            info!(

                smart_contract_id,
                data.slot_id,
                expected_versions.len()
            );
            return Ok(false);
        };

        // validate -- must be signed by the expected author
        let addr = match self
            .stackerdbs
            .get_slot_signer(smart_contract_id, data.slot_id)?
        {
            Some(addr) => addr,
            None => {
                return Ok(false);
            }
        };

        let slot_metadata = data.get_slot_metadata();
        if !slot_metadata.verify(&addr)? {
            info!(
                "StackerDBChunk for {} ID {} is not signed by {}",
                smart_contract_id, data.slot_id, &addr
            );
            return Ok(false);
        }

        if data.slot_version < *expected_version {

                "Received StackerDBChunk for {} ID {} version {}, which is stale (expected {})",
