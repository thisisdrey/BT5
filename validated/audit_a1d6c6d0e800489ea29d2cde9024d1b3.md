## Title
Stale `AcquiredDelegatedFrozenV2BalanceForBandwidth/Energy` on a re-created receiver account can be corrupted by a stale `UnDelegateResource` from before the account's self-destruction, causing unfair resource accounting - (File: `actuator/src/main/java/org/tron/core/actuator/UnDelegateResourceActuator.java`)

### Summary
This is the same bug class as the Salty `_arbitrageProfits` finding: state that is keyed by an identity (a pool ID / an account address) is not invalidated when that identity is "removed" (unwhitelisted / self-destructed), so it can be misapplied when the identity is re-established (re-whitelisted / re-created), producing an unfair/incorrect distribution of a shared accounting quantity.

### Finding Description
`DelegatedResourceStore` records `(owner, receiver)` delegation entries independently from the `receiverCapsule.getAcquiredDelegatedFrozenV2BalanceForBandwidth/Energy` counters stored on the receiver's `AccountCapsule`. When a receiver contract self-destructs (TVM `SUICIDE`), its `AccountCapsule` — and therefore its `AcquiredDelegatedFrozenV2Balance*` counters — is deleted, but the `DelegatedResourceStore` entry that still logically owes that receiver a chunk of frozen balance is **not** cleared, as shown by the developers' own comment and handling in `UnDelegateResourceActuator.execute`: [1](#0-0) 

If a new account (EOA or a freshly deployed contract via `CREATE`/`CREATE2`) is later established at that same address and receives *new, legitimate* delegations from other owners, its `AcquiredDelegatedFrozenV2BalanceForBandwidth/Energy` starts accumulating from zero again. The code only guards against **under**flow (`if (... < unDelegateBalance) { setAcquiredDelegatedFrozenV2BalanceForBandwidth(0); }`), but it does not verify that the account object currently at `receiverAddress` is the same logical delegation target that the stale `DelegatedResourceStore` entry refers to. If the new account's genuinely-acquired balance happens to be **greater than or equal to** the stale `unDelegateBalance` recorded from before the self-destruct, the original delegator (who never actually contributed to the new account's resource pool) can call `UnDelegateResourceContract` and have `receiverCapsule.addAcquiredDelegatedFrozenV2BalanceForBandwidth(-unDelegateBalance)` silently deduct that amount from the *new* account's legitimately-acquired resource, exactly mirroring the Salty pattern where a stale accumulator tied to an old identity is spent against activity that belongs to the new occupant of that identity.

The test suite acknowledges the self-destruct/re-create edge case exists (`testUnDelegatedForBandwidthWithRecreatedReceiver`) but only exercises the branch where the new balance is deliberately smaller than the stale `unDelegateBalance`, which triggers the "reset to 0" guard rather than the unguarded subtraction path: [2](#0-1) 

### Impact Explanation
This corrupts bandwidth/energy resource accounting for accounts unrelated to the original delegation: a re-created account's `AcquiredDelegatedFrozenV2Balance*` can be decremented by a stale claim it never actually received, degrading the resource ceiling calculated by `BandwidthProcessor`/`EnergyProcessor` for that account and for the delegators who legitimately delegated to the re-created address. This is a stake/delegation accounting corruption issue reachable purely by an unprivileged sequence of transactions (deploy contract, delegate resource to it, self-destruct it, wait for a new account/contract at the same address, submit `UnDelegateResourceContract`), matching the "stake/delegation/reward math" and "actuator validate/execute" categories.

### Likelihood Explanation
Requires: (1) delegating BANDWIDTH/ENERGY to a contract, (2) that contract self-destructing, (3) a new account/contract being created at the exact same address (achievable deterministically via `CREATE2`) and receiving new delegations from other users whose total meets or exceeds the stale amount, and (4) the original delegator submitting `UnDelegateResourceContract` after all that. This is a multi-step but fully attacker-controllable sequence requiring no special privileges, similar in complexity to the original Salty PoC which also required a specific sequence of whitelist/unwhitelist/reward-settlement transactions.

### Recommendation
Either (a) delete/invalidate outstanding `DelegatedResourceStore` entries pointing at a receiver when that receiver account is destroyed (so `UnDelegateResource` against a stale entry becomes a no-op instead of mutating whatever account now occupies the address), or (b) bind the `AcquiredDelegatedFrozenV2Balance*` decrement to a resource epoch/nonce created at account-creation time so that `unDelegateBalance` values recorded against a since-destroyed account can never be applied to a different (re-created) account instance at the same address.

### Proof of Concept
Conceptual reproduction (analogous to the Salty PoC restructured for java-tron):
1. Deploy contract `C` at address `A`; owner `O` calls `DelegateResourceContract` to delegate `X` bandwidth to `A`. `A.AcquiredDelegatedFrozenV2BalanceForBandwidth == X`.
2. `C` self-destructs; `AccountStore.delete(A)` removes the `AccountCapsule`, but the `DelegatedResourceStore` entry for `(O, A)` with `frozenBalanceForBandwidth == X` remains, as confirmed by `testUnDelegatedForBandwidthWithDeletedReceiver`.
3. A new contract `C2` is deployed at the same address `A` (e.g., via `CREATE2`), and other users `O2..On` delegate bandwidth to it such that `A.AcquiredDelegatedFrozenV2BalanceForBandwidth >= X`.
4. `O` submits `UnDelegateResourceContract(owner=O, receiver=A, resource=BANDWIDTH, balance=X)`. Since `X <= A.AcquiredDelegatedFrozenV2BalanceForBandwidth`, the code takes the subtraction branch and executes `receiverCapsule.addAcquiredDelegatedFrozenV2BalanceForBandwidth(-X)` against `C2`'s account, even though `O` never delegated to `C2`.
5. Result: `C2`'s bandwidth ceiling and `O2..On`'s effectively-acquired resource accounting is reduced by `X`, an amount tied to the destroyed `C`, not to `C2`. [3](#0-2) [4](#0-3)

  @Test
  public void testUnDelegatedForBandwidthWithDeletedReceiver() {
    delegateBandwidthForOwner();
    long now = System.currentTimeMillis();
    dbManager.getDynamicPropertiesStore().saveLatestBlockHeaderTimestamp(now);

    byte[] owner = ByteArray.fromHexString(OWNER_ADDRESS);
    byte[] receiver = ByteArray.fromHexString(RECEIVER_ADDRESS);
    dbManager.getAccountStore().delete(receiver);

    UnDelegateResourceActuator actuator = new UnDelegateResourceActuator();
    actuator.setChainBaseManager(dbManager.getChainBaseManager()).setAny(
        getDelegatedContractForBandwidth(OWNER_ADDRESS, delegateBalance));
    TransactionResultCapsule ret = new TransactionResultCapsule();

    try {
      actuator.validate();
      actuator.execute(ret);
      Assert.assertEquals(code.SUCESS, ret.getInstance().getRet());

      // check owner
      AccountCapsule ownerCapsule = dbManager.getAccountStore().get(owner);
      Assert.assertEquals(0, ownerCapsule.getDelegatedFrozenV2BalanceForBandwidth());
      Assert.assertEquals(delegateBalance, ownerCapsule.getFrozenV2BalanceForBandwidth());
      Assert.assertEquals(delegateBalance, ownerCapsule.getTronPower());
      Assert.assertEquals(0, ownerCapsule.getNetUsage());

      // check receiver
      Assert.assertNull(dbManager.getAccountStore().get(receiver));

      //check DelegatedResource
      byte[] key = DelegatedResourceCapsule.createDbKeyV2(owner, receiver, false);
      DelegatedResourceCapsule delegatedResourceCapsule =
          dbManager.getDelegatedResourceStore().get(key);
      Assert.assertNull(delegatedResourceCapsule);

      //check DelegatedResourceAccountIndex
      DelegatedResourceAccountIndexCapsule ownerIndexCapsule = dbManager
          .getDelegatedResourceAccountIndexStore().getV2Index(owner);
      Assert.assertEquals(0, ownerIndexCapsule.getFromAccountsList().size());
      Assert.assertEquals(0, ownerIndexCapsule.getToAccountsList().size());

      DelegatedResourceAccountIndexCapsule receiverIndexCapsule = dbManager
          .getDelegatedResourceAccountIndexStore().getV2Index(receiver);
      Assert.assertEquals(0, receiverIndexCapsule.getToAccountsList().size());
      Assert.assertEquals(0, receiverIndexCapsule.getFromAccountsList().size());

    } catch (ContractValidateException | ContractExeException e) {
      Assert.fail(e.getMessage());
    }

  }
