## Analog Found

### Title
Missing `supportUnfreezeDelay` migration gate lets TVM contracts keep using the legacy freeze mechanism after it is disabled by governance - (File: actuator/src/main/java/org/tron/core/vm/nativecontract/FreezeBalanceProcessor.java)

### Summary
`FreezeBalanceActuator`, the transaction-level entry point for the legacy `FreezeBalanceContract`, explicitly refuses to run once the committee has switched the chain to the new resource model: [1](#0-0) 

This mirrors the reported bug class exactly: a lifecycle/state flag (`ProtectionPoolCycleState.Locked` in the original report ↔ `dynamicStore.supportUnfreezeDelay()` here) is meant to gate an action, and one code path enforces it while a parallel path that reaches the same underlying effect does not.

### Finding Description
`FreezeBalanceProcessor`, which backs the TVM-callable `freeze()` opcode/precompile that a deployed smart contract can invoke on behalf of its own account, implements the same "freeze TRX for BANDWIDTH/ENERGY" logic as `FreezeBalanceActuator`, but its `validate()` never checks `dynamicStore.supportUnfreezeDelay()`: [2](#0-1) 

It is invoked from `Program.freeze()`: [3](#0-2) 

Once the committee flips `supportUnfreezeDelay` (i.e., activates the FreezeBalanceV2 model), the protocol's intent — reflected in the actuator-level checks — is that the legacy freeze/unfreeze accounting (`FreezeBalanceContract`, non-V2 `FrozenBalance`/`DelegatedResourceCapsule`) is closed for good and only the V2 model (`FreezeBalanceV2Actuator`, `UnfreezeBalanceV2Actuator`, `WithdrawExpireUnfreezeActuator`, `DelegateResourceActuator`, `UnDelegateResourceActuator`) should be reachable, all of which explicitly check `supportUnfreezeDelay` in their validators. `FreezeBalanceProcessor` (the TVM-native counterpart) does not, so a deployed contract can still call the internal `freeze` operation and create legacy, non-V2 frozen balance / delegated-resource entries and add to `TotalNetWeight`/`TotalEnergyWeight` through the old accounting path indefinitely, even after governance has migrated the network away from that model.

### Impact Explanation
This breaks a protocol-wide migration invariant enforced everywhere else in the actuator layer. It results in permanently-diverging, inconsistent resource-accounting state: legacy frozen balances and legacy `DelegatedResourceCapsule` entries can keep being created via TVM after the network was supposed to have fully moved to the V2 model, mixing with V2-only successor logic (`UnDelegateResourceActuator`, `UnfreezeBalanceV2Actuator`) that assumes the legacy path is closed. This can leave resources locked in a data structure the rest of the (post-migration) validation/reward code no longer expects to grow, creating a chain-wide state inconsistency reachable by any account deploying and calling a contract — not just a resource-metering nuisance, since it directly manipulates account balance, frozen balance, delegated-resource records, and global `TotalNetWeight`/`TotalEnergyWeight` counters that back bandwidth/energy issuance and voting power across the whole network.

### Likelihood Explanation
High reachability: any address can deploy a trivial contract that calls the `freeze` internal function (exposed via `Program.freeze()`/the corresponding precompiled contract), with no special privilege required, once `supportUnfreezeDelay` has been turned on by the committee (which is the documented end-state of the FreezeV2 rollout).

### Recommendation
Add the same guard used in `FreezeBalanceActuator.validate()` to `FreezeBalanceProcessor.validate()`:
```java
if (repo.getDynamicPropertiesStore().supportUnfreezeDelay()) {
  throw new ContractValidateException("freeze v2 is open, old freeze is closed");
}
```
Audit all other `nativecontract` processors that mirror actuators governed by `supportUnfreezeDelay` (or similar committee-controlled feature flags) to ensure the TVM-callable native-contract path enforces every gate its transaction-level actuator counterpart enforces.

### Proof of Concept
1. Committee enables the new resource model: `dynamicStore.saveUnfreezeDelayDays(...)` making `supportUnfreezeDelay()` return `true`.
2. Any user deploys a contract that internally invokes the TVM `freeze` capability (as exercised in `FreezeTest.testFreezeAndUnfreeze`, which drives `Program.freeze()` end-to-end): [4](#0-3) 
3. `Program.freeze()` → `FreezeBalanceProcessor.validate()`/`execute()` succeed and create legacy frozen balance / weight entries, whereas a direct `FreezeBalanceContract` transaction through `FreezeBalanceActuator` would be rejected with "freeze v2 is open, old freeze is closed" at the same point in time.

**Note on confidence:** I was not able to fully trace whether `UnfreezeBalanceActuator` (the legacy, non-V2 unfreeze) is itself gated by `supportUnfreezeDelay`, since only its `execute()` body was inspected, not its full `validate()`. This does not change the core finding (the freeze-side gate is provably missing on the TVM path), but it is relevant to precisely characterizing whether funds frozen this way remain retrievable through the old unfreeze flow or become stuck; a full review of `UnfreezeBalanceActuator.validate()` is recommended to complete the impact assessment.

  public void validate(FreezeBalanceParam param, Repository repo) throws ContractValidateException {
    if (repo == null) {
      throw new ContractValidateException(STORE_NOT_EXIST);
    }

    // validate arg @frozenBalance
    byte[] ownerAddress = param.getOwnerAddress();
    AccountCapsule ownerCapsule = repo.getAccount(ownerAddress);
    long frozenBalance = param.getFrozenBalance();
    if (frozenBalance <= 0) {
      throw new ContractValidateException("FrozenBalance must be positive");
    } else if (frozenBalance < TRX_PRECISION) {
      throw new ContractValidateException("FrozenBalance must be greater than or equal to 1 TRX");
    } else if (frozenBalance > ownerCapsule.getBalance()) {
      throw new ContractValidateException("FrozenBalance must be less than or equal to accountBalance");
    }

    // validate frozen count of owner account
    int frozenCount = ownerCapsule.getFrozenCount();
    if (frozenCount != 0 && frozenCount != 1) {
      throw new ContractValidateException("FrozenCount must be 0 or 1");
    }

    // validate arg @resourceType
    switch (param.getResourceType()) {
      case BANDWIDTH:
      case ENERGY:
        break;
      default:
        throw new ContractValidateException(
            "Unknown ResourceCode, valid ResourceCode[BANDWIDTH、ENERGY]");
    }

    // validate for delegating resource
    byte[] receiverAddress = param.getReceiverAddress();
    if (!FastByteComparisons.isEqual(ownerAddress, receiverAddress)) {
      param.setDelegating(true);

      // check if receiver account exists. if not, then create a new account
      AccountCapsule receiverCapsule = repo.getAccount(receiverAddress);
      if (receiverCapsule == null) {
        receiverCapsule = repo.createNormalAccount(receiverAddress);
      }

      // forbid delegating resource to contract account
      if (receiverCapsule.getType() == Protocol.AccountType.Contract) {
        throw new ContractValidateException(
            "Do not allow delegate resources to contract addresses");
      }
    }
  }

  public boolean freeze(DataWord receiverAddress, DataWord frozenBalance, DataWord resourceType) {
    Repository repository = getContractState().newRepositoryChild();
    byte[] owner = getContextAddress();
    byte[] receiver = receiverAddress.toTronAddress();

    increaseNonce();
    InternalTransaction internalTx = addInternalTx(null, owner, receiver,
        frozenBalance.longValue(), null,
        "freezeFor" + convertResourceToString(resourceType), nonce, null);

    FreezeBalanceParam param = new FreezeBalanceParam();
    param.setOwnerAddress(owner);
    param.setReceiverAddress(receiver);
    boolean needCheckFrozenTime = CommonParameter.getInstance()
        .getCheckFrozenTime() == 1; // for test
    param.setFrozenDuration(needCheckFrozenTime
        ? repository.getDynamicPropertiesStore().getMinFrozenTime() : 0);
    param.setResourceType(parseResourceCode(resourceType));
    try {
      FreezeBalanceProcessor processor = new FreezeBalanceProcessor();
      param.setFrozenBalance(frozenBalance.sValue().longValueExact());
      processor.validate(param, repository);
      processor.execute(param, repository);
      repository.commit();
      return true;
    } catch (ContractValidateException e) {
      logger.warn("TVM Freeze: validate failure. Reason: {}", e.getMessage());
    } catch (ArithmeticException e) {
      logger.warn("TVM Freeze: frozenBalance out of long range.");
    }
    if (internalTx != null) {
      internalTx.reject();
    }
    return false;
  }
