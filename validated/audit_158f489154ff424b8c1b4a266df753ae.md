### Title
Unbounded CPU/time consumption in `GetFileAttributes` via attacker-controlled `.gitattributes` complexity and path count - (File: internal/gitaly/service/repository/file_attributes.go)

### Summary
`GetFileAttributes` invokes `gitattributes.CheckAttrCmd.Check` once per entry in the attacker-supplied `Paths` field, and each invocation causes `git check-attr --stdin -z` to evaluate every pattern rule in the repository's `.gitattributes` files for that path. Neither the number of paths nor the complexity of `.gitattributes` content is bounded, so a repository owner can craft a request that ties up a worker for a long time.

### Finding Description
`validateGetFileAttributesRequest` only checks that `Repository`, `Revision`, `Paths`, and `Attributes` are non-empty; it does not cap `len(in.GetPaths())` or `len(in.GetAttributes())`. [1](#0-0) 

The handler then loops over every path synchronously, calling `checkAttrCmd.Check(path)` for each one: [2](#0-1) 

`CheckAttrCmd.Check` writes the path to the long-lived `git check-attr --stdin -z` process and blocks reading `c.count` (`len(names)`) NUL-delimited words from stdout before returning: [3](#0-2) 

Because `git check-attr` must scan the effective `.gitattributes` rule set for every queried path, an attacker who controls the repository content (push access to their own repo) can commit a `.gitattributes` file with a very large number of pattern rules (e.g. tens of thousands of `**` globs) and then call `GetFileAttributes` with a large `Paths` list and `Attributes` list. The per-request cost scales with `O(paths × attribute_names × gitattributes_rules)`, entirely attacker-controlled, and there is no timeout, size cap, or streaming/backpressure mechanism inside the handler itself.

The only mitigation present in the codebase is the optional, operator-configured `[[concurrency]]` per-RPC/per-repository concurrency limiter (`limithandler`), which is disabled by default and, even when enabled, only limits how many concurrent calls run for a given lock key — it does not bound the CPU/wall time consumed by a single already-admitted call. [4](#0-3) [5](#0-4) 

### Impact Explanation
A single unary `GetFileAttributes` call can pin a `git check-attr` subprocess and the handling goroutine for an extended duration, consuming CPU and holding a concurrency slot (if any is configured) or an unbounded worker thread (if not). Repeated or parallel requests of this kind from the same attacker-owned repository amplify the effect, potentially exhausting Gitaly's available goroutines/CPU and degrading service for other repositories/tenants sharing the same Gitaly node — matching a resource-exhaustion / DoS-of-RPC-handler impact class.

### Likelihood Explanation
The attacker only needs ownership of a repository (push access) and the ability to call an RPC with fields from their own commit — both are within the unprivileged-attacker capability model. Crafting a `.gitattributes` with tens of thousands of glob rules and a `GetFileAttributesRequest` with thousands of paths is straightforward and fully reproducible; no non-default configuration or privileged access is required.

### Recommendation
Add explicit upper bounds in `validateGetFileAttributesRequest` on `len(in.GetPaths())` and `len(in.GetAttributes())` (and reject requests exceeding them), and/or process paths in bounded batches with a deadline/size-based cap tied to the request context so a single request cannot run indefinitely. Consider also enabling a default per-RPC concurrency limit for `GetFileAttributes` in `config.toml` defaults so pathological requests cannot monopolize worker capacity even absent operator tuning.

func (c CheckAttrCmd) Check(path string) (Attributes, error) {
	if strings.Contains(path, "\000") {
		return nil, fmt.Errorf("path with NUL byte not allowed")
	}

	c.m.Lock()
	defer c.m.Unlock()

	if _, err := c.stdin.WriteString(path + "\000"); err != nil {
		return nil, fmt.Errorf("write path: %w", err)
	}
	if err := c.stdin.Flush(); err != nil {
		return nil, fmt.Errorf("flush: %w", err)
	}

	attrs := Attributes{}
	buf := make([]string, 0, 3)

	// Using git-check-attr(1) with -z will return data in the format:
	// <path> NUL <attribute> NUL <info> NUL ...
	for i := 0; i < c.count; {
		word, err := c.stdout.ReadBytes('\000')
		if err != nil {
			return nil, fmt.Errorf("read line: %w", err)
		}

		buf = append(buf, string(bytes.TrimSuffix(word, []byte{0})))

		if len(buf) < 3 {
			continue // Keep going until we have 3 words
		}

		if buf[0] != path {
			return nil, fmt.Errorf("wrong path name detected, expected %q, got %q", path, buf[0])
		}
		if buf[2] != Unspecified {
			attrs = append(attrs, Attribute{Name: buf[1], State: buf[2]})
		}

		i++
		buf = buf[:0]
	}

	return attrs, nil
}

// WithConcurrencyLimiters sets up middleware to limit the concurrency of
// requests based on RPC and repository
func WithConcurrencyLimiters(cfg config.Cfg) (map[string]*limiter.AdaptiveLimit, map[string]*limiter.AdaptiveLimit, SetupFunc) {
	perRPCLimits := map[string]*limiter.AdaptiveLimit{}
	perRPCLimitsUnauthenticated := map[string]*limiter.AdaptiveLimit{}

	for _, concurrency := range cfg.Concurrency {
		// Create authenticated limiter
		limitName := fmt.Sprintf("perRPC%s", concurrency.RPC)
		if concurrency.Adaptive {
			perRPCLimits[concurrency.RPC] = limiter.NewAdaptiveLimit(limitName, limiter.AdaptiveSetting{
				Initial:       concurrency.InitialLimit,
				Max:           concurrency.MaxLimit,
				Min:           concurrency.MinLimit,
				BackoffFactor: limiter.DefaultBackoffFactor,
			})
		} else {
			perRPCLimits[concurrency.RPC] = limiter.NewAdaptiveLimit(limitName, limiter.AdaptiveSetting{
				Initial: concurrency.Concurrency(),
			})
		}

		// Create unauthenticated limiter if configured
		unauthLimits := concurrency.Unauthenticated
		if unauthLimits.IsSet() {
			limitNameUnauth := fmt.Sprintf("perRPC%s-unauthenticated", concurrency.RPC)
			if unauthLimits.Adaptive {
				perRPCLimitsUnauthenticated[concurrency.RPC] = limiter.NewAdaptiveLimit(limitNameUnauth, limiter.AdaptiveSetting{
					Initial:       unauthLimits.InitialLimit,
					Max:           unauthLimits.MaxLimit,
					Min:           unauthLimits.MinLimit,
					BackoffFactor: limiter.DefaultBackoffFactor,
				})
			} else if unauthLimits.Concurrency() > 0 {
				perRPCLimitsUnauthenticated[concurrency.RPC] = limiter.NewAdaptiveLimit(limitNameUnauth, limiter.AdaptiveSetting{
					Initial: unauthLimits.Concurrency(),
				})
			}
		}
	}
