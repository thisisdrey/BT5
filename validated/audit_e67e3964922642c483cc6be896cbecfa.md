### Title
Handshake-pending connection exhaustion bypasses per-IP/global rate limiters, allowing a single unstaked attacker to deny all new connections up to `max_concurrent_connections()` - ([File: streamer/src/nonblocking/quic.rs])

### Summary
In the QUIC accept loop, `ClientConnectionTracker::new` reserves a global connection slot as soon as an `Incoming` passes the peek-only rate-limit checks, but the per-IP (`ConnectionRateLimiter`) and global (`overall_connection_rate_limiter`) token buckets are only *consumed* after a successful handshake in `setup_connection`. An attacker who never completes the handshake therefore never spends any rate-limit tokens, letting it repeatedly occupy slots up to `qos.max_concurrent_connections()` (125% of `max_staked_connections + max_unstaked_connections`) and cause `refused_connections_too_many_open_connections` for everyone else, bounded only by the 2‑second `QUIC_CONNECTION_HANDSHAKE_TIMEOUT`.

### Finding Description
The accept loop in `run_server` (`streamer/src/nonblocking/quic.rs:331-379`) processes each `Incoming` as follows:
1. `overall_connection_rate_limiter.current_tokens() == 0` — a peek, no token consumed.
2. `rate_limiter.is_allowed(&ip)` — also a peek (`ConnectionRateLimiter::is_allowed`, `streamer/src/nonblocking/connection_rate_limiter.rs:34-40`), which returns `true` for any IP with no prior *registered* (i.e., completed) connection.
3. `ClientConnectionTracker::new(stats.clone(), qos.max_concurrent_connections())` (`streamer/src/nonblocking/quic.rs:236-251`) — this is the only check that actually mutates shared state (`stats.open_connections.fetch_add`) and enforces the hard cap before the handshake is attempted.
4. `incoming.accept()` is called and `setup_connection` is spawned.

Only inside `setup_connection` (`streamer/src/nonblocking/quic.rs:456-543`), *after* `timeout(QUIC_CONNECTION_HANDSHAKE_TIMEOUT, connecting).await` succeeds, does the code call `rate_limiter.register_connection(&from.ip())` (line 483) and `overall_connection_rate_limiter.consume_tokens(1)` (line 495) — i.e., the actual token consumption that would throttle repeat offenders happens only for **completed** handshakes.

Consequently, an attacker who sends QUIC Initial packets and never completes the handshake (or deliberately stalls) never triggers the per-IP or global consuming rate limiters, since those are only "peeked" at admission and never decremented for failed/incomplete attempts. The only real gate is `ClientConnectionTracker::new`'s comparison against `max_concurrent_connections()`, which is a *shared, peer-type-agnostic* pool. Once `open_connections >= max_concurrent_connections()`, every subsequent `Incoming` — staked or unstaked — is refused via `incoming.refuse()` and counted in `stats.refused_connections_too_many_open_connections` (`streamer/src/nonblocking/quic.rs:371-379`, counter defined at `streamer/src/quic.rs:231`). Each occupied slot is released only when `QUIC_CONNECTION_HANDSHAKE_TIMEOUT` (`streamer/src/nonblocking/quic.rs:80`, 2 seconds) elapses and the `ClientConnectionTracker` is dropped at the end of `setup_connection`'s timeout branch. By continuously issuing fresh Initial packets (each with a new connection ID) from potentially a single source IP faster than the 2s expiry, an attacker can keep the global pool saturated indefinitely.

### Impact Explanation
This is a denial-of-service against the TPU QUIC ingress: legitimate staked and unstaked peers cannot open new connections while the pool is saturated, because `max_concurrent_connections()` is a single shared budget rather than being partitioned/reserved per peer class at the admission stage (partitioning by stake only happens later, inside `ConnectionTable`/QoS logic, which is never reached for stalled handshakes). This falls under the Denial-of-Service bounty category (temporary inability to accept new leader-bound QUIC connections), scoped to the connection-admission layer in `streamer/src/nonblocking/quic.rs`.

### Likelihood Explanation
Preconditions are low: the attacker is a fully unprivileged remote UDP client that only needs to send QUIC initial packets to the TPU port and let/keep them from completing the handshake (e.g., stop responding, or hold on the last flight) — no stake, keys, or gossip participation required. The attack is repeatable indefinitely as long as the attacker keeps generating fresh Incoming attempts faster than the 2-second timeout releases slots, since neither the per-IP nor global rate limiter charges anything for incomplete handshakes.

### Recommendation
Consume/charge rate-limiter tokens (both per-IP and global) at admission time (before or at `ClientConnectionTracker::new`), not only after a successful handshake, so that repeated stalled attempts from the same IP or in aggregate get throttled the same as completed ones. Additionally, consider reserving a portion of `max_concurrent_connections()` capacity for staked peers (or otherwise partitioning the handshake-pending pool by peer class) so unstaked attackers cannot starve the whole pool, and/or reduce the effective handshake-pending budget available to a single unverified IP before it has proven address ownership (e.g., via QUIC Retry/address validation).

### Proof of Concept
```rust
// streamer/src/nonblocking/quic.rs (test module)
#[tokio::test(flavor = "multi_thread")]
async fn test_handshake_pending_exhaustion_denies_new_connections() {
    let SpawnTestServerResult {
        join_handle,
        server_address,
        stats,
        cancel,
        ..
    } = setup_quic_server(
        None,
        QuicStreamerConfig::default_for_tests(),
        SwQosConfig::default(),
    );

    let max_concurrent = /* qos.max_concurrent_connections() computed from SwQosConfig::default() */;

    // Attacker: open `max_concurrent` connections but never let quinn complete the handshake
    // (e.g. by using a client endpoint configured to send Initial then drop/ignore responses,
    // or a raw UDP socket sending crafted Initial packets with distinct connection IDs).
    let mut stalled = Vec::new();
    for _ in 0..max_concurrent {
        stalled.push(spawn_stalled_initial_only_attempt(server_address));
    }

    // Give the server time to admit them all as pending (ClientConnectionTracker::new succeeds).
    tokio::time::sleep(Duration::from_millis(200)).await;
    assert_eq!(
        stats.open_connections.load(Ordering::Relaxed),
        max_concurrent
    );

    // A legitimate client attempt should now be refused.
    let legit = make_client_endpoint(&server_address, None).await;
    // expect connection error / refusal within a short window
    assert!(legit_connection_is_refused(&legit).await);
    assert!(
        stats
            .refused_connections_too_many_open_connections
            .load(Ordering::Relaxed)
            > 0
    );

    // After QUIC_CONNECTION_HANDSHAKE_TIMEOUT, slots free and a new legit attempt succeeds,
    // proving the window is bounded per-cycle but repeatable if attacker keeps refilling.
    tokio::time::sleep(QUIC_CONNECTION_HANDSHAKE_TIMEOUT + Duration::from_millis(200)).await;
    let legit2 = make_client_endpoint(&server_address, None).await;
    assert!(legit2_connects_successfully(&legit2).await);

    cancel.cancel();
    join_handle.await.unwrap();
}
```
Expected assertions: `stats.open_connections` reaches `max_concurrent_connections()` purely from stalled/never-completed handshakes; a concurrent legitimate connection attempt is refused (`refused_connections_too_many_open_connections` increments) during that window; and neither `rate_limiter` (per-IP) nor `overall_connection_rate_limiter` (global) tokens are decremented for the stalled attempts, confirming they never throttle the attacker.
