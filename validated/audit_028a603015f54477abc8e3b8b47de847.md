### Title
Unscoped `HooksPayload` bearer credential enables cross-repository push-authorization replay via externally-reachable `HookService.PreReceiveHook` - (File: internal/gitaly/hook/prereceive.go)

### Summary
`QuestFactory.mintReceipt`'s signature only binds `(signer, questId)` with no chain/contract/deadline scoping, so a signature valid in one context is replayable in another. The structural analog in Gitaly is the `HooksPayload`: a base64-encoded JSON blob (not a cryptographic signature, but functioning as the authorization credential for hook RPCs) that carries `UserDetails.UserID` (`GL_ID`), `GitalyClientContext`, and `TransactionID`, but is never bound to the `Repository` value present in the same RPC request, nor to the specific push/RPC invocation that created it.

### Finding Description
`gitcmd.HooksPayload` is constructed once per Git operation and embeds a `Repo` field, but the `HookService` RPC handlers (e.g. `PreReceiveHook`) use the top-level `Repository` field of the gRPC request for path resolution and never compare it against `payload.Repo`; they only pull `UserDetails.UserID`/`Protocol` out of the *payload* for the Rails `Allowed()` authorization call [2](#0-1) . The payload is a plain, unauthenticated JSON structure decoded straight from an environment-variable-style string with no signature or MAC of its own [3](#0-2) . `HookService` (including `PreReceiveHook`) is registered on the external, internet/API-facing gRPC listener, not only the internal Unix socket reserved for `gitaly-hooks` [4](#0-3) , and a test comment explicitly flags this: "*this test setup however is calling the HookService through the external API... in the longer term, we should stop serving HookService on the external socket given it is a service intended only to be used internally by Gitaly for hook callbacks*" [5](#0-4) . The only barrier to invoking `PreReceiveHook` externally is the generic V2 HMAC bearer token described in `auth/token.go` [6](#0-5) , which authenticates *that a caller possesses the shared secret*, not *which repository or user* the caller is entitled to act as — exactly the missing "message scoping" defect called out in the report (no binding of the credential to the specific resource/operation it should be limited to).

### Impact Explanation
Any caller holding a valid Gitaly auth token (the same class of token used generically for all RPCs, not repository- or user-scoped) can invoke `HookService.PreReceiveHook` directly with `Repository` set to an arbitrary target repo and `EnvironmentVariables` containing a self-crafted `HooksPayload` whose `UserDetails.UserID`/`GL_ID` claims to be any user, and whose `TransactionID`/`GitalyClientContext` were captured or replayed from an unrelated, legitimate push. Because the RPC never checks that the payload's embedded `Repo` matches the request's `Repository`, or that the `UserDetails` genuinely originated from the operation currently being processed, this can force Rails' `/internal/allowed` access check to run under attacker-chosen `GLID`/`GLRepository` pairs and execute the repository's custom `pre-receive` hooks with forged actor identity — a hook/access-check gating bypass on a different repository than the one the credential was ever meant to authorize.

### Likelihood Explanation
Reachability requires only possession of a generic Gitaly V2 bearer token (not admin/owner-level or repo-specific), and the vulnerable surface (`HookService` on the external listener) is enabled by default per the server wiring shown above, with an existing test explicitly acknowledging this exposure. Constructing the payload requires no cryptographic secret — it's a base64 JSON blob the caller fully controls — making exploitation straightforward for any party with API-level access, similar to how the original report's attacker needed nothing more than a previously-observed valid signature.

### Recommendation
Bind the `HooksPayload` to the specific request it belongs to: verify `payload.Repo` equals the RPC's `Repository` field, and require that `UserDetails`/`GitalyClientContext`/`TransactionID` be certified via an internal, non-forgeable channel (e.g., HMAC/sign the encoded payload with the internal socket token so it can't be replayed cross-repository, and restrict `HookService` to the internal socket only, resolving the flagged issue #3746) rather than trusting caller-supplied identity fields decoded from an unauthenticated payload.

### Proof of Concept
1. Obtain a valid generic Gitaly V2 auth token per `auth/token.go`'s HMAC scheme (does not require repository- or user-specific privilege).
2. Craft a `HooksPayload` JSON with `Repo` set to a *victim* repository, `UserDetails.UserID` set to a privileged `GL_ID` (e.g., copied from an observed legitimate hook invocation on a different repository), base64-encode it as `GITALY_HOOKS_PAYLOAD=...` per `Env()`/`HooksPayloadFromEnv` [7](#0-6) .
3. Call `HookService.PreReceiveHook` on Gitaly's external listener with `Repository` set to the victim repo and `EnvironmentVariables` containing the crafted payload plus fabricated `changes` stdin, as demonstrated by the RPC-level test harness in `internal/gitaly/service/hook/pre_receive_test.go` [8](#0-7) .
4. Observe that `preReceiveHook` builds `gitlab.AllowedParams` from the forged `payload.UserDetails.UserID`/`Protocol` and the request's `Repository`, invoking Rails' `/internal/allowed` and any custom `pre-receive` hook for that repository under the forged identity [9](#0-8) .

// HooksPayloadFromEnv extracts the HooksPayload from the given environment
// variables. If no HooksPayload exists, it returns a ErrPayloadNotFound
// error.
func HooksPayloadFromEnv(envs []string) (HooksPayload, error) {
	encoded, ok := lookupEnv(envs, EnvHooksPayload)
	if !ok {
		return HooksPayload{}, ErrPayloadNotFound
	}

	decoded, err := base64.StdEncoding.DecodeString(encoded)
	if err != nil {
		return HooksPayload{}, err
	}

	var jsonPayload jsonHooksPayload
	if err := json.Unmarshal(decoded, &jsonPayload); err != nil {
		return HooksPayload{}, err
	}

	var repo gitalypb.Repository
	err = protojson.Unmarshal([]byte(jsonPayload.Repo), &repo)
	if err != nil {
		return HooksPayload{}, err
	}

	payload := jsonPayload.HooksPayload
	payload.Repo = &repo

	// If no RequestedHooks are passed down to us, then we need to assume
	// that the caller of this hook isn't aware of this field and thus just
	// pretend that he wants to execute all hooks.
	if payload.RequestedHooks == 0 {
		payload.RequestedHooks = AllHooks
	}

	return payload, nil
}

// Env encodes the given HooksPayload into an environment variable.
func (p HooksPayload) Env() (string, error) {
	repo, err := protojson.Marshal(p.Repo)
	if err != nil {
		return "", err
	}

	jsonPayload := jsonHooksPayload{HooksPayload: p, Repo: string(repo)}
	marshalled, err := json.Marshal(jsonPayload)
	if err != nil {
		return "", err
	}

	encoded := base64.StdEncoding.EncodeToString(marshalled)

	return fmt.Sprintf("%s=%s", EnvHooksPayload, encoded), nil
}
