## Title
Non-atomic check-then-act race in `TronJsonRpcImpl.getFilterResult` allows a null-dereference crash of JSON-RPC filter requests when raced with `uninstallFilter` — (`File: framework/src/main/java/org/tron/core/services/jsonrpc/TronJsonRpcImpl.java`)

### Summary
The CVE describes a use-after-free in ceph's cap trimming: a cap is looked up/verified under one lock, the lock is released, and the (now possibly-removed) object is dereferenced under a second lock without re-checking it still exists. The analogous bug class — "check for existence, drop atomicity, then dereference" — exists in java-tron's public JSON-RPC filter subsystem: `TronJsonRpcImpl.getFilterResult()` performs a `containsKey()` check and then a separate, non-atomic `get()` call on the same `ConcurrentHashMap`, with no guarantee the entry still exists between the two operations.

### Finding Description
`eventFilter2ResultFull` / `eventFilter2ResultSolidity` are plain `ConcurrentHashMap`s shared across all anonymous JSON-RPC clients [1](#0-0) . Any client that knows a `filterId` (filter IDs are returned to whoever created the filter, but the maps themselves are process-global with no ownership/session binding) can call `eth_uninstallFilter` to remove an entry at any time [2](#0-1) .

Concurrently, `getFilterChanges`/`getLogs`-style calls resolve through `getFilterResult()`:
```java
if (blockFilter2Result.containsKey(filterId)) {
  List<String> blockHashList = blockFilter2Result.get(filterId).popAll();
  ...
} else if (eventFilter2Result.containsKey(filterId)) {
  List<LogFilterElement> logElementList = eventFilter2Result.get(filterId).popAll();
  ...
}
``` [3](#0-2) 

`containsKey()` and the subsequent `.get(filterId)` are two separate atomic operations on the map, not one atomic read. If another thread (either another client's `eth_uninstallFilter` call, or the internal expiry-eviction logic in `handleLogsFilter`/`handleBLockFilter` that removes entries once `isExpire()` is true [4](#0-3) [5](#0-4) ) removes the same `filterId` between the `containsKey` check and the `.get(filterId)` call, `.get(filterId)` returns `null`, and `null.popAll()` throws an unhandled `NullPointerException`. This is the same root-cause shape as the ceph bug: existence is validated, the validating lock/step is released, and a second step blindly dereferences an object that another concurrent path may have already removed.

### Impact Explanation
This is reachable by any unauthenticated JSON-RPC client (`eth_getFilterChanges`, `eth_getLogs` paths ultimately call `getFilterResult`) racing `eth_uninstallFilter`, or simply racing the server's own background filter-expiry sweep in `handleLogsFilter`/`handleBLockFilter`, which run per new block/log on separate threads (`logsFilterPool`) while filter reads happen on the JSON-RPC handler thread. A crash here throws inside the request-handling path; depending on the JSON-RPC dispatcher's exception handling this manifests at minimum as an unhandled internal error for that request, and if uncaught by the outer dispatcher, can destabilize the request-serving thread. Impact is capped at denial-of-service against the JSON-RPC filter API — it does not affect consensus, balances, or block-processing correctness.

### Likelihood Explanation
Exploitation requires precise timing to land inside the narrow race window between `containsKey` and `get`, or to race a filter removal with a background expiry pass — feasible but not trivially reliable, since the window is only a few CPU instructions wide under normal JIT-compiled execution. An attacker with two connections (one issuing `eth_uninstallFilter`, one issuing `eth_getFilterChanges`) in a tight loop against the same `filterId` can eventually win the race, but this is probabilistic rather than deterministic, unlike the kernel scenario which has broader concurrency windows.

### Recommendation
Replace the `containsKey()` + `get()` pattern in `getFilterResult()` (and similarly in `uninstallFilter`) with a single atomic `Map.get()` call, checking the returned reference for `null` directly instead of re-querying the map:
```java
BlockFilterAndResult blockResult = blockFilter2Result.get(filterId);
if (blockResult != null) {
  List<String> blockHashList = blockResult.popAll();
  ...
} else {
  LogFilterAndResult eventResult = eventFilter2Result.get(filterId);
  if (eventResult != null) {
    ...
  } else {
    throw new ItemNotFoundException(FILTER_NOT_FOUND);
  }
}
```
This removes the TOCTOU window entirely, mirroring the ceph fix's approach of re-validating existence at the point of use rather than trusting an earlier check.

### Proof of Concept
1. Client A creates a log filter via `eth_newFilter`, receiving `filterId = X`.
2. Client A spawns two tight loops concurrently:
   - Loop 1: repeatedly call `eth_uninstallFilter(X)` (re-adding the filter each time it's removed, or targeting the natural expiry/eviction path in `handleLogsFilter`).
   - Loop 2: repeatedly call `eth_getFilterChanges(X)`.
3. Given enough iterations, Loop 2's call lands between the `containsKey(X)` check succeeding and the `.get(X)` call, after Loop 1 (or the background expiry sweep) has removed the entry, causing `.get(X)` to return `null` and the subsequent `.popAll()` call to throw `NullPointerException` inside `getFilterResult` [6](#0-5) .

  @Override
  public boolean uninstallFilter(String filterId) throws ItemNotFoundException,
      JsonRpcMethodNotFoundException {
    disableInPBFT("eth_uninstallFilter");

    Map<String, BlockFilterAndResult> blockFilter2Result;
    Map<String, LogFilterAndResult> eventFilter2Result;
    if (getSource() == RequestSource.FULLNODE) {
      blockFilter2Result = blockFilter2ResultFull;
      eventFilter2Result = eventFilter2ResultFull;
    } else {
      blockFilter2Result = blockFilter2ResultSolidity;
      eventFilter2Result = eventFilter2ResultSolidity;
    }

    filterId = ByteArray.fromHex(filterId);
    if (eventFilter2Result.containsKey(filterId)) {
      eventFilter2Result.remove(filterId);
    } else if (blockFilter2Result.containsKey(filterId)) {
      blockFilter2Result.remove(filterId);
    } else {
      throw new ItemNotFoundException(FILTER_NOT_FOUND);
    }

    return true;
  }

  public Object[] getFilterResult(String filterId, Map<String, BlockFilterAndResult>
      blockFilter2Result, Map<String, LogFilterAndResult> eventFilter2Result)
      throws ItemNotFoundException {
    Object[] result;

    if (blockFilter2Result.containsKey(filterId)) {
      List<String> blockHashList = blockFilter2Result.get(filterId).popAll();
      result = blockHashList.toArray(new String[blockHashList.size()]);
      blockFilter2Result.get(filterId).updateExpireTime();

      List<LogFilterElement> logElementList = eventFilter2Result.get(filterId).popAll();
      result = logElementList.toArray(new LogFilterElement[0]);
      eventFilter2Result.get(filterId).updateExpireTime();

    } else {
      throw new ItemNotFoundException(FILTER_NOT_FOUND);
    }

    return result;
  }
