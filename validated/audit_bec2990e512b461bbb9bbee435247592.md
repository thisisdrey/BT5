### Title
Creator Can Burn Soul Bound Tokens Without Recipient Consent — (`aptos-move/framework/aptos-token-objects/sources/aptos_token.move`)

### Summary

When a collection is created with `tokens_burnable_by_creator=true`, the `mint_internal` function unconditionally stores a `burn_ref` inside every minted `AptosToken`, including those minted as soul bound via `mint_soul_bound_token_object`. The `burn` entry function's authorization check (`authorized_borrow`) verifies only the collection creator identity — not token ownership — so the creator can call `burn` on a soul bound token held by a recipient, permanently destroying it without the recipient's knowledge or consent.

### Finding Description

**Step 1 — `mint_internal` stores `burn_ref` unconditionally for burnable collections** [1](#0-0) 

When `tokens_burnable_by_creator=true`, a `BurnRef` is generated and stored in `AptosToken.burn_ref`. This happens for every token minted from the collection, including soul bound ones.

**Step 2 — `mint_soul_bound_token_object` disables transfer but does not clear `burn_ref`** [2](#0-1) 

The function disables ungated transfer (making the token non-transferable), but the `burn_ref` stored in step 1 is never removed or nullified. The `transfer_ref` used here is a local variable that is dropped — it is never stored in `AptosToken.transfer_ref`.

**Step 3 — `authorized_borrow` checks creator identity, not ownership** [3](#0-2) 

The check uses `token::creator(*token)`, which resolves to the collection's creator address: [4](#0-3) 

This is the collection creator's address, not the current token owner. The soul bound recipient is irrelevant to this check.

**Step 4 — `burn` succeeds end-to-end** [5](#0-4) 

`authorized_borrow` passes (creator check), `burn_ref.is_some()` is `true`, and `token::burn` is called. `token::burn` itself has no check for `allow_ungated_transfer` or soul bound status: [6](#0-5) 

The object is deleted from state. The recipient's soul bound token is permanently gone.

### Impact Explanation

The soul bound invariant — that the recipient has permanent, irrevocable custody of a non-transferable token — is broken. The recipient cannot transfer the token away to protect it (ungated transfer is disabled), yet the creator can destroy it at any time. This constitutes unauthorized burning of a user-controlled token object, which is an in-scope impact under the bounty rules.

### Likelihood Explanation

Any collection creator who sets `tokens_burnable_by_creator=true` and uses `mint_soul_bound` (the public entry function exposed in the SDK) can trigger this. The entry point is a standard transaction callable from any account. No special system privileges are required — the creator is an ordinary user who deployed a collection.

### Recommendation

`mint_soul_bound_token_object` should not store a `burn_ref` when minting a soul bound token, regardless of the collection's `tokens_burnable_by_creator` flag. Concretely, `mint_internal` should either:
- Accept a parameter indicating soul bound minting and skip `burn_ref` generation, or
- `mint_soul_bound_token_object` should override `burn_ref` to `option::none()` after calling `mint_internal`.

Alternatively, `burn` should assert that `allow_ungated_transfer` is `true` before proceeding, preventing burns of soul bound tokens.

### Proof of Concept

```move
#[test(creator = @0x123, recipient = @0x456)]
fun test_creator_burns_soul_bound(creator: &signer, recipient: &signer)
    acquires AptosCollection, AptosToken
{
    // 1. Create collection with tokens_burnable_by_creator = true
    create_collection_helper(creator, string::utf8(b"col"), true);

    // 2. Mint soul bound token to recipient
    let token = mint_soul_bound_token_object(
        creator,
        string::utf8(b"col"),
        string::utf8(b""),
        string::utf8(b"sbt"),
        string::utf8(b""),
        vector[], vector[], vector[],
        signer::address_of(recipient),
    );
    let token_addr = token.object_address();

    // 3. Verify recipient owns it and transfer is disabled
    assert!(token.owner() == signer::address_of(recipient), 0);

    // 4. Creator burns it — succeeds despite recipient owning it
    burn(creator, token);

    // 5. Token is gone — recipient permanently lost their soul bound token
    assert!(!exists<AptosToken>(token_addr), 1);
}
```
