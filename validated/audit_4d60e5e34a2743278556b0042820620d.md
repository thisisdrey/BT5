### Title
Gas-key nonce reset on same-block AddKey/DeleteKey cycle allows nonce-slot replay - ([File: runtime/runtime/src/access_keys.rs])

### Finding Description
`add_gas_key` (`runtime/runtime/src/access_keys.rs:194-227`) unconditionally reseeds every nonce slot `0..num_nonces` to `initial_nonce_value(block_height) = (block_height-1)*ACCESS_KEY_NONCE_RANGE_MULTIPLIER` via `set_gas_key_nonce`, regardless of any nonce value previously consumed at that slot in an earlier "generation" of the same public key. `delete_gas_key` (`:93-134`) fully removes the access key and all `num_nonces` nonce rows. `TrieKey::gas_key_nonce(account_id, key_handle, index)` carries no generation/epoch tag — it is keyed purely by `(account_id, public_key, index)`.

`verify_and_charge_gas_key_tx_ephemeral` (`runtime/runtime/src/verifier.rs:370-419`) checks `nonce_index >= gas_key_info.num_nonces` against the *current* `GasKeyInfo.num_nonces`, and then calls `verify_nonce` (`verifier.rs:211-236`) which for `NonceMode::Monotonic` only requires `tx_nonce > current_nonce` — it has no memory of nonce values used by a prior "incarnation" of the key.

Exploit flow (all actions performed by the account owner using their own regular access key, no privileged access needed):
1. Attacker's account (self-funded, self-owned) adds gas key `K` with `num_nonces=5` at block height `H` (`AddKey` action → `add_gas_key`). All 5 slots seeded to `(H-1)*1e6`.
2. Attacker signs and submits a gas-key transaction with `nonce_index=4`, `nonce=M`, where `M` is chosen close to the upper bound `H*1e6` (allowed per `verify_nonce`'s bound check, `verifier.rs:229-234`), consuming slot 4 to `M`.
3. Attacker issues `DeleteKey(K)` (`action_delete_key`→`delete_gas_key`) at the same height `H`; this burns the (≤1 NEAR) balance and removes all 5 nonce rows, including index 4.
4. Attacker re-adds `K` via `AddKey` with a smaller `num_nonces=2` (allowed since `K` no longer exists, so `AddKeyAlreadyExists` doesn't trigger); only indices 0–1 are (re)written, both reseeded to `(H-1)*1e6`. Index 4 has no live row.
5. Attacker deletes `K` again (`delete_gas_key` removes only indices 0–1, since the *current* `GasKeyInfo.num_nonces=2`).
6. Attacker re-adds `K` a third time with `num_nonces=5`; `add_gas_key`'s loop `for i in 0..num_nonces` unconditionally writes index 4 again, reseeded to `(H-1)*1e6` — a value strictly below the previously-consumed `M`.
7. Attacker (or anyone holding the original signed transaction bytes, since transactions are publicly visible) resubmits the *original signed transaction from step 2* (same `nonce_index=4`, `nonce=M`). `verify_and_charge_gas_key_tx_ephemeral` reads the reseeded `current_nonce = (H-1)*1e6 < M`, `verify_nonce` passes (`M > current_nonce`), and the transaction is accepted and re-executed a second time — even though it had already been executed once at step 2.

This defeats the nonce-monotonicity invariant per `(account, public_key, nonce_index)` that is explicitly documented as the sole anti-replay mechanism for gas keys (no per-generation nonce floor, no permanent tx-hash dedup beyond a single-chunk check at `runtime/runtime/src/lib.rs:2038` that only prevents committing two outcomes for the identical hash within one chunk). The `(block_height-1)*1e6` reseed floor (`initial_nonce_value`, `access_keys.rs:46-50`, referencing near/nearcore#3779) is only effective against nonces used in *earlier* block heights; it provides no protection when the delete/re-add cycle happens within the *same* block height as the original consumption, since nonces up to `block_height*1e6 - 1` are valid within that height.

### Impact Explanation
This breaks the "nonce monotonicity per (account, key, nonce_index)" invariant and permits the previously-executed transaction at a nonce slot to be re-executed after a same-height delete+re-add cycle of the gas key — a **replay of an already-consumed gas-key nonce slot**. The exploit is confined to the attacker's own account/key: `action_add_key`/`action_delete_key` both require `actor_id == account_id` (self-only, `runtime/runtime/src/actions.rs:746-760`), so the delete/re-add sequence cannot be performed against another user's key. Consequently, the only party that can be affected by resubmission of the old signed transaction is whoever relied on that transaction's effects being final/singular — e.g., a relayer or a contract (including one deployed by the attacker interacting with a shared pool) that treats the transaction's nonce as a unique idempotency token. Reproducing the double-execution itself (the scoped ask) is directly demonstrable and violates the documented invariant, but a concrete "loss of third-party funds" requires an additional external dependency (a relayer or contract that assumes nonce-based single-execution) that is not itself part of this codebase.

### Likelihood Explanation
Preconditions are all satisfiable by an ordinary funded account: creating/deleting a gas key repeatedly at the same block height, choosing an intentionally high nonce value close to the per-height upper bound, and resubmitting an old signed transaction (assuming it is still within its block-hash validity window, which is plausible for actions performed within the same block/height). Cost to the attacker is limited to gas fees and (optionally) burning ≤1 NEAR of gas-key balance per delete cycle (`GasKeyInfo::MAX_BALANCE_TO_BURN`). The sequence is fully repeatable for any nonce slot and any gas key the attacker controls.

### Recommendation
Do not reset gas-key nonce values downward when a public key is deleted and re-added; e.g., persist a per-account monotonic "last used" watermark across the lifetime of a public key (not just its currently-live generation), or forbid re-adding a previously-used public key as a gas key entirely (require deterministically-fresh keys), or seed new/recreated gas-key nonces strictly above the highest nonce value ever observed for that `(account_id, public_key)` pair rather than a function of block height alone.

### Proof of Concept
Unit test in `runtime/runtime/src/access_keys.rs` (or `verifier.rs`) test module, following the pattern of `test_add_gas_key`/`test_delete_gas_key`:
1. `add_gas_key_to_account` with `num_nonces=5` at `TEST_GAS_KEY_BLOCK_HEIGHT = H`.
2. Directly call `set_gas_key_nonce`/simulate consumption to set index 4's nonce to `M = H*ACCESS_KEY_NONCE_RANGE_MULTIPLIER - 1` (or via `verify_and_charge_gas_key_tx_ephemeral` + applying `AccessKeyUpdate::GasKey`).
3. Call `action_delete_key` for `K`.
4. Call `action_add_key` for `K` with `num_nonces=2`.
5. Call `action_delete_key` for `K` again.
6. Call `action_add_key` for `K` with `num_nonces=5` again.
7. Read `get_gas_key_nonce(state_update, account_id, K, 4)` and assert it equals `(H-1)*ACCESS_KEY_NONCE_RANGE_MULTIPLIER`, i.e., strictly less than `M`.
8. Call `verify_and_charge_gas_key_tx_ephemeral` with `nonce_index=4`, `tx_nonce=M`, `current_nonce` from step 7 — assert it returns `TxVerdict::Success` instead of `TxVerdict::Failed(InvalidTxError::InvalidNonce)`, proving the previously-consumed `(index=4, nonce=M)` pair is valid again. fn add_gas_key(
    fee_config: &RuntimeFeesConfig,
    state_update: &mut TrieUpdate,
    account: &mut Account,
    account_id: &AccountId,
    public_key: &PublicKey,
    access_key: &AccessKey,
    gas_key_info: &GasKeyInfo,
    block_height: BlockHeight,
) -> Result<(), StorageError> {
    // For gas keys, nonce stored on access key is not used and should always be zero
    let mut access_key = access_key.clone();
    access_key.nonce = 0;
    set_access_key(state_update, account_id.clone(), public_key.clone(), &access_key);

    // Set up nonces for gas key
    let num_nonces = gas_key_info.num_nonces;
    let nonce = initial_nonce_value(block_height);
    for i in 0..num_nonces {
        set_gas_key_nonce(state_update, account_id.clone(), public_key.clone(), i, nonce);
    }

    account.set_storage_usage(
        account
            .storage_usage()
            .checked_add(gas_key_storage_cost(fee_config, public_key, &access_key, num_nonces))
            .ok_or_else(|| {
                StorageError::StorageInconsistentState(format!(
                    "Storage usage integer overflow for account {}",
                    account_id
                ))
            })?,
    );
    Ok(())

fn verify_nonce(
    tx_nonce: Nonce,
    current_nonce: Nonce,
    block_height: Option<BlockHeight>,
    nonce_mode: NonceMode,
) -> Result<(), InvalidTxError> {
    match nonce_mode {
        NonceMode::Monotonic => {
            if tx_nonce <= current_nonce {
                return Err(InvalidTxError::InvalidNonce { tx_nonce, ak_nonce: current_nonce });
            }
        }
        NonceMode::Strict => {
            if !current_nonce.checked_add(1).is_some_and(|expected| tx_nonce == expected) {
                return Err(InvalidTxError::InvalidNonce { tx_nonce, ak_nonce: current_nonce });
            }
        }
    }
    if let Some(height) = block_height {
        let upper_bound = height
            .saturating_mul(near_primitives::account::AccessKey::ACCESS_KEY_NONCE_RANGE_MULTIPLIER);
        if tx_nonce >= upper_bound {
            return Err(InvalidTxError::NonceTooLarge { tx_nonce, upper_bound });
        }
    }
    Ok(())
