### Title
Unauthenticated remote shutdown of signer event receiver via `/shutdown` HTTP endpoint - (File: libsigner/src/events.rs)

### Summary
`SignerEventReceiver::next_event` dispatches control and data events purely by matching `request.url()` against string literals, with no authentication, shared secret, or source-address check. Because `/shutdown` is treated identically whether it originates from the trusted node or an arbitrary remote TCP client, any party able to reach the bound event-receiver socket can send a single unauthenticated `POST /shutdown` request and permanently halt the signer's event loop.

### Finding Description
In `next_event`, after checking the HTTP method is `POST`, the URL is matched literally: `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block`, and `/shutdown` [1](#0-0) . No signature, token, or peer-identity check gates entry into any of these branches — the only prior check is `request.method() != &HttpMethod::Post` [2](#0-1) . The `/shutdown` branch unconditionally sets `event_receiver.stop_signal.store(true, Ordering::SeqCst)` and returns `Err(EventError::Terminated)` [3](#0-2) .

This exact same code path is used intentionally by `SignerStopSignaler::send()`, which opens a plain `TcpStream::connect` to `self.local_addr` and writes a raw `POST /shutdown HTTP/1.1` request with no authentication token at all [4](#0-3) . This demonstrates that the shutdown mechanism was designed to be triggered by nothing more than the ability to open a TCP connection to the bound address — there is no secret embedded in the request that distinguishes a legitimate internal caller from an external attacker.

`EventReceiver::main_loop` treats `Err(EventError::Terminated)` as a clean exit condition: it logs "Caught termination signal" and `break`s out of the loop [5](#0-4) . Once broken, the thread returns, and per `Signer::spawn`, the event-receiver thread simply joins [6](#0-5)  — nothing restarts it. The signer's own documentation even acknowledges this exposure risk generically ("exercise caution if you are communicating with an external node...proper security checks") without implementing any concrete access control in this code path [7](#0-6) .

### Impact Explanation
A single crafted HTTP POST to `/shutdown` permanently disables the `SignerEventReceiver` main loop for the target signer process, which stops delivering all subsequent StackerDB chunks, burn-block, and proposal-response events to the signer's business logic runloop. This is a full denial of service against a signer's participation in consensus/signing until the process is manually restarted, requiring only one unauthenticated message and no privileged role, matching the "Critical - remote crash/unauthenticated DoS from few messages" category.

### Likelihood Explanation
The only precondition is TCP reachability to the signer's bound `endpoint` address configured for the event receiver (set via `SpawnedSigner::new`/`Signer::spawn` using `config.endpoint` [8](#0-7) ). If this endpoint is bound to a non-loopback interface or otherwise reachable by a remote attacker, no credentials, keys, or slot ownership are needed — a bare TCP client suffices, exactly as demonstrated by the internal `SignerStopSignaler::send()` implementation which uses no secret. The attack is trivially repeatable and costs a single short-lived TCP connection.

### Recommendation
Require authentication for control-plane actions distinct from data-plane ingestion: e.g., bind the event receiver to loopback only by default and document/enforce it, or require a shared secret/HMAC token (configured out-of-band between node and signer) checked before honoring `/shutdown`, and/or restrict `/shutdown` (and ideally all POST endpoints) to only be processed from the local dispatching node via source-address allowlisting plus a per-request authentication header, rejecting any request lacking a valid token before dispatching on `request.url()`.

### Proof of Concept
1. Start a `SignerEventReceiver`/`Signer` bound to `127.0.0.1:PORT` similar to `test_status_endpoint` in `libsigner/src/tests/mod.rs` [9](#0-8) .
2. From a plain `TcpStream::connect` (simulating an unauthenticated remote attacker, not using `SignerStopSignaler`), send:
   `POST /shutdown HTTP/1.1\r\nHost: 127.0.0.1:PORT\r\nConnection: close\r\nContent-Length: 0\r\n\r\n`
3. Assert that `running_signer` (or `event_receiver.is_stopped()`) becomes `true` and that `main_loop` exits, and that a subsequent legitimate `POST /stackerdb_chunks` sent to the same endpoint is never received/forwarded — confirming permanent loss of the event stream, mirroring the assertion pattern used in `test_simple_signer` [10](#0-9) .

#[test]
fn test_status_endpoint() {
    let ev = SignerEventReceiver::new(false);
    let (res_send, _res_recv) = channel();
    let max_events = 1;
    let mut signer = Signer::new(SimpleRunLoop::new(max_events), ev, res_send);
    let endpoint: SocketAddr = "127.0.0.1:31000".parse().unwrap();

    // Spawn the signer first so the HTTP server is listening before the mock client connects
    let running_signer = signer.spawn(endpoint).unwrap();

    // simulate a node that's trying to push data
    let mock_stacks_node = thread::spawn(move || {
        let mut sock = TcpStream::connect(endpoint).unwrap();
        let req = format!("GET /status HTTP/1.1\r\nHost: {endpoint}\r\nConnection: close\r\n\r\n");

        sock.write_all(req.as_bytes()).unwrap();
        let mut buf = [0; 128];
        let _ = sock.read(&mut buf).unwrap();
        let res_str = std::str::from_utf8(&buf).unwrap();
        let expected_status_res = "HTTP/1.1 200 OK\r\n";
        assert_eq!(expected_status_res, &res_str[..expected_status_res.len()]);
        sock.flush().unwrap();
    });
    sleep_ms(3000);
    let accepted_events = running_signer.stop().unwrap();

    let sent_events: Vec<SignerEvent<SignerMessage>> = vec![SignerEvent::StatusCheck];

    assert_eq!(sent_events, accepted_events);
    mock_stacks_node.join().unwrap();
}
