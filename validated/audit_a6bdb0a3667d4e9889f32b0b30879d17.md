### Title
HTTP API disabled-list access-control bypass via duplicate slashes in URL path - (File: `framework/src/main/java/org/tron/core/services/filter/HttpApiAccessFilter.java`)

### Summary
`HttpApiAccessFilter` is the servlet filter that enforces an operator-configured `disabledApiList`, blocking access to specific `/wallet/*`, `/walletsolidity/*`, `/walletpbft/*`, `net/listnodes`, and `monitor/*` HTTP endpoints. The rule-matching logic in `isDisabled()` extracts the API name from the request path using `String.split("/")` after only `URI.normalize()`, which (per RFC 3986 §5.2.4) removes `.`/`..` dot-segments but does **not** collapse repeated slashes. An unauthenticated remote client can therefore insert an extra `/` into the path (e.g. `GET /wallet//getnowblock`) to shift the array index used for matching, causing the disabled-API check to silently fail while the request still reaches the underlying servlet — the same root-cause pattern as the filebrowser advisory (rule enforcement does strict/positional string matching on a raw, non-fully-normalized path, while the actual request routing resolves the duplicated separators to the intended resource).

### Finding Description
The filter is applied globally (`context.addFilter(new FilterHolder(httpApiAccessFilter), "/*", ...)`, see `framework/src/main/java/org/tron/core/services/http/FullNodeHttpApiService.java:527-535`, and similarly in `HttpApiOnPBFTService`/`HttpApiOnSolidityService`) and its enforcement lives entirely in: [1](#0-0) 

```java
private boolean isDisabled(String endpoint) {
  boolean disabled = false;
  try {
    endpoint = URI.create(endpoint).normalize().toString();
    List<String> disabledApiList = CommonParameter.getInstance().getDisabledApiList();
    if (!disabledApiList.isEmpty()) {
      disabled = disabledApiList.contains(endpoint.split("/")[2].toLowerCase(Locale.ROOT));
    }
  } ...
}
```

- `URI.normalize()` only performs dot-segment removal; it deliberately does not merge `//` into `/`, because RFC 3986 treats an empty path segment as syntactically valid and distinct.
- The code assumes `endpoint.split("/")` always places the API name at index `[2]` (e.g. `["", "wallet", "getnowblock"]` for `/wallet/getnowblock`). A request such as `/wallet//getnowblock` produces `["", "wallet", "", "getnowblock"]`, so index `[2]` is `""`, which never matches any entry in `disabledApiList`. The filter then calls `chain.doFilter(...)` and the request proceeds unblocked.
- Meanwhile, the actual endpoint the request is dispatched to (`GetNowBlockServlet`, mapped at the exact literal path `/wallet/getnowblock` in `FullNodeHttpApiService.addServlet`) is resolved by Jetty's own request/URI handling, which — just like the filesystem in the original filebrowser bug — can still route the duplicated-slash request to the same underlying resource, so the "disallow" rule is defeated while the resource itself remains reachable.
- The existing test suite in `HttpApiAccessFilterTest.testIsDisabled` (`framework/src/test/java/org/tron/core/services/filter/HttpApiAccessFilterTest.java:127-151`) explicitly exercises dot-segment (`../`) bypass attempts and confirms the author was aware of path-normalization attacks against this check, but no test covers the duplicate-slash (`//`) case, confirming the gap. ### Impact Explanation
`disabledApiList` is the mechanism operators use to shut off specific query-path APIs on their full/solidity/PBFT nodes (e.g. shielded-note scanning APIs, `getnodeinfo`, `listnodes`, or any other endpoint an operator judges sensitive or wishes to disable for security/DoS reasons). Bypassing this filter lets any remote, unauthenticated HTTP client reach an API the node operator explicitly disabled — an authorization bypass (CWE-863) against the node's own access-control configuration, directly analogous to the filebrowser "Disallow" rule bypass. Depending on which API an operator has disabled (shielded-transaction note scanning endpoints are a common reason to disable APIs), this can expose privacy-sensitive data or reachable functionality that was intentionally turned off, undermining the confidentiality guarantees the control was meant to provide.

### Likelihood Explanation
The bypass requires only a single unauthenticated HTTP GET/POST request with an extra slash inserted into the path — no special privileges, signatures, or preconditions are needed, matching the "single API request" reachability bar. It is deterministic and does not depend on race conditions or node configuration beyond having `disabledApiList` populated (the feature's entire purpose).

### Recommendation
Fix `isDisabled()` to normalize path separators (e.g. collapse repeated `/` via `endpoint.replaceAll("/+", "/")` or route through `URI` path-segment parsing) before doing dot-segment normalization and array-index extraction, and prefer iterating/matching on the full decoded path segments rather than a fixed-index `split("/")[2]` assumption. Add regression tests covering `//`, encoded slashes (`%2F`), and mixed traversal + duplicate-slash inputs, mirroring the existing `../` test cases in `HttpApiAccessFilterTest`.

### Proof of Concept
1. Operator sets `disabledApiList = ["getnowblock"]` in node config, so `GET /wallet/getnowblock` correctly returns `{"Error":"this API is unavailable due to config"}` as verified by the existing test at `HttpApiAccessFilterTest.testHttpFilter`.
2. Attacker sends `GET /wallet//getnowblock` (or equivalently through the solidity/PBFT HTTP ports at `/walletsolidity//getnowblock`, `/walletpbft//getnowblock`).
3. In `isDisabled`, `URI.create("/wallet//getnowblock").normalize().toString()` returns the string unchanged (no dot-segments to remove), and `endpoint.split("/")[2]` evaluates to `""`, which is not contained in `disabledApiList`.
4. `isDisabled` returns `false`, the filter calls `chain.doFilter`, and the request is forwarded to `GetNowBlockServlet`, returning `200 OK` with block data despite the API being administratively disabled.
