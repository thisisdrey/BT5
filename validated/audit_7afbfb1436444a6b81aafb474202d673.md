### Title
Unprivileged attacker can permanently squat a victim's canonical PDA `MarginfiAccount` seed and seed it with attacker-chosen liabilities via `transfer_to_new_account_pda` - ([File: programs/marginfi/src/instructions/marginfi_account/transfer_account.rs])

### Summary
`transfer_to_new_account_pda` derives the new `MarginfiAccount` PDA from `new_authority`, `account_index`, and `third_party_id`, but `new_authority` is an `/// CHECK: WARN: New authority is completely unchecked` `UncheckedAccount` with no signature or consent requirement. Any account holder (including an attacker who owns a throwaway old account) can call this instruction with `new_authority = victim_pubkey`, permanently creating and populating a `MarginfiAccount` at the victim's canonical PDA seed with the attacker's copied lending state, without the victim ever signing.

### Finding Description
In `TransferToNewAccountPda`, `new_marginfi_account` is derived and `init`-ed using seeds `[MARGINFI_ACCOUNT_SEED, group, new_authority, account_index, third_party_id]` [1](#0-0) , while `new_authority` is only an `UncheckedAccount` that is never required to sign [2](#0-1) . The only signer checked against `old_marginfi_account` is `authority`, i.e. the caller's own existing account authority [3](#0-2) . In `transfer_to_new_account_pda`, `initialize_migrated_account` sets `new_account.authority = new_authority.key()` and copies `old_account.lending_account` (including any open borrow/liability shares) straight into the new account [4](#0-3) , and `finalize_migrated_old_account` disables the old account [5](#0-4) .

An attacker who opens a minimal old `MarginfiAccount` with a small deposit and borrow can call `transfer_to_new_account_pda(account_index, third_party_id)` with `new_authority = victim_pubkey`, paying `ACCOUNT_TRANSFER_FEE` [6](#0-5) . Because `init` is used for `new_marginfi_account` at a PDA solely derived from `group`, `victim_pubkey`, `account_index`, and `third_party_id`, this permanently occupies that exact address [1](#0-0) . Any subsequent legitimate `marginfi_account_initialize_pda` call by the victim at the same `(account_index, third_party_id)` will fail with an "account already in use" error since Anchor's `init` requires an uninitialized account. The resulting account also carries nonzero liability shares copied from the attacker's old account, with `authority` field set to the victim's pubkey — state the victim never consented to.

### Impact Explanation
This does not steal victim funds directly (the victim never signed for the pre-seeded account and the debt originated from the attacker's own borrow), but it does two things explicitly in scope: it permanently blocks the victim's genuine account creation at that canonical PDA seed (denial of a specific, deterministic address rather than generic high-traffic DoS), and it plants unauthorized liability-bearing state at an address the victim's authority key controls, violating the stated invariant that no instruction should be able to create/populate a `MarginfiAccount` under another user's authority without their consent. If the victim's tooling (e.g. an integrator or wallet) later derives and assumes this PDA is a fresh, empty account for that `(account_index, third_party_id)`, it could unknowingly interact with an account that already carries a borrow position.

### Likelihood Explanation
This requires no privileged access: attacker only needs to open a normal `MarginfiAccount`, deposit/borrow a minimal amount, and call the publicly reachable `transfer_to_new_account_pda` instruction, paying the flat `ACCOUNT_TRANSFER_FEE`. It is fully repeatable for any target `victim_pubkey` and any `(account_index, third_party_id)` combination the victim has not yet claimed, since `new_authority` requires no signature at all.

### Recommendation
Require `new_authority` to be a `Signer` (or otherwise prove consent, e.g. via a separate signed authorization) whenever it differs from the calling `authority`, so that a `MarginfiAccount` cannot be created/populated at another pubkey's canonical PDA seed without that pubkey's consent. At minimum, disallow `transfer_to_new_account_pda` from setting `new_authority` to an arbitrary unrelated pubkey unless that pubkey signs the transaction.

### Proof of Concept
1. Attacker creates `old_marginfi_account` via `MarginfiAccountInitialize`, deposits collateral, and borrows a minimal amount against a bank, so `old_account.lending_account` has one nonzero liability share.
2. Attacker computes `victim_pda = MarginfiAccount::derive_pda(group, victim_pubkey, account_index=0, third_party_id=None)`.
3. Attacker calls `TransferToNewAccountPda` with `authority = attacker`, `old_marginfi_account = attacker's account`, `new_marginfi_account = victim_pda`, `new_authority = victim_pubkey` (no victim signature included), `fee_payer = attacker`.
4. Assert the transaction succeeds and `victim_pda` account is created, with `new_account.authority == victim_pubkey` and `new_account.lending_account` containing the attacker's copied liability shares (nonzero borrow balance) — mirroring the assertions already present in `transfer_to_new_account_pda_success` [7](#0-6) , but now with `new_authority` unsigned by the victim.
5. Have the "victim" (using their real keypair) attempt `marginfi_account_initialize_pda` (or a second `transfer_to_new_account_pda`) at the same `(group, victim_pubkey, account_index=0, third_party_id=None)` seed and assert it fails because the account is already initialized, proving the canonical PDA slot is permanently squatted.

fn finalize_migrated_old_account(
    old_account: &mut MarginfiAccount,
    new_account_key: Pubkey,
    current_timestamp: u64,
) {
    old_account.migrated_to = new_account_key;
    old_account.last_update = current_timestamp;
    old_account.lending_account = LendingAccount::zeroed();
    old_account.set_flag(ACCOUNT_DISABLED, true);
