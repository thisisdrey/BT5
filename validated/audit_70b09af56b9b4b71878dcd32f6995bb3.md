### Title
Unauthenticated `RecvError` packet allows remote attacker to force tunnel teardown (griefing / remote state poisoning) - (File: outside.go)

### Summary
Nebula's `header.RecvError` control message is processed before any AEAD decryption/authentication and is validated only by comparing the packet's *claimed* UDP source address against the hostinfo's currently-recorded remote address, not by any cryptographic proof of possession of the tunnel's Noise keys. An attacker who can spoof or send packets that appear to originate from a peer's known UDP endpoint (learned from the lighthouse, which is public information on the mesh) can trigger `RecvError` and force any node to tear down the tunnel to that peer, without holding a valid certificate or having ever completed a handshake — the same "anyone can call the state-changing action on someone else's behalf" pattern described in the reference report's `claim()` griefing, replayed here against the connection's liveness state instead of vesting funds.

### Finding Description
In `readOutsidePackets` (outside.go:76-84), `header.RecvError` is dispatched immediately, ahead of the `hostinfo == nil` / decrypt checks that gate every other packet type: [1](#0-0) 

`handleRecvError` (outside.go:541-575) then authorizes teardown using only an address-equality check, not any Noise/AEAD authentication tag: [2](#0-1) 

The lookup key, `h.RemoteIndex`, is the 32-bit index that Nebula transmits in cleartext in every packet header (handshake and data) via `QueryReverseIndex`, so it is trivially observable by anyone who can see wire traffic between the two endpoints (or who received it from prior handshake/data packets): [3](#0-2) 

The only defense against forgery is:
```go
hr := hostinfo.GetRemote()
if hr.IsValid() && hr != addr {
    ... "Someone spoofing recv_errors?" ...
    return
}
f.closeTunnel(hostinfo)
f.handshakeManager.DeleteHostInfo(hostinfo)
```
i.e., the packet's UDP source address must equal the address Nebula currently believes is the peer's remote endpoint. Because UDP has no source-address authentication, and because that endpoint address is itself learned from the lighthouse and is not secret (it's actively distributed to any peer that queries for the target vpn address), an attacker positioned to spoof UDP source (or an on-path/off-path attacker who can forge the 4-tuple) can construct a `RecvError` packet with the correct `RemoteIndex` and spoofed source address to force `closeTunnel` on a victim's active session — with zero cryptographic proof that the sender actually terminated or lost the tunnel. Compare this to `header.CloseTunnel`, which is only processed *after* successful AEAD decryption (outside.go:113-166), i.e. it is cryptographically authenticated — `RecvError` conspicuously lacks that protection, which is the root cause. This mirrors the report's core bug class: a state-mutating action ("claim"/here "tear down my tunnel") gated only by a weak, externally-observable/forgeable credential (an NFT id / a plaintext index+spoofable address) rather than by proof of authorization from the actual counterparty.

### Impact Explanation
Triggering this forces `f.closeTunnel(hostinfo)` and deletes the pending handshake state, disestablishing an active, fully-authenticated Noise tunnel between two legitimate mesh peers. This is a remote, unauthenticated denial-of-service / griefing primitive: repeated forged `RecvError` packets can be used to continuously sever tunnels for a target node, disrupting connectivity for the victim and any dependent relay/lighthouse paths, with no attacker profit motive required — matching the "Griefing" impact class in the reference report (harm to protocol/users without direct attacker gain). It does not by itself decrypt traffic or forge data, but it does allow a non-certificate-holding network attacker to poison a peer's connection-liveness state remotely.

### Likelihood Explanation
Exploitability depends on the attacker's ability to spoof the source UDP `addr` field to match the victim's recorded remote of the target peer, or to be positioned on-path (e.g., NAT/ISP level, or already relayed traffic observation) to capture that 4-tuple. Since `RemoteIndex` travels in plaintext in every packet and UDP source addresses can be spoofed by many on-path/off-path attackers (particularly across the public internet where source IP filtering by intermediate routers is inconsistent), this is a realistic, low-cost attack requiring no valid certificate, no successful handshake, and no cryptographic material — only knowledge of the target's UDP endpoint (obtainable from the lighthouse) and its current index (observable on the wire).

### Recommendation
- Require the `RecvError` path to prove possession of the peer relationship, e.g., by authenticating it with the existing Noise transport keys (similar to how `CloseTunnel` is only honored after AEAD `Decrypt` succeeds), rather than relying solely on address equality of `via.UdpAddr`.
- Alternatively, rate-limit/challenge `RecvError` handling and require it to be accompanied by a signed/keyed value derived from session state so a spoofed source address alone cannot trigger teardown.
- At minimum, treat address-only validated `RecvError` as a soft signal (e.g., trigger a re-handshake attempt) rather than an unconditional `closeTunnel` + `DeleteHostInfo`, reducing the blast radius of a spoofed packet from full teardown to a bounded reconnection probe.

### Proof of Concept
Conceptual PoC (network-level, analogous to the report's `claim()` PoC calling a privileged function on someone else's behalf):
1. Two legitimate nodes A and B complete a Noise handshake and have an active tunnel; A's `hostinfo` for B records `remoteIndexId` = X and `GetRemote()` = B's known UDP `addr`.
2. Attacker (no certificate, not part of the mesh trust) observes/learns B's UDP endpoint via a lighthouse query (public information) and observes/guesses index X from any plaintext packet header exchanged between A and B.
3. Attacker sends a UDP packet to A with header `Type = header.RecvError`, `RemoteIndex = X`, spoofing source address to equal B's known `addr`.
4. In `readOutsidePackets`, this is dispatched directly to `f.handleRecvError` before any decryption (outside.go:81-83).
5. `handleRecvError` finds the hostinfo via `QueryReverseIndex(X)`, sees `hr == addr` (spoofed match), and calls `f.closeTunnel(hostinfo)` plus `hm.DeleteHostInfo(hostinfo)` (outside.go:563-574), tearing down A's legitimate tunnel to B without any involvement or consent from B. [4](#0-3)

```go
func (f *Interface) sendRecvError(endpoint netip.AddrPort, index uint32) {
	f.messageMetrics.Tx(header.RecvError, 0, 1)

	b := header.Encode(make([]byte, header.Len), header.Version, header.RecvError, 0, index, 0)
	_ = f.outside.WriteTo(b, endpoint)
	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error sent",
			"index", index,
			"udpAddr", endpoint,
		)
	}
}

func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
```

```go
func (hm *HostMap) QueryReverseIndex(index uint32) *HostInfo {
	hm.RLock()
	if h, ok := hm.RemoteIndexes[index]; ok {
		hm.RUnlock()
		return h
	} else {
		hm.RUnlock()
		return nil
	}
}
```
