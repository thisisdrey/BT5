Based on my investigation, I found a real local analog: `pallet-recovery`'s `control_inherited_account` filter, which validates only the outer `RuntimeCall` type and can be bypassed when the same privileged call is wrapped inside `pallet_utility::Call::batch`. This mirrors the Liquity report's core theme — a validation check placed at one call layer that a 3rd-party/nested-dispatch wrapper (here, `utility::batch`) can route around, producing state changes (a security-deposit slash) that the guard was designed to prevent.

### Title
`pallet-recovery::control_inherited_account` filter checks only the outer call, letting `utility::batch` bypass the guard against lower-priority inheritors slashing higher-priority recovery attempts - (File: `substrate/frame/recovery/src/lib.rs`)

### Summary
`pallet-recovery` lets an `inheritor` account act as `ALICE` via `control_inherited_account`, but this power is explicitly restricted so a lower-priority inheritor cannot dismiss (`slash_attempt`) a currently in-progress higher-priority recovery attempt or wipe all friend groups. The restriction is implemented as a filter that pattern-matches the *outer* `RuntimeCall` passed to `control_inherited_account`. Wrapping the very same forbidden call inside `pallet_utility::Call::batch { calls: vec![forbidden_call] }` changes the outer call's shape to `Utility::batch`, passes the filter, and then `Utility::batch` re-dispatches the inner call with the inherited origin, executing the action the filter was meant to block.

### Finding Description
The pallet's own regression tests document the intended invariant and the gap: [1](#0-0) 
shows that a direct `RecoveryCall::slash_attempt` dispatched via `control_inherited_account` is correctly blocked (BOB's deposit is not slashed).

However, the batch-wrapped variant test explicitly documents the bypass condition: [2](#0-1) 
The comment "the batch dispatched as ALICE, but the inner slash should have still executed since our filter only checks the outer call" confirms the filter is a shallow, outer-call-only check that does not inspect nested calls carried inside `pallet_utility::Call::batch`, `batch_all`, `as_derivative`, etc.

This is structurally the same defect class as the Liquity ERC20 issue: a validity/permission check enforced only at the "front door" (the token's own `transfer`/`transferFrom` recipient check, or here, the outer dispatched `RuntimeCall`) is bypassed once a 3rd-party composability primitive (a smart contract calling the token, or here `pallet-utility`'s batch re-dispatch) is interposed between the caller and the guarded logic. The repository's own `pallet-utility` tests confirm that `batch`/`batch_all` re-dispatch inner calls with the *same* origin and that filters added via `add_filter` on that origin are the mechanism meant to stop such nesting (see `batch_all_does_not_nest` at [3](#0-2) ), showing the codebase is aware nested dispatch can strip origin-level restrictions unless explicitly filtered — but `pallet-recovery`'s `control_inherited_account` guard is implemented as a manual match on the call variant rather than as an origin filter, so it does not benefit from that protection and can be routed around via `Utility::batch`.

### Impact Explanation
A malicious or opportunistic inheritor of a *lower-priority* friend group can use `Utility::batch` to slash the security deposit of a friend actively vouching for a *higher-priority* recovery attempt (`RecoveryCall::slash_attempt`), or to wipe out `friend_groups` entirely via `set_friend_groups { friend_groups: vec![] }`. This lets an unprivileged, non-victim actor cause unauthorized state changes (loss of another account's staked/reserved deposit, and destruction of legitimate recovery configuration) that the explicit filter in `control_inherited_account` was designed to prevent — a direct violation of "Public wrappers such as utility ... must not widen origin, bypass filters" from the impact gate, and it results in theft/loss of a friend's reserved balance (the slashed deposit) to the wrong beneficiary.

### Likelihood Explanation
The trigger requires only a signed extrinsic wrapping a single already-known call inside `Utility::batch` — no admin, governance, validator, or off-chain assumptions are needed. The pallet's own test suite (`inheritor_cannot_bypass_filter_via_utility_batch`) exists specifically because this bypass path was identified, indicating it is a known and directly reachable coding gap in the filter's implementation rather than a theoretical concern.

### Recommendation
Move the restriction on `control_inherited_account` from an outer-call pattern match into an origin-level `add_filter` (mirroring `pallet_utility::batch_all`'s nesting guard), or explicitly reject/unwrap `pallet_utility::Call::{batch, batch_all, force_batch}` and `as_derivative`/`dispatch_as` wrappers recursively before applying the existing call-variant checks, so the guard evaluates the terminal dispatched call rather than only the immediate outer call.

/// Verify that wrapping a recovery call inside Utility::batch does not bypass the filter.
#[test]
fn inheritor_cannot_bypass_filter_via_utility_batch() {
	new_test_ext().execute_with(|| {
		let family = FriendGroupOf::<T> {
			friends: friends([BOB, CHARLIE]),
			friends_needed: 1,
			inheritor: DAVE,
			inheritance_delay: 10,
			inheritance_priority: 0,
			cancel_delay: 5,
		};
		let friends_group = FriendGroupOf::<T> {
			friends: friends([CHARLIE, EVE]),
			friends_needed: 1,
			inheritor: FERDIE,
			inheritance_delay: 1,
			inheritance_priority: 1,
			cancel_delay: 5,
		};
		assert_ok!(Recovery::set_friend_groups(signed(ALICE), vec![family, friends_group]));

		// Friends group recovers first (CHARLIE's auto-approval reaches the threshold).
		assert_ok!(Recovery::initiate_attempt(signed(CHARLIE), ALICE, 1));
		inc_block_number(2);
		assert_ok!(Recovery::finish_attempt(signed(EVE), ALICE, 1));
		assert_eq!(Recovery::inheritor(ALICE), Some(FERDIE));

		// Family initiates higher-priority attempt
		assert_ok!(Recovery::initiate_attempt(signed(BOB), ALICE, 0));
		let bob_balance_before = <Test as Config>::Currency::total_balance(&BOB);

		// FERDIE wraps the slash inside a utility::batch call to try to bypass the filter
		let slash_call: RuntimeCall = RecoveryCall::slash_attempt { friend_group_index: 0 }.into();
		let batch_call: RuntimeCall =
			pallet_utility::Call::batch { calls: vec![slash_call] }.into();
		assert_ok!(Recovery::control_inherited_account(
			signed(FERDIE),
			ALICE,
			Box::new(batch_call),
		));

		// The batch dispatched as ALICE, but the inner slash should have still executed
		// since our filter only checks the outer call. Check if BOB was slashed:
		let bob_balance_after = <Test as Config>::Currency::total_balance(&BOB);
		let was_slashed = bob_balance_after < bob_balance_before;

		if was_slashed {
			panic!(
				"BYPASS: recovery call filter was circumvented via utility::batch! \
				 BOB lost {} from security deposit slash.",
				bob_balance_before - bob_balance_after
			);
		}
	});

#[test]
fn batch_all_does_not_nest() {
	new_test_ext().execute_with(|| {
		let batch_all = RuntimeCall::Utility(UtilityCall::batch_all {
			calls: vec![call_transfer(2, 1), call_transfer(2, 1), call_transfer(2, 1)],
		});

		let info = batch_all.get_dispatch_info();

		assert_eq!(Balances::free_balance(1), 10);
		assert_eq!(Balances::free_balance(2), 10);
		// A nested batch_all call will not pass the filter, and fail with `BadOrigin`.
		assert_noop!(
			Utility::batch_all(RuntimeOrigin::signed(1), vec![batch_all.clone()]),
			DispatchErrorWithPostInfo {
				post_info: PostDispatchInfo {
					actual_weight: Some(
						<Test as Config>::WeightInfo::batch_all(1) + info.call_weight
					),
					pays_fee: Pays::Yes
				},
				error: frame_system::Error::<Test>::CallFiltered.into(),
			}
		);

		// And for those who want to get a little fancy, we check that the filter persists across
		// other kinds of dispatch wrapping functions... in this case
		// `batch_all(batch(batch_all(..)))`
		let batch_nested = RuntimeCall::Utility(UtilityCall::batch { calls: vec![batch_all] });
		// Batch will end with `Ok`, but does not actually execute as we can see from the event
		// and balances.
		assert_ok!(Utility::batch_all(RuntimeOrigin::signed(1), vec![batch_nested]));
		System::assert_has_event(
			utility::Event::BatchInterrupted {
				index: 0,
				error: frame_system::Error::<Test>::CallFiltered.into(),
			}
			.into(),
		);
		assert_eq!(Balances::free_balance(1), 10);
		assert_eq!(Balances::free_balance(2), 10);
	});
}
