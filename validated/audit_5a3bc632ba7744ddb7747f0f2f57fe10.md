### Title
Interest accrual can be permanently suppressed by anyone when elapsed interest rounds to zero - (File: contracts/DebtToken.sol)

### Summary
`DebtToken.accrueInterest()` advances `lastTimestampAccrued` unconditionally, even when the computed `_interestAmountAccrued` rounds to zero via `wadMul`. Any unprivileged caller can invoke `accrueInterest()` frequently (once per block), keeping the per-call interest below the rounding threshold so that `debtIndex` and `totalSupply_` never grow while elapsed time is permanently discarded. Debt positions then accrue no interest despite a nonzero `interestRate`.

### Finding Description
In `DebtToken.sol`, `accrueInterest()` is `public` and callable by anyone: [1](#0-0) 

The early return at line 163 only triggers when the timestamp is unchanged. Otherwise `lastTimestampAccrued = block.timestamp` executes at line 167 **before** the `if (_interestAmountAccrued > 0)` guard at line 169 — so a call that computes zero accrued interest still consumes the elapsed time.

The accrual math in `_calculateInterestAccrual`: [2](#0-1) 

`_interestAmountAccrued = _interestRateToAccrue.wadMul(totalSupply_)`, where `wadMul` divides by `1e18` (WadRayMath). Whenever `totalSupply_ * interestRatePerSecond() * deltaT < ~0.5e18`, the result is zero, `debtIndex` stays flat, and `totalSupply_` is unchanged — yet the timestamp moves forward. `balanceOf()` and all debt views derive interest from the stored `lastTimestampAccrued` (lines 196–205), so the unaccrued interval is lost permanently, not deferred.

This is reachable with no privileges: `accrueInterest()` has no modifier beyond being public, is also triggered internally by `issue`/`repay`/etc., and an attacker can simply call it every block. Low-decimal synthetic debt tokens exist in deployed configuration (e.g. `MsBTCDebt` with 8 decimals, `MsDOGEDebt`, `MsOPDebt` in `deployments/`), where the zero-rounding threshold corresponds to a meaningful-but-small debt supply. Example at 2%/yr rate and 12s blocks: `ratePerSecond*dt ≈ 7.6e10`, so any `totalSupply_ < ~6.6e6` raw units (≈0.066 msBTC) accrues zero interest per call. As long as debt stays below the threshold, the attacker can suppress accrual indefinitely for gas cost only.

### Impact Explanation
The debt-growth invariant breaks: borrowers' `balanceOf` never increases while the attack runs, so they borrow interest-free; the feeCollector receives no synthetic interest mints (and `pendingInterestFee` never accumulates since `_interestAmountAccrued` is zero). Positions that should become unhealthy never do, undermining liquidation-driven solvency. This is theft of protocol yield / insolvency impact.

### Likelihood Explanation
Requires only an unprivileged EOA repeatedly calling a public function; no flash loan, oracle manipulation, or privileged role needed. Requires the debt token's `totalSupply_` to be below the rounding threshold — realistically a young/low-TVL pool or a low-decimal debt asset. The attacker must sustain calls each block, so the suppression window depends on how long they keep it up and whether new issuance pushes supply past the threshold (repayments can pull it back under). Impact is bounded by the suppression duration, but each skipped interval's interest is permanently lost rather than deferred.

### Recommendation
Only advance `lastTimestampAccrued` when interest is actually accrued (move the assignment inside the `_interestAmountAccrued > 0` branch), or accumulate the fractional remainder so sub-wei interest carries forward instead of being discarded. Alternatively track a higher-precision ray index and update `debtIndex` from the product rather than gating on rounded token-amount interest.

### Proof of Concept
Hardhat-style sketch (repo's own test scaffolding in `test/DebtToken.test.ts`):

```ts
// setup: deposit collateral, issue a small amount of msBTCDebt (8 decimals)
await msdUSDC.deposit(parseUnits('500', await usdc.decimals()), alice.address)
await msBTCDebt.issue(parseUnits('0.01', 8), alice.address) // totalSupply_ = 1e6
await msBTCDebt.connect(governor).updateInterestRate(parseEther('0.5')) // 50%/yr

const attacker = bob

for (let i = 0; i < 10; i++) {
  await time.increase(12) // one block
  await msBTCDebt.connect(attacker).accrueInterest() // rounds interest to 0, burns the interval
}

// Alice's debt is unchanged despite ~2 minutes elapsed at 50% APR
expect(await msBTCDebt.balanceOf(alice.address)).eq(parseUnits('0.01', 8))
expect(await msBTCDebt.totalSupply()).eq(parseUnits('0.01', 8))
```

Each call computes `_interestRateToAccrue.wadMul(1e6)` which is `< 1` and rounds to zero, while `lastTimestampAccrued` advances (lines 163–171 of `contracts/DebtToken.sol`), so the interest is never recoverable.
