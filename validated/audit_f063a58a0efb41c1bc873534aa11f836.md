### Title
Attacker Can Blind the Load Shedder's Resource Ranking by Spawning Cheap Commands to Evict Expensive Ones from Burden Tracking - (File: internal/burdenmonitor/rpc_entry.go)

### Summary
`RPCEntry` caps the number of concurrently tracked git subprocesses at `maxTrackedCommands` (20) and, when full, evicts the tracked command with the *lowest recorded* CPU usage to make room for a newly spawned one [1](#0-0) . Because CPU usage is only updated by a periodic poller running every 2 seconds [2](#0-1) [3](#0-2) , any command that hasn't yet been polled has `UserTime`/`SystemTime` of zero and is the preferred eviction victim, since `evictCommand` picks strictly the lowest `UserTime+SystemTime` [4](#0-3) .

### Finding Description
This is the same bug class as the reported "low-quality subscription queue DoS": a bounded collection with a naive "evict/reject the worst" heuristic can be gamed by an attacker who controls which entries populate it.

Here, a single accessor RPC (any RPC with `protoregistry.OpAccessor`, tracked whenever `featureflag.BurdenMonitorTrackCommands` is enabled) is registered with the `BurdenMonitor` [5](#0-4) . Every git subprocess it spawns is registered via `NotifyCommandStarted` → `RPCEntry.RegisterCommand` [6](#0-5) .

If a caller can make its single RPC spawn more than 20 subprocesses in quick succession (faster than the 2-second poll interval), each new command starts at zero recorded CPU. Once the cap is hit, `RegisterCommand` calls `evictCommand`, which removes the command with the lowest `UserTime+SystemTime` [7](#0-6) . Any real resource-heavy subprocess that was started but has not yet had a chance to be polled (its recorded time is still 0) is just as likely — or more likely, given ties are resolved by map iteration order — to be evicted as any other zero-usage entry, including genuinely expensive ones. Once evicted, that command's ongoing consumption is invisible to `TotalCPUTime()`/`TotalMemory()` until it eventually completes and calls `MarkCommandCompleted` [8](#0-7) [9](#0-8) .

These per-RPC totals are exactly what the `LoadShedder` uses to decide which in-flight RPCs to cancel under memory/CPU/IO pressure: `LoadShedder.shed` ranks entries with `GetTopNEntries(shedTopN, SortByCPU)`, which sorts by `TotalCPUTime()` [10](#0-9) [11](#0-10) . By flooding its own tracked command slots with a burst of cheap, short-lived subprocesses, an attacker's RPC can suppress its own reported CPU/memory footprint at the exact moment the load shedder queries burden state, reducing the odds that this abusive RPC is selected for cancellation while the host is under PSI/OOM pressure.

### Impact Explanation
This undermines a resource-limiting/DoS-mitigation handler (`LoadShedder`), which is explicitly meant to protect Gitaly under critical CPU/memory/IO pressure by killing the costliest RPCs [12](#0-11) . An unprivileged caller who can trigger many concurrent subprocess spawns within one RPC (e.g., an accessor RPC that fans out into many `git cat-file`/`git rev-parse` invocations) can make its own resource usage appear artificially low to this mechanism, letting the truly abusive RPC survive load-shedding cycles while other tracked RPCs are shed instead — effectively evading the safety valve that exists to prevent host-wide DoS from resource exhaustion.

### Likelihood Explanation
Exploitation requires: (1) `featureflag.BurdenMonitorTrackCommands` enabled, (2) an accessor RPC that legitimately spawns many concurrent git subprocesses (or is otherwise abusable to do so) faster than the 2-second poll tick, and (3) the host concurrently under critical PSI/OOM pressure so `LoadShedder.shed` actually runs. This is a narrower, timing-dependent condition compared to the original report (which required only filling a persistent, always-consulted structure), so likelihood is moderate rather than trivial.

### Recommendation
- Change the eviction heuristic in `evictCommand` to prefer evicting *completed-soon* or *short-lived* commands over commands whose CPU is simply unmeasured (zero due to not yet being polled), e.g., by tracking wall-clock age or by immediately snapshotting stats at registration time via a synchronous `readProcessStats` call instead of waiting for the next poll tick.
- Alternatively, fold a departing (evicted) command's last-known stats into `completedCPUTime`/`completedCount` immediately, and periodically re-poll evicted-but-still-running PIDs out-of-band so their consumption isn't fully invisible to `TotalCPUTime()`/`TotalMemory()` until process exit.
- Consider decoupling `maxTrackedCommands` capacity per RPC from a purely reactive/instantaneous CPU compare, e.g., use exponential decay or highest wall-time as tiebreaker so a rapid burst of near-simultaneous spawns cannot be used to selectively hide a co-located heavy process.

### Proof of Concept
1. Enable `featureflag.BurdenMonitorTrackCommands` and configure a `LoadShedder` with PSI critical thresholds.
2. Send a single accessor RPC that, internally, spawns one long-running/CPU-heavy git subprocess (e.g., a large `git log`/pack operation) followed immediately (within the same 2-second poll window) by 20+ short, cheap git subprocess invocations (e.g., trivial `git rev-parse` calls) so the tracked map fills to `maxTrackedCommands` before any of them are polled.
3. `RegisterCommand` will invoke `evictCommand` repeatedly; because all new entries start with `UserTime=0`, the long-running heavy command (also still at `UserTime=0` if it hasn't been polled yet) can be selected as the eviction victim, per `evictCommand`'s pure lowest-usage-wins comparison [13](#0-12) .
4. While the heavy subprocess continues to consume CPU/memory (untracked), trigger a simulated PSI-critical event and observe via `gitaly_burdenmonitor_commands_evicted_total` and `TotalCPUTime()`/`TotalMemory()` on the RPC's `RPCEntry` that the entry's reported burden does not reflect the still-running heavy subprocess, potentially causing `LoadShedder.shed` to rank/cancel a different, lower-impact RPC instead [14](#0-13) .

// TotalCPUTime returns the sum of user and system CPU time across running commands.
func (e *RPCEntry) TotalCPUTime() time.Duration {
	e.mu.RLock()
	defer e.mu.RUnlock()

	total := e.completedCPUTime
	for _, cmd := range e.Commands {
		total += cmd.UserTime + cmd.SystemTime
	}
	return total
}

// TotalMemory returns the sum of anonymous RSS memory across all commands.
func (e *RPCEntry) TotalMemory() int64 {
	e.mu.RLock()
	defer e.mu.RUnlock()

	var total int64
	for _, cmd := range e.Commands {
		total += cmd.AnonRSS
	}
	return total
}

func (e *RPCEntry) RegisterCommand(pid int, name string, startTime time.Time) {
	e.mu.Lock()
	defer e.mu.Unlock()

	if _, ok := e.Commands[pid]; !ok && len(e.Commands) >= maxTrackedCommands {
		e.evictCommand()
	}

	e.Commands[pid] = &CommandStats{
		Name:      name,
		Pid:       pid,
		StartTime: startTime,
	}
}

// evictCommand removes the tracked command with the lowest CPU consumption.
// Its resource consumption will be added to the aggregate during the
// MarkCommandCompleted call.
func (e *RPCEntry) evictCommand() {
	var victim *CommandStats
	for _, cmd := range e.Commands {
		if victim == nil || cmd.UserTime+cmd.SystemTime < victim.UserTime+victim.SystemTime {
			victim = cmd
		}
	}
	if victim == nil {
		return
	}

	delete(e.Commands, victim.Pid)

	commandsEvictedTotal.WithLabelValues(e.ServiceName, e.MethodName).Inc()
}

func (bm *BurdenMonitor) pollEntryCommands(entry *RPCEntry) {
	entry.mu.Lock()
	defer entry.mu.Unlock()

	for pid, cmd := range entry.Commands {
		stats, err := readProcessStats(pid)
		if err != nil {
			bm.logger.WithFields(log.Fields{
				"pid":   pid,
				"error": err,
			}).DebugContext(entry.Context, "failed to read process stats")
			continue
		}

		cmd.UserTime = stats.UserTime
		cmd.SystemTime = stats.SystemTime
		cmd.WallTime = time.Since(cmd.StartTime)
		cmd.AnonRSS = stats.AnonRSS
	}

func (ls *LoadShedder) shed(ctx context.Context, event loadmonitor.Event) {
	entries := ls.bm.GetTopNEntries(shedTopN, SortByCPU)
	reason := SortByCPU.reason()

	for _, entry := range entries {
		ls.cancel(entry, reason)
	}

	ls.logger.WithFields(log.Fields{
		"condition":    event.ConditionName,
		"reason":       event.Description,
		"sniped_count": len(entries),
	}).WarnContext(ctx, "load shedder cancelled in-flight RPCs")
}

// EntriesSortedBy returns all tracked RPC entries sorted by the specified field.
// The returned entries are sorted in descending order (highest resource usage first).
func (bm *BurdenMonitor) entriesSortedBy(sortBy SortBy) []*RPCEntry {
	entries := bm.Entries()

	switch sortBy {
	case SortByCPU:
		sort.Slice(entries, func(i, j int) bool {
			return entries[i].TotalCPUTime() > entries[j].TotalCPUTime()
		})
	case SortByMemory:
		sort.Slice(entries, func(i, j int) bool {
			return entries[i].TotalMemory() > entries[j].TotalMemory()
		})
	case SortByDuration:
		sort.Slice(entries, func(i, j int) bool {
			return entries[i].StartTime.Before(entries[j].StartTime)
		})
	}

	return entries
}

// GetTopNEntries returns the top N tracked RPC entries sorted by the specified
// field, in descending order. If fewer than N entries exist, the returned slice
// is shorter than N.
func (bm *BurdenMonitor) GetTopNEntries(n int, sortBy SortBy) []*RPCEntry {
	entries := bm.entriesSortedBy(sortBy)
	if len(entries) > n {
		entries = entries[:n]
	}
	return entries
}

func TestRPCEntry_CommandCap(t *testing.T) {
	t.Parallel()

	bm := New(testhelper.SharedLogger(t))
	_, entry := bm.RegisterRPC(testhelper.Context(t), "/foo.Service/Method")

	now := time.Now()
	// Fill the map to the cap with commands of strictly increasing CPU
	// consumption.
	for i := range maxTrackedCommands {
		pid := 1000 + i
		entry.RegisterCommand(pid, "git cat-file", now)
		entry.Commands[pid].UserTime = time.Duration(i+1) * time.Millisecond
	}
	require.Equal(t, maxTrackedCommands, entry.ActiveCommandCount())
	totalBefore := entry.TotalCPUTime()
	evictedBefore := testutil.ToFloat64(commandsEvictedTotal.WithLabelValues("foo.Service", "Method"))

	// Registering one more evicts the lowest-CPU command (pid 1000, 1ms) to
	// make room.
	entry.RegisterCommand(2000, "git rev-list", now)
	require.Equal(t, maxTrackedCommands, entry.ActiveCommandCount())
	require.NotContains(t, entry.Commands, 1000)
	require.Contains(t, entry.Commands, 2000)
	require.Equal(t, evictedBefore+1, testutil.ToFloat64(commandsEvictedTotal.WithLabelValues("foo.Service", "Method")))

	// The evicted command's observed CPU leaves the totals until the command
	// completes.
	require.Equal(t, totalBefore-time.Millisecond, entry.TotalCPUTime())

	// When the evicted command completes, its final consumption — including
	// anything it burned after eviction — is folded into the aggregates.
	entry.MarkCommandCompleted(1000, 5*time.Millisecond, 0)
	require.Equal(t, totalBefore+4*time.Millisecond, entry.TotalCPUTime())

	// Re-registering an already-tracked PID replaces it in place and does not
	// evict.
	entry.RegisterCommand(2000, "git rev-list", now)
	require.Equal(t, maxTrackedCommands, entry.ActiveCommandCount())
	require.Contains(t, entry.Commands, 1001)
	require.Equal(t, evictedBefore+1, testutil.ToFloat64(commandsEvictedTotal.WithLabelValues("foo.Service", "Method")))
}
