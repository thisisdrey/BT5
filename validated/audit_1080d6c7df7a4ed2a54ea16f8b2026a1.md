## Analog Vulnerability Found

### Title
`Wallet.getMarketOrderByAccount` Aborts Entire Market-Order Query When a Single Referenced Order Is Missing - ([File: framework/src/main/java/org/tron/core/Wallet.java])

### Summary
`Wallet.getMarketOrderByAccount` iterates over every order ID stored in an account's `MarketAccountOrderCapsule` and fetches each corresponding `MarketOrderCapsule` from `MarketOrderStore` inside a `forEach` lambda. If the lookup for **any single** order ID throws `ItemNotFoundException`, the handler converts it into an unchecked `IllegalStateException` and rethrows it, which propagates out of the `forEach` and aborts the whole loop — exactly the same failure pattern as the Sherlock report, where a single reverting/exception-throwing element inside a batch-processing loop (`BondAggregator.findMarketFor` → `payoutFor`) causes the entire multi-item scan to fail instead of degrading gracefully.

### Finding Description [1](#0-0) 

```
public MarketOrderList getMarketOrderByAccount(ByteString accountAddress) {
  ...
  orderIdList.forEach(
      orderId -> {
        try {
          MarketOrderCapsule orderCapsule = marketOrderStore.get(orderId.toByteArray());
          ...
        } catch (ItemNotFoundException e) {
          logger.warn("orderId = {} not found", orderId);
          throw new IllegalStateException("order not found in store");
        }
      }
  );
  return marketOrderListBuilder.build();
}
```

The account's list of order IDs is maintained in `MarketAccountOrderCapsule.getOrdersList()` [2](#0-1) , and each ID is expected to resolve via `MarketOrderStore.get` [3](#0-2) . The `forEach` construct provides no way to skip a single failing element — any `ItemNotFoundException` thrown for one order ID in the list is escalated to an `IllegalStateException` that unwinds the entire lambda stream, so none of the account's other, perfectly valid orders are returned; the whole query for that account fails.

This is directly analogous to the reported bug: `BondAggregator.findMarketFor` iterated over market IDs and called `payoutFor`, which could revert for one market, breaking the entire scan across all markets. Here, `getMarketOrderByAccount` iterates over an account's order IDs and calls `marketOrderStore.get`, which can throw for one order, breaking the entire scan across all of that account's orders.

### Impact Explanation
This function is reachable from unauthenticated/unprivileged API surfaces:
- HTTP: `GetMarketOrderByAccountServlet` (`/wallet/getmarketorderbyaccount`, and PBFT/Solidity variants) [4](#0-3) 
- gRPC: `RpcApiService.getMarketOrderByAccount` [5](#0-4) 

Any anonymous client can query any address's market orders. If even one order referenced in that account's order list cannot be resolved from `MarketOrderStore` (e.g., due to data pruning in lite-fullnode/solidity-node history modes, node state divergence, or any other inconsistency), the API becomes permanently unable to serve that account's market-order query — a legitimate "API the node can no longer serve" condition — instead of gracefully omitting the missing order and returning the rest.

### Likelihood Explanation
Triggering requires a scenario where an order ID present in the account's order list is absent from `MarketOrderStore`. Under normal full-node operation, orders are never deleted from `MarketOrderStore` (only their state is updated, e.g., to `CANCELED`/`INACTIVE`), so the condition is not trivially self-inflictable by a single actor under default full-node conditions. It becomes reachable in deployments with partial/pruned state (e.g., lite fullnode, PBFT/solidity read replicas) or any data-consistency edge case, at which point the query becomes unconditionally broken for the affected account, matching the "medium" likelihood bar for a query-path DoS.

### Recommendation
Do not let a single missing/erroring order abort the whole account order list. Replace the `forEach` with an explicit loop (or stream `flatMap`/`filter`) that catches `ItemNotFoundException` per-item, logs it, and skips that order while continuing to build the result for the remaining orders — mirroring the try/catch-based graceful handling adopted in the referenced fix for `BondAggregator.findMarketFor`.

### Proof of Concept
1. Craft or reach a node state where an account's `MarketAccountOrderCapsule` order list contains an order ID that is not resolvable via `MarketOrderStore.get` (e.g., a pruned/lite node, or a data-consistency edge case).
2. Call `GET/POST /wallet/getmarketorderbyaccount` (or the gRPC `getMarketOrderByAccount`) with that account's address.
3. Observe that the request fails entirely (throws), and none of the account's other valid orders are returned, denying the query for that account going forward. [6](#0-5)

  public MarketOrderList getMarketOrderByAccount(ByteString accountAddress) {

    if (accountAddress == null || accountAddress.isEmpty()) {
      return null;
    }

    MarketAccountOrderCapsule marketAccountOrderCapsule;
    try {
      marketAccountOrderCapsule = dbManager.getChainBaseManager()
          .getMarketAccountStore().get(accountAddress.toByteArray());
    } catch (ItemNotFoundException e) {
      return null;
    }

    MarketOrderStore marketOrderStore = dbManager.getChainBaseManager().getMarketOrderStore();

    MarketOrderList.Builder marketOrderListBuilder = MarketOrderList.newBuilder();
    List<ByteString> orderIdList = marketAccountOrderCapsule.getOrdersList();

    orderIdList.forEach(
        orderId -> {
          try {
            MarketOrderCapsule orderCapsule = marketOrderStore.get(orderId.toByteArray());
            // set prev and next, hide these messages in the print
            orderCapsule.setPrev(new byte[0]);
            orderCapsule.setNext(new byte[0]);

            marketOrderListBuilder
                .addOrders(orderCapsule.getInstance());
          } catch (ItemNotFoundException e) {
            logger.warn("orderId = {} not found", orderId);
            throw new IllegalStateException("order not found in store");
          }
        }
    );

    return marketOrderListBuilder.build();
  }
