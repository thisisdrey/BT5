### Title
Per-goroutine conntrack local cache bypasses firewall rule revalidation after ruleset reload - (File: firewall/cache.go, firewall.go)

### Summary
`nebula`'s firewall implements a "revalidate on ruleset change" mechanism: each conntrack entry stores the `rulesVersion` that allowed it, and `Firewall.inConns` re-checks the entry against the *current* ruleset whenever `f.rulesVersion` has advanced since the entry was created [1](#0-0) . However, `inConns` first consults a per-read-routine `localCache` (`firewall.ConntrackCache`) and returns "allowed" immediately on a hit, without ever reaching the `rulesVersion` comparison [2](#0-1) . This local cache is refreshed only on a timer tick (`ConntrackCacheTicker`), independent of firewall reloads [3](#0-2) . This is directly analogous to the referenced bug: an authorization state (endorsed votes / allowed-flow status) is cached and continues to be trusted after the authoritative state it was derived from has been revoked/tightened, because the revocation event does not invalidate the cached value.

### Finding Description
`Firewall.Drop` calls `f.inConns(fp, h, caPool, localCache)` to decide if a packet belongs to an already-permitted flow [4](#0-3) . Inside `inConns`:
1. If `localCache[fp]` exists, the function returns `true` (allow) immediately - no rule check, no `rulesVersion` check [2](#0-1) .
2. Only when there is no local-cache hit does the code fall through to the global `conntrack.Conns` map, where it explicitly detects a stale `rulesVersion` and re-validates the packet against the current rule table, dropping the entry if it no longer matches [5](#0-4) .
3. On success, the packet's tuple is written back into `localCache[fp]` [6](#0-5) .

`localCache` is a `firewall.ConntrackCache` obtained from a `ConntrackCacheTicker` that is created once per reader goroutine in `listenIn`/`listenOut` and only cleared when a background ticker fires (interval controlled by `conntrackCacheTimeout`) [7](#0-6) [8](#0-7) . Critically, this cache clearing is **not** tied to `Interface.reloadFirewall`, which is the function that bumps `rulesVersion` when the firewall config (or the certificate's `UnsafeNetworks`) changes [9](#0-8) .

The consequence: once a flow tuple is written into a goroutine's `localCache`, that goroutine will keep allowing packets for that exact tuple until its own ticker fires, completely bypassing the "must revalidate against the new ruleset" logic that the global-conntrack path enforces. This mirrors the referenced report precisely — a cached "authorized" state (`totalEndorsementsForProposal` / here, "flow is allowed") is not decremented/invalidated when the authoritative source of truth (`VOTES` balance / here, firewall `rulesVersion`) changes due to an administrative revocation action (`revokeVotesFrom` / here, a firewall reload that tightens or removes a rule).

### Impact Explanation
An operator tightening firewall rules via SIGHUP (e.g., removing a previously-allowed port/host rule, in direct response to detecting misuse) expects existing flows to be re-evaluated against the new rules, per the documented behavior in the changelog ("we will maintain the [conntrack] table and just validate that an entry still matches with the new rule set") [10](#0-9) . Because of the local-cache short-circuit, packets for flows that are already cached in a given reader goroutine's `localCache` will continue to be forwarded/accepted for up to one `conntrackCacheTimeout` interval after the reload, even though the new ruleset would reject them. This is a firewall-enforcement bypass: traffic that should be dropped under the newly-installed policy is still passed, undermining the security guarantee that a firewall reload immediately re-secures the tunnel.

### Likelihood Explanation
This requires no cryptographic bypass — it triggers deterministically any time an operator reloads/tightens the firewall configuration while active flows exist that were permitted under the old ruleset and are being processed by a reader goroutine holding a populated `localCache`. The window of exposure is bounded by `conntrackCacheTimeout`, but during that window the bypass is fully reliable and requires no attacker timing tricks — the vulnerable path (`localCache[fp]` short-circuit) is hit on every packet belonging to an already-cached tuple.

### Recommendation
Tie invalidation of the per-goroutine `localCache` to firewall rule changes, not just to the timer tick. For example, have `ConntrackCacheTicker`/`ConntrackCache` also record (or receive) the `rulesVersion` it was populated under, and treat a `rulesVersion` mismatch the same way `Get()` treats a tick mismatch — resetting the map. Alternatively, remove the local-cache fast path entirely for the case where `c.rulesVersion != f.rulesVersion`, forcing every `inConns` call to consult the global conntrack table (and thus the revalidation logic) at least once per firewall reload.

### Proof of Concept
1. Start an interface with a firewall rule allowing `udp/90` from a peer, and let a flow (tuple `fp`) pass through `Firewall.Drop` with a non-nil `localCache`; this both conntracks `fp` in the global table and inserts it into `localCache` per lines 573-575 of `firewall.go`.
2. Trigger a config reload (`reloadFirewall`) with a new ruleset that no longer allows `udp/90`; this increments `f.rulesVersion` and swaps `f.firewall` per `interface.go` lines 402-426.
3. Continue sending packets matching `fp` on the same reader goroutine before its `conntrackCacheTimeout` ticks. `inConns` hits `localCache[fp]` at line 507 of `firewall.go` and returns `true` immediately — the packet is allowed even though `TestFirewall_DropConntrackReload`-style logic (lines 667-729 of `firewall_test.go`) shows that, absent the local cache, the same tuple would correctly be dropped once `rulesVersion` diverges and the new table no longer matches.

```go
func (f *Firewall) inConns(fp firewall.Packet, h *HostInfo, caPool *cert.CAPool, localCache firewall.ConntrackCache) bool {
	if localCache != nil {
		if _, ok := localCache[fp]; ok {
			return true
		}
	}
	conntrack := f.Conntrack
	conntrack.Lock()

	// Purge every time we test
	ep, has := conntrack.TimerWheel.Purge()
	if has {
		f.evict(ep)
	}

	c, ok := conntrack.Conns[fp]

	if !ok {
		conntrack.Unlock()
		return false
	}

	if c.rulesVersion != f.rulesVersion {
		// This conntrack entry was for an older rule set, validate
		// it still passes with the current rule set
		table := f.OutRules
		if c.incoming {
			table = f.InRules
		}

		// We now know which firewall table to check against
		if !table.match(fp, c.incoming, h.ConnectionState.peerCert, caPool) {
			if f.l.Enabled(context.Background(), slog.LevelDebug) {
				h.logger(f.l).Debug("dropping old conntrack entry, does not match new ruleset",
					"fwPacket", fp,
					"incoming", c.incoming,
					"rulesVersion", f.rulesVersion,
					"oldRulesVersion", c.rulesVersion,
				)
			}
			delete(conntrack.Conns, fp)
			conntrack.Unlock()
			return false
		}

		if f.l.Enabled(context.Background(), slog.LevelDebug) {
			h.logger(f.l).Debug("keeping old conntrack entry, does match new ruleset",
				"fwPacket", fp,
				"incoming", c.incoming,
				"rulesVersion", f.rulesVersion,
				"oldRulesVersion", c.rulesVersion,
			)
		}

		c.rulesVersion = f.rulesVersion
	}
```

```go
type ConntrackCacheTicker struct {
	cacheV    uint64
	cacheTick atomic.Uint64

	l     *slog.Logger
	cache ConntrackCache
}

func NewConntrackCacheTicker(ctx context.Context, l *slog.Logger, d time.Duration) *ConntrackCacheTicker {
	if d == 0 {
		return nil
	}

	c := &ConntrackCacheTicker{
		l:     l,
		cache: ConntrackCache{},
	}

	go c.tick(ctx, d)

	return c
}

func (c *ConntrackCacheTicker) tick(ctx context.Context, d time.Duration) {
	t := time.NewTicker(d)
	defer t.Stop()
	for {
		select {
		case <-ctx.Done():
			return
		case <-t.C:
			c.cacheTick.Add(1)
		}
	}
}
```

```go
// Get checks if the cache ticker has moved to the next version before returning
// the map. If it has moved, we reset the map.
func (c *ConntrackCacheTicker) Get() ConntrackCache {
	if c == nil {
		return nil
	}
	if tick := c.cacheTick.Load(); tick != c.cacheV {
		c.cacheV = tick
		if ll := len(c.cache); ll > 0 {
			if c.l.Enabled(context.Background(), slog.LevelDebug) {
				c.l.Debug("resetting conntrack cache", "len", ll)
			}
			c.cache = make(ConntrackCache, ll)
		}
	}

	return c.cache
}
```

```go
func (f *Interface) reloadFirewall(c *config.C) {
	cs := f.pki.getCertState()
	curCert := cs.getCertificate(cert.Version2)
	if curCert == nil {
		curCert = cs.getCertificate(cert.Version1)
	}

	// The firewall builds its routableNetworks set from the certificate's UnsafeNetworks at construction.
	// Check to see if that set has changed, and if so, rebuild the firewall.
	certUnsafeChanged := curCert != nil && !slices.Equal(curCert.UnsafeNetworks(), f.firewall.unsafeNetworks)

	if !c.HasChanged("firewall") && !certUnsafeChanged {
		f.l.Debug("No firewall config change detected")
		return
	}

	fw, err := NewFirewallFromConfig(f.l, cs, c)
	if err != nil {
		f.l.Error("Error while creating firewall during reload", "error", err)
		return
	}

	oldFw := f.firewall
	conntrack := oldFw.Conntrack
	conntrack.Lock()
	defer conntrack.Unlock()

	fw.rulesVersion = oldFw.rulesVersion + 1
	// If rulesVersion is back to zero, we have wrapped all the way around. Be
	// safe and just reset conntrack in this case.
	if fw.rulesVersion == 0 {
		f.l.Warn("firewall rulesVersion has overflowed, resetting conntrack",
			"firewallHashes", fw.GetRuleHashes(),
			"oldFirewallHashes", oldFw.GetRuleHashes(),
			"rulesVersion", fw.rulesVersion,
		)
	} else {
		fw.Conntrack = conntrack
	}

	f.firewall = fw

	oldFw.Destroy()
	f.l.Info("New firewall has been installed",
		"firewallHashes", fw.GetRuleHashes(),
		"oldFirewallHashes", oldFw.GetRuleHashes(),
		"rulesVersion", fw.rulesVersion,
	)
}
```
