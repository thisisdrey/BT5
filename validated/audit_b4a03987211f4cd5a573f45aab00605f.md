Based on the investigation, the Go standard library's multipart parser does not share the vulnerable primitive described in the BentoML advisory.

The BentoML issue is about a Gradio-embedded HTTP endpoint that reprocesses an attacker-controlled multipart boundary character-by-character without bound, causing unbounded CPU/resource consumption on trailing dash characters appended to the boundary. The closest analog surface in this repo is `mime/multipart`'s boundary matching, exposed to untrusted input via `net/http`'s `Request.multipartReader` → `multipart.NewReader`.

However, this code path is explicitly hardened against exactly this class of boundary-manipulation issue:

- `scanUntilBoundary` and `matchAfterPrefix` in `src/mime/multipart/multipart.go` implement bounded, single-pass byte scanning over a fixed-size peek buffer (`peekBufferSize`), not unbounded character-by-character reprocessing. [1](#0-0) [2](#0-1) 
- The reader is built with a fixed peek buffer size regardless of boundary length or trailing dash manipulation. [3](#0-2) 
- Header parsing (`populateHeaders`) is explicitly bounded by `maxMIMEHeaderSize` and `maxMIMEHeaders` parameters, returning `ErrMessageTooLarge` on excess, which is the direct analog defense against the kind of unbounded resource consumption the BentoML report describes. [4](#0-3) 
- There is dedicated regression test coverage for pathological boundary edge cases (issues 10616, 12662, 46042 in the test data) confirming these code paths were specifically hardened against boundary-matching degenerate inputs, not left as an open resource-exhaustion vector. [5](#0-4) [6](#0-5) 
- `net/http`'s entry point `multipartReader` only constructs the reader after validating the `Content-Type` via `mime.ParseMediaType` and extracting a `boundary` parameter that is passed as-is into the bounded reader — no unbounded or reflective reprocessing occurs at this layer either. [7](#0-6) 

Per the rules (reject generic/unbounded-memory resource exhaustion claims and already-mitigated bug classes), this does not qualify as a concrete, reproducible analog — the Go implementation's bounded-buffer scanning and explicit header-size/count caps are a materially different (and already-defended) design compared to the BentoML boundary-reprocessing bug.

### No vulnerability found for this question.

func scanUntilBoundary(buf, dashBoundary, nlDashBoundary []byte, total int64, readErr error) (int, error) {
	if total == 0 {
		// At beginning of body, allow dashBoundary.
		if bytes.HasPrefix(buf, dashBoundary) {
			switch matchAfterPrefix(buf, dashBoundary, readErr) {
			case -1:
				return len(dashBoundary), nil
			case 0:
				return 0, nil
			case +1:
				return 0, io.EOF
			}
		}
		if bytes.HasPrefix(dashBoundary, buf) {
			return 0, readErr
		}
	}

	// Search for "\n--boundary".
	if i := bytes.Index(buf, nlDashBoundary); i >= 0 {
		switch matchAfterPrefix(buf[i:], nlDashBoundary, readErr) {
		case -1:
			return i + len(nlDashBoundary), nil
		case 0:
			return i, nil
		case +1:
			return i, io.EOF
		}
	}
	if bytes.HasPrefix(nlDashBoundary, buf) {
		return 0, readErr
	}

	// Otherwise, anything up to the final \n is not part of the boundary
	// and so must be part of the body.
	// Also if the section from the final \n onward is not a prefix of the boundary,
	// it too must be part of the body.
	i := bytes.LastIndexByte(buf, nlDashBoundary[0])
	if i >= 0 && bytes.HasPrefix(nlDashBoundary, buf[i:]) {
		return i, nil
	}
	return len(buf), readErr
}

func matchAfterPrefix(buf, prefix []byte, readErr error) int {
	if len(buf) == len(prefix) {
		if readErr != nil {
			return +1
		}
		return 0
	}
	c := buf[len(prefix)]

	if c == ' ' || c == '\t' || c == '\r' || c == '\n' {
		return +1
	}

	// Try to detect boundaryDash
	if c == '-' {
		if len(buf) == len(prefix)+1 {
			if readErr != nil {
				// Prefix + "-" does not match
				return -1
			}
			return 0
		}
		if buf[len(prefix)+1] == '-' {
			return +1
		}
	}

	return -1
}

func (r *Request) multipartReader(allowMixed bool) (*multipart.Reader, error) {
	v := r.Header.Get("Content-Type")
	if v == "" {
		return nil, ErrNotMultipart
	}
	if r.Body == nil {
		return nil, errors.New("missing form body")
	}
	d, params, err := mime.ParseMediaType(v)
	if err != nil || !(d == "multipart/form-data" || allowMixed && d == "multipart/mixed") {
		return nil, ErrNotMultipart
	}
	boundary, ok := params["boundary"]
	if !ok {
		return nil, ErrMissingBoundary
	}
	return multipart.NewReader(r.Body, boundary), nil
}
