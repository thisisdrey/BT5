### Title
Null pointer dereference in `TransactionTrace.checkIsConstant()` via malformed `TriggerSmartContract` parameter - (File: `chainbase/src/main/java/org/tron/core/db/TransactionTrace.java`)

### Summary
`ContractCapsule.getTriggerContractFromTransaction()` returns `null` whenever `Any.unpack(TriggerSmartContract.class)` throws `InvalidProtocolBufferException` on a transaction's raw contract parameter [1](#0-0) . Most callers of this helper (e.g. `VMActuator.call()`) correctly null-check the result before use [2](#0-1) , but `TransactionTrace.checkIsConstant()` does not, dereferencing the possibly-null `triggerContractFromTransaction` immediately [3](#0-2) . This mirrors the llama.cpp `gguf_init_from_file` bug class: a parser that can legitimately return a "no data"/null result on malformed untrusted input, followed by an unchecked dereference elsewhere in the code path.

### Finding Description
`checkIsConstant()` is only skipped when `dynamicPropertiesStore.getAllowTvmConstantinople() == 1`; otherwise it unconditionally calls `ContractCapsule.getTriggerContractFromTransaction(this.getTrx().getInstance())` and, if the transaction's contract type is `TriggerSmartContract`, immediately calls `triggerContractFromTransaction.getContractAddress().toByteArray()` without checking for `null` [3](#0-2) .

`getTriggerContractFromTransaction` unpacks the `Any` parameter of `contract(0)` into `TriggerSmartContract` and swallows `InvalidProtocolBufferException` by returning `null`: [1](#0-0) 

Since `Transaction.Contract.parameter` is a protobuf `Any` whose raw bytes are attacker-controlled at the wire level, and the outer `contract.getType()` enum used by `TransactionTrace`'s constructor to pick `trxType = TRX_CONTRACT_CALL_TYPE` is a separate field from the packed bytes, it is possible to craft a transaction where:
- `Transaction.Contract.type == TriggerSmartContract` (so `TransactionTrace` selects `TRX_CONTRACT_CALL_TYPE`) [4](#0-3) 
- the `Any.value` bytes are not a well-formed `TriggerSmartContract` message (e.g. malformed length-delimited/varint field), causing `unpack()` to throw `InvalidProtocolBufferException` and `getTriggerContractFromTransaction` to return `null`.

When `checkIsConstant()` subsequently runs on such a transaction, `triggerContractFromTransaction` is `null` and `.getContractAddress()` throws an unhandled `NullPointerException`. Unlike `VMActuator.call()`, which defensively returns when `contract == null` [2](#0-1) , `TransactionTrace.checkIsConstant()` has no such guard.

### Impact Explanation
`checkIsConstant()` is invoked from `Manager.java` (confirmed via 2 references), which handles transaction/block processing. An unhandled `NullPointerException` thrown from this path during transaction validation/processing on a broadcast (or block-included) transaction can crash the processing thread or halt block application, denying the node's ability to keep serving/validating transactions — a node crash/halt impact reachable by an unprivileged transaction broadcaster, consistent with the "node crash or halt" acceptance criterion.

### Likelihood Explanation
Likelihood is High for any actor able to submit a raw transaction: constructing a `Transaction.Contract` with `type = TriggerSmartContract` but a non-conforming `Any.value` payload requires only building the transaction protobuf manually (bypassing the normal SDK/servlet flows that build a valid `TriggerSmartContract` message via `Any.pack`). No special privilege, node control, or SR/witness role is needed — only the ability to submit a signed transaction (or object) that reaches transaction processing/`checkIsConstant()`.

### Recommendation
Add a null check on the result of `ContractCapsule.getTriggerContractFromTransaction(...)` in `TransactionTrace.checkIsConstant()`, mirroring the guard already used in `VMActuator.call()`, and throw `ContractValidateException` (rather than allowing an NPE) when the parameter cannot be unpacked as `TriggerSmartContract`.

### Proof of Concept
1. Construct a `Transaction.raw` with a single `Transaction.Contract` where `type = TriggerSmartContract`.
2. Set `parameter` to an `Any` whose `type_url` matches `TriggerSmartContract` but whose `value` bytes are deliberately malformed (e.g., a truncated/invalid length-delimited sub-message field) so that `Any.unpack(TriggerSmartContract.class)` throws `InvalidProtocolBufferException`.
3. Sign and broadcast this transaction to a java-tron node.
4. During transaction processing, `TransactionTrace` is constructed (selecting `TRX_CONTRACT_CALL_TYPE` from the outer `type` field) and `checkIsConstant()` is invoked; `ContractCapsule.getTriggerContractFromTransaction` returns `null` due to the parse failure, and the subsequent `triggerContractFromTransaction.getContractAddress()` call throws an unhandled `NullPointerException`, crashing/halting the processing path.
