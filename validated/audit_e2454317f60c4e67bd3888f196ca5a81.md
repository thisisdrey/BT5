### Title
StackerDB `write-freq` rate limit is enforced only on peer-sync fetches, not on direct/HTTP chunk writes - ([File: stackslib/src/net/stackerdb/db.rs])

### Summary
The Oracle report's bug class is a designed timing/window protection that can be bypassed because it is only enforced along one code path (or, in Oracle's case, at a boundary edge). The analogous fault here is that the StackerDB `write-freq` throttle — the contract-configured minimum interval between writes to a slot — is checked only when a node decides whether to *pull* a chunk during peer-to-peer sync, but is never checked in the function that actually performs the write (`try_replace_chunk`), which is reachable directly and unauthenticated-rate-wise via the `POST /v2/stackerdb/:principal/:contract/chunks` RPC endpoint.

### Finding Description
`StackerDBSync::sync_chunks` throttles chunk *fetches* based on `write_freq`: it skips requesting a chunk if `write_ts + self.write_freq > now` [1](#0-0) . This is the only place in the codebase that consults `write_freq` at write time.

The actual storage/write gate, `StackerDBs::try_replace_chunk` (called both from the sync-relay path in `relay.rs` and from the direct HTTP write path in `poststackerdbchunk.rs`), only checks: chunk size against `config.chunk_size`, that the slot signer's signature verifies, that the supplied version is strictly greater than the stored version, and that the version does not exceed `config.max_writes` — it never checks `config.write_freq` at all [2](#0-1) .

Similarly, `PeerNetwork::validate_received_chunk`, which gates unsolicited `StackerDBPushChunk` p2p messages and downloaded sync chunks, checks chunk size, expected version, signer, staleness, and `max_writes` — but likewise never checks `write_freq` [3](#0-2) .

The `RPCPostStackerDBChunkRequestHandler::try_handle_request` HTTP handler for `POST /v2/stackerdb/.../chunks` calls `tx.try_replace_chunk(...)` directly, with no write-frequency check anywhere in the handler [4](#0-3) . Because `try_replace_chunk` only enforces monotonic version increase and `max_writes`, a legitimate slot owner (who holds the valid signing key for that slot, as is required to write at all) can submit a rapid sequence of chunks with strictly increasing `slot_version` values directly to any replica's HTTP endpoint, bypassing the `write_freq` interval entirely — as long as they stay under `max_writes`.

This breaks the equality the design intends: "a slot may be updated no more often than once every `write_freq` seconds" vs. what is actually enforced: "a slot may be updated up to `max_writes` times with monotonically increasing versions, at any rate," on the write (store) path. The `write_freq` check that does exist only throttles a *puller's* request cadence during eventual-consistency sync, not the authoritative write itself — exactly the pattern in the report where a protection mechanism exists on paper but a different, reachable path circumvents it.

### Impact Explanation
This allows a valid slot signer (e.g., a signer or miner with a legitimately-issued StackerDB slot) to flood a replica — and, through automatic relay of accepted chunks (`node.set_relay_message(StacksMessageType::StackerDBPushChunk(...))` in the HTTP handler, and `self.p2p.broadcast_message(...)` in `relay.rs`) — flood the entire StackerDB network with chunk writes/broadcasts at a much higher rate than the smart contract's `write-freq` was designed to permit [5](#0-4) . Since `write-freq` is meant to bound per-slot write/propagation rate (a resource-consumption and freshness-consistency control), bypassing it enables a bounded-but-amplified compute/bandwidth DoS on StackerDB replicas and the associated relay/broadcast machinery, up to `max_writes` versions, without needing any secret beyond the signer's own already-authorized key. This matches the "bounded compute DoS on a read/propagation endpoint" impact class, since accepted-chunk writes are unconditionally re-broadcast to peers regardless of how quickly they arrive.

### Likelihood Explanation
Any account already holding a valid StackerDB slot signing key (e.g., a registered signer) can exploit this with no additional privilege — they only need to issue HTTP POSTs faster than `write_freq` intends, incrementing `slot_version` each time, up to `max_writes`. No manipulation of oracles, no timing race, and no protocol-level trickery is required; it is a straightforward path-inconsistency bug that any legitimate writer can trigger simply by not going through the (throttled) sync-fetch path.

### Recommendation
Enforce `config.write_freq` inside `StackerDBs::try_replace_chunk` (and/or `PeerNetwork::validate_received_chunk`) by comparing the new write's timestamp against the slot's `write_time` recorded in `SlotValidation`, rejecting writes that arrive before `write_time + write_freq` has elapsed, mirroring the check already present in `StackerDBSync::sync_chunks`. This closes the gap between the fetch-throttle and the actual storage gate so the two paths enforce the same invariant.

### Proof of Concept
1. Register/obtain a valid signing key for a StackerDB slot governed by a contract with `write-freq` set to, e.g., 600 seconds.
2. Repeatedly call `POST /v2/stackerdb/<addr>/<contract>/chunks` with a signed `StackerDBChunkData` whose `slot_version` strictly increases each time (version 1, 2, 3, ... up to `max_writes`), sending requests back-to-back with no delay.
3. Observe that `try_replace_chunk` in `stackslib/src/net/stackerdb/db.rs` accepts every write (since it only checks version monotonicity, signature validity, chunk size, and `max_writes`), and each accepted write is relayed/broadcast to the network, all without any enforcement of the `write_freq` interval that the controlling smart contract stipulated.

    /// Add or replace a chunk for a given reward cycle, if it is valid
    /// Otherwise, this errors out with Error::StaleChunk
    pub fn try_replace_chunk(
        &self,
        smart_contract: &QualifiedContractIdentifier,
        slot_desc: &SlotMetadata,
        chunk: &[u8],
    ) -> Result<(), net_error> {
        // Check per-replica chunk-size cap.
        if (chunk.len() as u64) > self.config.chunk_size {
            return Err(net_error::StackerDBChunkTooBig(chunk.len()));
        }

        let slot_validation = self
            .get_slot_validation(smart_contract, slot_desc.slot_id)?
            .ok_or(net_error::NoSuchSlot(
                smart_contract.clone(),
                slot_desc.slot_id,
            ))?;

        if !slot_desc.verify(&slot_validation.signer)? {
            return Err(net_error::BadSlotSigner(
                slot_validation.signer,
                slot_desc.slot_id,
            ));
        }
        if slot_desc.slot_version <= slot_validation.version {
            return Err(net_error::StaleChunk {
                supplied_version: slot_desc.slot_version,
                latest_version: slot_validation.version,
            });
        }
        if slot_desc.slot_version > self.config.max_writes {
            return Err(net_error::TooManySlotWrites {
                supplied_version: slot_desc.slot_version,
                latest_version: slot_validation.version,
                max_writes: self.config.max_writes,
            });
        }
        self.insert_chunk(smart_contract, slot_desc, chunk)
    }

    pub fn validate_received_chunk(
        &self,
        smart_contract_id: &QualifiedContractIdentifier,
        config: &StackerDBConfig,
        data: &StackerDBChunkData,
        expected_versions: &[u32],
    ) -> Result<bool, net_error> {
        // validate -- must not exceed this replica's configured chunk size.
        if (data.data.len() as u64) > config.chunk_size {
            info!(
                "Received StackerDBChunk for {} ID {}, which is oversized: {} bytes (max {} bytes)",
                smart_contract_id,
                data.slot_id,
                data.data.len(),
                config.chunk_size
            );
            return Ok(false);
        }

        // validate -- must be a valid chunk
        let Some(expected_version) = expected_versions.get(data.slot_id as usize) else {
            info!(
                "Received StackerDBChunk for {} ID {}, which is too big ({})",
                smart_contract_id,
                data.slot_id,
                expected_versions.len()
            );
            return Ok(false);
        };

        // validate -- must be signed by the expected author
        let addr = match self
            .stackerdbs
            .get_slot_signer(smart_contract_id, data.slot_id)?
        {
            Some(addr) => addr,
            None => {
                return Ok(false);
            }
        };

        let slot_metadata = data.get_slot_metadata();
        if !slot_metadata.verify(&addr)? {
            info!(
                "StackerDBChunk for {} ID {} is not signed by {}",
                smart_contract_id, data.slot_id, &addr
            );
            return Ok(false);
        }

        // validate -- must be the current or newer version
        if data.slot_version < *expected_version {
            info!(
                "Received StackerDBChunk for {} ID {} version {}, which is stale (expected {})",
                smart_contract_id, data.slot_id, data.slot_version, *expected_version
            );
            return Ok(false);
        }

        // validate -- must not exceed max writes
        if data.slot_version > config.max_writes {
            info!(
                "Write count exceeded for StackerDBChunk for {} ID {} version {} (max is {})",
                smart_contract_id, data.slot_id, data.slot_version, config.max_writes
            );
            return Ok(false);
        }

        Ok(true)
    }

                    // Classify the rejection directly from the error. `StaleChunk` is the

                    // else is terminal for an identical chunk. Anything unexpected (DB or

                        NetError::StaleChunk { .. } => StackerDBErrorCodes::DataAlreadyExists,
                        NetError::NoSuchSlot(..) => StackerDBErrorCodes::NoSuchSlot,
                        NetError::BadSlotSigner(..) | NetError::VerifyingError(..) => {
                            StackerDBErrorCodes::BadSigner
                        }
                        NetError::StackerDBChunkTooBig(..) => StackerDBErrorCodes::ChunkTooBig,
                        NetError::TooManySlotWrites { .. } => {
                            StackerDBErrorCodes::TooManySlotWrites
                        }
                        _ => {
                            error!("Failed to replace StackerDB chunk with an unexpected error";
                                   "smart_contract_id" => contract_identifier.to_string(),
                                   "error" => format!("{:?}", &e)
                            );
                            return Err(StacksHttpResponse::new_error(
                                &preamble,
                                &HttpServerError::new(format!(
                                    "Failed to store StackerDB chunk for {}: {:?}",
                                    &contract_identifier, &e
                                )),
                            ));
                        }
                    };

                    // Load the current slot metadata to populate the ack for the client.
                    let slot_metadata_opt =
                        match tx.get_slot_metadata(&contract_identifier, stackerdb_chunk.slot_id) {
                            Ok(slot_opt) => slot_opt,
                            Err(e) => {
                                // some other error
                                error!("Failed to load replaced StackerDB chunk metadata";
                                       "smart_contract_id" => contract_identifier.to_string(),
                                       "error" => format!("{:?}", &e)
                                );
                                return Err(StacksHttpResponse::new_error(
                                    &preamble,
                                    &HttpServerError::new(format!(
                                        "Failed to load StackerDB chunk for {}: {:?}",
                                        &contract_identifier, &e
                                    )),
                                ));
                            }
                        };

                    let reason = serde_json::to_string(&err_code.clone().into_json())
                        .unwrap_or("(unable to encode JSON)".to_string());

                    let ack = StackerDBChunkAckData {
                        accepted: false,
                        reason: Some(reason),
                        metadata: slot_metadata_opt,
                        code: Some(err_code.code()),
                    };

                }
