### Title
Object-directory quarantine validation bypass via "quarantine"-named path exclusion - ([File: internal/git/localrepo/paths.go])

### Summary
`Repo.ObjectDirectoryPath` grants an unconditional exemption from its per-repository quarantine ownership check whenever the caller-supplied `GitObjectDirectory` merely *looks like* a transaction quarantine path (its base name is literally `quarantine`, or its parent is `quarantine` and it starts with `tmp_objdir`). Because `GitObjectDirectory`/`GitAlternateObjectDirectories` are ordinary fields on the public `Repository` proto message that any RPC caller can set, an attacker can trivially satisfy this naming exclusion and skip the check that verifies the object directory actually belongs to their own repository — directly analogous to the reported governance bug where an exclusion condition ("does the action target governance itself?") could be trivially satisfied to bypass the veto's core security guarantee.

### Finding Description
`ObjectDirectoryPath` first performs a storage-wide traversal check with `storage.ValidateRelativePath(storagePath, filepath.Join(repoPath, objectDirectoryPath))`, which only guarantees the resulting path stays *somewhere inside the storage root* — not that it belongs to the specific repository being operated on: [1](#0-0) 

It then computes an exclusion flag based purely on the path's naming shape: [2](#0-1) 

If that exclusion is true, the function skips the stricter check entirely — the one that would otherwise ensure the object directory is either (a) actually inside the repository's own path, or (b) inside the storage's temp directory under a prefix keyed to this specific repository's relative path (`storage.QuarantineDirectoryPrefix(repo)`, a SHA-1 of the repo's relative path): [3](#0-2) 

The exclusion condition is:
```go
isTransactionQuarantineDir := (baseDir == "quarantine") || ((parentDir == "quarantine") && strings.HasPrefix(baseDir, "tmp_objdir"))
```
This is meant to recognize object directories created internally by the transaction manager's own quarantine mechanism, but it is based only on string matching against the last one or two path components — a property fully controlled by the RPC caller via the `git_object_directory` field of the `Repository` message: [4](#0-3) 

Any caller of an RPC that accepts a `Repository` (e.g. `GetObjectDirectorySize`, or any RPC using `s.localRepoFactory.Build(repository)` with an attacker-supplied `GitObjectDirectory`) can set `git_object_directory` to a path such as `../some-other-repo.git/quarantine` or `foo/quarantine` (anything within the storage root whose final component is literally `quarantine`). This satisfies `isTransactionQuarantineDir`, so the per-repository ownership check (which would otherwise reject a directory that doesn't match this repository's `QuarantineDirectoryPrefix`) is never executed. The resulting `fullPath` is then used directly for filesystem walks/size calculation and, more critically, in other consumers such as `customHooksEnv`, is exported as `GIT_OBJECT_DIRECTORY`/`GIT_ALTERNATE_OBJECT_DIRECTORIES` for Git subprocess invocations: [5](#0-4) 

This mirrors the vetoed-proposal bug class exactly: a supposedly protective check ("verify the quarantine directory belongs to this repository") is bypassed simply by making the attacker-controlled input match a narrow, easily forgeable exclusion pattern (a path segment literally named `quarantine`), defeating the purpose of the check for any input that trivially satisfies it.

### Impact Explanation
An attacker-controlled `GitObjectDirectory`/`GitAlternateObjectDirectories` value that merely ends in a `quarantine` component bypasses Gitaly's cross-repository object-directory ownership verification. Combined with `GetObjectDirectorySize`, `size.go`'s use of `repo.ObjectDirectoryPath`, and consumers that feed the resolved path into `GIT_OBJECT_DIRECTORY`/`GIT_ALTERNATE_OBJECT_DIRECTORIES` for spawned Git processes, this enables cross-repository object access: pointing a repository's "object directory" at another repository's (or an arbitrary storage-resident) directory happening to be named/rooted in `quarantine`, and having Git operations executed against that foreign directory's content on behalf of the wrong repository, without ever being verified as belonging to the requesting repository. This is a concrete storage-boundary escape within a single storage (crossing repository boundaries), not merely a filesystem-root escape.

### Likelihood Explanation
Reachable from any client that can issue a Gitaly RPC accepting a `Repository` message with `git_object_directory`/`git_alternate_object_directories` set (a normal, documented, non-privileged proto field), such as `GetObjectDirectorySize`. Constructing a path whose final component is `quarantine` (or `tmp_objdir*` under a `quarantine` parent) is trivial for any caller and requires no privileged access, no compromised token, and no race condition — it is a straightforward crafted-field attack against `ValidateRepository`/`ObjectDirectoryPath`.

### Recommendation
Do not rely on filename/parent-name pattern matching (`baseDir == "quarantine"`, `tmp_objdir` prefix) to exempt a caller-supplied object directory from the per-repository ownership check. Instead, always validate ownership either by (a) requiring the object directory to reside inside the repository's own path, or (b) requiring it reside under the storage temp directory with the exact `QuarantineDirectoryPrefix(repo)` computed for the current repository — with no naming-based bypass branch. If transaction-manager-created quarantine directories need a fast path, identify them by an authoritative source (e.g., cross-checked against the active transaction's own recorded quarantine directory) rather than by string pattern matching against attacker-controlled input.

### Proof of Concept
1. As an ordinary RPC caller, invoke `GetObjectDirectorySize` (or any RPC path exercising `Repo.ObjectDirectoryPath`) against a valid, accessible `Repository{storage_name, relative_path}`.
2. Set `git_object_directory` to a relative path that stays within the storage root but points outside the target repository and whose final path component is literally `quarantine`, e.g. `"../victim-repo.git/quarantine"` (or any storage-resident directory ending in `quarantine`).
3. `ObjectDirectoryPath` passes the storage-wide `ValidateRelativePath` check (path stays in storage root) and sets `isTransactionQuarantineDir = true` because `baseDir == "quarantine"`, skipping the block at `internal/git/localrepo/paths.go:53-75` that would otherwise require the path to match this repository's own `QuarantineDirectoryPrefix`.
4. `fullPath` resolves to the foreign `quarantine` directory, and the RPC (or any Git subprocess invocation that consumes `GitObjectDirectory`) operates against/reads objects from a directory not owned by or verified as belonging to the requesting repository.
