### Title
`Pool.swap()` accepts zero-output swaps and burns the caller's entire input without any minimum-output validation - ([File: contracts/Pool.sol](contracts/Pool.sol))

### Summary
The reference bug is an invalid validation of swap results: the check `amount_0_abs > 0 || amount_1_abs > 0` lets a swap succeed even when one side is zero, so a user can get a non-zero-input / zero-output fill. Metronome's `Pool.swap()` exhibits the same bug class in a stronger form: it performs **no validation on the swap output at all**. It burns the caller's `syntheticTokenIn_` first, then mints whatever `quoteSwapOut()` returns — including `0` — with no `amountOutMin` parameter and no `_amountOut > 0` assertion.

### Finding Description
In `contracts/Pool.sol`, `swap()` validates only the input:

```solidity
if (!isSwapActive) revert SwapFeatureIsInactive();
if (amountIn_ == 0 || amountIn_ > syntheticTokenIn_.balanceOf(_msgSender)) revert AmountInIsInvalid();

syntheticTokenIn_.burn(_msgSender, amountIn_);

(_amountOut, _fee) = quoteSwapOut(syntheticTokenIn_, syntheticTokenOut_, amountIn_);

if (_fee > 0) {
    syntheticTokenOut_.mint(_poolRegistry.feeCollector(), _fee);
}
syntheticTokenOut_.mint(_msgSender, _amountOut);
``` [1](#0-0) 

`quoteSwapOut()` derives `_amountOut` purely from `masterOracle().quote()` minus the swap fee; nothing in it or in `swap()` guarantees the result is non-zero:

```solidity
_amountOut = _poolRegistry.masterOracle().quote(
    address(syntheticTokenIn_),
    address(syntheticTokenOut_),
    amountIn_
);
uint256 _swapFee = feeProvider.swapFees(...);
if (_swapFee > 0) {
    _fee = _amountOut.wadMul(_swapFee);
    _amountOut -= _fee;
}
``` [2](#0-1) 

For small `amountIn_` and/or pairs with a large value discrepancy, the oracle quote (and the wad-precision fee subtraction) can round `_amountOut` down to `0`. The function then completes "successfully": the user's entire `amountIn_` is burned and they receive nothing, exactly the "non-zero input, zero output" scenario the judge flagged as unacceptable in the reference finding. Unlike the SmartFarmingManager paths (`flashRepay` at line 126 and `leverage` at line 198, which enforce `swapAmountOutMin_`/`depositAmountMin_`), `swap()` exposes no slippage parameter to the caller at all. [3](#0-2) [4](#0-3) 

### Impact Explanation
Permanent, irrecoverable loss of user funds: the input synthetic tokens are burned (they are not recoverable since mint/burn supply accounting has already moved) and zero output is minted. This mirrors the reference issue's accepted medium severity — it manifests "in low transaction amounts and high value discrepancy" pairs, where `masterOracle().quote()` returns a value that truncates to 0 (or is entirely consumed by the swap fee). No privileged actor is needed; any EOA can reach the loss path through the public `swap()` entry point. Modifiers (`whenNotShutdown`, `nonReentrant`, `onlyIfSyntheticTokenExists`) do not prevent it, since zero output is not treated as a failure.

### Likelihood Explanation
Low-to-medium: it requires a quote that rounds to zero — dust `amountIn_`, extreme price ratio between the two synthetics, or a swap fee that consumes the whole output. The function also gives users no way to protect themselves (no `amountOutMin_` argument), so every call relies entirely on off-chain pre-computation of the oracle quote. There is no atomicity guarantee between the user's quoted expectation and execution; same-transaction oracle price movement between quote and swap is not checked on-chain.

### Recommendation
Add output validation analogous to the fix in the reference report — require a non-zero (and ideally user-supplied minimum) output:

```diff
 function swap(
     ISyntheticToken syntheticTokenIn_,
     ISyntheticToken syntheticTokenOut_,
-    uint256 amountIn_
+    uint256 amountIn_,
+    uint256 amountOutMin_
 ) ... {
     ...
     (_amountOut, _fee) = quoteSwapOut(syntheticTokenIn_, syntheticTokenOut_, amountIn_);
+    if (_amountOut == 0 || _amountOut < amountOutMin_) revert SlippageTooHigh();
     ...
 }
```

At minimum, revert when `_amountOut == 0` so a burn-with-zero-mint can never finalize.

### Proof of Concept
Hardhat sketch (against the existing test harness, using `SwapperMock`-style oracle control or a stubbed `MasterOracle`):

```javascript
// Setup: pool with two synthetics msA (cheap) and msB (expensive),
// masterOracle.quote(msA -> msB, smallAmount) returns 0.

await msA.mint(user.address, 100);           // user holds 100 msA

const before = await msA.balanceOf(user.address);
await pool.connect(user).swap(msA.address, msB.address, 1); // tiny amountIn

// tx succeeds instead of reverting:
expect(await msA.balanceOf(user.address)).to.eq(before.sub(1)); // input burned
expect(await msB.balanceOf(user.address)).to.eq(0);             // zero output minted
// Net: user lost 1 msA and received nothing — swap finalized anyway.
```

Caveat: the exact rounding-to-zero condition depends on the deployed `MasterOracle` quote implementation and configured `swapFees`; with a fee configured, `_amountOut` can also be driven to zero when the fee equals the full quote. The burn-before-check ordering is unconditional, so the loss path is reachable whenever the quote result is zero.
