### Title
Unauthenticated `RecvError` packet allows any attacker to unilaterally tear down an established, honestly-negotiated tunnel - (File: `outside.go`)

### Summary
Nebula's `handleRecvError` path processes the `header.RecvError` message type entirely before any encryption/decryption or certificate check is performed. An attacker who can observe or spoof a single plaintext header field (`RemoteIndex`) and the victim's known UDP source address can force an immediate, unconditional teardown of a tunnel that was otherwise correctly and mutually authenticated — exactly the "special override always wins" pattern described in the source report, where a narrow, unconditionally-honored code path lets an interested party unilaterally override the legitimately-determined outcome and deny the honest party the benefit of their correct handshake/session.

### Finding Description
`readOutsidePackets` dispatches `header.RecvError` to `f.handleRecvError` in the "Unencrypted packets" switch, i.e. before the packet has been through Noise decryption or any certificate/authentication check: [1](#0-0) 

`handleRecvError` then looks up the hostinfo purely by the plaintext `h.RemoteIndex` value carried in the header, and the only "authentication" check is comparing the packet's UDP source address against the last known remote address of that hostinfo — a value that is not cryptographically bound to the packet at all: [2](#0-1) 

If that single, spoofable comparison passes, the function unconditionally calls `f.closeTunnel(hostinfo)` and deletes the pending handshake state, tearing down a tunnel that both sides may have correctly, mutually authenticated via the Noise handshake and valid CA-signed certificates. This mirrors the `challengeRootL2Block` bug class: a narrow "special case" mechanism that unconditionally wins/overrides normal, correctly-computed state, and is reachable by a party (here, anyone who can craft/spoof a UDP packet, no valid certificate required) who has no legitimate standing to determine the outcome of an already-correct interaction.

The `sendRecvError` sender-side code confirms the packet carries no authentication data beyond the raw header: [3](#0-2) 

By contrast, the codebase treats `CloseTunnel` — a semantically similar teardown action — as requiring the peer to hold live session keys, since it is only processed after successful AEAD decryption: [4](#0-3) 
`RecvError` deliberately skips this and only gates on the optional, non-cryptographic `sendRecvErrorConfig`/`acceptRecvErrorConfig` toggles.

### Impact Explanation
An attacker with no CA-signed certificate — someone who can merely observe cleartext Nebula UDP headers on path, or who can spoof UDP source addresses (trivial for UDP, especially across many NAT/firewall environments) — can send a forged `RecvError` packet carrying a guessed/observed `RemoteIndex` to unilaterally and repeatedly destroy live, correctly-established tunnels between two honest, mutually-authenticated peers. This is a remote state-poisoning / denial-of-service primitive: it lets an unauthorized third party override the legitimate outcome of a completed handshake, forcing constant tunnel teardown and re-handshakes, and can be used to selectively deny connectivity to a specific honest peer indefinitely.

### Likelihood Explanation
`RemoteIndex` values are sent unencrypted in every Nebula packet header, so any attacker positioned to observe a small amount of traffic (or simply guess indices, since `generateIndex` space may be brute-forced with enough traffic) learns valid values. UDP source-address spoofing is a well-known and often-feasible attack vector depending on network path egress filtering. `acceptRecvErrorConfig`/`sendRecvErrorConfig` are configurable, but the default `listen.send_recv_error`/accept behavior does not require cryptographic proof of possession of the session at all, only an address match.

### Recommendation
Require that `RecvError` handling only take effect against hostinfos in a state where index reuse could plausibly happen (e.g., only relevant right after this node's own restart), and prefer requiring the `RecvError` to reflect knowledge derived from an authenticated exchange (e.g., HMAC keyed off the session's static/ephemeral material, or fold RecvError handling into the encrypted message channel similar to `CloseTunnel`) rather than trusting a bare plaintext header plus a non-cryptographic address comparison.

### Proof of Concept
1. Attacker passively observes (or guesses) the `RemoteIndex` used between honest peer A and peer B by sniffing any cleartext Nebula packet header on the path, or by spoofing peer B's known UDP `ip:port`.
2. Attacker crafts a raw UDP packet with `header.Type = header.RecvError`, `RemoteIndex` = A's local index for the A↔B tunnel, and source address spoofed to match B's currently known remote address (as tracked in A's hostinfo), per the encoding done in `sendRecvError`: [3](#0-2) 
3. A receives the packet; `handleRecvError` finds the hostinfo via `QueryReverseIndex`, sees the spoofed address matches `hostinfo.GetRemote()`, and unconditionally calls `f.closeTunnel(hostinfo)` plus deletes pending handshake state: [5](#0-4) 
4. The legitimate, fully-authenticated tunnel between A and B is destroyed without either A or B having done anything wrong, and the attacker can repeat this at will to keep the honest tunnel from ever stabilizing — directly analogous to the "always-wins special path blocks the honest party" bug class in the source report.

func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
