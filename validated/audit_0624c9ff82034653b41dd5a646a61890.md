### Title
Unauthenticated `/shutdown` endpoint permits any TCP peer to halt `SignerEventReceiver::main_loop` - (File: libsigner/src/events.rs)

### Summary
`SignerEventReceiver::next_event` handles `POST /shutdown` by unconditionally setting `event_receiver.stop_signal.store(true, Ordering::SeqCst)` and returning `EventError::Terminated`, with no check of any secret, token, or peer identity. Since `main_loop` exits as soon as `is_stopped()` returns true or `next_event` returns `EventError::Terminated`, any TCP client capable of reaching the bound event-receiver socket and sending a well-formed HTTP POST to `/shutdown` can permanently stop the signer's event ingestion loop.

### Finding Description
The claimed equality/fault is: "an accepted shutdown command == a request the operator's own node issued." In the code, this equality is broken because the `/shutdown` branch performs no verification of the request's origin: [1](#0-0) 

Compare this to the legitimate use of the shutdown mechanism in `SignerStopSignaler::send`, which simply opens a `TcpStream` to `self.local_addr` and writes a raw HTTP POST to `/shutdown` — this is exactly the same wire format any unauthenticated remote peer could send: [2](#0-1) 

The only gating before reaching the `/shutdown` branch is a check that the HTTP method is `POST` and that the server successfully parsed a `tiny_http::Request`: [3](#0-2) 

There is no signature check, shared secret, bearer token, or source-IP allowlist anywhere in `next_event`, `with_server`, or `bind`. Once `stop_signal` is set to `true`, `is_stopped()` returns `true` on the next iteration of `EventReceiver::main_loop`, which breaks out of the loop and logs "Event receiver stopped": [4](#0-3) 

### Impact Explanation
Any party able to open a TCP connection to the signer's bound event-receiver address can send a single `POST /shutdown HTTP/1.1` request and terminate that signer's event-ingestion loop, cutting the signer off from further `stackerdb_chunks`, `proposal_response`, `new_burn_block`, and `new_block` events pushed by its node. This is a single-message, repeatable, unauthenticated denial of service against the signer's runloop input path, matching the "Critical - remote crash/unauthenticated DoS from few messages" category in scope. It does not forge chain data or bypass a signature check, but it does fully and permanently (until process restart/rebind) stop the signer from receiving events without the attacker needing any secret, key, or role.

### Likelihood Explanation
Preconditions: the attacker only needs network reachability to the TCP port that `SignerEventReceiver::bind` listens on. `bind` accepts whatever `SocketAddr` the operator configures — I was unable to fully confirm the default/typical bind address (e.g., loopback-only vs. `0.0.0.0`) from `stacks-signer/src/config.rs` before running out of tool calls, so whether this endpoint is remotely reachable in a typical deployment depends on operator configuration and network topology (e.g., firewalling this port to only the paired node). If the event-receiver port is bound to a non-loopback address or is otherwise reachable by a remote/unprivileged party (e.g., across a LAN, via port-forwarding, or in cloud deployments with permissive security groups), the attack is trivial: no authentication, no retries needed, single request, fully repeatable.

### Recommendation
Add authentication to the `/shutdown` endpoint (and ideally to all event endpoints), e.g., require a shared secret/bearer token configured between the node's event dispatcher and the signer, verified in `next_event` before acting on `/shutdown` (and before processing other event types). Alternatively/additionally, document and enforce that the event-receiver socket must only be bound to loopback or otherwise firewalled from untrusted networks, and reject `/shutdown` requests whose source address does not match the configured trusted peer.

```rust
use std::net::{TcpStream, SocketAddr};
use std::io::Write;
use std::sync::mpsc::channel;

#[test]
fn test_unauthenticated_shutdown_dos() {
    let mut receiver: SignerEventReceiver<SomeSignerMessageType> = SignerEventReceiver::new(false);
    let bind_addr: SocketAddr = "127.0.0.1:0".parse().unwrap();
    let addr = receiver.bind(bind_addr).unwrap();

    // Simulate an attacker with a plain TCP connection, no secret/credential.
    let mut stream = TcpStream::connect(addr).unwrap();
    let body = "attack";
    let req = format!(
        "POST /shutdown HTTP/1.1\r\nHost: {addr}\r\nConnection: close\r\nContent-Length: {}\r\nContent-Type: text/plain\r\n\r\n{}",
        body.len(), body
    );
    stream.write_all(req.as_bytes()).unwrap();

    // Drive next_event once to process the malicious request.
    let err = receiver.next_event().unwrap_err();
    assert!(matches!(err, EventError::Terminated));

    // Assert the DoS: the receiver is now permanently stopped for any future caller,
    // even though the attacker never held the node's secret or any privileged role.
    assert!(receiver.is_stopped());
}
```

```rust
    fn main_loop(&mut self) {
        loop {
            if self.is_stopped() {
                info!("Event receiver stopped");
                break;
            }
            let next_event = match self.next_event() {
                Ok(event) => event,
                Err(EventError::UnrecognizedEvent(..)) => {
                    // got an event that we don't care about (not a problem)
                    continue;
                }
                Err(EventError::Terminated) => {
                    // we're done
                    info!("Caught termination signal");
                    break;
                }
                Err(e) => {
                    warn!("Failed to receive next event: {:?}", &e);
                    continue;
                }
            };
            if !self.forward_event(next_event) {
                info!("Failed to forward event");
                break;
            }
        }
        info!("Event receiver main loop exit");
    }
```
