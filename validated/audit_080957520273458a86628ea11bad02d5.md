### Title
SSRF via Unrestricted `bundle-uri` Capability in `FetchRemote`/`UpdateRemoteMirror`/`FindRemoteRootRef` - (File: internal/gitaly/service/repository/fetch_remote.go)

### Summary
`git-fetch(1)`/`git-remote show`/`git-push(1)` invocations performed on behalf of a caller-supplied remote URL (`FetchRemote`, `UpdateRemoteMirror`, `FindRemoteRootRef`) do not disable the Git `bundle-uri` protocol v2 capability, unlike `CreateRepositoryFromURL`, which was explicitly patched to add `transfer.bundleURI=false` specifically "to prevent SSRF" (see `CHANGELOG.md` entry "repoFromURL: Disable bundle URIs when cloning from URL to prevent SSRF"). Any git server reachable at the user-controlled `remote_url` can advertise a `bundle-uri` value in its protocol v2 capability response pointing to an internal address, causing Gitaly to issue an outbound HTTP(S) request to that address as a side effect of the fetch/push/remote-show operation.

### Finding Description
`CreateRepositoryFromURL`'s clone command explicitly appends `gitcmd.WithGlobalOption(gitcmd.ConfigPair{Key: "transfer.bundleURI", Value: "false"})` with the comment: "Drop support for bundle URI when fetching from a remote repository. Since the URI can point to any server, including localhost, this is to prevent attack vectors that could abuse this mechanism." [1](#0-0) 

However, the analogous code paths that also connect Gitaly-as-a-git-client to an arbitrary, caller-supplied `remote_url` do not apply this same mitigation:

- `buildCommandOpts` in `FetchRemote` builds only `remote.inmemory.fetch`, `remote.inmemory.url`, `http.proactiveAuth`, and `http.*.extraHeader` config, never `transfer.bundleURI`. [2](#0-1) 

- `updateRemoteMirror` builds `remoteConfig` for `GetRemoteReferences` and `Push` similarly without disabling bundle-uri. [3](#0-2) 

- `findRemoteRootRefCmd` runs `git remote show inmemory` (which performs an ls-remote/fetch-refs handshake) against the caller-supplied URL, again without disabling bundle-uri. [4](#0-3) 

All three RPCs accept a free-form `remote_url`/`Remote.url` field directly from the caller with no allowlist beyond DNS-rebinding protection (`resolved_address` pinning via `GetURLAndResolveConfig`), which addresses DNS rebinding but does not prevent a server at the (legitimately resolved) target address from returning a malicious `bundle-uri` capability value during the Git protocol v2 handshake. [5](#0-4) [6](#0-5) 

### Impact Explanation
If Git's client-side `bundle-uri` feature is honored during these operations, a repository owner/maintainer configuring a pull mirror, a repository import, or an ad-hoc `FindRemoteRootRef`/`FetchRemote` call against a URL they control can host a Git server that advertises a `bundle-uri` pointing at an internal-only endpoint (e.g., a cloud metadata service, an internal admin API, or another internal Gitaly/Praefect port). Gitaly, running inside the trusted network, would then issue an outbound request to that internal endpoint, resulting in SSRF — the same class of issue for which `CreateRepositoryFromURL` was already fixed.

### Likelihood Explanation
`FetchRemote` and `UpdateRemoteMirror` are the RPCs backing GitLab's repository pull-mirroring feature, and `FindRemoteRootRef` is used during project import/mirror setup — all reachable by ordinary users with maintainer-level access configuring a mirror URL that points to a git server of their choosing. Since the exact same primitive was already recognized as an SSRF vector for `CreateRepositoryFromURL`, the omission of the identical mitigation on these three RPCs is a strong, root-cause-supported analog.

### Recommendation
Apply the same mitigation used in `CreateRepositoryFromURL` — explicitly set `transfer.bundleURI=false` (or otherwise disable/validate the bundle-uri capability) — in `buildCommandOpts` (`FetchRemote`), `updateRemoteMirror`, and `findRemoteRootRefCmd`, for any command that connects to a caller/attacker-influenceable remote URL.

### Proof of Concept
1. As a project maintainer, configure a pull mirror (`FetchRemote`/`UpdateRemoteMirror`) or perform a `FindRemoteRootRef` request pointing at a Git server the attacker controls (e.g., `http://attacker.example/repo.git`), optionally combined with `resolved_address` pinning to a permitted external IP to pass any allowlist checks.
2. The attacker's Git server responds to the protocol v2 handshake with a `bundle-uri` capability set to an internal URL, e.g. `http://169.254.169.254/latest/meta-data/` or `http://127.0.0.1:<internal-port>/admin`.
3. Because `transfer.bundleURI` is not disabled in `buildCommandOpts`/`updateRemoteMirror`/`findRemoteRootRefCmd` (unlike `create_repository_from_url.go`), the Git client process spawned by Gitaly follows the advertised bundle URI and issues an outbound request to the internal target, leaking metadata/responses or interacting with internal-only services — confirming the SSRF.

func buildCommandOpts(ctx context.Context, opts *localrepo.FetchOpts, req *gitalypb.FetchRemoteRequest) error {
	remoteURL := req.GetRemoteParams().GetUrl()
	var config []gitcmd.ConfigPair

	for _, refspec := range getRefspecs(req.GetRemoteParams().GetMirrorRefmaps()) {
		config = append(config, gitcmd.ConfigPair{
			Key: "remote.inmemory.fetch", Value: refspec,
		})
	}

	if resolvedAddress := req.GetRemoteParams().GetResolvedAddress(); resolvedAddress != "" {
		modifiedURL, resolveConfig, err := gitcmd.GetURLAndResolveConfig(remoteURL, resolvedAddress)
		if err != nil {
			return fmt.Errorf("couldn't get curloptResolve config: %w", err)
		}

		remoteURL = modifiedURL
		config = append(config, resolveConfig...)
	}

	config = append(config, gitcmd.ConfigPair{Key: "remote.inmemory.url", Value: remoteURL})

	if featureflag.FetchRemoteProactiveAuth.IsEnabled(ctx) {
		if u, err := url.Parse(remoteURL); err == nil && u.User != nil {
			password, _ := u.User.Password()
			if u.User.Username() != "" && password != "" {
				config = append(config, gitcmd.ConfigPair{
					Key:   "http.proactiveAuth",
					Value: "basic",
				})
			}
		}
	}

	if authHeader := req.GetRemoteParams().GetHttpAuthorizationHeader(); authHeader != "" {
		config = append(config, gitcmd.ConfigPair{
			Key:   fmt.Sprintf("http.%s.extraHeader", req.GetRemoteParams().GetUrl()),
			Value: "Authorization: " + authHeader,
		})
	}

	opts.CommandOptions = append(opts.CommandOptions, gitcmd.WithConfigEnv(config...))

	return nil
}

func (s *server) findRemoteRootRefCmd(ctx context.Context, request *gitalypb.FindRemoteRootRefRequest) (*command.Command, error) {
	remoteURL := request.GetRemoteUrl()
	var config []gitcmd.ConfigPair

	if resolvedAddress := request.GetResolvedAddress(); resolvedAddress != "" {
		modifiedURL, resolveConfig, err := gitcmd.GetURLAndResolveConfig(remoteURL, resolvedAddress)
		if err != nil {
			return nil, structerr.NewInvalidArgument("couldn't get curloptResolve config: %w", err)
		}

		remoteURL = modifiedURL
		config = append(config, resolveConfig...)
	}

	config = append(config, gitcmd.ConfigPair{Key: "remote.inmemory.url", Value: remoteURL})

	if authHeader := request.GetHttpAuthorizationHeader(); authHeader != "" {
		config = append(config, gitcmd.ConfigPair{
			Key:   fmt.Sprintf("http.%s.extraHeader", request.GetRemoteUrl()),
			Value: "Authorization: " + authHeader,
		})
	}

	repo := s.localRepoFactory.Build(request.GetRepository())

	return repo.Exec(ctx,
		gitcmd.Command{
			Name:   "remote",
			Action: "show",
			Args:   []string{"inmemory"},
		},
		gitcmd.WithDisabledHooks(),
		gitcmd.WithConfigEnv(config...),
		gitcmd.WithSetupStdout(),
	)
}

// Remote represents a git remote repository.
message Remote {
  // url is the URL of the remote repository.
  string url = 1;
  // http_authorization_header is the HTTP header which should be added to
  // the request in order to authenticate against the repository.
  string http_authorization_header = 3;
  // mirror_refmaps contains the refspecs which shall be fetched. Some special
  // refspecs are accepted:
  //
  // - "all_refs" gets translated to "+refs/*:refs/*", which mirrors all
  //   references of the source repository.
  // - "heads" gets translated to "+refs/heads/*:refs/heads/*", which mirrors
  //   all branches of the source repository.
  // - "tags" gets translated to "+refs/tags/*:refs/tags/*", which mirrors all
  //   tags of the source repository.
  //
  // If no refspecs are given, this defaults to "all_refs".
  repeated string mirror_refmaps = 4;
  // resolved_address holds the resolved IP address of the remote_url. This is
  // used to avoid DNS rebinding by mapping the url to the resolved address.
  // Only IPv4 dotted decimal ("192.0.2.1"), IPv6 ("2001:db8::68"), or IPv4-mapped
  // IPv6 ("::ffff:192.0.2.1") forms are supported.
  // Works with HTTP/HTTPS/Git/SSH protocols.
  // Optional.
  string resolved_address = 6;

message FindRemoteRootRefRequest {
  // repository is the repository in which the request shall be executed in. If
  // a remote name is given, then this is the repository in which the remote
  // will be looked up.

  // remote_url specifies the remote repository URL which should be fetched from.
  string remote_url = 3;
  // http_authorization_header is the HTTP header which should be added to the
  // request in order to authenticate against the repository.
  string http_authorization_header = 4;
  // resolved_address holds the resolved IP address of the remote_url. This is
  // used to avoid DNS rebinding by mapping the url to the resolved address.
  // Only IPv4 dotted decimal ("192.0.2.1"), IPv6 ("2001:db8::68"), or IPv4-mapped
  // IPv6 ("::ffff:192.0.2.1") forms are supported.
  // Works with HTTP/HTTPS/Git/SSH protocols.
  // Optional.
  string resolved_address = 6;

  reserved 2;
  reserved "remote";
