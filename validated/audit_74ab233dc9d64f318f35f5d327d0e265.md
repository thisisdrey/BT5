The core bug pattern in the report is: a `memory`-copied struct field gets mutated locally (`bounty.active = false`), but the mutation is never written back to the persistent array, so the on-chain state never reflects the intended state change — an authorization/activity flag that should transition from valid→invalid never actually does, since checks are re-run against a stale/never-updated copy.

I traced the closest analogous flow in this repo — StackerDB chunk authentication and storage:

- `SlotMetadata::verify` / `StackerDBChunkData::verify` recompute the digest and recover the signer fresh each call, with no cached/stale copy retained across calls. [1](#0-0) 
- `StackerDBTx::try_replace_chunk` re-reads `slot_validation` (the authoritative, DB-backed signer/version) immediately before verifying and inserting, inside the same transaction as the write via `insert_chunk`, so there is no memory/storage divergence between what's checked and what's persisted.

    /// Verify that a given principal signed this chunk metadata.
    /// Note that the address version is ignored.
    pub fn verify(&self, principal: &StacksAddress) -> Result<bool, Error> {
        let sigh = self.auth_digest();
        let pubk = StacksPublicKey::recover_to_pubkey_without_validating_low_s(
            sigh.as_bytes(),
            &self.signature,
        )
        .map_err(|ve| Error::VerifyingError(ve.to_string()))?;

        let pubkh = Hash160::from_node_public_key(&pubk);
        Ok(pubkh == *principal.bytes())
    }
