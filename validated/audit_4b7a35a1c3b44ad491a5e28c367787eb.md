### Title
Missing Zero-Address Check in `set_beneficiary_for_operator` Permanently Freezes Commission APT at `NULL_SHAREHOLDER` - (File: `aptos-move/framework/aptos-framework/sources/delegation_pool.move`)

### Summary

`delegation_pool::set_beneficiary_for_operator` accepts an arbitrary `new_beneficiary: address` and stores it without any zero-address guard. Because `@0x0` is the module's own `NULL_SHAREHOLDER` sentinel — and `unlock_internal` explicitly blocks `NULL_SHAREHOLDER` from ever unlocking shares — any commission credited to `@0x0` is permanently frozen inside the pool with no recovery path.

### Finding Description

`set_beneficiary_for_operator` in `delegation_pool.move` writes `new_beneficiary` directly to `BeneficiaryForOperator` with no check that the value is non-zero: [1](#0-0) 

The module defines `NULL_SHAREHOLDER = @0x0` as a special sentinel used to temporarily hold `add_stake` fees: [2](#0-1) 

`synchronize_delegation_pool` — called automatically inside every user-facing entry (`add_stake`, `unlock`, `reactivate_stake`, `withdraw`) — routes all operator commission to `beneficiary_for_operator(operator)`: [3](#0-2) 

If the beneficiary is `@0x0`, `buy_in_active_shares` and `buy_in_pending_inactive_shares` credit shares to `NULL_SHAREHOLDER`. Those shares can never be redeemed because `unlock_internal` hard-aborts on `NULL_SHAREHOLDER`: [4](#0-3) 

The same root cause exists in `staking_contract::set_beneficiary_for_operator`, where `distribute_internal` sends commission coins directly to `beneficiary_for_operator(operator)` via `aptos_account::deposit_coins`, permanently depositing them to `@0x0`: [5](#0-4) [6](#0-5) 

### Impact Explanation

Once an operator calls `set_beneficiary_for_operator(operator, @0x0)`, every subsequent call to `synchronize_delegation_pool` (permissionless, triggered by any delegator interaction) buys commission shares for `NULL_SHAREHOLDER`. Those shares appreciate with pool rewards but can never be unlocked or withdrawn. The commission APT is permanently frozen inside the pool. Even after the operator corrects the beneficiary, all commission accumulated during the window is irrecoverable. This constitutes permanent freezing of APT (commission staking balances).

### Likelihood Explanation

An operator could set `@0x0` accidentally (e.g., passing a zero-initialized address from an off-chain script or SDK). The window between the erroneous call and detection can span multiple epochs, during which `synchronize_delegation_pool` is called by every delegator operation, continuously minting frozen shares. The `staking_contract` path additionally affects the `vesting` module, which proxies `set_beneficiary_for_operator` directly: [7](#0-6) 

### Recommendation

Add a zero-address assertion at the top of both `set_beneficiary_for_operator` functions before writing the field:

```move
// delegation_pool.move
public entry fun set_beneficiary_for_operator(
    operator: &signer,
    new_beneficiary: address
) acquires BeneficiaryForOperator {
    assert!(new_beneficiary != @0x0, error::invalid_argument(EINVALID_BENEFICIARY_ADDRESS));
    // ... rest of function
}
```

```move
// staking_contract.move
public entry fun set_beneficiary_for_operator(
    operator: &signer, new_beneficiary: address
) acquires BeneficiaryForOperator {
    assert!(new_beneficiary != @0x0, error::invalid_argument(EINVALID_BENEFICIARY_ADDRESS));
    // ... rest of function
}
```

Similarly, `stake::set_operator_with_cap` and `stake::set_delegated_voter_with_cap` assign `new_operator`/`new_voter` without zero checks: [8](#0-7) [9](#0-8) 

Setting either to `@0x0` blocks all operator-gated functions (`rotate_consensus_key`, `join_validator_set`, etc.) until corrected.

### Proof of Concept

```
1. Operator deploys a delegation pool with 10% commission.
2. Delegators add stake; pool accumulates rewards over several epochs.
3. Operator calls:
       delegation_pool::set_beneficiary_for_operator(operator_signer, @0x0)
   No abort occurs; BeneficiaryForOperator.beneficiary_for_operator = @0x0.
4. Any delegator calls add_stake / unlock / withdraw, which internally calls
   synchronize_delegation_pool(pool_address).
5. Inside synchronize_delegation_pool:
       buy_in_active_shares(pool, @0x0 /*NULL_SHAREHOLDER*/, commission_active)
   Shares are minted for @0x0 in the active pool.
6. Operator realizes the mistake and calls set_beneficiary_for_operator again
   with a valid address. Future commission is now correctly routed.
7. However, the shares already credited to @0x0 remain permanently.
   Any attempt to call unlock(@0x0, ...) aborts with ECANNOT_UNLOCK_NULL_SHAREHOLDER.
   The commission APT represented by those shares is permanently frozen.
```

    public entry fun set_beneficiary_for_operator(
        operator: &signer,
        new_beneficiary: address
    ) acquires BeneficiaryForOperator {
        // The beneficiay address of an operator is stored under the operator's address.
        // So, the operator does not need to be validated with respect to a staking pool.
        let operator_addr = signer::address_of(operator);
        let old_beneficiary = beneficiary_for_operator(operator_addr);
        if (exists<BeneficiaryForOperator>(operator_addr)) {
            borrow_global_mut<BeneficiaryForOperator>(operator_addr).beneficiary_for_operator = new_beneficiary;
        } else {
            move_to(operator, BeneficiaryForOperator { beneficiary_for_operator: new_beneficiary });
        };

        emit(SetBeneficiaryForOperator {
            operator: operator_addr,
            old_beneficiary,
            new_beneficiary,
        });
    }
