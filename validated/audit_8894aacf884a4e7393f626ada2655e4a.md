### Title
Unauthenticated `POST /shutdown` permanently halts `SignerEventReceiver::main_loop` - (`libsigner/src/events.rs`)

### Summary
The signer's event-receiver HTTP endpoint accepts an unauthenticated `POST /shutdown` request from any TCP client and unconditionally sets `stop_signal` to `true`, terminating the receiver's `main_loop` for good. This breaks the intended invariant that only the signer's own `SignerStopSignaler::send()` can trigger a stop, allowing any remote peer able to reach the bound `endpoint` to permanently disable that signer's event processing with a single crafted request.

### Finding Description
`SignerEventReceiver::next_event` in `libsigner/src/events.rs` dispatches routes purely on URL string and HTTP method, with no authentication, no token/secret check, and no verification that the request originated from the local node: [1](#0-0) 

```rust
if request.method() != &HttpMethod::Post {
    return Err(EventError::MalformedRequest(...));
}
...
} else if request.url() == "/shutdown" {
    event_receiver.stop_signal.store(true, Ordering::SeqCst);
    Err(EventError::Terminated)
}
```

Compare this to the legitimate stop path, `SignerStopSignaler::send()`, which is the only intended caller of this transition, but which is implemented by literally sending the exact same unauthenticated HTTP request over the loopback connection: [2](#0-1) 

Since there is no secret, header, or source-address check distinguishing the signer's own stop-signaler traffic from an arbitrary remote client's traffic, any TCP peer that can reach the bound `endpoint` (configured via `GlobalConfig::endpoint`, used directly as the bind address in `SpawnedSigner::new`) can forge this exact same request: [3](#0-2) 

Once `stop_signal` is set, `is_stopped()` returns `true` and `EventReceiver::main_loop` exits at the `Err(EventError::Terminated)` branch, terminating the event receiver thread permanently — no restart logic exists: [4](#0-3) 

This is explicitly acknowledged as an operational risk in the signer's startup log, warning operators not to expose the signer event-receiver to untrusted networks — confirming there is no code-level protection and this is a known, unmitigated attack surface: [5](#0-4) 

### Impact Explanation
A single unauthenticated `POST /shutdown` message permanently stops the `SignerEventReceiver::main_loop` for the targeted signer process. Once stopped, the signer stops forwarding StackerDB chunk events, block-validation responses, burn-block/new-block events, and status checks (all of which flow through `next_event`), effectively taking that signer offline for signing rounds until manually restarted. This matches the "Critical – remote crash/unauthenticated DoS from a few messages" category if the signer's event-receiver port is reachable by remote/untrusted parties.

### Likelihood Explanation
The precondition is that the signer's `endpoint` (event-receiver bind address) is reachable by the attacker — this depends entirely on operator network configuration (e.g., binding to `0.0.0.0` or otherwise exposing it beyond the local trusted node). Given that the deployment guidance explicitly warns against exposing this endpoint externally, well-configured signers running the event receiver strictly on loopback/localhost are not exploitable by remote parties. However, for any signer that is misconfigured or intentionally exposes this endpoint (e.g., communicating with a remote/non-local Stacks node as the warning discusses), the attack requires zero credentials, one TCP connection, and one crafted HTTP request — trivially repeatable and low-cost.

### Recommendation
Add authentication to the `/shutdown` route (and ideally all mutable routes) in `SignerEventReceiver::next_event`, e.g. require a shared secret/token known only to the local node and signer, or restrict acceptance of `/shutdown` requests to loopback source addresses at the socket/accept level. At minimum, do not allow arbitrary external network exposure of this port to be a supported/undetected configuration without an authentication layer.

### Proof of Concept
```rust
// libsigner/src/tests/mod.rs (illustrative)
#[test]
fn test_unauthenticated_shutdown() {
    let mut ev = SignerEventReceiver::<StackerDBChunksEvent>::new(false);
    let endpoint: SocketAddr = "127.0.0.1:31999".parse().unwrap();
    ev.bind(endpoint).unwrap();
    let stop_signaler = ev.get_stop_signaler().unwrap(); // legit signaler, NOT used

    let handle = std::thread::spawn(move || ev.main_loop());

    // Attacker: unauthenticated raw TCP connection, no secret, no local access
    let mut sock = TcpStream::connect(endpoint).unwrap();
    let body = "attacker shutdown";
    let req = format!(
        "POST /shutdown HTTP/1.1\r\nHost: {}\r\nConnection: close\r\nContent-Length: {}\r\n\r\n{}",
        endpoint, body.len(), body
    );
    sock.write_all(req.as_bytes()).unwrap();

    // main_loop exits without SignerStopSignaler::send() ever being called
    handle.join().unwrap();
    // assert is_stopped() would be true if receiver were still accessible
}
```
This reproduces the exact request built in `SignerStopSignaler::send` (`libsigner/src/events.rs:382-394`) from an unrelated/unauthenticated connection, causing `main_loop` to exit via the `/shutdown` branch at `libsigner/src/events.rs:443-445` without the legitimate `stop_signaler` ever being invoked.
