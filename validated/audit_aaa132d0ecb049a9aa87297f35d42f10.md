### Title
Unstaked-peer connection eviction (`prune_oldest`) can be gamed via trickle traffic to entrench attacker slots and starve idle legitimate senders - (`streamer/src/nonblocking/quic.rs`)

### Summary
`ConnectionTable::prune_oldest`, used by `SwQos::prune_unstaked_connection_table` to shrink the unstaked table, evicts the IP-keyed entry whose connections have the smallest `last_update` timestamp. Because `last_update` is refreshed every time any stream on a connection finishes (`on_stream_finished`), an unprivileged unstaked attacker can keep sending trivial 1-byte streams to continuously refresh its own entry and guarantee it is never selected as "oldest," causing legitimate but less chatty unstaked IPs to be evicted first once the unstaked table nears `max_unstaked_connections`.

### Finding Description
`ConnectionTable::prune_oldest` computes, for each IP (or pubkey) key, the minimum `last_update` across all connections registered under that key, and evicts the key with the smallest such minimum: [1](#0-0) 

`last_update` is a per-connection `Arc<AtomicU64>` created at connection-context build time (`build_connection_context`, initialized to `timing::timestamp()`) and stored into each `ConnectionEntry`: [2](#0-1) [3](#0-2) 

Crucially, it is refreshed on every completed stream via `on_stream_finished`, which is called from the connection handling loop after a QUIC uni-stream finishes (`StreamState::Finished`), independent of whether the packet content is a valid transaction: [4](#0-3) [5](#0-4) 
`handle_chunks` returns `StreamState::Finished` unconditionally once the client closes the write side of the stream and the data is forwarded to the packet channel, without requiring the packet to be a well-formed/valid transaction: [6](#0-5) 

`prune_unstaked_connection_table` invokes `prune_oldest` whenever `unstaked_connection_table.total_size >= max_unstaked_connections`, pruning down to 90% capacity: [7](#0-6) 

Because the eviction key is a pure LRU timestamp with no per-source rate limiting on how often it can be refreshed, and unstaked connections are keyed by IP (`ConnectionTableKey::IP`), a single attacker IP holding up to `max_connections_per_unstaked_peer` connections can trivially open small streams at a modest cadence (well below any throttle, since `on_stream_finished`/`last_update` refresh has no independent rate limit distinct from the existing stream-throttling used for scheduling bandwidth, not eviction fairness) to keep its own entry's minimum `last_update` continuously fresh. Any other unstaked IP that is not doing this (e.g., a legitimate sender who opened a connection but has not yet sent, or sends infrequently) will have an older minimum `last_update` and will be preferentially evicted by `prune_oldest` when the table needs to shrink, regardless of connection count or actual traffic volume being sent by the attacker.

### Impact Explanation
This is a QoS-evasion / fairness-bypass issue in the accepted "QoS evasion" category. Once the unstaked table nears `max_unstaked_connections`, an attacker with minimal per-connection traffic can guarantee eviction priority against legitimate unstaked peers attempting new connections or holding idle-but-legitimate connections, entrenching its own slots and starving other unstaked senders of TPU ingress capacity. This does not defeat per-peer connection caps (`max_connections_per_unstaked_peer` still bounds the attacker's own slot count), but it converts the shared eviction policy into an attacker-favoring mechanism, undermining the intended per-source fairness of the unstaked connection pool.

### Likelihood Explanation
Fully unprivileged and remotely triggerable: the attacker only needs a QUIC endpoint to the public TPU port, no stake, no special config. Preconditions are realistic — an unstaked table near `max_unstaked_connections` is the normal steady-state under any load (mainnet-style traffic). The attack requires only periodic tiny writes (well within `max_streams_per_ms`/stream-throttle allowances, which govern bandwidth, not the eviction ordering) and is trivially repeatable and sustainable for as long as the attacker's connection remains open.

### Recommendation
Decouple eviction fairness from raw activity timestamps that a peer fully controls: consider (a) rate-limiting how often `last_update` can move an entry to "recently active" status (e.g. bucket/quantize timestamps, or require a minimum amount of genuinely useful throughput — successfully sigverified packets — before refreshing), (b) incorporating connection age or a fairness/round-robin component alongside recency so idle-but-established connections are not always penalized over actively-pinged ones, or (c) applying `prune_random`-style weighted sampling similar to the staked table instead of strict LRU for the unstaked table, removing the deterministic "always evict oldest" primitive that a churn/keepalive strategy can game.

### Proof of Concept
Unit test extension of the existing `test_prune_table_with_ip` pattern in `streamer/src/nonblocking/quic.rs`, operating directly on `ConnectionTable`:

```rust
#[test]
fn test_prune_oldest_gamed_by_activity_refresh() {
    use std::net::Ipv4Addr;
    let cancel = CancellationToken::new();
    let mut table = ConnectionTable::new(ConnectionTableType::Unstaked, cancel);
    let stats = Arc::new(StreamerStats::default());
    let max_connections_per_peer = 10;

    // Attacker IP: max_connections_per_unstaked_peer connections, each with a
    // continuously-refreshed last_update (simulating trickle keepalive traffic).
    let attacker_ip = IpAddr::V4(Ipv4Addr::new(1, 0, 0, 0));
    let attacker_last_updates: Vec<_> = (0..max_connections_per_peer)
        .map(|_| Arc::new(AtomicU64::new(1000))) // fresh timestamp
        .collect();
    for (port, lu) in attacker_last_updates.iter().enumerate() {
        table.try_add_connection(
            ConnectionTableKey::IP(attacker_ip),
            port as u16,
            ClientConnectionTracker::new(stats.clone(), 1000).unwrap(),
            None,
            ConnectionPeerType::Unstaked,
            lu.clone(),
            max_connections_per_peer,
            || Arc::new(NullStreamerCounter {}),
        ).unwrap();
    }

    // Victim IPs: single idle connections with an older timestamp (no keepalive activity).
    let victim_ips: Vec<_> = (2..5)
        .map(|i| IpAddr::V4(Ipv4Addr::new(i, 0, 0, 0)))
        .collect();
    for ip in &victim_ips {
        table.try_add_connection(
            ConnectionTableKey::IP(*ip),
            0,
            ClientConnectionTracker::new(stats.clone(), 1000).unwrap(),
            None,
            ConnectionPeerType::Unstaked,
            Arc::new(AtomicU64::new(0)), // stale, never refreshed
            max_connections_per_peer,
            || Arc::new(NullStreamerCounter {}),
        ).unwrap();
    }

    // Simulate attacker refreshing last_update again right before pruning
    // (mimics on_stream_finished being called from trickle traffic).
    for lu in &attacker_last_updates {
        lu.store(2000, Ordering::Relaxed);
    }

    // Prune to force eviction (table currently has 10 + 3 = 13 entries).
    let pruned = table.prune_oldest(10);

    // Assert: victim (idle, low-activity) entries were evicted first,
    // despite the attacker holding strictly more total connections.
    assert!(pruned > 0);
    for ip in &victim_ips {
        assert!(
            !table.table.contains_key(&ConnectionTableKey::IP(*ip)),
            "victim entry should have been evicted before attacker's refreshed entries"
        );
    }
    assert!(
        table.table.contains_key(&ConnectionTableKey::IP(attacker_ip)),
        "attacker entry should survive due to refreshed last_update"
    );
}
```
Expected result: the test passes, demonstrating that despite holding the maximum allowed number of connections, the attacker's IP entry always survives pruning by refreshing `last_update`, while victim IPs with fewer, idle connections are evicted first — confirming the fairness invariant is not upheld.

    pub(crate) fn prune_oldest(&mut self, max_size: usize) -> usize {
        let mut num_pruned = 0;
        let key = |(_, connections): &(_, &Vec<_>)| {
            connections.iter().map(ConnectionEntry::last_update).min()
        };
        while self.total_size.saturating_sub(num_pruned) > max_size {
            match self.table.values().enumerate().min_by_key(key) {
                None => break,
                Some((index, connections)) => {
                    num_pruned += connections.len();
                    self.table.swap_remove_index(index);
                }
            }
        }
        self.total_size = self.total_size.saturating_sub(num_pruned);
        num_pruned
    }

    fn prune_unstaked_connection_table(
