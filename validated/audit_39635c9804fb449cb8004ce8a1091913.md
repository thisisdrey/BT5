Audit Report

## Title
`CenterTargetPrice::adapt_price` recovers from a zero price by re-adopting the attacker-influenced `sellout_price`, letting an unprivileged buyer permanently pin Coretime pricing near zero - (File: `substrate/frame/broker/src/adapt_price.rs`)

## Summary
`CenterTargetPrice::adapt_price` computes the next sale's `end_price` as `1/10 * sellout_price`; when that floors to `0` (which happens whenever `sellout_price < 10`), it falls back to reusing `sellout_price` itself as both `end_price` and `target_price` with no floor or independent reference value, as confirmed in the code at [1](#0-0) . Since `sellout_price` is the price paid for the last core sold in a sale, and this value is fed directly into `SaleInfoRecord.end_price`/`sellout_price` and `PotentialRenewalRecord.price` in `rotate_sale`, an unprivileged buyer who purchases the last core cheaply (e.g., for `1`) can lock subsequent sale prices and lease-renewal prices to that same de minimis value, as shown by the wiring at [2](#0-1)  and [3](#0-2) .

## Finding Description
The zero-guard branch in `adapt_price` was added to fix a prior bug where price got permanently stuck at literal `0` — but the "fix" simply substitutes `sellout_price` (an attacker-influenced value) for the zero result, rather than any floor value: [4](#0-3) . This is a real, unguarded default behavior — the pallet's own test `price_never_goes_to_zero_and_recovers` explicitly documents that with `sellout_price = 1`, the recovered price stays at `1` indefinitely across repeated sale cycles: [5](#0-4) . The `MinimumPrice` wrapper exists specifically to enforce a floor on top of `CenterTargetPrice`, confirming that `CenterTargetPrice` itself has no such floor by design: [6](#0-5) . This value then propagates into `new_sale.end_price`/`sellout_price` and into `PotentialRenewalRecord.price` used for lease renewal settlement: [7](#0-6) .

I was unable to fully trace the exact purchase-price mechanics (`sale_price`/`do_purchase` in `substrate/frame/broker/src/dispatchable_impls.rs`) within the available iterations to confirm the precise leadin-decay path by which an attacker drives the actual paid price for the "last core" down to a value like `1`, though the `leadin_factor_at` decay function and the pallet's own recovery test both corroborate that sub-10 sellout prices are a reachable, non-degenerate outcome of normal price decay during low-demand sales.

## Impact Explanation
This matches the "public underpriced work that degrades block production" impact category: an unprivileged actor can, through ordinary permissionless purchase/renewal extrinsics (no governance, no validator/relayer compromise, no leaked keys), anchor the Coretime market price for an entire chain to a near-zero value that persists indefinitely absent the opt-in `MinimumPrice` wrapper. This directly affects economic settlement of a scarce public resource (blockspace) rather than being a cosmetic or low-severity issue.

## Likelihood Explanation
The attack requires only a normal purchase transaction targeting the last/cheapest core of a sale when the leadin-decayed price is below `10` — a condition most likely at chain launch or during periods of low demand, consistent with the claim's own caveat. No privileged role, node compromise, or off-chain trust assumption is needed, making this readily reachable by any funded account.

## Recommendation
Replace the zero-guard fallback in `CenterTargetPrice::adapt_price` with a protocol-level minimum price (not opt-in via `MinimumPrice`), or bound the recovery value using a stable reference (e.g., previous `end_price`/`target_price`, or a hard floor) instead of directly re-adopting `sellout_price`. Alternatively, require runtimes to always compose `CenterTargetPrice` with `MinimumPrice` rather than allowing bare use of `CenterTargetPrice` as `T::PriceAdapter`.

## Proof of Concept
1. Configure `pallet-broker` with `type PriceAdapter = CenterTargetPrice<Balance>` (no `MinimumPrice` wrapper).
2. During a live sale's leadin decay, have an unprivileged account purchase the final core when the current price is `< 10` (e.g., pay `1`), setting `sellout_price = Some(1)` for that sale.
3. On the next `rotate_sale` call, `adapt_price` computes `FixedU64::from_rational(1,10).saturating_mul_int(1) == 0`, triggers the guard, and returns `AdaptedPrices { end_price: 1, target_price: 1 }` per [8](#0-7) .
4. The pallet's own unit test `price_never_goes_to_zero_and_recovers` demonstrates that repeating this cycle with `sellout_price = 1` keeps `end_price` pinned at `1` across at least 11 subsequent sale rotations: [5](#0-4) .
5. `PotentialRenewalRecord.price` for any lease expiring in that window is also set to `1` via [9](#0-8) , pricing lease renewals at a de minimis value.

	fn adapt_price(performance: SalePerformance<Balance>) -> AdaptedPrices<Balance> {
		let Some(sellout_price) = performance.sellout_price else {
			return AdaptedPrices {
				end_price: performance.end_price,
				target_price: FixedU64::from(10).saturating_mul_int(performance.end_price),
			};
		};

		let price = FixedU64::from_rational(1, 10).saturating_mul_int(sellout_price);
		let price = if price == Balance::zero() {
			// We could not recover from a price equal 0 ever.
			sellout_price
		} else {
			price
		};

		AdaptedPrices { end_price: price, target_price: sellout_price }
	}

impl<Balance: FixedPointOperand, MinPrice: Get<Balance>> AdaptPrice<Balance>
	for MinimumPrice<Balance, MinPrice>
{
	fn leadin_factor_at(when: FixedU64) -> FixedU64 {
		CenterTargetPrice::<Balance>::leadin_factor_at(when)
	}

	fn adapt_price(performance: SalePerformance<Balance>) -> AdaptedPrices<Balance> {
		let mut proposal = CenterTargetPrice::<Balance>::adapt_price(performance);
		let min_price = MinPrice::get();
		if proposal.end_price < min_price {
			proposal.end_price = min_price;
		}
		// Fix target price if necessary:
		if proposal.target_price < proposal.end_price {
			proposal.target_price = proposal.end_price;
		}
		proposal
	}
}

	fn price_never_goes_to_zero_and_recovers() {
		// Check price stays stable if sold at the optimal price:
		let sellout_price = 1;
		let mut performance = SalePerformance::new(Some(sellout_price), 1);
		for _ in 0..11 {
			let prices = CenterTargetPrice::adapt_price(performance);
			performance.sellout_price = Some(sellout_price);
			performance.end_price = prices.end_price;

			assert!(prices.end_price <= sellout_price);
			assert!(prices.end_price > 0);
		}
	}
