### Title
Handshake re-key path lacks proof-of-possession of the previously trusted key, enabling unauthenticated identity hijack - (File: stackslib/src/net/chat.rs)

### Summary
`ConversationP2P::validate_handshake` only performs a signature check against the *claimed* `node_public_key` when no key is cached yet (TOFU case), but performs no signature check against the previously cached key when `self.connection.get_public_key()` is `Some(old_pk)`. It merely checks address/port equality, which is itself skipped for inbound connections. `update_from_handshake_data` then unconditionally swaps in the new key and it is persisted via `neighbor.save_update()`.

### Finding Description
In `validate_handshake` [1](#0-0) , the `None` branch verifies the incoming handshake's signature against the newly claimed key (`handshake_data.node_public_key`), which is the correct TOFU behavior for a first-time handshake. The `Some(_)` branch, however, does not call `message.verify_secp256k1` against the cached `old_pk` at all — it only enforces that, for outbound connections, the self-reported `addrbytes`/`port` match the known peer address [2](#0-1) . For inbound conversations (`self.stats.outbound == false`, the attacker's normal posture connecting to a node's P2P port), this address check is entirely bypassed by the `self.stats.outbound &&` guard, leaving no verification whatsoever that the new handshake is authorized by `old_pk`.

The upstream gate in `handle_handshake` only blocks unauthenticated handshakes when the operator has explicitly set `disable_inbound_handshakes` [3](#0-2) ; by default this option is false, so an unauthenticated (or falsely-authenticated) handshake is still routed into `validate_handshake`.

Once `validate_handshake` returns `Ok(())`, `update_from_handshake_data` compares the new key against `self.connection.get_public_key()`, sets `updated = true`, and unconditionally calls `self.connection.set_public_key(Some(pubk.clone()))` — again with no proof that the sender controlled `old_pk` [4](#0-3) . This directly breaks the equality invariant that the public key trusted for a given peer identity should remain the same absent a signature chaining old_pk → new_pk.

### Impact Explanation
An attacker who has already established one authenticated handshake with a node (or who races into the position where a conversation object has a cached key) can subsequently send a second Handshake message on the same conversation signed by an entirely unrelated, attacker-controlled keypair. `update_from_handshake_data` swaps the trusted key, and this new key is persisted to the node's `PeerDB` via `neighbor.save_update()`, effectively hijacking the peer's persisted identity. This is an unauthenticated/unauthorized write to persistent peer state and matches the "Critical: unauthenticated/unauthorized write to state" impact category.

### Likelihood Explanation
The precondition is simply that the target conversation has previously cached a public key for the connection (i.e., at least one successful prior handshake occurred on that connection, the common steady-state for any established peer link), which is trivial for a remote, unprivileged attacker to arrange by initiating a normal handshake first. No secret, admin role, or privileged access is required — only the ability to open a TCP connection to the node's P2P port and send two Handshake messages. The `disable_inbound_handshakes` option must be left at its default (`false`) for the second, unauthenticated handshake to reach `validate_handshake`, which is the default operational posture for public peers.

### Recommendation
In `validate_handshake`'s `Some(_)` branch, when a cached public key already exists for the conversation, require that the incoming message's signature verify against the *previously cached* key (`old_pk`) — not merely the newly claimed key — before permitting any key transition. If the node wishes to support key rotation, require that the handshake be signed by `old_pk` while announcing `new_pk` in the payload (proof of possession of the old key), rather than accepting a message merely self-signed by the new key.

### Proof of Concept
Rust test in `stackslib/src/net/chat.rs` test module, modeled on `convo_handshake_self_1`:
1. Establish `convo_1` and `convo_2` as in the existing re-key tests, complete an initial successful `Handshake`/`HandshakeAccept` exchange so that `convo_2.connection.get_public_key() == Some(local_peer_1_pubkey)`.
2. Construct a second `StacksMessage::Handshake` whose `HandshakeData.node_public_key` is a brand-new, attacker-generated keypair (`attacker_pk`), and sign the message with the attacker's *own* private key (not `local_peer_1`'s private key), so no proof-of-possession of `local_peer_1`'s key exists.
3. Call `convo_2.validate_handshake(...)` (or `handle_handshake` with `authenticated=false` and default `disable_inbound_handshakes=false`) and assert it returns `Ok(())`.
4. Call `convo_2.update_from_handshake_data(...)` and assert `self.connection.get_public_key() == Some(attacker_pk)`, demonstrating the key swap succeeded despite no cryptographic link between `attacker_pk` and `local_peer_1_pubkey`.

    fn validate_handshake(
        &mut self,
        local_peer: &LocalPeer,
        chain_view: &BurnchainView,
        message: &mut StacksMessage,
    ) -> Result<(), net_error> {
        let handshake_data = match message.payload {
            StacksMessageType::Handshake(ref mut data) => data.clone(),
            _ => panic!("Message is not a handshake"),
        };

        match self.connection.get_public_key() {
            None => {
                // if we don't yet have a public key for this node, verify the message.
                // if it's improperly signed, it's probably a poorly-timed re-key request (but either way the message should be rejected)
                message
                    .verify_secp256k1(&handshake_data.node_public_key)
                    .map_err(|_e| {
                        debug!(
                            "{:?}: invalid handshake: not signed with given public key",
                            &self
                        );
                        net_error::InvalidMessage
                    })?;
            }
            Some(_) => {
                // for outbound connections, the self-reported address must match socket address if we already have a public key.
                // (not the case for inbound connections, since the peer socket address we see may
                // not be the same as the address the remote peer thinks it has).
                // The only exception to this is if the remote peer does not yet know its own
                // public IP address, in which case, its handshake addrbytes will be the
                // any-network bind address (0.0.0.0 or ::)
                if self.stats.outbound
                    && (!handshake_data.addrbytes.is_anynet()
                        && (self.peer_addrbytes != handshake_data.addrbytes
                            || self.peer_port != handshake_data.port))
                {
                    // wrong peer address
                    debug!(
                        "{:?}: invalid handshake -- wrong addr/port ({:?}:{:?})",
                        &self, &handshake_data.addrbytes, handshake_data.port
                    );
                    return Err(net_error::InvalidHandshake);
                }
            }
        };

    pub fn update_from_handshake_data(
        &mut self,
        preamble: &Preamble,
        handshake_data: &HandshakeData,
    ) -> Result<bool, net_error> {
        let pubk = handshake_data
            .node_public_key
            .to_public_key()
            .map_err(|e| net_error::DeserializeError(e.into()))?;

        self.peer_version = preamble.peer_version;
        self.peer_network_id = preamble.network_id;
        self.peer_services = handshake_data.services;
        self.peer_expire_block_height = handshake_data.expire_block_height;
        self.handshake_addrbytes = handshake_data.addrbytes.clone();
        self.handshake_port = handshake_data.port;
        self.data_url = handshake_data.data_url.clone();

        let mut updated = false;
        let cur_pubk_opt = self.connection.get_public_key();
        if let Some(cur_pubk) = cur_pubk_opt {
            if pubk != cur_pubk {
                debug!(
                    "{:?}: Upgrade key {:?} to {:?} expires {:?}",
                    &self,
                    &to_hex(&cur_pubk.to_bytes_compressed()),
                    &to_hex(&pubk.to_bytes_compressed()),
                    self.peer_expire_block_height
                );
                updated = true;
            }
        }

        self.connection.set_public_key(Some(pubk.clone()));

        Ok(updated)
    }
