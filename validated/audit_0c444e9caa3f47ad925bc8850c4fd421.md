### Title
Per-connection stream throttling allows unstaked-peer aggregate throughput to scale linearly with `max_connections_per_unstaked_peer`, exceeding `MAX_UNSTAKED_TPS` - ([File: streamer/src/nonblocking/stream_throttle.rs])

### Summary
`throttle_stream` and `ConnectionStreamCounter` enforce the unstaked stream budget (`MAX_UNSTAKED_TPS`) per QUIC connection rather than per source IP/peer, and `available_load_capacity_in_throttling_duration` returns a fixed per-connection quota independent of how many concurrent connections the same unstaked peer holds. Because an unstaked IP is allowed up to `DEFAULT_MAX_QUIC_CONNECTIONS_PER_UNSTAKED_PEER` (8) simultaneous connections, an attacker can multiply its effective throughput by up to 8x the intended `MAX_UNSTAKED_TPS` simply by using multiple concurrent connections, without needing to defeat any connection-rate limiter.

### Finding Description
`StakedStreamLoadEMA::new` computes `max_unstaked_load_in_throttling_window = MAX_UNSTAKED_TPS * STREAM_THROTTLING_INTERVAL_MS / 1000` (200 * 100 / 1000 = 20 streams per 100ms) [1](#0-0) [2](#0-1) . This value is returned unconditionally for `ConnectionPeerType::Unstaked` in `available_load_capacity_in_throttling_duration`, with no dependence on the number of connections the peer/IP currently holds [3](#0-2) .

Enforcement happens inside `throttle_stream`, which reads/writes state from a `ConnectionStreamCounter` that is created fresh per connection (`|| Arc::new(ConnectionStreamCounter::new())`) in `SwQos::cache_new_connection` and stored keyed by `(ip, pubkey)`+stable connection id in the `ConnectionTable` [4](#0-3) . Each connection's `ConnectionStreamCounter` independently tracks and resets its own `stream_count` every `STREAM_THROTTLING_INTERVAL` (100ms) via `reset_throttling_params_if_needed` [5](#0-4) , and `throttle_stream` only compares that connection's own count against `max_streams_per_throttling_interval` before sleeping the caller [6](#0-5) .

Since `SwQosConfig::max_connections_per_unstaked_peer` defaults to `DEFAULT_MAX_QUIC_CONNECTIONS_PER_UNSTAKED_PEER = 8` [7](#0-6)  and this is the concurrent-connection cap enforced per (ip, pubkey) key in `cache_new_connection`/`try_add_connection` [8](#0-7) , an unstaked attacker that establishes up to 8 concurrent connections from one IP gets 8 independent 20-streams/100ms budgets = 160 streams/100ms = 1600 TPS, 8x the intended 200 TPS unstaked ceiling. No aggregate per-IP stream/token bucket exists anywhere in `swqos.rs` or `stream_throttle.rs` to cap the sum across connections from the same source.

The connection admission path does have a per-IP *connection-creation* rate limiter (`ConnectionRateLimiter`, default 8/min with a 10x burst = 80) enforced in `run_server`/`setup_connection` [9](#0-8) [10](#0-9) , but this only throttles the *rate of new connections*, not the aggregate stream throughput of already-established connections. Simply opening and holding 8 concurrent connections (well within the burst allowance) is sufficient to realize the 8x multiplier — connection churn is not even required, though repeated churn (within the burst budget) works equally well.

### Impact Explanation
This is a QoS/SWQoS evasion: the unstaked-peer TPS ceiling (`MAX_UNSTAKED_TPS = 200`), which is meant to bound the aggregate unprivileged/unstaked ingress rate accepted by a leader's TPU, can be inflated by up to `max_connections_per_unstaked_peer` (default 8x, i.e., up to ~1600 TPS) from a single attacker-controlled IP with zero stake. This lets an unstaked attacker consume a disproportionate share of leader ingress bandwidth/CPU (sigverify, banking-stage intake) relative to what the unstaked quota is designed to allow, at the expense of legitimate staked traffic capacity — a QoS-evasion category issue rather than a memory-safety or consensus-breaking bug.

### Likelihood Explanation
Fully reachable by an unprivileged, unstaked remote client with no special preconditions beyond opening ordinary QUIC connections to the leader's public TPU port. The attacker only needs to hold up to `DEFAULT_MAX_QUIC_CONNECTIONS_PER_UNSTAKED_PEER` (8) concurrent connections, which is within default limits and does not require defeating the connection-rate limiter (well under its burst allowance of 80). This is deterministic and trivially repeatable, requiring no timing races or privileged control.

### Recommendation
Track and enforce stream-throttling state (`stream_count`/token bucket) at the granularity of the unstaked source IP (or `(ip, pubkey)` for staked/unstaked-but-known peers) rather than per individual QUIC connection, e.g., by keying a shared `ConnectionStreamCounter`/token bucket in `SwQos` by remote IP for unstaked peers, so `available_load_capacity_in_throttling_duration` for `ConnectionPeerType::Unstaked` is divided among all concurrent connections from that IP instead of being granted in full to each one.

### Proof of Concept
Integration test plan (extending existing test harness in `streamer/src/nonblocking/quic.rs`, e.g. patterned after `test_throttling_check_no_packet_drop`):
1. Spawn a QUIC streamer with `QuicStreamerConfig::default_for_tests()` and `SwQosConfig { max_connections_per_unstaked_peer: 8, ..Default::default() }`.
2. Open 8 concurrent unstaked client connections from the same source IP (`make_client_endpoint` x8) instead of 1.
3. From each connection concurrently send `expected_num_txs = 20` uni streams per 100ms throttling window (i.e., each individually respects its own per-connection quota).
4. Measure aggregate packets/sec received by the server across all 8 connections over a fixed window.
5. Assert (expected to fail today): `total_packets_per_sec <= MAX_UNSTAKED_TPS` (200); actual observed throughput will be ~`8 * 200 = 1600` TPS, demonstrating the per-IP aggregate limit is not enforced, only the per-connection limit is.

    pub(crate) fn available_load_capacity_in_throttling_duration(
        &self,
        peer_type: ConnectionPeerType,
        total_stake: u64,
    ) -> u64 {
        match peer_type {
            ConnectionPeerType::Unstaked => self.max_unstaked_load_in_throttling_window,
            ConnectionPeerType::Staked(stake) => {
                if self.staked_throttling_enabled.load(Ordering::Relaxed) {
                    // 1 is added to `max_unstaked_load_in_throttling_window` to guarantee that staked
                    // clients get at least 1 more number of streams than unstaked connections.
                    self.max_staked_load_in_throttling_window
                        .saturating_mul(stake)
                        .checked_div(total_stake)
                        .unwrap_or(self.max_unstaked_load_in_throttling_window + 1)
                        .max(self.max_unstaked_load_in_throttling_window + 1)
                } else {
                    self.max_staked_load_in_throttling_window
                }
            }
        }
    }

    pub(crate) fn reset_throttling_params_if_needed(&self) -> tokio::time::Instant {
        let last_throttling_instant = *self.last_throttling_instant.read().unwrap();
        if tokio::time::Instant::now().duration_since(last_throttling_instant)
            > STREAM_THROTTLING_INTERVAL
        {
            let mut last_throttling_instant = self.last_throttling_instant.write().unwrap();
            // Recheck as some other thread might have done throttling since this thread tried to acquire the write lock.
            if tokio::time::Instant::now().duration_since(*last_throttling_instant)

                *last_throttling_instant = tokio::time::Instant::now();

pub(crate) async fn throttle_stream(
    stats: &StreamerStats,
    peer_type: ConnectionPeerType,
    remote_addr: std::net::SocketAddr,
    stream_counter: &Arc<ConnectionStreamCounter>,
    max_streams_per_throttling_interval: u64,
) {
    let throttle_interval_start = stream_counter.reset_throttling_params_if_needed();
    let streams_read_in_throttle_interval = stream_counter.stream_count.load(Ordering::Relaxed);
    if streams_read_in_throttle_interval >= max_streams_per_throttling_interval {
        // The peer is sending faster than we're willing to read. Sleep for what's
        // left of this read interval so the peer backs off.
        let throttle_duration =
            STREAM_THROTTLING_INTERVAL.saturating_sub(throttle_interval_start.elapsed());

        if !throttle_duration.is_zero() {
            debug!(
                "Throttling stream from {remote_addr:?}, peer type: {peer_type:?}, \
                 max_streams_per_interval: {max_streams_per_throttling_interval}, \
                 read_interval_streams: {streams_read_in_throttle_interval} throttle_duration: \
                 {throttle_duration:?}"
            );
            stats.throttled_streams.fetch_add(1, Ordering::Relaxed);
            match peer_type {
                ConnectionPeerType::Unstaked => {
                    stats
                        .throttled_unstaked_streams
                        .fetch_add(1, Ordering::Relaxed);
                }
                ConnectionPeerType::Staked(_) => {
                    stats
                        .throttled_staked_streams
                        .fetch_add(1, Ordering::Relaxed);
                }
            }
            sleep(throttle_duration).await;
        }
    }
