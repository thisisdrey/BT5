### Title
Missing pool-ownership verification in `LinkRepositoryToObjectPool` allows cross-repository object disclosure - (File: `internal/gitaly/service/objectpool/link.go`)

### Summary
The `setPool` bug in the reference report stems from performing a state-changing "effect" (fund transfer / balance mutation) without re-validating that the caller-supplied data is trustworthy at the point the effect is applied, allowing an attacker to shape state through a value they fully control. The closest reachable analog in Gitaly is in the `ObjectPoolService.LinkRepositoryToObjectPool` RPC: any caller that can reach the RPC supplies both the `repository` and the `object_pool` fields, and Gitaly links them together — granting the repository permanent, deduplicated read access to every object in the pool — without ever verifying that the two are actually related (e.g. that the pool was created *from* that repository, or that the caller is authorized to attach to that specific pool).

### Finding Description
The handler only checks that the target repository exists and that the `object_pool` field points to a syntactically/structurally valid pool repository: [1](#0-0) 
`poolForRequest` resolves the pool purely from the `object_pool.repository` path supplied in the request and validates only that it *is* a pool directory (`storage.IsPoolRepository`) and that it exists (`ObjectPool.IsValid`): [2](#0-1) [3](#0-2) 

There is no check anywhere in this path that the object pool named in the request is the pool that was actually created from (or is otherwise authorized for) the target `repository`. `objectpool.Link` then proceeds straight from this unauthenticated “pool is *a* pool” check to the effect — writing the pool's path into the repository's `objects/info/alternates` file, which is the Git mechanism that makes every object in the pool directly readable by the repository: [4](#0-3) 

This mirrors the `setPool` root cause: a caller-supplied value (`p.lender`/`p.poolBalance` in the token contract; `object_pool` here) is used to drive an irreversible effect (`transfer`; alternates linking) without re-verifying it belongs to the expected trust boundary at that exact step.

### Impact Explanation
Once linked, `git` treats the pool's object database as part of the repository's own search path — any blob, tree, or commit in the pool becomes retrievable through the linked repository via ordinary read RPCs (e.g. `GetBlob`, `TreeEntry`, `GetCommit`), regardless of whether the pushing/forking user has any right to see the pool's private repository contents. This is a concrete cross-repository object disclosure: private source-repository history could be exfiltrated by any actor who can name/guess a pool's relative path and invoke this mutator RPC against a repository they control.

### Likelihood Explanation
`LinkRepositoryToObjectPool` is a `MUTATOR`-classified RPC on the `ObjectPoolService`, reachable through Gitaly's normal gRPC surface in the same class of RPCs invoked as part of ordinary fork/import workflows (`proto/objectpool.proto`, lines documenting the pool lifecycle): [5](#0-4) 
Because Gitaly performs no server-side check binding the `object_pool` value to the `repository` being linked, the only barrier is whatever authorization exists in a calling layer (e.g. GitLab Rails) — Gitaly itself does not enforce this invariant, so any code path that lets a user influence the `object_pool.repository.relative_path` field of this request (directly or via a less-carefully-checked upstream feature) is sufficient to trigger it.

### Recommendation
Before linking, verify that the `object_pool` supplied in the request is the pool actually associated with the target repository's fork network / origin (e.g. via the same persisted pool-membership record used by `CreateObjectPool`/`ScanPoolMetadata`), and reject the request otherwise. This restores the missing "Check" step before the "Effect" of granting cross-repository object access, consistent with CEI principles.

### Proof of Concept
1. Attacker creates or forks repository `R1` under their control.
2. Attacker learns/guesses the relative path of an unrelated object pool `P` (pools live at deterministic hashed paths under `@pools/xx/yy/<hash>.git`, and pool disk paths are also exposed via replication/administrative RPCs such as `ScanPoolMetadata`): [6](#0-5) 
3. Attacker issues `LinkRepositoryToObjectPool{ repository: R1, object_pool: P }`.
4. Gitaly links `R1` to `P` without validating that `P` was created from `R1` or that the attacker has any right to that pool's contents: [1](#0-0) 
5. Attacker now performs `GetBlob`/`TreeEntry`/`GetCommit` against `R1` for object IDs belonging to `P`; because the alternates file makes `P`'s objects part of `R1`'s object database, Gitaly serves them successfully, disclosing objects from the unrelated (potentially private) pool.

func (s *server) LinkRepositoryToObjectPool(ctx context.Context, req *gitalypb.LinkRepositoryToObjectPoolRequest) (*gitalypb.LinkRepositoryToObjectPoolResponse, error) {
	repository := req.GetRepository()
	if err := s.locator.ValidateRepository(ctx, repository); err != nil {
		return nil, structerr.NewInvalidArgument("%w", err)
	}

	pool, err := s.poolForRequest(ctx, req)
	if err != nil {
		return nil, err
	}

	repo := s.localRepoFactory.Build(repository)

	if err := pool.Link(ctx, repo); err != nil {
		return nil, structerr.NewInternal("%w", err)
	}

	return &gitalypb.LinkRepositoryToObjectPoolResponse{}, nil
}

func (s *server) poolForRequest(ctx context.Context, req PoolRequest) (*objectpool.ObjectPool, error) {
	pool, err := objectpool.FromProto(ctx, s.logger, s.locator, s.gitCmdFactory, s.catfileCache, s.txManager, s.housekeepingManager, req.GetObjectPool())
	if err != nil {
		if errors.Is(err, objectpool.ErrInvalidPoolDir) {
			return nil, errInvalidPoolDir
		}

		if errors.Is(err, objectpool.ErrInvalidPoolRepository) {
			return nil, structerr.NewFailedPrecondition("%w", err)
		}

		return nil, structerr.NewInternal("%w", err)
	}

	return pool, nil
}

// FromProto returns an object pool object from its Protobuf representation. This function verifies
// that the object pool exists and is a valid pool repository.
func FromProto(
	ctx context.Context,
	logger log.Logger,
	locator storage.Locator,
	gitCmdFactory gitcmd.CommandFactory,
	catfileCache catfile.Cache,
	txManager transaction.Manager,
	housekeepingManager housekeepingmgr.Manager,
	proto *gitalypb.ObjectPool,
) (*ObjectPool, error) {
	poolPath, err := locator.GetRepoPath(ctx, proto.GetRepository(), storage.WithRepositoryVerificationSkipped())
	if err != nil {
		return nil, err
	}

	if !storage.IsPoolRepository(proto.GetRepository()) {
		// When creating repositories in the ObjectPool service we will first create the
		// repository in a temporary directory. So we need to check whether the path we see
		// here is in such a temporary directory and let it pass.
		tempDir, err := locator.TempDir(proto.GetRepository().GetStorageName())
		if err != nil {
			return nil, fmt.Errorf("getting temporary storage directory: %w", err)
		}

		if !strings.HasPrefix(poolPath, tempDir) {
			return nil, ErrInvalidPoolDir
		}
	}

	pool := &ObjectPool{
		Repo:                localrepo.New(logger, locator, gitCmdFactory, catfileCache, proto.GetRepository()),
		logger:              logger,
		locator:             locator,
		gitCmdFactory:       gitCmdFactory,
		txManager:           txManager,
		housekeepingManager: housekeepingManager,
	}

	if !pool.IsValid(ctx) {
		return nil, ErrInvalidPoolRepository
	}

	return pool, nil
}

// Link will link the given repository to the object pool. This is done by writing the object pool's
// path relative to the repository into the repository's "alternates" file. This does not trigger
// deduplication, which is the responsibility of the caller.
func Link(ctx context.Context, pool, repo *localrepo.Repo, txManager transaction.Manager) (returnedErr error) {
	altPath, err := repo.InfoAlternatesPath(ctx)
	if err != nil {
		return err
	}

	expectedRelPath, err := getRelativeObjectPath(ctx, pool, repo)
	if err != nil {
		return err
	}

	linked, err := linkedToRepository(ctx, pool, repo)
	if err != nil {
		return err
	}

	if linked {
		// When the repository is already linked to the repository, cast a vote to ensure the
		// repository is consistent with the other replicas.
		if err := transaction.VoteOnContext(ctx, txManager, voting.VoteFromData([]byte("repository linked")), voting.Synchronized); err != nil {
			return fmt.Errorf("vote on linked repository: %w", err)
		}

		return nil
	}

	alternatesWriter, err := safe.NewLockingFileWriter(altPath)
	if err != nil {
		return fmt.Errorf("creating alternates writer: %w", err)
	}
	defer func() {
		if err := alternatesWriter.Close(); err != nil && returnedErr == nil {
			returnedErr = fmt.Errorf("closing alternates writer: %w", err)
		}
	}()

	if _, err := io.WriteString(alternatesWriter, expectedRelPath); err != nil {
		return fmt.Errorf("writing alternates: %w", err)
	}

	if err := transaction.CommitLockedFile(ctx, txManager, alternatesWriter); err != nil {
		return fmt.Errorf("committing alternates: %w", err)
	}

	if tx := storage.ExtractTransaction(ctx); tx != nil {
		alternatesRelativePath, err := filepath.Rel(tx.FS().Root(), altPath)
		if err != nil {
			return fmt.Errorf("rel alternates file: %w", err)
		}

		if err := tx.FS().RecordFile(alternatesRelativePath); err != nil {
			return fmt.Errorf("record alternates file")
		}
	}

	return removeMemberBitmaps(ctx, pool, repo)

func processPoolMemberFunc(
	ctx context.Context,
	storagePath, storageName string,
	poolStore relational.PoolStore,
	logger log.Logger,
	stream gitalypb.InternalGitaly_ScanPoolMetadataServer,
) func(relPath string, _ fs.FileInfo) error {
	invalidPools := make(map[string]bool)

	return func(relPath string, fi fs.FileInfo) error {
		repoPath := filepath.Join(storagePath, relPath)

		altInfo, err := stats.AlternatesInfoForRepository(repoPath)
		if err != nil {
			return fmt.Errorf("read alternates for %q: %w", relPath, err)
		}

		if !altInfo.Exists || len(altInfo.ObjectDirectories) == 0 {
			return nil
		}

		absPoolPaths := altInfo.AbsoluteObjectDirectories()
		if len(absPoolPaths) == 0 {
			return nil
		}

		poolObjectDir := absPoolPaths[0]
		poolRepoPath := filepath.Dir(poolObjectDir)

		poolDiskPath, err := filepath.Rel(storagePath, poolRepoPath)
		if err != nil {
			return fmt.Errorf("compute relative path for pool %q (repo %q): %w", poolRepoPath, relPath, err)
		}
		poolDiskPath = filepath.ToSlash(poolDiskPath)

		// We could encounter the same invalid pool multiple times.
		if invalidPools[poolDiskPath] {
			recordBrokenPool(ctx, poolStore, logger, storageName, relPath, poolDiskPath)
			return nil
		}

		if err := storage.ValidateGitDirectory(poolRepoPath); err != nil {
			invalidPools[poolDiskPath] = true
			recordBrokenPool(ctx, poolStore, logger, storageName, relPath, poolDiskPath)
			return nil
		}

		return stream.Send(&gitalypb.ScanPoolMetadataResponse{
			RelativePath: relPath,
			PoolDiskPath: poolDiskPath,
		})
	}
