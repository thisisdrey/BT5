### Title
`DebtToken.balanceOf` and `Pool.debtOf` round down accrued debt, underestimating liabilities used by `issue`/`liquidate` health checks — (File: contracts/DebtToken.sol)

### Summary
The Unitas report flags liabilities computed with `Rounding.Down`, underestimating what the protocol is owed. Metronome has the same bug class: an account's debt (the protocol's liability side of the solvency check) is computed with floor division in `DebtToken.balanceOf` and in `Pool.debtOf` via `quoteTokenToUsd`, and the result feeds the health check `debtPositionOf` that gates both `issue` and `liquidate`. Debt is therefore systematically under-reported, which favors the borrower over the protocol — exactly the "round liabilities down" class.

### Finding Description
`DebtToken.balanceOf` computes principal + accrued interest with a plain floor division:

```solidity
return (_principal * _debtIndex) / debtIndexOf[account_];
``` [1](#0-0) 

`Pool.debtOf` then converts that floored debt-token balance to USD with `masterOracle().quoteTokenToUsd`, which (per `MasterOracleMock` and the oracle convention `amount * price / 10^decimals`) also truncates:

```solidity
_debtInUsd += _masterOracle.quoteTokenToUsd(
    address(_debtToken.syntheticToken()),
    _debtToken.balanceOf(account_)
);
``` [2](#0-1) 

`debtPositionOf` uses this `_debtInUsd` for both the solvency invariant `_isHealthy = _debtInUsd <= _issuableLimitInUsd` and the headroom `_issuableInUsd` [3](#0-2) . Two public entry points consume it:

- `DebtToken.issue` → `debtPositionOf` → `quoteUsdToToken(_issuableInUsd)`; the inflated `_issuableInUsd` plus the floor-rounded `quoteUsdToToken` cap lets a caller mint marginally more synth than collateral factors permit [4](#0-3) .
- `Pool.liquidate` → `debtPositionOf`; a position that is exactly at the boundary can be reported healthy (debt rounded down below the limit), reverting with `PositionIsHealthy` [5](#0-4) .
- The `maxLiquidable` bound `amountToRepay_.wadDiv(_debtTokenBalance) > maxLiquidable` also uses the floored `balanceOf`, slightly loosening the cap [6](#0-5) .

Both rounding operations favor the debtor: `balanceOf` loses up to ~1 wei of debt per account per query, and `quoteTokenToUsd` loses up to ~1 wei of USD per debt token. Summed across `debtTokensOfAccount`, the underestimate grows with the number of debt tokens held.

### Impact Explanation
The protocol's liabilities are under-estimated in the solvency check, mirroring the Unitas `_getTotalLiabilities` issue. Concretely: (1) `issue` can mint dust amounts of synth beyond the true collateral-factor limit; (2) borderline-underwater positions can revert liquidation as "healthy," delaying bad-debt cleanup. The per-call magnitude is small (sub-wei-per-unit dust), but it is systematic, grows with token count, and the rounding direction is wrong — liabilities should round up. No privileged role, oracle manipulation, or governance action is required; any EOA calling `issue`/`liquidate` on a boundary position hits it.

### Likelihood Explanation
The rounding-down is unconditional — every `balanceOf`, `debtOf`, and `debtPositionOf` call truncates. Exploiting it for material profit requires positions engineered to sit exactly at the collateral-factor boundary, and the extractable value per call is bounded by the accumulated rounding dust, so real-world impact is limited. The bug class is confirmed present; severity is low-to-medium rather than high.

### Recommendation
Round liabilities up:

- In `DebtToken.balanceOf`, use ceiling division: `(_principal * _debtIndex + debtIndexOf[account_] - 1) / debtIndexOf[account_]` (or a `wadMulUp`-style helper).
- In `Pool.debtOf`, request a round-up quote (or add `+1` post-division) so `_debtInUsd` is an upper bound, and conversely round collateral `depositOf` down so `_issuableLimitInUsd` is a lower bound.
- Apply the same asymmetric rounding inside `quoteLiquidateIn`/`quoteLiquidateOut` (already using half-up `wadMul`/`wadDiv` [7](#0-6) ) so the seize amount never under-covers the repaid debt.

### Proof of Concept
```solidity
// Foundry-style PoC sketch (contracts/ test harness, e.g. test/foundry/)
function test_debt_rounded_down() external {
    // alice deposits collateral and issues msUSD via msUSDDebt.issue(...)
    // warp so interest accrues: principal * debtIndex / debtIndexOf truncates

    uint256 debtBalance = msUSDDebt.balanceOf(alice);          // floor-divided
    uint256 exactDebt   = (principal * debtIndex + debtIndexOfAlice - 1)
                          / debtIndexOfAlice;                  // true debt (ceil)
    assertLt(debtBalance, exactDebt);                          // debt understated

    // debtPositionOf uses the understated debt:
    (bool healthy,, uint256 debtInUsd,, uint256 issuable) = pool.debtPositionOf(alice);
    // debtInUsd < true USD debt => issuable inflated by the rounding dust

    // Boundary case: craft collateral so true debt is just above issuableLimit.
    // pool.liquidate(...) reverts PositionIsHealthy while position is actually
    // underwater by the sub-wei rounding amount.
    vm.expectRevert(Pool.PositionIsHealthy.selector);
    pool.liquidate(msUSD, alice, amountToRepay, msdVaUSDC);
}
```

Reproduction path: `DebtToken.issue` → `Pool.debtPositionOf` → `Pool.debtOf` → `DebtToken.balanceOf` (floor div) and `IMasterOracle.quoteTokenToUsd` (floor div). Both truncation points underestimate the liability consumed by the health check [8](#0-7) [9](#0-8) .
