### Title
Zip Slip via partial-path prefix bypass in ijar's zip extractor - (File: third_party/ijar/zip_main.cc)

### Summary
The zip-extraction containment check in `UnzipProcessor::Process` in `third_party/ijar/zip_main.cc` compares a normalized target path against the normalized output root using a raw string-prefix comparison rather than a path-boundary-aware comparison. This is structurally the same bug class as CVE-2023-28465 (HAPI FHIR `TerminologyCacheManager`): a `startsWith`-style substring check without a trailing separator, which can be defeated by a sibling directory whose name has the root directory's name as a proper string prefix.

### Finding Description
`UnzipProcessor::Process` builds the destination path by concatenating the (attacker-controlled) zip entry name with the extraction root via `concat_path`, then normalizes both the target path and the root with `normalize_path`, and finally checks containment with: [1](#0-0) 

The check is:
```cpp
std::string normalized_root = normalize_path(output_root_);
std::string normalized = normalize_path(path);
if (normalized.compare(0, normalized_root.size(), normalized_root) != 0) {
  // reject
}
```
This is a bare prefix comparison — the same anti-pattern flagged in the HAPI FHIR advisory (`userControlled.startsWith(root)`). Because `normalized_root` is not slash-terminated before the comparison, a zip entry name containing `..` segments can be normalized to a path in a sibling directory whose name merely starts with the same characters as `output_root_` (e.g. `output_root_` = `/tmp/extract`, entry name resolving after `..` traversal to `/tmp/extractEVIL/payload`), and the prefix check `"/tmp/extractEVIL/payload".compare(0, len("/tmp/extract"), "/tmp/extract") == 0` incorrectly succeeds, allowing the write to land outside the intended extraction directory.

The existing regression test `test_no_path_traversal` in `third_party/ijar/test/zip_test.sh` only exercises a simple `..`-escape case, not the sibling-directory partial-path bypass described by CVE-2023-28465, so it does not validate against this specific class of bypass: [2](#0-1) 

### Impact Explanation
The `ijar` zipper/unzipper is used by Bazel's build tooling to extract zip archives (e.g. embedded tools, jar processing, archive extraction paths that route through this component). An attacker who controls the contents of a zip archive consumed by this extractor (e.g. a malicious jar/zip fetched or processed during a build) can craft entry names that, after `..`-normalization, resolve into a sibling directory of the extraction root whose name shares the root's name as a prefix, bypassing the containment check and writing files outside the intended output directory — a classic Zip Slip / arbitrary file write outside the sandboxed extraction root.

### Likelihood Explanation
Requires the attacker to control zip entry names in an archive that is extracted by this code path, and requires a sibling directory to exist (or be creatable) whose name is a superstring of the root directory name. This is a narrower precondition than a generic Zip Slip, but it is exactly the bypass class documented in the referenced advisory, and the existing test suite does not cover it, so the containment check as written does not defend against it.

### Recommendation
Replace the raw prefix comparison with a path-boundary-safe check, e.g. ensure `normalized_root` is slash-terminated before comparison (or compare using `std::filesystem::path` / segment-wise comparison), matching the fix pattern recommended in the referenced advisory (`file.getCanonicalFile().toPath().startsWith(BASE_DIRECTORY)`)—i.e., check `normalized == normalized_root || normalized.compare(0, normalized_root.size()+1, normalized_root + "/") == 0`.

### Proof of Concept
Construct a zip archive with an entry name such as `../extractEVIL/payload` (or an equivalent sequence of `..` segments) and extract it with the `ijar` unzipper (`zipper x`) into an output root `/tmp/extract` where a sibling directory `/tmp/extractEVIL` exists or is created by the archive itself. After `concat_path` and `normalize_path`, the resulting path `/tmp/extractEVIL/payload` passes the `compare(0, normalized_root.size(), normalized_root)` check because `"/tmp/extractEVIL/payload"` has `"/tmp/extract"` as a literal prefix, causing the file to be written outside `/tmp/extract`. This can be encoded as a `src/test/shell/bazel` shell test analogous to `test_no_path_traversal` in `third_party/ijar/test/zip_test.sh`, but using a crafted entry name that resolves to a sibling-prefix directory rather than a simple `../` escape, and asserting the file was **not** written outside the extraction root.
