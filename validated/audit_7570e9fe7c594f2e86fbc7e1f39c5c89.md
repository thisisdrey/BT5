### Title
`DebtToken.burn` skips `accrueInterest()`, rebasing a liquidated account's principal against a stale `debtIndex` and inflating its remaining debt - (File: contracts/DebtToken.sol)

### Summary
Every mutating entry point on `DebtToken` (`issue`, `repay`, `repayAll`, `mint`, `flashIssue`) refreshes the interest accumulator via `accrueInterest()` before touching `principalOf`/`debtIndexOf`. The pool-facing `burn(address from_, uint256 amount_)` does not. When `Pool.liquidate` burns a victim's debt through this path, `_burn` computes the balance with the *up-to-date* (virtual) index but persists `debtIndexOf[account_] = debtIndex` using the stale stored index — the same "verify/act on an outdated state snapshot" class as the Carapace report.

### Finding Description
- `burn` is the only state-mutating function that does not call `accrueInterest()` first [1](#0-0) 
- `_burn` reads `_accountBalance = balanceOf(account_)`, which uses the *freshly computed* index from `_calculateInterestAccrual()` [2](#0-1) 
- It then writes `principalOf[account_] = _accountBalance - amount_` but stores `debtIndexOf[account_] = debtIndex`, the stale storage value (not the fresh `_debtIndex`) [3](#0-2) 
- Since stale `debtIndex` ≤ fresh index, subsequent `balanceOf` calls multiply the remaining principal by `currentIndex / staleIndex` instead of `currentIndex / freshIndex`, permanently inflating the victim's remaining debt beyond actual interest accrual [4](#0-3) 
- Meanwhile `totalSupply_ -= amount_` shrinks supply by the true amount, so the sum of user debts no longer equals supply — the excess debt is unbacked (no corresponding synthetic token or fee was minted).

### Impact Explanation
The liquidated victim's remaining debt is inflated relative to real accrued interest, forcing them to overpay on `repay`/`repayAll` and breaking the debt-vs-synth-supply identity (unbacked debt is created). The longer `accrueInterest()` has gone uncalled when liquidation occurs, the larger the discrepancy.

### Likelihood Explanation
Reachable by any unprivileged liquidator through the public `Pool.liquidate` → `DebtToken.burn` path; `burn` has no `accrueInterest()` call and nothing forces accrual beforehand. Exploitation is passive — it simply requires liquidation between accruals — but the benefit accrues to the protocol/fee side rather than the liquidator, and the harm lands on the liquidated account, so impact is bounded to overcharged debt rather than direct theft by the caller.

### Recommendation
Call `accrueInterest()` at the top of `burn` (and inside `_burn` for defense-in-depth), or store the freshly computed `_debtIndex` into `debtIndexOf[account_]` instead of the stale storage value.

### Proof of Concept
Hardhat sketch (following the existing `DebtToken.test.ts` setup):
```ts
// user deposits collateral and issues debt
await msUSDDebt.connect(user).issue(parseEther('100'), user.address)
await msUSDDebt.updateInterestRate(parseEther('0.1')) // 10%
await time.increase(SECONDS_PER_YEAR) // ~110 debt, debtIndex storage still stale

// liquidator triggers Pool.liquidate without anyone calling accrueInterest()
await pool.connect(liq).liquidate(msdMET.address, user.address, repayAmt, msUSD.address)

// victim's remaining debt is higher than (freshAccruedBalance - repayAmt)
// because debtIndexOf was reset to the stale stored debtIndex
const remaining = await msUSDDebt.balanceOf(user.address)
// remaining > expected  -> inflated by factor freshIndex/staleIndex
```
Note: I was unable to confirm within my iteration budget the exact `Pool.liquidate` internals and whether it (or an upstream call) already invokes `accrueInterest` on the target debt token before `burn`; if liquidation accrues interest first, the stale-write window collapses and this finding reduces to a non-issue.

    function _calculateInterestAccrual()
        private
        view
        returns (uint256 _interestAmountAccrued, uint256 _debtIndex, uint256 _lastTimestampAccrued)
    {
        _lastTimestampAccrued = lastTimestampAccrued;
        _debtIndex = debtIndex;

        if (block.timestamp > _lastTimestampAccrued) {
            uint256 _interestRateToAccrue = interestRatePerSecond() * (block.timestamp - _lastTimestampAccrued);
            if (_interestRateToAccrue > 0) {
                _interestAmountAccrued = _interestRateToAccrue.wadMul(totalSupply_);
                _debtIndex += _interestRateToAccrue.wadMul(_debtIndex);
            }
        }
    }
