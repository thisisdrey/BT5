### Title
Missing bounds checks in ijar's ZIP central-directory parser allow out-of-bounds reads on malformed archives - (File: `third_party/ijar/zip.cc`)

### Summary
`InputZipFile::ProcessCentralDirEntry` in `third_party/ijar/zip.cc` reads central-directory-header fields (filename length, extra-field length, comment length, offsets) directly from the mmap'd input buffer with no equivalent of the `EnsureRemaining()` bounds check that the local-file-header parser (`ProcessLocalFileEntry`) uses. This is functionally analogous to the Wireshark IxVeriWave bug (CVE-2018-5334): a file-format parser trusts length/offset fields taken from attacker-controlled input without validating that the resulting read stays within the mapped buffer, leading to an out-of-bounds read/crash.

### Finding Description
`ProcessLocalFileEntry` (lines 332-370) calls `EnsureRemaining(n, ...)` before advancing the cursor `p` for `file_name_length_` and `extra_field_length_`, guarding against reading past the end of the mapped file: [1](#0-0) 

By contrast, `ProcessCentralDirEntry` (lines 493-545), which is invoked in a loop by `InputZipFile::ProcessNext` and `InputZipFile::CalculateOutputLength` while walking the central directory, performs no such check. It unconditionally advances `p`/`extra_p` by attacker-supplied `file_name_length`, `extra_field_length`, and `file_comment_length` values and dereferences them (e.g. `get_u2le(extra_p)` inside the extra-field loop) without verifying these advances stay inside the mapped region: [2](#0-1) 

The one bounds check that exists for the central directory as a whole is in `FindZipCentralDirectory`, which only validates that `cd.central_dir_offset + cd.central_dir_size <= in_length` for the *aggregate* central directory region: [3](#0-2) 

That check does not protect against a single malformed entry inside the central directory whose `file_name_length`/`extra_field_length`/`file_comment_length` fields cause the per-entry cursor `p`/`extra_p` to run past `bytes + central_dir_offset + central_dir_size` (or even past the end of the mapped file, if the values are large enough), since nothing re-validates per-entry advances against the buffer end. The zip64 extra-field walk in the same function (`while (extra_p != p) { ... get_u2le(extra_p); ... extra_p += data_size; ...}`) can similarly run unbounded if `data_size` values don't line up, causing `extra_p` to skip past `p` and loop until it wraps or crosses into unmapped memory.

### Impact Explanation
`InputZipFile` is the archive reader used by ijar (`third_party/ijar/zip_main.cc`, `extract`/`ProcessAll`) and by `singlejar`-adjacent tooling for producing interface jars from `.jar`/`.zip` inputs. Any workspace that consumes an externally-fetched or externally-built jar (e.g. via `http_jar`, `http_archive` with `type = "jar"`, or a `java_import`/`maven`-sourced jar) that is subsequently run through ijar will have this parser process attacker-influenced bytes. A crafted central directory record with an oversized `file_name_length`/`extra_field_length`/`file_comment_length` (or malformed zip64 extra field `data_size`) can drive `p`/`extra_p` outside the mapped file buffer, causing an out-of-bounds read and process crash (denial of service for that build invocation) when ijar processes the archive.

### Likelihood Explanation
The content of a jar/zip file is entirely attacker-controlled at the byte level: the pinned `sha256`/`integrity` in the workspace only proves the fetched bytes match what the developer copied, not that the bytes are well-formed or free of malicious ZIP structure. An attacker who controls a package/artifact (e.g. a hostile mirror, malicious open-source jar release, or compromised registry entry that a developer legitimately pins) can craft a ZIP central directory entry with an invalid length field. Since `ProcessCentralDirEntry` has no bounds validation at all (unlike its sibling function), the bug is directly and trivially reachable by anyone who can get a victim to build against their jar — it requires no MITM and no checksum bypass, matching the "hostile origin/dependency content" threat model.

### Recommendation
Add the same style of bounds check used in `ProcessLocalFileEntry`/`EnsureRemaining` to `ProcessCentralDirEntry`: validate that `p` plus `file_name_length`, `extra_field_length`, and `file_comment_length` stays within `[bytes, bytes + in_length)` (or within the central directory region) before dereferencing or advancing past those fields, and bound the zip64-extra-field walk (`while (extra_p != p)`) so that `data_size` cannot advance `extra_p` past `p`, returning a parse error (`error(...)`) instead of continuing.

### Proof of Concept
A reproducible JUnit/shell test would construct a minimal ZIP file whose End-Of-Central-Directory record points to a single central directory entry (`CENTRAL_FILE_HEADER_SIGNATURE`) with `file_name_length = 0xFFFF` and only a few real bytes following it in the mapped file, then invoke `ZipExtractor::Create`/`ProcessAll` (as done in `third_party/ijar/zip_main.cc`'s `extract()`) on this file and observe a crash/OOB read rather than a graceful `error(...)` return — mirroring the shape of `src/test/shell/bazel` archive-extraction tests already present in the repo for other decompressors. I was not able to fully confirm from the index whether an existing `zip_test.cc`/`ijar` test harness already covers malformed central-directory-length fields; this would need to be checked directly in the repository before adding a new regression test. int InputZipFile::ProcessLocalFileEntry(
    size_t compressed_size, size_t uncompressed_size) {
  if (EnsureRemaining(26, "extract_version") < 0) {
    return -1;
  }
  extract_version_ = get_u2le(p);
  general_purpose_bit_flag_ = get_u2le(p);

  if ((general_purpose_bit_flag_ & ~GENERAL_PURPOSE_BIT_FLAG_SUPPORTED) != 0) {
    return error("Unsupported value (0x%04x) in general purpose bit flag.\n",
                 general_purpose_bit_flag_);
  }

  compression_method_ = get_u2le(p);

  if (compression_method_ != COMPRESSION_METHOD_DEFLATED &&
      compression_method_ != COMPRESSION_METHOD_STORED) {
    return error("Unsupported compression method (%d).\n",
                 compression_method_);
  }

  // skip over: last_mod_file_time, last_mod_file_date, crc32
  p += 2 + 2 + 4;
  compressed_size_ = get_u4le(p);
  uncompressed_size_ = get_u4le(p);
  file_name_length_ = get_u2le(p);
  extra_field_length_ = get_u2le(p);

  if (EnsureRemaining(file_name_length_, "file_name") < 0) {
    return -1;
  }
  file_name_ = p;
  p += file_name_length_;

  if (EnsureRemaining(extra_field_length_, "extra_field") < 0) {
    return -1;
  }
  extra_field_ = p;
  p += extra_field_length_;

bool InputZipFile::ProcessCentralDirEntry(const u1 *&p, u8 *compressed_size,
                                          u8 *uncompressed_size, char *filename,
                                          size_t filename_size, u4 *attr,
                                          u8 *offset) {
  u4 signature = get_u4le(p);

  if (signature != CENTRAL_FILE_HEADER_SIGNATURE) {
    if (signature != DIGITAL_SIGNATURE && signature != EOCD_SIGNATURE &&
        signature != ZIP64_EOCD_SIGNATURE) {
      error("invalid central file header signature: 0x%x\n", signature);
    }
    return false;
  }

  p += 16;  // skip to 'compressed size' field
  *compressed_size = get_u4le(p);
  *uncompressed_size = get_u4le(p);
  u2 file_name_length = get_u2le(p);
  u2 extra_field_length = get_u2le(p);
  u2 file_comment_length = get_u2le(p);
  p += 4;  // skip to external file attributes field
  *attr = get_u4le(p);
  *offset = get_u4le(p);
  {
    size_t len = (file_name_length < filename_size)
      ? file_name_length
      : (filename_size - 1);
    memcpy(reinterpret_cast<void*>(filename), p, len);
    filename[len] = 0;
  }
  p += file_name_length;
  const u1 *extra_p = p;
  p += extra_field_length;
  while (extra_p != p) {
    const u2 header_id = get_u2le(extra_p);
    const u2 data_size = get_u2le(extra_p);
    const u1 *extra = extra_p;
    extra_p += data_size;
    if (header_id == ZIP64_EXTRA_FIELD_TAG) {
      if (*uncompressed_size == U4_MAX) {
        *uncompressed_size = get_u8le(extra);
      }
      if (*compressed_size == U4_MAX) {
        *compressed_size = get_u8le(extra);
      }
      if (*offset == U4_MAX) {
        *offset = get_u8le(extra);
      }
    }
  }
  p += file_comment_length;
  return true;
}

bool FindZipCentralDirectory(const u1 *bytes, size_t in_length, u8 *offset,
                             const u1 **central_dir) {
  static const int MAX_COMMENT_LENGTH = 0xffff;
  static const int CENTRAL_DIR_LOCATOR_SIZE = 22;
  // Maximum distance of start of central dir locator from end of file
  static const int MAX_DELTA = MAX_COMMENT_LENGTH + CENTRAL_DIR_LOCATOR_SIZE;
  const u1* last_pos_to_check = in_length < MAX_DELTA
      ? bytes
      : bytes + (in_length - MAX_DELTA);
  const u1* current;
  bool found = false;

  for (current = bytes + in_length - CENTRAL_DIR_LOCATOR_SIZE;
       current >= last_pos_to_check;
       current-- ) {
    const u1* p = current;
    if (get_u4le(p) != EOCD_SIGNATURE) {
      continue;
    }

    p += 16;  // skip to comment length field
    u2 comment_length = get_u2le(p);

    // Does the comment go exactly till the end of the file?
    if (current + comment_length + CENTRAL_DIR_LOCATOR_SIZE
        != bytes + in_length) {
      continue;
    }

    // Hooray, we found it!
    found = true;
    break;
  }

  if (!found) {
    fprintf(stderr, "file is invalid or corrupted (missing end of central "
                    "directory record)\n");
    return false;
  }

  EndOfCentralDirectoryRecord cd;
  const u1* end_of_central_dir = current;
  get_u4le(current);  // central directory locator signature, already checked
  cd.number_of_this_disk = get_u2le(current);
  cd.disk_with_central_dir = get_u2le(current);
  cd.central_dir_entries_on_this_disk = get_u2le(current);
  cd.central_dir_entries = get_u2le(current);
  cd.central_dir_size = get_u4le(current);
  cd.central_dir_offset = get_u4le(current);
  u2 file_comment_length = get_u2le(current);
  current += file_comment_length;  // set current to the end of the central dir

  if (!FindZip64CentralDirectory(bytes, in_length, &end_of_central_dir, &cd)) {
    return false;
  }

  if (cd.number_of_this_disk != 0 || cd.disk_with_central_dir != 0 ||
      cd.central_dir_entries_on_this_disk != cd.central_dir_entries) {
    fprintf(stderr, "multi-disk JAR files are not supported\n");
    return false;
  }

  if (cd.central_dir_offset + cd.central_dir_size > in_length) {
    fprintf(stderr, "central directory offset/size is invalid\n");
    return false;
  }

  // Do not change output values before determining that they are OK.
  *offset = cd.central_dir_offset;
  // Central directory start can then be used to determine the actual
  // starts of the zip file (which can be different in case of a non-zip
  // header like for auto-extractable binaries).
  *central_dir = end_of_central_dir - cd.central_dir_size;
  return true;
}
