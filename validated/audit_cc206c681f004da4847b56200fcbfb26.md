### Title
Bad debt is only socialized inside `liquidate()`, so positions whose leftover collateral rounds to zero can never be liquidated and their debt is never socialized — inflating vault `total-assets` and creating a "last lender to withdraw loses" scenario - ([File: mainnet/contracts/market/v0-4-market.clar])

### Summary
Bad-debt socialization in the Zest v2 market is implemented entirely inside the `liquidate()` transaction: it is only triggered *after* a successful `collateral-remove` call, and `liquidate()` unconditionally reverts if the computed `coll-final` (collateral to be seized) is zero. This reproduces the exact root cause described in the Frax H-02 report: whenever a position's remaining collateral is dust (or its value has crashed close to zero), the liquidation math rounds `coll-final` to `0`, the transaction reverts with `ERR-ZERO-LIQUIDATION-AMOUNTS`, and the socialize-debt code path is never reached. The bad debt then sits permanently un-socialized while the corresponding vault continues to report it as part of `total-assets`, letting earlier lenders redeem at an inflated share price at the expense of those who redeem later.

### Finding Description
`liquidate()` computes `coll-final` from the position's actual collateral balance, price, and liquidation penalty, then hard-fails if it is zero: [1](#0-0) 

The only place bad debt is ever written off is the `no-collateral-left` branch that runs *after* `collateral-remove` succeeds inside the same `liquidate()` call: [2](#0-1) 

There is no standalone "clean liquidation" or debt-write-off entry point analogous to what the report calls `liquidateClean()` — socialization is inseparably coupled to a successful, non-zero collateral seizure inside `liquidate()`. When a position's collateral balance has crashed to a dust level (or the debt/collateral ratio produces a `coll-expected`/`coll-actual` that rounds down to `0` via `mul-div-down` in `scale-debt-for-liquidation`/`process-collateral-asset`), `coll-final-raw` and hence `coll-final` become `0`: [3](#0-2) [4](#0-3) 

In that case `(asserts! (> coll-final u0) ERR-ZERO-LIQUIDATION-AMOUNTS)` reverts the entire transaction — no liquidator can ever complete `liquidate()` for that position, so the bad-debt-socialization branch is unreachable. Meanwhile the corresponding vault's `total-assets`/`total-assets-preview` keep including the outstanding (now uncollectible) principal + accrued interest as though it were solvent, since these are only corrected via `socialize-debt`, which reduces `assets`/`total-borrowed`/`lindex`: [5](#0-4) [6](#0-5) 

Because `redeem()` prices shares using `convert-to-assets-preview`, which is derived from this inflated `total-assets-preview`, lenders who redeem before socialization occurs receive proportionally more than the vault can actually back: [7](#0-6) [8](#0-7) 

This is precisely the H-02 pattern: because the only liquidation path that can mark off bad debt is gated on a non-zero collateral seizure, a position can be left with residual (dust) collateral and unresolved bad debt indefinitely, with no way for anyone to force socialization. Lenders who redeem early capture the inflated share value; the remainder absorb the loss.

### Impact Explanation
This causes temporary freezing (and effective loss) of funds for lenders who redeem after the bad debt accrues but is never socialized: their shares are diluted by debt that inflates `total-assets` yet is uncollectible, and they cannot withdraw the true backing value. Because dust positions can never be fully liquidated (the `> coll-final u0` assertion blocks completion), there is no mechanism, permissioned or not, to correct the vault accounting once this state is reached, matching the "temporary freezing of funds" impact class.

### Likelihood Explanation
This can occur naturally, without any privileged action, whenever a position's collateral value collapses (sharp price drop, or collateral withdrawn down to a de minimis amount before/alongside a price shock) to the point that the calculated seize amount rounds to zero under `mul-div-down`. Given the granular liquidation curve (partial and graduated liquidations reduce the seized collateral proportionally in `scale-debt-for-liquidation`), dust remainders after partial liquidations are a realistic and repeatable end-state, not merely a corner case, so likelihood is non-negligible under normal market volatility.

### Recommendation
Decouple bad-debt socialization from the requirement of a non-zero collateral seizure: add a dedicated code path (or relax the `coll-final > 0` assertion when the position's remaining collateral value is below a defined near-zero threshold) that allows socializing/writing off the remaining debt even when there is no economically meaningful collateral left to seize, so the vault's `assets`/`total-borrowed` accounting is corrected promptly instead of only opportunistically inside a full, profitable `liquidate()` call.

### Proof of Concept
1. A borrower's position collateral value crashes such that, after partial liquidations reduce `curr-scaled`/`coll-actual` proportionally in `scale-debt-for-liquidation`, the residual `user-coll-balance` for the asset is a dust amount (e.g., a few base units).
2. A liquidator calls `liquidate()`; `process-collateral-asset` and `scale-debt-for-liquidation` compute `coll-expected`/`coll-final-raw` that round to `0` via `mul-div-down` given the token's decimals/price.
3. `(asserts! (> coll-final u0) ERR-ZERO-LIQUIDATION-AMOUNTS)` at [9](#0-8)  reverts the transaction before the `no-collateral-left`/`socialize-debt-asset` logic ever runs.
4. The position's remaining bad debt keeps accruing interest in the vault's `total-debt`/`total-borrowed`, inflating `total-assets-preview` at [10](#0-9) .
5. Lenders who call `redeem()` before anyone (if ever) manages to socialize this debt receive shares priced off the inflated `total-assets`, while later redeemers face an under-collateralized vault, reproducing the "last lender to withdraw loses" scenario from the H-02 report.

(define-private (scale-debt-for-liquidation
  (debt-final uint)
  (coll-actual uint)
  (curr-scaled uint)
  (asset-id uint))
  (let (;; convert debt amount to scaled units for storage
        (borrow-index (get index (unwrap-panic (get-cached-indexes asset-id))))
        (scaled-debt (mul-div-down debt-final INDEX-PRECISION borrow-index))
        ;; cap at current debt (prevent over-repayment)
        (scaled-to-remove (if (> scaled-debt curr-scaled) curr-scaled scaled-debt))
        (debt-to-repay (mul-div-up scaled-to-remove borrow-index INDEX-PRECISION))
        ;; If debt was capped, scale collateral proportionally
        (coll-final (if (< scaled-to-remove scaled-debt)
                        (mul-div-down coll-actual scaled-to-remove scaled-debt)
                        coll-actual)))
    {
      scaled-to-remove: scaled-to-remove,
      debt-to-repay: debt-to-repay,
      coll-final: coll-final
    }))

(define-public (socialize-debt (scaled-amount uint))
  (let ((scaled-principal (var-get principal-scaled))
        (borrowed (var-get total-borrowed))
        (idx (var-get index))
        (current-assets (var-get assets))
        (current-lindex (var-get lindex))
        (old-total-assets (total-assets))
        (debt-reduction (mul-div-down scaled-amount idx INDEX-PRECISION))
        (principal-reduction (if (> scaled-principal u0)
                                (mul-div-down scaled-amount borrowed scaled-principal)
                                u0))
        ;; Write down lindex proportionally to loss in total-assets
        (new-lindex (if (and (> old-total-assets u0) (> old-total-assets debt-reduction))
                       (mul-div-down current-lindex (- old-total-assets debt-reduction) old-total-assets)
                       u0)))

    (try! (check-caller-auth))
    (asserts! (> scaled-amount u0) ERR-AMOUNT-ZERO)

    (var-set lindex new-lindex)
    (var-set principal-scaled (if (> scaled-principal scaled-amount) (- scaled-principal scaled-amount) u0))
    (var-set total-borrowed (if (> borrowed principal-reduction) (- borrowed principal-reduction) u0))
    (var-set assets (if (> current-assets principal-reduction) (- current-assets principal-reduction) u0))

    (print {
      action: "socialize-debt",
      caller: contract-caller,
      data: {
        scaled-amount: scaled-amount,
        debt-reduction: debt-reduction,
        principal-reduction: principal-reduction,
        old-lindex: current-lindex,
        new-lindex: new-lindex,
        old-total-assets: old-total-assets,
        principal-scaled: (if (> scaled-principal scaled-amount) (- scaled-principal scaled-amount) u0),
        total-borrowed: (if (> borrowed principal-reduction) (- borrowed principal-reduction) u0),
        index: idx
      }
    })

    (ok true)))
