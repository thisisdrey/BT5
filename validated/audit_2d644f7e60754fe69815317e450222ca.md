### Title
Unauthenticated `/shutdown` endpoint on signer event receiver allows any remote peer with network reachability to halt the signer's event ingestion - (File: `libsigner/src/events.rs`)

### Summary
`SignerEventReceiver::next_event` treats any HTTP POST to path `/shutdown` as a legitimate stop instruction, with no authentication, secret, or origin check tying it to the in-process `SignerStopSignaler`. Anyone who can open a TCP connection to the signer's event-receiver listening address can send this exact request and permanently stop the receiver's `main_loop`, halting all subsequent StackerDB/proposal/burn-block/new-block event ingestion for that signer.

### Finding Description
The intended invariant is that only the node operator's own process (via `SignerStopSignaler::send`, constructed from `get_stop_signaler()`) can halt the event receiver's `main_loop`. In practice, the halt condition is implemented purely as a URL match with no possession-based check: [1](#0-0) 

Any client that connects to the bound socket and issues `POST /shutdown HTTP/1.1 ...` triggers `event_receiver.stop_signal.store(true, Ordering::SeqCst)` followed by `Err(EventError::Terminated)`. `main_loop` interprets `EventError::Terminated` as the exit signal: [2](#0-1) 

The legitimate stop-signal path (`SignerStopSignaler::send`) builds this exact same wire request with no additional secret, HMAC, or token embedded in it: [3](#0-2) 

Because the only "credential" is knowledge of the URL string `/shutdown`, and the handler does not check any header, token, or peer identity, the equality "permitted to halt = operator or in-process signaler" collapses to "permitted to halt = anyone who can open a TCP connection to the socket." No other guard (e.g. auth token, allow-list, TLS client cert) exists in `next_event` prior to the URL dispatch. The `/status` endpoint for comparison also performs no authentication, confirming this is a general property of the receiver, not a one-off oversight for `/shutdown`.

### Impact Explanation
A single crafted HTTP POST causes `main_loop` to `break`, permanently stopping the signer's event receiver thread (it does not restart itself). All subsequent events pushed by the node — StackerDB chunks (block responses/state-machine updates), block-validation proposal responses, burn-block notifications, and new-block notifications — stop being ingested by the signer runloop. This effectively disables the signer's participation in block-signing consensus flow until the process is restarted, which is a remote, unauthenticated, single-message DoS against the signer's event pipeline, matching the "Critical – remote crash/unauthenticated DoS from few messages" category.

### Likelihood Explanation
The only precondition is that the attacker can reach the signer's event-receiver socket (the question stipulates this precondition is met — the port is bound and reachable). No secret, credential, peer registration, or StackerDB slot ownership is required; the attacker cost is a single TCP connection and one HTTP request, fully repeatable on demand. This is squarely within the unprivileged remote attacker capabilities defined by the rules (arbitrary bytes to a reachable port), and does not rely on volumetric traffic — one message suffices.

### Recommendation
Do not expose a network-triggerable shutdown path keyed purely on URL. Options:
- Bind the event-receiver's shutdown mechanism to an in-process/local-only channel (e.g., a `std::sync::mpsc` or `AtomicBool` set directly by `SignerStopSignaler`, without round-tripping through the HTTP listener) rather than requiring an HTTP request to unblock `http_server.recv()`.
- If a wake-up HTTP request is still needed to interrupt the blocking `recv()`, require it to originate from loopback only (verify the peer address of the accepted connection) and/or include a per-process random shared secret set at `bind()` time that `SignerStopSignaler` embeds and the handler verifies before honoring `/shutdown`.
- At minimum, reject `/shutdown` requests that don't originate from `127.0.0.1`/the same host as `local_addr`.

### Proof of Concept
```rust
// libsigner/src/events.rs (test module) or a standalone integration test
use std::net::{TcpStream, SocketAddr};
use std::io::Write;
use std::thread;
use std::time::Duration;

#[test]
fn test_unauthenticated_remote_shutdown() {
    let mut receiver: SignerEventReceiver<SomeSignerMessageType> = SignerEventReceiver::new(false);
    let addr: SocketAddr = "127.0.0.1:0".parse().unwrap(); // in prod, could be 0.0.0.0:PORT
    let bound = receiver.bind(addr).unwrap();

    // Run main_loop in a background thread
    let handle = thread::spawn(move || {
        receiver.main_loop();
    });

    // Attacker: plain TCP client, NOT using SignerStopSignaler
    let mut stream = TcpStream::connect(bound).unwrap();
    let body = "attacker shutdown";
    let req = format!(
        "POST /shutdown HTTP/1.1\r\nHost: {}\r\nConnection: close\r\nContent-Length: {}\r\nContent-Type: text/plain\r\n\r\n{}",
        bound, body.len(), body
    );
    stream.write_all(req.as_bytes()).unwrap();

    // main_loop should exit due to EventError::Terminated
    handle.join().unwrap(); // asserts the loop terminates without ever calling SignerStopSignaler::send
}
```
The assertion point is that `main_loop()` returns (thread joins) purely as a result of the raw, unauthenticated `POST /shutdown` bytes sent directly by the test, exercising `libsigner/src/events.rs:443-445` without ever invoking `SignerStopSignaler::send`.
