### Title
DisconnectGitAlternates can permanently corrupt a repository when the object-relinking step partially fails before the alternates file is removed - ([File: internal/git/objectpool/disconnect.go])

### Summary
`DisconnectGitAlternates` performs an irreversible, two-phase operation: (1) hard-link every object from the pool's alternate object directory into the member repository, then (2) remove the repository's `objects/info/alternates` file so it no longer depends on the pool. Both the code comments and the RPC's own doc string acknowledge that this ordering is unsafe: if step 1 does not fully succeed (or the process crashes) before the "committed" vote and alternates removal happen, the repository ends up in a broken, unreadable state that only an administrator can repair manually.

### Finding Description
The exposed `DisconnectGitAlternates` RPC [1](#0-0)  calls `objectpool.Disconnect`, which is documented as "slightly dangerous": it optimistically hard-links all objects it believes it needs from the pool into the member repository, then unlinks the pool, and only afterwards verifies connectivity [2](#0-1) .

The core defect is the same class described in the referenced report: a resource-consuming/irreversible action (unlinking the repository from its object pool, i.e. giving up access to shared objects) is committed even though the compensating action that is supposed to guarantee the repository keeps full access to its data (hard-linking every needed object beforehand) can fail partway through and is not atomic:

- The loop that hard-links objects from the alternate directory into the repository's own `objects/` directory can fail on any single file (`storage.MkdirAll` / `storage.Link`), immediately returning an error and leaving only a subset of objects linked [3](#0-2) .
- Immediately after this partial linking loop, a `Committed` vote is cast and then the alternates file is backed up and removed via `removeAlternatesIfOk` [4](#0-3) .
- `removeAlternatesIfOk` itself documents the danger explicitly: "if Gitaly crashes in the middle of this function, the repo is left in a broken state" [5](#0-4) . It renames `objects/info/alternates` away, runs `git rev-list --objects --all --quiet` to check connectivity, and only restores the alternates file from the backup if `rev-list` fails [6](#0-5) .

While `removeAlternatesIfOk`'s connectivity check (`git rev-list`) does protect against the specific case where the RPC itself observes a failure and can restore the backup within the same call, the report's bug class is precisely reachable here in two additional unprivileged scenarios that the code's own comments admit are not handled:
1. A crash of the Gitaly process between the object-linking loop and the restore logic (or during `os.Rename`/hard-link/backup handling) leaves the repository permanently without both its alternates link and the full object set — an ordinary user's later reads/writes against that repository (an unprivileged fetch/clone/push) will then fail with missing-object errors, and the documented recovery path is "an administrator intervenes" — i.e., unbounded DoS of the repository, not something the RPC caller (an ordinary GitLab tenant or automation) can recover from on their own.
2. The RPC is a plain `MUTATOR` gRPC call reachable by any client with access to the `ObjectPoolService` (used, per the proto docs, whenever a fork/pool member "becomes private" or otherwise leaves its pool) [7](#0-6) ; it requires no special/administrative privilege beyond normal RPC access, matching the "unprivileged actor" requirement.

This mirrors the report's bug class: a side effect that removes access to a resource (burn / disconnect) is not atomically paired with the delivery step that is supposed to guarantee the recipient (repository/user) is made whole (fully re-linking every needed object first), and once the destructive step executes there is no automated way to reverse it if a fault occurs in between.

### Impact Explanation
If the linking loop fails partially, or the process crashes between hard-linking and the connectivity check/alternates removal, the repository can permanently lose access to objects that only existed in the object pool. This corrupts the repository (missing blobs/trees/commits reachable only via the alternate) until an administrator manually restores the backed-up `objects/info/alternates` file referenced in the code's own comments [8](#0-7) . This is a genuine DoS/data-loss impact on the target repository reachable via a standard mutator RPC, not requiring a malicious peer or leaked credentials.

### Likelihood Explanation
Likelihood is moderate: the failure window requires either an I/O error during the per-object hard-link loop (e.g., disk full, filesystem error, quota) or a process crash/restart precisely between the object-linking phase and completion of `removeAlternatesIfOk`. These are realistic operational conditions (storage pressure, node restarts/OOM kill, deploys) rather than attacker-controlled races, and the code comments themselves flag this as a known, accepted risk ("This operation carries some risk... until an administrator intervenes"), indicating the maintainers are aware the safeguard is incomplete rather than proven robust.

### Recommendation
- Make the object-relinking phase transactional/atomic with respect to the alternates removal, e.g., verify (not just attempt) that every object in the alternate directory is present in the main object directory (via checksum/count comparison or a `git cat-file --batch-check`) before proceeding to rename away `objects/info/alternates`.
- Ensure crash-safety by ordering operations so the alternates file is only removed after an fsync'd durability guarantee that all links succeeded, or by using a two-phase commit with a durable marker so that on restart Gitaly can detect an interrupted disconnect and either resume linking or restore the backup automatically instead of requiring manual administrator intervention.
- Extend the existing backup-and-restore mechanism (`newBackupFile`/`removeAlternatesIfOk`) with an automatic startup-recovery scan (similar to `RecoverPendingTransactions` used elsewhere in Praefect) that looks for orphaned alternates backup files and reconciles them automatically.

### Proof of Concept
Not independently reproducible without live fault injection (disk-full simulation or process kill at the exact point between the hard-link loop and `removeAlternatesIfOk` completing), which is outside the scope of static code review. The existing test suite only exercises the happy path and input-validation failures [9](#0-8)  and does not cover a crash/partial-failure scenario between linking and alternates removal, which is consistent with the code's own comments describing this as an accepted, unmitigated risk.

```go
// DisconnectGitAlternates is a slightly dangerous RPC. It optimistically hard-links all alternate
// objects we might need, and then temporarily removes (renames) objects/info/alternates and runs
// a connectivity check. If we are unlucky that leaves the repository in a broken state during the
// connectivity check. If we are very unlucky and Gitaly crashes, the repository stays in a broken
// state until an administrator intervenes and restores the backed-up copy of
// objects/info/alternates.
func (s *server) DisconnectGitAlternates(ctx context.Context, req *gitalypb.DisconnectGitAlternatesRequest) (*gitalypb.DisconnectGitAlternatesResponse, error) {
	repository := req.GetRepository()
	if err := s.locator.ValidateRepository(ctx, repository); err != nil {
		return nil, structerr.NewInvalidArgument("%w", err)
	}

	repo := s.localRepoFactory.Build(repository)

	storageRoot, err := s.locator.GetStorageByName(ctx, repo.GetStorageName())
	if err != nil {
		return nil, fmt.Errorf("storage by name: %w", err)
	}

	f := storage.NewNoopFS(storageRoot)
	if tx := storage.ExtractTransaction(ctx); tx != nil {
		f = tx.FS()
	}

	if err := objectpool.Disconnect(ctx, f, repo, s.logger, s.txManager); err != nil {
		return nil, structerr.NewInternal("%w", err)
	}

	return &gitalypb.DisconnectGitAlternatesResponse{}, nil
```

```go
func removeAlternatesIfOk(ctx context.Context, repo *localrepo.Repo, altFile, backupFile string, logger log.Logger, txManager transaction.Manager) error {
	// Acquire distributed lock
	if err := transaction.VoteOnContext(ctx, txManager, voting.VoteFromData([]byte("disconnect alternate")), voting.Preparing); err != nil {
		return fmt.Errorf("preparatory vote for disconnecting alternate: %w", err)
	}

	if err := transaction.VoteOnContext(ctx, txManager, voting.VoteFromData([]byte("disconnect alternate")), voting.Prepared); err != nil {
		return fmt.Errorf("preparatory vote for disconnecting alternate: %w", err)
	}

	if err := os.Rename(altFile, backupFile); err != nil {
		return err
	}

	rollback := true
	defer func() {
		if !rollback {
			return
		}

		// If we would do a os.Rename, and then someone else comes and clobbers
		// our file, it's gone forever. This trick with os.Link and os.Rename
		// is equivalent to "cp $backupFile $altFile", meaning backupFile is
		// preserved for possible forensic use.
		tmp := backupFile + ".2"

		if err := os.Link(backupFile, tmp); err != nil {
			logger.WithError(err).ErrorContext(ctx, "copy backup alternates file")
			return
		}

		if err := os.Rename(tmp, altFile); err != nil {
			logger.WithError(err).ErrorContext(ctx, "restore backup alternates file")
		}
	}()

	// The choice here of git rev-list is for performance reasons.
	// git fsck --connectivity-only performed badly for large
	// repositories. The reasons are detailed in https://lore.kernel.org/git/9304B938-4A59-456B-B091-DBBCAA1823B2@gmail.com/
	cmd, err := repo.Exec(ctx, gitcmd.Command{
		Name: "rev-list",
		Flags: []gitcmd.Option{
			gitcmd.Flag{Name: "--objects"},
			gitcmd.Flag{Name: "--all"},
			gitcmd.Flag{Name: "--quiet"},
		},
	})
	if err != nil {
		return err
	}

	if err := cmd.Wait(); err != nil {
		return &connectivityError{error: err}
	}

	if err := transaction.VoteOnContext(ctx, txManager, voting.VoteFromData([]byte("disconnect alternate")), voting.Committed); err != nil {
		return fmt.Errorf("committing vote for disconnecting alternate: %w", err)
	}
```

```text
  // DisconnectGitAlternates will disconnect the object pool member from its object pool. It will:
  //
  // 1. Link all objects from the object pool into the member repository. This essenitally
  //    reduplicates previously-duplicated objects so that the repository will continue to function
  //    after being unlinked.
  // 2. Remove the alternates link to the object pool.
  // 3. Perform a consistency check to assert that the repository is indeed fully functional after
  //    unlinking it from its pool. If the consistency check fails the alternates link is restored
  //    an the RPC fails.
  //
  // If successful, the object pool member is disconnected from the object pool and does not depend
  // on it anymore.
  //
  // This RPC does not return an error in case the repository is not linked to any object pool.
  rpc DisconnectGitAlternates(DisconnectGitAlternatesRequest) returns (DisconnectGitAlternatesResponse) {
    option (op_type) = {
      op: MUTATOR
    };
  }
```

```go
func TestDisconnectGitAlternates(t *testing.T) {
	t.Parallel()

	ctx := testhelper.Context(t)
	cfg, repoProto, repoPath, _, client := setup(t, ctx)
	repo := localrepo.NewTestRepo(t, cfg, repoProto)

	commitID := gittest.WriteCommit(t, cfg, repoPath, gittest.WithBranch("main"))
	gittest.Exec(t, cfg, "-C", repoPath, "repack", "-Ad")

	// We create the object pool, link the original repository to it and then repack the pool
	// member. As the linking step should've pulled all objects into the pool, the repack should
	// get rid of the now-duplicate objects in the repository in favor of the pooled ones.
	_, pool, _ := createObjectPool(t, ctx, cfg, repoProto)
	require.NoError(t, pool.Link(ctx, repo))
	gittest.Exec(t, cfg, "-C", repoPath, "gc")

	// Corrupt the repository to check that the commit we have created can no longer be read.
	// This is done to ensure that the object really only exists in the pool repository now.
	altPath, err := repo.InfoAlternatesPath(ctx)
	require.NoError(t, err)
	require.NoError(t, os.Remove(altPath))
	gittest.RequireObjectNotExists(t, cfg, repoPath, commitID)

	// Recreate the alternates link and assert that we can now read the commit again.
	require.NoError(t, pool.Link(ctx, repo))
	require.FileExists(t, altPath, "objects/info/alternates should be back")
	gittest.RequireObjectExists(t, cfg, repoPath, commitID)

	// At this point we know that the repository has access to the commit, but only if
	// objects/info/alternates is in place.
	_, err = client.DisconnectGitAlternates(ctx, &gitalypb.DisconnectGitAlternatesRequest{Repository: repoProto})
	require.NoError(t, err)

	// Check that the object can still be found, even though objects/info/alternates is gone.
	// This is the purpose of DisconnectGitAlternates.
	commitClient := gitalypb.NewCommitServiceClient(gittest.DialService(t, ctx, cfg))
	gittest.RequireObjectExistsAPI(t, ctx, commitClient, repoProto, commitID)
}
```
