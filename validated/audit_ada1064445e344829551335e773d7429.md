### Title
Unvalidated client-supplied `GitObjectDirectory`/`GitAlternateObjectDirectories` fields are trusted directly when constructing Git subprocess environment - ([File: internal/git/gitcmd/command_factory.go])

### Summary
The Trail of Bits finding describes a trust-boundary defect: a downstream program (`folio`) blindly consumes an "accounting" value (`dao_fee_numerator`) from an account that is owned/controlled by a different, less-trusted authority (`dtfs`), without validating that the value actually belongs to a trusted configuration owner. The analogous class in Gitaly is trusting a security-relevant path field carried in a client-supplied RPC message (the `Repository` proto's `GitObjectDirectory` / `GitAlternateObjectDirectories`) as if it had already been validated/owned by Gitaly's trusted quarantine logic, when in the primary command-execution path it has not been.

### Finding Description
Gitaly's `gitalypb.Repository` message exposes `GitObjectDirectory` and `GitAlternateObjectDirectories` fields [1](#0-0) . These fields exist to support the object-quarantine mechanism, where Gitaly legitimately sets a temporary quarantine directory as the main object directory and the real object directory as an alternate [2](#0-1) . When quarantine information must be trusted and re-applied (e.g. for hooks or hostname resolution to check pushed objects), Gitaly performs strict validation: `ObjectDirectoryPath` in `internal/git/localrepo/paths.go` verifies the directory is either inside the repository or matches the expected quarantine-directory prefix under the storage's temp dir before it's used [3](#0-2) .

However, the primary command-construction routine used for *every* Git subprocess Gitaly spawns, `newCommand` in `command_factory.go`, does not go through this validated accessor. It takes the raw, client-supplied `repo.GetGitObjectDirectory()` and `repo.GetGitAlternateObjectDirectories()` values directly and passes them into `alternates.Env`, which simply joins them onto the repo path and emits `GIT_OBJECT_DIRECTORY` / `GIT_ALTERNATE_OBJECT_DIRECTORIES` environment variables with no boundary check: [4](#0-3) [5](#0-4) .

The same unguarded pattern also appears in `customHooksEnv`, which builds up the custom-hook execution environment straight from `payload.Repo.GetGitObjectDirectory()` / `GetGitAlternateObjectDirectories()` with only a `filepath.Join`, no containment check [6](#0-5) .

This mirrors the report's root cause exactly: a value that is supposed to originate from and be owned by a trusted internal mechanism (the quarantine subsystem / `folio`-controlled fee config) is instead accepted verbatim from an externally supplied structure (an RPC field / a dtfs-owned account) at a point in the code where the "owning/validating" component's guarantees no longer apply, letting an ordinary caller inject values that alter accounting/behavior — here, altering which on-disk object directories Git subprocesses will read from and write to.

### Impact Explanation
Any RPC caller that can control the `Repository` message passed to a given RPC (this field is part of the standard, client-suppliable `Repository` proto embedded in virtually every RPC request) can set `git_object_directory` / `git_alternate_object_directories` to arbitrary relative paths. Because `newCommand` uses these values unchecked to build `GIT_OBJECT_DIRECTORY`/`GIT_ALTERNATE_OBJECT_DIRECTORIES`, a crafted value (e.g. `../other-repo/objects` or an absolute-looking traversal) could point a Git subprocess at another repository's or another storage location's object store. This breaks the object-pool/alternates isolation Gitaly otherwise carefully enforces via `storage.ValidateRelativePath` in the quarantine-specific accessor, enabling cross-repository object visibility/manipulation and pollution of one repository's object store from a spoofed alternate — the same "manipulate the values used for internal, security-relevant accounting/behavior via an insufficiently authenticated/validated channel" class as the reported bug.

### Likelihood Explanation
Reaching this path only requires an ordinary, authenticated Gitaly client (any GitLab client that can issue gRPC requests, since the `Repository` message with these fields is attached to virtually all RPCs) to set the `git_object_directory`/`git_alternate_object_directories` fields to a crafted relative path and issue any RPC that ends up calling `gitCmdFactory`'s `newCommand` — i.e. essentially every Git operation. No privileged access, leaked token, or malicious peer/node collusion is required, satisfying the "ordinary user's ... crafted RPC field" validation criterion.

### Recommendation
Route the `GitObjectDirectory`/`GitAlternateObjectDirectories` fields through the same containment validation used in `localrepo.ObjectDirectoryPath` (i.e., `storage.ValidateRelativePath` combined with the quarantine-prefix check) before they are used in `newCommand` (`internal/git/gitcmd/command_factory.go`) and in `customHooksEnv` (`internal/gitaly/hook/custom.go`), rejecting any value that does not resolve inside the repository's own object directory or the expected per-request quarantine directory. Longer term, avoid deriving trusted execution-environment values directly from arbitrary client-supplied proto fields; instead, generate/attach quarantine directory information server-side (as already done by `quarantine.New`) and only accept that server-generated value for privileged operations.

### Proof of Concept
Conceptual PoC (cannot be executed without live infra, but the code path is concrete):
1. Issue any Gitaly RPC that includes a `Repository` message and results in a Git subprocess being spawned (e.g. `RepositoryService/OptimizeRepository`, `BlobService/GetBlob`, etc.).
2. In the `Repository` message, set `git_object_directory` to a relative path that escapes the repository, e.g. `"../victim-repo/objects"`, or set `git_alternate_object_directories` to `["../victim-repo/objects"]`.
3. Because `newCommand` (`internal/git/gitcmd/command_factory.go:519`) calls `alternates.Env(repoPath, repo.GetGitObjectDirectory(), repo.GetGitAlternateObjectDirectories())` directly, without the `storage.ValidateRelativePath`/quarantine-prefix check performed in `localrepo.ObjectDirectoryPath` (`internal/git/localrepo/paths.go:37-74`), the spawned `git` subprocess receives `GIT_OBJECT_DIRECTORY`/`GIT_ALTERNATE_OBJECT_DIRECTORIES` pointing outside the intended repository, allowing the requester to read or influence objects belonging to a different repository/storage path.

// Apply applies the quarantine on the repository. This is done by setting the quarantineDirectory
// as the repository's object directory, and configuring the repository's object directory as an alternate.
func Apply(repoPath string, repo *gitalypb.Repository, quarantineDir string) (*gitalypb.Repository, error) {
	relativePath, err := filepath.Rel(repoPath, quarantineDir)
	if err != nil {
		return nil, fmt.Errorf("creating quarantine: %w", err)
	}

	// All paths are relative to the repository root.
	objectDir := repo.GetGitObjectDirectory()
	if objectDir == "" {
		// Set the default object directory as an alternate if the repository didn't
		// have the object directory overwritten yet.
		objectDir = "objects"
	}

	alternateObjectDirs := make([]string, 0, len(repo.GetGitAlternateObjectDirectories())+1)
	alternateObjectDirs = append(alternateObjectDirs, objectDir)
	alternateObjectDirs = append(alternateObjectDirs, repo.GetGitAlternateObjectDirectories()...)

	quarantinedRepo := proto.Clone(repo).(*gitalypb.Repository)
	quarantinedRepo.GitObjectDirectory = relativePath
	quarantinedRepo.GitAlternateObjectDirectories = alternateObjectDirs

	return quarantinedRepo, nil
}

// Env returns the alternate object directory environment variables.
func Env(repoPath, objectDirectory string, alternateObjectDirectories []string) []string {
	var env []string
	if objectDirectory != "" {
		env = append(env, fmt.Sprintf("GIT_OBJECT_DIRECTORY=%s", filepath.Join(repoPath, objectDirectory)))
	}

	if len(alternateObjectDirectories) > 0 {
		var dirsList []string

		for _, dir := range alternateObjectDirectories {
			dirsList = append(dirsList, filepath.Join(repoPath, dir))
		}

		env = append(env, fmt.Sprintf("GIT_ALTERNATE_OBJECT_DIRECTORIES=%s", strings.Join(dirsList, ":")))
	}

	return env
}
