### Title
Non-atomic replay-window Check/Update race allows a captured packet to be decrypted twice (replay bypass) - ([File: connection_state.go])

### Summary
The polynomial `[H-05]` bug is fundamentally a **non-atomic state-check-then-update race**: the accounting used for one operation (`getTokenPrice()`/withdrawal) is computed at a different, uncoordinated point in time than the operation that mutates the authoritative state (`_resetTrade()`'s fee deduction), letting an attacker interleave their own action between the two and profit from the inconsistency. Nebula's `ConnectionState.Decrypt` and `ConnectionState.VerifyRelay` exhibit the same root-cause pattern: the anti-replay window is **checked** and **updated** as two separate, independently-locked operations with unprotected work (AEAD decryption) sandwiched in between, so two concurrent deliveries of the same packet can both pass the check before either commits the update.

### Finding Description
`ConnectionState.Decrypt` in [1](#0-0) acquires `decryptLock`, calls `cs.window.Check(l, messageCounter)`, releases the lock, performs `DecryptDanger` **outside the lock**, then re-acquires the lock only afterward to call `cs.window.Update(l, messageCounter)`. `VerifyRelay` follows the identical pattern at [2](#0-1) .

Because `Check` and `Update` are separate critical sections rather than one atomic check-and-set, two goroutines processing the same `messageCounter` concurrently (e.g., two UDP reader threads, since Nebula reads/dispatches packets from multiple queues) can both observe `Check()==true` before either has called `Update()` to mark the counter as consumed. Both then proceed to decrypt and process the packet as legitimate traffic. This mirrors the report's core issue: a value/authorization check (`getTokenPrice()` / window `Check`) that is not kept consistent with the state-mutating operation (`_resetTrade` fee deduction / window `Update`), letting a well-timed second action slip through the gap.

The entry point is reachable pre-authentication in the sense that no valid CA-signed certificate is required to *exploit the race* — an on-path or relaying attacker only needs to capture and duplicate an already-observed ciphertext packet (they don't need to forge or decrypt it, just replay bytes they intercepted) via `readOutsidePackets` → `hostinfo.ConnectionState.Decrypt` at [3](#0-2) , or via the relay path `VerifyRelay` at [4](#0-3) .

### Impact Explanation
A successful race yields double-processing of a replayed/duplicated ciphertext frame — i.e., a concrete **traffic replay** bypass of Nebula's anti-replay protection, one of the explicitly in-scope impacts (traffic decryption/forgery/replay). This is exactly the class of "one operation races ahead of an accounting update" bug described in the DeFi report, translated to Nebula's replay-window enforcement, and is reachable without possessing a CA-signed certificate — the attacker only needs to observe and resend a wire frame between two legitimate peers or through a relay.

### Likelihood Explanation
The window is 1024 entries wide (`ReplayWindow = 1024`, [5](#0-4) ), giving an attacker a wide margin to inject a duplicate of a just-observed packet while the original is still mid-flight through decryption on another goroutine. Nebula's packet-reading path uses multiple queues/goroutines (`q int` parameter threading through `readOutsidePackets`), so genuine concurrent delivery of duplicate UDP datagrams for the same tunnel is plausible on a lossy or attacker-controlled network path, without needing precise nanosecond timing — a duplicated UDP packet (trivial for an on-path attacker to produce) racing the original is sufficient.

### Recommendation
Make replay-window check-and-set atomic with respect to decryption: hold `decryptLock` for the entire `Check → Decrypt → Update` sequence (or perform an atomic "check-and-reserve" `Update`-like step before decrypting, rolling back the reservation only on decrypt failure), so no second copy of the same `messageCounter` can pass `Check()` until the first copy's outcome (success or failure) has been committed to the window.

### Proof of Concept
1. Establish a tunnel between two Nebula nodes so `ConnectionState` is populated via `newConnectionStateFromResult` ( [6](#0-5) ).
2. Capture a single legitimate outbound data packet (ciphertext) between the peers, noting its `messageCounter`.
3. Simultaneously re-inject two (or more) copies of that exact captured packet into the receiver's UDP input path so they are dispatched to `readOutsidePackets` on separate reader goroutines.
4. If both copies reach `cs.window.Check(l, messageCounter)` in `Decrypt` ( [7](#0-6) ) before either reaches `cs.window.Update`, both pass the check, both successfully `DecryptDanger`, and both get delivered to `handleOutsideMessagePacket`/tun — demonstrating a successful replay despite the anti-replay window being present.

func (cs *ConnectionState) Decrypt(l *slog.Logger, messageCounter uint64, out []byte, packet []byte, nb []byte) ([]byte, error) {
	var err error
	cs.decryptLock.Lock()
	result := cs.window.Check(l, messageCounter)
	cs.decryptLock.Unlock()
	if !result {
		return nil, ErrAlreadySeen
	}

	out, err = cs.dKey.DecryptDanger(out, packet[:header.Len], packet[header.Len:], messageCounter, nb)
	if err != nil {
		return nil, err
	}

	cs.decryptLock.Lock()
	result = cs.window.Update(l, messageCounter)
	cs.decryptLock.Unlock()
	if !result {
		return nil, ErrAlreadySeen
	}
	return out, nil
}

func (cs *ConnectionState) VerifyRelay(l *slog.Logger, messageCounter uint64, packet []byte, nb []byte) error {
	cs.decryptLock.Lock()
	result := cs.window.Check(l, messageCounter)
	cs.decryptLock.Unlock()
	if !result {
		return ErrAlreadySeen
	}

	signedPayload := packet[:len(packet)-cs.dKey.Overhead()]
	signatureValue := packet[len(packet)-cs.dKey.Overhead():]
	_, err := cs.dKey.DecryptDanger(nil, signedPayload, signatureValue, messageCounter, nb)
	if err != nil {
		return err
	}

	cs.decryptLock.Lock()
	result = cs.window.Update(l, messageCounter)
	cs.decryptLock.Unlock()
	if !result {
		return ErrAlreadySeen
	}

	return nil
}
