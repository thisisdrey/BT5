### Title
Protocol fee bypass on `Imt`/`Nep245` tokens via unit-splitting of `TokenDiff` deltas - ([File: contracts/defuse/core/src/intents/token_diff.rs])

### Summary
`TokenDiff::token_fee` waives the protocol fee whenever `amount <= 1` for `TokenIdType::Nep245` and `TokenIdType::Imt`, an exemption meant for one-off NFT/MT transfers. Because `Imt` tokens are arbitrary, minter-defined, fungible-quantity balances (minted via `ImtMint` in any amount, not necessarily NFTs), a signer can split any negative delta of size `N` into `N` separate `TokenDiff` intents each with `delta = -1`, so every leg hits the `amount == 1` exemption and pays `Pips::ZERO` instead of `fee.fee_ceil(N)`.

### Finding Description
The invariant that should hold is:
`fee_collector.balance[T] += Pips::fee_ceil(protocol_fee, Σ|negative_delta(T)|)` for all `TokenDiff` intents touching token `T` in a signer's transaction set.

`TokenDiff::token_fee` computes the fee per-intent, per-token-delta: [1](#0-0) 

and `execute_intent` calls it once per `(token_id, delta)` pair in a single `TokenDiff`, applying `fee_ceil(amount)` on that intent's own `amount`, not on any running total across the signer's other intents: [2](#0-1) 

`TokenIdType::Imt` is grouped with `Nep245`/`Nep171` in the `amount <= 1` no-fee branch, an exemption designed for indivisible NFT/MT transfers (comment: "do not take fees on NFTs and MTs with `|delta| <= 1`"). However, `ImtTokenId` tokens are minted by `ImtMint` in arbitrary quantities and are economically fungible-quantity balances, not necessarily one-off NFTs: [3](#0-2) [4](#0-3) 

An unprivileged signer who owns (or has minted, since minting is permissionless via `ImtMint`) `N` units of an `Imt` token can sign `N` separate `TokenDiff` intents, each `diff = {imt_token_id: -1}`, and submit them in one `MultiPayload`/`execute_intents` batch (or across several batches). Each intent independently calls `token_fee(imt_token_id, 1, protocol_fee)`, which falls through to `TokenIdType::Nep171 | TokenIdType::Nep245 | TokenIdType::Imt => return Pips::ZERO`, so `fee = Pips::ZERO.fee_ceil(1) = 0` for every leg. Aggregated over `N` legs the fee collector receives `0`, whereas a single combined `TokenDiff{imt_token_id: -N}` would have paid `fee.fee_ceil(N) > 0` for any nonzero `protocol_fee`.

Existing guards do not prevent this: signature/nonce verification, `internal_apply_deltas` balance checks, and `Amounts::add` overflow checks all operate correctly on each leg individually — none of them track or cap the number of unit-sized legs a signer can submit for the same token, and `token_fee` has no per-signer/per-batch aggregation of `amount` across intents.

### Impact Explanation
This is a direct, repeatable under-collection of protocol fees, matching the "protocol fees bypassed" Critical category in scope. Whoever is entitled to the fee (`fee_collector`) receives strictly less than what the fee schedule (`protocol_fee`) mandates for the same total economic transfer, purely because the transfer was chunked into `amount == 1` legs. The blast radius covers every `Imt` (and equally, `Nep245`) token whose per-unit value is non-negligible; any signer trading such a token can always restructure a large trade into `N` unit legs to erase the fee entirely, for any `N` bounded only by gas/transaction-size limits.

### Likelihood Explanation
No special privileges are required — any account holding (or having minted via the permissionless `ImtMint` intent) an `Imt` balance can submit ordinary `TokenDiff` intents with `delta = -1`. The only cost is the marginal gas of `N` intents instead of 1, which is a normal per-intent processing cost, not a resource-exhaustion attack. This is straightforward and repeatable across accounts, tokens, and batches whenever `protocol_fee > Pips::ZERO`.

### Recommendation
Compute the fee-exemption decision on the token type alone (or on an explicit "is this an NFT-like single unit" flag intrinsic to the `TokenId`, e.g. `Nep171` only), not on the transient per-intent `amount`. For `Imt`/`Nep245` tokens carrying fungible quantities, fees should be based on the token's registered fungibility (e.g., a per-token-id `decimals`/`is_fungible` marker set at mint time) rather than on whatever amount happens to appear in a single intent, so that splitting a transfer into unit-sized legs cannot change the total fee owed.

    pub fn token_fee(token_id: impl Into<TokenIdType>, amount: u128, fee: Pips) -> Pips {
        let token_id = token_id.into();
        match token_id {
            TokenIdType::Nep141 => {}
            TokenIdType::Nep245 | TokenIdType::Imt if amount > 1 => {}
            // do not take fees on NFTs and MTs with |delta| <= 1
            TokenIdType::Nep171 | TokenIdType::Nep245 | TokenIdType::Imt => return Pips::ZERO,
        }
        fee
    }
