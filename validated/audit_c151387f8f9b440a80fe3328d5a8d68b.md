### No vulnerability found for this question.

Analysis: The behavior is explicitly documented as intentional in the code itself — `AuthCall::attached_deposit` field comment states: "NOTE: the wNEAR will not be refunded in case of fail." [1](#0-0) . The debit happens via `self.withdraw(...)` in `auth_call()` in `state.rs`, followed by `near_withdraw` and a chained callback to `do_auth_call` which attaches the deposit to the callee promise [2](#0-1) [3](#0-2) .

Two independent reasons this fails validation:

1. **No external victim / no attacker profit.** The `AuthCall.contract_id` and `msg` are fields the signer themselves signs as part of their own intent. Per the attacker profile, the attacker only controls their own signed payloads and their own deployed contracts — there is no path for an unprivileged attacker to debit a *different* signer's wNEAR without that signer's own valid signature authorizing the specific `AuthCall{contract_id, attached_deposit, msg}`. If the "signer" and "attacker" are the same party (as the attacker profile requires — "sign with their own keys"), this is self-inflicted, not theft of someone else's funds, and yields no attacker profit — matching the excluded category "griefing with no attacker profit."

2. **The premise about NEAR's refund semantics is incorrect.** On NEAR protocol, when a `FunctionCall` action's receipt execution panics, the attached deposit is refunded automatically by the runtime back to the predecessor of that action — in this case, the Defuse contract itself (since `Promise::new(auth_call.contract_id)` was created by the Defuse contract) — not kept by the failing callee. So the claim "NEAR attached deposits are consumed regardless of receiver-side panic once the receipt executes" is factually wrong for a panicking callee; the callee only keeps NEAR it doesn't fail on. This means the described exploit ("attacker_contract... keeping it even on on_auth() panic") does not hold as stated.

The worst realistic consequence — with a truly failing callee — is that the signer's *own* signed, self-authorized debit results in the unwrapped NEAR being refunded to the Defuse contract's own account balance rather than being re-credited to the signer's ledger (since no resolver exists for `do_auth_call`). That is a self-inflicted ledger/balance mismatch confined to the signer's own funds with no attacker profit, which falls outside the Critical/High impact categories (no unauthorized movement of another party's funds, no double-settlement, no fee bypass) and is explicitly excluded ("griefing with no attacker profit").

    fn auth_call(&mut self, signer_id: &AccountIdRef, auth_call: AuthCall) -> Result<()> {
        if auth_call.attached_deposit.is_zero() {
            Self::do_auth_call(signer_id.to_owned(), auth_call)
        } else {
            // withdraw from signer's wNEAR balance
            self.withdraw(
                signer_id,
                [(
                    Nep141TokenId::new(self.wnear_id().into_owned()).into(),
                    auth_call.attached_deposit.as_yoctonear(),
                )],
                Some("withdraw"),
                false,
            )?;

            ext_wnear::ext(self.wnear_id.clone())
                .with_attached_deposit(NearToken::from_yoctonear(1))
                .with_static_gas(NEAR_WITHDRAW_GAS)
                // do not distribute remaining gas here
                .with_unused_gas_weight(0)
                .near_withdraw(U128(auth_call.attached_deposit.as_yoctonear()))
                .then(
                    // do_auth_call only after unwrapping NEAR
                    Self::ext(env::current_account_id())
                        .with_static_gas(
                            Self::auth_call_callback_gas(&auth_call)
                                .ok_or(DefuseError::GasOverflow)?,
                        )
                        .do_auth_call(signer_id.to_owned(), auth_call),
                )
        }
        .detach();

        Ok(())
    }

    #[private]
    pub fn do_auth_call(signer_id: AccountId, auth_call: AuthCall) -> Promise {
        if !auth_call.attached_deposit.is_zero() {
            require!(
                promise_result_checked_void(0).is_ok(),
                "near_withdraw failed",
            );
        }

        let min_gas = auth_call.min_gas();
        let mut p = Promise::new(auth_call.contract_id);

        if let Some(state_init) = auth_call.state_init {
            p = p.state_init(state_init, NearToken::ZERO);
        }

        ext_auth_callee::ext_on(p)
            .with_attached_deposit(auth_call.attached_deposit)
            .with_static_gas(min_gas)
            .on_auth(signer_id, auth_call.msg)
    }
