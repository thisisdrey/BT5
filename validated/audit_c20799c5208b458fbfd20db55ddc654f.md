### Title
Dust-collateral rounding lets a borrower permanently escape liquidation via `ERR-ZERO-LIQUIDATION-AMOUNTS` - (File: `mainnet/contracts/market/v0-4-market.clar`)

### Summary
The Uniswap-v3-position report is not directly reachable in Zest (no NFT/concentrated-liquidity collateral exists), but the same bug *class*—a borrower-controlled state that deterministically forces the liquidation call path to hard-revert—is reachable through the `liquidate()` function's rounding-to-zero checks on `debt-to-repay` / `coll-final`.

### Finding Description
`liquidate()` computes the liquidator's seizable collateral and repayable debt through a chain of fixed-point conversions: `process-collateral-asset` caps `coll-actual` at the user's actual balance [1](#0-0) , then `calc-final-liquidation-amounts` recomputes `debt-final-usd`/`debt-final` from `coll-actual` when the collateral was capped below the "expected" amount [2](#0-1) , and `scale-debt-for-liquidation` converts that into scaled debt units and the final `debt-to-repay`/`coll-final` [3](#0-2) .

If a borrower leaves only a dust amount (e.g. `u1`) of a given collateral asset backing their obligation, `coll-actual` is capped to that dust amount [4](#0-3) . When that dust amount is converted to USD (`normalize (* coll-actual coll-price) coll-decimals`) the result can truncate to `u0` for tokens with low price-per-unit-of-smallest-denomination, which propagates through `calc-final-liquidation-amounts` to `debt-final-usd = u0` and `debt-final = u0`, and finally to `debt-to-repay = u0` in `scale-debt-for-liquidation`.

The `liquidate()` function then hard-reverts on this exact state:
```
(asserts! (> debt-to-repay u0) ERR-ZERO-LIQUIDATION-AMOUNTS)
(asserts! (> coll-final u0) ERR-ZERO-LIQUIDATION-AMOUNTS)
``` [5](#0-4) 

This is functionally identical to the referenced report: an attacker-controlled zero/near-zero external state causes the liquidation function to unconditionally abort, so the liquidator can never seize that collateral or repay that debt, exactly as `positionManager.decreaseLiquidity()` reverting on a zero-liquidity position blocked Wild Credit's liquidation flow.

### Impact Explanation
If the dust asset is the borrower's sole remaining collateral (`len (get collateral pos-full)` == `u1`), the entire `liquidate()` call reverts before ever reaching the bad-debt-socialization branch [6](#0-5) , meaning liquidators have no path to either seize collateral or trigger `socialize-debt-asset`. The undercollateralized debt remains open and continues to accrue interest that the protocol can never recover, leading to protocol insolvency/bad debt exactly as described in the report. This lands on the in-scope **Critical** impact class (protocol insolvency).

### Likelihood Explanation
Any ordinary borrower can engineer this state unprivileged: deposit collateral, borrow near the maximum LTV, then use the normal `collateral-remove` path to withdraw down to a `u1` (or otherwise dust) balance of a collateral whose `coll-decimals`/`coll-price` combination makes 1 unit round to `$0` in `normalize`. No DAO action, oracle manipulation, or flashloan is required—this is a self-inflicted, deterministic state reachable through ordinary market entry points (`collateral-add`, `borrow`, `collateral-remove`), making the likelihood high once discovered.

### Recommendation
When `coll-actual`/`debt-final` round to zero because of dust collateral, the liquidation path should not simply revert and abandon the position. Instead, treat this as the "no meaningful collateral left" case and route directly into the bad-debt socialization logic (writing off the remaining debt against that collateral) rather than gating the whole `liquidate()` call behind `(asserts! (> debt-to-repay u0) ...)` / `(asserts! (> coll-final u0) ...)`. Alternatively, disallow withdrawing collateral down to a level where its USD value would resolve to zero, or apply a minimum-dust threshold check on the deposit/withdraw side so a position can never end up in this unliquidatable state.

### Proof of Concept
1. Borrower deposits sufficient collateral of a normal asset (e.g. sBTC) and borrows near the maximum LTV in a debt asset.
2. Borrower deposits a small amount of a second collateral asset with a decimals/price ratio such that `u1` unit's USD value rounds to `0` under `normalize`.
3. Borrower calls `collateral-remove` on the first (primary) collateral, withdrawing it all while remaining healthy, and reduces the second collateral to `u1`, leaving that dust unit as the sole remaining collateral asset backing the debt.
4. Price of the debt asset rises (or of the previous collateral drops) such that `current-ltv >= ltv-liq-partial`, making the position liquidatable.
5. A liquidator calls `liquidate()` specifying the dust collateral asset. `process-collateral-asset` caps `coll-actual` at `u1`; `calc-final-liquidation-amounts` computes `coll-actual-usd = u0` due to rounding; `scale-debt-for-liquidation` yields `debt-to-repay = u0`.
6. The `(asserts! (> debt-to-repay u0) ERR-ZERO-LIQUIDATION-AMOUNTS)` check at [5](#0-4)  fires and the entire liquidation transaction reverts, leaving the undercollateralized debt permanently unliquidatable.

;; Scale debt for storage and calculate final execution amounts
;; Converts to scaled units, caps at current debt, calculates final collateral
;; Returns: { scaled-to-remove: uint, debt-to-repay: uint, coll-final: uint }
(define-private (scale-debt-for-liquidation
  (debt-final uint)
  (coll-actual uint)
  (curr-scaled uint)
  (asset-id uint))
  (let (;; convert debt amount to scaled units for storage
        (borrow-index (get index (unwrap-panic (get-cached-indexes asset-id))))
        (scaled-debt (mul-div-down debt-final INDEX-PRECISION borrow-index))
        ;; cap at current debt (prevent over-repayment)
        (scaled-to-remove (if (> scaled-debt curr-scaled) curr-scaled scaled-debt))
        (debt-to-repay (mul-div-up scaled-to-remove borrow-index INDEX-PRECISION))
        ;; If debt was capped, scale collateral proportionally
        (coll-final (if (< scaled-to-remove scaled-debt)
                        (mul-div-down coll-actual scaled-to-remove scaled-debt)
                        coll-actual)))
    {
      scaled-to-remove: scaled-to-remove,
      debt-to-repay: debt-to-repay,
      coll-final: coll-final
    }))
