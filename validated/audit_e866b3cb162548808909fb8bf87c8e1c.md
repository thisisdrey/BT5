### Title
`drift_claim_bad_debt` sweeps the entire claimant ATA balance (not just the claimed reimbursement) to the global fee wallet, diverting bad-debt compensation away from users - (File: `programs/marginfi/src/instructions/drift/claim_bad_debt.rs`)

### Summary
The Morpho report describes `claimToTreasury(COMP)` sweeping an entire token balance to the treasury without distinguishing between the intended "reserve" amount and unrelated rewards that had accumulated in the same account, and notes that this sweep is permissionless and front-runnable. Marginfi's `drift_claim_bad_debt` instruction has the same root-cause pattern: it sweeps the *entire current balance* of a public, permissionlessly-fundable token account to the protocol's fee wallet, rather than sweeping only the amount actually claimed for the operation being performed.

### Finding Description
`drift_claim_bad_debt` is a permissionless instruction meant to let anyone claim a Drift bad-debt-portal reimbursement on behalf of a bank and forward it to the protocol. The claim lands in `claimant_token_account`, the canonical ATA of the bank's `liquidity_vault_authority` for the `claim_mint` [1](#0-0) .

The instruction correctly computes the amount actually received from the claim via a pre/post balance diff (`received_amount`) [2](#0-1) , but then discards that value for the sweep. `cpi_transfer_to_destination` instead reads the raw, live balance of the ATA with `accessor::amount(&self.claimant_token_account...)` and transfers *all of it* to the global fee wallet's ATA: [3](#0-2) 

Because `claimant_token_account` is a canonical Associated Token Account, it is a publicly-writable account: any unprivileged user can transfer tokens into it (directly via SPL transfer, or indirectly via any Drift/marketplace flow that happens to route funds through the bank's `liquidity_vault_authority` ATA for that mint) before this permissionless instruction is invoked. Since the sweep uses the raw balance rather than the tracked `received_amount`, any such balance is unconditionally redirected to the `global_fee_wallet`, not to the bank's `liquidity_vault` where it would benefit depositors/offset bad debt.

This exactly mirrors the Compound/Morpho pattern: the function conflates two different fund sources sharing one account (the "reserve"/tracked claim vs. any and all other balances the account happens to hold) and sweeps them together to a destination that is not the user-facing accounting the funds were meant for.

By contrast, the equivalent Kamino reward-harvest path in this codebase does this correctly — it computes `received = post_transfer_balance - pre_transfer_balance` and only transfers that delta [4](#0-3) , confirming that the Drift bad-debt path deviates from the codebase's own safe pattern.

### Impact Explanation
The claimed funds are meant as bad-debt reimbursement tied to a specific Drift bank's shortfall (i.e., funds that should restore value to the bank/its depositors), but the instruction unconditionally forwards the entire ATA balance to the protocol's `global_fee_wallet`, an unrelated, admin-controlled destination [5](#0-4) . Any balance in that account beyond the merkle-tree claim itself — including tokens an unprivileged party could deposit into the public ATA before the call — is misappropriated the same way. This results in an unauthorized diversion of value that should mitigate user-facing bad debt/insolvency exposure into a destination outside the bank's accounting, which is a concrete state-manipulation/fund-misdirection impact, not merely theoretical.

### Likelihood Explanation
The instruction is explicitly permissionless (any `payer` can call it) [6](#0-5) , the claimant ATA is a standard canonical ATA that anyone can top up with a plain SPL transfer, and the sweep uses live balance rather than the computed delta. No special privilege or validator/admin access is required to trigger the sweep of any pre-existing/injected balance; only a normal wallet is needed.

### Recommendation
Compute `received_amount` from the pre/post balance diff around the claim CPI (as already done) and use exactly that value — not the account's live balance — as the amount transferred in `cpi_transfer_to_destination`. If it is desired that stray/incidental balances in the account not be permanently stranded, sweep any excess back to the bank's `liquidity_vault` (benefiting depositors) rather than to the `global_fee_wallet`.

### Proof of Concept
1. An unprivileged user determines/derives the canonical ATA `claimant_token_account = ATA(liquidity_vault_authority, claim_mint)` for a target Drift bank (this address is fully deterministic and public).
2. Before (or independent of) any legitimate `drift_claim_bad_debt` call, the user (or anyone) sends an arbitrary amount of `claim_mint` tokens directly into that ATA via a normal SPL `transfer` instruction (the ATA only needs to exist, which `create_claimant_token_account` creates idempotently for anyone calling the instruction anyway) [7](#0-6) .
3. Anyone (permissionless) then calls `drift_claim_bad_debt` with a valid/legitimate merkle proof for whatever the actual bad-debt allocation is.
4. `cpi_transfer_to_destination` reads the total balance of `claimant_token_account` (legitimate claim + the injected tokens) and transfers all of it to `destination_token_account` (global fee wallet), rather than only the amount actually attributable to the merkle claim [3](#0-2) .
5. The bank's depositors receive none of the injected value, and even the reimbursement itself is directed to the fee wallet rather than the bank's `liquidity_vault`, so the mechanism cannot be used to actually make depositors whole for the underlying bad debt it was designed to remediate.

    fn cpi_transfer_to_destination(&self) -> MarginfiResult<u64> {
        let amount = accessor::amount(&self.claimant_token_account.to_account_info())?;
        if amount == 0 {
            return Ok(0);
        }

        let accounts = Transfer {
            from: self.claimant_token_account.to_account_info(),
            to: self.destination_token_account.to_account_info(),
            authority: self.liquidity_vault_authority.to_account_info(),
        };
        let bump = self.bank.load()?.liquidity_vault_authority_bump;
        let signer_seeds: &[&[&[u8]]] =
            bank_signer!(BankVaultType::Liquidity, self.bank.key(), bump);
        let cpi_ctx = CpiContext::new_with_signer(self.token_program.key(), accounts, signer_seeds);

        token::transfer(cpi_ctx, amount)?;
        Ok(amount)
    }

pub fn kamino_harvest_reward(

    reward_index: u64,

    let pre_transfer_balance = accessor::amount(&ctx.accounts.user_reward_ata.to_account_info())?;
    ctx.accounts.cpi_harvest_rewards(reward_index)?;
    let post_transfer_balance = accessor::amount(&ctx.accounts.user_reward_ata.to_account_info())?;
    let received = post_transfer_balance - pre_transfer_balance;
    ctx.accounts
        .cpi_transfer_obligation_owner_to_destination(received)?;
    Ok(())
}
