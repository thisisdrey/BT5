### Title
`transfer_to_new_account_pda` allows unauthorized front-running/squatting of a victim's future marginfi account PDA - (File: `programs/marginfi/src/instructions/marginfi_account/transfer_account.rs`)

### Summary
`transfer_to_new_account_pda` derives the destination `MarginfiAccount` PDA from a `new_authority` pubkey that is passed in as a completely unchecked, non-signing account. Anyone who owns (or freshly creates) any old `MarginfiAccount` can call this instruction, name an arbitrary victim's pubkey as `new_authority`, and choose the `account_index`/`third_party_id` the victim would naturally pick (e.g. `0`), thereby claiming/initializing that victim's canonical account PDA before the victim ever does — the same "identifier squatting via front-run" bug class described in the external Audius report, applied to marginfi's PDA-based account namespace.

### Finding Description
`marginfi_account_initialize_pda` derives a `MarginfiAccount` PDA from `[MARGINFI_ACCOUNT_SEED, group, authority, account_index, third_party_id]` where `authority` must be a `Signer` [1](#0-0) , so nobody can squat this PDA on behalf of someone else through this entrypoint (a real front-run there would require the victim's own signature).

However, `transfer_to_new_account_pda` derives the exact same PDA (`[MARGINFI_ACCOUNT_SEED, group, new_authority, account_index, third_party_id]`) but `new_authority` is declared `UncheckedAccount` with the comment "WARN: New authority is completely unchecked", and it is never required to sign the transaction: only `authority` (the *old* account's owner) and `fee_payer` sign [2](#0-1) .

This means any attacker can:
1. Create a throwaway `MarginfiAccount` for themselves via the permissionless `marginfi_account_initialize` (or `_pda`) instruction (attacker signs as its own `authority`).
2. Call `transfer_to_new_account_pda`, setting `old_marginfi_account` to their own throwaway account, and `new_authority` = the victim's pubkey, `account_index` = `0` (the conventional first index), `third_party_id = None`.
3. This "migrates" the attacker's account into a PDA at exactly `derive_pda(group, victim, 0, None)`, initializing it with `authority = new_authority` (victim), `migrated_from = attacker's old account`, and copying over the attacker's `lending_account`, `indexer_flags`, and `account_flags` [3](#0-2) .

Since the PDA uses Anchor's `init` constraint, once created it cannot be re-initialized [4](#0-3) . If the victim later tries to create their own clean account at that same, conventional `(group, victim, account_index=0, third_party_id=0)` slot via `marginfi_account_initialize_pda`, the transaction fails because the account already exists — exactly mirroring the Audius report's "honest user's registration fails because the identifier was already claimed."

### Impact Explanation
* **Unauthorized state change**: an attacker can force-initialize a specific victim's `MarginfiAccount` PDA slot without the victim's consent or signature, populating it with attacker-chosen `migrated_from`, `lending_account`, `account_flags`, and `indexer_flags` values that the victim did not create and cannot avoid.
* **Griefing / permanent occupation of the canonical slot**: the victim's `account_index = 0` PDA (the address most integrators/UIs assume is a user's primary/default account) becomes permanently unavailable for a clean self-initialization; the victim can only ever "inherit" whatever the attacker deposited (including stale, dust, or even leveraged/liability positions the attacker chooses to leave behind), rather than a fresh account.
* This matches the report's bug class of front-running a registration-style, identifier-claiming instruction, and produces a genuine on-chain state change the victim never authorized, at very low cost to the attacker (just the fixed `ACCOUNT_TRANSFER_FEE` plus rent for a throwaway old account).

### Likelihood Explanation
The attack requires no special privileges, no capital beyond negligible rent/fee, and no signature from the victim. Because `account_index=0` is the natural/default first index most wallets and users would choose, an attacker can pre-emptively squat this slot for any pubkey (or run this proactively against many addresses) at negligible cost, making the attack cheap and easy to execute at scale, similar in spirit (and even lower cost) than the Audius scenario, which required staking `minStake`.

### Recommendation
Require `new_authority` to be a co-signer on `transfer_to_new_account_pda` (and any similar "gift to a new owner" flow), or otherwise bind consent from the target authority (e.g., a prior on-chain approval/nonce created and signed by the intended new authority) before allowing a third party to initialize a PDA under that authority's namespace. At minimum, document/mitigate that unsolicited transfers can occupy a victim's canonical `account_index`, and consider reserving low `account_index` values (e.g. `0`) for self-initialization only, disallowing them as targets of `transfer_to_new_account_pda`.

### Proof of Concept
1. Attacker calls `marginfi_account_initialize` (fresh keypair, attacker as `authority`) to create a throwaway account with no/negligible positions. [5](#0-4) 
2. Attacker computes `victim_pda = MarginfiAccount::derive_pda(group, victim_pubkey, 0, None, marginfi::ID)` [6](#0-5) .
3. Attacker calls `transfer_to_new_account_pda` with `old_marginfi_account` = their throwaway account, `new_marginfi_account` = `victim_pda`, `new_authority` = `victim_pubkey`, `account_index = 0`, `third_party_id = None`, signing only as `authority`/`fee_payer` — no signature from `victim_pubkey` is required. [3](#0-2) 
4. `victim_pda` is now initialized on-chain with `authority = victim_pubkey`, `migrated_from = attacker's old account`. Any subsequent attempt by the victim to run `marginfi_account_initialize_pda(account_index=0, third_party_id=None)` fails because the PDA already exists (`init` constraint), demonstrated by the existing test pattern for duplicate PDA creation. [7](#0-6)

pub fn transfer_to_new_account_pda(
    ctx: Context<TransferToNewAccountPda>,
    account_index: u16,
    third_party_id: Option<u16>,
) -> MarginfiResult {
    // Validate the global fee wallet and claim a nominal fee
    let group = ctx.accounts.group.load()?;
    check_eq!(
        ctx.accounts.global_fee_wallet.key(),
        group.fee_state_cache.global_fee_wallet,
        MarginfiError::InvalidFeeAta
    );
    anchor_lang::system_program::transfer(ctx.accounts.transfer_fee(), ACCOUNT_TRANSFER_FEE)?;

    let mut old_account = ctx.accounts.old_marginfi_account.load_mut()?;

    check!(
        !old_account.get_flag(ACCOUNT_IN_FLASHLOAN),
        MarginfiError::AccountInFlashloan
    );

    check!(
        !old_account.get_flag(ACCOUNT_IN_RECEIVERSHIP),
        MarginfiError::ForbiddenIx
    );

    check!(
        !old_account.get_flag(ACCOUNT_IN_ORDER_EXECUTION),
        MarginfiError::ForbiddenIx
    );

    check!(
        old_account.active_orders == 0,
        MarginfiError::IllegalAction,
        "Close all active orders before transfer"
    );

    // Prevent multiple migrations from the same account
    check_eq!(
        old_account.migrated_to,
        Pubkey::default(),
        MarginfiError::AccountAlreadyMigrated
    );

    // Validate third-party id restriction if provided
    if let Some(id) = third_party_id {
        if !is_allowed_cpi_for_third_party_id(&ctx.accounts.instructions_sysvar, id)? {
            return err!(MarginfiError::Unauthorized);
        }
    }

    let mut new_account = ctx.accounts.new_marginfi_account.load_init()?;
    let current_timestamp = Clock::get()?.unix_timestamp as u64;
    initialize_migrated_account(
        &mut new_account,
        &old_account,
        ctx.accounts.new_authority.key(),
        current_timestamp,
        ctx.accounts.old_marginfi_account.key(),
    );
    new_account.account_index = account_index;
    new_account.third_party_index = third_party_id.unwrap_or(0);
    new_account.bump = ctx.bumps.new_marginfi_account;

    finalize_migrated_old_account(
        &mut old_account,
        ctx.accounts.new_marginfi_account.key(),
        current_timestamp,
    );

#[derive(Accounts)]
#[instruction(account_index: u16, third_party_id: Option<u16>)]
pub struct TransferToNewAccountPda<'info> {
    #[account(
        constraint = (
            !group.load()?.is_protocol_paused()
        ) @ MarginfiError::ProtocolPaused
    )]
    pub group: AccountLoader<'info, MarginfiGroup>,

    #[account(
        mut,
        has_one = group @ MarginfiError::InvalidGroup,
        constraint = {
            let a = old_marginfi_account.load()?;
            account_not_frozen_for_authority(&a, authority.key())
        } @ MarginfiError::AccountFrozen,
        constraint = {
            let a = old_marginfi_account.load()?;
            let g = group.load()?;
            is_signer_authorized(&a, g.admin, authority.key(), false, false)
        } @ MarginfiError::Unauthorized
    )]
    pub old_marginfi_account: AccountLoader<'info, MarginfiAccount>,

    #[account(
        init,
        payer = fee_payer,
        space = 8 + std::mem::size_of::<MarginfiAccount>(),
        seeds = [
            MARGINFI_ACCOUNT_SEED.as_bytes(),
            group.key().as_ref(),
            new_authority.key().as_ref(),
            &account_index.to_le_bytes(),

#[tokio::test]
async fn marginfi_account_create_pda_duplicate_fails() -> anyhow::Result<()> {
    let test_f = TestFixture::new(None).await;

    let authority = test_f.payer();
    let account_index = 0;
    let third_party_id = None;

    // Derive PDA for the marginfi account
    let (marginfi_account_pda, _bump) = MarginfiAccount::derive_pda(
        &test_f.marginfi_group.key,
        &authority,
        account_index,
        third_party_id,
        &marginfi::ID,
    );

    let accounts = marginfi::accounts::MarginfiAccountInitializePda {
        marginfi_group: test_f.marginfi_group.key,
        marginfi_account: marginfi_account_pda,
        authority: authority,
        fee_payer: authority,
        instructions_sysvar: solana_instructions_sysvar::id(),
        system_program: system_program::id(),
    };

    let init_marginfi_account_pda_ix = Instruction {
        program_id: marginfi::ID,
        accounts: accounts.to_account_metas(Some(true)),
        data: marginfi::instruction::MarginfiAccountInitializePda {
            account_index,
            third_party_id,
        }
        .data(),
    };

    // First transaction should succeed
    let tx1 = Transaction::new_signed_with_payer(
        &[init_marginfi_account_pda_ix.clone()],
        Some(&test_f.payer()),
        &[&test_f.payer_keypair()],
        test_f.get_latest_blockhash().await,
    );

    let res1 = test_f
        .context
        .borrow_mut()
        .banks_client
        .process_transaction(tx1)
        .await;

    assert!(res1.is_ok());

    // Second transaction with same parameters should fail
    let tx2 = Transaction::new_signed_with_payer(
        &[init_marginfi_account_pda_ix],
        Some(&test_f.payer()),
        &[&test_f.payer_keypair()],
        test_f.get_latest_blockhash().await,
    );

    let res2 = test_f
        .context
        .borrow_mut()
        .banks_client
        .process_transaction(tx2)
        .await;

    assert!(res2.is_err(), "Duplicate account creation should fail");

    Ok(())
}
