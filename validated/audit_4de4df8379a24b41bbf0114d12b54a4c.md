### Title
Multisig Executor Can Inject Unapproved Payload When `ABORT_IF_MULTISIG_PAYLOAD_MISMATCH` Is Disabled — (`File: aptos-move/framework/aptos-framework/sources/multisig_account.move`)

---

### Summary

When the `ABORT_IF_MULTISIG_PAYLOAD_MISMATCH` feature flag (id = 70) is not enabled, any owner of a multisig account can execute an **arbitrary, unapproved transaction payload** as the multisig account. The other owners approved payload P1 stored on-chain, but the executor submits payload P2 in the transaction. The prologue validation silently skips the mismatch check, and the VM executes P2 — not P1 — as the multisig account.

---

### Finding Description

The `validate_multisig_transaction` function in `multisig_account.move` contains two payload-binding checks:

1. **Hash check** (lines 1365–1371): fires only when `transaction.payload_hash.is_some()` — i.e., when the transaction was created with `create_transaction_with_hash`. If the full payload was stored on-chain via `create_transaction`, this branch is **skipped entirely**.

2. **Stored-payload mismatch check** (lines 1375–1384): fires only when `features::abort_if_multisig_payload_mismatch_enabled()` returns `true`.

```move
if (features::abort_if_multisig_payload_mismatch_enabled()
    && transaction.payload.is_some()
    && !payload.is_empty()
) {
    let stored_payload = transaction.payload.borrow();
    assert!(
        payload == *stored_payload,
        error::invalid_argument(EPAYLOAD_DOES_NOT_MATCH),
    );
}
``` [1](#0-0) 

When the feature is disabled, neither check fires for a full-payload transaction. The prologue passes, and the VM proceeds to call `get_next_transaction_payload(multisig_address, provided_payload)` with the executor's submitted bytes:

```rust
let provided_payload = match executable {
    TransactionExecutableRef::EntryFunction(entry_func) => {
        bcs::to_bytes(&MultisigTransactionPayload::EntryFunction(entry_func.clone()))...
    },
    ...
};
// ...
session.execute_function_bypass_visibility(
    &MULTISIG_ACCOUNT_MODULE,
    GET_NEXT_TRANSACTION_PAYLOAD,
    ...
    serialize_values(&vec![
        MoveValue::Address(multisig_address),
        MoveValue::vector_u8(provided_payload),   // executor's P2
    ]),
``` [2](#0-1) 

`get_next_transaction_payload` returns the executor's provided payload when it is non-empty, and the VM executes that payload as the multisig account — not the approved P1.

The feature flag `ABORT_IF_MULTISIG_PAYLOAD_MISMATCH = 70` is **not** annotated as "Enabled on mainnet, cannot be disabled" — unlike the immediately adjacent features 69 (`_LIMIT_VM_TYPE_SIZE`) and 71 (`_DISALLOW_USER_NATIVES`), which carry that annotation:

```rust

ABORT_IF_MULTISIG_PAYLOAD_MISMATCH = 70,   // ← no such annotation
/// Enabled on mainnet, cannot be disabled.
_DISALLOW_USER_NATIVES = 71,
``` [3](#0-2) 

The feature is described in `features.move` as a "fix" with `Lifetime: transient`, confirming it was added to patch this exact gap and has not yet been permanently locked:

```move

### Impact Explanation

A single malicious or compromised owner of a k-of-n multisig account can:

- Execute **any arbitrary entry function or script** as the multisig account, regardless of what the other k−1 owners approved.
- Drain APT or fungible assets held by the multisig account.
- Deploy or upgrade modules under the multisig account's address.
- Perform any privileged governance or administrative action the multisig account is authorized to perform.

The other owners' approvals are rendered meaningless — they approved P1, but P2 executes.

---

### Likelihood Explanation

- Requires the attacker to be an existing owner of a multisig account (unprivileged relative to the multisig, but a real on-chain actor).
- Requires `ABORT_IF_MULTISIG_PAYLOAD_MISMATCH` to be disabled. The flag is not permanently locked on mainnet per the repository annotations.
- The attack is a single transaction submission — no complex setup beyond being an owner and having quorum (the executor's implicit vote counts toward quorum).
- The `create_transaction` path (full payload stored on-chain) is the more common, "decentralized" path recommended in the module documentation, making it the primary attack surface.

---

### Recommendation

1. **Permanently enable and lock `ABORT_IF_MULTISIG_PAYLOAD_MISMATCH`** on mainnet, adding the `_` prefix and "Enabled on mainnet, cannot be disabled" annotation, consistent with features 69 and 71.
2. **Remove the feature gate** from `validate_multisig_transaction` and make the stored-payload mismatch check unconditional, so the check cannot be toggled off by governance.
3. Alternatively, restructure `validate_multisig_transaction` so that when `transaction.payload.is_some()` and the executor provides a non-empty payload, the check is always enforced regardless of feature flag state.

---

### Proof of Concept

**Setup**: 3-of-3 multisig account `M`. Owners: Alice, Bob, Carol. Attacker is Alice.

1. **Alice** calls `create_transaction(alice, M, payload_P1)` — stores P1 (e.g., `transfer(M, alice, 1_APT)`) on-chain.
2. **Bob** calls `approve_transaction(bob, M, seq=1)`.
3. **Carol** calls `approve_transaction(carol, M, seq=1)` — quorum reached for P1.
4. **Alice** submits a `MultisigTransaction` with `multisig_address = M` and `transaction_payload = Some(P2)` where P2 = `transfer(M, alice, 1_000_000_APT)`.
5. In `validate_multisig_transaction`:
   - `transaction.payload_hash.is_some()` → `false` (full payload stored, not hash) → hash check skipped.
   - `features::abort_if_multisig_payload_mismatch_enabled()` → `false` (feature disabled) → mismatch check skipped.
   - Quorum check passes (Alice's implicit vote + Bob + Carol = 3 ≥ 3).
6. `get_next_transaction_payload(M, BCS(P2))` returns P2 (non-empty provided payload takes precedence).
7. VM executes P2 as M — Alice drains the multisig account.

Bob and Carol approved `transfer(M, alice, 1_APT)` but `transfer(M, alice, 1_000_000_APT)` executed. [6](#0-5) [7](#0-6)

    fun validate_multisig_transaction(
        owner: &signer, multisig_account: address, payload: vector<u8>) {
        assert_multisig_account_exists(multisig_account);
        assert_is_owner(owner, multisig_account);
        let sequence_number = last_resolved_sequence_number(multisig_account) + 1;
        assert_transaction_exists(multisig_account, sequence_number);

        if (features::multisig_v2_enhancement_feature_enabled()) {
            assert!(
                can_execute(address_of(owner), multisig_account, sequence_number),
                error::invalid_argument(ENOT_ENOUGH_APPROVALS),
            );
        }
        else {
            assert!(
                can_be_executed(multisig_account, sequence_number),
                error::invalid_argument(ENOT_ENOUGH_APPROVALS),
            );
        };

        // Count approvals, including the executing owner's implicit vote.
        let (num_approvals, _) = num_approvals_and_rejections(multisig_account, sequence_number);
        if (!has_voted_for_approval(multisig_account, sequence_number, address_of(owner))) {
            num_approvals += 1;
        };
        assert!(num_approvals >= num_signatures_required(multisig_account), error::invalid_argument(ENOT_ENOUGH_APPROVALS));

        // Timelock check — separate from quorum so the error is unambiguous.
        assert!(
            can_execute_with_timelock(multisig_account, sequence_number, num_approvals),
            error::invalid_state(ETIMELOCK_NOT_EXPIRED),
        );

        // If the transaction payload is not stored on chain, verify that the provided payload matches the hashes stored
        // on chain.
        let multisig_account_resource = borrow_global<MultisigAccount>(multisig_account);
        let transaction = multisig_account_resource.transactions.borrow(sequence_number);
        if (transaction.payload_hash.is_some()) {
            let payload_hash = transaction.payload_hash.borrow();
            assert!(
                sha3_256(payload) == *payload_hash,
                error::invalid_argument(EPAYLOAD_DOES_NOT_MATCH_HASH),
            );
        };

        // If the transaction payload is stored on chain and there is a provided payload,
        // verify that the provided payload matches the stored payload.
        if (features::abort_if_multisig_payload_mismatch_enabled()
            && transaction.payload.is_some()
            && !payload.is_empty()
        ) {
            let stored_payload = transaction.payload.borrow();
            assert!(
                payload == *stored_payload,
                error::invalid_argument(EPAYLOAD_DOES_NOT_MATCH),
            );
        }
    }
