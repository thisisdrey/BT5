### Title
Missing public-key-hash verification in `handle_neighbor_handshake_accept()` allows forged peer identity binding into PeerDB - ([File: stackslib/src/net/neighbors/walk.rs])

### Summary
`handle_neighbor_handshake_accept()`, invoked from `neighbor_handshakes_try_finish()`, commits a remote peer's self-reported `HandshakeAcceptData.handshake` (including `node_public_key`) into the neighbor DB via `neighbor_db.add_or_schedule_replace_neighbor()` without ever checking that the responding key hashes to the `naddr.public_key_hash` that was originally requested. This is unlike the pingback path's `check_handshake_pubkey_hash()`, which enforces exactly this equality before accepting a handshake.

### Finding Description
The broken invariant is: `requested_identity_hash (naddr.public_key_hash) == responding_message_signer_hash (Hash160::from_node_public_key(&data.handshake.node_public_key))`.

In `neighbor_handshakes_try_finish()` [1](#0-0) , for each collected reply keyed by a `naddr: NeighborAddress` (which carries the `public_key_hash` the walk expected for that address, taken from the original `Neighbors`/`GetNeighbors` gossip), the code extracts `HandshakeAccept`/`StackerDBHandshakeAccept` payloads and passes them straight to `self.handle_neighbor_handshake_accept(network, naddr, &message.preamble, data, db_data)` at line 1224, without any comparison of `naddr.public_key_hash` to a hash derived from `data.handshake.node_public_key`.

`handle_neighbor_handshake_accept()` itself [2](#0-1)  forwards `&data.handshake` directly to `self.neighbor_db.add_or_schedule_replace_neighbor(network, preamble, &data.handshake, db_data, &mut self.neighbor_replacements)`, which persists/schedules the identity-address binding into PeerDB (`new`/`neighbor` are then inserted into `self.new_frontier` / `self.frontier`, and ultimately reach the peer database via the neighbor walk result). No step in this call chain re-derives `Hash160::from_node_public_key(&data.handshake.node_public_key)` and compares it against `naddr.public_key_hash`.

By contrast, the design intent for the analogous accept-handling path for pingback peers is to call `check_handshake_pubkey_hash()` before accepting the identity — a check that exists in this file specifically for `pingback_handshakes_try_finish()`. Its absence from `neighbor_handshakes_try_finish()` / `handle_neighbor_handshake_accept()` means an unprivileged remote peer that is asked to handshake at a given `NeighborAddress` (with a specific expected `public_key_hash`, gossiped by some third party as being at that address) can reply with a `HandshakeAccept` containing an arbitrary `node_public_key` of the attacker's choosing. That attacker-chosen key, and the identity/address binding it implies, is accepted and written into this node's neighbor frontier/PeerDB state without ever verifying it matches the hash that was actually being queried.

### Impact Explanation
An unprivileged remote peer can cause the walking node to bind an arbitrary attacker-controlled public key to a `NeighborAddress`/`NeighborKey` it did not prove ownership of, and have that forged identity record propagate into the node's `PeerDB` (via `add_or_schedule_replace_neighbor()`), then further propagate through gossip to other nodes performing neighbor walks against this one. This is an unauthenticated/unauthorized write to PeerDB identity records and network-wide propagation of forged peer identity, matching the Critical impact category. It is repeatable per handshake round since the walk performs `neighbor_handshakes_begin`/`neighbor_handshakes_try_finish` cycles continuously as part of normal peer-walk operation.

### Likelihood Explanation
No special preconditions beyond normal P2P reachability are required: any node that ends up as a "neighbor of a neighbor" candidate during a walk (i.e., any node whose address is gossiped to the walking node via `GetNeighbors`/`Neighbors`) will have the walking node open an outbound handshake to it and process the reply through this vulnerable path. The attacker does not need the target's RPC secret or any privileged role — only the ability to accept an inbound P2P handshake connection and reply with a crafted `HandshakeAccept`. This makes it low-cost and remotely reachable by any unprivileged peer that can get itself listed as a neighbor address (e.g., by having any peer, including itself, gossip its own address).

### Recommendation
In `handle_neighbor_handshake_accept()` (or immediately before it is invoked in `neighbor_handshakes_try_finish()`), compute `Hash160::from_node_public_key(&data.handshake.node_public_key)` and require it to equal `naddr.public_key_hash` before calling `add_or_schedule_replace_neighbor()`; on mismatch, treat the reply as a protocol violation (drop/mark broken) exactly as `check_handshake_pubkey_hash()` does for the pingback path. Apply the same check to `handle_handshake_accept_from_ping()` if it is likewise missing this validation (not fully confirmed in this review due to file size — see below).

### Proof of Concept
Rust test in `stackslib::net::neighbors::walk`:
1. Construct a `NeighborWalk` and drive it to `NeighborWalkState::GetHandshakesFinish`, with `self.comms` mocking a pending handshake sent to `naddr` where `naddr.public_key_hash = Hash160::from_node_public_key(&honest_pubkey)`.
2. Have the mock `comms.collect_replies()` return a `StacksMessageType::HandshakeAccept(HandshakeAcceptData { handshake: HandshakeData { node_public_key: attacker_pubkey, .. }, .. })` where `attacker_pubkey != honest_pubkey`.
3. Call `neighbor_handshakes_try_finish()` and assert that `self.neighbor_db.add_or_schedule_replace_neighbor()` is invoked with `data.handshake.node_public_key == attacker_pubkey` bound to `naddr` — i.e., no `net_error` is returned and no rejection occurs, despite `Hash160::from_node_public_key(&attacker_pubkey) != naddr.public_key_hash`. This demonstrates the finding: the mismatch is silently accepted and committed.

Note: due to file-size truncation of `walk.rs` during this review, `check_handshake_pubkey_hash()`'s exact definition, `pingback_handshakes_try_finish()`, `ping_existing_neighbors_try_finish()`, and `handle_handshake_accept_from_ping()` (which appear later in the ~1987-line file) were not directly inspected; the finding above is fully confirmed for `neighbor_handshakes_try_finish()`/`handle_neighbor_handshake_accept()` only. It is recommended to independently verify `handle_handshake_accept_from_ping()` for the same missing check before treating it as confirmed for that specific call site.

    fn handle_neighbor_handshake_accept(
        &mut self,
        network: &mut PeerNetwork,
        naddr: NeighborAddress,
        preamble: &Preamble,
        data: &HandshakeAcceptData,
        db_data: Option<&StackerDBHandshakeData>,
    ) -> Result<(), net_error> {
        // NOTE: even if cur_neighbor is an inbound neighbor, the neighbors
        // of cur_neighbor that we could handshake with are necessarily
        // outbound connections.  So, save them all.
        // Do we know about this peer already?
        let (new, neighbor) = self.neighbor_db.add_or_schedule_replace_neighbor(
            network,
            preamble,
            &data.handshake,
            db_data,
            &mut self.neighbor_replacements,
        )?;

        if new {
            // neighbor was new
            self.new_frontier
                .insert(neighbor.addr.clone(), neighbor.clone());
        } else {
            // frontier maintenance
            self.frontier
                .insert(neighbor.addr.clone(), neighbor.clone());
        }

        self.resolved_handshake_neighbors.insert(naddr, neighbor);
        Ok(())
    }

    pub fn neighbor_handshakes_try_finish(
        &mut self,
        network: &mut PeerNetwork,
    ) -> Result<bool, net_error> {
        assert!(self.state == NeighborWalkState::GetHandshakesFinish);

        // see if we got any replies
        test_debug!(
            "{:?}: Try to finish {} in-flight handshakes with neighbors-of-neighbor {:?}",
            network.get_local_peer(),
            self.comms.count_inflight(),
            &self.cur_neighbor.addr
        );

        for (naddr, message) in self.comms.collect_replies(network).into_iter() {
            let nkey = naddr.to_neighbor_key(network);
            let (data, db_data) = match message.payload {
                StacksMessageType::HandshakeAccept(ref data) => (data, None),
                StacksMessageType::StackerDBHandshakeAccept(ref data, ref db_data) => {
                    (data, Some(db_data))
                }
                StacksMessageType::HandshakeReject => {
                    // remote peer doesn't want to talk to us
                    debug!(
                        "{:?}: Neighbor {:?} rejected our handshake",
                        network.get_local_peer(),
                        &nkey
                    );
                    self.comms.add_dead(
                        network,
                        &NeighborKey::from_neighbor_address(
                            message.preamble.peer_version,
                            message.preamble.network_id,
                            &naddr,
                        ),
                        DropReason::DeadConnection("Handshake rejected".into()),
                        DropSource::NeighborWalkHandshake,
                    );
                    continue;
                }
                StacksMessageType::Nack(ref data) => {
                    // remote peer nope'd us
                    debug!(
                        "{:?}: Neighbor {:?} NACK'ed our handshake with error code {:?}",
                        network.get_local_peer(),
                        &nkey,
                        data.error_code
                    );
                    self.comms.add_dead(
                        network,
                        &NeighborKey::from_neighbor_address(
                            message.preamble.peer_version,
                            message.preamble.network_id,
                            &naddr,
                        ),
                        DropReason::DeadConnection(format!(
                            "NACK'ed with error code: {}",
                            data.error_code
                        )),
                        DropSource::NeighborWalkHandshake,
                    );
                    continue;
                }
                _ => {
                    // protocol violation
                    debug!(
                        "{:?}: Neighbor {:?} replied an out-of-sequence message",
                        network.get_local_peer(),
                        &naddr
                    );
                    self.comms.add_broken(
                        network,
                        &NeighborKey::from_neighbor_address(
                            message.preamble.peer_version,
                            message.preamble.network_id,
                            &naddr,
                        ),
                        DropReason::BrokenConnection("Out-of-sequence message".into()),
                        DropSource::NeighborWalkHandshake,
                    );
                    continue;
                }
            };
            debug!(
                "{:?}: Got HandshakeAccept from {:?}",
                network.get_local_peer(),
                &nkey;
                "handshake_data" => ?data,
                "stackerdb_data" => ?db_data
            );

            self.handle_neighbor_handshake_accept(
                network,
                naddr,
                &message.preamble,
                data,
                db_data,
            )?;
