### Title
Unstaked flood exhausts the shared pre-classification connection headroom, causing staked handshakes to be refused - (File: `streamer/src/nonblocking/swqos.rs`)

### Summary
`SwQos::max_concurrent_connections()` returns a single global cap, `(max_staked_connections + max_unstaked_connections) * 5/4`, with no reservation carved out for staked peers [1](#0-0) . Because peer classification (staked vs. unstaked) can only happen after the QUIC/TLS handshake completes and the client certificate pubkey is looked up against `StakedNodes`, this cap is necessarily consumed at a stage *before* the staked-preference eviction logic in `try_add_connection` ever runs [2](#0-1) , so an unstaked flood can occupy the entire headroom and starve staked handshakes.

### Finding Description
`QosController::max_concurrent_connections` is documented only as "How many concurrent [connections]" are allowed [3](#0-2) , and `SwQos` implements it as an undifferentiated pool sized at 125% of the combined staked+unstaked table capacity, with the comment "Allow 25% more connections than required to allow for handshake" [1](#0-0) .

The actual staked-vs-unstaked admission fairness is only enforced *after* this stage, inside `try_add_connection`: staked connections get preferential treatment via `prune_random` eviction of the staked table, and only fall back to the unstaked table if staked eviction fails [2](#0-1) . Unstaked connections are separately capped and pruned down to 90% of `max_unstaked_connections` when full [4](#0-3) .

However, before any of this per-table logic runs, the connection must first be accepted at the transport layer and pass whatever admission gate uses `max_concurrent_connections()` (per the qos.rs trait contract, this bounds "concurrent connections" globally, independent of stake). Because a QUIC/TLS handshake must complete before the server can extract the client's pubkey and query `get_connection_stake` (used in `build_connection_context`, `streamer/src/nonblocking/swqos.rs:302-341`), the peer's stake status is unknown at the point the shared headroom slot is consumed. An unstaked attacker who completes handshakes quickly enough can occupy up to `(max_staked_connections + max_unstaked_connections) * 5/4` slots of this shared, stake-agnostic pool before any staked-preference eviction in `try_add_connection` has a chance to run against them, since that eviction logic operates only within the already-classified `staked_connection_table`/`unstaked_connection_table`, not on the pre-classification headroom itself.

This means the very headroom whose purpose ("allow for handshake") is presumably to guarantee slack for legitimate staked handshakes-in-progress can be entirely consumed by unstaked attacker connections, causing subsequent staked handshake attempts to be refused at the pre-classification admission stage — a stage the staked-preference eviction design in `SwQos::try_add_connection` never reaches.

### Impact Explanation
Scoped impact: staked-tier connection admission denial caused entirely by unstaked traffic — a QoS evasion / denial-of-service against the fee-paying, stake-weighted admission path that the stake-weighted QoS system (`SwQosConfig`, `try_add_connection`'s staked-preference eviction) is specifically designed to protect. This falls under the Agave bounty category of QoS bypass/evasion leading to legitimate stake-weighted traffic being starved by unprivileged/unstaked traffic.

### Likelihood Explanation
Preconditions: the attacker only needs network access to the leader's TPU QUIC port and the ability to complete enough QUIC/TLS handshakes fast enough to fill `max_concurrent_connections()` slots before being pruned. No stake, keys, or privileged access are required — this is achievable by any unstaked identity opening many concurrent connections, which matches the attacker model in scope. Feasibility depends on how quickly the pre-classification semaphore/gate releases slots relative to attacker handshake throughput, but the underlying design flaw (shared, stake-agnostic headroom) is present regardless of exact timing constants.

### Recommendation
Reserve headroom slots for staked handshakes-in-progress separately from unstaked ones (e.g., split `max_concurrent_connections()` into a staked-headroom pool and an unstaked-headroom pool, or defer counting an unstaked connection against the shared headroom until after a preliminary lightweight identity check), so unstaked connection attempts cannot consume capacity intended to guarantee slack for staked peers.

### Proof of Concept
Integration test plan (extending `streamer/src/nonblocking/testing_utilities.rs` / `swqos.rs` test module):
1. Configure `SwQosConfig` with small `max_staked_connections` and `max_unstaked_connections` (e.g., 4 and 4), yielding `max_concurrent_connections() == 10`.
2. From unstaked identities, drive the pre-classification admission path (the same gate that calls `max_concurrent_connections()`) to open connections up to the full headroom (10 concurrent unstaked handshakes in flight, not yet added to any `ConnectionTable`).
3. Attempt a staked connection while the headroom is fully occupied by unstaked in-flight handshakes.
4. Assert the staked connection is refused with `refused_connections_too_many_open_connections` incrementing, and assert no unstaked connection was evicted to make room for it (i.e., `stats.num_evictions_unstaked` and `stats.num_evictions_staked` remain 0 for this refusal), demonstrating the staked-preference eviction logic in `try_add_connection` never had the opportunity to run because admission was refused earlier at the shared, stake-agnostic headroom stage.

    fn prune_unstaked_connection_table(
        &self,
        unstaked_connection_table: &mut ConnectionTable<ConnectionStreamCounter>,
        max_unstaked_connections: usize,
        stats: Arc<StreamerStats>,
    ) {
        if unstaked_connection_table.total_size >= max_unstaked_connections {
            // Prune the connection table down to 90% capacity
            const PRUNE_TABLE_RATIO: f64 = 0.90;
            let max_connections = (PRUNE_TABLE_RATIO * (max_unstaked_connections as f64)) as usize;
            let num_pruned = unstaked_connection_table.prune_oldest(max_connections);
            stats
                .num_evictions_unstaked
                .fetch_add(num_pruned, Ordering::Relaxed);
        }
    }
