Audit Report

## Title
`ProxyType::NonTransfer` in Asset Hub runtimes does not block `PolkadotXcm` calls, letting a "non-transfer" proxy move the delegator's funds - ([File: cumulus/parachains/runtimes/assets/asset-hub-westend/src/lib.rs])

## Summary
`ProxyType::NonTransfer::filter` in `cumulus/parachains/runtimes/assets/asset-hub-westend/src/lib.rs` (and the analogous implementation in `asset-hub-rococo`) is implemented as a blocklist that omits `RuntimeCall::PolkadotXcm(..)` from its exclusion set, so any call through this pallet is treated as "non-transfer" and allowed. Because `pallet-xcm` dispatchables (`transfer_assets`, `limited_teleport_assets`, `limited_reserve_transfer_assets`, `execute`, etc.) can move the caller's `Balances`/`Assets`/NFT holdings off-chain, a delegate with only `NonTransfer` proxy rights can use `Proxy::proxy` to steal the delegator's funds.

## Finding Description
`ProxyType::NonTransfer` returns `true` (call allowed) for every `RuntimeCall` variant not explicitly matched in `!matches!(c, RuntimeCall::Balances{..} | RuntimeCall::Assets{..} | ... | RuntimeCall::Whitelist(..))`. `RuntimeCall::PolkadotXcm(..)` is never included in this list, despite `PolkadotXcm` being a live, callable pallet in the runtime (confirmed via its use throughout `xcm_config.rs` and `lib.rs`). This means the filter fails to block XCM-based asset movement, unlike the relay-chain runtimes (`polkadot/runtime/rococo`, `polkadot/runtime/westend`), which use an allowlist style filter and explicitly document "Specifically omitting the entire XCM Pallet" to keep XCM calls out of `NonTransfer` scope. The sibling `asset-hub-rococo` runtime exhibits the identical gap in its blocklist.

## Impact Explanation
`pallet-proxy`'s public `proxy`/`proxy_announced` extrinsics dispatch the wrapped call with the delegator's origin if `InstanceFilter::filter` returns `true`. Since `PolkadotXcm` calls pass this filter under `NonTransfer`, a delegate who was only ever granted non-transfer capability (e.g., governance/voting delegation) can invoke `PolkadotXcm::limited_teleport_assets`, `limited_reserve_transfer_assets`, `transfer_assets`, or `execute` to withdraw and send the delegator's `Balances`/`Assets`/NFTs to an address of the delegate's choosing. This is unauthorized execution/theft of proxied funds via a public wrapper meant to strictly widen non-transfer capabilities — matching the "theft ... or unauthorized execution or origin escalation" impact class.

## Likelihood Explanation
Exploitation requires only that the attacker already hold a `NonTransfer` proxy relationship with the victim — a standard, expected configuration (e.g., set up for governance-only delegation) — and no privileged access, validator/governance power, or off-chain compromise. `PolkadotXcm` dispatchables are always present and publicly callable, so the attack is fully reachable from an unprivileged, external, already-delegated account.

## Recommendation
Add `RuntimeCall::PolkadotXcm(..)` to the `NonTransfer` exclusion set in all Asset Hub / parachain runtimes using this blocklist pattern (`asset-hub-westend`, `asset-hub-rococo`, and any others sharing the same `InstanceFilter` code, e.g. `staking-async/runtimes/parachain`), or switch to an allowlist style filter matching the relay-chain runtimes' explicit safe-call enumeration so newly added pallets/calls are excluded by default.

## Proof of Concept
1. Account `A` executes `Proxy::add_proxy(B, ProxyType::NonTransfer, delay)` on Asset Hub Westend/Rococo.
2. `B` submits `Proxy::proxy(RuntimeOrigin::signed(B), A, Some(ProxyType::NonTransfer), Box::new(RuntimeCall::PolkadotXcm(pallet_xcm::Call::limited_teleport_assets { dest, beneficiary: B, assets: A's_full_balance, fee_asset_item: 0, weight_limit: Unlimited })))`.
3. `ProxyType::NonTransfer::filter` evaluates the call against the blocklist; since `RuntimeCall::PolkadotXcm(..)` matches none of the listed variants, `!matches!(...)` returns `true`, and the call dispatches with `A`'s origin.
4. `A`'s assets are teleported to `B`'s control despite `B` never having transfer rights, confirmed by tracing `ProxyType::NonTransfer::filter` at `cumulus/parachains/runtimes/assets/asset-hub-westend/src/lib.rs` lines 826-849.
