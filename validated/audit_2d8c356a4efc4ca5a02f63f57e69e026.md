This confirms the design: the global `overall_connection_rate_limiter` gate in `run_server` (streamer/src/nonblocking/quic.rs:346-357) and the second consumption check in `setup_connection` (streamer/src/nonblocking/quic.rs:495-508) apply uniformly to **every** incoming connection attempt, before stake is known. Stake-based QoS logic (`SwQos::build_connection_context`/`try_add_connection` in `streamer/src/nonblocking/swqos.rs:301-443`) only runs *after* the connection has already passed the global token bucket check — it only prioritizes staked peers within the already-admitted pool via separate `staked_connection_table`/`unstaked_connection_table` and stream-level EMA throttling (`streamer/src/nonblocking/stream_throttle.rs:160-188`), not at the QUIC connection-admission stage.

### Title
Global connection admission rate limiter is stake-agnostic, allowing distributed unstaked flood to exhaust `overall_connection_rate_limiter` and starve legitimate staked connection admission - (streamer/src/nonblocking/quic.rs)

### Summary
The QUIC server's `run_server`/`setup_connection` functions gate every incoming connection through a single shared `TokenBucket` (`overall_connection_rate_limiter`, `MAX_CONNECTION_BURST`=1000, `TOTAL_CONNECTIONS_PER_SECOND`=2500) before any stake information is known. A distributed set of unstaked attacker IPs, each individually compliant with the per-IP `ConnectionRateLimiter`, can collectively saturate this shared bucket every second, causing legitimate stake-weighted validators/RPC clients to be rejected via `incoming.ignore()`/connection close with `CONNECTION_CLOSE_CODE_DISALLOWED`.

### Finding Description
In `run_server` (streamer/src/nonblocking/quic.rs:346-357), every accepted incoming connection attempt first checks `overall_connection_rate_limiter.current_tokens() == 0`; if tokens are exhausted, the connection is dropped via `incoming.ignore()` regardless of the peer's stake. The redundant check in `setup_connection` (streamer/src/nonblocking/quic.rs:495-508) similarly rejects post-handshake connections purely based on global token availability. Stake is only resolved later, inside `qos.build_connection_context(&new_connection)` (streamer/src/nonblocking/quic.rs:512) and `SwQos::try_add_connection` (streamer/src/nonblocking/swqos.rs:301-343), which happens *after* the global bucket gate has already passed or failed. Per-IP protection (`ConnectionRateLimiter`, streamer/src/nonblocking/connection_rate_limiter.rs) only bounds a single source IP's rate; it does nothing to prevent many distinct IPs from collectively consuming the shared `MAX_CONNECTION_BURST`/`TOTAL_CONNECTIONS_PER_SECOND` capacity. Since the token bucket is FIFO/first-come and blind to stake, an attacker who spreads connection attempts across enough distinct source IPs (each staying under its individual per-IP quota, e.g. `max_connections_per_ipaddr_per_min` default 8/min) can keep the shared bucket persistently empty, denying admission to legitimate staked/stake-weighted peers that arrive concurrently — this is a pure resource race with no stake preference.

### Impact Explanation
This is a network-availability / DoS-class issue affecting the leader's TPU QUIC ingress: legitimate staked validators/relayers can be starved of connection slots by unstaked, zero-fee, zero-stake attackers, degrading transaction ingestion at the leader without requiring the attacker to hold stake or pay fees. It maps to the "resource exhaustion / DoS of validator core function (leader ingress)" bounty category rather than a consensus-safety bug, since it does not corrupt state, bypass sigverify, or forge blocks — it only affects connection admission fairness/availability.

### Likelihood Explanation
Feasibility requires only many distinct source IPs (botnet or cheap IP rotation via cloud/proxy providers), which is a well-established capability for unprivileged network attackers and does not require stake, keys, or validator/operator control. The per-IP limiter (`ConnectionRateLimiter::new`, streamer/src/nonblocking/connection_rate_limiter.rs:21-29) explicitly permits each IP up to `limit_per_minute * 10` burst and refill at `limit_per_minute/60` per second, so a modest number of distributed IPs (low thousands) can sustain the full `TOTAL_CONNECTIONS_PER_SECOND` = 2500 without any single IP being flagged, making this continuously repeatable at negligible cost.

### Recommendation
Reserve a fraction of `overall_connection_rate_limiter`'s capacity (or maintain a separate token bucket) exclusively for peers with a valid stake-derived TLS pubkey, resolved during/after the handshake, before applying the shared/unstaked-only bucket to the remainder; alternatively, perform the global-rate check after `get_connection_stake`/`build_connection_context` and weight admission decisions by stake similar to the existing `SwQos` staked/unstaked connection table split and `StakedStreamLoadEMA` capacity partitioning already used for stream throttling.

    let overall = std::sync::Arc::new(
        solana_net_utils::token_bucket::TokenBucket::new(

        crate::nonblocking::connection_rate_limiter::ConnectionRateLimiter::new(8, 80, 4),

    // draining the shared MAX_CONNECTION_BURST.

    fn build_connection_context(&self, connection: &Connection) -> SwQosConnectionContext {
        let remote_address = connection.remote_address();
        get_connection_stake(connection, &self.staked_nodes).map_or(
            SwQosConnectionContext {
                peer_type: ConnectionPeerType::Unstaked,
                total_stake: 0,
                remote_pubkey: None,
                in_staked_table: false,
                remote_address,
                stream_counter: None,
                last_update: Arc::new(AtomicU64::new(timing::timestamp())),
            },
            |(pubkey, stake, total_stake)| {
                // The heuristic is that the stake should be large enough to have 1 stream pass through within one throttle
                // interval during which we allow max (MAX_STREAMS_PER_MS * STREAM_THROTTLING_INTERVAL_MS) streams.

                let peer_type = {
                    let max_streams_per_ms = self.staked_stream_load_ema.max_streams_per_ms();
                    let min_stake_ratio =
                        1_f64 / (max_streams_per_ms * STREAM_THROTTLING_INTERVAL_MS) as f64;
                    let stake_ratio = stake as f64 / total_stake as f64;
                    if stake_ratio < min_stake_ratio {
                        // If it is a staked connection with ultra low stake ratio, treat it as unstaked.
                        ConnectionPeerType::Unstaked
                    } else {
                        ConnectionPeerType::Staked(stake)
                    }
                };

                SwQosConnectionContext {
                    peer_type,
                    total_stake,
                    remote_pubkey: Some(pubkey),
                    in_staked_table: false,
                    remote_address,
                    last_update: Arc::new(AtomicU64::new(timing::timestamp())),
                    stream_counter: None,
                }
            },
        )
