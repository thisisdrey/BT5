### Title
Quarantine-directory heuristic in `ObjectDirectoryPath` allows storage-relative path traversal into another repository's object tree - ([File: internal/git/localrepo/paths.go])

### Summary
`Repo.ObjectDirectoryPath` validates a client-influenced `GitObjectDirectory` value only against the *storage* root, not against the specific repository's own directory, and then completely skips the per-repository ownership check whenever the final path component merely *looks* like a quarantine directory name (`quarantine` or `<parent>=quarantine`/`<base>` prefixed with `tmp_objdir`). This lets a crafted relative value such as `../victim.git/objects/quarantine/tmp_objdir-x` sail through validation and resolve to a path outside the calling repository, as long as a directory with that exact naming pattern exists somewhere else in the same storage.

### Finding Description
`ObjectDirectoryPath` (`internal/git/localrepo/paths.go:21-83`) first checks the requested `GitObjectDirectory` value with `storage.ValidateRelativePath(storagePath, filepath.Join(repoPath, objectDirectoryPath))` (line 38). `storage.ValidateRelativePath` (`internal/gitaly/storage/locator.go:157-164`) only asserts the resulting path stays inside `storagePath` — the entire storage root shared by every repository — not inside `repoPath`. This means any `../`-based traversal that stays within the storage (e.g., into a sibling repository's directory tree) passes this check.

The function then derives `parentDir`/`baseDir` from the resulting relative path and sets `isTransactionQuarantineDir` purely from filename heuristics (line 43-45): [1](#0-0) 
If that heuristic matches, the code jumps straight to `fullPath := filepath.Join(repoPath, objectDirectoryPath)` and returns it (lines 77-82), entirely skipping the block (lines 53-75) that would otherwise verify the quarantine directory actually belongs to *this* repository by checking it is prefixed with `filepath.Join(tempDir, storage.QuarantineDirectoryPrefix(repo))`: [2](#0-1) 

Because the heuristic is satisfied by naming alone, a value like `../victim.git/objects/quarantine/tmp_objdir-x` bypasses the repo-ownership prefix check entirely. The only remaining gate is `os.Stat` at line 78, requiring the traversed path to actually exist on disk. `quarantine.Apply` (`internal/git/quarantine/quarantine.go:65-88`) is the code that normally *produces* legitimate `GitObjectDirectory` values of this shape (a `filepath.Rel(repoPath, quarantineDir)` result), but the RPC-facing `Repository.GitObjectDirectory` proto field is a plain client-settable string, and `ObjectDirectoryPath` performs no cryptographic or storage-authoritative binding between the value and the specific repository beyond the bypassed ownership check.

### Impact Explanation
If a directory whose relative path from a victim repository ends in `.../quarantine` or `.../quarantine/tmp_objdir-*` exists elsewhere in the same storage (e.g., another repository's own transient quarantine directory during a concurrent push, or Gitaly's shared storage temp directory `+gitaly/tmp/`), an attacker-controlled `GitObjectDirectory` value can make Gitaly resolve and operate on that foreign path instead of the caller's own repository, resulting in cross-repository object directory access — a repository-isolation violation (GitLab bounty class: cross-repository/storage-isolation bypass, information disclosure of another repository's objects).

### Likelihood Explanation
Exploitability is constrained: the attacker needs (1) an RPC surface where the client-controlled `GitObjectDirectory` field on a `Repository` message reaches `ObjectDirectoryPath` unmodified, (2) knowledge of the storage's on-disk layout (repo hashing, temp directory location) to construct a working `../` traversal, and (3) an actually-existing directory matching the naming heuristic at the traversal target — which, for legitimately created quarantine directories, includes an unpredictable random suffix from `tempdir.NewWithPrefix`, and requires timing to coincide with another in-flight push. These constraints make targeted exploitation against an arbitrary victim difficult, but the underlying validation defect — storage-level-only containment plus a naming-only ownership bypass — is a genuine gap in the isolation invariant and is directly demonstrable at the unit level with an artificially-created directory, matching the proof idea's scope.

### Recommendation
Remove the naming-only shortcut. Always require the object directory to satisfy the existing repo-ownership check (`storage.ValidateRelativePath(repoPath, objectDirectoryPath)` or the temp-dir-prefix check against `QuarantineDirectoryPrefix(repo)`), never relying solely on `baseDir`/`parentDir` string matching to skip validation. The quarantine-detection heuristic should only be used to decide *which* legitimate check to apply (in-repo vs. temp-dir), not to bypass ownership verification altogether.

### Proof of Concept
```go
// internal/git/localrepo/paths_test.go (illustrative)
func TestObjectDirectoryPath_QuarantineHeuristicBypass(t *testing.T) {
    cfg := testcfg.Build(t)
    storagePath := cfg.Storages[0].Path

    victimRelPath := "victim.git"
    victimPath := filepath.Join(storagePath, victimRelPath)
    // simulate a directory that merely matches the naming heuristic,
    // located inside a sibling repository rather than this repo's own tempdir.
    require.NoError(t, os.MkdirAll(filepath.Join(victimPath, "objects", "quarantine", "tmp_objdir-x"), 0o700))

    attackerRelPath := "attacker.git"
    require.NoError(t, os.MkdirAll(filepath.Join(storagePath, attackerRelPath), 0o700))

    repoProto := &gitalypb.Repository{
        StorageName:   cfg.Storages[0].Name,
        RelativePath:  attackerRelPath,
        GitObjectDirectory: "../victim.git/objects/quarantine/tmp_objdir-x",
    }
    repo := localrepo.New(..., repoProto, cfg)

    path, err := repo.ObjectDirectoryPath(ctx)
    // Expected (secure) behavior: structerr.NewInvalidArgument, path stays inside attacker.git
    // Actual behavior: err == nil, path == victimPath/objects/quarantine/tmp_objdir-x
    require.Error(t, err, "expected InvalidArgument due to cross-repository escape, got path %q", path)
}
```
This test demonstrates that `ObjectDirectoryPath` resolves a crafted `GitObjectDirectory` value into a directory physically located inside a different repository, rather than rejecting it with `codes.InvalidArgument`.
