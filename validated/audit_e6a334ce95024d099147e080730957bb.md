## Title
Firewall bypass via ConntrackCacheTicker localCache short-circuit that skips rulesVersion re-validation - (`File: firewall.go / firewall/cache.go`)

### Summary
`(f *Firewall).inConns` checks the per-goroutine `localCache` before consulting the global `Conntrack.Conns` map, and returns `true` (allow) on a hit without ever checking `c.rulesVersion != f.rulesVersion`. The rulesVersion re-validation logic exists only in the global-map path, so once a UDP flow tuple has been cached locally it will keep being allowed by that goroutine until `ConntrackCacheTicker` rolls over its `cacheTick`, regardless of a firewall reload that tightens the ruleset in between.

### Finding Description
`(f *Firewall).Drop` calls `f.inConns(fp, h, caPool, localCache)` [1](#0-0) . Inside `inConns`, the very first check is:

```go
if localCache != nil {
    if _, ok := localCache[fp]; ok {
        return true
    }
}
``` [2](#0-1) 

This returns immediately on a cache hit, bypassing the block below that specifically exists to re-validate stale conntrack entries against the current ruleset:

```go
if c.rulesVersion != f.rulesVersion {
    // This conntrack entry was for an older rule set, validate
    // it still passes with the current rule set
    ...
    if !table.match(fp, c.incoming, h.ConnectionState.peerCert, caPool) {
        ...
        delete(conntrack.Conns, fp)
        conntrack.Unlock()
        return false
    }
    ...
    c.rulesVersion = f.rulesVersion
}
``` [3](#0-2) 

That re-validation only runs when the lookup falls through to the global `conntrack.Conns` map — it is never reached once `localCache[fp]` already has an entry. `localCache` itself is only invalidated by `(c *ConntrackCacheTicker).Get()`, which resets the map solely based on a time-based `cacheTick` counter incremented by a background ticker goroutine (`interface.go` `conntrackCacheTimeout`), with no relationship to `f.rulesVersion`:

```go
func (c *ConntrackCacheTicker) Get() ConntrackCache {
    if c == nil {
        return nil
    }
    if tick := c.cacheTick.Load(); tick != c.cacheV {
        c.cacheV = tick
        ...
        c.cache = make(ConntrackCache, ll)
    }
    return c.cache
}
``` [4](#0-3) 

So an attacker who gets a single UDP flow tuple accepted once (via a matching outbound/inbound rule, populating `localCache[fp]` at the bottom of `inConns` at line 573-575) can continue sending identical-tuple packets, and every one of them short-circuits to "allow" in the calling goroutine, for as long as the local cache survives — i.e. up to the full `conntrackCacheTimeout` interval — even if `reloadFirewall` installs a stricter ruleset (bumping `f.rulesVersion`) in the meantime. The intended protection (re-checking `table.match` on rulesVersion mismatch) is dead code from the perspective of any goroutine holding a warm local cache entry.

### Impact Explanation
This is a firewall enforcement/bypass bug: a flow that was legitimately allowed under an old, looser ruleset continues to be treated as allowed after an administrator tightens the rules, for up to one `conntrackCacheTimeout` window per packet-processing goroutine. This violates the stated invariant that firewall enforcement must be total for every routed packet, and directly undermines the rulesVersion re-validation mechanism that the code otherwise clearly implements (see the dedicated `conn.rulesVersion` field and comment "record why the original connection passed the firewall, so we can re-validate after ruleset changes" at firewall.go lines 33-37). Impact is scoped to a bounded traffic-continuation bypass window rather than an unbounded/new-flow bypass, since brand-new tuples must still pass `table.match` in the fallback path.

### Likelihood Explanation
Preconditions are minimal and fully within reach of an unprivileged, already-connected peer that had at least one flow tuple accepted under the prior ruleset: no certificate forgery, no host access, and no cooperation from lighthouse/relay is needed. The attacker just needs to keep transmitting on the same tuple after knowing (or guessing) that a reload happened. This is deterministic and repeatable in any build using the `ConntrackCacheTicker` local-cache optimization, and reproducible in a unit test.

### Recommendation
In `(f *Firewall).inConns`, do not treat a `localCache` hit as unconditionally authoritative. Either: (a) store the `rulesVersion` (or a value derived from it) alongside the cached tuple and compare it against `f.rulesVersion` before returning `true`, invalidating/falling through to the full conntrack path on mismatch; or (b) invalidate `localCache` immediately when `f.rulesVersion` changes (e.g., have `reloadFirewall` bump a shared version that `ConntrackCacheTicker.Get` checks in addition to the time-based tick), rather than relying solely on the independent `conntrackCacheTimeout` ticker.

### Proof of Concept
Unit test in `firewall_test.go`:
1. Construct a `Firewall` with an outbound rule allowing UDP to some CIDR/host, and a `firewall.ConntrackCache{}` (`localCache`).
2. Call `f.Drop(fp, false, h, caPool, localCache)` once; assert it returns `nil` (allowed) and that `localCache[fp]` is now populated (confirms line 573-575 executed).
3. Simulate a firewall reload by bumping `f.rulesVersion` (mirroring what `reloadFirewall` does) and replacing `f.OutRules`/`f.InRules` with a stricter table that would reject `fp` via `table.match`.
4. Call `f.Drop(fp, false, h, caPool, localCache)` again with the same stale `localCache` (do not advance `ConntrackCacheTicker`/`cacheTick`).
5. Assert: expected behavior is `Drop` returns `ErrNoMatchingRule` (re-validated and dropped); actual behavior is `Drop` returns `nil` because `inConns` hits `localCache[fp]` at line 507-509 and returns `true` before ever reaching the `c.rulesVersion != f.rulesVersion` check — demonstrating the bypass.
6. As a control, repeat step 4 with `localCache = nil` (forcing the global-map path) and confirm it correctly returns `ErrNoMatchingRule`, isolating the bug to the local-cache short-circuit.

func (c *ConntrackCacheTicker) Get() ConntrackCache {
