### Title
`OutboundQueue::calculate_fee` can silently compute a zero remote relayer fee for valid, non-zero pricing parameters, letting senders queue Ethereum-bound messages without paying the relayer reward - (File: `bridges/snowbridge/pallets/outbound-queue/src/lib.rs`)

### Summary
`Pallet::calculate_fee` (called from `SendMessage::validate` in `bridges/snowbridge/pallets/outbound-queue/src/send_message_impl.rs`) computes the fee that a sender pays to have a message delivered to Ethereum. The remote-fee component is truncated through several integer-division steps (`FixedU128` scaling, `checked_div` by the exchange rate, and `convert_from_ether_decimals`'s `checked_div` by a decimals scaling factor). For legitimate, non-zero `PricingParameters` (which pass `PricingParameters::validate`), small `gas_used_at_most` values or small enough intermediate products round the remote fee down to `0`, exactly the class of bug described in the BarnBridge report (Solidity truncation making small purchases fee-free). This is confirmed by the pallet's own test, `test_calculate_fees_with_valid_exchange_rate_but_remote_fee_calculated_as_zero` [1](#0-0) , which the test comment itself flags as "invalid...which should be avoided" — yet no such guard exists in production code.

### Finding Description
The fee formula is documented as:
```
RemoteFee(Message) = MaxGasRequired(Message) * Params.MaxFeePerGas + Params.Reward
RemoteFeeAdjusted(Message) = Params.Multiplier * (RemoteFee(Message) / Params.Ratio("ETH/DOT"))
```
implemented in `calculate_fee`: [2](#0-1) 

The remote component goes through:
1. `calculate_remote_fee` — `fee_per_gas * gas_used_at_most + reward` (U256, no truncation here).
2. Downcast to `u128`, then reinterpreted as a `FixedU128` via `from_inner`, multiplied by `params.multiplier`, and divided by `params.exchange_rate` via `checked_div` (integer division on the fixed-point representation).
3. `convert_from_ether_decimals` performs a final `checked_div` by `10^(18 - Decimals)` (e.g. `10^8` for a 10-decimal DOT-based chain): [3](#0-2) 

`PricingParameters::validate` only guards against zero-valued parameters (`exchange_rate`, `fee_per_gas`, `rewards.local`, `rewards.remote`, `multiplier`) [4](#0-3) . It does **not** guard against the *combination* of a small `gas_used_at_most` (determined per-command by `GasMeter::maximum_gas_used_at_most`) with these otherwise-valid parameters producing a sub-unit (and thus truncated-to-zero) remote fee. The pallet's own regression test proves this occurs with entirely plausible parameters (`exchange_rate = 1/1`, `fee_per_gas = 1`, `reward = 1`) — none of which are zero and all of which pass `validate()` .

`SendMessage::validate` calls `calculate_fee` and returns the `(Ticket, Fee)` pair without any check that `fee.remote != 0` [5](#0-4) ; `deliver` then unconditionally enqueues the message into `T::MessageQueue` [6](#0-5) . There is no invariant anywhere in this path enforcing `fee.remote > 0` before a message is accepted and queued for Ethereum delivery.

### Impact Explanation
This is a public, unprivileged entrypoint reachable by any sibling parachain sending XCM through the Snowbridge exporter, or (for governance-adjacent commands) the system pallet, whenever the chosen command's `maximum_gas_used_at_most` combined with governance-set pricing parameters produces a sub-unit remote fee. The result is underpriced (here, literally free) use of the bridge's finite outbound resources:
- `MaxMessagesPerBlock` capacity is consumed per block by messages that pay no relayer reward, since `do_process_message` enforces only the count limit, not fee validity [7](#0-6) .
- Because relayers are compensated purely from `Message.Reward` + gas refund on the Ethereum side, a `reward: 0` (or `max_fee_per_gas: 0`) message gives relayers no incentive to deliver it, so such messages can sit unrelayed indefinitely — a form of stalled/degraded bridge processing exactly matching the accepted impact category "public underpriced work that degrades block production or stalls bridge processing."
- Repeated exploitation lets an attacker spam the outbound queue and merkle commitment machinery (`Messages`/`MessageLeaves`/`on_finalize` commit) at zero marginal cost, displacing legitimately-priced messages within the `MaxMessagesPerBlock` bound.

### Likelihood Explanation
Likelihood is moderate-to-high: it does not require any privileged actor, malicious relayer, or governance misbehavior — only a combination of governance-set (but individually valid) pricing parameters and a low-`gas_used_at_most` command, which the pallet's own test suite demonstrates occurs with simple, realistic values. Since pricing parameters are periodically updated by governance for market conditions (per the module docs) rather than to specifically defend against this rounding edge case, drift into this zero-fee regime is plausible over time, and any XCM-originated message with a cheap command is a candidate trigger.

### Recommendation
Add an explicit non-zero check on the computed remote fee (and ideally each intermediate corrupted value) in `calculate_fee`/`SendMessage::validate`, e.g. reject (`SendError`) or round up (ceiling division) when the truncated remote fee is `0` for a message whose `gas_used_at_most`/`reward` inputs are non-zero — mirroring the minimum-fee pattern already used in `substrate/frame/transaction-payment/asset-tx-payment/src/payment.rs`'s `withdraw_fee`/`can_withdraw_fee` (`min_converted_fee = if fee.is_zero() { Zero::zero() } else { One::one() }`) [8](#0-7) . Convert the acknowledged-but-unfixed test `test_calculate_fees_with_valid_exchange_rate_but_remote_fee_calculated_as_zero` into an assertion that this case is rejected/rounded rather than merely documenting it as invalid.

### Proof of Concept
Using the existing pallet test harness (`bridges/snowbridge/pallets/outbound-queue/src/test.rs`), with valid, all-non-zero `PricingParameters` (`exchange_rate = FixedU128::from_rational(1,1)`, `fee_per_gas = 1`, `rewards = {local:1, remote:1}`, `multiplier = FixedU128::from_rational(1,1)`) and `gas_used = 250000`, `OutboundQueue::calculate_fee` returns `Fee { local: 698000000, remote: 0 }` [1](#0-0) . Since `SendMessage::validate` performs no check on `fee.remote` before returning the ticket, and `deliver` unconditionally enqueues the message [9](#0-8) , any command whose `GasMeter::maximum_gas_used_at_most` and the then-current governance pricing parameters reduce to this pattern will be accepted for delivery to Ethereum while contributing zero relayer reward.

fn test_calculate_fees_with_valid_exchange_rate_but_remote_fee_calculated_as_zero() {

	});

		/// Calculate total fee in native currency to cover all costs of delivering a message to the
		/// remote destination. See module-level documentation for more details.
		pub(crate) fn calculate_fee(
			gas_used_at_most: u64,
			params: PricingParameters<T::Balance>,
		) -> Fee<T::Balance> {
			// Remote fee in ether
			let fee = Self::calculate_remote_fee(
				gas_used_at_most,
				params.fee_per_gas,
				params.rewards.remote,
			);

			// downcast to u128
			let fee: u128 = fee.try_into().defensive_unwrap_or(u128::MAX);

			// multiply by multiplier and convert to local currency
			let fee = FixedU128::from_inner(fee)
				.saturating_mul(params.multiplier)
				.checked_div(&params.exchange_rate)
				.expect("exchange rate is not zero; qed")
				.into_inner();

			// adjust fixed point to match local currency
			let fee = Self::convert_from_ether_decimals(fee);

			Fee::from((Self::calculate_local_fee(), fee))
		}

			return Err(InvalidPricingParameters);

			return Err(InvalidPricingParameters);
		}
		if self.multiplier == FixedU128::zero() {
			return Err(InvalidPricingParameters);
		}
		Ok(())
	}

	fn validate(
		message: &Message,
	) -> Result<(Self::Ticket, Fee<<Self as SendMessageFeeProvider>::Balance>), SendError> {
		// The inner payload should not be too large
		let payload = message.command.abi_encode();
		ensure!(
			payload.len() < T::MaxMessagePayloadSize::get() as usize,
			SendError::MessageTooLarge
		);

		// Ensure there is a registered channel we can transmit this message on
		ensure!(T::Channels::contains(&message.channel_id), SendError::InvalidChannel);

		// Generate a unique message id unless one is provided
		let message_id: H256 = message
			.id
			.unwrap_or_else(|| unique((message.channel_id, &message.command)).into());

		let gas_used_at_most = T::GasMeter::maximum_gas_used_at_most(&message.command);
		let fee = Self::calculate_fee(gas_used_at_most, T::PricingParameters::get());

		let queued_message: VersionedQueuedMessage = QueuedMessage {
			id: message_id,
			channel_id: message.channel_id,
			command: message.command.clone(),
		}
		.into();
		// The whole message should not be too large
		let encoded = queued_message.encode().try_into().map_err(|_| SendError::MessageTooLarge)?;

		let ticket = Ticket { message_id, channel_id: message.channel_id, message: encoded };

		Ok((ticket, fee))
	}

	fn deliver(ticket: Self::Ticket) -> Result<H256, SendError> {
		let origin = AggregateMessageOrigin::Snowbridge(ticket.channel_id);

		if ticket.channel_id != PRIMARY_GOVERNANCE_CHANNEL {
			ensure!(!Self::operating_mode().is_halted(), SendError::Halted);
		}

		let message = ticket.message.as_bounded_slice();

		T::MessageQueue::enqueue_message(message, origin);
		Self::deposit_event(Event::MessageQueued { id: ticket.message_id });
		Ok(ticket.message_id)
	}
