## Title
Unauthenticated non-winning block accepted into staging DB via `/v2/blocks/upload` RPC endpoint bypassing sortition-winner check - (File: stackslib/src/net/api/postblock.rs)

## Summary
`Relayer::process_new_anchored_block` never itself checks that the posted block is the sortition winner for the given `consensus_hash`; that check lives only in `Relayer::validate_blocks_push`. The `/v2/blocks/upload/:consensus_hash` RPC handler calls `process_new_anchored_block` directly, so any remote unprivileged client can POST an arbitrary, non-winning `StacksBlock` for a *known, valid* `consensus_hash` and have it staged in the chainstate DB.

## Finding Description
`Relayer::process_new_anchored_block` (`stackslib/src/net/relay.rs:797-867`) only performs: fault-injection hiding check, `find_parent_snapshot_for_stacks_block`, `static_check_problematic_relayed_block`, and `chainstate.preprocess_anchored_block`. It never compares `block.block_hash()` against `sn.winning_stacks_block_hash` for the sortition tied to `consensus_hash` — that comparison exists only in the separate function `Relayer::validate_blocks_push` [1](#0-0) .

`RPCPostBlockRequestHandler::try_handle_request` (`stackslib/src/net/api/postblock.rs:125-227`) implements the `/v2/blocks/upload/(?P<consensus_hash>...)` HTTP RPC endpoint. It parses an attacker-supplied block from the raw POST body, verifies only that `consensus_hash` corresponds to *some* known sortition (`SortitionDB::get_sortition_id_by_consensus`), and then calls `Relayer::process_new_anchored_block` directly — with no call to `Relayer::validate_blocks_push` anywhere in this path [2](#0-1) .

Consequently, an attacker can pick any past/valid `consensus_hash` (which is public/known information, not secret) and submit a completely different, unauthenticated `StacksBlock` whose `block_hash()` does not match `sn.winning_stacks_block_hash` for that sortition. As long as it passes `find_parent_snapshot_for_stacks_block` (i.e., its declared parent block/consensus hash resolves to a real prior snapshot) and `static_check_problematic_relayed_block`, `chainstate.preprocess_anchored_block` will store it in the staging blocks DB, and `process_new_anchored_block` returns `BlockAcceptResponse::Accepted`. The handler then sets `accepted = true` and — critically — calls `node.set_relay_message(...)`, which forwards the forged block for propagation to the rest of the P2P network [3](#0-2) .

## Impact Explanation
This allows an unprivileged remote attacker to write an unauthenticated, non-canonical (non-winning) Stacks block into the node's staging blocks database via a single, unauthenticated HTTP POST, and to have the victim node relay/gossip this forged block onward to its peers. This matches "Critical: unauthenticated write to state ... network-wide propagation of forged data."

## Likelihood Explanation
Preconditions are minimal: the attacker needs only network reachability to the node's RPC HTTP port and knowledge of any valid `consensus_hash` from the chain history (publicly known, not secret) plus a syntactically valid `StacksBlock` whose declared parent resolves via `find_parent_snapshot_for_stacks_block`. No peer key, StackerDB slot, or RPC secret is required. The endpoint accepts arbitrary bytes up to `MAX_PAYLOAD_LEN`, and is repeatable per distinct consensus hash/parent pairing.

## Recommendation
Move the sortition-winner check (`sn.winning_stacks_block_hash == block.block_hash()`) into `Relayer::process_new_anchored_block` itself (or require `validate_blocks_push` semantics as a precondition enforced inside the function), so that every caller — including `RPCPostBlockRequestHandler::try_handle_request` — is protected regardless of whether it separately invokes `validate_blocks_push`.

## Proof of Concept
Rust test plan:
1. Set up a `TestPeer`/chainstate with a known valid sortition at `consensus_hash` CH where the actual winning block is `W`.
2. Construct a distinct, well-formed `StacksBlock` `B` (`B.block_hash() != W.block_hash()`) whose parent block/consensus-hash fields resolve successfully via `find_parent_snapshot_for_stacks_block` (e.g., reuse a legitimate earlier parent).
3. Issue an HTTP POST to `/v2/blocks/upload/{CH}` with body = `B.serialize_to_vec()` and `Content-Type: application/octet-stream`, using `RPCPostBlockRequestHandler`/`StacksHttpRequest::new_post_block`.
4. Assert the response JSON `StacksBlockAcceptedData.accepted == true`, and directly query the chainstate staging DB (`StacksChainState::get_staging_block`) to confirm `B` was stored despite `B.block_hash() != W.block_hash()` (`sn.winning_stacks_block_hash`), proving the sortition-winner check was bypassed.

    pub fn process_new_anchored_block(
        sort_ic: &SortitionDBConn,
        chainstate: &mut StacksChainState,
        consensus_hash: &ConsensusHash,
        block: &StacksBlock,
        download_time: u64,
    ) -> Result<BlockAcceptResponse, chainstate_error> {
        info!(
            "Handle incoming block {}/{}",
            consensus_hash,
            &block.block_hash()
        );

        let block_sn = SortitionDB::get_block_snapshot_consensus(sort_ic, consensus_hash)?
            .ok_or(chainstate_error::DBError(db_error::NotFoundError))?;

        if chainstate.fault_injection.hide_blocks
            && Self::fault_injection_is_block_hidden(&block.header, block_sn.block_height)
        {
            return Ok(BlockAcceptResponse::Rejected(
                "Fault injection: block is hidden".into(),
            ));
        }

        // find the snapshot of the parent of this block
        let parent_block_snapshot = match sort_ic
            .find_parent_snapshot_for_stacks_block(consensus_hash, &block.block_hash())?
        {
            Some(sn) => sn,
            None => {
                // doesn't correspond to a PoX-valid sortition
                return Ok(BlockAcceptResponse::Rejected(
                    "Block does not correspond to a known sortition".into(),
                ));
            }
        };

        // don't relay this block if it's using the wrong AST rules (this would render at least one of its
        // txs problematic).
        let epoch_id = SortitionDB::get_stacks_epoch(sort_ic, block_sn.block_height)?
            .expect("FATAL: no epoch defined")
            .epoch_id;
        if !Relayer::static_check_problematic_relayed_block(chainstate.mainnet, epoch_id, block) {
            warn!(
                "Block is problematic; will not store or relay";
                "stacks_block_hash" => %block.block_hash(),
                "consensus_hash" => %consensus_hash,
                "burn_height" => block.header.total_work.work,
                "sortition_height" => block_sn.block_height
            );
            return Ok(BlockAcceptResponse::Rejected("Block is problematic".into()));
        }

        let res = chainstate.preprocess_anchored_block(
            sort_ic,
            consensus_hash,
            block,
            &parent_block_snapshot.consensus_hash,
            download_time,
        )?;
        if res {
            debug!(
                "Stored incoming block {}/{}",
                consensus_hash,
                &block.block_hash()
            );
            return Ok(BlockAcceptResponse::Accepted);
        } else {
            return Ok(BlockAcceptResponse::AlreadyStored);
        }
    }
