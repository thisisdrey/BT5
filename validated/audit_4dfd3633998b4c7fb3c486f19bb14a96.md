### Title
`DebtToken.repayAll` always reverts when the payer holds exactly the outstanding debt and `repayFee > 0` - ([File: contracts/DebtToken.sol](contracts/DebtToken.sol)) [1](#0-0) 

### Summary
`DebtToken.repayAll` calculates the repayment requirement as `debt + repayFee`, first transfers the fee out of the payer’s synthetic-token balance, and then attempts to burn the full original debt amount from the same balance. [2](#0-1)  Consequently, a user holding exactly enough synthetic tokens to cover the debt cannot execute the intended “repay everything” operation; the call reverts after the fee is deducted because the remaining balance is only `debt - fee`. [3](#0-2) 

### Finding Description
`repayAll` obtains `_repaid` from the debtor’s full `DebtToken` balance and then calls `quoteRepayIn(_repaid)`, which returns `_repaid + fee` as the gross synthetic-token requirement. [4](#0-3)  The implementation then seizes `_fee` from `_msgSender` and separately burns `_repaid` from `_msgSender`, rather than treating the payer’s input as a gross amount from which the fee is deducted. [5](#0-4)  `SyntheticToken._burn` enforces sufficient post-seize balance, so a payer with exactly `_repaid` tokens necessarily hits `BurnAmountExceedsBalance` once the fee transfer leaves fewer than `_repaid` tokens. [6](#0-5)  By contrast, the ordinary `repay` path already treats `amount_` as a gross amount and uses `quoteRepayOut` to split it into principal and fee. [7](#0-6) 

### Impact Explanation
The dedicated dust-avoidance entry point is unusable in the natural case where the borrower holds synthetic tokens equal to the debt and expects the entire balance to be applied to the repayment. [8](#0-7)  The user must instead acquire additional synthetic tokens solely to pay the fee, or use `repay` and potentially leave residual debt. [9](#0-8)  Because outstanding debt keeps collateral locked, this can temporarily prevent full collateral withdrawal until the user obtains extra synthetic tokens or the fee configuration is zero. [10](#0-9) 

### Likelihood Explanation
The condition is deterministic whenever `repayFee > 0` and the payer’s synthetic-token balance is at least the debt but below `debt + fee`. [11](#0-10)  The protocol’s own test suite demonstrates that `repayAll` with a nonzero fee only succeeds after deliberately sending additional synthetic tokens to cover the fee. [12](#0-11)  The vulnerable path is externally reachable and is not prevented by `whenNotShutdown`, `nonReentrant`, or `onlyIfSyntheticTokenExists`. [13](#0-12) 

### Recommendation
Make `repayAll` derive the payer input using the same gross-amount semantics as `repay`, or document and enforce that it requires `debt + fee`. [14](#0-13)  A minimal fix is to burn `_amount` for accounting while transferring `_fee` to the collector and burning only `_repaid`, but this still requires `_amount = _repaid + _fee`; therefore the more user-compatible fix is to cap repayment at `quoteRepayOut(payerBalance)` or provide a separate gross-balance variant. [9](#0-8)  If the intended API requires `debt + fee`, add an explicit precheck against the payer’s synthetic-token balance and revert with a domain-specific error before attempting the fee seize and burn. [3](#0-2) 

### Proof of Concept
The following Hardhat-style sequence reproduces the revert from an unprivileged borrower once `repayFee` is already nonzero in the deployed configuration.

```ts
const debt = await msUSDDebt.balanceOf(alice.address);
const repayFee = await feeProvider.repayFee();
const fee = debt.mul(repayFee).div(parseEther('1'));

// Alice has exactly enough synthetic token to cover principal, but not principal + fee.
expect(await msUSD.balanceOf(alice.address)).to.eq(debt);

// repayAll internally seizes `fee`, leaving `debt - fee`, then tries to burn `debt`.
await expect(
  msUSDDebt.connect(alice).repayAll(alice.address)
).to.be.revertedWithCustomError(msUSD, 'BurnAmountExceedsBalance');
```

The existing test suite already establishes that this path only succeeds when extra synthetic tokens are supplied specifically to cover the fee. [15](#0-14)

     * @return _fee The fee amount collected

        address onBehalfOf_
    )
        external
        override
        whenNotShutdown
        nonReentrant
        onlyIfSyntheticTokenExists
        returns (uint256 _repaid, uint256 _fee)
    {
        accrueInterest();

        _repaid = balanceOf(onBehalfOf_);
        if (_repaid == 0) revert AmountIsZero();

        address _msgSender = _msgSender();
        ISyntheticToken _syntheticToken = syntheticToken;

        uint256 _amount;
