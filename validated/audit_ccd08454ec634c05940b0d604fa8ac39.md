### Title
Fee bypass via `|delta|<=1` NEP-245/IMT exemption when trades are split across many token_ids/intents - (File: contracts/defuse/core/src/intents/token_diff.rs)

### Summary
`TokenDiff::token_fee` returns `Pips::ZERO` for any `Nep245`/`Imt` entry whose `amount <= 1`, and the check is evaluated per `(token_id, delta)` entry independently rather than being aggregated over the economic value moved by the signer. Because an attacker fully controls their own NEP-245 contract and Verifier deposits are accepted from any predecessor with no whitelist, they can wrap N units of real value into N distinct token_ids (each with balance 1), deposit them via `mt_on_transfer`, and spend them all in one `TokenDiff` (or a batch of same-signer `TokenDiff`s) with N entries of `delta = -1`, each independently qualifying for the zero-fee branch, moving the same economic value that a single `Nep141` diff of `-N` would have paid `fee_ceil(N)` on.

### Finding Description
Binding claimed broken: `fee_owed(economic_value_moved = N) == fee_credited_to(fee_collector)`.

For a straight NEP-141 trade, `execute_intent` computes, for the single negative-delta entry, `fee = Self::token_fee(token_id, N, protocol_fee).fee_ceil(N)`, which for `TokenIdType::Nep141` always falls through to `fee` (the configured `protocol_fee`), so `fee_owed = fee_ceil(N) > 0` for `N` large enough [3](#0-2) .

The exemption logic is:
```
TokenIdType::Nep141 => {}
TokenIdType::Nep245 | TokenIdType::Imt if amount > 1 => {}
TokenIdType::Nep171 | TokenIdType::Nep245 | TokenIdType::Imt => return Pips::ZERO,
``` [4](#0-3) 

This is evaluated once per `(token_id, delta)` pair inside the `for (token_id, delta) in &self.diff` loop of `execute_intent`, using only that single entry's `amount = delta.unsigned_abs()` — there is no aggregation across entries in the same diff, nor across multiple `TokenDiff` intents from the same signer in the same batch [5](#0-4) .

`mt_on_transfer` derives `TokenId::Nep245` purely from `env::predecessor_account_id()` and the caller-supplied `token_id` string, with no restriction on which contracts may deposit [1](#0-0) ; anyone can deploy such a contract, as confirmed in test comments describing deposit of "fictitious" tokens from arbitrary contracts [2](#0-1) .

Exploit flow: attacker deploys their own MT contract, locks/backs `N` units of real value, mints `N` distinct token_ids each with balance `1`, and calls `mt_on_transfer` to deposit them into their Verifier account. They then submit one `TokenDiff` with `N` entries `{Nep245Token_i: -1}` plus a matching positive-delta entry for the payment token they receive (or, symmetrically, matched against a counterparty's diff in the same batch). Every negative-delta entry has `amount == 1`, so `token_fee` returns `Pips::ZERO` for all `N` entries — the protocol collects **zero** fee for moving `N` units of value, whereas doing the equivalent trade as one `Nep141` diff of `-N` would have paid `fee_ceil(N)`.

No existing guard catches this: `TransferMatcher::finalize` [6](#0-5)  only checks that deltas net to zero across the batch — it enforces no per-token minimum-fee or aggregate-value invariant, and the signature/nonce checks in `execute_signed_intent` [7](#0-6)  do not touch fee computation at all.

### Impact Explanation
Protocol fee revenue is systematically avoidable for arbitrarily large trade values by any unprivileged user, matching the listed Critical category "protocol fees bypassed." The `fee_collector` receives less than intended for economically equivalent trades [8](#0-7) ; this is repeatable per trade, per token, per account, with no upper bound on `N` other than transaction size/gas (splitting can also span multiple batched signed intents with sequential nonces).

However, note the caveat: this does not steal Verifier-custodied funds from unwilling parties — the batch must still net to zero, so any counterparty must voluntarily accept the self-minted MT tokens (which are only as valuable as the attacker's own contract's redemption logic makes them). The "victim" here is the protocol's fee revenue, not another user's balance.

### Likelihood Explanation
Fully within an unprivileged attacker's capability: deploying a NEP-245 contract, minting tokens to themselves, and calling `mt_on_transfer`/submitting `MultiPayload`s are all ordinary, permission-less actions. No role, relayer key, or DAO action is required. Cost is limited to NEAR gas/storage for deploying the MT contract and the (bounded by gas limits) number of token_id entries per transaction — this scales with `N` but is otherwise unrestricted and fully repeatable.

### Recommendation
Compute `token_fee`/apply the `|delta|<=1` exemption based on aggregate value per underlying token contract (or per signer per batch) rather than per individual `(token_id, delta)` entry, or restrict the exemption to `TokenIdType::Nep171` only (true NFTs, which cannot have fungible balance) and require actual NFT-uniqueness semantics rather than an arbitrary MT/IMT balance-of-1 heuristic that an attacker can trivially replicate at scale by minting many distinct token_ids.

### Proof of Concept
```
#[test]
fn fee_bypass_via_split_nep245_units() {
    // Setup: protocol_fee = Pips::ONE_PERCENT (or any non-zero fee)
    let fee = Pips::ONE_PERCENT;
    let n = 1000u128;

    // Case A: single Nep141 diff moving N units
    let nep141 = TokenId::from(Nep141TokenId::new("ft.near".parse().unwrap()));
    let fee_a = TokenDiff::token_fee(&nep141, n, fee).fee_ceil(n);
    assert!(fee_a > 0, "Nep141 diff of N must pay non-zero fee");

    // Case B: N separate Nep245 entries, each delta = -1, from attacker-controlled MT contract
    let mut fee_b_total: u128 = 0;
    for i in 0..n {
        let tid = TokenId::from(Nep245TokenId::new(
            "attacker-mt.near".parse().unwrap(),
            i.to_string(),
        ));
        fee_b_total += TokenDiff::token_fee(&tid, 1, fee).fee_ceil(1);
    }

    // Binding under test: fee_owed(N units moved) should be equal regardless of token representation
    assert_eq!(fee_b_total, 0, "attacker pays zero fee for N units split across Nep245 entries");
    assert_ne!(fee_a, fee_b_total, "fee bypass demonstrated: Nep141 path pays fee, split Nep245 path pays none");
}
```
This can be extended to a `near-workspaces` sandbox test: deploy an MT contract, deposit `N` token_ids of balance 1 via `mt_on_transfer`, submit one `TokenDiff` intent with `N` negative-delta entries plus a matching counterparty diff, and assert `fee_collector`'s balance increase is `0`, versus a control scenario using a plain `Nep141` diff of `-N` where `fee_collector`'s balance increases by `fee_ceil(N) > 0`.

    pub fn token_fee(token_id: impl Into<TokenIdType>, amount: u128, fee: Pips) -> Pips {
        let token_id = token_id.into();
        match token_id {
            TokenIdType::Nep141 => {}
            TokenIdType::Nep245 | TokenIdType::Imt if amount > 1 => {}
            // do not take fees on NFTs and MTs with |delta| <= 1
            TokenIdType::Nep171 | TokenIdType::Nep245 | TokenIdType::Imt => return Pips::ZERO,
        }
        fee
    }

    fn execute_signed_intent(&mut self, signed: MultiPayload) -> Result<()> {
        // verify signed payload and get public key
        let public_key = signed.verify().ok_or(DefuseError::InvalidSignature)?;

        // calculate intent hash
        let hash = signed.hash();

        // extract NEP-413 payload
        let DefusePayload::<DefuseIntents> {
            signer_id,
            verifying_contract,
            deadline,
            nonce,
            message: intents,
        } = signed.extract_defuse_payload()?;

        // check recipient
        if verifying_contract != *self.state.verifying_contract() {
            return Err(DefuseError::WrongVerifyingContract);
        }

        self.inspector.on_deadline(deadline);

        // make sure message is still valid
        if deadline < Timestamp::now() {
            return Err(DefuseError::DeadlineExpired);
        }

        // make sure the account has this public key
        if !self.state.has_public_key(&signer_id, &public_key) {
            return Err(DefuseError::PublicKeyNotExist(signer_id, public_key));
        }

        // commit nonce
        self.verify_intent_nonce(nonce, deadline)?;
        self.state.commit_nonce(signer_id.clone(), nonce)?;

        intents.execute_intent(&signer_id, self, hash)?;
        self.inspector.on_intent_executed(&signer_id, hash, nonce);

        Ok(())
    }
