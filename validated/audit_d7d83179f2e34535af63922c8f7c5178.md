### Title
Unvalidated Pre-Existing Alternates File Permanently Blocks Object-Pool Linking - ([File: internal/git/objectpool/link.go])

### Summary
Gitaly RPCs that create or import a repository from externally supplied content (e.g. `CreateRepositoryFromSnapshot`, `CreateRepositoryFromBundle`) do not validate that the resulting repository's `objects/info/alternates` file is unset/empty at creation time. If such a file already exists with unrecognized content, a later call to `LinkRepositoryToObjectPool` — the RPC responsible for joining the repository to an object pool for deduplication — permanently fails, mirroring the reported bug class where a missing "must be default/unset" check during initialization causes a later finalize-style operation to revert and require manual intervention.

### Finding Description
`objectpool.Link` (the implementation backing the `LinkRepositoryToObjectPool` RPC) calls `linkedToRepository` to decide whether the repository is already correctly linked: [1](#0-0) 

If the existing `objects/info/alternates` content doesn't match either the expected relative path or the pool's absolute path, `linkedToRepository` returns a hard error (`"unexpected alternates content: %q"`), and `Link` aborts without modifying the file: [2](#0-1) 

Nothing in the repository-creation paths validates that a freshly created repository's alternates file is empty/default before it is considered ready. `CreateRepositoryFromSnapshot` explicitly extracts an **untrusted, unvalidated tar archive** directly on top of a freshly `git init`'d bare repository: [3](#0-2) 

The archive can contain an `objects/info/alternates` file with arbitrary contents (e.g. a garbage path unrelated to any pool). Similarly, `CreateRepositoryFromBundle` clones from a user-supplied bundle stream into the new repository without stripping/validating alternates-related state: [4](#0-3) 

Because `repoutil.Create` only checks that the *target path* doesn't already exist on disk — not that the *contents seeded into it* are in a sane default state — there is no equivalent of the `tokenAddress == address(0)` guard from the reported bug. This is directly analogous: initialization accepts an untrusted/attacker-influenced value for a field ("alternates") that later logic (`Link`, playing the role of `finalizeCampaign`/`_createTokenAndMintSupply`) assumes to be unset, and unconditionally errors out if it is not.

The existing test suite already demonstrates the exact failure mode when an alternates file with unexpected content pre-exists before `LinkRepositoryToObjectPool` is called: [5](#0-4) 

### Impact Explanation
`LinkRepositoryToObjectPool` is a core step of the fork/pool deduplication workflow (GitLab forks are linked to an object pool to share objects). If a repository created via `CreateRepositoryFromSnapshot` or `CreateRepositoryFromBundle` contains a crafted/incidental `objects/info/alternates` file that doesn't match the pool's path, every subsequent `LinkRepositoryToObjectPool` call against that repository will deterministically fail with an `Internal` error (`"unexpected alternates content"`). This permanently prevents that repository from being deduplicated via the object pool, is not self-healing, and requires an operator to manually inspect and remove/repair the `objects/info/alternates` file on disk before the RPC can succeed — the same class of "administrator must manually intervene" impact described in the source report. Since `CreateRepositoryFromSnapshot`'s own code comment says the archive "is trusted *a lot*" and needs "a lot of hardening," this is a recognized but currently unmitigated trust boundary.

### Likelihood Explanation
Reachable by an ordinary user/administrative caller of `CreateRepositoryFromSnapshot` (HTTP-fetched tar snapshot) or `CreateRepositoryFromBundle` (client-streamed git bundle) — both are documented as accepting largely untrusted archive/bundle content. No special privileges beyond calling these already-exposed repository-creation RPCs are needed to plant a conflicting alternates file; the failure is deterministic and reproducible on the very next `LinkRepositoryToObjectPool` call.

### Recommendation
During repository creation/import (`repoutil.Create`, `CreateRepositoryFromSnapshot`, `CreateRepositoryFromBundle`), validate and reject (or explicitly strip) any pre-existing `objects/info/alternates` file in the seeded content before considering the repository successfully created — analogous to validating `tokenAddress == address(0)` at `initialize()`. Alternatively, harden `linkedToRepository`/`Link` to safely reconcile or clearly report this as a data-integrity error at creation time rather than surfacing it as a hard failure only when `LinkRepositoryToObjectPool` is later invoked.

### Proof of Concept
1. Call `CreateRepositoryFromSnapshot` (or `CreateRepositoryFromBundle`) with an archive/bundle whose `objects/info/alternates` file contains an arbitrary string, e.g. `"mock/objects\n"` (as used in the existing regression test) — this succeeds and the repository is created.
2. Create an object pool and call `LinkRepositoryToObjectPool` against the repository from step 1.
3. Observe the RPC fails with `structerr.NewInternal("unexpected alternates content: %q", "mock/objects")`, as reproduced by the existing `TestLink_noClobber` test: [5](#0-4) .
4. Repeated calls to `LinkRepositoryToObjectPool` continue to fail indefinitely until an operator manually fixes the on-disk alternates file — there is no RPC-level remediation path.

// linkedToRepository tests if a repository is linked to an object pool
func linkedToRepository(ctx context.Context, pool, repo *localrepo.Repo) (bool, error) {
	poolPath, err := pool.Path(ctx)
	if err != nil {
		return false, fmt.Errorf("getting object pool path: %w", err)
	}

	repoPath, err := repo.Path(ctx)
	if err != nil {
		return false, fmt.Errorf("getting repo path: %w", err)
	}

	altInfo, err := stats.AlternatesInfoForRepository(repoPath)
	if err != nil {
		return false, fmt.Errorf("getting alternates info: %w", err)
	}

	if !altInfo.Exists || len(altInfo.ObjectDirectories) == 0 {
		return false, nil
	}

	relPath := altInfo.ObjectDirectories[0]
	expectedRelPath, err := getRelativeObjectPath(ctx, pool, repo)
	if err != nil {
		return false, err
	}

	if relPath == expectedRelPath {
		return true, nil
	}

	if filepath.Clean(relPath) != filepath.Join(poolPath, "objects") {
		return false, fmt.Errorf("unexpected alternates content: %q", relPath)
	}

	return false, nil
}

func TestLink_noClobber(t *testing.T) {
	t.Parallel()

	ctx := testhelper.Context(t)

	cfg, repoProto, repoPath, _, client := setup(t, ctx)
	poolProto, _, _ := createObjectPool(t, ctx, cfg, repoProto)

	alternatesFile := filepath.Join(repoPath, "objects/info/alternates")
	require.NoFileExists(t, alternatesFile)

	contentBefore := "mock/objects\n"
	require.NoError(t, os.WriteFile(alternatesFile, []byte(contentBefore), mode.File))

	request := &gitalypb.LinkRepositoryToObjectPoolRequest{
		Repository: repoProto,
		ObjectPool: poolProto,
	}

	_, err := client.LinkRepositoryToObjectPool(ctx, request)
	testhelper.RequireGrpcError(t, structerr.NewInternal("unexpected alternates content: %q", "mock/objects"), err)

	contentAfter := testhelper.MustReadFile(t, alternatesFile)
	require.Equal(t, contentBefore, string(contentAfter), "contents of existing alternates file should not have changed")
}
