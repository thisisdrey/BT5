Audit Report

## Title
`eth_estimate_gas` dry-run weight-limit computation omits the `overweight_by` cap applied during real dispatch, making estimated gas insufficient on-chain - ([File: substrate/frame/revive/src/evm/call.rs])

## Summary
`GenericTransaction::into_call` computes the dispatchable's `weight_limit` differently for dry runs (`eth_estimateGas`/`eth_call`) versus real extrinsic submission: only the real-dispatch path (`is_dry_run == false`) subtracts `overweight_by = info.total_weight().saturating_sub(evm_max_extrinsic_weight())` from `weight_limit`. Because `eth_estimate_gas`'s binary search always uses the uncapped dry-run path, it can converge on a gas value that succeeds during estimation but fails with an out-of-weight error when the same transaction is submitted for real.

## Finding Description
In `into_call` at `substrate/frame/revive/src/evm/call.rs` (lines 203-239), `weight_limit` is first derived from `remaining_fee_weight.checked_sub(&info.total_weight())`. The subsequent `if !is_dry_run { ... }` block computes `overweight_by` and subtracts it from `weight_limit` only for real dispatch (`call.set_weight_limit(capped_weight)`), while the `else` branch (dry run) returns the uncapped `weight_limit` unchanged.

`eth_estimate_gas`'s binary search (in `substrate/frame/revive/src/lib.rs`) exclusively calls `dry_run_at`, which invokes `dry_run_eth_transact`, which constructs the call through `into_call` with `is_dry_run = true`. Therefore every probe in the binary search receives an uncapped `weight_limit`, and the final estimated `gas` reflects that uncapped budget. When the resulting transaction is later submitted as a real extrinsic, `into_call` runs with `is_dry_run = false` and applies the `overweight_by` reduction, shrinking the `weight_limit` actually handed to the contract-execution meter. For a call whose `info.total_weight()` is close to or exceeds `evm_max_extrinsic_weight()` (achievable via unbounded-cost precompiles such as `Bn128Pairing`, whose benchmarked weight scales steeply and linearly with input size), this reduction can turn a previously successful dry run into an on-chain out-of-weight failure.

## Impact Explanation
This breaks the invariant that `eth_estimateGas` should return a gas value sufficient for successful execution when submitted on-chain. Users following the standard Ethereum tooling workflow can have correctly-estimated transactions revert/fail due to running out of weight during real dispatch, wasting the fixed/length transaction fee (which is charged regardless of dispatch outcome). This falls under "public underpriced work that degrades... reliable execution" / a runtime bug compromising intended behavior of gas estimation, though it does not enable fund theft or origin escalation.

## Likelihood Explanation
Triggerable by any unprivileged EOA using only the public `eth_estimateGas` and transaction-submission RPC flow, with a contract call engineered to have `info.total_weight()` near `evm_max_extrinsic_weight()` (e.g., via `Bn128Pairing` or other unbounded-cost precompiles). No special role, validator/collator cooperation, or off-chain infrastructure control is required, though the discrepancy is only material near the extrinsic weight ceiling.

## Recommendation
Apply the same `overweight_by` capping computation in `into_call` regardless of `is_dry_run`, so the dry-run path used by `eth_estimate_gas` reflects the same weight ceiling that will be enforced on real dispatch. This ensures `eth_estimate_gas`'s binary search converges on a gas value that is genuinely sufficient for on-chain execution.

## Proof of Concept
1. Deploy a contract whose call path invokes `Bn128Pairing` (precompile address `0x8`) with input sized so `info.total_weight()` for the resulting `eth_call` sits near `evm_max_extrinsic_weight()`.
2. Call `eth_estimateGas` for a transaction invoking this contract; the binary search in `eth_estimate_gas` (`substrate/frame/revive/src/lib.rs`) uses `dry_run_at`, which builds the call with `is_dry_run = true`, skipping the `overweight_by` cap in `into_call`.
3. Submit the actual transaction with the returned gas; `into_call` now runs with `is_dry_run = false`, subtracting `overweight_by` and reducing `weight_limit`.
4. Observe the contract call, which succeeded during estimation, fails on-chain due to insufficient weight, confirming the reproducibility gap between estimation and real dispatch.
