### Title
`TokenDiff::token_fee` fee waiver bypassed by splitting a trade into |delta|==1 NEP-245 legs - (File: contracts/defuse/core/src/intents/token_diff.rs)

### Summary
`TokenDiff::token_fee` unconditionally returns `Pips::ZERO` for a `Nep245`/`Nep171`/`Imt` `TokenId` whenever the per-intent `amount <= 1`, regardless of the total volume traded. Because the fee is computed independently for each `TokenDiff` intent leg rather than on the net traded amount, a signer can split one large NEP-245 trade into `N` separate `delta == -1` legs and pay zero fee on the whole trade instead of the fee owed on the aggregate `-N` delta.

### Finding Description
The broken binding: for a NEP-245 token `T`, `fees_collected[T]` should equal `Pips::fee_ceil(protocol_fee, total_negative_delta_of_T_in_batch)`. In the actual code the fee is computed and summed per-leg: [1](#0-0) 

and `token_fee` special-cases `Nep245`/`Nep171`/`Imt` with `amount <= 1`: [2](#0-1) 

For a single `TokenDiff` with `delta = -N` (`N > 1`), `token_fee` falls into the `TokenIdType::Nep245 if amount > 1` arm and the full `protocol_fee` is applied, yielding `fee = fee_ceil(protocol_fee, N)`. If the same net trade is instead expressed as `N` separate `TokenDiff` intents (or `N` entries across a batch of `MultiPayload`s) each with `delta = -1`, every call to `token_fee` hits the `amount <= 1` arm and returns `Pips::ZERO`, so `fee_ceil` on each leg is `0`, and the total `fees_collected[T]` across the whole batch is `0`.

Crucially, the overall Verifier invariant only requires that the *net* deltas across the whole batch sum to zero per token (enforced by `TransferMatcher::finalize`/`Deltas::finalize`): [3](#0-2) 

This invariant is agnostic to how the net delta is split across intents/legs — it only matches deposits against withdrawals per token, not per-fee. Thus splitting the trade into unit legs still balances the batch (satisfying `finalize`) while individually starving the fee logic, which was only ever meant to skip fees on singleton NFT/MT (amount==1) transfers, not on an aggregated large volume artificially chopped into unit-sized intents. None of the existing guards (`MultiPayload::verify`, nonce/salt checks, `TransferMatcher::finalize`) inspect or aggregate the true traded volume per token across legs before computing fees — `token_fee` is evaluated strictly locally, per intent, per delta entry.

Exploit flow: the attacker (an ordinary signer with an NEP-245 balance in the Verifier, matched by a counterparty willing to trade against it — e.g. the attacker's own second account/intent acting as counterparty, or any market maker) signs `N` `TokenDiff` intents each with `{T_nep245: -1, T_out: +price}` instead of one `{T_nep245: -N, T_out: +N*price}`. Submitted together via `execute_intents`/`execute_signed_intents`, each leg's fee is `Pips::ZERO`, so `fee_collector` receives `0` total fee on the whole `N`-unit trade, whereas the single-intent equivalent would have paid `fee_ceil(protocol_fee, N)`.

### Impact Explanation
`fee_collector`'s protocol fee is under-collected for any NEP-245 (or NFT/IMT) trade that is split into unit legs, matching the "protocol fees bypassed" Critical category. No tokens are stolen from other users' balances (the Verifier's balances still net to zero per the `TransferMatcher` invariant), but value that should have accrued to the protocol's `fee_collector` is diverted back to the trading parties. This is repeatable for every NEP-245/NFT/IMT trade and scales with volume — the larger the trade, the more fee is avoided by simply increasing `N`.

### Likelihood Explanation
Preconditions are minimal: the attacker only needs to control both sides of a matched batch of intents (or coordinate with any counterparty) trading a NEP-245 token, with no special role or privilege required — this is fully within the "signer submits arbitrary `MultiPayload`" attacker model. The attack costs nothing beyond constructing `N` intents instead of 1 (bounded by gas/payload size, which is explicitly out of scope for this audit) and is fully repeatable across tokens, accounts, and batches.

### Recommendation
Compute the NEP-245/NFT/IMT fee waiver based on the aggregated net delta per `(signer, token_id)` across the whole intent/batch (or across all `TokenDiff`s executed by the transaction) rather than per individual delta entry, so that splitting a trade into unit legs cannot reduce the aggregate fee below what a single equivalent-sized `TokenDiff` would incur. Alternatively, only waive fees when the counterparty-matched aggregate size for that token in the finalized `Transfers` is `<= 1`.

### Proof of Concept
```rust
// contracts/defuse/core/src/intents/token_diff.rs (or an integration test crate)
#[test]
fn fee_bypass_by_splitting_nep245_legs() {
    let protocol_fee = Pips::ONE_PERCENT; // e.g. 1%
    let token = TokenId::from(Nep245TokenId::new(
        "mt.near".parse::<AccountId>().unwrap(), "unit1".to_string(),
    ));

    // Aggregate trade: single TokenDiff with delta = -1000
    let single_fee = TokenDiff::token_fee(&token, 1000, protocol_fee).fee_ceil(1000);
    assert!(single_fee > 0, "single large trade should pay fee");

    // Equivalent trade split into 1000 unit legs
    let mut split_fee_total: u128 = 0;
    for _ in 0..1000 {
        split_fee_total += TokenDiff::token_fee(&token, 1, protocol_fee).fee_ceil(1);
    }
    assert_eq!(split_fee_total, 0, "split trade pays zero fee");

    // Binding violated: fee collected on equivalent aggregate delta differs
    assert_ne!(single_fee, split_fee_total);
}
```

    // Finalizes all transfers, or returns unmatched deltas.
    // If unmatched deltas overflow, then Err(None) is returned.
    pub fn finalize(self) -> Result<Transfers, InvariantViolated> {
        let mut transfers = Transfers::default();
        let mut deltas = TokenDeltas::default();
        for (token_id, transfer_matcher) in self.0 {
            if let Err(unmatched) = transfer_matcher.finalize_into(&token_id, &mut transfers)
                && (unmatched == 0 || deltas.apply_delta(token_id, unmatched).is_none())
            {
                return Err(InvariantViolated::Overflow);
            }
        }
        if !deltas.is_empty() {
            return Err(InvariantViolated::UnmatchedDeltas {
                unmatched_deltas: deltas,
            });
        }
        Ok(transfers)
    }
