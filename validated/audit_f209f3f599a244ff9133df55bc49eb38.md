Audit Report

## Title
`pallet-broker::do_drop_history` can permanently strand contributor pool revenue before `claim_revenue` executes, due to a mismatched timeout reference point vs. `do_drop_contribution` - (File: `substrate/frame/broker/src/dispatchable_impls.rs`)

## Summary
`drop_history` is a permissionless (`_origin: OriginFor<T>`) extrinsic that removes an `InstaPoolHistoryRecord` for a given timeslice `when` once `status.last_timeslice > when + contribution_timeout`, and debits its `maybe_payout` from the pot via `Self::charge`. Because `do_drop_contribution`'s equivalent guard is keyed on the contribution's *end* (`region.begin + contribution.length + contribution_timeout`) rather than on the individual timeslice, any multi-timeslice `InstaPoolContribution` (`length > 1`) has a window where its earliest timeslices' `InstaPoolHistory` records become droppable while the contribution itself is still valid and unclaimed. This lets an unprivileged caller destroy history entries that `do_claim_revenue` still needs, causing the contributor's payout for those timeslices to be silently zeroed (via the `else { continue }` branch) while the corresponding value has already been charged out of the pot.

## Finding Description
`do_claim_revenue` iterates `region.begin..last` and for each timeslice `r` reads `InstaPoolHistory::<T>::get(r)`; if it returns `None` the loop does `continue`, silently contributing zero for that timeslice: [1](#0-0) 

`do_drop_history`'s only validity guard compares `status.last_timeslice` to `when + config.contribution_timeout`, and on success it `take`s the record and calls `Self::charge(&Self::account_id(), payout)` to debit the pot: [2](#0-1) 

`do_drop_contribution`'s guard, by contrast, is keyed on the contribution's *end* (`region_id.begin + contrib.length`), not on any single timeslice: [3](#0-2) 

For a contribution with `length > 1`, `when = region.begin` (the earliest timeslice) satisfies `drop_history`'s guard strictly earlier than `drop_contribution`'s guard becomes satisfiable for that same contribution. In that window, an unprivileged caller can call `drop_history(region.begin)` — the call takes `_origin: OriginFor<T>` with no `ensure_signed` check, confirmed both in `lib.rs`'s dispatchable and the explicit design note in `prdoc/1.6.0/pr_2656.prdoc`. This removes the `InstaPoolHistoryRecord` and debits the payout from the pot's ledger via `Self::charge`, while the contribution that should still be able to claim against that timeslice remains live in `InstaPoolContribution`. When the rightful contributor later calls `claim_revenue`, the lookup at line 436 returns `None` for that timeslice and the loop simply skips it — no error, no event, and no re-crediting — so the contributor's payout is short by exactly the amount already debited in step one, which is never transferred to them via `T::Currency::transfer` at line 461.

The existing guards are demonstrably insufficient because they anchor to two different reference points (`when` vs. `end = begin + length`) for what is effectively the same underlying claim window, breaking the invariant that a history record must not be reapable while any contribution that could still consume it remains outstanding.

## Impact Explanation
This is a permanent, unrecoverable fund-loss condition for the pool contributor: value is debited from the broker pot's accounting (via `Self::charge`) but is never routed to the contributor entitled to it via `claim_revenue`, and no on-chain mechanism restores or flags the discrepancy. This matches the "permanent user-fund lock" / unbacked-accounting-drift impact category, since a legitimate contributor's payout share is destroyed by an action outside their control and with no privileged-origin requirement.

## Likelihood Explanation
The precondition — a pool contribution spanning more than one timeslice (`contribution.length > 1`), which is a routine, non-edge case for coretime pool contributions — combined with `drop_history` accepting any origin, means this can be triggered by any account with no special capability, permission, or governance action, and is fully reproducible via a deterministic sequence of `pool` → time advance → `drop_history` → `claim_revenue` calls.

## Recommendation
1. Guard `do_drop_history(when)` so that it cannot remove a record while any `InstaPoolContribution` whose range still overlaps `when` remains unclaimed/undropped — e.g. only drop a history record once it is provably outside the range of every live contribution, not just based on its own `when + contribution_timeout`.
2. Alternatively, align `drop_history`'s timeout reference point with `drop_contribution`'s (i.e., defer eligibility for dropping timeslice `when` until all contributions overlapping `when` are themselves droppable), so the two are never mutually inconsistent.
3. Make the debit in `Self::charge` and the eventual payout in `do_claim_revenue` mutually exclusive for a given `(region_id, when)` pair, e.g. by failing `drop_history` if outstanding contributions still reference that timeslice, instead of silently succeeding.

## Proof of Concept
1. Purchase a region and call `do_pool(region, ..., Final)` to create an `InstaPoolContribution { length: N, payee: victim }` spanning `region.begin .. region.begin + N`, with `N > 1`.
2. Populate `InstaPoolHistory` for each timeslice in that range with `maybe_payout = Some(revenue_r)` via normal revenue reporting.
3. Advance `status.last_timeslice` so that `last_timeslice > region.begin + contribution_timeout` (satisfying `drop_history`'s guard for `when = region.begin`) but `last_timeslice < region.begin + N + contribution_timeout` (so `drop_contribution`'s guard for the whole contribution is not yet satisfied) — a valid window whenever `N > 1`.
4. Any unsigned/unprivileged account calls `drop_history(region.begin)`; it succeeds, removing the record and calling `Self::charge` on the pot for `revenue_region.begin`.
5. The victim calls `claim_revenue(region_id, N)`; the loop's `InstaPoolHistory::get(region.begin)` returns `None`, the timeslice is skipped via `continue`, and the victim's payout is short by exactly the amount already debited from the pot in step 4, with no compensating transfer or error raised.

	pub(crate) fn do_drop_contribution(region_id: RegionId) -> DispatchResult {
		let config = Configuration::<T>::get().ok_or(Error::<T>::Uninitialized)?;
		let status = Status::<T>::get().ok_or(Error::<T>::Uninitialized)?;
		let contrib =
			InstaPoolContribution::<T>::get(&region_id).ok_or(Error::<T>::UnknownContribution)?;
		let end = region_id.begin.saturating_add(contrib.length);
		ensure!(
			status.last_timeslice >= end.saturating_add(config.contribution_timeout),
			Error::<T>::StillValid
		);
		InstaPoolContribution::<T>::remove(region_id);
		Self::deposit_event(Event::ContributionDropped { region_id });
		Ok(())
	}

	pub(crate) fn do_drop_history(when: Timeslice) -> DispatchResult {
		let config = Configuration::<T>::get().ok_or(Error::<T>::Uninitialized)?;
		let status = Status::<T>::get().ok_or(Error::<T>::Uninitialized)?;
		ensure!(
			status.last_timeslice > when.saturating_add(config.contribution_timeout),
			Error::<T>::StillValid
		);
		let record = InstaPoolHistory::<T>::take(when).ok_or(Error::<T>::NoHistory)?;
		if let Some(payout) = record.maybe_payout {
			let _ = Self::charge(&Self::account_id(), payout);
		}
		let revenue = record.maybe_payout.unwrap_or_default();
		Self::deposit_event(Event::HistoryDropped { when, revenue });
		Ok(())
	}
