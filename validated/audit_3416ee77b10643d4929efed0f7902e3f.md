### Title
Frequent `accrueInterest()` calls freeze debt index: zero-interest loans on low-decimal synthetic debts - ([File: contracts/DebtToken.sol](contracts/DebtToken.sol))

### Summary
`DebtToken._calculateInterestAccrual` computes per-call interest as `wadMul(interestRatePerSecond() * elapsed, totalSupply_)`. `wadMul` rounds half-up to the nearest wei, so any accrued amount below `0.5` wei is truncated to `0`. Because `accrueInterest()` is permissionless and advances `lastTimestampAccrued` even when the accrued amount rounds to zero, an attacker who pokes it every block keeps `elapsed` small enough that interest permanently rounds to zero for low-decimal debt tokens (e.g. `msBTC`/`msETH` debt where `decimals = syntheticToken.decimals()` can be 8). The debt index never grows, `balanceOf()` under-reports debt, and borrowers get free loans while the `feeCollector` receives nothing.

### Finding Description
In `contracts/DebtToken.sol:551-566`:

```solidity
_interestRateToAccrue = interestRatePerSecond() * (block.timestamp - _lastTimestampAccrued);
if (_interestRateToAccrue > 0) {
    _interestAmountAccrued = _interestRateToAccrue.wadMul(totalSupply_);
    _debtIndex += _interestRateToAccrue.wadMul(_debtIndex);
}
```

`wadMul` (`contracts/lib/WadRayMath.sol:30`) returns `(a * b + HALF_WAD) / WAD`, which is `0` whenever `a * b < 5e17`. In `accrueInterest()` (`contracts/DebtToken.sol:156-180`), `lastTimestampAccrued` is updated to `block.timestamp` regardless of whether `_interestAmountAccrued` is zero — the elapsed-time window is "spent" even though no interest was booked. Since `accrueInterest()` is `public` and unauthenticated, anyone can call it.

Numerically: `interestRatePerSecond ≈ interestRate / 31_536_000`. For 10% APR this is ≈ `3.17e9`. With `dt = 12` s (one block), the interest term is `3.8e10 * totalSupply_ / 1e18`, which is `0` whenever `totalSupply_ < ~1.3e7` wei. For an 8-decimal debt token like `MsBTCDebt` (deployed on mainnet/hemi per `deployments/`), `1.3e7` units = 0.13 BTC — a realistic total-debt value for a small or new synthetic market. An attacker calling `accrueInterest()` once per block keeps `dt` permanently small, so `debtIndex` and `totalSupply_` are never updated and `debtIndexOf`-based `balanceOf` (`DebtToken.sol:196-206`) never grows. This is the same class as the Yieldoor issue: per-call rounding of an interest/index update truncated to zero because the per-interval increment is smaller than the token's smallest unit, exploitable by forcing frequent accrual.

### Impact Explanation
Borrowers pay zero interest for as long as the attack is maintained: their `balanceOf` stays equal to principal while real time accrues. The protocol permanently loses the interest-fee stream (`syntheticToken.mint(feeCollector, _interestAmountAccrued)` never fires), i.e. theft of unclaimed yield. Unlike Yieldoor's version, the loss here is total (0% accrual), not a small relative error — but it requires total debt supply below the dust threshold, so it applies to low-decimal synthetic debt tokens in their small-supply regime.

### Likelihood Explanation
`accrueInterest()` is callable by any EOA with no modifier, cost only gas. Deployed `MsBTCDebt` tokens exist on mainnet and hemi. The pre-condition is total borrows below ~`0.5e18 / (ratePerSecond * blockTime)` wei — for msBTC at 10% APR on a 12 s chain, ~0.13 BTC. On fast L2s (Base/Optimism/Swell, ~2 s blocks) the threshold is ~5-6x higher, making the attack viable over a wider supply range. The attacker can also be a borrower themselves, directly profiting from interest-free debt.

### Recommendation
Accumulate the sub-wei remainder instead of resetting the accrual window: either (a) only advance `lastTimestampAccrued` when `_interestAmountAccrued > 0` (so the un-accrued interval carries forward), or (b) track accrued interest in a higher-precision accumulator (ray/27-decimal index) and only materialize whole wei. Option (a) is a one-line change and preserves the existing accounting; it makes `accrueInterest` calls harmless regardless of frequency.

### Proof of Concept
Hardhat sketch (mirroring `test/DebtToken.test.ts` setup):

```ts
// msBTC-style debt token with 8 decimals, interestRate = 10% APR
await msBTCDebt.updateInterestRate(parseEther('0.1'));
// small total debt: 0.1 BTC = 1e7 wei < 1.3e7 threshold
await msdToken.deposit(collateralAmount, attacker.address);
await msBTCDebt.issue(1e7, attacker.address); // borrow 0.1 msBTC

const debtBefore = await msBTCDebt.balanceOf(attacker.address);

// attacker (or anyone) calls accrueInterest() every block for ~1 year
for (let i = 0; i < N; i++) {
  await time.increase(12);            // one block
  await msBTCDebt.accrueInterest();   // interest per call < 0.5 wei -> 0
}

const debtAfter = await msBTCDebt.balanceOf(attacker.address);
expect(debtAfter).eq(debtBefore);              // no interest accrued
expect(await msBTCDebt.debtIndex()).eq(parseEther('1')); // index frozen
// Expected honest debt would be ~1.1e7 wei; feeCollector receives 0 msBTC.
```
